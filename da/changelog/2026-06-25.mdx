**Dato**: 2026-06-25

**Version**: `v3.21.0`

![v3.21.0 release](/images/3.21.0.png)

Denne udgivelse tilføjer **`useI18nHead`** — en composable på sideniveau til i18n-SEO-tilpasninger oven på det indbyggede `02.meta`-plugin. Tilpas `hreflang`, canonical, `og:url` og Open Graph-tags pr. route uden et brugerdefineret meta-plugin eller `meta: false`.

## Hvad er nyt? {#what’s-new}

### `useI18nHead`-composable {#usei18nhead-composable}

Kald `useI18nHead` på en hvilken som helst side, når `meta: true` (standard). Modulet fletter dit input ind efter `useLocaleHead` ved hver route-opdatering:

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

Understøtter statiske objekter, reaktive getters, tilføjelse via `meta` / `link`, `replace` for indbyggede grupper og `disable` til at fjerne automatisk genererede tags. Se [`useI18nHead`](/da/composables/useI18nHead).

### `mergeI18nHead`-hjælpefunktion (`@i18n-micro/utils`) {#mergei18nhead-utility-@i18n-micro/utils}

Den framework-uafhængige fletningslogik ligger i `@i18n-micro/utils/merge-i18n-head` — den bruges af `02.meta`-pluginet og kan testes isoleret. Typerne (`I18nHeadInput`, `I18nHeadLink`, `I18nHeadMeta`) eksporteres fra `@i18n-micro/types`.

### Plugin-integration {#plugin-integration}

- **`02.meta`** — fletter outputtet fra `useLocaleHead` med sidetilstanden fra `useI18nHead` via `useHead`
- **`01.plugin`** — nulstiller sidens tilpasninger, når route-navnet ændres, via `resetPageHead()` (delt tilstand med composablen)

### Dokumentation og tests {#documentation-&-tests}

- Ny guide: [`useI18nHead`](/da/composables/useI18nHead) med CMS-/artikeleksempler
- Opdateret [SEO](/da/guide/seo) og [`useLocaleHead`](/da/composables/useLocaleHead) — hvornår man skal bruge hvilket API
- Playwright- + Vitest-dækning: SSR, SPA-navigation, genindlæsning, `nuxi generate`, delvise alternates, `x-default`, reaktiv indlæsning på klienten

## Typiske anvendelsestilfælde {#typical-use-cases}

| Scenarie                                     | Fremgangsmåde                                                  |
| -------------------------------------------- | -------------------------------------------------------------- |
| Blog/CMS med delvise oversættelser           | `replace.hreflang` + `replace.ogAlternates` fra API-locales    |
| Brugerdefineret canonical fra CMS            | `replace.canonical` + `replace.ogUrl`                          |
| Kun OG på landingsside                       | `meta: [{ property: 'og:title', ... }]` — behold modulets hreflang |
| Ingen hreflang på en side                    | `disable: ['hreflang', 'x-default']`                           |
| Erstat brugerdefineret plugin (`i18nManualHreflang`) | `useI18nHead` pr. indholdsside + `meta: true`          |

**JSON-LD** forbliver i `useHead({ script: [...] })` — `useI18nHead` genererer ikke strukturerede data.

## Breaking changes {#breaking-changes}

Ingen ved almindelig brug af `nuxt.config`. Den nye composable og utils-understien er rene tilføjelser.

## Hvorfor det er vigtigt {#why-it-matters}

- **Intet brugerdefineret meta-plugin** til CMS-indlæg, nyheder eller guides med URL'er pr. locale
- **Én pipeline** — modulets standarder + sidetilpasninger i ét `useHead`-kald
- **Typesikkert** — `I18nHeadInput` til hjælpere som `buildArticleHead(content)`

Den fulde changelog offentliggøres sammen med udgivelsen på [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
