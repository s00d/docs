---
title: "useI18nLocale"
description: "useI18nLocale læser og skriver locale-tilstanden og locale-cookien — indgangspunktet for brugerdefineret locale-registrering."
---

`useI18nLocale()` giver adgang til den locale, appen har valgt: `i18n-locale`-tilstanden og locale-cookien. Brug den i et plugin, der selv registrerer locale (domæne, brugerprofil, header), i stedet for at skrive `useState('i18n-locale')` eller cookien manuelt. Dens gyldighedskontroller bruger de aktiverede locales, inklusive runtime-tilsidesættelser.

## Signatur {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Centraliseret indgangspunkt for styring af i18n-locale.
Kombinerer useState('i18n-locale'), locale-cookie og synkroniseringsværktøjer.

## Returnerede værdier {#returned-values}

| Medlem | Type | Beskrivelse |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | `useState('i18n-locale')`-ref'en. |
| `localeCookie` | `Ref<string \| null>` | Cookien [`localeCookie`](/da/api/module-options#localecookie); et simpelt `{ value: null }`, når indstillingen er `null`. |
| `hashCookie` | `Ref<string \| null>` | Cookien `hash-locale` ved hash-routing; ellers `{ value: null }`. |
| `validLocales` | `string[]` | Koder for de aktiverede locales. |
| `setLocale(locale)` | `(locale: string \| null) => void` | Skriv tilstanden og cookierne. Validerer ikke og indlæser ikke oversættelser. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | Skriv kun cookierne. |
| `getLocale()` | `() => string \| null` | Tilstanden, derefter præferencecookien (hash-cookien ved hash-routing). Ikke valideret. |
| `getPreferredLocale()` | `() => string \| null` | Den første **gyldige** af tilstand og præferencecookie, eller `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | Tilstanden ved hash-routing, når den er sat; ellers `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, derefter en gyldig tilstand, derefter `options.serverLocale`, derefter routens locale. Gemmer resultatet i tilstanden, når tilstanden ikke er gyldig; på klienten skriver den også cookien. |
| `isValidLocale(locale)` | `(locale) => locale is string` | Om `locale` findes i `validLocales`. |

Cookierne varer ét år, med `path: '/'` og `sameSite: 'lax'`.

## Eksempel {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

Modulets loader-plugin læser tilstanden, når det starter, så et plugin, der sætter den, skal køre først (`enforce: 'pre'`). Hvordan tilstanden konkurrerer med URL'en, cookien og `Accept-Language`: [Locale-registrering](/da/guide/locale-detection). Fuld gennemgang: [Brugerdefineret registrering](/da/guide/custom-auto-detect).

`setLocale()` skifter ikke oversættelserne på skærmen. For at ændre den aktuelle sides locale skal du kalde [`$switchLocale()`](/da/api/methods#$switchlocale).
