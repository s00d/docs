---
title: "useI18nHead"
description: "useI18nHead tilsidesætter de genererede i18n-SEO-tags for én side: erstat eller fjern canonical-, hreflang- og og-tags, eller tilføj dine egne."
---

`useI18nHead()` ændrer de SEO-tags, som modulet genererer, for én side alene. Brug den, når en side ved bedre end routeren: en CMS-artikel, der kun findes i nogle locales, en canonical-URL fra et API, ekstra `og:`-tags. Du får de genererede tags med dine tilsidesættelser flettet ovenpå.

## Signatur {#signature}

```ts
useI18nHead(input?: MaybeRefOrGetter<I18nHeadInput | null>): { pageHead: any; resetPageHead: () => void }
```

Registrerer tilsidesættelser på sideniveau for i18n-SEO-head-tags.
Flettes oven på outputtet fra `useLocaleHead` af pluginet `02.meta`.

Foretræk en getter (`() => ({ … })`), når værdierne kommer fra `$t` / `t`, så de
opløses igen ved skift af locale. Et almindeligt objekt evalueres én gang og forbliver låst.

| Parameter | Type | Beskrivelse |
| --- | --- | --- |
| `input` *(valgfri)* | `MaybeRefOrGetter<I18nHeadInput \| null>` |  |

Den virker med [`meta: true`](/da/api/module-options#meta) (standard): modulets meta-plugin fletter inputtet oven på outputtet fra [`useLocaleHead`](/da/composables/useLocaleHead) ved hver head-rendering. Med `meta: false` er der intet, der læser det.

Tilsidesættelsen nulstilles, når route-navnet ændres. En side, der sætter `disableMeta`, får slet ingen i18n-tags, heller ikke tilsidesættelser.

## Input {#input}

`I18nHeadInput` (fra `@i18n-micro/types`):

| Nøgle | Type | Effekt |
| --- | --- | --- |
| `htmlAttrs` | `Record<string, string>` | Flettes ind i `<html>`-attributterne (`lang`, `dir`). |
| `meta` | `I18nHeadMeta[]` | Tilføjes efter de genererede tags; erstatter et tag med samme `id`, `property` eller `name`. |
| `link` | `I18nHeadLink[]` | Tilføjes efter de genererede links; erstatter et link med samme `id` eller `rel` + `hreflang`. |
| `replace.canonical` | `string \| false` | Erstat canonical-`href`, eller fjern linket. |
| `replace.hreflang` | `I18nHeadLink[] \| false` | Erstat eller fjern **alle** `rel="alternate"`-links, inklusive `x-default`. |
| `replace.xDefault` | `I18nHeadLink \| false` | Erstat eller fjern `x-default`-linket. |
| `replace.ogLocale` | `string \| false` | Erstat eller fjern `og:locale`. |
| `replace.ogUrl` | `string \| false` | Erstat eller fjern `og:url`. |
| `replace.ogAlternates` | `string[] \| false` | Genopbyg `og:locale:alternate` ud fra disse locale-koder (via `og` / `iso`) og spring den aktuelle locale, ukendte koder og koder uden en `og`- eller `iso`-værdi over, eller fjern dem. |
| `disable` | `I18nHeadDisableGroup[]` | Fjern genererede grupper: `'hreflang'` (ikke `x-default`), `'x-default'`, `'canonical'`, `'og'` (`og:locale` + `og:url`), `'og-alternates'`, `'html'`. |

Rækkefølge for anvendelse: `disable`, derefter `replace`, derefter `htmlAttrs`, `meta`, `link`.

## Eksempel {#example}

En artikel, der kun findes i nogle locales, med alternative URL'er fra API'et:

```vue
<script setup lang="ts">
const route = useRoute()
const { t } = useI18n()
const { data: article } = await useFetch<{ title: string; urls: Record<string, string> }>(`/api/articles/${route.params.slug}`)

useI18nHead(() => {
  if (!article.value) return null
  const codes = Object.keys(article.value.urls)
  return {
    meta: [{ property: 'og:title', content: article.value.title || t('blog.title') }],
    replace: {
      hreflang: codes.map((code) => ({ rel: 'alternate', hreflang: code, href: article.value!.urls[code]! })),
      ogAlternates: codes,
    },
  }
})
</script>
```

Send en getter, som her, når værdierne kommer fra `t()` eller asynkrone data: den kører igen ved skift af locale. Et almindeligt objekt læses én gang.
