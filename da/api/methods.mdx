---

Modulet injicerer sine runtime-hjælpefunktioner i Nuxt-appen: `$t`, `$tc`, `$localePath`, `$switchLocale` og resten. Brug denne side til at slå en hjælpefunktions signatur og adfærd op. Signaturer og beskrivelser stammer fra interfacene `PluginsInjections` og `NuxtAppOnlyInjections` i `src/runtime/plugins/01.plugin.ts`.

## Adgang {#access}

| Hvor | Hvordan |
| --- | --- |
| Template | `{{ $t('title') }}` — alle hjælpefunktioner, med `$` |
| `<script setup>` | `const { t, localePath } = useI18n()` — alle hjælpefunktioner i `PluginsInjections`, med og uden `$` |
| Plugin, middleware, `<script setup>` | `const { $t, $defineI18nRoute } = useNuxtApp()` — alt, kun med `$` |

`$defineI18nRoute` er kun typet på `useNuxtApp()`. Se [`useI18n`](/da/composables/useI18n).

```vue
<script setup lang="ts">
const { t, localePath } = useI18n()
</script>

<template>
  <NuxtLink :to="localePath('/about')">{{ t('nav.about') }}</NuxtLink>
</template>
```

## Locale {#locale}

### `$getLocale` {#$getlocale}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric) => string
```

Koden for den aktive locale. Angiv en route for at læse den locale, som routen hører til.

```ts
$getLocale() // 'de' on /de/about
```

### `$getLocaleName` {#$getlocalename}

```ts
() => string | null
```

Den aktive locales `displayName` fra konfigurationen, eller `null`, hvis den ikke har en.

### `$getLocales` {#$getlocales}

```ts
() => Locale[]
```

Alle konfigurerede locales med deres metadata.

Brugerdefinerede egenskaber på et locale-objekt returneres, som de er skrevet; typ dem med [module augmentation](/da/api/module-options#locales) af `Locale`.

### `$defaultLocale` {#$defaultlocale}

```ts
() => string | undefined
```

Koden for den konfigurerede standard-locale.

### `$getI18nConfig` {#$geti18nconfig}

```ts
() => ResolvedI18nConfig
```

Den resolvede modulkonfiguration, som runtime ser den.

Værdien omfatter [runtime-tilsidesættelser](/da/guide/runtime-overrides) (`defaultLocale`, `fallbackLocale`, deaktiverede locales).

```ts
const { strategy, localeCookie } = useNuxtApp().$getI18nConfig()
```

## Oversættelse {#translation}

### `$t` {#$t}

```ts
TranslationFn<CleanTranslation>
```

Oversæt en nøgle og interpoler `params` ind i den. Returnerer `defaultValue`, når nøglen
mangler, eller selve nøglen, når der ikke er angivet en standardværdi.

```ts
// { "welcome": "Welcome, {name}!" }
$t('welcome', { name: 'Ada' }) // 'Welcome, Ada!'
$t('missing.key', {}, 'Fallback') // 'Fallback'
```

En nøgle, der peger på et indlejret objekt, returnerer det objekt og ikke en streng. I en template vises det som `[object Object]`; brug en bladnøgle.

### `$ts` {#$ts}

```ts
TranslationFn<string>
```

Som `$t`, men returnerer altid en streng: værdien sendes gennem `toString()`, så et indlejret
objekt bliver til `'[object Object]'`. Lad nøglen pege på et blad.

### `$_t` {#$_t}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<CleanTranslation>
```

Bind `$t` til en bestemt route for at oversætte uden for den aktuelle side — f.eks. et layout,
der viser et link til en anden route.

```ts
const route = useRoute()
const t = useNuxtApp().$_t(route)
t('page.title')
```

### `$_ts` {#$_ts}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<string>
```

Bind `$ts` til en bestemt route. Se `$_t`.

### `$tc` {#$tc}

```ts
(key: TranslationKey, params: number | Params, defaultValue?: string) => string
```

Oversæt med pluralisering. `params` kan være selve antallet eller et objekt, der indeholder
`count`.

Formerne adskilles med `|`. Med den indbyggede regel vælger et ikke-negativt heltal `n` som antal form `n`, begrænset til den sidste form; et negativt, brøkdels- eller `NaN`-antal tager den sidste form. `{count}` og de øvrige parametre interpoleres ind i den valgte form.

For sprog, hvis pluralformer ikke følger antallet, skal templaten starte med `=0 `. Den første form er så til 0, og de øvrige følger kategorierne fra [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) i rækkefølgen `zero, one, two, few, many, other`:

```json
{
  "apples": "=0 no apples | one apple | {count} apples",
  "files": "=0 no files | {count} one | {count} few | {count} many"
}
```

```ts
$tc('apples', 0) // 'no apples'
$tc('apples', 1) // 'one apple'
$tc('apples', 7) // '7 apples'

// In `uk` (categories `one, few, many, other`) the forms after the zero form follow those categories:
$tc('files', 21) // '21 one'
$tc('files', 22) // '22 few'
$tc('files', 25) // '25 many'
$tc('files', 2.5) // '2.5 many': no form for `other`, so the last one
```

- `=0 ` tæller kun helt i starten af værdien, med mellemrummet. `$t` viser det som tekst: det hører til pluralformer.
- En kategori uden sin egen form tager den sidste form. Et negativt eller brøkdelsantal tager også den sidste form.
- Det virker i enhver locale: `=0 none | one | {count} many` på engelsk.
- Kategorien kommer fra locale'ens `iso`, ellers fra dens kode. En kode, som `Intl` ikke kender, falder tilbage til indeksreglen, stadig med markøren fjernet, så resultatet aldrig afhænger af maskinen.
- `<i18n-t :plural>` følger samme regel. En brugerdefineret [`plural`](/da/api/module-options#plural) eller `customPluralRule` får den rå værdi, inklusive markøren, og bestemmer selv; hvis `plural` returnerer `null`, overlades kaldet til den indbyggede regel, som respekterer markøren.

Uden markøren bliver en template på indeksreglen, med én undtagelse, der kun kan læses på én måde: en nulform uden pladsholder, derefter én form pr. kategori, med `{count}` i hver form, som flere antal deler (`no files | {count} one | {count} few | {count} many` i `uk`).

Sæt [`plural`](/da/api/module-options#plural) for at bruge dine egne regler.

```ts
// { "apples": "no apples | one apple | {count} apples" }
$tc('apples', 0) // 'no apples'
$tc('apples', 10) // '10 apples'
$tc('cart', { count: 2, name: 'Ada' }) // count and params in one object
```

Det tredje argument er `defaultValue`, ikke params.

### `$has` {#$has}

```ts
(key: string) => boolean
```

Om en nøgle kan resolves i den aktive locale. Brug den til at forgrene på valgfri tekst i stedet for
at vise en rå nøgle. Ligesom `$t` ser den også den forladte sides nøgler under et sideskift
inden for samme locale.

```ts
if ($has('promo.banner')) show.value = true
```

## Formatering {#formatting}

### `$tn` {#$tn}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

Formatér et tal med `Intl.NumberFormat` i den aktive locale. En nøgle vælger et navngivet format
fra konfigurationen.

Navngivne formater kommer fra [`numberFormats`](/da/api/module-options#numberformats).

```ts
$tn(1234.5, { style: 'currency', currency: 'EUR' }) // '1.234,50 €' in de
$tn(1000, 'currency') // named format
$tn(1000, 'currency', 'de') // named format in another locale
```

### `$td` {#$td}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

Formatér en dato med `Intl.DateTimeFormat` i den aktive locale. En nøgle vælger et navngivet format
fra konfigurationen.

Navngivne formater kommer fra [`datetimeFormats`](/da/api/module-options#datetimeformats).

```ts
$td(new Date(), { dateStyle: 'long' })
$td(post.createdAt, 'short')
```

### `$tdr` {#$tdr}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

Formatér en dato som relativ tid ("for 3 dage siden") med `Intl.RelativeTimeFormat`.

```ts
$tdr(Date.now() - 5 * 60_000) // '5 minutes ago' in en
```

## Skift og links {#switching-and-links}

### `$switchLocale` {#$switchlocale}

```ts
(locale: string) => Promise<boolean>
```

Naviger til den aktuelle side i en anden locale. Under `no_prefix` og hash-tilstand indlæser den
locale'ens oversættelser før navigationen; under `no_prefix` erstattes routen på stedet (ingen
ny historikpost). En ukendt locale ignoreres.
Kaldet er asynkront: brug `await` for at køre kode efter navigationen. Det resolver til `true`, når
locale'ens ordbog er aktiv, og `false`, når den ikke er: chunken kunne ikke indlæses (den aktuelle
ordbog bevares; kald den igen for at prøve igen), eller et nyere skift vandt.

```ts
await $switchLocale('de')
```

### `$switchLocalePath` {#$switchlocalepath}

```ts
(locale: string) => string
```

Stien til den aktuelle side i en anden locale, uden at navigere.

```vue
<NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
```

### `$switchLocaleRoute` {#$switchlocaleroute}

```ts
(locale: string) => RouteLocationRaw
```

Route-objektet for den aktuelle side i en anden locale, uden at navigere, eller en URL-streng
for en locale på sin egen `baseUrl`. Under `trailingSlash` har objektet `path` og `fullPath`,
der følger reglen, med `query` og `hash` uændret, og `router.push` eller et link bevarer dem.

### `$switchRoute` {#$switchroute}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => Promise<void>
```

Naviger til en anden route og behold den aktive locale eller skift til `toLocale`. Asynkron ligesom
`$switchLocale`.

```ts
$switchRoute('/about') // active locale
$switchRoute({ name: 'about' }, 'de') // switch to de
```

### `$localePath` {#$localepath}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => string
```

Resolve en sti i den angivne locale eller den aktive. En streng med et `http(s):`-, `mailto:`-
eller `tel:`-skema returneres uændret: send ikke brugerinput ukontrolleret videre som linkmål.

En strengsti læses som den side, den viser, så en locales brugerdefinerede sti anvendes også.

```ts
$localePath('/about') // '/about' in en, '/de/ueber-uns' in de with localeRoutes
$localePath({ name: 'about' }, 'fr') // '/fr/about'
```

### `$localeRoute` {#$localeroute}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => RouteLocationResolved
```

Resolve en route i den angivne locale eller den aktive. Et almindeligt objekt, der er sikkert at gemme i state. Når en parameter skal
escapes, har det `path`, `fullPath`, `query` og `hash`, men ingen `name` eller `params`: det er stien, der giver routeren
den kodede URL. For en locale på et andet domæne er `path` og `fullPath` absolutte, hvilket routeren ikke kan håndtere:
sådan et link skal gå gennem `<i18n-link>` eller `$localePath`.

### `$getRouteName` {#$getroutename}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric, locale?: string) => string
```

Route-navnet uden locale-præfiks — det navn, oversættelserne er nøglet efter.

```ts
$getRouteName() // 'about' on /de/about
```

## Sidekonfiguration {#page-config}

### `$defineI18nRoute` {#$definei18nroute}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

Registrer locale-konfiguration og oversættelser pr. side inde fra en komponent.
Flettes ind i den aktive locale og anvendes igen, når locale'en skifter.

Kald den i en sides `<script setup>`, altid destruktureret fra `useNuxtApp()`. Buildet læser `locales`, `localeRoutes` og `disableMeta` fra kaldet; på runtime er det kun `locales`, der betyder noget (inline-oversættelser flettes for den aktive locale). Alle regler: [Sidekonfiguration](/da/guide/per-component-translations).

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: { en: '/about', de: '/ueber-uns' },
})
</script>
```

### `$setI18nRouteParams` {#$seti18nrouteparams}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

Sæt parametre pr. locale for den aktuelle route, så et dynamisk segment kan variere fra sprog til sprog.
Kald den under SSR, før head renderes.

Parametrene ryddes, når en navigation til en anden sti gennemføres, også fra `/news/1` til `/news/4`, som beholder route-navnet. Detaljer: [Lokaliserede stier](/da/guide/custom-locale-routes).

```ts
$setI18nRouteParams({
  en: { slug: 'my-post' },
  de: { slug: 'mein-beitrag' },
})
```

## Runtime-oversættelser {#runtime-translations}

### `$mergeTranslations` {#$mergetranslations}

```ts
(newTranslations: Translations) => void
```

Flet oversættelser ind i den aktive locale på runtime, så de tilsidesætter det indlæste.

Deep-merger ind i den aktive locales aktuelle side-chunk; nøgler, der ikke nævnes, bevares.

```ts
$mergeTranslations({ banner: { title: 'Sale' } })
```

### `$setTranslation` {#$settranslation}

```ts
(key: string, value: unknown) => void
```

Erstat værdien ved `key` i den aktive ordbog. Dette er en erstatning, ikke en fletning —
brug `$mergeTranslations`, når eksisterende søskende skal bevares.

```ts
$setTranslation('banner', { title: 'Sale' }) // drops other keys under banner
$setTranslation('banner.title', 'Sale') // dotted path
```

### `$loadPageTranslations` {#$loadpagetranslations}

```ts
(locale: string, routeName: string, translations: Translations) => Promise<void>
```

Indlæs oversættelser til en side på runtime, til indhold hvis nøgler ikke kendes på build-tidspunktet.

Flettes ind i `(locale, routeName)`-chunken i hukommelsen, og skærmen opdateres, når den chunk er aktiv. Der hentes ingen payload her: for en side, der endnu ikke er indlæst, venter oversættelserne, og når dens fil indlæses, ligger de oven på den.

```ts
await $loadPageTranslations('en', 'about', { title: 'About us' })
```

### `$resolveTranslations` {#$resolvetranslations}

```ts
() => Translations
```

Alle oversættelser, der aktuelt er i hukommelsen for den aktive locale og route, som et træ.
Skrivebeskyttet visning af, hvad `$t()` kan resolve lige nu.

Behandl resultatet som skrivebeskyttet.

### `$setMissingHandler` {#$setmissinghandler}

```ts
(handler: MissingHandler | null) => void
```

Installer et callback, der kaldes for hver nøgle, som ikke kan resolves. Angiv `null` for at fjerne det.

Handleren kører i stedet for udviklingsadvarslen.

```ts
$setMissingHandler((locale, key, routeName) => {
  console.error(`[i18n] missing ${key} in ${locale} (${routeName})`)
})
```

### `$clearCache` {#$clearcache}

```ts
() => void
```

Smid alle cachede oversættelses-chunks væk, og genindlæs den aktuelle sides ordbog. Siden
bliver ved med at vise sine nuværende oversættelser, indtil de nye ankommer. Dev-HMR kalder den ved
hver ændring af en oversættelsesfil.

```ts
const { clearCache } = useI18n()
clearCache()
```

En mislykket genindlæsning bevarer den aktuelle ordbog.
