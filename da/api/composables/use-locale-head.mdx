# 🌍 `useLocaleHead` Composable

`useLocaleHead`-composablen er en utility i `Nuxt I18n Micro`, der hjælper dig med at håndtere SEO-attributter og HTML meta-tags for lokaliserede ruter. Den genererer dynamisk attributter for `lang` og `dir` for HTML-dokumentet og opretter `meta`- og `link`-tags for at forbedre SEO for dit lokaliserede indhold.

## ⚙️ Options

```ts
useLocaleHead(options: UseLocaleHeadOptions): { metaObject: Ref<{ htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string }; link: { href: string; hreflang?: string; rel: string; [key: string]: string | undefined }[]; meta: { content: string; property: string; [key: string]: string }[] }, MetaObject | { htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string }; link: { href: string; hreflang?: string; rel: string; [key: string]: string | undefined }[]; meta: { content: string; property: string; [key: string]: string }[] }>; updateMeta: () => void }
```

SEO head-tags for den aktuelle rute: `hreflang`-alternativer for hver locale plus
`x-default`, et canonical-link, `og:locale` og `lang`/`dir` på `<html>`.

Kun nødvendig, når `meta` er deaktiveret, eller standarderne skal justeres — med `meta: true`
registrerer modulet selv de samme tags.

**Returnerer** — en ref, der holder head-objektet, klar til at sende til `useHead`

```ts
const head = useLocaleHead({ addSeoAttributes: true })
useHead(head)
```

## 🛠️ Returværdier

`useLocaleHead`-composablen returnerer et reaktivt objekt og en updater-funktion, som du bør
kalde, når kilde-data ændres. Begge former er i signaturen ovenfor, genereret fra
kildekoden.

### `metaObject`

Reaktiv head-payload (html attrs, meta, link) egnet til `useHead(metaObject)`.

- **Eksempel**:
  ```js
  const { metaObject } = useLocaleHead()
  useHead(metaObject)
  ```

### `updateMeta`

Genberegner `metaObject` baseret på den aktuelle rute, locale og config. Kald den, når inputs
ændres — for eksempel ved et rute-skift.

- **Eksempel**:
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  useHead(metaObject)
  watch(
    () => route.fullPath,
    () => updateMeta(),
    { immediate: true },
  )
  ```

### Adgang til `link` og `meta`

`link`- og `meta`-arrays er tilgængelige via `metaObject.value`:

- **Eksempel**:
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  updateMeta()
  console.log(metaObject.value.link)
  // Output: [{ id: 'i18n-can', rel: 'canonical', href: 'https://example.com/about' }, ...]
  console.log(metaObject.value.meta)
  // Output: [{ id: 'i18n-og', property: 'og:locale', content: 'en_US' }, ...]
  ```

## 🛠️ Eksempler på brug

### Grundlæggende brug

Generér locale-specifikke head-attributter med standard-options.

```js
const head = useLocaleHead()
```

### Tilpas identifier-attributten

Brug en brugerdefineret identifier-attribut for de genererede tags.

```js
const head = useLocaleHead({ identifierAttribute: 'data-i18n' })
```

### Deaktivér SEO-attributter

Generér head-attributter uden at tilføje SEO-relaterede meta- og link-tags.

```js
const head = useLocaleHead({ addSeoAttributes: false })
```

### Specificér en base-URL

Sæt en brugerdefineret base-URL for canonical og alternate URL'er.

```js
const head = useLocaleHead({ baseUrl: 'https://mywebsite.com' })
```

## 🚀 Yderligere funktioner

### SEO meta- og link-tags

Når `addSeoAttributes` er aktiveret, genererer composablen automatisk følgende tags:

- `og:locale` for den aktuelle locale (`language_TERRITORY`, underscore). Afledt fra `locale.og` eller konverteret fra `locale.iso`, når det er muligt.
- `og:url` for den canonicale URL for siden.
- `og:locale:alternate` for alternative sprogversioner.
- `rel="canonical"` og `rel="alternate"`-links til SEO-optimering.
- `hreflang="x-default"`-link, der peger på standard-locale's URL. Dette fortæller søgemaskiner, hvilken URL brugere, hvis sprog ikke matcher nogen af de definerede locales, skal vises.

### Dynamisk locale og retning

Composablen bestemmer dynamisk `lang`- og `dir`-attributterne baseret på den aktuelle rutes locale og sikrer, at dit HTML-dokument er korrekt konfigureret til internationale brugere.

### Håndtering af lokaliserede ruter

Hvis dine ruter er præfikset med locale-koder (f.eks. `/en/about`), justerer composablen intelligent den fulde sti til generering af URL'er og sikrer, at SEO-attributter er præcise og relevante.

Denne composable forenkler processen med at optimere din Nuxt-applikation for internationale målgrupper og sikrer, at dit site er godt forberedt til globale søgemaskiner og brugere.

## 🛠️ Eksempel på brug

Følgende eksempel demonstrerer, hvordan man bruger `useLocaleHead`-composablen inde i en Vue-komponent med standard-indstillinger:

```vue
<script setup>
import { useRoute, watch } from '#imports'
const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({
  addDirAttribute: true,
  identifierAttribute: 'id',
  addSeoAttributes: true,
})
useHead(metaObject)
watch(
  () => route.fullPath,
  () => updateMeta(),
  { immediate: true },
)
</script>
```

### Forklaring af koden

- **`useLocaleHead`-composable**: Denne composable kaldes i `<script setup>`-sektionen og returnerer et objekt, der indeholder `htmlAttrs`, `meta` og `link`.

- **`<html>`-tag**: `lang`- og `dir`-attributterne for HTML-dokumentet bestemmes dynamisk baseret på den aktuelle locale og anvendes på `<html>`-tagget.

- **`<head>`-sektion**:
  - **Meta-tags**: SEO-relaterede meta-tags genereres, herunder `og:locale`, `og:url` og `rel="canonical"`- og `rel="alternate"`-tags til at specificere alternative sprogversioner af siden.
  - **Link-tags**: Canonical-links, links til alternative sprogversioner og `hreflang="x-default"`-linket (der peger på standard-locale-URL'en) inkluderes.

- **`<body>`-sektion**: Sidens hovedindhold vises her. I dette eksempel bruges en simpel header og et afsnit.

### 📝 Bemærkninger

1. **Attributter**: De anvendte attributter (`lang`, `dir`, `rel`, `href`, `hreflang`, `property`, `content`) ekstraheres fra objektet returneret af `useLocaleHead`.

2. **SEO-tag-generering**: Hvis `addSeoAttributes`-optionen er sat til `true`, genererer composablen automatisk SEO-tags for den aktuelle locale.

3. **Base-URL**: Du kan sætte din brugerdefinerede base-URL ved hjælp af `baseUrl`-optionen for at generere canonical- og alternate-links korrekt.

Dette eksempel demonstrerer, hvor let det er at integrere `useLocaleHead` i din applikations komponenter for at sikre korrekte SEO-attributter og forbedre søgemaskineindeksering af lokaliserede sider.

## 🧩 Tilpasning & livscyklus

- `useLocaleHead` abonnerer ikke på ændringer selv. Den returnerer `metaObject` og `updateMeta`.
- Du bør kalde `updateMeta()`, når inputs ændres (typisk ved rute-skift), for eksempel fra et plugin:

```ts
// plugins/02.meta.ts
export default defineNuxtPlugin(() => {
  const route = useRoute()
  const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
  useHead(metaObject)
  if (import.meta.server) updateMeta()
  else
    watch(
      () => route.fullPath,
      () => updateMeta(),
      { immediate: true },
    )
})
```

## Hvornår du skal bruge `useI18nHead` i stedet

Når `meta: true` (standarden), foretræk [`useI18nHead`](/api/composables/use-i18n-head) til **per-side**-tilsidesættelser (brugerdefineret hreflang, ekstra `og:title`, delvis deaktivering). Brug kun `useLocaleHead` direkte, når `meta: false`, eller når du selv håndterer `useHead`.
