# 🌍 Composablen `useLocaleHead`

Composablen `useLocaleHead` er en hjælper i `Nuxt I18n Micro`, der hjælper dig med at styre SEO-attributter og HTML-metatags for lokaliserede ruter. Den genererer dynamisk attributter for `lang` og `dir` for HTML-dokumentet og opretter `meta`- og `link`-tags for at forbedre SEO for dit lokaliserede indhold.

## ⚙️ Indstillinger

```ts
useLocaleHead(options: UseLocaleHeadOptions): { metaObject: Ref<{ htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string }; link: { href: string; hreflang?: string; rel: string; [key: string]: string | undefined }[]; meta: { content: string; property: string; [key: string]: string }[] }, MetaObject | { htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string }; link: { href: string; hreflang?: string; rel: string; [key: string]: string | undefined }[]; meta: { content: string; property: string; [key: string]: string }[] }>; updateMeta: () => void }
```

SEO-head-tags for den aktuelle rute: `hreflang`-alternater for hvert locale plus `x-default`, et canonical-link, `og:locale` og `lang`/`dir` på `<html>`.

Kun nødvendig, når `meta` er deaktiveret, eller når standarderne skal justeres. Med `meta: true` registrerer modulet selv de samme tags.

**Returnerer** — en ref, der holder head-objektet, klar til at sende til `useHead`

```ts
const head = useLocaleHead({ addSeoAttributes: true })
useHead(head)
```

## 🛠️ Returværdier

Composablen `useLocaleHead` returnerer et reaktivt objekt og en opdateringsfunktion, som du skal kalde, når kildedataene ændres. Begge former findes i signaturen ovenfor, genereret fra kilden.

### `metaObject`

Reaktiv head-payload (html-attrs, meta, link), egnet til `useHead(metaObject)`.

- **Eksempel**:
  ```js
  const { metaObject } = useLocaleHead()
  useHead(metaObject)
  ```

### `updateMeta`

Genberegner `metaObject` baseret på aktuel rute, locale og config. Kald den, når inputs ændres, f.eks. ved et ruteskift.

- **Eksempel**:
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  useHead(metaObject)
  watch(
    () => route.fullPath,
    () => updateMeta(),
    { immediate: true },
  )
  ```

### Adgang til `link` og `meta`

Arrays `link` og `meta` er tilgængelige via `metaObject.value`:

- **Eksempel**:
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  updateMeta()
  console.log(metaObject.value.link)
  // Output: [{ id: 'i18n-can', rel: 'canonical', href: 'https://example.com/about' }, ...]
  console.log(metaObject.value.meta)
  // Output: [{ id: 'i18n-og', property: 'og:locale', content: 'en_US' }, ...]
  ```

## 🛠️ Eksempler på brug

### Grundlæggende brug

Generér locale-specifikke head-attributter med standardindstillinger.

```js
const head = useLocaleHead()
```

### Tilpas identifikator-attribut

Brug en brugerdefineret identifikator-attribut for de genererede tags.

```js
const head = useLocaleHead({ identifierAttribute: 'data-i18n' })
```

### Deaktivér SEO-attributter

Generér head-attributter uden at tilføje SEO-relaterede meta- og link-tags.

```js
const head = useLocaleHead({ addSeoAttributes: false })
```

### Angiv en base-URL

Sæt en brugerdefineret base-URL for canoniske og alternative URL'er.

```js
const head = useLocaleHead({ baseUrl: 'https://mywebsite.com' })
```

## 🚀 Yderligere funktioner

### SEO-meta- og link-tags

Når `addSeoAttributes` er aktiveret, genererer composablen automatisk følgende tags:

- `og:locale` for det aktuelle locale (`language_TERRITORY` med underscore). Udledes af `locale.og` eller konverteres fra `locale.iso`, når det er muligt.
- `og:url` for sidens canoniske URL.
- `og:locale:alternate` for alternative sprogversioner.
- `rel="canonical"` og `rel="alternate"`-links til SEO-optimering.
- `hreflang="x-default"`-link, der peger på standard-locales URL. Det fortæller søgemaskiner, hvilken URL de skal vise brugere, hvis sprog ikke matcher nogen af de definerede locales.

### Dynamisk locale og retning

Composablen bestemmer dynamisk `lang`- og `dir`-attributterne baseret på den aktuelle rutes locale og sikrer, at dit HTML-dokument er konfigureret korrekt til internationale brugere.

### Håndtering af lokaliserede ruter

Hvis dine ruter er præfikset med locale-koder (f.eks. `/en/about`), justerer composablen intelligent den fulde sti for URL-generering og sikrer, at SEO-attributter er nøjagtige og relevante.

Denne composable forenkler processen med at optimere din Nuxt-applikation til internationale målgrupper og sikrer, at dit site er godt forberedt til globale søgemaskiner og brugere.

## 🛠️ Eksempel på brug

Følgende eksempel viser, hvordan du bruger composablen `useLocaleHead` i en Vue-komponent med standardindstillinger:

```vue
<script setup>
import { useRoute, watch } from '#imports'
const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({
  addDirAttribute: true,
  identifierAttribute: 'id',
  addSeoAttributes: true,
})
useHead(metaObject)
watch(
  () => route.fullPath,
  () => updateMeta(),
  { immediate: true },
)
</script>
```

### Forklaring af koden

- **Composablen `useLocaleHead`**: Denne composable kaldes i `<script setup>`-sektionen og returnerer et objekt med `htmlAttrs`, `meta` og `link`.

- **`<html>`-tag**: `lang`- og `dir`-attributterne for HTML-dokumentet bestemmes dynamisk baseret på det aktuelle locale og anvendes på `<html>`-tagget.

- **`<head>`-sektionen**:
  - **Meta-tags**: SEO-relaterede metatags genereres, inklusive `og:locale`, `og:url` og `rel="canonical"` og `rel="alternate"`-tags til at angive alternative sprogversioner af siden.
  - **Link-tags**: Canoniske links, links til alternative sprogversioner og `hreflang="x-default"`-linket (som peger på URL'en for standard-locale) inkluderes.

- **`<body>`-sektionen**: Sidens hovedindhold vises her. I dette eksempel bruges en simpel header og et afsnit.

### 📝 Bemærkninger

1. **Attributter**: De anvendte attributter (`lang`, `dir`, `rel`, `href`, `hreflang`, `property`, `content`) hentes fra objektet, `useLocaleHead` returnerer.

2. **SEO-tag-generering**: Hvis `addSeoAttributes` er `true`, genererer composablen automatisk SEO-tags for det aktuelle locale.

3. **Base-URL**: Du kan sætte din egen base-URL med `baseUrl`-indstillingen for korrekt at generere canoniske og alternative links.

Dette eksempel viser, hvor let det er at integrere `useLocaleHead` i din applikations komponenter for at sikre korrekte SEO-attributter og forbedre søgemaskinernes indeksering af lokaliserede sider.

## 🧩 Tilpasning og livscyklus

- `useLocaleHead` abonnerer ikke på ændringer af sig selv. Den returnerer `metaObject` og `updateMeta`.
- Du skal kalde `updateMeta()`, når inputs ændres (typisk ved ruteskift), for eksempel fra et plugin:

```ts
// plugins/02.meta.ts
export default defineNuxtPlugin(() => {
  const route = useRoute()
  const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
  useHead(metaObject)
  if (import.meta.server) updateMeta()
  else
    watch(
      () => route.fullPath,
      () => updateMeta(),
      { immediate: true },
    )
})
```

## Hvornår du bør bruge `useI18nHead` i stedet

Når `meta: true` (standard), foretræk [`useI18nHead`](/api/composables/use-i18n-head) til **overrides pr. side** (brugerdefineret hreflang, ekstra `og:title`, delvis deaktivering). Brug kun `useLocaleHead` direkte, når `meta: false`, eller når du selv styrer `useHead`.
