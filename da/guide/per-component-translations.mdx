---

`$defineI18nRoute` angiver i18n-indstillinger for én side inde fra selve siden. Brug den, når en side kun findes i visse locales, har brug for sin egen lokaliserede sti, har nogle få egne oversættelser eller ikke må få hreflang/canonical-tags. Modulet læser kaldet ved build-tid og bager det ind i de genererede ruter.

## Begræns en side til visse locales {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

Kun `/product` og `/de/product` genereres under standardstrategien `prefix_except_default`; siden har ingen rute i noget andet locale. Det samme kan angives fra `nuxt.config.ts` med [`routeLocales`](/da/api/module-options#routelocales).

`$defineI18nRoute` er en Nuxt app-injektion, ikke en compiler-makro: hent den altid fra `useNuxtApp()`, og kald den med `$`. Kun `$defineI18nRoute(` genkendes af build-trinnet.

## Tilføj inline-oversættelser {#add-inline-translations}

Send et objekt i stedet for et array. Dets nøgler er de tilladte locales, og dets værdier flettes ind i sidens ordbog for det aktive locale.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Inline-oversættelser leveres inde i sidekomponenten for alle locales. Foretræk [sideoversættelsesfiler](/da/guide/translations) til alt, der er større end nogle få nøgler; brug inline-nøgler til selvstændige sider og komponenter.

## Angiv lokaliserede stier {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

Med `prefix_except_default` og `defaultLocale: 'en'` giver dette `/welcome` og `/de/willkommen`. En `path` inde i et inline locale-objekt gør det samme: `locales: { de: { path: '/willkommen' } }`. Dynamiske parametre, indlejrede ruter og alternativet på konfigurationsniveau er beskrevet i [Lokaliserede stier](/da/guide/custom-locale-routes).

## Slå SEO-tags fra {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

Alternativet på konfigurationsniveau er [`routeDisableMeta`](/da/api/module-options#routedisablemeta). Hvad tags'ene er, står på siden [SEO](/da/guide/seo).

## Hvad buildet kan læse {#what-the-build-can-read}

Build-trinnet finder kaldet i hver sidefil og evaluerer dets argument uden at køre din app. Det virker, når konfigurationen er:

- et literalt objekt (strenge, arrays, indlejrede objekter, template literals, ternære udtryk på `process.env.NODE_ENV`);
- bygget af konstanter erklæret i samme `<script setup>` (`const locales = ['en', 'de']`, inklusive spreads);
- et array af objekter med et `code`-felt (`[{ code: 'en' }, { code: 'de' }]`).

Det kan ikke læse værdier importeret fra et andet modul eller noget, der kræver din app ved runtime (composables, `await`, hentede data). I så fald logger buildet `Ignored the $defineI18nRoute() config in <file>`, og siden beholder standard-locales og -ruter.

Ved runtime fletter kaldet kun inline-oversættelserne for det aktuelle locale og fletter dem igen, når localet skifter. `locales`, `localeRoutes` og `disableMeta` får kun virkning gennem buildet, så ændringer af dem kræver et nyt build (dev-serveren genbygger ved gem).
