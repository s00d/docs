---
title: "Brugerdefineret locale-detektion"
description: "Vælg selv locale'en — ud fra domæne, header eller brugerprofil — med et server-plugin og useI18nLocale().setLocale()."
---

Den indbyggede detektion læser URL'en, en cookie og `Accept-Language`. Når locale'en afhænger af noget andet — domænet, en geo-header sat af dit CDN, en brugerprofil — så sæt den selv i et plugin, der kører før i18n-pluginet. Modulet indlæser derefter den locales oversættelser og bruger den til omdirigeringer, præcis som hvis det selv havde detekteret den. Reglerne for, hvornår en valgt locale vinder over URL'en, står på [Locale-detektion](/da/guide/locale-detection); denne side viser, hvordan du kobler din egen kilde på.

## Sæt locale'en i et server-plugin {#set-the-locale-in-a-server-plugin}

```ts
// plugins/i18n-locale.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10, // before the i18n plugin (order -5)
  setup() {
    const { setLocale } = useI18nLocale()
    const host = (useRequestHeaders(['host']).host ?? '').split(':')[0]! // without the port

    if (host.endsWith('.de')) setLocale('de')
    else if (host.endsWith('.fr')) setLocale('fr')
  },
})
```

`setLocale(code)` skriver locale-tilstanden (`useState('i18n-locale')`) og, når en locale-cookie er konfigureret, cookien. Brug den i stedet for selv at skrive `useState` eller `useCookie`. Angiv kun koder for aktiverede locales.

Behold pluginet som `.server.ts`, når det læser request-headers: de findes ikke i browseren. Et `.client.ts`-plugin er stedet til kilder, der kun findes i browseren, som f.eks. `localStorage`.

## Slå det indbyggede Accept-Language-trin fra {#turn-off-the-built-in-accept-language-step}

Dit plugin og `Accept-Language` kan være uenige. For kun at lade din kode (plus URL'en og cookien) bestemme, skal du slå headeren fra:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    autoDetectLanguage: false,
  },
})
```

[`autoDetectLanguage`](/da/api/module-options#autodetectlanguage) styrer kun header-trinnet. URL'en og en gyldig cookie tæller stadig.

## Hvad der sker derefter {#what-happens-next}

Effekten af `setLocale` afhænger af [strategien](/da/guide/strategy):

| Strategi | Effekt af `setLocale('de')` i pluginet |
| --- | --- |
| `no_prefix` | Siden renderes på tysk; URL'en ændres ikke. |
| `prefix`, `prefix_except_default` | På en sti uden præfiks, hvor [`autoDetectPath`](/da/api/module-options#autodetectpath) tillader omdirigeringer (som standard kun `/`), svarer serveren med `302` til den tyske URL. En URL med locale-præfiks beholder det. |
| `prefix_and_default` | Ingen omdirigering: URL'en uden præfiks er en gyldig side for standard-locale'en. |

Under præfiks-strategierne er en locale i URL'en brugerens valg, og dit plugin tilsidesætter den ikke. `autoDetectPath: '*'` er undtagelsen: serveren flytter så URL'er med præfiks ud fra cookie og `Accept-Language` og ignorerer tilstanden, men `setLocale()` skriver også cookien, når en sådan er konfigureret, så fra næste request kan dit plugins valg omdirigere en URL med præfiks. Behold `'/'` eller brug `'no_prefix'`, når eksplicitte locale-URL'er skal vinde. Brug dit plugin til at vælge, hvor en besøgende lander, ikke til at omskrive links, vedkommende har fulgt.

## Respektér en locale, brugeren har valgt {#respect-a-locale-the-user-picked}

Når en bruger skifter sprog, skriver skiftet cookien. Spring din egen detektion over, når der allerede er en gyldig præference:

```ts
// plugins/i18n-locale.server.ts
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10,
  setup() {
    const { getPreferredLocale, setLocale, validLocales } = useI18nLocale()
    if (getPreferredLocale()) return // valid state or cookie: keep it

    const country = useRequestHeaders(['x-country'])['x-country']
    if (country === 'JP') return setLocale('ja')

    const header = useRequestHeaders(['accept-language'])['accept-language']
    setLocale(detectLocaleFromAcceptLanguage(header, validLocales))
  },
})
```

`getPreferredLocale()` returnerer kun tilstanden eller cookien, når den er en aktiveret locale, så en forældet cookie stopper ikke detektionen. `detectLocaleFromAcceptLanguage` er den q-værdi-bevidste matcher, som modulet selv bruger (installer `@i18n-micro/utils` for at importere den); `setLocale(null)` gør ingenting.

## Ét domæne pr. locale {#one-domain-per-locale}

Hvis hvert domæne skal servere sine egne locales, behøver du ikke et plugin: giv hver locale en `baseUrl`, sæt `baseDefault: true` på hvert domænes standard-locale, og byg én gang (et statisk site kører stadig `nuxi generate` pr. domæne). Se [Lag og domæner](/da/guide/layers#multiple-domains).
