---
title: "Runtime-overstyringer"
description: "Skift standard-locale, fallback-locale eller deaktiverede locales pr. instans af ét build med miljøvariabler eller runtimeConfig."
---

Runtime-overstyringer lader ét build-artefakt køre med forskellige locale-indstillinger pr. miljø eller tenant uden at bygge igen. Du kan ændre standard-locale, fallback-locale og hvilke locales der er deaktiveret. Routing, redirects, rendering og serverhjælpere bruger de overstyrede værdier, og det gør browseren også på en server-renderet side.

## Sæt overstyringer med miljøvariabler {#set-overrides-with-environment-variables}

```bash
NUXT_I18N_DEFAULT_LOCALE=de \
NUXT_I18N_FALLBACK_LOCALE=en \
NUXT_I18N_DISABLED_LOCALES=fr,it \
node .output/server/index.mjs
```

| Variabel | Alias |
| --- | --- |
| `NUXT_I18N_DEFAULT_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE` |
| `NUXT_I18N_FALLBACK_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE` |
| `NUXT_I18N_DISABLED_LOCALES` (kommasepareret) | `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES` |

Serveren læser dem én gang ved start; genstart for at anvende en ændring. På en server-renderet side får browseren de afgjorte værdier fra serveren. Med `ssr: false` er der ingen server-rendering, og browseren har intet miljø: kun `runtimeConfig.public.i18nRuntime` gælder der, og browseren logger advarslerne nedenfor.

## Sæt overstyringer i runtimeConfig {#set-overrides-in-runtimeconfig}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

En værdi sat i `runtimeConfig.public.i18nRuntime` vinder over `NUXT_I18N_*`-variablen for det samme felt.

Må ikke forveksles med build-time-variablen `DEFAULT_LOCALE`, som erstatter `defaultLocale` under build og ikke kræver runtime-understøttelse.

## Hvad der kan og ikke kan ændres {#what-can-and-cannot-change}

| Indstilling | Ved runtime |
| --- | --- |
| `defaultLocale` | Ja under `prefix` og `no_prefix`. Under `prefix_except_default` og `prefix_and_default` er den fastlagt ved build (dens sider er routerne uden præfiks); en overstyring ignoreres med en advarsel. |
| `fallbackLocale` | Ja. |
| `disabledLocales` | Lægges til de locales, der er deaktiveret ved build; genaktiverer aldrig en. Build-standarden kan ikke deaktiveres under `prefix_except_default` / `prefix_and_default`. |
| `strategy` | Nej. En runtime-strategi ignoreres med en advarsel; byg ét artefakt pr. strategi. |

Ugyldige værdier ødelægger aldrig appen. Hvert tilfælde logger én advarsel pr. serverproces:

- at deaktivere alle locales ignoreres;
- en `defaultLocale`, der ikke er aktiveret, falder tilbage til den første aktiverede locale;
- en `fallbackLocale`, der ikke er aktiveret, beholder build-værdien, hvis den er aktiveret, ellers er der ingen fallback.

## Læs den effektive konfiguration {#read-the-effective-config}

```vue
<script setup lang="ts">
const { $getI18nConfig } = useNuxtApp()
const config = $getI18nConfig() // build config with overrides applied
</script>
```

Behandl den som skrivebeskyttet: på serveren deles den af alle forespørgsler og er frosset under udvikling; browserens kopi er ikke frosset. Import af konfigurationen fra `#build/i18n.strategy.mjs` giver build-værdierne uden overstyringer.

## Deaktiverede locales og statiske filer {#disabled-locales-and-static-files}

En locale, der er deaktiveret ved runtime, svarer 404 på sine routes og sin payload-route, men dens payload-filer ligger stadig i `.output/public/_locales/`, og en statisk filserver returnerer dem. Når disse filer ikke må kunne nås, så deaktiver locale ved build med `disabled: true`.
