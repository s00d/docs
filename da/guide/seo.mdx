Med `meta: true` (standard) får hver lokaliseret side `<html lang dir>`, et canonical-link, `hreflang`-alternativer, `x-default` og Open Graph-locale-tags. Du har brug for denne side, når du vil angive den offentlige origin, justere hvilke locales der optræder i tags, eller tilsidesætte dem for én side. De fleste websteder har kun brug for en `site.url` eller `metaBaseUrl` og korrekte `iso`-koder.

## Minimal opsætning {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

`/de/about` renderer derefter:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Tekstretning {#text-direction}

`<html dir>` kommer fra localens `dir`. Uden en sådan får et sprog, der skrives fra højre mod venstre, `rtl`, aflæst ud fra `iso` (eller `code`): arabisk, hebraisk, persisk, urdu og nogle få andre samt ethvert tag med et RTL-skriftsystem som `az-Arab`. Alle andre locales får ingen `dir`-attribut, hvilket browsere læser som `ltr`.

<Warning>

**`dir: 'auto'` koster parsetid på store sider** — `auto` på `<html>` får browseren til at udlede retningen ud fra indholdet, mens den parser. I Chromium vokser den omkostning hurtigere end siden: omkring 100 ms ved 5.000 elementer og 1 s ved 20.000. Brug det kun til en lille side, hvis sprog du ikke kan kende.

</Warning>

## Hvilke tags du får {#which-tags-you-get}

- **hreflang**: ét tag pr. locale, der leverer siden, med værdien `iso` (eller `code`, når `iso` mangler) og dens URL med samme query som canonical. En side, der er begrænset med [Sidekonfiguration](/da/guide/per-component-translations) eller `routeLocales`, viser kun sine locales. [`hreflangBaseLanguage: true`](/da/api/module-options#hreflangbaselanguage) tilføjer også det rene sprog (`es-ES` → `es`) for den første regionale locale.
- **x-default**: standard-localens URL, kun når standard-localen leverer siden.
- **og:locale**: udledt af `iso` (`en-US` → `en_US`). Sæt `og` på localen, når mappingen ikke er direkte, f.eks. `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; uden nogen af dem skrives der ingen `og:locale`, og udviklingstilstanden advarer.
- **canonical / og:url**: den aktuelle URL uden query-parametre, bortset fra dem i [`canonicalQueryWhitelist`](/da/api/module-options#canonicalquerywhitelist) (standard `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Efter strategi:

| Strategi | hreflang og x-default | canonical, og:url, og:locale, html-attributter |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | ja | ja |
| `no_prefix` | nej (én URL leverer alle locales) | ja |

## Angiv den offentlige origin {#set-the-public-origin}

Absolutte URL'er bruger den første af:

1. [`metaBaseUrl`](/da/api/module-options#metabaseurl);
2. `site.url` fra `nuxt-site-config` (installeret af `@nuxtjs/seo`);
3. forespørgslens origin med `app.baseURL` tilføjet.

Fastlås en af de to første.

<Warning>

Fallbacken til forespørgslens origin læser `X-Forwarded-Host` og `X-Forwarded-Proto`, fordi [`metaTrustForwardedHost`](/da/api/module-options#metatrustforwardedhost) og `metaTrustForwardedProto` som standard er `true`. Det er kun sikkert bag en proxy, der overskriver disse headers; ellers kan en klient vælge værten i dine canonical-links, og en cache kan videregive den side.

Hvis appen kan nås direkte, så fastlås `metaBaseUrl`: i modsætning til at sætte begge indstillinger til `false` ignorerer den også en forfalsket `Host`. Se [Bag en proxy eller et CDN](/da/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

Fallbacken er nyttig, når én udrulning svarer for flere domæner: `https://site-a.com/en/about` og `https://site-b.com/en/about` får hver deres egen origin.

Med `baseUrl` på locales bruger en kendt vært sin egen `baseUrl` frem for `metaBaseUrl` og `site.url`, så canonical og `og:url` bliver på det domæne, og `hreflang` peger hver locale på dens domæne. Enhver anden vært bruger `metaBaseUrl`, ellers standard-localens `baseUrl`, ellers `site.url`, så en forfalsket `Host` ikke kan nå dine tags. Hvis ingen af dem er angivet, bevares fallbacken til forespørgslens origin, og buildet advarer. Se [Lag og domæner](/da/guide/layers#multiple-domains).

## Udelad locales eller sider {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Hvis standard-localen har `seo: false`, skrives der ingen `x-default`. For at slå tags fra for én side skal du bruge `disableMeta` i [Sidekonfiguration](/da/guide/per-component-translations#turn-off-seo-tags) eller [`routeDisableMeta`](/da/api/module-options#routedisablemeta) i konfigurationen.

## Tilsidesæt tags på én side {#override-tags-on-one-page}

Til CMS-indhold, hvor kun nogle oversættelser findes, eller hvor URL'er kommer fra et API, kan du erstatte de genererede tags med [`useI18nHead`](/da/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` kan også sætte eller fjerne `canonical`, `xDefault`, `ogLocale` og `ogUrl`; `disable` fjerner hele grupper (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Send en getter, så værdierne genberegnes efter et skift af locale. For slugs pr. locale skal du først sætte `$setI18nRouteParams` ([Lokaliserede stier](/da/guide/custom-locale-routes#per-locale-slugs)), så bruger de genererede alternativer dem allerede.

## Afsluttende skråstreg {#trailing-slash}

`$localePath`, `$switchLocalePath`, route-objektet fra `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, locale-omdirigeringer og SEO-URL'erne følger én regel for skråstreger: som standard `experimental.defaults.nuxtLink.trailingSlash` eller [`trailingSlash`](/da/api/module-options) i i18n-konfigurationen, når i18n-stier skal være anderledes.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) fungerer med dette modul via `nuxt-site-config` 4+. Angiv `nuxt-i18n-micro` først, så site-konfigurationen kan læse locales, og sæt `site.url` én gang — den forsyner også ovenstående tags.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Et oversat webstedsnavn og en oversat beskrivelse kommer fra nøglerne `nuxtSiteConfig.name` / `nuxtSiteConfig.description` i dine locale-filer. Fejlen `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` betyder, at `@nuxtjs/seo` er ældre end version 3; opgrader den ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
