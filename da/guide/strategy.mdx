Optionen `strategy` afgør, om et locale optræder i URL'en, og for hvilke locales. Vælg den én gang, før du offentliggør URL'er: ændrer du den senere, ændres alle links. Modulet genererer derefter de lokaliserede ruter ved build-tid, og `$localePath`, `<i18n-link>` og switcheren læser dem.

## De fire strategier {#the-four-strategies}

![Siden /about på en (standard) og de under hver strategi; de samme URL'er er listet i teksten nedenfor](/images/diagrams/strategies.svg)

**Type** `Strategies` · **Standard** `'prefix_except_default'`

URL-routingstrategi for locale-præfikser.

- `'no_prefix'` — intet locale i URL'en; localet gemmes i en cookie.
- `'prefix_except_default'` — præfiks på alle locales undtagen standard.
- `'prefix'` — altid præfiks, også for standard-localet.
- `'prefix_and_default'` — som `prefix`, men standard-localet er også tilgængeligt uden præfiks.

URL'er for en `about`-side med `defaultLocale: 'en'` og locales `en`, `de`:

| Strategi | Engelsk | Tysk | Serveres ikke |
| --- | --- | --- | --- |
| `prefix_except_default` (standard) | `/about` | `/de/about` | `/en` og `/en/about` giver 404 |
| `prefix` | `/en/about` | `/de/about` | `/about` omdirigerer til en URL med præfiks |
| `prefix_and_default` | `/about` og `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | localet er ikke i URL'en |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

Strategien er fastlagt ved build: en runtime-override af den ignoreres med en advarsel ([Runtime-overrides](/da/guide/runtime-overrides)).

## Hvilken skal du vælge {#which-one-to-choose}

- **`prefix_except_default`**: de fleste sites. Eksisterende URL'er uden præfiks fortsætter med at virke for standardsproget.
- **`prefix`**: alle sprog er ligestillede; `/` fører altid til en forside med præfiks.
- **`prefix_and_default`**: du har brug for, at både `/en/...` og URL'erne uden præfiks virker, for eksempel mens du flytter fra det ene til det andet. URL'er uden præfiks omdirigeres aldrig.
- **`no_prefix`**: apps bag et login eller én URL pr. side for alle sprog. Localet kommer fra en cookie eller `?locale=`. Søgemaskiner ser ét sprog pr. URL, så der udsendes ingen `hreflang`-alternativer.

Hvordan localet vælges for en URL, og hvornår en besøgende omdirigeres, står på [Locale-detektion](/da/guide/locale-detection).

## Genererede ruter {#generated-routes}

Ved build-tid får hver side de ruteposter, dens strategi kræver. Hver post har `meta.i18n = { name, locales }`: den side, den viser, og de locales, den betjener. Links, skift og omdirigeringer besvares alle ud fra disse poster, så en URL, modulet udleverer, altid er en, som routeren serverer.

Locales, der deler sidens sti, deler én post, `/:locale(de|fr)/about`. Et locale med sin egen sti får sin egen post med navnet `localized-<page>-<locale>`:

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

Brugerdefinerede stier, locale-lister pr. side og udelukkelse af en side fra lokalisering er beskrevet i [Lokaliserede stier](/da/guide/custom-locale-routes) og [Sidekonfiguration](/da/guide/per-component-translations). Præfikset `localized-` er [`localizedRouteNamePrefix`](/da/api/module-options#localizedroutenameprefix).

<Warning>

**Rutenavne genereres** — Hardkod ikke `localized-…`-navne i `router.push({ name })`. Send sidens eget navn til `$localeRoute` eller `<i18n-link>`; de vælger den rigtige post.

</Warning>

## Link til en side på et locale {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- Både navngivne ruter og stier virker. En sti matches mod de genererede ruter, så ethvert locales form af den accepteres.
- Et locale, der ikke betjener siden (se `locales` i [Sidekonfiguration](/da/guide/per-component-translations)), linker i stedet til det locales forside frem for en manglende side.
- Parametre pr. locale (en oversat slug) går gennem `$setI18nRouteParams`, se [Lokaliserede stier](/da/guide/custom-locale-routes).

Signaturerne findes under [Metoder](/da/api/methods).

## Detaljer om `no_prefix` {#no_prefix-details}

- [`localeCookie`](/da/api/module-options#localecookie) er som standard `'user-locale'` under `no_prefix`, så valget overlever en genindlæsning.
- `$switchLocale('de')` indlæser den tyske ordbog og erstatter den aktuelle historikpost; URL'en ændres ikke.
- Brugerdefinerede stier pr. locale virker stadig: med `globalLocaleRoutes: { about: { de: '/ueber-uns' } }` får tyske læsere `/ueber-uns`. Den URL renderes altid på tysk, uanset hvad den besøgende foretrækker, og en side begrænset til visse locales renderes i et af dem. En sti, som flere locales deler (`en` og `de` begge på `/page/:id`), renderer præferencen, når den er en af dem. Selve præferencen bevares: den næste side vender tilbage til den.
- [`noPrefixRedirect: true`](/da/api/module-options#noprefixredirect) omdirigerer den oprindelige sti for en side med en brugerdefineret sti i standard-localet: til den brugerdefinerede sti for den besøgendes locale, ellers standard-localets (`/about` → `/about-us`, når `en` har `/about-us`, → `/ueber-uns` med cookien `de`). Et locale uden egen brugerdefineret sti bliver på den oprindelige sti og renderes der. Sider med parametre omdirigeres ikke.

## Apps uden `pages/` {#apps-without-pages}

Med `pages: false` er der ingen sideruter at lokalisere. Brug kun rodoversættelsesfiler (`disablePageLocales: true`); detektion, cookien og `$switchLocale` virker stadig. Varianten `pages-false` af `test/fixtures/basic` i repositoriet er en fungerende opsætning.
