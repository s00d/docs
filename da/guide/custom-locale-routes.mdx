---
title: "Lokaliserede stier"
description: "Giv en side en forskellig URL pr. locale med localeRoutes eller globalLocaleRoutes, inklusive dynamiske parametre og slugs pr. locale."
---

Som standard leverer hver locale en side på den samme sti: `/en/about`, `/de/about`. Med lokaliserede stier kan hver locale bruge sine egne ord, f.eks. `/de/ueber-uns`, mens sidefilen forbliver den samme. Du angiver dem i siden med `$defineI18nRoute` eller for mange sider på én gang i `nuxt.config.ts`.

## I siden {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

Med `prefix_except_default` og `defaultLocale: 'en'` svarer siden på `/about`, `/de/ueber-uns` og `/fr/a-propos`. En locale uden en post beholder standardstien. Skriv stier uden locale-koden: præfikset tilføjes af [strategien](/da/guide/strategy), og en sti, der starter med locale-koden, logger en advarsel. Hvad kaldet ellers accepterer, står under [Sidekonfiguration](/da/guide/per-component-translations).

## I nuxt.config {#in-nuxt-config}

[`globalLocaleRoutes`](/da/api/module-options#globallocaleroutes) gør det samme for enhver side med dens sti som nøgle (eller dens route-navn, når det skrives uden en indledende skråstreg):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

Når en side sætter `localeRoutes`, og `globalLocaleRoutes` har den samme nøgle, vinder posten i konfigurationen.

## Dynamiske parametre {#dynamic-params}

Skriv parametre i en hvilken som helst Nuxt-form: `[id]`, `[[page]]`, `[...slug]` eller `:id()`. Parameternavnene skal matche sidefilen.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

Indlejrede sider tager en absolut understi (`/ueber-uns/team`) eller en sti relativ til forælderens lokaliserede sti (`team`).

## Links til lokaliserede sider {#linking-to-localized-pages}

Links opløses til den lokaliserede sti for mål-localen, uanset om du angiver et route-navn eller en almindelig sti:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

Route-navne kommer fra filstien (`pages/about/team.vue` er `about-team`), medmindre du angiver et med `definePageMeta({ name })`.

## Slugs pr. locale {#per-locale-slugs}

Når selve sluggen er forskellig pr. locale (`/our-products/red-shoe` vs. `/de/unsere-produkte/roter-schuh`), skal du fortælle sprogvælgeren, hvilke parametre den skal bruge, med `$setI18nRouteParams`, når dataene er indlæst:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

`$switchLocalePath('de')` og `<i18n-switcher>` linker derefter til `/de/unsere-produkte/roter-schuh`. Nøglerne er locale-koder, og værdierne er parametre efter navn (som i sidefilen).

En sprogvælger i layoutet renderes, før sidens asynkrone setup når hertil, så når renderingen slutter, omskriver modulet links i `<i18n-switcher>`, både i `app.vue` og i siden. Serverens HTML, en besøgende uden JavaScript og den første rendering på klienten stemmer så overens. Sæt parametrene under SSR for at få dette: med `lazy` eller `server: false` ændres links først efter hydrering. Nuxts SSR-streaming sender HTML'en, før parametrene kendes, så under streaming beholder links i den første HTML URL'ens egne parametre.

Kun sprogvælgerens egne links omskrives. Et håndskrevet `$switchLocalePath`-link skal renderes, efter at parametrene er sat, så placer det i den side, der sætter dem, også efter en `await`. I et layout renderes det først: dets server-HTML beholder URL'ens parametre, og hydreringen advarer om et mismatch. Brug `<i18n-switcher>` dér med dens slots og `custom*Style`-props til udseendet.

Parametrene tilhører den side, der satte dem:

- De fjernes, når en navigation til en anden sti gennemføres, så hver side sætter sine egne. En annulleret navigation lader dem blive.
- Hent `$setI18nRouteParams` fra `useNuxtApp()` eller `useI18n()` i `setup`, også når du kalder den senere i en `useAsyncData`-handler. Hentet dér kender funktionen sin side: hvis den besøgende er gået videre, gør et sent kald ingenting.
- Med `keepalive` får en side de parametre, den satte, tilbage, når den besøgende vender tilbage. `useI18nHead` gør det samme.

## Routes tilføjet i pages:extend {#routes-added-in-pagesextend}

Routes, du tilføjer i hooket `pages:extend`, har ingen sidefil, som `$defineI18nRoute` kan læses fra, og flere af dem deler ofte én wrapper-komponent. En route, der tilføjes uden et `name`, får det navn, Nuxt ville give dens sti (`/a/:id()` bliver til `a-id`), så sproglinks når frem til den, medmindre en anden route allerede har det navn; giv den i så fald et eksplicit `name`. Hold én liste, og del den op i sider og `globalLocaleRoutes` med route-navn som nøgle med `splitLocaleRoutes` fra `@i18n-micro/utils/split-locale-routes` (tilføj pakken til dine afhængigheder):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

Læg ikke lokaliserede stier i `route.meta`: de ville blive sendt med i klientens route-tabel.
