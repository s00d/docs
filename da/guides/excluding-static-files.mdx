# Udelukkelse af statiske filer fra i18n-routing

## Oversigt

Som standard udelukker nuxt-i18n-micro automatisk almindelige statiske filer fra i18n-routing-behandling. Du kan dog også konfigurere brugerdefinerede udelukkelsesmønstre for at forhindre, at bestemte stier behandles af i18n-systemet.

## Indbyggede udelukkelser

Modulet udelukker automatisk følgende filtyper og mønstre:

- **Sitemaps**: `/sitemap*.xml`, `/sitemap-en.xml` osv.
- **SEO-filer**: `/robots.txt`, `/favicon.ico`
- **PWA-filer**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Statiske assets**: filer med endelser som `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Interne Nuxt-stier**: enhver sti, der starter med `__` (som `/__nuxt/`)

## Brugerdefinerede udelukkelsesmønstre

Du kan definere brugerdefinerede udelukkelsesmønstre med `excludePatterns`-indstillingen:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Mønstertyper

### Strengmønstre

- **Eksakt match**: `'/api/health'` matcher præcist `/api/health`
- **Præfiks-match**: `'/admin'` matcher `/admin` og `/admin/dashboard`
- **Wildcards**: `'/api/*'` matcher `/api/users`, men ikke `/api/users/123`
- **Dybe wildcards**: `'/admin/**'` matcher `/admin/users` og `/admin/users/123`

### Regulære udtryk

Brug RegExp-objekter til kompleks mønstermatchning:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Brugstilfælde

### SEO-filer

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API-ruter

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Adminpaneler

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Statiske assets

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Sådan fungerer det

1. **Server-middleware**: En Nitro-middleware kører først for at tjekke udelukkelsesmønstre
2. **Sidebehandling**: Under sideopløsning springes udelukkede stier over
3. **Catch-all-rute**: Fallback-ruten tjekker udelukkelser før behandling
4. **Prerendering**: Udelukkede stier inkluderes ikke i prerenderede ruter

## Performance-indvirkning

- Udelukkelsestjek er optimerede og kører tidligt i request-livscyklussen
- Indbyggede mønstre bruger effektiv regex-matching
- Brugerdefinerede mønstre caches og genbruges
- Minimal performance-overhead for udelukkede stier

## Fejlfinding

### Statiske filer opfanges stadig

1. **Tjek mønstersyntaks**: Sørg for, at dine mønstre matcher den eksakte sti-struktur
2. **Brug regex til komplekse mønstre**: Streng-wildcards har begrænsninger
3. **Test mønstre**: Brug browserens udviklerværktøjer til at bekræfte den faktiske request-sti
4. **Tjek rækkefølgen**: Sørg for, at udelukkelsesmønstre er defineret før anden i18n-config

### Mønster virker ikke

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Debug-tilstand

Aktivér debug-tilstand for at se udelukkelsesbehandling:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Det logger udelukkelsesbeslutninger i konsollen.

## Migration fra workarounds

Hvis du brugte workarounds som route rules eller middleware, kan du nu erstatte dem med `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Den nye tilgang er mere pålidelig og fungerer på flere niveauer af routing-systemet.
