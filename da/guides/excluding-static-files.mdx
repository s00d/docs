# Udeladelse af statiske filer fra i18n-routing

## Oversigt

Som standard udelader nuxt-i18n-micro automatisk almindelige statiske filer fra i18n-routing-behandling. Du kan dog også konfigurere brugerdefinerede udeladelsesmønstre for at forhindre specifikke stier i at blive behandlet af i18n-systemet.

## Indbyggede udeladelser

Modulet udelader automatisk følgende filtyper og mønstre:

- **Sitemaps**: `/sitemap*.xml`, `/sitemap-en.xml` osv.
- **SEO-filer**: `/robots.txt`, `/favicon.ico`
- **PWA-filer**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Statiske assets**: Filer med endelser som `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Interne Nuxt-stier**: Enhver sti, der starter med `__` (som `/__nuxt/`)

## Brugerdefinerede udeladelsesmønstre

Du kan definere brugerdefinerede udeladelsesmønstre ved hjælp af `excludePatterns`-optionen:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Mønster-typer

### Streng-mønstre

- **Eksakt match**: `'/api/health'` - matcher præcis `/api/health`
- **Præfiks-match**: `'/admin'` - matcher `/admin` og `/admin/dashboard`
- **Wildcards**: `'/api/*'` - matcher `/api/users`, men ikke `/api/users/123`
- **Dybe wildcards**: `'/admin/**'` - matcher `/admin/users` og `/admin/users/123`

### Regulære udtryk

Brug RegExp-objekter til kompleks mønster-matching:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Brugsscenarier

### SEO-filer

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API-ruter

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Admin-paneler

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Statiske assets

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Sådan fungerer det

1. **Server-middleware**: En Nitro-middleware kører først for at tjekke udeladelsesmønstre
2. **Sidebehandling**: Under rute-resolvering springes udeladte stier over
3. **Catch-all-rute**: Fallback-ruten tjekker udeladelser før behandling
4. **Prerendering**: Udeladte stier medtages ikke i prerenderede ruter

## Indvirkning på ydeevne

- Udeladelses-tjek er optimerede og kører tidligt i request-livscyklussen
- Indbyggede mønstre bruger effektiv regex-matching
- Brugerdefinerede mønstre caches og genbruges
- Minimal ydelses-overhead for udeladte stier

## Fejlfinding

### Statiske filer opsnappes stadig

1. **Tjek mønster-syntaks**: Sørg for, at dine mønstre matcher den eksakte sti-struktur
2. **Brug regex til komplekse mønstre**: Streng-wildcards har begrænsninger
3. **Test mønstre**: Brug browserens dev tools til at verificere den faktiske request-sti
4. **Tjek rækkefølge**: Sørg for, at udeladelsesmønstre er defineret før anden i18n-config

### Mønster virker ikke

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Debug-mode

Aktivér debug-mode for at se udeladelses-behandling:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Dette logger udeladelses-beslutninger i konsollen.

## Migration fra workarounds

Hvis du brugte workarounds som route rules eller middleware, kan du nu erstatte dem med `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Den nye tilgang er mere pålidelig og fungerer på flere niveauer i routing-systemet.
