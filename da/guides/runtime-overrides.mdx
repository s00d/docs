# Runtime i18n-tilsidesættelser

Brug denne guide, når du har brug for at én build-artefakt skal køre med forskellige locale-standardværdier pr. miljø (for eksempel: forskellige tenant-instanser).

## Hvad kan tilsidesættes ved runtime

Modulet understøtter sikre runtime-tilsidesættelser for:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Disse tilsidesættelser lægges oven på build-time-konfigurationen fra `.nuxt/i18n.strategy.mjs` og `.nuxt/i18n.config.mjs`.

## Hvad kan ikke tilsidesættes ved runtime

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) er et build-time-anliggende, fordi det påvirker de genererede rutehåndtering.

Hvis du sender en runtime-strategi-tilsidesættelse, ignoreres den, og der udsendes en advarsel.

## RuntimeConfig-baserede tilsidesættelser

Angiv runtime-værdier under `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Tilsidesættelser via miljøvariabler

Du kan også konfigurere tilsidesættelser via miljøvariabler:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (kommasepareret, f.eks. `fr,it`)

Fallback-aliaser understøttes også:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Valideringsregler

Ved runtime validerer modulet tilsidesættelser for at undgå en ødelagt tilstand:

- Du kan ikke deaktivere alle locales.
- `defaultLocale` skal pege på en aktiveret locale.
- `fallbackLocale` skal findes i de deklarerede locales.

Hvis en tilsidesættelse er ugyldig, beholder modulet en sikker værdi og logger en advarsel.

## Bemærkninger til multi-instans-deployments

Denne runtime-funktion er designet til per-instans locale-aktivering og standardværdier uden at genbygge.

Hvis instanser kræver forskellige URL-strategier (`no_prefix` vs `prefix`), brug separate builds for hver strategi.

## Deaktiverede locales og statiske payloads

`runtimeConfig.public.i18nRuntime.disabledLocales` opdaterer routing, switcher og Nitro-payload-**handleren** — men Nitro serverer filer under `public/` **før** den handler.

Hvis `translationPayloads.publicAssets` (eller Node SSR's tvungne public-kopi) allerede har skrevet `/_locales/\{page\}/\{locale\}/data.json`, kan en runtime-deaktivering ikke skjule den fil. Foretræk `locale.disabled: true` ved build, så premerge ikke udsender den locales statiske payloads.
