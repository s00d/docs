# Runtime i18n-overrides

Brug denne guide, når du har brug for én build-artefakt til at køre med forskellige locale-standarder pr. miljø (f.eks. forskellige tenant-instanser).

## Hvad kan overskrives på runtime

Modulet understøtter sikre runtime-overrides for:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Disse overrides anvendes oven på buildtid-konfigurationen fra `.nuxt/i18n.strategy.mjs` og `.nuxt/i18n.config.mjs`.

## Hvad kan ikke overskrives på runtime

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) er et buildtid-anliggende, fordi det påvirker den genererede rute-adfærd.

Hvis du sender en runtime-strategi-override ind, ignoreres den, og en advarsel udsendes.

## Overrides baseret på RuntimeConfig

Angiv runtime-værdier under `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Overrides via miljøvariabler

Du kan også konfigurere overrides via miljøvariabler:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (komma-separeret, f.eks. `fr,it`)

Fallback-aliaser er også understøttet:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Valideringsregler

På runtime validerer modulet overrides for at undgå en ødelagt tilstand:

- Du kan ikke deaktivere alle locales.
- `defaultLocale` skal pege på et aktiveret locale.
- `fallbackLocale` skal findes i de deklarerede locales.

Hvis en override er ugyldig, beholder modulet en sikker værdi og logger en advarsel.

## Bemærkninger til multi-instans-deployments

Denne runtime-funktion er designet til locale-aktivering og -standarder pr. instans uden at genopbygge.

Hvis instanser kræver forskellige URL-strategier (`no_prefix` vs. `prefix`), skal du bruge separate builds for hver strategi.

## Deaktiverede locales og statiske payloads

`runtimeConfig.public.i18nRuntime.disabledLocales` opdaterer routing, switcher og Nitros payload-**handler** — men Nitro serverer filer under `public/` **før** den handler.

Hvis `translationPayloads.publicAssets` (eller Node-SSR's tvungne offentlige kopi) allerede har skrevet `/_locales/\{page\}/\{locale\}/data.json`, kan en runtime-deaktivering ikke skjule den fil. Foretræk `locale.disabled: true` ved build, så premerge ikke udsender det locales statiske payloads.
