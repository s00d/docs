# Brug af oversættelser i komponenter

Når modulet er installeret og konfigureret, kan du vise oversættelser ved at kalde `$t('din_nøgle')` i dine Vue-templates og -scripts.

## 1. Oversættelsesfiler på rodniveau og pr. side

1. **Rodniveau-oversættelser** ligger direkte under `/locales`-mappen (f.eks. `/locales/en.json`, `/locales/fr.json`). Ved buildtid flettes de automatisk ind i hver sideafgrænset fil og gøres tilgængelige på alle sider.
2. **Sideafgrænsede oversættelser** ligger under `/locales/pages/...` og matcher din Nuxt-pages-mappestruktur:

```text
locales/
├── en.json
├── fr.json
└── pages/
    └── dir1/
        ├── en.json
        └── fr.json

```

## 2. Brug i templates med `$t`

I dine `.vue`-filer kan du bruge `$t` direkte i templaten:

```vue
<template>
  <div>
    <!-- Root-level translation (available on all pages) -->
    <p>{{ $t('test_key') }}</p>
    <!-- Displays: Hello World! -->

    <!-- Page-specific translation (if this page is /dir1) -->
    <p>{{ $t('local_key') }}</p>
    <!-- Displays: This is a page-specific translation for /dir1. -->

    <!-- Nested key -->
    <p>{{ $t('nested.key.deeper') }}</p>
    <!-- Displays: Nested translation here -->

    <!-- Placeholder usage -->
    <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
    <!-- Displays: Hello, Alice! -->
  </div>
</template>

<script setup lang="ts">
// No need to import anything from 'nuxt-i18n-micro'.
// The plugin automatically provides `useI18n` and `$t`.
const { $t } = useI18n()

// You can now use $t in your script, for example:
console.log($t('test_key')) // "Hello World!"
</script>
```

<Tip>
`$t` kan returnere **objekter**, hvis nøglen peger på en indlejret JSON-node (f.eks. `$t('header')` → `\{ title: "Hi" \}`). I templates renderes det som `[object Object]`. Brug `$ts`, når du har brug for en garanteret streng, eller angiv en mere specifik nøgle som `$t('header.title')`. Se [API-reference — $t vs $ts](/api/methods#t) for detaljer.
</Tip>

## 3. Skift af det aktuelle locale

For at skifte sprog i din app kan du hente `$locale` fra `useI18n()` og tildele den en ny kode:

```vue
<template>
  <div>
    <button @click="$switchLocale('en')">English</button>
    <button @click="$switchLocale('fr')">Français</button>
  </div>
</template>

<script setup lang="ts">
// The plugin auto-injects these references
const { $t, $switchLocale } = useI18n()
</script>
```

## 4. Indlejrede nøgler og pladsholdere

- **Indlejrede nøgler** bruger dot-notation, f.eks. `nested.key.deeper`.
- **Pladsholdere** giver dig mulighed for at indsætte dynamiske værdier:
  ```json
  { "greeting": "Hello, {name}!" }
  ```
  ```vue
  <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
  <!-- Displays: Hello, Alice! -->
  ```

## 5. Tips og bedste praksis

- **Konflikter i nøgler**: Hvis en sideafgrænset fil indeholder samme nøgle som en rodfil, har den sideafgrænsede version prioritet (rod-oversættelser flettes som basis ved buildtid).
- **Deaktivering af sidefiler**: Hvis du ikke ønsker sideafgrænsede oversættelser, kan du sætte `disablePageLocales: true` i din Nuxt-config. Så bruges kun `/locales/*.json`-filerne.
- **Ingen direkte imports**: Du behøver ikke `import \{ useI18n \} from 'nuxt-i18n-micro'`. Modulets auto-injektion håndterer det for dig.

Det er det hele! Med disse trin kan du hurtigt **hente oversættelser** fra rodniveau- eller sideafgrænsede JSON-filer og **vise dem** i din Nuxt-applikation med `$t`.

## Yderligere ressourcer

For at udforske mere avancerede funktioner kan du med fordel tjekke:

1. **Komponenten `<i18n-t>`**  
   Komponenten `<i18n-t>` er et kraftfuldt alternativ til `$t`, især nyttigt i situationer med indlejrede elementer, avanceret brug af pladsholdere og mere komplekse oversættelsesstrukturer.

- **Dokumentation**: [i18n-t](/api/components/i18n-t)

2. **Composablen `useI18n`**  
   Composablen `useI18n` tilbyder et komplet sæt funktioner og reaktive egenskaber til styring af oversættelser, håndtering af locale-skift, formatering og mere.

- **Dokumentation**: [useI18n](/api/composables/use-i18n)
