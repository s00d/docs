`@i18n-micro/solid` giver SolidJS-apps en signal-baseret i18n-instans, en provider, `useI18n()` og fire komponenter. Brug den i en Solid-app, der ikke er bygget med Nuxt. Læsninger af `t()` inde i JSX eller effects sporer locale, routen og ordbøgerne; den fælles model står i [Frameworks](/da/integrations/overview).

## Installation {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer dependencies: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (valgfri, kun til `@i18n-micro/solid/router`). Solid 2 understøttes endnu ikke.

## Opsætning {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` tager `i18n`, `locales`, `defaultLocale` og `routingStrategy`; en udeladt prop beholder den ydre providers værdi, instansen inklusive. `getLocaleName()` og `<I18nSwitcher>` læser `locales`; uden dem har de intet at vise. Indstillingerne står under [instansen](/da/integrations/overview#the-instance). Instansen er [runtime](/da/integrations/runtime-package)'ens, med ét signal over dens store.

## Oversæt {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Kald metoderne inde i JSX eller en effect, så Solid sporer dem, også `localePath` og `getLocale`; en værdi læst én gang i komponentens krop opdateres ikke. På instansen sporer du med `i18n.locale` og `i18n.currentRoute`: `i18n.getLocale()` forbliver almindelig, fordi skrivninger læser den. Læsning af locale vågner kun på locale, så en effect, der læser den og indlæser en ordbog, kører én gang. Destrukturer ikke props, og gem ikke `t('key')`-resultater i almindelige variabler.

`useI18n()` returnerer `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (en accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` og `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Skift locale {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Et skift indlæser ikke noget; tilføj locales ordbog først.

`<I18nGroup>` sender en `t` med præfiks til et funktionsbarn. `<I18nT>` og `t()` inde i den får ikke præfiks:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Routing {#routing}

`@solidjs/router`-adapteren ligger i en subpath, så hovedindgangen aldrig importerer routeren. Kald den under routeren, typisk i routerens `root`, hvor `useNavigate` og `useLocation` virker:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

Adapteren sætter præfiks på alle locales undtagen standarden (`/about`, `/de/about`) og renderer `<I18nLink>` som routerens `<A>`. `getCurrentPath` læser routerens reaktive location, så aktive links og sprogvælgeren følger den; en brugerdefineret strategi opnår det samme ved at læse et signal der. Bemærk argumentrækkefølgen: `(locales, defaultLocale, navigate, location)`. Til andre routere skriver du en adapter med `getCurrentPath`, `push` og `replace` (alle påkrævede) — se [Router-adapter](/da/integrations/overview#router-adapter).

## SSR {#ssr}

Til server-rendering skal du bygge med `vite-plugin-solid`: pakkens `solid`-eksportbetingelse giver den kildekoden, så den kompileres til serveren. Den forudbyggede `dist` er kun til browseren. Instansen har ingen `destroy()`; opret én pr. app, eller én pr. forespørgsel på serveren, og lad den blive garbage-collected.
