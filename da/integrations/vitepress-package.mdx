`@i18n-micro/vitepress` tilføjer runtime-ordbøger til et VitePress-site: `$t` og `<I18nT>` inde i markdown, stihjælpere og SEO-tags, bygget på [`@i18n-micro/vue`](/da/integrations/vue-package). Brug det, når de samme UI-strenge optræder på mange sider, og du ikke vil duplikere dem pr. locale. Localet følger VitePress' egne sti-locales (`/`, `/fr/`).

## Hvornår du skal bruge det {#when-to-use-it}

| Behov | Løsning |
|------|----------|
| Duplikerede `.md`, URL-præfikser | VitePress `locales` |
| Runtime-`$t` / komponenter / stisynkronisering / SEO-head | `@i18n-micro/vitepress` |
| Labels i standardtemaets ramme (`docFooter`, søge-UI) | Din egen `themeConfig` pr. locale |

<Tip>

**Playground** — [`packages/vitepress/playground`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/vitepress/playground) — `pnpm -C packages/vitepress/playground dev`

</Tip>

## Installation {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vitepress
```

```bash npm
npm install @i18n-micro/vitepress
```

```bash yarn
yarn add @i18n-micro/vitepress
```

</CodeGroup>

Peer-afhængigheder: `vitepress` `>=1.0.0 || >=2.0.0-alpha.0`, `vue` `^3.3.0`. Node-scripts bruger `@i18n-micro/node`, som installeres med pakken og re-eksporteres via `/node`. De publicerede typer kræver Vue 3.5.5 eller nyere med `skipLibCheck: false`; med `skipLibCheck: true`, den sædvanlige skabelonindstilling, kompilerer ældre versioner også.

## Opsætning {#setup}

```
locales/en.json
locales/fr.json
locales/pages/guide/demo/en.json   # optional page-scoped
locales/pages/guide/demo/fr.json
```

Sidefiler mappes til rutenavne på samme måde som i Nuxt/Astro (`guide/demo` → `guide-demo`).

### 1. Konfiguration — `@i18n-micro/vitepress/config` {#1-config-—-@i18n-micro/vitepress/config}

```ts
// .vitepress/config.mts
import { defineConfig } from 'vitepress'
import { withI18n, buildVitePressLocales } from '@i18n-micro/vitepress/config'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English', og: 'en_US' },
  { code: 'fr', iso: 'fr-FR', displayName: 'Français', og: 'fr_FR' },
]
const defaultLocale = 'en'

export default defineConfig(
  withI18n(
    {
      locales: buildVitePressLocales(locales, defaultLocale),
      // themeConfig.i18nRouting is injected automatically
    },
    {
      locale: defaultLocale,
      defaultLocale,
      locales,
      translationDir: 'locales',
      metaBaseUrl: 'https://example.com', // optional SEO head
    },
  ),
)
```

### 2. Tema — `@i18n-micro/vitepress/theme` {#2-theme-—-@i18n-micro/vitepress/theme}

```ts
// .vitepress/theme/index.ts
import DefaultTheme from 'vitepress/theme'
import { defineI18nTheme } from '@i18n-micro/vitepress/theme'

export default defineI18nTheme(DefaultTheme)
```

Det indledende locale tages fra den aktuelle sti før installation (intet glimt af standard-localet på `/fr/…`).

### Avanceret: manuel `createI18n` {#advanced-manual-createi18n}

Én factory til klienten: Vue-plugin + stimetoder + `enhanceApp` (ingen separate router-hjælpereksporter).

```ts
import { createI18n, messagesFromGlob } from '@i18n-micro/vitepress'

const i18n = createI18n({
  locale: 'en',
  defaultLocale: 'en',
  locales: [{ code: 'en' }, { code: 'fr' }],
  messages: messagesFromGlob(import.meta.glob('../../locales/*.json', { eager: true })),
})

i18n.localizePath('/guide', 'fr')
// in theme enhanceApp:
i18n.enhanceApp({ app, router })
```

### Node-scripts — `@i18n-micro/vitepress/node` {#node-scripts-—-@i18n-micro/vitepress/node}

Bruger `@i18n-micro/node` `createI18n` / `loadTranslations` (som Astro og CLI) og tilføjer derefter VitePress-stimetoder med `BaseI18n.extend`:

```ts
import { createI18n } from '@i18n-micro/vitepress/node'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  translationDir: './locales',
  locales: ['en', 'fr'],
  defaultLocale: 'en',
})
await i18n.loadTranslations()
i18n.t('cta.readMore')
i18n.localizePath('/guide', 'fr')
```

Ren Node uden stier: `import { createI18n } from '@i18n-micro/node'`.

## Oversættelser på siden {#in-page-translations}

Hver VitePress-markdownfil er en Vue SFC.

### Globale komponenter og `$t` (anbefalet i markdown) {#global-components-and-$t-recommended-in-markdown}

`createI18n` / `defineI18nTheme` installerer `@i18n-micro/vue`, som registrerer `I18nT` / `I18nLink` / `I18nGroup` / `I18nSwitcher` og `$t` / `$tc` / `$ts`.

```md
{{ $t('cta.readMore') }}

<I18nT keypath="greeting" :params="{ name: 'VitePress' }" />

<I18nLink to="/guide/demo">Demo</I18nLink>
```

### `useI18n` i `<script setup>` {#usei18n-in-<script-setup>}

```md
<script setup>
import { useI18n } from '@i18n-micro/vitepress'
const { t, tc, locale, localePath, switchLocale } = useI18n()
</script>

# {{ t('section.title') }}
```

## Sprogmenu {#language-dropdown}

Når `locales` har mere end én post, viser VitePress sin egen sprogmenu (`VPNavBarTranslations`). `withI18n` kobler `themeConfig.i18nRouting` til, så globussen stemmer overens med `<I18nSwitcher>` / stihjælpere.

Brug kun `<I18nSwitcher>` i brugerdefinerede layouts, ikke ved siden af standardglobussen.

## SSR-noter {#ssr-notes}

- Localet ved prerender kommer fra URL-stien, ikke fra cookies.
- Temakode må ikke røre `window` ved import.
- Importér `defineI18nTheme` fra `/theme`, så Node-evalueringen af konfigurationen aldrig indlæser `virtual:i18n-micro/*`.

## API-overflade {#api-surface}

| Eksport | Rolle |
|--------|------|
| `createI18n` (`.`) | Klient: Vue-plugin + stimetoder + `enhanceApp` |
| `getLocaleFromPath` / `stripSiteBase` / `routeNameFromPath` (`.`) | Manuel locale-synkronisering, når `syncWithVitePress: false` |
| `createI18n` (`/node`) | Node: `@i18n-micro/node` + stimetoder |
| `defineI18nTheme` (`/theme`) | Tema uden boilerplate |
| `withI18n` (`/config`) | Konfiguration + virtuelle moduler + valgfri SEO |
| `buildVitePressLocales` (`/config`) | Byg VitePress-`locales` ud fra `Locale[]` |
| `buildVitePressLocaleHead` (`/config`) | Manuelt SEO-head (bruges også af `metaBaseUrl`) |
| `messagesFromGlob` | Valgfri glob → beskedmap til `createI18n` |
| `useI18n` / `I18nT` / … | Re-eksporteret fra `@i18n-micro/vue` |
| `BaseI18n.extend` (`@i18n-micro/core`) | Tilføj brugerdefinerede metoder på enhver i18n-instans |

## Sites i OpenAPI-stil (integrationslåse) {#openapi-style-sites-integration-locks}

Regressionssuite: `packages/vitepress/tests/integration-openapi.test.ts` (dybe stier, `base=/openapi_docs/`, synkronisering slået fra + manuelt locale, Node-generatorer, SEO).

| Mønster | Gør dette |
|---------|---------|
| Dybe `/…/{spec}/{op}`-sider, kun rod-UI-JSON | Foretræk standarden `syncWithVitePress: true` (beholder `setRoute('index')`, når der ikke er nogen sideordbog) **eller** `syncWithVitePress: false` + `getLocaleFromPath` |
| Kald aldrig `setRoute(deepName)` uden sideordbøger | Rod-UI-nøgler forsvinder indtil `setRoute('index')` |
| Generatorer / `getTranslation` | `createI18n` fra `/node` + `await loadTranslations()` + `i18n.t(key)` (sæt `i18n.locale`) |
| Brugerdefineret canonical i `transformPageData` | Send `meta: false` til `withI18n` (undgå dobbelte tags) |
| Pakkens SEO med site-base | `metaBaseUrl` + VitePress `base` → absolutte URL'er inkluderer base |
| Omdøbning fra ældre pakkebuilds | `withI18nMicro` → `withI18n`, `createVitePressI18n` → `createI18n`, `loadMessages` → node `createI18n` |
