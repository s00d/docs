En island kører i browseren, hvor serverens i18n-instans ikke findes. `@i18n-micro/astro` lader siden vælge de nøgler, en island har brug for, sende dem som én prop og læse dem i islanden via en lille framework-adapter. Du får `t`, `tc`, `tn`, `td`, `tdr` og `has` i Vue-, React-, Preact- og Svelte-islands, med kun de valgte strenge i HTML'en.

## Opsætning {#setup}

Sæt først [Astro-integrationen og middlewaren](/da/integrations/astro-package#setup) op, og tilføj derefter den framework-integration, du bruger (`@astrojs/vue`, `@astrojs/react`, `@astrojs/preact`, `@astrojs/svelte`). Island-adapterne kræver det framework som peer: `vue` `^3.3.0`, `react` `^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`, `preact` `^10.0.0 || ^11.0.0` eller `svelte` `^4.0.0 || ^5.0.0`.

## Send oversættelser til en island {#pass-translations-to-an-island}

```astro
---
// src/pages/index.astro
import { getI18nProps } from '@i18n-micro/astro'
import Counter from '../components/Counter.vue'

const i18n = getI18nProps(Astro, ['counter.title', 'counter.apples'])
---

<Counter client:load i18n={i18n} />
```

`getI18nProps(Astro, keys?)` returnerer `{ locale, fallbackLocale, currentRoute, translations }` (typen `I18nClientProps`). Send de nøgler, islanden bruger: hver af dem opløses på serveren som `t()` (rute-, rod- og fallback-ordbøger), og kun fundne nøgler kommer med i HTML'en. Uden `keys` sendes alt, hvad `t()` kan besvare på denne side, i hver island, så 2000 rodnøgler fylder omkring 100 KB pr. island; i dev advarer en meddelelse om det over 20 KB.

Islands oversætter kun ud fra det objekt. `t` returnerer nøglen for alt, der ikke er sendt med, og linkede beskeder opløses ikke.

## Vue {#vue}

Kald `provideI18n(() => props.i18n)` i islandens rodkomponent og `useAstroI18n()` i dens børn. Vues `inject` ser ikke en værdi, der er leveret af den samme komponent, så hooket skal køre i et barn, ikke i roden:

```vue
<!-- src/components/Counter.vue -->
<script setup lang="ts">
import { provideI18n } from '@i18n-micro/astro/client/vue'
import type { I18nClientProps } from '@i18n-micro/astro'
import CounterBody from './CounterBody.vue'

const props = defineProps<{ i18n: I18nClientProps }>()
provideI18n(() => props.i18n)
</script>

<template><CounterBody /></template>
```

```vue
<!-- src/components/CounterBody.vue -->
<script setup lang="ts">
import { ref } from 'vue'
import { useAstroI18n } from '@i18n-micro/astro/client/vue'

const { t, tc } = useAstroI18n()
const count = ref(0)
</script>

<template>
  <h3>{{ t('counter.title') }}</h3>
  <button @click="count++">{{ tc('counter.apples', count) }}</button>
</template>
```

## React og Preact {#react-and-preact}

```tsx
// src/components/Counter.tsx
import { useState } from 'react'
import { I18nProvider, useAstroI18n } from '@i18n-micro/astro/client/react'
import type { I18nClientProps } from '@i18n-micro/astro'

function Body() {
  const { t, tc } = useAstroI18n()
  const [count, setCount] = useState(0)
  return <button onClick={() => setCount(count + 1)}>{t('counter.title')}: {tc('counter.apples', count)}</button>
}

export default function Counter({ i18n }: { i18n: I18nClientProps }) {
  return (
    <I18nProvider value={i18n}>
      <Body />
    </I18nProvider>
  )
}
```

Til Preact importerer du `I18nProvider` og `useAstroI18n` fra `@i18n-micro/astro/client/preact`; API'et er det samme.

## Svelte {#svelte}

```svelte
<!-- src/components/Counter.svelte -->
<script lang="ts">
  import { createI18nStore, useAstroI18n } from '@i18n-micro/astro/client/svelte'
  import type { I18nClientProps } from '@i18n-micro/astro'

  export let i18n: I18nClientProps
  const { t, tc } = useAstroI18n(createI18nStore(i18n))
  let count = 0
</script>

<button on:click={() => count++}>{t('counter.title')}: {tc('counter.apples', count)}</button>
```

`useAstroI18n(store)` returnerer også `store` til `$store`-læsninger i skabelonen.

## Persisterede islands {#persisted-islands}

En island med `transition:persist` får nye props efter en navigation. React, Preact og Vue (givet en getter) følger dem. I Svelte beholder du storen og sender dem videre: `const store = createI18nStore(i18n)`, `const { t } = useAstroI18n(store)`, derefter `$: store.set(i18n)` (med runes, `$effect(() => store.set(i18n))`).

## API {#api}

| Indgang | Eksporter |
| --- | --- |
| `@i18n-micro/astro` | `getI18nProps`, typen `I18nClientProps` |
| `@i18n-micro/astro/client/vue` | `provideI18n(props \| () => props)`, `useAstroI18n()` |
| `@i18n-micro/astro/client/react` | `I18nProvider` (`value`-prop), `useAstroI18n()` |
| `@i18n-micro/astro/client/preact` | `I18nProvider` (`value`-prop), `useAstroI18n()` |
| `@i18n-micro/astro/client/svelte` | `createI18nStore(props)`, `useAstroI18n(store)` |
| `@i18n-micro/astro/client` | de rene `translate`, `hasTranslation`, uden framework |

Hver `useAstroI18n` returnerer `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `setLocale`, `setRoute` og `locale`. En island har én flettet ordbog, så dens `has` er sand for en nøgle, som `t` kan besvare, også fra fallback-localet; på serveren ser `has` kun på det aktive locale.
