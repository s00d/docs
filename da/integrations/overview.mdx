# Integrationer

`@i18n-micro`-pakkerne er letvægts, framework-specifikke versioner af Nuxt I18n Micro designet til integration i forskellige frameworks og miljøer. Disse pakker leverer kerne-internationaliseringsfunktionalitet med et minimalt fodaftryk og fokuserer på essentielle oversættelsesfunktioner og grundlæggende komponenter.

## Oversigt

Disse integrationspakker er **miniatureudgaver** af det fulde Nuxt I18n Micro-modul og indeholder kun den essentielle funktionalitet, der er nødvendig for internationalisering:

- **Kerne-oversættelsesfunktioner** — grundlæggende oversættelsesmetoder, pluralisering og formatering
- **Essentielle komponenter** — et lille sæt UI-komponenter til almindelige i18n-opgaver
- **Router-adapter-mønster** — fleksibel routing-integration via adapter-abstraktion
- **TypeScript-understøttelse** — fulde typedefinitioner til typesikker udvikling

I modsætning til det fulde Nuxt-modul:

- Indeholder pakkerne ikke framework-specifik routing-logik
- Kræver du, at du implementerer en router-adapter for routing-funktioner
- Fokuserer de på oversættelsesfunktionalitet frem for framework-integration
- Er de designet til at være letvægts og framework-uafhængige, hvor det er muligt

## Kernekomponenter

Alle framework-pakker indeholder følgende essentielle komponenter:

### `<I18nT>`

En oversættelseskomponent, der renderer oversat tekst med understøttelse af:

- **Parameter-interpolation** — erstat pladsholdere med dynamiske værdier
- **Pluralisering** — automatisk valg af pluralform baseret på antal
- **Talformatering** — formatér tal efter locale
- **Datoformatering** — formatér datoer og relative tider
- **HTML-rendering** — valgfri HTML-indholds-rendering
- **Standardværdier** — fallback-tekst, når oversættelsen mangler

**Eksempel:**

```vue
<!-- Vue -->
<I18nT keypath="greeting" :params="{ name: 'World' }" />
```

```tsx
// React
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```tsx
// Solid
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```astro
<!-- Astro -->
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

### `<I18nLink>`

En lokaliseret link-komponent, der automatisk håndterer locale-præfikser i URL'er. Funktioner:

- **Automatisk sti-lokalisering** — tilføjer/fjerner locale-præfikser baseret på routing-strategien
- **Detektion af aktiv tilstand** — fremhæver den aktuelle rute
- **Understøttelse af eksterne links** — opdager og håndterer automatisk eksterne URL'er
- **Router-integration** — bruger router-adapterens link-komponent, når den er tilgængelig
- **Brugerdefineret styling** — understøtter aktive og hover-tilstande

**Eksempel:**

```vue
<!-- Vue -->
<I18nLink to="/about" active-class="active">
  About Us
</I18nLink>
```

```tsx
// React
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```tsx
// Solid
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```astro
<!-- Astro -->
<I18nLink href="/about" class="nav-link">
  About Us
</I18nLink>
```

### `<I18nSwitcher>`

En sprogskifter-komponent, der giver en dropdown- eller list-grænseflade til at ændre locales. Funktioner:

- **Automatisk locale-liste** — genererer valgmuligheder ud fra konfigurerede locales
- **Fremhævning af aktuelt locale** — viser visuelt det aktive sprog
- **Brugerdefinerede labels** — understøtter brugerdefinerede visningsnavne pr. locale
- **Router-integration** — navigerer automatisk til lokaliserede stier
- **Tilgængelighed** — korrekte ARIA-attributter og keyboard-navigation

**Eksempel:**

```vue
<!-- Vue -->
<I18nSwitcher />
```

```tsx
// React
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```tsx
// Solid
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```astro
<!-- Astro -->
<I18nSwitcher />
```

### `<I18nGroup>`

En komponent til at gruppere oversættelser med et fælles præfiks, nyttig til at organisere oversættelser efter side eller feature. Funktioner:

- **Præfiks-scoping** — tilføjer automatisk præfiks til alle oversættelsesnøgler inden for gruppen
- **Indlejrede grupper** — understøtter indlejrede oversættelsesgrupper
- **Ren organisering** — hjælper med at opretholde organiserede oversættelsesstrukturer

**Eksempel:**

```vue
<!-- Vue -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

```tsx
// React
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```tsx
// Solid
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```astro
<!-- Astro -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

## Delte `createI18n`-indstillinger \{#create-i18n-options\}

Hver framework-pakke oprettes på samme måde — kun typenavnet for indstillingerne er opkaldt efter frameworket (`ReactI18nOptions`, `SolidI18nOptions` osv.). Indstillingerne selv er identiske:

| Egenskab         | Type                                                       | Påkrævet | Standard          | Beskrivelse                                    |
| ---------------- | ---------------------------------------------------------- | -------- | ---------------- | ---------------------------------------------- |
| `locale`         | `string`                                                   | ✅       | -                | Aktuel locale-kode (f.eks. `'en'`)             |
| `fallbackLocale` | `string`                                                   | ❌       | Samme som `locale` | Fallback-locale, når en oversættelse mangler   |
| `messages`       | `Record<string, Translations>`                             | ❌       | `\{\}`             | Indledende oversættelsesbeskeder               |
| `plural`         | `PluralFunc`                                               | ❌       | `defaultPlural`  | Brugerdefineret pluraliseringsfunktion         |
| `missingWarn`    | `boolean`                                                  | ❌       | `true`           | Vis konsoladvarsler for manglende oversættelser |
| `missingHandler` | `(locale: string, key: string, routeName: string) => void` | ❌       | -                | Brugerdefineret handler for manglende oversættelser |

Alt derudover er framework-specifikt og dokumenteret på den enkelte pakkes side.

## Router-adapter-abstraktion

Alle framework-pakker bruger et **router-adapter-mønster** for at frakoble i18n-funktionalitet fra specifikke router-implementeringer. Dette design giver:

- **Fleksibilitet** — brug ethvert router-bibliotek eller helt uden router
- **Framework-uafhængighed** — hold routing-logik i din applikation, ikke i i18n-pakken
- **Letvægts-kerne** — i18n-pakken forbliver lille og fokuseret

### Implementering af en router-adapter

For at bruge routing-funktioner skal du implementere interfacet `I18nRoutingStrategy`:

```typescript
interface I18nRoutingStrategy {
  getCurrentPath: () => string
  linkComponent?: Component
  push: (target: { path: string }) => void
  replace: (target: { path: string }) => void
  resolvePath?: (to: string | { path?: string }, locale: string) => string | { path?: string }
  getRoute?: () => { fullPath: string; query: Record<string, unknown> }
}
```

Hver pakkes dokumentation indeholder komplette eksempler på implementering af adaptere til populære routere:

- **Vue**: eksempel på Vue Router-adapter
- **React**: eksempel på React Router-adapter
- **Solid**: eksempel på Solid Router-adapter
- **Astro**: eksempel på filbaseret routing-adapter

## Kernefunktioner

Alle pakker deler disse kernefunktioner:

### Oversættelsesmetoder

- `t()` — grundlæggende oversættelse med parameter-interpolation
- `ts()` — oversættelse, der altid returnerer en streng
- `tc()` — pluralisering-bevidst oversættelse
- `tn()` — talformatering
- `td()` — datoformatering
- `tdr()` — formatering af relativ tid
- `has()` — tjek om en oversættelsesnøgle findes

### Locale-håndtering

- **Locale-skift** — skift aktuelt locale programmatisk
- **Fallback-locale** — automatisk fallback, når en oversættelse mangler
- **Rutespecifikke oversættelser** — organisering af oversættelser på sideniveau
- **Cache af oversættelser** — intelligent caching for ydeevne

### TypeScript-understøttelse

Alle pakker leverer:

- Fulde TypeScript-definitioner
- Typesikre oversættelsesnøgler (med types-generator)
- IntelliSense-understøttelse i IDE'er
- Compile-time fejltjek
