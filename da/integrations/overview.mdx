# Integrationer

`@i18n-micro`-pakkerne er letvægts, framework-specifikke versioner af Nuxt I18n Micro designet til integration i forskellige frameworks og miljøer. Disse pakker tilbyder kerne-internationaliseringsfunktionalitet med et minimalt fodaftryk, med fokus på essentielle oversættelsesfunktioner og grundlæggende komponenter.

## Oversigt

Disse integrationspakker er **miniature-versioner** af det fulde Nuxt I18n Micro-modul, som kun indeholder den essentielle funktionalitet, der er nødvendig for internationalisering:

- **Kerne-oversættelsesfunktioner** - Grundlæggende oversættelsesmetoder, pluralisering og formatering
- **Essentielle komponenter** - Et lille sæt UI-komponenter til almindelige i18n-opgaver
- **Router adapter-mønster** - Fleksibel routing-integration gennem adapter-abstraktion
- **TypeScript-understøttelse** - Fulde typedefinitioner til type-sikker udvikling

I modsætning til det fulde Nuxt-modul gør disse pakker:

- Inkluderer ikke framework-specifik routing-logik
- Kræver, at du implementerer en router-adapter for routing-funktioner
- Fokuserer på oversættelsesfunktionalitet frem for framework-integration
- Er designet til at være letvægts og framework-agnostiske, hvor muligt

## Kerne-komponenter

Alle framework-pakker inkluderer følgende essentielle komponenter:

### `<I18nT>`

En oversættelses-komponent, der renderer oversat tekst med understøttelse af:

- **Parameter-interpolation** - Erstat placeholders med dynamiske værdier
- **Pluralisering** - Automatisk valg af pluralform baseret på antal
- **Talformatering** - Formatér tal i henhold til locale
- **Datoformatering** - Formatér datoer og relative tider
- **HTML-rendering** - Valgfri HTML-indholds-rendering
- **Standardværdier** - Fallback-tekst, når oversættelse mangler

**Eksempel:**

```vue
<!-- Vue -->
<I18nT keypath="greeting" :params="{ name: 'World' }" />
```

```tsx
// React
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```tsx
// Solid
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```astro
<!-- Astro -->
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

### `<I18nLink>`

En lokaliseret link-komponent, der automatisk håndterer locale-præfikser i URL'er. Funktioner:

- **Automatisk sti-lokalisering** - Tilføjer/fjerner locale-præfikser baseret på routing-strategi
- **Aktiv tilstand-detektering** - Fremhæver den aktuelle rute
- **Understøttelse af eksterne links** - Detekterer og håndterer automatisk eksterne URL'er
- **Router-integration** - Bruger router-adapterens link-komponent, når tilgængelig
- **Brugerdefineret styling** - Understøtter aktive og hover-tilstande

**Eksempel:**

```vue
<!-- Vue -->
<I18nLink to="/about" active-class="active">
  About Us
</I18nLink>
```

```tsx
// React
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```tsx
// Solid
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```astro
<!-- Astro -->
<I18nLink href="/about" class="nav-link">
  About Us
</I18nLink>
```

### `<I18nSwitcher>`

En sprogswitcher-komponent, der tilbyder en dropdown- eller listegrænseflade til at ændre locales. Funktioner:

- **Automatisk locale-liste** - Genererer options fra konfigurerede locales
- **Fremhævning af aktuel locale** - Angiver visuelt det aktive sprog
- **Brugerdefinerede etiketter** - Understøttelse af brugerdefinerede visningsnavne pr. locale
- **Router-integration** - Navigerer automatisk til lokaliserede stier
- **Tilgængelighed** - Korrekte ARIA-attributter og tastaturnavigation

**Eksempel:**

```vue
<!-- Vue -->
<I18nSwitcher />
```

```tsx
// React
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```tsx
// Solid
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```astro
<!-- Astro -->
<I18nSwitcher />
```

### `<I18nGroup>`

En komponent til at gruppere oversættelser med et fælles præfiks, nyttig til at organisere oversættelser efter side eller feature. Funktioner:

- **Præfiks-scoping** - Præfikser automatisk alle oversættelsesnøgler inden i gruppen
- **Nested grupper** - Understøttelse af nested oversættelses-grupper
- **Ren organisering** - Hjælper med at opretholde organiserede oversættelsesstrukturer

**Eksempel:**

```vue
<!-- Vue -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

```tsx
// React
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```tsx
// Solid
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```astro
<!-- Astro -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

## Delte `createI18n`-options \{#create-i18n-options\}

Hver framework-pakke oprettes på samme måde — kun options-typen er navngivet efter
frameworket (`ReactI18nOptions`, `SolidI18nOptions` osv.). Options'ene selv
er identiske:

| Egenskab         | Type                                                       | Påkrævet | Standard         | Beskrivelse                                    |
| ---------------- | ---------------------------------------------------------- | -------- | ---------------- | ---------------------------------------------- |
| `locale`         | `string`                                                   | ✅       | -                | Aktuel locale-kode (f.eks. `'en'`)             |
| `fallbackLocale` | `string`                                                   | ❌       | Samme som `locale` | Fallback-locale, når oversættelse mangler     |
| `messages`       | `Record<string, Translations>`                             | ❌       | `\{\}`             | Indledende oversættelsesbeskeder               |
| `plural`         | `PluralFunc`                                               | ❌       | `defaultPlural`  | Brugerdefineret pluraliseringsfunktion         |
| `missingWarn`    | `boolean`                                                  | ❌       | `true`           | Vis konsol-advarsler for manglende oversættelser |
| `missingHandler` | `(locale: string, key: string, routeName: string) => void` | ❌       | -                | Brugerdefineret handler for manglende oversættelser |

Alt derudover er framework-specifikt og dokumenteret på den pakkes side.

## Router adapter-abstraktion

Alle framework-pakker bruger et **router adapter-mønster** til at afkoble i18n-funktionalitet fra specifikke router-implementeringer. Dette design tillader:

- **Fleksibilitet** - Brug ethvert router-bibliotek eller slet ingen router
- **Framework-uafhængighed** - Hold routing-logik i din applikation, ikke i i18n-pakken
- **Letvægts kerne** - i18n-pakken forbliver lille og fokuseret

### Implementering af en router-adapter

For at bruge routing-funktioner skal du implementere `I18nRoutingStrategy`-interfacet:

```typescript
interface I18nRoutingStrategy {
  getCurrentPath: () => string
  linkComponent?: Component
  push: (target: { path: string }) => void
  replace: (target: { path: string }) => void
  resolvePath?: (to: string | { path?: string }, locale: string) => string | { path?: string }
  getRoute?: () => { fullPath: string; query: Record<string, unknown> }
}
```

Hver pakke-dokumentation inkluderer komplette eksempler på implementering af adaptere for populære routere:

- **Vue**: Vue Router adapter-eksempel
- **React**: React Router adapter-eksempel
- **Solid**: Solid Router adapter-eksempel
- **Astro**: Fil-baseret routing-adapter-eksempel

## Kerne-funktioner

Alle pakker deler disse kerne-funktioner:

### Oversættelsesmetoder

- `t()` - Grundlæggende oversættelse med parameter-interpolation
- `ts()` - Oversættelse, der altid returnerer en streng
- `tc()` - Pluraliserings-bevidst oversættelse
- `tn()` - Talformatering
- `td()` - Datoformatering
- `tdr()` - Relativ tid-formatering
- `has()` - Tjek om oversættelsesnøgle findes

### Locale-håndtering

- **Locale-skift** - Ændr aktuel locale programmatisk
- **Fallback-locale** - Automatisk fallback, når oversættelse mangler
- **Rute-specifikke oversættelser** - Side-niveau oversættelsesorganisering
- **Oversættelses-caching** - Intelligent caching for ydeevne

### TypeScript-understøttelse

Alle pakker tilbyder:

- Fulde TypeScript-definitioner
- Type-sikre oversættelsesnøgler (med types generator)
- IntelliSense-understøttelse i IDE'er
- Fejltjek ved compile-tid
