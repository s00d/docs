`@i18n-micro/solid` dává aplikacím SolidJS i18n instanci postavenou na signálech, provider, `useI18n()` a čtyři komponenty. Použijte ho v Solid aplikaci, která není postavená na Nuxtu. Čtení `t()` uvnitř JSX nebo efektů sleduje locale, routu a slovníky; sdílený model je popsán ve [Frameworcích](/cs/integrations/overview).

## Instalace {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer závislosti: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (volitelné, jen pro `@i18n-micro/solid/router`). Solid 2 zatím není podporován.

## Nastavení {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` přijímá `i18n`, `locales`, `defaultLocale` a `routingStrategy`; vynechaný prop si ponechá hodnotu vnějšího provideru, včetně instance. `getLocaleName()` a `<I18nSwitcher>` čtou `locales`; bez nich nemají co vypsat. Možnosti jsou popsané v sekci [instance](/cs/integrations/overview#the-instance). Instance je instancí [runtime](/cs/integrations/runtime-package) s jedním signálem nad jejím úložištěm.

## Překlad {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Metody volejte uvnitř JSX nebo efektu, aby je Solid sledoval, a to i `localePath` a `getLocale`; hodnota přečtená jednou v těle komponenty se neaktualizuje. Na instanci sledujte pomocí `i18n.locale` a `i18n.currentRoute`: `i18n.getLocale()` zůstává obyčejné, protože ho čtou zápisy. Čtení locale se probudí jen při změně locale, takže efekt, který ho čte a načítá slovník, proběhne jednou. Nedestrukturujte props a neukládejte výsledky `t('key')` do obyčejných proměnných.

`useI18n()` vrací `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` a `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Přepnutí locale {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Přepnutí nic nenačítá; nejdřív přidejte slovník daného locale.

`<I18nGroup>` předá funkčnímu potomkovi `t` s prefixem. `<I18nT>` a `t()` uvnitř něj prefix nemají:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Routování {#routing}

Adaptér pro `@solidjs/router` je v samostatné podcestě, takže hlavní vstupní bod router nikdy neimportuje. Volejte ho pod routerem, typicky v `root` routeru, kde fungují `useNavigate` a `useLocation`:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

Adaptér přidává prefix každému locale kromě výchozího (`/about`, `/de/about`) a vykresluje `<I18nLink>` jako `<A>` routeru. `getCurrentPath` čte reaktivní location routeru, takže aktivní odkazy i přepínač ji sledují; vlastní strategie dosáhne téhož čtením signálu na tomto místě. Pozor na pořadí argumentů: `(locales, defaultLocale, navigate, location)`. Pro jiné routery napište adaptér s `getCurrentPath`, `push` a `replace` (všechny povinné) — viz [Adaptér routeru](/cs/integrations/overview#router-adapter).

## SSR {#ssr}

Pro serverové vykreslování sestavujte pomocí `vite-plugin-solid`: exportní podmínka `solid` balíčku mu předá zdrojový kód, takže se zkompiluje pro server. Předem sestavený `dist` je určený jen pro prohlížeč. Instance nemá `destroy()`; vytvořte jednu na aplikaci, nebo na serveru jednu na požadavek, a nechte ji uvolnit garbage collectorem.
