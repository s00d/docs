S `meta: true` (výchozí) dostane každá lokalizovaná stránka `<html lang dir>`, kanonický odkaz, alternativy `hreflang`, `x-default` a tagy locale pro Open Graph. Tuto stránku potřebujete, když chcete nastavit veřejný origin, vyladit, která locale se v tazích objeví, nebo je přepsat pro jednu stránku. Většině webů stačí `site.url` nebo `metaBaseUrl` a správné kódy `iso`.

## Minimální nastavení {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

`/de/about` pak vykreslí:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Směr textu {#text-direction}

`<html dir>` pochází z `dir` daného locale. Bez něj dostane jazyk psaný zprava doleva `rtl`, určené z `iso` (nebo `code`): arabština, hebrejština, perština, urdština a několik dalších a také jakýkoli tag s RTL písmem, například `az-Arab`. Všechna ostatní locale nedostanou atribut `dir`, což prohlížeče chápou jako `ltr`.

<Warning>

**`dir: 'auto'` stojí na velkých stránkách čas parsování** — `auto` na `<html>` nutí prohlížeč během parsování odvozovat směr z obsahu. V Chromiu tato cena roste rychleji než stránka: asi 100 ms při 5 000 elementech a 1 s při 20 000. Používejte ho jen pro malou stránku, jejíž jazyk nemůžete znát.

</Warning>

## Které tagy dostanete {#which-tags-you-get}

- **hreflang**: jeden tag pro každé locale, které stránku obsluhuje, s hodnotou `iso` (nebo `code`, když `iso` chybí) a jeho URL se stejným query jako canonical. Stránka omezená pomocí [Konfigurace stránky](/cs/guide/per-component-translations) nebo `routeLocales` uvádí jen svá locale. [`hreflangBaseLanguage: true`](/cs/api/module-options#hreflangbaselanguage) přidá pro první regionální locale také holý jazyk (`es-ES` → `es`).
- **x-default**: URL výchozího locale, jen pokud výchozí locale stránku obsluhuje.
- **og:locale**: odvozeno z `iso` (`en-US` → `en_US`). Pokud mapování není přímé, nastavte na locale `og`, například `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; bez obojího se `og:locale` nezapíše a vývojový režim zobrazí varování.
- **canonical / og:url**: aktuální URL bez query parametrů, kromě těch v [`canonicalQueryWhitelist`](/cs/api/module-options#canonicalquerywhitelist) (výchozí `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Podle strategie:

| Strategie | hreflang a x-default | canonical, og:url, og:locale, atributy html |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | ano | ano |
| `no_prefix` | ne (jedna URL obsluhuje všechna locale) | ano |

## Nastavení veřejného originu {#set-the-public-origin}

Absolutní URL používají první z:

1. [`metaBaseUrl`](/cs/api/module-options#metabaseurl);
2. `site.url` z `nuxt-site-config` (instaluje ho `@nuxtjs/seo`);
3. origin požadavku s připojeným `app.baseURL`.

Zafixujte jednu z prvních dvou možností.

<Warning>

Záložní varianta s originem požadavku čte `X-Forwarded-Host` a `X-Forwarded-Proto`, protože [`metaTrustForwardedHost`](/cs/api/module-options#metatrustforwardedhost) a `metaTrustForwardedProto` mají výchozí hodnotu `true`. To je bezpečné jen za proxy, která tyto hlavičky přepisuje; jinak si klient může zvolit host ve vašich kanonických odkazech a cache může takovou stránku předávat dál.

Pokud je aplikace dostupná přímo, zafixujte `metaBaseUrl`: na rozdíl od nastavení obou možností na `false` ignoruje i podvržený `Host`. Viz [Za proxy nebo CDN](/cs/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

Záložní varianta je užitečná pro jedno nasazení obsluhující několik domén: `https://site-a.com/en/about` a `https://site-b.com/en/about` dostanou každá svůj vlastní origin.

S `baseUrl` na locale používá známý host svůj vlastní `baseUrl`, přednostně před `metaBaseUrl` a `site.url`, takže canonical a `og:url` zůstanou na dané doméně a `hreflang` směruje každé locale na jeho doménu. Jakýkoli jiný host použije `metaBaseUrl`, jinak `baseUrl` výchozího locale, jinak `site.url`, takže podvržený `Host` se k vašim tagům nedostane. Pokud není nastaveno nic z toho, záložní varianta s originem požadavku zůstane a sestavení zobrazí varování. Viz [Vrstvy a domény](/cs/guide/layers#multiple-domains).

## Vynechání locale nebo stránek {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Pokud má výchozí locale `seo: false`, `x-default` se nezapíše. Chcete-li tagy vypnout pro jednu stránku, použijte `disableMeta` v [Konfiguraci stránky](/cs/guide/per-component-translations#turn-off-seo-tags), nebo [`routeDisableMeta`](/cs/api/module-options#routedisablemeta) v konfiguraci.

## Přepsání tagů na jedné stránce {#override-tags-on-one-page}

U obsahu z CMS, kde existují jen některé překlady nebo kde URL pocházejí z API, nahraďte vygenerované tagy pomocí [`useI18nHead`](/cs/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` může také nastavit nebo odstranit `canonical`, `xDefault`, `ogLocale` a `ogUrl`; `disable` vypustí celé skupiny (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Předejte getter, aby se hodnoty po přepnutí locale přepočítaly. U slugů pro jednotlivá locale nejprve nastavte `$setI18nRouteParams` ([Lokalizované cesty](/cs/guide/custom-locale-routes#per-locale-slugs)) a vygenerované alternativy je už použijí.

## Koncové lomítko {#trailing-slash}

`$localePath`, `$switchLocalePath`, objekt routy z `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, přesměrování locale i SEO URL se řídí jedním pravidlem pro lomítko: ve výchozím stavu `experimental.defaults.nuxtLink.trailingSlash`, nebo [`trailingSlash`](/cs/api/module-options) v konfiguraci i18n, když se mají i18n cesty lišit.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) funguje s tímto modulem přes `nuxt-site-config` 4+. Uveďte `nuxt-i18n-micro` jako první, aby konfigurace webu mohla číst locale, a nastavte `site.url` jednou — napájí i výše uvedené tagy.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Přeložený název a popis webu pocházejí z klíčů `nuxtSiteConfig.name` / `nuxtSiteConfig.description` ve vašich souborech locale. Chyba `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` znamená, že `@nuxtjs/seo` je starší než 3; aktualizujte ho ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
