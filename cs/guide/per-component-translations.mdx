---
title: "Konfigurace stránky"
description: "Omezte stránku na některé lokalizace, dejte jí vlastní cesty, inline překlady nebo ji zbavte SEO tagů pomocí $defineI18nRoute."
---

`$defineI18nRoute` nastavuje možnosti i18n pro jednu stránku přímo zevnitř této stránky. Použijte ho, když stránka existuje jen v některých lokalizacích, potřebuje vlastní lokalizovanou cestu, nese několik vlastních překladů nebo nesmí dostat tagy hreflang/canonical. Modul volání přečte při buildu a zapeče ho do generovaných tras.

## Omezení stránky na některé lokalizace {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

Při výchozí strategii `prefix_except_default` se vygenerují jen `/product` a `/de/product`; v žádné jiné lokalizaci stránka trasu nemá. Totéž lze nastavit z `nuxt.config.ts` pomocí [`routeLocales`](/cs/api/module-options#routelocales).

`$defineI18nRoute` je injekce aplikace Nuxt, nikoli makro kompilátoru: vždy ho získejte z `useNuxtApp()` a volejte ho se znakem `$`. Krok buildu rozpozná pouze `$defineI18nRoute(`.

## Přidání inline překladů {#add-inline-translations}

Místo pole předejte objekt. Jeho klíče jsou povolené lokalizace, jeho hodnoty se sloučí do slovníku stránky pro aktivní lokalizaci.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Inline překlady se dodávají uvnitř komponenty stránky pro každou lokalizaci. Pro cokoli většího než pár klíčů dejte přednost [souborům s překlady stránek](/cs/guide/translations); inline klíče si nechte pro samostatné stránky a komponenty.

## Nastavení lokalizovaných cest {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

S `prefix_except_default` a `defaultLocale: 'en'` vznikne `/welcome` a `/de/willkommen`. Totéž udělá `path` uvnitř inline objektu lokalizace: `locales: { de: { path: '/willkommen' } }`. Dynamické parametry, vnořené trasy a alternativa na úrovni konfigurace jsou popsány v části [Lokalizované cesty](/cs/guide/custom-locale-routes).

## Vypnutí SEO tagů {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

Alternativou na úrovni konfigurace je [`routeDisableMeta`](/cs/api/module-options#routedisablemeta). Co jsou tyto tagy zač, se dozvíte na stránce [SEO](/cs/guide/seo).

## Co dokáže build přečíst {#what-the-build-can-read}

Krok buildu najde volání v každém souboru stránky a vyhodnotí jeho argument, aniž by spouštěl vaši aplikaci. Funguje, když je konfigurace:

- literálový objekt (řetězce, pole, vnořené objekty, template literály, ternární výrazy nad `process.env.NODE_ENV`);
- sestavená z konstant deklarovaných ve stejném `<script setup>` (`const locales = ['en', 'de']`, včetně spreadů);
- pole objektů s polem `code` (`[{ code: 'en' }, { code: 'de' }]`).

Nedokáže přečíst hodnoty importované z jiného modulu ani nic, co za běhu potřebuje vaši aplikaci (composables, `await`, načtená data). V takovém případě build zapíše do logu `Ignored the $defineI18nRoute() config in <file>` a stránka si ponechá výchozí lokalizace a trasy.

Za běhu volání pouze sloučí inline překlady pro aktuální lokalizaci a při změně lokalizace je sloučí znovu. `locales`, `localeRoutes` a `disableMeta` se projeví jen prostřednictvím buildu, takže jejich změna vyžaduje nový build (vývojový server při uložení přebuildovává).
