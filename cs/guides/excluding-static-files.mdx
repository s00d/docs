# Vyloučení statických souborů z i18n routování

## Přehled

Ve výchozím nastavení nuxt-i18n-micro automaticky vylučuje běžné statické soubory ze zpracování i18n routováním. Můžete však také nakonfigurovat vlastní vzory vyloučení, aby konkrétní cesty nebyly zpracovávány systémem i18n.

## Vestavěná vyloučení

Modul automaticky vylučuje následující typy souborů a vzory:

- **Sitemapy**: `/sitemap*.xml`, `/sitemap-en.xml` atd.
- **SEO soubory**: `/robots.txt`, `/favicon.ico`
- **PWA soubory**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Statické assety**: Soubory s příponami jako `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Interní cesty Nuxt**: Jakákoli cesta začínající `__` (jako `/__nuxt/`)

## Vlastní vzory vyloučení

Vlastní vzory vyloučení můžete definovat pomocí volby `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Typy vzorů

### Řetězcové vzory

- **Přesná shoda**: `'/api/health'` - odpovídá přesně `/api/health`
- **Shoda prefixu**: `'/admin'` - odpovídá `/admin` a `/admin/dashboard`
- **Wildcards**: `'/api/*'` - odpovídá `/api/users`, ale ne `/api/users/123`
- **Hluboké wildcards**: `'/admin/**'` - odpovídá `/admin/users` a `/admin/users/123`

### Regulární výrazy

Pro složitější porovnávání vzorů použijte objekty RegExp:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Případy použití

### SEO soubory

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API routy

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Administrátorské panely

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Statické assety

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Jak to funguje

1. **Serverový middleware**: Nitro middleware se spouští jako první a kontroluje vzory vyloučení
2. **Zpracování stránky**: Během řešení stránky jsou vyloučené cesty přeskočeny
3. **Catch-all routa**: Fallback routa kontroluje vyloučení před zpracováním
4. **Prerendering**: Vyloučené cesty nejsou zahrnuty do prerenderovaných rout

## Dopad na výkon

- Kontroly vyloučení jsou optimalizované a spouštějí se brzy v životním cyklu požadavku
- Vestavěné vzory používají efektivní regex porovnávání
- Vlastní vzory jsou cachovány a znovu použity
- Minimální výkonnostní režie pro vyloučené cesty

## Řešení problémů

### Statické soubory jsou stále zachyceny

1. **Zkontrolujte syntaxi vzoru**: Ujistěte se, že vaše vzory odpovídají přesné struktuře cesty
2. **Pro složité vzory použijte regex**: Řetězcové wildcards mají omezení
3. **Otestujte vzory**: Použijte dev tools prohlížeče k ověření skutečné cesty požadavku
4. **Zkontrolujte pořadí**: Ujistěte se, že vzory vyloučení jsou definovány před ostatní i18n konfigurací

### Vzor nefunguje

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Debug režim

Povolte debug režim, abyste viděli zpracování vyloučení:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

To zaloguje rozhodnutí o vyloučení v konzoli.

## Migrace z workaroundů

Pokud jste používali workaroundy jako route rules nebo middleware, můžete je nyní nahradit pomocí `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Nový přístup je spolehlivější a funguje na více úrovních routovacího systému.
