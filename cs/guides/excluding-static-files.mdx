# Vyloučení statických souborů z i18n routování

## Přehled

Ve výchozím stavu nuxt-i18n-micro automaticky vylučuje běžné statické soubory ze zpracování i18n routování. Můžete však nakonfigurovat i vlastní vzory vyloučení, aby se konkrétní cesty i18n systémem nezpracovávaly.

## Vestavěná vyloučení

Modul automaticky vylučuje následující typy souborů a vzory:

- **Sitemapy**: `/sitemap*.xml`, `/sitemap-en.xml` a podobně.
- **SEO soubory**: `/robots.txt`, `/favicon.ico`
- **PWA soubory**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Statické assety**: Soubory s příponami jako `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Interní cesty Nuxtu**: Jakákoli cesta začínající `__` (například `/__nuxt/`)

## Vlastní vzory vyloučení

Vlastní vzory vyloučení můžete definovat pomocí volby `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Typy vzorů

### Řetězcové vzory

- **Přesná shoda**: `'/api/health'` odpovídá přesně `/api/health`
- **Shoda prefixu**: `'/admin'` odpovídá `/admin` i `/admin/dashboard`
- **Wildcardy**: `'/api/*'` odpovídá `/api/users`, ale ne `/api/users/123`
- **Hluboké wildcardy**: `'/admin/**'` odpovídá `/admin/users` i `/admin/users/123`

### Regulární výrazy

Pro složitější párování používejte objekty RegExp:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Případy použití

### SEO soubory

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API routy

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Admin panely

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Statické assety

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Jak to funguje

1. **Serverový middleware**: Nitro middleware běží jako první a kontroluje vzory vyloučení
2. **Zpracování stránek**: Během resolvingu stránek se vyloučené cesty přeskočí
3. **Catch-all routa**: Fallback routa kontroluje vyloučení před zpracováním
4. **Prerendering**: Vyloučené cesty se nezahrnují do prerendered rout

## Dopad na výkon

- Kontroly vyloučení jsou optimalizované a běží brzy v životním cyklu requestu
- Vestavěné vzory používají efektivní regex párování
- Vlastní vzory se cachují a znovupoužívají
- Minimální režie pro vyloučené cesty

## Řešení problémů

### Statické soubory jsou i tak zachycovány

1. **Zkontrolujte syntaxi vzoru**: Ujistěte se, že vaše vzory odpovídají přesné struktuře cest
2. **Pro složité vzory použijte regex**: Řetězcové wildcardy mají omezení
3. **Otestujte vzory**: Použijte dev nástroje prohlížeče k ověření skutečné cesty requestu
4. **Zkontrolujte pořadí**: Ujistěte se, že jsou vzory vyloučení definovány před ostatní i18n konfigurací

### Vzor nefunguje

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Debug režim

Zapněte debug režim pro zobrazení zpracování vyloučení:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Tím se do konzole zalogují rozhodnutí o vyloučení.

## Migrace z obcházení

Pokud jste používali obcházení jako route rules nebo middleware, můžete je nyní nahradit pomocí `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Nový přístup je spolehlivější a funguje na více úrovních routovacího systému.
