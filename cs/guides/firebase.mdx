# 🔥 Nasazení Firebase AppHosting

## 📖 Úvod

Firebase AppHosting je výkonná platforma pro nasazení Nuxt aplikací se serverless infrastrukturou. Při nasazování aplikací s `nuxt-i18n-micro` se však můžete setkat s konkrétními problémy souvisejícími s tím, jak jsou soubory překladů JSON servírované. Tento průvodce poskytuje komplexní řešení, aby vaše překlady v produkci fungovaly správně.

## ⚠️ Časté problémy

### Soubory překladů se neaplikují

**Příznaky:**

- ✅ Překlady fungují ve vývoji (`nuxt dev`) bezchybně
- ❌ Po nasazení na Firebase AppHosting se JSON soubory načtou, ale překlady se neaplikují
- ❌ V konzoli se neobjevují žádné chyby
- ❌ Soubory překladů jsou viditelné v Network tabu, ale mají nesprávný `Content-Type: text/html` místo `application/json`

**Hlavní příčina:**

Firebase AppHosting (a další platformy používající Nitro prerendering) mohou servírovat prerendered JSON soubory s nesprávnými MIME typy. Když prohlížeč obdrží JSON soubory s `Content-Type: text/html`, nemůže je správně parsovat a překlady tiše selžou.

## ✅ Řešení

### Řešení 1: Konfigurace Route Rules (doporučeno)

Nejpřímočařejším řešením je přidat explicitní hlavičky pro překladové routy do `nuxt.config.ts`:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**Výhody:**

- ✨ Jednoduchá konfigurace
- 🚀 Vylepšuje výkon správným cachováním
- 🔒 Funguje napříč všemi nasazovacími platformami

### Řešení 2: Vlastní API Base URL

Pokud používáte vlastní `apiBaseUrl` (jen prefix cesty), upravte route rules odpovídajícím způsobem:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### Řešení 3: Konfigurace specifická pro Firebase

Vytvořte nebo aktualizujte soubor `firebase.json` v kořenu projektu:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```


### Řešení 4: Konfigurace Firebase Functions

Pro nasazení Firebase Functions se ujistěte, že `functions/package.json` obsahuje potřebné závislosti:

```json
{
  "name": "functions",
  "type": "module",
  "engines": {
    "node": "18"
  },
  "dependencies": {
    "firebase-admin": "^12.0.0",
    "firebase-functions": "^5.0.0"
  }
}
```

## 🔍 Debugging

### Zapnutí debug módu

Přidejte debug logování pro identifikaci problémů:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

To vypíše podrobné logy o:

- 📝 Načítání souborů překladů
- 🔄 Cache operacích
- ⚠️ Chybách načítání

### Kontrola Network tabu

1. Otevřete DevTools → Network tab
2. Filtrujte podle „data.json“
3. Klikněte na request souboru překladu
4. Ověřte **Response Headers**:
   - ✅ `Content-Type: application/json` (správně)
   - ❌ `Content-Type: text/html` (nesprávně, potřebuje opravit)

### Ověření prerender výstupu

Po buildu zkontrolujte, že se soubory překladů generují:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

Pro každý locale pod každou stránkou byste měli vidět `data.json`.

## 🚀 Konfigurace buildu

### Nitro Preset

Pro Firebase AppHosting se ujistěte, že používáte správný preset:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### Konfigurace prerenderingu

Nakonfigurujte prerendering pro optimální výkon:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

## ✅ Kontrolní seznam ověření

Po aplikaci oprav ověřte, že vše funguje:

- [ ] Build se dokončí bez chyb
- [ ] JSON soubory překladů jsou v `.output/public/_locales/\{page\}/\{locale\}/data.json`
- [ ] Network tab pro soubory překladů zobrazuje `Content-Type: application/json`
- [ ] Překlady se správně zobrazují při prvním načtení stránky
- [ ] V konzoli nejsou žádné hydratační neshody
- [ ] Přepínání jazyka funguje správně
- [ ] SEO meta tagy se správně generují

## 🔄 Nasazovací workflow

### 1. Příprava buildu

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. Nasazení na Firebase

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. Ověření nasazení

1. Navštivte nasazený web
2. Otevřete DevTools → Network tab
3. Přejděte na stránku
4. Zkontrolujte, že se `/_locales/index/en/data.json` (nebo váš výchozí locale) načítá s:
   - Status: 200
   - Content-Type: application/json
   - Response obsahuje platný JSON

## 🔧 Řešení problémů

### Problém: 404 chyby pro soubory překladů

**Řešení:** Ujistěte se, že se soubory překladů kopírují do výstupního adresáře:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### Problém: Překlady fungují na některých stránkách, ale ne na jiných

**Řešení:** Zkontrolujte, zda se generují stránkově specifické překlady:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

Pokud stránkově specifické překlady chybí, ujistěte se, že `disablePageLocales` není nastaveno na `true`:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### Problém: Pomalé načítání překladů

**Řešení:** Optimalizujte cachování a preloading:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## ⚡ Optimalizace výkonu

### Zapnutí komprese

Firebase automaticky zpracovává Gzip/Brotli kompresi, ale ujistěte se, že je váš build optimalizovaný:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### Lazy loading překladů

`Nuxt I18n Micro` automaticky líně načítá překlady pro jednotlivé stránky. Překlady se načítají jen v případě potřeby a snižuje se počáteční velikost bundlu. Jde o vestavěnou funkčnost, žádná další konfigurace není potřeba.

Pro další optimalizaci:

- Použijte `disablePageLocales: false` (výchozí) pro zapnutí stránkově specifických překladů
- Udržujte kořenové překlady minimální
- Používejte soubory překladů specifické pro routy pro obsah stránek

<Tip>
Modul automaticky nastavuje správné hlavičky `Content-Type` počínaje verzí **v3.0.0+**. Pokud máte problémy, aktualizujte na nejnovější verzi:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
