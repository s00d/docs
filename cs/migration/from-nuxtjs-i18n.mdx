# 🔄 Migrace z `nuxt-i18n` na `Nuxt I18n Micro`

## Kterého průvodce potřebujete?

| Migrujete z…                           | Průvodce                                         |
| -------------------------------------- | ------------------------------------------------ |
| `@nuxtjs/i18n` (modul založený na vue-i18n) | **Tato stránka**                              |
| `nuxt-i18n-micro` v2.x                 | [Upgrade z v2.x na v3.x](/migration/v2-to-v3)    |

## Proč migrovat?

- **Vylepšený výkon**: přibližně o 51 % rychlejší buildy a o 54 % menší spotřeba paměti při buildu oproti `@nuxtjs/i18n` **v10.6** v našich [benchmark fixtures](/guides/performance-results)
- **Zjednodušená konfigurace**: zjednodušené nastavení s rozumnými výchozími hodnotami
- **Lepší správa zdrojů**: optimalizované zpracování velkých překladových souborů

## Klíčové rozdíly

| Vlastnost               | `nuxt-i18n`                      | `Nuxt I18n Micro`                         |
| ----------------------- | -------------------------------- | ----------------------------------------- |
| Překladové soubory      | JS/TS/JSON, načítané přes `vueI18n` | Pouze JSON, automaticky generované v dev  |
| Generování rout         | Runtime                          | Při buildu (`@i18n-micro/route-strategy`) |
| Načítání překladů       | Zabalené v JS                    | Lazy-loaded JSON na stránku               |
| Stav locale             | `useI18n()` z `vue-i18n`         | Composable `useI18nLocale()`              |
| `detectBrowserLanguage` | Podporováno                      | Místo toho použijte `autoDetectLanguage`  |

## Krok za krokem

### 1. Instalace

```bash
npm install nuxt-i18n-micro
```

### 2. Aktualizace konfigurace

**Předtím (nuxt-i18n):**

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    defaultLocale: 'en',
    vueI18n: './i18n.config.js',
    detectBrowserLanguage: { useCookie: true },
  },
})
```

**Potom (Nuxt I18n Micro v3):**

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    localeCookie: 'user-locale',
    autoDetectLanguage: true,
  },
})
```

### 3. Reorganizace překladových souborů

Přesuňte překlady do adresáře `locales` ve formátu JSON. Zde je kompletní porovnání projektu:

**Before (`nuxt-i18n`):**

```text
my-app/
├── i18n/
│   └── locales/          # langDir
│       ├── en.json       # all translations in one file
│       ├── ru.json
│       └── de.json
├── pages/
│   ├── index.vue
│   └── page.vue
├── server/
│   └── tsconfig.json
├── nuxt.config.ts        # config will change
└── package.json
```

**After (Nuxt I18n Micro):**

```text
my-app/
├── locales/              # translationDir
│   ├── en.json           # root-level translations
│   ├── ru.json
│   ├── de.json
│   └── pages/            # page-specific
│       ├── index/
│       │   ├── en.json
│       │   ├── ru.json
│       │   └── de.json
│       └── page/
│           ├── en.json
│           ├── ru.json
│           └── de.json
├── pages/
│   ├── index.vue         # API changes
│   └── page.vue
├── server/
│   └── tsconfig.json
├── nuxt.config.ts        # new config
└── package.json
```

<Tip>
Missing page-specific translation files are **auto-generated** in development mode — just run `nuxt dev` and the module will create empty JSON files for each page and locale.
</Tip>

### 4. Aktualizace navigace

```diff
- <nuxt-link :to="{ name: 'index' }">Home</nuxt-link>
+ <NuxtLink :to="$localeRoute({ name: 'index' })">Home</NuxtLink>
+ <!-- or use the built-in component -->
+ <i18n-link :to="{ name: 'index' }">Home</i18n-link>
```

### 5. Aktualizace SEO

Odstraňte veškeré ruční SEO konfigurace z `nuxt-i18n`. Nuxt I18n Micro automaticky generuje tagy `hreflang`, canonical URL a Open Graph, když je nastaveno `meta: true`.

### 6. Testování

Důkladně otestujte překlady, přepínání locale, přesměrování a SEO meta tagy.

## 🛡️ Časté problémy a jejich řešení

### ❌ Překladové soubory se nenačítají

Ujistěte se, že překladové soubory jsou ve správném adresáři a mají formát JSON. Ověřte, že `translationDir` odpovídá umístění souborů.

### ⚠️ Chyby „Route Not Found"

Zkontrolujte, že všechny kódy locale v poli `locales` jsou správné a routy jsou správně nastavené.

### 🏷️ Chybějící SEO tagy

Ověřte, že je nastaveno `meta: true` a každý locale má platný kód `iso`.

### 🔄 Nesoulady při hydrataci

Pokud používáte strategii `no_prefix`, nastavte locale v serverovém pluginu s `order: -10` pomocí `useI18nLocale().setLocale()`, abyste zajistili, že se server a klient shodnou na locale. Viz [Vlastní detekce jazyka](/guides/custom-language-detection).

### 🍪 Přesměrování nefungují

U prefix strategií zajistěte, aby bylo nastaveno `localeCookie: 'user-locale'`. Bez cookie nemá plugin serverového přesměrování možnost si zapamatovat preferovaný locale uživatele mezi znovunačteními stránky.
