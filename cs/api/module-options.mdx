# Reference voleb modulu

Každá volba, kterou `nuxt-i18n-micro` přijímá, se v době buildu čte z rozhraní `ModuleOptions` v [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts). Nic na této stránce není psáno ručně, takže nemůže zaostat za kódem. Typy, výchozí hodnoty i popisy pocházejí přímo z deklarací.

Chcete-li vědět, co tyto volby *znamenají* dohromady, které kombinace dávají smysl, co se změní při přepnutí strategie a viděné příklady, přečtěte si [Konfiguraci](/guides/configuration). Tato stránka je vyčerpávající seznam; ta druhá je vysvětlení.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Vnořené volby se zobrazují pod svou tečkovanou cestou, takže `translationPayloads.mode` je klíč `mode` uvnitř objektu `translationPayloads`.

## Locale a routování

Které jazyky existují a jak se objevují v URL.

| Volba | Typ | Výchozí | Popis |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Seznam podporovaných locale. Každá položka definuje kód locale plus volitelná metadata (ISO, směr, zobrazované jméno a další). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Strategie routování URL pro prefixy locale. - `'no_prefix'`: bez locale v URL; locale uložený v cookie. - `'prefix_except_default'`: prefix pro všechna locale kromě výchozího. - `'prefix'`: vždy prefix, včetně výchozího locale. - `'prefix_and_default'`: jako `prefix`, ale výchozí locale je dostupný i bez prefixu. |
| `defaultLocale` | `string` | `'en'` | Locale použitý, když z URL ani uživatelských preferencí nelze určit locale. Slouží také jako fallback pro chybějící překlady, pokud není nastaven `fallbackLocale`. |
| `localeCookie` | `string \| null` | `null` | Název cookie pro perzistenci preferovaného locale uživatele napříč sezeními. Nastavení na `null` vypne perzistenci přes cookie. Pro strategii `no_prefix` se automaticky nastaví na `'user-locale'`, pokud není zadáno. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Globální konfigurace locale na úrovni route. Umožňuje omezit nebo přizpůsobit locale routy pro konkrétní stránky bez úpravy jejich komponent. - `false`: vyloučí routu z lokalizace. - `Record<LocaleCode, string>`: vlastní cesty pro jednotlivé locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Vlastní regulární výraz (nebo jeho zdrojový řetězec) pro párování kódů locale v segmentech URL. Všechny kódy locale definované v `locales` musí tomuto vzoru odpovídat, jinak se vypíše varování. |
| `noPrefixRedirect` | `boolean` | `false` | Pro strategii `no_prefix`: zapne přesměrování z URL s prefixem locale (např. `/en/about`) na verzi bez prefixu (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Vzory URL (řetězce nebo RegExp), které se z i18n zpracování zcela vyloučí. Odpovídající routy nedostanou prefixy locale, přesměrování ani načítání překladů. Interní cesty Nuxtu (`/__nuxt_error` a další) jsou vždy automaticky vyloučeny. |
| `routeLocales` | `Record<string, string[]>` | — | Omezení locale pro jednotlivé routy získaná z volání `defineI18nRoute()`. Mapuje cestu routy (např. `'/about'`) na pole povolených kódů locale. Nevypsané routy nemají žádná omezení (všechna locale jsou povolena). |

## Překlady

Kde soubory s překlady žijí a jak se klíče rozhodují.

| Volba | Typ | Výchozí | Popis |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Cesta k adresáři s JSON soubory překladů, relativně k rootu projektu. |
| `disableWatcher` | `boolean` | `false` | Vypne file watcher, který ve vývojovém režimu automaticky vytváří chybějící soubory překladů. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Mapuje názvy rout na jiné názvy rout, aby sdílely stejné soubory překladů. Například `\{ 'about-us': 'about' \}` znamená, že stránka `about-us` použije překlady ze stránky `about` místo svých vlastních. |
| `plural` | `PluralFunc` | `built-in pluralization (form index by count)` | Vlastní funkce pluralizace. Přijímá `(key, count, params, locale, getter)` a měla by vrátit zvolený plurální tvar jako řetězec, nebo `null`/`undefined` pro fallback na vestavěnou logiku `defaultPlural` (takže můžete přepsat jen některé locale). Pro Nuxt modul se funkce serializuje pomocí `.toString()` do `.nuxt/i18n.plural.mjs`. Musí být soběstačná (bez importů a vnějšího scope). Řetězec s cestou k souboru **není** podporován. |
| `disablePageLocales` | `boolean` | `false` | Vypne soubory překladů pro jednotlivé stránky. Při `true` se načítají pouze globální překlady (`\{locale\}.json`); soubory specifické pro stránku (`pages/\{page\}/\{locale\}.json`) se negenerují ani nenačítají. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Kód globálního fallback locale. Když chybí klíč překladu v aktivním locale, modul jej vyhledá v tomto locale, než vrátí samotný klíč. |

## Payloady a cachování

Jak se překlady dostanou do prohlížeče. [Výkon](/guides/performance) vysvětluje, co tyto volby mění za běhu.

| Volba | Typ | Výchozí | Popis |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Preload překladů pro index stránku v globálním Nitro middleware (pouze na serveru, soukromá konfigurace). |
| `apiBaseUrl` | `string` | `'_locales'` | Základní segment URL cesty pro API routu překladů (používaný při načítání dat v SSR/SSG). Lze také nastavit přes proměnnou prostředí `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Přepíše hostitele používaného pro klientské požadavky na načtení překladů. Užitečné, když klient dosahuje na server přes jiný hostname, než jaký vidí Nuxt. Lze také nastavit přes proměnnou prostředí `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Přepíše hostitele používaného pro serverové požadavky na načtení překladů. Užitečné v kontejnerech/mikroslužbách, kde server dosahuje sám na sebe přes interní hostname. Lze také nastavit přes proměnnou prostředí `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Řídí, jak jsou emitovány payloady překladů (Node: `public/<apiBaseUrl>`; Edge: Nitro `serverAssets`). - **Node**: `serverAssets` znamená lokální SSR přes `readFile` pod `public/` (bez Rollup `raw:`). - **Edge**: `serverAssets` registruje Nitro `serverAssets` (`assets:i18n`); nevynucuje veřejnou kopii. Ponechejte výchozí hodnoty pro obvyklé all-in-one nastavení. Pro velké Edge katalogy preferujte `mode: 'source'`. Pro nasazení s CDN vypněte lokální výstupy a nastavte `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Strategie payloadu překladů. - `premerged`: matice `\{page\}/\{locale\}/data.json` v době buildu (výchozí) - `source`: kompaktní zdrojové soubory sloučené za běhu (preferujte na Edge / u velkých katalogů) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Lokální SSR payloady: Node čte `public/<apiBaseUrl>` (vynutí veřejnou kopii); Edge embeduje přes Nitro `serverAssets`. - **Node**: bez Nitro `serverAssets` (vyhýbá se Rollup `raw:`). SSR čte `public/<apiBaseUrl\|publicDir>` jako `\{page\}/\{locale\}/data.json`; když je `true`, veřejná kopie se vynutí, i když je `publicAssets` false. - **Edge** (`nitro.node === false`): Nitro `serverAssets` (`assets:i18n`) se stejným rozvržením jako `mode`. **Nevynucuje** veřejnou kopii. Pro CDN nastavte `publicAssets: true`. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Zaregistruje vestavěnou serverovou routu na `/\{apiBaseUrl\}/:page/:locale/data.json`. Vypněte, když jsou payloady překladů podávané z externího hostitele/CDN. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Zkopíruje payloady do Nitro veřejného výstupu. Premerged → `\{page\}/\{locale\}/data.json` pod `apiBaseUrl`; source → kompaktní strom. Na Node je tento strom také zdrojem pro SSR, když `serverAssets` vynutí veřejnou kopii. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Přihlaste se k Nitro-prerender `/\{apiBaseUrl\}/.../data.json`. Obvykle redundantní, když premerged `publicAssets` už tyto soubory zapsal. |
| `translationPayloads.publicDir` | `string` | — | Veřejná výstupní složka relativní k rootu Nitro public. Výchozí je `apiBaseUrl` (`_locales`). Aby statické soubory odpovídaly URL klientského načítání (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Během buildu vypíše varování, když počet vygenerovaných souborů payloadu překročí tento práh. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Během buildu vypíše varování, když celková velikost vygenerovaného payloadu překročí tento práh v bajtech. |

## SEO

Meta tagy generované pro každou lokalizovanou stránku.

| Volba | Typ | Výchozí | Popis |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Automaticky generuje SEO meta tagy (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | Základní URL pro SEO meta tagy (canonical, og:url, hreflang). - Konkrétní URL řetězec (např. `'https://example.com'`): použije se tak, jak je (nejvyšší priorita). - `undefined`: vrátí se k `site.url` z `nuxt-site-config`, když je tento modul přítomen, jinak k aktuálnímu origin requestu (`useRequestURL().origin` na serveru, `window.location.origin` na klientu). |
| `metaTrustForwardedHost` | `boolean` | `true` | Důvěřuje hlavičce `X-Forwarded-Host` při resolvování základní URL pro meta tagy. Zapněte, když aplikace běží za reverzní proxy (nginx, Cloudflare, AWS ALB a podobně), která tuto hlavičku nastavuje na skutečný klientský hostname. |
| `metaTrustForwardedProto` | `boolean` | `true` | Důvěřuje hlavičce `X-Forwarded-Proto` při resolvování protokolu pro meta tagy. Zapněte, když aplikace běží za TLS-terminující proxy, aby canonical URL používaly `https://`, i když samotná aplikace poslouchá na HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Seznam názvů query parametrů zachovaných v canonical a `og:url` meta tagách. Parametry mimo tento seznam se z canonical URL odstraní. |

## Detekce a přesměrování

Výběr locale pro návštěvníka, který si žádný nevybral.

| Volba | Typ | Výchozí | Popis |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Zapne automatická přesměrování založená na locale. Při `true` jsou návštěvníci při první návštěvě přesměrováni na svůj preferovaný locale (detekovaný z cookie, hlavičky `Accept-Language` nebo výchozího). |
| `autoDetectLanguage` | `boolean` | `true` | Automaticky detekuje preferovaný jazyk uživatele z HTTP hlavičky `Accept-Language`. Používá se v kombinaci s `autoDetectPath` pro rozhodnutí, kdy detekce probíhá. |
| `autoDetectPath` | `string` | `'/'` | Kde mohou přesměrování podle cookie / Accept-Language běžet (když je `redirects` zapnuto). - `'/'`: pouze `/` (deep linky v výchozím locale zůstávají dosažitelné; výchozí) - `'no_prefix'`: pouze cesty bez prefixu locale - `'*'`: každá cesta, včetně přepsání explicitního prefixu locale (např. `/fr/about` → `/de/about`, když cookie preferuje `de`) - jakýkoli jiný řetězec: přesná shoda cesty (např. `'/welcome'`) Úklid prefixované strategie (např. `/en` → `/` pod `prefix_except_default`) není podmíněný. |

## Registrace

Části modulu, které lze vypnout.

| Volba | Typ | Výchozí | Popis |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Zaregistruje plugin makra `defineI18nRoute()`, umožňující volání `defineI18nRoute()` pro jednotlivé stránky. |
| `plugin` | `boolean` | `true` | Zaregistruje hlavní i18n plugin, který poskytuje `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` a další runtime pomocníky. |
| `hooks` | `boolean` | `true` | Zaregistruje plugin i18n hooks, který poskytuje app-level hooks `i18n:register` a `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`. |
| `components` | `boolean` | `true` | Zaregistruje vestavěné i18n komponenty (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Nastavením na `false` vypnete automatickou registraci komponent (například když je nepoužíváte a chcete zmenšit stopu modulu). |
| `types` | `boolean` | `true` | Vygeneruje TypeScript deklarace typů pro `useI18n`, `$t` a související pomocníky na základě klíčů překladů ve výchozích souborech locale. |
| `debug` | `boolean` | `false` | Zapne podrobné debug logování pro detekci locale, generování rout a načítání překladů. |

| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Pojmenované formáty čísel pro každý locale (kompatibilní s Vue I18n). Umožňuje volání typu `$tn(1000, 'currency')`. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Pojmenované formáty datumu a času pro každý locale (kompatibilní s Vue I18n `datetimeFormats`). Umožňuje volání typu `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | HTTP `Cache-Control` max-age (sekundy) pro `/\{apiBaseUrl\}/:page/:locale/data.json`. Aplikuje se plně, jen dokud `dateBuild` bustuje URL (`?v=...`), což je výchozí: odpověď je pak `public, max-age=…, immutable` a bezpečná pro prohlížeče i CDN. - `dateBuild: 0`/`''`: URL je stabilní, takže tato doba se *nedodrží*; odpověď se místo toho stane `public, max-age=0, must-revalidate`. Payloady zkopírované do `public/` a podávané hostingovou platformou mají hlavičky té platformy. Viz Průvodce výkonem. Analogické k experimentálnímu `httpCacheDuration` z `@nuxtjs/i18n` (v10.2.0), ale jako explicitní hlavička odpovědi místo Nitro `defineCachedEventHandler` maxAge. |
| `dateBuild` | `string \| number` | — | Hodnota používaná pro cache-busting požadavků na překlady (`?v=...`). Když není zadána, modul se vrátí k `Date.now()` (nedeterministické). Pro reprodukovatelná / rolling nasazení nastavte na stabilní hodnotu (např. git SHA nebo číslo buildu). |
| `experimental` | `Record<string, unknown>` | — | Přihrádka pro experimentální/nestabilní volby. Obsah se může měnit nebo být bez upozornění odstraněn mezi minor verzemi. |
