# 🗄️ Architektura cache a úložiště překladů

## 📖 Přehled

Nuxt I18n Micro v3 používá vícevrstvou architekturu cache pro překlady. Načítání payloadu závisí na `translationPayloads.mode`:

- **`premerged`** (výchozí) — root, page, fallback a layer soubory jsou při buildu sloučeny přes `@i18n-micro/utils/build` do `\{page\}/\{locale\}/data.json`
- **`source`** — kompaktní zdrojové soubory jsou uchovány pro slučování za běhu přes `@i18n-micro/utils/source-loader` a `@i18n-micro/utils/merge-source` (Edge je vnořuje do Nitro `serverAssets`; Node je při kopírování čte z `public/`)

Tato stránka popisuje, jak vestavěná cache funguje a jak ji rozšířit pro vlastní použití (administrátorské nástroje, externí API, invalidace cache).

## 🧱 Klíčové komponenty

### 1. `TranslationStorage` (klient + server)

**Soubor**: `src/runtime/utils/storage.ts`

Singleton třída poskytující jednotné úložiště překladů pro klient i server. Používá `Symbol.for('__NUXT_I18N_STORAGE_CACHE__')` na `globalThis`, aby zajistila existenci pouze jedné instance, i když je načteno více bundle.

**Klíčové metody:**

| Metoda                              | Popis                                                                    |
| ----------------------------------- | ------------------------------------------------------------------------ |
| `getFromCache(locale, routeName?)`  | Synchronní kontrola: vrátí cachovaná in-memory data nebo `null`          |
| `load(locale, routeName?, options)` | Asynchronní načtení s cachováním: nejprve zkontroluje cache, poté fetch přes `$fetch` |
| `clear()`                           | Vymaže celou cache                                                       |

**Formát klíče cache**: `\{locale\}:\{routeName\}` (např. `en:index`, `fr:about`)

```typescript
import { translationStorage } from '../utils/storage'

// Synchronous cache check
const cached = translationStorage.getFromCache('en', 'index')

// Async load (with automatic caching)
const result = await translationStorage.load('en', 'index', {
  apiBaseUrl: '_locales',
  baseURL: '/',
  dateBuild: '2024-01-01',
})
// result.data — merged translations
// result.cacheKey — cache key used
```

### ⚙️ Deterministické cache busting (`i18n.dateBuild`)

Ve výchozím nastavení tento modul generuje `dateBuild` během buildu pomocí `Date.now()`. Ta je následně vložena do generovaného `#build/i18n.strategy.mjs` a použita jako query parametr (`?v=...`) k invalidaci cache požadavků na překlady po přebuildu.

Pokud potřebujete reprodukovatelné buildy (například pro zlepšení míry úspěšnosti cache chunků při rolling deploymentech), nastavte v `nuxt.config` stabilní hodnotu:

```ts
export default defineNuxtConfig({
  i18n: {
    // Any stable string/number (git SHA, CI build number, release tag, etc.)
    dateBuild: process.env.GIT_SHA ?? 'local-dev',
  },
})
```

### 2. `loadTranslationsFromServer()` (pouze server)

**Soubor**: `src/runtime/server/utils/server-loader.ts`

Načte překlady pro locale/stránku a cachuje sloučený výsledek do process-global `CacheControl` mapy klíčované přes `@i18n-micro/hmr/cache-keys` (`SERVER_CC_KEY`).

Chování: SSR načítá z `#i18n-internal/payload-source` — **Node** `readFile` pod `public/<apiBaseUrl>` (`\{page\}/\{locale\}/data.json` v režimu premerged), **Edge** `assets:i18n`. `premerged` čte jeden soubor; `source` slučuje root/page/fallback přes `@i18n-micro/utils/source-loader`.

```typescript
import { loadTranslationsFromServer } from '../server/utils/server-loader'

// Returns { data: Translations, json: string }
const { data, json } = await loadTranslationsFromServer('en', 'index')
```

### 3. Načítání na klientovi (bez HTML embed)

Slovníky **nejsou** zapisovány do `nuxtApp.payload`. Server je drží v paměti pro SSR
render; klientský plugin `await`uje `switchContext`, který načte `/\{apiBaseUrl\}/:page/:locale/data.json`
(stejné výchozí chování jako `@nuxtjs/i18n` s `experimental.preload: false`).

`NuxtI18n` drží aktivní slovník view-layer používaný `$t()` a `$has()`. `NuxtTranslationLoader` přepíná kontext locale/routy a slučuje chunky do této vrstvy.

### 4. Serverová API routa

**Routa**: `/_locales/\{page\}/\{locale\}/data.json`

**Soubor**: `src/runtime/server/routes/i18n.ts`

Tato Nitro routa servíruje sloučené překlady pro aktivní režim payloadu. Volá `loadTranslationsFromServer()` a vrací výsledek jako JSON.

V produkci také nastavuje:

```http
Cache-Control: public, max-age={httpCacheDuration}, immutable
```

Výchozí `httpCacheDuration` je `31536000` (1 rok). To je bezpečné, protože klienti požadují payloady s cache-bustingem `?v=\{dateBuild\}`. Nastavením `httpCacheDuration: 0` hlavičku vynecháte. V developmentu se hlavička neuplatňuje.

## 📥 Rozšíření: vlastní načítání překladů

### Čtení z cache (serverová routa)

```ts
// server/api/i18n/load-cache.[post].ts
import { defineEventHandler, readBody } from 'h3'
import { loadTranslationsFromServer } from '#imports'

export default defineEventHandler(async (event) => {
  const { page, locale } = await readBody<{ page: string; locale: string }>(event)
  const { data } = await loadTranslationsFromServer(locale, page)
  return { locale, page, data }
})
```

### Aktualizace překladů (soubor + invalidace cache)

```ts
// server/api/i18n/update.[post].ts
import { defineEventHandler, readBody, createError } from 'h3'
import { join } from 'node:path'
import { readFile, writeFile } from 'node:fs/promises'
import { deepMergeTranslations } from '@i18n-micro/utils/deep-merge'

export default defineEventHandler(async (event) => {
  const { path, updates } = await readBody<{ path: string; updates: Record<string, unknown> }>(event)

  if (!path || !updates) {
    throw createError({ statusCode: 400, statusMessage: 'Missing path or updates' })
  }

  const fullPath = join('locales', path)
  let existing: Record<string, unknown> = {}

  try {
    const content = await readFile(fullPath, 'utf-8')
    existing = JSON.parse(content) as Record<string, unknown>
  } catch {
    // File does not exist — create new
  }

  const merged = deepMergeTranslations(existing, updates)
  await writeFile(fullPath, JSON.stringify(merged, null, 2), 'utf-8')

  return { success: true, path, updated: merged }
})
```

## 🧹 Vyčištění cache

### Programové vyčištění cache (klient)

Použijte vestavěnou metodu `$clearCache`:

```vue
<script setup>
const { $clearCache } = useNuxtApp()

// Clears both TranslationStorage and plugin-level cache
$clearCache()
</script>
```

### Chování serverové cache

Serverová cache (`loadTranslationsFromServer`) je process-global a přetrvává, dokud:

- se serverový proces nerestartuje
- není detekováno nové nasazení (jiná hodnota `dateBuild`)

Pro serverless prostředí má každý cold start čerstvou cache.

## ⚙️ Konfigurace pro serverless

Pro serverless prostředí (Cloudflare Workers, AWS Lambda) vestavěná cache používá in-memory `Map` objekty. Pro samotnou cache překladů není potřeba žádná konfigurace externího úložiště.

Nitro úložiště pro zdrojové překladové soubory však může vyžadovat konfiguraci:

```ts
export default defineNuxtConfig({
  nitro: {
    storage: {
      // Only needed if default file-system storage is unavailable
      'assets:server': {
        driver: 'cloudflare-kv-binding',
        binding: 'MY_KV_NAMESPACE',
      },
    },
  },
})
```

## 💡 Klíčové rozdíly oproti v2

| Aspekt              | v2                            | v3                                                                       |
| ------------------- | ----------------------------- | ------------------------------------------------------------------------ |
| Klientská cache     | `useStorage('cache')`         | Singleton `TranslationStorage` (Symbol.for na globalThis)                |
| SSR přenos          | Runtime konfigurace           | Plné chunky přes `payload.data` (v3.0 používalo `useState`)              |
| Serverová cache     | Nitro cache storage           | Process-global `Map` přes `Symbol.for`                                   |
| Logika slučování    | Na straně klienta             | Při buildu (`premerged`) nebo za běhu (`source`) přes `@i18n-micro/utils/*` |
| Formát klíče cache  | `i18n:merged:\{page\}:\{locale\}` | `\{locale\}:\{routeName\}`                                               |
