---
title: "useI18nLocale"
description: "useI18nLocale はロケールの state とロケール cookie を読み書きします。カスタムロケール検出のエントリポイントです。"
---

`useI18nLocale()` は、アプリが選択したロケール、つまり `i18n-locale` の state とロケール cookie へのアクセスを提供します。`useState('i18n-locale')` や cookie を手動で書き込む代わりに、ロケールを独自に検出するプラグイン(ドメイン、ユーザープロフィール、ヘッダー)で使用してください。有効性のチェックには、ランタイムオーバーライドを含む有効なロケールが使われます。

## シグネチャ {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

i18n ロケール管理の一元的なエントリポイントです。
useState('i18n-locale')、ロケール cookie、同期ユーティリティを組み合わせます。

## 戻り値 {#returned-values}

| メンバー | 型 | 説明 |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | `useState('i18n-locale')` の ref。 |
| `localeCookie` | `Ref<string \| null>` | [`localeCookie`](/jp/api/module-options#localecookie) の cookie。オプションが `null` の場合は単なる `{ value: null }`。 |
| `hashCookie` | `Ref<string \| null>` | ハッシュルーティング時の `hash-locale` cookie。それ以外の場合は `{ value: null }`。 |
| `validLocales` | `string[]` | 有効なロケールのコード。 |
| `setLocale(locale)` | `(locale: string \| null) => void` | state と cookie を書き込みます。検証は行わず、翻訳も読み込みません。 |
| `syncLocale(locale)` | `(locale: string \| null) => void` | cookie のみを書き込みます。 |
| `getLocale()` | `() => string \| null` | state、次に優先 cookie(ハッシュルーティング時はハッシュ cookie)。検証されません。 |
| `getPreferredLocale()` | `() => string \| null` | state と優先 cookie のうち最初の**有効な**もの、または `null`。 |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | ハッシュルーティング時に設定されていれば state。それ以外は `getLocaleFromRoute(route)`。 |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`、次に有効な state、次に `options.serverLocale`、次にルートのロケール。state が有効でない場合は結果を state に保存します。クライアントでは cookie も書き込みます。 |
| `isValidLocale(locale)` | `(locale) => locale is string` | `locale` が `validLocales` に含まれるかどうか。 |

cookie の有効期間は 1 年で、`path: '/'` と `sameSite: 'lax'` が設定されます。

## 例 {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

モジュールのローダープラグインは開始時に state を読み込むため、state を設定するプラグインはそれより先に実行する必要があります(`enforce: 'pre'`)。state が URL、cookie、`Accept-Language` とどのように競合するかについては [ロケール検出](/jp/guide/locale-detection) を参照してください。完全な手順: [カスタム検出](/jp/guide/custom-auto-detect)。

`setLocale()` は画面上の翻訳を切り替えません。現在のページのロケールを変更するには、[`$switchLocale()`](/jp/api/methods#$switchlocale) を呼び出してください。
