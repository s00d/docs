---
title: "ヘルパー"
description: "モジュールが注入するすべてのランタイムヘルパー(`$t`、`$tc`、`$localePath`、`$switchLocale` など)とそのシグネチャ。"
---

モジュールは Nuxt アプリにランタイムヘルパーを注入します: `$t`、`$tc`、`$localePath`、`$switchLocale` などです。このページでヘルパーのシグネチャと動作を調べられます。シグネチャと説明は `src/runtime/plugins/01.plugin.ts` の `PluginsInjections` および `NuxtAppOnlyInjections` インターフェースに由来します。

## アクセス方法 {#access}

| 場所 | 方法 |
| --- | --- |
| テンプレート | `{{ $t('title') }}` — すべてのヘルパー、`$` 付き |
| `<script setup>` | `const { t, localePath } = useI18n()` — `PluginsInjections` のすべてのヘルパー、`$` あり・なしの両方 |
| プラグイン、ミドルウェア、`<script setup>` | `const { $t, $defineI18nRoute } = useNuxtApp()` — すべて、`$` 付きのみ |

`$defineI18nRoute` は `useNuxtApp()` でのみ型付けされています。[`useI18n`](/jp/composables/useI18n) を参照してください。

```vue
<script setup lang="ts">
const { t, localePath } = useI18n()
</script>

<template>
  <NuxtLink :to="localePath('/about')">{{ t('nav.about') }}</NuxtLink>
</template>
```

## ロケール {#locale}

### `$getLocale` {#$getlocale}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric) => string
```

アクティブなロケールのコード。ルートを渡すと、そのルートが属するロケールを読み取ります。

```ts
$getLocale() // 'de' on /de/about
```

### `$getLocaleName` {#$getlocalename}

```ts
() => string | null
```

設定にあるアクティブなロケールの `displayName`。ない場合は `null` を返します。

### `$getLocales` {#$getlocales}

```ts
() => Locale[]
```

設定されたすべてのロケールとそのメタデータ。

ロケールオブジェクトのカスタムプロパティは書いたとおりに返されます。`Locale` の[モジュール拡張](/jp/api/module-options#locales)で型を付けてください。

### `$defaultLocale` {#$defaultlocale}

```ts
() => string | undefined
```

設定されたデフォルトロケールのコード。

### `$getI18nConfig` {#$geti18nconfig}

```ts
() => ResolvedI18nConfig
```

ランタイムから見た、解決済みのモジュール設定。

この値には[ランタイムでの上書き](/jp/guide/runtime-overrides)(`defaultLocale`、`fallbackLocale`、無効化されたロケール)が含まれます。

```ts
const { strategy, localeCookie } = useNuxtApp().$getI18nConfig()
```

## 翻訳 {#translation}

### `$t` {#$t}

```ts
TranslationFn<CleanTranslation>
```

キーを翻訳し、`params` を埋め込みます。キーが存在しない場合は `defaultValue` を、デフォルトが指定されていない場合はキーそのものを返します。

```ts
// { "welcome": "Welcome, {name}!" }
$t('welcome', { name: 'Ada' }) // 'Welcome, Ada!'
$t('missing.key', {}, 'Fallback') // 'Fallback'
```

ネストしたオブジェクトを指すキーは、文字列ではなくそのオブジェクトを返します。テンプレートでは `[object Object]` と表示されるため、末端のキーを使ってください。

### `$ts` {#$ts}

```ts
TranslationFn<string>
```

`$t` と同様ですが、常に文字列を返します。値は `toString()` を通るため、ネストしたオブジェクトは `'[object Object]'` になります。キーは末端を指すようにしてください。

### `$_t` {#$_t}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<CleanTranslation>
```

`$t` を特定のルートにバインドし、現在のページの外で翻訳します。たとえば、別のルートへのリンクを描画するレイアウトなどです。

```ts
const route = useRoute()
const t = useNuxtApp().$_t(route)
t('page.title')
```

### `$_ts` {#$_ts}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<string>
```

`$ts` を特定のルートにバインドします。`$_t` を参照してください。

### `$tc` {#$tc}

```ts
(key: TranslationKey, params: number | Params, defaultValue?: string) => string
```

複数形を考慮して翻訳します。`params` にはカウントそのもの、または `count` を含むオブジェクトを指定できます。

形は `|` で区切ります。組み込みルールでは、負でない整数のカウント `n` が形 `n` を選び、最後の形で頭打ちになります。負の数、小数、`NaN` のカウントは最後の形になります。`{count}` やその他のパラメーターは選ばれた形に埋め込まれます。

複数形がカウントに従わない言語では、テンプレートを `=0 ` で始めます。すると最初の形は 0 用となり、残りの形は [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) のカテゴリーに従って `zero, one, two, few, many, other` の順に割り当てられます:

```json
{
  "apples": "=0 no apples | one apple | {count} apples",
  "files": "=0 no files | {count} one | {count} few | {count} many"
}
```

```ts
$tc('apples', 0) // 'no apples'
$tc('apples', 1) // 'one apple'
$tc('apples', 7) // '7 apples'

// In `uk` (categories `one, few, many, other`) the forms after the zero form follow those categories:
$tc('files', 21) // '21 one'
$tc('files', 22) // '22 few'
$tc('files', 25) // '25 many'
$tc('files', 2.5) // '2.5 many': no form for `other`, so the last one
```

- `=0 ` は値の先頭にスペース付きで置かれた場合にのみ有効です。`$t` はこれをテキストとして表示します。複数形専用のものです。
- 独自の形を持たないカテゴリーは最後の形になります。負の数や小数のカウントも最後の形になります。
- どのロケールでも動作します。英語なら `=0 none | one | {count} many` のように書けます。
- カテゴリーはロケールの `iso`、なければそのコードから決まります。`Intl` が認識しないコードはインデックスルールにフォールバックし、マーカーは引き続き取り除かれるため、結果が実行環境に左右されることはありません。
- `<i18n-t :plural>` も同じルールに従います。カスタムの [`plural`](/jp/api/module-options#plural) や `customPluralRule` はマーカーを含む生の値を受け取り、自分で判断します。`plural` が `null` を返すと、呼び出しは組み込みルールに戻され、マーカーが尊重されます。

マーカーがない場合、テンプレートはインデックスルールのままです。ただし、一通りにしか解釈できない例外が 1 つあります。プレースホルダーのない 0 の形に続いて、カテゴリーごとに 1 つずつ形があり、複数のカウントが共有する形にはそれぞれ `{count}` が含まれる場合です(`uk` での `no files | {count} one | {count} few | {count} many`)。

独自のルールを使うには [`plural`](/jp/api/module-options#plural) を設定してください。

```ts
// { "apples": "no apples | one apple | {count} apples" }
$tc('apples', 0) // 'no apples'
$tc('apples', 10) // '10 apples'
$tc('cart', { count: 2, name: 'Ada' }) // count and params in one object
```

3 番目の引数は params ではなく `defaultValue` です。

### `$has` {#$has}

```ts
(key: string) => boolean
```

アクティブなロケールでキーが解決されるかどうか。生のキーを表示する代わりに、任意の文言で分岐するために使います。`$t` と同様に、同一ロケール内のページ遷移中は離れていくページのキーも参照します。

```ts
if ($has('promo.banner')) show.value = true
```

## フォーマット {#formatting}

### `$tn` {#$tn}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

アクティブなロケールで `Intl.NumberFormat` を使って数値をフォーマットします。キーを指定すると、設定にある名前付きフォーマットを選択します。

名前付きフォーマットは [`numberFormats`](/jp/api/module-options#numberformats) から取得されます。

```ts
$tn(1234.5, { style: 'currency', currency: 'EUR' }) // '1.234,50 €' in de
$tn(1000, 'currency') // named format
$tn(1000, 'currency', 'de') // named format in another locale
```

### `$td` {#$td}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

アクティブなロケールで `Intl.DateTimeFormat` を使って日付をフォーマットします。キーを指定すると、設定にある名前付きフォーマットを選択します。

名前付きフォーマットは [`datetimeFormats`](/jp/api/module-options#datetimeformats) から取得されます。

```ts
$td(new Date(), { dateStyle: 'long' })
$td(post.createdAt, 'short')
```

### `$tdr` {#$tdr}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

`Intl.RelativeTimeFormat` を使って日付を相対時間("3 日前")としてフォーマットします。

```ts
$tdr(Date.now() - 5 * 60_000) // '5 minutes ago' in en
```

## 切り替えとリンク {#switching-and-links}

### `$switchLocale` {#$switchlocale}

```ts
(locale: string) => Promise<boolean>
```

現在のページの別ロケール版へ遷移します。`no_prefix` とハッシュモードでは、遷移の前にそのロケールの翻訳を読み込みます。`no_prefix` ではルートがその場で置き換えられます(新しい履歴エントリーは作られません)。不明なロケールは無視されます。
この呼び出しは非同期です。遷移後にコードを実行するには `await` してください。ロケールの辞書がアクティブになれば `true` で、そうでなければ `false` で解決されます。後者は、チャンクの読み込みに失敗した場合(現在の辞書が維持されるので、再試行するにはもう一度呼び出します)か、より新しい切り替えが優先された場合です。

```ts
await $switchLocale('de')
```

### `$switchLocalePath` {#$switchlocalepath}

```ts
(locale: string) => string
```

遷移せずに、現在のページの別ロケールでのパスを返します。

```vue
<NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
```

### `$switchLocaleRoute` {#$switchlocaleroute}

```ts
(locale: string) => RouteLocationRaw
```

遷移せずに、現在のページの別ロケールでのルートオブジェクトを返します。独自の `baseUrl` を持つロケールの場合は URL 文字列を返します。`trailingSlash` が有効な場合、オブジェクトはルールに従った `path` と `fullPath` を持ち、`query` と `hash` はそのまま保持されます。`router.push` やリンクでもそれらは維持されます。

### `$switchRoute` {#$switchroute}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => Promise<void>
```

アクティブなロケールを維持したまま、または `toLocale` に切り替えて、別のルートへ遷移します。`$switchLocale` と同様に非同期です。

```ts
$switchRoute('/about') // active locale
$switchRoute({ name: 'about' }, 'de') // switch to de
```

### `$localePath` {#$localepath}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => string
```

指定したロケール、またはアクティブなロケールでパスを解決します。`http(s):`、`mailto:`、`tel:` スキームを持つ文字列はそのまま返されます。ユーザー入力を検証せずにリンク先として渡さないでください。

文字列のパスは、それが表示するページとして解釈されるため、ロケールのカスタムパスも適用されます。

```ts
$localePath('/about') // '/about' in en, '/de/ueber-uns' in de with localeRoutes
$localePath({ name: 'about' }, 'fr') // '/fr/about'
```

### `$localeRoute` {#$localeroute}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => RouteLocationResolved
```

指定したロケール、またはアクティブなロケールでルートを解決します。プレーンなオブジェクトなので、状態に保持しても安全です。パラメーターのエスケープが必要な場合、`path`、`fullPath`、`query`、`hash` は持ちますが、`name` や `params` は持ちません。エンコード済みの URL をルーターに渡すのはパスだからです。別ドメインのロケールでは `path` と `fullPath` が絶対 URL になり、ルーターはこれを扱えません。そのようなリンクは `<i18n-link>` または `$localePath` を使ってください。

### `$getRouteName` {#$getroutename}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric, locale?: string) => string
```

ロケールのプレフィックスを除いたルート名。翻訳のキーとなる名前です。

```ts
$getRouteName() // 'about' on /de/about
```

## ページ設定 {#page-config}

### `$defineI18nRoute` {#$definei18nroute}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

コンポーネント内からページごとのロケール設定と翻訳を登録します。
アクティブなロケールにマージされ、ロケールが変わると再適用されます。

ページの `<script setup>` で、必ず `useNuxtApp()` から分割代入して呼び出してください。ビルドは呼び出しから `locales`、`localeRoutes`、`disableMeta` を読み取ります。ランタイムでは `locales` のみが意味を持ちます(インライン翻訳はアクティブなロケールにマージされます)。詳しいルール: [ページ設定](/jp/guide/per-component-translations)。

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: { en: '/about', de: '/ueber-uns' },
})
</script>
```

### `$setI18nRouteParams` {#$seti18nrouteparams}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

現在のルートにロケールごとのパラメーターを設定し、動的セグメントを言語ごとに変えられるようにします。
SSR 中、head が描画される前に呼び出してください。

パラメーターは、別のパスへの遷移が確定するとクリアされます。ルート名が同じままの `/news/1` から `/news/4` への遷移も含みます。詳細: [ローカライズされたパス](/jp/guide/custom-locale-routes)。

```ts
$setI18nRouteParams({
  en: { slug: 'my-post' },
  de: { slug: 'mein-beitrag' },
})
```

## ランタイム翻訳 {#runtime-translations}

### `$mergeTranslations` {#$mergetranslations}

```ts
(newTranslations: Translations) => void
```

ランタイムでアクティブなロケールに翻訳をマージし、読み込み済みの内容を上書きします。

アクティブなロケールの現在のページチャンクにディープマージします。指定されていないキーは残ります。

```ts
$mergeTranslations({ banner: { title: 'Sale' } })
```

### `$setTranslation` {#$settranslation}

```ts
(key: string, value: unknown) => void
```

アクティブな辞書の `key` の値を置き換えます。これはマージではなく置き換えです。既存の兄弟キーを残したい場合は `$mergeTranslations` を使ってください。

```ts
$setTranslation('banner', { title: 'Sale' }) // drops other keys under banner
$setTranslation('banner.title', 'Sale') // dotted path
```

### `$loadPageTranslations` {#$loadpagetranslations}

```ts
(locale: string, routeName: string, translations: Translations) => Promise<void>
```

ビルド時にキーがわからないコンテンツのために、ランタイムでページの翻訳を読み込みます。

メモリ上の `(locale, routeName)` チャンクにマージし、そのチャンクがアクティブなら画面が更新されます。ここではペイロードは取得されません。まだ読み込まれていないページの翻訳は待機し、そのファイルが読み込まれたときにその上に重ねられます。

```ts
await $loadPageTranslations('en', 'about', { title: 'About us' })
```

### `$resolveTranslations` {#$resolvetranslations}

```ts
() => Translations
```

アクティブなロケールとルートについて現在メモリにあるすべての翻訳をツリーとして返します。
`$t()` が今解決できる内容の読み取り専用ビューです。

結果は読み取り専用として扱ってください。

### `$setMissingHandler` {#$setmissinghandler}

```ts
(handler: MissingHandler | null) => void
```

解決できないキーごとに呼び出されるコールバックを設定します。削除するには `null` を渡します。

ハンドラーは開発時の警告の代わりに実行されます。

```ts
$setMissingHandler((locale, key, routeName) => {
  console.error(`[i18n] missing ${key} in ${locale} (${routeName})`)
})
```

### `$clearCache` {#$clearcache}

```ts
() => void
```

キャッシュされたすべての翻訳チャンクを破棄し、現在のページの辞書を再読み込みします。新しい翻訳が届くまで、ページは現在の翻訳を表示し続けます。開発時の HMR は翻訳ファイルが変更されるたびにこれを呼び出します。

```ts
const { clearCache } = useI18n()
clearCache()
```

再読み込みに失敗した場合、現在の辞書が維持されます。
