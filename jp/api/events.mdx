title: "フック"
description: "i18n:register ランタイムフック: 読み込み時とナビゲーション時に Nuxt プラグインから翻訳を追加します。"
---

モジュールは 1 つのランタイム(アプリ)フック `i18n:register` を呼び出します。プラグインやモジュールが `locales/` ファイルにない翻訳を追加する場合に使用します。コールバックには `register` 関数が渡され、表示中のページに翻訳をマージします。

## `i18n:register` {#i18nregister}

```ts
'i18n:register': (
  register: (translations: unknown, locale?: string) => void,
  locale: string,
) => HookResult
```

| 引数 | 説明 |
| --- | --- |
| `register(translations, locale?)` | 読み込み中のルートのページチャンクに、`locale`(デフォルト: フックの `locale`)の `translations` をディープマージします。既存のキーは上書きされます。 |
| `locale` | 読み込み中のルートのロケール。 |

このフックは `RuntimeNuxtHooks` を通じて型付けされているため、`nuxtApp.hook('i18n:register', …)` にキャストは不要です。

## 呼び出されるタイミング {#when-it-fires}

ローダープラグイン(`i18n-plugin-loader`)が次のタイミングで呼び出します。

1. 起動時に 1 回、すべてのプラグインが実行された後(`app:created`)、アプリのレンダリング前;
2. `router.beforeEach` 内で、パスが変わったときに遷移先ページの翻訳が読み込まれた後 — `no_prefix` ではすべてのナビゲーションで。

すべてのコールバックとすべての `register` 呼び出しは、アプリのレンダリングやナビゲーションの続行前に await されるため、ページはマージされたキーでレンダリングされます。[`hooks: false`](/jp/api/module-options#hooks) の場合、フックは呼び出されません。

## 例 {#example}

```ts
// plugins/i18n-extra.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('i18n:register', async (register, locale) => {
    const extra = await $fetch<Record<string, unknown>>(`/api/cms-strings/${locale}`)
    register(extra, locale)
  })
})
```

これはランタイムフックです。`nuxt.config` やモジュールの `setup` で `nuxt.hook` を使うのではなく、プラグイン内で `nuxtApp.hook` を使って登録してください。モジュールは `addPlugin` でそのようなプラグインを追加します。
