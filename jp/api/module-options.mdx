このページでは、`nuxt.config` の `i18n` オブジェクトのすべてのキーを掲載しています。型やデフォルト値を調べるには表を、例や注意点については下の詳細を使用してください。型、デフォルト値、説明は [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts) の `ModuleOptions` インターフェースから生成されています。

```ts nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
    ],
    defaultLocale: 'en',
  },
})
```

ネストされたオプションは、ドット区切りのパスで表記されます。`translationPayloads.mode` は `translationPayloads` の `mode` キーです。

## ロケールとルーティング {#locales-and-routing}

どの言語が存在し、URL にどのように表れるか。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | サポートするロケールのリスト。各エントリーはロケールコードと、任意のメタデータ（ISO、方向、表示名など）を定義します。 |
| `strategy` | `Strategies` | `'prefix_except_default'` | ロケールプレフィックスの URL ルーティング戦略。- `'no_prefix'` — URL にロケールを含めず、ロケールは Cookie に保存します。- `'prefix_except_default'` — デフォルト以外のすべてのロケールにプレフィックスを付けます。- `'prefix'` — デフォルトロケールも含め、常にプレフィックスを付けます。- `'prefix_and_default'` — `prefix` と同様ですが、デフォルトロケールにはプレフィックスなしでもアクセスできます。 |
| `defaultLocale` | `string` | `'en'` | URL やユーザーの設定からロケールを判断できない場合に使用するロケール。翻訳のフォールバックではありません。その目的には `fallbackLocale` を設定してください。 |
| `localeCookie` | `string \| null` | `null` | セッションをまたいでユーザーのロケール設定を保持するための Cookie 名。`null` に設定すると Cookie による保持を無効にします。`no_prefix` 戦略では、指定されていない場合は自動的に `'user-locale'` に設定されます。`i18n` 設定ブロックで明示的に `null` を指定すると、その場合も無効のままになります。 |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `{}` | ルートレベルのグローバルなロケール設定。コンポーネントを変更せずに、特定のページのロケールルートを制限またはカスタマイズできます。- `false` — ルートをローカライズの対象から除外します。- `Record<LocaleCode, string>` — ロケールごとのカスタムパス。 |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | URL セグメント内のロケールコードにマッチさせるためのカスタム正規表現（またはその文字列ソース）。`locales` のすべてのロケールコードがフラグなしでパターン全体にマッチする必要があり、そうでない場合はビルドが失敗します。 |
| `noPrefixRedirect` | `boolean` | `false` | `no_prefix` 戦略の場合: デフォルトロケールがページのカスタムパスを持つとき（`localeRoutes` / `globalLocaleRoutes`）、ページの元のパスを訪問者のロケールのカスタムパス、それがなければデフォルトロケールのカスタムパスにリダイレクトします（例: `/about` → `/about-us`）。独自のカスタムパスを持たないロケールは元のパスのままです。動的セグメントを持つページはリダイレクトされません。 |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | i18n ルーティングから除外するパス。文字列はパスのプレフィックス（`/admin` は `/admin/x` を含む）または `*` / `?` の glob で、RegExp はパスに対してテストされます。マッチしたページにはロケールのバリアント、ロケールリダイレクト、404 がなく、プリレンダリングからも除外されますが、翻訳付きでレンダリングはされます。`/api`、`/_nuxt`、`/__*`、翻訳ルート、および一般的な静的ファイル（sitemap、robots.txt、favicon、拡張子によるアセット）は常に除外されます。 |
| `routeLocales` | `Record<string, string[]>` | — | ルートごとのロケール制限。ビルド時に `$defineI18nRoute()` の呼び出しから抽出されます。ルートのパス（例: `'/about'`）を、許可されたロケールコードの配列にマッピングします。記載されていないルートには制限がありません（すべてのロケールが許可されます）。 |

## 翻訳 {#translations}

翻訳ファイルの置き場所と、キーの解決方法。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | 翻訳 JSON ファイルを含むディレクトリへのパス（プロジェクトルートからの相対パス）。 |
| `disableWatcher` | `boolean` | `false` | 開発モードで不足している翻訳ファイルを自動作成するファイルウォッチャーを無効にします。 |
| `routesLocaleLinks` | `{ [key: string]: string }` | `{}` | ルート名を別のルート名にマッピングして、同じ翻訳ファイルを共有します。例えば、`{ 'about-us': 'about' }` は、`about-us` ページが独自の翻訳ではなく `about` ページの翻訳を使用することを意味します。 |
| `plural` | `PluralFunc` | ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)`` | カスタムの複数形関数。`(key, count, params, locale, getter)` を受け取り、選択された複数形を文字列として返すか、組み込みの `defaultPlural` ロジックにフォールバックするために `null`/`undefined` を返します（そのため、一部のロケールだけを上書きできます）。Nuxt モジュールでは、関数は `.toString()` で `.nuxt/i18n.plural.mjs` にシリアライズされるため、自己完結している必要があります（import や外側のスコープは不可）。ファイルパスの文字列はサポート**されていません**。 |
| `disablePageLocales` | `boolean` | `false` | ページごとの翻訳ファイルを無効にします。`true` の場合、グローバルな翻訳（`{locale}.json`）のみが読み込まれ、ページ固有のファイル（`pages/{page}/{locale}.json`）は生成も読み込みもされません。 |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | グローバルなフォールバックロケールコード。あるロケールで不足しているキーはこのロケールから取得されます（各ペイロードのビルド時または読み込み時にマージされます）。設定しない場合、不足しているキーはキーそのものとしてレンダリングされます。 |

## ペイロードとキャッシュ {#payloads-and-caching}

翻訳がブラウザーに届く方法。これらがランタイムで何を変えるかは[パフォーマンス](/jp/guide/performance)で説明しています。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Nitro のグローバルミドルウェアで index ページの翻訳をプリロードします（サーバー専用、プライベート設定）。 |
| `apiBaseUrl` | `string` | `'_locales'` | 翻訳 API ルートのベース URL パスセグメント（SSR/SSG のデータ取得で使用）。環境変数 `NUXT_I18N_APP_BASE_URL` でも設定できます。 |
| `apiBaseClientHost` | `string` | `undefined` | クライアントサイドの翻訳取得リクエストに使用するホストを上書きします。クライアントが Nuxt から見えるホスト名とは異なるホスト名でサーバーにアクセスする場合に便利です。環境変数 `NUXT_I18N_APP_BASE_CLIENT_HOST` でも設定できます。 |
| `apiBaseServerHost` | `string` | `undefined` | サーバーサイドの翻訳取得リクエストに使用するホストを上書きします。サーバーが内部ホスト名で自身にアクセスするコンテナ／マイクロサービス構成で便利です。環境変数 `NUXT_I18N_APP_BASE_SERVER_HOST` でも設定できます。 |
| `translationPayloads` | `TranslationPayloadOptions` | — | 翻訳ペイロードの出力方法を制御します（Node サーバー: `public/<apiBaseUrl>`、Edge / 関数 / インライン: Nitro の `serverAssets`）。- **Node サーバー**（`node-server`、`node-cluster`、ディスクの `serveStatic`）: `serverAssets` は `public/` 配下を `readFile` で読み込むローカル SSR を意味します（Rollup の `raw:` なし）。- **Edge、関数プリセット、`serveStatic: "inline"`**（`vercel`、`netlify`、`aws-lambda`、winterjs など）: `public/` はディスク上で SSR から利用できないため、`serverAssets` は Nitro の `serverAssets`（`assets:i18n`）を登録します。パブリックへのコピーは強制しません。CDN／静的配信には `publicAssets: true` を設定してください。一般的なオールインワン構成ではデフォルトのままにしてください。大規模な Edge のカタログでは `mode: 'source'` を推奨します。CDN を利用するデプロイでは、ローカル出力を無効にし、`apiBaseClientHost` / `apiBaseServerHost` を設定してください。 |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | 翻訳ペイロードの戦略。- `premerged`: ビルド時に生成される `{page}/{locale}/data.json` のマトリックス（デフォルト）- `source`: ランタイムでマージされるコンパクトなソースファイル（Edge／大規模なカタログで推奨） |
| `translationPayloads.serverAssets` | `boolean` | `true` | ローカル SSR のペイロード: ディスクから `public/` を配信する Node サーバーはそのツリーを読み込み（パブリックへのコピーを強制）、Edge、関数プリセット、`serveStatic: "inline"` は Nitro の `serverAssets` で埋め込みます。- **Node サーバー**（プリセット自体が `public/` を配信するもの、例: `node-server`）: Nitro の `serverAssets` は使いません（Rollup の `raw:` を回避）。SSR は `public/<apiBaseUrl\|publicDir>` を `{page}/{locale}/data.json` として読み込みます。これが `true` の場合、`publicAssets` が false でもパブリックへのコピーが強制されます。- **Edge、関数プリセット、インライン**（`nitro.node === false` で、`vercel` / `netlify` / `aws-lambda` のようにディスクの `serveStatic` がないもの、または winterjs のような `serveStatic: "inline"`）: `mode` と同じレイアウトで Nitro の `serverAssets`（`assets:i18n`）を使用します。パブリックへのコピーは強制**しません**。CDN／静的配信には `publicAssets: true` を設定してください。 |
| `translationPayloads.serverHandler` | `boolean` | `true` | `/{apiBaseUrl}/:page/:locale/data.json` に組み込みのサーバールートを登録します。翻訳ペイロードを外部のホスト／CDN から配信する場合は無効にしてください。 |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | ペイロードを Nitro のパブリック出力にコピーします。premerged → `apiBaseUrl` 配下の `{page}/{locale}/data.json`、source → コンパクトなツリー。SSR が `public/` を読み込む場合（`node-server` など）、`serverAssets: true` でもこのコピーが強制されます。Edge / 関数 / `serveStatic: "inline"` のプリセットでは、これが `true` の場合にのみコピーします（SSR は Nitro の埋め込みを使用します）。 |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | `/{apiBaseUrl}/.../data.json` の Nitro プリレンダリングにオプトインします。premerged の `publicAssets` がすでにそれらのファイルを書き出している場合、通常は冗長です。 |
| `translationPayloads.publicDir` | `string` | — | Nitro のパブリックルートからの相対パスで指定するパブリック出力フォルダー。デフォルトは `apiBaseUrl`（`_locales`）です。そのため、静的ファイルはクライアントの取得 URL（`/{apiBaseUrl}/{page}/{locale}/data.json`）と一致します。 |
| `translationPayloads.rootDelta` | `boolean` | `true` | ロケールごとに 1 つのルートファイルを書き出し、各ページファイルにはそれとの差分のみを書き出します。クライアントと SSR がそれらをマージします。ファイルが読み込まれる場所ではどこでも、チャンク全体も引き続き機能します。`false` にすると、すべてのページファイルに辞書全体を保持します。`premerged` のみで、`disablePageLocales` では無効です。 |
| `translationPayloads.warnFileCount` | `number` | `500` | 生成されたペイロードのファイル数がこのしきい値を超えると、ビルド時に警告します。 |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | 生成されたペイロードの合計サイズがこのしきい値（バイト）を超えると、ビルド時に警告します。 |

## SEO {#seo}

ローカライズされた各ページに生成されるメタタグ。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | SEO メタタグ（`hreflang`、`canonical`、`og:url`、`og:locale`）を自動的に生成します。 |
| `metaBaseUrl` | `string` | `undefined` | SEO メタタグ（canonical、og:url、hreflang）のベース URL。- 具体的な URL 文字列（例: `'https://example.com'`）— そのまま使用されます（最優先）。- `undefined` — `nuxt-site-config` モジュールが存在する場合はその `site.url` に、存在しない場合は現在のリクエストのオリジン（サーバーでは `useRequestURL().origin`、クライアントでは `window.location.origin`）にフォールバックします。 |
| `metaTrustForwardedHost` | `boolean` | `true` | メタタグのベース URL を解決する際に `X-Forwarded-Host` ヘッダーを信頼します。このヘッダーに実際のクライアント向けホスト名を設定するリバースプロキシ（nginx、Cloudflare、AWS ALB など）の背後でアプリが動作している場合に有効にします。 |
| `metaTrustForwardedProto` | `boolean` | `true` | メタタグのプロトコルを解決する際に `X-Forwarded-Proto` ヘッダーを信頼します。TLS を終端するプロキシの背後でアプリが動作している場合に有効にすると、アプリ自体が HTTP で待ち受けていても canonical URL に `https://` が使われます。 |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | canonical と `og:url` メタタグで保持されるクエリパラメーター名のリスト。このリストにないパラメーターは canonical URL から取り除かれます。 |

## 検出とリダイレクト {#detection-and-redirects}

まだロケールを選択していない訪問者のためにロケールを選ぶ。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | ロケールの自動リダイレクト（サーバープラグインとクライアントのルートミドルウェア）を有効にします。`true` の場合、プレフィックス戦略ではプレフィックスのない URL をローカライズされた形式にリダイレクトします。ロケールは、アプリの状態、Cookie、または `autoDetectPath` が許可する場所では `Accept-Language` から決定され、それ以外の場合はデフォルトになります。`no_prefix` では、検出によって URL が変わることはありません（カスタムパスについては `noPrefixRedirect` を参照）。 |
| `autoDetectLanguage` | `boolean` | `true` | `Accept-Language` HTTP ヘッダーからユーザーの優先言語を自動的に検出します。`autoDetectPath` と組み合わせて、検出を行うタイミングを決定します。 |
| `autoDetectPath` | `string` | `'/'` | Cookie / Accept-Language の設定に基づくリダイレクトを実行できる場所（`redirects` が有効な場合）。- `'/'` — `/` のみ（デフォルトロケールのディープリンクには引き続きアクセスできます。デフォルト）- `'no_prefix'` — ロケールプレフィックスのないパスのみ - `'*'` — 明示的なロケールプレフィックスの書き換えを含む、すべてのパス（例: Cookie が `de` を優先する場合 `/fr/about` → `/de/about`）- その他の文字列 — そのパス。末尾のスラッシュは無視されます（例: `'/welcome'`）。`prefix` では、許可されたパス以外のプレフィックスのない URL も、デフォルトロケールの形式にリダイレクトされます（`/about` → `/en/about`）。`prefix_except_default` でプレフィックス付きのデフォルトロケール（`/en`）は、リダイレクトではなく 404 になります。 |

## 登録 {#registration}

オフにできるモジュールの部分。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | ランタイムで `$defineI18nRoute()` を提供します。いずれにしても、ビルドはページ内の `$defineI18nRoute()` の呼び出しを読み取ります。 |
| `plugin` | `boolean` | `true` | `$t()`、`$tc()`、`$getLocale()`、`$switchLocale()` などのランタイムヘルパーを提供するコア i18n プラグインを登録します。 |
| `hooks` | `boolean` | `true` | 読み込み時とナビゲーション時に `i18n:register` アプリフックを呼び出し、プラグインが翻訳を追加できるようにします。 |
| `components` | `boolean` | `true` | 組み込みの i18n コンポーネント（`<i18n-link>`、`<i18n-switcher>`、`<i18n-t>`、`<i18n-group>`）を登録します。`false` に設定すると、コンポーネントの自動登録を無効にします（例えば、それらを使わずモジュールのフットプリントを減らしたい場合）。 |
| `types` | `boolean` | `true` | デフォルトロケールファイルの翻訳キーに基づいて、`useI18n`、`$t`、および関連するヘルパーの TypeScript 型宣言を生成します。 |
| `debug` | `boolean` | `false` | ロケール検出、ルート生成、翻訳の読み込みについて詳細なデバッグログを有効にします。 |

## その他 {#other}

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `trustForwardedHost` | `boolean` | `false` | リクエストのドメイン（`locales[].baseUrl`）を `Host` ではなく `X-Forwarded-Host` から選択します。そのヘッダーを上書きするプロキシの背後でのみ有効にしてください。 |
| `hreflangBaseLanguage` | `boolean` | `false` | 各ロケールの `iso` から導出した言語のみの `hreflang` も出力します（例: `es-ES` → `es` も）。`locales` 内で最初の地域付きロケールが、その言語の言語のみのタグを取得します。ルーティングの `code` は使用されず、`iso \|\| code` のみが使われます。 |
| `additionalTranslationDirs` | `string[]` | `[]` | 追加のディレクトリ（プロジェクトルート／各 Nuxt レイヤーのルートからの相対パス）。そのトップレベルの `{locale}.json` ファイルは、`translationDir` の前にグローバル辞書へディープマージされます。マージ順: 配列内の各エントリーを順に（レイヤーをまたいで）、次に `translationDir`（競合時に優先）。ルートの `{locale}.json` ファイルのみが読み込まれ、これらのディレクトリ配下の `pages/` は無視されます。例: `translationDir: 'frontend'`、`additionalTranslationDirs: ['common']` → `common/en.json`、次に `frontend/en.json`。 |
| `vueDevtools` | `boolean` | `true` | 開発時に Vue DevTools のインスペクターとタイムラインを登録します（ブラウザー拡張機能）。Nuxt DevTools のカスタムタブとは別です。 |
| `trailingSlash` | `'append' \| 'remove'` | `undefined (inherit from Nuxt)` | `$localePath` / `$switchLocalePath` の末尾スラッシュ（NuxtLink と同等）。未設定の場合は `experimental.defaults.nuxtLink.trailingSlash` がデフォルトになります。i18n のパスヘルパーについて Nuxt のリンクのデフォルトを上書きするには、明示的に設定してください。 |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | ローカライズされたルート名の先頭に付けるプレフィックス（例: `'localized-index'`）。元のルートと生成されたロケールのバリアントを区別するために内部で使用されます。 |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | ルートごとのメタタグの無効化。ルート名またはパスを、`true`（すべてのメタを無効化）またはメタを無効にするロケールコードの配列にマッピングします。ビルド時に `$defineI18nRoute()` の呼び出しで見つかったエントリーが追加されます。 |
| `missingWarn` | `boolean` | `true` | 翻訳キーが不足している場合にコンソールに警告を表示します（開発ビルド、ブラウザー内）。 |
| `hmr` | `boolean` | `true` | 開発時に翻訳ファイルの Hot Module Replacement を有効にします。`true` の場合、JSON 翻訳ファイルの変更により、ページ全体を更新せずに自動的に再読み込みされます。 |
| `cacheMaxSize` | `number` | `0` | メモリー内の翻訳キャッシュの最大エントリー数。fetch キャッシュとサーバーキャッシュは最も長く使われていないエントリーを破棄し、ブラウザーの辞書マップは最も古いもの（FIFO）を破棄します。`0` はブラウザーでは無制限を意味し、その場合サーバーキャッシュは最大 1000 エントリーを保持するため、でっち上げのページ名を含むリクエスト URL によってサーバーメモリーが増大することはありません。 |
| `cacheTtl` | `number` | `0` | fetch とサーバーの翻訳キャッシュの有効期間（秒）。エントリーが保存された時点から数えられ（読み取りでは延長されません）、`apiBaseServerHost` からのデータは少なくともその頻度で更新されます。ブラウザーのアクティブな辞書はこれによって期限切れになりません。`0` はエントリーが期限切れにならないことを意味します。 |
| `cacheStorage` | `string` | — | 複数のサーバーインスタンスが辞書キャッシュとして共有する Nitro ストレージのマウント名（`nitro.storage`、例: `'redis'`）。プロセス内キャッシュの後、ソースの前に読み込まれます。主に `apiBaseServerHost` で効果を発揮し、インスタンスごとではなくバックエンドからの取得が 1 回で済みます。エントリーはビルドごとのキーを持ち、`cacheTtl` 後、または `0` の場合は 1 日後に期限切れになります。開発時とプリレンダリング時は無効です。ストレージが失敗するとソースにフォールバックします。未設定: 共有キャッシュなし。 |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | ロケールごとの名前付き数値フォーマット（Vue I18n 互換）。`$tn(1000, 'currency')` 形式の呼び出しを可能にします。 |
| `timeZone` | `string` | `the runtime's zone` | `$td` と `<i18n-t date>` の IANA タイムゾーン（`Europe/Berlin`）。サーバーとすべてのブラウザーで同じ日付をレンダリングするために設定します。名前付きフォーマット自身の `timeZone` が優先されます。 |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | ロケールごとの名前付き日時フォーマット（Vue I18n 互換の `datetimeFormats`）。`$td(date, 'short')` 形式の呼び出しを可能にします。 |
| `httpCacheDuration` | `number` | `31536000` | `/{apiBaseUrl}/:page/:locale/data.json` の HTTP `Cache-Control` max-age（秒）。`dateBuild` が URL をバスティングしている間（`?v=...`、デフォルト）にのみ完全に適用されます。その場合レスポンスは `private, max-age=…, immutable` となり、ブラウザーはそれを固定しますが、クエリを無視する CDN は固定できません（`httpCacheControl: false` の場合は `public`）。- `dateBuild: 0`/`''` — URL が固定されるため、この期間は*尊重されず*、代わりにレスポンスは `public, max-age=0, must-revalidate` になります。変わらない URL に長い `max-age` を設定すると、ブラウザーが最初に見たペイロードが固定されてしまいます。- `0` — `Cache-Control` をまったく設定しません（ローカルでのデバッグに便利）- 開発時（`import.meta.dev`）には適用されないため、HMR がブラウザーキャッシュと競合しません - Nitro を通じて配信されるレスポンスにのみ適用されます。`public/` にコピーされホスティングプラットフォームが配信するペイロードには、そのプラットフォームのヘッダーが適用されます。パフォーマンスガイドを参照してください。`@nuxtjs/i18n` の実験的な `httpCacheDuration`（v10.2.0）に相当しますが、Nitro の `defineCachedEventHandler` の maxAge ではなく、明示的なレスポンスヘッダーとして提供します。 |
| `httpCacheControl` | `string \| false` | `'public, max-age=60'` | ホストまたはパス全体に適用されるルールによって応答されるペイロードファイルの `Cache-Control`。これらは `?v=` を認識できません。Node サーバーでは、現在の `?v=` へのレスポンスは `httpCacheDuration` の間固定され、それ以外は再検証されます。`source`、`cacheTtl`、`apiBaseServerHost` のように、ビルドなしで辞書が変わる場合は、すべてのレスポンスがこのヘッダーを使用します。`false` にすると、すべてのファイルが `max-age=0, must-revalidate` のままになります。 |
| `dateBuild` | `string \| number` | — | 翻訳リクエストのキャッシュバスティングに使用する値（`?v=...`）。指定されていない場合、モジュールは翻訳ファイルのハッシュを使用するため、値は翻訳が変わったときにのみ変化します（ハッシュを計算できない場合は `Date.now()`）。`0` または `''` でキャッシュバスティングを無効にします。自分で固定するには、安定した値（git の SHA、ビルド番号）を設定してください。辞書がその場で置き換えられた後、`NUXT_I18N_DATE_BUILD` または `runtimeConfig.public.i18nRuntime.dateBuild` によってランタイムで置き換えられます。固定された URL は再ビルドなしで置き去りになります。 |
| `experimental` | `Record<string, unknown>` | — | 実験的／不安定なオプションの置き場所。内容はマイナーバージョン間で予告なく変更または削除されることがあります。 |

## オプションの詳細 {#option-details}

表以上に付け加えることのないオプションは、ここでは繰り返しません。

### ロケールと URL {#locales-and-urls}

#### `locales` {#locales}

**型** `Locale[]` · **デフォルト** `[]`

サポートするロケールのリスト。
各エントリーはロケールコードと、任意のメタデータ（ISO、方向、表示名など）を定義します。

各エントリーは `Locale` オブジェクトです:

| プロパティ | 型 | 説明 |
| --- | --- | --- |
| `code` | `string` | **必須。** URL セグメントとファイル名（`en`、`de-at`）。 |
| `iso` | `string` | `<html lang>`、`hreflang`、複数形、`$tn` / `$td` / `$tdr` 用の BCP-47 タグ（`en-US`）。 |
| `displayName` | `string` | `<i18n-switcher>` と `$getLocaleName()` でのラベル。 |
| `dir` | `'ltr' \| 'rtl' \| 'auto'` | `<html dir>`。指定しない場合、既知の RTL 言語には `rtl` が設定され、その他のロケールには属性が付きません。[SEO](/jp/guide/seo#text-direction) を参照してください。 |
| `disabled` | `boolean` | ルート、ペイロード、切り替えから除外されます。そのプレフィックスは 404 になり、そのロケールへのリンクは現在のページにとどまります。 |
| `fallbackLocale` | `string` | このロケールのフォールバック。グローバルな `fallbackLocale` を上書きします。 |
| `seo` | `boolean` | `false` にすると、ロケールを `hreflang` と `og:locale:alternate` から除外します。 |
| `og` | `string` | `og:locale` の値（`ar_AE`）。デフォルト: `iso` を変換したもの。 |
| `baseUrl` | `string` | ロケール独自のドメイン。1 つのビルドでそれを配信し、他のドメインからそこへのリンクは絶対 URL になります。 |
| `baseDefault` | `boolean` | `baseUrl` と併用: そのホストのデフォルトロケールで、そこへのリンクには `/<code>` プレフィックスが付きません（`prefix` では付きます）。 |

その他のプロパティは保持され、`$getLocales()` で返されます。`Locale` を拡張して型を付けます:

```ts
// i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
  }
}
export {}
```

モジュールは `@i18n-micro/types` をホイストするため、pnpm でもパッケージをインストールせずにこれが機能します。

#### `defaultLocale` {#defaultlocale}

**型** `string` · **デフォルト** `'en'`

URL やユーザーの設定からロケールを判断できない場合に使用するロケール。
翻訳のフォールバックではありません。その目的には `fallbackLocale` を設定してください。

#### `strategy` {#strategy}

**型** `Strategies` · **デフォルト** `'prefix_except_default'`

ロケールプレフィックスの URL ルーティング戦略。

- `'no_prefix'` — URL にロケールを含めず、ロケールは Cookie に保存します。
- `'prefix_except_default'` — デフォルト以外のすべてのロケールにプレフィックスを付けます。
- `'prefix'` — デフォルトロケールも含め、常にプレフィックスを付けます。
- `'prefix_and_default'` — `prefix` と同様ですが、デフォルトロケールにはプレフィックスなしでもアクセスできます。

戦略ごとの URL とリダイレクト: [ルーティング戦略](/jp/guide/strategy)。

#### `globalLocaleRoutes` {#globallocaleroutes}

**型** `GlobalLocaleRoutes` · **デフォルト** `{}`

ルートレベルのグローバルなロケール設定。
コンポーネントを変更せずに、特定のページのロケールルートを
制限またはカスタマイズできます。

- `false` — ルートをローカライズの対象から除外します。
- `Record<LocaleCode, string>` — ロケールごとのカスタムパス。

キーはルート名またはパスです。通常は [`$defineI18nRoute`](/jp/guide/per-component-translations) でページごとに設定します。

```ts
globalLocaleRoutes: {
  about: { en: '/about-us', de: '/ueber-uns' },
  'admin-dashboard': false, // not localized
}
```

詳細、動的セグメント、`pages:extend` のルート: [ローカライズされたパス](/jp/guide/custom-locale-routes)。

#### `routeLocales` {#routelocales}

**型** `Record<string, string[]>` · **デフォルト** —

ルートごとのロケール制限。ビルド時に `$defineI18nRoute()` の呼び出しから抽出されます。
ルートのパス（例: `'/about'`）を、許可されたロケールコードの配列にマッピングします。
記載されていないルートには制限がありません（すべてのロケールが許可されます）。

#### `routeDisableMeta` {#routedisablemeta}

**型** `Record<string, boolean \| string[]>` · **デフォルト** —

ルートごとのメタタグの無効化。ルート名またはパスを、`true`（すべてのメタを無効化）または
メタを無効にするロケールコードの配列にマッピングします。ビルド時に `$defineI18nRoute()`
の呼び出しで見つかったエントリーが追加されます。

#### `customRegexMatcher` {#customregexmatcher}

**型** `string \| RegExp` · **デフォルト** `undefined (uses built-in pattern based on locale codes)`

URL セグメント内のロケールコードにマッチさせるためのカスタム正規表現（またはその文字列ソース）。
`locales` のすべてのロケールコードがフラグなしでパターン全体にマッチする必要があり、そうでない場合はビルドが失敗します。

```ts
customRegexMatcher: '[a-z]{2}-[a-z]{2}', // en-us, de-at
```

#### `excludePatterns` {#excludepatterns}

**型** `(string \| RegExp)[]` · **デフォルト** `undefined`

i18n ルーティングから除外するパス。文字列はパスのプレフィックス（`/admin` は `/admin/x` を含む）
または `*` / `?` の glob で、RegExp はパスに対してテストされます。マッチしたページにはロケールの
バリアント、ロケールリダイレクト、404 がなく、プリレンダリングからも除外されますが、翻訳付きで
レンダリングはされます。`/api`、`/_nuxt`、`/__*`、翻訳ルート、および一般的な静的ファイル
（sitemap、robots.txt、favicon、拡張子によるアセット）は常に除外されます。

```ts
excludePatterns: ['/admin', '/docs/*', /^\/preview\//],
```

詳しくは: [パスの除外](/jp/guide/excluding-static-files)。

#### `localizedRouteNamePrefix` {#localizedroutenameprefix}

**型** `string` · **デフォルト** `'localized-'`

ローカライズされたルート名の先頭に付けるプレフィックス（例: `'localized-index'`）。
元のルートと生成されたロケールのバリアントを区別するために内部で使用されます。

#### `trailingSlash` {#trailingslash}

**型** `'append' \| 'remove'` · **デフォルト** `undefined (inherit from Nuxt)`

`$localePath` / `$switchLocalePath` の末尾スラッシュ（NuxtLink と同等）。
未設定の場合は `experimental.defaults.nuxtLink.trailingSlash` がデフォルトになります。
i18n のパスヘルパーについて Nuxt のリンクのデフォルトを上書きするには、明示的に設定してください。

### 翻訳 {#translations}

#### `translationDir` {#translationdir}

**型** `string` · **デフォルト** `'locales'`

翻訳 JSON ファイルを含むディレクトリへのパス（プロジェクトルートからの相対パス）。

`app/` ではなく、各レイヤーのルートからの相対パスです（Nuxt 4 のレイアウトでは `'app/locales'`）。ファイル構成: [翻訳ファイル](/jp/guide/translations)。

#### `additionalTranslationDirs` {#additionaltranslationdirs}

**型** `string[]` · **デフォルト** `[]`

追加のディレクトリ（プロジェクトルート／各 Nuxt レイヤーのルートからの相対パス）。そのトップレベルの
`{locale}.json` ファイルは、`translationDir` の前にグローバル辞書へディープマージされます。

マージ順: 配列内の各エントリーを順に（レイヤーをまたいで）、次に `translationDir`（競合時に優先）。
ルートの `{locale}.json` ファイルのみが読み込まれ、これらのディレクトリ配下の `pages/` は無視されます。

例: `translationDir: 'frontend'`、`additionalTranslationDirs: ['common']` → `common/en.json`、次に `frontend/en.json`。

#### `disablePageLocales` {#disablepagelocales}

**型** `boolean` · **デフォルト** `false`

ページごとの翻訳ファイルを無効にします。
`true` の場合、グローバルな翻訳（`{locale}.json`）のみが読み込まれ、
ページ固有のファイル（`pages/{page}/{locale}.json`）は生成も読み込みもされません。

#### `fallbackLocale` {#fallbacklocale}

**型** `string` · **デフォルト** `undefined (no fallback; returns the raw key)`

グローバルなフォールバックロケールコード。
あるロケールで不足しているキーはこのロケールから取得されます（各ペイロードのビルド時または
読み込み時にマージされます）。設定しない場合、不足しているキーはキーそのものとしてレンダリングされます。

#### `routesLocaleLinks` {#routeslocalelinks}

**型** `{ [key: string]: string }` · **デフォルト** `{}`

ルート名を別のルート名にマッピングして、同じ翻訳ファイルを共有します。
例えば、`{ 'about-us': 'about' }` は、`about-us` ページが独自の翻訳ではなく
`about` ページの翻訳を使用することを意味します。

```ts
routesLocaleLinks: { 'products-id': 'products' },
```

#### `plural` {#plural}

**型** `PluralFunc` · **デフォルト** ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)``

カスタムの複数形関数。
`(key, count, params, locale, getter)` を受け取り、選択された複数形を文字列として返すか、
組み込みの `defaultPlural` ロジックにフォールバックするために `null`/`undefined` を返します
（そのため、一部のロケールだけを上書きできます）。

Nuxt モジュールでは、関数は `.toString()` で `.nuxt/i18n.plural.mjs` に
シリアライズされるため、自己完結している必要があります（import や外側のスコープは不可）。
ファイルパスの文字列はサポート**されていません**。

組み込みのルールとその `=0 ` マーカーについては [`$tc`](/jp/api/methods#$tc) で説明しています。独自の関数は、それが応答する部分について組み込みのルールを置き換え、マーカーを含む生の値を受け取ります。`null` を返すと呼び出しは組み込みのルールに戻されます。関数は `(key, count, params, locale, getter)` を受け取り、`getter(key)` はすべての形を含む生の文字列を返します。自己完結した `function` またはアロー関数式として記述してください（メソッドの省略記法、import、外側の変数は不可）:

```ts
plural: function (key, count, params, locale, getter) {
  if (!locale.startsWith('en')) return null // built-in rule for other locales
  const forms = String(getter(key) ?? '').split('|').map((form) => form.trim())
  const index = count === 0 ? 0 : count === 1 ? 1 : 2
  return (forms[Math.min(index, forms.length - 1)] ?? '').replace('{count}', String(count))
},
```

```json
{ "apples": "no apples | one apple | {count} apples" }
```

#### `numberFormats` {#numberformats}

**型** `Record<string, Record<string, Intl.NumberFormatOptions>>` · **デフォルト** —

ロケールごとの名前付き数値フォーマット（Vue I18n 互換）。
`$tn(1000, 'currency')` 形式の呼び出しを可能にします。

[`$tn`](/jp/api/methods#$tn) で使用されます。

#### `datetimeFormats` {#datetimeformats}

**型** `Record<string, Record<string, Intl.DateTimeFormatOptions>>` · **デフォルト** —

ロケールごとの名前付き日時フォーマット（Vue I18n 互換の `datetimeFormats`）。
`$td(date, 'short')` 形式の呼び出しを可能にします。

[`$td`](/jp/api/methods#$td) で使用されます。

#### `timeZone` {#timezone}

**型** `string` · **デフォルト** `the runtime's zone`

`$td` と `<i18n-t date>` の IANA タイムゾーン（`Europe/Berlin`）。サーバーとすべてのブラウザーで

#### `disableWatcher` {#disablewatcher}

**型** `boolean` · **デフォルト** `false`

#### `missingWarn` {#missingwarn}

**型** `boolean` · **デフォルト** `true`

### ペイロードとキャッシュ {#payloads-and-caching}

#### `translationPayloads` {#translationpayloads}

**型** `TranslationPayloadOptions` · **デフォルト** —

翻訳ペイロードの出力方法を制御します（Node サーバー: `public/<apiBaseUrl>`、Edge / 関数 / インライン: Nitro の `serverAssets`）。

- **Node サーバー**（`node-server`、`node-cluster`、ディスクの `serveStatic`）: `serverAssets` は `public/` 配下を `readFile` で読み込むローカル SSR を意味します（Rollup の `raw:` なし）。
- **Edge、関数プリセット、`serveStatic: "inline"`**（`vercel`、`netlify`、`aws-lambda`、winterjs など）: `public/` はディスク上で SSR から利用できないため、`serverAssets` は Nitro の `serverAssets`（`assets:i18n`）を登録します。
  パブリックへのコピーは強制しません。CDN／静的配信には `publicAssets: true` を設定してください。

一般的なオールインワン構成ではデフォルトのままにしてください。大規模な Edge のカタログでは `mode: 'source'` を推奨します。
CDN を利用するデプロイでは、ローカル出力を無効にし、`apiBaseClientHost` / `apiBaseServerHost` を設定してください。

サブオプションは[ペイロードとキャッシュ](#payloads-and-caching)の表にあります。Node、サーバーレス、Edge、静的ホスティング、CDN にどの組み合わせが適しているか: [デプロイ](/jp/guide/deployment)。

#### `apiBaseUrl` {#apibaseurl}

**型** `string` · **デフォルト** `'_locales'`

翻訳 API ルートのベース URL パスセグメント（SSR/SSG のデータ取得で使用）。
環境変数 `NUXT_I18N_APP_BASE_URL` でも設定できます。

ペイロードの URL は `/{apiBaseUrl}/{page}/{locale}/data.json` です。

#### `apiBaseClientHost` {#apibaseclienthost}

**型** `string` · **デフォルト** `undefined`

クライアントサイドの翻訳取得リクエストに使用するホストを上書きします。
クライアントが Nuxt から見えるホスト名とは異なるホスト名でサーバーにアクセスする場合に便利です。
環境変数 `NUXT_I18N_APP_BASE_CLIENT_HOST` でも設定できます。

#### `apiBaseServerHost` {#apibaseserverhost}

**型** `string` · **デフォルト** `undefined`

サーバーサイドの翻訳取得リクエストに使用するホストを上書きします。
サーバーが内部ホスト名で自身にアクセスするコンテナ／マイクロサービス構成で便利です。
環境変数 `NUXT_I18N_APP_BASE_SERVER_HOST` でも設定できます。

ホストは、組み込みのルートと同じ `/{apiBaseUrl}/{page}/{locale}/data.json` のレスポンスを配信する必要があります。

#### `dateBuild` {#datebuild}

**型** `string \| number` · **デフォルト** —

翻訳リクエストのキャッシュバスティングに使用する値（`?v=...`）。

指定されていない場合、モジュールは翻訳ファイルのハッシュを使用するため、値は翻訳が変わったときに
のみ変化します（ハッシュを計算できない場合は `Date.now()`）。`0` または `''` でキャッシュバスティングを
無効にします。自分で固定するには、安定した値（git の SHA、ビルド番号）を設定してください。
辞書がその場で置き換えられた後、`NUXT_I18N_DATE_BUILD` または `runtimeConfig.public.i18nRuntime.dateBuild` によって
ランタイムで置き換えられます。固定された URL は再ビルドなしで置き去りになります。

#### `httpCacheDuration` {#httpcacheduration}

**型** `number` · **デフォルト** `31536000`

`/{apiBaseUrl}/:page/:locale/data.json` の HTTP `Cache-Control` max-age（秒）。

`dateBuild` が URL をバスティングしている間（`?v=...`、デフォルト）にのみ完全に適用されます。
その場合レスポンスは `private, max-age=…, immutable` となり、ブラウザーはそれを固定しますが、クエリを無視する CDN は固定できません
（`httpCacheControl: false` の場合は `public`）。

- `dateBuild: 0`/`''` — URL が固定されるため、この期間は*尊重されず*、代わりに
  レスポンスは `public, max-age=0, must-revalidate` になります。変わらない URL に長い `max-age` を
  設定すると、ブラウザーが最初に見たペイロードが固定されてしまいます。

- `0` — `Cache-Control` をまったく設定しません（ローカルでのデバッグに便利）
- 開発時（`import.meta.dev`）には適用されないため、HMR がブラウザーキャッシュと競合しません
- Nitro を通じて配信されるレスポンスにのみ適用されます。`public/` にコピーされホスティングプラットフォームが
  配信するペイロードには、そのプラットフォームのヘッダーが適用されます。パフォーマンスガイドを参照してください。

`@nuxtjs/i18n` の実験的な `httpCacheDuration`（v10.2.0）に相当しますが、Nitro の
`defineCachedEventHandler` の maxAge ではなく、明示的なレスポンスヘッダーとして提供します。

#### `cacheMaxSize` {#cachemaxsize}

**型** `number` · **デフォルト** `0`

メモリー内の翻訳キャッシュの最大エントリー数。fetch キャッシュとサーバーキャッシュは
最も長く使われていないエントリーを破棄し、ブラウザーの辞書マップは最も古いもの（FIFO）を破棄します。
`0` はブラウザーでは無制限を意味し、その場合サーバーキャッシュは最大 1000 エントリーを保持するため、
でっち上げのページ名を含むリクエスト URL によってサーバーメモリーが増大することはありません。

#### `cacheTtl` {#cachettl}

**型** `number` · **デフォルト** `0`

fetch とサーバーの翻訳キャッシュの有効期間（秒）。エントリーが保存された時点から数えられ
（読み取りでは延長されません）、`apiBaseServerHost` からのデータは少なくともその頻度で更新されます。
ブラウザーのアクティブな辞書はこれによって期限切れになりません。`0` はエントリーが
期限切れにならないことを意味します。

これら両方がランタイムで何を変えるか: [パフォーマンス](/jp/guide/performance)。

#### `serverTranslationPreload` {#servertranslationpreload}

**型** `boolean` · **デフォルト** `false`

Nitro のグローバルミドルウェアで index ページの翻訳をプリロードします（サーバー専用、プライベート設定）。

### SEO {#seo}

#### `meta` {#meta}

**型** `boolean` · **デフォルト** `true`

SEO メタタグ（`hreflang`、`canonical`、`og:url`、`og:locale`）を自動的に生成します。

ページごとの上書き: [`useI18nHead`](/jp/composables/useI18nHead)。その他すべて: [SEO](/jp/guide/seo)。

#### `metaBaseUrl` {#metabaseurl}

**型** `string` · **デフォルト** `undefined`

SEO メタタグ（canonical、og:url、hreflang）のベース URL。

- 具体的な URL 文字列（例: `'https://example.com'`）— そのまま使用されます（最優先）。
- `undefined` — `nuxt-site-config` モジュールが存在する場合はその `site.url` に、
  存在しない場合は現在のリクエストのオリジン
  （サーバーでは `useRequestURL().origin`、クライアントでは `window.location.origin`）にフォールバックします。

#### `metaTrustForwardedHost` {#metatrustforwardedhost}

**型** `boolean` · **デフォルト** `true`

メタタグのベース URL を解決する際に `X-Forwarded-Host` ヘッダーを信頼します。
このヘッダーに実際のクライアント向けホスト名を設定するリバースプロキシ（nginx、Cloudflare、AWS ALB など）の
背後でアプリが動作している場合に有効にします。

`metaBaseUrl` も `site.url` も設定されていない場合にのみ読み取られます。ヘッダーを上書きするプロキシなしでアプリにアクセスできる場合は `false` に設定してください。そうしないと、クライアントが canonical URL のホストを選べてしまいます。

#### `metaTrustForwardedProto` {#metatrustforwardedproto}

**型** `boolean` · **デフォルト** `true`

メタタグのプロトコルを解決する際に `X-Forwarded-Proto` ヘッダーを信頼します。
TLS を終端するプロキシの背後でアプリが動作している場合に有効にすると、
アプリ自体が HTTP で待ち受けていても canonical URL に `https://` が使われます。

適用範囲は `metaTrustForwardedHost` と同じです。

#### `trustForwardedHost` {#trustforwardedhost}

**型** `boolean` · **デフォルト** `false`

リクエストのドメイン（`locales[].baseUrl`）を `Host` ではなく `X-Forwarded-Host` から
選択します。そのヘッダーを上書きするプロキシの背後でのみ有効にしてください。

`metaTrustForwardedHost` とは別で、デフォルトでは無効です。ここではヘッダーがタグのオリジンだけでなく、別のドメインのロケールを選択してしまうためです。[レイヤーとドメイン](/jp/guide/layers#multiple-domains)を参照してください。

#### `hreflangBaseLanguage` {#hreflangbaselanguage}

**型** `boolean` · **デフォルト** `false`

各ロケールの `iso` から導出した言語のみの `hreflang` も出力します
（例: `es-ES` → `es` も）。`locales` 内で最初の地域付きロケールが、
その言語の言語のみのタグを取得します。ルーティングの `code` は使用されず、`iso || code` のみが使われます。

#### `canonicalQueryWhitelist` {#canonicalquerywhitelist}

**型** `string[]` · **デフォルト** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

canonical と `og:url` メタタグで保持されるクエリパラメーター名のリスト。
このリストにないパラメーターは canonical URL から取り除かれます。

### 検出とリダイレクト {#detection-and-redirects}

これらのオプションが反映されるルール: [ロケール検出](/jp/guide/locale-detection)。

#### `redirects` {#redirects}

**型** `boolean` · **デフォルト** `true`

ロケールの自動リダイレクト（サーバープラグインとクライアントのルートミドルウェア）を有効にします。
`true` の場合、プレフィックス戦略ではプレフィックスのない URL をローカライズされた形式にリダイレクトします。ロケールは
アプリの状態、Cookie、または `autoDetectPath` が許可する場所では `Accept-Language` から決定され、それ以外の場合は
デフォルトになります。`no_prefix` では、検出によって URL が変わることはありません（カスタムパスについては `noPrefixRedirect` を参照）。

`false` の場合、クライアントのリダイレクトミドルウェアは登録されません。サーバープラグインは、無効なロケールの URL に対して引き続き 404 を返し、プレフィックス付きの URL に対して Cookie を書き込みます。

#### `autoDetectLanguage` {#autodetectlanguage}

**型** `boolean` · **デフォルト** `true`

`Accept-Language` HTTP ヘッダーからユーザーの優先言語を自動的に検出します。
`autoDetectPath` と組み合わせて、検出を行うタイミングを決定します。

#### `autoDetectPath` {#autodetectpath}

**型** `string` · **デフォルト** `'/'`

Cookie / Accept-Language の設定に基づくリダイレクトを実行できる場所（`redirects` が有効な場合）。

- `'/'` — `/` のみ（デフォルトロケールのディープリンクには引き続きアクセスできます。デフォルト）
- `'no_prefix'` — ロケールプレフィックスのないパスのみ
- `'*'` — 明示的なロケールプレフィックスの書き換えを含む、すべてのパス
  （例: Cookie が `de` を優先する場合 `/fr/about` → `/de/about`）

- その他の文字列 — そのパス。末尾のスラッシュは無視されます（例: `'/welcome'`）

`prefix` では、許可されたパス以外のプレフィックスのない URL も、デフォルトロケールの
形式にリダイレクトされます（`/about` → `/en/about`）。`prefix_except_default` で
プレフィックス付きのデフォルトロケール（`/en`）は、リダイレクトではなく 404 になります。

#### `localeCookie` {#localecookie}

**型** `string \| null` · **デフォルト** `null`

セッションをまたいでユーザーのロケール設定を保持するための Cookie 名。
`null` に設定すると Cookie による保持を無効にします。
`no_prefix` 戦略では、指定されていない場合は自動的に `'user-locale'` に設定されます。`i18n` 設定ブロックで
明示的に `null` を指定すると、その場合も無効のままになります。

Cookie がなくても `Accept-Language` は引き続きリダイレクトを決定します。Cookie は訪問をまたいで選択を記憶します。

#### `noPrefixRedirect` {#noprefixredirect}

**型** `boolean` · **デフォルト** `false`

`no_prefix` 戦略の場合: デフォルトロケールがページのカスタムパスを持つとき
（`localeRoutes` / `globalLocaleRoutes`）、ページの元のパスを訪問者のロケールの
カスタムパス、それがなければデフォルトロケールのカスタムパスにリダイレクトします（例: `/about` → `/about-us`）。
独自のカスタムパスを持たないロケールは元のパスのままです。動的セグメントを持つ
ページはリダイレクトされません。

### 登録と開発 {#registration-and-development}

#### `plugin` {#plugin}

**型** `boolean` · **デフォルト** `true`

`$t()`、`$tc()`、`$getLocale()`、`$switchLocale()` などのランタイムヘルパーを
提供するコア i18n プラグインを登録します。

#### `define` {#define}

**型** `boolean` · **デフォルト** `true`

ランタイムで `$defineI18nRoute()` を提供します。いずれにしても、ビルドはページ内の
`$defineI18nRoute()` の呼び出しを読み取ります。

#### `hooks` {#hooks}

**型** `boolean` · **デフォルト** `true`

読み込み時とナビゲーション時に `i18n:register` アプリフックを呼び出し、プラグインが翻訳を追加できるようにします。

[フック](/jp/api/events)を参照してください。

#### `components` {#components}

**型** `boolean` · **デフォルト** `true`

組み込みの i18n コンポーネント（`<i18n-link>`、`<i18n-switcher>`、`<i18n-t>`、`<i18n-group>`）を登録します。
`false` に設定すると、コンポーネントの自動登録を無効にします（例えば、それらを使わず
モジュールのフットプリントを減らしたい場合）。

#### `types` {#types}

**型** `boolean` · **デフォルト** `true`

デフォルトロケールファイルの翻訳キーに基づいて、`useI18n`、`$t`、および関連するヘルパーの
TypeScript 型宣言を生成します。

[`@i18n-micro/types-generator`](/jp/integrations/types-generator) パッケージとは別です。

#### `hmr` {#hmr}

**型** `boolean` · **デフォルト** `true`

開発時に翻訳ファイルの Hot Module Replacement を有効にします。
`true` の場合、JSON 翻訳ファイルの変更により、ページ全体を更新せずに
自動的に再読み込みされます。

#### `debug` {#debug}

**型** `boolean` · **デフォルト** `false`

ロケール検出、ルート生成、翻訳の読み込みについて詳細なデバッグログを有効にします。

#### `vueDevtools` {#vuedevtools}

**型** `boolean` · **デフォルト** `true`

開発時に Vue DevTools のインスペクターとタイムラインを登録します（ブラウザー拡張機能）。
Nuxt DevTools のカスタムタブとは別です。

#### `experimental` {#experimental}

**型** `Record<string, unknown>` · **デフォルト** —

実験的／不安定なオプションの置き場所。
内容はマイナーバージョン間で予告なく変更または削除されることがあります。
