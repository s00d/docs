# モジュールオプションリファレンス

`nuxt-i18n-micro` が受け付けるすべてのオプションは、[`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts) の `ModuleOptions` インターフェースからビルド時に読み取られます。ここに手書きの情報はないため、コードと乖離することはありません — 型・デフォルト・説明はすべて宣言そのものに由来します。

これらのオプションが *組み合わされたときにどういう意味を持つか* — どの組み合わせが妥当か、戦略を切り替えると何が変わるか、動作するサンプルなどは、[設定](/guides/configuration) を参照してください。このページは網羅的なリスト、あちらのページは解説です。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

ネストされたオプションはドット区切りのパスで表記されるため、`translationPayloads.mode` は `translationPayloads` オブジェクト内の `mode` キーを指します。

## ロケールとルーティング

どの言語が存在し、URL 内でどのように表現されるか。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | サポートするロケールのリスト。各エントリはロケールコードとオプションのメタデータ（ISO、方向、表示名など）を定義します。 |
| `strategy` | `Strategies` | `'prefix_except_default'` | ロケールプレフィックス用の URL ルーティング戦略。- `'no_prefix'` — URL にロケールを含めない。ロケールは Cookie に保存されます。- `'prefix_except_default'` — デフォルト以外のすべてのロケールにプレフィックスを付けます。- `'prefix'` — デフォルトを含め常にプレフィックスを付けます。- `'prefix_and_default'` — `prefix` と同様ですが、デフォルトロケールにはプレフィックスなしでもアクセスできます。 |
| `defaultLocale` | `string` | `'en'` | URL やユーザー設定からロケールが決定できないときに使用するロケール。`fallbackLocale` が未設定の場合、翻訳欠落時のフォールバックロケールとしても使用されます。 |
| `localeCookie` | `string \| null` | `null` | セッションを跨いでユーザーのロケール設定を永続化する Cookie 名。`null` に設定すると Cookie ベースの永続化を無効化します。指定がない場合、`no_prefix` 戦略では自動的に `'user-locale'` が設定されます。 |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | ルート単位のグローバルなロケール設定。コンポーネントを変更することなく、特定ページのロケールルートを制限したりカスタマイズしたりできます。- `false` — そのルートをローカライズ対象から除外。- `Record<LocaleCode, string>` — ロケールごとのカスタムパス。 |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | URL セグメント内のロケールコードにマッチする正規表現（またはその文字列ソース）。`locales` で定義されたすべてのロケールコードがこのパターンにマッチする必要があり、そうでない場合は警告が発生します。 |
| `noPrefixRedirect` | `boolean` | `false` | `no_prefix` 戦略向け: ロケールプレフィックス付き URL（例: `/en/about`）からプレフィックスなし版（`/about`）へのリダイレクトを有効化します。 |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | i18n の処理から完全に除外する URL パターン（文字列または RegExp）。マッチするルートには、ロケールプレフィックス、リダイレクト、翻訳読み込みが適用されません。Nuxt 内部パス（`/__nuxt_error` など）は常に自動的に除外されます。 |
| `routeLocales` | `Record<string, string[]>` | — | `defineI18nRoute()` 呼び出しから抽出された、ルートごとのロケール制限。ルートパス（例: `'/about'`）を許可されるロケールコードの配列にマップします。リストにないルートには制限はありません（すべてのロケールが許可されます）。 |

## 翻訳

翻訳ファイルの配置場所とキー解決の挙動。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | 翻訳 JSON ファイルを含むディレクトリへのパス（プロジェクトルート相対）。 |
| `disableWatcher` | `boolean` | `false` | 開発モードで欠落する翻訳ファイルを自動作成するファイルウォッチャーを無効化します。 |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | 同じ翻訳ファイルを共有するために、あるルート名を別のルート名にマップします。たとえば `\{ 'about-us': 'about' \}` は、`about-us` ページが自身のではなく `about` ページの翻訳を利用することを意味します。 |
| `plural` | `PluralFunc` | `built-in pluralization (form index by count)` | カスタム複数形処理関数。`(key, count, params, locale, getter)` を受け取り、選択された複数形の文字列を返します。`null` / `undefined` を返すと組み込みの `defaultPlural` にフォールバックします（つまり一部ロケールだけを上書きできます）。Nuxt モジュールでは、この関数は `.toString()` で `.nuxt/i18n.plural.mjs` にシリアライズされるため、自己完結（import や外部スコープを参照しない）である必要があります。ファイルパスの文字列は **サポートされません**。 |
| `disablePageLocales` | `boolean` | `false` | ページごとの翻訳ファイルを無効化します。`true` の場合、グローバル翻訳（`\{locale\}.json`）のみが読み込まれ、ページ固有ファイル（`pages/\{page\}/\{locale\}.json`）は生成・読み込みされません。 |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | グローバルフォールバックロケールコード。アクティブなロケールに翻訳キーが存在しない場合、キー自体を返す前にこのロケールを参照します。 |

## ペイロードとキャッシュ

翻訳がブラウザに届く仕組み。ランタイムで何が変わるかは [パフォーマンス](/guides/performance) を参照してください。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Nitro グローバルミドルウェアで index ページの翻訳をプリロードします（サーバー専用、プライベート設定）。 |
| `apiBaseUrl` | `string` | `'_locales'` | 翻訳 API ルートで使用されるベース URL のパスセグメント（SSR/SSG のデータ取得に使用）。`NUXT_I18N_APP_BASE_URL` 環境変数からも設定できます。 |
| `apiBaseClientHost` | `string` | `undefined` | クライアント側の翻訳フェッチリクエストで使用するホストを上書きします。Nuxt が見るホスト名と異なるホスト名でクライアントがサーバーに到達する場合に有用です。`NUXT_I18N_APP_BASE_CLIENT_HOST` 環境変数からも設定できます。 |
| `apiBaseServerHost` | `string` | `undefined` | サーバー側の翻訳フェッチリクエストで使用するホストを上書きします。コンテナ/マイクロサービス構成で、サーバーが内部ホスト名を通じて自身に到達する場合に有用です。`NUXT_I18N_APP_BASE_SERVER_HOST` 環境変数からも設定できます。 |
| `translationPayloads` | `TranslationPayloadOptions` | — | 翻訳ペイロードの出力方法を制御します（Node: `public/<apiBaseUrl>`; Edge: Nitro `serverAssets`）。- **Node**: `serverAssets` は `public/` 配下の `readFile` によるローカル SSR を意味します（Rollup の `raw:` は使いません）。- **Edge**: `serverAssets` は Nitro の `serverAssets`（`assets:i18n`）を登録します。public コピーを強制するわけではありません。通常のオールインワン構成ではデフォルトのままで問題ありません。大規模な Edge カタログでは `mode: 'source'` を推奨します。CDN 配下のデプロイでは、ローカル出力を無効化し `apiBaseClientHost` / `apiBaseServerHost` を設定してください。 |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | 翻訳ペイロード戦略。- `premerged`: ビルド時の `\{page\}/\{locale\}/data.json` マトリクス（デフォルト）- `source`: ランタイムでマージされるコンパクトなソースファイル（Edge / 大規模カタログに推奨） |
| `translationPayloads.serverAssets` | `boolean` | `true` | ローカル SSR ペイロード: Node は `public/<apiBaseUrl>` を読み取ります（public コピーを強制）。Edge は Nitro `serverAssets` を通じて埋め込みます。- **Node**: Nitro `serverAssets` は使用しません（Rollup の `raw:` を回避）。SSR は `public/<apiBaseUrl\|publicDir>` を `\{page\}/\{locale\}/data.json` として読みます。この値が `true` の場合、`publicAssets` が false でも public コピーを強制します。- **Edge**（`nitro.node === false`）: `mode` と同じレイアウトで Nitro `serverAssets`（`assets:i18n`）を利用します。public コピーの強制は **行いません** — CDN 配信には `publicAssets: true` を設定してください。 |
| `translationPayloads.serverHandler` | `boolean` | `true` | 組み込みのサーバールート `/\{apiBaseUrl\}/:page/:locale/data.json` を登録します。翻訳ペイロードを外部ホスト / CDN から配信する場合は無効化します。 |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | ペイロードを Nitro の public 出力にコピーします。Premerged では `apiBaseUrl` 配下に `\{page\}/\{locale\}/data.json`、source ではコンパクトなツリーが出力されます。Node では、`serverAssets` が public コピーを強制する場合、このツリーが SSR ソースにもなります。 |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Nitro の prerender で `/\{apiBaseUrl\}/.../data.json` を出力するオプトイン。premerged の `publicAssets` が既にファイルを書き出している場合は通常冗長です。 |
| `translationPayloads.publicDir` | `string` | — | Nitro の public ルート相対の公開出力フォルダ。デフォルトは `apiBaseUrl`（`_locales`）。これにより静的ファイルがクライアントのフェッチ URL（`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`）と一致します。 |
| `translationPayloads.warnFileCount` | `number` | `500` | 生成されたペイロードファイル数がこの閾値を超えた場合、ビルド中に警告を発します。 |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | 生成されたペイロードの合計サイズ（バイト）がこの閾値を超えた場合、ビルド中に警告を発します。 |

## SEO

ローカライズされたページごとに生成されるメタタグ。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | SEO メタタグ（`hreflang`、`canonical`、`og:url`、`og:locale`）を自動生成します。 |
| `metaBaseUrl` | `string` | `undefined` | SEO メタタグ（canonical、og:url、hreflang）のベース URL。- 具体的な URL 文字列（例: `'https://example.com'`） — そのまま利用されます（最優先）。- `undefined` — `nuxt-site-config` モジュールが存在する場合はその `site.url` に、そうでない場合は現在のリクエスト origin（サーバーでは `useRequestURL().origin`、クライアントでは `window.location.origin`）にフォールバックします。 |
| `metaTrustForwardedHost` | `boolean` | `true` | メタタグのベース URL 解決時に `X-Forwarded-Host` ヘッダを信頼します。実クライアントに面するホスト名をこのヘッダにセットするリバースプロキシ（nginx、Cloudflare、AWS ALB など）配下でアプリを動かす場合に有効にします。 |
| `metaTrustForwardedProto` | `boolean` | `true` | メタタグのプロトコル解決時に `X-Forwarded-Proto` ヘッダを信頼します。アプリ自身は HTTP でリッスンしていても、TLS 終端プロキシ配下で canonical URL に `https://` を使いたい場合に有効にします。 |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | canonical と `og:url` メタタグで保持されるクエリパラメータ名のリスト。このリストにないパラメータは canonical URL から取り除かれます。 |

## 検出とリダイレクト

まだロケールを選択していない訪問者のロケールを選ぶ。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | ロケールに基づく自動リダイレクトを有効化します。`true` の場合、初回訪問時に Cookie、`Accept-Language` ヘッダ、またはデフォルトから検出された優先ロケールへリダイレクトされます。 |
| `autoDetectLanguage` | `boolean` | `true` | `Accept-Language` HTTP ヘッダから優先言語を自動検出します。検出タイミングを決めるため `autoDetectPath` と併用されます。 |
| `autoDetectPath` | `string` | `'/'` | Cookie / Accept-Language に基づくリダイレクトを実行しうるパス（`redirects` が有効な場合）。- `'/'` — `/` のみ（デフォルトロケールのディープリンクは到達可能なまま維持。デフォルト）- `'no_prefix'` — ロケールプレフィックスのないパスのみ - `'*'` — 明示的なロケールプレフィックスの書き換えを含む、あらゆるパス（例: Cookie が `de` を優先する場合 `/fr/about` → `/de/about`）- その他の文字列 — 完全一致のパス（例: `'/welcome'`）プレフィックス戦略のクリーンアップ（`prefix_except_default` 配下での `/en` → `/` など）はゲート対象になりません。 |
