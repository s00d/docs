`useI18n()` を呼び出すコンポーネントは、ユニットテストで i18n インスタンスを必要とします。`@i18n-micro/test-utils` は、実際の翻訳、複数形、フォーマットのロジックを備えたフェイクの `useI18n()` を提供するため、Nuxt サーバーなしで独自の辞書を使ってコンポーネントをマウントできます。ルーティングとリダイレクトについては、`@nuxt/test-utils` で実際のモジュールを E2E で実行してください。

このページはアプリケーションのテストについて説明します。このリポジトリでモジュール自体をどのようにテストしているかは、[モジュールのテスト](https://s00d.github.io/nuxt-i18n-micro/contributing/testing)を参照してください。

## インストール {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

```bash npm
npm install -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

</CodeGroup>

## useI18n をモックする {#mock-usei18n}

```ts
// tests/unit-setup.ts
import { setupNuxtI18nMock } from '@i18n-micro/test-utils'
import { mockNuxtImport } from '@nuxt/test-utils/runtime'
import { beforeEach, vi } from 'vitest'

export const { i18n, useI18n, setTranslationsFromJson } = setupNuxtI18nMock({
  spy: vi.fn, // every method becomes a vi.fn, so you can assert calls
  beforeEach, // reset state and reseed `translations` before each test
  translations: { welcome: 'Welcome' },
})

mockNuxtImport('useI18n', () => useI18n)
```

```ts
// vitest.config.ts
import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    environment: 'nuxt',
    setupFiles: ['./tests/unit-setup.ts'],
  },
})
```

`mockNuxtImport` はセットアップファイルに置いてください。`@nuxt/test-utils` がそれを変換する必要があるためです。`setupNuxtI18nMock` はプライベートな翻訳キャッシュを使用するため、並行して実行されるテストファイル間で状態は共有されません。

## テストを書く {#write-a-test}

```vue
<!-- components/Greeting.vue -->
<script setup lang="ts">
const { $t } = useI18n()
</script>

<template>
  <p>{{ $t('welcome') }}</p>
</template>
```

```ts
// tests/greeting.spec.ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { expect, it } from 'vitest'
import Greeting from '~/components/Greeting.vue'
import de from '~/locales/de.json'
import { i18n, setTranslationsFromJson } from './unit-setup'

it('renders the German greeting', async () => {
  await setTranslationsFromJson('de', de)
  i18n.setLocale('de')

  const wrapper = await mountSuspended(Greeting)
  expect(wrapper.text()).toBe('Willkommen') // de.json: { "welcome": "Willkommen" }
})
```

フェイクは実際の `useI18n()` と同じメソッド（`$t`、`$tc`、`$tn`、`$td`、`$has`、`$localePath` など、`$` 付きと `$` なしの両方）に加え、テスト用のセッターを公開します: `setLocale`、`setLocales`、`setDefaultLocale`、`setRouteName`、`setTranslationsFromJson`、`loadPageTranslations`、`mergeTranslations`、`setMissingHandler`。

`$localePath` と `$switchLocalePath` は、`strategy` オプションに従ってパスにプレフィックスを付けるスタブです（実際のルーターはありません）。実際のリンクとリダイレクトは E2E でテストしてください。

## 低レベルのヘルパー {#lower-level-helpers}

| ヘルパー | 用途 |
| --- | --- |
| `createIsolatedFakeI18n(options)` | Nuxt の `useI18n` への接続を持たない分離されたフェイク。例えば、`global.mocks` を使った素の `@vue/test-utils` の `mount` 向け。 |
| `createFakeI18n(options)` | 共有モジュールキャッシュ上のフェイク（`beforeEach` で `resetI18n()` を呼び出します）。`isolated: true` で分離することもできます。 |
| `createI18nTestContext(options)` | 両者の背後にあるコンテキスト。複数のフェイクが必要な場合に使用します。 |
| `t`, `tc`, `ts`, `tn`, `td`, `tdr`, `has` | 共有コンテキストへの直接呼び出し。素の関数のテスト向け。 |

モックは `BaseI18n` です。`t`、`tc`、`tn`、`td`、`tdr`、`has` は本物であり、実際の辞書上で動作するため、テストではアプリが表示する内容をそのまま確認できます。

上記のファクトリーヘルパーは、`locale`、`defaultLocale`、`locales`、`routeName`、`strategy`、`translations`、`messages`（ロケールごとの辞書）を受け付けます。完全なサンプルプロジェクトは [`packages/test-utils/example`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/test-utils/example) にあります。

## E2E テスト {#end-to-end-tests}

ルーティング、リダイレクト、SEO タグ、ペイロードの読み込みには実際のモジュールが必要です。`@nuxt/test-utils/e2e` でアプリを起動します:

```ts
// tests/e2e/locales.test.ts
import { $fetch, fetch, setup } from '@nuxt/test-utils/e2e'
import { describe, expect, it } from 'vitest'

describe('locales', async () => {
  await setup({ server: true })

  it('serves the German page', async () => {
    expect(await $fetch('/de')).toContain('lang="de-DE"')
  })

  it('redirects / for a German browser', async () => {
    const res = await fetch('/', { headers: { 'accept-language': 'de' }, redirect: 'manual' })
    expect(res.headers.get('location')).toBe('/de')
  })
})
```

2 つ目のテストは `prefix`（または別のデフォルトロケールを使った `prefix_except_default`）を前提としています。`/` がリダイレクトされる条件については、[ロケール検出](/jp/guide/locale-detection)を参照してください。
