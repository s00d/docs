title: "SEO"
description: "モジュールが追加する lang、hreflang、canonical、og:locale タグ、そのベース URL の決まり方、そしてページ単位での上書き方法。"
---

`meta: true`(デフォルト)の場合、ローカライズされたすべてのページに `<html lang dir>`、canonical リンク、`hreflang` 代替リンク、`x-default`、Open Graph のロケールタグが付与されます。公開オリジンを設定したい場合、タグに含めるロケールを調整したい場合、あるいは 1 ページだけ上書きしたい場合にこのページが必要になります。ほとんどのサイトでは `site.url` または `metaBaseUrl` と、正しい `iso` コードがあれば十分です。

## 最小構成 {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

すると `/de/about` は次のようにレンダリングされます:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## テキストの方向 {#text-direction}

`<html dir>` はロケールの `dir` から決まります。未設定の場合、右から左に書く言語には `iso`(または `code`)から判断して `rtl` が付きます: アラビア語、ヘブライ語、ペルシア語、ウルドゥー語などのいくつかの言語と、`az-Arab` のような RTL 文字を含むタグです。その他のロケールには `dir` 属性が付かず、ブラウザーは `ltr` として扱います。

<Warning>

**大きなページでは `dir: 'auto'` が解析時間を増やします** — `<html>` に `auto` を指定すると、ブラウザーは解析中にコンテンツから方向を判断します。Chromium ではそのコストがページの大きさ以上の速さで増加し、5,000 要素で約 100 ms、20,000 要素で 1 秒かかります。言語がわからない小さなページにのみ使用してください。

</Warning>

## 出力されるタグ {#which-tags-you-get}

- **hreflang**: ページを提供するロケールごとに 1 つのタグ。値は `iso`(`iso` がない場合は `code`)で、URL には canonical と同じクエリが付きます。[ページ設定](/jp/guide/per-component-translations)や `routeLocales` で制限されたページは、そのロケールのみを列挙します。[`hreflangBaseLanguage: true`](/jp/api/module-options#hreflangbaselanguage) を指定すると、最初の地域ロケールに対して言語のみのタグ(`es-ES` → `es`)も追加されます。
- **x-default**: デフォルトロケールの URL。デフォルトロケールがそのページを提供する場合のみ出力されます。
- **og:locale**: `iso` から導出されます(`en-US` → `en_US`)。対応関係が直接的でない場合は、ロケールに `og` を設定してください。例: `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`。どちらもない場合、`og:locale` は書き出されず、開発モードで警告が出ます。
- **canonical / og:url**: クエリパラメーターを除いた現在の URL。ただし [`canonicalQueryWhitelist`](/jp/api/module-options#canonicalquerywhitelist) にあるもの(デフォルトは `page`、`sort`、`filter`、`search`、`q`、`query`、`tag`)は残ります。

戦略ごと:

| 戦略 | hreflang と x-default | canonical、og:url、og:locale、html 属性 |
| --- | --- | --- |
| `prefix`、`prefix_except_default`、`prefix_and_default` | あり | あり |
| `no_prefix` | なし(1 つの URL がすべてのロケールを提供) | あり |

## 公開オリジンの設定 {#set-the-public-origin}

絶対 URL には、次のうち最初に見つかったものが使われます:

1. [`metaBaseUrl`](/jp/api/module-options#metabaseurl)
2. `nuxt-site-config` の `site.url`(`@nuxtjs/seo` によってインストールされます)
3. `app.baseURL` を付加したリクエストのオリジン

最初の 2 つのいずれかを固定してください。

<Warning>

[`metaTrustForwardedHost`](/jp/api/module-options#metatrustforwardedhost) と `metaTrustForwardedProto` のデフォルトが `true` であるため、リクエストオリジンへのフォールバックは `X-Forwarded-Host` と `X-Forwarded-Proto` を読み取ります。これはそれらのヘッダーを上書きするプロキシの背後にある場合にのみ安全です。そうでない場合、クライアントが canonical リンクのホストを選べてしまい、キャッシュがそのページを他の人に配信する可能性があります。

アプリに直接アクセスできる場合は `metaBaseUrl` を固定してください。両方のオプションを `false` にするのとは異なり、偽装された `Host` も無視されます。[プロキシまたは CDN の背後](/jp/guide/deployment#behind-a-proxy-or-cdn)を参照してください。

</Warning>

このフォールバックは、1 つのデプロイで複数のドメインに応答する場合に便利です: `https://site-a.com/en/about` と `https://site-b.com/en/about` はそれぞれ独自のオリジンを持ちます。

ロケールに `baseUrl` がある場合、既知のホストは `metaBaseUrl` や `site.url` より優先して自身の `baseUrl` を使います。そのため canonical と `og:url` はそのドメインにとどまり、`hreflang` は各ロケールをそのドメインに向けます。その他のホストは `metaBaseUrl`、なければデフォルトロケールの `baseUrl`、なければ `site.url` を使うため、偽装された `Host` がタグに影響することはありません。いずれも設定されていない場合はリクエストオリジンへのフォールバックが残り、ビルド時に警告が出ます。[レイヤーとドメイン](/jp/guide/layers#multiple-domains)を参照してください。

## ロケールやページを除外する {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

デフォルトロケールが `seo: false` の場合、`x-default` は書き出されません。1 ページだけタグをオフにするには、[ページ設定](/jp/guide/per-component-translations#turn-off-seo-tags)の `disableMeta`、または設定ファイルの [`routeDisableMeta`](/jp/api/module-options#routedisablemeta) を使用してください。

## 1 ページでタグを上書きする {#override-tags-on-one-page}

一部の翻訳しか存在しない CMS コンテンツや、URL が API から来る場合は、[`useI18nHead`](/jp/composables/useI18nHead) で生成されたタグを置き換えます:

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` では `canonical`、`xDefault`、`ogLocale`、`ogUrl` の設定や削除もできます。`disable` はグループ全体(`'hreflang'`、`'x-default'`、`'canonical'`、`'og'`、`'og-alternates'`、`'html'`)を削除します。ロケール切り替え後に値が再計算されるよう、ゲッターを渡してください。ロケールごとのスラッグについては、先に `$setI18nRouteParams` を設定すれば([ローカライズされたパス](/jp/guide/custom-locale-routes#per-locale-slugs))、生成される代替リンクがすでにそれを使用します。

## 末尾のスラッシュ {#trailing-slash}

`$localePath`、`$switchLocalePath`、`$switchLocaleRoute` のルートオブジェクト、`<i18n-link>`、`<i18n-switcher>`、ロケールのリダイレクト、そして SEO の URL は、1 つのスラッシュ規則に従います: デフォルトでは `experimental.defaults.nuxtLink.trailingSlash`、i18n のパスを別にしたい場合は i18n 設定の [`trailingSlash`](/jp/api/module-options) です。

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/)(サイトマップ、robots、schema.org)は `nuxt-site-config` 4 以降を通じてこのモジュールと連携します。サイト設定がロケールを読み取れるよう `nuxt-i18n-micro` を先に記載し、`site.url` を一度設定してください。これは上記のタグにも使われます。

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

翻訳されたサイト名と説明は、ロケールファイルの `nuxtSiteConfig.name` / `nuxtSiteConfig.description` キーから取得されます。`Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` というエラーは、`@nuxtjs/seo` がバージョン 3 より古いことを意味します。アップグレードしてください([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133))。
