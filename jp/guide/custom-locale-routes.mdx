---
title: "ローカライズされたパス"
description: "localeRoutes または globalLocaleRoutes を使って、動的パラメーターやロケールごとのスラッグを含め、ロケールごとに異なる URL をページに与えます。"
---

デフォルトでは、すべてのロケールが同じパスでページを提供します: `/en/about`、`/de/about`。ローカライズされたパスを使うと、ページファイルはそのままに、各ロケールが `/de/ueber-uns` のように独自の言葉を使えます。ページ内で `$defineI18nRoute` を使って設定するか、多数のページをまとめて `nuxt.config.ts` で設定します。

## ページ内で {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

`prefix_except_default` と `defaultLocale: 'en'` の場合、このページは `/about`、`/de/ueber-uns`、`/fr/a-propos` で応答します。エントリーのないロケールはデフォルトのパスを使います。パスはロケールコードなしで記述してください。プレフィックスは[戦略](/jp/guide/strategy)によって付加され、ロケールコードで始まるパスは警告を出力します。この呼び出しが受け付けるその他の項目は[ページ設定](/jp/guide/per-component-translations)にあります。

## nuxt.config で {#in-nuxt-config}

[`globalLocaleRoutes`](/jp/api/module-options#globallocaleroutes) は任意のページに対して同じことを行い、ページのパス(先頭のスラッシュなしで書いた場合はルート名)をキーとします:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

ページが `localeRoutes` を設定し、`globalLocaleRoutes` に同じキーがある場合は、設定ファイルのエントリーが優先されます。

## 動的パラメーター {#dynamic-params}

パラメーターは Nuxt のどの形式でも記述できます: `[id]`、`[[page]]`、`[...slug]`、`:id()`。パラメーター名はページファイルと一致している必要があります。

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

ネストされたページには、絶対子パス(`/ueber-uns/team`)か、親のローカライズされたパスからの相対パス(`team`)を指定します。

## ローカライズされたページへのリンク {#linking-to-localized-pages}

ルート名を渡してもプレーンなパスを渡しても、リンクは対象ロケールのローカライズされたパスに解決されます:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

ルート名は、`definePageMeta({ name })` で設定しない限り、ファイルパスから決まります(`pages/about/team.vue` は `about-team`)。

## ロケールごとのスラッグ {#per-locale-slugs}

スラッグ自体がロケールごとに異なる場合(`/our-products/red-shoe` と `/de/unsere-produkte/roter-schuh`)は、データの読み込み後に `$setI18nRouteParams` で言語スイッチャーが使うパラメーターを指定します:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

すると `$switchLocalePath('de')` と `<i18n-switcher>` は `/de/unsere-produkte/roter-schuh` にリンクします。キーはロケールコード、値は(ページファイルと同じ)名前ごとのパラメーターです。

レイアウト内のスイッチャーは、ページの非同期 setup がここに到達する前にレンダリングされます。そのため、レンダリングが終わるとモジュールは `<i18n-switcher>` のリンクを、`app.vue` 内でもページ内でも同様に書き換えます。これにより、サーバーの HTML、JavaScript を使わない訪問者、そして最初のクライアントレンダリングの結果が一致します。そのためにはパラメーターを SSR 中に設定してください。`lazy` や `server: false` の場合、リンクはハイドレーション後にのみ変わります。Nuxt の SSR ストリーミングはパラメーターが判明する前に HTML を送信するため、その場合は最初の HTML 内のリンクは URL 自体のパラメーターのままになります。

書き換えられるのはスイッチャー自身のリンクだけです。手書きの `$switchLocalePath` リンクはパラメーターが設定された後にレンダリングされる必要があるため、パラメーターを設定するページ内に、しかも `await` の後に置いてください。レイアウト内では先にレンダリングされるため、サーバーの HTML は URL のパラメーターのままとなり、ハイドレーション時に不一致の警告が出ます。レイアウトでは `<i18n-switcher>` を使い、見た目はそのスロットと `custom*Style` プロップで調整してください。

パラメーターはそれを設定したページに属します:

- 別のパスへのナビゲーションが確定すると破棄されるため、各ページが独自に設定します。キャンセルされたナビゲーションではそのまま残ります。
- `$setI18nRouteParams` は `setup` 内で `useNuxtApp()` または `useI18n()` から取得してください。後で `useAsyncData` ハンドラー内で呼び出す場合も同様です。そこで取得すると関数は自分のページを把握しており、訪問者がすでに離れていれば、遅れた呼び出しは何もしません。
- `keepalive` を使うと、訪問者が戻ってきたときにページは自分が設定したパラメーターを取り戻します。`useI18nHead` も同様です。

## pages:extend で追加したルート {#routes-added-in-pages-extend}

`pages:extend` フックで追加したルートには `$defineI18nRoute` を読み取るページファイルがなく、多くの場合、複数のルートが 1 つのラッパーコンポーネントを共有します。`name` なしで追加したルートには、Nuxt がそのパスに付ける名前(`/a/:id()` は `a-id`)が与えられるため、言語リンクから到達できます。ただし、別のルートがすでにその名前を持っている場合は明示的な `name` を指定してください。1 つのリストを保持し、`@i18n-micro/utils/split-locale-routes` の `splitLocaleRoutes` でページと、ルート名をキーとする `globalLocaleRoutes` に分割します(パッケージを依存関係に追加してください):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

ローカライズされたパスを `route.meta` に入れないでください。クライアントのルートテーブルに含まれて配信されてしまいます。
