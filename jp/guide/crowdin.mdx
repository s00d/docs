[Crowdin](https://crowdin.com/) は翻訳プラットフォームです。デフォルトロケールのファイルをアップロードし、翻訳者が Crowdin 上で作業し、他のロケールをダウンロードして戻します。モジュールはプレーンな JSON ファイルを読み込むため、Crowdin CLI には `locales/` と `locales/pages/` を正しくマッピングする `crowdin.yml` さえあれば十分です。モジュールの設定を変更する必要はありません。

## crowdin.yml の設定 {#configure-crowdin-yml}

```yml
# crowdin.yml
project_id_env: CROWDIN_PROJECT_ID
api_token_env: CROWDIN_PERSONAL_TOKEN
base_path: ./locales
preserve_hierarchy: true

files:
  - source: /en.json
    translation: /%two_letters_code%.json
  - source: /pages/**/en.json
    translation: /pages/**/%two_letters_code%.json
```

- `en` はデフォルトロケールで、そのファイルがソースになります。
- `project_id_env` / `api_token_env` は ID とトークンを環境変数から読み取るため、シークレットがコミットされることはありません。
- `preserve_hierarchy: true` は `pages/<page>/` フォルダーをそのまま保持します。
- 翻訳ファイルの名前は `nuxt.config.ts` のロケール `code` と一致している必要があります。`%two_letters_code%` は `de` のようなコードに適しています。`pt-BR` のようなコードには `%locale%` を使うか、`languages_mapping` で Crowdin のコードを自分のコードにマッピングしてください。

## アップロードとダウンロード {#upload-and-download}

```bash
npm install -g @crowdin/cli

export CROWDIN_PROJECT_ID=123456
export CROWDIN_PERSONAL_TOKEN=...   # from Crowdin account settings

crowdin upload sources   # push locales/en.json and locales/pages/**/en.json
crowdin download         # write locales/de.json, locales/pages/**/de.json, ...
```

ファイルを最新に保つため、両方を CI で実行してください。ダウンロードされたファイルは手で編集したファイルと同じようにリポジトリに配置され、次回のビルドや開発時のリロードで読み込まれます。

## アップロードの前に {#before-uploading}

翻訳者が使われていないキーに取り組まないよう、まずソースを整理してください: [`i18n-micro clean`](/jp/api/cli#clean) は未使用のキーを削除し、[`i18n-micro check`](/jp/api/cli#check) はダウンロード後の欠落を報告します。CLI 自体には Crowdin 連携はありません。このページの方法がサポートされている手順です。
