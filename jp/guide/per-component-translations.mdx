---
title: "ページ設定"
description: "$defineI18nRoute で、ページを一部のロケールに限定したり、カスタムパス、インライン翻訳を設定したり、SEO タグを無効にしたりします。"
---

`$defineI18nRoute` は、ページ自身の中からそのページの i18n オプションを設定します。ページが一部のロケールにのみ存在する場合、独自のローカライズされたパスが必要な場合、独自の翻訳をいくつか持つ場合、または hreflang/canonical タグを付けてはいけない場合に使用します。モジュールはビルド時にこの呼び出しを読み取り、生成されるルートに組み込みます。

## ページを一部のロケールに限定する {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

デフォルトの `prefix_except_default` 戦略では、`/product` と `/de/product` のみが生成され、他のロケールではこのページのルートはありません。同じことは `nuxt.config.ts` から [`routeLocales`](/jp/api/module-options#routelocales) で設定することもできます。

`$defineI18nRoute` はコンパイラマクロではなく、Nuxt アプリのインジェクションです。必ず `useNuxtApp()` から取得し、`$` 付きで呼び出してください。ビルドステップが認識するのは `$defineI18nRoute(` のみです。

## インライン翻訳を追加する {#add-inline-translations}

配列の代わりにオブジェクトを渡します。キーは許可されるロケールで、値はアクティブなロケールのページ辞書にマージされます。

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

インライン翻訳は、すべてのロケール分がページコンポーネント内に含まれて配信されます。数個のキーより大きいものには[ページ翻訳ファイル](/jp/guide/translations)を優先し、インラインキーは自己完結したページやコンポーネントに留めてください。

## ローカライズされたパスを設定する {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

`prefix_except_default` と `defaultLocale: 'en'` の場合、これは `/welcome` と `/de/willkommen` を生成します。インラインのロケールオブジェクト内の `path` も同じ効果を持ちます: `locales: { de: { path: '/willkommen' } }`。動的パラメータ、ネストされたルート、設定レベルでの代替方法については[ローカライズされたパス](/jp/guide/custom-locale-routes)で説明しています。

## SEO タグを無効にする {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

設定レベルでの代替方法は [`routeDisableMeta`](/jp/api/module-options#routedisablemeta) です。タグの内容については [SEO](/jp/guide/seo) ページをご覧ください。

## ビルドが読み取れるもの {#what-the-build-can-read}

ビルドステップは各ページファイル内の呼び出しを見つけ、アプリを実行せずに引数を評価します。設定が次のいずれかであれば機能します:

- リテラルオブジェクト(文字列、配列、ネストされたオブジェクト、テンプレートリテラル、`process.env.NODE_ENV` に対する三項演算子);
- 同じ `<script setup>` 内で宣言された定数から構築されたもの(`const locales = ['en', 'de']`、スプレッドを含む);
- `code` フィールドを持つオブジェクトの配列(`[{ code: 'en' }, { code: 'de' }]`)。

他のモジュールからインポートした値や、実行時にアプリを必要とするもの(コンポーザブル、`await`、フェッチしたデータ)は読み取れません。その場合、ビルドは `Ignored the $defineI18nRoute() config in <file>` をログに出力し、ページはデフォルトのロケールとルートを維持します。

実行時には、この呼び出しは現在のロケールのインライン翻訳をマージするだけで、ロケールが変わると再マージします。`locales`、`localeRoutes`、`disableMeta` はビルドを通じてのみ有効になるため、変更には再ビルドが必要です(開発サーバーは保存時に再ビルドします)。
