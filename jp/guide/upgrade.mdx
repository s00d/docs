このページでは、nuxt-i18n-micro とその `@i18n-micro/*` パッケージをアップグレードしたときにアプリで何が変わるかを一覧にしています。依存関係を上げる前に、移行元のバージョンのセクションを読んでください。ほとんどのアプリではコードの変更はわずかです。

<Tip>

**`@nuxtjs/i18n` からの移行ですか?** — [@nuxtjs/i18n からの移行](/jp/guide/migration)をご覧ください。

</Tip>

## 3.30.3 以降: メジャーリリース {#after-3-30-3-the-major-release}

モジュールオプション、`$t`、`$localePath`、`$switchLocale` などのヘルパー、コンポーネント、コンポーザブル、ドキュメント化されたサーバーユーティリティは名前が変わりません。変わったのは動作で、その多くはバグ修正です。アダプターパッケージとルーティングパッケージには実際の API の破壊的変更があります: [フレームワークパッケージ](#framework-packages)と[その他のパッケージ](#other-packages)をご覧ください。

### 最初にやること {#do-this-first}

1. **バージョンを確認する。** モジュールには Nuxt 3.18 以降と Node 20 以降が必要です。Nuxt には独自の Node 最小要件があります: Nuxt 4.5 は `^22.19.0 || ^24.11.0 || >=26.0.0` を宣言しています。Nuxt 3.18.0 自体での `nuxt generate` は素の Nuxt でも失敗します(`[unstorage] Invalid key: "/"`)。3.21.11 は動作します。`@i18n-micro/react` には React 18 以降が必要です。
2. **インストール済みのパッケージを修正する。**
   - `@i18n-micro/hmr` を削除してください。翻訳の HMR はモジュールに組み込まれています。
   - テストで `@i18n-micro/test-utils` をインポートしている場合は追加してください: `npm install -D @i18n-micro/test-utils`。モジュールと一緒にはインストールされなくなりました。
   - `nuxt-i18n-micro-cli` を `@i18n-micro/cli` に置き換えてください。28 個のコマンドが 16 個になり、`check` が 3 つを置き換え、終了コードも変わります: [CLI ガイド](/jp/guide/cli#moving-from-nuxt-i18n-micro-cli)をご覧ください。
3. **以下の表のエントリをコード内で検索する。**
4. **アプリの前段にあるものを確認する。** プロキシの背後でロケールに `baseUrl` を使っている場合は、[プロキシや CDN の背後](/jp/guide/deployment#behind-a-proxy-or-cdn)をご覧ください。CDN を使っている場合は、そのキャッシュキーを `Vary` ヘッダーと照らし合わせて確認してください: [HTML のキャッシュ](/jp/guide/deployment#caching-html)をご覧ください。`apiBaseClientHost` や厳格な CSP を使っている場合は、新しい `preload` リンクを許可してください: [SEO と head タグ](#seo-and-head-tags)をご覧ください。
5. **スナップショットを更新する。** head のスナップショットには `preload` リンクが追加され、スイッチャーのマークアップが変わり([`<i18n-switcher>` と `<i18n-link>`](#&lt;i18n-switcher>-and-&lt;i18n-link>))、`$localeRoute` の出力のクエリ文字列のエンコード方法も変わりました。
6. **各ロケールでページを開き、生のキーがないか確認する。** 前のページのファイルのキーを使っていたレイアウトは、それらを生のまま表示するようになります: それらのキーをルートファイルに移動してください。

<Warning>

**`@i18n-micro/path-strategy` の `switchLocaleRoute` は最初の引数がなくなりました** — `switchLocaleRoute(fromLocale, toLocale, route, options)` は `switchLocaleRoute(toLocale, route, options)` になりました。**古い JavaScript の呼び出しは失敗せず、誤った結果を返します。** `fromLocale` がターゲットとして、`toLocale` がルートとして読まれるためです。TypeScript だけが教えてくれます。Nuxt の `$switchLocaleRoute` は影響を受けません。

</Warning>

| 検索対象 | 対処法 |
| --- | --- |
| `@i18n-micro/path-strategy` の `switchLocaleRoute(` | 最初の引数を削除する。上記参照 |
| `dependsOn` 内の `i18n-plugin-hooks` または `i18n-plugin-define` | `i18n-plugin-loader` を使用する。古い名前はエラーなしで何も待たなくなった |
| `router.push({ name })` 内の `localized-…` という名前 | ページ自身の名前を `$localeRoute` または `<i18n-link>` に渡す |
| `$localeRoute` または `$switchLocaleRoute` の結果の `.name` や `.params` | それらがない場合を処理する。[リンク](#links-and-route-objects)を参照 |
| ロケールに `baseUrl` がある状態での `<NuxtLink :to>` や `router.push` 内の `$localeRoute(x, 'fr')` | `$localePath` を使用する。[ロケールドメイン](#locale-domains)を参照 |
| `$getI18nConfig().globalLocaleRoutes`、またはそこからの `isSSG`、`hmr`、`hooks`、`noPrefixRedirect`、`routeLocales`、`routeDisableMeta` | ランタイム設定からなくなった。ビルドだけがそれらを読み取っており、オプション自体は変わらない。`ModuleOptionsExtend.isSSG` は何も設定しない、オプションで非推奨のプロパティとして残る |
| `useLocaleServerMiddleware`、`useTranslationServerMiddleware`、`loadTranslationsFromServer`、`detectCurrentLocale` 以外のサーバー自動インポート | 削除する。`getI18nServerConfig`、`detectRequestLocale`、`getRequestLocale`、`loadLiveDevTranslations`、`getOrCreateServerTranslationCache`、`DEFAULT_SERVER_CACHE_SIZE` とウォッチャーヘルパーは自動インポートされなくなった |
| `nuxt-i18n-micro` からの `resolveTranslationPayloadMode`、`resolveTranslationPayloadOptions`、`resolveTranslationPayloadPublicDir`、`resolveTranslationPayloadPublicRel`、`shouldCopyTranslationPayloadsToPublic`、`shouldRegisterNitroServerAssets` | 削除する。`TranslationPayloadMode` 型は残る |

`detectCurrentLocale` は非推奨です。引き続き動作し、サーバーの自動インポートでもあります。同じルールを適用する [`useLocaleServerMiddleware(event).current`](/jp/guide/server-side-translations) を使用してください。

このドキュメントの 17 ページが移動しました。古い URL はリダイレクトされるため、それらへのリンクは引き続き機能します。

### URL とリダイレクト {#urls-and-redirects}

- **`prefix_except_default` では `/en` と `/en/...` は 404 になります**(`en` がデフォルトの場合)。ドキュメントどおりです。
- **大文字小文字や綴りが異なるロケールプレフィックスは 404 になります。** `/DE/about` は以前、ドイツ語のルートをデフォルトロケールでレンダリングするか、`/en/DE/about` にリダイレクトしていました。その URL に独自のページがある場合はページのままです。キャッチオールや `[slug]` ページは該当しません: `[...slug]` の下の `/DE/x` や `[slug]` の隣の `/DE` も 404 になるため、大文字小文字の異なるロケールコードと同じ CMS スラッグはそのページを失います。`ssr: false` ではサーバーが応答しないため、`/DE/about` はドイツ語のページを表示します。
- **大文字小文字の異なるページパスは本来の綴りにリダイレクトされます。** `/T/BASIC` は 200 でしたが、現在は `/t/basic` への `302` です。
- **未知の URL は 404 のままです。** `autoDetectPath: '*'` または `'no_prefix'` の場合、`/nope` は先に `/de/nope` にリダイレクトされなくなりました。`prefix` ではリダイレクトが維持されます(プレフィックスなしでは何も提供されないため)。`/` はどこでも同様です。
- **プレフィックスなしの別ロケールのカスタムパスは、`prefix_except_default` でそのページを見つけます。** `/a-propos` は 404 でしたが、現在はデフォルトロケールの URL(`/about`)への `302` です。`prefix` では同じリダイレクトが実在するページ(`/en/about`。以前は 404 の `/en/a-propos`)に到達するようになりました。`prefix_and_default` は 404 のままです。
- **`redirects: false` の `prefix` は、プレフィックスなし URL に 404 を返します**(`/about` は `302` でした)。デフォルトのカスタムパスを持つページの元の URL も含みます。`$localePath('/about')` は引き続きそのページを見つけます。
- **`prefix_except_default` では、デフォルトのカスタムパスを持つページの元の URL はそのカスタムパスにリダイレクトされます。** 動的ページも含みます。`/dir/one` は 404 でしたが、現在は `/dir-one/one` への `302` です。
- **`autoDetectPath: '*'` は、プレフィックスなしパスにも Cookie と `Accept-Language` を適用するようになりました**(`/about` → `/de/about`)。
- **`prefix` では、プレフィックスなし URL は訪問者のロケールを維持します。** Cookie が `de` の場合、`/about` と素の `<NuxtLink to="/about">` は、`autoDetectPath` の値にかかわらず、すべてのパスで `/de/about` に移動します。
- **`prefix_and_default` では、プレフィックスなし URL はデフォルトロケールです。** `Accept-Language: de` での `/contact` は以前、ドイツ語でレンダリングしてから英語でハイドレートしていました。現在はデフォルトロケールでレンダリングされ、訪問者は `/de/...` からドイツ語に到達します。
- **`no_prefix` では、カスタムパスはそのロケールでレンダリングされ**(`/ueber-uns` はどの設定でもドイツ語)、限定されたページは提供するロケールのいずれかでレンダリングされます。複数のロケールが共有するパスは、設定がそのいずれかであれば設定のロケールでレンダリングされ、`baseUrl` の下ではそれぞれのドメインでページになります。それらのロケールは 1 つのレコード `localized-<page>-<first locale>` を共有します。
- **`noPrefixRedirect` は訪問者のロケールに従います。** Cookie が `de` の場合、`/about` はデフォルトロケールの `/about-us` ではなく `/ueber-uns` に移動し、ドイツ語でレンダリングされます。独自のカスタムパスを持たないロケールは `/about` に留まります。
- **ページのない `routeRules` のリダイレクトはローカライズされません。** `/de/old` は空の 200 でしたが、現在は 404 です: 必要であればプレフィックス付きパスのルールを追加してください。別のロケールからそのようなルールへのリンクは記述どおりのパスを保ち、ルールのターゲットに到達します。
- **ルートルールはカスタムパスにも適用されます。** `blog/[slug]` が `/de/artikel/:slug` のパスを持つ場合、`/blog/**` はそれにも適用され、ルールは `no_prefix` でもコピーされます。`/de/artikel/news` のような静的な兄弟ページもそのパターンに一致します。すでにロケールプレフィックス付きで記述されたルールは記述どおりに残ります。
- **`disabled: true` のロケールはそのプレフィックスで即座に 404 を返し**、そのロケールへのリンクはページに留まります。ランタイムで無効化されたロケールも同様です: 以前はフォールバックロケールでレンダリングされていました。
- **モジュールの 404 は `Page Not Found` と表示されます。** 無効化されたロケールのプレフィックスと、ホスト自身のプレフィックスで、Nuxt が `Page not found: /de/about` と表示していた場合です。ステータスは同じです。
- **`customRegexMatcher` は、最初のセグメントがロケールに見える実在のページを 404 にしなくなりました。**
- **ローカライズされたルート名は一貫しています。** 共有ロケールレコードの下の子はページの名前を保ち、`no_prefix` は `localizedRouteNamePrefix` に従い、index の子を持つ親は名前なしのままです。
- **モジュールが `name` なしで追加するページ**(`extendPages`)はローカライズされ、ロケールバリアントと `hreflang` 付きで名前が付けられます。以前はローカライズされないままでした。
- **`nuxt.config` のエントリは `$defineI18nRoute` より優先されます。** キーの形式(`about/team`、`/about/team`、`about-team`)にかかわらずです。以前はどちらが優先されるかが綴りに依存していました。
- **新しいビルド警告:** 自身のロケールコードで始まる `localeRoutes` の値(`fr: '/fr/article'`)、および親の外にある子のカスタムパス。
- **ハッシュモードが `prefix` で機能します。** ドキュメントは `/` で、`/en` や `/about` はハッシュにリダイレクトされます。
- **`prefix_except_default` と `prefix_and_default` で `/#/de/x` はドイツ語でレンダリングされます。** 以前はハイドレーションの不一致を伴って英語でレンダリングされていました。

### リンクとルートオブジェクト {#links-and-route-objects}

- **ページを提供しないロケールは、そのホームにリンクします。** `$localeRoute`、`$switchLocalePath`、スイッチャーは他のロケールのページを返さなくなりました。
- **未知のロケールコードはデフォルトロケールに移動します。** `$localePath(path, 'xx')` と `$localeRoute` は以前 `/xx` を返していました。
- **`$localePath` は `http(s):`、`mailto:`、`tel:` スキームを持つ文字列をそのまま返し、`$localeRoute` の `path` と `fullPath` もそれを変更せずに保持します。** そのため、検証されていない値(`?next=` パラメータ)をリンクターゲットとして渡さないでください。`//host` や `x.com` のような素の名前はパスのままで、すべてのロケールでこのオリジン上にあり、それらから作られたリンクがオリジンを離れることはありません: デフォルトロケールへの `/de//x.com` は `/x.com` です。バックスラッシュはスラッシュとして扱われます。
- **`$localePath` はパスをエンコードします:** `/a b` は `/a%20b` になります。
- **`$localeRoute` と `$switchLocaleRoute` はプレーンなオブジェクトを返します。** `ref`、`reactive`、`useState`、JSON、スプレッドで安全に使えます。パラメータにエスケープが必要な場合、オブジェクトは `{ path, fullPath, query, hash }`(`$localeRoute` は `href` を追加)で、`name` や `params` はなく、URL はリロード前後で同じです。プレーンな URL では両方を持ちます。`name` は新しいもので、古いオブジェクトには一度もありませんでした。`.name` や `.params` を読み取るコードはそれらがない場合を処理する必要があり、どちらの形式になるかは値に依存します。
- **`trailingSlash` では、`$switchLocaleRoute` は常にそのパス形式を返し**、素のスラッグも同様で、サーバーのリダイレクトは `trailingSlash` に従います。このオプションでは結果や `Location` ヘッダーが変わることがあります。
- **`$localeRoute` の出力のクエリ値は vue-router のエンコードを使用します:** `/` はそのまま、スペースは `+` になります(`?redirect=/v2`。以前は `%2Fv2`)。デコードされた値は同じですが、そのような `href` のスナップショットは変わります。
- **パスのないリンクは現在のページに留まります。** `$localePath('#top')`、`'?p=2'`、`''`、`{ query }` は現在のページを保ちます。`'#top'` は以前サイトルートから読み取られていました。素の `'about'` は引き続き `/about` を意味します。
- **スプレッド。** `{ ...route, query }` と `{ ...route, hash }` は `$switchRoute` を通しても変更を保ちます。新しい `path` は `$localeRoute`、`$localePath`、`$switchRoute` で優先されます。`{ ...route, params }` は名前付きルートで機能します。パス形式のルートではパスが優先され、パラメータは vue-router の開発時警告とともに無視されます。`$localeRoute({ name, params })` を使用してください。
- **`$switchRoute` はアプリ内に留まります。** ロケール自身の `baseUrl`、`mailto:`、`tel:` はアプリを離れ、それ以外の文字列はパスです。
- **`excludePatterns`** はセグメント全体に一致し(`'/admin'` は `/administrator` に一致しなくなりました)、glob はアンカーされます(`/docs/*` は `/en/docs/x` に一致しなくなりました)。`RegExp` パターンがランタイムに届くようになりました。以前はそこで失われていました。それらに一致するページはローカライズされません: `hreflang` はなく、`prefix_except_default` ではデフォルトロケールになります。パターンを[パスの除外](/jp/guide/excluding-static-files)と照らし合わせて確認してください。

パラメータ内の `%` や `?` は、Nuxt 4.5.2 ではどのアプリでもサーバーレンダリングされたリロード後に保持されません: これはモジュールではなく上流の問題です。

### ロケールドメイン {#locale-domains}

- **`locales[].baseUrl` がリクエストをルーティングするようになりました。** 1 つのビルドですべてのドメインを提供します: [レイヤーとドメイン](/jp/guide/layers#multiple-domains)をご覧ください。`baseUrl` が設定されている場合、別ドメインのロケールはこのホストでは 404 になり(`example.de` 上の `/en/about`)、同じホスト上のロケールへのリンクは相対リンクになります。他のホスト(`localhost` を含む)へのリクエストは以前と同じように動作しますが、canonical と `hreflang` はリクエストのオリジンではなく、設定されていれば `metaBaseUrl`、なければデフォルトロケールの `baseUrl` を使用します。
- **`Host` を書き換えるプロキシの背後では、** [`trustForwardedHost`](/jp/api/module-options#trustforwardedhost) を設定するまで、すべてのリクエストがビルド設定にフォールバックします。`metaTrustForwardedHost` とは異なり、デフォルトは `false` です。[プロキシや CDN の背後](/jp/guide/deployment#behind-a-proxy-or-cdn)をご覧ください。
- **`baseUrl` を使った `nuxi generate` には、ドメインごとに 1 回 `NUXT_I18N_DOMAIN` が必要です。** これがないとビルドは警告を出し、それらのロケールはページのないリンクになります。[静的サイト](/jp/guide/deployment#static-site-(nuxi-generate))をご覧ください。
- **`baseUrl` を持つロケールへのリンクは `$localePath` または `<i18n-link>` を通します。** `<NuxtLink :to="$localePath(x, 'fr')">` と `<i18n-link :to="$localeRoute(x, 'fr')">` はその絶対 URL になり、クリックするとそこに移動します。ルーターは絶対オブジェクトを受け付けません: `<NuxtLink :to="$localeRoute(x, 'fr')">` と `router.push($localeRoute(x, 'fr'))` は `/https://fr.example.com/...` という、このアプリのパスのままになります。`localhost` やプレビューホストでは、`baseUrl` を持つすべてのロケール(現在のロケールも含む)がそのようなリンクになります。コードでは `navigateTo($localePath(x, 'fr'), { external: true })` を使用してください。
- **ドメインのホームは、リンク、canonical、`hreflang` のどこでも末尾のスラッシュなしで記述されます**(`https://example.de`)。
- **`prefix` では、別ドメインへのリンクは `baseDefault` の有無にかかわらずロケールプレフィックスを保持します。** `https://example.de/about`(リダイレクトするだけ)ではなく `https://example.de/de/about` です。
- **`prefix_except_default` で、ビルドのデフォルト以外のロケールに `baseDefault` がある場合、ルートはすべてのプレフィックスを保持し**、他のドメインからリンクできるようにします。`/en` は引き続き 404 です。違いが見えるのは `router.getRoutes()` を読み取るコードだけです。
- **`prefix_except_default` では、ホスト自身のプレフィックスはその `baseDefault` ホストで 404 になります。** `de` ホスト上の `/de/x` は 200 でした。
- **`$getI18nConfig().locales` はホストが提供するものだけを保持します。** `linkLocales` はすべてを保持し、`$getLocales()` は完全なままです。

### ナビゲーションと `$switchLocale` {#navigation-and-$switchlocale}

- **ナビゲーションはコミット時に適用されます。** 辞書、ロケール、パラメータ、head は `router.afterEach` で変わるため、キャンセルまたはブロックされたナビゲーションは何も変えず、次のチャンクの読み込み中も古いページのリンクは有効なままです。`beforeResolve`、`beforeRouteEnter`、または後続のグローバルガードは、古い辞書とロケールを参照するようになりました。ルートミドルウェアは影響を受けません。
- **失敗したチャンクは現在の辞書を保持します。** ルートファイルでの 5xx、ネットワークエラー、不正な本文は以前、生のキーを表示していました。現在は新しいページが古い文字列でレンダリングされ、次のナビゲーションで再試行されます。404、またはファイルの代わりに静的ホストの SPA シェルが返った場合は、次のリロードまでルート辞書が使われます。
- **`$switchLocale` は `true` または `false` で解決されます**(以前は何も返しませんでした)。ロケールの辞書が適用されなかった場合は `false` です。型は `Promise<boolean>` で、`$switchRoute` は `Promise<void>` です。
- **`$switchLocale` は明示的な選択です。** 到着時(404 でも)にロケールを保存します。ナビゲーションがブロック、キャンセル、または例外を投げた場合、保存された設定とステートは元のままで、例外は再スローされます。別のホストへの移動では先に保存します。`no_prefix` とハッシュモードでは、ナビゲーションの結果にかかわらず切り替えが維持されます。すべてのロケールで 1 つの URL を持つページ(`excludePatterns`)では選択は取り消されず、次のページの URL が決定します: `prefix_except_default` ではプレフィックスなしのリンクはデフォルトロケールに戻ります。
- **`no_prefix` では、2 つのページがカスタムパスを共有する場合、`$switchLocale` はそのページを保持します。** エスケープされたパラメータでも同様です。そのような URL のリロードや、エスケープされたパラメータを持つ `$localeRoute` は、最初のレコードに到達します。
- **クライアントリダイレクトはナビゲーションのモードを保持します。** `prefix` での素の `<NuxtLink to="/about">` は現在の履歴エントリを上書きせず、新しいエントリを追加します。`router.replace` は引き続き置き換えます。
- **サーバーからの `$setI18nRouteParams` と `useI18nHead` はハイドレーション後も保持されます。** `/news/2` に着地した後、ページが SSR 中にパラメータを設定していれば、スイッチャーはどこにあっても、サーバー HTML でも、`/de/news/2` ではなく翻訳されたスラッグ(`/de/news/2-zwei`)にリンクします。別のパスへのナビゲーションがコミットされると破棄されます(`/news/1` から `/news/4` も含む): 新しいページで再度設定してください。
- **setup で読み取った `$setI18nRouteParams` はそのページに紐づきます。** すでに離れたページからの遅延呼び出しは何もしません。`useNuxtApp().$setI18nRouteParams` はアクセサーになり、2 回読み取ると 2 つの関数が得られます。セッターはありません: テストのスタブで行うような `useI18n().$setI18nRouteParams = fn` は strict モードで例外を投げるため、`useI18n` 自体をスタブしてください。レイアウトや `app.vue` では、そこには離れるものがないため、プレーンな関数です。
- **サーバーはレンダリング終了時に `<i18n-switcher>` のリンクを書き換えます**(パラメータを持つページで)。レイアウト内のスイッチャーはページの非同期 setup より前にレンダリングされるためです。手書きの `$switchLocalePath` リンクは書き換えられません: [カスタムロケールルート](/jp/guide/custom-locale-routes)をご覧ください。Nuxt の SSR ストリーミングでは、最初の HTML は URL のパラメータを保持します。
- **サーバーコンポーネントの `locale` という名前の prop がそのレンダリングロケールを設定します。** そのため `<Greeting :locale="$getLocale()" />` は URL と切り替えに従います。その中の `$getLocale()`、`$localePath`、`$getLocaleName` も prop に従います。[サーバーサイド翻訳](/jp/guide/server-side-translations)をご覧ください。prop がない場合は引き続き Cookie またはデフォルトを使用します。
- **`keepalive` ページは戻ったときにパラメータと head を取り戻します。**
- **`prefix_except_default` で `false` に設定されたネストされたページにはロケール URL がありません。** `globalLocaleRoutes: { 'parent-kid': false }` での `/de/parent/kid` は提供されていましたが、現在は 404 です: ページは `/parent/kid` に留まります。

### ロケール検出と Cookie {#locale-detection-and-the-cookie}

どこでも 1 つの優先順位で、[ロケール検出](/jp/guide/locale-detection)で説明しています。

- **`?locale=` がページで評価されるのは `no_prefix` のみです。** プレフィックス戦略では URL が決定します。`/about?locale=de` が `lang="en"` のままドイツ語でレンダリングされることはなくなりました。`?locale=de&locale=fr` は最初の値を読み取ります。以前は `"de,fr"` でした。
- **`Accept-Language` は `q` 値に従います**(`fr;q=0.1, de;q=0.9` → `de`。`q=0` は言語を除外します)。地域の照合は `locales` の順序に依存しなくなり、中国語の文字体系を跨ぐことはありません。
- **ページへのクライアントナビゲーションは、そのロケールを Cookie に保存します。デフォルトロケールのプレフィックスなしページでも同様です。** `localeCookie` が設定されている場合、`/about` へのリンクをクリックした訪問者は `user-locale=en` を持つようになり、後でブラウザの言語を変えても `/` はリダイレクトされなくなります。その URL の初回読み込みでは何も保存されません。`no_prefix` とハッシュモードでは、ナビゲーションは変更のみを保存します。
- **404 は Cookie を書き込みません:** どのモードでも、レスポンスでも、そこへの素のクライアントナビゲーションでも書き込みません。`no_prefix` では、プレフィックス付きに見える URL も書き込みません。
- **`no_prefix` で明示的な `localeCookie: null` が尊重されます。** 以前は `user-locale` になっていました。`nuxt.config` の `i18n` ブロックで設定してください: `modules: [[name, opts]]` やレイヤー内の `null` は引き続き失われます。
- **ハッシュモードは `hash-locale` Cookie のみを読み取ります。** 単独の `user-locale=de` は評価されなくなりました。
- **不正なロケール Cookie は無視され、そのまま残ります。** すべての SSR ページが 500 で失敗することはなくなりました。リクエストごとに削除されることもなくなり、これによりプレフィックス付きページがロケールを保存できなくなる問題も解消されました。
- **URL のロケールが最優先です。** `/en/...` でのプラグインの `setLocale('de')` は `de` の辞書を読み込まなくなり、ステート内の未知のコードは無視されます。
- **サーバー API ヘルパー**(`useLocaleServerMiddleware`、`useTranslationServerMiddleware`)はすべてのルートで 1 つの順序を使用します: `?locale` → `[locale]` パラメータまたはプレフィックス → Cookie → ヘッダー → デフォルト。`localeCookie: null` と `autoDetectLanguage: false` を尊重するようになり、ロケールごとに辞書をキャッシュします。
- **ランタイムオーバーライドがルーティングに反映されます。** `NUXT_I18N_DEFAULT_LOCALE` とランタイムの `disabledLocales` は生成された戦略を変更するようになり(無効化されたロケールはルーティングを停止)、ランタイムの `disabledLocales` はビルドのものに追加されます。`prefix_except_default` と `prefix_and_default` では、そのロケールのプレフィックスなしルートはビルド時に生成されるため、ランタイムの `defaultLocale` は警告とともに無視されます。ランタイムの `fallbackLocale` は有効なロケールでなければなりません: そうでない場合は警告とともに破棄され、ビルドの値が有効であればそれが適用されます。[ランタイムオーバーライド](/jp/guide/runtime-overrides)をご覧ください。

### SEO と head タグ {#seo-and-head-tags}

- **`dir="auto"` はデフォルトではなくなりました。** `dir` のないロケールは以前 `dir="auto"` を得ており、大きなページのパースを遅くしていました。現在は既知の RTL 言語が `dir="rtl"` を得て、それ以外のロケールには属性が付きません。これは Nuxt、`@i18n-micro/vue`、`astro`、`vitepress` に適用されます。古い出力を維持するためにロケールに `dir: 'auto'` を設定すると、20,000 要素で約 1 秒のパースコストがかかります: [テキストの方向](/jp/guide/seo#text-direction)をご覧ください。
- **すべての SSR ページに新しいタグがあります:** `<link rel="preload" as="fetch" crossorigin="anonymous" href="/_locales/...">`。404 ページにもあります。`apiBaseClientHost` の場合、`href` はそのホスト上にあり、CORS が必要です。厳格な CSP はこれを許可する必要があります。
- **`hreflang` はページを提供するロケールのみを列挙します。** `x-default` はデフォルトロケールがページを提供する場合にのみ出力されます。
- **ローカライズされていないページには `hreflang` や `og:locale:alternate` がありません。**
- **オリジンがリクエストから取得される場合、canonical と `hreflang` には `app.baseURL` が含まれます。** `metaBaseUrl` と `site.url` は記述どおりです。
- **404 ページは URL のロケールで `<html lang dir>` を持ちます。** canonical、`hreflang`、`og:url`、`og:locale`、代替リンクはありません。モジュール自体が一致したレコード(`/en/...`)で 404 を返す場合も同様です。`useI18nHead` の `replace` で渡したタグは残るため、エラーページではスキップしてください。
- **canonical、`og:url`、`hreflang` はホワイトリストのクエリを保持します**(`/about?page=2`)。サーバーでも同様です: 以前は SSR 中に破棄されていました。デフォルトでは `page`、`sort`、`filter`、`search`、`q`、`query`、`tag` がホワイトリストに含まれます。[`canonicalQueryWhitelist`](/jp/api/module-options#canonicalquerywhitelist) をご覧ください。
- **パースできない `X-Forwarded-Host` は無視されます。** すべてのページで 500 になることはなくなりました。使用可能なホストがなく、`metaBaseUrl` や `site.url` もない場合、そのレスポンスの canonical と `hreflang` の URL は相対になります。パースできない `Host` は、素の Nuxt アプリと同様に 500 のままです。
- **`disableMeta` が機能するようになりました。** `$defineI18nRoute` でも `routeDisableMeta` でも、`nuxt.config` で設定した場合も同様です: ページには `hreflang`、canonical、`og:locale` がありません。`lang` と `dir` は残ります。
- `useLocaleHead()` は `build()` も返します。これは `useHead(() => build())` 用のゲッターです。
- `metaBaseUrl` のない素のビルドでは、以前と同様に `X-Forwarded-Host` がこれらのタグのホストを選びます。オリジンに直接アクセスできる場合は `metaBaseUrl` を固定してください: [プロキシや CDN の背後](/jp/guide/deployment#behind-a-proxy-or-cdn)をご覧ください。

### 翻訳 {#translations}

- **マージはすべての階層でディープになりました。** ルート、ページ、フォールバックのファイルは 2 階層のマージを使っていたため、ソースモードや開発環境ではフォールバックやルートからの `a.b.c` が失われていました。現在はすべてのモードで同じ辞書になります。
- **フォールバックチェーンはすべてのモードで最後までたどられます**(`fr` → `de` → `en`)。
- **マージはファイルの種類ではなくロケールごとに行われます。** アクティブなロケールのルートファイルが、フォールバックロケールのページファイルより優先されるようになりました。[フォールバックロケール](/jp/guide/translations#fallback-locales)をご覧ください。
- **同じ `code` に対して、プロジェクトの `locales` エントリがレイヤーのものより優先されます。** レイヤーは不足分を補うだけです。
- **独自の `pages/<name>/` フォルダを持たないページはルート辞書を読み取ります。** 子ページも同様です。以前は `{}` を得て生のキーを表示していました。出力にはそのようなページごとのファイルと、ロケールごとの `__root/<locale>/data.json` が追加されます: `/_locales/<any name>/en/data.json` はルートキーを含む 200 になります(以前は `{}`)。これは監視、静的ホストの許可リスト、ツリーを読み取るツールに影響します。
- **`disablePageLocales: true` はルートファイルのみを読み取ります。** `pages/index` はマージされなくなりました。
- **離れるページのキーは、その要素がドキュメントから離れると解決されなくなります。** レイアウトが前のページのファイルにしかないキーを使っていた場合は、それらをルートファイルに移動してください。親のキーは、子が表示されている間(`index` の子を持つ親も含む)、次のナビゲーションまで残ります。同じ親の 2 つの子の間では、親自身のキーには子の辞書またはルートの辞書が必要です。
- **`$clearCache()` は現在のページの辞書を再読み込みし**、新しいものが届くまで古いものを画面に保持します。再読み込みに失敗すると古い辞書が保持され、クリア前にリクエストされたレスポンスは破棄され、離れるトランジション中のページは翻訳されたままです。
- **`$has(key, route)` はルートを尊重します。**
- **まだ訪問していないページでの `$loadPageTranslations` は、そのファイルの読み込みを妨げなくなりました。** ファイルは最初の訪問時に読み込まれ、あなたのキーはその上に保持されます。以前はリロードするまでページに生のキーが表示されていました。
- **翻訳の HMR はページをリロードせずにその場で編集を適用します。** 削除されたキーは消え、ルートの編集はすべてのページに反映されます。
- **壊れたロケールファイルは、すべてのモードでパス付きで 1 回警告します。** 以前は開発環境では例外を投げ、premerged では黙ってスキップしていたため、開発環境での強制失敗に依存していたアプリではそれが見られなくなります。

### 複数形とフォーマット {#plurals-and-formatting}

- 負数、小数、巨大な数を指定した `$tc` は、実際の数で最後の形式を使います。`{ count: null }` は例外を投げなくなりました。存在しない複数形キーは missing ハンドラーに届きます。
- `$tdr` は実際の未来の日付を返し(`in 3 days`、または `numeric: 'auto'` で `tomorrow`)、無効な入力には `Invalid Date` を返します。過去 1 秒未満は `0 seconds ago` です。
- **`$tn`、`$td`、`$tdr` は複数形と同様に `iso` に従います:** `{ code: 'en', iso: 'en-GB' }` は日付を `31/10/2026` とフォーマットするようになりました。ロケールコード内の `_` は `-` として読まれるため `en_US` は例外を投げなくなり、`Intl` が知らないコードはマシンのロケールに従うのではなく `en` としてフォーマットされます。名前付きフォーマットは引き続き `code` で検索されます。
- `{param}` プレースホルダーは渡したパラメータのみを読み取ります(`{constructor}` は記述どおりに残ります)。
- `{placeholder}` の名前には波括弧とスペース以外の任意の文字を使えます: `{firstName}`、`{first-name}`、`{user.name}` は `params` から読み取られます。そのようなパラメータがない場合は、以前と同様に記述どおりに残ります。
- `defaultValue` は `$t` と `$tc` で補間されます: `$t('missing', { n: 1 }, 'Got {n}')` は `Got 1` を返します。以前は `Got {n}` でした。文字列でないデフォルト値はそのまま返されます。
- 空の翻訳に対する `$tc` は `$t` と同様に `''` を返します。以前はデフォルト値またはキーを返していました。
- **複数形テンプレートは 1 つの例外を除いて意味を保ちます。** 表にすべての形を示します。`Intl.PluralRules` のカテゴリを使うには、新しい [`=0 ` マーカー](/jp/api/methods#$tc)で明示してください: `=0 no apples | one apple | {count} apples`。

  | 形 | 例(`uk` で) | 以前 | 現在 |
  | --- | --- | --- | --- |
  | 整数カテゴリが 1 つまたは 2 つのロケール(`en`、`de`、`fr`、`es`、`ja`...)での任意のテンプレート | `none \| one \| {count} many` | インデックス順 | **変更なし** |
  | カテゴリごとに 1 つの形式 | `one \| few \| many` | インデックス順: 21 → `many` | **変更なし**。21 → `one` にするにはマーカーを追加 |
  | ゼロ形式が先頭、3 つの形式 | `none \| one \| many` | インデックス順 | **変更なし** |
  | 他のプレースホルダー | `no items \| {n} item \| {n} items` | インデックス順 | **変更なし** |
  | すべての形式に `{count}` | `{count} many \| {count} one \| {count} few` | インデックス順 | **変更なし** |
  | 以下より少ないまたは多い形式 | `a \| b`, `none \| one \| two \| {count} many` | インデックス順 | **変更なし** |
  | `lv`、`prg`、`blo`、`cv`、`ksh`、`lag` で | `none \| one \| {count} many` | インデックス順 | **変更なし** |
  | `=0 ` でマーク | `=0 none \| one \| many` | マーカーがテキストとして表示されていた | ゼロ形式、次にカテゴリ |
  | **プレースホルダーのないゼロ形式に続いてカテゴリごとに 1 つの形式があり、複数の数が共有する各形式に `{count}` がある** | `none \| {count} one \| {count} few \| {count} many` | インデックス順: 3 → `3 many`、21 → `21 many` | **カテゴリ順**: 3 → `3 few`、21 → `21 one`。0、1、2、および `many` のままの数はすべて同じ結果 |

  最後の形には 3 つ以上のカテゴリが必要です(`ru`、`uk`、`pl`、`cs`、`sk`、`hr`、`sr`、`lt`、`ro`、`sl`、`he`、`ar`、`cy`...)。`ar` では `one` と `two` は単一の数なので、その 2 つの形式には数字は不要です。
- **`Intl` が知らないロケールコードは、マーカーのカテゴリの有無にかかわらずインデックスルールを得ます:** `ua` はマシンのロケールに従わなくなりました。`iso` を設定してください: `{ code: 'ua', iso: 'uk-UA' }` は、モジュールでも `@i18n-micro/vue` でもウクライナ語として複数形を扱います。
- **カスタムの `plural` ルールはシグネチャを保ち**、引き続きロケールコードを受け取ります。生の値を読み取るため、マークされたテンプレートは `=0 ` がそのまま付いた状態で届き、数は `Number` として受け取ります: 以前 `1` を受け取っていたところで `1.5` を受け取ります。`null` を返すと、マーカーを尊重する組み込みルールにフォールバックします。
- **`timeZone` オプション。** これを設定する(`Europe/Berlin`)と、サーバーとすべてのブラウザで同じカレンダー日付をレンダリングします。時計に依存する `relativeDate` には効果がありません。

### `<i18n-t>` {#&lt;i18n-t>}

このセクションでは、モジュールの `<i18n-t>` と `@i18n-micro/vue` の `I18nT` について説明します。他のフレームワークについては[フレームワークパッケージ](#framework-packages)をご覧ください。

- **`html` はどの場合も `params` をエスケープし、すべてのスロットを無視します。** 信頼されるマークアップは翻訳だけです。意図的にマークアップを持っていたパラメータはテキストとして表示されるようになります: マークアップを翻訳に入れてデータをパラメータとして渡すか、`html` なしでスロットを使用してください。
- **スロットは `plural`、`number`、`date`、`relativeDate` で機能し**、それらの場合も `default` スロットは `{ translation }` を受け取ります。最初のものだけでなく、すべての `{name}` が埋められます。
- **スロットは同名のパラメータより優先されます。** プレースホルダーのように見えるパラメータ値はテキストのままです。`customPluralRule` やカスタムの `plural` では、ルールが完成した文字列を返すため、そこで補間されたパラメータがプレースホルダーと見なされることがあります。
- **`plural`、`number`、`date`、`relativeDate` では `null` は未設定を意味します。** `:plural="null"` は以前レンダリングに失敗し、`:date="null"` は 1970 年をレンダリングしていました。
- `plural` は `$tc` と同様に `Number` で数えます: `1.5` は `1.5` のままで最後の形式を使います(以前は `1` に切り捨てられていました)。`"2 items"` は `NaN` です(以前は `2`)。`""` は `0` です。`customPluralRule` も `1.5` を受け取ります。その他の契約は変わりません: 同じ引数で、その戻り値はそのまま使われ、`null` は空をレンダリングします。
- `hideIfEmpty` は `plural`、`number`、`date`、`relativeDate` に適用されます。非表示の値は空のテキストノードではなくコメントをレンダリングするため、`''` を読み取っていたテストは `<!---->` を見ることになります。
- **`html` での存在しないキーはテキストです。** 信頼されるのは翻訳だけで、キーはリクエストから来る可能性があるため、キーはエスケープされます。`defaultValue` はあなたのものなので、マークアップのままです。
- `plural` では、`$tc` と同様に、見つからない場合は `defaultValue` またはキーがそのまま使われます: `a | b` は分割されなくなりました。
- `defaultValue` はすべての分岐で、キーそのものではなく存在しないキーの代わりになり、`customPluralRule` は見つからない場合にゲッターを通じてそれを受け取ります。以前は `hideIfEmpty` の後でのみ機能していました。
- `number`、`date`、`relativeDate` を持つ `<i18n-t>` は `params` を保持し、それらはマージされます。
- `date` と `relativeDate` の出力には `data-allow-mismatch="text"` が付きます: サーバーとブラウザで異なる時計やタイムゾーンは、ハイドレーション中に警告を出さなくなりました。名前付きスロットの隣では、スロットの周囲のテキストは独自の `<span>` に入ります。Vue はこの属性を要素の単一のテキストでのみチェックするためです。
- `.innerHTML` と `textContent` 属性は `innerHTML` と一緒に破棄されます。
- `<i18n-t>` と `<i18n-group>` は、ルートのチャンクではなく、`$t` と同様にアクティブな辞書を読み取ります。追い出されたチャンク(`cacheMaxSize`)が生のキーを表示することはなくなりました。離れるトランジション中のページは、そこで `$t` が読み取るもの、つまり新しいページの辞書を読み取り、見つからない場合は自身の辞書にフォールスルーします。そのため両方のページが定義するキーは新しいテキストを表示し、ロケール切り替え後は、アンマウントされるまで自身のキーが生のまま表示されます。

### `<i18n-switcher>` と `<i18n-link>` {#&lt;i18n-switcher>-and-&lt;i18n-link>}

- **スイッチャーのリンクのクリックは 1 回のナビゲーションです。** `NuxtLink` とクリックハンドラーではなく、`$switchLocale` を呼び出す素の `<a>` なので、`router-link-active` クラスはなくなりました。`href` は引き続き `app.baseURL` を含み、現在のロケールのリンクは引き続き `aria-current="page"` を持ちます。Ctrl/cmd クリックは新しいタブを開き、このタブには影響しません。リンクはクエリとハッシュを保持します。
- ボタンは `type="button"` なので、周囲のフォームを送信しなくなり、`aria-expanded` を持ちます。`aria-haspopup` はモジュール、`@i18n-micro/vue`、`@i18n-micro/astro` でなくなりました: メニューを約束していましたが、リストはリンクだからです。Escape と外側のクリックでドロップダウンが閉じ、2 つのスイッチャーが同時に開いたままになることはなくなりました。
- ラッパーとドロップダウンには `i18n-switcher-wrapper` と `i18n-switcher-dropdown` クラスがあります。ボタンには `language-switcher` に加えて `i18n-switcher-button` があり、そのラベルは `<span>` に入ります。デフォルトのスタイルは論理 CSS プロパティ(`inset-inline-start`、`margin-inline-start`)を使用し、キャレットは `▾` です。ドロップダウンは `z-index: 1000`(以前は 10)、`min-width: 150px`、`box-shadow` を持ち、ラッパーは `vertical-align: middle` を持ちます。各リンクは `lang` を持ち、ロケールが設定していれば `dir` も持ちます。
- `<i18n-link>`: `https://`、`mailto:`、`tel:` は大文字小文字を問わず一致します(`HTTPS://x.com`、`Mailto:`)。素の `report.pdf` や `index.html` は `https://report.pdf` ではなくルートです。`example.com` と `example.com:8080` は外部のままです。TLD でもあるファイル末尾(`example.md`、`x.zip`)はファイルとして扱われます: `https://` を記述してください。`activeStyle` は末尾のスラッシュ、クエリ、ハッシュを無視します。型が `CSSProperties` になったため、一部の型付きの値は変更が必要になる場合があります。

### フック、プラグイン、型 {#hooks-plugins-and-types}

- **`i18n:register` は起動時に `app:created` で実行されます。** プラグインの間ではなく、すべてのプラグインの後です。`order` が 1 より大きいプラグインや `enforce: 'post'` のプラグインは、起動時にもサブスクライバーが呼び出されるようになりましたが、自身の `setup` で登録されたキーを読み取ることはできなくなりました。ナビゲーションでは、フックは他のプラグインの `router.beforeEach` ガードより前に実行されるようになりました。
- **`i18n:register` は埋めるページのロケールを受け取ります。** `hashMode` では、ロケールを変更するナビゲーションが以前は古いロケールを渡しており、キーが誤ったチャンクに入っていました。
- **`i18n:register` はランタイムフックです:** プラグイン内で `@ts-expect-error` なしに `nuxtApp.hook('i18n:register', …)` で登録してください。[フック](/jp/api/events)をご覧ください。
- **`hooks: false` と `define: false`** は引き続きそれぞれの部分を無効にします。
- **`plugin: false` の場合、`$defineI18nRoute` は呼び出し可能なままで**、実行時には何もしません。以前はページをクラッシュさせていました。
- `hooks` オプションは `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch` をドキュメント化しなくなりました。これらは一度も発行されていませんでした。
- ページ内の `const { $defineI18nRoute } = useNuxtApp()` は、変数を使う設定でも機能するようになりました。
- `useI18n()` のキーが増えました: `clearCache`、`pluralFunc`、`pluralLocale`。`clearCache` は型にも含まれます。
- `$getRouteName(route)` は与えられたルートについて答えます。以前は空文字列を返していました。
- `useI18nLocale()` から `getLocaleWithServerFallback(serverLocale)` が削除されました: `getPreferredLocale() ?? serverLocale ?? null` と記述してください。
- **開発環境のサーバーでは `$getI18nConfig()` は読み取り専用です。** そこでの書き込みは例外を投げます。本番環境ではすべてのリクエストに影響してしまうためです。

### サーバー、ビルド、デプロイ {#server,-build-and-deployment}

- **ページのペイロードファイルは、ロケールのルートとの差分のみを保持します。** クライアントはルートを 1 回読み込み、各ページをその上にマージするため、ディスクと Edge のバンドルが小さくなり、2 ページ目のコストは 1 ページ目のごく一部になります。`premerged` は `__root/<locale>/data.json` を書き込むようになり、`/_locales/<page>/<locale>/data.json` は差分のみを保持します: これらのファイルを直接読み取るものは 2 つをマージする必要があります。完全な辞書も引き続き有効なファイルなので、それを提供するホストや `source` モードは引き続き機能します。
- **辞書ファイルはバージョンでキャッシュされます。** 現在の `?v=` を持つ URL は Node サーバーで 1 年間固定され、その他の URL は再検証され、ホストの静的コピーは `max-age=60` を返します: [キャッシュヘッダー](/jp/guide/deployment#cache-headers-and-datebuild)をご覧ください。`httpCacheControl: false` は `max-age=0` を維持します。再ビルドなしで変更された翻訳は、`v` が変わったときにのみブラウザに届きます: `NUXT_I18N_DATE_BUILD` を設定してください。
- **辞書は `app.cdnURL` に従います。** ブラウザは公開ペイロードファイルを、以前の `app.baseURL` ではなく `<cdnURL>/_locales/...` から取得します: CDN は `_locales/` を保持し、サイトのオリジンを許可する(CORS)必要があります。[アプリの baseURL とペイロードホスト](/jp/guide/deployment#app-baseurl-and-payload-hosts)をご覧ください。
- **SSR は HTTP 経由で `/_locales` をリクエストしなくなりました。** そのため、そのルート上のサーバーミドルウェアやログはレンダリングの読み取りを見なくなります。外部の `apiBaseServerHost` は引き続き HTTP 経由です。
- **失敗した読み取りは保持されなくなり、404 も同様です。** ホストからの 404 は、そのようなファイルがないことを意味します: レンダリングはブラウザと同様にルート辞書を表示し、何も保持されず、ファイルが現れた時点で読み取られます。その他の失敗、JSON オブジェクトでない 200、または読み取れないか破損したローカルファイルはキャッシュに入らず、次のリクエストで再度読み取られます: ページのレンダリングは警告をログに出し、生のキーを表示し、`no-store` と `Retry-After` 付きで `503` を返すため、ルートルールや CDN は何も保持せず、ブラウザはハイドレーション時に引き続き辞書を読み取ります。`/_locales/...` は `no-store` 付きで `503` を返し、`useTranslationServerMiddleware` はキーまたはデフォルトを返す `t` を提供します。障害中はすべてのリクエストがホストに届き、60 秒間レスポンスヘッダーを送らないホストは読み取りに失敗します。大きなファイルの遅いダウンロードには制限がありません。[辞書を読み取れない場合](/jp/guide/deployment#when-a-dictionary-cannot-be-read)をご覧ください。`/_locales` もその 404 をそのまま返します。以前は `200 {}` を返していました。
- **辞書を読み込めないプリレンダリングは失敗します。** ホストがページのファイルもルートファイルも持たない場合も同様です。ルートは 500 になり、警告がロケールとページを示し、ファイルは書き込まれません。Nuxt のデフォルトの `failOnError` では、ビルドは 1 で終了します。ルートファイルの上に独自のファイルを持たないページは、ルートでプリレンダリングされます。
- **ビルド時に設定されたホストが SSR に応答します。** デフォルトの公開コピーでも、内部パスのエラーページでも同様です。以前は公開ファイルが応答していました。実行時の `NUXT_I18N_APP_BASE_SERVER_HOST` は `/_locales` とサーバーローダーに届くようになり、レンダリングはそのローダーを通じてどちらのホストも読み取ります。
- **カスタムの `nitro.output.publicDir`、および `public/` がサーバーの隣にないその他のレイアウトでは、ペイロードが埋め込まれます。**
- **`nuxi build --preset <static preset>` は `nuxi generate` と同様にプリレンダリングするため、** より多くのファイルを書き込む場合があります。`nuxi generate` は、ルートルールが `prerender: false` を設定しない限り、リンクされているかどうかにかかわらず、すべての静的ページをそれを提供する各ロケールでプリレンダリングします。
- **静的出力での `source` または `publicAssets: false` は警告を出します。** ブラウザが読み取るものがないためです。
- **埋め込みの警告はサイズチェックになりました。** ビルドはプラットフォームの制限を超えた場合にのみ警告します: [バンドルの制限](/jp/guide/deployment#bundle-limits-on-edge)をご覧ください。
- **訪問者が決定する場所ではどこでも `Vary` が設定されます:** `no_prefix` のすべてのページ、および `/` とその他の設定によってリダイレクトしうる URL です。Cookie を使用している場合は `Cookie` を、`autoDetectLanguage` の場合は `Accept-Language` を含みます。CDN のキャッシュキーを確認してください: [HTML のキャッシュ](/jp/guide/deployment#caching-html)をご覧ください。
- **`/_locales` のキャッシュが変わりました。** `/{apiBaseUrl}/**` には Nitro のルートキャッシュがなく、`s-maxage=60, stale-while-revalidate` ヘッダーはなくなりました。そのキャッシュに依存していた場合は、ペイロードルートの前に CDN を置いてください。空の辞書が `immutable` になることはありません。
- **サーバーキャッシュはデフォルトで上限があります:** `cacheMaxSize` が未設定の場合、最大 1000 エントリです。`cacheTtl` はエントリが保存された時点から数えられ、読み取りで延長されなくなりました。
- **新しいオプションの [`cacheStorage`](/jp/guide/performance#shared-cache-for-several-instances):** 複数のインスタンスが共有する辞書キャッシュです。未設定の場合は何も変わりません。

## v2 から v3 へ {#from-v2-to-v3}

### 削除されたオプション {#removed-options}

```diff
 i18n: {
-  includeDefaultLocaleRoute: true,
+  strategy: 'prefix',
-  fallbackRedirectComponentPath: '~/components/MyRedirect.vue',
-  experimental: { hmr: true, previousPageFallback: true },
+  hmr: true,
 }
```

- `includeDefaultLocaleRoute: true` は `strategy: 'prefix'` です。`false` はデフォルトの `prefix_except_default` です。
- `fallbackRedirectComponentPath` はなくなりました: リダイレクトはレンダリング前のサーバーとクライアントのルートミドルウェアで行われます。カスタムのリダイレクトロジックはロケールを設定するプラグインに入れてください。[カスタムロケール検出](/jp/guide/custom-auto-detect)をご覧ください。
- `experimental.hmr` はルートの `hmr` オプションです(デフォルトで有効)。
- `previousPageFallback` はなくなりました: 離れるページのキーは、オプションなしでトランジションが終わるまで解決されます。

### ロケールステート {#locale-state}

`useState('i18n-locale')` と `useCookie('user-locale')` の代わりに `useI18nLocale()` を使用してください:

```diff
- useState('i18n-locale').value = 'fr'
- useCookie('user-locale').value = 'fr'
+ useI18nLocale().setLocale('fr') // state and cookie together
```

### 実行時の設定 {#config-at-runtime}

ランタイムオーバーライドを含む設定は `$getI18nConfig()` で読み取ってください:

```diff
- const cookieName = useRuntimeConfig().public.i18nConfig?.localeCookie
+ const { $getI18nConfig } = useNuxtApp()
+ const cookieName = $getI18nConfig().localeCookie
```

### 内部型エイリアス {#internal-type-aliases}

IDE や `vue-tsc` が `#i18n-internal/*` のインポートを解決できない場合は、`package.json` でマッピングしてください。Nuxt はビルド時にそれらを解決するため、これが必要になることはまれです:

```json
{
  "imports": {
    "#i18n-internal/plural": "nuxt-i18n-micro/internals",
    "#i18n-internal/strategy": "nuxt-i18n-micro/internals",
    "#i18n-internal/config": "nuxt-i18n-micro/internals"
  }
}
```
