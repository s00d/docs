description: "ページや API リクエストのロケールがどのように選ばれるか: URL、クエリ、ステート、Cookie、Accept-Language、デフォルト、そして訪問者がリダイレクトされるタイミング。"
---

すべてのリクエストには 1 つのロケールが割り当てられ、サーバーでもブラウザでも同じソースのリストから同じ順序で選ばれます。初めての訪問者をどの言語に着地させるか、選択を記憶するかどうか、サーバー API に何が見えるかを決めるときにこのページをお読みください。優先順位、各戦略が行うリダイレクト、そして各ソースをオン/オフするオプションを説明します。

<Tip>

**前提条件** — [ルーティング戦略](/jp/guide/strategy)

</Tip>

## 優先順位 {#the-precedence}

**有効な**ロケールを指定する最初のソースが採用されます。無効または不正な値(未知のコード、壊れた Cookie)はスキップされ、次のソースが評価されます。

| # | ソース | 評価される条件 |
| --- | --- | --- |
| 1 | URL プレフィックス(`/de/about`) | プレフィックス戦略。`prefix_except_default` と `prefix_and_default` では、プレフィックスのない URL はデフォルトロケール |
| 2 | `?locale=de` | ページ: `no_prefix` のみ。サーバー API ヘルパー: 常に、かつ URL より先 |
| 3 | アプリが設定したロケールステート(`useI18nLocale().setLocale()`) | URL にロケールがない場合 |
| 4 | Cookie | [`localeCookie`](/jp/api/module-options#localecookie) が設定されている場合(`no_prefix` では自動的に `'user-locale'`) |
| 5 | `Accept-Language` ヘッダー | [`autoDetectLanguage`](/jp/api/module-options#autodetectlanguage) が `true`(デフォルト)の場合 |
| 6 | [`defaultLocale`](/jp/api/module-options#defaultlocale) | 常に |

つまり、プレフィックス戦略ではページの表示内容は URL が決めます。設定ソース(3–5)は訪問者がどこに**リダイレクト**されるかだけを決め、それも `autoDetectPath` が許可するパスに限られます。`no_prefix` ではリダイレクト先がないため、設定ソースがページの表示内容を決めます。

![判定フロー: URL にロケールプレフィックスがあればそのロケールでレンダリングする。ない場合、no_prefix は設定ソースからレンダリングし、prefix_and_default はデフォルトロケールでレンダリングし、prefix または prefix_except_default は autoDetectPath がそのパスを許可する場合に設定に基づいてリダイレクトする](/images/diagrams/locale-detection.svg)

## 戦略ごとのリダイレクト {#redirects-per-strategy}

リダイレクトは `302` で、ページのレンダリング前にサーバーで行われ、クライアントナビゲーションではルートミドルウェアによって行われます。クエリとハッシュは保持されます。[`redirects: false`](/jp/api/module-options#redirects) の場合はリダイレクトは一切行われませんが、誤ったプレフィックスは引き続き 404 になります。

訪問者が `de` を優先(Cookie またはヘッダー)、`defaultLocale: 'en'`、デフォルトの `autoDetectPath: '/'` の場合:

| リクエスト | `prefix_except_default` | `prefix` | `prefix_and_default` | `no_prefix` |
| --- | --- | --- | --- | --- |
| `/` | → `/de` | → `/de` | `/` を `en` で | `/` を `de` で |
| `/about` | `/about` を `en` で | → `/de/about` | `/about` を `en` で | `/about` を `de` で |
| `/fr/about` | `/fr/about` | `/fr/about` | `/fr/about` | — |
| `/en/about` | 404 | `/en/about` | `/en/about` | — |

`prefix_and_default` はリダイレクトしません。プレフィックスのない URL はデフォルトロケールに属し、他のロケールはそれぞれのプレフィックスの下にあります。`en` を優先する訪問者は、`prefix_except_default` では `/` からリダイレクトされません。リダイレクト先には末尾のスラッシュが付かず(`/de/` ではなく `/de`)、カスタムパスに従います(`/about` → `/de/ueber-uns`)。

Cookie またはヘッダーが決定する場合(`/` からのリダイレクト、`no_prefix` のすべてのページ)、レスポンスには `Vary: Cookie, Accept-Language` が付与されるため、CDN は応答を区別して保持します。

### `autoDetectPath` {#autodetectpath}

設定ソースが訪問者を移動させてよい場所:

| 値 | 設定が評価される場所 |
| --- | --- |
| `'/'`(デフォルト) | `/` のみ。ディープリンクは URL の言語のまま |
| `'no_prefix'` | ロケールプレフィックスのないすべてのパス(`/about` → `/de/about`) |
| `'/welcome'` | その正確なパス(末尾のスラッシュは無視) |
| `'*'` | プレフィックス付きを含むすべてのパス: 訪問者が `de` を優先する場合、`/about` と `/fr/about` → `/de/about` |

- 許可されていないパスでは、プレフィックスのない URL はデフォルトロケールとして扱われます。
- `prefix` は例外です。プレフィックスのないページがないため、`/about` は常に訪問者のロケールに移動します(Cookie が `de` なら `/de/about`、設定がなければ `/en/about`)。
- `'*'` の場合、サーバーはアプリのステートを無視し、プレフィックス付き URL は自身のロケールを Cookie に記録しなくなります。Cookie は訪問者が `$switchLocale` で切り替えたときに変わります。

<Warning>

`'*'` では、共有されたリンクが閲覧者の言語で開かれるため、驚かれることがあります。それが意図したものでない限り、`'/'` または `'no_prefix'` を推奨します。

</Warning>

## Accept-Language {#accept-language}

ヘッダーは RFC 9110 の定義どおりに読み取られ、設定内のロケール**コード**と照合されます:

- エントリは `q` 値の高い順に試されます(`fr;q=0.1, de;q=0.9` → `de`)。`q=0` は「この言語ではない」を意味し、`q` が不正なエントリは無視されます。`*` は何にも一致しません。
- `_` は `-` として読まれます(`en_US` = `en-US`)。
- エントリごとに: 完全一致のコード、次に短い形式(`de-AT` → `de`)、次に同じ言語の地域ロケール(`en` → `en-US`)。完全一致と短い形式は `locales` の順序に依存しません。複数の地域ロケールが一致する場合は、`locales` 内で最初のものが採用されます。
- 文字体系は決して跨ぎません: `zh-TW` と `zh-HK` は繁体字、`zh-CN` は簡体字を意味するため、`zh-CN` が `zh-Hant` ロケールに一致することはありません。
- 無効化されたロケールは一致しません。

```ts
// locales: [{ code: 'en' }, { code: 'de' }, { code: 'zh-Hant' }]
// 'de-CH,de;q=0.9,en;q=0.8'  → 'de'
// 'en-GB'                    → 'en'
// 'zh-TW'                    → 'zh-Hant'
// 'zh-CN'                    → no match, next source
```

ヘッダーによる検出は `autoDetectLanguage: false` で無効にできます。Cookie とステートは引き続き評価されます。

## Cookie {#the-cookie}

- プレフィックス戦略では**デフォルトでオフ**です(`localeCookie: null`)。その場合リダイレクトはヘッダーのみで動作し、選択は訪問をまたいで記憶されません。記憶するには `localeCookie: 'user-locale'` を設定してください。
- `no_prefix` では、別の名前を設定しない限り `'user-locale'` です。`localeCookie: null` でここでもオフにできます。
- 訪問者が切り替えたとき(`$switchLocale`、`<i18n-switcher>`、`useI18nLocale().setLocale()`)、およびプレフィックス付きページのサーバーレンダリング時に書き込まれます(`/fr/about` は `fr` を保存。ただし、URL がまだ移動しうる、リダイレクト有効の `autoDetectPath: '*'` では保存しません)。ページへのクライアントナビゲーションでもそのページのロケールが保存され、デフォルトロケールのプレフィックスなしページでも同様ですが、その URL の初回読み込みでは保存されません。`no_prefix` とハッシュモードでは、ナビゲーションは変更のみを保存します。404 は何も保存しません。ただし `$switchLocale` で 404 に着地した場合は除きます。
- 有効期間は 1 年です(`path=/`、`SameSite=Lax`)。
- `hashMode` では、設定は代わりに `hash-locale` Cookie に保存され、サーバーとクライアントは同じものを読み取ります。サーバーはそのロケールでレンダリングし、`prefix` 以外ではリダイレクトしません。ハッシュ内のロケール(`/#/de`)がそれより優先され、ハイドレーション直後に適用されます。`prefix` では `/` にページがないため、`/` はブラウザでレンダリングされ、Cookie、次にブラウザの言語(`autoDetectLanguage`)に従って `/#/de` に移動します。その他のドキュメント(`/about`、`/de`)はハッシュにリダイレクトされます。

設定の読み取りと設定には、`useCookie` や `useState` を直接使うのではなく、[`useI18nLocale`](/jp/composables/useI18nLocale) を使用してください。

## 独自の検出 {#your-own-detection}

ロケールを自分で選ぶ(ユーザー設定、サブドメインなど)には、モジュールのプラグインより前に実行されるプラグイン内で `useI18nLocale().setLocale(code)` を呼び出します。これがソース 3(アプリのステート)になります。組み込みの検出を無効にする方法を含む完全な手順は[カスタムロケール検出](/jp/guide/custom-auto-detect)にあります。

## サーバー API ルート {#server-api-routes}

[`useLocaleServerMiddleware`](/jp/guide/server-side-translations) と `useTranslationServerMiddleware` は、API の URL がローカライズされることはまれなため、独自の順序を使用します:

1. `?locale=`
2. `[locale]` ルートパラメータ、またはパス内のロケールプレフィックス
3. Cookie(`localeCookie` が設定されている場合)
4. `Accept-Language`(`autoDetectLanguage` が有効な場合)
5. `defaultLocale`

`localeCookie: null` と `autoDetectLanguage: false` は、ここでもソース 3 と 4 を無効にします。

## ランタイムオーバーライド {#runtime-overrides}

[ランタイムオーバーライド](/jp/guide/runtime-overrides)は、ソースが照合されるリストを変更します:

- ランタイムの `disabledLocales` はすべてのステップから除外されます: それを指定する Cookie やヘッダーはスキップされます。
- ランタイムの `defaultLocale` は、`prefix` と `no_prefix` ではステップ 6 になります。
- `prefix_except_default` と `prefix_and_default` では、デフォルトロケールはビルド時に固定されます(そのページがプレフィックスなしのルートであるため)。ランタイムの `defaultLocale` や、ビルド時のデフォルトの無効化は警告とともに無視されます。
