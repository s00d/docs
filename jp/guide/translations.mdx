title: "翻訳ファイル"
description: "翻訳キーの置き場所、ルートファイルとページファイルがフォールバックとどう組み合わさるか、そしてページが辞書をどう読み込むか。"
---

翻訳はプレーンな JSON ファイルです: 共有キー用にロケールごとに 1 つのルートファイル、そしてそのページのキー用にページとロケールごとに 1 つのファイルがあります。ページを追加するとき、ページ間でキーを共有するとき、フォールバックを設定するときにお読みください。キーをどのファイルに置くべきか、ページから何が見えるか、各ファイルがいつ読み込まれるかがわかります。

## レイアウト {#layout}

```text
locales/
├── en.json                 # root: menus, footer, buttons
├── de.json
└── pages/
    ├── index/              # pages/index.vue
    │   ├── en.json
    │   └── de.json
    ├── about/              # pages/about.vue
    │   ├── en.json
    │   └── de.json
    └── products-id/        # pages/products/[id].vue
        ├── en.json
        └── de.json
```

- `locales/pages/` 配下のフォルダー名は、ページの Nuxt **ルート名**です: `pages/products/[id].vue` は `products-id`、`pages/blog/[slug]/comments.vue` は `blog-slug-comments` です。
- キーは任意の深さでネストできます。`$t('auth.form.login')` は `{ "auth": { "form": { "login": … } } }` を読み取ります。
- `translationDir` でフォルダーを移動できます(デフォルトは `'locales'`。プロジェクトルートからの相対パスで、Nuxt 4 の `app/` レイアウトでも同様)。
- [`disableWatcher`](/jp/api/module-options#disablewatcher) が設定されていない限り、Nuxt がページを解決する際に、存在しないファイルは `{}` として作成されます。

## ページから見えるもの {#what-a-page-sees}

![Lookup order for a key on /about in de: pages/about/de.json, de.json, pages/about/en.json, en.json. They merge into one about/de/data.json that $t reads](/images/diagrams/page-dictionary.svg)

ページの辞書は、ルートファイルとページファイルを深く(すべての階層で)マージしたものです。衝突した場合はページファイルが優先されます:

```json
// locales/en.json
{ "title": "My shop", "nav": { "home": "Home", "cart": "Cart" } }
```

```json
// locales/pages/about/en.json
{ "title": "About us", "nav": { "cart": "Basket" } }
```

```ts
// on /about
t('title') // 'About us'
t('nav.home') // 'Home'   (root)
t('nav.cart') // 'Basket' (page wins)
// on any other page
t('title') // 'My shop'
```

独自のフォルダーを持たないページには、ルートの辞書だけが与えられます。他のページのキーは見えません。

### フォールバックロケール {#fallback-locales}

アクティブなロケールに存在しないキーは、キーそのものを表示する前に、フォールバックロケールから取得されます:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'de-at', iso: 'de-AT', fallbackLocale: 'de' },
    ],
    defaultLocale: 'en',
    fallbackLocale: 'en', // global, for every locale
  },
})
```

- ロケール自身の `fallbackLocale` は最後までたどられます: `de-at` → `de` → `en`。
- グローバルな `fallbackLocale` は最も弱いレイヤーで、すべてのチェーンの下に位置します。
- チェーン内の各ロケールは、最も弱いフォールバックからアクティブなロケールに向かって、ルートファイル、次にページファイルの順に追加されます。そのため、アクティブなロケールのルートファイルはフォールバックロケールのページファイルより優先されます。

フォールバックがない場合、存在しないキーはキーそのもの(`'nav.home'`)としてレンダリングされ、開発時にはブラウザーのコンソールに警告が出力されます([`missingWarn`](/jp/api/module-options#missingwarn))。

## 共有とその他のソース {#sharing-and-other-sources}

| 必要なこと | オプション |
| --- | --- |
| ルートファイルのみで、`pages/` フォルダーを使わない | [`disablePageLocales: true`](/jp/api/module-options#disablepagelocales) |
| 2 つのページが 1 つのページフォルダーを読み込む | [`routesLocaleLinks`](/jp/api/module-options#routeslocalelinks): `{ 'about-us': 'about' }` |
| 別のフォルダーにある共有ルートファイル | [`additionalTranslationDirs`](/jp/api/module-options#additionaltranslationdirs): `['common']`(メインの `translationDir` が優先) |
| Nuxt レイヤーからのキー | レイヤーのファイルがマージされ、プロジェクト自身のファイルが優先されます。[レイヤー](/jp/guide/layers)を参照 |
| ランタイムで追加されるキー | [`i18n:register`](/jp/api/events) フック、`$mergeTranslations`、`$setTranslation` |
| ページコンポーネント内にインラインで書くキー | `$defineI18nRoute({ locales: { en: { … } } })`。[ページ設定](/jp/guide/per-component-translations)を参照 |

## ページが辞書を読み込む仕組み {#how-a-page-loads-its-dictionary}

![Locale JSON files are built into a payload tree, stored in public/ on Node or in server assets on Edge, read by a server loader, then used by $t on the server and fetched for $t in the browser](/images/diagrams/translation-pipeline.svg)

モジュールはページとロケールごとに 1 つのペイロードを構築します: `/{apiBaseUrl}/{page}/{locale}/data.json`(デフォルトでは `/_locales/about/de/data.json`)。

1. **サーバーレンダリング。** Nitro がロケールを検出し、ページは HTTP リクエストなしでサーバーローダーから直接ペイロードを読み込みます。辞書は HTML ペイロードに書き込まれないため、ページは小さいままです。
2. **ハイドレーション。** ブラウザーは同じペイロードを取得します。サーバーはすでにそのための `<link rel="preload">` を出力しているため、取得は HTML と同時に始まります。
3. **ナビゲーション。** 次のページのペイロードが辞書を置き換えます。離れるページのキーは、そのページがなくなるまで(ページトランジションの終了、または `page:finish`)解決され続けるため、フェードアウト中のページに生のキーが一瞬表示されることはありません。読み込みに失敗したチャンク(ネットワークエラー、4xx や 5xx、オブジェクトでないボディ)は現在の辞書をそのまま残し、次のナビゲーションで再度読み込まれます。ロケール切り替えの失敗も同様です: `$switchLocale` は `false` で解決され、もう一度呼び出すかスイッチャーをもう一度クリックすると再試行されます。プレフィックス戦略ではその時点で URL がすでに移動しているため、古いテキストが画面に残る一方で、`lang` と `$getLocale()` は URL のロケールを示します。
4. **キャッシュ。** 読み込まれたペイロードはサーバーとブラウザーでキャッシュされます。サイズと TTL の設定は[パフォーマンス](/jp/guide/performance)にあります。

`translationPayloads.mode` はペイロードの構築方法を決めます。`'premerged'`(デフォルト)はビルド時にページ × ロケールのすべてのファイルを書き出します。`'source'` はソースファイルを保持してリクエストごとにマージするため、Edge ターゲットの大規模なカタログではサイズが小さくなります。どちらも同じ辞書を生成します。デプロイ先ごとにファイルがどこに配置されるかは[デプロイ](/jp/guide/deployment)にあります。

## 開発中の編集 {#editing-in-development}

`nuxt dev` はファイルをライブで読み込みます。翻訳ファイルを保存すると、開いているページの辞書がその場で更新されます: リロードは不要で、削除されたキーは消え、ルートファイルの変更はすべてのページに反映されます。壊れた JSON ファイルはそのパスとともに警告を出力し、空として扱われます。手動で更新したい場合は [`hmr: false`](/jp/api/module-options#hmr) を設定してください。
