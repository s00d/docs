`strategy` オプションは、URL にロケールを含めるかどうか、およびどのロケールで含めるかを決めます。URL を公開する前に一度だけ選んでください。後から変更するとすべてのリンクが変わります。モジュールはビルド時にローカライズされたルートを生成し、`$localePath`、`<i18n-link>`、スイッチャーがそれを読み取ります。

## 4 つの戦略 {#the-four-strategies}

![各戦略における en(デフォルト)と de の /about ページ。同じ URL は以下の本文に記載されています](/images/diagrams/strategies.svg)

**型** `Strategies` · **デフォルト** `'prefix_except_default'`

ロケールプレフィックスの URL ルーティング戦略。

- `'no_prefix'` — URL にロケールを含めない。ロケールは Cookie に保存される。
- `'prefix_except_default'` — デフォルト以外のすべてのロケールにプレフィックスを付ける。
- `'prefix'` — デフォルトロケールを含め、常にプレフィックスを付ける。
- `'prefix_and_default'` — `prefix` と同様だが、デフォルトロケールはプレフィックスなしでもアクセスできる。

`defaultLocale: 'en'` とロケール `en`、`de` の場合の `about` ページの URL:

| 戦略 | 英語 | ドイツ語 | 提供されないもの |
| --- | --- | --- | --- |
| `prefix_except_default`(デフォルト) | `/about` | `/de/about` | `/en` と `/en/about` は 404 |
| `prefix` | `/en/about` | `/de/about` | `/about` はプレフィックス付き URL にリダイレクト |
| `prefix_and_default` | `/about` と `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | ロケールは URL に含まれない |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

戦略はビルド時に固定されます。ランタイムでのオーバーライドは警告とともに無視されます([ランタイムオーバーライド](/jp/guide/runtime-overrides))。

## どれを選ぶか {#which-one-to-choose}

- **`prefix_except_default`**: ほとんどのサイト向け。既存のプレフィックスなし URL はデフォルト言語でそのまま機能します。
- **`prefix`**: すべての言語が対等です。`/` は常にプレフィックス付きのホームに移動します。
- **`prefix_and_default`**: 一方から他方へ移行する間など、`/en/...` とプレフィックスなし URL の両方を機能させる必要がある場合。プレフィックスなし URL はリダイレクトされません。
- **`no_prefix`**: ログインが必要なアプリや、すべての言語でページごとに 1 つの URL にしたい場合。ロケールは Cookie または `?locale=` から取得されます。検索エンジンには URL ごとに 1 つの言語しか見えないため、`hreflang` の代替リンクは出力されません。

URL に対してロケールがどのように選ばれるか、訪問者がいつリダイレクトされるかは[ロケール検出](/jp/guide/locale-detection)をご覧ください。

## 生成されるルート {#generated-routes}

ビルド時に、各ページにはその戦略が必要とするルートレコードが付与されます。各レコードは `meta.i18n = { name, locales }`(表示するページと提供するロケール)を持ちます。リンク、切り替え、リダイレクトはすべてこれらのレコードから解決されるため、モジュールが渡す URL は常にルーターが提供する URL です。

ページのパスを共有するロケールは 1 つのレコード `/:locale(de|fr)/about` を共有します。独自のパスを持つロケールは `localized-<page>-<locale>` という名前の独自のレコードを持ちます:

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

カスタムパス、ページごとのロケールリスト、ページのローカライズからの除外については、[ローカライズされたパス](/jp/guide/custom-locale-routes)と[ページ設定](/jp/guide/per-component-translations)をご覧ください。`localized-` プレフィックスは [`localizedRouteNamePrefix`](/jp/api/module-options#localizedroutenameprefix) です。

<Warning>

**ルート名は生成されます** — `router.push({ name })` に `localized-…` という名前をハードコードしないでください。ページ自身の名前を `$localeRoute` または `<i18n-link>` に渡せば、適切なレコードが選ばれます。

</Warning>

## ロケールのページへのリンク {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- 名前付きルートとパスの両方が機能します。パスは生成されたルートと照合されるため、どのロケールの形式でも受け付けられます。
- そのページを提供しないロケール([ページ設定](/jp/guide/per-component-translations)の `locales` を参照)は、存在しないページの代わりにそのロケールのホームにリンクします。
- ロケールごとのパラメータ(翻訳されたスラッグ)は `$setI18nRouteParams` を使用します。[ローカライズされたパス](/jp/guide/custom-locale-routes)をご覧ください。

シグネチャは[メソッド](/jp/api/methods)にあります。

## `no_prefix` の詳細 {#no_prefix-details}

- `no_prefix` では [`localeCookie`](/jp/api/module-options#localecookie) のデフォルトが `'user-locale'` なので、選択はリロード後も保持されます。
- `$switchLocale('de')` はドイツ語の辞書を読み込み、現在の履歴エントリを置き換えます。URL は変わりません。
- ロケールごとのカスタムパスは引き続き機能します: `globalLocaleRoutes: { about: { de: '/ueber-uns' } }` の場合、ドイツ語の読者は `/ueber-uns` を得ます。その URL は訪問者の設定にかかわらず常にドイツ語でレンダリングされ、一部のロケールに限定されたページはそのいずれかでレンダリングされます。複数のロケールが共有するパス(`en` と `de` の両方が `/page/:id`)は、設定がそのいずれかであれば設定のロケールでレンダリングされます。設定自体は維持され、次のページではそれに戻ります。
- [`noPrefixRedirect: true`](/jp/api/module-options#noprefixredirect) は、デフォルトロケールでカスタムパスを持つページの元のパスを、訪問者のロケールのカスタムパス、なければデフォルトロケールのカスタムパスにリダイレクトします(`en` が `/about-us` を持つ場合 `/about` → `/about-us`、Cookie が `de` なら → `/ueber-uns`)。独自のカスタムパスを持たないロケールは元のパスに留まり、そこでレンダリングされます。パラメータを持つページはリダイレクトされません。

## `pages/` のないアプリ {#apps-without-pages/}

`pages: false` の場合、ローカライズするページルートはありません。ルートの翻訳ファイルのみを使用してください(`disablePageLocales: true`)。検出、Cookie、`$switchLocale` は引き続き機能します。リポジトリ内の `test/fixtures/basic` の `pages-false` バリアントが動作する構成例です。
