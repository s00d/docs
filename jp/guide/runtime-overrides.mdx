---
title: "ランタイムオーバーライド"
description: "環境変数または runtimeConfig を使って、1 つのビルドのインスタンスごとにデフォルトロケール、フォールバックロケール、無効化ロケールを変更します。"
---

ランタイムオーバーライドを使うと、1 つのビルド成果物を、再ビルドせずに環境やテナントごとに異なるロケール設定で実行できます。デフォルトロケール、フォールバックロケール、無効化するロケールを変更できます。ルーティング、リダイレクト、レンダリング、サーバーヘルパーはオーバーライドされた値を使用し、サーバーレンダリングされたページではブラウザーも同様です。

## 環境変数でオーバーライドを設定する {#set-overrides-with-environment-variables}

```bash
NUXT_I18N_DEFAULT_LOCALE=de \
NUXT_I18N_FALLBACK_LOCALE=en \
NUXT_I18N_DISABLED_LOCALES=fr,it \
node .output/server/index.mjs
```

| 変数 | エイリアス |
| --- | --- |
| `NUXT_I18N_DEFAULT_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE` |
| `NUXT_I18N_FALLBACK_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE` |
| `NUXT_I18N_DISABLED_LOCALES`（カンマ区切り） | `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES` |

サーバーは起動時に一度だけこれらを読み込みます。変更を適用するには再起動してください。サーバーレンダリングされたページでは、ブラウザーは解決済みの値をサーバーから受け取ります。`ssr: false` の場合はサーバーレンダリングがなく、ブラウザーには環境変数がありません。そこでは `runtimeConfig.public.i18nRuntime` のみが適用され、ブラウザーは以下の警告をログに出力します。

## runtimeConfig でオーバーライドを設定する {#set-overrides-in-runtimeconfig}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

`runtimeConfig.public.i18nRuntime` に設定した値は、同じフィールドの `NUXT_I18N_*` 変数より優先されます。

ビルド時の `DEFAULT_LOCALE` 変数と混同しないでください。こちらはビルド中に `defaultLocale` を置き換えるもので、ランタイムのサポートは必要ありません。

## 変更できるものとできないもの {#what-can-and-cannot-change}

| 設定 | 実行時 |
| --- | --- |
| `defaultLocale` | `prefix` と `no_prefix` では可能。`prefix_except_default` と `prefix_and_default` ではビルド時に固定され（そのページはプレフィックスなしのルートです）、オーバーライドは警告とともに無視されます。 |
| `fallbackLocale` | 可能。 |
| `disabledLocales` | ビルド時に無効化されたロケールに追加されます。再有効化はできません。`prefix_except_default` / `prefix_and_default` では、ビルド時のデフォルトロケールは無効化できません。 |
| `strategy` | 不可。ランタイムの戦略は警告とともに無視されます。戦略ごとに 1 つの成果物をビルドしてください。 |

無効な値でアプリが壊れることはありません。各ケースはサーバープロセスごとに 1 回警告をログに出力します:

- すべてのロケールを無効化する設定は無視されます。
- 有効になっていない `defaultLocale` は、最初に有効なロケールにフォールバックします。
- 有効になっていない `fallbackLocale` は、ビルド時の値が有効であればそれを保持し、そうでなければフォールバックはありません。

## 有効な設定を読み取る {#read-the-effective-config}

```vue
<script setup lang="ts">
const { $getI18nConfig } = useNuxtApp()
const config = $getI18nConfig() // build config with overrides applied
</script>
```

読み取り専用として扱ってください。サーバーではすべてのリクエストで共有され、開発時には凍結（freeze）されています。ブラウザー側のコピーは凍結されていません。`#build/i18n.strategy.mjs` から設定をインポートすると、オーバーライドなしのビルド時の値が得られます。

## 無効化ロケールと静的ファイル {#disabled-locales-and-static-files}

ランタイムで無効化されたロケールは、そのルートとペイロードルートで 404 を返しますが、ペイロードファイルは `.output/public/_locales/` に残っており、静的ファイルサーバーはそれらを返します。これらのファイルにアクセスできてはならない場合は、ビルド時に `disabled: true` でロケールを無効化してください。
