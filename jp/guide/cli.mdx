`@i18n-micro/cli` は Nuxt プロジェクトのロケールファイルを管理します。`nuxt.config` から `locales`、`defaultLocale`、`translationDir` とレイヤーを読み取るため、独自の設定は不要です。

![A terminal running i18n-micro check, which lists a missing, an undefined and four unused keys and fails, then extract, which adds the undefined key, then clean --dryRun, which lists the four keys it would remove](/images/cli/demo.gif)

| コマンド | 用途 |
| --- | --- |
| `check` | ロケールファイルに問題があればビルドを失敗させる |
| `translate` | 翻訳サービスで不足しているキーを埋める |
| `clean` | 何にも使われていないキーを削除する |
| `rename` | キー、または名前空間全体を、すべての箇所で一度に移動する |

```bash
npm install -D @i18n-micro/cli
npx i18n-micro --help
```

アプリのルートから実行するか、`--cwd` でルートを指定してください。すべてのコマンドのすべてのフラグは[コマンドリファレンス](/jp/api/cli)にあります。

<Tip>

**nuxt-i18n-micro-cli から移行しますか?** `@i18n-micro/cli` がそれを置き換えます。バイナリ `i18n-micro` と `i18n-micro-cli` はそのまま残ります。[旧コマンドの対応表](#moving-from-nuxt-i18n-micro-cli)を参照してください。

</Tip>

## CI で使う {#use-it-in-ci}

```bash
i18n-micro check
```

`check` はゲートです。次の内容を報告します:

| チェック | 意味 |
| --- | --- |
| `missing` | デフォルトロケールのキーがあるロケールに存在しない |
| `empty` | 値が `''` である。アプリはフォールバックではなく空白を表示する |
| `extra` | デフォルトロケールにないキーがあるロケールに存在する |
| `placeholders` | `{name}` が失われたか追加された、または複数形の形が失われた |
| `undefined` | デフォルトロケールにないキーをコードが使用している |
| `unused` | プロジェクト内のどこでもキーが使われていない |
| `duplicates` | 同じテキストが異なるキーにある。デフォルトでは無効: `--duplicates` を渡す |

- `--only missing,placeholders` は一部のチェックだけを実行します。`--only` で指定したチェックが実行できなかった場合は失敗します。
- `--json` はツール向けのレポートを出力します。
- `--ignore` はソースファイルをスキップします。
- キーが実行時に計算される場合、`unused` はスキップされ、レポートにその理由が示されます。

すべてのコマンドは 3 つのコードのいずれかで終了するため、パイプラインは翻訳の問題とツールの問題を区別できます:

| 終了コード | 意味 |
| --- | --- |
| `0` | 報告事項なし |
| `1` | 検出事項あり |
| `2` | コマンドを実行できなかった: 使い方の誤り、壊れたファイル、失敗したリクエスト |

CI ステップに加える価値のあるその他のコマンド:

```bash
i18n-micro format --check      # fails if a file is not formatted
i18n-micro lint                # stray spaces, empty values, your own regex rules
i18n-micro stats --baseRef main
```

## ロケールの足並みをそろえる {#keep-locales-in-step}

| コマンド | 動作 |
| --- | --- |
| `extract` | コードが使用しているがまだテキストのないキーを一覧表示します。`$t('key', {}, 'Welcome')` のようなデフォルトテキストはデフォルトロケールに入ります。 |
| `sync` | デフォルトロケールにないキーを削除します。まず `--dryRun` で試してください。 |
| `clean` | 何にも使われていないキーを削除します。まず `--dryRun` で試してください。 |
| `search` | キーと値を検索し、各キーが使われている場所を表示します。 |
| `stats` | ロケールごとの完成度。`--baseRef main` で git の ref と比較します。 |

`sync` は、未使用であることを証明できないキーを削除しようとする場合に `clean` と同様に停止し、デフォルトロケールに比較対象が何もない場合にも停止します。削除するものがなければ停止しないため、`$t(item.label)` があるだけでは `--force` を使う理由にはなりません。

<Note>

`extract` と `sync` は、翻訳のないキーに `''` を書き込むことはありません。キーは存在しないままなので、実行時には `fallbackLocale` が適用され、`check` がそれを報告します。空文字列は定義済みの値となり、空白が表示されてしまいます。

</Note>

### コマンドが読み取るもの {#what-the-commands-read}

`check`、`extract`、`sync`、`clean`、`search`、`rename` は、固定のフォルダー一覧ではなくプロジェクト全体のソースコードを読み取ります:

- **読み取り対象:** パーサーを通したテンプレートとスクリプト、テキストとしての `.html` と Pug、すべてのレイヤー、エイリアスや `components` が指すルート外のフォルダー。
- **スキップ対象:** `node_modules`、ビルド出力、ロケールファイル。独自の除外は `--ignore 'legacy/**,*.stories.ts'` で追加します。
- **テストコード**は使用としてカウントされるため、`clean` と `check --only unused` はテストだけが読むキーも保持します。テストコードがキーを追加することはありません。`extract` はそのようなキーをスキップし、`check` はそれらを undefined として報告しません。

テストコードとは、ルートフォルダーの `tests`、`test`、`__tests__`、`e2e`、`cypress`、`playwright` と、場所を問わない `.spec` および `.test` の JavaScript・TypeScript ファイル（`.ts`、`.tsx`、`.mts`、`.js`、`.jsx`、`.mjs` など）を指します。以下の疑わしいケースから除外されるのはルートフォルダーだけです。`pages/tests/[id].vue` は他と同じページであり、コードがアプリの一部ではない `public/` やミニファイされたファイルも同様です。

コマンドが認識するもの:

- `$t`、`$ts`、`$tc`、`$has`、`$_t(route)`
- `useI18n()` と `useTranslationServerMiddleware()` からの `t()`
- テンプレートと JSX 内の `<i18n-t keypath>`、および `<i18n-group prefix>`
- `const { t: tr } = useI18n()` のようなエイリアス

### `clean` の判断方法 {#how-clean-decides}

`clean` は、使用中のキーを削除するよりも、不要なキーを残すことを優先します。次のいずれかに該当するキーは残されます:

- 呼び出しがそのキー、またはその下位や上位のキーを使用している
- コード内の文字列がそのキーと等しい: `const key = 'menu.home'`、`<Item label="menu.home" />`
- プロジェクト内の JSON、YAML、Markdown ファイルがそのキーを含む
- 計算されるキーの静的な先頭部分がそれをカバーしている: `` $t(`status.${state}`) `` は `status.` 配下のすべてを保持する
- レイヤーがそのキーを定義している

判断できない場合、`clean` は何も変更せずに停止し、その理由を一覧表示します:

- キーが完全に計算される場合。例: `$t(name)`、`<i18n-t :keypath="name" />`、`<i18n-t v-bind="props" />`
- `$t` が値として渡される場合。例: `items.map($t)`
- `t` という名前の関数が計算された引数を受け取り、それがパラメーター、インポート、または呼び出しから来ている場合。本物の関数のラッパーである可能性があります。同じファイルで定義されている関数はカウントされません。ラッパーであれば内部に独自の呼び出しがあるはずだからです
- ソースファイルをパースできない場合
- どのファイルもキーをまったく使用していない場合。これは通常、間違った場所を探していることを意味します
- ロケールファイルがプロジェクト外へのシンボリックリンクで、他のアプリが読んでいる可能性がある場合

## 不足しているキーを翻訳する {#translate-missing-keys}

```bash
i18n-micro translate --dryRun                     # keys and characters per locale, nothing sent
export I18N_TRANSLATE_TOKEN=...                   # or put it in .env
i18n-micro translate --service deepl --locale de,fr
```

- `translate` は不足しているキーまたは空のキーを埋めます。`--replace` はすべてを翻訳し直します。
- プレースホルダーと複数形の形は保護されます。プレースホルダーが失われた翻訳は書き込まれません。そのキーは一覧表示され、コマンドは `1` で終了します。
- 各バッチは次のリクエストを送る前に保存されるため、失敗しても失われるのは失敗したリクエストの分だけです。

| `--service` | サービス | `--token` | 便利な `--options` |
| --- | --- | --- | --- |
| `ai` | Vercel AI Gateway、OpenAI、Anthropic、または任意の OpenAI 互換サーバー | API キー、または `AI_GATEWAY_API_KEY`、`OPENAI_API_KEY`、`ANTHROPIC_API_KEY` | `provider`, `model`, `baseUrl`, `maxTokens` |
| `azure` | Azure Translator | サブスクリプションキー | `region` |
| `deepl` | DeepL（Free キーを含む） | 認証キー | `formality`, `glossaryId`, `context` |
| `google` | Google Cloud Translation v2 | API キー | `model` |
| `libretranslate` | LibreTranslate | 任意 | `baseUrl` |
| `yandexcloud` | Yandex Cloud Translate | API キー、または `authScheme:Bearer` を伴う IAM トークン | `folderId`, `model` |

オプションは `key:value` のペアです: `--options provider:openai,model:gpt-4o-mini`。すべてのサービスは `baseUrl`、`retries`、`retryDelayMs`、`timeoutMs` も受け付けます。翻訳リクエストはすでに課金されている可能性があるため、再試行は `429` または `503` の後にのみ行われ、サービスが 1 分を超える待機を求めた場合は行われません。

<Warning>

フラグはシェル履歴やプロセス一覧に表示されるため、トークンは環境変数で渡してください。CLI は、秘密であると分かっているもの（トークン、プロバイダーキー、Basic 認証情報、設定した URL のクエリと認証情報）を、`--debug` を含むどこで出力する場合でもマスクします。キーを整形してからエコーするサーバーまでは対応できないため、失敗した実行のログは慎重に扱ってください。

</Warning>

`ai` サービスは用語集に従います。`.i18n-glossary.json` が存在する場合はフラグなしで使用され、`--glossaryFile` で別のファイルを選べます。

```json .i18n-glossary.json
{ "entries": [{ "source": "Cart", "target": "Warenkorb", "to": "de" }] }
```

## ハードコードされたテキストをキーに変換する {#turn-hardcoded-text-into-keys}

```bash
i18n-micro text-to-i18n --dryRun   # list what would change
i18n-micro text-to-i18n            # rewrite the templates
```

```vue
<!-- before -->
<h1>Welcome to our site</h1>
<!-- after -->
<h1>{{ $t('pages.index.welcome-to-our') }}</h1>
```

書き換えられるのはプロジェクト自体の `.vue` テンプレートだけで、レイヤーやエイリアス先のものは対象外です。書き換えられた各ファイルは、書き込む前に再度パースされます。次のものは一覧表示され、テキストはそのまま残ります:

- `.ts` ファイルやスクリプト内のテキスト。`$t` がどこでもスコープ内にあるとは限らないためです
- マークアップや補間の隣にあるテキスト（例: `<p>Hello <b>world</b> today</p>`）。文の半分だけを単独で翻訳することはできません
- 親ページとその子ページのように、生成されたキーが別のキーと衝突する場合
- 引用符の中に入れられない既知のキー

<Warning>

先にコミットし、差分を確認してください。

</Warning>

## キーの名前を変更する {#rename-a-key}

```bash
i18n-micro rename --from common.save --to actions.save
i18n-micro rename --from settings --to account.settings   # a whole namespace
```

`rename` は構文木を編集するため、コメントや無関係な文字列はそのまま残り、エイリアスや `:keypath` も追跡されます。レイヤー自身のファイルが変更されることはありません。書き換えられないものについては警告し、そのままにします:

- 旧名の下にある計算されたキー
- それと等しい各プレーン文字列
- Pug テンプレート
- レイヤー内、またはプロジェクト外のフォルダー内のソース

`--to` はコードに書けるキーでなければなりません。引用符、バックスラッシュ、空のセグメント、`__proto__` は使用できません。

## 翻訳者とファイルをやり取りする {#exchange-files-with-translators}

```bash
i18n-micro export --format csv
i18n-micro import --format csv --dryRun
```

**`export`** は、未翻訳のものを含むすべてのロケールのすべてのキーを、デフォルトロケールのテキストをソースとして書き出します。CSV では `Source` 列、PO では `#.` コメントになります。

- `--dir` を指定しない場合、PO は `pots` に、CSV は `csv_exports` に出力されます。
- 書き出した内容は出力フォルダー内の `.i18n-export.json` に記録されます。それ以降にファイルが変更され、ロケールファイルにない翻訳（fuzzy の PO エントリーを含む）を含んでいる場合は停止します。`--force` で上書きします。ロケールファイルの通常の編集では停止しません。

**`import`** はマージを行い、空のセルと `fuzzy` とマークされた PO エントリーをスキップします。

- 値を上書きしてしまうキーや、キーのグループ全体を上書きしてしまう値は一覧表示されて除外され、コマンドは `1` で終了します。
- 想定外の場所にあるカタログ、前回のエクスポートで書き出されていないページのカタログ、CSV 内の不正な位置の引用符、`disablePageLocales` 下のページエントリーがあると、終了コード `2` で停止します。

翻訳プラットフォームを使う場合は、そのプラットフォーム独自の CLI を使用してください。[Crowdin](/jp/guide/crowdin) のセットアップでは、ページファイルを含む JSON ファイルを同期します。

## 独自のエンドポイントと同期する {#sync-with-your-own-endpoint}

`sync-remote` は、グローバルなロケールファイルを自分で運用する HTTP エンドポイントとやり取りします。ページファイルはローカルに残り、コマンドもその旨を表示します。エンドポイントは `.i18n-remote.json` に記述します:

```json .i18n-remote.json
{ "url": "https://translations.example.com", "path": "translations" }
```

エンドポイントは `GET` と `PUT` に `{ locale: messages }` オブジェクトで応答します。認証は `auth: { username, password }` で行うか、Bearer トークンを `I18N_REMOTE_TOKEN` に設定してください。

| | Pull | Push |
| --- | --- | --- |
| 移動するもの | 手元にないものを埋め、手元にしかないキーは保持する | レイヤーのものではなくプロジェクト自身のキーを送信し、空白は送らない |
| 競合 | 両側で異なるキー: 何も書き込まれず、終了コード `1`。`--force` でリモートの値を採用 | PUT はドキュメントを置き換えるため、push はまずエンドポイントを読み取り、手元にないテキストが含まれていれば終了コード `1` で停止する。`--force` で上書き。`404` を返すエンドポイントには失うものがない |
| `--dryRun` | エンドポイントから読み取り、変更を一覧表示し、何も書き込まない | エンドポイントに接続せずに、送信される内容を表示する |

設定されていないロケールはスキップされ、リモートの空の値が何かを消去することはありません。

## nuxt-i18n-micro-cli からの移行 {#moving-from-nuxt-i18n-micro-cli}

| 旧コマンド | 現在 |
| --- | --- |
| `validate` | `check` |
| `diff` | `check --only missing` |
| `check-duplicates` | `check --only duplicates` |
| `export-csv`, `import-csv` | `export --format csv`, `import --format csv` |
| `--potsDir`, `--csvDir` | `--dir` |
| `estimate` | `translate --dryRun` |
| `glossary` | `.i18n-glossary.json` を編集。`translate` が自動で読み取ります |
| `backup`, `restore` | Git。すでにロケールファイルを保持しています |
| `init` | `nuxi init` の後、`modules` に `nuxt-i18n-micro` を追加 |
| `split` | 削除: モジュールは分割ファイルを読み取りません |
| `optimize` | `check --only duplicates` |
| `replace-values` | エディターまたは `sed` |
| `stats --full` | `stats`。詳細は [DevTools](/jp/guide/devtools) にあります |
| `search --hardcodedOnly` | `text-to-i18n --dryRun` |
| `search --preferUnused`, `--onlyVue` | 削除 |
| `lint` ルール `no-html-tags`, `no-special-chars`, `no-mixed-case`, `no-missing-punctuation`, `no-inconsistent-pluralization` | 削除: 通常のテキストを誤検出していました。必要な場合は `customRegexRules` のエントリーを書いてください |
| `text-to-i18n --extractOnlyDirs`, `--extractOnlyPatterns`, `--verbose` | 削除: コードが書き換えられることはありません |
| `--logLevel verbose` | 削除: 何の効果もありませんでした |

**削除されたサービス:** `googlefree`、`yandex`（`yandexcloud` を使用）、`ibm`、`lingvatranslate`、`modernmt`、`lilt`、`unbabel`、`reverso`、`baidu`、`papago`、`tencent`、`systran`、`mymemory`。

**削除された `sync-remote` のタイプ:** `github`、`gitlab`、`crowdin`、`lokalise`、`tolgee`、`weblate`。プラットフォーム独自の CLI を使うか、`custom` を使用してください（`type` はもう不要です）。

### 変更された動作 {#changed-behaviour}

- `extract` と `sync` は `''` を書き込まなくなりました。キーは存在しないままとなり、`check` がそれを報告します。`extract` は、コードがテキストを与えている場合にのみキーを書き込みます。
- `extract` はページのキーを、モジュールが読み取る `locales/pages/<route name>/` に書き込み、Nuxt 4 では `app/` をスキャンします。`pages/_about` や `pages/blog_` のようなディレクトリから内容を移動し、紛れ込んだ `locales/pages/<locale>.json` は削除してください。
- `nuxt.config` の `translationDir` が尊重されます。以前はすべてのコマンドが暗黙的に `locales` を使用していました。
- `defaultLocale` がない場合、モジュールと同じくデフォルトは `en` で、`DEFAULT_LOCALE` も尊重されます。以前は最初のロケールでした。
- `check` と `sync` はデフォルトロケールを基準として使用し、ページファイルもチェックします。`"a.b"` と `a: { b }` は 1 つのキーとして数えられます。
- `clean` は、どのスコープであれどこかで使われているキーを保持し、使用状況を証明できない場合は停止します。`--include` と `--exclude` で削除してよいものを選びます。
- `sync` も同様に停止し、デフォルトロケールに比較対象のキーがない場合にも停止します。`--force` で上書きできます。また、`DEFAULT_LOCALE` が `nuxt.config` とは別の基準を選んだ場合にも停止します。
- シングルダッシュのロングフラグや余分な引数はエラーになります: `clean -dryRun` は `clean` を実行しなくなりました。
- 読み取り専用のファイルや UTF-8 でないファイルは保存できません。コマンドは何かを変更する前に停止します。そのようなファイルの読み取りは問題ありません。重複したキー、`__proto__` という名前のキー、2^53 を超える整数は、保存時に失われるためコマンドを停止させます。
- 値を必要とするフラグの後に別のフラグが続く場合はエラーになります。ダッシュで始まる値には `--flag=--value` と書いてください。真偽値のフラグは `true` または `false` のみを受け付けます。
- `export` は、インポートされていない翻訳を上書きする代わりに停止します。
- 終了コードは `0`、`1`、`2` です。以前は失敗が `1` で、`diff` と `check-duplicates` は常に `0` でした。
- `lint --fix` は `.bak` ファイルを残さなくなりました。
- 保存時には、ファイルのインデント、改行コード、末尾の改行、シンボリックリンク、ハードリンクが維持され、変更していないファイルには手を付けません。
- 打ち間違えたフラグや削除されたフラグは、黙って無視されるのではなくエラーになりました。
- `--dir` などのパスは、シェルではなくプロジェクトからの相対パスです。
- `ai` は `@ai-sdk/*` パッケージを読み込まなくなりました。`provider` に `gateway`、`openai`、`anthropic` を指定するか、OpenAI 互換サーバーには `baseUrl` を使用してください。
