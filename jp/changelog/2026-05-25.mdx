**日付**: 2026-05-25

**バージョン**: `v3.19.0`

![v3.19.0 release](/images/3.19.0.png)

このリリースは、**内部ユーティリティのモジュール化**、**コンパクトなサーバーレス向けペイロードモード**の追加、そして Nuxt、Node、Astro、DevTools 間での**共有ロジックの再利用**に重点を置いています。一般的なアプリで使う公開モジュール API は変わりません。

## 新機能 {#what’s-new}

### `@i18n-micro/utils` — フレームワーク非依存のユーティリティ {#@i18n-micro/utils-—-framework-agnostic-utilities}

これまで `src/runtime/utils/` と `src/module.ts` に散在していた共有ロジックは、**細かなサブパスインポート**(巨大なバレルなし、ツリーシェイキングに優しい)を備えた専用のワークスペースパッケージに移りました:

- **ビルド** — `preMergeLocales`、`buildTranslationSourceLayers`(`@i18n-micro/utils/build`)
- **ペイロード** — `translationPayloads` の解決、URL 構築、fetch ヘルパー、統計(`payload-config`、`payload-url`、`payload-fetch`、`payload-stats`)
- **Source モード** — フォールバックチェーン、ソースファイルパス、ランタイムマージ(`merge-source`、`source-loader`)
- **ランタイムヘルパー** — ロケール解決、Cookie、Accept-Language の解析、ルート/メタヘルパー(`resolve-locale`、`accept-language`、`cookie`、`route`、`route-pattern`、`runtime-config`)
- **共有 FS パス** — 翻訳ファイルの分類、ネストされたページパス(`parse-path`)

Nuxt モジュールは `src/runtime/` に薄いグルーコードだけを残し、必要なサブパスのみをインポートします。

### `@i18n-micro/hmr` — 開発時の翻訳ホットリロード {#@i18n-micro/hmr-—-dev-translation-hot-reload}

開発時の HMR は `@i18n-micro/hmr` に切り出されました:

- **`watcher`** — ファイル変更の処理、キャッシュの無効化、開発時の source/premerged マージ
- **`generate-plugin`** — クライアントサイド HMR プラグインの生成
- **`cache-keys`** — サーバー/ストレージキャッシュ用の共有 `Symbol.for` キー

`translationPayloads.mode: 'premerged'` と `'source'` の両方で動作します。

### `translationPayloads.mode: 'source'` — コンパクトなサーバーレスデプロイ {#translationpayloads-mode-‘source’-—-compact-serverless-deployments}

サーバーレスプラットフォーム(Cloudflare Workers など)上の大規模なロケールマトリクス向けの新しいペイロードモード:

```typescript
export default defineNuxtConfig({
  i18n: {
    translationPayloads: {
      mode: 'source',
    },
  },
})
```

- 完全な事前マージ済みマトリクスの代わりに、**コンパクトなソースファイル**を Nitro アセットにバンドルします
- 組み込みの `/_locales/:page/:locale/data.json` ルートを通じて、ルート、ページ、フォールバックのロケールチェーンを**ランタイムで**マージします
- `publicAssets` と `prerenderRoutes` のデフォルトは `false` です。純粋な静的ホスティングではなく Nitro/エッジランタイムに依存する場合に最適です

[デプロイ — サーバーレスとエッジ](/jp/guide/deployment#serverless-and-edge)および[キャッシュとストレージのアーキテクチャ](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api)を参照してください。

### 統合パッケージ間で共有されるユーティリティ {#shared-utilities-across-integration-packages}

- **`@i18n-micro/node`** と **`@i18n-micro/astro`** — `@i18n-micro/utils/parse-path` による翻訳パス解析とディープマージの統一
- **`@i18n-micro/astro`** — `@i18n-micro/utils/accept-language` の `detectLocaleFromAcceptLanguage` を使用(重複したパーサーを削除)
- **`@i18n-micro/devtools-ui`** — `merge-source` + `parse-path` ヘルパーによる仮想ファイルパス
- **サーバーのロケール検出** — Accept-Language の処理を共有ユーティリティに合わせました

### HMR と DevTools の修正 {#hmr-&-devtools-fixes}

- クライアント HMR プラグインは、削除された `$loadTranslations` の代わりに **`$loadPageTranslations`**(正しい API)を呼び出すようになりました
- **premerged** および **source** モードでの翻訳ウォッチャーの Playwright カバレッジ

## 破壊的変更(上級者向け / 内部) {#breaking-changes-advanced-/-internal}

これらは**内部**モジュールパス(公開 API の一部ではない)をインポートしていたプロジェクトにのみ影響します:

- `src/runtime/utils/` から削除: `route-utils.ts`、`runtime-i18n-config.ts`、および `@i18n-micro/utils/*` に移動したその他のユーティリティ
- `src/runtime/server/plugins/` から削除: インラインの HMR ウォッチャー/ジェネレーター — 開発ツールをフォークしている場合は `@i18n-micro/hmr/*` を使用してください
- **`nuxt-i18n-micro`** は `@i18n-micro/utils` と `@i18n-micro/hmr` のワークスペースパッケージに依存するようになりました(モジュールと一緒に自動でインストールされます)

一般的な `nuxt.config` + コンポーザブルの使い方は変わりません。

## なぜ重要なのか {#why-it-matters}

- **サーバーレスバンドルの縮小** — `source` モードでは、ロケール × ページごとに事前マージ済みファイルを配布する必要がありません
- **単一の信頼できる情報源** — パス解析、マージ、ロケール検出、ペイロード設定の実装が 1 つに
- **保守の容易化** — フレームワーク非依存のコードは `@i18n-micro/utils` でテストされ(50 以上のユニットテスト)、あらゆる場所で再利用されます
- **開発体験の向上** — HMR ロジックは分離され、テスト可能で、ペイロードモード間で一貫しています
