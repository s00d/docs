**日付**: 2026-11-03

**バージョン**: `v4.0.0`

![v4.0.0 release](/images/4.0.0.png)

**v4.0.0** をリリースしました。ルーティング、翻訳コア、辞書ファイル、ロケール検出、そしてすべてのフレームワークパッケージが書き直されました。オプション、`$t`、`$localePath`、`$switchLocale`、コンポーネント、コンポーザブルの名前は変わりません。変わるのは動作であり、その変更の大半は解消されたバグです。ほとんどのアプリではコードの変更はわずかですが、アップグレード前に[破壊的変更](#breaking-changes)を読んでください。URL、SEO タグ、フレームワークパッケージの API は一部変更されています。詳細はすべて[アップグレード](/jp/guide/upgrade)にあります。

## 新機能 {#what’s-new}

### すべてのドメインに 1 つのビルド {#one-build-for-every-domain}

`locales[].baseUrl` と `baseDefault` は、これまでリンクの形を決めるだけでした。現在は 4 つの戦略すべてと `nuxt generate` でリクエストのルーティングも行います:

```ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'fr', baseUrl: 'https://example.com' },
      { code: 'de', baseUrl: 'https://example.de', baseDefault: true },
    ],
  },
})
```

- ホストは自身のロケールを配信します。他のドメインのロケールへのリンクはそのドメイン上の絶対 URL になり、そのロケールへの切り替えはそこへ遷移します。
- `trustForwardedHost` は、`X-Forwarded-Host` を上書きするプロキシの背後で、そのヘッダーからドメインを選びます。デフォルトでは無効です。
- `NUXT_I18N_DOMAIN` は `nuxt generate` にホストを与えます。ドメインごとに 1 回実行すると、各出力にはそのドメインのページと辞書だけが含まれます。
- `baseUrl` を持たないアプリには、このコードは一切含まれません。

[レイヤーとドメイン](/jp/guide/layers#multiple-domains)と[デプロイ](/jp/guide/deployment)を参照してください。

### ルーターと一致するルーティング {#routing-that-agrees-with-the-router}

ビルドとランタイムが、ローカライズされた URL を別々に算出することはなくなりました。すべての答えはビルドが生成したルートから得られるため、リンク、スイッチャー、`hreflang`、リダイレクトが存在しないページを指すことはありません。

- ページを配信していないロケールは、他のロケールのページではなく、そのロケールのホームにリンクします。
- `hreflang` にはそのページを配信するロケールだけが列挙されます。
- `$switchLocale` は `true` または `false` で解決されるため、辞書の読み込みに失敗したことがわかります。再度呼び出すとリトライします。
- SSR 中に設定された `$setI18nRouteParams` と `useI18nHead` はハイドレーション後も維持されます。スイッチャーは、サーバー HTML でも翻訳されたスラッグにリンクします。
- ナビゲーションはコミット時に反映されます。キャンセルまたはブロックされたナビゲーションは何も変更しません。
- `prefix` でハッシュモードが動作します。
- サーバーコンポーネントの `<Greeting :locale="$getLocale()" />` は、そのレンダリングロケールを設定します。

### 1 つのロケール検出 {#one-locale-detection}

サーバー、ブラウザー、サーバー API ヘルパー、Astro のどこでも同じ順序です。`Accept-Language` は `q` 値を考慮し、地域の一致は `locales` の順序に依存しなくなり、中国語の文字体系をまたいで一致することはありません。ランタイムオーバーライドがルーティングにも及ぶようになりました。`NUXT_I18N_DEFAULT_LOCALE` とランタイムの `disabledLocales` は、実際に配信されるものを変更します。[ロケール検出](/jp/guide/locale-detection)を参照してください。

### すべてのモードで 1 つの辞書 {#one-dictionary-in-every-mode}

プリマージビルド、`mode: 'source'`、開発モードでは、多くのページで結果が食い違っていました。現在は同じ辞書を返します。

- マージはすべての階層でディープに行われ、フォールバックチェーン（`fr` → `de` → `en`）は最後までたどられます。
- 開発時の翻訳の編集は、ページをリロードせずにその場で反映されます。削除されたキーは消え、ルートファイルの編集はすべてのページに届きます。
- `$clearCache()` は現在のページを再読み込みし、新しいテキストが届くまで古いテキストを画面に残します。
- チャンクの読み込みに失敗しても、生のキーを表示する代わりに現在の辞書を維持します。

### より小さな辞書ファイル {#smaller-dictionary-files}

- ページのファイルには、`__root/<locale>/data.json` にあるロケールのルートとの差分だけが含まれるようになりました。ブラウザーはルートを一度だけ読み込み、各ページをその上にマージするため、ディスク使用量が減り、次のページのコストは最初のページのごく一部になります。
- 辞書の URL にはバージョンが付きます。現在の `?v=` を持つ URL は Node サーバー上で 1 年間固定され、ホストの静的コピーは `max-age=60` で応答します。[キャッシュヘッダー](/jp/guide/deployment#cache-headers-and-datebuild)を参照してください。
- すべての SSR ページは辞書ファイルをプリロードするため、HTML と同時に読み込みが始まります。
- 読み込みの失敗が残り続けることはなくなりました。次のリクエストで再度読み込みます。[辞書を読み込めない場合](/jp/guide/deployment#when-a-dictionary-cannot-be-read)を参照してください。

### 改善された `<i18n-t>`、複数形、フォーマット {#better-&lt;i18n-t&gt;-plurals-and-formats}

- スロットが `plural`、`number`、`date`、`relativeDate` と組み合わせて動作し、最初のものだけでなくすべての `{name}` が埋められます。
- `<i18n-t>` は Nuxt、Vue、React、Preact、Solid、Astro で共通の 1 つのレンダラーです。
- `=0 ` で始まる最初の形は明示的なゼロの形で、残りは `Intl.PluralRules` に従います: `=0 no apples | one apple | {count} apples`。[`$tc`](/jp/api/methods#$tc) を参照してください。
- 新しい `timeZone` オプション: サーバーとすべてのブラウザーで同じカレンダー日付になります。
- `{firstName}`、`{first-name}`、`{user.name}` は有効なプレースホルダーです。
- `$tn`、`$td`、`$tdr` は、複数形と同様に `iso` に従います。
- `$tdr` は実際の未来の日付を返します: `in 3 days`、または `numeric: 'auto'` で `tomorrow`。

### デフォルトでより安全に {#safer-by-default}

- `<i18n-t html>` は `params` をエスケープします。信頼されるマークアップは翻訳だけです。
- リンクが誤ってオリジンの外に出ることはありません。`//host`、`/\host`、空白はこのサイトにとどまります。
- サーバーの翻訳キャッシュには上限があるため、でっち上げのページ名を持つ URL でメモリが増え続けることはありません。
- DevTools の保存エンドポイントは、翻訳ディレクトリ内の既存の `.json` ファイルのみを受け付け、クロスサイトリクエストを拒否します。

### 2.0 になったフレームワークパッケージ {#framework-packages-at-2-0}

- **React、Preact、Solid:** `I18nT` はリッチテキスト用の `components` prop を受け取ります。新しい `useT` と `useLocaleSwitch`、および `@i18n-micro/react/server` と `/client` による React Server Components のサポート。Preact は `preact/compat` を必要としなくなりました。
- **Vue と VitePress:** `I18nLink` は `name`、`query`、`hash` を保持し、VitePress は `base` を尊重します。
- **Astro:** `i18nIntegration` は辞書をバンドルし、ミドルウェアをインストールします。メインエントリーに `node:*` のインポートがないため、エッジで動作します。`base` が動作します。
- **Node と runtime:** `fork(locale)` は低コストなリクエストごとのインスタンスを返し、`@i18n-micro/node` の `run(locale, fn)` はインスタンスをリクエストにスコープします。
- **`@i18n-micro/types-generator`:** サードパーティの依存関係がなく、プレーンな Vite および Rollup プラグインです。
- **`@i18n-micro/devtools-ui`:** Vite のソケットを介したライブ更新と、Astro ツールバーアプリ。

### `@i18n-micro/cli` {#@i18n-micro/cli}

CLI は `@i18n-micro/cli` としてモノレポに移り、28 個ではなく 16 個のコマンドで、はるかに少ない依存関係で書き直されました。`check` は `validate`、`diff`、`check-duplicates` を置き換え、CI 向けの `--json` と終了コードを備えています。キーが未使用であることを証明できない場合、`clean` は何も書き込みません。[CLI](/jp/guide/cli) を参照してください。

### ドキュメント {#documentation}

ドキュメントは、1 つの読み進め方（インストール、最初の翻訳ページ、翻訳ファイル、ルーティング、検出、そしてタスク別ガイド）に沿って、コードに基づいて書き直されました。古い URL はリダイレクトされます。[アップグレード](/jp/guide/upgrade)にはすべての変更が詳しく列挙されています。

## 速度とサイズ {#speed-and-size}

- サーバーレンダリングは、ローカルの HTTP リクエストや再パースなしに辞書を直接読み込みます。
- `dir="auto"` はデフォルトではなくなりました。大きなページではブラウザーがこれに長い時間を費やします。20,000 個の `$t` 要素がある場合、Chromium での DOMContentLoaded は約 980 ms から約 115 ms になりました。
- `serverTranslationPreload` と `i18n:register` がすべてのリクエストを遅くすることはなくなりました。
- Cookie が設定されていない場合、クライアントバンドルから `useCookie` が除かれ、`@i18n-micro/path-strategy` は以前のサイズのごく一部になりました。

**v3.30.3 と比較したテストアプリ。** 1 台の Mac 上の 1 つの Node サーバーで動作する生成された Nuxt アプリに対し、プレリリースビルドで、`wrk` を 24 接続・20 秒、ローテーションしながら 3 ラウンド実行しました。各行は別々の実行によるものなので、行内で比較してください。ハイドレーションは両側とも `dir: 'ltr'` を使用しています。

| 指標 | v3.30.3 | v4.0.0 |
| --- | ---: | ---: |
| 4 ロケール、10k カタログ: 毎秒リクエスト数 | 384-395 | 585-591 |
| 4 ロケール、10k カタログ: p95 レイテンシー | 106-110 ms | 70-72 ms |
| 4 ロケール、10k カタログ: リクエストあたりのサーバー CPU | 2.92-3.00 ms | 2.01-2.02 ms |
| 12 ロケール、100k カタログ: 毎秒リクエスト数 | 362-370 | 578-580 |
| 12 ロケール、100k カタログ: p95 レイテンシー | 115-117 ms | 72-73 ms |
| 12 ロケール、100k カタログ: リクエストあたりのサーバー CPU | 3.11-3.17 ms | 2.02-2.03 ms |
| ハイドレーション、100k ページ | 86-92 ms | 77-81 ms |
| このアプリのクライアント JS、gzip | 105.1 KB | 93.9 KB |
| `i18n:register` 購読者がいる場合のリクエスト時間、100k チャンク | 96-108 ms | 1.7 ms |

以前のプレリリースビルドで 100k カタログに対して 30 分間実行したところ、113 万件のリクエストをエラーなしで処理し、ライブヒープは横ばいのままでした。

**3 つの本番アプリと、それらが使っていた v3.29.5 との比較**（プレリリースビルド）。2 つは SSR サイト、1 つは SPA です。それぞれ 1 つの Node サーバーで、60 秒、8 接続、GET のみ、2 ラウンド実行しました。ビルド時間はそれぞれ 1 回の実行です。

| 指標 | SSR アプリ 1 | SSR アプリ 2 | SPA アプリ |
| --- | ---: | ---: | ---: |
| ディスク上の辞書バイト数 | 6.37 MB → 1.52 MB (-76%) | 4.43 MB → 1.52 MB (-66%) | 15.40 MB → 1.69 MB (-89%) |
| `.output` サイズ | -22% | -14% | -29% |
| ビルド時間 | 27 s → 22 s | 23 s → 19 s | 41 s → 28 s |
| クライアント JS、gzip | +1.7% | +0.9% | +0.5% |
| 毎秒リクエスト数 | 82 → 88 | 237 → 240（誤差の範囲内） | 233 → 404（SPA シェルのみ） |

**クライアント JS。** 独自のコードを持つ実際のアプリでは、上記のとおりわずかに増加します。共通の修正によってフレームワークパッケージも大きくなりました。別のプレリリースビルドで最小サイズの Vue、React、Preact、Solid アプリを使って測定したところ、gzip で約 1.4 KB から 2.5 KB の増加でした。React、Preact、Solid は共通のリッチテキストレンダラーも含んでいます。

**辞書リクエスト。** 初回読み込みはルートとページの 2 つのファイルを取得するようになりました。そのバイト数は変わりません（2 つの SSR アプリでの 103 回と 89 回の初回読み込みで +0.3%）。同じドキュメント内の次のページは小さなファイルを 1 つ取得するだけです。測定した 2 つのページでは、gzip で 4.7 KB → 1.5 KB、5.9 KB → 0.5 KB でした。SPA のログイン後の巡回では、辞書のバイト数が 21% 減少しました。

**エッジ。** 小さなデモアプリでは、Cloudflare Worker のアップロードサイズが、プレリリースビルドで gzip 241.5 KiB から 250.3 KiB になりました。Edge バンドルに埋め込まれた辞書も同じルートファイルとページファイルを使用しますが、大きなカタログでの埋め込みは測定していません。

## 破壊的変更 {#breaking-changes}

### 要件 {#requirements}

- **Nuxt 3.18 以降**、および **Node 20 以降**。
- **`@i18n-micro/test-utils`** はモジュールと一緒にインストールされなくなりました。テストでインポートしている場合は自分で追加してください。
- **`@i18n-micro/hmr`** は廃止されました。翻訳の HMR は組み込まれています。インストールしている場合はパッケージを削除してください。
- **`@i18n-micro/react`** には React 18 以降が必要です。
- **`nuxt-i18n-micro-cli`** は `@i18n-micro/cli` に置き換えられました。

### オプションと設定 {#options-and-config}

- `dependsOn` 内の `i18n-plugin-hooks` と `i18n-plugin-define` は、エラーなしに何も待たなくなりました。`i18n-plugin-loader` を使用してください。
- サーバーの自動インポートは `useLocaleServerMiddleware`、`useTranslationServerMiddleware`、`loadTranslationsFromServer`、`detectCurrentLocale` です。その他は自動インポートされなくなりました。
- `resolveTranslationPayloadMode` およびその他の `resolveTranslationPayload*` ヘルパーは、`shouldCopyTranslationPayloadsToPublic`、`shouldRegisterNitroServerAssets` とともに `nuxt-i18n-micro` から削除されました。`TranslationPayloadMode` 型は残ります。
- `$getI18nConfig()` には `isSSG`、`hmr`、`hooks`、`noPrefixRedirect`、`routeLocales`、`routeDisableMeta`、`globalLocaleRoutes` がなくなりました。オプション自体は変わりません。
- `locales[].baseUrl` はリクエストをルーティングするようになりました。他のドメインのロケールはこのホストでは 404 になり、同じホスト上のリンクは相対パスになります。そのようなビルドでは、`$getI18nConfig().locales` はホストが配信するものを保持し、`linkLocales` はすべてを保持します。
- `baseUrl` はその他のホストでもオリジンを設定します。canonical と `hreflang` は、リクエストのオリジンではなく、設定されていれば `metaBaseUrl`、そうでなければデフォルトロケールの `baseUrl` を使用します。
- `excludePatterns` はセグメント全体に一致し（`'/admin'` は `/administrator` に一致しなくなりました）、glob はアンカーされ、`RegExp` パターンがランタイムにも届くようになりました。
- `cacheMaxSize` を設定しない場合、サーバー上のエントリーは最大 1000 件です。`cacheTtl` はエントリーが保存された時点から数え、読み取りによって延長されなくなりました。
- `no_prefix` では、`i18n` 設定で明示的に指定した `localeCookie: null` は無効のままです。
- `prefix_except_default` と `prefix_and_default` では、ランタイムの `defaultLocale` は警告とともに無視されます。ランタイムの `fallbackLocale` は有効なロケールでなければなりません。
- `nuxt.config` の `routeDisableMeta` が尊重され、どのキー形式でも `nuxt.config` のエントリーが `$defineI18nRoute` より優先されます。
- 開発時のサーバーでは解決済みの設定が凍結されており、書き込むと例外がスローされます。
- 同じ `code` については、プロジェクトの `locales` エントリーがレイヤーのものより優先されます。

### コンポーザブルと `$` メソッド {#composables-and-$-methods}

- `$switchLocale` は `true` または `false` で解決されます（以前は何も返しませんでした）。`$switchRoute` の型は `Promise<void>` です。
- `$localeRoute`、`$switchLocalePath`、スイッチャーは、ページを配信していないロケールをそのロケールのホームにリンクします。
- `$localePath` は `http(s):`、`mailto:`、`tel:` スキームを持つ文字列をそのまま返し、`$localeRoute` はそれを `path` と `fullPath` に入れます。未検証の値をリンク先としてこれらに渡さないでください。`//host` や `x.com` のような名前だけのものは、このオリジン上のパスのままです。
- パスのないリンクは現在のページにとどまります: `$localePath('#top')`、`'?p=2'`、`''`、`{ query }`。`'#top'` は以前はサイトのルートから読み取っていました。単独の `'about'` は引き続き `/about` を意味します。
- `$switchRoute` はアプリ内にとどまります。アプリの外に出るのは、ロケール自身の `baseUrl`、`mailto:`、`tel:` だけです。
- `baseUrl` を持つロケールへのリンクは `$localePath` または `<i18n-link>` を通します。`<NuxtLink :to="$localeRoute(x, 'fr')">` と `router.push($localeRoute(x, 'fr'))` はこのアプリのパスのままです。コードでは `navigateTo($localePath(x, 'fr'), { external: true })` を使用してください。
- `$switchLocaleRoute` とリダイレクトは `trailingSlash` に従います。
- サーバーで設定された `$setI18nRouteParams` と `useI18nHead` は、ナビゲーションでパスが変わると破棄されます（`/news/1` から `/news/4` への遷移も含む）。新しいページで再度設定してください。
- setup で読み取った `$setI18nRouteParams` はそのページに結び付けられます。すでに離れたページからの遅れた呼び出しは何もしません。セッターがないため、テストでは `useI18n` 自体をスタブしてください。
- `useI18n()` はアプリごとに 1 つのオブジェクトを返します。それへの書き込みはすべての呼び出し元に届きます。
- 辞書、ロケール、パラメーター、head はナビゲーションのコミット時に変わります。`beforeResolve`、`beforeRouteEnter`、またはそれ以降のグローバルガードは古いものを参照します。ルートミドルウェアは影響を受けません。
- URL 戦略では、ナビゲーションがキャンセルされると `$switchLocale` は保存されていたロケールを復元します。
- `$t` は `defaultValue` を補間します: `$t('missing', { n: 1 }, 'Got {n}')` は `Got 1` になります。`$tc` も同様で、空の翻訳に対しては `''` を返します。
- `$has(key, route)` はルートを尊重します。
- `$clearCache()` は現在のページの辞書を再読み込みします。
- `{param}` プレースホルダーは渡したパラメーターだけを読み取ります: `{constructor}` は書かれたまま残ります。
- 負の値、小数、非常に大きなカウントを渡した `$tc` は、実際のカウントで最後の形を使います。`{ count: null }` は例外をスローしなくなり、存在しない複数形のキーは missing ハンドラーに届きます。
- `$tdr` は無効な入力に対して `Invalid Date` を返します。1 秒未満の過去は `0 seconds ago` です。
- `$tn`、`$td`、`$tdr` は `iso` に従います: `{ code: 'en', iso: 'en-GB' }` は日付を `31/10/2026` とフォーマットします。`Intl` が認識しないコードは `en` としてフォーマットされ、複数形はインデックスルールに従います。`iso` を設定してください（`{ code: 'ua', iso: 'uk-UA' }`）。
- `detectCurrentLocale` は非推奨です。`useLocaleServerMiddleware(event).current` を使用してください。

### 複数形 {#plurals}

テンプレートの意味は、1 つの例外を除いて変わりません。プレースホルダーのないゼロの形に続いてカテゴリーごとに 1 つの形があり、複数のカウントが共有する各形に `{count}` がある場合、3 つ以上のカテゴリーを持つロケール（`ru`、`uk`、`pl`、`cs`、`ar` など）ではカテゴリーに従うようになりました: `none | {count} one | {count} few | {count} many` は `uk` で `3 few` と `21 one` を返します。それ以外のテンプレートでカテゴリーを使うには、`=0 ` マーカーを追加してください。カスタムの `plural` ルールは生の値を読み取るため、マーカー付きのテンプレートは `=0 ` が付いたまま届きます。[アップグレードの表](/jp/guide/upgrade#plurals-and-formatting)を参照してください。

### コンポーネント {#components}

**`<i18n-t>`**

- `html` はすべてのケースで `params` をエスケープし、すべてのスロットを無視します。
- スロットは同名のパラメーターより優先されます。
- `plural`、`number`、`date`、`relativeDate` では、`null` は未設定を意味します。
- `plural` は `$tc` と同様に `Number` でカウントします: `1.5` は `1.5` のまま、`"2 items"` は `NaN`、`""` は `0` です。
- `number`、`date`、`relativeDate` は `params` を保持します。
- `hideIfEmpty` はすべての分岐で適用され、`defaultValue` はすべての分岐で存在しないキーの代わりになります。
- `html` での存在しないキーはエスケープされたテキストになります。
- `date` と `relativeDate` の出力には `data-allow-mismatch="text"` が付き、名前付きスロットの隣ではテキストは独自の `<span>` に入ります。
- `.innerHTML` と `textContent` 属性は破棄されます。
- 関数型コンポーネントです: `ref` を付けてもインスタンスは得られません。
- `<i18n-t>` と `<i18n-group>` は、`$t` と同様にアクティブな辞書を読み取ります。

**`<i18n-switcher>`**

- リンクは `$switchLocale` を呼び出すプレーンな `<a>` なので、`router-link-active` クラスはなくなりました。
- ボタンは `aria-expanded` を持つ `type="button"` です。Escape キーと外側のクリックでドロップダウンが閉じます。
- 新しいクラス `i18n-switcher-wrapper`、`i18n-switcher-dropdown`、`i18n-switcher-button`。各リンクには `lang` があり、ロケールが設定している場合は `dir` もあります。
- デフォルトのスタイルは論理 CSS プロパティを使用し、ドロップダウンにはより大きな `z-index`、最小幅、影があります。
- パラメーターを持つページでは、サーバーはレンダリング終了時にリンクを書き換えます。手書きの `$switchLocalePath` リンクは書き換えられません。

**`<i18n-link>`**

- `https://`、`mailto:`、`tel:` は大文字小文字を問わず一致します。単独の `report.pdf` はルートで、`example.com` は外部のままです。TLD でもあるファイル拡張子（`example.md`）はファイルとして扱われます。`https://` と書いてください。
- `activeStyle` は末尾のスラッシュ、クエリ、ハッシュを無視します。

### フックと型 {#hooks-and-types}

- `i18n:register` はランタイムフックです: プラグイン内で `nuxtApp.hook('i18n:register', …)`。
- エクスポートされる型 `ModuleHooks` は `ModuleRuntimeHooks` に名前が変更されました。
- `i18n:beforeLocaleSwitch` と `i18n:afterLocaleSwitch` は一度も発行されたことがなく、ドキュメントからも削除されました。
- `ModuleOptionsExtend.isSSG` はオプションかつ非推奨です。何もこれを設定しません。

### URL とリダイレクト {#urls-and-redirects}

- **`/en` と `/en/...` は 404 です**（`prefix_except_default` で `en` がデフォルトの場合）。
- **大文字小文字や綴りが異なるロケールプレフィックスは 404 です**（`/DE/about`）。`[...slug]` 下の `/DE/x` や `[slug]` と並ぶ `/DE` も同様なので、別の大文字小文字でロケールコードと等しい CMS のスラッグはページを失います。
- **未知の URL は 404 のままです**（`autoDetectPath: '*'` または `'no_prefix'` の場合）。`prefix` はリダイレクトを維持し、どこでも `/` も同様です。
- **プレフィックスなしの他のロケールのカスタムパス**は、`prefix_except_default` ではデフォルトロケールの URL への `302` です。`prefix` では、リダイレクトが実在するページに届くようになりました。`prefix_and_default` は 404 のままです。
- **`redirects: false` の `prefix`** は、プレフィックスなしの URL（カスタムのデフォルトパスを持つページの元の URL を含む）に 404 を返します。
- **`autoDetectPath: '*'`** は、プレフィックスなしのパスにも Cookie と `Accept-Language` を適用します。
- **`prefix` では**、`autoDetectPath` の設定にかかわらず、すべてのパスでプレフィックスなしの URL は訪問者のロケールを維持します。
- **`prefix_and_default` では**、プレフィックスなしの URL はデフォルトロケールです。
- **`no_prefix` では**、カスタムパスはそれ自身のロケールでレンダリングされ、制限されたページは配信しているロケールでレンダリングされ、パスを共有するロケールは 1 つのレコードを共有します。
- **ページのない `routeRules` のリダイレクト**はローカライズされません: `/de/old` は 404 です（以前は空の 200 でした）。
- **ルートルールはカスタムパスにも届き**、`no_prefix` でもコピーされます。`/de/artikel/news` のような静的な兄弟ルートは `/de/artikel/:slug` に一致します。
- **`disabled: true` のロケール**は、そのプレフィックスに即座に 404 を返し、そのロケールへのリンクはページにとどまります。
- **大文字小文字が異なるページパス**は、本来の綴りへの `302` です: `/T/BASIC` は `/t/basic` に移動します。
- **カスタムのデフォルトパスを持つページの元の URL** は、`prefix_except_default` ではそのパスへの `302` です。以前は 404 でした。
- **`noPrefixRedirect`** は訪問者のロケールに従います: Cookie が `de` の場合、`/about` はデフォルトロケールのパスではなく `/ueber-uns` に移動します。
- **ホスト自身のプレフィックス**は、`prefix_except_default` ではその `baseDefault` ホストで 404 です: `de` ホストでの `/de/x` は以前 200 でした。
- **`customRegexMatcher`** は、最初のセグメントがロケールに見える実在のページを 404 にしなくなりました。
- **`nuxi generate`** は、ルートルールが `prerender: false` を設定していない限り、すべての静的ページをそれを配信する各ロケールでプリレンダーします。出力のファイルは増えます。`baseUrl` がある場合は、`NUXT_I18N_DOMAIN` を使ってドメインごとに 1 回実行してください。
- **クライアントのリダイレクトはナビゲーションのモードを維持します:** プレーンな `<NuxtLink>` は履歴エントリーを追加します。
- **ローカライズされたルート名は一貫しています。** 影響を受けるのは、`router.push({ name })` で `localized-…` という名前をハードコードしているコードだけです。ページ自身の名前を `$localeRoute` に渡してください。
- **`extendPages` からの名前のないページ**はローカライズされ、名前が付けられます。
- **`prefix` では、他のドメインへのリンク**はロケールプレフィックスを保持します。
- **ドメインのホーム**は、どこでも末尾のスラッシュなしで書かれます。
- **`?locale=`** がページで考慮されるのは `no_prefix` の場合だけです。`/about?locale=de` が `lang="en"` の下でドイツ語をレンダリングすることはなくなりました。
- `/en/...` 上での**プラグインの `setLocale('de')`** は、`de` の辞書を読み込まなくなりました。

### SEO と HTML 出力 {#seo-and-html-output}

- `dir="auto"` はデフォルトではなくなりました。既知の RTL 言語には `dir="rtl"` が付き、`dir` を持たないその他のロケールには属性が付きません。以前の出力を維持するには `dir: 'auto'` を設定してください（大きなページではパースのコストがかかります）。[テキストの方向](/jp/guide/seo#text-direction)を参照してください。
- `disableMeta` が動作するようになりました: ページには `hreflang`、canonical、`og:locale` がありません。`lang` と `dir` は残ります。
- `hreflang` にはそのページを配信するロケールだけが列挙されます。`x-default` はデフォルトロケールがそのページを配信している場合にのみ表示されます。
- ローカライズされていないページには `hreflang` も `og:locale:alternate` もありません。
- 404 ページは URL のロケールで `<html lang dir>` を持ち、canonical や `hreflang` はありません。
- canonical、`og:url`、`hreflang` は、サーバー上でも、ホワイトリストに登録されたクエリ（`/about?page=2`）を保持します。
- オリジンがリクエストから得られる場合、canonical と `hreflang` には `app.baseURL` が含まれます。
- すべての SSR ページは、404 ページも含め、辞書ファイル用の `<link rel="preload" as="fetch" crossorigin="anonymous">` を持ちます。厳格な CSP ではこれを許可してください。`apiBaseClientHost` を使う場合、そのホストには CORS が必要です。
- `no_prefix` ではすべてのページに、その他の戦略ではロケールリダイレクトに `Vary` が設定されます。CDN のキャッシュキーを確認してください。
- ロケール Cookie は、配信されたページによってのみ書き込まれます。

### 検出とサーバー {#detection-and-server}

- `Accept-Language` は `q` 値を考慮し、`q=0` はその言語を除外します。
- `useLocaleServerMiddleware` と `useTranslationServerMiddleware` は、すべてのルートで同じ順序（`?locale`、`[locale]` パラメーターまたはプレフィックス、Cookie、ヘッダー、デフォルト）を使い、`localeCookie: null` と `autoDetectLanguage: false` を尊重し、ロケールごとに辞書をキャッシュします。
- 不正な形式のロケール Cookie は、SSR を失敗させる代わりに無視され、そのまま残されます。
- ハッシュモードは `hash-locale` Cookie だけを読み取ります。単独の `user-locale=de` は考慮されなくなりました。
- `NUXT_I18N_DEFAULT_LOCALE` とランタイムの `disabledLocales` はルーティングを変更します。
- **`premerged` の出力が変わりました。** `/{apiBaseUrl}/<page>/<locale>/data.json` は、`__root/<locale>/data.json` との差分だけを保持します。これらのファイルを直接読み取るものは、2 つをマージする必要があります。完全な辞書も引き続き有効なファイルです。
- **辞書は `app.cdnURL` に従います。** ブラウザーは、以前は `app.baseURL` を使っていたところを、`<cdnURL>/_locales/...` から辞書を取得します。CDN は `_locales/` を保持し、サイトのオリジンを許可する必要があります。[App baseURL とペイロードホスト](/jp/guide/deployment#app-baseurl-and-payload-hosts)を参照してください。
- `/{apiBaseUrl}/**` に Nitro のルートキャッシュはなく、`s-maxage=60, stale-while-revalidate` ヘッダーもなくなりました。そのキャッシュに依存していた場合は、ペイロードルートの前に CDN を置いてください。
- `/{apiBaseUrl}/<page without a folder>/<locale>/data.json` はルート辞書で応答します（以前は `{}` でした）。ホストの 404 は、以前は `200 {}` で応答していましたが、404 としてそのまま返されるようになりました。
- 辞書を読み込めないプリレンダーは 500 と警告で失敗し、Nuxt のデフォルトの `failOnError` ではビルドが 1 で終了します。
- 再ビルドなしで変更された翻訳は、`v` が変わったときにのみブラウザーに届きます: `NUXT_I18N_DATE_BUILD` を設定してください。
- `apiBaseServerHost` が設定されていない限り、SSR は HTTP 経由で `/{apiBaseUrl}` をリクエストしなくなりました。

### 翻訳 {#translations}

- マージはすべての階層でディープに行われ、フォールバックチェーンは最後までたどられます。
- マージはロケール単位で行われます: アクティブなロケールのルートファイルは、フォールバックロケールのページファイルより優先されます。
- 独自の `pages/<name>/` フォルダーを持たないページは、本番環境でルート辞書を読み取ります。以前は `{}` を受け取っていました。
- `disablePageLocales: true` はルートファイルだけを読み取ります。
- 離れたページのキーは、ナビゲーション後に解決されなくなります。前のページのファイルにしかないキーをレイアウトが使っていた場合は、それらをルートファイルに移動してください。
- 壊れたロケールファイルは、すべてのモードでそのパスとともに一度だけ警告を出します。以前は開発時に例外をスローしていました。

### `@i18n-micro/*` パッケージ {#@i18n-micro/*-packages}

`@i18n-micro/types` と新しい `@i18n-micro/cli` を含め、すべての `@i18n-micro/*` パッケージが 2.0.0 になりました。

**`@i18n-micro/react`、`preact`、`solid`**

- ルーターアダプターは `/router` に移動しました: `createReactRouterAdapter`、`createSolidRouterAdapter`、Preact の `createBrowserHistoryAdapter`。`createPreactRouterAdapter` は削除されました。
- `I18nT` は上記の `<i18n-t>` に従います。`dangerouslySetInnerHTML`、`innerHTML`、`textContent` 属性は破棄されます。
- `I18nSwitcher` は、`aria-current="page"`、`▾`、論理 CSS、ボタンの `language-switcher` を持つ `<a href>` 項目をレンダリングします。`aria-haspopup` はありません。`className` は `i18n-switcher-wrapper` に追加されます。
- `/` またはロケールのルートへのリンクは、完全一致の場合にのみアクティブになります（React、Preact）。
- `I18nLink` はユーザーの `onClick` と `style` を保持し、修飾キー付きのクリックはブラウザーに任せます。アクティブ判定ではクエリとハッシュは考慮されません。ルーターがない場合、どのリンクもアクティブになりません。
- React と Preact: `I18nLocalesContext`、`I18nDefaultLocaleContext`、`I18nRouterContext` は 1 つの `I18nConfigContext` になりました。Solid: 1 つの `I18nContext` が `{ i18n, locales, defaultLocale, router }` を保持します。
- アダプターの `getCurrentPath` にはクエリとハッシュが含まれ、`getRoute().query` 内の重複したキーは配列になります。
- `i18n` を持たないネストされた `I18nProvider` は外側のインスタンスを維持し、インスタンスがまったくないプロバイダーは例外をスローします。
- 値のない `defaultLocale()` は `fallbackLocale` です。
- Solid: `getCurrentPathAccessor` は削除されました。`useI18n()` は `locales` がなくても例外をスローしなくなりました。
- React: `use-sync-external-store` は依存関係ではなくなり、`react-dom` はオプションのピア依存関係です。

**`@i18n-micro/vue`、`vitepress`**

- `I18nT` は関数型コンポーネントです。
- `I18nSwitcher` と `I18nLink` は上記のセクションに従います。`aria-haspopup` はなくなりました。
- `I18nLink` と `createVueRouterAdapter` は `name`、`query`、`hash` を解決します。未知の `name` は、`RouterLink` と同様に例外をスローします。
- `useLocaleHead` は `//de/` を生成しなくなりました。1 つのページの canonical と `hreflang` は一致し（`/de`）、ホワイトリストに登録されたクエリパラメーターがそれらに届きます。
- `I18nRoutingStrategy.resolvePath` は、location オブジェクトや、クエリとハッシュを含むパスを受け取ることがあります。新しいオプションの `toHref`。
- VitePress: リンク、スイッチャー、`push`、`replace` は `site.base` を含みます。

**`@i18n-micro/astro`**

- `i18nIntegration` は `translationDir` をバンドルし、ミドルウェアをインストールします。セットアップをコピーしているだけの `src/middleware.ts` は削除するか、`middleware: false` を渡してください。独自の `src/middleware.ts` は `base: config.base` を渡します。
- `i18nIntegration` は `messages`、`plural`、`missingHandler`、`routingStrategy` に対して例外をスローします。これらは `middleware: false` とともに `createI18n` または `createI18nMiddleware` に渡してください。何の効果もなかったオプションは型から除かれました。
- `loadTranslationsFromDir` と `loadTranslationsIntoI18n` は、ESM 専用の `@i18n-micro/astro/node` に移動しました。
- `getGlobalRoutingStrategy`、`setGlobalRoutingStrategy`、`runWithRoutingStrategy` は削除されました。`Astro.locals.routingStrategy` を読み取ってください。
- `clone()` は `fork()` になり、`_storage` オプションはなくなりました。
- 動的ページは 1 つのルートです: `/blog/hello` は `blog-slug` です（以前は `blog-hello` でした）。`pages/blog-hello/` を `pages/blog-slug/` に移動してください。カスタムの `getRouteName` は 3 番目の引数としてパターンを受け取ります。
- ページのロケールは URL が決定します。`autoDetect` は `/` から優先ロケールのホームへの 302 です。新しい `localeCookie` オプションがあり、`redirectToDefault` が実装されました。
- 別のロケールの同一オリジンのページからのページビューは、ロケール Cookie を書き込み、リダイレクトしません。サーバーアイランドとアクションはリダイレクトせず、`Vary: Referer` を持ちます。
- `config.localeCodes` は無効化されたロケールを除外し、`prepareLocaleRewrite` はそれらに 404 を返します。
- キーを指定しない `getI18nProps()` は、そのページで `t()` が答えられるものをすべて送信し、20 KB を超えると開発時に警告を出します。アイランドが使用するキーを渡してください。
- `useLocaleHead`: デフォルトの `baseUrl` は `site`、なければルート相対です。リンクとメタには `id` が付きます。
- `<I18nT html>` は `params` をエスケープし、空の翻訳は空としてレンダリングされます。
- `<I18nLink>` と `localizePath` は、外部 URL、`#hash`、`?query` には手を付けず、末尾のスラッシュを保持します。
- `<I18nSwitcher>` はクエリを保持し、生成された id の代わりに `data-i18n-switcher` を使用します。
- `@i18n-micro/astro/client` には `translate` と `hasTranslation` だけがあります。アダプターは `/client/vue`、`/client/react`、`/client/preact`、`/client/svelte` からインポートしてください。`client/vue` には `vue` のインストールが必要です。
- アイランド: `has()` はサブツリーに対して true で、`t('')` は `''` です。`provideI18n` は新しい props に追従するためのゲッターを受け取ります。
- `getLocale` と `getDefaultLocale` はミドルウェアがないと例外をスローします。

**`@i18n-micro/runtime`、`node`**

- アクティブでもフォールバックでもないロケールへの書き込みは、購読者に通知しません。
- `addRouteTranslations(locale, route, messages, false)` はチャンクを置き換えます。
- `loadFromUrls` は並列に取得し、1 つでも失敗すると何も書き込みません。
- Node: `reload()` は辞書を先に空にするのではなく入れ替え、成功メッセージをログに出力しません。存在しなくなったディレクトリでは古い辞書が維持されます。
- Node、Astro、VitePress: locales フォルダーの読み取り処理は 1 つです。存在しないフォルダーは警告を出し、JSON オブジェクトでないファイルは報告されてスキップされ、メッセージは `[i18n]` で始まります。

**`@i18n-micro/test-utils`**

- モックは実際の翻訳ルールに従います: `tc('a', 1.5)` は最後の形を使い、`td('nope')` は `Invalid Date`、`t(miss, undefined, '')` はキーを返し、見つからない場合にログを出力しなくなりました。
- `createI18nTestContext` から `isolated` がなくなり、`./publish-smoke` は削除されました。

**`@i18n-micro/types-generator`**

- `I18nTypesPlugin(options)` はプレーンな Vite および Rollup プラグインです: `.vite()`、`.webpack()`、`.esbuild()` はありません。webpack や esbuild では、スクリプト内で `generateTypes` を呼び出してください。
- `getTypesString` と `generateTypes` は同期的です。`flattenKeys` と `isPlainTranslationObject` は削除されました。
- キーは `t()` が読み取るものです: オブジェクトのパスが追加され、ロケールレイアウト外のファイルは除外されます。

**`@i18n-micro/devtools-ui`**

- 保存は `translationDir` 内の既存の `.json` のみを受け付け、ファイルを作成しなくなりました。クロスサイトリクエストは 403 です。
- 到達可能なエンドポイントへの保存に失敗すると、例外をスローしてロールバックします。
- `createBridge` は `base` オプションを受け取ります。Astro は `i18nDevToolsIntegration` を使用します。

**`@i18n-micro/utils`、`core`、`path-strategy`、`route-strategy`**

カスタムアダプターとツール向けのみです。

- `utils`: サブパス `./route`、`./route-pattern`、`./build`、`./payload-stats`、`./payload-config` は、`resolveServerLocale` と `resolvePreferredLocale` とともに削除されました。`resolveLocale` を呼び出してください。`deepMergeTranslations` と `mergeRouteTranslationsWithRoot` はなくなりました。`deepMergeTranslationsRecursive` を使用してください。
- `core`: `TranslationHelper` から `setCache`、`getGeneration`、`lookupIn` が削除されました（`lookup(chunkKey, key)` を使用）。`BaseI18n` から `ensurePinnedChunk` と `invalidatePin` が削除されました。`useTranslationHelper(storage)` はなくなりました。`new TranslationHelper(storage)` を使用してください。
- `path-strategy`: **`switchLocaleRoute(fromLocale, toLocale, route, options)` は `switchLocaleRoute(toLocale, route, options)` になりました。古い JavaScript の呼び出しは、エラーなしに誤った結果を返します。** Nuxt の `$switchLocaleRoute` は影響を受けません。`/prefix`、`/no-prefix`、`/prefix-except-default`、`/prefix-and-default` のエントリーは、`getRedirect`、`getCanonicalPath` とともになくなりました。`RouterAdapter` には `getRoutes` が必要です。`createPathStrategy` は絶対 URL を生成しません。ロケールが `baseUrl` を持つ場合は `new DomainPathStrategy(ctx)` を使用してください。
- `route-strategy`: エクスポートされるのは `RouteGenerator`、`generateRoutes`、`Rules`、パスヘルパーだけです。

## 移行 {#migration}

1. 要件を確認します: Nuxt 3.18、Node 20、`@i18n-micro/react` を使う場合は React 18。
2. `nuxt-i18n-micro` とすべての `@i18n-micro/*` パッケージを一緒に更新します。`@i18n-micro/hmr` を削除します。テストでインポートしている場合は、`@i18n-micro/test-utils` を開発依存関係として追加します。`nuxt-i18n-micro-cli` を `@i18n-micro/cli` に置き換え、[そのコマンド表](/jp/guide/cli#moving-from-nuxt-i18n-micro-cli)に従います。
3. コード内で、`@i18n-micro/path-strategy` の `switchLocaleRoute(`、`i18n-plugin-hooks`、`i18n-plugin-define`、`localized-` で始まるルート名、`$getI18nConfig().globalLocaleRoutes` およびその他の削除された設定キー、`ModuleHooks`、`i18n:register` に付けた `@ts-expect-error` を検索します。
4. `<i18n-t html>` のパラメーターにあるマークアップを翻訳に移し、データはパラメーターとして渡します。
5. `baseUrl` を設定している場合: `$localeRoute` で作成したリンクを見直し、プロキシの背後では `trustForwardedHost` を設定し、`NUXT_I18N_DOMAIN` を使ってドメインごとに 1 回 `nuxi generate` を実行します。
6. 戦略に照らして URL を確認します: `prefix_except_default` での `/en`、ロケールに似た CMS のスラッグ、`routeRules` のリダイレクト、`excludePatterns`。
7. CDN のキャッシュキーで `Vary` を確認し、厳格な CSP ではプリロードリンクを許可します。`app.cdnURL` を使う場合は、`_locales/` を CDN に置き、CORS を許可します。
8. ツールが `/_locales/...` のファイルを直接読み取る場合は、ページファイルを `__root/<locale>/data.json` の上にマージします。
9. グローバルガードがロケールや辞書を読み取る場合は、ナビゲーションのコミット前に実行されても問題ないことを確認します。レイアウトが前のページのファイルから取得していたキーは、ルートファイルに移動します。
10. `nuxi generate` の出力またはサイトマップのクロール結果を前後で比較します: `hreflang`、`x-default`、canonical、ページ一覧は意図的に変わっています。
11. フレームワークパッケージのインポートを更新します: React、Solid、Preact のアダプターは `/router`、Astro のローダーは `/node`、型プラグインは `I18nTypesPlugin(o)`。
12. Astro では、セットアップをコピーしているだけの `src/middleware.ts` を削除し、`pages/blog-hello/` 形式の辞書をそのパターンの名前に変更します。
13. `router-link-active`、`li button`、`▼`、または古いモックの動作に依存していたテストを更新します。

詳細とすべてのエッジケース: [アップグレード](/jp/guide/upgrade)。

## なぜ重要なのか {#why-it-matters}

- **構造的に正しい:** リンク、リダイレクト、SEO タグは、アプリに実際に存在するルートから得られます。
- **どこでも同じ答え:** ビルド、ソースモード、開発モードが同じ辞書を返し、すべての呼び出し元が 1 つの検出順序を使います。
- **ドメイン:** 2 回目のビルドなしに、すべてのロケールドメインを 1 つのデプロイで。
- **より安全なデフォルト:** エスケープされたパラメーター、上限のあるキャッシュ、オリジンにとどまるリンク。
- **配信するものが少ない:** より小さな辞書ファイル、より小さなルーティングパッケージ、そして 1 か所にまとめられた共通ロジック。

変更の完全な一覧は、[アップグレード](/jp/guide/upgrade)と[変更履歴](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md)を参照してください。
