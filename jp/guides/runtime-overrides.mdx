# ランタイム i18n オーバーライド

1 つのビルド成果物を、環境ごとに異なるロケールデフォルトで実行する必要がある場合(例: テナントごとに異なるインスタンス)、このガイドを使用します。

## ランタイムで上書きできるもの

モジュールは以下について安全なランタイム上書きをサポートします。

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

これらの上書きは `.nuxt/i18n.strategy.mjs` と `.nuxt/i18n.config.mjs` のビルド時設定の上に適用されます。

## ランタイムで上書きできないもの

`strategy`(`no_prefix`、`prefix`、`prefix_except_default`、`prefix_and_default`)は、生成されるルートの動作に影響するためビルド時の関心事です。

ランタイムで戦略の上書きを渡した場合は無視され、警告が出されます。

## RuntimeConfig ベースの上書き

`runtimeConfig.public.i18nRuntime` の下にランタイム値を指定します。

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## 環境変数による上書き

環境変数を通じて上書きを設定することもできます。

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES`(カンマ区切り、例: `fr,it`)

フォールバックエイリアスもサポートされています。

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## 検証ルール

モジュールはランタイム時に上書きを検証し、壊れた状態を避けます。

- すべてのロケールを無効化することはできません。
- `defaultLocale` は有効なロケールを指す必要があります。
- `fallbackLocale` は宣言されたロケールに存在する必要があります。

上書きが無効な場合、モジュールは安全な値を保持し、警告をログに記録します。

## マルチインスタンスデプロイメントに関するメモ

このランタイム機能は、再ビルドせずにインスタンスごとのロケールアクティベーションとデフォルトを設定するために設計されています。

インスタンスが異なる URL 戦略(`no_prefix` と `prefix` など)を必要とする場合は、戦略ごとに別々のビルドを使用してください。

## 無効化されたロケールと静的ペイロード

`runtimeConfig.public.i18nRuntime.disabledLocales` はルーティング、スイッチャー、および Nitro のペイロード**ハンドラー**を更新しますが、Nitro はそのハンドラーの**前**に `public/` 配下のファイルを配信します。

`translationPayloads.publicAssets`(または Node SSR の強制パブリックコピー)がすでに `/_locales/\{page\}/\{locale\}/data.json` を書き込んでいる場合、ランタイムでの無効化ではそのファイルを隠せません。ビルド時に `locale.disabled: true` を設定し、premerge がそのロケールの静的ペイロードを出力しないようにすることを推奨します。
