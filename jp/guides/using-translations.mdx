# コンポーネントでの翻訳の利用

モジュールをインストール・設定したら、Vue のテンプレートやスクリプト内で `$t('your_key')` を呼び出すことで翻訳を表示できます。

## 1. ルートレベルとページ固有の翻訳ファイル

1. **ルートレベル** の翻訳は `/locales` フォルダ直下に配置します（例: `/locales/en.json`、`/locales/fr.json`）。ビルド時に、すべてのページ固有ファイルに自動的にマージされるため、あらゆるページで利用できます。
2. **ページ固有** の翻訳は `/locales/pages/...` 配下に配置し、Nuxt の pages フォルダ構造と一致させます:

```text
locales/
├── en.json
├── fr.json
└── pages/
    └── dir1/
        ├── en.json
        └── fr.json

```

## 2. テンプレートでの `$t` 利用

`.vue` ファイル内では、テンプレートで直接 `$t` を利用できます:

```vue
<template>
  <div>
    <!-- Root-level translation (available on all pages) -->
    <p>{{ $t('test_key') }}</p>
    <!-- Displays: Hello World! -->

    <!-- Page-specific translation (if this page is /dir1) -->
    <p>{{ $t('local_key') }}</p>
    <!-- Displays: This is a page-specific translation for /dir1. -->

    <!-- Nested key -->
    <p>{{ $t('nested.key.deeper') }}</p>
    <!-- Displays: Nested translation here -->

    <!-- Placeholder usage -->
    <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
    <!-- Displays: Hello, Alice! -->
  </div>
</template>

<script setup lang="ts">
// No need to import anything from 'nuxt-i18n-micro'.
// The plugin automatically provides `useI18n` and `$t`.
const { $t } = useI18n()

// You can now use $t in your script, for example:
console.log($t('test_key')) // "Hello World!"
</script>
```

<Tip>
キーがネストされた JSON ノードを指している場合（例: `$t('header')` → `\{ title: "Hi" \}`）、`$t` は **オブジェクト** を返す可能性があります。テンプレートでは `[object Object]` としてレンダリングされます。文字列を確実に得たい場合は `$ts` を使うか、`$t('header.title')` のようにより具体的なキーを指定してください。詳細は [API リファレンス — $t と $ts](/api/methods#t) を参照してください。
</Tip>

## 3. 現在のロケールの切り替え

アプリで言語を切り替えるには、`useI18n()` から `$locale` を取得し、新しいコードを代入します:

```vue
<template>
  <div>
    <button @click="$switchLocale('en')">English</button>
    <button @click="$switchLocale('fr')">Français</button>
  </div>
</template>

<script setup lang="ts">
// The plugin auto-injects these references
const { $t, $switchLocale } = useI18n()
</script>
```

## 4. ネストされたキーとプレースホルダ

- **ネストされたキー** はドット表記を使用します（例: `nested.key.deeper`）。
- **プレースホルダ** は動的な値の埋め込みを可能にします:
  ```json
  { "greeting": "Hello, {name}!" }
  ```
  ```vue
  <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
  <!-- Displays: Hello, Alice! -->
  ```

## 5. ヒントとベストプラクティス

- **競合するキー**: ページ固有ファイルにルートレベルファイルと同じキーが含まれる場合、ページ固有版が優先されます（ルート翻訳はビルド時にベースとしてマージされます）。
- **ページファイルの無効化**: ページ固有翻訳を使いたくない場合、Nuxt 設定で `disablePageLocales: true` を指定できます。この場合、`/locales/*.json` のファイルのみが使用されます。
- **直接インポート不要**: `import \{ useI18n \} from 'nuxt-i18n-micro'` を書く必要はありません。モジュールの自動注入機能がこれを処理します。

以上です！これらの手順で、ルートレベルまたはページ固有の JSON ファイルから **翻訳を取得** し、`$t` を使って Nuxt アプリケーションに **表示** できるようになります。

## 追加リソース

より高度な機能を試したい場合は、以下も参照してください:

1. **`<i18n-t>` コンポーネント**  
   `<i18n-t>` は `$t` の強力な代替であり、ネストされた要素、高度なプレースホルダの利用、より複雑な翻訳構造を扱う場面で特に有用です。

- **ドキュメント**: [i18n-t](/api/components/i18n-t)

2. **`useI18n` コンポーザブル**  
   `useI18n` コンポーザブルは、翻訳、ロケール切り替え、フォーマットなどを扱うための完全な関数・リアクティブプロパティ群を提供します。

- **ドキュメント**: [useI18n](/api/composables/use-i18n)
