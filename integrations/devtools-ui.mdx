`@i18n-micro/devtools-ui` is a self-contained development panel for browsing translation files, editing values, and saving them back to disk without leaving the browser. It ships as three composable pieces:

- A **Vite plugin** that mounts a floating button, wires up API endpoints, and reads/writes JSON files on the dev server.
- A **universal bridge** so any i18n implementation can plug into the panel.
- A **Web Component** (`<i18n-devtools-ui>`) that hosts the UI in isolation.

The panel works with the Nuxt module and every framework integration (Vue, React, Preact, Solid, Astro).

## What it does

- Lists every file under `translationDir`, including `pages/<route>/<locale>.json`.
- Opens files in an editor with key/value forms and JSON validation.
- Saves changes back to disk over a local `/__i18n_api` endpoint.
- Pushes updates into the live i18n cache so open tabs see the change immediately.
- Ships zero code to production builds.

## Quick start with Vite

Register `i18nDevToolsPlugin` in `vite.config.ts`. It injects a floating button that opens the panel and mounts the API endpoints.

```typescript vite.config.ts
import { defineConfig } from 'vite'
import { i18nDevToolsPlugin } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  plugins: [
    i18nDevToolsPlugin({
      translationDir: 'src/locales',
      base: '/__i18n_api',
      injectButton: true,
    }),
  ],
})
```

### Plugin options

| Option           | Type      | Default            | Description |
| ---------------- | --------- | ------------------ | ----------- |
| `base`           | `string`  | `'/__i18n_api'`    | Base path for the API endpoints. |
| `translationDir` | `string`  | `'src/locales'`    | Folder containing translation JSON. |
| `injectButton`   | `boolean` | `true`             | Inject the floating trigger button. |

The button:

- Sits in the bottom-right corner.
- Fades toward the edge when your cursor is more than ~200px away.
- Restores on hover and opens the DevTools UI on click.

## Usage in Nuxt

Nuxt uses Vite under the hood, so add the plugin under `vite.plugins` in `nuxt.config.ts`:

```typescript nuxt.config.ts
import { defineNuxtConfig } from 'nuxt/config'
import { i18nDevToolsPlugin } from '@i18n-micro/devtools-ui/vite'

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  vite: {
    plugins: [
      i18nDevToolsPlugin({
        translationDir: 'locales',
      }),
    ],
  },
})
```

## API endpoints

The plugin exposes these routes under `base` (defaults to `/__i18n_api`):

- `GET /files`: list translation files and directory structure.
- `GET /file?path=<relative-path>`: load a specific file.
- `POST /save`: save an updated JSON file. Body: `{ "file": "en.json", "content": { ... } }`.
- `GET /config`: read the default locale, fallback locale, locales, and translation directory.

The endpoints are also used by external tools such as CI validators or scripts that want to introspect your translation state during development.

## Standalone / custom mount

If you need to place the UI somewhere specific, mount the Web Component yourself and skip the injected button:

```typescript
import { register, createBridge } from '@i18n-micro/devtools-ui'
import type { BridgeAdapter } from '@i18n-micro/devtools-ui'

// Adapt any i18n instance to the panel API.
const adapter: BridgeAdapter = {
  getRouteCache: () => i18n.cache.route,
  addTranslations: (locale, content, merge) => i18n.addTranslations(locale, content, merge),
  addRouteTranslations: (locale, route, content, merge) =>
    i18n.addRouteTranslations(locale, route, content, merge),
  subscribe: (cb) => i18n.subscribe(cb),
  getCurrentLocale: () => i18n.locale,
  getFallbackLocale: () => i18n.fallbackLocale,
}

const bridge = createBridge({
  adapter,
  locales: [
    { code: 'en', displayName: 'English' },
    { code: 'fr', displayName: 'Français' },
  ],
  defaultLocale: 'en',
  translationDir: 'src/locales',
})

register() // registers <i18n-devtools-ui>

const el = document.createElement('i18n-devtools-ui')
;(el as any).bridge = bridge
document.body.appendChild(el)
```

### Bridge adapter contract

```typescript
interface BridgeAdapter {
  getRouteCache: () => Record<string, TranslationContent>  // keyed by "locale:routeName"
  addTranslations: (locale: string, content: TranslationContent, merge: boolean) => void
  addRouteTranslations: (
    locale: string,
    routeName: string,
    content: TranslationContent,
    merge: boolean,
  ) => void
  subscribe: (callback: () => void) => () => void
  getCurrentLocale?: () => string
  getFallbackLocale?: () => string
}
```

Every framework integration (`@i18n-micro/vue`, `@i18n-micro/react`, `@i18n-micro/preact`, `@i18n-micro/solid`, `@i18n-micro/astro`) exposes an i18n instance that lines up with this shape.

## Security

The plugin ships with guardrails, but you still need to keep it out of production:

- **Path traversal protection**: every requested file path is resolved and confirmed to stay inside the project root before reading or writing.
- **JSON only**: the `/save` endpoint rejects any target that is not a `.json` file.
- **Dev only**: the plugin is registered with `apply: 'serve'`, so it is never included in production bundles or SSR builds.

<Warning>
Never expose `i18nDevToolsPlugin` on a production or staging server. It is intended for `vite dev` on `localhost` only. If you host a preview build behind a network, disable the plugin or omit `injectButton` and gate the endpoints yourself.
</Warning>
