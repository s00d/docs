---
title: "Types generator"
description: "Auto-generate strict TypeScript types for translation keys, plural forms, and $t signatures from your JSON locale files with @i18n-micro/types-generator."
---

`@i18n-micro/types-generator` scans your translation JSON, flattens every key, and augments `@i18n-micro/types` so `TranslationKey` becomes the exact union of keys your project actually has. `t('...')`, `ts('...')`, `tc('...')`, and `has('...')` then get autocomplete and compile-time errors on typos.

- **Zero runtime cost**: the plugin only emits `.d.ts` output.
- **Framework-wide**: works with Nuxt, Vue, React, Preact, Solid, and Astro through the same Vite plugin.
- **Watched**: regenerates on save while `nuxt dev` or `vite dev` is running.

## Nuxt setup

Add the Nuxt integration alongside `nuxt-i18n-micro`:

```typescript nuxt.config.ts
import { defineNuxtConfig } from 'nuxt/config'

export default defineNuxtConfig({
  modules: [
    'nuxt-i18n-micro',
    '@i18n-micro/types-generator/nuxt',
  ],
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    translationDir: 'locales',
  },
})
```

By default the module:

- Reads JSON files from your configured `translationDir`.
- Writes `.nuxt/i18n-micro.d.ts` on every build and dev restart.
- Watches translation files and regenerates on change.

<Tip>
The Nuxt module option `types: true` on `nuxt-i18n-micro` and this generator are complementary. The core module sets up typed helpers and composables; the generator fills them with your actual translation keys. Use both for the best DX.
</Tip>

### Nuxt options

```typescript nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@i18n-micro/types-generator/nuxt'],
  i18nTypes: {
    translationDir: 'locales',
    outputFile: '.nuxt/custom-types.d.ts',
  },
})
```

## Vite setup (Vue, React, Preact, Solid, Astro)

Register the Vite plugin. It works in any Vite project regardless of framework.

```typescript vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { I18nTypesPlugin } from '@i18n-micro/types-generator'

export default defineConfig({
  plugins: [
    vue(),
    I18nTypesPlugin({
      srcDir: 'src',
      translationDir: 'locales',
      outputFile: 'src/i18n-types.d.ts',
    }),
  ],
})
```

Include the generated file so `tsc` and your editor pick it up:

```json tsconfig.json
{
  "include": ["src/**/*", "src/i18n-types.d.ts"]
}
```

For Astro, add the plugin under `vite.plugins` in `astro.config.mjs`.

### Plugin options

| Option           | Type     | Description |
| ---------------- | -------- | ----------- |
| `srcDir`         | `string` | Base directory used to resolve `translationDir` (default: `'src'`). |
| `translationDir` | `string` | Folder containing translation JSON (default: `'locales'`). |
| `outputFile`     | `string` | Path to write the augmentation file. |

## Translation layout

The generator supports flat, nested, and route-scoped structures:

```bash
locales/
├── en.json
├── fr.json
└── pages/
    ├── home/
    │   ├── en.json
    │   └── fr.json
    └── about/
        ├── en.json
        └── fr.json
```

```json locales/en.json
{
  "greeting": "Hello, {name}!",
  "header": { "title": "Welcome", "subtitle": "Nice to see you" },
  "errors": { "404": "Not found", "500": "Server error" },
  "apples": "no apples | one apple | {count} apples"
}
```

All keys are flattened with dot notation and merged across locales and route folders.

## Generated output

The plugin emits a declaration file that augments `@i18n-micro/types`:

```typescript src/i18n-types.d.ts
declare module '@i18n-micro/types' {
  export interface DefineLocaleMessage {
    greeting: string
    'header.title': string
    'header.subtitle': string
    'errors.404': string
    'errors.500': string
    apples: string
  }
}
```

Because `TranslationKey` in `@i18n-micro/types` is derived from `DefineLocaleMessage`, every downstream helper (`useI18n`, `<I18nT>`, `t()`, `has()`, `tc()`) automatically inherits the union.

## Using the types

```typescript
import { useI18n } from '@i18n-micro/vue'

const { t, tc, has } = useI18n()

t('greeting', { name: 'World' })  // ✅ typed
t('header.title')                 // ✅ typed
t('errors.404')                   // ✅ typed
t('invalid.key')                  // ❌ compile error
```

<Note>
Inside a Nuxt project, the strong typing flows through the `useI18n` composable. Direct access to `$i18n` on `NuxtApp` stays loosely typed, so prefer the composable in application code.
</Note>

## Dynamic keys with ScopedKey

Runtime type guards would defeat the "no bundle bloat" goal, so `@i18n-micro/types` ships two utilities for the common cases:

```typescript
import type { TranslationKey, ScopedKey } from '@i18n-micro/types'

// Assert when you know the key exists.
t(`status.${status}` as TranslationKey)

// Narrow by prefix. TypeScript still verifies the prefix exists.
function getErrorText(code: string) {
  return t(`errors.${code}` as ScopedKey<'errors'>)
}

// Check at runtime.
if (has(`status.${status}`)) {
  t(`status.${status}` as TranslationKey)
}
```

## Manual generation

Both the CLI-style helper and the internal utilities are exported for scripts and CI checks:

```typescript scripts/generate-i18n-types.ts
import { generateTypes, flattenKeys } from '@i18n-micro/types-generator'

await generateTypes({
  srcDir: './src',
  translationDir: 'locales',
  outputFile: './src/i18n-types.d.ts',
})

// Inspect a subtree if needed.
const keys = flattenKeys({
  header: { title: 'Title' },
  footer: { copyright: '© 2024' },
})
// -> ['header.title', 'footer.copyright']
```

The helpers `generateTypes` and `getTypesString` are exported from `@i18n-micro/types-generator` for pipelines that want to inspect or diff the output before writing it.

## Interaction with the Nuxt module's `types` option

- The Nuxt module (`nuxt-i18n-micro`) with `types: true` wires up global auto-imports and the type of the `useI18n` composable.
- The types generator produces the concrete `TranslationKey` union by inspecting your files.
- Enabling both means: composables are typed by the module, and their string arguments are narrowed by the generator.

If you only enable one, either global helpers stay loosely typed (module off) or `TranslationKey` stays as `string` (generator off).

## Troubleshooting

- **Types missing after adding a key**: restart the TS server (`Cmd/Ctrl + Shift + P` → `TypeScript: Restart TS Server`).
- **Types not picked up**: confirm the generated file is in `tsconfig.json > include`.
- **Autocomplete fails**: check `outputFile` and that the module augmentation still targets `'@i18n-micro/types'`.
- **JSON errors are silent**: invalid JSON files are skipped; look for warnings in the dev-server log.

TypeScript 4.1 or newer is required (template literal types).

## How it works

1. Uses `globby` to find every `**/*.json` under the translation folder.
2. Parses each file and flattens keys recursively.
3. Deduplicates across locales and route folders.
4. Emits a `declare module '@i18n-micro/types'` augmentation with the union.
5. In dev, watches for file changes and rewrites the output.
