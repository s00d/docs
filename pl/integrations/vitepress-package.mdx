`@i18n-micro/vitepress` dodaje do serwisu VitePress słowniki ładowane w czasie działania: `$t` i `<I18nT>` w markdownie, funkcje pomocnicze ścieżek i tagi SEO, zbudowane na [`@i18n-micro/vue`](/pl/integrations/vue-package). Używaj go, gdy te same teksty interfejsu pojawiają się na wielu stronach i nie chcesz ich duplikować dla każdego locale. Locale podąża za własnymi locale ścieżek VitePress (`/`, `/fr/`).

## Kiedy go używać {#when-to-use-it}

| Potrzeba | Rozwiązanie |
|------|----------|
| Zduplikowane pliki `.md`, prefiksy URL | `locales` VitePress |
| `$t` w czasie działania / komponenty / synchronizacja ścieżek / SEO w head | `@i18n-micro/vitepress` |
| Etykiety elementów domyślnego motywu (`docFooter`, interfejs wyszukiwania) | Własne `themeConfig` dla każdego locale |

<Tip>

**Playground** — [`packages/vitepress/playground`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/vitepress/playground) — `pnpm -C packages/vitepress/playground dev`

</Tip>

## Instalacja {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vitepress
```

```bash npm
npm install @i18n-micro/vitepress
```

```bash yarn
yarn add @i18n-micro/vitepress
```

</CodeGroup>

Zależności peer: `vitepress` `>=1.0.0 || >=2.0.0-alpha.0`, `vue` `^3.3.0`. Skrypty Node używają `@i18n-micro/node`, instalowanego razem z pakietem i reeksportowanego przez `/node`. Opublikowane typy wymagają Vue 3.5.5 lub nowszego przy `skipLibCheck: false`; przy `skipLibCheck: true`, typowym ustawieniu szablonu, kompilują się też starsze wersje.

## Konfiguracja {#setup}

```
locales/en.json
locales/fr.json
locales/pages/guide/demo/en.json   # optional page-scoped
locales/pages/guide/demo/fr.json
```

Pliki stron są mapowane na nazwy tras tak samo jak w Nuxt/Astro (`guide/demo` → `guide-demo`).

### 1. Konfiguracja — `@i18n-micro/vitepress/config` {#1-config-—-@i18n-micro/vitepress/config}

```ts
// .vitepress/config.mts
import { defineConfig } from 'vitepress'
import { withI18n, buildVitePressLocales } from '@i18n-micro/vitepress/config'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English', og: 'en_US' },
  { code: 'fr', iso: 'fr-FR', displayName: 'Français', og: 'fr_FR' },
]
const defaultLocale = 'en'

export default defineConfig(
  withI18n(
    {
      locales: buildVitePressLocales(locales, defaultLocale),
      // themeConfig.i18nRouting is injected automatically
    },
    {
      locale: defaultLocale,
      defaultLocale,
      locales,
      translationDir: 'locales',
      metaBaseUrl: 'https://example.com', // optional SEO head
    },
  ),
)
```

### 2. Motyw — `@i18n-micro/vitepress/theme` {#2-theme-—-@i18n-micro/vitepress/theme}

```ts
// .vitepress/theme/index.ts
import DefaultTheme from 'vitepress/theme'
import { defineI18nTheme } from '@i18n-micro/vitepress/theme'

export default defineI18nTheme(DefaultTheme)
```

Początkowe locale jest pobierane z bieżącej ścieżki przed instalacją (bez mignięcia domyślnego locale na `/fr/…`).

### Zaawansowane: ręczne `createI18n` {#advanced-manual-createi18n}

Jedna fabryka dla klienta: plugin Vue + metody ścieżek + `enhanceApp` (bez osobnych eksportów funkcji pomocniczych routera).

```ts
import { createI18n, messagesFromGlob } from '@i18n-micro/vitepress'

const i18n = createI18n({
  locale: 'en',
  defaultLocale: 'en',
  locales: [{ code: 'en' }, { code: 'fr' }],
  messages: messagesFromGlob(import.meta.glob('../../locales/*.json', { eager: true })),
})

i18n.localizePath('/guide', 'fr')
// in theme enhanceApp:
i18n.enhanceApp({ app, router })
```

### Skrypty Node — `@i18n-micro/vitepress/node` {#node-scripts-—-@i18n-micro/vitepress/node}

Używa `createI18n` / `loadTranslations` z `@i18n-micro/node` (tak samo jak Astro i CLI), a następnie dołącza metody ścieżek VitePress za pomocą `BaseI18n.extend`:

```ts
import { createI18n } from '@i18n-micro/vitepress/node'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  translationDir: './locales',
  locales: ['en', 'fr'],
  defaultLocale: 'en',
})
await i18n.loadTranslations()
i18n.t('cta.readMore')
i18n.localizePath('/guide', 'fr')
```

Czysty Node bez ścieżek: `import { createI18n } from '@i18n-micro/node'`.

## Tłumaczenia na stronie {#in-page-translations}

Każdy plik markdown VitePress jest komponentem Vue SFC.

### Komponenty globalne i `$t` (zalecane w markdownie) {#global-components-and-$t-recommended-in-markdown}

`createI18n` / `defineI18nTheme` instalują `@i18n-micro/vue`, który rejestruje `I18nT` / `I18nLink` / `I18nGroup` / `I18nSwitcher` oraz `$t` / `$tc` / `$ts`.

```md
{{ $t('cta.readMore') }}

<I18nT keypath="greeting" :params="{ name: 'VitePress' }" />

<I18nLink to="/guide/demo">Demo</I18nLink>
```

### `useI18n` w `<script setup>` {#usei18n-in-<script-setup>}

```md
<script setup>
import { useI18n } from '@i18n-micro/vitepress'
const { t, tc, locale, localePath, switchLocale } = useI18n()
</script>

# {{ t('section.title') }}
```

## Lista wyboru języka {#language-dropdown}

Gdy `locales` ma więcej niż jeden wpis, VitePress pokazuje własne menu języków (`VPNavBarTranslations`). `withI18n` podłącza `themeConfig.i18nRouting`, dzięki czemu ikona globu jest zgodna z `<I18nSwitcher>` / funkcjami pomocniczymi ścieżek.

Używaj `<I18nSwitcher>` tylko we własnych layoutach, nie obok domyślnego globu.

## Uwagi dotyczące SSR {#ssr-notes}

- Locale podczas prerenderowania pochodzi ze ścieżki URL, a nie z cookies.
- Kod motywu nie może odwoływać się do `window` w czasie importu.
- Importuj `defineI18nTheme` z `/theme`, aby ewaluacja konfiguracji w Node nigdy nie ładowała `virtual:i18n-micro/*`.

## Powierzchnia API {#api-surface}

| Eksport | Rola |
|--------|------|
| `createI18n` (`.`) | Klient: plugin Vue + metody ścieżek + `enhanceApp` |
| `getLocaleFromPath` / `stripSiteBase` / `routeNameFromPath` (`.`) | Ręczna synchronizacja locale przy `syncWithVitePress: false` |
| `createI18n` (`/node`) | Node: `@i18n-micro/node` + metody ścieżek |
| `defineI18nTheme` (`/theme`) | Motyw bez kodu szablonowego |
| `withI18n` (`/config`) | Konfiguracja + moduły wirtualne + opcjonalne SEO |
| `buildVitePressLocales` (`/config`) | Buduje `locales` VitePress z `Locale[]` |
| `buildVitePressLocaleHead` (`/config`) | Ręczne SEO w head (używane też przez `metaBaseUrl`) |
| `messagesFromGlob` | Opcjonalne mapowanie glob → wiadomości dla `createI18n` |
| `useI18n` / `I18nT` / … | Reeksportowane z `@i18n-micro/vue` |
| `BaseI18n.extend` (`@i18n-micro/core`) | Dołącza własne metody do dowolnej instancji i18n |

## Serwisy w stylu OpenAPI (blokady integracyjne) {#openapi-style-sites-integration-locks}

Zestaw testów regresyjnych: `packages/vitepress/tests/integration-openapi.test.ts` (głębokie ścieżki, `base=/openapi_docs/`, wyłączona synchronizacja + ręczne locale, generatory Node, SEO).

| Wzorzec | Co zrobić |
|---------|---------|
| Głębokie strony `/…/{spec}/{op}`, tylko główny JSON interfejsu | Wybierz domyślne `syncWithVitePress: true` (zachowuje `setRoute('index')`, gdy nie ma słownika strony) **lub** `syncWithVitePress: false` + `getLocaleFromPath` |
| Nigdy nie wywołuj `setRoute(deepName)` bez słowników stron | Główne klucze interfejsu znikają aż do `setRoute('index')` |
| Generatory / `getTranslation` | `createI18n` z `/node` + `await loadTranslations()` + `i18n.t(key)` (ustaw `i18n.locale`) |
| Własny canonical w `transformPageData` | Przekaż `meta: false` do `withI18n` (unikniesz podwójnych tagów) |
| SEO pakietu z bazą serwisu | `metaBaseUrl` + `base` VitePress → bezwzględne adresy URL zawierają bazę |
| Zmiany nazw względem starszych buildów pakietu | `withI18nMicro` → `withI18n`, `createVitePressI18n` → `createI18n`, `loadMessages` → `createI18n` z node |
