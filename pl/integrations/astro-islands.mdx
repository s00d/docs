title: "Wyspy Astro"
description: "Tłumaczenia w wyspach Vue, React, Preact i Svelte z @i18n-micro/astro."
---

Wyspa działa w przeglądarce, gdzie instancja i18n serwera nie istnieje. `@i18n-micro/astro` pozwala stronie wybrać klucze potrzebne wyspie, przekazać je jako jeden prop i odczytać je w wyspie przez mały adapter frameworka. Dostajesz `t`, `tc`, `tn`, `td`, `tdr` i `has` w wyspach Vue, React, Preact i Svelte, a w HTML trafiają tylko wybrane teksty.

## Konfiguracja {#setup}

Najpierw skonfiguruj [integrację Astro i middleware](/pl/integrations/astro-package#setup), a następnie dodaj integrację używanego frameworka (`@astrojs/vue`, `@astrojs/react`, `@astrojs/preact`, `@astrojs/svelte`). Adaptery wysp wymagają tego frameworka jako zależności peer: `vue` `^3.3.0`, `react` `^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`, `preact` `^10.0.0 || ^11.0.0` lub `svelte` `^4.0.0 || ^5.0.0`.

## Przekazywanie tłumaczeń do wyspy {#pass-translations-to-an-island}

```astro
---
// src/pages/index.astro
import { getI18nProps } from '@i18n-micro/astro'
import Counter from '../components/Counter.vue'

const i18n = getI18nProps(Astro, ['counter.title', 'counter.apples'])
---

<Counter client:load i18n={i18n} />
```

`getI18nProps(Astro, keys?)` zwraca `{ locale, fallbackLocale, currentRoute, translations }` (typ `I18nClientProps`). Przekaż klucze używane przez wyspę: każdy jest rozwiązywany na serwerze tak jak przez `t()` (słowniki trasy, główny i zapasowy), a do HTML trafiają tylko znalezione klucze. Bez `keys` wysyłane jest wszystko, na co `t()` może odpowiedzieć na tej stronie, i to w każdej wyspie, więc 2000 kluczy głównych to około 100 KB na wyspę; w trybie deweloperskim powyżej 20 KB pojawia się ostrzeżenie.

Wyspy tłumaczą wyłącznie na podstawie tego obiektu. `t` zwraca klucz dla wszystkiego, czego nie przekazano, a wiadomości powiązane (linked messages) nie są rozwiązywane.

## Vue {#vue}

Wywołaj `provideI18n(() => props.i18n)` w głównym komponencie wyspy, a `useAstroI18n()` w jego dzieciach. `inject` w Vue nie widzi wartości dostarczonej przez ten sam komponent, więc hook musi działać w dziecku, a nie w komponencie głównym:

```vue
<!-- src/components/Counter.vue -->
<script setup lang="ts">
import { provideI18n } from '@i18n-micro/astro/client/vue'
import type { I18nClientProps } from '@i18n-micro/astro'
import CounterBody from './CounterBody.vue'

const props = defineProps<{ i18n: I18nClientProps }>()
provideI18n(() => props.i18n)
</script>

<template><CounterBody /></template>
```

```vue
<!-- src/components/CounterBody.vue -->
<script setup lang="ts">
import { ref } from 'vue'
import { useAstroI18n } from '@i18n-micro/astro/client/vue'

const { t, tc } = useAstroI18n()
const count = ref(0)
</script>

<template>
  <h3>{{ t('counter.title') }}</h3>
  <button @click="count++">{{ tc('counter.apples', count) }}</button>
</template>
```

## React i Preact {#react-and-preact}

```tsx
// src/components/Counter.tsx
import { useState } from 'react'
import { I18nProvider, useAstroI18n } from '@i18n-micro/astro/client/react'
import type { I18nClientProps } from '@i18n-micro/astro'

function Body() {
  const { t, tc } = useAstroI18n()
  const [count, setCount] = useState(0)
  return <button onClick={() => setCount(count + 1)}>{t('counter.title')}: {tc('counter.apples', count)}</button>
}

export default function Counter({ i18n }: { i18n: I18nClientProps }) {
  return (
    <I18nProvider value={i18n}>
      <Body />
    </I18nProvider>
  )
}
```

W Preact importuj `I18nProvider` i `useAstroI18n` z `@i18n-micro/astro/client/preact`; API jest takie samo.

## Svelte {#svelte}

```svelte
<!-- src/components/Counter.svelte -->
<script lang="ts">
  import { createI18nStore, useAstroI18n } from '@i18n-micro/astro/client/svelte'
  import type { I18nClientProps } from '@i18n-micro/astro'

  export let i18n: I18nClientProps
  const { t, tc } = useAstroI18n(createI18nStore(i18n))
  let count = 0
</script>

<button on:click={() => count++}>{t('counter.title')}: {tc('counter.apples', count)}</button>
```

`useAstroI18n(store)` zwraca też `store` do odczytów `$store` w szablonie.

## Wyspy utrwalone {#persisted-islands}

Wyspa z `transition:persist` dostaje nowe propsy po nawigacji. React, Preact i Vue (gdy przekazano getter) za nimi podążają. W Svelte zachowaj store i przekazuj je dalej: `const store = createI18nStore(i18n)`, `const { t } = useAstroI18n(store)`, a następnie `$: store.set(i18n)` (z runami: `$effect(() => store.set(i18n))`).

## API {#api}

| Punkt wejścia | Eksporty |
| --- | --- |
| `@i18n-micro/astro` | `getI18nProps`, typ `I18nClientProps` |
| `@i18n-micro/astro/client/vue` | `provideI18n(props \| () => props)`, `useAstroI18n()` |
| `@i18n-micro/astro/client/react` | `I18nProvider` (prop `value`), `useAstroI18n()` |
| `@i18n-micro/astro/client/preact` | `I18nProvider` (prop `value`), `useAstroI18n()` |
| `@i18n-micro/astro/client/svelte` | `createI18nStore(props)`, `useAstroI18n(store)` |
| `@i18n-micro/astro/client` | czyste `translate`, `hasTranslation`, bez frameworka |

Każde `useAstroI18n` zwraca `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `setLocale`, `setRoute` oraz `locale`. Wyspa ma jeden scalony słownik, więc jej `has` zwraca true dla klucza, na który `t` może odpowiedzieć, także z zapasowego locale; na serwerze `has` sprawdza tylko aktywne locale.
