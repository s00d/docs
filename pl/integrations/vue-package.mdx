`@i18n-micro/vue` to wtyczka Vue 3 z rdzeniem tłumaczeń Nuxt I18n Micro: reaktywne `t()`, globalne `$t`, cztery komponenty i opcjonalny adapter vue-router. Używaj jej w aplikacji Vue opartej na Vite lub SSR, która nie jest budowana z Nuxt. Model instancji, kontrakt routera i propsy komponentów są wspólne z innymi pakietami i opisane w [Frameworki](/pl/integrations/overview).

## Instalacja {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vue
```

```bash npm
npm install @i18n-micro/vue
```

```bash yarn
yarn add @i18n-micro/vue
```

</CodeGroup>

Zależności peer: `vue` `^3.3.0`; `vue-router` `^4.5.1 || ^5.0.0` (opcjonalnie, tylko dla `@i18n-micro/vue/router`). Opublikowane typy wymagają Vue 3.5.5 lub nowszego przy `skipLibCheck: false`; przy `skipLibCheck: true`, typowym ustawieniu szablonów, starsze wersje również się kompilują.

## Konfiguracja {#setup}

```ts
// src/main.ts
import { createApp } from 'vue'
import { createI18n } from '@i18n-micro/vue'
import App from './App.vue'
import en from './locales/en.json'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales: [
    { code: 'en', iso: 'en-US', displayName: 'English' },
    { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
  ],
  defaultLocale: 'en',
})

createApp(App).use(i18n).mount('#app')
```

`locales` i `defaultLocale` są wymagane przez `useI18n()`: bez nich rzuca `I18nLocalesKey not provided`. Przekaż je do `createI18n` (jak powyżej), do `useI18n({ locales, defaultLocale })` lub przez `app.provide(I18nLocalesKey, …)` i `app.provide(I18nDefaultLocaleKey, …)`.

Wtyczka rejestruje globalnie `I18nT`, `I18nLink`, `I18nGroup` i `I18nSwitcher` oraz dodaje do szablonów `$t`, `$ts`, `$tc`, `$tn`, `$td`, `$tdr`, `$has` i `$i18n`. Poza komponentami instancja to `i18n.global`. Pozostałe opcje opisano w sekcji [instancja](/pl/integrations/overview#the-instance); `routeMessages` nie jest dostępne w Vue, użyj `addRouteTranslations`.

## Tłumaczenie {#translate}

```vue
<script setup lang="ts">
import { useI18n } from '@i18n-micro/vue'

const { t, tc, tn } = useI18n()
</script>

<template>
  <h1>{{ t('greeting', { name: 'Ada' }) }}</h1>
  <!-- Hello, Ada! -->
  <p>{{ tc('apples', 3) }}</p>
  <!-- 3 apples -->
  <p>{{ $t('nav.home') }} · {{ tn(1234.5) }}</p>
</template>
```

`useI18n()` zwraca metody tłumaczące (`t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`), `locale` (zapisywalny computed), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `localePath`, `localeRoute`, `switchLocale`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `mergeTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` i `instance`.

Kolejne słowniki możesz ładować w dowolnym momencie; każdy komponent, który z nich czyta, zostanie ponownie wyrenderowany:

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Przełączanie locale {#switch-locale}

```ts
const { locale, switchLocale } = useI18n()

locale.value = 'de' // only the locale
switchLocale('de') // the locale, then router.push to the localized current path
```

Załaduj słownik locale przed przełączeniem lub po nim; przełączanie niczego nie pobiera.

`<I18nGroup>` przekazuje do swojego slotu `t` z prefiksem. Klucze wewnątrz `<I18nT>` ani w zwykłym `t()` nie otrzymują prefiksu:

```vue
<I18nGroup prefix="profile" v-slot="{ t }">
  <h2>{{ t('title') }}</h2>
  <!-- profile.title -->
</I18nGroup>
```

## Routing {#routing}

Adapter vue-router znajduje się w podścieżce, dzięki czemu główny punkt wejścia nigdy nie importuje `vue-router`:

```ts
// src/main.ts
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import { createI18n } from '@i18n-micro/vue'
import { createVueRouterAdapter } from '@i18n-micro/vue/router'
import App from './App.vue'
import Home from './pages/Home.vue'
import About from './pages/About.vue'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/:locale(de)?', component: Home },
    { path: '/:locale(de)?/about', component: About },
  ],
})

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales,
  defaultLocale: 'en',
  routingStrategy: createVueRouterAdapter(router, locales, 'en'),
})

createApp(App).use(router).use(i18n).mount('#app')
```

`createVueRouterAdapter(router, locales, defaultLocale)` dodaje prefiks do każdego locale oprócz domyślnego (`/about`, `/de/about`) i renderuje `<I18nLink>` jako `RouterLink`. Locale z trasy odczytaj samodzielnie, na przykład w `router.beforeEach`, i ustaw `i18n.global.locale.value`. Adapter możesz też podłączyć później za pomocą `i18n.setRoutingStrategy(adapter)`; niestandardowy adapter opisano w [Adapter routera](/pl/integrations/overview#router-adapter).

## SSR {#ssr}

- Twórz router, instancję i18n i aplikację wewnątrz funkcji renderującej wywoływanej dla każdego żądania. Jedna współdzielona instancja przenosiłaby locale jednego odwiedzającego do innego.
- Na serwerze używaj `createMemoryHistory()`, pobierz locale z adresu URL i załaduj jego słownik (oraz słownik zapasowy) przed `renderToString`.
- Prześlij locale do klienta (na przykład w skrypcie `window.__STATE__`) i utwórz instancję klienta z tym samym `locale`, aby hydratacja się zgadzała.
- `<I18nSwitcher>` odczytuje `window.location` tylko wtedy, gdy lista rozwijana jest otwarta, więc renderuje się na serwerze.

`packages/vue/playground` zawiera kompletną parę `entry-server.ts` / `entry-client.ts`.

## SEO w head {#seo-head}

`useLocaleHead(options)` buduje `lang`/`dir`, canonical, tagi `hreflang` i `og:locale` na podstawie locale i adaptera routera. Wywołuj `updateMeta()` przy zmianie trasy i przekaż `metaObject` do swojego menedżera head:

```ts
import { watch } from 'vue'
import { useRoute } from 'vue-router'
import { useHead } from '@unhead/vue'
import { useLocaleHead } from '@i18n-micro/vue'

const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
watch(() => route.fullPath, () => updateMeta(), { immediate: true })
useHead(metaObject)
```

Opcje: `baseUrl` (ciąg znaków lub funkcja), `addDirAttribute` (domyślnie `true`), `addSeoAttributes` (domyślnie `true`), `identifierAttribute` (domyślnie `'id'`), `hreflangBaseLanguage` (domyślnie `false`). Locale z `disabled: true` lub `seo: false` nie otrzymują linku alternatywnego.
