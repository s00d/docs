`@i18n-micro/solid` daje aplikacjom SolidJS instancję i18n opartą na sygnałach, providera, `useI18n()` i cztery komponenty. Używaj go w aplikacji Solid, która nie jest zbudowana z Nuxt. Odczyty `t()` wewnątrz JSX lub efektów śledzą lokalizację, trasę i słowniki; wspólny model opisano w [Frameworkach](/pl/integrations/overview).

## Instalacja {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Zależności peer: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (opcjonalnie, tylko dla `@i18n-micro/solid/router`). Solid 2 nie jest jeszcze obsługiwany.

## Konfiguracja {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` przyjmuje `i18n`, `locales`, `defaultLocale` i `routingStrategy`; pominięta właściwość zachowuje wartość zewnętrznego providera, łącznie z instancją. `getLocaleName()` i `<I18nSwitcher>` odczytują `locales`; bez nich nie mają czego wyświetlić. Opcje opisano w sekcji [instancja](/pl/integrations/overview#the-instance). Instancja pochodzi z [runtime](/pl/integrations/runtime-package), z jednym sygnałem nad jej magazynem.

## Tłumaczenie {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Wywołuj metody wewnątrz JSX lub efektu, aby Solid je śledził, również `localePath` i `getLocale`; wartość odczytana raz w ciele komponentu nie aktualizuje się. W instancji śledź za pomocą `i18n.locale` i `i18n.currentRoute`: `i18n.getLocale()` pozostaje zwykłą funkcją, ponieważ odczytują ją operacje zapisu. Odczyt lokalizacji reaguje wyłącznie na zmianę lokalizacji, więc efekt, który ją odczytuje i wczytuje słownik, uruchamia się raz. Nie destrukturyzuj właściwości i nie przechowuj wyników `t('key')` w zwykłych zmiennych.

`useI18n()` zwraca `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (akcesor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` i `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Przełączanie lokalizacji {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Przełączenie niczego nie wczytuje; najpierw dodaj słownik danej lokalizacji.

`<I18nGroup>` przekazuje `t` z prefiksem do dziecka będącego funkcją. `<I18nT>` i `t()` wewnątrz niego nie mają prefiksu:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Routing {#routing}

Adapter `@solidjs/router` znajduje się w osobnej ścieżce podrzędnej, dzięki czemu główny punkt wejścia nigdy nie importuje routera. Wywołuj go pod routerem, zazwyczaj w `root` routera, gdzie działają `useNavigate` i `useLocation`:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

Adapter dodaje prefiks do każdej lokalizacji z wyjątkiem domyślnej (`/about`, `/de/about`) i renderuje `<I18nLink>` jako `<A>` routera. `getCurrentPath` odczytuje reaktywną lokalizację routera, więc aktywne linki i przełącznik za nią podążają; niestandardowa strategia uzyskuje to samo, odczytując tam sygnał. Zwróć uwagę na kolejność argumentów: `(locales, defaultLocale, navigate, location)`. Dla innych routerów napisz adapter z `getCurrentPath`, `push` i `replace` (wszystkie wymagane) — zobacz [Adapter routera](/pl/integrations/overview#router-adapter).

## SSR {#ssr}

Do renderowania po stronie serwera buduj z `vite-plugin-solid`: warunek eksportu `solid` pakietu przekazuje mu kod źródłowy, więc kompiluje się on dla serwera. Gotowy `dist` jest przeznaczony wyłącznie dla przeglądarki. Instancja nie ma `destroy()`; twórz jedną na aplikację lub jedną na żądanie na serwerze i pozwól, by została usunięta przez garbage collector.
