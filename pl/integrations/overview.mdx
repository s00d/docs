# Integracje

Pakiety `@i18n-micro` to lekkie, specyficzne dla frameworków wersje Nuxt I18n Micro zaprojektowane do integracji z różnymi frameworkami i środowiskami. Te pakiety zapewniają podstawową funkcjonalność internacjonalizacji przy minimalnym śladzie, koncentrując się na kluczowych funkcjach tłumaczeń i podstawowych komponentach.

## Omówienie

Te pakiety integracyjne to **miniaturowe wersje** pełnego modułu Nuxt I18n Micro, zawierające tylko niezbędną funkcjonalność do internacjonalizacji:

- **Podstawowe funkcje tłumaczeń** — metody tłumaczeń, pluralizacja i formatowanie
- **Kluczowe komponenty** — niewielki zestaw komponentów UI do typowych zadań i18n
- **Wzorzec adaptera routera** — elastyczna integracja routingu przez abstrakcję adaptera
- **Wsparcie TypeScript** — pełne definicje typów dla programowania bezpiecznego typowo

W przeciwieństwie do pełnego modułu Nuxt, te pakiety:

- Nie zawierają logiki routingu specyficznej dla frameworka
- Wymagają, abyś zaimplementował adapter routera dla funkcji routingu
- Skupiają się na funkcjonalności tłumaczeń, a nie na integracji z frameworkiem
- Są zaprojektowane tak, aby były lekkie i, gdzie to możliwe, niezależne od frameworka

## Kluczowe komponenty

Wszystkie pakiety frameworkowe zawierają następujące kluczowe komponenty:

### `<I18nT>`

Komponent tłumaczeń, który renderuje przetłumaczony tekst z obsługą:

- **Interpolacja parametrów** — zastąp placeholdery dynamicznymi wartościami
- **Pluralizacja** — automatyczny wybór formy liczby mnogiej na podstawie liczby
- **Formatowanie liczb** — formatuj liczby zgodnie z lokalizacją
- **Formatowanie dat** — formatuj daty i czasy względne
- **Renderowanie HTML** — opcjonalne renderowanie zawartości HTML
- **Wartości domyślne** — tekst zapasowy, gdy brakuje tłumaczenia

**Przykład:**

```vue
<!-- Vue -->
<I18nT keypath="greeting" :params="{ name: 'World' }" />
```

```tsx
// React
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```tsx
// Solid
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```astro
<!-- Astro -->
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

### `<I18nLink>`

Komponent linku zlokalizowanego, który automatycznie obsługuje prefiksy lokalizacji w URL-ach. Funkcje:

- **Automatyczna lokalizacja ścieżek** — dodaje/usuwa prefiksy lokalizacji w zależności od strategii routingu
- **Wykrywanie stanu aktywnego** — podświetla bieżącą trasę
- **Wsparcie linków zewnętrznych** — automatycznie wykrywa i obsługuje URL-e zewnętrzne
- **Integracja routera** — używa komponentu linku adaptera routera, gdy jest dostępny
- **Niestandardowa stylizacja** — obsługuje stany aktywne i hover

**Przykład:**

```vue
<!-- Vue -->
<I18nLink to="/about" active-class="active">
  About Us
</I18nLink>
```

```tsx
// React
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```tsx
// Solid
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```astro
<!-- Astro -->
<I18nLink href="/about" class="nav-link">
  About Us
</I18nLink>
```

### `<I18nSwitcher>`

Komponent przełącznika języka, który zapewnia rozwijaną listę lub interfejs listy do zmiany lokalizacji. Funkcje:

- **Automatyczna lista lokalizacji** — generuje opcje ze skonfigurowanych lokalizacji
- **Podświetlanie bieżącej lokalizacji** — wizualnie wskazuje aktywny język
- **Niestandardowe etykiety** — obsługa niestandardowych nazw wyświetlanych per lokalizacja
- **Integracja routera** — automatycznie przenosi do zlokalizowanych ścieżek
- **Dostępność** — prawidłowe atrybuty ARIA i nawigacja klawiaturą

**Przykład:**

```vue
<!-- Vue -->
<I18nSwitcher />
```

```tsx
// React
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```tsx
// Solid
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```astro
<!-- Astro -->
<I18nSwitcher />
```

### `<I18nGroup>`

Komponent do grupowania tłumaczeń pod wspólnym prefiksem, przydatny do organizowania tłumaczeń per strona lub funkcja. Funkcje:

- **Zakres prefiksu** — automatycznie dodaje prefiks do wszystkich kluczy tłumaczeń w grupie
- **Zagnieżdżone grupy** — obsługa zagnieżdżonych grup tłumaczeń
- **Czysta organizacja** — pomaga utrzymywać uporządkowane struktury tłumaczeń

**Przykład:**

```vue
<!-- Vue -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

```tsx
// React
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```tsx
// Solid
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```astro
<!-- Astro -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

## Wspólne opcje `createI18n` \{#create-i18n-options\}

Każdy pakiet frameworkowy jest tworzony w ten sam sposób — tylko typ opcji nazywa się według frameworka (`ReactI18nOptions`, `SolidI18nOptions` itd.). Same opcje są identyczne:

| Właściwość       | Typ                                                        | Wymagane | Domyślnie        | Opis                                                    |
| ---------------- | ---------------------------------------------------------- | -------- | ---------------- | ------------------------------------------------------- |
| `locale`         | `string`                                                   | ✅       | -                | Kod bieżącej lokalizacji (np. `'en'`)                   |
| `fallbackLocale` | `string`                                                   | ❌       | Ta sama co `locale` | Lokalizacja zapasowa, gdy brakuje tłumaczenia        |
| `messages`       | `Record<string, Translations>`                             | ❌       | `\{\}`           | Początkowe wiadomości tłumaczeń                         |
| `plural`         | `PluralFunc`                                               | ❌       | `defaultPlural`  | Niestandardowa funkcja pluralizacji                     |
| `missingWarn`    | `boolean`                                                  | ❌       | `true`           | Pokazuj ostrzeżenia w konsoli dla brakujących tłumaczeń |
| `missingHandler` | `(locale: string, key: string, routeName: string) => void` | ❌       | -                | Niestandardowy handler dla brakujących tłumaczeń        |

Wszystko poza tym jest specyficzne dla frameworka i udokumentowane na stronie tego pakietu.

## Abstrakcja adaptera routera

Wszystkie pakiety frameworkowe używają **wzorca adaptera routera**, aby oddzielić funkcjonalność i18n od konkretnych implementacji routera. Ten projekt pozwala na:

- **Elastyczność** — użyj dowolnej biblioteki routera lub żadnej
- **Niezależność od frameworka** — zachowaj logikę routingu w aplikacji, a nie w pakiecie i18n
- **Lekki rdzeń** — pakiet i18n pozostaje mały i skoncentrowany

### Implementacja adaptera routera

Aby używać funkcji routingu, musisz zaimplementować interfejs `I18nRoutingStrategy`:

```typescript
interface I18nRoutingStrategy {
  getCurrentPath: () => string
  linkComponent?: Component
  push: (target: { path: string }) => void
  replace: (target: { path: string }) => void
  resolvePath?: (to: string | { path?: string }, locale: string) => string | { path?: string }
  getRoute?: () => { fullPath: string; query: Record<string, unknown> }
}
```

Każda dokumentacja pakietu zawiera pełne przykłady implementacji adapterów dla popularnych routerów:

- **Vue**: przykład adaptera Vue Router
- **React**: przykład adaptera React Router
- **Solid**: przykład adaptera Solid Router
- **Astro**: przykład adaptera routingu opartego na plikach

## Kluczowe funkcje

Wszystkie pakiety współdzielą te kluczowe funkcje:

### Metody tłumaczeń

- `t()` — podstawowe tłumaczenie z interpolacją parametrów
- `ts()` — tłumaczenie zawsze zwracające ciąg
- `tc()` — tłumaczenie świadome pluralizacji
- `tn()` — formatowanie liczb
- `td()` — formatowanie dat
- `tdr()` — formatowanie czasu względnego
- `has()` — sprawdź, czy klucz tłumaczenia istnieje

### Zarządzanie lokalizacją

- **Przełączanie lokalizacji** — programowa zmiana bieżącej lokalizacji
- **Lokalizacja zapasowa** — automatyczny fallback, gdy brakuje tłumaczenia
- **Tłumaczenia specyficzne dla trasy** — organizacja tłumaczeń na poziomie strony
- **Cache tłumaczeń** — inteligentne cache'owanie dla wydajności

### Wsparcie TypeScript

Wszystkie pakiety zapewniają:

- Pełne definicje TypeScript
- Bezpieczne typowo klucze tłumaczeń (z generatorem typów)
- Wsparcie IntelliSense w IDE
- Sprawdzanie błędów w czasie kompilacji
