Pakiety `@i18n-micro/*` przenoszą rdzeń tłumaczeń Nuxt I18n Micro do Vue, React, Preact, Solid, Astro, VitePress i czystego JavaScriptu. Używaj ich, gdy Twoja aplikacja nie jest aplikacją Nuxt lub gdy skrypt albo serwer poza Nuxt potrzebuje tych samych plików tłumaczeń. Wszystkie pakiety współdzielą jeden model instancji, jeden kontrakt adaptera routera i te same cztery komponenty, opisane raz na tej stronie.

## Instancja {#the-instance}

`createI18n(options)` zwraca jedną instancję przechowującą słowniki, bieżącą lokalizację i bieżącą trasę. Opcje są takie same w każdym pakiecie:

| Opcja | Typ | Domyślnie | Uwagi |
| --- | --- | --- | --- |
| `locale` | `string` | wymagane | Aktywna lokalizacja. |
| `fallbackLocale` | `string` | `locale` | Przeszukiwana, gdy brakuje klucza w `locale`. |
| `messages` | `Record<locale, Translations>` | `{}` | Słowniki główne (trasa `'index'`). |
| `routeMessages` | `Record<route, Record<locale, Translations>>` | `{}` | Słowniki tras. Tylko Runtime, React, Preact, Node i VitePress. |
| `plural` | `PluralFunc` | `defaultPlural` | Własna reguła liczby mnogiej. |
| `missingWarn` | `boolean` | `true` | `console.warn` w przeglądarce dla brakującego klucza, tylko w trybie dev. |
| `missingHandler` | `(locale, key, routeName) => void` | — | Wywoływany zamiast ostrzeżenia. |
| `numberFormats` | `Record<locale, Record<name, Intl.NumberFormatOptions>>` | — | Nazwane formaty: `tn(9.5, 'currency')`. |
| `datetimeFormats` | `Record<locale, Record<name, Intl.DateTimeFormatOptions>>` | — | Nazwane formaty: `td(date, 'short')`. |
| `timeZone` | `string` | strefa środowiska | Strefa IANA dla dat `td`; nie wpływa na `tdr`. Ustaw ją, aby serwer i przeglądarka renderowały tę samą datę. |
| `now` | `() => number` | `Date.now` | Zegar dla `tdr`. Przekaż hydratacji czas serwera, aby oba renderowały ten sam tekst. |
| `localeIso` | `Record<code, string>` | — | Tag BCP 47 używany dla reguł liczby mnogiej (`ua` → `uk-UA`). React, Preact i Solid pobierają go z `iso` w `locales` providera. |

Słowniki znajdują się w `i18n.storage.translations`, czyli `Map` z kluczami `locale:route` (`en:index`, `en:about`).

Klucz jest wyszukiwany w słowniku bieżącej trasy, a potem w słowniku głównym, najpierw dla `locale`, potem dla `fallbackLocale`. Brakujący klucz zwraca sam klucz (lub przekazany `defaultValue`).

```ts
i18n.addTranslations('en', { nav: { home: 'Home' } }) // root, deep-merged
i18n.addRouteTranslations('en', 'about', { title: 'About us' }) // route chunk
i18n.addTranslations('en', { nav: { home: 'Start' } }, false) // replace instead of merge
i18n.setRoute('about')
i18n.t('title') // 'About us'
i18n.t('nav.home') // 'Start' (root key, still visible on the route)
```

### Tłumaczenie i formatowanie {#translate-and-format}

| Metoda | Zwraca |
| --- | --- |
| `t(key, params?, defaultValue?, routeName?)` | Wartość (string, liczba, obiekt) z zinterpolowanymi `{param}`. |
| `ts(...)` | To samo co `t`, jako string. |
| `tc(key, count \| params, defaultValue?)` | Forma liczby mnogiej. |
| `tn(value, options \| name)` | `Intl.NumberFormat` w aktywnej lokalizacji. |
| `td(value, options \| name)` | `Intl.DateTimeFormat`. |
| `tdr(value, options?)` | Czas względny (`3 days ago`). |
| `has(key, routeName?)` | `true`, gdy aktywna lokalizacja ma dany klucz (w słowniku trasy lub głównym; fallback nie jest sprawdzany). |

`defaultPlural` dzieli wartość według `|` i wybiera formę o indeksie `count`, ograniczonym do ostatniej formy; ujemna, ułamkowa lub `NaN` wartość count wybiera ostatnią formę.

Własna funkcja `plural` otrzymuje `(key, count, params, locale, getter)`. Odczytuj wartość przez `getter(key)`; nie dziel klucza:

```ts
import type { PluralFunc } from '@i18n-micro/vue'

const plural: PluralFunc = (key, count, params, _locale, getter) => {
  const value = getter(key)
  if (typeof value !== 'string') return null
  const forms = value.split('|').map((form) => form.trim())
  return (count === 1 ? forms[0] : forms[1] ?? forms[0])!.replace('{count}', String(count))
}
```

## Adapter routera {#router-adapter}

Pakiety SPA nie zależą od routera. Adapter routera (`I18nRoutingStrategy`) mówi im, jak odczytać bieżącą ścieżkę, nawigować i budować zlokalizowaną ścieżkę. Wbudowane adaptery dodają prefiks każdej lokalizacji oprócz `defaultLocale` (`/about`, `/de/about`).

| Element | Wymagany | Używany przez |
| --- | --- | --- |
| `getCurrentPath(): string` | tak | sprawdzanie aktywnego linku (według strony, query i hash się nie liczą), `switchLocale` (zachowuje je) |
| `push({ path }): void` | tak | `switchLocale`, `<I18nLink>` bez `linkComponent`, `<I18nSwitcher>` |
| `replace({ path }): void` | tak | — |
| `resolvePath(to, locale)` | nie | `localePath`, `localeRoute`, `<I18nLink>`; bez niego ścieżki są zwracane bez zmian |
| `linkComponent` | nie | `<I18nLink>` renderuje go (np. `RouterLink`) zamiast `<a>` |
| `getRoute()` | nie | `{ fullPath, query }` dla pomocników SEO |

`push` i `replace` są wymagane w Vue, React, Preact i Solid. Astro ma własny adapter po stronie serwera z opcjonalnymi `push`/`replace` (zobacz [Astro](/pl/integrations/astro-package#router-adapter)).

Minimalny adapter dla dowolnego routera opartego na historii:

```ts
import type { I18nRoutingStrategy } from '@i18n-micro/react'

const locales = ['en', 'de']
const stripLocale = (path: string) => path.replace(/^\/(en|de)(?=\/|$)/, '') || '/'

export const historyAdapter: I18nRoutingStrategy = {
  getCurrentPath: () => window.location.pathname + window.location.search + window.location.hash,
  push: ({ path }) => window.history.pushState({}, '', path),
  replace: ({ path }) => window.history.replaceState({}, '', path),
  resolvePath: (to, locale) => {
    const path = stripLocale(typeof to === 'string' ? to : to.path || '/')
    return locale === 'en' ? path : `/${locale}${path === '/' ? '' : path}`
  },
}
```

## Komponenty {#components}

Vue, React, Preact i Solid dostarczają te same cztery komponenty. Ich propsy są zgodne; React, Preact i Solid przekazują pozostałe propsy do elementu głównego.

### `<I18nT>` {#&lt;i18nt&gt;}

| Prop | Typ | Uwagi |
| --- | --- | --- |
| `keypath` | `string` | wymagany |
| `params` | `object` | wartości interpolacji |
| `plural` | `number \| string` | renderuje `tc(keypath, count)` |
| `number` | `number \| string` | przekazuje `tn(number)` jako `{number}` |
| `date` | `Date \| string \| number` | przekazuje `td(date)` jako `{date}` |
| `relativeDate` | `Date \| string \| number` | przekazuje `tdr(relativeDate)` jako `{relativeDate}` |
| `tag` | `string` | element opakowujący, domyślnie `span` |
| `html` | `boolean` | renderuje tłumaczenie jako HTML; musi być zaufane, parametry są escapowane |
| `defaultValue` | `string` | zastępuje brakujący klucz i jest renderowany bez opakowania, gdy `hideIfEmpty` ukrywa pustą wartość |
| `hideIfEmpty` | `boolean` | nie renderuje niczego dla pustego tłumaczenia |
| `customPluralRule` | `PluralFunc` | reguła liczby mnogiej dla tego elementu |

Stosowany jest tylko jeden prop formatujący, sprawdzany w tej kolejności: `number`, `date`, `relativeDate`, `plural`.

#### Tekst sformatowany {#rich-text}

`{placeholder}` może zawierać element. W Vue jest to nazwany slot; w React, Preact i Solid prop `components` podaje według nazwy elementy lub funkcje je zwracające. W obu przypadkach ma pierwszeństwo przed parametrem o tej samej nazwie, działa w każdej gałęzi i przetrwa lokalizację, która zmienia kolejność placeholderów.

```tsx
// { "terms": "I accept the {link} of {company}" }
<I18nT keypath="terms" params={{ company: 'ACME' }} components={{ link: <a href="/terms">terms</a> }} />
```

W Solid przekaż funkcję, gdy placeholder się powtarza: jeden węzeł może stać tylko w jednym miejscu. `children` zastępują tekst; jako funkcja otrzymują `{ translation }`, podobnie jak domyślny slot w Vue. `html` ignoruje to wszystko.

### `<I18nLink>` {#&lt;i18nlink&gt;}

| Prop | Typ | Uwagi |
| --- | --- | --- |
| `to` | `string \| { path }` | lokalizowany przez `resolvePath` adaptera |
| `activeStyle` | obiekt stylu | nakładany na `style` na bieżącej stronie; React, Preact i Solid stosują go także do sekcji nadrzędnej |
| `localeRoute` | funkcja | nadpisuje `resolvePath` dla tego linku |

Zewnętrzne URL-e (`https://`, `mailto:`, `tel:`) renderują się jako `<a target="_blank" rel="noopener noreferrer">`; własne `target` lub `rel` mają pierwszeństwo. `onClick` jest zawsze wywoływany. Kliknięcie z modyfikatorem, innym przyciskiem myszy lub przy ustawionym `target` obsługuje przeglądarka.

### `<I18nSwitcher>` {#&lt;i18nswitcher&gt;}

Lista rozwijana włączonych lokalizacji (lokalizacje z `disabled: true` są ukryte) z domyślnymi stylami inline. Jej elementy to linki z `lang`, `hreflang` i `dir` pochodzącymi z lokalizacji. Domyślnie kliknięcie jednego z nich ustawia lokalizację i wywołuje `push` adaptera ze zlokalizowaną bieżącą ścieżką; prop `switchLocale` zastępuje tę akcję. Przy `localeRoute` i braku routera przeglądarka podąża za linkiem. Escape lub kliknięcie poza listą ją zamyka.

| Prop | Uwagi |
| --- | --- |
| `locales`, `currentLocale`, `getLocaleName` | nadpisują przekazane wartości |
| `switchLocale(code)` | zastępuje wbudowane przełączanie |
| `localeRoute` | zastępuje `resolvePath` |
| `customLabels` | `{ de: 'DE' }` |
| `customWrapperStyle`, `customButtonStyle`, `customDropdownStyle`, `customItemStyle`, `customLinkStyle`, `customActiveLinkStyle`, `customDisabledLinkStyle`, `customIconStyle` | nadpisania stylów |

### `<I18nGroup>` {#&lt;i18ngroup&gt;}

`<div class="i18n-group">`, który przekazuje swoim dzieciom `t` z prefiksem. **Nie** dodaje prefiksu do `<I18nT>` ani wywołań `t()` wewnątrz niego; prefiks ma tylko przekazywane w dół `t`.

| Prop | Uwagi |
| --- | --- |
| `prefix` | wymagany, np. `'profile'` |
| `groupClass` | dodatkowa klasa na elemencie opakowującym |

`t` z prefiksem jest dostępne przez scoped slot w Vue (`v-slot="{ t }"`) oraz przez dziecko render-prop w React, Preact i Solid (`{({ t }) => …}`).

## Typowane klucze {#typed-keys}

`t()` przyjmuje dowolny string. Aby uzyskać autouzupełnianie kluczy, wygeneruj deklarację za pomocą [generatora typów](/pl/integrations/types-generator). Klucze są podpowiadane, a nie wymuszane, a parametry nie są typowane.

## Porównanie z modułem Nuxt {#compared-with-the-nuxt-module}

Pakiety nie mają routingu opartego na plikach, middleware serwera ani loadera tłumaczeń: sam decydujesz, kiedy ładować JSON (`import`, `fetch` lub `@i18n-micro/node` na serwerze) i jakiego adaptera routera użyć. Wykrywanie lokalizacji, meta SEO i generowanie tras to funkcje Nuxt; Astro ma własne middleware do wykrywania oraz `useLocaleHead` do SEO.
