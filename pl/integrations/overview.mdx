# Integracje

Pakiety `@i18n-micro` to lekkie, specyficzne dla frameworków wersje Nuxt I18n Micro zaprojektowane do integracji z różnymi frameworkami i środowiskami. Pakiety te dostarczają podstawową funkcjonalność internacjonalizacji przy minimalnym footprincie, skupiając się na kluczowych funkcjach tłumaczeń i podstawowych komponentach.

## Przegląd

Te pakiety integracyjne są **miniaturowymi wersjami** pełnego modułu Nuxt I18n Micro, zawierającymi tylko niezbędną funkcjonalność potrzebną do internacjonalizacji:

- **Podstawowe funkcje tłumaczeń** — Podstawowe metody tłumaczeń, liczba mnoga i formatowanie
- **Kluczowe komponenty** — Niewielki zestaw komponentów UI do typowych zadań i18n
- **Wzorzec Router Adapter** — Elastyczna integracja routingu przez abstrakcję adaptera
- **Wsparcie TypeScript** — Pełne definicje typów dla programowania z bezpieczeństwem typów

W przeciwieństwie do pełnego modułu Nuxt te pakiety:

- Nie zawierają logiki routingu specyficznej dla frameworka
- Wymagają zaimplementowania adaptera routera dla funkcji routingu
- Skupiają się na funkcjonalności tłumaczeń, a nie na integracji z frameworkiem
- Są zaprojektowane tak, aby były lekkie i w miarę możliwości niezależne od frameworka

## Podstawowe komponenty

Wszystkie pakiety frameworków zawierają następujące kluczowe komponenty:

### `<I18nT>`

Komponent tłumaczeń, który renderuje przetłumaczony tekst ze wsparciem dla:

- **Interpolacja parametrów** — Zastępowanie placeholderów wartościami dynamicznymi
- **Liczba mnoga** — Automatyczny dobór formy liczby mnogiej na podstawie liczby
- **Formatowanie liczb** — Formatowanie liczb zgodnie z locale
- **Formatowanie dat** — Formatowanie dat i czasów względnych
- **Renderowanie HTML** — Opcjonalne renderowanie zawartości HTML
- **Wartości domyślne** — Tekst zastępczy, gdy brakuje tłumaczenia

**Przykład:**

```vue
<!-- Vue -->
<I18nT keypath="greeting" :params="{ name: 'World' }" />
```

```tsx
// React
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```tsx
// Solid
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```astro
<!-- Astro -->
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

### `<I18nLink>`

Zlokalizowany komponent link, który automatycznie obsługuje prefiksy locale w URL-ach. Funkcje:

- **Automatyczna lokalizacja ścieżek** — Dodaje/usuwa prefiksy locale na podstawie strategii routingu
- **Wykrywanie stanu aktywnego** — Podświetla bieżącą trasę
- **Wsparcie linków zewnętrznych** — Automatycznie wykrywa i obsługuje URL-e zewnętrzne
- **Integracja z routerem** — Używa komponentu link adaptera routera, gdy jest dostępny
- **Niestandardowa stylizacja** — Wspiera stany aktywne i hover

**Przykład:**

```vue
<!-- Vue -->
<I18nLink to="/about" active-class="active">
  About Us
</I18nLink>
```

```tsx
// React
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```tsx
// Solid
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```astro
<!-- Astro -->
<I18nLink href="/about" class="nav-link">
  About Us
</I18nLink>
```

### `<I18nSwitcher>`

Komponent przełącznika języków zapewniający interfejs listy rozwijanej lub listy do zmiany locale. Funkcje:

- **Automatyczna lista locale** — Generuje opcje z skonfigurowanych locale
- **Podświetlanie bieżącego locale** — Wizualnie wskazuje aktywny język
- **Niestandardowe etykiety** — Wsparcie niestandardowych nazw wyświetlania per locale
- **Integracja z routerem** — Automatycznie nawiguje do zlokalizowanych ścieżek
- **Dostępność** — Poprawne atrybuty ARIA i nawigacja klawiaturą

**Przykład:**

```vue
<!-- Vue -->
<I18nSwitcher />
```

```tsx
// React
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```tsx
// Solid
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```astro
<!-- Astro -->
<I18nSwitcher />
```

### `<I18nGroup>`

Komponent do grupowania tłumaczeń pod wspólnym prefiksem, przydatny do organizowania tłumaczeń według strony lub funkcji. Funkcje:

- **Zakres prefiksu** — Automatycznie dodaje prefiks do wszystkich kluczy tłumaczeń w grupie
- **Zagnieżdżone grupy** — Wsparcie zagnieżdżonych grup tłumaczeń
- **Czysta organizacja** — Pomaga utrzymać uporządkowaną strukturę tłumaczeń

**Przykład:**

```vue
<!-- Vue -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

```tsx
// React
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```tsx
// Solid
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```astro
<!-- Astro -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

## Wspólne opcje `createI18n` \{#create-i18n-options\}

Każdy pakiet frameworka jest tworzony w ten sam sposób — jedynie nazwa typu opcji jest nadana zgodnie z frameworkiem (`ReactI18nOptions`, `SolidI18nOptions` itd.). Same opcje są identyczne:

| Właściwość       | Typ                                                        | Wymagane | Domyślnie        | Opis                                                     |
| ---------------- | ---------------------------------------------------------- | -------- | ---------------- | -------------------------------------------------------- |
| `locale`         | `string`                                                   | ✅       | -                | Kod bieżącego locale (np. `'en'`)                        |
| `fallbackLocale` | `string`                                                   | ❌       | Tak jak `locale` | Fallback locale, gdy tłumaczenia brakuje                  |
| `messages`       | `Record<string, Translations>`                             | ❌       | `\{\}`             | Początkowe komunikaty tłumaczeń                          |
| `plural`         | `PluralFunc`                                               | ❌       | `defaultPlural`  | Niestandardowa funkcja liczby mnogiej                    |
| `missingWarn`    | `boolean`                                                  | ❌       | `true`           | Pokazuj ostrzeżenia w konsoli dla brakujących tłumaczeń  |
| `missingHandler` | `(locale: string, key: string, routeName: string) => void` | ❌       | -                | Niestandardowy handler dla brakujących tłumaczeń          |

Wszystko poza tym jest specyficzne dla frameworka i udokumentowane na stronie tego pakietu.

## Abstrakcja adaptera routera

Wszystkie pakiety frameworków używają **wzorca router adapter**, aby oddzielić funkcjonalność i18n od konkretnych implementacji routera. Ten projekt pozwala na:

- **Elastyczność** — Używaj dowolnej biblioteki routera lub w ogóle bez routera
- **Niezależność od frameworka** — Trzymaj logikę routingu w swojej aplikacji, a nie w pakiecie i18n
- **Lekki rdzeń** — Pakiet i18n pozostaje mały i skupiony

### Implementacja adaptera routera

Aby używać funkcji routingu, musisz zaimplementować interfejs `I18nRoutingStrategy`:

```typescript
interface I18nRoutingStrategy {
  getCurrentPath: () => string
  linkComponent?: Component
  push: (target: { path: string }) => void
  replace: (target: { path: string }) => void
  resolvePath?: (to: string | { path?: string }, locale: string) => string | { path?: string }
  getRoute?: () => { fullPath: string; query: Record<string, unknown> }
}
```

Dokumentacja każdego pakietu zawiera kompletne przykłady implementacji adapterów dla popularnych routerów:

- **Vue**: przykład adaptera Vue Router
- **React**: przykład adaptera React Router
- **Solid**: przykład adaptera Solid Router
- **Astro**: przykład adaptera routingu opartego na plikach

## Podstawowe funkcje

Wszystkie pakiety dzielą te podstawowe funkcje:

### Metody tłumaczeń

- `t()` — Podstawowe tłumaczenie z interpolacją parametrów
- `ts()` — Tłumaczenie zawsze zwracające string
- `tc()` — Tłumaczenie świadome liczby mnogiej
- `tn()` — Formatowanie liczb
- `td()` — Formatowanie dat
- `tdr()` — Formatowanie czasu względnego
- `has()` — Sprawdź, czy klucz tłumaczenia istnieje

### Zarządzanie locale

- **Przełączanie locale** — Programowo zmieniaj bieżące locale
- **Fallback locale** — Automatyczny fallback, gdy tłumaczenia brakuje
- **Tłumaczenia specyficzne dla tras** — Organizacja tłumaczeń na poziomie stron
- **Cache tłumaczeń** — Inteligentny cache dla wydajności

### Wsparcie TypeScript

Wszystkie pakiety zapewniają:

- Pełne definicje TypeScript
- Bezpieczne typowo klucze tłumaczeń (z generatorem typów)
- Wsparcie IntelliSense w IDE
- Sprawdzanie błędów w czasie kompilacji

## Rozpocznij pracę

1. **Wybierz swój pakiet** — Wybierz pakiet dla swojego frameworka
2. **Zainstaluj pakiet** — Użyj preferowanego menedżera pakietów
3. **Przeczytaj dokumentację** — Każdy pakiet ma szczegółowe instrukcje konfiguracji
4. **Zaimplementuj adapter routera** — Jeśli potrzebujesz funkcji routingu, zaimplementuj adapter
5. **Zacznij tłumaczyć** — Używaj komponentów i metod, aby dodawać tłumaczenia
