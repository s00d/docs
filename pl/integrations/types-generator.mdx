# 🔧 Generator typów (`@i18n-micro/types-generator`)

Pakiet `@i18n-micro/types-generator` zapewnia automatyczne generowanie typów TypeScript dla kluczy tłumaczeń. Analizuje pliki JSON tłumaczeń i generuje ścisłe typy, umożliwiając pełne bezpieczeństwo typów i wsparcie autouzupełniania dla kluczy tłumaczeń.

## 📖 Omówienie

`@i18n-micro/types-generator` to opcjonalna zależność deweloperska, która ulepsza Twoje doświadczenie deweloperskie przez:

- 🔍 **Automatyczne generowanie typów** — skanuje pliki JSON tłumaczeń i generuje typy TypeScript
- ✅ **Bezpieczeństwo typów** — zapobiega literówkom i nieprawidłowym kluczom tłumaczeń w czasie kompilacji
- 🎯 **Wsparcie autouzupełniania** — pełne autouzupełnianie IDE dla kluczy tłumaczeń
- 🔄 **Hot reload** — automatycznie regeneruje typy, gdy zmieniają się pliki tłumaczeń
- 🚀 **Zerowy narzut runtime** — typy są tylko w czasie kompilacji, brak wpływu na rozmiar bundla

## 🚀 Instalacja

## 🎯 Szybki start

### Dla projektów Nuxt

Dodaj moduł do `nuxt.config.ts`:

```typescript
import { defineNuxtConfig } from 'nuxt/config'

export default defineNuxtConfig({
  modules: [
    'nuxt-i18n-micro',
    '@i18n-micro/types-generator/nuxt', // Add types generator
  ],
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    translationDir: 'locales', // Path to your translation files
  },
})
```

Generator automatycznie:

- Zeskanuje wszystkie pliki JSON w Twoim katalogu `locales`
- Wygeneruje typy w `.nuxt/i18n-micro.d.ts`
- Będzie obserwował zmiany i regenerował typy automatycznie

### Dla projektów Vue/Vite

Dodaj plugin do `vite.config.ts`:

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { I18nTypesPlugin } from '@i18n-micro/types-generator'

export default defineConfig({
  plugins: [
    vue(),
    I18nTypesPlugin({
      srcDir: 'src',
      translationDir: 'locales',
      outputFile: 'src/i18n-types.d.ts', // Optional: custom output path
    }),
  ],
})
```

Upewnij się, że wygenerowany plik jest uwzględniony w `tsconfig.json`:

```json
{
  "include": ["src/**/*", "src/i18n-types.d.ts"]
}
```

## 📁 Struktura plików tłumaczeń

Generator obsługuje zarówno płaskie, jak i zagnieżdżone struktury tłumaczeń:

```
locales/
  en.json
  fr.json
  pages/
    home/
      en.json
      fr.json
    about/
      en.json
      fr.json
```

**Przykład `locales/en.json`:**

```json
{
  "greeting": "Hello, {name}!",
  "header": {
    "title": "Welcome",
    "subtitle": "Subtitle"
  },
  "errors": {
    "404": "Not found",
    "500": "Server error"
  },
  "apples": "no apples | one apple | {count} apples"
}
```

Generator utworzy typy dla wszystkich kluczy, w tym zagnieżdżonych:

```typescript
// Generated types
declare module '@i18n-micro/types' {
  export interface DefineLocaleMessage {
    greeting: string
    'header.title': string
    'header.subtitle': string
    'errors.404': string
    'errors.500': string
    apples: string
  }
}
```

## 💡 Użycie

Gdy typy zostaną wygenerowane, uzyskujesz pełne bezpieczeństwo typów:

```typescript
import { useI18n } from '@i18n-micro/vue'

const { t } = useI18n()

// ✅ Type-safe: autocomplete works
t('greeting', { name: 'World' })
t('header.title')
t('errors.404')

// ❌ Type error: key doesn't exist
t('invalid.key') // Error: Argument of type '"invalid.key"' is not assignable
```

### Uwaga specyficzna dla Nuxt

**W projektach Nuxt bezpieczeństwo typów działa tylko z composable `useI18n`.** Wygenerowane typy są stosowane do wartości zwracanej przez composable, zapewniając bezpieczeństwo typów podczas używania metod `t()`, `ts()`, `tc()` i `has()`.

```typescript
// ✅ Correct: Using useI18n composable
<script setup lang="ts">
import { useI18n } from '#imports'

const { t } = useI18n()
t('greeting') // Type-safe with autocomplete
</script>

// ❌ Not type-safe: Direct access to $i18n or other methods
// Type safety is only available through the useI18n composable
```

## 🔄 Klucze dynamiczne

Czasami musisz używać kluczy dynamicznych (np. na podstawie danych wejściowych użytkownika lub odpowiedzi API). Generator zapewnia pomocniczy typ `ScopedKey` do bezpiecznego użycia kluczy dynamicznych.

### Dlaczego nie runtime type guards?

**Runtime type guards nie są zalecane** dla i18n-micro, ponieważ:

1. **Rozmiar bundla** — generowanie tablicy JavaScript wszystkich kluczy rozdęłoby Twój bundle
2. **Wydajność** — sprawdzenia w runtime dodają niepotrzebny narzut
3. **Filozofia** — i18n-micro jest zaprojektowany, aby być lekki i szybki

### Sposób TypeScript: asercje typu

Dla kluczy dynamicznych użyj asercji typu TypeScript:

```typescript
import type { TranslationKey, ScopedKey } from '@i18n-micro/types'

// ❌ Type error: dynamic key
const status = 'pending'
t(`status.${status}`) // Error: string is not assignable to TranslationKey

// ✅ Solution 1: Type assertion (if you're sure the key exists)
t(`status.${status}` as TranslationKey)

// ✅ Solution 2: ScopedKey helper (safer, checks prefix exists)
function getStatusText(status: string) {
  return t(`status.${status}` as ScopedKey<'status'>)
  // TypeScript verifies that keys starting with 'status.' exist
}

// ✅ Solution 3: Runtime check with has()
if (has(`status.${status}`)) {
  t(`status.${status}` as TranslationKey)
}
```

### Helper ScopedKey

Typ `ScopedKey<Scope>` pozwala zawęzić klucze dynamiczne przez prefiks:

```typescript
import type { ScopedKey } from '@i18n-micro/types'

// Assuming you have keys: 'errors.404', 'errors.500', 'btn.save'

function getErrorText(code: string) {
  // ✅ Safer than plain TranslationKey
  // TypeScript verifies that 'errors.*' keys exist
  return t(`errors.${code}` as ScopedKey<'errors'>)
}

// ❌ Type error: 'btn' prefix doesn't match 'errors'
function getErrorTextWrong(code: string) {
  return t(`errors.${code}` as ScopedKey<'btn'>) // Error
}
```

## 🎨 Zaawansowane użycie

### Obsługa tłumaczeń specyficznych dla tras

Generator automatycznie uwzględnia klucze z plików tłumaczeń specyficznych dla tras:

```
locales/
  en.json                    # Root-level translations
  pages/
    home/
      en.json               # Route-specific translations
    about/
      en.json
```

Wszystkie klucze zarówno z plików root-level, jak i tras są uwzględniane w wygenerowanych typach.

### Wyłączanie plików lokalizacji per strona

Jeśli używasz `disablePageLocales: true` w swojej konfiguracji i18n, generator potraktuje wszystkie pliki (w tym te w `pages/`) jako tłumaczenia root-level.

## 🐛 Rozwiązywanie problemów

### Typy się nie aktualizują

1. **Sprawdź ścieżki plików** — upewnij się, że `translationDir` wskazuje właściwy katalog
2. **Zrestartuj serwer TypeScript** — w VS Code: `Cmd/Ctrl + Shift + P` → "TypeScript: Restart TS Server"
3. **Sprawdź tsconfig.json** — upewnij się, że wygenerowany plik jest uwzględniony

### Błędy typów po dodaniu kluczy

1. **Zregeneruj typy** — generator powinien auto-regenerować, ale możesz też uruchomić ręcznie
2. **Sprawdź składnię JSON** — nieprawidłowe pliki JSON są pomijane z ostrzeżeniem
3. **Zrestartuj serwer dev** — czasami wymagane, aby zmiany zadziałały

### Autouzupełnianie nie działa

1. **Zweryfikuj włączenie pliku** — sprawdź, czy wygenerowany plik `.d.ts` jest w `include` `tsconfig.json`
2. **Sprawdź module augmentation** — upewnij się, że wygenerowany plik używa `declare module '@i18n-micro/types'`
3. **Wersja TypeScript** — wymaga TypeScript 4.1+ dla template literal types

## 📚 Dokumentacja API

### `generateTypes(options: GeneratorOptions)`

Ręcznie generuj typy (przydatne dla skryptów lub CI):

```typescript
import { generateTypes } from '@i18n-micro/types-generator'

await generateTypes({
  srcDir: './src',
  translationDir: 'locales',
  outputFile: './src/i18n-types.d.ts',
})
```

### `flattenKeys(obj: Record<string, unknown>, prefix?: string)`

Funkcja narzędziowa do spłaszczania zagnieżdżonych obiektów tłumaczeń:

```typescript
import { flattenKeys } from '@i18n-micro/types-generator'

const keys = flattenKeys({
  header: { title: 'Title' },
  footer: { copyright: 'Copyright' },
})
// Returns: ['header.title', 'footer.copyright']
```

## 🔍 Jak to działa

1. **Skanowanie** — używa `globby`, aby znaleźć wszystkie pliki `**/*.json` w katalogu tłumaczeń
2. **Parsowanie** — parsuje każdy plik JSON i wyodrębnia wszystkie klucze przez rekurencyjne spłaszczanie
3. **Deduplikacja** — łączy klucze ze wszystkich plików w unikalny zbiór
4. **Generowanie** — tworzy plik `.d.ts` z augmentacją `declare module`
5. **Obserwacja** — w trybie dev obserwuje zmiany plików i regeneruje typy

Wygenerowany plik używa module augmentation TypeScript do rozszerzenia `DefineLocaleMessage` w `@i18n-micro/types`, co automatycznie aktualizuje typ `TranslationKey` w całym projekcie.

## 🎯 Najlepsze praktyki

1. **Utrzymuj tłumaczenia zorganizowane** — używaj zagnieżdżonych obiektów dla powiązanych kluczy
2. **Używaj spójnego nazewnictwa** — trzymaj się konwencji nazewnictwa (np. `errors.*`, `buttons.*`)
3. **Wykorzystuj ScopedKey** — używaj `ScopedKey` dla kluczy dynamicznych zamiast zwykłych asercji
4. **Sprawdzaj typy w CI** — uruchamiaj sprawdzanie typów w pipeline CI
5. **Nie edytuj generowanych plików** — plik `.d.ts` jest auto-generowany i zostanie nadpisany
