# 🌐 Przewodnik integracji z Crowdin

## 📖 Wprowadzenie

Integracja Crowdin z Twoim projektem usprawnia proces lokalizacji i tłumaczenia, ułatwiając zarządzanie tłumaczeniami w wielu językach i na różnych platformach. Ten przewodnik krok po kroku pokazuje, jak skonfigurować Crowdin w Twoim projekcie, w tym konfigurację, przesyłanie źródeł i pobieranie tłumaczeń.

## 🔧 Instalacja i konfiguracja

Aby zacząć pracę z Crowdin, musisz zainstalować Crowdin CLI globalnie na swojej maszynie i zainicjalizować go w katalogu projektu.

### 📦 Instalacja Crowdin CLI

Najpierw zainstaluj Crowdin CLI globalnie za pomocą npm:

```bash
npm install -g @crowdin/cli
```

### 🛠 Inicjalizacja Crowdin w projekcie

Zainicjalizuj Crowdin w swoim projekcie, uruchamiając:

```bash
crowdin init
```

Ta komenda przeprowadzi Cię przez proces konfiguracji, w tym ustawienie ID projektu, tokenu API i innych szczegółów konfiguracji.

## 🗂️ Przewodnik konfiguracji

### 📄 Plik konfiguracji Crowdin (`crowdin.yml`)

Plik konfiguracji Crowdin (`crowdin.yml`) definiuje, jak mapowane są Twoje pliki źródłowe i gdzie powinny być umieszczone tłumaczenia. Poniżej przykładowa konfiguracja:

```yml
'project_id': 'YOUR_PROJECT_ID'
'api_token': 'YOUR_API_TOKEN'
'base_path': './locales'
'base_url': 'https://api.crowdin.com'
'preserve_hierarchy': true

files:
  [
    { 'source': '/en.json', 'translation': '/%two_letters_code%.json' },
    { 'source': '/pages/**/en.json', 'translation': '/pages/**/%two_letters_code%.json' },
  ]
```

### 📂 Kluczowe parametry konfiguracji

- **`project_id`**: ID Twojego projektu Crowdin. Identyfikuje projekt w Crowdin, w którym zarządzane są tłumaczenia.
- **`api_token`**: Token API używany do uwierzytelniania. Upewnij się, że token ma odpowiednie uprawnienia do przesyłania i pobierania tłumaczeń.
- **`base_path`**: Wskazuje bazowy katalog dla plików źródłowych. W tym przykładzie tłumaczenia są przechowywane w katalogu `./locales`.
- **`base_url`**: Bazowy URL API Crowdin.
- **`preserve_hierarchy`**: Gdy ustawione na `true`, Crowdin zachowa strukturę folderów Twoich plików źródłowych w projekcie.

### 📂 Konfiguracja plików

Sekcja `files` mapuje Twoje pliki źródłowe do ścieżek, gdzie będą przechowywane tłumaczenia. Na przykład:

- **Ścieżka źródłowa**: Definiuje lokalizację oryginalnych plików tłumaczeń.
- **Ścieżka tłumaczenia**: Wskazuje, gdzie w Crowdin będą przechowywane przetłumaczone pliki. Placeholdery takie jak `%two_letters_code%` są używane do dynamicznego ustawiania kodu języka w ścieżkach plików.

## ⬆️ Przesyłanie plików źródłowych do Crowdin

Gdy konfiguracja Crowdin jest gotowa, możesz przesłać pliki źródłowe za pomocą następującej komendy:

```bash
crowdin upload sources
```

Ta komenda przesyła wszystkie wskazane w konfiguracji pliki źródłowe do Crowdin, udostępniając je do tłumaczenia.

## ⬇️ Pobieranie tłumaczeń z Crowdin

Po zakończeniu lub aktualizacji tłumaczeń w Crowdin możesz je pobrać do swojego projektu za pomocą:

```bash
crowdin download
```

Ta komenda pobiera najnowsze tłumaczenia z Crowdin i zapisuje je zgodnie ze ścieżkami wskazanymi w pliku konfiguracji.

## ⚙️ Dobre praktyki

### 🔑 Spójne nazewnictwo kluczy

Zadbaj, aby klucze tłumaczeń były spójne we wszystkich plikach, aby uniknąć nieporozumień i duplikacji.

### 🧹 Regularne utrzymanie

Okresowo przeglądaj i usuwaj nieużywane klucze tłumaczeń, aby utrzymać porządek w plikach.

### 🛠 Automatyzacja przesyłania i pobierania

Zintegruj komendy Crowdin CLI ze swoim pipeline'em CI/CD, aby zautomatyzować przesyłanie plików źródłowych i pobieranie tłumaczeń, dzięki czemu tłumaczenia zawsze będą aktualne.

Postępując zgodnie z tym przewodnikiem, będziesz w stanie płynnie zintegrować Crowdin ze swoim projektem, zapewniając efektywne i uporządkowane podejście do zarządzania internacjonalizacją.
