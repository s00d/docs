# 🌐 Przewodnik integracji z Crowdin

## 📖 Wprowadzenie

Integracja Crowdin z Twoim projektem usprawnia proces lokalizacji i tłumaczenia, ułatwiając zarządzanie tłumaczeniami w wielu językach i na wielu platformach. Ten przewodnik przeprowadzi Cię krok po kroku przez konfigurację Crowdin w projekcie, w tym konfigurację, przesyłanie źródeł i pobieranie tłumaczeń.

## 🔧 Instalacja i konfiguracja

Aby rozpocząć pracę z Crowdin, musisz zainstalować Crowdin CLI globalnie na swoim komputerze i zainicjalizować je w katalogu projektu.

### 📦 Instalacja Crowdin CLI

Najpierw zainstaluj Crowdin CLI globalnie przez npm:

```bash
npm install -g @crowdin/cli
```

### 🛠 Inicjalizacja Crowdin w projekcie

Zainicjalizuj Crowdin w projekcie uruchamiając:

```bash
crowdin init
```

To polecenie przeprowadzi Cię przez proces konfiguracji, w tym ustawienie ID projektu, tokenu API i innych szczegółów konfiguracyjnych.

## 🗂️ Przewodnik konfiguracji

### 📄 Plik konfiguracyjny Crowdin (`crowdin.yml`)

Plik konfiguracyjny Crowdin (`crowdin.yml`) określa, jak mapowane są Twoje pliki źródłowe i gdzie mają być umieszczone tłumaczenia. Poniżej znajduje się przykładowa konfiguracja:

```yml
'project_id': 'YOUR_PROJECT_ID'
'api_token': 'YOUR_API_TOKEN'
'base_path': './locales'
'base_url': 'https://api.crowdin.com'
'preserve_hierarchy': true

files:
  [
    { 'source': '/en.json', 'translation': '/%two_letters_code%.json' },
    { 'source': '/pages/**/en.json', 'translation': '/pages/**/%two_letters_code%.json' },
  ]
```

### 📂 Kluczowe parametry konfiguracji

- **`project_id`**: ID Twojego projektu Crowdin. Identyfikuje projekt w Crowdin, w którym zarządzane są tłumaczenia.
- **`api_token`**: token API używany do uwierzytelniania. Upewnij się, że ten token ma poprawne uprawnienia do przesyłania i pobierania tłumaczeń.
- **`base_path`**: określa katalog bazowy dla plików źródłowych. W tym przykładzie tłumaczenia są przechowywane w katalogu `./locales`.
- **`base_url`**: bazowy URL dla API Crowdin.
- **`preserve_hierarchy`**: gdy ustawione na `true`, Crowdin zachowa strukturę folderów Twoich plików źródłowych w projekcie.

### 📂 Konfiguracja plików

Sekcja `files` mapuje pliki źródłowe na ścieżki, w których będą przechowywane tłumaczenia. Na przykład:

- **Ścieżka źródłowa**: definiuje lokalizację oryginalnych plików tłumaczeń.
- **Ścieżka tłumaczenia**: określa, gdzie w Crowdin będą przechowywane przetłumaczone pliki. Placeholdery takie jak `%two_letters_code%` są używane do dynamicznego ustawiania kodu języka w ścieżkach plików.

## ⬆️ Przesyłanie plików źródłowych do Crowdin

Gdy konfiguracja Crowdin jest gotowa, możesz przesłać swoje pliki źródłowe za pomocą następującego polecenia:

```bash
crowdin upload sources
```

To polecenie przesyła wszystkie określone w konfiguracji pliki źródłowe do Crowdin, udostępniając je do tłumaczenia.

## ⬇️ Pobieranie tłumaczeń z Crowdin

Po ukończeniu lub aktualizacji tłumaczeń w Crowdin możesz je pobrać do projektu przez:

```bash
crowdin download
```

To polecenie pobiera najnowsze tłumaczenia z Crowdin i zapisuje je zgodnie ze ścieżkami określonymi w pliku konfiguracyjnym.

## ⚙️ Najlepsze praktyki

### 🔑 Spójne nazewnictwo kluczy

Zadbaj o spójność kluczy tłumaczeń we wszystkich plikach, aby uniknąć nieporozumień i duplikacji.

### 🧹 Regularne utrzymanie

Okresowo przeglądaj i czyść nieużywane klucze tłumaczeń, aby pliki pozostały zorganizowane i łatwe w zarządzaniu.

### 🛠 Automatyzuj wysyłanie i pobieranie

Zintegruj polecenia Crowdin CLI z pipeline CI/CD, aby zautomatyzować przesyłanie plików źródłowych i pobieranie tłumaczeń, zapewniając, że tłumaczenia są zawsze aktualne.

Postępując zgodnie z tym przewodnikiem, będziesz w stanie płynnie zintegrować Crowdin z projektem, zapewniając wydajne i uporządkowane podejście do zarządzania wysiłkami internacjonalizacyjnymi.
