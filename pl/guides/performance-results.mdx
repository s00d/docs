# Wyniki testów wydajności

## Informacje o projekcie

- **[plain-nuxt](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/plain-nuxt)**: ./test/fixtures/plain-nuxt
- **[i18n-micro](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n-micro)**: ./test/fixtures/i18n-micro
- **[i18n](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n)**: ./test/fixtures/i18n
- **[CLI](https://github.com/s00d/nuxt-i18n-micro/tree/main/scripts/src/commands/performance.ts)**: `pnpm -C scripts cli performance` / `pnpm test:performance`

### Opis

Porównuje **czysty Nuxt** (baseline bez modułu i18n), **i18n-micro** oraz **`@nuxtjs/i18n` v10.6** pod jednym wspólnym profilem słownika.

Skupienie: czas budowania, szczytowy RSS, deployable **kod vs tłumaczenia vs łącznie** oraz zachowanie serwera pod Artillery + Autocannon.

### Uwagi metodologiczne

- Metryki są **średnimi z 3 kolejnych przebiegów per fixture** (fixture A ×3, potem B ×3, potem C ×3 — nie przeplatane).
- **Translations** obejmują JSON locale pod `locales/` / `_locales/` / `translations/`, wszystko pod `chunks/raw/` oraz odpowiadające chunki locale. Starsze raporty pokazujące „translations: 0 B” dla `@nuxtjs/i18n` i ogromną kolumnę „code” liczyły chunki wiadomości jako kod aplikacji.
- **plain-nuxt** serwuje ten sam wolumen liści jako statyczny JSON `public/translations` (nie statyczne importy JS). Pod Artillery ten baseline jest I/O-heavy; to nie jest „narzut i18n”, to koszt pobierania dużego JSON per żądanie.

### Runs

Wszystkie metryki poniżej są **średnimi z 3 przebiegów**.

| Parametr | Wartość |
|------|-------|
| Locale | **4** (`en`, `de`, `ru`, `fr`) |
| Strony | **2** (`index`, `page`) |

## Uwagi

- Wspólny profil: 4 locale × 2 strony × ~16.8k liści indexu.
- Artillery: 6s warm-up @6 VU/s + 60s głównego @60 VU/s. Autocannon: 10 połączeń × 10s.
- Ponowny run: `pnpm test:performance` lub `pnpm -C scripts cli performance --locales N --keys K --only all|micro|i18n|plain --runs N`.
