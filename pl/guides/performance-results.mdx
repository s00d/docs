# Wyniki testów wydajności

## Informacje o projekcie

- **[plain-nuxt](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/plain-nuxt)**: ./test/fixtures/plain-nuxt
- **[i18n-micro](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n-micro)**: ./test/fixtures/i18n-micro
- **[i18n](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n)**: ./test/fixtures/i18n
- **[CLI](https://github.com/s00d/nuxt-i18n-micro/tree/main/scripts/src/commands/performance.ts)**: `pnpm -C scripts cli performance` / `pnpm test:performance`

### Opis

Porównuje **plain Nuxt** (bazowa bez modułu i18n), **i18n-micro** i **`@nuxtjs/i18n` v10.6** w jednym wspólnym profilu słownikowym.

Skupienie: czas budowy, szczytowy RSS, deployowalne **kod vs tłumaczenia vs suma** oraz zachowanie serwera pod Artillery + Autocannon.

### Uwagi metodologiczne

- Metryki to **średnie z 3 kolejnych uruchomień per fixture** (fixture A ×3, potem B ×3, potem C ×3 — nie przeplatane).
- **Tłumaczenia** obejmują JSON lokalizacji pod `locales/` / `_locales/` / `translations/`, wszystko pod `chunks/raw/` oraz odpowiadające chunki lokalizacji. Starsze raporty, które pokazywały `@nuxtjs/i18n` „translations: 0 B” i ogromną kolumnę „code”, liczyły chunki wiadomości jako kod aplikacji.
- **plain-nuxt** serwuje ten sam wolumen liści jako statyczny JSON `public/translations` (nie statyczne importy JS). Pod Artillery ta baza jest ciężka I/O; to nie jest „narzut i18n”, to koszt pobierania dużych JSON per żądanie.

### Uruchomienia

Wszystkie metryki poniżej to **średnie z 3 uruchomień**.

## Uwagi

- Wspólny profil: 4 lokalizacje × 2 strony × ~16.8k liści indeksu.
- Artillery: 6s warm-up @6 VU/s + 60s głównego @60 VU/s. Autocannon: 10 połączeń × 10s.
- Ponowne uruchomienie: `pnpm test:performance` lub `pnpm -C scripts cli performance --locales N --keys K --only all|micro|i18n|plain --runs N`.
