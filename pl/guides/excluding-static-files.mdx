# Wykluczanie plików statycznych z routingu i18n

## Omówienie

Domyślnie nuxt-i18n-micro automatycznie wyklucza typowe pliki statyczne z przetwarzania routingu i18n. Możesz jednak także skonfigurować niestandardowe wzorce wykluczeń, aby zapobiec przetwarzaniu określonych ścieżek przez system i18n.

## Wbudowane wykluczenia

Moduł automatycznie wyklucza następujące typy plików i wzorce:

- **Sitemapy**: `/sitemap*.xml`, `/sitemap-en.xml` itd.
- **Pliki SEO**: `/robots.txt`, `/favicon.ico`
- **Pliki PWA**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Zasoby statyczne**: pliki z rozszerzeniami takimi jak `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Wewnętrzne ścieżki Nuxt**: dowolna ścieżka zaczynająca się od `__` (jak `/__nuxt/`)

## Niestandardowe wzorce wykluczeń

Możesz zdefiniować niestandardowe wzorce wykluczeń za pomocą opcji `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Typy wzorców

### Wzorce łańcuchowe

- **Dokładne dopasowanie**: `'/api/health'` — pasuje dokładnie do `/api/health`
- **Dopasowanie prefiksu**: `'/admin'` — pasuje do `/admin` i `/admin/dashboard`
- **Wildcards**: `'/api/*'` — pasuje do `/api/users`, ale nie do `/api/users/123`
- **Głębokie wildcards**: `'/admin/**'` — pasuje do `/admin/users` i `/admin/users/123`

### Wyrażenia regularne

Używaj obiektów RegExp do złożonego dopasowywania wzorców:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Przypadki użycia

### Pliki SEO

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### Trasy API

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Panele administracyjne

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Zasoby statyczne

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Jak to działa

1. **Middleware serwera**: middleware Nitro uruchamia się jako pierwsze, aby sprawdzić wzorce wykluczeń
2. **Przetwarzanie stron**: podczas rozwiązywania stron wykluczone ścieżki są pomijane
3. **Trasa catch-all**: trasa fallback sprawdza wykluczenia przed przetwarzaniem
4. **Prerender**: wykluczone ścieżki nie są uwzględniane w prerenderowanych trasach

## Wpływ na wydajność

- Sprawdzenia wykluczeń są zoptymalizowane i uruchamiają się wcześnie w cyklu życia żądania
- Wbudowane wzorce używają wydajnego dopasowywania regex
- Niestandardowe wzorce są cache'owane i reużywane
- Minimalny narzut wydajności dla wykluczonych ścieżek

## Rozwiązywanie problemów

### Pliki statyczne wciąż są przechwytywane

1. **Sprawdź składnię wzorca**: upewnij się, że wzorce pasują do dokładnej struktury ścieżki
2. **Używaj regex do złożonych wzorców**: wildcards łańcuchowe mają ograniczenia
3. **Testuj wzorce**: użyj narzędzi deweloperskich przeglądarki, aby zweryfikować faktyczną ścieżkę żądania
4. **Sprawdź kolejność**: upewnij się, że wzorce wykluczeń są zdefiniowane przed inną konfiguracją i18n

### Wzorzec nie działa

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Tryb debug

Włącz tryb debug, aby zobaczyć przetwarzanie wykluczeń:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Zaloguje to decyzje o wykluczeniach w konsoli.

## Migracja z obejść

Jeśli używałeś obejść takich jak route rules czy middleware, możesz je teraz zastąpić przez `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Nowe podejście jest bardziej niezawodne i działa na wielu poziomach systemu routingu.
