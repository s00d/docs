# 🧪 Testowanie modułu `Nuxt I18n Micro`

## 📖 Wprowadzenie do testowania

Testowanie modułu `Nuxt I18n Micro` ma kluczowe znaczenie, aby upewnić się, że funkcje lokalizacyjne aplikacji działają zgodnie z oczekiwaniami. Ta dokumentacja przeprowadzi Cię przez konfigurację środowiska testowego, tworzenie mock-konfiguracji dla vitest oraz pisanie testów komponentów. Praktyczny przykład znajdziesz w [projekcie przykładowym na GitHub](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/test-utils/example).

Zobacz [Testowanie strategii routingu](https://github.com/s00d/nuxt-i18n-micro/blob/main/docs/guide/testing-strategies.md), aby zobaczyć, jak to repozytorium uruchamia własne zestawy testów — projekty Vitest `unit` / `integration` / `e2e`, pliki per strategia (`test/strategies-*.test.ts`) oraz generuje regresje.

## 🛠️ Konfiguracja środowiska testowego

### 1. Zainstaluj `@i18n-micro/test-utils`

Najpierw musisz zainstalować narzędzia testowe dla `Nuxt I18n Micro`. Ten pakiet zapewnia niezbędne narzędzia do mockowania i testowania konfiguracji i18n.

```bash
npm install @i18n-micro/test-utils --save-dev
```

### 2. Utwórz plik mock-konfiguracji

Następnie utwórz plik do konfiguracji mockowanego i18n. Ten plik będzie używany do mockowania funkcji i narzędzi i18n podczas testów.

```typescript
// tests/unit-setup.ts

import { mockNuxtImport } from '@nuxt/test-utils/runtime'
import { vi } from 'vitest'
import { i18nUtils } from '@i18n-micro/test-utils'

export function createFakeI18n() {
  return {
    $getLocale: vi.fn(i18nUtils.getLocale),
    $t: vi.fn(i18nUtils.t),
    $tc: vi.fn(i18nUtils.tc),
    $setLocale: vi.fn(i18nUtils.setLocale),
    $getLocaleName: vi.fn(i18nUtils.getLocaleName),
    $setLocaleName: vi.fn(i18nUtils.setLocaleName),
    $getLocales: vi.fn(i18nUtils.getLocales),
    $setLocales: vi.fn(i18nUtils.setLocales),
    $defaultLocale: vi.fn(i18nUtils.defaultLocale),
    $setDefaultLocale: vi.fn(i18nUtils.setDefaultLocale),
    $getRouteName: vi.fn(i18nUtils.getRouteName),
    $settRouteName: vi.fn(i18nUtils.settRouteName),
    $ts: vi.fn(i18nUtils.ts),
    $tn: vi.fn(i18nUtils.tn),
    $td: vi.fn(i18nUtils.td),
    $has: vi.fn(i18nUtils.has),
    $resolveTranslations: vi.fn(i18nUtils.resolveTranslations),
    $setTranslation: vi.fn(i18nUtils.setTranslation),
    $mergeTranslations: vi.fn(i18nUtils.mergeTranslations),
    $switchLocaleRoute: vi.fn(i18nUtils.switchLocaleRoute),
    $switchLocalePath: vi.fn(i18nUtils.switchLocalePath),
    $switchLocale: vi.fn(i18nUtils.switchLocale),
    $switchRoute: vi.fn(i18nUtils.switchRoute),
    $localeRoute: vi.fn(i18nUtils.localeRoute),
    $localePath: vi.fn(i18nUtils.localePath),
    $setI18nRouteParams: vi.fn(i18nUtils.setI18nRouteParams),
  }
}

mockNuxtImport<() => ReturnType<typeof createFakeI18n>>('useI18n', () => vi.fn(() => createFakeI18n()))

export const setTranslationsFromJson = i18nUtils.setTranslationsFromJson
```

### 3. Skonfiguruj Vitest

Teraz skonfiguruj Vitest, aby używał pliku mock-konfiguracji i skonfigurował środowisko testowe.

```typescript
// vitest.config.ts

import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    watch: false,
    setupFiles: ['./tests/unit-setup.ts'],
    include: ['./**/*.spec.ts'],
  },
})
```

## 🧪 Pisanie testów

### Przykładowy komponent

Oto przykład prostego komponentu, który używa composable `useI18n` do tłumaczenia wiadomości.

```vue
<script setup lang="ts">
const { $t } = useI18n()

const props = defineProps({
  message: {
    type: String,
    default: null,
  },
})

// Test to see that $t works in script setup as well as the template
const message = props.message || $t('defaultMessage')
</script>

<template>
  <div>
    <p>Test from component: {{ $t('welcome') }}</p>
    <p data-testid="message">Test message from props: {{ message }}</p>
  </div>
</template>
```

### Plik testowy

Teraz napiszmy test dla tego komponentu.

```typescript
// tests/unit/example.spec.ts

import { describe, it, expect, beforeEach } from 'vitest'
import { mount } from '@vue/test-utils'
import ExampleComponent from '@/components/ExampleComponent.vue'
import fs from 'fs'
import path from 'path'
import { setTranslationsFromJson } from './unit-setup'

describe('ExampleComponent', () => {
  beforeEach(async () => {
    const fileContent = fs.readFileSync(path.join(__dirname, '../../locales/en-GB.json')).toString()
    await setTranslationsFromJson('en', JSON.parse(fileContent))
  })

  it('renders the welcome message correctly', () => {
    const wrapper = mount(ExampleComponent)
    expect(wrapper.text()).toContain('Test from component: Welcome')
  })

  it('renders the default message correctly', () => {
    const wrapper = mount(ExampleComponent)
    expect(wrapper.find('[data-testid="message"]').text()).toContain('Test message from props: Default Message')
  })

  it('renders the custom message correctly', () => {
    const wrapper = mount(ExampleComponent, {
      props: {
        message: 'Custom Message',
      },
    })
    expect(wrapper.find('[data-testid="message"]').text()).toContain('Test message from props: Custom Message')
  })
})
```

## 📝 Najlepsze praktyki testowania

- **🔧 Mockuj funkcje i18n:** zawsze mockuj funkcje i18n za pomocą `@i18n-micro/test-utils`, aby zapewnić spójne i przewidywalne wyniki testów.
- **⚙️ Używaj Vitest do testów jednostkowych:** Vitest to potężny framework testowy dla aplikacji Vue. Używaj go do pisania testów jednostkowych komponentów.
- **📚 Dokumentuj swoje testy:** wyraźnie dokumentuj cel i oczekiwane wyniki każdego testu. Ułatwi to utrzymanie klarowności i innym (lub przyszłemu Tobie) zrozumienie testów.

## 📊 Metody narzędziowe i18n

Poniżej znajduje się tabela opisująca wszystkie metody narzędziowe dostarczane przez `@i18n-micro/test-utils`.

| Metoda                                          | Opis                                                                                                                                       |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `t(key, params, defaultValue)`                  | Tłumaczy klucz z opcjonalnymi parametrami i wartością domyślną.                                                                            |
| `tc(key, params, defaultValue)`                 | Tłumaczy klucz z obsługą pluralizacji.                                                                                                     |
| `setTranslationsFromJson(locale, translations)` | Ładuje tłumaczenia z obiektu JSON dla konkretnej lokalizacji.                                                                              |
| `getLocale()`                                   | Zwraca bieżącą lokalizację.                                                                                                                |
| `setLocale(val)`                                | Ustawia bieżącą lokalizację.                                                                                                               |
| `getLocaleName()`                               | Zwraca nazwę bieżącej lokalizacji.                                                                                                         |
| `setLocaleName(val)`                            | Ustawia nazwę bieżącej lokalizacji.                                                                                                        |
| `getLocales()`                                  | Zwraca listę dostępnych lokalizacji.                                                                                                       |
| `setLocales(val)`                               | Ustawia listę dostępnych lokalizacji.                                                                                                      |
| `defaultLocale()`                               | Zwraca domyślną lokalizację.                                                                                                               |
| `setDefaultLocale(val)`                         | Ustawia domyślną lokalizację.                                                                                                              |
| `getRouteName()`                                | Zwraca bieżącą nazwę trasy.                                                                                                                |
| `settRouteName(val)`                            | Ustawia bieżącą nazwę trasy.                                                                                                               |
| `ts(key, params, defaultValue)`                 | Tłumaczy klucz i zwraca wynik jako ciąg.                                                                                                   |
| `tn(value, options?)`                           | Formatuje liczbę z inline'owymi `Intl.NumberFormatOptions`. Nazwane formaty wymagają konfiguracji modułu i nie są dostępne w tym samodzielnym helperze. |
| `td(value, options?)`                           | Formatuje datę z inline'owymi `Intl.DateTimeFormatOptions`. Nazwane formaty wymagają konfiguracji modułu i nie są dostępne w tym samodzielnym helperze. |
| `has(key)`                                      | Sprawdza, czy klucz tłumaczenia istnieje.                                                                                                  |
| `resolveTranslations()`                         | Zwraca aktywne drzewo tłumaczeń dla bieżącej lokalizacji i trasy.                                                                          |
| `setTranslation(key, value)`                    | Zastępuje wartość pod `key` w aktywnym słowniku (zastąpienie, nie scalenie).                                                               |
| `mergeTranslations(newTranslations)`            | Scala tłumaczenia z aktywną lokalizacją w runtime.                                                                                         |

Postępując zgodnie z tymi krokami, możesz skutecznie testować moduł `Nuxt I18n Micro` i upewnić się, że funkcje lokalizacyjne aplikacji działają zgodnie z oczekiwaniami.
