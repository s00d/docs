# Nadpisania i18n w runtime

Używaj tego przewodnika, gdy potrzebujesz jednego artefaktu buildu działającego z różnymi domyślnymi locale w zależności od środowiska (na przykład: różne instancje dla najemców).

## Co można nadpisać w runtime

Moduł obsługuje bezpieczne nadpisania w runtime dla:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Te nadpisania są stosowane na wierzchu konfiguracji z buildu z `.nuxt/i18n.strategy.mjs` i `.nuxt/i18n.config.mjs`.

## Czego nie można nadpisać w runtime

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) jest kwestią buildu, ponieważ wpływa na zachowanie wygenerowanych tras.

Jeśli przekażesz nadpisanie strategii w runtime, jest ignorowane i emitowane jest ostrzeżenie.

## Nadpisania oparte o RuntimeConfig

Podaj wartości runtime pod `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Nadpisania przez zmienne środowiskowe

Możesz też konfigurować nadpisania przez zmienne środowiskowe:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (rozdzielone przecinkami, np. `fr,it`)

Obsługiwane są też aliasy zastępcze:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Reguły walidacji

W runtime moduł waliduje nadpisania, aby uniknąć zepsutego stanu:

- Nie możesz wyłączyć wszystkich locale.
- `defaultLocale` musi wskazywać na włączone locale.
- `fallbackLocale` musi istnieć w zadeklarowanych locale.

Jeśli nadpisanie jest nieprawidłowe, moduł zachowuje bezpieczną wartość i loguje ostrzeżenie.

## Uwagi dla wdrożeń wieloinstancyjnych

Ta funkcja runtime jest zaprojektowana z myślą o aktywacji locale i wartościach domyślnych per instancja, bez przebudowywania.

Jeśli instancje wymagają różnych strategii URL (`no_prefix` vs `prefix`), użyj osobnych buildów dla każdej strategii.

## Wyłączone locale i statyczne payloady

`runtimeConfig.public.i18nRuntime.disabledLocales` aktualizuje routing, switcher oraz **handler** payloadów Nitro — ale Nitro serwuje pliki pod `public/` **przed** tym handlerem.

Jeśli `translationPayloads.publicAssets` (lub wymuszona kopia public dla Node SSR) już zapisało `/_locales/\{page\}/\{locale\}/data.json`, wyłączenie w runtime nie ukryje tego pliku. Preferuj `locale.disabled: true` w czasie buildu, aby premerge nie emitował statycznych payloadów dla tego locale.
