# Nadpisania i18n w runtime

Skorzystaj z tego przewodnika, gdy potrzebujesz, aby jeden artefakt buildu działał z różnymi domyślnymi lokalizacjami w zależności od środowiska (na przykład: różne instancje tenantów).

## Co można nadpisać w runtime

Moduł obsługuje bezpieczne nadpisania w runtime dla:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Te nadpisania są nakładane na konfigurację z czasu budowy z `.nuxt/i18n.strategy.mjs` i `.nuxt/i18n.config.mjs`.

## Czego nie można nadpisać w runtime

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) jest kwestią czasu budowy, ponieważ wpływa na zachowanie generowanych tras.

Jeśli przekażesz nadpisanie strategii w runtime, jest ono ignorowane i emitowane jest ostrzeżenie.

## Nadpisania oparte na RuntimeConfig

Podaj wartości runtime pod `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Nadpisania przez zmienne środowiskowe

Możesz też skonfigurować nadpisania przez zmienne środowiskowe:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (rozdzielone przecinkami, np. `fr,it`)

Obsługiwane są też aliasy fallbacków:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Reguły walidacji

W runtime moduł waliduje nadpisania, aby uniknąć zepsutego stanu:

- Nie możesz wyłączyć wszystkich lokalizacji.
- `defaultLocale` musi wskazywać włączoną lokalizację.
- `fallbackLocale` musi istnieć wśród zadeklarowanych lokalizacji.

Jeśli nadpisanie jest nieprawidłowe, moduł zachowuje bezpieczną wartość i loguje ostrzeżenie.

## Uwagi dotyczące wdrożeń wielo-instancyjnych

Ta funkcja runtime jest zaprojektowana do aktywacji i domyślnych wartości lokalizacji per instancja bez przebudowy.

Jeśli instancje wymagają różnych strategii URL (`no_prefix` vs `prefix`), użyj osobnych buildów dla każdej strategii.

## Wyłączone lokalizacje i statyczne payloady

`runtimeConfig.public.i18nRuntime.disabledLocales` aktualizuje routing, switcher i **handler** payloadu Nitro — ale Nitro serwuje pliki z `public/` **przed** tym handlerem.

Jeśli `translationPayloads.publicAssets` (lub wymuszona kopia publiczna dla Node SSR) już zapisała `/_locales/\{page\}/\{locale\}/data.json`, wyłączenie w runtime nie może ukryć tego pliku. Preferuj `locale.disabled: true` w buildzie, aby premerge nie emitował statycznych payloadów tej lokalizacji.
