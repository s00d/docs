Moduł wywołuje jeden hook wykonawczy (aplikacji), `i18n:register`. Używaj go, gdy plugin lub moduł dodaje tłumaczenia, których nie ma w Twoich plikach `locales/`. Twój callback otrzymuje funkcję `register`, która scala tłumaczenia ze stroną, która jest właśnie wyświetlana.

## `i18n:register` {#i18nregister}

```ts
'i18n:register': (
  register: (translations: unknown, locale?: string) => void,
  locale: string,
) => HookResult
```

| Argument | Opis |
| --- | --- |
| `register(translations, locale?)` | Głęboko scala `translations` z fragmentem (chunk) strony dla ładowanej trasy, dla `locale` (domyślnie: `locale` hooka). Istniejące klucze są nadpisywane. |
| `locale` | Locale ładowanej trasy. |

Hook jest typowany przez `RuntimeNuxtHooks`, więc `nuxtApp.hook('i18n:register', …)` nie wymaga rzutowania.

## Kiedy jest wywoływany {#when-it-fires}

Wywołuje go plugin ładujący (`i18n-plugin-loader`):

1. raz przy starcie, gdy wszystkie pluginy już się wykonały (`app:created`), a przed wyrenderowaniem aplikacji;
2. w swoim `router.beforeEach`, po załadowaniu tłumaczeń strony docelowej, gdy zmienia się ścieżka — przy każdej nawigacji w strategii `no_prefix`.

Na każdy callback i każde wywołanie `register` aplikacja czeka przed renderowaniem lub kontynuowaniem nawigacji, więc strona renderuje się ze scalonymi kluczami. Przy [`hooks: false`](/pl/api/module-options#hooks) hook nigdy nie jest wywoływany.

## Przykład {#example}

```ts
// plugins/i18n-extra.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('i18n:register', async (register, locale) => {
    const extra = await $fetch<Record<string, unknown>>(`/api/cms-strings/${locale}`)
    register(extra, locale)
  })
})
```

To jest hook wykonawczy: rejestruj go przez `nuxtApp.hook` w pluginie, a nie przez `nuxt.hook` w `nuxt.config` czy w `setup` modułu. Moduł dodaje taki plugin za pomocą `addPlugin`.
