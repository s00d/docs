# 🌍 Kompozycja `useLocaleHead`

Kompozycja `useLocaleHead` to narzędzie w `Nuxt I18n Micro`, które pomaga zarządzać atrybutami SEO i metatagami HTML dla zlokalizowanych tras. Dynamicznie generuje atrybuty `lang` i `dir` dla dokumentu HTML oraz tworzy tagi `meta` i `link` w celu poprawy SEO Twoich zlokalizowanych treści.

## ⚙️ Opcje

```ts
useLocaleHead(options: UseLocaleHeadOptions): { metaObject: Ref<{ htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string }; link: { href: string; hreflang?: string; rel: string; [key: string]: string | undefined }[]; meta: { content: string; property: string; [key: string]: string }[] }, MetaObject | { htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string }; link: { href: string; hreflang?: string; rel: string; [key: string]: string | undefined }[]; meta: { content: string; property: string; [key: string]: string }[] }>; updateMeta: () => void }
```

Tagi head SEO dla bieżącej trasy: alternatywy `hreflang` dla każdego locale plus
`x-default`, link kanoniczny, `og:locale` oraz `lang`/`dir` na `<html>`.

Potrzebne tylko, gdy `meta` jest wyłączone lub domyślne ustawienia wymagają korekty — przy `meta: true` moduł rejestruje te same tagi samodzielnie.

**Zwraca** — ref przechowujący obiekt head, gotowy do przekazania do `useHead`

const head = useLocaleHead({ addSeoAttributes: true })

## 🛠️ Wartości zwracane

Kompozycja `useLocaleHead` zwraca reaktywny obiekt oraz funkcję aktualizującą, którą należy wywołać, gdy zmieniają się dane źródłowe. Oba kształty znajdują się w sygnaturze powyżej, wygenerowanej ze źródła.

### `metaObject`

Reaktywny payload head (atrybuty html, meta, link) odpowiedni dla `useHead(metaObject)`.

- **Przykład**:
  ```js
  const { metaObject } = useLocaleHead()
  useHead(metaObject)
  ```

### `updateMeta`

Przelicza `metaObject` na podstawie bieżącej trasy, locale i konfiguracji. Wywołuj, gdy zmieniają się wejścia — na przykład przy zmianie trasy.

- **Przykład**:
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  useHead(metaObject)
  watch(
    () => route.fullPath,
    () => updateMeta(),
    { immediate: true },
  )
  ```

### Dostęp do `link` i `meta`

Tablice `link` i `meta` są dostępne przez `metaObject.value`:

- **Przykład**:
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  updateMeta()
  console.log(metaObject.value.link)
  // Output: [{ id: 'i18n-can', rel: 'canonical', href: 'https://example.com/about' }, ...]
  console.log(metaObject.value.meta)
  // Output: [{ id: 'i18n-og', property: 'og:locale', content: 'en_US' }, ...]
  ```

## 🛠️ Przykłady użycia

### Podstawowe użycie

Generuj atrybuty head specyficzne dla locale z domyślnymi opcjami.

```js
const head = useLocaleHead()
```

### Niestandardowy atrybut identyfikujący

Użyj niestandardowego atrybutu identyfikującego dla generowanych tagów.

```js
const head = useLocaleHead({ identifierAttribute: 'data-i18n' })
```

### Wyłącz atrybuty SEO

Generuj atrybuty head bez dodawania meta i link tagów związanych z SEO.

```js
const head = useLocaleHead({ addSeoAttributes: false })
```

### Wskaż bazowy URL

Ustaw niestandardowy bazowy URL dla URL-i kanonicznych i alternatywnych.

```js
const head = useLocaleHead({ baseUrl: 'https://mywebsite.com' })
```

## 🚀 Dodatkowe funkcje

### Meta i link tagi SEO

Gdy `addSeoAttributes` jest włączone, kompozycja automatycznie generuje następujące tagi:

- `og:locale` dla bieżącego locale (`language_TERRITORY`, z podkreśleniem). Wyprowadzane z `locale.og` lub konwertowane z `locale.iso`, gdy to możliwe.
- `og:url` dla kanonicznego URL-a strony.
- `og:locale:alternate` dla alternatywnych wersji językowych.
- Linki `rel="canonical"` i `rel="alternate"` na potrzeby optymalizacji SEO.
- Link `hreflang="x-default"` wskazujący na URL domyślnego locale. Informuje to wyszukiwarki, który URL pokazać użytkownikom, których język nie pasuje do żadnego zdefiniowanego locale.

### Dynamiczne locale i kierunek

Kompozycja dynamicznie ustala atrybuty `lang` i `dir` na podstawie locale bieżącej trasy, dzięki czemu Twój dokument HTML jest poprawnie skonfigurowany dla użytkowników międzynarodowych.

### Obsługa zlokalizowanych tras

Jeśli Twoje trasy mają prefiksy z kodami locale (np. `/en/about`), kompozycja inteligentnie dostosowuje pełną ścieżkę do generowania URL-i, zapewniając dokładność i trafność atrybutów SEO.

Ta kompozycja upraszcza optymalizację aplikacji Nuxt pod kątem odbiorców międzynarodowych, przygotowując Twoją stronę na globalne wyszukiwarki i użytkowników.

## 🛠️ Przykład użycia

Poniższy przykład pokazuje, jak używać kompozycji `useLocaleHead` w komponencie Vue z domyślnymi ustawieniami:

```vue
<script setup>
import { useRoute, watch } from '#imports'
const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({
  addDirAttribute: true,
  identifierAttribute: 'id',
  addSeoAttributes: true,
})
useHead(metaObject)
watch(
  () => route.fullPath,
  () => updateMeta(),
  { immediate: true },
)
</script>
```

### Wyjaśnienie kodu

- **Kompozycja `useLocaleHead`**: Wywoływana jest w sekcji `<script setup>` i zwraca obiekt zawierający `htmlAttrs`, `meta` oraz `link`.

- **Tag `<html>`**: Atrybuty `lang` i `dir` dokumentu HTML są dynamicznie ustalane na podstawie bieżącego locale i stosowane do tagu `<html>`.

- **Sekcja `<head>`**:
  - **Metatagi**: Generowane są metatagi SEO, w tym `og:locale`, `og:url` oraz `rel="canonical"` i `rel="alternate"` do wskazania alternatywnych wersji językowych strony.
  - **Tagi link**: Dołączane są linki kanoniczne, linki do alternatywnych wersji językowych oraz link `hreflang="x-default"` (wskazujący na URL domyślnego locale).

- **Sekcja `<body>`**: Wyświetla się tu główna zawartość strony. W tym przykładzie użyto prostego nagłówka i akapitu.

### 📝 Uwagi

1. **Atrybuty**: Używane atrybuty (`lang`, `dir`, `rel`, `href`, `hreflang`, `property`, `content`) są wyodrębniane z obiektu zwracanego przez `useLocaleHead`.

2. **Generowanie tagów SEO**: Jeśli opcja `addSeoAttributes` jest ustawiona na `true`, kompozycja automatycznie generuje tagi SEO dla bieżącego locale.

3. **Bazowy URL**: Możesz ustawić własny bazowy URL za pomocą opcji `baseUrl`, aby poprawnie generować linki kanoniczne i alternatywne.

Ten przykład pokazuje, jak łatwo zintegrować `useLocaleHead` z komponentami aplikacji, aby zapewnić poprawne atrybuty SEO i poprawić indeksowanie zlokalizowanych stron w wyszukiwarkach.

## 🧩 Dostosowanie i cykl życia

- `useLocaleHead` sam nie subskrybuje zmian. Zwraca `metaObject` i `updateMeta`.
- Powinieneś wywoływać `updateMeta()`, gdy zmieniają się wejścia (zwykle przy zmianie trasy), na przykład z wtyczki:

```ts
// plugins/02.meta.ts
export default defineNuxtPlugin(() => {
  const route = useRoute()
  const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
  useHead(metaObject)
  if (import.meta.server) updateMeta()
  else
    watch(
      () => route.fullPath,
      () => updateMeta(),
      { immediate: true },
    )
})
```

## Kiedy używać zamiast tego `useI18nHead`

Gdy `meta: true` (domyślnie), preferuj [`useI18nHead`](/api/composables/use-i18n-head) dla nadpisań **per strona** (niestandardowy hreflang, dodatkowe `og:title`, częściowe wyłączenie). Używaj `useLocaleHead` bezpośrednio tylko, gdy `meta: false` lub sam zarządzasz `useHead`.
