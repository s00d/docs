# 🌍 Composable `useLocaleHead`

Composable `useLocaleHead` to narzędzie w `Nuxt I18n Micro`, które pomaga zarządzać atrybutami SEO i tagami meta HTML dla zlokalizowanych tras. Dynamicznie generuje atrybuty `lang` i `dir` dokumentu HTML oraz tworzy tagi `meta` i `link`, aby poprawić SEO Twojej zlokalizowanej zawartości.

## ⚙️ Opcje

{/* generated:symbol:useLocaleHead — do not edit; run `pnpm run docs:generate` */}

```ts
useLocaleHead(options: UseLocaleHeadOptions): { metaObject: Ref<{ htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string }; link: { href: string; hreflang?: string; rel: string; [key: string]: string | undefined }[]; meta: { content: string; property: string; [key: string]: string }[] }, MetaObject | { htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string }; link: { href: string; hreflang?: string; rel: string; [key: string]: string | undefined }[]; meta: { content: string; property: string; [key: string]: string }[] }>; updateMeta: () => void }
```

Tagi head SEO dla bieżącej trasy: alternatywy `hreflang` dla każdej lokalizacji plus
`x-default`, link kanoniczny, `og:locale` oraz `lang`/`dir` na `<html>`.

Potrzebne tylko wtedy, gdy `meta` jest wyłączone lub wymaga dostosowania. Z `meta: true`
moduł rejestruje te same tagi samodzielnie.

| Parametr | Typ | Opis |
| --- | --- | --- |
| `options` | `UseLocaleHeadOptions` |  |

**Zwraca** — ref przechowujący obiekt head, gotowy do przekazania do `useHead`

```ts
const head = useLocaleHead({ addSeoAttributes: true })
useHead(head)
```

## 🛠️ Wartości zwracane

Composable `useLocaleHead` zwraca reaktywny obiekt oraz funkcję aktualizującą, którą powinieneś
wywołać, gdy zmieniają się dane źródłowe. Oba kształty są w sygnaturze powyżej, wygenerowanej ze źródła.

### `metaObject`

Reaktywny payload head (html attrs, meta, link) odpowiedni do `useHead(metaObject)`.

- **Przykład**:
  ```js
  const { metaObject } = useLocaleHead()
  useHead(metaObject)
  ```

### `updateMeta`

Przelicza `metaObject` na podstawie bieżącej trasy, lokalizacji i konfiguracji. Wywołaj ją, gdy dane wejściowe się zmieniają — na przykład przy zmianie trasy.

- **Przykład**:
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  useHead(metaObject)
  watch(
    () => route.fullPath,
    () => updateMeta(),
    { immediate: true },
  )
  ```

### Dostęp do `link` i `meta`

Tablice `link` i `meta` są dostępne przez `metaObject.value`:

- **Przykład**:
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  updateMeta()
  console.log(metaObject.value.link)
  // Output: [{ id: 'i18n-can', rel: 'canonical', href: 'https://example.com/about' }, ...]
  console.log(metaObject.value.meta)
  // Output: [{ id: 'i18n-og', property: 'og:locale', content: 'en_US' }, ...]
  ```

## 🛠️ Przykładowe użycia

### Podstawowe użycie

Wygeneruj atrybuty head specyficzne dla lokalizacji z domyślnymi opcjami.

```js
const head = useLocaleHead()
```

### Dostosowanie atrybutu identyfikatora

Użyj niestandardowego atrybutu identyfikatora dla generowanych tagów.

```js
const head = useLocaleHead({ identifierAttribute: 'data-i18n' })
```

### Wyłączenie atrybutów SEO

Wygeneruj atrybuty head bez dodawania tagów meta i link związanych z SEO.

```js
const head = useLocaleHead({ addSeoAttributes: false })
```

### Określenie bazowego URL

Ustaw niestandardowy bazowy URL dla linków kanonicznych i alternatywnych.

```js
const head = useLocaleHead({ baseUrl: 'https://mywebsite.com' })
```

## 🚀 Dodatkowe funkcje

### Tagi meta i link SEO

Gdy `addSeoAttributes` jest włączone, composable automatycznie generuje następujące tagi:

- `og:locale` dla bieżącej lokalizacji (`language_TERRITORY`, podkreślenie). Wyprowadzone z `locale.og` lub przekonwertowane z `locale.iso`, gdy to możliwe.
- `og:url` dla kanonicznego URL strony.
- `og:locale:alternate` dla alternatywnych wersji językowych.
- Linki `rel="canonical"` i `rel="alternate"` do optymalizacji SEO.
- Link `hreflang="x-default"` wskazujący URL domyślnej lokalizacji. Informuje wyszukiwarki, który URL pokazać użytkownikom, których język nie pasuje do żadnej ze zdefiniowanych lokalizacji.

### Dynamiczna lokalizacja i kierunek

Composable dynamicznie określa atrybuty `lang` i `dir` na podstawie lokalizacji bieżącej trasy, zapewniając, że dokument HTML jest prawidłowo skonfigurowany dla użytkowników międzynarodowych.

### Obsługa zlokalizowanych tras

Jeśli Twoje trasy mają prefiksy kodów lokalizacji (np. `/en/about`), composable inteligentnie dostosowuje pełną ścieżkę do generowania URL-i, zapewniając, że atrybuty SEO są dokładne i istotne.

Ten composable upraszcza proces optymalizacji Twojej aplikacji Nuxt pod kątem odbiorców międzynarodowych, zapewniając dobre przygotowanie witryny dla globalnych wyszukiwarek i użytkowników.

## 🛠️ Przykład użycia

Poniższy przykład pokazuje, jak używać composable `useLocaleHead` w komponencie Vue z domyślnymi ustawieniami:

```vue
<script setup>
import { useRoute, watch } from '#imports'
const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({
  addDirAttribute: true,
  identifierAttribute: 'id',
  addSeoAttributes: true,
})
useHead(metaObject)
watch(
  () => route.fullPath,
  () => updateMeta(),
  { immediate: true },
)
</script>
```

### Wyjaśnienie kodu

- **Composable `useLocaleHead`**: Ten composable jest wywoływany w sekcji `<script setup>` i zwraca obiekt zawierający `htmlAttrs`, `meta` i `link`.

- **Tag `<html>`**: Atrybuty `lang` i `dir` dokumentu HTML są dynamicznie określane na podstawie bieżącej lokalizacji i stosowane do tagu `<html>`.

- **Sekcja `<head>`**:
  - **Tagi meta**: generowane są tagi meta związane z SEO, w tym `og:locale`, `og:url` oraz tagi `rel="canonical"` i `rel="alternate"` określające alternatywne wersje językowe strony.
  - **Tagi link**: dołączane są linki kanoniczne, linki do alternatywnych wersji językowych oraz link `hreflang="x-default"` (wskazujący domyślny URL lokalizacji).

- **Sekcja `<body>`**: tutaj wyświetlana jest główna zawartość strony. W tym przykładzie użyto prostego nagłówka i akapitu.

### 📝 Uwagi

1. **Atrybuty**: użyte atrybuty (`lang`, `dir`, `rel`, `href`, `hreflang`, `property`, `content`) są wyodrębniane z obiektu zwracanego przez `useLocaleHead`.

2. **Generowanie tagów SEO**: jeśli opcja `addSeoAttributes` jest ustawiona na `true`, composable automatycznie generuje tagi SEO dla bieżącej lokalizacji.

3. **Base URL**: możesz ustawić własny bazowy URL za pomocą opcji `baseUrl`, aby poprawnie wygenerować linki kanoniczne i alternatywne.

Ten przykład pokazuje, jak łatwo jest zintegrować `useLocaleHead` w komponentach aplikacji, aby zapewnić prawidłowe atrybuty SEO i poprawić indeksację zlokalizowanych stron przez wyszukiwarki.

## 🧩 Dostosowywanie i cykl życia

- `useLocaleHead` nie subskrybuje zmian samodzielnie. Zwraca `metaObject` i `updateMeta`.
- Powinieneś wywołać `updateMeta()`, gdy dane wejściowe się zmieniają (zwykle przy zmianie trasy), na przykład z pluginu:

```ts
// plugins/02.meta.ts
export default defineNuxtPlugin(() => {
  const route = useRoute()
  const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
  useHead(metaObject)
  if (import.meta.server) updateMeta()
  else
    watch(
      () => route.fullPath,
      () => updateMeta(),
      { immediate: true },
    )
})
```

## Kiedy używać zamiast tego `useI18nHead`

Gdy `meta: true` (domyślnie), preferuj [`useI18nHead`](/api/composables/use-i18n-head) do nadpisań **per strona** (niestandardowy hreflang, dodatkowe `og:title`, częściowe wyłączenie). Używaj bezpośrednio `useLocaleHead` tylko wtedy, gdy `meta: false` lub sam zarządzasz `useHead`.
