# useI18nLocale

## Sygnatura

{/* generated:symbol:useI18nLocale — do not edit; run `pnpm run docs:generate` */}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getLocaleWithServerFallback: (serverLocale?: string | null) => string | null; getPreferredLocale: () => string | null; hashCookie: any; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: any; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Scentralizowany punkt wejścia do zarządzania lokalizacją i18n.
Łączy `useState('i18n-locale')`, ciasteczko lokalizacji oraz narzędzia synchronizacyjne.

{/* /generated:symbol:useI18nLocale */}

## Użycie

```vue
<script setup>
const {
  locale,
  localeCookie,
  hashCookie,
  validLocales,
  getPreferredLocale,
  getLocale,
  getLocaleWithServerFallback,
  getEffectiveLocale,
  resolveInitialLocale,
  setLocale,
  syncLocale,
  isValidLocale,
} = useI18nLocale()

// Set locale (updates state and cookies)
setLocale('de')

// Get current locale (state → cookie)
const current = getLocale()

// Get valid preferred locale
const preferred = getPreferredLocale()
</script>
```

## API

| Właściwość/Metoda                               | Typ                                 | Opis                                                                                       |
| ----------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------ |
| `locale`                                        | `Ref<string \| null>`               | Reaktywny stan lokalizacji (`useState('i18n-locale')`)                                     |
| `localeCookie`                                  | `Ref`                               | Ciasteczko lokalizacji (gdy opcja `localeCookie` jest włączona)                            |
| `hashCookie`                                    | `Ref`                               | Ciasteczko używane, gdy aktywny jest `hashMode`                                            |
| `validLocales`                                  | `string[]`                          | Włączone kody lokalizacji z konfiguracji modułu (bez `disabled`)                           |
| `getLocale()`                                   | `() => string \| null`              | Bieżąca lokalizacja: stan → ciasteczko (lub hash cookie w trybie hash)                     |
| `getPreferredLocale()`                          | `() => string \| null`              | Lokalizacja ze stanu/ciasteczka **zwalidowana** względem `validLocales` lub `null`         |
| `getLocaleWithServerFallback(serverLocale?)`    | `(serverLocale?) => string \| null` | Stan → ciasteczko → opcjonalny kontekst serwera (używane podczas inicjalizacji `no_prefix`) |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string`             | Lokalizacja do ładowania tłumaczeń: tryb hash preferuje stan; w przeciwnym razie z trasy   |
| `resolveInitialLocale(options)`                 | `(options) => string`               | Rozwiązuje lokalizację: stan → `serverLocale` → trasa; synchronizuje stan w razie potrzeby |
| `setLocale(locale)`                             | `(locale: string \| null) => void`  | Ustaw lokalizację i zsynchronizuj z ciasteczkami                                           |
| `syncLocale(locale)`                            | `(locale: string \| null) => void`  | Synchronizuj tylko ciasteczka (bez aktualizacji stanu)                                     |
| `isValidLocale(locale)`                         | `(locale) => boolean`               | Sprawdź, czy ciąg znajduje się w `validLocales`                                            |

### Opcje `resolveInitialLocale`

```typescript
interface ResolveInitialLocaleOptions {
  route: unknown
  serverLocale?: string | null
  getLocaleFromRoute: (route?: unknown) => string
}
```

Używane wewnętrznie przez główny plugin przy starcie. Niestandardowe pluginy mogą je wywołać, gdy implementują alternatywne przepływy wykrywania.

### `getEffectiveLocale`

```typescript
const { getEffectiveLocale } = useI18nLocale()
const { $getLocale } = useNuxtApp()

const locale = getEffectiveLocale(route, (r) => $getLocale(r))
```

Zwraca lokalizację używaną do ładowania tłumaczeń i formatowania komunikatów dla danego obiektu trasy.

## Programowe ustawianie lokalizacji

Preferuj `useI18nLocale()` zamiast bezpośredniego użycia `useState('i18n-locale')`:

```ts
// plugins/i18n-loader.server.ts
import { defineNuxtPlugin } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,

  setup() {
    const { setLocale } = useI18nLocale()
    const detectedLocale = 'ja' // Your detection logic here
    setLocale(detectedLocale)
  },
})
```

<Tip>
`setLocale()` aktualizuje preferencję lokalizacji (stan + ciasteczko) tylko. Aby dodatkowo przeładować aktywny kontekst tłumaczeń po stronie klienta, użyj `$switchLocale()` z `useNuxtApp()` lub `useI18n()`. Ma to szczególne znaczenie dla `no_prefix`, gdzie URL się nie zmienia. Zobacz [FAQ — przełącz lokalizację bez zmiany URL-a](/guides/faq#-switch-locale-without-changing-the-url).
</Tip>
