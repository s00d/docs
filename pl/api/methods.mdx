Moduł wstrzykuje swoje helpery runtime do aplikacji Nuxt: `$t`, `$tc`, `$localePath`, `$switchLocale` i pozostałe. Korzystaj z tej strony, aby sprawdzić sygnaturę i działanie helpera. Sygnatury i opisy pochodzą z interfejsów `PluginsInjections` i `NuxtAppOnlyInjections` w `src/runtime/plugins/01.plugin.ts`.

## Dostęp {#access}

| Gdzie | Jak |
| --- | --- |
| Szablon | `{{ $t('title') }}` — każdy helper, z `$` |
| `<script setup>` | `const { t, localePath } = useI18n()` — każdy helper z `PluginsInjections`, z `$` i bez |
| Plugin, middleware, `<script setup>` | `const { $t, $defineI18nRoute } = useNuxtApp()` — wszystko, tylko z `$` |

`$defineI18nRoute` jest typowany wyłącznie w `useNuxtApp()`. Zobacz [`useI18n`](/pl/composables/useI18n).

```vue
<script setup lang="ts">
const { t, localePath } = useI18n()
</script>

<template>
  <NuxtLink :to="localePath('/about')">{{ t('nav.about') }}</NuxtLink>
</template>
```

## Locale {#locale}

### `$getLocale` {#$getlocale}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric) => string
```

Kod aktywnego locale. Przekaż trasę, aby odczytać locale, do którego ta trasa należy.

```ts
$getLocale() // 'de' on /de/about
```

### `$getLocaleName` {#$getlocalename}

```ts
() => string | null
```

`displayName` aktywnego locale z konfiguracji lub `null`, gdy go nie ma.

### `$getLocales` {#$getlocales}

```ts
() => Locale[]
```

Każde skonfigurowane locale wraz z metadanymi.

Niestandardowe właściwości obiektu locale są zwracane tak, jak zostały zapisane; otypuj je za pomocą [rozszerzenia modułu](/pl/api/module-options#locales) typu `Locale`.

### `$defaultLocale` {#$defaultlocale}

```ts
() => string | undefined
```

Kod skonfigurowanego domyślnego locale.

### `$getI18nConfig` {#$geti18nconfig}

```ts
() => ResolvedI18nConfig
```

Rozwiązana konfiguracja modułu, tak jak widzi ją runtime.

Wartość uwzględnia [nadpisania w czasie działania](/pl/guide/runtime-overrides) (`defaultLocale`, `fallbackLocale`, wyłączone locale).

```ts
const { strategy, localeCookie } = useNuxtApp().$getI18nConfig()
```

## Tłumaczenie {#translation}

### `$t` {#$t}

```ts
TranslationFn<CleanTranslation>
```

Tłumaczy klucz, interpolując do niego `params`. Zwraca `defaultValue`, gdy brakuje klucza,
lub sam klucz, gdy nie podano wartości domyślnej.

```ts
// { "welcome": "Welcome, {name}!" }
$t('welcome', { name: 'Ada' }) // 'Welcome, Ada!'
$t('missing.key', {}, 'Fallback') // 'Fallback'
```

Klucz wskazujący zagnieżdżony obiekt zwraca ten obiekt, a nie ciąg znaków. W szablonie renderuje się jako `[object Object]`; używaj klucza liścia.

### `$ts` {#$ts}

```ts
TranslationFn<string>
```

Jak `$t`, ale zawsze zwraca ciąg znaków: wartość przechodzi przez `toString()`, więc zagnieżdżony
obiekt staje się `'[object Object]'`. Kieruj klucz na liść.

### `$_t` {#$_t}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<CleanTranslation>
```

Wiąże `$t` z określoną trasą, do tłumaczenia poza bieżącą stroną — na przykład w layoucie
renderującym link do innej trasy.

```ts
const route = useRoute()
const t = useNuxtApp().$_t(route)
t('page.title')
```

### `$_ts` {#$_ts}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<string>
```

Wiąże `$ts` z określoną trasą. Zobacz `$_t`.

### `$tc` {#$tc}

```ts
(key: TranslationKey, params: number | Params, defaultValue?: string) => string
```

Tłumaczy z uwzględnieniem liczby mnogiej. `params` może być samą liczbą lub obiektem zawierającym
`count`.

Formy oddziela się znakiem `|`. Przy wbudowanej regule nieujemna liczba całkowita `n` wybiera formę `n`, ograniczoną do ostatniej formy; liczba ujemna, ułamkowa lub `NaN` wybiera ostatnią formę. `{count}` i pozostałe parametry są interpolowane do wybranej formy.

Dla języków, których liczba mnoga nie wynika wprost z liczby, rozpocznij szablon od `=0 `. Pierwsza forma jest wtedy dla 0, a pozostałe są wybierane według kategorii [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules), w kolejności `zero, one, two, few, many, other`:

```json
{
  "apples": "=0 no apples | one apple | {count} apples",
  "files": "=0 no files | {count} one | {count} few | {count} many"
}
```

```ts
$tc('apples', 0) // 'no apples'
$tc('apples', 1) // 'one apple'
$tc('apples', 7) // '7 apples'

// In `uk` (categories `one, few, many, other`) the forms after the zero form follow those categories:
$tc('files', 21) // '21 one'
$tc('files', 22) // '22 few'
$tc('files', 25) // '25 many'
$tc('files', 2.5) // '2.5 many': no form for `other`, so the last one
```

- `=0 ` liczy się tylko na samym początku wartości, ze spacją. `$t` pokazuje go jako tekst: należy do liczby mnogiej.
- Kategoria bez własnej formy otrzymuje ostatnią formę. Liczba ujemna lub ułamkowa również otrzymuje ostatnią formę.
- Działa w każdym locale: `=0 none | one | {count} many` po angielsku.
- Kategoria pochodzi z `iso` locale, w przeciwnym razie z jego kodu. Kod, którego `Intl` nie zna, wraca do reguły indeksowej, przy czym znacznik jest nadal usuwany, więc wynik nigdy nie zależy od maszyny.
- `<i18n-t :plural>` stosuje tę samą regułę. Własna funkcja [`plural`](/pl/api/module-options#plural) lub `customPluralRule` otrzymuje surową wartość, łącznie ze znacznikiem, i decyduje sama; `plural` zwracające `null` przekazuje wywołanie z powrotem do wbudowanej reguły, która respektuje znacznik.

Bez znacznika szablon pozostaje przy regule indeksowej, z jednym wyjątkiem, który można odczytać tylko w jeden sposób: forma zerowa bez placeholdera, a następnie jedna forma na kategorię, z `{count}` w każdej formie współdzielonej przez kilka liczb (`no files | {count} one | {count} few | {count} many` w `uk`).

Dla własnych reguł ustaw [`plural`](/pl/api/module-options#plural).

```ts
// { "apples": "no apples | one apple | {count} apples" }
$tc('apples', 0) // 'no apples'
$tc('apples', 10) // '10 apples'
$tc('cart', { count: 2, name: 'Ada' }) // count and params in one object
```

Trzeci argument to `defaultValue`, a nie parametry.

### `$has` {#$has}

```ts
(key: string) => boolean
```

Czy klucz jest rozwiązywany w aktywnym locale. Używaj go do rozgałęziania opcjonalnych tekstów zamiast
renderowania surowego klucza. Podobnie jak `$t` widzi także klucze opuszczanej strony podczas przejścia
między stronami w tym samym locale.

```ts
if ($has('promo.banner')) show.value = true
```

## Formatowanie {#formatting}

### `$tn` {#$tn}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

Formatuje liczbę za pomocą `Intl.NumberFormat` w aktywnym locale. Klucz wybiera nazwany format
z konfiguracji.

Nazwane formaty pochodzą z [`numberFormats`](/pl/api/module-options#numberformats).

```ts
$tn(1234.5, { style: 'currency', currency: 'EUR' }) // '1.234,50 €' in de
$tn(1000, 'currency') // named format
$tn(1000, 'currency', 'de') // named format in another locale
```

### `$td` {#$td}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

Formatuje datę za pomocą `Intl.DateTimeFormat` w aktywnym locale. Klucz wybiera nazwany format
z konfiguracji.

Nazwane formaty pochodzą z [`datetimeFormats`](/pl/api/module-options#datetimeformats).

```ts
$td(new Date(), { dateStyle: 'long' })
$td(post.createdAt, 'short')
```

### `$tdr` {#$tdr}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

Formatuje datę jako czas względny („3 dni temu”) za pomocą `Intl.RelativeTimeFormat`.

```ts
$tdr(Date.now() - 5 * 60_000) // '5 minutes ago' in en
```

## Przełączanie i linki {#switching-and-links}

### `$switchLocale` {#$switchlocale}

```ts
(locale: string) => Promise<boolean>
```

Przechodzi do bieżącej strony w innym locale. W `no_prefix` i trybie hash wczytuje
tłumaczenia locale przed nawigacją; w `no_prefix` trasa jest zastępowana na miejscu (bez
nowego wpisu w historii). Nieznane locale jest ignorowane.
Wywołanie jest asynchroniczne: użyj `await`, aby uruchomić kod po nawigacji. Zwraca `true`, gdy
słownik locale jest aktywny, i `false`, gdy nie jest: nie udało się wczytać chunka (bieżący
słownik pozostaje; wywołaj ponownie, aby spróbować jeszcze raz) lub wygrało nowsze przełączenie.

```ts
await $switchLocale('de')
```

### `$switchLocalePath` {#$switchlocalepath}

```ts
(locale: string) => string
```

Ścieżka bieżącej strony w innym locale, bez nawigacji.

```vue
<NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
```

### `$switchLocaleRoute` {#$switchlocaleroute}

```ts
(locale: string) => RouteLocationRaw
```

Obiekt trasy dla bieżącej strony w innym locale, bez nawigacji, lub ciąg URL
dla locale z własnym `baseUrl`. Przy `trailingSlash` obiekt ma `path` i `fullPath`
zgodne z regułą, z `query` i `hash` bez zmian, a `router.push` lub link je zachowują.

### `$switchRoute` {#$switchroute}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => Promise<void>
```

Przechodzi do innej trasy, zachowując aktywne locale lub przełączając na `toLocale`. Asynchroniczne, tak jak
`$switchLocale`.

```ts
$switchRoute('/about') // active locale
$switchRoute({ name: 'about' }, 'de') // switch to de
```

### `$localePath` {#$localepath}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => string
```

Rozwiązuje ścieżkę w podanym locale lub w aktywnym. Ciąg ze schematem `http(s):`, `mailto:`
lub `tel:` jest zwracany bez zmian: nie przekazuj danych od użytkownika jako celu linku bez sprawdzenia.

Ścieżka w postaci ciągu jest odczytywana jako strona, którą pokazuje, więc stosowana jest także niestandardowa ścieżka locale.

```ts
$localePath('/about') // '/about' in en, '/de/ueber-uns' in de with localeRoutes
$localePath({ name: 'about' }, 'fr') // '/fr/about'
```

### `$localeRoute` {#$localeroute}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => RouteLocationResolved
```

Rozwiązuje trasę w podanym locale lub w aktywnym. Zwykły obiekt, który można bezpiecznie przechowywać w stanie. Gdy parametr wymaga
escapowania, obiekt ma `path`, `fullPath`, `query` i `hash`, ale nie ma `name` ani `params`: to ścieżka przekazuje routerowi
zakodowany adres URL. Dla locale w innej domenie `path` i `fullPath` są bezwzględne, czego router nie przyjmie:
taki link przechodzi przez `<i18n-link>` lub `$localePath`.

### `$getRouteName` {#$getroutename}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric, locale?: string) => string
```

Nazwa trasy z usuniętym prefiksem locale — nazwa, według której indeksowane są tłumaczenia.

```ts
$getRouteName() // 'about' on /de/about
```

## Konfiguracja strony {#page-config}

### `$defineI18nRoute` {#$definei18nroute}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

Rejestruje konfigurację locale i tłumaczenia dla strony z wnętrza komponentu.
Scala je z aktywnym locale i stosuje ponownie, gdy locale się zmieni.

Wywołuj go w `<script setup>` strony, zawsze destrukturyzując z `useNuxtApp()`. Build odczytuje z wywołania `locales`, `localeRoutes` i `disableMeta`; w czasie działania liczy się tylko `locales` (tłumaczenia inline są scalane dla aktywnego locale). Pełne reguły: [Konfiguracja strony](/pl/guide/per-component-translations).

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: { en: '/about', de: '/ueber-uns' },
})
</script>
```

### `$setI18nRouteParams` {#$seti18nrouteparams}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

Ustawia parametry dla poszczególnych locale dla bieżącej trasy, aby segment dynamiczny mógł się różnić w zależności od języka.
Wywołuj go podczas SSR, zanim zostanie wyrenderowany head.

Parametry są czyszczone, gdy zostanie zatwierdzona nawigacja do innej ścieżki, w tym z `/news/1` do `/news/4`, która zachowuje nazwę trasy. Szczegóły: [Zlokalizowane ścieżki](/pl/guide/custom-locale-routes).

```ts
$setI18nRouteParams({
  en: { slug: 'my-post' },
  de: { slug: 'mein-beitrag' },
})
```

## Tłumaczenia w czasie działania {#runtime-translations}

### `$mergeTranslations` {#$mergetranslations}

```ts
(newTranslations: Translations) => void
```

Scala tłumaczenia z aktywnym locale w czasie działania, nadpisując to, co zostało wczytane.

Scala głęboko z bieżącym chunkiem strony aktywnego locale; klucze, o których nie wspomina, pozostają.

```ts
$mergeTranslations({ banner: { title: 'Sale' } })
```

### `$setTranslation` {#$settranslation}

```ts
(key: string, value: unknown) => void
```

Zastępuje wartość pod `key` w aktywnym słowniku. To zastąpienie, a nie scalenie —
użyj `$mergeTranslations`, gdy istniejące klucze sąsiednie mają pozostać.

```ts
$setTranslation('banner', { title: 'Sale' }) // drops other keys under banner
$setTranslation('banner.title', 'Sale') // dotted path
```

### `$loadPageTranslations` {#$loadpagetranslations}

```ts
(locale: string, routeName: string, translations: Translations) => Promise<void>
```

Wczytuje tłumaczenia dla strony w czasie działania, dla treści, których klucze nie są znane w czasie budowania.

Scala je z chunkiem `(locale, routeName)` w pamięci, a ekran aktualizuje się, gdy ten chunk jest aktywny. Żaden payload nie jest tu pobierany: dla strony jeszcze niewczytanej tłumaczenia czekają, a gdy jej plik się wczyta, pozostają nad nim.

```ts
await $loadPageTranslations('en', 'about', { title: 'About us' })
```

### `$resolveTranslations` {#$resolvetranslations}

```ts
() => Translations
```

Każde tłumaczenie aktualnie w pamięci dla aktywnego locale i trasy, w postaci drzewa.
Widok tylko do odczytu tego, co `$t()` może teraz rozwiązać.

Traktuj wynik jako tylko do odczytu.

### `$setMissingHandler` {#$setmissinghandler}

```ts
(handler: MissingHandler | null) => void
```

Instaluje callback wywoływany dla każdego nierozwiązanego klucza. Przekaż `null`, aby go usunąć.

Handler działa zamiast ostrzeżenia w trybie deweloperskim.

```ts
$setMissingHandler((locale, key, routeName) => {
  console.error(`[i18n] missing ${key} in ${locale} (${routeName})`)
})
```

### `$clearCache` {#$clearcache}

```ts
() => void
```

Usuwa każdy zbuforowany chunk tłumaczeń i ponownie wczytuje słownik bieżącej strony. Strona
nadal pokazuje bieżące tłumaczenia, dopóki nie dotrą nowe. HMR w trybie deweloperskim wywołuje go
przy każdej zmianie pliku tłumaczeń.

```ts
const { clearCache } = useI18n()
clearCache()
```
