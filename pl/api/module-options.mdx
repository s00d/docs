# Dokumentacja opcji modułu

Każda opcja, którą akceptuje `nuxt-i18n-micro`, odczytana w czasie budowy z interfejsu `ModuleOptions` w
[`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).
Nic tutaj nie jest pisane ręcznie, więc nie może odbiec od kodu — typy, wartości domyślne i opisy pochodzą z samej deklaracji.

Aby dowiedzieć się, co te opcje *znaczą* razem — które kombinacje mają sens, co zmienia się przy przełączeniu strategii, przykłady w akcji — przeczytaj [Konfigurację](/guides/configuration). Ta strona jest wyczerpującą listą; tamta jest wyjaśnieniem.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Opcje zagnieżdżone pojawiają się pod swoją ścieżką z kropką, więc `translationPayloads.mode` to klucz `mode` wewnątrz obiektu `translationPayloads`.

## Lokalizacje i routing

Jakie języki istnieją i jak pojawiają się w adresie URL.

| Opcja | Typ | Domyślnie | Opis |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Lista obsługiwanych lokalizacji. Każdy wpis definiuje kod lokalizacji plus opcjonalne metadane (ISO, kierunek, nazwa wyświetlana itp.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Strategia routingu URL dla prefiksów lokalizacji. - `'no_prefix'` — brak lokalizacji w URL; lokalizacja przechowywana w ciasteczku. - `'prefix_except_default'` — prefiksuj wszystkie lokalizacje z wyjątkiem domyślnej. - `'prefix'` — zawsze prefiksuj, w tym domyślną lokalizację. - `'prefix_and_default'` — jak `prefix`, ale domyślna lokalizacja jest też dostępna bez prefiksu. |
| `defaultLocale` | `string` | `'en'` | Lokalizacja używana, gdy nie można jej ustalić z URL ani preferencji użytkownika. Używana też jako fallback dla brakujących tłumaczeń, gdy `fallbackLocale` nie jest ustawione. |
| `localeCookie` | `string \| null` | `null` | Nazwa ciasteczka do przechowywania preferencji lokalizacji użytkownika między sesjami. Ustaw na `null`, aby wyłączyć trwałość opartą na ciasteczkach. Automatycznie ustawiane na `'user-locale'` dla strategii `no_prefix`, jeśli nie podano. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Globalna konfiguracja lokalizacji na poziomie trasy. Pozwala ograniczyć lub dostosować trasy lokalizacji dla konkretnych stron bez modyfikowania ich komponentów. - `false` — wyklucz trasę z lokalizacji. - `Record<LocaleCode, string>` — niestandardowe ścieżki per lokalizacja. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Niestandardowe wyrażenie regularne (lub jego postać string) do dopasowywania kodów lokalizacji w segmentach URL. Wszystkie kody lokalizacji zdefiniowane w `locales` muszą pasować do tego wzorca, w przeciwnym razie emitowane jest ostrzeżenie. |
| `noPrefixRedirect` | `boolean` | `false` | Dla strategii `no_prefix`: włącz przekierowanie z URL-a z prefiksem lokalizacji (np. `/en/about`) do wersji bez prefiksu (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Wzorce URL (stringi lub RegExp) do całkowitego wykluczenia z przetwarzania i18n. Pasujące trasy nie dostaną prefiksów lokalizacji, przekierowań ani ładowania tłumaczeń. Wewnętrzne ścieżki Nuxt (`/__nuxt_error` itd.) są zawsze wykluczane automatycznie. |
| `routeLocales` | `Record<string, string[]>` | — | Ograniczenia lokalizacji per trasa, wyekstraktowane z wywołań `defineI18nRoute()`. Mapuje ścieżkę trasy (np. `'/about'`) na tablicę dozwolonych kodów lokalizacji. Trasy niewymienione nie mają ograniczeń (dozwolone wszystkie lokalizacje). |

## Tłumaczenia

Gdzie znajdują się pliki tłumaczeń i jak rozwiązywane są klucze.

| Opcja | Typ | Domyślnie | Opis |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Ścieżka do katalogu z plikami JSON tłumaczeń, względem katalogu głównego projektu. |
| `disableWatcher` | `boolean` | `false` | Wyłącz obserwatora plików, który auto-tworzy brakujące pliki tłumaczeń w trybie deweloperskim. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Mapuje nazwy tras na inne nazwy tras w celu współdzielenia tych samych plików tłumaczeń. Na przykład `\{ 'about-us': 'about' \}` oznacza, że strona `about-us` będzie używać tłumaczeń ze strony `about` zamiast własnych. |
| `plural` | `PluralFunc` | `built-in pluralization (form index by count)` | Niestandardowa funkcja pluralizacji. Otrzymuje `(key, count, params, locale, getter)` i powinna zwrócić wybraną formę liczby mnogiej jako string, lub `null`/`undefined`, aby wrócić do wbudowanej logiki `defaultPlural` (można więc nadpisać tylko wybrane lokalizacje). W module Nuxt funkcja jest serializowana przez `.toString()` do `.nuxt/i18n.plural.mjs` — musi być samowystarczalna (bez importów / zewnętrznego zakresu). Ścieżka pliku jako string **nie** jest obsługiwana. |
| `disablePageLocales` | `boolean` | `false` | Wyłącz pliki tłumaczeń per strona. Gdy `true`, ładowane są tylko globalne tłumaczenia (`\{locale\}.json`); pliki specyficzne dla strony (`pages/\{page\}/\{locale\}.json`) nie są generowane ani ładowane. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Globalny kod lokalizacji zapasowej. Gdy klucz tłumaczenia brakuje w aktywnej lokalizacji, moduł szuka go w tej lokalizacji, zanim zwróci sam klucz. |

## Payloady i cache

Jak tłumaczenia trafiają do przeglądarki. [Wydajność](/guides/performance) wyjaśnia, co te opcje zmieniają w runtime.

| Opcja | Typ | Domyślnie | Opis |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Preładuj tłumaczenia strony index w globalnym middleware Nitro (tylko serwer, prywatna konfiguracja). |
| `apiBaseUrl` | `string` | `'_locales'` | Bazowy segment ścieżki URL dla trasy API tłumaczeń (używany w pobieraniu danych SSR/SSG). Można też ustawić przez zmienną środowiskową `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Nadpisz host używany dla żądań pobierania tłumaczeń po stronie klienta. Przydatne, gdy klient dociera do serwera przez inną nazwę hosta niż widzi Nuxt. Można też ustawić przez zmienną `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Nadpisz host używany dla żądań pobierania tłumaczeń po stronie serwera. Przydatne w konfiguracjach kontenerowych/mikroserwisowych, gdzie serwer dociera do siebie przez wewnętrzną nazwę hosta. Można też ustawić przez zmienną `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Kontroluje sposób emisji payloadów tłumaczeń (Node: `public/<apiBaseUrl>`; Edge: `serverAssets` Nitro). - **Node**: `serverAssets` oznacza lokalne SSR przez `readFile` w `public/` (bez Rollup `raw:`). - **Edge**: `serverAssets` rejestruje `serverAssets` Nitro (`assets:i18n`); nie wymusza kopii publicznej. Zachowaj wartości domyślne dla typowej konfiguracji all-in-one. Dla dużych katalogów Edge preferuj `mode: 'source'`. Dla wdrożeń wspieranych przez CDN wyłącz lokalne wyjścia i ustaw `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Strategia payloadu tłumaczeń. - `premerged`: matryca `\{page\}/\{locale\}/data.json` generowana w czasie budowy (domyślne) - `source`: kompaktowe pliki źródłowe scalane w runtime (preferowane na Edge / dużych katalogach) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Lokalne payloady SSR: Node odczytuje `public/<apiBaseUrl>` (wymusza kopię publiczną); Edge osadza przez `serverAssets` Nitro. - **Node**: brak `serverAssets` Nitro (unika Rollup `raw:`). SSR odczytuje `public/<apiBaseUrl\|publicDir>` jako `\{page\}/\{locale\}/data.json`; gdy jest `true`, wymuszana jest kopia publiczna nawet jeśli `publicAssets` jest false. - **Edge** (`nitro.node === false`): `serverAssets` Nitro (`assets:i18n`) z tym samym układem co `mode`. **Nie** wymusza kopii publicznej — ustaw `publicAssets: true` dla CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Zarejestruj wbudowaną trasę serwera pod `/\{apiBaseUrl\}/:page/:locale/data.json`. Wyłącz to, gdy payloady tłumaczeń są serwowane z zewnętrznego hosta/CDN. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Kopiuj payloady do publicznego wyjścia Nitro. Premerged → `\{page\}/\{locale\}/data.json` pod `apiBaseUrl`; source → kompaktowe drzewo. Na Node to drzewo jest też źródłem SSR, gdy `serverAssets` wymusza kopię publiczną. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Włącz Nitro-prerender `/\{apiBaseUrl\}/.../data.json`. Zwykle zbędne, gdy premerged `publicAssets` już zapisał te pliki. |
| `translationPayloads.publicDir` | `string` | — | Folder wyjścia publicznego względem publicznego korzenia Nitro. Domyślnie `apiBaseUrl` (`_locales`). Dzięki temu pliki statyczne pasują do URL-i pobierania klienta (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Ostrzegaj podczas budowy, gdy liczba wygenerowanych plików payloadów przekracza ten próg. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Ostrzegaj podczas budowy, gdy łączny rozmiar wygenerowanych payloadów przekracza ten próg w bajtach. |

## SEO

Tagi meta generowane dla każdej zlokalizowanej strony.

| Opcja | Typ | Domyślnie | Opis |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Automatycznie generuj tagi meta SEO (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | Bazowy URL dla tagów meta SEO (canonical, og:url, hreflang). - Konkretny URL (np. `'https://example.com'`) — używany bez zmian (najwyższy priorytet). - `undefined` — wraca do `site.url` z `nuxt-site-config`, gdy ten moduł jest obecny, w przeciwnym razie do originu bieżącego żądania (`useRequestURL().origin` na serwerze, `window.location.origin` na kliencie). |
| `metaTrustForwardedHost` | `boolean` | `true` | Ufaj nagłówkowi `X-Forwarded-Host` przy rozwiązywaniu bazowego URL-a dla tagów meta. Włącz, gdy aplikacja działa za reverse proxy (nginx, Cloudflare, AWS ALB itp.), które ustawia ten nagłówek na prawdziwą nazwę hosta kliencką. |
| `metaTrustForwardedProto` | `boolean` | `true` | Ufaj nagłówkowi `X-Forwarded-Proto` przy rozwiązywaniu protokołu dla tagów meta. Włącz, gdy aplikacja działa za proxy terminującym TLS, aby URL-e kanoniczne używały `https://` mimo że sama aplikacja nasłuchuje HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Lista nazw parametrów query zachowywanych w tagach meta canonical i `og:url`. Parametry spoza listy są usuwane z kanonicznego URL-a. |

## Wykrywanie i przekierowania

Wybieranie lokalizacji dla odwiedzającego, który jej nie wybrał.

| Opcja | Typ | Domyślnie | Opis |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Włącz automatyczne przekierowania oparte na lokalizacji. Gdy `true`, odwiedzający są przekierowywani do preferowanej lokalizacji (wykrytej z ciasteczka, nagłówka `Accept-Language` lub domyślnej) przy pierwszej wizycie. |
| `autoDetectLanguage` | `boolean` | `true` | Automatycznie wykryj preferowany język użytkownika z nagłówka HTTP `Accept-Language`. Używane w połączeniu z `autoDetectPath`, aby zdecydować, kiedy zachodzi wykrywanie. |
| `autoDetectPath` | `string` | `'/'` | Gdzie mogą działać przekierowania na podstawie ciasteczka / Accept-Language (gdy `redirects` jest włączone). - `'/'` — tylko `/` (linki głębokie w domyślnej lokalizacji pozostają dostępne; domyślne) - `'no_prefix'` — tylko ścieżki bez prefiksu lokalizacji - `'*'` — każda ścieżka, w tym przepisywanie jawnego prefiksu lokalizacji (np. `/fr/about` → `/de/about`, gdy ciasteczko preferuje `de`) - dowolny inny ciąg — dokładne dopasowanie ścieżki (np. `'/welcome'`) Czyszczenie strategii z prefiksem (np. `/en` → `/` przy `prefix_except_default`) nie jest ograniczane. |

## Rejestracja

Części modułu, które można wyłączyć.

| Opcja | Typ | Domyślnie | Opis |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Zarejestruj plugin makra `defineI18nRoute()`, umożliwiając wywołania `defineI18nRoute()` per strona. |
| `plugin` | `boolean` | `true` | Zarejestruj główny plugin i18n dostarczający `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` i inne helpery runtime. |
| `hooks` | `boolean` | `true` | Zarejestruj plugin hooków i18n dostarczający hooki na poziomie aplikacji: `i18n:register` i `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`. |
| `components` | `boolean` | `true` | Zarejestruj wbudowane komponenty i18n (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Ustaw na `false`, aby wyłączyć automatyczną rejestrację komponentów (np. jeśli ich nie używasz i chcesz zmniejszyć rozmiar modułu). |
| `types` | `boolean` | `true` | Generuj deklaracje typów TypeScript dla `useI18n`, `$t` i powiązanych helperów na podstawie kluczy tłumaczeń w domyślnych plikach lokalizacji. |
| `debug` | `boolean` | `false` | Włącz szczegółowe logowanie debug dla wykrywania lokalizacji, generowania tras i ładowania tłumaczeń. |

## Inne

| Opcja | Typ | Domyślnie | Opis |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | Emituj też goły `hreflang` językowy wyprowadzony z `iso` każdej lokalizacji (np. `es-ES` → także `es`). Pierwsza regionalna lokalizacja w `locales` przejmuje goły tag dla tego języka. Kod routingu `code` nigdy nie jest używany — tylko `iso \|\| code`. |
| `vueDevtools` | `boolean` | `true` | Zarejestruj inspektor i oś czasu Vue DevTools w trybie dev (rozszerzenie przeglądarki). Osobne od niestandardowej karty Nuxt DevTools. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Prefiks dodawany do nazw zlokalizowanych tras (np. `'localized-index'`). Używany wewnętrznie do odróżnienia oryginalnych tras od generowanych wariantów lokalizacji. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Wyłączanie tagów meta per trasa, wyekstraktowane z wywołań `defineI18nRoute()`. Mapuje ścieżkę trasy na `true` (wyłącz wszystkie meta) lub tablicę kodów lokalizacji, dla których meta ma być wyłączone. |
| `missingWarn` | `boolean` | `true` | Pokazuj ostrzeżenia w konsoli, gdy brakuje klucza tłumaczenia. |
| `hmr` | `boolean` | `true` | Włącz Hot Module Replacement dla plików tłumaczeń w trybie deweloperskim. Gdy `true`, zmiany w plikach JSON tłumaczeń wyzwalają automatyczne przeładowanie bez pełnego odświeżenia strony. |
| `cacheMaxSize` | `number` | `0` | Maksymalna liczba wpisów w cache tłumaczeń w pamięci. `0` oznacza brak limitu. |
| `cacheTtl` | `number` | `0` | Czas życia (w sekundach) wpisów cache tłumaczeń. `0` oznacza, że wpisy nigdy nie wygasają. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Nazwane formaty liczb per lokalizacja (kompatybilne z Vue I18n). Umożliwia wywołania typu `$tn(1000, 'currency')`. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Nazwane formaty daty i czasu per lokalizacja (kompatybilne z `datetimeFormats` Vue I18n). Umożliwia wywołania typu `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | HTTP `Cache-Control` max-age (sekundy) dla `/\{apiBaseUrl\}/:page/:locale/data.json`. Stosuje się w pełni tylko wtedy, gdy `dateBuild` unieważnia URL (`?v=...`), co jest ustawieniem domyślnym: odpowiedź jest wtedy `public, max-age=…, immutable` i bezpieczna dla przeglądarek i CDN-ów. - `dateBuild: 0`/`''` — URL jest stabilny, więc ta wartość nie jest respektowana; odpowiedź staje się `public, max-age=0, must-revalidate`. Długie `max-age` na niezmiennym URL-u przypina pierwszy payload, jaki widziała przeglądarka. - `0` — w ogóle nie ustawiaj `Cache-Control` (przydatne w lokalnym debugu) - Nie stosowane w trybie deweloperskim (`import.meta.dev`), aby cache przeglądarki nie walczył z HMR - Dociera tylko do odpowiedzi serwowanych przez Nitro. Payloady kopiowane do `public/` i serwowane przez platformę hostingową dostają nagłówki tej platformy — zobacz Przewodnik po wydajności. Analogiczne do eksperymentalnego `httpCacheDuration` w `@nuxtjs/i18n` (v10.2.0), ale jako jawny nagłówek odpowiedzi, a nie `maxAge` w Nitro `defineCachedEventHandler`. |
| `dateBuild` | `string \| number` | — | Wartość używana do unieważniania cache żądań tłumaczeń (`?v=...`). Gdy nie podano, moduł wraca do `Date.now()` (niedeterministyczne). Dla powtarzalnych/rolling deployments ustaw stabilną wartość (np. git SHA lub numer builda). |
| `experimental` | `Record<string, unknown>` | — | Kubełek na eksperymentalne/niestabilne opcje. Zawartość może się zmienić lub zostać usunięta bez powiadomienia między wersjami minor. |
