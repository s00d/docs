title: "Konfiguracja strony"
description: "Ogranicz stronę do wybranych locale, nadaj jej własne ścieżki, tłumaczenia inline lub wyłącz tagi SEO za pomocą $defineI18nRoute."
---

`$defineI18nRoute` ustawia opcje i18n dla jednej strony z wnętrza samej strony. Używaj go, gdy strona istnieje tylko w niektórych locale, potrzebuje własnej zlokalizowanej ścieżki, zawiera kilka własnych tłumaczeń lub nie może dostać tagów hreflang/canonical. Moduł odczytuje to wywołanie w czasie budowania i wbudowuje je w generowane trasy.

## Ograniczanie strony do wybranych locale {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

W domyślnej strategii `prefix_except_default` generowane są tylko `/product` i `/de/product`; strona nie ma trasy w żadnym innym locale. To samo można ustawić w `nuxt.config.ts` za pomocą [`routeLocales`](/pl/api/module-options#routelocales).

`$defineI18nRoute` to wstrzyknięcie aplikacji Nuxt, a nie makro kompilatora: zawsze pobieraj je z `useNuxtApp()` i wywołuj ze znakiem `$`. Krok budowania rozpoznaje tylko `$defineI18nRoute(`.

## Dodawanie tłumaczeń inline {#add-inline-translations}

Przekaż obiekt zamiast tablicy. Jego klucze to dozwolone locale, a wartości są scalane ze słownikiem strony dla aktywnego locale.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Tłumaczenia inline trafiają do komponentu strony dla każdego locale. Do wszystkiego, co jest większe niż kilka kluczy, wybieraj [pliki tłumaczeń stron](/pl/guide/translations); klucze inline zostaw dla samodzielnych stron i komponentów.

## Ustawianie zlokalizowanych ścieżek {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

Przy `prefix_except_default` i `defaultLocale: 'en'` daje to `/welcome` i `/de/willkommen`. To samo robi `path` w obiekcie locale inline: `locales: { de: { path: '/willkommen' } }`. Parametry dynamiczne, trasy zagnieżdżone i alternatywa na poziomie konfiguracji są opisane w [Zlokalizowanych ścieżkach](/pl/guide/custom-locale-routes).

## Wyłączanie tagów SEO {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

Alternatywą na poziomie konfiguracji jest [`routeDisableMeta`](/pl/api/module-options#routedisablemeta). Czym są te tagi, wyjaśnia strona [SEO](/pl/guide/seo).

## Co krok budowania potrafi odczytać {#what-the-build-can-read}

Krok budowania znajduje wywołanie w każdym pliku strony i oblicza jego argument bez uruchamiania aplikacji. Działa to, gdy konfiguracja jest:

- literałem obiektu (ciągi znaków, tablice, zagnieżdżone obiekty, literały szablonowe, operatory warunkowe na `process.env.NODE_ENV`);
- zbudowana ze stałych zadeklarowanych w tym samym `<script setup>` (`const locales = ['en', 'de']`, łącznie ze spreadami);
- tablicą obiektów z polem `code` (`[{ code: 'en' }, { code: 'de' }]`).

Nie potrafi odczytać wartości importowanych z innego modułu ani niczego, co wymaga działającej aplikacji (composables, `await`, pobrane dane). W takim przypadku build loguje `Ignored the $defineI18nRoute() config in <file>`, a strona zachowuje domyślne locale i trasy.

W czasie działania wywołanie jedynie scala tłumaczenia inline dla bieżącego locale i ponownie je scala, gdy locale się zmienia. `locales`, `localeRoutes` i `disableMeta` działają wyłącznie przez build, więc ich zmiana wymaga przebudowania (serwer deweloperski przebudowuje przy zapisie).
