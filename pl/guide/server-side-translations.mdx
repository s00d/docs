Handlery serwerowe w `server/api/` i `server/routes/` mogą tłumaczyć teksty i odczytywać lokalizację żądania za pomocą dwóch automatycznie importowanych pomocników. Używaj ich w odpowiedziach API, e-mailach, feedach lub wszystkim, co jest renderowane poza stroną Vue. Odczytują te same pliki tłumaczeń co Twoje strony i wykrywają lokalizację na podstawie żądania.

## Tłumaczenie w handlerze {#translate-in-a-handler}

```ts
// server/api/greeting.get.ts
export default defineEventHandler(async (event) => {
  const t = await useTranslationServerMiddleware(event)
  return { message: t('greeting', { name: 'Ada' }) }
})
```

```bash
curl 'http://localhost:3000/api/greeting?locale=de'
# {"message":"Hallo, Ada!"}
```

`useTranslationServerMiddleware(event, defaultLocale?, locale?)` jest asynchroniczny i zwraca `t(key, params?, defaultValue?)`. `t` zwraca tekst, interpoluje parametry `{name}`, a gdy klucza brakuje, zwraca niepusty `defaultValue`, w przeciwnym razie sam klucz.

`t` widzi tylko chunk `index`: pliki główne (`locales/<locale>.json`) oraz `locales/pages/index/`, jeśli istnieje (przy `disablePageLocales` tylko pliki główne). Klucze innych stron nie są ładowane. Dla nich załaduj chunk samodzielnie:

```ts
const { data } = await loadTranslationsFromServer('de', 'about') // Translations object of the about page
```

## Odczytywanie lokalizacji żądania {#read-the-request-locale}

```ts
// server/api/locale.get.ts
export default defineEventHandler((event) => {
  const { current, isDefault, locale } = useLocaleServerMiddleware(event)
  return { current, isDefault, dir: locale?.dir ?? 'ltr' }
})
```

`useLocaleServerMiddleware(event, defaultLocale?, locale?)` jest synchroniczny i zwraca:

```ts
interface LocaleInfo {
  current: string // detected locale code
  default: string // defaultLocale, runtime overrides included (fixed at build under prefix_except_default / prefix_and_default)
  fallback: string // fallbackLocale, else the default
  available: string[] // enabled locale codes
  locale: Locale | null // the config entry of `current`
  isDefault: boolean
  isFallback: boolean
}
```

## Jak wybierana jest lokalizacja {#how-the-locale-is-chosen}

Oba pomocniki stosują tę samą kolejność na każdej trasie serwerowej, niezależnie od tego, czy jest to `/api`:

1. query `?locale=` (pierwsza wartość, gdy się powtarza);
2. parametr trasy `[locale]` lub prefiks lokalizacji w ścieżce (`/de/...`);
3. ciasteczko lokalizacji, gdy ustawiono [`localeCookie`](/pl/api/module-options#localecookie) (`hash-locale` w trybie `hashMode`);
4. `Accept-Language`, gdy włączone jest `autoDetectLanguage` (z uwzględnieniem wartości q);
5. `defaultLocale`.

Nieprawidłowe i wyłączone kody są pomijane na każdym etapie. To kolejność dla API; renderowanie strony ignoruje `?locale=` w strategiach z prefiksem. Obie kolejności porównano na stronie [Wykrywanie lokalizacji](/pl/guide/locale-detection).

## Wymuszanie lokalizacji {#force-a-locale}

Przekaż trzeci argument, aby pominąć wykrywanie, na przykład w zadaniu wysyłającym e-mail w języku użytkownika:

```ts
export default defineEventHandler(async (event) => {
  const user = await getUser(event) // your code
  const t = await useTranslationServerMiddleware(event, undefined, user.locale)
  return sendMail(user.email, t('mail.welcome.subject'))
})
```

Drugi argument zastępuje `defaultLocale` przy wykrywaniu w tym wywołaniu, więc nie ma żadnego efektu, gdy lokalizacja jest wymuszona. Słowniki są buforowane na żądanie i na lokalizację, a pomiędzy żądaniami w pamięci podręcznej tłumaczeń serwera, więc wielokrotne wywołanie pomocnika jest tanie.

## Komponenty serwerowe {#server-components}

Komponent serwerowy (`.server.vue`, `<NuxtIsland>`) renderuje się z własnego URL-a, `/__nuxt_island/...`, więc nie widzi URL-a strony, a Nuxt przekazuje mu tylko jego propsy. Przekaż lokalizację jako prop `locale`. Komponent renderuje się wtedy w tej lokalizacji, a zmiana lokalizacji pobiera go ponownie, ponieważ propsy są częścią URL-a i klucza cache wyspy. Nazwa jest zarezerwowana: dowolny kod włączonej lokalizacji w propie o nazwie `locale` ustawia lokalizację renderowania, więc propowi oznaczającemu coś innego, np. format liczb, nadaj inną nazwę:

```vue
<!-- components/Greeting.server.vue -->
<template><p>{{ $t('greeting') }}</p></template>
<script setup lang="ts">
defineProps<{ locale?: string }>()
</script>
```

```vue
<template>
  <Greeting :locale="$getLocale()" />
  <NuxtIsland name="Greeting" :props="{ locale: $getLocale() }" />
</template>
```

Bez tego propa komponent renderuje się w lokalizacji z ciasteczka, a w przeciwnym razie w domyślnej lokalizacji, niezależnie od URL-a, i nie reaguje na zmianę lokalizacji. Jego `$t` widzi chunk `index`: pliki główne oraz `locales/pages/index/`.
