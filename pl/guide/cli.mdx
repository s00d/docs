`@i18n-micro/cli` zarządza plikami lokalizacji projektu Nuxt. Odczytuje `locales`, `defaultLocale`, `translationDir` i Twoje warstwy z `nuxt.config`, więc nie wymaga własnej konfiguracji.

![A terminal running i18n-micro check, which lists a missing, an undefined and four unused keys and fails, then extract, which adds the undefined key, then clean --dryRun, which lists the four keys it would remove](/images/cli/demo.gif)

| Polecenie | Służy do |
| --- | --- |
| `check` | Przerwania builda przy jakimkolwiek problemie z plikami lokalizacji |
| `translate` | Uzupełniania brakujących kluczy przez usługę tłumaczeniową |
| `clean` | Usuwania kluczy, których nic nie używa |
| `rename` | Przenoszenia klucza lub całej przestrzeni nazw wszędzie jednocześnie |

```bash
npm install -D @i18n-micro/cli
npx i18n-micro --help
```

Uruchamiaj go z katalogu głównego aplikacji lub wskaż go za pomocą `--cwd`. Każda flaga każdego polecenia znajduje się w [dokumentacji poleceń](/pl/api/cli).

<Tip>

**Przechodzisz z nuxt-i18n-micro-cli?** `@i18n-micro/cli` go zastępuje; pliki wykonywalne `i18n-micro` i `i18n-micro-cli` pozostają. Zobacz [tabelę starych poleceń](#moving-from-nuxt-i18n-micro-cli).

</Tip>

## Użycie w CI {#use-it-in-ci}

```bash
i18n-micro check
```

`check` pełni rolę bramki. Zgłasza:

| Sprawdzenie | Oznacza |
| --- | --- |
| `missing` | Klucza domyślnej lokalizacji brakuje w innej lokalizacji |
| `empty` | Wartość to `''`. Aplikacja pokazuje puste miejsce, a nie wartość zapasową |
| `extra` | Lokalizacja ma klucz, którego nie ma domyślna lokalizacja |
| `placeholders` | `{name}` został utracony lub dodany albo forma liczby mnogiej utraciła swoje formy |
| `undefined` | Kod używa klucza, którego nie ma domyślna lokalizacja |
| `unused` | Nic w projekcie nie używa klucza |
| `duplicates` | Ten sam tekst pod różnymi kluczami. Domyślnie wyłączone: przekaż `--duplicates` |

- `--only missing,placeholders` uruchamia wybrane sprawdzenia; sprawdzenie wymienione w `--only`, którego nie udało się uruchomić, kończy się niepowodzeniem.
- `--json` generuje raport dla narzędzi.
- `--ignore` pomija pliki źródłowe.
- Gdy klucze są obliczane w czasie działania, `unused` jest pomijane, a raport podaje przyczynę.

Każde polecenie kończy się jednym z trzech kodów, dzięki czemu pipeline może odróżnić problem z tłumaczeniami od problemu z narzędziem:

| Kod wyjścia | Znaczenie |
| --- | --- |
| `0` | Nic do zgłoszenia |
| `1` | Znaleziono problemy |
| `2` | Polecenie nie mogło zostać wykonane: błąd użycia, uszkodzony plik, nieudane żądanie |

Inne polecenia warte kroku w CI:

```bash
i18n-micro format --check      # fails if a file is not formatted
i18n-micro lint                # stray spaces, empty values, your own regex rules
i18n-micro stats --baseRef main
```

## Utrzymywanie spójności lokalizacji {#keep-locales-in-step}

| Polecenie | Co robi |
| --- | --- |
| `extract` | Wyświetla klucze używane w kodzie, które nie mają jeszcze tekstu. Tekst domyślny, jak w `$t('key', {}, 'Welcome')`, trafia do domyślnej lokalizacji. |
| `sync` | Usuwa klucze, których nie ma domyślna lokalizacja. Najpierw spróbuj z `--dryRun`. |
| `clean` | Usuwa klucze, których nic nie używa. Najpierw spróbuj z `--dryRun`. |
| `search` | Wyszukuje klucze i wartości oraz pokazuje, gdzie każdy klucz jest używany. |
| `stats` | Stopień ukończenia dla każdej lokalizacji; `--baseRef main` porównuje z referencją git. |

`sync` zatrzymuje się tak jak `clean`, gdy miałby usunąć klucz, którego nieużywania nie potrafi udowodnić, a także gdy domyślna lokalizacja nie ma nic do porównania. Gdy nie ma nic do usunięcia, nigdy się nie zatrzymuje, więc samo `$t(item.label)` nie jest powodem do użycia `--force`.

<Note>

`extract` i `sync` nigdy nie zapisują `''` dla klucza bez tłumaczenia. Klucz pozostaje nieobecny, więc w czasie działania stosowane jest `fallbackLocale`, a `check` go zgłasza. Pusty ciąg byłby zdefiniowaną wartością i wyświetliłby puste miejsce.

</Note>

### Co odczytują polecenia {#what-the-commands-read}

`check`, `extract`, `sync`, `clean`, `search` i `rename` odczytują kod źródłowy z całego projektu, a nie ze stałej listy folderów:

- **Odczytywane:** szablony i skrypty przez parser, `.html` i Pug jako tekst, każda warstwa oraz foldery poza katalogiem głównym, na które wskazuje alias lub `components`.
- **Pomijane:** `node_modules`, wynik budowania i pliki lokalizacji. Dodaj własne za pomocą `--ignore 'legacy/**,*.stories.ts'`.
- **Kod testowy** liczy się jako użycie, więc `clean` i `check --only unused` zachowują klucz odczytywany tylko przez test. Nigdy nie dodaje klucza: `extract` pomija takie klucze, a `check` nie zgłasza ich jako niezdefiniowanych.

Kod testowy oznacza foldery główne `tests`, `test`, `__tests__`, `e2e`, `cypress` i `playwright`, a także pliki JavaScript i TypeScript `.spec` i `.test` (`.ts`, `.tsx`, `.mts`, `.js`, `.jsx`, `.mjs` itp.) w dowolnym miejscu. Tylko foldery główne są zwolnione z opisanych niżej wątpliwości: `pages/tests/[id].vue` to strona jak każda inna, podobnie jak `public/` i pliki zminifikowane, których kod nie jest częścią aplikacji.

Polecenia rozpoznają:

- `$t`, `$ts`, `$tc`, `$has` i `$_t(route)`;
- `t()` z `useI18n()` i `useTranslationServerMiddleware()`;
- `<i18n-t keypath>` w szablonach i JSX oraz `<i18n-group prefix>`;
- aliasy takie jak `const { t: tr } = useI18n()`.

### Jak decyduje `clean` {#how-clean-decides}

`clean` woli zostawić martwy klucz niż usunąć żywy. Klucz pozostaje, gdy spełniony jest którykolwiek z warunków:

- używa go wywołanie, albo klucza poniżej lub powyżej niego;
- ciąg w kodzie jest mu równy: `const key = 'menu.home'`, `<Item label="menu.home" />`;
- zawiera go plik JSON, YAML lub Markdown w projekcie;
- obliczany klucz ma statyczny początek, który go obejmuje: `` $t(`status.${state}`) `` zachowuje wszystko pod `status.`;
- definiuje go warstwa.

`clean` zatrzymuje się bez wprowadzania zmian, gdy nie może tego wiedzieć, i podaje przyczynę:

- klucz jest w pełni obliczany, jak w `$t(name)`, `<i18n-t :keypath="name" />` lub `<i18n-t v-bind="props" />`;
- `$t` jest przekazywane jako wartość, jak w `items.map($t)`;
- funkcja o nazwie `t` otrzymuje obliczany argument i pochodzi z parametru, importu lub wywołania: może to być wrapper wokół prawdziwej funkcji. Funkcja zdefiniowana w tym samym pliku się nie liczy, ponieważ wrapper miałby w środku własne wywołanie;
- pliku źródłowego nie da się sparsować;
- żaden plik nie używa żadnego klucza, co zwykle oznacza, że polecenie szuka w złym miejscu;
- plik lokalizacji jest dowiązaniem symbolicznym wychodzącym poza projekt, więc może go odczytywać inna aplikacja.

<Steps>

<Step title="Podgląd">

Uruchom `i18n-micro clean --dryRun` i przejrzyj wyświetloną listę.

</Step>

<Step title="Ochrona kluczy">

Zachowaj klucze, które tylko wyglądają na nieużywane, za pomocą `--exclude '^errors\.'`.

</Step>

<Step title="Usunięcie">

Uruchom polecenie ponownie z `--force`.

</Step>

</Steps>

## Tłumaczenie brakujących kluczy {#translate-missing-keys}

```bash
i18n-micro translate --dryRun                     # keys and characters per locale, nothing sent
export I18N_TRANSLATE_TOKEN=...                   # or put it in .env
i18n-micro translate --service deepl --locale de,fr
```

- `translate` uzupełnia klucze, których brakuje lub które są puste; `--replace` tłumaczy wszystko od nowa.
- Placeholdery i formy liczby mnogiej są chronione. Tłumaczenie, które utraciło placeholder, nie jest zapisywane: klucz zostaje wymieniony, a polecenie kończy się kodem `1`.
- Każda partia jest zapisywana przed wysłaniem kolejnego żądania, więc awaria kosztuje tylko żądanie, które się nie powiodło.

| `--service` | Usługa | `--token` | Przydatne `--options` |
| --- | --- | --- | --- |
| `ai` | Vercel AI Gateway, OpenAI, Anthropic lub dowolny serwer zgodny z OpenAI | Klucz API lub `AI_GATEWAY_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` | `provider`, `model`, `baseUrl`, `maxTokens` |
| `azure` | Azure Translator | Klucz subskrypcji | `region` |
| `deepl` | DeepL, łącznie z kluczami Free | Klucz uwierzytelniający | `formality`, `glossaryId`, `context` |
| `google` | Google Cloud Translation v2 | Klucz API | `model` |
| `libretranslate` | LibreTranslate | Opcjonalny | `baseUrl` |
| `yandexcloud` | Yandex Cloud Translate | Klucz API lub token IAM z `authScheme:Bearer` | `folderId`, `model` |

Opcje to pary `key:value`: `--options provider:openai,model:gpt-4o-mini`. Wszystkie usługi przyjmują też `baseUrl`, `retries`, `retryDelayMs` i `timeoutMs`. Żądanie tłumaczenia może już zostać naliczone, więc jest powtarzane tylko po `429` lub `503`, i to nie wtedy, gdy usługa prosi o czekanie dłuższe niż minuta.

<Warning>

Flagi są widoczne w historii powłoki i na listach procesów, więc przekazuj token przez zmienną środowiskową. CLI maskuje to, o czym wie, że jest tajne, wszędzie tam, gdzie to wypisuje, łącznie z `--debug`: tokeny, klucze dostawców, dane uwierzytelniające Basic oraz zapytanie i dane uwierzytelniające skonfigurowanego adresu URL. Serwer, który przeformatowuje klucz przed jego zwróceniem, jest poza zasięgiem CLI, więc ostrożnie obchodź się z logami z nieudanego uruchomienia.

</Warning>

Usługa `ai` stosuje glosariusz. Gdy istnieje `.i18n-glossary.json`, jest używany bez flagi; `--glossaryFile` wskazuje inny plik.

```json .i18n-glossary.json
{ "entries": [{ "source": "Cart", "target": "Warenkorb", "to": "de" }] }
```

## Zamiana tekstu zakodowanego na sztywno na klucze {#turn-hardcoded-text-into-keys}

```bash
i18n-micro text-to-i18n --dryRun   # list what would change
i18n-micro text-to-i18n            # rewrite the templates
```

```vue
<!-- before -->
<h1>Welcome to our site</h1>
<!-- after -->
<h1>{{ $t('pages.index.welcome-to-our') }}</h1>
```

Przepisywane są tylko szablony `.vue` samego projektu, a nie te z warstwy czy celu aliasu. Każdy przepisany plik jest ponownie parsowany przed zapisaniem. Następujące elementy są wymieniane i zachowują swój tekst:

- tekst w plikach `.ts` i skryptach, ponieważ `$t` nie jest wszędzie dostępne;
- tekst obok znaczników lub interpolacji, taki jak `<p>Hello <b>world</b> today</p>`: pół zdania nie da się przetłumaczyć osobno;
- wygenerowany klucz, który kolidowałby z innym, co może się zdarzyć stronie nadrzędnej i jej stronie podrzędnej;
- znany klucz, którego nie można umieścić w cudzysłowie.

<Warning>

Najpierw zrób commit i przejrzyj diff.

</Warning>

## Zmiana nazwy klucza {#rename-a-key}

```bash
i18n-micro rename --from common.save --to actions.save
i18n-micro rename --from settings --to account.settings   # a whole namespace
```

`rename` edytuje drzewo składniowe, więc komentarze i niepowiązane ciągi pozostają bez zmian, a aliasy i `:keypath` są śledzone. Własny plik warstwy nigdy nie jest zmieniany. Polecenie ostrzega o tym, czego nie może przepisać, i zostawia to bez zmian:

- obliczany klucz pod starą nazwą;
- każdy zwykły ciąg mu równy;
- szablon Pug;
- źródło w warstwie lub w folderze poza projektem.

`--to` musi być kluczem, który można zapisać w kodzie: bez cudzysłowów, bez ukośnika wstecznego, bez pustego segmentu, bez `__proto__`.

## Wymiana plików z tłumaczami {#exchange-files-with-translators}

```bash
i18n-micro export --format csv
i18n-micro import --format csv --dryRun
```

**`export`** zapisuje każdy klucz każdej lokalizacji, łącznie z nieprzetłumaczonymi, z tekstem domyślnej lokalizacji jako źródłem: kolumna `Source` w CSV, komentarz `#.` w PO.

- Bez `--dir` pliki PO trafiają do `pots`, a CSV do `csv_exports`.
- Zapisuje informację o tym, co zapisał, w `.i18n-export.json` w folderze wyjściowym. Zatrzymuje się, gdy plik zmienił się od tego czasu i zawiera tłumaczenia, których nie mają pliki lokalizacji, łącznie z wpisami PO oznaczonymi jako fuzzy; `--force` je nadpisuje. Zwykłe edycje plików lokalizacji go nie zatrzymują.

**`import`** scala, pomija puste komórki i pomija wpisy PO oznaczone jako `fuzzy`.

- Klucz, który nadpisałby wartość, lub wartość nad całą grupą kluczy, jest wymieniany i pomijany, a polecenie kończy się kodem `1`.
- Zatrzymuje się z kodem `2` przy katalogu w nieoczekiwanym miejscu, katalogu strony, którego ostatni eksport nie zapisał, cudzysłowie w niewłaściwym miejscu w CSV lub wpisie strony przy `disablePageLocales`.

W przypadku platformy tłumaczeniowej użyj jej własnego CLI: konfiguracja [Crowdin](/pl/guide/crowdin) synchronizuje pliki JSON, łącznie z plikami stron.

## Synchronizacja z własnym endpointem {#sync-with-your-own-endpoint}

`sync-remote` wymienia globalne pliki lokalizacji z endpointem HTTP, który prowadzisz. Pliki stron pozostają lokalne, o czym polecenie informuje. Opisz endpoint w `.i18n-remote.json`:

```json .i18n-remote.json
{ "url": "https://translations.example.com", "path": "translations" }
```

Endpoint odpowiada na `GET` i `PUT` obiektem `{ locale: messages }`. Uwierzytelniaj się za pomocą `auth: { username, password }` lub umieść token bearer w `I18N_REMOTE_TOKEN`.

| | Pull | Push |
| --- | --- | --- |
| Co jest przenoszone | Uzupełnia to, czego nie masz, i zachowuje klucze, które masz tylko Ty | Wysyła własne klucze projektu, nie klucze warstwy, i pomija Twoje puste wartości |
| Konflikty | Klucz różniący się po obu stronach: nic nie jest zapisywane, kod `1`; `--force` przyjmuje wartość zdalną | PUT zastępuje dokument, więc push najpierw odczytuje endpoint i zatrzymuje się z kodem `1`, gdy zawiera on tekst, którego nie masz; `--force` go nadpisuje. Endpoint, który odpowiada `404`, nie ma nic do stracenia |
| `--dryRun` | Odczytuje z endpointu, wymienia zmiany, niczego nie zapisuje | Podaje, co zostałoby wysłane, bez kontaktowania się z endpointem |

Lokalizacja, której nie skonfigurowano, jest pomijana, a pusta wartość zdalna niczego nie czyści.

## Przejście z nuxt-i18n-micro-cli {#moving-from-nuxt-i18n-micro-cli}

| Stare polecenie | Teraz |
| --- | --- |
| `validate` | `check` |
| `diff` | `check --only missing` |
| `check-duplicates` | `check --only duplicates` |
| `export-csv`, `import-csv` | `export --format csv`, `import --format csv` |
| `--potsDir`, `--csvDir` | `--dir` |
| `estimate` | `translate --dryRun` |
| `glossary` | Edytuj `.i18n-glossary.json`; `translate` odczytuje go samodzielnie |
| `backup`, `restore` | Git, który już przechowuje Twoje pliki lokalizacji |
| `init` | `nuxi init`, a następnie dodaj `nuxt-i18n-micro` do `modules` |
| `split` | Usunięte: moduł nie odczytuje podzielonych plików |
| `optimize` | `check --only duplicates` |
| `replace-values` | Twój edytor lub `sed` |
| `stats --full` | `stats`; szczegóły zawiera [DevTools](/pl/guide/devtools) |
| `search --hardcodedOnly` | `text-to-i18n --dryRun` |
| `search --preferUnused`, `--onlyVue` | Usunięte |
| reguły `lint` `no-html-tags`, `no-special-chars`, `no-mixed-case`, `no-missing-punctuation`, `no-inconsistent-pluralization` | Usunięte: oznaczały zwykły tekst. Jeśli potrzebujesz którejś, napisz wpis `customRegexRules` |
| `text-to-i18n --extractOnlyDirs`, `--extractOnlyPatterns`, `--verbose` | Usunięte: kod nigdy nie jest przepisywany |
| `--logLevel verbose` | Usunięte: nic nie robiło |

**Usunięte usługi:** `googlefree`, `yandex` (użyj `yandexcloud`), `ibm`, `lingvatranslate`, `modernmt`, `lilt`, `unbabel`, `reverso`, `baidu`, `papago`, `tencent`, `systran`, `mymemory`.

**Usunięte typy `sync-remote`:** `github`, `gitlab`, `crowdin`, `lokalise`, `tolgee`, `weblate`. Użyj własnego CLI platformy lub `custom`, który nie wymaga już `type`.

### Zmienione działanie {#changed-behaviour}

- `extract` i `sync` nie zapisują już `''`. Klucze pozostają nieobecne, a `check` je zgłasza. `extract` zapisuje klucz tylko wtedy, gdy kod podaje jego tekst.
- `extract` zapisuje klucze stron do `locales/pages/<route name>/`, skąd odczytuje je moduł, i skanuje `app/` w Nuxt 4. Przenieś wszystko z katalogów takich jak `pages/_about` i `pages/blog_` oraz usuń zbłąkany `locales/pages/<locale>.json`.
- `translationDir` z `nuxt.config` jest respektowane; wcześniej każde polecenie po cichu używało `locales`.
- Bez `defaultLocale` domyślną lokalizacją jest `en`, tak jak w module, a `DEFAULT_LOCALE` jest uwzględniane. Wcześniej była to pierwsza lokalizacja.
- `check` i `sync` używają domyślnej lokalizacji jako odniesienia i sprawdzają pliki stron. `"a.b"` i `a: { b }` liczą się jako jeden klucz.
- `clean` zachowuje klucz użyty gdziekolwiek, w dowolnym zakresie, i zatrzymuje się, gdy nie można udowodnić użycia. `--include` i `--exclude` wybierają, co może zostać usunięte.
- `sync` zatrzymuje się w ten sam sposób, a także gdy domyślna lokalizacja nie ma kluczy do porównania. `--force` to nadpisuje. Zatrzymuje się również, gdy `DEFAULT_LOCALE` wybrało inne odniesienie niż `nuxt.config`.
- Długie flagi z jednym myślnikiem i zbędne argumenty są błędami: `clean -dryRun` nie uruchamia już `clean`.
- Pliku tylko do odczytu lub pliku, który nie jest w UTF-8, nie można zapisać: polecenie zatrzymuje się, zanim cokolwiek zmieni. Odczyt takiego pliku jest w porządku. Powtórzony klucz, klucz o nazwie `__proto__` i liczba całkowita większa niż 2^53 zatrzymują polecenie, ponieważ zapis by je utracił.
- Flaga wymagająca wartości, po której następuje inna flaga, jest błędem; dla wartości zaczynającej się od myślnika zapisz `--flag=--value`. Flaga logiczna przyjmuje tylko `true` lub `false`.
- `export` zatrzymuje się zamiast nadpisywać tłumaczenia, które nigdy nie zostały zaimportowane.
- Kody wyjścia to `0`, `1` i `2`; wcześniej błędy zwracały `1`, a `diff` i `check-duplicates` zawsze `0`.
- `lint --fix` nie zostawia już plików `.bak`.
- Zapis zachowuje wcięcia pliku, zakończenia linii, końcowy znak nowej linii, dowiązanie symboliczne i twarde, a plików, których nie zmienił, nie rusza.
- Błędnie wpisana lub usunięta flaga jest teraz błędem, a nie jest po cichu ignorowana.
- Ścieżki takie jak `--dir` są względne wobec projektu, a nie powłoki.
- `ai` nie wczytuje już pakietów `@ai-sdk/*`: użyj `provider` `gateway`, `openai` lub `anthropic` albo `baseUrl` dla serwera zgodnego z OpenAI.
