Ta strona odwzorowuje aplikację `@nuxtjs/i18n` na nuxt-i18n-micro: opcje, funkcje pomocnicze i układ plików. Korzystaj z niej, gdy wymieniasz moduł w istniejącej aplikacji. Zachowujesz swoje adresy URL (nazwy strategii są takie same) i przenosisz tłumaczenia do plików JSON dla poszczególnych stron.

<Tip>

**Aktualizujesz samo nuxt-i18n-micro?** — Zobacz [Aktualizacja](/pl/guide/upgrade).

</Tip>

## Wymiana modułu {#swap-the-module}

```bash
npm uninstall @nuxtjs/i18n
npm install nuxt-i18n-micro
```

```ts
// nuxt.config.ts — before
export default defineNuxtConfig({
  modules: ['@nuxtjs/i18n'],
  i18n: {
    locales: [
      { code: 'en', language: 'en-US', file: 'en.json' },
      { code: 'de', language: 'de-DE', file: 'de.json' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    langDir: 'locales',
    detectBrowserLanguage: { useCookie: true, cookieKey: 'i18n_redirected', redirectOn: 'root' },
  },
})
```

```ts
// nuxt.config.ts — after
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    translationDir: 'locales',
    localeCookie: 'i18n_redirected',
    autoDetectPath: '/',
  },
})
```

## Opcje {#options}

| `@nuxtjs/i18n` | nuxt-i18n-micro |
| --- | --- |
| `locales[].code` | `locales[].code` |
| `locales[].language` (`iso` przed v9) | `locales[].iso` |
| `locales[].name` | `locales[].displayName` |
| `locales[].dir` | `locales[].dir` |
| `locales[].domain` | `locales[].baseUrl` (origin wraz ze schematem) |
| `locales[].domainDefault` | `locales[].baseDefault` |
| `differentDomains`, `multiDomainLocales` | niepotrzebne: sam `baseUrl` kieruje ruch według hosta, zobacz [Warstwy i domeny](/pl/guide/layers#multiple-domains) |
| `locales[].file` / `files`, `langDir`, `lazy` | `translationDir`; pliki są wyszukiwane po nazwie i zawsze ładowane dla każdej strony osobno |
| `defaultLocale`, `strategy` | te same nazwy, te same cztery wartości |
| `baseUrl` | `metaBaseUrl` |
| `customRoutes: 'config'` + `pages` | `globalLocaleRoutes` |
| `detectBrowserLanguage: false` | `redirects: false` (bez przekierowań) lub `autoDetectLanguage: false` (ignorowanie nagłówka) |
| `detectBrowserLanguage.useCookie` / `cookieKey` | `localeCookie: '<name>'` (`null` wyłącza cookie) |
| `detectBrowserLanguage.redirectOn: 'root'` | `autoDetectPath: '/'` (domyślnie) |
| `detectBrowserLanguage.redirectOn: 'no prefix'` | `autoDetectPath: 'no_prefix'` |
| `detectBrowserLanguage.redirectOn: 'all'` | `autoDetectPath: '*'` |
| plik konfiguracyjny `vueI18n` (`fallbackLocale`, `numberFormats`, `datetimeFormats`) | `fallbackLocale`, `numberFormats`, `datetimeFormats` w `i18n` |

Nie ma `alwaysRedirect`: gdy cookie jest ustawione, `/` stosuje je przy każdej wizycie. Pełna lista znajduje się w [Opcjach modułu](/pl/api/module-options); zasady wykrywania opisuje strona [Wykrywanie lokalizacji](/pl/guide/locale-detection).

## Funkcje pomocnicze i composables {#helpers-and-composables}

| `@nuxtjs/i18n` / vue-i18n | nuxt-i18n-micro (szablon / `useI18n()`) |
| --- | --- |
| `const { t } = useI18n()` | `const { t } = useI18n()`, `$t` w szablonach |
| `t('key', count)`, `tc` | `$tc('key', count)` |
| `te('key')` | `$has('key')` |
| `n(value, 'currency')`, `d(date, 'short')` | `$tn(value, 'currency')`, `$td(date, 'short')` |
| — | `$tdr(date)`: czas względny („za 3 dni”) |
| `locale.value` | `$getLocale()` |
| `locales.value` | `$getLocales()` |
| `setLocale('de')` | `$switchLocale('de')` |
| `useLocalePath()('about')` | `$localePath({ name: 'about' })` |
| `useLocaleRoute()` | `$localeRoute()` |
| `useSwitchLocalePath()('de')` | `$switchLocalePath('de')` |
| `useSetI18nParams()` | `$setI18nRouteParams()` |
| `useLocaleHead()` | automatycznie przy `meta: true`; [`useLocaleHead`](/pl/composables/useLocaleHead) dla niestandardowych nagłówków head |
| `defineI18nRoute({ paths: { de: '/ueber-uns' }, locales: [...] })` | `$defineI18nRoute({ localeRoutes: { de: '/ueber-uns' }, locales: [...] })` |
| `<NuxtLinkLocale to="about">` | `<i18n-link :to="{ name: 'about' }">` |
| `<i18n-t>` | `<i18n-t>` (sloty wypełniają placeholdery `{name}`) |
| `$i18n` w trasach serwerowych | `useTranslationServerMiddleware(event)`, zobacz [Trasy serwerowe i API](/pl/guide/server-side-translations) |

`useI18n()` jest importowane automatycznie. `$defineI18nRoute` musi zachować swój `$`: build odczytuje to wywołanie. Wszystkie funkcje pomocnicze: [Metody](/pl/api/methods).

## Pliki tłumaczeń {#translation-files}

Przenieś klucze z jednego dużego pliku dla każdej lokalizacji do pliku głównego oraz jednego pliku na stronę:

```text
locales/
├── en.json              # keys used on many pages (nav, footer)
├── de.json
└── pages/
    ├── index/en.json    # keys of pages/index.vue
    └── about/en.json    # keys of pages/about.vue
```

Trzymanie wszystkiego w plikach głównych również działa i jest najszybszym pierwszym krokiem. Ustaw `disablePageLocales: true`, dopóki ich nie podzielisz. Zobacz [Pliki tłumaczeń](/pl/guide/translations).

### Składnia wiadomości {#message-syntax}

| vue-i18n | nuxt-i18n-micro |
| --- | --- |
| interpolacja nazwana `{name}` | tak samo |
| `car \| cars` (2 formy: 1 → pierwsza) | formy są wybierane według liczby od 0: zapisz `no cars \| one car \| {count} cars` |
| powiązane wiadomości `@:other.key` | nieobsługiwane: powtórz tekst lub złóż go w kodzie |
| modyfikatory `@.upper:` | nieobsługiwane: formatuj w kodzie lub użyj `<i18n-t>` |
| dosłowne escapowanie `{'@'}` | niepotrzebne: zastępowane są tylko tokeny `{word}` |
| pliki wiadomości JS/TS | tylko JSON |

Regułę liczby mnogiej można zastąpić opcją [`plural`](/pl/api/module-options#plural).

## Sprawdzenie po zmianie {#check-after-the-switch}

- Każdy dotychczasowy adres URL nadal działa; nazwy strategii się zgadzają, a niestandardowe ścieżki przenoszą się do `globalLocaleRoutes` lub `$defineI18nRoute`.
- `hreflang`, canonical i `og:locale` działają od razu przy `meta: true`; usuń te napisane ręcznie.
- Błąd parsowania JSON zapisuje w logu ścieżkę pliku; brakujący klucz w trybie deweloperskim wyświetla ostrzeżenie w konsoli przeglądarki.
