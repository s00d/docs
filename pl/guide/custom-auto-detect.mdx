title: "Własne wykrywanie locale"
description: "Wybierz locale samodzielnie — na podstawie domeny, nagłówka lub profilu użytkownika — za pomocą pluginu serwerowego i useI18nLocale().setLocale()."
---

Wbudowane wykrywanie odczytuje adres URL, ciasteczko i `Accept-Language`. Gdy locale zależy od czegoś innego — domeny, nagłówka geolokalizacji ustawianego przez Twój CDN, profilu użytkownika — ustaw je samodzielnie w pluginie, który uruchamia się przed pluginem i18n. Moduł wczytuje wtedy tłumaczenia tego locale i używa go do przekierowań dokładnie tak, jakby sam je wykrył. Reguły decydujące o tym, kiedy wybrane locale wygrywa z adresem URL, opisuje strona [Wykrywanie locale](/pl/guide/locale-detection); ta strona pokazuje, jak podłączyć własne źródło.

## Ustawianie locale w pluginie serwerowym {#set-the-locale-in-a-server-plugin}

```ts
// plugins/i18n-locale.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10, // before the i18n plugin (order -5)
  setup() {
    const { setLocale } = useI18nLocale()
    const host = (useRequestHeaders(['host']).host ?? '').split(':')[0]! // without the port

    if (host.endsWith('.de')) setLocale('de')
    else if (host.endsWith('.fr')) setLocale('fr')
  },
})
```

`setLocale(code)` zapisuje stan locale (`useState('i18n-locale')`) oraz, jeśli skonfigurowano ciasteczko locale, także ciasteczko. Używaj go zamiast samodzielnie zapisywać `useState` lub `useCookie`. Przekazuj tylko kody włączonych locale.

Pozostaw plugin jako `.server.ts`, gdy odczytuje nagłówki żądania: nie istnieją one w przeglądarce. Plugin `.client.ts` jest miejscem dla źródeł dostępnych wyłącznie w przeglądarce, takich jak `localStorage`.

## Wyłączanie wbudowanego kroku Accept-Language {#turn-off-the-built-in-accept-language-step}

Twój plugin i `Accept-Language` mogą się nie zgadzać. Aby decydował wyłącznie Twój kod (oraz adres URL i ciasteczko), wyłącz nagłówek:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    autoDetectLanguage: false,
  },
})
```

[`autoDetectLanguage`](/pl/api/module-options#autodetectlanguage) steruje jedynie krokiem nagłówka. Adres URL i prawidłowe ciasteczko nadal się liczą.

## Co dzieje się dalej {#what-happens-next}

Efekt `setLocale` zależy od [strategii](/pl/guide/strategy):

| Strategia | Efekt `setLocale('de')` w pluginie |
| --- | --- |
| `no_prefix` | Strona renderuje się po niemiecku; adres URL się nie zmienia. |
| `prefix`, `prefix_except_default` | Na ścieżce bez prefiksu, gdzie [`autoDetectPath`](/pl/api/module-options#autodetectpath) zezwala na przekierowania (domyślnie tylko `/`), serwer odpowiada `302` na niemiecki adres URL. Adres URL z prefiksem locale go zachowuje. |
| `prefix_and_default` | Brak przekierowania: adres URL bez prefiksu jest prawidłową stroną domyślnego locale. |

W strategiach z prefiksem locale w adresie URL jest wyborem użytkownika i Twój plugin go nie nadpisuje. Wyjątkiem jest `autoDetectPath: '*'`: serwer przenosi wtedy adresy URL z prefiksem na podstawie ciasteczka i `Accept-Language` i ignoruje stan, ale `setLocale()` zapisuje także ciasteczko, jeśli jest skonfigurowane, więc od następnego żądania wybór Twojego pluginu może przekierować adres URL z prefiksem. Pozostaw `'/'` lub użyj `'no_prefix'`, gdy jawne adresy URL locale muszą wygrywać. Używaj pluginu do wyboru miejsca, w którym ląduje odwiedzający, a nie do przepisywania linków, w które kliknął.

## Respektowanie locale wybranego przez użytkownika {#respect-a-locale-the-user-picked}

Gdy użytkownik zmieni język, przełączenie zapisuje ciasteczko. Pomiń własne wykrywanie, gdy istnieje już prawidłowa preferencja:

```ts
// plugins/i18n-locale.server.ts
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10,
  setup() {
    const { getPreferredLocale, setLocale, validLocales } = useI18nLocale()
    if (getPreferredLocale()) return // valid state or cookie: keep it

    const country = useRequestHeaders(['x-country'])['x-country']
    if (country === 'JP') return setLocale('ja')

    const header = useRequestHeaders(['accept-language'])['accept-language']
    setLocale(detectLocaleFromAcceptLanguage(header, validLocales))
  },
})
```

`getPreferredLocale()` zwraca stan lub ciasteczko tylko wtedy, gdy jest to włączone locale, więc nieaktualne ciasteczko nie blokuje wykrywania. `detectLocaleFromAcceptLanguage` to uwzględniający wartości q mechanizm dopasowania, którego używa sam moduł (zainstaluj `@i18n-micro/utils`, aby go zaimportować); `setLocale(null)` nic nie robi.

## Jedna domena na locale {#one-domain-per-locale}

Jeśli każda domena ma obsługiwać własne locale, nie potrzebujesz pluginu: nadaj każdemu locale `baseUrl`, ustaw `baseDefault: true` dla domyślnego locale każdej domeny i zbuduj raz (strona statyczna nadal uruchamia `nuxi generate` dla każdej domeny). Zobacz [Warstwy i domeny](/pl/guide/layers#multiple-domains).
