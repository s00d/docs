---

Opcja `strategy` decyduje, czy locale pojawia się w URL i dla których locale. Wybierz ją raz, zanim opublikujesz adresy URL: późniejsza zmiana zmienia każdy link. Moduł generuje następnie zlokalizowane trasy w czasie budowania, a `$localePath`, `<i18n-link>` i przełącznik je odczytują.

## Cztery strategie {#the-four-strategies}

![Strona /about w en (domyślnym) i de w każdej strategii; te same adresy URL wymieniono w tekście poniżej](/images/diagrams/strategies.svg)

**Typ** `Strategies` · **Domyślnie** `'prefix_except_default'`

Strategia routingu URL dla prefiksów locale.

- `'no_prefix'` — brak locale w URL; locale przechowywane w cookie.
- `'prefix_except_default'` — prefiks dla wszystkich locale poza domyślnym.
- `'prefix'` — zawsze prefiks, także dla domyślnego locale.
- `'prefix_and_default'` — jak `prefix`, ale domyślne locale jest dostępne również bez prefiksu.

Adresy URL strony `about` przy `defaultLocale: 'en'` i locale `en`, `de`:

| Strategia | Angielski | Niemiecki | Nieobsługiwane |
| --- | --- | --- | --- |
| `prefix_except_default` (domyślna) | `/about` | `/de/about` | `/en` i `/en/about` zwracają 404 |
| `prefix` | `/en/about` | `/de/about` | `/about` przekierowuje na URL z prefiksem |
| `prefix_and_default` | `/about` i `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | locale nie występuje w URL |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

Strategia jest ustalana podczas budowania: jej nadpisanie w czasie działania jest ignorowane z ostrzeżeniem ([Nadpisania w czasie działania](/pl/guide/runtime-overrides)).

## Którą wybrać {#which-one-to-choose}

- **`prefix_except_default`**: większość serwisów. Istniejące adresy URL bez prefiksu nadal działają dla domyślnego języka.
- **`prefix`**: wszystkie języki są równorzędne; `/` zawsze prowadzi do strony głównej z prefiksem.
- **`prefix_and_default`**: potrzebujesz, aby działały zarówno `/en/...`, jak i adresy bez prefiksu, na przykład podczas przechodzenia z jednych na drugie. Adresy bez prefiksu nigdy nie są przekierowywane.
- **`no_prefix`**: aplikacje za logowaniem lub jeden URL na stronę dla wszystkich języków. Locale pochodzi z cookie lub `?locale=`. Wyszukiwarki widzą jeden język na URL, więc nie są emitowane alternatywy `hreflang`.

Jak wybierane jest locale dla URL i kiedy odwiedzający jest przekierowywany, opisuje strona [Wykrywanie locale](/pl/guide/locale-detection).

## Generowane trasy {#generated-routes}

W czasie budowania każda strona dostaje rekordy tras, których wymaga jej strategia. Każdy rekord zawiera `meta.i18n = { name, locales }`: stronę, którą pokazuje, i locale, które obsługuje. Linki, przełączenia i przekierowania są obsługiwane na podstawie tych rekordów, więc URL zwracany przez moduł jest zawsze takim, który router obsługuje.

Locale współdzielące ścieżkę strony współdzielą jeden rekord, `/:locale(de|fr)/about`. Locale z własną ścieżką dostaje własny rekord o nazwie `localized-<page>-<locale>`:

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

Niestandardowe ścieżki, listy locale dla poszczególnych stron i wykluczanie strony z lokalizacji są opisane w [Zlokalizowanych ścieżkach](/pl/guide/custom-locale-routes) i [Konfiguracji strony](/pl/guide/per-component-translations). Prefiks `localized-` to [`localizedRouteNamePrefix`](/pl/api/module-options#localizedroutenameprefix).

<Warning>

**Nazwy tras są generowane** — Nie wpisuj na sztywno nazw `localized-…` w `router.push({ name })`. Przekaż własną nazwę strony do `$localeRoute` lub `<i18n-link>`; one wybiorą właściwy rekord.

</Warning>

## Linkowanie do strony w danym locale {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- Działają zarówno nazwane trasy, jak i ścieżki. Ścieżka jest dopasowywana do generowanych tras, więc akceptowana jest jej forma w dowolnym locale.
- Locale, które nie obsługuje danej strony (zobacz `locales` w [Konfiguracji strony](/pl/guide/per-component-translations)), linkuje do strony głównej tego locale zamiast do brakującej strony.
- Parametry dla poszczególnych locale (przetłumaczony slug) przekazuje się przez `$setI18nRouteParams`, zobacz [Zlokalizowane ścieżki](/pl/guide/custom-locale-routes).

Sygnatury znajdziesz w [Metodach](/pl/api/methods).

## Szczegóły `no_prefix` {#no_prefix-details}

- [`localeCookie`](/pl/api/module-options#localecookie) w `no_prefix` domyślnie ma wartość `'user-locale'`, więc wybór przetrwa przeładowanie.
- `$switchLocale('de')` ładuje niemiecki słownik i zastępuje bieżący wpis historii; URL się nie zmienia.
- Niestandardowe ścieżki dla poszczególnych locale nadal działają: przy `globalLocaleRoutes: { about: { de: '/ueber-uns' } }` niemieckojęzyczni czytelnicy dostają `/ueber-uns`. Ten URL zawsze renderuje się po niemiecku, niezależnie od preferencji odwiedzającego, a strona ograniczona do niektórych locale renderuje się w jednym z nich. Ścieżka współdzielona przez kilka locale (`en` i `de` na `/page/:id`) renderuje się w preferowanym locale, jeśli jest jednym z nich. Sama preferencja pozostaje: następna strona do niej wraca.
- [`noPrefixRedirect: true`](/pl/api/module-options#noprefixredirect) przekierowuje oryginalną ścieżkę strony, która ma niestandardową ścieżkę w domyślnym locale: na niestandardową ścieżkę locale odwiedzającego, a w przeciwnym razie na ścieżkę domyślnego locale (`/about` → `/about-us`, gdy `en` ma `/about-us`, → `/ueber-uns` przy cookie `de`). Locale bez własnej niestandardowej ścieżki pozostaje na oryginalnej ścieżce i tam się renderuje. Strony z parametrami nie są przekierowywane.

## Aplikacje bez `pages/` {#apps-without-pages/}

Przy `pages: false` nie ma tras stron do lokalizowania. Używaj wyłącznie głównych plików tłumaczeń (`disablePageLocales: true`); wykrywanie, cookie i `$switchLocale` nadal działają. Działającą konfiguracją jest wariant `pages-false` w `test/fixtures/basic` w repozytorium.
