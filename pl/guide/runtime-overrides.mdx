Nadpisania w czasie działania pozwalają uruchamiać jeden artefakt builda z różnymi ustawieniami lokalizacji dla każdego środowiska lub tenanta, bez ponownego budowania. Możesz zmienić domyślną lokalizację, lokalizację zapasową oraz to, które lokalizacje są wyłączone. Routing, przekierowania, renderowanie i funkcje pomocnicze serwera używają nadpisanych wartości, podobnie jak przeglądarka na stronie renderowanej po stronie serwera.

## Ustawianie nadpisań za pomocą zmiennych środowiskowych {#set-overrides-with-environment-variables}

```bash
NUXT_I18N_DEFAULT_LOCALE=de \
NUXT_I18N_FALLBACK_LOCALE=en \
NUXT_I18N_DISABLED_LOCALES=fr,it \
node .output/server/index.mjs
```

| Zmienna | Alias |
| --- | --- |
| `NUXT_I18N_DEFAULT_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE` |
| `NUXT_I18N_FALLBACK_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE` |
| `NUXT_I18N_DISABLED_LOCALES` (rozdzielone przecinkami) | `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES` |

Serwer odczytuje je raz przy starcie; aby zastosować zmianę, uruchom go ponownie. Na stronie renderowanej po stronie serwera przeglądarka otrzymuje rozwiązane wartości od serwera. Przy `ssr: false` nie ma renderowania po stronie serwera, a przeglądarka nie ma środowiska: obowiązuje tam tylko `runtimeConfig.public.i18nRuntime`, a przeglądarka wyświetla poniższe ostrzeżenia.

## Ustawianie nadpisań w runtimeConfig {#set-overrides-in-runtimeconfig}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

Wartość ustawiona w `runtimeConfig.public.i18nRuntime` ma pierwszeństwo przed zmienną `NUXT_I18N_*` dla tego samego pola.

Nie należy tego mylić ze zmienną `DEFAULT_LOCALE` używaną podczas budowania, która zastępuje `defaultLocale` w trakcie budowania i nie wymaga obsługi w czasie działania.

## Co można, a czego nie można zmienić {#what-can-and-cannot-change}

| Ustawienie | W czasie działania |
| --- | --- |
| `defaultLocale` | Tak w strategiach `prefix` i `no_prefix`. W `prefix_except_default` i `prefix_and_default` jest ustalane podczas budowania (jej strony są trasami bez prefiksu); nadpisanie jest ignorowane z ostrzeżeniem. |
| `fallbackLocale` | Tak. |
| `disabledLocales` | Dodaje do lokalizacji wyłączonych podczas budowania; nigdy nie włącza ponownie żadnej z nich. Domyślnej lokalizacji builda nie można wyłączyć w `prefix_except_default` / `prefix_and_default`. |
| `strategy` | Nie. Strategia ustawiona w czasie działania jest ignorowana z ostrzeżeniem; zbuduj jeden artefakt na strategię. |

Nieprawidłowe wartości nigdy nie psują aplikacji. Każdy przypadek zapisuje jedno ostrzeżenie na proces serwera:

- wyłączenie wszystkich lokalizacji jest ignorowane;
- `defaultLocale`, która nie jest włączona, przechodzi na pierwszą włączoną lokalizację;
- `fallbackLocale`, która nie jest włączona, zachowuje wartość z builda, jeśli ta jest włączona, w przeciwnym razie nie ma lokalizacji zapasowej.

## Odczyt efektywnej konfiguracji {#read-the-effective-config}

```vue
<script setup lang="ts">
const { $getI18nConfig } = useNuxtApp()
const config = $getI18nConfig() // build config with overrides applied
</script>
```

Traktuj ją jako tylko do odczytu: na serwerze jest współdzielona przez wszystkie żądania i zamrożona w trybie deweloperskim; kopia w przeglądarce nie jest zamrożona. Import konfiguracji z `#build/i18n.strategy.mjs` daje wartości z builda bez nadpisań.

## Wyłączone lokalizacje i pliki statyczne {#disabled-locales-and-static-files}

Lokalizacja wyłączona w czasie działania zwraca 404 na swoich trasach i trasie payloadu, ale jej pliki payload nadal znajdują się w `.output/public/_locales/`, a serwer plików statycznych je zwraca. Jeśli te pliki nie mogą być dostępne, wyłącz lokalizację podczas budowania za pomocą `disabled: true`.
