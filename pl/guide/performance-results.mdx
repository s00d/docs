### Opis {#description}

Porównuje **czysty Nuxt**, **i18n-micro** i **`@nuxtjs/i18n`** przy jednym współdzielonym profilu słowników za pomocą `untestutils/perf`.

Skupienie: czas budowania, szczytowe RSS, wdrażalny **kod vs tłumaczenia (zasoby) vs łącznie** oraz obciążenie (Artillery).

### Uwagi metodologiczne {#methodology-notes}

- Metryki to **średnie z 3 kolejnych przebiegów na fixture** (nie przeplatanych).
- **Artefakt**: `.output/server/index.mjs` serwera node Nitro po wymuszonym `nuxi build`; `nuxt-i18n-micro` to **zbudowany dist modułu** (nie stub jiti z `dev:prepare`). Zobacz [metodologię benchmarków](https://s00d.github.io/nuxt-i18n-micro/contributing/performance-methodology).
- **Tłumaczenia** = `bundle.asset` (JSON locale, `chunks/raw/`, pasujące chunki locale przez `isTranslationFile`).
- **Kod** nie obejmuje map źródeł (`*.map`): fixture'y linkują moduł z repozytorium, więc Nitro zapisuje dla niego pełne mapy, a dla zależności npm żadnych.
- **plain-nuxt** serwuje tę samą liczbę liści jako statyczny JSON — intensywne I/O pod obciążeniem, a nie „narzut i18n”.
- Profil obciążenia `--load full`: rozgrzewka 6s@6 + główny 60s@60 bez limitu (historyczny).
- Okresy schładzania `--cool fast` (zobacz dokument metodologii).
- Każde z `runs` budowań jest **wymuszone** (bez zerowania czasu budowania przez ciepły cache).
- **Error rate** Artillery w tabelach to błędy statusu HTTP z metryk obciążenia. Wykresy pokazują też `vusers.failed` (timeouty klienta przy nasyceniu); mogą one być wysokie, podczas gdy współczynnik błędów HTTP pozostaje 0%.

## Uwagi {#notes}

- Współdzielony profil: 4 locale × 2 strony × ~16,8 tys. liści index.
- Obciążenie: wyłącznie programowe Artillery — rozgrzewka **6s@6** + główny **60s@60**, bez limitu VU (historyczna metodologia YAML). Ścieżki z profilu runtime — zobacz `scripts/src/perf/load.ts`.
- Okresy schładzania: 2 s po budowaniu, 3 s między przebiegami, 5 s między fixture'ami. Budowania są wymuszane w każdym przebiegu, więc średnie nie są zaburzone trafieniami w cache.
- Ponowne uruchamianie na co dzień: `pnpm test:performance` (`--load short --cool fast`).
- Regeneracja tej strony: `pnpm -C scripts cli performance --load full --only all --runs 3`.
- Flagi: `--locales N --keys K --only all|micro|i18n|plain --runs N --skip-load --cool fast|strict`.
