---

Przy `meta: true` (domyślnie) każda zlokalizowana strona otrzymuje `<html lang dir>`, link canonical, alternatywy `hreflang`, `x-default` oraz tagi lokalizacji Open Graph. Ta strona przyda Ci się, gdy chcesz ustawić publiczny origin, dostosować, które lokalizacje pojawiają się w tagach, lub nadpisać je dla jednej strony. Większości witryn wystarczy `site.url` lub `metaBaseUrl` oraz poprawne kody `iso`.

## Minimalna konfiguracja {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

`/de/about` renderuje wtedy:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Kierunek tekstu {#text-direction}

`<html dir>` pochodzi z `dir` lokalizacji. Bez niego język zapisywany od prawej do lewej otrzymuje `rtl`, odczytane z `iso` (lub `code`): arabski, hebrajski, perski, urdu i kilka innych, a także każdy tag z pismem RTL, np. `az-Arab`. Każda inna lokalizacja nie dostaje atrybutu `dir`, co przeglądarki interpretują jako `ltr`.

<Warning>

**`dir: 'auto'` wydłuża czas parsowania dużych stron** — `auto` na `<html>` sprawia, że przeglądarka ustala kierunek na podstawie treści podczas parsowania. W Chromium ten koszt rośnie szybciej niż strona: około 100 ms przy 5000 elementów i 1 s przy 20 000. Używaj go tylko dla małej strony, której języka nie możesz znać.

</Warning>

## Jakie tagi otrzymujesz {#which-tags-you-get}

- **hreflang**: jeden tag na każdą lokalizację serwującą stronę, z wartością `iso` (lub `code`, gdy brakuje `iso`) i jej URL-em z tym samym query co canonical. Strona ograniczona za pomocą [Konfiguracji strony](/pl/guide/per-component-translations) lub `routeLocales` wymienia tylko swoje lokalizacje. [`hreflangBaseLanguage: true`](/pl/api/module-options#hreflangbaselanguage) dodaje również sam język (`es-ES` → `es`) dla pierwszej regionalnej lokalizacji.
- **x-default**: URL domyślnej lokalizacji, tylko gdy domyślna lokalizacja serwuje stronę.
- **og:locale**: wyprowadzany z `iso` (`en-US` → `en_US`). Ustaw `og` na lokalizacji, gdy mapowanie nie jest bezpośrednie, np. `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; bez żadnego z nich `og:locale` nie jest zapisywany, a tryb dev wyświetla ostrzeżenie.
- **canonical / og:url**: bieżący URL bez parametrów query, z wyjątkiem tych z [`canonicalQueryWhitelist`](/pl/api/module-options#canonicalquerywhitelist) (domyślnie `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Według strategii:

| Strategia | hreflang i x-default | canonical, og:url, og:locale, atrybuty html |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | tak | tak |
| `no_prefix` | nie (jeden URL serwuje każdą lokalizację) | tak |

## Ustawianie publicznego originu {#set-the-public-origin}

Bezwzględne URL-e używają pierwszego z:

1. [`metaBaseUrl`](/pl/api/module-options#metabaseurl);
2. `site.url` z `nuxt-site-config` (instalowanego przez `@nuxtjs/seo`);
3. originu żądania z dołączonym `app.baseURL`.

Przypnij jedno z dwóch pierwszych.

<Warning>

Fallback do originu żądania odczytuje `X-Forwarded-Host` i `X-Forwarded-Proto`, ponieważ [`metaTrustForwardedHost`](/pl/api/module-options#metatrustforwardedhost) i `metaTrustForwardedProto` domyślnie mają wartość `true`. Jest to bezpieczne tylko za proxy, które nadpisuje te nagłówki; w przeciwnym razie klient może wybrać hosta w Twoich linkach canonical, a cache może przekazać taką stronę dalej.

Jeśli aplikacja jest dostępna bezpośrednio, przypnij `metaBaseUrl`: w przeciwieństwie do ustawienia obu opcji na `false` ignoruje on również sfałszowany `Host`. Zobacz [Za proxy lub CDN](/pl/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

Fallback przydaje się, gdy jedno wdrożenie obsługuje kilka domen: `https://site-a.com/en/about` i `https://site-b.com/en/about` otrzymują każda własny origin.

Przy `baseUrl` ustawionym na lokalizacjach znany host używa własnego `baseUrl`, z pierwszeństwem przed `metaBaseUrl` i `site.url`, więc canonical i `og:url` pozostają w tej domenie, a `hreflang` wskazuje każdą lokalizację w jej domenie. Każdy inny host używa `metaBaseUrl`, w przeciwnym razie `baseUrl` domyślnej lokalizacji, a w ostateczności `site.url`, więc sfałszowany `Host` nie dotrze do Twoich tagów. Jeśli żadne z nich nie jest ustawione, pozostaje fallback do originu żądania, a budowanie wyświetla ostrzeżenie. Zobacz [Warstwy i domeny](/pl/guide/layers#multiple-domains).

## Pomijanie lokalizacji lub stron {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Jeśli domyślna lokalizacja ma `seo: false`, `x-default` nie jest zapisywany. Aby wyłączyć tagi dla jednej strony, użyj `disableMeta` w [Konfiguracji strony](/pl/guide/per-component-translations#turn-off-seo-tags) lub [`routeDisableMeta`](/pl/api/module-options#routedisablemeta) w konfiguracji.

## Nadpisywanie tagów na jednej stronie {#override-tags-on-one-page}

Dla treści z CMS, gdy istnieją tylko niektóre tłumaczenia lub URL-e pochodzą z API, zastąp wygenerowane tagi za pomocą [`useI18nHead`](/pl/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` może także ustawić lub usunąć `canonical`, `xDefault`, `ogLocale` i `ogUrl`; `disable` usuwa całe grupy (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Przekaż getter, aby wartości były ponownie obliczane po zmianie lokalizacji. W przypadku slugów dla poszczególnych lokalizacji najpierw ustaw `$setI18nRouteParams` ([Zlokalizowane ścieżki](/pl/guide/custom-locale-routes#per-locale-slugs)), a wygenerowane alternatywy już ich użyją.

## Ukośnik na końcu {#trailing-slash}

`$localePath`, `$switchLocalePath`, obiekt trasy z `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, przekierowania lokalizacji i URL-e SEO stosują jedną regułę ukośnika: domyślnie `experimental.defaults.nuxtLink.trailingSlash` lub [`trailingSlash`](/pl/api/module-options) w konfiguracji i18n, gdy ścieżki i18n mają się różnić.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) współpracuje z tym modułem przez `nuxt-site-config` 4+. Umieść `nuxt-i18n-micro` jako pierwszy, aby konfiguracja witryny mogła odczytać lokalizacje, i ustaw `site.url` raz — zasila on również powyższe tagi.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Przetłumaczona nazwa i opis witryny pochodzą z kluczy `nuxtSiteConfig.name` / `nuxtSiteConfig.description` w Twoich plikach lokalizacji. Błąd `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` oznacza, że `@nuxtjs/seo` jest starszy niż 3; zaktualizuj go ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
