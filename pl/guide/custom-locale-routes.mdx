---
title: "Zlokalizowane ścieżki"
description: "Nadaj stronie inny URL dla każdej lokalizacji za pomocą localeRoutes lub globalLocaleRoutes, łącznie z dynamicznymi parametrami i slugami dla poszczególnych lokalizacji."
---

Domyślnie każda lokalizacja serwuje stronę pod tą samą ścieżką: `/en/about`, `/de/about`. Zlokalizowane ścieżki pozwalają każdej lokalizacji używać własnych słów, np. `/de/ueber-uns`, podczas gdy plik strony pozostaje ten sam. Ustawiasz je w stronie za pomocą `$defineI18nRoute` albo dla wielu stron naraz w `nuxt.config.ts`.

## W stronie {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

Przy `prefix_except_default` i `defaultLocale: 'en'` strona odpowiada pod `/about`, `/de/ueber-uns` i `/fr/a-propos`. Lokalizacja bez wpisu zachowuje domyślną ścieżkę. Zapisuj ścieżki bez kodu lokalizacji: prefiks dodaje [strategia](/pl/guide/strategy), a ścieżka zaczynająca się od kodu lokalizacji powoduje ostrzeżenie w logach. Co jeszcze przyjmuje to wywołanie, opisano w [Konfiguracji strony](/pl/guide/per-component-translations).

## W nuxt.config {#in-nuxt-config}

[`globalLocaleRoutes`](/pl/api/module-options#globallocaleroutes) robi to samo dla dowolnej strony, z kluczem w postaci jej ścieżki (lub nazwy trasy, gdy zapisano go bez wiodącego ukośnika):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

Gdy strona ustawia `localeRoutes`, a `globalLocaleRoutes` ma ten sam klucz, wygrywa wpis z konfiguracji.

## Parametry dynamiczne {#dynamic-params}

Zapisuj parametry w dowolnej formie Nuxt: `[id]`, `[[page]]`, `[...slug]` lub `:id()`. Nazwy parametrów muszą odpowiadać plikowi strony.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

Strony zagnieżdżone przyjmują bezwzględną ścieżkę potomną (`/ueber-uns/team`) lub ścieżkę względną wobec zlokalizowanej ścieżki rodzica (`team`).

## Linkowanie do zlokalizowanych stron {#linking-to-localized-pages}

Linki są rozwiązywane do zlokalizowanej ścieżki docelowej lokalizacji, niezależnie od tego, czy przekażesz nazwę trasy, czy zwykłą ścieżkę:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

Nazwy tras pochodzą ze ścieżki pliku (`pages/about/team.vue` to `about-team`), chyba że ustawisz ją przez `definePageMeta({ name })`.

## Slugi dla poszczególnych lokalizacji {#per-locale-slugs}

Gdy sam slug różni się w zależności od lokalizacji (`/our-products/red-shoe` vs `/de/unsere-produkte/roter-schuh`), po załadowaniu danych wskaż przełącznikowi języka, których parametrów ma użyć, za pomocą `$setI18nRouteParams`:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

`$switchLocalePath('de')` i `<i18n-switcher>` linkują wtedy do `/de/unsere-produkte/roter-schuh`. Klucze to kody lokalizacji, wartości to parametry według nazwy (jak w pliku strony).

Przełącznik w layoucie renderuje się, zanim asynchroniczny setup strony tu dotrze, dlatego po zakończeniu renderowania moduł przepisuje linki `<i18n-switcher>` — zarówno w `app.vue`, jak i w stronie. Dzięki temu HTML z serwera, odwiedzający bez JavaScriptu i pierwszy render po stronie klienta są zgodne. W tym celu ustawiaj parametry podczas SSR: przy `lazy` lub `server: false` linki zmieniają się dopiero po hydratacji. Streaming SSR w Nuxt wysyła HTML, zanim parametry są znane, więc w tym trybie linki w pierwszym HTML zachowują parametry z URL-a.

Przepisywane są tylko własne linki przełącznika. Ręcznie napisany link `$switchLocalePath` musi renderować się po ustawieniu parametrów, więc umieść go w stronie, która je ustawia, również po `await`. W layoucie renderuje się on najpierw: jego HTML z serwera zachowuje parametry z URL-a, a hydratacja ostrzega o niezgodności. Użyj tam `<i18n-switcher>`, a wygląd dostosuj jego slotami i propsami `custom*Style`.

Parametry należą do strony, która je ustawiła:

- Są usuwane, gdy zatwierdzona zostanie nawigacja do innej ścieżki, więc każda strona ustawia własne. Anulowana nawigacja pozostawia je bez zmian.
- Pobieraj `$setI18nRouteParams` z `useNuxtApp()` lub `useI18n()` w `setup`, także gdy wywołujesz ją później w handlerze `useAsyncData`. Pobrana tam funkcja zna swoją stronę: jeśli odwiedzający już ją opuścił, spóźnione wywołanie nic nie robi.
- Z `keepalive` strona odzyskuje ustawione przez siebie parametry, gdy odwiedzający wraca. `useI18nHead` działa tak samo.

## Trasy dodane w pages:extend {#routes-added-in-pagesextend}

Trasy dodawane w hooku `pages:extend` nie mają pliku strony, z którego można odczytać `$defineI18nRoute`, a kilka z nich często współdzieli jeden komponent opakowujący. Trasa dodana bez `name` dostaje nazwę, którą Nuxt nadałby jej ścieżce (`/a/:id()` staje się `a-id`), więc linki językowe do niej trafiają — chyba że inna trasa ma już tę nazwę; wtedy nadaj jej jawne `name`. Prowadź jedną listę i podziel ją na strony oraz `globalLocaleRoutes` z kluczami w postaci nazw tras za pomocą `splitLocaleRoutes` z `@i18n-micro/utils/split-locale-routes` (dodaj pakiet do zależności):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

Nie umieszczaj zlokalizowanych ścieżek w `route.meta`: trafiłyby do tabeli tras po stronie klienta.
