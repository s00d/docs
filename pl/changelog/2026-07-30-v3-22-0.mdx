## Nuxt I18n Micro v3.22.0 — formaty, cache i Translation Memory {#nuxt-i18n-micro-v3-22-0-—-formats-cache-&-translation-memory}

**Data**: 2026-07-30

**Wersja**: `v3.22.0`

![Wydanie v3.22.0](/images/3.22.0.png)

Ogłaszamy **v3.22.0**: nazwane formaty liczb i dat w stylu Vue I18n z cache formaterów, przyjazne dla CDN cache'owanie payloadów tłumaczeń (odcisk treści + `httpCacheDuration`) oraz API Translation Memory do odczytu i zastępowania aktywnego słownika w czasie działania.

## Co nowego? {#what’s-new}

### Nazwane `numberFormats` / `datetimeFormats` + cache formaterów {#named-numberformats-/-datetimeformats-+-formatter-cache}

Nazwane formaty zgodne z Vue I18n i szybsze formatowanie Intl:

- Konfiguracja: `numberFormats` / `datetimeFormats` dla każdego locale
- API: `$tn(1000, 'currency')`, `$td(date, 'short')` (+ nadpisanie locale i scalanie opcji)
- `FormatService` cache'uje `Intl.NumberFormat` / `DateTimeFormat` / `RelativeTimeFormat` według locale+opcji

Zobacz [Metody — `$tn` / `$td`](/pl/api/methods#$tn) i [Opcje modułu](/pl/api/module-options#numberformats).

### `dateBuild` domyślnie przyjmuje odcisk treści {#datebuild-defaults-to-a-content-fingerprint}

`?v=` w żądaniach `/_locales` domyślnie przyjmowało `Date.now()`, podczas gdy odpowiedzi są serwowane jako `immutable` przez rok. Każda przebudowa unieważniała więc słownik u każdego klienta, nawet gdy żadne tłumaczenie się nie zmieniło.

Wartością domyślną jest teraz odcisk SHA-256 źródeł tłumaczeń, w kolejności warstw. Przebudowy z niezmienionymi tłumaczeniami zachowują ten sam URL. Jawne ustawienie `dateBuild` nadal ma pierwszeństwo. Zobacz [Opcje modułu — `dateBuild`](/pl/api/module-options#datebuild).

### `httpCacheDuration` dla payloadów `/_locales` {#httpcacheduration-for-/_locales-payloads}

Wbudowana trasa `/{apiBaseUrl}/:page/:locale/data.json` wysyła teraz nagłówek HTTP `Cache-Control` dla przeglądarek i CDN:

- Opcja: `httpCacheDuration` (sekundy, domyślnie `31536000` / 1 rok)
- Nagłówek: `Cache-Control: public, max-age=…, immutable`
- Bezpieczne z istniejącym cache-bustingiem `dateBuild` (`?v=...`); `0` wyłącza nagłówek; nie jest stosowane w trybie deweloperskim

Odpowiednik `experimental.httpCacheDuration` z `@nuxtjs/i18n` v10.2.0, w formie jawnego nagłówka odpowiedzi.

### Skompresowane publiczne payloady {#compressed-public-payloads}

`nitro.compressPublicAssets` obejmuje teraz payloady tłumaczeń kopiowane do katalogu publicznego (`.gz` + `.br`). Nitro kompresuje publiczne zasoby przed kopiowaniem, więc wcześniej payloady były jedyną nieskompresowaną częścią statycznego buildu — 6,65 MB surowo wobec 1,01 MB gzip na indeksie playgroundu. Moduł nadal nigdy sam nie włącza kompresji. Zobacz [Wydajność](/pl/guide/performance#payload-size).

### `resolveTranslations()` i `setTranslation(key, value)` {#resolvetranslations-and-settranslationkey-value}

Helpery runtime do odczytu i zastępowania aktywnego słownika tłumaczeń w pamięci:

- **`resolveTranslations()`** zwraca pełne drzewo, z którego `$t()` czyta dla aktywnego locale i trasy — przydatne dla DevTools, testów i edytorów runtime. Gdy aktywna jest druga warstwa (locale zapasowe lub hot-reload przy przejściu stron Nuxt), zrzut zachowuje zagnieżdżony kształt dzięki `mergeTranslationLayers` i używa płaskich kluczy z kropkami tylko w kolizjach skalar-kontra-obiekt, których pojedyncze drzewo nie potrafi inaczej wyrazić.
- **`setTranslation(key, value)`** zastępuje wartość pod kluczem (najwyższego poziomu, ścieżka z kropkami, obiekt, string lub skalar). To jest **zastąpienie**, a nie scalenie; użyj `$mergeTranslations`, gdy elementy sąsiednie mają zostać zachowane.
- Dostępne w `useI18n()`, `useNuxtApp()` oraz w instancjach i18n frameworków dziedziczonych z `@i18n-micro/core`.
- `@i18n-micro/test-utils` dodaje odpowiadające helpery `resolveTranslations` / `setTranslation` do testów jednostkowych.

### `getAllTranslations()` usunięte z pakietu Vue {#getalltranslations-removed-from-vue-package}

Użyj `resolveTranslations()` dla aktywnego drzewa wyszukiwania. Dla pełnego zrzutu magazynu w Vue użyj `getStorage()` lub `getRouteCache()`.

## Zmiany niekompatybilne {#breaking-changes}

Nic w publicznej konfiguracji nie wymaga zmian w kodzie aplikacji przy typowym użyciu. Poniższe ma znaczenie, jeśli sięgałeś do wewnętrznych mechanizmów runtime:

- **Payload SSR przeniesiono z `useState('i18n-ssr-chunks')` do `nuxtApp.payload.data['i18n-ssr-chunks']`.** Nadal zawiera **pełne fragmenty tłumaczeń** dla każdej pary `(locale, route)` załadowanej podczas SSR — te same słowniki co wcześniej, w miejscu, które Nuxt może wydzielić do `_payload.json` przy prerenderze. `useState('i18n-ssr-chunks')` nie zwraca teraz niczego. Odczyt tłumaczeń w ten sposób nigdy nie był wspierany, ale był opisany w dokumentacji API cache, dlatego jest tu wymieniony.
- **`NuxtTranslationLoaderOptions` udostępnia `setSsrChunk`.** Loader zapisuje każdy scalony fragment do `payload.data` na serwerze podczas ładowania. `getSsrChunks` nie jest używane.
- **`nitro.compressPublicAssets` generuje teraz `.gz` / `.br` obok skopiowanych payloadów.** Jeśli miałeś tę opcję włączoną, spodziewaj się większej liczby plików w wyjściu publicznym. Narzędzia wdrożeniowe, które wyliczają katalog tłumaczeń, mogą musieć je uwzględnić.
- **URL-e payloadów zmieniają się jednorazowo po aktualizacji**, ponieważ `?v=` przechodzi ze znacznika czasu buildu na odcisk treści. Klienci pobierają słownik ponownie przy pierwszym żądaniu po aktualizacji, a potem zachowują go przez kolejne wdrożenia — i o to właśnie chodzi.
- **`getAllTranslations()` usunięte z `@i18n-micro/vue`.** Zamiast tego użyj `resolveTranslations()` / `getStorage()` / `getRouteCache()`.

## Poprawki błędów {#bug-fixes}

- **`<i18n-switcher>`** — pomija w liście rozwijanej locale z `disabled: true`. `$getLocales()` nadal zwraca pełną listę dla Twojego kodu, a wbudowane wyjście SEO/meta wyklucza wyłączone locale.
- **Style przełącznika** — `cursor: not-allowed` dotyczy **bieżącego** locale poprzez `activeLinkStyle` / `customActiveLinkStyle`; przywrócono `customDisabledLinkStyle` dla kompatybilności wstecznej i stosuje się go do przycisku przełącznika, gdy bieżące locale ma `disabled: true`.
- **Dev HMR** — zapis, który nie zmienia zawartości pliku (zapis edytora przy utracie fokusu, przepisanie przez formater), nie wywołuje już ponownego scalania. Zmiany locale głównego przebudowują każdą stronę dla tego locale, więc było to kosztowne jak na operację bez efektu.
- **Dev HMR** — strony są ponownie scalane współbieżnie przy zmianie locale głównego zamiast jedna po drugiej.
- **Przejścia stron** — nawigacja w obrębie tego samego locale zachowuje wychodzący fragment jako warstwę zapasową do `page:transition:finish`, zamiast kosztownego głębokiego scalania przy każdej nawigacji.

## Dlaczego to ważne {#why-it-matters}

- Formatowanie w stylu Vue I18n bez dołączania cięższego stosu.
- Przyjazne dla CDN URL-e tłumaczeń, które pozostają stabilne między przebudowami, gdy słownik się nie zmienił.
- Wspierane API runtime do inspekcji i łatania aktywnego słownika — DevTools, testy i edytory nie potrzebują już prywatnych helperów.

Pełny changelog zostanie opublikowany wraz z wydaniem na [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).

## Poprawka: nieskończona pętla przekierowań z `app.baseURL` + `strategy: 'prefix'` (#234) {#fix-infinite-redirect-loop-with-app-baseurl-+-strategy-‘prefix’-#234}

**Data**: 2026-07-03

Serwerowy plugin przekierowań (`06.redirect.ts`) usuwa teraz `runtimeConfig.app.baseURL` z `getRequestURL(event).pathname` przed wykryciem locale. Naprawia `ERR_TOO_MANY_REDIRECTS`, gdy aplikacja jest serwowana pod podścieżką (np. `/examples` → `/examples/ja` jednorazowo, a nie `/examples/ja/examples/ja/...`).
