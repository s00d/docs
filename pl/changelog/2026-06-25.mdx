**Data**: 2026-06-25

**Wersja**: `v3.21.0`

![v3.21.0 release](/images/3.21.0.png)

To wydanie dodaje **`useI18nHead`** — composable na poziomie strony do nadpisywania ustawień SEO i18n, działający na bazie wbudowanego pluginu `02.meta`. Dostosuj `hreflang`, canonical, `og:url` i tagi Open Graph dla każdej trasy bez własnego pluginu meta i bez `meta: false`.

## Co nowego? {#what’s-new}

### Composable `useI18nHead` {#usei18nhead-composable}

Wywołaj `useI18nHead` na dowolnej stronie, gdy `meta: true` (domyślnie). Moduł scala Twoje dane wejściowe po `useLocaleHead` przy każdej aktualizacji trasy:

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

Obsługuje statyczne obiekty, reaktywne gettery, dołączanie `meta` / `link`, `replace` dla wbudowanych grup oraz `disable` do usuwania automatycznie generowanych tagów. Zobacz [`useI18nHead`](/pl/composables/useI18nHead).

### Narzędzie `mergeI18nHead` (`@i18n-micro/utils`) {#mergei18nhead-utility-@i18n-micro/utils}

Niezależna od frameworka logika scalania znajduje się w `@i18n-micro/utils/merge-i18n-head` — jest używana przez plugin `02.meta` i można ją testować w izolacji. Typy (`I18nHeadInput`, `I18nHeadLink`, `I18nHeadMeta`) są eksportowane z `@i18n-micro/types`.

### Integracja z pluginami {#plugin-integration}

- **`02.meta`** — scala wynik `useLocaleHead` ze stanem strony z `useI18nHead` przez `useHead`
- **`01.plugin`** — resetuje nadpisania strony przy zmianie nazwy trasy przez `resetPageHead()` (stan współdzielony z composable)

### Dokumentacja i testy {#documentation-&-tests}

- Nowy przewodnik: [`useI18nHead`](/pl/composables/useI18nHead) z przykładami dla CMS/artykułów
- Zaktualizowane [SEO](/pl/guide/seo) i [`useLocaleHead`](/pl/composables/useLocaleHead) — kiedy używać którego API
- Pokrycie testami Playwright + Vitest: SSR, nawigacja SPA, przeładowanie, `nuxi generate`, częściowe alternatywy, `x-default`, reaktywne ładowanie po stronie klienta

## Typowe przypadki użycia {#typical-use-cases}

| Scenariusz                                   | Podejście                                                      |
| -------------------------------------------- | -------------------------------------------------------------- |
| Blog/CMS z częściowymi tłumaczeniami         | `replace.hreflang` + `replace.ogAlternates` z locale z API     |
| Własny canonical z CMS                       | `replace.canonical` + `replace.ogUrl`                          |
| Tylko OG dla strony docelowej                | `meta: [{ property: 'og:title', ... }]` — zachowaj hreflang modułu |
| Brak hreflang na stronie                     | `disable: ['hreflang', 'x-default']`                           |
| Zastąpienie własnego pluginu (`i18nManualHreflang`) | `useI18nHead` na każdej stronie z treścią + `meta: true` |

**JSON-LD** pozostaje w `useHead({ script: [...] })` — `useI18nHead` nie generuje danych strukturalnych.

## Zmiany niekompatybilne {#breaking-changes}

Brak przy standardowym użyciu `nuxt.config`. Nowy composable i ścieżka podrzędna utils są jedynie dodatkami.

## Dlaczego to ważne {#why-it-matters}

- **Bez własnego pluginu meta** dla wpisów CMS, aktualności czy przewodników z adresami URL dla poszczególnych locale
- **Jeden potok** — domyślne ustawienia modułu + nadpisania strony w jednym wywołaniu `useHead`
- **Bezpieczeństwo typów** — `I18nHeadInput` dla helperów takich jak `buildArticleHead(content)`
