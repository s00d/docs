---
title: "useLocaleHead"
description: "useLocaleHead buduje tagi SEO i18n (lang, dir, canonical, hreflang, og:locale) jako obiekt, który przekazujesz do useHead."
---

`useLocaleHead()` buduje tagi head i18n dla bieżącej trasy: `lang` i `dir` na `<html>`, link canonical, alternatywy `hreflang` z `x-default`, `og:url`, `og:locale` i `og:locale:alternate`. Używaj go, gdy ustawisz [`meta: false`](/pl/api/module-options#meta) i samodzielnie zarządzasz `useHead`; przy `meta: true` moduł sam rejestruje te tagi, a zmiany dla poszczególnych stron przechodzą przez [`useI18nHead`](/pl/composables/useI18nHead).

## Sygnatura {#signature}

```ts
useLocaleHead(options: UseLocaleHeadOptions): { build: () => LocaleHead; metaObject: Ref<{ htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string; [key: string]: string | undefined }; link: ({ href: string; rel: "canonical"; [key: string]: string | undefined } | { href: string; hreflang: string; rel: "alternate"; [key: string]: string | undefined })[]; meta: { content: string; property: string; [key: string]: string }[] }, LocaleHead | { htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string; [key: string]: string | undefined }; link: ({ href: string; rel: "canonical"; [key: string]: string | undefined } | { href: string; hreflang: string; rel: "alternate"; [key: string]: string | undefined })[]; meta: { content: string; property: string; [key: string]: string }[] }>; updateMeta: () => void }
```

Tagi SEO w head dla bieżącej trasy: alternatywy `hreflang` dla każdej lokalizacji plus
`x-default`, link canonical, `og:locale` oraz `lang`/`dir` na `<html>`.

Potrzebne tylko wtedy, gdy `meta` jest wyłączone lub trzeba dostosować wartości domyślne — przy `meta: true`
moduł sam rejestruje te same tagi.

| Parametr | Typ | Opis |
| --- | --- | --- |
| `options` | `UseLocaleHeadOptions` |  |

**Zwraca** — `metaObject`, ref przechowujący obiekt head gotowy do przekazania do `useHead`; `updateMeta` go odświeża; `build` oblicza obiekt head na podstawie bieżącej trasy (reaktywny, gdy jest odczytywany w getterze, np. `useHead(() => build())`)

```ts
const { metaObject } = useLocaleHead({ addSeoAttributes: true })
useHead(metaObject)
```

## Opcje {#options}

| Opcja | Domyślnie | Opis |
| --- | --- | --- |
| `addDirAttribute` | `true` | Ustawia `dir` na `<html>` na podstawie `dir` lokalizacji (`'auto'`, gdy go nie ma). |
| `identifierAttribute` | `'id'` | Atrybut identyfikujący każdy tag (`i18n-can`, `i18n-og`, `i18n-alternate-<hreflang>`, …), dzięki czemu aktualizacje zastępują tagi zamiast je dodawać. |
| `addSeoAttributes` | `true` | Emituje tagi canonical, `hreflang` i `og:`. `false` zachowuje tylko `htmlAttrs`. |
| `baseUrl` | `'/'` | Origin dołączany do każdego URL-a. Zostaw `'/'` dla względnych URL-i; przekaż `'https://example.com'` dla bezwzględnych. |
| `autoUpdate` | `true` | Odbudowuje `metaObject`, gdy zmienia się trasa lub stan `i18n-locale`. |

## Co emituje {#what-it-emits}

- Nic na trasie bez dopasowania (404) lub z `disableMeta` dla aktywnej lokalizacji.
- Canonical i `og:url`: `$switchLocalePath(<active locale>)`, query zredukowane do [`canonicalQueryWhitelist`](/pl/api/module-options#canonicalquerywhitelist), z zastosowanym [`trailingSlash`](/pl/api/module-options#trailingslash).
- `hreflang`: jeden link na każdą włączoną lokalizację, w której strona istnieje, `hreflang = iso || code`, z pominięciem lokalizacji z `seo: false`; przy `hreflangBaseLanguage: true` pierwsza regionalna lokalizacja danego języka emituje również tag samego języka. Brak w trybie `no_prefix`.
- `x-default`: URL domyślnej lokalizacji, chyba że strategią jest `no_prefix`, domyślna lokalizacja ma `seo: false` albo strona w niej nie istnieje.
- `og:locale` / `og:locale:alternate`: z `og` lokalizacji lub z przekonwertowanego `iso` (`en-US` → `en_US`); pomijane z ostrzeżeniem w trybie dev, gdy żadne nie działa.

## Przykład {#example}

```ts
// app.vue, with i18n.meta: false
const { metaObject } = useLocaleHead({ baseUrl: 'https://example.com' })
useHead(metaObject)
```

`build()` zwraca ten sam obiekt bez refa: `useHead(() => build())` pozostaje reaktywne bez watchera.
