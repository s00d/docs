---
title: "useI18nHead"
description: "useI18nHead nadpisuje wygenerowane tagi SEO i18n dla jednej strony: zastąp lub usuń tagi canonical, hreflang i og albo dodaj własne."
---

`useI18nHead()` zmienia tagi SEO generowane przez moduł, tylko dla jednej strony. Używaj go, gdy strona wie lepiej niż router: artykuł z CMS istniejący tylko w niektórych lokalizacjach, canonical URL pochodzący z API, dodatkowe tagi `og:`. Otrzymujesz wygenerowane tagi z nałożonymi na nie Twoimi nadpisaniami.

## Sygnatura {#signature}

```ts
useI18nHead(input?: MaybeRefOrGetter<I18nHeadInput | null>): { pageHead: any; resetPageHead: () => void }
```

Rejestruje nadpisania tagów SEO i18n w head na poziomie strony.
Są one scalane z wynikiem `useLocaleHead` przez plugin `02.meta`.

Preferuj getter (`() => ({ … })`), gdy wartości pochodzą z `$t` / `t`, aby
były ponownie wyliczane po zmianie lokalizacji. Zwykły obiekt jest obliczany raz i pozostaje zamrożony.

| Parametr | Typ | Opis |
| --- | --- | --- |
| `input` *(opcjonalny)* | `MaybeRefOrGetter<I18nHeadInput \| null>` |  |

Działa z [`meta: true`](/pl/api/module-options#meta) (domyślnie): plugin meta modułu scala dane wejściowe z wynikiem [`useLocaleHead`](/pl/composables/useLocaleHead) przy każdym renderowaniu head. Przy `meta: false` nic ich nie odczytuje.

Nadpisanie jest resetowane, gdy zmienia się nazwa trasy. Strona, która ustawia `disableMeta`, nie dostaje żadnych tagów i18n, również nadpisań.

## Dane wejściowe {#input}

`I18nHeadInput` (z `@i18n-micro/types`):

| Klucz | Typ | Efekt |
| --- | --- | --- |
| `htmlAttrs` | `Record<string, string>` | Scalane z atrybutami `<html>` (`lang`, `dir`). |
| `meta` | `I18nHeadMeta[]` | Dodawane po wygenerowanych tagach; zastępuje tag o tym samym `id`, `property` lub `name`. |
| `link` | `I18nHeadLink[]` | Dodawane po wygenerowanych linkach; zastępuje link o tym samym `id` albo `rel` + `hreflang`. |
| `replace.canonical` | `string \| false` | Zastępuje `href` canonical albo usuwa link. |
| `replace.hreflang` | `I18nHeadLink[] \| false` | Zastępuje lub usuwa **wszystkie** linki `rel="alternate"`, łącznie z `x-default`. |
| `replace.xDefault` | `I18nHeadLink \| false` | Zastępuje lub usuwa link `x-default`. |
| `replace.ogLocale` | `string \| false` | Zastępuje lub usuwa `og:locale`. |
| `replace.ogUrl` | `string \| false` | Zastępuje lub usuwa `og:url`. |
| `replace.ogAlternates` | `string[] \| false` | Odbudowuje `og:locale:alternate` z podanych kodów lokalizacji (przez `og` / `iso`), pomijając bieżącą lokalizację, nieznane kody i kody bez wartości `og` lub `iso`, albo je usuwa. |
| `disable` | `I18nHeadDisableGroup[]` | Usuwa wygenerowane grupy: `'hreflang'` (bez `x-default`), `'x-default'`, `'canonical'`, `'og'` (`og:locale` + `og:url`), `'og-alternates'`, `'html'`. |

Kolejność stosowania: `disable`, potem `replace`, potem `htmlAttrs`, `meta`, `link`.

## Przykład {#example}

Artykuł istniejący tylko w niektórych lokalizacjach, z alternatywnymi URL-ami z API:

```vue
<script setup lang="ts">
const route = useRoute()
const { t } = useI18n()
const { data: article } = await useFetch<{ title: string; urls: Record<string, string> }>(`/api/articles/${route.params.slug}`)

useI18nHead(() => {
  if (!article.value) return null
  const codes = Object.keys(article.value.urls)
  return {
    meta: [{ property: 'og:title', content: article.value.title || t('blog.title') }],
    replace: {
      hreflang: codes.map((code) => ({ rel: 'alternate', hreflang: code, href: article.value!.urls[code]! })),
      ogAlternates: codes,
    },
  }
})
</script>
```

Przekazuj getter, jak tutaj, gdy wartości pochodzą z `t()` lub danych asynchronicznych: jest on ponownie uruchamiany po zmianie lokalizacji. Zwykły obiekt jest odczytywany raz.
