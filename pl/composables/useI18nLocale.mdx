---
title: "useI18nLocale"
description: "useI18nLocale odczytuje i zapisuje stan locale oraz ciasteczko locale — punkt wejścia dla niestandardowego wykrywania locale."
---

`useI18nLocale()` daje dostęp do locale wybranego przez aplikację: stanu `i18n-locale` i ciasteczka locale. Używaj go we wtyczce, która samodzielnie wykrywa locale (domena, profil użytkownika, nagłówek), zamiast ręcznie zapisywać `useState('i18n-locale')` lub ciasteczko. Jego sprawdzenia poprawności korzystają z włączonych locale, z uwzględnieniem nadpisań w czasie działania.

## Sygnatura {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Scentralizowany punkt wejścia do zarządzania locale i18n.
Łączy useState('i18n-locale'), ciasteczko locale i narzędzia synchronizacji.

## Zwracane wartości {#returned-values}

| Składowa | Typ | Opis |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | Ref `useState('i18n-locale')`. |
| `localeCookie` | `Ref<string \| null>` | Ciasteczko [`localeCookie`](/pl/api/module-options#localecookie); zwykłe `{ value: null }`, gdy opcja ma wartość `null`. |
| `hashCookie` | `Ref<string \| null>` | Ciasteczko `hash-locale` przy routingu hash; w przeciwnym razie `{ value: null }`. |
| `validLocales` | `string[]` | Kody włączonych locale. |
| `setLocale(locale)` | `(locale: string \| null) => void` | Zapisuje stan i ciasteczka. Nie sprawdza poprawności i nie ładuje tłumaczeń. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | Zapisuje tylko ciasteczka. |
| `getLocale()` | `() => string \| null` | Stan, a następnie ciasteczko preferencji (ciasteczko hash przy routingu hash). Bez sprawdzania poprawności. |
| `getPreferredLocale()` | `() => string \| null` | Pierwsza **poprawna** wartość spośród stanu i ciasteczka preferencji albo `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | Stan przy routingu hash, jeśli jest ustawiony; w przeciwnym razie `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, następnie poprawny stan, następnie `options.serverLocale`, a na końcu locale trasy. Zapisuje wynik w stanie, gdy stan nie jest poprawny; po stronie klienta zapisuje też ciasteczko. |
| `isValidLocale(locale)` | `(locale) => locale is string` | Czy `locale` znajduje się w `validLocales`. |

Ciasteczka są ważne przez rok, z `path: '/'` i `sameSite: 'lax'`.

## Przykład {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

Wtyczka ładująca modułu odczytuje stan przy starcie, więc wtyczka, która go ustawia, musi uruchomić się wcześniej (`enforce: 'pre'`). Jak stan konkuruje z adresem URL, ciasteczkiem i `Accept-Language`: [Wykrywanie locale](/pl/guide/locale-detection). Pełny przewodnik: [Niestandardowe wykrywanie](/pl/guide/custom-auto-detect).

`setLocale()` nie przełącza tłumaczeń widocznych na ekranie. Aby zmienić locale bieżącej strony, wywołaj [`$switchLocale()`](/pl/api/methods#$switchlocale).
