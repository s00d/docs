# Referensi Opsi Modul

Setiap opsi yang diterima `nuxt-i18n-micro`, dibaca saat build dari interface `ModuleOptions`
di
[`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).
Tidak ada yang ditulis manual di sini, sehingga tidak akan tertinggal dari kode — tipe, default, dan
deskripsi berasal dari deklarasi itu sendiri.

Untuk *arti* opsi ini ketika digunakan bersama — kombinasi mana yang masuk akal, apa yang berubah saat
Anda beralih strategi, contoh yang dikerjakan — baca [Konfigurasi](/guides/configuration). Halaman ini
adalah daftar yang menyeluruh; halaman itu adalah penjelasannya.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Opsi bersarang muncul di bawah jalur bertanda titik, jadi `translationPayloads.mode` adalah
kunci `mode` di dalam objek `translationPayloads`.

## Lokal dan perutean

Bahasa apa saja yang ada dan bagaimana mereka muncul di URL.

| Opsi | Tipe | Default | Deskripsi |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Daftar lokal yang didukung. Setiap entri mendefinisikan kode lokal ditambah metadata opsional (ISO, arah, nama tampilan, dll.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Strategi perutean URL untuk awalan lokal. - `'no_prefix'` — tidak ada lokal di URL; lokal disimpan dalam cookie. - `'prefix_except_default'` — beri awalan pada semua lokal kecuali default. - `'prefix'` — selalu beri awalan, termasuk lokal default. - `'prefix_and_default'` — seperti `prefix`, tetapi lokal default juga dapat diakses tanpa awalan. |
| `defaultLocale` | `string` | `'en'` | Lokal yang digunakan saat lokal tidak dapat ditentukan dari URL atau preferensi pengguna. Juga digunakan sebagai lokal fallback untuk terjemahan yang hilang saat `fallbackLocale` tidak disetel. |
| `localeCookie` | `string \| null` | `null` | Nama cookie untuk mempertahankan preferensi lokal pengguna di seluruh sesi. Setel ke `null` untuk menonaktifkan persistensi berbasis cookie. Otomatis disetel ke `'user-locale'` untuk strategi `no_prefix` jika tidak diberikan. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Konfigurasi lokal tingkat rute global. Memungkinkan pembatasan atau penyesuaian rute lokal untuk halaman tertentu tanpa memodifikasi komponennya. - `false` — kecualikan rute dari lokalisasi. - `Record<LocaleCode, string>` — jalur kustom per lokal. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (menggunakan pola bawaan berdasarkan kode lokal)` | Ekspresi reguler kustom (atau string sumbernya) untuk mencocokkan kode lokal pada segmen URL. Semua kode lokal yang didefinisikan pada `locales` harus cocok dengan pola ini, atau peringatan dikeluarkan. |
| `noPrefixRedirect` | `boolean` | `false` | Untuk strategi `no_prefix`: aktifkan pengalihan dari URL dengan awalan lokal (mis. `/en/about`) ke versi tanpa awalan (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Pola URL (string atau RegExp) yang dikecualikan dari pemrosesan i18n sepenuhnya. Rute yang cocok tidak akan mendapat awalan lokal, pengalihan, atau pemuatan terjemahan. Jalur internal Nuxt (`/__nuxt_error`, dll.) selalu dikecualikan otomatis. |
| `routeLocales` | `Record<string, string[]>` | — | Pembatasan lokal per rute, diekstrak dari panggilan `defineI18nRoute()`. Memetakan jalur rute (mis. `'/about'`) ke array kode lokal yang diizinkan. Rute yang tidak terdaftar tidak memiliki pembatasan (semua lokal diizinkan). |

## Terjemahan

Di mana file terjemahan berada dan bagaimana kunci diselesaikan.

| Opsi | Tipe | Default | Deskripsi |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Jalur ke direktori yang berisi file JSON terjemahan, relatif terhadap root proyek. |
| `disableWatcher` | `boolean` | `false` | Menonaktifkan pengawas file yang secara otomatis membuat file terjemahan yang hilang pada mode development. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Memetakan nama rute ke nama rute lain untuk berbagi file terjemahan yang sama. Sebagai contoh, `\{ 'about-us': 'about' \}` berarti halaman `about-us` akan menggunakan terjemahan dari halaman `about` alih-alih miliknya sendiri. |
| `plural` | `PluralFunc` | `pluralisasi bawaan (indeks bentuk berdasarkan hitungan)` | Fungsi pluralisasi kustom. Menerima `(key, count, params, locale, getter)` dan harus mengembalikan bentuk plural yang dipilih sebagai string, atau `null`/`undefined` untuk jatuh kembali ke logika `defaultPlural` bawaan (sehingga Anda dapat menimpa hanya beberapa lokal). Untuk modul Nuxt, fungsi diserialisasi dengan `.toString()` ke `.nuxt/i18n.plural.mjs` — harus mandiri (tanpa impor / lingkup luar). String jalur file **tidak** didukung. |
| `disablePageLocales` | `boolean` | `false` | Menonaktifkan file terjemahan per halaman. Saat `true`, hanya terjemahan global (`\{locale\}.json`) yang dimuat; file per halaman (`pages/\{page\}/\{locale\}.json`) tidak dibuat atau dimuat. |
| `fallbackLocale` | `string` | `undefined (tanpa fallback; mengembalikan kunci mentah)` | Kode lokal fallback global. Saat kunci terjemahan hilang pada lokal aktif, modul mencarinya pada lokal ini sebelum mengembalikan kunci itu sendiri. |

## Payload dan caching

Bagaimana terjemahan mencapai peramban. [Performa](/guides/performance) menjelaskan apa yang mereka ubah pada runtime.

| Opsi | Tipe | Default | Deskripsi |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Memuat awal terjemahan halaman index pada middleware global Nitro (khusus server, konfigurasi privat). |
| `apiBaseUrl` | `string` | `'_locales'` | Segmen jalur URL dasar untuk rute API terjemahan (digunakan pada pengambilan data SSR/SSG). Dapat juga disetel melalui variabel lingkungan `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Menimpa host yang digunakan untuk permintaan pengambilan terjemahan sisi klien. Berguna saat klien mencapai server melalui hostname yang berbeda dari yang dilihat Nuxt. Dapat juga disetel melalui variabel lingkungan `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Menimpa host yang digunakan untuk permintaan pengambilan terjemahan sisi server. Berguna pada pengaturan container/microservice di mana server mencapai dirinya sendiri melalui hostname internal. Dapat juga disetel melalui variabel lingkungan `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Mengontrol bagaimana payload terjemahan dikeluarkan (Node: `public/<apiBaseUrl>`; Edge: `serverAssets` Nitro). - **Node**: `serverAssets` berarti SSR lokal melalui `readFile` di bawah `public/` (tanpa Rollup `raw:`). - **Edge**: `serverAssets` mendaftarkan `serverAssets` Nitro (`assets:i18n`); tidak memaksa salinan publik. Pertahankan default untuk pengaturan all-in-one biasa. Untuk katalog Edge besar, sebaiknya `mode: 'source'`. Untuk penerapan berbasis CDN, nonaktifkan output lokal dan setel `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Strategi payload terjemahan. - `premerged`: matriks `\{page\}/\{locale\}/data.json` saat build (default) - `source`: file sumber ringkas yang digabungkan pada runtime (sebaiknya pada Edge / katalog besar) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Payload SSR lokal: Node membaca `public/<apiBaseUrl>` (memaksa salinan publik); Edge menyematkan melalui `serverAssets` Nitro. - **Node**: tanpa `serverAssets` Nitro (menghindari Rollup `raw:`). SSR membaca   `public/<apiBaseUrl\|publicDir>` sebagai `\{page\}/\{locale\}/data.json`; saat ini `true`,   salinan publik dipaksa meskipun `publicAssets` false. - **Edge** (`nitro.node === false`): `serverAssets` Nitro (`assets:i18n`) dengan tata letak yang sama dengan `mode`. **Tidak** memaksa salinan publik — setel `publicAssets: true` untuk CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Mendaftarkan rute server bawaan pada `/\{apiBaseUrl\}/:page/:locale/data.json`. Nonaktifkan saat payload terjemahan disajikan dari host/CDN eksternal. |
| `translationPayloads.publicAssets` | `boolean` | `true pada mode premerged, false pada mode source` | Menyalin payload ke output publik Nitro. Premerged → `\{page\}/\{locale\}/data.json` di bawah `apiBaseUrl`; source → pohon ringkas. Pada Node, pohon ini juga menjadi sumber SSR saat `serverAssets` memaksa salinan publik. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Ikut serta dalam prerender Nitro `/\{apiBaseUrl\}/.../data.json`. Biasanya redundan saat premerged `publicAssets` sudah menulis file-file tersebut. |
| `translationPayloads.publicDir` | `string` | — | Folder output publik relatif terhadap root publik Nitro. Default ke `apiBaseUrl` (`_locales`). Sehingga file statis cocok dengan URL pengambilan klien (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Beri peringatan saat build ketika jumlah file payload yang dihasilkan melebihi ambang batas ini. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Beri peringatan saat build ketika total ukuran payload yang dihasilkan melebihi ambang batas ini dalam byte. |

## SEO

Tag meta yang dihasilkan untuk setiap halaman yang terlokalisasi.

| Opsi | Tipe | Default | Deskripsi |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Menghasilkan tag meta SEO (`hreflang`, `canonical`, `og:url`, `og:locale`) secara otomatis. |
| `metaBaseUrl` | `string` | `undefined` | URL dasar untuk tag meta SEO (canonical, og:url, hreflang). - String URL konkret (mis. `'https://example.com'`) — digunakan sebagaimana adanya (prioritas tertinggi). - `undefined` — jatuh kembali ke `site.url` dari `nuxt-site-config` saat modul itu   hadir, jika tidak, ke origin permintaan saat ini   (`useRequestURL().origin` di server, `window.location.origin` di klien). |
| `metaTrustForwardedHost` | `boolean` | `true` | Mempercayai header `X-Forwarded-Host` saat menyelesaikan URL dasar untuk tag meta. Aktifkan saat aplikasi berjalan di belakang reverse proxy (nginx, Cloudflare, AWS ALB, dll.) yang menyetel header ini ke hostname yang menghadap klien nyata. |
| `metaTrustForwardedProto` | `boolean` | `true` | Mempercayai header `X-Forwarded-Proto` saat menyelesaikan protokol untuk tag meta. Aktifkan saat aplikasi berjalan di belakang proxy yang menghentikan TLS sehingga URL canonical menggunakan `https://` meskipun aplikasi sendiri mendengarkan di HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Daftar nama parameter query yang dipertahankan pada tag meta canonical dan `og:url`. Parameter yang tidak ada di daftar ini dihapus dari URL canonical. |

## Deteksi dan pengalihan

Memilih lokal untuk pengunjung yang belum memilih.

| Opsi | Tipe | Default | Deskripsi |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Mengaktifkan pengalihan otomatis berbasis lokal. Saat `true`, pengunjung dialihkan ke lokal yang mereka sukai (dideteksi dari cookie, header `Accept-Language`, atau default) pada kunjungan pertama. |
| `autoDetectLanguage` | `boolean` | `true` | Secara otomatis mendeteksi bahasa yang disukai pengguna dari header HTTP `Accept-Language`. Digunakan bersama `autoDetectPath` untuk memutuskan kapan deteksi terjadi. |
| `autoDetectPath` | `string` | `'/'` | Di mana pengalihan preferensi cookie / Accept-Language dapat berjalan (saat `redirects` diaktifkan). - `'/'` — hanya `/` (tautan langsung pada lokal default tetap dapat dijangkau; default) - `'no_prefix'` — hanya jalur tanpa awalan lokal - `'*'` — setiap jalur, termasuk menulis ulang awalan lokal eksplisit   (mis. `/fr/about` → `/de/about` ketika cookie memilih `de`) - string lain apa pun — pencocokan jalur persis (mis. `'/welcome'`) Pembersihan strategi dengan awalan (mis. `/en` → `/` di bawah `prefix_except_default`) tidak dibatasi. |
