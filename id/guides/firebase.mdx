# 🔥 Deployment Firebase AppHosting

## 📖 Pendahuluan

Firebase AppHosting adalah platform yang kuat untuk men-deploy aplikasi Nuxt dengan infrastruktur serverless. Namun, saat men-deploy aplikasi dengan `nuxt-i18n-micro`, Anda mungkin menemui masalah tertentu terkait cara file JSON terjemahan disajikan. Panduan ini menyediakan solusi komprehensif untuk memastikan terjemahan Anda bekerja dengan benar di produksi.

## ⚠️ Masalah Umum

### File Terjemahan Tidak Diterapkan

**Gejala:**

- ✅ Terjemahan bekerja sempurna saat development (`nuxt dev`)
- ❌ Setelah deployment ke Firebase AppHosting, file JSON dimuat tetapi terjemahan tidak diterapkan
- ❌ Tidak ada kesalahan yang muncul di konsol
- ❌ File terjemahan terlihat di tab Network tetapi memiliki `Content-Type: text/html` yang salah alih-alih `application/json`

**Akar Penyebab:**

Firebase AppHosting (dan platform lain yang menggunakan prerendering Nitro) mungkin menyajikan file JSON yang di-prerender dengan tipe MIME yang salah. Saat peramban menerima file JSON dengan `Content-Type: text/html`, peramban tidak dapat mem-parsingnya dengan benar, menyebabkan terjemahan gagal secara diam-diam.

## ✅ Solusi

### Solusi 1: Konfigurasi Route Rules (Direkomendasikan)

Solusi paling langsung adalah menambahkan header eksplisit untuk rute terjemahan pada `nuxt.config.ts`:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**Manfaat:**

- ✨ Konfigurasi sederhana
- 🚀 Meningkatkan performa dengan caching yang tepat
- 🔒 Bekerja di semua platform deployment

### Solusi 2: URL Dasar API Kustom

Jika Anda menggunakan `apiBaseUrl` kustom (hanya awalan jalur), sesuaikan route rules-nya:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### Solusi 3: Konfigurasi Khusus Firebase

Buat atau perbarui file `firebase.json` di root proyek Anda:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```

### Solusi 4: Konfigurasi Firebase Functions

Untuk deployment Firebase Functions, pastikan `functions/package.json` Anda menyertakan dependensi yang diperlukan:

```json
{
  "name": "functions",

    "node": "18"
```

## 🔍 Debugging

### Aktifkan Mode Debug

Tambahkan logging debug untuk mengidentifikasi masalah:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

Ini akan menampilkan log detail tentang:

- 📝 Pemuatan file terjemahan
- 🔄 Operasi cache
- ⚠️ Kesalahan pemuatan

### Periksa Tab Network

1. Buka DevTools → tab Network
2. Filter berdasarkan "data.json"
3. Klik permintaan file terjemahan
4. Verifikasi **Response Headers**:
   - ✅ `Content-Type: application/json` (benar)
   - ❌ `Content-Type: text/html` (salah - perlu diperbaiki)

### Verifikasi Output Prerender

Setelah build, periksa bahwa file terjemahan dihasilkan:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

Anda seharusnya melihat `data.json` untuk setiap lokal di bawah setiap halaman.

## 🚀 Konfigurasi Build

### Nitro Preset

Untuk Firebase AppHosting, pastikan Anda menggunakan preset yang benar:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### Konfigurasi Prerender

Konfigurasikan prerendering untuk performa optimal:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

## ✅ Daftar Periksa Verifikasi

Setelah menerapkan perbaikan, verifikasi semuanya berfungsi:

- [ ] Build selesai tanpa kesalahan
- [ ] File JSON terjemahan berada di `.output/public/_locales/\{page\}/\{locale\}/data.json`
- [ ] Tab Network menunjukkan `Content-Type: application/json` untuk file terjemahan
- [ ] Terjemahan ditampilkan dengan benar pada pemuatan halaman pertama
- [ ] Tidak ada hydration mismatch di konsol
- [ ] Peralihan bahasa bekerja dengan benar
- [ ] Tag meta SEO dihasilkan dengan baik

## 🔄 Alur Kerja Deployment

### 1. Persiapkan Build

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. Deploy ke Firebase

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. Verifikasi Deployment

1. Kunjungi situs yang di-deploy
2. Buka DevTools → tab Network
3. Bernavigasi ke halaman
4. Periksa bahwa `/_locales/index/en/data.json` (atau lokal default Anda) dimuat dengan:
   - Status: 200
   - Content-Type: application/json
   - Respons berisi JSON yang valid

## 🔧 Pemecahan Masalah

### Masalah: Kesalahan 404 untuk File Terjemahan

**Solusi:** Pastikan file terjemahan sedang disalin ke direktori output:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### Masalah: Terjemahan Bekerja di Beberapa Halaman Tetapi Tidak di Halaman Lain

**Solusi:** Periksa apakah terjemahan per halaman dihasilkan:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

Jika terjemahan per halaman hilang, pastikan `disablePageLocales` tidak disetel ke `true`:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### Masalah: Pemuatan Terjemahan Lambat

**Solusi:** Optimalkan caching dan preloading:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## 💡 Tips

1. **Selalu uji di lingkungan yang mirip produksi** sebelum melakukan deployment
2. **Gunakan mode debug** selama pengaturan awal untuk mendeteksi masalah lebih awal
3. **Pantau rasio cache hit** untuk mengoptimalkan performa
4. **Jaga ukuran file terjemahan tetap kecil** untuk pemuatan lebih cepat
5. **Gunakan header cache yang tepat** untuk mengurangi beban server

## ⚡ Optimalisasi Performa

### Aktifkan Kompresi

Firebase secara otomatis menangani kompresi Gzip/Brotli, tetapi pastikan build Anda dioptimalkan:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### Lazy Load Terjemahan

`Nuxt I18n Micro` secara otomatis me-lazy-load terjemahan per halaman. Terjemahan hanya dimuat saat dibutuhkan, mengurangi ukuran bundle awal. Ini adalah fungsionalitas bawaan - tidak diperlukan konfigurasi tambahan.

Untuk mengoptimalkan lebih lanjut:

- Gunakan `disablePageLocales: false` (default) untuk mengaktifkan terjemahan per halaman
- Jaga terjemahan tingkat root tetap minimal
- Gunakan file terjemahan khusus rute untuk konten halaman

<Tip>
Modul secara otomatis mengatur header `Content-Type` yang tepat mulai dari versi **v3.0.0+**. Jika Anda mengalami masalah, update ke versi terbaru:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
