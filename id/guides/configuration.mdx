# Option details

The module menyediakan extensive configuration options to customize your internationalization setup.

### 🌍 Core Locale Settings

#### `locales`

{/* generated:option:locales — do not edit; run `pnpm run docs:generate` */}

**Tipe** `Locale[]` · **Default** `[]`

List of supported locales.
Setiap entri defines a locale code plus optional metadata (ISO, direction, display name, etc.).

{/* /generated:option:locales */}

Setiap lokal object supports:

| Property         | Type      | Required | Description                                           |
| ---------------- | --------- | -------- | ----------------------------------------------------- |
| `code`           | `string`  | ✅       | Unique identifier (e.g., `'en'`)                      |
| `displayName`    | `string`  | ❌       | Human-readable name untuk switchers (e.g., `'English'`) |
| `iso`            | `string`  | ❌       | ISO code (e.g., `'en-US'`)                            |
| `dir`            | `string`  | ❌       | Text direction (`'ltr'` atau `'rtl'`)                   |
| `disabled`       | `boolean` | ❌       | Disable in dropdown if `true`                         |
| `baseUrl`        | `string`  | ❌       | Base URL untuk locale-specific domains                  |
| `baseDefault`    | `boolean` | ❌       | Remove locale prefix dari URLs                        |
| `fallbackLocale` | `string`  | ❌       | Per-locale fallback (overrides global)                |
| `[key: string]`  | `unknown` | ❌       | Any custom properties (see below)                     |

**Contoh**:

```typescript
locales: [
  { code: 'en', iso: 'en-US', dir: 'ltr' },
  { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
  { code: 'ar', iso: 'ar-SA', dir: 'rtl', disabled: true },
  {
    code: 'de',
    iso: 'de-DE',
    dir: 'ltr',
    baseUrl: 'https://de.example.com',
    baseDefault: true,
  },
]
```

<Warning>
Using `baseUrl` can lead to duplication of internal routes as external links, complicating routing dan maintenance. Consider creating external links directly untuk specific locales instead.
</Warning>

#### Custom Locale Properties

Anda dapat add any custom properties to locale objects. They are passed through ke runtime dan accessible via `$getLocales()`:

```typescript
locales: [
  { code: 'en', iso: 'en-US', flag: '🇬🇧', currency: 'GBP' },
  { code: 'de', iso: 'de-DE', flag: '🇩🇪', currency: 'EUR' },
  { code: 'ru', iso: 'ru-RU', flag: '🇷🇺', currency: 'RUB' },
]
```

Access them in components:

```vue
<template>
  <ul>
    <li v-for="locale in $getLocales()" :key="locale.code">{{ locale.flag }} {{ locale.displayName }} ({{ locale.currency }})</li>
  </ul>
</template>
```

Secara default, custom properties are typed as `unknown`. To get full TypeScript support, use **module augmentation**. Create a declaration file (e.g., `app/i18n.d.ts` atau any `.d.ts` included in your `tsconfig`):

```typescript
// app/i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
    currency?: string
  }
}
```

After this, all custom properties are fully typed:

```typescript
const locales = $getLocales()
locales[0].flag // string | undefined ✅
locales[0].currency // string | undefined ✅
```

### 📂 Translation Management
#### `translationDir`

{/* generated:option:translationDir — do not edit; run `pnpm run docs:generate` */}

**Tipe** `string` · **Default** `'locales'`

Path ke directory containing translation JSON files, relative ke project root.

{/* /generated:option:translationDir */}

```typescript
translationDir: 'i18n' // Custom directory
// Nuxt 4 colocation example:
// translationDir: 'app/locales'
```

Paths are resolved dari the Nuxt **project root** (`rootDir`), not dari `app/`. With Nuxt 4, the usual setup is `app/pages/` untuk routes dan `locales/` (or `app/locales` if you set `translationDir`) untuk JSON files.
#### `disablePageLocales`

{/* generated:option:disablePageLocales — do not edit; run `pnpm run docs:generate` */}

**Tipe** `boolean` · **Default** `false`

Disable per-page translation files.
When `true`, only global translations (`\{locale\}.json`) are loaded;
page-specific files (`pages/\{page\}/\{locale\}.json`) are not generated atau loaded.

{/* /generated:option:disablePageLocales */}

When enabled, only root-level translation files are used:

```tree
locales/
├── en.json
├── fr.json
└── ar.json
```
#### `fallbackLocale`

{/* generated:option:fallbackLocale — do not edit; run `pnpm run docs:generate` */}

**Tipe** `string` · **Default** `undefined (no fallback; mengembalikan the raw key)`

Global fallback locale code.
Saat sebuah translation key is missing di active locale, the module looks it up
in this locale before returning the key itself.

{/* /generated:option:fallbackLocale */}

```typescript
fallbackLocale: 'en' // Global fallback
```
#### `types`

{/* generated:option:types — do not edit; run `pnpm run docs:generate` */}

**Tipe** `boolean` · **Default** `true`

Generate TypeScript type declarations untuk `useI18n`, `$t`, dan related helpers
based on the translation keys in your default locale files.

{/* /generated:option:types */}

When enabled, the module emits `.nuxt/i18n.d.ts` during build dengan typed translation keys. Set to `false` if you prefer untyped helpers atau use an external generator.

This built-in generator is separate dari the optional [`@i18n-micro/types-generator`](/integrations/types-generator) package, which can produce stricter atau standalone type files untuk monorepos dan CI.

```typescript
types: false // Disable built-in key typing
```
#### `routeLocales`

{/* generated:option:routeLocales — do not edit; run `pnpm run docs:generate` */}

**Tipe** `Record<string, string[]>` · **Default** —

Per-route locale restrictions, extracted dari `defineI18nRoute()` calls.
Maps a route path (e.g. `'/about'`) to an array of allowed locale codes.
Routes not listed have no restrictions (all locales allowed).

{/* /generated:option:routeLocales */}

Maps a route path (e.g. `'/about'`) to allowed locale codes. Routes not listed allow all configured locales.

You normally configure this via [`defineI18nRoute`](/guides/custom-locale-routes) in pages rather than in `nuxt.config`. The module merges page-level declarations into this map at build time.
#### `routeDisableMeta`

{/* generated:option:routeDisableMeta — do not edit; run `pnpm run docs:generate` */}

**Tipe** `Record<string, boolean \| string[]>` · **Default** —

Per-route meta tag disabling, extracted dari `defineI18nRoute()` calls.
Maps a route path to `true` (disable all meta) atau an array of locale codes
for which meta harus disabled.

{/* /generated:option:routeDisableMeta */}

- `true` — disable all SEO meta untuk the route
- `string[]` — disable meta only untuk listed locale codes

Like `routeLocales`, this is typically set in page components, not manually in config.
#### `experimental`

{/* generated:option:experimental — do not edit; run `pnpm run docs:generate` */}

**Tipe** `Record<string, unknown>` · **Default** —

Bucket untuk experimental/unstable options.
Contents may change atau be removed tanpa notice between minor versions.

{/* /generated:option:experimental */}

Most former `experimental.*` flags were promoted to top-level options in v3 (for example `hmr`). Prefer documented top-level options. Use `experimental` only when following a release note atau migration guide that references a specific key.

**Tipe** `boolean` · **Default** `true`

{/* /generated:option:meta */}

```typescript
meta: true // Generate alternate links, canonical URLs, etc.
```
#### `metaBaseUrl`

{/* generated:option:metaBaseUrl — do not edit; run `pnpm run docs:generate` */}

**Tipe** `string` · **Default** `undefined`

Base URL untuk SEO meta tags (canonical, og:url, hreflang).

- A concrete URL string (e.g. `'https://example.com'`) — used as-is (highest priority).
- `undefined` — falls back to `site.url` dari `nuxt-site-config` when that module is
  present, otherwise the current request origin
  (`useRequestURL().origin` on server, `window.location.origin` on client).

{/* /generated:option:metaBaseUrl */}

Priority when unset: `site.url` dari `nuxt-site-config` (if installed) → request origin
(`useRequestURL().origin` on the server dengan `X-Forwarded-Host` / `X-Forwarded-Proto`,
`window.location.origin` on the client). Ideal untuk **SEO stacks** that already set `site.url`,
and untuk **multi-domain** deployments when `site.url` is omitted.

- Any other string — used as a static base URL (wins over `site.url`).

```typescript
// Prefer sharing the SEO stack origin — omit metaBaseUrl when site.url is set
site: { url: 'https://example.com' }

// Or pin an explicit override
metaBaseUrl: 'https://example.com'
```

### 🔄 Advanced Features
#### `globalLocaleRoutes`

{/* generated:option:globalLocaleRoutes — do not edit; run `pnpm run docs:generate` */}

**Tipe** `GlobalLocaleRoutes` · **Default** `\{\}`

Global route-level locale configuration.
Allows restricting atau customizing locale routes untuk specific pages without

- `false` — exclude the route dari localization.

{/* /generated:option:globalLocaleRoutes */}

</Tip>

#### `routesLocaleLinks`

{/* generated:option:routesLocaleLinks — do not edit; run `pnpm run docs:generate` */}

**Tipe** `\{ [key: string]: string \}` · **Default** `\{\}`

Map route names to other route names to share the same translation files.
Sebagai contoh, `\{ 'about-us': 'about' \}` means the `about-us` page will use
translations dari the `about` page instead of its own.

{/* /generated:option:routesLocaleLinks */}

```typescript

  'products-id': 'products',
  'about-us': 'about'
}
```
#### `customRegexMatcher`

{/* generated:option:customRegexMatcher — do not edit; run `pnpm run docs:generate` */}

**Tipe** `string \| RegExp` · **Default** `undefined (uses built-in pattern based on locale codes)`

Custom regular expression (or its string source) untuk matching locale codes in URL segments.
All locale codes defined in `locales` must match this pattern, atau a warning is emitted.

{/* /generated:option:customRegexMatcher */}

<Danger>
At build time, the module **validates** that every locale code in your `locales` list matches the `customRegexMatcher` pattern. If any locale code does not match, **the build will fail** dengan the error:

> `Nuxt-i18n-micro: Some locale codes does not match customRegexMatcher`

Always verify your regex against all your locale codes before deploying.
</Danger>

```typescript
// ✅ Correct: matches 'en-us', 'de-de', 'fr-fr'
customRegexMatcher: '[a-z]{2}-[a-z]{2}'

// ✅ Correct: matches 'en', 'de', 'fr', 'zh'
customRegexMatcher: '[a-z]{2}'

// ❌ Wrong: won't match 'zh-Hant' (uppercase letter)
// This will FAIL the build if 'zh-Hant' is in your locales list
customRegexMatcher: '[a-z]{2}-[a-z]{2}'
```

### 🔢 Customization
#### `plural`

{/* generated:option:plural — do not edit; run `pnpm run docs:generate` */}

**Tipe** `PluralFunc` · **Default** `built-in pluralization (form index by count)`

Custom pluralization function.
Receives `(key, count, params, locale, getter)` dan should return the selected
plural form as a string, atau `null`/`undefined` to fall back ke built-in
`defaultPlural` logic (so you can override only some locales).

For the Nuxt module the function is serialized dengan `.toString()` into
`.nuxt/i18n.plural.mjs` — it harus self-contained (no imports / outer scope).
A file path string is **not** supported.

{/* /generated:option:plural */}

##### Cara kerjanya

Translations use `|` to separate plural forms:

```json
{
  "apples": "no apples | one apple | {count} apples"
}
```

Use `$tc('apples', count)` atau `$tc('cart', \{ count, name \})` when a form needs more than `\{count\}` — pass **`count` dan other params di second argument object**, not as a third argument (third is `defaultValue` only).

The `$tc` call invokes the `plural` function, which:

1. Calls `t(key)` to get the raw translation string (e.g. `"no apples | one apple | \{count\} apples"`)
2. Splits by `|` to get the forms array
3. Selects a form based on `count`
4. Replaces `\{count\}` dengan the actual number

The **default** implementation selects by index: `count < forms.length ? forms[count] : forms[last]`. This works untuk simple cases (0 → first form, 1 → second, 2+ → last).

##### Custom plural function

For languages dengan complex pluralization rules (e.g., Russian, Arabic, Polish), override the `plural` option.

<Danger>
The function is serialized via `.toString()` dan injected into a virtual module at build time. Ini berarti:

- **Must use `function` keyword** — NOT shorthand method syntax, NOT arrow functions dengan external references
- **No imports atau external references** — the function harus fully self-contained (a file path like `plural: '~/i18n/plural.ts'` is **not** supported)
- **No TypeScript-only syntax** that doesn't survive `.toString()` (type annotations are fine in `nuxt.config.ts` because Nuxt strips them)
- Returning `null` / `undefined` falls back ke built-in `defaultPlural` (useful untuk per-locale overrides)
</Danger>

**Example: Russian pluralization** (4 forms: zero, one, few, many):

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    plural: function (key, count, _params, _locale, t) {
      const translation = t(key)
      if (!translation) return key

      const forms = translation
        .toString()
        .split('|')
        .map(function (s) {
          return s.trim()
        })
      let idx

      if (count === 0) {
        idx = 0
      } else {
        const mod10 = count % 10
        const mod100 = count % 100
        if (mod10 === 1 && mod100 !== 11) {
          idx = 1
        } else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) {
          idx = 2
        } else {
          idx = 3
        }
      }

      if (idx >= forms.length) idx = forms.length - 1
      return (forms[idx] || '').replace('{count}', String(count))
    },
  },
})
```

With this translation:

```json
{
  "apples": "нет яблок | {count} яблоко | {count} яблока | {count} яблок"
}
```

Results:

- `$tc('apples', 0)` → `"нет яблок"`
- `$tc('apples', 1)` → `"1 яблоко"`
- `$tc('apples', 3)` → `"3 яблока"`
- `$tc('apples', 5)` → `"5 яблок"`
- `$tc('apples', 21)` → `"21 яблоко"`

**Example: Simple English (default behavior)**:

```typescript
// This is the built-in default — you don't need to set it explicitly
plural: function (key, count, params, _locale, t) {
  const translation = t(key, params)
  if (!translation) return null

  const forms = translation.toString().split('|')
  if (forms.length === 0) return null
  const form = count < forms.length ? forms[count] : forms[forms.length - 1]
  if (!form) return null
  return form.trim().replace('{count}', count.toString())
}
```

##### Per-locale pluralization

If different locales need different plural rules, branch on `locale` dan return `null`
for locales you do not customize — the built-in `defaultPlural` menangani the rest:

```typescript
plural: function (key, count, _params, locale, t) {
  // Only override Slavic locales; en/de/… keep the built-in rules
  if (locale !== 'ru' && locale !== 'uk') return null

  const translation = t(key)
  if (!translation) return null

  const forms = translation.toString().split('|').map(function (s) { return s.trim() })
  let idx
  if (count === 0) {
    idx = 0
  } else {
    const mod10 = count % 10
    const mod100 = count % 100
    if (mod10 === 1 && mod100 !== 11) idx = 1
    else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) idx = 2
    else idx = 3
  }
  if (idx >= forms.length) idx = forms.length - 1
  return (forms[idx] || '').replace('{count}', String(count))
}
```

<Warning>
`plural: '~/i18n/plural.ts'` (or any string path) is **not** supported. The Nuxt module
serializes the function dengan `.toString()` into a virtual file; external imports and
helpers dari another module are stripped dan akan `undefined` at runtime. Keep the
function fully inlined in `nuxt.config.ts` (see the danger note above).
</Warning>

#### `translationPayloads`

{/* generated:option:translationPayloads — do not edit; run `pnpm run docs:generate` */}

**Tipe** `TranslationPayloadOptions` · **Default** —

Controls how translation payloads are emitted (Node: `public/<apiBaseUrl>`; Edge: Nitro `serverAssets`).

- **Node**: `serverAssets` means local SSR via `readFile` under `public/` (no Rollup `raw:`).
- **Edge**: `serverAssets` registers Nitro `serverAssets` (`assets:i18n`); it does not force a public copy.

Keep the defaults untuk the usual all-in-one setup. For large Edge catalogs prefer `mode: 'source'`.
For CDN-backed deployments, disable local outputs dan set `apiBaseClientHost` / `apiBaseServerHost`.

{/* /generated:option:translationPayloads */}

```typescript
{
  mode?: 'premerged' | 'source'
  serverAssets?: boolean
  serverHandler?: boolean
  publicAssets?: boolean
  prerenderRoutes?: boolean
  publicDir?: string
  warnFileCount?: number
  warnSizeBytes?: number
}
```

**Default** (`mode: 'premerged'`):

```typescript
{
  mode: 'premerged',
  serverAssets: true,
  serverHandler: true,
  publicAssets: true,
  prerenderRoutes: false
}
```

SSR on **Node** reads the same tree copied to `public/<apiBaseUrl>/` (`readFile`). On **Edge**, Nitro `serverAssets` embeds it (no forced public copy — set `publicAssets: true` untuk CDN). `mode: 'premerged'` → `\{page\}/\{locale\}/data.json` per page/locale; `mode: 'source'` → compact source + runtime merge.

`serverAssets: true` on **Node** forces the public copy even if `publicAssets` is false. On **Edge** it only registers the Nitro embed. Prefer `mode: 'source'` on Edge untuk large catalogs. Without local payloads dan tanpa `apiBaseServerHost`, the build fails.

The local `/\{apiBaseUrl\}/:page/:locale/data.json` handler, prerender routes, dan public asset copies remain optional outputs.

For compact **public** / Edge payloads:

```typescript
i18n: {
  translationPayloads: {
    mode: 'source',
  },
}
```

`mode: 'source'` keeps layer files compact dan merges root/page/fallback at runtime through the built-in `/_locales` route (or Edge `assets:i18n`). Secara default it disables public asset copies dan prerendered payload routes.

<Warning>
With `mode: 'source'`, `publicAssets` defaults to `false` (`prerenderRoutes` adalahlways off unless you opt in). Pure static hosting tanpa a Nitro/edge runtime therefore cannot load translations on the client unless you enable one of these outputs, keep `serverHandler` available at runtime, atau host payloads externally.

With default `mode: 'premerged'` dan `publicAssets: true`, static files already land at `public/<apiBaseUrl>/\{page\}/\{locale\}/data.json` — matching client `$fetch` URLs — so a static host can serve them tanpa Nitro.
</Warning>

<Warning>
When `apiBaseServerHost` atau `apiBaseClientHost` diatur, the module fetches already merged JSON dari that origin. External hosts must serve the same `/\{apiBaseUrl\}/:page/:locale/data.json` responses as the built-in route. `mode: 'source'` applies to local payload dirs, not to an external CDN unless that CDN also serves runtime-merged payloads.
</Warning>

Anda dapat also disable duplicated local outputs manually dan serve translation payloads dari a CDN atau object storage:

```typescript
i18n: {
  apiBaseClientHost: 'https://cdn.example.com',
  apiBaseServerHost: 'https://cdn.example.com',
  translationPayloads: {
    serverHandler: false,
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

If you only want to avoid writing payloads into public output while keeping the built-in server route untuk SSR/runtime requests, disable both public outputs:

```typescript
i18n: {
  translationPayloads: {
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

On **Node**, `serverAssets: true` still forces a public copy untuk SSR even when `publicAssets` is false — set `serverAssets: false` dan `apiBaseServerHost` if you want zero local payload files.

Use `publicDir` to change the public output folder when payloads are copied. It defaults to `apiBaseUrl` (`_locales`). In premerged mode `publicAssets` writes `\{page\}/\{locale\}/data.json` there (same paths the client fetches). `prerenderRoutes` adalahn optional Nitro prerender of the handler routes — usually redundant when that tree was already copied.

If you disable all local payload outputs, you must configure both `apiBaseServerHost` (SSR) dan `apiBaseClientHost` (client navigation). Otherwise translations will resolve to empty objects dan UI keys may appear untranslated.

`warnFileCount` dan `warnSizeBytes` control build-time warnings when pre-merged payload output grows large (defaults: 500 files dan 10 MB).

{/* generated:option:dateBuild — do not edit; run `pnpm run docs:generate` */}

**Tipe** `string \| number` · **Default** —

Value digunakan untuk cache-busting translation requests (`?v=...`).

Secara default the module fingerprints your translation sources (SHA-256 over every
`<layer>/<translationDir>/**/*.json`, in layer order) dan uses that. The value only changes when a
translation actually changes, so rebuilding atau redeploying untouched translations leaves browser and
CDN caches intact — dengan `httpCacheDuration` set to a year, a build timestamp would instead force
every client to re-download the whole dictionary on each deploy.

It falls back to `Date.now()` only when there are no translation files to hash.

Set it explicitly to take control (e.g. to tie payload URLs to a release rather than to content):

```ts
export default defineNuxtConfig({
  i18n: {
    // Any stable string/number: git SHA, CI build number, release tag, etc.
    dateBuild: process.env.GIT_SHA ?? 'local-dev',
  },
})
```
#### `httpCacheDuration`

{/* generated:option:httpCacheDuration — do not edit; run `pnpm run docs:generate` */}

**Tipe** `number` · **Default** `31536000`

HTTP `Cache-Control` max-age (seconds) untuk `/\{apiBaseUrl\}/:page/:locale/data.json`.

Applies in full only while `dateBuild` busts the URL (`?v=...`), which is the default:
the response is then `public, max-age=…, immutable` dan safe untuk browsers dan CDNs.

- `dateBuild: 0`/`''` — the URL is stable, so this duration is *not* honoured; the
  response becomes `public, max-age=0, must-revalidate` instead. A long `max-age` on an
  unchanging URL pins the first payload a browser ever saw.

- `0` — do not set `Cache-Control` at all (useful in local debugging)
- Not applied in development (`import.meta.dev`) so HMR is not fought oleh browser cache
- Reaches only responses served through Nitro. Payloads copied into `public/` dan served
  oleh hosting platform take that platform's headers — see the Performance guide.

Analogous to `@nuxtjs/i18n` experimental `httpCacheDuration` (v10.2.0), tetapi as an
explicit response header rather than Nitro `defineCachedEventHandler` maxAge.

{/* /generated:option:httpCacheDuration */}

```ts
export default defineNuxtConfig({
  i18n: {
    // Per-build fallback (Date.now()) so immutable payloads never go stale when GIT_SHA is missing.
    dateBuild: process.env.GIT_SHA ?? String(Date.now()),
    httpCacheDuration: 86400, // 24 hours
    // httpCacheDuration: 0, // disable Cache-Control header
  },
})
```

**Tipe** `number` · **Default** `0`

Time-to-live (in seconds) untuk cached translation entries.
`0` means entries never expire.

{/* /generated:option:cacheTtl */}

```typescript
export default defineNuxtConfig({
  i18n: {
    // Limit cache to 1000 entries, each lives 10 minutes (refreshed on access)
    cacheMaxSize: 1000,
    cacheTtl: 600,
  },
})
```

<Tip>
For most projects the default (unlimited, no expiration) is fine — translations are small dan finite. However, if your project has **thousands of pages** dengan `disablePageLocales: false` dan **many locales**, the server cache can grow significantly. In long-running Node.js servers this may lead to excessive memory usage.

- **`cacheMaxSize`** — caps the number of cached entries. Useful untuk bounding memory.
- **`cacheTtl`** — ensures stale translations are eventually reloaded dari storage. Useful untuk serverless environments atau when translations change at runtime.

**Formula untuk estimating max entries**: `number_of_locales × (number_of_pages + 1)`. Sebagai contoh, 10 locales × 500 pages = ~5010 entries.
</Tip>
