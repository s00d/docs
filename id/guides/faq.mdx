# ❓ FAQ: Masalah & Solusi Umum

Temukan jawaban atas pertanyaan yang sering diajukan dan solusi untuk masalah umum pada Nuxt I18n Micro.

## 🚀 Masalah Memulai

### ❓ Bagaimana jika suatu rute tidak dimuat?

Saat menggunakan `Nuxt I18n Micro`, rute tertentu mungkin tidak dimuat seperti yang diharapkan, terutama jika router tidak secara otomatis memberikan nama pada rute di subfolder.

**Solusi:**
Untuk mengatasi hal ini, definisikan nama rute untuk halaman secara manual dengan menambahkan kode berikut ke file Vue terkait:

```javascript
definePageMeta({ name: 'pageName' })
```

Ini memastikan rute terdaftar dengan benar, memungkinkan navigasi yang lancar di dalam aplikasi.

### ❓ Mengapa `$t` atau composable i18n lainnya tidak bekerja pada plugin Nuxt?

Composable Nuxt I18n (`$t`, `$getLocale`, `$localePath`, dll.) mungkin tidak bekerja seperti yang diharapkan pada plugin Nuxt atau fungsi utilitas, sehingga mengakibatkan kesalahan runtime.

**Penyebab dan Solusi:**
Composable Nuxt memerlukan konteks tertentu (mis. hooks Nuxt atau fungsi setup Vue) untuk mengakses instance Nuxt. Jika digunakan di luar konteks tersebut (mis. dalam fungsi utilitas atau plugin), kesalahan berikut mungkin muncul di konsol:

```
[nuxt] A composable that requires access to the Nuxt instance was called outside of a plugin, Nuxt hook, Nuxt middleware, or Vue setup function. This is probably not a Nuxt bug. Find out more at https://nuxt.com/docs/guide/concepts/auto-imports#vue-and-nuxt-composables
```

**Solusi 1: Gunakan `runWithContext`**
Untuk memanggil composable i18n setelah operasi asinkron, gunakan [`runWithContext`](https://nuxt.com/docs/api/composables/use-nuxt-app#runwithcontext) untuk mempertahankan konteks yang diperlukan.

```javascript
await nuxtApp.runWithContext(() => $t('test_key'))
```

**Solusi 2: Ambil Nilai Terlebih Dahulu**
Alternatifnya, ambil nilai terjemahan terlebih dahulu, lalu oper ke fungsi utilitas.

```javascript
const val = nuxtApp.$t('common.errors.unknown.title')
showError({
  title: val,
})
```

**Solusi 3: Oper Kunci Terjemahan pada Service**
Pada service atau fungsi utilitas, oper kunci terjemahan alih-alih menggunakan `$t` langsung. Kemudian, ambil terjemahan di komponen.

```javascript
showError({
  title: 'common.errors.unknown.title',
  message: 'common.errors.unknown.message',
  i18n: true,
})
```

## 🌐 Peralihan Lokal

### ❓ Ganti lokal tanpa mengubah URL?

Bisa — tetapi bergantung pada [strategi perutean](/guides/routing-strategies) Anda.

**Strategi `no_prefix`** — lokal bukan bagian dari URL. Gunakan `$switchLocale()` untuk mengubah lokal dan memuat ulang terjemahan sambil tetap di jalur yang sama:

```typescript
const { $switchLocale } = useNuxtApp()
$switchLocale('de') // /about stays /about, content switches to German
```

Atau perbarui preferensi saja dengan `useI18nLocale().setLocale('de')`. Untuk memuat ulang terjemahan sisi klien secara penuh, gunakan `$switchLocale()`.

**Strategi prefix** (`prefix`, `prefix_except_default`, …) — lokal dan URL terkait. `$switchLocale()` selalu bernavigasi ke rute terlokalisasi. Tidak ada opsi `redirect: false`.

Jika Anda hanya memerlukan URL target (misalnya, tautan pemilih bahasa), gunakan `$switchLocalePath()` sebagai gantinya:

```vue
<NuxtLink :to="$switchLocalePath('fr')">Français</NuxtLink>
```

Lihat [Peralihan Rute & Lokal](/api/methods#-route-locale-switching) untuk semua method peralihan.

### ❓ Halaman menggulir ke atas (atau melompat) saat mengganti lokal?

Itu wajar — itu adalah **perilaku scroll Vue Router / Nuxt**, bukan sesuatu yang spesifik untuk nuxt-i18n-micro.

Dengan strategi prefix (`prefix`, `prefix_except_default`, …), `$switchLocale()` melakukan navigasi klien normal (`/en/page` → `/de/page`). [`scrollBehavior`](https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/pages/runtime/router.options.ts) default Nuxt menggulir ke atas pada perubahan rute (kecuali maju/mundur browser melalui `savedPosition`).

nuxt-i18n-micro tidak menambahkan penanganan scroll tersembunyi — gunakan komponen wrapper kecil di aplikasi Anda.

**Wrapper `SwitchLocalePreserve`**

Salin [`playground/components/SwitchLocalePreserve.vue`](https://github.com/s00d/nuxt-i18n-micro/blob/main/playground/components/SwitchLocalePreserve.vue) ke proyek Anda (`components/SwitchLocalePreserve.vue`). Demo yang berfungsi: [`playground/pages/scroll-test.vue`](https://github.com/s00d/nuxt-i18n-micro/blob/main/playground/pages/scroll-test.vue).

Pada halaman, setel `scrollToTop: false` dan bungkus UI pemilih bahasa Anda. Tandai target yang dapat diklik dengan `data-locale` — wrapper mencegat klik, memanggil `$switchLocale`, dan memulihkan gulir (termasuk saat panjang terjemahan mengubah tata letak):

```vue
<script setup lang="ts">
definePageMeta({ scrollToTop: false })

const { $getLocales, $getLocale } = useI18n()
</script>

<template>
  <SwitchLocalePreserve root-id="lang-switcher">
    <button v-for="locale in $getLocales()" :key="locale.code" :data-locale="locale.code" :disabled="locale.code === $getLocale()">
      {{ locale.code }}
    </button>
  </SwitchLocalePreserve>
</template>
```

Komponen tersebut:

1. **Pada klik** — membaca `data-locale` pada elemen yang diklik di dalam slot (tombol, tautan, atau markup kustom lainnya).
2. **Sebelum** `$switchLocale` — menyimpan `scrollY` dan posisi elemen yang diklik (menjaga tetap di bawah kursor).
3. **Selama** navigasi — mem-patch `router.options.scrollBehavior` sekali dan mengembalikan `\{ top: scrollY \}` alih-alih menggulir ke atas.
4. **Setelah** navigasi — menunggu `page:finish`, lalu menerapkan ulang scroll sementara `ResizeObserver` menangkap pergeseran tata letak dari panjang terjemahan yang berbeda.

`scrollToTop: false` diperlukan pada halaman di mana Anda menggunakan wrapper ini. Dokumen: [Nuxt — `definePageMeta` / `scrollToTop`](https://nuxt.com/docs/4.x/api/utils/define-page-meta#meta).

Jangan panggil `$switchLocale` secara langsung pada kontrol yang dibungkus — wrapper menangani peralihan. Untuk `<NuxtLink :to="$switchLocalePath('fr')">` di luar wrapper, perilaku scroll mengikuti perutean Nuxt normal kecuali Anda menambahkan `app/router.options.ts` Anda sendiri.

## 🌐 Masalah Terjemahan

### ❓ Mengapa terjemahan rusak selama transisi halaman, terutama dengan `defineAsyncComponent`?

Saat menggunakan `nuxt-i18n-micro` dengan transisi halaman, terjemahan sebentar mungkin berhenti bekerja selama transisi. Masalah ini terjadi karena rute berubah sebelum transisi selesai, menyebabkan terjemahan untuk halaman baru dimuat saat halaman lama masih terlihat.

**Akar Penyebab:**

- Transisi halaman menyebabkan perubahan rute sebelum terjemahan dimuat sepenuhnya
- `defineAsyncComponent` dan `useAsyncData` dapat menunda pemuatan terjemahan
- Kunci terjemahan mungkin muncul sebagai jalur mentah selama pemuatan

**Solusi 1: Cumulative Merge (Bawaan, Tanpa Config)**

Pada v3, modul secara otomatis menggunakan strategi cumulative merge. Saat bernavigasi dalam lokal yang sama, terjemahan halaman baru digabungkan ke kamus aktif alih-alih menggantinya. Ini berarti terjemahan dari halaman sebelumnya tetap tersedia selama animasi transisi. Setelah transisi selesai (hook `page:transition:finish`), kunci lama dibersihkan secara otomatis.

Tidak perlu konfigurasi — ini bekerja out of the box.

**Solusi 2: Konteks Rute Eksplisit**

Jika Anda lebih memilih kendali manual, oper rute saat ini secara eksplisit ke `$_t`:

```vue
<script lang="ts" setup>
import { useNuxtApp } from '#imports'
const route = useRoute()
const { $_t } = useNuxtApp()

const $t = $_t(route)
</script>

<template>
  {{ $t('page::blog-slug.title') }}
</template>
```

**Solusi 3: State Pemuatan**

Terapkan state pemuatan untuk menangani pemuatan terjemahan dengan baik:

```vue
<template>
  <div v-if="pending">
    <div class="loading-skeleton">
      <!-- Loading placeholder -->
    </div>
  </div>
  <div v-else>
    {{ $t('page.title') }}
  </div>
</template>

<script setup>
const { data, pending } = await useAsyncData('page-data', () => {
  // Your async data loading
})
</script>
```

### ❓ Mengapa kunci terjemahan tidak terselesaikan saat SSR di Vercel?

**Keterbatasan `$fetch` pada SSR**
Pada platform serverless seperti Vercel, `$fetch` hanya dapat mengambil file statis dari CDN dan bukan dari server Nitro internal. Ini berarti file terjemahan statis mungkin tidak dapat diakses langsung kecuali URL dasar yang benar ditetapkan.

**Perbaiki dengan mengatur `apiBaseClientHost` dan `apiBaseServerHost`**
Jika terjemahan dihosting secara eksternal di CDN atau domain berbeda, gunakan `apiBaseClientHost` untuk permintaan sisi klien dan `apiBaseServerHost` untuk permintaan sisi server. `apiBaseUrl` hanya boleh berisi awalan jalur (mis. `_locales`).

```typescript
export default defineNuxtConfig({
  i18n: {
    apiBaseUrl: '/_locales', // Path prefix only
    apiBaseClientHost: 'https://cdn.example.com', // CDN domain for client
    apiBaseServerHost: 'https://cdn.example.com', // CDN domain for server (SSR)
  },
})
```

Atau melalui variabel lingkungan:

```bash
NUXT_I18N_APP_BASE_URL=_locales
NUXT_I18N_APP_BASE_CLIENT_HOST=https://cdn.example.com
NUXT_I18N_APP_BASE_SERVER_HOST=https://cdn.example.com
```

Terjemahan akan diambil dari `https://cdn.example.com/_locales/\{routeName\}/\{locale\}/data.json` baik pada klien maupun server.

## 🔗 Masalah Perutean & Navigasi

### ❓ Bisakah saya menggunakan `NuxtLink` atau `<i18n-link>` langsung pada string terjemahan?

Ya, `Nuxt I18n Micro` memungkinkan penggunaan `NuxtLink` atau `<i18n-link>` di dalam terjemahan melalui komponen `<i18n-t>`, yang sangat membantu untuk menangani tata bahasa dan persyaratan bahasa RTL tanpa memecah string terjemahan.

**Contoh:**

File terjemahan:

```json
{
  "example": "Share your {link} with friends",
  "link_text": "translation link"
}
```

Template Vue:

```vue
<template>
  <i18n-t keypath="example">
    <template #link>
      <nuxt-link :to="{ name: 'referral' }">
        <i18n-t keypath="link_text" />
      </nuxt-link>
    </template>
  </i18n-t>
</template>
```

Ini memungkinkan tautan dinamis dalam terjemahan sambil mempertahankan struktur lokalisasi yang benar.

## 🏗️ Masalah Build & Deployment

### ❓ Mengapa payload terjemahan berakhir di bawah `public/_locales/` (atau di server bundle pada Edge)?

SSR dan klien keduanya membutuhkan payload `/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json` yang sama. Bagaimana mereka dikemas bergantung pada target Nitro:

**Penjelasan:**

- **Node (default):** modul **tidak** menyematkan terjemahan sebagai `serverAssets` Nitro / Rollup `raw:` (yang membludakkan RAM build pada katalog besar). Alih-alih, ia menyalin pohon yang telah di-premerge ke `public/<apiBaseUrl>/` (default `_locales`) dan SSR membaca file tersebut dengan `readFile`. Klien meng-`$fetch` URL yang sama — baik sebagai file statis atau melalui handler Nitro.
- **Edge** (`nitro.node === false`): tidak ada FS publik yang tahan lama untuk SSR, jadi payload disematkan melalui `serverAssets` Nitro (`assets:i18n`). Sebaiknya `translationPayloads.mode: 'source'` agar embed tetap ringkas. Setel `publicAssets: true` hanya jika Anda juga memerlukan salinan CDN/statis.
- **`prerenderRoutes`:** opsional. Pada mode premerged `publicAssets` sudah menulis `\{page\}/\{locale\}/data.json`, jadi pre-rendering rute-rute tersebut biasanya redundan.

### ❓ Mengapa saya mendapat kesalahan build yang merujuk `@unhead/vue` atau objek yang tidak terdefinisi, terutama pada Cloudflare Pages?

**Penyebab:**
Beberapa proyek mengalami konflik build atau dependensi yang hilang saat menggunakan `nuxt-i18n-micro`. Khususnya:

- Deployment di **Cloudflare Pages** atau **Cloudflare Workers** mungkin memerlukan flag kompatibilitas tambahan.
- Langkah prerendering dapat gagal jika dependensi seperti `@unhead/vue` tidak diinstal dengan benar.
- Modul tertentu (mis. **nuxthub**, **nitro-cloudflare-dev**) dapat menyebabkan konflik kecuali dikonfigurasi dengan flag atau dependensi yang benar.

**Kemungkinan Solusi:**

**Solusi 1: Instal `@unhead/vue` secara manual**
Jika kesalahan build mengeluhkan tidak menemukan `@unhead/vue`, instal langsung pada dependensi proyek Anda:

<CodeGroup>
```bash npm
npm install @unhead/vue
```

```bash yarn
yarn add @unhead/vue
```

```bash pnpm
pnpm add @unhead/vue
```
</CodeGroup>

Ini memastikan tersedia selama fase prerender Nitro.

**Solusi 2: Tambahkan flag kompatibilitas Cloudflare**
Saat menggunakan Cloudflare Pages atau Cloudflare Workers, kompatibilitas Node.js sering dinonaktifkan secara default. Aktifkan di `wrangler.toml` Anda:

```toml
compatibility_flags = [ "nodejs_compat_v2" ]
```

Flag ini memungkinkan banyak modul Node.js (termasuk yang digunakan oleh `nuxt-i18n-micro`) berjalan dengan lancar.

## 🔍 SEO & `@nuxtjs/seo`

### ❓ Kesalahan: `nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered`

Ini terjadi ketika **`@nuxtjs/seo`** menarik **`nuxt-site-config` 3.x** lama yang hanya mendaftarkan plugin i18n-nya untuk `@nuxtjs/i18n`, bukan untuk **nuxt-i18n-micro**.

**Perbaikan:**

1. Upgrade ke **`@nuxtjs/seo` 3+** (mencakup `nuxt-site-config` 4+ dengan dukungan micro).
2. Tempatkan **`nuxt-i18n-micro` sebelum `@nuxtjs/seo`** dalam `modules`.
3. Pertahankan **`i18n.meta: true`** untuk tag head yang sadar lokal.

Lihat [panduan SEO — bagian Nuxt SEO](/guides/seo#nuxt-seo-nuxtjs-seo) untuk contoh lengkap.

## 🔧 Konfigurasi & Kompatibilitas

### ❓ Apakah `Nuxt I18n Micro` terinspirasi oleh `vue-i18n`? Bagaimana dengan modifier?

Meskipun `Nuxt I18n Micro` berfungsi sebagai alternatif performa untuk `nuxt-i18n`, ia dibangun secara independen dari `vue-i18n`. Meskipun beberapa nama method dan parameter mungkin mirip, fungsi dasarnya berbeda secara signifikan.

**Modifier**: Pemelihara awalnya mempertimbangkan modifier, tetapi menyimpulkan bahwa komponen seperti `<i18n-t>` dan `<i18n-link>` secara efektif memenuhi kebutuhan tersebut.

Sebagai contoh:

```vue
<template>
  <i18n-t keypath="feedback.text">
    <template #link>
      <nuxt-link :to="{ name: 'index' }">
        <i18n-t keypath="feedback.link" />
      </nuxt-link>
    </template>
  </i18n-t>
</template>
```

Pendekatan ini fleksibel, sehingga merilis modifier saat ini tidak diperlukan. Namun, modifier mungkin ditambahkan pada rilis mendatang jika ada permintaan.
