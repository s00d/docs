# Integrasi

The `@i18n-micro` packages are lightweight, framework-specific versions of Nuxt I18n Micro designed untuk integration into various frameworks dan environments. These packages provide core internationalization functionality dengan a minimal footprint, focusing on essential translation features dan basic components.

## Ikhtisar

These integration packages are **miniature versions** of the full Nuxt I18n Micro module, containing only the essential functionality diperlukan untuk internationalization:

- **Core Translation Features** - Basic translation methods, pluralization, dan formatting
- **Essential Components** - A small set of UI components untuk common i18n tasks
- **Router Adapter Pattern** - Flexible routing integration through adapter abstraction
- **TypeScript Support** - Full type definitions untuk type-safe development

Unlike the full Nuxt module, these packages:

- Do not include framework-specific routing logic
- Require you to implement a router adapter untuk routing features
- Focus on translation functionality rather than framework integration
- Are designed to be lightweight dan framework-agnostic where possible

## Core Components

All framework packages include the following essential components:

### `<I18nT>`

A translation component that renders translated text dengan support for:

- **Parameter interpolation** - Replace placeholders dengan dynamic values
- **Pluralization** - Automatic plural form selection based on count
- **Number formatting** - Format numbers according to locale
- **Date formatting** - Format dates dan relative times
- **HTML rendering** - Optional HTML content rendering
- **Default values** - Fallback text when translation is missing

**Contoh:**

```vue
<!-- Vue -->
<I18nT keypath="greeting" :params="{ name: 'World' }" />
```

```tsx
// React
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```tsx
// Solid
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```astro
<!-- Astro -->
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

### `<I18nLink>`

A localized link component that automatically menangani locale prefixes in URLs. Features:

- **Automatic path localization** - Adds/removes locale prefixes based on routing strategy
- **Active state detection** - Highlights the current route
- **External link support** - Automatically detects dan menangani external URLs
- **Router integration** - Uses router adapter's link component when available
- **Custom styling** - Supports active dan hover states

**Contoh:**

```vue
<!-- Vue -->
<I18nLink to="/about" active-class="active">
  About Us
</I18nLink>
```

```tsx
// React
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```tsx
// Solid
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```astro
<!-- Astro -->
<I18nLink href="/about" class="nav-link">
  About Us
</I18nLink>
```

### `<I18nSwitcher>`

A language switcher component that menyediakan a dropdown atau list interface untuk changing locales. Features:

- **Automatic locale list** - Generates options dari configured locales
- **Current locale highlighting** - Visually indicates the active language
- **Custom labels** - Support untuk custom display names per locale
- **Router integration** - Automatically navigates to localized paths
- **Accessibility** - Proper ARIA attributes dan keyboard navigation

**Contoh:**

```vue
<!-- Vue -->
<I18nSwitcher />
```

```tsx
// React
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```tsx
// Solid
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```astro
<!-- Astro -->
<I18nSwitcher />
```

### `<I18nGroup>`

A component untuk grouping translations dengan a common prefix, useful untuk organizing translations by page atau feature. Features:

- **Prefix scoping** - Automatically prepends prefix to all translation keys within the group
- **Nested groups** - Support untuk nested translation groups
- **Clean organization** - Helps maintain organized translation structures

**Contoh:**

```vue
<!-- Vue -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

```tsx
// React
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```tsx
// Solid
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```astro
<!-- Astro -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

## Shared `createI18n` options \{#create-i18n-options\}

Every framework package is created the same way — only the options type is named after
the framework (`ReactI18nOptions`, `SolidI18nOptions`, dan so on). The options themselves
are identical:

| Property         | Type                                                       | Required | Default          | Description                                    |
| ---------------- | ---------------------------------------------------------- | -------- | ---------------- | ---------------------------------------------- |
| `locale`         | `string`                                                   | ✅       | -                | Current locale code (e.g., `'en'`)             |
| `fallbackLocale` | `string`                                                   | ❌       | Same as `locale` | Fallback locale when translation is missing    |
| `messages`       | `Record<string, Translations>`                             | ❌       | `\{\}`             | Initial translation messages                   |
| `plural`         | `PluralFunc`                                               | ❌       | `defaultPlural`  | Custom pluralization function                  |
| `missingWarn`    | `boolean`                                                  | ❌       | `true`           | Show console warnings untuk missing translations |
| `missingHandler` | `(locale: string, key: string, routeName: string) => void` | ❌       | -                | Custom handler untuk missing translations        |

Anything beyond these is framework-specific dan documented on that package's page.

## Router Adapter Abstraction

All framework packages use a **router adapter pattern** to decouple i18n functionality dari specific router implementations. This design allows:

- **Flexibility** - Use any router library atau no router at all
- **Framework independence** - Keep routing logic in your application, not di i18n package
- **Lightweight core** - The i18n package remains small dan focused

### Implementing a Router Adapter

To use routing features, you need to implement the `I18nRoutingStrategy` interface:

```typescript
interface I18nRoutingStrategy {
  getCurrentPath: () => string
  linkComponent?: Component
  push: (target: { path: string }) => void
  replace: (target: { path: string }) => void
  resolvePath?: (to: string | { path?: string }, locale: string) => string | { path?: string }
  getRoute?: () => { fullPath: string; query: Record<string, unknown> }
}
```

Each package documentation includes complete examples of implementing adapters untuk popular routers:

- **Vue**: Vue Router adapter example
- **React**: React Router adapter example
- **Solid**: Solid Router adapter example
- **Astro**: File-based routing adapter example

## Core Features

All packages share these core features:

### Translation Methods

- `t()` - Basic translation dengan parameter interpolation
- `ts()` - Translation that always mengembalikan a string
- `tc()` - Pluralization-aware translation
- `tn()` - Number formatting
- `td()` - Date formatting
- `tdr()` - Relative time formatting
- `has()` - Check if translation key exists

### Locale Management

- **Locale switching** - Change current locale programmatically
- **Fallback locale** - Automatic fallback when translation is missing
- **Route-specific translations** - Page-level translation organization
- **Translation caching** - Intelligent caching untuk performance

### TypeScript Support

All packages provide:

- Full TypeScript definitions
- Type-safe translation keys (with types generator)
- IntelliSense support in IDEs
- Compile-time error checking
