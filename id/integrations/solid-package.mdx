`@i18n-micro/solid` memberikan app SolidJS sebuah instance i18n berbasis signal, provider, `useI18n()`, dan empat komponen. Gunakan di app Solid yang tidak dibangun dengan Nuxt. Pembacaan `t()` di dalam JSX atau effect melacak locale, route, dan kamus; model bersamanya dijelaskan di [Framework](/id/integrations/overview).

## Instalasi {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer dependency: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (opsional, hanya untuk `@i18n-micro/solid/router`). Solid 2 belum didukung.

## Penyiapan {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` menerima `i18n`, `locales`, `defaultLocale`, dan `routingStrategy`; prop yang tidak diberikan mempertahankan nilai provider luar, termasuk instance-nya. `getLocaleName()` dan `<I18nSwitcher>` membaca `locales`; tanpanya tidak ada yang bisa ditampilkan. Opsi dijelaskan di [instance](/id/integrations/overview#the-instance). Instance-nya adalah milik [runtime](/id/integrations/runtime-package), dengan satu signal di atas store-nya.

## Menerjemahkan {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Panggil metode di dalam JSX atau effect agar Solid melacaknya, begitu pula `localePath` dan `getLocale`; nilai yang dibaca sekali di body komponen tidak diperbarui. Pada instance, lacak dengan `i18n.locale` dan `i18n.currentRoute`: `i18n.getLocale()` tetap biasa, karena operasi tulis membacanya. Membaca locale hanya bereaksi terhadap locale, sehingga effect yang membacanya dan memuat kamus hanya berjalan sekali. Jangan melakukan destructuring pada props atau menyimpan hasil `t('key')` di variabel biasa.

`useI18n()` mengembalikan `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (sebuah accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache`, dan `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Mengganti locale {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Mengganti locale tidak memuat apa pun; tambahkan kamus locale tersebut terlebih dahulu.

`<I18nGroup>` meneruskan `t` berprefiks ke child berupa fungsi. `<I18nT>` dan `t()` di dalamnya tidak diberi prefiks:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Routing {#routing}

Adapter `@solidjs/router` berada di subpath sehingga entry utama tidak pernah mengimpor router. Panggil di bawah router, biasanya di `root` milik router, tempat `useNavigate` dan `useLocation` berfungsi:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

Adapter memberi prefiks pada setiap locale kecuali default (`/about`, `/de/about`), dan merender `<I18nLink>` sebagai `<A>` milik router. `getCurrentPath` membaca location reaktif milik router, sehingga link aktif dan switcher mengikutinya; strategi kustom mendapatkan hal yang sama dengan membaca signal di sana. Perhatikan urutan argumen: `(locales, defaultLocale, navigate, location)`. Untuk router lain, tulis adapter dengan `getCurrentPath`, `push`, dan `replace` (semuanya wajib) — lihat [Adapter router](/id/integrations/overview#router-adapter).

## SSR {#ssr}

Untuk server rendering, build dengan `vite-plugin-solid`: kondisi ekspor `solid` milik paket memberikan source-nya, sehingga dikompilasi untuk server. `dist` yang sudah di-build hanya untuk browser. Instance tidak memiliki `destroy()`; buat satu per app, atau satu per request di server, dan biarkan di-garbage-collect.
