Sebuah layer Nuxt dapat membawa konfigurasi i18n dan folder `locales/` untuk beberapa app, dan setiap app menambahkan atau menimpa apa yang dibutuhkannya. Halaman ini menunjukkan hal tersebut, serta bagaimana satu build melayani beberapa domain.

## Membagikan konfigurasi dan terjemahan {#share-config-and-translations}

```ts
// base/nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    defaultLocale: 'en',
  },
})
```

```ts
// shop/nuxt.config.ts
export default defineNuxtConfig({
  extends: ['../base'], // a layer directory or package, not a nuxt.config file
  i18n: {
    locales: [
      { code: 'es', iso: 'es-ES' }, // added
      { code: 'fr', disabled: true }, // the base layer's fr, switched off here
    ],
  },
})
```

- **Konfigurasi:** opsi skalar di app menggantikan milik layer. Array `locales` dari semua layer digabungkan, dan entri dengan `code` yang sama digabung menjadi satu dengan field milik app yang menang, sehingga app dapat menambahkan locale atau mengatur field seperti `disabled: true` pada locale yang diwarisi.
- **Terjemahan:** `locales/` dari setiap layer digabung key demi key, layer lebih dulu dan app terakhir, sehingga key di `shop/locales/en.json` menimpa key yang sama di `base/locales/en.json`. File halaman (`locales/pages/<page>/`) digabung dengan cara yang sama.
- **Halaman:** `$defineI18nRoute` dibaca dari halaman di setiap layer.

Untuk menggabungkan folder yang bukan bagian dari layer, cantumkan di [`additionalTranslationDirs`](/id/api/module-options#additionaltranslationdirs).

## Beberapa domain {#multiple-domains}

Satu build melayani setiap domain. Cantumkan setiap locale beserta domainnya; `baseDefault` menjadikannya default untuk host tersebut:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'de', iso: 'de-DE', baseUrl: 'https://example.de', baseDefault: true },
      { code: 'nl', iso: 'nl-NL', baseUrl: 'https://example.de' },
      { code: 'fr', iso: 'fr-FR' },
    ],
  },
})
```

Arahkan kedua domain ke server yang sama. Host dari request menentukan sisanya:

- **Default:** locale `baseDefault` milik host. Jika tidak ada, default build bila host tersebut melayaninya, jika tidak, locale pertama milik host.
- **Locale yang dilayani:** locale milik host tersebut, ditambah setiap locale tanpa `baseUrl`. Di `example.de` itu adalah `de`, `nl`, dan `fr`.
- **Locale milik domain lain** adalah target link. `$localePath`, `$localeRoute`, `$switchLocalePath`, `<i18n-switcher>`, dan `hreflang` memberikan URL absolut pada `baseUrl`-nya, dan `$switchLocale` bernavigasi ke sana. Di host ini URL-nya menghasilkan 404, dan cookie maupun `Accept-Language` tidak dapat memilihnya.
- **Link ke domain lain** melalui `$localePath` atau `<i18n-link>`: `<NuxtLink :to="$localePath('/contact', 'de')">`, `<i18n-link :to="$localeRoute('/contact', 'de')">`. Router tidak menerima objek absolut, sehingga `<NuxtLink :to="$localeRoute(...)">` dan `router.push($localeRoute(...))` tetap berada di origin ini. Di `localhost` atau host preview, setiap locale dengan `baseUrl` adalah link semacam itu, termasuk locale saat ini. Di dalam kode gunakan `navigateTo($localePath('/contact', 'de'), { external: true })`, atau `$switchRoute`.
- **Host lainnya** mendapat konfigurasi build, dengan setiap locale `baseUrl` sebagai target link. Tidak ada yang diambil dari request: canonical dan `hreflang` menggunakan `metaBaseUrl`, atau `baseUrl` milik default build (default tanpa `baseUrl` membutuhkan `metaBaseUrl` atau `site.url`, lihat [SEO](/id/guide/seo#set-the-public-origin)).
- **File payload** di `public/` bersifat statis: host mana pun mengembalikan file locale mana pun. [Generate](/id/guide/deployment#static-site-(nuxi-generate)) per domain hanya menerbitkan milik domain tersebut.

`example.de` di bawah setiap strategi, dengan `de: '/kontakt'` sebagai path kustom dari `contact`:

| Strategi | `/` | Halaman locale default | URL lainnya |
| --- | --- | --- | --- |
| `prefix_except_default` | `de` | `/kontakt` | `/de/kontakt` dan `/en/contact` menghasilkan 404, `/contact` di-redirect ke `/kontakt` |
| `prefix_and_default` | `de` | `/kontakt` dan `/de/kontakt`, link menggunakan `/kontakt` | `/en/contact` dan `/contact` menghasilkan 404 |
| `prefix` | di-redirect ke `/de` | `/de/kontakt` | `/kontakt` di-redirect ke `/de/kontakt`, `/en/contact` menghasilkan 404 |
| `no_prefix` | `de` | `/kontakt` | path kustom dari locale di domain lain menghasilkan 404 |

Di bawah `prefix`, link dari domain lain mempertahankan prefiks, karena URL tanpa prefiks hanya akan melakukan redirect. Di bawah `no_prefix`, link ke domain lain mendarat di locale default milik host tersebut: URL tidak dapat menyebutkan locale kedua.

Hal-hal yang perlu diketahui:

- **Di belakang proxy**, host diambil dari `Host`. Jika proxy menaruh host publik di `X-Forwarded-Host`, atur [`trustForwardedHost`](/id/api/module-options#trustforwardedhost), dan hanya jika proxy menimpa header tersebut. Proxy yang tidak mengirim keduanya tidak dapat melayani build domain. Lihat [Di belakang proxy atau CDN](/id/guide/deployment#behind-a-proxy-or-cdn).
- **`app.baseURL`** juga harus ada di `baseUrl`: `baseUrl: 'https://example.de/shop'` dengan `app.baseURL: '/shop'`.
- **Host dicocokkan secara persis.** `www.example.de` adalah host yang berbeda: redirect di edge, atau atur `baseUrl` tersebut pada locale. Hanya satu host per locale.
- **Cache harus menggunakan host sebagai key.** CDN biasanya sudah melakukannya. Cache route Nitro menggunakan path sebagai key, sehingga dalam build domain modul menambahkan `host` ke `cache.varies` dari setiap aturan `swr` dan `cache`, serta `x-forwarded-host` jika `trustForwardedHost` aktif. Aturan dengan `cache: false` tetap seperti yang ditulis. `isr` adalah cache milik platform: pastikan cache tersebut menggunakan host sebagai key.
- **Path kustom dari dua default host tidak boleh bertabrakan.** Record tanpa prefiks berbagi satu router, sehingga `/x` tidak bisa menjadi satu halaman di `example.de` dan halaman lain di `example.com`.
- **Halaman yang di-prerender:** aturan route `prerender: true` di `nuxt build` merender sekali, tanpa host, dan file tersebut menjawab setiap domain. Serahkan halaman yang berbeda per domain ke server, atau [generate per domain](/id/guide/deployment#static-site-(nuxi-generate)).
- **`noPrefixRedirect`** mengikuti locale milik host dan pengunjung, di setiap host.
- **`hashMode`:** host memilih render seperti di atas, link ke domain lain membawa route di dalam hash (`https://example.com/#/contact`).
- **`ssr: false`:** browser membaca domain dari `location.host`, sehingga host tanpa server tetap dapat di-resolve.
- **[Override runtime](/id/guide/runtime-overrides)** diterapkan lebih dulu. `disabledLocales` runtime berlaku di setiap host, dengan satu pengecualian: di bawah `prefix_except_default` dan `prefix_and_default`, default sebuah host tetap aktif di host-nya, karena halamannya adalah record tanpa prefiks. Di bawah `prefix` dan `no_prefix`, host beralih ke locale berikutnya yang dilayaninya. `defaultLocale` runtime hanya berlaku untuk host yang tidak dikenal.

Untuk [situs statis](/id/guide/deployment#static-site-(nuxi-generate)), lakukan generate sekali per domain.

### Satu app per domain {#one-app-per-domain}

Layer bersama dengan satu app kecil per domain tetap berfungsi, ketika domain membutuhkan halaman atau modul yang berbeda. Setiap app mengatur `defaultLocale`-nya sendiri di atas daftar `locales` yang sama. Locale di domain lain menghasilkan 404 di app tersebut, seperti di atas.

### Memilih locale di dalam kode {#choosing-the-locale-in-code}

Untuk satu instance yang menjawab setiap domain dengan origin request itu sendiri di tag SEO, lihat [SEO](/id/guide/seo#set-the-public-origin); untuk memilih locale dari host di dalam kode, lihat [Deteksi locale kustom](/id/guide/custom-auto-detect).
