`@i18n-micro/cli` mengelola file locale dari proyek Nuxt. CLI ini membaca `locales`, `defaultLocale`, `translationDir`, dan layer Anda dari `nuxt.config`, sehingga tidak membutuhkan konfigurasi tersendiri.

![Terminal yang menjalankan i18n-micro check, yang menampilkan satu key hilang, satu key tidak terdefinisi, dan empat key tidak digunakan lalu gagal, kemudian extract, yang menambahkan key tidak terdefinisi, kemudian clean --dryRun, yang menampilkan empat key yang akan dihapusnya](/images/cli/demo.gif)

| Perintah | Gunakan untuk |
| --- | --- |
| `check` | Menggagalkan build jika ada yang salah dengan file locale |
| `translate` | Mengisi key yang hilang melalui layanan terjemahan |
| `clean` | Menghapus key yang tidak digunakan apa pun |
| `rename` | Memindahkan key, atau seluruh namespace, di semua tempat sekaligus |

```bash
npm install -D @i18n-micro/cli
npx i18n-micro --help
```

Jalankan dari root app, atau arahkan ke sana dengan `--cwd`. Setiap flag dari setiap perintah ada di [referensi perintah](/id/api/cli).

<Tip>

**Beralih dari nuxt-i18n-micro-cli?** `@i18n-micro/cli` menggantikannya; bin `i18n-micro` dan `i18n-micro-cli` tetap ada. Lihat [tabel perintah lama](#moving-from-nuxt-i18n-micro-cli).

</Tip>

## Menggunakannya di CI {#use-it-in-ci}

```bash
i18n-micro check
```

`check` adalah gerbangnya. Perintah ini melaporkan:

| Pemeriksaan | Artinya |
| --- | --- |
| `missing` | Key dari locale default tidak ada di sebuah locale |
| `empty` | Nilainya `''`. App menampilkan kekosongan, bukan fallback |
| `extra` | Sebuah locale memiliki key yang tidak dimiliki locale default |
| `placeholders` | `{name}` hilang atau ditambahkan, atau bentuk jamak kehilangan bentuk-bentuknya |
| `undefined` | Kode menggunakan key yang tidak dimiliki locale default |
| `unused` | Tidak ada bagian proyek yang menggunakan key tersebut |
| `duplicates` | Teks yang sama di bawah key yang berbeda. Nonaktif secara default: berikan `--duplicates` |

- `--only missing,placeholders` menjalankan sebagian pemeriksaan; pemeriksaan yang disebut di `--only` tetapi tidak dapat dijalankan akan gagal.
- `--json` memberikan laporan untuk tooling.
- `--ignore` melewati file source.
- Selama key dihitung saat runtime, `unused` dilewati dan laporan menyebutkan alasannya.

Setiap perintah keluar dengan salah satu dari tiga kode, sehingga pipeline dapat membedakan masalah pada terjemahan Anda dari masalah pada tool:

| Kode keluar | Arti |
| --- | --- |
| `0` | Tidak ada yang dilaporkan |
| `1` | Ada temuan |
| `2` | Perintah tidak dapat dijalankan: kesalahan penggunaan, file rusak, request gagal |

Perintah lain yang layak dijadikan langkah CI:

```bash
i18n-micro format --check      # fails if a file is not formatted
i18n-micro lint                # stray spaces, empty values, your own regex rules
i18n-micro stats --baseRef main
```

## Menjaga locale tetap selaras {#keep-locales-in-step}

| Perintah | Apa yang dilakukannya |
| --- | --- |
| `extract` | Menampilkan key yang digunakan kode tetapi belum memiliki teks. Teks default, seperti di `$t('key', {}, 'Welcome')`, masuk ke locale default. |
| `sync` | Menghapus key yang tidak dimiliki locale default. Coba `--dryRun` terlebih dahulu. |
| `clean` | Menghapus key yang tidak digunakan apa pun. Coba `--dryRun` terlebih dahulu. |
| `search` | Menemukan key dan nilai, serta menunjukkan di mana setiap key digunakan. |
| `stats` | Kelengkapan per locale; `--baseRef main` membandingkan dengan sebuah ref git. |

`sync` berhenti seperti halnya `clean` ketika akan menghapus key yang tidak dapat dibuktikannya tidak digunakan, dan juga ketika locale default tidak memiliki apa pun untuk dibandingkan. Jika tidak ada yang perlu dihapus, perintah ini tidak pernah berhenti, sehingga `$t(item.label)` saja bukan alasan untuk menggunakan `--force`.

<Note>

`extract` dan `sync` tidak pernah menulis `''` untuk key tanpa terjemahan. Key tetap tidak ada, sehingga `fallbackLocale` berlaku saat runtime dan `check` melaporkannya. String kosong akan menjadi nilai yang terdefinisi dan menampilkan kekosongan.

</Note>

### Apa yang dibaca perintah {#what-the-commands-read}

`check`, `extract`, `sync`, `clean`, `search`, dan `rename` membaca kode source di seluruh proyek, bukan daftar folder yang tetap:

- **Dibaca:** template dan skrip melalui parser, `.html` dan Pug sebagai teks, setiap layer, dan folder di luar root yang ditunjuk oleh alias atau `components`.
- **Dilewati:** `node_modules`, output build, dan file locale. Tambahkan milik Anda sendiri dengan `--ignore 'legacy/**,*.stories.ts'`.
- **Kode test** dihitung sebagai penggunaan, sehingga `clean` dan `check --only unused` mempertahankan key yang hanya dibaca oleh test. Kode test tidak pernah menambahkan key: `extract` melewati key semacam itu, dan `check` tidak melaporkannya sebagai tidak terdefinisi.

Kode test berarti folder root `tests`, `test`, `__tests__`, `e2e`, `cypress`, dan `playwright`, ditambah file JavaScript dan TypeScript `.spec` dan `.test` (`.ts`, `.tsx`, `.mts`, `.js`, `.jsx`, `.mjs`, dan sejenisnya) di mana pun. Hanya folder root yang dikecualikan dari keraguan di bawah: `pages/tests/[id].vue` adalah halaman seperti halaman lainnya, begitu pula `public/` dan file yang di-minify, yang kodenya bukan bagian dari app.

Perintah-perintah ini mengenali:

- `$t`, `$ts`, `$tc`, `$has`, dan `$_t(route)`;
- `t()` dari `useI18n()` dan `useTranslationServerMiddleware()`;
- `<i18n-t keypath>` di template dan JSX, serta `<i18n-group prefix>`;
- alias seperti `const { t: tr } = useI18n()`.

### Bagaimana `clean` memutuskan {#how-clean-decides}

`clean` lebih memilih membiarkan key mati daripada menghapus key yang masih hidup. Sebuah key dipertahankan jika salah satu dari hal berikut benar:

- sebuah pemanggilan menggunakannya, atau key di bawah maupun di atasnya;
- sebuah string di kode sama dengannya: `const key = 'menu.home'`, `<Item label="menu.home" />`;
- sebuah file JSON, YAML, atau Markdown di proyek berisi key tersebut;
- sebuah key yang dihitung memiliki awal statis yang mencakupnya: `` $t(`status.${state}`) `` mempertahankan semua yang ada di bawah `status.`;
- sebuah layer mendefinisikannya.

`clean` berhenti tanpa mengubah apa pun ketika tidak dapat memastikan, dan menampilkan alasannya:

- sebuah key sepenuhnya dihitung, seperti di `$t(name)`, `<i18n-t :keypath="name" />` atau `<i18n-t v-bind="props" />`;
- `$t` diteruskan sebagai nilai, seperti di `items.map($t)`;
- sebuah fungsi bernama `t` menerima argumen yang dihitung dan berasal dari parameter, import, atau pemanggilan: fungsi tersebut mungkin wrapper dari fungsi yang asli. Fungsi yang didefinisikan di file yang sama tidak dihitung, karena wrapper akan memiliki pemanggilannya sendiri di dalamnya;
- sebuah file source tidak dapat di-parse;
- tidak ada file yang menggunakan key apa pun, yang biasanya berarti perintah mencari di tempat yang salah;
- sebuah file locale adalah symlink ke luar proyek, sehingga app lain mungkin membacanya.

<Steps>

<Step title="Pratinjau">

Jalankan `i18n-micro clean --dryRun` dan tinjau apa yang ditampilkannya.

</Step>

<Step title="Lindungi key">

Pertahankan key yang hanya terlihat tidak digunakan dengan `--exclude '^errors\.'`.

</Step>

<Step title="Hapus">

Jalankan lagi dengan `--force`.

</Step>

</Steps>

## Menerjemahkan key yang hilang {#translate-missing-keys}

```bash
i18n-micro translate --dryRun                     # keys and characters per locale, nothing sent
export I18N_TRANSLATE_TOKEN=...                   # or put it in .env
i18n-micro translate --service deepl --locale de,fr
```

- `translate` mengisi key yang hilang atau kosong; `--replace` menerjemahkan ulang semuanya.
- Placeholder dan bentuk jamak dilindungi. Terjemahan yang kehilangan placeholder tidak ditulis: key ditampilkan dan perintah keluar dengan `1`.
- Setiap batch disimpan sebelum request berikutnya dikirim, sehingga kegagalan hanya menghabiskan request yang gagal.

| `--service` | Layanan | `--token` | `--options` yang berguna |
| --- | --- | --- | --- |
| `ai` | Vercel AI Gateway, OpenAI, Anthropic, atau server apa pun yang kompatibel dengan OpenAI | API key, atau `AI_GATEWAY_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` | `provider`, `model`, `baseUrl`, `maxTokens` |
| `azure` | Azure Translator | Subscription key | `region` |
| `deepl` | DeepL, termasuk key Free | Auth key | `formality`, `glossaryId`, `context` |
| `google` | Google Cloud Translation v2 | API key | `model` |
| `libretranslate` | LibreTranslate | Opsional | `baseUrl` |
| `yandexcloud` | Yandex Cloud Translate | API key, atau token IAM dengan `authScheme:Bearer` | `folderId`, `model` |

Opsi berupa pasangan `key:value`: `--options provider:openai,model:gpt-4o-mini`. Semua layanan juga menerima `baseUrl`, `retries`, `retryDelayMs`, dan `timeoutMs`. Request terjemahan mungkin sudah ditagih, sehingga hanya diulang setelah `429` atau `503`, dan tidak diulang ketika layanan meminta menunggu lebih dari satu menit.

<Warning>

Flag terlihat di riwayat shell dan daftar proses, jadi teruskan token melalui variabel lingkungan. CLI menyamarkan apa yang diketahuinya sebagai rahasia di mana pun ia mencetaknya, termasuk `--debug`: token, key provider, kredensial Basic, serta query dan kredensial dari URL yang Anda konfigurasikan. Server yang memformat ulang key sebelum menampilkannya kembali berada di luar jangkauannya, jadi perlakukan log dari proses yang gagal dengan hati-hati.

</Warning>

Layanan `ai` mengikuti glosarium. Jika `.i18n-glossary.json` ada, file tersebut digunakan tanpa flag; `--glossaryFile` memilih file lain.

```json .i18n-glossary.json
{ "entries": [{ "source": "Cart", "target": "Warenkorb", "to": "de" }] }
```

## Mengubah teks hardcode menjadi key {#turn-hardcoded-text-into-keys}

```bash
i18n-micro text-to-i18n --dryRun   # list what would change
i18n-micro text-to-i18n            # rewrite the templates
```

```vue
<!-- before -->
<h1>Welcome to our site</h1>
<!-- after -->
<h1>{{ $t('pages.index.welcome-to-our') }}</h1>
```

Hanya template `.vue` dari proyek itu sendiri yang ditulis ulang, bukan milik layer atau target alias. Setiap file yang ditulis ulang di-parse lagi sebelum ditulis. Hal-hal berikut ditampilkan dan teksnya dipertahankan:

- teks di file `.ts` dan skrip, karena `$t` tidak tersedia di setiap scope;
- teks di samping markup atau interpolasi, seperti `<p>Hello <b>world</b> today</p>`: setengah kalimat tidak dapat diterjemahkan sendiri;
- key yang dihasilkan yang akan bertabrakan dengan key lain, seperti yang bisa terjadi pada halaman induk dan anaknya;
- key yang dikenal yang tidak dapat ditempatkan di antara tanda kutip.

<Warning>

Commit terlebih dahulu, dan tinjau diff-nya.

</Warning>

## Mengganti nama key {#rename-a-key}

```bash
i18n-micro rename --from common.save --to actions.save
i18n-micro rename --from settings --to account.settings   # a whole namespace
```

`rename` mengedit syntax tree, sehingga komentar dan string yang tidak terkait tetap seperti semula, serta alias dan `:keypath` diikuti. File milik layer tidak pernah diubah. Perintah ini memberi peringatan tentang apa yang tidak dapat ditulis ulangnya, dan membiarkannya:

- key yang dihitung di bawah nama lama;
- setiap string biasa yang sama dengannya;
- template Pug;
- source di sebuah layer atau di folder di luar proyek.

`--to` harus berupa key yang dapat ditulis di kode: tanpa tanda kutip, tanpa backslash, tanpa segmen kosong, tanpa `__proto__`.

## Bertukar file dengan penerjemah {#exchange-files-with-translators}

```bash
i18n-micro export --format csv
i18n-micro import --format csv --dryRun
```

**`export`** menulis setiap key dari setiap locale, termasuk yang belum diterjemahkan, dengan teks locale default sebagai sumber: kolom `Source` di CSV, komentar `#.` di PO.

- Tanpa `--dir`, PO masuk ke `pots` dan CSV ke `csv_exports`.
- Perintah ini mencatat apa yang ditulisnya di `.i18n-export.json`, di folder output. Perintah berhenti ketika sebuah file telah berubah sejak saat itu dan berisi terjemahan yang tidak dimiliki file locale, termasuk entri PO fuzzy; `--force` menimpanya. Pengeditan biasa pada file locale tidak menghentikannya.

**`import`** menggabungkan, melewati sel kosong, dan melewati entri PO yang ditandai `fuzzy`.

- Key yang akan menimpa sebuah nilai, atau nilai yang akan menimpa seluruh grup key, ditampilkan dan dikecualikan, dan perintah keluar dengan `1`.
- Perintah berhenti dengan kode keluar `2` pada katalog di lokasi yang tidak terduga, katalog halaman yang tidak ditulis oleh export terakhir, tanda kutip yang salah tempat di CSV, atau entri halaman di bawah `disablePageLocales`.

Untuk platform terjemahan, gunakan CLI milik platform tersebut: penyiapan [Crowdin](/id/guide/crowdin) menyinkronkan file JSON, termasuk file halaman.

## Sinkronisasi dengan endpoint Anda sendiri {#sync-with-your-own-endpoint}

`sync-remote` menukar file locale global dengan endpoint HTTP yang Anda jalankan. File halaman tetap lokal, dan perintah menyebutkannya. Jelaskan endpoint di `.i18n-remote.json`:

```json .i18n-remote.json
{ "url": "https://translations.example.com", "path": "translations" }
```

Endpoint menjawab `GET` dan `PUT` dengan objek `{ locale: messages }`. Autentikasi dengan `auth: { username, password }`, atau taruh bearer token di `I18N_REMOTE_TOKEN`.

| | Pull | Push |
| --- | --- | --- |
| Apa yang dipindahkan | Mengisi apa yang tidak Anda miliki dan mempertahankan key yang hanya Anda miliki | Mengirim key milik proyek sendiri, bukan milik layer, dan tidak menyertakan nilai kosong Anda |
| Konflik | Key yang berbeda di kedua sisi: tidak ada yang ditulis, kode keluar `1`; `--force` mengambil nilai remote | PUT menggantikan dokumen, sehingga push terlebih dahulu membaca endpoint dan berhenti dengan kode keluar `1` ketika endpoint berisi teks yang tidak Anda miliki; `--force` menimpanya. Endpoint yang menjawab `404` tidak memiliki apa pun untuk hilang |
| `--dryRun` | Membaca dari endpoint, menampilkan perubahan, tidak menulis apa pun | Menyebutkan apa yang akan dikirim, tanpa menghubungi endpoint |

Locale yang belum Anda konfigurasikan dilewati, dan nilai remote yang kosong tidak menghapus apa pun.

## Beralih dari nuxt-i18n-micro-cli {#moving-from-nuxt-i18n-micro-cli}

| Perintah lama | Sekarang |
| --- | --- |
| `validate` | `check` |
| `diff` | `check --only missing` |
| `check-duplicates` | `check --only duplicates` |
| `export-csv`, `import-csv` | `export --format csv`, `import --format csv` |
| `--potsDir`, `--csvDir` | `--dir` |
| `estimate` | `translate --dryRun` |
| `glossary` | Edit `.i18n-glossary.json`; `translate` membacanya sendiri |
| `backup`, `restore` | Git, yang sudah menyimpan file locale Anda |
| `init` | `nuxi init`, lalu tambahkan `nuxt-i18n-micro` ke `modules` |
| `split` | Dihapus: modul tidak membaca file yang dipecah |
| `optimize` | `check --only duplicates` |
| `replace-values` | Editor Anda atau `sed` |
| `stats --full` | `stats`; [DevTools](/id/guide/devtools) memiliki detailnya |
| `search --hardcodedOnly` | `text-to-i18n --dryRun` |
| `search --preferUnused`, `--onlyVue` | Dihapus |
| Aturan `lint` `no-html-tags`, `no-special-chars`, `no-mixed-case`, `no-missing-punctuation`, `no-inconsistent-pluralization` | Dihapus: aturan ini menandai teks normal. Tulis entri `customRegexRules` jika Anda membutuhkannya |
| `text-to-i18n --extractOnlyDirs`, `--extractOnlyPatterns`, `--verbose` | Dihapus: kode tidak pernah ditulis ulang |
| `--logLevel verbose` | Dihapus: tidak melakukan apa pun |

**Layanan yang dihapus:** `googlefree`, `yandex` (gunakan `yandexcloud`), `ibm`, `lingvatranslate`, `modernmt`, `lilt`, `unbabel`, `reverso`, `baidu`, `papago`, `tencent`, `systran`, `mymemory`.

**Tipe `sync-remote` yang dihapus:** `github`, `gitlab`, `crowdin`, `lokalise`, `tolgee`, `weblate`. Gunakan CLI milik platform, atau `custom`, yang tidak lagi membutuhkan `type`.

### Perilaku yang berubah {#changed-behaviour}

- `extract` dan `sync` tidak lagi menulis `''`. Key tetap tidak ada, dan `check` melaporkannya. `extract` menulis key hanya ketika kode memberikan teksnya.
- `extract` menulis key halaman ke `locales/pages/<route name>/`, tempat modul membacanya, dan memindai `app/` di Nuxt 4. Pindahkan apa pun dari direktori seperti `pages/_about` dan `pages/blog_`, dan hapus `locales/pages/<locale>.json` yang tersesat.
- `translationDir` dari `nuxt.config` dihormati; sebelumnya, setiap perintah diam-diam menggunakan `locales`.
- Tanpa `defaultLocale`, default-nya adalah `en`, seperti di modul, dan `DEFAULT_LOCALE` dihormati. Dulu default-nya adalah locale pertama.
- `check` dan `sync` menggunakan locale default sebagai referensi dan memeriksa file halaman. `"a.b"` dan `a: { b }` dihitung sebagai satu key.
- `clean` mempertahankan key yang digunakan di mana pun, dalam scope apa pun, dan berhenti ketika penggunaan tidak dapat dibuktikan. `--include` dan `--exclude` memilih apa yang boleh dihapus.
- `sync` berhenti dengan cara yang sama, dan ketika locale default tidak memiliki key untuk dibandingkan. `--force` mengesampingkannya. Perintah ini juga berhenti ketika `DEFAULT_LOCALE` memilih referensi yang berbeda dari `nuxt.config`.
- Flag panjang dengan satu tanda hubung dan argumen yang tersesat adalah error: `clean -dryRun` tidak lagi menjalankan `clean`.
- File read-only, atau file yang bukan UTF-8, tidak dapat disimpan: perintah berhenti sebelum mengubah apa pun. Membaca file semacam itu tidak masalah. Key yang berulang, key bernama `__proto__`, dan bilangan bulat di atas 2^53 menghentikan perintah, karena penyimpanan akan menghilangkannya.
- Flag yang membutuhkan nilai dan diikuti oleh flag lain adalah error; tulis `--flag=--value` untuk nilai yang diawali tanda hubung. Flag boolean hanya menerima `true` atau `false`.
- `export` berhenti alih-alih menimpa terjemahan yang belum pernah diimpor.
- Kode keluar adalah `0`, `1`, dan `2`; kegagalan dulu bernilai `1`, dan `diff` serta `check-duplicates` selalu `0`.
- `lint --fix` tidak lagi meninggalkan file `.bak`.
- Penyimpanan mempertahankan indentasi, akhir baris, newline akhir, symlink, dan hard link sebuah file, dan membiarkan file yang tidak diubahnya.
- Flag yang salah ketik atau dihapus kini menjadi error, tidak diabaikan diam-diam.
- Path seperti `--dir` relatif terhadap proyek, bukan terhadap shell.
- `ai` tidak lagi memuat paket `@ai-sdk/*`: gunakan `provider` `gateway`, `openai` atau `anthropic`, atau `baseUrl` untuk server yang kompatibel dengan OpenAI.
