Halaman ini mencantumkan apa yang berubah untuk aplikasi Anda saat Anda meng-upgrade nuxt-i18n-micro dan paket-paket `@i18n-micro/*`-nya. Baca bagian untuk versi asal Anda sebelum menaikkan versi dependensi. Sebagian besar aplikasi hanya membutuhkan sedikit perubahan kode.

<Tip>

**Berasal dari `@nuxtjs/i18n`?** — Lihat [Migrasi dari @nuxtjs/i18n](/id/guide/migration).

</Tip>

## Setelah 3.30.3: rilis mayor {#after-3-30-3-the-major-release}

Opsi modul, `$t`, `$localePath`, `$switchLocale` dan helper lainnya, komponen, composable, serta utilitas server yang terdokumentasi tetap mempertahankan namanya. Yang berubah adalah perilakunya, sebagian besar berupa perbaikan bug. Paket adapter dan paket routing memiliki perubahan API yang benar-benar breaking: lihat [Paket framework](#framework-packages) dan [Paket lainnya](#other-packages).

### Lakukan ini terlebih dahulu {#do-this-first}

1. **Periksa versi Anda.** Modul membutuhkan Nuxt 3.18 atau lebih baru dan Node 20 atau lebih baru. Nuxt memiliki batas minimum Node sendiri: Nuxt 4.5 mendeklarasikan `^22.19.0 || ^24.11.0 || >=26.0.0`. `nuxt generate` pada Nuxt 3.18.0 itu sendiri juga gagal di Nuxt biasa (`[unstorage] Invalid key: "/"`); 3.21.11 berfungsi. `@i18n-micro/react` membutuhkan React 18 atau lebih baru.
2. **Perbaiki paket yang terpasang.**
   - Hapus `@i18n-micro/hmr`. HMR terjemahan sudah terpasang di dalam modul.
   - Jika pengujian Anda mengimpor `@i18n-micro/test-utils`, tambahkan paket tersebut: `npm install -D @i18n-micro/test-utils`. Paket ini tidak lagi dipasang bersama modul.
   - Ganti `nuxt-i18n-micro-cli` dengan `@i18n-micro/cli`. 28 perintah menjadi 16, `check` menggantikan tiga di antaranya, dan exit code berubah: lihat [panduan CLI](/id/guide/cli#moving-from-nuxt-i18n-micro-cli).
3. **Cari di kode Anda** entri-entri pada tabel di bawah.
4. **Periksa apa yang berada di depan aplikasi.** Dengan `baseUrl` pada locale di balik proxy, lihat [Di balik proxy atau CDN](/id/guide/deployment#behind-a-proxy-or-cdn). Dengan CDN, periksa cache key-nya terhadap header `Vary`: lihat [Caching HTML](/id/guide/deployment#caching-html). Dengan `apiBaseClientHost` atau CSP yang ketat, izinkan link `preload` yang baru: lihat [SEO dan tag head](#seo-and-head-tags).
5. **Perbarui snapshot.** Snapshot head mendapatkan link `preload`, markup switcher berubah ([`<i18n-switcher>` dan `<i18n-link>`](#&lt;i18n-switcher>-and-&lt;i18n-link>)), dan query string pada output `$localeRoute` di-encode secara berbeda.
6. **Buka halaman Anda di setiap locale dan cari kunci mentah.** Layout yang menggunakan kunci dari file halaman sebelumnya kini menampilkannya mentah: pindahkan kunci tersebut ke file root.

<Warning>

**`switchLocaleRoute` dari `@i18n-micro/path-strategy` kehilangan argumen pertamanya** — `switchLocaleRoute(fromLocale, toLocale, route, options)` kini menjadi `switchLocaleRoute(toLocale, route, options)`. **Pemanggilan JavaScript lama tidak gagal: pemanggilan itu mengembalikan hasil yang salah,** karena `fromLocale` dibaca sebagai target dan `toLocale` sebagai rute. Hanya TypeScript yang memberi tahu Anda. `$switchLocaleRoute` milik Nuxt tidak terpengaruh.

</Warning>

17 halaman dokumentasi ini dipindahkan. URL lama di-redirect, sehingga tautan ke halaman tersebut tetap berfungsi.

### URL dan redirect {#urls-and-redirects}

- **`/en` dan `/en/...` menghasilkan 404 di bawah `prefix_except_default`** (dengan `en` sebagai default), sesuai dokumentasi.
- **Prefiks locale dengan huruf besar/kecil atau ejaan lain menghasilkan 404.** `/DE/about` dulu merender rute Jerman dalam locale default, atau me-redirect ke `/en/DE/about`. Halaman tersendiri pada URL tersebut tetap menjadi halaman. Catch-all atau halaman `[slug]` tidak termasuk: `/DE/x` di bawah `[...slug]` dan `/DE` di samping `[slug]` juga menghasilkan 404, sehingga slug CMS yang sama dengan kode locale dalam huruf besar/kecil berbeda kehilangan halamannya. Dengan `ssr: false` tidak ada server yang menjawab, sehingga `/DE/about` menampilkan halaman Jerman.
- **Path halaman dengan huruf besar/kecil berbeda di-redirect ke ejaannya sendiri.** `/T/BASIC` dulu 200 dan kini menjadi `302` ke `/t/basic`.
- **URL yang tidak dikenal tetap 404.** Dengan `autoDetectPath: '*'` atau `'no_prefix'`, `/nope` tidak lagi di-redirect ke `/de/nope` terlebih dahulu. `prefix` mempertahankan redirect (tidak ada yang dilayani tanpa prefiks di sana), begitu juga `/` di mana pun.
- **Path kustom locale lain, tanpa prefiks, menemukan halamannya di bawah `prefix_except_default`.** `/a-propos` dulu 404 dan kini menjadi `302` ke URL locale default (`/about`). Di bawah `prefix` redirect yang sama kini mencapai halaman yang aktif (`/en/about`, dulu `/en/a-propos`, sebuah 404). `prefix_and_default` tetap 404.
- **`prefix` dengan `redirects: false` menjawab 404 pada URL tanpa prefiks** (`/about` dulu `302`), termasuk URL asli dari halaman dengan path default kustom. `$localePath('/about')` tetap menemukan halaman tersebut.
- **Di bawah `prefix_except_default` URL asli dari halaman dengan path default kustom di-redirect ke path tersebut,** termasuk halaman dinamis. `/dir/one` dulu 404 dan kini menjadi `302` ke `/dir-one/one`.
- **`autoDetectPath: '*'` kini juga menerapkan cookie dan `Accept-Language` pada path tanpa prefiks** (`/about` → `/de/about`).
- **Di bawah `prefix` URL tanpa prefiks mempertahankan locale pengunjung.** Dengan cookie `de`, `/about` dan `<NuxtLink to="/about">` biasa menuju `/de/about`, di setiap path, apa pun nilai `autoDetectPath`.
- **Di bawah `prefix_and_default` URL tanpa prefiks adalah locale default.** `/contact` dengan `Accept-Language: de` dulu merender bahasa Jerman lalu melakukan hidrasi dalam bahasa Inggris. Kini dirender dalam locale default; pengunjung mencapai bahasa Jerman melalui `/de/...`.
- **Di bawah `no_prefix` path kustom merender locale-nya sendiri** (`/ueber-uns` berbahasa Jerman dengan preferensi apa pun), dan halaman yang dibatasi dirender dalam locale yang dilayaninya. Path yang dibagi oleh beberapa locale merender preferensi jika preferensi tersebut adalah salah satunya, dan di bawah `baseUrl` menjadi halaman di setiap domain mereka. Locale-locale tersebut berbagi satu record, `localized-<page>-<first locale>`.
- **`noPrefixRedirect` mengikuti locale pengunjung.** Dengan cookie `de`, `/about` menuju `/ueber-uns`, dan dirender dalam bahasa Jerman, bukan ke `/about-us` milik locale default. Locale tanpa path kustom sendiri tetap di `/about`.
- **Redirect `routeRules` tanpa halaman tidak dilokalkan.** `/de/old` dulu 200 kosong, kini menjadi 404: tambahkan aturan untuk path berprefiks jika Anda membutuhkannya. Tautan dari locale lain ke aturan semacam itu mempertahankan path seperti yang ditulis dan mendarat di target aturan tersebut.
- **Route rules menjangkau path kustom.** `/blog/**` juga berlaku untuk `/de/artikel/:slug` ketika `blog/[slug]` memiliki path tersebut, dan aturan juga disalin di bawah `no_prefix`. Sibling statis seperti `/de/artikel/news` juga cocok dengan pola tersebut. Aturan yang sudah ditulis di bawah prefiks locale tetap seperti yang ditulis.
- **Locale dengan `disabled: true` langsung menjawab 404 pada prefiksnya**, dan tautan ke locale tersebut tetap berada di halaman. Locale yang dinonaktifkan saat runtime melakukan hal yang sama: dulu dirender dalam locale fallback.
- **Halaman 404 milik modul bertuliskan `Page Not Found`** pada prefiks locale yang dinonaktifkan dan pada prefiks milik host sendiri, di mana Nuxt dulu menuliskan `Page not found: /de/about`. Status kodenya sama.
- **`customRegexMatcher` tidak lagi menghasilkan 404 untuk halaman nyata** yang segmen pertamanya terlihat seperti locale.
- **Nama rute terlokalisasi kini konsisten.** Child di bawah record locale bersama mempertahankan nama halaman, `no_prefix` mematuhi `localizedRouteNamePrefix`, dan parent dengan child index tetap tanpa nama.
- **Halaman yang ditambahkan modul tanpa `name`** (`extendPages`) dilokalkan dan mendapatkan nama, dengan varian locale dan `hreflang`. Dulu halaman tersebut tetap tidak terlokalisasi.
- **Entri `nuxt.config` mengalahkan `$defineI18nRoute`,** dalam bentuk kunci apa pun (`about/team`, `/about/team`, `about-team`). Mana yang menang dulu bergantung pada ejaannya.
- **Peringatan build baru:** nilai `localeRoutes` yang diawali kode locale-nya sendiri (`fr: '/fr/article'`), dan path kustom child yang berada di luar parent-nya.
- **Mode hash berfungsi di bawah `prefix`.** Dokumennya adalah `/`, dan `/en` atau `/about` di-redirect ke dalam hash.
- **`/#/de/x` merender bahasa Jerman** di bawah `prefix_except_default` dan `prefix_and_default`. Dulu merender bahasa Inggris dengan hydration mismatch.

### Tautan dan objek rute {#links-and-route-objects}

- **Locale yang tidak melayani sebuah halaman menautkan ke berandanya.** `$localeRoute`, `$switchLocalePath`, dan switcher tidak lagi mengembalikan halaman locale lain.
- **Kode locale yang tidak dikenal menuju locale default.** `$localePath(path, 'xx')` dan `$localeRoute` dulu memberikan `/xx`.
- **`$localePath` mengembalikan string dengan skema `http(s):`, `mailto:`, atau `tel:` apa adanya, dan `path` serta `fullPath` dari `$localeRoute` membawanya tanpa perubahan**, jadi jangan berikan nilai yang belum diperiksa (parameter `?next=`) sebagai target tautan. `//host` dan nama polos seperti `x.com` tetap dianggap path, di origin ini pada setiap locale, dan tidak ada tautan hasil perubahannya yang keluar dari origin: `/de//x.com` ke locale default adalah `/x.com`. Backslash dihitung sebagai garis miring.
- **`$localePath` meng-encode path:** `/a b` menghasilkan `/a%20b`.
- **`$localeRoute` dan `$switchLocaleRoute` mengembalikan objek biasa,** aman di `ref`, `reactive`, `useState`, JSON, dan spread. Ketika sebuah parameter perlu di-escape, objeknya adalah `{ path, fullPath, query, hash }` (`$localeRoute` menambahkan `href`), tanpa `name` atau `params`, dan URL tetap sama sebelum dan sesudah reload. URL biasa memiliki keduanya. `name` adalah hal baru: objek lama tidak pernah memilikinya. Kode yang membaca `.name` atau `.params` harus menangani ketiadaannya, dan bentuk mana yang Anda dapatkan bergantung pada nilainya.
- **Di bawah `trailingSlash`, `$switchLocaleRoute` selalu mengembalikan bentuk path tersebut,** termasuk untuk slug biasa, dan redirect server mengikuti `trailingSlash`. Hasil dan header `Location` dapat berubah di bawah opsi tersebut.
- **Nilai query di output `$localeRoute` menggunakan encoding vue-router:** `/` tetap literal dan spasi menjadi `+` (`?redirect=/v2`, dulu `%2Fv2`). Nilai hasil decode-nya sama, tetapi snapshot dari `href` semacam itu berubah.
- **Tautan tanpa path tetap di halaman saat ini.** `$localePath('#top')`, `'?p=2'`, `''`, dan `{ query }` mempertahankan halaman tempat mereka berada; `'#top'` dulu dibaca dari root situs. `'about'` polos tetap berarti `/about`.
- **Spread.** `{ ...route, query }` dan `{ ...route, hash }` mempertahankan perubahannya, juga melalui `$switchRoute`. `path` baru menang di `$localeRoute`, `$localePath`, dan `$switchRoute`. `{ ...route, params }` berfungsi pada rute bernama; pada rute berbentuk path, path yang menang dan params diabaikan, disertai peringatan dev dari vue-router. Gunakan `$localeRoute({ name, params })`.
- **`$switchRoute` tetap berada di dalam aplikasi.** `baseUrl` milik sebuah locale, `mailto:`, dan `tel:` keluar dari aplikasi; string lainnya dianggap path.
- **`excludePatterns`** mencocokkan segmen utuh (`'/admin'` tidak lagi cocok dengan `/administrator`), dan glob dijangkarkan (`/docs/*` tidak lagi cocok dengan `/en/docs/x`). Pola `RegExp` kini mencapai runtime; dulu pola ini hilang di sana. Halaman yang cocok dengan pola tersebut tidak dilokalkan: tanpa `hreflang`, dan menggunakan locale default di bawah `prefix_except_default`. Periksa pola Anda terhadap [Mengecualikan path](/id/guide/excluding-static-files).

`%` atau `?` di dalam parameter tidak bertahan setelah reload yang dirender server pada Nuxt 4.5.2, di aplikasi apa pun: itu masalah upstream, bukan modul.

### Domain locale {#locale-domains}

- **`locales[].baseUrl` kini merutekan request.** Satu build melayani setiap domain: lihat [Layer dan domain](/id/guide/layers#multiple-domains). Dengan `baseUrl` diatur, locale dari domain lain menghasilkan 404 di host ini (`/en/about` di `example.de`), dan tautan ke locale di host yang sama bersifat relatif. Request di host lain mana pun, termasuk `localhost`, berperilaku seperti sebelumnya, kecuali bahwa canonical dan `hreflang` menggunakan `metaBaseUrl` jika diatur, atau `baseUrl` milik locale default jika tidak, dan bukan origin dari request.
- **Di balik proxy yang menulis ulang `Host`,** setiap request jatuh ke konfigurasi build sampai Anda mengatur [`trustForwardedHost`](/id/api/module-options#trustforwardedhost). Default-nya `false`, berbeda dengan `metaTrustForwardedHost`. Lihat [Di balik proxy atau CDN](/id/guide/deployment#behind-a-proxy-or-cdn).
- **`nuxi generate` dengan `baseUrl` membutuhkan `NUXT_I18N_DOMAIN`, sekali per domain.** Tanpanya build memberi peringatan, dan locale-locale tersebut menjadi tautan tanpa halaman. Lihat [Situs statis](/id/guide/deployment#static-site-(nuxi-generate)).
- **Tautan ke locale dengan `baseUrl` melalui `$localePath` atau `<i18n-link>`.** `<NuxtLink :to="$localePath(x, 'fr')">` dan `<i18n-link :to="$localeRoute(x, 'fr')">` adalah URL absolut tersebut, dan klik akan menuju ke sana. Router tidak menerima objek absolut: `<NuxtLink :to="$localeRoute(x, 'fr')">` dan `router.push($localeRoute(x, 'fr'))` tetap menjadi `/https://fr.example.com/...`, sebuah path dari aplikasi ini. Di `localhost` atau host preview, setiap locale dengan `baseUrl` adalah tautan semacam itu, termasuk locale saat ini. Di dalam kode, gunakan `navigateTo($localePath(x, 'fr'), { external: true })`.
- **Beranda sebuah domain ditulis tanpa garis miring di akhir di mana pun** (`https://example.de`), di tautan, canonical, dan `hreflang`.
- **Di bawah `prefix`, tautan ke domain lain mempertahankan prefiks locale, dengan atau tanpa `baseDefault`.** `https://example.de/de/about`, bukan `https://example.de/about`, yang hanya me-redirect.
- **Di bawah `prefix_except_default` dengan `baseDefault` pada locale selain default build, rute mempertahankan setiap prefiks** agar domain lain dapat menautkannya. `/en` tetap 404. Hanya kode yang membaca `router.getRoutes()` yang melihat perbedaannya.
- **Di bawah `prefix_except_default` prefiks milik host sendiri menghasilkan 404 di host `baseDefault`-nya.** `/de/x` di host `de` dulu 200.
- **`$getI18nConfig().locales` hanya berisi apa yang dilayani host.** `linkLocales` berisi semuanya, dan `$getLocales()` tetap lengkap.

### Navigasi dan `$switchLocale` {#navigation-and-$switchlocale}

- **Navigasi diterapkan saat di-commit.** Kamus, locale, params, dan head berubah di `router.afterEach`, sehingga navigasi yang dibatalkan atau diblokir tidak mengubah apa pun, dan tautan halaman lama tetap valid saat chunk berikutnya dimuat. `beforeResolve`, `beforeRouteEnter`, atau global guard yang lebih belakangan kini melihat kamus dan locale lama. Route middleware tidak terpengaruh.
- **Chunk yang gagal mempertahankan kamus saat ini.** 5xx, error jaringan, atau body yang rusak pada file root dulu menampilkan kunci mentah. Halaman baru kini dirender dengan string lama, dan navigasi berikutnya mencoba lagi. 404, atau shell SPA dari host statis di tempat file tersebut, memberikan kamus root sampai reload berikutnya.
- **`$switchLocale` di-resolve menjadi `true` atau `false`** (dulu tidak me-resolve apa pun), `false` ketika kamus locale tidak diterapkan. Tipenya `Promise<boolean>`, dan `$switchRoute` bertipe `Promise<void>`.
- **`$switchLocale` adalah pilihan eksplisit.** Saat tiba, ia menyimpan locale, termasuk pada 404. Jika navigasi diblokir, dibatalkan, atau melempar error, preferensi yang tersimpan dan state tetap seperti semula, dan error dilempar ulang. Perpindahan ke host lain menyimpannya terlebih dahulu. Di bawah `no_prefix` dan dalam mode hash, perpindahan tetap berlaku apa pun yang dilakukan navigasi. Pada halaman dengan satu URL untuk setiap locale (`excludePatterns`) pilihan tidak dibatalkan, dan URL halaman berikutnya yang menentukan: di bawah `prefix_except_default` tautan tanpa prefiks kembali ke locale default.
- **Di bawah `no_prefix`, `$switchLocale` mempertahankan halamannya ketika dua halaman berbagi path kustom,** termasuk dengan params yang di-escape. Reload URL semacam itu, dan `$localeRoute` dengan param yang di-escape, mendarat di record pertama.
- **Redirect klien mempertahankan mode navigasinya.** `<NuxtLink to="/about">` biasa di bawah `prefix` menambahkan entri riwayat alih-alih menimpa entri saat ini; `router.replace` tetap mengganti.
- **`$setI18nRouteParams` dan `useI18nHead` dari server bertahan setelah hidrasi.** Setelah mendarat di `/news/2`, switcher menautkan ke slug yang diterjemahkan (`/de/news/2-zwei`), bukan `/de/news/2`, juga di HTML server, di mana pun switcher berada, ketika halaman mengatur params selama SSR. Params dihapus ketika navigasi ke path lain di-commit, termasuk `/news/1` ke `/news/4`: atur lagi di halaman baru.
- **`$setI18nRouteParams` yang dibaca di setup terikat pada halaman tersebut.** Pemanggilan terlambat dari halaman yang sudah ditinggalkan tidak melakukan apa pun. `useNuxtApp().$setI18nRouteParams` kini merupakan accessor, dan dua kali pembacaan memberikan dua fungsi. Tidak ada setter-nya: `useI18n().$setI18nRouteParams = fn`, seperti yang mungkin dilakukan stub pengujian, melempar error dalam strict mode, jadi stub `useI18n` itu sendiri. Di layout atau `app.vue` ini adalah fungsi biasa, karena tidak ada yang ditinggalkan di sana.
- **Server menulis ulang tautan `<i18n-switcher>` ketika render selesai**, pada halaman dengan params, karena switcher di layout dirender sebelum setup async milik halaman. Tautan `$switchLocalePath` yang ditulis manual tidak ditulis ulang: lihat [rute locale kustom](/id/guide/custom-locale-routes). Di bawah SSR streaming Nuxt, HTML pertama mempertahankan params dari URL.
- **Prop bernama `locale` pada server component mengatur locale render-nya**, sehingga `<Greeting :locale="$getLocale()" />` mengikuti URL dan perpindahan locale. `$getLocale()`, `$localePath`, dan `$getLocaleName` di dalamnya juga mengikuti prop tersebut. Lihat [terjemahan sisi server](/id/guide/server-side-translations). Tanpa prop tersebut, komponen tetap menggunakan cookie atau default.
- **Halaman `keepalive` mendapatkan kembali params dan head-nya** saat kembali.
- **Halaman bersarang yang diatur ke `false` di bawah `prefix_except_default` tidak memiliki URL locale.** `/de/parent/kid` dengan `globalLocaleRoutes: { 'parent-kid': false }` dulu dilayani dan kini menjadi 404: halaman tetap berada di `/parent/kid`.

### Deteksi locale dan cookie {#locale-detection-and-the-cookie}

Satu urutan prioritas di mana pun, dijelaskan di [Deteksi locale](/id/guide/locale-detection).

- **`?locale=` hanya dihitung pada halaman di bawah `no_prefix`.** Di bawah strategi berprefiks, URL yang menentukan; `/about?locale=de` tidak lagi merender bahasa Jerman di bawah `lang="en"`. `?locale=de&locale=fr` membaca nilai pertama, dulu `"de,fr"`.
- **`Accept-Language` mematuhi nilai `q`** (`fr;q=0.1, de;q=0.9` → `de`; `q=0` mengecualikan sebuah bahasa). Pencocokan regional tidak lagi bergantung pada urutan `locales`, dan tidak pernah menyilangkan aksara Tionghoa.
- **Navigasi klien ke sebuah halaman menyimpan locale-nya di cookie, juga pada halaman tanpa prefiks dari locale default.** Dengan `localeCookie` diatur, pengunjung yang mengklik tautan ke `/about` kini memiliki `user-locale=en`, dan perubahan bahasa browser setelahnya tidak lagi me-redirect `/`. Pemuatan pertama URL tersebut tidak menyimpan apa pun. Di bawah `no_prefix` dan dalam mode hash, navigasi hanya menyimpan perubahan.
- **404 tidak menulis cookie:** baik responsnya, maupun navigasi klien biasa ke sana, dalam mode apa pun. Di bawah `no_prefix` URL yang tampak berprefiks juga tidak menulis cookie.
- **Di bawah `no_prefix`, `localeCookie: null` yang eksplisit dipatuhi.** Dulu berubah menjadi `user-locale`. Atur di blok `i18n` pada `nuxt.config`: `null` di `modules: [[name, opts]]` atau di sebuah layer tetap hilang.
- **Mode hash hanya membaca cookie `hash-locale`.** `user-locale=de` sendirian tidak lagi dihitung.
- **Cookie locale yang rusak diabaikan dan dibiarkan apa adanya,** alih-alih membuat setiap halaman SSR gagal dengan 500. Cookie tidak lagi dihapus pada setiap request, yang juga dulu menghalangi halaman berprefiks menyimpan locale-nya.
- **Locale dari URL didahulukan.** `setLocale('de')` dari sebuah plugin pada `/en/...` tidak lagi memuat kamus `de`, dan kode yang tidak dikenal di state diabaikan.
- **Helper API server** (`useLocaleServerMiddleware`, `useTranslationServerMiddleware`) menggunakan satu urutan di setiap rute: `?locale` → param `[locale]` atau prefiks → cookie → header → default. Keduanya kini mematuhi `localeCookie: null` dan `autoDetectLanguage: false`, dan menyimpan cache kamus per locale.
- **Override runtime menjangkau routing.** `NUXT_I18N_DEFAULT_LOCALE` dan `disabledLocales` runtime kini mengubah strategi yang dihasilkan (locale yang dinonaktifkan berhenti dirutekan), dan `disabledLocales` runtime ditambahkan ke milik build. Di bawah `prefix_except_default` dan `prefix_and_default`, `defaultLocale` runtime diabaikan dengan peringatan, karena rute tanpa prefiks milik locale tersebut dihasilkan saat build. `fallbackLocale` runtime harus berupa locale yang diaktifkan: jika tidak, nilai tersebut dibuang dengan peringatan dan nilai dari build berlaku jika locale tersebut diaktifkan. Lihat [Override runtime](/id/guide/runtime-overrides).

### SEO dan tag head {#seo-and-head-tags}

- **`dir="auto"` tidak lagi menjadi default.** Locale tanpa `dir` dulu mendapatkan `dir="auto"`, yang memperlambat parsing halaman besar. Kini bahasa RTL yang dikenal mendapatkan `dir="rtl"`, dan locale lainnya tidak mendapatkan atribut. Ini berlaku untuk Nuxt, `@i18n-micro/vue`, `astro`, dan `vitepress`. Jika Anda mengatur `dir: 'auto'` pada sebuah locale untuk mempertahankan output lama, biayanya sekitar 1 detik parsing pada 20.000 elemen: lihat [Arah teks](/id/guide/seo#text-direction).
- **Setiap halaman SSR memiliki tag baru:** `<link rel="preload" as="fetch" crossorigin="anonymous" href="/_locales/...">`, termasuk halaman 404. Dengan `apiBaseClientHost`, `href` berada di host tersebut, yang membutuhkan CORS. CSP yang ketat harus mengizinkannya.
- **`hreflang` hanya mencantumkan locale yang melayani halaman tersebut**; `x-default` hanya dihasilkan ketika locale default melayaninya.
- **Halaman yang tidak dilokalkan tidak memiliki `hreflang` atau `og:locale:alternate`.**
- **Canonical dan `hreflang` menyertakan `app.baseURL`** ketika origin berasal dari request. `metaBaseUrl` dan `site.url` tetap seperti yang ditulis.
- **Halaman 404 membawa `<html lang dir>`**, dalam locale dari URL. Halaman tersebut tidak memiliki canonical, `hreflang`, `og:url`, `og:locale`, atau alternatif, juga ketika modul sendiri yang menjawab 404 pada record yang cocok (`/en/...`). Tag yang Anda berikan melalui `replace` pada `useI18nHead` tetap ada, jadi lewati tag tersebut di halaman error.
- **Canonical, `og:url`, dan `hreflang` mempertahankan query yang masuk whitelist** (`/about?page=2`), juga di server: dulu dihapus selama SSR. `page`, `sort`, `filter`, `search`, `q`, `query`, dan `tag` masuk whitelist secara default; lihat [`canonicalQueryWhitelist`](/id/api/module-options#canonicalquerywhitelist).
- **`X-Forwarded-Host` yang tidak dapat di-parse diabaikan** alih-alih menghasilkan 500 di setiap halaman. Tanpa host yang dapat digunakan, dan tanpa `metaBaseUrl` atau `site.url`, URL canonical dan `hreflang` pada respons tersebut bersifat relatif. `Host` yang tidak dapat di-parse tetap menghasilkan 500, seperti pada aplikasi Nuxt biasa.
- **`disableMeta` kini berfungsi,** baik di `$defineI18nRoute` maupun `routeDisableMeta`, juga ketika diatur di `nuxt.config`: halaman tidak memiliki `hreflang`, canonical, atau `og:locale`. `lang` dan `dir` tetap ada.
- `useLocaleHead()` juga mengembalikan `build()`, sebuah getter untuk `useHead(() => build())`.
- Pada build biasa tanpa `metaBaseUrl`, `X-Forwarded-Host` tetap memilih host di tag-tag ini, seperti sebelumnya. Tetapkan `metaBaseUrl` jika origin dapat dijangkau secara langsung: lihat [Di balik proxy atau CDN](/id/guide/deployment#behind-a-proxy-or-cdn).

### Terjemahan {#translations}

- **Penggabungan bersifat mendalam di setiap level.** File root, halaman, dan fallback dulu menggunakan penggabungan 2 level, sehingga `a.b.c` dari fallback atau root hilang dalam mode source dan di dev. Semua mode kini memberikan kamus yang sama.
- **Rantai fallback diikuti sampai akhir** (`fr` → `de` → `en`) di setiap mode.
- **Penggabungan dilakukan berdasarkan locale, bukan jenis file.** File root dari locale aktif kini mengalahkan file halaman dari locale fallback. Lihat [Locale fallback](/id/guide/translations#fallback-locales).
- **Entri `locales` milik proyek mengalahkan milik layer** untuk `code` yang sama; layer hanya mengisi celah.
- **Halaman tanpa folder `pages/<name>/` sendiri membaca kamus root,** termasuk halaman child. Dulu halaman tersebut mendapatkan `{}` dan menampilkan kunci mentah. Output mendapatkan satu file per halaman semacam itu, dan `__root/<locale>/data.json` per locale: `/_locales/<any name>/en/data.json` adalah 200 dengan kunci root, dulu `{}`. Hal ini penting untuk monitoring, untuk allow-list di host statis, dan untuk tool yang membaca pohon tersebut.
- **`disablePageLocales: true` hanya membaca file root;** `pages/index` tidak lagi digabungkan.
- **Kunci halaman yang ditinggalkan berhenti di-resolve ketika elemennya meninggalkan dokumen.** Jika sebuah layout menggunakan kunci yang hanya dimiliki file halaman sebelumnya, pindahkan kunci tersebut ke file root. Kunci milik parent tetap ada selama child-nya ditampilkan, termasuk parent dengan child `index`, sampai navigasi berikutnya. Di antara dua child dari satu parent, kunci milik parent sendiri membutuhkan kamus child atau kamus root.
- **`$clearCache()` memuat ulang kamus halaman saat ini** dan mempertahankan kamus lama di layar sampai yang baru tiba. Pemuatan ulang yang gagal mempertahankan kamus lama, respons yang diminta sebelum pembersihan dibuang, dan halaman dalam transisi keluarnya tetap diterjemahkan.
- **`$has(key, route)` mematuhi rute.**
- **`$loadPageTranslations` pada halaman yang belum dikunjungi tidak lagi menghentikan file-nya dimuat.** File dimuat pada kunjungan pertama dan kunci Anda tetap berada di atasnya. Halaman dulu menampilkan kunci mentah sampai reload.
- **HMR terjemahan menerapkan perubahan di tempat**, tanpa reload halaman; kunci yang dihapus menghilang dan perubahan root menjangkau setiap halaman.
- **File locale yang rusak memberi peringatan sekali beserta path-nya, di setiap mode.** Dev dulu melempar error dan premerged melewatinya secara diam-diam, sehingga aplikasi yang mengandalkan dev gagal keras tidak lagi melihat hal itu.

### Bentuk jamak dan pemformatan {#plurals-and-formatting}

- `$tc` dengan hitungan negatif, pecahan, atau sangat besar mengambil bentuk terakhir dengan hitungan sebenarnya; `{ count: null }` tidak lagi melempar error; kunci plural yang hilang mencapai missing handler.
- `$tdr` memberikan tanggal masa depan yang sebenarnya (`in 3 days`, atau `tomorrow` dengan `numeric: 'auto'`) dan `Invalid Date` untuk input yang tidak valid. Kurang dari satu detik di masa lalu adalah `0 seconds ago`.
- **`$tn`, `$td`, dan `$tdr` mengikuti `iso`**, seperti halnya bentuk jamak: `{ code: 'en', iso: 'en-GB' }` kini memformat tanggal sebagai `31/10/2026`. Dalam kode locale, `_` dibaca sebagai `-`, sehingga `en_US` tidak lagi melempar error, dan kode yang tidak dikenal `Intl` diformat sebagai `en` alih-alih mengikuti locale mesin. Format bernama tetap dicari berdasarkan `code`.
- Placeholder `{param}` hanya membaca params yang Anda berikan (`{constructor}` tetap seperti yang ditulis).
- Nama `{placeholder}` boleh berisi karakter apa pun kecuali kurung kurawal dan spasi: `{firstName}`, `{first-name}`, dan `{user.name}` dibaca dari `params`. Tanpa param tersebut, placeholder tetap seperti yang ditulis, seperti sebelumnya.
- `defaultValue` diinterpolasi, di `$t` dan `$tc`: `$t('missing', { n: 1 }, 'Got {n}')` memberikan `Got 1`, dulu memberikan `Got {n}`. Default yang bukan string dikembalikan apa adanya.
- `$tc` pada terjemahan kosong menjawab `''`, seperti `$t`. Dulu menjawab nilai default atau kunci.
- **Template plural mempertahankan maknanya, dengan satu pengecualian.** Tabel mencantumkan setiap bentuk. Untuk mendapatkan kategori `Intl.PluralRules`, nyatakan dengan [penanda `=0 `](/id/api/methods#$tc) yang baru: `=0 no apples | one apple | {count} apples`.

  | Bentuk | Contoh (dalam `uk`) | Sebelumnya | Sekarang |
  | --- | --- | --- | --- |
  | Template apa pun dalam locale dengan satu atau dua kategori bilangan bulat (`en`, `de`, `fr`, `es`, `ja`...) | `none \| one \| {count} many` | berdasarkan indeks | **tidak berubah** |
  | Satu bentuk per kategori | `one \| few \| many` | berdasarkan indeks: 21 → `many` | **tidak berubah**. Tambahkan penanda agar 21 → `one` |
  | Bentuk nol terlebih dahulu, tiga bentuk | `none \| one \| many` | berdasarkan indeks | **tidak berubah** |
  | Placeholder lain | `no items \| {n} item \| {n} items` | berdasarkan indeks | **tidak berubah** |
  | `{count}` di setiap bentuk | `{count} many \| {count} one \| {count} few` | berdasarkan indeks | **tidak berubah** |
  | Lebih sedikit atau lebih banyak bentuk daripada di bawah | `a \| b`, `none \| one \| two \| {count} many` | berdasarkan indeks | **tidak berubah** |
  | Dalam `lv`, `prg`, `blo`, `cv`, `ksh`, `lag` | `none \| one \| {count} many` | berdasarkan indeks | **tidak berubah** |
  | Ditandai dengan `=0 ` | `=0 none \| one \| many` | penanda ditampilkan sebagai teks | bentuk nol, lalu kategori |
  | **Bentuk nol tanpa placeholder, lalu satu bentuk per kategori, dengan `{count}` di setiap bentuk yang dibagi oleh beberapa hitungan** | `none \| {count} one \| {count} few \| {count} many` | berdasarkan indeks: 3 → `3 many`, 21 → `21 many` | **berdasarkan kategori**: 3 → `3 few`, 21 → `21 one`. 0, 1, 2, dan setiap hitungan yang tetap di `many` memberikan hasil yang sama |

  Bentuk terakhir membutuhkan tiga kategori atau lebih (`ru`, `uk`, `pl`, `cs`, `sk`, `hr`, `sr`, `lt`, `ro`, `sl`, `he`, `ar`, `cy`...). Dalam `ar`, `one` dan `two` adalah hitungan tunggal, sehingga kedua bentuk tersebut tidak membutuhkan angka.
- **Kode locale yang tidak dikenal `Intl` mendapatkan aturan indeks**, dengan atau tanpa kategori dari penanda: `ua` tidak lagi mengikuti locale mesin. Atur `iso`: `{ code: 'ua', iso: 'uk-UA' }` menghasilkan bentuk jamak bahasa Ukraina, di modul dan di `@i18n-micro/vue`.
- **Aturan `plural` kustom mempertahankan signature-nya** dan tetap mendapatkan kode locale. Aturan tersebut membaca nilai mentah, sehingga template yang ditandai mencapainya dengan `=0 ` di tempatnya, dan aturan tersebut mendapatkan hitungan sebagai `Number`: `1.5` di mana dulu mendapatkan `1`. Mengembalikan `null` akan kembali ke aturan bawaan, yang mematuhi penanda.
- **Opsi `timeZone`.** Atur (`Europe/Berlin`) untuk merender satu tanggal kalender di server dan di setiap browser. Opsi ini tidak berpengaruh pada `relativeDate`, yang bergantung pada jam.

### `<i18n-t>` {#&lt;i18n-t>}

Bagian ini membahas `<i18n-t>` di modul dan `I18nT` di `@i18n-micro/vue`. Untuk framework lain, lihat [Paket framework](#framework-packages).

- **`html` meng-escape `params`, dalam setiap kasus, dan mengabaikan semua slot.** Hanya terjemahan yang dianggap markup tepercaya. Param yang sengaja berisi markup kini ditampilkan sebagai teks: letakkan markup di terjemahan dan berikan data sebagai params, atau gunakan slot tanpa `html`.
- **Slot berfungsi dengan `plural`, `number`, `date`, dan `relativeDate`,** dan slot `default` menerima `{ translation }` dalam kasus-kasus tersebut juga. Setiap `{name}` diisi, bukan hanya yang pertama.
- **Slot mengalahkan param dengan nama yang sama.** Nilai param yang terlihat seperti placeholder tetap menjadi teks. Dengan `customPluralRule` atau `plural` kustom, aturan mengembalikan string yang sudah jadi, sehingga param yang diinterpolasinya dapat dianggap sebagai placeholder di sana.
- **`null` berarti tidak diatur** untuk `plural`, `number`, `date`, dan `relativeDate`. `:plural="null"` dulu membuat render gagal, `:date="null"` merender 1970.
- `plural` menghitung seperti `$tc`, dengan `Number`: `1.5` tetap `1.5` dan mengambil bentuk terakhir, dulu dipotong menjadi `1`; `"2 items"` adalah `NaN`, dulu `2`; `""` adalah `0`. `customPluralRule` juga melihat `1.5`. Kontrak lainnya tidak berubah: argumen yang sama, jawabannya digunakan apa adanya, `null` merender kosong.
- `hideIfEmpty` berlaku untuk `plural`, `number`, `date`, dan `relativeDate`. Nilai yang disembunyikan merender sebuah komentar, bukan text node kosong, sehingga pengujian yang membaca `''` melihat `<!---->`.
- **Kunci yang hilang di bawah `html` adalah teks.** Kunci di-escape, karena hanya terjemahan yang tepercaya dan kunci dapat berasal dari request. `defaultValue` adalah milik Anda dan tetap menjadi markup.
- Dengan `plural`, `defaultValue` atau kunci tetap utuh ketika tidak ditemukan, seperti di `$tc`: `a | b` tidak lagi dipecah.
- `defaultValue` menggantikan kunci yang hilang di setiap cabang, bukan kunci itu sendiri, dan `customPluralRule` mendapatkannya melalui getter-nya ketika tidak ditemukan. Dulu hanya berpengaruh setelah `hideIfEmpty`.
- `<i18n-t>` dengan `number`, `date`, atau `relativeDate` mempertahankan `params`; params tersebut digabungkan.
- Output `date` dan `relativeDate` membawa `data-allow-mismatch="text"`: jam atau zona waktu yang berbeda antara server dan browser tidak lagi memberi peringatan selama hidrasi. Di samping slot bernama, teks di sekitar slot berada dalam `<span>` sendiri, karena Vue hanya memeriksa atribut pada teks tunggal sebuah elemen.
- Atribut `.innerHTML` dan `textContent` dibuang bersama dengan `innerHTML`.
- `<i18n-t>` dan `<i18n-group>` membaca kamus aktif, seperti `$t`, bukan chunk milik rute. Chunk yang dikeluarkan (`cacheMaxSize`) tidak lagi menampilkan kunci mentah. Halaman dalam transisi keluarnya kini membaca apa yang dibaca `$t` di sana: kamus halaman baru, dan jatuh ke kamusnya sendiri jika tidak ditemukan, sehingga kunci yang didefinisikan kedua halaman menampilkan teks baru, dan setelah perpindahan locale kuncinya sendiri ditampilkan mentah sampai halaman tersebut di-unmount.

### `<i18n-switcher>` dan `<i18n-link>` {#&lt;i18n-switcher>-and-&lt;i18n-link>}

- **Klik pada tautan switcher adalah satu navigasi.** Tautan ini adalah `<a>` biasa yang memanggil `$switchLocale`, bukan `NuxtLink` ditambah click handler, sehingga kelas `router-link-active` hilang. `href` tetap membawa `app.baseURL`, dan tautan locale saat ini tetap memiliki `aria-current="page"`. Ctrl/cmd-klik membuka tab baru dan membiarkan tab ini. Tautan mempertahankan query dan hash.
- Tombolnya bertipe `type="button"`, sehingga tidak lagi men-submit form di sekitarnya, dan memiliki `aria-expanded`. `aria-haspopup` dihapus, di modul, `@i18n-micro/vue`, dan `@i18n-micro/astro`: atribut itu menjanjikan menu, padahal daftarnya berupa tautan. Escape dan klik di luar menutup dropdown; dua switcher tidak lagi tetap terbuka bersamaan.
- Wrapper dan dropdown memiliki kelas `i18n-switcher-wrapper` dan `i18n-switcher-dropdown`; tombol memiliki `i18n-switcher-button` selain `language-switcher`, dan label-nya berada dalam `<span>`. Gaya default menggunakan properti CSS logis (`inset-inline-start`, `margin-inline-start`), dan caret-nya adalah `▾`. Dropdown memiliki `z-index: 1000` (dulu 10), `min-width: 150px`, dan `box-shadow`, wrapper memiliki `vertical-align: middle`. Setiap tautan memiliki `lang`, dan `dir` ketika locale mengaturnya.
- `<i18n-link>`: `https://`, `mailto:`, dan `tel:` dicocokkan tanpa memperhatikan huruf besar/kecil (`HTTPS://x.com`, `Mailto:`). `report.pdf` atau `index.html` polos adalah rute, bukan `https://report.pdf`; `example.com` dan `example.com:8080` tetap eksternal. Akhiran file yang juga merupakan TLD (`example.md`, `x.zip`) dihitung sebagai file: tulis `https://`. `activeStyle` mengabaikan garis miring di akhir, query, dan hash. Kini bertipe `CSSProperties`, sehingga beberapa nilai bertipe mungkin perlu diubah.

### Hook, plugin, dan tipe {#hooks-plugins-and-types}

- **`i18n:register` berjalan di `app:created` saat startup,** setelah semua plugin alih-alih di antara plugin. Plugin dengan `order` di atas 1 atau `enforce: 'post'` kini juga dipanggil subscriber-nya saat startup, tetapi tidak lagi membaca kunci yang terdaftar di `setup`-nya sendiri. Dalam navigasi, hook ini kini berjalan sebelum guard `router.beforeEach` milik plugin lain.
- **`i18n:register` mendapatkan locale dari halaman yang diisinya.** Di bawah `hashMode`, navigasi yang mengubah locale dulu meneruskan locale lama, dan kunci-kunci mendarat di chunk yang salah.
- **`i18n:register` adalah hook runtime:** daftarkan dengan `nuxtApp.hook('i18n:register', …)` di dalam plugin, tanpa `@ts-expect-error`. Lihat [Hook](/id/api/events).
- **`hooks: false` dan `define: false`** tetap menonaktifkan bagiannya masing-masing.
- **Dengan `plugin: false`, `$defineI18nRoute` tetap dapat dipanggil** dan tidak melakukan apa pun saat runtime. Dulu membuat halaman crash.
- Opsi `hooks` tidak lagi mendokumentasikan `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`; keduanya tidak pernah dipancarkan.
- `const { $defineI18nRoute } = useNuxtApp()` di sebuah halaman kini berfungsi dengan konfigurasi yang menggunakan variabel.
- `useI18n()` memiliki lebih banyak kunci: `clearCache`, `pluralFunc`, `pluralLocale`. `clearCache` ada di tipenya.
- `$getRouteName(route)` menjawab untuk rute yang diberikan. Dulu mengembalikan string kosong.
- `useI18nLocale()` menghapus `getLocaleWithServerFallback(serverLocale)`: tulis `getPreferredLocale() ?? serverLocale ?? null`.
- **`$getI18nConfig()` bersifat read-only di server dalam mode dev.** Penulisan melempar error di sana, dan di production penulisan tersebut akan menjangkau setiap request.

### Server, build, dan deployment {#server-build-and-deployment}

- **File payload sebuah halaman hanya berisi apa yang berbeda dari root locale.** Klien memuat root sekali dan menggabungkan setiap halaman di atasnya, sehingga bundle disk dan Edge menyusut dan halaman kedua hanya memakan sebagian kecil biaya halaman pertama. `premerged` kini menulis `__root/<locale>/data.json`, dan `/_locales/<page>/<locale>/data.json` hanya berisi selisihnya: apa pun yang membaca file tersebut secara langsung harus menggabungkan keduanya. Kamus lengkap tetap merupakan file yang valid, sehingga host atau mode `source` yang menyajikannya tetap berfungsi.
- **File kamus di-cache berdasarkan versi.** URL dengan `?v=` saat ini dipatok selama satu tahun di server Node, URL lain melakukan revalidasi, dan salinan statis milik host menjawab `max-age=60`: lihat [Header cache](/id/guide/deployment#cache-headers-and-datebuild). `httpCacheControl: false` mempertahankan `max-age=0`. Terjemahan yang diubah tanpa rebuild hanya mencapai browser ketika `v` berubah: atur `NUXT_I18N_DATE_BUILD`.
- **Kamus mengikuti `app.cdnURL`.** Browser mengambil file payload publik dari `<cdnURL>/_locales/...`, yang sebelumnya menggunakan `app.baseURL`: CDN harus menyimpan `_locales/` dan mengizinkan origin situs Anda (CORS). Lihat [App baseURL dan host payload](/id/guide/deployment#app-baseurl-and-payload-hosts).
- **SSR tidak lagi meminta `/_locales` melalui HTTP,** sehingga server middleware atau log pada rute tersebut berhenti melihat pembacaan render. `apiBaseServerHost` eksternal tetap melalui HTTP.
- **Pembacaan yang gagal tidak lagi menempel, begitu pula 404.** 404 dari host berarti host tersebut tidak memiliki file tersebut: render menampilkan kamus root, seperti yang dilakukan browser, tidak ada yang disimpan, dan file dibaca begitu muncul. Kegagalan lainnya, 200 yang bukan objek JSON, atau file lokal yang tidak dapat dibaca atau rusak tidak masuk ke cache, dan request berikutnya membaca lagi: render halaman mencatat peringatan, menampilkan kunci mentah, dan menjawab `503` dengan `no-store` dan `Retry-After`, sehingga route rule atau CDN tidak menyimpan apa pun darinya sementara browser tetap membaca kamus saat hidrasi, `/_locales/...` menjawab `503` dengan `no-store`, dan `useTranslationServerMiddleware` memberikan `t` yang menjawab dengan kunci atau default. Selama gangguan, setiap request mencapai host, dan host yang tidak mengirim header respons selama 60 detik menggagalkan pembacaan. Unduhan lambat untuk file besar tidak memiliki batas. Lihat [Ketika kamus tidak dapat dibaca](/id/guide/deployment#when-a-dictionary-cannot-be-read). `/_locales` juga meneruskan 404 tersebut, di mana dulu menjawab `200 {}`.
- **Prerender yang tidak dapat memuat kamusnya akan gagal,** begitu pula prerender yang host-nya tidak memiliki file halaman maupun file root. Rutenya menjadi 500, sebuah peringatan menyebutkan locale dan halamannya, dan tidak ada file yang ditulis; dengan `failOnError` default milik Nuxt, build keluar dengan kode 1. Halaman tanpa file sendiri di atas file root di-prerender dengan root.
- **Host yang diatur saat build menjawab SSR,** juga dengan salinan publik default, dan pada halaman error di path internal. File publik dulu yang menjawab. `NUXT_I18N_APP_BASE_SERVER_HOST` saat runtime kini mencapai `/_locales` dan server loader, dan render membaca host mana pun melalui loader tersebut.
- **`nitro.output.publicDir` kustom, dan tata letak lain apa pun di mana `public/` tidak berada di samping server, menyematkan payload.**
- **`nuxi build --preset <static preset>` melakukan prerender seperti `nuxi generate`,** sehingga mungkin menulis lebih banyak file. `nuxi generate` melakukan prerender setiap halaman statis di setiap locale yang melayaninya, tertaut atau tidak, kecuali route rule mengatur `prerender: false`.
- **`source` atau `publicAssets: false` pada output statis memberi peringatan.** Tidak ada yang dapat dibaca oleh browser.
- **Peringatan embed kini berupa pemeriksaan ukuran.** Build hanya memberi peringatan jika melewati batas platform: lihat [Batas bundle](/id/guide/deployment#bundle-limits-on-edge).
- **`Vary` diatur di mana pun pengunjung yang menentukan:** di setiap halaman di bawah `no_prefix`, dan di `/` serta URL lain apa pun yang dapat di-redirect berdasarkan preferensi. Header ini berisi `Cookie` ketika cookie digunakan dan, dengan `autoDetectLanguage`, `Accept-Language`. Periksa cache key CDN Anda: lihat [Caching HTML](/id/guide/deployment#caching-html).
- **Caching `/_locales` berubah.** Tidak ada route cache Nitro pada `/{apiBaseUrl}/**`, dan header `s-maxage=60, stale-while-revalidate` sudah dihapus. Jika Anda mengandalkan cache tersebut, letakkan CDN di depan rute payload. Kamus kosong tidak pernah `immutable`.
- **Cache server dibatasi secara default:** paling banyak 1000 entri ketika `cacheMaxSize` tidak diatur. `cacheTtl` dihitung sejak entri disimpan; pembacaan tidak lagi memperpanjangnya.
- **[`cacheStorage`](/id/guide/performance#shared-cache-for-several-instances) opsional yang baru:** cache kamus yang dibagi oleh beberapa instance. Jika tidak diatur, tidak ada yang berubah.

## Dari v2 ke v3 {#from-v2-to-v3}

### Opsi yang dihapus {#removed-options}

```diff
 i18n: {
-  includeDefaultLocaleRoute: true,
+  strategy: 'prefix',
-  fallbackRedirectComponentPath: '~/components/MyRedirect.vue',
-  experimental: { hmr: true, previousPageFallback: true },
+  hmr: true,
 }
```

- `includeDefaultLocaleRoute: true` menjadi `strategy: 'prefix'`; `false` adalah default `prefix_except_default`.
- `fallbackRedirectComponentPath` dihapus: redirect terjadi di server sebelum render dan di route middleware klien. Logika redirect kustom dimasukkan ke dalam plugin yang mengatur locale, lihat [Deteksi locale kustom](/id/guide/custom-auto-detect).
- `experimental.hmr` menjadi opsi root `hmr` (aktif secara default).
- `previousPageFallback` dihapus: kunci halaman yang ditinggalkan tetap di-resolve sampai transisinya selesai, tanpa opsi.

### State locale {#locale-state}

Gunakan `useI18nLocale()` alih-alih `useState('i18n-locale')` dan `useCookie('user-locale')`:

```diff
- useState('i18n-locale').value = 'fr'
- useCookie('user-locale').value = 'fr'
+ useI18nLocale().setLocale('fr') // state and cookie together
```

### Konfigurasi saat runtime {#config-at-runtime}

Baca konfigurasi, termasuk override runtime, dengan `$getI18nConfig()`:

```diff
- const cookieName = useRuntimeConfig().public.i18nConfig?.localeCookie
+ const { $getI18nConfig } = useNuxtApp()
+ const cookieName = $getI18nConfig().localeCookie
```

### Alias tipe internal {#internal-type-aliases}

Jika IDE Anda atau `vue-tsc` tidak dapat me-resolve import `#i18n-internal/*`, petakan di `package.json` Anda. Nuxt me-resolve-nya saat build, sehingga hal ini jarang diperlukan:

```json
{
  "imports": {
    "#i18n-internal/plural": "nuxt-i18n-micro/internals",
    "#i18n-internal/strategy": "nuxt-i18n-micro/internals",
    "#i18n-internal/config": "nuxt-i18n-micro/internals"
  }
}
```
