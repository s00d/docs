title: "Konfigurasi halaman"
description: "Batasi halaman ke beberapa locale, beri path kustom, terjemahan inline, atau tanpa tag SEO dengan $defineI18nRoute."
---

`$defineI18nRoute` mengatur opsi i18n untuk satu halaman dari dalam halaman itu sendiri. Gunakan ketika sebuah halaman hanya ada di beberapa locale, membutuhkan path terlokalisasi sendiri, membawa beberapa terjemahan miliknya sendiri, atau tidak boleh mendapatkan tag hreflang/canonical. Modul membaca pemanggilan ini saat build dan menanamkannya ke dalam rute yang dihasilkan.

## Membatasi halaman ke beberapa locale {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

Hanya `/product` dan `/de/product` yang dihasilkan di bawah strategi default `prefix_except_default`; halaman ini tidak memiliki rute di locale lain. Hal yang sama dapat diatur dari `nuxt.config.ts` dengan [`routeLocales`](/id/api/module-options#routelocales).

`$defineI18nRoute` adalah injeksi aplikasi Nuxt, bukan makro compiler: selalu ambil dari `useNuxtApp()` dan panggil dengan `$`. Hanya `$defineI18nRoute(` yang dikenali oleh langkah build.

## Menambahkan terjemahan inline {#add-inline-translations}

Berikan objek alih-alih array. Kuncinya adalah locale yang diizinkan, nilainya digabungkan ke kamus halaman untuk locale yang aktif.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Terjemahan inline dikirim di dalam komponen halaman untuk setiap locale. Utamakan [file terjemahan halaman](/id/guide/translations) untuk apa pun yang lebih besar dari beberapa kunci; gunakan kunci inline untuk halaman dan komponen yang mandiri.

## Mengatur path terlokalisasi {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

Dengan `prefix_except_default` dan `defaultLocale: 'en'` ini menghasilkan `/welcome` dan `/de/willkommen`. `path` di dalam objek locale inline melakukan hal yang sama: `locales: { de: { path: '/willkommen' } }`. Parameter dinamis, rute bersarang, dan alternatif di tingkat konfigurasi dibahas di [Path terlokalisasi](/id/guide/custom-locale-routes).

## Menonaktifkan tag SEO {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

Alternatif di tingkat konfigurasi adalah [`routeDisableMeta`](/id/api/module-options#routedisablemeta). Penjelasan tentang tag-tag tersebut ada di halaman [SEO](/id/guide/seo).

## Apa yang dapat dibaca oleh build {#what-the-build-can-read}

Langkah build menemukan pemanggilan di setiap file halaman dan mengevaluasi argumennya tanpa menjalankan aplikasi Anda. Ini berfungsi ketika konfigurasinya berupa:

- objek literal (string, array, objek bersarang, template literal, operator ternary pada `process.env.NODE_ENV`);
- dibangun dari konstanta yang dideklarasikan di `<script setup>` yang sama (`const locales = ['en', 'de']`, termasuk spread);
- array objek dengan field `code` (`[{ code: 'en' }, { code: 'de' }]`).

Langkah build tidak dapat membaca nilai yang diimpor dari modul lain, atau apa pun yang membutuhkan aplikasi Anda saat runtime (composable, `await`, data hasil fetch). Dalam kasus tersebut build mencatat `Ignored the $defineI18nRoute() config in <file>` dan halaman tetap menggunakan locale dan rute default.

Saat runtime, pemanggilan ini hanya menggabungkan terjemahan inline untuk locale saat ini dan menggabungkannya kembali ketika locale berubah. `locales`, `localeRoutes`, dan `disableMeta` hanya berlaku melalui build, sehingga mengubahnya memerlukan build ulang (server dev melakukan build ulang saat file disimpan).
