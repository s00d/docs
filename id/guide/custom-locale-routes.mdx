---
title: "Path yang dilokalkan"
description: "Berikan URL berbeda per locale untuk sebuah halaman dengan localeRoutes atau globalLocaleRoutes, termasuk parameter dinamis dan slug per locale."
---

Secara default setiap locale menyajikan halaman pada path yang sama: `/en/about`, `/de/about`. Path yang dilokalkan memungkinkan setiap locale menggunakan kata-katanya sendiri, seperti `/de/ueber-uns`, sementara file halaman tetap sama. Anda menetapkannya di halaman dengan `$defineI18nRoute`, atau untuk banyak halaman sekaligus di `nuxt.config.ts`.

## Di halaman {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

Dengan `prefix_except_default` dan `defaultLocale: 'en'` halaman merespons di `/about`, `/de/ueber-uns`, dan `/fr/a-propos`. Locale tanpa entri tetap memakai path default. Tulis path tanpa kode locale: prefiks ditambahkan oleh [strategi](/id/guide/strategy), dan path yang diawali kode locale akan mencatat peringatan. Apa lagi yang diterima oleh pemanggilan ini ada di [Konfigurasi halaman](/id/guide/per-component-translations).

## Di nuxt.config {#in-nuxt-config}

[`globalLocaleRoutes`](/id/api/module-options#globallocaleroutes) melakukan hal yang sama untuk halaman mana pun, dengan kunci berupa path-nya (atau nama route-nya, jika ditulis tanpa garis miring di depan):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

Jika sebuah halaman menetapkan `localeRoutes` dan `globalLocaleRoutes` memiliki kunci yang sama, entri konfigurasi yang menang.

## Parameter dinamis {#dynamic-params}

Tulis parameter dalam bentuk Nuxt mana pun: `[id]`, `[[page]]`, `[...slug]`, atau `:id()`. Nama parameter harus sama dengan file halaman.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

Halaman bersarang menerima path anak absolut (`/ueber-uns/team`) atau path relatif terhadap path induk yang dilokalkan (`team`).

## Menautkan ke halaman yang dilokalkan {#linking-to-localized-pages}

Link di-resolve ke path yang dilokalkan dari locale tujuan, baik Anda memberikan nama route maupun path biasa:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

Nama route berasal dari path file (`pages/about/team.vue` menjadi `about-team`) kecuali Anda menetapkannya dengan `definePageMeta({ name })`.

## Slug per locale {#per-locale-slugs}

Jika slug itu sendiri berbeda per locale (`/our-products/red-shoe` vs `/de/unsere-produkte/roter-schuh`), beri tahu pengalih bahasa parameter mana yang digunakan dengan `$setI18nRouteParams` setelah data dimuat:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

`$switchLocalePath('de')` dan `<i18n-switcher>` kemudian menautkan ke `/de/unsere-produkte/roter-schuh`. Kuncinya adalah kode locale, nilainya adalah parameter berdasarkan nama (seperti di file halaman).

Pengalih di layout dirender sebelum setup async halaman sampai di sini, sehingga ketika render selesai modul menulis ulang link `<i18n-switcher>`, baik di `app.vue` maupun di halaman. HTML server, pengunjung tanpa JavaScript, dan render klien pertama kemudian akan sesuai. Untuk ini, tetapkan parameter selama SSR: dengan `lazy` atau `server: false` link baru berubah setelah hidrasi. SSR streaming Nuxt mengirim HTML sebelum parameter diketahui, sehingga dalam mode tersebut link di HTML pertama tetap memakai parameter dari URL itu sendiri.

Hanya link milik pengalih yang ditulis ulang. Link `$switchLocalePath` yang ditulis manual harus dirender setelah parameter ditetapkan, jadi letakkan di halaman yang menetapkannya, juga setelah `await`. Di layout link tersebut dirender lebih dulu: HTML server-nya mempertahankan parameter URL, dan hidrasi memperingatkan adanya ketidakcocokan. Gunakan `<i18n-switcher>` di sana, dengan slot dan prop `custom*Style`-nya untuk tampilan.

Parameter tersebut milik halaman yang menetapkannya:

- Parameter dibuang ketika navigasi ke path lain di-commit, sehingga setiap halaman menetapkan parameternya sendiri. Navigasi yang dibatalkan membiarkannya tetap ada.
- Ambil `$setI18nRouteParams` dari `useNuxtApp()` atau `useI18n()` di `setup`, juga ketika Anda memanggilnya belakangan di handler `useAsyncData`. Jika diambil di sana, fungsi tersebut mengetahui halamannya: jika pengunjung sudah pergi, pemanggilan yang terlambat tidak melakukan apa pun.
- Dengan `keepalive`, halaman mendapatkan kembali parameter yang ditetapkannya saat pengunjung kembali. `useI18nHead` melakukan hal yang sama.

## Route yang ditambahkan di pages:extend {#routes-added-in-pagesextend}

Route yang Anda tambahkan di hook `pages:extend` tidak memiliki file halaman untuk membaca `$defineI18nRoute`, dan beberapa di antaranya sering berbagi satu komponen pembungkus. Route yang ditambahkan tanpa `name` mendapatkan nama yang akan diberikan Nuxt untuk path-nya (`/a/:id()` menjadi `a-id`), sehingga link bahasa dapat menjangkaunya, kecuali route lain sudah memiliki nama tersebut; dalam hal itu berikan `name` secara eksplisit. Simpan satu daftar dan pisahkan menjadi halaman dan `globalLocaleRoutes` dengan kunci nama route menggunakan `splitLocaleRoutes` dari `@i18n-micro/utils/split-locale-routes` (tambahkan paket ini ke dependensi Anda):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

Jangan letakkan path yang dilokalkan di `route.meta`: path tersebut akan ikut terkirim dalam tabel route klien.
