**Tanggal**: 2026-05-14

**Versi**: `v3.20.0`

![Rilis v3.20.0](/images/3.20.0.png)

Rilis ini merefaktor runtime Nuxt menjadi lapisan **`NuxtI18n`** khusus, memisahkan penanganan redirect server/klien, dan memperbaiki beberapa regresi SSR/hidrasi. Composable publik dan opsi `nuxt.config` tetap sama untuk aplikasi pada umumnya.

## Apa yang Baru? {#what’s-new}

### `NuxtI18n` & `NuxtTranslationLoader` {#nuxti18n-&-nuxttranslationloader}

Logika i18n runtime dipindahkan dari plugin monolitik ke kelas-kelas yang terfokus:

- **`NuxtI18n`** — lapisan tampilan terjemahan aktif (`$t`, `$has`, konteks locale/rute, penggabungan/pembersihan saat transisi)
- **`NuxtTranslationLoader`** — memuat chunk, mengganti konteks saat navigasi, mengisi payload SSR
- **`createNuxtI18nPluginApi`** — permukaan plugin yang tipis (`$switchLocale`, `$localeRoute`, dll.)

Lihat [Arsitektur Cache & Storage](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api) dan [Performa](/id/guide/performance) yang telah diperbarui.

### Payload SSR melalui `useState('i18n-ssr-chunks')` {#ssr-payload-via-usestate‘i18n-ssr-chunks’}

Terjemahan SSR diserialisasi melalui **state Nuxt**, bukan tag script `window.__I18N__`:

1. Server memuat chunk → `useState('i18n-ssr-chunks')`
2. Klien melakukan hidrasi → `translationStorage.seedFromSsrChunks()`
3. Nol fetch tambahan pada render pertama

Jalur baca lama `window.__I18N__` telah **dihapus**.

### Pemisahan Arsitektur Redirect {#redirect-architecture-split}

Redirect kini spesifik per lingkungan untuk perilaku yang lebih jelas dan lebih sedikit gangguan di klien:

| Lingkungan     | Komponen                       | Peran                                      |
| -------------- | ------------------------------ | ------------------------------------------ |
| **SSR Server** | `06.redirect.ts` (khusus server) | 302 sebelum render, pemeriksaan 404, sinkronisasi cookie |
| **SPA Klien**  | `i18n-redirect.global.ts`      | Middleware rute global saat navigasi       |

Redirect klien menurunkan locale dari **rute tujuan**, mempertahankan **query string dan hash**, serta menghormati `redirects: false` (middleware tidak didaftarkan). Lihat [Deteksi locale — redirect per strategi](/id/guide/locale-detection#redirects-per-strategy).

### Waktu Hook `i18n:register` {#i18nregister-hook-timing}

Plugin **`05.hooks`** (`dependsOn: i18n-plugin-loader`) memicu `i18n:register` setelah loader siap — saat startup dan saat navigasi — sehingga plugin pengguna menerima event tersebut secara andal. Nonaktifkan dengan `hooks: false`. Lihat [Event](/id/api/events).

### Ekstraksi `defineI18nRoute` saat Build {#build-time-definei18nroute-extraction}

Sebuah unplugin Vite memindai file `.vue` halaman saat build dan menulis meta rute untuk `@i18n-micro/route-strategy`. `$defineI18nRoute` runtime di `script setup` tetap ada untuk dev dan konfigurasi inline. Lihat [Terjemahan Per-Komponen](/id/guide/per-component-translations).

## Perbaikan Bug {#bug-fixes}

- **Hidrasi SSR** — kloning chunk SSR reaktif sebelum `Object.freeze` (memperbaiki crash `#locale` / 404 di klien)
- **Pergantian locale** — ganti lapisan tampilan saat locale berubah (tidak ada kunci usang dari locale sebelumnya)
- **Redirect klien** — locale dari rute tujuan; query/hash dipertahankan saat redirect
- **`has()`** — hanya memeriksa locale aktif; fallback berlaku di `$t()`, bukan di `$has()`
- **Meta `defineI18nRoute`** — cache per instance plugin; kecocokan `rootDir` terpanjang; path `pages/index` vs `pages/index/index` yang benar

## Breaking Changes {#breaking-changes}

Tidak ada untuk penggunaan standar `nuxt.config` + composable. Path internal dan mekanisme injeksi SSR berubah; aplikasi yang mengandalkan injeksi `window.__I18N__` secara manual harus menggunakan payload Nuxt / API modul sebagai gantinya.

## Mengapa Ini Penting {#why-it-matters}

- **Serah terima SSR → klien yang lebih andal** — state bawaan Nuxt alih-alih variabel global ad-hoc
- **Model redirect yang lebih jelas** — 302 dari server sebelum render; middleware klien hanya jika diperlukan
- **Lebih mudah dipelihara** — runtime dipecah menjadi unit yang dapat diuji dengan pengujian regresi yang terfokus
