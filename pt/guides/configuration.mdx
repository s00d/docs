# Detalhes das opções

O módulo fornece opções de configuração extensas para personalizar o seu setup de internacionalização.

### 🌍 Definições essenciais de locale

#### `locales`

{/* generated:option:locales — do not edit; run `pnpm run docs:generate` */}

**Tipo** `Locale[]` · **Predefinição** `[]`

Lista de locales suportados.
Cada entrada define um código de locale e metadados opcionais (ISO, direção, nome de apresentação, etc.).

{/* /generated:option:locales */}

Cada objeto locale suporta:

| Propriedade      | Tipo      | Obrigatório | Descrição                                             |
| ---------------- | --------- | -------- | ----------------------------------------------------- |
| `code`           | `string`  | ✅       | Identificador único (por exemplo, `'en'`)             |
| `displayName`    | `string`  | ❌       | Nome legível para seletores (por exemplo, `'English'`) |
| `iso`            | `string`  | ❌       | Código ISO (por exemplo, `'en-US'`)                   |
| `dir`            | `string`  | ❌       | Direção do texto (`'ltr'` ou `'rtl'`)                 |
| `disabled`       | `boolean` | ❌       | Desativa na lista pendente se `true`                  |
| `baseUrl`        | `string`  | ❌       | URL base para domínios específicos de locale          |
| `baseDefault`    | `boolean` | ❌       | Remove o prefixo de locale dos URLs                   |
| `fallbackLocale` | `string`  | ❌       | Fallback por locale (substitui o global)              |
| `[key: string]`  | `unknown` | ❌       | Quaisquer propriedades personalizadas (ver abaixo)    |

**Exemplo**:

```typescript
locales: [
  { code: 'en', iso: 'en-US', dir: 'ltr' },
  { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
  { code: 'ar', iso: 'ar-SA', dir: 'rtl', disabled: true },
  {
    code: 'de',
    iso: 'de-DE',
    dir: 'ltr',
    baseUrl: 'https://de.example.com',
    baseDefault: true,
  },
]
```

<Warning>
Utilizar `baseUrl` pode conduzir a duplicação de rotas internas como ligações externas, complicando o encaminhamento e a manutenção. Considere criar ligações externas diretamente para locales específicos.
</Warning>

#### Propriedades personalizadas de locale

Pode adicionar quaisquer propriedades personalizadas aos objetos de locale. São passadas ao runtime e ficam acessíveis via `$getLocales()`:

```typescript
locales: [
  { code: 'en', iso: 'en-US', flag: '🇬🇧', currency: 'GBP' },
  { code: 'de', iso: 'de-DE', flag: '🇩🇪', currency: 'EUR' },
  { code: 'ru', iso: 'ru-RU', flag: '🇷🇺', currency: 'RUB' },
]
```

Aceda-as em componentes:

```vue
<template>
  <ul>
    <li v-for="locale in $getLocales()" :key="locale.code">{{ locale.flag }} {{ locale.displayName }} ({{ locale.currency }})</li>
  </ul>
</template>
```

Por predefinição, as propriedades personalizadas têm tipo `unknown`. Para obter suporte total de TypeScript, use **module augmentation**. Crie um ficheiro de declaração (por exemplo, `app/i18n.d.ts` ou qualquer `.d.ts` incluído no seu `tsconfig`):

```typescript
// app/i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
    currency?: string
  }
}
```

Depois disto, todas as propriedades personalizadas ficam totalmente tipadas:

```typescript
const locales = $getLocales()
locales[0].flag // string | undefined ✅
locales[0].currency // string | undefined ✅
```

#### `defaultLocale`

{/* generated:option:defaultLocale — do not edit; run `pnpm run docs:generate` */}

**Tipo** `string` · **Predefinição** `'en'`

O locale a usar quando não é possível determinar um locale a partir do URL ou das preferências do utilizador. Também é usado como locale de fallback para traduções em falta quando `fallbackLocale` não está definido.

{/* /generated:option:defaultLocale */}

```typescript
defaultLocale: 'en'
```

#### `strategy`

{/* generated:option:strategy — do not edit; run `pnpm run docs:generate` */}

**Tipo** `Strategies` · **Predefinição** `'prefix_except_default'`

Estratégia de encaminhamento de URL para prefixos de locale.

- `'no_prefix'` — sem locale no URL; locale armazenado em cookie.
- `'prefix_except_default'` — prefixa todos os locales exceto o predefinido.
- `'prefix'` — prefixa sempre, incluindo o locale predefinido.
- `'prefix_and_default'` — como `prefix`, mas o predefinido também está acessível sem prefixo.

{/* /generated:option:strategy */}

<CodeGroup>
```typescript no_prefix
strategy: 'no_prefix'
// Routes: /about, /contact
// Locale detection via browser/cookies
```

```typescript prefix_except_default
strategy: 'prefix_except_default'
// Default locale: /about, /contact
// Other locales: /fr/about, /de/contact
```

```typescript prefix
strategy: 'prefix'
// All locales: /en/about, /fr/about, /de/about
```

```typescript prefix_and_default
strategy: 'prefix_and_default'
// Both prefixed and non-prefixed versions for default locale
```
</CodeGroup>

### 📂 Gestão de traduções

#### `translationDir`

{/* generated:option:translationDir — do not edit; run `pnpm run docs:generate` */}

**Tipo** `string` · **Predefinição** `'locales'`

Caminho para o diretório de ficheiros JSON de tradução, relativo à raiz do projeto.

{/* /generated:option:translationDir */}

```typescript
translationDir: 'i18n' // Custom directory
// Nuxt 4 colocation example:
// translationDir: 'app/locales'
```

Os caminhos são resolvidos a partir da **raiz do projeto** (`rootDir`), e não de `app/`. Com Nuxt 4, o setup habitual é `app/pages/` para rotas e `locales/` (ou `app/locales` se definir `translationDir`) para os JSON.

#### `disablePageLocales`

{/* generated:option:disablePageLocales — do not edit; run `pnpm run docs:generate` */}

**Tipo** `boolean` · **Predefinição** `false`

Desativa os ficheiros de tradução por página.
Quando `true`, apenas as traduções globais (`\{locale\}.json`) são carregadas;
os ficheiros específicos de página (`pages/\{page\}/\{locale\}.json`) não são gerados nem carregados.

{/* /generated:option:disablePageLocales */}

Quando ativado, só os ficheiros de nível raiz são usados:

```tree
locales/
├── en.json
├── fr.json
└── ar.json
```

#### `fallbackLocale`

{/* generated:option:fallbackLocale — do not edit; run `pnpm run docs:generate` */}

**Tipo** `string` · **Predefinição** `undefined (sem fallback; devolve a chave em bruto)`

Código de locale de fallback global.
Quando uma chave de tradução está em falta no locale ativo, o módulo procura-a neste locale antes de devolver a própria chave.

{/* /generated:option:fallbackLocale */}

```typescript
fallbackLocale: 'en' // Global fallback
```

#### `types`

{/* generated:option:types — do not edit; run `pnpm run docs:generate` */}

**Tipo** `boolean` · **Predefinição** `true`

Gera declarações de tipos TypeScript para `useI18n`, `$t` e helpers relacionados com base nas chaves de tradução dos seus ficheiros de locale predefinido.

{/* /generated:option:types */}

Quando ativado, o módulo emite `.nuxt/i18n.d.ts` durante o build com chaves de tradução tipadas. Defina como `false` se preferir helpers sem tipos ou usar um gerador externo.

Este gerador incorporado é independente do pacote opcional [`@i18n-micro/types-generator`](/integrations/types-generator), que pode produzir ficheiros de tipos mais rigorosos ou autónomos para monorepos e CI.

```typescript
types: false // Disable built-in key typing
```

#### `routeLocales`

{/* generated:option:routeLocales — do not edit; run `pnpm run docs:generate` */}

**Tipo** `Record<string, string[]>` · **Predefinição** —

Restrições de locale por rota, extraídas de chamadas a `defineI18nRoute()`.
Mapeia um caminho de rota (por exemplo, `'/about'`) para um array de códigos de locale permitidos.
Rotas não listadas não têm restrições (todos os locales permitidos).

{/* /generated:option:routeLocales */}

Mapeia um caminho de rota (por exemplo, `'/about'`) para os códigos de locale permitidos. Rotas não listadas permitem todos os locales configurados.

Normalmente configura isto via [`defineI18nRoute`](/guides/custom-locale-routes) nas páginas, e não em `nuxt.config`. O módulo funde as declarações ao nível da página neste mapa em tempo de build.

#### `routeDisableMeta`

{/* generated:option:routeDisableMeta — do not edit; run `pnpm run docs:generate` */}

**Tipo** `Record<string, boolean \| string[]>` · **Predefinição** —

Desativação de meta tags por rota, extraída de chamadas a `defineI18nRoute()`.
Mapeia um caminho de rota para `true` (desativar todas as metas) ou para um array de códigos de locale para os quais as metas devem ser desativadas.

{/* /generated:option:routeDisableMeta */}

- `true` — desativa todas as metas SEO para a rota
- `string[]` — desativa as metas apenas para os códigos de locale listados

Como `routeLocales`, é normalmente definido em componentes de página, e não manualmente na configuração.

#### `experimental`

{/* generated:option:experimental — do not edit; run `pnpm run docs:generate` */}

**Tipo** `Record<string, unknown>` · **Predefinição** —

Reservatório para opções experimentais/instáveis.
Os conteúdos podem mudar ou ser removidos sem aviso entre versões menores.

{/* /generated:option:experimental */}

A maioria das antigas flags `experimental.*` foi promovida a opções de topo na v3 (por exemplo, `hmr`). Prefira as opções documentadas de topo. Use `experimental` apenas quando seguir uma nota de lançamento ou guia de migração que refira uma chave específica.

### 🔍 SEO e meta tags

#### `meta`

{/* generated:option:meta — do not edit; run `pnpm run docs:generate` */}

**Tipo** `boolean` · **Predefinição** `true`

Gera automaticamente meta tags SEO (`hreflang`, `canonical`, `og:url`, `og:locale`).

{/* /generated:option:meta */}

```typescript
meta: true // Generate alternate links, canonical URLs, etc.
```

#### `metaBaseUrl`

{/* generated:option:metaBaseUrl — do not edit; run `pnpm run docs:generate` */}

**Tipo** `string` · **Predefinição** `undefined`

URL base para meta tags SEO (canonical, og:url, hreflang).

- Uma string de URL concreta (por exemplo, `'https://example.com'`) — usada tal como está (prioridade mais alta).
- `undefined` — recai em `site.url` do `nuxt-site-config` quando esse módulo está presente; caso contrário, na origem do pedido atual (`useRequestURL().origin` no servidor, `window.location.origin` no cliente).

{/* /generated:option:metaBaseUrl */}

Prioridade quando não definido: `site.url` do `nuxt-site-config` (se instalado) → origem do pedido (`useRequestURL().origin` no servidor com `X-Forwarded-Host` / `X-Forwarded-Proto`, `window.location.origin` no cliente). Ideal para **stacks SEO** que já definem `site.url`, e para implementações **multidomínio** quando `site.url` é omitido.

- Qualquer outra string — usada como URL base estático (prevalece sobre `site.url`).

```typescript
// Prefer sharing the SEO stack origin — omit metaBaseUrl when site.url is set
site: { url: 'https://example.com' }

// Or pin an explicit override
metaBaseUrl: 'https://example.com'
```

#### `canonicalQueryWhitelist`

{/* generated:option:canonicalQueryWhitelist — do not edit; run `pnpm run docs:generate` */}

**Tipo** `string[]` · **Predefinição** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

Lista de nomes de parâmetros de consulta preservados em meta tags canonical e `og:url`. Parâmetros que não estejam nesta lista são removidos do URL canónico.

{/* /generated:option:canonicalQueryWhitelist */}

```typescript
canonicalQueryWhitelist: ['page', 'sort', 'category']
```

### 🔄 Funcionalidades avançadas

#### `globalLocaleRoutes`

{/* generated:option:globalLocaleRoutes — do not edit; run `pnpm run docs:generate` */}

**Tipo** `GlobalLocaleRoutes` · **Predefinição** `\{\}`

Configuração de locale ao nível da rota global.
Permite restringir ou personalizar rotas de locale para páginas específicas sem alterar os seus componentes.

- `false` — exclui a rota da localização.
- `Record<LocaleCode, string>` — caminhos personalizados por locale.

{/* /generated:option:globalLocaleRoutes */}

```typescript
globalLocaleRoutes: {
  'about': {
    en: '/about-us',
    fr: '/a-propos',
    de: '/uber-uns'
  },
  'unlocalized': false // Disable localization entirely
}
```

<Tip>
Para rotas adicionadas em `pages:extend` (especialmente muitas a partilhar um SFC wrapper), construa tanto `pages` como `globalLocaleRoutes` a partir de uma única lista com [`splitLocaleRoutes`](/guides/custom-locale-routes#programmatic-routes-pagesextend--244) — indexada por **nome** de rota, não por caminho de ficheiro.
</Tip>

#### `routesLocaleLinks`

{/* generated:option:routesLocaleLinks — do not edit; run `pnpm run docs:generate` */}

**Tipo** `\{ [key: string]: string \}` · **Predefinição** `\{\}`

Mapeia nomes de rota para outros nomes de rota para partilhar os mesmos ficheiros de tradução.
Por exemplo, `\{ 'about-us': 'about' \}` significa que a página `about-us` usará as traduções da página `about` em vez das suas próprias.

{/* /generated:option:routesLocaleLinks */}

```typescript
routesLocaleLinks: {
  'products-id': 'products',
  'about-us': 'about'
}
```

#### `customRegexMatcher`

{/* generated:option:customRegexMatcher — do not edit; run `pnpm run docs:generate` */}

**Tipo** `string \| RegExp` · **Predefinição** `undefined (utiliza padrão incorporado)`

Expressão regular personalizada (ou a sua origem em string) para fazer correspondência de códigos de locale em segmentos de URL.
Todos os códigos de locale definidos em `locales` devem corresponder a este padrão; caso contrário, é emitido um aviso.

{/* /generated:option:customRegexMatcher */}

<Danger>
Em tempo de build, o módulo **valida** que todos os códigos de locale na sua lista `locales` correspondem ao padrão `customRegexMatcher`. Se qualquer código não corresponder, **o build falha** com o erro:

> `Nuxt-i18n-micro: Some locale codes does not match customRegexMatcher`

Verifique sempre o seu regex contra todos os seus códigos de locale antes de implementar.
</Danger>

```typescript
// ✅ Correct: matches 'en-us', 'de-de', 'fr-fr'
customRegexMatcher: '[a-z]{2}-[a-z]{2}'

// ✅ Correct: matches 'en', 'de', 'fr', 'zh'
customRegexMatcher: '[a-z]{2}'

// ❌ Wrong: won't match 'zh-Hant' (uppercase letter)
// This will FAIL the build if 'zh-Hant' is in your locales list
customRegexMatcher: '[a-z]{2}-[a-z]{2}'
```

### 🔢 Personalização

#### `plural`

{/* generated:option:plural — do not edit; run `pnpm run docs:generate` */}

**Tipo** `PluralFunc` · **Predefinição** `pluralização incorporada (índice de forma por contagem)`

Função de pluralização personalizada.
Recebe `(key, count, params, locale, getter)` e deve devolver a forma plural selecionada como string, ou `null`/`undefined` para cair na lógica incorporada `defaultPlural` (para poder substituir apenas alguns locales).

No módulo Nuxt, a função é serializada com `.toString()` em `.nuxt/i18n.plural.mjs` — deve ser autossuficiente (sem imports/escopo exterior).
Uma string de caminho de ficheiro **não** é suportada.

{/* /generated:option:plural */}

##### Como funciona

As traduções usam `|` para separar formas plurais:

```json
{
  "apples": "no apples | one apple | {count} apples"
}
```

Use `$tc('apples', count)` ou `$tc('cart', \{ count, name \})` quando uma forma precisa de mais do que `\{count\}`. Passe **`count` e outros params no objeto do segundo argumento**, não como terceiro argumento (o terceiro é apenas `defaultValue`).

A chamada `$tc` invoca a função `plural`, que:

1. Chama `t(key)` para obter a string de tradução em bruto (por exemplo, `"no apples | one apple | \{count\} apples"`)
2. Divide por `|` para obter o array de formas
3. Seleciona uma forma com base em `count`
4. Substitui `\{count\}` pelo número real

A implementação **predefinida** seleciona por índice: `count < forms.length ? forms[count] : forms[last]`. Isto funciona em casos simples (0 → primeira forma, 1 → segunda, 2+ → última).

##### Função plural personalizada

Para idiomas com regras complexas (por exemplo, russo, árabe, polaco), substitua a opção `plural`.

<Danger>
A função é serializada via `.toString()` e injetada num módulo virtual em tempo de build. Isto significa:

- **Tem de usar a palavra-chave `function`** — NÃO sintaxe de método abreviada, NÃO funções seta com referências externas
- **Sem imports ou referências externas** — a função deve ser totalmente autossuficiente (um caminho de ficheiro como `plural: '~/i18n/plural.ts'` **não** é suportado)
- **Sem sintaxe exclusiva de TypeScript** que não sobreviva a `.toString()` (anotações de tipo estão bem em `nuxt.config.ts` porque o Nuxt as remove)
- Devolver `null`/`undefined` recorre ao `defaultPlural` incorporado (útil para substituições por locale)
</Danger>

**Exemplo: pluralização russa** (4 formas: zero, one, few, many):

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    plural: function (key, count, _params, _locale, t) {
      const translation = t(key)
      if (!translation) return key

      const forms = translation
        .toString()
        .split('|')
        .map(function (s) {
          return s.trim()
        })
      let idx

      if (count === 0) {
        idx = 0
      } else {
        const mod10 = count % 10
        const mod100 = count % 100
        if (mod10 === 1 && mod100 !== 11) {
          idx = 1
        } else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) {
          idx = 2
        } else {
          idx = 3
        }
      }

      if (idx >= forms.length) idx = forms.length - 1
      return (forms[idx] || '').replace('{count}', String(count))
    },
  },
})
```

Com esta tradução:

```json
{
  "apples": "нет яблок | {count} яблоко | {count} яблока | {count} яблок"
}
```

Resultados:

- `$tc('apples', 0)` → `"нет яблок"`
- `$tc('apples', 1)` → `"1 яблоко"`
- `$tc('apples', 3)` → `"3 яблока"`
- `$tc('apples', 5)` → `"5 яблок"`
- `$tc('apples', 21)` → `"21 яблоко"`

**Exemplo: inglês simples (comportamento predefinido)**:

```typescript
// This is the built-in default — you don't need to set it explicitly
plural: function (key, count, params, _locale, t) {
  const translation = t(key, params)
  if (!translation) return null

  const forms = translation.toString().split('|')
  if (forms.length === 0) return null
  const form = count < forms.length ? forms[count] : forms[forms.length - 1]
  if (!form) return null
  return form.trim().replace('{count}', count.toString())
}
```

##### Pluralização por locale

Se diferentes locales precisarem de regras diferentes, ramifique com base em `locale` e devolva `null` para os locales que não personaliza. O `defaultPlural` incorporado trata dos restantes:

```typescript
plural: function (key, count, _params, locale, t) {
  // Only override Slavic locales; en/de/… keep the built-in rules
  if (locale !== 'ru' && locale !== 'uk') return null

  const translation = t(key)
  if (!translation) return null

  const forms = translation.toString().split('|').map(function (s) { return s.trim() })
  let idx
  if (count === 0) {
    idx = 0
  } else {
    const mod10 = count % 10
    const mod100 = count % 100
    if (mod10 === 1 && mod100 !== 11) idx = 1
    else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) idx = 2
    else idx = 3
  }
  if (idx >= forms.length) idx = forms.length - 1
  return (forms[idx] || '').replace('{count}', String(count))
}
```

<Warning>
`plural: '~/i18n/plural.ts'` (ou qualquer caminho em string) **não** é suportado. O módulo Nuxt serializa a função com `.toString()` num ficheiro virtual; imports externos e helpers de outros módulos são removidos e ficam `undefined` em runtime. Mantenha a função totalmente inline em `nuxt.config.ts` (ver a nota de perigo acima).
</Warning>

#### `localeCookie`

{/* generated:option:localeCookie — do not edit; run `pnpm run docs:generate` */}

**Tipo** `string \| null` · **Predefinição** `null`

Nome do cookie que persiste a preferência de locale do utilizador entre sessões.
Defina como `null` para desativar a persistência por cookie.
Definido automaticamente como `'user-locale'` para a estratégia `no_prefix` se não for fornecido.

{/* /generated:option:localeCookie */}

<Warning>
Embora o valor predefinido seja `null` (desativado), o módulo **substitui automaticamente** para `'user-locale'` ao usar `strategy: 'no_prefix'`. Isto significa:

- **`no_prefix`**: o cookie está **sempre ativado** (`'user-locale'`), mesmo que não o defina explicitamente. É necessário porque o URL não contém informação de locale.
- **Todas as outras estratégias**: o cookie é `null` (desativado) a menos que o defina explicitamente.

Se definir `localeCookie` explicitamente, o seu valor é sempre usado, independentemente da estratégia.
</Warning>

<Warning>
Ao usar estratégias de prefixo (`prefix`, `prefix_except_default`, `prefix_and_default`) com `redirects: true` (predefinição), **tem** de definir `localeCookie` para que o comportamento de redirecionamento funcione corretamente. Sem um cookie, o plugin de redirecionamento não pode lembrar a preferência de locale do utilizador entre recargas de página, e os redirecionamentos funcionarão apenas com base no cabeçalho `Accept-Language` (se `autoDetectLanguage: true`) ou em `defaultLocale`.
</Warning>

```typescript
// Enable cookie (recommended when using redirects with prefix strategies)
localeCookie: 'user-locale'

// Enable cookie with custom name
localeCookie: 'my-locale-cookie'

// Disable cookie (default) - locale won't persist across reloads
localeCookie: null
```

**O que o `localeCookie` permite:**

- Persistir a preferência de locale do utilizador entre recargas de página
- Recordar o locale quando o utilizador regressa ao seu site
- Necessário para a estratégia `no_prefix` funcionar corretamente
- **Necessário** para o comportamento de redirecionamento em estratégias de prefixo (quando `redirects: true`)

#### `translationPayloads`

{/* generated:option:translationPayloads — do not edit; run `pnpm run docs:generate` */}

**Tipo** `TranslationPayloadOptions` · **Predefinição** —

Controla como os payloads de tradução são emitidos (Node: `public/<apiBaseUrl>`; Edge: `serverAssets` do Nitro).

- **Node**: `serverAssets` significa SSR local via `readFile` em `public/` (sem `raw:` do Rollup).
- **Edge**: `serverAssets` regista `serverAssets` do Nitro (`assets:i18n`); não força uma cópia pública.

Mantenha os valores predefinidos para a configuração habitual "tudo-em-um". Para catálogos Edge grandes prefira `mode: 'source'`.
Para implementações apoiadas por CDN, desative as saídas locais e defina `apiBaseClientHost` / `apiBaseServerHost`.

{/* /generated:option:translationPayloads */}

```typescript
{
  mode?: 'premerged' | 'source'
  serverAssets?: boolean
  serverHandler?: boolean
  publicAssets?: boolean
  prerenderRoutes?: boolean
  publicDir?: string
  warnFileCount?: number
  warnSizeBytes?: number
}
```

**Predefinição** (`mode: 'premerged'`):

```typescript
{
  mode: 'premerged',
  serverAssets: true,
  serverHandler: true,
  publicAssets: true,
  prerenderRoutes: false
}
```

O SSR em **Node** lê a mesma árvore copiada para `public/<apiBaseUrl>/` (`readFile`). Em **Edge**, `serverAssets` do Nitro incorpora-a (sem cópia pública forçada — defina `publicAssets: true` para CDN). `mode: 'premerged'` → `\{page\}/\{locale\}/data.json` por página/locale; `mode: 'source'` → origem compacta + fusão em runtime.

`serverAssets: true` em **Node** força a cópia pública mesmo que `publicAssets` seja false. Em **Edge** apenas regista o embed do Nitro. Prefira `mode: 'source'` em Edge para catálogos grandes. Sem payloads locais e sem `apiBaseServerHost`, o build falha.

O handler local `/\{apiBaseUrl\}/:page/:locale/data.json`, as rotas de prerender e as cópias de assets públicos permanecem saídas opcionais.

Para payloads **públicos** / Edge compactos:

```typescript
i18n: {
  translationPayloads: {
    mode: 'source',
  },
}
```

`mode: 'source'` mantém os ficheiros de camada compactos e funde raiz/página/fallback em runtime através da rota `/_locales` incorporada (ou `assets:i18n` no Edge). Por predefinição, desativa cópias de assets públicos e rotas de payload pré-renderizadas.

<Warning>
Com `mode: 'source'`, `publicAssets` fica em `false` por predefinição (`prerenderRoutes` está sempre desligado a menos que o ative). Um alojamento estático puro sem runtime Nitro/Edge não conseguirá, portanto, carregar traduções no cliente a menos que ative uma destas saídas, mantenha `serverHandler` disponível em runtime ou aloje os payloads externamente.

Com `mode: 'premerged'` e `publicAssets: true` (predefinição), os ficheiros estáticos já são gerados em `public/<apiBaseUrl>/\{page\}/\{locale\}/data.json` — a corresponder aos URLs de `$fetch` do cliente. Assim, um host estático pode servi-los sem Nitro.
</Warning>

<Warning>
Quando `apiBaseServerHost` ou `apiBaseClientHost` está definido, o módulo obtém JSON já fundido dessa origem. Hosts externos devem servir as mesmas respostas `/\{apiBaseUrl\}/:page/:locale/data.json` da rota incorporada. `mode: 'source'` aplica-se a diretórios de payload locais, e não a uma CDN externa a menos que essa CDN também sirva payloads fundidos em runtime.
</Warning>

Também pode desativar manualmente saídas locais duplicadas e servir os payloads de tradução a partir de uma CDN ou armazenamento de objetos:

```typescript
i18n: {
  apiBaseClientHost: 'https://cdn.example.com',
  apiBaseServerHost: 'https://cdn.example.com',
  translationPayloads: {
    serverHandler: false,
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

Se quiser apenas evitar escrever payloads na saída pública mantendo a rota de servidor incorporada para pedidos SSR/runtime, desative ambas as saídas públicas:

```typescript
i18n: {
  translationPayloads: {
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

Em **Node**, `serverAssets: true` ainda força uma cópia pública para SSR mesmo quando `publicAssets` é false. Defina `serverAssets: false` e `apiBaseServerHost` se quiser zero ficheiros de payload locais.

Use `publicDir` para alterar a pasta de saída pública quando os payloads são copiados. Predefinição igual a `apiBaseUrl` (`_locales`). No modo premerged, `publicAssets` escreve `\{page\}/\{locale\}/data.json` aí (os mesmos caminhos que o cliente pede). `prerenderRoutes` é um prerender opcional do Nitro das rotas do handler — normalmente redundante quando essa árvore já foi copiada.

Se desativar todas as saídas locais de payload, tem de configurar ambos `apiBaseServerHost` (SSR) e `apiBaseClientHost` (navegação no cliente). Caso contrário, as traduções resolverão para objetos vazios e as chaves de UI podem aparecer não traduzidas.

`warnFileCount` e `warnSizeBytes` controlam avisos em tempo de build quando o output pré-fundido cresce (predefinições: 500 ficheiros e 10 MB).

#### `dateBuild`

{/* generated:option:dateBuild — do not edit; run `pnpm run docs:generate` */}

**Tipo** `string \| number` · **Predefinição** —

Valor usado para invalidar a cache dos pedidos de tradução (`?v=...`).

Quando não é fornecido, o módulo recorre a `Date.now()` (não determinístico). Para implementações reproduzíveis/rolantes, defina para um valor estável (por exemplo, um SHA de git ou número de build).

{/* /generated:option:dateBuild */}

Por predefinição, o módulo faz fingerprint das suas fontes de tradução (SHA-256 de cada `<layer>/<translationDir>/**/*.json`, por ordem de camada) e usa esse valor. O valor só muda quando uma tradução muda mesmo, pelo que reconstruir ou reimplementar traduções intocadas mantém intactas as caches de browser e CDN. Com `httpCacheDuration` definido para um ano, um timestamp de build obrigaria cada cliente a voltar a transferir todo o dicionário em cada deploy.

Recorre a `Date.now()` apenas quando não há ficheiros de tradução para fazer hash.

Defina-o explicitamente para assumir o controlo (por exemplo, para ligar os URLs de payload a uma release em vez do conteúdo):

```ts
export default defineNuxtConfig({
  i18n: {
    // Any stable string/number: git SHA, CI build number, release tag, etc.
    dateBuild: process.env.GIT_SHA ?? 'local-dev',
  },
})
```

#### `httpCacheDuration`

{/* generated:option:httpCacheDuration — do not edit; run `pnpm run docs:generate` */}

**Tipo** `number` · **Predefinição** `31536000`

HTTP `Cache-Control` max-age (segundos) para `/\{apiBaseUrl\}/:page/:locale/data.json`.

Aplica-se em pleno apenas enquanto `dateBuild` invalida o URL (`?v=...`), o que é o comportamento predefinido: a resposta é então `public, max-age=…, immutable` e segura para browsers e CDNs.

- `dateBuild: 0`/`''` — o URL é estável, pelo que esta duração *não* é respeitada; a resposta passa a `public, max-age=0, must-revalidate`. Um `max-age` longo num URL estático fixa o primeiro payload que o browser recebeu.

- `0` — não define `Cache-Control` de todo (útil em depuração local)
- Não é aplicado em desenvolvimento (`import.meta.dev`) para que o HMR não seja contrariado pela cache do browser
- Alcança apenas as respostas servidas pelo Nitro. Payloads copiados para `public/` e servidos pela plataforma de alojamento recebem os cabeçalhos dessa plataforma — consulte o guia de desempenho.

Análogo à opção experimental `httpCacheDuration` do `@nuxtjs/i18n` (v10.2.0), mas como cabeçalho de resposta explícito em vez do maxAge do `defineCachedEventHandler` do Nitro.

{/* /generated:option:httpCacheDuration */}

```ts
export default defineNuxtConfig({
  i18n: {
    // Per-build fallback (Date.now()) so immutable payloads never go stale when GIT_SHA is missing.
    dateBuild: process.env.GIT_SHA ?? String(Date.now()),
    httpCacheDuration: 86400, // 24 hours
    // httpCacheDuration: 0, // disable Cache-Control header
  },
})
```

#### `cacheMaxSize`

{/* generated:option:cacheMaxSize — do not edit; run `pnpm run docs:generate` */}

**Tipo** `number` · **Predefinição** `0`

Número máximo de entradas na cache de traduções em memória. `0` significa sem limite.

#### `cacheTtl`

{/* generated:option:cacheTtl — do not edit; run `pnpm run docs:generate` */}

**Tipo** `number` · **Predefinição** `0`

Tempo de vida (em segundos) das entradas de tradução em cache. `0` significa que as entradas nunca expiram.

{/* /generated:option:cacheTtl */}

```typescript
export default defineNuxtConfig({
  i18n: {
    // Limit cache to 1000 entries, each lives 10 minutes (refreshed on access)
    cacheMaxSize: 1000,
    cacheTtl: 600,
  },
})
```

<Tip>
Para a maioria dos projetos, a predefinição (ilimitada, sem expiração) é adequada — as traduções são pequenas e finitas. No entanto, se o seu projeto tem **milhares de páginas** com `disablePageLocales: false` e **muitos locales**, a cache do servidor pode crescer significativamente. Em servidores Node.js de longa duração, isto pode levar a uso excessivo de memória.

- **`cacheMaxSize`** — limita o número de entradas em cache. Útil para limitar a memória.
- **`cacheTtl`** — garante que traduções desatualizadas são recarregadas do armazenamento. Útil em ambientes serverless ou quando as traduções mudam em runtime.

**Fórmula para estimar o máximo de entradas**: `número_de_locales × (número_de_páginas + 1)`. Por exemplo, 10 locales × 500 páginas = ~5010 entradas.
</Tip>
