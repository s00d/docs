# Detalhes das opções

O módulo disponibiliza opções de configuração extensas para personalizar a sua configuração de internacionalização.

### 🌍 Definições principais de locale

#### `locales`

{/* generated:option:locales — do not edit; run `pnpm run docs:generate` */}

**Type** `Locale[]` · **Default** `[]`

List of supported locales.
Each entry defines a locale code plus optional metadata (ISO, direction, display name, etc.).

{/* /generated:option:locales */}

Cada objeto de locale suporta:

| Propriedade         | Tipo      | Obrigatório | Descrição                                           |
| ---------------- | --------- | -------- | ----------------------------------------------------- |
| `code`           | `string`  | ✅       | Identificador único (p. ex., `'en'`)                      |
| `displayName`    | `string`  | ❌       | Nome legível para switchers (p. ex., `'English'`) |
| `iso`            | `string`  | ❌       | Código ISO (p. ex., `'en-US'`)                            |
| `dir`            | `string`  | ❌       | Direção do texto (`'ltr'` ou `'rtl'`)                   |
| `disabled`       | `boolean` | ❌       | Desativar no dropdown se `true`                         |
| `baseUrl`        | `string`  | ❌       | URL base para domínios específicos por locale                  |
| `baseDefault`    | `boolean` | ❌       | Remover prefixo de locale dos URLs                        |
| `fallbackLocale` | `string`  | ❌       | Fallback por locale (substitui o global)                |
| `[key: string]`  | `unknown` | ❌       | Quaisquer propriedades personalizadas (ver abaixo)                     |

**Exemplo**:

```typescript
locales: [
  { code: 'en', iso: 'en-US', dir: 'ltr' },
  { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
  { code: 'ar', iso: 'ar-SA', dir: 'rtl', disabled: true },
  {
    code: 'de',
    iso: 'de-DE',
    dir: 'ltr',
    baseUrl: 'https://de.example.com',
    baseDefault: true,
  },
]
```

<Warning>
Utilizar `baseUrl` pode levar à duplicação de rotas internas como ligações externas, complicando o encaminhamento e a manutenção. Considere, em alternativa, criar ligações externas diretamente para locales específicos.
</Warning>

#### Propriedades personalizadas de locale

Pode adicionar quaisquer propriedades personalizadas aos objetos de locale. São passadas para o runtime e ficam acessíveis através de `$getLocales()`:

```typescript
locales: [
  { code: 'en', iso: 'en-US', flag: '🇬🇧', currency: 'GBP' },
  { code: 'de', iso: 'de-DE', flag: '🇩🇪', currency: 'EUR' },
  { code: 'ru', iso: 'ru-RU', flag: '🇷🇺', currency: 'RUB' },
]
```

Access them in components:

```vue
<template>
  <ul>
    <li v-for="locale in $getLocales()" :key="locale.code">{{ locale.flag }} {{ locale.displayName }} ({{ locale.currency }})</li>
  </ul>
</template>
```

Por predefinição, as propriedades personalizadas são tipadas como `unknown`. Para obter suporte completo em TypeScript, utilize **module augmentation**. Crie um ficheiro de declaração (p. ex., `app/i18n.d.ts` ou qualquer `.d.ts` incluído no seu `tsconfig`):

```typescript
// app/i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
    currency?: string
  }
}
```

Depois disto, todas as propriedades personalizadas ficam totalmente tipadas:

```typescript
const locales = $getLocales()
locales[0].flag // string | undefined ✅
locales[0].currency // string | undefined ✅
```

#### `strategy`

{/* generated:option:strategy — do not edit; run `pnpm run docs:generate` */}

**Type** `Strategies` · **Default** `'prefix_except_default'`

URL routing strategy for locale prefixes.

- `'no_prefix'` — no locale in URL; locale stored in cookie.
- `'prefix_except_default'` — prefix all locales except the default.
- `'prefix'` — always prefix, including the default locale.
- `'prefix_and_default'` — like `prefix`, but the default locale is also accessible without prefix.

{/* /generated:option:strategy */}

<CodeGroup>
```typescript no_prefix
strategy: 'no_prefix'
// Routes: /about, /contact
// Locale detection via browser/cookies
```

```typescript prefix_except_default
strategy: 'prefix_except_default'
// Default locale: /about, /contact
// Other locales: /fr/about, /de/contact
```

```typescript prefix
strategy: 'prefix'
// All locales: /en/about, /fr/about, /de/about
```

```typescript prefix_and_default
strategy: 'prefix_and_default'
// Both prefixed and non-prefixed versions for default locale
```
</CodeGroup>

### 📂 Gestão de traduções
#### `translationDir`

{/* generated:option:translationDir — do not edit; run `pnpm run docs:generate` */}

**Type** `string` · **Default** `'locales'`

Path to the directory containing translation JSON files, relative to the project root.

{/* /generated:option:translationDir */}

```typescript
translationDir: 'i18n' // Custom directory
// Nuxt 4 colocation example:
// translationDir: 'app/locales'
```

Os caminhos são resolvidos a partir da **raiz do projeto** Nuxt (`rootDir`), e não de `app/`. Com Nuxt 4, a configuração habitual é `app/pages/` para rotas e `locales/` (ou `app/locales`, caso defina `translationDir`) para ficheiros JSON.
#### `disablePageLocales`

{/* generated:option:disablePageLocales — do not edit; run `pnpm run docs:generate` */}

**Type** `boolean` · **Default** `false`

Disable per-page translation files.
When `true`, only global translations (`\{locale\}.json`) are loaded;
page-specific files (`pages/\{page\}/\{locale\}.json`) are not generated or loaded.

{/* /generated:option:disablePageLocales */}

Quando ativado, apenas os ficheiros de tradução ao nível da raiz são utilizados:

```tree
locales/
├── en.json
├── fr.json
└── ar.json
```
#### `fallbackLocale`

{/* generated:option:fallbackLocale — do not edit; run `pnpm run docs:generate` */}

**Type** `string` · **Default** `undefined (no fallback; returns the raw key)`

Global fallback locale code.
When a translation key is missing in the active locale, the module looks it up
in this locale before returning the key itself.

{/* /generated:option:fallbackLocale */}

```typescript
fallbackLocale: 'en' // Global fallback
```
#### `types`

{/* generated:option:types — do not edit; run `pnpm run docs:generate` */}

**Type** `boolean` · **Default** `true`

Generate TypeScript type declarations for `useI18n`, `$t`, and related helpers
based on the translation keys in your default locale files.

{/* /generated:option:types */}

Quando ativado, o módulo emite `.nuxt/i18n.d.ts` durante o build com chaves de tradução tipadas. Defina como `false` se preferir helpers sem tipos ou utilizar um gerador externo.

Este gerador incorporado é distinto do pacote opcional [`@i18n-micro/types-generator`](/integrations/types-generator), que pode produzir ficheiros de tipos mais rigorosos ou autónomos para monorepos e CI.

```typescript
types: false // Disable built-in key typing
```
#### `routeLocales`

{/* generated:option:routeLocales — do not edit; run `pnpm run docs:generate` */}

**Type** `Record<string, string[]>` · **Default** —

Per-route locale restrictions, extracted from `defineI18nRoute()` calls.
Maps a route path (e.g. `'/about'`) to an array of allowed locale codes.
Routes not listed have no restrictions (all locales allowed).

{/* /generated:option:routeLocales */}

Mapeia um caminho de rota (p. ex. `'/about'`) para os códigos de locale permitidos. As rotas não listadas permitem todos os locales configurados.

Normalmente configura isto via [`defineI18nRoute`](/guides/custom-locale-routes) nas páginas, em vez do `nuxt.config`. O módulo funde as declarações ao nível da página neste mapa em build-time.
#### `routeDisableMeta`

{/* generated:option:routeDisableMeta — do not edit; run `pnpm run docs:generate` */}

**Type** `Record<string, boolean \| string[]>` · **Default** —

Per-route meta tag disabling, extracted from `defineI18nRoute()` calls.
Maps a route path to `true` (disable all meta) or an array of locale codes
for which meta should be disabled.

{/* /generated:option:routeDisableMeta */}

- `true` — desativa todas as meta SEO para a rota.
- `string[]` — desativa meta apenas para os códigos de locale indicados.

Tal como `routeLocales`, isto é normalmente definido em componentes de página, e não manualmente na configuração.
#### `experimental`

{/* generated:option:experimental — do not edit; run `pnpm run docs:generate` */}

**Type** `Record<string, unknown>` · **Default** —

Bucket for experimental/unstable options.
Contents may change or be removed without notice between minor versions.

{/* /generated:option:experimental */}

A maioria das antigas flags `experimental.*` foi promovida a opções de topo na v3 (por exemplo `hmr`). Prefira as opções de topo documentadas. Utilize `experimental` apenas quando seguir uma nota de release ou um guia de migração que refira uma chave específica.

### 🔍 SEO e meta tags
#### `meta`

{/* generated:option:meta — do not edit; run `pnpm run docs:generate` */}

**Type** `boolean` · **Default** `true`

Generate SEO meta tags (`hreflang`, `canonical`, `og:url`, `og:locale`) automatically.

{/* /generated:option:meta */}

```typescript
meta: true // Generate alternate links, canonical URLs, etc.
```
#### `metaBaseUrl`

{/* generated:option:metaBaseUrl — do not edit; run `pnpm run docs:generate` */}

**Type** `string` · **Default** `undefined`

Base URL for SEO meta tags (canonical, og:url, hreflang).

- A concrete URL string (e.g. `'https://example.com'`) — used as-is (highest priority).
- `undefined` — falls back to `site.url` from `nuxt-site-config` when that module is
  present, otherwise the current request origin
  (`useRequestURL().origin` on server, `window.location.origin` on client).

{/* /generated:option:metaBaseUrl */}

Prioridade quando não definido: `site.url` do `nuxt-site-config` (se instalado) → origem do pedido
(`useRequestURL().origin` no servidor com `X-Forwarded-Host` / `X-Forwarded-Proto`,
`window.location.origin` no cliente). Ideal para **stacks SEO** que já definem `site.url`,
e para implementações **multi-domínio** quando `site.url` é omitido.

- Qualquer outra string — utilizada como URL base estático (tem precedência sobre `site.url`).

```typescript
// Prefer sharing the SEO stack origin — omit metaBaseUrl when site.url is set
site: { url: 'https://example.com' }

// Or pin an explicit override
metaBaseUrl: 'https://example.com'
```

{/* generated:option:canonicalQueryWhitelist — do not edit; run `pnpm run docs:generate` */}

List of query parameter names preserved in canonical and `og:url` meta tags.
Parameters not in this list are stripped from the canonical URL.

{/* /generated:option:canonicalQueryWhitelist */}

```typescript
canonicalQueryWhitelist: ['page', 'sort', 'category']
```

### 🔄 Funcionalidades avançadas
#### `globalLocaleRoutes`

{/* generated:option:globalLocaleRoutes — do not edit; run `pnpm run docs:generate` */}

**Type** `GlobalLocaleRoutes` · **Default** `\{\}`

Global route-level locale configuration.
Allows restricting or customizing locale routes for specific pages without
modifying their components.

- `false` — exclude the route from localization.
- `Record<LocaleCode, string>` — custom per-locale paths.

{/* /generated:option:globalLocaleRoutes */}

```typescript
globalLocaleRoutes: {
  'about': {
    en: '/about-us',
    fr: '/a-propos',
    de: '/uber-uns'
  },
  'unlocalized': false // Disable localization entirely
}
```

<Tip>
Para rotas adicionadas em `pages:extend` (sobretudo quando várias partilham um SFC wrapper), construa tanto `pages` como `globalLocaleRoutes` a partir de uma única lista com [`splitLocaleRoutes`](/guides/custom-locale-routes#programmatic-routes-pagesextend--244) — indexada pelo **nome** da rota, e não pelo caminho do ficheiro.
</Tip>

#### `routesLocaleLinks`

{/* generated:option:routesLocaleLinks — do not edit; run `pnpm run docs:generate` */}

**Type** `\{ [key: string]: string \}` · **Default** `\{\}`

Map route names to other route names to share the same translation files.
For example, `\{ 'about-us': 'about' \}` means the `about-us` page will use
translations from the `about` page instead of its own.

{/* /generated:option:routesLocaleLinks */}

```typescript
routesLocaleLinks: {
  'products-id': 'products',
  'about-us': 'about'
}
```
#### `customRegexMatcher`

{/* generated:option:customRegexMatcher — do not edit; run `pnpm run docs:generate` */}

**Type** `string \| RegExp` · **Default** `undefined (uses built-in pattern based on locale codes)`

Custom regular expression (or its string source) for matching locale codes in URL segments.
All locale codes defined in `locales` must match this pattern, or a warning is emitted.

{/* /generated:option:customRegexMatcher */}

<Danger>
Em build-time, o módulo **valida** que todos os códigos de locale da sua lista `locales` correspondem ao padrão de `customRegexMatcher`. Se algum código de locale não corresponder, **o build falha** com o erro:

> `Nuxt-i18n-micro: Some locale codes does not match customRegexMatcher`

Verifique sempre a sua regex contra todos os códigos de locale antes de implementar.
</Danger>

```typescript
// ✅ Correct: matches 'en-us', 'de-de', 'fr-fr'
customRegexMatcher: '[a-z]{2}-[a-z]{2}'

// ✅ Correct: matches 'en', 'de', 'fr', 'zh'
customRegexMatcher: '[a-z]{2}'

// ❌ Wrong: won't match 'zh-Hant' (uppercase letter)
// This will FAIL the build if 'zh-Hant' is in your locales list
customRegexMatcher: '[a-z]{2}-[a-z]{2}'
```

### 🔢 Personalização
#### `plural`

{/* generated:option:plural — do not edit; run `pnpm run docs:generate` */}

**Type** `PluralFunc` · **Default** `built-in pluralization (form index by count)`

Custom pluralization function.
Receives `(key, count, params, locale, getter)` and should return the selected
plural form as a string, or `null`/`undefined` to fall back to the built-in
`defaultPlural` logic (so you can override only some locales).

For the Nuxt module the function is serialized with `.toString()` into
`.nuxt/i18n.plural.mjs` — it must be self-contained (no imports / outer scope).
A file path string is **not** supported.

{/* /generated:option:plural */}

##### Como funciona

As traduções utilizam `|` para separar formas plurais:

```json
{
  "apples": "no apples | one apple | {count} apples"
}
```

Utilize `$tc('apples', count)` ou `$tc('cart', \{ count, name \})` quando uma forma precisar de mais do que `\{count\}` — passe **`count` e outros parâmetros no objeto do segundo argumento**, e não como terceiro argumento (o terceiro é apenas `defaultValue`).

A chamada de `$tc` invoca a função `plural`, que:

1. Chama `t(key)` para obter a string de tradução em bruto (p. ex. `"no apples | one apple | \{count\} apples"`).
2. Divide por `|` para obter o array de formas.
3. Seleciona uma forma com base em `count`.
4. Substitui `\{count\}` pelo número real.

A implementação **predefinida** seleciona por índice: `count < forms.length ? forms[count] : forms[last]`. Funciona para casos simples (0 → primeira forma, 1 → segunda, 2+ → última).

##### Função plural personalizada

Para idiomas com regras de pluralização complexas (p. ex., russo, árabe, polaco), substitua a opção `plural`.

<Danger>
The function is serialized via `.toString()` and injected into a virtual module at build time. This means:

- **Must use `function` keyword** — NOT shorthand method syntax, NOT arrow functions with external references
- **No imports or external references** — the function must be fully self-contained (a file path like `plural: '~/i18n/plural.ts'` is **not** supported)
- **No TypeScript-only syntax** that doesn't survive `.toString()` (type annotations are fine in `nuxt.config.ts` because Nuxt strips them)
- Returning `null` / `undefined` falls back to the built-in `defaultPlural` (useful for per-locale overrides)
</Danger>

**Example: Russian pluralization** (4 forms: zero, one, few, many):

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    plural: function (key, count, _params, _locale, t) {
      const translation = t(key)
      if (!translation) return key

      const forms = translation
        .toString()
        .split('|')
        .map(function (s) {
          return s.trim()
        })
      let idx

      if (count === 0) {
        idx = 0
      } else {
        const mod10 = count % 10
        const mod100 = count % 100
        if (mod10 === 1 && mod100 !== 11) {
          idx = 1
        } else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) {
          idx = 2
        } else {
          idx = 3
        }
      }

      if (idx >= forms.length) idx = forms.length - 1
      return (forms[idx] || '').replace('{count}', String(count))
    },
  },
})
```

With this translation:

```json
{
  "apples": "нет яблок | {count} яблоко | {count} яблока | {count} яблок"
}
```

Results:

- `$tc('apples', 0)` → `"нет яблок"`
- `$tc('apples', 1)` → `"1 яблоко"`
- `$tc('apples', 3)` → `"3 яблока"`
- `$tc('apples', 5)` → `"5 яблок"`
- `$tc('apples', 21)` → `"21 яблоко"`

**Exemplo: inglês simples (comportamento predefinido)**:

```typescript
// This is the built-in default — you don't need to set it explicitly
plural: function (key, count, params, _locale, t) {
  const translation = t(key, params)
  if (!translation) return null

  const forms = translation.toString().split('|')
  if (forms.length === 0) return null
  const form = count < forms.length ? forms[count] : forms[forms.length - 1]
  if (!form) return null
  return form.trim().replace('{count}', count.toString())
}
```

##### Pluralização por locale

Se diferentes locales precisarem de regras plurais distintas, ramifique em `locale` e devolva `null`
para os locales que não personaliza — o `defaultPlural` incorporado trata do restante:

```typescript
plural: function (key, count, _params, locale, t) {
  // Only override Slavic locales; en/de/… keep the built-in rules
  if (locale !== 'ru' && locale !== 'uk') return null

  const translation = t(key)
  if (!translation) return null

  const forms = translation.toString().split('|').map(function (s) { return s.trim() })
  let idx
  if (count === 0) {
    idx = 0
  } else {
    const mod10 = count % 10
    const mod100 = count % 100
    if (mod10 === 1 && mod100 !== 11) idx = 1

    else idx = 3

  if (idx >= forms.length) idx = forms.length - 1
  return (forms[idx] || '').replace('{count}', String(count))
}
```

#### `translationPayloads`

{/* generated:option:translationPayloads — do not edit; run `pnpm run docs:generate` */}

**Type** `TranslationPayloadOptions` · **Default** —

Controls how translation payloads are emitted (Node: `public/<apiBaseUrl>`; Edge: Nitro `serverAssets`).

- **Node**: `serverAssets` means local SSR via `readFile` under `public/` (no Rollup `raw:`).
- **Edge**: `serverAssets` registers Nitro `serverAssets` (`assets:i18n`); it does not force a public copy.

Keep the defaults for the usual all-in-one setup. For large Edge catalogs prefer `mode: 'source'`.
For CDN-backed deployments, disable local outputs and set `apiBaseClientHost` / `apiBaseServerHost`.

{/* /generated:option:translationPayloads */}

```typescript
{
  mode?: 'premerged' | 'source'
  serverAssets?: boolean
  serverHandler?: boolean
  publicAssets?: boolean
  prerenderRoutes?: boolean
  publicDir?: string
  warnFileCount?: number
  warnSizeBytes?: number
}
```

**Predefinição** (`mode: 'premerged'`):

```typescript
{
  mode: 'premerged',
  serverAssets: true,
  serverHandler: true,
  publicAssets: true,
  prerenderRoutes: false
}
```

O SSR em **Node** lê a mesma árvore copiada para `public/<apiBaseUrl>/` (`readFile`). Em **Edge**, o `serverAssets` do Nitro incorpora-a (sem cópia pública forçada — defina `publicAssets: true` para CDN). `mode: 'premerged'` → `\{page\}/\{locale\}/data.json` por página/locale; `mode: 'source'` → origem compacta + fusão em runtime.

`serverAssets: true` em **Node** força a cópia pública mesmo que `publicAssets` seja `false`. Em **Edge** apenas regista o embed do Nitro. Prefira `mode: 'source'` em Edge para catálogos grandes. Sem payloads locais e sem `apiBaseServerHost`, o build falha.

O handler local `/\{apiBaseUrl\}/:page/:locale/data.json`, as rotas de prerender e as cópias de assets públicos continuam a ser saídas opcionais.

Para payloads **públicos** / Edge compactos:

```typescript
i18n: {
  translationPayloads: {
    mode: 'source',
  },
}
```

O `mode: 'source'` mantém ficheiros por camadas compactos e funde raiz/página/fallback em runtime através da rota incorporada `/_locales` (ou `assets:i18n` em Edge). Por predefinição, desativa as cópias de assets públicos e as rotas de payload pré-renderizadas.

<Warning>
Com `mode: 'source'`, `publicAssets` tem `false` como predefinição (`prerenderRoutes` está sempre desligado, salvo se optar por o ativar). Alojamento puramente estático sem um runtime Nitro/edge não consegue, portanto, carregar traduções no cliente, a menos que ative uma destas saídas, mantenha `serverHandler` disponível em runtime ou aloje payloads externamente.

Com o `mode: 'premerged'` predefinido e `publicAssets: true`, os ficheiros estáticos já ficam em `public/<apiBaseUrl>/\{page\}/\{locale\}/data.json` — coincidindo com os URLs de `$fetch` do cliente — pelo que um host estático pode servi-los sem Nitro.
</Warning>

<Warning>
Quando `apiBaseServerHost` ou `apiBaseClientHost` está definido, o módulo obtém JSON já fundido dessa origem. Hosts externos têm de servir as mesmas respostas `/\{apiBaseUrl\}/:page/:locale/data.json` da rota incorporada. `mode: 'source'` aplica-se aos diretórios locais de payloads, e não a um CDN externo, salvo se esse CDN também servir payloads fundidos em runtime.
</Warning>

Também pode desativar manualmente saídas locais duplicadas e servir os payloads de tradução a partir de um CDN ou armazenamento de objetos:

```typescript
i18n: {
  apiBaseClientHost: 'https://cdn.example.com',
  apiBaseServerHost: 'https://cdn.example.com',
  translationPayloads: {
    serverHandler: false,
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

Se apenas quiser evitar escrever payloads na saída pública mantendo a rota do servidor incorporada para pedidos SSR/runtime, desative ambas as saídas públicas:

```typescript
i18n: {
  translationPayloads: {
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

Em **Node**, `serverAssets: true` continua a forçar uma cópia pública para o SSR mesmo quando `publicAssets` é `false` — defina `serverAssets: false` e `apiBaseServerHost` se quiser zero ficheiros de payload locais.

Use `publicDir` para alterar a pasta de saída pública quando os payloads são copiados. A predefinição é `apiBaseUrl` (`_locales`). Em modo premerged, o `publicAssets` escreve aí `\{page\}/\{locale\}/data.json` (os mesmos caminhos que o cliente obtém). `prerenderRoutes` é um prerender opcional do Nitro das rotas do handler — normalmente redundante quando essa árvore já foi copiada.

Se desativar todas as saídas locais de payloads, tem de configurar tanto `apiBaseServerHost` (SSR) como `apiBaseClientHost` (navegação do cliente). Outroswise translations will resolve to empty objects and UI keys may appear untranslated.

`warnFileCount` and `warnSizeBytes` control build-time warnings when pre-merged payload output grows large (defaults: 500 files and 10 MB).

#### `dateBuild`

{/* generated:option:dateBuild — do not edit; run `pnpm run docs:generate` */}

**Type** `string \| number` · **Default** —

Value used for cache-busting translation requests (`?v=...`).

(e.g. a git SHA or build number).

{/* /generated:option:dateBuild */}

Por predefinição, o módulo gera um fingerprint das suas fontes de tradução (SHA-256 sobre cada
`<layer>/<translationDir>/**/*.json`, pela ordem das camadas) e utiliza-o. O valor apenas muda quando uma
tradução realmente muda, portanto reconstruir ou reimplementar traduções inalteradas deixa as caches do navegador e
do CDN intactas — com `httpCacheDuration` definido para um ano, um timestamp de build forçaria
todos os clientes a voltar a transferir o dicionário completo a cada deploy.

Faz fallback para `Date.now()` apenas quando não existem ficheiros de tradução para submeter a hash.

Defina-o explicitamente para assumir o controlo (p. ex., para associar URLs de payload a uma release em vez do conteúdo):

```ts
export default defineNuxtConfig({
  i18n: {
    // Any stable string/number: git SHA, CI build number, release tag, etc.
    dateBuild: process.env.GIT_SHA ?? 'local-dev',
  },
})
```
#### `httpCacheDuration`

{/* generated:option:httpCacheDuration — do not edit; run `pnpm run docs:generate` */}

**Type** `number` · **Default** `31536000`

HTTP `Cache-Control` max-age (seconds) for `/\{apiBaseUrl\}/:page/:locale/data.json`.

Applies in full only while `dateBuild` busts the URL (`?v=...`), which is the default:
the response is then `public, max-age=…, immutable` and safe for browsers and CDNs.

- `dateBuild: 0`/`''` — the URL is stable, so this duration is *not* honoured; the
  response becomes `public, max-age=0, must-revalidate` instead. A long `max-age` on an
  unchanging URL pins the first payload a browser ever saw.

- `0` — do not set `Cache-Control` at all (useful in local debugging)
- Not applied in development (`import.meta.dev`) so HMR is not fought by the browser cache
- Reaches only responses served through Nitro. Payloads copied into `public/` and served
  by the hosting platform take that platform's headers — see the Performance guide.

Analogous to `@nuxtjs/i18n` experimental `httpCacheDuration` (v10.2.0), but as an
explicit response header rather than Nitro `defineCachedEventHandler` maxAge.

{/* /generated:option:httpCacheDuration */}

```ts
export default defineNuxtConfig({
  i18n: {
    // Per-build fallback (Date.now()) so immutable payloads never go stale when GIT_SHA is missing.
    dateBuild: process.env.GIT_SHA ?? String(Date.now()),
    httpCacheDuration: 86400, // 24 hours
    // httpCacheDuration: 0, // disable Cache-Control header
  },
})
```

```ts
  i18n: {
    numberFormats: {
      en: {

        decimal: { style: 'decimal', minimumFractionDigits: 2, maximumFractionDigits: 2 },

      },
      de: {
        currency: { style: 'currency', currency: 'EUR' },
      },
    },
  },
})
```

```ts
$tn(10000, 'currency') // $10,000.00
$tn(10000, 'currency', 'de') // 10.000,00 €
$tn(10000, 'currency', { notation: 'compact' })
```

As chaves devem corresponder aos valores de `code` do locale. Se faltar uma chave de locale exata, é tentada a subetiqueta de idioma (`en-US` → `en`).

#### `cacheTtl`

{/* generated:option:cacheTtl — do not edit; run `pnpm run docs:generate` */}

**Type** `number` · **Default** `0`

Time-to-live (in seconds) for cached translation entries.
`0` means entries never expire.

{/* /generated:option:cacheTtl */}

```typescript
export default defineNuxtConfig({
  i18n: {
    // Limit cache to 1000 entries, each lives 10 minutes (refreshed on access)
    cacheMaxSize: 1000,
    cacheTtl: 600,
  },
})
```

<Tip>
Para a maioria dos projetos, a predefinição (ilimitado, sem expiração) é adequada — as traduções são pequenas e finitas. Contudo, se o seu projeto tiver **milhares de páginas** com `disablePageLocales: false` e **muitos locales**, a cache do servidor pode crescer significativamente. Em servidores Node.js de longa duração, isto pode levar a uma utilização excessiva de memória.

- **`cacheMaxSize`** — limita o número de entradas em cache. Útil para conter a memória.
- **`cacheTtl`** — garante que traduções obsoletas acabam por ser recarregadas do armazenamento. Útil em ambientes serverless ou quando as traduções mudam em runtime.

**Fórmula para estimar o número máximo de entradas**: `número_de_locales × (número_de_páginas + 1)`. Por exemplo, 10 locales × 500 páginas = ~5010 entradas.
</Tip>
