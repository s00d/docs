### Descrição

Compara **plain Nuxt** (linha base sem módulo i18n), **i18n-micro** e **`@nuxtjs/i18n` v10.6** com um perfil de dicionário partilhado.

Foco: tempo de build, RSS de pico, código vs traduções vs total implementáveis e comportamento do servidor com Artillery + Autocannon.

### Notas sobre a metodologia

- As métricas são **médias de 3 execuções consecutivas por fixture** (fixture A ×3, depois B ×3, depois C ×3 — não intercaladas).
- **Traduções** incluem JSON de locale em `locales/` / `_locales/` / `translations/`, tudo em `chunks/raw/` e chunks de locale correspondentes. Relatórios antigos que mostravam `@nuxtjs/i18n` "translations: 0 B" e uma coluna enorme de "code" estavam a contar chunks de mensagens como código de aplicação.
- O **plain-nuxt** serve o mesmo volume de folhas como JSON estático em `public/translations` (e não como imports JS estáticos). Sob Artillery, essa linha base é intensiva em I/O; não é "overhead de i18n", é o custo de obter JSON grande por pedido.

### Execuções

Todas as métricas abaixo são **médias de 3 execuções**.

### Perfil da fixture

| Parâmetro | Valor |
|------|-------|
| Locales | **4** (`en`, `de`, `ru`, `fr`) |
| Páginas | **2** (`index`, `page`) |
| Árvore do index | profundidade **5**, ramo **7** → **16 807** chaves-folha / locale |
| Páginas secundárias | profundidade **5**, ramo **6** → **7 776** chaves-folha / página / locale |
| Objetivo | Perfil predefinido da CLI (`--locales 4 --keys 10000`); aumente parâmetros para cargas de "radar de regressão" |

Os dicionários vêm de `test/fixtures/perf-shared/runtime.json` (escrito pela CLI) para que as três fixtures se mantenham alinhadas.

## Notas

- Perfil partilhado: 4 locales × 2 páginas × ~16,8k folhas de index.
- Artillery: aquecimento de 6s a 6 VU/s + 60s principal a 60 VU/s. Autocannon: 10 ligações × 10s.
- Reexecutar: `pnpm test:performance` ou `pnpm -C scripts cli performance --locales N --keys K --only all|micro|i18n|plain --runs N`.
