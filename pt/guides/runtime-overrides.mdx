# Substituições i18n em runtime

Use este guia quando precisar que um único artefacto de build corra com predefinições de locale diferentes por ambiente (por exemplo, várias instâncias por tenant).

## O que pode ser substituído em runtime

O módulo suporta substituições seguras em runtime para:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Estas substituições são aplicadas por cima da configuração em tempo de build, proveniente de `.nuxt/i18n.strategy.mjs` e `.nuxt/i18n.config.mjs`.

## O que não pode ser substituído em runtime

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) é uma questão de tempo de build porque afeta o comportamento das rotas geradas.

Se passar uma substituição de estratégia em runtime, é ignorada e é emitido um aviso.

## Substituições baseadas em RuntimeConfig

Forneça valores em runtime em `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Substituições via variáveis de ambiente

Também pode configurar substituições através de variáveis de ambiente:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (separado por vírgulas, por exemplo, `fr,it`)

Aliases de fallback também são suportados:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Regras de validação

Em runtime, o módulo valida as substituições para evitar estados inválidos:

- Não pode desativar todos os locales.
- `defaultLocale` deve apontar para um locale ativado.
- `fallbackLocale` deve existir nos locales declarados.

Se uma substituição for inválida, o módulo mantém um valor seguro e regista um aviso.

## Notas para implementações multi-instância

Esta funcionalidade em runtime foi concebida para ativação e predefinições de locale por instância sem rebuild.

Se as instâncias exigirem estratégias de URL diferentes (`no_prefix` vs `prefix`), utilize builds separadas para cada estratégia.

## Locales desativados e payloads estáticos

`runtimeConfig.public.i18nRuntime.disabledLocales` atualiza o encaminhamento, o switcher e o **handler** de payloads do Nitro. Mas o Nitro serve ficheiros em `public/` **antes** desse handler.

Se `translationPayloads.publicAssets` (ou a cópia pública forçada do SSR em Node) já escreveu `/_locales/\{page\}/\{locale\}/data.json`, uma desativação em runtime não consegue ocultar esse ficheiro. Prefira `locale.disabled: true` em tempo de build para que o premerge não emita os payloads estáticos desse locale.
