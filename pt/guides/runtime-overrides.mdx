# Substituições i18n em runtime

Utilize este guia quando precisar que um único artefacto de build seja executado com predefinições de locale diferentes por ambiente (por exemplo, instâncias de tenants distintos).

## O que pode ser substituído em runtime

O módulo suporta substituições seguras em runtime para:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Estas substituições são aplicadas sobre a configuração de build definida em `.nuxt/i18n.strategy.mjs` e `.nuxt/i18n.config.mjs`.

## O que não pode ser substituído em runtime

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) é uma preocupação de build-time, uma vez que afeta o comportamento das rotas geradas.

Se passar uma substituição de estratégia em runtime, esta é ignorada e é emitido um aviso.

## Substituições através de RuntimeConfig

Forneça os valores de runtime em `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Substituições por variáveis de ambiente

Também pode configurar substituições através de variáveis de ambiente:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (separadas por vírgulas, p. ex. `fr,it`)

São também suportados aliases de fallback:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Regras de validação

Em runtime, o módulo valida as substituições para evitar estados inconsistentes:

- Não pode desativar todos os locales.
- `defaultLocale` tem de apontar para um locale ativado.
- `fallbackLocale` tem de existir nos locales declarados.

Se uma substituição for inválida, o módulo mantém um valor seguro e regista um aviso.

## Notas para implementações multi-instância

Esta funcionalidade em runtime foi concebida para ativar e definir predefinições de locales por instância, sem reconstruir a aplicação.

Se as instâncias necessitarem de estratégias de URL diferentes (`no_prefix` vs `prefix`), utilize builds separados para cada estratégia.

## Locales desativados e payloads estáticos

`runtimeConfig.public.i18nRuntime.disabledLocales` atualiza o encaminhamento, o switcher e o **handler** de payloads do Nitro — mas o Nitro serve ficheiros de `public/` **antes** desse handler.

Se `translationPayloads.publicAssets` (ou a cópia pública forçada no SSR do Node) já tiver escrito `/_locales/\{page\}/\{locale\}/data.json`, uma desativação em runtime não consegue ocultar esse ficheiro. Prefira `locale.disabled: true` no build, para que o premerge não emita os payloads estáticos desse locale.
