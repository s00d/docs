# 🔥 Deploy no Firebase AppHosting

## 📖 Introdução

O Firebase AppHosting é uma plataforma poderosa para implementar aplicações Nuxt com infraestrutura serverless. Contudo, ao implementar aplicações com o `nuxt-i18n-micro`, poderá encontrar problemas específicos relacionados com a forma como os ficheiros JSON de tradução são servidos. Este guia apresenta soluções abrangentes para garantir que as suas traduções funcionam corretamente em produção.

## ⚠️ Problemas comuns

### Ficheiros de tradução não são aplicados

**Sintomas:**

- ✅ As traduções funcionam perfeitamente em desenvolvimento (`nuxt dev`).
- ❌ Após a implementação no Firebase AppHosting, os ficheiros JSON carregam, mas as traduções não são aplicadas.
- ❌ Não aparecem erros na consola.
- ❌ Os ficheiros de tradução são visíveis no separador Network, mas com o `Content-Type: text/html` incorreto em vez de `application/json`.

**Causa raiz:**

O Firebase AppHosting (e outras plataformas que utilizam a pré-renderização do Nitro) podem servir ficheiros JSON pré-renderizados com tipos MIME incorretos. Quando o navegador recebe ficheiros JSON com `Content-Type: text/html`, não consegue analisá-los corretamente, e as traduções falham silenciosamente.

## ✅ Soluções

### Solução 1: configuração de Route Rules (recomendada)

A solução mais direta é adicionar cabeçalhos explícitos para as rotas de tradução no seu `nuxt.config.ts`:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**Vantagens:**

- ✨ Configuração simples.
- 🚀 Melhora o desempenho com uma cache adequada.
- 🔒 Funciona em todas as plataformas de implementação.

### Solução 2: URL base de API personalizado

Se estiver a utilizar um `apiBaseUrl` personalizado (apenas prefixo de caminho), ajuste as route rules em conformidade:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### Solução 3: configuração específica do Firebase

Crie ou atualize o ficheiro `firebase.json` na raiz do projeto:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```

## 🔍 Depuração

### Ativar o modo de depuração

Adicione registos de depuração para identificar problemas:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

Isto produzirá registos detalhados sobre:

- 📝 Carregamento de ficheiros de tradução.
- 🔄 Operações de cache.
- ⚠️ Erros de carregamento.

### Verifique o separador Network

1. Abra as DevTools → separador Network.
2. Filtre por "data.json".
3. Clique num pedido de ficheiro de tradução.
4. Verifique os **Response Headers**:
   - ✅ `Content-Type: application/json` (correto).
   - ❌ `Content-Type: text/html` (incorreto — precisa de ser corrigido).

### Verifique a saída de prerender

Após o build, verifique se os ficheiros de tradução são gerados:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

Deve ver `data.json` para cada locale em cada página.

## 🚀 Configuração de build

### Preset do Nitro

Para o Firebase AppHosting, garanta que utiliza o preset correto:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### Configuração de prerender

Configure a pré-renderização para desempenho ótimo:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

## 📋 Exemplo de configuração completa

Segue-se uma configuração completa e funcional para o Firebase AppHosting:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'es', iso: 'es-ES', dir: 'ltr' },
      { code: 'it', iso: 'it-IT', dir: 'ltr' },
      { code: 'pt', iso: 'pt-PT', dir: 'ltr' },
      { code: 'ru', iso: 'ru-RU', dir: 'ltr' },
      { code: 'zh', iso: 'zh-CN', dir: 'ltr' },
      { code: 'ko', iso: 'ko-KR', dir: 'ltr' },
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
    debug: false, // Enable in development if needed
  },

  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },

  nitro: {
    preset: 'firebase-app-hosting',
    prerender: {
      crawlLinks: true,
      routes: ['/'],
    },
  },
})
```

## ✅ Checklist de verificação

Depois de aplicar as correções, verifique se tudo funciona:

- [ ] O build termina sem erros.
- [ ] Os ficheiros JSON de tradução estão em `.output/public/_locales/\{page\}/\{locale\}/data.json`.
- [ ] O separador Network mostra `Content-Type: application/json` para os ficheiros de tradução.
- [ ] As traduções aparecem corretamente no primeiro carregamento da página.
- [ ] Não há divergências de hidratação na consola.
- [ ] A alternância de idiomas funciona corretamente.
- [ ] As meta tags de SEO são geradas corretamente.

## 🔄 Fluxo de implementação

### 1. Preparar o build

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. Deploy para o Firebase

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. Verificar a implementação

1. Visite o seu site implementado.
2. Abra as DevTools → separador Network.
3. Navegue para uma página.
4. Verifique se `/_locales/index/en/data.json` (ou o seu locale predefinido) carrega com:
   - Status: 200.
   - Content-Type: application/json.
   - A resposta contém JSON válido.

## 🔧 Resolução de problemas

### Problema: erros 404 para ficheiros de tradução

**Solução:** garanta que os ficheiros de tradução são copiados para o diretório de saída:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### Problema: as traduções funcionam em algumas páginas, mas não noutras

**Solução:** verifique se as traduções específicas de página estão a ser geradas:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

Se faltarem traduções específicas de página, garanta que `disablePageLocales` não está definido como `true`:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### Problema: carregamento lento das traduções

**Solução:** otimize a cache e o pré-carregamento:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## 💡 Dicas

1. **Teste sempre num ambiente semelhante ao de produção** antes de implementar.
2. **Utilize o modo de depuração** durante a configuração inicial para detetar problemas cedo.
3. **Monitorize as taxas de acerto da cache** para otimizar o desempenho.
4. **Mantenha os ficheiros de tradução pequenos** para um carregamento mais rápido.
5. **Utilize cabeçalhos de cache adequados** para reduzir a carga do servidor.

## ⚡ Otimização de desempenho

### Ativar a compressão

O Firebase trata automaticamente da compressão Gzip/Brotli, mas garanta que o seu build está otimizado:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### Carregar traduções de forma preguiçosa

O `Nuxt I18n Micro` faz automaticamente lazy load das traduções por página. As traduções só são carregadas quando necessárias, reduzindo o tamanho inicial do bundle. Esta funcionalidade é nativa — não é necessária configuração adicional.

Para otimizar ainda mais:

- Use `disablePageLocales: false` (predefinição) para ativar traduções específicas de página.
- Mantenha as traduções ao nível da raiz mínimas.
- Utilize ficheiros de tradução específicos de rota para o conteúdo da página.

<Tip>
O módulo define automaticamente cabeçalhos `Content-Type` adequados a partir da versão **v3.0.0+**. Se estiver a ter problemas, atualize para a versão mais recente:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
