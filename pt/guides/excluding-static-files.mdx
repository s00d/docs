# Excluir ficheiros estáticos do encaminhamento i18n

## Visão geral

Por predefinição, o nuxt-i18n-micro exclui automaticamente ficheiros estáticos comuns do processamento de encaminhamento i18n. No entanto, pode também configurar padrões de exclusão personalizados para impedir que caminhos específicos sejam processados pelo sistema i18n.

## Exclusões incorporadas

O módulo exclui automaticamente os seguintes tipos e padrões de ficheiro:

- **Sitemaps**: `/sitemap*.xml`, `/sitemap-en.xml`, etc.
- **Ficheiros SEO**: `/robots.txt`, `/favicon.ico`
- **Ficheiros PWA**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Assets estáticos**: ficheiros com extensões como `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Caminhos internos do Nuxt**: qualquer caminho iniciado por `__` (como `/__nuxt/`)

## Padrões de exclusão personalizados

Pode definir padrões de exclusão personalizados através da opção `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Tipos de padrão

### Padrões em string

- **Correspondência exata**: `'/api/health'` — corresponde exatamente a `/api/health`
- **Correspondência de prefixo**: `'/admin'` — corresponde a `/admin` e `/admin/dashboard`
- **Curingas**: `'/api/*'` — corresponde a `/api/users`, mas não a `/api/users/123`
- **Curingas profundos**: `'/admin/**'` — corresponde a `/admin/users` e `/admin/users/123`

### Expressões regulares

Utilize objetos RegExp para correspondência de padrões complexos:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Casos de uso

### Ficheiros SEO

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### Rotas de API

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Painéis de administração

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Assets estáticos

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Como funciona

1. **Middleware de servidor**: um middleware Nitro corre primeiro para verificar os padrões de exclusão
2. **Processamento de página**: durante a resolução de páginas, os caminhos excluídos são ignorados
3. **Rota catch-all**: a rota de fallback verifica exclusões antes de processar
4. **Pré-renderização**: caminhos excluídos não são incluídos nas rotas pré-renderizadas

## Impacto no desempenho

- As verificações de exclusão são otimizadas e correm cedo no ciclo de vida do pedido
- Os padrões incorporados usam correspondência regex eficiente
- Padrões personalizados são colocados em cache e reutilizados
- Overhead de desempenho mínimo para caminhos excluídos

## Resolução de problemas

### Ficheiros estáticos continuam a ser intercetados

1. **Verifique a sintaxe do padrão**: garanta que os padrões correspondem exatamente à estrutura do caminho
2. **Use regex para padrões complexos**: os curingas em strings têm limitações
3. **Teste os padrões**: use as ferramentas de programador do browser para verificar o caminho real do pedido
4. **Verifique a ordem**: garanta que os padrões de exclusão são definidos antes de outras configurações i18n

### Padrão não funciona

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Modo de depuração

Ative o modo de depuração para ver o processamento de exclusões:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Isto irá registar as decisões de exclusão na consola.

## Migração de soluções alternativas

Se estava a usar soluções alternativas, como regras de rota ou middleware, pode agora substituí-las por `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

A nova abordagem é mais fiável e funciona em vários níveis do sistema de encaminhamento.
