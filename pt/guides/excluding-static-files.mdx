# Excluir ficheiros estáticos do encaminhamento i18n

## Visão geral

Por predefinição, o nuxt-i18n-micro exclui automaticamente ficheiros estáticos comuns do processamento de encaminhamento i18n. Contudo, também pode configurar padrões de exclusão personalizados para impedir que caminhos específicos sejam processados pelo sistema i18n.

## Exclusões incorporadas

O módulo exclui automaticamente os seguintes tipos de ficheiros e padrões:

- **Sitemaps**: `/sitemap*.xml`, `/sitemap-en.xml`, etc.
- **Ficheiros SEO**: `/robots.txt`, `/favicon.ico`
- **Ficheiros PWA**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Assets estáticos**: ficheiros com extensões como `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Caminhos internos do Nuxt**: qualquer caminho que comece por `__` (como `/__nuxt/`)

## Padrões de exclusão personalizados

Pode definir padrões de exclusão personalizados através da opção `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Tipos de padrão

### Padrões em string

- **Correspondência exata**: `'/api/health'` — corresponde exatamente a `/api/health`.
- **Correspondência por prefixo**: `'/admin'` — corresponde a `/admin` e a `/admin/dashboard`.
- **Wildcards**: `'/api/*'` — corresponde a `/api/users` mas não a `/api/users/123`.
- **Wildcards profundos**: `'/admin/**'` — corresponde a `/admin/users` e a `/admin/users/123`.

### Expressões regulares

Utilize objetos RegExp para correspondência de padrões complexos:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Casos de utilização

### Ficheiros SEO

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### Rotas de API

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Painéis de administração

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Assets estáticos

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Como funciona

1. **Middleware do servidor**: um middleware Nitro é executado primeiro para verificar os padrões de exclusão.
2. **Processamento de páginas**: durante a resolução da página, os caminhos excluídos são ignorados.
3. **Rota catch-all**: a rota de fallback verifica as exclusões antes de processar.
4. **Prerendering**: os caminhos excluídos não são incluídos nas rotas pré-renderizadas.

## Impacto no desempenho

- As verificações de exclusão são otimizadas e executadas no início do ciclo de vida do pedido.
- Os padrões incorporados utilizam correspondência regex eficiente.
- Os padrões personalizados são colocados em cache e reutilizados.
- Impacto mínimo no desempenho para os caminhos excluídos.

## Resolução de problemas

### Ficheiros estáticos continuam a ser intercetados

1. **Verifique a sintaxe do padrão**: certifique-se de que os padrões correspondem exatamente à estrutura do caminho.
2. **Utilize regex para padrões complexos**: os wildcards em strings têm limitações.
3. **Teste os padrões**: use as dev tools do navegador para verificar o caminho real do pedido.
4. **Verifique a ordem**: garanta que os padrões de exclusão são definidos antes de outra configuração i18n.

### Padrão não funciona

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Modo de depuração

Ative o modo de depuração para ver o processamento das exclusões:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Isto registará as decisões de exclusão na consola.

## Migração a partir de soluções de contorno

Se estava a utilizar soluções de contorno como route rules ou middleware, pode agora substituí-las por `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

A nova abordagem é mais fiável e funciona em vários níveis do sistema de encaminhamento.
