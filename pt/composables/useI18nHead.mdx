---
title: "useI18nHead"
description: "useI18nHead substitui as tags SEO i18n geradas para uma página: substitua ou remova as tags canonical, hreflang e og, ou adicione as suas."
---

`useI18nHead()` altera as tags SEO que o módulo gera, apenas para uma página. Use-o quando uma página sabe mais do que o router: um artigo de CMS que só existe em alguns locales, um URL canónico vindo de uma API, tags `og:` adicionais. Obtém as tags geradas com as suas substituições fundidas por cima.

## Assinatura {#signature}

```ts
useI18nHead(input?: MaybeRefOrGetter<I18nHeadInput | null>): { pageHead: any; resetPageHead: () => void }
```

Regista substituições ao nível da página para as tags de head SEO i18n.
Fundidas por cima do resultado de `useLocaleHead` pelo plugin `02.meta`.

Prefira um getter (`() => ({ … })`) quando os valores vêm de `$t` / `t`, para que
sejam resolvidos novamente quando o locale muda. Um objeto simples é avaliado uma vez e fica congelado.

| Parâmetro | Tipo | Descrição |
| --- | --- | --- |
| `input` *(opcional)* | `MaybeRefOrGetter<I18nHeadInput \| null>` |  |

Funciona com [`meta: true`](/pt/api/module-options#meta) (a predefinição): o plugin meta do módulo funde o input sobre o resultado de [`useLocaleHead`](/pt/composables/useLocaleHead) em cada renderização do head. Com `meta: false` nada o lê.

A substituição é reposta quando o nome da rota muda. Uma página que define `disableMeta` não recebe nenhuma tag i18n, incluindo as substituições.

## Input {#input}

`I18nHeadInput` (de `@i18n-micro/types`):

| Chave | Tipo | Efeito |
| --- | --- | --- |
| `htmlAttrs` | `Record<string, string>` | Fundido nos atributos de `<html>` (`lang`, `dir`). |
| `meta` | `I18nHeadMeta[]` | Adicionado depois das tags geradas; substitui uma tag com o mesmo `id`, `property` ou `name`. |
| `link` | `I18nHeadLink[]` | Adicionado depois dos links gerados; substitui um link com o mesmo `id`, ou `rel` + `hreflang`. |
| `replace.canonical` | `string \| false` | Substitui o `href` canónico ou remove o link. |
| `replace.hreflang` | `I18nHeadLink[] \| false` | Substitui ou remove **todos** os links `rel="alternate"`, incluindo `x-default`. |
| `replace.xDefault` | `I18nHeadLink \| false` | Substitui ou remove o link `x-default`. |
| `replace.ogLocale` | `string \| false` | Substitui ou remove `og:locale`. |
| `replace.ogUrl` | `string \| false` | Substitui ou remove `og:url`. |
| `replace.ogAlternates` | `string[] \| false` | Reconstrói `og:locale:alternate` a partir destes códigos de locale (via `og` / `iso`), ignorando o locale atual, os códigos desconhecidos e os códigos sem valor `og` ou `iso`, ou remove-os. |
| `disable` | `I18nHeadDisableGroup[]` | Remove grupos gerados: `'hreflang'` (não `x-default`), `'x-default'`, `'canonical'`, `'og'` (`og:locale` + `og:url`), `'og-alternates'`, `'html'`. |

Ordem de aplicação: `disable`, depois `replace`, depois `htmlAttrs`, `meta`, `link`.

## Exemplo {#example}

Um artigo que só existe em alguns locales, com URLs alternativos vindos da API:

```vue
<script setup lang="ts">
const route = useRoute()
const { t } = useI18n()
const { data: article } = await useFetch<{ title: string; urls: Record<string, string> }>(`/api/articles/${route.params.slug}`)

useI18nHead(() => {
  if (!article.value) return null
  const codes = Object.keys(article.value.urls)
  return {
    meta: [{ property: 'og:title', content: article.value.title || t('blog.title') }],
    replace: {
      hreflang: codes.map((code) => ({ rel: 'alternate', hreflang: code, href: article.value!.urls[code]! })),
      ogAlternates: codes,
    },
  }
})
</script>
```

Passe um getter, como aqui, quando os valores vêm de `t()` ou de dados assíncronos: é executado novamente quando o locale muda. Um objeto simples é lido uma vez.
