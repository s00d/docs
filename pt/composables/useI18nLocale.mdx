---
title: "useI18nLocale"
description: "useI18nLocale lê e escreve o estado do locale e o cookie de locale — o ponto de entrada para a deteção de locale personalizada."
---

`useI18nLocale()` dá acesso ao locale escolhido pela aplicação: o estado `i18n-locale` e o cookie de locale. Use-o num plugin que deteta o locale por si próprio (domínio, perfil do utilizador, cabeçalho) em vez de escrever `useState('i18n-locale')` ou o cookie à mão. As suas verificações de validade usam os locales ativos, incluindo as substituições em runtime.

## Assinatura {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Ponto de entrada centralizado para a gestão do locale i18n.
Combina useState('i18n-locale'), o cookie de locale e utilitários de sincronização.

## Valores devolvidos {#returned-values}

| Membro | Tipo | Descrição |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | A ref `useState('i18n-locale')`. |
| `localeCookie` | `Ref<string \| null>` | O cookie [`localeCookie`](/pt/api/module-options#localecookie); um simples `{ value: null }` quando a opção é `null`. |
| `hashCookie` | `Ref<string \| null>` | O cookie `hash-locale` com hash routing; `{ value: null }` caso contrário. |
| `validLocales` | `string[]` | Códigos dos locales ativos. |
| `setLocale(locale)` | `(locale: string \| null) => void` | Escreve o estado e os cookies. Não valida e não carrega traduções. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | Escreve apenas os cookies. |
| `getLocale()` | `() => string \| null` | O estado e, a seguir, o cookie de preferência (o cookie de hash com hash routing). Não validado. |
| `getPreferredLocale()` | `() => string \| null` | O primeiro valor **válido** entre o estado e o cookie de preferência, ou `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | O estado com hash routing, quando definido; caso contrário, `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, depois um estado válido, depois `options.serverLocale` e depois o locale da rota. Guarda o resultado no estado quando este não é válido; no cliente, escreve também o cookie. |
| `isValidLocale(locale)` | `(locale) => locale is string` | Indica se `locale` está em `validLocales`. |

Os cookies duram um ano, com `path: '/'` e `sameSite: 'lax'`.

## Exemplo {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

O plugin de carregamento do módulo lê o estado quando arranca, por isso um plugin que o define tem de correr primeiro (`enforce: 'pre'`). Como o estado concorre com o URL, o cookie e o `Accept-Language`: [Deteção de locale](/pt/guide/locale-detection). Guia completo: [Deteção personalizada](/pt/guide/custom-auto-detect).

`setLocale()` não muda as traduções no ecrã. Para mudar o locale da página atual, chame [`$switchLocale()`](/pt/api/methods#$switchlocale).
