`@i18n-micro/vitepress` adiciona dicionários em runtime a um site VitePress: `$t` e `<I18nT>` dentro do markdown, helpers de caminhos e tags de SEO, construído sobre [`@i18n-micro/vue`](/pt/integrations/vue-package). Utilize-o quando as mesmas strings da interface aparecem em muitas páginas e não quer duplicá-las por locale. O locale segue os locales de caminho do próprio VitePress (`/`, `/fr/`).

## Quando o utilizar {#when-to-use-it}

| Necessidade | Solução |
|------|----------|
| `.md` duplicados, prefixos de URL | `locales` do VitePress |
| `$t` em runtime / componentes / sincronização de caminhos / head de SEO | `@i18n-micro/vitepress` |
| Etiquetas da interface do tema por omissão (`docFooter`, UI de pesquisa) | O seu próprio `themeConfig` por locale |

<Tip>

**Playground** — [`packages/vitepress/playground`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/vitepress/playground) — `pnpm -C packages/vitepress/playground dev`

</Tip>

## Instalação {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vitepress
```

```bash npm
npm install @i18n-micro/vitepress
```

```bash yarn
yarn add @i18n-micro/vitepress
```

</CodeGroup>

Dependências peer: `vitepress` `>=1.0.0 || >=2.0.0-alpha.0`, `vue` `^3.3.0`. Os scripts Node utilizam `@i18n-micro/node`, instalado com o pacote e reexportado através de `/node`. Os tipos publicados precisam do Vue 3.5.5 ou posterior com `skipLibCheck: false`; com `skipLibCheck: true`, a definição habitual dos templates, as versões mais antigas também compilam.

## Configuração {#setup}

```
locales/en.json
locales/fr.json
locales/pages/guide/demo/en.json   # optional page-scoped
locales/pages/guide/demo/fr.json
```

Os ficheiros de página correspondem a nomes de rota da mesma forma que no Nuxt/Astro (`guide/demo` → `guide-demo`).

### 1. Configuração — `@i18n-micro/vitepress/config` {#1-config-—-@i18n-micro/vitepress/config}

```ts
// .vitepress/config.mts
import { defineConfig } from 'vitepress'
import { withI18n, buildVitePressLocales } from '@i18n-micro/vitepress/config'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English', og: 'en_US' },
  { code: 'fr', iso: 'fr-FR', displayName: 'Français', og: 'fr_FR' },
]
const defaultLocale = 'en'

export default defineConfig(
  withI18n(
    {
      locales: buildVitePressLocales(locales, defaultLocale),
      // themeConfig.i18nRouting is injected automatically
    },
    {
      locale: defaultLocale,
      defaultLocale,
      locales,
      translationDir: 'locales',
      metaBaseUrl: 'https://example.com', // optional SEO head
    },
  ),
)
```

### 2. Tema — `@i18n-micro/vitepress/theme` {#2-theme-—-@i18n-micro/vitepress/theme}

```ts
// .vitepress/theme/index.ts
import DefaultTheme from 'vitepress/theme'
import { defineI18nTheme } from '@i18n-micro/vitepress/theme'

export default defineI18nTheme(DefaultTheme)
```

O locale inicial é obtido a partir do caminho atual antes da instalação (sem flash do locale por omissão em `/fr/…`).

### Avançado: `createI18n` manual {#advanced-manual-createi18n}

Uma única factory para o cliente: plugin Vue + métodos de caminho + `enhanceApp` (sem exportações separadas de helpers do router).

```ts
import { createI18n, messagesFromGlob } from '@i18n-micro/vitepress'

const i18n = createI18n({
  locale: 'en',
  defaultLocale: 'en',
  locales: [{ code: 'en' }, { code: 'fr' }],
  messages: messagesFromGlob(import.meta.glob('../../locales/*.json', { eager: true })),
})

i18n.localizePath('/guide', 'fr')
// in theme enhanceApp:
i18n.enhanceApp({ app, router })
```

### Scripts Node — `@i18n-micro/vitepress/node` {#node-scripts-—-@i18n-micro/vitepress/node}

Utiliza `createI18n` / `loadTranslations` de `@i18n-micro/node` (tal como o Astro e a CLI) e depois acrescenta os métodos de caminho do VitePress com `BaseI18n.extend`:

```ts
import { createI18n } from '@i18n-micro/vitepress/node'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  translationDir: './locales',
  locales: ['en', 'fr'],
  defaultLocale: 'en',
})
await i18n.loadTranslations()
i18n.t('cta.readMore')
i18n.localizePath('/guide', 'fr')
```

Node simples sem caminhos: `import { createI18n } from '@i18n-micro/node'`.

## Traduções na página {#in-page-translations}

Cada ficheiro markdown do VitePress é um SFC Vue.

### Componentes globais e `$t` (recomendado em markdown) {#global-components-and-$t-recommended-in-markdown}

`createI18n` / `defineI18nTheme` instalam `@i18n-micro/vue`, que regista `I18nT` / `I18nLink` / `I18nGroup` / `I18nSwitcher` e `$t` / `$tc` / `$ts`.

```md
{{ $t('cta.readMore') }}

<I18nT keypath="greeting" :params="{ name: 'VitePress' }" />

<I18nLink to="/guide/demo">Demo</I18nLink>
```

### `useI18n` em `<script setup>` {#usei18n-in-<script-setup>}

```md
<script setup>
import { useI18n } from '@i18n-micro/vitepress'
const { t, tc, locale, localePath, switchLocale } = useI18n()
</script>

# {{ t('section.title') }}
```

## Menu de idiomas {#language-dropdown}

Quando `locales` tem mais do que uma entrada, o VitePress mostra o seu próprio menu de idiomas (`VPNavBarTranslations`). `withI18n` configura `themeConfig.i18nRouting` para que o globo corresponda a `<I18nSwitcher>` / helpers de caminhos.

Utilize `<I18nSwitcher>` apenas em layouts personalizados, não ao lado do globo por omissão.

## Notas sobre SSR {#ssr-notes}

- O locale na pré-renderização vem do caminho do URL, não dos cookies.
- O código do tema não pode aceder a `window` no momento da importação.
- Importe `defineI18nTheme` de `/theme` para que a avaliação da configuração em Node nunca carregue `virtual:i18n-micro/*`.

## Superfície da API {#api-surface}

| Exportação | Função |
|--------|------|
| `createI18n` (`.`) | Cliente: plugin Vue + métodos de caminho + `enhanceApp` |
| `getLocaleFromPath` / `stripSiteBase` / `routeNameFromPath` (`.`) | Sincronização manual do locale quando `syncWithVitePress: false` |
| `createI18n` (`/node`) | Node: `@i18n-micro/node` + métodos de caminho |
| `defineI18nTheme` (`/theme`) | Tema sem boilerplate |
| `withI18n` (`/config`) | Configuração + módulos virtuais + SEO opcional |
| `buildVitePressLocales` (`/config`) | Constrói os `locales` do VitePress a partir de `Locale[]` |
| `buildVitePressLocaleHead` (`/config`) | Head de SEO manual (também utilizado por `metaBaseUrl`) |
| `messagesFromGlob` | Mapa opcional glob → mensagens para `createI18n` |
| `useI18n` / `I18nT` / … | Reexportados de `@i18n-micro/vue` |
| `BaseI18n.extend` (`@i18n-micro/core`) | Acrescenta métodos personalizados a qualquer instância i18n |

## Sites ao estilo OpenAPI (garantias de integração) {#openapi-style-sites-integration-locks}

Conjunto de testes de regressão: `packages/vitepress/tests/integration-openapi.test.ts` (caminhos profundos, `base=/openapi_docs/`, sincronização desativada + locale manual, geradores Node, SEO).

| Padrão | Faça isto |
|---------|---------|
| Páginas profundas `/…/{spec}/{op}`, apenas JSON da UI raiz | Prefira o valor por omissão `syncWithVitePress: true` (mantém `setRoute('index')` quando não há dicionário de página) **ou** `syncWithVitePress: false` + `getLocaleFromPath` |
| Nunca chame `setRoute(deepName)` sem dicionários de página | As chaves da UI raiz desaparecem até `setRoute('index')` |
| Geradores / `getTranslation` | `createI18n` de `/node` + `await loadTranslations()` + `i18n.t(key)` (defina `i18n.locale`) |
| Canonical personalizado em `transformPageData` | Passe `meta: false` a `withI18n` (evita tags duplicadas) |
| SEO do pacote com base do site | `metaBaseUrl` + `base` do VitePress → os URLs absolutos incluem a base |
| Renomeações face a builds mais antigos do pacote | `withI18nMicro` → `withI18n`, `createVitePressI18n` → `createI18n`, `loadMessages` → `createI18n` do node |
