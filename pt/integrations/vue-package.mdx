`@i18n-micro/vue` é um plugin Vue 3 com o núcleo de tradução do Nuxt I18n Micro: `t()` reativo, `$t` global, quatro componentes e um adapter opcional para vue-router. Use-o numa aplicação Vue com Vite ou SSR que não seja construída com Nuxt. O modelo de instância, o contrato do router e as props dos componentes são partilhados com os outros pacotes e descritos em [Frameworks](/pt/integrations/overview).

## Instalação {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vue
```

```bash npm
npm install @i18n-micro/vue
```

```bash yarn
yarn add @i18n-micro/vue
```

</CodeGroup>

Peer dependencies: `vue` `^3.3.0`; `vue-router` `^4.5.1 || ^5.0.0` (opcional, apenas para `@i18n-micro/vue/router`). Os tipos publicados precisam do Vue 3.5.5 ou posterior com `skipLibCheck: false`; com `skipLibCheck: true`, a definição habitual dos templates, as versões mais antigas também compilam.

## Configuração {#setup}

```ts
// src/main.ts
import { createApp } from 'vue'
import { createI18n } from '@i18n-micro/vue'
import App from './App.vue'
import en from './locales/en.json'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales: [
    { code: 'en', iso: 'en-US', displayName: 'English' },
    { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
  ],
  defaultLocale: 'en',
})

createApp(App).use(i18n).mount('#app')
```

`locales` e `defaultLocale` são obrigatórios para `useI18n()`: sem eles, lança `I18nLocalesKey not provided`. Passe-os a `createI18n` (como acima), a `useI18n({ locales, defaultLocale })`, ou através de `app.provide(I18nLocalesKey, …)` e `app.provide(I18nDefaultLocaleKey, …)`.

O plugin regista `I18nT`, `I18nLink`, `I18nGroup` e `I18nSwitcher` globalmente e adiciona `$t`, `$ts`, `$tc`, `$tn`, `$td`, `$tdr`, `$has` e `$i18n` aos templates. Fora dos componentes, a instância é `i18n.global`. As restantes opções estão em [a instância](/pt/integrations/overview#the-instance); `routeMessages` não está disponível em Vue, use `addRouteTranslations`.

## Traduzir {#translate}

```vue
<script setup lang="ts">
import { useI18n } from '@i18n-micro/vue'

const { t, tc, tn } = useI18n()
</script>

<template>
  <h1>{{ t('greeting', { name: 'Ada' }) }}</h1>
  <!-- Hello, Ada! -->
  <p>{{ tc('apples', 3) }}</p>
  <!-- 3 apples -->
  <p>{{ $t('nav.home') }} · {{ tn(1234.5) }}</p>
</template>
```

`useI18n()` devolve os métodos de tradução (`t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`), `locale` (um computed com escrita), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `localePath`, `localeRoute`, `switchLocale`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `mergeTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` e `instance`.

Carregue mais dicionários a qualquer momento; todos os componentes que os leem voltam a renderizar:

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Mudar de locale {#switch-locale}

```ts
const { locale, switchLocale } = useI18n()

locale.value = 'de' // only the locale
switchLocale('de') // the locale, then router.push to the localized current path
```

Carregue o dicionário do locale antes ou depois da mudança; mudar de locale não vai buscar nada.

`<I18nGroup>` dá ao seu slot um `t` com prefixo. As chaves dentro de `<I18nT>` ou de um `t()` simples não levam prefixo:

```vue
<I18nGroup prefix="profile" v-slot="{ t }">
  <h2>{{ t('title') }}</h2>
  <!-- profile.title -->
</I18nGroup>
```

## Roteamento {#routing}

O adapter para vue-router está num subcaminho, para que o ponto de entrada principal nunca importe `vue-router`:

```ts
// src/main.ts
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import { createI18n } from '@i18n-micro/vue'
import { createVueRouterAdapter } from '@i18n-micro/vue/router'
import App from './App.vue'
import Home from './pages/Home.vue'
import About from './pages/About.vue'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/:locale(de)?', component: Home },
    { path: '/:locale(de)?/about', component: About },
  ],
})

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales,
  defaultLocale: 'en',
  routingStrategy: createVueRouterAdapter(router, locales, 'en'),
})

createApp(App).use(router).use(i18n).mount('#app')
```

`createVueRouterAdapter(router, locales, defaultLocale)` adiciona prefixo a todos os locales exceto o predefinido (`/about`, `/de/about`) e renderiza `<I18nLink>` como `RouterLink`. Leia o locale da rota por si próprio, por exemplo em `router.beforeEach`, e defina `i18n.global.locale.value`. Também pode associar um adapter mais tarde com `i18n.setRoutingStrategy(adapter)`; para um adapter personalizado, consulte [Adapter de router](/pt/integrations/overview#router-adapter).

## SSR {#ssr}

- Crie o router, a instância i18n e a aplicação dentro da função de renderização por pedido. Uma única instância partilhada faria passar o locale de um visitante para outro.
- Use `createMemoryHistory()` no servidor, obtenha o locale a partir do URL e carregue o seu dicionário (e o do fallback) antes de `renderToString`.
- Envie o locale para o cliente (por exemplo, num script `window.__STATE__`) e crie a instância do cliente com o mesmo `locale` para que a hidratação coincida.
- `<I18nSwitcher>` só lê `window.location` quando o menu suspenso está aberto, por isso renderiza no servidor.

`packages/vue/playground` tem um par completo `entry-server.ts` / `entry-client.ts`.

## Head de SEO {#seo-head}

`useLocaleHead(options)` constrói as tags `lang`/`dir`, canonical, `hreflang` e `og:locale` a partir dos locales e do adapter de router. Chame `updateMeta()` quando a rota muda e passe `metaObject` ao seu gestor de head:

```ts
import { watch } from 'vue'
import { useRoute } from 'vue-router'
import { useHead } from '@unhead/vue'
import { useLocaleHead } from '@i18n-micro/vue'

const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
watch(() => route.fullPath, () => updateMeta(), { immediate: true })
useHead(metaObject)
```

Opções: `baseUrl` (string ou função), `addDirAttribute` (predefinição `true`), `addSeoAttributes` (predefinição `true`), `identifierAttribute` (predefinição `'id'`), `hreflangBaseLanguage` (predefinição `false`). Os locales com `disabled: true` ou `seo: false` não recebem link alternativo.

| --- | --- |

| `I18nT`, `I18nLink`, `I18nSwitcher`, `I18nGroup` | `@i18n-micro/vue` |
