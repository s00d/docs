# 🔧 Gerador de tipos (`@i18n-micro/types-generator`)

O pacote `@i18n-micro/types-generator` fornece geração automática de tipos TypeScript para chaves de tradução. Analisa os seus ficheiros JSON de tradução e gera tipos rigorosos, permitindo tipagem segura total e suporte a autocompletar para chaves de tradução.

## 📖 Visão geral

`@i18n-micro/types-generator` é uma dependência de dev opcional que melhora a sua experiência de desenvolvimento ao:

- 🔍 **Geração automática de tipos** — analisa ficheiros JSON de tradução e gera tipos TypeScript
- ✅ **Segurança de tipos** — evita erros de escrita e chaves de tradução inválidas em tempo de compilação
- 🎯 **Suporte a autocompletar** — autocompletar completo no IDE para chaves de tradução
- 🔄 **Hot reload** — regenera tipos automaticamente quando os ficheiros de tradução mudam
- 🚀 **Sem overhead em runtime** — os tipos existem apenas em tempo de compilação, sem impacto no tamanho do bundle

## 🎯 Início rápido

### Para projetos Nuxt

Adicione o módulo ao seu `nuxt.config.ts`:

```typescript
import { defineNuxtConfig } from 'nuxt/config'

export default defineNuxtConfig({
  modules: [
    'nuxt-i18n-micro',
    '@i18n-micro/types-generator/nuxt', // Add types generator
  ],
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    translationDir: 'locales', // Path to your translation files
  },
})
```

O gerador irá automaticamente:

- Analisar todos os ficheiros JSON no seu diretório `locales`
- Gerar tipos em `.nuxt/i18n-micro.d.ts`
- Observar alterações e regenerar tipos automaticamente

### Para projetos Vue/Vite

Adicione o plugin ao seu `vite.config.ts`:

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { I18nTypesPlugin } from '@i18n-micro/types-generator'

export default defineConfig({
  plugins: [
    vue(),
    I18nTypesPlugin({
      srcDir: 'src',
      translationDir: 'locales',
      outputFile: 'src/i18n-types.d.ts', // Optional: custom output path
    }),
  ],
})
```

Certifique-se de que inclui o ficheiro gerado no seu `tsconfig.json`:

```json
{
  "include": ["src/**/*", "src/i18n-types.d.ts"]
}
```

## 📁 Estrutura dos ficheiros de tradução

O gerador suporta estruturas de tradução planas e aninhadas:

```
locales/
  en.json
  fr.json
  pages/
    home/
      en.json
      fr.json
    about/
      en.json
      fr.json
```

**Exemplo `locales/en.json`:**

```json
{
  "greeting": "Hello, {name}!",
  "header": {
    "title": "Welcome",
    "subtitle": "Subtitle"
  },
  "errors": {
    "404": "Not found",
    "500": "Server error"
  },
  "apples": "no apples | one apple | {count} apples"
}
```

O gerador criará tipos para todas as chaves, incluindo as aninhadas:

```typescript
// Generated types
declare module '@i18n-micro/types' {
  export interface DefineLocaleMessage {
    greeting: string
    'header.title': string
    'header.subtitle': string
    'errors.404': string
    'errors.500': string
    apples: string
  }
}
```

## 💡 Utilização

Uma vez gerados os tipos, obtém segurança de tipos completa:

```typescript
import { useI18n } from '@i18n-micro/vue'

const { t } = useI18n()

// ✅ Type-safe: autocomplete works
t('greeting', { name: 'World' })
t('header.title')
t('errors.404')

// ❌ Type error: key doesn't exist
t('invalid.key') // Error: Argument of type '"invalid.key"' is not assignable
```

### Nota específica para Nuxt

**Em projetos Nuxt, a segurança de tipos funciona apenas com o composable `useI18n`.** Os tipos gerados são aplicados ao valor devolvido pelo composable, garantindo segurança de tipos ao usar `t()`, `ts()`, `tc()` e `has()`.

```typescript
// ✅ Correct: Using useI18n composable
<script setup lang="ts">
import { useI18n } from '#imports'

const { t } = useI18n()
t('greeting') // Type-safe with autocomplete
</script>

// ❌ Not type-safe: Direct access to $i18n or other methods
// Type safety is only available through the useI18n composable
```

## 🔄 Chaves dinâmicas

Por vezes precisa de usar chaves dinâmicas (por exemplo, baseadas em entrada do utilizador ou respostas de API). O gerador fornece um tipo auxiliar `ScopedKey` para uso seguro de chaves dinâmicas.

### Porquê não usar type guards em runtime?

**Type guards em runtime não são recomendados** para o i18n-micro porque:

1. **Tamanho do bundle** — gerar um array JavaScript com todas as chaves inflaria o bundle
2. **Desempenho** — verificações em runtime adicionam overhead desnecessário
3. **Filosofia** — o i18n-micro foi concebido para ser leve e rápido

### A abordagem TypeScript: type assertions

Para chaves dinâmicas, use type assertion do TypeScript:

```typescript
import type { TranslationKey, ScopedKey } from '@i18n-micro/types'

// ❌ Type error: dynamic key
const status = 'pending'
t(`status.${status}`) // Error: string is not assignable to TranslationKey

// ✅ Solution 1: Type assertion (if you're sure the key exists)
t(`status.${status}` as TranslationKey)

// ✅ Solution 2: ScopedKey helper (safer, checks prefix exists)
function getStatusText(status: string) {
  return t(`status.${status}` as ScopedKey<'status'>)
  // TypeScript verifies that keys starting with 'status.' exist
}

// ✅ Solution 3: Runtime check with has()
if (has(`status.${status}`)) {
  t(`status.${status}` as TranslationKey)
}
```

### Helper ScopedKey

O tipo `ScopedKey<Scope>` permite estreitar chaves dinâmicas por prefixo:

```typescript
import type { ScopedKey } from '@i18n-micro/types'

// Assuming you have keys: 'errors.404', 'errors.500', 'btn.save'

function getErrorText(code: string) {
  // ✅ Safer than plain TranslationKey
  // TypeScript verifies that 'errors.*' keys exist
  return t(`errors.${code}` as ScopedKey<'errors'>)
}

// ❌ Type error: 'btn' prefix doesn't match 'errors'
function getErrorTextWrong(code: string) {
  return t(`errors.${code}` as ScopedKey<'btn'>) // Error
}
```

## 🎨 Utilização avançada

### Tratamento de traduções específicas de rota

O gerador inclui automaticamente chaves de ficheiros de tradução específicos de rota:

```
locales/
  en.json                    # Root-level translations
  pages/
    home/
      en.json               # Route-specific translations
    about/
      en.json
```

Todas as chaves de ficheiros de nível raiz e específicos de rota são incluídas nos tipos gerados.

### Desativar locales de página

Se usar `disablePageLocales: true` na sua configuração i18n, o gerador tratará todos os ficheiros (incluindo os em `pages/`) como traduções de nível raiz.

## 🐛 Resolução de problemas

### Tipos não atualizam

1. **Verifique caminhos de ficheiros** — garanta que `translationDir` aponta para o diretório correto
2. **Reinicie o servidor TypeScript** — no VS Code: `Cmd/Ctrl + Shift + P` → "TypeScript: Restart TS Server"
3. **Verifique o tsconfig.json** — garanta que o ficheiro gerado está incluído

### Erros de tipo após adicionar chaves

1. **Regenere os tipos** — o gerador deve regenerar automaticamente, mas pode acioná-lo manualmente
2. **Verifique a sintaxe JSON** — ficheiros JSON inválidos são ignorados com um aviso
3. **Reinicie o servidor de dev** — por vezes necessário para as alterações produzirem efeito

### Autocompletar não funciona

1. **Verifique a inclusão do ficheiro** — verifique se o `.d.ts` gerado está no `include` do seu `tsconfig.json`
2. **Verifique a module augmentation** — garanta que o ficheiro gerado usa `declare module '@i18n-micro/types'`
3. **Versão do TypeScript** — requer TypeScript 4.1+ para tipos template literal

## 📚 Referência da API

### `generateTypes(options: GeneratorOptions)`

Gera tipos manualmente (útil para scripts ou CI):

```typescript
import { generateTypes } from '@i18n-micro/types-generator'

await generateTypes({
  srcDir: './src',
  translationDir: 'locales',
  outputFile: './src/i18n-types.d.ts',
})
```

### `flattenKeys(obj: Record<string, unknown>, prefix?: string)`

Função utilitária para achatar objetos de tradução aninhados:

```typescript
import { flattenKeys } from '@i18n-micro/types-generator'

const keys = flattenKeys({
  header: { title: 'Title' },
  footer: { copyright: 'Copyright' },
})
// Returns: ['header.title', 'footer.copyright']
```

## 🔍 Como funciona

1. **Análise** — usa `globby` para encontrar todos os ficheiros `**/*.json` no diretório de traduções
2. **Parsing** — faz parsing de cada ficheiro JSON e extrai todas as chaves recursivamente
3. **Deduplicação** — combina as chaves de todos os ficheiros num conjunto único
4. **Geração** — cria um ficheiro `.d.ts` com module augmentation via `declare module`
5. **Observação** — em modo dev, observa alterações de ficheiros e regenera os tipos

O ficheiro gerado utiliza module augmentation do TypeScript para estender `DefineLocaleMessage` em `@i18n-micro/types`, o que atualiza automaticamente o tipo `TranslationKey` em todo o seu projeto.

## 🎯 Boas práticas

1. **Mantenha as traduções organizadas** — use objetos aninhados para chaves relacionadas
2. **Use nomenclatura consistente** — siga uma convenção (por exemplo, `errors.*`, `buttons.*`)
3. **Aproveite o ScopedKey** — use `ScopedKey` para chaves dinâmicas em vez de type assertions simples
4. **Verifique tipos em CI** — corra a verificação de tipos no seu pipeline de CI
5. **Não edite ficheiros gerados** — o ficheiro `.d.ts` é gerado automaticamente e será sobrescrito
