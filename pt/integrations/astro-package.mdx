---
title: "Astro"
description: "Traduções do lado do servidor, rotas com prefixo de locale, deteção na página inicial e etiquetas de SEO para Astro com @i18n-micro/astro."
---

`@i18n-micro/astro` traduz páginas Astro no servidor: um middleware escolhe o locale a partir do URL e coloca uma instância por pedido em `Astro.locals`, e `useI18n(Astro)` lê-a. Use-o num site Astro que precise de URLs com prefixo de locale (`/about`, `/fr/about`) e de dicionários JSON partilhados. Obtém componentes `.astro`, um redirecionamento da página inicial para o idioma do visitante, etiquetas `hreflang` e props para [ilhas](/pt/integrations/astro-islands).

## Instalar {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/astro
```

```bash npm
npm install @i18n-micro/astro
```

```bash yarn
yarn add @i18n-micro/astro
```

</CodeGroup>

Dependências peer: `astro` `^5.0.0 || ^6.0.0 || ^7.0.0`. Opcionais, apenas para [ilhas](/pt/integrations/astro-islands): `vue` `^3.3.0`, `react` `^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`, `preact` `^10.0.0 || ^11.0.0`, `svelte` `^4.0.0 || ^5.0.0`.

## Configuração {#setup}

Adicione a integração. Ela inclui os seus dicionários no servidor e instala o middleware, pelo que não é necessário `src/middleware.ts`:

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import node from '@astrojs/node'
import { i18nIntegration } from '@i18n-micro/astro'

export default defineConfig({
  output: 'server',
  adapter: node({ mode: 'standalone' }),
  integrations: [
    i18nIntegration({
      locale: 'en',
      fallbackLocale: 'en',
      locales: [
        { code: 'en', iso: 'en-US', displayName: 'English' },
        { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
        { code: 'fr', iso: 'fr-FR', displayName: 'Français' },
      ],
      translationDir: 'src/locales',
    }),
  ],
})
```

Os dicionários tornam-se código no momento do build: o servidor não lê o disco, pelo que também corre na edge (Cloudflare, Vercel Edge). Em `astro dev`, uma edição a um ficheiro aplica-se no pedido seguinte.

### Opções da integração {#integration-options}

| Opção | Por omissão | Notas |
| --- | --- | --- |
| `locale` | obrigatória | Locale por omissão. |
| `fallbackLocale` | `locale` | |
| `locales` | `[]` | Objetos `Locale` completos. Um locale `disabled` não é o locale de nenhum URL nem destino de redirecionamento. `iso` é a etiqueta pela qual se regem os plurais quando o código não o é (`ua` → `uk-UA`). |
| `translationDir` | nenhum | Pasta incluída no servidor, relativa à raiz do projeto. |
| `disablePageLocales` | `false` | Os ficheiros de página contam como traduções raiz. |
| `autoDetect` | `true` | Redirecionamento da página inicial, consulte [Deteção de locale](#locale-detection). |
| `redirectToDefault` | `false` | `/` também redireciona quando nada prefere outro locale. |
| `localeCookie` | `'i18n-locale'` | `null` desativa o cookie. |
| `missingWarn` | `false` | |
| `middleware` | `true` | `false`: escreva o middleware por si, ver abaixo. |

As definições de runtime são publicadas em `virtual:i18n-micro/config` (`config.base` é o `base` do Astro, `config.localeCodes` os códigos ativos) e os dicionários em `virtual:i18n-micro/messages`.

### O seu próprio middleware {#your-own-middleware}

Uma regra de plural, um handler de chaves em falta e um router adapter não podem passar do processo de configuração para o bundle do servidor. Para esses casos, passe `middleware: false` e escreva `src/middleware.ts`. A configuração `i18n` do Astro é então definida por si com `routing: 'manual'`, pelo que `Astro.currentLocale` e `astro:i18n` funcionam. O Astro não permite essa definição sem um `src/middleware.ts`, por isso com o middleware da própria integração não funcionam.

```ts
// src/middleware.ts
import { config } from 'virtual:i18n-micro/config'
import { messages } from 'virtual:i18n-micro/messages'
import { createAstroRouterAdapter, createI18n, createI18nMiddleware, localeIsoMap } from '@i18n-micro/astro'

const i18n = createI18n({
  locale: config.defaultLocale,
  fallbackLocale: config.fallbackLocale,
  localeIso: localeIsoMap(config.locales),
  messages: messages.root,
  routeMessages: messages.routes,
  plural: myPluralRule,
})

export const onRequest = createI18nMiddleware({
  i18n,
  defaultLocale: config.defaultLocale,
  locales: config.localeCodes,
  localeObjects: config.locales,
  autoDetect: config.autoDetect,
  redirectToDefault: config.redirectToDefault,
  localeCookie: config.localeCookie,
  base: config.base,
  routingStrategy: createAstroRouterAdapter(config.locales, config.defaultLocale),
})
```

Para, em vez disso, ler a pasta em runtime, `loadTranslationsFromDir` e `loadTranslationsIntoI18n` estão em `@i18n-micro/astro/node` (apenas Node).

### Opções do middleware {#middleware-options}

| Opção | Por omissão | Notas |
| --- | --- | --- |
| `i18n` | obrigatória | Instância global; cada pedido recebe `i18n.fork(locale)`, que custa o mesmo independentemente do número de dicionários. |
| `defaultLocale` | obrigatória | |
| `locales` | obrigatória | Códigos de locale. |
| `localeObjects` | `locales` como `{ code }` | Objetos `Locale` completos para componentes e SEO. |
| `autoDetect` | `true` | Redirecionamento da página inicial, consulte [Deteção de locale](#locale-detection). |
| `redirectToDefault` | `false` | `/` também redireciona quando nada prefere outro locale, para a página inicial do locale por omissão tal como a estratégia de encaminhamento a resolve. |
| `localeCookie` | `'i18n-locale'` | `null` desativa o cookie. |
| `routingStrategy` | prefixo exceto por omissão | Router adapter. Os métodos que omite vêm do adapter por omissão. |
| `base` | nenhum | O `base` do Astro: `config.base`. |

Os ficheiros de página (`src/locales/pages/blog/post/de.json`) correspondem à rota `blog-post`: o caminho da página unido com `-`.

## Traduzir {#translate}

```astro
---
// src/pages/index.astro
import { useI18n } from '@i18n-micro/astro'
import I18nT from '@i18n-micro/astro/i18n-t'

const { t, tc, locale } = useI18n(Astro)
---

<h1>{t('greeting', { name: 'Ada' })}</h1>
<p>{tc('apples', 3)}</p>
<I18nT keypath="welcome" tag="p" />
<p>{locale}</p>
```

`useI18n(Astro)` devolve `locale`, `defaultLocale`, `locales`, `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `getRoute`, `getRouteName(path?)`, `getLocaleFromPath(path?)`, `switchLocalePath(locale)`, `localizePath(path, locale?)`, `getBasePath(url?)`, `getI18n`, `addTranslations`, `addRouteTranslations`, `mergeTranslations` e `clearCache`. Lança um erro quando o middleware não correu. Os helpers `getI18n`, `getLocale`, `getDefaultLocale` e `getLocales` leem o mesmo `Astro.locals`.

O nome da rota vem da rota sem o seu locale: `/fr/blog/post` → `blog-post`, e todos os URLs de `src/pages/blog/[slug].astro` → `blog-slug`, pelo que uma única pasta `locales/pages/blog-slug/` serve todos. `[...path]` é `path`. Com o `base` do Astro, os helpers recebem e devolvem URLs do site: `switchLocalePath` e `localizePath` incluem-no, `getBasePath` não, porque `Astro.rewrite` recebe o caminho sem ele.

### Componentes {#components}

Importe-os de `@i18n-micro/astro/<name>` (ou `@i18n-micro/astro/components/<name>.astro`):

| Componente | Props |
| --- | --- |
| `i18n-t` | `keypath`, `params`, `plural`, `number`, `date`, `relativeDate`, `tag` (`span`, qualquer etiqueta), `html`, `hideIfEmpty`, `defaultValue`; os restantes atributos são passados. Com `html`, o resultado de cada ramo é apresentado como HTML e os `params` são escapados. Não há slots |
| `i18n-link` | `href`, `locale` (locale de destino, por omissão o atual), `class`; os restantes atributos são passados. URLs externos, `#hash` e `?query` ficam tal como escritos; uma rota mantém a sua query, hash e barra final |
| `i18n-switcher` | `class`, `activeClass` (`'active'`), `customLabels`; apresenta links para a página atual em cada locale ativo, com a sua query |
| `i18n-group` | nenhuma que altere o resultado: um `<div>` à volta do seu slot, sem prefixo |

## Rotas com prefixo de locale {#locale-prefixed-routes}

Mantenha uma página por rota em `src/pages/` e adicione pequenos stubs de rewrite em `src/pages/[locale]/`:

```
src/pages/
  index.astro
  about.astro
  [locale]/
    index.astro
    about.astro
```

```astro
---
// src/pages/[locale]/about.astro
import { prepareLocaleRewrite } from '@i18n-micro/astro'

const target = prepareLocaleRewrite(Astro)
if (target instanceof Response) return target
return Astro.rewrite(target)
---
```

`prepareLocaleRewrite` devolve uma resposta `404` para um `:locale` desconhecido; caso contrário, define o locale em `Astro.locals` e devolve o caminho sem o prefixo. O middleware mantém um locale que já esteja em `locals`, pelo que a página reescrita é apresentada nesse locale. `getLocaleRewritePath(Astro)` devolve apenas o caminho, para quando valida o locale por si.

## Deteção de locale {#locale-detection}

O URL decide o locale da página:

1. Um prefixo de locale (`/fr/about` → `fr`; `/en/about` também é `en`).
2. Caso contrário, o que o `getLocaleFromPath` do router adapter devolver, se não for o locale por omissão.
3. Caso contrário, o locale por omissão. `/about` é sempre a página do locale por omissão, diga o cookie o que disser.

`autoDetect` é uma indicação de redirecionamento apenas na página inicial:

- Um pedido para `/` cujo cookie ou `Accept-Language` prefira outro locale recebe um `302` para a página inicial desse locale (`/de`). Os pesos q são respeitados; `de-DE` corresponde a um locale `de`, e `de` corresponde a um `de-DE`.
- Com `redirectToDefault`, `/` redireciona sempre: para a página inicial do locale preferido ou, caso contrário, para a do locale por omissão.
- A resposta de `/` inclui `Vary: Cookie, Accept-Language` (apenas `Accept-Language` quando `localeCookie` é `null`).
- As páginas pré-renderizadas nunca redirecionam.

`detectLocale(pathname, cookies, headers, defaultLocale, locales, localeCookie?, routingStrategy?, autoDetect?)` devolve o mesmo locale preferido para a sua própria lógica.

O cookie memoriza uma escolha. Uma visualização de página que vem de uma página da mesma origem noutro locale é um visitante a mudar de idioma, seja qual for o link que o levou até lá: a resposta HTML define o cookie com o novo locale e `/` não redireciona, pelo que um seletor chega à página inicial do locale por omissão. Um endpoint, uma imagem, um 404, um envio de formulário e um prefetch não alteram nada. "Mesma origem" é o que o navegador indica em `Sec-Fetch-Site`; sem esse cabeçalho, o host do `Referer` é comparado com o do pedido, por isso atrás de um proxy defina `security.allowedDomains` do Astro.

Uma [server island](https://docs.astro.build/en/guides/server-islands/) ou uma action não tem locale no seu URL. É apresentada para a página que a pediu, lida a partir do `Referer`, do qual só o caminho conta, pelo que um proxy à frente do servidor não altera nada, e nunca redireciona. A sua resposta inclui `Vary: Referer`. Sem `Referer` (uma política `no-referrer`) fica no locale por omissão e, numa página dinâmica, a sua rota vem do URL, pelo que os dicionários de página não chegam até ela.

## Router adapter {#router-adapter}

`createAstroRouterAdapter(locales, defaultLocale)` prefixa todos os locales exceto o por omissão. Um adapter Astro só precisa de `getCurrentPath`; os restantes membros são opcionais e recorrem ao adapter por omissão: `getRouteName(path, locales, routePattern?)`, `getLocaleFromPath`, `switchLocalePath`, `localizePath`, `removeLocaleFromPath`, `resolvePath` (destino do redirecionamento da página inicial), `push`, `replace`, `getRoute`. Escreva o seu próprio para URLs com subdomínio ou sufixo e passe-o a `createI18nMiddleware`.

## SEO {#seo}

```astro
---
// src/layouts/Layout.astro
import { useLocaleHead } from '@i18n-micro/astro'

const head = useLocaleHead(Astro, { baseUrl: 'https://example.com' })
---

<html lang={head.htmlAttrs.lang} dir={head.htmlAttrs.dir}>
  <head>
    {head.link.map((l) => <link rel={l.rel} href={l.href} hreflang={l.hreflang} />)}
    {head.meta.map((m) => <meta property={m.property} content={m.content} />)}
  </head>
  <body><slot /></body>
</html>
```

Devolve `htmlAttrs` (`lang` a partir de `iso`, `dir`), um link canonical (caminho sem query), alternativas `hreflang` para cada locale ativo com `seo !== false` mais `x-default`, `og:locale`, `og:locale:alternate` e `og:url`. Opções: `baseUrl` (`site` da configuração do Astro ou, caso contrário, URLs relativos à raiz), `addDirAttribute` (`true`), `addSeoAttributes` (`true`), `hreflangBaseLanguage` (`false`).
