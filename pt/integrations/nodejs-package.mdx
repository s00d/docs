`@i18n-micro/node` é a instância do [runtime](/pt/integrations/runtime-package) mais um loader que lê uma pasta de traduções a partir do disco. Utilize-o num servidor Express ou Fastify, numa CLI, num gerador de emails ou PDFs, ou em qualquer script que precise dos mesmos ficheiros JSON da sua aplicação Nuxt. Carrega os ficheiros uma vez e traduz por pedido sem partilhar estado mutável entre pedidos.

## Instalação {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/node @i18n-micro/utils
```

```bash npm
npm install @i18n-micro/node @i18n-micro/utils
```

```bash yarn
yarn add @i18n-micro/node @i18n-micro/utils
```

</CodeGroup>

Sem dependências peer; Node.js `>=20`. `@i18n-micro/utils` só é necessário para o helper de `Accept-Language` abaixo.

## Configuração {#setup}

O loader lê a [estrutura de pastas do Nuxt](/pt/guide/translations): `locales/en.json` é um dicionário raiz, `locales/pages/blog/post/en.json` pertence à rota `blog-post`.

```ts
import { createI18n } from '@i18n-micro/node'

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

i18n.t('greeting', { name: 'Ada' }) // 'Hello, Ada!'
i18n.t('title', undefined, undefined, 'blog-post') // from locales/pages/blog/post/en.json
```

As opções são as do runtime (consulte [a instância](/pt/integrations/overview#the-instance)) mais `translationDir` e `disablePageLocales` (trata os ficheiros `pages/**` como dicionários raiz). `i18n.reload()` limpa todos os dicionários e volta a ler a pasta, para um file watcher em desenvolvimento.

`loadTranslations(dir, disablePageLocales?)` também é exportado isoladamente e devolve `{ root, routes }`:

```ts
import { loadTranslations } from '@i18n-micro/node'

const { root, routes } = await loadTranslations('./locales')
// root:   { en: {...}, de: {...} }
// routes: { 'blog-post': { en: {...}, de: {...} } }
```

## Por pedido {#per-request}

Uma instância contém um locale e uma rota. Alterar `i18n.locale` numa instância partilhada dentro de um handler de pedido entra em concorrência com pedidos simultâneos. `run` dá a cada pedido a sua própria:

```ts
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

// `() => next()`: `run` hands its callback the fork, and Express reads an argument of `next` as an error
app.use((req, res, next) => i18n.run(pickLocale(req), () => next()))

app.get('/', (req, res) => {
  res.send(i18n.t('greeting')) // the request's locale, in everything it awaits
})
```

Dentro de `run`, a instância partilhada lê e define o locale e a rota do pedido (`AsyncLocalStorage`); o fork começa na rota atual, e `i18n.setRoute(...)` dentro do callback altera a rota desse pedido. O callback também recebe o fork do pedido: os dicionários escritos nele ficam no pedido, os dicionários escritos na instância partilhada chegam a todos.

Sem `AsyncLocalStorage`, `i18n.fork(locale)` devolve o mesmo tipo de instância para passar de um lado para o outro.

`reload()` volta a ler o diretório; os dicionários antigos respondem até os novos estarem carregados.

## Escolher o locale {#pick-the-locale}

`detectLocaleFromAcceptLanguage(header, locales)` respeita os pesos `q` e faz corresponder `de-DE` a um locale `de` (e `de` a `de-DE`). Devolve `null` quando nada corresponde.

```ts
import express from 'express'
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

const app = express()

app.get('/hello', (req, res) => {
  const locale = detectLocaleFromAcceptLanguage(req.headers['accept-language'], locales) ?? 'en'
  const i18n = byLocale.get(locale)!
  res.json({ message: i18n.t('greeting', { name: 'Ada' }) })
})
```

Para prefixo de URL, cookie e cabeçalho em conjunto, `resolveLocale({ defaultLocale, validLocales, url, cookie, acceptLanguage, autoDetectLanguage: true })` de `@i18n-micro/utils/resolve-locale` aplica a precedência do módulo: URL, depois cookie, depois `Accept-Language`, depois o predefinido. Os valores inválidos são ignorados.

Dentro de uma aplicação Nuxt não precisa deste pacote no servidor: utilize as [traduções do lado do servidor](/pt/guide/server-side-translations) do módulo.

## API {#api}

| Export | Notas |
| --- | --- |
| `createI18n(options)`, `I18n` | instância do runtime + `translationDir`, `loadTranslations(dir?)`, `reload()` |
| `loadTranslations(dir, disablePageLocales?)` | `{ root, routes }` |
| `loadRootTranslations(dir, disablePageLocales?)` | apenas `root` |
| `FormatService`, `interpolate` | do core |
| Tipos: `I18nOptions`, `LoadedTranslations`, `Translations`, `Locale`, `PluralFunc`, `Params` | |

Os métodos da instância estão listados em [Runtime](/pt/integrations/runtime-package#api). Assinaturas completas: [referência do pacote](/pt/api/packages/node).
