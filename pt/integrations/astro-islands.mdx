title: "Ilhas Astro"
description: "Traduções dentro de ilhas Vue, React, Preact e Svelte com @i18n-micro/astro."
---

Uma ilha é executada no browser, onde a instância i18n do servidor não existe. `@i18n-micro/astro` permite que a página escolha as chaves de que uma ilha precisa, as passe como uma única prop e as leia na ilha através de um pequeno adaptador da framework. Obtém `t`, `tc`, `tn`, `td`, `tdr` e `has` em ilhas Vue, React, Preact e Svelte, com apenas as strings escolhidas no HTML.

## Configuração {#setup}

Configure primeiro a [integração e o middleware do Astro](/pt/integrations/astro-package#setup) e depois adicione a integração da framework que utiliza (`@astrojs/vue`, `@astrojs/react`, `@astrojs/preact`, `@astrojs/svelte`). Os adaptadores das ilhas precisam dessa framework como peer: `vue` `^3.3.0`, `react` `^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`, `preact` `^10.0.0 || ^11.0.0` ou `svelte` `^4.0.0 || ^5.0.0`.

## Passar traduções a uma ilha {#pass-translations-to-an-island}

```astro
---
// src/pages/index.astro
import { getI18nProps } from '@i18n-micro/astro'
import Counter from '../components/Counter.vue'

const i18n = getI18nProps(Astro, ['counter.title', 'counter.apples'])
---

<Counter client:load i18n={i18n} />
```

`getI18nProps(Astro, keys?)` devolve `{ locale, fallbackLocale, currentRoute, translations }` (tipo `I18nClientProps`). Passe as chaves que a ilha utiliza: cada uma é resolvida no servidor como `t()` (dicionários da rota, raiz e de fallback) e apenas as chaves encontradas vão para o HTML. Sem `keys`, é enviado tudo o que `t()` consegue responder nesta página, em todas as ilhas, pelo que 2000 chaves raiz correspondem a cerca de 100 KB por ilha; em desenvolvimento, um aviso alerta para isso acima de 20 KB.

As ilhas traduzem apenas a partir desse objeto. `t` devolve a chave para tudo o que não foi passado, e as mensagens ligadas não são resolvidas.

## Vue {#vue}

Chame `provideI18n(() => props.i18n)` no componente raiz da ilha e `useAstroI18n()` nos seus filhos. O `inject` do Vue não vê um valor fornecido pelo mesmo componente, pelo que o hook tem de ser executado num filho, não na raiz:

```vue
<!-- src/components/Counter.vue -->
<script setup lang="ts">
import { provideI18n } from '@i18n-micro/astro/client/vue'
import type { I18nClientProps } from '@i18n-micro/astro'
import CounterBody from './CounterBody.vue'

const props = defineProps<{ i18n: I18nClientProps }>()
provideI18n(() => props.i18n)
</script>

<template><CounterBody /></template>
```

```vue
<!-- src/components/CounterBody.vue -->
<script setup lang="ts">
import { ref } from 'vue'
import { useAstroI18n } from '@i18n-micro/astro/client/vue'

const { t, tc } = useAstroI18n()
const count = ref(0)
</script>

<template>
  <h3>{{ t('counter.title') }}</h3>
  <button @click="count++">{{ tc('counter.apples', count) }}</button>
</template>
```

## React e Preact {#react-and-preact}

```tsx
// src/components/Counter.tsx
import { useState } from 'react'
import { I18nProvider, useAstroI18n } from '@i18n-micro/astro/client/react'
import type { I18nClientProps } from '@i18n-micro/astro'

function Body() {
  const { t, tc } = useAstroI18n()
  const [count, setCount] = useState(0)
  return <button onClick={() => setCount(count + 1)}>{t('counter.title')}: {tc('counter.apples', count)}</button>
}

export default function Counter({ i18n }: { i18n: I18nClientProps }) {
  return (
    <I18nProvider value={i18n}>
      <Body />
    </I18nProvider>
  )
}
```

Para Preact, importe `I18nProvider` e `useAstroI18n` de `@i18n-micro/astro/client/preact`; a API é a mesma.

## Svelte {#svelte}

```svelte
<!-- src/components/Counter.svelte -->
<script lang="ts">
  import { createI18nStore, useAstroI18n } from '@i18n-micro/astro/client/svelte'
  import type { I18nClientProps } from '@i18n-micro/astro'

  export let i18n: I18nClientProps
  const { t, tc } = useAstroI18n(createI18nStore(i18n))
  let count = 0
</script>

<button on:click={() => count++}>{t('counter.title')}: {tc('counter.apples', count)}</button>
```

`useAstroI18n(store)` também devolve a `store` para leituras com `$store` no template.

## Ilhas persistentes {#persisted-islands}

Uma ilha com `transition:persist` recebe novas props após uma navegação. React, Preact e Vue (com um getter) acompanham-nas. Em Svelte, mantenha a store e passe-lhas: `const store = createI18nStore(i18n)`, `const { t } = useAstroI18n(store)` e depois `$: store.set(i18n)` (com runes, `$effect(() => store.set(i18n))`).

## API {#api}

| Entrada | Exportações |
| --- | --- |
| `@i18n-micro/astro` | `getI18nProps`, tipo `I18nClientProps` |
| `@i18n-micro/astro/client/vue` | `provideI18n(props \| () => props)`, `useAstroI18n()` |
| `@i18n-micro/astro/client/react` | `I18nProvider` (prop `value`), `useAstroI18n()` |
| `@i18n-micro/astro/client/preact` | `I18nProvider` (prop `value`), `useAstroI18n()` |
| `@i18n-micro/astro/client/svelte` | `createI18nStore(props)`, `useAstroI18n(store)` |
| `@i18n-micro/astro/client` | as funções puras `translate` e `hasTranslation`, sem framework |

Cada `useAstroI18n` devolve `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `setLocale`, `setRoute` e o `locale`. Uma ilha tem um único dicionário fundido, pelo que o seu `has` é verdadeiro para qualquer chave que `t` consiga responder, incluindo a partir do locale de fallback; no servidor, `has` olha apenas para o locale ativo.
