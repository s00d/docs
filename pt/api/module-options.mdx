# Referência das opções do módulo

Cada opção que o `nuxt-i18n-micro` aceita, lida em tempo de build a partir da interface `ModuleOptions` em
[`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).
Nada aqui é escrito à mão, pelo que não pode ficar desatualizado face ao código: tipos, predefinições e descrições vêm da própria declaração.

Para saber o que estas opções *significam* em conjunto (que combinações fazem sentido, o que muda quando troca de estratégia, exemplos concretos), leia [Configuração](/guides/configuration). Esta página é a lista exaustiva; a outra é a explicação.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

As opções aninhadas aparecem sob o respetivo caminho com ponto, pelo que `translationPayloads.mode` é a chave `mode` dentro do objeto `translationPayloads`.

## Locales e encaminhamento

Que idiomas existem e como aparecem no URL.

| Opção | Tipo | Predefinição | Descrição |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Lista de locales suportados. Cada entrada define um código de locale e metadados opcionais (ISO, direção, nome de apresentação, etc.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Estratégia de encaminhamento de URL para prefixos de locale. - `'no_prefix'` — sem locale no URL; locale armazenado em cookie. - `'prefix_except_default'` — prefixar todos os locales exceto o predefinido. - `'prefix'` — prefixar sempre, incluindo o locale predefinido. - `'prefix_and_default'` — como `prefix`, mas o locale predefinido também é acessível sem prefixo. |
| `defaultLocale` | `string` | `'en'` | O locale a usar quando não é possível determinar um locale a partir do URL ou das preferências do utilizador. Também é usado como locale de fallback para traduções em falta quando `fallbackLocale` não está definido. |
| `localeCookie` | `string \| null` | `null` | Nome do cookie que persiste a preferência de locale do utilizador entre sessões. Defina como `null` para desativar a persistência por cookie. Definido automaticamente como `'user-locale'` para a estratégia `no_prefix` se não for fornecido. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Configuração de locale ao nível da rota global. Permite restringir ou personalizar rotas de locale para páginas específicas sem alterar os seus componentes. - `false` — exclui a rota da localização. - `Record<LocaleCode, string>` — caminhos personalizados por locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Expressão regular personalizada (ou a sua origem em string) para fazer correspondência de códigos de locale em segmentos de URL. Todos os códigos de locale definidos em `locales` devem corresponder a este padrão; caso contrário, é emitido um aviso. |
| `noPrefixRedirect` | `boolean` | `false` | Para a estratégia `no_prefix`: ativa o redirecionamento de um URL com prefixo de locale (por exemplo, `/en/about`) para a versão sem prefixo (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Padrões de URL (strings ou RegExp) a excluir totalmente do processamento i18n. Rotas correspondentes não recebem prefixos de locale, redirecionamentos, nem carregamento de traduções. Caminhos internos do Nuxt (`/__nuxt_error`, etc.) são sempre excluídos automaticamente. |
| `routeLocales` | `Record<string, string[]>` | — | Restrições de locale por rota, extraídas de chamadas a `defineI18nRoute()`. Mapeia um caminho de rota (por exemplo, `'/about'`) para um array de códigos de locale permitidos. Rotas não listadas não têm restrições (todos os locales são permitidos). |

## Traduções

Onde vivem os ficheiros de tradução e como as chaves são resolvidas.

| Opção | Tipo | Predefinição | Descrição |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Caminho para o diretório que contém os ficheiros JSON de tradução, relativo à raiz do projeto. |
| `disableWatcher` | `boolean` | `false` | Desativa o watcher de ficheiros que cria automaticamente ficheiros de tradução em falta em modo de desenvolvimento. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Mapeia nomes de rota para outros nomes de rota para partilhar os mesmos ficheiros de tradução. Por exemplo, `\{ 'about-us': 'about' \}` significa que a página `about-us` usará as traduções da página `about` em vez das suas próprias. |
| `plural` | `PluralFunc` | `built-in pluralization (form index by count)` | Função de pluralização personalizada. Recebe `(key, count, params, locale, getter)` e deve devolver a forma plural selecionada como string, ou `null`/`undefined` para cair na lógica incorporada `defaultPlural` (para poder substituir apenas alguns locales). No módulo Nuxt, a função é serializada com `.toString()` em `.nuxt/i18n.plural.mjs` — deve ser autossuficiente (sem imports/escopo exterior). Uma string de caminho de ficheiro **não** é suportada. |
| `disablePageLocales` | `boolean` | `false` | Desativa os ficheiros de tradução por página. Quando `true`, só as traduções globais (`\{locale\}.json`) são carregadas; os ficheiros específicos de página (`pages/\{page\}/\{locale\}.json`) não são gerados nem carregados. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Código de locale de fallback global. Quando uma chave de tradução está em falta no locale ativo, o módulo procura-a neste locale antes de devolver a própria chave. |

## Payloads e cache

Como as traduções chegam ao navegador. [Desempenho](/guides/performance) explica o que estas opções alteram em runtime.

| Opção | Tipo | Predefinição | Descrição |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Pré-carrega as traduções da página inicial no middleware global do Nitro (apenas servidor, configuração privada). |
| `apiBaseUrl` | `string` | `'_locales'` | Segmento base de caminho de URL para a rota de API das traduções (usado na obtenção de dados em SSR/SSG). Também pode ser definido através da variável de ambiente `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Substitui o host usado nos pedidos de fetch de traduções no cliente. Útil quando o cliente alcança o servidor via um hostname diferente daquele que o Nuxt vê. Também pode ser definido através da variável de ambiente `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Substitui o host usado nos pedidos de fetch de traduções no servidor. Útil em configurações de contentores/microserviços onde o servidor se alcança a si próprio via um hostname interno. Também pode ser definido através da variável de ambiente `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Controla como os payloads de tradução são emitidos (Node: `public/<apiBaseUrl>`; Edge: `serverAssets` do Nitro). - **Node**: `serverAssets` significa SSR local via `readFile` em `public/` (sem `raw:` do Rollup). - **Edge**: `serverAssets` regista `serverAssets` do Nitro (`assets:i18n`); não força uma cópia pública. Mantenha os valores predefinidos para a configuração habitual "tudo-em-um". Para catálogos Edge grandes, prefira `mode: 'source'`. Para implementações apoiadas por CDN, desative as saídas locais e defina `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Estratégia de payload de tradução. - `premerged`: matriz `\{page\}/\{locale\}/data.json` em tempo de build (predefinição) - `source`: ficheiros de origem compactos fundidos em runtime (preferível em Edge/catálogos grandes) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Payloads SSR locais: o Node lê `public/<apiBaseUrl>` (força cópia pública); o Edge incorpora via `serverAssets` do Nitro. - **Node**: sem `serverAssets` do Nitro (evita `raw:` do Rollup). O SSR lê `public/<apiBaseUrl\|publicDir>` como `\{page\}/\{locale\}/data.json`; quando isto é `true`, uma cópia pública é forçada mesmo que `publicAssets` seja false. - **Edge** (`nitro.node === false`): `serverAssets` do Nitro (`assets:i18n`) com o mesmo layout de `mode`. Não força cópia pública — defina `publicAssets: true` para CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Regista a rota de servidor incorporada em `/\{apiBaseUrl\}/:page/:locale/data.json`. Desative isto quando os payloads de tradução forem servidos a partir de um host/CDN externo. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Copia os payloads para a saída pública do Nitro. Premerged → `\{page\}/\{locale\}/data.json` em `apiBaseUrl`; source → árvore compacta. Em Node, esta árvore é também a origem do SSR quando `serverAssets` força uma cópia pública. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Ativa o prerender do Nitro para `/\{apiBaseUrl\}/.../data.json`. Normalmente redundante quando `publicAssets` no modo premerged já escreveu esses ficheiros. |
| `translationPayloads.publicDir` | `string` | — | Pasta de saída pública relativa à raiz pública do Nitro. Predefinição igual a `apiBaseUrl` (`_locales`). Assim, os ficheiros estáticos correspondem aos URLs de fetch do cliente (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Avisa durante o build quando o número de ficheiros de payload gerado ultrapassa este limiar. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Avisa durante o build quando o tamanho total de payload gerado ultrapassa este limiar em bytes. |

## SEO

Meta tags geradas para cada página localizada.

| Opção | Tipo | Predefinição | Descrição |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Gera automaticamente meta tags SEO (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | URL base para meta tags SEO (canonical, og:url, hreflang). - Uma string de URL concreta (por exemplo, `'https://example.com'`) — usada tal como está (prioridade mais alta). - `undefined` — recai em `site.url` do `nuxt-site-config` quando esse módulo está presente; caso contrário, na origem do pedido atual (`useRequestURL().origin` no servidor, `window.location.origin` no cliente). |
| `metaTrustForwardedHost` | `boolean` | `true` | Confia no cabeçalho `X-Forwarded-Host` ao resolver o URL base para meta tags. Ative quando a aplicação corre atrás de um proxy reverso (nginx, Cloudflare, AWS ALB, etc.) que define este cabeçalho para o hostname real visível ao cliente. |
| `metaTrustForwardedProto` | `boolean` | `true` | Confia no cabeçalho `X-Forwarded-Proto` ao resolver o protocolo para meta tags. Ative quando a aplicação corre atrás de um proxy que termina TLS, para que os URLs canónicos utilizem `https://` mesmo que a aplicação em si escute em HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Lista de nomes de parâmetros de consulta preservados em meta tags canonical e `og:url`. Parâmetros que não estejam nesta lista são removidos do URL canónico. |

## Deteção e redirecionamentos

Escolher um locale para um visitante que ainda não escolheu um.

| Opção | Tipo | Predefinição | Descrição |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Ativa redirecionamentos automáticos baseados em locale. Quando `true`, os visitantes são redirecionados para o seu locale preferido (detetado a partir de cookie, cabeçalho `Accept-Language` ou o predefinido) na primeira visita. |
| `autoDetectLanguage` | `boolean` | `true` | Deteta automaticamente o idioma preferido do utilizador a partir do cabeçalho HTTP `Accept-Language`. Usado em conjunto com `autoDetectPath` para decidir quando a deteção ocorre. |
| `autoDetectPath` | `string` | `'/'` | Onde podem ocorrer redirecionamentos por preferência de cookie/Accept-Language (quando `redirects` está ativado). - `'/'` — apenas `/` (deep links no locale predefinido continuam acessíveis; predefinição) - `'no_prefix'` — apenas caminhos sem prefixo de locale - `'*'` — todos os caminhos, incluindo reescrever um prefixo explícito de locale (por exemplo, `/fr/about` → `/de/about` quando o cookie prefere `de`) - qualquer outra string — correspondência exata do caminho (por exemplo, `'/welcome'`) A limpeza de prefixos da estratégia (por exemplo, `/en` → `/` em `prefix_except_default`) não está condicionada. |

## Registo

Partes do módulo que pode desligar.

| Opção | Tipo | Predefinição | Descrição |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Regista o plugin macro `defineI18nRoute()`, ativando chamadas a `defineI18nRoute()` por página. |
| `plugin` | `boolean` | `true` | Regista o plugin i18n principal que fornece `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` e outros helpers de runtime. |
| `hooks` | `boolean` | `true` | Regista o plugin de hooks i18n que fornece os hooks ao nível da aplicação `i18n:register` e `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`. |
| `components` | `boolean` | `true` | Regista os componentes i18n incorporados (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Defina como `false` para desativar o registo automático de componentes (por exemplo, se não os utiliza e quer reduzir o footprint do módulo). |
| `types` | `boolean` | `true` | Gera declarações de tipos TypeScript para `useI18n`, `$t` e helpers relacionados com base nas chaves de tradução dos seus ficheiros de locale predefinido. |
| `debug` | `boolean` | `false` | Ativa logging de debug detalhado para deteção de locale, geração de rotas e carregamento de traduções. |

## Outros

| Opção | Tipo | Predefinição | Descrição |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | Emite também um `hreflang` de idioma simples derivado do `iso` de cada locale (por exemplo, `es-ES` → também `es`). O primeiro locale regional em `locales` reivindica a tag simples para esse idioma. O `code` de encaminhamento nunca é usado — apenas `iso \|\| code`. |
| `vueDevtools` | `boolean` | `true` | Regista o inspetor e a timeline do Vue DevTools em dev (extensão do browser). Independente do separador personalizado do Nuxt DevTools. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Prefixo colocado antes dos nomes de rotas localizadas (por exemplo, `'localized-index'`). Usado internamente para distinguir rotas originais de variantes de locale geradas. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Desativação de meta tags por rota, extraída de chamadas a `defineI18nRoute()`. Mapeia um caminho de rota para `true` (desativar todas as metas) ou para um array de códigos de locale para os quais as metas devem ser desativadas. |
| `missingWarn` | `boolean` | `true` | Mostra avisos na consola quando uma chave de tradução está em falta. |
| `hmr` | `boolean` | `true` | Ativa o Hot Module Replacement para ficheiros de tradução em desenvolvimento. Quando `true`, alterações a ficheiros JSON de tradução desencadeiam um recarregamento automático sem refresh completo da página. |
| `cacheMaxSize` | `number` | `0` | Número máximo de entradas na cache de traduções em memória. `0` significa sem limite. |
| `cacheTtl` | `number` | `0` | Tempo de vida (em segundos) das entradas de tradução em cache. `0` significa que as entradas nunca expiram. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Formatos de número nomeados por locale (compatíveis com Vue I18n). Permite chamadas ao estilo `$tn(1000, 'currency')`. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Formatos de data/hora nomeados por locale (`datetimeFormats` compatível com Vue I18n). Permite chamadas ao estilo `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | `Cache-Control` HTTP max-age (segundos) para `/\{apiBaseUrl\}/:page/:locale/data.json`. Aplica-se em pleno apenas enquanto `dateBuild` invalida o URL (`?v=...`), o que é o comportamento predefinido: a resposta é então `public, max-age=…, immutable` e segura para browsers e CDNs. - `dateBuild: 0`/`''` — o URL é estável, pelo que esta duração *não* é respeitada; a resposta passa a `public, max-age=0, must-revalidate`. Um `max-age` longo num URL estático fixa o primeiro payload que o browser recebeu. - `0` — não define `Cache-Control` de todo (útil em depuração local) - Não é aplicado em desenvolvimento (`import.meta.dev`) para que o HMR não seja contrariado pela cache do browser - Alcança apenas as respostas servidas pelo Nitro. Payloads copiados para `public/` e servidos pela plataforma de alojamento recebem os cabeçalhos dessa plataforma — consulte o guia de desempenho. Análogo à opção experimental `httpCacheDuration` do `@nuxtjs/i18n` (v10.2.0), mas como cabeçalho de resposta explícito em vez do maxAge do `defineCachedEventHandler` do Nitro. |
| `dateBuild` | `string \| number` | — | Valor usado para invalidar a cache dos pedidos de tradução (`?v=...`). Quando não é fornecido, o módulo recorre a `Date.now()` (não determinístico). Para implementações reproduzíveis/rolantes, defina isto para um valor estável (por exemplo, um SHA de git ou número de build). |
| `experimental` | `Record<string, unknown>` | — | Reservatório para opções experimentais/instáveis. Os conteúdos podem mudar ou ser removidos sem aviso entre versões menores. |
