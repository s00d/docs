Esta página lista todas as chaves do objeto `i18n` em `nuxt.config`. Utilize as tabelas para consultar um tipo ou uma predefinição, e os detalhes mais abaixo para exemplos e ressalvas. Os tipos, as predefinições e as descrições são gerados a partir da interface `ModuleOptions` em [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).

```ts nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
    ],
    defaultLocale: 'en',
  },
})
```

Uma opção aninhada aparece sob o seu caminho com pontos: `translationPayloads.mode` é a chave `mode` de `translationPayloads`.

## Locales e encaminhamento {#locales-and-routing}

Que idiomas existem e como aparecem no URL.

| Opção | Tipo | Predefinição | Descrição |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Lista de locales suportados. Cada entrada define um código de locale e metadados opcionais (ISO, direção, nome apresentado, etc.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Estratégia de encaminhamento de URL para os prefixos de locale. - `'no_prefix'` — nenhum locale no URL; o locale é guardado num cookie. - `'prefix_except_default'` — prefixo em todos os locales exceto o predefinido. - `'prefix'` — prefixo sempre, incluindo o locale predefinido. - `'prefix_and_default'` — como `prefix`, mas o locale predefinido também é acessível sem prefixo. |
| `defaultLocale` | `string` | `'en'` | O locale a usar quando não é possível determinar nenhum locale a partir do URL ou das preferências do utilizador. Não é um fallback de tradução: para isso, defina `fallbackLocale`. |
| `localeCookie` | `string \| null` | `null` | Nome do cookie para persistir a preferência de locale do utilizador entre sessões. Defina como `null` para desativar a persistência baseada em cookie. É definido automaticamente como `'user-locale'` para a estratégia `no_prefix` se não for indicado; um `null` explícito no bloco de configuração `i18n` mantém-no desativado também aí. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `{}` | Configuração global de locales ao nível da rota. Permite restringir ou personalizar as rotas de locale de páginas específicas sem modificar os seus componentes. - `false` — exclui a rota da localização. - `Record<LocaleCode, string>` — caminhos personalizados por locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Expressão regular personalizada (ou a sua fonte em string) para corresponder aos códigos de locale nos segmentos do URL. Todos os códigos de locale em `locales` têm de corresponder ao padrão completo, sem as suas flags, ou a build falha. |
| `noPrefixRedirect` | `boolean` | `false` | Para a estratégia `no_prefix`: quando o locale predefinido tem um caminho personalizado para uma página (`localeRoutes` / `globalLocaleRoutes`), redireciona o caminho original da página para o caminho personalizado do locale do visitante ou, caso contrário, para o do locale predefinido (por exemplo, `/about` → `/about-us`). Um locale sem caminho personalizado próprio mantém-se no caminho original. As páginas com segmentos dinâmicos não são redirecionadas. |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Caminhos a deixar fora do encaminhamento i18n: uma string é um prefixo de caminho (`/admin` abrange `/admin/x`) ou um glob `*` / `?`; uma RegExp é testada contra o caminho. As páginas correspondentes não têm variantes de locale, nem redirecionamento de locale ou 404, e são retiradas do prerender; continuam a ser apresentadas com traduções. `/api`, `/_nuxt`, `/__*`, a rota de traduções e os ficheiros estáticos comuns (sitemap, robots.txt, favicon, recursos por extensão) são sempre excluídos. |
| `routeLocales` | `Record<string, string[]>` | — | Restrições de locale por rota, extraídas em tempo de build das chamadas a `$defineI18nRoute()`. Associa um caminho de rota (por exemplo, `'/about'`) a um array de códigos de locale permitidos. As rotas não listadas não têm restrições (todos os locales são permitidos). |

## Traduções {#translations}

Onde estão os ficheiros de tradução e como as chaves são resolvidas.

| Opção | Tipo | Predefinição | Descrição |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Caminho para o diretório que contém os ficheiros JSON de tradução, relativo à raiz do projeto. |
| `disableWatcher` | `boolean` | `false` | Desativa o observador de ficheiros que cria automaticamente os ficheiros de tradução em falta no modo de desenvolvimento. |
| `routesLocaleLinks` | `{ [key: string]: string }` | `{}` | Associa nomes de rotas a outros nomes de rotas para partilharem os mesmos ficheiros de tradução. Por exemplo, `{ 'about-us': 'about' }` significa que a página `about-us` usará as traduções da página `about` em vez das suas. |
| `plural` | `PluralFunc` | ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)`` | Função de pluralização personalizada. Recebe `(key, count, params, locale, getter)` e deve devolver a forma plural selecionada como string, ou `null`/`undefined` para recorrer à lógica integrada `defaultPlural` (para que possa substituir apenas alguns locales). No módulo Nuxt, a função é serializada com `.toString()` para `.nuxt/i18n.plural.mjs` — tem de ser autossuficiente (sem imports / âmbito exterior). Uma string com um caminho de ficheiro **não** é suportada. |
| `disablePageLocales` | `boolean` | `false` | Desativa os ficheiros de tradução por página. Quando `true`, só são carregadas as traduções globais (`{locale}.json`); os ficheiros específicos de página (`pages/{page}/{locale}.json`) não são gerados nem carregados. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Código do locale de fallback global. As chaves em falta num locale são obtidas deste locale (fundidas em cada payload quando é gerado ou carregado); sem ele, uma chave em falta é apresentada como a própria chave. |

## Payloads e cache {#payloads-and-caching}

Como as traduções chegam ao browser. [Desempenho](/pt/guide/performance) explica o que estas opções alteram em runtime.

| Opção | Tipo | Predefinição | Descrição |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Pré-carrega as traduções da página index no middleware global do Nitro (apenas no servidor, configuração privada). |
| `apiBaseUrl` | `string` | `'_locales'` | Segmento base do caminho do URL para a rota da API de traduções (usado na obtenção de dados em SSR/SSG). Também pode ser definido através da variável de ambiente `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Substitui o host usado nos pedidos de tradução do lado do cliente. Útil quando o cliente chega ao servidor através de um hostname diferente do que o Nuxt vê. Também pode ser definido através da variável de ambiente `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Substitui o host usado nos pedidos de tradução do lado do servidor. Útil em configurações com contentores/microsserviços em que o servidor se alcança a si próprio através de um hostname interno. Também pode ser definido através da variável de ambiente `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Controla como os payloads de tradução são emitidos (servidor Node: `public/<apiBaseUrl>`; Edge / function / inline: `serverAssets` do Nitro). - **Servidor Node** (`node-server`, `node-cluster`, `serveStatic` em disco): `serverAssets` significa SSR local através de `readFile` em `public/` (sem `raw:` do Rollup). - **Edge, presets de funções e `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …): `serverAssets` regista `serverAssets` do Nitro (`assets:i18n`),   porque `public/` não está disponível em disco para o SSR. Não força uma cópia pública — defina `publicAssets: true` para CDN/estático. Mantenha as predefinições para a configuração habitual tudo-em-um. Para catálogos Edge grandes, prefira `mode: 'source'`. Para deploys apoiados numa CDN, desative os outputs locais e defina `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Estratégia dos payloads de tradução. - `premerged`: matriz `{page}/{locale}/data.json` gerada em tempo de build (predefinição) - `source`: ficheiros-fonte compactos fundidos em runtime (preferível no Edge / em catálogos grandes) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Payloads de SSR local: um servidor Node que serve `public/` a partir do disco lê essa árvore (força a cópia pública); Edge, presets de funções e `serveStatic: "inline"` incorporam através de `serverAssets` do Nitro. - **Servidor Node** (o preset serve o próprio `public/`, por exemplo `node-server`): sem `serverAssets` do Nitro (evita `raw:` do Rollup). O SSR lê   `public/<apiBaseUrl\|publicDir>` como `{page}/{locale}/data.json`; quando isto é `true`,   é forçada uma cópia pública mesmo que `publicAssets` seja false. - **Edge, presets de funções e inline** (`nitro.node === false`, sem `serveStatic` em disco, como `vercel` /   `netlify` / `aws-lambda`, ou `serveStatic: "inline"`, por exemplo winterjs): `serverAssets` do Nitro (`assets:i18n`)   com a mesma estrutura que `mode`. **Não** força uma cópia pública — defina `publicAssets: true` para CDN/estático. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Regista a rota de servidor integrada em `/{apiBaseUrl}/:page/:locale/data.json`. Desative-a quando os payloads de tradução são servidos a partir de um host/CDN externo. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Copia os payloads para o output público do Nitro. Premerged → `{page}/{locale}/data.json` sob `apiBaseUrl`; source → árvore compacta. Quando o SSR lê `public/` (`node-server` e semelhantes), `serverAssets: true` também força esta cópia. Nos presets Edge / function / `serveStatic: "inline"`, só copia quando isto é `true` (o SSR usa a incorporação do Nitro). |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Ativa o prerender pelo Nitro de `/{apiBaseUrl}/.../data.json`. Normalmente redundante quando o `publicAssets` pré-fundido já escreveu esses ficheiros. |
| `translationPayloads.publicDir` | `string` | — | Pasta de output pública relativa à raiz pública do Nitro. A predefinição é `apiBaseUrl` (`_locales`). Assim, os ficheiros estáticos correspondem aos URLs de fetch do cliente (`/{apiBaseUrl}/{page}/{locale}/data.json`). |
| `translationPayloads.rootDelta` | `boolean` | `true` | Escreve um ficheiro raiz por locale e, em cada ficheiro de página, apenas o que difere dele. O cliente e o SSR fundem-nos; um chunk completo continua a funcionar onde quer que um ficheiro seja lido. `false` mantém um dicionário completo em cada ficheiro de página. Apenas `premerged`, e desativado com `disablePageLocales`. |
| `translationPayloads.warnFileCount` | `number` | `500` | Emite um aviso durante a build quando o número de ficheiros de payload gerados excede este limiar. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Emite um aviso durante a build quando o tamanho total dos payloads gerados excede este limiar em bytes. |

## SEO {#seo}

Meta tags geradas para cada página localizada.

| Opção | Tipo | Predefinição | Descrição |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Gera automaticamente meta tags SEO (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | URL base para as meta tags SEO (canonical, og:url, hreflang). - Uma string de URL concreta (por exemplo, `'https://example.com'`) — usada tal como está (prioridade máxima). - `undefined` — recorre a `site.url` do `nuxt-site-config` quando esse módulo está   presente e, caso contrário, à origem do pedido atual   (`useRequestURL().origin` no servidor, `window.location.origin` no cliente). |
| `metaTrustForwardedHost` | `boolean` | `true` | Confia no cabeçalho `X-Forwarded-Host` ao resolver o URL base para as meta tags. Ative quando a aplicação corre atrás de um proxy inverso (nginx, Cloudflare, AWS ALB, etc.) que define este cabeçalho com o hostname real visto pelo cliente. |
| `metaTrustForwardedProto` | `boolean` | `true` | Confia no cabeçalho `X-Forwarded-Proto` ao resolver o protocolo para as meta tags. Ative quando a aplicação corre atrás de um proxy que termina o TLS, para que os URLs canónicos usem `https://` mesmo que a própria aplicação escute em HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Lista de nomes de parâmetros de query preservados nas meta tags canonical e `og:url`. Os parâmetros que não constam desta lista são removidos do URL canónico. |

## Deteção e redirecionamentos {#detection-and-redirects}

Escolher um locale para um visitante que ainda não escolheu nenhum.

| Opção | Tipo | Predefinição | Descrição |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Ativa os redirecionamentos automáticos de locale (plugin de servidor e middleware de rota do cliente). Quando `true`, as estratégias com prefixo redirecionam um URL sem prefixo para a sua forma localizada. O locale vem do estado da aplicação, do cookie ou de `Accept-Language` onde `autoDetectPath` o permitir e, caso contrário, do predefinido. Em `no_prefix`, a deteção nunca altera o URL (consulte `noPrefixRedirect` para caminhos personalizados). |
| `autoDetectLanguage` | `boolean` | `true` | Deteta automaticamente o idioma preferido do utilizador a partir do cabeçalho HTTP `Accept-Language`. Usado em conjunto com `autoDetectPath` para decidir quando ocorre a deteção. |
| `autoDetectPath` | `string` | `'/'` | Onde podem ocorrer os redirecionamentos por preferência do cookie / Accept-Language (quando `redirects` está ativo). - `'/'` — apenas `/` (as ligações diretas no locale predefinido continuam acessíveis; predefinição) - `'no_prefix'` — apenas caminhos sem prefixo de locale - `'*'` — todos os caminhos, incluindo a reescrita de um prefixo de locale explícito   (por exemplo, `/fr/about` → `/de/about` quando o cookie prefere `de`) - qualquer outra string — esse caminho, ignorando barras finais (por exemplo, `'/welcome'`) Em `prefix`, um URL sem prefixo fora dos caminhos permitidos continua a redirecionar para a forma do locale predefinido (`/about` → `/en/about`). O locale predefinido com prefixo em `prefix_except_default` (`/en`) é um 404, não um redirecionamento. |

| --- | --- | --- | --- |
| `trustForwardedHost` | `boolean` | `false` | Escolhe o domínio de um pedido (`locales[].baseUrl`) a partir de `X-Forwarded-Host` em vez de `Host`. Ative-o apenas atrás de um proxy que substitua esse cabeçalho. |

Ordem de fusão: cada entrada pela ordem do array (através das camadas) e depois `translationDir` (prevalece em caso de conflito). Só são lidos os ficheiros `{locale}.json` raiz — `pages/` dentro destes diretórios é ignorado. Exemplo: `translationDir: 'frontend'`, `additionalTranslationDirs: ['common']` → `common/en.json` e depois `frontend/en.json`. |
| `vueDevtools` | `boolean` | `true` | Regista o inspetor e a linha temporal do Vue DevTools em desenvolvimento (extensão de browser). Separado do separador personalizado do Nuxt DevTools. |

A predefinição é `experimental.defaults.nuxtLink.trailingSlash` quando não definido. Defina explicitamente para substituir a predefinição de ligações do Nuxt nos helpers de caminhos i18n. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Prefixo acrescentado aos nomes de rotas localizadas (por exemplo, `'localized-index'`). Usado internamente para distinguir as rotas originais das variantes de locale geradas. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Desativação de meta tags por rota. Associa um nome ou caminho de rota a `true` (desativa todas as meta) ou a um array de códigos de locale para os quais as meta devem ser desativadas. As entradas encontradas nas chamadas a `$defineI18nRoute()` em tempo de build são-lhe acrescentadas. |
| `missingWarn` | `boolean` | `true` | Mostra avisos na consola quando falta uma chave de tradução (build de desenvolvimento, no browser). |
| `hmr` | `boolean` | `true` | Ativa o Hot Module Replacement para os ficheiros de tradução em desenvolvimento. Quando `true`, as alterações aos ficheiros JSON de tradução desencadeiam um recarregamento automático sem atualizar a página inteira. |
| `cacheMaxSize` | `number` | `0` | Número máximo de entradas nas caches de traduções em memória. As caches de fetch e do servidor descartam a entrada usada menos recentemente; o mapa de dicionários do browser descarta a mais antiga (FIFO). `0` significa sem limite no browser; as caches do servidor mantêm então no máximo 1000 entradas, para que URLs de pedidos com páginas inventadas não possam fazer crescer a memória do servidor. |
| `cacheTtl` | `number` | `0` | Tempo de vida (em segundos) das caches de traduções de fetch e do servidor, contado a partir do momento em que uma entrada foi guardada (as leituras não o prolongam), para que os dados de `apiBaseServerHost` sejam atualizados pelo menos com essa frequência. Os dicionários ativos do browser não expiram por causa dele. `0` significa que as entradas nunca expiram. |
| `cacheStorage` | `string` | — | Nome de uma montagem de armazenamento Nitro (`nitro.storage`, por exemplo `'redis'`) que várias instâncias de servidor partilham como cache de dicionários, lida depois da cache em processo e antes da fonte. Compensa sobretudo com `apiBaseServerHost`: um único fetch ao backend em vez de um por instância. As entradas são indexadas pela build e expiram após `cacheTtl`, ou após um dia quando este é `0`. Desativado em desenvolvimento e no prerender. Um armazenamento com falhas recorre à fonte. Não definido: sem cache partilhada. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Formatos de números nomeados por locale (compatíveis com o Vue I18n). Permite chamadas como `$tn(1000, 'currency')`. |
| `timeZone` | `string` | `the runtime's zone` | Fuso horário IANA para `$td` e `<i18n-t date>` (`Europe/Berlin`). Defina-o para apresentar a mesma data no servidor e em todos os browsers; o `timeZone` próprio de um formato nomeado prevalece. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Formatos de data/hora nomeados por locale (`datetimeFormats` compatíveis com o Vue I18n). Permite chamadas como `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | max-age (segundos) do `Cache-Control` HTTP para `/{apiBaseUrl}/:page/:locale/data.json`. Aplica-se integralmente apenas enquanto `dateBuild` altera o URL (`?v=...`), que é a predefinição: a resposta é então `private, max-age=…, immutable`: um browser fixa-a, e uma CDN que ignore a query não consegue (`public` com `httpCacheControl: false`). - `dateBuild: 0`/`''` — o URL é estável, pelo que esta duração *não* é respeitada; a   resposta passa a ser `public, max-age=0, must-revalidate`. Um `max-age` longo num   URL que não muda fixa o primeiro payload que um browser alguma vez viu. - `0` — não define `Cache-Control` de todo (útil na depuração local) - Não é aplicado em desenvolvimento (`import.meta.dev`), para que o HMR não seja contrariado pela cache do browser - Abrange apenas respostas servidas através do Nitro. Os payloads copiados para `public/` e servidos   pela plataforma de alojamento recebem os cabeçalhos dessa plataforma — consulte o guia de Desempenho. Análogo ao `httpCacheDuration` experimental do `@nuxtjs/i18n` (v10.2.0), mas como cabeçalho de resposta explícito em vez do maxAge de `defineCachedEventHandler` do Nitro. |
| `httpCacheControl` | `string \| false` | `'public, max-age=60'` | `Cache-Control` de um ficheiro de payload respondido por um host ou por uma regra para todo o caminho, que não consegue ver `?v=`. Num servidor Node, uma resposta ao `?v=` atual é fixada durante `httpCacheDuration` e qualquer outra é revalidada; com `source`, `cacheTtl` ou `apiBaseServerHost`, em que um dicionário muda sem build, todas as respostas recebem este cabeçalho. `false` mantém todos os ficheiros em `max-age=0, must-revalidate`. |
| `dateBuild` | `string \| number` | — | Valor usado para o cache-busting dos pedidos de tradução (`?v=...`). Quando não é indicado, o módulo usa um hash dos ficheiros de tradução, pelo que o valor só muda quando as traduções mudam (`Date.now()` quando não é possível calcular nenhum hash). `0` ou `''` desativa o cache-busting. Defina um valor estável (um SHA do git, um número de build) para o fixar você mesmo. `NUXT_I18N_DATE_BUILD` ou `runtimeConfig.public.i18nRuntime.dateBuild` substitui-o em runtime, depois de um dicionário ter sido substituído no local: os URLs fixados ficam para trás, sem nova build. |
| `experimental` | `Record<string, unknown>` | — | Conjunto de opções experimentais/instáveis. O conteúdo pode mudar ou ser removido sem aviso entre versões minor. |

## Detalhes das opções {#option-details}

As opções sem nada a acrescentar à tabela não são repetidas aqui.

### Locales e URLs {#locales-and-urls}

#### `locales` {#locales}

**Tipo** `Locale[]` · **Predefinição** `[]`

Lista de locales suportados.
Cada entrada define um código de locale e metadados opcionais (ISO, direção, nome apresentado, etc.).

Cada entrada é um objeto `Locale`:

| Propriedade | Tipo | Descrição |
| --- | --- | --- |
| `code` | `string` | **Obrigatório.** Segmento do URL e nome de ficheiro (`en`, `de-at`). |
| `iso` | `string` | Tag BCP-47 para `<html lang>`, `hreflang`, plurais e `$tn` / `$td` / `$tdr` (`en-US`). |
| `displayName` | `string` | Etiqueta em `<i18n-switcher>` e `$getLocaleName()`. |
| `dir` | `'ltr' \| 'rtl' \| 'auto'` | `<html dir>`. Sem ele, os idiomas RTL conhecidos recebem `rtl` e todos os outros locales não recebem nenhum atributo. Consulte [SEO](/pt/guide/seo#text-direction). |
| `disabled` | `boolean` | Excluído das rotas, dos payloads e da mudança de locale. O seu prefixo é um 404, e as ligações para ele permanecem na página. |
| `fallbackLocale` | `string` | Fallback para este locale; substitui o `fallbackLocale` global. |
| `seo` | `boolean` | `false` deixa o locale fora de `hreflang` e de `og:locale:alternate`. |
| `og` | `string` | Valor de `og:locale` (`ar_AE`); predefinição: `iso` convertido. |
| `baseUrl` | `string` | O domínio próprio do locale: uma única build serve-o, e as ligações para ele a partir de outros domínios são absolutas. |
| `baseDefault` | `boolean` | Com `baseUrl`: o locale predefinido do seu host, sem prefixo `/<code>` nas ligações para ele (`prefix` mantém-no). |

As outras propriedades são mantidas e devolvidas por `$getLocales()`. Tipifique-as aumentando `Locale`:

```ts
// i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
  }
}
export {}
```

O módulo faz hoisting de `@i18n-micro/types`, pelo que isto funciona com pnpm sem instalar o pacote.

#### `defaultLocale` {#defaultlocale}

**Tipo** `string` · **Predefinição** `'en'`

O locale a usar quando não é possível determinar nenhum locale a partir do URL ou das preferências do utilizador.
Não é um fallback de tradução: para isso, defina `fallbackLocale`.

#### `strategy` {#strategy}

**Tipo** `Strategies` · **Predefinição** `'prefix_except_default'`

Estratégia de encaminhamento de URL para os prefixos de locale.

- `'no_prefix'` — nenhum locale no URL; o locale é guardado num cookie.
- `'prefix_except_default'` — prefixo em todos os locales exceto o predefinido.
- `'prefix'` — prefixo sempre, incluindo o locale predefinido.
- `'prefix_and_default'` — como `prefix`, mas o locale predefinido também é acessível sem prefixo.

URLs por estratégia e redirecionamentos: [Estratégias de encaminhamento](/pt/guide/strategy).

#### `globalLocaleRoutes` {#globallocaleroutes}

**Tipo** `GlobalLocaleRoutes` · **Predefinição** `{}`

Configuração global de locales ao nível da rota.
Permite restringir ou personalizar as rotas de locale de páginas específicas sem
modificar os seus componentes.

- `false` — exclui a rota da localização.
- `Record<LocaleCode, string>` — caminhos personalizados por locale.

As chaves são nomes ou caminhos de rotas. Normalmente definido por página com [`$defineI18nRoute`](/pt/guide/per-component-translations).

```ts
globalLocaleRoutes: {
  about: { en: '/about-us', de: '/ueber-uns' },
  'admin-dashboard': false, // not localized
}
```

Detalhes, segmentos dinâmicos e rotas de `pages:extend`: [Caminhos localizados](/pt/guide/custom-locale-routes).

#### `routeLocales` {#routelocales}

**Tipo** `Record<string, string[]>` · **Predefinição** —

Restrições de locale por rota, extraídas em tempo de build das chamadas a `$defineI18nRoute()`.
Associa um caminho de rota (por exemplo, `'/about'`) a um array de códigos de locale permitidos.
As rotas não listadas não têm restrições (todos os locales são permitidos).

#### `routeDisableMeta` {#routedisablemeta}

**Tipo** `Record<string, boolean \| string[]>` · **Predefinição** —

Desativação de meta tags por rota. Associa um nome ou caminho de rota a `true` (desativa todas as meta) ou a um array
de códigos de locale para os quais as meta devem ser desativadas. As entradas encontradas nas chamadas a `$defineI18nRoute()`
em tempo de build são-lhe acrescentadas.

#### `customRegexMatcher` {#customregexmatcher}

**Tipo** `string \| RegExp` · **Predefinição** `undefined (uses built-in pattern based on locale codes)`

Expressão regular personalizada (ou a sua fonte em string) para corresponder aos códigos de locale nos segmentos do URL.
Todos os códigos de locale em `locales` têm de corresponder ao padrão completo, sem as suas flags, ou a build falha.

```ts
customRegexMatcher: '[a-z]{2}-[a-z]{2}', // en-us, de-at
```

#### `excludePatterns` {#excludepatterns}

**Tipo** `(string \| RegExp)[]` · **Predefinição** `undefined`

Caminhos a deixar fora do encaminhamento i18n: uma string é um prefixo de caminho (`/admin` abrange `/admin/x`)
ou um glob `*` / `?`; uma RegExp é testada contra o caminho. As páginas correspondentes não têm variantes
de locale, nem redirecionamento de locale ou 404, e são retiradas do prerender; continuam a ser apresentadas com
traduções. `/api`, `/_nuxt`, `/__*`, a rota de traduções e os ficheiros estáticos comuns
(sitemap, robots.txt, favicon, recursos por extensão) são sempre excluídos.

```ts
excludePatterns: ['/admin', '/docs/*', /^\/preview\//],
```

Mais: [Excluir caminhos](/pt/guide/excluding-static-files).

#### `localizedRouteNamePrefix` {#localizedroutenameprefix}

**Tipo** `string` · **Predefinição** `'localized-'`

Prefixo acrescentado aos nomes de rotas localizadas (por exemplo, `'localized-index'`).
Usado internamente para distinguir as rotas originais das variantes de locale geradas.

#### `trailingSlash` {#trailingslash}

**Tipo** `'append' \| 'remove'` · **Predefinição** `undefined (inherit from Nuxt)`

Barra final para `$localePath` / `$switchLocalePath` (paridade com o NuxtLink).
A predefinição é `experimental.defaults.nuxtLink.trailingSlash` quando não definido.
Defina explicitamente para substituir a predefinição de ligações do Nuxt nos helpers de caminhos i18n.

### Traduções {#translations}

#### `translationDir` {#translationdir}

**Tipo** `string` · **Predefinição** `'locales'`

Caminho para o diretório que contém os ficheiros JSON de tradução, relativo à raiz do projeto.

Relativo à raiz de cada camada, e não a `app/` (`'app/locales'` para uma estrutura Nuxt 4). Estrutura dos ficheiros: [Ficheiros de tradução](/pt/guide/translations).

#### `additionalTranslationDirs` {#additionaltranslationdirs}

**Tipo** `string[]` · **Predefinição** `[]`

Diretórios extra (relativos à raiz do projeto / à raiz de cada camada Nuxt) cujos ficheiros
`{locale}.json` de nível superior são fundidos em profundidade no dicionário global antes de `translationDir`.

Ordem de fusão: cada entrada pela ordem do array (através das camadas) e depois `translationDir` (prevalece em caso de conflito).
Só são lidos os ficheiros `{locale}.json` raiz — `pages/` dentro destes diretórios é ignorado.

Exemplo: `translationDir: 'frontend'`, `additionalTranslationDirs: ['common']` → `common/en.json` e depois `frontend/en.json`.

#### `disablePageLocales` {#disablepagelocales}

**Tipo** `boolean` · **Predefinição** `false`

Desativa os ficheiros de tradução por página.
Quando `true`, só são carregadas as traduções globais (`{locale}.json`);
os ficheiros específicos de página (`pages/{page}/{locale}.json`) não são gerados nem carregados.

#### `fallbackLocale` {#fallbacklocale}

**Tipo** `string` · **Predefinição** `undefined (no fallback; returns the raw key)`

Código do locale de fallback global.
As chaves em falta num locale são obtidas deste locale (fundidas em cada payload quando é
gerado ou carregado); sem ele, uma chave em falta é apresentada como a própria chave.

#### `routesLocaleLinks` {#routeslocalelinks}

**Tipo** `{ [key: string]: string }` · **Predefinição** `{}`

Associa nomes de rotas a outros nomes de rotas para partilharem os mesmos ficheiros de tradução.
Por exemplo, `{ 'about-us': 'about' }` significa que a página `about-us` usará
as traduções da página `about` em vez das suas.

```ts
routesLocaleLinks: { 'products-id': 'products' },
```

#### `plural` {#plural}

**Tipo** `PluralFunc` · **Predefinição** ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)``

Função de pluralização personalizada.
Recebe `(key, count, params, locale, getter)` e deve devolver a forma
plural selecionada como string, ou `null`/`undefined` para recorrer à lógica integrada
`defaultPlural` (para que possa substituir apenas alguns locales).

No módulo Nuxt, a função é serializada com `.toString()` para
`.nuxt/i18n.plural.mjs` — tem de ser autossuficiente (sem imports / âmbito exterior).
Uma string com um caminho de ficheiro **não** é suportada.

A regra integrada e o seu marcador `=0 ` estão descritos em [`$tc`](/pt/api/methods#$tc). A sua função substitui-a naquilo a que responde, recebe o valor em bruto com qualquer marcador no lugar, e `null` devolve-lhe a chamada. A função recebe `(key, count, params, locale, getter)`; `getter(key)` devolve a string em bruto com todas as formas. Escreva-a como uma expressão `function` ou arrow autossuficiente (sem abreviatura de método, sem imports, sem variáveis exteriores):

```ts
plural: function (key, count, params, locale, getter) {
  if (!locale.startsWith('en')) return null // built-in rule for other locales
  const forms = String(getter(key) ?? '').split('|').map((form) => form.trim())
  const index = count === 0 ? 0 : count === 1 ? 1 : 2
  return (forms[Math.min(index, forms.length - 1)] ?? '').replace('{count}', String(count))
},
```

```json
{ "apples": "no apples | one apple | {count} apples" }
```

#### `numberFormats` {#numberformats}

**Tipo** `Record<string, Record<string, Intl.NumberFormatOptions>>` · **Predefinição** —

Formatos de números nomeados por locale (compatíveis com o Vue I18n).
Permite chamadas como `$tn(1000, 'currency')`.

Usado por [`$tn`](/pt/api/methods#$tn).

#### `datetimeFormats` {#datetimeformats}

**Tipo** `Record<string, Record<string, Intl.DateTimeFormatOptions>>` · **Predefinição** —

Formatos de data/hora nomeados por locale (`datetimeFormats` compatíveis com o Vue I18n).
Permite chamadas como `$td(date, 'short')`.

Usado por [`$td`](/pt/api/methods#$td).

#### `timeZone` {#timezone}

**Tipo** `string` · **Predefinição** `the runtime's zone`

Fuso horário IANA para `$td` e `<i18n-t date>` (`Europe/Berlin`). Defina-o para apresentar a mesma data
no servidor e em todos os browsers; o `timeZone` próprio de um formato nomeado prevalece.

#### `disableWatcher` {#disablewatcher}

**Tipo** `boolean` · **Predefinição** `false`

Desativa o observador de ficheiros que cria automaticamente os ficheiros de tradução em falta no modo de desenvolvimento.

#### `missingWarn` {#missingwarn}

**Tipo** `boolean` · **Predefinição** `true`

Mostra avisos na consola quando falta uma chave de tradução (build de desenvolvimento, no browser).

Para reportar as chaves em falta, utilize antes [`$setMissingHandler`](/pt/api/methods#$setmissinghandler).

### Payloads e cache {#payloads-and-caching}

#### `translationPayloads` {#translationpayloads}

**Tipo** `TranslationPayloadOptions` · **Predefinição** —

Controla como os payloads de tradução são emitidos (servidor Node: `public/<apiBaseUrl>`; Edge / function / inline: `serverAssets` do Nitro).

- **Servidor Node** (`node-server`, `node-cluster`, `serveStatic` em disco): `serverAssets` significa SSR local através de `readFile` em `public/` (sem `raw:` do Rollup).
- **Edge, presets de funções e `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …): `serverAssets` regista `serverAssets` do Nitro (`assets:i18n`),
  porque `public/` não está disponível em disco para o SSR. Não força uma cópia pública — defina `publicAssets: true` para CDN/estático.

Mantenha as predefinições para a configuração habitual tudo-em-um. Para catálogos Edge grandes, prefira `mode: 'source'`.
Para deploys apoiados numa CDN, desative os outputs locais e defina `apiBaseClientHost` / `apiBaseServerHost`.

As subopções estão na tabela [Payloads e cache](#payloads-and-caching). Que combinação se adequa a Node, serverless, Edge, alojamento estático ou uma CDN: [Deploy](/pt/guide/deployment).

#### `apiBaseUrl` {#apibaseurl}

**Tipo** `string` · **Predefinição** `'_locales'`

Segmento base do caminho do URL para a rota da API de traduções (usado na obtenção de dados em SSR/SSG).
Também pode ser definido através da variável de ambiente `NUXT_I18N_APP_BASE_URL`.

Os URLs dos payloads são `/{apiBaseUrl}/{page}/{locale}/data.json`.

#### `apiBaseClientHost` {#apibaseclienthost}

**Tipo** `string` · **Predefinição** `undefined`

Substitui o host usado nos pedidos de tradução do lado do cliente.
Útil quando o cliente chega ao servidor através de um hostname diferente do que o Nuxt vê.
Também pode ser definido através da variável de ambiente `NUXT_I18N_APP_BASE_CLIENT_HOST`.

#### `apiBaseServerHost` {#apibaseserverhost}

**Tipo** `string` · **Predefinição** `undefined`

Substitui o host usado nos pedidos de tradução do lado do servidor.
Útil em configurações com contentores/microsserviços em que o servidor se alcança a si próprio através de um hostname interno.
Também pode ser definido através da variável de ambiente `NUXT_I18N_APP_BASE_SERVER_HOST`.

Um host tem de servir as mesmas respostas `/{apiBaseUrl}/{page}/{locale}/data.json` que a rota integrada.

#### `dateBuild` {#datebuild}

**Tipo** `string \| number` · **Predefinição** —

Valor usado para o cache-busting dos pedidos de tradução (`?v=...`).

Quando não é indicado, o módulo usa um hash dos ficheiros de tradução, pelo que o valor só muda
quando as traduções mudam (`Date.now()` quando não é possível calcular nenhum hash). `0` ou `''` desativa
o cache-busting. Defina um valor estável (um SHA do git, um número de build) para o fixar você mesmo.
`NUXT_I18N_DATE_BUILD` ou `runtimeConfig.public.i18nRuntime.dateBuild` substitui-o em runtime, depois de um dicionário
ter sido substituído no local: os URLs fixados ficam para trás, sem nova build.

#### `httpCacheDuration` {#httpcacheduration}

**Tipo** `number` · **Predefinição** `31536000`

max-age (segundos) do `Cache-Control` HTTP para `/{apiBaseUrl}/:page/:locale/data.json`.

Aplica-se integralmente apenas enquanto `dateBuild` altera o URL (`?v=...`), que é a predefinição:
a resposta é então `private, max-age=…, immutable`: um browser fixa-a, e uma CDN que ignore a query não consegue
(`public` com `httpCacheControl: false`).

- `dateBuild: 0`/`''` — o URL é estável, pelo que esta duração *não* é respeitada; a
  resposta passa a ser `public, max-age=0, must-revalidate`. Um `max-age` longo num
  URL que não muda fixa o primeiro payload que um browser alguma vez viu.

- `0` — não define `Cache-Control` de todo (útil na depuração local)
- Não é aplicado em desenvolvimento (`import.meta.dev`), para que o HMR não seja contrariado pela cache do browser
- Abrange apenas respostas servidas através do Nitro. Os payloads copiados para `public/` e servidos
  pela plataforma de alojamento recebem os cabeçalhos dessa plataforma — consulte o guia de Desempenho.

Análogo ao `httpCacheDuration` experimental do `@nuxtjs/i18n` (v10.2.0), mas como
cabeçalho de resposta explícito em vez do maxAge de `defineCachedEventHandler` do Nitro.

#### `cacheMaxSize` {#cachemaxsize}

**Tipo** `number` · **Predefinição** `0`

Número máximo de entradas nas caches de traduções em memória. As caches de fetch e do servidor
descartam a entrada usada menos recentemente; o mapa de dicionários do browser descarta a mais antiga (FIFO).
`0` significa sem limite no browser; as caches do servidor mantêm então no máximo 1000 entradas, para que
URLs de pedidos com páginas inventadas não possam fazer crescer a memória do servidor.

#### `cacheTtl` {#cachettl}

**Tipo** `number` · **Predefinição** `0`

Tempo de vida (em segundos) das caches de traduções de fetch e do servidor, contado a partir do momento em que uma
entrada foi guardada (as leituras não o prolongam), para que os dados de `apiBaseServerHost` sejam atualizados pelo
menos com essa frequência. Os dicionários ativos do browser não expiram por causa dele. `0` significa que as entradas
nunca expiram.

O que ambas alteram em runtime: [Desempenho](/pt/guide/performance).

#### `serverTranslationPreload` {#servertranslationpreload}

**Tipo** `boolean` · **Predefinição** `false`

Pré-carrega as traduções da página index no middleware global do Nitro (apenas no servidor, configuração privada).

### SEO {#seo}

#### `meta` {#meta}

**Tipo** `boolean` · **Predefinição** `true`

Gera automaticamente meta tags SEO (`hreflang`, `canonical`, `og:url`, `og:locale`).

Substituições por página: [`useI18nHead`](/pt/composables/useI18nHead). Tudo o resto: [SEO](/pt/guide/seo).

#### `metaBaseUrl` {#metabaseurl}

**Tipo** `string` · **Predefinição** `undefined`

URL base para as meta tags SEO (canonical, og:url, hreflang).

- Uma string de URL concreta (por exemplo, `'https://example.com'`) — usada tal como está (prioridade máxima).
- `undefined` — recorre a `site.url` do `nuxt-site-config` quando esse módulo está
  presente e, caso contrário, à origem do pedido atual
  (`useRequestURL().origin` no servidor, `window.location.origin` no cliente).

#### `metaTrustForwardedHost` {#metatrustforwardedhost}

**Tipo** `boolean` · **Predefinição** `true`

Confia no cabeçalho `X-Forwarded-Host` ao resolver o URL base para as meta tags.
Ative quando a aplicação corre atrás de um proxy inverso (nginx, Cloudflare, AWS ALB, etc.)
que define este cabeçalho com o hostname real visto pelo cliente.

Só é lido quando nem `metaBaseUrl` nem `site.url` estão definidos. Defina-o como `false` quando a aplicação é acessível sem um proxy que substitua o cabeçalho: caso contrário, um cliente poderia escolher o host nos seus URLs canónicos.

#### `metaTrustForwardedProto` {#metatrustforwardedproto}

**Tipo** `boolean` · **Predefinição** `true`

Confia no cabeçalho `X-Forwarded-Proto` ao resolver o protocolo para as meta tags.
Ative quando a aplicação corre atrás de um proxy que termina o TLS, para que
os URLs canónicos usem `https://` mesmo que a própria aplicação escute em HTTP.

Mesmo âmbito que `metaTrustForwardedHost`.

#### `trustForwardedHost` {#trustforwardedhost}

**Tipo** `boolean` · **Predefinição** `false`

Escolhe o domínio de um pedido (`locales[].baseUrl`) a partir de `X-Forwarded-Host` em vez de
`Host`. Ative-o apenas atrás de um proxy que substitua esse cabeçalho.

Separado de `metaTrustForwardedHost` e desativado por predefinição: aqui o cabeçalho selecionaria os locales de outro domínio, e não apenas a origem de uma tag. Consulte [Camadas e domínios](/pt/guide/layers#multiple-domains).

#### `hreflangBaseLanguage` {#hreflangbaselanguage}

**Tipo** `boolean` · **Predefinição** `false`

Emite também um `hreflang` apenas com o idioma, derivado do `iso` de cada locale
(por exemplo, `es-ES` → também `es`). O primeiro locale regional em `locales` fica com
a tag simples desse idioma. O `code` de encaminhamento nunca é usado — apenas `iso || code`.

#### `canonicalQueryWhitelist` {#canonicalquerywhitelist}

**Tipo** `string[]` · **Predefinição** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

Lista de nomes de parâmetros de query preservados nas meta tags canonical e `og:url`.
Os parâmetros que não constam desta lista são removidos do URL canónico.

### Deteção e redirecionamentos {#detection-and-redirects}

As regras que estas opções alimentam: [Deteção de locale](/pt/guide/locale-detection).

#### `redirects` {#redirects}

**Tipo** `boolean` · **Predefinição** `true`

Ativa os redirecionamentos automáticos de locale (plugin de servidor e middleware de rota do cliente).
Quando `true`, as estratégias com prefixo redirecionam um URL sem prefixo para a sua forma localizada. O locale
vem do estado da aplicação, do cookie ou de `Accept-Language` onde `autoDetectPath` o permitir e, caso contrário,
do predefinido. Em `no_prefix`, a deteção nunca altera o URL (consulte `noPrefixRedirect` para caminhos personalizados).

Com `false`, o middleware de redirecionamento do cliente não é registado. O plugin de servidor continua a devolver 404 para URLs de locale inválidos e a escrever o cookie para um URL com prefixo.

#### `autoDetectLanguage` {#autodetectlanguage}

**Tipo** `boolean` · **Predefinição** `true`

Deteta automaticamente o idioma preferido do utilizador a partir do cabeçalho HTTP `Accept-Language`.
Usado em conjunto com `autoDetectPath` para decidir quando ocorre a deteção.

#### `autoDetectPath` {#autodetectpath}

**Tipo** `string` · **Predefinição** `'/'`

Onde podem ocorrer os redirecionamentos por preferência do cookie / Accept-Language (quando `redirects` está ativo).

- `'/'` — apenas `/` (as ligações diretas no locale predefinido continuam acessíveis; predefinição)
- `'no_prefix'` — apenas caminhos sem prefixo de locale
- `'*'` — todos os caminhos, incluindo a reescrita de um prefixo de locale explícito
  (por exemplo, `/fr/about` → `/de/about` quando o cookie prefere `de`)

- qualquer outra string — esse caminho, ignorando barras finais (por exemplo, `'/welcome'`)

Em `prefix`, um URL sem prefixo fora dos caminhos permitidos continua a redirecionar para a forma do locale
predefinido (`/about` → `/en/about`). O locale predefinido com prefixo em
`prefix_except_default` (`/en`) é um 404, não um redirecionamento.

#### `localeCookie` {#localecookie}

**Tipo** `string \| null` · **Predefinição** `null`

Nome do cookie para persistir a preferência de locale do utilizador entre sessões.
Defina como `null` para desativar a persistência baseada em cookie.
É definido automaticamente como `'user-locale'` para a estratégia `no_prefix` se não for indicado; um
`null` explícito no bloco de configuração `i18n` mantém-no desativado também aí.

Sem cookie, `Accept-Language` continua a conduzir os redirecionamentos; o cookie memoriza uma escolha entre visitas.

#### `noPrefixRedirect` {#noprefixredirect}

**Tipo** `boolean` · **Predefinição** `false`

Para a estratégia `no_prefix`: quando o locale predefinido tem um caminho personalizado para uma página
(`localeRoutes` / `globalLocaleRoutes`), redireciona o caminho original da página para o caminho
personalizado do locale do visitante ou, caso contrário, para o do locale predefinido (por exemplo, `/about` → `/about-us`).
Um locale sem caminho personalizado próprio mantém-se no caminho original. As páginas com segmentos
dinâmicos não são redirecionadas.

com base nas chaves de tradução dos ficheiros do seu locale predefinido.

Separado do pacote [`@i18n-micro/types-generator`](/pt/integrations/types-generator).

#### `hmr` {#hmr}

**Tipo** `boolean` · **Predefinição** `true`

Ativa o Hot Module Replacement para os ficheiros de tradução em desenvolvimento.
Quando `true`, as alterações aos ficheiros JSON de tradução desencadeiam um recarregamento automático
sem atualizar a página inteira.

#### `debug` {#debug}

**Tipo** `boolean` · **Predefinição** `false`

Ativa o registo de depuração detalhado para a deteção de locale, a geração de rotas e o carregamento de traduções.

#### `vueDevtools` {#vuedevtools}

**Tipo** `boolean` · **Predefinição** `true`

Regista o inspetor e a linha temporal do Vue DevTools em desenvolvimento (extensão de browser).
Separado do separador personalizado do Nuxt DevTools.

#### `experimental` {#experimental}

**Tipo** `Record<string, unknown>` · **Predefinição** —

Conjunto de opções experimentais/instáveis.
O conteúdo pode mudar ou ser removido sem aviso entre versões minor.
