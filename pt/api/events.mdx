O módulo chama um hook de runtime (da app), `i18n:register`. Utilize-o quando um plugin ou um módulo adiciona traduções que não estão nos seus ficheiros `locales/`. A sua callback recebe uma função `register` que funde as traduções na página que está a ser apresentada.

## `i18n:register` {#i18nregister}

```ts
'i18n:register': (
  register: (translations: unknown, locale?: string) => void,
  locale: string,
) => HookResult
```

| Argumento | Descrição |
| --- | --- |
| `register(translations, locale?)` | Funde em profundidade `translations` no chunk da página da rota que está a ser carregada, para `locale` (por omissão: o `locale` do hook). As chaves já existentes são substituídas. |
| `locale` | O locale da rota que está a ser carregada. |

O hook é tipado através de `RuntimeNuxtHooks`, pelo que `nuxtApp.hook('i18n:register', …)` não precisa de cast.

## Quando é disparado {#when-it-fires}

O plugin de carregamento (`i18n-plugin-loader`) chama-o:

1. uma vez no arranque, quando todos os plugins já foram executados (`app:created`) e antes de a app ser renderizada;
2. no seu `router.beforeEach`, depois de as traduções da página de destino serem carregadas, quando o caminho muda — em cada navegação com `no_prefix`.

Cada callback e cada chamada a `register` é aguardada antes de a app ser renderizada ou de a navegação prosseguir, pelo que a página é renderizada com as chaves fundidas. Com [`hooks: false`](/pt/api/module-options#hooks) o hook nunca é chamado.

## Exemplo {#example}

```ts
// plugins/i18n-extra.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('i18n:register', async (register, locale) => {
    const extra = await $fetch<Record<string, unknown>>(`/api/cms-strings/${locale}`)
    register(extra, locale)
  })
})
```

Este é um hook de runtime: registe-o com `nuxtApp.hook` num plugin, não com `nuxt.hook` no `nuxt.config` nem no `setup` de um módulo. Um módulo adiciona esse plugin com `addPlugin`.
