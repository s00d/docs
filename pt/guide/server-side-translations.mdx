Os handlers de servidor em `server/api/` e `server/routes/` podem traduzir strings e ler o locale do pedido com dois helpers importados automaticamente. Use-os para respostas de API, emails, feeds ou qualquer coisa renderizada fora de uma página Vue. Leem os mesmos ficheiros de tradução que as suas páginas e detetam o locale a partir do pedido.

## Traduzir num handler {#translate-in-a-handler}

```ts
// server/api/greeting.get.ts
export default defineEventHandler(async (event) => {
  const t = await useTranslationServerMiddleware(event)
  return { message: t('greeting', { name: 'Ada' }) }
})
```

```bash
curl 'http://localhost:3000/api/greeting?locale=de'
# {"message":"Hallo, Ada!"}
```

`useTranslationServerMiddleware(event, defaultLocale?, locale?)` é assíncrono e devolve `t(key, params?, defaultValue?)`. `t` devolve a string, interpola parâmetros `{name}` e, quando a chave não existe, devolve um `defaultValue` não vazio ou, caso contrário, a chave.

`t` vê apenas o chunk `index`: os ficheiros raiz (`locales/<locale>.json`) mais `locales/pages/index/` quando existe (apenas os ficheiros raiz com `disablePageLocales`). As chaves de outras páginas não são carregadas. Para essas, carregue o chunk por si:

```ts
const { data } = await loadTranslationsFromServer('de', 'about') // Translations object of the about page
```

## Ler o locale do pedido {#read-the-request-locale}

```ts
// server/api/locale.get.ts
export default defineEventHandler((event) => {
  const { current, isDefault, locale } = useLocaleServerMiddleware(event)
  return { current, isDefault, dir: locale?.dir ?? 'ltr' }
})
```

`useLocaleServerMiddleware(event, defaultLocale?, locale?)` é síncrono e devolve:

```ts
interface LocaleInfo {
  current: string // detected locale code
  default: string // defaultLocale, runtime overrides included (fixed at build under prefix_except_default / prefix_and_default)
  fallback: string // fallbackLocale, else the default
  available: string[] // enabled locale codes
  locale: Locale | null // the config entry of `current`
  isDefault: boolean
  isFallback: boolean
}
```

## Como o locale é escolhido {#how-the-locale-is-chosen}

Ambos os helpers usam a mesma ordem em todas as rotas de servidor, `/api` ou não:

1. a query `?locale=` (o primeiro valor quando repetido);
2. um parâmetro de rota `[locale]`, ou um prefixo de locale no caminho (`/de/...`);
3. o cookie do locale, quando [`localeCookie`](/pt/api/module-options#localecookie) está definido (`hash-locale` com `hashMode`);
4. `Accept-Language`, quando `autoDetectLanguage` está ativo (os valores q são respeitados);
5. `defaultLocale`.

Os códigos inválidos e desativados são ignorados em cada passo. Esta é a ordem da API; a renderização de uma página ignora `?locale=` com as estratégias de prefixo. As duas ordens são comparadas em [Deteção de locale](/pt/guide/locale-detection).

## Forçar um locale {#force-a-locale}

Passe o terceiro argumento para ignorar a deteção, por exemplo numa tarefa que envia emails na língua do utilizador:

```ts
export default defineEventHandler(async (event) => {
  const user = await getUser(event) // your code
  const t = await useTranslationServerMiddleware(event, undefined, user.locale)
  return sendMail(user.email, t('mail.welcome.subject'))
})
```

O segundo argumento substitui `defaultLocale` na deteção desta chamada, por isso não tem efeito quando um locale é forçado. Os dicionários são guardados em cache por pedido e por locale, e entre pedidos na cache de traduções do servidor, por isso chamar um helper várias vezes tem um custo baixo.

## Componentes de servidor {#server-components}

Um componente de servidor (`.server.vue`, `<NuxtIsland>`) é renderizado a partir do seu próprio URL, `/__nuxt_island/...`, por isso não vê o URL da página, e o Nuxt passa-lhe apenas as suas props. Passe o locale como prop `locale`. O componente é então renderizado nesse locale, e uma mudança de locale volta a pedi-lo, já que as props fazem parte do URL e da chave de cache da island. O nome está reservado: qualquer código de locale ativo numa prop chamada `locale` define o locale da renderização, por isso dê outro nome a uma prop que signifique outra coisa, como um formato de número:

```vue
<!-- components/Greeting.server.vue -->
<template><p>{{ $t('greeting') }}</p></template>
<script setup lang="ts">
defineProps<{ locale?: string }>()
</script>
```

```vue
<template>
  <Greeting :locale="$getLocale()" />
  <NuxtIsland name="Greeting" :props="{ locale: $getLocale() }" />
</template>
```

Sem a prop, é renderizado no locale do cookie ou, caso contrário, no locale predefinido, independentemente do que diga o URL, e não acompanha uma mudança de locale. O seu `$t` vê o chunk `index`: os ficheiros raiz mais `locales/pages/index/`.
