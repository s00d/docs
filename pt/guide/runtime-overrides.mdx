---
title: "Substituições em tempo de execução"
description: "Altere o locale predefinido, o locale de fallback ou os locales desativados por instância de um mesmo build, com variáveis de ambiente ou runtimeConfig."
---

As substituições em tempo de execução permitem que um mesmo artefacto de build seja executado com definições de locale diferentes por ambiente ou tenant, sem voltar a fazer build. Pode alterar o locale predefinido, o locale de fallback e os locales desativados. O encaminhamento, os redirecionamentos, a renderização e os helpers de servidor utilizam os valores substituídos, tal como o navegador numa página renderizada no servidor.

## Definir substituições com variáveis de ambiente {#set-overrides-with-environment-variables}

```bash
NUXT_I18N_DEFAULT_LOCALE=de \
NUXT_I18N_FALLBACK_LOCALE=en \
NUXT_I18N_DISABLED_LOCALES=fr,it \
node .output/server/index.mjs
```

| Variável | Alias |
| --- | --- |
| `NUXT_I18N_DEFAULT_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE` |
| `NUXT_I18N_FALLBACK_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE` |
| `NUXT_I18N_DISABLED_LOCALES` (separados por vírgulas) | `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES` |

O servidor lê-as uma vez no arranque; reinicie para aplicar uma alteração. Numa página renderizada no servidor, o navegador recebe os valores resolvidos do servidor. Com `ssr: false` não há renderização no servidor e o navegador não tem ambiente: aí aplica-se apenas `runtimeConfig.public.i18nRuntime`, e o navegador regista os avisos indicados abaixo.

## Definir substituições em runtimeConfig {#set-overrides-in-runtimeconfig}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

Um valor definido em `runtimeConfig.public.i18nRuntime` prevalece sobre a variável `NUXT_I18N_*` do mesmo campo.

Não confundir com a variável `DEFAULT_LOCALE` de tempo de build, que substitui `defaultLocale` durante o build e não precisa de suporte em tempo de execução.

## O que pode e não pode ser alterado {#what-can-and-cannot-change}

| Definição | Em tempo de execução |
| --- | --- |
| `defaultLocale` | Sim, com `prefix` e `no_prefix`. Com `prefix_except_default` e `prefix_and_default` é fixado no build (as suas páginas são as rotas sem prefixo); uma substituição é ignorada com um aviso. |
| `fallbackLocale` | Sim. |
| `disabledLocales` | Acrescenta aos locales desativados no build; nunca reativa nenhum. O locale predefinido do build não pode ser desativado com `prefix_except_default` / `prefix_and_default`. |
| `strategy` | Não. Uma estratégia em tempo de execução é ignorada com um aviso; faça um artefacto de build por estratégia. |

Valores inválidos nunca quebram a aplicação. Cada caso regista um aviso por processo de servidor:

- desativar todos os locales é ignorado;
- um `defaultLocale` que não esteja ativo recai no primeiro locale ativo;
- um `fallbackLocale` que não esteja ativo mantém o valor do build se este estiver ativo; caso contrário, não há fallback.

## Ler a configuração efetiva {#read-the-effective-config}

```vue
<script setup lang="ts">
const { $getI18nConfig } = useNuxtApp()
const config = $getI18nConfig() // build config with overrides applied
</script>
```

Trate-a como só de leitura: no servidor é partilhada por todos os pedidos e está congelada em desenvolvimento; a cópia do navegador não está congelada. Importar a configuração de `#build/i18n.strategy.mjs` fornece os valores do build sem substituições.

## Locales desativados e ficheiros estáticos {#disabled-locales-and-static-files}

Um locale desativado em tempo de execução responde com 404 nas suas rotas e na sua rota de payload, mas os seus ficheiros de payload continuam em `.output/public/_locales/` e um servidor de ficheiros estáticos devolve-os. Quando esses ficheiros não devem estar acessíveis, desative o locale em tempo de build com `disabled: true`.
