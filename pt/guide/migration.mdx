Esta página faz a correspondência de uma aplicação `@nuxtjs/i18n` para o nuxt-i18n-micro: opções, helpers e estrutura de ficheiros. Utilize-a quando trocar o módulo numa aplicação existente. Mantém os seus URLs (os nomes das estratégias são os mesmos) e move as traduções para ficheiros JSON por página.

<Tip>

**Está a atualizar o próprio nuxt-i18n-micro?** — Consulte [Atualização](/pt/guide/upgrade).

</Tip>

## Trocar o módulo {#swap-the-module}

```bash
npm uninstall @nuxtjs/i18n
npm install nuxt-i18n-micro
```

```ts
// nuxt.config.ts — before
export default defineNuxtConfig({
  modules: ['@nuxtjs/i18n'],
  i18n: {
    locales: [
      { code: 'en', language: 'en-US', file: 'en.json' },
      { code: 'de', language: 'de-DE', file: 'de.json' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    langDir: 'locales',
    detectBrowserLanguage: { useCookie: true, cookieKey: 'i18n_redirected', redirectOn: 'root' },
  },
})
```

```ts
// nuxt.config.ts — after
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    translationDir: 'locales',
    localeCookie: 'i18n_redirected',
    autoDetectPath: '/',
  },
})
```

## Opções {#options}

| `@nuxtjs/i18n` | nuxt-i18n-micro |
| --- | --- |
| `locales[].code` | `locales[].code` |
| `locales[].language` (`iso` antes da v9) | `locales[].iso` |
| `locales[].name` | `locales[].displayName` |
| `locales[].dir` | `locales[].dir` |
| `locales[].domain` | `locales[].baseUrl` (uma origem com o respetivo esquema) |
| `locales[].domainDefault` | `locales[].baseDefault` |
| `differentDomains`, `multiDomainLocales` | não são necessários: `baseUrl` por si só encaminha por host, consulte [Layers e domínios](/pt/guide/layers#multiple-domains) |
| `locales[].file` / `files`, `langDir`, `lazy` | `translationDir`; os ficheiros são encontrados pelo nome e sempre carregados por página |
| `defaultLocale`, `strategy` | mesmos nomes, mesmos quatro valores |
| `baseUrl` | `metaBaseUrl` |
| `customRoutes: 'config'` + `pages` | `globalLocaleRoutes` |
| `detectBrowserLanguage: false` | `redirects: false` (sem redirecionamentos) ou `autoDetectLanguage: false` (ignorar o cabeçalho) |
| `detectBrowserLanguage.useCookie` / `cookieKey` | `localeCookie: '<name>'` (`null` desativa o cookie) |
| `detectBrowserLanguage.redirectOn: 'root'` | `autoDetectPath: '/'` (predefinição) |
| `detectBrowserLanguage.redirectOn: 'no prefix'` | `autoDetectPath: 'no_prefix'` |
| `detectBrowserLanguage.redirectOn: 'all'` | `autoDetectPath: '*'` |
| Ficheiro de configuração `vueI18n` (`fallbackLocale`, `numberFormats`, `datetimeFormats`) | `fallbackLocale`, `numberFormats`, `datetimeFormats` em `i18n` |

Não existe `alwaysRedirect`: com um cookie definido, `/` segue-o em cada visita. A lista completa está em [Opções do módulo](/pt/api/module-options); as regras de deteção estão em [Deteção de locale](/pt/guide/locale-detection).

## Helpers e composables {#helpers-and-composables}

| `@nuxtjs/i18n` / vue-i18n | nuxt-i18n-micro (template / `useI18n()`) |
| --- | --- |
| `const { t } = useI18n()` | `const { t } = useI18n()`, `$t` nos templates |
| `t('key', count)`, `tc` | `$tc('key', count)` |
| `te('key')` | `$has('key')` |
| `n(value, 'currency')`, `d(date, 'short')` | `$tn(value, 'currency')`, `$td(date, 'short')` |
| — | `$tdr(date)`: tempo relativo ("daqui a 3 dias") |
| `locale.value` | `$getLocale()` |
| `locales.value` | `$getLocales()` |
| `setLocale('de')` | `$switchLocale('de')` |
| `useLocalePath()('about')` | `$localePath({ name: 'about' })` |
| `useLocaleRoute()` | `$localeRoute()` |
| `useSwitchLocalePath()('de')` | `$switchLocalePath('de')` |
| `useSetI18nParams()` | `$setI18nRouteParams()` |
| `useLocaleHead()` | automático com `meta: true`; [`useLocaleHead`](/pt/composables/useLocaleHead) para heads personalizados |
| `defineI18nRoute({ paths: { de: '/ueber-uns' }, locales: [...] })` | `$defineI18nRoute({ localeRoutes: { de: '/ueber-uns' }, locales: [...] })` |
| `<NuxtLinkLocale to="about">` | `<i18n-link :to="{ name: 'about' }">` |
| `<i18n-t>` | `<i18n-t>` (os slots preenchem os placeholders `{name}`) |
| `$i18n` em rotas de servidor | `useTranslationServerMiddleware(event)`, consulte [Rotas de servidor e API](/pt/guide/server-side-translations) |

`useI18n()` é importado automaticamente. `$defineI18nRoute` tem de manter o seu `$`: o build lê essa chamada. Todos os helpers: [Métodos](/pt/api/methods).

## Ficheiros de tradução {#translation-files}

Mova as chaves de um único ficheiro grande por locale para um ficheiro raiz mais um ficheiro por página:

```text
locales/
├── en.json              # keys used on many pages (nav, footer)
├── de.json
└── pages/
    ├── index/en.json    # keys of pages/index.vue
    └── about/en.json    # keys of pages/about.vue
```

Manter tudo nos ficheiros raiz também funciona e é o primeiro passo mais rápido. Defina `disablePageLocales: true` até os dividir. Consulte [Ficheiros de tradução](/pt/guide/translations).

### Sintaxe das mensagens {#message-syntax}

| vue-i18n | nuxt-i18n-micro |
| --- | --- |
| Interpolação com nome `{name}` | igual |
| `car \| cars` (2 formas: 1 → primeira) | as formas são escolhidas pela contagem a partir de 0: escreva `no cars \| one car \| {count} cars` |
| Mensagens ligadas `@:other.key` | não suportado: repita o texto ou componha no código |
| Modificadores `@.upper:` | não suportado: formate no código ou utilize `<i18n-t>` |
| Escapes literais `{'@'}` | não são necessários: apenas os tokens `{word}` são substituídos |
| Ficheiros de mensagens JS/TS | apenas JSON |

A regra de plural pode ser substituída com a opção [`plural`](/pt/api/module-options#plural).

## Verificar após a troca {#check-after-the-switch}

- Todos os URLs que tinha continuam a ser resolvidos; os nomes das estratégias coincidem e os caminhos personalizados passam para `globalLocaleRoutes` ou `$defineI18nRoute`.
- `hreflang`, canonical e `og:locale` são gerados de origem com `meta: true`; remova os que escreveu à mão.
- Um erro de parsing de JSON regista o caminho do ficheiro; uma chave em falta regista um aviso na consola do navegador em desenvolvimento.
