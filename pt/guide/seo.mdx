---

Com `meta: true` (a predefinição), cada página localizada recebe `<html lang dir>`, um link canónico, alternativas `hreflang`, `x-default` e tags de locale Open Graph. Precisa desta página quando quiser definir a origem pública, ajustar que locales aparecem nas tags ou substituí-las numa página. A maioria dos sites só precisa de um `site.url` ou `metaBaseUrl` e de códigos `iso` corretos.

## Configuração mínima {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

`/de/about` renderiza então:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Direção do texto {#text-direction}

`<html dir>` vem do `dir` do locale. Sem ele, uma língua escrita da direita para a esquerda recebe `rtl`, lido a partir de `iso` (ou `code`): árabe, hebraico, persa, urdu e algumas outras, e qualquer tag com um sistema de escrita RTL como `az-Arab`. Todos os outros locales não recebem o atributo `dir`, que os browsers interpretam como `ltr`.

<Warning>

**`dir: 'auto'` aumenta o tempo de análise em páginas grandes** — `auto` em `<html>` obriga o browser a determinar a direção a partir do conteúdo enquanto o analisa. No Chromium, esse custo cresce mais depressa do que a página: cerca de 100 ms com 5.000 elementos e 1 s com 20.000. Use-o apenas numa página pequena cuja língua não consiga saber.

</Warning>

## Que tags obtém {#which-tags-you-get}

- **hreflang**: uma tag por cada locale que serve a página, com o valor `iso` (ou `code` quando falta `iso`), e o respetivo URL com a mesma query que o canónico. Uma página restringida com [Configuração da página](/pt/guide/per-component-translations) ou `routeLocales` lista apenas os seus locales. [`hreflangBaseLanguage: true`](/pt/api/module-options#hreflangbaselanguage) adiciona também a língua base (`es-ES` → `es`) para o primeiro locale regional.
- **x-default**: o URL do locale predefinido, apenas quando o locale predefinido serve a página.
- **og:locale**: derivado de `iso` (`en-US` → `en_US`). Defina `og` no locale quando o mapeamento não é direto, por exemplo `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; sem nenhum dos dois, não é escrito nenhum `og:locale` e o modo de desenvolvimento emite um aviso.
- **canonical / og:url**: o URL atual sem parâmetros de query, exceto os que estão em [`canonicalQueryWhitelist`](/pt/api/module-options#canonicalquerywhitelist) (por omissão `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Por estratégia:

| Estratégia | hreflang e x-default | canonical, og:url, og:locale, atributos html |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | sim | sim |
| `no_prefix` | não (um único URL serve todos os locales) | sim |

## Definir a origem pública {#set-the-public-origin}

Os URLs absolutos usam o primeiro dos seguintes:

1. [`metaBaseUrl`](/pt/api/module-options#metabaseurl);
2. `site.url` do `nuxt-site-config` (instalado pelo `@nuxtjs/seo`);
3. a origem do pedido, com `app.baseURL` acrescentado.

Fixe um dos dois primeiros.

<Warning>

O fallback para a origem do pedido lê `X-Forwarded-Host` e `X-Forwarded-Proto`, porque [`metaTrustForwardedHost`](/pt/api/module-options#metatrustforwardedhost) e `metaTrustForwardedProto` são `true` por omissão. Isso só é seguro atrás de um proxy que sobrescreva esses cabeçalhos; caso contrário, um cliente pode escolher o host nos seus links canónicos, e uma cache pode servir essa página a outros.

Se a aplicação for acessível diretamente, fixe `metaBaseUrl`: ao contrário de definir ambas as opções como `false`, isso também ignora um `Host` forjado. Consulte [Atrás de um proxy ou CDN](/pt/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

O fallback é útil quando um único deployment responde a vários domínios: `https://site-a.com/en/about` e `https://site-b.com/en/about` recebem cada um a sua própria origem.

Com `baseUrl` nos locales, um host conhecido usa o seu próprio `baseUrl`, acima de `metaBaseUrl` e `site.url`, para que canonical e `og:url` fiquem nesse domínio e `hreflang` aponte cada locale para o seu domínio. Qualquer outro host usa `metaBaseUrl`, ou então o `baseUrl` do locale predefinido, ou então `site.url`, para que um `Host` falsificado não chegue às suas tags. Se nenhum deles estiver definido, mantém-se o fallback para a origem do pedido e o build emite um aviso. Consulte [Layers e domínios](/pt/guide/layers#multiple-domains).

## Excluir locales ou páginas {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Se o locale predefinido tiver `seo: false`, não é escrito nenhum `x-default`. Para desativar as tags numa página, use `disableMeta` em [Configuração da página](/pt/guide/per-component-translations#turn-off-seo-tags), ou [`routeDisableMeta`](/pt/api/module-options#routedisablemeta) na configuração.

## Substituir tags numa página {#override-tags-on-one-page}

Para conteúdo de CMS em que só existem algumas traduções, ou em que os URLs vêm de uma API, substitua as tags geradas com [`useI18nHead`](/pt/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` também pode definir ou remover `canonical`, `xDefault`, `ogLocale` e `ogUrl`; `disable` remove grupos inteiros (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Passe um getter para que os valores sejam recalculados depois de uma mudança de locale. Para slugs por locale, defina primeiro `$setI18nRouteParams` ([Caminhos localizados](/pt/guide/custom-locale-routes#per-locale-slugs)) e as alternativas geradas já os utilizam.

## Barra final {#trailing-slash}

`$localePath`, `$switchLocalePath`, o objeto de rota de `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, os redirecionamentos de locale e os URLs de SEO seguem uma única regra para a barra: `experimental.defaults.nuxtLink.trailingSlash` por omissão, ou [`trailingSlash`](/pt/api/module-options) na configuração i18n quando os caminhos i18n devem ser diferentes.

## Nuxt SEO {#nuxt-seo}

O [`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) funciona com este módulo através do `nuxt-site-config` 4+. Liste `nuxt-i18n-micro` primeiro para que a configuração do site consiga ler os locales, e defina `site.url` uma vez — também alimenta as tags acima.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

O nome e a descrição traduzidos do site vêm das chaves `nuxtSiteConfig.name` / `nuxtSiteConfig.description` nos seus ficheiros de locale. O erro `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` significa que o `@nuxtjs/seo` é anterior à versão 3; atualize-o ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
