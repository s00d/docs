---
title: "Configuração da página"
description: "Restrinja uma página a alguns locales, dê-lhe caminhos personalizados, traduções inline ou nenhuma tag de SEO com $defineI18nRoute."
---

`$defineI18nRoute` define opções de i18n para uma página a partir da própria página. Utilize-o quando uma página existe apenas em alguns locales, precisa do seu próprio caminho localizado, transporta algumas traduções próprias ou não deve receber tags hreflang/canonical. O módulo lê a chamada no momento do build e incorpora-a nas rotas geradas.

## Restringir uma página a alguns locales {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

Com a estratégia por omissão `prefix_except_default`, apenas são geradas `/product` e `/de/product`; a página não tem rota em nenhum outro locale. O mesmo pode ser definido a partir do `nuxt.config.ts` com [`routeLocales`](/pt/api/module-options#routelocales).

`$defineI18nRoute` é uma injeção da app Nuxt, não uma macro do compilador: obtenha-o sempre a partir de `useNuxtApp()` e chame-o com o `$`. Apenas `$defineI18nRoute(` é reconhecido pelo passo de build.

## Adicionar traduções inline {#add-inline-translations}

Passe um objeto em vez de um array. As suas chaves são os locales permitidos e os seus valores são fundidos no dicionário da página para o locale ativo.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

As traduções inline são incluídas no componente da página para todos os locales. Prefira [ficheiros de tradução da página](/pt/guide/translations) para tudo o que tenha mais do que algumas chaves; reserve as chaves inline para páginas e componentes autónomos.

## Definir caminhos localizados {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

Com `prefix_except_default` e `defaultLocale: 'en'` isto produz `/welcome` e `/de/willkommen`. Um `path` dentro de um objeto de locale inline faz o mesmo: `locales: { de: { path: '/willkommen' } }`. Os parâmetros dinâmicos, as rotas aninhadas e a alternativa ao nível da configuração são abordados em [Caminhos localizados](/pt/guide/custom-locale-routes).

## Desativar as tags de SEO {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

A alternativa ao nível da configuração é [`routeDisableMeta`](/pt/api/module-options#routedisablemeta). O que são estas tags está explicado na página de [SEO](/pt/guide/seo).

## O que o build consegue ler {#what-the-build-can-read}

O passo de build encontra a chamada em cada ficheiro de página e avalia o seu argumento sem executar a sua app. Funciona quando a configuração é:

- um objeto literal (strings, arrays, objetos aninhados, template literals, ternários sobre `process.env.NODE_ENV`);
- construída a partir de constantes declaradas no mesmo `<script setup>` (`const locales = ['en', 'de']`, incluindo spreads);
- um array de objetos com um campo `code` (`[{ code: 'en' }, { code: 'de' }]`).

Não consegue ler valores importados de outro módulo, nem nada que precise da sua app em runtime (composables, `await`, dados obtidos). Nesse caso, o build regista `Ignored the $defineI18nRoute() config in <file>` e a página mantém os locales e as rotas por omissão.

Em runtime, a chamada apenas funde as traduções inline para o locale atual e volta a fundi-las quando o locale muda. `locales`, `localeRoutes` e `disableMeta` só têm efeito através do build, pelo que alterá-los exige um novo build (o servidor de desenvolvimento refaz o build ao guardar).
