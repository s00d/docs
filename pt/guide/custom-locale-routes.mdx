---
title: "Caminhos localizados"
description: "Dê a uma página um URL diferente por locale com localeRoutes ou globalLocaleRoutes, incluindo parâmetros dinâmicos e slugs por locale."
---

Por omissão, cada locale serve uma página no mesmo caminho: `/en/about`, `/de/about`. Os caminhos localizados permitem que cada locale use as suas próprias palavras, como `/de/ueber-uns`, enquanto o ficheiro da página se mantém o mesmo. Defina-os na página com `$defineI18nRoute`, ou para muitas páginas de uma só vez em `nuxt.config.ts`.

## Na página {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

Com `prefix_except_default` e `defaultLocale: 'en'`, a página responde em `/about`, `/de/ueber-uns` e `/fr/a-propos`. Um locale sem entrada mantém o caminho predefinido. Escreva os caminhos sem o código do locale: o prefixo é adicionado pela [estratégia](/pt/guide/strategy), e um caminho que comece pelo código do locale regista um aviso. O que mais a chamada aceita está em [Configuração da página](/pt/guide/per-component-translations).

## No nuxt.config {#in-nuxt-config}

[`globalLocaleRoutes`](/pt/api/module-options#globallocaleroutes) faz o mesmo para qualquer página, indexado pelo respetivo caminho (ou pelo nome da rota, quando escrito sem barra inicial):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

Quando uma página define `localeRoutes` e `globalLocaleRoutes` tem a mesma chave, prevalece a entrada da configuração.

## Parâmetros dinâmicos {#dynamic-params}

Escreva os parâmetros em qualquer forma do Nuxt: `[id]`, `[[page]]`, `[...slug]` ou `:id()`. Os nomes dos parâmetros têm de corresponder aos do ficheiro da página.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

As páginas aninhadas aceitam um caminho filho absoluto (`/ueber-uns/team`) ou um caminho relativo ao caminho localizado do pai (`team`).

## Ligar a páginas localizadas {#linking-to-localized-pages}

Os links resolvem para o caminho localizado do locale de destino, quer passe um nome de rota quer um caminho simples:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

Os nomes das rotas vêm do caminho do ficheiro (`pages/about/team.vue` é `about-team`), a menos que defina um com `definePageMeta({ name })`.

## Slugs por locale {#per-locale-slugs}

Quando o próprio slug difere por locale (`/our-products/red-shoe` vs `/de/unsere-produkte/roter-schuh`), indique ao seletor de idioma que parâmetros usar com `$setI18nRouteParams` assim que os dados estiverem carregados:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

`$switchLocalePath('de')` e `<i18n-switcher>` passam então a ligar a `/de/unsere-produkte/roter-schuh`. As chaves são códigos de locale e os valores são parâmetros por nome (como no ficheiro da página).

Um seletor no layout é renderizado antes de o setup assíncrono da página chegar aqui, por isso, quando a renderização termina, o módulo reescreve os links de `<i18n-switcher>`, tanto em `app.vue` como na página. O HTML do servidor, um visitante sem JavaScript e a primeira renderização no cliente ficam assim de acordo. Para isso, defina os parâmetros durante o SSR: com `lazy` ou `server: false` os links só mudam depois da hidratação. O streaming SSR do Nuxt envia o HTML antes de os parâmetros serem conhecidos, por isso, nesse caso, os links no primeiro HTML mantêm os parâmetros do próprio URL.

Só os links do próprio seletor são reescritos. Um link `$switchLocalePath` escrito à mão tem de ser renderizado depois de os parâmetros serem definidos, por isso coloque-o na página que os define, também depois de um `await`. Num layout é renderizado primeiro: o seu HTML do servidor mantém os parâmetros do URL e a hidratação avisa sobre uma discrepância. Use aí `<i18n-switcher>`, com os seus slots e as props `custom*Style` para o aspeto.

Os parâmetros pertencem à página que os definiu:

- São descartados quando uma navegação para outro caminho é concluída, por isso cada página define os seus. Uma navegação cancelada mantém-nos.
- Obtenha `$setI18nRouteParams` a partir de `useNuxtApp()` ou `useI18n()` no `setup`, também quando o chamar mais tarde num handler de `useAsyncData`. Obtida aí, a função conhece a sua página: se o visitante já saiu, uma chamada tardia não faz nada.
- Com `keepalive`, uma página recupera os parâmetros que definiu quando o visitante regressa. `useI18nHead` faz o mesmo.

## Rotas adicionadas em pages:extend {#routes-added-in-pagesextend}

As rotas que adiciona no hook `pages:extend` não têm um ficheiro de página de onde ler `$defineI18nRoute`, e várias delas partilham frequentemente um mesmo componente wrapper. Uma rota adicionada sem `name` recebe o nome que o Nuxt daria ao seu caminho (`/a/:id()` passa a `a-id`), para que os links de idioma a alcancem, exceto se outra rota já tiver esse nome; nesse caso, dê-lhe um `name` explícito. Mantenha uma única lista e divida-a em páginas e em `globalLocaleRoutes` indexadas por nome de rota com `splitLocaleRoutes` de `@i18n-micro/utils/split-locale-routes` (adicione o pacote às suas dependências):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

Não coloque caminhos localizados em `route.meta`: seriam enviados na tabela de rotas do cliente.
