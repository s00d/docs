A opção `strategy` decide se um locale aparece no URL e para que locales. Escolha-a uma única vez, antes de publicar URLs: alterá-la mais tarde altera todos os links. O módulo gera então as rotas localizadas no momento do build, e `$localePath`, `<i18n-link>` e o seletor leem-nas.

## As quatro estratégias {#the-four-strategies}

![The /about page in en (default) and de under each strategy; the same URLs are listed in the text below](/images/diagrams/strategies.svg)

**Tipo** `Strategies` · **Por omissão** `'prefix_except_default'`

Estratégia de encaminhamento de URL para os prefixos de locale.

- `'no_prefix'` — nenhum locale no URL; o locale é guardado num cookie.
- `'prefix_except_default'` — prefixa todos os locales exceto o locale por omissão.
- `'prefix'` — prefixa sempre, incluindo o locale por omissão.
- `'prefix_and_default'` — como `prefix`, mas o locale por omissão também está acessível sem prefixo.

URLs para uma página `about` com `defaultLocale: 'en'` e os locales `en`, `de`:

| Estratégia | Inglês | Alemão | Não servido |
| --- | --- | --- | --- |
| `prefix_except_default` (por omissão) | `/about` | `/de/about` | `/en` e `/en/about` dão 404 |
| `prefix` | `/en/about` | `/de/about` | `/about` redireciona para um URL com prefixo |
| `prefix_and_default` | `/about` e `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | o locale não está no URL |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

A estratégia é fixada no build: uma substituição em runtime é ignorada com um aviso ([Substituições em runtime](/pt/guide/runtime-overrides)).

## Qual escolher {#which-one-to-choose}

- **`prefix_except_default`**: a maioria dos sites. Os URLs existentes sem prefixo continuam a funcionar para o idioma por omissão.
- **`prefix`**: todos os idiomas são iguais; `/` leva sempre a uma página inicial com prefixo.
- **`prefix_and_default`**: precisa que tanto `/en/...` como os URLs sem prefixo funcionem, por exemplo durante a migração de um para o outro. Os URLs sem prefixo nunca são redirecionados.
- **`no_prefix`**: apps protegidas por login, ou um único URL por página para todos os idiomas. O locale vem de um cookie ou de `?locale=`. Os motores de busca veem um idioma por URL, pelo que não são emitidas alternativas `hreflang`.

A forma como o locale é escolhido para um URL, e quando um visitante é redirecionado, está em [Deteção do locale](/pt/guide/locale-detection).

## Rotas geradas {#generated-routes}

No momento do build, cada página recebe os registos de rota de que a sua estratégia precisa. Cada registo transporta `meta.i18n = { name, locales }`: a página que mostra e os locales que serve. Links, trocas de locale e redirecionamentos são todos resolvidos a partir desses registos, pelo que um URL fornecido pelo módulo é sempre um que o router serve.

Os locales que partilham o caminho da página partilham um registo, `/:locale(de|fr)/about`. Um locale com o seu próprio caminho recebe o seu próprio registo, chamado `localized-<page>-<locale>`:

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

Os caminhos personalizados, as listas de locales por página e a exclusão de uma página da localização estão em [Caminhos localizados](/pt/guide/custom-locale-routes) e [Configuração da página](/pt/guide/per-component-translations). O prefixo `localized-` é [`localizedRouteNamePrefix`](/pt/api/module-options#localizedroutenameprefix).

<Warning>

**Os nomes das rotas são gerados** — Não escreva nomes `localized-…` diretamente em `router.push({ name })`. Passe o nome da própria página a `$localeRoute` ou `<i18n-link>`; estes escolhem o registo certo.

</Warning>

## Criar links para uma página num locale {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- Funcionam tanto rotas com nome como caminhos. Um caminho é comparado com as rotas geradas, pelo que é aceite a forma de qualquer locale.
- Um locale que não serve a página (ver `locales` em [Configuração da página](/pt/guide/per-component-translations)) cria um link para a página inicial desse locale em vez de uma página inexistente.
- Os parâmetros por locale (um slug traduzido) passam por `$setI18nRouteParams`; ver [Caminhos localizados](/pt/guide/custom-locale-routes).

As assinaturas estão em [Métodos](/pt/api/methods).

## Detalhes de `no_prefix` {#no_prefix-details}

- [`localeCookie`](/pt/api/module-options#localecookie) assume por omissão `'user-locale'` com `no_prefix`, pelo que a escolha sobrevive a um recarregamento.
- `$switchLocale('de')` carrega o dicionário alemão e substitui a entrada atual do histórico; o URL não muda.
- Os caminhos personalizados por locale continuam a funcionar: com `globalLocaleRoutes: { about: { de: '/ueber-uns' } }`, os leitores alemães recebem `/ueber-uns`. Esse URL é sempre renderizado em alemão, seja qual for a preferência do visitante, e uma página restrita a alguns locales é renderizada num deles. Um caminho partilhado por vários locales (`en` e `de` ambos em `/page/:id`) é renderizado na preferência quando esta é um deles. A preferência em si mantém-se: a página seguinte regressa a ela.
- [`noPrefixRedirect: true`](/pt/api/module-options#noprefixredirect) redireciona o caminho original de uma página com um caminho personalizado no locale por omissão: para o caminho personalizado do locale do visitante, ou caso contrário para o do locale por omissão (`/about` → `/about-us` quando `en` tem `/about-us`, → `/ueber-uns` com o cookie `de`). Um locale sem caminho personalizado próprio fica no caminho original e é renderizado aí. As páginas com parâmetros não são redirecionadas.

## Apps sem `pages/` {#apps-without-pages/}

Com `pages: false` não há rotas de páginas para localizar. Utilize apenas ficheiros de tradução raiz (`disablePageLocales: true`); a deteção, o cookie e `$switchLocale` continuam a funcionar. A variante `pages-false` de `test/fixtures/basic` no repositório é uma configuração funcional.
