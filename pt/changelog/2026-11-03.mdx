**Data**: 2026-11-03

**Versão**: `v4.0.0`

![v4.0.0 release](/images/4.0.0.png)

A **v4.0.0** já está disponível. O encaminhamento, o núcleo de tradução, os ficheiros de dicionário, a deteção de locale e todos os pacotes para frameworks foram reescritos. As opções, `$t`, `$localePath`, `$switchLocale`, os componentes e os composables mantêm os seus nomes. O que muda é o comportamento, e a maioria dessas alterações são bugs que desapareceram. A maioria das aplicações precisa de poucas alterações de código, mas leia as [Alterações incompatíveis](#breaking-changes) antes de atualizar: os URLs, as tags de SEO e as APIs dos pacotes para frameworks mudaram em alguns pontos. A página [Atualização](/pt/guide/upgrade) tem todos os detalhes.

## Novidades {#what’s-new}

### Um build para todos os domínios {#one-build-for-every-domain}

`locales[].baseUrl` e `baseDefault` costumavam apenas moldar as ligações. Agora também encaminham pedidos, nas quatro estratégias e em `nuxt generate`:

```ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'fr', baseUrl: 'https://example.com' },
      { code: 'de', baseUrl: 'https://example.de', baseDefault: true },
    ],
  },
})
```

- Um host serve os seus próprios locales. As ligações para o locale de outro domínio tornam-se URLs absolutos nesse domínio, e mudar para ele navega até lá.
- `trustForwardedHost` obtém o domínio a partir de `X-Forwarded-Host` atrás de um proxy que o substitui. Desativado por predefinição.
- `NUXT_I18N_DOMAIN` indica o host ao `nuxt generate`: execute-o uma vez por domínio, e cada resultado contém apenas as páginas e os dicionários desse domínio.
- Uma aplicação sem `baseUrl` não inclui nada deste código.

Consulte [Layers e domínios](/pt/guide/layers#multiple-domains) e [Implementação](/pt/guide/deployment).

### Encaminhamento em concordância com o router {#routing-that-agrees-with-the-router}

O build e o runtime já não calculam os URLs localizados separadamente. Todas as respostas vêm das rotas geradas pelo build, pelo que uma ligação, um seletor de idioma, o `hreflang` e um redirecionamento não podem apontar para uma página que não existe.

- Um locale que não serve uma página aponta para a sua página inicial, nunca para a página de outro locale.
- `hreflang` lista apenas os locales que servem a página.
- `$switchLocale` resolve para `true` ou `false`, para que saiba quando um dicionário não conseguiu ser carregado. Uma nova chamada volta a tentar.
- `$setI18nRouteParams` e `useI18nHead` definidos durante o SSR sobrevivem à hidratação. O seletor de idioma aponta para o slug traduzido, também no HTML do servidor.
- Uma navegação produz efeito quando é confirmada: uma navegação cancelada ou bloqueada não altera nada.
- O modo hash funciona com `prefix`.
- `<Greeting :locale="$getLocale()" />` num server component define o seu locale de renderização.

### Uma única deteção de locale {#one-locale-detection}

Uma única ordem em todo o lado: no servidor, no navegador, nos helpers de API do servidor e no Astro. `Accept-Language` respeita os valores `q`, a correspondência regional já não depende da ordem de `locales` e nunca cruza escritas chinesas. As substituições em tempo de execução chegam agora ao encaminhamento: `NUXT_I18N_DEFAULT_LOCALE` e `disabledLocales` em tempo de execução alteram o que é efetivamente servido. Consulte [Deteção de locale](/pt/guide/locale-detection).

### Um único dicionário em todos os modos {#one-dictionary-in-every-mode}

Os builds premerged, `mode: 'source'` e o modo de desenvolvimento costumavam divergir em muitas páginas. Agora fornecem o mesmo dicionário.

- As fusões são profundas em todos os níveis, e as cadeias de fallback (`fr` → `de` → `en`) são seguidas até ao fim.
- As edições de traduções em desenvolvimento aplicam-se no local, sem recarregar a página. As chaves removidas desaparecem, e uma edição de um ficheiro raiz chega a todas as páginas.
- `$clearCache()` recarrega a página atual e mantém o texto antigo no ecrã até o novo texto chegar.
- Um chunk falhado mantém o dicionário atual em vez de mostrar chaves em bruto.

### Ficheiros de dicionário mais pequenos {#smaller-dictionary-files}

- O ficheiro de uma página contém agora apenas o que difere da raiz do locale, em `__root/<locale>/data.json`. O navegador carrega a raiz uma vez e funde cada página sobre ela, pelo que a utilização de disco diminui e a página seguinte custa uma fração da primeira.
- Os URLs dos dicionários incluem uma versão. Um URL com o `?v=` atual é fixado durante um ano num servidor Node, e a cópia estática de um host responde com `max-age=60`. Consulte [Cabeçalhos de cache](/pt/guide/deployment#cache-headers-and-datebuild).
- Todas as páginas SSR pré-carregam os seus ficheiros de dicionário, que assim começam a ser descarregados juntamente com o HTML.
- Uma leitura falhada já não fica memorizada: o pedido seguinte volta a ler. Consulte [Quando um dicionário não pode ser lido](/pt/guide/deployment#when-a-dictionary-cannot-be-read).

### Melhor `<i18n-t>`, plurais e formatos {#better-&lt;i18n-t&gt;-plurals-and-formats}

- Os slots funcionam com `plural`, `number`, `date` e `relativeDate`, e todos os `{name}` são preenchidos, não apenas o primeiro.
- `<i18n-t>` é um único renderizador em Nuxt, Vue, React, Preact, Solid e Astro.
- Uma primeira forma que comece por `=0 ` é uma forma zero explícita, e as restantes seguem `Intl.PluralRules`: `=0 no apples | one apple | {count} apples`. Consulte [`$tc`](/pt/api/methods#$tc).
- Nova opção `timeZone`: uma mesma data de calendário no servidor e em todos os navegadores.
- `{firstName}`, `{first-name}` e `{user.name}` são placeholders válidos.
- `$tn`, `$td` e `$tdr` seguem `iso`, tal como os plurais.
- `$tdr` produz datas futuras reais: `in 3 days`, ou `tomorrow` com `numeric: 'auto'`.

### Mais seguro por predefinição {#safer-by-default}

- `<i18n-t html>` escapa os `params`. Apenas a tradução é considerada markup de confiança.
- Nenhuma ligação sai da origem por acidente: `//host`, `/\host` e valores em branco permanecem neste site.
- A cache de traduções do servidor é limitada, pelo que URLs com nomes de página inventados não conseguem fazer crescer a memória.
- Os endpoints de gravação das DevTools aceitam apenas ficheiros `.json` existentes dentro dos seus diretórios de tradução, e recusam pedidos cross-site.

### Pacotes para frameworks na versão 2.0 {#framework-packages-at-2-0}

- **React, Preact, Solid:** `I18nT` aceita uma prop `components` para rich text. Novos `useT` e `useLocaleSwitch`, e suporte para React Server Components através de `@i18n-micro/react/server` e `/client`. O Preact já não precisa de `preact/compat`.
- **Vue e VitePress:** `I18nLink` mantém `name`, `query` e `hash`, e o VitePress respeita `base`.
- **Astro:** `i18nIntegration` agrupa os seus dicionários e instala o middleware. A entrada principal não tem nenhum import `node:*`, pelo que é executada no edge. `base` funciona.
- **Node e runtime:** `fork(locale)` fornece uma instância por pedido de baixo custo, e `run(locale, fn)` em `@i18n-micro/node` limita uma instância a um pedido.
- **`@i18n-micro/types-generator`:** sem dependências de terceiros, e um plugin simples para Vite e Rollup.
- **`@i18n-micro/devtools-ui`:** atualizações em tempo real através do socket do Vite, e uma aplicação para a toolbar do Astro.

### `@i18n-micro/cli` {#@i18n-micro/cli}

A CLI vive agora no monorepo como `@i18n-micro/cli`, reescrita com 16 comandos em vez de 28 e muito menos dependências. `check` substitui `validate`, `diff` e `check-duplicates`, com `--json` e códigos de saída para CI. Quando não consegue provar que uma chave não é utilizada, `clean` não escreve nada. Consulte [CLI](/pt/guide/cli).

### Documentação {#documentation}

A documentação foi reescrita a partir do código em torno de um percurso de leitura: instalação, primeira página traduzida, ficheiros de tradução, encaminhamento, deteção e, por fim, guias por tarefa. Os URLs antigos redirecionam. A página [Atualização](/pt/guide/upgrade) lista todas as alterações em detalhe.

## Velocidade e tamanho {#speed-and-size}

- Uma renderização no servidor lê os dicionários diretamente, sem pedidos HTTP locais nem nova interpretação.
- `dir="auto"` já não é a predefinição. Os navegadores gastam muito tempo com ele em páginas grandes: com 20 000 elementos `$t`, o DOMContentLoaded no Chromium passou de cerca de 980 ms para cerca de 115 ms.
- `serverTranslationPreload` e `i18n:register` já não tornam todos os pedidos mais lentos.
- O bundle do cliente deixa de incluir `useCookie` quando nenhum cookie está configurado, e `@i18n-micro/path-strategy` tem uma fração do seu tamanho anterior.

## Alterações incompatíveis {#breaking-changes}

### Requisitos {#requirements}

- **Nuxt 3.18 ou posterior** e **Node 20 ou posterior**.
- **`@i18n-micro/test-utils`** já não é instalado com o módulo. Adicione-o manualmente se os seus testes o importarem.
- **`@i18n-micro/hmr`** foi removido: o HMR de traduções está incorporado. Remova o pacote se o tiver instalado.
- **`@i18n-micro/react`** precisa do React 18 ou posterior.
- **`nuxt-i18n-micro-cli`** é substituído por `@i18n-micro/cli`.

### Opções e configuração {#options-and-config}

- `i18n-plugin-hooks` e `i18n-plugin-define` num `dependsOn` já não esperam por nada, sem qualquer erro. Utilize `i18n-plugin-loader`.
- Os auto-imports do servidor são `useLocaleServerMiddleware`, `useTranslationServerMiddleware`, `loadTranslationsFromServer` e `detectCurrentLocale`. Os restantes deixaram de ser importados automaticamente.
- `resolveTranslationPayloadMode` e os outros helpers `resolveTranslationPayload*` foram removidos de `nuxt-i18n-micro`, juntamente com `shouldCopyTranslationPayloadsToPublic` e `shouldRegisterNitroServerAssets`. O tipo `TranslationPayloadMode` mantém-se.
- `$getI18nConfig()` já não tem `isSSG`, `hmr`, `hooks`, `noPrefixRedirect`, `routeLocales`, `routeDisableMeta` nem `globalLocaleRoutes`. As opções em si não mudaram.
- `locales[].baseUrl` encaminha agora pedidos: um locale de outro domínio devolve 404 neste host, e as ligações no mesmo host são relativas. Num build deste tipo, `$getI18nConfig().locales` contém o que o host serve, e `linkLocales` contém todos.
- `baseUrl` também define a origem em qualquer outro host: canonical e `hreflang` utilizam `metaBaseUrl` se estiver definido, caso contrário o `baseUrl` do locale predefinido, e não a origem do pedido.
- `excludePatterns` correspondem a segmentos inteiros (`'/admin'` já não corresponde a `/administrator`), os globs são ancorados, e os padrões `RegExp` chegam agora ao runtime.
- `cacheMaxSize` não definido significa no máximo 1000 entradas no servidor. `cacheTtl` conta a partir do momento em que uma entrada foi guardada, e as leituras já não o prolongam.
- Com `no_prefix`, um `localeCookie: null` explícito na configuração `i18n` mantém-se desativado.
- Com `prefix_except_default` e `prefix_and_default`, um `defaultLocale` em tempo de execução é ignorado com um aviso. Um `fallbackLocale` em tempo de execução tem de ser um locale ativo.
- `routeDisableMeta` no `nuxt.config` é respeitado, e uma entrada do `nuxt.config` prevalece sobre `$defineI18nRoute` em qualquer forma de chave.
- Num servidor em desenvolvimento, a configuração resolvida está congelada: uma escrita nela lança uma exceção.
- A entrada `locales` de um projeto prevalece sobre a de uma layer para o mesmo `code`.

### Composables e métodos `$` {#composables-and-$-methods}

- `$switchLocale` resolve para `true` ou `false`; antes não resolvia para nada. `$switchRoute` tem o tipo `Promise<void>`.
- `$localeRoute`, `$switchLocalePath` e o seletor de idioma apontam um locale que não serve uma página para a página inicial desse locale.
- `$localePath` devolve tal como está uma string com esquema `http(s):`, `mailto:` ou `tel:`, e `$localeRoute` transporta-a em `path` e `fullPath`. Não lhes passe um valor não verificado como destino de ligação. `//host` e nomes simples como `x.com` permanecem caminhos nesta origem.
- Uma ligação sem caminho permanece na página atual: `$localePath('#top')`, `'?p=2'`, `''` e `{ query }`. `'#top'` costumava ser lido a partir da raiz do site. Um `'about'` simples continua a significar `/about`.
- `$switchRoute` permanece na aplicação. Apenas o `baseUrl` próprio de um locale, `mailto:` e `tel:` saem dela.
- Uma ligação para um locale com `baseUrl` passa por `$localePath` ou `<i18n-link>`. `<NuxtLink :to="$localeRoute(x, 'fr')">` e `router.push($localeRoute(x, 'fr'))` permanecem caminhos desta aplicação. No código, utilize `navigateTo($localePath(x, 'fr'), { external: true })`.
- `$switchLocaleRoute` e os redirecionamentos seguem `trailingSlash`.
- `$setI18nRouteParams` e `useI18nHead` definidos no servidor são descartados quando uma navegação altera o caminho, incluindo de `/news/1` para `/news/4`: volte a defini-los na nova página.
- `$setI18nRouteParams` lido no setup está associado a essa página: uma chamada tardia a partir de uma página já abandonada não faz nada. Não tem setter, por isso faça stub do próprio `useI18n` nos testes.
- `useI18n()` devolve um único objeto por aplicação. Escrever nele afeta todos os chamadores.
- O dicionário, o locale, os parâmetros e o head mudam quando uma navegação é confirmada. Um `beforeResolve`, um `beforeRouteEnter` ou um guard global posterior vê os antigos. O middleware de rota não é afetado.
- `$switchLocale` restaura o locale guardado quando a sua navegação é cancelada, nas estratégias baseadas em URL.
- `$t` interpola um `defaultValue`: `$t('missing', { n: 1 }, 'Got {n}')` produz `Got 1`. `$tc` também o faz e, perante uma tradução vazia, responde `''`.
- `$has(key, route)` respeita a rota.
- `$clearCache()` recarrega o dicionário da página atual.
- Um placeholder `{param}` lê apenas os parâmetros que passar: `{constructor}` fica tal como está escrito.
- `$tc` com uma contagem negativa, fracionária ou enorme utiliza a última forma com a contagem real. `{ count: null }` já não lança exceção, e uma chave de plural em falta chega ao handler de chaves em falta.
- `$tdr` produz `Invalid Date` para uma entrada inválida. Menos de um segundo no passado é `0 seconds ago`.
- `$tn`, `$td` e `$tdr` seguem `iso`: `{ code: 'en', iso: 'en-GB' }` formata as datas como `31/10/2026`. Um código que o `Intl` não conhece é formatado como `en`, e os plurais pela regra de índice: defina `iso` (`{ code: 'ua', iso: 'uk-UA' }`).
- `detectCurrentLocale` está obsoleto: utilize `useLocaleServerMiddleware(event).current`.

### Plurais {#plurals}

Os templates mantêm o seu significado, com uma exceção. Uma forma zero sem placeholder, seguida de uma forma por categoria, com `{count}` em cada forma partilhada por várias contagens, passa agora a ser escolhida por categoria em locales com três ou mais categorias (`ru`, `uk`, `pl`, `cs`, `ar` e outros): `none | {count} one | {count} few | {count} many` produz `3 few` e `21 one` em `uk`. Para utilizar categorias em qualquer outro template, acrescente o marcador `=0 `. Uma regra `plural` personalizada lê o valor em bruto, pelo que um template marcado lhe chega com `=0 ` no lugar. Consulte [a tabela em Atualização](/pt/guide/upgrade#plurals-and-formatting).

### Componentes {#components}

**`<i18n-t>`**

- `html` escapa os `params` em todos os casos e ignora todos os slots.
- Um slot prevalece sobre um parâmetro com o mesmo nome.
- `null` significa não definido para `plural`, `number`, `date` e `relativeDate`.
- `plural` conta como `$tc`, com `Number`: `1.5` mantém-se `1.5`, `"2 items"` é `NaN`, `""` é `0`.
- `number`, `date` e `relativeDate` mantêm os `params`.
- `hideIfEmpty` aplica-se em todos os ramos, e `defaultValue` substitui uma chave em falta em todos os ramos.
- Uma chave em falta com `html` é texto escapado.
- O resultado de `date` e `relativeDate` inclui `data-allow-mismatch="text"` e, ao lado de um slot com nome, o texto fica no seu próprio `<span>`.
- Os atributos `.innerHTML` e `textContent` são descartados.
- É um componente funcional: um `ref` sobre ele não fornece instância.
- `<i18n-t>` e `<i18n-group>` leem o dicionário ativo, tal como `$t`.

**`<i18n-switcher>`**

- Uma ligação é um `<a>` simples que chama `$switchLocale`, pelo que as classes `router-link-active` desapareceram.
- O botão é `type="button"` com `aria-expanded`. Escape e um clique fora fecham o menu suspenso.
- Novas classes `i18n-switcher-wrapper`, `i18n-switcher-dropdown` e `i18n-switcher-button`. Cada ligação tem `lang`, e `dir` quando o locale o define.
- Os estilos predefinidos utilizam propriedades CSS lógicas, e o menu suspenso tem um `z-index` maior, uma largura mínima e uma sombra.
- O servidor reescreve as suas ligações quando a renderização termina, em páginas com parâmetros. Uma ligação `$switchLocalePath` escrita à mão não é reescrita.

**`<i18n-link>`**

- `https://`, `mailto:` e `tel:` correspondem independentemente de maiúsculas e minúsculas. Um `report.pdf` simples é uma rota, e `example.com` continua a ser externo. Uma terminação de ficheiro que também seja um TLD (`example.md`) conta como ficheiro: escreva `https://`.
- `activeStyle` ignora uma barra final, a query e o hash.

### Hooks e tipos {#hooks-and-types}

- `i18n:register` é um hook de runtime: `nuxtApp.hook('i18n:register', …)` num plugin.
- O tipo exportado `ModuleHooks` passa a chamar-se `ModuleRuntimeHooks`.
- `i18n:beforeLocaleSwitch` e `i18n:afterLocaleSwitch` nunca foram emitidos e deixaram de ser documentados.
- `ModuleOptionsExtend.isSSG` é opcional e está obsoleto: nada o define.

### URLs e redirecionamentos {#urls-and-redirects}

- **`/en` e `/en/...` devolvem 404** com `prefix_except_default`, sendo `en` o predefinido.
- **Um prefixo de locale com outras maiúsculas/minúsculas ou outra grafia devolve 404** (`/DE/about`). O mesmo acontece com `/DE/x` sob `[...slug]` e `/DE` ao lado de `[slug]`, pelo que um slug de CMS igual a um código de locale com outras maiúsculas/minúsculas perde a sua página.
- **Um URL desconhecido continua a devolver 404** com `autoDetectPath: '*'` ou `'no_prefix'`. `prefix` mantém o redirecionamento, tal como `/` em todo o lado.
- **O caminho personalizado de outro locale, sem prefixo,** é um `302` para o URL do locale predefinido com `prefix_except_default`. Com `prefix`, o redirecionamento chega agora a uma página existente. `prefix_and_default` continua a devolver 404.
- **`prefix` com `redirects: false`** responde 404 a um URL sem prefixo, incluindo o URL original de uma página com um caminho predefinido personalizado.
- **`autoDetectPath: '*'`** aplica o cookie e o `Accept-Language` também a caminhos sem prefixo.
- **Com `prefix`**, um URL sem prefixo mantém o locale do visitante, em todos os caminhos, independentemente do que `autoDetectPath` indique.
- **Com `prefix_and_default`**, um URL sem prefixo corresponde ao locale predefinido.
- **Com `no_prefix`**, um caminho personalizado renderiza o seu próprio locale, uma página restrita é renderizada num locale que serve, e os locales que partilham um caminho partilham um único registo.
- **Um redirecionamento de `routeRules` sem página** não é localizado: `/de/old` devolve 404; antes era um 200 vazio.
- **As regras de rota chegam aos caminhos personalizados,** e também são copiadas com `no_prefix`. Um irmão estático como `/de/artikel/news` corresponde a `/de/artikel/:slug`.
- **Um locale com `disabled: true`** responde de imediato 404 no seu prefixo, e as ligações para ele permanecem na página.
- **Um caminho de página com outras maiúsculas/minúsculas** é um `302` para a sua própria grafia: `/T/BASIC` vai para `/t/basic`.
- **O URL original de uma página com um caminho predefinido personalizado** é um `302` para esse caminho com `prefix_except_default`. Antes era um 404.
- **`noPrefixRedirect`** baseia-se no locale do visitante: com o cookie `de`, `/about` vai para `/ueber-uns`, e não para o caminho do locale predefinido.
- **O próprio prefixo de um host** devolve 404 no seu host `baseDefault` com `prefix_except_default`: `/de/x` no host `de` era um 200.
- **`customRegexMatcher`** já não devolve 404 para uma página real cujo primeiro segmento se pareça com um locale.
- **`nuxi generate`** pré-renderiza todas as páginas estáticas em cada locale que as serve, a menos que uma regra de rota defina `prerender: false`: mais ficheiros no resultado. Com `baseUrl`, execute-o uma vez por domínio com `NUXT_I18N_DOMAIN`.
- **Um redirecionamento no cliente mantém o modo da sua navegação:** um `<NuxtLink>` simples acrescenta uma entrada ao histórico.
- **Os nomes das rotas localizadas são consistentes.** Apenas é afetado o código que fixa nomes `localized-…` em `router.push({ name })`: passe o próprio nome da página a `$localeRoute`.
- **As páginas sem nome provenientes de `extendPages`** são localizadas e recebem um nome.
- **Com `prefix`, uma ligação para outro domínio** mantém o prefixo do locale.
- **A página inicial de um domínio** é escrita sem barra final em todo o lado.
- **`?locale=`** só conta nas páginas com `no_prefix`. `/about?locale=de` já não renderiza alemão com `lang="en"`.
- **O `setLocale('de')` de um plugin** em `/en/...` já não carrega o dicionário `de`.

### SEO e resultado HTML {#seo-and-html-output}

- `dir="auto"` já não é a predefinição. Uma língua RTL conhecida recebe `dir="rtl"`, e qualquer outro locale sem `dir` não recebe atributo. Para manter o resultado antigo, defina `dir: 'auto'`, com um custo de interpretação em páginas grandes. Consulte [Direção do texto](/pt/guide/seo#text-direction).
- `disableMeta` funciona agora: a página não tem `hreflang`, canonical nem `og:locale`. `lang` e `dir` mantêm-se.
- `hreflang` lista apenas os locales que servem a página. `x-default` só aparece quando o locale predefinido a serve.
- Uma página não localizada não tem `hreflang` nem `og:locale:alternate`.
- As páginas 404 incluem `<html lang dir>` no locale do URL, e nenhum canonical nem `hreflang`.
- Canonical, `og:url` e `hreflang` mantêm uma query da lista de permissões (`/about?page=2`), também no servidor.
- Canonical e `hreflang` incluem `app.baseURL` quando a origem vem do pedido.
- Todas as páginas SSR têm `<link rel="preload" as="fetch" crossorigin="anonymous">` para os seus ficheiros de dicionário, incluindo as páginas 404. Permita-o numa CSP restritiva. Com `apiBaseClientHost`, esse host precisa de CORS.
- `Vary` é definido em todas as páginas com `no_prefix`, e nos redirecionamentos de locale das outras estratégias. Verifique a chave de cache da sua CDN.
- O cookie de locale só é escrito por uma página servida.

### Deteção e servidor {#detection-and-server}

- `Accept-Language` respeita os valores `q`, e `q=0` exclui uma língua.
- `useLocaleServerMiddleware` e `useTranslationServerMiddleware` utilizam uma única ordem em todas as rotas (`?locale`, parâmetro `[locale]` ou prefixo, cookie, cabeçalho, predefinição), respeitam `localeCookie: null` e `autoDetectLanguage: false`, e guardam em cache um dicionário por locale.
- Um cookie de locale malformado é ignorado e deixado como está, em vez de fazer falhar o SSR.
- O modo hash lê apenas o cookie `hash-locale`. Um `user-locale=de` isolado já não conta.
- `NUXT_I18N_DEFAULT_LOCALE` e `disabledLocales` em tempo de execução alteram o encaminhamento.
- **O resultado `premerged` mudou.** `/{apiBaseUrl}/<page>/<locale>/data.json` contém apenas o que difere de `__root/<locale>/data.json`. Tudo o que lê esses ficheiros diretamente tem de fundir os dois. Um dicionário completo continua a ser um ficheiro válido.
- **Os dicionários seguem `app.cdnURL`.** O navegador obtém-nos a partir de `<cdnURL>/_locales/...`, onde antes utilizava `app.baseURL`. A CDN tem de conter `_locales/` e permitir a origem do seu site. Consulte [App baseURL e hosts de payload](/pt/guide/deployment#app-baseurl-and-payload-hosts).
- Não há cache de rotas do Nitro em `/{apiBaseUrl}/**`, e o cabeçalho `s-maxage=60, stale-while-revalidate` desapareceu. Se dependia dessa cache, coloque uma CDN à frente da rota de payload.
- `/{apiBaseUrl}/<page without a folder>/<locale>/data.json` responde com o dicionário raiz; antes era `{}`. Um 404 de um host passa agora como 404, onde antes respondia `200 {}`.
- Uma pré-renderização que não consegue carregar o seu dicionário falha com um 500 e um aviso e, com o `failOnError` predefinido do Nuxt, o build termina com 1.
- Uma tradução alterada sem novo build só chega a um navegador quando `v` muda: defina `NUXT_I18N_DATE_BUILD`.
- O SSR já não pede `/{apiBaseUrl}` por HTTP, a menos que `apiBaseServerHost` esteja definido.

### Traduções {#translations}

- As fusões são profundas em todos os níveis, e as cadeias de fallback são seguidas até ao fim.
- A fusão é feita por locale: o ficheiro raiz do locale ativo prevalece sobre o ficheiro de página de um locale de fallback.
- Uma página sem a sua própria pasta `pages/<name>/` lê o dicionário raiz em produção. Antes recebia `{}`.
- `disablePageLocales: true` lê apenas os ficheiros raiz.
- As chaves da página que se abandona deixam de ser resolvidas após a navegação. Se um layout utilizava chaves que apenas o ficheiro da página anterior tinha, mova-as para o ficheiro raiz.
- Um ficheiro de locale danificado emite um único aviso com o seu caminho em todos os modos. Em desenvolvimento costumava lançar uma exceção.

### Pacotes `@i18n-micro/*` {#@i18n-micro/*-packages}

Todos os pacotes `@i18n-micro/*` estão na versão 2.0.0, incluindo `@i18n-micro/types` e o novo `@i18n-micro/cli`.

**`@i18n-micro/react`, `preact`, `solid`**

- Os adaptadores de router passaram para `/router`: `createReactRouterAdapter`, `createSolidRouterAdapter` e o `createBrowserHistoryAdapter` do Preact. `createPreactRouterAdapter` foi removido.
- `I18nT` segue o `<i18n-t>` acima. Os atributos `dangerouslySetInnerHTML`, `innerHTML` e `textContent` são descartados.
- `I18nSwitcher` renderiza itens `<a href>` com `aria-current="page"`, `▾`, CSS lógico e `language-switcher` no botão. Sem `aria-haspopup`. `className` acrescenta a `i18n-switcher-wrapper`.
- Uma ligação para `/` ou para a raiz de um locale só fica ativa com uma correspondência exata (React, Preact).
- `I18nLink` mantém um `onClick` e um `style` do utilizador, e deixa um clique com teclas modificadoras ao navegador. A query e o hash não contam para a verificação de ligação ativa. Sem router, nenhuma ligação fica ativa.
- React e Preact: `I18nLocalesContext`, `I18nDefaultLocaleContext` e `I18nRouterContext` passam a ser um único `I18nConfigContext`. Solid: um único `I18nContext` contém `{ i18n, locales, defaultLocale, router }`.
- O `getCurrentPath` dos adaptadores inclui a query e o hash, e uma chave repetida em `getRoute().query` é um array.
- Um `I18nProvider` aninhado sem `i18n` mantém a instância exterior, e um provider sem qualquer instância lança uma exceção.
- `defaultLocale()` sem valor é `fallbackLocale`.
- Solid: `getCurrentPathAccessor` foi removido. `useI18n()` já não lança exceção sem `locales`.
- React: `use-sync-external-store` já não é uma dependência, e `react-dom` é uma dependência peer opcional.

**`@i18n-micro/vue`, `vitepress`**

- `I18nT` é um componente funcional.
- `I18nSwitcher` e `I18nLink` seguem as secções acima. `aria-haspopup` desapareceu.
- `I18nLink` e `createVueRouterAdapter` resolvem `name`, `query` e `hash`. Um `name` desconhecido lança uma exceção, tal como em `RouterLink`.
- `useLocaleHead` já não gera `//de/`. O canonical e o `hreflang` de uma página coincidem (`/de`), e os parâmetros de query da lista de permissões chegam a eles.
- `I18nRoutingStrategy.resolvePath` pode receber um objeto de localização e um caminho com query e hash. Novo `toHref` opcional.
- VitePress: as ligações, o seletor de idioma, `push` e `replace` incluem `site.base`.

**`@i18n-micro/astro`**

- `i18nIntegration` agrupa `translationDir` e instala o middleware: apague um `src/middleware.ts` que apenas copia a configuração, ou passe `middleware: false`. Um `src/middleware.ts` próprio passa `base: config.base`.
- `i18nIntegration` lança uma exceção perante `messages`, `plural`, `missingHandler` e `routingStrategy`: passe-os a `createI18n` ou `createI18nMiddleware`, com `middleware: false`. As opções que nunca fizeram nada foram retiradas do seu tipo.
- `loadTranslationsFromDir` e `loadTranslationsIntoI18n` passaram para `@i18n-micro/astro/node`, que é apenas ESM.
- `getGlobalRoutingStrategy`, `setGlobalRoutingStrategy` e `runWithRoutingStrategy` foram removidos: leia `Astro.locals.routingStrategy`.
- `clone()` passa a ser `fork()`, e a opção `_storage` desapareceu.
- As páginas dinâmicas são uma única rota: `/blog/hello` é `blog-slug`; antes era `blog-hello`. Mova `pages/blog-hello/` para `pages/blog-slug/`. Um `getRouteName` personalizado recebe o padrão como terceiro argumento.
- O URL decide o locale da página. `autoDetect` é um 302 de `/` para a página inicial do locale preferido. Nova opção `localeCookie`, e `redirectToDefault` está implementado.
- A visualização de uma página a partir de uma página da mesma origem noutro locale escreve o cookie de locale e não redireciona. As server islands e as actions nunca redirecionam e incluem `Vary: Referer`.
- `config.localeCodes` deixa de fora os locales desativados, e `prepareLocaleRewrite` responde 404 para eles.
- `getI18nProps()` sem chaves envia tudo o que `t()` consegue responder na página, com um aviso em desenvolvimento acima de 20 KB. Passe as chaves que a island utiliza.
- `useLocaleHead`: o `baseUrl` predefinido é `site`; caso contrário, relativo à raiz. As ligações e as metas incluem `id`.
- `<I18nT html>` escapa os `params`, e uma tradução vazia é renderizada vazia.
- `<I18nLink>` e `localizePath` deixam intactos os URLs externos, `#hash` e `?query`, e mantêm uma barra final.
- `<I18nSwitcher>` mantém a query e utiliza `data-i18n-switcher` em vez de ids gerados.
- `@i18n-micro/astro/client` tem apenas `translate` e `hasTranslation`: importe os adaptadores a partir de `/client/vue`, `/client/react`, `/client/preact` e `/client/svelte`. `client/vue` precisa de `vue` instalado.
- Islands: `has()` é verdadeiro para uma subárvore, `t('')` é `''`. `provideI18n` aceita um getter para acompanhar novas props.
- `getLocale` e `getDefaultLocale` lançam uma exceção sem o middleware.

**`@i18n-micro/runtime`, `node`**

- Uma escrita num locale que não seja nem o ativo nem o de fallback não notifica os subscritores.
- `addRouteTranslations(locale, route, messages, false)` substitui o chunk.
- `loadFromUrls` obtém em paralelo e não escreve nada se um falhar.
- Node: `reload()` troca os dicionários em vez de os esvaziar primeiro, e não regista mensagem de sucesso. Um diretório que desapareceu mantém os antigos.
- Node, Astro, VitePress: um único leitor de pastas de locales. Uma pasta em falta emite um aviso, um ficheiro que não seja um objeto JSON é reportado e ignorado, e as mensagens começam por `[i18n]`.

**`@i18n-micro/test-utils`**

- O mock segue as regras reais de tradução: `tc('a', 1.5)` utiliza a última forma, `td('nope')` é `Invalid Date`, `t(miss, undefined, '')` é a chave, e uma chave em falta já não é registada.
- `isolated` desapareceu de `createI18nTestContext`, e `./publish-smoke` foi removido.

**`@i18n-micro/types-generator`**

- `I18nTypesPlugin(options)` é um plugin simples para Vite e Rollup: sem `.vite()`, `.webpack()` nem `.esbuild()`. Para webpack ou esbuild, chame `generateTypes` num script.
- `getTypesString` e `generateTypes` são síncronos. `flattenKeys` e `isPlainTranslationObject` foram removidos.
- As chaves são o que `t()` lê: os caminhos de objeto são acrescentados, e os ficheiros fora da estrutura de locales são descartados.

**`@i18n-micro/devtools-ui`**

- A gravação aceita apenas um `.json` existente dentro de `translationDir`, e já não cria ficheiros. Um pedido cross-site é um 403.
- Uma gravação falhada num endpoint acessível lança uma exceção e reverte.
- `createBridge` aceita uma opção `base`. O Astro utiliza `i18nDevToolsIntegration`.

**`@i18n-micro/utils`, `core`, `path-strategy`, `route-strategy`**

Apenas para adaptadores personalizados e ferramentas.

- `utils`: os subcaminhos `./route`, `./route-pattern`, `./build`, `./payload-stats` e `./payload-config` foram removidos, juntamente com `resolveServerLocale` e `resolvePreferredLocale`: chame `resolveLocale`. `deepMergeTranslations` e `mergeRouteTranslationsWithRoot` desapareceram: utilize `deepMergeTranslationsRecursive`.
- `core`: `TranslationHelper` perde `setCache`, `getGeneration` e `lookupIn` (utilize `lookup(chunkKey, key)`). `BaseI18n` perde `ensurePinnedChunk` e `invalidatePin`. `useTranslationHelper(storage)` desapareceu: utilize `new TranslationHelper(storage)`.
- `path-strategy`: **`switchLocaleRoute(fromLocale, toLocale, route, options)` passa a ser `switchLocaleRoute(toLocale, route, options)`. Uma chamada JavaScript antiga devolve um resultado errado sem qualquer erro.** O `$switchLocaleRoute` do Nuxt não é afetado. As entradas `/prefix`, `/no-prefix`, `/prefix-except-default` e `/prefix-and-default` desapareceram, tal como `getRedirect` e `getCanonicalPath`. `RouterAdapter` precisa de `getRoutes`. `createPathStrategy` não gera URLs absolutos: utilize `new DomainPathStrategy(ctx)` quando os locales têm `baseUrl`.
- `route-strategy`: apenas são exportados `RouteGenerator`, `generateRoutes`, `Rules` e os helpers de caminhos.

## Migração {#migration}

1. Verifique os requisitos: Nuxt 3.18, Node 20 e React 18 se utilizar `@i18n-micro/react`.
2. Atualize o `nuxt-i18n-micro` e todos os pacotes `@i18n-micro/*` em conjunto. Remova `@i18n-micro/hmr`. Adicione `@i18n-micro/test-utils` como dependência de desenvolvimento se os seus testes o importarem. Substitua `nuxt-i18n-micro-cli` por `@i18n-micro/cli` e siga [a sua tabela de comandos](/pt/guide/cli#moving-from-nuxt-i18n-micro-cli).
3. Procure no seu código `switchLocaleRoute(` de `@i18n-micro/path-strategy`, `i18n-plugin-hooks`, `i18n-plugin-define`, nomes de rota `localized-`, `$getI18nConfig().globalLocaleRoutes` e as outras chaves de configuração removidas, `ModuleHooks` e `@ts-expect-error` em `i18n:register`.
4. Mova o markup dos parâmetros de `<i18n-t html>` para a tradução, e passe os dados como parâmetros.
5. Se definir `baseUrl`: reveja as ligações construídas com `$localeRoute`, defina `trustForwardedHost` atrás de um proxy, e execute `nuxi generate` uma vez por domínio com `NUXT_I18N_DOMAIN`.
6. Verifique os seus URLs em função da sua estratégia: `/en` com `prefix_except_default`, slugs de CMS semelhantes a locales, redirecionamentos de `routeRules` e `excludePatterns`.
7. Verifique a chave de cache da sua CDN quanto a `Vary`, e permita a ligação de preload numa CSP restritiva. Com `app.cdnURL`, coloque `_locales/` na CDN e permita CORS.
8. Se uma ferramenta ler diretamente os ficheiros `/_locales/...`, funda o ficheiro de página sobre `__root/<locale>/data.json`.
9. Se um guard global ler o locale ou o dicionário, confirme que pode ser executado antes de a navegação ser confirmada. Mova para o ficheiro raiz as chaves que um layout obtinha do ficheiro da página anterior.
10. Compare o resultado de um `nuxi generate` ou um crawl do sitemap antes e depois: `hreflang`, `x-default`, canonical e a lista de páginas mudam intencionalmente.
11. Atualize os imports dos pacotes para frameworks: `/router` para os adaptadores de React, Solid e Preact, `/node` para os loaders do Astro, e `I18nTypesPlugin(o)` para o plugin de tipos.
12. Para o Astro, apague um `src/middleware.ts` que apenas copia a configuração, e renomeie os dicionários do estilo `pages/blog-hello/` para o respetivo padrão.
13. Atualize os testes que fixavam `router-link-active`, `li button`, `▼` ou o comportamento antigo do mock.

Detalhes e todos os casos limite: [Atualização](/pt/guide/upgrade).

## Porque é importante {#why-it-matters}

- **Correto por construção:** as ligações, os redirecionamentos e as tags de SEO vêm das rotas que a aplicação realmente tem.
- **Uma só resposta em todo o lado:** um build, o modo source e o modo de desenvolvimento fornecem o mesmo dicionário, e todos os chamadores utilizam uma única ordem de deteção.
- **Domínios:** uma única implementação para todos os domínios de locale, sem um segundo build.
- **Predefinições mais seguras:** parâmetros escapados, caches limitadas, ligações que permanecem na sua origem.
- **Menos para distribuir:** ficheiros de dicionário mais pequenos, pacotes de encaminhamento mais pequenos e lógica partilhada num único lugar.

Para a lista completa de alterações, consulte [Atualização](/pt/guide/upgrade) e o [changelog](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
