## Nuxt I18n Micro v3.22.0 — Formatos, cache e Translation Memory {#nuxt-i18n-micro-v3-22-0-—-formats-cache-&-translation-memory}

**Data**: 2026-07-30

**Versão**: `v3.22.0`

![Lançamento v3.22.0](/images/3.22.0.png)

Anunciamos a **v3.22.0**: formatos nomeados de números/datas ao estilo do Vue I18n com uma cache de formatadores, cache de payloads de tradução compatível com CDN (impressão digital do conteúdo + `httpCacheDuration`) e uma API Translation Memory para ler e substituir o dicionário ativo em runtime.

## O que há de novo? {#what’s-new}

### `numberFormats` / `datetimeFormats` nomeados + cache de formatadores {#named-numberformats-/-datetimeformats-+-formatter-cache}

Formatos nomeados compatíveis com o Vue I18n e formatação Intl mais rápida:

- Configuração: `numberFormats` / `datetimeFormats` por locale
- API: `$tn(1000, 'currency')`, `$td(date, 'short')` (+ substituição do locale e fusão de opções)
- O `FormatService` guarda em cache `Intl.NumberFormat` / `DateTimeFormat` / `RelativeTimeFormat` por locale+opções

Consulte [Métodos — `$tn` / `$td`](/pt/api/methods#$tn) e [Opções do módulo](/pt/api/module-options#numberformats).

### `dateBuild` passa a usar por omissão uma impressão digital do conteúdo {#datebuild-defaults-to-a-content-fingerprint}

O `?v=` nos pedidos a `/_locales` usava por omissão `Date.now()`, enquanto as respostas são servidas como `immutable` durante um ano. Cada nova build invalidava, portanto, o dicionário de todos os clientes, mesmo quando nenhuma tradução tinha mudado.

O valor predefinido é agora uma impressão digital SHA-256 das fontes de tradução, pela ordem das camadas. As builds com traduções inalteradas mantêm o mesmo URL. Definir `dateBuild` explicitamente continua a ter prioridade. Consulte [Opções do módulo — `dateBuild`](/pt/api/module-options#datebuild).

### `httpCacheDuration` para os payloads de `/_locales` {#httpcacheduration-for-/_locales-payloads}

A rota integrada `/{apiBaseUrl}/:page/:locale/data.json` envia agora o cabeçalho HTTP `Cache-Control` para browsers e CDN:

- Opção: `httpCacheDuration` (segundos, predefinição `31536000` / 1 ano)
- Cabeçalho: `Cache-Control: public, max-age=…, immutable`
- Seguro com o cache-busting existente de `dateBuild` (`?v=...`); `0` desativa o cabeçalho; não é aplicado em desenvolvimento

Análogo ao `experimental.httpCacheDuration` do `@nuxtjs/i18n` v10.2.0, como cabeçalho de resposta explícito.

### Payloads públicos comprimidos {#compressed-public-payloads}

O `nitro.compressPublicAssets` abrange agora os payloads de tradução copiados para o diretório público (`.gz` + `.br`). O Nitro comprime os recursos públicos antes de a cópia acontecer, pelo que anteriormente os payloads eram a única parte não comprimida de uma build estática — 6,65 MB em bruto contra 1,01 MB em gzip no índice do playground. O módulo continua a nunca ativar a compressão por si só. Consulte [Desempenho](/pt/guide/performance#payload-size).

### `resolveTranslations()` e `setTranslation(key, value)` {#resolvetranslations-and-settranslationkey-value}

Helpers de runtime para ler e substituir em memória o dicionário de tradução ativo:

- **`resolveTranslations()`** devolve a árvore completa a partir da qual `$t()` lê para o locale e a rota ativos — útil para DevTools, testes e editores em runtime. Quando uma segunda camada está ativa (locale de fallback ou hot-reload de transição de página do Nuxt), o dump mantém a forma aninhada através de `mergeTranslationLayers` e só usa chaves planas com pontos para colisões entre escalares e objetos que uma única árvore não consegue exprimir de outra forma.
- **`setTranslation(key, value)`** substitui o valor numa chave (de nível superior, caminho com pontos, objeto, string ou escalar). Trata-se de uma **substituição**, não de uma fusão; utilize `$mergeTranslations` quando os irmãos devem ser preservados.
- Disponível em `useI18n()`, `useNuxtApp()` e nas instâncias i18n das frameworks herdadas de `@i18n-micro/core`.
- O `@i18n-micro/test-utils` acrescenta os helpers correspondentes `resolveTranslations` / `setTranslation` para testes unitários.

### `getAllTranslations()` removido do pacote Vue {#getalltranslations-removed-from-vue-package}

Utilize `resolveTranslations()` para a árvore de pesquisa ativa. Para um dump completo do armazenamento em Vue, utilize `getStorage()` ou `getRouteCache()`.

## Alterações incompatíveis {#breaking-changes}

Nada na superfície pública de configuração exige alterações no código da aplicação para uma utilização típica. Estes pontos são relevantes se acedeu aos detalhes internos do runtime:

- **O payload SSR passou de `useState('i18n-ssr-chunks')` para `nuxtApp.payload.data['i18n-ssr-chunks']`.** Continua a transportar **chunks de tradução completos** para cada `(locale, route)` carregado durante o SSR — os mesmos dicionários de antes, num espaço que o Nuxt pode externalizar para `_payload.json` no prerender. `useState('i18n-ssr-chunks')` passa a não devolver nada. Ler traduções dessa forma nunca foi suportado, mas estava descrito na documentação da API de cache, por isso é aqui assinalado.
- **`NuxtTranslationLoaderOptions` expõe `setSsrChunk`.** O loader escreve cada chunk fundido em `payload.data` no servidor à medida que carrega. `getSsrChunks` não é utilizado.
- **`nitro.compressPublicAssets` emite agora `.gz` / `.br` ao lado dos payloads copiados.** Espere mais ficheiros no output público se o tinha ativado. As ferramentas de deploy que enumeram o diretório de traduções poderão ter de os ter em conta.
- **Os URLs dos payloads mudam uma vez na atualização**, porque `?v=` passa de um timestamp de build para uma impressão digital do conteúdo. Os clientes voltam a descarregar o dicionário no primeiro pedido após a atualização e depois mantêm-no nos deploys seguintes — que é precisamente o objetivo.
- **`getAllTranslations()` removido de `@i18n-micro/vue`.** Utilize `resolveTranslations()` / `getStorage()` / `getRouteCache()` em alternativa.

## Correções de erros {#bug-fixes}

- **`<i18n-switcher>`** — omite do menu pendente os locales com `disabled: true`. `$getLocales()` continua a devolver a lista completa para o seu próprio código, enquanto o output SEO/meta integrado exclui os locales desativados.
- **Estilos do switcher** — `cursor: not-allowed` aplica-se ao locale **atual** através de `activeLinkStyle` / `customActiveLinkStyle`; foi reposto `customDisabledLinkStyle` para retrocompatibilidade, aplicado ao botão do switcher quando o locale atual tem `disabled: true`.
- **HMR em desenvolvimento** — uma escrita que deixa o conteúdo do ficheiro inalterado (gravação ao perder o foco no editor, reescrita do formatador) já não desencadeia uma nova fusão. As alterações ao locale raiz reconstroem todas as páginas desse locale, pelo que era um custo elevado para uma operação nula.
- **HMR em desenvolvimento** — as páginas são fundidas de novo em simultâneo numa alteração ao locale raiz, em vez de uma após a outra.
- **Transições de página** — a navegação no mesmo locale mantém o chunk de saída como camada de fallthrough até `page:transition:finish`, em vez de uma fusão profunda dispendiosa em cada navegação.

## Porque é importante {#why-it-matters}

- Formatação ao estilo do Vue I18n sem recorrer a uma stack mais pesada.
- URLs de tradução compatíveis com CDN que se mantêm estáveis entre builds quando o dicionário não mudou.
- Uma API de runtime suportada para inspecionar e corrigir o dicionário ativo — DevTools, testes e editores já não precisam de helpers privados.

O changelog completo será publicado com o lançamento no [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).

## Correção: ciclo de redirecionamento infinito com `app.baseURL` + `strategy: 'prefix'` (#234) {#fix-infinite-redirect-loop-with-app-baseurl-+-strategy-‘prefix’-#234}

**Data**: 2026-07-03

O plugin de redirecionamento do lado do servidor (`06.redirect.ts`) remove agora `runtimeConfig.app.baseURL` de `getRequestURL(event).pathname` antes da deteção do locale. Corrige `ERR_TOO_MANY_REDIRECTS` quando a aplicação é servida num subcaminho (por exemplo, `/examples` → `/examples/ja` uma vez, e não `/examples/ja/examples/ja/...`).
