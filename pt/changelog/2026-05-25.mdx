**Data**: 2026-05-25

**Versão**: `v3.19.0`

![v3.19.0 release](/images/3.19.0.png)

Esta versão centra-se na **modularização dos utilitários internos**, na adição de um **modo de payload compacto para serverless** e na **reutilização de lógica partilhada** entre Nuxt, Node, Astro e DevTools — sem alterar a API pública do módulo para as aplicações típicas.

## O que há de novo? {#what’s-new}

### `@i18n-micro/utils` — Utilitários independentes de framework {#@i18n-micro/utils-—-framework-agnostic-utilities}

A lógica partilhada que antes estava dispersa por `src/runtime/utils/` e `src/module.ts` vive agora num pacote de workspace dedicado, com **imports granulares por subcaminho** (sem barrel volumoso, compatível com tree-shaking):

- **Build** — `preMergeLocales`, `buildTranslationSourceLayers` (`@i18n-micro/utils/build`)
- **Payloads** — resolução de `translationPayloads`, construção de URLs, helpers de fetch, estatísticas (`payload-config`, `payload-url`, `payload-fetch`, `payload-stats`)
- **Modo source** — cadeias de fallback, caminhos dos ficheiros source, fusão em runtime (`merge-source`, `source-loader`)
- **Helpers de runtime** — resolução de locale, cookies, análise de Accept-Language, helpers de rotas/meta (`resolve-locale`, `accept-language`, `cookie`, `route`, `route-pattern`, `runtime-config`)
- **Caminhos FS partilhados** — classificação de ficheiros de tradução, caminhos de páginas aninhadas (`parse-path`)

O módulo Nuxt mantém uma camada fina de ligação em `src/runtime/` e importa apenas os subcaminhos de que precisa.

### `@i18n-micro/hmr` — Hot reload de traduções em desenvolvimento {#@i18n-micro/hmr-—-dev-translation-hot-reload}

O HMR de desenvolvimento foi extraído para `@i18n-micro/hmr`:

- **`watcher`** — tratamento de alterações de ficheiros, invalidação de cache, fusão source/premerged em desenvolvimento
- **`generate-plugin`** — geração do plugin HMR do lado do cliente
- **`cache-keys`** — chaves `Symbol.for` partilhadas para as caches do servidor/armazenamento

Funciona tanto com `translationPayloads.mode: 'premerged'` como com `'source'`.

### `translationPayloads.mode: 'source'` — Deployments serverless compactos {#translationpayloads-mode-‘source’-—-compact-serverless-deployments}

Novo modo de payload para grandes matrizes de locales em plataformas serverless (Cloudflare Workers, etc.):

```typescript
export default defineNuxtConfig({
  i18n: {
    translationPayloads: {
      mode: 'source',
    },
  },
})
```

- Inclui **ficheiros source compactos** nos assets do Nitro em vez de uma matriz completa pré-fundida
- Funde as cadeias de locales raiz, de página e de fallback **em runtime** através da rota integrada `/_locales/:page/:locale/data.json`
- Define por omissão `publicAssets` e `prerenderRoutes` como `false` — ideal quando depende de um runtime Nitro/edge em vez de alojamento puramente estático

Consulte [Deployment — serverless e Edge](/pt/guide/deployment#serverless-and-edge) e [Arquitetura de cache e armazenamento](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api).

### Utilitários partilhados entre pacotes de integração {#shared-utilities-across-integration-packages}

- **`@i18n-micro/node`** e **`@i18n-micro/astro`** — análise de caminhos de tradução e deep merge unificados através de `@i18n-micro/utils/parse-path`
- **`@i18n-micro/astro`** — `detectLocaleFromAcceptLanguage` a partir de `@i18n-micro/utils/accept-language` (parser duplicado removido)
- **`@i18n-micro/devtools-ui`** — caminhos de ficheiros virtuais através dos helpers `merge-source` + `parse-path`
- **Deteção de locale no servidor** — tratamento de Accept-Language alinhado com os utilitários partilhados

### Correções de HMR e DevTools {#hmr-&-devtools-fixes}

- O plugin HMR do cliente chama agora **`$loadPageTranslations`** (a API correta) em vez do removido `$loadTranslations`
- Cobertura Playwright para o watcher de traduções nos modos **premerged** e **source**

## Alterações incompatíveis (avançado / interno) {#breaking-changes-advanced-/-internal}

Afetam apenas projetos que importavam caminhos **internos** do módulo (que não fazem parte da API pública):

- Removidos de `src/runtime/utils/`: `route-utils.ts`, `runtime-i18n-config.ts` e outros utilitários movidos para `@i18n-micro/utils/*`
- Removidos de `src/runtime/server/plugins/`: o watcher/gerador HMR inline — use `@i18n-micro/hmr/*` se tiver feito fork das ferramentas de desenvolvimento
- **`nuxt-i18n-micro`** depende agora dos pacotes de workspace `@i18n-micro/utils` e `@i18n-micro/hmr` (instalados automaticamente com o módulo)

A utilização típica de `nuxt.config` + composables não se altera.

## Porque é importante {#why-it-matters}

- **Bundles serverless mais pequenos** — o modo `source` evita incluir um ficheiro pré-fundido por locale × página
- **Fonte única de verdade** — uma única implementação para análise de caminhos, fusão, deteção de locale e configuração de payloads
- **Manutenção mais fácil** — o código independente de framework é testado em `@i18n-micro/utils` (mais de 50 testes unitários) e reutilizado em todo o lado
- **Melhor experiência de desenvolvimento** — a lógica de HMR está isolada, é testável e é consistente entre modos de payload
