**Data**: 2026-06-25

**Versão**: `v3.21.0`

![v3.21.0 release](/images/3.21.0.png)

Esta versão adiciona o **`useI18nHead`** — um composable ao nível da página para substituições de SEO de i18n sobre o plugin `02.meta` incorporado. Personalize `hreflang`, canonical, `og:url` e as etiquetas Open Graph por rota, sem um plugin de meta personalizado nem `meta: false`.

## O que há de novo? {#what’s-new}

### Composable `useI18nHead` {#usei18nhead-composable}

Chame `useI18nHead` em qualquer página quando `meta: true` (por omissão). O módulo funde os seus dados depois de `useLocaleHead` em cada atualização de rota:

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

Suporta objetos estáticos, getters reativos, acréscimo de `meta` / `link`, `replace` para os grupos incorporados e `disable` para remover etiquetas geradas automaticamente. Consulte [`useI18nHead`](/pt/composables/useI18nHead).

### Utilitário `mergeI18nHead` (`@i18n-micro/utils`) {#mergei18nhead-utility-@i18n-micro/utils}

A lógica de fusão independente de framework está em `@i18n-micro/utils/merge-i18n-head` — usada pelo plugin `02.meta` e testável isoladamente. Os tipos (`I18nHeadInput`, `I18nHeadLink`, `I18nHeadMeta`) são exportados a partir de `@i18n-micro/types`.

### Integração com plugins {#plugin-integration}

- **`02.meta`** — funde o resultado de `useLocaleHead` com o estado da página vindo de `useI18nHead` através de `useHead`
- **`01.plugin`** — repõe as substituições da página quando o nome da rota muda, através de `resetPageHead()` (estado partilhado com o composable)

## Casos de utilização típicos {#typical-use-cases}

| Cenário                                      | Abordagem                                                      |
| -------------------------------------------- | -------------------------------------------------------------- |
| Blog/CMS com traduções parciais              | `replace.hreflang` + `replace.ogAlternates` a partir dos locales da API |
| Canonical personalizado a partir do CMS      | `replace.canonical` + `replace.ogUrl`                          |
| Apenas OG numa landing page                  | `meta: [{ property: 'og:title', ... }]` — manter o hreflang do módulo |
| Sem hreflang numa página                     | `disable: ['hreflang', 'x-default']`                           |
| Substituir um plugin personalizado (`i18nManualHreflang`) | `useI18nHead` por página de conteúdo + `meta: true` |

O **JSON-LD** permanece em `useHead({ script: [...] })` — o `useI18nHead` não gera dados estruturados.

## Alterações incompatíveis {#breaking-changes}

Nenhuma para a utilização padrão de `nuxt.config`. O novo composable e o subcaminho de utils são aditivos.

## Porque é importante {#why-it-matters}

- **Sem plugin de meta personalizado** para publicações de CMS, notícias ou guias com URLs por locale
- **Pipeline único** — predefinições do módulo + substituições da página numa só chamada a `useHead`
- **Type-safe** — `I18nHeadInput` para helpers como `buildArticleHead(content)`
