Every option documented here lives under the `i18n` key in `nuxt.config`. Types and defaults track [`ModuleOptions`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts) in `@i18n-micro/types`. Where a default is listed, it matches the source of truth exactly.

<Note>
  You rarely need to set every option. Start with `locales`, `defaultLocale`, and `strategy`, then adjust the sections below as needs come up.
</Note>

## Locales

### `locales`

**Type:** `Locale[]` &nbsp;·&nbsp; **Default:** `[]`

List of supported locales. Each entry is a `Locale` object with the following recognised fields.

| Property | Type | Notes |
| --- | --- | --- |
| `code` | `string` | BCP-47 identifier used in URLs (e.g. `en`, `de-DE`, `zh-Hans`). Required. |
| `iso` | `string` | Emitted in `<html lang>` and `hreflang` (e.g. `en-US`). |
| `og` | `string` | Value for `og:locale` / `og:locale:alternate` (e.g. `ar_AE`). Falls back to a normalised `iso` (`en-US` → `en_US`) when possible. |
| `seo` | `boolean` | Set to `false` to omit the locale from cross-locale SEO tags. When the default locale has `seo: false`, the `x-default` hreflang is not emitted. |
| `dir` | `'ltr' \| 'rtl' \| 'auto'` | Reflected in `<html dir>` when the locale is active. |
| `displayName` | `string` | Human-readable name shown in switchers. |
| `disabled` | `boolean` | Excludes the locale from route generation and switching. |
| `baseUrl` | `string` | Per-locale base URL for multi-domain setups. |
| `baseDefault` | `boolean` | Marks this locale as the base default for its `baseUrl`. |
| `fallbackLocale` | `string` | Overrides the global `fallbackLocale` for this locale only. |
| Any other key | `unknown` | Passed through to the runtime and surfaced via `$getLocales()`. |

```typescript nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl', disabled: true },
      {
        code: 'de',
        iso: 'de-DE',
        dir: 'ltr',
        baseUrl: 'https://de.example.com',
        baseDefault: true,
      },
    ],
  },
})
```

<Warning>
  Using `baseUrl` can duplicate internal routes as external links. For multi-domain deployments, prefer domain-scoped canonical URLs and be explicit about which locale owns each host.
</Warning>

#### Custom locale properties

Any extra key on a `Locale` object is preserved and available at runtime.

```typescript
locales: [
  { code: 'en', iso: 'en-US', flag: '🇬🇧', currency: 'GBP' },
  { code: 'de', iso: 'de-DE', flag: '🇩🇪', currency: 'EUR' },
]
```

Access them through `$getLocales()`:

```vue
<template>
  <ul>
    <li v-for="locale in $getLocales()" :key="locale.code">
      {{ locale.flag }} {{ locale.displayName }} ({{ locale.currency }})
    </li>
  </ul>
</template>
```

To keep these properties typed, use module augmentation:

```typescript app/i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
    currency?: string
  }
}
```

<Tip>
  `Locale` is declared as an `interface`, so TypeScript merges your declarations wherever `Locale` is referenced. The typing applies to `$getLocales()`, `useI18n()`, server middleware, and every other consumer.
</Tip>

### `defaultLocale`

**Type:** `string` &nbsp;·&nbsp; **Default:** `'en'`

Locale used when nothing else can be resolved from the URL, cookie, or `Accept-Language`. Also acts as the fallback for missing translations when `fallbackLocale` is unset.

```typescript
i18n: { defaultLocale: 'en' }
```

### `strategy`

**Type:** `'no_prefix' | 'prefix_except_default' | 'prefix' | 'prefix_and_default'` &nbsp;·&nbsp; **Default:** `'prefix_except_default'`

Controls whether and where the locale appears in URLs.

- `no_prefix`: no locale in the URL. Persisted through `localeCookie`.
- `prefix_except_default`: every locale except the default gets a prefix.
- `prefix`: every locale, including the default, gets a prefix.
- `prefix_and_default`: same as `prefix`, but the default locale is also reachable without a prefix.

See [Routing strategies](/guides/routing-strategies) for the full breakdown, redirect behaviour, and URL tables.

### `localeCookie`

**Type:** `string | null` &nbsp;·&nbsp; **Default:** `null`

Cookie name for persisting the locale across sessions. Set to `null` to disable cookie-based persistence. For the `no_prefix` strategy, the module automatically substitutes `'user-locale'` when this option is not provided.

```typescript
i18n: { localeCookie: 'user-locale' }
```

### `globalLocaleRoutes`

**Type:** `GlobalLocaleRoutes` &nbsp;·&nbsp; **Default:** `{}`

Per-route locale configuration keyed by route name. Use it to give a route different paths per locale, or to opt a route out of localisation entirely.

```typescript
i18n: {
  globalLocaleRoutes: {
    about: {
      en: '/about-us',
      fr: '/a-propos',
      de: '/ueber-uns',
    },
    unlocalized: false,
  },
}
```

<Tip>
  For routes injected via `pages:extend`, build both `pages` and `globalLocaleRoutes` from the same list. See [Custom locale routes](/guides/custom-locale-routes) for the `splitLocaleRoutes` helper.
</Tip>

### `routesLocaleLinks`

**Type:** `{ [key: string]: string }` &nbsp;·&nbsp; **Default:** `{}`

Map a route name to another route name so both routes share the same translation file.

```typescript
i18n: {
  routesLocaleLinks: {
    'products-id': 'products',
    'about-us': 'about',
  },
}
```

### `customRegexMatcher`

**Type:** `string | RegExp` &nbsp;·&nbsp; **Default:** `undefined`

Custom pattern used to match the locale segment in URLs.

<Warning>
  Every locale `code` in `locales` must match this pattern. If a code does not match, the build fails with `Nuxt-i18n-micro: Some locale codes does not match customRegexMatcher`.
</Warning>

```typescript
// Matches en, de, zh
customRegexMatcher: '[a-z]{2}'
```

### `noPrefixRedirect`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `false`

Only relevant with `strategy: 'no_prefix'`. When `true`, a request to `/en/about` is redirected to `/about`.

### `excludePatterns`

**Type:** `(string | RegExp)[]` &nbsp;·&nbsp; **Default:** `undefined`

URL patterns that bypass i18n processing entirely. Internal Nuxt paths (`/__nuxt_error` and similar) are always excluded automatically.

```typescript
i18n: {
  excludePatterns: ['/api', '/admin', /^\/internal\/.*/],
}
```

### `localizedRouteNamePrefix`

**Type:** `string` &nbsp;·&nbsp; **Default:** `'localized-'`

Prefix used internally when the module generates locale variants of your routes (for example `localized-index`). Change it if the default collides with your own route names.

## Translation files

### `translationDir`

**Type:** `string` &nbsp;·&nbsp; **Default:** `'locales'`

Directory that holds translation JSON files, resolved from the project **root**. Nuxt 4 projects that colocate assets under `app/` typically set `translationDir: 'app/locales'`.

```typescript
i18n: { translationDir: 'i18n' }
```

### `disableWatcher`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `false`

Disables the dev-mode watcher that auto-creates missing translation files. Set to `true` when you want the files to be authored strictly by hand.

### `routesLocaleLinks`

See [Locales and routing](#routeslocalelinks).

### `plural`

**Type:** `PluralFunc` &nbsp;·&nbsp; **Default:** built-in pluralization (form index by count)

Custom pluralization function called by `$tc()`. Signature: `(key, count, params, locale, getter) => string | null`. Return `null` or `undefined` to fall back to the built-in rule for that call.

<Warning>
  The function is serialised via `.toString()` into `.nuxt/i18n.plural.mjs`. It must be self-contained: no imports, no closures over outer variables. A file path string is **not** accepted.
</Warning>

```typescript nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    plural: function (key, count, _params, locale, t) {
      if (locale !== 'ru') return null
      const translation = t(key)
      if (!translation) return null

      const forms = translation.toString().split('|').map(function (s) {
        return s.trim()
      })
      const mod10 = count % 10
      const mod100 = count % 100

      let idx
      if (count === 0) idx = 0
      else if (mod10 === 1 && mod100 !== 11) idx = 1
      else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) idx = 2
      else idx = 3

      if (idx >= forms.length) idx = forms.length - 1
      return (forms[idx] || '').replace('{count}', String(count))
    },
  },
})
```

### `disablePageLocales`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `false`

When `true`, only root-level translations (`locales/{locale}.json`) are loaded. Page-specific files under `locales/pages/**` are neither generated nor loaded.

### `fallbackLocale`

**Type:** `string` &nbsp;·&nbsp; **Default:** `undefined`

Global fallback locale used when a key is missing in the active locale. When unset, missing keys resolve to the key itself.

```typescript
i18n: { fallbackLocale: 'en' }
```

### `missingWarn`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `true`

Print a console warning when a translation key is missing. Combine with `setMissingHandler()` to forward misses to your monitoring stack.

### `hmr`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `true`

Enable HMR for JSON translation files during development. Disable if you prefer full page reloads.

### `types`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `true`

Generate TypeScript declarations for `useI18n()`, `$t()`, and related helpers from your default-locale files. The generator writes `.nuxt/i18n.d.ts` during build.

## Payload delivery

### `apiBaseUrl`

**Type:** `string` &nbsp;·&nbsp; **Default:** `'_locales'`

URL segment for the translations API route. Payloads are served from `/{apiBaseUrl}/:page/:locale/data.json`. Can also be set through the `NUXT_I18N_APP_BASE_URL` environment variable.

### `apiBaseClientHost`

**Type:** `string` &nbsp;·&nbsp; **Default:** `undefined`

Overrides the host used for client-side payload fetches. Useful when the browser reaches your app through a different hostname than Nuxt sees. Env: `NUXT_I18N_APP_BASE_CLIENT_HOST`.

### `apiBaseServerHost`

**Type:** `string` &nbsp;·&nbsp; **Default:** `undefined`

Overrides the host used for server-side payload fetches. Useful for container or microservice setups where the server reaches itself through an internal address. Env: `NUXT_I18N_APP_BASE_SERVER_HOST`.

### `translationPayloads`

**Type:** `TranslationPayloadOptions`

Controls how translation payloads are emitted and served. Defaults suit an all-in-one Node deployment. Tune the sub-keys below for Edge, CDN, or static hosting.

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `mode` | `'premerged' \| 'source'` | `'premerged'` | `premerged` writes a `{page}/{locale}/data.json` matrix at build time. `source` keeps compact source files and merges at runtime, better for large Edge catalogs. |
| `serverAssets` | `boolean` | `true` | On Node, forces a public copy that SSR reads via `readFile`. On Edge, registers Nitro `serverAssets` (`assets:i18n`) without forcing a public copy. |
| `serverHandler` | `boolean` | `true` | Register the built-in Nitro handler at `/{apiBaseUrl}/:page/:locale/data.json`. Disable when payloads are served from an external CDN. |
| `publicAssets` | `boolean` | `true` in `premerged`, `false` in `source` | Copy payloads into Nitro's public output so static hosting can serve them. |
| `prerenderRoutes` | `boolean` | `false` | Opt in to Nitro-prerender of the payload routes. Usually redundant when `publicAssets` already writes them. |
| `publicDir` | `string` | `apiBaseUrl` | Public output folder relative to Nitro's public root. |
| `warnFileCount` | `number` | `500` | Emit a build warning when generated payload count exceeds this threshold. |
| `warnSizeBytes` | `number` | `10485760` (10 MB) | Emit a build warning when the total payload size exceeds this threshold. |

```typescript
i18n: {
  translationPayloads: {
    mode: 'premerged',
    serverAssets: true,
    serverHandler: true,
    publicAssets: true,
    prerenderRoutes: false,
  },
}
```

<Warning>
  With `mode: 'source'`, `publicAssets` defaults to `false`. Pure static hosting cannot load translations unless you re-enable `publicAssets`, keep `serverHandler` reachable at runtime, or point `apiBaseClientHost` / `apiBaseServerHost` at an external host that serves the same routes.
</Warning>

For a CDN-backed deployment:

```typescript
i18n: {
  apiBaseClientHost: 'https://cdn.example.com',
  apiBaseServerHost: 'https://cdn.example.com',
  translationPayloads: {
    serverHandler: false,
    publicAssets: false,
    prerenderRoutes: false,
  },
}
```

### `dateBuild`

**Type:** `string | number` &nbsp;·&nbsp; **Default:** SHA-256 fingerprint of translation sources, or `Date.now()` if none exist

Value appended as `?v=…` to payload URLs to bust caches. Set it to a git SHA or build number for deterministic, rolling deploys.

```typescript
i18n: { dateBuild: process.env.GIT_SHA ?? 'local-dev' }
```

### `httpCacheDuration`

**Type:** `number` &nbsp;·&nbsp; **Default:** `31536000` (one year)

`Cache-Control` `max-age` on `/{apiBaseUrl}/:page/:locale/data.json` responses. The full duration is only honoured when `dateBuild` busts the URL. With a stable `dateBuild` (`0` or `''`), responses become `public, max-age=0, must-revalidate` instead. Set to `0` to omit the header entirely. Not applied in development.

```typescript
i18n: {
  dateBuild: process.env.GIT_SHA ?? String(Date.now()),
  httpCacheDuration: 86400,
}
```

### `cacheMaxSize`

**Type:** `number` &nbsp;·&nbsp; **Default:** `0` (unlimited)

Maximum entries in the in-memory translation cache. `0` means no limit.

### `cacheTtl`

**Type:** `number` &nbsp;·&nbsp; **Default:** `0` (no expiry)

TTL (seconds) for cached translation entries. `0` means entries never expire.

```typescript
i18n: {
  cacheMaxSize: 1000,
  cacheTtl: 600,
}
```

## SEO and meta

### `meta`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `true`

Emit SEO meta tags automatically: `hreflang`, `canonical`, `og:url`, `og:locale`.

### `metaBaseUrl`

**Type:** `string` &nbsp;·&nbsp; **Default:** `undefined`

Base URL used for SEO tags. When unset, the module falls back to `site.url` from `nuxt-site-config` (if installed), then to the request origin (`useRequestURL().origin` on the server, `window.location.origin` on the client).

```typescript
// Prefer sharing the SEO stack origin
site: { url: 'https://example.com' }

// Or pin an override
i18n: { metaBaseUrl: 'https://example.com' }
```

### `metaTrustForwardedHost`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `true`

Trust the `X-Forwarded-Host` header when resolving the base URL. Enable when running behind a proxy that sets it. Disable if you cannot trust the header.

### `metaTrustForwardedProto`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `true`

Trust the `X-Forwarded-Proto` header when resolving the protocol. Enable behind a TLS-terminating proxy so canonical URLs use `https://`.

### `hreflangBaseLanguage`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `false`

Also emit a bare-language `hreflang` derived from each locale's `iso` (`es-ES` → also `es`). The first regional locale in `locales` claims the bare tag for its language.

### `canonicalQueryWhitelist`

**Type:** `string[]` &nbsp;·&nbsp; **Default:** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

Query parameters preserved in canonical and `og:url` meta tags. Anything outside the list is stripped from the canonical URL.

## Redirects and detection

### `redirects`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `true`

Enable locale-aware redirects. When `false`, the server-side redirect plugin still handles 404 checks and cookie synchronisation, but the client middleware is not registered. See [Routing strategies](/guides/routing-strategies#redirect-architecture) for the full flow.

### `autoDetectLanguage`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `true`

Detect the user's preferred language from the `Accept-Language` header. Acts as a fallback: a cookie value or explicit state wins.

### `autoDetectPath`

**Type:** `string` &nbsp;·&nbsp; **Default:** `'/'`

Where cookie / `Accept-Language` preference redirects may run.

- `'/'`: only on `/`. Deep links in the default locale stay reachable.
- `'no_prefix'`: only paths without a locale prefix.
- `'*'`: every path, including rewriting explicit locale prefixes (for example `/fr/about` → `/de/about`).
- Any other string: an exact path match, for example `'/welcome'`.

Prefixed strategy cleanup (`/en` → `/` under `prefix_except_default`) is never gated by this option.

## Runtime toggles

### `define`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `true`

Register the `defineI18nRoute()` macro plugin so pages can declare per-route locale metadata.

### `plugin`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `true`

Register the core i18n plugin. Provides `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()`, and other helpers.

### `hooks`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `true`

Register the hooks plugin. Provides `i18n:register`, `i18n:beforeLocaleSwitch`, and `i18n:afterLocaleSwitch` app-level hooks.

### `components`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `true`

Register `<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, and `<i18n-group>`. Set to `false` to shrink the module footprint when you do not use them.

## Formatting

### `numberFormats`

**Type:** `Record<string, Record<string, Intl.NumberFormatOptions>>`

Named number formats per locale. Enables `$tn(1000, 'currency')` style calls.

```typescript
i18n: {
  numberFormats: {
    en: { currency: { style: 'currency', currency: 'USD' } },
    de: { currency: { style: 'currency', currency: 'EUR' } },
  },
}
```

If an exact locale key is missing, the language subtag is tried (`en-US` → `en`).

### `datetimeFormats`

**Type:** `Record<string, Record<string, Intl.DateTimeFormatOptions>>`

Named datetime formats per locale. Enables `$td(date, 'short')` style calls.

```typescript
i18n: {
  datetimeFormats: {
    en: { short: { year: 'numeric', month: 'short', day: 'numeric' } },
    ja: { short: { year: 'numeric', month: 'short', day: 'numeric' } },
  },
}
```

## Development and experimental

### `debug`

**Type:** `boolean` &nbsp;·&nbsp; **Default:** `false`

Turn on verbose logging for locale detection, route generation, and translation loading.

### `experimental`

**Type:** `Record<string, unknown>`

Bucket for unstable options. Contents may change or be removed between minor versions. Most legacy `experimental.*` flags were promoted to top-level options in v3 (for example `hmr`). Only use this bucket when a release note or migration guide references a specific key.
