title: "Custom locale routes"
description: "Define per-locale URL slugs with defineI18nRoute, globalLocaleRoutes, and splitLocaleRoutes for translated pages and programmatic routes."
---

The `localeRoutes` feature lets you define different URL paths per locale for the same page, so `/en/products`, `/de/produkte`, and `/ru/tovary` can all render the same component. You can configure this per page (with `defineI18nRoute`), globally (with `globalLocaleRoutes`), or from `pages:extend` (with `splitLocaleRoutes`).

## Per-page overrides with `defineI18nRoute`

Inside a page component, retrieve `$defineI18nRoute` from `useNuxtApp()` and pass a `localeRoutes` map:

```vue pages/products.vue
<script setup lang="ts">
import { useNuxtApp } from '#imports'

const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    en: '/products',
    de: '/produkte',
    ru: '/tovary',
  },
})
</script>
```

<Info>
`$defineI18nRoute` is not a global function. In `<script setup>`, always get it from `useNuxtApp()` first.
</Info>

Without `localeRoutes`, all locales use the primary path structure. With it, the specified locales use their own paths while others fall back to the default.

## Navigation with custom routes

Because localized paths no longer match the filename, reference navigation by **route name** rather than by literal URL:

```vue
<template>
  <!-- pages/about-us.vue -->
  <NuxtLink :to="$localeRoute({ name: 'about-us' })">
    Go to About page
  </NuxtLink>

  <I18nLink :to="{ name: 'about-us' }">
    Go to About page
  </I18nLink>

  <!-- This literal only works for English -->
  <I18nLink to="/about-us">
    Go to About page
  </I18nLink>
</template>
```

### Nested page naming

Nuxt names pages after their file path by default:

- `/pages/about-us.vue` becomes `about-us`.
- `/pages/about-us/physical-stores.vue` becomes `about-us-physical-stores`.

Override the name with `definePageMeta`:

```vue pages/about-us/physical-stores.vue
<script setup>
definePageMeta({ name: 'our-stores' })
</script>
```

You can now link with `:to="{ name: 'our-stores' }"`.

## Dynamic segments and `$setI18nRouteParams`

Dynamic routes can carry different slugs per locale. Define the route shape with `localeRoutes`, then set the actual parameter values with `$setI18nRouteParams` after your data loads.

```vue pages/products/[...slug].vue
<script setup lang="ts">
import { useNuxtApp, useRoute, useFetch, createError } from '#imports'

interface Product {
  title: string
  price: string
  urlEn: string
  urlEs: string
}

const { $t, $defineI18nRoute, $setI18nRouteParams, $switchLocalePath } = useNuxtApp()

definePageMeta({ name: 'product-slug' })

const route = useRoute()
const slug = Array.isArray(route.params.slug) ? route.params.slug[0] : route.params.slug

const { data: product, error } = await useFetch<Product>(`/api/product/${slug}`)
if (error.value) {
  throw createError({
    statusCode: error.value?.statusCode,
    statusMessage: error.value?.statusMessage,
    fatal: true,
  })
}

$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    es: '/nuestros-productos/[...slug]',
  },
})

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.urlEn },
    es: { slug: product.value.urlEs },
  })
}
</script>

<template>
  <div v-if="product">
    <h1>{{ product.title }}</h1>
    <p>{{ $t('price') }}: {{ product.price }}</p>
    <a :href="$switchLocalePath('en')">English</a>
    <a :href="$switchLocalePath('es')">Español</a>
  </div>
</template>
```

<Tip>
Call `$setI18nRouteParams` after your data fetch resolves. Parameter names in the map must match your route parameter names (`slug` for `[...slug]`, `id` for `[id]`, and so on).
</Tip>

For catch-all routes (`[...slug]`), the slug value can be a string or an array. When linking from a list page, use the route name plus params:

```vue
<I18nLink :to="{ name: 'product-slug', params: { slug: product.url } }">
  {{ product.title }}
</I18nLink>
```

## Global overrides with `globalLocaleRoutes`

`globalLocaleRoutes` (module option) applies overrides to routes you did not annotate in the page itself. It is keyed by **route name**, not by file path.

```typescript nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    globalLocaleRoutes: {
      // Exclude a page from localization entirely.
      internal: false,

      // Custom per-locale paths for the "about" route.
      about: {
        en: '/about',
        de: '/uber-uns',
        fr: '/a-propos',
      },
    },
  },
})
```

<Warning>
`globalLocaleRoutes` only customizes routes that already exist in the Nuxt page table. For routes you create dynamically, pair it with `splitLocaleRoutes` (below).
</Warning>

## Programmatic routes with `splitLocaleRoutes`

Routes generated in `pages:extend` have no page component to host `defineI18nRoute()`, and several routes often share a single wrapper SFC. File-keyed scanning would collapse them onto a single entry.

Use `splitLocaleRoutes` from `@i18n-micro/utils/split-locale-routes` to project a single registry into both `pages:extend` and `i18n.globalLocaleRoutes`:

```typescript nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  {
    name: 'products_tag',
    path: '/products/:tag',
    file: '~/pages/_dynamic.vue',
    paths: { fr: '/produits/:tag', de: '/produkte/:tag' },
  },
  {
    name: 'products_category',
    path: '/products/category/:category',
    file: '~/pages/_dynamic.vue',
    paths: { fr: '/produits/categorie/:category' },
  },
  // Disable localization for a programmatic route:
  // { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false },
])

export default defineNuxtConfig({
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

Both halves stay in sync, and shared wrappers no longer overwrite each other.

<Warning>
Do **not** put localized paths in `route.meta`. They would ship in the client route table. Keep them in `globalLocaleRoutes` instead.
</Warning>

## Interaction with routing strategies

- `no_prefix`: routes served without a locale prefix. `localeRoutes` still work, but the client only ever hits the path for the active locale.
- `prefix`, `prefix_except_default`, `prefix_and_default`: the module prepends the locale prefix to the per-locale path from `localeRoutes`. For example, `de: '/produkte'` becomes `/de/produkte`.

See [routing strategies](/guides/routing-strategies) for a full comparison.

## Best practices

- Use `localeRoutes` where URL structure impacts UX or SEO. Avoid overuse for minor cosmetic differences.
- Keep route names stable, and reference them explicitly via `definePageMeta({ name: '...' })` for anything shared or nested.
- Document custom routes so team members can find the mapping when adding new locales.
