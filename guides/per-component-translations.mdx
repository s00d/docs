---
title: "Per-component translations"
description: "Attach translations, locale restrictions, and custom paths to a single Vue component with $defineI18nRoute."
---

`$defineI18nRoute` lets you declare translations, locale allow-lists, and per-locale route paths directly inside a page component. It suits reusable widgets, ad-hoc landing pages, and any component where colocated translations are easier to maintain than a matching file under `locales/pages/`.

## Getting `$defineI18nRoute`

`$defineI18nRoute` is a Nuxt app injection, not a global macro. Always destructure it from `useNuxtApp()`:

```ts
import { useNuxtApp } from '#imports'

const { $defineI18nRoute } = useNuxtApp()
```

If you have set `define: false` in [configuration](/guides/configuration#define), this injection is not registered.

## Quick start

```vue pages/welcome.vue
<template>
  <div>
    <h1>{{ $t('greeting') }}</h1>
    <p>{{ $t('farewell') }}</p>
  </div>
</template>

<script setup lang="ts">
import { useNuxtApp } from '#imports'

const { $defineI18nRoute, $t } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello', farewell: 'Goodbye' },
    fr: { greeting: 'Bonjour', farewell: 'Au revoir' },
    de: { greeting: 'Hallo', farewell: 'Auf Wiedersehen' },
  },
})
</script>
```

<Note>
  At build time, a Vite plugin scans page `.vue` files for `$defineI18nRoute(...)` and extracts the config into `i18n-route-meta.json` under the Nuxt build directory. At runtime, the same plugin still exposes `$defineI18nRoute` for HMR and inline calls.
</Note>

## Configuration shape

```typescript
interface DefineI18nRouteConfig {
  locales?: string[] | Record<LocaleCode, Translations>
  localeRoutes?: Record<LocaleCode, string>
  disableMeta?: boolean | string[]
}
```

| Parameter | Type | Purpose |
| --- | --- | --- |
| `locales` | `string[] \| Record<string, Translations>` | Locales allowed for the route, optionally with inline translations. |
| `localeRoutes` | `Record<string, string>` | Per-locale custom paths for this route. |
| `disableMeta` | `boolean \| string[]` | Disable SEO meta for all locales (`true`) or for specific codes. |

## `locales`

### Array form: restrict which locales may access the page

```typescript
$defineI18nRoute({
  locales: ['en', 'fr', 'de'],
})
```

Any locale not in the list resolves to a 404 for this route. Translations are still loaded from your `locales/` files.

### Record form: inline translations per locale

```typescript
$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello', farewell: 'Goodbye' },
    fr: { greeting: 'Bonjour', farewell: 'Au revoir' },
    de: { greeting: 'Hallo', farewell: 'Auf Wiedersehen' },
    ru: {}, // locale allowed, no inline translations
  },
})
```

Every key you provide becomes available to `$t()` on this route, in addition to any translation files that exist on disk.

## `localeRoutes`

Assign a different URL path for each locale on the same page.

```typescript
$defineI18nRoute({
  locales: ['en', 'fr', 'de', 'ru'],
  localeRoutes: {
    en: '/welcome',
    fr: '/bienvenue',
    de: '/willkommen',
    ru: '/privet',
  },
})
```

Combined with `locales`, this is a lightweight way to introduce per-locale SEO-friendly slugs without touching global config.

## `disableMeta`

Turns off automatic `hreflang`, `canonical`, `og:url`, and `og:locale` tags for the current route.

<Tabs>
  <Tab title="Disable for all locales">
    ```typescript
    $defineI18nRoute({
      locales: ['en', 'fr', 'de'],
      disableMeta: true,
    })
    ```
  </Tab>
  <Tab title="Disable for specific locales">
    ```typescript
    $defineI18nRoute({
      locales: ['en', 'fr', 'de'],
      disableMeta: ['en', 'fr'], // only en and fr skip meta tags
    })
    ```
  </Tab>
</Tabs>

## Per-locale dynamic params: `$setI18nRouteParams`

When a page has dynamic segments (`pages/articles/[slug].vue`), the same segment can hold different values in different locales: `/articles/hello-world` in English, `/fr/articles/bonjour-monde` in French. Call `$setI18nRouteParams` on setup so `<i18n-link>` and `$switchLocalePath()` know which values to use per locale.

```vue pages/articles/[slug].vue
<template>
  <article>
    <h1>{{ post.title }}</h1>
  </article>
</template>

<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: post } = await useAsyncData(() =>
  $fetch(`/api/posts/${route.params.slug}`),
)

$setI18nRouteParams({
  en: { slug: post.value.slugs.en },
  fr: { slug: post.value.slugs.fr },
  de: { slug: post.value.slugs.de },
})
</script>
```

When the user switches from `en` to `fr`, the switcher now points at `/fr/articles/bonjour-monde` rather than reusing the English slug.

## Supported configuration formats

The parser understands static and lightly dynamic JavaScript, but not full runtime evaluation.

<Tabs>
  <Tab title="Static">
    ```typescript
    $defineI18nRoute({
      locales: ['en', 'de', 'fr'],
      localeRoutes: {
        en: '/welcome',
        de: '/willkommen',
      },
    })
    ```
  </Tab>
  <Tab title="Variables">
    ```typescript
    const locales = ['en', 'de', 'fr']
    const routes = { en: '/welcome', de: '/willkommen' }

    $defineI18nRoute({
      locales,
      localeRoutes: routes,
    })
    ```
  </Tab>
  <Tab title="Template literals">
    ```typescript
    const prefix = 'api'

    $defineI18nRoute({
      locales: [`${prefix}-en`, `${prefix}-de`],
      localeRoutes: {
        [`${prefix}-en`]: '/api/welcome',
        [`${prefix}-de`]: '/api/willkommen',
      },
    })
    ```
  </Tab>
  <Tab title="Spread and conditional">
    ```typescript
    const baseLocales = ['en', 'de']
    const extra = ['fr', 'es']

    $defineI18nRoute({
      locales: [
        ...baseLocales,
        ...(process.env.NODE_ENV === 'production' ? [] : extra),
      ],
    })
    ```
  </Tab>
</Tabs>

## Not supported

The static parser cannot handle:

- `import` statements
- `async` / `await`
- Class methods
- Loops, `try` / `catch`, `switch`
- Arrow functions in the configuration values
- Generator functions

If you need any of these, generate a plain object above the `$defineI18nRoute` call and pass it in through a variable.

## Full example

```vue pages/welcome.vue
<template>
  <div class="welcome-page">
    <header>
      <h1>{{ $t('title') }}</h1>
      <p>{{ $t('subtitle') }}</p>
    </header>

    <section>
      <h2>{{ $t('features.title') }}</h2>
      <ul>
        <li v-for="feature in $t('features.list')" :key="feature">
          {{ feature }}
        </li>
      </ul>
    </section>
  </div>
</template>

<script setup lang="ts">
import { useNuxtApp } from '#imports'

const { $defineI18nRoute, $t } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: {
      title: 'Welcome to Our Platform',
      subtitle: 'The best solution for your needs',
      features: {
        title: 'Key Features',
        list: ['High Performance', 'Easy to Use', 'Scalable Architecture'],
      },
    },
    fr: {
      title: 'Bienvenue sur Notre Plateforme',
      subtitle: 'La meilleure solution pour vos besoins',
      features: {
        title: 'Fonctionnalités Clés',
        list: ['Haute Performance', 'Facile à Utiliser', 'Architecture Évolutive'],
      },
    },
    de: {
      title: 'Willkommen auf Unserer Plattform',
      subtitle: 'Die beste Lösung für Ihre Bedürfnisse',
      features: {
        title: 'Hauptfunktionen',
        list: ['Hohe Leistung', 'Einfach zu Verwenden', 'Skalierbare Architektur'],
      },
    },
  },
  localeRoutes: {
    en: '/welcome',
    fr: '/bienvenue',
    de: '/willkommen',
  },
  disableMeta: false,
})
</script>
```

## Performance notes

Embedding translations in an SFC means every locale ships with that component:

- Payload grows with every added locale.
- Translations are processed at render time, not resolved from a prefetched JSON payload.
- All locales stay in memory even when only one is active.

<Tip>
  Reserve component-level translations for reusable npm components, small landing pages, or fragments that do not fit into your route-scoped `locales/pages/` tree. For most application pages, `locales/pages/{route}/{locale}.json` is faster and easier to translate externally.
</Tip>
