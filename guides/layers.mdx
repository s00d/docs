---
title: "Nuxt layers"
description: "Compose i18n configuration and translation files across Nuxt layers, with predictable merge order for shared locales and page translations."
---

Nuxt Layers let you extend one project from another and are the recommended way to keep i18n configuration reusable across variants of the same app (admin panel, support portal, tenant-specific deployments, and so on). Nuxt I18n Micro reads the merged configuration from every layer, so you can define a base setup once and override or extend it downstream.

## How inheritance works

Extending a layer inherits its `i18n` options. Downstream layers can:

- Add locales to the `locales` array.
- Override scalar options like `defaultLocale`, `meta`, `translationDir`, or `autoDetectLanguage`.
- Provide their own translation files, which are merged with the ones inherited from the base.

## Primary configuration

The primary layer defines the shared defaults for every extending layer:

```typescript nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', iso: 'en-EN', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    autoDetectLanguage: true,
  },
})
```

## Child layers

A child layer can add locales or override defaults for a specific section:

```typescript basic/nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', iso: 'en-EN', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
    meta: true,
    translationDir: 'locales',
  },
})
```

```typescript extended/nuxt.config.ts
export default defineNuxtConfig({
  extends: '../basic',
  i18n: {
    locales: [
      { code: 'en', iso: 'en-EN', dir: 'ltr' }, // inherited from basic
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' }, // inherited from basic
      { code: 'de', iso: 'de-DE', dir: 'ltr' }, // added in this layer
    ],
    defaultLocale: 'fr',        // overrides basic
    autoDetectLanguage: false,  // overrides basic
  },
})
```

## Modular applications

Larger apps often split configuration across several layers. A common pattern is a global base plus per-section overrides (admin, support, marketing, and so on).

### Global base

```typescript nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', iso: 'en-EN', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
    meta: true,
    translationDir: 'locales',
    autoDetectLanguage: true,
  },
})
```

### Admin panel layer

```typescript admin/nuxt.config.ts
export default defineNuxtConfig({
  extends: '../nuxt.config',
  i18n: {
    locales: [
      { code: 'en', iso: 'en-EN', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'es', iso: 'es-ES', dir: 'ltr' }, // added
    ],
    defaultLocale: 'en',
    meta: false, // disable meta generation for admin
  },
})
```

### Support portal layer

```typescript support/nuxt.config.ts
export default defineNuxtConfig({
  extends: '../nuxt.config',
  i18n: {
    locales: [
      { code: 'en', iso: 'en-EN', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' }, // added
    ],
    defaultLocale: 'de',
    autoDetectLanguage: false,
  },
})
```

Each section inherits the global defaults and only overrides what it needs.

## Translation merge behavior

Translation files from every layer are merged together at build time. When both a base layer and a child layer provide the same key for the same locale, the **top layer wins**. This lets you:

- Ship a full default catalog in the base layer.
- Override single keys or entire subtrees in a child layer without duplicating the rest.

<Tip>
Do not flatten your translations into a single dump per locale in a child layer just to override one key. Keep the file structure that mirrors your pages, override the specific keys you need, and inherit everything else from the base.
</Tip>

## Best practices

- **Keep the primary layer simple.** Put the most common settings there so children only override what changes.
- **Use child layers for narrow customizations.** Do not override anything you can inherit.
- **Document each layer's purpose.** Clarity here saves debugging time when locales look wrong in a specific section.
- **Watch the `defaultLocale`.** A child layer that changes `defaultLocale` also changes redirect and canonical behavior for that section.
