Effective SEO is essential for multilingual sites. Nuxt I18n Micro handles most of it automatically when the `meta` option is enabled: your app emits the correct `<html lang>`, canonical URLs, `hreflang` alternates, `x-default`, and Open Graph metadata on every rendered page.

## Enable automatic SEO

Set `meta: true` in `nuxt.config.ts`. The module then manages head tags for every locale you declare.

```typescript nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
  },
})
```

### Tags the module generates

| Tag             | Example                                                  |
| --------------- | -------------------------------------------------------- |
| HTML attributes | `<html lang="en" dir="ltr">`                             |
| Canonical       | `<link rel="canonical" href="...">`                      |
| hreflang        | `<link rel="alternate" hreflang="en" href="...">`        |
| x-default       | `<link rel="alternate" hreflang="x-default" href="...">` |
| Open Graph      | `<meta property="og:locale" content="en_US">`            |

Each locale emits **one** `hreflang` tag using `iso || code`. If `iso` is set, the routing `code` is never used as a language tag, so market keys like `mx` do not become invalid `hreflang` values.

### `og:locale` versus BCP 47

`<html lang>` and `hreflang` use BCP 47 through `locale.iso` (for example, `ar-AE`). Open Graph requires `language_TERRITORY` with an underscore (`ar_AE`). By default, `og:locale` is derived from `iso` when the mapping is unambiguous (`en-US` becomes `en_US`).

Set an explicit `og` string when you need a custom value (for example, `zh-Hans` should be `zh_CN`).

```typescript
i18n: {
  meta: true,
  locales: [
    { code: 'ar', iso: 'ar-AE', og: 'ar_AE', dir: 'rtl' },
    { code: 'en', iso: 'en-US' },                          // og:locale -> en_US
    { code: 'zh', iso: 'zh-Hans', og: 'zh_CN' },
  ],
}
```

If neither `og` nor a convertible `iso` is available, `og:locale` tags are not generated. In development you get a console warning that respects `missingWarn`.

## Base URL resolution

When `metaBaseUrl` is unset, absolute SEO URLs resolve in this order:

1. `site.url` from [`nuxt-site-config`](https://nuxtseo.com/docs/site-config) (used by `@nuxtjs/seo`).
2. Otherwise the hostname from the current request (`useRequestURL()` on the server, `window.location.origin` on the client).

The request-origin fallback respects reverse-proxy headers, so it works correctly behind nginx, Cloudflare, AWS ALB, and similar proxies. This means one application instance can serve multiple domains with the correct SEO tags for each.

```typescript nuxt.config.ts
export default defineNuxtConfig({
  site: {
    url: process.env.NUXT_SITE_URL, // reused by micro for canonical, og:url, hreflang
  },
  i18n: {
    meta: true,
  },
})
```

If you need a fixed base URL that always wins over `site.url` and the request origin, pass a static string:

```typescript
i18n: {
  meta: true,
  metaBaseUrl: 'https://example.com',
}
```

### Behind a reverse proxy

For correct HTTPS origins on SSR without a custom origin composable, trust the forwarded headers:

```typescript
i18n: {
  meta: true,
  metaBaseUrl: undefined,
  metaTrustForwardedHost: true,
  metaTrustForwardedProto: true,
}
```

## Canonical query whitelist

By default, query parameters are stripped from canonical and `og:url` to avoid duplicate content. Whitelist specific parameters that should be preserved:

```typescript
i18n: {
  canonicalQueryWhitelist: ['page', 'sort', 'filter', 'search', 'q', 'query', 'tag'],
}
```

Only parameters listed here appear in canonical URLs. Everything else (tracking, session IDs) is removed.

## Bare-language hreflang

`hreflangBaseLanguage: true` also emits a bare-language `hreflang` derived from `iso`. For example, with `es-ES` set, a `hreflang="es"` tag is added and claimed by the first regional locale in `locales`.

```typescript
i18n: {
  meta: true,
  hreflangBaseLanguage: true,
  locales: [
    { code: 'es', iso: 'es-ES' }, // emits hreflang="es-ES" and hreflang="es"
    { code: 'es-mx', iso: 'es-MX' },
  ],
}
```

## Disabling meta per page

Disable SEO meta tag generation for specific pages using `defineI18nRoute()`:

```vue
<script setup>
defineI18nRoute({
  disableMeta: true,
})
</script>
```

You can also disable meta only for specific locales:

```vue
<script setup>
defineI18nRoute({
  disableMeta: ['en'],
})
</script>
```

When `disableMeta` is active no `hreflang`, `canonical`, `og:locale`, `og:url`, or `x-default` tags are generated for the affected page or locale.

## Disabled and opt-out locales

<Info>
Locales with `disabled: true` are excluded from all SEO tag generation: no `hreflang`, `og:locale:alternate`, or alternate links are created for them.
</Info>

For locales that should remain routable and translated but not appear in cross-locale discovery, set `seo: false`. These locales are omitted from `hreflang` alternates and `og:locale:alternate`. If your default locale has `seo: false`, the `x-default` link is not emitted either.

```typescript
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'fr', iso: 'fr-FR', disabled: true }, // excluded from SEO tags
    { code: 'ru', iso: 'ru-RU', seo: false },     // routable but not indexed
  ],
}
```

## Strategy-specific behavior

| Strategy                | hreflang         | x-default             | canonical       | og:url |
| ----------------------- | ---------------- | --------------------- | --------------- | ------ |
| `prefix`                | All locales      | Default locale URL    | Current URL     | Yes    |
| `prefix_except_default` | All locales      | Unprefixed URL        | Current URL     | Yes    |
| `prefix_and_default`    | All locales      | Default locale URL    | Current URL     | Yes    |
| `no_prefix`             | Not generated    | Not generated         | Current URL     | Yes    |

For the `no_prefix` strategy only `canonical`, `og:url`, `og:locale`, and the `<html>` `lang`/`dir` attributes are generated. `hreflang` and `x-default` are omitted because there are no distinct URLs per locale.

## Manual head management

For fine-grained control (per-article alternates, per-locale slugs from a CMS, custom Open Graph fields) use the [`useLocaleHead`](/api/composables/use-locale-head) composable on the page instead of a custom i18n head plugin.

<Tip>
See the [`useLocaleHead` reference](/api/composables/use-locale-head) for the full options object, along with `replace`, `merge`, and reactive-fetch patterns.
</Tip>

## Nuxt SEO integration

[`@nuxtjs/seo`](https://nuxtseo.com/) bundles sitemap, robots, schema.org, OG images, and related modules. It integrates with Nuxt I18n Micro through [`nuxt-site-config`](https://nuxtseo.com/docs/site-config/guides/i18n) 4 and later.

**Requirements**

- `@nuxtjs/seo` 3 or later (current releases pull in `nuxt-site-config` 4, which registers the `nuxt-site-config:i18n` plugin for micro).
- `i18n.meta: true` so micro supplies locale-aware head tags while Nuxt SEO adds sitemap, schema.org, and related outputs.

List `nuxt-i18n-micro` **before** `@nuxtjs/seo` in `modules` so site config can read your locale setup:

```typescript nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: {
    url: 'https://example.com',
    name: 'My Site',
  },
  i18n: {
    meta: true,
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Nuxt Site Config also reads optional translation keys from your locale files:

```json locales/en.json
{
  "nuxtSiteConfig": {
    "name": "My Site",
    "description": "My site description"
  }
}
```

Per-locale values in `locales/en.json`, `locales/de.json`, and so on are picked up automatically.

<Warning>
If you see `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered`, upgrade `@nuxtjs/seo` to 3 or later. Older `nuxt-site-config` 3.x only wired i18n for `@nuxtjs/i18n`, not micro.
</Warning>

## Trailing slash consistency

The module generates canonical and `hreflang` URLs based on the actual path from `useRoute().fullPath`. If your application uses trailing slashes (via Nuxt's `router.options`), the generated URLs reflect this. Note that `$switchLocalePath` may normalize paths and remove trailing slashes, so verify generated URLs match your application's URL structure if trailing-slash consistency is critical for your SEO.
