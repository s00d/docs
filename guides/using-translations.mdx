Once you install Nuxt I18n Micro and declare your locales, translations become available through `$t()` in every template and `<script setup>` block. This guide walks through where JSON files live, how to read them at runtime, and when to reach for `$ts` instead of `$t`.

## Root-level vs page-specific files

Translation files live under `translationDir` (default `locales/`). Two scopes exist:

1. **Root-level** files (`locales/{locale}.json`) contain translations shared across every page: navigation, footers, shared UI copy.
2. **Page-specific** files (`locales/pages/{route}/{locale}.json`) contain translations for a single page. With the default `translationPayloads.mode: 'premerged'`, root-level entries are merged into each page file at build time, so a page always sees the union of both.

```tree
locales/
├── en.json          # root-level: shared with every page
├── fr.json
├── ar.json
└── pages/
    └── dir1/
        ├── en.json  # page-specific for /dir1
        └── fr.json
```

<Tip>
  When a key exists in both scopes, the page-specific value wins. Root translations are merged in as a base at build time.
</Tip>

Dynamic segments are flattened by replacing brackets with dashes: `pages/articles/[id].vue` maps to `locales/pages/articles-id/`.

## Reading translations with `$t`

`$t` is auto-injected. You do not need to import anything.

```vue pages/dir1/index.vue
<template>
  <div>
    <!-- Root-level translation, available everywhere -->
    <p>{{ $t('test_key') }}</p>

    <!-- Page-specific translation for /dir1 -->
    <p>{{ $t('local_key') }}</p>

    <!-- Nested key via dot notation -->
    <p>{{ $t('nested.key.deeper') }}</p>

    <!-- Placeholder interpolation -->
    <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
  </div>
</template>

<script setup lang="ts">
const { $t } = useI18n()

console.log($t('test_key'))
</script>
```

With translations:

```json locales/en.json
{
  "test_key": "Hello World!",
  "greeting": "Hello, {name}!",
  "nested": {
    "key": {
      "deeper": "Nested translation here"
    }
  }
}
```

### `$t` vs `$ts`

`$t` can return **any** JSON node, including an object when the key points to a nested branch. Templates render objects as `[object Object]`.

Use `$ts` whenever you need a guaranteed `string`. It coerces (or resolves the fallback) so the return type is always `string`.

<Warning>
  `$t('header')` where `header` is `{ title: "Hi" }` renders as `[object Object]`. Either target a leaf key (`$t('header.title')`) or use `$ts('header.title')` for the string-only return.
</Warning>

```vue
<template>
  <!-- Guaranteed to be a string -->
  <h1>{{ $ts('header.title') }}</h1>
</template>

<script setup lang="ts">
const { $t, $ts } = useI18n()

// $t returns unknown here; the object is preserved
const header = $t('header') // { title: 'Hi' }

// $ts always returns string
const title = $ts('header.title')
</script>
```

See [API reference: `$t` vs `$ts`](/api/methods) for the full return-type contract.

## Nested keys and placeholders

Use dot notation for nested lookups and curly-brace tokens for interpolation:

```json locales/en.json
{
  "cart": {
    "summary": "You have {count} item in your cart",
    "empty": "Your cart is empty"
  }
}
```

```vue
<template>
  <p>{{ $t('cart.summary', { count: 3 }) }}</p>
</template>
```

For plural forms (`"no items | one item | {count} items"`), reach for `$tc()` and see the [pluralization section of the API reference](/api/methods). Custom rules per locale go through the `plural` option; see [Configuration → plural](/guides/configuration#plural).

## Switching locales at runtime

`$switchLocale(code)` navigates to the same route in another locale, respecting your chosen routing strategy.

```vue components/LanguageSwitcher.vue
<template>
  <div>
    <button @click="$switchLocale('en')">English</button>
    <button @click="$switchLocale('fr')">Français</button>
  </div>
</template>

<script setup lang="ts">
const { $switchLocale } = useI18n()
</script>
```

To iterate over available locales:

```vue
<template>
  <nav>
    <button
      v-for="locale in $getLocales()"
      :key="locale.code"
      :disabled="locale.disabled"
      @click="$switchLocale(locale.code)"
    >
      {{ locale.displayName ?? locale.code }}
    </button>
  </nav>
</template>
```

<Note>
  Prefer the built-in `<i18n-switcher>` component when you just want a dropdown. See [`<i18n-switcher>`](/api/components/i18n-switcher).
</Note>

## Opting out of page-specific files

If your project fits entirely into root-level files, set `disablePageLocales: true` in `nuxt.config`:

```typescript nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    disablePageLocales: true,
  },
})
```

With this option enabled, the module only reads and generates `locales/{locale}.json`. Page-specific files under `locales/pages/**` are ignored even if they exist.
