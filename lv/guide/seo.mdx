Ar `meta: true` (noklusējums) katra lokalizētā lapa saņem `<html lang dir>`, canonical saiti, `hreflang` alternatīvas, `x-default` un Open Graph lokāles tagus. Šī lapa jums noderēs, ja vēlaties iestatīt publisko izcelsmi (origin), noregulēt, kuras lokāles parādās tagos, vai pārrakstīt tos vienai lapai. Lielākajai daļai vietņu pietiek ar `site.url` vai `metaBaseUrl` un pareiziem `iso` kodiem.

## Minimālā iestatīšana {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

Tad `/de/about` renderē:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Teksta virziens {#text-direction}

`<html dir>` nāk no lokāles `dir`. Ja tā nav, valoda, kas tiek rakstīta no labās uz kreiso, saņem `rtl`, nolasot no `iso` (vai `code`): arābu, ivrits, persiešu, urdu un dažas citas, kā arī jebkurš tags ar RTL rakstību, piemēram, `az-Arab`. Visas pārējās lokāles nesaņem `dir` atribūtu, ko pārlūki interpretē kā `ltr`.

<Warning>

**`dir: 'auto'` lielās lapās maksā parsēšanas laiku** — `auto` elementā `<html>` liek pārlūkam parsēšanas laikā noteikt virzienu no satura. Chromium šīs izmaksas aug ātrāk nekā lapa: aptuveni 100 ms pie 5000 elementiem un 1 s pie 20 000. Izmantojiet to tikai mazai lapai, kuras valodu nevarat zināt.

</Warning>

## Kādus tagus jūs saņemat {#which-tags-you-get}

- **hreflang**: viens tags katrai lokālei, kas apkalpo lapu, vērtība `iso` (vai `code`, ja `iso` trūkst), tās URL ar tādu pašu vaicājumu kā canonical. Lapa, kas ierobežota ar [Lapas konfigurāciju](/lv/guide/per-component-translations) vai `routeLocales`, uzskaita tikai savas lokāles. [`hreflangBaseLanguage: true`](/lv/api/module-options#hreflangbaselanguage) pirmajai reģionālajai lokālei pievieno arī pamata valodu (`es-ES` → `es`).
- **x-default**: noklusējuma lokāles URL, tikai tad, ja noklusējuma lokāle apkalpo lapu.
- **og:locale**: atvasināts no `iso` (`en-US` → `en_US`). Iestatiet lokālei `og`, ja kartējums nav tiešs, piemēram, `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; bez abiem `og:locale` netiek ierakstīts, un izstrādes režīms brīdina.
- **canonical / og:url**: pašreizējais URL bez vaicājuma parametriem, izņemot tos, kas ir [`canonicalQueryWhitelist`](/lv/api/module-options#canonicalquerywhitelist) (pēc noklusējuma `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Pēc stratēģijas:

| Stratēģija | hreflang un x-default | canonical, og:url, og:locale, html atribūti |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | jā | jā |
| `no_prefix` | nē (viens URL apkalpo visas lokāles) | jā |

## Publiskās izcelsmes iestatīšana {#set-the-public-origin}

Absolūtie URL izmanto pirmo no:

1. [`metaBaseUrl`](/lv/api/module-options#metabaseurl);
2. `site.url` no `nuxt-site-config` (instalē `@nuxtjs/seo`);
3. pieprasījuma izcelsmes, ar pievienotu `app.baseURL`.

Nofiksējiet vienu no pirmajiem diviem.

<Warning>

Pieprasījuma izcelsmes rezerves variants nolasa `X-Forwarded-Host` un `X-Forwarded-Proto`, jo [`metaTrustForwardedHost`](/lv/api/module-options#metatrustforwardedhost) un `metaTrustForwardedProto` pēc noklusējuma ir `true`. Tas ir droši tikai aiz starpniekservera, kas pārraksta šīs galvenes; citādi klients var izvēlēties resursdatoru jūsu canonical saitēs, un kešatmiņa var šo lapu nodot tālāk.

Ja lietotne ir sasniedzama tieši, nofiksējiet `metaBaseUrl`: atšķirībā no abu opciju iestatīšanas uz `false`, tas ignorē arī viltotu `Host`. Skatiet [Aiz starpniekservera vai CDN](/lv/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

Rezerves variants ir noderīgs vienam izvietojumam, kas apkalpo vairākus domēnus: `https://site-a.com/en/about` un `https://site-b.com/en/about` katrs saņem savu izcelsmi.

Ja lokālēm ir `baseUrl`, zināms resursdators izmanto savu `baseUrl` pār `metaBaseUrl` un `site.url`, tāpēc canonical un `og:url` paliek šajā domēnā, un `hreflang` katru lokāli norāda uz tās domēnu. Jebkurš cits resursdators izmanto `metaBaseUrl`, citādi noklusējuma lokāles `baseUrl`, citādi `site.url`, tāpēc viltots `Host` nevar sasniegt jūsu tagus. Ja neviens no tiem nav iestatīts, paliek pieprasījuma izcelsmes rezerves variants, un būvēšana brīdina. Skatiet [Slāņi un domēni](/lv/guide/layers#multiple-domains).

## Lokāļu vai lapu izslēgšana {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Ja noklusējuma lokālei ir `seo: false`, `x-default` netiek ierakstīts. Lai izslēgtu tagus vienai lapai, izmantojiet `disableMeta` [Lapas konfigurācijā](/lv/guide/per-component-translations#turn-off-seo-tags) vai [`routeDisableMeta`](/lv/api/module-options#routedisablemeta) konfigurācijā.

## Tagu pārrakstīšana vienā lapā {#override-tags-on-one-page}

CMS saturam, kur eksistē tikai daži tulkojumi vai URL nāk no API, aizstājiet ģenerētos tagus ar [`useI18nHead`](/lv/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` var arī iestatīt vai noņemt `canonical`, `xDefault`, `ogLocale` un `ogUrl`; `disable` atmet veselas grupas (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Nododiet getteri, lai vērtības tiktu pārrēķinātas pēc lokāles pārslēgšanas. Lokālei specifiskiem slugiem vispirms iestatiet `$setI18nRouteParams` ([Lokalizēti ceļi](/lv/guide/custom-locale-routes#per-locale-slugs)), un ģenerētās alternatīvas tos jau izmantos.

## Beigu slīpsvītra {#trailing-slash}

`$localePath`, `$switchLocalePath`, `$switchLocaleRoute` maršruta objekts, `<i18n-link>`, `<i18n-switcher>`, lokāles pāradresācijas un SEO URL ievēro vienu slīpsvītras noteikumu: pēc noklusējuma `experimental.defaults.nuxtLink.trailingSlash` vai [`trailingSlash`](/lv/api/module-options) i18n konfigurācijā, ja i18n ceļiem jāatšķiras.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) darbojas ar šo moduli caur `nuxt-site-config` 4+. Norādiet `nuxt-i18n-micro` pirmo, lai vietnes konfigurācija varētu nolasīt lokāles, un iestatiet `site.url` vienreiz — tas nodrošina arī iepriekš minētos tagus.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Tulkots vietnes nosaukums un apraksts nāk no atslēgām `nuxtSiteConfig.name` / `nuxtSiteConfig.description` jūsu lokāļu failos. Kļūda `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` nozīmē, ka `@nuxtjs/seo` ir vecāks par 3; jauniniet to ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
