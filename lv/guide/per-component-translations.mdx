`$defineI18nRoute` iestata i18n opcijas vienai lapai no pašas lapas iekšpuses. Izmantojiet to, ja lapa pastāv tikai dažās lokalizācijās, tai vajadzīgs savs lokalizēts ceļš, tai ir daži savi tulkojumi vai tai nedrīkst būt hreflang/canonical tagu. Modulis nolasa šo izsaukumu būvēšanas laikā un iestrādā to ģenerētajos maršrutos.

## Lapas ierobežošana līdz dažām lokalizācijām {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

Ar noklusējuma stratēģiju `prefix_except_default` tiek ģenerēti tikai `/product` un `/de/product`; citās lokalizācijās lapai nav maršruta. To pašu var iestatīt no `nuxt.config.ts` ar [`routeLocales`](/lv/api/module-options#routelocales).

`$defineI18nRoute` ir Nuxt lietotnes injekcija, nevis kompilatora makro: vienmēr ņemiet to no `useNuxtApp()` un izsauciet ar `$`. Būvēšanas solis atpazīst tikai `$defineI18nRoute(`.

## Iekļauto tulkojumu pievienošana {#add-inline-translations}

Masīva vietā nododiet objektu. Tā atslēgas ir atļautās lokalizācijas, tā vērtības tiek sapludinātas lapas vārdnīcā aktīvajai lokalizācijai.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Iekļautie tulkojumi tiek piegādāti lapas komponentā visām lokalizācijām. Visam, kas ir lielāks par dažām atslēgām, dodiet priekšroku [lapu tulkojumu failiem](/lv/guide/translations); iekļautās atslēgas paturiet pašpietiekamām lapām un komponentiem.

## Lokalizēto ceļu iestatīšana {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

Ar `prefix_except_default` un `defaultLocale: 'en'` tas izveido `/welcome` un `/de/willkommen`. `path` iekļautās lokalizācijas objektā dara to pašu: `locales: { de: { path: '/willkommen' } }`. Dinamiskie parametri, ligzdotie maršruti un alternatīva konfigurācijas līmenī ir aprakstīti sadaļā [Lokalizētie ceļi](/lv/guide/custom-locale-routes).

## SEO tagu izslēgšana {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

Alternatīva konfigurācijas līmenī ir [`routeDisableMeta`](/lv/api/module-options#routedisablemeta). Kas ir šie tagi, skatiet lapā [SEO](/lv/guide/seo).

## Ko būvēšana var nolasīt {#what-the-build-can-read}

Būvēšanas solis atrod izsaukumu katrā lapas failā un novērtē tā argumentu, nepalaižot jūsu lietotni. Tas darbojas, ja konfigurācija ir:

- literāls objekts (virknes, masīvi, ligzdoti objekti, veidņu literāļi, trīsvietīgie operatori ar `process.env.NODE_ENV`);
- veidota no konstantēm, kas deklarētas tajā pašā `<script setup>` (`const locales = ['en', 'de']`, ieskaitot izklāšanu);
- objektu masīvs ar lauku `code` (`[{ code: 'en' }, { code: 'de' }]`).

Tas nevar nolasīt vērtības, kas importētas no cita moduļa, vai jebko, kam izpildlaikā vajadzīga jūsu lietotne (composables, `await`, ielādēti dati). Tādā gadījumā būvēšana reģistrē `Ignored the $defineI18nRoute() config in <file>`, un lapa saglabā noklusējuma lokalizācijas un maršrutus.

Izpildlaikā izsaukums tikai sapludina iekļautos tulkojumus pašreizējai lokalizācijai un sapludina tos atkārtoti, kad lokalizācija mainās. `locales`, `localeRoutes` un `disableMeta` stājas spēkā tikai ar būvēšanu, tāpēc to mainīšanai vajadzīga atkārtota būvēšana (izstrādes serveris pārbūvē saglabāšanas brīdī).
