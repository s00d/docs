Nuxt slānis var saturēt i18n konfigurāciju un `locales/` mapi vairākām lietotnēm, un katra lietotne pievieno vai pārraksta to, kas tai vajadzīgs. Šajā lapā parādīts, kā to izdarīt un kā viena būve apkalpo vairākus domēnus.

## Konfigurācijas un tulkojumu koplietošana {#share-config-and-translations}

```ts
// base/nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    defaultLocale: 'en',
  },
})
```

```ts
// shop/nuxt.config.ts
export default defineNuxtConfig({
  extends: ['../base'], // a layer directory or package, not a nuxt.config file
  i18n: {
    locales: [
      { code: 'es', iso: 'es-ES' }, // added
      { code: 'fr', disabled: true }, // the base layer's fr, switched off here
    ],
  },
})
```

- **Konfigurācija:** skalārās opcijas lietotnē aizstāj slāņa opcijas. Visu slāņu `locales` masīvi tiek apvienoti, un ieraksti ar vienādu `code` saplūst vienā, kur priekšroka ir lietotnes laukiem, tāpēc lietotne var pievienot lokalizāciju vai iestatīt laukus, piemēram, `disabled: true`, mantotai lokalizācijai.
- **Tulkojumi:** katra slāņa `locales/` tiek apvienoti atslēgu pa atslēgai — vispirms slānis, pēdējā lietotne —, tāpēc atslēga failā `shop/locales/en.json` pārraksta to pašu atslēgu failā `base/locales/en.json`. Lapu faili (`locales/pages/<page>/`) tiek apvienoti tāpat.
- **Lapas:** `$defineI18nRoute` tiek nolasīts no visu slāņu lapām.

Lai apvienotu mapes, kas nav daļa no slāņa, norādiet tās opcijā [`additionalTranslationDirs`](/lv/api/module-options#additionaltranslationdirs).

## Vairāki domēni {#multiple-domains}

Viena būve apkalpo visus domēnus. Norādiet katru lokalizāciju ar tās domēnu; `baseDefault` padara to par attiecīgā resursdatora noklusējumu:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'de', iso: 'de-DE', baseUrl: 'https://example.de', baseDefault: true },
      { code: 'nl', iso: 'nl-NL', baseUrl: 'https://example.de' },
      { code: 'fr', iso: 'fr-FR' },
    ],
  },
})
```

Novirziet abus domēnus uz to pašu serveri. Pārējo nosaka pieprasījuma resursdators:

- **Noklusējums:** resursdatora `baseDefault` lokalizācija. Ja tādas nav — būves noklusējums, ja resursdators to apkalpo, citādi resursdatora pirmā lokalizācija.
- **Apkalpotās lokalizācijas:** šī resursdatora lokalizācijas, kā arī visas lokalizācijas bez `baseUrl`. Domēnā `example.de` tās ir `de`, `nl` un `fr`.
- **Citu domēnu lokalizācijas** ir saišu mērķi. `$localePath`, `$localeRoute`, `$switchLocalePath`, `<i18n-switcher>` un `hreflang` sniedz absolūtus URL to `baseUrl`, un `$switchLocale` veic navigāciju uz turieni. Šajā resursdatorā to URL atgriež 404, un sīkdatne vai `Accept-Language` tos nevar izvēlēties.
- **Saite uz citu domēnu** tiek veidota ar `$localePath` vai `<i18n-link>`: `<NuxtLink :to="$localePath('/contact', 'de')">`, `<i18n-link :to="$localeRoute('/contact', 'de')">`. Maršrutētājs nepieņem absolūtu objektu, tāpēc `<NuxtLink :to="$localeRoute(...)">` un `router.push($localeRoute(...))` paliek šajā izcelsmē. Uz `localhost` vai priekšskatījuma resursdatora katra lokalizācija ar `baseUrl` ir šāda saite, arī pašreizējā. Kodā izmantojiet `navigateTo($localePath('/contact', 'de'), { external: true })` vai `$switchRoute`.
- **Jebkurš cits resursdators** saņem būves konfigurāciju, kurā katra `baseUrl` lokalizācija ir saites mērķis. Nekas no pieprasījuma netiek atkārtots: kanoniskais URL un `hreflang` izmanto `metaBaseUrl`, citādi būves noklusējuma `baseUrl` (noklusējumam bez `baseUrl` vajadzīgs `metaBaseUrl` vai `site.url`, skatiet [SEO](/lv/guide/seo#set-the-public-origin)).
- **Kravas faili** mapē `public/` ir statiski: jebkurš resursdators atgriež jebkuras lokalizācijas failu. [Ģenerēšana](/lv/guide/deployment#static-site-(nuxi-generate)) katram domēnam atsevišķi publicē tikai attiecīgā domēna failus.

`example.de` katrā stratēģijā, ar `de: '/kontakt'` kā pielāgotu `contact` ceļu:

| Stratēģija | `/` | Noklusējuma lokalizācijas lapa | Citi URL |
| --- | --- | --- | --- |
| `prefix_except_default` | `de` | `/kontakt` | `/de/kontakt` un `/en/contact` atgriež 404, `/contact` novirza uz `/kontakt` |
| `prefix_and_default` | `de` | `/kontakt` un `/de/kontakt`, saites izmanto `/kontakt` | `/en/contact` un `/contact` atgriež 404 |
| `prefix` | novirza uz `/de` | `/de/kontakt` | `/kontakt` novirza uz `/de/kontakt`, `/en/contact` atgriež 404 |
| `no_prefix` | `de` | `/kontakt` | citā domēnā esošas lokalizācijas pielāgotais ceļš atgriež 404 |

Ar `prefix` saite no cita domēna saglabā prefiksu, jo URL bez prefiksa tikai novirzītu. Ar `no_prefix` saite uz citu domēnu nonāk šī resursdatora noklusējuma lokalizācijā: URL nevar norādīt otru.

Kas jāzina:

- **Aiz starpniekservera** resursdators tiek ņemts no `Host`. Ja starpniekserveris publisko resursdatoru ievieto `X-Forwarded-Host`, iestatiet [`trustForwardedHost`](/lv/api/module-options#trustforwardedhost), un tikai tad, ja starpniekserveris šo galveni pārraksta. Starpniekserveris, kas nesūta nevienu no tām, nevar apkalpot domēnu būvi. Skatiet [Aiz starpniekservera vai CDN](/lv/guide/deployment#behind-a-proxy-or-cdn).
- **`app.baseURL`** jāiekļauj arī `baseUrl`: `baseUrl: 'https://example.de/shop'` kopā ar `app.baseURL: '/shop'`.
- **Resursdatori tiek salīdzināti precīzi.** `www.example.de` ir cits resursdators: novirziet to tīkla malā vai iestatiet šo `baseUrl` lokalizācijai. Katrai lokalizācijai tikai viens resursdators.
- **Kešatmiņām jāizmanto resursdators kā atslēga.** CDN parasti tā dara. Nitro maršrutu kešatmiņa par atslēgu izmanto ceļu, tāpēc domēnu būvē modulis pievieno `host` katra `swr` un `cache` noteikuma `cache.varies`, un ar `trustForwardedHost` arī `x-forwarded-host`. Noteikums ar `cache: false` paliek, kā uzrakstīts. `isr` ir platformas kešatmiņa: pārbaudiet, vai tā par atslēgu izmanto resursdatoru.
- **Divu resursdatoru noklusējumu pielāgotie ceļi nedrīkst sakrist.** Ieraksti bez prefiksa koplieto vienu maršrutētāju, tāpēc `/x` nevar būt viena lapa domēnā `example.de` un cita domēnā `example.com`.
- **Priekšatveidotas lapas:** `prerender: true` maršruta noteikums `nuxt build` laikā tiek atveidots vienreiz, bez resursdatora, un fails atbild visiem domēniem. Lapas, kas atšķiras katrā domēnā, atstājiet serverim vai [ģenerējiet katram domēnam](/lv/guide/deployment#static-site-(nuxi-generate)).
- **`noPrefixRedirect`** vadās pēc resursdatora un apmeklētāja lokalizācijas katrā resursdatorā.
- **`hashMode`:** resursdators izvēlas atveidojumu, kā aprakstīts iepriekš; saites uz citu domēnu nes maršrutu jaucējfragmentā (`https://example.com/#/contact`).
- **`ssr: false`:** pārlūks nolasa domēnu no `location.host`, tāpēc arī resursdators bez servera tiek atrisināts.
- **[Izpildlaika pārrakstījumi](/lv/guide/runtime-overrides)** tiek piemēroti vispirms. Izpildlaika `disabledLocales` darbojas katrā resursdatorā ar vienu izņēmumu: ar `prefix_except_default` un `prefix_and_default` resursdatora noklusējums paliek iespējots savā resursdatorā, jo tā lapas ir ieraksti bez prefiksa. Ar `prefix` un `no_prefix` resursdators pāriet uz nākamo lokalizāciju, ko tas apkalpo. Izpildlaika `defaultLocale` attiecas tikai uz nezināmiem resursdatoriem.

[Statiskai vietnei](/lv/guide/deployment#static-site-(nuxi-generate)) ģenerējiet vienreiz katram domēnam.

### Viena lietotne katram domēnam {#one-app-per-domain}

Koplietots slānis ar vienu nelielu lietotni katram domēnam joprojām darbojas, ja domēniem vajadzīgas atšķirīgas lapas vai moduļi. Katra lietotne iestata savu `defaultLocale` virs tā paša `locales` saraksta. Lokalizācija citā domēnā šajā lietotnē atgriež 404, kā aprakstīts iepriekš.

### Lokalizācijas izvēle kodā {#choosing-the-locale-in-code}

Par vienu instanci, kas atbild visiem domēniem ar pieprasījuma izcelsmi SEO tagos, skatiet [SEO](/lv/guide/seo#set-the-public-origin); lai kodā izvēlētos lokalizāciju pēc resursdatora, skatiet [Pielāgota lokalizācijas noteikšana](/lv/guide/custom-auto-detect).
