`@i18n-micro/react` un `@i18n-micro/preact` ietin no ietvara neatkarīgo [runtime](/lv/integrations/runtime-package) nodrošinātājā, `useI18n()` āķī un četros komponentos. Izmantojiet tos React vai Preact lietotnē, kas nav būvēta ar Nuxt. Abām pakotnēm ir vienāds API; sadaļā [Preact](#preact) uzskaitītas dažas atšķirības, un kopīgais modelis ir aprakstīts lapā [Ietvari](/lv/integrations/overview).

## Instalēšana {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/react
```

```bash npm
npm install @i18n-micro/react
```

```bash yarn
yarn add @i18n-micro/react
```

</CodeGroup>

Vienādranga atkarības: `react` `^18.0.0 || ^19.0.0`; `react-dom` (neobligāta, atveidošanai); `react-router-dom` `^6.0.0 || ^7.0.0` (neobligāta, tikai `@i18n-micro/react/router`). Pārbaudīts ar React 19.3 un 18.3, React Router 7.18 un 6.30.

## Iestatīšana {#setup}

```tsx
// src/main.tsx
import { createRoot } from 'react-dom/client'
import { createI18n, I18nProvider } from '@i18n-micro/react'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

createRoot(document.getElementById('root')!).render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
    <App />
  </I18nProvider>,
)
```

<Warning>

Izveidojiet instanci vienreiz — moduļa līmenī vai `useState` inicializētājā, nekad komponenta ķermenī.

</Warning>

`<I18nProvider>` pieņem `i18n`, `locales`, `defaultLocale` un `routingStrategy`:

- Izlaists rekvizīts saglabā ārējā nodrošinātāja vērtību, ieskaitot instanci.
- Ja instances nav vispār, tas izveido to no blakus norādītajām `createI18n` opcijām, tāpēc rekvizīti paliek vienkārši dati: `<I18nProvider locale="de" messages={messages}>`.
- Jauns `locale` rekvizīts izveido jaunu instanci ar šī atveidojuma `messages`. Šāda instance dzīvo komponentā: ja kaut kas virs tā montēšanas laikā aptur atveidošanu (suspend), React to izmet kopā ar visu, kas tai tika pievienots.

Visas `createI18n` opcijas, ieskaitot `routeMessages`, ir aprakstītas sadaļā [instance](/lv/integrations/overview#the-instance).

## Tulkošana {#translate}

```tsx
import { useI18n } from '@i18n-micro/react'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' })}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

`useI18n()` atgriež:

| Grupa | Locekļi |
| --- | --- |
| Tulkošana | `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` |
| Lokalizācija un maršruts | `locale`, `fallbackLocale`, `currentRoute`, `setLocale`, `setRoute`, `getRoute`, `getLocales`, `defaultLocale()`, `getLocaleName` |
| Maršrutēšana | `switchLocale`, `localePath`, `localeRoute` |
| Vārdnīcas | `addTranslations`, `addRouteTranslations`, `clearCache` |

- Komponents tiek atkārtoti atveidots, kad mainās lokalizācija, maršruts vai nolasāma vārdnīca, un kad nodrošinātājs saņem jaunu `locales` vai `routingStrategy` objektu. Vārdnīca lokalizācijai, kas nav ne aktīvā, ne rezerves, neko neatveido.
- `t` un pārējās tulkošanas metodes mainās tikai kopā ar krātuvi, tāpēc tās ir drošas `memo` un efektu atkarībās.

`useT` ir viena virkne kā vērtība. Komponents tiek atveidots tikai tad, kad šī virkne mainās, neatkarīgi no tā, kas notiek ar nodrošinātāja pārējiem rekvizītiem; arī `<I18nT>` no tiem nav atkarīgs:

```tsx
const title = useT('page.title')
```

Ielādējiet papildu vārdnīcas jebkurā laikā:

```tsx
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

useEffect(() => {
  import('./locales/de.json').then((m) => addTranslations('de', m.default))
  addRouteTranslations('en', 'about', { title: 'About us' })
  setRoute('about') // t('title') now reads the 'about' dictionary first
}, [])
```

Pašai instancei ir arī `loadFromUrl(url, { locale, routeName })` JSON ielādei ar `fetch`.

## Lokalizācijas pārslēgšana {#switch-locale}

```tsx
const { setLocale, switchLocale } = useI18n()

setLocale('de') // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Pārslēgšana neko neielādē; vispirms pievienojiet lokalizācijas vārdnīcu. Ieraksts krātuvē React ir sinhrons pat `startTransition` iekšienē, tāpēc komponents, kas aptur atveidošanu trūkstošas vārdnīcas dēļ, parādītu savu rezerves saturu. `useLocaleSwitch` vispirms ielādē un saglabā veco UI, līdz vārdnīca ir ielādēta:

```tsx
const [switchTo, pending] = useLocaleSwitch((locale) => i18n.loadFromUrl(`/locales/${locale}.json`, { locale }))

<button disabled={pending} onClick={() => switchTo('de')}>Deutsch</button>
```

Uzvar pēdējais izsaukums. Neveiksmīga ielāde tiek noraidīta un atstāj lokalizāciju nemainītu.

`<I18nGroup>` nodod render-prop bērnam `t` ar prefiksu. `<I18nT>` un `t()` tā iekšienē prefiksu nesaņem:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Maršrutēšana {#routing}

React Router adapteris atrodas apakšceļā, lai galvenais ieejas punkts nekad neimportētu `react-router-dom`. Tam vajadzīgi `useLocation()` un `useNavigate()`, tāpēc izveidojiet to komponentā zem maršrutētāja:

```tsx
// src/App.tsx
import { useMemo } from 'react'
import { BrowserRouter, Route, Routes, useLocation, useNavigate } from 'react-router-dom'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/react'
import { createReactRouterAdapter } from '@i18n-micro/react/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Localized() {
  const location = useLocation()
  const navigate = useNavigate()
  // memoized: a new object on every render re-renders every `useI18n()` consumer
  const routingStrategy = useMemo(() => createReactRouterAdapter(locales, 'en', location, navigate), [location, navigate])
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      <Routes>
        <Route path="/:locale?" element={<Home />} />
        <Route path="/:locale?/about" element={<About />} />
      </Routes>
    </I18nProvider>
  )
}

export default function App() {
  return (
    <BrowserRouter>
      <Localized />
    </BrowserRouter>
  )
}
```

Adapteris pievieno prefiksu katrai lokalizācijai, izņemot noklusējuma (`/about`, `/de/about`), un atveido `<I18nLink>` kā React Router `<Link>`. Iestatiet lokalizāciju no URL paši (piemēram, no `useParams().locale` efektā). Jebkuram citam maršrutētājam uzrakstiet adapteri ar `getCurrentPath`, `push` un `replace` (visi obligāti) — skatiet [Maršrutētāja adapteris](/lv/integrations/overview#router-adapter).

## SSR {#ssr}

`renderToString` darbojas: `useI18n()` ir servera momentuzņēmums. Izveidojiet vienu instanci katram pieprasījumam un pievienojiet tās vārdnīcas pirms atveidošanas, lai pieprasījumi dažādās lokalizācijās nekoplietotu stāvokli, vai nododiet nodrošinātājam vienkāršus datus.

### Hidratācija {#hydration}

Skaitļi, daudzskaitļi un teksts tiek hidratēti, kā ir. Datums ir atkarīgs no laika joslas, bet relatīvs datums — no pulksteņa: iestatiet `timeZone` serverī un pārlūkā, un `tdr` gadījumā nododiet pārlūkam servera laiku ar `now`. `<I18nT>` ar `date` vai `relativeDate` iestata `suppressHydrationWarning`, tāpēc atšķirība nesabojā hidratāciju, taču servera teksts paliek, līdz teksts mainās. Tas sniedzas tikai vienu līmeni: `children`, kas ietin tulkojumu elementā, atšķirības gadījumā joprojām izraisa kļūdu, tāpēc piešķiriet tiem to pašu `timeZone`.

### Servera komponenti {#server-components}

Pakotne atzīmē savu klienta kodu ar `'use client'`. `@i18n-micro/react/server` ir `createI18n` un `I18nT` bez āķiem, kas pieņem instanci kā rekvizītu, tāpēc teksts nenonāk klienta pakotnē. Ar `react-server` nosacījumu, kā Next.js app router, arī galvenais ieejas punkts atrisinās uz to, taču TypeScript pēc noklusējuma to nezina: importējiet no `/server`. `@i18n-micro/react/client` vienmēr sniedz klienta ieejas punktu.

```tsx
// app/[locale]/layout.tsx: a server component
import { cache } from 'react'
import { createI18n, I18nT } from '@i18n-micro/react/server'
import { I18nProvider } from '@i18n-micro/react/client'
import { loadMessages } from './messages'

const getI18n = cache(async (locale: string) => createI18n({ locale, messages: await loadMessages(locale) }))

export default async function Layout({ params, children }) {
  const { locale } = await params
  const i18n = await getI18n(locale)
  return (
    <I18nProvider locale={locale} messages={{ [locale]: i18n.resolveTranslations() }}>
      <h1>
        <I18nT i18n={i18n} keypath="title" />
      </h1>
      {children}
    </I18nProvider>
  )
}
```

Atveidots ar `react-server-dom-webpack`; ar pašu Next.js lietotni tas nav pārbaudīts.

## Preact {#preact}

`@i18n-micro/preact` ir būvēts no tā paša pirmkoda, uz paša Preact, bez `preact/compat`: tā pati instance, nodrošinātājs, āķi un komponenti. Atšķirības:

| | React | Preact |
| --- | --- | --- |
| Vienādranga atkarība | `react` (+ neobligāta `react-router-dom`) | `preact` `^10.0.0 \|\| ^11.0.0`, pārbaudīts ar 10.29 un 11.1 |
| Instances klase | `ReactI18n` | `PreactI18n` |
| Maršrutētāja adapteris | `createReactRouterAdapter` no `/router` | `createBrowserHistoryAdapter(locales, defaultLocale, ssrUrl?)` no `/router` |
| Atkārtota atveidošana | `useSyncExternalStore` | layout-effect abonements, kas atkārtoti pārbauda krātuvi |
| Servera komponenti | `/server`, `/client` | nav |

`createBrowserHistoryAdapter` darbojas ar jebkuru History API maršrutētāju (wouter, preact-router): `push` un `replace` izsauc `history.pushState` / `replaceState` un izsūta `popstate`, un `<I18nLink>` atveido vienkāršu `<a>`, kas veic navigāciju ar `push`. Serverim nav adreses joslas: nododiet pieprasījuma URL kā `ssrUrl`, citādi saites un pārslēdzējs tiek atveidoti kā uz `/`. Pārlūkā priekšroka ir adreses joslai.

```tsx
// src/main.tsx
import { render } from 'preact'
import { createI18n, I18nProvider } from '@i18n-micro/preact'
import { createBrowserHistoryAdapter } from '@i18n-micro/preact/router'
import { App } from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={createBrowserHistoryAdapter(locales, 'en')}>
    <App />
  </I18nProvider>,
  document.getElementById('app')!,
)
```
