`@i18n-micro/solid` sniedz SolidJS lietotnēm ar signāliem balstītu i18n instanci, nodrošinātāju, `useI18n()` un četrus komponentus. Izmantojiet to Solid lietotnē, kas nav būvēta ar Nuxt. `t()` nolasījumi JSX vai efektos seko lokalizācijai, maršrutam un vārdnīcām; kopīgais modelis ir aprakstīts lapā [Ietvari](/lv/integrations/overview).

## Instalēšana {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Vienādranga atkarības: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (neobligāta, tikai `@i18n-micro/solid/router`). Solid 2 pagaidām netiek atbalstīts.

## Iestatīšana {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` pieņem `i18n`, `locales`, `defaultLocale` un `routingStrategy`; izlaists rekvizīts saglabā ārējā nodrošinātāja vērtību, ieskaitot instanci. `getLocaleName()` un `<I18nSwitcher>` nolasa `locales`; bez tām tiem nav ko uzskaitīt. Opcijas ir aprakstītas sadaļā [instance](/lv/integrations/overview#the-instance). Instance ir [runtime](/lv/integrations/runtime-package) instance ar vienu signālu pār tās krātuvi.

## Tulkošana {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Izsauciet metodes JSX vai efektā, lai Solid tām sekotu, arī `localePath` un `getLocale`; vērtība, kas vienreiz nolasīta komponenta ķermenī, netiek atjaunināta. Instancē sekojiet ar `i18n.locale` un `i18n.currentRoute`: `i18n.getLocale()` paliek vienkārša, jo ieraksti to nolasa. Lokalizācijas nolasīšana reaģē tikai uz lokalizāciju, tāpēc efekts, kas to nolasa un ielādē vārdnīcu, izpildās vienreiz. Nedestrukturējiet rekvizītus un neglabājiet `t('key')` rezultātus vienkāršos mainīgajos.

`useI18n()` atgriež `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (piekļuves funkcija: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` un `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Lokalizācijas pārslēgšana {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Pārslēgšana neko neielādē; vispirms pievienojiet lokalizācijas vārdnīcu.

`<I18nGroup>` nodod funkcijas bērnam `t` ar prefiksu. `<I18nT>` un `t()` tā iekšienē prefiksu nesaņem:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Maršrutēšana {#routing}

`@solidjs/router` adapteris atrodas apakšceļā, lai galvenais ieejas punkts nekad neimportētu maršrutētāju. Izsauciet to zem maršrutētāja, parasti maršrutētāja `root`, kur darbojas `useNavigate` un `useLocation`:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

Adapteris pievieno prefiksu katrai lokalizācijai, izņemot noklusējuma (`/about`, `/de/about`), un atveido `<I18nLink>` kā maršrutētāja `<A>`. `getCurrentPath` nolasa maršrutētāja reaktīvo atrašanās vietu, tāpēc aktīvās saites un pārslēdzējs tai seko; pielāgota stratēģija panāk to pašu, tur nolasot signālu. Ievērojiet argumentu secību: `(locales, defaultLocale, navigate, location)`. Citiem maršrutētājiem uzrakstiet adapteri ar `getCurrentPath`, `push` un `replace` (visi obligāti) — skatiet [Maršrutētāja adapteris](/lv/integrations/overview#router-adapter).

## SSR {#ssr}

Servera atveidošanai būvējiet ar `vite-plugin-solid`: pakotnes `solid` eksporta nosacījums nodod tam pirmkodu, tāpēc tas tiek kompilēts serverim. Iepriekš būvētais `dist` paredzēts tikai pārlūkam. Instancei nav `destroy()`; izveidojiet vienu katrai lietotnei vai serverī vienu katram pieprasījumam un ļaujiet atkritumu savācējam to savākt.
