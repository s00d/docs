# 🔥 Firebase AppHosting izvietošana

## 📖 Ievads

Firebase AppHosting ir jaudīga platforma Nuxt lietotņu izvietošanai ar bezservera infrastruktūru. Tomēr, izvietojot lietotnes ar `nuxt-i18n-micro`, jūs varat saskarties ar specifiskām problēmām, kas saistītas ar to, kā tulkojumu JSON faili tiek apkalpoti. Šis ceļvedis sniedz vispusīgus risinājumus, lai nodrošinātu, ka jūsu tulkojumi produkcijā darbojas pareizi.

## ⚠️ Biežas problēmas

### Tulkojumu faili netiek piemēroti

**Simptomi:**

- ✅ Tulkojumi izstrādes vidē darbojas nevainojami (`nuxt dev`)
- ❌ Pēc izvietošanas uz Firebase AppHosting JSON faili tiek ielādēti, bet tulkojumi netiek piemēroti
- ❌ Konsolē neparādās kļūdas
- ❌ Tulkojumu faili ir redzami cilnē Network, bet ar nepareizu `Content-Type: text/html`, nevis `application/json`

**Galvenais cēlonis:**

Firebase AppHosting (un citas platformas, kas izmanto Nitro iepriekšēju renderēšanu) var apkalpot iepriekš renderētus JSON failus ar nepareiziem MIME tipiem. Kad pārlūks saņem JSON failus ar `Content-Type: text/html`, tas nevar tos pareizi parsēt, izraisot tulkojumu klusi neizdošanos.

## ✅ Risinājumi

### 1. risinājums: maršruta noteikumu konfigurācija (ieteicams)

Vienkāršākais risinājums ir savā `nuxt.config.ts` pievienot skaidras galvenes tulkojumu maršrutiem:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**Priekšrocības:**

- ✨ Vienkārša konfigurācija
- 🚀 Uzlabo veiktspēju ar pareizu kešošanu
- 🔒 Darbojas visās izvietošanas platformās

### 2. risinājums: pielāgots API bāzes URL

Ja izmantojat pielāgotu `apiBaseUrl` (tikai ceļa priedēkli), attiecīgi pielāgojiet maršruta noteikumus:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### 3. risinājums: Firebase specifiska konfigurācija

Izveidojiet vai atjauniniet failu `firebase.json` projekta saknē:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```

## 🔍 Atkļūdošana

### Iespējojiet atkļūdošanas režīmu

Pievienojiet atkļūdošanas reģistrēšanu, lai identificētu problēmas:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

Tas izvadīs detalizētus žurnālus par:

- 📝 Tulkojumu failu ielādi
- 🔄 Kešatmiņas operācijām
- ⚠️ Ielādes kļūdām

### Pārbaudiet Network cilni

1. Atveriet DevTools → Network cilne
2. Filtrējiet pēc "data.json"
3. Noklikšķiniet uz tulkojuma faila pieprasījuma
4. Pārbaudiet **atbildes galvenes**:
   - ✅ `Content-Type: application/json` (pareizi)
   - ❌ `Content-Type: text/html` (nepareizi — nepieciešams labojums)

### Pārbaudiet iepriekšēju renderēšanas izvadi

Pēc būvēšanas pārbaudiet, vai tulkojumu faili ir ģenerēti:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

Jums vajadzētu redzēt `data.json` katrai lokālei zem katras lapas.

## 🚀 Būvēšanas konfigurācija

### Nitro sākotnēja iestatījuma kopa (preset)

Firebase AppHosting pārliecinieties, ka izmantojat pareizo sākotnējo iestatījumu kopu:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### Iepriekšējas renderēšanas konfigurācija

Konfigurējiet iepriekšēju renderēšanu optimālai veiktspējai:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

## ✅ Pārbaudes kontrolsaraksts

Pēc labojumu piemērošanas pārbaudiet, vai viss darbojas:

- [ ] Būvēšana pabeidzas bez kļūdām
- [ ] Tulkojumu JSON faili atrodas `.output/public/_locales/\{page\}/\{locale\}/data.json`
- [ ] Network cilne tulkojumu failiem rāda `Content-Type: application/json`
- [ ] Tulkojumi tiek pareizi parādīti pirmajā lapas ielādē
- [ ] Konsolē nav hidratācijas nesakritību
- [ ] Valodas pārslēgšana darbojas pareizi
- [ ] SEO meta tagi tiek pareizi ģenerēti

## 🔄 Izvietošanas darbplūsma

### 1. Sagatavojiet būvējumu

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. Izvietojiet uz Firebase

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. Pārbaudiet izvietošanu

1. Apmeklējiet savu izvietoto vietni
2. Atveriet DevTools → Network cilne
3. Pārvietojieties uz lapu
4. Pārbaudiet, ka `/_locales/index/en/data.json` (vai jūsu noklusējuma lokāle) tiek ielādēts ar:
   - Statuss: 200
   - Content-Type: application/json
   - Atbilde satur derīgu JSON

## 🔧 Problēmu novēršana

### Problēma: 404 kļūdas tulkojumu failiem

**Risinājums:** pārliecinieties, ka tulkojumu faili tiek kopēti izvades mapē:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### Problēma: tulkojumi darbojas dažās lapās, bet citās ne

**Risinājums:** pārbaudiet, vai tiek ģenerēti lapas specifiski tulkojumi:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

Ja trūkst lapas specifisku tulkojumu, pārliecinieties, ka `disablePageLocales` nav iestatīts uz `true`:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### Problēma: lēna tulkojumu ielāde

**Risinājums:** optimizējiet kešošanu un iepriekšēju ielādi:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## ⚡ Veiktspējas optimizācija

### Iespējojiet saspiešanu

Firebase automātiski apstrādā Gzip/Brotli saspiešanu, bet pārliecinieties, ka jūsu būvējums ir optimizēts:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### Lēni ielādējiet tulkojumus

`Nuxt I18n Micro` automātiski lēni ielādē tulkojumus pa lapām. Tulkojumi tiek ielādēti tikai tad, kad nepieciešami, samazinot sākotnējo pakotnes izmēru. Šī ir iebūvēta funkcionalitāte — nav nepieciešama papildu konfigurācija.

Lai vēl vairāk optimizētu:

- Izmantojiet `disablePageLocales: false` (noklusējums), lai iespējotu lapas specifiskus tulkojumus
- Uzturiet saknes līmeņa tulkojumus minimālus
- Lapas saturam izmantojiet maršrutam specifiskus tulkojumu failus

<Tip>
Modulis, sākot ar versiju **v3.0.0+**, automātiski iestata pareizas `Content-Type` galvenes. Ja jums ir problēmas, atjauniniet uz jaunāko versiju:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
