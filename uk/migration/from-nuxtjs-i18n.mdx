# 🔄 Міграція з `nuxt-i18n` на `Nuxt I18n Micro`

## Який гайд вам потрібен?

| Ви мігруєте з…                          | Гайд                                             |
| --------------------------------------- | ------------------------------------------------ |
| `@nuxtjs/i18n` (модуль на базі vue-i18n) | **Ця сторінка**                                  |
| `nuxt-i18n-micro` v2.x                  | [Оновлення з v2.x до v3.x](/migration/v2-to-v3)  |

## Навіщо мігрувати?

- **Покращена продуктивність**: ~51% швидша збірка та ~54% менше памʼяті на збірку порівняно з `@nuxtjs/i18n` **v10.6** у наших [бенчмарк-фікстурах](/guides/performance-results)
- **Спрощена конфігурація**: оптимізоване налаштування з розумними значеннями за замовчуванням
- **Краще керування ресурсами**: оптимізована робота з великими файлами перекладів

## Ключові відмінності

| Можливість              | `nuxt-i18n`                      | `Nuxt I18n Micro`                         |
| ----------------------- | -------------------------------- | ----------------------------------------- |
| Файли перекладів        | JS/TS/JSON, завантажуються через `vueI18n` | Лише JSON, автогенерація у dev |
| Генерація маршрутів     | Runtime                          | На етапі збірки (`@i18n-micro/route-strategy`) |
| Завантаження перекладів | Включено в JS-бандл              | Лінива JSON-завантаження на сторінку      |
| Стан локалі             | `useI18n()` з `vue-i18n`         | Composable `useI18nLocale()`              |
| `detectBrowserLanguage` | Підтримується                    | Використовуйте `autoDetectLanguage`       |

## Крок за кроком

### 1. Встановлення

```bash
npm install nuxt-i18n-micro
```

### 2. Оновіть конфігурацію

**До (nuxt-i18n):**

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    defaultLocale: 'en',
    vueI18n: './i18n.config.js',
    detectBrowserLanguage: { useCookie: true },
  },
})
```

**Після (Nuxt I18n Micro v3):**

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    localeCookie: 'user-locale',
    autoDetectLanguage: true,
  },
})
```

### 3. Реорганізуйте файли перекладів

Перенесіть переклади до теки `locales` у форматі JSON. Ось повне порівняння проєкту:

**Before (`nuxt-i18n`):**

```text
my-app/
├── i18n/
│   └── locales/          # langDir
│       ├── en.json       # all translations in one file
│       ├── ru.json
│       └── de.json
├── pages/
│   ├── index.vue
│   └── page.vue
├── server/
│   └── tsconfig.json
├── nuxt.config.ts        # config will change
└── package.json
```

**After (Nuxt I18n Micro):**

```text
my-app/
├── locales/              # translationDir
│   ├── en.json           # root-level translations
│   ├── ru.json
│   ├── de.json
│   └── pages/            # page-specific
│       ├── index/
│       │   ├── en.json
│       │   ├── ru.json
│       │   └── de.json
│       └── page/
│           ├── en.json
│           ├── ru.json
│           └── de.json
├── pages/
│   ├── index.vue         # API changes
│   └── page.vue
├── server/
│   └── tsconfig.json
├── nuxt.config.ts        # new config
└── package.json
```

<Tip>
Missing page-specific translation files are **auto-generated** in development mode — just run `nuxt dev` and the module will create empty JSON files for each page and locale.
</Tip>

### 4. Оновіть навігацію

```diff
- <nuxt-link :to="{ name: 'index' }">Home</nuxt-link>
+ <NuxtLink :to="$localeRoute({ name: 'index' })">Home</NuxtLink>
+ <!-- or use the built-in component -->
+ <i18n-link :to="{ name: 'index' }">Home</i18n-link>
```

### 5. Оновіть SEO

Видаліть будь-які ручні SEO-налаштування з `nuxt-i18n`. Nuxt I18n Micro автоматично генерує `hreflang`, канонічні URL та теги Open Graph, коли встановлено `meta: true`.

### 6. Тестування

Ретельно перевірте переклади, перемикання локалей, перенаправлення та SEO-мета-теги.

---

## 🛡️ Поширені проблеми та їх усунення

### ❌ Файли перекладів не завантажуються

Переконайтеся, що файли перекладів знаходяться в правильній теці та відповідають формату JSON. Перевірте, що `translationDir` відповідає розташуванню ваших файлів.

### ⚠️ Помилки «Route Not Found»

Перевірте, що всі коди локалей у масиві `locales` є коректними та що маршрути належно налаштовані.

### 🏷️ Відсутні SEO-теги

Переконайтеся, що встановлено `meta: true` і що кожна локаль має валідний `iso`-код.

### 🔄 Розбіжності гідратації

Якщо використовуєте стратегію `no_prefix`, встановіть локаль у серверному плагіні з `order: -10` за допомогою `useI18nLocale().setLocale()`, щоб сервер та клієнт узгодили локаль. Див. [Кастомне визначення мови](/guides/custom-language-detection).

### 🍪 Перенаправлення не працюють

Для стратегій із префіксом переконайтеся, що встановлено `localeCookie: 'user-locale'`. Без cookie серверний плагін перенаправлення не має способу запамʼятати обрану користувачем локаль між перезавантаженнями сторінки.
