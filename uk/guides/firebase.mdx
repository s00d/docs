# 🔥 Розгортання у Firebase AppHosting

## 📖 Вступ

Firebase AppHosting — потужна платформа для розгортання Nuxt-застосунків з serverless-інфраструктурою. Однак при розгортанні застосунків з `nuxt-i18n-micro` ви можете зіштовхнутися з конкретними проблемами, повʼязаними з тим, як подаються JSON-файли перекладу. Цей посібник надає комплексні рішення, щоб забезпечити коректну роботу ваших перекладів у продакшені.

## ⚠️ Поширені проблеми

### Файли перекладів не застосовуються

**Симптоми:**

- ✅ Переклади ідеально працюють у розробці (`nuxt dev`)
- ❌ Після розгортання у Firebase AppHosting JSON-файли завантажуються, але переклади не застосовуються
- ❌ У консолі немає помилок
- ❌ Файли перекладу видно у вкладці Network, але з некоректним `Content-Type: text/html` замість `application/json`

**Корінь проблеми:**

Firebase AppHosting (та інші платформи, що використовують Nitro-prerender) можуть подавати prerender-ні JSON-файли з некоректними MIME-типами. Коли браузер отримує JSON-файли з `Content-Type: text/html`, він не може їх належно розпарсити, і переклади мовчки не спрацьовують.

## ✅ Рішення

### Рішення 1: конфігурація Route Rules (рекомендовано)

Найпряміше рішення — додати явні заголовки для маршрутів перекладу у ваш `nuxt.config.ts`:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**Переваги:**

- ✨ Просте налаштування
- 🚀 Покращує продуктивність з належним кешуванням
- 🔒 Працює на всіх платформах розгортання

### Рішення 2: кастомний API Base URL

Якщо ви використовуєте кастомний `apiBaseUrl` (лише префікс шляху), відповідно налаштуйте route rules:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### Рішення 3: Firebase-специфічна конфігурація

Створіть або оновіть файл `firebase.json` у корені проєкту:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```


### Рішення 4: конфігурація Firebase Functions

Для розгортання Firebase Functions переконайтеся, що ваш `functions/package.json` містить необхідні залежності:

```json
{
  "name": "functions",
  "type": "module",
  "engines": {
    "node": "18"
  },
  "dependencies": {
    "firebase-admin": "^12.0.0",
    "firebase-functions": "^5.0.0"
  }
}
```

## 🔍 Налагодження

### Увімкніть debug-режим

Додайте debug-логування, щоб визначити проблеми:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

Це видасть детальні логи щодо:

- 📝 Завантаження файлів перекладу
- 🔄 Операцій кешу
- ⚠️ Помилок завантаження

### Перевірте вкладку Network

1. Відкрийте DevTools → вкладку Network
2. Відфільтруйте за «data.json»
3. Клікніть на запит файлу перекладу
4. Перевірте **Response Headers**:
   - ✅ `Content-Type: application/json` (правильно)
   - ❌ `Content-Type: text/html` (неправильно — потрібно виправити)

### Перевірте вивід prerender

Після збірки перевірте, що файли перекладу згенеровані:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

Ви маєте побачити `data.json` для кожної локалі на кожній сторінці.

## 🚀 Конфігурація збірки

### Nitro-пресет

Для Firebase AppHosting переконайтеся, що ви використовуєте правильний пресет:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### Конфігурація prerender

Налаштуйте prerender для оптимальної продуктивності:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

## ✅ Чек-лист перевірки

Після застосування виправлень перевірте, що все працює:

- [ ] Збірка завершується без помилок
- [ ] JSON-файли перекладу є у `.output/public/_locales/\{page\}/\{locale\}/data.json`
- [ ] Вкладка Network показує `Content-Type: application/json` для файлів перекладу
- [ ] Переклади коректно відображаються при першому завантаженні сторінки
- [ ] Немає розбіжностей гідратації у консолі
- [ ] Перемикання мови працює правильно
- [ ] SEO-мета теги генеруються належним чином

## 🔄 Робочий процес розгортання

### 1. Підготовка збірки

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. Розгортання у Firebase

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. Перевірка розгортання

1. Відвідайте розгорнутий сайт
2. Відкрийте DevTools → вкладку Network
3. Перейдіть на сторінку
4. Перевірте, що `/_locales/index/en/data.json` (або ваша локаль за замовчуванням) завантажується з:
   - Status: 200
   - Content-Type: application/json
   - Відповідь містить валідний JSON

## 🔧 Пошук проблем

### Проблема: 404 для файлів перекладу

**Рішення:** переконайтеся, що файли перекладу копіюються у теку виводу:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### Проблема: переклади працюють на одних сторінках, але не на інших

**Рішення:** перевірте, чи генеруються посторінкові переклади:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

Якщо посторінкові переклади відсутні, переконайтеся, що `disablePageLocales` не встановлено у `true`:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### Проблема: повільне завантаження перекладів

**Рішення:** оптимізуйте кешування та попереднє завантаження:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

1. **Завжди тестуйте у середовищі, наближеному до продакшена** перед розгортанням

3. **Моніторте частоту потрапляння в кеш**, щоб оптимізувати продуктивність

## ⚡ Оптимізація продуктивності

### Увімкнення стиснення

Firebase автоматично обробляє Gzip/Brotli-стиснення, але переконайтеся, що ваша збірка оптимізована:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### Ліниве завантаження перекладів

`Nuxt I18n Micro` автоматично лінько завантажує переклади посайтово. Переклади завантажуються лише за потреби, зменшуючи початковий розмір бандла. Це вбудована функціональність — додаткова конфігурація не потрібна.

Для подальшої оптимізації:

- Використовуйте `disablePageLocales: false` (за замовчуванням), щоб увімкнути посайтові переклади
- Тримайте root-переклади мінімальними
- Використовуйте посайтові файли перекладу для контенту сторінок

<Tip>
Модуль автоматично встановлює правильні заголовки `Content-Type` починаючи з версії **v3.0.0+**. Якщо у вас проблеми, оновіться до останньої версії:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
