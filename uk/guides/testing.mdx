# 🧪 Тестування модуля `Nuxt I18n Micro`

## 📖 Вступ до тестування

Тестування модуля `Nuxt I18n Micro` є критично важливим, щоб забезпечити коректну роботу можливостей локалізації вашого застосунку. Ця документація проведе вас через налаштування середовища тестування, створення мокованих конфігурацій для vitest та написання тестів для ваших компонентів. Для практичного прикладу зверніться до [прикладу проєкту на GitHub](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/test-utils/example).

Див. [Testing routing strategies](https://github.com/s00d/nuxt-i18n-micro/blob/main/docs/guide/testing-strategies.md), щоб дізнатися, як цей репозиторій запускає власні набори тестів — Vitest-проєкти `unit` / `integration` / `e2e`, файли для кожної стратегії (`test/strategies-*.test.ts`) та генеруючі регресії.

## 🛠️ Налаштування середовища тестування

### 1. Встановіть `@i18n-micro/test-utils`

Спочатку встановіть тестові утиліти для `Nuxt I18n Micro`. Цей пакет надає необхідні інструменти для мокування та тестування ваших i18n-конфігурацій.

```bash
npm install @i18n-micro/test-utils --save-dev
```

### 2. Створіть файл мокової конфігурації

Далі створіть файл для налаштування мокової i18n-конфігурації. Цей файл використовуватиметься для мокування i18n-функцій та утиліт під час ваших тестів.

```typescript
// tests/unit-setup.ts

import { mockNuxtImport } from '@nuxt/test-utils/runtime'
import { vi } from 'vitest'
import { i18nUtils } from '@i18n-micro/test-utils'

export function createFakeI18n() {
  return {
    $getLocale: vi.fn(i18nUtils.getLocale),
    $t: vi.fn(i18nUtils.t),
    $tc: vi.fn(i18nUtils.tc),
    $setLocale: vi.fn(i18nUtils.setLocale),
    $getLocaleName: vi.fn(i18nUtils.getLocaleName),
    $setLocaleName: vi.fn(i18nUtils.setLocaleName),
    $getLocales: vi.fn(i18nUtils.getLocales),
    $setLocales: vi.fn(i18nUtils.setLocales),
    $defaultLocale: vi.fn(i18nUtils.defaultLocale),
    $setDefaultLocale: vi.fn(i18nUtils.setDefaultLocale),
    $getRouteName: vi.fn(i18nUtils.getRouteName),
    $settRouteName: vi.fn(i18nUtils.settRouteName),
    $ts: vi.fn(i18nUtils.ts),
    $tn: vi.fn(i18nUtils.tn),
    $td: vi.fn(i18nUtils.td),
    $has: vi.fn(i18nUtils.has),
    $resolveTranslations: vi.fn(i18nUtils.resolveTranslations),
    $setTranslation: vi.fn(i18nUtils.setTranslation),
    $mergeTranslations: vi.fn(i18nUtils.mergeTranslations),
    $switchLocaleRoute: vi.fn(i18nUtils.switchLocaleRoute),
    $switchLocalePath: vi.fn(i18nUtils.switchLocalePath),
    $switchLocale: vi.fn(i18nUtils.switchLocale),
    $switchRoute: vi.fn(i18nUtils.switchRoute),
    $localeRoute: vi.fn(i18nUtils.localeRoute),
    $localePath: vi.fn(i18nUtils.localePath),
    $setI18nRouteParams: vi.fn(i18nUtils.setI18nRouteParams),
  }
}

mockNuxtImport<() => ReturnType<typeof createFakeI18n>>('useI18n', () => vi.fn(() => createFakeI18n()))

export const setTranslationsFromJson = i18nUtils.setTranslationsFromJson
```

### 3. Налаштуйте Vitest

Тепер налаштуйте Vitest на використання файлу мокової конфігурації та середовища тестування.

```typescript
// vitest.config.ts

import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    watch: false,
    setupFiles: ['./tests/unit-setup.ts'],
    include: ['./**/*.spec.ts'],
  },
})
```

## 🧪 Написання тестів

### Приклад компонента

Ось приклад простого компонента, який використовує composable `useI18n` для перекладу повідомлень.

```vue
<script setup lang="ts">
const { $t } = useI18n()

const props = defineProps({
  message: {
    type: String,
    default: null,
  },
})

// Test to see that $t works in script setup as well as the template
const message = props.message || $t('defaultMessage')
</script>

<template>
  <div>
    <p>Test from component: {{ $t('welcome') }}</p>
    <p data-testid="message">Test message from props: {{ message }}</p>
  </div>
</template>
```

### Файл тесту

Тепер напишімо тест для цього компонента.

```typescript
// tests/unit/example.spec.ts

import { describe, it, expect, beforeEach } from 'vitest'
import { mount } from '@vue/test-utils'
import ExampleComponent from '@/components/ExampleComponent.vue'
import fs from 'fs'
import path from 'path'
import { setTranslationsFromJson } from './unit-setup'

describe('ExampleComponent', () => {
  beforeEach(async () => {
    const fileContent = fs.readFileSync(path.join(__dirname, '../../locales/en-GB.json')).toString()
    await setTranslationsFromJson('en', JSON.parse(fileContent))
  })

  it('renders the welcome message correctly', () => {
    const wrapper = mount(ExampleComponent)
    expect(wrapper.text()).toContain('Test from component: Welcome')
  })

  it('renders the default message correctly', () => {
    const wrapper = mount(ExampleComponent)
    expect(wrapper.find('[data-testid="message"]').text()).toContain('Test message from props: Default Message')
  })

  it('renders the custom message correctly', () => {
    const wrapper = mount(ExampleComponent, {
      props: {
        message: 'Custom Message',
      },
    })
    expect(wrapper.find('[data-testid="message"]').text()).toContain('Test message from props: Custom Message')
  })
})
```

## 📝 Найкращі практики тестування

- **🔧 Мокуйте i18n-функції:** завжди мокуйте i18n-функції за допомогою `@i18n-micro/test-utils`, щоб забезпечити узгоджені та передбачувані результати тестів.
- **⚙️ Використовуйте Vitest для unit-тестів:** Vitest — потужний тестовий фреймворк для Vue-застосунків. Використовуйте його для написання unit-тестів для ваших компонентів.
- **📚 Документуйте свої тести:** чітко документуйте призначення та очікувані результати кожного тесту. Це допоможе підтримувати ясність та полегшить розуміння тестів для інших (або майбутнього вас).

## 📊 Методи-утиліти i18n

Нижче наведено таблицю, що описує всі методи-утиліти, надані `@i18n-micro/test-utils`.

| Метод                                           | Опис                                                                                                                                       |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `t(key, params, defaultValue)`                  | Перекладає ключ з опціональними параметрами та значенням за замовчуванням.                                                                 |
| `tc(key, params, defaultValue)`                 | Перекладає ключ з підтримкою множинних форм.                                                                                               |
| `setTranslationsFromJson(locale, translations)` | Завантажує переклади з JSON-обʼєкта для конкретної локалі.                                                                                 |
| `getLocale()`                                   | Повертає поточну локаль.                                                                                                                    |
| `setLocale(val)`                                | Встановлює поточну локаль.                                                                                                                   |
| `getLocaleName()`                               | Повертає імʼя поточної локалі.                                                                                                             |
| `setLocaleName(val)`                            | Встановлює імʼя поточної локалі.                                                                                                             |
| `getLocales()`                                  | Повертає список доступних локалей.                                                                                                         |
| `setLocales(val)`                               | Встановлює список доступних локалей.                                                                                                        |
| `defaultLocale()`                               | Повертає локаль за замовчуванням.                                                                                                                |
| `setDefaultLocale(val)`                         | Встановлює локаль за замовчуванням.                                                                                                                   |
| `getRouteName()`                                | Повертає імʼя поточного маршруту.                                                                                                            |
| `settRouteName(val)`                            | Встановлює імʼя поточного маршруту.                                                                                                               |
| `ts(key, params, defaultValue)`                 | Перекладає ключ та повертає результат як рядок.                                                                                            |
| `tn(value, options?)`                           | Форматує число з inline `Intl.NumberFormatOptions`. Іменовані формати потребують конфігурації модуля та недоступні у цьому окремому помічнику. |
| `td(value, options?)`                           | Форматує дату з inline `Intl.DateTimeFormatOptions`. Іменовані формати потребують конфігурації модуля та недоступні у цьому окремому помічнику. |
| `has(key)`                                      | Перевіряє, чи існує ключ перекладу.                                                                                                        |
| `resolveTranslations()`                         | Повертає активне дерево перекладів для поточної локалі та маршруту.                                                                       |
| `setTranslation(key, value)`                    | Замінює значення за `key` в активному словнику (заміна, не злиття).                                                                       |
| `mergeTranslations(newTranslations)`            | Зливає переклади в активну локаль під час виконання.                                                                                       |

Дотримуючись цих кроків, ви зможете ефективно тестувати модуль `Nuxt I18n Micro` та забезпечити коректну роботу можливостей локалізації вашого застосунку.
