# 🌐 Посібник з інтеграції Crowdin

## 📖 Вступ

Інтеграція Crowdin у ваш проєкт спрощує процес локалізації та перекладу, роблячи керування перекладами кількома мовами та платформами простішим. Цей посібник надає покроковий огляд налаштування Crowdin з вашим проєктом, включно з конфігурацією, вивантаженням джерел та завантаженням перекладів.

## 🔧 Встановлення та налаштування

Щоб почати роботу з Crowdin, вам потрібно встановити Crowdin CLI глобально на вашій машині та ініціалізувати його в теці проєкту.

### 📦 Встановлення Crowdin CLI

Спершу встановіть Crowdin CLI глобально через npm:

```bash
npm install -g @crowdin/cli
```

### 🛠 Ініціалізація Crowdin у вашому проєкті

Ініціалізуйте Crowdin у вашому проєкті:

```bash
crowdin init
```

Ця команда проведе вас через процес налаштування, включно з встановленням ID проєкту, API-токена та інших деталей конфігурації.

## 🗂️ Посібник з конфігурації

### 📄 Файл конфігурації Crowdin (`crowdin.yml`)

Файл конфігурації Crowdin (`crowdin.yml`) визначає, як мапляться ваші вихідні файли та куди мають потрапляти переклади. Ось приклад конфігурації:

```yml
'project_id': 'YOUR_PROJECT_ID'
'api_token': 'YOUR_API_TOKEN'
'base_path': './locales'
'base_url': 'https://api.crowdin.com'
'preserve_hierarchy': true

files:
  [
    { 'source': '/en.json', 'translation': '/%two_letters_code%.json' },
    { 'source': '/pages/**/en.json', 'translation': '/pages/**/%two_letters_code%.json' },
  ]
```

### 📂 Ключові параметри конфігурації

- **`project_id`**: ID вашого проєкту Crowdin. Він ідентифікує проєкт у Crowdin, де керуються переклади.
- **`api_token`**: API-токен для автентифікації. Переконайтеся, що цей токен має правильні дозволи для вивантаження та завантаження перекладів.
- **`base_path`**: вказує базову теку для вихідних файлів. У цьому прикладі переклади зберігаються у теці `./locales`.
- **`base_url`**: базовий URL API Crowdin.
- **`preserve_hierarchy`**: коли встановлено `true`, Crowdin зберігатиме структуру тек ваших вихідних файлів у проєкті.

### 📂 Конфігурація файлів

Секція `files` мапить ваші вихідні файли на шляхи, де зберігатимуться переклади. Наприклад:

- **Source Path**: визначає розташування оригінальних файлів перекладу.
- **Translation Path**: вказує, де перекладені файли зберігатимуться у Crowdin. Плейсхолдери на кшталт `%two_letters_code%` використовуються для динамічного встановлення коду мови у шляхах файлів.

## ⬆️ Вивантаження вихідних файлів у Crowdin

Коли конфігурація Crowdin налаштована, ви можете вивантажити свої вихідні файли за допомогою команди:

```bash
crowdin upload sources
```

Ця команда вивантажує всі вихідні файли, вказані у вашій конфігурації, у Crowdin, роблячи їх доступними для перекладу.

## ⬇️ Завантаження перекладів з Crowdin

Після завершення чи оновлення перекладів у Crowdin ви можете завантажити їх у проєкт командою:

```bash
crowdin download
```

Ця команда отримує найновіші переклади з Crowdin і зберігає їх відповідно до шляхів, вказаних у вашому файлі конфігурації.

## ⚙️ Кращі практики

### 🔑 Узгоджене іменування ключів

Забезпечте узгодженість ключів перекладу у всіх файлах, щоб уникнути плутанини та дублювання.

### 🧹 Регулярне обслуговування

Періодично переглядайте й прибирайте невикористовувані ключі перекладу, щоб ваші файли залишалися організованими та керованими.

### 🛠 Автоматизація вивантаження та завантаження

Інтегруйте CLI-команди Crowdin у ваш CI/CD-конвеєр, щоб автоматизувати вивантаження вихідних файлів та завантаження перекладів. Це гарантує, що ваші переклади завжди актуальні.

Дотримуючись цього посібника, ви зможете безшовно інтегрувати Crowdin у ваш проєкт, забезпечуючи ефективний та організований підхід до керування вашими зусиллями з інтернаціоналізації.
