# 🌐 Гайд з інтеграції Crowdin

## 📖 Вступ

Інтеграція Crowdin у ваш проєкт спрощує процес локалізації та перекладу, полегшуючи керування перекладами кількома мовами та платформами. Цей гайд надає покроковий інструктаж з налаштування Crowdin у вашому проєкті, включно з конфігурацією, завантаженням джерел та завантаженням перекладів.

## 🔧 Встановлення та налаштування

Щоб почати роботу з Crowdin, вам потрібно встановити Crowdin CLI глобально на вашій машині та ініціалізувати його у теці вашого проєкту.

### 📦 Встановлення Crowdin CLI

Спочатку встановіть Crowdin CLI глобально через npm:

```bash
npm install -g @crowdin/cli
```

### 🛠 Ініціалізація Crowdin у вашому проєкті

Ініціалізуйте Crowdin у вашому проєкті, виконавши:

```bash
crowdin init
```

Ця команда проведе вас через процес налаштування, включно з встановленням ідентифікатора проєкту, API-токена та інших деталей конфігурації.

## 🗂️ Гайд з конфігурації

### 📄 Файл конфігурації Crowdin (`crowdin.yml`)

Файл конфігурації Crowdin (`crowdin.yml`) визначає, як мапляться ваші source-файли та куди мають розміщуватися переклади. Нижче наведено приклад конфігурації:

```yml
'project_id': 'YOUR_PROJECT_ID'
'api_token': 'YOUR_API_TOKEN'
'base_path': './locales'
'base_url': 'https://api.crowdin.com'
'preserve_hierarchy': true

files:
  [
    { 'source': '/en.json', 'translation': '/%two_letters_code%.json' },
    { 'source': '/pages/**/en.json', 'translation': '/pages/**/%two_letters_code%.json' },
  ]
```

### 📂 Ключові параметри конфігурації

- **`project_id`**: ідентифікатор вашого Crowdin-проєкту. Він ідентифікує проєкт у Crowdin, де керуються переклади.
- **`api_token`**: API-токен, що використовується для автентифікації. Переконайтеся, що цей токен має правильні дозволи для завантаження та вивантаження перекладів.
- **`base_path`**: вказує базову теку для source-файлів. У цьому прикладі переклади зберігаються у теці `./locales`.
- **`base_url`**: базовий URL для API Crowdin.
- **`preserve_hierarchy`**: коли встановлено `true`, Crowdin збереже структуру тек ваших source-файлів у проєкті.

### 📂 Конфігурація файлів

Секція `files` мапить ваші source-файли на шляхи, де зберігатимуться переклади. Наприклад:

- **Source Path**: визначає розташування оригінальних файлів перекладу.
- **Translation Path**: вказує, де перекладені файли зберігатимуться у Crowdin. Плейсхолдери, як-от `%two_letters_code%`, використовуються для динамічного встановлення коду мови у шляхах файлів.

## ⬆️ Завантаження source-файлів до Crowdin

Коли конфігурацію Crowdin налаштовано, ви можете завантажити ваші source-файли за допомогою такої команди:

```bash
crowdin upload sources
```

Ця команда завантажує всі вказані у вашій конфігурації source-файли до Crowdin, роблячи їх доступними для перекладу.

## ⬇️ Отримання перекладів з Crowdin

Після того як переклади завершено або оновлено в Crowdin, ви можете завантажити їх у ваш проєкт за допомогою:

```bash
crowdin download
```

Ця команда отримує останні переклади з Crowdin та зберігає їх відповідно до шляхів, вказаних у файлі конфігурації.

## ⚙️ Найкращі практики

### 🔑 Узгоджене іменування ключів

Забезпечте узгодженість ключів перекладу у всіх файлах, щоб уникнути плутанини та дублювання.

### 🧹 Регулярне обслуговування

Періодично переглядайте та очищуйте невикористані ключі перекладу, щоб тримати ваші файли організованими та керованими.

### 🛠 Автоматизуйте завантаження та отримання

Інтегруйте команди Crowdin CLI у ваш CI/CD-pipeline, щоб автоматизувати завантаження source-файлів та отримання перекладів, забезпечуючи, що ваші переклади завжди актуальні.

Дотримуючись цього гайду, ви зможете безшовно інтегрувати Crowdin у ваш проєкт, забезпечуючи ефективний та організований підхід до керування вашими зусиллями з інтернаціоналізації.
