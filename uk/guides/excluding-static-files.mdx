# Виключення статичних файлів з i18n-маршрутизації

## Огляд

За замовчуванням nuxt-i18n-micro автоматично виключає поширені статичні файли з обробки i18n-маршрутизації. Однак ви також можете налаштувати кастомні шаблони виключення, щоб запобігти обробці конкретних шляхів системою i18n.

## Вбудовані виключення

Модуль автоматично виключає наступні типи файлів та шаблони:

- **Sitemap-и**: `/sitemap*.xml`, `/sitemap-en.xml` тощо.
- **SEO-файли**: `/robots.txt`, `/favicon.ico`
- **PWA-файли**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Статичні ресурси**: файли з розширеннями `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Внутрішні шляхи Nuxt**: будь-який шлях, що починається з `__` (наприклад, `/__nuxt/`)

## Кастомні шаблони виключення

Ви можете визначити кастомні шаблони виключення через опцію `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Типи шаблонів

### Рядкові шаблони

- **Точне співпадіння**: `'/api/health'` — відповідає точно `/api/health`
- **Співпадіння за префіксом**: `'/admin'` — відповідає `/admin` та `/admin/dashboard`
- **Wildcards**: `'/api/*'` — відповідає `/api/users`, але не `/api/users/123`
- **Глибокі wildcards**: `'/admin/**'` — відповідає `/admin/users` та `/admin/users/123`

### Регулярні вирази

Використовуйте обʼєкти RegExp для складнішого співставлення шаблонів:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Сценарії використання

### SEO-файли

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API-маршрути

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Адмін-панелі

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Статичні ресурси

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Як це працює

1. **Server Middleware**: спочатку виконується Nitro middleware для перевірки шаблонів виключення
2. **Обробка сторінки**: під час розвʼязання сторінки виключені шляхи пропускаються
3. **Catch-all маршрут**: резервний маршрут перевіряє виключення перед обробкою
4. **Prerendering**: виключені шляхи не включаються у пре-рендерені маршрути

## Вплив на продуктивність

- Перевірки виключень оптимізовані та виконуються рано у життєвому циклі запиту
- Вбудовані шаблони використовують ефективне співставлення з regex
- Кастомні шаблони кешуються та повторно використовуються
- Мінімальні накладні витрати продуктивності для виключених шляхів

## Усунення несправностей

### Статичні файли все ще перехоплюються

1. **Перевірте синтаксис шаблону**: переконайтеся, що ваші шаблони відповідають точній структурі шляху
2. **Використовуйте regex для складних шаблонів**: рядкові wildcards мають обмеження
3. **Тестуйте шаблони**: використовуйте devtools браузера, щоб перевірити фактичний шлях запиту
4. **Перевірте порядок**: переконайтеся, що шаблони виключення визначено перед іншою i18n-конфігурацією

### Шаблон не працює

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Режим debug

Увімкніть режим debug, щоб побачити обробку виключень:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Це логуватиме рішення про виключення в консолі.

## Міграція з обхідних шляхів

Якщо ви використовували обхідні шляхи, як-от route rules або middleware, тепер ви можете замінити їх на `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Новий підхід є надійнішим і працює на кількох рівнях системи маршрутизації.
