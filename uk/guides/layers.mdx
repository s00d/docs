# 🗂️ Шари у `Nuxt I18n Micro`

## 📖 Вступ до шарів

Шари у `Nuxt I18n Micro` дозволяють гнучко керувати та налаштовувати параметри локалізації у різних частинах вашого застосунку. Визначаючи різні шари, ви можете підлаштовувати конфігурацію під різні контексти: перевизначати налаштування для конкретних секцій сайту або створювати багаторазові базові конфігурації, які можуть розширювати інші частини застосунку.

## 🛠️ Основний шар конфігурації

**Основний шар конфігурації** — це місце, де ви задаєте налаштування локалізації за замовчуванням для всього застосунку. Цей шар є ключовим, бо визначає глобальну конфігурацію, включно з підтримуваними локалями, мовою за замовчуванням та іншими критичними налаштуваннями i18n.

### 📄 Приклад: визначення основного шару конфігурації

Ось приклад того, як ви можете визначити основний шар конфігурації у файлі `nuxt.config.ts`:

```typescript
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', iso: 'en-EN', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en', // The default locale for the entire app
    translationDir: 'locales', // Directory where translations are stored
    meta: true, // Automatically generate SEO-related meta tags like `alternate`
    autoDetectLanguage: true, // Automatically detect and use the user's preferred language
  },
})
```

## 🌱 Дочірні шари

Дочірні шари використовуються, щоб розширювати або перевизначати основну конфігурацію для конкретних частин застосунку. Наприклад, ви можете захотіти додати додаткові локалі або змінити локаль за замовчуванням для окремої секції сайту. Дочірні шари особливо корисні у модульних застосунках, де різні частини можуть мати різні вимоги до локалізації.

### 📄 Приклад: розширення основного шару у дочірньому

Припустімо, у вас є секція сайту, яка має підтримувати додаткові локалі, або ви хочете вимкнути конкретну локаль у певному контексті. Ось як цього досягти, розширивши основний шар конфігурації:

```typescript
// basic/nuxt.config.ts (Primary Layer)
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', iso: 'en-EN', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
    meta: true,
    translationDir: 'locales',
  },
})
```

```typescript
// extended/nuxt.config.ts (Child Layer)
export default defineNuxtConfig({
  extends: '../basic', // Inherit the base configuration from the 'basic' layer
  i18n: {
    locales: [
      { code: 'en', iso: 'en-EN', dir: 'ltr' }, // Inherited from the base layer
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' }, // Inherited from the base layer
      { code: 'de', iso: 'de-DE', dir: 'ltr' }, // Added in the child layer
    ],
    defaultLocale: 'fr', // Override the default locale to French for this section
    autoDetectLanguage: false, // Disable automatic language detection in this section
  },
})
```

### 🌐 Використання шарів у модульному застосунку

У великому модульному Nuxt-застосунку у вас можуть бути кілька секцій, кожна з яких потребує власних налаштувань i18n. Використовуючи шари, ви можете підтримувати чисту й масштабовану структуру конфігурації.

### 📄 Приклад: шарова конфігурація у модульному застосунку

Уявіть, що у вас є e-commerce сайт з окремими секціями: основний сайт, адмін-панель та портал підтримки клієнтів. Кожна секція може потребувати свого набору локалей або інших налаштувань i18n.

#### **Основний шар (глобальна конфігурація):**

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', iso: 'en-EN', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
    meta: true,
    translationDir: 'locales',
    autoDetectLanguage: true,
  },
})
```

#### **Дочірній шар для адмін-панелі:**

```typescript
// admin/nuxt.config.ts
export default defineNuxtConfig({
  extends: '../nuxt.config', // Inherit the global settings
  i18n: {
    locales: [
      { code: 'en', iso: 'en-EN', dir: 'ltr' }, // Inherited
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' }, // Inherited
      { code: 'es', iso: 'es-ES', dir: 'ltr' }, // Specific to the admin panel
    ],
    defaultLocale: 'en',
    meta: false, // Disable automatic meta generation in the admin panel
  },
})
```

#### **Дочірній шар для порталу підтримки:**

```typescript
// support/nuxt.config.ts
export default defineNuxtConfig({
  extends: '../nuxt.config', // Inherit the global settings
  i18n: {
    locales: [
      { code: 'en', iso: 'en-EN', dir: 'ltr' }, // Inherited
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' }, // Inherited
      { code: 'de', iso: 'de-DE', dir: 'ltr' }, // Specific to the support portal
    ],
    defaultLocale: 'de', // Default to German in the support portal
    autoDetectLanguage: false, // Disable automatic language detection
  },
})
```

У цьому модульному прикладі:

- Кожна секція (admin, support) має власні налаштування i18n, але всі вони успадковують базову конфігурацію.
- Адмін-панель додає іспанську (`es`) як локаль і вимикає генерацію мета-тегів.
- Портал підтримки додає німецьку (`de`) як локаль і використовує її як мову за замовчуванням для інтерфейсу.

## 📝 Кращі практики використання шарів

- **🔧 Тримайте основний шар простим:** основний шар має містити найпоширеніші налаштування, які застосовуються глобально у застосунку. Тримайте його лаконічним, щоб забезпечити узгодженість.
- **⚙️ Використовуйте дочірні шари для конкретних кастомізацій:** перевизначайте чи розширюйте налаштування у дочірніх шарах лише за необхідності. Такий підхід уникає зайвої складності у конфігурації.
- **📚 Документуйте свої шари:** чітко документуйте призначення й особливості кожного шару у вашому проєкті. Це допоможе підтримувати ясність та полегшить розуміння конфігурації іншим (чи вам у майбутньому).
