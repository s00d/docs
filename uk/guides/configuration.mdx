# Довідник з конфігурації

Повний довідник для кожної опції під ключем `i18n` у `nuxt.config`. Типи й значення за замовчуванням відповідають [`ModuleOptions`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts) у `@i18n-micro/types`.

## Швидкий довідник

Кожна опція, яку приймає модуль, взята з типу `ModuleOptions`. Розділи нижче пояснюють, як вони працюють разом; [Довідник опцій модуля](/api/module-options) містить повні описи.

# Деталі опцій

Модуль надає широкі можливості конфігурації, щоб налаштувати ваше i18n-налаштування.

### 🌍 Основні налаштування локалей

#### `locales`

{/* generated:option:locales — do not edit; run `pnpm run docs:generate` */}

**Тип** `Locale[]` · **За замовчуванням** `[]`

Список підтримуваних локалей.
Кожен запис визначає код локалі плюс опційні метадані (ISO, напрямок, відображуване імʼя тощо).

{/* /generated:option:locales */}

Кожен обʼєкт локалі підтримує:

| Властивість      | Тип       | Обовʼязково | Опис                                                    |
| ---------------- | --------- | ----------- | ------------------------------------------------------- |
| `code`           | `string`  | ✅          | Унікальний ідентифікатор (наприклад, `'en'`)            |
| `displayName`    | `string`  | ❌          | Людське імʼя для перемикачів (наприклад, `'English'`)   |
| `iso`            | `string`  | ❌          | ISO-код (наприклад, `'en-US'`)                          |
| `dir`            | `string`  | ❌          | Напрямок тексту (`'ltr'` або `'rtl'`)                   |
| `disabled`       | `boolean` | ❌          | Вимкнути у dropdown при `true`                          |
| `baseUrl`        | `string`  | ❌          | Базовий URL для locale-specific доменів                 |
| `baseDefault`    | `boolean` | ❌          | Прибрати префікс локалі з URL                           |
| `fallbackLocale` | `string`  | ❌          | Посайтовий fallback (перевизначає глобальний)           |
| `[key: string]`  | `unknown` | ❌          | Будь-які кастомні властивості (див. нижче)              |

**Приклад**:

```typescript
locales: [
  { code: 'en', iso: 'en-US', dir: 'ltr' },
  { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
  { code: 'ar', iso: 'ar-SA', dir: 'rtl', disabled: true },
  {
    code: 'de',
    iso: 'de-DE',
    dir: 'ltr',
    baseUrl: 'https://de.example.com',
    baseDefault: true,
  },
]
```

<Warning>
Використання `baseUrl` може призвести до дублювання внутрішніх маршрутів як зовнішніх посилань, ускладнюючи маршрутизацію та супровід. Розгляньте створення зовнішніх посилань напряму для конкретних локалей.
</Warning>

#### Кастомні властивості локалі

Ви можете додавати будь-які кастомні властивості до обʼєктів локалі. Вони передаються у рантайм і доступні через `$getLocales()`:

```typescript
locales: [
  { code: 'en', iso: 'en-US', flag: '🇬🇧', currency: 'GBP' },
  { code: 'de', iso: 'de-DE', flag: '🇩🇪', currency: 'EUR' },
  { code: 'ru', iso: 'ru-RU', flag: '🇷🇺', currency: 'RUB' },
]
```

Доступ у компонентах:

```vue
<template>
  <ul>
    <li v-for="locale in $getLocales()" :key="locale.code">{{ locale.flag }} {{ locale.displayName }} ({{ locale.currency }})</li>
  </ul>
</template>
```

За замовчуванням кастомні властивості типізовані як `unknown`. Для повної підтримки TypeScript використовуйте **аугментацію модуля**. Створіть файл декларацій (наприклад, `app/i18n.d.ts` або будь-який `.d.ts`, включений у ваш `tsconfig`):

```typescript
// app/i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
    currency?: string
  }
}
```

Після цього всі кастомні властивості повністю типізовані:

```typescript
const locales = $getLocales()
locales[0].flag // string | undefined ✅
locales[0].currency // string | undefined ✅
```

#### `defaultLocale`

{/* generated:option:defaultLocale — do not edit; run `pnpm run docs:generate` */}

**Тип** `string` · **За замовчуванням** `'en'`

Локаль, що використовується, коли її неможливо визначити з URL чи уподобань користувача.
Також використовується як fallback-локаль для відсутніх перекладів, коли `fallbackLocale` не задано.

{/* /generated:option:defaultLocale */}

```typescript
defaultLocale: 'en'
```

#### `strategy`

{/* generated:option:strategy — do not edit; run `pnpm run docs:generate` */}

**Тип** `Strategies` · **За замовчуванням** `'prefix_except_default'`

Стратегія URL-маршрутизації для префіксів локалей.

- `'no_prefix'` — без локалі в URL; локаль зберігається у cookie.
- `'prefix_except_default'` — префікс усім локалям, крім за замовчуванням.
- `'prefix'` — завжди префікс, включно з локаллю за замовчуванням.
- `'prefix_and_default'` — як `prefix`, але локаль за замовчуванням також доступна без префікса.

{/* /generated:option:strategy */}

<CodeGroup>
```typescript no_prefix
strategy: 'no_prefix'
// Routes: /about, /contact
// Locale detection via browser/cookies
```

```typescript prefix_except_default
strategy: 'prefix_except_default'
// Default locale: /about, /contact
// Other locales: /fr/about, /de/contact
```

```typescript prefix
strategy: 'prefix'
// All locales: /en/about, /fr/about, /de/about
```

```typescript prefix_and_default
strategy: 'prefix_and_default'
// Both prefixed and non-prefixed versions for default locale
```
</CodeGroup>

### 📂 Керування перекладами

#### `translationDir`

{/* generated:option:translationDir — do not edit; run `pnpm run docs:generate` */}

**Тип** `string` · **За замовчуванням** `'locales'`

Шлях до каталогу з JSON-файлами перекладів, відносно кореня проєкту.

{/* /generated:option:translationDir */}

```typescript
translationDir: 'i18n' // Custom directory
// Nuxt 4 colocation example:
// translationDir: 'app/locales'
```

Шляхи розвʼязуються від **кореня Nuxt-проєкту** (`rootDir`), а не від `app/`. З Nuxt 4 звичайне налаштування — `app/pages/` для маршрутів та `locales/` (або `app/locales`, якщо задано `translationDir`) для JSON-файлів.

#### `disablePageLocales`

{/* generated:option:disablePageLocales — do not edit; run `pnpm run docs:generate` */}

**Тип** `boolean` · **За замовчуванням** `false`

Вимкнути посайтові файли перекладів.
Коли `true`, завантажуються лише глобальні переклади (`\{locale\}.json`); посайтові файли (`pages/\{page\}/\{locale\}.json`) не генеруються і не завантажуються.

{/* /generated:option:disablePageLocales */}

Коли увімкнено, використовуються лише root-файли перекладів:

```tree
locales/
├── en.json
├── fr.json
└── ar.json
```

#### `fallbackLocale`

{/* generated:option:fallbackLocale — do not edit; run `pnpm run docs:generate` */}

**Тип** `string` · **За замовчуванням** `undefined (без fallback; повертає сирий ключ)`

Код глобальної fallback-локалі.
Коли ключ перекладу відсутній в активній локалі, модуль шукає його у цій локалі перед тим, як повернути сам ключ.

{/* /generated:option:fallbackLocale */}

```typescript
fallbackLocale: 'en' // Global fallback
```

#### `types`

{/* generated:option:types — do not edit; run `pnpm run docs:generate` */}

**Тип** `boolean` · **За замовчуванням** `true`

Генерувати декларації типів TypeScript для `useI18n`, `$t` та повʼязаних помічників на основі ключів перекладів у ваших файлах локалі за замовчуванням.

{/* /generated:option:types */}

Коли увімкнено, модуль видає `.nuxt/i18n.d.ts` під час збірки з типізованими ключами перекладу. Встановіть `false`, якщо ви віддаєте перевагу нетипізованим помічникам або використовуєте зовнішній генератор.

Цей вбудований генератор окремий від опціонального пакета [`@i18n-micro/types-generator`](/integrations/types-generator), який може продукувати суворіші або окремі файли типів для monorepo та CI.

```typescript
types: false // Disable built-in key typing
```

#### `routeLocales`

{/* generated:option:routeLocales — do not edit; run `pnpm run docs:generate` */}

**Тип** `Record<string, string[]>` · **За замовчуванням** —

Посайтові обмеження локалей, витягнуті з викликів `defineI18nRoute()`.
Мапить шлях маршруту (наприклад, `'/about'`) на масив дозволених кодів локалей.
Маршрути, не перелічені тут, не мають обмежень (усі локалі дозволені).

{/* /generated:option:routeLocales */}

Мапить шлях маршруту (наприклад, `'/about'`) на дозволені коди локалей. Маршрути, не перелічені, дозволяють усі налаштовані локалі.

Зазвичай ви налаштовуєте це через [`defineI18nRoute`](/guides/custom-locale-routes) на сторінках, а не в `nuxt.config`. Модуль зливає посайтові оголошення у цю мапу на етапі збірки.

#### `routeDisableMeta`

{/* generated:option:routeDisableMeta — do not edit; run `pnpm run docs:generate` */}

**Тип** `Record<string, boolean \| string[]>` · **За замовчуванням** —

Посайтове вимкнення мета-тегів, витягнуте з викликів `defineI18nRoute()`.
Мапить шлях маршруту на `true` (вимкнути всі мета) або масив кодів локалей, для яких мета має бути вимкнене.

{/* /generated:option:routeDisableMeta */}

- `true` — вимкнути всі SEO мета для маршруту
- `string[]` — вимкнути мета лише для перелічених кодів локалей

Як і `routeLocales`, зазвичай встановлюється у компонентах сторінок, а не вручну у конфігу.

#### `experimental`

{/* generated:option:experimental — do not edit; run `pnpm run docs:generate` */}

**Тип** `Record<string, unknown>` · **За замовчуванням** —

Кошик для експериментальних/нестабільних опцій.
Вміст може змінюватися чи видалятися без попередження між мінорними версіями.

{/* /generated:option:experimental */}

Більшість колишніх прапорців `experimental.*` було переведено на top-level опції у v3 (наприклад, `hmr`). Надавайте перевагу задокументованим top-level опціям. Використовуйте `experimental` лише коли слідуєте release note або посібнику з міграції, що посилається на конкретний ключ.

Автоматично генерувати SEO мета-теги (`hreflang`, `canonical`, `og:url`, `og:locale`).

{/* /generated:option:meta */}

```typescript
meta: true // Generate alternate links, canonical URLs, etc.
```

#### `metaBaseUrl`

{/* generated:option:metaBaseUrl — do not edit; run `pnpm run docs:generate` */}

**Тип** `string` · **За замовчуванням** `undefined`

Базовий URL для SEO мета-тегів (canonical, og:url, hreflang).

- Конкретний URL-рядок (наприклад, `'https://example.com'`) — використовується як є (найвищий пріоритет).
- `undefined` — використовує `site.url` з `nuxt-site-config`, якщо цей модуль присутній, інакше origin поточного запиту (`useRequestURL().origin` на сервері, `window.location.origin` на клієнті).

{/* /generated:option:metaBaseUrl */}

#### `plural`

{/* generated:option:plural — do not edit; run `pnpm run docs:generate` */}

**Тип** `PluralFunc` · **За замовчуванням** `вбудована плюралізація (індекс форми за count)`

Кастомна функція плюралізації.
Отримує `(key, count, params, locale, getter)` і має повертати обрану плюральну форму як рядок, або `null`/`undefined`, щоб повернутися до вбудованої логіки `defaultPlural` (тож ви можете перевизначити лише деякі локалі).

Для Nuxt-модуля функція серіалізується через `.toString()` у `.nuxt/i18n.plural.mjs` — вона має бути самодостатньою (без імпортів / зовнішніх областей).
Рядок з шляхом до файла **не** підтримується.

{/* /generated:option:plural */}

##### Як це працює

Переклади використовують `|` для розділення плюральних форм:

```json
{
  "apples": "no apples | one apple | {count} apples"
}
```

Використовуйте `$tc('apples', count)` або `$tc('cart', \{ count, name \})`, коли формі потрібно більше ніж `\{count\}` — передавайте **`count` та інші параметри у другому аргументі-обʼєкті**, а не як третій аргумент (третій — лише `defaultValue`).

Виклик `$tc` викликає функцію `plural`, яка:

1. Викликає `t(key)`, щоб отримати сирий рядок перекладу (наприклад, `"no apples | one apple | \{count\} apples"`)
2. Ділить за `|`, щоб отримати масив форм
3. Обирає форму на основі `count`
4. Замінює `\{count\}` фактичним числом

**Стандартна** реалізація обирає за індексом: `count < forms.length ? forms[count] : forms[last]`. Це працює для простих випадків (0 → перша форма, 1 → друга, 2+ → остання).

##### Кастомна функція плюралів

Для мов зі складними правилами плюралізації (наприклад, українська, російська, арабська, польська) перевизначте опцію `plural`.

<Danger>
Функція серіалізується через `.toString()` і впорскується у віртуальний модуль на етапі збірки. Це означає:

- **Обовʼязково використовуйте ключове слово `function`** — НЕ shorthand-синтаксис методу, НЕ стрілкові функції із зовнішніми посиланнями
- **Без імпортів чи зовнішніх посилань** — функція має бути повністю самодостатньою (шлях до файла на кшталт `plural: '~/i18n/plural.ts'` **не** підтримується)
- **Без TypeScript-специфічного синтаксису**, який не переживе `.toString()` (анотації типів у `nuxt.config.ts` допустимі, бо Nuxt їх видаляє)
- Повернення `null` / `undefined` падає до вбудованого `defaultPlural` (корисно для посайтових перевизначень)
</Danger>

**Приклад: російська плюралізація** (4 форми: zero, one, few, many):

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    plural: function (key, count, _params, _locale, t) {
      const translation = t(key)
      if (!translation) return key

      const forms = translation
        .toString()
        .split('|')
        .map(function (s) {
          return s.trim()
        })
      let idx

      if (count === 0) {
        idx = 0
      } else {
        const mod10 = count % 10
        const mod100 = count % 100
        if (mod10 === 1 && mod100 !== 11) {
          idx = 1
        } else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) {
          idx = 2
        } else {
          idx = 3
        }
      }

      if (idx >= forms.length) idx = forms.length - 1
      return (forms[idx] || '').replace('{count}', String(count))
    },
  },
})
```

З таким перекладом:

```json
{
  "apples": "нет яблок | {count} яблоко | {count} яблока | {count} яблок"
}
```

Результати:

- `$tc('apples', 0)` → `"нет яблок"`
- `$tc('apples', 1)` → `"1 яблоко"`
- `$tc('apples', 3)` → `"3 яблока"`
- `$tc('apples', 5)` → `"5 яблок"`
- `$tc('apples', 21)` → `"21 яблоко"`

**Приклад: проста англійська (поведінка за замовчуванням)**:

```typescript
// This is the built-in default — you don't need to set it explicitly
plural: function (key, count, params, _locale, t) {
  const translation = t(key, params)
  if (!translation) return null

  const forms = translation.toString().split('|')
  if (forms.length === 0) return null
  const form = count < forms.length ? forms[count] : forms[forms.length - 1]
  if (!form) return null
  return form.trim().replace('{count}', count.toString())
}
```

Якщо різним локалям потрібні різні правила плюралів, розгалужуйте за `locale` і повертайте `null` для локалей, які не кастомізуєте, — вбудований `defaultPlural` опрацьовує решту:

```typescript

  // Only override Slavic locales; en/de/… keep the built-in rules
  if (locale !== 'ru' && locale !== 'uk') return null

  const translation = t(key)
  if (!translation) return null

  const forms = translation.toString().split('|').map(function (s) { return s.trim() })

  if (count === 0) {
    idx = 0

    const mod10 = count % 10
    const mod100 = count % 100

    else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) idx = 2
    else idx = 3
  }
  if (idx >= forms.length) idx = forms.length - 1
  return (forms[idx] || '').replace('{count}', String(count))
}
```

- Зберігає вподобання локалі користувача між перезавантаженнями сторінки

{/* /generated:option:apiBaseClientHost */}

**Змінна оточення**: `NUXT_I18N_APP_BASE_CLIENT_HOST`

```typescript
apiBaseClientHost: 'https://cdn.example.com'
```

Коли задано `apiBaseClientHost`, клієнтські переклади отримуватимуться з `\{apiBaseClientHost\}/\{apiBaseUrl\}/\{routeName\}/\{locale\}/data.json` (наприклад, `https://cdn.example.com/_locales/index/en/data.json`).

#### `apiBaseServerHost`

{/* generated:option:apiBaseServerHost — do not edit; run `pnpm run docs:generate` */}

**Тип** `string` · **За замовчуванням** `undefined`

Перевизначає хост для серверних запитів на завантаження перекладів.
Корисно у контейнерних/мікросервісних налаштуваннях, де сервер досягає себе через внутрішнє імʼя хоста.
Також можна задати через змінну оточення `NUXT_I18N_APP_BASE_SERVER_HOST`.

{/* /generated:option:apiBaseServerHost */}

**Змінна оточення**: `NUXT_I18N_APP_BASE_SERVER_HOST`

```typescript
apiBaseServerHost: 'https://internal-cdn.example.com'
```

Коли задано `apiBaseServerHost`, серверні переклади отримуватимуться з `\{apiBaseServerHost\}/\{apiBaseUrl\}/\{routeName\}/\{locale\}/data.json` (наприклад, `https://internal-cdn.example.com/_locales/index/en/data.json`).

#### `translationPayloads`

{/* generated:option:translationPayloads — do not edit; run `pnpm run docs:generate` */}

**Тип** `TranslationPayloadOptions` · **За замовчуванням** —

Контролює, як видаються пейлоади перекладів (Node: `public/<apiBaseUrl>`; Edge: Nitro `serverAssets`).

- **Node**: `serverAssets` означає локальний SSR через `readFile` під `public/` (без Rollup `raw:`).
- **Edge**: `serverAssets` реєструє Nitro `serverAssets` (`assets:i18n`); не примушує до публічної копії.

Тримайте значення за замовчуванням для звичайного all-in-one налаштування. Для великих Edge-каталогів надавайте перевагу `mode: 'source'`.
Для розгортань з CDN — вимкніть локальні виводи та задайте `apiBaseClientHost` / `apiBaseServerHost`.

{/* /generated:option:translationPayloads */}

```typescript
{
  mode?: 'premerged' | 'source'
  serverAssets?: boolean
  serverHandler?: boolean
  publicAssets?: boolean
  prerenderRoutes?: boolean
  publicDir?: string
  warnFileCount?: number
  warnSizeBytes?: number
}
```

**За замовчуванням** (`mode: 'premerged'`):

```typescript
{
  mode: 'premerged',
  serverAssets: true,
  serverHandler: true,
  publicAssets: true,
  prerenderRoutes: false
}
```

SSR на **Node** читає те саме дерево, скопійоване у `public/<apiBaseUrl>/` (`readFile`). На **Edge** Nitro `serverAssets` вбудовує його (без форсованої публічної копії — задайте `publicAssets: true` для CDN). `mode: 'premerged'` → `\{page\}/\{locale\}/data.json` на сторінку/локаль; `mode: 'source'` → компактне джерело + рантайм-злиття.

`serverAssets: true` на **Node** форсує публічну копію, навіть якщо `publicAssets` є false. На **Edge** він лише реєструє Nitro-вбудовування. Надавайте перевагу `mode: 'source'` на Edge для великих каталогів. Без локальних пейлоадів і без `apiBaseServerHost` збірка впаде.

Локальний хендлер `/\{apiBaseUrl\}/:page/:locale/data.json`, prerender-маршрути та копії публічних ресурсів залишаються опційними виводами.

Для компактних **публічних** / Edge-пейлоадів:

```typescript
i18n: {
  translationPayloads: {
    mode: 'source',
  },
}
```

`mode: 'source'` тримає файли шарів компактними та зливає root/page/fallback у рантаймі через вбудований маршрут `/_locales` (або Edge `assets:i18n`). За замовчуванням він вимикає копії публічних ресурсів та маршрути пре-рендерованого пейлоаду.

<Warning>
З `mode: 'source'` `publicAssets` за замовчуванням дорівнює `false` (`prerenderRoutes` завжди вимкнено, якщо ви не увімкнете). Чистий статичний хостинг без рантайму Nitro/edge тому не може завантажити переклади на клієнті, доки ви не увімкнете один із цих виводів, не залишите `serverHandler` доступним у рантаймі або не розмістите пейлоади зовні.

Зі стандартним `mode: 'premerged'` та `publicAssets: true` статичні файли вже опиняються у `public/<apiBaseUrl>/\{page\}/\{locale\}/data.json` — збігаючись з URL клієнтського `$fetch` — тож статичний хост може обслуговувати їх без Nitro.
</Warning>

<Warning>
Коли задано `apiBaseServerHost` або `apiBaseClientHost`, модуль отримує вже злитий JSON з цього origin. Зовнішні хости мають подавати ті самі відповіді `/\{apiBaseUrl\}/:page/:locale/data.json`, що й вбудований маршрут. `mode: 'source'` застосовується до локальних тек пейлоаду, а не до зовнішнього CDN, якщо цей CDN також не подає runtime-merged пейлоади.
</Warning>

Ви також можете вимкнути дубльовані локальні виводи вручну і подавати пейлоади перекладу з CDN або обʼєктного сховища:

```typescript
i18n: {
  apiBaseClientHost: 'https://cdn.example.com',
  apiBaseServerHost: 'https://cdn.example.com',
  translationPayloads: {
    serverHandler: false,
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

Якщо ви хочете лише уникнути запису пейлоадів у публічний вивід, зберігаючи вбудований серверний маршрут для SSR/рантайм-запитів, вимкніть обидва публічні виводи:

```typescript
i18n: {
  translationPayloads: {
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

На **Node** `serverAssets: true` все ще форсує публічну копію для SSR, навіть коли `publicAssets` — false. Задайте `serverAssets: false` та `apiBaseServerHost`, якщо хочете нуль локальних файлів пейлоаду.

Використовуйте `publicDir`, щоб змінити теку публічного виводу, коли пейлоади копіюються. За замовчуванням — `apiBaseUrl` (`_locales`). У режимі premerged `publicAssets` записує туди `\{page\}/\{locale\}/data.json` (ті ж шляхи, які отримує клієнт). `prerenderRoutes` — опційний Nitro-prerender маршрутів хендлера, зазвичай зайвий, коли це дерево вже скопійовано.

Якщо ви вимкнете всі локальні виводи пейлоаду, ви маєте налаштувати як `apiBaseServerHost` (SSR), так і `apiBaseClientHost` (клієнтська навігація). Інакше переклади розвʼязуватимуться у порожні обʼєкти, і ключі UI можуть виявитися неперекладеними.

`warnFileCount` та `warnSizeBytes` контролюють попередження на етапі збірки, коли вивід pre-merged пейлоаду росте великим (за замовчуванням: 500 файлів та 10 MB).

#### `dateBuild`

{/* generated:option:dateBuild — do not edit; run `pnpm run docs:generate` */}

**Тип** `string \| number` · **За замовчуванням** —

Значення, що використовується для інвалідації кешу запитів перекладу (`?v=...`).

Для відтворюваних/rolling-розгортань встановіть це у стабільне значення (наприклад, git SHA або номер збірки).

{/* /generated:option:dateBuild */}

За замовчуванням модуль створює відбиток ваших джерел перекладу (SHA-256 по кожному `<layer>/<translationDir>/**/*.json` у порядку шарів) і використовує його. Значення змінюється лише коли переклад справді змінюється, тож перезбирання чи повторне розгортання незмінених перекладів залишає кеші браузера та CDN цілими — з `httpCacheDuration`, встановленим на рік, timestamp збірки натомість змушував би кожного клієнта повторно завантажувати весь словник на кожному деплої.

Він падає до `Date.now()` лише коли немає файлів перекладу для хешування.

Задавайте його явно, щоб взяти контроль (наприклад, привʼязати URL пейлоадів до релізу, а не до вмісту):

```ts
export default defineNuxtConfig({
  i18n: {
    // Any stable string/number: git SHA, CI build number, release tag, etc.
    dateBuild: process.env.GIT_SHA ?? 'local-dev',
  },
})
```

#### `httpCacheDuration`

{/* generated:option:httpCacheDuration — do not edit; run `pnpm run docs:generate` */}

**Тип** `number` · **За замовчуванням** `31536000`

HTTP `Cache-Control` max-age (секунд) для `/\{apiBaseUrl\}/:page/:locale/data.json`.

Застосовується повною мірою лише поки `dateBuild` інвалідує URL (`?v=...`), що є значенням за замовчуванням: відповідь тоді буде `public, max-age=…, immutable` і безпечною для браузерів та CDN.

- `dateBuild: 0`/`''` — URL стабільний, тож ця тривалість *не* поважається; відповідь стає `public, max-age=0, must-revalidate`. Довгий `max-age` на незмінному URL закріпить перший пейлоад, який будь-коли бачив браузер.

- `0` — не встановлювати `Cache-Control` взагалі (корисно у локальному дебагу)
- Не застосовується у розробці (`import.meta.dev`), щоб HMR не боровся з кешем браузера
- Досягає лише відповідей, поданих через Nitro. Пейлоади, скопійовані у `public/` та подані хостинг-платформою, беруть заголовки цієї платформи — див. посібник з продуктивності.

Аналогічно експериментальному `httpCacheDuration` у `@nuxtjs/i18n` (v10.2.0), але як явний заголовок відповіді, а не Nitro `defineCachedEventHandler` maxAge.

{/* /generated:option:httpCacheDuration */}

```ts
export default defineNuxtConfig({
  i18n: {
    // Per-build fallback (Date.now()) so immutable payloads never go stale when GIT_SHA is missing.
    dateBuild: process.env.GIT_SHA ?? String(Date.now()),
    httpCacheDuration: 86400, // 24 hours
    // httpCacheDuration: 0, // disable Cache-Control header
  },
})
```

<Tip>
Для більшості проєктів значення за замовчуванням (без обмежень, без спливання) підходить — переклади малі й скінченні. Однак, якщо ваш проєкт має **тисячі сторінок** з `disablePageLocales: false` та **багато локалей**, серверний кеш може значно вирости. У довготривалих Node.js-серверах це може призвести до надмірного використання памʼяті.

- **`cacheMaxSize`** — обмежує кількість кешованих записів. Корисно для обмеження памʼяті.
- **`cacheTtl`** — гарантує, що застарілі переклади зрештою будуть перезавантажені зі сховища. Корисно для serverless-середовищ або коли переклади змінюються у рантаймі.

**Формула для оцінки макс. записів**: `кількість_локалей × (кількість_сторінок + 1)`. Наприклад, 10 локалей × 500 сторінок = ~5010 записів.
</Tip>
