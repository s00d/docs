# Рантайм-перевизначення i18n

Використовуйте цей посібник, коли вам потрібно, щоб один артефакт збірки працював з різними значеннями локалей за замовчуванням для різних середовищ (наприклад, різні tenant-інстанси).

## Що можна перевизначити у рантаймі

Модуль підтримує безпечні рантайм-перевизначення для:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Ці перевизначення застосовуються поверх конфігу на етапі збірки з `.nuxt/i18n.strategy.mjs` та `.nuxt/i18n.config.mjs`.

## Що не можна перевизначити у рантаймі

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) — це справа етапу збірки, бо вона впливає на згенеровану поведінку маршрутів.

Якщо ви передасте рантайм-перевизначення стратегії, воно ігнорується і видається попередження.

## Перевизначення через RuntimeConfig

Надавайте рантайм-значення під `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Перевизначення через змінні оточення

Ви також можете налаштувати перевизначення через змінні оточення:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (через кому, наприклад `fr,it`)

Також підтримуються fallback-аліаси:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Правила валідації

У рантаймі модуль валідує перевизначення, щоб уникнути поламаного стану:

- Ви не можете вимкнути всі локалі.
- `defaultLocale` має вказувати на увімкнену локаль.
- `fallbackLocale` має існувати серед оголошених локалей.

Якщо перевизначення невалідне, модуль зберігає безпечне значення і логує попередження.

## Нотатки для розгортань з кількома інстансами

Ця рантайм-можливість розроблена для активації локалей та значень за замовчуванням на рівні інстансу без перезбирання.

Якщо інстансам потрібні різні URL-стратегії (`no_prefix` проти `prefix`), використовуйте окремі збірки для кожної стратегії.

## Вимкнені локалі та статичні пейлоади

`runtimeConfig.public.i18nRuntime.disabledLocales` оновлює маршрутизацію, перемикач та **хендлер** пейлоаду Nitro, але Nitro обслуговує файли під `public/` **до** цього хендлера.

Якщо `translationPayloads.publicAssets` (або форсована публічна копія Node SSR) вже записали `/_locales/\{page\}/\{locale\}/data.json`, рантайм-вимкнення не може приховати цей файл. Надавайте перевагу `locale.disabled: true` на етапі збірки, щоб premerge не видавав статичних пейлоадів цієї локалі.
