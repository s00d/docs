# Runtime-перевизначення i18n

Використовуйте цей гайд, коли вам потрібно, щоб один артефакт збірки працював з різними значеннями локалі за замовчуванням у різних середовищах (наприклад, різні тенант-інстанси).

## Що можна перевизначити під час виконання

Модуль підтримує безпечні runtime-перевизначення для:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Ці перевизначення застосовуються поверх конфігурації з етапу збірки з `.nuxt/i18n.strategy.mjs` та `.nuxt/i18n.config.mjs`.

## Що не можна перевизначити під час виконання

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) — це проблема етапу збірки, оскільки вона впливає на поведінку згенерованих маршрутів.

Якщо ви передаєте runtime-перевизначення стратегії, воно ігнорується та виводиться попередження.

## Перевизначення на основі RuntimeConfig

Надайте runtime-значення під `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Перевизначення через змінні середовища

Ви також можете налаштувати перевизначення через змінні середовища:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (розділені комами, наприклад, `fr,it`)

Також підтримуються резервні аліаси:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Правила валідації

Під час виконання модуль валідує перевизначення, щоб уникнути зламаного стану:

- Не можна вимкнути всі локалі.
- `defaultLocale` має вказувати на увімкнену локаль.
- `fallbackLocale` має існувати в оголошених локалях.

Якщо перевизначення невалідне, модуль зберігає безпечне значення та логує попередження.

## Примітки для мульти-інстансних деплойментів

Ця runtime-функціональність розроблена для активації локалей та значень за замовчуванням для кожного інстансу без повторної збірки.

Якщо інстансам потрібні різні стратегії URL (`no_prefix` проти `prefix`), використовуйте окремі збірки для кожної стратегії.

## Вимкнені локалі та статичні payload-и

`runtimeConfig.public.i18nRuntime.disabledLocales` оновлює маршрутизацію, switcher та **обробник** Nitro payload — але Nitro обслуговує файли з `public/` **до** цього обробника.

Якщо `translationPayloads.publicAssets` (або примусова публічна копія Node SSR) вже записали `/_locales/\{page\}/\{locale\}/data.json`, runtime-вимкнення не може приховати цей файл. Надавайте перевагу `locale.disabled: true` на етапі збірки, щоб premerge не генерував статичні payload-и для цієї локалі.
