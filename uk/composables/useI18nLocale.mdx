---
title: "useI18nLocale"
description: "useI18nLocale читає та записує стан локалі й cookie локалі — точка входу для власного визначення локалі."
---

`useI18nLocale()` надає доступ до локалі, яку обрав застосунок: стану `i18n-locale` та cookie локалі. Використовуйте його в плагіні, який сам визначає локаль (домен, профіль користувача, заголовок), замість того щоб вручну записувати `useState('i18n-locale')` або cookie. Перевірки коректності використовують увімкнені локалі, включно з перевизначеннями під час виконання.

## Сигнатура {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Централізована точка входу для керування локаллю i18n.
Поєднує useState('i18n-locale'), cookie локалі та утиліти синхронізації.

## Повернені значення {#returned-values}

| Член | Тип | Опис |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | Ref `useState('i18n-locale')`. |
| `localeCookie` | `Ref<string \| null>` | Cookie [`localeCookie`](/uk/api/module-options#localecookie); простий `{ value: null }`, коли опція дорівнює `null`. |
| `hashCookie` | `Ref<string \| null>` | Cookie `hash-locale` при hash-маршрутизації; інакше `{ value: null }`. |
| `validLocales` | `string[]` | Коди увімкнених локалей. |
| `setLocale(locale)` | `(locale: string \| null) => void` | Записати стан і cookie. Не перевіряє коректність і не завантажує переклади. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | Записати лише cookie. |
| `getLocale()` | `() => string \| null` | Стан, потім cookie вподобання (hash-cookie при hash-маршрутизації). Без перевірки. |
| `getPreferredLocale()` | `() => string \| null` | Перше **коректне** значення зі стану та cookie вподобання, або `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | Стан при hash-маршрутизації, якщо він заданий; інакше `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, потім коректний стан, потім `options.serverLocale`, потім локаль маршруту. Зберігає результат у стан, коли стан некоректний; на клієнті також записує cookie. |
| `isValidLocale(locale)` | `(locale) => locale is string` | Чи є `locale` у `validLocales`. |

Cookie зберігаються один рік, з `path: '/'` та `sameSite: 'lax'`.

## Приклад {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

Плагін завантаження модуля читає стан під час запуску, тому плагін, який його встановлює, має виконатися раніше (`enforce: 'pre'`). Як стан конкурує з URL, cookie та `Accept-Language`: [Визначення локалі](/uk/guide/locale-detection). Повний покроковий опис: [Власне визначення](/uk/guide/custom-auto-detect).

`setLocale()` не перемикає переклади на екрані. Щоб змінити локаль поточної сторінки, викличте [`$switchLocale()`](/uk/api/methods#$switchlocale).
