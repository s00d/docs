---
title: "useLocaleHead"
description: "useLocaleHead будує SEO-теги i18n (lang, dir, canonical, hreflang, og:locale) як об'єкт, який ви передаєте в useHead."
---

`useLocaleHead()` будує теги head i18n для поточного маршруту: `lang` і `dir` на `<html>`, canonical-посилання, альтернативи `hreflang` з `x-default`, `og:url`, `og:locale` і `og:locale:alternate`. Використовуйте його, коли встановлюєте [`meta: false`](/uk/api/module-options#meta) і самі керуєте `useHead`; з `meta: true` модуль уже реєструє ці теги, а зміни для окремих сторінок робляться через [`useI18nHead`](/uk/composables/useI18nHead).

## Сигнатура {#signature}

```ts
useLocaleHead(options: UseLocaleHeadOptions): { build: () => LocaleHead; metaObject: Ref<{ htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string; [key: string]: string | undefined }; link: ({ href: string; rel: "canonical"; [key: string]: string | undefined } | { href: string; hreflang: string; rel: "alternate"; [key: string]: string | undefined })[]; meta: { content: string; property: string; [key: string]: string }[] }, LocaleHead | { htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string; [key: string]: string | undefined }; link: ({ href: string; rel: "canonical"; [key: string]: string | undefined } | { href: string; hreflang: string; rel: "alternate"; [key: string]: string | undefined })[]; meta: { content: string; property: string; [key: string]: string }[] }>; updateMeta: () => void }
```

SEO-теги head для поточного маршруту: альтернативи `hreflang` для кожної локалі плюс
`x-default`, canonical-посилання, `og:locale`, а також `lang`/`dir` на `<html>`.

Потрібен лише тоді, коли `meta` вимкнено або значення за замовчуванням потребують коригування — з `meta: true`
модуль сам реєструє ті самі теги.

| Параметр | Тип | Опис |
| --- | --- | --- |
| `options` | `UseLocaleHeadOptions` |  |

**Повертає** — `metaObject`, ref з об'єктом head, готовим до передачі в `useHead`; `updateMeta` оновлює його; `build` обчислює об'єкт head з поточного маршруту (реактивний, якщо читається в getter-функції, наприклад `useHead(() => build())`)

```ts
const { metaObject } = useLocaleHead({ addSeoAttributes: true })
useHead(metaObject)
```

## Опції {#options}

| Опція | За замовчуванням | Опис |
| --- | --- | --- |
| `addDirAttribute` | `true` | Встановлює `dir` на `<html>` з `dir` локалі (`'auto'`, якщо його немає). |
| `identifierAttribute` | `'id'` | Атрибут, що ідентифікує кожен тег (`i18n-can`, `i18n-og`, `i18n-alternate-<hreflang>`, …), щоб оновлення замінювали теги, а не додавали нові. |
| `addSeoAttributes` | `true` | Генерує теги canonical, `hreflang` і `og:`. `false` залишає лише `htmlAttrs`. |
| `baseUrl` | `'/'` | Origin, що додається до кожного URL. Залиште `'/'` для відносних URL; передайте `'https://example.com'` для абсолютних. |
| `autoUpdate` | `true` | Перебудовує `metaObject`, коли змінюється маршрут або стан `i18n-locale`. |

## Що генерується {#what-it-emits}

- Нічого на маршруті без збігу (404) або з `disableMeta` для активної локалі.
- Canonical і `og:url`: `$switchLocalePath(<active locale>)`, query скорочено до [`canonicalQueryWhitelist`](/uk/api/module-options#canonicalquerywhitelist), застосовано [`trailingSlash`](/uk/api/module-options#trailingslash).
- `hreflang`: одне посилання на кожну ввімкнену локаль, у якій існує сторінка, `hreflang = iso || code`, пропускаючи локалі з `seo: false`; з `hreflangBaseLanguage: true` перша регіональна локаль мови також генерує тег базової мови. Нічого за стратегії `no_prefix`.
- `x-default`: URL локалі за замовчуванням, крім випадків, коли стратегія — `no_prefix`, локаль за замовчуванням має `seo: false` або сторінки в ній не існує.
- `og:locale` / `og:locale:alternate`: з `og` локалі або з її перетвореного `iso` (`en-US` → `en_US`); пропускається з попередженням у режимі розробки, коли жоден варіант не підходить.

## Приклад {#example}

```ts
// app.vue, with i18n.meta: false
const { metaObject } = useLocaleHead({ baseUrl: 'https://example.com' })
useHead(metaObject)
```

`build()` повертає той самий об'єкт без ref: `useHead(() => build())` залишається реактивним без watcher.
