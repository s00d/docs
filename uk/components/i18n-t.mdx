`<i18n-t>` рендерить один переклад в елемент. Використовуйте його, коли переклад потребує компонентів усередині (посилання в реченні), форми множини або відформатованого числа чи дати. Він розв'язує ключ для поточного маршруту, як і `$t`.

## Пропси {#props}

| Проп | Тип | За замовчуванням | Опис |
| --- | --- | --- | --- |
| `keypath` **\*** | `string` | — | Ключ перекладу для рендерингу. |
| `plural` | `number \| string \| null` | — | Кількість, що визначає форму множини. Задайте його, щоб використовувати `$tc` замість `$t`. `null` означає «не задано». |
| `tag` | `string` | `'span'` | Елемент для рендерингу. |
| `params` | `Record<string, string \| number \| boolean>` | — | Значення інтерполяції, що підставляються в переклад. |
| `defaultValue` | `string` | `''` | Рендериться замість компонента, коли `hideIfEmpty` приховує порожній переклад. |
| `html` | `boolean` | `false` | Рендерити переклад як HTML, а не як текст. Лише для перекладів, які ви контролюєте: `params` екрануються, переклад — ні. |
| `hideIfEmpty` | `boolean` | `false` | Нічого не рендерити, коли переклад розв'язується в порожній рядок. |
| `customPluralRule` | `PluralFunc` | `null` | Правило множини лише для цього елемента, що перевизначає налаштоване. Його відповідь використовується як є; `null` рендерить порожнечу. |
| `number` | `number \| string \| null` | — | Форматує значення за допомогою `$tn` і передає його в переклад як `{number}` разом із `params`. |
| `date` | `Date \| string \| number \| null` | — | Форматує значення за допомогою `$td` і передає його в переклад як `{date}` разом із `params`. |
| `relativeDate` | `Date \| string \| number \| null` | — | Форматує значення за допомогою `$tdr` і передає його в переклад як `{relativeDate}` разом із `params`. |

**\*** обов'язковий.

## Правила рендерингу {#rendering-rules}

Результат визначає перший відповідний випадок:

1. `number` — переклад із `{ ...params, number: $tn(number) }`.
2. `date` — переклад із `{ ...params, date: $td(date) }`.
3. `relativeDate` — переклад із `{ ...params, relativeDate: $tdr(relativeDate) }`.
4. `plural` — форма, яку обирає `$tc`, включно з [маркером `=0 `](/uk/api/methods#$tc), із `{ ...params, count }`; або `customPluralRule(keypath, count, params, locale, t)`, якщо задано, — він читає сире значення разом із маркером, а його відповідь використовується як є (`null` означає порожнечу).
5. Інакше — переклад із `params`.

`null` вважається незаданим. У кожному випадку:

- `defaultValue` підставляється замість відсутнього ключа в кожній гілці.
- `hideIfEmpty` рендерить `defaultValue` замість порожнього результату.
- `html` рендерить результат як HTML. `params` екрануються, переклад — ні; слоти ігноруються.
- Слот `default` отримує `{ translation }`, а іменовані слоти ігноруються.
- Інакше кожен іменований слот замінює кожен заповнювач `{name}` раніше, ніж параметр із таким самим ім'ям. Значення параметра, схоже на заповнювач, лишається текстом.

Вивід `date` і `relativeDate` має `data-allow-mismatch="text"`, оскільки часовий пояс і годинник сервера не збігаються з браузерними. Задайте [`timeZone`](/uk/api/module-options#timezone), щоб рендерити однакову календарну дату в обох; `relativeDate` залежить від годинника, тому все одно може відрізнятися.

## Приклад {#example}

```json
{
  "terms": "I accept the {link}.",
  "termsLink": "terms of use",
  "items": "no items | one item | {count} items"
}
```

```vue
<template>
  <i18n-t keypath="terms" tag="p">
    <template #link>
      <NuxtLink :to="$localePath('/terms')">{{ $t('termsLink') }}</NuxtLink>
    </template>
  </i18n-t>

  <i18n-t keypath="items" :plural="cart.length" />
</template>
```

`html` встановлює `innerHTML`: використовуйте його лише для перекладів, які ви контролюєте. `params` екрануються, тож дані користувача там безпечні, як і ключ, для якого не знайшлося перекладу.
