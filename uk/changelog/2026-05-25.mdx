**Дата**: 2026-05-25

**Версія**: `v3.19.0`

![Випуск v3.19.0](/images/3.19.0.png)

Цей випуск зосереджений на **модуляризації внутрішніх утиліт**, додаванні **компактного режиму payload для serverless** та **повторному використанні спільної логіки** в Nuxt, Node, Astro і DevTools — без зміни публічного API модуля для типових застосунків.

## Що нового? {#what’s-new}

### `@i18n-micro/utils` — утиліти, незалежні від фреймворку {#@i18n-micro/utils-—-framework-agnostic-utilities}

Спільна логіка, яка раніше була розкидана по `src/runtime/utils/` і `src/module.ts`, тепер міститься в окремому пакеті робочого простору з **детальними імпортами за підшляхами** (без громіздкого barrel-файлу, дружньо до tree-shaking):

- **Build** — `preMergeLocales`, `buildTranslationSourceLayers` (`@i18n-micro/utils/build`)
- **Payloads** — розв'язання `translationPayloads`, побудова URL, допоміжні функції fetch, статистика (`payload-config`, `payload-url`, `payload-fetch`, `payload-stats`)
- **Режим source** — ланцюжки fallback, шляхи до вихідних файлів, злиття в runtime (`merge-source`, `source-loader`)
- **Допоміжні функції runtime** — визначення локалі, cookies, розбір Accept-Language, допоміжні функції для маршрутів/meta (`resolve-locale`, `accept-language`, `cookie`, `route`, `route-pattern`, `runtime-config`)
- **Спільні шляхи FS** — класифікація файлів перекладів, вкладені шляхи сторінок (`parse-path`)

Модуль Nuxt зберігає тонкий сполучний код у `src/runtime/` та імпортує лише потрібні йому підшляхи.

### `@i18n-micro/hmr` — гаряче перезавантаження перекладів у розробці {#@i18n-micro/hmr-—-dev-translation-hot-reload}

HMR для розробки винесено в `@i18n-micro/hmr`:

- **`watcher`** — обробка змін файлів, інвалідація кешу, злиття source/premerged у режимі розробки
- **`generate-plugin`** — генерація клієнтського HMR-плагіна
- **`cache-keys`** — спільні ключі `Symbol.for` для серверних кешів і кешів сховища

Працює як з `translationPayloads.mode: 'premerged'`, так і з `'source'`.

### `translationPayloads.mode: 'source'` — компактні serverless-розгортання {#translationpayloads-mode-‘source’-—-compact-serverless-deployments}

Новий режим payload для великих матриць локалей на serverless-платформах (Cloudflare Workers тощо):

```typescript
export default defineNuxtConfig({
  i18n: {
    translationPayloads: {
      mode: 'source',
    },
  },
})
```

- Пакує **компактні вихідні файли** в ассети Nitro замість повної попередньо злитої матриці
- Зливає кореневі, сторінкові та fallback-ланцюжки локалей **у runtime** через вбудований маршрут `/_locales/:page/:locale/data.json`
- За замовчуванням встановлює `publicAssets` і `prerenderRoutes` у `false` — ідеально, коли ви покладаєтеся на runtime Nitro/edge, а не на чистий статичний хостинг

Див. [Розгортання — serverless і Edge](/uk/guide/deployment#serverless-and-edge) та [Архітектура кешу і сховища](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api).

### Спільні утиліти в пакетах інтеграцій {#shared-utilities-across-integration-packages}

- **`@i18n-micro/node`** і **`@i18n-micro/astro`** — уніфікований розбір шляхів перекладів і глибоке злиття через `@i18n-micro/utils/parse-path`
- **`@i18n-micro/astro`** — `detectLocaleFromAcceptLanguage` з `@i18n-micro/utils/accept-language` (видалено дубльований парсер)
- **`@i18n-micro/devtools-ui`** — віртуальні шляхи файлів через допоміжні функції `merge-source` + `parse-path`
- **Визначення локалі на сервері** — обробку Accept-Language узгоджено зі спільними утилітами

### Виправлення HMR і DevTools {#hmr-&-devtools-fixes}

- Клієнтський HMR-плагін тепер викликає **`$loadPageTranslations`** (правильний API) замість видаленого `$loadTranslations`
- Покриття Playwright для спостерігача перекладів у режимах **premerged** і **source**

## Несумісні зміни (розширені / внутрішні) {#breaking-changes-advanced-/-internal}

Вони стосуються лише проєктів, які імпортували **внутрішні** шляхи модуля (що не є частиною публічного API):

- Видалено з `src/runtime/utils/`: `route-utils.ts`, `runtime-i18n-config.ts` та інші утиліти, перенесені до `@i18n-micro/utils/*`
- Видалено з `src/runtime/server/plugins/`: вбудований HMR-спостерігач/генератор — використовуйте `@i18n-micro/hmr/*`, якщо ви форкнули інструменти розробки
- **`nuxt-i18n-micro`** тепер залежить від пакетів робочого простору `@i18n-micro/utils` і `@i18n-micro/hmr` (встановлюються автоматично разом із модулем)

Типове використання `nuxt.config` + composables не змінилося.

## Чому це важливо {#why-it-matters}

- **Менші serverless-бандли** — режим `source` дозволяє не постачати попередньо злитий файл для кожної пари локаль × сторінка
- **Єдине джерело істини** — одна реалізація для розбору шляхів, злиття, визначення локалі та конфігурації payload
- **Простіша підтримка** — код, незалежний від фреймворку, тестується в `@i18n-micro/utils` (50+ модульних тестів) і повторно використовується всюди
- **Кращий досвід розробки** — логіка HMR ізольована, тестована та узгоджена між режимами payload

Повний список комітів див. у [журналі змін](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
