## Nuxt I18n Micro v3.22.0 — формати, кеш і Translation Memory {#nuxt-i18n-micro-v3-22-0-—-formats-cache-&-translation-memory}

**Дата**: 2026-07-30

**Версія**: `v3.22.0`

![Випуск v3.22.0](/images/3.22.0.png)

Представляємо **v3.22.0**: іменовані формати чисел і дат у стилі Vue I18n із кешем форматерів, дружнє до CDN кешування payload перекладів (відбиток вмісту + `httpCacheDuration`) та API Translation Memory для читання й заміни активного словника під час виконання.

## Що нового? {#what’s-new}

### Іменовані `numberFormats` / `datetimeFormats` + кеш форматерів {#named-numberformats-/-datetimeformats-+-formatter-cache}

Іменовані формати, сумісні з Vue I18n, і швидше форматування Intl:

- Конфігурація: `numberFormats` / `datetimeFormats` для кожної локалі
- API: `$tn(1000, 'currency')`, `$td(date, 'short')` (+ перевизначення локалі та злиття опцій)
- `FormatService` кешує `Intl.NumberFormat` / `DateTimeFormat` / `RelativeTimeFormat` за локаллю й опціями

Див. [Методи — `$tn` / `$td`](/uk/api/methods#$tn) та [Опції модуля](/uk/api/module-options#numberformats).

### `dateBuild` за замовчуванням — відбиток вмісту {#datebuild-defaults-to-a-content-fingerprint}

`?v=` у запитах `/_locales` раніше за замовчуванням дорівнював `Date.now()`, тоді як відповіді віддаються як `immutable` на рік. Тож кожна перезбірка інвалідувала словник у кожного клієнта, навіть якщо жоден переклад не змінився.

Тепер значенням за замовчуванням є відбиток SHA-256 джерел перекладів у порядку шарів. Перезбірки з незмінними перекладами зберігають той самий URL. Явно задане `dateBuild` і далі має пріоритет. Див. [Опції модуля — `dateBuild`](/uk/api/module-options#datebuild).

### `httpCacheDuration` для payload `/_locales` {#httpcacheduration-for-/_locales-payloads}

Вбудований маршрут `/{apiBaseUrl}/:page/:locale/data.json` тепер надсилає HTTP-заголовок `Cache-Control` для браузерів і CDN:

- Опція: `httpCacheDuration` (секунди, за замовчуванням `31536000` / 1 рік)
- Заголовок: `Cache-Control: public, max-age=…, immutable`
- Безпечно працює з наявним скиданням кешу через `dateBuild` (`?v=...`); `0` вимикає заголовок; не застосовується в режимі розробки

Аналог `experimental.httpCacheDuration` з `@nuxtjs/i18n` v10.2.0, але у вигляді явного заголовка відповіді.

### Стиснені публічні payload {#compressed-public-payloads}

`nitro.compressPublicAssets` тепер поширюється на payload перекладів, скопійовані в публічну директорію (`.gz` + `.br`). Nitro стискає публічні ресурси до того, як відбувається копіювання, тому раніше payload були єдиною нестисненою частиною статичної збірки — 6.65 MB без стиснення проти 1.01 MB gzip на індексі playground. Модуль, як і раніше, ніколи не вмикає стиснення самостійно. Див. [Продуктивність](/uk/guide/performance#payload-size).

### `resolveTranslations()` і `setTranslation(key, value)` {#resolvetranslations-and-settranslationkey-value}

Хелпери часу виконання для читання й заміни активного словника перекладів у пам'яті:

- **`resolveTranslations()`** повертає повне дерево, з якого читає `$t()` для активної локалі й маршруту — корисно для DevTools, тестів і редакторів часу виконання. Коли активний другий шар (резервна локаль або гаряче перезавантаження під час переходу між сторінками Nuxt), дамп зберігає вкладену форму через `mergeTranslationLayers` і використовує пласкі ключі з крапками лише для колізій «скаляр проти об'єкта», які інакше неможливо виразити одним деревом.
- **`setTranslation(key, value)`** замінює значення за ключем (верхній рівень, шлях із крапками, об'єкт, рядок або скаляр). Це **заміна**, а не злиття; використовуйте `$mergeTranslations`, коли сусідні ключі мають зберегтися.
- Доступно в `useI18n()`, `useNuxtApp()` та в i18n-екземплярах фреймворків, успадкованих від `@i18n-micro/core`.
- `@i18n-micro/test-utils` додає відповідні хелпери `resolveTranslations` / `setTranslation` для модульних тестів.

### `getAllTranslations()` видалено з пакета Vue {#getalltranslations-removed-from-vue-package}

Використовуйте `resolveTranslations()` для активного дерева пошуку. Для повного дампу сховища у Vue використовуйте `getStorage()` або `getRouteCache()`.

## Несумісні зміни {#breaking-changes}

Для типового використання жодна зміна публічної конфігурації не вимагає правок коду застосунку. Ці пункти важливі, якщо ви зверталися до внутрішніх механізмів часу виконання:

- **SSR payload переміщено з `useState('i18n-ssr-chunks')` до `nuxtApp.payload.data['i18n-ssr-chunks']`.** Він, як і раніше, містить **повні чанки перекладів** для кожної пари `(locale, route)`, завантаженої під час SSR — ті самі словники, що й раніше, але в слоті, який Nuxt може винести в `_payload.json` під час пререндерингу. `useState('i18n-ssr-chunks')` тепер нічого не повертає. Читання перекладів у такий спосіб ніколи не підтримувалося, але було описане в документації API кешу, тому ми згадуємо це тут.
- **`NuxtTranslationLoaderOptions` надає `setSsrChunk`.** Завантажувач записує кожен об'єднаний чанк у `payload.data` на сервері під час завантаження. `getSsrChunks` не використовується.
- **`nitro.compressPublicAssets` тепер створює `.gz` / `.br` поруч зі скопійованими payload.** Якщо цю опцію ввімкнено, очікуйте більше файлів у публічному виводі. Інструментам розгортання, які перелічують директорію перекладів, можливо, доведеться їх враховувати.
- **URL payload один раз зміняться після оновлення**, оскільки `?v=` перемикається з часової мітки збірки на відбиток вмісту. Клієнти повторно завантажать словник під час першого запиту після оновлення, а потім зберігатимуть його між наступними розгортаннями — у цьому й суть.
- **`getAllTranslations()` видалено з `@i18n-micro/vue`.** Натомість використовуйте `resolveTranslations()` / `getStorage()` / `getRouteCache()`.

## Виправлення помилок {#bug-fixes}

- **`<i18n-switcher>`** — пропускає локалі з `disabled: true` у випадному списку. `$getLocales()` і далі повертає повний список для вашого коду, а вбудований SEO/meta-вивід виключає вимкнені локалі.
- **Стилі перемикача** — `cursor: not-allowed` застосовується до **поточної** локалі через `activeLinkStyle` / `customActiveLinkStyle`; відновлено `customDisabledLinkStyle` для зворотної сумісності, і він застосовується до кнопки перемикача, коли поточна локаль має `disabled: true`.
- **Dev HMR** — запис, що не змінює вміст файлу (збереження редактора при втраті фокуса, перезапис форматером), більше не запускає повторне злиття. Зміни кореневої локалі перебудовують кожну сторінку цієї локалі, тож витрачати на це ресурси без потреби було дорого.
- **Dev HMR** — сторінки повторно зливаються паралельно при зміні кореневої локалі, а не одна за одною.
- **Переходи між сторінками** — навігація в межах тієї самої локалі зберігає попередній чанк як резервний шар до `page:transition:finish` замість дорогого глибокого злиття при кожній навігації.

## Чому це важливо {#why-it-matters}

- Форматування в стилі Vue I18n без важчого стеку.
- Дружні до CDN URL перекладів, які залишаються стабільними між перезбірками, якщо словник не змінився.
- Підтримуваний API часу виконання для перегляду й латання живого словника — DevTools, тестам і редакторам більше не потрібні приватні хелпери.

Повний список змін буде опубліковано разом із випуском на [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
