![v3.21.0 release](/images/3.21.0.png)

Цей випуск додає **`useI18nHead`** — composable рівня сторінки для перевизначень i18n SEO поверх вбудованого плагіна `02.meta`. Налаштовуйте теги `hreflang`, canonical, `og:url` і Open Graph для кожного маршруту без власного meta-плагіна чи `meta: false`.

## Що нового? {#what’s-new}

### Composable `useI18nHead` {#usei18nhead-composable}

Викликайте `useI18nHead` на будь-якій сторінці, коли `meta: true` (за замовчуванням). Модуль об’єднує ваші вхідні дані після `useLocaleHead` під час кожного оновлення маршруту:

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

Підтримує статичні об’єкти, реактивні геттери, додавання `meta` / `link`, `replace` для вбудованих груп і `disable` для видалення автоматично згенерованих тегів. Див. [`useI18nHead`](/uk/composables/useI18nHead).

### Утиліта `mergeI18nHead` (`@i18n-micro/utils`) {#mergei18nhead-utility-@i18n-micro/utils}

Незалежна від фреймворку логіка об’єднання міститься в `@i18n-micro/utils/merge-i18n-head` — її використовує плагін `02.meta`, і її можна тестувати ізольовано. Типи (`I18nHeadInput`, `I18nHeadLink`, `I18nHeadMeta`) експортуються з `@i18n-micro/types`.

### Інтеграція з плагінами {#plugin-integration}

- **`02.meta`** — об’єднує вивід `useLocaleHead` зі станом сторінки з `useI18nHead` через `useHead`
- **`01.plugin`** — скидає перевизначення сторінки при зміні імені маршруту через `resetPageHead()` (спільний стан із composable)

### Документація та тести {#documentation-&-tests}

- Новий посібник: [`useI18nHead`](/uk/composables/useI18nHead) з прикладами для CMS/статей

## Типові сценарії використання {#typical-use-cases}

| Сценарій                                     | Підхід                                                         |
| -------------------------------------------- | -------------------------------------------------------------- |
| Блог/CMS із частковими перекладами           | `replace.hreflang` + `replace.ogAlternates` з локалей API      |
| Власний canonical із CMS                     | `replace.canonical` + `replace.ogUrl`                          |
| Лише OG для лендингу                         | `meta: [{ property: 'og:title', ... }]` — залишити hreflang модуля |
| Без hreflang на сторінці                     | `disable: ['hreflang', 'x-default']`                           |
| Заміна власного плагіна (`i18nManualHreflang`) | `useI18nHead` на кожній сторінці контенту + `meta: true`     |

**JSON-LD** залишається в `useHead({ script: [...] })` — `useI18nHead` не генерує структуровані дані.

## Несумісні зміни {#breaking-changes}

Немає для стандартного використання `nuxt.config`. Новий composable і підшлях utils лише доповнюють API.

## Чому це важливо {#why-it-matters}

- **Без власного meta-плагіна** для публікацій CMS, новин чи посібників з URL для кожної локалі
- **Єдиний конвеєр** — типові налаштування модуля + перевизначення сторінки в одному виклику `useHead`
- **Типобезпека** — `I18nHeadInput` для хелперів на кшталт `buildArticleHead(content)`
