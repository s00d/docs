**Дата**: 2026-05-14

**Версія**: `v3.20.0`

![Випуск v3.20.0](/images/3.20.0.png)

Цей випуск переносить середовище виконання Nuxt в окремий шар **`NuxtI18n`**, розділяє обробку перенаправлень на серверну й клієнтську та виправляє кілька регресій SSR/гідратації. Публічні композабли й опції `nuxt.config` для типових застосунків залишаються без змін.

## Що нового? {#what’s-new}

### `NuxtI18n` і `NuxtTranslationLoader` {#nuxti18n-&-nuxttranslationloader}

Логіку i18n під час виконання винесено з монолітного плагіна у вузькоспеціалізовані класи:

- **`NuxtI18n`** — шар представлення активних перекладів (`$t`, `$has`, контекст локалі/маршруту, об'єднання/очищення під час переходів)
- **`NuxtTranslationLoader`** — завантажує чанки, перемикає контекст під час навігації, заповнює SSR payload
- **`createNuxtI18nPluginApi`** — тонкий інтерфейс плагіна (`$switchLocale`, `$localeRoute` тощо)

Див. оновлені [Архітектура кешу та сховища](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api) і [Продуктивність](/uk/guide/performance).

### SSR payload через `useState('i18n-ssr-chunks')` {#ssr-payload-via-usestate‘i18n-ssr-chunks’}

SSR-переклади серіалізуються через **стан Nuxt**, а не через тег script `window.__I18N__`:

1. Сервер завантажує чанки → `useState('i18n-ssr-chunks')`
2. Клієнт гідратується → `translationStorage.seedFromSsrChunks()`
3. Жодних додаткових запитів під час першого відображення

Застарілий шлях читання `window.__I18N__` **видалено**.

### Розділення архітектури перенаправлень {#redirect-architecture-split}

Перенаправлення тепер залежать від середовища — для зрозумілішої поведінки та меншої кількості смикань на клієнті:

| Середовище    | Компонент                      | Роль                                       |
| -------------- | ------------------------------ | ------------------------------------------ |
| **Серверний SSR** | `06.redirect.ts` (лише сервер) | 302 до рендерингу, перевірки 404, синхронізація cookie |
| **Клієнтський SPA** | `i18n-redirect.global.ts`      | Глобальний middleware маршрутів під час навігації      |

Клієнтські перенаправлення визначають локаль із **цільового маршруту**, зберігають **рядок запиту та хеш** і враховують `redirects: false` (middleware не реєструється). Див. [Визначення локалі — перенаправлення для кожної стратегії](/uk/guide/locale-detection#redirects-per-strategy).

### Час виклику хука `i18n:register` {#i18nregister-hook-timing}

Плагін **`05.hooks`** (`dependsOn: i18n-plugin-loader`) викликає `i18n:register` після того, як завантажувач готовий — під час запуску та навігації, — тож користувацькі плагіни надійно отримують подію. Вимкнути можна через `hooks: false`. Див. [Події](/uk/api/events).

### Витягування `defineI18nRoute` під час збирання {#build-time-definei18nroute-extraction}

Vite-unplugin сканує файли сторінок `.vue` під час збирання та записує мета маршрутів для `@i18n-micro/route-strategy`. `$defineI18nRoute` під час виконання в `script setup` залишається для розробки та вбудованої конфігурації. Див. [Переклади на рівні компонентів](/uk/guide/per-component-translations).

## Виправлення помилок {#bug-fixes}

- **SSR-гідратація** — клонування реактивних SSR-чанків перед `Object.freeze` (виправляє збої `#locale` / 404 на клієнті)
- **Перемикання локалі** — заміна шару представлення при зміні локалі (жодних застарілих ключів із попередньої локалі)
- **Клієнтське перенаправлення** — локаль із цільового маршруту; запит/хеш зберігаються під час перенаправлення
- **`has()`** — перевіряє лише активну локаль; резервна локаль застосовується в `$t()`, а не в `$has()`
- **Мета `defineI18nRoute`** — кеш для кожного екземпляра плагіна; найдовший збіг `rootDir`; коректні шляхи `pages/index` проти `pages/index/index`

## Несумісні зміни {#breaking-changes}

Немає для стандартного використання `nuxt.config` + композаблів. Змінилися внутрішні шляхи та механізм впровадження SSR; застосунки, які покладалися на ручне впровадження `window.__I18N__`, мають натомість використовувати payload Nuxt / API модуля.

## Чому це важливо {#why-it-matters}

- **Надійніша передача SSR → клієнт** — нативний стан Nuxt замість саморобних глобальних змінних
- **Зрозуміліша модель перенаправлень** — серверний 302 до відображення; клієнтський middleware лише там, де потрібно
- **Простіший супровід** — середовище виконання розділено на тестовані модулі з цільовими регресійними тестами

Повний журнал змін буде опубліковано разом із випуском на [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
