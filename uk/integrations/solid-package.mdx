`@i18n-micro/solid` дає застосункам SolidJS екземпляр i18n на основі сигналів, провайдер, `useI18n()` і чотири компоненти. Використовуйте його в застосунку Solid, який не зібрано за допомогою Nuxt. Виклики `t()` усередині JSX або ефектів відстежують локаль, маршрут і словники; спільна модель описана в розділі [Фреймворки](/uk/integrations/overview).

## Встановлення {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer-залежності: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (необов'язково, лише для `@i18n-micro/solid/router`). Solid 2 поки що не підтримується.

## Налаштування {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` приймає `i18n`, `locales`, `defaultLocale` і `routingStrategy`; пропущений проп зберігає значення зовнішнього провайдера, включно з екземпляром. `getLocaleName()` і `<I18nSwitcher>` читають `locales`; без них їм нічого показувати. Опції описано в розділі [екземпляр](/uk/integrations/overview#the-instance). Екземпляр — це екземпляр [runtime](/uk/integrations/runtime-package) з одним сигналом над його сховищем.

## Переклад {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Викликайте методи всередині JSX або ефекту, щоб Solid їх відстежував, — це стосується й `localePath` та `getLocale`; значення, прочитане один раз у тілі компонента, не оновлюється. На екземплярі відстежуйте через `i18n.locale` і `i18n.currentRoute`: `i18n.getLocale()` лишається звичайним, бо його читають операції запису. Читання локалі реагує лише на локаль, тож ефект, який її читає й завантажує словник, виконується один раз. Не деструктуруйте пропси й не зберігайте результати `t('key')` у звичайних змінних.

`useI18n()` повертає `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (аксесор: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` і `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Перемикання локалі {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Перемикання нічого не завантажує; спочатку додайте словник локалі.

`<I18nGroup>` передає `t` з префіксом дочірній функції. `<I18nT>` і `t()` усередині нього префікса не мають:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Маршрутизація {#routing}

Адаптер `@solidjs/router` міститься в підшляху, тож основна точка входу ніколи не імпортує роутер. Викликайте його всередині роутера, зазвичай у `root` роутера, де працюють `useNavigate` і `useLocation`:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

Адаптер додає префікс до кожної локалі, крім локалі за замовчуванням (`/about`, `/de/about`), і рендерить `<I18nLink>` як `<A>` роутера. `getCurrentPath` читає реактивне розташування роутера, тож активні посилання та перемикач слідують за ним; користувацька стратегія отримує те саме, якщо читатиме там сигнал. Зверніть увагу на порядок аргументів: `(locales, defaultLocale, navigate, location)`. Для інших роутерів напишіть адаптер із `getCurrentPath`, `push` і `replace` (усі обов'язкові) — див. [Адаптер роутера](/uk/integrations/overview#router-adapter).

## SSR {#ssr}

Для серверного рендерингу збирайте з `vite-plugin-solid`: умова експорту `solid` пакета передає йому вихідний код, тож він компілюється для сервера. Попередньо зібраний `dist` призначений лише для браузера. Екземпляр не має `destroy()`; створюйте один на застосунок або один на запит на сервері й дайте збирачу сміття його прибрати.
