# Інтеграції

Пакети `@i18n-micro` — це легкі, framework-specific версії Nuxt I18n Micro, розроблені для інтеграції у різні фреймворки та середовища. Ці пакети надають ядерну функціональність інтернаціоналізації з мінімальним слідом, зосереджуючись на основних можливостях перекладу та базових компонентах.

## Огляд

Ці пакети інтеграції — **мініатюрні версії** повного модуля Nuxt I18n Micro, що містять лише необхідну функціональність для інтернаціоналізації:

- **Ядерні можливості перекладу** — базові методи перекладу, плюралізація та форматування
- **Необхідні компоненти** — невеликий набір UI-компонентів для поширених i18n-задач
- **Шаблон адаптера маршрутизатора** — гнучка інтеграція маршрутизації через абстракцію адаптера
- **Підтримка TypeScript** — повні визначення типів для type-safe розробки

На відміну від повного Nuxt-модуля, ці пакети:

- Не містять framework-specific логіки маршрутизації
- Потребують від вас реалізації адаптера маршрутизатора для функцій маршрутизації
- Зосереджуються на функціональності перекладу, а не на інтеграції з фреймворком
- Розроблені як легкі та по можливості незалежні від фреймворка

## Основні компоненти

Усі пакети фреймворків містять такі основні компоненти:

### `<I18nT>`

Компонент перекладу, що рендерить перекладений текст з підтримкою:

- **Інтерполяції параметрів** — заміна плейсхолдерів динамічними значеннями
- **Плюралізації** — автоматичний вибір плюральної форми за лічильником
- **Форматування чисел** — форматування чисел відповідно до локалі
- **Форматування дат** — форматування дат та відносного часу
- **Рендерингу HTML** — опційний рендеринг HTML-вмісту
- **Значень за замовчуванням** — fallback-текст, коли переклад відсутній

**Приклад:**

```vue
<!-- Vue -->
<I18nT keypath="greeting" :params="{ name: 'World' }" />
```

```tsx
// React
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```tsx
// Solid
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```astro
<!-- Astro -->
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

### `<I18nLink>`

Компонент локалізованого посилання, що автоматично опрацьовує префікси локалі в URL. Можливості:

- **Автоматична локалізація шляху** — додає/видаляє префікси локалі на основі стратегії маршрутизації
- **Виявлення активного стану** — підсвічує поточний маршрут
- **Підтримка зовнішніх посилань** — автоматично виявляє та обробляє зовнішні URL
- **Інтеграція з маршрутизатором** — використовує link-компонент адаптера, коли доступний
- **Кастомна стилізація** — підтримує стани active та hover

**Приклад:**

```vue
<!-- Vue -->
<I18nLink to="/about" active-class="active">
  About Us
</I18nLink>
```

```tsx
// React
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```tsx
// Solid
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```astro
<!-- Astro -->
<I18nLink href="/about" class="nav-link">
  About Us
</I18nLink>
```

### `<I18nSwitcher>`

Компонент перемикача мови, що надає dropdown або list-інтерфейс для зміни локалей. Можливості:

- **Автоматичний список локалей** — генерує опції з налаштованих локалей
- **Підсвічування поточної локалі** — візуально позначає активну мову
- **Кастомні підписи** — підтримка кастомних відображуваних імен на локаль
- **Інтеграція з маршрутизатором** — автоматично навігує на локалізовані шляхи
- **Доступність** — правильні ARIA-атрибути та клавіатурна навігація

**Приклад:**

```vue
<!-- Vue -->
<I18nSwitcher />
```

```tsx
// React
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```tsx
// Solid
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```astro
<!-- Astro -->
<I18nSwitcher />
```

### `<I18nGroup>`

Компонент для групування перекладів зі спільним префіксом, корисний для організації перекладів за сторінкою чи можливістю. Особливості:

- **Область префікса** — автоматично додає префікс до всіх ключів перекладу всередині групи
- **Вкладені групи** — підтримка вкладених груп перекладів
- **Чиста організація** — допомагає підтримувати організовані структури перекладів

**Приклад:**

```vue
<!-- Vue -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

```tsx
// React
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```tsx
// Solid
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```astro
<!-- Astro -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

## Спільні опції `createI18n` \{#create-i18n-options\}

Кожен пакет фреймворка створюється однаково — лише тип опцій названо за фреймворком (`ReactI18nOptions`, `SolidI18nOptions` тощо). Самі опції ідентичні:

| Властивість      | Тип                                                        | Обовʼязково | За замовчуванням | Опис                                        |
| ---------------- | ---------------------------------------------------------- | ----------- | ---------------- | ------------------------------------------- |
| `locale`         | `string`                                                   | ✅          | -                | Код поточної локалі (наприклад, `'en'`)     |
| `fallbackLocale` | `string`                                                   | ❌          | Те саме, що `locale` | Fallback-локаль, коли переклад відсутній |
| `messages`       | `Record<string, Translations>`                             | ❌          | `\{\}`           | Початкові повідомлення перекладу            |
| `plural`         | `PluralFunc`                                               | ❌          | `defaultPlural`  | Кастомна функція плюралізації               |
| `missingWarn`    | `boolean`                                                  | ❌          | `true`           | Показувати попередження про відсутні переклади |
| `missingHandler` | `(locale: string, key: string, routeName: string) => void` | ❌          | -                | Кастомний хендлер для відсутніх перекладів  |

Усе інше, окрім цього, — framework-specific і документується на сторінці цього пакета.

## Абстракція адаптера маршрутизатора

Усі пакети фреймворків використовують **шаблон адаптера маршрутизатора**, щоб відокремити функціональність i18n від конкретних реалізацій маршрутизатора. Цей дизайн дозволяє:

- **Гнучкість** — використовуйте будь-яку бібліотеку маршрутизатора чи взагалі жодну
- **Незалежність від фреймворка** — тримайте логіку маршрутизації у своєму застосунку, а не в i18n-пакеті
- **Легке ядро** — i18n-пакет залишається малим і сфокусованим

### Реалізація адаптера маршрутизатора

Щоб використовувати функції маршрутизації, вам потрібно реалізувати інтерфейс `I18nRoutingStrategy`:

```typescript
interface I18nRoutingStrategy {
  getCurrentPath: () => string
  linkComponent?: Component
  push: (target: { path: string }) => void
  replace: (target: { path: string }) => void
  resolvePath?: (to: string | { path?: string }, locale: string) => string | { path?: string }
  getRoute?: () => { fullPath: string; query: Record<string, unknown> }
}
```

Документація кожного пакета містить повні приклади реалізації адаптерів для популярних маршрутизаторів:

- **Vue**: приклад адаптера Vue Router
- **React**: приклад адаптера React Router
- **Solid**: приклад адаптера Solid Router
- **Astro**: приклад адаптера маршрутизації на основі файлів

## Основні можливості

Усі пакети діляться цими основними можливостями:

### Методи перекладу

- `t()` — базовий переклад з інтерполяцією параметрів
- `ts()` — переклад, що завжди повертає рядок
- `tc()` — переклад з плюралізацією
- `tn()` — форматування чисел
- `td()` — форматування дат
- `tdr()` — форматування відносного часу
- `has()` — перевірка існування ключа перекладу

### Керування локалями

- **Перемикання локалі** — програмна зміна поточної локалі
- **Fallback-локаль** — автоматичний fallback при відсутньому перекладі
- **Посайтові переклади** — організація перекладів на рівні сторінок
- **Кешування перекладів** — інтелектуальне кешування для продуктивності

### Підтримка TypeScript

Усі пакети надають:

- Повні визначення TypeScript
- Type-safe ключі перекладу (з types generator)
- Підтримка IntelliSense в IDE
- Перевірка помилок на етапі компіляції
