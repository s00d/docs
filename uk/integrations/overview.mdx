Пакети `@i18n-micro/*` переносять ядро перекладів Nuxt I18n Micro у Vue, React, Preact, Solid, Astro, VitePress і чистий JavaScript. Використовуйте їх, коли ваш застосунок не є застосунком Nuxt або коли скрипту чи серверу поза Nuxt потрібні ті самі файли перекладів. Усі пакети мають спільну модель екземпляра, один контракт адаптера роутера та ті самі чотири компоненти, описані один раз на цій сторінці.

`@i18n-micro/core`, `@i18n-micro/types` і `@i18n-micro/utils` встановлюються разом із цими пакетами; ви рідко імпортуєте їх напряму. Сигнатури всіх експортів наведено в згенерованому [довіднику пакетів](/uk/api/packages/overview).

Кожен пакет має playground у `packages/<name>/playground` в репозиторії.

## Екземпляр {#the-instance}

`createI18n(options)` повертає один екземпляр, що містить словники, поточну локаль і поточний маршрут. Опції однакові в усіх пакетах:

| Опція | Тип | За замовчуванням | Примітки |
| --- | --- | --- | --- |
| `locale` | `string` | обов'язкова | Активна локаль. |
| `fallbackLocale` | `string` | `locale` | Використовується, коли ключ відсутній у `locale`. |
| `messages` | `Record<locale, Translations>` | `{}` | Кореневі словники (маршрут `'index'`). |
| `routeMessages` | `Record<route, Record<locale, Translations>>` | `{}` | Словники маршрутів. Лише Runtime, React, Preact, Node і VitePress. |
| `plural` | `PluralFunc` | `defaultPlural` | Власне правило множини. |
| `missingWarn` | `boolean` | `true` | `console.warn` у браузері для відсутнього ключа, лише в режимі розробки. |
| `missingHandler` | `(locale, key, routeName) => void` | — | Викликається замість попередження. |
| `numberFormats` | `Record<locale, Record<name, Intl.NumberFormatOptions>>` | — | Іменовані формати: `tn(9.5, 'currency')`. |
| `datetimeFormats` | `Record<locale, Record<name, Intl.DateTimeFormatOptions>>` | — | Іменовані формати: `td(date, 'short')`. |
| `timeZone` | `string` | зона runtime | Зона IANA для дат `td`; не впливає на `tdr`. Задайте її, щоб сервер і браузер рендерили однакову дату. |
| `now` | `() => number` | `Date.now` | Годинник для `tdr`. Передайте гідратації час сервера, щоб обидва рендерили однаковий текст. |
| `localeIso` | `Record<code, string>` | — | Тег BCP 47 для правил множини (`ua` → `uk-UA`). React, Preact і Solid беруть його з `iso` у `locales` провайдера. |

Словники зберігаються в `i18n.storage.translations` — `Map` з ключами `locale:route` (`en:index`, `en:about`).

Ключ шукається в словнику поточного маршруту, потім у кореневому словнику, спершу для `locale`, потім для `fallbackLocale`. Відсутній ключ повертає сам ключ (або передане вами `defaultValue`).

```ts
i18n.addTranslations('en', { nav: { home: 'Home' } }) // root, deep-merged
i18n.addRouteTranslations('en', 'about', { title: 'About us' }) // route chunk
i18n.addTranslations('en', { nav: { home: 'Start' } }, false) // replace instead of merge
i18n.setRoute('about')
i18n.t('title') // 'About us'
i18n.t('nav.home') // 'Start' (root key, still visible on the route)
```

### Переклад і форматування {#translate-and-format}

| Метод | Повертає |
| --- | --- |
| `t(key, params?, defaultValue?, routeName?)` | Значення (рядок, число, об'єкт) з підставленими `{param}`. |
| `ts(...)` | Те саме, що `t`, у вигляді рядка. |
| `tc(key, count \| params, defaultValue?)` | Форму множини. |
| `tn(value, options \| name)` | `Intl.NumberFormat` в активній локалі. |
| `td(value, options \| name)` | `Intl.DateTimeFormat`. |
| `tdr(value, options?)` | Відносний час (`3 days ago`). |
| `has(key, routeName?)` | `true`, коли активна локаль має ключ (у словнику маршруту або кореневому; fallback не перевіряється). |

`defaultPlural` розділяє значення за `|` і вибирає форму з індексом `count`, обмеженим останньою формою; від'ємне, дробове або `NaN` значення count вибирає останню форму.

Власна функція `plural` отримує `(key, count, params, locale, getter)`. Читайте значення через `getter(key)`; не розділяйте ключ:

```ts
import type { PluralFunc } from '@i18n-micro/vue'

const plural: PluralFunc = (key, count, params, _locale, getter) => {
  const value = getter(key)
  if (typeof value !== 'string') return null
  const forms = value.split('|').map((form) => form.trim())
  return (count === 1 ? forms[0] : forms[1] ?? forms[0])!.replace('{count}', String(count))
}
```

## Адаптер роутера {#router-adapter}

SPA-пакети не залежать від роутера. Адаптер роутера (`I18nRoutingStrategy`) повідомляє їм, як читати поточний шлях, виконувати навігацію та будувати локалізований шлях. Вбудовані адаптери додають префікс до кожної локалі, крім `defaultLocale` (`/about`, `/de/about`).

| Член | Обов'язковий | Використовується |
| --- | --- | --- |
| `getCurrentPath(): string` | так | перевірка активного посилання (за сторінкою, query і hash не враховуються), `switchLocale` (зберігає їх) |
| `push({ path }): void` | так | `switchLocale`, `<I18nLink>` без `linkComponent`, `<I18nSwitcher>` |
| `replace({ path }): void` | так | — |
| `resolvePath(to, locale)` | ні | `localePath`, `localeRoute`, `<I18nLink>`; без нього шляхи повертаються як є |
| `linkComponent` | ні | `<I18nLink>` рендерить його (наприклад, `RouterLink`) замість `<a>` |
| `getRoute()` | ні | `{ fullPath, query }` для SEO-допоміжних функцій |

`push` і `replace` обов'язкові у Vue, React, Preact і Solid. Astro має власний серверний адаптер з необов'язковими `push`/`replace` (див. [Astro](/uk/integrations/astro-package#router-adapter)).

Мінімальний адаптер для будь-якого роутера на основі history:

```ts
import type { I18nRoutingStrategy } from '@i18n-micro/react'

const locales = ['en', 'de']
const stripLocale = (path: string) => path.replace(/^\/(en|de)(?=\/|$)/, '') || '/'

export const historyAdapter: I18nRoutingStrategy = {
  getCurrentPath: () => window.location.pathname + window.location.search + window.location.hash,
  push: ({ path }) => window.history.pushState({}, '', path),
  replace: ({ path }) => window.history.replaceState({}, '', path),
  resolvePath: (to, locale) => {
    const path = stripLocale(typeof to === 'string' ? to : to.path || '/')
    return locale === 'en' ? path : `/${locale}${path === '/' ? '' : path}`
  },
}
```

## Компоненти {#components}

Vue, React, Preact і Solid постачають ті самі чотири компоненти. Їхні props збігаються; React, Preact і Solid передають інші props кореневому елементу.

### `<I18nT>` {#&lt;i18nt&gt;}

| Prop | Тип | Примітки |
| --- | --- | --- |
| `keypath` | `string` | обов'язковий |
| `params` | `object` | значення для підстановки |
| `plural` | `number \| string` | рендерить `tc(keypath, count)` |
| `number` | `number \| string` | передає `tn(number)` як `{number}` |
| `date` | `Date \| string \| number` | передає `td(date)` як `{date}` |
| `relativeDate` | `Date \| string \| number` | передає `tdr(relativeDate)` як `{relativeDate}` |
| `tag` | `string` | елемент-обгортка, за замовчуванням `span` |
| `html` | `boolean` | рендерити переклад як HTML; він має бути довіреним, параметри екрануються |
| `defaultValue` | `string` | замінює відсутній ключ і рендериться без обгортки, коли `hideIfEmpty` приховує порожнє значення |
| `hideIfEmpty` | `boolean` | нічого не рендерити для порожнього перекладу |
| `customPluralRule` | `PluralFunc` | правило множини для цього елемента |

Застосовується лише один prop форматування, перевірка в такому порядку: `number`, `date`, `relativeDate`, `plural`.

#### Форматований текст {#rich-text}

`{placeholder}` може містити елемент. У Vue це іменований слот; у React, Preact і Solid prop `components` задає елементи або функції, що їх повертають, за іменем. У будь-якому разі він має пріоритет над параметром з тим самим іменем, працює в кожній гілці та витримує локаль, яка змінює порядок плейсхолдерів.

```tsx
// { "terms": "I accept the {link} of {company}" }
<I18nT keypath="terms" params={{ company: 'ACME' }} components={{ link: <a href="/terms">terms</a> }} />
```

У Solid передавайте функцію, коли плейсхолдер повторюється: один вузол може стояти лише в одному місці. `children` замінюють текст, а у вигляді функції отримують `{ translation }`, як слот за замовчуванням у Vue. `html` ігнорує все це.

### `<I18nLink>` {#&lt;i18nlink&gt;}

| Prop | Тип | Примітки |
| --- | --- | --- |
| `to` | `string \| { path }` | локалізується через `resolvePath` адаптера |
| `activeStyle` | об'єкт стилів | зливається поверх `style` на поточній сторінці; React, Preact і Solid також застосовують його до розділу вищого рівня |
| `localeRoute` | функція | перевизначає `resolvePath` для цього посилання |

Зовнішні URL (`https://`, `mailto:`, `tel:`) рендеряться як `<a target="_blank" rel="noopener noreferrer">`; ваші власні `target` чи `rel` мають пріоритет. `onClick` виконується завжди. Клік із модифікатором, інша кнопка миші або `target` залишаються за браузером.

### `<I18nSwitcher>` {#&lt;i18nswitcher&gt;}

Випадний список увімкнених локалей (локалі з `disabled: true` приховані) з вбудованими стилями за замовчуванням. Його елементи — посилання з `lang`, `hreflang` і `dir` з локалі. За замовчуванням клік на одному з них встановлює локаль і викликає `push` адаптера з локалізованим поточним шляхом; prop `switchLocale` замінює цю дію. З `localeRoute` і без роутера браузер переходить за посиланням. Escape або клік поза списком закриває його.

| Prop | Примітки |
| --- | --- |
| `locales`, `currentLocale`, `getLocaleName` | перевизначають надані значення |
| `switchLocale(code)` | замінює вбудоване перемикання |
| `localeRoute` | замінює `resolvePath` |
| `customLabels` | `{ de: 'DE' }` |
| `customWrapperStyle`, `customButtonStyle`, `customDropdownStyle`, `customItemStyle`, `customLinkStyle`, `customActiveLinkStyle`, `customDisabledLinkStyle`, `customIconStyle` | перевизначення стилів |

### `<I18nGroup>` {#&lt;i18ngroup&gt;}

`<div class="i18n-group">`, який передає своїм дочірнім елементам `t` з префіксом. Він **не** додає префікс до `<I18nT>` або викликів `t()` усередині; префікс має лише `t`, який він передає вниз.

| Prop | Примітки |
| --- | --- |
| `prefix` | обов'язковий, наприклад `'profile'` |
| `groupClass` | додатковий клас на обгортці |

`t` з префіксом надходить через scoped slot у Vue (`v-slot="{ t }"`) і через дочірній render-prop у React, Preact і Solid (`{({ t }) => …}`).

## Типізовані ключі {#typed-keys}

`t()` приймає будь-який рядок. Щоб отримати автодоповнення для ваших ключів, згенеруйте декларацію за допомогою [генератора типів](/uk/integrations/types-generator). Ключі лише підказуються, а не примусово перевіряються, і параметри не типізуються.

## Порівняння з модулем Nuxt {#compared-with-the-nuxt-module}

Пакети не мають маршрутизації на основі файлів, серверного middleware і завантажувача перекладів: ви самі вирішуєте, коли завантажувати JSON (`import`, `fetch` або `@i18n-micro/node` на сервері) і який адаптер роутера використовувати. Визначення локалі, SEO-meta та генерація маршрутів — це можливості Nuxt; Astro має власний middleware для визначення локалі та `useLocaleHead` для SEO.
