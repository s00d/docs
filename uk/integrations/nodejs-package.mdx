`@i18n-micro/node` — це екземпляр [runtime](/uk/integrations/runtime-package) плюс завантажувач, що зчитує теку перекладів із диска. Використовуйте його в сервері Express або Fastify, CLI, генераторі листів чи PDF або будь-якому скрипті, якому потрібні ті самі JSON-файли, що й вашому застосунку Nuxt. Ви завантажуєте файли один раз і перекладаєте для кожного запиту без спільного змінного стану між запитами.

## Встановлення {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/node @i18n-micro/utils
```

```bash npm
npm install @i18n-micro/node @i18n-micro/utils
```

```bash yarn
yarn add @i18n-micro/node @i18n-micro/utils
```

</CodeGroup>

Без peer-залежностей; Node.js `>=20`. `@i18n-micro/utils` потрібен лише для хелпера `Accept-Language`, описаного нижче.

## Налаштування {#setup}

Завантажувач читає [структуру тек Nuxt](/uk/guide/translations): `locales/en.json` — кореневий словник, `locales/pages/blog/post/en.json` належить маршруту `blog-post`.

```ts
import { createI18n } from '@i18n-micro/node'

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

i18n.t('greeting', { name: 'Ada' }) // 'Hello, Ada!'
i18n.t('title', undefined, undefined, 'blog-post') // from locales/pages/blog/post/en.json
```

Опції — це опції runtime (див. [екземпляр](/uk/integrations/overview#the-instance)) плюс `translationDir` і `disablePageLocales` (обробляти файли `pages/**` як кореневі словники). `i18n.reload()` очищує всі словники й заново читає теку — для спостерігача за файлами в режимі розробки.

`loadTranslations(dir, disablePageLocales?)` також експортується окремо й повертає `{ root, routes }`:

```ts
import { loadTranslations } from '@i18n-micro/node'

const { root, routes } = await loadTranslations('./locales')
// root:   { en: {...}, de: {...} }
// routes: { 'blog-post': { en: {...}, de: {...} } }
```

## Для кожного запиту {#per-request}

Екземпляр містить одну локаль і один маршрут. Перемикання `i18n.locale` на спільному екземплярі всередині обробника запиту створює гонку з паралельними запитами. `run` дає запиту власний:

```ts
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

// `() => next()`: `run` hands its callback the fork, and Express reads an argument of `next` as an error
app.use((req, res, next) => i18n.run(pickLocale(req), () => next()))

app.get('/', (req, res) => {
  res.send(i18n.t('greeting')) // the request's locale, in everything it awaits
})
```

Усередині `run` спільний екземпляр читає та задає локаль і маршрут запиту (`AsyncLocalStorage`); форк починає з поточного маршруту, а `i18n.setRoute(...)` усередині колбека змінює маршрут цього запиту. Колбек також отримує форк запиту: словники, записані в нього, лишаються в межах запиту, а словники, записані в спільний екземпляр, доступні всім.

Без `AsyncLocalStorage` `i18n.fork(locale)` повертає такий самий екземпляр, який можна передавати далі.

`reload()` заново читає каталог; старі словники відповідають, доки не завантажаться нові.

## Вибір локалі {#pick-the-locale}

`detectLocaleFromAcceptLanguage(header, locales)` враховує ваги `q` і зіставляє `de-DE` з локаллю `de` (і `de` з `de-DE`). Повертає `null`, якщо нічого не збігається.

```ts
import express from 'express'
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

const app = express()

app.get('/hello', (req, res) => {
  const locale = detectLocaleFromAcceptLanguage(req.headers['accept-language'], locales) ?? 'en'
  const i18n = byLocale.get(locale)!
  res.json({ message: i18n.t('greeting', { name: 'Ada' }) })
})
```

Для префікса URL, cookie та заголовка разом `resolveLocale({ defaultLocale, validLocales, url, cookie, acceptLanguage, autoDetectLanguage: true })` з `@i18n-micro/utils/resolve-locale` застосовує пріоритет модуля: URL, потім cookie, потім `Accept-Language`, потім значення за замовчуванням. Некоректні значення пропускаються.

У застосунку Nuxt цей пакет на сервері не потрібен: використовуйте [серверні переклади](/uk/guide/server-side-translations) модуля.

## API {#api}

| Експорт | Примітки |
| --- | --- |
| `createI18n(options)`, `I18n` | екземпляр runtime + `translationDir`, `loadTranslations(dir?)`, `reload()` |
| `loadTranslations(dir, disablePageLocales?)` | `{ root, routes }` |
| `loadRootTranslations(dir, disablePageLocales?)` | лише `root` |
| `FormatService`, `interpolate` | з core |
| Типи: `I18nOptions`, `LoadedTranslations`, `Translations`, `Locale`, `PluralFunc`, `Params` | |

Методи екземпляра наведено на сторінці [Runtime](/uk/integrations/runtime-package#api). Повні сигнатури: [довідник пакета](/uk/api/packages/node).
