`@i18n-micro/vitepress` додає до сайту VitePress словники під час виконання: `$t` і `<I18nT>` усередині markdown, хелпери шляхів і SEO-теги, побудовані на [`@i18n-micro/vue`](/uk/integrations/vue-package). Використовуйте його, коли ті самі рядки інтерфейсу з’являються на багатьох сторінках і ви не хочете дублювати їх для кожної локалі. Локаль слідує за власними локалями шляхів VitePress (`/`, `/fr/`).

## Коли його використовувати {#when-to-use-it}

| Потреба | Рішення |
|------|----------|
| Дублікати `.md`, префікси URL | `locales` у VitePress |
| `$t` під час виконання / компоненти / синхронізація шляхів / SEO head | `@i18n-micro/vitepress` |
| Підписи елементів стандартної теми (`docFooter`, інтерфейс пошуку) | Власний `themeConfig` для кожної локалі |

<Tip>

**Playground** — [`packages/vitepress/playground`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/vitepress/playground) — `pnpm -C packages/vitepress/playground dev`

</Tip>

## Встановлення {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vitepress
```

```bash npm
npm install @i18n-micro/vitepress
```

```bash yarn
yarn add @i18n-micro/vitepress
```

</CodeGroup>

Peer-залежності: `vitepress` `>=1.0.0 || >=2.0.0-alpha.0`, `vue` `^3.3.0`. Node-скрипти використовують `@i18n-micro/node`, що встановлюється разом із пакетом і реекспортується через `/node`. Опубліковані типи потребують Vue 3.5.5 або новішого з `skipLibCheck: false`; з `skipLibCheck: true`, звичайним налаштуванням шаблонів, компілюються й старіші версії.

## Налаштування {#setup}

```
locales/en.json
locales/fr.json
locales/pages/guide/demo/en.json   # optional page-scoped
locales/pages/guide/demo/fr.json
```

Файли сторінок зіставляються з назвами маршрутів так само, як у Nuxt/Astro (`guide/demo` → `guide-demo`).

### 1. Конфігурація — `@i18n-micro/vitepress/config` {#1-config-—-@i18n-micro/vitepress/config}

```ts
// .vitepress/config.mts
import { defineConfig } from 'vitepress'
import { withI18n, buildVitePressLocales } from '@i18n-micro/vitepress/config'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English', og: 'en_US' },
  { code: 'fr', iso: 'fr-FR', displayName: 'Français', og: 'fr_FR' },
]
const defaultLocale = 'en'

export default defineConfig(
  withI18n(
    {
      locales: buildVitePressLocales(locales, defaultLocale),
      // themeConfig.i18nRouting is injected automatically
    },
    {
      locale: defaultLocale,
      defaultLocale,
      locales,
      translationDir: 'locales',
      metaBaseUrl: 'https://example.com', // optional SEO head
    },
  ),
)
```

### 2. Тема — `@i18n-micro/vitepress/theme` {#2-theme-—-@i18n-micro/vitepress/theme}

```ts
// .vitepress/theme/index.ts
import DefaultTheme from 'vitepress/theme'
import { defineI18nTheme } from '@i18n-micro/vitepress/theme'

export default defineI18nTheme(DefaultTheme)
```

Початкова локаль береться з поточного шляху до встановлення (без мигання локалі за замовчуванням на `/fr/…`).

### Розширено: ручний `createI18n` {#advanced-manual-createi18n}

Одна фабрика для клієнта: плагін Vue + методи шляхів + `enhanceApp` (без окремих експортів хелперів роутера).

```ts
import { createI18n, messagesFromGlob } from '@i18n-micro/vitepress'

const i18n = createI18n({
  locale: 'en',
  defaultLocale: 'en',
  locales: [{ code: 'en' }, { code: 'fr' }],
  messages: messagesFromGlob(import.meta.glob('../../locales/*.json', { eager: true })),
})

i18n.localizePath('/guide', 'fr')
// in theme enhanceApp:
i18n.enhanceApp({ app, router })
```

### Node-скрипти — `@i18n-micro/vitepress/node` {#node-scripts-—-@i18n-micro/vitepress/node}

Використовує `createI18n` / `loadTranslations` з `@i18n-micro/node` (як Astro і CLI), а потім додає методи шляхів VitePress через `BaseI18n.extend`:

```ts
import { createI18n } from '@i18n-micro/vitepress/node'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  translationDir: './locales',
  locales: ['en', 'fr'],
  defaultLocale: 'en',
})
await i18n.loadTranslations()
i18n.t('cta.readMore')
i18n.localizePath('/guide', 'fr')
```

Звичайний Node без шляхів: `import { createI18n } from '@i18n-micro/node'`.

## Переклади на сторінці {#in-page-translations}

Кожен markdown-файл VitePress є Vue SFC.

### Глобальні компоненти та `$t` (рекомендовано в markdown) {#global-components-and-$t-recommended-in-markdown}

`createI18n` / `defineI18nTheme` встановлюють `@i18n-micro/vue`, який реєструє `I18nT` / `I18nLink` / `I18nGroup` / `I18nSwitcher` і `$t` / `$tc` / `$ts`.

```md
{{ $t('cta.readMore') }}

<I18nT keypath="greeting" :params="{ name: 'VitePress' }" />

<I18nLink to="/guide/demo">Demo</I18nLink>
```

### `useI18n` у `<script setup>` {#usei18n-in-<script-setup>}

```md
<script setup>
import { useI18n } from '@i18n-micro/vitepress'
const { t, tc, locale, localePath, switchLocale } = useI18n()
</script>

# {{ t('section.title') }}
```

## Випадний список мов {#language-dropdown}

Коли `locales` має більше одного запису, VitePress показує власне меню мов (`VPNavBarTranslations`). `withI18n` налаштовує `themeConfig.i18nRouting`, щоб глобус відповідав `<I18nSwitcher>` / хелперам шляхів.

Використовуйте `<I18nSwitcher>` лише у власних макетах, а не поруч зі стандартним глобусом.

## Примітки щодо SSR {#ssr-notes}

- Локаль під час пререндерингу береться зі шляху URL, а не з cookie.
- Код теми не повинен звертатися до `window` під час імпорту.
- Імпортуйте `defineI18nTheme` з `/theme`, щоб обчислення конфігурації в Node ніколи не завантажувало `virtual:i18n-micro/*`.

## Поверхня API {#api-surface}

| Експорт | Роль |
|--------|------|
| `createI18n` (`.`) | Клієнт: плагін Vue + методи шляхів + `enhanceApp` |
| `getLocaleFromPath` / `stripSiteBase` / `routeNameFromPath` (`.`) | Ручна синхронізація локалі, коли `syncWithVitePress: false` |
| `createI18n` (`/node`) | Node: `@i18n-micro/node` + методи шляхів |
| `defineI18nTheme` (`/theme`) | Тема без шаблонного коду |
| `withI18n` (`/config`) | Конфігурація + віртуальні модулі + необов’язкове SEO |
| `buildVitePressLocales` (`/config`) | Побудова `locales` для VitePress з `Locale[]` |
| `buildVitePressLocaleHead` (`/config`) | Ручний SEO head (також використовується `metaBaseUrl`) |
| `messagesFromGlob` | Необов’язкове перетворення glob → мапа повідомлень для `createI18n` |
| `useI18n` / `I18nT` / … | Реекспортовано з `@i18n-micro/vue` |
| `BaseI18n.extend` (`@i18n-micro/core`) | Додавання власних методів до будь-якого екземпляра i18n |

## Сайти у стилі OpenAPI (інтеграційні гарантії) {#openapi-style-sites-integration-locks}

Набір регресійних тестів: `packages/vitepress/tests/integration-openapi.test.ts` (глибокі шляхи, `base=/openapi_docs/`, вимкнена синхронізація + ручна локаль, Node-генератори, SEO).

| Шаблон | Що зробити |
|---------|---------|
| Глибокі сторінки `/…/{spec}/{op}`, лише кореневий JSON інтерфейсу | Надавайте перевагу `syncWithVitePress: true` за замовчуванням (зберігає `setRoute('index')`, коли немає словника сторінки) **або** `syncWithVitePress: false` + `getLocaleFromPath` |
| Ніколи не викликайте `setRoute(deepName)` без словників сторінок | Кореневі ключі інтерфейсу зникають до `setRoute('index')` |
| Генератори / `getTranslation` | `createI18n` з `/node` + `await loadTranslations()` + `i18n.t(key)` (задайте `i18n.locale`) |
| Власний canonical у `transformPageData` | Передайте `meta: false` у `withI18n` (щоб уникнути подвійних тегів) |
| SEO пакета з base сайту | `metaBaseUrl` + `base` у VitePress → абсолютні URL містять base |
| Перейменування зі старіших збірок пакета | `withI18nMicro` → `withI18n`, `createVitePressI18n` → `createI18n`, `loadMessages` → `createI18n` з node |
