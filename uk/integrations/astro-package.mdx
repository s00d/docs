`@i18n-micro/astro` перекладає сторінки Astro на сервері: middleware обирає локаль з URL і кладе екземпляр для кожного запиту в `Astro.locals`, а `useI18n(Astro)` зчитує його. Використовуйте його в сайті на Astro, якому потрібні URL з префіксом локалі (`/about`, `/fr/about`) і спільні JSON-словники. Ви отримуєте компоненти `.astro`, перенаправлення з головної сторінки на мову відвідувача, теги `hreflang` і пропси для [островів](/uk/integrations/astro-islands).

## Встановлення {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/astro
```

```bash npm
npm install @i18n-micro/astro
```

```bash yarn
yarn add @i18n-micro/astro
```

</CodeGroup>

Peer-залежності: `astro` `^5.0.0 || ^6.0.0 || ^7.0.0`. Необов’язкові, лише для [островів](/uk/integrations/astro-islands): `vue` `^3.3.0`, `react` `^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`, `preact` `^10.0.0 || ^11.0.0`, `svelte` `^4.0.0 || ^5.0.0`.

## Налаштування {#setup}

Додайте інтеграцію. Вона вбудовує ваші словники в сервер і встановлює middleware, тож `src/middleware.ts` не потрібен:

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import node from '@astrojs/node'
import { i18nIntegration } from '@i18n-micro/astro'

export default defineConfig({
  output: 'server',
  adapter: node({ mode: 'standalone' }),
  integrations: [
    i18nIntegration({
      locale: 'en',
      fallbackLocale: 'en',
      locales: [
        { code: 'en', iso: 'en-US', displayName: 'English' },
        { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
        { code: 'fr', iso: 'fr-FR', displayName: 'Français' },
      ],
      translationDir: 'src/locales',
    }),
  ],
})
```

Словники стають кодом під час збирання: сервер нічого не читає з диска, тож він працює й на edge (Cloudflare, Vercel Edge). В `astro dev` зміна у файлі застосовується під час наступного запиту.

### Опції інтеграції {#integration-options}

| Опція | За замовчуванням | Примітки |
| --- | --- | --- |
| `locale` | обов’язкова | Локаль за замовчуванням. |
| `fallbackLocale` | `locale` | |
| `locales` | `[]` | Повні об’єкти `Locale`. Локаль із `disabled` не є локаллю жодного URL і не є ціллю перенаправлення. `iso` — тег, за яким визначаються форми множини, коли код не є таким тегом (`ua` → `uk-UA`). |
| `translationDir` | немає | Тека, що вбудовується в сервер, відносно кореня проєкту. |
| `disablePageLocales` | `false` | Файли сторінок вважаються кореневими перекладами. |
| `autoDetect` | `true` | Перенаправлення з головної сторінки, див. [Визначення локалі](#locale-detection). |
| `redirectToDefault` | `false` | `/` також перенаправляє, коли ніщо не віддає перевагу іншій локалі. |
| `localeCookie` | `'i18n-locale'` | `null` вимикає cookie. |
| `missingWarn` | `false` | |
| `middleware` | `true` | `false`: напишіть middleware самостійно, див. нижче. |

Runtime-налаштування публікуються у `virtual:i18n-micro/config` (`config.base` — це `base` Astro, `config.localeCodes` — увімкнені коди), а словники — у `virtual:i18n-micro/messages`.

### Власний middleware {#your-own-middleware}

Правило множини, обробник відсутніх ключів і адаптер маршрутизатора не можуть перейти з процесу конфігурації в серверний бандл. Для них передайте `middleware: false` і напишіть `src/middleware.ts`. Тоді конфігурацію `i18n` Astro буде встановлено за вас із `routing: 'manual'`, тож `Astro.currentLocale` і `astro:i18n` працюють. Astro не дозволяє цього налаштування без `src/middleware.ts`, тому з власним middleware інтеграції вони не працюють.

```ts
// src/middleware.ts
import { config } from 'virtual:i18n-micro/config'
import { messages } from 'virtual:i18n-micro/messages'
import { createAstroRouterAdapter, createI18n, createI18nMiddleware, localeIsoMap } from '@i18n-micro/astro'

const i18n = createI18n({
  locale: config.defaultLocale,
  fallbackLocale: config.fallbackLocale,
  localeIso: localeIsoMap(config.locales),
  messages: messages.root,
  routeMessages: messages.routes,
  plural: myPluralRule,
})

export const onRequest = createI18nMiddleware({
  i18n,
  defaultLocale: config.defaultLocale,
  locales: config.localeCodes,
  localeObjects: config.locales,
  autoDetect: config.autoDetect,
  redirectToDefault: config.redirectToDefault,
  localeCookie: config.localeCookie,
  base: config.base,
  routingStrategy: createAstroRouterAdapter(config.locales, config.defaultLocale),
})
```

Щоб натомість зчитувати теку під час виконання, використовуйте `loadTranslationsFromDir` і `loadTranslationsIntoI18n` з `@i18n-micro/astro/node` (лише Node).

### Опції middleware {#middleware-options}

| Опція | За замовчуванням | Примітки |
| --- | --- | --- |
| `i18n` | обов’язкова | Глобальний екземпляр; кожен запит отримує `i18n.fork(locale)`, вартість якого однакова незалежно від кількості словників. |
| `defaultLocale` | обов’язкова | |
| `locales` | обов’язкова | Коди локалей. |
| `localeObjects` | `locales` як `{ code }` | Повні об’єкти `Locale` для компонентів і SEO. |
| `autoDetect` | `true` | Перенаправлення з головної сторінки, див. [Визначення локалі](#locale-detection). |
| `redirectToDefault` | `false` | `/` також перенаправляє, коли ніщо не віддає перевагу іншій локалі, — на головну сторінку локалі за замовчуванням, як її визначає стратегія маршрутизації. |
| `localeCookie` | `'i18n-locale'` | `null` вимикає cookie. |
| `routingStrategy` | префікс, крім локалі за замовчуванням | Адаптер маршрутизатора. Методи, яких у ньому немає, беруться з адаптера за замовчуванням. |
| `base` | немає | `base` Astro: `config.base`. |

Файли сторінок (`src/locales/pages/blog/post/de.json`) — це маршрут `blog-post`: шлях сторінки, з’єднаний через `-`.

## Переклад {#translate}

```astro
---
// src/pages/index.astro
import { useI18n } from '@i18n-micro/astro'
import I18nT from '@i18n-micro/astro/i18n-t'

const { t, tc, locale } = useI18n(Astro)
---

<h1>{t('greeting', { name: 'Ada' })}</h1>
<p>{tc('apples', 3)}</p>
<I18nT keypath="welcome" tag="p" />
<p>{locale}</p>
```

`useI18n(Astro)` повертає `locale`, `defaultLocale`, `locales`, `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `getRoute`, `getRouteName(path?)`, `getLocaleFromPath(path?)`, `switchLocalePath(locale)`, `localizePath(path, locale?)`, `getBasePath(url?)`, `getI18n`, `addTranslations`, `addRouteTranslations`, `mergeTranslations` і `clearCache`. Він викидає помилку, якщо middleware не виконався. Хелпери `getI18n`, `getLocale`, `getDefaultLocale` і `getLocales` зчитують той самий `Astro.locals`.

Ім’я маршруту береться з маршруту без локалі: `/fr/blog/post` → `blog-post`, а кожен URL `src/pages/blog/[slug].astro` → `blog-slug`, тож одна тека `locales/pages/blog-slug/` обслуговує їх усі. `[...path]` — це `path`. За наявності `base` Astro хелпери приймають і повертають URL сайту: `switchLocalePath` і `localizePath` включають його, `getBasePath` — ні, бо `Astro.rewrite` приймає шлях без нього.

### Компоненти {#components}

Імпортуйте їх з `@i18n-micro/astro/<name>` (або `@i18n-micro/astro/components/<name>.astro`):

| Компонент | Пропси |
| --- | --- |
| `i18n-t` | `keypath`, `params`, `plural`, `number`, `date`, `relativeDate`, `tag` (`span`, будь-який тег), `html`, `hideIfEmpty`, `defaultValue`; інші атрибути передаються далі. З `html` результат кожної гілки рендериться як HTML, а `params` екрануються. Слотів немає |
| `i18n-link` | `href`, `locale` (цільова локаль, за замовчуванням поточна), `class`; інші атрибути передаються далі. Зовнішні URL, `#hash` і `?query` залишаються як написано; маршрут зберігає свій query, hash і кінцеву скісну риску |
| `i18n-switcher` | `class`, `activeClass` (`'active'`), `customLabels`; рендерить посилання на поточну сторінку в кожній увімкненій локалі, зі збереженням query |
| `i18n-group` | жодних, що змінюють вивід: `<div>` навколо свого слота, без префікса |

## Маршрути з префіксом локалі {#locale-prefixed-routes}

Тримайте одну сторінку на маршрут у `src/pages/` і додайте тонкі заглушки-перезаписи в `src/pages/[locale]/`:

```
src/pages/
  index.astro
  about.astro
  [locale]/
    index.astro
    about.astro
```

```astro
---
// src/pages/[locale]/about.astro
import { prepareLocaleRewrite } from '@i18n-micro/astro'

const target = prepareLocaleRewrite(Astro)
if (target instanceof Response) return target
return Astro.rewrite(target)
---
```

`prepareLocaleRewrite` повертає відповідь `404` для невідомої `:locale`, а інакше встановлює локаль в `Astro.locals` і повертає шлях без префікса. Middleware зберігає локаль, яка вже є в `locals`, тож перезаписана сторінка рендериться в ній. `getLocaleRewritePath(Astro)` повертає лише шлях, коли ви перевіряєте локаль самостійно.

## Визначення локалі {#locale-detection}

Локаль сторінки визначає URL:

1. Префікс локалі (`/fr/about` → `fr`; `/en/about` — теж `en`).
2. Інакше те, що повертає `getLocaleFromPath` адаптера маршрутизатора, якщо це не локаль за замовчуванням.
3. Інакше локаль за замовчуванням. `/about` — завжди сторінка локалі за замовчуванням, хай що каже cookie.

`autoDetect` — це підказка для перенаправлення лише на головній сторінці:

- Запит до `/`, cookie або `Accept-Language` якого віддає перевагу іншій локалі, отримує `302` на головну сторінку цієї локалі (`/de`). Ваги q враховуються; `de-DE` відповідає локалі `de`, а `de` — локалі `de-DE`.
- З `redirectToDefault` `/` завжди перенаправляє: на головну сторінку вподобаної локалі, а інакше — локалі за замовчуванням.
- Відповідь для `/` містить `Vary: Cookie, Accept-Language` (лише `Accept-Language`, коли `localeCookie` дорівнює `null`).
- Попередньо відрендерені сторінки ніколи не перенаправляють.

`detectLocale(pathname, cookies, headers, defaultLocale, locales, localeCookie?, routingStrategy?, autoDetect?)` повертає ту саму вподобану локаль для вашої власної логіки.

Cookie запам’ятовує вибір. Перегляд сторінки, що надходить зі сторінки того самого походження іншої локалі, — це перемикання відвідувачем, хоч би яке посилання привело його туди: HTML-відповідь встановлює cookie на нову локаль, а `/` не перенаправляє, тож перемикач потрапляє на головну сторінку локалі за замовчуванням. Ендпоінт, зображення, 404, надсилання форми та prefetch нічого не змінюють. «Те саме походження» — це те, що браузер повідомляє в `Sec-Fetch-Site`; без цього заголовка хост `Referer` порівнюється з хостом запиту, тому за проксі налаштуйте `security.allowedDomains` в Astro.

[Серверний острів](https://docs.astro.build/en/guides/server-islands/) або action не має локалі у своєму URL. Він рендериться для сторінки, яка його запросила, визначеної з `Referer`, у якому враховується лише шлях, тож проксі перед сервером нічого не змінює, і він ніколи не перенаправляє. Його відповідь містить `Vary: Referer`. Без `Referer` (політика `no-referrer`) він рендериться в локалі за замовчуванням, а на динамічній сторінці його маршрут береться з URL, тож словники сторінки до нього не потрапляють.

## Адаптер маршрутизатора {#router-adapter}

`createAstroRouterAdapter(locales, defaultLocale)` додає префікс до кожної локалі, крім локалі за замовчуванням. Адаптеру Astro потрібен лише `getCurrentPath`; інші члени необов’язкові й беруться з адаптера за замовчуванням: `getRouteName(path, locales, routePattern?)`, `getLocaleFromPath`, `switchLocalePath`, `localizePath`, `removeLocaleFromPath`, `resolvePath` (ціль перенаправлення з головної), `push`, `replace`, `getRoute`. Напишіть власний для URL із субдоменами чи суфіксами та передайте його в `createI18nMiddleware`.

## SEO {#seo}

```astro
---
// src/layouts/Layout.astro
import { useLocaleHead } from '@i18n-micro/astro'

const head = useLocaleHead(Astro, { baseUrl: 'https://example.com' })
---

<html lang={head.htmlAttrs.lang} dir={head.htmlAttrs.dir}>
  <head>
    {head.link.map((l) => <link rel={l.rel} href={l.href} hreflang={l.hreflang} />)}
    {head.meta.map((m) => <meta property={m.property} content={m.content} />)}
  </head>
  <body><slot /></body>
</html>
```

Він повертає `htmlAttrs` (`lang` з `iso`, `dir`), канонічне посилання (шлях без query), альтернативи `hreflang` для кожної увімкненої локалі з `seo !== false` плюс `x-default`, `og:locale`, `og:locale:alternate` і `og:url`. Опції: `baseUrl` (`site` з конфігурації Astro, інакше URL відносно кореня), `addDirAttribute` (`true`), `addSeoAttributes` (`true`), `hreflangBaseLanguage` (`false`).
