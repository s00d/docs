`@i18n-micro/react` і `@i18n-micro/preact` обгортають незалежний від фреймворку [runtime](/uk/integrations/runtime-package) у провайдер, хук `useI18n()` і чотири компоненти. Використовуйте їх у застосунку React або Preact, який не зібрано за допомогою Nuxt. Обидва пакети мають однаковий API; блок [Preact](#preact) перелічує кілька відмінностей, а спільна модель описана в розділі [Фреймворки](/uk/integrations/overview).

## Встановлення {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/react
```

```bash npm
npm install @i18n-micro/react
```

```bash yarn
yarn add @i18n-micro/react
```

</CodeGroup>

Peer-залежності: `react` `^18.0.0 || ^19.0.0`; `react-dom` (необов'язково, для рендерингу); `react-router-dom` `^6.0.0 || ^7.0.0` (необов'язково, лише для `@i18n-micro/react/router`). Протестовано на React 19.3 і 18.3, React Router 7.18 і 6.30.

## Налаштування {#setup}

```tsx
// src/main.tsx
import { createRoot } from 'react-dom/client'
import { createI18n, I18nProvider } from '@i18n-micro/react'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

createRoot(document.getElementById('root')!).render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
    <App />
  </I18nProvider>,
)
```

<Warning>

Створюйте екземпляр один раз — на рівні модуля або в ініціалізаторі `useState`, ніколи в тілі компонента.

</Warning>

`<I18nProvider>` приймає `i18n`, `locales`, `defaultLocale` і `routingStrategy`:

- Пропущений проп зберігає значення зовнішнього провайдера, включно з екземпляром.
- Якщо екземпляра немає взагалі, провайдер створює його з опцій `createI18n`, переданих поруч, тож пропси лишаються простими даними: `<I18nProvider locale="de" messages={messages}>`.
- Новий проп `locale` створює новий екземпляр із `messages` цього рендеру. Такий екземпляр живе в компоненті: якщо щось над ним призупиняється під час монтування, React його відкидає разом з усім, що до нього додали.

Усі опції `createI18n`, включно з `routeMessages`, описано в розділі [екземпляр](/uk/integrations/overview#the-instance).

## Переклад {#translate}

```tsx
import { useI18n } from '@i18n-micro/react'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' })}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

`useI18n()` повертає:

| Група | Члени |
| --- | --- |
| Переклад | `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` |
| Локаль і маршрут | `locale`, `fallbackLocale`, `currentRoute`, `setLocale`, `setRoute`, `getRoute`, `getLocales`, `defaultLocale()`, `getLocaleName` |
| Маршрутизація | `switchLocale`, `localePath`, `localeRoute` |
| Словники | `addTranslations`, `addRouteTranslations`, `clearCache` |

- Компонент перерендерюється, коли змінюється локаль, маршрут або доступний для читання словник, а також коли провайдер отримує новий об'єкт `locales` або `routingStrategy`. Словник локалі, яка не є ні активною, ні резервною, не спричиняє рендеру.
- `t` та інші методи перекладу змінюються лише разом зі сховищем, тож їх безпечно використовувати в `memo` і залежностях ефектів.

`useT` — це один рядок як значення. Компонент рендериться лише тоді, коли змінюється цей рядок, хоч би що відбувалося з іншими пропсами провайдера; `<I18nT>` від них також не залежить:

```tsx
const title = useT('page.title')
```

Завантажуйте додаткові словники будь-коли:

```tsx
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

useEffect(() => {
  import('./locales/de.json').then((m) => addTranslations('de', m.default))
  addRouteTranslations('en', 'about', { title: 'About us' })
  setRoute('about') // t('title') now reads the 'about' dictionary first
}, [])
```

Сам екземпляр також має `loadFromUrl(url, { locale, routeName })` для JSON через `fetch`.

## Перемикання локалі {#switch-locale}

```tsx
const { setLocale, switchLocale } = useI18n()

setLocale('de') // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Перемикання нічого не завантажує; спочатку додайте словник локалі. Запис у сховище для React синхронний, навіть усередині `startTransition`, тож компонент, який призупиняється через відсутній словник, показав би свій fallback. `useLocaleSwitch` спершу завантажує й зберігає старий інтерфейс, доки словник не з'явиться:

```tsx
const [switchTo, pending] = useLocaleSwitch((locale) => i18n.loadFromUrl(`/locales/${locale}.json`, { locale }))

<button disabled={pending} onClick={() => switchTo('de')}>Deutsch</button>
```

Перемагає останній виклик. Невдале завантаження відхиляється й залишає локаль без змін.

`<I18nGroup>` передає `t` з префіксом дочірньому render-prop. `<I18nT>` і `t()` усередині нього префікса не мають:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Маршрутизація {#routing}

Адаптер React Router міститься в підшляху, тож основна точка входу ніколи не імпортує `react-router-dom`. Йому потрібні `useLocation()` і `useNavigate()`, тому створюйте його всередині компонента під роутером:

```tsx
// src/App.tsx
import { useMemo } from 'react'
import { BrowserRouter, Route, Routes, useLocation, useNavigate } from 'react-router-dom'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/react'
import { createReactRouterAdapter } from '@i18n-micro/react/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Localized() {
  const location = useLocation()
  const navigate = useNavigate()
  // memoized: a new object on every render re-renders every `useI18n()` consumer
  const routingStrategy = useMemo(() => createReactRouterAdapter(locales, 'en', location, navigate), [location, navigate])
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      <Routes>
        <Route path="/:locale?" element={<Home />} />
        <Route path="/:locale?/about" element={<About />} />
      </Routes>
    </I18nProvider>
  )
}

export default function App() {
  return (
    <BrowserRouter>
      <Localized />
    </BrowserRouter>
  )
}
```

Адаптер додає префікс до кожної локалі, крім локалі за замовчуванням (`/about`, `/de/about`), і рендерить `<I18nLink>` як `<Link>` React Router. Встановлюйте локаль з URL самостійно (наприклад, з `useParams().locale` в ефекті). Для будь-якого іншого роутера напишіть адаптер із `getCurrentPath`, `push` і `replace` (усі обов'язкові) — див. [Адаптер роутера](/uk/integrations/overview#router-adapter).

## SSR {#ssr}

`renderToString` працює: `useI18n()` має серверний знімок. Створюйте один екземпляр на запит і додавайте його словники перед рендерингом, щоб запити різними локалями не мали спільного стану, або передавайте провайдеру прості дані.

### Гідратація {#hydration}

Числа, форми множини та текст гідратуються як є. Дата залежить від часового поясу, а відносна дата — від годинника: задайте `timeZone` на сервері та в браузері, а для `tdr` передайте браузеру час сервера через `now`. `<I18nT>` з `date` або `relativeDate` встановлює `suppressHydrationWarning`, тож розбіжність не ламає гідратацію, але текст сервера лишається, доки текст не зміниться. Це діє лише на один рівень: `children`, що обгортають переклад в елемент, усе одно падають через розбіжність, тож задайте їм той самий `timeZone`.

### Серверні компоненти {#server-components}

Пакет позначає свій клієнтський код директивою `'use client'`. `@i18n-micro/react/server` містить `createI18n` і `I18nT` без хуків, який приймає екземпляр як проп, тож текст не потрапляє в клієнтський бандл. За умови `react-server`, як у app router Next.js, основна точка входу також розв'язується в нього, але TypeScript за замовчуванням цього не знає: імпортуйте з `/server`. `@i18n-micro/react/client` завжди дає клієнтську точку входу.

```tsx
// app/[locale]/layout.tsx: a server component
import { cache } from 'react'
import { createI18n, I18nT } from '@i18n-micro/react/server'
import { I18nProvider } from '@i18n-micro/react/client'
import { loadMessages } from './messages'

const getI18n = cache(async (locale: string) => createI18n({ locale, messages: await loadMessages(locale) }))

export default async function Layout({ params, children }) {
  const { locale } = await params
  const i18n = await getI18n(locale)
  return (
    <I18nProvider locale={locale} messages={{ [locale]: i18n.resolveTranslations() }}>
      <h1>
        <I18nT i18n={i18n} keypath="title" />
      </h1>
      {children}
    </I18nProvider>
  )
}
```

Рендериться через `react-server-dom-webpack`; на самому застосунку Next.js це не перевірялося.

## Preact {#preact}

`@i18n-micro/preact` зібрано з того самого вихідного коду, на самому Preact, без `preact/compat`: той самий екземпляр, провайдер, хуки та компоненти. Відмінності:

| | React | Preact |
| --- | --- | --- |
| Peer-залежність | `react` (+ необов'язковий `react-router-dom`) | `preact` `^10.0.0 \|\| ^11.0.0`, протестовано на 10.29 і 11.1 |
| Клас екземпляра | `ReactI18n` | `PreactI18n` |
| Адаптер роутера | `createReactRouterAdapter` з `/router` | `createBrowserHistoryAdapter(locales, defaultLocale, ssrUrl?)` з `/router` |
| Перерендер | `useSyncExternalStore` | підписка через layout-ефект, що повторно перевіряє сховище |
| Серверні компоненти | `/server`, `/client` | немає |

`createBrowserHistoryAdapter` працює з будь-яким роутером на History API (wouter, preact-router): `push` і `replace` викликають `history.pushState` / `replaceState` і надсилають `popstate`, а `<I18nLink>` рендерить звичайний `<a>`, що виконує навігацію через `push`. Сервер не має адресного рядка: передайте URL запиту як `ssrUrl`, інакше посилання та перемикач рендеряться як на `/`. У браузері перевагу має адресний рядок.

```tsx
// src/main.tsx
import { render } from 'preact'
import { createI18n, I18nProvider } from '@i18n-micro/preact'
import { createBrowserHistoryAdapter } from '@i18n-micro/preact/router'
import { App } from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={createBrowserHistoryAdapter(locales, 'en')}>
    <App />
  </I18nProvider>,
  document.getElementById('app')!,
)
```

Повні сигнатури: [довідник Preact](/uk/api/packages/preact).
