# 🔧 Генератор типів (`@i18n-micro/types-generator`)

Пакет `@i18n-micro/types-generator` надає автоматичну генерацію типів TypeScript для ключів перекладу. Він аналізує ваші JSON-файли перекладу та генерує сурові типи, уможливлюючи повну типобезпеку та автокомпліт для ключів перекладу.

## 📖 Огляд

`@i18n-micro/types-generator` — це опційна dev-залежність, що покращує ваш досвід розробки шляхом:

- 🔍 **Автоматична генерація типів** — сканує JSON-файли перекладу та генерує типи TypeScript
- ✅ **Типобезпека** — запобігає одруківкам і невалідним ключам перекладу на етапі компіляції
- 🎯 **Підтримка автокомпліту** — повний IDE-автокомпліт для ключів перекладу
- 🔄 **Hot Reload** — автоматично регенерує типи при змінах файлів перекладу
- 🚀 **Без рантайм-накладних витрат** — типи існують лише на етапі компіляції, без впливу на розмір бандла

## 🎯 Швидкий старт

### Для проєктів Nuxt

Додайте модуль у `nuxt.config.ts`:

```typescript
import { defineNuxtConfig } from 'nuxt/config'

export default defineNuxtConfig({
  modules: [
    'nuxt-i18n-micro',
    '@i18n-micro/types-generator/nuxt', // Add types generator
  ],
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    translationDir: 'locales', // Path to your translation files
  },
})
```

Генератор автоматично:

- Просканує всі JSON-файли у вашому каталозі `locales`
- Згенерує типи у `.nuxt/i18n-micro.d.ts`
- Спостерігатиме за змінами й автоматично регенеруватиме типи

### Для проєктів Vue/Vite

Додайте плагін у `vite.config.ts`:

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { I18nTypesPlugin } from '@i18n-micro/types-generator'

export default defineConfig({
  plugins: [
    vue(),
    I18nTypesPlugin({
      srcDir: 'src',
      translationDir: 'locales',
      outputFile: 'src/i18n-types.d.ts', // Optional: custom output path
    }),
  ],
})
```

Переконайтеся, що згенерований файл включено у ваш `tsconfig.json`:

```json
{
  "include": ["src/**/*", "src/i18n-types.d.ts"]
}
```

## 📁 Структура файлів перекладу

Генератор підтримує як плоскі, так і вкладені структури перекладу:

```
locales/
  en.json
  fr.json
  pages/
    home/
      en.json
      fr.json
    about/
      en.json
      fr.json
```

**Приклад `locales/en.json`:**

```json
{
  "greeting": "Hello, {name}!",
  "header": {
    "title": "Welcome",
    "subtitle": "Subtitle"
  },
  "errors": {
    "404": "Not found",
    "500": "Server error"
  },
  "apples": "no apples | one apple | {count} apples"
}
```

Генератор створить типи для всіх ключів, включно з вкладеними:

```typescript
// Generated types
declare module '@i18n-micro/types' {
  export interface DefineLocaleMessage {
    greeting: string
    'header.title': string
    'header.subtitle': string
    'errors.404': string
    'errors.500': string
    apples: string
  }
}
```

## 💡 Використання

Коли типи згенеровано, ви отримуєте повну типобезпеку:

```typescript
import { useI18n } from '@i18n-micro/vue'

const { t } = useI18n()

// ✅ Type-safe: autocomplete works
t('greeting', { name: 'World' })
t('header.title')
t('errors.404')

// ❌ Type error: key doesn't exist
t('invalid.key') // Error: Argument of type '"invalid.key"' is not assignable
```

### Nuxt-специфічна нотатка

**У проєктах Nuxt типобезпека працює лише з композаблом `useI18n`.** Згенеровані типи застосовуються до значення, яке повертає композабл, забезпечуючи типобезпеку при використанні методів `t()`, `ts()`, `tc()` та `has()`.

```typescript
// ✅ Correct: Using useI18n composable
<script setup lang="ts">
import { useI18n } from '#imports'

const { t } = useI18n()
t('greeting') // Type-safe with autocomplete
</script>

// ❌ Not type-safe: Direct access to $i18n or other methods
// Type safety is only available through the useI18n composable
```

## 🔄 Динамічні ключі

Іноді вам потрібно використовувати динамічні ключі (наприклад, на основі вводу користувача чи відповідей API). Генератор надає помічник-тип `ScopedKey` для безпечного використання динамічних ключів.

### Чому не runtime type guards?

**Runtime type guards не рекомендовані** для i18n-micro, бо:

1. **Розмір бандла** — генерація JavaScript-масиву всіх ключів роздула б ваш бандл
2. **Продуктивність** — рантайм-перевірки додають зайві накладні витрати
3. **Філософія** — i18n-micro розроблений бути легким і швидким

### TypeScript-спосіб: type assertions

Для динамічних ключів використовуйте type assertion TypeScript:

```typescript
import type { TranslationKey, ScopedKey } from '@i18n-micro/types'

// ❌ Type error: dynamic key
const status = 'pending'
t(`status.${status}`) // Error: string is not assignable to TranslationKey

// ✅ Solution 1: Type assertion (if you're sure the key exists)
t(`status.${status}` as TranslationKey)

// ✅ Solution 2: ScopedKey helper (safer, checks prefix exists)
function getStatusText(status: string) {
  return t(`status.${status}` as ScopedKey<'status'>)
  // TypeScript verifies that keys starting with 'status.' exist
}

// ✅ Solution 3: Runtime check with has()
if (has(`status.${status}`)) {
  t(`status.${status}` as TranslationKey)
}
```

### Помічник ScopedKey

Тип `ScopedKey<Scope>` дозволяє звужувати динамічні ключі за префіксом:

```typescript
import type { ScopedKey } from '@i18n-micro/types'

// Assuming you have keys: 'errors.404', 'errors.500', 'btn.save'

function getErrorText(code: string) {
  // ✅ Safer than plain TranslationKey
  // TypeScript verifies that 'errors.*' keys exist
  return t(`errors.${code}` as ScopedKey<'errors'>)
}

// ❌ Type error: 'btn' prefix doesn't match 'errors'
function getErrorTextWrong(code: string) {
  return t(`errors.${code}` as ScopedKey<'btn'>) // Error
}
```

## 🎨 Розширене використання

### Робота з посайтовими перекладами

Генератор автоматично включає ключі з посайтових файлів перекладу:

```
locales/
  en.json                    # Root-level translations
  pages/
    home/
      en.json               # Route-specific translations
    about/
      en.json
```

Усі ключі як з root-, так і з посайтових файлів включаються у згенеровані типи.

### Вимкнення посайтових локалей

Якщо ви використовуєте `disablePageLocales: true` у своєму i18n-конфігу, генератор трактуватиме всі файли (включно з тими у `pages/`) як root-переклади.

## 🐛 Пошук проблем

### Типи не оновлюються

1. **Перевірте шляхи файлів** — переконайтеся, що `translationDir` вказує на правильний каталог
2. **Перезапустіть TypeScript-сервер** — у VS Code: `Cmd/Ctrl + Shift + P` → «TypeScript: Restart TS Server»
3. **Перевірте tsconfig.json** — переконайтеся, що згенерований файл включено

### Помилки типів після додавання ключів

1. **Регенеруйте типи** — генератор має авто-регенерувати, але ви можете запустити вручну
2. **Перевірте синтаксис JSON** — невалідні JSON-файли пропускаються з попередженням
3. **Перезапустіть dev-сервер** — іноді потрібно, щоб зміни набули чинності

### Автокомпліт не працює

1. **Перевірте включення файла** — переконайтеся, що згенерований `.d.ts` файл є у `include` вашого `tsconfig.json`
2. **Перевірте module augmentation** — згенерований файл має використовувати `declare module '@i18n-micro/types'`
3. **Версія TypeScript** — потребує TypeScript 4.1+ для template literal types

## 📚 Довідник API

### `generateTypes(options: GeneratorOptions)`

Згенерувати типи вручну (корисно для скриптів чи CI):

```typescript
import { generateTypes } from '@i18n-micro/types-generator'

await generateTypes({
  srcDir: './src',
  translationDir: 'locales',
  outputFile: './src/i18n-types.d.ts',
})
```

### `flattenKeys(obj: Record<string, unknown>, prefix?: string)`

Утилітарна функція для сплющення вкладених обʼєктів перекладу:

```typescript
import { flattenKeys } from '@i18n-micro/types-generator'

const keys = flattenKeys({
  header: { title: 'Title' },
  footer: { copyright: 'Copyright' },
})
// Returns: ['header.title', 'footer.copyright']
```

## 🔍 Як це працює

1. **Сканування** — використовує `globby`, щоб знайти всі `**/*.json` файли у теці перекладів
2. **Парсинг** — парсить кожен JSON-файл та витягує всі ключі через рекурсивне сплющення
3. **Дедуплікація** — обʼєднує ключі з усіх файлів в унікальний набір
4. **Генерація** — створює `.d.ts`-файл з `declare module` augmentation
5. **Спостереження** — у dev-режимі спостерігає за змінами файлів та регенерує типи

Згенерований файл використовує module augmentation TypeScript, щоб розширити `DefineLocaleMessage` у `@i18n-micro/types`, що автоматично оновлює тип `TranslationKey` у всьому вашому проєкті.

## 🎯 Кращі практики

1. **Тримайте переклади організованими** — використовуйте вкладені обʼєкти для повʼязаних ключів
2. **Використовуйте узгоджене іменування** — дотримуйтесь конвенції іменування (наприклад, `errors.*`, `buttons.*`)
3. **Використовуйте ScopedKey** — використовуйте `ScopedKey` для динамічних ключів замість чистих assertion
4. **Перевіряйте типи в CI** — запускайте перевірку типів у вашому CI-конвеєрі
5. **Не редагуйте згенеровані файли** — `.d.ts` файл авто-генерується і буде перезаписаний
