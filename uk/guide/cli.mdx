`@i18n-micro/cli` керує файлами локалей проєкту Nuxt. Він зчитує `locales`, `defaultLocale`, `translationDir` і ваші шари з `nuxt.config`, тож власної конфігурації не потребує.

![A terminal running i18n-micro check, which lists a missing, an undefined and four unused keys and fails, then extract, which adds the undefined key, then clean --dryRun, which lists the four keys it would remove](/images/cli/demo.gif)

| Команда | Використовуйте, щоб |
| --- | --- |
| `check` | Зупиняти збірку через будь-які проблеми з файлами локалей |
| `translate` | Заповнювати відсутні ключі через сервіс перекладу |
| `clean` | Видаляти ключі, які ніде не використовуються |
| `rename` | Переміщувати ключ або цілий простір імен скрізь одночасно |

```bash
npm install -D @i18n-micro/cli
npx i18n-micro --help
```

Запускайте з кореня застосунку або вкажіть його через `--cwd`. Кожен прапорець кожної команди описано в [довіднику команд](/uk/api/cli).

<Tip>

**Переходите з nuxt-i18n-micro-cli?** `@i18n-micro/cli` замінює його; виконувані файли `i18n-micro` і `i18n-micro-cli` лишаються. Див. [таблицю старих команд](#moving-from-nuxt-i18n-micro-cli).

</Tip>

## Використання в CI {#use-it-in-ci}

```bash
i18n-micro check
```

`check` — це контрольна точка. Вона повідомляє:

| Перевірка | Означає |
| --- | --- |
| `missing` | Ключ локалі за замовчуванням відсутній у локалі |
| `empty` | Значення дорівнює `''`. Застосунок показує порожнечу, а не резервний переклад |
| `extra` | Локаль має ключ, якого немає в локалі за замовчуванням |
| `placeholders` | `{name}` втрачено або додано, або форма множини втратила свої форми |
| `undefined` | Код використовує ключ, якого немає в локалі за замовчуванням |
| `unused` | Ключ ніде в проєкті не використовується |
| `duplicates` | Той самий текст під різними ключами. Вимкнено за замовчуванням: передайте `--duplicates` |

- `--only missing,placeholders` запускає лише деякі перевірки; перевірка, вказана в `--only`, яку не вдалося виконати, вважається проваленою.
- `--json` видає звіт для інструментів.
- `--ignore` пропускає вихідні файли.
- Поки ключі обчислюються під час виконання, `unused` пропускається, і звіт пояснює чому.

Кожна команда завершується одним із трьох кодів, тож конвеєр може відрізнити проблему з вашими перекладами від проблеми з інструментом:

| Код виходу | Значення |
| --- | --- |
| `0` | Нема про що повідомити |
| `1` | Знайдено проблеми |
| `2` | Команду не вдалося виконати: помилка використання, пошкоджений файл, невдалий запит |

Інші команди, варті кроку в CI:

```bash
i18n-micro format --check      # fails if a file is not formatted
i18n-micro lint                # stray spaces, empty values, your own regex rules
i18n-micro stats --baseRef main
```

## Синхронізація локалей {#keep-locales-in-step}

| Команда | Що робить |
| --- | --- |
| `extract` | Перелічує ключі, які використовує код, але для яких ще немає тексту. Текст за замовчуванням, як у `$t('key', {}, 'Welcome')`, потрапляє в локаль за замовчуванням. |
| `sync` | Видаляє ключі, яких немає в локалі за замовчуванням. Спершу спробуйте `--dryRun`. |
| `clean` | Видаляє ключі, які ніде не використовуються. Спершу спробуйте `--dryRun`. |
| `search` | Знаходить ключі та значення й показує, де використовується кожен ключ. |
| `stats` | Повнота для кожної локалі; `--baseRef main` порівнює з git-посиланням. |

`sync` зупиняється так само, як `clean`, коли мав би видалити ключ, невикористання якого не може довести, а також коли локаль за замовчуванням не має з чим порівнювати. Якщо видаляти нічого, він ніколи не зупиняється, тож сам по собі `$t(item.label)` не є причиною для `--force`.

<Note>

`extract` і `sync` ніколи не записують `''` для ключа без перекладу. Ключ лишається відсутнім, тож під час виконання застосовується `fallbackLocale`, а `check` про нього повідомляє. Порожній рядок був би визначеним значенням і показував би порожнечу.

</Note>

### Що читають команди {#what-the-commands-read}

`check`, `extract`, `sync`, `clean`, `search` і `rename` читають вихідний код усього проєкту, а не фіксований список тек:

- **Читаються:** шаблони та скрипти через парсер, `.html` і Pug як текст, кожен шар, а також теки поза коренем, на які вказує псевдонім або `components`.
- **Пропускаються:** `node_modules`, результати збірки та файли локалей. Додайте власні через `--ignore 'legacy/**,*.stories.ts'`.
- **Тестовий код** вважається використанням, тож `clean` і `check --only unused` зберігають ключ, який читає лише тест. Він ніколи не додає ключ: `extract` пропускає такі ключі, а `check` не повідомляє про них як про невизначені.

Тестовий код — це кореневі теки `tests`, `test`, `__tests__`, `e2e`, `cypress` і `playwright`, а також файли JavaScript і TypeScript `.spec` і `.test` (`.ts`, `.tsx`, `.mts`, `.js`, `.jsx`, `.mjs` тощо) будь-де. Лише кореневі теки звільнені від описаних нижче сумнівів: `pages/tests/[id].vue` — така сама сторінка, як і будь-яка інша, так само як `public/` і мініфіковані файли, код яких не є частиною застосунку.

Команди розпізнають:

- `$t`, `$ts`, `$tc`, `$has` і `$_t(route)`;
- `t()` з `useI18n()` і `useTranslationServerMiddleware()`;
- `<i18n-t keypath>` у шаблонах і JSX, а також `<i18n-group prefix>`;
- псевдоніми на кшталт `const { t: tr } = useI18n()`.

### Як вирішує `clean` {#how-clean-decides}

`clean` радше залишить мертвий ключ, ніж видалить живий. Ключ лишається, якщо виконується будь-що з цього:

- його використовує виклик, або ключ нижче чи вище за ним;
- рядок у коді дорівнює йому: `const key = 'menu.home'`, `<Item label="menu.home" />`;
- JSON-, YAML- або Markdown-файл у проєкті містить його;
- обчислюваний ключ має статичний початок, що його охоплює: `` $t(`status.${state}`) `` зберігає все під `status.`;
- його визначає шар.

`clean` зупиняється, нічого не змінюючи, коли не може знати напевно, і пояснює чому:

- ключ повністю обчислюваний, як у `$t(name)`, `<i18n-t :keypath="name" />` або `<i18n-t v-bind="props" />`;
- `$t` передається як значення, як у `items.map($t)`;
- функція з назвою `t` отримує обчислюваний аргумент і походить із параметра, імпорту або виклику: вона може бути обгорткою над справжньою. Функція, визначена в тому самому файлі, не враховується, оскільки обгортка мала б власний виклик усередині;
- вихідний файл не вдається розібрати;
- жоден файл не використовує взагалі жодного ключа, що зазвичай означає пошук не в тому місці;
- файл локалі є символьним посиланням за межі проєкту, тож його може читати інший застосунок.

## Переклад відсутніх ключів {#translate-missing-keys}

```bash
i18n-micro translate --dryRun                     # keys and characters per locale, nothing sent
export I18N_TRANSLATE_TOKEN=...                   # or put it in .env
i18n-micro translate --service deepl --locale de,fr
```

- `translate` заповнює відсутні або порожні ключі; `--replace` перекладає все заново.
- Заповнювачі та форми множини захищені. Переклад, який втратив заповнювач, не записується: ключ потрапляє до списку, а команда завершується з кодом `1`.
- Кожен пакет зберігається до відправлення наступного запиту, тож збій коштує лише невдалого запиту.

| `--service` | Сервіс | `--token` | Корисні `--options` |
| --- | --- | --- | --- |
| `ai` | Vercel AI Gateway, OpenAI, Anthropic або будь-який OpenAI-сумісний сервер | API-ключ, або `AI_GATEWAY_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` | `provider`, `model`, `baseUrl`, `maxTokens` |
| `azure` | Azure Translator | Ключ підписки | `region` |
| `deepl` | DeepL, включно з безкоштовними ключами | Ключ автентифікації | `formality`, `glossaryId`, `context` |
| `google` | Google Cloud Translation v2 | API-ключ | `model` |
| `libretranslate` | LibreTranslate | Необов'язково | `baseUrl` |
| `yandexcloud` | Yandex Cloud Translate | API-ключ або IAM-токен з `authScheme:Bearer` | `folderId`, `model` |

Опції — це пари `key:value`: `--options provider:openai,model:gpt-4o-mini`. Усі сервіси також приймають `baseUrl`, `retries`, `retryDelayMs` і `timeoutMs`. Запит на переклад може вже бути оплачений, тому він повторюється лише після `429` або `503`, і не тоді, коли сервіс просить зачекати понад хвилину.

<Warning>

Прапорці видно в історії оболонки та списках процесів, тож передавайте токен через змінну оточення. CLI маскує те, що вважає секретним, усюди, де це виводить, включно з `--debug`: токени, ключі провайдерів, облікові дані Basic, а також query й облікові дані налаштованого вами URL. Сервер, який переформатовує ключ перед тим, як повернути його у відповіді, поза межами його впливу, тож обережно поводьтеся з журналами невдалого запуску.

</Warning>

Сервіс `ai` дотримується глосарію. Якщо існує `.i18n-glossary.json`, він використовується без прапорця; `--glossaryFile` обирає інший файл.

```json .i18n-glossary.json
{ "entries": [{ "source": "Cart", "target": "Warenkorb", "to": "de" }] }
```

## Перетворення жорстко закодованого тексту на ключі {#turn-hardcoded-text-into-keys}

```bash
i18n-micro text-to-i18n --dryRun   # list what would change
i18n-micro text-to-i18n            # rewrite the templates
```

```vue
<!-- before -->
<h1>Welcome to our site</h1>
<!-- after -->
<h1>{{ $t('pages.index.welcome-to-our') }}</h1>
```

Переписуються лише шаблони `.vue` самого проєкту, а не шаблони шару чи цілі псевдоніма. Кожен переписаний файл повторно розбирається перед записом. Ці випадки потрапляють до списку й зберігають свій текст:

- текст у файлах `.ts` і скриптах, оскільки `$t` доступний не скрізь;
- текст поруч із розміткою чи інтерполяцією, як-от `<p>Hello <b>world</b> today</p>`: половину речення не можна перекласти окремо;
- згенерований ключ, що конфліктував би з іншим, як це може статися з батьківською сторінкою та її дочірньою;
- відомий ключ, який не можна взяти в лапки.

<Warning>

Спершу зробіть коміт і перегляньте diff.

</Warning>

## Перейменування ключа {#rename-a-key}

```bash
i18n-micro rename --from common.save --to actions.save
i18n-micro rename --from settings --to account.settings   # a whole namespace
```

`rename` редагує синтаксичне дерево, тож коментарі та непов'язані рядки лишаються як є, а псевдоніми та `:keypath` відстежуються. Власний файл шару ніколи не змінюється. Команда попереджає про те, що не може переписати, і залишає це без змін:

- обчислюваний ключ під старою назвою;
- кожен простий рядок, що дорівнює йому;
- шаблон Pug;
- джерело в шарі або в теці поза проєктом.

`--to` має бути ключем, який можна записати в коді: без лапок, без зворотної скісної риски, без порожнього сегмента, без `__proto__`.

## Обмін файлами з перекладачами {#exchange-files-with-translators}

```bash
i18n-micro export --format csv
i18n-micro import --format csv --dryRun
```

**`export`** записує кожен ключ кожної локалі, включно з неперекладеними, з текстом локалі за замовчуванням як джерелом: стовпець `Source` у CSV, коментар `#.` у PO.

- Без `--dir` PO потрапляє в `pots`, а CSV — у `csv_exports`.
- Команда фіксує записане в `.i18n-export.json` у вихідній теці. Вона зупиняється, коли файл змінився відтоді й містить переклади, яких немає у файлах локалей, включно з fuzzy-записами PO; `--force` їх перезаписує. Звичайні зміни файлів локалей її не зупиняють.

**`import`** зливає дані, пропускає порожні клітинки та записи PO, позначені `fuzzy`.

- Ключ, що перезаписав би значення, або значення поверх цілої групи ключів потрапляє до списку й пропускається, а команда завершується з кодом `1`.
- Команда зупиняється з кодом `2` на каталозі в неочікуваному місці, каталозі сторінки, який не записав останній експорт, лапках не на своєму місці в CSV або записі сторінки за `disablePageLocales`.

Для платформи перекладу використовуйте її власний CLI: налаштування [Crowdin](/uk/guide/crowdin) синхронізує JSON-файли, включно з файлами сторінок.

## Синхронізація з власним ендпоінтом {#sync-with-your-own-endpoint}

`sync-remote` обмінює глобальні файли локалей з HTTP-ендпоінтом, який ви запускаєте. Файли сторінок лишаються локальними, і команда про це повідомляє. Опишіть ендпоінт у `.i18n-remote.json`:

```json .i18n-remote.json
{ "url": "https://translations.example.com", "path": "translations" }
```

Ендпоінт відповідає на `GET` і `PUT` об'єктом `{ locale: messages }`. Автентифікуйтеся через `auth: { username, password }` або передайте bearer-токен в `I18N_REMOTE_TOKEN`.

| | Pull | Push |
| --- | --- | --- |
| Що передається | Заповнює те, чого у вас немає, і зберігає ключі, які є лише у вас | Надсилає власні ключі проєкту, а не ключі шару, і не включає ваші порожні значення |
| Конфлікти | Ключ, що відрізняється з обох боків: нічого не записується, код `1`; `--force` бере віддалене значення | PUT замінює документ, тож push спершу читає ендпоінт і зупиняється з кодом `1`, якщо там є текст, якого у вас немає; `--force` його перезаписує. Ендпоінту, що відповідає `404`, нічого втрачати |
| `--dryRun` | Читає з ендпоінта, перелічує зміни, нічого не записує | Повідомляє, що було б надіслано, не звертаючись до ендпоінта |

Локаль, яку ви не налаштували, пропускається, а порожнє віддалене значення нічого не очищує.

## Перехід з nuxt-i18n-micro-cli {#moving-from-nuxt-i18n-micro-cli}

| Стара команда | Тепер |
| --- | --- |
| `validate` | `check` |
| `diff` | `check --only missing` |
| `check-duplicates` | `check --only duplicates` |
| `export-csv`, `import-csv` | `export --format csv`, `import --format csv` |
| `--potsDir`, `--csvDir` | `--dir` |
| `estimate` | `translate --dryRun` |
| `glossary` | Редагуйте `.i18n-glossary.json`; `translate` читає його сам |
| `backup`, `restore` | Git, який уже зберігає ваші файли локалей |
| `init` | `nuxi init`, потім додайте `nuxt-i18n-micro` до `modules` |
| `split` | Видалено: модуль не читає розділені файли |
| `optimize` | `check --only duplicates` |
| `replace-values` | Ваш редактор або `sed` |
| `stats --full` | `stats`; подробиці є в [DevTools](/uk/guide/devtools) |
| `search --hardcodedOnly` | `text-to-i18n --dryRun` |
| `search --preferUnused`, `--onlyVue` | Видалено |
| Правила `lint` `no-html-tags`, `no-special-chars`, `no-mixed-case`, `no-missing-punctuation`, `no-inconsistent-pluralization` | Видалено: вони позначали звичайний текст. Напишіть запис `customRegexRules`, якщо потрібно |
| `text-to-i18n --extractOnlyDirs`, `--extractOnlyPatterns`, `--verbose` | Видалено: код ніколи не переписується |
| `--logLevel verbose` | Видалено: він нічого не робив |

**Видалені сервіси:** `googlefree`, `yandex` (використовуйте `yandexcloud`), `ibm`, `lingvatranslate`, `modernmt`, `lilt`, `unbabel`, `reverso`, `baidu`, `papago`, `tencent`, `systran`, `mymemory`.

**Видалені типи `sync-remote`:** `github`, `gitlab`, `crowdin`, `lokalise`, `tolgee`, `weblate`. Використовуйте власний CLI платформи або `custom`, якому більше не потрібен `type`.

### Змінена поведінка {#changed-behaviour}

- `extract` і `sync` більше не записують `''`. Ключі лишаються відсутніми, і `check` про них повідомляє. `extract` записує ключ лише тоді, коли код надає його текст.
- `extract` записує ключі сторінок у `locales/pages/<route name>/`, звідки їх читає модуль, і сканує `app/` у Nuxt 4. Перенесіть усе з тек на кшталт `pages/_about` і `pages/blog_` та видаліть зайвий `locales/pages/<locale>.json`.
- `translationDir` з `nuxt.config` враховується; раніше кожна команда мовчки використовувала `locales`.
- Без `defaultLocale` значенням за замовчуванням є `en`, як у модулі, і `DEFAULT_LOCALE` враховується. Раніше це була перша локаль.
- `check` і `sync` використовують локаль за замовчуванням як еталон і перевіряють файли сторінок. `"a.b"` і `a: { b }` вважаються одним ключем.
- `clean` зберігає ключ, що використовується будь-де, у будь-якій області видимості, і зупиняється, коли використання неможливо довести. `--include` і `--exclude` визначають, що можна видаляти.
- `sync` зупиняється так само, а також коли локаль за замовчуванням не має ключів для порівняння. `--force` це перевизначає. Він також зупиняється, коли `DEFAULT_LOCALE` обрав інший еталон, ніж `nuxt.config`.
- Довгі прапорці з одним дефісом і зайві аргументи є помилками: `clean -dryRun` більше не запускає `clean`.
- Файл лише для читання або файл не в UTF-8 неможливо зберегти: команда зупиняється, перш ніж щось змінити. Читати такий файл можна. Повторюваний ключ, ключ з назвою `__proto__` і ціле число понад 2^53 зупиняють команду, оскільки під час збереження вони були б втрачені.
- Прапорець, що потребує значення, після якого йде інший прапорець, є помилкою; пишіть `--flag=--value` для значення, що починається з дефіса. Булевий прапорець приймає лише `true` або `false`.
- `export` зупиняється, а не перезаписує переклади, які ніколи не імпортувалися.
- Коди виходу — `0`, `1` і `2`; раніше збої мали код `1`, а `diff` і `check-duplicates` завжди `0`.
- `lint --fix` більше не залишає файлів `.bak`.
- Збереження зберігає відступи файлу, закінчення рядків, фінальний перенос рядка, символьне та жорстке посилання, а файли, які не змінювалися, не чіпає.
- Помилково введений або видалений прапорець тепер є помилкою, а не мовчки ігнорується.
- Шляхи на кшталт `--dir` відносні до проєкту, а не до оболонки.
- `ai` більше не завантажує пакети `@ai-sdk/*`: використовуйте `provider` `gateway`, `openai` або `anthropic`, або `baseUrl` для OpenAI-сумісного сервера.
