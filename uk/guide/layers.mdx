description: "Діліться конфігурацією i18n і файлами перекладів через шари Nuxt та обслуговуйте локалі на власних доменах."
---

Шар Nuxt може містити конфігурацію i18n і теку `locales/` для кількох застосунків, а кожен застосунок додає або перевизначає те, що йому потрібно. Ця сторінка показує, як це зробити, а також як одна збірка обслуговує кілька доменів.

## Спільна конфігурація та переклади {#share-config-and-translations}

```ts
// base/nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    defaultLocale: 'en',
  },
})
```

```ts
// shop/nuxt.config.ts
export default defineNuxtConfig({
  extends: ['../base'], // a layer directory or package, not a nuxt.config file
  i18n: {
    locales: [
      { code: 'es', iso: 'es-ES' }, // added
      { code: 'fr', disabled: true }, // the base layer's fr, switched off here
    ],
  },
})
```

- **Конфігурація:** скалярні опції в застосунку замінюють опції шару. Масиви `locales` з усіх шарів поєднуються, а записи з однаковим `code` зливаються в один, де перевагу мають поля застосунку, тож застосунок може додати локаль або задати поля на кшталт `disabled: true` для успадкованої.
- **Переклади:** `locales/` кожного шару зливаються ключ за ключем — спочатку шар, останнім застосунок, тож ключ у `shop/locales/en.json` перевизначає той самий ключ у `base/locales/en.json`. Файли сторінок (`locales/pages/<page>/`) зливаються так само.
- **Сторінки:** `$defineI18nRoute` зчитується зі сторінок кожного шару.

Щоб злити теки, які не є частиною шару, перелічіть їх у [`additionalTranslationDirs`](/uk/api/module-options#additionaltranslationdirs).

## Кілька доменів {#multiple-domains}

Одна збірка обслуговує всі домени. Вкажіть для кожної локалі її домен; `baseDefault` робить її локаллю за замовчуванням для цього хоста:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'de', iso: 'de-DE', baseUrl: 'https://example.de', baseDefault: true },
      { code: 'nl', iso: 'nl-NL', baseUrl: 'https://example.de' },
      { code: 'fr', iso: 'fr-FR' },
    ],
  },
})
```

Спрямуйте обидва домени на той самий сервер. Решту визначає хост запиту:

- **За замовчуванням:** локаль `baseDefault` хоста. Якщо її немає — локаль за замовчуванням зі збірки, якщо хост її обслуговує, інакше перша локаль хоста.
- **Обслуговувані локалі:** локалі цього хоста плюс кожна локаль без `baseUrl`. На `example.de` це `de`, `nl` і `fr`.
- **Локалі інших доменів** є цілями посилань. `$localePath`, `$localeRoute`, `$switchLocalePath`, `<i18n-switcher>` і `hreflang` дають абсолютні URL на їхньому `baseUrl`, а `$switchLocale` переходить туди. На цьому хості їхні URL повертають 404, і cookie чи `Accept-Language` не можуть їх обрати.
- **Посилання на інший домен** проходить через `$localePath` або `<i18n-link>`: `<NuxtLink :to="$localePath('/contact', 'de')">`, `<i18n-link :to="$localeRoute('/contact', 'de')">`. Роутер не приймає абсолютний об'єкт, тому `<NuxtLink :to="$localeRoute(...)">` і `router.push($localeRoute(...))` лишаються на цьому origin. На `localhost` або хості попереднього перегляду кожна локаль із `baseUrl` є таким посиланням, зокрема й поточна. У коді використовуйте `navigateTo($localePath('/contact', 'de'), { external: true })` або `$switchRoute`.
- **Будь-який інший хост** отримує конфігурацію збірки, де кожна локаль із `baseUrl` є ціллю посилання. Нічого із запиту не відтворюється: canonical і `hreflang` використовують `metaBaseUrl`, інакше `baseUrl` локалі за замовчуванням зі збірки (локалі за замовчуванням без `baseUrl` потрібен `metaBaseUrl` або `site.url`, див. [SEO](/uk/guide/seo#set-the-public-origin)).
- **Файли пейлоадів** у `public/` статичні: будь-який хост повертає файл будь-якої локалі. [Generate](/uk/guide/deployment#static-site-(nuxi-generate)) для окремого домену публікує лише файли цього домену.

`example.de` за кожної стратегії з `de: '/kontakt'` як користувацьким шляхом для `contact`:

| Стратегія | `/` | Сторінка локалі за замовчуванням | Інші URL |
| --- | --- | --- | --- |
| `prefix_except_default` | `de` | `/kontakt` | `/de/kontakt` і `/en/contact` повертають 404, `/contact` перенаправляє на `/kontakt` |
| `prefix_and_default` | `de` | `/kontakt` і `/de/kontakt`, посилання використовують `/kontakt` | `/en/contact` і `/contact` повертають 404 |
| `prefix` | перенаправляє на `/de` | `/de/kontakt` | `/kontakt` перенаправляє на `/de/kontakt`, `/en/contact` повертає 404 |
| `no_prefix` | `de` | `/kontakt` | користувацький шлях локалі з іншого домену повертає 404 |

За `prefix` посилання з іншого домену зберігає префікс, оскільки URL без префікса лише перенаправив би. За `no_prefix` посилання на інший домен веде на локаль за замовчуванням того хоста: URL не може вказати другу.

Що варто знати:

- **За проксі** хост береться із `Host`. Якщо проксі натомість передає публічний хост у `X-Forwarded-Host`, задайте [`trustForwardedHost`](/uk/api/module-options#trustforwardedhost), і лише тоді, коли проксі перезаписує цей заголовок. Проксі, який не надсилає жодного з них, не може обслуговувати доменну збірку. Див. [За проксі або CDN](/uk/guide/deployment#behind-a-proxy-or-cdn).
- **`app.baseURL`** також має входити в `baseUrl`: `baseUrl: 'https://example.de/shop'` з `app.baseURL: '/shop'`.
- **Хости зіставляються точно.** `www.example.de` — це інший хост: перенаправляйте його на edge або задайте цей `baseUrl` для локалі. Лише один хост на локаль.
- **Кеші мають враховувати хост у ключі.** CDN зазвичай так і робить. Кеш маршрутів Nitro використовує як ключ шлях, тому в доменній збірці модуль додає `host` до `cache.varies` кожного правила `swr` і `cache`, а з `trustForwardedHost` — ще й `x-forwarded-host`. Правило з `cache: false` лишається як є. `isr` — це кеш платформи: перевірте, що він враховує хост у ключі.
- **Користувацькі шляхи двох локалей за замовчуванням хостів не повинні збігатися.** Записи без префікса використовують один роутер, тому `/x` не може бути однією сторінкою на `example.de` та іншою на `example.com`.
- **Пререндерені сторінки:** правило маршруту `prerender: true` в `nuxt build` рендерить один раз, без хоста, і файл відповідає для всіх доменів. Залишайте сторінки, що відрізняються між доменами, серверу або [генеруйте для кожного домену окремо](/uk/guide/deployment#static-site-(nuxi-generate)).
- **`noPrefixRedirect`** орієнтується на локаль хоста та відвідувача на кожному хості.
- **`hashMode`:** хост обирає рендер, як описано вище, посилання на інший домен передають маршрут у хеші (`https://example.com/#/contact`).
- **`ssr: false`:** браузер зчитує домен із `location.host`, тож хост без сервера все одно розв'язується.
- **[Перевизначення під час виконання](/uk/guide/runtime-overrides)** застосовуються першими. `disabledLocales` під час виконання діє на кожному хості з одним винятком: за `prefix_except_default` і `prefix_and_default` локаль за замовчуванням хоста лишається ввімкненою на своєму хості, оскільки її сторінки — це записи без префікса. За `prefix` і `no_prefix` хост переходить до наступної локалі, яку він обслуговує. `defaultLocale` під час виконання застосовується лише до невідомих хостів.

Для [статичного сайту](/uk/guide/deployment#static-site-(nuxi-generate)) генеруйте окремо для кожного домену.

### Один застосунок на домен {#one-app-per-domain}

Спільний шар з одним невеликим застосунком на кожен домен теж працює, коли доменам потрібні різні сторінки або модулі. Кожен застосунок задає власну `defaultLocale` поверх того самого списку `locales`. Локаль на іншому домені в цьому застосунку повертає 404, як описано вище.

### Вибір локалі в коді {#choosing-the-locale-in-code}

Для одного екземпляра, що відповідає всім доменам із власним origin запиту в SEO-тегах, див. [SEO](/uk/guide/seo#set-the-public-origin); щоб обирати локаль за хостом у коді, див. [Користувацьке визначення локалі](/uk/guide/custom-auto-detect).
