З `meta: true` (за замовчуванням) кожна локалізована сторінка отримує `<html lang dir>`, canonical-посилання, альтернативи `hreflang`, `x-default` і теги локалі Open Graph. Ця сторінка знадобиться вам, коли потрібно задати публічний origin, налаштувати, які локалі з'являються в тегах, або перевизначити їх для однієї сторінки. Більшості сайтів достатньо `site.url` або `metaBaseUrl` і правильних кодів `iso`.

## Мінімальне налаштування {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

Тоді `/de/about` рендерить:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Напрямок тексту {#text-direction}

`<html dir>` береться з `dir` локалі. Якщо його немає, мова, що пишеться справа наліво, отримує `rtl`, визначений за `iso` (або `code`): арабська, іврит, перська, урду та кілька інших, а також будь-який тег з RTL-письмом, наприклад `az-Arab`. Усі інші локалі не отримують атрибута `dir`, що браузери сприймають як `ltr`.

<Warning>

**`dir: 'auto'` збільшує час парсингу на великих сторінках** — `auto` на `<html>` змушує браузер визначати напрямок за вмістом під час парсингу. У Chromium ці витрати зростають швидше, ніж сторінка: близько 100 ms при 5 000 елементів і 1 s при 20 000. Використовуйте його лише для невеликої сторінки, мову якої ви не можете знати заздалегідь.

</Warning>

## Які теги ви отримуєте {#which-tags-you-get}

- **hreflang**: один тег на кожну локаль, що обслуговує сторінку, зі значенням `iso` (або `code`, коли `iso` відсутній), її URL з тим самим query, що й canonical. Сторінка, обмежена через [Конфігурацію сторінки](/uk/guide/per-component-translations) або `routeLocales`, перелічує лише свої локалі. [`hreflangBaseLanguage: true`](/uk/api/module-options#hreflangbaselanguage) також додає базову мову (`es-ES` → `es`) для першої регіональної локалі.
- **x-default**: URL локалі за замовчуванням, лише коли локаль за замовчуванням обслуговує сторінку.
- **og:locale**: виводиться з `iso` (`en-US` → `en_US`). Задайте `og` для локалі, коли зіставлення не пряме, наприклад `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; без жодного з них `og:locale` не записується, а режим розробки виводить попередження.
- **canonical / og:url**: поточний URL без параметрів query, окрім тих, що в [`canonicalQueryWhitelist`](/uk/api/module-options#canonicalquerywhitelist) (за замовчуванням `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

За стратегією:

| Стратегія | hreflang і x-default | canonical, og:url, og:locale, атрибути html |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | так | так |
| `no_prefix` | ні (один URL обслуговує всі локалі) | так |

## Задання публічного origin {#set-the-public-origin}

Абсолютні URL використовують перше з:

1. [`metaBaseUrl`](/uk/api/module-options#metabaseurl);
2. `site.url` з `nuxt-site-config` (встановлюється `@nuxtjs/seo`);
3. origin запиту з доданим `app.baseURL`.

Зафіксуйте один із перших двох.

<Warning>

Резервний варіант з origin запиту читає `X-Forwarded-Host` і `X-Forwarded-Proto`, оскільки [`metaTrustForwardedHost`](/uk/api/module-options#metatrustforwardedhost) і `metaTrustForwardedProto` за замовчуванням дорівнюють `true`. Це безпечно лише за проксі, який перезаписує ці заголовки; інакше клієнт може вибрати хост у ваших canonical-посиланнях, а кеш може передати цю сторінку далі.

Якщо застосунок доступний напряму, зафіксуйте `metaBaseUrl`: на відміну від встановлення обох опцій у `false`, це також ігнорує підроблений `Host`. Див. [За проксі або CDN](/uk/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

Резервний варіант корисний для одного розгортання, яке обслуговує кілька доменів: `https://site-a.com/en/about` і `https://site-b.com/en/about` отримують кожен свій origin.

Коли в локалей задано `baseUrl`, відомий хост використовує власний `baseUrl` з пріоритетом над `metaBaseUrl` і `site.url`, тож canonical і `og:url` залишаються на цьому домені, а `hreflang` спрямовує кожну локаль на її домен. Будь-який інший хост використовує `metaBaseUrl`, інакше `baseUrl` локалі за замовчуванням, інакше `site.url`, тож підроблений `Host` не може потрапити у ваші теги. Якщо нічого з цього не задано, залишається резервний варіант з origin запиту, а збірка виводить попередження. Див. [Шари і домени](/uk/guide/layers#multiple-domains).

## Виключення локалей або сторінок {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Якщо локаль за замовчуванням має `seo: false`, `x-default` не записується. Щоб вимкнути теги для однієї сторінки, використовуйте `disableMeta` у [Конфігурації сторінки](/uk/guide/per-component-translations#turn-off-seo-tags) або [`routeDisableMeta`](/uk/api/module-options#routedisablemeta) у конфігурації.

## Перевизначення тегів на одній сторінці {#override-tags-on-one-page}

Для контенту з CMS, де існують лише деякі переклади або URL надходять з API, замініть згенеровані теги за допомогою [`useI18nHead`](/uk/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` також може задавати або видаляти `canonical`, `xDefault`, `ogLocale` і `ogUrl`; `disable` прибирає цілі групи (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Передавайте getter-функцію, щоб значення перераховувалися після перемикання локалі. Для slug, що відрізняються для кожної локалі, спершу задайте `$setI18nRouteParams` ([Локалізовані шляхи](/uk/guide/custom-locale-routes#per-locale-slugs)), і згенеровані альтернативи вже використовуватимуть їх.

## Кінцевий слеш {#trailing-slash}

`$localePath`, `$switchLocalePath`, об'єкт маршруту `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, перенаправлення локалей і SEO-URL дотримуються одного правила щодо слеша: за замовчуванням `experimental.defaults.nuxtLink.trailingSlash` або [`trailingSlash`](/uk/api/module-options) у конфігурації i18n, коли шляхи i18n мають відрізнятися.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) працює з цим модулем через `nuxt-site-config` 4+. Вкажіть `nuxt-i18n-micro` першим, щоб конфігурація сайту могла прочитати локалі, і задайте `site.url` один раз — він також використовується для наведених вище тегів.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Перекладені назва й опис сайту беруться з ключів `nuxtSiteConfig.name` / `nuxtSiteConfig.description` у ваших файлах локалей. Помилка `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` означає, що `@nuxtjs/seo` старіший за версію 3; оновіть його ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
