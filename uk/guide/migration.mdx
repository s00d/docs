---

Ця сторінка показує, як перенести застосунок із `@nuxtjs/i18n` на nuxt-i18n-micro: опції, хелпери та структуру файлів. Використовуйте її, коли замінюєте модуль в наявному застосунку. Ваші URL зберігаються (назви стратегій однакові), а переклади переносяться в JSON-файли для кожної сторінки.

<Tip>

**Оновлюєте сам nuxt-i18n-micro?** — Див. [Оновлення](/uk/guide/upgrade).

</Tip>

## Заміна модуля {#swap-the-module}

```bash
npm uninstall @nuxtjs/i18n
npm install nuxt-i18n-micro
```

```ts
// nuxt.config.ts — before
export default defineNuxtConfig({
  modules: ['@nuxtjs/i18n'],
  i18n: {
    locales: [
      { code: 'en', language: 'en-US', file: 'en.json' },
      { code: 'de', language: 'de-DE', file: 'de.json' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    langDir: 'locales',
    detectBrowserLanguage: { useCookie: true, cookieKey: 'i18n_redirected', redirectOn: 'root' },
  },
})
```

```ts
// nuxt.config.ts — after
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    translationDir: 'locales',
    localeCookie: 'i18n_redirected',
    autoDetectPath: '/',
  },
})
```

## Опції {#options}

| `@nuxtjs/i18n` | nuxt-i18n-micro |
| --- | --- |
| `locales[].code` | `locales[].code` |
| `locales[].language` (`iso` до v9) | `locales[].iso` |
| `locales[].name` | `locales[].displayName` |
| `locales[].dir` | `locales[].dir` |
| `locales[].domain` | `locales[].baseUrl` (origin зі схемою) |
| `locales[].domainDefault` | `locales[].baseDefault` |
| `differentDomains`, `multiDomainLocales` | не потрібні: самого `baseUrl` достатньо для маршрутизації за хостом, див. [Шари та домени](/uk/guide/layers#multiple-domains) |
| `locales[].file` / `files`, `langDir`, `lazy` | `translationDir`; файли знаходяться за назвою й завжди завантажуються для кожної сторінки |
| `defaultLocale`, `strategy` | ті самі назви, ті самі чотири значення |
| `baseUrl` | `metaBaseUrl` |
| `customRoutes: 'config'` + `pages` | `globalLocaleRoutes` |
| `detectBrowserLanguage: false` | `redirects: false` (без перенаправлень) або `autoDetectLanguage: false` (ігнорувати заголовок) |
| `detectBrowserLanguage.useCookie` / `cookieKey` | `localeCookie: '<name>'` (`null` вимикає cookie) |
| `detectBrowserLanguage.redirectOn: 'root'` | `autoDetectPath: '/'` (за замовчуванням) |
| `detectBrowserLanguage.redirectOn: 'no prefix'` | `autoDetectPath: 'no_prefix'` |
| `detectBrowserLanguage.redirectOn: 'all'` | `autoDetectPath: '*'` |
| Файл конфігурації `vueI18n` (`fallbackLocale`, `numberFormats`, `datetimeFormats`) | `fallbackLocale`, `numberFormats`, `datetimeFormats` в `i18n` |

`alwaysRedirect` немає: якщо cookie встановлено, `/` слідує за ним під час кожного відвідування. Повний список — у [Опціях модуля](/uk/api/module-options); правила визначення — на сторінці [Визначення локалі](/uk/guide/locale-detection).

## Хелпери та композабли {#helpers-and-composables}

| `@nuxtjs/i18n` / vue-i18n | nuxt-i18n-micro (шаблон / `useI18n()`) |
| --- | --- |
| `const { t } = useI18n()` | `const { t } = useI18n()`, `$t` у шаблонах |
| `t('key', count)`, `tc` | `$tc('key', count)` |
| `te('key')` | `$has('key')` |
| `n(value, 'currency')`, `d(date, 'short')` | `$tn(value, 'currency')`, `$td(date, 'short')` |
| — | `$tdr(date)`: відносний час («через 3 дні») |
| `locale.value` | `$getLocale()` |
| `locales.value` | `$getLocales()` |
| `setLocale('de')` | `$switchLocale('de')` |
| `useLocalePath()('about')` | `$localePath({ name: 'about' })` |
| `useLocaleRoute()` | `$localeRoute()` |
| `useSwitchLocalePath()('de')` | `$switchLocalePath('de')` |
| `useSetI18nParams()` | `$setI18nRouteParams()` |
| `useLocaleHead()` | автоматично з `meta: true`; [`useLocaleHead`](/uk/composables/useLocaleHead) для власних head |
| `defineI18nRoute({ paths: { de: '/ueber-uns' }, locales: [...] })` | `$defineI18nRoute({ localeRoutes: { de: '/ueber-uns' }, locales: [...] })` |
| `<NuxtLinkLocale to="about">` | `<i18n-link :to="{ name: 'about' }">` |
| `<i18n-t>` | `<i18n-t>` (слоти заповнюють заповнювачі `{name}`) |
| `$i18n` у серверних маршрутах | `useTranslationServerMiddleware(event)`, див. [Серверні маршрути та API](/uk/guide/server-side-translations) |

`useI18n()` імпортується автоматично. `$defineI18nRoute` має зберігати свій `$`: збірка зчитує саме цей виклик. Усі хелпери: [Методи](/uk/api/methods).

## Файли перекладів {#translation-files}

Перенесіть ключі одного великого файлу для кожної локалі в кореневий файл плюс по одному файлу на сторінку:

```text
locales/
├── en.json              # keys used on many pages (nav, footer)
├── de.json
└── pages/
    ├── index/en.json    # keys of pages/index.vue
    └── about/en.json    # keys of pages/about.vue
```

Зберігати все в кореневих файлах теж можна, і це найшвидший перший крок. Задайте `disablePageLocales: true`, доки не розділите їх. Див. [Файли перекладів](/uk/guide/translations).

### Синтаксис повідомлень {#message-syntax}

| vue-i18n | nuxt-i18n-micro |
| --- | --- |
| Іменована інтерполяція `{name}` | так само |
| `car \| cars` (2 форми: 1 → перша) | форми обираються за кількістю, починаючи з 0: пишіть `no cars \| one car \| {count} cars` |
| Пов'язані повідомлення `@:other.key` | не підтримуються: повторіть текст або компонуйте в коді |
| Модифікатори `@.upper:` | не підтримуються: форматуйте в коді або використовуйте `<i18n-t>` |
| Екранування літералів `{'@'}` | не потрібне: замінюються лише токени `{word}` |
| Файли повідомлень JS/TS | лише JSON |

Правило множини можна замінити опцією [`plural`](/uk/api/module-options#plural).

## Перевірка після переходу {#check-after-the-switch}

- Кожен ваш URL, як і раніше, розв'язується; назви стратегій збігаються, а користувацькі шляхи переносяться в `globalLocaleRoutes` або `$defineI18nRoute`.
- `hreflang`, canonical і `og:locale` доступні з коробки з `meta: true`; приберіть написані вручну.
- Помилка розбору JSON виводить шлях до файлу; відсутній ключ у режимі розробки виводить попередження в консоль браузера.
