`$defineI18nRoute` задає опції i18n для однієї сторінки зсередини самої сторінки. Використовуйте його, коли сторінка існує лише в деяких локалях, потребує власного локалізованого шляху, містить кілька власних перекладів або не повинна отримувати теги hreflang/canonical. Модуль зчитує виклик під час збирання і вбудовує його в згенеровані маршрути.

## Обмеження сторінки деякими локалями {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

За стратегії `prefix_except_default` за замовчуванням генеруються лише `/product` і `/de/product`; в інших локалях сторінка не має маршруту. Те саме можна задати з `nuxt.config.ts` через [`routeLocales`](/uk/api/module-options#routelocales).

`$defineI18nRoute` — це ін’єкція застосунку Nuxt, а не макрос компілятора: завжди беріть її з `useNuxtApp()` і викликайте з `$`. Крок збирання розпізнає лише `$defineI18nRoute(`.

## Додавання вбудованих перекладів {#add-inline-translations}

Передайте об’єкт замість масиву. Його ключі — дозволені локалі, а значення зливаються зі словником сторінки для активної локалі.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Вбудовані переклади постачаються всередині компонента сторінки для кожної локалі. Для всього, що більше кількох ключів, надавайте перевагу [файлам перекладів сторінок](/uk/guide/translations); залишайте вбудовані ключі для самодостатніх сторінок і компонентів.

## Задання локалізованих шляхів {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

З `prefix_except_default` і `defaultLocale: 'en'` це дає `/welcome` і `/de/willkommen`. `path` усередині вбудованого об’єкта локалі робить те саме: `locales: { de: { path: '/willkommen' } }`. Динамічні параметри, вкладені маршрути та альтернативу на рівні конфігурації описано в [Локалізованих шляхах](/uk/guide/custom-locale-routes).

## Вимкнення SEO-тегів {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

Альтернатива на рівні конфігурації — [`routeDisableMeta`](/uk/api/module-options#routedisablemeta). Що це за теги, описано на сторінці [SEO](/uk/guide/seo).

## Що може прочитати збирання {#what-the-build-can-read}

Крок збирання знаходить виклик у кожному файлі сторінки й обчислює його аргумент без запуску вашого застосунку. Це працює, коли конфігурація є:

- літеральним об’єктом (рядки, масиви, вкладені об’єкти, шаблонні літерали, тернарні оператори з `process.env.NODE_ENV`);
- побудованою з констант, оголошених у тому самому `<script setup>` (`const locales = ['en', 'de']`, включно зі spread);
- масивом об’єктів із полем `code` (`[{ code: 'en' }, { code: 'de' }]`).

Воно не може прочитати значення, імпортовані з іншого модуля, чи будь-що, що потребує вашого застосунку під час виконання (composables, `await`, отримані дані). У такому разі збирання логує `Ignored the $defineI18nRoute() config in <file>`, і сторінка зберігає локалі та маршрути за замовчуванням.

Під час виконання виклик лише зливає вбудовані переклади для поточної локалі й повторно зливає їх, коли локаль змінюється. `locales`, `localeRoutes` і `disableMeta` діють лише через збирання, тож їхня зміна потребує перезбирання (dev-сервер перезбирає під час збереження).
