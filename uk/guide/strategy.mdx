Опція `strategy` визначає, чи з’являється локаль в URL і для яких локалей. Оберіть її один раз, до публікації URL: зміна пізніше змінює кожне посилання. Потім модуль генерує локалізовані маршрути під час збирання, а `$localePath`, `<i18n-link>` і перемикач зчитують їх.

## Чотири стратегії {#the-four-strategies}

![Сторінка /about в en (за замовчуванням) і de за кожної стратегії; ті самі URL перелічено в тексті нижче](/images/diagrams/strategies.svg)

**Тип** `Strategies` · **За замовчуванням** `'prefix_except_default'`

Стратегія маршрутизації URL для префіксів локалей.

- `'no_prefix'` — без локалі в URL; локаль зберігається в cookie.
- `'prefix_except_default'` — префікс для всіх локалей, крім локалі за замовчуванням.
- `'prefix'` — завжди префікс, включно з локаллю за замовчуванням.
- `'prefix_and_default'` — як `prefix`, але локаль за замовчуванням також доступна без префікса.

URL для сторінки `about` з `defaultLocale: 'en'` і локалями `en`, `de`:

| Стратегія | Англійська | Німецька | Не обслуговується |
| --- | --- | --- | --- |
| `prefix_except_default` (за замовчуванням) | `/about` | `/de/about` | `/en` і `/en/about` дають 404 |
| `prefix` | `/en/about` | `/de/about` | `/about` перенаправляє на URL із префіксом |
| `prefix_and_default` | `/about` і `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | локалі немає в URL |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

Стратегія фіксується під час збирання: її runtime-перевизначення ігнорується з попередженням ([Runtime-перевизначення](/uk/guide/runtime-overrides)).

## Яку обрати {#which-one-to-choose}

- **`prefix_except_default`**: більшість сайтів. Наявні URL без префікса продовжують працювати для мови за замовчуванням.
- **`prefix`**: усі мови рівноправні; `/` завжди веде на головну з префіксом.
- **`prefix_and_default`**: вам потрібно, щоб працювали і `/en/...`, і URL без префікса, наприклад під час переходу від одного до іншого. URL без префікса ніколи не перенаправляються.
- **`no_prefix`**: застосунки за логіном або один URL на сторінку для всіх мов. Локаль береться з cookie або `?locale=`. Пошукові системи бачать одну мову на URL, тож альтернативи `hreflang` не генеруються.

Як обирається локаль для URL і коли відвідувача перенаправляють, описано у [Визначенні локалі](/uk/guide/locale-detection).

## Згенеровані маршрути {#generated-routes}

Під час збирання кожна сторінка отримує записи маршрутів, потрібні її стратегії. Кожен запис містить `meta.i18n = { name, locales }`: сторінку, яку він показує, і локалі, які він обслуговує. Посилання, перемикання та перенаправлення обчислюються з цих записів, тож URL, який видає модуль, завжди обслуговується роутером.

Локалі, що мають спільний шлях сторінки, мають один спільний запис, `/:locale(de|fr)/about`. Локаль із власним шляхом отримує власний запис із назвою `localized-<page>-<locale>`:

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

Кастомні шляхи, списки локалей для окремих сторінок і виключення сторінки з локалізації описано в [Локалізованих шляхах](/uk/guide/custom-locale-routes) і [Конфігурації сторінки](/uk/guide/per-component-translations). Префікс `localized-` задається через [`localizedRouteNamePrefix`](/uk/api/module-options#localizedroutenameprefix).

<Warning>

**Назви маршрутів генеруються** — Не прописуйте жорстко назви `localized-…` у `router.push({ name })`. Передавайте власну назву сторінки в `$localeRoute` чи `<i18n-link>`; вони оберуть правильний запис.

</Warning>

## Посилання на сторінку в локалі {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- Працюють і іменовані маршрути, і шляхи. Шлях зіставляється зі згенерованими маршрутами, тож приймається його форма для будь-якої локалі.
- Локаль, яка не обслуговує сторінку (див. `locales` у [Конфігурації сторінки](/uk/guide/per-component-translations)), веде на головну цієї локалі замість відсутньої сторінки.
- Параметри для окремих локалей (перекладений slug) задаються через `$setI18nRouteParams`, див. [Локалізовані шляхи](/uk/guide/custom-locale-routes).

Сигнатури наведено в [Методах](/uk/api/methods).

## Подробиці `no_prefix` {#no_prefix-details}

- [`localeCookie`](/uk/api/module-options#localecookie) за `no_prefix` за замовчуванням має значення `'user-locale'`, тож вибір зберігається після перезавантаження.
- `$switchLocale('de')` завантажує німецький словник і замінює поточний запис історії; URL не змінюється.
- Кастомні шляхи для локалей і далі працюють: з `globalLocaleRoutes: { about: { de: '/ueber-uns' } }` німецькомовні читачі отримують `/ueber-uns`. Цей URL завжди рендериться німецькою, незалежно від вподобань відвідувача, а сторінка, обмежена деякими локалями, рендериться однією з них. Шлях, спільний для кількох локалей (`en` і `de` обидві на `/page/:id`), рендериться за вподобанням, якщо воно є однією з них. Саме вподобання зберігається: наступна сторінка повертається до нього.
- [`noPrefixRedirect: true`](/uk/api/module-options#noprefixredirect) перенаправляє початковий шлях сторінки з кастомним шляхом у локалі за замовчуванням: на кастомний шлях локалі відвідувача, інакше — локалі за замовчуванням (`/about` → `/about-us`, коли `en` має `/about-us`, → `/ueber-uns` з cookie `de`). Локаль без власного кастомного шляху залишається на початковому шляху й рендериться там. Сторінки з параметрами не перенаправляються.

## Застосунки без `pages/` {#apps-without-pages}

З `pages: false` немає маршрутів сторінок для локалізації. Використовуйте лише кореневі файли перекладів (`disablePageLocales: true`); визначення локалі, cookie і `$switchLocale` і далі працюють. Варіант `pages-false` фікстури `test/fixtures/basic` у репозиторії — робочий приклад налаштування.
