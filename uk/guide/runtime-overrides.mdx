description: "Змінюйте локаль за замовчуванням, резервну локаль або вимкнені локалі для кожного екземпляра однієї збірки за допомогою змінних оточення або runtimeConfig."
---

Перевизначення під час виконання дають змогу запускати один артефакт збірки з різними налаштуваннями локалей для кожного оточення або тенанта без повторної збірки. Можна змінити локаль за замовчуванням, резервну локаль і те, які локалі вимкнено. Маршрутизація, перенаправлення, рендеринг і серверні хелпери використовують перевизначені значення, як і браузер на сторінці, відрендереній на сервері.

## Задання перевизначень через змінні оточення {#set-overrides-with-environment-variables}

```bash
NUXT_I18N_DEFAULT_LOCALE=de \
NUXT_I18N_FALLBACK_LOCALE=en \
NUXT_I18N_DISABLED_LOCALES=fr,it \
node .output/server/index.mjs
```

| Змінна | Псевдонім |
| --- | --- |
| `NUXT_I18N_DEFAULT_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE` |
| `NUXT_I18N_FALLBACK_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE` |
| `NUXT_I18N_DISABLED_LOCALES` (через кому) | `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES` |

Сервер зчитує їх один раз під час запуску; щоб застосувати зміну, перезапустіть його. На сторінці, відрендереній на сервері, браузер отримує розв'язані значення від сервера. З `ssr: false` серверного рендерингу немає, а браузер не має оточення: там застосовується лише `runtimeConfig.public.i18nRuntime`, і браузер виводить у журнал наведені нижче попередження.

## Задання перевизначень у runtimeConfig {#set-overrides-in-runtimeconfig}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

Значення, задане в `runtimeConfig.public.i18nRuntime`, має пріоритет над змінною `NUXT_I18N_*` для того самого поля.

Не плутайте зі змінною часу збірки `DEFAULT_LOCALE`, яка замінює `defaultLocale` під час збірки й не потребує підтримки під час виконання.

## Що можна і що не можна змінити {#what-can-and-cannot-change}

| Налаштування | Під час виконання |
| --- | --- |
| `defaultLocale` | Так, для `prefix` і `no_prefix`. Для `prefix_except_default` і `prefix_and_default` вона фіксується під час збірки (її сторінки — це маршрути без префікса); перевизначення ігнорується з попередженням. |
| `fallbackLocale` | Так. |
| `disabledLocales` | Додається до локалей, вимкнених під час збірки; ніколи не вмикає локаль повторно. Локаль за замовчуванням зі збірки не можна вимкнути для `prefix_except_default` / `prefix_and_default`. |
| `strategy` | Ні. Стратегія під час виконання ігнорується з попередженням; збирайте окремий артефакт для кожної стратегії. |

Некоректні значення ніколи не ламають застосунок. Кожен випадок виводить одне попередження на серверний процес:

- вимкнення всіх локалей ігнорується;
- `defaultLocale`, яка не ввімкнена, замінюється першою ввімкненою локаллю;
- `fallbackLocale`, яка не ввімкнена, зберігає значення зі збірки, якщо воно ввімкнене, інакше резервної локалі немає.

## Читання ефективної конфігурації {#read-the-effective-config}

```vue
<script setup lang="ts">
const { $getI18nConfig } = useNuxtApp()
const config = $getI18nConfig() // build config with overrides applied
</script>
```

Вважайте її доступною лише для читання: на сервері вона спільна для всіх запитів і заморожена в режимі розробки; копія в браузері не заморожена. Імпорт конфігурації з `#build/i18n.strategy.mjs` дає значення збірки без перевизначень.

## Вимкнені локалі та статичні файли {#disabled-locales-and-static-files}

Локаль, вимкнена під час виконання, відповідає 404 на своїх маршрутах і маршруті пейлоада, але її файли пейлоадів усе ще лежать у `.output/public/_locales/`, і статичний файловий сервер їх віддає. Якщо ці файли не мають бути доступними, вимкніть локаль під час збірки за допомогою `disabled: true`.
