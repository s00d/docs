description: "Задайте сторінці різні URL для кожної локалі за допомогою localeRoutes або globalLocaleRoutes, включно з динамічними параметрами та slug для кожної локалі."
---

За замовчуванням кожна локаль обслуговує сторінку за тим самим шляхом: `/en/about`, `/de/about`. Локалізовані шляхи дозволяють кожній локалі використовувати власні слова, наприклад `/de/ueber-uns`, тоді як файл сторінки залишається тим самим. Ви задаєте їх на сторінці через `$defineI18nRoute` або для багатьох сторінок одразу в `nuxt.config.ts`.

## На сторінці {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

З `prefix_except_default` і `defaultLocale: 'en'` сторінка відповідає за адресами `/about`, `/de/ueber-uns` і `/fr/a-propos`. Локаль без запису зберігає шлях за замовчуванням. Пишіть шляхи без коду локалі: префікс додає [стратегія](/uk/guide/strategy), а шлях, що починається з коду локалі, записує попередження в лог. Що ще приймає цей виклик, описано на сторінці [Конфігурація сторінки](/uk/guide/per-component-translations).

## У nuxt.config {#in-nuxt-config}

[`globalLocaleRoutes`](/uk/api/module-options#globallocaleroutes) робить те саме для будь-якої сторінки, з ключем за її шляхом (або за іменем маршруту, якщо записано без початкового слеша):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

Коли сторінка задає `localeRoutes`, а `globalLocaleRoutes` має той самий ключ, перемагає запис із конфігурації.

## Динамічні параметри {#dynamic-params}

Пишіть параметри в будь-якій формі Nuxt: `[id]`, `[[page]]`, `[...slug]` або `:id()`. Імена параметрів мають збігатися з файлом сторінки.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

Вкладені сторінки приймають абсолютний дочірній шлях (`/ueber-uns/team`) або шлях відносно локалізованого шляху батьківської сторінки (`team`).

## Посилання на локалізовані сторінки {#linking-to-localized-pages}

Посилання розв'язуються в локалізований шлях цільової локалі, незалежно від того, чи передаєте ви ім'я маршруту, чи звичайний шлях:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

Імена маршрутів походять від шляху до файлу (`pages/about/team.vue` — це `about-team`), якщо ви не задали ім'я через `definePageMeta({ name })`.

## Slug для кожної локалі {#per-locale-slugs}

Коли сам slug відрізняється для кожної локалі (`/our-products/red-shoe` проти `/de/unsere-produkte/roter-schuh`), повідомте перемикачу мов, які параметри використовувати, через `$setI18nRouteParams` після завантаження даних:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

Після цього `$switchLocalePath('de')` і `<i18n-switcher>` посилаються на `/de/unsere-produkte/roter-schuh`. Ключі — це коди локалей, значення — параметри за іменем (як у файлі сторінки).

Перемикач у layout рендериться раніше, ніж асинхронний setup сторінки доходить до цього місця, тому після завершення рендерингу модуль переписує посилання `<i18n-switcher>` — як в `app.vue`, так і на сторінці. Тоді серверний HTML, відвідувач без JavaScript і перший клієнтський рендер збігаються. Для цього задавайте параметри під час SSR: з `lazy` або `server: false` посилання змінюються лише після гідратації. SSR-стрімінг Nuxt надсилає HTML ще до того, як параметри стануть відомі, тож за нього посилання в першому HTML зберігають власні параметри URL.

Переписуються лише власні посилання перемикача. Написане вручну посилання з `$switchLocalePath` має рендеритися після встановлення параметрів, тож розміщуйте його на сторінці, яка їх задає, також після `await`. У layout воно рендериться першим: його серверний HTML зберігає параметри URL, а гідратація попереджає про невідповідність. Використовуйте там `<i18n-switcher>` з його слотами та пропсами `custom*Style` для оформлення.

Параметри належать сторінці, яка їх задала:

- Вони скидаються, коли завершується навігація на інший шлях, тож кожна сторінка задає власні. Скасована навігація залишає їх на місці.
- Беріть `$setI18nRouteParams` з `useNuxtApp()` або `useI18n()` у `setup`, навіть якщо викликаєте його пізніше в обробнику `useAsyncData`. Отримана там функція знає свою сторінку: якщо відвідувач уже пішов, пізній виклик нічого не робить.
- З `keepalive` сторінка отримує назад задані нею параметри, коли відвідувач повертається. `useI18nHead` поводиться так само.

## Маршрути, додані в pages:extend {#routes-added-in-pagesextend}

Маршрути, які ви додаєте в хуку `pages:extend`, не мають файлу сторінки, з якого можна прочитати `$defineI18nRoute`, і кілька з них часто використовують один спільний компонент-обгортку. Маршрут, доданий без `name`, отримує ім'я, яке Nuxt дав би його шляху (`/a/:id()` стає `a-id`), тож мовні посилання до нього доходять, якщо тільки інший маршрут уже не має такого імені; тоді задайте явне `name`. Тримайте один список і розділяйте його на сторінки та `globalLocaleRoutes` з ключами за іменем маршруту за допомогою `splitLocaleRoutes` з `@i18n-micro/utils/split-locale-routes` (додайте пакет до залежностей):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

Не розміщуйте локалізовані шляхи в `route.meta`: вони потраплять у клієнтську таблицю маршрутів.
