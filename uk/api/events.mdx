---

Модуль викликає один runtime-хук (хук застосунку) — `i18n:register`. Використовуйте його, коли плагін або модуль додає переклади, яких немає у ваших файлах `locales/`. Ваш колбек отримує функцію `register`, яка зливає переклади зі сторінкою, що відображається.

## `i18n:register` {#i18nregister}

```ts
'i18n:register': (
  register: (translations: unknown, locale?: string) => void,
  locale: string,
) => HookResult
```

| Аргумент | Опис |
| --- | --- |
| `register(translations, locale?)` | Глибоко зливає `translations` із чанком сторінки маршруту, що завантажується, для `locale` (за замовчуванням — `locale` хука). Наявні ключі перезаписуються. |
| `locale` | Локаль маршруту, що завантажується. |

Хук типізовано через `RuntimeNuxtHooks`, тож `nuxtApp.hook('i18n:register', …)` не потребує приведення типів.

## Коли він спрацьовує {#when-it-fires}

Його викликає плагін-завантажувач (`i18n-plugin-loader`):

1. один раз під час запуску, коли всі плагіни відпрацювали (`app:created`) і до рендерингу застосунку;
2. у своєму `router.beforeEach`, після завантаження перекладів цільової сторінки, коли змінюється шлях — за `no_prefix` під час кожної навігації.

Кожен колбек і кожен виклик `register` очікуються (await) до рендерингу застосунку або продовження навігації, тож сторінка рендериться вже зі злитими ключами. З [`hooks: false`](/uk/api/module-options#hooks) хук ніколи не викликається.

## Приклад {#example}

```ts
// plugins/i18n-extra.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('i18n:register', async (register, locale) => {
    const extra = await $fetch<Record<string, unknown>>(`/api/cms-strings/${locale}`)
    register(extra, locale)
  })
})
```

Це runtime-хук: реєструйте його через `nuxtApp.hook` у плагіні, а не через `nuxt.hook` у `nuxt.config` чи в `setup` модуля. Модуль додає такий плагін за допомогою `addPlugin`.
