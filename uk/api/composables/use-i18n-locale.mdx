# useI18nLocale

## Сигнатура

{/* generated:symbol:useI18nLocale — do not edit; run `pnpm run docs:generate` */}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getLocaleWithServerFallback: (serverLocale?: string | null) => string | null; getPreferredLocale: () => string | null; hashCookie: any; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: any; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Централізована точка входу для керування локалями i18n.
Обʼєднує useState('i18n-locale'), cookie локалі та утиліти синхронізації.

## Використання

```vue
<script setup>
const {
  locale,
  localeCookie,
  hashCookie,
  validLocales,
  getPreferredLocale,
  getLocale,
  getLocaleWithServerFallback,
  getEffectiveLocale,
  resolveInitialLocale,
  setLocale,
  syncLocale,
  isValidLocale,
} = useI18nLocale()

// Set locale (updates state and cookies)
setLocale('de')

// Get current locale (state → cookie)

// Get valid preferred locale
const preferred = getPreferredLocale()
</script>
```

## API

| Властивість/Метод                               | Тип                                 | Опис                                                                                 |
| ----------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------ |
| `locale`                                        | `Ref<string \| null>`               | Реактивний стан локалі (`useState('i18n-locale')`)                                   |
| `localeCookie`                                  | `Ref`                               | Cookie локалі (коли увімкнено опцію `localeCookie`)                                  |
| `hashCookie`                                    | `Ref`                               | Cookie, який використовується, коли активний `hashMode`                              |
| `validLocales`                                  | `string[]`                          | Увімкнені коди локалей з конфігурації модуля (без `disabled`)                        |
| `getLocale()`                                   | `() => string \| null`              | Поточна локаль: стан → cookie (або hash cookie у hash-режимі)                        |
| `getPreferredLocale()`                          | `() => string \| null`              | Локаль зі стану/cookie **перевірена** проти `validLocales`, або `null`               |
| `getLocaleWithServerFallback(serverLocale?)`    | `(serverLocale?) => string \| null` | Стан → cookie → опційно серверний контекст (використовується під час init `no_prefix`) |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string`             | Локаль для завантаження перекладів: у hash-режимі надає перевагу стану; інакше читає з маршруту |
| `resolveInitialLocale(options)`                 | `(options) => string`               | Розвʼязує локаль: стан → `serverLocale` → маршрут; синхронізує стан за потреби        |
| `setLocale(locale)`                             | `(locale: string \| null) => void`  | Встановити локаль і синхронізувати з cookie                                          |
| `syncLocale(locale)`                            | `(locale: string \| null) => void`  | Синхронізувати лише cookie (без оновлення стану)                                     |
| `isValidLocale(locale)`                         | `(locale) => boolean`               | Перевірити, чи рядок є у `validLocales`                                              |

### Опції `resolveInitialLocale`

```typescript
interface ResolveInitialLocaleOptions {
  route: unknown
  serverLocale?: string | null
  getLocaleFromRoute: (route?: unknown) => string
}
```

Використовується внутрішньо головним плагіном під час запуску. Кастомні плагіни можуть викликати його, реалізуючи альтернативні потоки визначення.

### `getEffectiveLocale`

```typescript
const { getEffectiveLocale } = useI18nLocale()
const { $getLocale } = useNuxtApp()

const locale = getEffectiveLocale(route, (r) => $getLocale(r))
```

Повертає локаль, яка використовується для завантаження перекладів і форматування повідомлень для заданого обʼєкта маршруту.

## Програмне встановлення локалі

Надавайте перевагу `useI18nLocale()` перед прямим використанням `useState('i18n-locale')`:

```ts
// plugins/i18n-loader.server.ts
import { defineNuxtPlugin } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,

  setup() {
    const { setLocale } = useI18nLocale()
    const detectedLocale = 'ja' // Your detection logic here
    setLocale(detectedLocale)
  },
})
```

<Tip>
`setLocale()` оновлює лише вподобання локалі (стан + cookie). Щоб також перезавантажити активний контекст перекладу на клієнті, використовуйте `$switchLocale()` з `useNuxtApp()` або `useI18n()`. Це важливо особливо для `no_prefix`, де URL не змінюється. Див. [FAQ — перемикання локалі без зміни URL](/guides/faq#-switch-locale-without-changing-the-url).
</Tip>
