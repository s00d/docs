# Довідник опцій модуля

Кожна опція, яку приймає `nuxt-i18n-micro`, зчитана на етапі збірки з інтерфейсу `ModuleOptions` у
[`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).
Нічого тут не написано вручну, тож воно не може відставати від коду — типи, значення за замовчуванням та
описи беруться безпосередньо з декларації.

Про те, що ці опції *означають* разом — які комбінації мають сенс, що змінюється при
перемиканні стратегії, робочі приклади — читайте [Конфігурація](/guides/configuration). Ця
сторінка є вичерпним переліком; та інша — поясненням.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Вкладені опції зʼявляються під шляхом із крапкою, тож `translationPayloads.mode` — це
ключ `mode` всередині обʼєкта `translationPayloads`.

## Локалі та маршрутизація

Які мови існують і як вони зʼявляються в URL.

| Опція | Тип | Значення за замовчуванням | Опис |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Список підтримуваних локалей. Кожен елемент визначає код локалі плюс опціональні метадані (ISO, напрямок, відображуване імʼя тощо). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Стратегія URL-маршрутизації для префіксів локалей. - `'no_prefix'` — без локалі в URL; локаль зберігається в cookie. - `'prefix_except_default'` — префіксувати всі локалі, крім за замовчуванням. - `'prefix'` — завжди префіксувати, включно з локаллю за замовчуванням. - `'prefix_and_default'` — як `prefix`, але локаль за замовчуванням також доступна без префікса. |
| `defaultLocale` | `string` | `'en'` | Локаль, яка використовується, коли неможливо визначити локаль з URL або уподобань користувача. Також використовується як резервна локаль для відсутніх перекладів, коли `fallbackLocale` не встановлено. |
| `localeCookie` | `string \| null` | `null` | Імʼя cookie для збереження уподобань локалі користувача між сесіями. Встановіть `null`, щоб вимкнути збереження на основі cookie. Автоматично встановлюється у `'user-locale'` для стратегії `no_prefix`, якщо не надано. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Глобальна конфігурація локалей на рівні маршрутів. Дозволяє обмежувати або кастомізувати маршрути локалей для конкретних сторінок без модифікації їхніх компонентів. - `false` — виключити маршрут з локалізації. - `Record<LocaleCode, string>` — кастомні шляхи для кожної локалі. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Кастомний регулярний вираз (або його рядкове джерело) для співставлення кодів локалей у сегментах URL. Усі коди локалей, визначені в `locales`, мають відповідати цьому шаблону, інакше виводиться попередження. |
| `noPrefixRedirect` | `boolean` | `false` | Для стратегії `no_prefix`: увімкнути перенаправлення з URL з префіксом локалі (наприклад, `/en/about`) на версію без префікса (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | URL-шаблони (рядки або RegExp), які повністю виключаються з i18n-обробки. Маршрути, що відповідають шаблонам, не отримують префіксів локалей, перенаправлень чи завантаження перекладів. Внутрішні шляхи Nuxt (`/__nuxt_error` тощо) завжди виключаються автоматично. |
| `routeLocales` | `Record<string, string[]>` | — | Обмеження локалей на рівні маршрутів, вилучені з викликів `defineI18nRoute()`. Мапить шлях маршруту (наприклад, `'/about'`) на масив дозволених кодів локалей. Маршрути, не зазначені у списку, не мають обмежень (усі локалі дозволені). |

## Переклади

Де зберігаються файли перекладів та як розвʼязуються ключі.

| Опція | Тип | Значення за замовчуванням | Опис |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Шлях до теки, що містить JSON-файли перекладів, відносно кореня проєкту. |
| `disableWatcher` | `boolean` | `false` | Вимкнути file watcher, який автоматично створює відсутні файли перекладів у режимі розробки. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Мапить імена маршрутів на інші імена маршрутів для спільного використання тих самих файлів перекладів. Наприклад, `\{ 'about-us': 'about' \}` означає, що сторінка `about-us` використовуватиме переклади зі сторінки `about` замість власних. |
| `plural` | `PluralFunc` | `built-in pluralization (form index by count)` | Кастомна функція множинних форм. Отримує `(key, count, params, locale, getter)` і має повернути обрану множинну форму у вигляді рядка, або `null`/`undefined`, щоб повернутися до вбудованої логіки `defaultPlural` (тож ви можете перевизначити лише деякі локалі). Для модуля Nuxt функція серіалізується через `.toString()` у `.nuxt/i18n.plural.mjs` — вона має бути самодостатньою (без імпортів / зовнішньої області видимості). Рядок зі шляхом до файлу **не** підтримується. |
| `disablePageLocales` | `boolean` | `false` | Вимкнути посторінкові файли перекладів. Коли `true`, завантажуються лише глобальні переклади (`\{locale\}.json`); файли для окремих сторінок (`pages/\{page\}/\{locale\}.json`) не генеруються і не завантажуються. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Глобальний код резервної локалі. Коли ключ перекладу відсутній в активній локалі, модуль шукає його у цій локалі, перш ніж повернути сам ключ. |

## Payloads та кешування

Як переклади потрапляють до браузера. [Продуктивність](/guides/performance) пояснює, що вони змінюють під час виконання.

| Опція | Тип | Значення за замовчуванням | Опис |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Попередньо завантажувати переклади сторінки index у Nitro global middleware (лише сервер, приватна конфігурація). |
| `apiBaseUrl` | `string` | `'_locales'` | Базовий сегмент URL для API-маршруту перекладів (використовується у SSR/SSG-fetch даних). Також можна встановити через змінну середовища `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Перевизначає хост, що використовується для клієнтських fetch-запитів перекладів. Корисно, коли клієнт звертається до сервера через інше імʼя хосту, ніж бачить Nuxt. Також можна встановити через змінну середовища `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Перевизначає хост, що використовується для серверних fetch-запитів перекладів. Корисно у контейнерних/мікросервісних налаштуваннях, коли сервер звертається до себе через внутрішнє імʼя хосту. Також можна встановити через змінну середовища `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Керує тим, як генеруються payload-и перекладів (Node: `public/<apiBaseUrl>`; Edge: Nitro `serverAssets`). - **Node**: `serverAssets` означає локальне SSR через `readFile` під `public/` (без Rollup `raw:`). - **Edge**: `serverAssets` реєструє Nitro `serverAssets` (`assets:i18n`); це не змушує до публічної копії. Залиште значення за замовчуванням для звичайного all-in-one налаштування. Для великих Edge-каталогів надайте перевагу `mode: 'source'`. Для деплойментів на CDN вимкніть локальні виходи та встановіть `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Стратегія payload перекладів. - `premerged`: матриця `\{page\}/\{locale\}/data.json` на етапі збірки (за замовчуванням) - `source`: компактні source-файли, обʼєднані під час виконання (перевага на Edge / великих каталогах) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Локальні SSR-payload-и: Node читає `public/<apiBaseUrl>` (примушує до публічної копії); Edge вбудовує через Nitro `serverAssets`. - **Node**: без Nitro `serverAssets` (уникає Rollup `raw:`). SSR читає `public/<apiBaseUrl\|publicDir>` як `\{page\}/\{locale\}/data.json`; коли `true`, публічна копія примусова, навіть якщо `publicAssets` дорівнює false. - **Edge** (`nitro.node === false`): Nitro `serverAssets` (`assets:i18n`) з тим самим лейаутом, що й `mode`. **Не** примушує до публічної копії — встановіть `publicAssets: true` для CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Реєструвати вбудований серверний маршрут за `/\{apiBaseUrl\}/:page/:locale/data.json`. Вимикайте це, коли payload-и перекладів обслуговуються з зовнішнього хосту/CDN. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Копіювати payload-и у публічний вивід Nitro. Premerged → `\{page\}/\{locale\}/data.json` під `apiBaseUrl`; source → компактне дерево. На Node це дерево також є SSR-джерелом, коли `serverAssets` примушує до публічної копії. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Увімкнути пре-рендер Nitro для `/\{apiBaseUrl\}/.../data.json`. Зазвичай надлишкове, коли `publicAssets` у premerged вже записав ці файли. |
| `translationPayloads.publicDir` | `string` | — | Тека публічного виводу відносно кореня публічного простору Nitro. За замовчуванням — `apiBaseUrl` (`_locales`). Тож статичні файли відповідають клієнтським fetch-URL (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Попереджати під час збірки, коли згенерована кількість payload-файлів перевищує цей поріг. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Попереджати під час збірки, коли загальний розмір згенерованих payload-ів перевищує цей поріг у байтах. |

## SEO

Мета-теги, згенеровані для кожної локалізованої сторінки.

| Опція | Тип | Значення за замовчуванням | Опис |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Автоматично генерувати SEO-мета-теги (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | Базовий URL для SEO-мета-тегів (canonical, og:url, hreflang). - Конкретний URL-рядок (наприклад, `'https://example.com'`) — використовується як є (найвищий пріоритет). - `undefined` — повертається до `site.url` з `nuxt-site-config`, коли цей модуль присутній, інакше — origin поточного запиту (`useRequestURL().origin` на сервері, `window.location.origin` на клієнті). |
| `metaTrustForwardedHost` | `boolean` | `true` | Довіряти заголовку `X-Forwarded-Host` при розвʼязанні базового URL для мета-тегів. Увімкніть, коли застосунок працює за reverse proxy (nginx, Cloudflare, AWS ALB тощо), який встановлює цей заголовок на реальне клієнтське імʼя хосту. |
| `metaTrustForwardedProto` | `boolean` | `true` | Довіряти заголовку `X-Forwarded-Proto` при розвʼязанні протоколу для мета-тегів. Увімкніть, коли застосунок працює за TLS-термінуючим проксі, щоб канонічні URL використовували `https://`, навіть якщо сам застосунок слухає HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Список імен query-параметрів, збережених у мета-тегах canonical та `og:url`. Параметри, яких немає у списку, видаляються з канонічного URL. |

## Визначення та перенаправлення

Вибір локалі для відвідувача, який ще не обрав жодної.

| Опція | Тип | Значення за замовчуванням | Опис |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Увімкнути автоматичні перенаправлення на основі локалі. Коли `true`, відвідувачі перенаправляються на бажану локаль (визначену з cookie, заголовка `Accept-Language` або за замовчуванням) при першому відвідуванні. |
| `autoDetectLanguage` | `boolean` | `true` | Автоматично визначати бажану мову користувача з HTTP-заголовка `Accept-Language`. Використовується разом з `autoDetectPath` для визначення, коли відбувається виявлення. |
| `autoDetectPath` | `string` | `'/'` | Де можуть спрацьовувати перенаправлення за уподобаннями cookie / Accept-Language (коли `redirects` увімкнено). - `'/'` — лише `/` (глибокі посилання у локалі за замовчуванням залишаються досяжними; за замовчуванням) - `'no_prefix'` — лише шляхи без префікса локалі - `'*'` — кожен шлях, включно з перезаписом явного префікса локалі (наприклад, `/fr/about` → `/de/about`, коли cookie надає перевагу `de`) - будь-який інший рядок — точне співставлення шляху (наприклад, `'/welcome'`) Прибирання префіксованої стратегії (наприклад, `/en` → `/` за `prefix_except_default`) не обмежується. |

## Реєстрація

Частини модуля, які можна вимкнути.

| Опція | Тип | Значення за замовчуванням | Опис |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Реєструвати плагін макроса `defineI18nRoute()`, дозволяючи посторінкові виклики `defineI18nRoute()`. |
| `plugin` | `boolean` | `true` | Реєструвати основний i18n-плагін, що надає `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` та інші runtime-помічники. |
| `hooks` | `boolean` | `true` | Реєструвати плагін i18n-хуків, що надає хуки рівня застосунку `i18n:register` та `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`. |
| `components` | `boolean` | `true` | Реєструвати вбудовані i18n-компоненти (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Встановіть `false`, щоб вимкнути автоматичну реєстрацію компонентів (наприклад, якщо ви їх не використовуєте і хочете зменшити відбиток модуля). |
| `types` | `boolean` | `true` | Генерувати декларації TypeScript-типів для `useI18n`, `$t` та повʼязаних помічників на основі ключів перекладів у файлах вашої локалі за замовчуванням. |
| `debug` | `boolean` | `false` | Увімкнути детальне debug-логування для визначення локалі, генерації маршрутів та завантаження перекладів. |
