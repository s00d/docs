# Довідник опцій модуля

Кожна опція, яку приймає `nuxt-i18n-micro`, читається під час збірки з інтерфейсу `ModuleOptions` у [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).
Тут нічого не написано вручну, тому цей довідник не може відставати від коду: типи, значення за замовчуванням та описи беруться безпосередньо з декларації.

Що ці опції *означають* разом, які комбінації мають сенс, що змінюється при перемиканні стратегії, — див. у [Конфігурації](/guides/configuration) з робочими прикладами. Ця сторінка — вичерпний список; та — пояснення.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Вкладені опції зʼявляються під своїм крапковим шляхом, тож `translationPayloads.mode` — це ключ `mode` всередині обʼєкта `translationPayloads`.

## Локалі та маршрутизація

Які мови існують і як вони зʼявляються в URL.

| Опція | Тип | За замовчуванням | Опис |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Список підтримуваних локалей. Кожен запис визначає код локалі плюс опціональні метадані (ISO, напрямок, відображуване імʼя тощо). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Стратегія URL-маршрутизації для префіксів локалей. - `'no_prefix'` — без локалі в URL; локаль зберігається у cookie. - `'prefix_except_default'` — додавати префікс усім локалям, крім локалі за замовчуванням. - `'prefix'` — завжди префікс, включно з локаллю за замовчуванням. - `'prefix_and_default'` — як `prefix`, але локаль за замовчуванням також доступна без префікса. |
| `defaultLocale` | `string` | `'en'` | Локаль, що використовується, коли її неможливо визначити з URL або уподобань користувача. Також використовується як fallback-локаль для відсутніх перекладів, коли `fallbackLocale` не задано. |
| `localeCookie` | `string \| null` | `null` | Назва cookie для збереження вподобань локалі користувача між сесіями. Встановіть `null`, щоб вимкнути збереження через cookie. Автоматично встановлюється у `'user-locale'` для стратегії `no_prefix`, якщо не задано. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Глобальна маршрутно-рівнева конфігурація локалей. Дозволяє обмежувати чи налаштовувати маршрути локалей для конкретних сторінок без модифікації їхніх компонентів. - `false` — виключити маршрут з локалізації. - `Record<LocaleCode, string>` — кастомні посторінкові шляхи. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Кастомний регулярний вираз (або його рядкове джерело) для матчингу кодів локалей у сегментах URL. Усі коди локалей, визначені у `locales`, мають відповідати цьому патерну, інакше видається попередження. |
| `noPrefixRedirect` | `boolean` | `false` | Для стратегії `no_prefix`: увімкнути редирект з URL із префіксом локалі (наприклад, `/en/about`) на версію без префікса (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Шаблони URL (рядки або RegExp), які повністю виключаються з обробки i18n. Маршрути, які збігаються, не отримують префіксів локалі, редиректів чи завантаження перекладів. Внутрішні шляхи Nuxt (`/__nuxt_error` тощо) завжди виключаються автоматично. |
| `routeLocales` | `Record<string, string[]>` | — | Посторінкові обмеження локалей, витягнуті з викликів `defineI18nRoute()`. Мапить шлях маршруту (наприклад, `'/about'`) на масив дозволених кодів локалей. Маршрути, не перелічені тут, не мають обмежень (усі локалі дозволені). |

## Переклади

Де живуть файли перекладів і як розвʼязуються ключі.

| Опція | Тип | За замовчуванням | Опис |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Шлях до каталогу з JSON-файлами перекладів відносно кореня проєкту. |
| `disableWatcher` | `boolean` | `false` | Вимкнути файловий watcher, що автоматично створює відсутні файли перекладів у режимі розробки. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Мапить імена маршрутів на інші імена маршрутів для спільного використання одних файлів перекладів. Наприклад, `\{ 'about-us': 'about' \}` означає, що сторінка `about-us` використовуватиме переклади зі сторінки `about` замість власних. |
| `plural` | `PluralFunc` | `built-in pluralization (form index by count)` | Кастомна функція плюралізації. Отримує `(key, count, params, locale, getter)` і має повертати обрану плюральну форму як рядок, або `null`/`undefined`, щоб повернутися до вбудованої логіки `defaultPlural` (тож ви можете перевизначити лише деякі локалі). Для Nuxt-модуля функція серіалізується через `.toString()` у `.nuxt/i18n.plural.mjs` — вона має бути самодостатньою (без імпортів / зовнішніх областей). Рядок з шляхом до файлу **не** підтримується. |
| `disablePageLocales` | `boolean` | `false` | Вимкнути посторінкові файли перекладів. Коли `true`, завантажуються лише глобальні переклади (`\{locale\}.json`); посторінкові файли (`pages/\{page\}/\{locale\}.json`) не генеруються і не завантажуються. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Код глобальної fallback-локалі. Коли ключ перекладу відсутній в активній локалі, модуль шукає його у цій локалі перед тим, як повернути сам ключ. |

## Пейлоади та кешування

Як переклади потрапляють у браузер. [Продуктивність](/guides/performance) пояснює, що ці опції змінюють у рантаймі.

| Опція | Тип | За замовчуванням | Опис |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Попередньо завантажувати переклади індексної сторінки у глобальному middleware Nitro (лише сервер, приватний конфіг). |
| `apiBaseUrl` | `string` | `'_locales'` | Базовий сегмент URL для API-маршруту перекладів (використовується у SSR/SSG-fetch даних). Також можна задати через змінну оточення `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Перевизначає хост для клієнтських запитів на завантаження перекладів. Корисно, коли клієнт досягає сервера через інше імʼя хоста, ніж бачить Nuxt. Також можна задати через змінну оточення `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Перевизначає хост для серверних запитів на завантаження перекладів. Корисно у контейнерних/мікросервісних налаштуваннях, де сервер досягає себе через внутрішнє імʼя хоста. Також можна задати через змінну оточення `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Контролює, як видаються пейлоади перекладів (Node: `public/<apiBaseUrl>`; Edge: Nitro `serverAssets`). - **Node**: `serverAssets` означає локальний SSR через `readFile` під `public/` (без Rollup `raw:`). - **Edge**: `serverAssets` реєструє Nitro `serverAssets` (`assets:i18n`); не примушує до публічної копії. Тримайте значення за замовчуванням для звичайного all-in-one налаштування. Для великих Edge-каталогів надавайте перевагу `mode: 'source'`. Для розгортань з CDN — вимкніть локальні виводи та задайте `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Стратегія пейлоаду перекладів. - `premerged`: матриця `\{page\}/\{locale\}/data.json` на етапі збірки (за замовчуванням) - `source`: компактні вихідні файли, що зливаються у рантаймі (краще для Edge / великих каталогів) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Локальні SSR-пейлоади: Node читає `public/<apiBaseUrl>` (примушує до публічної копії); Edge вбудовує через Nitro `serverAssets`. - **Node**: без Nitro `serverAssets` (уникає Rollup `raw:`). SSR читає `public/<apiBaseUrl\|publicDir>` як `\{page\}/\{locale\}/data.json`; коли це `true`, публічна копія форсована навіть якщо `publicAssets` є false. - **Edge** (`nitro.node === false`): Nitro `serverAssets` (`assets:i18n`) з тією ж розкладкою, що й `mode`. **Не** форсує публічну копію — встановіть `publicAssets: true` для CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Реєструвати вбудований серверний маршрут за `/\{apiBaseUrl\}/:page/:locale/data.json`. Вимикайте це, коли пейлоади перекладів обслуговуються з зовнішнього хоста/CDN. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Копіювати пейлоади у публічний вивід Nitro. Premerged → `\{page\}/\{locale\}/data.json` під `apiBaseUrl`; source → компактне дерево. У Node це дерево також є джерелом SSR, коли `serverAssets` форсує публічну копію. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Погоджуватися на prerender Nitro для `/\{apiBaseUrl\}/.../data.json`. Зазвичай зайве, коли premerged `publicAssets` вже записав ці файли. |
| `translationPayloads.publicDir` | `string` | — | Публічна тека виводу відносно кореня publish Nitro. За замовчуванням `apiBaseUrl` (`_locales`), тож статичні файли збігаються з URL клієнтських fetch (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Попереджати під час збірки, коли кількість згенерованих файлів пейлоаду перевищує цей поріг. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Попереджати під час збірки, коли сумарний розмір згенерованих пейлоадів перевищує цей поріг у байтах. |

## SEO

Мета-теги, що генеруються для кожної локалізованої сторінки.

| Опція | Тип | За замовчуванням | Опис |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Генерувати SEO мета-теги (`hreflang`, `canonical`, `og:url`, `og:locale`) автоматично. |
| `metaBaseUrl` | `string` | `undefined` | Базовий URL для SEO мета-тегів (canonical, og:url, hreflang). - Конкретний URL-рядок (наприклад, `'https://example.com'`) — використовується як є (найвищий пріоритет). - `undefined` — використовує `site.url` з `nuxt-site-config`, якщо цей модуль присутній, інакше origin поточного запиту (`useRequestURL().origin` на сервері, `window.location.origin` на клієнті). |
| `metaTrustForwardedHost` | `boolean` | `true` | Довіряти заголовку `X-Forwarded-Host` при розвʼязанні базового URL для мета-тегів. Увімкніть, коли застосунок працює за reverse-proxy (nginx, Cloudflare, AWS ALB тощо), який встановлює цей заголовок у справжнє клієнтське імʼя хоста. |
| `metaTrustForwardedProto` | `boolean` | `true` | Довіряти заголовку `X-Forwarded-Proto` при розвʼязанні протоколу для мета-тегів. Увімкніть, коли застосунок працює за TLS-термінуючим проксі, щоб канонічні URL використовували `https://`, навіть якщо застосунок сам слухає HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Список імен query-параметрів, які зберігаються у canonical та `og:url` мета-тегах. Параметри поза цим списком видаляються з канонічного URL. |

## Визначення й редиректи

Вибір локалі для відвідувача, який ще не обрав.

| Опція | Тип | За замовчуванням | Опис |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Увімкнути автоматичні редиректи за локаллю. Коли `true`, відвідувачі перенаправляються до їхньої бажаної локалі (визначеної з cookie, заголовка `Accept-Language` або за замовчуванням) при першому візиті. |
| `autoDetectLanguage` | `boolean` | `true` | Автоматично визначати переважну мову користувача з HTTP-заголовка `Accept-Language`. Використовується в поєднанні з `autoDetectPath`, щоб вирішити, коли відбувається визначення. |
| `autoDetectPath` | `string` | `'/'` | Де можуть спрацьовувати редиректи за cookie/Accept-Language (коли `redirects` увімкнено). - `'/'` — лише `/` (глибокі посилання в локалі за замовчуванням залишаються доступними; за замовчуванням) - `'no_prefix'` — лише шляхи без префікса локалі - `'*'` — кожен шлях, включно з переписуванням явного префікса локалі (наприклад, `/fr/about` → `/de/about`, коли cookie надає перевагу `de`) - будь-який інший рядок — точний збіг шляху (наприклад, `'/welcome'`) Очищення для префіксних стратегій (наприклад, `/en` → `/` під `prefix_except_default`) не гейтується. |

## Реєстрація

Частини модуля, які можна вимкнути.

| Опція | Тип | За замовчуванням | Опис |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Реєструвати плагін макросу `defineI18nRoute()`, уможливлюючи посторінкові виклики `defineI18nRoute()`. |
| `plugin` | `boolean` | `true` | Реєструвати ядерний плагін i18n, що надає `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` та інші рантайм-помічники. |
| `hooks` | `boolean` | `true` | Реєструвати плагін хуків i18n, що надає `i18n:register` та `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch` — хуки рівня застосунку. |
| `components` | `boolean` | `true` | Реєструвати вбудовані компоненти i18n (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Встановіть `false`, щоб вимкнути автоматичну реєстрацію компонентів (наприклад, якщо ви їх не використовуєте і хочете зменшити слід модуля). |
| `types` | `boolean` | `true` | Генерувати декларації типів TypeScript для `useI18n`, `$t` та повʼязаних помічників на основі ключів перекладів у ваших файлах локалі за замовчуванням. |
| `debug` | `boolean` | `false` | Увімкнути детальне debug-логування для визначення локалей, генерації маршрутів та завантаження перекладів. |
