title: "Опції модуля"
description: "Кожна опція ключа i18n у nuxt.config з типом, значенням за замовчуванням і описом, згенерована з типу ModuleOptions."
---

На цій сторінці перелічено кожен ключ об'єкта `i18n` у `nuxt.config`. Використовуйте таблиці, щоб знайти тип або значення за замовчуванням, а подробиці нижче — для прикладів і застережень. Типи, значення за замовчуванням і описи згенеровано з інтерфейсу `ModuleOptions` у [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).

```ts nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
    ],
    defaultLocale: 'en',
  },
})
```

Вкладена опція вказується за шляхом із крапками: `translationPayloads.mode` — це ключ `mode` у `translationPayloads`.

## Локалі та маршрутизація {#locales-and-routing}

Які мови існують і як вони відображаються в URL.

| Опція | Тип | За замовчуванням | Опис |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Список підтримуваних локалей. Кожен запис визначає код локалі та необов'язкові метадані (ISO, напрям, відображувану назву тощо). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Стратегія маршрутизації URL для префіксів локалей. - `'no_prefix'` — без локалі в URL; локаль зберігається в cookie. - `'prefix_except_default'` — префікс для всіх локалей, крім локалі за замовчуванням. - `'prefix'` — завжди префікс, включно з локаллю за замовчуванням. - `'prefix_and_default'` — як `prefix`, але локаль за замовчуванням також доступна без префікса. |
| `defaultLocale` | `string` | `'en'` | Локаль, що використовується, коли локаль не вдається визначити з URL чи вподобань користувача. Це не резервна локаль для перекладів: для цього задайте `fallbackLocale`. |
| `localeCookie` | `string \| null` | `null` | Назва cookie для збереження вибраної користувачем локалі між сесіями. Задайте `null`, щоб вимкнути збереження через cookie. Автоматично встановлюється в `'user-locale'` для стратегії `no_prefix`, якщо не задано; явне `null` у блоці конфігурації `i18n` вимикає його й там. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `{}` | Глобальна конфігурація локалей на рівні маршрутів. Дозволяє обмежувати чи налаштовувати маршрути локалей для окремих сторінок без змін їхніх компонентів. - `false` — виключити маршрут із локалізації. - `Record<LocaleCode, string>` — власні шляхи для кожної локалі. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Власний регулярний вираз (або його рядкове джерело) для зіставлення кодів локалей у сегментах URL. Кожен код локалі в `locales` має повністю відповідати шаблону без його прапорців, інакше збірка завершиться помилкою. |
| `noPrefixRedirect` | `boolean` | `false` | Для стратегії `no_prefix`: коли локаль за замовчуванням має власний шлях для сторінки (`localeRoutes` / `globalLocaleRoutes`), перенаправляти з оригінального шляху сторінки на власний шлях локалі відвідувача, а інакше — локалі за замовчуванням (напр., `/about` → `/about-us`). Локаль без власного шляху залишається на оригінальному шляху. Сторінки з динамічними сегментами не перенаправляються. |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Шляхи, які слід виключити з маршрутизації i18n: рядок — це префікс шляху (`/admin` охоплює `/admin/x`) або glob із `*` / `?`; RegExp перевіряється на шляху. Відповідні сторінки не отримують варіантів локалей, перенаправлення локалі чи 404 і виключаються з пререндерингу; вони все одно рендеряться з перекладами. `/api`, `/_nuxt`, `/__*`, маршрут перекладів і поширені статичні файли (sitemap, robots.txt, favicon, ресурси за розширенням) виключаються завжди. |
| `routeLocales` | `Record<string, string[]>` | — | Обмеження локалей для окремих маршрутів, що витягуються під час збірки з викликів `$defineI18nRoute()`. Зіставляє шлях маршруту (напр., `'/about'`) із масивом дозволених кодів локалей. Маршрути, яких немає в списку, не мають обмежень (дозволено всі локалі). |

## Переклади {#translations}

Де знаходяться файли перекладів і як розв'язуються ключі.

| Опція | Тип | За замовчуванням | Опис |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Шлях до директорії з JSON-файлами перекладів відносно кореня проєкту. |
| `disableWatcher` | `boolean` | `false` | Вимкнути спостерігач файлів, який автоматично створює відсутні файли перекладів у режимі розробки. |
| `routesLocaleLinks` | `{ [key: string]: string }` | `{}` | Зіставлення назв маршрутів з іншими назвами маршрутів для спільного використання тих самих файлів перекладів. Наприклад, `{ 'about-us': 'about' }` означає, що сторінка `about-us` використовуватиме переклади сторінки `about` замість власних. |
| `plural` | `PluralFunc` | ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)`` | Власна функція плюралізації. Отримує `(key, count, params, locale, getter)` і має повертати вибрану форму множини як рядок або `null`/`undefined`, щоб повернутися до вбудованої логіки `defaultPlural` (тож можна перевизначити лише деякі локалі). Для модуля Nuxt функція серіалізується через `.toString()` у `.nuxt/i18n.plural.mjs` — вона має бути самодостатньою (без імпортів / зовнішньої області видимості). Рядок зі шляхом до файлу **не** підтримується. |
| `disablePageLocales` | `boolean` | `false` | Вимкнути файли перекладів для окремих сторінок. Коли `true`, завантажуються лише глобальні переклади (`{locale}.json`); файли для окремих сторінок (`pages/{page}/{locale}.json`) не генеруються й не завантажуються. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Код глобальної резервної локалі. Ключі, відсутні в локалі, беруться з цієї локалі (зливаються в кожен payload під час його збирання чи завантаження); без неї відсутній ключ рендериться як сам ключ. |

## Payload і кешування {#payloads-and-caching}

Як переклади потрапляють до браузера. [Продуктивність](/uk/guide/performance) пояснює, що ці опції змінюють під час виконання.

| Опція | Тип | За замовчуванням | Опис |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Попередньо завантажувати переклади індексної сторінки в глобальному middleware Nitro (лише на сервері, приватна конфігурація). |
| `apiBaseUrl` | `string` | `'_locales'` | Базовий сегмент шляху URL для API-маршруту перекладів (використовується під час завантаження даних у SSR/SSG). Також можна задати через змінну середовища `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Перевизначити хост для клієнтських запитів перекладів. Корисно, коли клієнт звертається до сервера через інше ім'я хоста, ніж те, яке бачить Nuxt. Також можна задати через змінну середовища `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Перевизначити хост для серверних запитів перекладів. Корисно в конфігураціях із контейнерами/мікросервісами, де сервер звертається до себе через внутрішнє ім'я хоста. Також можна задати через змінну середовища `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Керує тим, як створюються payload перекладів (Node-сервер: `public/<apiBaseUrl>`; Edge / функції / inline: Nitro `serverAssets`). - **Node-сервер** (`node-server`, `node-cluster`, дисковий `serveStatic`): `serverAssets` означає локальний SSR через `readFile` у `public/` (без Rollup `raw:`). - **Edge, пресети функцій і `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …): `serverAssets` реєструє Nitro `serverAssets` (`assets:i18n`),   оскільки `public/` недоступний для SSR на диску. Не примушує створювати публічну копію — задайте `publicAssets: true` для CDN/статики. Залиште значення за замовчуванням для звичайної конфігурації «все в одному». Для великих каталогів на Edge віддавайте перевагу `mode: 'source'`. Для розгортань на основі CDN вимкніть локальні виводи й задайте `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Стратегія payload перекладів. - `premerged`: матриця `{page}/{locale}/data.json` під час збірки (за замовчуванням) - `source`: компактні вихідні файли, що зливаються під час виконання (перевага на Edge / для великих каталогів) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Локальні payload для SSR: Node-сервер, який віддає `public/` з диска, читає це дерево (примусово створює публічну копію); Edge, пресети функцій і `serveStatic: "inline"` вбудовують через Nitro `serverAssets`. - **Node-сервер** (пресет сам віддає `public/`, напр., `node-server`): без Nitro `serverAssets` (уникає Rollup `raw:`). SSR читає   `public/<apiBaseUrl\|publicDir>` як `{page}/{locale}/data.json`; коли це `true`,   публічна копія створюється примусово, навіть якщо `publicAssets` має значення false. - **Edge, пресети функцій і inline** (`nitro.node === false`, без дискового `serveStatic`, як-от `vercel` /   `netlify` / `aws-lambda`, або `serveStatic: "inline"`, напр., winterjs): Nitro `serverAssets` (`assets:i18n`)   з тією самою структурою, що й `mode`. **Не** примушує створювати публічну копію — задайте `publicAssets: true` для CDN/статики. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Зареєструвати вбудований серверний маршрут за адресою `/{apiBaseUrl}/:page/:locale/data.json`. Вимкніть, коли payload перекладів віддаються із зовнішнього хоста/CDN. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Копіювати payload у публічний вивід Nitro. Premerged → `{page}/{locale}/data.json` у `apiBaseUrl`; source → компактне дерево. Коли SSR читає `public/` (`node-server` та подібні), `serverAssets: true` також примусово створює цю копію. На пресетах Edge / функцій / `serveStatic: "inline"` копіювання відбувається лише тоді, коли це `true` (SSR використовує вбудовування Nitro). |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Увімкнути пререндеринг Nitro для `/{apiBaseUrl}/.../data.json`. Зазвичай зайве, коли premerged `publicAssets` уже записав ці файли. |
| `translationPayloads.publicDir` | `string` | — | Публічна папка виводу відносно публічного кореня Nitro. За замовчуванням `apiBaseUrl` (`_locales`). Тож статичні файли відповідають клієнтським URL запитів (`/{apiBaseUrl}/{page}/{locale}/data.json`). |
| `translationPayloads.rootDelta` | `boolean` | `true` | Записувати один кореневий файл на локаль, а в кожен файл сторінки — лише те, що від нього відрізняється. Клієнт і SSR зливають їх; цілий чанк і далі працює всюди, де читається файл. `false` зберігає цілий словник у кожному файлі сторінки. Лише для `premerged` і вимкнено з `disablePageLocales`. |
| `translationPayloads.warnFileCount` | `number` | `500` | Попереджати під час збірки, коли кількість згенерованих файлів payload перевищує цей поріг. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Попереджати під час збірки, коли загальний розмір згенерованих payload перевищує цей поріг у байтах. |

## SEO {#seo}

Meta-теги, що генеруються для кожної локалізованої сторінки.

| Опція | Тип | За замовчуванням | Опис |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Автоматично генерувати SEO meta-теги (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | Базовий URL для SEO meta-тегів (canonical, og:url, hreflang). - Конкретний рядок URL (напр., `'https://example.com'`) — використовується як є (найвищий пріоритет). - `undefined` — використовується `site.url` з `nuxt-site-config`, якщо цей модуль   присутній, інакше — origin поточного запиту   (`useRequestURL().origin` на сервері, `window.location.origin` на клієнті). |
| `metaTrustForwardedHost` | `boolean` | `true` | Довіряти заголовку `X-Forwarded-Host` під час визначення базового URL для meta-тегів. Увімкніть, коли застосунок працює за зворотним проксі (nginx, Cloudflare, AWS ALB тощо), який задає в цьому заголовку справжнє ім'я хоста, видиме клієнту. |
| `metaTrustForwardedProto` | `boolean` | `true` | Довіряти заголовку `X-Forwarded-Proto` під час визначення протоколу для meta-тегів. Увімкніть, коли застосунок працює за проксі, що термінує TLS, щоб канонічні URL використовували `https://`, хоча сам застосунок слухає HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Список назв параметрів запиту, що зберігаються в meta-тегах canonical і `og:url`. Параметри, яких немає в цьому списку, вилучаються з канонічного URL. |

## Визначення та перенаправлення {#detection-and-redirects}

Вибір локалі для відвідувача, який її ще не вибрав.

| Опція | Тип | За замовчуванням | Опис |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Увімкнути автоматичні перенаправлення локалі (серверний плагін і клієнтський middleware маршрутів). Коли `true`, стратегії з префіксом перенаправляють URL без префікса на його локалізовану форму. Локаль береться зі стану застосунку, cookie або `Accept-Language`, де це дозволяє `autoDetectPath`, інакше — локаль за замовчуванням. За `no_prefix` визначення ніколи не змінює URL (див. `noPrefixRedirect` для власних шляхів). |
| `autoDetectLanguage` | `boolean` | `true` | Автоматично визначати бажану мову користувача з HTTP-заголовка `Accept-Language`. Використовується разом з `autoDetectPath`, щоб вирішити, коли відбувається визначення. |
| `autoDetectPath` | `string` | `'/'` | Де можуть виконуватися перенаправлення за вподобаннями з cookie / Accept-Language (коли ввімкнено `redirects`). - `'/'` — лише `/` (глибокі посилання в локалі за замовчуванням залишаються доступними; за замовчуванням) - `'no_prefix'` — лише шляхи без префікса локалі - `'*'` — кожен шлях, включно з переписуванням явного префікса локалі   (напр., `/fr/about` → `/de/about`, коли cookie надає перевагу `de`) - будь-який інший рядок — цей шлях, кінцеві слеші ігноруються (напр., `'/welcome'`) За `prefix` URL без префікса поза дозволеними шляхами все одно перенаправляється на форму локалі за замовчуванням (`/about` → `/en/about`). Локаль за замовчуванням із префіксом за `prefix_except_default` (`/en`) — це 404, а не перенаправлення. |

## Реєстрація {#registration}

Частини модуля, які можна вимкнути.

| Опція | Тип | За замовчуванням | Опис |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Надавати `$defineI18nRoute()` під час виконання. Збірка в будь-якому разі читає виклики `$defineI18nRoute()` на сторінках. |
| `plugin` | `boolean` | `true` | Зареєструвати основний плагін i18n, що надає `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` та інші хелпери часу виконання. |
| `hooks` | `boolean` | `true` | Викликати хук застосунку `i18n:register` під час завантаження та навігації, щоб плагіни могли додавати переклади. |
| `components` | `boolean` | `true` | Зареєструвати вбудовані компоненти i18n (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Задайте `false`, щоб вимкнути автоматичну реєстрацію компонентів (напр., якщо ви їх не використовуєте й хочете зменшити слід модуля). |
| `types` | `boolean` | `true` | Генерувати оголошення типів TypeScript для `useI18n`, `$t` і пов'язаних хелперів на основі ключів перекладу у файлах вашої локалі за замовчуванням. |
| `debug` | `boolean` | `false` | Увімкнути докладне налагоджувальне логування для визначення локалі, генерації маршрутів і завантаження перекладів. |

## Інше {#other}

| Опція | Тип | За замовчуванням | Опис |
| --- | --- | --- | --- |
| `trustForwardedHost` | `boolean` | `false` | Вибирати домен запиту (`locales[].baseUrl`) з `X-Forwarded-Host` замість `Host`. Вмикайте лише за проксі, який перезаписує цей заголовок. |
| `hreflangBaseLanguage` | `boolean` | `false` | Також виводити `hreflang` лише з мовою, похідний від `iso` кожної локалі (напр., `es-ES` → також `es`). Перша регіональна локаль у `locales` забирає базовий тег для цієї мови. Маршрутний `code` ніколи не використовується — лише `iso \|\| code`. |
| `additionalTranslationDirs` | `string[]` | `[]` | Додаткові директорії (відносно кореня проєкту / кореня кожного шару Nuxt), чиї файли верхнього рівня `{locale}.json` глибоко зливаються в глобальний словник перед `translationDir`. Порядок злиття: кожен запис у порядку масиву (між шарами), потім `translationDir` (перемагає при конфліктах). Читаються лише кореневі файли `{locale}.json` — `pages/` у цих директоріях ігнорується. Приклад: `translationDir: 'frontend'`, `additionalTranslationDirs: ['common']` → `common/en.json`, потім `frontend/en.json`. |
| `vueDevtools` | `boolean` | `true` | Реєструвати інспектор і часову шкалу Vue DevTools у режимі розробки (браузерне розширення). Окремо від власної вкладки Nuxt DevTools. |
| `trailingSlash` | `'append' \| 'remove'` | `undefined (inherit from Nuxt)` | Кінцевий слеш для `$localePath` / `$switchLocalePath` (паритет із NuxtLink). Якщо не задано, за замовчуванням дорівнює `experimental.defaults.nuxtLink.trailingSlash`. Задайте явно, щоб перевизначити типове значення посилань Nuxt для хелперів шляхів i18n. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Префікс, що додається до назв локалізованих маршрутів (напр., `'localized-index'`). Використовується всередині для відрізнення оригінальних маршрутів від згенерованих варіантів локалей. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Вимкнення meta-тегів для окремих маршрутів. Зіставляє назву або шлях маршруту з `true` (вимкнути всі meta) або з масивом кодів локалей, для яких meta слід вимкнути. До нього додаються записи, знайдені у викликах `$defineI18nRoute()` під час збірки. |
| `missingWarn` | `boolean` | `true` | Показувати попередження в консолі, коли ключ перекладу відсутній (збірка для розробки, у браузері). |
| `hmr` | `boolean` | `true` | Увімкнути Hot Module Replacement для файлів перекладів у режимі розробки. Коли `true`, зміни в JSON-файлах перекладів запускають автоматичне перезавантаження без повного оновлення сторінки. |
| `cacheMaxSize` | `number` | `0` | Максимальна кількість записів у кешах перекладів у пам'яті. Кеші запитів і сервера видаляють запис, що використовувався найдавніше; мапа словників у браузері видаляє найстаріший (FIFO). `0` означає відсутність обмеження в браузері; серверні кеші тоді зберігають щонайбільше 1000 записів, тож URL запитів із вигаданими сторінками не можуть збільшувати пам'ять сервера. |
| `cacheTtl` | `number` | `0` | Час життя (у секундах) кешів запитів і серверних кешів перекладів, що відраховується від моменту збереження запису (читання його не подовжує), тож дані з `apiBaseServerHost` оновлюються щонайменше з такою частотою. Активні словники браузера через нього не спливають. `0` означає, що записи ніколи не спливають. |
| `cacheStorage` | `string` | — | Назва точки монтування сховища Nitro (`nitro.storage`, напр., `'redis'`), яку кілька серверних інстансів спільно використовують як кеш словників; читається після кешу в процесі й перед джерелом. Окупається здебільшого з `apiBaseServerHost`: один запит до бекенду замість одного на інстанс. Ключі записів містять збірку, і записи спливають через `cacheTtl` або через один день, якщо він дорівнює `0`. Вимкнено в режимі розробки та під час пререндерингу. Якщо сховище збоїть, використовується джерело. Не задано: спільного кешу немає. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Іменовані формати чисел для кожної локалі (сумісні з Vue I18n). Дозволяють виклики на кшталт `$tn(1000, 'currency')`. |
| `timeZone` | `string` | `the runtime's zone` | Часовий пояс IANA для `$td` і `<i18n-t date>` (`Europe/Berlin`). Задайте його, щоб рендерити однакову дату на сервері й у кожному браузері; власний `timeZone` іменованого формату має пріоритет. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Іменовані формати дати й часу для кожної локалі (сумісні з `datetimeFormats` у Vue I18n). Дозволяють виклики на кшталт `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | HTTP `Cache-Control` max-age (секунди) для `/{apiBaseUrl}/:page/:locale/data.json`. Повністю застосовується лише тоді, коли `dateBuild` скидає кеш URL (`?v=...`), що є поведінкою за замовчуванням: тоді відповідь має вигляд `private, max-age=…, immutable`: браузер її закріплює, а CDN, що ігнорує запит, — ні (`public` з `httpCacheControl: false`). - `dateBuild: 0`/`''` — URL стабільний, тож ця тривалість *не* враховується;   натомість відповідь стає `public, max-age=0, must-revalidate`. Довгий `max-age` на   незмінному URL закріплює перший payload, який браузер колись бачив. - `0` — взагалі не задавати `Cache-Control` (корисно для локального налагодження) - Не застосовується в режимі розробки (`import.meta.dev`), щоб кеш браузера не заважав HMR - Стосується лише відповідей, що віддаються через Nitro. Payload, скопійовані в `public/` і віддані   платформою хостингу, отримують заголовки цієї платформи — див. посібник із продуктивності. Аналог експериментального `httpCacheDuration` з `@nuxtjs/i18n` (v10.2.0), але у вигляді явного заголовка відповіді, а не maxAge з Nitro `defineCachedEventHandler`. |
| `httpCacheControl` | `string \| false` | `'public, max-age=60'` | `Cache-Control` файлу payload, який віддає хостинг або правило для всього шляху, що не бачить `?v=`. На Node-сервері відповідь на поточний `?v=` закріплюється на `httpCacheDuration`, а будь-яка інша проходить повторну перевірку; із `source`, `cacheTtl` або `apiBaseServerHost`, де словник змінюється без збірки, кожна відповідь отримує цей заголовок. `false` залишає кожен файл на `max-age=0, must-revalidate`. |
| `dateBuild` | `string \| number` | — | Значення для скидання кешу запитів перекладів (`?v=...`). Якщо не задано, модуль використовує хеш файлів перекладів, тож значення змінюється лише тоді, коли змінюються переклади (`Date.now()`, якщо хеш неможливо обчислити). `0` або `''` вимикає скидання кешу. Задайте стабільне значення (git SHA, номер збірки), щоб зафіксувати його самостійно. `NUXT_I18N_DATE_BUILD` або `runtimeConfig.public.i18nRuntime.dateBuild` замінює його під час виконання після того, як словник було замінено на місці: закріплені URL залишаються позаду без перезбірки. |
| `experimental` | `Record<string, unknown>` | — | Місце для експериментальних/нестабільних опцій. Вміст може змінюватися або видалятися без попередження між мінорними версіями. |

## Подробиці опцій {#option-details}

Опції, до яких нема чого додати понад таблицю, тут не повторюються.

### Локалі та URL {#locales-and-urls}

#### `locales` {#locales}

**Тип** `Locale[]` · **За замовчуванням** `[]`

Список підтримуваних локалей.
Кожен запис визначає код локалі та необов'язкові метадані (ISO, напрям, відображувану назву тощо).

Кожен запис — це об'єкт `Locale`:

| Властивість | Тип | Опис |
| --- | --- | --- |
| `code` | `string` | **Обов'язкова.** Сегмент URL і назва файлу (`en`, `de-at`). |
| `iso` | `string` | Тег BCP-47 для `<html lang>`, `hreflang`, форм множини та `$tn` / `$td` / `$tdr` (`en-US`). |
| `displayName` | `string` | Підпис у `<i18n-switcher>` і `$getLocaleName()`. |
| `dir` | `'ltr' \| 'rtl' \| 'auto'` | `<html dir>`. Без неї відомі RTL-мови отримують `rtl`, а кожна інша локаль не отримує атрибута. Див. [SEO](/uk/guide/seo#text-direction). |
| `disabled` | `boolean` | Виключається з маршрутів, payload і перемикання. Її префікс повертає 404, а посилання на неї залишаються на сторінці. |
| `fallbackLocale` | `string` | Резервна локаль для цієї локалі; перевизначає глобальну `fallbackLocale`. |
| `seo` | `boolean` | `false` виключає локаль із `hreflang` і `og:locale:alternate`. |
| `og` | `string` | Значення `og:locale` (`ar_AE`); за замовчуванням — перетворене `iso`. |
| `baseUrl` | `string` | Власний домен локалі: його обслуговує одна збірка, а посилання на нього з інших доменів абсолютні. |
| `baseDefault` | `boolean` | З `baseUrl`: локаль за замовчуванням для свого хоста, без префікса `/<code>` у посиланнях на неї (`prefix` його зберігає). |

Інші властивості зберігаються й повертаються `$getLocales()`. Типізуйте їх, розширивши `Locale`:

```ts
// i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
  }
}
export {}
```

Модуль піднімає `@i18n-micro/types`, тож це працює в pnpm без встановлення пакета.

#### `defaultLocale` {#defaultlocale}

**Тип** `string` · **За замовчуванням** `'en'`

Локаль, що використовується, коли локаль не вдається визначити з URL чи вподобань користувача.
Це не резервна локаль для перекладів: для цього задайте `fallbackLocale`.

#### `strategy` {#strategy}

**Тип** `Strategies` · **За замовчуванням** `'prefix_except_default'`

Стратегія маршрутизації URL для префіксів локалей.

- `'no_prefix'` — без локалі в URL; локаль зберігається в cookie.
- `'prefix_except_default'` — префікс для всіх локалей, крім локалі за замовчуванням.
- `'prefix'` — завжди префікс, включно з локаллю за замовчуванням.
- `'prefix_and_default'` — як `prefix`, але локаль за замовчуванням також доступна без префікса.

URL для кожної стратегії та перенаправлення: [Стратегії маршрутизації](/uk/guide/strategy).

#### `globalLocaleRoutes` {#globallocaleroutes}

**Тип** `GlobalLocaleRoutes` · **За замовчуванням** `{}`

Глобальна конфігурація локалей на рівні маршрутів.
Дозволяє обмежувати чи налаштовувати маршрути локалей для окремих сторінок без
змін їхніх компонентів.

- `false` — виключити маршрут із локалізації.
- `Record<LocaleCode, string>` — власні шляхи для кожної локалі.

Ключі — це назви або шляхи маршрутів. Зазвичай задається для кожної сторінки через [`$defineI18nRoute`](/uk/guide/per-component-translations).

```ts
globalLocaleRoutes: {
  about: { en: '/about-us', de: '/ueber-uns' },
  'admin-dashboard': false, // not localized
}
```

Подробиці, динамічні сегменти та маршрути `pages:extend`: [Локалізовані шляхи](/uk/guide/custom-locale-routes).

#### `routeLocales` {#routelocales}

**Тип** `Record<string, string[]>` · **За замовчуванням** —

Обмеження локалей для окремих маршрутів, що витягуються під час збірки з викликів `$defineI18nRoute()`.
Зіставляє шлях маршруту (напр., `'/about'`) із масивом дозволених кодів локалей.
Маршрути, яких немає в списку, не мають обмежень (дозволено всі локалі).

#### `routeDisableMeta` {#routedisablemeta}

**Тип** `Record<string, boolean \| string[]>` · **За замовчуванням** —

Вимкнення meta-тегів для окремих маршрутів. Зіставляє назву або шлях маршруту з `true` (вимкнути всі meta) або з масивом
кодів локалей, для яких meta слід вимкнути. До нього додаються записи, знайдені у викликах `$defineI18nRoute()`
під час збірки.

#### `customRegexMatcher` {#customregexmatcher}

**Тип** `string \| RegExp` · **За замовчуванням** `undefined (uses built-in pattern based on locale codes)`

Власний регулярний вираз (або його рядкове джерело) для зіставлення кодів локалей у сегментах URL.
Кожен код локалі в `locales` має повністю відповідати шаблону без його прапорців, інакше збірка завершиться помилкою.

```ts
customRegexMatcher: '[a-z]{2}-[a-z]{2}', // en-us, de-at
```

#### `excludePatterns` {#excludepatterns}

**Тип** `(string \| RegExp)[]` · **За замовчуванням** `undefined`

Шляхи, які слід виключити з маршрутизації i18n: рядок — це префікс шляху (`/admin` охоплює `/admin/x`)
або glob із `*` / `?`; RegExp перевіряється на шляху. Відповідні сторінки не отримують варіантів
локалей, перенаправлення локалі чи 404 і виключаються з пререндерингу; вони все одно рендеряться з
перекладами. `/api`, `/_nuxt`, `/__*`, маршрут перекладів і поширені статичні файли
(sitemap, robots.txt, favicon, ресурси за розширенням) виключаються завжди.

```ts
excludePatterns: ['/admin', '/docs/*', /^\/preview\//],
```

Докладніше: [Виключення шляхів](/uk/guide/excluding-static-files).

#### `localizedRouteNamePrefix` {#localizedroutenameprefix}

**Тип** `string` · **За замовчуванням** `'localized-'`

Префікс, що додається до назв локалізованих маршрутів (напр., `'localized-index'`).
Використовується всередині для відрізнення оригінальних маршрутів від згенерованих варіантів локалей.

#### `trailingSlash` {#trailingslash}

**Тип** `'append' \| 'remove'` · **За замовчуванням** `undefined (inherit from Nuxt)`

Кінцевий слеш для `$localePath` / `$switchLocalePath` (паритет із NuxtLink).
Якщо не задано, за замовчуванням дорівнює `experimental.defaults.nuxtLink.trailingSlash`.
Задайте явно, щоб перевизначити типове значення посилань Nuxt для хелперів шляхів i18n.

### Переклади {#translations}

#### `translationDir` {#translationdir}

**Тип** `string` · **За замовчуванням** `'locales'`

Шлях до директорії з JSON-файлами перекладів відносно кореня проєкту.

Відносно кореня кожного шару, а не `app/` (`'app/locales'` для структури Nuxt 4). Структура файлів: [Файли перекладів](/uk/guide/translations).

#### `additionalTranslationDirs` {#additionaltranslationdirs}

**Тип** `string[]` · **За замовчуванням** `[]`

Додаткові директорії (відносно кореня проєкту / кореня кожного шару Nuxt), чиї файли верхнього рівня
`{locale}.json` глибоко зливаються в глобальний словник перед `translationDir`.

Порядок злиття: кожен запис у порядку масиву (між шарами), потім `translationDir` (перемагає при конфліктах).
Читаються лише кореневі файли `{locale}.json` — `pages/` у цих директоріях ігнорується.

Приклад: `translationDir: 'frontend'`, `additionalTranslationDirs: ['common']` → `common/en.json`, потім `frontend/en.json`.

#### `disablePageLocales` {#disablepagelocales}

**Тип** `boolean` · **За замовчуванням** `false`

Вимкнути файли перекладів для окремих сторінок.
Коли `true`, завантажуються лише глобальні переклади (`{locale}.json`);
файли для окремих сторінок (`pages/{page}/{locale}.json`) не генеруються й не завантажуються.

#### `fallbackLocale` {#fallbacklocale}

**Тип** `string` · **За замовчуванням** `undefined (no fallback; returns the raw key)`

Код глобальної резервної локалі.
Ключі, відсутні в локалі, беруться з цієї локалі (зливаються в кожен payload під час його
збирання чи завантаження); без неї відсутній ключ рендериться як сам ключ.

#### `routesLocaleLinks` {#routeslocalelinks}

**Тип** `{ [key: string]: string }` · **За замовчуванням** `{}`

Зіставлення назв маршрутів з іншими назвами маршрутів для спільного використання тих самих файлів перекладів.
Наприклад, `{ 'about-us': 'about' }` означає, що сторінка `about-us` використовуватиме
переклади сторінки `about` замість власних.

```ts
routesLocaleLinks: { 'products-id': 'products' },
```

#### `plural` {#plural}

**Тип** `PluralFunc` · **За замовчуванням** ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)``

Власна функція плюралізації.
Отримує `(key, count, params, locale, getter)` і має повертати вибрану
форму множини як рядок або `null`/`undefined`, щоб повернутися до вбудованої
логіки `defaultPlural` (тож можна перевизначити лише деякі локалі).

Для модуля Nuxt функція серіалізується через `.toString()` у
`.nuxt/i18n.plural.mjs` — вона має бути самодостатньою (без імпортів / зовнішньої області видимості).
Рядок зі шляхом до файлу **не** підтримується.

Вбудоване правило та його маркер `=0 ` описано в [`$tc`](/uk/api/methods#$tc). Ваша функція замінює його для тих випадків, на які вона відповідає, отримує сире значення з усіма маркерами, а `null` повертає виклик вбудованому правилу. Функція отримує `(key, count, params, locale, getter)`; `getter(key)` повертає сирий рядок з усіма формами. Пишіть її як самодостатній вираз `function` або стрілкову функцію (без скороченого запису методу, без імпортів, без зовнішніх змінних):

```ts
plural: function (key, count, params, locale, getter) {
  if (!locale.startsWith('en')) return null // built-in rule for other locales
  const forms = String(getter(key) ?? '').split('|').map((form) => form.trim())
  const index = count === 0 ? 0 : count === 1 ? 1 : 2
  return (forms[Math.min(index, forms.length - 1)] ?? '').replace('{count}', String(count))
},
```

```json
{ "apples": "no apples | one apple | {count} apples" }
```

### Payload і кешування {#payloads-and-caching}

#### `translationPayloads` {#translationpayloads}

**Тип** `TranslationPayloadOptions` · **За замовчуванням** —

Керує тим, як створюються payload перекладів (Node-сервер: `public/<apiBaseUrl>`; Edge / функції / inline: Nitro `serverAssets`).

- **Node-сервер** (`node-server`, `node-cluster`, дисковий `serveStatic`): `serverAssets` означає локальний SSR через `readFile` у `public/` (без Rollup `raw:`).
- **Edge, пресети функцій і `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …): `serverAssets` реєструє Nitro `serverAssets` (`assets:i18n`),
  оскільки `public/` недоступний для SSR на диску. Не примушує створювати публічну копію — задайте `publicAssets: true` для CDN/статики.

Залиште значення за замовчуванням для звичайної конфігурації «все в одному». Для великих каталогів на Edge віддавайте перевагу `mode: 'source'`.
Для розгортань на основі CDN вимкніть локальні виводи й задайте `apiBaseClientHost` / `apiBaseServerHost`.

Підопції наведено в таблиці [Payload і кешування](#payloads-and-caching). Яка комбінація підходить для Node, serverless, Edge, статичного хостингу чи CDN: [Розгортання](/uk/guide/deployment).

#### `apiBaseUrl` {#apibaseurl}

**Тип** `string` · **За замовчуванням** `'_locales'`

Базовий сегмент шляху URL для API-маршруту перекладів (використовується під час завантаження даних у SSR/SSG).
Також можна задати через змінну середовища `NUXT_I18N_APP_BASE_URL`.

URL payload мають вигляд `/{apiBaseUrl}/{page}/{locale}/data.json`.

#### `apiBaseClientHost` {#apibaseclienthost}

**Тип** `string` · **За замовчуванням** `undefined`

Перевизначити хост для клієнтських запитів перекладів.
Корисно, коли клієнт звертається до сервера через інше ім'я хоста, ніж те, яке бачить Nuxt.
Також можна задати через змінну середовища `NUXT_I18N_APP_BASE_CLIENT_HOST`.

#### `apiBaseServerHost` {#apibaseserverhost}

**Тип** `string` · **За замовчуванням** `undefined`

Перевизначити хост для серверних запитів перекладів.
Корисно в конфігураціях із контейнерами/мікросервісами, де сервер звертається до себе через внутрішнє ім'я хоста.
Також можна задати через змінну середовища `NUXT_I18N_APP_BASE_SERVER_HOST`.

Хост має віддавати ті самі відповіді `/{apiBaseUrl}/{page}/{locale}/data.json`, що й вбудований маршрут.

#### `dateBuild` {#datebuild}

**Тип** `string \| number` · **За замовчуванням** —

Значення для скидання кешу запитів перекладів (`?v=...`).

Якщо не задано, модуль використовує хеш файлів перекладів, тож значення змінюється
лише тоді, коли змінюються переклади (`Date.now()`, якщо хеш неможливо обчислити). `0` або `''` вимикає
скидання кешу. Задайте стабільне значення (git SHA, номер збірки), щоб зафіксувати його самостійно.
`NUXT_I18N_DATE_BUILD` або `runtimeConfig.public.i18nRuntime.dateBuild` замінює його під час виконання після того, як словник
було замінено на місці: закріплені URL залишаються позаду без перезбірки.

#### `httpCacheDuration` {#httpcacheduration}

**Тип** `number` · **За замовчуванням** `31536000`

HTTP `Cache-Control` max-age (секунди) для `/{apiBaseUrl}/:page/:locale/data.json`.

Повністю застосовується лише тоді, коли `dateBuild` скидає кеш URL (`?v=...`), що є поведінкою за замовчуванням:
тоді відповідь має вигляд `private, max-age=…, immutable`: браузер її закріплює, а CDN, що ігнорує запит, — ні
(`public` з `httpCacheControl: false`).

- `dateBuild: 0`/`''` — URL стабільний, тож ця тривалість *не* враховується;
  натомість відповідь стає `public, max-age=0, must-revalidate`. Довгий `max-age` на
  незмінному URL закріплює перший payload, який браузер колись бачив.

- `0` — взагалі не задавати `Cache-Control` (корисно для локального налагодження)
- Не застосовується в режимі розробки (`import.meta.dev`), щоб кеш браузера не заважав HMR
- Стосується лише відповідей, що віддаються через Nitro. Payload, скопійовані в `public/` і віддані
  платформою хостингу, отримують заголовки цієї платформи — див. посібник із продуктивності.

Аналог експериментального `httpCacheDuration` з `@nuxtjs/i18n` (v10.2.0), але у вигляді
явного заголовка відповіді, а не maxAge з Nitro `defineCachedEventHandler`.

#### `cacheMaxSize` {#cachemaxsize}

**Тип** `number` · **За замовчуванням** `0`

Максимальна кількість записів у кешах перекладів у пам'яті. Кеші запитів і сервера
видаляють запис, що використовувався найдавніше; мапа словників у браузері видаляє найстаріший (FIFO).
`0` означає відсутність обмеження в браузері; серверні кеші тоді зберігають щонайбільше 1000 записів, тож
URL запитів із вигаданими сторінками не можуть збільшувати пам'ять сервера.

#### `cacheTtl` {#cachettl}

**Тип** `number` · **За замовчуванням** `0`

Час життя (у секундах) кешів запитів і серверних кешів перекладів, що відраховується від моменту
збереження запису (читання його не подовжує), тож дані з `apiBaseServerHost` оновлюються
щонайменше з такою частотою. Активні словники браузера через нього не спливають. `0` означає, що записи
ніколи не спливають.

Що обидві опції змінюють під час виконання: [Продуктивність](/uk/guide/performance).

#### `serverTranslationPreload` {#servertranslationpreload}

**Тип** `boolean` · **За замовчуванням** `false`

Попередньо завантажувати переклади індексної сторінки в глобальному middleware Nitro (лише на сервері, приватна конфігурація).

### SEO {#seo}

#### `meta` {#meta}

**Тип** `boolean` · **За замовчуванням** `true`

Автоматично генерувати SEO meta-теги (`hreflang`, `canonical`, `og:url`, `og:locale`).

Перевизначення для окремих сторінок: [`useI18nHead`](/uk/composables/useI18nHead). Усе інше: [SEO](/uk/guide/seo).

#### `metaBaseUrl` {#metabaseurl}

**Тип** `string` · **За замовчуванням** `undefined`

Базовий URL для SEO meta-тегів (canonical, og:url, hreflang).

- Конкретний рядок URL (напр., `'https://example.com'`) — використовується як є (найвищий пріоритет).
- `undefined` — використовується `site.url` з `nuxt-site-config`, якщо цей модуль
  присутній, інакше — origin поточного запиту
  (`useRequestURL().origin` на сервері, `window.location.origin` на клієнті).

#### `metaTrustForwardedHost` {#metatrustforwardedhost}

**Тип** `boolean` · **За замовчуванням** `true`

Довіряти заголовку `X-Forwarded-Host` під час визначення базового URL для meta-тегів.
Увімкніть, коли застосунок працює за зворотним проксі (nginx, Cloudflare, AWS ALB тощо),
який задає в цьому заголовку справжнє ім'я хоста, видиме клієнту.

Читається лише тоді, коли не задано ні `metaBaseUrl`, ні `site.url`. Задайте `false`, коли застосунок доступний без проксі, що перезаписує заголовок: інакше клієнт міг би вибирати хост у ваших канонічних URL.

#### `metaTrustForwardedProto` {#metatrustforwardedproto}

**Тип** `boolean` · **За замовчуванням** `true`

Довіряти заголовку `X-Forwarded-Proto` під час визначення протоколу для meta-тегів.
Увімкніть, коли застосунок працює за проксі, що термінує TLS, щоб
канонічні URL використовували `https://`, хоча сам застосунок слухає HTTP.

Та сама сфера дії, що й у `metaTrustForwardedHost`.

#### `trustForwardedHost` {#trustforwardedhost}

**Тип** `boolean` · **За замовчуванням** `false`

Вибирати домен запиту (`locales[].baseUrl`) з `X-Forwarded-Host` замість
`Host`. Вмикайте лише за проксі, який перезаписує цей заголовок.

Окремо від `metaTrustForwardedHost` і вимкнено за замовчуванням: тут заголовок вибирав би локалі іншого домену, а не лише origin тегу. Див. [Шари та домени](/uk/guide/layers#multiple-domains).

#### `hreflangBaseLanguage` {#hreflangbaselanguage}

**Тип** `boolean` · **За замовчуванням** `false`

Також виводити `hreflang` лише з мовою, похідний від `iso` кожної локалі
(напр., `es-ES` → також `es`). Перша регіональна локаль у `locales` забирає
базовий тег для цієї мови. Маршрутний `code` ніколи не використовується — лише `iso || code`.

#### `canonicalQueryWhitelist` {#canonicalquerywhitelist}

**Тип** `string[]` · **За замовчуванням** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

Список назв параметрів запиту, що зберігаються в meta-тегах canonical і `og:url`.
Параметри, яких немає в цьому списку, вилучаються з канонічного URL.

### Визначення та перенаправлення {#detection-and-redirects}

Правила, які використовують ці опції: [Визначення локалі](/uk/guide/locale-detection).

#### `redirects` {#redirects}

**Тип** `boolean` · **За замовчуванням** `true`

Увімкнути автоматичні перенаправлення локалі (серверний плагін і клієнтський middleware маршрутів).
Коли `true`, стратегії з префіксом перенаправляють URL без префікса на його локалізовану форму. Локаль
береться зі стану застосунку, cookie або `Accept-Language`, де це дозволяє `autoDetectPath`, інакше —
локаль за замовчуванням. За `no_prefix` визначення ніколи не змінює URL (див. `noPrefixRedirect` для власних шляхів).

З `false` клієнтський middleware перенаправлення не реєструється. Серверний плагін і далі повертає 404 для недійсних URL локалей і записує cookie для URL із префіксом.

#### `autoDetectLanguage` {#autodetectlanguage}

**Тип** `boolean` · **За замовчуванням** `true`

Автоматично визначати бажану мову користувача з HTTP-заголовка `Accept-Language`.
Використовується разом з `autoDetectPath`, щоб вирішити, коли відбувається визначення.

#### `autoDetectPath` {#autodetectpath}

**Тип** `string` · **За замовчуванням** `'/'`

Де можуть виконуватися перенаправлення за вподобаннями з cookie / Accept-Language (коли ввімкнено `redirects`).

- `'/'` — лише `/` (глибокі посилання в локалі за замовчуванням залишаються доступними; за замовчуванням)
- `'no_prefix'` — лише шляхи без префікса локалі
- `'*'` — кожен шлях, включно з переписуванням явного префікса локалі
  (напр., `/fr/about` → `/de/about`, коли cookie надає перевагу `de`)

- будь-який інший рядок — цей шлях, кінцеві слеші ігноруються (напр., `'/welcome'`)

За `prefix` URL без префікса поза дозволеними шляхами все одно перенаправляється на форму
локалі за замовчуванням (`/about` → `/en/about`). Локаль за замовчуванням із префіксом за
`prefix_except_default` (`/en`) — це 404, а не перенаправлення.

#### `localeCookie` {#localecookie}

**Тип** `string \| null` · **За замовчуванням** `null`

Назва cookie для збереження вибраної користувачем локалі між сесіями.
Задайте `null`, щоб вимкнути збереження через cookie.
Автоматично встановлюється в `'user-locale'` для стратегії `no_prefix`, якщо не задано; явне
`null` у блоці конфігурації `i18n` вимикає його й там.

Без cookie `Accept-Language` і далі керує перенаправленнями; cookie запам'ятовує вибір між відвідуваннями.

#### `noPrefixRedirect` {#noprefixredirect}

**Тип** `boolean` · **За замовчуванням** `false`

Для стратегії `no_prefix`: коли локаль за замовчуванням має власний шлях для сторінки
(`localeRoutes` / `globalLocaleRoutes`), перенаправляти з оригінального шляху сторінки на власний
шлях локалі відвідувача, а інакше — локалі за замовчуванням (напр., `/about` → `/about-us`).
Локаль без власного шляху залишається на оригінальному шляху. Сторінки з динамічними
сегментами не перенаправляються.
