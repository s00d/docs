## 🔍 Методи перекладу

Основні методи для отримання та керування перекладами.

### `$t`

{/* generated:method:$t — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params?: Params, defaultValue?: string | null) => CleanTranslation
```

Перекладає ключ, підставляючи в нього `params`. Повертає `defaultValue`, коли ключ
відсутній, або сам ключ, коли значення за замовчуванням не задано.

{/* /generated:method:$t */}

```typescript
const welcomeMessage = $t('welcome', { username: 'Alice', unreadCount: 5 })
// Output: "Welcome, Alice! You have 5 unread messages."
```

<Warning>
`$t` повертає `CleanTranslation`, тобто `string | number | boolean | Translations | PluralTranslations | null`. Якщо ключ вказує на **вкладений обʼєкт** у вашому JSON (наприклад, `$t('header')`, коли JSON містить `\{ "header": \{ "title": "Hi" \} \}`), значенням, що повертається, буде цей **обʼєкт**, а не рядок. Використання його безпосередньо у Vue-шаблоні (<code v-pre>\{\{ $t('header') \}\}</code>) відрендерить `[object Object]`.

**Як цього уникнути:**

- Використайте специфічніший ключ: `$t('header.title')` → `"Hi"`
- Використайте `$ts()`, який завжди повертає рядок (викликає `.toString()` для нерядкових значень)
- Використовуйте `$t` із вкладеним ключем свідомо, щоб отримати підобʼєкти для програмного використання
</Warning>

### `$ts`

{/* generated:method:$ts — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params?: Params, defaultValue?: string) => string
```

Як `$t`, але завжди повертає рядок: обʼєкт або масив перетворюється на рядок, а не повертається як є.

{/* /generated:method:$ts */}

```typescript
const welcomeMessage = $ts('welcome', { username: 'Alice', unreadCount: 5 })
// Output: "Welcome, Alice! You have 5 unread messages."
```

### `$_t` та `$_ts`

{/* generated:method:$_t — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNormalizedLoaded) => (key: string, params?: Params, defaultValue?: string | null) => CleanTranslation
```

Прив'язати `$t` до конкретного маршруту, для перекладу поза поточною сторінкою — наприклад, коли layout рендерить
посилання на інший маршрут.

{/* /generated:method:$_t */}

{/* generated:method:$_ts — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNormalizedLoaded) => (key: string, params?: Params, defaultValue?: string | null) => string
```

Прив'язати `$ts` до конкретного маршруту. Див. `$_t`.

{/* /generated:method:$_ts */}

Варіанти `$t` та `$ts`, привʼязані до маршруту. Вони приймають **маршрут** першим і повертають функцію перекладу, замкнену на локаль та контекст сторінки цього маршруту.

- **Доступ**: `useNuxtApp()` (також реекспортується `useI18n()` як `$_t` / `$_ts`)

Використовуйте їх, коли активний маршрут під час SSR або переходів відрізняється від `router.currentRoute` — наприклад, всередині `<i18n-t>`, `<i18n-group>`, або при рендерингу контенту для конкретного обʼєкта `route`.

```typescript
import { useRoute, useNuxtApp } from '#imports'

const route = useRoute()
const { $_t, $_ts } = useNuxtApp()

const $t = $_t(route)
const title = $t('page.title')

// String-safe variant
const label = $_ts(route)('page.label')
```

</Tip>

### `$tc`

{/* generated:method:$tc — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params: number | Params, defaultValue?: string) => string
```

Перекладає з підтримкою множинних форм. `params` може бути самою кількістю або обʼєктом, що містить
`count`.

{/* /generated:method:$tc */}

**Формат перекладу**: форми, розділені `|`. Вставляйте плейсхолдери в **кожну** форму:

```json
{
  "apples": "no apples | one apple | {count} apples",
  "cart": "no items for {name} | one item for {name} | {count} items for {name}"
}
```

```typescript
$tc('apples', 0) // "no apples"
$tc('apples', 1) // "one apple"
$tc('apples', 10) // "10 apples"

// count + other params (second argument must be an object)
$tc('cart', { count: 10, name: 'Alice' }) // "10 items for Alice"
```

<Warning>

</Warning>

**Альтернатива-компонент** — `<i18n-t keypath="cart" :plural="count" :params="\{ name \}" />` (внутрішньо зливає `count` з `params`).

<Tip>

</Tip>

### `$mergeTranslations`

{/* generated:method:$mergeTranslations — do not edit; run `pnpm run docs:generate` */}

```ts
(newTranslations: Translations) => void
```

Зливає переклади в активну локаль під час виконання, перевизначаючи те, що завантажено.

{/* /generated:method:$mergeTranslations */}

```typescript
$mergeTranslations({
  welcome: 'Bienvenue, {username}!',
})
// Output: Updates the translation cache with the new French translation
```

### `$resolveTranslations`

{/* generated:method:$resolveTranslations — do not edit; run `pnpm run docs:generate` */}

```ts
() => Translations
```

Усі переклади, що зараз у памʼяті для активної локалі та маршруту, у вигляді дерева.
Тільки для читання — представлення того, що `$t()` може розвʼязати прямо зараз.

{/* /generated:method:$resolveTranslations */}

```typescript
const tree = $resolveTranslations()
// { aaa: { bbb: 'ccc' }, ddd: 1111 } — the same dictionary $t() reads from
```

Використовуйте це, коли потрібен повний in-memory словник (DevTools, тести, runtime-редактори). Ставтеся до значення, що повертається, як до тільки для читання; змінюйте значення через `$setTranslation` або накладайте патчі через `$mergeTranslations`.

### `$setTranslation`

{/* generated:method:$setTranslation — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, value: unknown) => void
```

Замінює значення за `key` в активному словнику. Це заміна, а не злиття —
використовуйте `$mergeTranslations`, коли існуючі сусідні значення мають зберегтися.

{/* /generated:method:$setTranslation */}

```typescript
$setTranslation('aaa', { fff: 'ggg' }) // replaces the whole `aaa` subtree
$setTranslation('aaa', 'text')          // replaces `aaa` with a string
$setTranslation('ddd', 1111)            // scalar at the top level
$setTranslation('aaa.bbb', 'nested')    // dotted path
```

Це **заміна**, а не злиття. Наявні сусідні значення під тим самим ключем видаляються. Щоб застосувати патч без втрати сусідніх значень, використовуйте `$mergeTranslations`.

### `$setMissingHandler`

{/* generated:method:$setMissingHandler — do not edit; run `pnpm run docs:generate` */}

```ts
(handler: MissingHandler | null) => void
```

Встановлює callback, що викликається для кожного нерозвʼязаного ключа. Передайте `null`, щоб видалити його.

{/* /generated:method:$setMissingHandler */}

**Визначення типу**:

```typescript
type MissingHandler = (locale: string, key: string, routeName: string, instance?: unknown, type?: string) => void
```

```typescript
// Set a custom handler
$setMissingHandler((locale, key, routeName) => {
  console.error(`Missing translation: ${key} in ${locale} for route ${routeName}`)
  // Send to Sentry or other error tracking service
  // Sentry.captureMessage(`Missing translation: ${key}`)
})

// Remove the handler
$setMissingHandler(null)
```

**Сценарії використання**:

- Логування відсутніх перекладів у сервіси відстеження помилок (Sentry, LogRocket тощо)
- Збір аналітики про відсутні переклади
- Кастомна обробка помилок для відсутніх ключів перекладу

## 🔢 Форматування чисел та дат

Методи для форматування чисел та дат відповідно до конвенцій локалі.

### `$tn`

{/* generated:method:$tn — do not edit; run `pnpm run docs:generate` */}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

Форматує число через `Intl.NumberFormat` в активній локалі. Ключ обирає іменований формат
з конфігурації.

{/* /generated:method:$tn */}

```typescript
// Inline options
const formattedNumber = $tn(1234567.89, { style: 'currency', currency: 'USD' })
// "$1,234,567.89"

// Named format (from nuxt.config i18n.numberFormats)
const price = $tn(1000, 'currency')
const priceDe = $tn(1000, 'currency', 'de')
const compact = $tn(1000, 'currency', { notation: 'compact' })
```

Невідомі ключі іменованих форматів повертаються до значень за замовчуванням `Intl.NumberFormat`. У розробці (клієнт) виводиться `console.warn`, коли `missingWarn` увімкнено (за замовчуванням).

**Приклад конфігурації**:

```ts
export default defineNuxtConfig({
  i18n: {
    numberFormats: {
      en: {
        currency: { style: 'currency', currency: 'USD' },
        decimal: { style: 'decimal', minimumFractionDigits: 2, maximumFractionDigits: 2 },
      },
      de: {
        currency: { style: 'currency', currency: 'EUR' },
      },
    },
  },
})
```

**Сценарії використання**:

- Форматування чисел як валюти, відсотків або десяткових у відповідному форматі локалі
- Повторне використання іменованих форматів у застосунку (паритет з міграцією з Vue I18n)

### `$td`

{/* generated:method:$td — do not edit; run `pnpm run docs:generate` */}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

Форматує дату через `Intl.DateTimeFormat` в активній локалі. Ключ обирає іменований формат
з конфігурації.

{/* /generated:method:$td */}

```typescript
const formattedDate = $td(new Date(), { weekday: 'long', year: 'numeric', month: 'long', day: 'numeric' })
// "Friday, September 1, 2023"

const short = $td(new Date(), 'short')
const longDe = $td(new Date(), 'long', 'de')
```

Невідомі ключі іменованих форматів повертаються до значень за замовчуванням `Intl.DateTimeFormat`. У розробці (клієнт) виводиться `console.warn`, коли `missingWarn` увімкнено (за замовчуванням).

**Приклад конфігурації**:

```ts
export default defineNuxtConfig({
  i18n: {
    datetimeFormats: {
      en: {
        short: { year: 'numeric', month: 'short', day: 'numeric' },
        long: { year: 'numeric', month: 'long', day: 'numeric', weekday: 'long' },
      },
    },
  },
})
```

**Сценарії використання**:

- Відображення дат у форматі, що відповідає локалі користувача
- Спільні пресети short/long/date-time на рівні застосунку

### `$tdr`

{/* generated:method:$tdr — do not edit; run `pnpm run docs:generate` */}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

Форматує дату як відносний час («3 дні тому») через `Intl.RelativeTimeFormat`.

{/* /generated:method:$tdr */}

```typescript
const relativeDate = $tdr(new Date(Date.now() - 1000 * 60 * 5))
// Output: "5 minutes ago" in the 'en-US' locale
```

## 🔄 Перемикання маршрутів та локалей

Методи для перемикання між локалями та маршрутами.

### `$switchLocale`

{/* generated:method:$switchLocale — do not edit; run `pnpm run docs:generate` */}


## 🚦 Конфігурація маршрутів

Методи для конфігурації поведінки маршрутів та контролю доступу.

### `$defineI18nRoute`

{/* generated:method:$defineI18nRoute — do not edit; run `pnpm run docs:generate` */}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

Реєструє посторінкову конфігурацію локалей та переклади зсередини компонента.
Зливається з активною локаллю та повторно застосовується при зміні локалі.

{/* /generated:method:$defineI18nRoute */}

> [!IMPORTANT]
> `$defineI18nRoute` надається **define-плагіном** і доступний лише через `useNuxtApp()` — він **не** є частиною обʼєкта, що повертається `useI18n()`.
> Завжди діструктурізуйте його з `useNuxtApp()` всередині `script setup`. Виклик `$defineI18nRoute(...)` як голого глобального призводить до `"$defineI18nRoute is not defined"` під час SSR/prerender.

**Параметри**:

- **locales**: `string[] | Record<string, Record<string, string>>` — доступні локалі для маршруту
- **localeRoutes**: `Record<string, string>` — опціонально. Кастомні маршрути для конкретних локалей
- **disableMeta**: `boolean | string[]` — опціонально. Вимикає i18n-мета-теги для всіх або конкретних локалей

**Базовий приклад**:

```typescript
import { useNuxtApp } from '#imports'

const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'fr', 'de'],
  localeRoutes: {
    en: '/welcome',
    fr: '/bienvenue',
    de: '/willkommen',
  },
  disableMeta: false,
})
```

> 📖 **Для детальних прикладів використання, форматів конфігурації та найкращих практик див. [Гайд з посторінкових перекладів](/guides/per-component-translations).**

### `$setI18nRouteParams`

{/* generated:method:$setI18nRouteParams — do not edit; run `pnpm run docs:generate` */}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

Встановлює параметри для кожної локалі для поточного маршруту, щоб динамічний сегмент міг відрізнятися для кожної мови.
Викликайте його під час SSR, до того як буде відрендерено head.

{/* /generated:method:$setI18nRouteParams */}

```typescript
// in pages/news/[id].vue
// for en/news/1-first-article
const { $switchLocaleRoute, $setI18nRouteParams, $defineI18nRoute } = useNuxtApp()
$defineI18nRoute({
  localeRoutes: {
    en: '/news/:id()',
    fr: '/nouvelles/:id()',
    de: '/Nachricht/:id()',
  },
})
const { data: news } = await useAsyncData(`news-${params.id}`, async () => {
  let response = await $fetch("/api/getNews", {
    query: {
      id: params.id,
    },
  });
  if (response?.localeSlugs) {
    response.localeSlugs = {
      en: {
        id: '1-first-article'
      }
      fr: {
        id: '1-premier-article'
      }
      de: {
        id: '1-erster-Artikel'
      }
    }
    $setI18nRouteParams(response?.localeSlugs);
  }
  return response;
});
$switchLocalePath('fr') // === 'fr/nouvelles/1-premier-article'
$switchLocalePath('de') // === 'de/Nachricht/1-erster-Artikel'
```

## 🧭 Composable `useI18nLocale`

Централізований composable для керування станом локалі. Використовуйте його замість прямого маніпулювання `useState('i18n-locale')` або `useCookie('user-locale')`.

```typescript
const {
  setLocale, // (locale: string) => void — updates state + cookie
  getLocale, // () => string | null — from state or cookie
  getPreferredLocale, // () => string | null — validated against locales list
  getEffectiveLocale, // (route, getLocaleFromRoute) => string
  resolveInitialLocale, // (options) => string
  isValidLocale, // (locale) => boolean
  locale, // Ref<string | null> — reactive state
  localeCookie, // CookieRef — reactive cookie
  syncLocale, // (locale) => void — sync to cookie only
  validLocales, // string[] — list of valid locale codes
} = useI18nLocale()
```

### Ключові методи

| Метод                   | Опис                                                        |
| ----------------------- | ----------------------------------------------------------- |
| `setLocale(locale)`     | Атомарно встановлює локаль у `useState` та cookie           |
| `getLocale()`           | Повертає поточну локаль зі стану або cookie                 |
| `getPreferredLocale()`  | Повертає локаль, валідовану відносно списку `locales`, або `null` |
| `isValidLocale(locale)` | Перевіряє, чи код локалі є у налаштованому списку `locales` |

### Використання у кастомних плагінах

```typescript
// plugins/i18n-loader.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,
  setup() {
    const { setLocale } = useI18nLocale()
    // Detect locale from headers, domain, etc.
    setLocale('de')
  },
})
```
