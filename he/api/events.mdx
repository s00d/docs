---

המודול קורא ל-hook אחד של זמן ריצה (של האפליקציה), `i18n:register`. השתמשו בו כאשר פלאגין או מודול מוסיפים תרגומים שאינם נמצאים בקבצי ה-`locales/` שלכם. ה-callback שלכם מקבל פונקציית `register` שממזגת תרגומים לתוך הדף המוצג.

## `i18n:register` {#i18nregister}

```ts
'i18n:register': (
  register: (translations: unknown, locale?: string) => void,
  locale: string,
) => HookResult
```

| ארגומנט | תיאור |
| --- | --- |
| `register(translations, locale?)` | ממזג לעומק את `translations` לתוך ה-chunk של הדף עבור הנתיב הנטען, עבור `locale` (ברירת מחדל: ה-`locale` של ה-hook). מפתחות שכבר קיימים נדרסים. |
| `locale` | ה-locale של הנתיב הנטען. |

ה-hook מוגדר בטיפוסים דרך `RuntimeNuxtHooks`, כך ש-`nuxtApp.hook('i18n:register', …)` אינו דורש המרת טיפוס.

## מתי הוא מופעל {#when-it-fires}

פלאגין הטעינה (`i18n-plugin-loader`) קורא לו:

1. פעם אחת בעת ההפעלה, לאחר שכל הפלאגינים רצו (`app:created`) ולפני שהאפליקציה מרונדרת;
2. בתוך ה-`router.beforeEach` שלו, לאחר שתרגומי דף היעד נטענו, כאשר הנתיב משתנה — בכל ניווט תחת `no_prefix`.

ממתינים לכל callback ולכל קריאה ל-`register` לפני שהאפליקציה מרונדרת או שהניווט ממשיך, כך שהדף מרונדר עם המפתחות הממוזגים. עם [`hooks: false`](/he/api/module-options#hooks) ה-hook לעולם אינו נקרא.

## דוגמה {#example}

```ts
// plugins/i18n-extra.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('i18n:register', async (register, locale) => {
    const extra = await $fetch<Record<string, unknown>>(`/api/cms-strings/${locale}`)
    register(extra, locale)
  })
})
```

זהו hook של זמן ריצה: רשמו אותו עם `nuxtApp.hook` בתוך פלאגין, ולא עם `nuxt.hook` ב-`nuxt.config` או ב-`setup` של מודול. מודול מוסיף פלאגין כזה באמצעות `addPlugin`.
