**תאריך**: 2026-11-03

**גרסה**: `v4.0.0`

![v4.0.0 release](/images/4.0.0.png)

**v4.0.0** שוחררה. הניתוב, ליבת התרגום, קובצי המילון, זיהוי ה-locale וכל חבילות ה-frameworks נכתבו מחדש. אפשרויות, `$t`, `$localePath`, `$switchLocale`, הרכיבים וה-composables שומרים על שמותיהם. מה שמשתנה הוא ההתנהגות, ורוב השינויים האלה הם באגים שנעלמו. רוב האפליקציות צריכות מעט שינויי קוד, אבל קראו את [שינויים שוברים](#breaking-changes) לפני השדרוג: כתובות URL, תגיות SEO ו-APIs של חבילות frameworks זזו במקומות מסוימים. ב-[שדרוג](/he/guide/upgrade) יש את כל הפרטים.

## מה חדש? {#what’s-new}

### build אחד לכל הדומיינים {#one-build-for-every-domain}

`locales[].baseUrl` ו-`baseDefault` עיצבו בעבר רק קישורים. כעת הם גם מנתבים בקשות, תחת כל ארבע האסטרטגיות וב-`nuxt generate`:

```ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'fr', baseUrl: 'https://example.com' },
      { code: 'de', baseUrl: 'https://example.de', baseDefault: true },
    ],
  },
})
```

- host מגיש את ה-locales שלו. קישורים ל-locale של דומיין אחר הופכים לכתובות URL מוחלטות באותו דומיין, והחלפה אליו מנווטת לשם.
- `trustForwardedHost` בוחר את הדומיין מתוך `X-Forwarded-Host` מאחורי proxy שדורס אותו. כבוי כברירת מחדל.
- `NUXT_I18N_DOMAIN` נותן ל-`nuxt generate` את ה-host שלו: הריצו אותו פעם אחת לכל דומיין, וכל פלט מכיל רק את העמודים והמילונים של אותו דומיין.
- אפליקציה ללא `baseUrl` אינה כוללת שום חלק מהקוד הזה.

ראו [שכבות ודומיינים](/he/guide/layers#multiple-domains) ו-[פריסה](/he/guide/deployment).

### ניתוב שמסכים עם ה-router {#routing-that-agrees-with-the-router}

ה-build וה-runtime כבר אינם מחשבים כתובות URL מתורגמות בנפרד. כל תשובה מגיעה מה-routes שה-build יצר, כך שקישור, switcher, `hreflang` והפניה אינם יכולים להצביע על עמוד שאינו קיים.

- locale שאינו מגיש עמוד מקשר לדף הבית שלו, ולעולם לא לעמוד של locale אחר.
- `hreflang` מפרט רק את ה-locales שמגישים את העמוד.
- `$switchLocale` נפתר ל-`true` או `false`, כך שתוכלו לדעת מתי מילון נכשל בטעינה. קריאה חוזרת מנסה שוב.
- `$setI18nRouteParams` ו-`useI18nHead` שהוגדרו במהלך SSR שורדים את ה-hydration. ה-switcher מקשר ל-slug המתורגם, גם ב-HTML של השרת.
- ניווט נכנס לתוקף כאשר הוא מבוצע: ניווט שבוטל או נחסם אינו משנה דבר.
- מצב hash עובד תחת `prefix`.
- `<Greeting :locale="$getLocale()" />` על server component מגדיר את locale הרינדור שלו.

### זיהוי locale אחד {#one-locale-detection}

סדר אחד בכל מקום, בשרת, בדפדפן, בפונקציות העזר של server API וב-Astro. `Accept-Language` מכבד ערכי `q`, התאמה אזורית כבר אינה תלויה בסדר של `locales`, והיא לעולם אינה חוצה בין כתבי סינית. דריסות בזמן ריצה מגיעות כעת לניתוב: `NUXT_I18N_DEFAULT_LOCALE` ו-`disabledLocales` בזמן ריצה משנים את מה שמוגש בפועל. ראו [זיהוי locale](/he/guide/locale-detection).

### מילון אחד בכל מצב {#one-dictionary-in-every-mode}

builds ממוזגים מראש, `mode: 'source'` ומצב פיתוח היו חלוקים בעבר בעמודים רבים. כעת הם נותנים את אותו המילון.

- המיזוגים עמוקים בכל רמה, ושרשראות גיבוי (`fr` → `de` → `en`) נעקבות עד סופן.
- עריכות תרגום בפיתוח מוחלות במקום, ללא טעינה מחדש של העמוד. מפתחות שהוסרו נעלמים, ועריכה של קובץ שורש מגיעה לכל עמוד.
- `$clearCache()` טוען מחדש את העמוד הנוכחי ושומר את הטקסט הישן על המסך עד שהטקסט החדש מגיע.
- chunk שנכשל שומר על המילון הנוכחי במקום להציג מפתחות גולמיים.

### קובצי מילון קטנים יותר {#smaller-dictionary-files}

- הקובץ של עמוד מכיל כעת רק את מה ששונה מהשורש של ה-locale, ב-`__root/<locale>/data.json`. הדפדפן טוען את השורש פעם אחת וממזג כל עמוד מעליו, כך שהשימוש בדיסק יורד והעמוד הבא עולה שבריר מהראשון.
- כתובות URL של מילונים נושאות גרסה. URL עם ה-`?v=` הנוכחי מקובע לשנה בשרת Node, והעותק הסטטי של host עונה `max-age=60`. ראו [כותרות מטמון](/he/guide/deployment#cache-headers-and-datebuild).
- כל עמוד SSR טוען מראש את קובצי המילון שלו, כך שהם מתחילים יחד עם ה-HTML.
- קריאה שנכשלה כבר אינה נדבקת: הבקשה הבאה קוראת שוב. ראו [כאשר לא ניתן לקרוא מילון](/he/guide/deployment#when-a-dictionary-cannot-be-read).

### `<i18n-t>`, צורות רבים ועיצובים טובים יותר {#better-&lt;i18n-t&gt;-plurals-and-formats}

- Slots עובדים עם `plural`, `number`, `date` ו-`relativeDate`, וכל `{name}` ממולא, לא רק הראשון.
- `<i18n-t>` הוא renderer אחד ב-Nuxt, Vue, React, Preact, Solid ו-Astro.
- צורה ראשונה שמתחילה ב-`=0 ` היא צורת אפס מפורשת, והשאר נקבעות לפי `Intl.PluralRules`: `=0 no apples | one apple | {count} apples`. ראו [`$tc`](/he/api/methods#$tc).
- אפשרות `timeZone` חדשה: תאריך לוח שנה אחד בשרת ובכל דפדפן.
- `{firstName}`, `{first-name}` ו-`{user.name}` הם placeholders תקינים.
- `$tn`, `$td` ו-`$tdr` עוקבים אחר `iso`, כמו צורות הרבים.
- `$tdr` נותן תאריכי עתיד אמיתיים: `in 3 days`, או `tomorrow` עם `numeric: 'auto'`.

### בטוח יותר כברירת מחדל {#safer-by-default}

- `<i18n-t html>` מבצע escape ל-`params`. רק התרגום נחשב markup מהימן.
- שום קישור אינו עוזב את ה-origin בטעות: `//host`, `/\host` ורווחים נשארים באתר הזה.
- מטמון התרגומים בשרת מוגבל, כך שכתובות URL עם שמות עמודים מומצאים אינן יכולות להגדיל את הזיכרון.
- נקודות הקצה של שמירה ב-DevTools מקבלות רק קובצי `.json` קיימים בתוך תיקיות התרגום שלכם, ודוחות בקשות חוצות אתרים.

### חבילות frameworks בגרסה 2.0 {#framework-packages-at-2-0}

- **React, Preact, Solid:** `I18nT` מקבל prop בשם `components` לטקסט עשיר. `useT` ו-`useLocaleSwitch` חדשים, ותמיכה ב-React Server Components דרך `@i18n-micro/react/server` ו-`/client`. Preact כבר אינו צריך את `preact/compat`.
- **Vue ו-VitePress:** `I18nLink` שומר על `name`, `query` ו-`hash`, ו-VitePress מכבד את `base`.
- **Astro:** `i18nIntegration` אורז את המילונים שלכם ומתקין את ה-middleware. לנקודת הכניסה הראשית אין import של `node:*`, כך שהיא רצה ב-edge. `base` עובד.
- **Node ו-runtime:** `fork(locale)` נותן מופע זול לכל בקשה, ו-`run(locale, fn)` ב-`@i18n-micro/node` תוחם מופע לבקשה.
- **`@i18n-micro/types-generator`:** ללא תלויות צד שלישי, ו-plugin פשוט של Vite ו-Rollup.
- **`@i18n-micro/devtools-ui`:** עדכונים חיים דרך ה-socket של Vite, ואפליקציית toolbar של Astro.

### `@i18n-micro/cli` {#@i18n-micro/cli}

ה-CLI נמצא כעת ב-monorepo בשם `@i18n-micro/cli`, נכתב מחדש עם 16 פקודות במקום 28 והרבה פחות תלויות. `check` מחליפה את `validate`, `diff` ו-`check-duplicates`, עם `--json` וקודי יציאה עבור CI. כאשר היא אינה יכולה להוכיח שמפתח אינו בשימוש, `clean` אינה כותבת דבר. ראו [CLI](/he/guide/cli).

### תיעוד {#documentation}

התיעוד נכתב מחדש מתוך הקוד סביב מסלול קריאה אחד: התקנה, עמוד מתורגם ראשון, קובצי תרגום, ניתוב, זיהוי, ואז מדריכי משימות. כתובות URL ישנות מפנות. [שדרוג](/he/guide/upgrade) מפרט כל שינוי בפירוט.

## מהירות וגודל {#speed-and-size}

- רינדור בשרת קורא מילונים ישירות, ללא בקשת HTTP מקומית וללא ניתוח מחדש.
- `dir="auto"` כבר אינו ברירת המחדל. דפדפנים מבזבזים עליו זמן רב בעמודים גדולים: עם 20,000 אלמנטים של `$t`, ה-DOMContentLoaded ב-Chromium ירד מכ-980 ms לכ-115 ms.
- `serverTranslationPreload` ו-`i18n:register` כבר אינם מאטים כל בקשה.
- ה-bundle של הלקוח משמיט את `useCookie` כאשר לא מוגדר cookie, ו-`@i18n-micro/path-strategy` הוא שבריר מגודלו הקודם.

**אפליקציית בדיקה מול v3.30.3.** אפליקציית Nuxt שנוצרה, על שרת Node אחד, על Mac אחד, `wrk` עם 24 חיבורים למשך 20 שניות, שלושה סבבים מתחלפים, על build טרום-שחרור. השורות מגיעות מהרצות נפרדות, לכן השוו בתוך שורה. ה-hydration משתמש ב-`dir: 'ltr'` בשני הצדדים.

**JS לקוח.** אפליקציה אמיתית עם קוד משלה גדלה מעט, כמו לעיל. תיקונים משותפים הגדילו גם את חבילות ה-frameworks, כפי שנמדד עם אפליקציות Vue, React, Preact ו-Solid בגודל מינימלי על build טרום-שחרור אחר: בערך 1.4 KB עד 2.5 KB gzip יותר. React, Preact ו-Solid נושאות גם את ה-renderer המשותף לטקסט עשיר.

**בקשות מילון.** טעינה ראשונה לוקחת כעת שני קבצים, השורש והעמוד. הבתים שלה נשארים זהים (+0.3% על פני 103 ו-89 טעינות ראשונות בשתי אפליקציות ה-SSR). העמוד הבא באותו מסמך לוקח קובץ קטן אחד: 4.7 KB ל-1.5 KB gzip ו-5.9 KB ל-0.5 KB gzip בשני העמודים שנמדדו. לאורך מעבר של משתמש מחובר ב-SPA, הבתים של המילונים ירדו ב-21%.

**Edge.** באפליקציית הדגמה קטנה, ההעלאה של Cloudflare Worker עלתה מ-241.5 KiB ל-250.3 KiB gzip, על build טרום-שחרור. מילונים שמוטמעים ב-bundle של Edge משתמשים באותם קובצי שורש ועמוד, אבל לא מדדנו את ההטמעה הזו על קטלוג גדול.

## שינויים שוברים {#breaking-changes}

### דרישות {#requirements}

- **Nuxt 3.18 ומעלה**, ו-**Node 20 ומעלה**.
- **`@i18n-micro/test-utils`** כבר אינו מותקן יחד עם המודול. הוסיפו אותו בעצמכם אם הבדיקות שלכם מייבאות אותו.
- **`@i18n-micro/hmr`** נעלם: HMR של תרגומים מובנה. הסירו את החבילה אם התקנתם אותה.
- **`@i18n-micro/react`** דורש React 18 ומעלה.
- **`nuxt-i18n-micro-cli`** הוחלף ב-`@i18n-micro/cli`.

### אפשרויות ותצורה {#options-and-config}

- `i18n-plugin-hooks` ו-`i18n-plugin-define` ב-`dependsOn` כבר אינם ממתינים לשום דבר, ללא שגיאה. השתמשו ב-`i18n-plugin-loader`.
- ה-auto-imports בשרת הם `useLocaleServerMiddleware`, `useTranslationServerMiddleware`, `loadTranslationsFromServer` ו-`detectCurrentLocale`. אחרים כבר אינם מיובאים אוטומטית.
- `resolveTranslationPayloadMode` ושאר פונקציות העזר `resolveTranslationPayload*` הוסרו מ-`nuxt-i18n-micro`, יחד עם `shouldCopyTranslationPayloadsToPublic` ו-`shouldRegisterNitroServerAssets`. הטיפוס `TranslationPayloadMode` נשאר.
- ל-`$getI18nConfig()` כבר אין `isSSG`, `hmr`, `hooks`, `noPrefixRedirect`, `routeLocales`, `routeDisableMeta` או `globalLocaleRoutes`. האפשרויות עצמן לא השתנו.
- `locales[].baseUrl` מנתב כעת בקשות: locale של דומיין אחר מחזיר 404 ב-host הזה, וקישורים באותו host הם יחסיים. ב-build כזה `$getI18nConfig().locales` מכיל את מה שה-host מגיש, ו-`linkLocales` מכיל את כולם.
- `baseUrl` מגדיר גם את ה-origin בכל host אחר: canonical ו-`hreflang` משתמשים ב-`metaBaseUrl` אם הוגדר, אחרת ב-`baseUrl` של locale ברירת המחדל, ולא ב-origin של הבקשה.
- `excludePatterns` מתאימים מקטעים שלמים (`'/admin'` כבר אינו תואם ל-`/administrator`), ה-globs מעוגנים, ותבניות `RegExp` מגיעות כעת ל-runtime.
- `cacheMaxSize` שלא הוגדר פירושו לכל היותר 1000 רשומות בשרת. `cacheTtl` נספר מהרגע שבו רשומה נשמרה, וקריאות כבר אינן מאריכות אותו.
- תחת `no_prefix`, `localeCookie: null` מפורש בתצורת `i18n` נשאר כבוי.
- תחת `prefix_except_default` ו-`prefix_and_default` מתעלמים מ-`defaultLocale` בזמן ריצה עם אזהרה. `fallbackLocale` בזמן ריצה חייב להיות locale מופעל.
- `routeDisableMeta` ב-`nuxt.config` מכובד, ורשומה ב-`nuxt.config` גוברת על `$defineI18nRoute` תחת כל צורת מפתח.
- בשרת בפיתוח, התצורה הפתורה מוקפאת: כתיבה אליה זורקת שגיאה.
- רשומת `locales` של פרויקט גוברת על זו של שכבה עבור אותו `code`.

### Composables ומתודות `$` {#composables-and-$-methods}

- `$switchLocale` נפתר ל-`true` או `false`; בעבר הוא לא נפתר לשום ערך. `$switchRoute` מוגדר כטיפוס `Promise<void>`.
- `$localeRoute`, `$switchLocalePath` וה-switcher מקשרים locale שאינו מגיש עמוד לדף הבית של אותו locale.
- `$localePath` מחזיר מחרוזת עם scheme מסוג `http(s):`, `mailto:` או `tel:` כמות שהיא, ו-`$localeRoute` נושא אותה ב-`path` וב-`fullPath`. אל תעבירו אליהם ערך שלא נבדק כיעד קישור. `//host` ושמות חשופים כמו `x.com` נשארים נתיבים ב-origin הזה.
- קישור ללא נתיב נשאר בעמוד הנוכחי: `$localePath('#top')`, `'?p=2'`, `''` ו-`{ query }`. `'#top'` נקרא בעבר משורש האתר. `'about'` חשוף עדיין פירושו `/about`.
- `$switchRoute` נשאר באפליקציה. רק `baseUrl` של locale עצמו, `mailto:` ו-`tel:` עוזבים אותה.
- קישור ל-locale עם `baseUrl` עובר דרך `$localePath` או `<i18n-link>`. `<NuxtLink :to="$localeRoute(x, 'fr')">` ו-`router.push($localeRoute(x, 'fr'))` נשארים נתיבים של אפליקציה זו. בקוד השתמשו ב-`navigateTo($localePath(x, 'fr'), { external: true })`.
- `$switchLocaleRoute` והפניות עוקבים אחר `trailingSlash`.
- `$setI18nRouteParams` ו-`useI18nHead` שהוגדרו בשרת נזרקים כאשר ניווט משנה את הנתיב, כולל `/news/1` ל-`/news/4`: הגדירו אותם שוב בעמוד החדש.
- `$setI18nRouteParams` שנקרא ב-setup קשור לאותו עמוד: קריאה מאוחרת מעמוד שכבר עזבתם אינה עושה דבר. אין לו setter, לכן החליפו ב-stub את `useI18n` עצמו בבדיקות.
- `useI18n()` מחזיר אובייקט אחד לכל אפליקציה. כתיבה אליו מגיעה לכל הקוראים.
- המילון, ה-locale, ה-params וה-head משתנים כאשר ניווט מבוצע. `beforeResolve`, `beforeRouteEnter` או guard גלובלי מאוחר יותר רואים את הישנים. Route middleware אינו מושפע.
- `$switchLocale` משחזר את ה-locale השמור כאשר הניווט שלו מבוטל, תחת אסטרטגיות ה-URL.
- `$t` מבצע אינטרפולציה ל-`defaultValue`: `$t('missing', { n: 1 }, 'Got {n}')` נותן `Got 1`. כך גם `$tc`, ועל תרגום ריק הוא עונה `''`.
- `$has(key, route)` מכבד את ה-route.
- `$clearCache()` טוען מחדש את המילון של העמוד הנוכחי.
- placeholder מסוג `{param}` קורא רק את ה-params שאתם מעבירים: `{constructor}` נשאר כפי שנכתב.
- `$tc` עם ספירה שלילית, שברית או ענקית לוקח את הצורה האחרונה עם הספירה האמיתית. `{ count: null }` כבר אינו זורק שגיאה, ומפתח רבים חסר מגיע ל-missing handler.
- `$tdr` נותן `Invalid Date` עבור קלט לא תקין. פחות משנייה בעבר הוא `0 seconds ago`.
- `$tn`, `$td` ו-`$tdr` פועלים לפי `iso`: `{ code: 'en', iso: 'en-GB' }` מעצב תאריכים כ-`31/10/2026`. קוד ש-`Intl` אינו מכיר מעוצב כ-`en`, וצורות רבים לפי כלל האינדקס: הגדירו `iso` (`{ code: 'ua', iso: 'uk-UA' }`).
- `detectCurrentLocale` הוצא משימוש: השתמשו ב-`useLocaleServerMiddleware(event).current`.

### צורות רבים {#plurals}

התבניות שומרות על משמעותן, עם חריג אחד. צורת אפס ללא placeholder, ואחריה צורה אחת לכל קטגוריה, עם `{count}` בכל צורה שכמה ספירות חולקות, נקבעת כעת לפי קטגוריה ב-locales עם שלוש קטגוריות או יותר (`ru`, `uk`, `pl`, `cs`, `ar` ואחרים): `none | {count} one | {count} few | {count} many` נותן `3 few` ו-`21 one` ב-`uk`. כדי להשתמש בקטגוריות בכל תבנית אחרת, הוסיפו את הסמן `=0 `. כלל `plural` מותאם אישית קורא את הערך הגולמי, כך שתבנית מסומנת מגיעה אליו עם `=0 ` במקומו. ראו [הטבלה בשדרוג](/he/guide/upgrade#plurals-and-formatting).

### רכיבים {#components}

**`<i18n-t>`**

- `html` מבצע escape ל-`params` בכל מקרה ומתעלם מכל ה-slots.
- slot גובר על param באותו שם.
- `null` פירושו לא מוגדר עבור `plural`, `number`, `date` ו-`relativeDate`.
- `plural` סופר כמו `$tc`, עם `Number`: `1.5` נשאר `1.5`, `"2 items"` הוא `NaN`, `""` הוא `0`.
- `number`, `date` ו-`relativeDate` שומרים על `params`.
- `hideIfEmpty` חל בכל ענף, ו-`defaultValue` מחליף מפתח חסר בכל ענף.
- מפתח חסר תחת `html` הוא טקסט שעבר escape.
- הפלט של `date` ו-`relativeDate` נושא `data-allow-mismatch="text"`, ולצד slot בעל שם הטקסט יושב ב-`<span>` משלו.
- התכונות `.innerHTML` ו-`textContent` נזרקות.
- זהו רכיב פונקציונלי: `ref` עליו אינו נותן מופע.
- `<i18n-t>` ו-`<i18n-group>` קוראים את המילון הפעיל, כמו `$t`.

**`<i18n-switcher>`**

- קישור הוא `<a>` רגיל שקורא ל-`$switchLocale`, כך שה-classes של `router-link-active` נעלמו.
- הכפתור הוא `type="button"` עם `aria-expanded`. Escape ולחיצה מחוץ סוגרים את התפריט הנפתח.
- classes חדשים `i18n-switcher-wrapper`, `i18n-switcher-dropdown` ו-`i18n-switcher-button`. לכל קישור יש `lang`, ו-`dir` כאשר ה-locale מגדיר אותו.
- סגנונות ברירת המחדל משתמשים במאפייני CSS לוגיים, ולתפריט הנפתח יש `z-index` גדול יותר, רוחב מינימלי וצל.
- השרת כותב מחדש את הקישורים שלו כאשר הרינדור מסתיים, בעמודים עם params. קישור `$switchLocalePath` שנכתב ידנית אינו נכתב מחדש.

**`<i18n-link>`**

- `https://`, `mailto:` ו-`tel:` מותאמים בכל רישיות. `report.pdf` חשוף הוא route, ו-`example.com` נשאר חיצוני. סיומת קובץ שהיא גם TLD (`example.md`) נחשבת לקובץ: כתבו `https://`.
- `activeStyle` מתעלם מלוכסן סופי, מה-query ומה-hash.

### Hooks וטיפוסים {#hooks-and-types}

- `i18n:register` הוא hook של runtime: `nuxtApp.hook('i18n:register', …)` ב-plugin.
- שם הטיפוס המיוצא `ModuleHooks` שונה ל-`ModuleRuntimeHooks`.
- `i18n:beforeLocaleSwitch` ו-`i18n:afterLocaleSwitch` מעולם לא נשלחו וכבר אינם מתועדים.
- `ModuleOptionsExtend.isSSG` הוא אופציונלי והוצא משימוש: שום דבר אינו מגדיר אותו.

### כתובות URL והפניות {#urls-and-redirects}

- **`/en` ו-`/en/...` מחזירים 404** תחת `prefix_except_default`, כאשר `en` הוא ברירת המחדל.
- **קידומת locale ברישיות או באיות אחרים מחזירה 404** (`/DE/about`). כך גם `/DE/x` תחת `[...slug]` ו-`/DE` לצד `[slug]`, כך ש-slug של CMS ששווה לקוד locale ברישיות אחרות מאבד את העמוד שלו.
- **URL לא מוכר נשאר 404** עם `autoDetectPath: '*'` או `'no_prefix'`. `prefix` שומר על ההפניה, וכך גם `/` בכל מקום.
- **נתיב מותאם אישית של locale אחר, ללא קידומת,** הוא `302` ל-URL של locale ברירת המחדל תחת `prefix_except_default`. תחת `prefix` ההפניה מגיעה כעת לעמוד חי. `prefix_and_default` נשאר 404.
- **`prefix` עם `redirects: false`** עונה 404 על URL ללא קידומת, כולל ה-URL המקורי של עמוד עם נתיב ברירת מחדל מותאם אישית.
- **`autoDetectPath: '*'`** מחיל את ה-cookie ואת `Accept-Language` גם על נתיבים ללא קידומת.
- **תחת `prefix`** URL ללא קידומת שומר על ה-locale של המבקר, בכל נתיב, לא משנה מה `autoDetectPath` אומר.
- **תחת `prefix_and_default`** URL ללא קידומת הוא locale ברירת המחדל.
- **תחת `no_prefix`** נתיב מותאם אישית מרנדר את ה-locale שלו, עמוד מוגבל מתרנדר ב-locale שהוא מגיש, ו-locales שחולקים נתיב חולקים רשומה אחת.
- **הפניית `routeRules` ללא עמוד** אינה מתורגמת: `/de/old` מחזיר 404, בעבר זה היה 200 ריק.
- **כללי route מגיעים לנתיבים מותאמים אישית,** ומועתקים גם תחת `no_prefix`. אח סטטי כמו `/de/artikel/news` תואם ל-`/de/artikel/:slug`.
- **locale עם `disabled: true`** עונה 404 על הקידומת שלו מיד, וקישורים אליו נשארים בעמוד.
- **נתיב עמוד ברישיות אחרות** הוא `302` לאיות שלו: `/T/BASIC` עובר ל-`/t/basic`.
- **ה-URL המקורי של עמוד עם נתיב ברירת מחדל מותאם אישית** הוא `302` לאותו נתיב תחת `prefix_except_default`. בעבר זה היה 404.
- **`noPrefixRedirect`** פועל לפי ה-locale של המבקר: עם cookie `de`, `/about` עובר ל-`/ueber-uns`, ולא לנתיב של locale ברירת המחדל.
- **הקידומת של host עצמו** מחזירה 404 ב-host שלה מסוג `baseDefault` תחת `prefix_except_default`: `/de/x` ב-host של `de` היה 200.
- **`customRegexMatcher`** כבר אינו מחזיר 404 לעמוד אמיתי שהמקטע הראשון שלו נראה כמו locale.
- **`nuxi generate`** מבצע prerender לכל עמוד סטטי בכל locale שמגיש אותו, אלא אם כלל route מגדיר `prerender: false`: יותר קבצים בפלט. עם `baseUrl`, הריצו אותו פעם אחת לכל דומיין עם `NUXT_I18N_DOMAIN`.
- **הפניה בצד הלקוח שומרת על המצב של הניווט שלה:** `<NuxtLink>` רגיל מוסיף רשומת היסטוריה.
- **שמות routes מתורגמים עקביים.** רק קוד שמקודד בתוכו שמות `localized-…` ב-`router.push({ name })` מושפע: העבירו את השם של העמוד עצמו ל-`$localeRoute`.
- **עמודים ללא שם מ-`extendPages`** מתורגמים ומקבלים שם.
- **תחת `prefix`, קישור לדומיין אחר** שומר על קידומת ה-locale.
- **דף הבית של דומיין** נכתב ללא לוכסן סופי בכל מקום.
- **`?locale=`** נחשב בעמודים רק תחת `no_prefix`. `/about?locale=de` כבר אינו מרנדר גרמנית תחת `lang="en"`.
- **`setLocale('de')` של plugin** ב-`/en/...` כבר אינו טוען את המילון של `de`.

### SEO ופלט HTML {#seo-and-html-output}

- `dir="auto"` כבר אינו ברירת המחדל. שפת RTL מוכרת מקבלת `dir="rtl"`, וכל locale אחר ללא `dir` אינו מקבל תכונה. כדי לשמור על הפלט הישן הגדירו `dir: 'auto'`, במחיר ניתוח בעמודים גדולים. ראו [כיוון טקסט](/he/guide/seo#text-direction).
- `disableMeta` עובד כעת: לעמוד אין `hreflang`, canonical או `og:locale`. `lang` ו-`dir` נשארים.
- `hreflang` מפרט רק את ה-locales שמגישים את העמוד. `x-default` מופיע רק כאשר locale ברירת המחדל מגיש אותו.
- לעמוד שאינו מתורגם אין `hreflang` או `og:locale:alternate`.
- עמודי 404 נושאים `<html lang dir>` ב-locale של ה-URL, וללא canonical או `hreflang`.
- Canonical, `og:url` ו-`hreflang` שומרים על query שברשימה המותרת (`/about?page=2`), גם בשרת.
- Canonical ו-`hreflang` כוללים את `app.baseURL` כאשר ה-origin מגיע מהבקשה.
- לכל עמוד SSR יש `<link rel="preload" as="fetch" crossorigin="anonymous">` עבור קובצי המילון שלו, גם לעמודי 404. אפשרו זאת ב-CSP מחמיר. עם `apiBaseClientHost` ה-host הזה צריך CORS.
- `Vary` מוגדר בכל עמוד תחת `no_prefix`, ובהפניות ה-locale של שאר האסטרטגיות. בדקו את מפתח המטמון של ה-CDN שלכם.
- ה-cookie של ה-locale נכתב רק על ידי עמוד שהוגש.

### זיהוי ושרת {#detection-and-server}

- `Accept-Language` מכבד ערכי `q`, ו-`q=0` מחריג שפה.
- `useLocaleServerMiddleware` ו-`useTranslationServerMiddleware` משתמשים בסדר אחד בכל route (`?locale`, param `[locale]` או קידומת, cookie, כותרת, ברירת מחדל), מכבדים את `localeCookie: null` ואת `autoDetectLanguage: false`, ושומרים במטמון מילון לכל locale.
- cookie של locale פגום מתעלמים ממנו ומשאירים אותו כפי שהוא, במקום להכשיל את ה-SSR.
- מצב hash קורא רק את ה-cookie `hash-locale`. `user-locale=de` בודד כבר אינו נחשב.
- `NUXT_I18N_DEFAULT_LOCALE` ו-`disabledLocales` בזמן ריצה משנים את הניתוב.
- **הפלט של `premerged` השתנה.** `/{apiBaseUrl}/<page>/<locale>/data.json` מכיל רק את מה ששונה מ-`__root/<locale>/data.json`. כל דבר שקורא את הקבצים האלה ישירות חייב למזג את השניים. מילון מלא הוא עדיין קובץ תקין.
- **מילונים עוקבים אחר `app.cdnURL`.** הדפדפן מביא אותם מ-`<cdnURL>/_locales/...`, במקום שבו השתמש ב-`app.baseURL`. ה-CDN חייב להכיל את `_locales/` ולאפשר את ה-origin של האתר שלכם. ראו [App baseURL ו-hosts של payloads](/he/guide/deployment#app-baseurl-and-payload-hosts).
- אין מטמון routes של Nitro על `/{apiBaseUrl}/**`, והכותרת `s-maxage=60, stale-while-revalidate` נעלמה. אם הסתמכתם על המטמון הזה, שימו CDN לפני route ה-payload.
- `/{apiBaseUrl}/<page without a folder>/<locale>/data.json` עונה עם מילון השורש; בעבר זה היה `{}`. 404 של host עובר כעת כ-404, במקום שבו ענה `200 {}`.
- prerender שאינו יכול לטעון את המילון שלו נכשל עם 500 ואזהרה, ועם ברירת המחדל של Nuxt `failOnError` ה-build יוצא עם 1.
- תרגום שהשתנה ללא build מחדש מגיע לדפדפן רק כאשר `v` זז: הגדירו `NUXT_I18N_DATE_BUILD`.
- SSR כבר אינו מבקש את `/{apiBaseUrl}` דרך HTTP, אלא אם `apiBaseServerHost` מוגדר.

### תרגומים {#translations}

- המיזוגים עמוקים בכל רמה, ושרשראות גיבוי נעקבות עד סופן.
- המיזוג פועל לפי locale: קובץ השורש של ה-locale הפעיל גובר על קובץ העמוד של locale גיבוי.
- עמוד ללא תיקיית `pages/<name>/` משלו קורא את מילון השורש ב-production. בעבר הוא קיבל `{}`.
- `disablePageLocales: true` קורא את קובצי השורש בלבד.
- המפתחות של העמוד היוצא מפסיקים להיפתר אחרי ניווט. אם layout השתמש במפתחות שרק בקובץ של העמוד הקודם היו, העבירו אותם לקובץ השורש.
- קובץ locale פגום מזהיר פעם אחת עם הנתיב שלו בכל מצב. בפיתוח הוא זרק שגיאה בעבר.

### חבילות `@i18n-micro/*` {#@i18n-micro/*-packages}

כל חבילות `@i18n-micro/*` נמצאות בגרסה 2.0.0, כולל `@i18n-micro/types` ו-`@i18n-micro/cli` החדשה.

**`@i18n-micro/react`, `preact`, `solid`**

- מתאמי ה-router עברו ל-`/router`: `createReactRouterAdapter`, `createSolidRouterAdapter`, ו-`createBrowserHistoryAdapter` של Preact. `createPreactRouterAdapter` הוסר.
- `I18nT` עוקב אחר `<i18n-t>` לעיל. התכונות `dangerouslySetInnerHTML`, `innerHTML` ו-`textContent` נזרקות.
- `I18nSwitcher` מרנדר פריטי `<a href>` עם `aria-current="page"`, `▾`, CSS לוגי ו-`language-switcher` על הכפתור. ללא `aria-haspopup`. `className` מתווסף ל-`i18n-switcher-wrapper`.
- קישור ל-`/` או לשורש של locale פעיל רק בהתאמה מדויקת (React, Preact).
- `I18nLink` שומר על `onClick` ו-`style` של המשתמש, ומשאיר לחיצה עם מקש שינוי לדפדפן. query ו-hash אינם נחשבים בבדיקת הפעילות. ללא router, אף קישור אינו פעיל.
- React ו-Preact: `I18nLocalesContext`, `I18nDefaultLocaleContext` ו-`I18nRouterContext` הם `I18nConfigContext` אחד. Solid: `I18nContext` אחד מכיל `{ i18n, locales, defaultLocale, router }`.
- `getCurrentPath` של המתאמים כולל את ה-query וה-hash, ומפתח חוזר ב-`getRoute().query` הוא מערך.
- `I18nProvider` מקונן ללא `i18n` שומר על המופע החיצוני, ו-provider ללא מופע כלל זורק שגיאה.
- `defaultLocale()` ללא ערך הוא `fallbackLocale`.
- Solid: `getCurrentPathAccessor` הוסר. `useI18n()` כבר אינו זורק שגיאה ללא `locales`.
- React: `use-sync-external-store` כבר אינו תלות, ו-`react-dom` הוא peer אופציונלי.

**`@i18n-micro/vue`, `vitepress`**

- `I18nT` הוא רכיב פונקציונלי.
- `I18nSwitcher` ו-`I18nLink` עוקבים אחר הסעיפים לעיל. `aria-haspopup` נעלם.
- `I18nLink` ו-`createVueRouterAdapter` פותרים את `name`, `query` ו-`hash`. `name` לא מוכר זורק שגיאה, כמו `RouterLink`.
- `useLocaleHead` כבר אינו בונה `//de/`. ה-canonical וה-`hreflang` של עמוד אחד מסכימים (`/de`), ופרמטרי query שברשימה המותרת מגיעים אליהם.
- `I18nRoutingStrategy.resolvePath` עשוי לקבל אובייקט מיקום ונתיב עם query ו-hash. `toHref` אופציונלי חדש.
- VitePress: קישורים, ה-switcher, `push` ו-`replace` נושאים את `site.base`.

**`@i18n-micro/astro`**

- `i18nIntegration` אורז את `translationDir` ומתקין את ה-middleware: מחקו `src/middleware.ts` שרק מעתיק את ההגדרה, או העבירו `middleware: false`. `src/middleware.ts` משלכם מעביר `base: config.base`.
- `i18nIntegration` זורק שגיאה על `messages`, `plural`, `missingHandler` ו-`routingStrategy`: העבירו אותם ל-`createI18n` או ל-`createI18nMiddleware`, עם `middleware: false`. אפשרויות שמעולם לא עשו דבר הוסרו מהטיפוס שלו.
- `loadTranslationsFromDir` ו-`loadTranslationsIntoI18n` עברו ל-`@i18n-micro/astro/node`, שהוא ESM בלבד.
- `getGlobalRoutingStrategy`, `setGlobalRoutingStrategy` ו-`runWithRoutingStrategy` הוסרו: קראו את `Astro.locals.routingStrategy`.
- `clone()` הוא `fork()`, והאפשרות `_storage` נעלמה.
- עמודים דינמיים הם route אחד: `/blog/hello` הוא `blog-slug`, בעבר `blog-hello`. העבירו את `pages/blog-hello/` ל-`pages/blog-slug/`. `getRouteName` מותאם אישית מקבל את התבנית כארגומנט שלישי.
- ה-URL קובע את ה-locale של העמוד. `autoDetect` הוא 302 מ-`/` לדף הבית של ה-locale המועדף. אפשרות `localeCookie` חדשה, ו-`redirectToDefault` מומש.
- צפייה בעמוד מעמוד באותו origin של locale אחר כותבת את ה-cookie של ה-locale ואינה מפנה. Server islands ו-actions לעולם אינם מפנים ונושאים `Vary: Referer`.
- `config.localeCodes` משמיט locales מושבתים, ו-`prepareLocaleRewrite` עונה 404 עבורם.
- `getI18nProps()` ללא מפתחות שולח את כל מה ש-`t()` יכול לענות בעמוד, עם אזהרת פיתוח מעל 20 KB. העבירו את המפתחות שה-island משתמש בהם.
- `useLocaleHead`: ברירת המחדל של `baseUrl` היא `site`, אחרת יחסית לשורש. קישורים ו-metas נושאים `id`.
- `<I18nT html>` מבצע escape ל-`params`, ותרגום ריק מתרנדר ריק.
- `<I18nLink>` ו-`localizePath` משאירים כתובות URL חיצוניות, `#hash` ו-`?query` כפי שהם ושומרים על לוכסן סופי.
- `<I18nSwitcher>` שומר על ה-query ומשתמש ב-`data-i18n-switcher` במקום ids שנוצרו.
- ל-`@i18n-micro/astro/client` יש רק `translate` ו-`hasTranslation`: ייבאו מתאמים מ-`/client/vue`, `/client/react`, `/client/preact` ו-`/client/svelte`. `client/vue` דורש ש-`vue` יהיה מותקן.
- Islands: `has()` הוא true עבור תת-עץ, `t('')` הוא `''`. `provideI18n` מקבל getter כדי לעקוב אחר props חדשים.
- `getLocale` ו-`getDefaultLocale` זורקים שגיאה ללא ה-middleware.

**`@i18n-micro/runtime`, `node`**

- כתיבה ל-locale שאינו פעיל ואינו גיבוי אינה מודיעה למנויים.
- `addRouteTranslations(locale, route, messages, false)` מחליף את ה-chunk.
- `loadFromUrls` מביא במקביל ואינו כותב דבר אם אחד נכשל.
- Node: `reload()` מחליף מילונים במקום לרוקן אותם קודם, ואינו רושם הודעת הצלחה. תיקייה שנעלמה שומרת על הישנים.
- Node, Astro, VitePress: קורא אחד של תיקיית locales. תיקייה חסרה מזהירה, קובץ שאינו אובייקט JSON מדווח ומדולג, והודעות מתחילות ב-`[i18n]`.

**`@i18n-micro/test-utils`**

- ה-mock עוקב אחר כללי התרגום האמיתיים: `tc('a', 1.5)` לוקח את הצורה האחרונה, `td('nope')` הוא `Invalid Date`, `t(miss, undefined, '')` הוא המפתח, והחטאה כבר אינה נרשמת ביומן.
- `isolated` הוסר מ-`createI18nTestContext`, ו-`./publish-smoke` הוסר.

**`@i18n-micro/types-generator`**

- `I18nTypesPlugin(options)` הוא plugin פשוט של Vite ו-Rollup: ללא `.vite()`, `.webpack()` או `.esbuild()`. עבור webpack או esbuild, קראו ל-`generateTypes` בסקריפט.
- `getTypesString` ו-`generateTypes` סינכרוניים. `flattenKeys` ו-`isPlainTranslationObject` הוסרו.
- המפתחות הם מה ש-`t()` קורא: נתיבי אובייקטים נוספים, וקבצים מחוץ למבנה ה-locale נזרקים.

**`@i18n-micro/devtools-ui`**

- השמירה מקבלת רק `.json` קיים בתוך `translationDir`, וכבר אינה יוצרת קבצים. בקשה חוצת אתרים היא 403.
- שמירה שנכשלה ל-endpoint נגיש זורקת שגיאה ומבצעת rollback.
- `createBridge` מקבל אפשרות `base`. Astro משתמש ב-`i18nDevToolsIntegration`.

**`@i18n-micro/utils`, `core`, `path-strategy`, `route-strategy`**

עבור מתאמים מותאמים אישית וכלים בלבד.

- `utils`: ה-subpaths `./route`, `./route-pattern`, `./build`, `./payload-stats` ו-`./payload-config` הוסרו, יחד עם `resolveServerLocale` ו-`resolvePreferredLocale`: קראו ל-`resolveLocale`. `deepMergeTranslations` ו-`mergeRouteTranslationsWithRoot` נעלמו: השתמשו ב-`deepMergeTranslationsRecursive`.
- `core`: `TranslationHelper` משמיט את `setCache`, `getGeneration` ו-`lookupIn` (השתמשו ב-`lookup(chunkKey, key)`). `BaseI18n` משמיט את `ensurePinnedChunk` ו-`invalidatePin`. `useTranslationHelper(storage)` נעלם: השתמשו ב-`new TranslationHelper(storage)`.
- `path-strategy`: **`switchLocaleRoute(fromLocale, toLocale, route, options)` הוא כעת `switchLocaleRoute(toLocale, route, options)`. קריאת JavaScript ישנה מחזירה תוצאה שגויה ללא שגיאה.** `$switchLocaleRoute` של Nuxt אינו מושפע. נקודות הכניסה `/prefix`, `/no-prefix`, `/prefix-except-default` ו-`/prefix-and-default` נעלמו, וכך גם `getRedirect` ו-`getCanonicalPath`. `RouterAdapter` דורש `getRoutes`. `createPathStrategy` אינו בונה כתובות URL מוחלטות: השתמשו ב-`new DomainPathStrategy(ctx)` כאשר ל-locales יש `baseUrl`.
- `route-strategy`: רק `RouteGenerator`, `generateRoutes`, `Rules` ופונקציות העזר לנתיבים מיוצאים.

## הגירה {#migration}

1. בדקו את הדרישות: Nuxt 3.18, Node 20, ו-React 18 אם אתם משתמשים ב-`@i18n-micro/react`.
2. עדכנו את `nuxt-i18n-micro` ואת כל חבילות `@i18n-micro/*` יחד. הסירו את `@i18n-micro/hmr`. הוסיפו את `@i18n-micro/test-utils` כתלות פיתוח אם הבדיקות שלכם מייבאות אותו. החליפו את `nuxt-i18n-micro-cli` ב-`@i18n-micro/cli` ועקבו אחר [טבלת הפקודות שלו](/he/guide/cli#moving-from-nuxt-i18n-micro-cli).
3. חפשו בקוד שלכם `switchLocaleRoute(` מתוך `@i18n-micro/path-strategy`, `i18n-plugin-hooks`, `i18n-plugin-define`, שמות routes מסוג `localized-`, `$getI18nConfig().globalLocaleRoutes` ושאר מפתחות התצורה שהוסרו, `ModuleHooks`, ו-`@ts-expect-error` על `i18n:register`.
4. העבירו markup מתוך params של `<i18n-t html>` לתוך התרגום, והעבירו נתונים כ-params.
5. אם הגדרתם `baseUrl`: בדקו קישורים שנבנו עם `$localeRoute`, הגדירו `trustForwardedHost` מאחורי proxy, והריצו `nuxi generate` פעם אחת לכל דומיין עם `NUXT_I18N_DOMAIN`.
6. בדקו את כתובות ה-URL שלכם מול האסטרטגיה שלכם: `/en` תחת `prefix_except_default`, slugs של CMS שנראים כמו locale, הפניות `routeRules`, ו-`excludePatterns`.
7. בדקו את מפתח המטמון של ה-CDN שלכם עבור `Vary`, ואפשרו את קישור ה-preload ב-CSP מחמיר. עם `app.cdnURL`, שימו את `_locales/` ב-CDN ואפשרו CORS.
8. אם כלי קורא קובצי `/_locales/...` ישירות, מזגו את קובץ העמוד מעל `__root/<locale>/data.json`.
9. אם guard גלובלי קורא את ה-locale או המילון, ודאו שהוא יכול לרוץ לפני שהניווט מבוצע. העבירו מפתחות ש-layout לקח מהקובץ של העמוד הקודם לקובץ השורש.
10. השוו פלט של `nuxi generate` או סריקת sitemap לפני ואחרי: `hreflang`, `x-default`, canonical ורשימת העמודים משתנים במכוון.
11. עדכנו imports עבור חבילות frameworks: `/router` עבור מתאמי React, Solid ו-Preact, `/node` עבור ה-loaders של Astro, ו-`I18nTypesPlugin(o)` עבור plugin הטיפוסים.
12. עבור Astro, מחקו `src/middleware.ts` שרק מעתיק את ההגדרה, ושנו את שמות המילונים בסגנון `pages/blog-hello/` לתבנית שלהם.
13. עדכנו בדיקות שקיבעו את `router-link-active`, `li button`, `▼`, או התנהגות mock ישנה.

פרטים וכל מקרה קצה: [שדרוג](/he/guide/upgrade).

## למה זה חשוב {#why-it-matters}

- **נכון מעצם המבנה:** קישורים, הפניות ותגיות SEO מגיעים מה-routes שיש לאפליקציה בפועל.
- **תשובה אחת בכל מקום:** build, מצב source ופיתוח נותנים את אותו המילון, וכל קורא משתמש בסדר זיהוי אחד.
- **דומיינים:** פריסה אחת לכל דומייני ה-locale, ללא build שני.
- **ברירות מחדל בטוחות יותר:** params שעברו escape, מטמונים מוגבלים, קישורים שנשארים ב-origin שלכם.
- **פחות לשלוח:** קובצי מילון קטנים יותר, חבילות ניתוב קטנות יותר, ולוגיקה משותפת במקום אחד.

לרשימה המלאה של השינויים, ראו [שדרוג](/he/guide/upgrade) ואת [יומן השינויים](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
