description: "הגבילו דף לחלק מה-locales, תנו לו נתיבים מותאמים, תרגומים מוטמעים או ביטול תגיות SEO עם $defineI18nRoute."
---

`$defineI18nRoute` מגדיר אפשרויות i18n עבור דף אחד מתוך הדף עצמו. השתמשו בו כאשר דף קיים רק בחלק מה-locales, זקוק לנתיב מותאם locale משלו, נושא כמה תרגומים משלו, או שאסור שיקבל תגיות hreflang/canonical. המודול קורא את הקריאה בזמן הבנייה וצורב אותה לתוך הנתיבים שנוצרים.

## הגבלת דף לחלק מה-locales {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

תחת אסטרטגיית ברירת המחדל `prefix_except_default` נוצרים רק `/product` ו-`/de/product`; לדף אין נתיב בשום locale אחר. ניתן להגדיר את אותו הדבר מתוך `nuxt.config.ts` עם [`routeLocales`](/he/api/module-options#routelocales).

`$defineI18nRoute` הוא הזרקה של אפליקציית Nuxt, לא מאקרו של קומפיילר: קחו אותו תמיד מ-`useNuxtApp()` וקראו לו עם ה-`$`. שלב הבנייה מזהה רק את `$defineI18nRoute(`.

## הוספת תרגומים מוטמעים {#add-inline-translations}

העבירו אובייקט במקום מערך. המפתחות שלו הם ה-locales המותרים, והערכים שלו ממוזגים לתוך המילון של הדף עבור ה-locale הפעיל.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

תרגומים מוטמעים נשלחים בתוך רכיב הדף עבור כל locale. העדיפו [קבצי תרגום של דפים](/he/guide/translations) לכל דבר גדול מכמה מפתחות; שמרו מפתחות מוטמעים לדפים ורכיבים עצמאיים.

## הגדרת נתיבים מותאמי locale {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

עם `prefix_except_default` ו-`defaultLocale: 'en'` זה מפיק את `/welcome` ואת `/de/willkommen`. `path` בתוך אובייקט locale מוטמע עושה את אותו הדבר: `locales: { de: { path: '/willkommen' } }`. פרמטרים דינמיים, נתיבים מקוננים והחלופה ברמת ההגדרות מוסברים ב[נתיבים מותאמי locale](/he/guide/custom-locale-routes).

## ביטול תגיות SEO {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

החלופה ברמת ההגדרות היא [`routeDisableMeta`](/he/api/module-options#routedisablemeta). הסבר על התגיות נמצא בדף [SEO](/he/guide/seo).

## מה הבנייה יכולה לקרוא {#what-the-build-can-read}

שלב הבנייה מוצא את הקריאה בכל קובץ דף ומעריך את הארגומנט שלה בלי להריץ את האפליקציה שלכם. זה עובד כאשר ההגדרה היא:

- אובייקט ליטרלי (מחרוזות, מערכים, אובייקטים מקוננים, template literals, אופרטורים טרנריים על `process.env.NODE_ENV`);
- בנויה מקבועים שהוצהרו באותו `<script setup>` (`const locales = ['en', 'de']`, כולל פריסות);
- מערך של אובייקטים עם שדה `code` (`[{ code: 'en' }, { code: 'de' }]`).

היא אינה יכולה לקרוא ערכים המיובאים ממודול אחר, או כל דבר שדורש את האפליקציה שלכם בזמן ריצה (composables, `await`, נתונים שנטענו). במקרה כזה הבנייה רושמת ביומן `Ignored the $defineI18nRoute() config in <file>` והדף שומר על ה-locales והנתיבים של ברירת המחדל.

בזמן ריצה הקריאה רק ממזגת את התרגומים המוטמעים עבור ה-locale הנוכחי וממזגת אותם מחדש כאשר ה-locale משתנה. `locales`, `localeRoutes` ו-`disableMeta` נכנסים לתוקף רק דרך הבנייה, ולכן שינוי שלהם מחייב בנייה מחדש (שרת הפיתוח בונה מחדש בעת שמירה).
