הזיהוי המובנה קורא את כתובת ה-URL, עוגייה ו-`Accept-Language`. כאשר השפה תלויה במשהו אחר — הדומיין, header גיאוגרפי שה-CDN שלכם מגדיר, פרופיל משתמש — הגדירו אותה בעצמכם בפלאגין שרץ לפני פלאגין ה-i18n. המודול טוען אז את התרגומים של אותה שפה ומשתמש בה להפניות בדיוק כאילו זיהה אותה בעצמו. הכללים שקובעים מתי שפה שנבחרה גוברת על ה-URL מופיעים ב-[זיהוי שפה](/he/guide/locale-detection); עמוד זה מראה כיצד לחבר מקור משלכם.

## הגדרת השפה בפלאגין שרת {#set-the-locale-in-a-server-plugin}

```ts
// plugins/i18n-locale.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10, // before the i18n plugin (order -5)
  setup() {
    const { setLocale } = useI18nLocale()
    const host = (useRequestHeaders(['host']).host ?? '').split(':')[0]! // without the port

    if (host.endsWith('.de')) setLocale('de')
    else if (host.endsWith('.fr')) setLocale('fr')
  },
})
```

`setLocale(code)` כותב את מצב השפה (`useState('i18n-locale')`) וגם, כאשר מוגדרת עוגיית שפה, את העוגייה. השתמשו בו במקום לכתוב בעצמכם ל-`useState` או ל-`useCookie`. העבירו רק קודי שפות פעילות.

השאירו את הפלאגין כ-`.server.ts` כאשר הוא קורא headers של הבקשה: הם לא קיימים בדפדפן. פלאגין `.client.ts` הוא המקום למקורות שקיימים רק בדפדפן, כמו `localStorage`.

## כיבוי שלב ה-Accept-Language המובנה {#turn-off-the-built-in-accept-language-step}

הפלאגין שלכם ו-`Accept-Language` עשויים לא להסכים. כדי לתת רק לקוד שלכם (יחד עם ה-URL והעוגייה) להחליט, כבו את ה-header:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    autoDetectLanguage: false,
  },
})
```

[`autoDetectLanguage`](/he/api/module-options#autodetectlanguage) שולט רק בשלב ה-header. ה-URL ועוגייה תקפה עדיין נלקחים בחשבון.

## מה קורה אחר כך {#what-happens-next}

ההשפעה של `setLocale` תלויה ב-[אסטרטגיה](/he/guide/strategy):

| אסטרטגיה | ההשפעה של `setLocale('de')` בפלאגין |
| --- | --- |
| `no_prefix` | העמוד מוצג בגרמנית; ה-URL לא משתנה. |
| `prefix`, `prefix_except_default` | בנתיב ללא קידומת שבו [`autoDetectPath`](/he/api/module-options#autodetectpath) מאפשר הפניות (כברירת מחדל רק `/`), השרת עונה `302` לכתובת הגרמנית. כתובת URL עם קידומת שפה שומרת עליה. |
| `prefix_and_default` | אין הפניה: ה-URL ללא קידומת הוא עמוד תקף בשפת ברירת המחדל. |

תחת אסטרטגיות הקידומת, שפה ב-URL היא בחירת המשתמש והפלאגין שלכם אינו דורס אותה. `autoDetectPath: '*'` הוא היוצא מן הכלל: השרת מעביר אז כתובות עם קידומת לפי העוגייה ו-`Accept-Language` ומתעלם מהמצב, אבל `setLocale()` כותב גם את העוגייה כאשר היא מוגדרת, כך שמהבקשה הבאה הבחירה של הפלאגין שלכם יכולה להפנות כתובת עם קידומת. השאירו `'/'` או השתמשו ב-`'no_prefix'` כאשר כתובות שפה מפורשות חייבות לגבור. השתמשו בפלאגין כדי לבחור לאן מבקר מגיע, לא כדי לשכתב קישורים שהוא עקב אחריהם.

## כיבוד שפה שהמשתמש בחר {#respect-a-locale-the-user-picked}

ברגע שמשתמש מחליף שפה, ההחלפה כותבת את העוגייה. דלגו על הזיהוי שלכם כאשר כבר קיימת העדפה תקפה:

```ts
// plugins/i18n-locale.server.ts
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10,
  setup() {
    const { getPreferredLocale, setLocale, validLocales } = useI18nLocale()
    if (getPreferredLocale()) return // valid state or cookie: keep it

    const country = useRequestHeaders(['x-country'])['x-country']
    if (country === 'JP') return setLocale('ja')

    const header = useRequestHeaders(['accept-language'])['accept-language']
    setLocale(detectLocaleFromAcceptLanguage(header, validLocales))
  },
})
```

`getPreferredLocale()` מחזיר את המצב או את העוגייה רק כאשר מדובר בשפה פעילה, כך שעוגייה מיושנת אינה עוצרת את הזיהוי. `detectLocaleFromAcceptLanguage` הוא המתאם שמתחשב בערכי q, שבו המודול עצמו משתמש (התקינו את `@i18n-micro/utils` כדי לייבא אותו); ‏`setLocale(null)` אינו עושה דבר.

## דומיין אחד לכל שפה {#one-domain-per-locale}

אם כל דומיין צריך להגיש את השפות שלו, אין צורך בפלאגין: תנו לכל שפה `baseUrl`, הגדירו `baseDefault: true` בשפת ברירת המחדל של כל דומיין, ובנו פעם אחת (אתר סטטי עדיין מריץ `nuxi generate` לכל דומיין). ראו [שכבות ודומיינים](/he/guide/layers#multiple-domains).
