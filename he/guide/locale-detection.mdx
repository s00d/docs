כל בקשה מקבלת locale אחד, הנבחר מאותה רשימת מקורות באותו סדר בשרת ובדפדפן. קראו זאת כאשר אתם מחליטים באיזו שפה מבקרים חדשים נוחתים, אם הבחירה שלהם נזכרת, ומה ה-API של השרת שלכם רואה. תקבלו את סדר הקדימות, ההפניה שכל אסטרטגיה מבצעת, והאפשרויות שמפעילות או מכבות כל מקור.

<Tip>

**דרישות מוקדמות** — [אסטרטגיות ניתוב](/he/guide/strategy)

</Tip>

## סדר הקדימות {#the-precedence}

המקור הראשון שמציין locale **מופעל** מנצח. ערך לא חוקי או פגום (קוד לא מוכר, עוגייה שבורה) מדולג והמקור הבא נספר.

| # | מקור | נספר כאשר |
| --- | --- | --- |
| 1 | קידומת URL (`/de/about`) | אסטרטגיות קידומת. תחת `prefix_except_default` ו-`prefix_and_default` כתובת URL ללא קידומת היא ה-locale של ברירת המחדל |
| 2 | `?locale=de` | דפים: רק `no_prefix`. פונקציות העזר של API בשרת: תמיד, ולפני ה-URL |
| 3 | מצב locale שהוגדר על ידי האפליקציה (`useI18nLocale().setLocale()`) | ב-URL אין locale |
| 4 | עוגייה | [`localeCookie`](/he/api/module-options#localecookie) מוגדר (`'user-locale'` אוטומטית תחת `no_prefix`) |
| 5 | כותרת `Accept-Language` | [`autoDetectLanguage`](/he/api/module-options#autodetectlanguage) הוא `true` (ברירת מחדל) |
| 6 | [`defaultLocale`](/he/api/module-options#defaultlocale) | תמיד |

לכן תחת אסטרטגיית קידומת ה-URL קובע מה הדף מציג; מקורות ההעדפה (3–5) קובעים רק לאן מבקר **מופנה**, ורק בנתיבים ש-`autoDetectPath` מתיר. תחת `no_prefix` אין מה להפנות, ומקורות ההעדפה קובעים מה הדף מציג.

![תרשים החלטה: קידומת locale ב-URL מרנדרת את אותו locale. בלעדיה, no_prefix מרנדר לפי מקורות ההעדפה, prefix_and_default מרנדר את ה-locale של ברירת המחדל, ו-prefix או prefix_except_default מפנים לפי ההעדפה כאשר autoDetectPath מתיר את הנתיב](/images/diagrams/locale-detection.svg)

## הפניות לפי אסטרטגיה {#redirects-per-strategy}

הפניות הן `302`, מתבצעות בשרת לפני שהדף מרונדר, ועל ידי route middleware בניווטים בצד הלקוח. ה-query וה-hash נשמרים. עם [`redirects: false`](/he/api/module-options#redirects) אף הפניה אינה מתבצעת; קידומות שגויות עדיין מחזירות 404.

המבקר מעדיף `de` (עוגייה או כותרת), `defaultLocale: 'en'`, ברירת המחדל `autoDetectPath: '/'`:

| בקשה | `prefix_except_default` | `prefix` | `prefix_and_default` | `no_prefix` |
| --- | --- | --- | --- | --- |
| `/` | → `/de` | → `/de` | `/` ב-`en` | `/` ב-`de` |
| `/about` | `/about` ב-`en` | → `/de/about` | `/about` ב-`en` | `/about` ב-`de` |
| `/fr/about` | `/fr/about` | `/fr/about` | `/fr/about` | — |
| `/en/about` | 404 | `/en/about` | `/en/about` | — |

`prefix_and_default` לעולם אינו מפנה: כתובת URL ללא קידומת שייכת ל-locale של ברירת המחדל, ו-locales אחרים נמצאים תחת הקידומת שלהם. מבקר שמעדיף `en` אינו מופנה מ-`/` תחת `prefix_except_default`. ליעדים אין לוכסן סופי (`/de`, לא `/de/`) והם עוקבים אחר נתיבים מותאמים (`/about` → `/de/ueber-uns`).

בכל מקום שבו העוגייה או הכותרת קובעות (ההפניה מ-`/`, כל דף תחת `no_prefix`), התגובה נושאת `Vary: Cookie, Accept-Language`, כך ש-CDN שומר את התשובות בנפרד.

### `autoDetectPath` {#autodetectpath}

לאן מקורות ההעדפה רשאים להעביר מבקר:

| ערך | ההעדפה נספרת ב- |
| --- | --- |
| `'/'` (ברירת מחדל) | `/` בלבד. קישורים עמוקים נשארים בשפת ה-URL |
| `'no_prefix'` | כל נתיב ללא קידומת locale (`/about` → `/de/about`) |
| `'/welcome'` | הנתיב המדויק הזה (לוכסן סופי מתעלם) |
| `'*'` | כל נתיב, כולל נתיבים עם קידומת: `/about` ו-`/fr/about` → `/de/about` כאשר המבקר מעדיף `de` |

- בנתיבים שהוא אינו מתיר, כתובת URL ללא קידומת מטופלת כ-locale של ברירת המחדל.
- `prefix` הוא החריג: אין לו דפים ללא קידומת, ולכן `/about` תמיד הולך ל-locale של המבקר (`/de/about` עם עוגייה `de`, `/en/about` ללא העדפה).
- עם `'*'` השרת מתעלם מה-state של האפליקציה, ו-URL עם קידומת כבר אינו רושם את ה-locale שלו בעוגייה; העוגייה משתנה כאשר המבקר מחליף עם `$switchLocale`.

<Warning>

עם `'*'`, קישורים משותפים נפתחים בשפת הקורא, מה שעלול להפתיע. העדיפו `'/'` או `'no_prefix'` אלא אם זה מה שאתם רוצים.

</Warning>

## Accept-Language {#accept-language}

הכותרת נקראת כפי ש-RFC 9110 מגדיר אותה ומותאמת מול **קודי** ה-locale בהגדרות שלכם:

- הרשומות נבדקות לפי ערך `q`, מהגבוה לנמוך (`fr;q=0.1, de;q=0.9` → `de`). `q=0` פירושו "לא השפה הזו"; רשומה עם `q` פגום מתעלמת. `*` אינו מתאים לשום דבר.
- `_` נקרא כ-`-` (`en_US` = `en-US`).
- לכל רשומה: הקוד המדויק, אחר כך צורות קצרות יותר (`de-AT` → `de`), ואז locale אזורי של אותה שפה (`en` → `en-US`). צורות מדויקות וקצרות אינן תלויות בסדר של `locales`; מבין כמה התאמות אזוריות, הראשונה ב-`locales` מנצחת.
- כתבים לעולם אינם מוחלפים: `zh-TW` ו-`zh-HK` מרמזים על סינית מסורתית, `zh-CN` על מפושטת, ולכן `zh-CN` לעולם אינו מתאים ל-locale `zh-Hant`.
- Locales מושבתים לעולם אינם מתאימים.

```ts
// locales: [{ code: 'en' }, { code: 'de' }, { code: 'zh-Hant' }]
// 'de-CH,de;q=0.9,en;q=0.8'  → 'de'
// 'en-GB'                    → 'en'
// 'zh-TW'                    → 'zh-Hant'
// 'zh-CN'                    → no match, next source
```

כבו את הזיהוי לפי כותרת עם `autoDetectLanguage: false`; העוגייה וה-state עדיין נספרים.

## העוגייה {#the-cookie}

- **כבויה כברירת מחדל** באסטרטגיות הקידומת (`localeCookie: null`). אז ההפניות פועלות לפי הכותרת בלבד, והבחירה אינה נזכרת בין ביקורים. הגדירו `localeCookie: 'user-locale'` כדי לזכור אותה.
- תחת `no_prefix` היא `'user-locale'` אלא אם תגדירו שם אחר. `localeCookie: null` מכבה אותה גם שם.
- היא נכתבת כאשר המבקר מחליף (`$switchLocale`, `<i18n-switcher>`, `useI18nLocale().setLocale()`), ובעת רינדור בשרת של דף תחת קידומת (`/fr/about` שומר `fr`; לא תחת `autoDetectPath: '*'` עם הפניות מופעלות, שבו ה-URL עדיין יכול לזוז). ניווט בצד הלקוח לדף שומר גם את ה-locale של אותו דף, גם בדף ללא קידומת של ה-locale של ברירת המחדל; טעינה ראשונה של אותו URL אינה שומרת. תחת `no_prefix` ובמצב hash ניווט שומר רק שינוי. 404 אינו שומר דבר, אלא אם `$switchLocale` נוחת עליו.
- היא נשמרת שנה אחת (`path=/`, `SameSite=Lax`).
- תחת `hashMode` ההעדפה נשמרת במקום זאת בעוגייה `hash-locale`; השרת והלקוח קוראים את אותה עוגייה. השרת מרנדר את אותו locale ומחוץ ל-`prefix` לעולם אינו מפנה; locale ב-hash (`/#/de`) גובר עליה ומוחל מיד לאחר ה-hydration. תחת `prefix` אין דף ב-`/`, ולכן `/` מרונדר בדפדפן, שעובר אל `/#/de` לפי העוגייה, ואז לפי שפת הדפדפן (`autoDetectLanguage`); כל מסמך אחר (`/about`, `/de`) מפנה לתוך ה-hash.

קראו והגדירו את ההעדפה עם [`useI18nLocale`](/he/composables/useI18nLocale), לא עם `useCookie` או `useState` ישירות.

## זיהוי משלכם {#your-own-detection}

כדי לבחור את ה-locale בעצמכם (הגדרת משתמש, תת-דומיין), קראו ל-`useI18nLocale().setLocale(code)` בפלאגין שרץ לפני הפלאגין של המודול. הוא הופך למקור 3, ה-state של האפליקציה. ב[זיהוי locale מותאם אישית](/he/guide/custom-auto-detect) יש את המתכון המלא, כולל כיבוי הזיהוי המובנה.

## נתיבי API בשרת {#server-api-routes}

[`useLocaleServerMiddleware`](/he/guide/server-side-translations) ו-`useTranslationServerMiddleware` משתמשים בסדר משלהם, מכיוון ש-URL של API מותאם locale לעיתים רחוקות:

1. `?locale=`
2. פרמטר נתיב `[locale]`, או קידומת locale בנתיב
3. עוגייה (כאשר `localeCookie` מוגדר)
4. `Accept-Language` (כאשר `autoDetectLanguage` מופעל)
5. `defaultLocale`

`localeCookie: null` ו-`autoDetectLanguage: false` מכבים את מקורות 3 ו-4 גם כאן.

## דריסות בזמן ריצה {#runtime-overrides}

[דריסות בזמן ריצה](/he/guide/runtime-overrides) משנות את הרשימה שמולה מותאמים המקורות:

- `disabledLocales` בזמן ריצה מוסרים מכל שלב: עוגייה או כותרת שמציינת אחד מהם מדולגת.
- `defaultLocale` בזמן ריצה הוא שלב 6 תחת `prefix` ו-`no_prefix`.
- תחת `prefix_except_default` ו-`prefix_and_default` ה-locale של ברירת המחדל נקבע בזמן הבנייה (הדפים שלו הם הנתיבים ללא קידומת). `defaultLocale` בזמן ריצה, או השבתת ברירת המחדל של הבנייה, מתעלמים עם אזהרה.
