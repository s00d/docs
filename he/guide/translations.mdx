תרגומים הם קובצי JSON פשוטים: קובץ שורש אחד לכל locale עבור מפתחות משותפים, וקובץ אחד לכל עמוד ו-locale עבור המפתחות של אותו עמוד. קראו זאת כשאתם מוסיפים עמודים, משתפים מפתחות ביניהם או מגדירים fallbacks. תלמדו לאיזה קובץ מפתח צריך להיכנס, מה עמוד יכול לראות, ומתי כל קובץ נטען.

## מבנה {#layout}

```text
locales/
├── en.json                 # root: menus, footer, buttons
├── de.json
└── pages/
    ├── index/              # pages/index.vue
    │   ├── en.json
    │   └── de.json
    ├── about/              # pages/about.vue
    │   ├── en.json
    │   └── de.json
    └── products-id/        # pages/products/[id].vue
        ├── en.json
        └── de.json
```

- התיקייה תחת `locales/pages/` היא **שם הנתיב** של העמוד ב-Nuxt: ‏`pages/products/[id].vue` הוא `products-id`, ‏`pages/blog/[slug]/comments.vue` הוא `blog-slug-comments`.
- מפתחות יכולים להיות מקוננים לכל עומק; `$t('auth.form.login')` קורא את `{ "auth": { "form": { "login": … } } }`.
- `translationDir` מעביר את התיקייה (`'locales'` כברירת מחדל, יחסית לשורש הפרויקט, גם תחת מבנה `app/` של Nuxt 4).
- קבצים חסרים נוצרים כ-`{}` כש-Nuxt מפענח את העמודים, אלא אם [`disableWatcher`](/he/api/module-options#disablewatcher) מוגדר.

## מה עמוד רואה {#what-a-page-sees}

![Lookup order for a key on /about in de: pages/about/de.json, de.json, pages/about/en.json, en.json. They merge into one about/de/data.json that $t reads](/images/diagrams/page-dictionary.svg)

המילון של עמוד הוא קובץ השורש שלו ממוזג עם קובץ העמוד שלו, באופן עמוק (בכל רמה). קובץ העמוד גובר בהתנגשות:

```json
// locales/en.json
{ "title": "My shop", "nav": { "home": "Home", "cart": "Cart" } }
```

```json
// locales/pages/about/en.json
{ "title": "About us", "nav": { "cart": "Basket" } }
```

```ts
// on /about
t('title') // 'About us'
t('nav.home') // 'Home'   (root)
t('nav.cart') // 'Basket' (page wins)
// on any other page
t('title') // 'My shop'
```

עמוד ללא תיקייה משלו מקבל את מילון השורש בלבד. מפתחות של עמודים אחרים אינם גלויים.

### locales של fallback {#fallback-locales}

מפתח שחסר ב-locale הפעיל נלקח מה-locale של ה-fallback שלו לפני שהמפתח עצמו מוצג:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'de-at', iso: 'de-AT', fallbackLocale: 'de' },
    ],
    defaultLocale: 'en',
    fallbackLocale: 'en', // global, for every locale
  },
})
```

- ה-`fallbackLocale` של locale נעקב עד סופו: `de-at` → `de` → `en`.
- ה-`fallbackLocale` הגלובלי הוא השכבה החלשה ביותר, מתחת לכל שרשרת.
- כל locale בשרשרת מוסיף את קובץ השורש שלו ואז את קובץ העמוד שלו, מה-fallback החלש ביותר ועד ל-locale הפעיל. כך קובץ השורש של ה-locale הפעיל גובר על קובץ העמוד של locale ה-fallback.

ללא fallback, מפתח חסר מתרנדר כמפתח עצמו (`'nav.home'`) ורושם אזהרה בקונסולת הדפדפן בפיתוח ([`missingWarn`](/he/api/module-options#missingwarn)).

## שיתוף ומקורות נוספים {#sharing-and-other-sources}

| צורך | אפשרות |
| --- | --- |
| רק קובצי שורש, ללא תיקיות `pages/` | [`disablePageLocales: true`](/he/api/module-options#disablepagelocales) |
| שני עמודים קוראים תיקיית עמוד אחת | [`routesLocaleLinks`](/he/api/module-options#routeslocalelinks): `{ 'about-us': 'about' }` |
| קובצי שורש משותפים בתיקייה אחרת | [`additionalTranslationDirs`](/he/api/module-options#additionaltranslationdirs): `['common']` (ה-`translationDir` הראשי גובר) |
| מפתחות משכבת Nuxt | הקבצים של השכבות ממוזגים, הקבצים של הפרויקט עצמו גוברים. ראו [שכבות](/he/guide/layers) |
| מפתחות שנוספים בזמן ריצה | ה-hook ‏[`i18n:register`](/he/api/events), ‏`$mergeTranslations`, ‏`$setTranslation` |
| מפתחות מוטמעים בקומפוננטת עמוד | `$defineI18nRoute({ locales: { en: { … } } })`, ראו [תצורת עמוד](/he/guide/per-component-translations) |

## איך עמוד טוען את המילון שלו {#how-a-page-loads-its-dictionary}

![Locale JSON files are built into a payload tree, stored in public/ on Node or in server assets on Edge, read by a server loader, then used by $t on the server and fetched for $t in the browser](/images/diagrams/translation-pipeline.svg)

המודול בונה payload אחד לכל עמוד ו-locale: ‏`/{apiBaseUrl}/{page}/{locale}/data.json` (`/_locales/about/de/data.json` כברירת מחדל).

1. **רינדור בשרת.** Nitro מזהה את ה-locale והעמוד טוען את ה-payload שלו ישירות מטוען השרת, ללא בקשת HTTP. המילון לא נכתב לתוך ה-payload של ה-HTML, כך שהעמודים נשארים קטנים.
2. **Hydration.** הדפדפן מוריד את אותו payload. השרת כבר פלט עבורו `<link rel="preload">`, כך שההורדה מתחילה יחד עם ה-HTML.
3. **ניווט.** ה-payload של העמוד הבא מחליף את המילון. המפתחות של העמוד היוצא עדיין נפתרים עד שהוא נעלם (סוף מעבר העמוד, או `page:finish`), כך שעמוד שנעלם בהדרגה לא מהבהב מפתחות גולמיים. chunk שנכשל בטעינה (שגיאת רשת, 4xx או 5xx, גוף שאינו אובייקט) משאיר את המילון הנוכחי במקומו, והניווט הבא טוען אותו שוב. החלפת locale שנכשלה מתנהגת באותו אופן: `$switchLocale` נפתר ל-`false`, וקריאה חוזרת אליו, או לחיצה חוזרת על המחליף, מנסה שוב. תחת אסטרטגיות הקידומת ה-URL כבר השתנה בשלב זה, כך ש-`lang` ו-`$getLocale()` מציינים את ה-locale של ה-URL בעוד הטקסטים הישנים נשארים על המסך.
4. **מטמון.** payloads שנטענו נשמרים במטמון בשרת ובדפדפן; בעמוד [ביצועים](/he/guide/performance) נמצאות ההגדרות של גודל ו-TTL.

`translationPayloads.mode` קובע איך ה-payloads נבנים. ‏`'premerged'` (ברירת המחדל) כותב כל קובץ עמוד × locale בזמן הבנייה. ‏`'source'` שומר את קובצי המקור וממזג בכל בקשה, מה שקטן יותר עבור קטלוגים גדולים ביעדי Edge. שניהם מפיקים את אותם מילונים. היכן הקבצים מגיעים בכל יעד פריסה מתואר בעמוד [פריסה](/he/guide/deployment).

## עריכה בפיתוח {#editing-in-development}

`nuxt dev` קורא את הקבצים בזמן אמת. שמירת קובץ תרגום מרעננת את המילון של העמוד הפתוח במקום: ללא טעינה מחדש, מפתחות שהוסרו נעלמים, ושינוי בקובץ שורש מגיע לכל עמוד. קובץ JSON שבור רושם אזהרה עם הנתיב שלו ומטופל כריק. הגדירו [`hmr: false`](/he/api/module-options#hmr) כדי לרענן ידנית במקום זאת.
