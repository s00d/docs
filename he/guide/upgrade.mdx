דף זה מפרט מה משתנה באפליקציה שלכם כאשר אתם משדרגים את nuxt-i18n-micro ואת חבילות ה-`@i18n-micro/*` שלו. קראו את הסעיף של הגרסה שממנה אתם מגיעים לפני שאתם מעדכנים את התלות. רוב האפליקציות זקוקות לשינויי קוד מעטים.

<Tip>

**מגיעים מ-`@nuxtjs/i18n`?** — ראו [מעבר מ-@nuxtjs/i18n](/he/guide/migration).

</Tip>

## אחרי 3.30.3: הגרסה הראשית {#after-3-30-3-the-major-release}

אפשרויות המודול, `$t`, `$localePath`, `$switchLocale` ושאר פונקציות העזר, הרכיבים, ה-composables וכלי השרת המתועדים שומרים על שמותיהם. מה שהשתנה הוא ההתנהגות, בעיקר באגים שתוקנו. בחבילות המתאמים ובחבילות הניתוב יש שינויי API שוברים אמיתיים: ראו [חבילות framework](#framework-packages) ו[חבילות אחרות](#other-packages).

### עשו זאת קודם {#do-this-first}

1. **בדקו את הגרסאות שלכם.** המודול דורש Nuxt 3.18 ומעלה ו-Node 20 ומעלה. ל-Nuxt יש דרישת Node מינימלית משלו: Nuxt 4.5 מצהיר על `^22.19.0 || ^24.11.0 || >=26.0.0`. `nuxt generate` על Nuxt 3.18.0 עצמו נכשל גם ב-Nuxt רגיל (`[unstorage] Invalid key: "/"`); 3.21.11 עובד. `@i18n-micro/react` דורש React 18 ומעלה.
2. **תקנו את החבילות המותקנות.**
   - הסירו את `@i18n-micro/hmr`. HMR של תרגומים מובנה במודול.
   - אם הבדיקות שלכם מייבאות את `@i18n-micro/test-utils`, הוסיפו אותו: `npm install -D @i18n-micro/test-utils`. הוא כבר אינו מותקן עם המודול.
   - החליפו את `nuxt-i18n-micro-cli` ב-`@i18n-micro/cli`. 28 פקודות הפכו ל-16, `check` מחליפה שלוש מהן, וקודי היציאה משתנים: ראו [מדריך ה-CLI](/he/guide/cli#moving-from-nuxt-i18n-micro-cli).
3. **חפשו בקוד שלכם** את הרשומות שבטבלה שלהלן.
4. **בדקו מה עומד לפני האפליקציה.** עם `baseUrl` ב-locales מאחורי proxy, ראו [מאחורי proxy או CDN](/he/guide/deployment#behind-a-proxy-or-cdn). עם CDN, בדקו את מפתח המטמון שלו מול כותרת ה-`Vary`: ראו [שמירת HTML במטמון](/he/guide/deployment#caching-html). עם `apiBaseClientHost` או CSP מחמיר, אפשרו את קישור ה-`preload` החדש: ראו [SEO ותגיות head](#seo-and-head-tags).
5. **עדכנו snapshots.** snapshots של ה-head מקבלים את קישור ה-`preload`, ה-markup של בורר השפות השתנה ([`<i18n-switcher>` ו-`<i18n-link>`](#&lt;i18n-switcher>-and-&lt;i18n-link>)), ומחרוזות query בפלט של `$localeRoute` מקודדות אחרת.
6. **פתחו את הדפים שלכם בכל locale וחפשו מפתחות גולמיים.** Layouts שהשתמשו במפתחות מהקובץ של הדף הקודם מציגים אותם כעת גולמיים: העבירו את המפתחות האלה לקובץ השורש.

<Warning>

**`switchLocaleRoute` של `@i18n-micro/path-strategy` איבד את הארגומנט הראשון שלו** — `switchLocaleRoute(fromLocale, toLocale, route, options)` הוא כעת `switchLocaleRoute(toLocale, route, options)`. **קריאת JavaScript ישנה אינה נכשלת: היא מחזירה תוצאה שגויה,** מכיוון ש-`fromLocale` נקרא כיעד ו-`toLocale` כנתיב. רק TypeScript מתריע על כך. `$switchLocaleRoute` של Nuxt אינו מושפע.

</Warning>

### כתובות URL והפניות {#urls-and-redirects}

- **`/en` ו-`/en/...` מחזירים 404 תחת `prefix_except_default`** (כאשר `en` היא ברירת המחדל), כפי שמתועד.
- **קידומת locale באותיות או בכתיב אחרים מחזירה 404.** `/DE/about` נהג לרנדר את הנתיב הגרמני ב-locale של ברירת המחדל, או להפנות אל `/en/DE/about`. דף משלו בכתובת הזו נשאר דף. catch-all או דף `[slug]` אינם כאלה: `/DE/x` תחת `[...slug]` ו-`/DE` לצד `[slug]` מחזירים גם הם 404, כך ש-slug של CMS השווה לקוד locale באותיות אחרות מאבד את הדף שלו. עם `ssr: false` אף שרת אינו עונה, ולכן `/DE/about` מציג את הדף הגרמני.
- **נתיב דף באותיות אחרות מפנה לכתיב שלו.** `/T/BASIC` החזיר 200 וכעת הוא `302` אל `/t/basic`.
- **כתובת URL לא מוכרת נשארת 404.** עם `autoDetectPath: '*'` או `'no_prefix'`, `/nope` כבר אינו מפנה תחילה אל `/de/nope`. `prefix` שומר על ההפניה (שם שום דבר אינו מוגש ללא קידומת), וכך גם `/` בכל מקום.
- **נתיב מותאם של locale אחר, ללא קידומת, מוצא את הדף שלו תחת `prefix_except_default`.** `/a-propos` החזיר 404 וכעת הוא `302` לכתובת של ה-locale של ברירת המחדל (`/about`). תחת `prefix` אותה הפניה מגיעה כעת לדף חי (`/en/about`, בעבר `/en/a-propos`, שהחזיר 404). `prefix_and_default` נשאר 404.
- **`prefix` עם `redirects: false` עונה 404 על כתובת URL ללא קידומת** (`/about` היה `302`), כולל הכתובת המקורית של דף עם נתיב ברירת מחדל מותאם. `$localePath('/about')` עדיין מוצא את הדף הזה.
- **תחת `prefix_except_default` הכתובת המקורית של דף עם נתיב ברירת מחדל מותאם מפנה אליו,** כולל דפים דינמיים. `/dir/one` החזיר 404 וכעת הוא `302` אל `/dir-one/one`.
- **`autoDetectPath: '*'` מחיל כעת את העוגייה ואת `Accept-Language` גם על נתיבים ללא קידומת** (`/about` → `/de/about`).
- **תחת `prefix` כתובת URL ללא קידומת שומרת על ה-locale של המבקר.** עם עוגייה `de`, `/about` ו-`<NuxtLink to="/about">` רגיל הולכים אל `/de/about`, בכל נתיב, לא משנה מה `autoDetectPath` אומר.
- **תחת `prefix_and_default` כתובת URL ללא קידומת היא ה-locale של ברירת המחדל.** `/contact` עם `Accept-Language: de` נהג לרנדר גרמנית ואז לבצע hydration באנגלית. כעת הוא מרנדר את ה-locale של ברירת המחדל; מבקרים מגיעים לגרמנית דרך `/de/...`.
- **תחת `no_prefix` נתיב מותאם מרנדר את ה-locale שלו** (`/ueber-uns` הוא גרמני עם כל העדפה), ודף מוגבל מרונדר ב-locale שהוא משרת. נתיב שכמה locales חולקים מרונדר בהעדפה כאשר היא אחת מהם, ותחת `baseUrl` הוא דף בכל אחד מהדומיינים שלהם. ה-locales האלה חולקים רשומה אחת, `localized-<page>-<first locale>`.
- **`noPrefixRedirect` פועל לפי ה-locale של המבקר.** עם עוגייה `de`, `/about` הולך אל `/ueber-uns`, ומרנדר גרמנית, ולא אל `/about-us` של ה-locale של ברירת המחדל. Locale ללא נתיב מותאם משלו נשאר ב-`/about`.
- **הפניית `routeRules` ללא דף אינה מותאמת locale.** `/de/old` היה 200 ריק, כעת הוא 404: הוסיפו כלל לנתיב עם הקידומת אם אתם צריכים אחד. קישור מ-locale אחר לכלל כזה שומר על הנתיב כפי שנכתב ונוחת ביעד של הכלל.
- **כללי נתיב מגיעים לנתיבים מותאמים.** `/blog/**` חל גם על `/de/artikel/:slug` כאשר ל-`blog/[slug]` יש את הנתיב הזה, וכללים מועתקים גם תחת `no_prefix`. אח סטטי כמו `/de/artikel/news` מתאים גם הוא לתבנית הזו. כלל שכבר נכתב תחת קידומת locale נשאר כפי שנכתב.
- **Locale עם `disabled: true` עונה 404 על הקידומת שלו** מיד, וקישורים אליו נשארים בדף. Locale שהושבת בזמן ריצה עושה את אותו הדבר: בעבר הוא רונדר ב-locale של ה-fallback.
- **דף ה-404 של המודול מציג `Page Not Found`** בקידומת של locale מושבת ובקידומת של host עצמו, במקום שבו Nuxt הציג `Page not found: /de/about`. הסטטוס זהה.
- **`customRegexMatcher` כבר אינו מחזיר 404 לדף אמיתי** שהמקטע הראשון שלו נראה כמו locale.
- **שמות נתיבים מותאמי locale עקביים.** ילד תחת רשומת locale משותפת שומר על שם הדף, `no_prefix` מכבד את `localizedRouteNamePrefix`, והורה עם ילד index נשאר ללא שם.
- **דפים שמודול מוסיף ללא `name`** (`extendPages`) מותאמים locale ומקבלים שם, עם גרסאות locale ו-`hreflang`. בעבר הם נשארו ללא לוקליזציה.
- **רשומה ב-`nuxt.config` גוברת על `$defineI18nRoute`,** בכל צורת מפתח (`about/team`, `/about/team`, `about-team`). בעבר מי שניצח היה תלוי בכתיב.
- **אזהרות בנייה חדשות:** ערך `localeRoutes` שמתחיל בקוד ה-locale שלו (`fr: '/fr/article'`), ונתיב מותאם של ילד מחוץ להורה שלו.
- **מצב hash עובד תחת `prefix`.** המסמך הוא `/`, ו-`/en` או `/about` מפנים לתוך ה-hash.
- **`/#/de/x` מרנדר גרמנית** תחת `prefix_except_default` ו-`prefix_and_default`. בעבר הוא רינדר אנגלית עם אי-התאמה ב-hydration.

### קישורים ואובייקטי נתיב {#links-and-route-objects}

- **Locale שאינו משרת דף מקשר לדף הבית שלו.** `$localeRoute`, `$switchLocalePath` ובורר השפות כבר אינם מחזירים דף של locale אחר.
- **קוד locale לא מוכר הולך ל-locale של ברירת המחדל.** `$localePath(path, 'xx')` ו-`$localeRoute` נהגו להחזיר `/xx`.
- **`$localePath` מחזיר מחרוזת עם סכמה `http(s):`, `mailto:` או `tel:` כפי שהיא, וה-`path` וה-`fullPath` של `$localeRoute` נושאים אותה ללא שינוי**, לכן אל תעבירו אליהם ערך שלא נבדק (פרמטר `?next=`) כיעד קישור. `//host` ושמות חשופים כמו `x.com` נשארים נתיבים, ב-origin הזה בכל locale, ושום קישור שהם הופכים אליו אינו עוזב אותו: `/de//x.com` ל-locale של ברירת המחדל הוא `/x.com`. לוכסנים הפוכים נחשבים כלוכסנים.
- **`$localePath` מקודד נתיב:** `/a b` נותן `/a%20b`.
- **`$localeRoute` ו-`$switchLocaleRoute` מחזירים אובייקטים פשוטים,** בטוחים ב-`ref`, `reactive`, `useState`, JSON ופריסות. כאשר פרמטר דורש escaping האובייקט הוא `{ path, fullPath, query, hash }` (`$localeRoute` מוסיף `href`), ללא `name` או `params`, וה-URL נשאר זהה לפני ואחרי טעינה מחדש. ל-URL פשוט יש את שניהם. `name` חדש: לאובייקטים הישנים מעולם לא היה. קוד שקורא `.name` או `.params` חייב לטפל בהיעדרם, ואיזו צורה תקבלו תלוי בערך.
- **תחת `trailingSlash`, `$switchLocaleRoute` תמיד מחזיר את צורת הנתיב הזו,** גם עבור slugs פשוטים, והפניות שרת עוקבות אחר `trailingSlash`. תוצאות וכותרות `Location` יכולות להשתנות תחת אפשרות זו.
- **ערכי query בפלט של `$localeRoute` משתמשים בקידוד של vue-router:** `/` נשאר מילולי ורווח הוא `+` (`?redirect=/v2`, בעבר `%2Fv2`). הערך המפוענח זהה, אבל snapshot של `href` כזה משתנה.
- **קישור ללא נתיב נשאר בדף הנוכחי.** `$localePath('#top')`, `'?p=2'`, `''` ו-`{ query }` שומרים על הדף שבו הם נמצאים; `'#top'` נהג להיקרא משורש האתר. `'about'` חשוף עדיין פירושו `/about`.
- **פריסות.** `{ ...route, query }` ו-`{ ...route, hash }` שומרים על השינוי, גם דרך `$switchRoute`. `path` חדש מנצח ב-`$localeRoute`, `$localePath` ו-`$switchRoute`. `{ ...route, params }` עובד על נתיב בעל שם; על נתיב בצורת path הנתיב מנצח והפרמטרים מתעלמים, עם אזהרת הפיתוח של vue-router. השתמשו ב-`$localeRoute({ name, params })`.
- **`$switchRoute` נשאר באפליקציה.** `baseUrl` משלו של locale, `mailto:` ו-`tel:` עוזבים אותה; כל מחרוזת אחרת היא נתיב.
- **`excludePatterns`** מתאימים למקטעים שלמים (`'/admin'` כבר אינו מתאים ל-`/administrator`), ו-globs מעוגנים (`/docs/*` כבר אינו מתאים ל-`/en/docs/x`). תבניות `RegExp` מגיעות כעת לזמן הריצה; בעבר הן אבדו שם. דף שהן מתאימות לו הוא ללא לוקליזציה: ללא `hreflang`, וה-locale של ברירת המחדל תחת `prefix_except_default`. בדקו את התבניות שלכם מול [החרגת נתיבים](/he/guide/excluding-static-files).

`%` או `?` בפרמטר אינם שורדים טעינה מחדש עם רינדור בשרת ב-Nuxt 4.5.2, בכל אפליקציה: זו בעיה ב-upstream, לא במודול.

### דומיינים של locale {#locale-domains}

- **`locales[].baseUrl` מנתב כעת בקשות.** בנייה אחת משרתת כל דומיין: ראו [שכבות ודומיינים](/he/guide/layers#multiple-domains). כאשר `baseUrl` מוגדר, locale של דומיין אחר מחזיר 404 ב-host הזה (`/en/about` ב-`example.de`), וקישורים ל-locale באותו host הם יחסיים. בקשות בכל host אחר, כולל `localhost`, מתנהגות כמו קודם, מלבד ש-canonical ו-`hreflang` משתמשים ב-`metaBaseUrl` אם הוגדר, ואחרת ב-`baseUrl` של ה-locale של ברירת המחדל, ולא ב-origin של הבקשה.
- **מאחורי proxy שכותב מחדש את `Host`,** כל בקשה נופלת להגדרות הבנייה עד שתגדירו את [`trustForwardedHost`](/he/api/module-options#trustforwardedhost). ברירת המחדל שלו היא `false`, בניגוד ל-`metaTrustForwardedHost`. ראו [מאחורי proxy או CDN](/he/guide/deployment#behind-a-proxy-or-cdn).
- **`nuxi generate` עם `baseUrl` דורש `NUXT_I18N_DOMAIN`, פעם אחת לכל דומיין.** בלעדיו הבנייה מזהירה, וה-locales האלה הם קישורים ללא דפים. ראו [אתר סטטי](/he/guide/deployment#static-site-(nuxi-generate)).
- **קישור ל-locale עם `baseUrl` עובר דרך `$localePath` או `<i18n-link>`.** `<NuxtLink :to="$localePath(x, 'fr')">` ו-`<i18n-link :to="$localeRoute(x, 'fr')">` הם אותה כתובת URL מוחלטת, ולחיצה מובילה לשם. הנתב אינו מקבל אובייקט מוחלט: `<NuxtLink :to="$localeRoute(x, 'fr')">` ו-`router.push($localeRoute(x, 'fr'))` נשארים `/https://fr.example.com/...`, נתיב של האפליקציה הזו. ב-`localhost` או ב-host של תצוגה מקדימה כל locale עם `baseUrl` הוא קישור כזה, גם הנוכחי. בקוד השתמשו ב-`navigateTo($localePath(x, 'fr'), { external: true })`.
- **דף הבית של דומיין נכתב ללא לוכסן סופי בכל מקום** (`https://example.de`), בקישורים, ב-canonical וב-`hreflang`.
- **תחת `prefix`, קישור לדומיין אחר שומר על קידומת ה-locale, עם או בלי `baseDefault`.** `https://example.de/de/about`, ולא `https://example.de/about`, שרק מפנה.
- **תחת `prefix_except_default` עם `baseDefault` על locale שאינו ברירת המחדל של הבנייה, הנתיבים שומרים על כל קידומת** כדי שדומיינים אחרים יוכלו לקשר אליהם. `/en` עדיין מחזיר 404. רק קוד שקורא את `router.getRoutes()` רואה את ההבדל.
- **תחת `prefix_except_default` הקידומת של host עצמו מחזירה 404 ב-host ה-`baseDefault` שלו.** `/de/x` ב-host של `de` החזיר 200.
- **`$getI18nConfig().locales` מכיל רק את מה שה-host משרת.** `linkLocales` מכיל את כולם, ו-`$getLocales()` נשאר מלא.

### ניווט ו-`$switchLocale` {#navigation-and-$switchlocale}

- **ניווט מוחל כאשר הוא מתבצע בפועל.** המילון, ה-locale, הפרמטרים וה-head משתנים ב-`router.afterEach`, כך שניווט שבוטל או נחסם אינו משנה דבר, והקישורים של הדף הישן נשארים תקפים בזמן שה-chunk הבא נטען. `beforeResolve`, `beforeRouteEnter` או guard גלובלי מאוחר יותר רואים כעת את המילון וה-locale הישנים. Route middleware אינו מושפע.
- **chunk שנכשל שומר על המילון הנוכחי.** 5xx, שגיאת רשת או גוף פגום בקובץ השורש נהגו להציג מפתחות גולמיים. הדף החדש מרונדר כעת עם המחרוזות הישנות, והניווט הבא מנסה שוב. 404, או מעטפת SPA של host סטטי במקום הקובץ, נותנים את מילון השורש עד הטעינה מחדש הבאה.
- **`$switchLocale` נפתר ל-`true` או `false`** (בעבר לא נפתר לשום ערך), `false` כאשר המילון של ה-locale לא הוחל. הוא מוגדר כ-`Promise<boolean>`, ו-`$switchRoute` כ-`Promise<void>`.
- **`$switchLocale` הוא בחירה מפורשת.** בהגעה הוא שומר את ה-locale, גם ב-404. אם הניווט נחסם, בוטל או זורק שגיאה, ההעדפה השמורה וה-state נשארים כפי שהיו, ושגיאה נזרקת מחדש. מעבר ל-host אחר שומר אותו קודם. תחת `no_prefix` ובמצב hash ההחלפה עומדת בתוקף לא משנה מה הניווט עושה. בדף עם כתובת URL אחת לכל ה-locales (`excludePatterns`) הבחירה אינה מבוטלת, וכתובת ה-URL של הדף הבא קובעת: תחת `prefix_except_default` קישור ללא קידומת חוזר ל-locale של ברירת המחדל.
- **תחת `no_prefix`, `$switchLocale` שומר על הדף שלו כאשר שני דפים חולקים נתיב מותאם,** גם עם פרמטרים שעברו escaping. טעינה מחדש של כתובת כזו, ו-`$localeRoute` עם פרמטר שעבר escaping, נוחתים ברשומה הראשונה.
- **הפניה בצד הלקוח שומרת על המצב של הניווט שלה.** `<NuxtLink to="/about">` רגיל תחת `prefix` מוסיף רשומת היסטוריה במקום לדרוס את הנוכחית; `router.replace` עדיין מחליף.
- **`$setI18nRouteParams` ו-`useI18nHead` מהשרת שורדים את ה-hydration.** לאחר נחיתה ב-`/news/2` בורר השפות מקשר ל-slug המתורגם (`/de/news/2-zwei`), ולא ל-`/de/news/2`, גם ב-HTML של השרת, בכל מקום שבו בורר השפות נמצא, כאשר הדף מגדיר את הפרמטרים במהלך SSR. הם נמחקים כאשר ניווט לנתיב אחר מתבצע, כולל מ-`/news/1` ל-`/news/4`: הגדירו אותם שוב בדף החדש.
- **`$setI18nRouteParams` שנקרא ב-setup קשור לדף הזה.** קריאה מאוחרת מדף שכבר עזבתם אינה עושה דבר. `useNuxtApp().$setI18nRouteParams` הוא כעת accessor, ושתי קריאות נותנות שתי פונקציות. אין לו setter: `useI18n().$setI18nRouteParams = fn`, כפי ש-stub בבדיקה עשוי לעשות, זורק שגיאה ב-strict mode, לכן החליפו ב-stub את `useI18n` עצמו. ב-layout או ב-`app.vue` זו הפונקציה הרגילה, כיוון ששום דבר שם אינו נעזב.
- **השרת כותב מחדש את הקישורים של `<i18n-switcher>` כאשר הרינדור מסתיים**, בדפים עם פרמטרים, מכיוון שבורר שפות ב-layout מרונדר לפני ה-setup האסינכרוני של הדף. קישור `$switchLocalePath` שנכתב ידנית אינו נכתב מחדש: ראו [נתיבי locale מותאמים](/he/guide/custom-locale-routes). תחת SSR streaming של Nuxt ה-HTML הראשון שומר על הפרמטרים של ה-URL.
- **prop בשם `locale` על server component מגדיר את locale הרינדור שלו**, כך ש-`<Greeting :locale="$getLocale()" />` עוקב אחר ה-URL ואחר החלפה. `$getLocale()`, `$localePath` ו-`$getLocaleName` בתוכו עוקבים גם הם אחר ה-prop. ראו [תרגומים בצד השרת](/he/guide/server-side-translations). ללא ה-prop הוא עדיין משתמש בעוגייה או בברירת המחדל.
- **דפי `keepalive` מקבלים בחזרה את הפרמטרים וה-head שלהם** בעת חזרה.
- **לדף מקונן שהוגדר כ-`false` תחת `prefix_except_default` אין כתובת locale.** `/de/parent/kid` עם `globalLocaleRoutes: { 'parent-kid': false }` הוגש וכעת מחזיר 404: הדף נשאר ב-`/parent/kid`.

### זיהוי locale והעוגייה {#locale-detection-and-the-cookie}

סדר קדימות אחד בכל מקום, המתואר ב[זיהוי locale](/he/guide/locale-detection).

- **`?locale=` נספר בדפים רק תחת `no_prefix`.** תחת אסטרטגיות הקידומת ה-URL קובע; `/about?locale=de` כבר אינו מרנדר גרמנית תחת `lang="en"`. `?locale=de&locale=fr` קורא את הערך הראשון, בעבר `"de,fr"`.
- **`Accept-Language` מכבד ערכי `q`** (`fr;q=0.1, de;q=0.9` → `de`; `q=0` מחריג שפה). התאמה אזורית כבר אינה תלויה בסדר של `locales`, ולעולם אינה חוצה כתבים סיניים.
- **ניווט בצד הלקוח לדף שומר את ה-locale שלו בעוגייה, גם בדף ללא קידומת של ה-locale של ברירת המחדל.** כאשר `localeCookie` מוגדר, למבקר שלוחץ על קישור ל-`/about` יש כעת `user-locale=en`, ושינוי מאוחר של שפת הדפדפן כבר אינו מפנה את `/`. טעינה ראשונה של אותה כתובת אינה שומרת דבר. תחת `no_prefix` ובמצב hash ניווט שומר רק שינוי.
- **404 אינו כותב עוגייה:** לא בתגובה, ולא בניווט רגיל בצד הלקוח אליו, בשום מצב. תחת `no_prefix` כתובת URL שנראית כבעלת קידומת גם אינה כותבת.
- **תחת `no_prefix` הגדרה מפורשת `localeCookie: null` מכובדת.** בעבר היא הפכה ל-`user-locale`. הגדירו אותה בבלוק `i18n` של `nuxt.config`: `null` ב-`modules: [[name, opts]]` או בשכבה עדיין הולך לאיבוד.
- **מצב hash קורא רק את העוגייה `hash-locale`.** `user-locale=de` לבדו כבר אינו נספר.
- **עוגיית locale פגומה מתעלמת ונשארת כפי שהיא,** במקום להכשיל כל דף SSR עם 500. היא כבר אינה נמחקת בכל בקשה, מה שגם מנע מדף עם קידומת לשמור את ה-locale שלו.
- **ה-locale של ה-URL קודם.** `setLocale('de')` של פלאגין ב-`/en/...` כבר אינו טוען את המילון של `de`, וקוד לא מוכר ב-state מתעלם.
- **פונקציות העזר של API בשרת** (`useLocaleServerMiddleware`, `useTranslationServerMiddleware`) משתמשות בסדר אחד בכל נתיב: `?locale` → פרמטר `[locale]` או קידומת → עוגייה → כותרת → ברירת מחדל. הן מכבדות כעת את `localeCookie: null` ואת `autoDetectLanguage: false`, ושומרות מילון במטמון לכל locale.
- **דריסות בזמן ריצה מגיעות לניתוב.** `NUXT_I18N_DEFAULT_LOCALE` ו-`disabledLocales` בזמן ריצה משנים כעת את האסטרטגיה שנוצרה (locale מושבת מפסיק להיות מנותב), ו-`disabledLocales` בזמן ריצה מתווספים לאלה של הבנייה. תחת `prefix_except_default` ו-`prefix_and_default` מתעלמים מ-`defaultLocale` בזמן ריצה עם אזהרה, מכיוון שהנתיבים ללא קידומת של אותו locale נוצרים בזמן הבנייה. `fallbackLocale` בזמן ריצה חייב להיות locale מופעל: אחרת הוא מושמט עם אזהרה והערך של הבנייה חל אם הוא מופעל. ראו [דריסות בזמן ריצה](/he/guide/runtime-overrides).

### SEO ותגיות head {#seo-and-head-tags}

- **`dir="auto"` כבר אינו ברירת המחדל.** locale ללא `dir` נהג לקבל `dir="auto"`, מה שמאט את הפענוח של דפים גדולים. כעת שפת RTL מוכרת מקבלת `dir="rtl"`, וכל locale אחר אינו מקבל מאפיין. זה חל על Nuxt, `@i18n-micro/vue`, `astro` ו-`vitepress`. אם תגדירו `dir: 'auto'` על locale כדי לשמור על הפלט הישן, זה עולה כשנייה אחת של פענוח ב-20,000 אלמנטים: ראו [כיוון טקסט](/he/guide/seo#text-direction).
- **לכל דף SSR יש תגית חדשה:** `<link rel="preload" as="fetch" crossorigin="anonymous" href="/_locales/...">`, גם לדפי 404. עם `apiBaseClientHost` ה-`href` נמצא ב-host הזה, מה שדורש CORS. CSP מחמיר חייב לאפשר אותה.
- **`hreflang` מפרט רק את ה-locales שמשרתים את הדף**; `x-default` נפלט רק כאשר ה-locale של ברירת המחדל משרת אותו.
- **לדף ללא לוקליזציה אין `hreflang` או `og:locale:alternate`.**
- **canonical ו-`hreflang` כוללים את `app.baseURL`** כאשר ה-origin מגיע מהבקשה. `metaBaseUrl` ו-`site.url` נשארים כפי שנכתבו.
- **דפי 404 נושאים `<html lang dir>`**, ב-locale של ה-URL. אין להם canonical, `hreflang`, `og:url`, `og:locale` או חלופות, גם כאשר המודול עצמו עונה 404 על רשומה תואמת (`/en/...`). תגיות שאתם מעבירים דרך `replace` של `useI18nHead` נשארות, לכן דלגו עליהן בדפי שגיאה.
- **canonical, `og:url` ו-`hreflang` שומרים על query שברשימה המותרת** (`/about?page=2`), גם בשרת: בעבר הוא הושמט במהלך SSR. `page`, `sort`, `filter`, `search`, `q`, `query` ו-`tag` מותרים כברירת מחדל; ראו [`canonicalQueryWhitelist`](/he/api/module-options#canonicalquerywhitelist).
- **`X-Forwarded-Host` שאינו ניתן לפענוח מתעלם** במקום 500 בכל דף. ללא host שמיש, וללא `metaBaseUrl` או `site.url`, כתובות ה-canonical וה-`hreflang` בתגובה הזו יחסיות. `Host` שאינו ניתן לפענוח נשאר 500, כמו באפליקציית Nuxt רגילה.
- **`disableMeta` עובד כעת,** הן ב-`$defineI18nRoute` והן ב-`routeDisableMeta`, גם כשהוא מוגדר ב-`nuxt.config`: לדף אין `hreflang`, canonical או `og:locale`. `lang` ו-`dir` נשארים.
- `useLocaleHead()` מחזיר גם את `build()`, getter עבור `useHead(() => build())`.
- בבנייה רגילה ללא `metaBaseUrl`, `X-Forwarded-Host` עדיין בוחר את ה-host בתגיות האלה, כמו קודם. קבעו את `metaBaseUrl` אם ה-origin נגיש ישירות: ראו [מאחורי proxy או CDN](/he/guide/deployment#behind-a-proxy-or-cdn).

### תרגומים {#translations}

- **המיזוגים עמוקים בכל רמה.** קבצי השורש, הדף וה-fallback השתמשו במיזוג של 2 רמות, כך ש-`a.b.c` מ-fallback או מהשורש אבד במצב source ובפיתוח. כל המצבים נותנים כעת את אותו מילון.
- **שרשראות fallback נעקבות עד סופן** (`fr` → `de` → `en`) בכל מצב.
- **המיזוג נעשה לפי locale, לא לפי סוג הקובץ.** קובץ השורש של ה-locale הפעיל גובר כעת על קובץ הדף של locale ה-fallback. ראו [locales של fallback](/he/guide/translations#fallback-locales).
- **רשומת `locales` של פרויקט גוברת על זו של שכבה** עבור אותו `code`; שכבה רק ממלאת את הפערים.
- **דף ללא תיקיית `pages/<name>/` משלו קורא את מילון השורש,** גם דפי ילד. בעבר הוא קיבל `{}` והציג מפתחות גולמיים. הפלט מקבל קובץ לכל דף כזה, ו-`__root/<locale>/data.json` לכל locale: `/_locales/<any name>/en/data.json` מחזיר 200 עם מפתחות השורש, בעבר `{}`. זה חשוב לניטור, לרשימות היתר ב-hosts סטטיים ולכלים שקוראים את העץ.
- **`disablePageLocales: true` קורא רק את קבצי השורש;** `pages/index` כבר אינו ממוזג פנימה.
- **המפתחות של הדף העוזב מפסיקים להיפתר כאשר האלמנט שלו עוזב את המסמך.** אם layout השתמש במפתחות שרק לקובץ של הדף הקודם היו, העבירו אותם לקובץ השורש. המפתחות של הורה נשארים בזמן שהילד שלו מוצג, כולל הורה עם ילד `index`, עד הניווט הבא. בין שני ילדים של אותו הורה, המפתחות של ההורה עצמו זקוקים למילון של הילד או לזה של השורש.
- **`$clearCache()` טוען מחדש את המילון של הדף הנוכחי** ושומר את הישן על המסך עד שהחדש מגיע. טעינה מחדש שנכשלה שומרת על המילון הישן, תגובה שהתבקשה לפני הניקוי נזרקת, ודף במעבר העזיבה שלו נשאר מתורגם.
- **`$has(key, route)` מכבד את הנתיב.**
- **`$loadPageTranslations` על דף שעדיין לא בוקר כבר אינו מונע מהקובץ שלו להיטען.** הקובץ נטען בביקור הראשון והמפתחות שלכם נשארים מעליו. בעבר הדף הציג מפתחות גולמיים עד לטעינה מחדש.
- **HMR של תרגומים מחיל עריכות במקום**, ללא טעינה מחדש של הדף; מפתחות שהוסרו נעלמים ועריכות בשורש מגיעות לכל דף.
- **קובץ locale פגום מזהיר פעם אחת עם הנתיב שלו, בכל מצב.** בפיתוח הוא נהג לזרוק שגיאה ו-premerged דילג עליו בשקט, כך שאפליקציה שהסתמכה על כך שהפיתוח ייכשל בצורה קשה כבר אינה רואה זאת.

### צורות ריבוי ועיצוב {#plurals-and-formatting}

- `$tc` עם ספירה שלילית, שברית או ענקית לוקח את הצורה האחרונה עם הספירה האמיתית; `{ count: null }` כבר אינו זורק שגיאה; מפתח ריבוי חסר מגיע ל-missing handler.
- `$tdr` נותן תאריכים עתידיים אמיתיים (`in 3 days`, או `tomorrow` עם `numeric: 'auto'`) ו-`Invalid Date` עבור קלט לא חוקי. פחות משנייה בעבר הוא `0 seconds ago`.
- **`$tn`, `$td` ו-`$tdr` פועלים לפי `iso`**, כמו צורות הריבוי: `{ code: 'en', iso: 'en-GB' }` מעצב כעת תאריכים כ-`31/10/2026`. בקוד locale `_` נקרא כ-`-`, כך ש-`en_US` כבר אינו זורק שגיאה, וקוד ש-`Intl` אינו מכיר מעוצב כ-`en` במקום לעקוב אחר ה-locale של המכונה. פורמטים בעלי שם עדיין נמצאים לפי `code`.
- מציין מיקום `{param}` קורא רק את הפרמטרים שאתם מעבירים (`{constructor}` נשאר כפי שנכתב).
- שמות `{placeholder}` יכולים להכיל כל תו מלבד סוגריים מסולסלים ורווחים: `{firstName}`, `{first-name}` ו-`{user.name}` נקראים מ-`params`. ללא פרמטר כזה הם נשארים כפי שנכתבו, כמו קודם.
- `defaultValue` עובר אינטרפולציה, ב-`$t` וב-`$tc`: `$t('missing', { n: 1 }, 'Got {n}')` נותן `Got 1`, בעבר נתן `Got {n}`. ברירת מחדל שאינה מחרוזת חוזרת כפי שהיא.
- `$tc` על תרגום ריק עונה `''`, כמו `$t`. בעבר הוא ענה את ערך ברירת המחדל או את המפתח.
- **תבניות ריבוי שומרות על משמעותן, עם חריג אחד.** הטבלה מפרטת כל צורה. כדי לקבל קטגוריות של `Intl.PluralRules`, ציינו זאת עם [הסמן `=0 `](/he/api/methods#$tc) החדש: `=0 no apples | one apple | {count} apples`.

  | צורה | דוגמה (ב-`uk`) | קודם | עכשיו |
  | --- | --- | --- | --- |
  | כל תבנית ב-locale עם קטגוריה שלמה אחת או שתיים (`en`, `de`, `fr`, `es`, `ja`...) | `none \| one \| {count} many` | לפי אינדקס | **ללא שינוי** |
  | צורה אחת לכל קטגוריה | `one \| few \| many` | לפי אינדקס: 21 → `many` | **ללא שינוי**. הוסיפו את הסמן כדי לקבל 21 → `one` |
  | צורת אפס ראשונה, שלוש צורות | `none \| one \| many` | לפי אינדקס | **ללא שינוי** |
  | מצייני מיקום אחרים | `no items \| {n} item \| {n} items` | לפי אינדקס | **ללא שינוי** |
  | `{count}` בכל צורה | `{count} many \| {count} one \| {count} few` | לפי אינדקס | **ללא שינוי** |
  | פחות או יותר צורות מאשר להלן | `a \| b`, `none \| one \| two \| {count} many` | לפי אינדקס | **ללא שינוי** |
  | ב-`lv`, `prg`, `blo`, `cv`, `ksh`, `lag` | `none \| one \| {count} many` | לפי אינדקס | **ללא שינוי** |
  | מסומן עם `=0 ` | `=0 none \| one \| many` | הסמן הוצג כטקסט | צורת אפס, ואז קטגוריות |
  | **צורת אפס ללא מציין מיקום, ואז צורה אחת לכל קטגוריה, עם `{count}` בכל צורה שכמה ספירות חולקות** | `none \| {count} one \| {count} few \| {count} many` | לפי אינדקס: 3 → `3 many`, 21 → `21 many` | **לפי קטגוריה**: 3 → `3 few`, 21 → `21 one`. 0, 1, 2 וכל ספירה שנשארת ב-`many` נותנות את אותה תוצאה |

  הצורה האחרונה דורשת שלוש קטגוריות או יותר (`ru`, `uk`, `pl`, `cs`, `sk`, `hr`, `sr`, `lt`, `ro`, `sl`, `he`, `ar`, `cy`...). ב-`ar`, `one` ו-`two` הן ספירות בודדות, כך ששתי הצורות האלה אינן זקוקות למספר.
- **קוד locale ש-`Intl` אינו מכיר מקבל את כלל האינדקס**, עם או בלי הקטגוריות של הסמן: `ua` כבר אינו עוקב אחר ה-locale של המכונה. הגדירו `iso`: `{ code: 'ua', iso: 'uk-UA' }` מטפל בריבוי כאוקראינית, במודול וב-`@i18n-micro/vue`.
- **כלל `plural` מותאם שומר על החתימה שלו** ועדיין מקבל את קוד ה-locale. הוא קורא את הערך הגולמי, כך שתבנית מסומנת מגיעה אליו עם `=0 ` במקומו, והוא מקבל את הספירה כ-`Number`: `1.5` במקום שבו בעבר קיבל `1`. החזרת `null` חוזרת לכלל המובנה, שמכבד את הסמן.
- **האפשרות `timeZone`.** הגדירו אותה (`Europe/Berlin`) כדי לרנדר תאריך לוח שנה אחד בשרת ובכל דפדפן. אין לה השפעה על `relativeDate`, שתלוי בשעון.

### `<i18n-t>` {#&lt;i18n-t>}

סעיף זה עוסק ב-`<i18n-t>` במודול וב-`I18nT` ב-`@i18n-micro/vue`. עבור ה-frameworks האחרים ראו [חבילות framework](#framework-packages).

- **`html` מבצע escaping ל-`params`, בכל מקרה, ומתעלם מכל ה-slots.** רק התרגום הוא markup מהימן. פרמטר שהכיל markup בכוונה מוצג כעת כטקסט: שימו את ה-markup בתרגום והעבירו את הנתונים כפרמטרים, או השתמשו ב-slots ללא `html`.
- **Slots עובדים עם `plural`, `number`, `date` ו-`relativeDate`,** ו-slot ‏`default` מקבל `{ translation }` גם במקרים האלה. כל `{name}` מתמלא, לא רק הראשון.
- **slot גובר על פרמטר באותו שם.** ערך פרמטר שנראה כמו מציין מיקום נשאר טקסט. עם `customPluralRule` או `plural` מותאם הכלל מחזיר מחרוזת גמורה, כך שפרמטר שהוא ביצע לו אינטרפולציה עלול להיחשב שם למציין מיקום.
- **`null` פירושו לא מוגדר** עבור `plural`, `number`, `date` ו-`relativeDate`. `:plural="null"` נהג להכשיל את הרינדור, `:date="null"` רינדר את 1970.
- `plural` סופר כמו `$tc`, עם `Number`: `1.5` נשאר `1.5` ולוקח את הצורה האחרונה, בעבר נחתך ל-`1`; `"2 items"` הוא `NaN`, בעבר היה `2`; `""` הוא `0`. גם `customPluralRule` רואה `1.5`. שאר החוזה שלו לא השתנה: אותם ארגומנטים, התשובה שלו משמשת כפי שהיא, `null` מרנדר ריק.
- `hideIfEmpty` חל על `plural`, `number`, `date` ו-`relativeDate`. ערך מוסתר מרנדר הערה, לא צומת טקסט ריק, כך שבדיקה שקראה `''` רואה `<!---->`.
- **מפתח חסר תחת `html` הוא טקסט.** המפתח עובר escaping, מכיוון שרק תרגום הוא מהימן ומפתח יכול להגיע מבקשה. `defaultValue` שייך לכם ונשאר markup.
- עם `plural`, `defaultValue` או המפתח מוצגים בשלמותם כאשר אין התאמה, כמו ב-`$tc`: `a | b` כבר אינו מפוצל.
- `defaultValue` מחליף מפתח חסר בכל ענף, ולא המפתח עצמו, ו-`customPluralRule` מקבל אותו דרך ה-getter שלו כאשר אין התאמה. בעבר הוא עשה משהו רק אחרי `hideIfEmpty`.
- `<i18n-t>` עם `number`, `date` או `relativeDate` שומר על `params`; הם ממוזגים פנימה.
- הפלט של `date` ו-`relativeDate` נושא `data-allow-mismatch="text"`: שעון או אזור זמן שונים בין השרת לדפדפן כבר אינם מזהירים במהלך ה-hydration. לצד slot בעל שם, הטקסט סביב ה-slot יושב ב-`<span>` משלו, מכיוון ש-Vue בודק את המאפיין רק על הטקסט היחיד של אלמנט.
- המאפיינים `.innerHTML` ו-`textContent` מושמטים יחד עם `innerHTML`.
- `<i18n-t>` ו-`<i18n-group>` קוראים את המילון הפעיל, כמו `$t`, ולא את ה-chunk של הנתיב. chunks שפונו (`cacheMaxSize`) כבר אינם מציגים מפתחות גולמיים. דף במעבר העזיבה שלו קורא כעת את מה ש-`$t` קורא שם: את המילון של הדף החדש, ובאין התאמה את המילון שלו, כך שמפתח ששני הדפים מגדירים מציג את הטקסט החדש, ולאחר החלפת locale המפתחות שלו מוצגים גולמיים עד שהוא מוסר.

### `<i18n-switcher>` ו-`<i18n-link>` {#&lt;i18n-switcher>-and-&lt;i18n-link>}

- **לחיצה על קישור בבורר השפות היא ניווט אחד.** זהו `<a>` רגיל שקורא ל-`$switchLocale`, לא `NuxtLink` יחד עם click handler, ולכן מחלקות `router-link-active` נעלמו. ה-`href` עדיין נושא את `app.baseURL`, ולקישור של ה-locale הנוכחי עדיין יש `aria-current="page"`. Ctrl/cmd-click פותח לשונית חדשה ומשאיר את הלשונית הזו כפי שהיא. קישורים שומרים על ה-query וה-hash.
- הכפתור הוא `type="button"`, כך שהוא כבר אינו שולח טופס עוטף, ויש לו `aria-expanded`. `aria-haspopup` הוסר, במודול, ב-`@i18n-micro/vue` וב-`@i18n-micro/astro`: הוא הבטיח תפריט, והרשימה היא קישורים. Escape ולחיצה מחוץ לתפריט סוגרים את התפריט הנפתח; שני בוררי שפות כבר אינם נשארים פתוחים יחד.
- לעוטף ולתפריט הנפתח יש את המחלקות `i18n-switcher-wrapper` ו-`i18n-switcher-dropdown`; לכפתור יש `i18n-switcher-button` וגם `language-switcher`, והתווית שלו יושבת ב-`<span>`. סגנונות ברירת המחדל משתמשים במאפייני CSS לוגיים (`inset-inline-start`, `margin-inline-start`), והחץ הוא `▾`. לתפריט הנפתח יש `z-index: 1000` (בעבר 10), `min-width: 150px` ו-`box-shadow`, ולעוטף `vertical-align: middle`. לכל קישור יש `lang`, ו-`dir` כאשר ה-locale מגדיר אותו.
- `<i18n-link>`: `https://`, `mailto:` ו-`tel:` מותאמים ללא תלות באותיות (`HTTPS://x.com`, `Mailto:`). `report.pdf` או `index.html` חשופים הם נתיב, לא `https://report.pdf`; `example.com` ו-`example.com:8080` נשארים חיצוניים. סיומת קובץ שהיא גם TLD (`example.md`, `x.zip`) נחשבת כקובץ: כתבו `https://`. `activeStyle` מתעלם מלוכסן סופי, מה-query ומה-hash. כעת הוא מוגדר כ-`CSSProperties`, כך שחלק מהערכים עם טיפוסים עשויים לדרוש שינוי.

### Hooks, פלאגינים וטיפוסים {#hooks-plugins-and-types}

- **`i18n:register` רץ ב-`app:created` בעת ההפעלה,** אחרי כל הפלאגינים במקום ביניהם. לפלאגין עם `order` מעל 1 או `enforce: 'post'` המנוי נקרא כעת גם בעת ההפעלה, אבל הוא כבר אינו קורא מפתחות רשומים ב-`setup` שלו. בניווט ה-hook רץ כעת לפני ה-guards של `router.beforeEach` של פלאגינים אחרים.
- **`i18n:register` מקבל את ה-locale של הדף שהוא ממלא.** תחת `hashMode` ניווט שמשנה את ה-locale נהג להעביר את הישן, והמפתחות נחתו ב-chunk הלא נכון.
- **`i18n:register` הוא hook של זמן ריצה:** רשמו אותו עם `nuxtApp.hook('i18n:register', …)` בפלאגין, ללא `@ts-expect-error`. ראו [Hooks](/he/api/events).
- **`hooks: false` ו-`define: false`** עדיין מכבים את החלקים שלהם.
- **עם `plugin: false`, `$defineI18nRoute` נשאר ניתן לקריאה** ואינו עושה דבר בזמן ריצה. בעבר הוא הקריס את הדף.
- האפשרות `hooks` כבר אינה מתעדת את `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`; הם מעולם לא נפלטו.
- `const { $defineI18nRoute } = useNuxtApp()` בדף עובד כעת עם הגדרות שמשתמשות במשתנים.
- ל-`useI18n()` יש יותר מפתחות: `clearCache`, `pluralFunc`, `pluralLocale`. `clearCache` נמצא בטיפוס שלו.
- `$getRouteName(route)` עונה עבור הנתיב שניתן לו. בעבר הוא החזיר מחרוזת ריקה.
- `useI18nLocale()` מסיר את `getLocaleWithServerFallback(serverLocale)`: כתבו `getPreferredLocale() ?? serverLocale ?? null`.
- **`$getI18nConfig()` הוא לקריאה בלבד בשרת בסביבת פיתוח.** כתיבה זורקת שם שגיאה, ובייצור היא הייתה מגיעה לכל בקשה.

### שרת, בנייה ופריסה {#server-build-and-deployment}

- **קובץ ה-payload של דף מכיל רק את מה ששונה מהשורש של ה-locale.** הלקוח טוען את השורש פעם אחת וממזג כל דף מעליו, כך שהדיסק וחבילות ה-Edge מתכווצים ודף שני עולה חלק קטן מהראשון. `premerged` כותב כעת `__root/<locale>/data.json`, ו-`/_locales/<page>/<locale>/data.json` מכיל רק את ההבדל: כל דבר שקורא את הקבצים האלה ישירות חייב למזג את השניים. מילון מלא הוא עדיין קובץ תקין, כך ש-host או מצב `source` שמגישים מילון כזה ממשיכים לעבוד.
- **קבצי מילון נשמרים במטמון לפי גרסה.** URL עם ה-`?v=` הנוכחי מוצמד לשנה בשרת Node, כתובות אחרות עוברות אימות מחדש, והעותק הסטטי של host עונה `max-age=60`: ראו [כותרות מטמון](/he/guide/deployment#cache-headers-and-datebuild). `httpCacheControl: false` שומר על `max-age=0`. תרגום ששונה ללא בנייה מחדש מגיע לדפדפן רק כאשר `v` זז: הגדירו `NUXT_I18N_DATE_BUILD`.
- **המילונים עוקבים אחר `app.cdnURL`.** הדפדפן מוריד קבצי payload ציבוריים מ-`<cdnURL>/_locales/...`, במקום שבו השתמש ב-`app.baseURL`: ה-CDN חייב להכיל את `_locales/` ולאפשר את ה-origin של האתר שלכם (CORS). ראו [App baseURL ו-hosts של payload](/he/guide/deployment#app-baseurl-and-payload-hosts).
- **SSR כבר אינו מבקש את `/_locales` דרך HTTP,** כך ש-middleware בשרת או יומן בנתיב הזה מפסיקים לראות את הקריאות של הרינדור. `apiBaseServerHost` חיצוני עדיין עובר דרך HTTP.
- **קריאה שנכשלה כבר אינה נשמרת, וגם 404 לא.** 404 מ-host פירושו שאין לו קובץ כזה: הרינדור מציג את מילון השורש, כמו הדפדפן, שום דבר אינו נשמר, והקובץ נקרא ברגע שהוא מופיע. כל כשל אחר, 200 שאינו אובייקט JSON, או קובץ מקומי שאינו קריא או פגום אינם מגיעים לשום מטמון, והבקשה הבאה קוראת שוב: רינדור דף רושם אזהרה, מציג מפתחות גולמיים ועונה `503` עם `no-store` ו-`Retry-After`, כך שכלל נתיב או CDN אינם שומרים ממנו דבר בזמן שהדפדפן עדיין קורא את המילון ב-hydration, `/_locales/...` עונה `503` עם `no-store`, ו-`useTranslationServerMiddleware` נותן `t` שעונה את המפתח או את ברירת המחדל. במהלך תקלה כל בקשה מגיעה ל-host, ו-host שאינו שולח כותרות תגובה במשך 60 שניות מכשיל את הקריאה. להורדה איטית של קובץ גדול אין מגבלה. ראו [כאשר לא ניתן לקרוא מילון](/he/guide/deployment#when-a-dictionary-cannot-be-read). `/_locales` מעביר הלאה גם את ה-404 הזה, במקום שבו ענה `200 {}`.
- **prerender שאינו יכול לטעון את המילון שלו נכשל,** וכך גם כזה שב-host שלו אין לא את קובץ הדף ולא את קובץ השורש. הנתיב הוא 500, אזהרה מציינת את ה-locale ואת הדף, ושום קובץ אינו נכתב; עם ברירת המחדל `failOnError` של Nuxt הבנייה יוצאת עם 1. דף ללא קובץ משלו מעל קובץ שורש עובר prerender עם השורש.
- **host שהוגדר בזמן הבנייה עונה ל-SSR,** גם עם העותק הציבורי של ברירת המחדל, ובדף שגיאה בנתיב פנימי. בעבר הקובץ הציבורי ענה. `NUXT_I18N_APP_BASE_SERVER_HOST` בזמן ריצה מגיע כעת ל-`/_locales` ולטוען השרת, והרינדור קורא כל אחד מה-hosts דרך הטוען הזה.
- **`nitro.output.publicDir` מותאם, וכל מבנה אחר שבו `public/` אינו לצד השרת, מטמיע את ה-payloads.**
- **`nuxi build --preset <static preset>` מבצע prerender כמו `nuxi generate`,** ולכן עשוי לכתוב יותר קבצים. `nuxi generate` מבצע prerender לכל דף סטטי בכל locale שמשרת אותו, מקושר או לא, אלא אם כלל נתיב מגדיר `prerender: false`.
- **`source` או `publicAssets: false` בפלט סטטי מזהירים.** אין לדפדפן מה לקרוא.
- **אזהרת ההטמעה היא כעת בדיקת גודל.** הבנייה מזהירה רק מעבר למגבלה של פלטפורמה: ראו [מגבלות חבילה](/he/guide/deployment#bundle-limits-on-edge).
- **`Vary` מוגדר בכל מקום שבו המבקר קובע:** בכל דף תחת `no_prefix`, וב-`/` ובכל כתובת URL אחרת שיכולה להפנות לפי העדפה. הוא מכיל `Cookie` כאשר עוגייה בשימוש, ועם `autoDetectLanguage`, את `Accept-Language`. בדקו את מפתח המטמון של ה-CDN שלכם: ראו [שמירת HTML במטמון](/he/guide/deployment#caching-html).
- **שמירת `/_locales` במטמון השתנתה.** אין מטמון נתיבים של Nitro על `/{apiBaseUrl}/**`, והכותרת `s-maxage=60, stale-while-revalidate` הוסרה. אם הסתמכתם על המטמון הזה, שימו CDN לפני נתיב ה-payload. מילון ריק לעולם אינו `immutable`.
- **מטמון השרת מוגבל כברירת מחדל:** לכל היותר 1000 רשומות כאשר `cacheMaxSize` אינו מוגדר. `cacheTtl` נספר מרגע שמירת הרשומה; קריאות כבר אינן מאריכות אותו.
- **[`cacheStorage`](/he/guide/performance#shared-cache-for-several-instances) אופציונלי חדש:** מטמון מילונים שכמה מופעים חולקים. כאשר אינו מוגדר, שום דבר אינו משתנה.

## מ-v2 ל-v3 {#from-v2-to-v3}

### אפשרויות שהוסרו {#removed-options}

```diff
 i18n: {
-  includeDefaultLocaleRoute: true,
+  strategy: 'prefix',
-  fallbackRedirectComponentPath: '~/components/MyRedirect.vue',
-  experimental: { hmr: true, previousPageFallback: true },
+  hmr: true,
 }
```

- `includeDefaultLocaleRoute: true` הוא `strategy: 'prefix'`; `false` הוא ברירת המחדל `prefix_except_default`.
- `fallbackRedirectComponentPath` הוסר: הפניות מתבצעות בשרת לפני הרינדור וב-route middleware בצד הלקוח. לוגיקת הפניה מותאמת נכנסת לפלאגין שמגדיר את ה-locale, ראו [זיהוי locale מותאם אישית](/he/guide/custom-auto-detect).
- `experimental.hmr` הוא אפשרות ה-`hmr` ברמת השורש (מופעלת כברירת מחדל).
- `previousPageFallback` הוסר: המפתחות של הדף העוזב נפתרים עד שהמעבר שלו מסתיים, ללא אפשרות.

### מצב ה-locale {#locale-state}

השתמשו ב-`useI18nLocale()` במקום `useState('i18n-locale')` ו-`useCookie('user-locale')`:

```diff
- useState('i18n-locale').value = 'fr'
- useCookie('user-locale').value = 'fr'
+ useI18nLocale().setLocale('fr') // state and cookie together
```

### הגדרות בזמן ריצה {#config-at-runtime}

קראו את ההגדרות, כולל דריסות בזמן ריצה, עם `$getI18nConfig()`:

```diff
- const cookieName = useRuntimeConfig().public.i18nConfig?.localeCookie
+ const { $getI18nConfig } = useNuxtApp()
+ const cookieName = $getI18nConfig().localeCookie
```

### כינויי טיפוסים פנימיים {#internal-type-aliases}

אם ה-IDE שלכם או `vue-tsc` אינם מצליחים לפתור ייבואים של `#i18n-internal/*`, מפו אותם ב-`package.json` שלכם. Nuxt פותר אותם בזמן הבנייה, כך שלעיתים רחוקות יש בכך צורך:

```json
{
  "imports": {
    "#i18n-internal/plural": "nuxt-i18n-micro/internals",
    "#i18n-internal/strategy": "nuxt-i18n-micro/internals",
    "#i18n-internal/config": "nuxt-i18n-micro/internals"
  }
}
```
