---
title: "נתיבים מותאמים ל-locale"
description: "הגדרת כתובת URL שונה לעמוד בכל locale באמצעות localeRoutes או globalLocaleRoutes, כולל פרמטרים דינמיים ו-slugs לכל locale."
---

כברירת מחדל, כל locale מגיש עמוד באותו נתיב: `/en/about`, `/de/about`. נתיבים מותאמים ל-locale מאפשרים לכל locale להשתמש במילים שלו, כמו `/de/ueber-uns`, בעוד קובץ העמוד נשאר אותו קובץ. מגדירים אותם בעמוד באמצעות `$defineI18nRoute`, או עבור עמודים רבים בבת אחת ב-`nuxt.config.ts`.

## בתוך העמוד {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

עם `prefix_except_default` ו-`defaultLocale: 'en'` העמוד עונה בכתובות `/about`, ‏`/de/ueber-uns` ו-`/fr/a-propos`. locale ללא רשומה שומר על נתיב ברירת המחדל. כתבו נתיבים ללא קוד ה-locale: הקידומת מתווספת על ידי [האסטרטגיה](/he/guide/strategy), ונתיב שמתחיל בקוד ה-locale רושם אזהרה ביומן. מה עוד הקריאה מקבלת מתואר ב[תצורת עמוד](/he/guide/per-component-translations).

## ב-nuxt.config {#in-nuxt-config}

[`globalLocaleRoutes`](/he/api/module-options#globallocaleroutes) עושה את אותו הדבר לכל עמוד, כשהמפתח הוא הנתיב שלו (או שם הנתיב שלו, כשהוא נכתב ללא לוכסן מוביל):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

כשעמוד מגדיר `localeRoutes` ול-`globalLocaleRoutes` יש אותו מפתח, הרשומה בתצורה גוברת.

## פרמטרים דינמיים {#dynamic-params}

כתבו פרמטרים בכל צורה של Nuxt: ‏`[id]`, ‏`[[page]]`, ‏`[...slug]` או `:id()`. שמות הפרמטרים חייבים להתאים לקובץ העמוד.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

עמודים מקוננים מקבלים נתיב צאצא מוחלט (`/ueber-uns/team`) או נתיב יחסי לנתיב המותאם של ההורה (`team`).

## קישור לעמודים מותאמים {#linking-to-localized-pages}

קישורים נפתרים לנתיב המותאם של ה-locale היעד, בין אם מעבירים שם נתיב ובין אם נתיב פשוט:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

שמות נתיבים נגזרים מנתיב הקובץ (`pages/about/team.vue` הוא `about-team`) אלא אם מגדירים שם באמצעות `definePageMeta({ name })`.

## slugs לכל locale {#per-locale-slugs}

כשה-slug עצמו שונה בכל locale ‏(`/our-products/red-shoe` לעומת `/de/unsere-produkte/roter-schuh`), ציינו למחליף השפה באילו פרמטרים להשתמש באמצעות `$setI18nRouteParams` לאחר שהנתונים נטענו:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

`$switchLocalePath('de')` ו-`<i18n-switcher>` מקשרים אז אל `/de/unsere-produkte/roter-schuh`. המפתחות הם קודי locale, והערכים הם פרמטרים לפי שם (כמו בקובץ העמוד).

מחליף שפה ב-layout מתרנדר לפני שה-setup האסינכרוני של העמוד מגיע לכאן, ולכן בסיום הרינדור המודול משכתב את הקישורים של `<i18n-switcher>`, הן ב-`app.vue` והן בעמוד. ה-HTML של השרת, מבקר ללא JavaScript והרינדור הראשון בצד הלקוח מסכימים אז ביניהם. לשם כך הגדירו את הפרמטרים במהלך SSR: עם `lazy` או `server: false` הקישורים משתנים רק אחרי ה-hydration. ה-SSR streaming של Nuxt שולח את ה-HTML לפני שהפרמטרים ידועים, ולכן תחתיו הקישורים ב-HTML הראשון שומרים על הפרמטרים של ה-URL עצמו.

רק הקישורים של המחליף עצמו משוכתבים. קישור `$switchLocalePath` שנכתב ידנית חייב להתרנדר אחרי שהפרמטרים הוגדרו, לכן שימו אותו בעמוד שמגדיר אותם, גם אחרי `await`. ב-layout הוא מתרנדר ראשון: ה-HTML שלו בשרת שומר על הפרמטרים של ה-URL, וה-hydration מזהיר על אי-התאמה. השתמשו שם ב-`<i18n-switcher>`, עם ה-slots שלו והמאפיינים `custom*Style` לעיצוב.

הפרמטרים שייכים לעמוד שהגדיר אותם:

- הם נמחקים כשניווט לנתיב אחר מתבצע, כך שכל עמוד מגדיר את שלו. ניווט שבוטל משאיר אותם במקומם.
- קחו את `$setI18nRouteParams` מ-`useNuxtApp()` או מ-`useI18n()` בתוך `setup`, גם כשאתם קוראים לו מאוחר יותר ב-handler של `useAsyncData`. כשהיא נלקחת שם, הפונקציה מכירה את העמוד שלה: אם המבקר עזב, קריאה מאוחרת לא עושה כלום.
- עם `keepalive`, עמוד מקבל בחזרה את הפרמטרים שהגדיר כשהמבקר חוזר. ‏`useI18nHead` עושה אותו הדבר.

## נתיבים שנוספו ב-pages:extend {#routes-added-in-pagesextend}

לנתיבים שמוסיפים ב-hook ‏`pages:extend` אין קובץ עמוד שממנו אפשר לקרוא את `$defineI18nRoute`, ולעתים קרובות כמה מהם חולקים קומפוננטת עטיפה אחת. נתיב שנוסף ללא `name` מקבל את השם ש-Nuxt הייתה נותנת לנתיב שלו (`/a/:id()` הופך ל-`a-id`), כך שקישורי שפה מגיעים אליו, אלא אם לנתיב אחר כבר יש את השם הזה; במקרה כזה תנו לו `name` מפורש. שמרו רשימה אחת ופצלו אותה לעמודים ול-`globalLocaleRoutes` עם מפתח לפי שם נתיב באמצעות `splitLocaleRoutes` מתוך `@i18n-micro/utils/split-locale-routes` (הוסיפו את החבילה לתלויות שלכם):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

אל תשימו נתיבים מותאמים ב-`route.meta`: הם יישלחו בטבלת הנתיבים של הלקוח.
