`@i18n-micro/cli` מנהל את קובצי ה-locale של פרויקט Nuxt. הוא קורא את `locales`, `defaultLocale`, `translationDir` ואת השכבות שלכם מתוך `nuxt.config`, ולכן אינו צריך תצורה משלו.

![A terminal running i18n-micro check, which lists a missing, an undefined and four unused keys and fails, then extract, which adds the undefined key, then clean --dryRun, which lists the four keys it would remove](/images/cli/demo.gif)

| פקודה | השתמשו בה כדי |
| --- | --- |
| `check` | להכשיל build על כל בעיה בקובצי ה-locale |
| `translate` | למלא מפתחות חסרים באמצעות שירות תרגום |
| `clean` | להסיר מפתחות ששום דבר אינו משתמש בהם |
| `rename` | להעביר מפתח, או namespace שלם, בכל מקום בבת אחת |

```bash
npm install -D @i18n-micro/cli
npx i18n-micro --help
```

הריצו אותו משורש האפליקציה, או הצביעו עליו עם `--cwd`. כל דגל של כל פקודה מופיע ב-[מדריך הפקודות](/he/api/cli).

<Tip>

**עוברים מ-nuxt-i18n-micro-cli?** `@i18n-micro/cli` מחליף אותו; קובצי ההרצה `i18n-micro` ו-`i18n-micro-cli` נשארים. ראו את [טבלת הפקודות הישנות](#moving-from-nuxt-i18n-micro-cli).

</Tip>

## שימוש ב-CI {#use-it-in-ci}

```bash
i18n-micro check
```

`check` הוא השער. הוא מדווח:

| בדיקה | משמעות |
| --- | --- |
| `missing` | מפתח של locale ברירת המחדל חסר ב-locale מסוים |
| `empty` | ערך הוא `''`. האפליקציה מציגה ריק, לא את הגיבוי |
| `extra` | ל-locale יש מפתח שאין ל-locale ברירת המחדל |
| `placeholders` | `{name}` אבד או נוסף, או שצורת רבים איבדה את הצורות שלה |
| `undefined` | הקוד משתמש במפתח שאין ל-locale ברירת המחדל |
| `unused` | שום דבר בפרויקט אינו משתמש במפתח |
| `duplicates` | אותו טקסט תחת מפתחות שונים. כבוי כברירת מחדל: העבירו `--duplicates` |

- `--only missing,placeholders` מריץ חלק מהבדיקות; בדיקה שצוינה ב-`--only` ולא ניתן היה להריץ אותה נכשלת.
- `--json` נותן דוח עבור כלים.
- `--ignore` מדלג על קובצי מקור.
- כל עוד מפתחות מחושבים בזמן ריצה, `unused` מדולג והדוח מסביר מדוע.

כל פקודה יוצאת עם אחד משלושה קודים, כך ש-pipeline יכול להבחין בין בעיה בתרגומים שלכם לבין בעיה בכלי:

| קוד יציאה | משמעות |
| --- | --- |
| `0` | אין מה לדווח |
| `1` | ממצאים |
| `2` | הפקודה לא הצליחה לרוץ: שגיאת שימוש, קובץ פגום, בקשה שנכשלה |

פקודות נוספות ששוות שלב ב-CI:

```bash
i18n-micro format --check      # fails if a file is not formatted
i18n-micro lint                # stray spaces, empty values, your own regex rules
i18n-micro stats --baseRef main
```

## שמירה על locales מסונכרנים {#keep-locales-in-step}

| פקודה | מה היא עושה |
| --- | --- |
| `extract` | מפרטת את המפתחות שהקוד משתמש בהם ושעדיין אין להם טקסט. טקסט ברירת מחדל, כמו ב-`$t('key', {}, 'Welcome')`, נכתב ל-locale ברירת המחדל. |
| `sync` | מסירה מפתחות שאין ל-locale ברירת המחדל. נסו קודם עם `--dryRun`. |
| `clean` | מסירה מפתחות ששום דבר אינו משתמש בהם. נסו קודם עם `--dryRun`. |
| `search` | מוצאת מפתחות וערכים, ומראה היכן כל מפתח בשימוש. |
| `stats` | השלמה לכל locale; `--baseRef main` משווה ל-git ref. |

`sync` נעצרת כמו `clean` כאשר היא עומדת להסיר מפתח שאינה יכולה להוכיח שאינו בשימוש, וגם כאשר ל-locale ברירת המחדל אין מה להשוות אליו. כשאין מה להסיר היא לעולם אינה נעצרת, כך ש-`$t(item.label)` לבדו אינו סיבה ל-`--force`.

<Note>

`extract` ו-`sync` לעולם אינן כותבות `''` עבור מפתח ללא תרגום. המפתח נשאר חסר, כך ש-`fallbackLocale` חל בזמן ריצה ו-`check` מדווח עליו. מחרוזת ריקה הייתה ערך מוגדר ומציגה ריק.

</Note>

### מה הפקודות קוראות {#what-the-commands-read}

`check`, `extract`, `sync`, `clean`, `search` ו-`rename` קוראות קוד מקור בכל הפרויקט, לא רשימה קבועה של תיקיות:

- **נקרא:** תבניות וסקריפטים באמצעות parser, `.html` ו-Pug כטקסט, כל שכבה, ותיקיות מחוץ לשורש שכינוי או `components` מצביעים עליהן.
- **מדולג:** `node_modules`, פלט build וקובצי ה-locale. הוסיפו משלכם עם `--ignore 'legacy/**,*.stories.ts'`.
- **קוד בדיקות** נחשב כשימוש, כך ש-`clean` ו-`check --only unused` שומרים מפתח שרק בדיקה קוראת. הוא לעולם אינו מוסיף מפתח: `extract` מדלגת על מפתחות כאלה, ו-`check` אינו מדווח עליהם כלא מוגדרים.

קוד בדיקות פירושו תיקיות השורש `tests`, `test`, `__tests__`, `e2e`, `cypress` ו-`playwright`, וכן קובצי JavaScript ו-TypeScript מסוג `.spec` ו-`.test` (`.ts`, `.tsx`, `.mts`, `.js`, `.jsx`, `.mjs` וכדומה) בכל מקום. רק תיקיות השורש פטורות מהספקות שלהלן: `pages/tests/[id].vue` הוא עמוד ככל עמוד אחר, וכך גם `public/` וקבצים מכווצים, שהקוד שלהם אינו חלק מהאפליקציה.

הפקודות מזהות:

- `$t`, `$ts`, `$tc`, `$has` ו-`$_t(route)`;
- `t()` מתוך `useI18n()` ו-`useTranslationServerMiddleware()`;
- `<i18n-t keypath>` בתבניות וב-JSX, ו-`<i18n-group prefix>`;
- כינויים כמו `const { t: tr } = useI18n()`.

### איך `clean` מחליטה {#how-clean-decides}

`clean` מעדיפה להשאיר מפתח מת מאשר להסיר מפתח חי. מפתח נשאר כאשר אחד מהבאים מתקיים:

- קריאה משתמשת בו, או במפתח מתחתיו או מעליו;
- מחרוזת בקוד שווה לו: `const key = 'menu.home'`, `<Item label="menu.home" />`;
- קובץ JSON, YAML או Markdown בפרויקט מכיל אותו;
- למפתח מחושב יש התחלה סטטית שמכסה אותו: `` $t(`status.${state}`) `` שומר את כל מה שתחת `status.`;
- שכבה מגדירה אותו.

`clean` נעצרת בלי לשנות דבר כאשר אינה יכולה לדעת, ומפרטת מדוע:

- מפתח מחושב לחלוטין, כמו ב-`$t(name)`, `<i18n-t :keypath="name" />` או `<i18n-t v-bind="props" />`;
- `$t` מועבר כערך, כמו ב-`items.map($t)`;
- פונקציה בשם `t` מקבלת ארגומנט מחושב ומגיעה מפרמטר, מ-import או מקריאה: ייתכן שהיא עטיפה סביב הפונקציה האמיתית. פונקציה שאותו קובץ מגדיר אינה נחשבת, כי לעטיפה הייתה קריאה משלה בתוכה;
- קובץ מקור אינו עובר ניתוח;
- אף קובץ אינו משתמש באף מפתח, מה שבדרך כלל אומר שהיא מחפשת במקום הלא נכון;
- קובץ locale הוא symlink אל מחוץ לפרויקט, כך שאפליקציה אחרת עשויה לקרוא אותו.

<Steps>

<Step title="תצוגה מקדימה">

הריצו `i18n-micro clean --dryRun` ועברו על מה שהיא מפרטת.

</Step>

<Step title="הגנה על מפתחות">

שמרו מפתחות שרק נראים כלא בשימוש עם `--exclude '^errors\.'`.

</Step>

<Step title="הסרה">

הריצו אותה שוב עם `--force`.

</Step>

</Steps>

## תרגום מפתחות חסרים {#translate-missing-keys}

```bash
i18n-micro translate --dryRun                     # keys and characters per locale, nothing sent
export I18N_TRANSLATE_TOKEN=...                   # or put it in .env
i18n-micro translate --service deepl --locale de,fr
```

- `translate` ממלאת מפתחות חסרים או ריקים; `--replace` מתרגם הכול מחדש.
- Placeholders וצורות רבים מוגנים. תרגום שאיבד placeholder אינו נכתב: המפתח מפורט והפקודה יוצאת עם `1`.
- כל אצווה נשמרת לפני שהבקשה הבאה יוצאת, כך שכישלון עולה רק את הבקשה שנכשלה.

| `--service` | שירות | `--token` | `--options` שימושיים |
| --- | --- | --- | --- |
| `ai` | Vercel AI Gateway, OpenAI, Anthropic או כל שרת תואם OpenAI | מפתח API, או `AI_GATEWAY_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` | `provider`, `model`, `baseUrl`, `maxTokens` |
| `azure` | Azure Translator | מפתח מנוי | `region` |
| `deepl` | DeepL, כולל מפתחות Free | מפתח אימות | `formality`, `glossaryId`, `context` |
| `google` | Google Cloud Translation v2 | מפתח API | `model` |
| `libretranslate` | LibreTranslate | אופציונלי | `baseUrl` |
| `yandexcloud` | Yandex Cloud Translate | מפתח API, או IAM token עם `authScheme:Bearer` | `folderId`, `model` |

האפשרויות הן זוגות `key:value`: `--options provider:openai,model:gpt-4o-mini`. כל השירותים מקבלים גם `baseUrl`, `retries`, `retryDelayMs` ו-`timeoutMs`. ייתכן שבקשת תרגום כבר חויבה, ולכן היא חוזרת רק אחרי `429` או `503`, ולא כאשר השירות מבקש להמתין יותר מדקה.

<Warning>

דגלים גלויים בהיסטוריית ה-shell וברשימות תהליכים, לכן העבירו את ה-token באמצעות משתנה הסביבה. ה-CLI ממסך את מה שהוא יודע שהוא סודי בכל מקום שבו הוא מדפיס אותו, כולל `--debug`: tokens, מפתחות ספקים, אישורי Basic, וה-query והאישורים של URL שהגדרתם. שרת שמעצב מחדש מפתח לפני שהוא מחזיר אותו נמצא מחוץ להישג ידו, לכן התייחסו בזהירות ליומנים של הרצה שנכשלה.

</Warning>

השירות `ai` עוקב אחר מילון מונחים. כאשר `.i18n-glossary.json` קיים הוא משמש ללא דגל; `--glossaryFile` בוחר קובץ אחר.

```json .i18n-glossary.json
{ "entries": [{ "source": "Cart", "target": "Warenkorb", "to": "de" }] }
```

## הפיכת טקסט מקודד לטקסט למפתחות {#turn-hardcoded-text-into-keys}

```bash
i18n-micro text-to-i18n --dryRun   # list what would change
i18n-micro text-to-i18n            # rewrite the templates
```

```vue
<!-- before -->
<h1>Welcome to our site</h1>
<!-- after -->
<h1>{{ $t('pages.index.welcome-to-our') }}</h1>
```

רק תבניות `.vue` של הפרויקט עצמו נכתבות מחדש, לא אלה של שכבה או של יעד כינוי. כל קובץ שנכתב מחדש מנותח שוב לפני שהוא נשמר. הבאים מפורטים ושומרים על הטקסט שלהם:

- טקסט בקובצי `.ts` ובסקריפטים, מכיוון ש-`$t` אינו זמין בכל מקום;
- טקסט לצד markup או אינטרפולציה, כמו `<p>Hello <b>world</b> today</p>`: חצי משפט אינו ניתן לתרגום בפני עצמו;
- מפתח שנוצר שהיה מתנגש באחר, כפי שעמוד הורה ועמוד הצאצא שלו עלולים;
- מפתח ידוע שאינו יכול להופיע בין מירכאות.

<Warning>

בצעו commit קודם, ועברו על ה-diff.

</Warning>

## שינוי שם של מפתח {#rename-a-key}

```bash
i18n-micro rename --from common.save --to actions.save
i18n-micro rename --from settings --to account.settings   # a whole namespace
```

`rename` עורכת את עץ התחביר, כך שהערות ומחרוזות לא קשורות נשארות כפי שהן, וכינויים ו-`:keypath` נעקבים. הקובץ של שכבה עצמה לעולם אינו משתנה. היא מזהירה לגבי מה שאינה יכולה לכתוב מחדש, ומשאירה אותו כפי שהוא:

- מפתח מחושב תחת השם הישן;
- כל מחרוזת פשוטה ששווה לו;
- תבנית Pug;
- מקור בשכבה או בתיקייה מחוץ לפרויקט.

`--to` חייב להיות מפתח שניתן לכתוב בקוד: ללא מירכאות, ללא backslash, ללא מקטע ריק, ללא `__proto__`.

## החלפת קבצים עם מתרגמים {#exchange-files-with-translators}

```bash
i18n-micro export --format csv
i18n-micro import --format csv --dryRun
```

**`export`** כותבת כל מפתח של כל locale, כולל כאלה שלא תורגמו, עם הטקסט של locale ברירת המחדל כמקור: עמודת `Source` ב-CSV, הערת `#.` ב-PO.

- ללא `--dir`, PO נכתב ל-`pots` ו-CSV ל-`csv_exports`.
- היא מתעדת מה כתבה ב-`.i18n-export.json`, בתיקיית הפלט. היא נעצרת כאשר קובץ השתנה מאז ומכיל תרגומים שאין בקובצי ה-locale, כולל רשומות PO מסוג fuzzy; `--force` דורס אותם. עריכות רגילות של קובצי ה-locale אינן עוצרות אותה.

**`import`** ממזגת, מדלגת על תאים ריקים, ומדלגת על רשומות PO המסומנות `fuzzy`.

- מפתח שהיה דורס ערך, או ערך מעל קבוצה שלמה של מפתחות, מפורט ומושמט, והפקודה יוצאת עם `1`.
- היא נעצרת עם יציאה `2` על קטלוג במיקום לא צפוי, קטלוג של עמוד שה-export האחרון לא כתב, מירכאה שלא במקומה ב-CSV, או רשומת עמוד תחת `disablePageLocales`.

עבור פלטפורמת תרגום, השתמשו ב-CLI שלה: הגדרת [Crowdin](/he/guide/crowdin) מסנכרנת את קובצי ה-JSON, כולל קובצי עמוד.

## סנכרון עם endpoint משלכם {#sync-with-your-own-endpoint}

`sync-remote` מחליפה את קובצי ה-locale הגלובליים עם endpoint של HTTP שאתם מפעילים. קובצי עמוד נשארים מקומיים, והפקודה אומרת זאת. תארו את ה-endpoint ב-`.i18n-remote.json`:

```json .i18n-remote.json
{ "url": "https://translations.example.com", "path": "translations" }
```

ה-endpoint עונה ל-`GET` ול-`PUT` עם אובייקט `{ locale: messages }`. בצעו אימות עם `auth: { username, password }`, או שימו bearer token ב-`I18N_REMOTE_TOKEN`.

| | Pull | Push |
| --- | --- | --- |
| מה עובר | ממלא את מה שאין לכם ושומר מפתחות שרק לכם יש | שולח את המפתחות של הפרויקט עצמו, לא את אלה של שכבה, ומשמיט את הערכים הריקים שלכם |
| התנגשויות | מפתח ששונה בשני הצדדים: שום דבר אינו נכתב, יציאה `1`; `--force` לוקח את הערך המרוחק | PUT מחליף את המסמך, ולכן push קורא קודם את ה-endpoint ונעצר עם יציאה `1` כאשר הוא מכיל טקסט שאין לכם; `--force` דורס אותו. ל-endpoint שעונה `404` אין מה להפסיד |
| `--dryRun` | קורא מה-endpoint, מפרט את השינויים, אינו כותב דבר | אומר מה היה נשלח, בלי לפנות ל-endpoint |

locale שלא הגדרתם מדולג, וערך מרוחק ריק אינו מנקה דבר.

## מעבר מ-nuxt-i18n-micro-cli {#moving-from-nuxt-i18n-micro-cli}

| פקודה ישנה | כעת |
| --- | --- |
| `validate` | `check` |
| `diff` | `check --only missing` |
| `check-duplicates` | `check --only duplicates` |
| `export-csv`, `import-csv` | `export --format csv`, `import --format csv` |
| `--potsDir`, `--csvDir` | `--dir` |
| `estimate` | `translate --dryRun` |
| `glossary` | ערכו את `.i18n-glossary.json`; `translate` קוראת אותו בעצמה |
| `backup`, `restore` | Git, שכבר שומר את קובצי ה-locale שלכם |
| `init` | `nuxi init`, ואז הוסיפו את `nuxt-i18n-micro` ל-`modules` |
| `split` | הוסר: המודול אינו קורא קבצים מפוצלים |
| `optimize` | `check --only duplicates` |
| `replace-values` | העורך שלכם או `sed` |
| `stats --full` | `stats`; ל-[DevTools](/he/guide/devtools) יש את הפרטים |
| `search --hardcodedOnly` | `text-to-i18n --dryRun` |
| `search --preferUnused`, `--onlyVue` | הוסר |
| כללי `lint` `no-html-tags`, `no-special-chars`, `no-mixed-case`, `no-missing-punctuation`, `no-inconsistent-pluralization` | הוסרו: הם סימנו טקסט רגיל. כתבו רשומת `customRegexRules` אם אתם צריכים אחד |
| `text-to-i18n --extractOnlyDirs`, `--extractOnlyPatterns`, `--verbose` | הוסרו: קוד לעולם אינו נכתב מחדש |
| `--logLevel verbose` | הוסר: הוא לא עשה דבר |

**שירותים שהוסרו:** `googlefree`, `yandex` (השתמשו ב-`yandexcloud`), `ibm`, `lingvatranslate`, `modernmt`, `lilt`, `unbabel`, `reverso`, `baidu`, `papago`, `tencent`, `systran`, `mymemory`.

**סוגי `sync-remote` שהוסרו:** `github`, `gitlab`, `crowdin`, `lokalise`, `tolgee`, `weblate`. השתמשו ב-CLI של הפלטפורמה, או ב-`custom`, שכבר אינו צריך `type`.

### התנהגות שהשתנתה {#changed-behaviour}

- `extract` ו-`sync` כבר אינן כותבות `''`. מפתחות נשארים חסרים, ו-`check` מדווח עליהם. `extract` כותבת מפתח רק כאשר הקוד נותן את הטקסט שלו.
- `extract` כותבת מפתחות עמוד ל-`locales/pages/<route name>/`, שם המודול קורא אותם, וסורקת את `app/` ב-Nuxt 4. העבירו כל דבר מתיקיות כמו `pages/_about` ו-`pages/blog_`, ומחקו `locales/pages/<locale>.json` תועה.
- `translationDir` מתוך `nuxt.config` מכובד; קודם לכן, כל פקודה השתמשה בשקט ב-`locales`.
- ללא `defaultLocale`, ברירת המחדל היא `en`, כמו במודול, ו-`DEFAULT_LOCALE` מכובד. בעבר זה היה ה-locale הראשון.
- `check` ו-`sync` משתמשות ב-locale ברירת המחדל כנקודת ייחוס ובודקות קובצי עמוד. `"a.b"` ו-`a: { b }` נחשבים כמפתח אחד.
- `clean` שומרת מפתח שבשימוש בכל מקום, בכל scope, ונעצרת כאשר לא ניתן להוכיח שימוש. `--include` ו-`--exclude` בוחרים מה מותר להסיר.
- `sync` נעצרת באותו אופן, וכאשר ל-locale ברירת המחדל אין מפתחות להשוות אליהם. `--force` עוקף זאת. היא נעצרת גם כאשר `DEFAULT_LOCALE` בחר נקודת ייחוס אחרת מ-`nuxt.config`.
- דגלים ארוכים עם מקף בודד וארגומנטים תועים הם שגיאות: `clean -dryRun` כבר אינו מריץ `clean`.
- קובץ לקריאה בלבד, או קובץ שאינו UTF-8, אינו ניתן לשמירה: הפקודה נעצרת לפני שהיא משנה משהו. קריאת קובץ כזה תקינה. מפתח חוזר, מפתח בשם `__proto__` ומספר שלם מעל 2^53 עוצרים פקודה, כי שמירה הייתה מאבדת אותם.
- דגל שדורש ערך ואחריו בא דגל אחר הוא שגיאה; כתבו `--flag=--value` עבור ערך שמתחיל במקף. דגל בוליאני מקבל רק `true` או `false`.
- `export` נעצרת במקום לדרוס תרגומים שמעולם לא יובאו.
- קודי היציאה הם `0`, `1` ו-`2`; כישלונות היו בעבר `1`, ו-`diff` ו-`check-duplicates` תמיד `0`.
- `lint --fix` כבר אינו משאיר קובצי `.bak`.
- שמירה שומרת על ההזחה של קובץ, סיומות השורות, השורה החדשה הסופית, symlink ו-hard link, ומשאירה קבצים שלא שינתה כפי שהם.
- דגל שגוי או שהוסר הוא כעת שגיאה, ולא מתעלמים ממנו בשקט.
- נתיבים כמו `--dir` הם יחסיים לפרויקט, לא ל-shell.
- `ai` כבר אינו טוען חבילות `@ai-sdk/*`: השתמשו ב-`provider` `gateway`, `openai` או `anthropic`, או ב-`baseUrl` עבור שרת תואם OpenAI.
