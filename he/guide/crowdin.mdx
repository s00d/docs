[Crowdin](https://crowdin.com/) היא פלטפורמת תרגום: אתם מעלים את קובצי ה-locale ברירת המחדל, המתרגמים עובדים ב-Crowdin, ואתם מורידים בחזרה את שאר ה-locales. המודול קורא קובצי JSON פשוטים, ולכן Crowdin CLI צריך רק קובץ `crowdin.yml` שממפה נכון את `locales/` ואת `locales/pages/`. אין צורך לשנות אף הגדרה של המודול.

## הגדרת crowdin.yml {#configure-crowdin-yml}

```yml
# crowdin.yml
project_id_env: CROWDIN_PROJECT_ID
api_token_env: CROWDIN_PERSONAL_TOKEN
base_path: ./locales
preserve_hierarchy: true

files:
  - source: /en.json
    translation: /%two_letters_code%.json
  - source: /pages/**/en.json
    translation: /pages/**/%two_letters_code%.json
```

- `en` הוא ה-locale ברירת המחדל שלכם; הקבצים שלו הם המקורות.
- `project_id_env` / `api_token_env` קוראים את המזהה ואת הטוקן ממשתני סביבה, כך שאף סוד לא נכנס ל-commit.
- `preserve_hierarchy: true` שומר את תיקיות `pages/<page>/` כפי שהן.
- שם הקובץ המתורגם חייב להיות זהה ל-`code` של ה-locale ב-`nuxt.config.ts`. ‏`%two_letters_code%` מתאים לקודים כמו `de`; עבור קודים כמו `pt-BR` השתמשו ב-`%locale%`, או מפו את הקודים של Crowdin לשלכם באמצעות `languages_mapping`.

## העלאה והורדה {#upload-and-download}

```bash
npm install -g @crowdin/cli

export CROWDIN_PROJECT_ID=123456
export CROWDIN_PERSONAL_TOKEN=...   # from Crowdin account settings

crowdin upload sources   # push locales/en.json and locales/pages/**/en.json
crowdin download         # write locales/de.json, locales/pages/**/de.json, ...
```

הריצו את שניהם ב-CI כדי לשמור על הקבצים מעודכנים. הקבצים שהורדו נכנסים למאגר שלכם כמו קבצים שנערכו ידנית; הבנייה הבאה או הטעינה מחדש בפיתוח יקלטו אותם.

## לפני ההעלאה {#before-uploading}

נקו קודם את המקורות כדי שהמתרגמים לא יעבדו על מפתחות מתים: [`i18n-micro clean`](/he/api/cli#clean) מסיר מפתחות שאינם בשימוש, [`i18n-micro check`](/he/api/cli#check) מדווח על חוסרים אחרי הורדה. ל-CLI אין אינטגרציה משלו עם Crowdin: העמוד הזה הוא הדרך הנתמכת.
