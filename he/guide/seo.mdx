עם `meta: true` (ברירת המחדל) כל עמוד מותאם ל-locale מקבל `<html lang dir>`, קישור canonical, חלופות `hreflang`, ‏`x-default` ותגי locale של Open Graph. תזדקקו לעמוד הזה כשתרצו להגדיר את ה-origin הציבורי, לכוונן אילו locales יופיעו בתגים, או לדרוס אותם בעמוד אחד. רוב האתרים צריכים רק `site.url` או `metaBaseUrl` וקודי `iso` נכונים.

## הגדרה מינימלית {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

`/de/about` מתרנדר אז כך:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## כיוון הטקסט {#text-direction}

`<html dir>` מגיע מה-`dir` של ה-locale. בלעדיו, שפה שנכתבת מימין לשמאל מקבלת `rtl`, לפי `iso` (או `code`): ערבית, עברית, פרסית, אורדו ועוד כמה, וכל תג עם כתב RTL כמו `az-Arab`. כל locale אחר לא מקבל מאפיין `dir`, ודפדפנים מפרשים זאת כ-`ltr`.

<Warning>

**`dir: 'auto'` עולה בזמן פענוח בעמודים גדולים** — `auto` על `<html>` גורם לדפדפן לחשב את הכיוון מהתוכן בזמן הפענוח. ב-Chromium העלות הזו גדלה מהר יותר מהעמוד: כ-100 ms ב-5,000 אלמנטים ו-1 s ב-20,000. השתמשו בו רק לעמוד קטן שאת שפתו אינכם יכולים לדעת.

</Warning>

## אילו תגים מקבלים {#which-tags-you-get}

- **hreflang**: תג אחד לכל locale שמגיש את העמוד, עם הערך `iso` (או `code` כש-`iso` חסר), וכתובת ה-URL שלו עם אותו query כמו ה-canonical. עמוד שהוגבל באמצעות [תצורת עמוד](/he/guide/per-component-translations) או `routeLocales` מציג רק את ה-locales שלו. [`hreflangBaseLanguage: true`](/he/api/module-options#hreflangbaselanguage) מוסיף גם את השפה הבסיסית (`es-ES` → `es`) עבור ה-locale האזורי הראשון.
- **x-default**: הכתובת של ה-locale ברירת המחדל, רק כשה-locale ברירת המחדל מגיש את העמוד.
- **og:locale**: נגזר מ-`iso` (`en-US` → `en_US`). הגדירו `og` ב-locale כשהמיפוי אינו ישיר, למשל `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; ללא אף אחד מהם, לא נכתב `og:locale` ומצב הפיתוח מזהיר.
- **canonical / og:url**: הכתובת הנוכחית ללא פרמטרי query, למעט אלה שב-[`canonicalQueryWhitelist`](/he/api/module-options#canonicalquerywhitelist) (ברירת המחדל: `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

לפי אסטרטגיה:

| אסטרטגיה | hreflang ו-x-default | canonical, ‏og:url, ‏og:locale, מאפייני html |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | כן | כן |
| `no_prefix` | לא (כתובת אחת מגישה כל locale) | כן |

## הגדרת ה-origin הציבורי {#set-the-public-origin}

כתובות URL מוחלטות משתמשות בראשון מבין:

1. [`metaBaseUrl`](/he/api/module-options#metabaseurl);
2. `site.url` מתוך `nuxt-site-config` (מותקן על ידי `@nuxtjs/seo`);
3. ה-origin של הבקשה, עם `app.baseURL` בסופו.

קבעו אחד משני הראשונים.

<Warning>

ברירת המחדל של origin הבקשה קוראת את `X-Forwarded-Host` ו-`X-Forwarded-Proto`, מכיוון שברירת המחדל של [`metaTrustForwardedHost`](/he/api/module-options#metatrustforwardedhost) ו-`metaTrustForwardedProto` היא `true`. זה בטוח רק מאחורי proxy שדורס את הכותרות האלה; אחרת לקוח יכול לבחור את המארח בקישורי ה-canonical שלכם, ומטמון יכול להעביר את העמוד הזה הלאה.

אם האפליקציה נגישה ישירות, קבעו את `metaBaseUrl`: בניגוד להגדרת שתי האפשרויות ל-`false`, הוא גם מתעלם מ-`Host` מזויף. ראו [מאחורי proxy או CDN](/he/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

ברירת המחדל הזו שימושית לפריסה אחת שעונה לכמה דומיינים: `https://site-a.com/en/about` ו-`https://site-b.com/en/about` מקבלים כל אחד את ה-origin שלו.

כשיש `baseUrl` ב-locales, מארח מוכר משתמש ב-`baseUrl` שלו, לפני `metaBaseUrl` ו-`site.url`, כך ש-canonical ו-`og:url` נשארים באותו דומיין ו-`hreflang` מפנה כל locale לדומיין שלו. כל מארח אחר משתמש ב-`metaBaseUrl`, אחרת ב-`baseUrl` של ה-locale ברירת המחדל, אחרת ב-`site.url`, כך ש-`Host` מזויף לא יכול להגיע לתגים שלכם. אם אף אחד מאלה לא הוגדר, ברירת המחדל של origin הבקשה נשארת, והבנייה מזהירה. ראו [שכבות ודומיינים](/he/guide/layers#multiple-domains).

## השמטת locales או עמודים {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

אם ל-locale ברירת המחדל יש `seo: false`, לא נכתב `x-default`. כדי לכבות את התגים בעמוד אחד, השתמשו ב-`disableMeta` ב[תצורת עמוד](/he/guide/per-component-translations#turn-off-seo-tags), או ב-[`routeDisableMeta`](/he/api/module-options#routedisablemeta) בתצורה.

## דריסת תגים בעמוד אחד {#override-tags-on-one-page}

עבור תוכן CMS שבו קיימים רק חלק מהתרגומים, או שהכתובות מגיעות מ-API, החליפו את התגים שנוצרו באמצעות [`useI18nHead`](/he/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` יכול גם להגדיר או להסיר את `canonical`, ‏`xDefault`, ‏`ogLocale` ו-`ogUrl`; ‏`disable` מסיר קבוצות שלמות (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). העבירו getter כדי שהערכים יחושבו מחדש אחרי החלפת locale. עבור slugs לכל locale, הגדירו קודם את `$setI18nRouteParams` ‏([נתיבים מותאמים ל-locale](/he/guide/custom-locale-routes#per-locale-slugs)) והחלופות שנוצרות כבר ישתמשו בהם.

## לוכסן בסוף הכתובת {#trailing-slash}

`$localePath`, ‏`$switchLocalePath`, אובייקט הנתיב של `$switchLocaleRoute`, ‏`<i18n-link>`, ‏`<i18n-switcher>`, הפניות locale וכתובות ה-SEO פועלים לפי כלל לוכסן אחד: `experimental.defaults.nuxtLink.trailingSlash` כברירת מחדל, או [`trailingSlash`](/he/api/module-options) בתצורת i18n כשנתיבי i18n צריכים להיות שונים.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) ‏(sitemap, ‏robots, ‏schema.org) עובד עם המודול הזה דרך `nuxt-site-config` 4+‎. רשמו את `nuxt-i18n-micro` ראשון כדי שתצורת האתר תוכל לקרוא את ה-locales, והגדירו את `site.url` פעם אחת — הוא גם מזין את התגים שלמעלה.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

שם ותיאור מתורגמים של האתר מגיעים מהמפתחות `nuxtSiteConfig.name` / `nuxtSiteConfig.description` בקובצי ה-locale שלכם. השגיאה `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` פירושה ש-`@nuxtjs/seo` ישן מגרסה 3; שדרגו אותו ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
