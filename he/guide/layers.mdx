שכבת Nuxt יכולה לשאת את תצורת ה-i18n ואת תיקיית `locales/` עבור כמה אפליקציות, וכל אפליקציה מוסיפה או דורסת את מה שהיא צריכה. עמוד זה מראה זאת, וכיצד build אחד מגיש כמה דומיינים.

## שיתוף תצורה ותרגומים {#share-config-and-translations}

```ts
// base/nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    defaultLocale: 'en',
  },
})
```

```ts
// shop/nuxt.config.ts
export default defineNuxtConfig({
  extends: ['../base'], // a layer directory or package, not a nuxt.config file
  i18n: {
    locales: [
      { code: 'es', iso: 'es-ES' }, // added
      { code: 'fr', disabled: true }, // the base layer's fr, switched off here
    ],
  },
})
```

- **תצורה:** אפשרויות סקלריות באפליקציה מחליפות את אלה של השכבה. מערכי `locales` מכל השכבות משולבים, ורשומות עם אותו `code` מתמזגות לאחת כאשר השדות של האפליקציה גוברים, כך שאפליקציה יכולה להוסיף locale או להגדיר שדות כמו `disabled: true` על locale שעבר בירושה.
- **תרגומים:** תיקיות `locales/` של כל שכבה ממוזגות מפתח אחר מפתח, השכבה ראשונה והאפליקציה אחרונה, כך שמפתח ב-`shop/locales/en.json` דורס את אותו מפתח ב-`base/locales/en.json`. קובצי עמוד (`locales/pages/<page>/`) מתמזגים באותו אופן.
- **עמודים:** `$defineI18nRoute` נקרא מהעמודים של כל שכבה.

כדי למזג תיקיות שאינן חלק משכבה, רשמו אותן ב-[`additionalTranslationDirs`](/he/api/module-options#additionaltranslationdirs).

## דומיינים מרובים {#multiple-domains}

build אחד מגיש את כל הדומיינים. רשמו כל locale עם הדומיין שלו; `baseDefault` הופך אותו לברירת המחדל של אותו host:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'de', iso: 'de-DE', baseUrl: 'https://example.de', baseDefault: true },
      { code: 'nl', iso: 'nl-NL', baseUrl: 'https://example.de' },
      { code: 'fr', iso: 'fr-FR' },
    ],
  },
})
```

כוונו את שני הדומיינים לאותו שרת. ה-host של הבקשה מחליט את השאר:

- **ברירת מחדל:** ה-locale בעל `baseDefault` של ה-host. אם אין כזה, ברירת המחדל של ה-build אם ה-host מגיש אותה, אחרת ה-locale הראשון של ה-host.
- **Locales מוגשים:** ה-locales של אותו host, וכן כל locale ללא `baseUrl`. ב-`example.de` אלה הם `de`, `nl` ו-`fr`.
- **Locales של דומיינים אחרים** הם יעדי קישור. `$localePath`, `$localeRoute`, `$switchLocalePath`, `<i18n-switcher>` ו-`hreflang` נותנים כתובות URL מוחלטות על ה-`baseUrl` שלהם, ו-`$switchLocale` מנווט לשם. ב-host הזה כתובות ה-URL שלהם מחזירות 404, ו-cookie או `Accept-Language` אינם יכולים לבחור בהם.
- **קישור לדומיין אחר** עובר דרך `$localePath` או `<i18n-link>`: `<NuxtLink :to="$localePath('/contact', 'de')">`, `<i18n-link :to="$localeRoute('/contact', 'de')">`. ה-router אינו מקבל אובייקט מוחלט, ולכן `<NuxtLink :to="$localeRoute(...)">` ו-`router.push($localeRoute(...))` נשארים ב-origin הזה. ב-`localhost` או ב-host של preview כל locale בעל `baseUrl` הוא קישור כזה, גם הנוכחי. בקוד השתמשו ב-`navigateTo($localePath('/contact', 'de'), { external: true })`, או ב-`$switchRoute`.
- **כל host אחר** מקבל את תצורת ה-build, כאשר כל locale בעל `baseUrl` הוא יעד קישור. שום דבר מהבקשה אינו מוחזר: canonical ו-`hreflang` משתמשים ב-`metaBaseUrl`, אחרת ב-`baseUrl` של ברירת המחדל של ה-build (ברירת מחדל ללא `baseUrl` דורשת `metaBaseUrl` או `site.url`, ראו [SEO](/he/guide/seo#set-the-public-origin)).
- **קובצי payload** ב-`public/` הם סטטיים: כל host מחזיר את הקובץ של כל locale. [generate](/he/guide/deployment#static-site-(nuxi-generate)) לכל דומיין מפרסם רק את אלה של אותו דומיין.

`example.de` תחת כל אסטרטגיה, עם `de: '/kontakt'` כנתיב מותאם אישית של `contact`:

| אסטרטגיה | `/` | העמוד של locale ברירת המחדל | כתובות URL אחרות |
| --- | --- | --- | --- |
| `prefix_except_default` | `de` | `/kontakt` | `/de/kontakt` ו-`/en/contact` מחזירים 404, `/contact` מפנה ל-`/kontakt` |
| `prefix_and_default` | `de` | `/kontakt` ו-`/de/kontakt`, קישורים משתמשים ב-`/kontakt` | `/en/contact` ו-`/contact` מחזירים 404 |
| `prefix` | מפנה ל-`/de` | `/de/kontakt` | `/kontakt` מפנה ל-`/de/kontakt`, `/en/contact` מחזיר 404 |
| `no_prefix` | `de` | `/kontakt` | נתיב מותאם אישית של locale בדומיין אחר מחזיר 404 |

תחת `prefix` קישור מדומיין אחר שומר על הקידומת, מכיוון שה-URL ללא קידומת רק היה מפנה. תחת `no_prefix` קישור לדומיין אחר נוחת על locale ברירת המחדל של אותו host: ה-URL אינו יכול לציין locale שני.

דברים שכדאי לדעת:

- **מאחורי proxy** ה-host מגיע מ-`Host`. אם ה-proxy שם את ה-host הציבורי ב-`X-Forwarded-Host` במקום זאת, הגדירו [`trustForwardedHost`](/he/api/module-options#trustforwardedhost), ורק כאשר ה-proxy דורס את הכותרת הזו. proxy שאינו שולח אף אחת מהן אינו יכול להגיש build של דומיינים. ראו [מאחורי proxy או CDN](/he/guide/deployment#behind-a-proxy-or-cdn).
- **`app.baseURL`** שייך גם ל-`baseUrl`: `baseUrl: 'https://example.de/shop'` עם `app.baseURL: '/shop'`.
- **Hosts מותאמים במדויק.** `www.example.de` הוא host אחר: הפנו אותו ב-edge, או הגדירו את ה-`baseUrl` הזה על ה-locale. רק host אחד לכל locale.
- **מטמונים חייבים להיות ממופתחים לפי ה-host.** CDN בדרך כלל עושה זאת. מטמון ה-routes של Nitro ממופתח לפי הנתיב, ולכן ב-build של דומיינים המודול מוסיף `host` ל-`cache.varies` של כל כלל `swr` ו-`cache`, ו-`x-forwarded-host` עם `trustForwardedHost`. כלל עם `cache: false` נשאר כפי שנכתב. `isr` הוא המטמון של הפלטפורמה: ודאו שהוא ממופתח לפי ה-host.
- **נתיבים מותאמים אישית של שתי ברירות מחדל של hosts אסור שיתנגשו.** הרשומות ללא קידומת חולקות router אחד, ולכן `/x` אינו יכול להיות עמוד אחד ב-`example.de` ועמוד אחר ב-`example.com`.
- **עמודים שעברו prerender:** כלל route מסוג `prerender: true` ב-`nuxt build` מרנדר פעם אחת, ללא host, והקובץ עונה לכל הדומיינים. השאירו עמודים ששונים בין דומיינים לשרת, או [בצעו generate לכל דומיין](/he/guide/deployment#static-site-(nuxi-generate)).
- **`noPrefixRedirect`** פועל לפי ה-locale של ה-host ושל המבקר, בכל host.
- **`hashMode`:** ה-host בוחר את הרינדור כמתואר לעיל, קישורים לדומיין אחר נושאים את ה-route ב-hash (`https://example.com/#/contact`).
- **`ssr: false`:** הדפדפן קורא את הדומיין מ-`location.host`, כך ש-host ללא שרת עדיין נפתר.
- **[דריסות בזמן ריצה](/he/guide/runtime-overrides)** מוחלות ראשונות. `disabledLocales` בזמן ריצה תקף בכל host, עם חריג אחד: תחת `prefix_except_default` ו-`prefix_and_default` ברירת המחדל של host נשארת מופעלת ב-host שלה, מכיוון שהעמודים שלה הם הרשומות ללא קידומת. תחת `prefix` ו-`no_prefix` ה-host עובר ל-locale הבא שהוא מגיש. `defaultLocale` בזמן ריצה חל על hosts לא מוכרים בלבד.

עבור [אתר סטטי](/he/guide/deployment#static-site-(nuxi-generate)), בצעו generate פעם אחת לכל דומיין.

### אפליקציה אחת לכל דומיין {#one-app-per-domain}

שכבה משותפת עם אפליקציה קטנה אחת לכל דומיין עדיין עובדת, כאשר הדומיינים צריכים עמודים או מודולים שונים. כל אפליקציה מגדירה `defaultLocale` משלה על גבי אותה רשימת `locales`. locale בדומיין אחר מחזיר 404 באותה אפליקציה, כמתואר לעיל.

### בחירת ה-locale בקוד {#choosing-the-locale-in-code}

עבור מופע יחיד שעונה לכל הדומיינים עם ה-origin של הבקשה עצמה בתגיות SEO, ראו [SEO](/he/guide/seo#set-the-public-origin); כדי לבחור את ה-locale מתוך ה-host בקוד, ראו [זיהוי locale מותאם אישית](/he/guide/custom-auto-detect).
