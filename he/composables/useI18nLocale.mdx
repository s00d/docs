---
title: "useI18nLocale"
description: "useI18nLocale קורא וכותב את מצב ה-locale ואת ה-cookie של ה-locale — נקודת הכניסה לזיהוי locale מותאם אישית."
---

`useI18nLocale()` מעניק גישה ל-locale שהאפליקציה בחרה: ה-state `i18n-locale` וה-cookie של ה-locale. השתמשו בו ב-plugin שמזהה את ה-locale בעצמו (דומיין, פרופיל משתמש, header) במקום לכתוב ידנית ל-`useState('i18n-locale')` או ל-cookie. בדיקות התקינות שלו משתמשות ב-locales המופעלים, כולל דריסות בזמן ריצה.

## חתימה {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

נקודת כניסה מרכזית לניהול ה-locale של i18n.
משלב את useState('i18n-locale'), את ה-cookie של ה-locale ואת כלי הסנכרון.

## ערכים מוחזרים {#returned-values}

| חבר | טיפוס | תיאור |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | ה-ref של `useState('i18n-locale')`. |
| `localeCookie` | `Ref<string \| null>` | ה-cookie של [`localeCookie`](/he/api/module-options#localecookie); אובייקט פשוט `{ value: null }` כאשר האפשרות היא `null`. |
| `hashCookie` | `Ref<string \| null>` | ה-cookie `hash-locale` בניתוב hash; `{ value: null }` אחרת. |
| `validLocales` | `string[]` | הקודים של ה-locales המופעלים. |
| `setLocale(locale)` | `(locale: string \| null) => void` | כתיבת ה-state וה-cookies. אינו מאמת ואינו טוען תרגומים. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | כתיבת ה-cookies בלבד. |
| `getLocale()` | `() => string \| null` | ה-state, ואחריו cookie ההעדפה (cookie ה-hash בניתוב hash). לא מאומת. |
| `getPreferredLocale()` | `() => string \| null` | הערך ה**תקין** הראשון מבין ה-state ו-cookie ההעדפה, או `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | ה-state בניתוב hash כאשר הוא מוגדר; אחרת `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, אחריו state תקין, אחריו `options.serverLocale`, ואחריו ה-locale של הנתיב. שומר את התוצאה ב-state כאשר ה-state אינו תקין; בלקוח הוא גם כותב את ה-cookie. |
| `isValidLocale(locale)` | `(locale) => locale is string` | האם `locale` נמצא ב-`validLocales`. |

ה-cookies תקפים לשנה אחת, עם `path: '/'` ו-`sameSite: 'lax'`.

## דוגמה {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

ה-plugin של ה-loader של המודול קורא את ה-state כשהוא מתחיל, ולכן plugin שמגדיר אותו חייב לרוץ קודם (`enforce: 'pre'`). כיצד ה-state מתחרה ב-URL, ב-cookie וב-`Accept-Language`: [זיהוי locale](/he/guide/locale-detection). הדרכה מלאה: [זיהוי מותאם אישית](/he/guide/custom-auto-detect).

`setLocale()` אינו מחליף את התרגומים שעל המסך. כדי לשנות את ה-locale של העמוד הנוכחי, קראו ל-[`$switchLocale()`](/he/api/methods#$switchlocale).
