`@i18n-micro/react` ו-`@i18n-micro/preact` עוטפים את ה-[runtime](/he/integrations/runtime-package) שאינו תלוי ב-framework ב-provider, ב-hook בשם `useI18n()` ובארבעה רכיבים. השתמשו בהם באפליקציית React או Preact שאינה בנויה עם Nuxt. לשתי החבילות אותו API; הבלוק [Preact](#preact) מפרט את ההבדלים המעטים, והמודל המשותף מתואר ב-[Frameworks](/he/integrations/overview).

## התקנה {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/react
```

```bash npm
npm install @i18n-micro/react
```

```bash yarn
yarn add @i18n-micro/react
```

</CodeGroup>

תלויות peer: `react` `^18.0.0 || ^19.0.0`; `react-dom` (אופציונלי, לרינדור); `react-router-dom` `^6.0.0 || ^7.0.0` (אופציונלי, רק עבור `@i18n-micro/react/router`). נבדק על React 19.3 ו-18.3, React Router 7.18 ו-6.30.

## הגדרה {#setup}

```tsx
// src/main.tsx
import { createRoot } from 'react-dom/client'
import { createI18n, I18nProvider } from '@i18n-micro/react'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

createRoot(document.getElementById('root')!).render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
    <App />
  </I18nProvider>,
)
```

<Warning>

צרו את המופע פעם אחת, ברמת המודול או ב-initializer של `useState`, ולעולם לא בגוף של רכיב.

</Warning>

`<I18nProvider>` מקבל `i18n`, `locales`, `defaultLocale` ו-`routingStrategy`:

- prop שהושמט שומר על הערך של provider חיצוני, כולל המופע.
- כאשר אין מופע כלל, הוא בונה אחד מאפשרויות `createI18n` שלצידם, כך שה-props נשארים נתונים פשוטים: `<I18nProvider locale="de" messages={messages}>`.
- prop חדש של `locale` בונה מופע חדש עם ה-`messages` של אותו רינדור. מופע כזה חי ברכיב: אם משהו מעליו מבצע suspend במהלך ה-mount, React זורק אותו, יחד עם כל מה שנוסף אליו.

כל אפשרויות `createI18n`, כולל `routeMessages`, מפורטות ב-[המופע](/he/integrations/overview#the-instance).

## תרגום {#translate}

```tsx
import { useI18n } from '@i18n-micro/react'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' })}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

`useI18n()` מחזיר:

| קבוצה | חברים |
| --- | --- |
| תרגום | `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` |
| Locale ו-route | `locale`, `fallbackLocale`, `currentRoute`, `setLocale`, `setRoute`, `getRoute`, `getLocales`, `defaultLocale()`, `getLocaleName` |
| ניתוב | `switchLocale`, `localePath`, `localeRoute` |
| מילונים | `addTranslations`, `addRouteTranslations`, `clearCache` |

- הרכיב מתרנדר מחדש כאשר ה-locale, ה-route או מילון קריא משתנים, וכאשר ה-provider מקבל אובייקט `locales` או `routingStrategy` חדש. מילון של locale שאינו פעיל ואינו גיבוי אינו גורם לרינדור.
- `t` ושאר מתודות התרגום משתנות רק עם ה-store, ולכן הן בטוחות ב-`memo` וב-deps של effects.

`useT` הוא מחרוזת אחת כערך. הרכיב מתרנדר רק כאשר המחרוזת הזו משתנה, לא משנה מה קורה ל-props האחרים של ה-provider; גם `<I18nT>` אינו תלוי בהם:

```tsx
const title = useT('page.title')
```

טענו מילונים נוספים בכל עת:

```tsx
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

useEffect(() => {
  import('./locales/de.json').then((m) => addTranslations('de', m.default))
  addRouteTranslations('en', 'about', { title: 'About us' })
  setRoute('about') // t('title') now reads the 'about' dictionary first
}, [])
```

למופע עצמו יש גם `loadFromUrl(url, { locale, routeName })` עבור JSON דרך `fetch`.

## החלפת locale {#switch-locale}

```tsx
const { setLocale, switchLocale } = useI18n()

setLocale('de') // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

ההחלפה אינה טוענת דבר; הוסיפו קודם את המילון של ה-locale. כתיבה ל-store היא סינכרונית עבור React, אפילו בתוך `startTransition`, כך שרכיב שמבצע suspend על מילון חסר יציג את ה-fallback שלו. `useLocaleSwitch` טוען קודם ושומר על הממשק הישן עד שהמילון נטען:

```tsx
const [switchTo, pending] = useLocaleSwitch((locale) => i18n.loadFromUrl(`/locales/${locale}.json`, { locale }))

<button disabled={pending} onClick={() => switchTo('de')}>Deutsch</button>
```

הקריאה האחרונה גוברת. טעינה שנכשלה נדחית ומשאירה את ה-locale כפי שהיה.

`<I18nGroup>` מעביר `t` עם קידומת לילד מסוג render-prop. `<I18nT>` ו-`t()` בתוכו אינם מקבלים קידומת:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## ניתוב {#routing}

המתאם של React Router נמצא ב-subpath כך שנקודת הכניסה הראשית לעולם אינה מייבאת את `react-router-dom`. הוא צריך את `useLocation()` ו-`useNavigate()`, לכן צרו אותו בתוך רכיב מתחת ל-router:

```tsx
// src/App.tsx
import { useMemo } from 'react'
import { BrowserRouter, Route, Routes, useLocation, useNavigate } from 'react-router-dom'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/react'
import { createReactRouterAdapter } from '@i18n-micro/react/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Localized() {
  const location = useLocation()
  const navigate = useNavigate()
  // memoized: a new object on every render re-renders every `useI18n()` consumer
  const routingStrategy = useMemo(() => createReactRouterAdapter(locales, 'en', location, navigate), [location, navigate])
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      <Routes>
        <Route path="/:locale?" element={<Home />} />
        <Route path="/:locale?/about" element={<About />} />
      </Routes>
    </I18nProvider>
  )
}

export default function App() {
  return (
    <BrowserRouter>
      <Localized />
    </BrowserRouter>
  )
}
```

המתאם מוסיף קידומת לכל locale מלבד ברירת המחדל (`/about`, `/de/about`) ומרנדר את `<I18nLink>` כ-`<Link>` של React Router. הגדירו את ה-locale מתוך ה-URL בעצמכם (למשל מתוך `useParams().locale` ב-effect). עבור כל router אחר כתבו מתאם עם `getCurrentPath`, `push` ו-`replace` (כולם חובה) — ראו [מתאם router](/he/integrations/overview#router-adapter).

## SSR {#ssr}

`renderToString` עובד: ל-`useI18n()` יש snapshot של שרת. צרו מופע אחד לכל בקשה והוסיפו את המילונים שלו לפני הרינדור, כך שבקשות ב-locales שונים לא ישתפו מצב, או העבירו נתונים פשוטים ל-provider.

### Hydration {#hydration}

מספרים, צורות רבים וטקסט עוברים hydration כפי שהם. תאריך תלוי באזור הזמן ותאריך יחסי בשעון: הגדירו `timeZone` בשרת ובדפדפן, ועבור `tdr` מסרו לדפדפן את זמן השרת עם `now`. `<I18nT>` עם `date` או `relativeDate` מגדיר `suppressHydrationWarning`, כך שהבדל אינו מכשיל את ה-hydration, אבל הטקסט של השרת נשאר עד שהטקסט משתנה. זה מגיע לרמה אחת בלבד: `children` שעוטפים את התרגום באלמנט עדיין נכשלים בהבדל, לכן תנו להם את אותו `timeZone`.

### Server Components {#server-components}

החבילה מסמנת את קוד הלקוח שלה עם `'use client'`. ל-`@i18n-micro/react/server` יש `createI18n` ו-`I18nT` ללא hooks שמקבל את המופע כ-prop, כך שהטקסט נשאר מחוץ ל-bundle של הלקוח. תחת התנאי `react-server`, כמו ב-app router של Next.js, גם נקודת הכניסה הראשית נפתרת אליו, אבל TypeScript אינו יודע זאת כברירת מחדל: ייבאו מ-`/server`. `@i18n-micro/react/client` תמיד נותן את נקודת הכניסה של הלקוח.

```tsx
// app/[locale]/layout.tsx: a server component
import { cache } from 'react'
import { createI18n, I18nT } from '@i18n-micro/react/server'
import { I18nProvider } from '@i18n-micro/react/client'
import { loadMessages } from './messages'

const getI18n = cache(async (locale: string) => createI18n({ locale, messages: await loadMessages(locale) }))

export default async function Layout({ params, children }) {
  const { locale } = await params
  const i18n = await getI18n(locale)
  return (
    <I18nProvider locale={locale} messages={{ [locale]: i18n.resolveTranslations() }}>
      <h1>
        <I18nT i18n={i18n} keypath="title" />
      </h1>
      {children}
    </I18nProvider>
  )
}
```

רונדר באמצעות `react-server-dom-webpack`; אפליקציית Next.js עצמה טרם הורצה מול זה.

## Preact {#preact}

`@i18n-micro/preact` נבנה מאותו קוד מקור, על Preact עצמו, ללא `preact/compat`: אותו מופע, provider, hooks ורכיבים. הבדלים:

| | React | Preact |
| --- | --- | --- |
| תלות peer | `react` (+ `react-router-dom` אופציונלי) | `preact` `^10.0.0 \|\| ^11.0.0`, נבדק על 10.29 ו-11.1 |
| מחלקת המופע | `ReactI18n` | `PreactI18n` |
| מתאם router | `createReactRouterAdapter` מתוך `/router` | `createBrowserHistoryAdapter(locales, defaultLocale, ssrUrl?)` מתוך `/router` |
| רינדור מחדש | `useSyncExternalStore` | מנוי layout-effect שבודק מחדש את ה-store |
| Server Components | `/server`, `/client` | אין |

`createBrowserHistoryAdapter` עובד עם כל router מבוסס History API (wouter, preact-router): `push` ו-`replace` קוראים ל-`history.pushState` / `replaceState` ושולחים `popstate`, ו-`<I18nLink>` מרנדר `<a>` רגיל שמנווט דרך `push`. לשרת אין שורת כתובת: העבירו את ה-URL של הבקשה כ-`ssrUrl`, אחרת קישורים וה-switcher מתרנדרים כמו ב-`/`. בדפדפן שורת הכתובת גוברת.

```tsx
// src/main.tsx
import { render } from 'preact'
import { createI18n, I18nProvider } from '@i18n-micro/preact'
import { createBrowserHistoryAdapter } from '@i18n-micro/preact/router'
import { App } from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={createBrowserHistoryAdapter(locales, 'en')}>
    <App />
  </I18nProvider>,
  document.getElementById('app')!,
)
```

חתימות מלאות: [מדריך Preact](/he/api/packages/preact).
