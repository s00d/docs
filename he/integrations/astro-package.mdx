`@i18n-micro/astro` מתרגם עמודי Astro בשרת: middleware בוחר את השפה מתוך ה-URL ומציב מופע לכל בקשה ב-`Astro.locals`, ו-`useI18n(Astro)` קורא אותו. השתמשו בו באתר Astro שזקוק לכתובות URL עם קידומת שפה (`/about`, `/fr/about`) ולמילוני JSON משותפים. תקבלו רכיבי `.astro`, הפניה מדף הבית לשפת המבקר, תגיות `hreflang`, ו-props עבור [islands](/he/integrations/astro-islands).

## התקנה {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/astro
```

```bash npm
npm install @i18n-micro/astro
```

```bash yarn
yarn add @i18n-micro/astro
```

</CodeGroup>

תלויות עמית: ‏`astro` ‏`^5.0.0 || ^6.0.0 || ^7.0.0`. אופציונליות, רק עבור [islands](/he/integrations/astro-islands): ‏`vue` ‏`^3.3.0`, ‏`react` ‏`^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`, ‏`preact` ‏`^10.0.0 || ^11.0.0`, ‏`svelte` ‏`^4.0.0 || ^5.0.0`.

## הגדרה {#setup}

הוסיפו את האינטגרציה. היא אורזת את המילונים שלכם לתוך השרת ומתקינה את ה-middleware, כך שאין צורך ב-`src/middleware.ts`:

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import node from '@astrojs/node'
import { i18nIntegration } from '@i18n-micro/astro'

export default defineConfig({
  output: 'server',
  adapter: node({ mode: 'standalone' }),
  integrations: [
    i18nIntegration({
      locale: 'en',
      fallbackLocale: 'en',
      locales: [
        { code: 'en', iso: 'en-US', displayName: 'English' },
        { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
        { code: 'fr', iso: 'fr-FR', displayName: 'Français' },
      ],
      translationDir: 'src/locales',
    }),
  ],
})
```

המילונים הופכים לקוד בזמן הבנייה: השרת אינו קורא מהדיסק, ולכן הוא רץ גם ב-edge ‏(Cloudflare, ‏Vercel Edge). ב-`astro dev` עריכה של קובץ מוחלת בבקשה הבאה.

### אפשרויות האינטגרציה {#integration-options}

| אפשרות | ברירת מחדל | הערות |
| --- | --- | --- |
| `locale` | חובה | שפת ברירת המחדל. |
| `fallbackLocale` | `locale` | |
| `locales` | `[]` | אובייקטי `Locale` מלאים. שפה עם `disabled` אינה השפה של אף URL ואינה יעד להפניה. `iso` הוא התג שלפיו נקבעים כללי הרבים כאשר הקוד אינו תג כזה (`ua` → `uk-UA`). |
| `translationDir` | אין | תיקייה שנארזת לתוך השרת, יחסית לשורש הפרויקט. |
| `disablePageLocales` | `false` | קובצי עמודים נחשבים לתרגומי שורש. |
| `autoDetect` | `true` | הפניה מדף הבית, ראו [זיהוי שפה](#locale-detection). |
| `redirectToDefault` | `false` | `/` מפנה גם כאשר שום דבר אינו מעדיף שפה אחרת. |
| `localeCookie` | `'i18n-locale'` | `null` מבטל את העוגייה. |
| `missingWarn` | `false` | |
| `middleware` | `true` | `false`: כתבו את ה-middleware בעצמכם, ראו להלן. |

הגדרות זמן הריצה מתפרסמות ב-`virtual:i18n-micro/config` ‏(`config.base` הוא ה-`base` של Astro, ‏`config.localeCodes` הם הקודים הפעילים), והמילונים ב-`virtual:i18n-micro/messages`.

### Middleware משלכם {#your-own-middleware}

כלל רבים, מטפל במפתחות חסרים ו-router adapter אינם יכולים לעבור מתהליך התצורה אל ה-bundle של השרת. עבורם, העבירו `middleware: false` וכתבו `src/middleware.ts`. תצורת ה-`i18n` של Astro מוגדרת אז עבורכם עם `routing: 'manual'`, כך ש-`Astro.currentLocale` ו-`astro:i18n` עובדים. Astro אינו מאפשר הגדרה זו ללא `src/middleware.ts`, ולכן עם ה-middleware של האינטגרציה עצמה הם אינם עובדים.

```ts
// src/middleware.ts
import { config } from 'virtual:i18n-micro/config'
import { messages } from 'virtual:i18n-micro/messages'
import { createAstroRouterAdapter, createI18n, createI18nMiddleware, localeIsoMap } from '@i18n-micro/astro'

const i18n = createI18n({
  locale: config.defaultLocale,
  fallbackLocale: config.fallbackLocale,
  localeIso: localeIsoMap(config.locales),
  messages: messages.root,
  routeMessages: messages.routes,
  plural: myPluralRule,
})

export const onRequest = createI18nMiddleware({
  i18n,
  defaultLocale: config.defaultLocale,
  locales: config.localeCodes,
  localeObjects: config.locales,
  autoDetect: config.autoDetect,
  redirectToDefault: config.redirectToDefault,
  localeCookie: config.localeCookie,
  base: config.base,
  routingStrategy: createAstroRouterAdapter(config.locales, config.defaultLocale),
})
```

כדי לקרוא את התיקייה בזמן ריצה במקום זאת, `loadTranslationsFromDir` ו-`loadTranslationsIntoI18n` נמצאים ב-`@i18n-micro/astro/node` ‏(Node בלבד).

### אפשרויות ה-Middleware {#middleware-options}

| אפשרות | ברירת מחדל | הערות |
| --- | --- | --- |
| `i18n` | חובה | מופע גלובלי; כל בקשה מקבלת `i18n.fork(locale)`, שעלותו זהה ללא קשר למספר המילונים. |
| `defaultLocale` | חובה | |
| `locales` | חובה | קודי שפות. |
| `localeObjects` | `locales` בתור `{ code }` | אובייקטי `Locale` מלאים עבור רכיבים ו-SEO. |
| `autoDetect` | `true` | הפניה מדף הבית, ראו [זיהוי שפה](#locale-detection). |
| `redirectToDefault` | `false` | `/` מפנה גם כאשר שום דבר אינו מעדיף שפה אחרת, אל דף הבית של שפת ברירת המחדל כפי שאסטרטגיית הניתוב מחשבת אותו. |
| `localeCookie` | `'i18n-locale'` | `null` מבטל את העוגייה. |
| `routingStrategy` | קידומת למעט ברירת המחדל | Router adapter. מתודות שהוא משמיט מגיעות מה-adapter ברירת המחדל. |
| `base` | אין | ה-`base` של Astro: ‏`config.base`. |

קובצי עמודים (`src/locales/pages/blog/post/de.json`) הם הנתיב `blog-post`: נתיב העמוד מחובר עם `-`.

## תרגום {#translate}

```astro
---
// src/pages/index.astro
import { useI18n } from '@i18n-micro/astro'
import I18nT from '@i18n-micro/astro/i18n-t'

const { t, tc, locale } = useI18n(Astro)
---

<h1>{t('greeting', { name: 'Ada' })}</h1>
<p>{tc('apples', 3)}</p>
<I18nT keypath="welcome" tag="p" />
<p>{locale}</p>
```

`useI18n(Astro)` מחזיר את `locale`, `defaultLocale`, `locales`, `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `getRoute`, `getRouteName(path?)`, `getLocaleFromPath(path?)`, `switchLocalePath(locale)`, `localizePath(path, locale?)`, `getBasePath(url?)`, `getI18n`, `addTranslations`, `addRouteTranslations`, `mergeTranslations` ו-`clearCache`. הוא זורק שגיאה כאשר ה-middleware לא רץ. פונקציות העזר `getI18n`, `getLocale`, `getDefaultLocale` ו-`getLocales` קוראות את אותו `Astro.locals`.

שם הנתיב מגיע מהנתיב ללא השפה שלו: `/fr/blog/post` → `blog-post`, וכל URL של `src/pages/blog/[slug].astro` → `blog-slug`, כך שתיקייה אחת `locales/pages/blog-slug/` משרתת את כולם. `[...path]` הוא `path`. תחת ה-`base` של Astro, פונקציות העזר מקבלות ומחזירות כתובות URL של האתר: `switchLocalePath` ו-`localizePath` כוללות אותו, `getBasePath` לא, כי `Astro.rewrite` מקבל את הנתיב בלעדיו.

### רכיבים {#components}

ייבאו אותם מ-`@i18n-micro/astro/<name>` (או מ-`@i18n-micro/astro/components/<name>.astro`):

| רכיב | Props |
| --- | --- |
| `i18n-t` | `keypath`, `params`, `plural`, `number`, `date`, `relativeDate`, `tag` (`span`, כל תג), `html`, `hideIfEmpty`, `defaultValue`; מאפיינים אחרים מועברים הלאה. עם `html` התוצאה של כל ענף מוצגת כ-HTML ו-`params` עוברים escaping. אין slots |
| `i18n-link` | `href`, `locale` (שפת היעד, ברירת מחדל הנוכחית), `class`; מאפיינים אחרים מועברים הלאה. כתובות URL חיצוניות, `#hash` ו-`?query` נשארים כפי שנכתבו; נתיב שומר על ה-query, ה-hash והלוכסן הסופי שלו |
| `i18n-switcher` | `class`, `activeClass` (`'active'`), `customLabels`; מציג קישורים לעמוד הנוכחי בכל שפה פעילה, עם ה-query שלו |
| `i18n-group` | אין כאלה שמשנים את הפלט: `<div>` סביב ה-slot שלו, ללא קידומת |

## נתיבים עם קידומת שפה {#locale-prefixed-routes}

שמרו עמוד אחד לכל נתיב ב-`src/pages/` והוסיפו stubs דקים של rewrite תחת `src/pages/[locale]/`:

```
src/pages/
  index.astro
  about.astro
  [locale]/
    index.astro
    about.astro
```

```astro
---
// src/pages/[locale]/about.astro
import { prepareLocaleRewrite } from '@i18n-micro/astro'

const target = prepareLocaleRewrite(Astro)
if (target instanceof Response) return target
return Astro.rewrite(target)
---
```

`prepareLocaleRewrite` מחזיר תגובת `404` עבור `:locale` לא מוכר, ואחרת מגדיר את השפה ב-`Astro.locals` ומחזיר את הנתיב ללא הקידומת. ה-middleware שומר על שפה שכבר נמצאת ב-`locals`, כך שהעמוד שעבר rewrite מוצג בה. `getLocaleRewritePath(Astro)` מחזיר רק את הנתיב, כאשר אתם מאמתים את השפה בעצמכם.

## זיהוי שפה {#locale-detection}

ה-URL קובע את שפת העמוד:

1. קידומת שפה (`/fr/about` → `fr`; גם `/en/about` הוא `en`).
2. אחרת, מה שה-`getLocaleFromPath` של ה-router adapter מחזיר, אם זו אינה ברירת המחדל.
3. אחרת, שפת ברירת המחדל. `/about` הוא תמיד העמוד של שפת ברירת המחדל, לא משנה מה העוגייה אומרת.

`autoDetect` הוא רמז להפניה בדף הבית בלבד:

- בקשה ל-`/` שהעוגייה או ה-`Accept-Language` שלה מעדיפים שפה אחרת מקבלת `302` לדף הבית של אותה שפה (`/de`). משקלי q נלקחים בחשבון; `de-DE` תואם לשפה `de`, ו-`de` תואם לשפה `de-DE`.
- עם `redirectToDefault`, ‏`/` תמיד מפנה: לדף הבית של השפה המועדפת, ואחרת לזה של שפת ברירת המחדל.
- תגובת `/` נושאת `Vary: Cookie, Accept-Language` (רק `Accept-Language` כאשר `localeCookie` הוא `null`).
- עמודים שעברו prerender לעולם אינם מפנים.

`detectLocale(pathname, cookies, headers, defaultLocale, locales, localeCookie?, routingStrategy?, autoDetect?)` מחזיר את אותה שפה מועדפת עבור הלוגיקה שלכם.

העוגייה זוכרת בחירה. צפייה בעמוד שמגיעה מעמוד באותו מקור (same-origin) בשפה אחרת היא מבקר שמחליף שפה, לא משנה איזה קישור הביא אותו: תגובת ה-HTML מגדירה את העוגייה לשפה החדשה, ו-`/` אינו מפנה, כך שמחליף שפות מגיע לדף הבית של שפת ברירת המחדל. Endpoint, תמונה, 404, שליחת טופס ו-prefetch אינם משנים דבר. "אותו מקור" הוא מה שהדפדפן אומר ב-`Sec-Fetch-Site`; ללא header זה, ה-host של ה-`Referer` מושווה לזה של הבקשה, ולכן מאחורי proxy הגדירו את `security.allowedDomains` של Astro.

ל-[server island](https://docs.astro.build/en/guides/server-islands/) או ל-action אין שפה ב-URL שלהם. הם מוצגים עבור העמוד שביקש אותם, שנקרא מתוך ה-`Referer`, שרק הנתיב שלו נחשב, כך ש-proxy מול השרת אינו משנה דבר, והם לעולם אינם מפנים. התגובה שלהם נושאת `Vary: Referer`. ללא `Referer` (מדיניות `no-referrer`) הם בשפת ברירת המחדל, ובעמוד דינמי הנתיב שלהם מגיע מה-URL, כך שמילוני העמוד אינם מגיעים אליהם.

## Router adapter {#router-adapter}

`createAstroRouterAdapter(locales, defaultLocale)` מוסיף קידומת לכל שפה למעט ברירת המחדל. Adapter של Astro צריך רק את `getCurrentPath`; שאר החברים אופציונליים ונופלים חזרה ל-adapter ברירת המחדל: `getRouteName(path, locales, routePattern?)`, `getLocaleFromPath`, `switchLocalePath`, `localizePath`, `removeLocaleFromPath`, `resolvePath` (יעד ההפניה מדף הבית), `push`, `replace`, `getRoute`. כתבו adapter משלכם עבור כתובות עם תת-דומיין או סיומת והעבירו אותו ל-`createI18nMiddleware`.

## SEO {#seo}

```astro
---
// src/layouts/Layout.astro
import { useLocaleHead } from '@i18n-micro/astro'

const head = useLocaleHead(Astro, { baseUrl: 'https://example.com' })
---

<html lang={head.htmlAttrs.lang} dir={head.htmlAttrs.dir}>
  <head>
    {head.link.map((l) => <link rel={l.rel} href={l.href} hreflang={l.hreflang} />)}
    {head.meta.map((m) => <meta property={m.property} content={m.content} />)}
  </head>
  <body><slot /></body>
</html>
```

הוא מחזיר את `htmlAttrs` (`lang` מתוך `iso`, `dir`), קישור canonical (נתיב ללא query), חלופות `hreflang` לכל שפה פעילה עם `seo !== false` ועוד `x-default`, ‏`og:locale`, ‏`og:locale:alternate` ו-`og:url`. אפשרויות: `baseUrl` (`site` מתצורת Astro, ואחרת כתובות URL יחסיות לשורש), `addDirAttribute` (`true`), `addSeoAttributes` (`true`), `hreflangBaseLanguage` (`false`).
