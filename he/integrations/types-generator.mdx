---

`@i18n-micro/types-generator` קורא כל קובץ JSON בתיקיית התרגומים שלכם וכותב הצהרה שמפרטת את כל המפתחות. הוסיפו אותו כשאתם רוצים שהעורך שלכם יציע מפתחות ב-`t()`, ב-`$t()` וב-`<I18nT keypath>`. הוא עובד כמודול Nuxt וכפלאגין Vite או Rollup, ומייצר מחדש כאשר קובץ משתנה.

## התקנה {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/types-generator
```

```bash npm
npm install -D @i18n-micro/types-generator
```

```bash yarn
yarn add -D @i18n-micro/types-generator
```

</CodeGroup>

תלות עמית (peer dependency): ‏`@nuxt/kit` ‏`^3.18.0 || ^4.0.0`. רק נקודת הכניסה `/nuxt` מייבאת אותה; בפרויקט Vite בלבד ניתן להתעלם מאזהרת ה-peer.

## Nuxt {#nuxt}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@i18n-micro/types-generator/nuxt'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    translationDir: 'locales',
  },
})
```

המודול כותב את `.nuxt/types/i18n-micro.d.ts` ו-Nuxt מוסיף אותו להקשר הטיפוסים; אין צורך לכלול דבר ידנית. הוא קורא את `i18nTypes.translationDir`, ואחרת את המקום שממנו `nuxt-i18n-micro` קורא תרגומים: `translationDir` (מתוך `i18n` או מאפשרויות מודול מוטבעות, ברירת מחדל `'locales'`) בכל שכבה, ו-`additionalTranslationDirs`. עריכת קובץ JSON תחת אותה תיקייה מייצרת מחדש את הטיפוסים ב-`nuxi dev`. ‏`i18nTypes.outputFile` מתעלמים ממנו ב-Nuxt (אזהרה מציינת זאת).

## Vite {#vite}

`I18nTypesPlugin` הוא פלאגין Vite, ש-Rollup מקבל גם הוא. עבור bundler אחר, קראו ל-`generateTypes` בסקריפט.

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { I18nTypesPlugin } from '@i18n-micro/types-generator'

export default defineConfig({
  plugins: [
    vue(),
    I18nTypesPlugin({
      srcDir: process.cwd(),
      translationDir: 'src/locales',
      outputFile: 'src/i18n-micro.d.ts',
    }),
  ],
})
```

| אפשרות | חובה | הערות |
| --- | --- | --- |
| `srcDir` | כן | תיקיית הבסיס; `translationDir` מחושב ביחס אליה. |
| `translationDir` | כן | תיקייה עם קובצי ה-JSON (כולל תיקיות משנה כמו `pages/`), או מערך של תיקיות. |
| `outputFile` | לא | היכן לכתוב את ההצהרה; ברירת מחדל `<srcDir>/i18n-micro.d.ts`. |

הפלאגין מייצר פעם אחת בתחילת הבנייה, ובשרת הפיתוח מייצר מחדש 300 ms אחרי שינוי בתיקייה. ודאו שה-`include` ב-`tsconfig.json` שלכם מכסה את קובץ הפלט.

## שימוש במפתחות {#use-the-keys}

הקובץ שנוצר מרחיב את `DefineLocaleMessage` ב-`@i18n-micro/types`, מה שהופך את `TranslationKey` למפתחות שלכם:

```ts
declare module '@i18n-micro/types' {
  export interface DefineLocaleMessage {
    nav: object
    'nav.home': string
    'profile.title': string
  }
}
```

המפתחות הם אלה ש-`t()` עונה עליהם, כולל אובייקטים, מכל שפה ומכל קובץ עמוד, עם הטיפוס של ערך ה-JSON שלהם. `TranslationKey` הוא האיחוד של מפתחות אלה ועוד כל מחרוזת, כך שתקבלו השלמה אוטומטית, לא שגיאות: מפתח עם שגיאת כתיב או מפתח דינמי עדיין מתקמפל. פרמטרים וערכי החזרה אינם מוגדרים בטיפוסים.

עבור מפתחות דינמיים תחת קידומת ידועה, `ScopedKey<'prefix'>` מצמצם למפתחות התואמים:

```ts
import type { ScopedKey } from '@i18n-micro/types'

const statusText = (status: string) => t(`status.${status}` as ScopedKey<'status'>)
```

`TranslationKey` ו-`ScopedKey` מגיעים מ-`@i18n-micro/types` ‏(React, ‏Preact ו-Solid מייצאים מחדש את `TranslationKey`; ‏Vue לא).

## API {#api}

| ייצוא | נקודת כניסה | הערות |
| --- | --- | --- |
| `I18nTypesPlugin(options)` | `@i18n-micro/types-generator` | פלאגין Vite ו-Rollup |
| `generateTypes(options)` | `@i18n-micro/types-generator` | כותב את הקובץ, מחזיר את הנתיב שלו |
| `getTypesString(options)` | `@i18n-micro/types-generator` | מחזיר את ההצהרה בלי לכתוב |
| `formatKeyProperty(key)` | `@i18n-micro/types-generator` | פונקציית עזר |
| מודול Nuxt (`configKey: 'i18nTypes'`) | `@i18n-micro/types-generator/nuxt` | אפשרות `translationDir` |

חתימות מלאות: [עיון בחבילה](/he/api/packages/types-generator).
