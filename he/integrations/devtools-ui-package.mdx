`@i18n-micro/devtools-ui` הוא עורך התרגומים מלשונית ה-Nuxt DevTools, ארוז כ-web component עם plugin של Vite. הוסיפו אותו לפרויקט Vue, React, Preact, Solid או Astro כדי לעיין ולערוך את קובצי ה-JSON שבתיקיית התרגומים שלכם מהדפדפן במהלך הפיתוח. באפליקציות Nuxt הוא כבר קיים ב-[Nuxt DevTools](/he/guide/devtools).

![The DevTools UI: a file tree and an editor with the default-locale text next to each key](/images/devtools/02-translations-editor-dark.webp)

## התקנה {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/devtools-ui
```

```bash npm
npm install -D @i18n-micro/devtools-ui
```

```bash yarn
yarn add -D @i18n-micro/devtools-ui
```

</CodeGroup>

אין תלויות peer.

## הגדרה {#setup}

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import { i18nDevToolsPlugin } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  plugins: [i18nDevToolsPlugin({ translationDir: 'src/locales' })],
})
```

| אפשרות | ברירת מחדל | הערות |
| --- | --- | --- |
| `translationDir` | `'src/locales'` | התיקייה עם קובצי ה-JSON, יחסית לשורש של Vite. |
| `base` | `'/__i18n_api'` | נתיב הבסיס של נקודות הקצה של ה-API. |
| `injectButton` | `true` | הוספת כפתור צף לעמודים שמוגשים דרך טרנספורמציית ה-`index.html` של Vite. ל-Astro אין עמודים כאלה: ראו בהמשך. |
| `defaultLocale` | קובץ ה-locale הראשון ב-`translationDir` | מדווח על ידי `/config`. |
| `fallbackLocale` | `defaultLocale` | מדווח על ידי `/config`. |

ה-plugin רץ בשרת הפיתוח בלבד (`apply: 'serve'`); build של production אינו מכיל ממנו דבר. הכפתור פותח את `/__i18n_devtools.html`, שקורא ושומר קבצים דרך נקודות הקצה של ה-plugin:

| נקודת קצה | פעולה |
| --- | --- |
| `GET <base>/translations` | כל מילון תחת `translationDir`, לפי נתיב יחסי |
| `POST <base>/save` | גוף `{ file, content }`; דורס קובץ `.json` קיים בתוך `translationDir`, 403 לכל דבר אחר. הוא לעולם אינו יוצר קובץ |
| `GET <base>/config` | `{ defaultLocale, fallbackLocale, locales, translationDir }`; `locales` מגיעים מקובצי השורש ב-`translationDir` |

נקודות הקצה עונות לעמוד ה-devtools בלבד: בקשה ממקור (origin) או host אחר מקבלת `403`, ו-`/save` מקבל `application/json` בלבד (`415`). העמוד מקבל עדכונים על שינויי קבצים דרך ה-socket של HMR של Vite.

ב-Astro, הוסיפו את ה-integration במקום ה-plugin. הוא מוסיף אפליקציה לסרגל הכלים של הפיתוח:

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import { i18nDevToolsIntegration } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  integrations: [i18nDevToolsIntegration({ translationDir: 'src/locales' })],
})
```

שמירה כותבת את הקובץ בלבד. אפליקציה שמייבאת את ה-JSON דרך Vite מקבלת אותו דרך HMR; לעריכות שיוחלו ישירות על המופע הרץ, השתמשו בגשר.

## גשר למופע חי {#bridge-to-a-live-instance}

כדי להטמיע את העורך בעמוד משלכם ולהחיל עריכות על המופע הרץ באופן מיידי, צרו גשר מ-adapter והעבירו אותו לאלמנט `<i18n-devtools-ui>`:

```ts
import { createBridge, register } from '@i18n-micro/devtools-ui'
import { i18n, locales } from './i18n' // a runtime, React, Preact or Solid instance

register() // defines <i18n-devtools-ui> once

const bridge = createBridge({
  adapter: {
    getRouteCache: () => Object.fromEntries(i18n.storage.translations),
    addTranslations: (locale, content, merge) => i18n.addTranslations(locale, content, merge),
    addRouteTranslations: (locale, route, content, merge) => i18n.addRouteTranslations(locale, route, content, merge),
    subscribe: (cb) => i18n.subscribe(cb),
    getCurrentLocale: () => i18n.locale,
  },
  locales,
  defaultLocale: 'en',
  translationDir: 'src/locales',
})

const el = document.createElement('i18n-devtools-ui') as HTMLElement & { bridge: typeof bridge }
el.bridge = bridge
document.body.append(el)
```

`getRouteCache` חייב להחזיר את המילונים עם מפתחות בצורה `locale:route` (`en:index`, `en:blog-post`), וזה מה ש-`i18n.storage.translations` מחזיק. עבור מופע Vue השתמשו ב-`i18n.global.getRouteCache()` וב-`i18n.global.subscribeToChanges(cb)`.

`saveTranslation` מעדכן קודם את המופע, ולאחר מכן שולח POST אל `<base>/save`. כאשר אין נקודת קצה (build תצוגה מקדימה סטטי) או שלא ניתן להגיע לשרת הפיתוח, העריכה נשמרת ב-`localStorage`; כל שגיאת שמירה אחרת משחזרת את המילון הקודם וזורקת שגיאה.

| ייצוא | נקודת כניסה |

| `createRpcClient`, `setupRpcHost` | `@i18n-micro/devtools-ui` |
