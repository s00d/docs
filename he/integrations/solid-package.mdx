`@i18n-micro/solid` מעניק לאפליקציות SolidJS מופע i18n מבוסס signals, provider, `useI18n()` וארבעה רכיבים. השתמשו בו באפליקציית Solid שאינה בנויה עם Nuxt. קריאות ל-`t()` בתוך JSX או effects עוקבות אחר ה-locale, ה-route והמילונים; המודל המשותף מתואר ב-[Frameworks](/he/integrations/overview).

## התקנה {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

תלויות peer: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (אופציונלי, רק עבור `@i18n-micro/solid/router`). Solid 2 עדיין אינו נתמך.

## הגדרה {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` מקבל `i18n`, `locales`, `defaultLocale` ו-`routingStrategy`; prop שהושמט שומר על הערך של ה-provider החיצוני, כולל המופע. `getLocaleName()` ו-`<I18nSwitcher>` קוראים את `locales`; בלעדיהם אין להם מה להציג. האפשרויות מפורטות ב-[המופע](/he/integrations/overview#the-instance). המופע הוא זה של ה-[runtime](/he/integrations/runtime-package), עם signal אחד מעל ה-store שלו.

## תרגום {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

קראו למתודות בתוך JSX או effect כדי ש-Solid יעקוב אחריהן, וגם ל-`localePath` ו-`getLocale`; ערך שנקרא פעם אחת בגוף הרכיב אינו מתעדכן. במופע, עקבו באמצעות `i18n.locale` ו-`i18n.currentRoute`: `i18n.getLocale()` נשאר רגיל, מכיוון שפעולות כתיבה קוראות אותו. קריאת ה-locale מתעוררת רק על ה-locale, כך ש-effect שקורא אותו וטוען מילון רץ פעם אחת. אל תפרקו props ואל תשמרו תוצאות `t('key')` במשתנים רגילים.

`useI18n()` מחזיר `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` ו-`instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## החלפת locale {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

ההחלפה אינה טוענת דבר; הוסיפו קודם את המילון של ה-locale.

`<I18nGroup>` מעביר `t` עם קידומת לילד שהוא פונקציה. `<I18nT>` ו-`t()` בתוכו אינם מקבלים קידומת:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## ניתוב {#routing}

המתאם של `@solidjs/router` נמצא ב-subpath כך שנקודת הכניסה הראשית לעולם אינה מייבאת את ה-router. קראו לו מתחת ל-router, בדרך כלל ב-`root` של ה-router, שם `useNavigate` ו-`useLocation` עובדים:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

המתאם מוסיף קידומת לכל locale מלבד ברירת המחדל (`/about`, `/de/about`), ומרנדר את `<I18nLink>` כ-`<A>` של ה-router. `getCurrentPath` קורא את המיקום הריאקטיבי של ה-router, כך שקישורים פעילים וה-switcher עוקבים אחריו; אסטרטגיה מותאמת אישית מקבלת את אותו הדבר על ידי קריאת signal שם. שימו לב לסדר הארגומנטים: `(locales, defaultLocale, navigate, location)`. עבור routers אחרים כתבו מתאם עם `getCurrentPath`, `push` ו-`replace` (כולם חובה) — ראו [מתאם router](/he/integrations/overview#router-adapter).

## SSR {#ssr}

לרינדור בשרת, בנו עם `vite-plugin-solid`: תנאי הייצוא `solid` של החבילה מעביר לו את קוד המקור, כך שהוא מהודר עבור השרת. ה-`dist` הבנוי מראש מיועד לדפדפן בלבד. למופע אין `destroy()`; צרו אחד לכל אפליקציה, או אחד לכל בקשה בשרת, ותנו ל-garbage collector לאסוף אותו.
