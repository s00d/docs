### תיאור

משווה **plain Nuxt** (baseline ללא מודול i18n), **i18n-micro** ו-**`@nuxtjs/i18n` v10.6** תחת פרופיל מילון משותף אחד.

מיקוד: זמן build, RSS שיא, **קוד לעומת תרגומים לעומת סך הכל** ניתן לפריסה, והתנהגות שרת תחת Artillery + Autocannon.

### הערות מתודולוגיה

- מדדים הם **ממוצעים של 3 ריצות רצופות לכל fixture** (fixture A ×3, אחר כך B ×3, אחר כך C ×3 — לא משולבים).
- **Translations** כוללים JSON של locale תחת `locales/` / `_locales/` / `translations/`, כל מה שתחת `chunks/raw/`, ו-chunks locale תואמים. דוחות ישנים שהראו `@nuxtjs/i18n` "translations: 0 B" ועמודת "code" ענקית ספרו message chunks כקוד אפליקציה.
- **plain-nuxt** מגיש את אותו נפח leaves כ-JSON סטטי `public/translations` (לא ייבוא JS סטטי). תחת Artillery ה-baseline הוא I/O-heavy; זה לא "תקורת i18n", זה העלות של הבאת JSON גדול לכל בקשה.

### ריצות

כל המדדים למטה הם **ממוצעים על פני 3 ריצות**.

## הערות

- פרופיל משותף: 4 locales × 2 pages × ~16.8k index leaves.
- Artillery: 6s warm-up @6 VU/s + 60s main @60 VU/s. Autocannon: 10 connections × 10s.
- הריצו שוב: `pnpm test:performance` או `pnpm -C scripts cli performance --locales N --keys K --only all|micro|i18n|plain --runs N`.
