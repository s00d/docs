`@i18n-micro/vue` ist ein Vue-3-Plugin mit dem Übersetzungskern von Nuxt I18n Micro: reaktives `t()`, globales `$t`, vier Komponenten und ein optionaler vue-router-Adapter. Verwenden Sie es in einer Vite- oder SSR-Vue-App, die nicht mit Nuxt gebaut wird. Das Instanzmodell, der Router-Vertrag und die Komponenten-Props werden mit den anderen Paketen geteilt und unter [Frameworks](/de/integrations/overview) beschrieben.

## Installation {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vue
```

```bash npm
npm install @i18n-micro/vue
```

```bash yarn
yarn add @i18n-micro/vue
```

</CodeGroup>

Peer-Abhängigkeiten: `vue` `^3.3.0`; `vue-router` `^4.5.1 || ^5.0.0` (optional, nur für `@i18n-micro/vue/router`). Die veröffentlichten Typen benötigen Vue 3.5.5 oder neuer bei `skipLibCheck: false`; mit `skipLibCheck: true`, der üblichen Template-Einstellung, kompilieren auch ältere Versionen.

## Einrichtung {#setup}

```ts
// src/main.ts
import { createApp } from 'vue'
import { createI18n } from '@i18n-micro/vue'
import App from './App.vue'
import en from './locales/en.json'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales: [
    { code: 'en', iso: 'en-US', displayName: 'English' },
    { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
  ],
  defaultLocale: 'en',
})

createApp(App).use(i18n).mount('#app')
```

`locales` und `defaultLocale` sind für `useI18n()` erforderlich: Ohne sie wirft es `I18nLocalesKey not provided`. Übergeben Sie sie an `createI18n` (wie oben), an `useI18n({ locales, defaultLocale })` oder über `app.provide(I18nLocalesKey, …)` und `app.provide(I18nDefaultLocaleKey, …)`.

Das Plugin registriert `I18nT`, `I18nLink`, `I18nGroup` und `I18nSwitcher` global und stellt `$t`, `$ts`, `$tc`, `$tn`, `$td`, `$tdr`, `$has` und `$i18n` in Templates bereit. Außerhalb von Komponenten ist die Instanz `i18n.global`. Weitere Optionen finden Sie unter [Die Instanz](/de/integrations/overview#the-instance); `routeMessages` ist in Vue nicht verfügbar, verwenden Sie `addRouteTranslations`.

## Übersetzen {#translate}

```vue
<script setup lang="ts">
import { useI18n } from '@i18n-micro/vue'

const { t, tc, tn } = useI18n()
</script>

<template>
  <h1>{{ t('greeting', { name: 'Ada' }) }}</h1>
  <!-- Hello, Ada! -->
  <p>{{ tc('apples', 3) }}</p>
  <!-- 3 apples -->
  <p>{{ $t('nav.home') }} · {{ tn(1234.5) }}</p>
</template>
```

`useI18n()` gibt die Übersetzungsmethoden (`t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`), `locale` (ein beschreibbares Computed), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `localePath`, `localeRoute`, `switchLocale`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `mergeTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` und `instance` zurück.

Laden Sie jederzeit weitere Wörterbücher; jede Komponente, die sie liest, wird neu gerendert:

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Locale wechseln {#switch-locale}

```ts
const { locale, switchLocale } = useI18n()

locale.value = 'de' // only the locale
switchLocale('de') // the locale, then router.push to the localized current path
```

Laden Sie das Wörterbuch der Locale vor oder nach dem Wechsel; der Wechsel selbst ruft nichts ab.

`<I18nGroup>` gibt seinem Slot ein `t` mit Präfix. Schlüssel innerhalb von `<I18nT>` oder in einem einfachen `t()` erhalten kein Präfix:

```vue
<I18nGroup prefix="profile" v-slot="{ t }">
  <h2>{{ t('title') }}</h2>
  <!-- profile.title -->
</I18nGroup>
```

## Routing {#routing}

Der vue-router-Adapter liegt in einem Subpath, sodass der Haupteinstiegspunkt `vue-router` nie importiert:

```ts
// src/main.ts
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import { createI18n } from '@i18n-micro/vue'
import { createVueRouterAdapter } from '@i18n-micro/vue/router'
import App from './App.vue'
import Home from './pages/Home.vue'
import About from './pages/About.vue'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/:locale(de)?', component: Home },
    { path: '/:locale(de)?/about', component: About },
  ],
})

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales,
  defaultLocale: 'en',
  routingStrategy: createVueRouterAdapter(router, locales, 'en'),
})

createApp(App).use(router).use(i18n).mount('#app')
```

`createVueRouterAdapter(router, locales, defaultLocale)` versieht jede Locale außer der Standard-Locale mit einem Präfix (`/about`, `/de/about`) und rendert `<I18nLink>` als `RouterLink`. Lesen Sie die Locale selbst aus der Route, zum Beispiel in `router.beforeEach`, und setzen Sie `i18n.global.locale.value`. Sie können einen Adapter auch später mit `i18n.setRoutingStrategy(adapter)` anhängen; für einen eigenen Adapter siehe [Router-Adapter](/de/integrations/overview#router-adapter).

## SSR {#ssr}

- Erstellen Sie den Router, die i18n-Instanz und die App innerhalb der Render-Funktion pro Anfrage. Eine gemeinsam genutzte Instanz würde die Locale eines Besuchers an einen anderen weitergeben.
- Verwenden Sie auf dem Server `createMemoryHistory()`, entnehmen Sie die Locale der URL und laden Sie ihr Wörterbuch (und das der Fallback-Locale) vor `renderToString`.
- Senden Sie die Locale an den Client (zum Beispiel in einem `window.__STATE__`-Script) und erstellen Sie die Client-Instanz mit derselben `locale`, damit die Hydration übereinstimmt.
- `<I18nSwitcher>` liest `window.location` nur, wenn das Dropdown geöffnet ist, und lässt sich daher auf dem Server rendern.

`packages/vue/playground` enthält ein vollständiges Paar aus `entry-server.ts` / `entry-client.ts`.

## SEO-Head {#seo-head}

`useLocaleHead(options)` erzeugt `lang`/`dir`, Canonical-, `hreflang`- und `og:locale`-Tags aus den Locales und dem Router-Adapter. Rufen Sie `updateMeta()` auf, wenn sich die Route ändert, und übergeben Sie `metaObject` an Ihren Head-Manager:

```ts
import { watch } from 'vue'
import { useRoute } from 'vue-router'
import { useHead } from '@unhead/vue'
import { useLocaleHead } from '@i18n-micro/vue'

const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
watch(() => route.fullPath, () => updateMeta(), { immediate: true })
useHead(metaObject)
```

Optionen: `baseUrl` (String oder Funktion), `addDirAttribute` (Standard `true`), `addSeoAttributes` (Standard `true`), `identifierAttribute` (Standard `'id'`), `hreflangBaseLanguage` (Standard `false`). Locales mit `disabled: true` oder `seo: false` erhalten keinen Alternate-Link.

| Export | Einstiegspunkt |
| --- | --- |
| `createI18n`, `useI18n`, `useLocaleHead` | `@i18n-micro/vue` |
| `I18nT`, `I18nLink`, `I18nSwitcher`, `I18nGroup` | `@i18n-micro/vue` |
| `VueI18n` (Instanzklasse), `I18nInjectionKey`, `I18nLocalesKey`, `I18nDefaultLocaleKey` | `@i18n-micro/vue` |
| `defaultPlural`, `FormatService`, `interpolate` | `@i18n-micro/vue` |
| Typen: `I18nRoutingStrategy`, `Locale`, `Translations`, `PluralFunc`, `Params`, `Getter`, `CleanTranslation`, `LocaleCode`, `VueI18nOptions`, `UseI18nOptions`, `UseLocaleHeadOptions`, `I18nPlugin` | `@i18n-micro/vue` |
