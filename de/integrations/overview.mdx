# Integrationen

Die `@i18n-micro`-Pakete sind schlanke, framework-spezifische Varianten von Nuxt I18n Micro für die Integration in verschiedene Frameworks und Umgebungen. Sie liefern Kern-Internationalisierung mit minimalem Footprint und Fokus auf zentrale Übersetzungsfunktionen und Basiskomponenten.

## Überblick

Diese Integrations-Pakete sind **Miniaturversionen** des vollständigen Nuxt-I18n-Micro-Moduls und enthalten nur das für Internationalisierung Nötige:

- **Kern-Übersetzungsfunktionen**: grundlegende Übersetzungsmethoden, Pluralisierung und Formatierung.
- **Wesentliche Komponenten**: eine kleine Auswahl an UI-Komponenten für gängige i18n-Aufgaben.
- **Router-Adapter-Muster**: flexible Routing-Integration über eine Adapter-Abstraktion.
- **TypeScript-Unterstützung**: vollständige Typdefinitionen für typsichere Entwicklung.

Anders als das vollständige Nuxt-Modul:

- Keine framework-spezifische Routing-Logik enthalten.
- Für Routing implementierst du einen Router-Adapter.
- Fokus auf Übersetzungsfunktionalität statt auf Framework-Integration.
- So leichtgewichtig und framework-agnostisch wie möglich gestaltet.

## Kernkomponenten

Alle Framework-Pakete enthalten folgende Kernkomponenten:

### `<I18nT>`

Eine Übersetzungskomponente, die übersetzten Text rendert und Folgendes unterstützt:

- **Parameter-Interpolation**: Platzhalter durch dynamische Werte ersetzen.
- **Pluralisierung**: automatische Wahl der Pluralform anhand einer Zahl.
- **Zahlenformatierung**: Zahlen gemäß Locale formatieren.
- **Datumsformatierung**: Datumsangaben und relative Zeit formatieren.
- **HTML-Rendering**: optionales Rendern von HTML-Inhalten.
- **Standardwerte**: Fallback-Text bei fehlender Übersetzung.

**Beispiel:**

```vue
<!-- Vue -->
<I18nT keypath="greeting" :params="{ name: 'World' }" />
```

```tsx
// React
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```tsx
// Solid
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```astro
<!-- Astro -->
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

### `<I18nLink>`

Eine lokalisierte Link-Komponente, die Locale-Präfixe in URLs automatisch handhabt. Funktionen:

- **Automatische Pfad-Lokalisierung**: fügt Locale-Präfixe je nach Routing-Strategie hinzu oder entfernt sie.
- **Aktivzustand erkennen**: hebt die aktuelle Route hervor.
- **Unterstützung externer Links**: erkennt und behandelt externe URLs automatisch.
- **Router-Integration**: verwendet die Link-Komponente des Router-Adapters, sofern vorhanden.
- **Eigenes Styling**: unterstützt Aktiv- und Hover-Zustände.

**Beispiel:**

```vue
<!-- Vue -->
<I18nLink to="/about" active-class="active">
  About Us
</I18nLink>
```

```tsx
// React
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```tsx
// Solid
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```astro
<!-- Astro -->
<I18nLink href="/about" class="nav-link">
  About Us
</I18nLink>
```

### `<I18nSwitcher>`

Ein Sprachwechsler mit Dropdown- oder Listen-Oberfläche zum Ändern der Locale. Funktionen:

- **Automatische Locale-Liste**: erzeugt Optionen aus den konfigurierten Locales.
- **Aktive Locale hervorheben**: markiert die gerade aktive Sprache.
- **Eigene Labels**: unterstützt eigene Anzeigenamen je Locale.
- **Router-Integration**: navigiert automatisch zu lokalisierten Pfaden.
- **Barrierefreiheit**: korrekte ARIA-Attribute und Tastaturnavigation.

**Beispiel:**

```vue
<!-- Vue -->
<I18nSwitcher />
```

```tsx
// React
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```tsx
// Solid
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```astro
<!-- Astro -->
<I18nSwitcher />
```

### `<I18nGroup>`

Komponente zum Gruppieren von Übersetzungen mit gemeinsamem Präfix, praktisch zum Organisieren nach Seite oder Feature. Funktionen:

- **Präfix-Scoping**: setzt das Präfix automatisch vor alle Übersetzungsschlüssel in der Gruppe.
- **Verschachtelte Gruppen**: unterstützt geschachtelte Übersetzungsgruppen.
- **Saubere Struktur**: hilft, Übersetzungen geordnet zu halten.

**Beispiel:**

```vue
<!-- Vue -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

```tsx
// React
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```tsx
// Solid
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```astro
<!-- Astro -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

## Gemeinsame `createI18n`-Optionen \{#create-i18n-options\}

Jedes Framework-Paket wird gleich erzeugt. Nur der Typ der Optionen trägt den Namen des Frameworks (`ReactI18nOptions`, `SolidI18nOptions` usw.). Die Optionen selbst sind identisch:

| Property         | Typ                                                        | Erforderlich | Standard         | Beschreibung                                       |
| ---------------- | ---------------------------------------------------------- | ------------ | ---------------- | -------------------------------------------------- |
| `locale`         | `string`                                                   | ✅           | -                | Aktueller Locale-Code (zum Beispiel `'en'`)         |
| `fallbackLocale` | `string`                                                   | ❌           | wie `locale`     | Fallback-Locale bei fehlender Übersetzung          |
| `messages`       | `Record<string, Translations>`                             | ❌           | `\{\}`             | Initiale Übersetzungsnachrichten                   |
| `plural`         | `PluralFunc`                                               | ❌           | `defaultPlural`  | Eigene Pluralisierungsfunktion                     |
| `missingWarn`    | `boolean`                                                  | ❌           | `true`           | Konsolen-Warnungen für fehlende Übersetzungen      |
| `missingHandler` | `(locale: string, key: string, routeName: string) => void` | ❌           | -                | Eigener Handler für fehlende Übersetzungen         |

Alles darüber hinaus ist framework-spezifisch und auf der Seite des jeweiligen Pakets dokumentiert.

## Router-Adapter-Abstraktion

Alle Framework-Pakete nutzen ein **Router-Adapter-Muster**, um die i18n-Funktionen von konkreten Router-Implementierungen zu entkoppeln. Vorteile:

- **Flexibilität**: beliebige Router-Bibliothek oder gar keinen Router.
- **Framework-Unabhängigkeit**: Routing-Logik bleibt in deiner Anwendung, nicht im i18n-Paket.
- **Schlanker Kern**: das i18n-Paket bleibt klein und fokussiert.

### Router-Adapter implementieren

Für Routing-Funktionen implementierst du das Interface `I18nRoutingStrategy`:

```typescript
interface I18nRoutingStrategy {
  getCurrentPath: () => string
  linkComponent?: Component
  push: (target: { path: string }) => void
  replace: (target: { path: string }) => void
  resolvePath?: (to: string | { path?: string }, locale: string) => string | { path?: string }
  getRoute?: () => { fullPath: string; query: Record<string, unknown> }
}
```

Die Dokumentation jedes Pakets enthält vollständige Beispiele für Adapter zu gängigen Routern:

- **Vue**: Beispiel für einen Vue-Router-Adapter.
- **React**: Beispiel für einen React-Router-Adapter.
- **Solid**: Beispiel für einen Solid-Router-Adapter.
- **Astro**: Beispiel für einen dateibasierten Routing-Adapter.

## Kernfunktionen

Alle Pakete teilen diese Kernfunktionen:

### Übersetzungsmethoden

- `t()`: einfache Übersetzung mit Parameter-Interpolation.
- `ts()`: Übersetzung, die immer einen String liefert.
- `tc()`: pluralisierungsbewusste Übersetzung.
- `tn()`: Zahlenformatierung.
- `td()`: Datumsformatierung.
- `tdr()`: relative Zeit formatieren.
- `has()`: prüft, ob ein Übersetzungsschlüssel existiert.

### Locale-Management

- **Locale wechseln**: aktuelle Locale programmatisch ändern.
- **Fallback-Locale**: automatischer Fallback bei fehlender Übersetzung.
- **Routen-spezifische Übersetzungen**: Übersetzungen auf Seitenebene organisieren.
- **Übersetzungs-Caching**: intelligentes Caching für gute Performance.

### TypeScript-Unterstützung

Alle Pakete bieten:

- vollständige TypeScript-Definitionen.
- typsichere Übersetzungsschlüssel (mit Types-Generator).
- IntelliSense-Unterstützung in IDEs.
- Fehlerprüfung zur Compile-Zeit.

## Erste Schritte

2. **Paket installieren**: bevorzugten Package-Manager verwenden.
