Die `@i18n-micro/*`-Pakete bringen den Übersetzungskern von Nuxt I18n Micro zu Vue, React, Preact, Solid, Astro, VitePress und reinem JavaScript. Verwenden Sie sie, wenn Ihre App keine Nuxt-App ist oder wenn ein Skript oder Server außerhalb von Nuxt dieselben Übersetzungsdateien benötigt. Alle Pakete teilen ein Instanzmodell, einen Router-Adapter-Vertrag und dieselben vier Komponenten, die auf dieser Seite einmalig beschrieben werden.

Jedes Paket hat im Repository einen Playground unter `packages/<name>/playground`.

## Die Instanz {#the-instance}

`createI18n(options)` gibt eine Instanz zurück, die die Wörterbücher, die aktuelle Locale und die aktuelle Route enthält. Die Optionen sind in allen Paketen gleich:

| Option | Typ | Standard | Hinweise |
| --- | --- | --- | --- |
| `locale` | `string` | erforderlich | Aktive Locale. |
| `fallbackLocale` | `string` | `locale` | Wird nachgeschlagen, wenn ein Schlüssel in `locale` fehlt. |
| `messages` | `Record<locale, Translations>` | `{}` | Root-Wörterbücher (Route `'index'`). |
| `routeMessages` | `Record<route, Record<locale, Translations>>` | `{}` | Routen-Wörterbücher. Nur Runtime, React, Preact, Node und VitePress. |
| `plural` | `PluralFunc` | `defaultPlural` | Eigene Pluralregel. |
| `missingWarn` | `boolean` | `true` | Nur in der Entwicklung: `console.warn` im Browser bei einem fehlenden Schlüssel. |
| `missingHandler` | `(locale, key, routeName) => void` | — | Wird anstelle der Warnung aufgerufen. |
| `numberFormats` | `Record<locale, Record<name, Intl.NumberFormatOptions>>` | — | Benannte Formate: `tn(9.5, 'currency')`. |
| `datetimeFormats` | `Record<locale, Record<name, Intl.DateTimeFormatOptions>>` | — | Benannte Formate: `td(date, 'short')`. |
| `timeZone` | `string` | Zeitzone der Laufzeit | IANA-Zeitzone für `td`-Datumsangaben; wirkt sich nicht auf `tdr` aus. Setzen Sie sie, damit Server und Browser dasselbe Datum rendern. |
| `now` | `() => number` | `Date.now` | Die Uhr von `tdr`. Geben Sie der Hydration die Zeit des Servers, damit beide denselben Text rendern. |
| `localeIso` | `Record<code, string>` | — | BCP-47-Tag für Pluralregeln (`ua` → `uk-UA`). React, Preact und Solid übernehmen es aus `iso` in den `locales` des Providers. |

Die Wörterbücher liegen in `i18n.storage.translations`, einer `Map` mit Schlüsseln der Form `locale:route` (`en:index`, `en:about`).

Ein Schlüssel wird im Wörterbuch der aktuellen Route und dann im Root-Wörterbuch gesucht, zuerst für `locale`, dann für `fallbackLocale`. Ein fehlender Schlüssel gibt den Schlüssel selbst zurück (oder den übergebenen `defaultValue`).

```ts
i18n.addTranslations('en', { nav: { home: 'Home' } }) // root, deep-merged
i18n.addRouteTranslations('en', 'about', { title: 'About us' }) // route chunk
i18n.addTranslations('en', { nav: { home: 'Start' } }, false) // replace instead of merge
i18n.setRoute('about')
i18n.t('title') // 'About us'
i18n.t('nav.home') // 'Start' (root key, still visible on the route)
```

### Übersetzen und formatieren {#translate-and-format}

| Methode | Rückgabewert |
| --- | --- |
| `t(key, params?, defaultValue?, routeName?)` | Der Wert (String, Zahl, Objekt) mit interpolierten `{param}`. |
| `ts(...)` | Wie `t`, als String. |
| `tc(key, count \| params, defaultValue?)` | Pluralform. |
| `tn(value, options \| name)` | `Intl.NumberFormat` in der aktiven Locale. |
| `td(value, options \| name)` | `Intl.DateTimeFormat`. |
| `tdr(value, options?)` | Relative Zeit (`3 days ago`). |
| `has(key, routeName?)` | `true`, wenn die aktive Locale den Schlüssel hat (Routen- oder Root-Wörterbuch; der Fallback wird nicht geprüft). |

`defaultPlural` teilt den Wert an `|` auf und wählt die Form am Index `count`, begrenzt auf die letzte; ein negativer, gebrochener oder `NaN`-Wert für count wählt die letzte Form.

Ein eigenes `plural` erhält `(key, count, params, locale, getter)`. Lesen Sie den Wert über `getter(key)`; teilen Sie nicht den Schlüssel auf:

```ts
import type { PluralFunc } from '@i18n-micro/vue'

const plural: PluralFunc = (key, count, params, _locale, getter) => {
  const value = getter(key)
  if (typeof value !== 'string') return null
  const forms = value.split('|').map((form) => form.trim())
  return (count === 1 ? forms[0] : forms[1] ?? forms[0])!.replace('{count}', String(count))
}
```

## Router-Adapter {#router-adapter}

Die SPA-Pakete hängen von keinem Router ab. Ein Router-Adapter (`I18nRoutingStrategy`) teilt ihnen mit, wie sie den aktuellen Pfad lesen, navigieren und einen lokalisierten Pfad erzeugen. Die eingebauten Adapter versehen jede Locale außer `defaultLocale` mit einem Präfix (`/about`, `/de/about`).

| Member | Erforderlich | Verwendet von |
| --- | --- | --- |
| `getCurrentPath(): string` | ja | Prüfung auf aktiven Link (nach Seite, Query und Hash zählen nicht), `switchLocale` (behält sie bei) |
| `push({ path }): void` | ja | `switchLocale`, `<I18nLink>` ohne `linkComponent`, `<I18nSwitcher>` |
| `replace({ path }): void` | ja | — |
| `resolvePath(to, locale)` | nein | `localePath`, `localeRoute`, `<I18nLink>`; ohne ihn werden Pfade unverändert zurückgegeben |
| `linkComponent` | nein | `<I18nLink>` rendert ihn (z. B. `RouterLink`) anstelle von `<a>` |
| `getRoute()` | nein | `{ fullPath, query }` für SEO-Helfer |

`push` und `replace` sind in Vue, React, Preact und Solid erforderlich. Astro hat einen eigenen serverseitigen Adapter mit optionalem `push`/`replace` (siehe [Astro](/de/integrations/astro-package#router-adapter)).

Ein minimaler Adapter für einen beliebigen History-basierten Router:

```ts
import type { I18nRoutingStrategy } from '@i18n-micro/react'

const locales = ['en', 'de']
const stripLocale = (path: string) => path.replace(/^\/(en|de)(?=\/|$)/, '') || '/'

export const historyAdapter: I18nRoutingStrategy = {
  getCurrentPath: () => window.location.pathname + window.location.search + window.location.hash,
  push: ({ path }) => window.history.pushState({}, '', path),
  replace: ({ path }) => window.history.replaceState({}, '', path),
  resolvePath: (to, locale) => {
    const path = stripLocale(typeof to === 'string' ? to : to.path || '/')
    return locale === 'en' ? path : `/${locale}${path === '/' ? '' : path}`
  },
}
```

## Komponenten {#components}

Vue, React, Preact und Solid liefern dieselben vier Komponenten aus. Ihre Props stimmen überein; React, Preact und Solid reichen weitere Props an das Root-Element durch.

### `<I18nT>` {#&lt;i18nt&gt;}

| Prop | Typ | Hinweise |
| --- | --- | --- |
| `keypath` | `string` | erforderlich |
| `params` | `object` | Interpolationswerte |
| `plural` | `number \| string` | rendert `tc(keypath, count)` |
| `number` | `number \| string` | übergibt `tn(number)` als `{number}` |
| `date` | `Date \| string \| number` | übergibt `td(date)` als `{date}` |
| `relativeDate` | `Date \| string \| number` | übergibt `tdr(relativeDate)` als `{relativeDate}` |
| `tag` | `string` | umgebendes Element, Standard `span` |
| `html` | `boolean` | rendert die Übersetzung als HTML; sie muss vertrauenswürdig sein, Parameter werden escaped |
| `defaultValue` | `string` | ersetzt einen fehlenden Schlüssel und wird ohne Wrapper gerendert, wenn `hideIfEmpty` einen leeren Wert ausblendet |
| `hideIfEmpty` | `boolean` | rendert bei einer leeren Übersetzung nichts |
| `customPluralRule` | `PluralFunc` | Pluralregel für dieses Element |

Es gilt nur eine Formatierungs-Prop, geprüft in dieser Reihenfolge: `number`, `date`, `relativeDate`, `plural`.

#### Rich Text {#rich-text}

Ein `{placeholder}` kann ein Element enthalten. In Vue ist es ein benannter Slot; in React, Preact und Solid liefert die Prop `components` Elemente oder Funktionen, die ein Element zurückgeben, nach Namen. In beiden Fällen hat es Vorrang vor einem gleichnamigen Parameter, funktioniert in jedem Zweig und übersteht eine Locale, die die Platzhalter umordnet.

```tsx
// { "terms": "I accept the {link} of {company}" }
<I18nT keypath="terms" params={{ company: 'ACME' }} components={{ link: <a href="/terms">terms</a> }} />
```

Übergeben Sie in Solid eine Funktion, wenn sich ein Platzhalter wiederholt: Ein Knoten steht nur an einer Stelle. `children` ersetzen den Text; als Funktion erhalten sie `{ translation }`, wie der Standard-Slot in Vue. `html` ignoriert all dies.

### `<I18nLink>` {#&lt;i18nlink&gt;}

| Prop | Typ | Hinweise |
| --- | --- | --- |
| `to` | `string \| { path }` | wird über `resolvePath` des Adapters lokalisiert |
| `activeStyle` | Style-Objekt | wird auf der aktuellen Seite über `style` gelegt; React, Preact und Solid wenden es auch auf einen übergeordneten Abschnitt an |
| `localeRoute` | Funktion | überschreibt `resolvePath` für diesen Link |

Externe URLs (`https://`, `mailto:`, `tel:`) werden als `<a target="_blank" rel="noopener noreferrer">` gerendert; ein eigenes `target` oder `rel` hat Vorrang. `onClick` wird immer ausgeführt. Ein Klick mit Modifikatortaste, eine andere Maustaste oder ein `target` bleibt dem Browser überlassen.

### `<I18nSwitcher>` {#&lt;i18nswitcher&gt;}

Ein Dropdown der aktivierten Locales (Locales mit `disabled: true` werden ausgeblendet) mit eingebetteten Standardstilen. Seine Einträge sind Links mit `lang`, `hreflang` und `dir` aus der Locale. Standardmäßig setzt ein Klick auf einen Eintrag die Locale und ruft `push` des Adapters mit dem lokalisierten aktuellen Pfad auf; eine Prop `switchLocale` ersetzt diese Aktion. Mit einem `localeRoute` und ohne Router folgt der Browser dem Link. Escape oder ein Klick außerhalb schließt es.

| Prop | Hinweise |
| --- | --- |
| `locales`, `currentLocale`, `getLocaleName` | überschreiben die bereitgestellten Werte |
| `switchLocale(code)` | ersetzt den eingebauten Wechsel |
| `localeRoute` | ersetzt `resolvePath` |
| `customLabels` | `{ de: 'DE' }` |
| `customWrapperStyle`, `customButtonStyle`, `customDropdownStyle`, `customItemStyle`, `customLinkStyle`, `customActiveLinkStyle`, `customDisabledLinkStyle`, `customIconStyle` | Stil-Überschreibungen |

### `<I18nGroup>` {#&lt;i18ngroup&gt;}

Ein `<div class="i18n-group">`, das seinen Kindern ein `t` mit Präfix übergibt. Es versieht `<I18nT>` oder `t()`-Aufrufe darin **nicht** mit einem Präfix; nur das weitergereichte `t` hat ein Präfix.

| Prop | Hinweise |
| --- | --- |
| `prefix` | erforderlich, z. B. `'profile'` |
| `groupClass` | zusätzliche Klasse am Wrapper |

Das `t` mit Präfix kommt in Vue über einen Scoped Slot (`v-slot="{ t }"`) und in React, Preact und Solid über ein Render-Prop-Kind (`{({ t }) => …}`).

## Typisierte Schlüssel {#typed-keys}

`t()` akzeptiert jeden String. Um Autovervollständigung für Ihre Schlüssel zu erhalten, erzeugen Sie mit dem [Typgenerator](/de/integrations/types-generator) eine Deklaration. Schlüssel werden vorgeschlagen, nicht erzwungen, und Parameter sind nicht typisiert.

## Vergleich mit dem Nuxt-Modul {#compared-with-the-nuxt-module}

Die Pakete haben kein dateibasiertes Routing, keine Server-Middleware und keinen Übersetzungs-Loader: Sie entscheiden, wann JSON geladen wird (`import`, `fetch` oder `@i18n-micro/node` auf dem Server) und welcher Router-Adapter verwendet wird. Locale-Erkennung, SEO-Meta-Tags und Routengenerierung sind Nuxt-Funktionen; Astro hat eine eigene Middleware für die Erkennung und `useLocaleHead` für SEO.
