`@i18n-micro/react` und `@i18n-micro/preact` verpacken die framework-unabhängige [Runtime](/de/integrations/runtime-package) in einen Provider, einen `useI18n()`-Hook und vier Komponenten. Verwenden Sie sie in einer React- oder Preact-App, die nicht mit Nuxt gebaut wird. Beide Pakete haben dieselbe API; der Abschnitt [Preact](#preact) listet die wenigen Unterschiede auf, und das gemeinsame Modell ist unter [Frameworks](/de/integrations/overview) beschrieben.

## Installation {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/react
```

```bash npm
npm install @i18n-micro/react
```

```bash yarn
yarn add @i18n-micro/react
```

</CodeGroup>

Peer-Dependencies: `react` `^18.0.0 || ^19.0.0`; `react-dom` (optional, zum Rendern); `react-router-dom` `^6.0.0 || ^7.0.0` (optional, nur für `@i18n-micro/react/router`). Getestet mit React 19.3 und 18.3, React Router 7.18 und 6.30.

## Einrichtung {#setup}

```tsx
// src/main.tsx
import { createRoot } from 'react-dom/client'
import { createI18n, I18nProvider } from '@i18n-micro/react'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

createRoot(document.getElementById('root')!).render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
    <App />
  </I18nProvider>,
)
```

<Warning>

Erstellen Sie die Instanz einmal, auf Modulebene oder in einem `useState`-Initializer, niemals im Rumpf einer Komponente.

</Warning>

`<I18nProvider>` nimmt `i18n`, `locales`, `defaultLocale` und `routingStrategy` entgegen:

- Ein weggelassenes Prop behält den Wert eines äußeren Providers, einschließlich der Instanz.
- Gibt es überhaupt keine Instanz, erstellt er eine aus den daneben angegebenen `createI18n`-Optionen, sodass die Props einfache Daten bleiben: `<I18nProvider locale="de" messages={messages}>`.
- Ein neues `locale`-Prop erstellt eine neue Instanz mit den `messages` dieses Renders. Eine solche Instanz lebt in der Komponente: Wenn etwas darüber während des Mountens suspendiert, verwirft React sie samt allem, was ihr hinzugefügt wurde.

Alle `createI18n`-Optionen, einschließlich `routeMessages`, finden Sie unter [die Instanz](/de/integrations/overview#the-instance).

## Übersetzen {#translate}

```tsx
import { useI18n } from '@i18n-micro/react'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' })}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

`useI18n()` gibt zurück:

| Gruppe | Mitglieder |
| --- | --- |
| Übersetzen | `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` |
| Locale und Route | `locale`, `fallbackLocale`, `currentRoute`, `setLocale`, `setRoute`, `getRoute`, `getLocales`, `defaultLocale()`, `getLocaleName` |
| Routing | `switchLocale`, `localePath`, `localeRoute` |
| Wörterbücher | `addTranslations`, `addRouteTranslations`, `clearCache` |

- Die Komponente rendert neu, wenn sich die Locale, die Route oder ein lesbares Wörterbuch ändert, und wenn der Provider ein neues `locales`- oder `routingStrategy`-Objekt erhält. Ein Wörterbuch einer Locale, die weder aktiv noch Fallback ist, löst kein Rendering aus.
- `t` und die anderen Übersetzungsmethoden ändern sich nur mit dem Store, daher sind sie in `memo` und Effect-Abhängigkeiten sicher.

`useT` liefert einen einzelnen String als Wert. Die Komponente rendert nur, wenn sich dieser String ändert, unabhängig davon, was mit den anderen Props des Providers geschieht; auch `<I18nT>` hängt nicht von ihnen ab:

```tsx
const title = useT('page.title')
```

Laden Sie jederzeit weitere Wörterbücher:

```tsx
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

useEffect(() => {
  import('./locales/de.json').then((m) => addTranslations('de', m.default))
  addRouteTranslations('en', 'about', { title: 'About us' })
  setRoute('about') // t('title') now reads the 'about' dictionary first
}, [])
```

Die Instanz selbst hat außerdem `loadFromUrl(url, { locale, routeName })` für JSON über `fetch`.

## Locale wechseln {#switch-locale}

```tsx
const { setLocale, switchLocale } = useI18n()

setLocale('de') // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Der Wechsel lädt nichts; fügen Sie zuerst das Wörterbuch der Locale hinzu. Ein Store-Schreibvorgang ist für React synchron, selbst innerhalb von `startTransition`, sodass eine Komponente, die wegen eines fehlenden Wörterbuchs suspendiert, ihren Fallback anzeigen würde. `useLocaleSwitch` lädt zuerst und behält die alte UI bei, bis das Wörterbuch geladen ist:

```tsx
const [switchTo, pending] = useLocaleSwitch((locale) => i18n.loadFromUrl(`/locales/${locale}.json`, { locale }))

<button disabled={pending} onClick={() => switchTo('de')}>Deutsch</button>
```

Der letzte Aufruf gewinnt. Ein fehlgeschlagener Ladevorgang wird abgelehnt (reject) und lässt die Locale unverändert.

`<I18nGroup>` übergibt einem Render-Prop-Child ein `t` mit Präfix. `<I18nT>` und `t()` darin erhalten kein Präfix:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Routing {#routing}

Der React-Router-Adapter liegt in einem Subpath, sodass der Haupteinstieg `react-router-dom` nie importiert. Er benötigt `useLocation()` und `useNavigate()`, erstellen Sie ihn daher innerhalb einer Komponente unterhalb des Routers:

```tsx
// src/App.tsx
import { useMemo } from 'react'
import { BrowserRouter, Route, Routes, useLocation, useNavigate } from 'react-router-dom'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/react'
import { createReactRouterAdapter } from '@i18n-micro/react/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Localized() {
  const location = useLocation()
  const navigate = useNavigate()
  // memoized: a new object on every render re-renders every `useI18n()` consumer
  const routingStrategy = useMemo(() => createReactRouterAdapter(locales, 'en', location, navigate), [location, navigate])
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      <Routes>
        <Route path="/:locale?" element={<Home />} />
        <Route path="/:locale?/about" element={<About />} />
      </Routes>
    </I18nProvider>
  )
}

export default function App() {
  return (
    <BrowserRouter>
      <Localized />
    </BrowserRouter>
  )
}
```

Der Adapter versieht jede Locale außer der Standard-Locale mit einem Präfix (`/about`, `/de/about`) und rendert `<I18nLink>` als `<Link>` von React Router. Setzen Sie die Locale selbst anhand der URL (zum Beispiel aus `useParams().locale` in einem Effect). Für jeden anderen Router schreiben Sie einen Adapter mit `getCurrentPath`, `push` und `replace` (alle erforderlich) — siehe [Router-Adapter](/de/integrations/overview#router-adapter).

## SSR {#ssr}

`renderToString` funktioniert: `useI18n()` hat einen Server-Snapshot. Erstellen Sie pro Anfrage eine Instanz und fügen Sie ihre Wörterbücher vor dem Rendern hinzu, damit Anfragen in unterschiedlichen Locales keinen Zustand teilen, oder übergeben Sie dem Provider einfache Daten.

### Hydration {#hydration}

Zahlen, Pluralformen und Text werden unverändert hydriert. Ein Datum hängt von der Zeitzone ab und ein relatives Datum von der Uhr: Setzen Sie `timeZone` auf dem Server und im Browser, und übergeben Sie dem Browser für `tdr` die Serverzeit mit `now`. `<I18nT>` mit `date` oder `relativeDate` setzt `suppressHydrationWarning`, sodass eine Abweichung die Hydration nicht scheitern lässt, aber der Text des Servers bleibt bestehen, bis sich der Text ändert. Das reicht nur eine Ebene tief: `children`, die die Übersetzung in ein Element einschließen, scheitern bei einer Abweichung weiterhin, geben Sie diesen daher dieselbe `timeZone`.

### Server Components {#server-components}

Das Paket kennzeichnet seinen Client-Code mit `'use client'`. `@i18n-micro/react/server` enthält `createI18n` und ein `I18nT` ohne Hooks, das die Instanz als Prop erhält, sodass der Text aus dem Client-Bundle herausbleibt. Unter der Bedingung `react-server`, wie im App Router von Next.js, wird auch der Haupteinstieg darauf aufgelöst, aber TypeScript weiß das standardmäßig nicht: Importieren Sie aus `/server`. `@i18n-micro/react/client` liefert immer den Client-Einstieg.

```tsx
// app/[locale]/layout.tsx: a server component
import { cache } from 'react'
import { createI18n, I18nT } from '@i18n-micro/react/server'
import { I18nProvider } from '@i18n-micro/react/client'
import { loadMessages } from './messages'

const getI18n = cache(async (locale: string) => createI18n({ locale, messages: await loadMessages(locale) }))

export default async function Layout({ params, children }) {
  const { locale } = await params
  const i18n = await getI18n(locale)
  return (
    <I18nProvider locale={locale} messages={{ [locale]: i18n.resolveTranslations() }}>
      <h1>
        <I18nT i18n={i18n} keypath="title" />
      </h1>
      {children}
    </I18nProvider>
  )
}
```

Gerendert über `react-server-dom-webpack`; eine Next.js-App selbst wurde damit noch nicht ausgeführt.

## Preact {#preact}

`@i18n-micro/preact` wird aus demselben Quellcode gebaut, auf Preact selbst, ohne `preact/compat`: dieselbe Instanz, derselbe Provider, dieselben Hooks und Komponenten. Unterschiede:

| | React | Preact |
| --- | --- | --- |
| Peer-Dependency | `react` (+ optional `react-router-dom`) | `preact` `^10.0.0 \|\| ^11.0.0`, getestet mit 10.29 und 11.1 |
| Instanzklasse | `ReactI18n` | `PreactI18n` |
| Router-Adapter | `createReactRouterAdapter` aus `/router` | `createBrowserHistoryAdapter(locales, defaultLocale, ssrUrl?)` aus `/router` |
| Neu-Rendering | `useSyncExternalStore` | ein Layout-Effect-Abonnement, das den Store erneut prüft |
| Server Components | `/server`, `/client` | keine |

`createBrowserHistoryAdapter` funktioniert mit jedem History-API-Router (wouter, preact-router): `push` und `replace` rufen `history.pushState` / `replaceState` auf und lösen `popstate` aus, und `<I18nLink>` rendert ein einfaches `<a>`, das über `push` navigiert. Ein Server hat keine Adressleiste: Übergeben Sie die URL der Anfrage als `ssrUrl`, sonst werden Links und der Switcher wie auf `/` gerendert. Im Browser hat die Adressleiste Vorrang.

```tsx
// src/main.tsx
import { render } from 'preact'
import { createI18n, I18nProvider } from '@i18n-micro/preact'
import { createBrowserHistoryAdapter } from '@i18n-micro/preact/router'
import { App } from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={createBrowserHistoryAdapter(locales, 'en')}>
    <App />
  </I18nProvider>,
  document.getElementById('app')!,
)
```
