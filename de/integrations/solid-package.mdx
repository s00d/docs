`@i18n-micro/solid` stellt SolidJS-Apps eine signalbasierte i18n-Instanz, einen Provider, `useI18n()` und vier Komponenten bereit. Verwenden Sie es in einer Solid-App, die nicht mit Nuxt gebaut wird. Aufrufe von `t()` innerhalb von JSX oder Effects verfolgen die Locale, die Route und die Wörterbücher; das gemeinsame Modell ist unter [Frameworks](/de/integrations/overview) beschrieben.

## Installation {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer-Dependencies: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (optional, nur für `@i18n-micro/solid/router`). Solid 2 wird noch nicht unterstützt.

## Einrichtung {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` nimmt `i18n`, `locales`, `defaultLocale` und `routingStrategy` entgegen; ein weggelassenes Prop behält den Wert des äußeren Providers, einschließlich der Instanz. `getLocaleName()` und `<I18nSwitcher>` lesen `locales`; ohne diese haben sie nichts aufzulisten. Die Optionen finden Sie unter [die Instanz](/de/integrations/overview#the-instance). Die Instanz ist die der [Runtime](/de/integrations/runtime-package), mit einem Signal über ihrem Store.

## Übersetzen {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Rufen Sie die Methoden innerhalb von JSX oder eines Effects auf, damit Solid sie verfolgt, auch `localePath` und `getLocale`; ein einmal im Komponentenrumpf gelesener Wert aktualisiert sich nicht. Auf der Instanz verfolgen Sie mit `i18n.locale` und `i18n.currentRoute`: `i18n.getLocale()` bleibt einfach, weil Schreibvorgänge es lesen. Das Lesen der Locale reagiert nur auf die Locale, sodass ein Effect, der sie liest und ein Wörterbuch lädt, einmal läuft. Destrukturieren Sie keine Props und speichern Sie keine `t('key')`-Ergebnisse in einfachen Variablen.

`useI18n()` gibt `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (ein Accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` und `instance` zurück.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Locale wechseln {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Der Wechsel lädt nichts; fügen Sie zuerst das Wörterbuch der Locale hinzu.

`<I18nGroup>` übergibt einem Funktions-Child ein `t` mit Präfix. `<I18nT>` und `t()` darin erhalten kein Präfix:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Routing {#routing}

Der `@solidjs/router`-Adapter liegt in einem Subpath, sodass der Haupteinstieg den Router nie importiert. Rufen Sie ihn unterhalb des Routers auf, typischerweise im `root` des Routers, wo `useNavigate` und `useLocation` funktionieren:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

Der Adapter versieht jede Locale außer der Standard-Locale mit einem Präfix (`/about`, `/de/about`) und rendert `<I18nLink>` als `<A>` des Routers. `getCurrentPath` liest die reaktive Location des Routers, sodass aktive Links und der Switcher ihr folgen; eine benutzerdefinierte Strategie erreicht dasselbe, indem sie dort ein Signal liest. Beachten Sie die Reihenfolge der Argumente: `(locales, defaultLocale, navigate, location)`. Für andere Router schreiben Sie einen Adapter mit `getCurrentPath`, `push` und `replace` (alle erforderlich) — siehe [Router-Adapter](/de/integrations/overview#router-adapter).

## SSR {#ssr}

Für Server-Rendering bauen Sie mit `vite-plugin-solid`: Die Export-Bedingung `solid` des Pakets übergibt ihm den Quellcode, sodass er für den Server kompiliert wird. Das vorgebaute `dist` ist nur für den Browser. Die Instanz hat kein `destroy()`; erstellen Sie eine pro App bzw. auf dem Server eine pro Anfrage und überlassen Sie sie der Garbage Collection.
