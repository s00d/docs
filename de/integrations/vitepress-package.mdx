`@i18n-micro/vitepress` fügt einer VitePress-Website Laufzeit-Wörterbücher hinzu: `$t` und `<I18nT>` in Markdown, Pfad-Helfer und SEO-Tags, aufgebaut auf [`@i18n-micro/vue`](/de/integrations/vue-package). Verwende es, wenn dieselben UI-Strings auf vielen Seiten vorkommen und du sie nicht pro Locale duplizieren willst. Die Locale folgt den eigenen Pfad-Locales von VitePress (`/`, `/fr/`).

## Wann du es verwenden solltest {#when-to-use-it}

| Bedarf | Lösung |
|------|----------|
| Duplizierte `.md`-Dateien, URL-Präfixe | VitePress `locales` |
| Laufzeit-`$t` / Komponenten / Pfad-Synchronisierung / SEO-Head | `@i18n-micro/vitepress` |
| Beschriftungen des Default-Themes (`docFooter`, Such-UI) | Dein eigenes `themeConfig` pro Locale |

<Tip>

**Playground** — [`packages/vitepress/playground`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/vitepress/playground) — `pnpm -C packages/vitepress/playground dev`

</Tip>

## Installation {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vitepress
```

```bash npm
npm install @i18n-micro/vitepress
```

```bash yarn
yarn add @i18n-micro/vitepress
```

</CodeGroup>

Peer-Abhängigkeiten: `vitepress` `>=1.0.0 || >=2.0.0-alpha.0`, `vue` `^3.3.0`. Node-Skripte verwenden `@i18n-micro/node`, das mit dem Paket installiert und über `/node` re-exportiert wird. Die veröffentlichten Typen benötigen Vue 3.5.5 oder neuer mit `skipLibCheck: false`; mit `skipLibCheck: true`, der üblichen Template-Einstellung, kompilieren auch ältere Versionen.

## Einrichtung {#setup}

```
locales/en.json
locales/fr.json
locales/pages/guide/demo/en.json   # optional page-scoped
locales/pages/guide/demo/fr.json
```

Seitendateien werden auf dieselbe Weise wie bei Nuxt/Astro auf Routennamen abgebildet (`guide/demo` → `guide-demo`).

### 1. Konfiguration — `@i18n-micro/vitepress/config` {#1-config-—-i18n-microvitepressconfig}

```ts
// .vitepress/config.mts
import { defineConfig } from 'vitepress'
import { withI18n, buildVitePressLocales } from '@i18n-micro/vitepress/config'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English', og: 'en_US' },
  { code: 'fr', iso: 'fr-FR', displayName: 'Français', og: 'fr_FR' },
]
const defaultLocale = 'en'

export default defineConfig(
  withI18n(
    {
      locales: buildVitePressLocales(locales, defaultLocale),
      // themeConfig.i18nRouting is injected automatically
    },
    {
      locale: defaultLocale,
      defaultLocale,
      locales,
      translationDir: 'locales',
      metaBaseUrl: 'https://example.com', // optional SEO head
    },
  ),
)
```

### 2. Theme — `@i18n-micro/vitepress/theme` {#2-theme-—-i18n-microvitepresstheme}

```ts
// .vitepress/theme/index.ts
import DefaultTheme from 'vitepress/theme'
import { defineI18nTheme } from '@i18n-micro/vitepress/theme'

export default defineI18nTheme(DefaultTheme)
```

Die anfängliche Locale wird vor der Installation aus dem aktuellen Pfad übernommen (kein kurzes Aufblitzen der Standard-Locale auf `/fr/…`).

### Fortgeschritten: manuelles `createI18n` {#advanced-manual-createi18n}

Eine Factory für den Client: Vue-Plugin + Pfadmethoden + `enhanceApp` (keine separaten Router-Helfer-Exporte).

```ts
import { createI18n, messagesFromGlob } from '@i18n-micro/vitepress'

const i18n = createI18n({
  locale: 'en',
  defaultLocale: 'en',
  locales: [{ code: 'en' }, { code: 'fr' }],
  messages: messagesFromGlob(import.meta.glob('../../locales/*.json', { eager: true })),
})

i18n.localizePath('/guide', 'fr')
// in theme enhanceApp:
i18n.enhanceApp({ app, router })
```

### Node-Skripte — `@i18n-micro/vitepress/node` {#node-scripts-—-i18n-microvitepressnode}

Verwendet `createI18n` / `loadTranslations` aus `@i18n-micro/node` (wie Astro und CLI) und hängt dann mit `BaseI18n.extend` die VitePress-Pfadmethoden an:

```ts
import { createI18n } from '@i18n-micro/vitepress/node'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  translationDir: './locales',
  locales: ['en', 'fr'],
  defaultLocale: 'en',
})
await i18n.loadTranslations()
i18n.t('cta.readMore')
i18n.localizePath('/guide', 'fr')
```

Reines Node ohne Pfade: `import { createI18n } from '@i18n-micro/node'`.

## Übersetzungen in der Seite {#in-page-translations}

Jede VitePress-Markdown-Datei ist eine Vue-SFC.

### Globale Komponenten und `$t` (empfohlen in Markdown) {#global-components-and-$t-recommended-in-markdown}

`createI18n` / `defineI18nTheme` installieren `@i18n-micro/vue`, das `I18nT` / `I18nLink` / `I18nGroup` / `I18nSwitcher` und `$t` / `$tc` / `$ts` registriert.

```md
{{ $t('cta.readMore') }}

<I18nT keypath="greeting" :params="{ name: 'VitePress' }" />

<I18nLink to="/guide/demo">Demo</I18nLink>
```

### `useI18n` in `<script setup>` {#usei18n-in-script-setup}

```md
<script setup>
import { useI18n } from '@i18n-micro/vitepress'
const { t, tc, locale, localePath, switchLocale } = useI18n()
</script>

# {{ t('section.title') }}
```

## Sprach-Dropdown {#language-dropdown}

Wenn `locales` mehr als einen Eintrag hat, zeigt VitePress sein eigenes Sprachmenü (`VPNavBarTranslations`). `withI18n` verdrahtet `themeConfig.i18nRouting`, sodass der Globus mit `<I18nSwitcher>` / den Pfad-Helfern übereinstimmt.

Verwende `<I18nSwitcher>` nur in eigenen Layouts, nicht neben dem Standard-Globus.

## SSR-Hinweise {#ssr-notes}

- Die Locale beim Prerendern kommt aus dem URL-Pfad, nicht aus Cookies.
- Theme-Code darf zur Importzeit nicht auf `window` zugreifen.
- Importiere `defineI18nTheme` aus `/theme`, damit die Auswertung der Node-Konfiguration nie `virtual:i18n-micro/*` lädt.

## API-Oberfläche {#api-surface}

| Export | Rolle |
|--------|------|
| `createI18n` (`.`) | Client: Vue-Plugin + Pfadmethoden + `enhanceApp` |
| `getLocaleFromPath` / `stripSiteBase` / `routeNameFromPath` (`.`) | Manuelle Locale-Synchronisierung bei `syncWithVitePress: false` |
| `createI18n` (`/node`) | Node: `@i18n-micro/node` + Pfadmethoden |
| `defineI18nTheme` (`/theme`) | Theme ohne Boilerplate |
| `withI18n` (`/config`) | Konfiguration + virtuelle Module + optionales SEO |
| `buildVitePressLocales` (`/config`) | VitePress-`locales` aus `Locale[]` erstellen |
| `buildVitePressLocaleHead` (`/config`) | Manueller SEO-Head (wird auch von `metaBaseUrl` verwendet) |
| `messagesFromGlob` | Optionales Glob → Messages-Map für `createI18n` |
| `useI18n` / `I18nT` / … | Re-exportiert aus `@i18n-micro/vue` |
| `BaseI18n.extend` (`@i18n-micro/core`) | Eigene Methoden an jede i18n-Instanz anhängen |

## Websites im OpenAPI-Stil (Integrations-Locks) {#openapi-style-sites-integration-locks}

Regressionssuite: `packages/vitepress/tests/integration-openapi.test.ts` (tiefe Pfade, `base=/openapi_docs/`, Synchronisierung aus + manuelle Locale, Node-Generatoren, SEO).

| Muster | So gehst du vor |
|---------|---------|
| Tiefe `/…/{spec}/{op}`-Seiten, nur Root-UI-JSON | Bevorzuge das Standard-`syncWithVitePress: true` (behält `setRoute('index')`, wenn kein Seitenwörterbuch existiert) **oder** `syncWithVitePress: false` + `getLocaleFromPath` |
| Rufe nie `setRoute(deepName)` ohne Seitenwörterbücher auf | Root-UI-Schlüssel verschwinden bis `setRoute('index')` |
| Generatoren / `getTranslation` | `createI18n` aus `/node` + `await loadTranslations()` + `i18n.t(key)` (setze `i18n.locale`) |
| Eigenes Canonical in `transformPageData` | Übergib `meta: false` an `withI18n` (vermeidet doppelte Tags) |
| Paket-SEO mit Site-Base | `metaBaseUrl` + VitePress-`base` → absolute URLs enthalten die Base |
| Umbenennungen aus älteren Paket-Builds | `withI18nMicro` → `withI18n`, `createVitePressI18n` → `createI18n`, `loadMessages` → Node-`createI18n` |
