Eine Island läuft im Browser, wo die i18n-Instanz des Servers nicht existiert. Mit `@i18n-micro/astro` wählt die Seite die Schlüssel, die eine Island braucht, übergibt sie als ein Prop und liest sie in der Island über einen kleinen Framework-Adapter. Du erhältst `t`, `tc`, `tn`, `td`, `tdr` und `has` in Vue-, React-, Preact- und Svelte-Islands, wobei nur die gewählten Strings im HTML landen.

## Einrichtung {#setup}

Richte zuerst die [Astro-Integration und Middleware](/de/integrations/astro-package#setup) ein und füge dann die Framework-Integration hinzu, die du verwendest (`@astrojs/vue`, `@astrojs/react`, `@astrojs/preact`, `@astrojs/svelte`). Die Island-Adapter benötigen dieses Framework als Peer: `vue` `^3.3.0`, `react` `^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`, `preact` `^10.0.0 || ^11.0.0` oder `svelte` `^4.0.0 || ^5.0.0`.

## Übersetzungen an eine Island übergeben {#pass-translations-to-an-island}

```astro
---
// src/pages/index.astro
import { getI18nProps } from '@i18n-micro/astro'
import Counter from '../components/Counter.vue'

const i18n = getI18nProps(Astro, ['counter.title', 'counter.apples'])
---

<Counter client:load i18n={i18n} />
```

`getI18nProps(Astro, keys?)` gibt `{ locale, fallbackLocale, currentRoute, translations }` zurück (Typ `I18nClientProps`). Übergib die Schlüssel, die die Island verwendet: Jeder wird auf dem Server wie bei `t()` aufgelöst (Routen-, Root- und Fallback-Wörterbücher), und nur gefundene Schlüssel kommen ins HTML. Ohne `keys` wird alles, was `t()` auf dieser Seite beantworten kann, in jeder Island mitgeschickt, sodass 2000 Root-Schlüssel etwa 100 KB pro Island ausmachen; im Dev-Modus warnt eine Meldung ab 20 KB.

Islands übersetzen nur aus diesem Objekt. `t` gibt für alles, was nicht übergeben wurde, den Schlüssel zurück, und verlinkte Nachrichten werden nicht aufgelöst.

## Vue {#vue}

Rufe `provideI18n(() => props.i18n)` in der Root-Komponente der Island auf und `useAstroI18n()` in ihren Kindern. Vues `inject` sieht keinen Wert, der von derselben Komponente bereitgestellt wird, daher muss der Hook in einem Kind laufen, nicht in der Root-Komponente:

```vue
<!-- src/components/Counter.vue -->
<script setup lang="ts">
import { provideI18n } from '@i18n-micro/astro/client/vue'
import type { I18nClientProps } from '@i18n-micro/astro'
import CounterBody from './CounterBody.vue'

const props = defineProps<{ i18n: I18nClientProps }>()
provideI18n(() => props.i18n)
</script>

<template><CounterBody /></template>
```

```vue
<!-- src/components/CounterBody.vue -->
<script setup lang="ts">
import { ref } from 'vue'
import { useAstroI18n } from '@i18n-micro/astro/client/vue'

const { t, tc } = useAstroI18n()
const count = ref(0)
</script>

<template>
  <h3>{{ t('counter.title') }}</h3>
  <button @click="count++">{{ tc('counter.apples', count) }}</button>
</template>
```

## React und Preact {#react-and-preact}

```tsx
// src/components/Counter.tsx
import { useState } from 'react'
import { I18nProvider, useAstroI18n } from '@i18n-micro/astro/client/react'
import type { I18nClientProps } from '@i18n-micro/astro'

function Body() {
  const { t, tc } = useAstroI18n()
  const [count, setCount] = useState(0)
  return <button onClick={() => setCount(count + 1)}>{t('counter.title')}: {tc('counter.apples', count)}</button>
}

export default function Counter({ i18n }: { i18n: I18nClientProps }) {
  return (
    <I18nProvider value={i18n}>
      <Body />
    </I18nProvider>
  )
}
```

Für Preact importierst du `I18nProvider` und `useAstroI18n` aus `@i18n-micro/astro/client/preact`; die API ist dieselbe.

## Svelte {#svelte}

```svelte
<!-- src/components/Counter.svelte -->
<script lang="ts">
  import { createI18nStore, useAstroI18n } from '@i18n-micro/astro/client/svelte'
  import type { I18nClientProps } from '@i18n-micro/astro'

  export let i18n: I18nClientProps
  const { t, tc } = useAstroI18n(createI18nStore(i18n))
  let count = 0
</script>

<button on:click={() => count++}>{t('counter.title')}: {tc('counter.apples', count)}</button>
```

`useAstroI18n(store)` gibt außerdem den `store` für `$store`-Zugriffe im Template zurück.

## Persistente Islands {#persisted-islands}

Eine Island mit `transition:persist` erhält nach einer Navigation neue Props. React, Preact und Vue (mit einem Getter) folgen ihnen. In Svelte behältst du den Store und reichst sie weiter: `const store = createI18nStore(i18n)`, `const { t } = useAstroI18n(store)`, dann `$: store.set(i18n)` (mit Runes `$effect(() => store.set(i18n))`).

## API {#api}

| Einstiegspunkt | Exporte |
| --- | --- |
| `@i18n-micro/astro` | `getI18nProps`, Typ `I18nClientProps` |
| `@i18n-micro/astro/client/vue` | `provideI18n(props \| () => props)`, `useAstroI18n()` |
| `@i18n-micro/astro/client/react` | `I18nProvider` (Prop `value`), `useAstroI18n()` |
| `@i18n-micro/astro/client/preact` | `I18nProvider` (Prop `value`), `useAstroI18n()` |
| `@i18n-micro/astro/client/svelte` | `createI18nStore(props)`, `useAstroI18n(store)` |
| `@i18n-micro/astro/client` | die reinen Funktionen `translate`, `hasTranslation`, ohne Framework |

Jedes `useAstroI18n` gibt `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `setLocale`, `setRoute` und die `locale` zurück. Eine Island hat ein zusammengeführtes Wörterbuch, daher ist ihr `has` für jeden Schlüssel wahr, den `t` beantworten kann, auch aus der Fallback-Locale; auf dem Server prüft `has` nur die aktive Locale.
