`@i18n-micro/runtime` ist die framework-unabhängige i18n-Instanz: Wörterbücher, `t()`, Pluralformen, `Intl`-Formatierung und ein Änderungsabonnement, ohne `fs` und ohne Framework. Verwende sie in reinem TypeScript, in einem Web Worker, in einer Edge-Funktion oder als Basis deines eigenen Bindings. Die Pakete für React, Preact, Node und Astro erweitern genau diese Klasse.

## Installation {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/runtime
```

```bash npm
npm install @i18n-micro/runtime
```

```bash yarn
yarn add @i18n-micro/runtime
```

</CodeGroup>

Keine Peer-Abhängigkeiten. Für Übersetzungsdateien auf der Festplatte verwende [`@i18n-micro/node`](/de/integrations/nodejs-package).

## Einrichtung {#setup}

```ts
import { createI18n } from '@i18n-micro/runtime'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: {
    en: { greeting: 'Hello, {name}!', apples: 'no apples | one apple | {count} apples' },
    de: { greeting: 'Hallo, {name}!' },
  },
  routeMessages: {
    about: { en: { title: 'About us' } },
  },
})
```

Alle Optionen (`plural`, `missingWarn`, `missingHandler`, `numberFormats`, `datetimeFormats`) sind unter [Die Instanz](/de/integrations/overview#the-instance) aufgeführt.

## Übersetzen {#translate}

```ts
i18n.t('greeting', { name: 'Ada' }) // 'Hello, Ada!'
i18n.tc('apples', 5) // '5 apples'
i18n.tn(1234.5) // '1,234.5'

i18n.setRoute('about')
i18n.t('title') // 'About us' (route dictionary)
i18n.t('greeting', { name: 'Ada' }) // 'Hello, Ada!' (root, still visible)
```

Weitere Wörterbücher später laden:

```ts
i18n.loadMessages({ fr: { greeting: 'Bonjour, {name} !' } }, { about: { fr: { title: 'À propos' } } })
i18n.addTranslations('fr', { nav: { home: 'Accueil' } }) // deep merge; pass false to replace

await i18n.loadFromUrl('/locales/fr.json', { locale: 'fr' })
await i18n.loadFromUrl('/locales/pages/about/fr.json', { locale: 'fr', routeName: 'about' })
await i18n.loadFromUrls([
  { url: '/locales/en.json', locale: 'en' },
  { url: '/locales/de.json', locale: 'de' },
])
```

`loadFromUrl` verwendet `fetch` (übergib `init` für Header) und wirft bei einer Nicht-OK-Antwort einen Fehler. `loadFromUrls` lädt nacheinander.

## Locale wechseln {#switch-locale}

```ts
i18n.locale = 'de'
i18n.t('greeting', { name: 'Ada' }) // 'Hallo, Ada!'
```

Änderungen an Locale, Route und Wörterbuch benachrichtigen die Abonnenten; so rendern Framework-Bindings neu:

```ts
const stop = i18n.subscribe(() => {
  document.querySelector('#greeting')!.textContent = i18n.t('greeting', { name: 'Ada' }) as string
})
i18n.locale = 'fr'
stop()
```

`getSnapshot()` gibt einen String zurück, der sich bei jeder Benachrichtigung ändert (für Stores im Stil von `useSyncExternalStore`).

## Pro Anfrage {#per-request}

Die Instanz hält eine Locale und eine Route. Wechsle auf einem Server keine gemeinsam genutzte Instanz pro Anfrage: Zwei gleichzeitige Anfragen würden die Locale der jeweils anderen sehen. `i18n.fork(locale)` gibt einer Anfrage ihre eigene: eigene Locale, eigenes Fallback und eigene Route; dieselben Wörterbücher, Formatierer und Regeln. Ein Fork kostet gleich viel, egal wie viele Wörterbücher es gibt. Ein Fork sieht Schreibvorgänge in seinem Elternobjekt bis zu seinem ersten eigenen Schreibvorgang, und seine Schreibvorgänge bleiben bei ihm. [Node.js](/de/integrations/nodejs-package#per-request) fügt `run` hinzu.

## API {#api}

| Mitglied | Hinweise |
| --- | --- |
| `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` | siehe [Übersetzen und formatieren](/de/integrations/overview#translate-and-format) |
| `locale`, `fallbackLocale` | lesen/setzen |
| `currentRoute`, `setRoute(name)`, `getRoute()` | aktive Route, Standard `'index'` |
| `loadMessages(messages?, routeMessages?)` | viele Locales und Routen auf einmal zusammenführen |
| `addTranslations(locale, tree, merge = true)`, `addRouteTranslations(locale, route, tree, merge = true)` | |
| `loadFromUrl(url, { locale?, routeName?, init? })`, `loadFromUrls(entries)` | JSON per `fetch` |
| `hasTranslation(key)` | aktive Locale, beliebige Route (anders als `has`, das die aktive Route und Root prüft) |
| `setTranslation(key, value)`, `resolveTranslations()` | einen Schlüssel schreiben; den zusammengeführten Baum lesen |
| `clear()`, `clearCache()` | alle Wörterbücher verwerfen |
| `subscribe(cb)`, `getSnapshot()` | Änderungsbenachrichtigungen |
| `storage` | `{ translations: Map<'locale:route', Translations> }` |

Ein Code, der kein Sprach-Tag ist, erhält seine Pluralformen über `localeIso: { ua: 'uk-UA' }`; `localeIsoMap(locales)` erstellt das aus den Einträgen einer Locale-Liste, die ein `iso` haben.

Modul-Exporte: `createI18n`, `I18n`, `fetchJsonTranslations`, `FormatService`, `interpolate`, `localeIsoMap` sowie die Typen `I18nOptions`, `LoadFromUrlOptions`, `LoadFromUrlEntry`, `TranslationStorage`, `Translations`, `Locale`, `PluralFunc`. Vollständige Signaturen: [Paketreferenz](/de/api/packages/runtime).
