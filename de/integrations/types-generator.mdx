# 🔧 Types-Generator (`@i18n-micro/types-generator`)

Das Paket `@i18n-micro/types-generator` erzeugt automatisch TypeScript-Typen für Übersetzungsschlüssel. Es analysiert deine JSON-Übersetzungsdateien und generiert strikte Typen. So bekommst du volle Typsicherheit und Autovervollständigung für Übersetzungsschlüssel.

## 📖 Überblick

`@i18n-micro/types-generator` ist eine optionale Dev-Abhängigkeit und verbessert deine Entwicklungserfahrung durch:

- 🔍 **Automatische Typenerzeugung**: scannt JSON-Übersetzungsdateien und erzeugt TypeScript-Typen.
- ✅ **Typsicherheit**: verhindert Tippfehler und ungültige Übersetzungsschlüssel zur Compile-Zeit.
- 🎯 **Autovervollständigung**: volle IDE-Autovervollständigung für Übersetzungsschlüssel.
- 🔄 **Hot Reload**: erzeugt Typen automatisch neu, wenn sich Übersetzungsdateien ändern.
- 🚀 **Kein Runtime-Overhead**: Typen existieren nur zur Compile-Zeit, kein Einfluss auf die Bundle-Größe.

## 🎯 Schnellstart

### Für Nuxt-Projekte

Ergänze das Modul in deiner `nuxt.config.ts`:

```typescript
import { defineNuxtConfig } from 'nuxt/config'

export default defineNuxtConfig({
  modules: [
    'nuxt-i18n-micro',
    '@i18n-micro/types-generator/nuxt', // Add types generator
  ],
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    translationDir: 'locales', // Path to your translation files
  },
})
```

Der Generator wird automatisch:

- alle JSON-Dateien im Verzeichnis `locales` scannen.
- Typen in `.nuxt/i18n-micro.d.ts` erzeugen.
- Änderungen beobachten und Typen automatisch neu erzeugen.

### Für Vue-/Vite-Projekte

Ergänze das Plugin in deiner `vite.config.ts`:

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { I18nTypesPlugin } from '@i18n-micro/types-generator'

export default defineConfig({
  plugins: [
    vue(),
    I18nTypesPlugin({
      srcDir: 'src',
      translationDir: 'locales',
      outputFile: 'src/i18n-types.d.ts', // Optional: custom output path
    }),
  ],
})
```

Achte darauf, die generierte Datei in deiner `tsconfig.json` einzubinden:

```json
{
  "include": ["src/**/*", "src/i18n-types.d.ts"]
}
```

## 📁 Struktur der Übersetzungsdateien

Der Generator unterstützt flache und verschachtelte Übersetzungsstrukturen:

```
locales/
  en.json
  fr.json
  pages/
    home/
      en.json
      fr.json
    about/
      en.json
      fr.json
```

**Beispiel `locales/en.json`:**

```json
{
  "greeting": "Hello, {name}!",
  "header": {
    "title": "Welcome",
    "subtitle": "Subtitle"
  },
  "errors": {
    "404": "Not found",
    "500": "Server error"
  },
  "apples": "no apples | one apple | {count} apples"
}
```

Der Generator erzeugt Typen für alle Schlüssel, auch verschachtelte:

```typescript
// Generated types
declare module '@i18n-micro/types' {
  export interface DefineLocaleMessage {
    greeting: string
    'header.title': string
    'header.subtitle': string
    'errors.404': string
    'errors.500': string
    apples: string
  }
}
```

## 💡 Verwendung

Nach der Typenerzeugung hast du volle Typsicherheit:

```typescript
import { useI18n } from '@i18n-micro/vue'

const { t } = useI18n()

// ✅ Type-safe: autocomplete works
t('greeting', { name: 'World' })
t('header.title')
t('errors.404')

// ❌ Type error: key doesn't exist
t('invalid.key') // Error: Argument of type '"invalid.key"' is not assignable
```

### Hinweis für Nuxt

**In Nuxt-Projekten funktioniert Typsicherheit nur mit dem Composable `useI18n`.** Die generierten Typen wirken auf den Rückgabewert des Composables und stellen Typsicherheit bei den Methoden `t()`, `ts()`, `tc()` und `has()` sicher.

```typescript
// ✅ Correct: Using useI18n composable
<script setup lang="ts">
import { useI18n } from '#imports'

const { t } = useI18n()
t('greeting') // Type-safe with autocomplete
</script>

// ❌ Not type-safe: Direct access to $i18n or other methods
// Type safety is only available through the useI18n composable
```

## 🔄 Dynamische Schlüssel

Manchmal brauchst du dynamische Schlüssel (zum Beispiel abhängig von Nutzereingaben oder API-Antworten). Der Generator bietet den Hilfstyp `ScopedKey` für die sichere Nutzung dynamischer Schlüssel.

### Warum keine Runtime-Type-Guards?

**Runtime-Type-Guards werden bei i18n-micro nicht empfohlen**, weil:

1. **Bundle-Größe**: Ein JavaScript-Array aller Schlüssel würde dein Bundle aufblähen.
2. **Performance**: Runtime-Prüfungen verursachen unnötigen Overhead.
3. **Philosophie**: i18n-micro ist bewusst schlank und schnell.

### Der TypeScript-Weg: Type Assertions

Für dynamische Schlüssel nutzt du TypeScript-Type-Assertions:

```typescript
import type { TranslationKey, ScopedKey } from '@i18n-micro/types'

// ❌ Type error: dynamic key
const status = 'pending'
t(`status.${status}`) // Error: string is not assignable to TranslationKey

// ✅ Solution 1: Type assertion (if you're sure the key exists)
t(`status.${status}` as TranslationKey)

// ✅ Solution 2: ScopedKey helper (safer, checks prefix exists)
function getStatusText(status: string) {
  return t(`status.${status}` as ScopedKey<'status'>)
  // TypeScript verifies that keys starting with 'status.' exist
}

// ✅ Solution 3: Runtime check with has()
if (has(`status.${status}`)) {
  t(`status.${status}` as TranslationKey)
}
```

### `ScopedKey`-Helfer

Der Typ `ScopedKey<Scope>` schränkt dynamische Schlüssel per Präfix ein:

```typescript
import type { ScopedKey } from '@i18n-micro/types'

// Assuming you have keys: 'errors.404', 'errors.500', 'btn.save'

function getErrorText(code: string) {
  // ✅ Safer than plain TranslationKey
  // TypeScript verifies that 'errors.*' keys exist
  return t(`errors.${code}` as ScopedKey<'errors'>)
}

// ❌ Type error: 'btn' prefix doesn't match 'errors'
function getErrorTextWrong(code: string) {
  return t(`errors.${code}` as ScopedKey<'btn'>) // Error
}
```

## 🎨 Fortgeschrittene Nutzung

### Umgang mit routenspezifischen Übersetzungen

Der Generator übernimmt automatisch Schlüssel aus routenspezifischen Übersetzungsdateien:

```
locales/
  en.json                    # Root-level translations
  pages/
    home/
      en.json               # Route-specific translations
    about/
      en.json
```

Alle Schlüssel aus Root- und routenspezifischen Dateien fließen in die generierten Typen ein.

### Seiten-Locales deaktivieren

Wenn du `disablePageLocales: true` in deiner i18n-Konfiguration verwendest, behandelt der Generator alle Dateien (auch die in `pages/`) als Root-Übersetzungen.

## 🐛 Fehlersuche

### Typen werden nicht aktualisiert

1. **Pfade prüfen**: `translationDir` muss auf das richtige Verzeichnis zeigen.
2. **TypeScript-Server neu starten**: In VS Code `Cmd/Ctrl + Shift + P` → „TypeScript: Restart TS Server“.
3. **`tsconfig.json` prüfen**: Die generierte Datei muss enthalten sein.

### Typfehler nach dem Hinzufügen von Schlüsseln

1. **Typen neu erzeugen**: Der Generator sollte automatisch neu erzeugen. Du kannst das auch manuell auslösen.
2. **JSON-Syntax prüfen**: Ungültige JSON-Dateien werden mit einer Warnung übersprungen.
3. **Dev-Server neu starten**: Manchmal nötig, damit Änderungen greifen.

### Autovervollständigung fehlt

1. **Datei-Einbindung prüfen**: Die generierte `.d.ts` muss im `include` der `tsconfig.json` stehen.
2. **Module-Augmentation prüfen**: Die generierte Datei verwendet `declare module '@i18n-micro/types'`.
3. **TypeScript-Version**: Erfordert TypeScript 4.1+ für Template-Literal-Typen.

## 📚 API-Referenz

### `generateTypes(options: GeneratorOptions)`

Typen manuell erzeugen (nützlich für Skripte oder CI):

```typescript
import { generateTypes } from '@i18n-micro/types-generator'

await generateTypes({
  srcDir: './src',
  translationDir: 'locales',
  outputFile: './src/i18n-types.d.ts',
})
```

### `flattenKeys(obj: Record<string, unknown>, prefix?: string)`

Utility, um verschachtelte Übersetzungsobjekte zu flatten:

```typescript
import { flattenKeys } from '@i18n-micro/types-generator'

const keys = flattenKeys({
  header: { title: 'Title' },
  footer: { copyright: 'Copyright' },
})
// Returns: ['header.title', 'footer.copyright']
```

## 🔍 So funktioniert es

1. **Scannen**: `globby` findet alle `**/*.json`-Dateien im Übersetzungsverzeichnis.
2. **Parsen**: Jede JSON-Datei wird geparst und alle Schlüssel werden rekursiv geflattet.
3. **Deduplizieren**: Schlüssel aus allen Dateien werden zu einem eindeutigen Set kombiniert.
4. **Erzeugen**: Eine `.d.ts`-Datei mit `declare module`-Augmentation wird geschrieben.
5. **Beobachten**: Im Dev-Modus werden Dateiänderungen beobachtet und Typen neu erzeugt.

Die generierte Datei nutzt TypeScript-Modul-Augmentation, um `DefineLocaleMessage` in `@i18n-micro/types` zu erweitern. Dadurch aktualisiert sich der Typ `TranslationKey` in deinem gesamten Projekt automatisch.

## 🎯 Best Practices

1. **Übersetzungen ordnen**: Nutze verschachtelte Objekte für zusammengehörige Schlüssel.
2. **Konsistente Benennung**: Halte dich an eine Namenskonvention (zum Beispiel `errors.*`, `buttons.*`).
3. **`ScopedKey` nutzen**: Verwende `ScopedKey` für dynamische Schlüssel statt roher Assertions.
4. **Typprüfung im CI**: Lasse die Typprüfung in deiner CI-Pipeline laufen.
5. **Generierte Dateien nicht bearbeiten**: Die `.d.ts` wird automatisch erzeugt und überschrieben.
