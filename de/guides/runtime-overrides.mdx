# i18n-Überschreibungen zur Laufzeit

Nutze diesen Guide, wenn ein Build-Artefakt mit unterschiedlichen Locale-Defaults pro Umgebung laufen soll (zum Beispiel unterschiedliche Mandanten-Instanzen).

## Was zur Laufzeit überschrieben werden kann

Das Modul unterstützt sichere Runtime-Überschreibungen für:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Diese Überschreibungen werden auf die Build-Zeit-Konfiguration aus `.nuxt/i18n.strategy.mjs` und `.nuxt/i18n.config.mjs` angewendet.

## Was zur Laufzeit nicht überschrieben werden kann

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) ist eine Build-Zeit-Angelegenheit, weil sie das Verhalten der generierten Routen beeinflusst.

Wenn du eine Runtime-Überschreibung für `strategy` übergibst, wird sie ignoriert und eine Warnung ausgegeben.

## Überschreibungen per RuntimeConfig

Setze Runtime-Werte unter `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Überschreibungen per Umgebungsvariablen

Alternativ kannst du Überschreibungen über Umgebungsvariablen konfigurieren:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (kommagetrennt, zum Beispiel `fr,it`)

Fallback-Aliase werden ebenfalls unterstützt:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Validierungsregeln

Zur Laufzeit validiert das Modul Überschreibungen, um einen kaputten Zustand zu vermeiden:

- Du kannst nicht alle Locales deaktivieren.
- `defaultLocale` muss auf eine aktive Locale zeigen.
- `fallbackLocale` muss in den deklarierten Locales enthalten sein.

Ist eine Überschreibung ungültig, behält das Modul einen sicheren Wert bei und protokolliert eine Warnung.

## Hinweise für Multi-Instance-Deployments

Diese Runtime-Funktion ist für die Locale-Aktivierung und Defaults pro Instanz gedacht, ohne neu zu bauen.

Wenn Instanzen unterschiedliche URL-Strategien brauchen (`no_prefix` vs. `prefix`), verwende getrennte Builds pro Strategie.

## Deaktivierte Locales und statische Payloads

`runtimeConfig.public.i18nRuntime.disabledLocales` aktualisiert Routing, Switcher und den Nitro-Payload-**Handler**. Nitro liefert Dateien unter `public/` jedoch **vor** diesem Handler aus.

Wenn `translationPayloads.publicAssets` (oder die erzwungene Public-Kopie bei Node-SSR) bereits `/_locales/\{page\}/\{locale\}/data.json` geschrieben hat, kann ein Runtime-Disable diese Datei nicht verstecken. Bevorzuge `locale.disabled: true` zur Buildzeit, damit Premerge die statischen Payloads dieser Locale erst gar nicht erzeugt.
