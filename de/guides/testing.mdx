# 🧪 Modul `Nuxt I18n Micro` testen

## 📖 Einführung ins Testen

Das Modul `Nuxt I18n Micro` zu testen ist entscheidend, damit die Lokalisierungsfunktionen deiner Anwendung wie erwartet arbeiten. Diese Doku führt dich durch das Einrichten der Testumgebung, das Erstellen von Mock-Konfigurationen für Vitest und das Schreiben von Tests für deine Komponenten. Ein praxisnahes Beispiel findest du im [Beispielprojekt auf GitHub](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/test-utils/example).

Wie dieses Repository seine eigenen Suiten laufen lässt, siehst du unter [Testing routing strategies](https://github.com/s00d/nuxt-i18n-micro/blob/main/docs/guide/testing-strategies.md). Dort werden die Vitest-Projekte `unit`, `integration` und `e2e`, die Dateien je Strategie (`test/strategies-*.test.ts`) und Regressionstests behandelt.

## 🛠️ Testumgebung einrichten

### 1. `@i18n-micro/test-utils` installieren

Installiere zuerst die Test-Utilities für `Nuxt I18n Micro`. Dieses Paket bringt die nötigen Werkzeuge zum Mocken und Testen deiner i18n-Konfigurationen mit.

```bash
npm install @i18n-micro/test-utils --save-dev
```

### 2. Mock-Konfigurationsdatei anlegen

Als Nächstes legst du eine Datei für die Mock-i18n-Konfiguration an. Sie mockt die i18n-Funktionen und -Utilities in deinen Tests.

```typescript
// tests/unit-setup.ts

import { mockNuxtImport } from '@nuxt/test-utils/runtime'
import { vi } from 'vitest'
import { i18nUtils } from '@i18n-micro/test-utils'

export function createFakeI18n() {
  return {
    $getLocale: vi.fn(i18nUtils.getLocale),
    $t: vi.fn(i18nUtils.t),
    $tc: vi.fn(i18nUtils.tc),
    $setLocale: vi.fn(i18nUtils.setLocale),
    $getLocaleName: vi.fn(i18nUtils.getLocaleName),
    $setLocaleName: vi.fn(i18nUtils.setLocaleName),
    $getLocales: vi.fn(i18nUtils.getLocales),
    $setLocales: vi.fn(i18nUtils.setLocales),
    $defaultLocale: vi.fn(i18nUtils.defaultLocale),
    $setDefaultLocale: vi.fn(i18nUtils.setDefaultLocale),
    $getRouteName: vi.fn(i18nUtils.getRouteName),
    $settRouteName: vi.fn(i18nUtils.settRouteName),
    $ts: vi.fn(i18nUtils.ts),
    $tn: vi.fn(i18nUtils.tn),
    $td: vi.fn(i18nUtils.td),
    $has: vi.fn(i18nUtils.has),
    $resolveTranslations: vi.fn(i18nUtils.resolveTranslations),
    $setTranslation: vi.fn(i18nUtils.setTranslation),
    $mergeTranslations: vi.fn(i18nUtils.mergeTranslations),
    $switchLocaleRoute: vi.fn(i18nUtils.switchLocaleRoute),
    $switchLocalePath: vi.fn(i18nUtils.switchLocalePath),
    $switchLocale: vi.fn(i18nUtils.switchLocale),
    $switchRoute: vi.fn(i18nUtils.switchRoute),
    $localeRoute: vi.fn(i18nUtils.localeRoute),
    $localePath: vi.fn(i18nUtils.localePath),
    $setI18nRouteParams: vi.fn(i18nUtils.setI18nRouteParams),
  }
}

mockNuxtImport<() => ReturnType<typeof createFakeI18n>>('useI18n', () => vi.fn(() => createFakeI18n()))

export const setTranslationsFromJson = i18nUtils.setTranslationsFromJson
```

### 3. Vitest konfigurieren

Konfiguriere nun Vitest so, dass die Mock-Konfigurationsdatei verwendet und die Testumgebung eingerichtet wird.

```typescript
// vitest.config.ts

import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    watch: false,
    setupFiles: ['./tests/unit-setup.ts'],
    include: ['./**/*.spec.ts'],
  },
})
```

## 🧪 Tests schreiben

### Beispielkomponente

Hier ein Beispiel für eine einfache Komponente, die mit dem Composable `useI18n` Nachrichten übersetzt.

```vue
<script setup lang="ts">
const { $t } = useI18n()

const props = defineProps({
  message: {
    type: String,
    default: null,
  },
})

// Test to see that $t works in script setup as well as the template
const message = props.message || $t('defaultMessage')
</script>

<template>
  <div>
    <p>Test from component: {{ $t('welcome') }}</p>
    <p data-testid="message">Test message from props: {{ message }}</p>
  </div>
</template>
```

### Testdatei

Und nun ein Test für diese Komponente.

```typescript
// tests/unit/example.spec.ts

import { describe, it, expect, beforeEach } from 'vitest'
import { mount } from '@vue/test-utils'
import ExampleComponent from '@/components/ExampleComponent.vue'
import fs from 'fs'
import path from 'path'
import { setTranslationsFromJson } from './unit-setup'

describe('ExampleComponent', () => {
  beforeEach(async () => {
    const fileContent = fs.readFileSync(path.join(__dirname, '../../locales/en-GB.json')).toString()
    await setTranslationsFromJson('en', JSON.parse(fileContent))
  })

  it('renders the welcome message correctly', () => {
    const wrapper = mount(ExampleComponent)
    expect(wrapper.text()).toContain('Test from component: Welcome')
  })

  it('renders the default message correctly', () => {
    const wrapper = mount(ExampleComponent)
    expect(wrapper.find('[data-testid="message"]').text()).toContain('Test message from props: Default Message')
  })

  it('renders the custom message correctly', () => {
    const wrapper = mount(ExampleComponent, {
      props: {
        message: 'Custom Message',
      },
    })
    expect(wrapper.find('[data-testid="message"]').text()).toContain('Test message from props: Custom Message')
  })
})
```

## 📝 Best Practices fürs Testen

- **🔧 i18n-Funktionen mocken:** Mocke i18n-Funktionen immer mit `@i18n-micro/test-utils`, damit deine Tests konsistente und vorhersagbare Ergebnisse liefern.
- **⚙️ Unit-Tests mit Vitest:** Vitest ist ein starkes Test-Framework für Vue-Anwendungen. Nutze es für Unit-Tests deiner Komponenten.
- **📚 Tests dokumentieren:** Beschreibe Zweck und erwartete Ergebnisse jedes Tests. Das erhält die Übersicht und macht es leichter, die Tests später zu verstehen.

## 📊 i18n-Utility-Methoden

Die folgende Tabelle beschreibt alle Utility-Methoden, die `@i18n-micro/test-utils` bereitstellt.

| Methode                                          | Beschreibung                                                                                                                                |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `t(key, params, defaultValue)`                  | Übersetzt einen Schlüssel mit optionalen Parametern und einem Default-Wert.                                                                 |
| `tc(key, params, defaultValue)`                 | Übersetzt einen Schlüssel mit Pluralisierung.                                                                                              |
| `setTranslationsFromJson(locale, translations)` | Lädt Übersetzungen aus einem JSON-Objekt für eine bestimmte Locale.                                                                        |
| `getLocale()`                                   | Liefert die aktuelle Locale.                                                                                                               |
| `setLocale(val)`                                | Setzt die aktuelle Locale.                                                                                                                 |
| `getLocaleName()`                               | Liefert den aktuellen Locale-Namen.                                                                                                        |
| `setLocaleName(val)`                            | Setzt den aktuellen Locale-Namen.                                                                                                          |
| `getLocales()`                                  | Liefert die Liste der verfügbaren Locales.                                                                                                 |
| `setLocales(val)`                               | Setzt die Liste der verfügbaren Locales.                                                                                                   |
| `defaultLocale()`                               | Liefert die Standard-Locale.                                                                                                               |
| `setDefaultLocale(val)`                         | Setzt die Standard-Locale.                                                                                                                 |
| `getRouteName()`                                | Liefert den aktuellen Routennamen.                                                                                                         |
| `settRouteName(val)`                            | Setzt den aktuellen Routennamen.                                                                                                           |
| `ts(key, params, defaultValue)`                 | Übersetzt einen Schlüssel und liefert das Ergebnis als String.                                                                             |
| `tn(value, options?)`                           | Formatiert eine Zahl mit inline übergebenen `Intl.NumberFormatOptions`. Benannte Formate brauchen Modulkonfiguration und sind hier nicht verfügbar. |
| `td(value, options?)`                           | Formatiert ein Datum mit inline übergebenen `Intl.DateTimeFormatOptions`. Benannte Formate brauchen Modulkonfiguration und sind hier nicht verfügbar. |
| `has(key)`                                      | Prüft, ob ein Übersetzungs-Schlüssel existiert.                                                                                            |
| `resolveTranslations()`                         | Liefert den aktiven Übersetzungsbaum für aktuelle Locale und Route.                                                                        |
| `setTranslation(key, value)`                    | Ersetzt den Wert bei `key` im aktiven Wörterbuch (Ersetzen, kein Mergen).                                                                  |
| `mergeTranslations(newTranslations)`            | Mischt Übersetzungen zur Laufzeit in die aktive Locale.                                                                                    |

Mit diesen Schritten testest du das Modul `Nuxt I18n Micro` effektiv und stellst sicher, dass die Lokalisierungsfunktionen deiner Anwendung wie erwartet funktionieren.
