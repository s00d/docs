# Statische Dateien vom i18n-Routing ausschließen

## Überblick

Standardmäßig schließt `nuxt-i18n-micro` gängige statische Dateien automatisch aus der i18n-Routing-Verarbeitung aus. Zusätzlich kannst du eigene Ausschlussmuster konfigurieren, damit bestimmte Pfade nicht vom i18n-System bearbeitet werden.

## Eingebaute Ausschlüsse

Das Modul schließt folgende Dateitypen und Muster automatisch aus:

- **Sitemaps**: `/sitemap*.xml`, `/sitemap-en.xml` usw.
- **SEO-Dateien**: `/robots.txt`, `/favicon.ico`
- **PWA-Dateien**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Statische Assets**: Dateien mit Endungen wie `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Interne Nuxt-Pfade**: Jeder Pfad, der mit `__` beginnt (zum Beispiel `/__nuxt/`)

## Eigene Ausschlussmuster

Eigene Ausschlussmuster definierst du über die Option `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Musterarten

### String-Muster

- **Exakte Übereinstimmung**: `'/api/health'` trifft genau auf `/api/health`.
- **Präfix-Übereinstimmung**: `'/admin'` trifft auf `/admin` und `/admin/dashboard`.
- **Wildcards**: `'/api/*'` trifft auf `/api/users`, aber nicht auf `/api/users/123`.
- **Tiefe Wildcards**: `'/admin/**'` trifft auf `/admin/users` und `/admin/users/123`.

### Reguläre Ausdrücke

Verwende RegExp-Objekte für komplexes Pattern-Matching:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Anwendungsfälle

### SEO-Dateien

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API-Routen

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Admin-Bereiche

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Statische Assets

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## So funktioniert es

1. **Server-Middleware**: Zuerst prüft eine Nitro-Middleware die Ausschlussmuster.
2. **Seitenverarbeitung**: Bei der Seitenauflösung werden ausgeschlossene Pfade übersprungen.
3. **Catch-all-Route**: Die Fallback-Route prüft Ausschlüsse vor der Verarbeitung.
4. **Prerendering**: Ausgeschlossene Pfade werden nicht mit prerenderten Routen erzeugt.

## Performance

- Ausschlussprüfungen sind optimiert und laufen früh im Request-Lifecycle.
- Eingebaute Muster nutzen effizientes Regex-Matching.
- Eigene Muster werden gecached und wiederverwendet.
- Der Overhead für ausgeschlossene Pfade ist minimal.

## Fehlersuche

### Statische Dateien werden weiterhin abgefangen

1. **Muster-Syntax prüfen**: Deine Muster müssen zur exakten Pfadstruktur passen.
2. **Für komplexe Muster Regex verwenden**: String-Wildcards haben Grenzen.
3. **Muster testen**: Prüfe den tatsächlichen Request-Pfad mit den Dev-Tools des Browsers.
4. **Reihenfolge prüfen**: Ausschlussmuster müssen vor anderen i18n-Konfigurationen definiert sein.

### Muster funktioniert nicht

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Debug-Modus

Aktiviere den Debug-Modus, um die Ausschlussverarbeitung zu sehen:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Damit werden Ausschluss-Entscheidungen in die Konsole geloggt.

## Migration von Workarounds

Wenn du bisher Workarounds wie Route Rules oder Middleware genutzt hast, kannst du sie nun durch `excludePatterns` ersetzen:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Der neue Ansatz ist zuverlässiger und wirkt auf mehreren Ebenen des Routing-Systems.
