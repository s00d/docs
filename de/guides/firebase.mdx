# 🔥 Firebase-AppHosting-Deployment

## 📖 Einführung

Firebase AppHosting ist eine leistungsfähige Plattform, um Nuxt-Anwendungen auf serverloser Infrastruktur zu deployen. Beim Deployment von Anwendungen mit `nuxt-i18n-micro` können jedoch spezifische Probleme rund um die Auslieferung von Übersetzungs-JSON-Dateien auftreten. Dieser Guide bietet umfassende Lösungen, damit deine Übersetzungen in der Produktion zuverlässig funktionieren.

## ⚠️ Häufige Probleme

### Übersetzungsdateien werden nicht angewendet

**Symptome:**

- ✅ Übersetzungen funktionieren in der Entwicklung (`nuxt dev`) einwandfrei.
- ❌ Nach dem Deployment auf Firebase AppHosting werden JSON-Dateien geladen, Übersetzungen aber nicht angewendet.
- ❌ In der Konsole erscheinen keine Fehler.
- ❌ Übersetzungsdateien sind im Network-Tab sichtbar, haben aber `Content-Type: text/html` statt `application/json`.

**Grundursache:**

Firebase AppHosting (und andere Plattformen mit Nitro-Prerendering) liefert vorgerenderte JSON-Dateien manchmal mit falschem MIME-Typ aus. Empfängt der Browser JSON-Dateien mit `Content-Type: text/html`, kann er sie nicht korrekt parsen. Die Übersetzungen scheitern still.

## ✅ Lösungen

### Lösung 1: Route Rules konfigurieren (empfohlen)

Am einfachsten fügst du in `nuxt.config.ts` explizite Header für die Übersetzungsrouten hinzu:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**Vorteile:**

- ✨ Einfache Konfiguration
- 🚀 Bessere Performance durch geeignetes Caching
- 🔒 Funktioniert plattformübergreifend

### Lösung 2: Eigene API-Basis-URL

Wenn du eine eigene `apiBaseUrl` (nur Pfad-Präfix) nutzt, passe die Route Rules entsprechend an:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### Lösung 3: Firebase-spezifische Konfiguration

Erstelle oder aktualisiere die Datei `firebase.json` im Projekt-Root:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```


### Lösung 4: Firebase-Functions-Konfiguration

Für ein Deployment mit Firebase Functions stellst du sicher, dass `functions/package.json` die nötigen Abhängigkeiten enthält:

```json
{
  "name": "functions",
  "type": "module",
  "engines": {
    "node": "18"
  },
  "dependencies": {
    "firebase-admin": "^12.0.0",
    "firebase-functions": "^5.0.0"
  }
}
```

## 🔍 Debugging

### Debug-Modus aktivieren

Aktiviere Debug-Logs, um Probleme zu erkennen:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

Damit werden ausführliche Logs ausgegeben zu:

- 📝 Laden der Übersetzungsdateien
- 🔄 Cache-Operationen
- ⚠️ Ladefehlern

### Network-Tab prüfen

1. DevTools öffnen → Tab „Network“.
2. Nach „data.json“ filtern.
3. Einen Übersetzungs-Request anklicken.
4. **Response Headers** prüfen:
   - ✅ `Content-Type: application/json` (korrekt)
   - ❌ `Content-Type: text/html` (falsch, muss korrigiert werden)

### Prerender-Ausgabe verifizieren

Nach dem Build prüfst du, ob Übersetzungsdateien erzeugt wurden:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

Du solltest `data.json` je Locale und je Seite sehen.

## 🚀 Build-Konfiguration

### Nitro-Preset

Für Firebase AppHosting nutzt du das passende Preset:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### Prerender-Konfiguration

Prerendering für optimale Performance konfigurieren:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

## 📋 Vollständiges Beispiel

Eine komplette, funktionierende Konfiguration für Firebase AppHosting:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'es', iso: 'es-ES', dir: 'ltr' },
      { code: 'it', iso: 'it-IT', dir: 'ltr' },
      { code: 'pt', iso: 'pt-PT', dir: 'ltr' },
      { code: 'ru', iso: 'ru-RU', dir: 'ltr' },
      { code: 'zh', iso: 'zh-CN', dir: 'ltr' },
      { code: 'ko', iso: 'ko-KR', dir: 'ltr' },
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
    debug: false, // Enable in development if needed
  },

  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },

  nitro: {
    preset: 'firebase-app-hosting',
    prerender: {
      crawlLinks: true,
      routes: ['/'],
    },
  },
})
```

```json
// firebase.json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "headers": [
      {
        "source": "/_locales/**/*.json",

          {
            "key": "Content-Type",
            "value": "application/json"

        "source": "**/*.@(jpg|jpeg|gif|png|webp|svg|ico)",

          {
            "key": "Cache-Control",

          }
        ]

    ],
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ]
  },

    "source": ".output/server",
    "runtime": "nodejs18"
  }
}
```

## ✅ Verifizierungs-Checkliste

Nach den Anpassungen prüfst du, dass alles funktioniert:

- [ ] Build läuft ohne Fehler durch.
- [ ] Übersetzungs-JSON-Dateien liegen unter `.output/public/_locales/\{page\}/\{locale\}/data.json`.
- [ ] Der Network-Tab zeigt `Content-Type: application/json` für Übersetzungsdateien.
- [ ] Übersetzungen erscheinen beim ersten Laden korrekt.
- [ ] Keine Hydration-Mismatches in der Konsole.
- [ ] Sprachwechsel funktioniert.
- [ ] SEO-Meta-Tags werden korrekt erzeugt.

## 🔄 Deployment-Workflow

### 1. Build vorbereiten

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. Auf Firebase deployen

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. Deployment verifizieren

1. Rufe deine deployte Seite auf.
2. Öffne die DevTools → Tab „Network“.
3. Navigiere zu einer Seite.
4. Prüfe, dass `/_locales/index/en/data.json` (oder deine Standard-Locale) lädt:
   - Status: 200
   - Content-Type: application/json
   - Antwort enthält gültiges JSON

## 🔧 Fehlersuche

### Problem: 404-Fehler für Übersetzungsdateien

**Lösung:** Stelle sicher, dass die Übersetzungsdateien in das Ausgabeverzeichnis kopiert werden:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### Problem: Übersetzungen funktionieren auf einigen Seiten, auf anderen nicht

**Lösung:** Prüfe, ob seitenspezifische Übersetzungen erzeugt werden:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

Fehlen seitenspezifische Übersetzungen, stelle sicher, dass `disablePageLocales` nicht auf `true` steht:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### Problem: Übersetzungen laden langsam

**Lösung:** Caching und Preloading optimieren:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## 💡 Tipps

1. **Immer in einer produktionsnahen Umgebung testen**, bevor du deployst.
2. **Debug-Modus** in der Anfangsphase aktivieren, um Probleme früh zu erkennen.
3. **Cache-Hit-Raten überwachen**, um die Performance zu optimieren.
4. **Übersetzungsdateien schlank halten** für schnelleres Laden.
5. **Passende Cache-Header setzen**, um die Serverlast zu senken.

## ⚡ Performance-Optimierung

### Kompression aktivieren

Firebase handhabt Gzip- und Brotli-Kompression automatisch. Achte dennoch auf einen optimierten Build:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### Lazy-Load für Übersetzungen

`Nuxt I18n Micro` lädt Übersetzungen automatisch pro Seite lazy. Nur benötigte Übersetzungen werden geladen, was die initiale Bundle-Größe reduziert. Das ist eingebaut, keine zusätzliche Konfiguration nötig.

Zur weiteren Optimierung:

- Nutze `disablePageLocales: false` (Standard), damit seitenspezifische Übersetzungen aktiv sind.
- Halte Root-Übersetzungen minimal.
- Verwende routenspezifische Übersetzungsdateien für Seiteninhalte.

<Tip>
Das Modul setzt ab **v3.0.0+** automatisch die richtigen `Content-Type`-Header. Wenn du Probleme hast, aktualisiere auf die neueste Version:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
