# Übersetzungen in Komponenten verwenden

Sobald das Modul installiert und konfiguriert ist, zeigst du Übersetzungen mit `$t('your_key')` in deinen Vue-Templates und -Skripten an.

## 1. Root- und seitenspezifische Übersetzungsdateien

1. **Root-Übersetzungen** liegen direkt im Ordner `/locales` (zum Beispiel `/locales/en.json`, `/locales/fr.json`). Sie werden zur Buildzeit automatisch in jede seitenspezifische Datei eingemischt und sind auf allen Seiten verfügbar.
2. **Seitenspezifische Übersetzungen** liegen unter `/locales/pages/...` und spiegeln die Ordnerstruktur deiner Nuxt-Seiten:

```text
locales/
├── en.json
├── fr.json
└── pages/
    └── dir1/
        ├── en.json
        └── fr.json

```

## 2. Verwendung im Template mit `$t`

In deinen `.vue`-Dateien nutzt du `$t` direkt im Template:

```vue
<template>
  <div>
    <!-- Root-level translation (available on all pages) -->
    <p>{{ $t('test_key') }}</p>
    <!-- Displays: Hello World! -->

    <!-- Page-specific translation (if this page is /dir1) -->
    <p>{{ $t('local_key') }}</p>
    <!-- Displays: This is a page-specific translation for /dir1. -->

    <!-- Nested key -->
    <p>{{ $t('nested.key.deeper') }}</p>
    <!-- Displays: Nested translation here -->

    <!-- Placeholder usage -->
    <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
    <!-- Displays: Hello, Alice! -->
  </div>
</template>

<script setup lang="ts">
// No need to import anything from 'nuxt-i18n-micro'.
// The plugin automatically provides `useI18n` and `$t`.
const { $t } = useI18n()

// You can now use $t in your script, for example:
console.log($t('test_key')) // "Hello World!"
</script>
```

<Tip>
`$t` kann **Objekte** zurückgeben, wenn der Schlüssel auf einen verschachtelten JSON-Knoten zeigt (zum Beispiel `$t('header')` → `\{ title: "Hi" \}`). In Templates rendert das als `[object Object]`. Verwende `$ts`, wenn du garantiert einen String brauchst, oder nutze einen spezifischeren Schlüssel wie `$t('header.title')`. Details in der [API-Referenz zu $t vs. $ts](/api/methods#t).
</Tip>

## 3. Aktuelle Locale wechseln

Um in deiner App die Sprache zu wechseln, holst du dir `$locale` aus `useI18n()` und weist ihm einen neuen Code zu:

```vue
<template>
  <div>
    <button @click="$switchLocale('en')">English</button>
    <button @click="$switchLocale('fr')">Français</button>
  </div>
</template>

<script setup lang="ts">
// The plugin auto-injects these references
const { $t, $switchLocale } = useI18n()
</script>
```

## 4. Verschachtelte Schlüssel und Platzhalter

- **Verschachtelte Schlüssel** nutzen die Punkt-Notation, zum Beispiel `nested.key.deeper`.
- **Platzhalter** setzen dynamische Werte ein:
  ```json
  { "greeting": "Hello, {name}!" }
  ```
  ```vue
  <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
  <!-- Displays: Hello, Alice! -->
  ```

## 5. Tipps und Best Practices

- **Konflikte bei Schlüsseln**: Enthält eine seitenspezifische Datei denselben Schlüssel wie eine Root-Datei, hat die seitenspezifische Version Vorrang (Root-Übersetzungen werden zur Buildzeit als Basis eingemischt).
- **Seitendateien deaktivieren**: Falls du keine seitenspezifischen Übersetzungen nutzen willst, setze `disablePageLocales: true` in deiner Nuxt-Konfiguration. Dann werden nur die Dateien in `/locales/*.json` verwendet.
- **Keine direkten Imports**: Du brauchst kein `import \{ useI18n \} from 'nuxt-i18n-micro'`. Die Auto-Injection des Moduls erledigt das für dich.

Das war’s. Mit diesen Schritten kannst du **Übersetzungen** aus Root- oder seitenspezifischen JSON-Dateien schnell **abrufen** und mit `$t` in deiner Nuxt-Anwendung **anzeigen**.

## Weitere Ressourcen

Für fortgeschrittene Funktionen schau dir das an:

1. **Komponente `<i18n-t>`**  
   Die Komponente `<i18n-t>` ist eine mächtige Alternative zu `$t`, besonders nützlich bei verschachtelten Elementen, fortgeschrittenem Platzhalter-Einsatz und komplexeren Übersetzungsstrukturen.

- **Dokumentation**: [i18n-t](/api/components/i18n-t)

2. **Composable `useI18n`**  
   Das Composable `useI18n` bietet eine komplette Sammlung an Funktionen und reaktiven Properties zum Verwalten von Übersetzungen, Wechsel der Locale, Formatierung und mehr.

- **Dokumentation**: [useI18n](/api/composables/use-i18n)
