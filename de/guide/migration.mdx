Diese Seite überträgt eine `@nuxtjs/i18n`-App auf nuxt-i18n-micro: Optionen, Helfer und Dateistruktur. Verwenden Sie sie, wenn Sie das Modul in einer bestehenden App austauschen. Ihre URLs bleiben erhalten (die Strategienamen sind identisch), und die Übersetzungen wandern in JSON-Dateien pro Seite.

<Tip>

**Sie aktualisieren nuxt-i18n-micro selbst?** — Siehe [Upgrade](/de/guide/upgrade).

</Tip>

## Das Modul austauschen {#swap-the-module}

```bash
npm uninstall @nuxtjs/i18n
npm install nuxt-i18n-micro
```

```ts
// nuxt.config.ts — before
export default defineNuxtConfig({
  modules: ['@nuxtjs/i18n'],
  i18n: {
    locales: [
      { code: 'en', language: 'en-US', file: 'en.json' },
      { code: 'de', language: 'de-DE', file: 'de.json' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    langDir: 'locales',
    detectBrowserLanguage: { useCookie: true, cookieKey: 'i18n_redirected', redirectOn: 'root' },
  },
})
```

```ts
// nuxt.config.ts — after
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    translationDir: 'locales',
    localeCookie: 'i18n_redirected',
    autoDetectPath: '/',
  },
})
```

## Optionen {#options}

| `@nuxtjs/i18n` | nuxt-i18n-micro |
| --- | --- |
| `locales[].code` | `locales[].code` |
| `locales[].language` (`iso` vor v9) | `locales[].iso` |
| `locales[].name` | `locales[].displayName` |
| `locales[].dir` | `locales[].dir` |
| `locales[].domain` | `locales[].baseUrl` (ein Origin mit Schema) |
| `locales[].domainDefault` | `locales[].baseDefault` |
| `differentDomains`, `multiDomainLocales` | nicht nötig: `baseUrl` allein routet nach Host, siehe [Layers und Domains](/de/guide/layers#multiple-domains) |
| `locales[].file` / `files`, `langDir`, `lazy` | `translationDir`; Dateien werden anhand des Namens gefunden und immer pro Seite geladen |
| `defaultLocale`, `strategy` | gleiche Namen, gleiche vier Werte |
| `baseUrl` | `metaBaseUrl` |
| `customRoutes: 'config'` + `pages` | `globalLocaleRoutes` |
| `detectBrowserLanguage: false` | `redirects: false` (keine Redirects) oder `autoDetectLanguage: false` (Header ignorieren) |
| `detectBrowserLanguage.useCookie` / `cookieKey` | `localeCookie: '<name>'` (`null` deaktiviert das Cookie) |
| `detectBrowserLanguage.redirectOn: 'root'` | `autoDetectPath: '/'` (Standard) |
| `detectBrowserLanguage.redirectOn: 'no prefix'` | `autoDetectPath: 'no_prefix'` |
| `detectBrowserLanguage.redirectOn: 'all'` | `autoDetectPath: '*'` |
| `vueI18n`-Konfigurationsdatei (`fallbackLocale`, `numberFormats`, `datetimeFormats`) | `fallbackLocale`, `numberFormats`, `datetimeFormats` in `i18n` |

Es gibt kein `alwaysRedirect`: Ist ein Cookie gesetzt, folgt `/` ihm bei jedem Besuch. Die vollständige Liste finden Sie unter [Moduloptionen](/de/api/module-options); die Erkennungsregeln stehen unter [Locale-Erkennung](/de/guide/locale-detection).

## Helfer und Composables {#helpers-and-composables}

| `@nuxtjs/i18n` / vue-i18n | nuxt-i18n-micro (Template / `useI18n()`) |
| --- | --- |
| `const { t } = useI18n()` | `const { t } = useI18n()`, `$t` in Templates |
| `t('key', count)`, `tc` | `$tc('key', count)` |
| `te('key')` | `$has('key')` |
| `n(value, 'currency')`, `d(date, 'short')` | `$tn(value, 'currency')`, `$td(date, 'short')` |
| — | `$tdr(date)`: relative Zeit („in 3 Tagen“) |
| `locale.value` | `$getLocale()` |
| `locales.value` | `$getLocales()` |
| `setLocale('de')` | `$switchLocale('de')` |
| `useLocalePath()('about')` | `$localePath({ name: 'about' })` |
| `useLocaleRoute()` | `$localeRoute()` |
| `useSwitchLocalePath()('de')` | `$switchLocalePath('de')` |
| `useSetI18nParams()` | `$setI18nRouteParams()` |
| `useLocaleHead()` | automatisch mit `meta: true`; [`useLocaleHead`](/de/composables/useLocaleHead) für eigene Heads |
| `defineI18nRoute({ paths: { de: '/ueber-uns' }, locales: [...] })` | `$defineI18nRoute({ localeRoutes: { de: '/ueber-uns' }, locales: [...] })` |
| `<NuxtLinkLocale to="about">` | `<i18n-link :to="{ name: 'about' }">` |
| `<i18n-t>` | `<i18n-t>` (Slots füllen `{name}`-Platzhalter) |
| `$i18n` in Server-Routen | `useTranslationServerMiddleware(event)`, siehe [Server-Routen und API](/de/guide/server-side-translations) |

`useI18n()` wird automatisch importiert. `$defineI18nRoute` muss sein `$` behalten: Der Build liest diesen Aufruf. Alle Helfer: [Methoden](/de/api/methods).

## Übersetzungsdateien {#translation-files}

Verschieben Sie die Schlüssel einer großen Datei pro Locale in eine Root-Datei plus eine Datei pro Seite:

```text
locales/
├── en.json              # keys used on many pages (nav, footer)
├── de.json
└── pages/
    ├── index/en.json    # keys of pages/index.vue
    └── about/en.json    # keys of pages/about.vue
```

Alles in den Root-Dateien zu belassen funktioniert ebenfalls und ist der schnellste erste Schritt. Setzen Sie `disablePageLocales: true`, bis Sie sie aufteilen. Siehe [Übersetzungsdateien](/de/guide/translations).

### Nachrichtensyntax {#message-syntax}

| vue-i18n | nuxt-i18n-micro |
| --- | --- |
| `{name}` benannte Interpolation | identisch |
| `car \| cars` (2 Formen: 1 → erste) | Formen werden nach Anzahl ab 0 gewählt: Schreiben Sie `no cars \| one car \| {count} cars` |
| `@:other.key` Linked Messages | nicht unterstützt: Text wiederholen oder im Code zusammensetzen |
| `@.upper:` Modifier | nicht unterstützt: im Code formatieren oder `<i18n-t>` verwenden |
| `{'@'}` Literal-Escapes | nicht nötig: Nur `{word}`-Tokens werden ersetzt |
| JS/TS-Nachrichtendateien | nur JSON |

Die Pluralregel lässt sich mit der Option [`plural`](/de/api/module-options#plural) ersetzen.

## Nach dem Umstieg prüfen {#check-after-the-switch}

- Jede bisherige URL wird weiterhin aufgelöst; die Strategienamen stimmen überein, benutzerdefinierte Pfade wandern nach `globalLocaleRoutes` oder `$defineI18nRoute`.
- `hreflang`, Canonical und `og:locale` gibt es mit `meta: true` ab Werk; entfernen Sie handgeschriebene.
- Ein JSON-Parse-Fehler protokolliert den Dateipfad; ein fehlender Schlüssel erzeugt in der Entwicklung eine Warnung in der Browserkonsole.
