title: "Routing-Strategien"
description: "Die vier URL-Strategien, die lokalisierten Routen, die sie erzeugen, und wie du auf eine Seite in einer beliebigen Locale verlinkst."
---

Die Option `strategy` entscheidet, ob eine Locale in der URL erscheint und für welche Locales. Wähle sie einmal, bevor du URLs veröffentlichst: Eine spätere Änderung ändert jeden Link. Das Modul erzeugt dann die lokalisierten Routen zur Build-Zeit, und `$localePath`, `<i18n-link>` sowie der Switcher lesen sie.

## Die vier Strategien {#the-four-strategies}

![Die Seite /about in en (Standard) und de unter jeder Strategie; dieselben URLs sind im Text unten aufgeführt](/images/diagrams/strategies.svg)

**Typ** `Strategies` · **Standard** `'prefix_except_default'`

URL-Routing-Strategie für Locale-Präfixe.

- `'no_prefix'` — keine Locale in der URL; die Locale wird im Cookie gespeichert.
- `'prefix_except_default'` — alle Locales außer der Standard-Locale erhalten ein Präfix.
- `'prefix'` — immer ein Präfix, auch für die Standard-Locale.
- `'prefix_and_default'` — wie `prefix`, aber die Standard-Locale ist auch ohne Präfix erreichbar.

URLs für eine `about`-Seite mit `defaultLocale: 'en'` und den Locales `en`, `de`:

| Strategie | Englisch | Deutsch | Nicht ausgeliefert |
| --- | --- | --- | --- |
| `prefix_except_default` (Standard) | `/about` | `/de/about` | `/en` und `/en/about` ergeben einen 404 |
| `prefix` | `/en/about` | `/de/about` | `/about` leitet auf eine URL mit Präfix weiter |
| `prefix_and_default` | `/about` und `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | die Locale steht nicht in der URL |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

Die Strategie wird beim Build festgelegt: Ein Runtime-Override wird mit einer Warnung ignoriert ([Runtime-Overrides](/de/guide/runtime-overrides)).

## Welche du wählen solltest {#which-one-to-choose}

- **`prefix_except_default`**: die meisten Websites. Bestehende URLs ohne Präfix funktionieren für die Standardsprache weiter.
- **`prefix`**: Alle Sprachen sind gleichberechtigt; `/` führt immer zu einer Startseite mit Präfix.
- **`prefix_and_default`**: Sowohl `/en/...` als auch die URLs ohne Präfix müssen funktionieren, zum Beispiel während eines Umstiegs vom einen zum anderen. URLs ohne Präfix werden nie weitergeleitet.
- **`no_prefix`**: Apps hinter einem Login oder eine URL pro Seite für jede Sprache. Die Locale kommt aus einem Cookie oder `?locale=`. Suchmaschinen sehen eine Sprache pro URL, daher werden keine `hreflang`-Alternativen ausgegeben.

Wie die Locale für eine URL gewählt wird und wann ein Besucher weitergeleitet wird, steht unter [Locale-Erkennung](/de/guide/locale-detection).

## Generierte Routen {#generated-routes}

Zur Build-Zeit erhält jede Seite die Routeneinträge, die ihre Strategie benötigt. Jeder Eintrag trägt `meta.i18n = { name, locales }`: die Seite, die er anzeigt, und die Locales, die er bedient. Links, Wechsel und Weiterleitungen werden alle anhand dieser Einträge beantwortet, sodass eine URL, die das Modul ausgibt, immer eine ist, die der Router bedient.

Locales, die sich den Pfad der Seite teilen, teilen sich einen Eintrag, `/:locale(de|fr)/about`. Eine Locale mit eigenem Pfad erhält einen eigenen Eintrag namens `localized-<page>-<locale>`:

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

Benutzerdefinierte Pfade, Locale-Listen pro Seite und das Ausschließen einer Seite von der Lokalisierung werden unter [Lokalisierte Pfade](/de/guide/custom-locale-routes) und [Seitenkonfiguration](/de/guide/per-component-translations) behandelt. Das Präfix `localized-` ist [`localizedRouteNamePrefix`](/de/api/module-options#localizedroutenameprefix).

<Warning>

**Routennamen werden generiert** — Codiere `localized-…`-Namen nicht fest in `router.push({ name })`. Übergib den eigenen Namen der Seite an `$localeRoute` oder `<i18n-link>`; sie wählen den richtigen Eintrag.

</Warning>

## Auf eine Seite in einer Locale verlinken {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- Benannte Routen und Pfade funktionieren beide. Ein Pfad wird mit den generierten Routen abgeglichen, daher wird die Form jeder Locale akzeptiert.
- Eine Locale, die die Seite nicht bedient (siehe `locales` unter [Seitenkonfiguration](/de/guide/per-component-translations)), verlinkt stattdessen auf die Startseite dieser Locale statt auf eine fehlende Seite.
- Parameter pro Locale (ein übersetzter Slug) laufen über `$setI18nRouteParams`, siehe [Lokalisierte Pfade](/de/guide/custom-locale-routes).

Signaturen findest du unter [Methoden](/de/api/methods).

## Details zu `no_prefix` {#no_prefix-details}

- [`localeCookie`](/de/api/module-options#localecookie) ist unter `no_prefix` standardmäßig `'user-locale'`, sodass die Wahl ein Neuladen übersteht.
- `$switchLocale('de')` lädt das deutsche Wörterbuch und ersetzt den aktuellen Verlaufseintrag; die URL ändert sich nicht.
- Benutzerdefinierte Pfade pro Locale funktionieren weiterhin: Mit `globalLocaleRoutes: { about: { de: '/ueber-uns' } }` erhalten deutsche Leser `/ueber-uns`. Diese URL rendert immer Deutsch, unabhängig von der Präferenz des Besuchers, und eine auf bestimmte Locales beschränkte Seite rendert in einer davon. Ein Pfad, den sich mehrere Locales teilen (`en` und `de` beide auf `/page/:id`), rendert die Präferenz, wenn sie eine davon ist. Die Präferenz selbst bleibt bestehen: Die nächste Seite kehrt zu ihr zurück.
- [`noPrefixRedirect: true`](/de/api/module-options#noprefixredirect) leitet den ursprünglichen Pfad einer Seite mit benutzerdefiniertem Pfad in der Standard-Locale weiter: auf den benutzerdefinierten Pfad der Locale des Besuchers, andernfalls auf den der Standard-Locale (`/about` → `/about-us`, wenn `en` `/about-us` hat, → `/ueber-uns` mit Cookie `de`). Eine Locale ohne eigenen benutzerdefinierten Pfad bleibt auf dem ursprünglichen Pfad und rendert dort. Seiten mit Parametern werden nicht weitergeleitet.

## Apps ohne `pages/` {#apps-without-pages}

Mit `pages: false` gibt es keine Seitenrouten zum Lokalisieren. Verwende nur Root-Übersetzungsdateien (`disablePageLocales: true`); Erkennung, Cookie und `$switchLocale` funktionieren weiterhin. Die Variante `pages-false` von `test/fixtures/basic` im Repository ist ein funktionierendes Setup.
