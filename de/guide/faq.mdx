Kurze Antworten auf die häufigsten Probleme, für Fragen, die die Themenseiten nicht direkt beantworten. Jede Antwort verlinkt die Seite, die das Thema behandelt. Falls Ihre Frage nicht dabei ist, durchsuchen Sie die Dokumentation oder eröffnen Sie ein [Issue](https://github.com/s00d/nuxt-i18n-micro/issues).

## Übersetzungen {#translations}

### `$t` schlägt in einem Plugin oder einer Utility-Funktion fehl {#$t-fails-in-a-plugin-or-a-utility-function}

Composables benötigen den Nuxt-Kontext. Außerhalb von `setup` holen Sie den Helfer aus der App oder führen ihn nach einem `await` in deren Kontext aus:

```ts
const nuxtApp = useNuxtApp()
const title = nuxtApp.$t('errors.unknown')
await nuxtApp.runWithContext(() => nuxtApp.$t('errors.unknown'))
```

In Services, die überhaupt keine App haben, übergeben Sie Schlüssel und übersetzen Sie diese in der Komponente.

### Ein Schlüssel erscheint nur auf einer Seite als Rohtext {#a-key-shows-as-raw-text-on-one-page-only}

Der Schlüssel befindet sich in der Datei einer anderen Seite. Eine Seite sieht nur die Root-Datei und ihre eigene Datei `locales/pages/<route-name>/`; verschieben Sie gemeinsam genutzte Schlüssel in die Root-Datei. Siehe [Übersetzungsdateien](/de/guide/translations).

### Schlüssel blitzen während eines Seitenübergangs auf {#keys-flash-while-a-page-transition-runs}

Das sollten sie nicht: Die Schlüssel der verlassenen Seite werden aufgelöst, bis der Übergang endet. Wenn sie dennoch aufblitzen, liegt der Schlüssel nur in einer Seitendatei, die keiner der beiden Seiten gehört (zum Beispiel in einem Layout); verschieben Sie ihn in die Root-Datei.

### Übersetzungen fehlen beim SSR auf Vercel, Netlify oder Edge {#translations-are-missing-during-ssr-on-vercel-netlify-or-edge}

Die Serverfunktion kann dort `public/` nicht lesen, daher werden Payloads in das Server-Bundle eingebettet. Das ist der Standard; prüfen Sie, dass `translationPayloads.serverAssets` nicht deaktiviert ist. Wenn das Log `public/ is not deployed next to the server` meldet, setzen Sie `nitro.serveStatic: false`. Siehe [Deployment](/de/guide/deployment).

### Wie füge ich einen Link in einen übersetzten Satz ein? {#how-do-i-put-a-link-inside-a-translated-sentence}

Verwenden Sie `<i18n-t>`: Jeder benannte Slot füllt den gleichnamigen `{placeholder}`.

```vue
<!-- "share": "Share your {link} with friends" -->
<i18n-t keypath="share">
  <template #link>
    <i18n-link :to="{ name: 'referral' }">{{ $t('referralLink') }}</i18n-link>
  </template>
</i18n-t>
```

Siehe [`<i18n-t>`](/de/components/i18n-t). Die Linked Messages und Modifier von vue-i18n werden nicht unterstützt; setzen Sie die Inhalte wie hier im Template zusammen.

## Locales und URLs {#locales-and-urls}

### `/en/about` ergibt einen 404 {#/en/about-is-a-404}

Mit dem Standard `prefix_except_default` hat die Standard-Locale kein Präfix: `/about` ist Englisch. Verwenden Sie `prefix` oder `prefix_and_default`, wenn Sie `/en/...` möchten. Siehe [Routing-Strategien](/de/guide/strategy).

### Besucher werden bei Deep Links nicht weitergeleitet {#visitors-are-not-redirected-on-deep-links}

Standardmäßig folgt nur `/` der Browsersprache oder dem Cookie, damit geteilte Links ihre Sprache behalten. Setzen Sie `autoDetectPath: 'no_prefix'` oder `'*'`. Siehe [Locale-Erkennung](/de/guide/locale-detection#autodetectpath).

### Die gewählte Sprache geht nach einem Neuladen verloren {#the-chosen-language-is-forgotten-after-a-reload}

Das Locale-Cookie ist bei den Präfix-Strategien deaktiviert. Setzen Sie `localeCookie: 'user-locale'`. Siehe [Locale-Erkennung](/de/guide/locale-detection#the-cookie).

### Kann ich die Locale wechseln, ohne die URL zu ändern? {#can-i-switch-locale-without-changing-the-url}

Nur mit `strategy: 'no_prefix'`, wobei `$switchLocale('de')` das Wörterbuch auf demselben Pfad neu lädt. Bei den Präfix-Strategien ist die Locale Teil der URL, daher führt ein Wechsel zu einer Navigation. Für einen Link statt eines Aufrufs verwenden Sie `$switchLocalePath('de')`.

### Die Seite scrollt beim Locale-Wechsel nach oben {#the-page-scrolls-to-the-top-when-i-switch-locale}

Das ist Nuxts `scrollBehavior` für jede Navigation. Setzen Sie `definePageMeta({ scrollToTop: false })` und stellen Sie die Position selbst wieder her. [`SwitchLocalePreserve.vue`](https://github.com/s00d/nuxt-i18n-micro/blob/main/playground/components/SwitchLocalePreserve.vue) aus dem Playground ist ein kopierbarer Wrapper ([Demoseite](https://github.com/s00d/nuxt-i18n-micro/blob/main/playground/pages/scroll-test.vue)).

## Build und Integrationen {#build-and-integrations}

### `nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` {#nuxt-seodefaults-depends-on-nuxt-site-configi18n-but-they-are-not-registered}

Ein altes `nuxt-site-config` kennt nur `@nuxtjs/i18n`. Aktualisieren Sie `@nuxtjs/seo` auf Version 3 oder neuer und führen Sie `nuxt-i18n-micro` in `modules` davor auf. Siehe [SEO](/de/guide/seo).

### Build-Fehler zu `@unhead/vue` auf Cloudflare {#build-error-about-@unhead/vue-on-cloudflare}

Installieren Sie `@unhead/vue` in der App, damit der Prerender-Schritt es findet. Das Modul selbst benötigt kein `nodejs_compat`: Fügen Sie `compatibility_flags = ["nodejs_compat"]` nur dann zu `wrangler.toml` hinzu, wenn etwas anderes in der App es benötigt.
