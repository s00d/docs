---
title: "Lokalisierte Pfade"
description: "Geben Sie einer Seite pro Locale eine eigene URL mit localeRoutes oder globalLocaleRoutes, einschließlich dynamischer Parameter und Slugs pro Locale."
---

Standardmäßig liefert jede Locale eine Seite unter demselben Pfad aus: `/en/about`, `/de/about`. Mit lokalisierten Pfaden kann jede Locale eigene Wörter verwenden, etwa `/de/ueber-uns`, während die Seitendatei dieselbe bleibt. Sie legen sie in der Seite mit `$defineI18nRoute` fest oder für viele Seiten auf einmal in `nuxt.config.ts`.

## In der Seite {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

Mit `prefix_except_default` und `defaultLocale: 'en'` antwortet die Seite unter `/about`, `/de/ueber-uns` und `/fr/a-propos`. Eine Locale ohne Eintrag behält den Standardpfad. Schreiben Sie Pfade ohne den Locale-Code: Das Präfix wird von der [Strategie](/de/guide/strategy) hinzugefügt, und ein Pfad, der mit dem Locale-Code beginnt, erzeugt eine Warnung. Was der Aufruf sonst noch akzeptiert, steht unter [Seitenkonfiguration](/de/guide/per-component-translations).

## In nuxt.config {#in-nuxt-config}

[`globalLocaleRoutes`](/de/api/module-options#globallocaleroutes) leistet dasselbe für jede beliebige Seite, indiziert nach ihrem Pfad (oder nach ihrem Routennamen, wenn ohne führenden Schrägstrich geschrieben):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

Wenn eine Seite `localeRoutes` setzt und `globalLocaleRoutes` denselben Schlüssel enthält, hat der Konfigurationseintrag Vorrang.

## Dynamische Parameter {#dynamic-params}

Schreiben Sie Parameter in jeder Nuxt-Form: `[id]`, `[[page]]`, `[...slug]` oder `:id()`. Die Parameternamen müssen mit der Seitendatei übereinstimmen.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

Verschachtelte Seiten verwenden einen absoluten Kindpfad (`/ueber-uns/team`) oder einen Pfad relativ zum lokalisierten Pfad des Elternelements (`team`).

## Auf lokalisierte Seiten verlinken {#linking-to-localized-pages}

Links werden zum lokalisierten Pfad der Ziel-Locale aufgelöst, egal ob Sie einen Routennamen oder einen einfachen Pfad übergeben:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

Routennamen ergeben sich aus dem Dateipfad (`pages/about/team.vue` ist `about-team`), sofern Sie nicht mit `definePageMeta({ name })` einen eigenen festlegen.

## Slugs pro Locale {#per-locale-slugs}

Wenn sich der Slug selbst je nach Locale unterscheidet (`/our-products/red-shoe` vs. `/de/unsere-produkte/roter-schuh`), teilen Sie dem Sprachumschalter mit `$setI18nRouteParams` mit, welche Parameter er verwenden soll, sobald die Daten geladen sind:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

`$switchLocalePath('de')` und `<i18n-switcher>` verlinken dann auf `/de/unsere-produkte/roter-schuh`. Die Schlüssel sind Locale-Codes, die Werte sind Parameter nach Namen (wie in der Seitendatei).

Ein Umschalter im Layout wird gerendert, bevor das asynchrone Setup der Seite diese Stelle erreicht. Deshalb schreibt das Modul am Ende des Renderings die Links von `<i18n-switcher>` um, in `app.vue` ebenso wie in der Seite. Das Server-HTML, ein Besucher ohne JavaScript und das erste Client-Rendering stimmen dann überein. Setzen Sie die Parameter dafür während des SSR: Mit `lazy` oder `server: false` ändern sich die Links erst nach der Hydration. Das SSR-Streaming von Nuxt sendet das HTML, bevor die Parameter bekannt sind; in diesem Fall behalten die Links im ersten HTML die Parameter der URL.

Nur die eigenen Links des Umschalters werden umgeschrieben. Ein von Hand geschriebener `$switchLocalePath`-Link muss gerendert werden, nachdem die Parameter gesetzt sind. Platzieren Sie ihn daher in der Seite, die sie setzt, und zwar auch nach einem `await`. In einem Layout wird er zuerst gerendert: Sein Server-HTML behält die Parameter der URL, und die Hydration warnt vor einer Abweichung. Verwenden Sie dort `<i18n-switcher>` und gestalten Sie das Aussehen über seine Slots und die `custom*Style`-Props.

Die Parameter gehören zu der Seite, die sie gesetzt hat:

- Sie werden verworfen, wenn eine Navigation zu einem anderen Pfad abgeschlossen wird, sodass jede Seite ihre eigenen setzt. Eine abgebrochene Navigation lässt sie bestehen.
- Holen Sie `$setI18nRouteParams` in `setup` aus `useNuxtApp()` oder `useI18n()`, auch wenn Sie es später in einem `useAsyncData`-Handler aufrufen. Dort geholt, kennt die Funktion ihre Seite: Hat der Besucher die Seite verlassen, bewirkt ein verspäteter Aufruf nichts.
- Mit `keepalive` erhält eine Seite die von ihr gesetzten Parameter zurück, wenn der Besucher zurückkehrt. `useI18nHead` verhält sich genauso.

## In pages:extend hinzugefügte Routen {#routes-added-in-pages-extend}

Für Routen, die Sie im Hook `pages:extend` hinzufügen, gibt es keine Seitendatei, aus der `$defineI18nRoute` gelesen werden könnte, und oft teilen sich mehrere davon eine Wrapper-Komponente. Eine ohne `name` hinzugefügte Route erhält den Namen, den Nuxt ihrem Pfad geben würde (`/a/:id()` wird zu `a-id`), sodass Sprachlinks sie erreichen, es sei denn, eine andere Route trägt diesen Namen bereits; geben Sie ihr dann einen expliziten `name`. Pflegen Sie eine einzige Liste und teilen Sie sie mit `splitLocaleRoutes` aus `@i18n-micro/utils/split-locale-routes` in Seiten und nach Routennamen indizierte `globalLocaleRoutes` auf (fügen Sie das Paket zu Ihren Abhängigkeiten hinzu):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

Legen Sie lokalisierte Pfade nicht in `route.meta` ab: Sie würden sonst mit der Client-Routentabelle ausgeliefert.
