Diese Seite führt eine Nuxt-App von null i18n zu einer übersetzten Seite mit Sprachumschalter. Du brauchst sie einmal, zu Beginn eines Projekts. Am Ende hast du lokalisierte URLs (`/about`, `/de/about`), eine JSON-Datei pro Locale und Seite sowie `$t` in deinen Templates.

## Installation {#install}

Das Modul benötigt Nuxt 3.18 oder neuer (Nuxt 4 funktioniert ebenfalls) und Node 20 oder neuer.

<CodeGroup>

```bash npm
npm install nuxt-i18n-micro
```

```bash pnpm
pnpm add nuxt-i18n-micro
```

```bash yarn
yarn add nuxt-i18n-micro
```

```bash bun
bun add nuxt-i18n-micro
```

</CodeGroup>

## Locales konfigurieren {#configure-the-locales}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
      { code: 'fr', iso: 'fr-FR', displayName: 'Français' },
    ],
    defaultLocale: 'en',
  },
})
```

Mehr Konfiguration braucht eine erste App nicht. Die Standardwerte liefern dir:

- `strategy: 'prefix_except_default'`: Die Standard-Locale hat kein Präfix (`/about`), die anderen schon (`/de/about`). Siehe [Routing-Strategien](/de/guide/strategy).
- `translationDir: 'locales'`: Übersetzungsdateien liegen in `locales/` im Projektstamm, auch beim `app/`-Layout von Nuxt 4.
- `meta: true`: `hreflang`-, Canonical- und `og:locale`-Tags sowie `lang` und `dir` auf `<html>`. Siehe [SEO](/de/guide/seo).
- Ein Besucher, der `/` öffnet, wird zu der Sprache weitergeleitet, die sein Browser anfragt (`Accept-Language`). Siehe [Locale-Erkennung](/de/guide/locale-detection).

`iso` ist das Sprach-Tag, das in SEO-Tags verwendet wird; `code` ist das, was in der URL erscheint. Alle Optionen sind unter [Moduloptionen](/de/api/module-options) aufgeführt.

## Übersetzungsdateien hinzufügen {#add-translation-files}

Starte den Dev-Server mit `nuxt dev`. Wenn Nuxt die Seiten auflöst, erstellt das Modul eine leere `{}`-Datei für jede Locale und Seite, die noch keine hat (abschaltbar mit [`disableWatcher`](/de/api/module-options#disablewatcher)):

```text
locales/
├── en.json            # root: keys every page can use
├── de.json
├── fr.json
└── pages/
    ├── index/         # pages/index.vue
    │   ├── en.json
    │   ├── de.json
    │   └── fr.json
    └── about/         # pages/about.vue
        ├── en.json
        ├── de.json
        └── fr.json
```

Fülle die Root-Datei und eine Seitendatei aus:

```json
// locales/en.json
{ "nav": { "home": "Home", "about": "About" } }
```

```json
// locales/pages/index/en.json
{ "welcome": "Welcome, {name}!", "items": "no items | one item | {count} items" }
```

Eine Seite sieht die Root-Schlüssel und ihre eigenen Schlüssel; bei einem Konflikt gewinnt ihre eigene Datei. Ordnernamen folgen dem Routennamen (`pages/articles/[id].vue` wird zu `locales/pages/articles-id/`). [Übersetzungsdateien](/de/guide/translations) behandelt Aufbau, Fallbacks und Laden.

## `$t` auf einer Seite verwenden {#use-$t-on-a-page}

```vue
<!-- pages/index.vue -->
<script setup lang="ts">
const { t, tc, getLocale } = useI18n()

const title = t('nav.home') // 'Home'
</script>

<template>
  <h1>{{ $t('welcome', { name: 'Ada' }) }}</h1>
  <!-- Welcome, Ada! -->
  <p>{{ $tc('items', 3) }}</p>
  <!-- 3 items -->
  <p>{{ getLocale() }}</p>
  <!-- en -->
</template>
```

- In Templates ist jeder Helfer mit einem `$` verfügbar (`$t`, `$tc`, `$localePath`, …).
- In `<script setup>` gibt `useI18n()` dieselben Helfer zurück, mit und ohne `$` (`t` und `$t` sind dieselbe Funktion). Es wird automatisch importiert.
- `{name}`-Platzhalter werden aus dem Params-Objekt befüllt. Pluralformen werden durch `|` getrennt; die Anzahl wählt die Form (0, 1, dann die letzte für alles darüber).

Alle Helfer sind unter [Methoden](/de/api/methods) aufgeführt.

## Zwischen Seiten verlinken und Locale wechseln {#link-between-pages-and-switch-locale}

```vue
<!-- components/AppHeader.vue -->
<template>
  <nav>
    <i18n-link :to="{ name: 'index' }">{{ $t('nav.home') }}</i18n-link>
    <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
    <i18n-switcher />
  </nav>
</template>
```

- [`<i18n-link>`](/de/components/i18n-link) ist ein `NuxtLink`, der auf die Seite in der aktuellen Locale zeigt: Auf `/de` führt der About-Link zu `/de/about`.
- [`<i18n-switcher>`](/de/components/i18n-switcher) ist ein Dropdown der aktivierten Locales; der Besucher bleibt auf derselben Seite.
- Für eigene Buttons rufe `$switchLocale('de')` auf. Das navigiert zur aktuellen Seite auf Deutsch und merkt sich die Wahl. Für einen einfachen `NuxtLink` verwende `$localePath({ name: 'about' })` oder `$switchLocalePath('de')`.

## Überprüfen {#check-it}

Führe `nuxt dev` aus und öffne:

| URL | Zeigt |
| --- | --- |
| `/` | Englische Startseite (oder eine Weiterleitung zu `/de`, wenn dein Browser Deutsch bevorzugt) |
| `/de` | Deutsche Startseite |
| `/de/about` | Deutsche About-Seite |
| `/en/about` | 404: Die Standard-Locale hat unter `prefix_except_default` kein Präfix |

Änderungen an den JSON-Dateien werden in der geöffneten Seite ohne Neuladen übernommen.
