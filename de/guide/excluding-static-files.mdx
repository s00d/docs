---
title: "Pfade ausschließen"
description: "Seiten und Dateien mit excludePatterns aus dem Locale-Routing heraushalten und sehen, welche Pfade bereits ausgeschlossen sind."
---

Manche Pfade dürfen nie ein Locale-Präfix oder eine Locale-Weiterleitung erhalten: ein Admin-Bereich, ein Health-Check, ein generierter Feed. `excludePatterns` markiert sie, und eine eingebaute Liste deckt bereits Nuxt-Interna und gängige statische Dateien ab. Eine ausgeschlossene Seite behält genau den Pfad, den du geschrieben hast, und rendert weiterhin mit `$t`.

## Einen Pfad ausschließen {#exclude-a-path}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    excludePatterns: [
      '/admin', // /admin and everything below it
      '/preview-*', // glob over the whole path
    ],
  },
})
```

Mit dieser Konfiguration antwortet `pages/admin/index.vue` nur unter `/admin`; es gibt kein `/de/admin`, und `/admin` wird nie nach `/de/admin` weitergeleitet.

## Muster-Syntax {#pattern-syntax}

Muster werden gegen den Pfad ohne `app.baseURL` geprüft:

| Muster | Passt auf | Passt nicht auf |
| --- | --- | --- |
| `'/admin'` | `/admin`, `/admin/users` | `/administrator`, `/de/admin` |
| `'/preview-*'` | `/preview-1`, `/preview-a/b` | `/de/preview-1` |
| `'/file-?'` | `/file-a` | `/file-ab` |
| `/^\/v\d+\//` | `/v2/docs` | `/docs` |

Ein String ohne `*` oder `?` passt auf den Pfad und ganze Segmente darunter. Mit `*` (beliebige Zeichenfolge, Schrägstriche eingeschlossen) oder `?` (ein Zeichen) muss er auf den gesamten Pfad passen. Beginne Strings immer mit `/`.

## Was bereits ausgeschlossen ist {#what-is-excluded-already}

Diese erhalten nie Locale-Routen oder Weiterleitungen, ganz ohne Konfiguration:

- `/api` und `/_nuxt` sowie alles darunter;
- die Übersetzungsroute, standardmäßig `/_locales` ([`apiBaseUrl`](/de/api/module-options#apibaseurl));
- jeder Pfad mit einem Segment, das mit `__` beginnt (`/__nuxt_content`, `/en/__og-image__`);
- `/sitemap*.xml`, `/robots.txt`, `/favicon.ico`, `/apple-touch-icon*.png`, `/manifest.json`, `/sw.js`, `/workbox-*.js`;
- jeder Pfad, dessen letztes Segment auf eine Dateiendung für statische Dateien endet: `xml txt ico json js css png jpg jpeg gif svg webp avif pdf wasm map mp4 webm mp3 zip gz woff woff2 ttf eot`. Seiten-Slugs mit Punkt wie `/user/john.doe` und `.html`-Pfade bleiben Seiten.

## Was ein Ausschluss bewirkt {#what-an-exclusion-does}

- **Routen:** Es werden keine lokalisierten Varianten erzeugt; die Seite bleibt wie geschrieben.
- **Weiterleitungen und 404-Fehler:** Das Server-Redirect-Plugin und die Client-Redirect-Middleware überspringen den Pfad.
- **Prerender:** Passende Pfade werden aus der Prerender-Routenliste entfernt.

Ein Ausschluss hindert die i18n-Server-Middleware nicht daran, eine Locale für die Anfrage zu erkennen, und er hindert die Seite nicht daran, Übersetzungen zu verwenden. Um eine Seite lokalisiert, aber ohne SEO-Tags zu halten, verwende `disableMeta` ([Seitenkonfiguration](/de/guide/per-component-translations#turn-off-seo-tags)). Um eine einzelne Seite per Pfad aus `nuxt.config.ts` unlokalisiert zu lassen, bewirkt `globalLocaleRoutes: { '/admin': false }` ([Lokalisierte Pfade](/de/guide/custom-locale-routes#in-nuxt-config)) dasselbe für das Routing.
