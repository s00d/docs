description: "Die Tags lang, hreflang, canonical und og:locale, die das Modul hinzufügt, wie deren Base-URL gewählt wird und wie Sie sie pro Seite überschreiben."
---

Mit `meta: true` (Standard) erhält jede lokalisierte Seite `<html lang dir>`, einen Canonical-Link, `hreflang`-Alternativen, `x-default` und Open-Graph-Locale-Tags. Sie benötigen diese Seite, wenn Sie den öffentlichen Origin festlegen, steuern möchten, welche Locales in den Tags erscheinen, oder die Tags für eine einzelne Seite überschreiben wollen. Die meisten Websites benötigen nur eine `site.url` oder `metaBaseUrl` und korrekte `iso`-Codes.

## Minimale Einrichtung {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

`/de/about` rendert dann:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Textrichtung {#text-direction}

`<html dir>` stammt aus dem `dir` der Locale. Ist keines gesetzt, erhält eine von rechts nach links geschriebene Sprache `rtl`, ermittelt aus `iso` (oder `code`): Arabisch, Hebräisch, Persisch, Urdu und einige andere sowie jedes Tag mit einer RTL-Schrift wie `az-Arab`. Alle anderen Locales erhalten kein `dir`-Attribut, was Browser als `ltr` interpretieren.

<Warning>

**`dir: 'auto'` kostet bei großen Seiten Parse-Zeit** — `auto` auf `<html>` veranlasst den Browser, die Richtung beim Parsen aus dem Inhalt zu ermitteln. In Chromium wachsen diese Kosten schneller als die Seite: etwa 100 ms bei 5.000 Elementen und 1 s bei 20.000. Verwenden Sie es nur für eine kleine Seite, deren Sprache Sie nicht kennen können.

</Warning>

## Welche Tags Sie erhalten {#which-tags-you-get}

- **hreflang**: ein Tag pro Locale, die die Seite ausliefert, mit dem Wert `iso` (oder `code`, wenn `iso` fehlt) und ihrer URL mit derselben Query wie die Canonical-URL. Eine über die [Seitenkonfiguration](/de/guide/per-component-translations) oder `routeLocales` eingeschränkte Seite listet nur ihre Locales auf. [`hreflangBaseLanguage: true`](/de/api/module-options#hreflangbaselanguage) fügt für die erste regionale Locale zusätzlich die reine Sprache hinzu (`es-ES` → `es`).
- **x-default**: die URL der Standard-Locale, nur wenn die Standard-Locale die Seite ausliefert.
- **og:locale**: abgeleitet aus `iso` (`en-US` → `en_US`). Setzen Sie `og` auf der Locale, wenn die Zuordnung nicht direkt ist, zum Beispiel `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; ohne beides wird kein `og:locale` geschrieben, und im Dev-Modus erscheint eine Warnung.
- **canonical / og:url**: die aktuelle URL ohne Query-Parameter, mit Ausnahme derer in [`canonicalQueryWhitelist`](/de/api/module-options#canonicalquerywhitelist) (Standard: `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Nach Strategie:

| Strategie | hreflang und x-default | canonical, og:url, og:locale, html-Attribute |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | ja | ja |
| `no_prefix` | nein (eine URL liefert jede Locale aus) | ja |

## Den öffentlichen Origin festlegen {#set-the-public-origin}

Absolute URLs verwenden den ersten verfügbaren Wert aus:

1. [`metaBaseUrl`](/de/api/module-options#metabaseurl);
2. `site.url` aus `nuxt-site-config` (installiert von `@nuxtjs/seo`);
3. dem Origin der Anfrage, mit angehängtem `app.baseURL`.

Legen Sie einen der ersten beiden fest.

<Warning>

Der Fallback auf den Origin der Anfrage liest `X-Forwarded-Host` und `X-Forwarded-Proto`, da [`metaTrustForwardedHost`](/de/api/module-options#metatrustforwardedhost) und `metaTrustForwardedProto` standardmäßig `true` sind. Das ist nur hinter einem Proxy sicher, der diese Header überschreibt; andernfalls kann ein Client den Host in Ihren Canonical-Links bestimmen, und ein Cache kann diese Seite weitergeben.

Wenn die App direkt erreichbar ist, legen Sie `metaBaseUrl` fest: Anders als das Setzen beider Optionen auf `false` ignoriert dies auch einen gefälschten `Host`. Siehe [Hinter einem Proxy oder CDN](/de/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

Der Fallback ist nützlich, wenn ein Deployment mehrere Domains bedient: `https://site-a.com/en/about` und `https://site-b.com/en/about` erhalten jeweils ihren eigenen Origin.

Mit `baseUrl` auf den Locales verwendet ein bekannter Host seine eigene `baseUrl`, vorrangig vor `metaBaseUrl` und `site.url`, sodass Canonical und `og:url` auf dieser Domain bleiben und `hreflang` jede Locale auf ihre Domain verweist. Jeder andere Host verwendet `metaBaseUrl`, andernfalls die `baseUrl` der Standard-Locale, andernfalls `site.url`, sodass ein gefälschter `Host` Ihre Tags nicht erreichen kann. Ist keiner dieser Werte gesetzt, bleibt der Fallback auf den Origin der Anfrage bestehen, und der Build gibt eine Warnung aus. Siehe [Layer und Domains](/de/guide/layers#multiple-domains).

## Locales oder Seiten auslassen {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Hat die Standard-Locale `seo: false`, wird kein `x-default` geschrieben. Um die Tags für eine einzelne Seite abzuschalten, verwenden Sie `disableMeta` in der [Seitenkonfiguration](/de/guide/per-component-translations#turn-off-seo-tags) oder [`routeDisableMeta`](/de/api/module-options#routedisablemeta) in der Konfiguration.

## Tags auf einer Seite überschreiben {#override-tags-on-one-page}

Für CMS-Inhalte, bei denen nur einige Übersetzungen existieren oder URLs aus einer API stammen, ersetzen Sie die generierten Tags mit [`useI18nHead`](/de/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` kann außerdem `canonical`, `xDefault`, `ogLocale` und `ogUrl` setzen oder entfernen; `disable` entfernt ganze Gruppen (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Übergeben Sie einen Getter, damit die Werte nach einem Locale-Wechsel neu berechnet werden. Für Slugs pro Locale setzen Sie zuerst `$setI18nRouteParams` ([Lokalisierte Pfade](/de/guide/custom-locale-routes#per-locale-slugs)), dann verwenden die generierten Alternativen sie bereits.

## Abschließender Schrägstrich {#trailing-slash}

`$localePath`, `$switchLocalePath`, das Routenobjekt von `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, Locale-Weiterleitungen und die SEO-URLs folgen einer einzigen Schrägstrich-Regel: standardmäßig `experimental.defaults.nuxtLink.trailingSlash` oder [`trailingSlash`](/de/api/module-options) in der i18n-Konfiguration, wenn i18n-Pfade davon abweichen sollen.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (Sitemap, robots, schema.org) funktioniert mit diesem Modul über `nuxt-site-config` 4+. Führen Sie `nuxt-i18n-micro` zuerst auf, damit die Site-Konfiguration die Locales lesen kann, und setzen Sie `site.url` einmalig — es speist auch die oben genannten Tags.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Ein übersetzter Website-Name und eine übersetzte Beschreibung stammen aus den Schlüsseln `nuxtSiteConfig.name` / `nuxtSiteConfig.description` in Ihren Locale-Dateien. Der Fehler `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` bedeutet, dass `@nuxtjs/seo` älter als Version 3 ist; aktualisieren Sie es ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
