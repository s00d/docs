Server-Handler in `server/api/` und `server/routes/` können mit zwei automatisch importierten Helfern Strings übersetzen und die Locale der Anfrage lesen. Verwenden Sie sie für API-Antworten, E-Mails, Feeds oder alles, was außerhalb einer Vue-Seite gerendert wird. Sie lesen dieselben Übersetzungsdateien wie Ihre Seiten und erkennen die Locale aus der Anfrage.

## In einem Handler übersetzen {#translate-in-a-handler}

```ts
// server/api/greeting.get.ts
export default defineEventHandler(async (event) => {
  const t = await useTranslationServerMiddleware(event)
  return { message: t('greeting', { name: 'Ada' }) }
})
```

```bash
curl 'http://localhost:3000/api/greeting?locale=de'
# {"message":"Hallo, Ada!"}
```

`useTranslationServerMiddleware(event, defaultLocale?, locale?)` ist asynchron und gibt `t(key, params?, defaultValue?)` zurück. `t` gibt den String zurück, interpoliert `{name}`-Parameter und gibt bei fehlendem Schlüssel einen nicht leeren `defaultValue` zurück, andernfalls den Schlüssel selbst.

`t` sieht nur den `index`-Chunk: die Root-Dateien (`locales/<locale>.json`) plus `locales/pages/index/`, sofern vorhanden (mit `disablePageLocales` nur die Root-Dateien). Schlüssel anderer Seiten werden nicht geladen. Für diese laden Sie den Chunk selbst:

```ts
const { data } = await loadTranslationsFromServer('de', 'about') // Translations object of the about page
```

## Die Locale der Anfrage lesen {#read-the-request-locale}

```ts
// server/api/locale.get.ts
export default defineEventHandler((event) => {
  const { current, isDefault, locale } = useLocaleServerMiddleware(event)
  return { current, isDefault, dir: locale?.dir ?? 'ltr' }
})
```

`useLocaleServerMiddleware(event, defaultLocale?, locale?)` ist synchron und gibt Folgendes zurück:

```ts
interface LocaleInfo {
  current: string // detected locale code
  default: string // defaultLocale, runtime overrides included (fixed at build under prefix_except_default / prefix_and_default)
  fallback: string // fallbackLocale, else the default
  available: string[] // enabled locale codes
  locale: Locale | null // the config entry of `current`
  isDefault: boolean
  isFallback: boolean
}
```

## Wie die Locale gewählt wird {#how-the-locale-is-chosen}

Beide Helfer verwenden auf jeder Server-Route dieselbe Reihenfolge, ob `/api` oder nicht:

1. Query `?locale=` (bei Wiederholung der erste Wert);
2. ein Routenparameter `[locale]` oder ein Locale-Präfix im Pfad (`/de/...`);
3. das Locale-Cookie, wenn [`localeCookie`](/de/api/module-options#localecookie) gesetzt ist (`hash-locale` unter `hashMode`);
4. `Accept-Language`, wenn `autoDetectLanguage` aktiviert ist (q-Werte werden berücksichtigt);
5. `defaultLocale`.

Ungültige und deaktivierte Codes werden in jedem Schritt übersprungen. Dies ist die Reihenfolge für die API; beim Rendern einer Seite wird `?locale=` unter den Präfix-Strategien ignoriert. Beide Reihenfolgen werden unter [Locale-Erkennung](/de/guide/locale-detection) verglichen.

## Eine Locale erzwingen {#force-a-locale}

Übergeben Sie das dritte Argument, um die Erkennung zu überspringen, zum Beispiel in einem Job, der E-Mails in der Sprache des Benutzers versendet:

```ts
export default defineEventHandler(async (event) => {
  const user = await getUser(event) // your code
  const t = await useTranslationServerMiddleware(event, undefined, user.locale)
  return sendMail(user.email, t('mail.welcome.subject'))
})
```

Das zweite Argument ersetzt `defaultLocale` für die Erkennung dieses Aufrufs und hat daher keine Wirkung, wenn eine Locale erzwungen wird. Wörterbücher werden pro Anfrage und pro Locale gecacht sowie anfrageübergreifend im Übersetzungs-Cache des Servers, sodass mehrfache Aufrufe eines Helfers kostengünstig sind.

## Server-Komponenten {#server-components}

Eine Server-Komponente (`.server.vue`, `<NuxtIsland>`) wird über ihre eigene URL `/__nuxt_island/...` gerendert. Sie sieht daher die URL der Seite nicht, und Nuxt übergibt ihr nur ihre Props. Übergeben Sie die Locale als Prop `locale`. Die Komponente wird dann in dieser Locale gerendert, und bei einem Wechsel wird sie erneut abgerufen, da die Props Teil der URL und des Cache-Schlüssels der Island sind. Der Name ist reserviert: Jeder aktivierte Locale-Code in einer Prop namens `locale` legt die Locale des Renderings fest. Geben Sie einer Prop, die etwas anderes bedeutet, etwa ein Zahlenformat, daher einen anderen Namen:

```vue
<!-- components/Greeting.server.vue -->
<template><p>{{ $t('greeting') }}</p></template>
<script setup lang="ts">
defineProps<{ locale?: string }>()
</script>
```

```vue
<template>
  <Greeting :locale="$getLocale()" />
  <NuxtIsland name="Greeting" :props="{ locale: $getLocale() }" />
</template>
```

Ohne die Prop wird sie in der Locale des Cookies gerendert, andernfalls in der Standard-Locale, unabhängig von der URL, und sie folgt keinem Wechsel. Ihr `$t` sieht den `index`-Chunk: die Root-Dateien plus `locales/pages/index/`.
