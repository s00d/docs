# Referenz der Moduloptionen

Jede Option, die `nuxt-i18n-micro` akzeptiert, wird zur Build-Zeit aus dem Interface `ModuleOptions` in [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts) gelesen. Nichts hier wird von Hand geschrieben, deshalb kann diese Seite dem Code nicht hinterherhinken. Typen, Standardwerte und Beschreibungen stammen aus der Deklaration selbst.

Was diese Optionen im Zusammenspiel *bedeuten* — welche Kombinationen sinnvoll sind, was sich beim Wechsel der Strategie ändert und ausgearbeitete Beispiele — findest du unter [Konfiguration](/guides/configuration). Diese Seite ist die vollständige Liste, jene ist die Erklärung.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Verschachtelte Optionen erscheinen unter ihrem gepunkteten Pfad, sodass `translationPayloads.mode` der Schlüssel `mode` im Objekt `translationPayloads` ist.

## Locales und Routing

Welche Sprachen existieren und wie sie in der URL erscheinen.

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Liste unterstützter Locales. Jeder Eintrag definiert einen Locale-Code sowie optionale Metadaten (ISO, Richtung, Anzeigename usw.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | URL-Routing-Strategie für Locale-Präfixe. - `'no_prefix'` — keine Locale in der URL; Locale wird im Cookie gespeichert. - `'prefix_except_default'` — alle Locales außer der Standard-Locale werden mit Präfix versehen. - `'prefix'` — immer mit Präfix, auch die Standard-Locale. - `'prefix_and_default'` — wie `prefix`, aber die Standard-Locale ist zusätzlich ohne Präfix erreichbar. |
| `defaultLocale` | `string` | `'en'` | Die Locale, die verwendet wird, wenn keine aus URL oder Nutzerpräferenz bestimmt werden kann. Dient auch als Fallback-Locale für fehlende Übersetzungen, wenn `fallbackLocale` nicht gesetzt ist. |
| `localeCookie` | `string \| null` | `null` | Cookie-Name, um die Locale-Präferenz des Nutzers sitzungsübergreifend zu speichern. Setze auf `null`, um die cookiebasierte Persistenz zu deaktivieren. Wird für die Strategie `no_prefix` automatisch auf `'user-locale'` gesetzt, falls nicht angegeben. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Globale Locale-Konfiguration auf Routenebene. Ermöglicht das Einschränken oder Anpassen von Locale-Routen für einzelne Seiten, ohne deren Komponenten zu ändern. - `false` — schließt die Route von der Lokalisierung aus. - `Record<LocaleCode, string>` — benutzerdefinierte Pfade pro Locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (verwendet das eingebaute Muster basierend auf Locale-Codes)` | Benutzerdefinierter regulärer Ausdruck (oder seine String-Quelle), um Locale-Codes in URL-Segmenten zu erkennen. Alle in `locales` definierten Locale-Codes müssen zu diesem Muster passen, sonst wird eine Warnung ausgegeben. |
| `noPrefixRedirect` | `boolean` | `false` | Für die Strategie `no_prefix`: aktiviert die Weiterleitung von einer URL mit Locale-Präfix (z. B. `/en/about`) zur präfixlosen Version (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | URL-Muster (Strings oder RegExp), die von der i18n-Verarbeitung vollständig ausgenommen werden. Passende Routen erhalten keine Locale-Präfixe, Weiterleitungen oder Übersetzungsladungen. Interne Nuxt-Pfade (`/__nuxt_error` usw.) werden immer automatisch ausgeschlossen. |
| `routeLocales` | `Record<string, string[]>` | — | Locale-Einschränkungen pro Route, extrahiert aus `defineI18nRoute()`-Aufrufen. Ordnet einem Routenpfad (z. B. `'/about'`) ein Array erlaubter Locale-Codes zu. Nicht aufgeführte Routen unterliegen keinen Einschränkungen (alle Locales erlaubt). |

## Übersetzungen

Wo Übersetzungsdateien liegen und wie Schlüssel aufgelöst werden.

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Pfad zum Verzeichnis mit den JSON-Übersetzungsdateien, relativ zum Projektstamm. |
| `disableWatcher` | `boolean` | `false` | Deaktiviert den File-Watcher, der im Entwicklungsmodus fehlende Übersetzungsdateien automatisch erstellt. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Ordnet Routennamen anderen Routennamen zu, um dieselben Übersetzungsdateien zu teilen. Beispielsweise bedeutet `\{ 'about-us': 'about' \}`, dass die Seite `about-us` die Übersetzungen der Seite `about` statt eigener verwendet. |
| `plural` | `PluralFunc` | `eingebaute Pluralisierung (Formindex nach Anzahl)` | Benutzerdefinierte Pluralisierungsfunktion. Erhält `(key, count, params, locale, getter)` und sollte die gewählte Pluralform als String zurückgeben, oder `null`/`undefined`, um auf die eingebaute Logik `defaultPlural` zurückzufallen (so kannst du nur einzelne Locales überschreiben). Für das Nuxt-Modul wird die Funktion mit `.toString()` in `.nuxt/i18n.plural.mjs` serialisiert. Sie muss autark sein (keine Imports und kein äußerer Scope). Ein Dateipfad-String wird **nicht** unterstützt. |
| `disablePageLocales` | `boolean` | `false` | Deaktiviert seitenspezifische Übersetzungsdateien. Bei `true` werden nur globale Übersetzungen (`\{locale\}.json`) geladen; seitenspezifische Dateien (`pages/\{page\}/\{locale\}.json`) werden weder generiert noch geladen. |
| `fallbackLocale` | `string` | `undefined (kein Fallback; gibt den rohen Schlüssel zurück)` | Globaler Fallback-Locale-Code. Fehlt ein Übersetzungsschlüssel in der aktiven Locale, sucht das Modul ihn zunächst in dieser Locale, bevor der Schlüssel selbst zurückgegeben wird. |

## Payloads und Caching

Wie Übersetzungen den Browser erreichen. [Performance](/guides/performance) erklärt, was sich zur Laufzeit dadurch ändert.

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Lädt Übersetzungen der Startseite in einer globalen Nitro-Middleware vor (nur Server, private Konfiguration). |
| `apiBaseUrl` | `string` | `'_locales'` | Basis-URL-Segment für die API-Route der Übersetzungen (wird beim Datenabruf für SSR/SSG verwendet). Lässt sich auch über die Umgebungsvariable `NUXT_I18N_APP_BASE_URL` setzen. |
| `apiBaseClientHost` | `string` | `undefined` | Überschreibt den Host für clientseitige Übersetzungs-Fetches. Nützlich, wenn der Client den Server über einen anderen Hostnamen erreicht als Nuxt sieht. Lässt sich auch über `NUXT_I18N_APP_BASE_CLIENT_HOST` setzen. |
| `apiBaseServerHost` | `string` | `undefined` | Überschreibt den Host für serverseitige Übersetzungs-Fetches. Nützlich in Container/Microservice-Setups, in denen sich der Server über einen internen Hostnamen selbst erreicht. Lässt sich auch über `NUXT_I18N_APP_BASE_SERVER_HOST` setzen. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Steuert, wie Übersetzungspayloads ausgegeben werden (Node: `public/<apiBaseUrl>`; Edge: Nitro `serverAssets`). - **Node**: `serverAssets` bedeutet lokales SSR per `readFile` unter `public/` (kein Rollup `raw:`). - **Edge**: `serverAssets` registriert Nitro `serverAssets` (`assets:i18n`); es erzwingt keine öffentliche Kopie. Behalte die Standardwerte für das übliche All-in-One-Setup. Für große Edge-Kataloge bevorzuge `mode: 'source'`. Für CDN-gestützte Deployments deaktiviere die lokalen Ausgaben und setze `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Strategie der Übersetzungspayloads. - `premerged`: zur Build-Zeit generierte Matrix `\{page\}/\{locale\}/data.json` (Standard). - `source`: kompakte Quelldateien, die zur Laufzeit zusammengeführt werden (bevorzugt an Edge und bei großen Katalogen). |
| `translationPayloads.serverAssets` | `boolean` | `true` | Lokale SSR-Payloads: Node liest `public/<apiBaseUrl>` (erzwingt öffentliche Kopie); Edge bettet sie über Nitro `serverAssets` ein. - **Node**: keine Nitro `serverAssets` (vermeidet Rollup `raw:`). SSR liest `public/<apiBaseUrl\|publicDir>` als `\{page\}/\{locale\}/data.json`; bei `true` wird eine öffentliche Kopie erzwungen, selbst wenn `publicAssets` `false` ist. - **Edge** (`nitro.node === false`): Nitro `serverAssets` (`assets:i18n`) mit demselben Layout wie `mode`. Erzwingt **keine** öffentliche Kopie. Setze `publicAssets: true` für CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Registriert die eingebaute Server-Route unter `/\{apiBaseUrl\}/:page/:locale/data.json`. Deaktiviere dies, wenn Übersetzungspayloads von einem externen Host/CDN ausgeliefert werden. |
| `translationPayloads.publicAssets` | `boolean` | `true im Modus premerged, false im Modus source` | Kopiert Payloads in die öffentliche Nitro-Ausgabe. Premerged → `\{page\}/\{locale\}/data.json` unter `apiBaseUrl`; source → kompakter Baum. Auf Node ist dieser Baum auch die SSR-Quelle, wenn `serverAssets` eine öffentliche Kopie erzwingt. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Aktiviert Nitro-Prerender für `/\{apiBaseUrl\}/.../data.json`. In der Regel überflüssig, wenn premerged `publicAssets` diese Dateien bereits geschrieben hat. |
| `translationPayloads.publicDir` | `string` | — | Öffentlicher Ausgabeordner relativ zum Nitro-Public-Root. Standardwert ist `apiBaseUrl` (`_locales`). Damit passen statische Dateien zu den Client-Fetch-URLs (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Warnt während des Builds, wenn die Anzahl der generierten Payload-Dateien diesen Schwellenwert überschreitet. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Warnt während des Builds, wenn die Gesamtgröße der generierten Payloads in Bytes diesen Schwellenwert überschreitet. |

## SEO

Meta-Tags, die für jede lokalisierte Seite generiert werden.

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Generiert automatisch SEO-Meta-Tags (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | Basis-URL für SEO-Meta-Tags (canonical, og:url, hreflang). - Ein konkreter URL-String (z. B. `'https://example.com'`) — wird unverändert übernommen (höchste Priorität). - `undefined` — greift auf `site.url` aus `nuxt-site-config` zurück, wenn dieses Modul vorhanden ist, ansonsten auf den Origin der aktuellen Anfrage (`useRequestURL().origin` auf dem Server, `window.location.origin` auf dem Client). |
| `metaTrustForwardedHost` | `boolean` | `true` | Vertraut dem Header `X-Forwarded-Host` beim Auflösen der Basis-URL für Meta-Tags. Aktivieren, wenn die App hinter einem Reverse-Proxy (nginx, Cloudflare, AWS ALB usw.) läuft, der diesen Header auf den tatsächlichen kundenseitigen Hostnamen setzt. |
| `metaTrustForwardedProto` | `boolean` | `true` | Vertraut dem Header `X-Forwarded-Proto` beim Auflösen des Protokolls für Meta-Tags. Aktivieren, wenn die App hinter einem TLS-terminierenden Proxy läuft, damit kanonische URLs `https://` verwenden, obwohl die App selbst auf HTTP lauscht. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Liste der Namen von Query-Parametern, die in den Meta-Tags canonical und `og:url` erhalten bleiben. Parameter, die nicht in dieser Liste stehen, werden aus der kanonischen URL entfernt. |

## Erkennung und Weiterleitungen

Locale-Wahl für Besucher, die noch keine ausgewählt haben.

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Aktiviert automatische, locale-basierte Weiterleitungen. Bei `true` werden Besucher beim ersten Besuch auf ihre bevorzugte Locale weitergeleitet (erkannt aus Cookie, `Accept-Language`-Header oder Standardwert). |
| `autoDetectLanguage` | `boolean` | `true` | Erkennt die bevorzugte Sprache des Nutzers automatisch aus dem HTTP-Header `Accept-Language`. Wird zusammen mit `autoDetectPath` verwendet, um den Zeitpunkt der Erkennung festzulegen. |
| `autoDetectPath` | `string` | `'/'` | Wo Cookie- / Accept-Language-Weiterleitungen laufen dürfen (bei aktiviertem `redirects`). - `'/'` — nur `/` (Deep Links in der Standard-Locale bleiben erreichbar; Standard). - `'no_prefix'` — nur Pfade ohne Locale-Präfix. - `'*'` — jeder Pfad, einschließlich Umschreibung eines expliziten Locale-Präfixes (z. B. `/fr/about` → `/de/about`, wenn das Cookie `de` bevorzugt). - jeder andere String — exakte Pfadübereinstimmung (z. B. `'/welcome'`). Aufräumarbeiten präfixbasierter Strategien (z. B. `/en` → `/` bei `prefix_except_default`) sind nicht eingeschränkt. |

## Registrierung

Teile des Moduls, die du abschalten kannst.

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Registriert das Makro-Plugin `defineI18nRoute()` und ermöglicht damit seitenweite `defineI18nRoute()`-Aufrufe. |
| `plugin` | `boolean` | `true` | Registriert das i18n-Kernplugin, das `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` und weitere Laufzeit-Helfer bereitstellt. |
| `hooks` | `boolean` | `true` | Registriert das i18n-Hooks-Plugin, das die App-Hooks `i18n:register` sowie `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch` bereitstellt. |
| `components` | `boolean` | `true` | Registriert die eingebauten i18n-Komponenten (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Setze auf `false`, um die automatische Komponentenregistrierung zu deaktivieren (z. B. wenn du sie nicht verwendest und die Modulgröße reduzieren möchtest). |
| `types` | `boolean` | `true` | Generiert TypeScript-Typdeklarationen für `useI18n`, `$t` und verwandte Helfer basierend auf den Übersetzungsschlüsseln deiner Dateien für die Standard-Locale. |
| `debug` | `boolean` | `false` | Aktiviert ausführliches Debug-Logging für Locale-Erkennung, Routen-Generierung und Laden der Übersetzungen. |

## Sonstiges

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | Gibt zusätzlich ein reines Sprach-`hreflang` aus, das aus dem `iso` jeder Locale abgeleitet wird (z. B. `es-ES` → zusätzlich `es`). Die erste regionale Locale in `locales` beansprucht das reine Tag für diese Sprache. Der Routing-`code` wird nie verwendet — ausschließlich `iso \|\| code`. |
| `vueDevtools` | `boolean` | `true` | Registriert im Entwicklungsmodus den Vue-DevTools-Inspector und die Timeline (Browsererweiterung). Getrennt vom benutzerdefinierten Tab in den Nuxt DevTools. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Präfix vor lokalisierten Routennamen (z. B. `'localized-index'`). Wird intern verwendet, um Originalrouten von generierten Locale-Varianten zu unterscheiden. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Deaktivierung von Meta-Tags pro Route, extrahiert aus `defineI18nRoute()`-Aufrufen. Ordnet einem Routenpfad `true` (alle Meta-Tags deaktivieren) oder ein Array von Locale-Codes zu, für die Meta-Tags deaktiviert werden sollen. |
| `missingWarn` | `boolean` | `true` | Zeigt Konsolenwarnungen an, wenn ein Übersetzungsschlüssel fehlt. |
| `hmr` | `boolean` | `true` | Aktiviert Hot Module Replacement für Übersetzungsdateien in der Entwicklung. Bei `true` lösen Änderungen an JSON-Übersetzungsdateien ein automatisches Neuladen ohne vollständigen Seitenreload aus. |
| `cacheMaxSize` | `number` | `0` | Maximale Anzahl an Einträgen im In-Memory-Cache für Übersetzungen. `0` bedeutet kein Limit. |
| `cacheTtl` | `number` | `0` | Time-to-live (in Sekunden) für zwischengespeicherte Übersetzungseinträge. `0` bedeutet, dass Einträge nie ablaufen. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Benannte Zahlenformate pro Locale (kompatibel zu Vue I18n). Ermöglicht Aufrufe im Stil `$tn(1000, 'currency')`. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Benannte Datums-/Zeitformate pro Locale (kompatibel zu `datetimeFormats` von Vue I18n). Ermöglicht Aufrufe im Stil `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | HTTP-`Cache-Control` max-age (Sekunden) für `/\{apiBaseUrl\}/:page/:locale/data.json`. Wirkt vollständig nur, solange `dateBuild` die URL invalidiert (`?v=...`), was der Standard ist: Die Antwort ist dann `public, max-age=…, immutable` und sicher für Browser und CDNs. - `dateBuild: 0`/`''` — die URL bleibt stabil, daher wird diese Dauer *nicht* respektiert; die Antwort wird stattdessen `public, max-age=0, must-revalidate`. Ein langer `max-age` auf einer unveränderlichen URL friert das erste Payload ein, das ein Browser je gesehen hat. - `0` — setzt überhaupt kein `Cache-Control` (nützlich beim lokalen Debuggen). - Wird in der Entwicklung nicht angewendet (`import.meta.dev`), damit der Browser-Cache HMR nicht behindert. - Wirkt nur auf Antworten, die über Nitro ausgeliefert werden. In `public/` kopierte und von der Hosting-Plattform ausgelieferte Payloads erhalten die Header dieser Plattform — siehe den Performance-Leitfaden. Analog zum experimentellen `httpCacheDuration` von `@nuxtjs/i18n` (v10.2.0), aber als expliziter Antwort-Header statt als `maxAge` von `defineCachedEventHandler`. |
| `dateBuild` | `string \| number` | — | Wert, der zum Cache-Busting von Übersetzungsanfragen (`?v=...`) verwendet wird. Ohne Angabe fällt das Modul auf `Date.now()` zurück (nicht deterministisch). Für reproduzierbare/rollende Deployments setze einen stabilen Wert (z. B. einen Git-SHA oder eine Build-Nummer). |
| `experimental` | `Record<string, unknown>` | — | Sammelstelle für experimentelle/instabile Optionen. Inhalt kann sich ohne Vorankündigung zwischen Minor-Versionen ändern oder entfernt werden. |
