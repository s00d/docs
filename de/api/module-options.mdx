Diese Seite listet jeden Schlüssel des `i18n`-Objekts in `nuxt.config` auf. Verwenden Sie die Tabellen, um einen Typ oder Standardwert nachzuschlagen, und die Details weiter unten für Beispiele und Hinweise. Typen, Standardwerte und Beschreibungen werden aus dem Interface `ModuleOptions` in [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts) generiert.

```ts nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
    ],
    defaultLocale: 'en',
  },
})
```

Eine verschachtelte Option erscheint unter ihrem Punkt-Pfad: `translationPayloads.mode` ist der Schlüssel `mode` von `translationPayloads`.

## Locales und Routing {#locales-and-routing}

Welche Sprachen existieren und wie sie in der URL erscheinen.

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Liste der unterstützten Locales. Jeder Eintrag definiert einen Locale-Code plus optionale Metadaten (ISO, Richtung, Anzeigename usw.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | URL-Routing-Strategie für Locale-Präfixe. - `'no_prefix'` — keine Locale in der URL; die Locale wird in einem Cookie gespeichert. - `'prefix_except_default'` — Präfix für alle Locales außer der Standard-Locale. - `'prefix'` — immer ein Präfix, auch für die Standard-Locale. - `'prefix_and_default'` — wie `prefix`, aber die Standard-Locale ist auch ohne Präfix erreichbar. |
| `defaultLocale` | `string` | `'en'` | Die Locale, die verwendet wird, wenn sich aus URL oder Benutzerpräferenzen keine Locale bestimmen lässt. Sie ist kein Übersetzungs-Fallback: Setzen Sie dafür `fallbackLocale`. |
| `localeCookie` | `string \| null` | `null` | Cookie-Name, um die Locale-Präferenz des Benutzers über Sitzungen hinweg zu speichern. Auf `null` setzen, um die Cookie-basierte Speicherung zu deaktivieren. Wird bei der Strategie `no_prefix` automatisch auf `'user-locale'` gesetzt, wenn nichts angegeben ist; ein explizites `null` im `i18n`-Konfigurationsblock hält es auch dort deaktiviert. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `{}` | Globale Locale-Konfiguration auf Routenebene. Erlaubt es, Locale-Routen für bestimmte Seiten einzuschränken oder anzupassen, ohne deren Komponenten zu ändern. - `false` — die Route von der Lokalisierung ausschließen. - `Record<LocaleCode, string>` — eigene Pfade pro Locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Eigener regulärer Ausdruck (oder dessen String-Quelle) zum Erkennen von Locale-Codes in URL-Segmenten. Jeder Locale-Code in `locales` muss dem gesamten Muster ohne dessen Flags entsprechen, sonst schlägt der Build fehl. |
| `noPrefixRedirect` | `boolean` | `false` | Für die Strategie `no_prefix`: Wenn die Standard-Locale für eine Seite einen eigenen Pfad hat (`localeRoutes` / `globalLocaleRoutes`), wird der ursprüngliche Pfad der Seite auf den eigenen Pfad der Locale des Besuchers weitergeleitet, andernfalls auf den der Standard-Locale (z. B. `/about` → `/about-us`). Eine Locale ohne eigenen Pfad bleibt auf dem ursprünglichen Pfad. Seiten mit dynamischen Segmenten werden nicht weitergeleitet. |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Pfade, die vom i18n-Routing ausgenommen werden: Ein String ist ein Pfadpräfix (`/admin` umfasst `/admin/x`) oder ein `*` / `?`-Glob; ein RegExp wird gegen den Pfad getestet. Passende Seiten erhalten keine Locale-Varianten, keine Locale-Weiterleitung oder 404 und werden aus dem Prerendering entfernt; sie werden weiterhin mit Übersetzungen gerendert. `/api`, `/_nuxt`, `/__*`, die Übersetzungsroute und gängige statische Dateien (Sitemap, robots.txt, Favicon, Assets nach Dateiendung) sind immer ausgeschlossen. |
| `routeLocales` | `Record<string, string[]>` | — | Locale-Einschränkungen pro Route, zur Build-Zeit aus `$defineI18nRoute()`-Aufrufen extrahiert. Ordnet einem Routenpfad (z. B. `'/about'`) ein Array erlaubter Locale-Codes zu. Nicht aufgeführte Routen haben keine Einschränkungen (alle Locales erlaubt). |

## Übersetzungen {#translations}

Wo Übersetzungsdateien liegen und wie Schlüssel aufgelöst werden.

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Pfad zum Verzeichnis mit den JSON-Übersetzungsdateien, relativ zum Projekt-Root. |
| `disableWatcher` | `boolean` | `false` | Deaktiviert den Datei-Watcher, der im Entwicklungsmodus fehlende Übersetzungsdateien automatisch anlegt. |
| `routesLocaleLinks` | `{ [key: string]: string }` | `{}` | Ordnet Routennamen anderen Routennamen zu, damit sie dieselben Übersetzungsdateien teilen. Zum Beispiel bedeutet `{ 'about-us': 'about' }`, dass die Seite `about-us` die Übersetzungen der Seite `about` statt ihrer eigenen verwendet. |
| `plural` | `PluralFunc` | ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)`` | Eigene Pluralisierungsfunktion. Erhält `(key, count, params, locale, getter)` und sollte die gewählte Pluralform als String zurückgeben, oder `null`/`undefined`, um auf die integrierte `defaultPlural`-Logik zurückzufallen (so können Sie nur einige Locales überschreiben). Für das Nuxt-Modul wird die Funktion mit `.toString()` in `.nuxt/i18n.plural.mjs` serialisiert — sie muss eigenständig sein (keine Imports / kein äußerer Scope). Ein Dateipfad als String wird **nicht** unterstützt. |
| `disablePageLocales` | `boolean` | `false` | Deaktiviert seitenspezifische Übersetzungsdateien. Bei `true` werden nur globale Übersetzungen (`{locale}.json`) geladen; seitenspezifische Dateien (`pages/{page}/{locale}.json`) werden weder generiert noch geladen. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Globaler Fallback-Locale-Code. Schlüssel, die in einer Locale fehlen, werden aus dieser Locale übernommen (beim Erstellen oder Laden in jede Payload eingemischt); ohne sie wird ein fehlender Schlüssel als der Schlüssel selbst gerendert. |

## Payloads und Caching {#payloads-and-caching}

Wie Übersetzungen den Browser erreichen. [Performance](/de/guide/performance) erklärt, was diese Optionen zur Laufzeit ändern.

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Lädt die Übersetzungen der Index-Seite in der globalen Nitro-Middleware vor (nur Server, private Konfiguration). |
| `apiBaseUrl` | `string` | `'_locales'` | Basis-URL-Pfadsegment für die API-Route der Übersetzungen (verwendet beim Datenabruf in SSR/SSG). Kann auch über die Umgebungsvariable `NUXT_I18N_APP_BASE_URL` gesetzt werden. |
| `apiBaseClientHost` | `string` | `undefined` | Überschreibt den Host für clientseitige Abrufe von Übersetzungen. Nützlich, wenn der Client den Server über einen anderen Hostnamen erreicht als den, den Nuxt sieht. Kann auch über die Umgebungsvariable `NUXT_I18N_APP_BASE_CLIENT_HOST` gesetzt werden. |
| `apiBaseServerHost` | `string` | `undefined` | Überschreibt den Host für serverseitige Abrufe von Übersetzungen. Nützlich in Container-/Microservice-Setups, in denen der Server sich selbst über einen internen Hostnamen erreicht. Kann auch über die Umgebungsvariable `NUXT_I18N_APP_BASE_SERVER_HOST` gesetzt werden. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Steuert, wie Übersetzungs-Payloads ausgegeben werden (Node-Server: `public/<apiBaseUrl>`; Edge / Function / Inline: Nitro-`serverAssets`). - **Node-Server** (`node-server`, `node-cluster`, Festplatten-`serveStatic`): `serverAssets` bedeutet lokales SSR über `readFile` unter `public/` (kein Rollup-`raw:`). - **Edge, Function-Presets und `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …): `serverAssets` registriert Nitro-`serverAssets` (`assets:i18n`),   weil `public/` für SSR nicht auf der Festplatte verfügbar ist. Erzwingt keine öffentliche Kopie — setzen Sie `publicAssets: true` für CDN/statisches Hosting. Behalten Sie die Standardwerte für das übliche All-in-one-Setup bei. Für große Edge-Kataloge `mode: 'source'` bevorzugen. Für CDN-gestützte Deployments lokale Ausgaben deaktivieren und `apiBaseClientHost` / `apiBaseServerHost` setzen. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Strategie für Übersetzungs-Payloads. - `premerged`: zur Build-Zeit erzeugte `{page}/{locale}/data.json`-Matrix (Standard) - `source`: kompakte Quelldateien, die zur Laufzeit zusammengeführt werden (bei Edge / großen Katalogen bevorzugen) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Lokale SSR-Payloads: Ein Node-Server, der `public/` von der Festplatte ausliefert, liest diesen Baum (erzwingt eine öffentliche Kopie); Edge, Function-Presets und `serveStatic: "inline"` betten über Nitro-`serverAssets` ein. - **Node-Server** (das Preset liefert `public/` selbst aus, z. B. `node-server`): keine Nitro-`serverAssets` (vermeidet Rollup-`raw:`). SSR liest   `public/<apiBaseUrl\|publicDir>` als `{page}/{locale}/data.json`; wenn dies `true` ist,   wird eine öffentliche Kopie erzwungen, auch wenn `publicAssets` false ist. - **Edge, Function-Presets und Inline** (`nitro.node === false`, kein Festplatten-`serveStatic` wie bei `vercel` /   `netlify` / `aws-lambda`, oder `serveStatic: "inline"` z. B. winterjs): Nitro-`serverAssets` (`assets:i18n`)   mit demselben Layout wie `mode`. Erzwingt **keine** öffentliche Kopie — setzen Sie `publicAssets: true` für CDN/statisches Hosting. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Registriert die integrierte Server-Route unter `/{apiBaseUrl}/:page/:locale/data.json`. Deaktivieren Sie dies, wenn Übersetzungs-Payloads von einem externen Host/CDN ausgeliefert werden. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Kopiert Payloads in die öffentliche Nitro-Ausgabe. Premerged → `{page}/{locale}/data.json` unter `apiBaseUrl`; source → kompakter Baum. Wenn SSR `public/` liest (`node-server` und ähnliche), erzwingt auch `serverAssets: true` diese Kopie. Bei Edge- / Function- / `serveStatic: "inline"`-Presets wird nur kopiert, wenn dies `true` ist (SSR verwendet die Nitro-Einbettung). |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Opt-in für das Nitro-Prerendering von `/{apiBaseUrl}/.../data.json`. Meist überflüssig, wenn premerged `publicAssets` diese Dateien bereits geschrieben hat. |
| `translationPayloads.publicDir` | `string` | — | Öffentlicher Ausgabeordner relativ zum öffentlichen Nitro-Root. Standardmäßig `apiBaseUrl` (`_locales`). Damit entsprechen statische Dateien den Abruf-URLs des Clients (`/{apiBaseUrl}/{page}/{locale}/data.json`). |
| `translationPayloads.rootDelta` | `boolean` | `true` | Schreibt eine Root-Datei pro Locale und in jede Seitendatei nur das, was sich davon unterscheidet. Client und SSR führen sie zusammen; ein vollständiger Chunk funktioniert weiterhin überall, wo eine Datei gelesen wird. `false` behält ein vollständiges Wörterbuch in jeder Seitendatei. Nur bei `premerged` und deaktiviert mit `disablePageLocales`. |
| `translationPayloads.warnFileCount` | `number` | `500` | Warnt beim Build, wenn die Anzahl der generierten Payload-Dateien diesen Schwellenwert überschreitet. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Warnt beim Build, wenn die Gesamtgröße der generierten Payloads diesen Schwellenwert in Bytes überschreitet. |

## SEO {#seo}

Meta-Tags, die für jede lokalisierte Seite generiert werden.

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Generiert SEO-Meta-Tags (`hreflang`, `canonical`, `og:url`, `og:locale`) automatisch. |
| `metaBaseUrl` | `string` | `undefined` | Basis-URL für SEO-Meta-Tags (canonical, og:url, hreflang). - Ein konkreter URL-String (z. B. `'https://example.com'`) — wird unverändert verwendet (höchste Priorität). - `undefined` — fällt auf `site.url` aus `nuxt-site-config` zurück, wenn dieses Modul   vorhanden ist, andernfalls auf den Origin der aktuellen Anfrage   (`useRequestURL().origin` auf dem Server, `window.location.origin` auf dem Client). |
| `metaTrustForwardedHost` | `boolean` | `true` | Vertraut beim Auflösen der Basis-URL für Meta-Tags dem Header `X-Forwarded-Host`. Aktivieren, wenn die App hinter einem Reverse-Proxy (nginx, Cloudflare, AWS ALB usw.) läuft, der diesen Header auf den echten, für Clients sichtbaren Hostnamen setzt. |
| `metaTrustForwardedProto` | `boolean` | `true` | Vertraut beim Auflösen des Protokolls für Meta-Tags dem Header `X-Forwarded-Proto`. Aktivieren, wenn die App hinter einem TLS-terminierenden Proxy läuft, damit kanonische URLs `https://` verwenden, obwohl die App selbst über HTTP lauscht. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Liste der Query-Parameter-Namen, die in den Meta-Tags canonical und `og:url` erhalten bleiben. Parameter, die nicht in dieser Liste stehen, werden aus der kanonischen URL entfernt. |

## Erkennung und Weiterleitungen {#detection-and-redirects}

Auswahl einer Locale für Besucher, die noch keine gewählt haben.

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Aktiviert automatische Locale-Weiterleitungen (Server-Plugin und clientseitige Routen-Middleware). Bei `true` leiten die Präfix-Strategien eine URL ohne Präfix auf ihre lokalisierte Form weiter. Die Locale stammt aus dem App-Zustand, dem Cookie oder `Accept-Language`, wo `autoDetectPath` es erlaubt, andernfalls aus dem Standard. Unter `no_prefix` ändert die Erkennung nie die URL (siehe `noPrefixRedirect` für eigene Pfade). |
| `autoDetectLanguage` | `boolean` | `true` | Erkennt die bevorzugte Sprache des Benutzers automatisch aus dem HTTP-Header `Accept-Language`. Wird zusammen mit `autoDetectPath` verwendet, um zu entscheiden, wann die Erkennung stattfindet. |
| `autoDetectPath` | `string` | `'/'` | Wo Weiterleitungen nach Cookie- / Accept-Language-Präferenz ausgeführt werden dürfen (wenn `redirects` aktiviert ist). - `'/'` — nur `/` (Deep Links in der Standard-Locale bleiben erreichbar; Standard) - `'no_prefix'` — nur Pfade ohne Locale-Präfix - `'*'` — jeder Pfad, einschließlich des Umschreibens eines expliziten Locale-Präfixes   (z. B. `/fr/about` → `/de/about`, wenn das Cookie `de` bevorzugt) - jeder andere String — genau dieser Pfad, abschließende Schrägstriche werden ignoriert (z. B. `'/welcome'`) Unter `prefix` leitet eine URL ohne Präfix außerhalb der erlaubten Pfade weiterhin auf die Form der Standard-Locale weiter (`/about` → `/en/about`). Die Standard-Locale mit Präfix unter `prefix_except_default` (`/en`) ist ein 404, keine Weiterleitung. |

## Registrierung {#registration}

Teile des Moduls, die Sie abschalten können.

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Stellt `$defineI18nRoute()` zur Laufzeit bereit. Der Build liest `$defineI18nRoute()`-Aufrufe in Seiten in jedem Fall. |
| `plugin` | `boolean` | `true` | Registriert das zentrale i18n-Plugin, das `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` und weitere Laufzeit-Helfer bereitstellt. |
| `hooks` | `boolean` | `true` | Ruft den App-Hook `i18n:register` beim Laden und bei der Navigation auf, damit Plugins Übersetzungen hinzufügen können. |
| `components` | `boolean` | `true` | Registriert die integrierten i18n-Komponenten (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Auf `false` setzen, um die automatische Registrierung der Komponenten zu deaktivieren (z. B. wenn Sie sie nicht verwenden und den Umfang des Moduls verringern möchten). |
| `types` | `boolean` | `true` | Generiert TypeScript-Typdeklarationen für `useI18n`, `$t` und verwandte Helfer auf Basis der Übersetzungsschlüssel in den Dateien Ihrer Standard-Locale. |
| `debug` | `boolean` | `false` | Aktiviert ausführliches Debug-Logging für Locale-Erkennung, Routengenerierung und das Laden von Übersetzungen. |

## Sonstiges {#other}

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `trustForwardedHost` | `boolean` | `false` | Bestimmt die Domain einer Anfrage (`locales[].baseUrl`) aus `X-Forwarded-Host` statt aus `Host`. Aktivieren Sie dies nur hinter einem Proxy, der diesen Header überschreibt. |
| `hreflangBaseLanguage` | `boolean` | `false` | Gibt zusätzlich ein `hreflang` nur mit der Sprache aus, abgeleitet aus dem `iso` jeder Locale (z. B. `es-ES` → zusätzlich `es`). Die erste regionale Locale in `locales` beansprucht das reine Sprach-Tag für diese Sprache. Der Routing-`code` wird nie verwendet — nur `iso \|\| code`. |
| `additionalTranslationDirs` | `string[]` | `[]` | Zusätzliche Verzeichnisse (relativ zum Projekt-Root / zum Root jeder Nuxt-Layer), deren `{locale}.json`-Dateien auf oberster Ebene vor `translationDir` tief in das globale Wörterbuch eingemischt werden. Merge-Reihenfolge: jeder Eintrag in Array-Reihenfolge (über Layer hinweg), dann `translationDir` (gewinnt bei Konflikten). Nur `{locale}.json`-Dateien im Root werden gelesen — `pages/` unter diesen Verzeichnissen wird ignoriert. Beispiel: `translationDir: 'frontend'`, `additionalTranslationDirs: ['common']` → `common/en.json`, dann `frontend/en.json`. |
| `vueDevtools` | `boolean` | `true` | Registriert in der Entwicklung Inspector und Timeline in Vue DevTools (Browsererweiterung). Getrennt vom eigenen Tab in Nuxt DevTools. |
| `trailingSlash` | `'append' \| 'remove'` | `undefined (inherit from Nuxt)` | Abschließender Schrägstrich für `$localePath` / `$switchLocalePath` (wie bei NuxtLink). Standardmäßig `experimental.defaults.nuxtLink.trailingSlash`, wenn nicht gesetzt. Explizit setzen, um den Link-Standard von Nuxt für die i18n-Pfad-Helfer zu überschreiben. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Präfix, das lokalisierten Routennamen vorangestellt wird (z. B. `'localized-index'`). Wird intern verwendet, um ursprüngliche Routen von generierten Locale-Varianten zu unterscheiden. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Deaktivierung von Meta-Tags pro Route. Ordnet einem Routennamen oder -pfad `true` (alle Meta-Tags deaktivieren) oder ein Array von Locale-Codes zu, für die Meta-Tags deaktiviert werden sollen. Einträge aus `$defineI18nRoute()`-Aufrufen werden zur Build-Zeit hinzugefügt. |
| `missingWarn` | `boolean` | `true` | Zeigt Konsolenwarnungen, wenn ein Übersetzungsschlüssel fehlt (Entwicklungs-Build, im Browser). |
| `hmr` | `boolean` | `true` | Aktiviert Hot Module Replacement für Übersetzungsdateien in der Entwicklung. Bei `true` lösen Änderungen an JSON-Übersetzungsdateien ein automatisches Neuladen ohne vollständige Seitenaktualisierung aus. |
| `cacheMaxSize` | `number` | `0` | Maximale Anzahl Einträge in den In-Memory-Übersetzungscaches. Die Fetch- und Server-Caches verwerfen den am längsten nicht verwendeten Eintrag; die Wörterbuch-Map des Browsers verwirft den ältesten (FIFO). `0` bedeutet kein Limit im Browser; Server-Caches behalten dann höchstens 1000 Einträge, damit Anfrage-URLs mit erfundenen Seiten den Serverspeicher nicht wachsen lassen können. |
| `cacheTtl` | `number` | `0` | Lebensdauer (in Sekunden) der Fetch- und Server-Übersetzungscaches, gezählt ab dem Speichern eines Eintrags (Lesezugriffe verlängern sie nicht), sodass Daten von `apiBaseServerHost` mindestens so oft aktualisiert werden. Die aktiven Wörterbücher des Browsers laufen dadurch nicht ab. `0` bedeutet, dass Einträge nie ablaufen. |
| `cacheStorage` | `string` | — | Name eines Nitro-Storage-Mounts (`nitro.storage`, z. B. `'redis'`), den mehrere Server-Instanzen als Wörterbuch-Cache teilen; er wird nach dem prozessinternen Cache und vor der Quelle gelesen. Lohnt sich vor allem mit `apiBaseServerHost`: ein Abruf vom Backend statt einer pro Instanz. Einträge sind nach Build geschlüsselt und laufen nach `cacheTtl` ab, oder nach einem Tag, wenn es `0` ist. Deaktiviert in Dev und beim Prerendering. Ein fehlerhafter Storage fällt auf die Quelle zurück. Nicht gesetzt: kein gemeinsamer Cache. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Benannte Zahlenformate pro Locale (Vue-I18n-kompatibel). Ermöglicht Aufrufe im Stil von `$tn(1000, 'currency')`. |
| `timeZone` | `string` | `the runtime's zone` | IANA-Zeitzone für `$td` und `<i18n-t date>` (`Europe/Berlin`). Setzen Sie sie, damit ein Datum auf dem Server und in jedem Browser gleich gerendert wird; die eigene `timeZone` eines benannten Formats hat Vorrang. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Benannte Datums-/Zeitformate pro Locale (Vue-I18n-kompatible `datetimeFormats`). Ermöglicht Aufrufe im Stil von `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | HTTP-`Cache-Control`-max-age (Sekunden) für `/{apiBaseUrl}/:page/:locale/data.json`. Gilt nur vollständig, solange `dateBuild` die URL per Cache-Busting versioniert (`?v=...`), was der Standard ist: Die Antwort ist dann `private, max-age=…, immutable`: Ein Browser hält sie fest, ein CDN, das die Query ignoriert, kann das nicht (`public` mit `httpCacheControl: false`). - `dateBuild: 0`/`''` — die URL ist stabil, daher wird diese Dauer *nicht* berücksichtigt; die   Antwort wird stattdessen `public, max-age=0, must-revalidate`. Ein langes `max-age` auf einer   unveränderlichen URL hält die erste Payload fest, die ein Browser je gesehen hat. - `0` — `Cache-Control` überhaupt nicht setzen (nützlich beim lokalen Debugging) - Wird in der Entwicklung (`import.meta.dev`) nicht angewendet, damit der Browser-Cache HMR nicht behindert - Erreicht nur Antworten, die über Nitro ausgeliefert werden. Payloads, die nach `public/` kopiert und   von der Hosting-Plattform ausgeliefert werden, erhalten deren Header — siehe den Performance-Leitfaden. Analog zu `httpCacheDuration` aus `@nuxtjs/i18n` experimental (v10.2.0), aber als expliziter Antwort-Header statt als maxAge von Nitros `defineCachedEventHandler`. |
| `httpCacheControl` | `string \| false` | `'public, max-age=60'` | `Cache-Control` einer Payload-Datei, die von einem Host oder einer pfadweiten Regel beantwortet wird, die `?v=` nicht sehen kann. Auf einem Node-Server wird eine Antwort auf das aktuelle `?v=` für `httpCacheDuration` festgehalten und jede andere revalidiert; mit `source`, `cacheTtl` oder `apiBaseServerHost`, bei denen sich ein Wörterbuch ohne Build ändert, erhält jede Antwort diesen Header. `false` belässt jede Datei auf `max-age=0, must-revalidate`. |
| `dateBuild` | `string \| number` | — | Wert für das Cache-Busting von Übersetzungsanfragen (`?v=...`). Wenn nicht angegeben, verwendet das Modul einen Hash der Übersetzungsdateien, sodass sich der Wert nur ändert, wenn sich Übersetzungen ändern (`Date.now()`, wenn kein Hash berechnet werden kann). `0` oder `''` schaltet das Cache-Busting ab. Setzen Sie einen stabilen Wert (einen Git-SHA, eine Build-Nummer), um ihn selbst festzulegen. `NUXT_I18N_DATE_BUILD` oder `runtimeConfig.public.i18nRuntime.dateBuild` ersetzt ihn zur Laufzeit, nachdem ein Wörterbuch an Ort und Stelle ersetzt wurde: Festgehaltene URLs bleiben zurück, ohne Rebuild. |
| `experimental` | `Record<string, unknown>` | — | Sammelbecken für experimentelle/instabile Optionen. Der Inhalt kann sich zwischen Minor-Versionen ohne Ankündigung ändern oder entfernt werden. |

## Details zu den Optionen {#option-details}

Optionen, zu denen es über die Tabelle hinaus nichts zu ergänzen gibt, werden hier nicht wiederholt.

### Locales und URLs {#locales-and-urls}

#### `locales` {#locales}

**Typ** `Locale[]` · **Standard** `[]`

Liste der unterstützten Locales.
Jeder Eintrag definiert einen Locale-Code plus optionale Metadaten (ISO, Richtung, Anzeigename usw.).

Jeder Eintrag ist ein `Locale`-Objekt:

| Eigenschaft | Typ | Beschreibung |
| --- | --- | --- |
| `code` | `string` | **Erforderlich.** URL-Segment und Dateiname (`en`, `de-at`). |
| `iso` | `string` | BCP-47-Tag für `<html lang>`, `hreflang`, Pluralformen und `$tn` / `$td` / `$tdr` (`en-US`). |
| `displayName` | `string` | Beschriftung in `<i18n-switcher>` und `$getLocaleName()`. |
| `dir` | `'ltr' \| 'rtl' \| 'auto'` | `<html dir>`. Ohne Angabe erhalten bekannte RTL-Sprachen `rtl` und jede andere Locale kein Attribut. Siehe [SEO](/de/guide/seo#text-direction). |
| `disabled` | `boolean` | Ausgeschlossen von Routen, Payloads und Umschaltung. Ihr Präfix ist ein 404, und Links darauf bleiben auf der Seite. |
| `fallbackLocale` | `string` | Fallback für diese Locale; überschreibt die globale `fallbackLocale`. |
| `seo` | `boolean` | `false` lässt die Locale in `hreflang` und `og:locale:alternate` weg. |
| `og` | `string` | Wert für `og:locale` (`ar_AE`); Standard: konvertiertes `iso`. |
| `baseUrl` | `string` | Die eigene Domain der Locale: Ein Build bedient sie, und Links von anderen Domains darauf sind absolut. |
| `baseDefault` | `boolean` | Mit `baseUrl`: die Standard-Locale ihres Hosts, ohne `/<code>`-Präfix in Links darauf (`prefix` behält es bei). |

Weitere Eigenschaften bleiben erhalten und werden von `$getLocales()` zurückgegeben. Typisieren Sie sie, indem Sie `Locale` erweitern:

```ts
// i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
  }
}
export {}
```

Das Modul hoistet `@i18n-micro/types`, daher funktioniert dies unter pnpm, ohne das Paket zu installieren.

#### `defaultLocale` {#defaultlocale}

**Typ** `string` · **Standard** `'en'`

Die Locale, die verwendet wird, wenn sich aus URL oder Benutzerpräferenzen keine Locale bestimmen lässt.
Sie ist kein Übersetzungs-Fallback: Setzen Sie dafür `fallbackLocale`.

#### `strategy` {#strategy}

**Typ** `Strategies` · **Standard** `'prefix_except_default'`

URL-Routing-Strategie für Locale-Präfixe.

- `'no_prefix'` — keine Locale in der URL; die Locale wird in einem Cookie gespeichert.
- `'prefix_except_default'` — Präfix für alle Locales außer der Standard-Locale.
- `'prefix'` — immer ein Präfix, auch für die Standard-Locale.
- `'prefix_and_default'` — wie `prefix`, aber die Standard-Locale ist auch ohne Präfix erreichbar.

URLs pro Strategie und Weiterleitungen: [Routing-Strategien](/de/guide/strategy).

#### `globalLocaleRoutes` {#globallocaleroutes}

**Typ** `GlobalLocaleRoutes` · **Standard** `{}`

Globale Locale-Konfiguration auf Routenebene.
Erlaubt es, Locale-Routen für bestimmte Seiten einzuschränken oder anzupassen, ohne
deren Komponenten zu ändern.

- `false` — die Route von der Lokalisierung ausschließen.
- `Record<LocaleCode, string>` — eigene Pfade pro Locale.

Schlüssel sind Routennamen oder Pfade. Wird üblicherweise pro Seite mit [`$defineI18nRoute`](/de/guide/per-component-translations) gesetzt.

```ts
globalLocaleRoutes: {
  about: { en: '/about-us', de: '/ueber-uns' },
  'admin-dashboard': false, // not localized
}
```

Details, dynamische Segmente und `pages:extend`-Routen: [Lokalisierte Pfade](/de/guide/custom-locale-routes).

#### `routeLocales` {#routelocales}

**Typ** `Record<string, string[]>` · **Standard** —

Locale-Einschränkungen pro Route, zur Build-Zeit aus `$defineI18nRoute()`-Aufrufen extrahiert.
Ordnet einem Routenpfad (z. B. `'/about'`) ein Array erlaubter Locale-Codes zu.
Nicht aufgeführte Routen haben keine Einschränkungen (alle Locales erlaubt).

#### `routeDisableMeta` {#routedisablemeta}

**Typ** `Record<string, boolean \| string[]>` · **Standard** —

Deaktivierung von Meta-Tags pro Route. Ordnet einem Routennamen oder -pfad `true` (alle Meta-Tags deaktivieren) oder ein Array
von Locale-Codes zu, für die Meta-Tags deaktiviert werden sollen. Einträge aus `$defineI18nRoute()`-Aufrufen
werden zur Build-Zeit hinzugefügt.

#### `customRegexMatcher` {#customregexmatcher}

**Typ** `string \| RegExp` · **Standard** `undefined (uses built-in pattern based on locale codes)`

Eigener regulärer Ausdruck (oder dessen String-Quelle) zum Erkennen von Locale-Codes in URL-Segmenten.
Jeder Locale-Code in `locales` muss dem gesamten Muster ohne dessen Flags entsprechen, sonst schlägt der Build fehl.

```ts
customRegexMatcher: '[a-z]{2}-[a-z]{2}', // en-us, de-at
```

#### `excludePatterns` {#excludepatterns}

**Typ** `(string \| RegExp)[]` · **Standard** `undefined`

Pfade, die vom i18n-Routing ausgenommen werden: Ein String ist ein Pfadpräfix (`/admin` umfasst `/admin/x`)
oder ein `*` / `?`-Glob; ein RegExp wird gegen den Pfad getestet. Passende Seiten erhalten keine Locale-Varianten,
keine Locale-Weiterleitung oder 404 und werden aus dem Prerendering entfernt; sie werden weiterhin mit
Übersetzungen gerendert. `/api`, `/_nuxt`, `/__*`, die Übersetzungsroute und gängige statische Dateien
(Sitemap, robots.txt, Favicon, Assets nach Dateiendung) sind immer ausgeschlossen.

```ts
excludePatterns: ['/admin', '/docs/*', /^\/preview\//],
```

Mehr dazu: [Pfade ausschließen](/de/guide/excluding-static-files).

#### `localizedRouteNamePrefix` {#localizedroutenameprefix}

**Typ** `string` · **Standard** `'localized-'`

Präfix, das lokalisierten Routennamen vorangestellt wird (z. B. `'localized-index'`).
Wird intern verwendet, um ursprüngliche Routen von generierten Locale-Varianten zu unterscheiden.

#### `trailingSlash` {#trailingslash}

**Typ** `'append' \| 'remove'` · **Standard** `undefined (inherit from Nuxt)`

Abschließender Schrägstrich für `$localePath` / `$switchLocalePath` (wie bei NuxtLink).
Standardmäßig `experimental.defaults.nuxtLink.trailingSlash`, wenn nicht gesetzt.
Explizit setzen, um den Link-Standard von Nuxt für die i18n-Pfad-Helfer zu überschreiben.

### Übersetzungen {#translations}

#### `translationDir` {#translationdir}

**Typ** `string` · **Standard** `'locales'`

Pfad zum Verzeichnis mit den JSON-Übersetzungsdateien, relativ zum Projekt-Root.

Relativ zum Root jeder Layer, nicht zu `app/` (`'app/locales'` für ein Nuxt-4-Layout). Dateistruktur: [Übersetzungsdateien](/de/guide/translations).

#### `additionalTranslationDirs` {#additionaltranslationdirs}

**Typ** `string[]` · **Standard** `[]`

Zusätzliche Verzeichnisse (relativ zum Projekt-Root / zum Root jeder Nuxt-Layer), deren `{locale}.json`-Dateien
auf oberster Ebene vor `translationDir` tief in das globale Wörterbuch eingemischt werden.

Merge-Reihenfolge: jeder Eintrag in Array-Reihenfolge (über Layer hinweg), dann `translationDir` (gewinnt bei Konflikten).
Nur `{locale}.json`-Dateien im Root werden gelesen — `pages/` unter diesen Verzeichnissen wird ignoriert.

Beispiel: `translationDir: 'frontend'`, `additionalTranslationDirs: ['common']` → `common/en.json`, dann `frontend/en.json`.

#### `disablePageLocales` {#disablepagelocales}

**Typ** `boolean` · **Standard** `false`

Deaktiviert seitenspezifische Übersetzungsdateien.
Bei `true` werden nur globale Übersetzungen (`{locale}.json`) geladen;
seitenspezifische Dateien (`pages/{page}/{locale}.json`) werden weder generiert noch geladen.

#### `fallbackLocale` {#fallbacklocale}

**Typ** `string` · **Standard** `undefined (no fallback; returns the raw key)`

Globaler Fallback-Locale-Code.
Schlüssel, die in einer Locale fehlen, werden aus dieser Locale übernommen (beim Erstellen oder
Laden in jede Payload eingemischt); ohne sie wird ein fehlender Schlüssel als der Schlüssel selbst gerendert.

#### `routesLocaleLinks` {#routeslocalelinks}

**Typ** `{ [key: string]: string }` · **Standard** `{}`

Ordnet Routennamen anderen Routennamen zu, damit sie dieselben Übersetzungsdateien teilen.
Zum Beispiel bedeutet `{ 'about-us': 'about' }`, dass die Seite `about-us` die
Übersetzungen der Seite `about` statt ihrer eigenen verwendet.

```ts
routesLocaleLinks: { 'products-id': 'products' },
```

#### `plural` {#plural}

**Typ** `PluralFunc` · **Standard** ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)``

Eigene Pluralisierungsfunktion.
Erhält `(key, count, params, locale, getter)` und sollte die gewählte
Pluralform als String zurückgeben, oder `null`/`undefined`, um auf die integrierte
`defaultPlural`-Logik zurückzufallen (so können Sie nur einige Locales überschreiben).

Für das Nuxt-Modul wird die Funktion mit `.toString()` in
`.nuxt/i18n.plural.mjs` serialisiert — sie muss eigenständig sein (keine Imports / kein äußerer Scope).
Ein Dateipfad als String wird **nicht** unterstützt.

Die integrierte Regel und ihre Markierung `=0 ` sind bei [`$tc`](/de/api/methods#$tc) beschrieben. Ihre Funktion ersetzt sie für das, was sie beantwortet, erhält den Rohwert mitsamt einer eventuellen Markierung, und `null` gibt den Aufruf an sie zurück. Die Funktion erhält `(key, count, params, locale, getter)`; `getter(key)` gibt den Roh-String mit allen Formen zurück. Schreiben Sie sie als eigenständige `function` oder als Pfeilfunktionsausdruck (keine Methoden-Kurzschreibweise, keine Imports, keine äußeren Variablen):

```ts
plural: function (key, count, params, locale, getter) {
  if (!locale.startsWith('en')) return null // built-in rule for other locales
  const forms = String(getter(key) ?? '').split('|').map((form) => form.trim())
  const index = count === 0 ? 0 : count === 1 ? 1 : 2
  return (forms[Math.min(index, forms.length - 1)] ?? '').replace('{count}', String(count))
},
```

```json
{ "apples": "no apples | one apple | {count} apples" }
```

### Payloads und Caching {#payloads-and-caching}

#### `translationPayloads` {#translationpayloads}

**Typ** `TranslationPayloadOptions` · **Standard** —

Steuert, wie Übersetzungs-Payloads ausgegeben werden (Node-Server: `public/<apiBaseUrl>`; Edge / Function / Inline: Nitro-`serverAssets`).

- **Node-Server** (`node-server`, `node-cluster`, Festplatten-`serveStatic`): `serverAssets` bedeutet lokales SSR über `readFile` unter `public/` (kein Rollup-`raw:`).
- **Edge, Function-Presets und `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …): `serverAssets` registriert Nitro-`serverAssets` (`assets:i18n`),
  weil `public/` für SSR nicht auf der Festplatte verfügbar ist. Erzwingt keine öffentliche Kopie — setzen Sie `publicAssets: true` für CDN/statisches Hosting.

Behalten Sie die Standardwerte für das übliche All-in-one-Setup bei. Für große Edge-Kataloge `mode: 'source'` bevorzugen.
Für CDN-gestützte Deployments lokale Ausgaben deaktivieren und `apiBaseClientHost` / `apiBaseServerHost` setzen.

Die Unteroptionen stehen in der Tabelle [Payloads und Caching](#payloads-and-caching). Welche Kombination zu Node, Serverless, Edge, statischem Hosting oder einem CDN passt: [Deployment](/de/guide/deployment).

#### `apiBaseUrl` {#apibaseurl}

**Typ** `string` · **Standard** `'_locales'`

Basis-URL-Pfadsegment für die API-Route der Übersetzungen (verwendet beim Datenabruf in SSR/SSG).
Kann auch über die Umgebungsvariable `NUXT_I18N_APP_BASE_URL` gesetzt werden.

Payload-URLs sind `/{apiBaseUrl}/{page}/{locale}/data.json`.

#### `apiBaseClientHost` {#apibaseclienthost}

**Typ** `string` · **Standard** `undefined`

Überschreibt den Host für clientseitige Abrufe von Übersetzungen.
Nützlich, wenn der Client den Server über einen anderen Hostnamen erreicht als den, den Nuxt sieht.
Kann auch über die Umgebungsvariable `NUXT_I18N_APP_BASE_CLIENT_HOST` gesetzt werden.

#### `apiBaseServerHost` {#apibaseserverhost}

**Typ** `string` · **Standard** `undefined`

Überschreibt den Host für serverseitige Abrufe von Übersetzungen.
Nützlich in Container-/Microservice-Setups, in denen der Server sich selbst über einen internen Hostnamen erreicht.
Kann auch über die Umgebungsvariable `NUXT_I18N_APP_BASE_SERVER_HOST` gesetzt werden.

Ein Host muss dieselben `/{apiBaseUrl}/{page}/{locale}/data.json`-Antworten liefern wie die integrierte Route.

#### `dateBuild` {#datebuild}

**Typ** `string \| number` · **Standard** —

Wert für das Cache-Busting von Übersetzungsanfragen (`?v=...`).

Wenn nicht angegeben, verwendet das Modul einen Hash der Übersetzungsdateien, sodass sich der Wert
nur ändert, wenn sich Übersetzungen ändern (`Date.now()`, wenn kein Hash berechnet werden kann). `0` oder `''` schaltet
das Cache-Busting ab. Setzen Sie einen stabilen Wert (einen Git-SHA, eine Build-Nummer), um ihn selbst festzulegen.
`NUXT_I18N_DATE_BUILD` oder `runtimeConfig.public.i18nRuntime.dateBuild` ersetzt ihn zur Laufzeit, nachdem ein Wörterbuch
an Ort und Stelle ersetzt wurde: Festgehaltene URLs bleiben zurück, ohne Rebuild.

#### `httpCacheDuration` {#httpcacheduration}

**Typ** `number` · **Standard** `31536000`

HTTP-`Cache-Control`-max-age (Sekunden) für `/{apiBaseUrl}/:page/:locale/data.json`.

Gilt nur vollständig, solange `dateBuild` die URL per Cache-Busting versioniert (`?v=...`), was der Standard ist:
Die Antwort ist dann `private, max-age=…, immutable`: Ein Browser hält sie fest, ein CDN, das die Query ignoriert, kann das nicht
(`public` mit `httpCacheControl: false`).

- `dateBuild: 0`/`''` — die URL ist stabil, daher wird diese Dauer *nicht* berücksichtigt; die
  Antwort wird stattdessen `public, max-age=0, must-revalidate`. Ein langes `max-age` auf einer
  unveränderlichen URL hält die erste Payload fest, die ein Browser je gesehen hat.

- `0` — `Cache-Control` überhaupt nicht setzen (nützlich beim lokalen Debugging)
- Wird in der Entwicklung (`import.meta.dev`) nicht angewendet, damit der Browser-Cache HMR nicht behindert
- Erreicht nur Antworten, die über Nitro ausgeliefert werden. Payloads, die nach `public/` kopiert und
  von der Hosting-Plattform ausgeliefert werden, erhalten deren Header — siehe den Performance-Leitfaden.

Analog zu `httpCacheDuration` aus `@nuxtjs/i18n` experimental (v10.2.0), aber als
expliziter Antwort-Header statt als maxAge von Nitros `defineCachedEventHandler`.

#### `cacheMaxSize` {#cachemaxsize}

**Typ** `number` · **Standard** `0`

Maximale Anzahl Einträge in den In-Memory-Übersetzungscaches. Die Fetch- und Server-Caches
verwerfen den am längsten nicht verwendeten Eintrag; die Wörterbuch-Map des Browsers verwirft den ältesten (FIFO).
`0` bedeutet kein Limit im Browser; Server-Caches behalten dann höchstens 1000 Einträge, damit Anfrage-URLs
mit erfundenen Seiten den Serverspeicher nicht wachsen lassen können.

#### `cacheTtl` {#cachettl}

**Typ** `number` · **Standard** `0`

Lebensdauer (in Sekunden) der Fetch- und Server-Übersetzungscaches, gezählt ab dem Speichern eines
Eintrags (Lesezugriffe verlängern sie nicht), sodass Daten von `apiBaseServerHost` mindestens
so oft aktualisiert werden. Die aktiven Wörterbücher des Browsers laufen dadurch nicht ab. `0` bedeutet, dass Einträge
nie ablaufen.

Was beide zur Laufzeit ändern: [Performance](/de/guide/performance).

#### `serverTranslationPreload` {#servertranslationpreload}

**Typ** `boolean` · **Standard** `false`

Lädt die Übersetzungen der Index-Seite in der globalen Nitro-Middleware vor (nur Server, private Konfiguration).

### SEO {#seo}

#### `meta` {#meta}

**Typ** `boolean` · **Standard** `true`

Generiert SEO-Meta-Tags (`hreflang`, `canonical`, `og:url`, `og:locale`) automatisch.

Überschreibungen pro Seite: [`useI18nHead`](/de/composables/useI18nHead). Alles andere: [SEO](/de/guide/seo).

#### `metaBaseUrl` {#metabaseurl}

**Typ** `string` · **Standard** `undefined`

Basis-URL für SEO-Meta-Tags (canonical, og:url, hreflang).

- Ein konkreter URL-String (z. B. `'https://example.com'`) — wird unverändert verwendet (höchste Priorität).
- `undefined` — fällt auf `site.url` aus `nuxt-site-config` zurück, wenn dieses Modul
  vorhanden ist, andernfalls auf den Origin der aktuellen Anfrage
  (`useRequestURL().origin` auf dem Server, `window.location.origin` auf dem Client).

#### `metaTrustForwardedHost` {#metatrustforwardedhost}

**Typ** `boolean` · **Standard** `true`

Vertraut beim Auflösen der Basis-URL für Meta-Tags dem Header `X-Forwarded-Host`.
Aktivieren, wenn die App hinter einem Reverse-Proxy (nginx, Cloudflare, AWS ALB usw.) läuft,
der diesen Header auf den echten, für Clients sichtbaren Hostnamen setzt.

Wird nur gelesen, wenn weder `metaBaseUrl` noch `site.url` gesetzt ist. Setzen Sie es auf `false`, wenn die App ohne einen Proxy erreichbar ist, der den Header überschreibt: Ein Client könnte sonst den Host in Ihren kanonischen URLs bestimmen.

#### `metaTrustForwardedProto` {#metatrustforwardedproto}

**Typ** `boolean` · **Standard** `true`

Vertraut beim Auflösen des Protokolls für Meta-Tags dem Header `X-Forwarded-Proto`.
Aktivieren, wenn die App hinter einem TLS-terminierenden Proxy läuft, damit
kanonische URLs `https://` verwenden, obwohl die App selbst über HTTP lauscht.

Gleicher Geltungsbereich wie `metaTrustForwardedHost`.

#### `trustForwardedHost` {#trustforwardedhost}

**Typ** `boolean` · **Standard** `false`

Bestimmt die Domain einer Anfrage (`locales[].baseUrl`) aus `X-Forwarded-Host` statt aus
`Host`. Aktivieren Sie dies nur hinter einem Proxy, der diesen Header überschreibt.

Getrennt von `metaTrustForwardedHost` und standardmäßig deaktiviert: Hier würde der Header die Locales einer anderen Domain auswählen, nicht nur den Origin eines Tags. Siehe [Layer und Domains](/de/guide/layers#multiple-domains).

#### `hreflangBaseLanguage` {#hreflangbaselanguage}

**Typ** `boolean` · **Standard** `false`

Gibt zusätzlich ein `hreflang` nur mit der Sprache aus, abgeleitet aus dem `iso` jeder Locale
(z. B. `es-ES` → zusätzlich `es`). Die erste regionale Locale in `locales` beansprucht
das reine Sprach-Tag für diese Sprache. Der Routing-`code` wird nie verwendet — nur `iso || code`.

#### `canonicalQueryWhitelist` {#canonicalquerywhitelist}

**Typ** `string[]` · **Standard** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

Liste der Query-Parameter-Namen, die in den Meta-Tags canonical und `og:url` erhalten bleiben.
Parameter, die nicht in dieser Liste stehen, werden aus der kanonischen URL entfernt.

### Erkennung und Weiterleitungen {#detection-and-redirects}

Die Regeln, in die diese Optionen einfließen: [Locale-Erkennung](/de/guide/locale-detection).

#### `redirects` {#redirects}

**Typ** `boolean` · **Standard** `true`

Aktiviert automatische Locale-Weiterleitungen (Server-Plugin und clientseitige Routen-Middleware).
Bei `true` leiten die Präfix-Strategien eine URL ohne Präfix auf ihre lokalisierte Form weiter. Die Locale
stammt aus dem App-Zustand, dem Cookie oder `Accept-Language`, wo `autoDetectPath` es erlaubt, andernfalls
aus dem Standard. Unter `no_prefix` ändert die Erkennung nie die URL (siehe `noPrefixRedirect` für eigene Pfade).

Bei `false` wird die clientseitige Weiterleitungs-Middleware nicht registriert. Das Server-Plugin gibt für ungültige Locale-URLs weiterhin 404 zurück und schreibt das Cookie für eine URL mit Präfix.

#### `autoDetectLanguage` {#autodetectlanguage}

**Typ** `boolean` · **Standard** `true`

Erkennt die bevorzugte Sprache des Benutzers automatisch aus dem HTTP-Header `Accept-Language`.
Wird zusammen mit `autoDetectPath` verwendet, um zu entscheiden, wann die Erkennung stattfindet.

#### `autoDetectPath` {#autodetectpath}

**Typ** `string` · **Standard** `'/'`

Wo Weiterleitungen nach Cookie- / Accept-Language-Präferenz ausgeführt werden dürfen (wenn `redirects` aktiviert ist).

- `'/'` — nur `/` (Deep Links in der Standard-Locale bleiben erreichbar; Standard)
- `'no_prefix'` — nur Pfade ohne Locale-Präfix
- `'*'` — jeder Pfad, einschließlich des Umschreibens eines expliziten Locale-Präfixes
  (z. B. `/fr/about` → `/de/about`, wenn das Cookie `de` bevorzugt)

- jeder andere String — genau dieser Pfad, abschließende Schrägstriche werden ignoriert (z. B. `'/welcome'`)

Unter `prefix` leitet eine URL ohne Präfix außerhalb der erlaubten Pfade weiterhin auf die Form der
Standard-Locale weiter (`/about` → `/en/about`). Die Standard-Locale mit Präfix unter
`prefix_except_default` (`/en`) ist ein 404, keine Weiterleitung.

#### `localeCookie` {#localecookie}

**Typ** `string \| null` · **Standard** `null`

Cookie-Name, um die Locale-Präferenz des Benutzers über Sitzungen hinweg zu speichern.
Auf `null` setzen, um die Cookie-basierte Speicherung zu deaktivieren.
Wird bei der Strategie `no_prefix` automatisch auf `'user-locale'` gesetzt, wenn nichts angegeben ist; ein explizites
`null` im `i18n`-Konfigurationsblock hält es auch dort deaktiviert.

Ohne Cookie steuert weiterhin `Accept-Language` die Weiterleitungen; das Cookie merkt sich eine Auswahl über Besuche hinweg.

#### `noPrefixRedirect` {#noprefixredirect}

**Typ** `boolean` · **Standard** `false`

Für die Strategie `no_prefix`: Wenn die Standard-Locale für eine Seite einen eigenen Pfad hat
(`localeRoutes` / `globalLocaleRoutes`), wird der ursprüngliche Pfad der Seite auf den eigenen
Pfad der Locale des Besuchers weitergeleitet, andernfalls auf den der Standard-Locale (z. B. `/about` → `/about-us`).
Eine Locale ohne eigenen Pfad bleibt auf dem ursprünglichen Pfad. Seiten mit dynamischen
Segmenten werden nicht weitergeleitet.

### Registrierung und Entwicklung {#registration-and-development}

#### `plugin` {#plugin}

**Typ** `boolean` · **Standard** `true`

Registriert das zentrale i18n-Plugin, das `$t()`, `$tc()`, `$getLocale()`,
`$switchLocale()` und weitere Laufzeit-Helfer bereitstellt.

#### `define` {#define}

**Typ** `boolean` · **Standard** `true`

Stellt `$defineI18nRoute()` zur Laufzeit bereit. Der Build liest `$defineI18nRoute()`-Aufrufe in Seiten
in jedem Fall.

#### `hooks` {#hooks}

**Typ** `boolean` · **Standard** `true`

Ruft den App-Hook `i18n:register` beim Laden und bei der Navigation auf, damit Plugins Übersetzungen hinzufügen können.

Siehe [Hooks](/de/api/events).

#### `components` {#components}

**Typ** `boolean` · **Standard** `true`

Registriert die integrierten i18n-Komponenten (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`).
Auf `false` setzen, um die automatische Registrierung der Komponenten zu deaktivieren (z. B. wenn Sie sie nicht verwenden
und den Umfang des Moduls verringern möchten).

#### `types` {#types}

**Typ** `boolean` · **Standard** `true`

Generiert TypeScript-Typdeklarationen für `useI18n`, `$t` und verwandte Helfer
auf Basis der Übersetzungsschlüssel in den Dateien Ihrer Standard-Locale.

Getrennt vom Paket [`@i18n-micro/types-generator`](/de/integrations/types-generator).

#### `hmr` {#hmr}

**Typ** `boolean` · **Standard** `true`

Aktiviert Hot Module Replacement für Übersetzungsdateien in der Entwicklung.
Bei `true` lösen Änderungen an JSON-Übersetzungsdateien ein automatisches Neuladen
ohne vollständige Seitenaktualisierung aus.

#### `debug` {#debug}

**Typ** `boolean` · **Standard** `false`

Aktiviert ausführliches Debug-Logging für Locale-Erkennung, Routengenerierung und das Laden von Übersetzungen.

#### `vueDevtools` {#vuedevtools}

**Typ** `boolean` · **Standard** `true`

Registriert in der Entwicklung Inspector und Timeline in Vue DevTools (Browsererweiterung).
Getrennt vom eigenen Tab in Nuxt DevTools.

#### `experimental` {#experimental}

**Typ** `Record<string, unknown>` · **Standard** —

Sammelbecken für experimentelle/instabile Optionen.
Der Inhalt kann sich zwischen Minor-Versionen ohne Ankündigung ändern oder entfernt werden.
