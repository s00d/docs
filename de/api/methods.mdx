---
title: "Helfer"
description: "Jeder Laufzeit-Helfer, den das Modul injiziert – `$t`, `$tc`, `$localePath`, `$switchLocale` und die übrigen – mit seiner Signatur."
---

Das Modul injiziert seine Laufzeit-Helfer in die Nuxt-App: `$t`, `$tc`, `$localePath`, `$switchLocale` und die übrigen. Auf dieser Seite schlägst du die Signatur und das Verhalten eines Helfers nach. Signaturen und Beschreibungen stammen aus den Interfaces `PluginsInjections` und `NuxtAppOnlyInjections` in `src/runtime/plugins/01.plugin.ts`.

## Zugriff {#access}

| Wo | Wie |
| --- | --- |
| Template | `{{ $t('title') }}` – jeder Helfer, mit dem `$` |
| `<script setup>` | `const { t, localePath } = useI18n()` – jeder Helfer aus `PluginsInjections`, mit und ohne `$` |
| Plugin, Middleware, `<script setup>` | `const { $t, $defineI18nRoute } = useNuxtApp()` – alles, nur mit `$` |

`$defineI18nRoute` ist nur auf `useNuxtApp()` typisiert. Siehe [`useI18n`](/de/composables/useI18n).

```vue
<script setup lang="ts">
const { t, localePath } = useI18n()
</script>

<template>
  <NuxtLink :to="localePath('/about')">{{ t('nav.about') }}</NuxtLink>
</template>
```

## Locale {#locale}

### `$getLocale` {#$getlocale}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric) => string
```

Code der aktiven Locale. Übergib eine Route, um die Locale zu lesen, zu der diese Route gehört.

```ts
$getLocale() // 'de' on /de/about
```

### `$getLocaleName` {#$getlocalename}

```ts
() => string | null
```

Der `displayName` der aktiven Locale aus der Konfiguration oder `null`, wenn sie keinen hat.

### `$getLocales` {#$getlocales}

```ts
() => Locale[]
```

Alle konfigurierten Locales mit ihren Metadaten.

Eigene Eigenschaften eines Locale-Objekts kommen so zurück, wie sie geschrieben wurden; typisiere sie per [Module Augmentation](/de/api/module-options#locales) von `Locale`.

### `$defaultLocale` {#$defaultlocale}

```ts
() => string | undefined
```

Code der konfigurierten Standard-Locale.

### `$getI18nConfig` {#$geti18nconfig}

```ts
() => ResolvedI18nConfig
```

Die aufgelöste Modulkonfiguration, wie die Laufzeit sie sieht.

Der Wert enthält [Laufzeit-Überschreibungen](/de/guide/runtime-overrides) (`defaultLocale`, `fallbackLocale`, deaktivierte Locales).

```ts
const { strategy, localeCookie } = useNuxtApp().$getI18nConfig()
```

## Übersetzung {#translation}

### `$t` {#$t}

```ts
TranslationFn<CleanTranslation>
```

Übersetzt einen Schlüssel und interpoliert `params` hinein. Gibt `defaultValue` zurück, wenn der Schlüssel
fehlt, oder den Schlüssel selbst, wenn kein Standardwert angegeben ist.

```ts
// { "welcome": "Welcome, {name}!" }
$t('welcome', { name: 'Ada' }) // 'Welcome, Ada!'
$t('missing.key', {}, 'Fallback') // 'Fallback'
```

Ein Schlüssel, der auf ein verschachteltes Objekt zeigt, gibt dieses Objekt zurück, keinen String. In einem Template wird es als `[object Object]` gerendert; verwende einen Blattschlüssel.

### `$ts` {#$ts}

```ts
TranslationFn<string>
```

Wie `$t`, gibt aber immer einen String zurück: Der Wert durchläuft `toString()`, sodass ein verschachteltes
Objekt zu `'[object Object]'` wird. Lass den Schlüssel auf ein Blatt zeigen.

### `$_t` {#$_t}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<CleanTranslation>
```

Bindet `$t` an eine bestimmte Route, um außerhalb der aktuellen Seite zu übersetzen – zum Beispiel in einem Layout,
das einen Link zu einer anderen Route rendert.

```ts
const route = useRoute()
const t = useNuxtApp().$_t(route)
t('page.title')
```

### `$_ts` {#$_ts}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<string>
```

Bindet `$ts` an eine bestimmte Route. Siehe `$_t`.

### `$tc` {#$tc}

```ts
(key: TranslationKey, params: number | Params, defaultValue?: string) => string
```

Übersetzt mit Pluralisierung. `params` kann die Anzahl selbst sein oder ein Objekt, das
`count` enthält.

Formen werden durch `|` getrennt. Mit der eingebauten Regel wählt eine nicht negative ganzzahlige Anzahl `n` die Form `n`, begrenzt auf die letzte Form; eine negative, gebrochene oder `NaN`-Anzahl nimmt die letzte Form. `{count}` und die übrigen Parameter werden in die gewählte Form interpoliert.

Für Sprachen, deren Pluralformen nicht der Anzahl folgen, beginne das Template mit `=0 `. Die erste Form gilt dann für 0, und die übrigen richten sich nach der [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules)-Kategorie in der Reihenfolge `zero, one, two, few, many, other`:

```json
{
  "apples": "=0 no apples | one apple | {count} apples",
  "files": "=0 no files | {count} one | {count} few | {count} many"
}
```

```ts
$tc('apples', 0) // 'no apples'
$tc('apples', 1) // 'one apple'
$tc('apples', 7) // '7 apples'

// In `uk` (categories `one, few, many, other`) the forms after the zero form follow those categories:
$tc('files', 21) // '21 one'
$tc('files', 22) // '22 few'
$tc('files', 25) // '25 many'
$tc('files', 2.5) // '2.5 many': no form for `other`, so the last one
```

- `=0 ` zählt nur ganz am Anfang des Werts, mit dem Leerzeichen. `$t` zeigt es als Text an: Es gehört zu den Pluralformen.
- Eine Kategorie ohne eigene Form nimmt die letzte Form. Eine negative oder gebrochene Anzahl nimmt ebenfalls die letzte Form.
- Es funktioniert in jeder Locale: `=0 none | one | {count} many` auf Englisch.
- Die Kategorie ergibt sich aus dem `iso` der Locale, sonst aus ihrem Code. Ein Code, den `Intl` nicht kennt, fällt auf die Indexregel zurück, wobei der Marker trotzdem entfernt wird, sodass das Ergebnis nie von der Maschine abhängt.
- `<i18n-t :plural>` folgt derselben Regel. Ein eigenes [`plural`](/de/api/module-options#plural) oder `customPluralRule` erhält den Rohwert inklusive Marker und entscheidet selbst; gibt `plural` `null` zurück, wird der Aufruf an die eingebaute Regel zurückgegeben, die den Marker berücksichtigt.

Ohne den Marker bleibt ein Template bei der Indexregel, mit einer Ausnahme, die sich nur auf eine Weise lesen lässt: eine Null-Form ohne Platzhalter, dann eine Form pro Kategorie, mit `{count}` in jeder Form, die sich mehrere Anzahlen teilen (`no files | {count} one | {count} few | {count} many` in `uk`).

Für eigene Regeln setze [`plural`](/de/api/module-options#plural).

```ts
// { "apples": "no apples | one apple | {count} apples" }
$tc('apples', 0) // 'no apples'
$tc('apples', 10) // '10 apples'
$tc('cart', { count: 2, name: 'Ada' }) // count and params in one object
```

Das dritte Argument ist `defaultValue`, nicht params.

### `$has` {#$has}

```ts
(key: string) => boolean
```

Ob ein Schlüssel in der aktiven Locale aufgelöst wird. Verwende es, um bei optionalem Text zu verzweigen, statt
einen rohen Schlüssel zu rendern. Wie `$t` sieht es während eines Seitenübergangs innerhalb derselben Locale auch
die Schlüssel der verlassenen Seite.

```ts
if ($has('promo.banner')) show.value = true
```

## Formatierung {#formatting}

### `$tn` {#$tn}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

Formatiert eine Zahl mit `Intl.NumberFormat` in der aktiven Locale. Ein Schlüssel wählt ein benanntes Format
aus der Konfiguration.

Benannte Formate stammen aus [`numberFormats`](/de/api/module-options#numberformats).

```ts
$tn(1234.5, { style: 'currency', currency: 'EUR' }) // '1.234,50 €' in de
$tn(1000, 'currency') // named format
$tn(1000, 'currency', 'de') // named format in another locale
```

### `$td` {#$td}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

Formatiert ein Datum mit `Intl.DateTimeFormat` in der aktiven Locale. Ein Schlüssel wählt ein benanntes Format
aus der Konfiguration.

Benannte Formate stammen aus [`datetimeFormats`](/de/api/module-options#datetimeformats).

```ts
$td(new Date(), { dateStyle: 'long' })
$td(post.createdAt, 'short')
```

### `$tdr` {#$tdr}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

Formatiert ein Datum als relative Zeit („vor 3 Tagen“) mit `Intl.RelativeTimeFormat`.

```ts
$tdr(Date.now() - 5 * 60_000) // '5 minutes ago' in en
```

## Wechseln und Links {#switching-and-links}

### `$switchLocale` {#$switchlocale}

```ts
(locale: string) => Promise<boolean>
```

Navigiert zur aktuellen Seite in einer anderen Locale. Unter `no_prefix` und im Hash-Modus lädt es die
Übersetzungen der Locale vor dem Navigieren; unter `no_prefix` wird die Route an Ort und Stelle ersetzt (kein
neuer History-Eintrag). Eine unbekannte Locale wird ignoriert.
Der Aufruf ist asynchron: Verwende `await`, um Code nach der Navigation auszuführen. Er wird mit `true` aufgelöst, wenn das
Wörterbuch der Locale aktiv ist, mit `false`, wenn nicht: Der Chunk konnte nicht geladen werden (das aktuelle
Wörterbuch bleibt; rufe ihn erneut auf, um es nochmal zu versuchen) oder ein neuerer Wechsel hat gewonnen.

```ts
await $switchLocale('de')
```

### `$switchLocalePath` {#$switchlocalepath}

```ts
(locale: string) => string
```

Der Pfad der aktuellen Seite in einer anderen Locale, ohne zu navigieren.

```vue
<NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
```

### `$switchLocaleRoute` {#$switchlocaleroute}

```ts
(locale: string) => RouteLocationRaw
```

Das Routenobjekt der aktuellen Seite in einer anderen Locale, ohne zu navigieren, oder ein URL-String
für eine Locale mit eigener `baseUrl`. Unter `trailingSlash` hat das Objekt `path` und `fullPath`
gemäß der Regel, mit `query` und `hash` unverändert, und `router.push` oder ein Link behalten sie bei.

### `$switchRoute` {#$switchroute}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => Promise<void>
```

Navigiert zu einer anderen Route und behält die aktive Locale bei oder wechselt zu `toLocale`. Asynchron wie
`$switchLocale`.

```ts
$switchRoute('/about') // active locale
$switchRoute({ name: 'about' }, 'de') // switch to de
```

### `$localePath` {#$localepath}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => string
```

Löst einen Pfad in der angegebenen oder der aktiven Locale auf. Ein String mit einem `http(s):`-, `mailto:`-
oder `tel:`-Schema wird unverändert zurückgegeben: Übergib Benutzereingaben nicht ungeprüft als Linkziel.

Ein String-Pfad wird als die Seite gelesen, die er anzeigt, sodass auch ein eigener Pfad der Locale angewendet wird.

```ts
$localePath('/about') // '/about' in en, '/de/ueber-uns' in de with localeRoutes
$localePath({ name: 'about' }, 'fr') // '/fr/about'
```

### `$localeRoute` {#$localeroute}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => RouteLocationResolved
```

Löst eine Route in der angegebenen oder der aktiven Locale auf. Ein einfaches Objekt, das sicher im State gehalten werden kann. Wenn ein Parameter
escaped werden muss, hat es `path`, `fullPath`, `query` und `hash`, aber kein `name` oder `params`: Der Pfad liefert dem Router
die kodierte URL. Für eine Locale auf einer anderen Domain sind `path` und `fullPath` absolut, was der Router nicht annehmen kann:
Ein solcher Link läuft über `<i18n-link>` oder `$localePath`.

### `$getRouteName` {#$getroutename}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric, locale?: string) => string
```

Routenname ohne Locale-Präfix – der Name, unter dem Übersetzungen abgelegt sind.

```ts
$getRouteName() // 'about' on /de/about
```

## Seitenkonfiguration {#page-config}

### `$defineI18nRoute` {#$definei18nroute}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

Registriert Locale-Konfiguration und Übersetzungen pro Seite aus einer Komponente heraus.
Führt sie in die aktive Locale zusammen und wendet sie erneut an, wenn sich die Locale ändert.

Rufe es im `<script setup>` einer Seite auf, immer destrukturiert aus `useNuxtApp()`. Der Build liest `locales`, `localeRoutes` und `disableMeta` aus dem Aufruf; zur Laufzeit zählt nur `locales` (Inline-Übersetzungen werden für die aktive Locale zusammengeführt). Vollständige Regeln: [Seitenkonfiguration](/de/guide/per-component-translations).

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: { en: '/about', de: '/ueber-uns' },
})
</script>
```

### `$setI18nRouteParams` {#$seti18nrouteparams}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

Setzt Parameter pro Locale für die aktuelle Route, damit sich ein dynamisches Segment je Sprache unterscheiden kann.
Rufe es während des SSR auf, bevor der Head gerendert wird.

Die Parameter werden gelöscht, wenn eine Navigation zu einem anderen Pfad abgeschlossen wird, auch von `/news/1` zu `/news/4`, wobei der Routenname gleich bleibt. Details: [Lokalisierte Pfade](/de/guide/custom-locale-routes).

```ts
$setI18nRouteParams({
  en: { slug: 'my-post' },
  de: { slug: 'mein-beitrag' },
})
```

## Laufzeit-Übersetzungen {#runtime-translations}

### `$mergeTranslations` {#$mergetranslations}

```ts
(newTranslations: Translations) => void
```

Führt zur Laufzeit Übersetzungen in die aktive Locale zusammen und überschreibt dabei Geladenes.

Führt einen Deep-Merge in den aktuellen Seiten-Chunk der aktiven Locale durch; Schlüssel, die nicht erwähnt werden, bleiben erhalten.

```ts
$mergeTranslations({ banner: { title: 'Sale' } })
```

### `$setTranslation` {#$settranslation}

```ts
(key: string, value: unknown) => void
```

Ersetzt den Wert unter `key` im aktiven Wörterbuch. Das ist ein Ersetzen, kein Zusammenführen –
verwende `$mergeTranslations`, wenn vorhandene Geschwister erhalten bleiben sollen.

```ts
$setTranslation('banner', { title: 'Sale' }) // drops other keys under banner
$setTranslation('banner.title', 'Sale') // dotted path
```

### `$loadPageTranslations` {#$loadpagetranslations}

```ts
(locale: string, routeName: string, translations: Translations) => Promise<void>
```

Lädt Übersetzungen für eine Seite zur Laufzeit, für Inhalte, deren Schlüssel beim Build nicht bekannt sind.

Führt sie in den `(locale, routeName)`-Chunk im Speicher zusammen, und die Anzeige aktualisiert sich, wenn dieser Chunk aktiv ist. Hier wird kein Payload abgerufen: Für eine noch nicht geladene Seite warten die Übersetzungen, und wenn ihre Datei geladen wird, bleiben sie darüber.

```ts
await $loadPageTranslations('en', 'about', { title: 'About us' })
```

### `$resolveTranslations` {#$resolvetranslations}

```ts
() => Translations
```

Alle aktuell im Speicher befindlichen Übersetzungen für die aktive Locale und Route, als Baum.
Schreibgeschützte Ansicht dessen, was `$t()` gerade auflösen kann.

Behandle das Ergebnis als schreibgeschützt.

### `$setMissingHandler` {#$setmissinghandler}

```ts
(handler: MissingHandler | null) => void
```

Installiert einen Callback, der für jeden nicht aufgelösten Schlüssel aufgerufen wird. Übergib `null`, um ihn zu entfernen.

Der Handler läuft anstelle der Dev-Warnung.

```ts
$setMissingHandler((locale, key, routeName) => {
  console.error(`[i18n] missing ${key} in ${locale} (${routeName})`)
})
```

### `$clearCache` {#$clearcache}

```ts
() => void
```

Verwirft alle gecachten Übersetzungs-Chunks und lädt das Wörterbuch der aktuellen Seite neu. Die Seite
zeigt weiterhin ihre aktuellen Übersetzungen, bis die neuen eintreffen. Dev-HMR ruft es bei
jeder Änderung an einer Übersetzungsdatei auf.

```ts
const { clearCache } = useI18n()
clearCache()
```

Ein fehlgeschlagenes Neuladen behält das aktuelle Wörterbuch bei.
