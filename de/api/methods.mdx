### `$getI18nConfig`

{/* generated:method:$getI18nConfig — do not edit; run `pnpm run docs:generate` */}

```ts
() => ModuleOptionsExtend
```

Die aufgelöste Modulkonfiguration, wie sie zur Laufzeit sichtbar ist.

{/* /generated:method:$getI18nConfig */}

```typescript
const nuxtApp = useNuxtApp()
const { localeCookie, strategy, hooks } = nuxtApp.$getI18nConfig()
```

In Build-Zeit- oder Nicht-Nuxt-Kontexten nutzt du stattdessen `getI18nConfig()` aus `#build/i18n.strategy.mjs`.

<Info>
`serverTranslationPreload` ist eine private Modul-Option, die nur in der privaten Server-Config (`#i18n-internal/config`) verfügbar ist. Sie gehört nicht zur öffentlichen Runtime-API und kann sich ohne Vorankündigung ändern.
</Info>

## 🔍 Übersetzungsmethoden

Kernmethoden zum Abrufen und Verwalten von Übersetzungen.

### `$t`

{/* generated:method:$t — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params?: Params, defaultValue?: string | null) => CleanTranslation
```

Übersetzt einen Schlüssel und interpoliert `params`. Gibt `defaultValue` zurück, wenn der Schlüssel fehlt, oder den Schlüssel selbst, wenn kein Default angegeben ist.

{/* /generated:method:$t */}

```typescript
const welcomeMessage = $t('welcome', { username: 'Alice', unreadCount: 5 })
// Output: "Welcome, Alice! You have 5 unread messages."
```

<Warning>
`$t` liefert `CleanTranslation`, also `string | number | boolean | Translations | PluralTranslations | null`. Verweist der Schlüssel in deinem JSON auf ein **verschachteltes Objekt** (zum Beispiel `$t('header')`, wenn das JSON `\{ "header": \{ "title": "Hi" \} \}` enthält), ist der Rückgabewert dieses **Objekt**, kein String. Direkt in einem Vue-Template genutzt (<code v-pre>\{\{ $t('header') \}\}</code>) rendert es als `[object Object]`.

**So vermeidest du das:**

- Nutze einen spezifischeren Schlüssel: `$t('header.title')` → `"Hi"`
- Nutze `$ts()`, das immer einen String liefert (ruft `.toString()` auf Nicht-Strings auf).
- Nutze `$t` mit einem verschachtelten Schlüssel, wenn du gezielt Unterobjekte für die programmatische Verwendung willst.
</Warning>

### `$ts`

{/* generated:method:$ts — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params?: Params, defaultValue?: string) => string
```

Wie `$t`, gibt aber immer einen String zurück: Objekt- oder Array-Werte werden zu einem String konvertiert statt unverändert übergeben.

{/* /generated:method:$ts */}

```typescript
const welcomeMessage = $ts('welcome', { username: 'Alice', unreadCount: 5 })
// Output: "Welcome, Alice! You have 5 unread messages."
```

### `$_t` und `$_ts`

{/* generated:method:$_t — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNormalizedLoaded) => (key: string, params?: Params, defaultValue?: string | null) => CleanTranslation
```

Bindet `$t` an eine bestimmte Route, um außerhalb der aktuellen Seite zu übersetzen. Zum Beispiel in einem Layout, das einen Link zu einer anderen Route rendert.

{/* /generated:method:$_t */}

{/* generated:method:$_ts — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNormalizedLoaded) => (key: string, params?: Params, defaultValue?: string | null) => string
```

Bindet `$ts` an eine bestimmte Route. Siehe `$_t`.

{/* /generated:method:$_ts */}

Route-gebundene Varianten von `$t` und `$ts`. Sie nehmen zuerst eine **Route** und liefern eine Übersetzungsfunktion, die auf die Locale und den Seitenkontext dieser Route festgelegt ist.

- **Zugriff**: `useNuxtApp()` (auch von `useI18n()` als `$_t`/`$_ts` re-exportiert)

Verwende sie, wenn die aktive Route bei SSR oder Übergängen von `router.currentRoute` abweicht. Zum Beispiel innerhalb von `<i18n-t>`, `<i18n-group>` oder beim Rendern von Inhalten für ein bestimmtes `route`-Objekt.

```typescript
import { useRoute, useNuxtApp } from '#imports'

const route = useRoute()
const { $_t, $_ts } = useNuxtApp()

const $t = $_t(route)
const title = $t('page.title')

// String-safe variant
const label = $_ts(route)('page.label')
```


### `$tc`

{/* generated:method:$tc — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params: number | Params, defaultValue?: string) => string
```

Übersetzt mit Pluralisierung. `params` kann direkt der Zähler sein oder ein Objekt mit `count`.

{/* /generated:method:$tc */}

**Übersetzungsformat**: Formen werden durch `|` getrennt. Platzhalter kommen in **jede** Form:

```json
{
  "apples": "no apples | one apple | {count} apples",
  "cart": "no items for {name} | one item for {name} | {count} items for {name}"
}
```

```typescript
$tc('apples', 0) // "no apples"
$tc('apples', 1) // "one apple"
$tc('apples', 10) // "10 apples"

// count + other params (second argument must be an object)
$tc('cart', { count: 10, name: 'Alice' }) // "10 items for Alice"
```


**Komponenten-Alternative**: `<i18n-t keypath="cart" :plural="count" :params="\{ name \}" />` (mischt `count` intern mit `params`).


### `$mergeTranslations`

{/* generated:method:$mergeTranslations — do not edit; run `pnpm run docs:generate` */}

```ts
(newTranslations: Translations) => void
```

Mischt Übersetzungen zur Laufzeit in die aktive Locale und überschreibt Geladenes.

{/* /generated:method:$mergeTranslations */}

```typescript
$mergeTranslations({
  welcome: 'Bienvenue, {username}!',
})
// Output: Updates the translation cache with the new French translation
```

### `$resolveTranslations`

{/* generated:method:$resolveTranslations — do not edit; run `pnpm run docs:generate` */}

```ts
() => Translations
```

Alle aktuell im Speicher gehaltenen Übersetzungen für aktive Locale und Route als Baum.
Read-only-Sicht auf das, was `$t()` gerade auflösen kann.

{/* /generated:method:$resolveTranslations */}

```typescript
const tree = $resolveTranslations()
// { aaa: { bbb: 'ccc' }, ddd: 1111 } — the same dictionary $t() reads from
```

Verwende das, wenn du das komplette In-Memory-Wörterbuch brauchst (DevTools, Tests, Runtime-Editoren). Behandle den Rückgabewert als schreibgeschützt. Ändere Werte über `$setTranslation` oder mische Patches per `$mergeTranslations` ein.

### `$setTranslation`

{/* generated:method:$setTranslation — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, value: unknown) => void
```

Ersetzt den Wert bei `key` im aktiven Wörterbuch. Das ist ein Ersetzen, kein Mergen. Nutze `$mergeTranslations`, wenn bestehende Geschwisterknoten erhalten bleiben sollen.

{/* /generated:method:$setTranslation */}

```typescript
$setTranslation('aaa', { fff: 'ggg' }) // replaces the whole `aaa` subtree
$setTranslation('aaa', 'text')          // replaces `aaa` with a string
$setTranslation('ddd', 1111)            // scalar at the top level
$setTranslation('aaa.bbb', 'nested')    // dotted path
```

Das ist ein **Ersetzen**, kein Mergen. Bestehende Geschwister unter demselben Schlüssel werden entfernt. Um zu patchen, ohne Geschwister zu verlieren, nutze `$mergeTranslations`.

### `$setMissingHandler`

{/* generated:method:$setMissingHandler — do not edit; run `pnpm run docs:generate` */}

```ts
(handler: MissingHandler | null) => void
```

Installiert einen Callback, der für jeden nicht aufgelösten Schlüssel aufgerufen wird. Übergib `null`, um ihn zu entfernen.

{/* /generated:method:$setMissingHandler */}

**Typdefinition**:

```typescript
type MissingHandler = (locale: string, key: string, routeName: string, instance?: unknown, type?: string) => void
```

```typescript
// Set a custom handler
$setMissingHandler((locale, key, routeName) => {
  console.error(`Missing translation: ${key} in ${locale} for route ${routeName}`)
  // Send to Sentry or other error tracking service
  // Sentry.captureMessage(`Missing translation: ${key}`)
})

// Remove the handler
$setMissingHandler(null)
```

**Anwendungsfälle**:

- Fehlende Übersetzungen an Error-Tracking-Dienste protokollieren (Sentry, LogRocket usw.)
- Analytics zu fehlenden Übersetzungen sammeln
- Eigene Fehlerbehandlung für fehlende Übersetzungsschlüssel

## 🔢 Zahlen- und Datumsformatierung

Methoden zur Formatierung von Zahlen und Daten gemäß Locale-Konventionen.

### `$tn`

{/* generated:method:$tn — do not edit; run `pnpm run docs:generate` */}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

Formatiert eine Zahl mit `Intl.NumberFormat` in der aktiven Locale. Ein Schlüssel wählt ein benanntes Format aus der Konfiguration.

{/* /generated:method:$tn */}

```typescript
// Inline options
const formattedNumber = $tn(1234567.89, { style: 'currency', currency: 'USD' })
// "$1,234,567.89"

// Named format (from nuxt.config i18n.numberFormats)
const price = $tn(1000, 'currency')
const priceDe = $tn(1000, 'currency', 'de')
const compact = $tn(1000, 'currency', { notation: 'compact' })
```

Unbekannte Format-Namen fallen auf die Standardoptionen von `Intl.NumberFormat` zurück. Im Entwicklungsmodus (Client) wird ein `console.warn` ausgegeben, wenn `missingWarn` aktiv ist (Standard).

**Konfigurationsbeispiel**:

```ts
export default defineNuxtConfig({
  i18n: {
    numberFormats: {
      en: {
        currency: { style: 'currency', currency: 'USD' },
        decimal: { style: 'decimal', minimumFractionDigits: 2, maximumFractionDigits: 2 },
      },
      de: {
        currency: { style: 'currency', currency: 'EUR' },
      },
    },
  },
})
```

**Anwendungsfälle**:

- Zahlen als Währung, Prozent oder Dezimal im passenden Locale-Format ausgeben
- Benannte Formate app-weit wiederverwenden (Parität zur Vue-I18n-Migration)

### `$td`

{/* generated:method:$td — do not edit; run `pnpm run docs:generate` */}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

Formatiert ein Datum mit `Intl.DateTimeFormat` in der aktiven Locale. Ein Schlüssel wählt ein benanntes Format aus der Konfiguration.

{/* /generated:method:$td */}

```typescript
const formattedDate = $td(new Date(), { weekday: 'long', year: 'numeric', month: 'long', day: 'numeric' })
// "Friday, September 1, 2023"

const short = $td(new Date(), 'short')
const longDe = $td(new Date(), 'long', 'de')
```

Unbekannte Format-Namen fallen auf die Standardoptionen von `Intl.DateTimeFormat` zurück. Im Entwicklungsmodus (Client) wird ein `console.warn` ausgegeben, wenn `missingWarn` aktiv ist (Standard).

**Konfigurationsbeispiel**:

```ts
export default defineNuxtConfig({
  i18n: {
    datetimeFormats: {
      en: {
        short: { year: 'numeric', month: 'short', day: 'numeric' },
        long: { year: 'numeric', month: 'long', day: 'numeric', weekday: 'long' },
      },
    },
  },
})
```

**Anwendungsfälle**:

- Datumsangaben im Format der Locale des Nutzers darstellen
- App-weit einheitliche Presets für Kurz-, Lang- und Datum-mit-Uhrzeit-Formate teilen

### `$tdr`

{/* generated:method:$tdr — do not edit; run `pnpm run docs:generate` */}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

Formatiert ein Datum als relative Zeit ("vor 3 Tagen") mit `Intl.RelativeTimeFormat`.

{/* /generated:method:$tdr */}

```typescript
const relativeDate = $tdr(new Date(Date.now() - 1000 * 60 * 5))
// Output: "5 minutes ago" in the 'en-US' locale
```

```ts
(locale: string) => void
```

Navigiert zur aktuellen Seite in einer anderen Locale.

{/* /generated:method:$switchLocale */}

```typescript
$switchLocale('fr')
```

<Tip>

{/* /generated:method:$switchLocaleRoute */}

```typescript
// Output: A route object with the new locale applied, e.g., { name: 'localized-news', params: { locale: 'fr' } }
```

{/* generated:method:$switchLocalePath — do not edit; run `pnpm run docs:generate` */}

```ts
(locale: string) => string
```

Der Pfad der aktuellen Seite in einer anderen Locale, ohne zu navigieren.

{/* /generated:method:$switchLocalePath */}

```typescript

```

### `$switchRoute`

{/* generated:method:$switchRoute — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => void
```

Navigiert zu einer anderen Route und behält dabei die aktive Locale oder wechselt zu `toLocale`.

{/* /generated:method:$switchRoute */}

**Beispiele**:

<CodeGroup>
```typescript String Path
// Switches to the given path with the current locale
$switchRoute('/about')
```

```typescript String Path with Locale
// Switches to the given path with French locale
$switchRoute('/about', 'fr')
```

```typescript Named Route
// Switches to a named route with the current locale
$switchRoute({ name: 'page' })
```

```typescript Named Route with Locale
// Switches to a named route and changes the locale to Spanish
$switchRoute({ name: 'page' }, 'es')
```
</CodeGroup>

## 🚦 Routen-Konfiguration

Methoden zum Konfigurieren von Routenverhalten und Zugriffskontrolle.

### `$defineI18nRoute`

{/* generated:method:$defineI18nRoute — do not edit; run `pnpm run docs:generate` */}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

Registriert die pro-Seite Locale-Konfiguration und Übersetzungen aus einer Komponente heraus.
Mischt in die aktive Locale und wendet sie beim Locale-Wechsel erneut an.

{/* /generated:method:$defineI18nRoute */}

> [!IMPORTANT]
> `$defineI18nRoute` wird vom **Define-Plugin** bereitgestellt und ist nur über `useNuxtApp()` verfügbar. Es ist **nicht** Teil des Rückgabeobjekts von `useI18n()`.
> Destrukturiere es immer aus `useNuxtApp()` innerhalb von `script setup`. Ein Aufruf von `$defineI18nRoute(...)` als reines Global wirft während SSR/Prerender einen `"$defineI18nRoute is not defined"`-Fehler.

**Parameter**:

- **locales**: `string[] | Record<string, Record<string, string>>`: Verfügbare Locales für die Route.
- **localeRoutes**: `Record<string, string>`: Optional. Eigene Routen für bestimmte Locales.
- **disableMeta**: `boolean | string[]`: Optional. Deaktiviert i18n-Meta-Tags für alle oder bestimmte Locales.

**Einfaches Beispiel**:

```typescript
import { useNuxtApp } from '#imports'

const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'fr', 'de'],
  localeRoutes: {
    en: '/welcome',
    fr: '/bienvenue',
    de: '/willkommen',
  },
  disableMeta: false,
})
```

> 📖 **Ausführliche Nutzungsbeispiele, Konfigurationsformate und Best Practices findest du im [Guide zu Übersetzungen pro Komponente](/guides/per-component-translations).**

### `$setI18nRouteParams`

{/* generated:method:$setI18nRouteParams — do not edit; run `pnpm run docs:generate` */}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

Setzt pro Locale Parameter für die aktuelle Route, sodass ein dynamisches Segment je Sprache abweichen kann.
Rufe die Funktion während SSR auf, bevor der Head gerendert wird.

{/* /generated:method:$setI18nRouteParams */}

```typescript
// in pages/news/[id].vue
// for en/news/1-first-article
const { $switchLocaleRoute, $setI18nRouteParams, $defineI18nRoute } = useNuxtApp()
$defineI18nRoute({
  localeRoutes: {
    en: '/news/:id()',
    fr: '/nouvelles/:id()',
    de: '/Nachricht/:id()',
  },
})
const { data: news } = await useAsyncData(`news-${params.id}`, async () => {
  let response = await $fetch("/api/getNews", {
    query: {
      id: params.id,
    },
  });
  if (response?.localeSlugs) {
    response.localeSlugs = {
      en: {
        id: '1-first-article'
      }
      fr: {
        id: '1-premier-article'
      }
      de: {
        id: '1-erster-Artikel'
      }
    }
    $setI18nRouteParams(response?.localeSlugs);
  }
  return response;
});
$switchLocalePath('fr') // === 'fr/nouvelles/1-premier-article'
$switchLocalePath('de') // === 'de/Nachricht/1-erster-Artikel'
```

## 🔧 Cache- und Utility-Methoden

### `$has`

{/* generated:method:$has — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string) => boolean
```

Ob sich ein Schlüssel in der aktiven Locale auflöst. Nutze dies, um bei optionalen Texten zu verzweigen, statt einen rohen Schlüssel zu rendern.

{/* /generated:method:$has */}

Während Seitenübergängen in derselben Locale mischt v3 die Übersetzungen der verlassenen Seite bis zum Ende des Übergangs automatisch tief in dieses Wörterbuch. Deshalb können Schlüssel der vorherigen Seite kurz weiterhin `true` liefern. Eine Option `previousPageFallback` gibt es nicht. Dieses Verhalten ist eingebaut. Siehe [FAQ: Seitenübergänge](/guides/faq#-why-do-translations-break-during-page-transitions-especially-with-defineasynccomponent).

```typescript
if ($has('welcome')) {
  console.log($t('welcome'))
} else {
  console.log('Key not found')
}
```

### `$clearCache`

{/* generated:method:$clearCache — do not edit; run `pnpm run docs:generate` */}

```ts
() => void
```

## 🧭 Composable `useI18nLocale`

Das zentrale Composable für das Locale-State-Management. Verwende es statt direkt `useState('i18n-locale')` oder `useCookie('user-locale')` zu manipulieren.

```typescript
const {
  setLocale, // (locale: string) => void — updates state + cookie
  getLocale, // () => string | null — from state or cookie
  getPreferredLocale, // () => string | null — validated against locales list
  getEffectiveLocale, // (route, getLocaleFromRoute) => string
  resolveInitialLocale, // (options) => string
  isValidLocale, // (locale) => boolean
  locale, // Ref<string | null> — reactive state
  localeCookie, // CookieRef — reactive cookie
  syncLocale, // (locale) => void — sync to cookie only
  validLocales, // string[] — list of valid locale codes
} = useI18nLocale()
```

### Wichtige Methoden

| Methode                 | Beschreibung                                                    |
| ----------------------- | --------------------------------------------------------------- |
| `setLocale(locale)`     | Setzt die Locale atomar in `useState` und Cookie                |
| `getLocale()`           | Liefert die aktuelle Locale aus State oder Cookie               |
| `getPreferredLocale()`  | Liefert die gegen die `locales`-Liste validierte Locale oder `null` |
| `isValidLocale(locale)` | Prüft, ob ein Locale-Code in der konfigurierten `locales`-Liste steht |

### Verwendung in eigenen Plugins

```typescript
// plugins/i18n-loader.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,
  setup() {
    const { setLocale } = useI18nLocale()
    // Detect locale from headers, domain, etc.
    setLocale('de')
  },
})
```
