title: "Hooks"
description: "Der Runtime-Hook i18n:register: Übersetzungen aus einem Nuxt-Plugin beim Laden und bei der Navigation hinzufügen."
---

Das Modul ruft einen Runtime-(App-)Hook auf: `i18n:register`. Verwende ihn, wenn ein Plugin oder ein Modul Übersetzungen hinzufügt, die nicht in deinen `locales/`-Dateien stehen. Dein Callback erhält eine `register`-Funktion, die Übersetzungen in die gerade angezeigte Seite einfügt.

## `i18n:register` {#i18nregister}

```ts
'i18n:register': (
  register: (translations: unknown, locale?: string) => void,
  locale: string,
) => HookResult
```

| Argument | Beschreibung |
| --- | --- |
| `register(translations, locale?)` | Führt `translations` per Deep-Merge in den Seiten-Chunk der zu ladenden Route für `locale` zusammen (Standard: die `locale` des Hooks). Bereits vorhandene Schlüssel werden überschrieben. |
| `locale` | Die Locale der zu ladenden Route. |

Der Hook ist über `RuntimeNuxtHooks` typisiert, daher braucht `nuxtApp.hook('i18n:register', …)` keinen Cast.

## Wann er ausgelöst wird {#when-it-fires}

Das Loader-Plugin (`i18n-plugin-loader`) ruft ihn auf:

1. einmal beim Start, nachdem alle Plugins gelaufen sind (`app:created`) und bevor die App rendert;
2. in seinem `router.beforeEach`, nachdem die Übersetzungen der Zielseite geladen sind, wenn sich der Pfad ändert — bei jeder Navigation unter `no_prefix`.

Auf jeden Callback und jeden `register`-Aufruf wird gewartet, bevor die App rendert oder die Navigation fortfährt, sodass die Seite mit den zusammengeführten Schlüsseln rendert. Mit [`hooks: false`](/de/api/module-options#hooks) wird der Hook nie aufgerufen.

## Beispiel {#example}

```ts
// plugins/i18n-extra.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('i18n:register', async (register, locale) => {
    const extra = await $fetch<Record<string, unknown>>(`/api/cms-strings/${locale}`)
    register(extra, locale)
  })
})
```

Dies ist ein Runtime-Hook: Registriere ihn mit `nuxtApp.hook` in einem Plugin, nicht mit `nuxt.hook` in `nuxt.config` oder im `setup` eines Moduls. Ein Modul fügt ein solches Plugin mit `addPlugin` hinzu.
