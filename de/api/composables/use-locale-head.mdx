# 🌍 Composable `useLocaleHead`

Das Composable `useLocaleHead` in `Nuxt I18n Micro` unterstützt dich beim Verwalten von SEO-Attributen und HTML-Meta-Tags für lokalisierte Routen. Es erzeugt dynamisch die Attribute `lang` und `dir` des HTML-Dokuments und generiert `meta`- und `link`-Tags, um die SEO deiner lokalisierten Inhalte zu verbessern.

## ⚙️ Optionen

```ts
useLocaleHead(options: UseLocaleHeadOptions): { metaObject: Ref<{ htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string }; link: { href: string; hreflang?: string; rel: string; [key: string]: string | undefined }[]; meta: { content: string; property: string; [key: string]: string }[] }, MetaObject | { htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string }; link: { href: string; hreflang?: string; rel: string; [key: string]: string | undefined }[]; meta: { content: string; property: string; [key: string]: string }[] }>; updateMeta: () => void }
```

Die SEO-Head-Tags für die aktuelle Route: `hreflang`-Alternates für jede Locale plus `x-default`, ein Canonical-Link, `og:locale` und `lang`/`dir` an `<html>`.

Nur nötig, wenn `meta` deaktiviert ist oder die Defaults angepasst werden müssen. Bei `meta: true` registriert das Modul dieselben Tags selbst.

## 🛠️ Rückgabewerte

Das Composable `useLocaleHead` liefert ein reaktives Objekt und eine Updater-Funktion, die du aufrufen solltest, wenn sich Quelldaten ändern. Beide Formen stehen in der Signatur oben und werden aus dem Quellcode generiert.

### `metaObject`

Reaktives Head-Payload (HTML-Attrs, Meta, Link), geeignet für `useHead(metaObject)`.

- **Beispiel**:
  ```js
  const { metaObject } = useLocaleHead()
  useHead(metaObject)
  ```

### `updateMeta`

Berechnet `metaObject` anhand von aktueller Route, Locale und Konfiguration neu. Rufe die Funktion bei Änderungen der Eingaben auf, zum Beispiel bei einem Routenwechsel.

- **Beispiel**:
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  useHead(metaObject)
  watch(
    () => route.fullPath,
    () => updateMeta(),
    { immediate: true },
  )
  ```

### Zugriff auf `link` und `meta`

Die Arrays `link` und `meta` sind über `metaObject.value` erreichbar:

- **Beispiel**:
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  updateMeta()
  console.log(metaObject.value.link)
  // Output: [{ id: 'i18n-can', rel: 'canonical', href: 'https://example.com/about' }, ...]
  console.log(metaObject.value.meta)
  // Output: [{ id: 'i18n-og', property: 'og:locale', content: 'en_US' }, ...]
  ```

## 🛠️ Beispielverwendungen

### Einfache Verwendung

Erzeuge locale-spezifische Head-Attribute mit den Standardoptionen.

```js
const head = useLocaleHead()
```

### Identifier-Attribut anpassen

Verwende ein eigenes Identifier-Attribut für die erzeugten Tags.

```js
const head = useLocaleHead({ identifierAttribute: 'data-i18n' })
```

### SEO-Attribute deaktivieren

Erzeuge Head-Attribute, ohne SEO-bezogene Meta- und Link-Tags hinzuzufügen.

```js
const head = useLocaleHead({ addSeoAttributes: false })
```

### Eigene Basis-URL angeben

Setze eine eigene Basis-URL für Canonical- und Alternate-URLs.

```js
const head = useLocaleHead({ baseUrl: 'https://mywebsite.com' })
```

## 🚀 Zusätzliche Funktionen

### SEO-Meta- und Link-Tags

Wenn `addSeoAttributes` aktiv ist, erzeugt das Composable automatisch folgende Tags:

- `og:locale` für die aktuelle Locale (`language_TERRITORY`, mit Unterstrich). Wird aus `locale.og` abgeleitet oder wenn möglich aus `locale.iso` konvertiert.
- `og:url` für die Canonical-URL der Seite.
- `og:locale:alternate` für alternative Sprachversionen.
- `rel="canonical"` und `rel="alternate"`-Links zur SEO-Optimierung.
- `hreflang="x-default"`-Link, der auf die URL der Standard-Locale zeigt. Damit erfährt die Suchmaschine, welche URL Nutzern gezeigt werden soll, deren Sprache zu keiner der definierten Locales passt.

### Dynamische Locale und Schreibrichtung

Das Composable bestimmt die Attribute `lang` und `dir` dynamisch anhand der Locale der aktuellen Route, damit dein HTML-Dokument für internationale Nutzer korrekt konfiguriert ist.

### Umgang mit lokalisierten Routen

Wenn deine Routen mit Locale-Codes präfixiert sind (zum Beispiel `/en/about`), passt das Composable den vollständigen Pfad zur URL-Erzeugung intelligent an. So bleiben die SEO-Attribute genau und relevant.

Damit vereinfacht dieses Composable die SEO-Optimierung deiner Nuxt-Anwendung für internationale Zielgruppen. Deine Seite ist gut vorbereitet für globale Suchmaschinen und Nutzer.

## 🛠️ Beispielverwendung

Das folgende Beispiel zeigt, wie du das Composable `useLocaleHead` in einer Vue-Komponente mit Standardeinstellungen einsetzt:

```vue
<script setup>
import { useRoute, watch } from '#imports'
const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({
  addDirAttribute: true,
  identifierAttribute: 'id',
  addSeoAttributes: true,
})
useHead(metaObject)
watch(
  () => route.fullPath,
  () => updateMeta(),
  { immediate: true },
)
</script>
```

### Erläuterung des Codes

- **Composable `useLocaleHead`**: Wird im `<script setup>` aufgerufen und liefert ein Objekt mit `htmlAttrs`, `meta` und `link`.

- **`<html>`-Tag**: Die Attribute `lang` und `dir` des HTML-Dokuments werden dynamisch anhand der aktuellen Locale bestimmt und an das `<html>`-Tag gesetzt.

- **`<head>`-Bereich**:
  - **Meta-Tags**: SEO-relevante Meta-Tags werden erzeugt, darunter `og:locale`, `og:url` sowie `rel="canonical"`- und `rel="alternate"`-Tags für alternative Sprachversionen der Seite.
  - **Link-Tags**: Canonical-Links, Links auf alternative Sprachversionen sowie der `hreflang="x-default"`-Link (auf die URL der Standard-Locale) werden eingebunden.

- **`<body>`-Bereich**: Hier steht der eigentliche Inhalt der Seite. In diesem Beispiel wird eine einfache Überschrift mit Absatz verwendet.

### 📝 Hinweise

1. **Attribute**: Die verwendeten Attribute (`lang`, `dir`, `rel`, `href`, `hreflang`, `property`, `content`) stammen aus dem Objekt, das `useLocaleHead` zurückgibt.

2. **Erzeugung der SEO-Tags**: Wenn die Option `addSeoAttributes` auf `true` gesetzt ist, erzeugt das Composable automatisch SEO-Tags für die aktuelle Locale.

3. **Basis-URL**: Über die Option `baseUrl` legst du deine eigene Basis-URL fest, um Canonical- und Alternate-Links korrekt zu erzeugen.

Dieses Beispiel zeigt, wie einfach sich `useLocaleHead` in die Komponenten deiner Anwendung einbinden lässt, um korrekte SEO-Attribute sicherzustellen und die Indexierung lokalisierter Seiten in Suchmaschinen zu verbessern.

## 🧩 Anpassung und Lifecycle

- `useLocaleHead` abonniert selbst keine Änderungen. Es liefert `metaObject` und `updateMeta`.
- Rufe `updateMeta()` bei Änderungen der Eingaben auf (typischerweise bei Routenwechsel), zum Beispiel aus einem Plugin:

```ts
// plugins/02.meta.ts
export default defineNuxtPlugin(() => {
  const route = useRoute()
  const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
  useHead(metaObject)
  if (import.meta.server) updateMeta()
  else
    watch(
      () => route.fullPath,
      () => updateMeta(),
      { immediate: true },
    )
})
```

## Wann du stattdessen `useI18nHead` verwendest

Bei `meta: true` (dem Standard) bevorzuge [`useI18nHead`](/api/composables/use-i18n-head) für **seitenweise** Überschreibungen (eigenes hreflang, zusätzliches `og:title`, teilweises Deaktivieren). Verwende `useLocaleHead` nur direkt, wenn `meta: false` gesetzt ist oder du `useHead` selbst verwaltest.
