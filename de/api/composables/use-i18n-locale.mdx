# useI18nLocale

## Signatur

{/* generated:symbol:useI18nLocale — do not edit; run `pnpm run docs:generate` */}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getLocaleWithServerFallback: (serverLocale?: string | null) => string | null; getPreferredLocale: () => string | null; hashCookie: any; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: any; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Zentraler Einstiegspunkt für das i18n-Locale-Management.
Kombiniert `useState('i18n-locale')`, das Locale-Cookie und Sync-Utilities.

{/* /generated:symbol:useI18nLocale */}

## Verwendung

```vue
<script setup>
const {
  locale,
  localeCookie,
  hashCookie,
  validLocales,
  getPreferredLocale,
  getLocale,
  getLocaleWithServerFallback,
  getEffectiveLocale,
  resolveInitialLocale,
  setLocale,
  syncLocale,
  isValidLocale,
} = useI18nLocale()

// Setzt die Locale (aktualisiert State und Cookies)
setLocale('de')

// Aktuelle Locale ermitteln (State → Cookie)
const current = getLocale()

// Bevorzugte, gültige Locale ermitteln
const preferred = getPreferredLocale()
</script>
```

## API

| Property bzw. Methode                            | Typ                                 | Beschreibung                                                                          |
| ------------------------------------------------ | ----------------------------------- | ------------------------------------------------------------------------------------ |
| `locale`                                         | `Ref<string \| null>`               | Reaktiver Locale-State (`useState('i18n-locale')`)                                    |
| `localeCookie`                                   | `Ref`                               | Locale-Cookie (wenn die Option `localeCookie` aktiv ist)                              |
| `hashCookie`                                     | `Ref`                               | Cookie, das im `hashMode` verwendet wird                                              |
| `validLocales`                                   | `string[]`                          | Aktive Locale-Codes aus der Modulkonfiguration (ohne `disabled`)                      |
| `getLocale()`                                    | `() => string \| null`              | Aktuelle Locale: State → Cookie (bzw. Hash-Cookie im Hash-Modus)                      |
| `getPreferredLocale()`                           | `() => string \| null`              | Locale aus State/Cookie, **validiert** gegen `validLocales`, sonst `null`             |
| `getLocaleWithServerFallback(serverLocale?)`     | `(serverLocale?) => string \| null` | State → Cookie → optionaler Server-Kontext (bei `no_prefix`-Init genutzt)              |
| `getEffectiveLocale(route, getLocaleFromRoute)`  | `(route, fn) => string`             | Locale zum Laden von Übersetzungen: im Hash-Modus State bevorzugt, sonst aus der Route |
| `resolveInitialLocale(options)`                  | `(options) => string`               | Löst die Locale auf: State → `serverLocale` → Route. Synct den State, wenn nötig     |
| `setLocale(locale)`                              | `(locale: string \| null) => void`  | Setzt die Locale und synchronisiert die Cookies                                       |
| `syncLocale(locale)`                             | `(locale: string \| null) => void`  | Synchronisiert nur die Cookies (kein State-Update)                                    |
| `isValidLocale(locale)`                          | `(locale) => boolean`               | Prüft, ob der String in `validLocales` enthalten ist                                  |

### Optionen von `resolveInitialLocale`

```typescript
interface ResolveInitialLocaleOptions {
  route: unknown
  serverLocale?: string | null
  getLocaleFromRoute: (route?: unknown) => string
}
```

Wird intern vom Haupt-Plugin beim Start verwendet. Eigene Plugins können sie aufrufen, wenn sie einen alternativen Erkennungsablauf umsetzen.

### `getEffectiveLocale`

```typescript
const { getEffectiveLocale } = useI18nLocale()
const { $getLocale } = useNuxtApp()

const locale = getEffectiveLocale(route, (r) => $getLocale(r))
```

Liefert die Locale, mit der Übersetzungen geladen und Nachrichten für ein gegebenes Route-Objekt formatiert werden.

## Locale programmatisch setzen

Bevorzuge `useI18nLocale()` gegenüber direktem `useState('i18n-locale')`:

```ts
// plugins/i18n-loader.server.ts
import { defineNuxtPlugin } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,

  setup() {
    const { setLocale } = useI18nLocale()
    const detectedLocale = 'ja' // Deine Erkennungslogik
    setLocale(detectedLocale)
  },
})
```

<Tip>
`setLocale()` aktualisiert nur die Locale-Präferenz (State und Cookie). Um zusätzlich den aktiven Übersetzungskontext im Client neu zu laden, nutze `$switchLocale()` aus `useNuxtApp()` oder `useI18n()`. Das ist besonders bei `no_prefix` wichtig, wo sich die URL nicht ändert. Siehe [FAQ: Locale wechseln, ohne die URL zu ändern](/guides/faq#-switch-locale-without-changing-the-url).
</Tip>
