**Datum**: 2026-11-03

**Version**: `v4.0.0`

![v4.0.0 release](/images/4.0.0.png)

**v4.0.0** ist erschienen. Routing, der Übersetzungskern, die Wörterbuchdateien, die Locale-Erkennung und jedes Framework-Paket wurden neu geschrieben. Optionen, `$t`, `$localePath`, `$switchLocale`, die Komponenten und die Composables behalten ihre Namen. Was sich ändert, ist das Verhalten, und die meisten dieser Änderungen sind behobene Fehler. Die meisten Apps benötigen nur wenige Codeänderungen, aber lesen Sie vor dem Upgrade die [Breaking Changes](#breaking-changes): URLs, SEO-Tags und APIs der Framework-Pakete haben sich stellenweise verändert. [Upgrade](/de/guide/upgrade) enthält alle Details.

## Was ist neu? {#what’s-new}

### Ein Build für jede Domain {#one-build-for-every-domain}

`locales[].baseUrl` und `baseDefault` beeinflussten bisher nur Links. Jetzt routen sie auch Anfragen, unter allen vier Strategien und in `nuxt generate`:

```ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'fr', baseUrl: 'https://example.com' },
      { code: 'de', baseUrl: 'https://example.de', baseDefault: true },
    ],
  },
})
```

- Ein Host bedient seine eigenen Locales. Links zur Locale einer anderen Domain werden zu absoluten URLs auf dieser Domain, und ein Wechsel dorthin navigiert dorthin.
- `trustForwardedHost` wählt die Domain aus `X-Forwarded-Host` hinter einem Proxy, der diesen Header überschreibt. Standardmäßig deaktiviert.
- `NUXT_I18N_DOMAIN` gibt `nuxt generate` seinen Host: Führen Sie es einmal pro Domain aus, und jede Ausgabe enthält nur die Seiten und Wörterbücher dieser Domain.
- Eine App ohne `baseUrl` liefert nichts von diesem Code aus.

Siehe [Layers und Domains](/de/guide/layers#multiple-domains) und [Deployment](/de/guide/deployment).

### Routing, das mit dem Router übereinstimmt {#routing-that-agrees-with-the-router}

Build und Runtime ermitteln lokalisierte URLs nicht mehr getrennt. Jede Antwort stammt aus den Routen, die der Build erzeugt hat, sodass ein Link, ein Switcher, `hreflang` und ein Redirect nicht auf eine Seite zeigen können, die es nicht gibt.

- Eine Locale, die eine Seite nicht bedient, verlinkt auf ihre Startseite, nie auf die Seite einer anderen Locale.
- `hreflang` listet nur die Locales auf, die die Seite bedienen.
- `$switchLocale` wird zu `true` oder `false` aufgelöst, sodass Sie erkennen können, wenn ein Wörterbuch nicht geladen werden konnte. Ein wiederholter Aufruf versucht es erneut.
- Während des SSR gesetzte `$setI18nRouteParams` und `useI18nHead` überstehen die Hydration. Der Switcher verlinkt auf den übersetzten Slug, auch im Server-HTML.
- Eine Navigation wird wirksam, wenn sie committet wird: Eine abgebrochene oder blockierte Navigation ändert nichts.
- Der Hash-Modus funktioniert unter `prefix`.
- `<Greeting :locale="$getLocale()" />` auf einer Server-Komponente setzt deren Render-Locale.

### Eine Locale-Erkennung {#one-locale-detection}

Eine Reihenfolge überall: auf dem Server, im Browser, in Server-API-Helfern und in Astro. `Accept-Language` berücksichtigt `q`-Werte, der regionale Abgleich hängt nicht mehr von der Reihenfolge von `locales` ab und überschreitet nie die Grenzen chinesischer Schriftsysteme. Laufzeit-Overrides erreichen jetzt das Routing: `NUXT_I18N_DEFAULT_LOCALE` und Laufzeit-`disabledLocales` ändern, was tatsächlich ausgeliefert wird. Siehe [Locale-Erkennung](/de/guide/locale-detection).

### Ein Wörterbuch in jedem Modus {#one-dictionary-in-every-mode}

Premerged-Builds, `mode: 'source'` und Dev waren sich auf vielen Seiten uneinig. Jetzt liefern sie dasselbe Wörterbuch.

- Zusammenführungen sind auf jeder Ebene tief, und Fallback-Ketten (`fr` → `de` → `en`) werden bis zum Ende verfolgt.
- Übersetzungsänderungen in Dev werden direkt angewendet, ohne Neuladen der Seite. Entfernte Schlüssel verschwinden, und eine Änderung an einer Root-Datei erreicht jede Seite.
- `$clearCache()` lädt die aktuelle Seite neu und behält den alten Text auf dem Bildschirm, bis der neue Text eintrifft.
- Ein fehlgeschlagener Chunk behält das aktuelle Wörterbuch, statt Rohschlüssel anzuzeigen.

### Kleinere Wörterbuchdateien {#smaller-dictionary-files}

- Die Datei einer Seite enthält jetzt nur noch, was sich vom Root der Locale in `__root/<locale>/data.json` unterscheidet. Der Browser lädt den Root einmal und führt jede Seite darüber zusammen, sodass der Speicherbedarf auf der Festplatte sinkt und die nächste Seite nur einen Bruchteil der ersten kostet.
- Wörterbuch-URLs tragen eine Version. Eine URL mit dem aktuellen `?v=` wird auf einem Node-Server für ein Jahr festgeschrieben, und die statische Kopie eines Hosts antwortet mit `max-age=60`. Siehe [Cache-Header](/de/guide/deployment#cache-headers-and-datebuild).
- Jede SSR-Seite lädt ihre Wörterbuchdateien per Preload vor, sodass sie zusammen mit dem HTML starten.
- Ein fehlgeschlagener Lesevorgang bleibt nicht mehr hängen: Die nächste Anfrage liest erneut. Siehe [Wenn ein Wörterbuch nicht gelesen werden kann](/de/guide/deployment#when-a-dictionary-cannot-be-read).

### Besseres `<i18n-t>`, Pluralformen und Formate {#better-&lt;i18n-t&gt;-plurals-and-formats}

- Slots funktionieren mit `plural`, `number`, `date` und `relativeDate`, und jedes `{name}` wird gefüllt, nicht nur das erste.
- `<i18n-t>` ist ein einziger Renderer für Nuxt, Vue, React, Preact, Solid und Astro.
- Eine erste Form, die mit `=0 ` beginnt, ist eine explizite Nullform, und der Rest richtet sich nach `Intl.PluralRules`: `=0 no apples | one apple | {count} apples`. Siehe [`$tc`](/de/api/methods#$tc).
- Neue Option `timeZone`: ein einheitliches Kalenderdatum auf dem Server und in jedem Browser.
- `{firstName}`, `{first-name}` und `{user.name}` sind gültige Platzhalter.
- `$tn`, `$td` und `$tdr` richten sich nach `iso`, wie die Pluralformen.
- `$tdr` liefert echte Zukunftsdaten: `in 3 days`, oder `tomorrow` mit `numeric: 'auto'`.

### Standardmäßig sicherer {#safer-by-default}

- `<i18n-t html>` escaped `params`. Nur die Übersetzung gilt als vertrauenswürdiges Markup.
- Kein Link verlässt versehentlich den Origin: `//host`, `/\host` und Leerwerte bleiben auf dieser Website.
- Der Server-Übersetzungscache ist begrenzt, sodass URLs mit erfundenen Seitennamen den Speicher nicht anwachsen lassen.
- Die Speicher-Endpoints der DevTools akzeptieren nur bestehende `.json`-Dateien in Ihren Übersetzungsverzeichnissen und lehnen Cross-Site-Anfragen ab.

### Framework-Pakete in Version 2.0 {#framework-packages-at-2-0}

- **React, Preact, Solid:** `I18nT` nimmt ein `components`-Prop für Rich Text entgegen. Neu sind `useT` und `useLocaleSwitch` sowie Unterstützung für React Server Components über `@i18n-micro/react/server` und `/client`. Preact benötigt `preact/compat` nicht mehr.
- **Vue und VitePress:** `I18nLink` behält `name`, `query` und `hash`, und VitePress berücksichtigt `base`.
- **Astro:** `i18nIntegration` bündelt Ihre Wörterbücher und installiert die Middleware. Der Haupteinstieg hat keinen `node:*`-Import, sodass er am Edge läuft. `base` funktioniert.
- **Node und Runtime:** `fork(locale)` liefert eine günstige Instanz pro Anfrage, und `run(locale, fn)` in `@i18n-micro/node` beschränkt eine Instanz auf eine Anfrage.
- **`@i18n-micro/types-generator`:** keine Abhängigkeiten von Drittanbietern und ein einfaches Vite- und Rollup-Plugin.
- **`@i18n-micro/devtools-ui`:** Live-Updates über den Socket von Vite und eine Astro-Toolbar-App.

### `@i18n-micro/cli` {#@i18n-micro/cli}

Die CLI liegt jetzt als `@i18n-micro/cli` im Monorepo, neu geschrieben mit 16 statt 28 Befehlen und weit weniger Abhängigkeiten. `check` ersetzt `validate`, `diff` und `check-duplicates`, mit `--json` und Exit-Codes für die CI. Wenn `clean` nicht beweisen kann, dass ein Schlüssel ungenutzt ist, schreibt es nichts. Siehe [CLI](/de/guide/cli).

### Dokumentation {#documentation}

Die Dokumentation wurde anhand des Codes entlang eines Lesepfads neu geschrieben: Installation, erste übersetzte Seite, Übersetzungsdateien, Routing, Erkennung, dann aufgabenbezogene Leitfäden. Alte URLs werden weitergeleitet. [Upgrade](/de/guide/upgrade) listet jede Änderung im Detail auf.

## Geschwindigkeit und Größe {#speed-and-size}

- Ein Server-Rendering liest Wörterbücher direkt, ohne lokale HTTP-Anfrage und ohne erneutes Parsen.
- `dir="auto"` ist nicht mehr der Standard. Browser verbringen auf großen Seiten viel Zeit damit: Mit 20.000 `$t`-Elementen sank DOMContentLoaded in Chromium von etwa 980 ms auf etwa 115 ms.
- `serverTranslationPreload` und `i18n:register` verlangsamen nicht mehr jede Anfrage.
- Das Client-Bundle verzichtet auf `useCookie`, wenn kein Cookie konfiguriert ist, und `@i18n-micro/path-strategy` hat nur noch einen Bruchteil seiner alten Größe.

**Test-App im Vergleich zu v3.30.3.** Eine generierte Nuxt-App auf einem Node-Server, auf einem Mac, `wrk` mit 24 Verbindungen für 20 s, drei rotierte Runden, auf einem Pre-Release-Build. Die Zeilen stammen aus separaten Läufen, vergleichen Sie daher innerhalb einer Zeile. Die Hydration verwendet auf beiden Seiten `dir: 'ltr'`.

| 4 Locales, 10k-Katalog: p95-Latenz | 106-110 ms | 70-72 ms |
| 4 Locales, 10k-Katalog: Server-CPU pro Anfrage | 2.92-3.00 ms | 2.01-2.02 ms |
| 12 Locales, 100k-Katalog: Anfragen pro Sekunde | 362-370 | 578-580 |

## Breaking Changes {#breaking-changes}

### Voraussetzungen {#requirements}

- **Nuxt 3.18 oder neuer** und **Node 20 oder neuer**.
- **`@i18n-micro/test-utils`** wird nicht mehr mit dem Modul installiert. Fügen Sie es selbst hinzu, wenn Ihre Tests es importieren.
- **`@i18n-micro/hmr`** entfällt: Übersetzungs-HMR ist integriert. Entfernen Sie das Paket, falls Sie es installiert haben.
- **`@i18n-micro/react`** benötigt React 18 oder neuer.
- **`nuxt-i18n-micro-cli`** wird durch `@i18n-micro/cli` ersetzt.

### Optionen und Konfiguration {#options-and-config}

- `i18n-plugin-hooks` und `i18n-plugin-define` in einem `dependsOn` warten auf nichts mehr, ohne Fehlermeldung. Verwenden Sie `i18n-plugin-loader`.
- Server-Auto-Imports sind `useLocaleServerMiddleware`, `useTranslationServerMiddleware`, `loadTranslationsFromServer` und `detectCurrentLocale`. Andere werden nicht mehr automatisch importiert.
- `resolveTranslationPayloadMode` und die anderen `resolveTranslationPayload*`-Helfer wurden aus `nuxt-i18n-micro` entfernt, ebenso `shouldCopyTranslationPayloadsToPublic` und `shouldRegisterNitroServerAssets`. Der Typ `TranslationPayloadMode` bleibt.
- `$getI18nConfig()` hat kein `isSSG`, `hmr`, `hooks`, `noPrefixRedirect`, `routeLocales`, `routeDisableMeta` oder `globalLocaleRoutes` mehr. Die Optionen selbst bleiben unverändert.
- `locales[].baseUrl` routet jetzt Anfragen: Eine Locale einer anderen Domain ergibt auf diesem Host einen 404, und Links auf demselben Host sind relativ. In einem solchen Build enthält `$getI18nConfig().locales`, was der Host bedient, und `linkLocales` enthält alle.
- `baseUrl` setzt den Origin auch auf jedem anderen Host: Canonical und `hreflang` verwenden `metaBaseUrl`, falls gesetzt, sonst die `baseUrl` der Standard-Locale, nicht den Origin der Anfrage.
- `excludePatterns` passen auf ganze Segmente (`'/admin'` passt nicht mehr auf `/administrator`), Globs sind verankert, und `RegExp`-Muster erreichen jetzt die Runtime.
- Ein nicht gesetztes `cacheMaxSize` bedeutet höchstens 1000 Einträge auf dem Server. `cacheTtl` zählt ab dem Zeitpunkt, zu dem ein Eintrag gespeichert wurde, und Lesezugriffe verlängern es nicht mehr.
- Unter `no_prefix` bleibt ein explizites `localeCookie: null` in der `i18n`-Konfiguration deaktiviert.
- Unter `prefix_except_default` und `prefix_and_default` wird ein Laufzeit-`defaultLocale` mit einer Warnung ignoriert. Ein Laufzeit-`fallbackLocale` muss eine aktivierte Locale sein.
- `routeDisableMeta` in `nuxt.config` wird berücksichtigt, und ein `nuxt.config`-Eintrag schlägt `$defineI18nRoute` in jeder Schlüsselform.
- Auf einem Server in Dev ist die aufgelöste Konfiguration eingefroren: Ein Schreibzugriff darauf wirft einen Fehler.
- Der `locales`-Eintrag eines Projekts schlägt den eines Layers für denselben `code`.

### Composables und `$`-Methoden {#composables-and-$-methods}

- `$switchLocale` wird zu `true` oder `false` aufgelöst, früher zu nichts. `$switchRoute` ist als `Promise<void>` typisiert.
- `$localeRoute`, `$switchLocalePath` und der Switcher verlinken eine Locale, die eine Seite nicht bedient, auf die Startseite dieser Locale.
- `$localePath` gibt einen String mit einem `http(s):`-, `mailto:`- oder `tel:`-Schema unverändert zurück, und `$localeRoute` trägt ihn in `path` und `fullPath`. Übergeben Sie ihnen keinen ungeprüften Wert als Link-Ziel. `//host` und reine Namen wie `x.com` bleiben Pfade auf diesem Origin.
- Ein Link ohne Pfad bleibt auf der aktuellen Seite: `$localePath('#top')`, `'?p=2'`, `''` und `{ query }`. `'#top'` wurde früher vom Website-Root aus gelesen. Ein einfaches `'about'` bedeutet weiterhin `/about`.
- `$switchRoute` bleibt in der App. Nur die eigene `baseUrl` einer Locale, `mailto:` und `tel:` verlassen sie.
- Ein Link zu einer Locale mit einer `baseUrl` läuft über `$localePath` oder `<i18n-link>`. `<NuxtLink :to="$localeRoute(x, 'fr')">` und `router.push($localeRoute(x, 'fr'))` bleiben Pfade dieser App. Im Code verwenden Sie `navigateTo($localePath(x, 'fr'), { external: true })`.
- `$switchLocaleRoute` und Redirects folgen `trailingSlash`.
- Auf dem Server gesetzte `$setI18nRouteParams` und `useI18nHead` werden verworfen, wenn eine Navigation den Pfad ändert, auch von `/news/1` zu `/news/4`: Setzen Sie sie auf der neuen Seite erneut.
- In setup gelesene `$setI18nRouteParams` sind an diese Seite gebunden: Ein verspäteter Aufruf von einer bereits verlassenen Seite bewirkt nichts. Es gibt keinen Setter, stubben Sie in Tests daher `useI18n` selbst.
- `useI18n()` gibt ein Objekt pro App zurück. Ein Schreibzugriff darauf erreicht jeden Aufrufer.
- Wörterbuch, Locale, Params und Head ändern sich, wenn eine Navigation committet wird. Ein `beforeResolve`, ein `beforeRouteEnter` oder ein späterer globaler Guard sieht die alten Werte. Route-Middleware ist nicht betroffen.
- `$switchLocale` stellt unter den URL-Strategien die gespeicherte Locale wieder her, wenn seine Navigation abgebrochen wird.
- `$t` interpoliert einen `defaultValue`: `$t('missing', { n: 1 }, 'Got {n}')` ergibt `Got 1`. `$tc` ebenso, und bei einer leeren Übersetzung antwortet es mit `''`.
- `$has(key, route)` berücksichtigt die Route.
- `$clearCache()` lädt das Wörterbuch der aktuellen Seite neu.
- Ein `{param}`-Platzhalter liest nur die Params, die Sie übergeben: `{constructor}` bleibt wie geschrieben.
- `$tc` mit einer negativen, gebrochenen oder sehr großen Anzahl nimmt die letzte Form mit der echten Anzahl. `{ count: null }` wirft keinen Fehler mehr, und ein fehlender Pluralschlüssel erreicht den Missing-Handler.
- `$tdr` liefert `Invalid Date` für eine ungültige Eingabe. Weniger als eine Sekunde in der Vergangenheit ergibt `0 seconds ago`.
- `$tn`, `$td` und `$tdr` richten sich nach `iso`: `{ code: 'en', iso: 'en-GB' }` formatiert Daten als `31/10/2026`. Ein Code, den `Intl` nicht kennt, wird wie `en` formatiert und Pluralformen nach der Indexregel: Setzen Sie `iso` (`{ code: 'ua', iso: 'uk-UA' }`).
- `detectCurrentLocale` ist veraltet: Verwenden Sie `useLocaleServerMiddleware(event).current`.

### Pluralformen {#plurals}

Templates behalten ihre Bedeutung, mit einer Ausnahme. Eine Nullform ohne Platzhalter, gefolgt von einer Form pro Kategorie, mit `{count}` in jeder Form, die sich mehrere Anzahlen teilen, richtet sich jetzt in Locales mit drei oder mehr Kategorien (`ru`, `uk`, `pl`, `cs`, `ar` und andere) nach der Kategorie: `none | {count} one | {count} few | {count} many` ergibt in `uk` `3 few` und `21 one`. Um Kategorien in einem anderen Template zu verwenden, fügen Sie den Marker `=0 ` hinzu. Eine benutzerdefinierte `plural`-Regel liest den Rohwert, sodass ein markiertes Template sie mit `=0 ` an Ort und Stelle erreicht. Siehe [die Tabelle unter Upgrade](/de/guide/upgrade#plurals-and-formatting).

### Komponenten {#components}

**`<i18n-t>`**

- `html` escaped `params` in jedem Fall und ignoriert alle Slots.
- Ein Slot schlägt einen gleichnamigen Param.
- `null` bedeutet für `plural`, `number`, `date` und `relativeDate` nicht gesetzt.
- `plural` zählt wie `$tc`, mit `Number`: `1.5` bleibt `1.5`, `"2 items"` ist `NaN`, `""` ist `0`.
- `number`, `date` und `relativeDate` behalten `params`.
- `hideIfEmpty` gilt in jedem Zweig, und `defaultValue` ersetzt in jedem Zweig einen fehlenden Schlüssel.
- Ein fehlender Schlüssel unter `html` ist escapeter Text.
- Die Ausgabe von `date` und `relativeDate` trägt `data-allow-mismatch="text"`, und neben einem benannten Slot steht der Text in einem eigenen `<span>`.
- Die Attribute `.innerHTML` und `textContent` werden verworfen.
- Sie ist eine funktionale Komponente: Ein `ref` darauf liefert keine Instanz.
- `<i18n-t>` und `<i18n-group>` lesen das aktive Wörterbuch, wie `$t`.

**`<i18n-switcher>`**

- Ein Link ist ein einfaches `<a>`, das `$switchLocale` aufruft, daher entfallen die `router-link-active`-Klassen.
- Der Button ist `type="button"` mit `aria-expanded`. Escape und ein Klick außerhalb schließen das Dropdown.
- Neue Klassen `i18n-switcher-wrapper`, `i18n-switcher-dropdown` und `i18n-switcher-button`. Jeder Link hat `lang` sowie `dir`, wenn die Locale es setzt.
- Die Standard-Styles verwenden logische CSS-Eigenschaften, und das Dropdown hat einen größeren `z-index`, eine Mindestbreite und einen Schatten.
- Der Server schreibt seine Links am Ende des Renderings um, auf Seiten mit Params. Ein handgeschriebener `$switchLocalePath`-Link wird nicht umgeschrieben.

**`<i18n-link>`**

- `https://`, `mailto:` und `tel:` werden unabhängig von der Groß-/Kleinschreibung erkannt. Ein einfaches `report.pdf` ist eine Route, und `example.com` bleibt extern. Eine Dateiendung, die zugleich eine TLD ist (`example.md`), zählt als Datei: Schreiben Sie `https://`.
- `activeStyle` ignoriert einen abschließenden Schrägstrich, die Query und den Hash.

### Hooks und Typen {#hooks-and-types}

- `i18n:register` ist ein Runtime-Hook: `nuxtApp.hook('i18n:register', …)` in einem Plugin.
- Der exportierte Typ `ModuleHooks` wurde in `ModuleRuntimeHooks` umbenannt.
- `i18n:beforeLocaleSwitch` und `i18n:afterLocaleSwitch` wurden nie ausgelöst und sind nicht mehr dokumentiert.
- `ModuleOptionsExtend.isSSG` ist optional und veraltet: Nichts setzt es.

### URLs und Redirects {#urls-and-redirects}

- **`/en` und `/en/...` ergeben einen 404** unter `prefix_except_default`, mit `en` als Standard.
- **Ein Locale-Präfix in anderer Groß-/Kleinschreibung oder Schreibweise ergibt einen 404** (`/DE/about`). Ebenso `/DE/x` unter `[...slug]` und `/DE` neben `[slug]`, sodass ein CMS-Slug, der einem Locale-Code in anderer Schreibweise entspricht, seine Seite verliert.
- **Eine unbekannte URL bleibt ein 404** mit `autoDetectPath: '*'` oder `'no_prefix'`. `prefix` behält den Redirect, ebenso `/` überall.
- **Der benutzerdefinierte Pfad einer anderen Locale ohne Präfix** ist unter `prefix_except_default` ein `302` zur URL der Standard-Locale. Unter `prefix` erreicht der Redirect jetzt eine existierende Seite. `prefix_and_default` bleibt ein 404.
- **`prefix` mit `redirects: false`** antwortet auf eine URL ohne Präfix mit 404, einschließlich der ursprünglichen URL einer Seite mit benutzerdefiniertem Standardpfad.
- **`autoDetectPath: '*'`** wendet das Cookie und `Accept-Language` auch auf Pfade ohne Präfix an.
- **Unter `prefix`** behält eine URL ohne Präfix die Locale des Besuchers, auf jedem Pfad, unabhängig von `autoDetectPath`.
- **Unter `prefix_and_default`** ist eine URL ohne Präfix die Standard-Locale.
- **Unter `no_prefix`** rendert ein benutzerdefinierter Pfad seine eigene Locale, eine eingeschränkte Seite rendert in einer Locale, die sie bedient, und Locales mit gemeinsamem Pfad teilen sich einen Eintrag.
- **Ein `routeRules`-Redirect ohne Seite** wird nicht lokalisiert: `/de/old` ergibt einen 404, früher ein leeres 200.
- **Route-Regeln erreichen benutzerdefinierte Pfade** und werden auch unter `no_prefix` kopiert. Ein statisches Geschwister wie `/de/artikel/news` passt auf `/de/artikel/:slug`.
- **Eine Locale mit `disabled: true`** antwortet sofort mit 404 auf ihr Präfix, und Links zu ihr bleiben auf der Seite.
- **Ein Seitenpfad in anderer Groß-/Kleinschreibung** ist ein `302` zu seiner eigenen Schreibweise: `/T/BASIC` führt zu `/t/basic`.
- **Die ursprüngliche URL einer Seite mit benutzerdefiniertem Standardpfad** ist unter `prefix_except_default` ein `302` zu diesem Pfad. Früher war sie ein 404.
- **`noPrefixRedirect`** richtet sich nach der Locale des Besuchers: Mit Cookie `de` führt `/about` zu `/ueber-uns`, nicht zum Pfad der Standard-Locale.
- **Das eigene Präfix eines Hosts** ergibt unter `prefix_except_default` auf seinem `baseDefault`-Host einen 404: `/de/x` auf dem `de`-Host war ein 200.
- **`customRegexMatcher`** liefert keinen 404 mehr für eine echte Seite, deren erstes Segment wie eine Locale aussieht.
- **`nuxi generate`** rendert jede statische Seite in jeder Locale vor, die sie bedient, sofern keine Route-Regel `prerender: false` setzt: mehr Dateien in der Ausgabe. Mit `baseUrl` führen Sie es einmal pro Domain mit `NUXT_I18N_DOMAIN` aus.
- **Ein Client-Redirect behält den Modus seiner Navigation:** Ein einfacher `<NuxtLink>` fügt einen History-Eintrag hinzu.
- **Lokalisierte Routennamen sind konsistent.** Betroffen ist nur Code, der `localized-…`-Namen in `router.push({ name })` hartcodiert: Übergeben Sie den eigenen Namen der Seite an `$localeRoute`.
- **Unbenannte Seiten aus `extendPages`** werden lokalisiert und erhalten einen Namen.
- **Unter `prefix` behält ein Link zu einer anderen Domain** das Locale-Präfix.
- **Die Startseite einer Domain** wird überall ohne abschließenden Schrägstrich geschrieben.
- **`?locale=`** zählt auf Seiten nur unter `no_prefix`. `/about?locale=de` rendert nicht mehr Deutsch unter `lang="en"`.
- **Ein `setLocale('de')` eines Plugins** auf `/en/...` lädt nicht mehr das `de`-Wörterbuch.

### SEO und HTML-Ausgabe {#seo-and-html-output}

- `dir="auto"` ist nicht mehr der Standard. Eine bekannte RTL-Sprache erhält `dir="rtl"`, und jede andere Locale ohne `dir` erhält kein Attribut. Um die alte Ausgabe beizubehalten, setzen Sie `dir: 'auto'`, mit Parsing-Kosten auf großen Seiten. Siehe [Textrichtung](/de/guide/seo#text-direction).
- `disableMeta` funktioniert jetzt: Die Seite hat kein `hreflang`, Canonical oder `og:locale`. `lang` und `dir` bleiben.
- `hreflang` listet nur die Locales auf, die die Seite bedienen. `x-default` erscheint nur, wenn die Standard-Locale sie bedient.
- Eine nicht lokalisierte Seite hat kein `hreflang` oder `og:locale:alternate`.
- 404-Seiten tragen `<html lang dir>` in der Locale der URL und kein Canonical oder `hreflang`.
- Canonical, `og:url` und `hreflang` behalten eine Query aus der Whitelist (`/about?page=2`), auch auf dem Server.
- Canonical und `hreflang` enthalten `app.baseURL`, wenn der Origin aus der Anfrage stammt.
- Jede SSR-Seite hat `<link rel="preload" as="fetch" crossorigin="anonymous">` für ihre Wörterbuchdateien, auch 404-Seiten. Erlauben Sie dies in einer strengen CSP. Mit `apiBaseClientHost` benötigt dieser Host CORS.
- `Vary` wird unter `no_prefix` auf jeder Seite gesetzt und bei den anderen Strategien auf den Locale-Redirects. Prüfen Sie den Cache-Key Ihres CDN.
- Das Locale-Cookie wird nur von einer ausgelieferten Seite geschrieben.

### Erkennung und Server {#detection-and-server}

- `Accept-Language` berücksichtigt `q`-Werte, und `q=0` schließt eine Sprache aus.
- `useLocaleServerMiddleware` und `useTranslationServerMiddleware` verwenden auf jeder Route eine Reihenfolge (`?locale`, `[locale]`-Param oder Präfix, Cookie, Header, Standard), berücksichtigen `localeCookie: null` und `autoDetectLanguage: false` und cachen ein Wörterbuch pro Locale.
- Ein fehlerhaftes Locale-Cookie wird ignoriert und unverändert gelassen, statt das SSR scheitern zu lassen.
- Der Hash-Modus liest nur das Cookie `hash-locale`. Ein einzelnes `user-locale=de` zählt nicht mehr.
- `NUXT_I18N_DEFAULT_LOCALE` und Laufzeit-`disabledLocales` ändern das Routing.
- **Die `premerged`-Ausgabe hat sich geändert.** `/{apiBaseUrl}/<page>/<locale>/data.json` enthält nur, was sich von `__root/<locale>/data.json` unterscheidet. Alles, was diese Dateien direkt liest, muss die beiden zusammenführen. Ein vollständiges Wörterbuch ist weiterhin eine gültige Datei.
- **Wörterbücher folgen `app.cdnURL`.** Der Browser lädt sie von `<cdnURL>/_locales/...`, wo er früher `app.baseURL` verwendete. Das CDN muss `_locales/` enthalten und den Origin Ihrer Website erlauben. Siehe [App-baseURL und Payload-Hosts](/de/guide/deployment#app-baseurl-and-payload-hosts).
- Kein Nitro-Route-Cache auf `/{apiBaseUrl}/**`, und der Header `s-maxage=60, stale-while-revalidate` entfällt. Wenn Sie sich auf diesen Cache verlassen haben, schalten Sie ein CDN vor die Payload-Route.
- `/{apiBaseUrl}/<page without a folder>/<locale>/data.json` antwortet mit dem Root-Wörterbuch, früher mit `{}`. Ein 404 eines Hosts wird jetzt als 404 durchgereicht, wo früher `200 {}` geantwortet wurde.
- Ein Prerender, der sein Wörterbuch nicht laden kann, scheitert mit einem 500 und einer Warnung, und mit Nuxts Standard-`failOnError` endet der Build mit 1.
- Eine geänderte Übersetzung ohne Neubau erreicht einen Browser nur, wenn sich `v` ändert: Setzen Sie `NUXT_I18N_DATE_BUILD`.
- SSR fragt `/{apiBaseUrl}` nicht mehr über HTTP an, es sei denn, `apiBaseServerHost` ist gesetzt.

### Übersetzungen {#translations}

- Zusammenführungen sind auf jeder Ebene tief, und Fallback-Ketten werden bis zum Ende verfolgt.
- Die Zusammenführung erfolgt nach Locale: Die Root-Datei der aktiven Locale schlägt die Seitendatei einer Fallback-Locale.
- Eine Seite ohne eigenen `pages/<name>/`-Ordner liest in Produktion das Root-Wörterbuch. Früher erhielt sie `{}`.
- `disablePageLocales: true` liest nur die Root-Dateien.
- Die Schlüssel der verlassenen Seite werden nach der Navigation nicht mehr aufgelöst. Wenn ein Layout Schlüssel verwendete, die nur die Datei der vorherigen Seite hatte, verschieben Sie sie in die Root-Datei.
- Eine defekte Locale-Datei warnt in jedem Modus einmal mit ihrem Pfad. Dev warf früher einen Fehler.

### `@i18n-micro/*`-Pakete {#@i18n-micro/*-packages}

Jedes `@i18n-micro/*`-Paket ist auf 2.0.0, einschließlich `@i18n-micro/types` und des neuen `@i18n-micro/cli`.

**`@i18n-micro/react`, `preact`, `solid`**

- Router-Adapter wurden nach `/router` verschoben: `createReactRouterAdapter`, `createSolidRouterAdapter` und Preacts `createBrowserHistoryAdapter`. `createPreactRouterAdapter` wurde entfernt.
- `I18nT` folgt `<i18n-t>` oben. Die Attribute `dangerouslySetInnerHTML`, `innerHTML` und `textContent` werden verworfen.
- `I18nSwitcher` rendert `<a href>`-Einträge mit `aria-current="page"`, `▾`, logischem CSS und `language-switcher` am Button. Kein `aria-haspopup`. `className` ergänzt `i18n-switcher-wrapper`.
- Ein Link zu `/` oder einem Locale-Root ist nur bei exakter Übereinstimmung aktiv (React, Preact).
- `I18nLink` behält ein benutzerdefiniertes `onClick` und `style` und überlässt einen modifizierten Klick dem Browser. Query und Hash zählen für die Aktiv-Prüfung nicht. Ohne Router ist kein Link aktiv.
- React und Preact: `I18nLocalesContext`, `I18nDefaultLocaleContext` und `I18nRouterContext` sind zu einem `I18nConfigContext` zusammengefasst. Solid: Ein `I18nContext` enthält `{ i18n, locales, defaultLocale, router }`.
- `getCurrentPath` der Adapter enthält Query und Hash, und ein wiederholter Schlüssel in `getRoute().query` ist ein Array.
- Ein verschachtelter `I18nProvider` ohne `i18n` behält die äußere Instanz, und ein Provider ganz ohne Instanz wirft einen Fehler.
- `defaultLocale()` ohne Wert ist `fallbackLocale`.
- Solid: `getCurrentPathAccessor` wurde entfernt. `useI18n()` wirft ohne `locales` keinen Fehler mehr.
- React: `use-sync-external-store` ist keine Abhängigkeit mehr, und `react-dom` ist ein optionaler Peer.

**`@i18n-micro/vue`, `vitepress`**

- `I18nT` ist eine funktionale Komponente.
- `I18nSwitcher` und `I18nLink` folgen den Abschnitten oben. `aria-haspopup` entfällt.
- `I18nLink` und `createVueRouterAdapter` lösen `name`, `query` und `hash` auf. Ein unbekannter `name` wirft einen Fehler, wie bei `RouterLink`.
- `useLocaleHead` erzeugt kein `//de/` mehr. Canonical und `hreflang` einer Seite stimmen überein (`/de`), und Query-Params aus der Whitelist erreichen sie.
- `I18nRoutingStrategy.resolvePath` kann ein Location-Objekt und einen Pfad mit Query und Hash erhalten. Neu ist das optionale `toHref`.
- VitePress: Links, der Switcher, `push` und `replace` tragen `site.base`.

**`@i18n-micro/astro`**

- `i18nIntegration` bündelt `translationDir` und installiert die Middleware: Löschen Sie eine `src/middleware.ts`, die nur das Setup kopiert, oder übergeben Sie `middleware: false`. Eine eigene `src/middleware.ts` übergibt `base: config.base`.
- `i18nIntegration` wirft bei `messages`, `plural`, `missingHandler` und `routingStrategy` einen Fehler: Übergeben Sie diese an `createI18n` oder `createI18nMiddleware`, mit `middleware: false`. Optionen, die nie etwas bewirkt haben, sind aus ihrem Typ entfernt.
- `loadTranslationsFromDir` und `loadTranslationsIntoI18n` wurden nach `@i18n-micro/astro/node` verschoben, das nur ESM ist.
- `getGlobalRoutingStrategy`, `setGlobalRoutingStrategy` und `runWithRoutingStrategy` wurden entfernt: Lesen Sie `Astro.locals.routingStrategy`.
- `clone()` heißt `fork()`, und die Option `_storage` entfällt.
- Dynamische Seiten sind eine Route: `/blog/hello` ist `blog-slug`, früher `blog-hello`. Verschieben Sie `pages/blog-hello/` nach `pages/blog-slug/`. Ein benutzerdefiniertes `getRouteName` erhält das Muster als drittes Argument.
- Die URL bestimmt die Seiten-Locale. `autoDetect` ist ein 302 von `/` zur Startseite der bevorzugten Locale. Neue Option `localeCookie`, und `redirectToDefault` ist implementiert.
- Ein Seitenaufruf von einer Seite desselben Origins in einer anderen Locale schreibt das Locale-Cookie und leitet nicht weiter. Server Islands und Actions leiten nie weiter und tragen `Vary: Referer`.
- `config.localeCodes` lässt deaktivierte Locales weg, und `prepareLocaleRewrite` antwortet für sie mit 404.
- `getI18nProps()` ohne Schlüssel sendet alles, was `t()` auf der Seite beantworten kann, mit einer Dev-Warnung über 20 KB. Übergeben Sie die Schlüssel, die die Island verwendet.
- `useLocaleHead`: Die Standard-`baseUrl` ist `site`, sonst Root-relativ. Links und Metas tragen `id`.
- `<I18nT html>` escaped `params`, und eine leere Übersetzung rendert leer.
- `<I18nLink>` und `localizePath` lassen externe URLs, `#hash` und `?query` unangetastet und behalten einen abschließenden Schrägstrich.
- `<I18nSwitcher>` behält die Query und verwendet `data-i18n-switcher` statt generierter IDs.
- `@i18n-micro/astro/client` hat nur noch `translate` und `hasTranslation`: Importieren Sie Adapter aus `/client/vue`, `/client/react`, `/client/preact` und `/client/svelte`. `client/vue` benötigt ein installiertes `vue`.
- Islands: `has()` ist für einen Teilbaum true, `t('')` ist `''`. `provideI18n` nimmt einen Getter entgegen, um neuen Props zu folgen.
- `getLocale` und `getDefaultLocale` werfen ohne die Middleware einen Fehler.

**`@i18n-micro/runtime`, `node`**

- Ein Schreibzugriff auf eine Locale, die weder aktiv noch Fallback ist, benachrichtigt keine Subscriber.
- `addRouteTranslations(locale, route, messages, false)` ersetzt den Chunk.
- `loadFromUrls` lädt parallel und schreibt nichts, wenn einer fehlschlägt.
- Node: `reload()` tauscht Wörterbücher aus, statt sie zuerst zu leeren, und protokolliert keine Erfolgsmeldung. Ein nicht mehr vorhandenes Verzeichnis behält die alten.
- Node, Astro, VitePress: ein einziger Leser für einen Locales-Ordner. Ein fehlender Ordner erzeugt eine Warnung, eine Datei, die kein JSON-Objekt ist, wird gemeldet und übersprungen, und Meldungen beginnen mit `[i18n]`.

**`@i18n-micro/test-utils`**

- Der Mock folgt den echten Übersetzungsregeln: `tc('a', 1.5)` nimmt die letzte Form, `td('nope')` ist `Invalid Date`, `t(miss, undefined, '')` ist der Schlüssel, und ein Fehltreffer wird nicht mehr protokolliert.

**`@i18n-micro/types-generator`**

## Migration {#migration}

1. Prüfen Sie die Voraussetzungen: Nuxt 3.18, Node 20 und React 18, falls Sie `@i18n-micro/react` verwenden.
2. Aktualisieren Sie `nuxt-i18n-micro` und alle `@i18n-micro/*`-Pakete gemeinsam. Entfernen Sie `@i18n-micro/hmr`. Fügen Sie `@i18n-micro/test-utils` als Dev-Dependency hinzu, wenn Ihre Tests es importieren. Ersetzen Sie `nuxt-i18n-micro-cli` durch `@i18n-micro/cli` und folgen Sie [seiner Befehlstabelle](/de/guide/cli#moving-from-nuxt-i18n-micro-cli).
3. Durchsuchen Sie Ihren Code nach `switchLocaleRoute(` aus `@i18n-micro/path-strategy`, `i18n-plugin-hooks`, `i18n-plugin-define`, `localized-`-Routennamen, `$getI18nConfig().globalLocaleRoutes` und den anderen entfernten Konfigurationsschlüsseln, `ModuleHooks` sowie `@ts-expect-error` an `i18n:register`.
4. Verschieben Sie Markup aus den Params von `<i18n-t html>` in die Übersetzung und übergeben Sie Daten als Params.
5. Wenn Sie `baseUrl` setzen: Überprüfen Sie mit `$localeRoute` erstellte Links, setzen Sie `trustForwardedHost` hinter einem Proxy und führen Sie `nuxi generate` einmal pro Domain mit `NUXT_I18N_DOMAIN` aus.
6. Prüfen Sie Ihre URLs anhand Ihrer Strategie: `/en` unter `prefix_except_default`, Locale-ähnliche CMS-Slugs, `routeRules`-Redirects und `excludePatterns`.
7. Prüfen Sie den Cache-Key Ihres CDN auf `Vary` und erlauben Sie den Preload-Link in einer strengen CSP. Mit `app.cdnURL` legen Sie `_locales/` auf das CDN und erlauben CORS.
8. Wenn ein Tool `/_locales/...`-Dateien direkt liest, führen Sie die Seitendatei über `__root/<locale>/data.json` zusammen.
9. Wenn ein globaler Guard die Locale oder das Wörterbuch liest, stellen Sie sicher, dass er laufen kann, bevor die Navigation committet wird. Verschieben Sie Schlüssel, die ein Layout aus der Datei der vorherigen Seite übernommen hat, in die Root-Datei.
10. Vergleichen Sie eine `nuxi generate`-Ausgabe oder einen Sitemap-Crawl vorher und nachher: `hreflang`, `x-default`, Canonical und die Seitenliste ändern sich beabsichtigt.
11. Aktualisieren Sie Importe für Framework-Pakete: `/router` für React-, Solid- und Preact-Adapter, `/node` für die Loader von Astro und `I18nTypesPlugin(o)` für das Types-Plugin.
12. Für Astro löschen Sie eine `src/middleware.ts`, die nur das Setup kopiert, und benennen Wörterbücher im Stil von `pages/blog-hello/` nach ihrem Muster um.
13. Aktualisieren Sie Tests, die `router-link-active`, `li button`, `▼` oder altes Mock-Verhalten festgeschrieben haben.

Details und jeder Sonderfall: [Upgrade](/de/guide/upgrade).

## Warum das wichtig ist {#why-it-matters}

- **Korrekt durch Konstruktion:** Links, Redirects und SEO-Tags stammen aus den Routen, die die App tatsächlich hat.
- **Eine Antwort überall:** Ein Build, der Source-Modus und Dev liefern dasselbe Wörterbuch, und jeder Aufrufer verwendet eine Erkennungsreihenfolge.
- **Domains:** ein Deployment für jede Locale-Domain, ohne zweiten Build.
- **Sicherere Standards:** escapete Params, begrenzte Caches, Links, die auf Ihrem Origin bleiben.
- **Weniger auszuliefern:** kleinere Wörterbuchdateien, kleinere Routing-Pakete und gemeinsame Logik an einem Ort.

Die vollständige Liste der Änderungen finden Sie unter [Upgrade](/de/guide/upgrade) und im [Changelog](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
