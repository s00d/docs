**Datum**: 2026-06-25

**Version**: `v3.21.0`

![v3.21.0 release](/images/3.21.0.png)

Dieses Release führt **`useI18nHead`** ein – ein Composable auf Seitenebene für i18n-SEO-Überschreibungen zusätzlich zum eingebauten `02.meta`-Plugin. Passe `hreflang`, Canonical, `og:url` und Open-Graph-Tags pro Route an, ohne eigenes Meta-Plugin oder `meta: false`.

## Was ist neu? {#what’s-new}

### `useI18nHead`-Composable {#usei18nhead-composable}

Rufe `useI18nHead` in einer beliebigen Seite auf, wenn `meta: true` (Standard) gesetzt ist. Das Modul führt deine Eingabe bei jeder Routenaktualisierung nach `useLocaleHead` zusammen:

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

Unterstützt statische Objekte, reaktive Getter, Anhängen von `meta` / `link`, `replace` für eingebaute Gruppen und `disable`, um automatisch generierte Tags zu entfernen. Siehe [`useI18nHead`](/de/composables/useI18nHead).

### `mergeI18nHead`-Hilfsfunktion (`@i18n-micro/utils`) {#mergei18nhead-utility-@i18n-micro/utils}

Die framework-unabhängige Merge-Logik liegt in `@i18n-micro/utils/merge-i18n-head` – sie wird vom `02.meta`-Plugin verwendet und ist isoliert testbar. Die Typen (`I18nHeadInput`, `I18nHeadLink`, `I18nHeadMeta`) werden aus `@i18n-micro/types` exportiert.

### Plugin-Integration {#plugin-integration}

- **`02.meta`** – führt die Ausgabe von `useLocaleHead` über `useHead` mit dem Seitenzustand aus `useI18nHead` zusammen
- **`01.plugin`** – setzt Seitenüberschreibungen bei Änderung des Routennamens über `resetPageHead()` zurück (gemeinsamer Zustand mit dem Composable)

## Typische Anwendungsfälle {#typical-use-cases}

| Szenario                                     | Ansatz                                                         |
| -------------------------------------------- | -------------------------------------------------------------- |
| Blog/CMS mit teilweisen Übersetzungen        | `replace.hreflang` + `replace.ogAlternates` aus API-Locales    |
| Eigene Canonical-URL aus dem CMS             | `replace.canonical` + `replace.ogUrl`                          |
| Nur OG auf einer Landingpage                 | `meta: [{ property: 'og:title', ... }]` – hreflang des Moduls beibehalten |
| Kein hreflang auf einer Seite                | `disable: ['hreflang', 'x-default']`                           |
| Eigenes Plugin ersetzen (`i18nManualHreflang`) | `useI18nHead` pro Inhaltsseite + `meta: true`                |

**JSON-LD** bleibt in `useHead({ script: [...] })` – `useI18nHead` erzeugt keine strukturierten Daten.

## Breaking Changes {#breaking-changes}

Keine bei normaler Verwendung von `nuxt.config`. Das neue Composable und der Utils-Subpfad sind rein additiv.

## Warum das wichtig ist {#why-it-matters}

- **Kein eigenes Meta-Plugin** für CMS-Beiträge, News oder Leitfäden mit URLs pro Locale
- **Eine einzige Pipeline** – Modul-Standards + Seitenüberschreibungen in einem `useHead`-Aufruf
- **Typsicher** – `I18nHeadInput` für Helfer wie `buildArticleHead(content)`
