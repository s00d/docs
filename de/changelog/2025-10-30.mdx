**Datum**: 2025-10-30

**Version**: `v2.0.0`

![v2.0.0 release](/images/2.0.0.png)

Wir führen serverseitiges HMR für Übersetzungsdateien in der Entwicklung ein. Wenn sich eine JSON-Übersetzung ändert, invalidiert der Server-Cache nur die betroffenen Schlüssel, und nachfolgende Anfragen erhalten sofort frische Daten – ganz ohne Neustart.

## Was ist neu? {#what’s-new}

- Serverseitiges HMR für Übersetzungsdateien
- Sofortige Cache-Invalidierung pro Seite/Locale
- Nahtlose DX beim Bearbeiten von Inhalten

## Funktionsweise {#how-it-works}

- Ein Watcher in `src/runtime/server/plugins/watcher.dev.ts` überwacht `<rootDir>/<translationDir>/**/*.json`
- Seitendateien (z. B. `pages/<page>/<locale>.json`) invalidieren `_locales:merged:<page>:<locale>`
- Dateien auf Root-Ebene (z. B. `<locale>.json`) invalidieren alle zusammengeführten Schlüssel für diese Locale
- Wird in der Entwicklung automatisch aus `src/module.ts` registriert, wenn `experimental.hmr !== false`

## Konfiguration {#configuration}

```ts
export default defineNuxtConfig({
  i18n: {
    experimental: { hmr: true }, // default in dev
  },
})
```
