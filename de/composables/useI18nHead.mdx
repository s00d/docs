---
title: "useI18nHead"
description: "useI18nHead überschreibt die generierten i18n-SEO-Tags für eine einzelne Seite: Canonical-, hreflang- und og-Tags ersetzen oder entfernen oder eigene hinzufügen."
---

`useI18nHead()` ändert die vom Modul generierten SEO-Tags, und zwar nur für eine Seite. Verwenden Sie es, wenn eine Seite es besser weiß als der Router: ein CMS-Artikel, der nur in einigen Locales existiert, eine Canonical-URL aus einer API, zusätzliche `og:`-Tags. Sie erhalten die generierten Tags, über die Ihre Überschreibungen gelegt werden.

## Signatur {#signature}

```ts
useI18nHead(input?: MaybeRefOrGetter<I18nHeadInput | null>): { pageHead: any; resetPageHead: () => void }
```

Registriert Überschreibungen auf Seitenebene für i18n-SEO-Head-Tags.
Wird vom Plugin `02.meta` über die Ausgabe von `useLocaleHead` gelegt.

Verwenden Sie bevorzugt einen Getter (`() => ({ … })`), wenn Werte aus `$t` / `t` stammen, damit sie
bei einem Locale-Wechsel neu aufgelöst werden. Ein einfaches Objekt wird einmal ausgewertet und bleibt danach unverändert.

| Parameter | Typ | Beschreibung |
| --- | --- | --- |
| `input` *(optional)* | `MaybeRefOrGetter<I18nHeadInput \| null>` |  |

Es funktioniert mit [`meta: true`](/de/api/module-options#meta) (Standard): Das Meta-Plugin des Moduls legt die Eingabe bei jedem Head-Rendering über die Ausgabe von [`useLocaleHead`](/de/composables/useLocaleHead). Mit `meta: false` liest niemand sie aus.

Die Überschreibung wird zurückgesetzt, wenn sich der Routenname ändert. Eine Seite, die `disableMeta` setzt, erhält überhaupt keine i18n-Tags, Überschreibungen eingeschlossen.

## Eingabe {#input}

`I18nHeadInput` (aus `@i18n-micro/types`):

| Schlüssel | Typ | Wirkung |
| --- | --- | --- |
| `htmlAttrs` | `Record<string, string>` | Wird in die Attribute von `<html>` (`lang`, `dir`) übernommen. |
| `meta` | `I18nHeadMeta[]` | Wird nach den generierten Tags hinzugefügt; ersetzt ein Tag mit gleichem `id`, `property` oder `name`. |
| `link` | `I18nHeadLink[]` | Wird nach den generierten Links hinzugefügt; ersetzt einen Link mit gleichem `id` oder gleichem `rel` + `hreflang`. |
| `replace.canonical` | `string \| false` | Ersetzt das Canonical-`href` oder entfernt den Link. |
| `replace.hreflang` | `I18nHeadLink[] \| false` | Ersetzt oder entfernt **jeden** `rel="alternate"`-Link, `x-default` eingeschlossen. |
| `replace.xDefault` | `I18nHeadLink \| false` | Ersetzt oder entfernt den `x-default`-Link. |
| `replace.ogLocale` | `string \| false` | Ersetzt oder entfernt `og:locale`. |
| `replace.ogUrl` | `string \| false` | Ersetzt oder entfernt `og:url`. |
| `replace.ogAlternates` | `string[] \| false` | Baut `og:locale:alternate` aus diesen Locale-Codes neu auf (über `og` / `iso`), wobei die aktuelle Locale, unbekannte Codes und Codes ohne `og`- oder `iso`-Wert übersprungen werden, oder entfernt die Tags. |
| `disable` | `I18nHeadDisableGroup[]` | Entfernt generierte Gruppen: `'hreflang'` (nicht `x-default`), `'x-default'`, `'canonical'`, `'og'` (`og:locale` + `og:url`), `'og-alternates'`, `'html'`. |

Reihenfolge der Anwendung: `disable`, dann `replace`, dann `htmlAttrs`, `meta`, `link`.

## Beispiel {#example}

Ein Artikel, der nur in einigen Locales existiert, mit alternativen URLs aus der API:

```vue
<script setup lang="ts">
const route = useRoute()
const { t } = useI18n()
const { data: article } = await useFetch<{ title: string; urls: Record<string, string> }>(`/api/articles/${route.params.slug}`)

useI18nHead(() => {
  if (!article.value) return null
  const codes = Object.keys(article.value.urls)
  return {
    meta: [{ property: 'og:title', content: article.value.title || t('blog.title') }],
    replace: {
      hreflang: codes.map((code) => ({ rel: 'alternate', hreflang: code, href: article.value!.urls[code]! })),
      ogAlternates: codes,
    },
  }
})
</script>
```

Übergeben Sie wie hier einen Getter, wenn Werte aus `t()` oder asynchronen Daten stammen: Er wird bei einem Locale-Wechsel erneut ausgeführt. Ein einfaches Objekt wird nur einmal gelesen.
