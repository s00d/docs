**التاريخ**: 2026-06-25

**الإصدار**: `v3.21.0`

![v3.21.0 release](/images/3.21.0.png)

يضيف هذا الإصدار **`useI18nHead`**، وهو composable على مستوى الصفحة لتجاوزات SEO الخاصة بـ i18n فوق الإضافة المدمجة `02.meta`. خصّص وسوم `hreflang` وcanonical و`og:url` وOpen Graph لكل مسار دون إضافة meta مخصصة أو `meta: false`.

## ما الجديد؟ {#what’s-new}

### الـ Composable `useI18nHead` {#usei18nhead-composable}

استدعِ `useI18nHead` في أي صفحة عندما يكون `meta: true` (الافتراضي). تدمج الوحدة مدخلاتك بعد `useLocaleHead` عند كل تحديث للمسار:

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

يدعم الكائنات الثابتة، والدوال المُرجِعة التفاعلية (getters)، والإلحاق عبر `meta` / `link`، و`replace` للمجموعات المدمجة، و`disable` لإزالة الوسوم المولَّدة تلقائيًا. راجع [`useI18nHead`](/ar/composables/useI18nHead).

### الأداة المساعدة `mergeI18nHead` (`@i18n-micro/utils`) {#mergei18nhead-utility-i18n-microutils}

يوجد منطق الدمج المستقل عن أي إطار عمل في `@i18n-micro/utils/merge-i18n-head`، وتستخدمه الإضافة `02.meta` ويمكن اختباره بمعزل. تُصدَّر الأنواع (`I18nHeadInput` و`I18nHeadLink` و`I18nHeadMeta`) من `@i18n-micro/types`.

### التكامل مع الإضافات {#plugin-integration}

- **`02.meta`** — يدمج مخرجات `useLocaleHead` مع حالة الصفحة من `useI18nHead` عبر `useHead`
- **`01.plugin`** — يعيد ضبط تجاوزات الصفحة عند تغيّر اسم المسار عبر `resetPageHead()` (حالة مشتركة مع الـ composable)

### التوثيق والاختبارات {#documentation-tests}

- دليل جديد: [`useI18nHead`](/ar/composables/useI18nHead) مع أمثلة لأنظمة إدارة المحتوى والمقالات
- تحديث [SEO](/ar/guide/seo) و[`useLocaleHead`](/ar/composables/useLocaleHead) — متى تستخدم كل واجهة
- تغطية بـ Playwright وVitest: SSR، والتنقل في SPA، وإعادة التحميل، و`nuxi generate`، والبدائل الجزئية، و`x-default`، والتحميل التفاعلي على العميل

## حالات الاستخدام النموذجية {#typical-use-cases}

| السيناريو                                     | النهج                                                       |
| -------------------------------------------- | -------------------------------------------------------------- |
| مدوّنة/نظام إدارة محتوى بترجمات جزئية           | `replace.hreflang` + `replace.ogAlternates` من لغات الواجهة البرمجية   |
| canonical مخصص من نظام إدارة المحتوى                    | `replace.canonical` + `replace.ogUrl`                          |
| OG فقط لصفحة هبوط                         | `meta: [{ property: 'og:title', ... }]` — مع الإبقاء على hreflang الخاص بالوحدة |
| بلا hreflang في صفحة                        | `disable: ['hreflang', 'x-default']`                           |
| استبدال إضافة مخصصة (`i18nManualHreflang`) | `useI18nHead` لكل صفحة محتوى + `meta: true`                  |

يبقى **JSON-LD** في `useHead({ script: [...] })`، إذ لا يولّد `useI18nHead` بيانات منظَّمة.

## التغييرات الجذرية {#breaking-changes}

لا شيء عند الاستخدام المعتاد لـ `nuxt.config`. الـ composable الجديد والمسار الفرعي للأدوات المساعدة إضافات لا تكسر شيئًا.

## لماذا يهم ذلك {#why-it-matters}

- **لا حاجة إلى إضافة meta مخصصة** لمنشورات أنظمة إدارة المحتوى أو الأخبار أو الأدلة ذات عناوين URL لكل لغة
- **مسار معالجة واحد** — إعدادات الوحدة الافتراضية + تجاوزات الصفحة في استدعاء `useHead` واحد
- **آمن من حيث الأنواع** — `I18nHeadInput` للدوال المساعدة مثل `buildArticleHead(content)`

سيُنشر سجل التغييرات الكامل مع الإصدار على [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
