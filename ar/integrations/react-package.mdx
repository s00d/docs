تغلّف `@i18n-micro/react` و`@i18n-micro/preact` [وقت التشغيل](/ar/integrations/runtime-package) المستقل عن أطر العمل في مزوِّد، وhook باسم `useI18n()`، وأربعة مكونات. استخدمهما في تطبيق React أو Preact غير مبني باستخدام Nuxt. تملك الحزمتان واجهة API نفسها؛ يسرد قسم [Preact](#preact) الفروق القليلة، والنموذج المشترك موجود في [أطر العمل](/ar/integrations/overview).

## التثبيت {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/react
```

```bash npm
npm install @i18n-micro/react
```

```bash yarn
yarn add @i18n-micro/react
```

</CodeGroup>

التبعيات النظيرة: `react` `^18.0.0 || ^19.0.0`؛ و`react-dom` (اختيارية، للعرض)؛ و`react-router-dom` `^6.0.0 || ^7.0.0` (اختيارية، فقط لـ `@i18n-micro/react/router`). مُختبرة على React 19.3 و18.3، وReact Router 7.18 و6.30.

## الإعداد {#setup}

```tsx
// src/main.tsx
import { createRoot } from 'react-dom/client'
import { createI18n, I18nProvider } from '@i18n-micro/react'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

createRoot(document.getElementById('root')!).render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
    <App />
  </I18nProvider>,
)
```

<Warning>

أنشئ النسخة مرة واحدة، على مستوى الوحدة أو في مُهيِّئ `useState`، وليس أبدًا في جسم مكوّن.

</Warning>

يأخذ `<I18nProvider>` الخصائص `i18n` و`locales` و`defaultLocale` و`routingStrategy`:

- الخاصية المحذوفة تحتفظ بقيمة المزوِّد الخارجي، بما في ذلك النسخة.
- إن لم توجد نسخة على الإطلاق، يبني واحدة من خيارات `createI18n` المجاورة لها، لذا تبقى الخصائص بيانات عادية: `<I18nProvider locale="de" messages={messages}>`.
- تؤدي خاصية `locale` جديدة إلى بناء نسخة جديدة بقيمة `messages` لذلك العرض. تعيش هذه النسخة في المكوّن: إن عُلِّق شيء فوقه أثناء التركيب، يتخلص منها React، مع كل ما أُضيف إليها.

جميع خيارات `createI18n`، بما فيها `routeMessages`، موجودة في [النسخة](/ar/integrations/overview#the-instance).

## الترجمة {#translate}

```tsx
import { useI18n } from '@i18n-micro/react'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' })}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

تعيد `useI18n()`:

| المجموعة | الأعضاء |
| --- | --- |
| الترجمة | `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` |
| الـ Locale والمسار | `locale`, `fallbackLocale`, `currentRoute`, `setLocale`, `setRoute`, `getRoute`, `getLocales`, `defaultLocale()`, `getLocaleName` |
| التوجيه | `switchLocale`, `localePath`, `localeRoute` |
| القواميس | `addTranslations`, `addRouteTranslations`, `clearCache` |

- يُعاد عرض المكوّن عندما يتغير الـ locale أو المسار أو قاموس قابل للقراءة، وعندما يحصل المزوِّد على كائن `locales` أو `routingStrategy` جديد. قاموس locale ليس نشطًا ولا احتياطيًا لا يسبب أي عرض.
- لا تتغير `t` ودوال الترجمة الأخرى إلا مع المخزن، لذا فهي آمنة في `memo` وتبعيات التأثيرات.

`useT` سلسلة واحدة كقيمة. لا يُعرض المكوّن إلا عندما تتغير تلك السلسلة، مهما حدث لخصائص المزوِّد الأخرى؛ ولا يعتمد `<I18nT>` عليها أيضًا:

```tsx
const title = useT('page.title')
```

حمّل المزيد من القواميس في أي وقت:

```tsx
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

useEffect(() => {
  import('./locales/de.json').then((m) => addTranslations('de', m.default))
  addRouteTranslations('en', 'about', { title: 'About us' })
  setRoute('about') // t('title') now reads the 'about' dictionary first
}, [])
```

تملك النسخة نفسها أيضًا `loadFromUrl(url, { locale, routeName })` لتحميل JSON عبر `fetch`.

## تبديل الـ locale {#switch-locale}

```tsx
const { setLocale, switchLocale } = useI18n()

setLocale('de') // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

لا يحمّل التبديل أي شيء؛ أضف قاموس الـ locale أولًا. الكتابة في المخزن متزامنة بالنسبة إلى React، حتى داخل `startTransition`، لذا فإن المكوّن الذي يُعلَّق بسبب قاموس مفقود سيعرض الـ fallback الخاص به. تحمّل `useLocaleSwitch` أولًا وتحتفظ بالواجهة القديمة حتى يصبح القاموس جاهزًا:

```tsx
const [switchTo, pending] = useLocaleSwitch((locale) => i18n.loadFromUrl(`/locales/${locale}.json`, { locale }))

<button disabled={pending} onClick={() => switchTo('de')}>Deutsch</button>
```

آخر استدعاء هو الذي يفوز. يُرفض التحميل الفاشل ويترك الـ locale كما كان.

يمرر `<I18nGroup>` دالة `t` ذات بادئة إلى ابن من نوع render-prop. أما `<I18nT>` و`t()` بداخله فلا تحملان بادئة:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## التوجيه {#routing}

يقع محوِّل React Router في مسار فرعي حتى لا تستورد نقطة الدخول الرئيسية `react-router-dom` أبدًا. يحتاج إلى `useLocation()` و`useNavigate()`، لذا أنشئه داخل مكوّن تحت الموجِّه:

```tsx
// src/App.tsx
import { useMemo } from 'react'
import { BrowserRouter, Route, Routes, useLocation, useNavigate } from 'react-router-dom'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/react'
import { createReactRouterAdapter } from '@i18n-micro/react/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Localized() {
  const location = useLocation()
  const navigate = useNavigate()
  // memoized: a new object on every render re-renders every `useI18n()` consumer
  const routingStrategy = useMemo(() => createReactRouterAdapter(locales, 'en', location, navigate), [location, navigate])
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      <Routes>
        <Route path="/:locale?" element={<Home />} />
        <Route path="/:locale?/about" element={<About />} />
      </Routes>
    </I18nProvider>
  )
}

export default function App() {
  return (
    <BrowserRouter>
      <Localized />
    </BrowserRouter>
  )
}
```

يضيف المحوِّل بادئة لكل locale ما عدا الافتراضي (`/about`، `/de/about`) ويعرض `<I18nLink>` على أنه `<Link>` الخاص بـ React Router. اضبط الـ locale من عنوان URL بنفسك (مثلًا من `useParams().locale` في تأثير). لأي موجِّه آخر اكتب محوِّلًا يتضمن `getCurrentPath` و`push` و`replace` (جميعها مطلوبة) — راجع [محوِّل الموجِّه](/ar/integrations/overview#router-adapter).

## SSR {#ssr}

تعمل `renderToString`: تملك `useI18n()` لقطة للخادم. أنشئ نسخة واحدة لكل طلب وأضف قواميسها قبل العرض، حتى لا تتشارك الطلبات بـ locales مختلفة الحالة، أو مرّر بيانات عادية إلى المزوِّد.

### الإماهة {#hydration}

تُماه الأرقام وصيغ الجمع والنصوص كما هي. يعتمد التاريخ على المنطقة الزمنية والتاريخ النسبي على الساعة: اضبط `timeZone` على الخادم وفي المتصفح، وبالنسبة إلى `tdr` سلّم المتصفح وقت الخادم عبر `now`. يضبط `<I18nT>` مع `date` أو `relativeDate` الخاصية `suppressHydrationWarning`، لذا لا يُفشل الاختلاف الإماهة، لكن نص الخادم يبقى حتى يتغير النص. يصل ذلك إلى مستوى واحد فقط: لا يزال `children` الذي يغلّف الترجمة في عنصر يفشل عند الاختلاف، لذا امنحه `timeZone` نفسه.

### مكونات الخادم {#server-components}

تَسِم الحزمة شيفرة العميل الخاصة بها بـ `'use client'`. تملك `@i18n-micro/react/server` الدالة `createI18n` و`I18nT` بلا hooks يأخذ النسخة كخاصية، لذا يبقى النص خارج حزمة العميل. تحت الشرط `react-server`، كما في موجِّه التطبيقات في Next.js، تُحَل نقطة الدخول الرئيسية إليها أيضًا، لكن TypeScript لا يعرف ذلك افتراضيًا: استورد من `/server`. تعطي `@i18n-micro/react/client` دائمًا نقطة دخول العميل.

```tsx
// app/[locale]/layout.tsx: a server component
import { cache } from 'react'
import { createI18n, I18nT } from '@i18n-micro/react/server'
import { I18nProvider } from '@i18n-micro/react/client'
import { loadMessages } from './messages'

const getI18n = cache(async (locale: string) => createI18n({ locale, messages: await loadMessages(locale) }))

export default async function Layout({ params, children }) {
  const { locale } = await params
  const i18n = await getI18n(locale)
  return (
    <I18nProvider locale={locale} messages={{ [locale]: i18n.resolveTranslations() }}>
      <h1>
        <I18nT i18n={i18n} keypath="title" />
      </h1>
      {children}
    </I18nProvider>
  )
}
```

معروض عبر `react-server-dom-webpack`؛ لم يُشغَّل تطبيق Next.js نفسه على هذا بعد.

## Preact {#preact}

`@i18n-micro/preact` مبنية من الشيفرة المصدرية نفسها، على Preact نفسه، دون `preact/compat`: النسخة والمزوِّد والـ hooks والمكونات نفسها. الفروق:

| | React | Preact |
| --- | --- | --- |
| التبعية النظيرة | `react` (+ `react-router-dom` اختيارية) | `preact` `^10.0.0 \|\| ^11.0.0`، مُختبرة على 10.29 و11.1 |
| صنف النسخة | `ReactI18n` | `PreactI18n` |
| محوِّل الموجِّه | `createReactRouterAdapter` من `/router` | `createBrowserHistoryAdapter(locales, defaultLocale, ssrUrl?)` من `/router` |
| إعادة العرض | `useSyncExternalStore` | اشتراك layout-effect يعيد فحص المخزن |
| مكونات الخادم | `/server`, `/client` | لا يوجد |

يعمل `createBrowserHistoryAdapter` مع أي موجِّه يعتمد History API (wouter، preact-router): تستدعي `push` و`replace` الدالتين `history.pushState` / `replaceState` وترسلان `popstate`، ويعرض `<I18nLink>` عنصر `<a>` عاديًا ينتقل عبر `push`. لا يملك الخادم شريط عنوان: مرّر عنوان URL للطلب بصفته `ssrUrl`، وإلا تُعرض الروابط ومبدِّل اللغة كما لو كانت على `/`. في المتصفح يفوز شريط العنوان.

```tsx
// src/main.tsx
import { render } from 'preact'
import { createI18n, I18nProvider } from '@i18n-micro/preact'
import { createBrowserHistoryAdapter } from '@i18n-micro/preact/router'
import { App } from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={createBrowserHistoryAdapter(locales, 'en')}>
    <App />
  </I18nProvider>,
  document.getElementById('app')!,
)
```

التواقيع الكاملة: [مرجع Preact](/ar/api/packages/preact).
