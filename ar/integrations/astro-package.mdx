تترجم `@i18n-micro/astro` صفحات Astro على الخادم: يختار وسيط (middleware) اللغة من عنوان URL ويضع نسخة خاصة بكل طلب في `Astro.locals`، ويقرؤها `useI18n(Astro)`. استخدمها في موقع Astro يحتاج إلى عناوين URL ببادئة اللغة (`/about` و`/fr/about`) وقواميس JSON مشتركة. تحصل على مكوّنات `.astro`، وإعادة توجيه من الصفحة الرئيسية إلى لغة الزائر، ووسوم `hreflang`، وخصائص لـ [الجزر](/ar/integrations/astro-islands).

## التثبيت {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/astro
```

```bash npm
npm install @i18n-micro/astro
```

```bash yarn
yarn add @i18n-micro/astro
```

</CodeGroup>

الاعتماديات النظيرة: `astro` `^5.0.0 || ^6.0.0 || ^7.0.0`. اختيارية، فقط لـ [الجزر](/ar/integrations/astro-islands): `vue` `^3.3.0`، و`react` `^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`، و`preact` `^10.0.0 || ^11.0.0`، و`svelte` `^4.0.0 || ^5.0.0`.

## الإعداد {#setup}

أضف التكامل. فهو يدمج قواميسك في الخادم ويثبّت الوسيط، لذا لا حاجة إلى `src/middleware.ts`:

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import node from '@astrojs/node'
import { i18nIntegration } from '@i18n-micro/astro'

export default defineConfig({
  output: 'server',
  adapter: node({ mode: 'standalone' }),
  integrations: [
    i18nIntegration({
      locale: 'en',
      fallbackLocale: 'en',
      locales: [
        { code: 'en', iso: 'en-US', displayName: 'English' },
        { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
        { code: 'fr', iso: 'fr-FR', displayName: 'Français' },
      ],
      translationDir: 'src/locales',
    }),
  ],
})
```

تصبح القواميس شيفرةً وقت البناء: لا يقرأ الخادم من القرص، لذا يعمل على الحافة أيضًا (Cloudflare وVercel Edge). في `astro dev` يُطبَّق تعديل أي ملف عند الطلب التالي.

### خيارات التكامل {#integration-options}

| الخيار | الافتراضي | ملاحظات |
| --- | --- | --- |
| `locale` | مطلوب | اللغة الافتراضية. |
| `fallbackLocale` | `locale` | |
| `locales` | `[]` | كائنات `Locale` كاملة. اللغة ذات `disabled` ليست لغة أي عنوان URL ولا هدفًا لإعادة التوجيه. `iso` هو الوسم الذي تعتمد عليه صيغ الجمع عندما لا يكون الرمز وسمًا صالحًا (`ua` → `uk-UA`). |
| `translationDir` | لا يوجد | المجلد المدمج في الخادم، نسبةً إلى جذر المشروع. |
| `disablePageLocales` | `false` | تُحتسب ملفات الصفحات كترجمات جذرية. |
| `autoDetect` | `true` | إعادة التوجيه من الصفحة الرئيسية، راجع [اكتشاف اللغة](#locale-detection). |
| `redirectToDefault` | `false` | يُعاد توجيه `/` أيضًا عندما لا يوجد ما يفضّل لغة أخرى. |
| `localeCookie` | `'i18n-locale'` | `null` يعطّل ملف تعريف الارتباط. |
| `missingWarn` | `false` | |
| `middleware` | `true` | `false`: اكتب الوسيط بنفسك، راجع أدناه. |

تُنشر إعدادات وقت التشغيل في `virtual:i18n-micro/config` (`config.base` هو `base` الخاص بـ Astro، و`config.localeCodes` الرموز المفعّلة)، والقواميس في `virtual:i18n-micro/messages`.

### وسيطك الخاص {#your-own-middleware}

لا يمكن لقاعدة جمع، ولا لمعالج المفاتيح المفقودة، ولا لمحوّل الموجّه العبور من عملية الإعدادات إلى حزمة الخادم. لهذه الحالات، مرّر `middleware: false` واكتب `src/middleware.ts`. يُضبط حينها إعداد `i18n` في Astro نيابةً عنك مع `routing: 'manual'`، فيعمل `Astro.currentLocale` و`astro:i18n`. لا يسمح Astro بهذا الإعداد دون `src/middleware.ts`، لذا لا يعملان مع وسيط التكامل نفسه.

```ts
// src/middleware.ts
import { config } from 'virtual:i18n-micro/config'
import { messages } from 'virtual:i18n-micro/messages'
import { createAstroRouterAdapter, createI18n, createI18nMiddleware, localeIsoMap } from '@i18n-micro/astro'

const i18n = createI18n({
  locale: config.defaultLocale,
  fallbackLocale: config.fallbackLocale,
  localeIso: localeIsoMap(config.locales),
  messages: messages.root,
  routeMessages: messages.routes,
  plural: myPluralRule,
})

export const onRequest = createI18nMiddleware({
  i18n,
  defaultLocale: config.defaultLocale,
  locales: config.localeCodes,
  localeObjects: config.locales,
  autoDetect: config.autoDetect,
  redirectToDefault: config.redirectToDefault,
  localeCookie: config.localeCookie,
  base: config.base,
  routingStrategy: createAstroRouterAdapter(config.locales, config.defaultLocale),
})
```

لقراءة المجلد في وقت التشغيل بدلًا من ذلك، توجد `loadTranslationsFromDir` و`loadTranslationsIntoI18n` في `@i18n-micro/astro/node` (Node فقط).

### خيارات الوسيط {#middleware-options}

| الخيار | الافتراضي | ملاحظات |
| --- | --- | --- |
| `i18n` | مطلوب | النسخة العامة؛ يحصل كل طلب على `i18n.fork(locale)`، الذي يكلّف الشيء نفسه مهما كان عدد القواميس. |
| `defaultLocale` | مطلوب | |
| `locales` | مطلوب | رموز اللغات. |
| `localeObjects` | `locales` على شكل `{ code }` | كائنات `Locale` كاملة للمكوّنات وSEO. |
| `autoDetect` | `true` | إعادة التوجيه من الصفحة الرئيسية، راجع [اكتشاف اللغة](#locale-detection). |
| `redirectToDefault` | `false` | يُعاد توجيه `/` أيضًا عندما لا يوجد ما يفضّل لغة أخرى، إلى الصفحة الرئيسية للغة الافتراضية كما تحلّلها استراتيجية التوجيه. |
| `localeCookie` | `'i18n-locale'` | `null` يعطّل ملف تعريف الارتباط. |
| `routingStrategy` | بادئة باستثناء الافتراضية | محوّل الموجّه. الدوال التي يغفلها تأتي من المحوّل الافتراضي. |
| `base` | لا يوجد | قيمة `base` في Astro: `config.base`. |

ملفات الصفحات (`src/locales/pages/blog/post/de.json`) هي المسار `blog-post`: مسار الصفحة مربوطًا بـ `-`.

## الترجمة {#translate}

```astro
---
// src/pages/index.astro
import { useI18n } from '@i18n-micro/astro'
import I18nT from '@i18n-micro/astro/i18n-t'

const { t, tc, locale } = useI18n(Astro)
---

<h1>{t('greeting', { name: 'Ada' })}</h1>
<p>{tc('apples', 3)}</p>
<I18nT keypath="welcome" tag="p" />
<p>{locale}</p>
```

تُرجع `useI18n(Astro)` كلًّا من `locale` و`defaultLocale` و`locales` و`t` و`ts` و`tc` و`tn` و`td` و`tdr` و`has` و`getRoute` و`getRouteName(path?)` و`getLocaleFromPath(path?)` و`switchLocalePath(locale)` و`localizePath(path, locale?)` و`getBasePath(url?)` و`getI18n` و`addTranslations` و`addRouteTranslations` و`mergeTranslations` و`clearCache`. وترمي خطأً عندما لا يكون الوسيط قد عمل. تقرأ الدوال المساعدة `getI18n` و`getLocale` و`getDefaultLocale` و`getLocales` القيمة نفسها من `Astro.locals`.

يأتي اسم المسار من المسار دون لغته: `/fr/blog/post` → `blog-post`، وكل عنوان URL لـ `src/pages/blog/[slug].astro` → `blog-slug`، لذا يخدمها جميعًا مجلد واحد `locales/pages/blog-slug/`. `[...path]` هو `path`. مع `base` في Astro تأخذ الدوال المساعدة عناوين URL الخاصة بالموقع وتُرجعها: تتضمنه `switchLocalePath` و`localizePath`، ولا تتضمنه `getBasePath`، لأن `Astro.rewrite` يأخذ المسار بدونه.

### المكوّنات {#components}

استوردها من `@i18n-micro/astro/<name>` (أو `@i18n-micro/astro/components/<name>.astro`):

| المكوّن | الخصائص |
| --- | --- |
| `i18n-t` | `keypath`، `params`، `plural`، `number`، `date`، `relativeDate`، `tag` (`span`، أي وسم)، `html`، `hideIfEmpty`، `defaultValue`؛ وتمرّ السمات الأخرى كما هي. مع `html` تُعرض نتيجة كل فرع كـ HTML وتُهرَّب `params`. لا توجد فتحات (slots) |
| `i18n-link` | `href`، `locale` (اللغة الهدف، الافتراضي الحالية)، `class`؛ وتمرّ السمات الأخرى كما هي. تبقى عناوين URL الخارجية و`#hash` و`?query` كما كُتبت؛ ويحتفظ المسار باستعلامه وhash والشرطة المائلة اللاحقة |
| `i18n-switcher` | `class`، `activeClass` (`'active'`)، `customLabels`؛ يعرض روابط إلى الصفحة الحالية بكل لغة مفعّلة، مع استعلامها |
| `i18n-group` | لا شيء يغيّر المخرجات: `<div>` حول فتحته، بلا بادئة |

## المسارات ببادئة اللغة {#locale-prefixed-routes}

احتفظ بصفحة واحدة لكل مسار في `src/pages/` وأضف ملفات إعادة كتابة رفيعة تحت `src/pages/[locale]/`:

```
src/pages/
  index.astro
  about.astro
  [locale]/
    index.astro
    about.astro
```

```astro
---
// src/pages/[locale]/about.astro
import { prepareLocaleRewrite } from '@i18n-micro/astro'

const target = prepareLocaleRewrite(Astro)
if (target instanceof Response) return target
return Astro.rewrite(target)
---
```

تُرجع `prepareLocaleRewrite` استجابة `404` لقيمة `:locale` غير معروفة، وإلا تضبط اللغة على `Astro.locals` وتُرجع المسار دون البادئة. يحتفظ الوسيط باللغة الموجودة مسبقًا في `locals`، فتُعرض الصفحة المعاد كتابتها بها. تُرجع `getLocaleRewritePath(Astro)` المسار فقط، عندما تتحقق من اللغة بنفسك.

## اكتشاف اللغة {#locale-detection}

يحدد عنوان URL لغة الصفحة:

1. بادئة اللغة (`/fr/about` → `fr`؛ و`/en/about` هي `en` أيضًا).
2. وإلا فما تُرجعه `getLocaleFromPath` في محوّل الموجّه، إن لم تكن الافتراضية.
3. وإلا فاللغة الافتراضية. `/about` هي دائمًا صفحة اللغة الافتراضية، أيًّا كان ما يقوله ملف تعريف الارتباط.

`autoDetect` تلميح لإعادة التوجيه في الصفحة الرئيسية فقط:

- الطلب إلى `/` الذي يفضّل ملف تعريف الارتباط أو `Accept-Language` فيه لغة أخرى يحصل على `302` إلى الصفحة الرئيسية لتلك اللغة (`/de`). تُحترم أوزان q؛ ويطابق `de-DE` لغة `de`، ويطابق `de` لغة `de-DE`.
- مع `redirectToDefault`، يُعاد توجيه `/` دائمًا: إلى الصفحة الرئيسية للغة المفضّلة، وإلا إلى الصفحة الرئيسية للغة الافتراضية.
- تحمل استجابة `/` الترويسة `Vary: Cookie, Accept-Language` (`Accept-Language` فقط عندما يكون `localeCookie` هو `null`).
- الصفحات المعروضة مسبقًا (prerendered) لا تعيد التوجيه أبدًا.

تُرجع `detectLocale(pathname, cookies, headers, defaultLocale, locales, localeCookie?, routingStrategy?, autoDetect?)` اللغة المفضّلة نفسها لمنطقك الخاص.

يتذكر ملف تعريف الارتباط الاختيار. عرض الصفحة القادم من صفحة من الأصل نفسه بلغة أخرى يعني أن الزائر يبدّل اللغة، أيًّا كان الرابط الذي أوصله: تضبط استجابة HTML ملف تعريف الارتباط على اللغة الجديدة، ولا يُعاد توجيه `/`، لذا يصل المبدّل إلى الصفحة الرئيسية للغة الافتراضية. أما نقطة النهاية والصورة وصفحة 404 وإرسال النموذج والجلب المسبق فلا تغيّر شيئًا. "الأصل نفسه" هو ما يقوله المتصفح في `Sec-Fetch-Site`؛ وبدون هذه الترويسة يُقارَن مضيف `Referer` بمضيف الطلب، لذا خلف وكيل (proxy) اضبط `security.allowedDomains` في Astro.

لا تحتوي [جزيرة الخادم](https://docs.astro.build/en/guides/server-islands/) أو الإجراء (action) على لغة في عنوان URL. تُعرض للصفحة التي طلبتها، المقروءة من `Referer`، الذي لا يُحتسب منه إلا المسار، لذا لا يغيّر الوكيل أمام الخادم شيئًا، ولا تعيد التوجيه أبدًا. تحمل استجابتها `Vary: Referer`. بدون `Referer` (سياسة `no-referrer`) تكون باللغة الافتراضية، وفي صفحة ديناميكية يأتي مسارها من عنوان URL، لذا لا تصل إليها قواميس الصفحة.

## محوّل الموجّه {#router-adapter}

يضيف `createAstroRouterAdapter(locales, defaultLocale)` بادئة لكل لغة باستثناء الافتراضية. لا يحتاج محوّل Astro إلا إلى `getCurrentPath`؛ أما الأعضاء الآخرون فاختياريون ويرجعون إلى المحوّل الافتراضي: `getRouteName(path, locales, routePattern?)`، و`getLocaleFromPath`، و`switchLocalePath`، و`localizePath`، و`removeLocaleFromPath`، و`resolvePath` (هدف إعادة التوجيه من الصفحة الرئيسية)، و`push`، و`replace`، و`getRoute`. اكتب محوّلك الخاص لعناوين URL بنطاقات فرعية أو لواحق ومرّره إلى `createI18nMiddleware`.

## SEO {#seo}

```astro
---
// src/layouts/Layout.astro
import { useLocaleHead } from '@i18n-micro/astro'

const head = useLocaleHead(Astro, { baseUrl: 'https://example.com' })
---

<html lang={head.htmlAttrs.lang} dir={head.htmlAttrs.dir}>
  <head>
    {head.link.map((l) => <link rel={l.rel} href={l.href} hreflang={l.hreflang} />)}
    {head.meta.map((m) => <meta property={m.property} content={m.content} />)}
  </head>
  <body><slot /></body>
</html>
```

تُرجع `htmlAttrs` (`lang` من `iso`، و`dir`)، ورابط canonical (المسار دون استعلام)، وبدائل `hreflang` لكل لغة مفعّلة ذات `seo !== false` إضافة إلى `x-default`، و`og:locale` و`og:locale:alternate` و`og:url`. الخيارات: `baseUrl` (`site` من إعدادات Astro، وإلا فعناوين URL نسبية إلى الجذر)، و`addDirAttribute` (`true`)، و`addSeoAttributes` (`true`)، و`hreflangBaseLanguage` (`false`).
