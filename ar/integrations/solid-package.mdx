تمنح `@i18n-micro/solid` تطبيقات SolidJS نسخة i18n مدعومة بالإشارات (signals)، ومزوِّدًا، و`useI18n()`، وأربعة مكونات. استخدمها في تطبيق Solid غير مبني باستخدام Nuxt. قراءات `t()` داخل JSX أو التأثيرات تتتبع الـ locale والمسار والقواميس؛ والنموذج المشترك موجود في [أطر العمل](/ar/integrations/overview).

## التثبيت {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

التبعيات النظيرة: `solid-js` `^1.8.0`؛ و`@solidjs/router` `^0.15.4 || ^1.0.0` (اختيارية، فقط لـ `@i18n-micro/solid/router`). Solid 2 غير مدعوم بعد.

## الإعداد {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

يأخذ `<I18nProvider>` الخصائص `i18n` و`locales` و`defaultLocale` و`routingStrategy`؛ والخاصية المحذوفة تحتفظ بقيمة المزوِّد الخارجي، بما في ذلك النسخة. تقرأ `getLocaleName()` و`<I18nSwitcher>` القيمة `locales`؛ وبدونها لا يوجد ما تعرضانه. الخيارات موجودة في [النسخة](/ar/integrations/overview#the-instance). النسخة هي نسخة [وقت التشغيل](/ar/integrations/runtime-package)، مع إشارة واحدة فوق مخزنها.

## الترجمة {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

استدعِ الدوال داخل JSX أو تأثير حتى يتتبعها Solid، وكذلك `localePath` و`getLocale`؛ فالقيمة المقروءة مرة واحدة في جسم المكوّن لا تتحدث. على النسخة، تتبّع باستخدام `i18n.locale` و`i18n.currentRoute`: تبقى `i18n.getLocale()` عادية، لأن عمليات الكتابة تقرؤها. قراءة الـ locale تستيقظ على الـ locale وحده، لذا يعمل التأثير الذي يقرؤه ويحمّل قاموسًا مرة واحدة. لا تفكك الخصائص ولا تحتفظ بنتائج `t('key')` في متغيرات عادية.

تعيد `useI18n()` القيم `t` و`ts` و`tc` و`tn` و`td` و`tdr` و`has` و`locale` (دالة وصول: `locale()`) و`getLocale` و`getLocales` و`defaultLocale()` و`getLocaleName` و`switchLocale` و`localePath` و`localeRoute` و`setRoute` و`getRoute` و`addTranslations` و`addRouteTranslations` و`resolveTranslations` و`setTranslation` و`clearCache` و`instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## تبديل الـ locale {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

لا يحمّل التبديل أي شيء؛ أضف قاموس الـ locale أولًا.

يمرر `<I18nGroup>` دالة `t` ذات بادئة إلى ابن على شكل دالة. أما `<I18nT>` و`t()` بداخله فلا تحملان بادئة:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## التوجيه {#routing}

يقع محوِّل `@solidjs/router` في مسار فرعي حتى لا تستورد نقطة الدخول الرئيسية الموجِّه أبدًا. استدعِه تحت الموجِّه، عادةً في `root` الخاص بالموجِّه، حيث تعمل `useNavigate` و`useLocation`:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

يضيف المحوِّل بادئة لكل locale ما عدا الافتراضي (`/about`، `/de/about`)، ويعرض `<I18nLink>` على أنه `<A>` الخاص بالموجِّه. تقرأ `getCurrentPath` الموقع التفاعلي للموجِّه، لذا تتبعه الروابط النشطة ومبدِّل اللغة؛ وتحصل الاستراتيجية المخصصة على الشيء نفسه بقراءة إشارة هناك. لاحظ ترتيب الوسائط: `(locales, defaultLocale, navigate, location)`. للموجِّهات الأخرى اكتب محوِّلًا يتضمن `getCurrentPath` و`push` و`replace` (جميعها مطلوبة) — راجع [محوِّل الموجِّه](/ar/integrations/overview#router-adapter).

## SSR {#ssr}

للعرض على الخادم، ابنِ باستخدام `vite-plugin-solid`: يمرر شرط التصدير `solid` في الحزمة الشيفرة المصدرية إليه، فيترجمها للخادم. أما `dist` المبني مسبقًا فهو للمتصفح فقط. لا تملك النسخة `destroy()`؛ أنشئ واحدة لكل تطبيق، أو واحدة لكل طلب على الخادم، ودعها يجمعها جامع البيانات المهملة.
