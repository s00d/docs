[Crowdin](https://crowdin.com/) منصة ترجمة: ترفع ملفات اللغة الافتراضية، ويعمل المترجمون داخل Crowdin، ثم تنزّل اللغات الأخرى. تقرأ الوحدة ملفات JSON عادية، لذا لا يحتاج Crowdin CLI إلا إلى ملف `crowdin.yml` يربط `locales/` و`locales/pages/` بشكل صحيح. لا يتغيّر أي إعداد في الوحدة.

## إعداد crowdin.yml {#configure-crowdin-yml}

```yml
# crowdin.yml
project_id_env: CROWDIN_PROJECT_ID
api_token_env: CROWDIN_PERSONAL_TOKEN
base_path: ./locales
preserve_hierarchy: true

files:
  - source: /en.json
    translation: /%two_letters_code%.json
  - source: /pages/**/en.json
    translation: /pages/**/%two_letters_code%.json
```

- `en` هي لغتك الافتراضية؛ وملفاتها هي المصادر.
- يقرأ `project_id_env` / `api_token_env` المعرّف والرمز المميز (token) من متغيرات البيئة، فلا يُودَع أي سرّ في المستودع.
- يُبقي `preserve_hierarchy: true` مجلدات `pages/<page>/` كما هي.
- يجب أن يساوي اسم الملف المترجم قيمة `code` للغة في `nuxt.config.ts`. يناسب `%two_letters_code%` رموزًا مثل `de`؛ أما لرموز مثل `pt-BR` فاستخدم `%locale%`، أو اربط رموز Crowdin برموزك باستخدام `languages_mapping`.

## الرفع والتنزيل {#upload-and-download}

```bash
npm install -g @crowdin/cli

export CROWDIN_PROJECT_ID=123456
export CROWDIN_PERSONAL_TOKEN=...   # from Crowdin account settings

crowdin upload sources   # push locales/en.json and locales/pages/**/en.json
crowdin download         # write locales/de.json, locales/pages/**/de.json, ...
```

شغّل الأمرين في CI لإبقاء الملفات محدّثة. تصل الملفات المنزّلة إلى مستودعك مثل الملفات المعدّلة يدويًا؛ ويلتقطها البناء التالي أو إعادة التحميل في وضع التطوير.

## قبل الرفع {#before-uploading}

نظّف المصادر أولًا كي لا يعمل المترجمون على مفاتيح ميتة: يزيل [`i18n-micro clean`](/ar/api/cli#clean) المفاتيح غير المستخدمة، ويُبلغ [`i18n-micro check`](/ar/api/cli#check) عن النواقص بعد التنزيل. لا تملك CLI تكاملًا خاصًا بها مع Crowdin: هذه الصفحة هي الطريقة المدعومة.
