يمكن لطبقة Nuxt أن تحمل إعداد i18n ومجلد `locales/` لعدة تطبيقات، ويضيف كل تطبيق ما يحتاجه أو يتجاوزه. تعرض هذه الصفحة ذلك، وكيف يخدم بناء واحد عدة نطاقات.

## شارك الإعداد والترجمات {#share-config-and-translations}

```ts
// base/nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    defaultLocale: 'en',
  },
})
```

```ts
// shop/nuxt.config.ts
export default defineNuxtConfig({
  extends: ['../base'], // a layer directory or package, not a nuxt.config file
  i18n: {
    locales: [
      { code: 'es', iso: 'es-ES' }, // added
      { code: 'fr', disabled: true }, // the base layer's fr, switched off here
    ],
  },
})
```

- **الإعداد:** تستبدل الخيارات العددية في التطبيق خيارات الطبقة. تُجمع مصفوفات `locales` من جميع الطبقات، وتُدمج الإدخالات ذات `code` نفسه في إدخال واحد تتغلب فيه حقول التطبيق، لذا يمكن للتطبيق إضافة locale أو ضبط حقول مثل `disabled: true` على locale موروث.
- **الترجمات:** تُدمج مجلدات `locales/` لكل طبقة مفتاحًا بمفتاح، الطبقة أولًا والتطبيق أخيرًا، لذا يتجاوز مفتاح في `shop/locales/en.json` المفتاح نفسه في `base/locales/en.json`. وتُدمج ملفات الصفحات (`locales/pages/<page>/`) بالطريقة نفسها.
- **الصفحات:** يُقرأ `$defineI18nRoute` من صفحات كل طبقة.

لدمج مجلدات ليست جزءًا من طبقة، أدرجها في [`additionalTranslationDirs`](/ar/api/module-options#additionaltranslationdirs).

## نطاقات متعددة {#multiple-domains}

يخدم بناء واحد كل النطاقات. أدرج كل locale مع نطاقه؛ ويجعله `baseDefault` الافتراضي لذلك المضيف:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'de', iso: 'de-DE', baseUrl: 'https://example.de', baseDefault: true },
      { code: 'nl', iso: 'nl-NL', baseUrl: 'https://example.de' },
      { code: 'fr', iso: 'fr-FR' },
    ],
  },
})
```

وجّه كلا النطاقين إلى الخادم نفسه. ويقرر مضيف الطلب الباقي:

- **الافتراضي:** الـ locale ذو `baseDefault` للمضيف. وإن لم يوجد، فافتراضي البناء إن كان المضيف يخدمه، وإلا فأول locale للمضيف.
- **الـ locales المخدومة:** locales ذلك المضيف، بالإضافة إلى كل locale بلا `baseUrl`. على `example.de` هي `de` و`nl` و`fr`.
- **locales النطاقات الأخرى** أهداف روابط. تعطي `$localePath` و`$localeRoute` و`$switchLocalePath` و`<i18n-switcher>` و`hreflang` عناوين URL مطلقة على `baseUrl` الخاص بها، وتنتقل `$switchLocale` إليها. على هذا المضيف تعيد عناوينها 404، ولا يمكن لملف تعريف ارتباط أو `Accept-Language` اختيارها.
- **الرابط إلى نطاق آخر** يمر عبر `$localePath` أو `<i18n-link>`: `<NuxtLink :to="$localePath('/contact', 'de')">`، `<i18n-link :to="$localeRoute('/contact', 'de')">`. لا يقبل الموجِّه كائنًا مطلقًا، لذا تبقى `<NuxtLink :to="$localeRoute(...)">` و`router.push($localeRoute(...))` على هذا الأصل. على `localhost` أو مضيف المعاينة يكون كل locale ذي `baseUrl` رابطًا من هذا النوع، بما في ذلك الحالي. في الكود استخدم `navigateTo($localePath('/contact', 'de'), { external: true })`، أو `$switchRoute`.
- **أي مضيف آخر** يحصل على إعداد البناء، مع كل locale ذي `baseUrl` كهدف رابط. لا يُعاد شيء من الطلب: تستخدم canonical و`hreflang` القيمة `metaBaseUrl`، وإلا `baseUrl` لافتراضي البناء (يحتاج الافتراضي الذي بلا `baseUrl` إلى `metaBaseUrl` أو `site.url`، راجع [SEO](/ar/guide/seo#set-the-public-origin)).
- **ملفات الحمولة** في `public/` ثابتة: يعيد أي مضيف ملف أي locale. أما [generate](/ar/guide/deployment#static-site-(nuxi-generate)) لكل نطاق فينشر ملفات ذلك النطاق فقط.

`example.de` في كل استراتيجية، مع `de: '/kontakt'` كمسار مخصص لـ `contact`:

| الاستراتيجية | `/` | صفحة الـ locale الافتراضي | عناوين URL أخرى |
| --- | --- | --- | --- |
| `prefix_except_default` | `de` | `/kontakt` | `/de/kontakt` و`/en/contact` تعيدان 404، و`/contact` تعيد التوجيه إلى `/kontakt` |
| `prefix_and_default` | `de` | `/kontakt` و`/de/kontakt`، وتستخدم الروابط `/kontakt` | `/en/contact` و`/contact` تعيدان 404 |
| `prefix` | تعيد التوجيه إلى `/de` | `/de/kontakt` | `/kontakt` تعيد التوجيه إلى `/de/kontakt`، و`/en/contact` تعيد 404 |
| `no_prefix` | `de` | `/kontakt` | المسار المخصص لـ locale على نطاق آخر يعيد 404 |

مع `prefix` يحتفظ الرابط من نطاق آخر بالبادئة، لأن عنوان URL بلا بادئة لن يفعل سوى إعادة التوجيه. ومع `no_prefix` يصل الرابط إلى نطاق آخر إلى الـ locale الافتراضي لذلك المضيف: لا يمكن لعنوان URL أن يسمّي locale ثانيًا.

أمور ينبغي معرفتها:

- **خلف وكيل** يأتي المضيف من `Host`. إن وضع الوكيل المضيف العام في `X-Forwarded-Host` بدلًا من ذلك، فاضبط [`trustForwardedHost`](/ar/api/module-options#trustforwardedhost)، وفقط عندما يستبدل الوكيل تلك الترويسة. الوكيل الذي لا يرسل أيًا منهما لا يمكنه خدمة بناء النطاقات. راجع [خلف وكيل أو CDN](/ar/guide/deployment#behind-a-proxy-or-cdn).
- **`app.baseURL`** ينتمي إلى `baseUrl` أيضًا: `baseUrl: 'https://example.de/shop'` مع `app.baseURL: '/shop'`.
- **تتطابق المضيفات تطابقًا تامًا.** `www.example.de` مضيف آخر: أعد توجيهه على الحافة، أو اضبط ذلك الـ `baseUrl` على الـ locale. مضيف واحد فقط لكل locale.
- **يجب أن تعتمد ذاكرات التخزين المؤقت على المضيف كمفتاح.** عادةً ما تفعل شبكة CDN ذلك. تعتمد ذاكرة المسارات في Nitro على المسار، لذا في بناء النطاقات تضيف الوحدة `host` إلى `cache.varies` لكل قاعدة `swr` و`cache`، و`x-forwarded-host` مع `trustForwardedHost`. تبقى القاعدة ذات `cache: false` كما كُتبت. `isr` هي ذاكرة المنصة: تحقق من أنها تعتمد على المضيف كمفتاح.
- **يجب ألا تتصادم المسارات المخصصة لافتراضيَّي مضيفين.** تتشارك السجلات بلا بادئة موجِّهًا واحدًا، لذا لا يمكن أن تكون `/x` صفحة على `example.de` وصفحة أخرى على `example.com`.
- **الصفحات المصيَّرة مسبقًا:** قاعدة المسار `prerender: true` في `nuxt build` تُصيِّر مرة واحدة، بلا مضيف، ويجيب الملف كل النطاقات. اترك الصفحات التي تختلف حسب النطاق للخادم، أو [ولّد لكل نطاق](/ar/guide/deployment#static-site-(nuxi-generate)).
- **`noPrefixRedirect`** يعتمد على locale المضيف والزائر، على كل مضيف.
- **`hashMode`:** يختار المضيف العرض كما سبق، وتحمل الروابط إلى نطاق آخر المسار في الـ hash (`https://example.com/#/contact`).
- **`ssr: false`:** يقرأ المتصفح النطاق من `location.host`، لذا يُحَل المضيف الذي لا خادم له مع ذلك.
- **[تجاوزات وقت التشغيل](/ar/guide/runtime-overrides)** تُطبَّق أولًا. تسري `disabledLocales` المحددة وقت التشغيل على كل مضيف، باستثناء واحد: مع `prefix_except_default` و`prefix_and_default` يبقى افتراضي المضيف مفعَّلًا على مضيفه، لأن صفحاته هي السجلات بلا بادئة. ومع `prefix` و`no_prefix` ينتقل المضيف إلى الـ locale التالي الذي يخدمه. أما `defaultLocale` المحدد وقت التشغيل فيُطبَّق على المضيفات غير المعروفة فقط.

بالنسبة إلى [موقع ثابت](/ar/guide/deployment#static-site-(nuxi-generate))، ولّد مرة واحدة لكل نطاق.

### تطبيق واحد لكل نطاق {#one-app-per-domain}

لا تزال الطبقة المشتركة مع تطبيق صغير لكل نطاق تعمل، عندما تحتاج النطاقات إلى صفحات أو وحدات مختلفة. يضبط كل تطبيق `defaultLocale` الخاص به فوق قائمة `locales` نفسها. الـ locale الموجود على نطاق آخر يعيد 404 في ذلك التطبيق، كما سبق.

### اختيار الـ locale في الكود {#choosing-the-locale-in-code}

لنسخة واحدة تجيب كل النطاقات بأصل الطلب نفسه في وسوم SEO، راجع [SEO](/ar/guide/seo#set-the-public-origin)؛ ولاختيار الـ locale من المضيف في الكود، راجع [اكتشاف الـ locale المخصص](/ar/guide/custom-auto-detect).
