الترجمات ملفات JSON عادية: ملف جذري واحد لكل لغة للمفاتيح المشتركة، وملف واحد لكل صفحة ولغة لمفاتيح تلك الصفحة. اقرأ هذا عندما تضيف صفحات، أو تشارك مفاتيح بينها، أو تُعدّ البدائل. ستتعلم في أي ملف يجب أن يوضع المفتاح، وما الذي تراه الصفحة، ومتى يُحمَّل كل ملف.

## البنية {#layout}

```text
locales/
├── en.json                 # root: menus, footer, buttons
├── de.json
└── pages/
    ├── index/              # pages/index.vue
    │   ├── en.json
    │   └── de.json
    ├── about/              # pages/about.vue
    │   ├── en.json
    │   └── de.json
    └── products-id/        # pages/products/[id].vue
        ├── en.json
        └── de.json
```

- المجلد الموجود تحت `locales/pages/` هو **اسم مسار** Nuxt للصفحة: `pages/products/[id].vue` هو `products-id`، و`pages/blog/[slug]/comments.vue` هو `blog-slug-comments`.
- يمكن أن تتداخل المفاتيح إلى أي عمق؛ تقرأ `$t('auth.form.login')` القيمة `{ "auth": { "form": { "login": … } } }`.
- ينقل `translationDir` المجلد (`'locales'` افتراضيًا، نسبةً إلى جذر المشروع، وأيضًا تحت بنية `app/` في Nuxt 4).
- تُنشأ الملفات المفقودة بالمحتوى `{}` عندما يحلّ Nuxt الصفحات، ما لم يُضبط [`disableWatcher`](/ar/api/module-options#disablewatcher).

## ما تراه الصفحة {#what-a-page-sees}

![ترتيب البحث عن مفتاح على /about باللغة de: pages/about/de.json، de.json، pages/about/en.json، en.json. تُدمج في ملف واحد about/de/data.json تقرؤه $t](/images/diagrams/page-dictionary.svg)

قاموس الصفحة هو ملفها الجذري مدموجًا مع ملف صفحتها، دمجًا عميقًا (على كل مستوى). يفوز ملف الصفحة عند التعارض:

```json
// locales/en.json
{ "title": "My shop", "nav": { "home": "Home", "cart": "Cart" } }
```

```json
// locales/pages/about/en.json
{ "title": "About us", "nav": { "cart": "Basket" } }
```

```ts
// on /about
t('title') // 'About us'
t('nav.home') // 'Home'   (root)
t('nav.cart') // 'Basket' (page wins)
// on any other page
t('title') // 'My shop'
```

الصفحة التي ليس لها مجلد خاص تحصل على القاموس الجذري وحده. مفاتيح الصفحات الأخرى غير مرئية.

### اللغات البديلة {#fallback-locales}

يؤخذ المفتاح المفقود في اللغة النشطة من لغته البديلة قبل عرض المفتاح نفسه:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'de-at', iso: 'de-AT', fallbackLocale: 'de' },
    ],
    defaultLocale: 'en',
    fallbackLocale: 'en', // global, for every locale
  },
})
```

- يُتتبَّع `fallbackLocale` الخاص باللغة حتى نهايته: `de-at` → `de` → `en`.
- `fallbackLocale` العام هو الطبقة الأضعف، تحت كل سلسلة.
- تضيف كل لغة في السلسلة ملفها الجذري، ثم ملف صفحتها، من البديل الأضعف صعودًا إلى اللغة النشطة. لذا يتغلب الملف الجذري للغة النشطة على ملف الصفحة الخاص بلغة بديلة.

بدون بديل، يُصيَّر المفتاح المفقود كمفتاح (`'nav.home'`) ويُسجَّل تحذير في وحدة تحكم المتصفح في وضع التطوير ([`missingWarn`](/ar/api/module-options#missingwarn)).

## المشاركة والمصادر الأخرى {#sharing-and-other-sources}

| الحاجة | الخيار |
| --- | --- |
| ملفات جذرية فقط، دون مجلدات `pages/` | [`disablePageLocales: true`](/ar/api/module-options#disablepagelocales) |
| صفحتان تقرآن مجلد صفحة واحدًا | [`routesLocaleLinks`](/ar/api/module-options#routeslocalelinks): `{ 'about-us': 'about' }` |
| ملفات جذرية مشتركة في مجلد آخر | [`additionalTranslationDirs`](/ar/api/module-options#additionaltranslationdirs): `['common']` (يفوز `translationDir` الرئيسي) |
| مفاتيح من طبقة Nuxt | تُدمج ملفات الطبقات، وتفوز ملفات المشروع نفسه. راجع [الطبقات](/ar/guide/layers) |
| مفاتيح تُضاف وقت التشغيل | الخطّاف [`i18n:register`](/ar/api/events)، و`$mergeTranslations`، و`$setTranslation` |
| مفاتيح مضمّنة في مكوّن صفحة | `$defineI18nRoute({ locales: { en: { … } } })`، راجع [إعداد الصفحة](/ar/guide/per-component-translations) |

## كيف تحمّل الصفحة قاموسها {#how-a-page-loads-its-dictionary}

![تُبنى ملفات JSON الخاصة باللغات في شجرة حمولات، تُخزَّن في public/ على Node أو في أصول الخادم على Edge، ويقرؤها محمّل الخادم، ثم تستخدمها $t على الخادم وتُجلب لـ $t في المتصفح](/images/diagrams/translation-pipeline.svg)

تبني الوحدة حمولة واحدة لكل صفحة ولغة: `/{apiBaseUrl}/{page}/{locale}/data.json` (`/_locales/about/de/data.json` افتراضيًا).

1. **التصيير على الخادم.** يكتشف Nitro اللغة وتحمّل الصفحة حمولتها من محمّل الخادم مباشرة، دون طلب HTTP. لا يُكتب القاموس في حمولة HTML، فتبقى الصفحات صغيرة.
2. **الإماهة (Hydration).** يجلب المتصفح الحمولة نفسها. وقد أصدر الخادم بالفعل `<link rel="preload">` لها، فيبدأ الجلب مع HTML.
3. **التنقّل.** تستبدل حمولة الصفحة التالية القاموس. تظل مفاتيح الصفحة المغادِرة قابلة للحل حتى تختفي (نهاية انتقال الصفحة، أو `page:finish`)، فلا تُظهر الصفحة المتلاشية مفاتيح خامًا. الجزء الذي يفشل تحميله (خطأ في الشبكة، أو 4xx أو 5xx، أو محتوى ليس كائنًا) يترك القاموس الحالي في مكانه، ويحمّله التنقّل التالي مجددًا. وكذلك الأمر عند فشل تبديل اللغة: تُحلّ `$switchLocale` إلى `false`، واستدعاؤها مجددًا، أو النقر على المبدّل مجددًا، يعيد المحاولة. تحت استراتيجيات البادئة يكون عنوان URL قد تغيّر بالفعل حينها، فيشير `lang` و`$getLocale()` إلى لغة عنوان URL بينما تبقى النصوص القديمة على الشاشة.
4. **ذاكرة التخزين المؤقت.** تُخزَّن الحمولات المحمّلة مؤقتًا على الخادم وفي المتصفح؛ وتجد في [الأداء](/ar/guide/performance) خيارات الحجم وTTL.

يحدّد `translationPayloads.mode` كيفية بناء الحمولات. يكتب `'premerged'` (الافتراضي) كل ملف صفحة × لغة وقت البناء. أما `'source'` فيحتفظ بالملفات المصدرية ويدمجها لكل طلب، وهو أصغر للكتالوجات الكبيرة على أهداف Edge. كلاهما يعطي القواميس نفسها. أين تنتهي الملفات لكل هدف نشر موضّح في [النشر](/ar/guide/deployment).

## التحرير أثناء التطوير {#editing-in-development}

يقرأ `nuxt dev` الملفات مباشرة. حفظ ملف ترجمة يحدّث قاموس الصفحة المفتوحة في مكانه: دون إعادة تحميل، وتختفي المفاتيح المحذوفة، ويصل التغيير في ملف جذري إلى كل صفحة. ملف JSON المعطوب يسجّل تحذيرًا بمساره ويُعامل كملف فارغ. اضبط [`hmr: false`](/ar/api/module-options#hmr) للتحديث يدويًا بدلًا من ذلك.
