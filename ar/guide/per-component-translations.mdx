---
title: "إعدادات الصفحة"
description: "اقصر صفحة على بعض اللغات، أو امنحها مسارات مخصصة، أو ترجمات مضمّنة، أو ألغِ وسوم SEO باستخدام $defineI18nRoute."
---

يضبط `$defineI18nRoute` خيارات i18n لصفحة واحدة من داخل الصفحة نفسها. استخدمه عندما تكون الصفحة موجودة في بعض اللغات فقط، أو تحتاج إلى مسار مترجم خاص بها، أو تحمل بعض الترجمات الخاصة بها، أو يجب ألا تحصل على وسوم hreflang/canonical. تقرأ الوحدة هذا الاستدعاء وقت البناء وتدمجه في المسارات المُولَّدة.

## قصر صفحة على بعض اللغات {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

لا يُولَّد سوى `/product` و`/de/product` في ظل الاستراتيجية الافتراضية `prefix_except_default`؛ وليس للصفحة أي مسار في أي لغة أخرى. يمكن ضبط الأمر نفسه من `nuxt.config.ts` باستخدام [`routeLocales`](/ar/api/module-options#routelocales).

إن `$defineI18nRoute` حقنٌ في تطبيق Nuxt، وليس ماكرو للمترجم: احصل عليه دائمًا من `useNuxtApp()` واستدعِه مع `$`. لا تتعرف خطوة البناء إلا على `$defineI18nRoute(`.

## إضافة ترجمات مضمّنة {#add-inline-translations}

مرّر كائنًا بدلًا من مصفوفة. مفاتيحه هي اللغات المسموح بها، وتُدمج قيمه في قاموس الصفحة للغة النشطة.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

تُشحن الترجمات المضمّنة داخل مكوّن الصفحة لكل اللغات. فضّل [ملفات ترجمة الصفحات](/ar/guide/translations) لأي شيء يتجاوز بضعة مفاتيح؛ واحتفظ بالمفاتيح المضمّنة للصفحات والمكونات المستقلة بذاتها.

## تعيين المسارات المترجمة {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

مع `prefix_except_default` و`defaultLocale: 'en'` ينتج هذا `/welcome` و`/de/willkommen`. ويؤدي `path` داخل كائن لغة مضمّن الشيء نفسه: `locales: { de: { path: '/willkommen' } }`. تُشرح المعاملات الديناميكية والمسارات المتداخلة والبديل على مستوى الإعدادات في [المسارات المترجمة](/ar/guide/custom-locale-routes).

## إيقاف وسوم SEO {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

البديل على مستوى الإعدادات هو [`routeDisableMeta`](/ar/api/module-options#routedisablemeta). يوضح ماهية هذه الوسوم في صفحة [SEO](/ar/guide/seo).

## ما الذي يمكن للبناء قراءته {#what-the-build-can-read}

تعثر خطوة البناء على الاستدعاء في كل ملف صفحة وتقيّم وسيطه دون تشغيل تطبيقك. ويعمل ذلك عندما تكون الإعدادات:

- كائنًا حرفيًا (سلاسل نصية، ومصفوفات، وكائنات متداخلة، وقوالب نصية، وعمليات شرطية ثلاثية على `process.env.NODE_ENV`)؛
- مبنية من ثوابت مُعرَّفة في `<script setup>` نفسه (`const locales = ['en', 'de']`، بما في ذلك عوامل النشر)؛
- مصفوفة من الكائنات تحتوي على حقل `code` (`[{ code: 'en' }, { code: 'de' }]`).

لا يمكنها قراءة القيم المستوردة من وحدة أخرى، أو أي شيء يحتاج إلى تطبيقك وقت التشغيل (الدوال التركيبية، `await`، البيانات المجلوبة). في هذه الحالة يسجّل البناء `Ignored the $defineI18nRoute() config in <file>` وتحتفظ الصفحة باللغات والمسارات الافتراضية.

في وقت التشغيل، لا يفعل الاستدعاء سوى دمج الترجمات المضمّنة للغة الحالية، ويعيد دمجها عند تغيّر اللغة. لا تسري `locales` و`localeRoutes` و`disableMeta` إلا من خلال البناء، لذا يتطلب تغييرها إعادة البناء (يعيد خادم التطوير البناء عند الحفظ).
