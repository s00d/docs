افتراضيًا، تقدّم كل لغة الصفحة على المسار نفسه: `/en/about`، `/de/about`. تتيح المسارات المترجمة لكل لغة استخدام كلماتها الخاصة، مثل `/de/ueber-uns`، بينما يبقى ملف الصفحة نفسه. تضبطها داخل الصفحة باستخدام `$defineI18nRoute`، أو لعدة صفحات دفعة واحدة في `nuxt.config.ts`.

## داخل الصفحة {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

مع `prefix_except_default` و`defaultLocale: 'en'` تستجيب الصفحة على `/about` و`/de/ueber-uns` و`/fr/a-propos`. اللغة التي ليس لها مُدخل تحتفظ بالمسار الافتراضي. اكتب المسارات دون رمز اللغة: تضيف [الاستراتيجية](/ar/guide/strategy) البادئة، والمسار الذي يبدأ برمز اللغة يسجّل تحذيرًا. ما يقبله الاستدعاء أيضًا موجود في [إعداد الصفحة](/ar/guide/per-component-translations).

## في nuxt.config {#in-nuxt-config}

يفعل [`globalLocaleRoutes`](/ar/api/module-options#globallocaleroutes) الشيء نفسه لأي صفحة، مفهرسًا بمسارها (أو باسم مسارها، عند كتابته دون شرطة مائلة في البداية):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

عندما تضبط الصفحة `localeRoutes` ويحتوي `globalLocaleRoutes` على المفتاح نفسه، يفوز مُدخل الإعدادات.

## المعاملات الديناميكية {#dynamic-params}

اكتب المعاملات بأي صيغة من صيغ Nuxt: `[id]`، `[[page]]`، `[...slug]`، أو `:id()`. يجب أن تطابق أسماء المعاملات ملف الصفحة.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

تأخذ الصفحات المتداخلة مسارًا فرعيًا مطلقًا (`/ueber-uns/team`) أو مسارًا نسبيًا إلى المسار المترجم للصفحة الأم (`team`).

## الربط بالصفحات المترجمة {#linking-to-localized-pages}

تُحلّ الروابط إلى المسار المترجم للغة الهدف، سواء مرّرت اسم مسار أو مسارًا عاديًا:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

تأتي أسماء المسارات من مسار الملف (`pages/about/team.vue` هو `about-team`) ما لم تضبط اسمًا باستخدام `definePageMeta({ name })`.

## الـ slugs الخاصة بكل لغة {#per-locale-slugs}

عندما يختلف الـ slug نفسه من لغة لأخرى (`/our-products/red-shoe` مقابل `/de/unsere-produkte/roter-schuh`)، أخبر مبدّل اللغة بالمعاملات التي يستخدمها عبر `$setI18nRouteParams` بمجرد تحميل البيانات:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

عندها يربط `$switchLocalePath('de')` و`<i18n-switcher>` إلى `/de/unsere-produkte/roter-schuh`. المفاتيح هي رموز اللغات، والقيم هي المعاملات بأسمائها (كما في ملف الصفحة).

يُصيَّر المبدّل الموجود في التخطيط (layout) قبل أن يصل الإعداد غير المتزامن للصفحة إلى هذه النقطة، لذا عند انتهاء التصيير تعيد الوحدة كتابة روابط `<i18n-switcher>`، سواء في `app.vue` أو في الصفحة. وبذلك يتطابق HTML الخادم، والزائر الذي لا يستخدم JavaScript، وأول تصيير على العميل. اضبط المعاملات أثناء SSR لتحقيق ذلك: مع `lazy` أو `server: false` لا تتغيّر الروابط إلا بعد الإماهة (hydration). يرسل بثّ SSR في Nuxt ملف HTML قبل معرفة المعاملات، لذا تحتفظ الروابط في أول HTML تحته بمعاملات عنوان URL نفسه.

لا يُعاد كتابة إلا روابط المبدّل نفسه. يجب أن يُصيَّر رابط `$switchLocalePath` المكتوب يدويًا بعد ضبط المعاملات، لذا ضعه في الصفحة التي تضبطها، وبعد `await` أيضًا. في التخطيط يُصيَّر أولًا: فيحتفظ HTML الخادم الخاص به بمعاملات عنوان URL، وتُحذّر الإماهة من عدم تطابق. استخدم `<i18n-switcher>` هناك، مع خاناته (slots) وخصائص `custom*Style` للمظهر.

تنتمي المعاملات إلى الصفحة التي ضبطتها:

- تُحذف عند اعتماد تنقّل إلى مسار آخر، لذا تضبط كل صفحة معاملاتها الخاصة. التنقّل الملغى يتركها في مكانها.
- خذ `$setI18nRouteParams` من `useNuxtApp()` أو `useI18n()` داخل `setup`، حتى عندما تستدعيها لاحقًا في معالج `useAsyncData`. عند أخذها هناك، تعرف الدالة صفحتها: إذا غادر الزائر، لا يفعل الاستدعاء المتأخر شيئًا.
- مع `keepalive`، تستعيد الصفحة المعاملات التي ضبطتها عند عودة الزائر. وتفعل `useI18nHead` الشيء نفسه.

## المسارات المضافة في pages:extend {#routes-added-in-pagesextend}

المسارات التي تدفعها في الخطّاف `pages:extend` ليس لها ملف صفحة يُقرأ منه `$defineI18nRoute`، وغالبًا ما يتشارك عدد منها مكوّنًا غلافًا واحدًا. المسار المدفوع دون `name` يحصل على الاسم الذي كان Nuxt سيعطيه لمساره (`/a/:id()` يصبح `a-id`)، فتصل إليه روابط اللغات، ما لم يكن لمسار آخر هذا الاسم بالفعل؛ عندها أعطه `name` صريحًا. احتفظ بقائمة واحدة وقسّمها إلى صفحات و`globalLocaleRoutes` مفهرسة باسم المسار باستخدام `splitLocaleRoutes` من `@i18n-micro/utils/split-locale-routes` (أضف الحزمة إلى تبعياتك):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

لا تضع المسارات المترجمة في `route.meta`: إذ ستُشحن ضمن جدول المسارات على العميل.
