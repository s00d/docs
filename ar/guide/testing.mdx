تحتاج المكونات التي تستدعي `useI18n()` إلى نسخة i18n في اختبارات الوحدات. تمنحك `@i18n-micro/test-utils` نسخة وهمية من `useI18n()` بمنطق حقيقي للترجمة وصيغ الجمع والتنسيق، لذا يمكنك تركيب مكون بقواميسك الخاصة دون خادم Nuxt. أما للتوجيه وإعادة التوجيه، فشغّل الوحدة الحقيقية اختبارًا شاملًا باستخدام `@nuxt/test-utils`.

تتناول هذه الصفحة اختبار تطبيقك. أما كيفية اختبار هذا المستودع للوحدة نفسها فموجودة في [اختبار الوحدة](https://s00d.github.io/nuxt-i18n-micro/contributing/testing).

## التثبيت {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

```bash npm
npm install -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

</CodeGroup>

## محاكاة useI18n {#mock-usei18n}

```ts
// tests/unit-setup.ts
import { setupNuxtI18nMock } from '@i18n-micro/test-utils'
import { mockNuxtImport } from '@nuxt/test-utils/runtime'
import { beforeEach, vi } from 'vitest'

export const { i18n, useI18n, setTranslationsFromJson } = setupNuxtI18nMock({
  spy: vi.fn, // every method becomes a vi.fn, so you can assert calls
  beforeEach, // reset state and reseed `translations` before each test
  translations: { welcome: 'Welcome' },
})

mockNuxtImport('useI18n', () => useI18n)
```

```ts
// vitest.config.ts
import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    environment: 'nuxt',
    setupFiles: ['./tests/unit-setup.ts'],
  },
})
```

أبقِ `mockNuxtImport` في ملف الإعداد: إذ يجب أن تحوّله `@nuxt/test-utils`. تستخدم `setupNuxtI18nMock` ذاكرة تخزين مؤقت خاصة للترجمات، لذا لا تتشارك ملفات الاختبار المتوازية الحالة.

## كتابة اختبار {#write-a-test}

```vue
<!-- components/Greeting.vue -->
<script setup lang="ts">
const { $t } = useI18n()
</script>

<template>
  <p>{{ $t('welcome') }}</p>
</template>
```

```ts
// tests/greeting.spec.ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { expect, it } from 'vitest'
import Greeting from '~/components/Greeting.vue'
import de from '~/locales/de.json'
import { i18n, setTranslationsFromJson } from './unit-setup'

it('renders the German greeting', async () => {
  await setTranslationsFromJson('de', de)
  i18n.setLocale('de')

  const wrapper = await mountSuspended(Greeting)
  expect(wrapper.text()).toBe('Willkommen') // de.json: { "welcome": "Willkommen" }
})
```

تكشف النسخة الوهمية عن الدوال نفسها الموجودة في `useI18n()` الحقيقية (`$t` و`$tc` و`$tn` و`$td` و`$has` و`$localePath`، …، مع `$` وبدونها) بالإضافة إلى دوال تعيين للاختبارات: `setLocale`, `setLocales`, `setDefaultLocale`, `setRouteName`, `setTranslationsFromJson`, `loadPageTranslations`, `mergeTranslations`, `setMissingHandler`.

`$localePath` و`$switchLocalePath` بدائل بسيطة تضيف بادئة إلى المسار وفق خيار `strategy` (دون موجّه حقيقي). اختبر الروابط وإعادة التوجيه الحقيقية اختبارًا شاملًا.

## دوال مساعدة منخفضة المستوى {#lower-level-helpers}

| الدالة المساعدة | استخدمها من أجل |
| --- | --- |
| `createIsolatedFakeI18n(options)` | نسخة وهمية معزولة دون ربط `useI18n` الخاص بـ Nuxt، مثلًا لاستخدام `mount` العادي من `@vue/test-utils` مع `global.mocks`. |
| `createFakeI18n(options)` | نسخة وهمية على ذاكرة التخزين المؤقت المشتركة للوحدة (استدعِ `resetI18n()` في `beforeEach`)، أو معزولة مع `isolated: true`. |
| `createI18nTestContext(options)` | السياق الكامن خلف كلتيهما، عندما تحتاج إلى عدة نسخ وهمية. |
| `t`, `tc`, `ts`, `tn`, `td`, `tdr`, `has` | استدعاءات مباشرة على السياق المشترك، لاختبار الدوال العادية. |

المحاكاة هي `BaseI18n`: الدوال `t` و`tc` و`tn` و`td` و`tdr` و`has` هي الدوال الحقيقية، على قواميس حقيقية، لذا يرى الاختبار ما يعرضه التطبيق.

تقبل الدوال المُنشئة أعلاه `locale` و`defaultLocale` و`locales` و`routeName` و`strategy` و`translations` و`messages` (قواميس لكل لغة محلية). يوجد مشروع مثال كامل في [`packages/test-utils/example`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/test-utils/example).

## الاختبارات الشاملة {#end-to-end-tests}

يحتاج التوجيه وإعادة التوجيه ووسوم SEO وتحميل الحمولات إلى الوحدة الحقيقية. شغّل تطبيقك باستخدام `@nuxt/test-utils/e2e`:

```ts
// tests/e2e/locales.test.ts
import { $fetch, fetch, setup } from '@nuxt/test-utils/e2e'
import { describe, expect, it } from 'vitest'

describe('locales', async () => {
  await setup({ server: true })

  it('serves the German page', async () => {
    expect(await $fetch('/de')).toContain('lang="de-DE"')
  })

  it('redirects / for a German browser', async () => {
    const res = await fetch('/', { headers: { 'accept-language': 'de' }, redirect: 'manual' })
    expect(res.headers.get('location')).toBe('/de')
  })
})
```

يفترض الاختبار الثاني استخدام `prefix` (أو `prefix_except_default` مع لغة افتراضية أخرى)؛ راجع [اكتشاف اللغة المحلية](/ar/guide/locale-detection) لمعرفة متى يعيد `/` التوجيه.
