<Tip>
  Migrating from `@nuxtjs/i18n` instead? See [Migration from @nuxtjs/i18n](/migration/from-nuxtjs-i18n). That guide covers moving from the vue-i18n ecosystem, not from `nuxt-i18n-micro` v2.
</Tip>

v3.0.0 introduces fundamental architectural changes: strategy packages, a new caching system, centralized locale management via `useI18nLocale()`, and a redesigned redirect pipeline. This page covers all breaking changes and how to update your code.

## Migration flow

<Steps>
  <Step title="Update dependencies">
    Bump `nuxt-i18n-micro` to v3 in your package manifest.
  </Step>
  <Step title="Fix configuration">
    Remove deprecated options and move `hmr` to the root level.
  </Step>
  <Step title="Update plugins and composables">
    Replace manual state access with `useI18nLocale()` and `getI18nConfig()`.
  </Step>
  <Step title="Test">
    Verify locale switching, redirects, SEO tags, and payload transfer end-to-end.
  </Step>
</Steps>

## Breaking changes summary

- **Locale state**: Manual `useState` / `useCookie` replaced with the [`useI18nLocale()`](/api/composables/use-i18n-locale) composable.
- **Config access**: `useRuntimeConfig().public.i18nConfig` replaced with `getI18nConfig()` from `#build/i18n.strategy.mjs`.
- **Redirect component**: The `fallbackRedirectComponentPath` option was removed. Redirects are handled by a server plugin plus client route middleware automatically.
- **`includeDefaultLocaleRoute`**: Removed. Use the `strategy` option instead.
- **`experimental.hmr`**: Moved from `experimental` to a root-level option.
- **`previousPageFallback`**: Removed entirely. The cumulative deep-merge strategy handles this automatically.
- **Caching**: `useStorage('cache')` replaced by a `TranslationStorage` singleton (`Symbol.for` on `globalThis`).
- **SSR transfer**: Runtime config replaced with the Nuxt payload. Chunks now live in `payload.data`. See [Performance](/guides/performance).
- **Strategy classes**: Internal classes moved into separate packages: `@i18n-micro/route-strategy` and `@i18n-micro/path-strategy`.

## Removed: `fallbackRedirectComponentPath`

The `fallbackRedirectComponentPath` option and the `locale-redirect.vue` fallback component have been removed. Redirect logic is now handled by:

1. **Server middleware** (`i18n.global.ts`) sets `event.context.i18n.locale`.
2. **Server redirect plugin** (`06.redirect.ts`, server-only) issues 302 redirects before render.
3. **Client route middleware** (`i18n-redirect.global.ts`) handles SPA redirects after hydration.

```diff
 i18n: {
   strategy: 'prefix_except_default',
-  fallbackRedirectComponentPath: '~/components/MyRedirect.vue',
 }
```

If you had custom redirect logic in the fallback component, implement it in a server plugin instead:

```typescript
// plugins/i18n-loader.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-redirect',
  enforce: 'pre',
  order: -10,
  setup() {
    const { setLocale } = useI18nLocale()
    // Your custom detection logic
    setLocale(detectedLocale)
  },
})
```

See [Custom language detection](/guides/custom-language-detection) for detailed examples.

## Removed: `includeDefaultLocaleRoute`

Use the `strategy` option instead:

- `includeDefaultLocaleRoute: true` becomes `strategy: 'prefix'`.
- `includeDefaultLocaleRoute: false` becomes `strategy: 'prefix_except_default'` (the default).

```diff
 i18n: {
-  includeDefaultLocaleRoute: true,
+  strategy: 'prefix',
 }
```

See [Routing strategies](/guides/routing-strategies) for the full behavior of each strategy.

## Config access: `getI18nConfig()` replaces `useRuntimeConfig`

Runtime config is no longer the transport for i18n options. Import `getI18nConfig()` from the generated build module instead.

```diff
- const config = useRuntimeConfig()
- const cookieName = config.public.i18nConfig?.localeCookie || 'user-locale'
+ import { getI18nConfig } from '#build/i18n.strategy.mjs'
+ const { localeCookie: configCookie } = getI18nConfig()
+ const cookieName = configCookie ?? 'user-locale'
```

## Locale management: `useI18nLocale()` replaces manual state

In v2 you may have used `useState('i18n-locale')` or `useCookie('user-locale')` directly. In v3, use the centralized [`useI18nLocale()`](/api/composables/use-i18n-locale) composable:

```diff
- const locale = useState('i18n-locale')
- const cookie = useCookie('user-locale')
- locale.value = 'fr'
- cookie.value = 'fr'
+ const { setLocale } = useI18nLocale()
+ setLocale('fr') // Updates both state and cookie atomically
```

See [Custom language detection](/guides/custom-language-detection) for a full setup that runs before render on the server.

## Experimental options moved and removed

`hmr` has moved from `experimental` to a root-level option. `previousPageFallback` has been removed entirely. The module now uses a cumulative deep-merge strategy (2-level depth) that automatically preserves translations from the previous page during transition animations, even when pages share overlapping nested keys. After the transition animation completes, the `page:transition:finish` hook cleans up old-page keys from memory.

```diff
 i18n: {
-  experimental: {
-    hmr: true,
-    previousPageFallback: true
-  }
+  hmr: true,
+  // previousPageFallback removed — handled automatically
 }
```

## Redirect architecture in v3

Redirects are now handled automatically by two components:

1. **Server-side** (`06.redirect.ts`, server-only) runs during SSR and issues 302 redirects before any page rendering. There is no error flash.
2. **Client-side** (`i18n-redirect.global.ts`) is a global route middleware for SPA navigation. It preserves the query string and hash.

Locale priority for redirects:

1. `useState('i18n-locale')` set via `useI18nLocale().setLocale()`.
2. Cookie, if `localeCookie` is configured.
3. `Accept-Language` header, if `autoDetectLanguage: true`.
4. `defaultLocale` as the final fallback.

No code changes are required for standard setups.

<Warning>
  **`localeCookie` for prefix strategies.** For `prefix` and `prefix_except_default` strategies with `redirects: true`, set `localeCookie: 'user-locale'` to enable locale persistence across page reloads. Without it, redirects only use `Accept-Language` or `defaultLocale`.
</Warning>

## TypeScript: internal module types (optional)

If you encounter type errors related to internal imports like `#i18n-internal/plural`, `#i18n-internal/strategy`, or `#i18n-internal/config`, add the `imports` section to your project's `package.json`:

```json
{
  "imports": {
    "#i18n-internal/plural": "nuxt-i18n-micro/internals",
    "#i18n-internal/strategy": "nuxt-i18n-micro/internals",
    "#i18n-internal/config": "nuxt-i18n-micro/internals"
  }
}
```

<Tip>
  This is not required in most cases. Nuxt resolves these automatically at build time. Add this only if your IDE or `vue-tsc` reports unresolved module errors.
</Tip>
