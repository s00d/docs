## Which guide do you need?

| You are migrating from                    | Guide                                              |
| ----------------------------------------- | -------------------------------------------------- |
| `@nuxtjs/i18n` (vue-i18n based module)    | **This page**                                      |
| `nuxt-i18n-micro` v2.x                    | [Upgrading from v2.x to v3.x](/migration/v2-to-v3) |

## Why migrate

- **Improved performance**: Roughly 51% faster builds and 54% less build memory versus `@nuxtjs/i18n` v10.6 in the benchmark fixtures. See [Performance](/guides/performance) for details.
- **Simplified configuration**: A streamlined setup with sensible defaults.
- **Better resource management**: Optimized handling of large translation files.

## Key differences

| Feature                 | `@nuxtjs/i18n`                    | `Nuxt I18n Micro`                          |
| ----------------------- | --------------------------------- | ------------------------------------------ |
| Translation files       | JS/TS/JSON, loaded via `vueI18n`  | JSON only, auto-generated in dev           |
| Route generation        | Runtime                           | Build-time (`@i18n-micro/route-strategy`)  |
| Translation loading     | Bundled into JS                   | Lazy-loaded JSON per page                  |
| Locale state            | `useI18n()` from `vue-i18n`       | `useI18nLocale()` composable               |
| `detectBrowserLanguage` | Supported                         | Use `autoDetectLanguage` instead           |

## Step-by-step

<Steps>
  <Step title="Install">
    Add Nuxt I18n Micro to your project.

    ```bash
    npm install nuxt-i18n-micro
    ```
  </Step>

  <Step title="Update configuration">
    Replace the `@nuxtjs/i18n` module and its `vueI18n` config with the Nuxt I18n Micro options.

    <CodeGroup>
      ```typescript Before (@nuxtjs/i18n)
      export default defineNuxtConfig({
        modules: ['nuxt-i18n'],
        i18n: {
          locales: [
            { code: 'en', iso: 'en-US' },
            { code: 'fr', iso: 'fr-FR' },
          ],
          defaultLocale: 'en',
          vueI18n: './i18n.config.js',
          detectBrowserLanguage: { useCookie: true },
        },
      })
      ```

      ```typescript After (Nuxt I18n Micro v3)
      export default defineNuxtConfig({
        modules: ['nuxt-i18n-micro'],
        i18n: {
          locales: [
            { code: 'en', iso: 'en-US', dir: 'ltr' },
            { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
          ],
          defaultLocale: 'en',
          translationDir: 'locales',
          meta: true,
          localeCookie: 'user-locale',
          autoDetectLanguage: true,
        },
      })
      ```
    </CodeGroup>

    See [Configuration](/guides/configuration) and [Module options](/api/module-options) for the full option reference.
  </Step>

  <Step title="Reorganize translation files">
    Move translations into the `locales` directory in JSON format. Nuxt I18n Micro splits translations into a root-level file per locale and optional per-page translations under `locales/pages/<page>/<locale>.json`.

    <CodeGroup>
      ```text Before (@nuxtjs/i18n)
      my-app/
      ├── i18n/                    # langDir
      │   └── locales/
      │       ├── en.json          # all translations in one file
      │       ├── ru.json
      │       └── de.json
      ├── pages/
      │   ├── index.vue
      │   └── page.vue
      ├── server/
      │   └── tsconfig.json
      ├── nuxt.config.ts           # config will change
      └── package.json
      ```

      ```text After (Nuxt I18n Micro)
      my-app/
      ├── locales/                 # translationDir
      │   ├── en.json              # root-level translations
      │   ├── ru.json
      │   ├── de.json
      │   └── pages/               # page-specific
      │       ├── index/
      │       │   ├── en.json
      │       │   ├── ru.json
      │       │   └── de.json
      │       └── page/
      │           ├── en.json
      │           ├── ru.json
      │           └── de.json
      ├── pages/
      │   ├── index.vue            # API changes
      │   └── page.vue
      ├── server/
      │   └── tsconfig.json
      ├── nuxt.config.ts           # new config
      └── package.json
      ```
    </CodeGroup>

    <Tip>
      Missing page-specific translation files are auto-generated in development mode. Run `nuxt dev` and the module will create empty JSON files for each page and locale.
    </Tip>

    For details on page-scoped translations, see [Per-component translations](/guides/per-component-translations).
  </Step>

  <Step title="Update navigation">
    Swap `nuxt-link` with an i18n-aware version, either by wrapping route targets in `$localeRoute` or by using the `<i18n-link>` component.

    ```diff
    - <nuxt-link :to="{ name: 'index' }">Home</nuxt-link>
    + <NuxtLink :to="$localeRoute({ name: 'index' })">Home</NuxtLink>
    + <!-- or use the built-in component -->
    + <i18n-link :to="{ name: 'index' }">Home</i18n-link>
    ```

    See [`<i18n-link>`](/api/components/i18n-link) for props and options.
  </Step>

  <Step title="Update SEO">
    Remove manual SEO configuration that was tailored for `@nuxtjs/i18n`. Nuxt I18n Micro generates `hreflang`, canonical URLs, and Open Graph tags automatically when `meta: true` is set.

    See [SEO](/guides/seo) for the generated tags and how to customize them.
  </Step>

  <Step title="Test">
    Thoroughly test translations, locale switching, redirects, and SEO meta tags across every configured locale and route.
  </Step>
</Steps>

## Common issues and troubleshooting

### Translation files not loading

Ensure translation files are in the correct directory and follow JSON format. Verify that `translationDir` matches your file location.

### Route not found errors

Check that all locale codes in the `locales` array are correct and that routes are properly set up. Review [Routing strategies](/guides/routing-strategies) if you changed the strategy during migration.

### Missing SEO tags

Verify that `meta: true` is set and each locale has a valid `iso` code. See [SEO](/guides/seo).

### Hydration mismatches

If you use the `no_prefix` strategy, set the locale in a server plugin with `order: -10` using `useI18nLocale().setLocale()`. This ensures the server and client agree on the locale. See [Custom language detection](/guides/custom-language-detection).

### Redirects not working

For prefix strategies, ensure `localeCookie: 'user-locale'` is set. Without a cookie, the server redirect plugin has no way to remember the user's preferred locale across page reloads.
