`@i18n-micro/solid` proporciona a les aplicacions SolidJS una instància d'i18n basada en senyals, un proveïdor, `useI18n()` i quatre components. Feu-lo servir en una aplicació Solid que no estigui feta amb Nuxt. Les lectures de `t()` dins de JSX o d'efectes fan el seguiment del locale, la ruta i els diccionaris; el model compartit és a [Frameworks](/ca/integrations/overview).

## Instal·lació {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Dependències peer: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (opcional, només per a `@i18n-micro/solid/router`). Solid 2 encara no és compatible.

## Configuració {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` accepta `i18n`, `locales`, `defaultLocale` i `routingStrategy`; una prop omesa conserva el valor del proveïdor exterior, la instància inclosa. `getLocaleName()` i `<I18nSwitcher>` llegeixen `locales`; sense aquesta prop no tenen res a llistar. Les opcions són a [la instància](/ca/integrations/overview#the-instance). La instància és la del [runtime](/ca/integrations/runtime-package), amb un senyal sobre el seu magatzem.

## Traduir {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Crideu els mètodes dins de JSX o d'un efecte perquè Solid en faci el seguiment, també `localePath` i `getLocale`; un valor llegit una sola vegada al cos del component no s'actualitza. A la instància, feu el seguiment amb `i18n.locale` i `i18n.currentRoute`: `i18n.getLocale()` continua sent simple, perquè les escriptures el llegeixen. Llegir el locale només reacciona al locale, de manera que un efecte que el llegeix i carrega un diccionari s'executa una sola vegada. No desestructureu les props ni guardeu els resultats de `t('key')` en variables simples.

`useI18n()` retorna `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (un accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` i `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Canviar de locale {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Canviar de locale no carrega res; afegiu primer el diccionari del locale.

`<I18nGroup>` passa una `t` amb prefix a una funció filla. `<I18nT>` i `t()` a dins no porten prefix:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Encaminament {#routing}

L'adaptador de `@solidjs/router` és en un subcamí perquè l'entrada principal no importi mai el router. Crideu-lo sota el router, normalment al `root` del router, on funcionen `useNavigate` i `useLocation`:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

L'adaptador posa prefix a tots els locales excepte el per defecte (`/about`, `/de/about`), i renderitza `<I18nLink>` com l'`<A>` del router. `getCurrentPath` llegeix la ubicació reactiva del router, de manera que els enllaços actius i el selector la segueixen; una estratègia personalitzada aconsegueix el mateix llegint-hi un senyal. Fixeu-vos en l'ordre dels arguments: `(locales, defaultLocale, navigate, location)`. Per a altres routers, escriviu un adaptador amb `getCurrentPath`, `push` i `replace` (tots obligatoris) — vegeu [Adaptador de router](/ca/integrations/overview#router-adapter).

## SSR {#ssr}

Per al renderitzat al servidor, compileu amb `vite-plugin-solid`: la condició d'exportació `solid` del paquet li proporciona el codi font, de manera que es compila per al servidor. El `dist` precompilat és només per al navegador. La instància no té `destroy()`; creeu-ne una per aplicació, o una per petició al servidor, i deixeu que el recol·lector d'escombraries se n'encarregui.
