`@i18n-micro/node` és la instància de [runtime](/ca/integrations/runtime-package) més un carregador que llegeix una carpeta de traduccions del disc. Feu-lo servir en un servidor Express o Fastify, una CLI, un generador de correus o PDF, o qualsevol script que necessiti els mateixos fitxers JSON que la vostra aplicació Nuxt. Carregueu els fitxers una vegada i traduïu per petició sense compartir estat mutable entre peticions.

## Instal·lació {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/node @i18n-micro/utils
```

```bash npm
npm install @i18n-micro/node @i18n-micro/utils
```

```bash yarn
yarn add @i18n-micro/node @i18n-micro/utils
```

</CodeGroup>

Sense dependències peer; Node.js `>=20`. `@i18n-micro/utils` només cal per al helper d'`Accept-Language` de més avall.

## Configuració {#setup}

El carregador llegeix l'[estructura de carpetes de Nuxt](/ca/guide/translations): `locales/en.json` és un diccionari arrel, `locales/pages/blog/post/en.json` pertany a la ruta `blog-post`.

```ts
import { createI18n } from '@i18n-micro/node'

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

i18n.t('greeting', { name: 'Ada' }) // 'Hello, Ada!'
i18n.t('title', undefined, undefined, 'blog-post') // from locales/pages/blog/post/en.json
```

Les opcions són les del runtime (vegeu [la instància](/ca/integrations/overview#the-instance)) més `translationDir` i `disablePageLocales` (tracta els fitxers `pages/**` com a diccionaris arrel). `i18n.reload()` buida tots els diccionaris i torna a llegir la carpeta, per a un observador de fitxers en desenvolupament.

`loadTranslations(dir, disablePageLocales?)` també s'exporta per separat i retorna `{ root, routes }`:

```ts
import { loadTranslations } from '@i18n-micro/node'

const { root, routes } = await loadTranslations('./locales')
// root:   { en: {...}, de: {...} }
// routes: { 'blog-post': { en: {...}, de: {...} } }
```

## Per petició {#per-request}

Una instància conté un locale i una ruta. Canviar `i18n.locale` en una instància compartida dins d'un gestor de peticions provoca condicions de carrera amb les peticions concurrents. `run` dona a cada petició la seva pròpia instància:

```ts
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

// `() => next()`: `run` hands its callback the fork, and Express reads an argument of `next` as an error
app.use((req, res, next) => i18n.run(pickLocale(req), () => next()))

app.get('/', (req, res) => {
  res.send(i18n.t('greeting')) // the request's locale, in everything it awaits
})
```

Dins de `run`, la instància compartida llegeix i estableix el locale i la ruta de la petició (`AsyncLocalStorage`); la bifurcació comença a la ruta actual, i `i18n.setRoute(...)` dins del callback canvia la ruta d'aquella petició. El callback també rep la bifurcació de la petició: els diccionaris que s'hi escriuen es queden a la petició, i els que s'escriuen a la instància compartida arriben a tothom.

Sense `AsyncLocalStorage`, `i18n.fork(locale)` retorna el mateix tipus d'instància per passar-la d'un lloc a un altre.

`reload()` torna a llegir el directori; els diccionaris antics responen fins que els nous estan carregats.

## Triar el locale {#pick-the-locale}

`detectLocaleFromAcceptLanguage(header, locales)` respecta els pesos `q` i fa coincidir `de-DE` amb un locale `de` (i `de` amb `de-DE`). Retorna `null` quan no coincideix res.

```ts
import express from 'express'
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

const app = express()

app.get('/hello', (req, res) => {
  const locale = detectLocaleFromAcceptLanguage(req.headers['accept-language'], locales) ?? 'en'
  const i18n = byLocale.get(locale)!
  res.json({ message: i18n.t('greeting', { name: 'Ada' }) })
})
```

Per combinar el prefix de l'URL, la galeta i la capçalera, `resolveLocale({ defaultLocale, validLocales, url, cookie, acceptLanguage, autoDetectLanguage: true })` de `@i18n-micro/utils/resolve-locale` aplica la precedència del mòdul: l'URL, després la galeta, després `Accept-Language` i finalment el locale per defecte. Els valors no vàlids s'ometen.

Dins d'una aplicació Nuxt no necessiteu aquest paquet al servidor: feu servir les [traduccions al servidor](/ca/guide/server-side-translations) del mòdul.

## API {#api}

| Exportació | Notes |
| --- | --- |
| `createI18n(options)`, `I18n` | instància de runtime + `translationDir`, `loadTranslations(dir?)`, `reload()` |
| `loadTranslations(dir, disablePageLocales?)` | `{ root, routes }` |
| `loadRootTranslations(dir, disablePageLocales?)` | només `root` |
| `FormatService`, `interpolate` | de core |
| Tipus: `I18nOptions`, `LoadedTranslations`, `Translations`, `Locale`, `PluralFunc`, `Params` | |

Els mètodes de la instància es llisten a [Runtime](/ca/integrations/runtime-package#api). Signatures completes: [referència del paquet](/ca/api/packages/node).
