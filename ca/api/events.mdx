El mòdul crida un hook d'execució (de l'aplicació), `i18n:register`. Feu-lo servir quan un plugin o un mòdul afegeix traduccions que no són als vostres fitxers de `locales/`. La vostra funció de retorn rep una funció `register` que fusiona traduccions a la pàgina que s'està mostrant.

## `i18n:register` {#i18nregister}

```ts
'i18n:register': (
  register: (translations: unknown, locale?: string) => void,
  locale: string,
) => HookResult
```

| Argument | Descripció |
| --- | --- |
| `register(translations, locale?)` | Fusiona en profunditat `translations` al fragment de pàgina de la ruta que s'està carregant, per a `locale` (per defecte: el `locale` del hook). Les claus que ja hi són se sobreescriuen. |
| `locale` | El locale de la ruta que s'està carregant. |

El hook està tipat mitjançant `RuntimeNuxtHooks`, de manera que `nuxtApp.hook('i18n:register', …)` no necessita cap conversió de tipus.

## Quan s'executa {#when-it-fires}

El plugin carregador (`i18n-plugin-loader`) el crida:

1. una vegada en iniciar-se, quan tots els plugins s'han executat (`app:created`) i abans que l'aplicació es renderitzi;
2. al seu `router.beforeEach`, després de carregar les traduccions de la pàgina de destinació, quan canvia la ruta — a cada navegació amb `no_prefix`.

Cada funció de retorn i cada crida a `register` s'espera abans que l'aplicació es renderitzi o que la navegació continuï, de manera que la pàgina es renderitza amb les claus fusionades. Amb [`hooks: false`](/ca/api/module-options#hooks) el hook no es crida mai.

## Exemple {#example}

```ts
// plugins/i18n-extra.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('i18n:register', async (register, locale) => {
    const extra = await $fetch<Record<string, unknown>>(`/api/cms-strings/${locale}`)
    register(extra, locale)
  })
})
```

Aquest és un hook d'execució: registreu-lo amb `nuxtApp.hook` en un plugin, no amb `nuxt.hook` a `nuxt.config` ni al `setup` d'un mòdul. Un mòdul afegeix un plugin d'aquest tipus amb `addPlugin`.
