---
title: "Capes i dominis"
description: "Compartiu la configuració d'i18n i els fitxers de traducció amb capes de Nuxt, i serviu els locales als seus propis dominis."
---

Una capa de Nuxt pot contenir la configuració d'i18n i la carpeta `locales/` per a diverses aplicacions, i cada aplicació hi afegeix o en substitueix el que necessita. Aquesta pàgina ho mostra, i també com una sola compilació serveix diversos dominis.

## Compartir la configuració i les traduccions {#share-config-and-translations}

```ts
// base/nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    defaultLocale: 'en',
  },
})
```

```ts
// shop/nuxt.config.ts
export default defineNuxtConfig({
  extends: ['../base'], // a layer directory or package, not a nuxt.config file
  i18n: {
    locales: [
      { code: 'es', iso: 'es-ES' }, // added
      { code: 'fr', disabled: true }, // the base layer's fr, switched off here
    ],
  },
})
```

- **Configuració:** les opcions escalars de l'aplicació substitueixen les de la capa. Els arrays `locales` de totes les capes es combinen, i les entrades amb el mateix `code` es fusionen en una de sola en què guanyen els camps de l'aplicació, de manera que una aplicació pot afegir un locale o establir camps com `disabled: true` en un d'heretat.
- **Traduccions:** les carpetes `locales/` de totes les capes es fusionen clau per clau, primer la capa i l'aplicació al final, de manera que una clau a `shop/locales/en.json` substitueix la mateixa clau a `base/locales/en.json`. Els fitxers de pàgina (`locales/pages/<page>/`) es fusionen de la mateixa manera.
- **Pàgines:** `$defineI18nRoute` es llegeix de les pàgines de totes les capes.

Per fusionar carpetes que no formen part d'una capa, llisteu-les a [`additionalTranslationDirs`](/ca/api/module-options#additionaltranslationdirs).

## Diversos dominis {#multiple-domains}

Una sola compilació serveix tots els dominis. Llisteu cada locale amb el seu domini; `baseDefault` el converteix en el locale per defecte d'aquell host:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'de', iso: 'de-DE', baseUrl: 'https://example.de', baseDefault: true },
      { code: 'nl', iso: 'nl-NL', baseUrl: 'https://example.de' },
      { code: 'fr', iso: 'fr-FR' },
    ],
  },
})
```

Apunteu els dos dominis al mateix servidor. El host de la petició decideix la resta:

- **Per defecte:** el locale `baseDefault` del host. Si no n'hi ha, el locale per defecte de la compilació si el host el serveix; si no, el primer locale del host.
- **Locales servits:** els locales d'aquell host, més tots els locales sense `baseUrl`. A `example.de` són `de`, `nl` i `fr`.
- **Els locales d'altres dominis** són destinacions d'enllaç. `$localePath`, `$localeRoute`, `$switchLocalePath`, `<i18n-switcher>` i `hreflang` donen URL absoluts al seu `baseUrl`, i `$switchLocale` hi navega. En aquest host els seus URL donen 404, i ni una galeta ni `Accept-Language` els poden triar.
- **Un enllaç a un altre domini** passa per `$localePath` o `<i18n-link>`: `<NuxtLink :to="$localePath('/contact', 'de')">`, `<i18n-link :to="$localeRoute('/contact', 'de')">`. El router no accepta cap objecte absolut, de manera que `<NuxtLink :to="$localeRoute(...)">` i `router.push($localeRoute(...))` es queden en aquest origen. A `localhost` o en un host de previsualització, cada locale amb `baseUrl` és un enllaç d'aquest tipus, l'actual inclòs. En codi, feu servir `navigateTo($localePath('/contact', 'de'), { external: true })`, o `$switchRoute`.
- **Qualsevol altre host** rep la configuració de la compilació, amb cada locale amb `baseUrl` com a destinació d'enllaç. No es reprodueix res de la petició: canonical i `hreflang` fan servir `metaBaseUrl`, o si no el `baseUrl` del locale per defecte de la compilació (un locale per defecte sense `baseUrl` necessita `metaBaseUrl` o `site.url`, vegeu [SEO](/ca/guide/seo#set-the-public-origin)).
- **Els fitxers de càrrega** a `public/` són estàtics: qualsevol host retorna el fitxer de qualsevol locale. La [generació](/ca/guide/deployment#static-site-(nuxi-generate)) per domini només publica els d'aquell domini.

`example.de` amb cada estratègia, amb `de: '/kontakt'` com a camí personalitzat de `contact`:

| Estratègia | `/` | Pàgina del locale per defecte | Altres URL |
| --- | --- | --- | --- |
| `prefix_except_default` | `de` | `/kontakt` | `/de/kontakt` i `/en/contact` donen 404, `/contact` redirigeix a `/kontakt` |
| `prefix_and_default` | `de` | `/kontakt` i `/de/kontakt`, els enllaços fan servir `/kontakt` | `/en/contact` i `/contact` donen 404 |
| `prefix` | redirigeix a `/de` | `/de/kontakt` | `/kontakt` redirigeix a `/de/kontakt`, `/en/contact` dona 404 |
| `no_prefix` | `de` | `/kontakt` | un camí personalitzat d'un locale d'un altre domini dona 404 |

Amb `prefix`, un enllaç des d'un altre domini manté el prefix, ja que l'URL sense prefix només redirigiria. Amb `no_prefix`, un enllaç a un altre domini arriba al locale per defecte d'aquell host: l'URL no en pot indicar un segon.

Coses a tenir en compte:

- **Darrere d'un proxy**, el host ve de `Host`. Si el proxy posa el host públic a `X-Forwarded-Host`, establiu [`trustForwardedHost`](/ca/api/module-options#trustforwardedhost), i només quan el proxy sobreescriu aquesta capçalera. Un proxy que no envia cap de les dues no pot servir una compilació amb dominis. Vegeu [Darrere d'un proxy o CDN](/ca/guide/deployment#behind-a-proxy-or-cdn).
- **`app.baseURL`** també ha d'anar a `baseUrl`: `baseUrl: 'https://example.de/shop'` amb `app.baseURL: '/shop'`.
- **Els hosts coincideixen exactament.** `www.example.de` és un altre host: redirigiu-lo a la vora (edge), o establiu aquest `baseUrl` al locale. Només un host per locale.
- **Les memòries cau han d'indexar per host.** Una CDN normalment ho fa. La memòria cau de rutes de Nitro indexa pel camí, així que en una compilació amb dominis el mòdul afegeix `host` a `cache.varies` de cada regla `swr` i `cache`, i `x-forwarded-host` amb `trustForwardedHost`. Una regla amb `cache: false` es queda tal com està escrita. `isr` és la memòria cau de la plataforma: comproveu que indexi per host.
- **Els camins personalitzats de dos locales per defecte de host no poden col·lidir.** Els registres sense prefix comparteixen un sol router, de manera que `/x` no pot ser una pàgina a `example.de` i una altra a `example.com`.
- **Pàgines prerenderitzades:** una regla de ruta `prerender: true` a `nuxt build` es renderitza una sola vegada, sense host, i el fitxer respon a tots els dominis. Deixeu al servidor les pàgines que difereixen per domini, o [genereu per domini](/ca/guide/deployment#static-site-(nuxi-generate)).
- **`noPrefixRedirect`** es basa en el locale del host i del visitant, a tots els hosts.
- **`hashMode`:** el host tria el renderitzat com s'ha descrit, i els enllaços a un altre domini porten la ruta al hash (`https://example.com/#/contact`).
- **`ssr: false`:** el navegador llegeix el domini de `location.host`, així que un host sense servidor també es resol.
- **Les [substitucions en temps d'execució](/ca/guide/runtime-overrides)** s'apliquen primer. Un `disabledLocales` en temps d'execució s'aplica a tots els hosts, amb una excepció: amb `prefix_except_default` i `prefix_and_default`, el locale per defecte d'un host continua habilitat al seu host, ja que les seves pàgines són els registres sense prefix. Amb `prefix` i `no_prefix`, el host passa al següent locale que serveix. Un `defaultLocale` en temps d'execució només s'aplica als hosts desconeguts.

Per a un [lloc estàtic](/ca/guide/deployment#static-site-(nuxi-generate)), genereu una vegada per domini.

### Una aplicació per domini {#one-app-per-domain}

Una capa compartida amb una petita aplicació per domini també funciona, quan els dominis necessiten pàgines o mòduls diferents. Cada aplicació estableix el seu propi `defaultLocale` sobre la mateixa llista `locales`. Un locale d'un altre domini dona 404 en aquella aplicació, com s'ha explicat.

### Triar el locale en codi {#choosing-the-locale-in-code}

Per a una sola instància que respon a tots els dominis amb l'origen de la petició a les etiquetes SEO, vegeu [SEO](/ca/guide/seo#set-the-public-origin); per triar el locale a partir del host en codi, vegeu [Detecció personalitzada del locale](/ca/guide/custom-auto-detect).
