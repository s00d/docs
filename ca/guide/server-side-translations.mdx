Els handlers de servidor a `server/api/` i `server/routes/` poden traduir cadenes i llegir el locale de la petició amb dos helpers importats automàticament. Feu-los servir per a respostes d'API, correus electrònics, feeds o qualsevol cosa renderitzada fora d'una pàgina Vue. Llegeixen els mateixos fitxers de traducció que les vostres pàgines i detecten el locale a partir de la petició.

## Traduir en un handler {#translate-in-a-handler}

```ts
// server/api/greeting.get.ts
export default defineEventHandler(async (event) => {
  const t = await useTranslationServerMiddleware(event)
  return { message: t('greeting', { name: 'Ada' }) }
})
```

```bash
curl 'http://localhost:3000/api/greeting?locale=de'
# {"message":"Hallo, Ada!"}
```

`useTranslationServerMiddleware(event, defaultLocale?, locale?)` és asíncron i retorna `t(key, params?, defaultValue?)`. `t` retorna la cadena, interpola els paràmetres `{name}` i, quan falta la clau, retorna un `defaultValue` no buit o, si no n'hi ha, la clau.

`t` només veu el fragment `index`: els fitxers arrel (`locales/<locale>.json`) més `locales/pages/index/` si existeix (només els fitxers arrel amb `disablePageLocales`). Les claus d'altres pàgines no es carreguen. Per a aquestes, carregueu el fragment vosaltres mateixos:

```ts
const { data } = await loadTranslationsFromServer('de', 'about') // Translations object of the about page
```

## Llegir el locale de la petició {#read-the-request-locale}

```ts
// server/api/locale.get.ts
export default defineEventHandler((event) => {
  const { current, isDefault, locale } = useLocaleServerMiddleware(event)
  return { current, isDefault, dir: locale?.dir ?? 'ltr' }
})
```

`useLocaleServerMiddleware(event, defaultLocale?, locale?)` és síncron i retorna:

```ts
interface LocaleInfo {
  current: string // detected locale code
  default: string // defaultLocale, runtime overrides included (fixed at build under prefix_except_default / prefix_and_default)
  fallback: string // fallbackLocale, else the default
  available: string[] // enabled locale codes
  locale: Locale | null // the config entry of `current`
  isDefault: boolean
  isFallback: boolean
}
```

## Com es tria el locale {#how-the-locale-is-chosen}

Tots dos helpers fan servir el mateix ordre a cada ruta de servidor, sigui `/api` o no:

1. la query `?locale=` (el primer valor si es repeteix);
2. un paràmetre de ruta `[locale]`, o un prefix de locale al camí (`/de/...`);
3. la galeta del locale, quan [`localeCookie`](/ca/api/module-options#localecookie) està definit (`hash-locale` amb `hashMode`);
4. `Accept-Language`, quan `autoDetectLanguage` està activat (es respecten els valors q);
5. `defaultLocale`.

Els codis no vàlids i desactivats s'ometen a cada pas. Aquest és l'ordre de l'API; la renderització d'una pàgina ignora `?locale=` amb les estratègies de prefix. Tots dos ordres es comparen a [Detecció del locale](/ca/guide/locale-detection).

## Forçar un locale {#force-a-locale}

Passeu el tercer argument per ometre la detecció, per exemple en una tasca que envia correus en l'idioma de l'usuari:

```ts
export default defineEventHandler(async (event) => {
  const user = await getUser(event) // your code
  const t = await useTranslationServerMiddleware(event, undefined, user.locale)
  return sendMail(user.email, t('mail.welcome.subject'))
})
```

El segon argument substitueix `defaultLocale` per a la detecció d'aquesta crida, de manera que no té cap efecte quan es força un locale. Els diccionaris es desen a la memòria cau per petició i per locale, i entre peticions a la memòria cau de traduccions del servidor, de manera que cridar un helper diverses vegades és barat.

## Components de servidor {#server-components}

Un component de servidor (`.server.vue`, `<NuxtIsland>`) es renderitza des de la seva pròpia URL, `/__nuxt_island/...`, de manera que no veu la URL de la pàgina, i Nuxt només li passa les seves props. Passeu el locale com a prop `locale`. Aleshores es renderitza en aquest locale, i un canvi de locale el torna a obtenir, ja que les props formen part de la URL i de la clau de memòria cau de l'illa. El nom està reservat: qualsevol codi de locale habilitat en una prop anomenada `locale` estableix el locale de la renderització, així que doneu un altre nom a una prop que signifiqui una altra cosa, com ara un format de números:

```vue
<!-- components/Greeting.server.vue -->
<template><p>{{ $t('greeting') }}</p></template>
<script setup lang="ts">
defineProps<{ locale?: string }>()
</script>
```

```vue
<template>
  <Greeting :locale="$getLocale()" />
  <NuxtIsland name="Greeting" :props="{ locale: $getLocale() }" />
</template>
```

Sense la prop es renderitza en el locale de la galeta o, si no n'hi ha, en el locale per defecte, digui el que digui la URL, i no segueix els canvis de locale. El seu `$t` veu el fragment `index`: els fitxers arrel més `locales/pages/index/`.
