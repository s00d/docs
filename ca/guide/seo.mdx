---
title: "SEO"
description: "Les etiquetes lang, hreflang, canonical i og:locale que afegeix el mòdul, com es tria la seva URL base i com sobreescriure-les per pàgina."
---

Amb `meta: true` (el valor per defecte) cada pàgina localitzada rep `<html lang dir>`, un enllaç canònic, alternatives `hreflang`, `x-default` i etiquetes de locale d'Open Graph. Necessiteu aquesta pàgina quan vulgueu establir l'origen públic, ajustar quins locales apareixen a les etiquetes o sobreescriure-les per a una pàgina. La majoria de llocs només necessiten un `site.url` o `metaBaseUrl` i uns codis `iso` correctes.

## Configuració mínima {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

Aleshores `/de/about` renderitza:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Direcció del text {#text-direction}

`<html dir>` prové del `dir` del locale. Si no en té, una llengua que s'escriu de dreta a esquerra rep `rtl`, llegit de l'`iso` (o del `code`): àrab, hebreu, persa, urdú i algunes altres, i qualsevol etiqueta amb una escriptura RTL com ara `az-Arab`. La resta de locales no reben cap atribut `dir`, cosa que els navegadors interpreten com a `ltr`.

<Warning>

**`dir: 'auto'` costa temps d'anàlisi a les pàgines grans**: `auto` a `<html>` fa que el navegador dedueixi la direcció a partir del contingut mentre l'analitza. A Chromium aquest cost creix més de pressa que la pàgina: uns 100 ms amb 5.000 elements i 1 s amb 20.000. Feu-lo servir només per a una pàgina petita de la qual no podeu saber la llengua.

</Warning>

## Quines etiquetes obteniu {#which-tags-you-get}

- **hreflang**: una etiqueta per cada locale que serveix la pàgina, amb el valor `iso` (o `code` si falta `iso`), i la seva URL amb la mateixa query que la canònica. Una pàgina restringida amb [Configuració de la pàgina](/ca/guide/per-component-translations) o `routeLocales` només llista els seus locales. [`hreflangBaseLanguage: true`](/ca/api/module-options#hreflangbaselanguage) també afegeix la llengua base (`es-ES` → `es`) per al primer locale regional.
- **x-default**: la URL del locale per defecte, només quan el locale per defecte serveix la pàgina.
- **og:locale**: derivat de l'`iso` (`en-US` → `en_US`). Establiu `og` al locale quan la correspondència no és directa, per exemple `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; sense cap dels dos, no s'escriu cap `og:locale` i el mode de desenvolupament avisa.
- **canonical / og:url**: la URL actual sense paràmetres de query, excepte els de [`canonicalQueryWhitelist`](/ca/api/module-options#canonicalquerywhitelist) (per defecte `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Per estratègia:

| Estratègia | hreflang i x-default | canonical, og:url, og:locale, atributs html |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | sí | sí |
| `no_prefix` | no (una sola URL serveix tots els locales) | sí |

## Establir l'origen públic {#set-the-public-origin}

Les URL absolutes fan servir el primer de:

1. [`metaBaseUrl`](/ca/api/module-options#metabaseurl);
2. `site.url` de `nuxt-site-config` (instal·lat per `@nuxtjs/seo`);
3. l'origen de la petició, amb `app.baseURL` afegit.

Fixeu un dels dos primers.

<Warning>

L'alternativa de l'origen de la petició llegeix `X-Forwarded-Host` i `X-Forwarded-Proto`, perquè [`metaTrustForwardedHost`](/ca/api/module-options#metatrustforwardedhost) i `metaTrustForwardedProto` valen `true` per defecte. Això només és segur darrere d'un proxy que sobreescrigui aquestes capçaleres; altrament, un client pot triar l'amfitrió dels vostres enllaços canònics, i una memòria cau pot propagar aquesta pàgina.

Si l'aplicació és accessible directament, fixeu `metaBaseUrl`: a diferència d'establir totes dues opcions a `false`, també ignora una capçalera `Host` falsificada. Vegeu [Darrere d'un proxy o CDN](/ca/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

L'alternativa és útil per a un sol desplegament que respon a diversos dominis: `https://site-a.com/en/about` i `https://site-b.com/en/about` reben cadascun el seu propi origen.

Amb `baseUrl` als locales, un amfitrió conegut fa servir el seu propi `baseUrl`, per sobre de `metaBaseUrl` i `site.url`, de manera que canonical i `og:url` es mantenen en aquell domini i `hreflang` dirigeix cada locale al seu domini. Qualsevol altre amfitrió fa servir `metaBaseUrl`, o si no el `baseUrl` del locale per defecte, o si no `site.url`, de manera que un `Host` falsificat no pot arribar a les vostres etiquetes. Si no n'hi ha cap de definit, es manté l'alternativa de l'origen de la petició i la compilació avisa. Vegeu [Capes i dominis](/ca/guide/layers#multiple-domains).

## Excloure locales o pàgines {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Si el locale per defecte té `seo: false`, no s'escriu cap `x-default`. Per desactivar les etiquetes en una pàgina, feu servir `disableMeta` a [Configuració de la pàgina](/ca/guide/per-component-translations#turn-off-seo-tags), o [`routeDisableMeta`](/ca/api/module-options#routedisablemeta) a la configuració.

## Sobreescriure etiquetes en una pàgina {#override-tags-on-one-page}

Per a contingut d'un CMS on només existeixen algunes traduccions, o quan les URL provenen d'una API, substituïu les etiquetes generades amb [`useI18nHead`](/ca/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` també pot establir o eliminar `canonical`, `xDefault`, `ogLocale` i `ogUrl`; `disable` descarta grups sencers (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Passeu un getter perquè els valors es tornin a calcular després d'un canvi de locale. Per a slugs per locale, establiu primer `$setI18nRouteParams` ([Rutes localitzades](/ca/guide/custom-locale-routes#per-locale-slugs)) i les alternatives generades ja els faran servir.

## Barra final {#trailing-slash}

`$localePath`, `$switchLocalePath`, l'objecte de ruta de `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, les redireccions de locale i les URL de SEO segueixen una sola regla de barra final: `experimental.defaults.nuxtLink.trailingSlash` per defecte, o [`trailingSlash`](/ca/api/module-options) a la configuració d'i18n quan els camins d'i18n hagin de ser diferents.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) funciona amb aquest mòdul mitjançant `nuxt-site-config` 4+. Poseu `nuxt-i18n-micro` primer a la llista perquè la configuració del lloc pugui llegir els locales, i establiu `site.url` una sola vegada: també alimenta les etiquetes anteriors.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Un nom i una descripció del lloc traduïts provenen de les claus `nuxtSiteConfig.name` / `nuxtSiteConfig.description` dels vostres fitxers de locale. L'error `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` vol dir que `@nuxtjs/seo` és anterior a la 3; actualitzeu-lo ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
