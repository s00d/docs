---
title: "Detecció personalitzada del locale"
description: "Trieu vosaltres mateixos el locale (per domini, capçalera o perfil d'usuari) amb un plugin de servidor i useI18nLocale().setLocale()."
---

La detecció integrada llegeix l'URL, una galeta i `Accept-Language`. Quan el locale depèn d'una altra cosa (el domini, una capçalera geogràfica definida pel vostre CDN, un perfil d'usuari), establiu-lo vosaltres mateixos en un plugin que s'executi abans del plugin d'i18n. Aleshores el mòdul carrega les traduccions d'aquest locale i l'utilitza per a les redireccions exactament com si l'hagués detectat ell. Les regles que decideixen quan un locale triat preval sobre l'URL es troben a [Detecció del locale](/ca/guide/locale-detection); aquesta pàgina mostra com connectar-hi la vostra pròpia font.

## Establir el locale en un plugin de servidor {#set-the-locale-in-a-server-plugin}

```ts
// plugins/i18n-locale.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10, // before the i18n plugin (order -5)
  setup() {
    const { setLocale } = useI18nLocale()
    const host = (useRequestHeaders(['host']).host ?? '').split(':')[0]! // without the port

    if (host.endsWith('.de')) setLocale('de')
    else if (host.endsWith('.fr')) setLocale('fr')
  },
})
```

`setLocale(code)` escriu l'estat del locale (`useState('i18n-locale')`) i, quan hi ha configurada una galeta de locale, també la galeta. Utilitzeu-lo en lloc d'escriure vosaltres mateixos `useState` o `useCookie`. Passeu-hi només codis de locales habilitats.

Mantingueu el plugin com a `.server.ts` quan llegeixi capçaleres de la petició: no existeixen al navegador. Un plugin `.client.ts` és el lloc per a fonts exclusives del navegador com ara `localStorage`.

## Desactivar el pas integrat d'Accept-Language {#turn-off-the-built-in-accept-language-step}

El vostre plugin i `Accept-Language` poden no coincidir. Per deixar que només decideixi el vostre codi (més l'URL i la galeta), desactiveu la capçalera:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    autoDetectLanguage: false,
  },
})
```

[`autoDetectLanguage`](/ca/api/module-options#autodetectlanguage) només controla el pas de la capçalera. L'URL i una galeta vàlida continuen comptant.

## Què passa després {#what-happens-next}

L'efecte de `setLocale` depèn de l'[estratègia](/ca/guide/strategy):

| Estratègia | Efecte de `setLocale('de')` al plugin |
| --- | --- |
| `no_prefix` | La pàgina es renderitza en alemany; l'URL no canvia. |
| `prefix`, `prefix_except_default` | En un camí sense prefix on [`autoDetectPath`](/ca/api/module-options#autodetectpath) permet redireccions (per defecte només `/`), el servidor respon `302` cap a l'URL alemanya. Una URL amb prefix de locale el conserva. |
| `prefix_and_default` | Sense redirecció: l'URL sense prefix és una pàgina vàlida del locale per defecte. |

Amb les estratègies de prefix, un locale a l'URL és l'elecció de l'usuari i el vostre plugin no el sobreescriu. `autoDetectPath: '*'` és l'excepció: aleshores el servidor mou les URL amb prefix segons la galeta i `Accept-Language` i ignora l'estat, però `setLocale()` també escriu la galeta quan n'hi ha una de configurada, de manera que a partir de la petició següent l'elecció del vostre plugin pot redirigir una URL amb prefix. Mantingueu `'/'` o utilitzeu `'no_prefix'` quan les URL de locale explícites hagin de prevaler. Utilitzeu el plugin per triar on arriba un visitant, no per reescriure els enllaços que ha seguit.

## Respectar un locale triat per l'usuari {#respect-a-locale-the-user-picked}

Quan un usuari canvia d'idioma, el canvi escriu la galeta. Ometeu la vostra pròpia detecció quan ja hi hagi una preferència vàlida:

```ts
// plugins/i18n-locale.server.ts
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10,
  setup() {
    const { getPreferredLocale, setLocale, validLocales } = useI18nLocale()
    if (getPreferredLocale()) return // valid state or cookie: keep it

    const country = useRequestHeaders(['x-country'])['x-country']
    if (country === 'JP') return setLocale('ja')

    const header = useRequestHeaders(['accept-language'])['accept-language']
    setLocale(detectLocaleFromAcceptLanguage(header, validLocales))
  },
})
```

`getPreferredLocale()` retorna l'estat o la galeta només quan és un locale habilitat, de manera que una galeta obsoleta no atura la detecció. `detectLocaleFromAcceptLanguage` és el comparador que té en compte els valors q i que el mateix mòdul utilitza (instal·leu `@i18n-micro/utils` per importar-lo); `setLocale(null)` no fa res.

## Un domini per locale {#one-domain-per-locale}

Si cada domini ha de servir els seus propis locales, no necessiteu cap plugin: doneu a cada locale un `baseUrl`, establiu `baseDefault: true` al locale per defecte de cada domini i compileu una sola vegada (un lloc estàtic continua executant `nuxi generate` per domini). Vegeu [Capes i dominis](/ca/guide/layers#multiple-domains).
