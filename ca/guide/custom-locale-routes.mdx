---
title: "Rutes localitzades"
description: "Doneu a una pàgina una URL diferent per locale amb localeRoutes o globalLocaleRoutes, inclosos paràmetres dinàmics i slugs per locale."
---

Per defecte, cada locale serveix una pàgina al mateix camí: `/en/about`, `/de/about`. Les rutes localitzades permeten que cada locale faci servir les seves pròpies paraules, com ara `/de/ueber-uns`, mentre el fitxer de la pàgina continua sent el mateix. Les definiu a la pàgina amb `$defineI18nRoute`, o per a moltes pàgines alhora a `nuxt.config.ts`.

## A la pàgina {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

Amb `prefix_except_default` i `defaultLocale: 'en'`, la pàgina respon a `/about`, `/de/ueber-uns` i `/fr/a-propos`. Un locale sense entrada conserva el camí per defecte. Escriviu els camins sense el codi del locale: el prefix l'afegeix l'[estratègia](/ca/guide/strategy), i un camí que comença amb el codi del locale registra un avís. Què més accepta la crida s'explica a [Configuració de la pàgina](/ca/guide/per-component-translations).

## A nuxt.config {#in-nuxt-config}

[`globalLocaleRoutes`](/ca/api/module-options#globallocaleroutes) fa el mateix per a qualsevol pàgina, indexada pel seu camí (o pel nom de la ruta, si s'escriu sense barra inicial):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

Quan una pàgina estableix `localeRoutes` i `globalLocaleRoutes` té la mateixa clau, guanya l'entrada de la configuració.

## Paràmetres dinàmics {#dynamic-params}

Escriviu els paràmetres en qualsevol forma de Nuxt: `[id]`, `[[page]]`, `[...slug]` o `:id()`. Els noms dels paràmetres han de coincidir amb el fitxer de la pàgina.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

Les pàgines niades admeten un camí fill absolut (`/ueber-uns/team`) o un camí relatiu al camí localitzat del pare (`team`).

## Enllaçar a pàgines localitzades {#linking-to-localized-pages}

Els enllaços es resolen al camí localitzat del locale de destinació, tant si passeu un nom de ruta com un camí simple:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

Els noms de ruta provenen del camí del fitxer (`pages/about/team.vue` és `about-team`), tret que n'establiu un amb `definePageMeta({ name })`.

## Slugs per locale {#per-locale-slugs}

Quan el mateix slug difereix per locale (`/our-products/red-shoe` vs `/de/unsere-produkte/roter-schuh`), indiqueu al selector d'idioma quins paràmetres ha de fer servir amb `$setI18nRouteParams` un cop carregades les dades:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

Aleshores `$switchLocalePath('de')` i `<i18n-switcher>` enllacen a `/de/unsere-produkte/roter-schuh`. Les claus són codis de locale i els valors són paràmetres per nom (com al fitxer de la pàgina).

Un selector al layout es renderitza abans que el setup asíncron de la pàgina arribi fins aquí, de manera que quan acaba la renderització el mòdul reescriu els enllaços de `<i18n-switcher>`, tant a `app.vue` com a la pàgina. Així, l'HTML del servidor, un visitant sense JavaScript i la primera renderització del client coincideixen. Per a això, establiu els paràmetres durant l'SSR: amb `lazy` o `server: false` els enllaços només canvien després de la hidratació. L'streaming SSR de Nuxt envia l'HTML abans que es coneguin els paràmetres, de manera que en aquest cas els enllaços del primer HTML conserven els paràmetres de la mateixa URL.

Només es reescriuen els enllaços propis del selector. Un enllaç `$switchLocalePath` escrit a mà s'ha de renderitzar després d'establir els paràmetres, així que poseu-lo a la pàgina que els estableix, també després d'un `await`. En un layout es renderitza primer: el seu HTML del servidor conserva els paràmetres de la URL i la hidratació avisa d'una discrepància. Feu servir `<i18n-switcher>` allà, amb els seus slots i les props `custom*Style` per a l'aspecte.

Els paràmetres pertanyen a la pàgina que els ha establert:

- Es descarten quan es confirma una navegació cap a un altre camí, de manera que cada pàgina estableix els seus. Una navegació cancel·lada els deixa al seu lloc.
- Obteniu `$setI18nRouteParams` de `useNuxtApp()` o `useI18n()` dins de `setup`, també quan el crideu més tard en un handler de `useAsyncData`. Obtinguda allà, la funció coneix la seva pàgina: si el visitant ja ha marxat, una crida tardana no fa res.
- Amb `keepalive`, una pàgina recupera els paràmetres que havia establert quan el visitant hi torna. `useI18nHead` fa el mateix.

## Rutes afegides a pages:extend {#routes-added-in-pagesextend}

Les rutes que afegiu al hook `pages:extend` no tenen cap fitxer de pàgina del qual llegir `$defineI18nRoute`, i sovint diverses comparteixen un mateix component embolcall. Una ruta afegida sense `name` rep el nom que Nuxt donaria al seu camí (`/a/:id()` esdevé `a-id`), de manera que els enllaços d'idioma hi arriben, tret que una altra ruta ja tingui aquest nom; en aquest cas, doneu-li un `name` explícit. Mantingueu una sola llista i dividiu-la en pàgines i `globalLocaleRoutes` indexades per nom de ruta amb `splitLocaleRoutes` de `@i18n-micro/utils/split-locale-routes` (afegiu el paquet a les vostres dependències):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

No poseu camins localitzats a `route.meta`: s'inclourien a la taula de rutes del client.
