### Descripció {#description}

Compara **Nuxt sense i18n**, **i18n-micro** i **`@nuxtjs/i18n`** amb un mateix perfil de diccionari compartit mitjançant `untestutils/perf`.

Enfocament: temps de compilació, RSS màxim, **codi vs traduccions (asset) vs total** desplegable, i càrrega (Artillery).

### Notes de metodologia {#methodology-notes}

- Les mètriques són **mitjanes de 3 execucions consecutives per fixture** (no intercalades).
- **Artefacte**: `.output/server/index.mjs` del node-server de Nitro després d'un `nuxi build` forçat; `nuxt-i18n-micro` és el **dist compilat del mòdul** (no l'stub jiti de `dev:prepare`). Vegeu la [metodologia dels benchmarks](https://s00d.github.io/nuxt-i18n-micro/contributing/performance-methodology).
- **Traduccions** = `bundle.asset` (JSON de locales, `chunks/raw/`, chunks de locale coincidents mitjançant `isTranslationFile`).
- **Codi** exclou els source maps (`*.map`): les fixtures enllacen el mòdul des del repositori, de manera que Nitro hi escriu maps complets i cap per a les dependències de npm.
- **plain-nuxt** serveix el mateix volum de fulles com a JSON estàtic: intensiu en E/S sota càrrega, no “sobrecàrrega d'i18n”.
- Perfil de càrrega `--load full`: escalfament 6s@6 + principal 60s@60 sense límit (històric).
- Pauses de refredament `--cool fast` (vegeu el document de metodologia).
- Cadascuna de les compilacions de `runs` és **forçada** (sense posar a zero el temps de compilació per memòria cau calenta).
- La **taxa d'errors** d'Artillery a les taules correspon a errors d'estat HTTP de les mètriques de càrrega. Els gràfics també mostren `vusers.failed` (temps d'espera esgotats del client en saturació); aquests poden ser alts mentre la taxa d'errors HTTP es manté al 0%.

## Notes {#notes}

- Perfil compartit: 4 locales × 2 pàgines × ~16.8k fulles d'índex.
- Càrrega: només Artillery programàtic: escalfament **6s@6** + principal **60s@60**, VU sense límit (metodologia YAML històrica). Camins del perfil d'execució: vegeu `scripts/src/perf/load.ts`.
- Pauses de refredament: 2s després de compilar, 3s entre execucions, 5s entre fixtures. Les compilacions es forcen a cada execució perquè les mitjanes no es dilueixin amb encerts de memòria cau.
- Per tornar-ho a executar en el dia a dia: `pnpm test:performance` (`--load short --cool fast`).
- Per regenerar aquesta pàgina: `pnpm -C scripts cli performance --load full --only all --runs 3`.
- Opcions: `--locales N --keys K --only all|micro|i18n|plain --runs N --skip-load --cool fast|strict`.
