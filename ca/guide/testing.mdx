Els components que criden `useI18n()` necessiten una instància d'i18n a les proves unitàries. `@i18n-micro/test-utils` us proporciona un `useI18n()` fals amb lògica real de traducció, plurals i format, de manera que podeu muntar un component amb els vostres propis diccionaris i sense servidor Nuxt. Per a l'encaminament i les redireccions, executeu el mòdul real de punta a punta amb `@nuxt/test-utils`.

Aquesta pàgina tracta de provar la vostra aplicació. Com aquest repositori prova el mateix mòdul s'explica a [Provar el mòdul](https://s00d.github.io/nuxt-i18n-micro/contributing/testing).

## Instal·lació {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

```bash npm
npm install -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

</CodeGroup>

## Simular useI18n {#mock-usei18n}

```ts
// tests/unit-setup.ts
import { setupNuxtI18nMock } from '@i18n-micro/test-utils'
import { mockNuxtImport } from '@nuxt/test-utils/runtime'
import { beforeEach, vi } from 'vitest'

export const { i18n, useI18n, setTranslationsFromJson } = setupNuxtI18nMock({
  spy: vi.fn, // every method becomes a vi.fn, so you can assert calls
  beforeEach, // reset state and reseed `translations` before each test
  translations: { welcome: 'Welcome' },
})

mockNuxtImport('useI18n', () => useI18n)
```

```ts
// vitest.config.ts
import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    environment: 'nuxt',
    setupFiles: ['./tests/unit-setup.ts'],
  },
})
```

Mantingueu `mockNuxtImport` al fitxer de configuració: `@nuxt/test-utils` l'ha de transformar. `setupNuxtI18nMock` fa servir una memòria cau de traduccions privada, de manera que els fitxers de prova en paral·lel no comparteixen estat.

## Escriure una prova {#write-a-test}

```vue
<!-- components/Greeting.vue -->
<script setup lang="ts">
const { $t } = useI18n()
</script>

<template>
  <p>{{ $t('welcome') }}</p>
</template>
```

```ts
// tests/greeting.spec.ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { expect, it } from 'vitest'
import Greeting from '~/components/Greeting.vue'
import de from '~/locales/de.json'
import { i18n, setTranslationsFromJson } from './unit-setup'

it('renders the German greeting', async () => {
  await setTranslationsFromJson('de', de)
  i18n.setLocale('de')

  const wrapper = await mountSuspended(Greeting)
  expect(wrapper.text()).toBe('Willkommen') // de.json: { "welcome": "Willkommen" }
})
```

El fals exposa els mateixos mètodes que el `useI18n()` real (`$t`, `$tc`, `$tn`, `$td`, `$has`, `$localePath`, …, amb i sense `$`) més setters per a les proves: `setLocale`, `setLocales`, `setDefaultLocale`, `setRouteName`, `setTranslationsFromJson`, `loadPageTranslations`, `mergeTranslations`, `setMissingHandler`.

`$localePath` i `$switchLocalePath` són stubs que afegeixen el prefix al camí segons l'opció `strategy` (sense router real). Proveu els enllaços i les redireccions reals de punta a punta.

## Helpers de nivell inferior {#lower-level-helpers}

| Helper | Feu-lo servir per a |
| --- | --- |
| `createIsolatedFakeI18n(options)` | Un fals aïllat sense la connexió amb el `useI18n` de Nuxt, p. ex. per a un `mount` simple de `@vue/test-utils` amb `global.mocks`. |
| `createFakeI18n(options)` | Un fals sobre la memòria cau compartida del mòdul (crideu `resetI18n()` a `beforeEach`), o aïllat amb `isolated: true`. |
| `createI18nTestContext(options)` | El context que hi ha darrere de tots dos, quan necessiteu diversos falsos. |
| `t`, `tc`, `ts`, `tn`, `td`, `tdr`, `has` | Crides directes sobre el context compartit, per provar funcions simples. |

El mock és un `BaseI18n`: `t`, `tc`, `tn`, `td`, `tdr` i `has` són els reals, sobre diccionaris reals, de manera que una prova veu el que mostra l'aplicació.

Els helpers de fàbrica anteriors accepten `locale`, `defaultLocale`, `locales`, `routeName`, `strategy`, `translations` i `messages` (diccionaris per idioma). Hi ha un projecte d'exemple complet a [`packages/test-utils/example`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/test-utils/example).

## Proves de punta a punta {#end-to-end-tests}

L'encaminament, les redireccions, les etiquetes SEO i la càrrega de payloads necessiten el mòdul real. Inicieu la vostra aplicació amb `@nuxt/test-utils/e2e`:

```ts
// tests/e2e/locales.test.ts
import { $fetch, fetch, setup } from '@nuxt/test-utils/e2e'
import { describe, expect, it } from 'vitest'

describe('locales', async () => {
  await setup({ server: true })

  it('serves the German page', async () => {
    expect(await $fetch('/de')).toContain('lang="de-DE"')
  })

  it('redirects / for a German browser', async () => {
    const res = await fetch('/', { headers: { 'accept-language': 'de' }, redirect: 'manual' })
    expect(res.headers.get('location')).toBe('/de')
  })
})
```

La segona prova pressuposa `prefix` (o `prefix_except_default` amb un altre idioma per defecte); vegeu [Detecció de l'idioma](/ca/guide/locale-detection) per saber quan redirigeix `/`.
