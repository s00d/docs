---
title: "useI18nLocale"
description: "useI18nLocale은 로케일 상태와 로케일 쿠키를 읽고 씁니다. 사용자 정의 로케일 감지의 진입점입니다."
---

`useI18nLocale()`은 앱이 선택한 로케일, 즉 `i18n-locale` 상태와 로케일 쿠키에 접근할 수 있게 해 줍니다. 로케일을 직접 감지하는 플러그인(도메인, 사용자 프로필, 헤더)에서 `useState('i18n-locale')`이나 쿠키를 직접 쓰는 대신 이것을 사용하세요. 유효성 검사에는 런타임 재정의를 포함하여 활성화된 로케일이 사용됩니다.

## 시그니처 {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

i18n 로케일 관리를 위한 중앙화된 진입점입니다.
useState('i18n-locale'), 로케일 쿠키, 동기화 유틸리티를 결합합니다.

## 반환 값 {#returned-values}

| 멤버 | 타입 | 설명 |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | `useState('i18n-locale')` ref. |
| `localeCookie` | `Ref<string \| null>` | [`localeCookie`](/ko/api/module-options#localecookie) 쿠키. 옵션이 `null`이면 단순한 `{ value: null }`입니다. |
| `hashCookie` | `Ref<string \| null>` | 해시 라우팅에서는 `hash-locale` 쿠키, 그 외에는 `{ value: null }`입니다. |
| `validLocales` | `string[]` | 활성화된 로케일의 코드. |
| `setLocale(locale)` | `(locale: string \| null) => void` | 상태와 쿠키를 씁니다. 유효성을 검사하지 않으며 번역을 로드하지 않습니다. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | 쿠키만 씁니다. |
| `getLocale()` | `() => string \| null` | 상태, 그다음 선호 쿠키(해시 라우팅에서는 해시 쿠키). 유효성을 검사하지 않습니다. |
| `getPreferredLocale()` | `() => string \| null` | 상태와 선호 쿠키 중 첫 번째 **유효한** 값, 또는 `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | 해시 라우팅에서 상태가 설정되어 있으면 상태, 그렇지 않으면 `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, 그다음 유효한 상태, 그다음 `options.serverLocale`, 그다음 라우트의 로케일. 상태가 유효하지 않으면 결과를 상태에 저장하며, 클라이언트에서는 쿠키도 씁니다. |
| `isValidLocale(locale)` | `(locale) => locale is string` | `locale`이 `validLocales`에 있는지 여부. |

쿠키는 `path: '/'`와 `sameSite: 'lax'`로 1년간 유지됩니다.

## 예제 {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

모듈의 로더 플러그인은 시작할 때 상태를 읽으므로, 상태를 설정하는 플러그인은 먼저 실행되어야 합니다(`enforce: 'pre'`). 상태가 URL, 쿠키, `Accept-Language`와 어떻게 우선순위를 다투는지는 [로케일 감지](/ko/guide/locale-detection)를 참고하세요. 전체 안내: [사용자 정의 감지](/ko/guide/custom-auto-detect).

`setLocale()`은 화면의 번역을 전환하지 않습니다. 현재 페이지의 로케일을 변경하려면 [`$switchLocale()`](/ko/api/methods#$switchlocale)을 호출하세요.
