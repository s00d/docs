---

번역은 일반 JSON 파일입니다: 공유 키를 위한 로케일별 루트 파일 하나와, 해당 페이지의 키를 위한 페이지 및 로케일별 파일 하나. 페이지를 추가하거나, 페이지 간에 키를 공유하거나, 폴백을 설정할 때 이 문서를 읽으세요. 키를 어떤 파일에 넣어야 하는지, 페이지가 무엇을 볼 수 있는지, 각 파일이 언제 로드되는지 알 수 있습니다.

## 구조 {#layout}

```text
locales/
├── en.json                 # root: menus, footer, buttons
├── de.json
└── pages/
    ├── index/              # pages/index.vue
    │   ├── en.json
    │   └── de.json
    ├── about/              # pages/about.vue
    │   ├── en.json
    │   └── de.json
    └── products-id/        # pages/products/[id].vue
        ├── en.json
        └── de.json
```

- `locales/pages/` 아래의 폴더는 페이지의 Nuxt **라우트 이름**입니다: `pages/products/[id].vue`는 `products-id`, `pages/blog/[slug]/comments.vue`는 `blog-slug-comments`입니다.
- 키는 어떤 깊이로든 중첩할 수 있습니다. `$t('auth.form.login')`은 `{ "auth": { "form": { "login": … } } }`를 읽습니다.
- `translationDir`은 폴더 위치를 바꿉니다(기본값 `'locales'`, 프로젝트 루트 기준이며 Nuxt 4의 `app/` 구조에서도 마찬가지).
- [`disableWatcher`](/ko/api/module-options#disablewatcher)가 설정되지 않은 한, Nuxt가 페이지를 해석할 때 없는 파일은 `{}`로 생성됩니다.

## 페이지가 보는 것 {#what-a-page-sees}

![Lookup order for a key on /about in de: pages/about/de.json, de.json, pages/about/en.json, en.json. They merge into one about/de/data.json that $t reads](/images/diagrams/page-dictionary.svg)

페이지의 사전은 루트 파일과 페이지 파일을 깊게(모든 수준에서) 병합한 것입니다. 충돌하면 페이지 파일이 우선합니다:

```json
// locales/en.json
{ "title": "My shop", "nav": { "home": "Home", "cart": "Cart" } }
```

```json
// locales/pages/about/en.json
{ "title": "About us", "nav": { "cart": "Basket" } }
```

```ts
// on /about
t('title') // 'About us'
t('nav.home') // 'Home'   (root)
t('nav.cart') // 'Basket' (page wins)
// on any other page
t('title') // 'My shop'
```

자체 폴더가 없는 페이지는 루트 사전만 받습니다. 다른 페이지의 키는 보이지 않습니다.

### 폴백 로케일 {#fallback-locales}

활성 로케일에 없는 키는 키 자체를 표시하기 전에 폴백 로케일에서 가져옵니다:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'de-at', iso: 'de-AT', fallbackLocale: 'de' },
    ],
    defaultLocale: 'en',
    fallbackLocale: 'en', // global, for every locale
  },
})
```

- 로케일 자체의 `fallbackLocale`은 끝까지 따라갑니다: `de-at` → `de` → `en`.
- 전역 `fallbackLocale`은 모든 체인 아래에 있는 가장 약한 계층입니다.
- 체인의 각 로케일은 가장 약한 폴백부터 활성 로케일까지 차례로 루트 파일, 그다음 페이지 파일을 추가합니다. 따라서 활성 로케일의 루트 파일이 폴백 로케일의 페이지 파일보다 우선합니다.

폴백이 없으면 없는 키는 키(`'nav.home'`)로 렌더링되고, 개발 환경에서는 브라우저 콘솔에 경고를 기록합니다([`missingWarn`](/ko/api/module-options#missingwarn)).

## 공유 및 기타 소스 {#sharing-and-other-sources}

| 필요 | 옵션 |
| --- | --- |
| 루트 파일만, `pages/` 폴더 없음 | [`disablePageLocales: true`](/ko/api/module-options#disablepagelocales) |
| 두 페이지가 하나의 페이지 폴더를 읽음 | [`routesLocaleLinks`](/ko/api/module-options#routeslocalelinks): `{ 'about-us': 'about' }` |
| 다른 폴더의 공유 루트 파일 | [`additionalTranslationDirs`](/ko/api/module-options#additionaltranslationdirs): `['common']` (주 `translationDir`이 우선) |
| Nuxt 레이어의 키 | 레이어의 파일이 병합되며, 프로젝트 자체 파일이 우선합니다. [레이어](/ko/guide/layers) 참고 |
| 런타임에 추가되는 키 | [`i18n:register`](/ko/api/events) 훅, `$mergeTranslations`, `$setTranslation` |
| 페이지 컴포넌트 안의 인라인 키 | `$defineI18nRoute({ locales: { en: { … } } })`, [페이지 설정](/ko/guide/per-component-translations) 참고 |

## 페이지가 사전을 로드하는 방식 {#how-a-page-loads-its-dictionary}

![Locale JSON files are built into a payload tree, stored in public/ on Node or in server assets on Edge, read by a server loader, then used by $t on the server and fetched for $t in the browser](/images/diagrams/translation-pipeline.svg)

모듈은 페이지와 로케일마다 페이로드 하나를 만듭니다: `/{apiBaseUrl}/{page}/{locale}/data.json`(기본값은 `/_locales/about/de/data.json`).

1. **서버 렌더링.** Nitro가 로케일을 감지하고, 페이지는 HTTP 요청 없이 서버 로더에서 직접 페이로드를 로드합니다. 사전은 HTML 페이로드에 기록되지 않으므로 페이지가 작게 유지됩니다.
2. **하이드레이션.** 브라우저가 같은 페이로드를 가져옵니다. 서버가 이미 이에 대한 `<link rel="preload">`를 출력했으므로, 가져오기는 HTML과 함께 시작됩니다.
3. **내비게이션.** 다음 페이지의 페이로드가 사전을 교체합니다. 떠나는 페이지의 키는 페이지가 사라질 때까지(페이지 전환 종료 또는 `page:finish`) 계속 해석되므로, 페이드아웃되는 페이지에 원시 키가 깜박이지 않습니다. 로드에 실패한 청크(네트워크 오류, 4xx 또는 5xx, 객체가 아닌 본문)는 현재 사전을 그대로 두며, 다음 내비게이션에서 다시 로드합니다. 로케일 전환이 실패한 경우도 같습니다: `$switchLocale`이 `false`로 resolve되고, 다시 호출하거나 전환기를 다시 클릭하면 재시도합니다. 접두사 전략에서는 그 시점에 URL이 이미 바뀌었으므로, 이전 텍스트가 화면에 남아 있는 동안 `lang`과 `$getLocale()`은 URL의 로케일을 가리킵니다.
4. **캐시.** 로드된 페이로드는 서버와 브라우저에 캐시됩니다. 크기와 TTL 설정은 [성능](/ko/guide/performance)에 있습니다.

`translationPayloads.mode`는 페이로드를 만드는 방식을 결정합니다. `'premerged'`(기본값)는 빌드 시 모든 페이지 × 로케일 파일을 작성합니다. `'source'`는 소스 파일을 유지하고 요청마다 병합하며, Edge 대상의 대규모 카탈로그에서 더 작습니다. 둘 다 같은 사전을 제공합니다. 배포 대상별로 파일이 어디에 위치하는지는 [배포](/ko/guide/deployment)에 있습니다.

## 개발 중 편집 {#editing-in-development}

`nuxt dev`는 파일을 실시간으로 읽습니다. 번역 파일을 저장하면 열려 있는 페이지의 사전이 그 자리에서 갱신됩니다: 새로고침 없이, 제거된 키는 사라지고, 루트 파일 변경은 모든 페이지에 반영됩니다. 손상된 JSON 파일은 경로와 함께 경고를 기록하고 빈 파일로 처리됩니다. 대신 수동으로 갱신하려면 [`hmr: false`](/ko/api/module-options#hmr)로 설정하세요.
