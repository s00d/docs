---

`meta: true`(기본값)이면 현지화된 모든 페이지에 `<html lang dir>`, canonical 링크, `hreflang` 대체 링크, `x-default`, Open Graph 로케일 태그가 추가됩니다. 공개 origin을 설정하거나, 태그에 나타날 로케일을 조정하거나, 한 페이지의 태그를 재정의하려는 경우 이 페이지가 필요합니다. 대부분의 사이트에는 `site.url` 또는 `metaBaseUrl`과 올바른 `iso` 코드만 있으면 됩니다.

## 최소 설정 {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

그러면 `/de/about`은 다음과 같이 렌더링됩니다:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## 텍스트 방향 {#text-direction}

`<html dir>`은 로케일의 `dir`에서 가져옵니다. `dir`이 없으면 오른쪽에서 왼쪽으로 쓰는 언어는 `iso`(또는 `code`)에서 읽어 `rtl`을 받습니다: 아랍어, 히브리어, 페르시아어, 우르두어 및 몇몇 다른 언어, 그리고 `az-Arab`처럼 RTL 문자를 사용하는 모든 태그가 해당됩니다. 그 밖의 로케일은 `dir` 속성을 받지 않으며, 브라우저는 이를 `ltr`로 읽습니다.

<Warning>

**`dir: 'auto'`는 큰 페이지에서 파싱 시간을 소모합니다** — `<html>`의 `auto`는 브라우저가 파싱하는 동안 콘텐츠로부터 방향을 판단하게 합니다. Chromium에서 이 비용은 페이지 크기보다 빠르게 증가합니다: 요소 5,000개에서 약 100 ms, 20,000개에서 1초. 언어를 알 수 없는 작은 페이지에만 사용하세요.

</Warning>

## 생성되는 태그 {#which-tags-you-get}

- **hreflang**: 페이지를 제공하는 로케일마다 태그 하나, 값은 `iso`(`iso`가 없으면 `code`), URL은 canonical과 같은 쿼리를 사용합니다. [페이지 설정](/ko/guide/per-component-translations) 또는 `routeLocales`로 제한된 페이지는 해당 로케일만 나열합니다. [`hreflangBaseLanguage: true`](/ko/api/module-options#hreflangbaselanguage)는 첫 번째 지역 로케일에 대해 언어만 있는 태그(`es-ES` → `es`)도 추가합니다.
- **x-default**: 기본 로케일의 URL이며, 기본 로케일이 페이지를 제공하는 경우에만 추가됩니다.
- **og:locale**: `iso`에서 파생됩니다(`en-US` → `en_US`). 매핑이 직접적이지 않으면 로케일에 `og`를 설정하세요. 예: `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`. 둘 다 없으면 `og:locale`이 작성되지 않고 개발 모드에서 경고합니다.
- **canonical / og:url**: [`canonicalQueryWhitelist`](/ko/api/module-options#canonicalquerywhitelist)(기본값 `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`)에 있는 것을 제외한 쿼리 매개변수가 없는 현재 URL.

전략별:

| 전략 | hreflang 및 x-default | canonical, og:url, og:locale, html 속성 |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | 예 | 예 |
| `no_prefix` | 아니요 (하나의 URL이 모든 로케일을 제공) | 예 |

## 공개 origin 설정 {#set-the-public-origin}

절대 URL은 다음 중 첫 번째 값을 사용합니다:

1. [`metaBaseUrl`](/ko/api/module-options#metabaseurl);
2. `nuxt-site-config`(`@nuxtjs/seo`가 설치)의 `site.url`;
3. `app.baseURL`이 덧붙여진 요청 origin.

처음 두 가지 중 하나를 고정하세요.

<Warning>

[`metaTrustForwardedHost`](/ko/api/module-options#metatrustforwardedhost)와 `metaTrustForwardedProto`의 기본값이 `true`이므로, 요청 origin 폴백은 `X-Forwarded-Host`와 `X-Forwarded-Proto`를 읽습니다. 이는 해당 헤더를 덮어쓰는 프록시 뒤에서만 안전합니다. 그렇지 않으면 클라이언트가 canonical 링크의 호스트를 선택할 수 있고, 캐시가 그 페이지를 다른 사용자에게 전달할 수 있습니다.

앱에 직접 접근할 수 있다면 `metaBaseUrl`을 고정하세요: 두 옵션을 모두 `false`로 설정하는 것과 달리 위조된 `Host`도 무시합니다. [프록시 또는 CDN 뒤에서](/ko/guide/deployment#behind-a-proxy-or-cdn)를 참고하세요.

</Warning>

폴백은 하나의 배포가 여러 도메인에 응답할 때 유용합니다: `https://site-a.com/en/about`과 `https://site-b.com/en/about`이 각각 자체 origin을 받습니다.

로케일에 `baseUrl`이 있으면 알려진 호스트는 `metaBaseUrl`과 `site.url`보다 우선하여 자체 `baseUrl`을 사용하므로, canonical과 `og:url`은 해당 도메인에 머물고 `hreflang`은 각 로케일을 해당 도메인으로 가리킵니다. 그 밖의 호스트는 `metaBaseUrl`, 없으면 기본 로케일의 `baseUrl`, 없으면 `site.url`을 사용하므로, 위조된 `Host`가 태그에 영향을 줄 수 없습니다. 이 중 아무것도 설정되지 않으면 요청 origin 폴백이 유지되고 빌드가 경고합니다. [레이어와 도메인](/ko/guide/layers#multiple-domains)을 참고하세요.

## 로케일 또는 페이지 제외 {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

기본 로케일에 `seo: false`가 있으면 `x-default`가 작성되지 않습니다. 한 페이지의 태그를 끄려면 [페이지 설정](/ko/guide/per-component-translations#turn-off-seo-tags)의 `disableMeta`, 또는 설정의 [`routeDisableMeta`](/ko/api/module-options#routedisablemeta)를 사용하세요.

## 한 페이지의 태그 재정의 {#override-tags-on-one-page}

일부 번역만 존재하거나 URL이 API에서 오는 CMS 콘텐츠의 경우, 생성된 태그를 [`useI18nHead`](/ko/composables/useI18nHead)로 교체하세요:

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace`는 `canonical`, `xDefault`, `ogLocale`, `ogUrl`을 설정하거나 제거할 수도 있습니다. `disable`은 그룹 전체(`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`)를 제거합니다. 로케일 전환 후 값이 다시 계산되도록 getter를 전달하세요. 로케일별 슬러그의 경우 먼저 `$setI18nRouteParams`를 설정하면([현지화된 경로](/ko/guide/custom-locale-routes#per-locale-slugs)) 생성된 대체 링크가 이를 이미 사용합니다.

## 후행 슬래시 {#trailing-slash}

`$localePath`, `$switchLocalePath`, `$switchLocaleRoute`의 라우트 객체, `<i18n-link>`, `<i18n-switcher>`, 로케일 리디렉션, SEO URL은 하나의 슬래시 규칙을 따릅니다: 기본적으로 `experimental.defaults.nuxtLink.trailingSlash`를 따르며, i18n 경로가 달라야 할 때는 i18n 설정의 [`trailingSlash`](/ko/api/module-options)를 따릅니다.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/)(sitemap, robots, schema.org)는 `nuxt-site-config` 4+를 통해 이 모듈과 함께 동작합니다. 사이트 설정이 로케일을 읽을 수 있도록 `nuxt-i18n-micro`를 먼저 나열하고, `site.url`을 한 번 설정하세요 — 이 값은 위의 태그에도 사용됩니다.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

번역된 사이트 이름과 설명은 로케일 파일의 `nuxtSiteConfig.name` / `nuxtSiteConfig.description` 키에서 가져옵니다. `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` 오류는 `@nuxtjs/seo`가 3보다 오래된 버전이라는 뜻입니다. 업그레이드하세요([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
