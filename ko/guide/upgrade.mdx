이 페이지는 nuxt-i18n-micro와 `@i18n-micro/*` 패키지를 업그레이드할 때 앱에서 무엇이 바뀌는지 정리합니다. 의존성 버전을 올리기 전에 현재 사용 중인 버전에 해당하는 섹션을 읽으세요. 대부분의 앱은 코드를 거의 변경할 필요가 없습니다.

<Tip>

**`@nuxtjs/i18n`에서 오셨나요?** — [@nuxtjs/i18n에서 마이그레이션](/ko/guide/migration)을 참조하세요.

</Tip>

## 3.30.3 이후: 메이저 릴리스 {#after-3-30-3-the-major-release}

모듈 옵션, `$t`, `$localePath`, `$switchLocale` 및 기타 헬퍼, 컴포넌트, 컴포저블, 문서화된 서버 유틸리티는 이름이 그대로 유지됩니다. 바뀐 것은 동작이며, 대부분 버그 수정입니다. 어댑터 패키지와 라우팅 패키지에는 실제 API 변경이 있습니다: [프레임워크 패키지](#framework-packages)와 [기타 패키지](#other-packages)를 참조하세요.

### 먼저 할 일 {#do-this-first}

1. **버전을 확인하세요.** 모듈에는 Nuxt 3.18 이상과 Node 20 이상이 필요합니다. Nuxt에는 자체 Node 최소 버전이 있습니다: Nuxt 4.5는 `^22.19.0 || ^24.11.0 || >=26.0.0`을 선언합니다. Nuxt 3.18.0 자체에서의 `nuxt generate`는 순수 Nuxt에서도 실패합니다(`[unstorage] Invalid key: "/"`). 3.21.11은 작동합니다. `@i18n-micro/react`에는 React 18 이상이 필요합니다.
2. **설치된 패키지를 정리하세요.**
   - `@i18n-micro/hmr`을 제거하세요. 번역 HMR은 모듈에 내장되어 있습니다.
   - 테스트에서 `@i18n-micro/test-utils`를 가져온다면 추가하세요: `npm install -D @i18n-micro/test-utils`. 더 이상 모듈과 함께 설치되지 않습니다.
   - `nuxt-i18n-micro-cli`를 `@i18n-micro/cli`로 교체하세요. 28개 명령이 16개가 되었고, `check`가 그중 세 개를 대체하며, 종료 코드가 변경됩니다: [CLI 가이드](/ko/guide/cli#moving-from-nuxt-i18n-micro-cli)를 참조하세요.
3. 아래 표의 항목을 **코드에서 검색하세요**.
4. **앱 앞단에 무엇이 있는지 확인하세요.** 프록시 뒤에서 로케일에 `baseUrl`을 사용한다면 [프록시 또는 CDN 뒤에서](/ko/guide/deployment#behind-a-proxy-or-cdn)를 참조하세요. CDN을 사용한다면 캐시 키를 `Vary` 헤더와 대조하세요: [HTML 캐싱](/ko/guide/deployment#caching-html)을 참조하세요. `apiBaseClientHost`나 엄격한 CSP를 사용한다면 새로운 `preload` 링크를 허용하세요: [SEO와 head 태그](#seo-and-head-tags)를 참조하세요.
5. **스냅숏을 업데이트하세요.** head 스냅숏에 `preload` 링크가 추가되고, 스위처 마크업이 변경되었으며([`<i18n-switcher>`와 `<i18n-link>`](#&lt;i18n-switcher>-and-&lt;i18n-link>)), `$localeRoute` 출력의 쿼리 문자열이 다르게 인코딩됩니다.
6. **각 로케일로 페이지를 열어 원시 키가 보이는지 확인하세요.** 이전 페이지 파일의 키를 사용하던 레이아웃은 이제 키를 그대로 표시합니다: 해당 키를 루트 파일로 옮기세요.

<Warning>

**`@i18n-micro/path-strategy`의 `switchLocaleRoute`에서 첫 번째 인수가 제거되었습니다** — `switchLocaleRoute(fromLocale, toLocale, route, options)`는 이제 `switchLocaleRoute(toLocale, route, options)`입니다. **기존 JavaScript 호출은 실패하지 않고 잘못된 결과를 반환합니다.** `fromLocale`이 대상으로, `toLocale`이 라우트로 읽히기 때문입니다. TypeScript만이 알려 줍니다. Nuxt의 `$switchLocaleRoute`는 영향을 받지 않습니다.

</Warning>

`detectCurrentLocale`은 사용 중단되었습니다. 여전히 작동하며 서버 자동 가져오기로 남아 있습니다. 같은 규칙을 적용하는 [`useLocaleServerMiddleware(event).current`](/ko/guide/server-side-translations)를 사용하세요.

이 문서의 17개 페이지가 이동했습니다. 기존 URL은 리디렉션되므로 해당 페이지로의 링크는 계속 작동합니다.

### URL과 리디렉션 {#urls-and-redirects}

- **`prefix_except_default`에서 `/en`과 `/en/...`은 404입니다**(`en`이 기본값인 경우). 문서에 설명된 대로입니다.
- **대소문자나 철자가 다른 로케일 접두사는 404입니다.** `/DE/about`은 이전에 독일어 라우트를 기본 로케일로 렌더링하거나 `/en/DE/about`으로 리디렉션했습니다. 해당 URL에 자체 페이지가 있으면 페이지로 유지됩니다. catch-all이나 `[slug]` 페이지는 해당하지 않습니다: `[...slug]` 아래의 `/DE/x`와 `[slug]` 옆의 `/DE`도 404이므로, 다른 대소문자의 로케일 코드와 같은 CMS 슬러그는 페이지를 잃습니다. `ssr: false`에서는 응답하는 서버가 없으므로 `/DE/about`은 독일어 페이지를 표시합니다.
- **대소문자가 다른 페이지 경로는 원래 철자로 리디렉션됩니다.** `/T/BASIC`은 200이었으나 이제 `/t/basic`으로의 `302`입니다.
- **알 수 없는 URL은 404로 유지됩니다.** `autoDetectPath: '*'` 또는 `'no_prefix'`에서 `/nope`은 더 이상 먼저 `/de/nope`으로 리디렉션되지 않습니다. `prefix`는 리디렉션을 유지하며(여기서는 접두사 없이 제공되는 것이 없음), 모든 곳에서 `/`도 마찬가지입니다.
- **접두사 없는 다른 로케일의 사용자 지정 경로는 `prefix_except_default`에서 해당 페이지를 찾습니다.** `/a-propos`는 404였으나 이제 기본 로케일의 URL(`/about`)로의 `302`입니다. `prefix`에서는 같은 리디렉션이 이제 실제 페이지(`/en/about`, 이전에는 404인 `/en/a-propos`)에 도달합니다. `prefix_and_default`는 404로 유지됩니다.
- **`redirects: false`를 사용하는 `prefix`는 접두사 없는 URL에 404로 응답합니다**(`/about`은 `302`였음). 기본 사용자 지정 경로가 있는 페이지의 원래 URL도 포함됩니다. `$localePath('/about')`는 여전히 해당 페이지를 찾습니다.
- **`prefix_except_default`에서 기본 사용자 지정 경로가 있는 페이지의 원래 URL은 해당 경로로 리디렉션됩니다.** 동적 페이지도 포함됩니다. `/dir/one`은 404였으나 이제 `/dir-one/one`으로의 `302`입니다.
- **`autoDetectPath: '*'`는 이제 접두사 없는 경로에도 쿠키와 `Accept-Language`를 적용합니다**(`/about` → `/de/about`).
- **`prefix`에서 접두사 없는 URL은 방문자의 로케일을 유지합니다.** 쿠키가 `de`이면 `/about`과 일반 `<NuxtLink to="/about">`는 `autoDetectPath` 설정과 관계없이 모든 경로에서 `/de/about`으로 이동합니다.
- **`prefix_and_default`에서 접두사 없는 URL은 기본 로케일입니다.** `Accept-Language: de`인 `/contact`는 이전에 독일어로 렌더링된 다음 영어로 하이드레이션되었습니다. 이제 기본 로케일로 렌더링되며, 방문자는 `/de/...`를 통해 독일어에 접근합니다.
- **`no_prefix`에서 사용자 지정 경로는 자체 로케일로 렌더링되며**(`/ueber-uns`는 어떤 선호에서도 독일어), 제한된 페이지는 제공하는 로케일 중 하나로 렌더링됩니다. 여러 로케일이 공유하는 경로는 선호가 그중 하나일 때 선호 로케일로 렌더링되며, `baseUrl`에서는 각 도메인의 페이지가 됩니다. 이러한 로케일은 하나의 레코드 `localized-<page>-<first locale>`을 공유합니다.
- **`noPrefixRedirect`는 방문자의 로케일을 따릅니다.** 쿠키가 `de`이면 `/about`은 기본 로케일의 `/about-us`가 아닌 `/ueber-uns`로 이동하며 독일어로 렌더링됩니다. 자체 사용자 지정 경로가 없는 로케일은 `/about`에 머무릅니다.
- **페이지가 없는 `routeRules` 리디렉션은 현지화되지 않습니다.** `/de/old`는 빈 200이었으나 이제 404입니다: 필요하다면 접두사가 있는 경로에 대한 규칙을 추가하세요. 다른 로케일에서 이러한 규칙으로의 링크는 작성된 경로를 유지하며 규칙의 대상에 도착합니다.
- **라우트 규칙이 사용자 지정 경로에 적용됩니다.** `blog/[slug]`에 해당 경로가 있으면 `/blog/**`는 `/de/artikel/:slug`에도 적용되며, 규칙은 `no_prefix`에서도 복사됩니다. `/de/artikel/news` 같은 정적 형제 경로도 해당 패턴과 일치합니다. 이미 로케일 접두사 아래에 작성된 규칙은 작성된 그대로 유지됩니다.
- **`disabled: true`인 로케일은 접두사에서 즉시 404로 응답하며**, 해당 로케일로의 링크는 페이지에 머무릅니다. 런타임에 비활성화된 로케일도 마찬가지입니다: 이전에는 폴백 로케일로 렌더링되었습니다.
- **모듈의 404는 `Page Not Found`를 표시합니다.** 비활성화된 로케일의 접두사와 호스트 자체의 접두사에서, Nuxt는 `Page not found: /de/about`라고 표시했습니다. 상태 코드는 같습니다.
- **`customRegexMatcher`는 더 이상 첫 세그먼트가 로케일처럼 보이는 실제 페이지를 404로 만들지 않습니다.**
- **현지화된 라우트 이름이 일관됩니다.** 공유 로케일 레코드 아래의 자식은 페이지의 이름을 유지하고, `no_prefix`는 `localizedRouteNamePrefix`를 따르며, index 자식이 있는 부모는 이름 없이 유지됩니다.
- **모듈이 `name` 없이 추가한 페이지**(`extendPages`)는 현지화되고 이름을 받으며, 로케일 변형과 `hreflang`이 생깁니다. 이전에는 현지화되지 않은 상태로 남았습니다.
- **`nuxt.config` 항목이 `$defineI18nRoute`보다 우선합니다.** 키 형식(`about/team`, `/about/team`, `about-team`)과 관계없이 그렇습니다. 이전에는 어느 쪽이 우선할지가 철자에 따라 달랐습니다.
- **새로운 빌드 경고:** 자체 로케일 코드로 시작하는 `localeRoutes` 값(`fr: '/fr/article'`), 그리고 부모 밖에 있는 자식의 사용자 지정 경로.
- **해시 모드가 `prefix`에서 작동합니다.** 문서는 `/`이며, `/en`이나 `/about`은 해시로 리디렉션됩니다.
- **`/#/de/x`는 `prefix_except_default`와 `prefix_and_default`에서 독일어로 렌더링됩니다.** 이전에는 하이드레이션 불일치와 함께 영어로 렌더링되었습니다.

### 링크와 라우트 객체 {#links-and-route-objects}

- **페이지를 제공하지 않는 로케일은 해당 로케일의 홈으로 링크됩니다.** `$localeRoute`, `$switchLocalePath`, 스위처는 더 이상 다른 로케일의 페이지를 반환하지 않습니다.
- **알 수 없는 로케일 코드는 기본 로케일로 이동합니다.** `$localePath(path, 'xx')`와 `$localeRoute`는 이전에 `/xx`를 반환했습니다.
- **`$localePath`는 `http(s):`, `mailto:`, `tel:` 스킴이 있는 문자열을 그대로 반환하며, `$localeRoute`의 `path`와 `fullPath`도 이를 변경 없이 포함합니다.** 따라서 검증되지 않은 값(`?next=` 매개변수)을 링크 대상으로 전달하지 마세요. `//host`와 `x.com` 같은 단순 이름은 모든 로케일에서 이 오리진의 경로로 유지되며, 이로부터 만들어진 링크는 오리진을 벗어나지 않습니다: 기본 로케일로의 `/de//x.com`은 `/x.com`입니다. 백슬래시는 슬래시로 간주됩니다.
- **`$localePath`는 경로를 인코딩합니다:** `/a b`는 `/a%20b`가 됩니다.
- **`$localeRoute`와 `$switchLocaleRoute`는 일반 객체를 반환하며,** `ref`, `reactive`, `useState`, JSON, 스프레드에서 안전합니다. 매개변수에 이스케이프가 필요하면 객체는 `name`이나 `params` 없이 `{ path, fullPath, query, hash }`이며(`$localeRoute`는 `href`를 추가), URL은 새로고침 전후로 동일합니다. 일반 URL은 둘 다 가집니다. `name`은 새로 추가되었습니다: 이전 객체에는 없었습니다. `.name`이나 `.params`를 읽는 코드는 이들이 없는 경우를 처리해야 하며, 어떤 형식을 받는지는 값에 따라 달라집니다.
- **`trailingSlash`에서 `$switchLocaleRoute`는 항상 해당 경로 형식을 반환하며,** 일반 슬러그도 마찬가지이고, 서버 리디렉션은 `trailingSlash`를 따릅니다. 이 옵션에서는 결과와 `Location` 헤더가 바뀔 수 있습니다.
- **`$localeRoute` 출력의 쿼리 값은 vue-router의 인코딩을 사용합니다:** `/`는 그대로 유지되고 공백은 `+`입니다(`?redirect=/v2`, 이전에는 `%2Fv2`). 디코딩된 값은 같지만 이러한 `href`의 스냅숏은 바뀝니다.
- **경로가 없는 링크는 현재 페이지에 머무릅니다.** `$localePath('#top')`, `'?p=2'`, `''`, `{ query }`는 현재 페이지를 유지합니다. `'#top'`은 이전에 사이트 루트를 기준으로 읽혔습니다. 단순 `'about'`은 여전히 `/about`을 의미합니다.
- **스프레드.** `{ ...route, query }`와 `{ ...route, hash }`는 `$switchRoute`를 통해서도 변경을 유지합니다. 새 `path`는 `$localeRoute`, `$localePath`, `$switchRoute`에서 우선합니다. `{ ...route, params }`는 이름이 있는 라우트에서 작동합니다. 경로 형식의 라우트에서는 경로가 우선하고 params는 vue-router의 개발 경고와 함께 무시됩니다. `$localeRoute({ name, params })`를 사용하세요.
- **`$switchRoute`는 앱 안에 머무릅니다.** 로케일 자체의 `baseUrl`, `mailto:`, `tel:`은 앱을 벗어나며, 그 외 문자열은 경로입니다.
- **`excludePatterns`**는 전체 세그먼트와 일치하며(`'/admin'`은 더 이상 `/administrator`와 일치하지 않음), glob은 고정됩니다(`/docs/*`는 더 이상 `/en/docs/x`와 일치하지 않음). `RegExp` 패턴이 이제 런타임에 도달합니다. 이전에는 런타임에서 손실되었습니다. 일치하는 페이지는 현지화되지 않습니다: `hreflang`이 없으며, `prefix_except_default`에서는 기본 로케일입니다. [경로 제외](/ko/guide/excluding-static-files)와 패턴을 대조해 확인하세요.

Nuxt 4.5.2에서는 매개변수의 `%`나 `?`가 어떤 앱에서든 서버 렌더링 새로고침 후 유지되지 않습니다: 이는 모듈이 아니라 업스트림 문제입니다.

### 로케일 도메인 {#locale-domains}

- **`locales[].baseUrl`이 이제 요청을 라우팅합니다.** 하나의 빌드가 모든 도메인을 제공합니다: [레이어와 도메인](/ko/guide/layers#multiple-domains)을 참조하세요. `baseUrl`이 설정되면 다른 도메인의 로케일은 이 호스트에서 404이며(`example.de`의 `/en/about`), 같은 호스트의 로케일로의 링크는 상대 경로입니다. `localhost`를 포함한 다른 호스트의 요청은 이전과 같이 동작하지만, canonical과 `hreflang`은 요청의 오리진이 아니라 설정된 경우 `metaBaseUrl`을, 그렇지 않으면 기본 로케일의 `baseUrl`을 사용합니다.
- **`Host`를 다시 쓰는 프록시 뒤에서는** [`trustForwardedHost`](/ko/api/module-options#trustforwardedhost)를 설정할 때까지 모든 요청이 빌드 설정으로 처리됩니다. `metaTrustForwardedHost`와 달리 기본값은 `false`입니다. [프록시 또는 CDN 뒤에서](/ko/guide/deployment#behind-a-proxy-or-cdn)를 참조하세요.
- **`baseUrl`을 사용하는 `nuxi generate`에는 도메인마다 한 번씩 `NUXT_I18N_DOMAIN`이 필요합니다.** 없으면 빌드가 경고하며, 해당 로케일은 페이지 없는 링크가 됩니다. [정적 사이트](/ko/guide/deployment#static-site-(nuxi-generate))를 참조하세요.
- **`baseUrl`이 있는 로케일로의 링크는 `$localePath`나 `<i18n-link>`를 거칩니다.** `<NuxtLink :to="$localePath(x, 'fr')">`와 `<i18n-link :to="$localeRoute(x, 'fr')">`는 해당 절대 URL이며, 클릭하면 그곳으로 이동합니다. 라우터는 절대 객체를 받지 않습니다: `<NuxtLink :to="$localeRoute(x, 'fr')">`와 `router.push($localeRoute(x, 'fr'))`는 이 앱의 경로인 `/https://fr.example.com/...`로 남습니다. `localhost`나 프리뷰 호스트에서는 `baseUrl`이 있는 모든 로케일이 이러한 링크이며, 현재 로케일도 마찬가지입니다. 코드에서는 `navigateTo($localePath(x, 'fr'), { external: true })`를 사용하세요.
- **도메인의 홈은 모든 곳에서 후행 슬래시 없이 작성됩니다**(`https://example.de`). 링크, canonical, `hreflang` 모두 해당됩니다.
- **`prefix`에서 다른 도메인으로의 링크는 `baseDefault` 여부와 관계없이 로케일 접두사를 유지합니다.** 리디렉션만 하는 `https://example.de/about`이 아니라 `https://example.de/de/about`입니다.
- **`prefix_except_default`에서 빌드 기본값이 아닌 로케일에 `baseDefault`가 있으면, 다른 도메인이 링크할 수 있도록 라우트가 모든 접두사를 유지합니다.** `/en`은 여전히 404입니다. `router.getRoutes()`를 읽는 코드만 차이를 봅니다.
- **`prefix_except_default`에서 호스트 자체의 접두사는 해당 `baseDefault` 호스트에서 404입니다.** `de` 호스트의 `/de/x`는 200이었습니다.
- **`$getI18nConfig().locales`는 호스트가 제공하는 것만 담습니다.** `linkLocales`는 전부를 담으며, `$getLocales()`는 완전하게 유지됩니다.

### 내비게이션과 `$switchLocale` {#navigation-and-$switchlocale}

- **내비게이션은 커밋될 때 적용됩니다.** 사전, 로케일, 매개변수, head는 `router.afterEach`에서 변경되므로 취소되거나 차단된 내비게이션은 아무것도 바꾸지 않으며, 다음 청크가 로드되는 동안 이전 페이지의 링크가 유효하게 유지됩니다. `beforeResolve`, `beforeRouteEnter` 또는 이후의 전역 가드는 이제 이전 사전과 로케일을 봅니다. 라우트 미들웨어는 영향을 받지 않습니다.
- **청크 로드에 실패하면 현재 사전이 유지됩니다.** 루트 파일에서 5xx, 네트워크 오류, 잘못된 본문이 발생하면 이전에는 원시 키가 표시되었습니다. 이제 새 페이지는 이전 문자열로 렌더링되며, 다음 내비게이션에서 다시 시도합니다. 404, 또는 파일 위치에 정적 호스트의 SPA 셸이 있으면 다음 새로고침까지 루트 사전이 사용됩니다.
- **`$switchLocale`은 `true` 또는 `false`로 resolve되며**(이전에는 아무것도 반환하지 않음), 로케일의 사전이 적용되지 않으면 `false`입니다. 타입은 `Promise<boolean>`이며, `$switchRoute`는 `Promise<void>`입니다.
- **`$switchLocale`은 명시적인 선택입니다.** 도착 시 로케일을 저장하며, 404에서도 저장합니다. 내비게이션이 차단되거나 취소되거나 예외를 던지면 저장된 선호와 상태는 그대로 유지되며, 예외는 다시 던져집니다. 다른 호스트로 이동할 때는 먼저 저장합니다. `no_prefix`와 해시 모드에서는 내비게이션 결과와 관계없이 전환이 유지됩니다. 모든 로케일에 하나의 URL을 사용하는 페이지(`excludePatterns`)에서는 선택이 취소되지 않으며, 다음 페이지의 URL이 결정합니다: `prefix_except_default`에서 접두사 없는 링크는 기본 로케일로 돌아갑니다.
- **`no_prefix`에서 두 페이지가 사용자 지정 경로를 공유하면 `$switchLocale`은 현재 페이지를 유지하며,** 이스케이프된 매개변수에서도 마찬가지입니다. 이러한 URL의 새로고침과 이스케이프된 매개변수를 사용한 `$localeRoute`는 첫 번째 레코드에 도착합니다.
- **클라이언트 리디렉션은 내비게이션의 모드를 유지합니다.** `prefix`에서 일반 `<NuxtLink to="/about">`는 현재 항목을 덮어쓰지 않고 히스토리 항목을 추가합니다. `router.replace`는 여전히 교체합니다.
- **서버에서 설정한 `$setI18nRouteParams`와 `useI18nHead`는 하이드레이션 후에도 유지됩니다.** `/news/2`에 도착한 후 페이지가 SSR 중에 매개변수를 설정하면, 스위처는 위치와 관계없이 서버 HTML에서도 `/de/news/2`가 아닌 번역된 슬러그(`/de/news/2-zwei`)로 링크됩니다. 다른 경로로의 내비게이션이 커밋되면 제거되며, `/news/1`에서 `/news/4`로의 이동도 포함됩니다: 새 페이지에서 다시 설정하세요.
- **setup에서 읽은 `$setI18nRouteParams`는 해당 페이지에 바인딩됩니다.** 이미 떠난 페이지에서의 늦은 호출은 아무것도 하지 않습니다. `useNuxtApp().$setI18nRouteParams`는 이제 접근자이며, 두 번 읽으면 두 개의 함수를 얻습니다. setter가 없습니다: 테스트 스텁이 할 수 있는 `useI18n().$setI18nRouteParams = fn`은 strict 모드에서 예외를 던지므로 `useI18n` 자체를 스텁하세요. 레이아웃이나 `app.vue`에서는 떠날 페이지가 없으므로 일반 함수입니다.
- **서버는 렌더링이 끝날 때 `<i18n-switcher>`의 링크를 다시 씁니다.** 매개변수가 있는 페이지에서, 레이아웃의 스위처가 페이지의 비동기 setup보다 먼저 렌더링되기 때문입니다. 직접 작성한 `$switchLocalePath` 링크는 다시 쓰이지 않습니다: [사용자 지정 로케일 라우트](/ko/guide/custom-locale-routes)를 참조하세요. Nuxt의 SSR 스트리밍에서는 첫 HTML이 URL의 매개변수를 유지합니다.
- **서버 컴포넌트의 `locale`이라는 이름의 prop이 렌더링 로케일을 설정하므로**, `<Greeting :locale="$getLocale()" />`는 URL과 전환을 따릅니다. 그 안의 `$getLocale()`, `$localePath`, `$getLocaleName`도 prop을 따릅니다. [서버 측 번역](/ko/guide/server-side-translations)을 참조하세요. prop이 없으면 여전히 쿠키나 기본값을 사용합니다.
- **`keepalive` 페이지는 돌아올 때 매개변수와 head를 되찾습니다.**
- **`prefix_except_default`에서 `false`로 설정된 중첩 페이지에는 로케일 URL이 없습니다.** `globalLocaleRoutes: { 'parent-kid': false }`에서 `/de/parent/kid`는 제공되었으나 이제 404입니다: 페이지는 `/parent/kid`에 머무릅니다.

### 로케일 감지와 쿠키 {#locale-detection-and-the-cookie}

[로케일 감지](/ko/guide/locale-detection)에 설명된 하나의 우선순위가 모든 곳에 적용됩니다.

- **`?locale=`은 `no_prefix`에서만 페이지에 적용됩니다.** 접두사 전략에서는 URL이 결정합니다. `/about?locale=de`는 더 이상 `lang="en"` 아래에서 독일어로 렌더링되지 않습니다. `?locale=de&locale=fr`은 첫 번째 값을 읽으며, 이전에는 `"de,fr"`이었습니다.
- **`Accept-Language`는 `q` 값을 따릅니다**(`fr;q=0.1, de;q=0.9` → `de`, `q=0`은 언어를 제외). 지역 일치는 더 이상 `locales`의 순서에 의존하지 않으며, 중국어 문자 체계를 절대 교차하지 않습니다.
- **페이지로의 클라이언트 내비게이션은 기본 로케일의 접두사 없는 페이지에서도 해당 로케일을 쿠키에 저장합니다.** `localeCookie`가 설정된 경우, `/about` 링크를 클릭한 방문자는 이제 `user-locale=en`을 가지며, 이후 브라우저 언어를 변경해도 더 이상 `/`가 리디렉션되지 않습니다. 해당 URL의 첫 로드는 아무것도 저장하지 않습니다. `no_prefix`와 해시 모드에서는 내비게이션이 변경 사항만 저장합니다.
- **404는 쿠키를 쓰지 않습니다:** 응답도, 그곳으로의 일반 클라이언트 내비게이션도 어떤 모드에서든 쓰지 않습니다. `no_prefix`에서 접두사가 있는 것처럼 보이는 URL도 쓰지 않습니다.
- **`no_prefix`에서 명시적인 `localeCookie: null`이 존중됩니다.** 이전에는 `user-locale`이 되었습니다. `nuxt.config`의 `i18n` 블록에 설정하세요: `modules: [[name, opts]]`나 레이어의 `null`은 여전히 손실됩니다.
- **해시 모드는 `hash-locale` 쿠키만 읽습니다.** 단독 `user-locale=de`는 더 이상 적용되지 않습니다.
- **형식이 잘못된 로케일 쿠키는 무시되고 그대로 유지되며,** 모든 SSR 페이지를 500으로 실패시키지 않습니다. 더 이상 모든 요청에서 삭제되지 않으며, 이로 인해 접두사가 있는 페이지가 로케일을 저장하지 못하던 문제도 해결되었습니다.
- **URL의 로케일이 우선합니다.** `/en/...`에서 플러그인의 `setLocale('de')`는 더 이상 `de` 사전을 로드하지 않으며, 상태의 알 수 없는 코드는 무시됩니다.
- **서버 API 헬퍼**(`useLocaleServerMiddleware`, `useTranslationServerMiddleware`)는 모든 라우트에서 하나의 순서를 사용합니다: `?locale` → `[locale]` 매개변수 또는 접두사 → 쿠키 → 헤더 → 기본값. 이제 `localeCookie: null`과 `autoDetectLanguage: false`를 존중하며, 로케일별로 사전을 캐시합니다.
- **런타임 재정의가 라우팅에 적용됩니다.** `NUXT_I18N_DEFAULT_LOCALE`과 런타임 `disabledLocales`는 이제 생성된 전략을 변경하며(비활성화된 로케일은 라우팅을 중단), 런타임 `disabledLocales`는 빌드의 값에 추가됩니다. `prefix_except_default`와 `prefix_and_default`에서는 해당 로케일의 접두사 없는 라우트가 빌드 시 생성되므로 런타임 `defaultLocale`이 경고와 함께 무시됩니다. 런타임 `fallbackLocale`은 활성화된 로케일이어야 합니다: 그렇지 않으면 경고와 함께 제거되며, 빌드의 값이 활성화되어 있으면 그 값이 적용됩니다. [런타임 재정의](/ko/guide/runtime-overrides)를 참조하세요.

### SEO와 head 태그 {#seo-and-head-tags}

- **`dir="auto"`는 더 이상 기본값이 아닙니다.** `dir`이 없는 로케일은 이전에 `dir="auto"`를 받았으며, 이는 큰 페이지의 파싱을 느리게 합니다. 이제 알려진 RTL 언어는 `dir="rtl"`을 받고, 그 외 로케일은 속성을 받지 않습니다. Nuxt, `@i18n-micro/vue`, `astro`, `vitepress`에 적용됩니다. 이전 출력을 유지하기 위해 로케일에 `dir: 'auto'`를 설정하면 20,000개 요소에서 약 1초의 파싱 비용이 듭니다: [텍스트 방향](/ko/guide/seo#text-direction)을 참조하세요.
- **모든 SSR 페이지에 새 태그가 있습니다:** `<link rel="preload" as="fetch" crossorigin="anonymous" href="/_locales/...">`, 404 페이지도 마찬가지입니다. `apiBaseClientHost`를 사용하면 `href`가 해당 호스트에 있으므로 CORS가 필요합니다. 엄격한 CSP는 이를 허용해야 합니다.
- **`hreflang`은 페이지를 제공하는 로케일만 나열합니다.** `x-default`는 기본 로케일이 페이지를 제공할 때만 출력됩니다.
- **현지화되지 않은 페이지에는 `hreflang`이나 `og:locale:alternate`가 없습니다.**
- **오리진이 요청에서 오는 경우 canonical과 `hreflang`에 `app.baseURL`이 포함됩니다.** `metaBaseUrl`과 `site.url`은 작성된 그대로 유지됩니다.
- **404 페이지는 URL의 로케일로 `<html lang dir>`을 가집니다.** canonical, `hreflang`, `og:url`, `og:locale`, 대체 링크가 없으며, 모듈 자체가 일치한 레코드(`/en/...`)에서 404로 응답할 때도 마찬가지입니다. `useI18nHead` `replace`로 전달한 태그는 유지되므로 오류 페이지에서는 건너뛰세요.
- **canonical, `og:url`, `hreflang`은 허용 목록의 쿼리를 유지합니다**(`/about?page=2`). 서버에서도 마찬가지이며, 이전에는 SSR 중에 제거되었습니다. 기본적으로 `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`가 허용 목록에 있습니다. [`canonicalQueryWhitelist`](/ko/api/module-options#canonicalquerywhitelist)를 참조하세요.
- **파싱할 수 없는 `X-Forwarded-Host`는 무시되며**, 모든 페이지에서 500이 발생하지 않습니다. 사용 가능한 호스트가 없고 `metaBaseUrl`이나 `site.url`도 없으면, 해당 응답의 canonical과 `hreflang` URL은 상대 경로입니다. 파싱할 수 없는 `Host`는 일반 Nuxt 앱에서처럼 500으로 유지됩니다.
- **`disableMeta`가 이제 작동합니다.** `$defineI18nRoute`와 `routeDisableMeta` 모두에서, `nuxt.config`에 설정한 경우에도: 페이지에 `hreflang`, canonical, `og:locale`이 없습니다. `lang`과 `dir`은 유지됩니다.
- `useLocaleHead()`는 `useHead(() => build())`를 위한 getter인 `build()`도 반환합니다.
- `metaBaseUrl`이 없는 일반 빌드에서는 이전과 같이 `X-Forwarded-Host`가 여전히 이 태그의 호스트를 선택합니다. 오리진에 직접 접근할 수 있다면 `metaBaseUrl`을 고정하세요: [프록시 또는 CDN 뒤에서](/ko/guide/deployment#behind-a-proxy-or-cdn)를 참조하세요.

### 번역 {#translations}

- **병합은 모든 수준에서 깊게 수행됩니다.** 루트, 페이지, 폴백 파일은 2단계 병합을 사용했으므로, 폴백이나 루트의 `a.b.c`가 source 모드와 개발 환경에서 손실되었습니다. 이제 모든 모드가 같은 사전을 제공합니다.
- **폴백 체인은 끝까지 따라갑니다**(`fr` → `de` → `en`). 모든 모드에서 마찬가지입니다.
- **병합은 파일 종류가 아니라 로케일을 기준으로 합니다.** 이제 활성 로케일의 루트 파일이 폴백 로케일의 페이지 파일보다 우선합니다. [폴백 로케일](/ko/guide/translations#fallback-locales)을 참조하세요.
- **같은 `code`에 대해 프로젝트의 `locales` 항목이 레이어의 항목보다 우선합니다.** 레이어는 빈 부분만 채웁니다.
- **자체 `pages/<name>/` 폴더가 없는 페이지는 루트 사전을 읽으며,** 자식 페이지도 마찬가지입니다. 이전에는 `{}`를 받아 원시 키를 표시했습니다. 출력에 이러한 페이지마다 파일 하나와 로케일마다 `__root/<locale>/data.json`이 추가됩니다: `/_locales/<any name>/en/data.json`은 루트 키와 함께 200이며, 이전에는 `{}`였습니다. 이는 모니터링, 정적 호스트의 허용 목록, 트리를 읽는 도구에 중요합니다.
- **`disablePageLocales: true`는 루트 파일만 읽습니다.** `pages/index`는 더 이상 병합되지 않습니다.
- **떠나는 페이지의 요소가 문서를 떠나면 해당 페이지의 키는 더 이상 해석되지 않습니다.** 레이아웃이 이전 페이지 파일에만 있는 키를 사용했다면 루트 파일로 옮기세요. 부모의 키는 자식이 표시되는 동안 다음 내비게이션까지 유지되며, `index` 자식이 있는 부모도 포함됩니다. 한 부모의 두 자식 사이에서는 부모 자체의 키에 자식의 사전이나 루트 사전이 필요합니다.
- **`$clearCache()`는 현재 페이지의 사전을 다시 로드하며** 새 사전이 도착할 때까지 이전 사전을 화면에 유지합니다. 다시 로드에 실패하면 이전 사전이 유지되고, 초기화 전에 요청된 응답은 폐기되며, 떠나는 전환 중인 페이지는 번역된 상태로 유지됩니다.
- **`$has(key, route)`는 라우트를 존중합니다.**
- **아직 방문하지 않은 페이지에 대한 `$loadPageTranslations`는 더 이상 해당 파일의 로드를 막지 않습니다.** 파일은 첫 방문 시 로드되며 사용자의 키가 그 위에 유지됩니다. 이전에는 새로고침할 때까지 페이지에 원시 키가 표시되었습니다.
- **번역 HMR은 페이지 새로고침 없이 편집을 그 자리에서 적용합니다.** 제거된 키는 사라지고 루트 편집은 모든 페이지에 반영됩니다.
- **손상된 로케일 파일은 모든 모드에서 경로와 함께 한 번 경고합니다.** 개발 환경에서는 예외를 던지고 premerged는 조용히 건너뛰었으므로, 개발 환경의 강한 실패에 의존하던 앱은 더 이상 그것을 보지 못합니다.

### 복수형과 서식 {#plurals-and-formatting}

- 음수, 소수 또는 매우 큰 수를 사용하는 `$tc`는 실제 수와 함께 마지막 형식을 사용합니다. `{ count: null }`은 더 이상 예외를 던지지 않으며, 누락된 복수형 키는 누락 핸들러에 도달합니다.
- `$tdr`은 실제 미래 날짜(`in 3 days`, 또는 `numeric: 'auto'`에서 `tomorrow`)를 제공하며 잘못된 입력에는 `Invalid Date`를 제공합니다. 1초 미만의 과거는 `0 seconds ago`입니다.
- **`$tn`, `$td`, `$tdr`은 복수형처럼 `iso`를 따릅니다**: `{ code: 'en', iso: 'en-GB' }`는 이제 날짜를 `31/10/2026`으로 형식화합니다. 로케일 코드에서 `_`는 `-`로 읽히므로 `en_US`는 더 이상 예외를 던지지 않으며, `Intl`이 모르는 코드는 머신의 로케일을 따르지 않고 `en`으로 형식화됩니다. 이름이 있는 형식은 여전히 `code`로 조회됩니다.
- `{param}` 자리 표시자는 전달한 매개변수만 읽습니다(`{constructor}`는 작성된 그대로 유지됨).
- `{placeholder}` 이름에는 중괄호와 공백을 제외한 모든 문자를 사용할 수 있습니다: `{firstName}`, `{first-name}`, `{user.name}`은 `params`에서 읽힙니다. 해당 매개변수가 없으면 이전과 같이 작성된 그대로 유지됩니다.
- `defaultValue`는 `$t`와 `$tc`에서 보간됩니다: `$t('missing', { n: 1 }, 'Got {n}')`은 `Got 1`을 반환하며, 이전에는 `Got {n}`을 반환했습니다. 문자열이 아닌 기본값은 그대로 반환됩니다.
- 빈 번역에 대한 `$tc`는 `$t`처럼 `''`를 반환합니다. 이전에는 기본값이나 키를 반환했습니다.
- **복수형 템플릿은 한 가지 예외를 제외하고 의미가 유지됩니다.** 표에 모든 형태가 나열되어 있습니다. `Intl.PluralRules` 카테고리를 사용하려면 새로운 [`=0 ` 마커](/ko/api/methods#$tc)로 명시하세요: `=0 no apples | one apple | {count} apples`.

  | 형태 | 예시 (`uk`) | 이전 | 현재 |
  | --- | --- | --- | --- |
  | 정수 카테고리가 하나 또는 두 개인 로케일(`en`, `de`, `fr`, `es`, `ja`...)의 모든 템플릿 | `none \| one \| {count} many` | 인덱스 기준 | **변경 없음** |
  | 카테고리당 하나의 형식 | `one \| few \| many` | 인덱스 기준: 21 → `many` | **변경 없음**. 21 → `one`을 원하면 마커를 추가하세요 |
  | 0 형식이 먼저, 세 개의 형식 | `none \| one \| many` | 인덱스 기준 | **변경 없음** |
  | 다른 자리 표시자 | `no items \| {n} item \| {n} items` | 인덱스 기준 | **변경 없음** |
  | 모든 형식에 `{count}` | `{count} many \| {count} one \| {count} few` | 인덱스 기준 | **변경 없음** |
  | 아래보다 형식이 적거나 많은 경우 | `a \| b`, `none \| one \| two \| {count} many` | 인덱스 기준 | **변경 없음** |
  | `lv`, `prg`, `blo`, `cv`, `ksh`, `lag`에서 | `none \| one \| {count} many` | 인덱스 기준 | **변경 없음** |
  | `=0 `으로 표시됨 | `=0 none \| one \| many` | 마커가 텍스트로 표시됨 | 0 형식, 그다음 카테고리 |
  | **자리 표시자가 없는 0 형식, 그다음 카테고리당 하나의 형식, 여러 수가 공유하는 각 형식에 `{count}`** | `none \| {count} one \| {count} few \| {count} many` | 인덱스 기준: 3 → `3 many`, 21 → `21 many` | **카테고리 기준**: 3 → `3 few`, 21 → `21 one`. 0, 1, 2와 `many`에 머무는 모든 수는 같은 결과를 제공합니다 |

  마지막 형태에는 세 개 이상의 카테고리가 필요합니다(`ru`, `uk`, `pl`, `cs`, `sk`, `hr`, `sr`, `lt`, `ro`, `sl`, `he`, `ar`, `cy`...). `ar`에서 `one`과 `two`는 단일 수이므로 이 두 형식에는 숫자가 필요하지 않습니다.
- **`Intl`이 모르는 로케일 코드는 마커의 카테고리 유무와 관계없이 인덱스 규칙을 받습니다**: `ua`는 더 이상 머신의 로케일을 따르지 않습니다. `iso`를 설정하세요: `{ code: 'ua', iso: 'uk-UA' }`는 모듈과 `@i18n-micro/vue`에서 우크라이나어로 복수형을 처리합니다.
- **사용자 지정 `plural` 규칙은 시그니처를 유지하며** 여전히 로케일 코드를 받습니다. 원시 값을 읽으므로 표시된 템플릿은 `=0 `이 그대로 있는 상태로 전달되며, 수를 `Number`로 받습니다: 이전에 `1`을 받던 곳에서 `1.5`를 받습니다. `null`을 반환하면 마커를 존중하는 기본 제공 규칙으로 폴백합니다.
- **`timeZone` 옵션.** 서버와 모든 브라우저에서 하나의 달력 날짜를 렌더링하려면 설정하세요(`Europe/Berlin`). 시계에 의존하는 `relativeDate`에는 영향을 주지 않습니다.

### `<i18n-t>` {#&lt;i18n-t>}

이 섹션은 모듈의 `<i18n-t>`와 `@i18n-micro/vue`의 `I18nT`를 다룹니다. 다른 프레임워크는 [프레임워크 패키지](#framework-packages)를 참조하세요.

- **`html`은 모든 경우에 `params`를 이스케이프하며, 모든 슬롯을 무시합니다.** 번역만 신뢰할 수 있는 마크업입니다. 의도적으로 마크업을 담은 매개변수는 이제 텍스트로 표시됩니다: 마크업을 번역에 넣고 데이터를 매개변수로 전달하거나, `html` 없이 슬롯을 사용하세요.
- **슬롯은 `plural`, `number`, `date`, `relativeDate`와 함께 작동하며,** 이 경우에도 `default` 슬롯이 `{ translation }`을 받습니다. 첫 번째뿐 아니라 모든 `{name}`이 채워집니다.
- **슬롯이 같은 이름의 매개변수보다 우선합니다.** 자리 표시자처럼 보이는 매개변수 값은 텍스트로 유지됩니다. `customPluralRule`이나 사용자 지정 `plural`을 사용하면 규칙이 완성된 문자열을 반환하므로, 규칙이 보간한 매개변수가 그곳에서 자리 표시자로 간주될 수 있습니다.
- **`null`은 `plural`, `number`, `date`, `relativeDate`에서 설정되지 않음을 의미합니다.** `:plural="null"`은 이전에 렌더링을 실패시켰고, `:date="null"`은 1970년을 렌더링했습니다.
- `plural`은 `$tc`처럼 `Number`로 셉니다: `1.5`는 `1.5`로 유지되어 마지막 형식을 사용하며, 이전에는 `1`로 잘렸습니다. `"2 items"`는 `NaN`이며, 이전에는 `2`였습니다. `""`는 `0`입니다. `customPluralRule`도 `1.5`를 봅니다. 그 외 계약은 변경되지 않았습니다: 같은 인수, 응답은 그대로 사용되며, `null`은 빈 값으로 렌더링됩니다.
- `hideIfEmpty`는 `plural`, `number`, `date`, `relativeDate`에 적용됩니다. 숨겨진 값은 빈 텍스트 노드가 아니라 주석으로 렌더링되므로, `''`를 읽던 테스트는 `<!---->`를 봅니다.
- **`html`에서 누락된 키는 텍스트입니다.** 번역만 신뢰할 수 있고 키는 요청에서 올 수 있으므로 키는 이스케이프됩니다. `defaultValue`는 사용자가 제공한 것이므로 마크업으로 유지됩니다.
- `plural`을 사용하면 `$tc`처럼 누락 시 `defaultValue`나 키가 통째로 사용됩니다: `a | b`는 더 이상 분할되지 않습니다.
- `defaultValue`는 키 자체가 아니라 모든 분기에서 누락된 키를 대신하며, `customPluralRule`은 누락 시 getter를 통해 이를 받습니다. 이전에는 `hideIfEmpty` 이후에만 동작했습니다.
- `number`, `date`, `relativeDate`를 사용하는 `<i18n-t>`는 `params`를 유지하며, 병합됩니다.
- `date`와 `relativeDate` 출력은 `data-allow-mismatch="text"`를 가집니다: 서버와 브라우저 간에 다른 시계나 시간대는 더 이상 하이드레이션 중에 경고하지 않습니다. 이름이 있는 슬롯 옆에서는 Vue가 요소의 단일 텍스트에서만 속성을 확인하므로, 슬롯 주변의 텍스트가 자체 `<span>`에 들어갑니다.
- `.innerHTML`과 `textContent` 속성은 `innerHTML`과 함께 제거됩니다.
- `<i18n-t>`와 `<i18n-group>`은 라우트의 청크가 아니라 `$t`처럼 활성 사전을 읽습니다. 제거된 청크(`cacheMaxSize`)는 더 이상 원시 키를 표시하지 않습니다. 떠나는 전환 중인 페이지는 이제 그곳에서 `$t`가 읽는 것을 읽습니다: 새 페이지의 사전을 읽고 누락 시 자체 사전으로 넘어가므로, 두 페이지 모두 정의한 키는 새 텍스트를 표시하며, 로케일 전환 후에는 언마운트될 때까지 자체 키가 원시 상태로 표시됩니다.

### `<i18n-switcher>`와 `<i18n-link>` {#&lt;i18n-switcher>-and-&lt;i18n-link>}

- **스위처 링크 클릭은 하나의 내비게이션입니다.** `NuxtLink`와 클릭 핸들러가 아니라 `$switchLocale`을 호출하는 일반 `<a>`이므로 `router-link-active` 클래스가 없어졌습니다. `href`는 여전히 `app.baseURL`을 포함하며, 현재 로케일의 링크는 여전히 `aria-current="page"`를 가집니다. Ctrl/cmd 클릭은 새 탭을 열고 현재 탭은 그대로 둡니다. 링크는 쿼리와 해시를 유지합니다.
- 버튼은 `type="button"`이므로 더 이상 주변 폼을 제출하지 않으며, `aria-expanded`를 가집니다. `aria-haspopup`은 모듈, `@i18n-micro/vue`, `@i18n-micro/astro`에서 제거되었습니다: 메뉴를 약속했지만 목록은 링크입니다. Escape와 외부 클릭으로 드롭다운이 닫히며, 두 스위처가 더 이상 함께 열린 상태로 유지되지 않습니다.
- 래퍼와 드롭다운에는 `i18n-switcher-wrapper`와 `i18n-switcher-dropdown` 클래스가 있으며, 버튼에는 `language-switcher`와 함께 `i18n-switcher-button`이 있고 레이블은 `<span>`에 들어 있습니다. 기본 스타일은 논리적 CSS 속성(`inset-inline-start`, `margin-inline-start`)을 사용하며, 캐럿은 `▾`입니다. 드롭다운에는 `z-index: 1000`(이전에는 10), `min-width: 150px`, `box-shadow`가 있고, 래퍼에는 `vertical-align: middle`이 있습니다. 각 링크에는 `lang`이 있으며, 로케일이 설정한 경우 `dir`도 있습니다.
- `<i18n-link>`: `https://`, `mailto:`, `tel:`은 대소문자와 관계없이 일치합니다(`HTTPS://x.com`, `Mailto:`). 단순 `report.pdf`나 `index.html`은 `https://report.pdf`가 아니라 라우트입니다. `example.com`과 `example.com:8080`은 외부 링크로 유지됩니다. TLD이기도 한 파일 확장자(`example.md`, `x.zip`)는 파일로 간주됩니다: `https://`를 작성하세요. `activeStyle`은 후행 슬래시, 쿼리, 해시를 무시합니다. 이제 타입이 `CSSProperties`이므로 일부 타입이 지정된 값은 변경이 필요할 수 있습니다.

### 훅, 플러그인, 타입 {#hooks-plugins-and-types}

- **`i18n:register`는 시작 시 `app:created`에서 실행되며,** 플러그인 사이가 아니라 모든 플러그인 이후에 실행됩니다. `order`가 1보다 크거나 `enforce: 'post'`인 플러그인도 이제 시작 시 구독자가 호출되지만, 자체 `setup`에서 등록된 키를 더 이상 읽지 못합니다. 내비게이션에서는 훅이 이제 다른 플러그인의 `router.beforeEach` 가드보다 먼저 실행됩니다.
- **`i18n:register`는 채우는 페이지의 로케일을 받습니다.** `hashMode`에서 로케일을 변경하는 내비게이션은 이전에 이전 로케일을 전달했고, 키가 잘못된 청크에 들어갔습니다.
- **`i18n:register`는 런타임 훅입니다:** 플러그인에서 `@ts-expect-error` 없이 `nuxtApp.hook('i18n:register', …)`으로 등록하세요. [훅](/ko/api/events)을 참조하세요.
- **`hooks: false`와 `define: false`**는 여전히 해당 부분을 끕니다.
- **`plugin: false`를 사용해도 `$defineI18nRoute`는 호출 가능하며** 런타임에 아무것도 하지 않습니다. 이전에는 페이지를 중단시켰습니다.
- `hooks` 옵션은 더 이상 `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`를 문서화하지 않습니다. 이들은 한 번도 발생한 적이 없습니다.
- 페이지에서 `const { $defineI18nRoute } = useNuxtApp()`는 이제 변수를 사용하는 설정에서도 작동합니다.
- `useI18n()`에 키가 추가되었습니다: `clearCache`, `pluralFunc`, `pluralLocale`. `clearCache`는 타입에 포함되어 있습니다.
- `$getRouteName(route)`는 주어진 라우트에 대해 응답합니다. 이전에는 빈 문자열을 반환했습니다.
- `useI18nLocale()`에서 `getLocaleWithServerFallback(serverLocale)`이 제거되었습니다: `getPreferredLocale() ?? serverLocale ?? null`로 작성하세요.
- **개발 환경의 서버에서 `$getI18nConfig()`는 읽기 전용입니다.** 그곳에서 쓰기는 예외를 던지며, 프로덕션에서는 모든 요청에 영향을 줄 것입니다.

### 서버, 빌드, 배포 {#server-build-and-deployment}

- **페이지의 페이로드 파일은 로케일의 루트와 다른 부분만 담습니다.** 클라이언트는 루트를 한 번 로드하고 각 페이지를 그 위에 병합하므로, 디스크와 Edge 번들이 줄어들고 두 번째 페이지의 비용은 첫 번째의 일부에 불과합니다. `premerged`는 이제 `__root/<locale>/data.json`을 작성하며, `/_locales/<page>/<locale>/data.json`은 차이만 담습니다: 이 파일을 직접 읽는 모든 것은 두 파일을 병합해야 합니다. 전체 사전도 여전히 유효한 파일이므로, 이를 제공하는 호스트나 `source` 모드는 계속 작동합니다.
- **사전 파일은 버전별로 캐시됩니다.** 현재 `?v=`가 있는 URL은 Node 서버에서 1년 동안 고정되고, 다른 URL은 재검증되며, 호스트의 정적 사본은 `max-age=60`으로 응답합니다: [캐시 헤더](/ko/guide/deployment#cache-headers-and-datebuild)를 참조하세요. `httpCacheControl: false`는 `max-age=0`을 유지합니다. 재빌드 없이 변경된 번역은 `v`가 바뀔 때만 브라우저에 도달합니다: `NUXT_I18N_DATE_BUILD`를 설정하세요.
- **사전은 `app.cdnURL`을 따릅니다.** 브라우저는 `app.baseURL`을 사용하던 곳에서 이제 `<cdnURL>/_locales/...`에서 공개 페이로드 파일을 가져옵니다: CDN은 `_locales/`를 보유하고 사이트의 오리진을 허용해야 합니다(CORS). [앱 baseURL과 페이로드 호스트](/ko/guide/deployment#app-baseurl-and-payload-hosts)를 참조하세요.
- **SSR은 더 이상 HTTP로 `/_locales`를 요청하지 않으므로,** 해당 라우트의 서버 미들웨어나 로그는 렌더링의 읽기를 더 이상 보지 못합니다. 외부 `apiBaseServerHost`는 여전히 HTTP를 사용합니다.
- **실패한 읽기는 더 이상 고정되지 않으며, 404도 마찬가지입니다.** 호스트의 404는 해당 파일이 없다는 의미입니다: 렌더링은 브라우저처럼 루트 사전을 표시하고, 아무것도 보관하지 않으며, 파일이 나타나면 읽습니다. 그 외 실패, JSON 객체가 아닌 200, 읽을 수 없거나 손상된 로컬 파일은 캐시에 들어가지 않으며 다음 요청에서 다시 읽습니다: 페이지 렌더링은 경고를 기록하고 원시 키를 표시하며 `no-store`와 `Retry-After`와 함께 `503`으로 응답하므로, 브라우저가 하이드레이션 시 여전히 사전을 읽는 동안 라우트 규칙이나 CDN은 아무것도 보관하지 않습니다. `/_locales/...`는 `no-store`와 함께 `503`으로 응답하고, `useTranslationServerMiddleware`는 키나 기본값으로 응답하는 `t`를 제공합니다. 장애 중에는 모든 요청이 호스트에 도달하며, 60초 동안 응답 헤더를 보내지 않는 호스트는 읽기에 실패합니다. 큰 파일의 느린 다운로드에는 제한이 없습니다. [사전을 읽을 수 없을 때](/ko/guide/deployment#when-a-dictionary-cannot-be-read)를 참조하세요. `/_locales`도 `200 {}`로 응답하던 곳에서 해당 404를 그대로 전달합니다.
- **사전을 로드할 수 없는 프리렌더는 실패하며,** 호스트에 페이지 파일도 루트 파일도 없는 경우도 마찬가지입니다. 라우트는 500이 되고, 경고가 로케일과 페이지를 알려 주며, 파일은 작성되지 않습니다. Nuxt의 기본 `failOnError`에서는 빌드가 1로 종료됩니다. 루트 파일 위에 자체 파일이 없는 페이지는 루트로 프리렌더됩니다.
- **빌드 시 설정된 호스트가 SSR에 응답하며,** 기본 공개 사본에서도, 내부 경로의 오류 페이지에서도 마찬가지입니다. 이전에는 공개 파일이 응답했습니다. 런타임의 `NUXT_I18N_APP_BASE_SERVER_HOST`가 이제 `/_locales`와 서버 로더에 적용되며, 렌더링은 해당 로더를 통해 어느 호스트든 읽습니다.
- **사용자 지정 `nitro.output.publicDir`, 그리고 `public/`이 서버 옆에 있지 않은 다른 모든 레이아웃은 페이로드를 임베드합니다.**
- **`nuxi build --preset <static preset>`은 `nuxi generate`처럼 프리렌더하므로,** 더 많은 파일을 작성할 수 있습니다. `nuxi generate`는 라우트 규칙이 `prerender: false`를 설정하지 않는 한, 링크 여부와 관계없이 모든 정적 페이지를 해당 페이지를 제공하는 각 로케일로 프리렌더합니다.
- **정적 출력에서 `source`나 `publicAssets: false`는 경고합니다.** 브라우저가 읽을 것이 없습니다.
- **임베드 경고는 이제 크기 검사입니다.** 빌드는 플랫폼의 한도를 넘을 때만 경고합니다: [번들 한도](/ko/guide/deployment#bundle-limits-on-edge)를 참조하세요.
- **방문자가 결정하는 모든 곳에 `Vary`가 설정됩니다:** `no_prefix`의 모든 페이지, 그리고 `/`와 선호에 따라 리디렉션할 수 있는 다른 모든 URL. 쿠키가 사용 중이면 `Cookie`를, `autoDetectLanguage`를 사용하면 `Accept-Language`를 담습니다. CDN의 캐시 키를 확인하세요: [HTML 캐싱](/ko/guide/deployment#caching-html)을 참조하세요.
- **`/_locales` 캐싱이 변경되었습니다.** `/{apiBaseUrl}/**`에 Nitro 라우트 캐시가 없으며, `s-maxage=60, stale-while-revalidate` 헤더가 제거되었습니다. 해당 캐시에 의존했다면 페이로드 라우트 앞에 CDN을 두세요. 빈 사전은 절대 `immutable`이 아닙니다.
- **서버 캐시는 기본적으로 제한됩니다:** `cacheMaxSize`가 설정되지 않으면 최대 1000개 항목입니다. `cacheTtl`은 항목이 저장된 시점부터 계산되며, 읽기는 더 이상 이를 연장하지 않습니다.
- **새로운 선택적 [`cacheStorage`](/ko/guide/performance#shared-cache-for-several-instances):** 여러 인스턴스가 공유하는 사전 캐시입니다. 설정하지 않으면 아무것도 바뀌지 않습니다.

| devtools-ui | `/files`와 `/file`은 `/translations`로 대체되었습니다. 크로스 사이트 또는 외부 호스트 요청은 403이며, `/save`에는 `application/json`이 필요합니다. 업데이트는 2초 폴링 없이 Vite의 소켓으로 전달됩니다. Astro는 `i18nDevToolsIntegration`을 사용합니다. `vite`는 선택적 피어입니다 | — |
| devtools-ui | `createBridge`는 `base` 옵션을 받습니다. 접근 가능한 엔드포인트로의 저장이 실패하면 예외를 던지고 롤백합니다 | 플러그인의 `base`를 변경했다면 `base`를 전달하세요 |
| devtools-ui | `/save`는 `translationDir` 안의 기존 `.json`만 받으며 더 이상 파일을 만들지 않습니다 | 새 로케일 파일은 직접 만드세요 |

## v2에서 v3로 {#from-v2-to-v3}

### 제거된 옵션 {#removed-options}

```diff
 i18n: {
-  includeDefaultLocaleRoute: true,
+  strategy: 'prefix',
-  fallbackRedirectComponentPath: '~/components/MyRedirect.vue',
-  experimental: { hmr: true, previousPageFallback: true },
+  hmr: true,
 }
```

- `includeDefaultLocaleRoute: true`는 `strategy: 'prefix'`이며, `false`는 기본값 `prefix_except_default`입니다.
- `fallbackRedirectComponentPath`는 제거되었습니다: 리디렉션은 렌더링 전 서버에서, 그리고 클라이언트 라우트 미들웨어에서 수행됩니다. 사용자 지정 리디렉션 로직은 로케일을 설정하는 플러그인에 넣으세요. [사용자 지정 로케일 감지](/ko/guide/custom-auto-detect)를 참조하세요.
- `experimental.hmr`은 루트 `hmr` 옵션입니다(기본적으로 켜져 있음).
- `previousPageFallback`은 제거되었습니다: 떠나는 페이지의 키는 옵션 없이 전환이 끝날 때까지 해석됩니다.

### 로케일 상태 {#locale-state}

`useState('i18n-locale')`와 `useCookie('user-locale')` 대신 `useI18nLocale()`을 사용하세요:

```diff
- useState('i18n-locale').value = 'fr'
- useCookie('user-locale').value = 'fr'
+ useI18nLocale().setLocale('fr') // state and cookie together
```

### 런타임 설정 {#config-at-runtime}

런타임 재정의를 포함한 설정은 `$getI18nConfig()`로 읽으세요:

```diff
- const cookieName = useRuntimeConfig().public.i18nConfig?.localeCookie
+ const { $getI18nConfig } = useNuxtApp()
+ const cookieName = $getI18nConfig().localeCookie
```

### 내부 타입 별칭 {#internal-type-aliases}

IDE나 `vue-tsc`가 `#i18n-internal/*` 가져오기를 해석하지 못하면 `package.json`에서 매핑하세요. Nuxt는 빌드 시 이를 해석하므로 거의 필요하지 않습니다:

```json
{
  "imports": {
    "#i18n-internal/plural": "nuxt-i18n-micro/internals",
    "#i18n-internal/strategy": "nuxt-i18n-micro/internals",
    "#i18n-internal/config": "nuxt-i18n-micro/internals"
  }
}
```
