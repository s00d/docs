`useI18n()`을 호출하는 컴포넌트는 단위 테스트에서 i18n 인스턴스가 필요합니다. `@i18n-micro/test-utils`는 실제 번역, 복수형, 서식 지정 로직을 갖춘 가짜 `useI18n()`을 제공하므로, Nuxt 서버 없이 직접 준비한 사전으로 컴포넌트를 마운트할 수 있습니다. 라우팅과 리디렉션은 `@nuxt/test-utils`로 실제 모듈을 엔드 투 엔드로 실행하세요.

이 페이지는 애플리케이션 테스트에 관한 내용입니다. 이 저장소가 모듈 자체를 테스트하는 방법은 [모듈 테스트하기](https://s00d.github.io/nuxt-i18n-micro/contributing/testing)에 있습니다.

## 설치 {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

```bash npm
npm install -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

</CodeGroup>

## useI18n 모킹 {#mock-usei18n}

```ts
// tests/unit-setup.ts
import { setupNuxtI18nMock } from '@i18n-micro/test-utils'
import { mockNuxtImport } from '@nuxt/test-utils/runtime'
import { beforeEach, vi } from 'vitest'

export const { i18n, useI18n, setTranslationsFromJson } = setupNuxtI18nMock({
  spy: vi.fn, // every method becomes a vi.fn, so you can assert calls
  beforeEach, // reset state and reseed `translations` before each test
  translations: { welcome: 'Welcome' },
})

mockNuxtImport('useI18n', () => useI18n)
```

```ts
// vitest.config.ts
import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    environment: 'nuxt',
    setupFiles: ['./tests/unit-setup.ts'],
  },
})
```

`mockNuxtImport`는 설정 파일에 두세요. `@nuxt/test-utils`가 이를 변환해야 하기 때문입니다. `setupNuxtI18nMock`은 비공개 번역 캐시를 사용하므로 병렬로 실행되는 테스트 파일끼리 상태를 공유하지 않습니다.

## 테스트 작성 {#write-a-test}

```vue
<!-- components/Greeting.vue -->
<script setup lang="ts">
const { $t } = useI18n()
</script>

<template>
  <p>{{ $t('welcome') }}</p>
</template>
```

```ts
// tests/greeting.spec.ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { expect, it } from 'vitest'
import Greeting from '~/components/Greeting.vue'
import de from '~/locales/de.json'
import { i18n, setTranslationsFromJson } from './unit-setup'

it('renders the German greeting', async () => {
  await setTranslationsFromJson('de', de)
  i18n.setLocale('de')

  const wrapper = await mountSuspended(Greeting)
  expect(wrapper.text()).toBe('Willkommen') // de.json: { "welcome": "Willkommen" }
})
```

가짜 객체는 실제 `useI18n()`과 동일한 메서드(`$t`, `$tc`, `$tn`, `$td`, `$has`, `$localePath`, …, `$`가 있는 형태와 없는 형태 모두)와 함께 테스트용 setter를 제공합니다: `setLocale`, `setLocales`, `setDefaultLocale`, `setRouteName`, `setTranslationsFromJson`, `loadPageTranslations`, `mergeTranslations`, `setMissingHandler`.

`$localePath`와 `$switchLocalePath`는 `strategy` 옵션에 따라 경로에 접두사를 붙이는 스텁입니다(실제 라우터 없음). 실제 링크와 리디렉션은 엔드 투 엔드로 테스트하세요.

## 저수준 헬퍼 {#lower-level-helpers}

| 헬퍼 | 용도 |
| --- | --- |
| `createIsolatedFakeI18n(options)` | Nuxt `useI18n` 연결이 없는 격리된 가짜 객체. 예: `global.mocks`를 사용하는 일반 `@vue/test-utils` `mount`용. |
| `createFakeI18n(options)` | 공유 모듈 캐시를 사용하는 가짜 객체(`beforeEach`에서 `resetI18n()` 호출), 또는 `isolated: true`로 격리된 객체. |
| `createI18nTestContext(options)` | 여러 개의 가짜 객체가 필요할 때 사용하는, 두 헬퍼의 기반 컨텍스트. |
| `t`, `tc`, `ts`, `tn`, `td`, `tdr`, `has` | 일반 함수 테스트를 위한 공유 컨텍스트 직접 호출. |

모의 객체는 `BaseI18n`입니다. `t`, `tc`, `tn`, `td`, `tdr`, `has`는 실제 사전 위에서 동작하는 실제 구현이므로, 테스트는 앱이 보여 주는 것과 같은 결과를 봅니다.

위의 팩토리 헬퍼는 `locale`, `defaultLocale`, `locales`, `routeName`, `strategy`, `translations`, `messages`(로케일별 사전)를 받습니다. 전체 예제 프로젝트는 [`packages/test-utils/example`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/test-utils/example)에 있습니다.

## 엔드 투 엔드 테스트 {#end-to-end-tests}

라우팅, 리디렉션, SEO 태그, 페이로드 로딩에는 실제 모듈이 필요합니다. `@nuxt/test-utils/e2e`로 앱을 시작하세요:

```ts
// tests/e2e/locales.test.ts
import { $fetch, fetch, setup } from '@nuxt/test-utils/e2e'
import { describe, expect, it } from 'vitest'

describe('locales', async () => {
  await setup({ server: true })

  it('serves the German page', async () => {
    expect(await $fetch('/de')).toContain('lang="de-DE"')
  })

  it('redirects / for a German browser', async () => {
    const res = await fetch('/', { headers: { 'accept-language': 'de' }, redirect: 'manual' })
    expect(res.headers.get('location')).toBe('/de')
  })
})
```

두 번째 테스트는 `prefix`(또는 다른 기본 로케일을 사용하는 `prefix_except_default`)를 가정합니다. `/`가 언제 리디렉션되는지는 [로케일 감지](/ko/guide/locale-detection)를 참고하세요.
