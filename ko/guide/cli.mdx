`@i18n-micro/cli`는 Nuxt 프로젝트의 로케일 파일을 관리합니다. `nuxt.config`에서 `locales`, `defaultLocale`, `translationDir`와 레이어를 읽으므로 자체 구성이 필요하지 않습니다.

![i18n-micro check를 실행하는 터미널. 누락된 키 하나, 정의되지 않은 키 하나, 사용되지 않는 키 네 개를 나열하고 실패한 뒤, extract가 정의되지 않은 키를 추가하고, clean --dryRun이 제거할 네 개의 키를 나열합니다](/images/cli/demo.gif)

| 명령 | 용도 |
| --- | --- |
| `check` | 로케일 파일에 문제가 있으면 빌드를 실패시킵니다 |
| `translate` | 번역 서비스로 누락된 키를 채웁니다 |
| `clean` | 아무것도 사용하지 않는 키를 제거합니다 |
| `rename` | 키 또는 네임스페이스 전체를 모든 곳에서 한 번에 옮깁니다 |

```bash
npm install -D @i18n-micro/cli
npx i18n-micro --help
```

앱 루트에서 실행하거나 `--cwd`로 앱 루트를 지정하세요. 모든 명령의 모든 플래그는 [명령 레퍼런스](/ko/api/cli)에 있습니다.

<Tip>

**nuxt-i18n-micro-cli에서 옮겨 오나요?** `@i18n-micro/cli`가 이를 대체하며, `i18n-micro`와 `i18n-micro-cli` 실행 파일은 그대로 유지됩니다. [이전 명령 표](#moving-from-nuxt-i18n-micro-cli)를 참고하세요.

</Tip>

## CI에서 사용하기 {#use-it-in-ci}

```bash
i18n-micro check
```

`check`는 관문 역할을 합니다. 다음을 보고합니다:

| 검사 | 의미 |
| --- | --- |
| `missing` | 기본 로케일의 키가 어떤 로케일에 없음 |
| `empty` | 값이 `''`임. 앱은 폴백이 아니라 빈 값을 표시합니다 |
| `extra` | 기본 로케일에 없는 키가 어떤 로케일에 있음 |
| `placeholders` | `{name}`이 사라지거나 추가되었거나, 복수형이 형태를 잃음 |
| `undefined` | 코드가 기본 로케일에 없는 키를 사용함 |
| `unused` | 프로젝트의 어떤 것도 키를 사용하지 않음 |
| `duplicates` | 서로 다른 키 아래에 같은 텍스트가 있음. 기본적으로 꺼져 있음: `--duplicates`를 전달하세요 |

- `--only missing,placeholders`는 일부 검사만 실행합니다. `--only`에 지정된 검사가 실행될 수 없으면 실패합니다.
- `--json`은 도구용 보고서를 제공합니다.
- `--ignore`는 소스 파일을 건너뜁니다.
- 키가 런타임에 계산되는 동안에는 `unused`를 건너뛰며, 보고서에 그 이유가 표시됩니다.

모든 명령은 세 가지 코드 중 하나로 종료되므로, 파이프라인은 번역의 문제와 도구의 문제를 구별할 수 있습니다:

| 종료 코드 | 의미 |
| --- | --- |
| `0` | 보고할 것이 없음 |
| `1` | 발견 사항 있음 |
| `2` | 명령을 실행할 수 없음: 사용법 오류, 손상된 파일, 실패한 요청 |

CI 단계로 둘 만한 다른 명령:

```bash
i18n-micro format --check      # fails if a file is not formatted
i18n-micro lint                # stray spaces, empty values, your own regex rules
i18n-micro stats --baseRef main
```

## 로케일을 동기 상태로 유지하기 {#keep-locales-in-step}

| 명령 | 하는 일 |
| --- | --- |
| `extract` | 코드가 사용하지만 아직 텍스트가 없는 키를 나열합니다. `$t('key', {}, 'Welcome')`처럼 지정된 기본 텍스트는 기본 로케일에 들어갑니다. |
| `sync` | 기본 로케일에 없는 키를 제거합니다. 먼저 `--dryRun`으로 시도하세요. |
| `clean` | 아무것도 사용하지 않는 키를 제거합니다. 먼저 `--dryRun`으로 시도하세요. |
| `search` | 키와 값을 찾고, 각 키가 어디에서 사용되는지 보여줍니다. |
| `stats` | 로케일별 완성도. `--baseRef main`은 git ref와 비교합니다. |

`sync`는 사용되지 않음을 증명할 수 없는 키를 제거하려 할 때 `clean`과 마찬가지로 중단되며, 기본 로케일에 비교할 것이 없을 때도 중단됩니다. 제거할 것이 없으면 절대 중단되지 않으므로, `$t(item.label)`만으로는 `--force`를 쓸 이유가 되지 않습니다.

<Note>

`extract`와 `sync`는 번역이 없는 키에 `''`를 절대 쓰지 않습니다. 키가 없는 상태로 유지되므로 런타임에 `fallbackLocale`이 적용되고 `check`가 이를 보고합니다. 빈 문자열은 정의된 값이 되어 빈 값을 표시하게 됩니다.

</Note>

### 명령이 읽는 대상 {#what-the-commands-read}

`check`, `extract`, `sync`, `clean`, `search`, `rename`은 고정된 폴더 목록이 아니라 프로젝트 전체의 소스 코드를 읽습니다:

- **읽음:** 파서를 통한 템플릿과 스크립트, 텍스트로서의 `.html`과 Pug, 모든 레이어, 그리고 별칭이나 `components`가 가리키는 루트 외부의 폴더.
- **건너뜀:** `node_modules`, 빌드 출력, 로케일 파일. `--ignore 'legacy/**,*.stories.ts'`로 직접 추가할 수 있습니다.
- **테스트 코드**는 사용으로 간주되므로, `clean`과 `check --only unused`는 테스트만 읽는 키도 유지합니다. 테스트 코드는 키를 추가하지 않습니다: `extract`는 그런 키를 건너뛰고, `check`는 정의되지 않은 키로 보고하지 않습니다.

테스트 코드란 루트 폴더 `tests`, `test`, `__tests__`, `e2e`, `cypress`, `playwright`와, 어디에 있든 `.spec` 및 `.test` JavaScript와 TypeScript 파일(`.ts`, `.tsx`, `.mts`, `.js`, `.jsx`, `.mjs` 등)을 의미합니다. 아래의 불확실성 규칙에서 면제되는 것은 루트 폴더뿐입니다: `pages/tests/[id].vue`는 다른 페이지와 같은 페이지이며, 코드가 앱의 일부가 아닌 `public/`과 압축된 파일도 마찬가지입니다.

명령이 인식하는 것:

- `$t`, `$ts`, `$tc`, `$has`, `$_t(route)`;
- `useI18n()`과 `useTranslationServerMiddleware()`의 `t()`;
- 템플릿과 JSX의 `<i18n-t keypath>`, 그리고 `<i18n-group prefix>`;
- `const { t: tr } = useI18n()` 같은 별칭.

### `clean`이 판단하는 방식 {#how-clean-decides}

`clean`은 사용 중인 키를 제거하느니 죽은 키를 남겨 둡니다. 다음 중 하나라도 해당하면 키는 유지됩니다:

- 호출이 그 키나 그 하위 또는 상위 키를 사용함;
- 코드의 문자열이 그 키와 같음: `const key = 'menu.home'`, `<Item label="menu.home" />`;
- 프로젝트의 JSON, YAML 또는 Markdown 파일에 그 키가 포함됨;
- 계산된 키의 정적인 시작 부분이 그 키를 포함함: `` $t(`status.${state}`) ``는 `status.` 아래의 모든 것을 유지합니다;
- 레이어가 그 키를 정의함.

`clean`은 알 수 없을 때 아무것도 변경하지 않고 중단하며, 그 이유를 나열합니다:

- `$t(name)`, `<i18n-t :keypath="name" />` 또는 `<i18n-t v-bind="props" />`처럼 키가 완전히 계산됨;
- `items.map($t)`처럼 `$t`가 값으로 전달됨;
- `t`라는 함수가 계산된 인수를 받고 매개변수, import 또는 호출에서 온 경우: 실제 함수를 감싼 래퍼일 수 있습니다. 같은 파일에서 정의한 함수는 해당하지 않습니다. 래퍼라면 내부에 자체 호출이 있을 것이기 때문입니다;
- 소스 파일을 파싱할 수 없음;
- 어떤 파일도 키를 전혀 사용하지 않음. 이는 대개 잘못된 위치를 보고 있다는 뜻입니다;
- 로케일 파일이 프로젝트 외부로 향하는 심볼릭 링크여서 다른 앱이 읽을 수 있음.

<Steps>

<Step title="미리보기">

`i18n-micro clean --dryRun`을 실행하고 나열된 내용을 검토하세요.

</Step>

<Step title="키 보호하기">

사용되지 않는 것처럼 보이기만 하는 키는 `--exclude '^errors\.'`로 유지하세요.

</Step>

<Step title="제거하기">

`--force`로 다시 실행하세요.

</Step>

</Steps>

## 누락된 키 번역하기 {#translate-missing-keys}

```bash
i18n-micro translate --dryRun                     # keys and characters per locale, nothing sent
export I18N_TRANSLATE_TOKEN=...                   # or put it in .env
i18n-micro translate --service deepl --locale de,fr
```

- `translate`는 누락되었거나 비어 있는 키를 채웁니다. `--replace`는 모든 것을 다시 번역합니다.
- 플레이스홀더와 복수형은 보호됩니다. 플레이스홀더를 잃은 번역은 기록되지 않습니다: 키가 나열되고 명령은 `1`로 종료됩니다.
- 각 배치는 다음 요청이 나가기 전에 저장되므로, 실패 시 잃는 것은 실패한 요청뿐입니다.

| `--service` | 서비스 | `--token` | 유용한 `--options` |
| --- | --- | --- | --- |
| `ai` | Vercel AI Gateway, OpenAI, Anthropic 또는 OpenAI 호환 서버 | API 키, 또는 `AI_GATEWAY_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` | `provider`, `model`, `baseUrl`, `maxTokens` |
| `azure` | Azure Translator | 구독 키 | `region` |
| `deepl` | DeepL, Free 키 포함 | 인증 키 | `formality`, `glossaryId`, `context` |
| `google` | Google Cloud Translation v2 | API 키 | `model` |
| `libretranslate` | LibreTranslate | 선택 사항 | `baseUrl` |
| `yandexcloud` | Yandex Cloud Translate | API 키, 또는 `authScheme:Bearer`와 함께 IAM 토큰 | `folderId`, `model` |

옵션은 `key:value` 쌍입니다: `--options provider:openai,model:gpt-4o-mini`. 모든 서비스는 `baseUrl`, `retries`, `retryDelayMs`, `timeoutMs`도 받습니다. 번역 요청은 이미 과금되었을 수 있으므로 `429` 또는 `503` 이후에만 재시도하며, 서비스가 1분 넘게 기다리라고 요청하면 재시도하지 않습니다.

<Warning>

플래그는 셸 기록과 프로세스 목록에 노출되므로 토큰은 환경 변수로 전달하세요. CLI는 `--debug`를 포함해 출력하는 모든 곳에서 비밀로 알려진 것을 마스킹합니다: 토큰, 제공자 키, Basic 자격 증명, 그리고 구성한 URL의 쿼리와 자격 증명. 키를 다시 출력하기 전에 형식을 바꾸는 서버는 처리할 수 없으므로, 실패한 실행의 로그는 주의해서 다루세요.

</Warning>

`ai` 서비스는 용어집을 따릅니다. `.i18n-glossary.json`이 있으면 플래그 없이 사용되며, `--glossaryFile`로 다른 파일을 선택할 수 있습니다.

```json .i18n-glossary.json
{ "entries": [{ "source": "Cart", "target": "Warenkorb", "to": "de" }] }
```

## 하드코딩된 텍스트를 키로 바꾸기 {#turn-hardcoded-text-into-keys}

```bash
i18n-micro text-to-i18n --dryRun   # list what would change
i18n-micro text-to-i18n            # rewrite the templates
```

```vue
<!-- before -->
<h1>Welcome to our site</h1>
<!-- after -->
<h1>{{ $t('pages.index.welcome-to-our') }}</h1>
```

레이어나 별칭 대상의 템플릿이 아닌, 프로젝트 자체의 `.vue` 템플릿만 다시 작성됩니다. 다시 작성된 모든 파일은 기록되기 전에 다시 파싱됩니다. 다음은 나열되며 텍스트가 유지됩니다:

- `.ts` 파일과 스크립트의 텍스트. `$t`가 모든 곳에서 사용 가능한 것은 아니기 때문입니다;
- `<p>Hello <b>world</b> today</p>`처럼 마크업이나 보간 옆에 있는 텍스트: 문장의 절반은 단독으로 번역할 수 없습니다;
- 부모 페이지와 자식 페이지처럼 다른 키와 충돌하는 생성된 키;
- 따옴표 사이에 넣을 수 없는 알려진 키.

<Warning>

먼저 커밋하고 diff를 검토하세요.

</Warning>

## 키 이름 바꾸기 {#rename-a-key}

```bash
i18n-micro rename --from common.save --to actions.save
i18n-micro rename --from settings --to account.settings   # a whole namespace
```

`rename`은 구문 트리를 편집하므로 주석과 관련 없는 문자열은 그대로 유지되며, 별칭과 `:keypath`도 추적됩니다. 레이어 자체의 파일은 절대 변경되지 않습니다. 다시 작성할 수 없는 것에 대해서는 경고하고 그대로 둡니다:

- 이전 이름 아래의 계산된 키;
- 그것과 같은 각각의 일반 문자열;
- Pug 템플릿;
- 레이어 또는 프로젝트 외부 폴더에 있는 소스.

`--to`는 코드에 작성할 수 있는 키여야 합니다: 따옴표, 백슬래시, 빈 세그먼트, `__proto__`는 사용할 수 없습니다.

## 번역가와 파일 주고받기 {#exchange-files-with-translators}

```bash
i18n-micro export --format csv
i18n-micro import --format csv --dryRun
```

**`export`**는 번역되지 않은 키를 포함해 모든 로케일의 모든 키를 기록하며, 기본 로케일 텍스트를 원문으로 사용합니다: CSV에서는 `Source` 열, PO에서는 `#.` 주석입니다.

- `--dir` 없이는 PO는 `pots`로, CSV는 `csv_exports`로 갑니다.
- 기록한 내용을 출력 폴더의 `.i18n-export.json`에 기록합니다. 그 이후 파일이 변경되어 로케일 파일에 없는 번역(퍼지 PO 항목 포함)을 담고 있으면 중단합니다. `--force`는 이를 덮어씁니다. 로케일 파일의 일반적인 편집으로는 중단되지 않습니다.

**`import`**는 병합하며, 빈 셀과 `fuzzy`로 표시된 PO 항목을 건너뜁니다.

- 값을 덮어쓰게 될 키나 키 그룹 전체를 덮어쓰게 될 값은 나열된 뒤 제외되며, 명령은 `1`로 종료됩니다.
- 예상치 못한 위치의 카탈로그, 마지막 export가 기록하지 않은 페이지의 카탈로그, CSV에서 잘못된 위치의 따옴표, 또는 `disablePageLocales`에서의 페이지 항목이 있으면 종료 코드 `2`로 중단됩니다.

번역 플랫폼의 경우 해당 플랫폼의 자체 CLI를 사용하세요: [Crowdin](/ko/guide/crowdin) 설정은 페이지 파일을 포함한 JSON 파일을 동기화합니다.

## 자체 엔드포인트와 동기화하기 {#sync-with-your-own-endpoint}

`sync-remote`는 직접 운영하는 HTTP 엔드포인트와 전역 로케일 파일을 주고받습니다. 페이지 파일은 로컬에 남으며, 명령이 이를 알려줍니다. `.i18n-remote.json`에 엔드포인트를 기술하세요:

```json .i18n-remote.json
{ "url": "https://translations.example.com", "path": "translations" }
```

엔드포인트는 `GET`과 `PUT`에 `{ locale: messages }` 객체로 응답합니다. `auth: { username, password }`로 인증하거나, `I18N_REMOTE_TOKEN`에 bearer 토큰을 넣으세요.

| | Pull | Push |
| --- | --- | --- |
| 이동하는 것 | 없는 것을 채우고 로컬에만 있는 키는 유지합니다 | 레이어의 키가 아닌 프로젝트 자체의 키를 보내며, 빈 값은 제외합니다 |
| 충돌 | 양쪽에서 다른 키: 아무것도 기록하지 않고 `1`로 종료. `--force`는 원격 값을 사용합니다 | PUT은 문서를 대체하므로, push는 먼저 엔드포인트를 읽고 로컬에 없는 텍스트가 있으면 `1`로 종료하며 중단합니다. `--force`는 이를 덮어씁니다. `404`로 응답하는 엔드포인트는 잃을 것이 없습니다 |
| `--dryRun` | 엔드포인트에서 읽고 변경 사항을 나열하며, 아무것도 기록하지 않습니다 | 엔드포인트에 접속하지 않고 무엇이 전송될지 알려줍니다 |

구성하지 않은 로케일은 건너뛰며, 비어 있는 원격 값은 아무것도 지우지 않습니다.

## nuxt-i18n-micro-cli에서 옮겨 오기 {#moving-from-nuxt-i18n-micro-cli}

| 이전 명령 | 현재 |
| --- | --- |
| `validate` | `check` |
| `diff` | `check --only missing` |
| `check-duplicates` | `check --only duplicates` |
| `export-csv`, `import-csv` | `export --format csv`, `import --format csv` |
| `--potsDir`, `--csvDir` | `--dir` |
| `estimate` | `translate --dryRun` |
| `glossary` | `.i18n-glossary.json`을 편집하세요. `translate`가 알아서 읽습니다 |
| `backup`, `restore` | 이미 로케일 파일을 보관하고 있는 Git |
| `init` | `nuxi init` 후 `modules`에 `nuxt-i18n-micro` 추가 |
| `split` | 제거됨: 모듈은 분할된 파일을 읽지 않습니다 |
| `optimize` | `check --only duplicates` |
| `replace-values` | 편집기 또는 `sed` |
| `stats --full` | `stats`; 자세한 내용은 [DevTools](/ko/guide/devtools)에 있습니다 |
| `search --hardcodedOnly` | `text-to-i18n --dryRun` |
| `search --preferUnused`, `--onlyVue` | 제거됨 |
| `lint` 규칙 `no-html-tags`, `no-special-chars`, `no-mixed-case`, `no-missing-punctuation`, `no-inconsistent-pluralization` | 제거됨: 일반 텍스트를 문제로 표시했습니다. 필요하다면 `customRegexRules` 항목을 작성하세요 |
| `text-to-i18n --extractOnlyDirs`, `--extractOnlyPatterns`, `--verbose` | 제거됨: 코드는 절대 다시 작성되지 않습니다 |
| `--logLevel verbose` | 제거됨: 아무 효과가 없었습니다 |

**제거된 서비스:** `googlefree`, `yandex` (`yandexcloud` 사용), `ibm`, `lingvatranslate`, `modernmt`, `lilt`, `unbabel`, `reverso`, `baidu`, `papago`, `tencent`, `systran`, `mymemory`.

**제거된 `sync-remote` 유형:** `github`, `gitlab`, `crowdin`, `lokalise`, `tolgee`, `weblate`. 플랫폼 자체의 CLI를 사용하거나, 이제 `type`이 필요 없는 `custom`을 사용하세요.

### 변경된 동작 {#changed-behaviour}

- `extract`와 `sync`는 더 이상 `''`를 기록하지 않습니다. 키는 없는 상태로 유지되며 `check`가 이를 보고합니다. `extract`는 코드가 텍스트를 제공할 때만 키를 기록합니다.
- `extract`는 모듈이 읽는 위치인 `locales/pages/<route name>/`에 페이지 키를 기록하며, Nuxt 4에서는 `app/`을 스캔합니다. `pages/_about`이나 `pages/blog_` 같은 디렉터리의 내용을 옮기고, 잘못 생성된 `locales/pages/<locale>.json`은 삭제하세요.
- `nuxt.config`의 `translationDir`가 반영됩니다. 이전에는 모든 명령이 조용히 `locales`를 사용했습니다.
- `defaultLocale`이 없으면 모듈과 마찬가지로 기본값은 `en`이며, `DEFAULT_LOCALE`이 반영됩니다. 이전에는 첫 번째 로케일이었습니다.
- `check`와 `sync`는 기본 로케일을 기준으로 사용하고 페이지 파일도 검사합니다. `"a.b"`와 `a: { b }`는 하나의 키로 간주됩니다.
- `clean`은 어떤 범위에서든 어디에서든 사용되는 키를 유지하며, 사용 여부를 증명할 수 없으면 중단합니다. `--include`와 `--exclude`로 제거할 수 있는 대상을 선택합니다.
- `sync`도 같은 방식으로 중단되며, 기본 로케일에 비교할 키가 없을 때도 중단됩니다. `--force`로 무시할 수 있습니다. `DEFAULT_LOCALE`이 `nuxt.config`와 다른 기준을 선택한 경우에도 중단됩니다.
- 대시 하나로 된 긴 플래그와 불필요한 인수는 오류입니다: `clean -dryRun`은 더 이상 `clean`을 실행하지 않습니다.
- 읽기 전용 파일이나 UTF-8이 아닌 파일은 저장할 수 없습니다: 명령은 아무것도 변경하기 전에 중단됩니다. 그런 파일을 읽는 것은 괜찮습니다. 중복된 키, `__proto__`라는 이름의 키, 2^53보다 큰 정수는 저장 시 손실되므로 명령을 중단시킵니다.
- 값이 필요한 플래그 뒤에 다른 플래그가 오면 오류입니다. 대시로 시작하는 값은 `--flag=--value`로 작성하세요. 불리언 플래그는 `true` 또는 `false`만 받습니다.
- `export`는 가져오지 않은 번역을 덮어쓰지 않고 중단합니다.
- 종료 코드는 `0`, `1`, `2`입니다. 이전에는 실패가 `1`이었고, `diff`와 `check-duplicates`는 항상 `0`이었습니다.
- `lint --fix`는 더 이상 `.bak` 파일을 남기지 않습니다.
- 저장 시 파일의 들여쓰기, 줄 끝, 마지막 줄바꿈, 심볼릭 링크, 하드 링크가 유지되며, 변경하지 않은 파일은 그대로 둡니다.
- 잘못 입력했거나 제거된 플래그는 이제 조용히 무시되지 않고 오류가 됩니다.
- `--dir` 같은 경로는 셸이 아니라 프로젝트를 기준으로 합니다.
- `ai`는 더 이상 `@ai-sdk/*` 패키지를 로드하지 않습니다: `provider`로 `gateway`, `openai` 또는 `anthropic`을 사용하거나, OpenAI 호환 서버에는 `baseUrl`을 사용하세요.
