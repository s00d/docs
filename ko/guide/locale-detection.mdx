모든 요청은 하나의 로케일을 받으며, 서버와 브라우저에서 동일한 소스 목록에서 동일한 순서로 선택됩니다. 처음 방문한 사용자가 어떤 언어로 도착할지, 사용자의 선택을 기억할지, 서버 API가 무엇을 보게 될지 결정할 때 이 문서를 읽으세요. 우선순위, 각 전략이 수행하는 리디렉션, 그리고 각 소스를 켜고 끄는 옵션을 설명합니다.

<Tip>

**사전 요구 사항** — [라우팅 전략](/ko/guide/strategy)

</Tip>

## 우선순위 {#the-precedence}

**활성화된** 로케일을 지정하는 첫 번째 소스가 우선합니다. 유효하지 않거나 형식이 잘못된 값(알 수 없는 코드, 손상된 쿠키)은 건너뛰고 다음 소스가 적용됩니다.

| # | 소스 | 적용 조건 |
| --- | --- | --- |
| 1 | URL 접두사 (`/de/about`) | 접두사 전략. `prefix_except_default`와 `prefix_and_default`에서는 접두사 없는 URL이 기본 로케일입니다 |
| 2 | `?locale=de` | 페이지: `no_prefix`에서만. 서버 API 헬퍼: 항상, 그리고 URL보다 먼저 |
| 3 | 앱이 설정한 로케일 상태 (`useI18nLocale().setLocale()`) | URL에 로케일이 없을 때 |
| 4 | 쿠키 | [`localeCookie`](/ko/api/module-options#localecookie)가 설정된 경우 (`no_prefix`에서는 자동으로 `'user-locale'`) |
| 5 | `Accept-Language` 헤더 | [`autoDetectLanguage`](/ko/api/module-options#autodetectlanguage)가 `true`인 경우 (기본값) |
| 6 | [`defaultLocale`](/ko/api/module-options#defaultlocale) | 항상 |

따라서 접두사 전략에서는 URL이 페이지에 표시할 내용을 결정합니다. 선호 소스(3–5)는 방문자가 어디로 **리디렉션**될지만 결정하며, `autoDetectPath`가 허용하는 경로에서만 그렇습니다. `no_prefix`에서는 리디렉션할 대상이 없으므로 선호 소스가 페이지에 표시할 내용을 결정합니다.

![결정 흐름: URL에 로케일 접두사가 있으면 해당 로케일로 렌더링합니다. 없으면 no_prefix는 선호 소스로 렌더링하고, prefix_and_default는 기본 로케일로 렌더링하며, prefix 또는 prefix_except_default는 autoDetectPath가 경로를 허용할 때 선호에 따라 리디렉션합니다](/images/diagrams/locale-detection.svg)

## 전략별 리디렉션 {#redirects-per-strategy}

리디렉션은 `302`이며, 페이지가 렌더링되기 전에 서버에서 수행되고, 클라이언트 내비게이션에서는 라우트 미들웨어가 수행합니다. 쿼리와 해시는 유지됩니다. [`redirects: false`](/ko/api/module-options#redirects)를 사용하면 리디렉션이 일어나지 않으며, 잘못된 접두사는 여전히 404입니다.

방문자가 `de`를 선호(쿠키 또는 헤더), `defaultLocale: 'en'`, 기본 `autoDetectPath: '/'`인 경우:

| 요청 | `prefix_except_default` | `prefix` | `prefix_and_default` | `no_prefix` |
| --- | --- | --- | --- | --- |
| `/` | → `/de` | → `/de` | `en`으로 `/` | `de`로 `/` |
| `/about` | `en`으로 `/about` | → `/de/about` | `en`으로 `/about` | `de`로 `/about` |
| `/fr/about` | `/fr/about` | `/fr/about` | `/fr/about` | — |
| `/en/about` | 404 | `/en/about` | `/en/about` | — |

`prefix_and_default`는 절대 리디렉션하지 않습니다: 접두사 없는 URL은 기본 로케일에 속하고, 다른 로케일은 해당 접두사 아래에 있습니다. `en`을 선호하는 방문자는 `prefix_except_default`에서 `/`로부터 리디렉션되지 않습니다. 대상에는 후행 슬래시가 없으며(`/de/`가 아닌 `/de`) 사용자 지정 경로를 따릅니다(`/about` → `/de/ueber-uns`).

쿠키나 헤더가 결정하는 모든 경우(`/`에서의 리디렉션, `no_prefix`의 모든 페이지)에 응답에는 `Vary: Cookie, Accept-Language`가 포함되므로 CDN이 응답을 구분해 보관합니다.

### `autoDetectPath` {#autodetectpath}

선호 소스가 방문자를 이동시킬 수 있는 위치:

| 값 | 선호가 적용되는 경로 |
| --- | --- |
| `'/'` (기본값) | `/`만. 딥 링크는 URL의 언어를 유지합니다 |
| `'no_prefix'` | 로케일 접두사가 없는 모든 경로 (`/about` → `/de/about`) |
| `'/welcome'` | 정확히 그 경로 (후행 슬래시는 무시됨) |
| `'*'` | 접두사가 있는 경로를 포함한 모든 경로: 방문자가 `de`를 선호하면 `/about`과 `/fr/about` → `/de/about` |

- 허용되지 않은 경로에서는 접두사 없는 URL이 기본 로케일로 처리됩니다.
- `prefix`는 예외입니다: 접두사 없는 페이지가 없으므로 `/about`은 항상 방문자의 로케일로 이동합니다(쿠키가 `de`이면 `/de/about`, 선호가 없으면 `/en/about`).
- `'*'`를 사용하면 서버는 앱의 상태를 무시하며, 접두사가 있는 URL은 더 이상 자신의 로케일을 쿠키에 기록하지 않습니다. 쿠키는 방문자가 `$switchLocale`로 전환할 때 변경됩니다.

<Warning>

`'*'`를 사용하면 공유된 링크가 읽는 사람의 언어로 열리므로 예상치 못한 결과가 될 수 있습니다. 그것이 원하는 동작이 아니라면 `'/'` 또는 `'no_prefix'`를 사용하세요.

</Warning>

## Accept-Language {#accept-language}

헤더는 RFC 9110의 정의대로 읽히며 설정의 로케일 **코드**와 비교됩니다:

- 항목은 `q` 값이 높은 순서대로 시도됩니다(`fr;q=0.1, de;q=0.9` → `de`). `q=0`은 "이 언어는 아님"을 의미하며, `q` 형식이 잘못된 항목은 무시됩니다. `*`는 아무것과도 일치하지 않습니다.
- `_`는 `-`로 읽힙니다(`en_US` = `en-US`).
- 항목별로: 정확한 코드, 그다음 짧은 형식(`de-AT` → `de`), 그다음 같은 언어의 지역 로케일(`en` → `en-US`). 정확한 형식과 짧은 형식은 `locales`의 순서에 의존하지 않으며, 여러 지역 로케일이 일치하면 `locales`에서 첫 번째가 우선합니다.
- 문자 체계는 절대 교차되지 않습니다: `zh-TW`와 `zh-HK`는 번체, `zh-CN`은 간체를 의미하므로 `zh-CN`은 `zh-Hant` 로케일과 절대 일치하지 않습니다.
- 비활성화된 로케일은 절대 일치하지 않습니다.

```ts
// locales: [{ code: 'en' }, { code: 'de' }, { code: 'zh-Hant' }]
// 'de-CH,de;q=0.9,en;q=0.8'  → 'de'
// 'en-GB'                    → 'en'
// 'zh-TW'                    → 'zh-Hant'
// 'zh-CN'                    → no match, next source
```

`autoDetectLanguage: false`로 헤더 감지를 끌 수 있으며, 쿠키와 상태는 여전히 적용됩니다.

## 쿠키 {#the-cookie}

- 접두사 전략에서는 **기본적으로 꺼져** 있습니다(`localeCookie: null`). 이 경우 리디렉션은 헤더만으로 작동하며, 선택은 방문 간에 기억되지 않습니다. 기억하려면 `localeCookie: 'user-locale'`을 설정하세요.
- `no_prefix`에서는 다른 이름을 설정하지 않는 한 `'user-locale'`입니다. 여기서도 `localeCookie: null`로 끌 수 있습니다.
- 방문자가 전환할 때(`$switchLocale`, `<i18n-switcher>`, `useI18nLocale().setLocale()`), 그리고 접두사가 있는 페이지를 서버 렌더링할 때 기록됩니다(`/fr/about`은 `fr`을 저장합니다. 단, 리디렉션이 켜진 `autoDetectPath: '*'`에서는 URL이 여전히 이동할 수 있으므로 저장하지 않습니다). 페이지로의 클라이언트 내비게이션도 해당 페이지의 로케일을 저장하며, 기본 로케일의 접두사 없는 페이지에서도 마찬가지입니다. 해당 URL의 첫 로드는 저장하지 않습니다. `no_prefix`와 해시 모드에서는 내비게이션이 변경 사항만 저장합니다. 404는 `$switchLocale`이 그곳에 도착하지 않는 한 아무것도 저장하지 않습니다.
- 유효 기간은 1년입니다(`path=/`, `SameSite=Lax`).
- `hashMode`에서는 선호가 대신 `hash-locale` 쿠키에 저장되며, 서버와 클라이언트가 같은 쿠키를 읽습니다. 서버는 해당 로케일로 렌더링하며, `prefix` 외에는 절대 리디렉션하지 않습니다. 해시의 로케일(`/#/de`)이 이보다 우선하며 하이드레이션 직후 적용됩니다. `prefix`에서는 `/`에 페이지가 없으므로 `/`는 브라우저에서 렌더링되고, 브라우저는 쿠키, 그다음 브라우저 언어(`autoDetectLanguage`)에 따라 `/#/de`로 이동합니다. 다른 모든 문서(`/about`, `/de`)는 해시로 리디렉션됩니다.

선호는 `useCookie`나 `useState`를 직접 사용하지 말고 [`useI18nLocale`](/ko/composables/useI18nLocale)로 읽고 설정하세요.

## 직접 구현하는 감지 {#your-own-detection}

로케일을 직접 선택하려면(사용자 설정, 서브도메인 등) 모듈의 플러그인보다 먼저 실행되는 플러그인에서 `useI18nLocale().setLocale(code)`를 호출하세요. 이것이 소스 3, 즉 앱의 상태가 됩니다. [사용자 지정 로케일 감지](/ko/guide/custom-auto-detect)에 기본 제공 감지를 끄는 방법을 포함한 전체 방법이 있습니다.

## 서버 API 라우트 {#server-api-routes}

[`useLocaleServerMiddleware`](/ko/guide/server-side-translations)와 `useTranslationServerMiddleware`는 API URL이 현지화되는 경우가 드물기 때문에 자체 순서를 사용합니다:

1. `?locale=`
2. `[locale]` 라우트 매개변수, 또는 경로의 로케일 접두사
3. 쿠키 (`localeCookie`가 설정된 경우)
4. `Accept-Language` (`autoDetectLanguage`가 켜진 경우)
5. `defaultLocale`

여기서도 `localeCookie: null`과 `autoDetectLanguage: false`가 소스 3과 4를 끕니다.

## 런타임 재정의 {#runtime-overrides}

[런타임 재정의](/ko/guide/runtime-overrides)는 소스와 비교되는 목록을 변경합니다:

- 런타임 `disabledLocales`는 모든 단계에서 제거됩니다: 이를 지정하는 쿠키나 헤더는 건너뜁니다.
- 런타임 `defaultLocale`은 `prefix`와 `no_prefix`에서 6단계입니다.
- `prefix_except_default`와 `prefix_and_default`에서는 기본 로케일이 빌드 시 고정됩니다(해당 페이지가 접두사 없는 라우트이기 때문). 런타임 `defaultLocale`이나 빌드 기본값의 비활성화는 경고와 함께 무시됩니다.
