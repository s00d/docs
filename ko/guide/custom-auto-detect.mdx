---

내장 감지는 URL, 쿠키, `Accept-Language`를 읽습니다. 로케일이 다른 무언가 — 도메인, CDN이 설정한 지역 헤더, 사용자 프로필 — 에 따라 달라진다면, i18n 플러그인보다 먼저 실행되는 플러그인에서 직접 설정하세요. 그러면 모듈은 해당 로케일의 번역을 로드하고, 직접 감지한 것과 똑같이 리디렉션에 사용합니다. 선택된 로케일이 언제 URL보다 우선하는지 결정하는 규칙은 [로케일 감지](/ko/guide/locale-detection)에 있으며, 이 페이지에서는 자신만의 소스를 연결하는 방법을 보여줍니다.

## 서버 플러그인에서 로케일 설정 {#set-the-locale-in-a-server-plugin}

```ts
// plugins/i18n-locale.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10, // before the i18n plugin (order -5)
  setup() {
    const { setLocale } = useI18nLocale()
    const host = (useRequestHeaders(['host']).host ?? '').split(':')[0]! // without the port

    if (host.endsWith('.de')) setLocale('de')
    else if (host.endsWith('.fr')) setLocale('fr')
  },
})
```

`setLocale(code)`는 로케일 상태(`useState('i18n-locale')`)를 기록하고, 로케일 쿠키가 구성되어 있으면 쿠키도 기록합니다. `useState`나 `useCookie`를 직접 쓰는 대신 이것을 사용하세요. 활성화된 로케일 코드만 전달하세요.

요청 헤더를 읽는 플러그인은 `.server.ts`로 유지하세요. 헤더는 브라우저에 존재하지 않습니다. `localStorage` 같은 브라우저 전용 소스는 `.client.ts` 플러그인에서 다루세요.

## 내장 Accept-Language 단계 끄기 {#turn-off-the-built-in-accept-language-step}

플러그인과 `Accept-Language`의 결과가 다를 수 있습니다. 코드(그리고 URL과 쿠키)만 결정하도록 하려면 헤더 단계를 끄세요:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    autoDetectLanguage: false,
  },
})
```

[`autoDetectLanguage`](/ko/api/module-options#autodetectlanguage)는 헤더 단계만 제어합니다. URL과 유효한 쿠키는 여전히 반영됩니다.

## 그다음에 일어나는 일 {#what-happens-next}

`setLocale`의 효과는 [전략](/ko/guide/strategy)에 따라 다릅니다:

| 전략 | 플러그인에서 `setLocale('de')`의 효과 |
| --- | --- |
| `no_prefix` | 페이지가 독일어로 렌더링되며, URL은 바뀌지 않습니다. |
| `prefix`, `prefix_except_default` | [`autoDetectPath`](/ko/api/module-options#autodetectpath)가 리디렉션을 허용하는 접두사 없는 경로(기본적으로 `/`만)에서 서버는 독일어 URL로 `302`를 응답합니다. 로케일 접두사가 있는 URL은 그대로 유지됩니다. |
| `prefix_and_default` | 리디렉션 없음: 접두사 없는 URL은 유효한 기본 로케일 페이지입니다. |

접두사 전략에서 URL의 로케일은 사용자의 선택이며, 플러그인이 이를 재정의하지 않습니다. `autoDetectPath: '*'`는 예외입니다. 이 경우 서버는 쿠키와 `Accept-Language`에 따라 접두사가 있는 URL을 이동시키고 상태는 무시하지만, 쿠키가 구성되어 있으면 `setLocale()`이 쿠키도 기록하므로 다음 요청부터는 플러그인의 선택이 접두사가 있는 URL을 리디렉션할 수 있습니다. 명시적인 로케일 URL이 우선해야 한다면 `'/'`를 유지하거나 `'no_prefix'`를 사용하세요. 플러그인은 방문자가 도착할 위치를 선택하는 데 사용하고, 사용자가 따라온 링크를 다시 쓰는 데 사용하지 마세요.

## 사용자가 선택한 로케일 존중하기 {#respect-a-locale-the-user-picked}

사용자가 언어를 전환하면 전환 시 쿠키가 기록됩니다. 이미 유효한 선호 설정이 있으면 자체 감지를 건너뛰세요:

```ts
// plugins/i18n-locale.server.ts
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10,
  setup() {
    const { getPreferredLocale, setLocale, validLocales } = useI18nLocale()
    if (getPreferredLocale()) return // valid state or cookie: keep it

    const country = useRequestHeaders(['x-country'])['x-country']
    if (country === 'JP') return setLocale('ja')

    const header = useRequestHeaders(['accept-language'])['accept-language']
    setLocale(detectLocaleFromAcceptLanguage(header, validLocales))
  },
})
```

`getPreferredLocale()`는 상태나 쿠키가 활성화된 로케일일 때만 반환하므로, 오래된 쿠키가 감지를 막지 않습니다. `detectLocaleFromAcceptLanguage`는 모듈 자체가 사용하는 q 값 인식 매처입니다(가져오려면 `@i18n-micro/utils`를 설치하세요). `setLocale(null)`은 아무 작업도 하지 않습니다.

## 로케일당 하나의 도메인 {#one-domain-per-locale}

각 도메인이 자체 로케일을 제공해야 한다면 플러그인이 필요 없습니다. 각 로케일에 `baseUrl`을 지정하고, 각 도메인의 기본 로케일에 `baseDefault: true`를 설정한 뒤 한 번 빌드하세요(정적 사이트는 여전히 도메인별로 `nuxi generate`를 실행합니다). [레이어와 도메인](/ko/guide/layers#multiple-domains)을 참고하세요.
