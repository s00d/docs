---
title: "페이지 설정"
description: "$defineI18nRoute로 페이지를 일부 로케일로 제한하고, 사용자 지정 경로, 인라인 번역을 지정하거나 SEO 태그를 끕니다."
---

`$defineI18nRoute`는 페이지 내부에서 해당 페이지의 i18n 옵션을 설정합니다. 페이지가 일부 로케일에만 존재하거나, 자체 현지화 경로가 필요하거나, 자체 번역을 몇 개 가지고 있거나, hreflang/canonical 태그를 받으면 안 될 때 사용하세요. 모듈은 빌드 시 이 호출을 읽고 생성된 라우트에 반영합니다.

## 페이지를 일부 로케일로 제한하기 {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

기본 `prefix_except_default` 전략에서는 `/product`와 `/de/product`만 생성되며, 페이지는 다른 로케일에서는 라우트가 없습니다. 같은 설정을 `nuxt.config.ts`에서 [`routeLocales`](/ko/api/module-options#routelocales)로 지정할 수도 있습니다.

`$defineI18nRoute`는 컴파일러 매크로가 아니라 Nuxt 앱 주입입니다: 항상 `useNuxtApp()`에서 가져와 `$`와 함께 호출하세요. 빌드 단계에서는 `$defineI18nRoute(`만 인식됩니다.

## 인라인 번역 추가하기 {#add-inline-translations}

배열 대신 객체를 전달하세요. 키는 허용되는 로케일이고, 값은 활성 로케일의 페이지 사전에 병합됩니다.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

인라인 번역은 모든 로케일에 대해 페이지 컴포넌트 안에 포함되어 배포됩니다. 키가 몇 개를 넘는다면 [페이지 번역 파일](/ko/guide/translations)을 사용하고, 인라인 키는 독립적인 페이지와 컴포넌트에만 사용하세요.

## 현지화된 경로 설정하기 {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

`prefix_except_default`와 `defaultLocale: 'en'`에서는 `/welcome`과 `/de/willkommen`이 생성됩니다. 인라인 로케일 객체 안의 `path`도 같은 역할을 합니다: `locales: { de: { path: '/willkommen' } }`. 동적 매개변수, 중첩 라우트, 설정 수준의 대안은 [현지화된 경로](/ko/guide/custom-locale-routes)에서 다룹니다.

## SEO 태그 끄기 {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

설정 수준의 대안은 [`routeDisableMeta`](/ko/api/module-options#routedisablemeta)입니다. 태그에 대한 설명은 [SEO](/ko/guide/seo) 페이지에 있습니다.

## 빌드가 읽을 수 있는 것 {#what-the-build-can-read}

빌드 단계는 각 페이지 파일에서 호출을 찾아 앱을 실행하지 않고 인수를 평가합니다. 설정이 다음과 같을 때 작동합니다:

- 리터럴 객체(문자열, 배열, 중첩 객체, 템플릿 리터럴, `process.env.NODE_ENV`에 대한 삼항 연산자);
- 같은 `<script setup>`에 선언된 상수로 구성된 경우(`const locales = ['en', 'de']`, 스프레드 포함);
- `code` 필드가 있는 객체의 배열(`[{ code: 'en' }, { code: 'de' }]`).

다른 모듈에서 가져온 값이나 런타임에 앱이 필요한 것(컴포저블, `await`, 가져온 데이터)은 읽을 수 없습니다. 이 경우 빌드는 `Ignored the $defineI18nRoute() config in <file>`을 로그로 남기고, 페이지는 기본 로케일과 라우트를 유지합니다.

런타임에 이 호출은 현재 로케일의 인라인 번역만 병합하고, 로케일이 바뀌면 다시 병합합니다. `locales`, `localeRoutes`, `disableMeta`는 빌드를 통해서만 적용되므로 변경하려면 다시 빌드해야 합니다(개발 서버는 저장 시 다시 빌드합니다).
