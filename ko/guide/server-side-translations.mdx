`server/api/`와 `server/routes/`의 서버 핸들러는 자동 임포트되는 두 헬퍼로 문자열을 번역하고 요청의 로케일을 읽을 수 있습니다. API 응답, 이메일, 피드 등 Vue 페이지 밖에서 렌더링되는 모든 것에 사용하세요. 이 헬퍼들은 페이지와 같은 번역 파일을 읽고 요청에서 로케일을 감지합니다.

## 핸들러에서 번역하기 {#translate-in-a-handler}

```ts
// server/api/greeting.get.ts
export default defineEventHandler(async (event) => {
  const t = await useTranslationServerMiddleware(event)
  return { message: t('greeting', { name: 'Ada' }) }
})
```

```bash
curl 'http://localhost:3000/api/greeting?locale=de'
# {"message":"Hallo, Ada!"}
```

`useTranslationServerMiddleware(event, defaultLocale?, locale?)`는 비동기이며 `t(key, params?, defaultValue?)`를 반환합니다. `t`는 문자열을 반환하고 `{name}` 매개변수를 보간하며, 키가 없으면 비어 있지 않은 `defaultValue`를, 그것도 없으면 키를 반환합니다.

`t`는 `index` 청크만 볼 수 있습니다: 루트 파일(`locales/<locale>.json`)과, 존재하는 경우 `locales/pages/index/`(`disablePageLocales`이면 루트 파일만). 다른 페이지의 키는 로드되지 않습니다. 그런 키는 청크를 직접 로드하세요:

```ts
const { data } = await loadTranslationsFromServer('de', 'about') // Translations object of the about page
```

## 요청 로케일 읽기 {#read-the-request-locale}

```ts
// server/api/locale.get.ts
export default defineEventHandler((event) => {
  const { current, isDefault, locale } = useLocaleServerMiddleware(event)
  return { current, isDefault, dir: locale?.dir ?? 'ltr' }
})
```

`useLocaleServerMiddleware(event, defaultLocale?, locale?)`는 동기이며 다음을 반환합니다:

```ts
interface LocaleInfo {
  current: string // detected locale code
  default: string // defaultLocale, runtime overrides included (fixed at build under prefix_except_default / prefix_and_default)
  fallback: string // fallbackLocale, else the default
  available: string[] // enabled locale codes
  locale: Locale | null // the config entry of `current`
  isDefault: boolean
  isFallback: boolean
}
```

## 로케일 선택 방식 {#how-the-locale-is-chosen}

두 헬퍼는 `/api`인지 여부와 관계없이 모든 서버 라우트에서 같은 순서를 사용합니다:

1. `?locale=` 쿼리(반복되면 첫 번째 값);
2. `[locale]` 라우트 매개변수, 또는 경로의 로케일 접두사(`/de/...`);
3. [`localeCookie`](/ko/api/module-options#localecookie)가 설정된 경우 로케일 쿠키(`hashMode`에서는 `hash-locale`);
4. `autoDetectLanguage`가 켜져 있으면 `Accept-Language`(q 값 반영);
5. `defaultLocale`.

유효하지 않거나 비활성화된 코드는 모든 단계에서 건너뜁니다. 이것은 API의 순서이며, 페이지 렌더링은 접두사 전략에서 `?locale=`을 무시합니다. 두 순서는 [로케일 감지](/ko/guide/locale-detection)에서 비교합니다.

## 로케일 강제 지정 {#force-a-locale}

감지를 건너뛰려면 세 번째 인수를 전달하세요. 예를 들어 사용자의 언어로 메일을 보내는 작업에서:

```ts
export default defineEventHandler(async (event) => {
  const user = await getUser(event) // your code
  const t = await useTranslationServerMiddleware(event, undefined, user.locale)
  return sendMail(user.email, t('mail.welcome.subject'))
})
```

두 번째 인수는 이 호출의 감지에서 `defaultLocale`을 대체하므로, 로케일이 강제 지정되면 효과가 없습니다. 사전은 요청별, 로케일별로 캐시되며, 요청 간에는 서버의 번역 캐시에 캐시되므로 헬퍼를 여러 번 호출해도 비용이 적습니다.

## 서버 컴포넌트 {#server-components}

서버 컴포넌트(`.server.vue`, `<NuxtIsland>`)는 자체 URL인 `/__nuxt_island/...`에서 렌더링되므로 페이지의 URL을 보지 못하며, Nuxt는 props만 전달합니다. 로케일을 `locale` prop으로 전달하세요. 그러면 해당 로케일로 렌더링되며, props가 아일랜드의 URL과 캐시 키의 일부이므로 로케일을 전환하면 다시 가져옵니다. 이 이름은 예약되어 있습니다: `locale`이라는 prop에 활성화된 로케일 코드가 들어 있으면 렌더링 로케일이 설정되므로, 숫자 형식처럼 다른 의미의 prop에는 다른 이름을 지정하세요:

```vue
<!-- components/Greeting.server.vue -->
<template><p>{{ $t('greeting') }}</p></template>
<script setup lang="ts">
defineProps<{ locale?: string }>()
</script>
```

```vue
<template>
  <Greeting :locale="$getLocale()" />
  <NuxtIsland name="Greeting" :props="{ locale: $getLocale() }" />
</template>
```

prop이 없으면 URL과 관계없이 쿠키의 로케일, 없으면 기본 로케일로 렌더링되며, 로케일 전환을 따르지 않습니다. 이 컴포넌트의 `$t`는 `index` 청크, 즉 루트 파일과 `locales/pages/index/`를 봅니다.
