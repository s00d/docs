`strategy` 옵션은 URL에 로케일이 나타나는지, 어떤 로케일에 대해 나타나는지를 결정합니다. URL을 공개하기 전에 한 번 선택하세요: 나중에 변경하면 모든 링크가 바뀝니다. 그런 다음 모듈은 빌드 시 현지화된 라우트를 생성하며, `$localePath`, `<i18n-link>`, 스위처가 이를 읽습니다.

## 네 가지 전략 {#the-four-strategies}

![각 전략에서 en(기본값)과 de의 /about 페이지. 같은 URL이 아래 본문에 나열되어 있습니다](/images/diagrams/strategies.svg)

**타입** `Strategies` · **기본값** `'prefix_except_default'`

로케일 접두사를 위한 URL 라우팅 전략입니다.

- `'no_prefix'` — URL에 로케일이 없으며, 로케일은 쿠키에 저장됩니다.
- `'prefix_except_default'` — 기본 로케일을 제외한 모든 로케일에 접두사를 붙입니다.
- `'prefix'` — 기본 로케일을 포함해 항상 접두사를 붙입니다.
- `'prefix_and_default'` — `prefix`와 같지만, 기본 로케일은 접두사 없이도 접근할 수 있습니다.

`defaultLocale: 'en'`과 로케일 `en`, `de`에서 `about` 페이지의 URL:

| 전략 | 영어 | 독일어 | 제공되지 않음 |
| --- | --- | --- | --- |
| `prefix_except_default` (기본값) | `/about` | `/de/about` | `/en`과 `/en/about`은 404 |
| `prefix` | `/en/about` | `/de/about` | `/about`은 접두사가 있는 URL로 리디렉션 |
| `prefix_and_default` | `/about`과 `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | 로케일이 URL에 없음 |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

전략은 빌드 시 고정됩니다: 런타임 재정의는 경고와 함께 무시됩니다([런타임 재정의](/ko/guide/runtime-overrides)).

## 어떤 전략을 선택할까 {#which-one-to-choose}

- **`prefix_except_default`**: 대부분의 사이트. 기존의 접두사 없는 URL이 기본 언어로 계속 작동합니다.
- **`prefix`**: 모든 언어가 동등합니다. `/`는 항상 접두사가 있는 홈으로 이동합니다.
- **`prefix_and_default`**: `/en/...`과 접두사 없는 URL이 모두 작동해야 할 때, 예를 들어 한쪽에서 다른 쪽으로 이전하는 동안. 접두사 없는 URL은 절대 리디렉션되지 않습니다.
- **`no_prefix`**: 로그인 뒤에 있는 앱, 또는 모든 언어에 대해 페이지당 하나의 URL을 사용하는 경우. 로케일은 쿠키나 `?locale=`에서 옵니다. 검색 엔진은 URL당 하나의 언어만 보므로 `hreflang` 대체 링크가 출력되지 않습니다.

URL의 로케일이 선택되는 방식과 방문자가 리디렉션되는 시점은 [로케일 감지](/ko/guide/locale-detection)에 있습니다.

## 생성된 라우트 {#generated-routes}

빌드 시 모든 페이지는 전략에 필요한 라우트 레코드를 받습니다. 각 레코드는 `meta.i18n = { name, locales }`를 가지며, 이는 표시하는 페이지와 제공하는 로케일입니다. 링크, 전환, 리디렉션은 모두 이 레코드를 기반으로 응답하므로, 모듈이 제공하는 URL은 항상 라우터가 제공하는 URL입니다.

페이지의 경로를 공유하는 로케일은 하나의 레코드 `/:locale(de|fr)/about`을 공유합니다. 자체 경로가 있는 로케일은 `localized-<page>-<locale>`이라는 이름의 자체 레코드를 받습니다:

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

사용자 지정 경로, 페이지별 로케일 목록, 페이지를 현지화에서 제외하는 방법은 [현지화된 경로](/ko/guide/custom-locale-routes)와 [페이지 설정](/ko/guide/per-component-translations)에 있습니다. `localized-` 접두사는 [`localizedRouteNamePrefix`](/ko/api/module-options#localizedroutenameprefix)입니다.

<Warning>

**라우트 이름은 생성됩니다** — `router.push({ name })`에 `localized-…` 이름을 하드코딩하지 마세요. 페이지 자체의 이름을 `$localeRoute`나 `<i18n-link>`에 전달하면 올바른 레코드를 선택합니다.

</Warning>

## 특정 로케일의 페이지로 링크하기 {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- 이름이 있는 라우트와 경로 모두 작동합니다. 경로는 생성된 라우트와 비교되므로 어느 로케일 형식이든 허용됩니다.
- 해당 페이지를 제공하지 않는 로케일([페이지 설정](/ko/guide/per-component-translations)의 `locales` 참조)은 존재하지 않는 페이지 대신 해당 로케일의 홈으로 링크됩니다.
- 로케일별 매개변수(번역된 슬러그)는 `$setI18nRouteParams`를 통해 처리됩니다. [현지화된 경로](/ko/guide/custom-locale-routes)를 참조하세요.

시그니처는 [메서드](/ko/api/methods)에 있습니다.

## `no_prefix` 세부 사항 {#no_prefix-details}

- `no_prefix`에서 [`localeCookie`](/ko/api/module-options#localecookie)의 기본값은 `'user-locale'`이므로 새로고침 후에도 선택이 유지됩니다.
- `$switchLocale('de')`는 독일어 사전을 로드하고 현재 히스토리 항목을 교체합니다. URL은 변경되지 않습니다.
- 로케일별 사용자 지정 경로도 여전히 작동합니다: `globalLocaleRoutes: { about: { de: '/ueber-uns' } }`를 사용하면 독일어 독자는 `/ueber-uns`를 받습니다. 이 URL은 방문자의 선호와 관계없이 항상 독일어로 렌더링되며, 일부 로케일로 제한된 페이지는 그중 하나로 렌더링됩니다. 여러 로케일이 공유하는 경로(`en`과 `de`가 모두 `/page/:id`)는 선호가 그중 하나일 때 선호 로케일로 렌더링됩니다. 선호 자체는 유지됩니다: 다음 페이지에서 다시 선호 로케일로 돌아갑니다.
- [`noPrefixRedirect: true`](/ko/api/module-options#noprefixredirect)는 기본 로케일에서 사용자 지정 경로가 있는 페이지의 원래 경로를 리디렉션합니다: 방문자 로케일의 사용자 지정 경로로, 없으면 기본 로케일의 사용자 지정 경로로 이동합니다(`en`에 `/about-us`가 있으면 `/about` → `/about-us`, 쿠키가 `de`이면 → `/ueber-uns`). 자체 사용자 지정 경로가 없는 로케일은 원래 경로에 머무르며 그곳에서 렌더링됩니다. 매개변수가 있는 페이지는 리디렉션되지 않습니다.

## `pages/`가 없는 앱 {#apps-without-pages/}

`pages: false`를 사용하면 현지화할 페이지 라우트가 없습니다. 루트 번역 파일만 사용하세요(`disablePageLocales: true`). 감지, 쿠키, `$switchLocale`는 여전히 작동합니다. 저장소의 `test/fixtures/basic`의 `pages-false` 변형이 작동하는 설정 예시입니다.
