Nuxt 레이어는 여러 앱을 위한 i18n 구성과 `locales/` 폴더를 담을 수 있으며, 각 앱은 필요한 것을 추가하거나 재정의합니다. 이 페이지에서는 그 방법과 하나의 빌드로 여러 도메인을 제공하는 방법을 보여줍니다.

## 구성과 번역 공유하기 {#share-config-and-translations}

```ts
// base/nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    defaultLocale: 'en',
  },
})
```

```ts
// shop/nuxt.config.ts
export default defineNuxtConfig({
  extends: ['../base'], // a layer directory or package, not a nuxt.config file
  i18n: {
    locales: [
      { code: 'es', iso: 'es-ES' }, // added
      { code: 'fr', disabled: true }, // the base layer's fr, switched off here
    ],
  },
})
```

- **구성:** 앱의 스칼라 옵션은 레이어의 옵션을 대체합니다. 모든 레이어의 `locales` 배열은 합쳐지며, 같은 `code`를 가진 항목은 앱의 필드가 우선하는 방식으로 하나로 병합됩니다. 따라서 앱은 로케일을 추가하거나 상속받은 로케일에 `disabled: true` 같은 필드를 설정할 수 있습니다.
- **번역:** 모든 레이어의 `locales/`는 레이어가 먼저, 앱이 마지막으로 키 단위로 병합되므로, `shop/locales/en.json`의 키는 `base/locales/en.json`의 같은 키를 재정의합니다. 페이지 파일(`locales/pages/<page>/`)도 같은 방식으로 병합됩니다.
- **페이지:** `$defineI18nRoute`는 모든 레이어의 페이지에서 읽힙니다.

레이어에 속하지 않는 폴더를 병합하려면 [`additionalTranslationDirs`](/ko/api/module-options#additionaltranslationdirs)에 나열하세요.

## 여러 도메인 {#multiple-domains}

하나의 빌드가 모든 도메인을 제공합니다. 각 로케일을 해당 도메인과 함께 나열하세요. `baseDefault`는 해당 로케일을 그 호스트의 기본값으로 만듭니다:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'de', iso: 'de-DE', baseUrl: 'https://example.de', baseDefault: true },
      { code: 'nl', iso: 'nl-NL', baseUrl: 'https://example.de' },
      { code: 'fr', iso: 'fr-FR' },
    ],
  },
})
```

두 도메인 모두 같은 서버를 가리키게 하세요. 나머지는 요청의 호스트가 결정합니다:

- **기본값:** 호스트의 `baseDefault` 로케일. 없으면 호스트가 제공하는 경우 빌드 기본값, 그렇지 않으면 호스트의 첫 번째 로케일.
- **제공되는 로케일:** 해당 호스트의 로케일과 `baseUrl`이 없는 모든 로케일. `example.de`에서는 `de`, `nl`, `fr`입니다.
- **다른 도메인의 로케일**은 링크 대상입니다. `$localePath`, `$localeRoute`, `$switchLocalePath`, `<i18n-switcher>`, `hreflang`은 해당 `baseUrl`의 절대 URL을 제공하며, `$switchLocale`은 그곳으로 이동합니다. 이 호스트에서 해당 URL은 404이며, 쿠키나 `Accept-Language`로 선택할 수 없습니다.
- **다른 도메인으로의 링크**는 `$localePath` 또는 `<i18n-link>`를 거칩니다: `<NuxtLink :to="$localePath('/contact', 'de')">`, `<i18n-link :to="$localeRoute('/contact', 'de')">`. 라우터는 절대 객체를 받지 않으므로 `<NuxtLink :to="$localeRoute(...)">`와 `router.push($localeRoute(...))`는 현재 오리진에 머뭅니다. `localhost`나 미리보기 호스트에서는 현재 로케일을 포함해 `baseUrl`이 있는 모든 로케일이 이러한 링크입니다. 코드에서는 `navigateTo($localePath('/contact', 'de'), { external: true })` 또는 `$switchRoute`를 사용하세요.
- **그 외의 호스트**는 빌드 구성을 받으며, `baseUrl`이 있는 모든 로케일이 링크 대상이 됩니다. 요청의 어떤 값도 그대로 반영되지 않습니다: canonical과 `hreflang`은 `metaBaseUrl`을 사용하고, 없으면 빌드 기본값의 `baseUrl`을 사용합니다(`baseUrl`이 없는 기본값에는 `metaBaseUrl` 또는 `site.url`이 필요합니다. [SEO](/ko/guide/seo#set-the-public-origin) 참고).
- `public/`의 **페이로드 파일**은 정적입니다: 어떤 호스트든 모든 로케일의 파일을 반환합니다. 도메인별 [generate](/ko/guide/deployment#static-site-(nuxi-generate))는 해당 도메인의 파일만 게시합니다.

`contact`의 사용자 정의 경로로 `de: '/kontakt'`를 지정했을 때 각 전략에서의 `example.de`:

| 전략 | `/` | 기본 로케일의 페이지 | 기타 URL |
| --- | --- | --- | --- |
| `prefix_except_default` | `de` | `/kontakt` | `/de/kontakt`와 `/en/contact`는 404, `/contact`는 `/kontakt`로 리디렉션 |
| `prefix_and_default` | `de` | `/kontakt`와 `/de/kontakt`, 링크는 `/kontakt` 사용 | `/en/contact`와 `/contact`는 404 |
| `prefix` | `/de`로 리디렉션 | `/de/kontakt` | `/kontakt`는 `/de/kontakt`로 리디렉션, `/en/contact`는 404 |
| `no_prefix` | `de` | `/kontakt` | 다른 도메인에 있는 로케일의 사용자 정의 경로는 404 |

`prefix`에서는 접두사 없는 URL은 리디렉션만 되므로 다른 도메인에서 오는 링크가 접두사를 유지합니다. `no_prefix`에서는 다른 도메인으로의 링크가 해당 호스트의 기본 로케일에 도달합니다: URL로 두 번째 로케일을 지정할 수 없기 때문입니다.

알아 두어야 할 사항:

- **프록시 뒤에서는** 호스트를 `Host`에서 가져옵니다. 프록시가 공개 호스트를 대신 `X-Forwarded-Host`에 넣는다면 [`trustForwardedHost`](/ko/api/module-options#trustforwardedhost)를 설정하되, 프록시가 해당 헤더를 덮어쓰는 경우에만 설정하세요. 둘 다 보내지 않는 프록시는 도메인 빌드를 제공할 수 없습니다. [프록시 또는 CDN 뒤에서](/ko/guide/deployment#behind-a-proxy-or-cdn)를 참고하세요.
- **`app.baseURL`**도 `baseUrl`에 포함되어야 합니다: `app.baseURL: '/shop'`과 함께 `baseUrl: 'https://example.de/shop'`.
- **호스트는 정확히 일치해야 합니다.** `www.example.de`는 다른 호스트입니다: 엣지에서 리디렉션하거나 로케일에 해당 `baseUrl`을 설정하세요. 로케일당 호스트는 하나뿐입니다.
- **캐시는 호스트를 키로 사용해야 합니다.** CDN은 보통 그렇게 합니다. Nitro의 라우트 캐시는 경로를 키로 사용하므로, 도메인 빌드에서 모듈은 모든 `swr` 및 `cache` 규칙의 `cache.varies`에 `host`를 추가하고, `trustForwardedHost`가 설정된 경우 `x-forwarded-host`도 추가합니다. `cache: false`인 규칙은 작성된 그대로 유지됩니다. `isr`은 플랫폼의 캐시이므로 호스트를 키로 사용하는지 확인하세요.
- **두 호스트 기본값의 사용자 정의 경로는 충돌해서는 안 됩니다.** 접두사 없는 레코드는 하나의 라우터를 공유하므로, `/x`가 `example.de`에서는 한 페이지이고 `example.com`에서는 다른 페이지일 수 없습니다.
- **사전 렌더링된 페이지:** `nuxt build`에서 `prerender: true` 라우트 규칙은 호스트 없이 한 번만 렌더링되며, 그 파일이 모든 도메인에 응답합니다. 도메인마다 다른 페이지는 서버에 맡기거나 [도메인별로 generate](/ko/guide/deployment#static-site-(nuxi-generate))하세요.
- **`noPrefixRedirect`**는 모든 호스트에서 호스트와 방문자의 로케일을 따릅니다.
- **`hashMode`:** 위와 같이 호스트가 렌더링을 선택하며, 다른 도메인으로의 링크는 라우트를 해시에 담습니다(`https://example.com/#/contact`).
- **`ssr: false`:** 브라우저가 `location.host`에서 도메인을 읽으므로 서버가 없는 호스트도 해석됩니다.
- **[런타임 재정의](/ko/guide/runtime-overrides)**가 먼저 적용됩니다. 런타임 `disabledLocales`는 모든 호스트에 적용되지만 한 가지 예외가 있습니다: `prefix_except_default`와 `prefix_and_default`에서는 호스트의 기본값이 접두사 없는 레코드이므로 해당 호스트에서 활성 상태로 유지됩니다. `prefix`와 `no_prefix`에서는 호스트가 제공하는 다음 로케일로 넘어갑니다. 런타임 `defaultLocale`은 알 수 없는 호스트에만 적용됩니다.

[정적 사이트](/ko/guide/deployment#static-site-(nuxi-generate))의 경우 도메인마다 한 번씩 generate하세요.

### 도메인당 하나의 앱 {#one-app-per-domain}

도메인마다 다른 페이지나 모듈이 필요할 때는 공유 레이어와 도메인마다 작은 앱 하나를 두는 방식도 여전히 동작합니다. 각 앱은 같은 `locales` 목록 위에 자체 `defaultLocale`을 설정합니다. 위와 마찬가지로 다른 도메인의 로케일은 해당 앱에서 404입니다.

### 코드에서 로케일 선택하기 {#choosing-the-locale-in-code}

SEO 태그에 요청 자체의 오리진을 사용하여 모든 도메인에 응답하는 단일 인스턴스에 대해서는 [SEO](/ko/guide/seo#set-the-public-origin)를 참고하세요. 코드에서 호스트를 기반으로 로케일을 선택하려면 [사용자 정의 로케일 감지](/ko/guide/custom-auto-detect)를 참고하세요.
