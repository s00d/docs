### 설명 {#description}

`untestutils/perf`를 통해 하나의 공유 사전 프로필에서 **순수 Nuxt**, **i18n-micro**, **`@nuxtjs/i18n`**을 비교합니다.

초점: 빌드 시간, 최대 RSS, 배포 가능한 **코드 vs 번역(asset) vs 전체**, 그리고 부하(Artillery).

### 방법론 참고 사항 {#methodology-notes}

- 지표는 **픽스처당 연속 3회 실행의 평균**입니다(교차 실행 아님).
- **아티팩트**: 강제 `nuxi build` 후의 Nitro node-server `.output/server/index.mjs`. `nuxt-i18n-micro`는 **빌드된 모듈 dist**입니다(`dev:prepare` jiti 스텁이 아님). [벤치마크 방법론](https://s00d.github.io/nuxt-i18n-micro/contributing/performance-methodology)을 참고하세요.
- **번역** = `bundle.asset`(로케일 JSON, `chunks/raw/`, `isTranslationFile`로 일치하는 로케일 청크).
- **코드**는 소스 맵(`*.map`)을 제외합니다. 픽스처가 저장소에서 모듈을 링크하므로 Nitro는 모듈에 대해서는 전체 맵을 작성하고 npm 의존성에 대해서는 작성하지 않습니다.
- **plain-nuxt**는 같은 양의 리프를 정적 JSON으로 제공합니다. 부하 상황에서 I/O 부담이 크며, "i18n 오버헤드"가 아닙니다.
- 부하 프로필 `--load full`: 워밍업 6s@6 + 메인 60s@60, 상한 없음(기존 방식).
- 쿨다운 `--cool fast`(방법론 문서 참고).
- 각 `runs` 빌드는 **강제**됩니다(웜 캐시로 빌드 시간이 0이 되지 않음).
- 표의 Artillery **오류율**은 부하 지표의 HTTP 상태 오류입니다. 차트는 `vusers.failed`(포화 상태에서의 클라이언트 타임아웃)도 표시하며, HTTP 오류율이 0%여도 이 값은 높을 수 있습니다.

## 참고 사항 {#notes}

- 공유 프로필: 4개 로케일 × 2개 페이지 × 약 16.8k index 리프.
- 부하: 프로그래밍 방식 Artillery만 사용 — 워밍업 **6s@6** + 메인 **60s@60**, VU 상한 없음(기존 YAML 방법론). 경로는 런타임 프로필에서 가져옵니다 — `scripts/src/perf/load.ts`를 참고하세요.
- 쿨다운: 빌드 후 2초, 실행 간 3초, 픽스처 간 5초. 빌드는 매 실행마다 강제되므로 평균이 캐시 적중으로 희석되지 않습니다.
- 일상적인 재실행: `pnpm test:performance`(`--load short --cool fast`).
- 이 페이지 재생성: `pnpm -C scripts cli performance --load full --only all --runs 3`.
- 플래그: `--locales N --keys K --only all|micro|i18n|plain --runs N --skip-load --cool fast|strict`.
