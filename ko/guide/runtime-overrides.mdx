---
title: "런타임 재정의"
description: "환경 변수나 runtimeConfig를 사용해 하나의 빌드의 인스턴스마다 기본 로케일, 폴백 로케일 또는 비활성화된 로케일을 변경합니다."
---

런타임 재정의를 사용하면 하나의 빌드 결과물을 다시 빌드하지 않고도 환경이나 테넌트마다 다른 로케일 설정으로 실행할 수 있습니다. 기본 로케일, 폴백 로케일, 그리고 비활성화할 로케일을 변경할 수 있습니다. 라우팅, 리디렉션, 렌더링, 서버 헬퍼는 재정의된 값을 사용하며, 서버 렌더링된 페이지의 브라우저도 마찬가지입니다.

## 환경 변수로 재정의 설정하기 {#set-overrides-with-environment-variables}

```bash
NUXT_I18N_DEFAULT_LOCALE=de \
NUXT_I18N_FALLBACK_LOCALE=en \
NUXT_I18N_DISABLED_LOCALES=fr,it \
node .output/server/index.mjs
```

| 변수 | 별칭 |
| --- | --- |
| `NUXT_I18N_DEFAULT_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE` |
| `NUXT_I18N_FALLBACK_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE` |
| `NUXT_I18N_DISABLED_LOCALES` (쉼표로 구분) | `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES` |

서버는 시작 시 이 값들을 한 번 읽습니다. 변경 사항을 적용하려면 재시작하세요. 서버 렌더링된 페이지에서 브라우저는 서버로부터 해석된 값을 받습니다. `ssr: false`에서는 서버 렌더링이 없고 브라우저에는 환경이 없습니다: 이 경우 `runtimeConfig.public.i18nRuntime`만 적용되며, 브라우저는 아래의 경고를 기록합니다.

## runtimeConfig에서 재정의 설정하기 {#set-overrides-in-runtimeconfig}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

`runtimeConfig.public.i18nRuntime`에 설정된 값은 같은 필드의 `NUXT_I18N_*` 변수보다 우선합니다.

빌드 시점의 `DEFAULT_LOCALE` 변수와 혼동하지 마세요. 이 변수는 빌드 중에 `defaultLocale`을 대체하며 런타임 지원이 필요하지 않습니다.

## 변경할 수 있는 것과 없는 것 {#what-can-and-cannot-change}

| 설정 | 런타임에서 |
| --- | --- |
| `defaultLocale` | `prefix`와 `no_prefix`에서는 가능. `prefix_except_default`와 `prefix_and_default`에서는 빌드 시 고정되며(해당 페이지가 접두사 없는 라우트이므로), 재정의는 경고와 함께 무시됩니다. |
| `fallbackLocale` | 가능. |
| `disabledLocales` | 빌드 시 비활성화된 로케일에 추가되며, 다시 활성화하지는 않습니다. `prefix_except_default` / `prefix_and_default`에서는 빌드 기본값을 비활성화할 수 없습니다. |
| `strategy` | 불가. 런타임 전략은 경고와 함께 무시됩니다. 전략마다 하나의 결과물을 빌드하세요. |

잘못된 값은 절대 앱을 망가뜨리지 않습니다. 각 경우는 서버 프로세스당 한 번 경고를 기록합니다:

- 모든 로케일을 비활성화하는 것은 무시됩니다;
- 활성화되지 않은 `defaultLocale`은 첫 번째 활성화된 로케일로 대체됩니다;
- 활성화되지 않은 `fallbackLocale`은 빌드 값이 활성화되어 있으면 그 값을 유지하고, 그렇지 않으면 폴백이 없습니다.

## 실제 적용되는 구성 읽기 {#read-the-effective-config}

```vue
<script setup lang="ts">
const { $getI18nConfig } = useNuxtApp()
const config = $getI18nConfig() // build config with overrides applied
</script>
```

읽기 전용으로 취급하세요: 서버에서는 모든 요청이 공유하며 개발 환경에서는 동결되어 있습니다. 브라우저의 사본은 동결되어 있지 않습니다. `#build/i18n.strategy.mjs`에서 구성을 가져오면 재정의가 적용되지 않은 빌드 값을 얻습니다.

## 비활성화된 로케일과 정적 파일 {#disabled-locales-and-static-files}

런타임에 비활성화된 로케일은 해당 라우트와 페이로드 라우트에서 404로 응답하지만, 페이로드 파일은 여전히 `.output/public/_locales/`에 있으며 정적 파일 서버는 이를 반환합니다. 이 파일들에 접근할 수 없어야 한다면 빌드 시 `disabled: true`로 로케일을 비활성화하세요.
