---
title: "현지화된 경로"
description: "localeRoutes 또는 globalLocaleRoutes로 동적 매개변수와 로케일별 슬러그를 포함하여 페이지에 로케일마다 다른 URL을 부여합니다."
---

기본적으로 모든 로케일은 같은 경로에서 페이지를 제공합니다: `/en/about`, `/de/about`. 현지화된 경로를 사용하면 페이지 파일은 그대로 두고 각 로케일이 `/de/ueber-uns`처럼 자체 단어를 사용할 수 있습니다. 페이지 안에서 `$defineI18nRoute`로 설정하거나, 여러 페이지를 한 번에 `nuxt.config.ts`에서 설정합니다.

## 페이지에서 {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

`prefix_except_default`와 `defaultLocale: 'en'`을 사용하면 페이지는 `/about`, `/de/ueber-uns`, `/fr/a-propos`에서 응답합니다. 항목이 없는 로케일은 기본 경로를 유지합니다. 경로는 로케일 코드 없이 작성하세요: 접두사는 [전략](/ko/guide/strategy)이 추가하며, 로케일 코드로 시작하는 경로는 경고를 기록합니다. 이 호출이 받는 다른 옵션은 [페이지 설정](/ko/guide/per-component-translations)에 있습니다.

## nuxt.config에서 {#in-nuxt-config}

[`globalLocaleRoutes`](/ko/api/module-options#globallocaleroutes)는 어떤 페이지에 대해서든 같은 작업을 하며, 페이지의 경로(또는 앞에 슬래시 없이 작성한 경우 라우트 이름)를 키로 사용합니다:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

페이지가 `localeRoutes`를 설정하고 `globalLocaleRoutes`에 같은 키가 있으면 설정 파일의 항목이 우선합니다.

## 동적 매개변수 {#dynamic-params}

매개변수는 Nuxt의 어떤 형식으로든 작성할 수 있습니다: `[id]`, `[[page]]`, `[...slug]`, 또는 `:id()`. 매개변수 이름은 페이지 파일과 일치해야 합니다.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

중첩된 페이지는 절대 자식 경로(`/ueber-uns/team`) 또는 부모의 현지화된 경로에 대한 상대 경로(`team`)를 사용합니다.

## 현지화된 페이지로 링크하기 {#linking-to-localized-pages}

라우트 이름을 전달하든 일반 경로를 전달하든, 링크는 대상 로케일의 현지화된 경로로 해석됩니다:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

라우트 이름은 `definePageMeta({ name })`으로 직접 설정하지 않는 한 파일 경로에서 만들어집니다(`pages/about/team.vue`는 `about-team`).

## 로케일별 슬러그 {#per-locale-slugs}

슬러그 자체가 로케일마다 다른 경우(`/our-products/red-shoe`와 `/de/unsere-produkte/roter-schuh`), 데이터가 로드되면 `$setI18nRouteParams`로 언어 전환기에 사용할 매개변수를 알려 주세요:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

그러면 `$switchLocalePath('de')`와 `<i18n-switcher>`가 `/de/unsere-produkte/roter-schuh`로 링크합니다. 키는 로케일 코드이고, 값은 (페이지 파일에서와 같은) 이름별 매개변수입니다.

레이아웃의 전환기는 페이지의 비동기 setup이 여기에 도달하기 전에 렌더링되므로, 렌더링이 끝나면 모듈이 `app.vue`와 페이지에 있는 것을 포함해 `<i18n-switcher>`의 링크를 다시 작성합니다. 그러면 서버 HTML, JavaScript가 없는 방문자, 첫 번째 클라이언트 렌더링이 일치합니다. 이를 위해 SSR 중에 매개변수를 설정하세요: `lazy` 또는 `server: false`를 사용하면 링크는 하이드레이션 이후에만 바뀝니다. Nuxt의 SSR 스트리밍은 매개변수가 알려지기 전에 HTML을 보내므로, 이 경우 첫 HTML의 링크는 URL 자체의 매개변수를 유지합니다.

전환기 자체의 링크만 다시 작성됩니다. 직접 작성한 `$switchLocalePath` 링크는 매개변수가 설정된 후에 렌더링되어야 하므로, 매개변수를 설정하는 페이지에, 그것도 `await` 이후에 두세요. 레이아웃에서는 먼저 렌더링됩니다: 서버 HTML이 URL의 매개변수를 유지하고, 하이드레이션 시 불일치 경고가 발생합니다. 그곳에서는 `<i18n-switcher>`를 사용하고, 모양은 슬롯과 `custom*Style` props로 조정하세요.

매개변수는 이를 설정한 페이지에 속합니다:

- 다른 경로로의 내비게이션이 확정되면 제거되므로, 각 페이지가 자체 매개변수를 설정합니다. 취소된 내비게이션은 매개변수를 그대로 둡니다.
- 나중에 `useAsyncData` 핸들러에서 호출하더라도 `$setI18nRouteParams`는 `setup`에서 `useNuxtApp()` 또는 `useI18n()`으로부터 가져오세요. 그곳에서 가져온 함수는 자신의 페이지를 알고 있어서, 방문자가 이미 떠났다면 늦은 호출은 아무 일도 하지 않습니다.
- `keepalive`를 사용하면 방문자가 돌아올 때 페이지가 설정했던 매개변수를 다시 받습니다. `useI18nHead`도 마찬가지입니다.

## pages:extend에서 추가한 라우트 {#routes-added-in-pagesextend}

`pages:extend` 훅에서 추가한 라우트에는 `$defineI18nRoute`를 읽을 페이지 파일이 없으며, 여러 라우트가 하나의 래퍼 컴포넌트를 공유하는 경우가 많습니다. `name` 없이 추가된 라우트는 Nuxt가 해당 경로에 부여할 이름(`/a/:id()`는 `a-id`)을 받으므로 언어 링크가 도달할 수 있습니다. 단, 다른 라우트가 이미 그 이름을 가지고 있다면 명시적인 `name`을 지정하세요. 목록 하나를 유지하고 `@i18n-micro/utils/split-locale-routes`의 `splitLocaleRoutes`로 페이지와 라우트 이름을 키로 하는 `globalLocaleRoutes`로 나누세요(패키지를 의존성에 추가하세요):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

현지화된 경로를 `route.meta`에 넣지 마세요: 클라이언트 라우트 테이블에 포함되어 배포됩니다.
