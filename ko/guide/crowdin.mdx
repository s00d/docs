[Crowdin](https://crowdin.com/)은 번역 플랫폼입니다: 기본 로케일의 파일을 업로드하면 번역가가 Crowdin에서 작업하고, 다른 로케일을 다시 다운로드합니다. 모듈은 일반 JSON 파일을 읽으므로, Crowdin CLI에는 `locales/`와 `locales/pages/`를 올바르게 매핑하는 `crowdin.yml`만 있으면 됩니다. 모듈 설정은 변경할 필요가 없습니다.

## crowdin.yml 설정 {#configure-crowdin-yml}

```yml
# crowdin.yml
project_id_env: CROWDIN_PROJECT_ID
api_token_env: CROWDIN_PERSONAL_TOKEN
base_path: ./locales
preserve_hierarchy: true

files:
  - source: /en.json
    translation: /%two_letters_code%.json
  - source: /pages/**/en.json
    translation: /pages/**/%two_letters_code%.json
```

- `en`은 기본 로케일이며, 그 파일들이 소스입니다.
- `project_id_env` / `api_token_env`는 환경 변수에서 ID와 토큰을 읽으므로 비밀 값이 커밋되지 않습니다.
- `preserve_hierarchy: true`는 `pages/<page>/` 폴더를 그대로 유지합니다.
- 번역된 파일 이름은 `nuxt.config.ts`의 로케일 `code`와 같아야 합니다. `%two_letters_code%`는 `de` 같은 코드에 맞습니다. `pt-BR` 같은 코드에는 `%locale%`를 사용하거나, `languages_mapping`으로 Crowdin의 코드를 여러분의 코드에 매핑하세요.

## 업로드와 다운로드 {#upload-and-download}

```bash
npm install -g @crowdin/cli

export CROWDIN_PROJECT_ID=123456
export CROWDIN_PERSONAL_TOKEN=...   # from Crowdin account settings

crowdin upload sources   # push locales/en.json and locales/pages/**/en.json
crowdin download         # write locales/de.json, locales/pages/**/de.json, ...
```

파일을 최신 상태로 유지하려면 CI에서 두 명령을 모두 실행하세요. 다운로드된 파일은 직접 편집한 파일처럼 저장소에 들어가며, 다음 빌드나 개발 서버 리로드 때 반영됩니다.

## 업로드하기 전에 {#before-uploading}

번역가가 사용되지 않는 키를 작업하지 않도록 먼저 소스를 정리하세요: [`i18n-micro clean`](/ko/api/cli#clean)은 사용되지 않는 키를 제거하고, [`i18n-micro check`](/ko/api/cli#check)는 다운로드 후 누락된 부분을 보고합니다. CLI에는 자체 Crowdin 통합 기능이 없습니다: 이 페이지에서 설명하는 방법이 지원되는 방식입니다.
