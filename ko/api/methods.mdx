---

모듈은 런타임 헬퍼를 Nuxt 앱에 주입합니다: `$t`, `$tc`, `$localePath`, `$switchLocale` 등. 이 페이지에서 헬퍼의 시그니처와 동작을 찾아보세요. 시그니처와 설명은 `src/runtime/plugins/01.plugin.ts`의 `PluginsInjections` 및 `NuxtAppOnlyInjections` 인터페이스에서 가져옵니다.

## 접근 방법 {#access}

| 위치 | 방법 |
| --- | --- |
| 템플릿 | `{{ $t('title') }}` — 모든 헬퍼, `$` 포함 |
| `<script setup>` | `const { t, localePath } = useI18n()` — `PluginsInjections`의 모든 헬퍼, `$` 포함 및 미포함 |
| 플러그인, 미들웨어, `<script setup>` | `const { $t, $defineI18nRoute } = useNuxtApp()` — 전부, `$` 포함만 |

`$defineI18nRoute`는 `useNuxtApp()`에서만 타입이 지정됩니다. [`useI18n`](/ko/composables/useI18n)을 참고하세요.

```vue
<script setup lang="ts">
const { t, localePath } = useI18n()
</script>

<template>
  <NuxtLink :to="localePath('/about')">{{ t('nav.about') }}</NuxtLink>
</template>
```

## 로케일 {#locale}

### `$getLocale` {#$getlocale}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric) => string
```

활성 로케일의 코드. 라우트를 전달하면 해당 라우트가 속한 로케일을 읽습니다.

```ts
$getLocale() // 'de' on /de/about
```

### `$getLocaleName` {#$getlocalename}

```ts
() => string | null
```

구성에 있는 활성 로케일의 `displayName`, 없으면 `null`.

### `$getLocales` {#$getlocales}

```ts
() => Locale[]
```

메타데이터를 포함한 구성된 모든 로케일.

로케일 객체의 사용자 정의 속성은 작성한 그대로 반환됩니다. `Locale`의 [모듈 확장](/ko/api/module-options#locales)으로 타입을 지정하세요.

### `$defaultLocale` {#$defaultlocale}

```ts
() => string | undefined
```

구성된 기본 로케일의 코드.

### `$getI18nConfig` {#$geti18nconfig}

```ts
() => ResolvedI18nConfig
```

런타임이 보는 해석된 모듈 구성.

값에는 [런타임 재정의](/ko/guide/runtime-overrides)(`defaultLocale`, `fallbackLocale`, 비활성화된 로케일)가 포함됩니다.

```ts
const { strategy, localeCookie } = useNuxtApp().$getI18nConfig()
```

## 번역 {#translation}

### `$t` {#$t}

```ts
TranslationFn<CleanTranslation>
```

키를 번역하고 `params`를 보간합니다. 키가 없으면 `defaultValue`를 반환하고,
기본값이 없으면 키 자체를 반환합니다.

```ts
// { "welcome": "Welcome, {name}!" }
$t('welcome', { name: 'Ada' }) // 'Welcome, Ada!'
$t('missing.key', {}, 'Fallback') // 'Fallback'
```

중첩 객체를 가리키는 키는 문자열이 아닌 해당 객체를 반환합니다. 템플릿에서는 `[object Object]`로 렌더링되므로 리프 키를 사용하세요.

### `$ts` {#$ts}

```ts
TranslationFn<string>
```

`$t`와 같지만 항상 문자열을 반환합니다: 값이 `toString()`을 거치므로 중첩
객체는 `'[object Object]'`가 됩니다. 키가 리프를 가리키도록 하세요.

### `$_t` {#$_t}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<CleanTranslation>
```

현재 페이지 밖에서 번역하기 위해 `$t`를 특정 라우트에 바인딩합니다. 예를 들어 다른 라우트로의
링크를 렌더링하는 레이아웃에서 사용합니다.

```ts
const route = useRoute()
const t = useNuxtApp().$_t(route)
t('page.title')
```

### `$_ts` {#$_ts}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<string>
```

`$ts`를 특정 라우트에 바인딩합니다. `$_t`를 참고하세요.

### `$tc` {#$tc}

```ts
(key: TranslationKey, params: number | Params, defaultValue?: string) => string
```

복수형 처리와 함께 번역합니다. `params`는 개수 자체이거나 `count`를 포함하는
객체일 수 있습니다.

형태는 `|`로 구분합니다. 내장 규칙에서는 음이 아닌 정수 개수 `n`이 형태 `n`을 선택하며, 마지막 형태로 제한됩니다. 음수, 소수 또는 `NaN` 개수는 마지막 형태를 사용합니다. `{count}`와 다른 params는 선택된 형태에 보간됩니다.

복수형이 개수를 따르지 않는 언어의 경우 템플릿을 `=0 `으로 시작하세요. 그러면 첫 번째 형태는 0용이 되고, 나머지는 [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) 카테고리를 `zero, one, two, few, many, other` 순서로 따릅니다:

```json
{
  "apples": "=0 no apples | one apple | {count} apples",
  "files": "=0 no files | {count} one | {count} few | {count} many"
}
```

```ts
$tc('apples', 0) // 'no apples'
$tc('apples', 1) // 'one apple'
$tc('apples', 7) // '7 apples'

// In `uk` (categories `one, few, many, other`) the forms after the zero form follow those categories:
$tc('files', 21) // '21 one'
$tc('files', 22) // '22 few'
$tc('files', 25) // '25 many'
$tc('files', 2.5) // '2.5 many': no form for `other`, so the last one
```

- `=0 `은 값의 맨 처음에 공백과 함께 있을 때만 인정됩니다. `$t`는 이를 텍스트로 표시합니다: 복수형 전용입니다.
- 자체 형태가 없는 카테고리는 마지막 형태를 사용합니다. 음수나 소수 개수도 마지막 형태를 사용합니다.
- 모든 로케일에서 동작합니다: 영어에서 `=0 none | one | {count} many`.
- 카테고리는 로케일의 `iso`에서, 없으면 코드에서 결정됩니다. `Intl`이 모르는 코드는 인덱스 규칙으로 폴백하며 마커는 여전히 제거되므로, 결과가 실행 환경에 따라 달라지지 않습니다.
- `<i18n-t :plural>`도 같은 규칙을 따릅니다. 사용자 정의 [`plural`](/ko/api/module-options#plural) 또는 `customPluralRule`은 마커를 포함한 원시 값을 받아 스스로 결정합니다. `plural`이 `null`을 반환하면 호출이 마커를 반영하는 내장 규칙으로 넘어갑니다.

마커가 없으면 템플릿은 인덱스 규칙을 따르지만, 한 가지로만 해석되는 예외가 있습니다: 자리 표시자가 없는 0 형태 다음에 카테고리당 하나의 형태가 오고, 여러 개수가 공유하는 각 형태에 `{count}`가 있는 경우입니다(`uk`에서 `no files | {count} one | {count} few | {count} many`).

자체 규칙을 사용하려면 [`plural`](/ko/api/module-options#plural)을 설정하세요.

```ts
// { "apples": "no apples | one apple | {count} apples" }
$tc('apples', 0) // 'no apples'
$tc('apples', 10) // '10 apples'
$tc('cart', { count: 2, name: 'Ada' }) // count and params in one object
```

세 번째 인수는 params가 아니라 `defaultValue`입니다.

### `$has` {#$has}

```ts
(key: string) => boolean
```

키가 활성 로케일에서 해석되는지 여부. 원시 키를 렌더링하는 대신 선택적 문구에 따라
분기할 때 사용하세요. `$t`와 마찬가지로, 같은 로케일 내 페이지 전환 중에는 떠나는
페이지의 키도 볼 수 있습니다.

```ts
if ($has('promo.banner')) show.value = true
```

## 포맷팅 {#formatting}

### `$tn` {#$tn}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

활성 로케일에서 `Intl.NumberFormat`으로 숫자를 포맷합니다. 키는 구성에서 이름 있는
포맷을 선택합니다.

이름 있는 포맷은 [`numberFormats`](/ko/api/module-options#numberformats)에서 가져옵니다.

```ts
$tn(1234.5, { style: 'currency', currency: 'EUR' }) // '1.234,50 €' in de
$tn(1000, 'currency') // named format
$tn(1000, 'currency', 'de') // named format in another locale
```

### `$td` {#$td}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

활성 로케일에서 `Intl.DateTimeFormat`으로 날짜를 포맷합니다. 키는 구성에서 이름 있는
포맷을 선택합니다.

이름 있는 포맷은 [`datetimeFormats`](/ko/api/module-options#datetimeformats)에서 가져옵니다.

```ts
$td(new Date(), { dateStyle: 'long' })
$td(post.createdAt, 'short')
```

### `$tdr` {#$tdr}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

`Intl.RelativeTimeFormat`으로 날짜를 상대 시간("3일 전")으로 포맷합니다.

```ts
$tdr(Date.now() - 5 * 60_000) // '5 minutes ago' in en
```

## 전환과 링크 {#switching-and-links}

### `$switchLocale` {#$switchlocale}

```ts
(locale: string) => Promise<boolean>
```

현재 페이지의 다른 로케일 버전으로 이동합니다. `no_prefix`와 해시 모드에서는 이동하기 전에
로케일의 번역을 로드하며, `no_prefix`에서는 라우트가 제자리에서 교체됩니다(새 히스토리
항목 없음). 알 수 없는 로케일은 무시됩니다.
호출은 비동기입니다: 이동 후에 코드를 실행하려면 `await`하세요. 로케일의 사전이 활성화되면
`true`로, 그렇지 않으면 `false`로 resolve됩니다: 청크 로드에 실패했거나(현재 사전이
유지되며, 다시 호출하여 재시도할 수 있습니다) 더 최근의 전환이 우선한 경우입니다.

```ts
await $switchLocale('de')
```

### `$switchLocalePath` {#$switchlocalepath}

```ts
(locale: string) => string
```

이동하지 않고 현재 페이지의 다른 로케일 경로를 반환합니다.

```vue
<NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
```

### `$switchLocaleRoute` {#$switchlocaleroute}

```ts
(locale: string) => RouteLocationRaw
```

이동하지 않고 현재 페이지의 다른 로케일 라우트 객체를 반환하며, 자체 `baseUrl`을 가진 로케일의
경우 URL 문자열을 반환합니다. `trailingSlash`에서는 객체가 규칙을 따르는 `path`와 `fullPath`를
가지며, `query`와 `hash`는 그대로이고, `router.push`나 링크가 이를 유지합니다.

### `$switchRoute` {#$switchroute}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => Promise<void>
```

활성 로케일을 유지하거나 `toLocale`로 전환하면서 다른 라우트로 이동합니다. `$switchLocale`처럼
비동기입니다.

```ts
$switchRoute('/about') // active locale
$switchRoute({ name: 'about' }, 'de') // switch to de
```

### `$localePath` {#$localepath}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => string
```

주어진 로케일 또는 활성 로케일로 경로를 해석합니다. `http(s):`, `mailto:`, `tel:` 스킴을
가진 문자열은 그대로 반환됩니다: 사용자 입력을 검증 없이 링크 대상으로 전달하지 마세요.

문자열 경로는 그것이 표시하는 페이지로 해석되므로, 로케일의 사용자 정의 경로도 적용됩니다.

```ts
$localePath('/about') // '/about' in en, '/de/ueber-uns' in de with localeRoutes
$localePath({ name: 'about' }, 'fr') // '/fr/about'
```

### `$localeRoute` {#$localeroute}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => RouteLocationResolved
```

주어진 로케일 또는 활성 로케일로 라우트를 해석합니다. 일반 객체이므로 상태에 보관해도 안전합니다. param에
이스케이프가 필요하면 `path`, `fullPath`, `query`, `hash`는 있지만 `name`이나 `params`는 없습니다: 경로가 라우터에
인코딩된 URL을 제공합니다. 다른 도메인의 로케일에서는 `path`와 `fullPath`가 절대 경로이며 라우터는 이를 받을 수 없으므로,
그런 링크는 `<i18n-link>` 또는 `$localePath`를 사용하세요.

### `$getRouteName` {#$getroutename}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric, locale?: string) => string
```

로케일 접두사를 제거한 라우트 이름 — 번역의 키가 되는 이름.

```ts
$getRouteName() // 'about' on /de/about
```

## 페이지 구성 {#page-config}

### `$defineI18nRoute` {#$definei18nroute}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

컴포넌트 내부에서 페이지별 로케일 구성과 번역을 등록합니다.
활성 로케일에 병합되며 로케일이 변경되면 다시 적용됩니다.

페이지의 `<script setup>`에서 호출하며, 항상 `useNuxtApp()`에서 구조 분해하세요. 빌드는 호출에서 `locales`, `localeRoutes`, `disableMeta`를 읽으며, 런타임에는 `locales`만 의미가 있습니다(인라인 번역은 활성 로케일에 병합됩니다). 전체 규칙: [페이지 구성](/ko/guide/per-component-translations).

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: { en: '/about', de: '/ueber-uns' },
})
</script>
```

### `$setI18nRouteParams` {#$seti18nrouteparams}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

현재 라우트에 로케일별 params를 설정하여, 동적 세그먼트가 언어마다 다를 수 있게 합니다.
SSR 중 head가 렌더링되기 전에 호출하세요.

다른 경로로의 이동이 확정되면 params가 지워지며, 라우트 이름이 유지되는 `/news/1`에서 `/news/4`로의 이동도 포함됩니다. 자세한 내용: [현지화된 경로](/ko/guide/custom-locale-routes).

```ts
$setI18nRouteParams({
  en: { slug: 'my-post' },
  de: { slug: 'mein-beitrag' },
})
```

## 런타임 번역 {#runtime-translations}

### `$mergeTranslations` {#$mergetranslations}

```ts
(newTranslations: Translations) => void
```

런타임에 번역을 활성 로케일에 병합하여, 로드된 내용을 재정의합니다.

활성 로케일의 현재 페이지 청크에 깊은 병합을 수행하며, 언급되지 않은 키는 유지됩니다.

```ts
$mergeTranslations({ banner: { title: 'Sale' } })
```

### `$setTranslation` {#$settranslation}

```ts
(key: string, value: unknown) => void
```

활성 사전에서 `key`의 값을 교체합니다. 이것은 병합이 아닌 교체입니다 —
기존 형제 키가 유지되어야 하면 `$mergeTranslations`를 사용하세요.

```ts
$setTranslation('banner', { title: 'Sale' }) // drops other keys under banner
$setTranslation('banner.title', 'Sale') // dotted path
```

### `$loadPageTranslations` {#$loadpagetranslations}

```ts
(locale: string, routeName: string, translations: Translations) => Promise<void>
```

빌드 시 키를 알 수 없는 콘텐츠를 위해 런타임에 페이지의 번역을 로드합니다.

메모리의 `(locale, routeName)` 청크에 병합되며, 해당 청크가 활성 상태이면 화면이 업데이트됩니다. 여기서는 페이로드를 가져오지 않습니다: 아직 로드되지 않은 페이지의 경우 번역이 대기하며, 파일이 로드되면 그 위에 유지됩니다.

```ts
await $loadPageTranslations('en', 'about', { title: 'About us' })
```

### `$resolveTranslations` {#$resolvetranslations}

```ts
() => Translations
```

활성 로케일과 라우트에 대해 현재 메모리에 있는 모든 번역을 트리로 반환합니다.
`$t()`가 지금 해석할 수 있는 내용의 읽기 전용 뷰입니다.

결과는 읽기 전용으로 취급하세요.

### `$setMissingHandler` {#$setmissinghandler}

```ts
(handler: MissingHandler | null) => void
```

해석되지 않은 모든 키에 대해 호출되는 콜백을 설치합니다. 제거하려면 `null`을 전달하세요.

핸들러는 개발 경고 대신 실행됩니다.

```ts
$setMissingHandler((locale, key, routeName) => {
  console.error(`[i18n] missing ${key} in ${locale} (${routeName})`)
})
```

### `$clearCache` {#$clearcache}

```ts
() => void
```

캐시된 모든 번역 청크를 삭제하고 현재 페이지의 사전을 다시 로드합니다. 새 번역이
도착할 때까지 페이지는 현재 번역을 계속 표시합니다. 개발 HMR은 번역 파일이 변경될
때마다 이를 호출합니다.

```ts
const { clearCache } = useI18n()
clearCache()
```

다시 로드에 실패하면 현재 사전이 유지됩니다.
