# 모듈 옵션 레퍼런스

`nuxt-i18n-micro`가 받아들이는 모든 옵션은
[`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts)의
`ModuleOptions` 인터페이스에서 빌드 타임에 읽어들입니다.
여기의 어느 것도 손으로 작성되지 않았으므로 코드에 뒤처질 수 없습니다. 유형, 기본값,
설명은 선언 자체에서 가져옵니다.

이러한 옵션들이 함께 *무엇을 의미하는지* — 어떤 조합이 의미가 있는지, 전략을 바꿀 때
무엇이 변하는지, 예제와 함께 자세히 알고 싶다면 [설정](/guides/configuration)을 읽어보세요.
이 페이지는 전체 목록이고, 그 페이지는 설명입니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

중첩된 옵션은 점 표기 경로 아래에 표시되므로, `translationPayloads.mode`는
`translationPayloads` 객체 내부의 `mode` 키입니다.

## 로케일 및 라우팅

어떤 언어가 존재하고 URL에 어떻게 나타나는지.

| 옵션 | 유형 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | 지원되는 로케일 목록. 각 항목은 로케일 코드와 선택적 메타데이터(ISO, 방향, 표시 이름 등)를 정의합니다. |
| `strategy` | `Strategies` | `'prefix_except_default'` | 로케일 접두사를 위한 URL 라우팅 전략. - `'no_prefix'` — URL에 로케일 없음; 로케일은 쿠키에 저장됨. - `'prefix_except_default'` — 기본 로케일을 제외한 모든 로케일에 접두사. - `'prefix'` — 기본 로케일을 포함하여 항상 접두사. - `'prefix_and_default'` — `prefix`와 유사하지만 기본 로케일에도 접두사 없이 접근 가능. |
| `defaultLocale` | `string` | `'en'` | URL이나 사용자 기본 설정으로 로케일을 결정할 수 없을 때 사용할 로케일. `fallbackLocale`이 설정되지 않은 경우 누락된 번역의 대체 로케일로도 사용됩니다. |
| `localeCookie` | `string \| null` | `null` | 세션 간 사용자의 로케일 기본 설정을 유지하기 위한 쿠키 이름. 쿠키 기반 지속성을 비활성화하려면 `null`로 설정하세요. 제공되지 않으면 `no_prefix` 전략의 경우 자동으로 `'user-locale'`로 설정됩니다. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | 전역 라우트 수준 로케일 설정. 컴포넌트를 수정하지 않고도 특정 페이지의 로케일 라우트를 제한하거나 사용자 정의할 수 있습니다. - `false` — 라우트를 지역화에서 제외. - `Record<LocaleCode, string>` — 로케일별 사용자 정의 경로. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | URL 세그먼트에서 로케일 코드를 매칭하기 위한 사용자 정의 정규 표현식(또는 그 문자열 소스). `locales`에 정의된 모든 로케일 코드는 이 패턴과 일치해야 하며, 그렇지 않으면 경고가 발생합니다. |
| `noPrefixRedirect` | `boolean` | `false` | `no_prefix` 전략의 경우: 로케일 접두사가 있는 URL(예: `/en/about`)에서 접두사 없는 버전(`/about`)으로의 리디렉션을 활성화합니다. |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | i18n 처리에서 완전히 제외할 URL 패턴(문자열 또는 RegExp). 일치하는 라우트는 로케일 접두사, 리디렉션 또는 번역 로딩을 받지 않습니다. Nuxt 내부 경로(`/__nuxt_error` 등)는 항상 자동으로 제외됩니다. |
| `routeLocales` | `Record<string, string[]>` | — | `defineI18nRoute()` 호출에서 추출된 라우트별 로케일 제한. 라우트 경로(예: `'/about'`)를 허용된 로케일 코드 배열에 매핑합니다. 나열되지 않은 라우트에는 제한이 없습니다(모든 로케일 허용). |

## 번역

번역 파일이 있는 위치와 키가 해결되는 방식.

| 옵션 | 유형 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | 번역 JSON 파일을 포함하는 디렉터리의 경로(프로젝트 루트 기준). |
| `disableWatcher` | `boolean` | `false` | 개발 모드에서 누락된 번역 파일을 자동 생성하는 파일 워처를 비활성화합니다. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | 라우트 이름을 다른 라우트 이름에 매핑하여 동일한 번역 파일을 공유합니다. 예를 들어, `\{ 'about-us': 'about' \}`는 `about-us` 페이지가 자체 번역 대신 `about` 페이지의 번역을 사용하도록 함을 의미합니다. |
| `plural` | `PluralFunc` | `built-in pluralization (form index by count)` | 사용자 정의 복수형 함수. `(key, count, params, locale, getter)`를 받으며 선택된 복수형을 문자열로 반환해야 하며, 내장된 `defaultPlural` 로직으로 대체하려면 `null`/`undefined`를 반환합니다(일부 로케일만 재정의 가능). Nuxt 모듈의 경우 이 함수는 `.toString()`으로 직렬화되어 `.nuxt/i18n.plural.mjs`에 저장됩니다. 자체 완결적이어야 합니다(임포트나 외부 스코프 없음). 파일 경로 문자열은 **지원되지 않습니다**. |
| `disablePageLocales` | `boolean` | `false` | 페이지별 번역 파일 비활성화. `true`이면 전역 번역(`\{locale\}.json`)만 로드되며, 페이지별 파일(`pages/\{page\}/\{locale\}.json`)은 생성되거나 로드되지 않습니다. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | 전역 대체 로케일 코드. 활성 로케일에 번역 키가 없으면 모듈은 키 자체를 반환하기 전에 이 로케일에서 조회합니다. |

## 페이로드와 캐싱

번역이 브라우저에 도달하는 방식. [성능](/guides/performance)에서 이러한 옵션이 런타임에 무엇을 변경하는지 설명합니다.

| 옵션 | 유형 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Nitro 전역 미들웨어(서버 전용, 비공개 설정)에서 인덱스 페이지 번역을 미리 로드합니다. |
| `apiBaseUrl` | `string` | `'_locales'` | 번역 API 라우트의 기본 URL 경로 세그먼트(SSR/SSG 데이터 페칭에서 사용). `NUXT_I18N_APP_BASE_URL` 환경 변수로도 설정할 수 있습니다. |
| `apiBaseClientHost` | `string` | `undefined` | 클라이언트 사이드 번역 페치 요청에 사용되는 호스트를 재정의합니다. 클라이언트가 Nuxt가 보는 것과 다른 호스트 이름을 통해 서버에 도달할 때 유용합니다. `NUXT_I18N_APP_BASE_CLIENT_HOST` 환경 변수로도 설정할 수 있습니다. |
| `apiBaseServerHost` | `string` | `undefined` | 서버 사이드 번역 페치 요청에 사용되는 호스트를 재정의합니다. 서버가 내부 호스트 이름을 통해 자기 자신에 도달하는 컨테이너/마이크로서비스 설정에서 유용합니다. `NUXT_I18N_APP_BASE_SERVER_HOST` 환경 변수로도 설정할 수 있습니다. |
| `translationPayloads` | `TranslationPayloadOptions` | — | 번역 페이로드가 방출되는 방식을 제어합니다 (Node: `public/<apiBaseUrl>`; Edge: Nitro `serverAssets`). - **Node**: `serverAssets`는 `public/` 아래에서 `readFile`을 통한 로컬 SSR을 의미합니다 (Rollup `raw:` 없음). - **Edge**: `serverAssets`는 Nitro `serverAssets`(`assets:i18n`)를 등록합니다. 공용 복사본을 강제하지는 않습니다. 일반적인 올인원 설정에는 기본값을 유지하세요. 대규모 Edge 카탈로그에는 `mode: 'source'`를 선호하세요. CDN 기반 배포의 경우 로컬 출력을 비활성화하고 `apiBaseClientHost` / `apiBaseServerHost`를 설정하세요. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | 번역 페이로드 전략. - `premerged`: 빌드 타임 `\{page\}/\{locale\}/data.json` 매트릭스(기본값) - `source`: 런타임에 병합되는 컴팩트 소스 파일(Edge/대규모 카탈로그에 선호) |
| `translationPayloads.serverAssets` | `boolean` | `true` | 로컬 SSR 페이로드: Node는 `public/<apiBaseUrl>`을 읽습니다(공용 복사본 강제); Edge는 Nitro `serverAssets`를 통해 임베드합니다. - **Node**: Nitro `serverAssets` 없음(Rollup `raw:` 회피). SSR은 `public/<apiBaseUrl\|publicDir>`을 `\{page\}/\{locale\}/data.json`으로 읽으며, 이것이 `true`이면 `publicAssets`가 false여도 공용 복사본이 강제됩니다. - **Edge** (`nitro.node === false`): `mode`와 동일한 레이아웃의 Nitro `serverAssets`(`assets:i18n`). 공용 복사본을 강제하지 **않습니다** — CDN의 경우 `publicAssets: true`를 설정하세요. |
| `translationPayloads.serverHandler` | `boolean` | `true` | `/\{apiBaseUrl\}/:page/:locale/data.json`에 내장 서버 라우트를 등록합니다. 번역 페이로드가 외부 호스트/CDN에서 제공되는 경우 비활성화하세요. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | 페이로드를 Nitro 공용 출력으로 복사합니다. Premerged → `apiBaseUrl` 아래에 `\{page\}/\{locale\}/data.json`; source → 컴팩트 트리. Node에서 `serverAssets`가 공용 복사본을 강제할 때 이 트리는 SSR 소스이기도 합니다. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Nitro-prerender `/\{apiBaseUrl\}/.../data.json`을 옵트인합니다. premerged `publicAssets`가 이미 해당 파일을 작성했다면 일반적으로 중복됩니다. |
| `translationPayloads.publicDir` | `string` | — | Nitro 공용 루트에 상대적인 공용 출력 폴더. 기본값은 `apiBaseUrl`(`_locales`)입니다. 이렇게 하면 정적 파일이 클라이언트 페치 URL(`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`)과 일치합니다. |
| `translationPayloads.warnFileCount` | `number` | `500` | 생성된 페이로드 파일 개수가 이 임계값을 초과할 때 빌드 중 경고합니다. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | 생성된 페이로드 총 크기가 이 임계값(바이트)을 초과할 때 빌드 중 경고합니다. |

## SEO

각 로케일 페이지에 대해 생성되는 메타 태그.

| 옵션 | 유형 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | SEO 메타 태그(`hreflang`, `canonical`, `og:url`, `og:locale`)를 자동으로 생성합니다. |
| `metaBaseUrl` | `string` | `undefined` | SEO 메타 태그(canonical, og:url, hreflang)를 위한 기본 URL. - 구체적인 URL 문자열(예: `'https://example.com'`) — 그대로 사용됨(최우선 순위). - `undefined` — `nuxt-site-config`가 있으면 `site.url`로 대체되고, 그렇지 않으면 현재 요청 원본(서버에서는 `useRequestURL().origin`, 클라이언트에서는 `window.location.origin`)으로 대체됩니다. |
| `metaTrustForwardedHost` | `boolean` | `true` | 메타 태그의 기본 URL을 해결할 때 `X-Forwarded-Host` 헤더를 신뢰합니다. 이 헤더를 실제 클라이언트 대면 호스트 이름으로 설정하는 리버스 프록시(nginx, Cloudflare, AWS ALB 등) 뒤에서 앱을 실행할 때 활성화하세요. |
| `metaTrustForwardedProto` | `boolean` | `true` | 메타 태그의 프로토콜을 해결할 때 `X-Forwarded-Proto` 헤더를 신뢰합니다. 앱 자체는 HTTP를 수신하지만 canonical URL이 `https://`를 사용하도록 TLS 종단 프록시 뒤에서 앱을 실행할 때 활성화하세요. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | canonical 및 `og:url` 메타 태그에 보존되는 쿼리 매개변수 이름 목록. 이 목록에 없는 매개변수는 canonical URL에서 제거됩니다. |

## 감지와 리디렉션

로케일을 선택하지 않은 방문자에게 로케일을 선택하는 방식.

| 옵션 | 유형 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | 자동 로케일 기반 리디렉션 활성화. `true`이면 방문자는 첫 방문 시 선호하는 로케일(쿠키, `Accept-Language` 헤더 또는 기본값에서 감지)로 리디렉션됩니다. |
| `autoDetectLanguage` | `boolean` | `true` | `Accept-Language` HTTP 헤더에서 사용자의 선호 언어를 자동으로 감지합니다. 감지가 발생하는 시기를 결정하기 위해 `autoDetectPath`와 함께 사용됩니다. |
| `autoDetectPath` | `string` | `'/'` | 쿠키 / Accept-Language 기본 설정 리디렉션이 실행될 수 있는 위치(`redirects`가 활성화된 경우). - `'/'` — `/`만(기본 로케일의 딥 링크는 접근 가능한 상태로 유지; 기본값) - `'no_prefix'` — 로케일 접두사가 없는 경로만 - `'*'` — 모든 경로, 명시적인 로케일 접두사를 다시 작성하는 것을 포함(예: 쿠키가 `de`를 선호할 때 `/fr/about` → `/de/about`) - 다른 문자열 — 정확한 경로 일치(예: `'/welcome'`) 접두사 전략 정리(예: `prefix_except_default`에서 `/en` → `/`)는 게이팅되지 않습니다. |

## 등록

끄기 가능한 모듈의 부분들.

| 옵션 | 유형 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | 페이지별 `defineI18nRoute()` 호출을 가능하게 하는 `defineI18nRoute()` 매크로 플러그인을 등록합니다. |
| `plugin` | `boolean` | `true` | `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` 및 기타 런타임 헬퍼를 제공하는 핵심 i18n 플러그인을 등록합니다. |
| `hooks` | `boolean` | `true` | `i18n:register`와 `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch` 앱 수준 훅을 제공하는 i18n 훅 플러그인을 등록합니다. |
| `components` | `boolean` | `true` | 내장 i18n 컴포넌트(`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`)를 등록합니다. 자동 컴포넌트 등록을 비활성화하려면 `false`로 설정하세요(예: 사용하지 않고 모듈 풋프린트를 줄이고 싶은 경우). |
| `types` | `boolean` | `true` | 기본 로케일 파일의 번역 키를 기반으로 `useI18n`, `$t` 및 관련 헬퍼에 대한 TypeScript 타입 선언을 생성합니다. |
| `debug` | `boolean` | `false` | 로케일 감지, 라우트 생성, 번역 로딩에 대한 자세한 디버그 로깅을 활성화합니다. |
