이 페이지에는 `nuxt.config`의 `i18n` 객체에 있는 모든 키가 나열되어 있습니다. 타입이나 기본값을 찾을 때는 표를, 예제와 주의 사항은 아래의 세부 정보를 참고하세요. 타입, 기본값, 설명은 [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts)의 `ModuleOptions` 인터페이스에서 생성됩니다.

```ts nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
    ],
    defaultLocale: 'en',
  },
})
```

중첩된 옵션은 점으로 구분된 경로로 표시됩니다. `translationPayloads.mode`는 `translationPayloads`의 `mode` 키입니다.

## 로케일 및 라우팅 {#locales-and-routing}

어떤 언어가 존재하며 URL에 어떻게 나타나는지.

| 옵션 | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | 지원되는 로케일 목록. 각 항목은 로케일 코드와 선택적 메타데이터(ISO, 방향, 표시 이름 등)를 정의합니다. |
| `strategy` | `Strategies` | `'prefix_except_default'` | 로케일 접두사에 대한 URL 라우팅 전략. - `'no_prefix'` — URL에 로케일이 없으며, 로케일은 쿠키에 저장됩니다. - `'prefix_except_default'` — 기본 로케일을 제외한 모든 로케일에 접두사를 붙입니다. - `'prefix'` — 기본 로케일을 포함하여 항상 접두사를 붙입니다. - `'prefix_and_default'` — `prefix`와 같지만, 기본 로케일은 접두사 없이도 접근할 수 있습니다. |
| `defaultLocale` | `string` | `'en'` | URL이나 사용자 선호도로 로케일을 결정할 수 없을 때 사용할 로케일. 번역 폴백이 아닙니다. 폴백에는 `fallbackLocale`을 설정하세요. |
| `localeCookie` | `string \| null` | `null` | 세션 간에 사용자의 로케일 선호도를 유지하기 위한 쿠키 이름. 쿠키 기반 유지를 비활성화하려면 `null`로 설정하세요. 지정하지 않으면 `no_prefix` 전략에서 자동으로 `'user-locale'`로 설정되며, `i18n` 설정 블록에 명시적으로 `null`을 지정하면 그 경우에도 꺼진 상태로 유지됩니다. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `{}` | 전역 라우트 수준 로케일 설정. 컴포넌트를 수정하지 않고 특정 페이지의 로케일 라우트를 제한하거나 사용자 정의할 수 있습니다. - `false` — 라우트를 현지화에서 제외합니다. - `Record<LocaleCode, string>` — 로케일별 사용자 정의 경로. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | URL 세그먼트에서 로케일 코드를 매칭하기 위한 사용자 정의 정규식(또는 그 문자열 소스). `locales`의 모든 로케일 코드는 플래그를 제외한 전체 패턴과 일치해야 하며, 그렇지 않으면 빌드가 실패합니다. |
| `noPrefixRedirect` | `boolean` | `false` | `no_prefix` 전략용: 기본 로케일에 페이지의 사용자 정의 경로(`localeRoutes` / `globalLocaleRoutes`)가 있으면, 페이지의 원래 경로를 방문자 로케일의 사용자 정의 경로로, 없으면 기본 로케일의 사용자 정의 경로로 리디렉션합니다(예: `/about` → `/about-us`). 자체 사용자 정의 경로가 없는 로케일은 원래 경로에 머무릅니다. 동적 세그먼트가 있는 페이지는 리디렉션되지 않습니다. |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | i18n 라우팅에서 제외할 경로: 문자열은 경로 접두사(`/admin`은 `/admin/x`를 포함) 또는 `*` / `?` glob이며, RegExp는 경로에 대해 테스트됩니다. 일치하는 페이지는 로케일 변형, 로케일 리디렉션이나 404가 없고 프리렌더에서 제외되지만, 번역과 함께 렌더링은 됩니다. `/api`, `/_nuxt`, `/__*`, 번역 라우트, 일반적인 정적 파일(sitemap, robots.txt, favicon, 확장자별 에셋)은 항상 제외됩니다. |
| `routeLocales` | `Record<string, string[]>` | — | 빌드 시 `$defineI18nRoute()` 호출에서 추출한 라우트별 로케일 제한. 라우트 경로(예: `'/about'`)를 허용된 로케일 코드 배열에 매핑합니다. 나열되지 않은 라우트에는 제한이 없습니다(모든 로케일 허용). |

## 번역 {#translations}

번역 파일이 어디에 있고 키가 어떻게 해석되는지.

| 옵션 | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | 번역 JSON 파일이 들어 있는 디렉터리 경로로, 프로젝트 루트 기준입니다. |
| `disableWatcher` | `boolean` | `false` | 개발 모드에서 누락된 번역 파일을 자동으로 생성하는 파일 감시자를 비활성화합니다. |
| `routesLocaleLinks` | `{ [key: string]: string }` | `{}` | 같은 번역 파일을 공유하도록 라우트 이름을 다른 라우트 이름에 매핑합니다. 예를 들어 `{ 'about-us': 'about' }`는 `about-us` 페이지가 자체 번역 대신 `about` 페이지의 번역을 사용한다는 뜻입니다. |
| `plural` | `PluralFunc` | ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)`` | 사용자 정의 복수형 함수. `(key, count, params, locale, getter)`를 받아 선택된 복수형을 문자열로 반환하거나, 내장 `defaultPlural` 로직으로 폴백하려면 `null`/`undefined`를 반환해야 합니다(따라서 일부 로케일만 재정의할 수 있습니다). Nuxt 모듈에서는 함수가 `.toString()`으로 `.nuxt/i18n.plural.mjs`에 직렬화되므로 자체 완결적이어야 합니다(import / 외부 스코프 없음). 파일 경로 문자열은 지원되지 **않습니다**. |
| `disablePageLocales` | `boolean` | `false` | 페이지별 번역 파일을 비활성화합니다. `true`이면 전역 번역(`{locale}.json`)만 로드되고, 페이지별 파일(`pages/{page}/{locale}.json`)은 생성되거나 로드되지 않습니다. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | 전역 폴백 로케일 코드. 어떤 로케일에서 누락된 키는 이 로케일에서 가져오며(각 페이로드를 빌드하거나 로드할 때 병합됨), 이 옵션이 없으면 누락된 키는 키 자체로 렌더링됩니다. |

## 페이로드 및 캐싱 {#payloads-and-caching}

번역이 브라우저에 도달하는 방식. 이 옵션들이 런타임에 무엇을 바꾸는지는 [성능](/ko/guide/performance)에서 설명합니다.

| 옵션 | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Nitro 전역 미들웨어에서 인덱스 페이지 번역을 미리 로드합니다(서버 전용, 비공개 설정). |
| `apiBaseUrl` | `string` | `'_locales'` | 번역 API 라우트의 기본 URL 경로 세그먼트(SSR/SSG 데이터 가져오기에 사용). `NUXT_I18N_APP_BASE_URL` 환경 변수로도 설정할 수 있습니다. |
| `apiBaseClientHost` | `string` | `undefined` | 클라이언트 측 번역 fetch 요청에 사용되는 호스트를 재정의합니다. 클라이언트가 Nuxt가 보는 것과 다른 호스트 이름으로 서버에 접근할 때 유용합니다. `NUXT_I18N_APP_BASE_CLIENT_HOST` 환경 변수로도 설정할 수 있습니다. |
| `apiBaseServerHost` | `string` | `undefined` | 서버 측 번역 fetch 요청에 사용되는 호스트를 재정의합니다. 서버가 내부 호스트 이름으로 자신에게 접근하는 컨테이너/마이크로서비스 구성에서 유용합니다. `NUXT_I18N_APP_BASE_SERVER_HOST` 환경 변수로도 설정할 수 있습니다. |
| `translationPayloads` | `TranslationPayloadOptions` | — | 번역 페이로드가 생성되는 방식을 제어합니다(Node 서버: `public/<apiBaseUrl>`, Edge / 함수 / 인라인: Nitro `serverAssets`). - **Node 서버**(`node-server`, `node-cluster`, 디스크 `serveStatic`): `serverAssets`는 `public/` 아래에서 `readFile`을 통한 로컬 SSR을 의미합니다(Rollup `raw:` 없음). - **Edge, 함수 프리셋, `serveStatic: "inline"`**(`vercel`, `netlify`, `aws-lambda`, winterjs, …): `public/`이 SSR에서 디스크로 사용할 수 없으므로 `serverAssets`는 Nitro `serverAssets`(`assets:i18n`)를 등록합니다. 공개 복사본을 강제하지 않으므로, CDN/정적 호스팅에는 `publicAssets: true`를 설정하세요. 일반적인 올인원 구성에서는 기본값을 유지하세요. 대규모 Edge 카탈로그에는 `mode: 'source'`를 권장합니다. CDN 기반 배포에서는 로컬 출력을 비활성화하고 `apiBaseClientHost` / `apiBaseServerHost`를 설정하세요. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | 번역 페이로드 전략. - `premerged`: 빌드 시점의 `{page}/{locale}/data.json` 매트릭스(기본값) - `source`: 런타임에 병합되는 압축된 소스 파일(Edge / 대규모 카탈로그에 권장) |
| `translationPayloads.serverAssets` | `boolean` | `true` | 로컬 SSR 페이로드: 디스크에서 `public/`을 제공하는 Node 서버는 해당 트리를 읽으며(공개 복사본 강제), Edge, 함수 프리셋, `serveStatic: "inline"`은 Nitro `serverAssets`를 통해 임베드합니다. - **Node 서버**(프리셋이 직접 `public/`을 제공, 예: `node-server`): Nitro `serverAssets` 없음(Rollup `raw:` 회피). SSR은 `public/<apiBaseUrl\|publicDir>`을 `{page}/{locale}/data.json` 형태로 읽으며, 이 값이 `true`이면 `publicAssets`가 false여도 공개 복사본이 강제됩니다. - **Edge, 함수 프리셋, 인라인**(`nitro.node === false`, `vercel` / `netlify` / `aws-lambda`처럼 디스크 `serveStatic`이 없거나 winterjs 같은 `serveStatic: "inline"`): `mode`와 동일한 레이아웃의 Nitro `serverAssets`(`assets:i18n`). 공개 복사본을 강제하지 **않으므로**, CDN/정적 호스팅에는 `publicAssets: true`를 설정하세요. |
| `translationPayloads.serverHandler` | `boolean` | `true` | `/{apiBaseUrl}/:page/:locale/data.json`에 내장 서버 라우트를 등록합니다. 번역 페이로드를 외부 호스트/CDN에서 제공할 때는 비활성화하세요. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | 페이로드를 Nitro 공개 출력에 복사합니다. premerged → `apiBaseUrl` 아래의 `{page}/{locale}/data.json`, source → 압축된 트리. SSR이 `public/`을 읽을 때(`node-server` 등)는 `serverAssets: true`도 이 복사를 강제합니다. Edge / 함수 / `serveStatic: "inline"` 프리셋에서는 이 값이 `true`일 때만 복사합니다(SSR은 Nitro 임베드 사용). |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | `/{apiBaseUrl}/.../data.json`의 Nitro 프리렌더를 선택적으로 활성화합니다. premerged `publicAssets`가 이미 해당 파일을 썼다면 대개 불필요합니다. |
| `translationPayloads.publicDir` | `string` | — | Nitro 공개 루트 기준의 공개 출력 폴더. 기본값은 `apiBaseUrl`(`_locales`)입니다. 따라서 정적 파일이 클라이언트 fetch URL(`/{apiBaseUrl}/{page}/{locale}/data.json`)과 일치합니다. |
| `translationPayloads.rootDelta` | `boolean` | `true` | 로케일마다 루트 파일 하나를 쓰고, 각 페이지 파일에는 그것과 다른 부분만 씁니다. 클라이언트와 SSR이 이를 병합하며, 파일을 읽는 곳 어디에서나 전체 청크도 여전히 동작합니다. `false`는 모든 페이지 파일에 전체 사전을 유지합니다. `premerged` 전용이며 `disablePageLocales`와 함께 쓰면 꺼집니다. |
| `translationPayloads.warnFileCount` | `number` | `500` | 생성된 페이로드 파일 수가 이 임계값을 넘으면 빌드 중에 경고합니다. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | 생성된 페이로드의 전체 크기가 이 임계값(바이트)을 넘으면 빌드 중에 경고합니다. |

## SEO {#seo}

현지화된 각 페이지에 대해 생성되는 메타 태그.

| 옵션 | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | SEO 메타 태그(`hreflang`, `canonical`, `og:url`, `og:locale`)를 자동으로 생성합니다. |
| `metaBaseUrl` | `string` | `undefined` | SEO 메타 태그(canonical, og:url, hreflang)의 기본 URL. - 구체적인 URL 문자열(예: `'https://example.com'`) — 그대로 사용됩니다(최우선). - `undefined` — `nuxt-site-config` 모듈이 있으면 그 모듈의 `site.url`로, 없으면 현재 요청의 origin(서버에서는 `useRequestURL().origin`, 클라이언트에서는 `window.location.origin`)으로 폴백합니다. |
| `metaTrustForwardedHost` | `boolean` | `true` | 메타 태그의 기본 URL을 결정할 때 `X-Forwarded-Host` 헤더를 신뢰합니다. 앱이 이 헤더를 실제 클라이언트용 호스트 이름으로 설정하는 리버스 프록시(nginx, Cloudflare, AWS ALB 등) 뒤에서 실행될 때 활성화하세요. |
| `metaTrustForwardedProto` | `boolean` | `true` | 메타 태그의 프로토콜을 결정할 때 `X-Forwarded-Proto` 헤더를 신뢰합니다. 앱 자체는 HTTP로 수신하더라도 canonical URL이 `https://`를 사용하도록, 앱이 TLS 종료 프록시 뒤에서 실행될 때 활성화하세요. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | canonical 및 `og:url` 메타 태그에서 유지되는 쿼리 매개변수 이름 목록. 이 목록에 없는 매개변수는 canonical URL에서 제거됩니다. |

## 감지 및 리디렉션 {#detection-and-redirects}

아직 로케일을 선택하지 않은 방문자를 위한 로케일 선택.

| 옵션 | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | 자동 로케일 리디렉션(서버 플러그인 및 클라이언트 라우트 미들웨어)을 활성화합니다. `true`이면 접두사 전략은 접두사가 없는 URL을 현지화된 형태로 리디렉션합니다. 로케일은 앱 상태, 쿠키 또는 `autoDetectPath`가 허용하는 경우 `Accept-Language`에서 오며, 그렇지 않으면 기본값입니다. `no_prefix`에서는 감지가 URL을 절대 바꾸지 않습니다(사용자 정의 경로는 `noPrefixRedirect` 참고). |
| `autoDetectLanguage` | `boolean` | `true` | `Accept-Language` HTTP 헤더에서 사용자의 선호 언어를 자동으로 감지합니다. `autoDetectPath`와 함께 사용하여 감지가 언제 일어날지 결정합니다. |
| `autoDetectPath` | `string` | `'/'` | 쿠키 / Accept-Language 선호도 리디렉션이 실행될 수 있는 위치(`redirects`가 활성화된 경우). - `'/'` — `/`만(기본 로케일의 딥 링크에 계속 접근 가능, 기본값) - `'no_prefix'` — 로케일 접두사가 없는 경로만 - `'*'` — 명시적 로케일 접두사의 재작성을 포함한 모든 경로(예: 쿠키가 `de`를 선호하면 `/fr/about` → `/de/about`) - 그 밖의 문자열 — 해당 경로, 후행 슬래시 무시(예: `'/welcome'`) `prefix`에서는 허용된 경로 밖의 접두사 없는 URL도 여전히 기본 로케일 형태로 리디렉션됩니다(`/about` → `/en/about`). `prefix_except_default`에서 접두사가 붙은 기본 로케일(`/en`)은 리디렉션이 아니라 404입니다. |

| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | 로케일별 이름 있는 날짜/시간 포맷(Vue I18n 호환 `datetimeFormats`). `$td(date, 'short')` 형태의 호출을 가능하게 합니다. |
| `httpCacheDuration` | `number` | `31536000` | `/{apiBaseUrl}/:page/:locale/data.json`의 HTTP `Cache-Control` max-age(초). `dateBuild`가 URL을 무효화(`?v=...`)하는 동안에만 완전히 적용되며, 이것이 기본값입니다. 이때 응답은 `private, max-age=…, immutable`이 됩니다. 브라우저는 이를 고정하고, 쿼리를 무시하는 CDN은 고정할 수 없습니다(`httpCacheControl: false`이면 `public`). - `dateBuild: 0`/`''` — URL이 고정되므로 이 기간은 적용되지 *않으며*, 응답은 대신 `public, max-age=0, must-revalidate`가 됩니다. 변하지 않는 URL에 긴 `max-age`를 주면 브라우저가 처음 본 페이로드에 고정됩니다. - `0` — `Cache-Control`을 전혀 설정하지 않습니다(로컬 디버깅에 유용). - 개발 모드(`import.meta.dev`)에서는 적용되지 않으므로 HMR이 브라우저 캐시와 충돌하지 않습니다. - Nitro를 통해 제공되는 응답에만 적용됩니다. `public/`으로 복사되어 호스팅 플랫폼이 제공하는 페이로드는 해당 플랫폼의 헤더를 따릅니다. 성능 가이드를 참고하세요. `@nuxtjs/i18n`의 실험적 `httpCacheDuration`(v10.2.0)에 해당하지만, Nitro `defineCachedEventHandler` maxAge가 아니라 명시적인 응답 헤더로 제공됩니다. |
| `httpCacheControl` | `string \| false` | `'public, max-age=60'` | 호스트나 경로 전체 규칙이 응답하는 페이로드 파일의 `Cache-Control`로, 이들은 `?v=`를 볼 수 없습니다. | `dateBuild` | `string \| number` | — | 번역 요청의 캐시 무효화(`?v=...`)에 사용되는 값. 지정하지 않으면 모듈은 번역 파일의 해시를 사용하므로 번역이 바뀔 때만 값이 바뀝니다(해시를 계산할 수 없으면 `Date.now()`). `0` 또는 `''`는 캐시 무효화를 끕니다. 직접 고정하려면 안정적인 값(git SHA, 빌드 번호)을 설정하세요. `NUXT_I18N_DATE_BUILD` 또는 `runtimeConfig.public.i18nRuntime.dateBuild`는 사전이 제자리에서 교체된 후 런타임에 이 값을 대체하므로, 다시 빌드하지 않고도 고정된 URL을 벗어납니다. |
| `experimental` | `Record<string, unknown>` | — | 실험적/불안정한 옵션을 위한 영역. 내용은 마이너 버전 사이에 예고 없이 변경되거나 제거될 수 있습니다. |

## 옵션 세부 정보 {#option-details}

표 이상으로 덧붙일 내용이 없는 옵션은 여기서 반복하지 않습니다.

### 로케일 및 URL {#locales-and-urls}

#### `locales` {#locales}

**타입** `Locale[]` · **기본값** `[]`

지원되는 로케일 목록.
각 항목은 로케일 코드와 선택적 메타데이터(ISO, 방향, 표시 이름 등)를 정의합니다.

각 항목은 `Locale` 객체입니다.

| 속성 | 타입 | 설명 |
| --- | --- | --- |
| `code` | `string` | **필수.** URL 세그먼트이자 파일 이름(`en`, `de-at`). |
| `iso` | `string` | `<html lang>`, `hreflang`, 복수형 및 `$tn` / `$td` / `$tdr`에 사용되는 BCP-47 태그(`en-US`). |
| `displayName` | `string` | `<i18n-switcher>`와 `$getLocaleName()`의 레이블. |
| `dir` | `'ltr' \| 'rtl' \| 'auto'` | `<html dir>`. 지정하지 않으면 알려진 RTL 언어는 `rtl`을 받고 다른 모든 로케일은 속성을 받지 않습니다. [SEO](/ko/guide/seo#text-direction)를 참고하세요. |
| `disabled` | `boolean` | 라우트, 페이로드, 전환에서 제외됩니다. 해당 접두사는 404이며, 이 로케일로의 링크는 현재 페이지에 머무릅니다. |
| `fallbackLocale` | `string` | 이 로케일의 폴백으로, 전역 `fallbackLocale`을 재정의합니다. |
| `seo` | `boolean` | `false`이면 로케일이 `hreflang`과 `og:locale:alternate`에서 제외됩니다. |
| `og` | `string` | `og:locale` 값(`ar_AE`). 기본값: 변환된 `iso`. |
| `baseUrl` | `string` | 로케일 고유의 도메인. 하나의 빌드가 이를 제공하며, 다른 도메인에서 이 도메인으로의 링크는 절대 경로가 됩니다. |
| `baseDefault` | `boolean` | `baseUrl`과 함께 사용: 해당 호스트의 기본 로케일로, 이 로케일로의 링크에 `/<code>` 접두사가 붙지 않습니다(`prefix`는 유지). |

그 밖의 속성은 유지되며 `$getLocales()`가 반환합니다. `Locale`을 확장하여 타입을 지정하세요.

```ts
// i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
  }
}
export {}
```

모듈이 `@i18n-micro/types`를 호이스팅하므로, 패키지를 설치하지 않아도 pnpm에서 동작합니다.

#### `defaultLocale` {#defaultlocale}

**타입** `string` · **기본값** `'en'`

URL이나 사용자 선호도로 로케일을 결정할 수 없을 때 사용할 로케일.
번역 폴백이 아닙니다. 폴백에는 `fallbackLocale`을 설정하세요.

#### `strategy` {#strategy}

**타입** `Strategies` · **기본값** `'prefix_except_default'`

로케일 접두사에 대한 URL 라우팅 전략.

- `'no_prefix'` — URL에 로케일이 없으며, 로케일은 쿠키에 저장됩니다.
- `'prefix_except_default'` — 기본 로케일을 제외한 모든 로케일에 접두사를 붙입니다.
- `'prefix'` — 기본 로케일을 포함하여 항상 접두사를 붙입니다.
- `'prefix_and_default'` — `prefix`와 같지만, 기본 로케일은 접두사 없이도 접근할 수 있습니다.

전략별 URL과 리디렉션: [라우팅 전략](/ko/guide/strategy).

#### `globalLocaleRoutes` {#globallocaleroutes}

**타입** `GlobalLocaleRoutes` · **기본값** `{}`

전역 라우트 수준 로케일 설정.
컴포넌트를 수정하지 않고 특정 페이지의 로케일 라우트를
제한하거나 사용자 정의할 수 있습니다.

- `false` — 라우트를 현지화에서 제외합니다.
- `Record<LocaleCode, string>` — 로케일별 사용자 정의 경로.

키는 라우트 이름 또는 경로입니다. 보통 [`$defineI18nRoute`](/ko/guide/per-component-translations)로 페이지별로 설정합니다.

```ts
globalLocaleRoutes: {
  about: { en: '/about-us', de: '/ueber-uns' },
  'admin-dashboard': false, // not localized
}
```

세부 사항, 동적 세그먼트, `pages:extend` 라우트: [현지화된 경로](/ko/guide/custom-locale-routes).

#### `routeLocales` {#routelocales}

**타입** `Record<string, string[]>` · **기본값** —

빌드 시 `$defineI18nRoute()` 호출에서 추출한 라우트별 로케일 제한.
라우트 경로(예: `'/about'`)를 허용된 로케일 코드 배열에 매핑합니다.
나열되지 않은 라우트에는 제한이 없습니다(모든 로케일 허용).

#### `routeDisableMeta` {#routedisablemeta}

**타입** `Record<string, boolean \| string[]>` · **기본값** —

라우트별 메타 태그 비활성화. 라우트 이름이나 경로를 `true`(모든 메타 비활성화) 또는

### 번역 {#translations}

#### `translationDir` {#translationdir}

**타입** `string` · **기본값** `'locales'`

#### `additionalTranslationDirs` {#additionaltranslationdirs}

**타입** `string[]` · **기본값** `[]`

**타입** `boolean` · **기본값** `false`

#### `fallbackLocale` {#fallbacklocale}

**타입** `string` · **기본값** `undefined (no fallback; returns the raw key)`

어떤 로케일에서 누락된 키는 이 로케일에서 가져오며(각 페이로드를 빌드하거나

#### `routesLocaleLinks` {#routeslocalelinks}

**타입** `{ [key: string]: string }` · **기본값** `{}`

같은 번역 파일을 공유하도록 라우트 이름을 다른 라우트 이름에 매핑합니다.
예를 들어 `{ 'about-us': 'about' }`는 `about-us` 페이지가 자체 번역 대신
`about` 페이지의 번역을 사용한다는 뜻입니다.

```ts
routesLocaleLinks: { 'products-id': 'products' },
```

#### `plural` {#plural}

**타입** `PluralFunc` · **기본값** ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)``

사용자 정의 복수형 함수.
`(key, count, params, locale, getter)`를 받아 선택된 복수형을 문자열로
반환하거나, 내장 `defaultPlural` 로직으로 폴백하려면 `null`/`undefined`를
반환해야 합니다(따라서 일부 로케일만 재정의할 수 있습니다).

Nuxt 모듈에서는 함수가 `.toString()`으로 `.nuxt/i18n.plural.mjs`에
직렬화되므로 자체 완결적이어야 합니다(import / 외부 스코프 없음).
파일 경로 문자열은 지원되지 **않습니다**.

내장 규칙과 그 `=0 ` 마커는 [`$tc`](/ko/api/methods#$tc)에 설명되어 있습니다. 여러분의 함수는 자신이 응답하는 경우에 한해 내장 규칙을 대체하며, 마커가 그대로 있는 원시 값을 받고, `null`을 반환하면 호출을 내장 규칙에 넘깁니다. 함수는 `(key, count, params, locale, getter)`를 받으며, `getter(key)`는 모든 형태를 담은 원시 문자열을 반환합니다. 자체 완결적인 `function` 또는 화살표 표현식으로 작성하세요(메서드 축약형, import, 외부 변수 없음).

```ts
plural: function (key, count, params, locale, getter) {
  if (!locale.startsWith('en')) return null // built-in rule for other locales
  const forms = String(getter(key) ?? '').split('|').map((form) => form.trim())
  const index = count === 0 ? 0 : count === 1 ? 1 : 2
  return (forms[Math.min(index, forms.length - 1)] ?? '').replace('{count}', String(count))
},
```

```json
{ "apples": "no apples | one apple | {count} apples" }
```

### 페이로드 및 캐싱 {#payloads-and-caching}

#### `translationPayloads` {#translationpayloads}

**타입** `TranslationPayloadOptions` · **기본값** —

번역 페이로드가 생성되는 방식을 제어합니다(Node 서버: `public/<apiBaseUrl>`, Edge / 함수 / 인라인: Nitro `serverAssets`).

- **Node 서버**(`node-server`, `node-cluster`, 디스크 `serveStatic`): `serverAssets`는 `public/` 아래에서 `readFile`을 통한 로컬 SSR을 의미합니다(Rollup `raw:` 없음).
- **Edge, 함수 프리셋, `serveStatic: "inline"`**(`vercel`, `netlify`, `aws-lambda`, winterjs, …): `public/`이 SSR에서 디스크로 사용할 수 없으므로
  `serverAssets`는 Nitro `serverAssets`(`assets:i18n`)를 등록합니다. 공개 복사본을 강제하지 않으므로, CDN/정적 호스팅에는 `publicAssets: true`를 설정하세요.

일반적인 올인원 구성에서는 기본값을 유지하세요. 대규모 Edge 카탈로그에는 `mode: 'source'`를 권장합니다.
CDN 기반 배포에서는 로컬 출력을 비활성화하고 `apiBaseClientHost` / `apiBaseServerHost`를 설정하세요.

하위 옵션은 [페이로드 및 캐싱](#payloads-and-caching) 표에 있습니다. Node, 서버리스, Edge, 정적 호스팅, CDN에 어떤 조합이 맞는지: [배포](/ko/guide/deployment).

#### `apiBaseUrl` {#apibaseurl}

**타입** `string` · **기본값** `'_locales'`

번역 API 라우트의 기본 URL 경로 세그먼트(SSR/SSG 데이터 가져오기에 사용).
`NUXT_I18N_APP_BASE_URL` 환경 변수로도 설정할 수 있습니다.

페이로드 URL은 `/{apiBaseUrl}/{page}/{locale}/data.json`입니다.

#### `apiBaseClientHost` {#apibaseclienthost}

**타입** `string` · **기본값** `undefined`

클라이언트 측 번역 fetch 요청에 사용되는 호스트를 재정의합니다.
클라이언트가 Nuxt가 보는 것과 다른 호스트 이름으로 서버에 접근할 때 유용합니다.
`NUXT_I18N_APP_BASE_CLIENT_HOST` 환경 변수로도 설정할 수 있습니다.

#### `apiBaseServerHost` {#apibaseserverhost}

**타입** `string` · **기본값** `undefined`

서버 측 번역 fetch 요청에 사용되는 호스트를 재정의합니다.
서버가 내부 호스트 이름으로 자신에게 접근하는 컨테이너/마이크로서비스 구성에서 유용합니다.
`NUXT_I18N_APP_BASE_SERVER_HOST` 환경 변수로도 설정할 수 있습니다.

호스트는 내장 라우트와 동일한 `/{apiBaseUrl}/{page}/{locale}/data.json` 응답을 제공해야 합니다.

#### `dateBuild` {#datebuild}

**타입** `string \| number` · **기본값** —

번역 요청의 캐시 무효화(`?v=...`)에 사용되는 값.

지정하지 않으면 모듈은 번역 파일의 해시를 사용하므로 번역이 바뀔 때만
값이 바뀝니다(해시를 계산할 수 없으면 `Date.now()`). `0` 또는 `''`는
캐시 무효화를 끕니다. 직접 고정하려면 안정적인 값(git SHA, 빌드 번호)을 설정하세요.
`NUXT_I18N_DATE_BUILD` 또는 `runtimeConfig.public.i18nRuntime.dateBuild`는 사전이 제자리에서
교체된 후 런타임에 이 값을 대체하므로, 다시 빌드하지 않고도 고정된 URL을 벗어납니다.

#### `httpCacheDuration` {#httpcacheduration}

**타입** `number` · **기본값** `31536000`

`/{apiBaseUrl}/:page/:locale/data.json`의 HTTP `Cache-Control` max-age(초).

`dateBuild`가 URL을 무효화(`?v=...`)하는 동안에만 완전히 적용되며, 이것이 기본값입니다.
이때 응답은 `private, max-age=…, immutable`이 됩니다. 브라우저는 이를 고정하고, 쿼리를 무시하는 CDN은 고정할 수 없습니다
(`httpCacheControl: false`이면 `public`).

- `dateBuild: 0`/`''` — URL이 고정되므로 이 기간은 적용되지 *않으며*,
  응답은 대신 `public, max-age=0, must-revalidate`가 됩니다. 변하지 않는 URL에
  긴 `max-age`를 주면 브라우저가 처음 본 페이로드에 고정됩니다.

- `0` — `Cache-Control`을 전혀 설정하지 않습니다(로컬 디버깅에 유용)
- 개발 모드(`import.meta.dev`)에서는 적용되지 않으므로 HMR이 브라우저 캐시와 충돌하지 않습니다
- Nitro를 통해 제공되는 응답에만 적용됩니다. `public/`으로 복사되어 호스팅 플랫폼이
  제공하는 페이로드는 해당 플랫폼의 헤더를 따릅니다. 성능 가이드를 참고하세요.

`@nuxtjs/i18n`의 실험적 `httpCacheDuration`(v10.2.0)에 해당하지만, Nitro
`defineCachedEventHandler` maxAge가 아니라 명시적인 응답 헤더로 제공됩니다.

#### `cacheMaxSize` {#cachemaxsize}

**타입** `number` · **기본값** `0`

메모리 내 번역 캐시의 최대 항목 수. fetch 및 서버 캐시는
가장 오래전에 사용된 항목을 제거하고, 브라우저의 사전 맵은 가장 오래된 항목을 제거합니다(FIFO).
`0`은 브라우저에서 제한이 없음을 의미하며, 이때 서버 캐시는 최대 1000개 항목을 유지하므로
임의로 만든 페이지 이름을 담은 요청 URL이 서버 메모리를 늘릴 수 없습니다.

#### `cacheTtl` {#cachettl}

**타입** `number` · **기본값** `0`

fetch 및 서버 번역 캐시의 유효 시간(초)으로, 항목이 저장된 시점부터
계산되므로(읽기로 연장되지 않음) `apiBaseServerHost`의 데이터가 최소한
그 주기로 새로 고쳐집니다. 브라우저의 활성 사전은 이 값으로 만료되지 않습니다. `0`은
항목이 만료되지 않음을 의미합니다.

두 옵션이 런타임에 바꾸는 것: [성능](/ko/guide/performance).

#### `serverTranslationPreload` {#servertranslationpreload}

**타입** `boolean` · **기본값** `false`

Nitro 전역 미들웨어에서 인덱스 페이지 번역을 미리 로드합니다(서버 전용, 비공개 설정).

### SEO {#seo}

#### `meta` {#meta}

**타입** `boolean` · **기본값** `true`

SEO 메타 태그(`hreflang`, `canonical`, `og:url`, `og:locale`)를 자동으로 생성합니다.

페이지별 재정의: [`useI18nHead`](/ko/composables/useI18nHead). 그 밖의 모든 것: [SEO](/ko/guide/seo).

#### `metaBaseUrl` {#metabaseurl}

**타입** `string` · **기본값** `undefined`

SEO 메타 태그(canonical, og:url, hreflang)의 기본 URL.

- 구체적인 URL 문자열(예: `'https://example.com'`) — 그대로 사용됩니다(최우선).
- `undefined` — `nuxt-site-config` 모듈이 있으면 그 모듈의 `site.url`로,
  없으면 현재 요청의 origin으로 폴백합니다
  (서버에서는 `useRequestURL().origin`, 클라이언트에서는 `window.location.origin`).

#### `metaTrustForwardedHost` {#metatrustforwardedhost}

**타입** `boolean` · **기본값** `true`

메타 태그의 기본 URL을 결정할 때 `X-Forwarded-Host` 헤더를 신뢰합니다.
앱이 이 헤더를 실제 클라이언트용 호스트 이름으로 설정하는
리버스 프록시(nginx, Cloudflare, AWS ALB 등) 뒤에서 실행될 때 활성화하세요.

`metaBaseUrl`과 `site.url`이 모두 설정되지 않은 경우에만 읽힙니다. 헤더를 덮어쓰는 프록시 없이 앱에 접근할 수 있다면 `false`로 설정하세요. 그렇지 않으면 클라이언트가 canonical URL의 호스트를 선택할 수 있습니다.

#### `metaTrustForwardedProto` {#metatrustforwardedproto}

**타입** `boolean` · **기본값** `true`

메타 태그의 프로토콜을 결정할 때 `X-Forwarded-Proto` 헤더를 신뢰합니다.
앱 자체는 HTTP로 수신하더라도 canonical URL이 `https://`를 사용하도록,
앱이 TLS 종료 프록시 뒤에서 실행될 때 활성화하세요.

`metaTrustForwardedHost`와 같은 범위입니다.

#### `trustForwardedHost` {#trustforwardedhost}

**타입** `boolean` · **기본값** `false`

요청의 도메인(`locales[].baseUrl`)을 `Host` 대신 `X-Forwarded-Host`로
선택합니다. 해당 헤더를 덮어쓰는 프록시 뒤에서만 활성화하세요.

`metaTrustForwardedHost`와는 별개이며 기본적으로 꺼져 있습니다. 여기서는 헤더가 태그의 origin뿐 아니라 다른 도메인의 로케일을 선택하게 됩니다. [레이어 및 도메인](/ko/guide/layers#multiple-domains)을 참고하세요.

#### `hreflangBaseLanguage` {#hreflangbaselanguage}

**타입** `boolean` · **기본값** `false`

각 로케일의 `iso`에서 파생된 언어만의 `hreflang`도 출력합니다
(예: `es-ES` → `es`도 출력). `locales`의 첫 번째 지역 로케일이
해당 언어의 단독 태그를 차지합니다. 라우팅 `code`는 절대 사용되지 않으며 `iso || code`만 사용됩니다.

#### `canonicalQueryWhitelist` {#canonicalquerywhitelist}

**타입** `string[]` · **기본값** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

canonical 및 `og:url` 메타 태그에서 유지되는 쿼리 매개변수 이름 목록.
이 목록에 없는 매개변수는 canonical URL에서 제거됩니다.

### 감지 및 리디렉션 {#detection-and-redirects}

이 옵션들이 적용되는 규칙: [로케일 감지](/ko/guide/locale-detection).

#### `redirects` {#redirects}

**타입** `boolean` · **기본값** `true`

자동 로케일 리디렉션(서버 플러그인 및 클라이언트 라우트 미들웨어)을 활성화합니다.
`true`이면 접두사 전략은 접두사가 없는 URL을 현지화된 형태로 리디렉션합니다. 로케일은
앱 상태, 쿠키 또는 `autoDetectPath`가 허용하는 경우 `Accept-Language`에서 오며, 그렇지 않으면
기본값입니다. `no_prefix`에서는 감지가 URL을 절대 바꾸지 않습니다(사용자 정의 경로는 `noPrefixRedirect` 참고).

`false`이면 클라이언트 리디렉션 미들웨어가 등록되지 않습니다. 서버 플러그인은 여전히 잘못된 로케일 URL에 404를 반환하고, 접두사가 붙은 URL에 대해 쿠키를 기록합니다.

#### `autoDetectLanguage` {#autodetectlanguage}

**타입** `boolean` · **기본값** `true`

`Accept-Language` HTTP 헤더에서 사용자의 선호 언어를 자동으로 감지합니다.
`autoDetectPath`와 함께 사용하여 감지가 언제 일어날지 결정합니다.

#### `autoDetectPath` {#autodetectpath}

**타입** `string` · **기본값** `'/'`

쿠키 / Accept-Language 선호도 리디렉션이 실행될 수 있는 위치(`redirects`가 활성화된 경우).

- `'/'` — `/`만(기본 로케일의 딥 링크에 계속 접근 가능, 기본값)
- `'no_prefix'` — 로케일 접두사가 없는 경로만
- `'*'` — 명시적 로케일 접두사의 재작성을 포함한 모든 경로
  (예: 쿠키가 `de`를 선호하면 `/fr/about` → `/de/about`)

- 그 밖의 문자열 — 해당 경로, 후행 슬래시 무시(예: `'/welcome'`)

`prefix`에서는 허용된 경로 밖의 접두사 없는 URL도 여전히 기본 로케일
형태로 리디렉션됩니다(`/about` → `/en/about`). `prefix_except_default`에서
접두사가 붙은 기본 로케일(`/en`)은 리디렉션이 아니라 404입니다.

#### `localeCookie` {#localecookie}

**타입** `string \| null` · **기본값** `null`

세션 간에 사용자의 로케일 선호도를 유지하기 위한 쿠키 이름.
쿠키 기반 유지를 비활성화하려면 `null`로 설정하세요.
지정하지 않으면 `no_prefix` 전략에서 자동으로 `'user-locale'`로 설정되며, `i18n` 설정 블록에
명시적으로 `null`을 지정하면 그 경우에도 꺼진 상태로 유지됩니다.

쿠키가 없어도 `Accept-Language`가 여전히 리디렉션을 결정합니다. 쿠키는 방문 간에 선택을 기억합니다.

#### `noPrefixRedirect` {#noprefixredirect}

**타입** `boolean` · **기본값** `false`

`no_prefix` 전략용: 기본 로케일에 페이지의 사용자 정의 경로
(`localeRoutes` / `globalLocaleRoutes`)가 있으면, 페이지의 원래 경로를 방문자 로케일의
사용자 정의 경로로, 없으면 기본 로케일의 사용자 정의 경로로 리디렉션합니다(예: `/about` → `/about-us`).
자체 사용자 정의 경로가 없는 로케일은 원래 경로에 머무릅니다. 동적
세그먼트가 있는 페이지는 리디렉션되지 않습니다.

### 등록 및 개발 {#registration-and-development}

#### `plugin` {#plugin}

**타입** `boolean` · **기본값** `true`

`$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` 및 기타 런타임 헬퍼를
제공하는 핵심 i18n 플러그인을 등록합니다.

#### `define` {#define}

**타입** `boolean` · **기본값** `true`

런타임에 `$defineI18nRoute()`를 제공합니다. 빌드는 어느 경우든 페이지의
`$defineI18nRoute()` 호출을 읽습니다.

#### `hooks` {#hooks}

**타입** `boolean` · **기본값** `true`

플러그인이 번역을 추가할 수 있도록 로드 시와 탐색 시 `i18n:register` 앱 훅을 호출합니다.

[훅](/ko/api/events)을 참고하세요.

#### `components` {#components}

**타입** `boolean` · **기본값** `true`

내장 i18n 컴포넌트(`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`)를 등록합니다.
자동 컴포넌트 등록을 비활성화하려면 `false`로 설정하세요(예: 사용하지 않으며
모듈 크기를 줄이고 싶은 경우).

#### `types` {#types}

**타입** `boolean` · **기본값** `true`

기본 로케일 파일의 번역 키를 기반으로 `useI18n`, `$t` 및 관련 헬퍼의
TypeScript 타입 선언을 생성합니다.

[`@i18n-micro/types-generator`](/ko/integrations/types-generator) 패키지와는 별개입니다.

#### `hmr` {#hmr}

**타입** `boolean` · **기본값** `true`

개발 중 번역 파일에 대한 Hot Module Replacement를 활성화합니다.
`true`이면 JSON 번역 파일을 변경할 때 전체 페이지 새로 고침 없이
자동으로 다시 로드됩니다.

#### `debug` {#debug}

**타입** `boolean` · **기본값** `false`

로케일 감지, 라우트 생성, 번역 로딩에 대한 상세 디버그 로깅을 활성화합니다.

#### `vueDevtools` {#vuedevtools}

**타입** `boolean` · **기본값** `true`

개발 모드에서 Vue DevTools 인스펙터와 타임라인(브라우저 확장 프로그램)을 등록합니다.
Nuxt DevTools 사용자 정의 탭과는 별개입니다.

#### `experimental` {#experimental}

**타입** `Record<string, unknown>` · **기본값** —

실험적/불안정한 옵션을 위한 영역.
내용은 마이너 버전 사이에 예고 없이 변경되거나 제거될 수 있습니다.
