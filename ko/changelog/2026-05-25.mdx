**날짜**: 2026-05-25

**버전**: `v3.19.0`

![v3.19.0 release](/images/3.19.0.png)

이번 릴리스는 일반적인 앱의 공개 모듈 API를 변경하지 않으면서 **내부 유틸리티 모듈화**, **간결한 서버리스 페이로드 모드** 추가, 그리고 Nuxt, Node, Astro, DevTools 전반에서의 **공유 로직 재사용**에 중점을 둡니다.

## 새로운 기능 {#what’s-new}

### `@i18n-micro/utils` — 프레임워크에 구애받지 않는 유틸리티 {#@i18n-micro/utils-—-framework-agnostic-utilities}

이전에 `src/runtime/utils/`와 `src/module.ts`에 흩어져 있던 공유 로직이 이제 **세분화된 서브패스 임포트**(거대한 배럴 없음, 트리 셰이킹 친화적)를 제공하는 전용 워크스페이스 패키지에 있습니다:

- **빌드** — `preMergeLocales`, `buildTranslationSourceLayers` (`@i18n-micro/utils/build`)
- **페이로드** — `translationPayloads` 해석, URL 생성, fetch 헬퍼, 통계 (`payload-config`, `payload-url`, `payload-fetch`, `payload-stats`)
- **Source 모드** — 폴백 체인, 소스 파일 경로, 런타임 병합 (`merge-source`, `source-loader`)
- **런타임 헬퍼** — 로케일 해석, 쿠키, Accept-Language 파싱, 라우트/메타 헬퍼 (`resolve-locale`, `accept-language`, `cookie`, `route`, `route-pattern`, `runtime-config`)
- **공유 FS 경로** — 번역 파일 분류, 중첩 페이지 경로 (`parse-path`)

Nuxt 모듈은 `src/runtime/`에 얇은 연결 코드만 유지하고 필요한 서브패스만 임포트합니다.

### `@i18n-micro/hmr` — 개발용 번역 핫 리로드 {#@i18n-micro/hmr-—-dev-translation-hot-reload}

개발용 HMR이 `@i18n-micro/hmr`로 분리되었습니다:

- **`watcher`** — 개발 환경에서의 파일 변경 처리, 캐시 무효화, source/premerged 병합
- **`generate-plugin`** — 클라이언트 측 HMR 플러그인 생성
- **`cache-keys`** — 서버/스토리지 캐시용 공유 `Symbol.for` 키

`translationPayloads.mode: 'premerged'`와 `'source'` 모두에서 동작합니다.

### `translationPayloads.mode: 'source'` — 간결한 서버리스 배포 {#translationpayloads-mode-‘source’-—-compact-serverless-deployments}

서버리스 플랫폼(Cloudflare Workers 등)에서 대규모 로케일 매트릭스를 위한 새로운 페이로드 모드:

```typescript
export default defineNuxtConfig({
  i18n: {
    translationPayloads: {
      mode: 'source',
    },
  },
})
```

- 전체 사전 병합 매트릭스 대신 **간결한 소스 파일**을 Nitro 에셋에 번들링합니다
- 내장 `/_locales/:page/:locale/data.json` 라우트를 통해 루트, 페이지, 폴백 로케일 체인을 **런타임에** 병합합니다
- `publicAssets`와 `prerenderRoutes`의 기본값이 `false`입니다 — 순수 정적 호스팅이 아닌 Nitro/엣지 런타임에 의존할 때 이상적입니다

[배포 — 서버리스와 엣지](/ko/guide/deployment#serverless-and-edge) 및 [캐시 및 스토리지 아키텍처](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api)를 참고하세요.

### 통합 패키지 간 공유 유틸리티 {#shared-utilities-across-integration-packages}

- **`@i18n-micro/node`** 및 **`@i18n-micro/astro`** — `@i18n-micro/utils/parse-path`를 통한 통일된 번역 경로 파싱과 딥 머지
- **`@i18n-micro/astro`** — `@i18n-micro/utils/accept-language`의 `detectLocaleFromAcceptLanguage` 사용 (중복 파서 제거)
- **`@i18n-micro/devtools-ui`** — `merge-source` + `parse-path` 헬퍼를 통한 가상 파일 경로
- **서버 로케일 감지** — Accept-Language 처리를 공유 유틸리티와 일치시킴

### HMR 및 DevTools 수정 사항 {#hmr-&-devtools-fixes}

- 클라이언트 HMR 플러그인이 이제 제거된 `$loadTranslations` 대신 **`$loadPageTranslations`**(올바른 API)를 호출합니다
- **premerged** 및 **source** 모드에서 번역 감시자에 대한 Playwright 테스트 커버리지

## 호환성을 깨는 변경 사항 (고급 / 내부) {#breaking-changes-advanced-/-internal}

다음 변경 사항은 **내부** 모듈 경로(공개 API에 포함되지 않음)를 임포트한 프로젝트에만 영향을 줍니다:

- `src/runtime/utils/`에서 제거됨: `route-utils.ts`, `runtime-i18n-config.ts` 및 `@i18n-micro/utils/*`로 이동한 기타 유틸리티
- `src/runtime/server/plugins/`에서 제거됨: 인라인 HMR 감시자/생성기 — 개발 도구를 포크했다면 `@i18n-micro/hmr/*`를 사용하세요
- **`nuxt-i18n-micro`**는 이제 `@i18n-micro/utils` 및 `@i18n-micro/hmr` 워크스페이스 패키지에 의존합니다 (모듈과 함께 자동 설치됨)

일반적인 `nuxt.config` + 컴포저블 사용법은 변경되지 않습니다.

## 왜 중요한가 {#why-it-matters}

- **더 작은 서버리스 번들** — `source` 모드는 로케일 × 페이지마다 사전 병합된 파일을 배포하지 않습니다
- **단일 진실 공급원** — 경로 파싱, 병합, 로케일 감지, 페이로드 설정을 하나의 구현으로 처리합니다
- **더 쉬운 유지보수** — 프레임워크에 구애받지 않는 코드가 `@i18n-micro/utils`에서 테스트되고(50개 이상의 단위 테스트) 모든 곳에서 재사용됩니다
- **더 나은 개발 경험** — HMR 로직이 격리되어 있고, 테스트 가능하며, 페이로드 모드 전반에서 일관됩니다

전체 커밋 목록은 [변경 로그](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md)를 참고하세요.
