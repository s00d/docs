**날짜**: 2026-11-03

**버전**: `v4.0.0`

![v4.0.0 릴리스](/images/4.0.0.png)

**v4.0.0**이 출시되었습니다. 라우팅, 번역 코어, 사전 파일, 로케일 감지, 그리고 모든 프레임워크 패키지가 다시 작성되었습니다. 옵션, `$t`, `$localePath`, `$switchLocale`, 컴포넌트, 컴포저블은 이름이 그대로입니다. 바뀌는 것은 동작이며, 그 변경의 대부분은 사라진 버그입니다. 대부분의 앱은 코드 변경이 거의 필요 없지만, 업그레이드하기 전에 [호환성을 깨는 변경 사항](#breaking-changes)을 읽어 보세요: URL, SEO 태그, 프레임워크 패키지 API가 일부 바뀌었습니다. 모든 세부 사항은 [업그레이드](/ko/guide/upgrade)에 있습니다.

## 새로운 기능 {#what’s-new}

### 모든 도메인을 위한 하나의 빌드 {#one-build-for-every-domain}

`locales[].baseUrl`과 `baseDefault`는 이전에는 링크 형태만 결정했습니다. 이제는 네 가지 전략 모두와 `nuxt generate`에서 요청도 라우팅합니다:

```ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'fr', baseUrl: 'https://example.com' },
      { code: 'de', baseUrl: 'https://example.de', baseDefault: true },
    ],
  },
})
```

- 호스트는 자신의 로케일을 제공합니다. 다른 도메인의 로케일로의 링크는 해당 도메인의 절대 URL이 되며, 그 로케일로 전환하면 그곳으로 이동합니다.
- `trustForwardedHost`는 `X-Forwarded-Host`를 덮어쓰는 프록시 뒤에서 그 헤더로부터 도메인을 선택합니다. 기본적으로 꺼져 있습니다.
- `NUXT_I18N_DOMAIN`은 `nuxt generate`에 호스트를 제공합니다: 도메인마다 한 번씩 실행하면 각 출력에는 해당 도메인의 페이지와 사전만 포함됩니다.
- `baseUrl`이 없는 앱에는 이 코드가 전혀 포함되지 않습니다.

[레이어와 도메인](/ko/guide/layers#multiple-domains)과 [배포](/ko/guide/deployment)를 참고하세요.

### 라우터와 일치하는 라우팅 {#routing-that-agrees-with-the-router}

빌드와 런타임은 더 이상 현지화된 URL을 따로 계산하지 않습니다. 모든 답은 빌드가 생성한 라우트에서 나오므로, 링크, 스위처, `hreflang`, 리디렉션이 존재하지 않는 페이지를 가리킬 수 없습니다.

- 페이지를 제공하지 않는 로케일은 다른 로케일의 페이지가 아니라 자신의 홈으로 연결됩니다.
- `hreflang`은 페이지를 제공하는 로케일만 나열합니다.
- `$switchLocale`은 `true` 또는 `false`로 resolve되므로 사전 로드 실패를 알 수 있습니다. 다시 호출하면 재시도합니다.
- SSR 중에 설정된 `$setI18nRouteParams`와 `useI18nHead`는 하이드레이션 후에도 유지됩니다. 스위처는 서버 HTML에서도 번역된 slug로 연결됩니다.
- 페이지 이동은 커밋될 때 적용됩니다: 취소되거나 차단된 이동은 아무것도 바꾸지 않습니다.
- 해시 모드가 `prefix`에서 동작합니다.
- 서버 컴포넌트의 `<Greeting :locale="$getLocale()" />`는 렌더링 로케일을 설정합니다.

### 하나의 로케일 감지 {#one-locale-detection}

서버, 브라우저, 서버 API 헬퍼, Astro 어디에서나 하나의 순서를 사용합니다. `Accept-Language`는 `q` 값을 존중하고, 지역 일치는 더 이상 `locales`의 순서에 의존하지 않으며, 중국어 문자 체계를 넘나들지 않습니다. 런타임 재정의가 이제 라우팅에도 적용됩니다: `NUXT_I18N_DEFAULT_LOCALE`과 런타임 `disabledLocales`가 실제로 제공되는 것을 바꿉니다. [로케일 감지](/ko/guide/locale-detection)를 참고하세요.

### 모든 모드에서 하나의 사전 {#one-dictionary-in-every-mode}

사전 병합된 빌드, `mode: 'source'`, 개발 환경은 이전에 많은 페이지에서 서로 결과가 달랐습니다. 이제 같은 사전을 제공합니다.

- 병합은 모든 수준에서 깊게 이루어지며, 폴백 체인(`fr` → `de` → `en`)은 끝까지 따라갑니다.
- 개발 환경에서 번역 편집은 페이지를 새로고침하지 않고 그 자리에서 적용됩니다. 제거된 키는 사라지며, 루트 파일 편집은 모든 페이지에 반영됩니다.
- `$clearCache()`는 현재 페이지를 다시 로드하며, 새 텍스트가 도착할 때까지 이전 텍스트를 화면에 유지합니다.
- 청크 로드에 실패하면 원시 키를 보여주는 대신 현재 사전을 유지합니다.

### 더 작은 사전 파일 {#smaller-dictionary-files}

- 이제 페이지의 파일에는 `__root/<locale>/data.json`에 있는 로케일 루트와 다른 부분만 담깁니다. 브라우저는 루트를 한 번 로드하고 각 페이지를 그 위에 병합하므로, 디스크 사용량이 줄고 다음 페이지의 비용은 첫 페이지의 일부에 불과합니다.
- 사전 URL에는 버전이 붙습니다. 현재 `?v=`가 붙은 URL은 Node 서버에서 1년 동안 고정되며, 호스트의 정적 사본은 `max-age=60`으로 응답합니다. [캐시 헤더](/ko/guide/deployment#cache-headers-and-datebuild)를 참고하세요.
- 모든 SSR 페이지는 사전 파일을 미리 로드하므로 HTML과 함께 로드가 시작됩니다.
- 읽기 실패가 더 이상 고착되지 않습니다: 다음 요청이 다시 읽습니다. [사전을 읽을 수 없을 때](/ko/guide/deployment#when-a-dictionary-cannot-be-read)를 참고하세요.

### 더 나아진 `<i18n-t>`, 복수형, 서식 {#better-&lt;i18n-t&gt;-plurals-and-formats}

- 슬롯이 `plural`, `number`, `date`, `relativeDate`와 함께 동작하며, 첫 번째뿐 아니라 모든 `{name}`이 채워집니다.
- `<i18n-t>`는 Nuxt, Vue, React, Preact, Solid, Astro 전반에서 하나의 렌더러입니다.
- `=0 `으로 시작하는 첫 번째 형태는 명시적인 0 형태이며, 나머지는 `Intl.PluralRules`를 따릅니다: `=0 no apples | one apple | {count} apples`. [`$tc`](/ko/api/methods#$tc)를 참고하세요.
- 새로운 `timeZone` 옵션: 서버와 모든 브라우저에서 같은 달력 날짜를 표시합니다.
- `{firstName}`, `{first-name}`, `{user.name}`은 유효한 플레이스홀더입니다.
- `$tn`, `$td`, `$tdr`은 복수형과 마찬가지로 `iso`를 따릅니다.
- `$tdr`은 실제 미래 날짜를 제공합니다: `in 3 days`, 또는 `numeric: 'auto'`일 때 `tomorrow`.

### 기본적으로 더 안전하게 {#safer-by-default}

- `<i18n-t html>`은 `params`를 이스케이프합니다. 신뢰할 수 있는 마크업은 번역뿐입니다.
- 어떤 링크도 실수로 오리진을 벗어나지 않습니다: `//host`, `/\host`, 빈 값은 이 사이트에 머뭅니다.
- 서버 번역 캐시에는 상한이 있으므로, 임의로 만든 페이지 이름이 담긴 URL로 메모리를 늘릴 수 없습니다.
- DevTools 저장 엔드포인트는 번역 디렉터리 안에 이미 존재하는 `.json` 파일만 받아들이며, 크로스 사이트 요청을 거부합니다.

### 2.0이 된 프레임워크 패키지 {#framework-packages-at-2-0}

- **React, Preact, Solid:** `I18nT`가 리치 텍스트를 위한 `components` prop을 받습니다. 새로운 `useT`와 `useLocaleSwitch`, 그리고 `@i18n-micro/react/server`와 `/client`를 통한 React 서버 컴포넌트 지원이 추가되었습니다. Preact는 더 이상 `preact/compat`이 필요하지 않습니다.
- **Vue와 VitePress:** `I18nLink`는 `name`, `query`, `hash`를 유지하며, VitePress는 `base`를 존중합니다.
- **Astro:** `i18nIntegration`이 사전을 번들링하고 미들웨어를 설치합니다. 메인 엔트리에 `node:*` import가 없으므로 엣지에서 실행됩니다. `base`가 동작합니다.
- **Node와 런타임:** `fork(locale)`은 저렴한 요청별 인스턴스를 제공하며, `@i18n-micro/node`의 `run(locale, fn)`은 인스턴스를 요청 범위로 한정합니다.
- **`@i18n-micro/types-generator`:** 서드파티 의존성이 없으며, 일반 Vite 및 Rollup 플러그인입니다.
- **`@i18n-micro/devtools-ui`:** Vite 소켓을 통한 실시간 업데이트와 Astro 툴바 앱.

### `@i18n-micro/cli` {#@i18n-micro/cli}

CLI는 이제 모노레포에서 `@i18n-micro/cli`로 관리되며, 28개 대신 16개의 명령과 훨씬 적은 의존성으로 다시 작성되었습니다. `check`가 `validate`, `diff`, `check-duplicates`를 대체하며, CI를 위한 `--json`과 종료 코드를 제공합니다. 키가 사용되지 않음을 증명할 수 없으면 `clean`은 아무것도 기록하지 않습니다. [CLI](/ko/guide/cli)를 참고하세요.

### 문서 {#documentation}

문서는 하나의 읽기 경로를 중심으로 코드로부터 다시 작성되었습니다: 설치, 첫 번째 번역된 페이지, 번역 파일, 라우팅, 감지, 그리고 작업별 가이드. 이전 URL은 리디렉션됩니다. [업그레이드](/ko/guide/upgrade)에 모든 변경 사항이 자세히 나열되어 있습니다.

## 속도와 크기 {#speed-and-size}

- 서버 렌더링은 로컬 HTTP 요청이나 재파싱 없이 사전을 직접 읽습니다.
- `dir="auto"`는 더 이상 기본값이 아닙니다. 브라우저는 큰 페이지에서 이 처리에 오랜 시간을 소비합니다: `$t` 요소가 20,000개일 때 Chromium의 DOMContentLoaded가 약 980 ms에서 약 115 ms로 줄었습니다.
- `serverTranslationPreload`와 `i18n:register`는 더 이상 모든 요청을 느리게 하지 않습니다.
- 쿠키가 구성되지 않으면 클라이언트 번들에서 `useCookie`가 빠지며, `@i18n-micro/path-strategy`는 이전 크기의 일부에 불과합니다.

**v3.30.3 대비 테스트 앱.** 하나의 Node 서버, 한 대의 Mac에서 실행한 생성된 Nuxt 앱으로, 사전 릴리스 빌드에서 `wrk`로 24개 연결, 20초, 순환하는 세 라운드를 측정했습니다. 각 행은 별도의 실행에서 나온 것이므로 행 안에서 비교하세요. 하이드레이션은 양쪽 모두 `dir: 'ltr'`을 사용합니다.

| 측정 항목 | v3.30.3 | v4.0.0 |
| --- | ---: | ---: |
| 로케일 4개, 10k 카탈로그: 초당 요청 수 | 384-395 | 585-591 |
| 로케일 4개, 10k 카탈로그: p95 지연 시간 | 106-110 ms | 70-72 ms |
| 로케일 4개, 10k 카탈로그: 요청당 서버 CPU | 2.92-3.00 ms | 2.01-2.02 ms |
| 로케일 12개, 100k 카탈로그: 초당 요청 수 | 362-370 | 578-580 |
| 로케일 12개, 100k 카탈로그: p95 지연 시간 | 115-117 ms | 72-73 ms |
| 로케일 12개, 100k 카탈로그: 요청당 서버 CPU | 3.11-3.17 ms | 2.02-2.03 ms |
| 하이드레이션, 100k 페이지 | 86-92 ms | 77-81 ms |
| 이 앱의 클라이언트 JS, gzip | 105.1 KB | 93.9 KB |
| `i18n:register` 구독자가 있을 때의 요청 시간, 100k 청크 | 96-108 ms | 1.7 ms |

이전 사전 릴리스 빌드에서 100k 카탈로그로 30분간 실행한 결과, 오류 없이 113만 건의 요청을 처리했으며 라이브 힙은 일정하게 유지되었습니다.

**v3.29.5 대비 세 개의 프로덕션 앱.** 이들이 실행하던 버전이며, 사전 릴리스 빌드에서 측정했습니다. 두 개는 SSR 사이트이고 하나는 SPA입니다. 각각 하나의 Node 서버에서 60초, 8개 연결, GET만, 두 라운드로 실행했습니다. 빌드 시간은 각각 한 번 실행한 값입니다.

| 측정 항목 | SSR 앱 1 | SSR 앱 2 | SPA 앱 |
| --- | ---: | ---: | ---: |
| 디스크의 사전 바이트 | 6.37 MB에서 1.52 MB로 (-76%) | 4.43 MB에서 1.52 MB로 (-66%) | 15.40 MB에서 1.69 MB로 (-89%) |
| `.output` 크기 | -22% | -14% | -29% |
| 빌드 시간 | 27초에서 22초로 | 23초에서 19초로 | 41초에서 28초로 |
| 클라이언트 JS, gzip | +1.7% | +0.9% | +0.5% |
| 초당 요청 수 | 82에서 88로 | 237에서 240으로, 오차 범위 내 | 233에서 404로, SPA 셸만 |

**클라이언트 JS.** 자체 코드가 있는 실제 앱은 위와 같이 약간 늘어납니다. 공유된 수정으로 프레임워크 패키지도 커졌으며, 다른 사전 릴리스 빌드에서 최소 크기의 Vue, React, Preact, Solid 앱으로 측정한 결과 gzip 기준 약 1.4 KB에서 2.5 KB 늘었습니다. React, Preact, Solid는 공유 리치 텍스트 렌더러도 포함합니다.

**사전 요청.** 첫 로드는 이제 루트와 페이지, 두 개의 파일을 가져옵니다. 바이트 수는 그대로입니다(두 SSR 앱에서 103회와 89회의 첫 로드에 대해 +0.3%). 같은 문서의 다음 페이지는 작은 파일 하나를 가져옵니다: 측정한 두 페이지에서 gzip 기준 4.7 KB에서 1.5 KB로, 5.9 KB에서 0.5 KB로 줄었습니다. SPA를 로그인 상태로 둘러보는 동안 사전 바이트는 21% 감소했습니다.

**엣지.** 작은 데모 앱에서 Cloudflare Worker 업로드가 사전 릴리스 빌드 기준 gzip 241.5 KiB에서 250.3 KiB로 늘었습니다. Edge 번들에 포함된 사전은 같은 루트 및 페이지 파일을 사용하지만, 대형 카탈로그에서 그 포함 크기는 측정하지 않았습니다.

## 호환성을 깨는 변경 사항 {#breaking-changes}

### 요구 사항 {#requirements}

- **Nuxt 3.18 이상**, 그리고 **Node 20 이상**.
- **`@i18n-micro/test-utils`**는 더 이상 모듈과 함께 설치되지 않습니다. 테스트에서 import한다면 직접 추가하세요.
- **`@i18n-micro/hmr`**은 사라졌습니다: 번역 HMR이 내장되었습니다. 설치했다면 패키지를 제거하세요.
- **`@i18n-micro/react`**는 React 18 이상이 필요합니다.
- **`nuxt-i18n-micro-cli`**는 `@i18n-micro/cli`로 대체되었습니다.

### 옵션과 구성 {#options-and-config}

- `dependsOn`의 `i18n-plugin-hooks`와 `i18n-plugin-define`은 더 이상 아무것도 기다리지 않으며, 오류도 없습니다. `i18n-plugin-loader`를 사용하세요.
- 서버 자동 import는 `useLocaleServerMiddleware`, `useTranslationServerMiddleware`, `loadTranslationsFromServer`, `detectCurrentLocale`입니다. 나머지는 더 이상 자동으로 import되지 않습니다.
- `resolveTranslationPayloadMode`와 다른 `resolveTranslationPayload*` 헬퍼는 `shouldCopyTranslationPayloadsToPublic`, `shouldRegisterNitroServerAssets`와 함께 `nuxt-i18n-micro`에서 제거되었습니다. `TranslationPayloadMode` 타입은 유지됩니다.
- `$getI18nConfig()`에는 더 이상 `isSSG`, `hmr`, `hooks`, `noPrefixRedirect`, `routeLocales`, `routeDisableMeta`, `globalLocaleRoutes`가 없습니다. 옵션 자체는 변경되지 않았습니다.
- `locales[].baseUrl`이 이제 요청을 라우팅합니다: 다른 도메인의 로케일은 이 호스트에서 404이며, 같은 호스트의 링크는 상대 경로입니다. 이러한 빌드에서 `$getI18nConfig().locales`에는 호스트가 제공하는 것이 담기고, `linkLocales`에는 전부가 담깁니다.
- `baseUrl`은 그 외의 호스트에서도 오리진을 설정합니다: canonical과 `hreflang`은 요청의 오리진이 아니라, 설정된 경우 `metaBaseUrl`을, 그렇지 않으면 기본 로케일의 `baseUrl`을 사용합니다.
- `excludePatterns`는 세그먼트 전체와 일치하며(`'/admin'`은 더 이상 `/administrator`와 일치하지 않음), glob은 고정되고, `RegExp` 패턴이 이제 런타임에도 적용됩니다.
- `cacheMaxSize`가 설정되지 않으면 서버에서 최대 1000개 항목입니다. `cacheTtl`은 항목이 저장된 시점부터 계산되며, 읽기로 연장되지 않습니다.
- `no_prefix`에서 `i18n` 구성의 명시적인 `localeCookie: null`은 꺼진 상태로 유지됩니다.
- `prefix_except_default`와 `prefix_and_default`에서 런타임 `defaultLocale`은 경고와 함께 무시됩니다. 런타임 `fallbackLocale`은 활성화된 로케일이어야 합니다.
- `nuxt.config`의 `routeDisableMeta`가 반영되며, `nuxt.config` 항목은 어떤 키 형식에서든 `$defineI18nRoute`보다 우선합니다.
- 개발 환경의 서버에서 해석된 구성은 동결됩니다: 쓰기 시 예외가 발생합니다.
- 같은 `code`에 대해 프로젝트의 `locales` 항목이 레이어의 항목보다 우선합니다.

### 컴포저블과 `$` 메서드 {#composables-and-$-methods}

- `$switchLocale`은 `true` 또는 `false`로 resolve됩니다. 이전에는 아무것도 resolve하지 않았습니다. `$switchRoute`의 타입은 `Promise<void>`입니다.
- `$localeRoute`, `$switchLocalePath`, 스위처는 페이지를 제공하지 않는 로케일을 해당 로케일의 홈으로 연결합니다.
- `$localePath`는 `http(s):`, `mailto:` 또는 `tel:` 스킴이 있는 문자열을 그대로 반환하며, `$localeRoute`는 이를 `path`와 `fullPath`에 담습니다. 검증되지 않은 값을 링크 대상으로 전달하지 마세요. `//host`와 `x.com` 같은 단순 이름은 이 오리진의 경로로 유지됩니다.
- 경로가 없는 링크는 현재 페이지에 머뭅니다: `$localePath('#top')`, `'?p=2'`, `''`, `{ query }`. `'#top'`은 이전에 사이트 루트를 기준으로 했습니다. 단순한 `'about'`은 여전히 `/about`을 의미합니다.
- `$switchRoute`는 앱 안에 머뭅니다. 로케일 자체의 `baseUrl`, `mailto:`, `tel:`만 앱을 벗어납니다.
- `baseUrl`이 있는 로케일로의 링크는 `$localePath` 또는 `<i18n-link>`를 거칩니다. `<NuxtLink :to="$localeRoute(x, 'fr')">`와 `router.push($localeRoute(x, 'fr'))`는 이 앱의 경로로 유지됩니다. 코드에서는 `navigateTo($localePath(x, 'fr'), { external: true })`를 사용하세요.
- `$switchLocaleRoute`와 리디렉션은 `trailingSlash`를 따릅니다.
- 서버에서 설정된 `$setI18nRouteParams`와 `useI18nHead`는 페이지 이동으로 경로가 바뀌면 폐기되며, `/news/1`에서 `/news/4`로의 이동도 포함됩니다: 새 페이지에서 다시 설정하세요.
- setup에서 읽은 `$setI18nRouteParams`는 해당 페이지에 바인딩됩니다: 이미 떠난 페이지에서의 늦은 호출은 아무 효과가 없습니다. setter가 없으므로 테스트에서는 `useI18n` 자체를 스텁하세요.
- `useI18n()`은 앱당 하나의 객체를 반환합니다. 여기에 쓰면 모든 호출자에게 반영됩니다.
- 사전, 로케일, params, head는 페이지 이동이 커밋될 때 바뀝니다. `beforeResolve`, `beforeRouteEnter` 또는 이후의 전역 가드는 이전 값을 봅니다. 라우트 미들웨어는 영향을 받지 않습니다.
- URL 전략에서 `$switchLocale`은 페이지 이동이 취소되면 저장된 로케일을 복원합니다.
- `$t`는 `defaultValue`를 보간합니다: `$t('missing', { n: 1 }, 'Got {n}')`은 `Got 1`을 반환합니다. `$tc`도 마찬가지이며, 빈 번역에는 `''`로 응답합니다.
- `$has(key, route)`는 라우트를 반영합니다.
- `$clearCache()`는 현재 페이지의 사전을 다시 로드합니다.
- `{param}` 플레이스홀더는 전달한 params만 읽습니다: `{constructor}`는 작성된 그대로 남습니다.
- 음수, 소수 또는 아주 큰 개수를 받은 `$tc`는 실제 개수로 마지막 형태를 사용합니다. `{ count: null }`은 더 이상 예외를 발생시키지 않으며, 누락된 복수형 키는 누락 핸들러에 도달합니다.
- `$tdr`은 잘못된 입력에 대해 `Invalid Date`를 반환합니다. 과거 1초 미만은 `0 seconds ago`입니다.
- `$tn`, `$td`, `$tdr`은 `iso`를 따릅니다: `{ code: 'en', iso: 'en-GB' }`는 날짜를 `31/10/2026`으로 서식 지정합니다. `Intl`이 모르는 코드는 `en`으로 서식 지정되고, 복수형은 인덱스 규칙을 따릅니다: `iso`를 설정하세요(`{ code: 'ua', iso: 'uk-UA' }`).
- `detectCurrentLocale`은 더 이상 사용되지 않습니다: `useLocaleServerMiddleware(event).current`를 사용하세요.

### 복수형 {#plurals}

템플릿의 의미는 한 가지 예외를 제외하고 그대로 유지됩니다. 플레이스홀더가 없는 0 형태 다음에 범주마다 하나의 형태가 오고, 여러 개수가 공유하는 각 형태에 `{count}`가 있는 템플릿은, 이제 세 개 이상의 범주를 가진 로케일(`ru`, `uk`, `pl`, `cs`, `ar` 등)에서 범주를 따릅니다: `uk`에서 `none | {count} one | {count} few | {count} many`는 `3 few`와 `21 one`을 반환합니다. 다른 템플릿에서 범주를 사용하려면 `=0 ` 마커를 추가하세요. 사용자 정의 `plural` 규칙은 원시 값을 읽으므로, 마커가 있는 템플릿은 `=0 `이 그대로 있는 상태로 전달됩니다. [업그레이드의 표](/ko/guide/upgrade#plurals-and-formatting)를 참고하세요.

### 컴포넌트 {#components}

**`<i18n-t>`**

- `html`은 모든 경우에 `params`를 이스케이프하고 모든 슬롯을 무시합니다.
- 슬롯이 같은 이름의 param보다 우선합니다.
- `plural`, `number`, `date`, `relativeDate`에서 `null`은 설정되지 않음을 의미합니다.
- `plural`은 `$tc`처럼 `Number`로 개수를 셉니다: `1.5`는 `1.5`로 유지되고, `"2 items"`는 `NaN`, `""`는 `0`입니다.
- `number`, `date`, `relativeDate`는 `params`를 유지합니다.
- `hideIfEmpty`는 모든 분기에 적용되며, `defaultValue`는 모든 분기에서 누락된 키를 대신합니다.
- `html`에서 누락된 키는 이스케이프된 텍스트입니다.
- `date`와 `relativeDate`의 출력에는 `data-allow-mismatch="text"`가 붙으며, 이름이 지정된 슬롯 옆에서는 텍스트가 자체 `<span>`에 들어갑니다.
- `.innerHTML`과 `textContent` 속성은 제거됩니다.
- 함수형 컴포넌트입니다: 여기에 붙인 `ref`는 인스턴스를 제공하지 않습니다.
- `<i18n-t>`와 `<i18n-group>`은 `$t`처럼 활성 사전을 읽습니다.

**`<i18n-switcher>`**

- 링크는 `$switchLocale`을 호출하는 일반 `<a>`이므로 `router-link-active` 클래스가 사라졌습니다.
- 버튼은 `aria-expanded`가 있는 `type="button"`입니다. Escape 키와 바깥 클릭으로 드롭다운이 닫힙니다.
- 새로운 클래스 `i18n-switcher-wrapper`, `i18n-switcher-dropdown`, `i18n-switcher-button`. 각 링크에는 `lang`이 있으며, 로케일이 설정한 경우 `dir`도 있습니다.
- 기본 스타일은 논리적 CSS 속성을 사용하며, 드롭다운에는 더 큰 `z-index`, 최소 너비, 그림자가 있습니다.
- params가 있는 페이지에서는 렌더링이 끝날 때 서버가 링크를 다시 작성합니다. 직접 작성한 `$switchLocalePath` 링크는 다시 작성되지 않습니다.

**`<i18n-link>`**

- `https://`, `mailto:`, `tel:`은 대소문자에 관계없이 일치합니다. 단순한 `report.pdf`는 라우트이며, `example.com`은 외부 링크로 유지됩니다. TLD이기도 한 파일 확장자(`example.md`)는 파일로 간주됩니다: `https://`를 작성하세요.
- `activeStyle`은 후행 슬래시, 쿼리, 해시를 무시합니다.

### 훅과 타입 {#hooks-and-types}

- `i18n:register`는 런타임 훅입니다: 플러그인에서 `nuxtApp.hook('i18n:register', …)`.
- export된 타입 `ModuleHooks`의 이름이 `ModuleRuntimeHooks`로 변경되었습니다.
- `i18n:beforeLocaleSwitch`와 `i18n:afterLocaleSwitch`는 한 번도 발생한 적이 없으며 더 이상 문서화되지 않습니다.
- `ModuleOptionsExtend.isSSG`는 선택 사항이며 더 이상 사용되지 않습니다: 아무것도 이를 설정하지 않습니다.

### URL과 리디렉션 {#urls-and-redirects}

- `en`이 기본값인 `prefix_except_default`에서 **`/en`과 `/en/...`은 404입니다**.
- **다른 대소문자나 철자의 로케일 접두사는 404입니다**(`/DE/about`). `[...slug]` 아래의 `/DE/x`와 `[slug]` 옆의 `/DE`도 마찬가지이므로, 대소문자만 다르고 로케일 코드와 같은 CMS slug는 페이지를 잃습니다.
- `autoDetectPath: '*'` 또는 `'no_prefix'`에서 **알 수 없는 URL은 404로 유지됩니다**. `prefix`는 리디렉션을 유지하며, 모든 곳의 `/`도 마찬가지입니다.
- **접두사가 없는 다른 로케일의 사용자 정의 경로**는 `prefix_except_default`에서 기본 로케일의 URL로 `302`됩니다. `prefix`에서는 리디렉션이 이제 실제 페이지에 도달합니다. `prefix_and_default`는 404로 유지됩니다.
- **`redirects: false`인 `prefix`**는 접두사 없는 URL에 404로 응답하며, 사용자 정의 기본 경로가 있는 페이지의 원래 URL도 포함됩니다.
- **`autoDetectPath: '*'`**는 접두사 없는 경로에도 쿠키와 `Accept-Language`를 적용합니다.
- **`prefix`에서** 접두사 없는 URL은 `autoDetectPath` 설정에 관계없이 모든 경로에서 방문자의 로케일을 유지합니다.
- **`prefix_and_default`에서** 접두사 없는 URL은 기본 로케일입니다.
- **`no_prefix`에서** 사용자 정의 경로는 자신의 로케일로 렌더링되고, 제한된 페이지는 제공하는 로케일로 렌더링되며, 경로를 공유하는 로케일은 하나의 레코드를 공유합니다.
- **페이지가 없는 `routeRules` 리디렉션**은 현지화되지 않습니다: `/de/old`는 404이며, 이전에는 빈 200이었습니다.
- **라우트 규칙이 사용자 정의 경로에 적용되며**, `no_prefix`에서도 복사됩니다. `/de/artikel/news` 같은 정적 형제 경로는 `/de/artikel/:slug`와 일치합니다.
- **`disabled: true`인 로케일**은 즉시 해당 접두사에서 404로 응답하며, 그 로케일로의 링크는 페이지에 머뭅니다.
- **다른 대소문자의 페이지 경로**는 원래 철자로 `302`됩니다: `/T/BASIC`은 `/t/basic`으로 이동합니다.
- **사용자 정의 기본 경로가 있는 페이지의 원래 URL**은 `prefix_except_default`에서 그 경로로 `302`됩니다. 이전에는 404였습니다.
- **`noPrefixRedirect`**는 방문자의 로케일을 따릅니다: 쿠키가 `de`이면 `/about`은 기본 로케일의 경로가 아니라 `/ueber-uns`로 이동합니다.
- **호스트 자체의 접두사**는 `prefix_except_default`에서 해당 `baseDefault` 호스트에서 404입니다: `de` 호스트의 `/de/x`는 이전에 200이었습니다.
- **`customRegexMatcher`**는 첫 번째 세그먼트가 로케일처럼 보이는 실제 페이지를 더 이상 404로 처리하지 않습니다.
- **`nuxi generate`**는 라우트 규칙이 `prerender: false`를 설정하지 않는 한, 모든 정적 페이지를 해당 페이지를 제공하는 각 로케일로 사전 렌더링합니다: 출력에 더 많은 파일이 생깁니다. `baseUrl`이 있으면 `NUXT_I18N_DOMAIN`과 함께 도메인마다 한 번씩 실행하세요.
- **클라이언트 리디렉션은 페이지 이동의 모드를 유지합니다:** 일반 `<NuxtLink>`는 히스토리 항목을 추가합니다.
- **현지화된 라우트 이름이 일관됩니다.** `router.push({ name })`에서 `localized-…` 이름을 하드코딩한 코드만 영향을 받습니다: 페이지 자체의 이름을 `$localeRoute`에 전달하세요.
- **`extendPages`의 이름 없는 페이지**는 현지화되며 이름을 받습니다.
- **`prefix`에서 다른 도메인으로의 링크**는 로케일 접두사를 유지합니다.
- **도메인의 홈**은 모든 곳에서 후행 슬래시 없이 작성됩니다.
- **`?locale=`**은 `no_prefix`에서만 페이지에 반영됩니다. `/about?locale=de`는 더 이상 `lang="en"` 아래에서 독일어로 렌더링되지 않습니다.
- `/en/...`에서 **플러그인의 `setLocale('de')`**는 더 이상 `de` 사전을 로드하지 않습니다.

### SEO와 HTML 출력 {#seo-and-html-output}

- `dir="auto"`는 더 이상 기본값이 아닙니다. 알려진 RTL 언어는 `dir="rtl"`을 받고, `dir`이 없는 다른 로케일은 속성을 받지 않습니다. 이전 출력을 유지하려면 `dir: 'auto'`를 설정하세요. 단, 큰 페이지에서는 파싱 비용이 듭니다. [텍스트 방향](/ko/guide/seo#text-direction)을 참고하세요.
- `disableMeta`가 이제 동작합니다: 페이지에 `hreflang`, canonical, `og:locale`이 없습니다. `lang`과 `dir`은 유지됩니다.
- `hreflang`은 페이지를 제공하는 로케일만 나열합니다. `x-default`는 기본 로케일이 페이지를 제공할 때만 나타납니다.
- 현지화되지 않은 페이지에는 `hreflang`이나 `og:locale:alternate`가 없습니다.
- 404 페이지는 URL의 로케일로 `<html lang dir>`을 가지며, canonical이나 `hreflang`은 없습니다.
- Canonical, `og:url`, `hreflang`은 서버에서도 허용 목록의 쿼리(`/about?page=2`)를 유지합니다.
- 오리진이 요청에서 오는 경우 canonical과 `hreflang`에 `app.baseURL`이 포함됩니다.
- 404 페이지를 포함한 모든 SSR 페이지에는 사전 파일을 위한 `<link rel="preload" as="fetch" crossorigin="anonymous">`가 있습니다. 엄격한 CSP에서 이를 허용하세요. `apiBaseClientHost`를 사용하면 해당 호스트에 CORS가 필요합니다.
- `no_prefix`에서는 모든 페이지에, 다른 전략에서는 로케일 리디렉션에 `Vary`가 설정됩니다. CDN의 캐시 키를 확인하세요.
- 로케일 쿠키는 제공된 페이지에서만 기록됩니다.

### 감지와 서버 {#detection-and-server}

- `Accept-Language`는 `q` 값을 존중하며, `q=0`은 해당 언어를 제외합니다.
- `useLocaleServerMiddleware`와 `useTranslationServerMiddleware`는 모든 라우트에서 하나의 순서(`?locale`, `[locale]` param 또는 접두사, 쿠키, 헤더, 기본값)를 사용하고, `localeCookie: null`과 `autoDetectLanguage: false`를 존중하며, 로케일별로 사전을 캐시합니다.
- 형식이 잘못된 로케일 쿠키는 SSR을 실패시키는 대신 무시되고 그대로 남습니다.
- 해시 모드는 `hash-locale` 쿠키만 읽습니다. 단독 `user-locale=de`는 더 이상 반영되지 않습니다.
- `NUXT_I18N_DEFAULT_LOCALE`과 런타임 `disabledLocales`가 라우팅을 바꿉니다.
- **`premerged` 출력이 변경되었습니다.** `/{apiBaseUrl}/<page>/<locale>/data.json`에는 `__root/<locale>/data.json`과 다른 부분만 담깁니다. 이 파일들을 직접 읽는 것은 무엇이든 둘을 병합해야 합니다. 전체 사전도 여전히 유효한 파일입니다.
- **사전이 `app.cdnURL`을 따릅니다.** 브라우저는 `app.baseURL`을 사용하던 곳에서 이제 `<cdnURL>/_locales/...`로부터 사전을 가져옵니다. CDN에는 `_locales/`가 있어야 하고 사이트의 오리진을 허용해야 합니다. [App baseURL과 페이로드 호스트](/ko/guide/deployment#app-baseurl-and-payload-hosts)를 참고하세요.
- `/{apiBaseUrl}/**`에 Nitro 라우트 캐시가 없으며, `s-maxage=60, stale-while-revalidate` 헤더가 사라졌습니다. 그 캐시에 의존했다면 페이로드 라우트 앞에 CDN을 두세요.
- `/{apiBaseUrl}/<page without a folder>/<locale>/data.json`은 루트 사전으로 응답하며, 이전에는 `{}`였습니다. 호스트의 404는 이제 `200 {}`로 응답하던 대신 404로 전달됩니다.
- 사전을 로드할 수 없는 사전 렌더링은 500과 경고로 실패하며, Nuxt의 기본 `failOnError`에서는 빌드가 1로 종료됩니다.
- 다시 빌드하지 않고 변경된 번역은 `v`가 바뀔 때만 브라우저에 도달합니다: `NUXT_I18N_DATE_BUILD`를 설정하세요.
- `apiBaseServerHost`가 설정되지 않는 한, SSR은 더 이상 HTTP로 `/{apiBaseUrl}`을 요청하지 않습니다.

### 번역 {#translations}

- 병합은 모든 수준에서 깊게 이루어지며, 폴백 체인은 끝까지 따라갑니다.
- 병합은 로케일 기준입니다: 활성 로케일의 루트 파일이 폴백 로케일의 페이지 파일보다 우선합니다.
- 자체 `pages/<name>/` 폴더가 없는 페이지는 프로덕션에서 루트 사전을 읽습니다. 이전에는 `{}`를 받았습니다.
- `disablePageLocales: true`는 루트 파일만 읽습니다.
- 떠나는 페이지의 키는 페이지 이동 후 해석이 중단됩니다. 레이아웃이 이전 페이지의 파일에만 있던 키를 사용했다면 루트 파일로 옮기세요.
- 손상된 로케일 파일은 모든 모드에서 경로와 함께 한 번 경고합니다. 개발 환경에서는 이전에 예외가 발생했습니다.

### `@i18n-micro/*` 패키지 {#@i18n-micro/*-packages}

`@i18n-micro/types`와 새로운 `@i18n-micro/cli`를 포함한 모든 `@i18n-micro/*` 패키지가 2.0.0입니다.

**`@i18n-micro/react`, `preact`, `solid`**

- 라우터 어댑터가 `/router`로 이동했습니다: `createReactRouterAdapter`, `createSolidRouterAdapter`, 그리고 Preact의 `createBrowserHistoryAdapter`. `createPreactRouterAdapter`는 제거되었습니다.
- `I18nT`는 위의 `<i18n-t>`를 따릅니다. `dangerouslySetInnerHTML`, `innerHTML`, `textContent` 속성은 제거됩니다.
- `I18nSwitcher`는 `aria-current="page"`, `▾`, 논리적 CSS, 버튼의 `language-switcher`와 함께 `<a href>` 항목을 렌더링합니다. `aria-haspopup`은 없습니다. `className`은 `i18n-switcher-wrapper`에 추가됩니다.
- `/` 또는 로케일 루트로의 링크는 정확히 일치할 때만 활성입니다(React, Preact).
- `I18nLink`는 사용자의 `onClick`과 `style`을 유지하며, 수정자 키가 눌린 클릭은 브라우저에 맡깁니다. 쿼리와 해시는 활성 여부 확인에 반영되지 않습니다. 라우터가 없으면 어떤 링크도 활성이 아닙니다.
- React와 Preact: `I18nLocalesContext`, `I18nDefaultLocaleContext`, `I18nRouterContext`가 하나의 `I18nConfigContext`가 되었습니다. Solid: 하나의 `I18nContext`가 `{ i18n, locales, defaultLocale, router }`를 담습니다.
- 어댑터의 `getCurrentPath`는 쿼리와 해시를 포함하며, `getRoute().query`에서 반복된 키는 배열입니다.
- `i18n`이 없는 중첩된 `I18nProvider`는 바깥 인스턴스를 유지하며, 인스턴스가 전혀 없는 프로바이더는 예외를 발생시킵니다.
- 값이 없는 `defaultLocale()`은 `fallbackLocale`입니다.
- Solid: `getCurrentPathAccessor`가 제거되었습니다. `useI18n()`은 `locales` 없이도 더 이상 예외를 발생시키지 않습니다.
- React: `use-sync-external-store`는 더 이상 의존성이 아니며, `react-dom`은 선택적 피어입니다.

**`@i18n-micro/vue`, `vitepress`**

- `I18nT`는 함수형 컴포넌트입니다.
- `I18nSwitcher`와 `I18nLink`는 위의 섹션을 따릅니다. `aria-haspopup`은 사라졌습니다.
- `I18nLink`와 `createVueRouterAdapter`는 `name`, `query`, `hash`를 해석합니다. 알 수 없는 `name`은 `RouterLink`처럼 예외를 발생시킵니다.
- `useLocaleHead`는 더 이상 `//de/`를 만들지 않습니다. 한 페이지의 canonical과 `hreflang`이 일치하며(`/de`), 허용 목록의 쿼리 params가 반영됩니다.
- `I18nRoutingStrategy.resolvePath`는 location 객체와 쿼리 및 해시가 포함된 경로를 받을 수 있습니다. 새로운 선택적 `toHref`.
- VitePress: 링크, 스위처, `push`, `replace`가 `site.base`를 포함합니다.

**`@i18n-micro/astro`**

- `i18nIntegration`은 `translationDir`를 번들링하고 미들웨어를 설치합니다: 설정만 복사하는 `src/middleware.ts`는 삭제하거나 `middleware: false`를 전달하세요. 직접 작성한 `src/middleware.ts`는 `base: config.base`를 전달합니다.
- `i18nIntegration`은 `messages`, `plural`, `missingHandler`, `routingStrategy`에 대해 예외를 발생시킵니다: `middleware: false`와 함께 이것들을 `createI18n` 또는 `createI18nMiddleware`에 전달하세요. 아무 효과가 없던 옵션은 타입에서 제외되었습니다.
- `loadTranslationsFromDir`와 `loadTranslationsIntoI18n`은 ESM 전용인 `@i18n-micro/astro/node`로 이동했습니다.
- `getGlobalRoutingStrategy`, `setGlobalRoutingStrategy`, `runWithRoutingStrategy`는 제거되었습니다: `Astro.locals.routingStrategy`를 읽으세요.
- `clone()`은 `fork()`가 되었고, `_storage` 옵션은 사라졌습니다.
- 동적 페이지는 하나의 라우트입니다: `/blog/hello`는 `blog-slug`이며, 이전에는 `blog-hello`였습니다. `pages/blog-hello/`를 `pages/blog-slug/`로 옮기세요. 사용자 정의 `getRouteName`은 세 번째 인수로 패턴을 받습니다.
- URL이 페이지 로케일을 결정합니다. `autoDetect`는 `/`에서 선호 로케일의 홈으로의 302입니다. 새로운 `localeCookie` 옵션이 추가되었고, `redirectToDefault`가 구현되었습니다.
- 다른 로케일의 같은 오리진 페이지에서 온 페이지 조회는 로케일 쿠키를 기록하며 리디렉션하지 않습니다. 서버 아일랜드와 액션은 절대 리디렉션하지 않으며 `Vary: Referer`를 포함합니다.
- `config.localeCodes`는 비활성화된 로케일을 제외하며, `prepareLocaleRewrite`는 이에 대해 404로 응답합니다.
- 키 없는 `getI18nProps()`는 페이지에서 `t()`가 답할 수 있는 모든 것을 보내며, 20 KB를 넘으면 개발 환경에서 경고합니다. 아일랜드가 사용하는 키를 전달하세요.
- `useLocaleHead`: 기본 `baseUrl`은 `site`이며, 없으면 루트 기준 상대 경로입니다. 링크와 메타에는 `id`가 붙습니다.
- `<I18nT html>`은 `params`를 이스케이프하며, 빈 번역은 빈 값으로 렌더링됩니다.
- `<I18nLink>`와 `localizePath`는 외부 URL, `#hash`, `?query`를 그대로 두며 후행 슬래시를 유지합니다.
- `<I18nSwitcher>`는 쿼리를 유지하며 생성된 id 대신 `data-i18n-switcher`를 사용합니다.
- `@i18n-micro/astro/client`에는 `translate`와 `hasTranslation`만 있습니다: 어댑터는 `/client/vue`, `/client/react`, `/client/preact`, `/client/svelte`에서 import하세요. `client/vue`는 `vue`가 설치되어 있어야 합니다.
- 아일랜드: `has()`는 하위 트리에 대해 true이며, `t('')`는 `''`입니다. `provideI18n`은 새 props를 따르기 위해 getter를 받습니다.
- `getLocale`과 `getDefaultLocale`은 미들웨어 없이 예외를 발생시킵니다.

**`@i18n-micro/runtime`, `node`**

- 활성 로케일도 폴백 로케일도 아닌 로케일에 쓰면 구독자에게 알리지 않습니다.
- `addRouteTranslations(locale, route, messages, false)`는 청크를 대체합니다.
- `loadFromUrls`는 병렬로 가져오며, 하나라도 실패하면 아무것도 기록하지 않습니다.
- Node: `reload()`는 사전을 먼저 비우는 대신 교체하며, 성공 메시지를 기록하지 않습니다. 디렉터리가 사라지면 이전 사전을 유지합니다.
- Node, Astro, VitePress: locales 폴더를 읽는 하나의 리더. 누락된 폴더는 경고하고, JSON 객체가 아닌 파일은 보고된 뒤 건너뛰며, 메시지는 `[i18n]`으로 시작합니다.

**`@i18n-micro/test-utils`**

- 목(mock)이 실제 번역 규칙을 따릅니다: `tc('a', 1.5)`는 마지막 형태를 사용하고, `td('nope')`는 `Invalid Date`, `t(miss, undefined, '')`는 키이며, 누락은 더 이상 로그를 남기지 않습니다.
- `createI18nTestContext`에서 `isolated`가 사라졌고, `./publish-smoke`는 제거되었습니다.

**`@i18n-micro/types-generator`**

- `I18nTypesPlugin(options)`는 일반 Vite 및 Rollup 플러그인입니다: `.vite()`, `.webpack()`, `.esbuild()`는 없습니다. webpack이나 esbuild에서는 스크립트에서 `generateTypes`를 호출하세요.
- `getTypesString`과 `generateTypes`는 동기 함수입니다. `flattenKeys`와 `isPlainTranslationObject`는 제거되었습니다.
- 키는 `t()`가 읽는 것입니다: 객체 경로가 추가되며, 로케일 구성 밖의 파일은 제외됩니다.

**`@i18n-micro/devtools-ui`**

- 저장은 `translationDir` 안에 이미 존재하는 `.json`만 받아들이며, 더 이상 파일을 생성하지 않습니다. 크로스 사이트 요청은 403입니다.
- 접근 가능한 엔드포인트로의 저장이 실패하면 예외를 발생시키고 롤백합니다.
- `createBridge`는 `base` 옵션을 받습니다. Astro는 `i18nDevToolsIntegration`을 사용합니다.

**`@i18n-micro/utils`, `core`, `path-strategy`, `route-strategy`**

사용자 정의 어댑터와 도구에만 해당합니다.

- `utils`: 하위 경로 `./route`, `./route-pattern`, `./build`, `./payload-stats`, `./payload-config`가 `resolveServerLocale`, `resolvePreferredLocale`과 함께 제거되었습니다: `resolveLocale`을 호출하세요. `deepMergeTranslations`와 `mergeRouteTranslationsWithRoot`는 사라졌습니다: `deepMergeTranslationsRecursive`를 사용하세요.
- `core`: `TranslationHelper`에서 `setCache`, `getGeneration`, `lookupIn`이 빠졌습니다(`lookup(chunkKey, key)` 사용). `BaseI18n`에서 `ensurePinnedChunk`와 `invalidatePin`이 빠졌습니다. `useTranslationHelper(storage)`는 사라졌습니다: `new TranslationHelper(storage)`를 사용하세요.
- `path-strategy`: **`switchLocaleRoute(fromLocale, toLocale, route, options)`는 이제 `switchLocaleRoute(toLocale, route, options)`입니다. 이전 JavaScript 호출은 오류 없이 잘못된 결과를 반환합니다.** Nuxt의 `$switchLocaleRoute`는 영향을 받지 않습니다. `/prefix`, `/no-prefix`, `/prefix-except-default`, `/prefix-and-default` 엔트리는 `getRedirect`, `getCanonicalPath`와 함께 사라졌습니다. `RouterAdapter`에는 `getRoutes`가 필요합니다. `createPathStrategy`는 절대 URL을 만들지 않습니다: 로케일에 `baseUrl`이 있으면 `new DomainPathStrategy(ctx)`를 사용하세요.
- `route-strategy`: `RouteGenerator`, `generateRoutes`, `Rules`, 경로 헬퍼만 export됩니다.

## 마이그레이션 {#migration}

1. 요구 사항을 확인하세요: Nuxt 3.18, Node 20, 그리고 `@i18n-micro/react`를 사용한다면 React 18.
2. `nuxt-i18n-micro`와 모든 `@i18n-micro/*` 패키지를 함께 업데이트하세요. `@i18n-micro/hmr`을 제거하세요. 테스트에서 import한다면 `@i18n-micro/test-utils`를 개발 의존성으로 추가하세요. `nuxt-i18n-micro-cli`를 `@i18n-micro/cli`로 교체하고 [명령 표](/ko/guide/cli#moving-from-nuxt-i18n-micro-cli)를 따르세요.
3. 코드에서 `@i18n-micro/path-strategy`의 `switchLocaleRoute(`, `i18n-plugin-hooks`, `i18n-plugin-define`, `localized-` 라우트 이름, `$getI18nConfig().globalLocaleRoutes`와 기타 제거된 구성 키, `ModuleHooks`, `i18n:register`의 `@ts-expect-error`를 검색하세요.
4. `<i18n-t html>` params의 마크업을 번역으로 옮기고, 데이터는 params로 전달하세요.
5. `baseUrl`을 설정했다면: `$localeRoute`로 만든 링크를 검토하고, 프록시 뒤에서는 `trustForwardedHost`를 설정하고, `NUXT_I18N_DOMAIN`과 함께 도메인마다 한 번씩 `nuxi generate`를 실행하세요.
6. 전략에 맞게 URL을 확인하세요: `prefix_except_default`의 `/en`, 로케일처럼 보이는 CMS slug, `routeRules` 리디렉션, `excludePatterns`.
7. CDN 캐시 키에서 `Vary`를 확인하고, 엄격한 CSP에서 preload 링크를 허용하세요. `app.cdnURL`을 사용한다면 `_locales/`를 CDN에 두고 CORS를 허용하세요.
8. 도구가 `/_locales/...` 파일을 직접 읽는다면, 페이지 파일을 `__root/<locale>/data.json` 위에 병합하세요.
9. 전역 가드가 로케일이나 사전을 읽는다면, 페이지 이동이 커밋되기 전에 실행되어도 되는지 확인하세요. 레이아웃이 이전 페이지의 파일에서 가져오던 키는 루트 파일로 옮기세요.
10. `nuxi generate` 출력이나 사이트맵 크롤링 결과를 전후로 비교하세요: `hreflang`, `x-default`, canonical, 페이지 목록은 의도적으로 바뀝니다.
11. 프레임워크 패키지의 import를 업데이트하세요: React, Solid, Preact 어댑터는 `/router`, Astro의 로더는 `/node`, 타입 플러그인은 `I18nTypesPlugin(o)`.
12. Astro의 경우, 설정만 복사하는 `src/middleware.ts`를 삭제하고 `pages/blog-hello/` 형식의 사전을 패턴에 맞게 이름을 바꾸세요.
13. `router-link-active`, `li button`, `▼`, 또는 이전 목 동작에 고정된 테스트를 업데이트하세요.

세부 사항과 모든 예외적인 경우: [업그레이드](/ko/guide/upgrade).

## 왜 중요한가 {#why-it-matters}

- **구조적으로 올바름:** 링크, 리디렉션, SEO 태그는 앱이 실제로 가진 라우트에서 나옵니다.
- **어디서나 하나의 답:** 빌드, 소스 모드, 개발 환경이 같은 사전을 제공하며, 모든 호출자가 하나의 감지 순서를 사용합니다.
- **도메인:** 두 번째 빌드 없이 모든 로케일 도메인을 위한 하나의 배포.
- **더 안전한 기본값:** 이스케이프된 params, 상한이 있는 캐시, 오리진에 머무는 링크.
- **더 적은 배포량:** 더 작은 사전 파일, 더 작은 라우팅 패키지, 그리고 한곳에 모인 공유 로직.
