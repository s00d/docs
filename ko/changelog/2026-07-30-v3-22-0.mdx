## Nuxt I18n Micro v3.22.0 — 포맷, 캐시 및 Translation Memory {#nuxt-i18n-micro-v3-22-0-—-formats-cache-&-translation-memory}

**날짜**: 2026-07-30

**버전**: `v3.22.0`

![v3.22.0 릴리스](/images/3.22.0.png)

**v3.22.0**을 발표합니다. 포매터 캐시를 갖춘 Vue I18n 스타일의 이름 있는 숫자/날짜 포맷, CDN 친화적인 번역 페이로드 캐싱(콘텐츠 지문 + `httpCacheDuration`), 그리고 런타임에 활성 사전을 읽고 교체할 수 있는 Translation Memory API가 포함되어 있습니다.

## 새로운 기능 {#what’s-new}

### 이름 있는 `numberFormats` / `datetimeFormats` + 포매터 캐시 {#named-numberformats-/-datetimeformats-+-formatter-cache}

Vue I18n과 호환되는 이름 있는 포맷과 더 빠른 Intl 서식 지정:

- 설정: 로케일별 `numberFormats` / `datetimeFormats`
- API: `$tn(1000, 'currency')`, `$td(date, 'short')` (+ 로케일 재정의 및 옵션 병합)
- `FormatService`는 `Intl.NumberFormat` / `DateTimeFormat` / `RelativeTimeFormat`을 로케일+옵션 기준으로 캐시합니다

[메서드 — `$tn` / `$td`](/ko/api/methods#$tn) 및 [모듈 옵션](/ko/api/module-options#numberformats)을 참고하세요.

### `dateBuild`의 기본값이 콘텐츠 지문으로 변경 {#datebuild-defaults-to-a-content-fingerprint}

예전에는 `/_locales` 요청의 `?v=`가 기본적으로 `Date.now()`였고, 응답은 1년 동안 `immutable`로 제공되었습니다. 그래서 번역이 하나도 바뀌지 않았더라도 다시 빌드할 때마다 모든 클라이언트의 사전이 무효화되었습니다.

이제 기본값은 레이어 순서대로 계산한 번역 소스의 SHA-256 지문입니다. 번역이 변경되지 않은 상태로 다시 빌드하면 같은 URL이 유지됩니다. `dateBuild`를 명시적으로 설정하면 여전히 그 값이 우선합니다. [모듈 옵션 — `dateBuild`](/ko/api/module-options#datebuild)를 참고하세요.

### `/_locales` 페이로드를 위한 `httpCacheDuration` {#httpcacheduration-for-/_locales-payloads}

내장 `/{apiBaseUrl}/:page/:locale/data.json` 라우트가 이제 브라우저와 CDN을 위한 HTTP `Cache-Control`을 전송합니다.

- 옵션: `httpCacheDuration` (초 단위, 기본값 `31536000` / 1년)
- 헤더: `Cache-Control: public, max-age=…, immutable`
- 기존 `dateBuild` 캐시 무효화(`?v=...`)와 함께 사용해도 안전하며, `0`이면 헤더를 비활성화합니다. 개발 모드에서는 적용되지 않습니다

`@nuxtjs/i18n` v10.2.0의 `experimental.httpCacheDuration`에 해당하는 기능으로, 명시적인 응답 헤더로 제공됩니다.

### 압축된 공개 페이로드 {#compressed-public-payloads}

이제 `nitro.compressPublicAssets`가 공개 디렉터리로 복사되는 번역 페이로드(`.gz` + `.br`)에도 적용됩니다. Nitro는 복사가 일어나기 전에 공개 에셋을 압축하기 때문에, 이전에는 페이로드가 정적 빌드에서 유일하게 압축되지 않은 부분이었습니다. 플레이그라운드 인덱스 기준으로 원본 6.65 MB 대 gzip 1.01 MB였습니다. 모듈은 여전히 스스로 압축을 활성화하지 않습니다. [성능](/ko/guide/performance#payload-size)을 참고하세요.

### `resolveTranslations()` 및 `setTranslation(key, value)` {#resolvetranslations-and-settranslationkey-value}

메모리에 있는 활성 번역 사전을 읽고 교체하기 위한 런타임 헬퍼:

- **`resolveTranslations()`**는 활성 로케일과 라우트에 대해 `$t()`가 읽는 전체 트리를 반환합니다. DevTools, 테스트, 런타임 편집기에 유용합니다. 두 번째 레이어가 활성 상태일 때(폴백 로케일 또는 Nuxt 페이지 전환 핫 리로드), 덤프는 `mergeTranslationLayers`를 통해 중첩 구조를 유지하며, 단일 트리로는 표현할 수 없는 스칼라 대 객체 충돌에 대해서만 평탄한 점 표기 키를 사용합니다.
- **`setTranslation(key, value)`**는 키의 값(최상위, 점 표기 경로, 객체, 문자열 또는 스칼라)을 교체합니다. 이것은 병합이 아니라 **교체**입니다. 형제 항목을 유지해야 한다면 `$mergeTranslations`를 사용하세요.
- `useI18n()`, `useNuxtApp()`, 그리고 `@i18n-micro/core`를 상속하는 프레임워크 i18n 인스턴스에서 사용할 수 있습니다.
- `@i18n-micro/test-utils`는 단위 테스트를 위한 대응 헬퍼 `resolveTranslations` / `setTranslation`을 추가합니다.

### Vue 패키지에서 `getAllTranslations()` 제거 {#getalltranslations-removed-from-vue-package}

활성 조회 트리에는 `resolveTranslations()`를 사용하세요. Vue에서 전체 저장소 덤프가 필요하면 `getStorage()` 또는 `getRouteCache()`를 사용하세요.

## 호환성이 깨지는 변경 사항 {#breaking-changes}

일반적인 사용에서는 공개 설정 영역 중 앱 코드 수정이 필요한 부분은 없습니다. 다음 사항은 런타임 내부에 직접 접근했던 경우에 중요합니다.

- **SSR 페이로드가 `useState('i18n-ssr-chunks')`에서 `nuxtApp.payload.data['i18n-ssr-chunks']`로 이동했습니다.** 여전히 SSR 중에 로드된 모든 `(locale, route)`에 대해 **전체 번역 청크**를 담고 있습니다. 이전과 같은 사전이지만, 프리렌더 시 Nuxt가 `_payload.json`으로 외부화할 수 있는 슬롯에 들어갑니다. 이제 `useState('i18n-ssr-chunks')`는 아무것도 반환하지 않습니다. 이런 방식으로 번역을 읽는 것은 공식적으로 지원된 적이 없지만, 캐시 API 문서에 설명되어 있었기 때문에 여기서 언급합니다.
- **`NuxtTranslationLoaderOptions`가 `setSsrChunk`를 노출합니다.** 로더는 서버에서 각 병합된 청크를 로드하면서 `payload.data`에 기록합니다. `getSsrChunks`는 사용되지 않습니다.
- **이제 `nitro.compressPublicAssets`가 복사된 페이로드 옆에 `.gz` / `.br`을 생성합니다.** 이 옵션을 활성화했다면 공개 출력에 파일이 더 많아집니다. 번역 디렉터리를 열거하는 배포 도구는 이를 고려해야 할 수 있습니다.
- **업그레이드 시 페이로드 URL이 한 번 변경됩니다.** `?v=`가 빌드 타임스탬프에서 콘텐츠 지문으로 바뀌기 때문입니다. 클라이언트는 업그레이드 후 첫 요청에서 사전을 다시 다운로드하고, 이후 배포에서는 이를 계속 유지합니다. 바로 이것이 목적입니다.
- **`@i18n-micro/vue`에서 `getAllTranslations()`가 제거되었습니다.** 대신 `resolveTranslations()` / `getStorage()` / `getRouteCache()`를 사용하세요.

## 버그 수정 {#bug-fixes}

- **`<i18n-switcher>`** — `disabled: true`인 로케일을 드롭다운에서 제외합니다. `$getLocales()`는 여러분의 코드를 위해 여전히 전체 목록을 반환하며, 내장 SEO/메타 출력은 비활성화된 로케일을 제외합니다.
- **스위처 스타일** — `cursor: not-allowed`가 `activeLinkStyle` / `customActiveLinkStyle`을 통해 **현재** 로케일에 적용됩니다. 하위 호환성을 위해 `customDisabledLinkStyle`을 복원했으며, 현재 로케일이 `disabled: true`일 때 스위처 버튼에 적용합니다.
- **개발 HMR** — 파일 내용이 바뀌지 않는 쓰기(편집기의 포커스 해제 시 저장, 포매터의 재작성)가 더 이상 재병합을 일으키지 않습니다. 루트 로케일 변경은 해당 로케일의 모든 페이지를 다시 빌드하므로, 아무 변화 없는 작업에 쓰기에는 비용이 컸습니다.
- **개발 HMR** — 루트 로케일이 변경되면 페이지를 하나씩 순서대로가 아니라 동시에 재병합합니다.
- **페이지 전환** — 같은 로케일 내 이동 시, 탐색할 때마다 비용이 큰 깊은 병합을 하는 대신 `page:transition:finish`까지 나가는 청크를 폴스루 레이어로 유지합니다.

## 왜 중요한가 {#why-it-matters}

- 더 무거운 스택을 끌어오지 않고도 Vue I18n 스타일의 서식 지정을 사용할 수 있습니다.
- 사전이 바뀌지 않았다면 다시 빌드해도 안정적으로 유지되는 CDN 친화적인 번역 URL.
- 실시간 사전을 검사하고 수정하기 위한 공식 런타임 API — DevTools, 테스트, 편집기에서 더 이상 비공개 헬퍼가 필요하지 않습니다.

전체 변경 로그는 릴리스와 함께 [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md)에 게시됩니다.

## 수정: `app.baseURL` + `strategy: 'prefix'` 사용 시 무한 리디렉션 루프 (#234) {#fix-infinite-redirect-loop-with-app-baseurl-+-strategy-‘prefix’-#234}

**날짜**: 2026-07-03

서버 측 리디렉션 플러그인(`06.redirect.ts`)이 이제 로케일 감지 전에 `getRequestURL(event).pathname`에서 `runtimeConfig.app.baseURL`을 제거합니다. 앱이 하위 경로에서 제공될 때 발생하던 `ERR_TOO_MANY_REDIRECTS`를 수정합니다(예: `/examples` → `/examples/ja`로 한 번만 이동하며, `/examples/ja/examples/ja/...`가 되지 않음).
