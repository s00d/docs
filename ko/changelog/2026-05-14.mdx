**날짜**: 2026-05-14

**버전**: `v3.20.0`

![v3.20.0 릴리스](/images/3.20.0.png)

이번 릴리스는 Nuxt 런타임을 전용 **`NuxtI18n`** 레이어로 리팩터링하고, 서버/클라이언트 리디렉션 처리를 분리하며, 여러 SSR/하이드레이션 회귀 문제를 수정합니다. 일반적인 앱에서는 공개 컴포저블과 `nuxt.config` 옵션이 그대로 유지됩니다.

## 새로운 기능 {#what’s-new}

### `NuxtI18n` 및 `NuxtTranslationLoader` {#nuxti18n-&-nuxttranslationloader}

런타임 i18n 로직이 단일 플러그인에서 역할이 분명한 클래스들로 옮겨졌습니다.

- **`NuxtI18n`** — 활성 번역 뷰 레이어(`$t`, `$has`, 로케일/라우트 컨텍스트, 전환 시 병합/정리)
- **`NuxtTranslationLoader`** — 청크를 로드하고, 내비게이션 시 컨텍스트를 전환하며, SSR 페이로드를 시드합니다
- **`createNuxtI18nPluginApi`** — 얇은 플러그인 인터페이스(`$switchLocale`, `$localeRoute` 등)

업데이트된 [캐시 및 저장소 아키텍처](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api)와 [성능](/ko/guide/performance)을 참고하세요.

### `useState('i18n-ssr-chunks')`를 통한 SSR 페이로드 {#ssr-payload-via-usestate‘i18n-ssr-chunks’}

SSR 번역은 `window.__I18N__` 스크립트 태그가 아니라 **Nuxt 상태**를 통해 직렬화됩니다.

1. 서버가 청크를 로드 → `useState('i18n-ssr-chunks')`
2. 클라이언트가 하이드레이션 → `translationStorage.seedFromSsrChunks()`
3. 첫 페인트 시 추가 요청 없음

레거시 `window.__I18N__` 읽기 경로는 **제거되었습니다**.

### 리디렉션 아키텍처 분리 {#redirect-architecture-split}

더 명확한 동작과 클라이언트 버벅임 감소를 위해 리디렉션이 이제 환경별로 처리됩니다.

| 환경    | 컴포넌트                      | 역할                                       |
| -------------- | ------------------------------ | ------------------------------------------ |
| **서버 SSR** | `06.redirect.ts` (서버 전용) | 렌더링 전 302, 404 검사, 쿠키 동기화 |
| **클라이언트 SPA** | `i18n-redirect.global.ts`      | 내비게이션 시 전역 라우트 미들웨어      |

클라이언트 리디렉션은 **대상 라우트**에서 로케일을 도출하고, **쿼리 문자열과 해시**를 유지하며, `redirects: false`(미들웨어 미등록)를 준수합니다. [로케일 감지 — 전략별 리디렉션](/ko/guide/locale-detection#redirects-per-strategy)을 참고하세요.

### `i18n:register` 훅 타이밍 {#i18nregister-hook-timing}

**`05.hooks`** 플러그인(`dependsOn: i18n-plugin-loader`)은 로더가 준비된 후 — 시작 시와 내비게이션 시 — `i18n:register`를 발생시키므로, 사용자 플러그인이 이벤트를 안정적으로 수신합니다. `hooks: false`로 비활성화할 수 있습니다. [이벤트](/ko/api/events)를 참고하세요.

### 빌드 시점 `defineI18nRoute` 추출 {#build-time-definei18nroute-extraction}

Vite unplugin이 빌드 시점에 페이지 `.vue` 파일을 스캔하여 `@i18n-micro/route-strategy`용 라우트 메타를 작성합니다. `script setup`의 런타임 `$defineI18nRoute`는 개발 환경과 인라인 구성을 위해 유지됩니다. [컴포넌트별 번역](/ko/guide/per-component-translations)을 참고하세요.

## 버그 수정 {#bug-fixes}

- **SSR 하이드레이션** — `Object.freeze` 전에 반응형 SSR 청크를 복제합니다(클라이언트 `#locale` / 404 충돌 수정)
- **로케일 전환** — 로케일 변경 시 뷰 레이어를 교체합니다(이전 로케일의 오래된 키가 남지 않음)
- **클라이언트 리디렉션** — 대상 라우트에서 로케일을 가져오며, 리디렉션 시 쿼리/해시를 유지합니다
- **`has()`** — 활성 로케일만 검사합니다. 폴백은 `$has()`가 아닌 `$t()`에서 적용됩니다
- **`defineI18nRoute` 메타** — 플러그인 인스턴스별 캐시, 가장 긴 `rootDir` 일치, `pages/index`와 `pages/index/index` 경로의 올바른 구분

## 호환성을 깨는 변경 사항 {#breaking-changes}

표준 `nuxt.config` + 컴포저블 사용에는 없습니다. 내부 경로와 SSR 주입 메커니즘이 변경되었으므로, 수동 `window.__I18N__` 주입에 의존하던 앱은 대신 Nuxt 페이로드 / 모듈 API를 사용해야 합니다.

## 중요한 이유 {#why-it-matters}

- **더 안정적인 SSR → 클라이언트 전달** — 임시방편적인 전역 변수 대신 Nuxt 네이티브 상태 사용
- **더 명확한 리디렉션 모델** — 페인트 전 서버 302, 필요한 곳에서만 클라이언트 미들웨어
- **더 쉬운 유지보수** — 런타임을 테스트 가능한 단위로 분리하고 집중된 회귀 테스트 추가

전체 변경 로그는 릴리스와 함께 [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md)에 게시됩니다.
