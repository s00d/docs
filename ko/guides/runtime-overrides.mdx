# 런타임 i18n 오버라이드

하나의 빌드 산출물을 환경마다 다른 로케일 기본값으로 실행해야 할 때(예: 서로 다른 테넌트 인스턴스) 이 가이드를 사용하세요.

## 런타임에서 오버라이드할 수 있는 항목

이 모듈은 다음 항목에 대해 안전한 런타임 오버라이드를 지원합니다:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

이러한 오버라이드는 빌드 타임의 `.nuxt/i18n.strategy.mjs` 및 `.nuxt/i18n.config.mjs` 설정 위에 적용됩니다.

## 런타임에서 오버라이드할 수 없는 항목

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`)는 생성된 라우트 동작에 영향을 미치므로 빌드 타임에 결정됩니다.

런타임 strategy 오버라이드를 전달하면 무시되고 경고가 표시됩니다.

## RuntimeConfig 기반 오버라이드

`runtimeConfig.public.i18nRuntime` 아래에 런타임 값을 제공합니다:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## 환경 변수 오버라이드

환경 변수로도 오버라이드를 구성할 수 있습니다:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (쉼표로 구분, 예: `fr,it`)

폴백 별칭도 지원됩니다:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## 검증 규칙

런타임에 모듈은 잘못된 상태를 방지하기 위해 오버라이드를 검증합니다:

- 모든 로케일을 비활성화할 수 없습니다.
- `defaultLocale`은 활성화된 로케일을 가리켜야 합니다.
- `fallbackLocale`은 선언된 로케일에 존재해야 합니다.

오버라이드가 유효하지 않으면 모듈은 안전한 값을 유지하고 경고를 기록합니다.

## 다중 인스턴스 배포 시 참고 사항

이 런타임 기능은 재빌드 없이 인스턴스별 로케일 활성화와 기본값 설정을 위해 설계되었습니다.

인스턴스마다 다른 URL 전략(`no_prefix` vs `prefix`)이 필요하다면, 각 전략별로 별도의 빌드를 사용하세요.

## 비활성화된 로케일과 정적 페이로드

`runtimeConfig.public.i18nRuntime.disabledLocales`는 라우팅, 스위처, Nitro 페이로드 **핸들러**를 업데이트하지만, Nitro는 해당 핸들러보다 **먼저** `public/` 아래 파일을 제공합니다.

`translationPayloads.publicAssets`(또는 Node SSR의 강제 public 복사)가 이미 `/_locales/\{page\}/\{locale\}/data.json`을 작성했다면, 런타임 비활성화로는 그 파일을 숨길 수 없습니다. premerge가 해당 로케일의 정적 페이로드를 생성하지 않도록 빌드 시에 `locale.disabled: true`를 사용하는 것이 좋습니다.
