# i18n 라우팅에서 정적 파일 제외

## 개요

기본적으로 nuxt-i18n-micro는 일반적인 정적 파일을 i18n 라우팅 처리에서 자동으로 제외합니다. 그러나 사용자 정의 제외 패턴을 설정하여 특정 경로가 i18n 시스템에 의해 처리되지 않도록 할 수도 있습니다.

## 내장 제외 항목

이 모듈은 다음 파일 유형과 패턴을 자동으로 제외합니다:

- **사이트맵**: `/sitemap*.xml`, `/sitemap-en.xml` 등
- **SEO 파일**: `/robots.txt`, `/favicon.ico`
- **PWA 파일**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **정적 자산**: `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot` 같은 확장자를 가진 파일
- **Nuxt 내부 경로**: `__`로 시작하는 모든 경로 (예: `/__nuxt/`)

## 사용자 정의 제외 패턴

`excludePatterns` 옵션을 사용하여 사용자 정의 제외 패턴을 정의할 수 있습니다:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## 패턴 유형

### 문자열 패턴

- **정확한 일치**: `'/api/health'` - 정확히 `/api/health`와 일치
- **접두사 일치**: `'/admin'` - `/admin`과 `/admin/dashboard`와 일치
- **와일드카드**: `'/api/*'` - `/api/users`와 일치하지만 `/api/users/123`은 아님
- **깊은 와일드카드**: `'/admin/**'` - `/admin/users`와 `/admin/users/123`과 일치

### 정규 표현식

복잡한 패턴 일치를 위해 RegExp 객체를 사용합니다:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## 사용 사례

### SEO 파일

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API 라우트

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### 관리자 패널

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### 정적 자산

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## 작동 방식

1. **서버 미들웨어**: Nitro 미들웨어가 먼저 실행되어 제외 패턴을 확인합니다
2. **페이지 처리**: 페이지 해결 중 제외된 경로가 건너뛰어집니다
3. **캐치올 라우트**: 대체 라우트가 처리 전에 제외를 확인합니다
4. **사전 렌더링**: 제외된 경로는 사전 렌더링된 라우트에 포함되지 않습니다

## 성능 영향

- 제외 검사는 최적화되어 있으며 요청 수명 주기 초기에 실행됩니다
- 내장 패턴은 효율적인 정규 표현식 일치를 사용합니다
- 사용자 정의 패턴은 캐시되고 재사용됩니다
- 제외된 경로에 대한 성능 오버헤드는 최소한입니다

## 문제 해결

### 정적 파일이 여전히 가로채짐

1. **패턴 구문 확인**: 패턴이 정확한 경로 구조와 일치하는지 확인하세요
2. **복잡한 패턴에는 정규 표현식 사용**: 문자열 와일드카드에는 제한이 있습니다
3. **패턴 테스트**: 실제 요청 경로를 확인하기 위해 브라우저 개발자 도구를 사용하세요
4. **순서 확인**: 제외 패턴이 다른 i18n 설정 전에 정의되어 있는지 확인하세요

### 패턴이 작동하지 않음

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### 디버그 모드

제외 처리를 보려면 디버그 모드를 활성화합니다:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

이렇게 하면 콘솔에서 제외 결정을 로그합니다.

## 임시 방편에서 마이그레이션

라우트 규칙이나 미들웨어 같은 임시 방편을 사용했다면, 이제 `excludePatterns`로 대체할 수 있습니다:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

새 접근 방식은 더 안정적이며 라우팅 시스템의 여러 수준에서 작동합니다.
