# 성능 테스트 결과

## 프로젝트 정보

### 설명

하나의 공유 사전 프로필 하에서 **plain Nuxt**(i18n 모듈이 없는 기준), **i18n-micro**, **`@nuxtjs/i18n` v10.6**을 비교합니다.

초점: 빌드 시간, 최고 RSS, 배포 가능한 **code vs translations vs total**, 그리고 Artillery + Autocannon 하에서의 서버 동작.

### 방법론 참고 사항

- 지표는 **fixture당 연속 3회 실행의 평균**입니다(fixture A ×3, 그다음 B ×3, 그다음 C ×3 — 교차 실행 아님).
- **번역**에는 `locales/` / `_locales/` / `translations/` 아래의 로케일 JSON, `chunks/raw/` 아래의 모든 것, 그리고 일치하는 로케일 청크가 포함됩니다. `@nuxtjs/i18n` "translations: 0 B"와 큰 "code" 열을 보여주던 이전 보고서는 메시지 청크를 앱 코드로 계산했습니다.
- **plain-nuxt**는 동일한 리프 볼륨을 정적 `public/translations` JSON으로 제공합니다(정적 JS import 아님). Artillery 하에서는 그 기준선이 I/O 중심입니다. 이는 "i18n 오버헤드"가 아니라 요청당 대용량 JSON을 가져오는 비용입니다.

### 실행 횟수

아래의 모든 지표는 **3회 실행의 평균**입니다.
