# 🔥 Firebase AppHosting 배포

## 📖 소개

Firebase AppHosting은 서버리스 인프라로 Nuxt 애플리케이션을 배포하기 위한 강력한 플랫폼입니다. 그러나 `nuxt-i18n-micro`로 애플리케이션을 배포할 때, 번역 JSON 파일이 제공되는 방식과 관련된 특정 문제가 발생할 수 있습니다. 이 가이드는 프로덕션에서 번역이 올바르게 작동하도록 하는 포괄적인 솔루션을 제공합니다.

## ⚠️ 일반적인 문제

### 번역 파일이 적용되지 않음

**증상:**

- ✅ 번역이 개발(`nuxt dev`)에서 완벽하게 작동합니다.
- ❌ Firebase AppHosting에 배포 후 JSON 파일은 로드되지만 번역이 적용되지 않습니다.
- ❌ 콘솔에 오류가 표시되지 않습니다.
- ❌ 네트워크 탭에 번역 파일은 보이지만 `application/json` 대신 `Content-Type: text/html`이 잘못 지정됩니다.

**근본 원인:**

Firebase AppHosting(및 Nitro 사전 렌더링을 사용하는 다른 플랫폼)은 사전 렌더링된 JSON 파일을 잘못된 MIME 타입으로 제공할 수 있습니다. 브라우저가 `Content-Type: text/html`로 JSON 파일을 받으면 이를 제대로 파싱할 수 없어 번역이 조용히 실패합니다.

## ✅ 솔루션

### 솔루션 1: 라우트 규칙 설정 (권장)

가장 직접적인 솔루션은 `nuxt.config.ts`에 번역 라우트를 위한 명시적 헤더를 추가하는 것입니다:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**이점:**

- ✨ 간단한 설정
- 🚀 적절한 캐싱으로 성능 향상
- 🔒 모든 배포 플랫폼에서 작동

### 솔루션 2: 사용자 정의 API 기본 URL

사용자 정의 `apiBaseUrl`(경로 접두사만)을 사용하는 경우, 그에 따라 라우트 규칙을 조정하세요:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### 솔루션 3: Firebase 특정 설정

프로젝트 루트에 `firebase.json` 파일을 만들거나 업데이트합니다:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```


### 솔루션 4: Firebase Functions 설정

Firebase Functions 배포의 경우, `functions/package.json`에 필요한 종속성이 포함되어 있는지 확인하세요:

```json
{
  "name": "functions",
  "type": "module",
  "engines": {
    "node": "18"
  },
  "dependencies": {
    "firebase-admin": "^12.0.0",
    "firebase-functions": "^5.0.0"
  }
}
```

## 🔍 디버깅

### 디버그 모드 활성화

문제를 식별하기 위해 디버그 로깅을 추가합니다:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

이는 다음에 대한 자세한 로그를 출력합니다:

- 📝 번역 파일 로딩
- 🔄 캐시 작업
- ⚠️ 로딩 오류

### 네트워크 탭 확인

1. DevTools → Network 탭을 엽니다.
2. "data.json"으로 필터링합니다.
3. 번역 파일 요청을 클릭합니다.
4. **응답 헤더** 확인:
   - ✅ `Content-Type: application/json` (올바름)
   - ❌ `Content-Type: text/html` (잘못됨 - 수정 필요)

### 사전 렌더 출력 확인

빌드 후 번역 파일이 생성되었는지 확인합니다:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

각 페이지 아래의 각 로케일에 대해 `data.json`을 볼 수 있어야 합니다.

## 🚀 빌드 설정

### Nitro 프리셋

Firebase AppHosting의 경우, 올바른 프리셋을 사용하고 있는지 확인하세요:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### 사전 렌더링 설정

최적의 성능을 위해 사전 렌더링을 설정합니다:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

## ✅ 검증 체크리스트

수정 사항을 적용한 후 모든 것이 작동하는지 확인하세요:

- [ ] 빌드가 오류 없이 완료됩니다.
- [ ] 번역 JSON 파일이 `.output/public/_locales/\{page\}/\{locale\}/data.json`에 있습니다.
- [ ] 네트워크 탭에서 번역 파일에 대한 `Content-Type: application/json`이 표시됩니다.
- [ ] 첫 페이지 로드 시 번역이 올바르게 표시됩니다.
- [ ] 콘솔에 하이드레이션 불일치가 없습니다.
- [ ] 언어 전환이 올바르게 작동합니다.
- [ ] SEO 메타 태그가 제대로 생성됩니다.

## 🔄 배포 워크플로

### 1. 빌드 준비

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. Firebase에 배포

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. 배포 확인

1. 배포된 사이트를 방문합니다.
2. DevTools → Network 탭을 엽니다.
3. 페이지로 이동합니다.
4. `/_locales/index/en/data.json`(또는 기본 로케일)이 다음과 함께 로드되는지 확인합니다:
   - 상태: 200
   - Content-Type: application/json
   - 응답에 유효한 JSON이 포함됨

## 🔧 문제 해결

### 문제: 번역 파일에 대한 404 오류

**해결책:** 번역 파일이 출력 디렉터리로 복사되고 있는지 확인하세요:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### 문제: 일부 페이지에서는 번역이 작동하지만 다른 페이지에서는 작동하지 않음

**해결책:** 페이지별 번역이 생성되고 있는지 확인하세요:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

페이지별 번역이 누락된 경우, `disablePageLocales`가 `true`로 설정되지 않았는지 확인하세요:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### 문제: 느린 번역 로딩

**해결책:** 캐싱 및 사전 로딩 최적화:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## ⚡ 성능 최적화

### 압축 활성화

Firebase는 자동으로 Gzip/Brotli 압축을 처리하지만, 빌드가 최적화되었는지 확인하세요:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### 번역 지연 로드

`Nuxt I18n Micro`는 페이지별로 번역을 자동으로 지연 로드합니다. 번역은 필요할 때만 로드되어 초기 번들 크기를 줄입니다. 이는 내장된 기능이므로 추가 설정이 필요하지 않습니다.

추가로 최적화하려면:

- 페이지별 번역을 활성화하기 위해 `disablePageLocales: false`(기본값)를 사용하세요.
- 루트 레벨 번역을 최소한으로 유지하세요.
- 페이지 콘텐츠에는 라우트별 번역 파일을 사용하세요.

<Tip>
모듈은 버전 **v3.0.0+**부터 적절한 `Content-Type` 헤더를 자동으로 설정합니다. 문제가 있는 경우 최신 버전으로 업데이트하세요:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
