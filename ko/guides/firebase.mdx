# 🔥 Firebase AppHosting 배포

## 📖 소개

Firebase AppHosting은 서버리스 인프라를 사용하여 Nuxt 애플리케이션을 배포하기 위한 강력한 플랫폼입니다. 그러나 `nuxt-i18n-micro`를 사용하여 애플리케이션을 배포할 때 번역 JSON 파일이 제공되는 방식과 관련된 특정 문제가 발생할 수 있습니다. 이 가이드는 프로덕션에서 번역이 올바르게 작동하도록 하는 포괄적인 해결책을 제공합니다.

## ⚠️ 일반적인 문제

### 번역 파일이 적용되지 않음

**증상:**

- ✅ 개발 환경(`nuxt dev`)에서는 번역이 완벽하게 작동합니다.
- ❌ Firebase AppHosting에 배포한 후에는 JSON 파일이 로드되지만 번역이 적용되지 않습니다.
- ❌ 콘솔에 오류가 표시되지 않습니다.
- ❌ Network 탭에서 번역 파일이 보이지만 `application/json` 대신 잘못된 `Content-Type: text/html`을 가지고 있습니다.

**근본 원인:**

Firebase AppHosting(및 Nitro 사전 렌더링을 사용하는 다른 플랫폼)은 잘못된 MIME 타입으로 사전 렌더링된 JSON 파일을 제공할 수 있습니다. 브라우저가 `Content-Type: text/html`로 JSON 파일을 수신하면 이를 제대로 파싱할 수 없어 번역이 자동으로 실패합니다.

## ✅ 해결책

### 해결책 1: 라우트 규칙 구성 (권장)

가장 간단한 해결책은 `nuxt.config.ts`에서 번역 라우트에 대한 명시적인 헤더를 추가하는 것입니다:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**이점:**

- ✨ 간단한 구성
- 🚀 적절한 캐싱으로 성능 향상
- 🔒 모든 배포 플랫폼에서 작동

### 해결책 2: 사용자 정의 API Base URL

사용자 정의 `apiBaseUrl`(경로 접두사만)을 사용하는 경우 라우트 규칙을 적절히 조정하세요:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### 해결책 3: Firebase 전용 구성

프로젝트 루트에 `firebase.json` 파일을 만들거나 업데이트하세요:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```

### 해결책 4: Firebase Functions 구성

Firebase Functions 배포의 경우 `functions/package.json`에 필요한 종속성이 포함되어 있는지 확인하세요:

```json
{
  "name": "functions",
  "type": "module",
  "engines": {
    "node": "18"
  },
  "dependencies": {
    "firebase-admin": "^12.0.0",
    "firebase-functions": "^5.0.0"
  }
}
```

## 🔍 디버깅

### 디버그 모드 활성화

문제를 식별하기 위해 디버그 로깅을 추가하세요:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

이렇게 하면 다음에 대한 자세한 로그가 출력됩니다:

- 📝 번역 파일 로드
- 🔄 캐시 작업
- ⚠️ 로드 오류

### Network 탭 확인

1. DevTools → Network 탭 열기
2. "data.json"으로 필터링
3. 번역 파일 요청 클릭
4. **응답 헤더** 확인:
   - ✅ `Content-Type: application/json` (올바름)
   - ❌ `Content-Type: text/html` (잘못됨 - 수정 필요)

### 사전 렌더링 출력 확인

빌드 후 번역 파일이 생성되었는지 확인하세요:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

각 로케일과 페이지에 대해 `data.json`을 볼 수 있어야 합니다.

## 🚀 빌드 구성

### Nitro 프리셋

Firebase AppHosting의 경우 올바른 프리셋을 사용하고 있는지 확인하세요:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### 사전 렌더링 구성

최적의 성능을 위해 사전 렌더링을 구성하세요:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

## 📋 전체 예제 구성

다음은 Firebase AppHosting을 위한 완전한 작동 구성입니다:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'es', iso: 'es-ES', dir: 'ltr' },
      { code: 'it', iso: 'it-IT', dir: 'ltr' },
      { code: 'pt', iso: 'pt-PT', dir: 'ltr' },
      { code: 'ru', iso: 'ru-RU', dir: 'ltr' },
      { code: 'zh', iso: 'zh-CN', dir: 'ltr' },
      { code: 'ko', iso: 'ko-KR', dir: 'ltr' },
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
    debug: false, // Enable in development if needed
  },

  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },

  nitro: {
    preset: 'firebase-app-hosting',
    prerender: {
      crawlLinks: true,
      routes: ['/'],
    },
  },
})
```

## ✅ 확인 체크리스트

수정 사항을 적용한 후 모든 것이 작동하는지 확인하세요:

- [ ] 빌드가 오류 없이 완료됨
- [ ] 번역 JSON 파일이 `.output/public/_locales/\{page\}/\{locale\}/data.json`에 있음
- [ ] Network 탭에 번역 파일에 대해 `Content-Type: application/json`이 표시됨
- [ ] 첫 페이지 로드 시 번역이 올바르게 표시됨
- [ ] 콘솔에 하이드레이션 불일치가 없음
- [ ] 언어 전환이 올바르게 작동함
- [ ] SEO 메타 태그가 제대로 생성됨

## 🔄 배포 워크플로우

### 1. 빌드 준비

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. Firebase에 배포

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. 배포 확인

1. 배포된 사이트 방문
2. DevTools → Network 탭 열기
3. 페이지로 이동
4. `/_locales/index/en/data.json`(또는 기본 로케일)이 다음과 함께 로드되는지 확인:
   - 상태: 200
   - Content-Type: application/json
   - 응답에 유효한 JSON 포함

## 🔧 문제 해결

### 문제: 번역 파일에 대한 404 오류

**해결책:** 번역 파일이 출력 디렉터리로 복사되고 있는지 확인하세요:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### 문제: 일부 페이지에서는 번역이 작동하지만 다른 페이지에서는 작동하지 않음

**해결책:** 페이지별 번역이 생성되고 있는지 확인하세요:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

페이지별 번역이 누락된 경우 `disablePageLocales`가 `true`로 설정되어 있지 않은지 확인하세요:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### 문제: 번역 로드가 느림

**해결책:** 캐싱 및 프리로드를 최적화하세요:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## ⚡ 성능 최적화

### 압축 활성화

Firebase는 자동으로 Gzip/Brotli 압축을 처리하지만, 빌드가 최적화되어 있는지 확인하세요:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### 지연 로드 번역

`Nuxt I18n Micro`는 페이지별로 번역을 자동으로 지연 로드합니다. 번역은 필요할 때만 로드되어 초기 번들 크기가 줄어듭니다. 이는 기본 제공 기능으로 추가 구성이 필요 없습니다.

추가 최적화를 위해:

- 페이지별 번역을 활성화하려면 `disablePageLocales: false`(기본값)를 사용하세요.
- 루트 레벨 번역을 최소한으로 유지하세요.
- 페이지 콘텐츠에는 라우트별 번역 파일을 사용하세요.

<Tip>
모듈은 **v3.0.0+** 버전부터 적절한 `Content-Type` 헤더를 자동으로 설정합니다. 문제가 발생하면 최신 버전으로 업데이트하세요:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
