`@i18n-micro/solid`는 SolidJS 앱에 시그널 기반 i18n 인스턴스, 프로바이더, `useI18n()`, 그리고 네 개의 컴포넌트를 제공합니다. Nuxt로 빌드하지 않는 Solid 앱에서 사용하세요. JSX나 이펙트 안에서 `t()`를 읽으면 로케일, 라우트, 사전을 추적합니다. 공통 모델은 [프레임워크](/ko/integrations/overview)에 있습니다.

## 설치 {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

피어 의존성: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (선택 사항, `@i18n-micro/solid/router`에만 필요). Solid 2는 아직 지원되지 않습니다.

## 설정 {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>`는 `i18n`, `locales`, `defaultLocale`, `routingStrategy`를 받습니다. 생략된 prop은 인스턴스를 포함해 바깥 프로바이더의 값을 유지합니다. `getLocaleName()`과 `<I18nSwitcher>`는 `locales`를 읽으며, 이것이 없으면 나열할 것이 없습니다. 옵션은 [인스턴스](/ko/integrations/overview#the-instance)에 있습니다. 인스턴스는 [런타임](/ko/integrations/runtime-package)의 인스턴스이며, 그 스토어 위에 하나의 시그널이 있습니다.

## 번역하기 {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Solid가 추적할 수 있도록 메서드는 JSX나 이펙트 안에서 호출하세요. `localePath`와 `getLocale`도 마찬가지입니다. 컴포넌트 본문에서 한 번 읽은 값은 업데이트되지 않습니다. 인스턴스에서는 `i18n.locale`과 `i18n.currentRoute`로 추적하세요: `i18n.getLocale()`은 쓰기 작업이 읽기 때문에 일반 함수로 유지됩니다. 로케일 읽기는 로케일 변경에만 반응하므로, 로케일을 읽고 사전을 로드하는 이펙트는 한 번만 실행됩니다. props를 구조 분해하거나 `t('key')`의 결과를 일반 변수에 보관하지 마세요.

`useI18n()`은 `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale`(접근자: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache`, `instance`를 반환합니다.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## 로케일 전환하기 {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

전환은 아무것도 로드하지 않습니다. 먼저 해당 로케일의 사전을 추가하세요.

`<I18nGroup>`은 함수 자식에 접두사가 붙은 `t`를 전달합니다. 그 안의 `<I18nT>`와 `t()`에는 접두사가 붙지 않습니다:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## 라우팅 {#routing}

`@solidjs/router` 어댑터는 메인 엔트리가 라우터를 import하지 않도록 하위 경로에 있습니다. `useNavigate`와 `useLocation`이 동작하는 라우터 아래, 일반적으로 라우터의 `root`에서 호출하세요:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

어댑터는 기본 로케일을 제외한 모든 로케일에 접두사를 붙이며(`/about`, `/de/about`), `<I18nLink>`를 라우터의 `<A>`로 렌더링합니다. `getCurrentPath`는 라우터의 반응형 location을 읽으므로 활성 링크와 스위처가 이를 따릅니다. 사용자 정의 전략도 그곳에서 시그널을 읽으면 같은 효과를 얻습니다. 인수 순서에 주의하세요: `(locales, defaultLocale, navigate, location)`. 다른 라우터의 경우 `getCurrentPath`, `push`, `replace`(모두 필수)를 가진 어댑터를 작성하세요 — [라우터 어댑터](/ko/integrations/overview#router-adapter)를 참고하세요.

## SSR {#ssr}

서버 렌더링을 위해서는 `vite-plugin-solid`로 빌드하세요: 패키지의 `solid` export 조건이 소스를 전달하므로 서버용으로 컴파일됩니다. 미리 빌드된 `dist`는 브라우저 전용입니다. 인스턴스에는 `destroy()`가 없습니다. 앱마다 하나, 또는 서버에서는 요청마다 하나를 만들고 가비지 컬렉션되도록 두세요.
