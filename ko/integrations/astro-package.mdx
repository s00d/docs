`@i18n-micro/astro`는 서버에서 Astro 페이지를 번역합니다. 미들웨어가 URL에서 로케일을 선택하고 요청별 인스턴스를 `Astro.locals`에 넣으며, `useI18n(Astro)`가 이를 읽습니다. 로케일 접두사 URL(`/about`, `/fr/about`)과 공유 JSON 사전이 필요한 Astro 사이트에서 사용하세요. `.astro` 컴포넌트, 방문자의 언어로 이동하는 홈 페이지 리디렉션, `hreflang` 태그, 그리고 [아일랜드](/ko/integrations/astro-islands)용 props를 얻을 수 있습니다.

## 설치 {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/astro
```

```bash npm
npm install @i18n-micro/astro
```

```bash yarn
yarn add @i18n-micro/astro
```

</CodeGroup>

피어 의존성: `astro` `^5.0.0 || ^6.0.0 || ^7.0.0`. 선택 사항이며 [아일랜드](/ko/integrations/astro-islands)에만 필요: `vue` `^3.3.0`, `react` `^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`, `preact` `^10.0.0 || ^11.0.0`, `svelte` `^4.0.0 || ^5.0.0`.

## 설정 {#setup}

통합을 추가하세요. 사전을 서버에 번들링하고 미들웨어를 설치하므로 `src/middleware.ts`가 필요하지 않습니다:

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import node from '@astrojs/node'
import { i18nIntegration } from '@i18n-micro/astro'

export default defineConfig({
  output: 'server',
  adapter: node({ mode: 'standalone' }),
  integrations: [
    i18nIntegration({
      locale: 'en',
      fallbackLocale: 'en',
      locales: [
        { code: 'en', iso: 'en-US', displayName: 'English' },
        { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
        { code: 'fr', iso: 'fr-FR', displayName: 'Français' },
      ],
      translationDir: 'src/locales',
    }),
  ],
})
```

사전은 빌드 시 코드가 됩니다. 서버는 디스크를 읽지 않으므로 엣지(Cloudflare, Vercel Edge)에서도 실행됩니다. `astro dev`에서는 파일을 편집하면 다음 요청에 적용됩니다.

### 통합 옵션 {#integration-options}

| 옵션 | 기본값 | 참고 |
| --- | --- | --- |
| `locale` | 필수 | 기본 로케일. |
| `fallbackLocale` | `locale` | |
| `locales` | `[]` | 전체 `Locale` 객체. `disabled`인 로케일은 어떤 URL의 로케일도 아니며 리디렉션 대상도 아닙니다. `iso`는 코드가 언어 태그가 아닐 때 복수형 규칙이 따르는 태그입니다(`ua` → `uk-UA`). |
| `translationDir` | 없음 | 서버에 번들링되는 폴더, 프로젝트 루트 기준. |
| `disablePageLocales` | `false` | 페이지 파일을 루트 번역으로 취급합니다. |
| `autoDetect` | `true` | 홈 페이지 리디렉션, [로케일 감지](#locale-detection) 참고. |
| `redirectToDefault` | `false` | 다른 로케일을 선호하는 것이 없어도 `/`가 리디렉션됩니다. |
| `localeCookie` | `'i18n-locale'` | `null`이면 쿠키를 비활성화합니다. |
| `missingWarn` | `false` | |
| `middleware` | `true` | `false`: 미들웨어를 직접 작성합니다. 아래 참고. |

런타임 설정은 `virtual:i18n-micro/config`(`config.base`는 Astro의 `base`, `config.localeCodes`는 활성화된 코드)에, 사전은 `virtual:i18n-micro/messages`에 게시됩니다.

### 직접 작성하는 미들웨어 {#your-own-middleware}

복수형 규칙, 누락 키 핸들러, 라우터 어댑터는 설정 프로세스에서 서버 번들로 넘어갈 수 없습니다. 이런 경우 `middleware: false`를 전달하고 `src/middleware.ts`를 작성하세요. 그러면 Astro의 `i18n` 설정이 `routing: 'manual'`로 자동 설정되어 `Astro.currentLocale`과 `astro:i18n`이 동작합니다. Astro는 `src/middleware.ts` 없이 해당 설정을 허용하지 않으므로, 통합 자체의 미들웨어에서는 동작하지 않습니다.

```ts
// src/middleware.ts
import { config } from 'virtual:i18n-micro/config'
import { messages } from 'virtual:i18n-micro/messages'
import { createAstroRouterAdapter, createI18n, createI18nMiddleware, localeIsoMap } from '@i18n-micro/astro'

const i18n = createI18n({
  locale: config.defaultLocale,
  fallbackLocale: config.fallbackLocale,
  localeIso: localeIsoMap(config.locales),
  messages: messages.root,
  routeMessages: messages.routes,
  plural: myPluralRule,
})

export const onRequest = createI18nMiddleware({
  i18n,
  defaultLocale: config.defaultLocale,
  locales: config.localeCodes,
  localeObjects: config.locales,
  autoDetect: config.autoDetect,
  redirectToDefault: config.redirectToDefault,
  localeCookie: config.localeCookie,
  base: config.base,
  routingStrategy: createAstroRouterAdapter(config.locales, config.defaultLocale),
})
```

대신 런타임에 폴더를 읽으려면 `@i18n-micro/astro/node`에 있는 `loadTranslationsFromDir`와 `loadTranslationsIntoI18n`을 사용하세요(Node 전용).

### 미들웨어 옵션 {#middleware-options}

| 옵션 | 기본값 | 참고 |
| --- | --- | --- |
| `i18n` | 필수 | 전역 인스턴스. 각 요청은 `i18n.fork(locale)`를 받으며, 사전이 몇 개이든 비용은 같습니다. |
| `defaultLocale` | 필수 | |
| `locales` | 필수 | 로케일 코드. |
| `localeObjects` | `{ code }` 형태의 `locales` | 컴포넌트와 SEO를 위한 전체 `Locale` 객체. |
| `autoDetect` | `true` | 홈 페이지 리디렉션, [로케일 감지](#locale-detection) 참고. |
| `redirectToDefault` | `false` | 다른 로케일을 선호하는 것이 없어도 `/`가 라우팅 전략이 해석한 기본 로케일의 홈으로 리디렉션됩니다. |
| `localeCookie` | `'i18n-locale'` | `null`이면 쿠키를 비활성화합니다. |
| `routingStrategy` | 기본값 제외 접두사 | 라우터 어댑터. 생략된 메서드는 기본 어댑터에서 가져옵니다. |
| `base` | 없음 | Astro의 `base`: `config.base`. |

페이지 파일(`src/locales/pages/blog/post/de.json`)은 라우트 `blog-post`입니다: 페이지 경로를 `-`로 연결한 것입니다.

## 번역하기 {#translate}

```astro
---
// src/pages/index.astro
import { useI18n } from '@i18n-micro/astro'
import I18nT from '@i18n-micro/astro/i18n-t'

const { t, tc, locale } = useI18n(Astro)
---

<h1>{t('greeting', { name: 'Ada' })}</h1>
<p>{tc('apples', 3)}</p>
<I18nT keypath="welcome" tag="p" />
<p>{locale}</p>
```

`useI18n(Astro)`는 `locale`, `defaultLocale`, `locales`, `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `getRoute`, `getRouteName(path?)`, `getLocaleFromPath(path?)`, `switchLocalePath(locale)`, `localizePath(path, locale?)`, `getBasePath(url?)`, `getI18n`, `addTranslations`, `addRouteTranslations`, `mergeTranslations`, `clearCache`를 반환합니다. 미들웨어가 실행되지 않았다면 예외를 던집니다. 헬퍼 `getI18n`, `getLocale`, `getDefaultLocale`, `getLocales`도 같은 `Astro.locals`를 읽습니다.

라우트 이름은 로케일을 제외한 라우트에서 나옵니다: `/fr/blog/post` → `blog-post`, 그리고 `src/pages/blog/[slug].astro`의 모든 URL → `blog-slug`이므로, 하나의 폴더 `locales/pages/blog-slug/`가 이들 모두를 담당합니다. `[...path]`는 `path`입니다. Astro의 `base` 아래에서 헬퍼는 사이트의 URL을 받고 반환합니다: `switchLocalePath`와 `localizePath`는 이를 포함하고, `getBasePath`는 포함하지 않습니다. `Astro.rewrite`가 base 없는 경로를 받기 때문입니다.

### 컴포넌트 {#components}

`@i18n-micro/astro/<name>`(또는 `@i18n-micro/astro/components/<name>.astro`)에서 import하세요:

| 컴포넌트 | Props |
| --- | --- |
| `i18n-t` | `keypath`, `params`, `plural`, `number`, `date`, `relativeDate`, `tag`(`span`, 모든 태그), `html`, `hideIfEmpty`, `defaultValue`. 다른 속성은 그대로 전달됩니다. `html`을 사용하면 모든 분기의 결과가 HTML로 렌더링되고 `params`는 이스케이프됩니다. 슬롯은 없습니다 |
| `i18n-link` | `href`, `locale`(대상 로케일, 기본값은 현재), `class`. 다른 속성은 그대로 전달됩니다. 외부 URL, `#hash`, `?query`는 작성한 그대로 유지되며, 라우트는 쿼리, 해시, 후행 슬래시를 유지합니다 |
| `i18n-switcher` | `class`, `activeClass`(`'active'`), `customLabels`. 활성화된 각 로케일로 현재 페이지에 대한 링크를 쿼리와 함께 렌더링합니다 |
| `i18n-group` | 출력을 바꾸는 props 없음: 슬롯을 감싸는 `<div>`, 접두사 없음 |

## 로케일 접두사 라우트 {#locale-prefixed-routes}

`src/pages/`에 라우트당 하나의 페이지를 두고, `src/pages/[locale]/` 아래에 얇은 rewrite 스텁을 추가하세요:

```
src/pages/
  index.astro
  about.astro
  [locale]/
    index.astro
    about.astro
```

```astro
---
// src/pages/[locale]/about.astro
import { prepareLocaleRewrite } from '@i18n-micro/astro'

const target = prepareLocaleRewrite(Astro)
if (target instanceof Response) return target
return Astro.rewrite(target)
---
```

`prepareLocaleRewrite`는 알 수 없는 `:locale`에 대해 `404` 응답을 반환하고, 그렇지 않으면 `Astro.locals`에 로케일을 설정하고 접두사 없는 경로를 반환합니다. 미들웨어는 `locals`에 이미 있는 로케일을 유지하므로, 다시 쓰인 페이지는 해당 로케일로 렌더링됩니다. 로케일을 직접 검증하는 경우 `getLocaleRewritePath(Astro)`는 경로만 반환합니다.

## 로케일 감지 {#locale-detection}

URL이 페이지의 로케일을 결정합니다:

1. 로케일 접두사(`/fr/about` → `fr`; `/en/about`도 `en`).
2. 그렇지 않으면 라우터 어댑터의 `getLocaleFromPath`가 반환하는 값(기본값이 아닌 경우).
3. 그렇지 않으면 기본 로케일. `/about`은 쿠키가 무엇이든 항상 기본 로케일의 페이지입니다.

`autoDetect`는 홈 페이지에서만 동작하는 리디렉션 힌트입니다:

- 쿠키나 `Accept-Language`가 다른 로케일을 선호하는 `/` 요청은 해당 로케일의 홈(`/de`)으로 `302`를 받습니다. q 가중치가 반영되며, `de-DE`는 `de` 로케일과, `de`는 `de-DE` 로케일과 일치합니다.
- `redirectToDefault`를 사용하면 `/`는 항상 리디렉션됩니다: 선호 로케일의 홈으로, 없으면 기본 로케일의 홈으로.
- `/` 응답에는 `Vary: Cookie, Accept-Language`가 포함됩니다(`localeCookie`가 `null`이면 `Accept-Language`만).
- 사전 렌더링된 페이지는 절대 리디렉션되지 않습니다.

`detectLocale(pathname, cookies, headers, defaultLocale, locales, localeCookie?, routingStrategy?, autoDetect?)`는 자체 로직을 위해 같은 선호 로케일을 반환합니다.

쿠키는 선택을 기억합니다. 다른 로케일의 동일 출처 페이지에서 온 페이지 조회는 어떤 링크를 통해 왔든 방문자가 전환하는 것으로 간주됩니다: HTML 응답이 쿠키를 새 로케일로 설정하고 `/`는 리디렉션되지 않으므로, 스위처는 기본 로케일의 홈에 도달할 수 있습니다. 엔드포인트, 이미지, 404, 폼 전송, 프리페치는 아무것도 바꾸지 않습니다. "동일 출처"는 브라우저가 `Sec-Fetch-Site`에서 알려주는 값이며, 이 헤더가 없으면 `Referer`의 호스트를 요청의 호스트와 비교하므로, 프록시 뒤에서는 Astro의 `security.allowedDomains`를 설정하세요.

[서버 아일랜드](https://docs.astro.build/en/guides/server-islands/)나 액션은 URL에 로케일이 없습니다. 요청한 페이지를 위해 렌더링되며, 이는 `Referer`에서 읽고 그 경로만 중요하므로 서버 앞의 프록시는 아무것도 바꾸지 않고, 절대 리디렉션되지 않습니다. 응답에는 `Vary: Referer`가 포함됩니다. `Referer`가 없으면(`no-referrer` 정책) 기본 로케일로 렌더링되며, 동적 페이지에서는 라우트가 URL에서 오므로 페이지 사전이 전달되지 않습니다.

## 라우터 어댑터 {#router-adapter}

`createAstroRouterAdapter(locales, defaultLocale)`는 기본값을 제외한 모든 로케일에 접두사를 붙입니다. Astro 어댑터에는 `getCurrentPath`만 필요하며, 다른 멤버는 선택 사항이고 기본 어댑터로 폴백합니다: `getRouteName(path, locales, routePattern?)`, `getLocaleFromPath`, `switchLocalePath`, `localizePath`, `removeLocaleFromPath`, `resolvePath`(홈 리디렉션 대상), `push`, `replace`, `getRoute`. 서브도메인이나 접미사 URL을 위해 직접 작성하고 `createI18nMiddleware`에 전달하세요.

## SEO {#seo}

```astro
---
// src/layouts/Layout.astro
import { useLocaleHead } from '@i18n-micro/astro'

const head = useLocaleHead(Astro, { baseUrl: 'https://example.com' })
---

<html lang={head.htmlAttrs.lang} dir={head.htmlAttrs.dir}>
  <head>
    {head.link.map((l) => <link rel={l.rel} href={l.href} hreflang={l.hreflang} />)}
    {head.meta.map((m) => <meta property={m.property} content={m.content} />)}
  </head>
  <body><slot /></body>
</html>
```

`htmlAttrs`(`iso`에서 온 `lang`, `dir`), canonical 링크(쿼리 없는 경로), `seo !== false`인 모든 활성 로케일과 `x-default`에 대한 `hreflang` alternate, `og:locale`, `og:locale:alternate`, `og:url`을 반환합니다. 옵션: `baseUrl`(Astro 설정의 `site`, 없으면 루트 상대 URL), `addDirAttribute`(`true`), `addSeoAttributes`(`true`), `hreflangBaseLanguage`(`false`).
