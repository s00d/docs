`@i18n-micro/react`와 `@i18n-micro/preact`는 프레임워크에 독립적인 [런타임](/ko/integrations/runtime-package)을 프로바이더, `useI18n()` 훅, 그리고 네 개의 컴포넌트로 감쌉니다. Nuxt로 빌드하지 않는 React 또는 Preact 앱에서 사용하세요. 두 패키지는 같은 API를 가지며, [Preact](#preact) 섹션에 몇 가지 차이점이 나열되어 있고, 공통 모델은 [프레임워크](/ko/integrations/overview)에 있습니다.

## 설치 {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/react
```

```bash npm
npm install @i18n-micro/react
```

```bash yarn
yarn add @i18n-micro/react
```

</CodeGroup>

피어 의존성: `react` `^18.0.0 || ^19.0.0`; `react-dom` (선택 사항, 렌더링용); `react-router-dom` `^6.0.0 || ^7.0.0` (선택 사항, `@i18n-micro/react/router`에만 필요). React 19.3 및 18.3, React Router 7.18 및 6.30에서 테스트되었습니다.

## 설정 {#setup}

```tsx
// src/main.tsx
import { createRoot } from 'react-dom/client'
import { createI18n, I18nProvider } from '@i18n-micro/react'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

createRoot(document.getElementById('root')!).render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
    <App />
  </I18nProvider>,
)
```

<Warning>

인스턴스는 모듈 수준이나 `useState` 초기화 함수에서 한 번만 생성하고, 컴포넌트 본문에서는 절대 생성하지 마세요.

</Warning>

`<I18nProvider>`는 `i18n`, `locales`, `defaultLocale`, `routingStrategy`를 받습니다:

- 생략된 prop은 인스턴스를 포함해 바깥 프로바이더의 값을 유지합니다.
- 인스턴스가 전혀 없으면 함께 전달된 `createI18n` 옵션으로 인스턴스를 만들므로, props는 일반 데이터로 유지됩니다: `<I18nProvider locale="de" messages={messages}>`.
- 새로운 `locale` prop은 해당 렌더링의 `messages`로 새 인스턴스를 만듭니다. 이러한 인스턴스는 컴포넌트 안에 존재합니다: 마운트 중에 그 위의 무언가가 suspend되면 React는 추가된 내용과 함께 인스턴스를 버립니다.

`routeMessages`를 포함한 모든 `createI18n` 옵션은 [인스턴스](/ko/integrations/overview#the-instance)에 있습니다.

## 번역하기 {#translate}

```tsx
import { useI18n } from '@i18n-micro/react'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' })}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

`useI18n()`이 반환하는 것:

| 그룹 | 멤버 |
| --- | --- |
| 번역 | `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` |
| 로케일과 라우트 | `locale`, `fallbackLocale`, `currentRoute`, `setLocale`, `setRoute`, `getRoute`, `getLocales`, `defaultLocale()`, `getLocaleName` |
| 라우팅 | `switchLocale`, `localePath`, `localeRoute` |
| 사전 | `addTranslations`, `addRouteTranslations`, `clearCache` |

- 컴포넌트는 로케일, 라우트 또는 읽을 수 있는 사전이 변경될 때, 그리고 프로바이더가 새로운 `locales` 또는 `routingStrategy` 객체를 받을 때 다시 렌더링됩니다. 활성 로케일도 폴백 로케일도 아닌 로케일의 사전은 아무것도 렌더링하지 않습니다.
- `t`와 다른 번역 메서드는 스토어가 바뀔 때만 변경되므로 `memo`와 이펙트 의존성에서 안전하게 사용할 수 있습니다.

`useT`는 하나의 문자열을 값으로 제공합니다. 프로바이더의 다른 props에 무슨 일이 일어나든, 컴포넌트는 그 문자열이 변경될 때만 렌더링됩니다. `<I18nT>`도 그것들에 의존하지 않습니다:

```tsx
const title = useT('page.title')
```

언제든지 더 많은 사전을 로드할 수 있습니다:

```tsx
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

useEffect(() => {
  import('./locales/de.json').then((m) => addTranslations('de', m.default))
  addRouteTranslations('en', 'about', { title: 'About us' })
  setRoute('about') // t('title') now reads the 'about' dictionary first
}, [])
```

인스턴스 자체에도 `fetch`로 JSON을 가져오는 `loadFromUrl(url, { locale, routeName })`이 있습니다.

## 로케일 전환하기 {#switch-locale}

```tsx
const { setLocale, switchLocale } = useI18n()

setLocale('de') // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

전환은 아무것도 로드하지 않습니다. 먼저 해당 로케일의 사전을 추가하세요. 스토어 쓰기는 `startTransition` 안에서도 React에 대해 동기적이므로, 누락된 사전 때문에 suspend되는 컴포넌트는 폴백을 표시하게 됩니다. `useLocaleSwitch`는 먼저 로드하고 사전이 준비될 때까지 이전 UI를 유지합니다:

```tsx
const [switchTo, pending] = useLocaleSwitch((locale) => i18n.loadFromUrl(`/locales/${locale}.json`, { locale }))

<button disabled={pending} onClick={() => switchTo('de')}>Deutsch</button>
```

마지막 호출이 우선합니다. 로드에 실패하면 reject되며 로케일은 그대로 유지됩니다.

`<I18nGroup>`은 render-prop 자식에 접두사가 붙은 `t`를 전달합니다. 그 안의 `<I18nT>`와 `t()`에는 접두사가 붙지 않습니다:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## 라우팅 {#routing}

React Router 어댑터는 메인 엔트리가 `react-router-dom`을 import하지 않도록 하위 경로에 있습니다. `useLocation()`과 `useNavigate()`가 필요하므로 라우터 아래의 컴포넌트 안에서 생성하세요:

```tsx
// src/App.tsx
import { useMemo } from 'react'
import { BrowserRouter, Route, Routes, useLocation, useNavigate } from 'react-router-dom'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/react'
import { createReactRouterAdapter } from '@i18n-micro/react/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Localized() {
  const location = useLocation()
  const navigate = useNavigate()
  // memoized: a new object on every render re-renders every `useI18n()` consumer
  const routingStrategy = useMemo(() => createReactRouterAdapter(locales, 'en', location, navigate), [location, navigate])
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      <Routes>
        <Route path="/:locale?" element={<Home />} />
        <Route path="/:locale?/about" element={<About />} />
      </Routes>
    </I18nProvider>
  )
}

export default function App() {
  return (
    <BrowserRouter>
      <Localized />
    </BrowserRouter>
  )
}
```

어댑터는 기본 로케일을 제외한 모든 로케일에 접두사를 붙이며(`/about`, `/de/about`), `<I18nLink>`를 React Router의 `<Link>`로 렌더링합니다. URL에서 로케일을 설정하는 것은 직접 해야 합니다(예: 이펙트에서 `useParams().locale`로). 다른 라우터의 경우 `getCurrentPath`, `push`, `replace`(모두 필수)를 가진 어댑터를 작성하세요 — [라우터 어댑터](/ko/integrations/overview#router-adapter)를 참고하세요.

## SSR {#ssr}

`renderToString`이 동작합니다: `useI18n()`에는 서버 스냅샷이 있습니다. 서로 다른 로케일의 요청이 상태를 공유하지 않도록 요청마다 하나의 인스턴스를 만들고 렌더링 전에 사전을 추가하거나, 프로바이더에 일반 데이터를 전달하세요.

### 하이드레이션 {#hydration}

숫자, 복수형, 텍스트는 그대로 하이드레이션됩니다. 날짜는 시간대에, 상대 날짜는 시계에 의존합니다: 서버와 브라우저에 `timeZone`을 설정하고, `tdr`의 경우 `now`로 서버의 시간을 브라우저에 전달하세요. `date` 또는 `relativeDate`가 있는 `<I18nT>`는 `suppressHydrationWarning`을 설정하므로 차이가 있어도 하이드레이션이 실패하지 않지만, 텍스트가 변경될 때까지 서버의 텍스트가 유지됩니다. 이는 한 단계에만 적용됩니다: 번역을 요소로 감싸는 `children`은 차이가 있으면 여전히 실패하므로, 그런 경우에는 같은 `timeZone`을 지정하세요.

### 서버 컴포넌트 {#server-components}

패키지는 클라이언트 코드를 `'use client'`로 표시합니다. `@i18n-micro/react/server`에는 `createI18n`과, 훅 없이 인스턴스를 prop으로 받는 `I18nT`가 있어 텍스트가 클라이언트 번들에 포함되지 않습니다. Next.js 앱 라우터처럼 `react-server` 조건에서는 메인 엔트리도 이것으로 해석되지만, TypeScript는 기본적으로 이를 알지 못합니다: `/server`에서 import하세요. `@i18n-micro/react/client`는 항상 클라이언트 엔트리를 제공합니다.

```tsx
// app/[locale]/layout.tsx: a server component
import { cache } from 'react'
import { createI18n, I18nT } from '@i18n-micro/react/server'
import { I18nProvider } from '@i18n-micro/react/client'
import { loadMessages } from './messages'

const getI18n = cache(async (locale: string) => createI18n({ locale, messages: await loadMessages(locale) }))

export default async function Layout({ params, children }) {
  const { locale } = await params
  const i18n = await getI18n(locale)
  return (
    <I18nProvider locale={locale} messages={{ [locale]: i18n.resolveTranslations() }}>
      <h1>
        <I18nT i18n={i18n} keypath="title" />
      </h1>
      {children}
    </I18nProvider>
  )
}
```

`react-server-dom-webpack`을 통해 렌더링되었으며, Next.js 앱 자체에서는 아직 실행해 보지 않았습니다.

## Preact {#preact}

`@i18n-micro/preact`는 같은 소스로 `preact/compat` 없이 Preact 자체 위에서 빌드됩니다: 같은 인스턴스, 프로바이더, 훅, 컴포넌트를 제공합니다. 차이점:

| | React | Preact |
| --- | --- | --- |
| 피어 의존성 | `react` (+ 선택 사항 `react-router-dom`) | `preact` `^10.0.0 \|\| ^11.0.0`, 10.29 및 11.1에서 테스트됨 |
| 인스턴스 클래스 | `ReactI18n` | `PreactI18n` |
| 라우터 어댑터 | `/router`의 `createReactRouterAdapter` | `/router`의 `createBrowserHistoryAdapter(locales, defaultLocale, ssrUrl?)` |
| 재렌더링 | `useSyncExternalStore` | 스토어를 다시 확인하는 레이아웃 이펙트 구독 |
| 서버 컴포넌트 | `/server`, `/client` | 없음 |

`createBrowserHistoryAdapter`는 모든 History API 라우터(wouter, preact-router)와 함께 동작합니다: `push`와 `replace`는 `history.pushState` / `replaceState`를 호출하고 `popstate`를 발생시키며, `<I18nLink>`는 `push`를 통해 이동하는 일반 `<a>`를 렌더링합니다. 서버에는 주소 표시줄이 없습니다: 요청의 URL을 `ssrUrl`로 전달하지 않으면 링크와 스위처가 `/`에 있는 것처럼 렌더링됩니다. 브라우저에서는 주소 표시줄이 우선합니다.

```tsx
// src/main.tsx
import { render } from 'preact'
import { createI18n, I18nProvider } from '@i18n-micro/preact'
import { createBrowserHistoryAdapter } from '@i18n-micro/preact/router'
import { App } from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={createBrowserHistoryAdapter(locales, 'en')}>
    <App />
  </I18nProvider>,
  document.getElementById('app')!,
)
```

전체 시그니처: [Preact 레퍼런스](/ko/api/packages/preact).
