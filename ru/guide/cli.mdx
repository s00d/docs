`@i18n-micro/cli` управляет файлами локалей проекта Nuxt. Он читает `locales`, `defaultLocale`, `translationDir` и ваши слои из `nuxt.config`, поэтому собственная конфигурация ему не нужна.

![Терминал, в котором запущены i18n-micro check, выводящий один отсутствующий, один неопределённый и четыре неиспользуемых ключа и завершающийся ошибкой, затем extract, добавляющий неопределённый ключ, затем clean --dryRun, выводящий четыре ключа, которые он удалил бы](/images/cli/demo.gif)

| Команда | Для чего |
| --- | --- |
| `check` | Остановить сборку при любой проблеме с файлами локалей |
| `translate` | Заполнить отсутствующие ключи через сервис перевода |
| `clean` | Удалить ключи, которые нигде не используются |
| `rename` | Переместить ключ или целое пространство имён везде сразу |

```bash
npm install -D @i18n-micro/cli
npx i18n-micro --help
```

Запускайте его из корня приложения или укажите корень через `--cwd`. Все флаги всех команд описаны в [справочнике команд](/ru/api/cli).

<Tip>

**Переходите с nuxt-i18n-micro-cli?** `@i18n-micro/cli` заменяет его; бинарники `i18n-micro` и `i18n-micro-cli` сохраняются. См. [таблицу старых команд](#moving-from-nuxt-i18n-micro-cli).

</Tip>

## Использование в CI {#use-it-in-ci}

```bash
i18n-micro check
```

`check` — это контрольная точка. Он сообщает:

| Проверка | Значение |
| --- | --- |
| `missing` | Ключ локали по умолчанию отсутствует в локали |
| `empty` | Значение равно `''`. Приложение показывает пустоту, а не резервное значение |
| `extra` | В локали есть ключ, которого нет в локали по умолчанию |
| `placeholders` | `{name}` потерян или добавлен, либо форма множественного числа потеряла формы |
| `undefined` | Код использует ключ, которого нет в локали по умолчанию |
| `unused` | Ключ нигде в проекте не используется |
| `duplicates` | Один и тот же текст под разными ключами. По умолчанию выключено: передайте `--duplicates` |

- `--only missing,placeholders` запускает отдельные проверки; проверка, указанная в `--only`, которую не удалось выполнить, считается проваленной.
- `--json` выдаёт отчёт для инструментов.
- `--ignore` пропускает исходные файлы.
- Пока ключи вычисляются во время выполнения, `unused` пропускается, и отчёт объясняет почему.

Каждая команда завершается одним из трёх кодов, чтобы пайплайн мог отличить проблему с переводами от проблемы с инструментом:

| Код выхода | Значение |
| --- | --- |
| `0` | Сообщать не о чем |
| `1` | Есть находки |
| `2` | Команду не удалось выполнить: ошибка использования, повреждённый файл, неудачный запрос |

Другие команды, заслуживающие шага в CI:

```bash
i18n-micro format --check      # fails if a file is not formatted
i18n-micro lint                # stray spaces, empty values, your own regex rules
i18n-micro stats --baseRef main
```

## Синхронизация локалей {#keep-locales-in-step}

| Команда | Что делает |
| --- | --- |
| `extract` | Выводит ключи, которые использует код, но у которых ещё нет текста. Текст по умолчанию, как в `$t('key', {}, 'Welcome')`, попадает в локаль по умолчанию. |
| `sync` | Удаляет ключи, которых нет в локали по умолчанию. Сначала попробуйте `--dryRun`. |
| `clean` | Удаляет ключи, которые нигде не используются. Сначала попробуйте `--dryRun`. |
| `search` | Находит ключи и значения и показывает, где используется каждый ключ. |
| `stats` | Заполненность по локалям; `--baseRef main` сравнивает с git-ссылкой. |

`sync` останавливается, как и `clean`, когда собирается удалить ключ, неиспользуемость которого не может доказать, а также когда в локали по умолчанию нечего сравнивать. Если удалять нечего, он никогда не останавливается, поэтому один лишь `$t(item.label)` — не повод для `--force`.

<Note>

`extract` и `sync` никогда не записывают `''` для ключа без перевода. Ключ остаётся отсутствующим, поэтому во время выполнения применяется `fallbackLocale`, а `check` сообщает о нём. Пустая строка была бы определённым значением и показала бы пустоту.

</Note>

### Что читают команды {#what-the-commands-read}

`check`, `extract`, `sync`, `clean`, `search` и `rename` читают исходный код всего проекта, а не фиксированный список папок:

- **Читается:** шаблоны и скрипты через парсер, `.html` и Pug как текст, все слои, а также папки вне корня, на которые указывает алиас или `components`.
- **Пропускается:** `node_modules`, результат сборки и файлы локалей. Добавьте свои через `--ignore 'legacy/**,*.stories.ts'`.
- **Тестовый код** считается использованием, поэтому `clean` и `check --only unused` сохраняют ключ, который читает только тест. Он никогда не добавляет ключ: `extract` пропускает такие ключи, а `check` не сообщает о них как о неопределённых.

Тестовый код — это корневые папки `tests`, `test`, `__tests__`, `e2e`, `cypress` и `playwright`, а также файлы JavaScript и TypeScript с `.spec` и `.test` (`.ts`, `.tsx`, `.mts`, `.js`, `.jsx`, `.mjs` и подобные) в любом месте. Только корневые папки освобождены от сомнений, описанных ниже: `pages/tests/[id].vue` — такая же страница, как любая другая, как и `public/` и минифицированные файлы, код которых не является частью приложения.

Команды распознают:

- `$t`, `$ts`, `$tc`, `$has` и `$_t(route)`;
- `t()` из `useI18n()` и `useTranslationServerMiddleware()`;
- `<i18n-t keypath>` в шаблонах и JSX, а также `<i18n-group prefix>`;
- алиасы вроде `const { t: tr } = useI18n()`.

### Как решает `clean` {#how-clean-decides}

`clean` скорее оставит мёртвый ключ, чем удалит живой. Ключ сохраняется, если выполняется любое из условий:

- его использует вызов либо ключ ниже или выше него;
- строка в коде равна ему: `const key = 'menu.home'`, `<Item label="menu.home" />`;
- его содержит файл JSON, YAML или Markdown в проекте;
- вычисляемый ключ имеет статическое начало, которое его покрывает: `` $t(`status.${state}`) `` сохраняет всё под `status.`;
- его определяет слой.

`clean` останавливается, ничего не меняя, когда не может знать наверняка, и перечисляет причины:

- ключ полностью вычисляемый, как в `$t(name)`, `<i18n-t :keypath="name" />` или `<i18n-t v-bind="props" />`;
- `$t` передаётся как значение, как в `items.map($t)`;
- функция с именем `t` получает вычисляемый аргумент и приходит из параметра, импорта или вызова: она может быть обёрткой над настоящей. Функция, определённая в том же файле, не считается, потому что у обёртки был бы собственный вызов внутри;
- исходный файл не разбирается;
- ни один файл не использует вообще никаких ключей, что обычно означает, что поиск идёт не в том месте;
- файл локали — символическая ссылка за пределы проекта, поэтому его может читать другое приложение.

<Step title="Предпросмотр">

</Step>

<Step title="Защита ключей">

</Step>

## Перевод отсутствующих ключей {#translate-missing-keys}

```bash
i18n-micro translate --dryRun                     # keys and characters per locale, nothing sent
export I18N_TRANSLATE_TOKEN=...                   # or put it in .env
i18n-micro translate --service deepl --locale de,fr
```

- `translate` заполняет отсутствующие или пустые ключи; `--replace` переводит всё заново.
- Плейсхолдеры и формы множественного числа защищены. Перевод, потерявший плейсхолдер, не записывается: ключ выводится в списке, и команда завершается с кодом `1`.
- Каждый пакет сохраняется до отправки следующего запроса, поэтому сбой стоит только неудавшегося запроса.

| `--service` | Сервис | `--token` | Полезные `--options` |
| --- | --- | --- | --- |
| `ai` | Vercel AI Gateway, OpenAI, Anthropic или любой OpenAI-совместимый сервер | API-ключ или `AI_GATEWAY_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` | `provider`, `model`, `baseUrl`, `maxTokens` |
| `azure` | Azure Translator | Ключ подписки | `region` |
| `deepl` | DeepL, включая бесплатные ключи | Ключ авторизации | `formality`, `glossaryId`, `context` |
| `google` | Google Cloud Translation v2 | API-ключ | `model` |
| `libretranslate` | LibreTranslate | Необязательно | `baseUrl` |
| `yandexcloud` | Yandex Cloud Translate | API-ключ или IAM-токен с `authScheme:Bearer` | `folderId`, `model` |

Опции — это пары `key:value`: `--options provider:openai,model:gpt-4o-mini`. Все сервисы также принимают `baseUrl`, `retries`, `retryDelayMs` и `timeoutMs`. Запрос на перевод может уже быть оплачен, поэтому он повторяется только после `429` или `503`, и не повторяется, если сервис просит подождать больше минуты.

<Warning>

Флаги видны в истории оболочки и списках процессов, поэтому передавайте токен через переменную окружения. CLI маскирует то, что считает секретом, везде, где это выводит, включая `--debug`: токены, ключи провайдеров, учётные данные Basic, а также query и учётные данные настроенного вами URL. Сервер, который переформатирует ключ перед тем, как вернуть его в ответе, вне его досягаемости, поэтому обращайтесь с логами неудачного запуска осторожно.

</Warning>

Сервис `ai` следует глоссарию. Если существует `.i18n-glossary.json`, он используется без флага; `--glossaryFile` выбирает другой файл.

```json .i18n-glossary.json
{ "entries": [{ "source": "Cart", "target": "Warenkorb", "to": "de" }] }
```

## Превращение жёстко заданного текста в ключи {#turn-hardcoded-text-into-keys}

```bash
i18n-micro text-to-i18n --dryRun   # list what would change
i18n-micro text-to-i18n            # rewrite the templates
```

```vue
<!-- before -->
<h1>Welcome to our site</h1>
<!-- after -->
<h1>{{ $t('pages.index.welcome-to-our') }}</h1>
```

Переписываются только шаблоны `.vue` самого проекта, а не слоя или цели алиаса. Каждый переписанный файл повторно разбирается перед записью. Следующее выводится в списке и сохраняет свой текст:

- текст в файлах `.ts` и скриптах, потому что `$t` доступна не везде;
- текст рядом с разметкой или интерполяцией, например `<p>Hello <b>world</b> today</p>`: половину предложения нельзя перевести отдельно;
- сгенерированный ключ, который столкнулся бы с другим, как это бывает у родительской и дочерней страниц;
- известный ключ, который нельзя поместить в кавычки.

<Warning>

Сначала сделайте коммит и просмотрите diff.

</Warning>

## Переименование ключа {#rename-a-key}

```bash
i18n-micro rename --from common.save --to actions.save
i18n-micro rename --from settings --to account.settings   # a whole namespace
```

`rename` редактирует синтаксическое дерево, поэтому комментарии и несвязанные строки остаются как есть, а алиасы и `:keypath` отслеживаются. Собственный файл слоя никогда не меняется. Команда предупреждает о том, что не может переписать, и оставляет это без изменений:

- вычисляемый ключ под старым именем;
- каждую простую строку, равную ему;
- шаблон Pug;
- исходник в слое или в папке вне проекта.

`--to` должен быть ключом, который можно записать в коде: без кавычек, без обратной косой черты, без пустых сегментов, без `__proto__`.

## Обмен файлами с переводчиками {#exchange-files-with-translators}

```bash
i18n-micro export --format csv
i18n-micro import --format csv --dryRun
```

**`export`** записывает все ключи всех локалей, включая непереведённые, с текстом локали по умолчанию в качестве источника: столбец `Source` в CSV, комментарий `#.` в PO.

- Без `--dir` PO попадает в `pots`, а CSV — в `csv_exports`.
- Команда записывает сведения о том, что выгрузила, в `.i18n-export.json` в папке вывода. Она останавливается, если файл изменился с тех пор и содержит переводы, которых нет в файлах локалей, включая нечёткие (fuzzy) записи PO; `--force` перезаписывает их. Обычные правки файлов локалей её не останавливают.

**`import`** выполняет слияние, пропускает пустые ячейки и пропускает записи PO, помеченные как `fuzzy`.

- Ключ, который перезаписал бы значение, или значение поверх целой группы ключей выводится в списке и пропускается, а команда завершается с кодом `1`.
- Она останавливается с кодом `2` при каталоге в неожиданном месте, каталоге страницы, который не записал последний экспорт, неуместной кавычке в CSV или записи страницы при `disablePageLocales`.

Для платформы переводов используйте её собственный CLI: настройка [Crowdin](/ru/guide/crowdin) синхронизирует JSON-файлы, включая файлы страниц.

## Синхронизация с собственным эндпоинтом {#sync-with-your-own-endpoint}

`sync-remote` обменивает глобальные файлы локалей с HTTP-эндпоинтом, который вы запускаете. Файлы страниц остаются локальными, и команда сообщает об этом. Опишите эндпоинт в `.i18n-remote.json`:

```json .i18n-remote.json
{ "url": "https://translations.example.com", "path": "translations" }
```

Эндпоинт отвечает на `GET` и `PUT` объектом `{ locale: messages }`. Аутентифицируйтесь через `auth: { username, password }` или поместите bearer-токен в `I18N_REMOTE_TOKEN`.

| | Pull | Push |
| --- | --- | --- |
| Что передаётся | Заполняет то, чего у вас нет, и сохраняет ключи, которые есть только у вас | Отправляет собственные ключи проекта, но не ключи слоя, и не отправляет ваши пустые значения |
| Конфликты | Ключ, различающийся на обеих сторонах: ничего не записывается, код выхода `1`; `--force` берёт удалённое значение | PUT заменяет документ, поэтому push сначала читает эндпоинт и останавливается с кодом `1`, если там есть текст, которого нет у вас; `--force` перезаписывает его. Эндпоинту, отвечающему `404`, терять нечего |
| `--dryRun` | Читает с эндпоинта, выводит изменения, ничего не записывает | Сообщает, что было бы отправлено, не обращаясь к эндпоинту |

Ненастроенная локаль пропускается, а пустое удалённое значение ничего не очищает.

## Переход с nuxt-i18n-micro-cli {#moving-from-nuxt-i18n-micro-cli}

| Старая команда | Теперь |
| --- | --- |
| `validate` | `check` |
| `diff` | `check --only missing` |
| `check-duplicates` | `check --only duplicates` |
| `export-csv`, `import-csv` | `export --format csv`, `import --format csv` |
| `--potsDir`, `--csvDir` | `--dir` |
| `estimate` | `translate --dryRun` |
| `glossary` | Редактируйте `.i18n-glossary.json`; `translate` читает его сам |
| `backup`, `restore` | Git, который уже хранит ваши файлы локалей |
| `init` | `nuxi init`, затем добавьте `nuxt-i18n-micro` в `modules` |
| `split` | Удалена: модуль не читает разделённые файлы |
| `optimize` | `check --only duplicates` |
| `replace-values` | Ваш редактор или `sed` |
| `stats --full` | `stats`; подробности есть в [DevTools](/ru/guide/devtools) |
| `search --hardcodedOnly` | `text-to-i18n --dryRun` |
| `search --preferUnused`, `--onlyVue` | Удалены |
| Правила `lint` `no-html-tags`, `no-special-chars`, `no-mixed-case`, `no-missing-punctuation`, `no-inconsistent-pluralization` | Удалены: они помечали обычный текст. Если нужно, напишите запись `customRegexRules` |
| `text-to-i18n --extractOnlyDirs`, `--extractOnlyPatterns`, `--verbose` | Удалены: код никогда не переписывается |
| `--logLevel verbose` | Удалён: он ничего не делал |

**Удалённые сервисы:** `googlefree`, `yandex` (используйте `yandexcloud`), `ibm`, `lingvatranslate`, `modernmt`, `lilt`, `unbabel`, `reverso`, `baidu`, `papago`, `tencent`, `systran`, `mymemory`.

**Удалённые типы `sync-remote`:** `github`, `gitlab`, `crowdin`, `lokalise`, `tolgee`, `weblate`. Используйте собственный CLI платформы или `custom`, которому больше не нужен `type`.

### Изменённое поведение {#changed-behaviour}

- `extract` и `sync` больше не записывают `''`. Ключи остаются отсутствующими, и `check` сообщает о них. `extract` записывает ключ, только когда код задаёт его текст.
- `extract` записывает ключи страниц в `locales/pages/<route name>/`, где их читает модуль, и сканирует `app/` в Nuxt 4. Перенесите всё из каталогов вроде `pages/_about` и `pages/blog_` и удалите случайный `locales/pages/<locale>.json`.
- `translationDir` из `nuxt.config` учитывается; раньше все команды молча использовали `locales`.
- Без `defaultLocale` по умолчанию используется `en`, как в модуле, и учитывается `DEFAULT_LOCALE`. Раньше это была первая локаль.
- `check` и `sync` используют локаль по умолчанию как эталон и проверяют файлы страниц. `"a.b"` и `a: { b }` считаются одним ключом.
- `clean` сохраняет ключ, используемый где угодно, в любой области видимости, и останавливается, когда использование нельзя доказать. `--include` и `--exclude` выбирают, что можно удалять.
- `sync` останавливается так же, а также когда в локали по умолчанию нет ключей для сравнения. `--force` переопределяет это. Он также останавливается, когда `DEFAULT_LOCALE` выбрал другой эталон, чем `nuxt.config`.
- Длинные флаги с одним дефисом и лишние аргументы считаются ошибками: `clean -dryRun` больше не запускает `clean`.
- Файл только для чтения или файл не в UTF-8 нельзя сохранить: команда останавливается до каких-либо изменений. Читать такой файл можно. Повторяющийся ключ, ключ с именем `__proto__` и целое число больше 2^53 останавливают команду, потому что при сохранении они были бы потеряны.
- Флаг, которому нужно значение и за которым следует другой флаг, — ошибка; для значения, начинающегося с дефиса, пишите `--flag=--value`. Булев флаг принимает только `true` или `false`.
- `export` останавливается, а не перезаписывает переводы, которые так и не были импортированы.
- Коды выхода — `0`, `1` и `2`; раньше сбои давали `1`, а `diff` и `check-duplicates` всегда `0`.
- `lint --fix` больше не оставляет файлы `.bak`.
- Сохранение сохраняет отступы файла, окончания строк, завершающий перевод строки, символическую и жёсткую ссылку и не трогает файлы, которые не изменились.
- Опечатка во флаге или удалённый флаг теперь ошибка, а не молча игнорируются.
- Пути вроде `--dir` задаются относительно проекта, а не оболочки.
- `ai` больше не загружает пакеты `@ai-sdk/*`: используйте `provider` `gateway`, `openai` или `anthropic` либо `baseUrl` для OpenAI-совместимого сервера.
