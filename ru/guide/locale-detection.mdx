Каждый запрос получает одну локаль, выбранную из одного и того же списка источников в одном и том же порядке на сервере и в браузере. Прочитайте этот раздел, когда решаете, на каком языке оказываются новые посетители, запоминается ли их выбор и что видит ваш серверный API. Здесь описаны приоритет источников, перенаправления каждой стратегии и опции, которые включают или выключают каждый источник.

<Tip>

**Предварительные требования** — [Стратегии маршрутизации](/ru/guide/strategy)

</Tip>

## Приоритет {#the-precedence}

Побеждает первый источник, который указывает **включённую** локаль. Недопустимое или некорректное значение (неизвестный код, повреждённый cookie) пропускается, и учитывается следующий источник.

| # | Источник | Учитывается, когда |
| --- | --- | --- |
| 1 | Префикс URL (`/de/about`) | стратегии с префиксом. При `prefix_except_default` и `prefix_and_default` URL без префикса соответствует локали по умолчанию |
| 2 | `?locale=de` | страницы: только `no_prefix`. Серверные API-хелперы: всегда, и раньше URL |
| 3 | Состояние локали, заданное приложением (`useI18nLocale().setLocale()`) | в URL нет локали |
| 4 | Cookie | задан [`localeCookie`](/ru/api/module-options#localecookie) (автоматически `'user-locale'` при `no_prefix`) |
| 5 | Заголовок `Accept-Language` | [`autoDetectLanguage`](/ru/api/module-options#autodetectlanguage) равен `true` (по умолчанию) |
| 6 | [`defaultLocale`](/ru/api/module-options#defaultlocale) | всегда |

Таким образом, при стратегии с префиксом то, что показывает страница, определяет URL; источники предпочтений (3–5) решают лишь, куда посетителя **перенаправить**, и только на путях, которые разрешает `autoDetectPath`. При `no_prefix` перенаправлять некуда, и то, что показывает страница, определяют источники предпочтений.

![Decision flow: a locale prefix in the URL renders that locale. Without one, no_prefix renders from the preference sources, prefix_and_default renders the default locale, and prefix or prefix_except_default redirect by preference when autoDetectPath allows the path](/images/diagrams/locale-detection.svg)

## Перенаправления по стратегиям {#redirects-per-strategy}

Перенаправления выполняются с кодом `302` на сервере до рендеринга страницы, а при клиентской навигации — route middleware. Query и hash сохраняются. При [`redirects: false`](/ru/api/module-options#redirects) перенаправлений нет; неверные префиксы по-прежнему дают 404.

Посетитель предпочитает `de` (cookie или заголовок), `defaultLocale: 'en'`, `autoDetectPath: '/'` по умолчанию:

| Запрос | `prefix_except_default` | `prefix` | `prefix_and_default` | `no_prefix` |
| --- | --- | --- | --- | --- |
| `/` | → `/de` | → `/de` | `/` на `en` | `/` на `de` |
| `/about` | `/about` на `en` | → `/de/about` | `/about` на `en` | `/about` на `de` |
| `/fr/about` | `/fr/about` | `/fr/about` | `/fr/about` | — |
| `/en/about` | 404 | `/en/about` | `/en/about` | — |

`prefix_and_default` никогда не перенаправляет: URL без префикса принадлежит локали по умолчанию, а остальные локали живут под своим префиксом. Посетителя, предпочитающего `en`, при `prefix_except_default` не перенаправляют с `/`. Целевые адреса не имеют завершающего слеша (`/de`, а не `/de/`) и учитывают пользовательские пути (`/about` → `/de/ueber-uns`).

Везде, где решают cookie или заголовок (перенаправление с `/`, каждая страница при `no_prefix`), ответ содержит `Vary: Cookie, Accept-Language`, чтобы CDN хранил ответы раздельно.

### `autoDetectPath` {#autodetectpath}

Где источники предпочтений могут перемещать посетителя:

| Значение | Предпочтение учитывается на |
| --- | --- |
| `'/'` (по умолчанию) | только `/`. Глубокие ссылки остаются на языке URL |
| `'no_prefix'` | каждом пути без префикса локали (`/about` → `/de/about`) |
| `'/welcome'` | точно этом пути (завершающий слеш игнорируется) |
| `'*'` | каждом пути, включая пути с префиксом: `/about` и `/fr/about` → `/de/about`, когда посетитель предпочитает `de` |

- На путях, которые не разрешены, URL без префикса считается локалью по умолчанию.
- Исключение — `prefix`: у этой стратегии нет страниц без префикса, поэтому `/about` всегда ведёт на локаль посетителя (`/de/about` при cookie `de`, `/en/about` без предпочтения).
- При `'*'` сервер игнорирует состояние приложения, а URL с префиксом больше не записывает свою локаль в cookie; cookie меняется, когда посетитель переключает язык через `$switchLocale`.

<Warning>

При `'*'` общие ссылки открываются на языке читателя, что может удивить. Предпочитайте `'/'` или `'no_prefix'`, если вам нужно не именно это.

</Warning>

## Accept-Language {#accept-language}

Заголовок разбирается так, как определено в RFC 9110, и сопоставляется с **кодами** локалей из вашей конфигурации:

- Записи перебираются по значению `q`, начиная с наибольшего (`fr;q=0.1, de;q=0.9` → `de`). `q=0` означает «не этот язык»; запись с некорректным `q` игнорируется. `*` ничему не соответствует.
- `_` читается как `-` (`en_US` = `en-US`).
- Для каждой записи: точный код, затем более короткие формы (`de-AT` → `de`), затем региональная локаль того же языка (`en` → `en-US`). Точные и более короткие формы не зависят от порядка `locales`; среди нескольких региональных совпадений побеждает первое в `locales`.
- Системы письма никогда не смешиваются: `zh-TW` и `zh-HK` подразумевают традиционную, `zh-CN` — упрощённую, поэтому `zh-CN` никогда не совпадает с локалью `zh-Hant`.
- Отключённые локали никогда не совпадают.

```ts
// locales: [{ code: 'en' }, { code: 'de' }, { code: 'zh-Hant' }]
// 'de-CH,de;q=0.9,en;q=0.8'  → 'de'
// 'en-GB'                    → 'en'
// 'zh-TW'                    → 'zh-Hant'
// 'zh-CN'                    → no match, next source
```

Отключите определение по заголовку с помощью `autoDetectLanguage: false`; cookie и состояние по-прежнему учитываются.

## Cookie {#the-cookie}

- **По умолчанию выключен** для стратегий с префиксом (`localeCookie: null`). Тогда перенаправления работают только по заголовку, а выбор не запоминается между визитами. Задайте `localeCookie: 'user-locale'`, чтобы запоминать его.
- При `no_prefix` он равен `'user-locale'`, если вы не задали другое имя. `localeCookie: null` отключает его и там.
- Он записывается, когда посетитель переключает язык (`$switchLocale`, `<i18n-switcher>`, `useI18nLocale().setLocale()`), и при серверном рендеринге страницы с префиксом (`/fr/about` сохраняет `fr`; но не при `autoDetectPath: '*'` с включёнными перенаправлениями, где URL ещё может измениться). Клиентская навигация на страницу тоже сохраняет локаль этой страницы, в том числе на странице без префикса для локали по умолчанию; первая загрузка этого URL — нет. При `no_prefix` и в hash-режиме навигация сохраняет только изменение. Страница 404 ничего не сохраняет, если только на неё не попадает `$switchLocale`.
- Он действует один год (`path=/`, `SameSite=Lax`).
- При `hashMode` предпочтение хранится вместо этого в cookie `hash-locale`; сервер и клиент читают один и тот же cookie. Сервер рендерит эту локаль и, кроме `prefix`, никогда не перенаправляет; локаль в hash (`/#/de`) имеет приоритет над ним и применяется сразу после гидратации. При `prefix` на `/` нет страницы, поэтому `/` рендерится в браузере, который переходит на `/#/de` по cookie, затем по языку браузера (`autoDetectLanguage`); любой другой документ (`/about`, `/de`) перенаправляет в hash.

Читайте и задавайте предпочтение с помощью [`useI18nLocale`](/ru/composables/useI18nLocale), а не напрямую через `useCookie` или `useState`.

## Собственное определение {#your-own-detection}

Чтобы выбирать локаль самостоятельно (пользовательская настройка, поддомен), вызовите `useI18nLocale().setLocale(code)` в плагине, который выполняется раньше плагина модуля. Это становится источником 3 — состоянием приложения. В разделе [Пользовательское определение локали](/ru/guide/custom-auto-detect) приведён полный рецепт, включая отключение встроенного определения.

## Серверные API-маршруты {#server-api-routes}

[`useLocaleServerMiddleware`](/ru/guide/server-side-translations) и `useTranslationServerMiddleware` используют собственный порядок, потому что URL API редко бывает локализован:

1. `?locale=`
2. параметр маршрута `[locale]` или префикс локали в пути
3. cookie (если задан `localeCookie`)
4. `Accept-Language` (если включён `autoDetectLanguage`)
5. `defaultLocale`

`localeCookie: null` и `autoDetectLanguage: false` отключают источники 3 и 4 и здесь.

## Переопределения во время выполнения {#runtime-overrides}

[Переопределения во время выполнения](/ru/guide/runtime-overrides) меняют список, с которым сопоставляются источники:

- `disabledLocales`, заданные во время выполнения, исключаются на каждом шаге: cookie или заголовок, указывающие такую локаль, пропускаются.
- `defaultLocale`, заданный во время выполнения, является шагом 6 при `prefix` и `no_prefix`.
- При `prefix_except_default` и `prefix_and_default` локаль по умолчанию фиксируется при сборке (её страницы — маршруты без префикса). `defaultLocale`, заданный во время выполнения, или отключение локали по умолчанию из сборки игнорируются с предупреждением.
