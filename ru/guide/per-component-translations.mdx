---
title: "Конфигурация страницы"
description: "Ограничение страницы набором локалей, пользовательские пути, встроенные переводы или отключение SEO-тегов с помощью $defineI18nRoute."
---

`$defineI18nRoute` задаёт опции i18n для одной страницы изнутри самой страницы. Используйте его, когда страница существует только в некоторых локалях, нуждается в собственном локализованном пути, содержит несколько своих переводов или не должна получать теги hreflang/canonical. Модуль читает этот вызов во время сборки и встраивает его в сгенерированные маршруты.

## Ограничение страницы набором локалей {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

При стратегии по умолчанию `prefix_except_default` генерируются только `/product` и `/de/product`; в других локалях у страницы нет маршрута. То же самое можно задать в `nuxt.config.ts` через [`routeLocales`](/ru/api/module-options#routelocales).

`$defineI18nRoute` — это инъекция приложения Nuxt, а не макрос компилятора: всегда получайте её из `useNuxtApp()` и вызывайте с `$`. Этап сборки распознаёт только `$defineI18nRoute(`.

## Встроенные переводы {#add-inline-translations}

Передайте объект вместо массива. Его ключи — разрешённые локали, а значения объединяются со словарём страницы для активной локали.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Встроенные переводы поставляются внутри компонента страницы для каждой локали. Для всего, что больше нескольких ключей, предпочитайте [файлы переводов страниц](/ru/guide/translations); встроенные ключи оставьте для самодостаточных страниц и компонентов.

## Локализованные пути {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

При `prefix_except_default` и `defaultLocale: 'en'` это даёт `/welcome` и `/de/willkommen`. То же самое делает `path` внутри встроенного объекта локали: `locales: { de: { path: '/willkommen' } }`. Динамические параметры, вложенные маршруты и альтернатива на уровне конфигурации описаны в разделе [Локализованные пути](/ru/guide/custom-locale-routes).

## Отключение SEO-тегов {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

Альтернатива на уровне конфигурации — [`routeDisableMeta`](/ru/api/module-options#routedisablemeta). Что это за теги, описано на странице [SEO](/ru/guide/seo).

## Что может прочитать сборка {#what-the-build-can-read}

Этап сборки находит вызов в каждом файле страницы и вычисляет его аргумент, не запуская ваше приложение. Это работает, когда конфигурация:

- литеральный объект (строки, массивы, вложенные объекты, шаблонные строки, тернарные операторы по `process.env.NODE_ENV`);
- построена из констант, объявленных в том же `<script setup>` (`const locales = ['en', 'de']`, включая spread);
- массив объектов с полем `code` (`[{ code: 'en' }, { code: 'de' }]`).

Сборка не может прочитать значения, импортированные из другого модуля, или всё, что требует работающего приложения (composables, `await`, загружаемые данные). В этом случае сборка выводит в лог `Ignored the $defineI18nRoute() config in <file>`, а страница сохраняет локали и маршруты по умолчанию.

Во время выполнения вызов только объединяет встроенные переводы для текущей локали и повторно объединяет их при смене локали. `locales`, `localeRoutes` и `disableMeta` действуют только через сборку, поэтому их изменение требует пересборки (dev-сервер пересобирает при сохранении).
