title: "Локализованные пути"
description: "Задайте странице свой URL для каждой локали с помощью localeRoutes или globalLocaleRoutes, включая динамические параметры и slug для каждой локали."
---

По умолчанию каждая локаль отдаёт страницу по одному и тому же пути: `/en/about`, `/de/about`. Локализованные пути позволяют каждой локали использовать собственные слова, например `/de/ueber-uns`, при этом файл страницы остаётся тем же. Вы задаёте их в самой странице через `$defineI18nRoute` или сразу для многих страниц в `nuxt.config.ts`.

## В странице {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

При `prefix_except_default` и `defaultLocale: 'en'` страница отвечает по адресам `/about`, `/de/ueber-uns` и `/fr/a-propos`. Локаль без записи сохраняет путь по умолчанию. Пишите пути без кода локали: префикс добавляет [стратегия](/ru/guide/strategy), а путь, начинающийся с кода локали, вызывает предупреждение в логе. Что ещё принимает этот вызов, описано на странице [Конфигурация страницы](/ru/guide/per-component-translations).

## В nuxt.config {#in-nuxt-config}

[`globalLocaleRoutes`](/ru/api/module-options#globallocaleroutes) делает то же самое для любой страницы, используя в качестве ключа её путь (или имя маршрута, если он записан без ведущего слэша):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

Если страница задаёт `localeRoutes`, а в `globalLocaleRoutes` есть тот же ключ, побеждает запись из конфигурации.

## Динамические параметры {#dynamic-params}

Записывайте параметры в любой форме Nuxt: `[id]`, `[[page]]`, `[...slug]` или `:id()`. Имена параметров должны совпадать с файлом страницы.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

Вложенные страницы принимают абсолютный дочерний путь (`/ueber-uns/team`) или путь относительно локализованного пути родителя (`team`).

## Ссылки на локализованные страницы {#linking-to-localized-pages}

Ссылки разрешаются в локализованный путь целевой локали, передаёте ли вы имя маршрута или обычный путь:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

Имена маршрутов берутся из пути файла (`pages/about/team.vue` — это `about-team`), если только вы не задали имя через `definePageMeta({ name })`.

## Slug для каждой локали {#per-locale-slugs}

Когда сам slug отличается в разных локалях (`/our-products/red-shoe` и `/de/unsere-produkte/roter-schuh`), сообщите переключателю языка, какие параметры использовать, с помощью `$setI18nRouteParams` после загрузки данных:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

После этого `$switchLocalePath('de')` и `<i18n-switcher>` ведут на `/de/unsere-produkte/roter-schuh`. Ключи — коды локалей, значения — параметры по имени (как в файле страницы).

Переключатель в layout рендерится раньше, чем асинхронный setup страницы доходит до этого места, поэтому по окончании рендеринга модуль переписывает ссылки `<i18n-switcher>` — и в `app.vue`, и в самой странице. Благодаря этому серверный HTML, посетитель без JavaScript и первый клиентский рендер совпадают. Для этого задавайте параметры во время SSR: при `lazy` или `server: false` ссылки изменятся только после гидратации. SSR-стриминг Nuxt отправляет HTML до того, как параметры станут известны, поэтому при нём ссылки в первом HTML сохраняют собственные параметры URL.

Переписываются только собственные ссылки переключателя. Ссылка с `$switchLocalePath`, написанная вручную, должна рендериться после установки параметров, поэтому размещайте её в странице, которая их задаёт, причём после `await`. В layout она рендерится первой: её серверный HTML сохраняет параметры URL, и гидратация предупреждает о несоответствии. Используйте там `<i18n-switcher>`, а внешний вид настраивайте через его слоты и пропсы `custom*Style`.

Параметры принадлежат странице, которая их задала:

- Они сбрасываются, когда фиксируется навигация на другой путь, поэтому каждая страница задаёт свои. Отменённая навигация оставляет их на месте.
- Берите `$setI18nRouteParams` из `useNuxtApp()` или `useI18n()` в `setup`, даже если вызываете его позже в обработчике `useAsyncData`. Полученная там функция знает свою страницу: если посетитель уже ушёл, поздний вызов ничего не делает.
- С `keepalive` страница получает обратно заданные ею параметры, когда посетитель возвращается. `useI18nHead` ведёт себя так же.

## Маршруты, добавленные в pages:extend {#routes-added-in-pagesextend}

У маршрутов, которые вы добавляете в хуке `pages:extend`, нет файла страницы, из которого можно прочитать `$defineI18nRoute`, и часто несколько из них используют один общий компонент-обёртку. Маршрут, добавленный без `name`, получает имя, которое Nuxt дал бы его пути (`/a/:id()` становится `a-id`), поэтому языковые ссылки до него доходят, если только у другого маршрута уже нет такого имени; в этом случае задайте явный `name`. Ведите один список и разделяйте его на страницы и `globalLocaleRoutes` с ключами по имени маршрута с помощью `splitLocaleRoutes` из `@i18n-micro/utils/split-locale-routes` (добавьте пакет в зависимости):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

Не помещайте локализованные пути в `route.meta`: они попадут в клиентскую таблицу маршрутов.
