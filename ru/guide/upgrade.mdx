## После 3.30.3: мажорный выпуск {#after-3-30-3-the-major-release}

Опции модуля, `$t`, `$localePath`, `$switchLocale` и другие хелперы, компоненты, composables и документированные серверные утилиты сохраняют свои имена. Изменилось поведение — в основном это исправленные ошибки. В пакетах-адаптерах и пакетах маршрутизации есть реальные несовместимые изменения API: см. [Пакеты для фреймворков](#framework-packages) и [Другие пакеты](#other-packages).

### Сначала сделайте это {#do-this-first}

1. **Проверьте версии.** Модулю нужны Nuxt 3.18 или новее и Node 20 или новее. У Nuxt есть собственный минимум Node: Nuxt 4.5 объявляет `^22.19.0 || ^24.11.0 || >=26.0.0`. `nuxt generate` на самом Nuxt 3.18.0 падает и в чистом Nuxt (`[unstorage] Invalid key: "/"`); 3.21.11 работает. `@i18n-micro/react` нужен React 18 или новее.
2. **Исправьте установленные пакеты.**
   - Удалите `@i18n-micro/hmr`. HMR переводов встроен в модуль.
   - Если ваши тесты импортируют `@i18n-micro/test-utils`, добавьте его: `npm install -D @i18n-micro/test-utils`. Он больше не устанавливается вместе с модулем.
   - Замените `nuxt-i18n-micro-cli` на `@i18n-micro/cli`. 28 команд превратились в 16, `check` заменяет три из них, а коды выхода изменились: см. [руководство по CLI](/ru/guide/cli#moving-from-nuxt-i18n-micro-cli).
3. **Найдите в своём коде** элементы из таблицы ниже.
4. **Проверьте, что стоит перед приложением.** Если у локалей задан `baseUrl` и приложение находится за прокси, см. [За прокси или CDN](/ru/guide/deployment#behind-a-proxy-or-cdn). При использовании CDN сверьте его ключ кэша с заголовком `Vary`: см. [Кэширование HTML](/ru/guide/deployment#caching-html). При `apiBaseClientHost` или строгой CSP разрешите новую ссылку `preload`: см. [SEO и теги head](#seo-and-head-tags).
5. **Обновите снапшоты.** В снапшотах head появляется ссылка `preload`, разметка переключателя изменилась ([`<i18n-switcher>` и `<i18n-link>`](#&lt;i18n-switcher>-and-&lt;i18n-link>)), а строки запроса в результате `$localeRoute` кодируются иначе.
6. **Откройте свои страницы в каждой локали и поищите необработанные ключи.** Макеты, которые использовали ключи из файла предыдущей страницы, теперь показывают их как есть: перенесите эти ключи в корневой файл.

<Warning>

**`switchLocaleRoute` из `@i18n-micro/path-strategy` лишился первого аргумента** — `switchLocaleRoute(fromLocale, toLocale, route, options)` теперь записывается как `switchLocaleRoute(toLocale, route, options)`. **Старый вызов в JavaScript не падает: он возвращает неверный результат,** потому что `fromLocale` читается как целевая локаль, а `toLocale` — как маршрут. Сообщит об этом только TypeScript. `$switchLocaleRoute` в Nuxt это не затрагивает.

</Warning>

17 страниц этой документации переехали. Старые URL перенаправляют, поэтому ссылки на них продолжают работать.

### URL и перенаправления {#urls-and-redirects}

- **`/en` и `/en/...` дают 404 при `prefix_except_default`** (если `en` — локаль по умолчанию), как и описано в документации.
- **Префикс локали в другом регистре или написании даёт 404.** `/DE/about` раньше рендерил немецкий маршрут в локали по умолчанию или перенаправлял на `/en/DE/about`. Собственная страница по такому URL остаётся страницей. Catch-all или страница `[slug]` таковой не являются: `/DE/x` при `[...slug]` и `/DE` рядом с `[slug]` тоже дают 404, так что slug CMS, совпадающий с кодом локали в другом регистре, теряет свою страницу. При `ssr: false` сервер не отвечает, поэтому `/DE/about` показывает немецкую страницу.
- **Путь страницы в другом регистре перенаправляет на её собственное написание.** `/T/BASIC` отдавал 200, а теперь даёт `302` на `/t/basic`.
- **Неизвестный URL остаётся 404.** При `autoDetectPath: '*'` или `'no_prefix'` `/nope` больше не перенаправляется сначала на `/de/nope`. `prefix` сохраняет перенаправление (там ничего не обслуживается без префикса), как и `/` везде.
- **Пользовательский путь другой локали без префикса находит свою страницу при `prefix_except_default`.** `/a-propos` давал 404, а теперь даёт `302` на URL локали по умолчанию (`/about`). При `prefix` то же перенаправление теперь ведёт на существующую страницу (`/en/about`; раньше было `/en/a-propos`, то есть 404). `prefix_and_default` по-прежнему даёт 404.
- **`prefix` с `redirects: false` отвечает 404 на URL без префикса** (`/about` давал `302`), включая исходный URL страницы с пользовательским путём по умолчанию. `$localePath('/about')` по-прежнему находит эту страницу.
- **При `prefix_except_default` исходный URL страницы с пользовательским путём по умолчанию перенаправляет на него,** включая динамические страницы. `/dir/one` давал 404, а теперь даёт `302` на `/dir-one/one`.
- **`autoDetectPath: '*'` теперь применяет cookie и `Accept-Language` и к путям без префикса** (`/about` → `/de/about`).
- **При `prefix` URL без префикса сохраняет локаль посетителя.** При cookie `de` `/about` и обычный `<NuxtLink to="/about">` ведут на `/de/about` — на любом пути, что бы ни говорил `autoDetectPath`.
- **При `prefix_and_default` URL без префикса — это локаль по умолчанию.** `/contact` с `Accept-Language: de` раньше рендерился на немецком, а затем гидратировался на английском. Теперь он рендерится в локали по умолчанию; посетители попадают на немецкую версию через `/de/...`.
- **При `no_prefix` пользовательский путь рендерится в своей локали** (`/ueber-uns` — немецкий при любом предпочтении), а страница с ограниченным набором локалей рендерится в одной из обслуживаемых ею локалей. Путь, общий для нескольких локалей, рендерится в предпочтительной локали, если она входит в их число, а при `baseUrl` является страницей на каждом из их доменов. Эти локали используют одну запись: `localized-<page>-<first locale>`.
- **`noPrefixRedirect` ориентируется на локаль посетителя.** При cookie `de` `/about` ведёт на `/ueber-uns` и рендерится на немецком, а не на `/about-us` локали по умолчанию. Локаль без собственного пользовательского пути остаётся на `/about`.
- **Перенаправление `routeRules` без страницы не локализуется.** `/de/old` отдавал пустой 200, теперь это 404: добавьте правило для пути с префиксом, если оно нужно. Ссылка из другой локали на такое правило сохраняет путь как написан и попадает на цель правила.
- **Правила маршрутов распространяются на пользовательские пути.** `/blog/**` применяется и к `/de/artikel/:slug`, когда у `blog/[slug]` есть такой путь, и правила копируются также при `no_prefix`. Статический соседний путь, например `/de/artikel/news`, тоже совпадает с этим шаблоном. Правило, уже записанное под префиксом локали, остаётся как есть.
- **Локаль с `disabled: true` сразу отвечает 404 на своём префиксе,** а ссылки на неё остаются на странице. Локаль, отключённая во время выполнения, ведёт себя так же: раньше она рендерилась в резервной локали.
- **Страница 404 модуля выводит `Page Not Found`** на префиксе отключённой локали и на собственном префиксе хоста, где Nuxt выводил `Page not found: /de/about`. Статус тот же.
- **`customRegexMatcher` больше не даёт 404 для реальной страницы,** первый сегмент которой похож на локаль.
- **Имена локализованных маршрутов согласованы.** Дочерний маршрут в общей записи локалей сохраняет имя страницы, `no_prefix` учитывает `localizedRouteNamePrefix`, а родитель с дочерним index остаётся без имени.
- **Страницы, которые модуль добавляет без `name`** (`extendPages`), локализуются и получают имя, с вариантами для локалей и `hreflang`. Раньше они оставались нелокализованными.
- **Запись в `nuxt.config` имеет приоритет над `$defineI18nRoute`** при любой форме ключа (`about/team`, `/about/team`, `about-team`). Раньше то, что побеждало, зависело от написания.
- **Новые предупреждения сборки:** значение `localeRoutes`, начинающееся с кода собственной локали (`fr: '/fr/article'`), и пользовательский путь дочернего маршрута вне его родителя.
- **Hash-режим работает при `prefix`.** Документ — это `/`, а `/en` или `/about` перенаправляют в hash.
- **`/#/de/x` рендерится на немецком** при `prefix_except_default` и `prefix_and_default`. Раньше он рендерился на английском с ошибкой гидратации.

### Ссылки и объекты маршрутов {#links-and-route-objects}

- **Локаль, которая не обслуживает страницу, ссылается на свою главную страницу.** `$localeRoute`, `$switchLocalePath` и переключатель больше не возвращают страницу другой локали.
- **Неизвестный код локали ведёт на локаль по умолчанию.** `$localePath(path, 'xx')` и `$localeRoute` раньше давали `/xx`.
- **`$localePath` возвращает строку со схемой `http(s):`, `mailto:` или `tel:` как есть, а `path` и `fullPath` результата `$localeRoute` передают её без изменений**, поэтому не передавайте им непроверенное значение (параметр `?next=`) в качестве цели ссылки. `//host` и голые имена вроде `x.com` остаются путями на этом origin в каждой локали, и ни одна получаемая из них ссылка его не покидает: `/de//x.com` для локали по умолчанию — это `/x.com`. Обратные слеши считаются слешами.
- **`$localePath` кодирует путь:** `/a b` даёт `/a%20b`.
- **`$localeRoute` и `$switchLocaleRoute` возвращают простые объекты,** безопасные в `ref`, `reactive`, `useState`, JSON и spread. Когда параметр требует экранирования, объект имеет вид `{ path, fullPath, query, hash }` (`$localeRoute` добавляет `href`), без `name` и `params`, и URL остаётся одинаковым до и после перезагрузки. У обычного URL есть и то, и другое. `name` — новое поле: у старых объектов его никогда не было. Код, читающий `.name` или `.params`, должен обрабатывать их отсутствие, а то, какую форму вы получите, зависит от значения.
- **При `trailingSlash` `$switchLocaleRoute` всегда возвращает соответствующую форму пути,** в том числе для простых slug, а серверные перенаправления следуют `trailingSlash`. При этой опции результаты и заголовки `Location` могут измениться.
- **Значения query в результате `$localeRoute` используют кодирование vue-router:** `/` остаётся буквальным, а пробел — это `+` (`?redirect=/v2`, раньше было `%2Fv2`). Декодированное значение то же, но снапшот такого `href` меняется.
- **Ссылка без пути остаётся на текущей странице.** `$localePath('#top')`, `'?p=2'`, `''` и `{ query }` сохраняют страницу, на которой находятся; `'#top'` раньше отсчитывался от корня сайта. Голое `'about'` по-прежнему означает `/about`.
- **Spread.** `{ ...route, query }` и `{ ...route, hash }` сохраняют изменение, в том числе через `$switchRoute`. Новый `path` побеждает в `$localeRoute`, `$localePath` и `$switchRoute`. `{ ...route, params }` работает для именованного маршрута; для маршрута в форме пути побеждает путь, а params игнорируются с предупреждением vue-router в режиме разработки. Используйте `$localeRoute({ name, params })`.
- **`$switchRoute` остаётся внутри приложения.** Собственный `baseUrl` локали, `mailto:` и `tel:` выводят за его пределы; любая другая строка — это путь.
- **`excludePatterns`** сопоставляются с целыми сегментами (`'/admin'` больше не совпадает с `/administrator`), а glob-шаблоны привязаны к началу и концу (`/docs/*` больше не совпадает с `/en/docs/x`). Шаблоны `RegExp` теперь доходят до runtime; раньше они там терялись. Страница, совпадающая с ними, не локализуется: нет `hreflang`, а при `prefix_except_default` — локаль по умолчанию. Проверьте свои шаблоны по разделу [Исключение путей](/ru/guide/excluding-static-files).

`%` или `?` в параметре не переживают перезагрузку с серверным рендерингом на Nuxt 4.5.2 в любом приложении: это проблема upstream, а не модуля.

### Домены локалей {#locale-domains}

- **`locales[].baseUrl` теперь маршрутизирует запросы.** Одна сборка обслуживает все домены: см. [Слои и домены](/ru/guide/layers#multiple-domains). Если задан `baseUrl`, локаль другого домена на этом хосте даёт 404 (`/en/about` на `example.de`), а ссылки на локаль на том же хосте относительные. Запросы на любой другой хост, включая `localhost`, ведут себя как раньше, за исключением того, что canonical и `hreflang` используют `metaBaseUrl`, если он задан, иначе `baseUrl` локали по умолчанию, а не origin запроса.
- **За прокси, который переписывает `Host`,** каждый запрос попадает на конфигурацию сборки, пока вы не зададите [`trustForwardedHost`](/ru/api/module-options#trustforwardedhost). По умолчанию он равен `false`, в отличие от `metaTrustForwardedHost`. См. [За прокси или CDN](/ru/guide/deployment#behind-a-proxy-or-cdn).
- **`nuxi generate` с `baseUrl` требует `NUXT_I18N_DOMAIN`, по одному разу на домен.** Без него сборка выводит предупреждение, а эти локали становятся ссылками без страниц. См. [Статический сайт](/ru/guide/deployment#static-site-(nuxi-generate)).
- **Ссылка на локаль с `baseUrl` идёт через `$localePath` или `<i18n-link>`.** `<NuxtLink :to="$localePath(x, 'fr')">` и `<i18n-link :to="$localeRoute(x, 'fr')">` дают этот абсолютный URL, и клик ведёт туда. Роутер не принимает абсолютный объект: `<NuxtLink :to="$localeRoute(x, 'fr')">` и `router.push($localeRoute(x, 'fr'))` остаются `/https://fr.example.com/...` — путём этого приложения. На `localhost` или хосте предпросмотра каждая локаль с `baseUrl` является такой ссылкой, в том числе текущая. В коде используйте `navigateTo($localePath(x, 'fr'), { external: true })`.
- **Главная страница домена везде записывается без завершающего слеша** (`https://example.de`) — в ссылках, canonical и `hreflang`.
- **При `prefix` ссылка на другой домен сохраняет префикс локали, с `baseDefault` или без него.** `https://example.de/de/about`, а не `https://example.de/about`, который лишь перенаправляет.
- **При `prefix_except_default` с `baseDefault` на локали, отличной от локали сборки по умолчанию, маршруты сохраняют все префиксы,** чтобы другие домены могли на них ссылаться. `/en` по-прежнему даёт 404. Разницу видит только код, читающий `router.getRoutes()`.
- **При `prefix_except_default` собственный префикс хоста даёт 404 на его хосте `baseDefault`.** `/de/x` на хосте `de` отдавал 200.
- **`$getI18nConfig().locales` содержит только то, что обслуживает хост.** `linkLocales` содержит их все, а `$getLocales()` остаётся полным.

### Навигация и `$switchLocale` {#navigation-and-$switchlocale}

- **Навигация применяется при фиксации.** Словарь, локаль, параметры и head меняются в `router.afterEach`, поэтому отменённая или заблокированная навигация ничего не меняет, а ссылки старой страницы остаются действительными, пока загружается следующий чанк. `beforeResolve`, `beforeRouteEnter` или более поздний глобальный guard теперь видят старые словарь и локаль. Route middleware это не затрагивает.
- **Неудачная загрузка чанка сохраняет текущий словарь.** 5xx, сетевая ошибка или некорректное тело корневого файла раньше приводили к показу необработанных ключей. Теперь новая страница рендерится со старыми строками, а следующая навигация повторяет попытку. 404 или SPA-оболочка статического хоста на месте файла дают корневой словарь до следующей перезагрузки.
- **`$switchLocale` разрешается в `true` или `false`** (раньше ни во что), `false` — когда словарь локали не был применён. Он типизирован как `Promise<boolean>`, а `$switchRoute` — как `Promise<void>`.
- **`$switchLocale` — явный выбор.** По прибытии он сохраняет локаль, в том числе на 404. Если навигация заблокирована, отменена или выбрасывает ошибку, сохранённое предпочтение и состояние остаются прежними, а ошибка пробрасывается дальше. Переход на другой хост сначала сохраняет её. При `no_prefix` и в hash-режиме переключение остаётся в силе, что бы ни происходило с навигацией. На странице с одним URL для всех локалей (`excludePatterns`) выбор не отменяется, а решает URL следующей страницы: при `prefix_except_default` ссылка без префикса возвращает к локали по умолчанию.
- **При `no_prefix` `$switchLocale` сохраняет свою страницу, когда две страницы используют общий пользовательский путь,** в том числе с экранированными параметрами. Перезагрузка такого URL и `$localeRoute` с экранированным параметром попадают на первую запись.
- **Клиентское перенаправление сохраняет режим своей навигации.** Обычный `<NuxtLink to="/about">` при `prefix` добавляет запись в историю вместо перезаписи текущей; `router.replace` по-прежнему заменяет.
- **`$setI18nRouteParams` и `useI18nHead` с сервера переживают гидратацию.** После перехода на `/news/2` переключатель ссылается на переведённый slug (`/de/news/2-zwei`), а не на `/de/news/2`, в том числе в серверном HTML, где бы ни находился переключатель, если страница задаёт параметры во время SSR. Они сбрасываются, когда фиксируется навигация на другой путь, включая переход с `/news/1` на `/news/4`: задайте их снова на новой странице.
- **`$setI18nRouteParams`, прочитанный в setup, привязан к этой странице.** Поздний вызов со страницы, которую уже покинули, ничего не делает. `useNuxtApp().$setI18nRouteParams` теперь является аксессором, и два чтения дают две функции. Сеттера у него нет: `useI18n().$setI18nRouteParams = fn`, как может сделать тестовая заглушка, выбрасывает ошибку в strict mode, поэтому подменяйте сам `useI18n`. В макете или `app.vue` это обычная функция, так как там ничего не покидается.
- **Сервер переписывает ссылки `<i18n-switcher>` по окончании рендеринга** на страницах с параметрами, потому что переключатель в макете рендерится раньше асинхронного setup страницы. Написанная вручную ссылка `$switchLocalePath` не переписывается: см. [пользовательские маршруты локалей](/ru/guide/custom-locale-routes). При SSR-стриминге Nuxt первый HTML сохраняет параметры URL.
- **Prop с именем `locale` у серверного компонента задаёт локаль его рендеринга**, поэтому `<Greeting :locale="$getLocale()" />` следует за URL и переключением. `$getLocale()`, `$localePath` и `$getLocaleName` внутри него тоже следуют за prop. См. [серверные переводы](/ru/guide/server-side-translations). Без prop он по-прежнему использует cookie или значение по умолчанию.
- **Страницы с `keepalive` получают свои параметры и head обратно** при возвращении.
- **Вложенная страница, для которой задано `false` при `prefix_except_default`, не имеет URL локали.** `/de/parent/kid` с `globalLocaleRoutes: { 'parent-kid': false }` обслуживался, а теперь даёт 404: страница остаётся на `/parent/kid`.

### Определение локали и cookie {#locale-detection-and-the-cookie}

Везде действует один порядок приоритета, описанный в разделе [Определение локали](/ru/guide/locale-detection).

- **`?locale=` учитывается на страницах только при `no_prefix`.** При стратегиях с префиксом решает URL; `/about?locale=de` больше не рендерится на немецком при `lang="en"`. `?locale=de&locale=fr` читает первое значение, раньше было `"de,fr"`.
- **`Accept-Language` учитывает значения `q`** (`fr;q=0.1, de;q=0.9` → `de`; `q=0` исключает язык). Региональное сопоставление больше не зависит от порядка `locales` и никогда не пересекает системы письма китайского языка.
- **Клиентская навигация на страницу сохраняет её локаль в cookie, в том числе на странице без префикса для локали по умолчанию.** Если задан `localeCookie`, у посетителя, который нажал ссылку на `/about`, теперь будет `user-locale=en`, и последующая смена языка браузера больше не перенаправляет `/`. Первая загрузка этого URL ничего не сохраняет. При `no_prefix` и в hash-режиме навигация сохраняет только изменение.
- **404 не записывает cookie:** ни ответ, ни обычная клиентская навигация на неё, ни в каком режиме. При `no_prefix` URL, похожий на URL с префиксом, тоже ничего не записывает.
- **При `no_prefix` явный `localeCookie: null` учитывается.** Раньше он превращался в `user-locale`. Задавайте его в блоке `i18n` в `nuxt.config`: `null` в `modules: [[name, opts]]` или в слое по-прежнему теряется.
- **Hash-режим читает только cookie `hash-locale`.** Одиночный `user-locale=de` больше не учитывается.
- **Некорректный cookie локали игнорируется и остаётся как есть,** вместо того чтобы ронять каждую SSR-страницу с 500. Он больше не удаляется при каждом запросе, что также мешало странице с префиксом сохранять свою локаль.
- **Локаль из URL идёт первой.** `setLocale('de')` из плагина на `/en/...` больше не загружает словарь `de`, а неизвестный код в состоянии игнорируется.
- **Серверные API-хелперы** (`useLocaleServerMiddleware`, `useTranslationServerMiddleware`) используют один порядок на каждом маршруте: `?locale` → параметр `[locale]` или префикс → cookie → заголовок → значение по умолчанию. Теперь они учитывают `localeCookie: null` и `autoDetectLanguage: false` и кэшируют словарь для каждой локали.
- **Переопределения во время выполнения доходят до маршрутизации.** `NUXT_I18N_DEFAULT_LOCALE` и `disabledLocales`, заданные во время выполнения, теперь меняют сгенерированную стратегию (отключённая локаль перестаёт маршрутизироваться), а `disabledLocales` времени выполнения добавляются к заданным при сборке. При `prefix_except_default` и `prefix_and_default` `defaultLocale`, заданный во время выполнения, игнорируется с предупреждением, потому что маршруты этой локали без префикса генерируются при сборке. `fallbackLocale`, заданный во время выполнения, должен быть включённой локалью: иначе он отбрасывается с предупреждением, и применяется значение из сборки, если та локаль включена. См. [Переопределения во время выполнения](/ru/guide/runtime-overrides).

### SEO и теги head {#seo-and-head-tags}

- **`dir="auto"` больше не используется по умолчанию.** Локаль без `dir` раньше получала `dir="auto"`, что замедляет разбор больших страниц. Теперь известный RTL-язык получает `dir="rtl"`, а любая другая локаль — никакого атрибута. Это относится к Nuxt, `@i18n-micro/vue`, `astro` и `vitepress`. Если вы зададите `dir: 'auto'` для локали, чтобы сохранить старый вывод, это стоит около 1 с разбора на 20 000 элементов: см. [Направление текста](/ru/guide/seo#text-direction).
- **На каждой SSR-странице появляется новый тег:** `<link rel="preload" as="fetch" crossorigin="anonymous" href="/_locales/...">`, в том числе на страницах 404. При `apiBaseClientHost` `href` указывает на этот хост, что требует CORS. Строгая CSP должна это разрешать.
- **`hreflang` перечисляет только локали, которые обслуживают страницу**; `x-default` выводится только тогда, когда её обслуживает локаль по умолчанию.
- **У нелокализованной страницы нет `hreflang` и `og:locale:alternate`.**
- **Canonical и `hreflang` включают `app.baseURL`**, когда origin берётся из запроса. `metaBaseUrl` и `site.url` остаются как написаны.
- **Страницы 404 содержат `<html lang dir>`** в локали URL. У них нет canonical, `hreflang`, `og:url`, `og:locale` и альтернатив, в том числе когда модуль сам отвечает 404 на совпавшую запись (`/en/...`). Теги, которые вы передаёте через `replace` в `useI18nHead`, остаются, поэтому не выводите их на страницах ошибок.
- **Canonical, `og:url` и `hreflang` сохраняют query из белого списка** (`/about?page=2`), в том числе на сервере: во время SSR он отбрасывался. По умолчанию в белом списке `page`, `sort`, `filter`, `search`, `q`, `query` и `tag`; см. [`canonicalQueryWhitelist`](/ru/api/module-options#canonicalquerywhitelist).
- **`X-Forwarded-Host`, который не удаётся разобрать, игнорируется** вместо 500 на каждой странице. Если пригодного хоста нет, а также нет `metaBaseUrl` или `site.url`, URL в canonical и `hreflang` в этом ответе относительные. `Host`, который не удаётся разобрать, по-прежнему даёт 500, как в обычном приложении Nuxt.
- **`disableMeta` теперь работает** — как в `$defineI18nRoute`, так и в `routeDisableMeta`, в том числе при задании в `nuxt.config`: у страницы нет `hreflang`, canonical и `og:locale`. `lang` и `dir` остаются.
- `useLocaleHead()` также возвращает `build()` — геттер для `useHead(() => build())`.
- В обычной сборке без `metaBaseUrl` `X-Forwarded-Host` по-прежнему выбирает хост в этих тегах, как и раньше. Зафиксируйте `metaBaseUrl`, если origin доступен напрямую: см. [За прокси или CDN](/ru/guide/deployment#behind-a-proxy-or-cdn).

### Переводы {#translations}

- **Объединение глубокое на каждом уровне.** Корневые, страничные и резервные файлы использовали двухуровневое объединение, поэтому `a.b.c` из резервного или корневого файла терялся в режиме source и в режиме разработки. Теперь все режимы дают одинаковый словарь.
- **Цепочки резервных локалей проходятся до конца** (`fr` → `de` → `en`) в каждом режиме.
- **Объединение идёт по локали, а не по виду файла.** Корневой файл активной локали теперь побеждает страничный файл резервной локали. См. [Резервные локали](/ru/guide/translations#fallback-locales).
- **Элемент `locales` проекта побеждает элемент слоя** с тем же `code`; слой лишь заполняет пробелы.
- **Страница без собственной папки `pages/<name>/` читает корневой словарь,** в том числе дочерние страницы. Раньше она получала `{}` и показывала необработанные ключи. В выводе появляется файл для каждой такой страницы и `__root/<locale>/data.json` для каждой локали: `/_locales/<any name>/en/data.json` отдаёт 200 с корневыми ключами, раньше было `{}`. Это важно для мониторинга, списков разрешённых путей на статических хостах и инструментов, читающих дерево.
- **`disablePageLocales: true` читает только корневые файлы;** `pages/index` больше не подмешивается.
- **Ключи покидаемой страницы перестают разрешаться, когда её элемент покидает документ.** Если макет использовал ключи, которые были только в файле предыдущей страницы, перенесите их в корневой файл. Ключи родителя остаются, пока показан его дочерний маршрут, включая родителя с дочерним `index`, до следующей навигации. Между двумя дочерними маршрутами одного родителя собственным ключам родителя нужен словарь дочернего маршрута или корневой.
- **`$clearCache()` перезагружает словарь текущей страницы** и держит старый на экране, пока не придёт новый. Неудачная перезагрузка сохраняет старый словарь, ответ, запрошенный до очистки, отбрасывается, а страница в своём уходящем переходе остаётся переведённой.
- **`$has(key, route)` учитывает маршрут.**
- **`$loadPageTranslations` на ещё не посещённой странице больше не мешает загрузке её файла.** Файл загружается при первом посещении, а ваши ключи остаются поверх него. Раньше страница показывала необработанные ключи до перезагрузки.
- **HMR переводов применяет правки на месте**, без перезагрузки страницы; удалённые ключи исчезают, а правки корня доходят до всех страниц.
- **Повреждённый файл локали один раз выводит предупреждение с указанием пути, в каждом режиме.** Раньше в режиме разработки выбрасывалась ошибка, а premerged молча пропускал его, так что приложение, которое полагалось на жёсткое падение в режиме разработки, больше этого не увидит.

### Множественные формы и форматирование {#plurals-and-formatting}

- `$tc` с отрицательным, дробным или очень большим значением count берёт последнюю форму с реальным count; `{ count: null }` больше не выбрасывает ошибку; отсутствующий ключ множественной формы доходит до обработчика отсутствующих ключей.
- `$tdr` выдаёт настоящие будущие даты (`in 3 days` или `tomorrow` при `numeric: 'auto'`) и `Invalid Date` для некорректного входного значения. Меньше секунды в прошлом — это `0 seconds ago`.
- **`$tn`, `$td` и `$tdr` ориентируются на `iso`**, как и множественные формы: `{ code: 'en', iso: 'en-GB' }` теперь форматирует даты как `31/10/2026`. В коде локали `_` читается как `-`, поэтому `en_US` больше не выбрасывает ошибку, а код, неизвестный `Intl`, форматируется как `en`, а не по локали машины. Именованные форматы по-прежнему ищутся по `code`.
- Плейсхолдер `{param}` читает только переданные вами параметры (`{constructor}` остаётся как написан).
- Имена `{placeholder}` могут содержать любые символы, кроме фигурных скобок и пробелов: `{firstName}`, `{first-name}` и `{user.name}` читаются из `params`. Без такого параметра они, как и раньше, остаются как написаны.
- `defaultValue` интерполируется в `$t` и `$tc`: `$t('missing', { n: 1 }, 'Got {n}')` даёт `Got 1`, раньше давало `Got {n}`. Значение по умолчанию, не являющееся строкой, возвращается как есть.
- `$tc` для пустого перевода возвращает `''`, как и `$t`. Раньше он возвращал значение по умолчанию или ключ.
- **Шаблоны множественных форм сохраняют своё значение, за одним исключением.** В таблице перечислены все варианты. Чтобы получить категории `Intl.PluralRules`, укажите это явно новым [маркером `=0 `](/ru/api/methods#$tc): `=0 no apples | one apple | {count} apples`.

  | Вид | Пример (в `uk`) | Раньше | Теперь |
  | --- | --- | --- | --- |
  | Любой шаблон в локали с одной или двумя целочисленными категориями (`en`, `de`, `fr`, `es`, `ja`...) | `none \| one \| {count} many` | по индексу | **без изменений** |
  | По одной форме на категорию | `one \| few \| many` | по индексу: 21 → `many` | **без изменений**. Добавьте маркер, чтобы получить 21 → `one` |
  | Сначала нулевая форма, три формы | `none \| one \| many` | по индексу | **без изменений** |
  | Другие плейсхолдеры | `no items \| {n} item \| {n} items` | по индексу | **без изменений** |
  | `{count}` в каждой форме | `{count} many \| {count} one \| {count} few` | по индексу | **без изменений** |
  | Меньше или больше форм, чем ниже | `a \| b`, `none \| one \| two \| {count} many` | по индексу | **без изменений** |
  | В `lv`, `prg`, `blo`, `cv`, `ksh`, `lag` | `none \| one \| {count} many` | по индексу | **без изменений** |
  | С маркером `=0 ` | `=0 none \| one \| many` | маркер выводился как текст | нулевая форма, затем категории |
  | **Нулевая форма без плейсхолдера, затем по одной форме на категорию, с `{count}` в каждой форме, общей для нескольких значений count** | `none \| {count} one \| {count} few \| {count} many` | по индексу: 3 → `3 many`, 21 → `21 many` | **по категории**: 3 → `3 few`, 21 → `21 one`. 0, 1, 2 и все значения count, остающиеся в `many`, дают тот же результат |

  Последнему варианту нужны три или более категорий (`ru`, `uk`, `pl`, `cs`, `sk`, `hr`, `sr`, `lt`, `ro`, `sl`, `he`, `ar`, `cy`...). В `ar` `one` и `two` — единичные значения, поэтому этим двум формам число не нужно.
- **Код локали, неизвестный `Intl`, получает правило по индексу** — с категориями маркера или без них: `ua` больше не следует локали машины. Задайте `iso`: `{ code: 'ua', iso: 'uk-UA' }` склоняется как украинский, в модуле и в `@i18n-micro/vue`.
- **Пользовательское правило `plural` сохраняет свою сигнатуру** и по-прежнему получает код локали. Оно читает исходное значение, поэтому шаблон с маркером доходит до него с `=0 ` на месте, а count оно получает как `Number`: `1.5` там, где раньше получало `1`. Возврат `null` откатывается к встроенному правилу, которое учитывает маркер.
- **Опция `timeZone`.** Задайте её (`Europe/Berlin`), чтобы отображать одну и ту же календарную дату на сервере и во всех браузерах. На `relativeDate`, которая зависит от часов, она не влияет.

### `<i18n-t>` {#&lt;i18n-t>}

Этот раздел относится к `<i18n-t>` в модуле и `I18nT` в `@i18n-micro/vue`. Для других фреймворков см. [Пакеты для фреймворков](#framework-packages).

- **`html` экранирует `params` во всех случаях и игнорирует все слоты.** Доверенной разметкой считается только перевод. Параметр, намеренно содержавший разметку, теперь отображается как текст: поместите разметку в перевод и передавайте данные как параметры либо используйте слоты без `html`.
- **Слоты работают с `plural`, `number`, `date` и `relativeDate`,** и слот `default` в этих случаях тоже получает `{ translation }`. Заполняется каждый `{name}`, а не только первый.
- **Слот побеждает параметр с тем же именем.** Значение параметра, похожее на плейсхолдер, остаётся текстом. При `customPluralRule` или пользовательском `plural` правило возвращает готовую строку, поэтому интерполированный им параметр там может быть принят за плейсхолдер.
- **`null` означает «не задано»** для `plural`, `number`, `date` и `relativeDate`. `:plural="null"` раньше ломал рендеринг, `:date="null"` выводил 1970 год.
- `plural` считает так же, как `$tc`, через `Number`: `1.5` остаётся `1.5` и берёт последнюю форму, раньше обрезалось до `1`; `"2 items"` — это `NaN`, раньше было `2`; `""` — это `0`. `customPluralRule` тоже видит `1.5`. Остальной его контракт не изменился: те же аргументы, его ответ используется как есть, `null` рендерится пустым.
- `hideIfEmpty` применяется к `plural`, `number`, `date` и `relativeDate`. Скрытое значение рендерится как комментарий, а не пустой текстовый узел, поэтому тест, читавший `''`, увидит `<!---->`.
- **Отсутствующий ключ при `html` — это текст.** Ключ экранируется, потому что доверенным считается только перевод, а ключ может прийти из запроса. `defaultValue` принадлежит вам и остаётся разметкой.
- С `plural` `defaultValue` или ключ при промахе выводятся целиком, как в `$tc`: `a | b` больше не разделяется.
- `defaultValue` заменяет отсутствующий ключ в каждой ветке, а не сам ключ, и `customPluralRule` получает его через свой геттер при промахе. Раньше оно действовало только после `hideIfEmpty`.
- `<i18n-t>` с `number`, `date` или `relativeDate` сохраняет `params`; они подмешиваются.
- Вывод `date` и `relativeDate` содержит `data-allow-mismatch="text"`: часы или часовой пояс, различающиеся на сервере и в браузере, больше не вызывают предупреждения при гидратации. Рядом с именованным слотом текст вокруг слота находится в собственном `<span>`, потому что Vue проверяет этот атрибут только для единственного текста элемента.
- Атрибуты `.innerHTML` и `textContent` отбрасываются вместе с `innerHTML`.
- `<i18n-t>` и `<i18n-group>` читают активный словарь, как `$t`, а не чанк маршрута. Вытесненные чанки (`cacheMaxSize`) больше не приводят к показу необработанных ключей. Страница в своём уходящем переходе теперь читает то же, что читает там `$t`: словарь новой страницы с откатом к собственному при промахе, поэтому ключ, определённый на обеих страницах, показывает новый текст, а после смены локали её собственные ключи отображаются необработанными, пока она не будет размонтирована.

### `<i18n-switcher>` и `<i18n-link>` {#&lt;i18n-switcher>-and-&lt;i18n-link>}

- **Клик по ссылке переключателя — это одна навигация.** Это обычный `<a>`, вызывающий `$switchLocale`, а не `NuxtLink` плюс обработчик клика, поэтому классов `router-link-active` больше нет. `href` по-прежнему содержит `app.baseURL`, а у ссылки текущей локали по-прежнему есть `aria-current="page"`. Ctrl/cmd-клик открывает новую вкладку и не трогает текущую. Ссылки сохраняют query и hash.
- Кнопка имеет `type="button"`, поэтому больше не отправляет окружающую форму, и имеет `aria-expanded`. `aria-haspopup` удалён в модуле, `@i18n-micro/vue` и `@i18n-micro/astro`: он обещал меню, а список состоит из ссылок. Escape и клик снаружи закрывают выпадающий список; два переключателя больше не остаются открытыми одновременно.
- Обёртка и выпадающий список имеют классы `i18n-switcher-wrapper` и `i18n-switcher-dropdown`; кнопка имеет `i18n-switcher-button` наряду с `language-switcher`, а её подпись находится в `<span>`. Стили по умолчанию используют логические CSS-свойства (`inset-inline-start`, `margin-inline-start`), а стрелка — `▾`. Выпадающий список имеет `z-index: 1000` (было 10), `min-width: 150px` и `box-shadow`, обёртка — `vertical-align: middle`. У каждой ссылки есть `lang`, а также `dir`, если локаль его задаёт.
- `<i18n-link>`: `https://`, `mailto:` и `tel:` распознаются в любом регистре (`HTTPS://x.com`, `Mailto:`). Голые `report.pdf` или `index.html` — это маршрут, а не `https://report.pdf`; `example.com` и `example.com:8080` остаются внешними. Окончание файла, являющееся также TLD (`example.md`, `x.zip`), считается файлом: пишите `https://`. `activeStyle` игнорирует завершающий слеш, query и hash. Теперь он типизирован как `CSSProperties`, поэтому некоторые типизированные значения может потребоваться изменить.

### Хуки, плагины и типы {#hooks-plugins-and-types}

- **`i18n:register` выполняется на `app:created` при запуске,** после всех плагинов, а не между ними. У плагина с `order` выше 1 или `enforce: 'post'` теперь тоже вызывается подписчик при запуске, но в собственном `setup` он больше не читает зарегистрированные ключи. При навигации хук теперь выполняется раньше guard'ов `router.beforeEach` других плагинов.
- **`i18n:register` получает локаль страницы, которую заполняет.** При `hashMode` навигация, меняющая локаль, раньше передавала старую, и ключи попадали не в тот чанк.
- **`i18n:register` — runtime-хук:** регистрируйте его через `nuxtApp.hook('i18n:register', …)` в плагине, без `@ts-expect-error`. См. [Хуки](/ru/api/events).
- **`hooks: false` и `define: false`** по-прежнему отключают свои части.
- **При `plugin: false` `$defineI18nRoute` остаётся вызываемым** и ничего не делает во время выполнения. Раньше он ронял страницу.
- Опция `hooks` больше не документирует `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`; они никогда не генерировались.
- `const { $defineI18nRoute } = useNuxtApp()` на странице теперь работает с конфигурациями, использующими переменные.
- У `useI18n()` больше ключей: `clearCache`, `pluralFunc`, `pluralLocale`. `clearCache` есть в его типе.
- `$getRouteName(route)` отвечает для переданного маршрута. Раньше он возвращал пустую строку.
- `useI18nLocale()` убирает `getLocaleWithServerFallback(serverLocale)`: пишите `getPreferredLocale() ?? serverLocale ?? null`.
- **`$getI18nConfig()` доступен только для чтения на сервере в режиме разработки.** Запись там выбрасывает ошибку, а в продакшене она дошла бы до каждого запроса.

### Сервер, сборка и развёртывание {#server,-build-and-deployment}

- **Payload-файл страницы содержит только то, что отличается от корня локали.** Клиент загружает корень один раз и накладывает поверх него каждую страницу, поэтому на диске и в Edge-бандлах становится меньше, а вторая страница стоит лишь долю от первой. `premerged` теперь записывает `__root/<locale>/data.json`, а `/_locales/<page>/<locale>/data.json` содержит только разницу: всё, что читает эти файлы напрямую, должно объединять их. Полный словарь по-прежнему является допустимым файлом, поэтому хост или режим `source`, отдающий его, продолжает работать.
- **Файлы словарей кэшируются по версии.** URL с текущим `?v=` закрепляется на год на Node-сервере, другие URL перепроверяются, а статическая копия хоста отвечает с `max-age=60`: см. [Заголовки кэша](/ru/guide/deployment#cache-headers-and-datebuild). `httpCacheControl: false` сохраняет `max-age=0`. Перевод, изменённый без пересборки, доходит до браузера только при изменении `v`: задайте `NUXT_I18N_DATE_BUILD`.
- **Словари следуют `app.cdnURL`.** Браузер загружает публичные payload-файлы из `<cdnURL>/_locales/...`, где раньше использовал `app.baseURL`: CDN должен содержать `_locales/` и разрешать origin вашего сайта (CORS). См. [App baseURL и хосты payload](/ru/guide/deployment#app-baseurl-and-payload-hosts).
- **SSR больше не запрашивает `/_locales` по HTTP,** поэтому серверный middleware или лог на этом маршруте перестают видеть чтения при рендеринге. Внешний `apiBaseServerHost` по-прежнему работает через HTTP.
- **Неудачное чтение больше не закрепляется, как и 404.** 404 от хоста означает, что такого файла у него нет: рендеринг показывает корневой словарь, как и браузер, ничего не сохраняется, а файл будет прочитан, как только появится. Любой другой сбой, 200 с телом, не являющимся JSON-объектом, или нечитаемый либо повреждённый локальный файл не попадают ни в какой кэш, и следующий запрос читает заново: рендеринг страницы пишет предупреждение в лог, показывает необработанные ключи и отвечает `503` с `no-store` и `Retry-After`, так что правило маршрута или CDN ничего из этого не сохраняют, а браузер всё равно читает словарь при гидратации; `/_locales/...` отвечает `503` с `no-store`, а `useTranslationServerMiddleware` даёт `t`, который возвращает ключ или значение по умолчанию. Во время сбоя каждый запрос доходит до хоста, а хост, не отправивший заголовки ответа за 60 секунд, проваливает чтение. Медленная загрузка большого файла не ограничена. См. [Когда словарь не удаётся прочитать](/ru/guide/deployment#when-a-dictionary-cannot-be-read). `/_locales` тоже передаёт этот 404 дальше, где раньше отвечал `200 {}`.
- **Пререндеринг, который не может загрузить свой словарь, завершается ошибкой,** как и тот, у хоста которого нет ни файла страницы, ни корневого файла. Маршрут даёт 500, предупреждение называет локаль и страницу, и файл не записывается; при `failOnError` по умолчанию в Nuxt сборка завершается с кодом 1. Страница без собственного файла поверх корневого файла пререндерится с корнем.
- **Хост, заданный при сборке, отвечает для SSR,** в том числе с публичной копией по умолчанию и на странице ошибки по внутреннему пути. Раньше отвечал публичный файл. `NUXT_I18N_APP_BASE_SERVER_HOST` во время выполнения теперь доходит до `/_locales` и серверного загрузчика, а рендеринг читает любой из хостов через этот загрузчик.
- **При пользовательском `nitro.output.publicDir` и любой другой структуре, где `public/` не находится рядом с сервером, payload-файлы встраиваются.**
- **`nuxi build --preset <static preset>` пререндерит так же, как `nuxi generate`,** поэтому может записать больше файлов. `nuxi generate` пререндерит каждую статическую страницу в каждой обслуживающей её локали, есть на неё ссылка или нет, если только правило маршрута не задаёт `prerender: false`.
- **`source` или `publicAssets: false` при статическом выводе вызывают предупреждение.** Браузеру нечего читать.
- **Предупреждение о встраивании теперь — проверка размера.** Сборка предупреждает только при превышении лимита платформы: см. [Лимиты бандла](/ru/guide/deployment#bundle-limits-on-edge).
- **`Vary` задаётся везде, где решает посетитель:** на каждой странице при `no_prefix`, а также на `/` и любом другом URL, который может перенаправлять по предпочтению. Он содержит `Cookie`, когда используется cookie, и `Accept-Language` при `autoDetectLanguage`. Проверьте ключ кэша своего CDN: см. [Кэширование HTML](/ru/guide/deployment#caching-html).
- **Кэширование `/_locales` изменилось.** Кэша маршрутов Nitro на `/{apiBaseUrl}/**` нет, а заголовок `s-maxage=60, stale-while-revalidate` удалён. Если вы полагались на этот кэш, поставьте CDN перед маршрутом payload. Пустой словарь никогда не бывает `immutable`.
- **Серверный кэш по умолчанию ограничен:** не более 1000 записей, если `cacheMaxSize` не задан. `cacheTtl` отсчитывается с момента сохранения записи; чтения его больше не продлевают.
- **Новая опциональная настройка [`cacheStorage`](/ru/guide/performance#shared-cache-for-several-instances):** кэш словарей, общий для нескольких экземпляров. Если она не задана, ничего не меняется.

## С v2 на v3 {#from-v2-to-v3}

### Удалённые опции {#removed-options}

```diff
 i18n: {
-  includeDefaultLocaleRoute: true,
+  strategy: 'prefix',
-  fallbackRedirectComponentPath: '~/components/MyRedirect.vue',
-  experimental: { hmr: true, previousPageFallback: true },
+  hmr: true,
 }
```

- `includeDefaultLocaleRoute: true` — это `strategy: 'prefix'`; `false` — это `prefix_except_default` по умолчанию.
- `fallbackRedirectComponentPath` удалён: перенаправления выполняются на сервере до рендеринга и в клиентском route middleware. Пользовательская логика перенаправлений помещается в плагин, который задаёт локаль, см. [Пользовательское определение локали](/ru/guide/custom-auto-detect).
- `experimental.hmr` — это корневая опция `hmr` (включена по умолчанию).
- `previousPageFallback` удалён: ключи покидаемой страницы разрешаются до окончания её перехода, без какой-либо опции.

### Состояние локали {#locale-state}

Используйте `useI18nLocale()` вместо `useState('i18n-locale')` и `useCookie('user-locale')`:

```diff
- useState('i18n-locale').value = 'fr'
- useCookie('user-locale').value = 'fr'
+ useI18nLocale().setLocale('fr') // state and cookie together
```

### Конфигурация во время выполнения {#config-at-runtime}

Читайте конфигурацию, включая переопределения во время выполнения, через `$getI18nConfig()`:

```diff
- const cookieName = useRuntimeConfig().public.i18nConfig?.localeCookie
+ const { $getI18nConfig } = useNuxtApp()
+ const cookieName = $getI18nConfig().localeCookie
```

### Внутренние псевдонимы типов {#internal-type-aliases}

Если ваша IDE или `vue-tsc` не может разрешить импорты `#i18n-internal/*`, сопоставьте их в своём `package.json`. Nuxt разрешает их во время сборки, поэтому это нужно редко:

```json
{
  "imports": {
    "#i18n-internal/plural": "nuxt-i18n-micro/internals",
    "#i18n-internal/strategy": "nuxt-i18n-micro/internals",
    "#i18n-internal/config": "nuxt-i18n-micro/internals"
  }
}
```
