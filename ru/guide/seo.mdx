description: "Теги lang, hreflang, canonical и og:locale, которые добавляет модуль, как выбирается их базовый URL и как переопределить их для отдельной страницы."
---

При `meta: true` (по умолчанию) каждая локализованная страница получает `<html lang dir>`, ссылку canonical, альтернативы `hreflang`, `x-default` и теги локали Open Graph. Эта страница нужна, когда вы хотите задать публичный origin, настроить, какие локали попадают в теги, или переопределить их для одной страницы. Большинству сайтов достаточно `site.url` или `metaBaseUrl` и правильных кодов `iso`.

## Минимальная настройка {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

Тогда `/de/about` рендерит:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Направление текста {#text-direction}

`<html dir>` берётся из `dir` локали. Если он не задан, язык с письмом справа налево получает `rtl`, определяемый по `iso` (или `code`): арабский, иврит, персидский, урду и ещё несколько, а также любой тег с RTL-письменностью, например `az-Arab`. Все остальные локали не получают атрибута `dir`, что браузеры трактуют как `ltr`.

<Warning>

**`dir: 'auto'` увеличивает время разбора больших страниц** — `auto` на `<html>` заставляет браузер определять направление по содержимому во время разбора. В Chromium эти затраты растут быстрее, чем размер страницы: около 100 мс при 5 000 элементов и 1 с при 20 000. Используйте его только для небольшой страницы, язык которой вы не можете знать заранее.

</Warning>

## Какие теги вы получаете {#which-tags-you-get}

- **hreflang**: по одному тегу на каждую локаль, отдающую страницу, со значением `iso` (или `code`, если `iso` отсутствует) и её URL с тем же query, что и у canonical. Страница, ограниченная через [Конфигурацию страницы](/ru/guide/per-component-translations) или `routeLocales`, перечисляет только свои локали. [`hreflangBaseLanguage: true`](/ru/api/module-options#hreflangbaselanguage) также добавляет базовый язык (`es-ES` → `es`) для первой региональной локали.
- **x-default**: URL локали по умолчанию, только если локаль по умолчанию отдаёт страницу.
- **og:locale**: выводится из `iso` (`en-US` → `en_US`). Задайте `og` у локали, если сопоставление не прямое, например `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; без обоих значений `og:locale` не записывается, а в режиме разработки выводится предупреждение.
- **canonical / og:url**: текущий URL без query-параметров, кроме перечисленных в [`canonicalQueryWhitelist`](/ru/api/module-options#canonicalquerywhitelist) (по умолчанию `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

По стратегиям:

| Стратегия | hreflang и x-default | canonical, og:url, og:locale, атрибуты html |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | да | да |
| `no_prefix` | нет (один URL обслуживает все локали) | да |

## Задайте публичный origin {#set-the-public-origin}

Абсолютные URL используют первое из:

1. [`metaBaseUrl`](/ru/api/module-options#metabaseurl);
2. `site.url` из `nuxt-site-config` (устанавливается `@nuxtjs/seo`);
3. origin запроса с добавленным `app.baseURL`.

Зафиксируйте один из первых двух вариантов.

<Warning>

Запасной вариант с origin запроса читает `X-Forwarded-Host` и `X-Forwarded-Proto`, потому что [`metaTrustForwardedHost`](/ru/api/module-options#metatrustforwardedhost) и `metaTrustForwardedProto` по умолчанию равны `true`. Это безопасно только за прокси, который перезаписывает эти заголовки; иначе клиент может выбрать хост в ваших ссылках canonical, а кэш — раздать такую страницу дальше.

Если приложение доступно напрямую, зафиксируйте `metaBaseUrl`: в отличие от установки обеих опций в `false`, это также игнорирует поддельный `Host`. См. [За прокси или CDN](/ru/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

Запасной вариант полезен, когда одно развёртывание обслуживает несколько доменов: `https://site-a.com/en/about` и `https://site-b.com/en/about` получают каждый свой origin.

Если у локалей задан `baseUrl`, известный хост использует собственный `baseUrl` с приоритетом над `metaBaseUrl` и `site.url`, так что canonical и `og:url` остаются на этом домене, а `hreflang` направляет каждую локаль на её домен. Любой другой хост использует `metaBaseUrl`, иначе `baseUrl` локали по умолчанию, иначе `site.url`, поэтому поддельный `Host` не может повлиять на ваши теги. Если ничего из этого не задано, остаётся запасной вариант с origin запроса, а сборка выводит предупреждение. См. [Слои и домены](/ru/guide/layers#multiple-domains).

## Исключение локалей или страниц {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Если у локали по умолчанию задано `seo: false`, `x-default` не записывается. Чтобы отключить теги для одной страницы, используйте `disableMeta` в [Конфигурации страницы](/ru/guide/per-component-translations#turn-off-seo-tags) или [`routeDisableMeta`](/ru/api/module-options#routedisablemeta) в конфигурации.

## Переопределение тегов на одной странице {#override-tags-on-one-page}

Для контента из CMS, где существуют лишь некоторые переводы или URL приходят из API, замените сгенерированные теги с помощью [`useI18nHead`](/ru/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` также может задавать или удалять `canonical`, `xDefault`, `ogLocale` и `ogUrl`; `disable` отбрасывает целые группы (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Передавайте геттер, чтобы значения пересчитывались после смены локали. Для slug, различающихся по локалям, сначала задайте `$setI18nRouteParams` ([Локализованные пути](/ru/guide/custom-locale-routes#per-locale-slugs)), и сгенерированные альтернативы уже будут их использовать.

## Завершающий слэш {#trailing-slash}

`$localePath`, `$switchLocalePath`, объект маршрута из `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, редиректы локалей и SEO-URL следуют одному правилу слэша: по умолчанию `experimental.defaults.nuxtLink.trailingSlash`, либо [`trailingSlash`](/ru/api/module-options) в конфигурации i18n, если пути i18n должны отличаться.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) работает с этим модулем через `nuxt-site-config` 4+. Укажите `nuxt-i18n-micro` первым, чтобы конфигурация сайта могла прочитать локали, и задайте `site.url` один раз — он также используется для описанных выше тегов.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Переведённые название и описание сайта берутся из ключей `nuxtSiteConfig.name` / `nuxtSiteConfig.description` в ваших файлах локалей. Ошибка `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` означает, что `@nuxtjs/seo` старше версии 3; обновите его ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
