---

Переопределения во время выполнения позволяют запускать один артефакт сборки с разными настройками локалей для каждого окружения или арендатора без пересборки. Можно изменить локаль по умолчанию, резервную локаль и список отключённых локалей. Маршрутизация, редиректы, рендеринг и серверные хелперы используют переопределённые значения, как и браузер на странице, отрендеренной на сервере.

## Переопределения через переменные окружения {#set-overrides-with-environment-variables}

```bash
NUXT_I18N_DEFAULT_LOCALE=de \
NUXT_I18N_FALLBACK_LOCALE=en \
NUXT_I18N_DISABLED_LOCALES=fr,it \
node .output/server/index.mjs
```

| Переменная | Псевдоним |
| --- | --- |
| `NUXT_I18N_DEFAULT_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE` |
| `NUXT_I18N_FALLBACK_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE` |
| `NUXT_I18N_DISABLED_LOCALES` (через запятую) | `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES` |

Сервер читает их один раз при старте; чтобы применить изменение, перезапустите его. На странице, отрендеренной на сервере, браузер получает разрешённые значения от сервера. При `ssr: false` серверного рендеринга нет, а у браузера нет окружения: там применяется только `runtimeConfig.public.i18nRuntime`, и браузер выводит в лог предупреждения, описанные ниже.

## Переопределения в runtimeConfig {#set-overrides-in-runtimeconfig}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

Значение, заданное в `runtimeConfig.public.i18nRuntime`, имеет приоритет над переменной `NUXT_I18N_*` для того же поля.

Не путайте с переменной `DEFAULT_LOCALE` этапа сборки, которая заменяет `defaultLocale` при сборке и не требует поддержки во время выполнения.

## Что можно и нельзя изменить {#what-can-and-cannot-change}

| Настройка | Во время выполнения |
| --- | --- |
| `defaultLocale` | Да, при `prefix` и `no_prefix`. При `prefix_except_default` и `prefix_and_default` она фиксируется при сборке (её страницы — маршруты без префикса); переопределение игнорируется с предупреждением. |
| `fallbackLocale` | Да. |
| `disabledLocales` | Добавляется к локалям, отключённым при сборке; никогда не включает локаль обратно. Локаль по умолчанию из сборки нельзя отключить при `prefix_except_default` / `prefix_and_default`. |
| `strategy` | Нет. Стратегия, заданная во время выполнения, игнорируется с предупреждением; собирайте отдельный артефакт для каждой стратегии. |

Недопустимые значения никогда не ломают приложение. Каждый случай выводит одно предупреждение на серверный процесс:

- отключение всех локалей игнорируется;
- `defaultLocale`, которая не включена, заменяется первой включённой локалью;
- если `fallbackLocale` не включена, сохраняется значение из сборки, если оно включено, иначе резервной локали нет.

## Чтение действующей конфигурации {#read-the-effective-config}

```vue
<script setup lang="ts">
const { $getI18nConfig } = useNuxtApp()
const config = $getI18nConfig() // build config with overrides applied
</script>
```

Считайте её доступной только для чтения: на сервере она общая для всех запросов и заморожена в режиме разработки; копия в браузере не заморожена. Импорт конфигурации из `#build/i18n.strategy.mjs` даёт значения сборки без переопределений.

## Отключённые локали и статические файлы {#disabled-locales-and-static-files}

Локаль, отключённая во время выполнения, отвечает 404 на своих маршрутах и маршруте payload, но её файлы payload по-прежнему лежат в `.output/public/_locales/`, и статический файловый сервер их отдаёт. Если эти файлы не должны быть доступны, отключите локаль на этапе сборки с помощью `disabled: true`.
