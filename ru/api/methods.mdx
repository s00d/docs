Модуль внедряет свои хелперы среды выполнения в приложение Nuxt: `$t`, `$tc`, `$localePath`, `$switchLocale` и остальные. На этой странице можно посмотреть сигнатуру и поведение хелпера. Сигнатуры и описания взяты из интерфейсов `PluginsInjections` и `NuxtAppOnlyInjections` в `src/runtime/plugins/01.plugin.ts`.

## Доступ {#access}

| Где | Как |
| --- | --- |
| Шаблон | `{{ $t('title') }}` — любой хелпер, с `$` |
| `<script setup>` | `const { t, localePath } = useI18n()` — любой хелпер из `PluginsInjections`, с `$` и без него |
| Плагин, middleware, `<script setup>` | `const { $t, $defineI18nRoute } = useNuxtApp()` — всё, только с `$` |

`$defineI18nRoute` типизирован только в `useNuxtApp()`. См. [`useI18n`](/ru/composables/useI18n).

```vue
<script setup lang="ts">
const { t, localePath } = useI18n()
</script>

<template>
  <NuxtLink :to="localePath('/about')">{{ t('nav.about') }}</NuxtLink>
</template>
```

## Локаль {#locale}

### `$getLocale` {#$getlocale}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric) => string
```

Код активной локали. Передайте маршрут, чтобы узнать локаль, к которой он относится.

```ts
$getLocale() // 'de' on /de/about
```

### `$getLocaleName` {#$getlocalename}

```ts
() => string | null
```

`displayName` активной локали из конфигурации или `null`, если его нет.

### `$getLocales` {#$getlocales}

```ts
() => Locale[]
```

Все настроенные локали с их метаданными.

Пользовательские свойства объекта локали возвращаются в том виде, в каком записаны; типизируйте их с помощью [расширения модуля](/ru/api/module-options#locales) для `Locale`.

### `$defaultLocale` {#$defaultlocale}

```ts
() => string | undefined
```

Код настроенной локали по умолчанию.

### `$getI18nConfig` {#$geti18nconfig}

```ts
() => ResolvedI18nConfig
```

Итоговая конфигурация модуля в том виде, в каком её видит среда выполнения.

Значение учитывает [переопределения во время выполнения](/ru/guide/runtime-overrides) (`defaultLocale`, `fallbackLocale`, отключённые локали).

```ts
const { strategy, localeCookie } = useNuxtApp().$getI18nConfig()
```

## Перевод {#translation}

### `$t` {#$t}

```ts
TranslationFn<CleanTranslation>
```

Переводит ключ, подставляя в него `params`. Возвращает `defaultValue`, если ключ
отсутствует, или сам ключ, если значение по умолчанию не задано.

```ts
// { "welcome": "Welcome, {name}!" }
$t('welcome', { name: 'Ada' }) // 'Welcome, Ada!'
$t('missing.key', {}, 'Fallback') // 'Fallback'
```

Ключ, указывающий на вложенный объект, возвращает этот объект, а не строку. В шаблоне он отображается как `[object Object]`; используйте конечный ключ.

### `$ts` {#$ts}

```ts
TranslationFn<string>
```

Как `$t`, но всегда возвращает строку: значение проходит через `toString()`, поэтому вложенный
объект превращается в `'[object Object]'`. Указывайте конечный ключ.

### `$_t` {#$_t}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<CleanTranslation>
```

Привязывает `$t` к конкретному маршруту, чтобы переводить вне текущей страницы — например,
в макете, который выводит ссылку на другой маршрут.

```ts
const route = useRoute()
const t = useNuxtApp().$_t(route)
t('page.title')
```

### `$_ts` {#$_ts}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<string>
```

Привязывает `$ts` к конкретному маршруту. См. `$_t`.

### `$tc` {#$tc}

```ts
(key: TranslationKey, params: number | Params, defaultValue?: string) => string
```

Перевод с учётом множественного числа. `params` может быть самим числом или объектом,
содержащим `count`.

Формы разделяются символом `|`. Со встроенным правилом неотрицательное целое число `n` выбирает форму `n`, но не дальше последней формы; отрицательное, дробное число или `NaN` выбирает последнюю форму. `{count}` и остальные параметры подставляются в выбранную форму.

Для языков, где множественное число не следует напрямую за числом, начните шаблон с `=0 `. Тогда первая форма предназначена для 0, а остальные выбираются по категории [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) в порядке `zero, one, two, few, many, other`:

```json
{
  "apples": "=0 no apples | one apple | {count} apples",
  "files": "=0 no files | {count} one | {count} few | {count} many"
}
```

```ts
$tc('apples', 0) // 'no apples'
$tc('apples', 1) // 'one apple'
$tc('apples', 7) // '7 apples'

// In `uk` (categories `one, few, many, other`) the forms after the zero form follow those categories:
$tc('files', 21) // '21 one'
$tc('files', 22) // '22 few'
$tc('files', 25) // '25 many'
$tc('files', 2.5) // '2.5 many': no form for `other`, so the last one
```

- `=0 ` учитывается только в самом начале значения и вместе с пробелом. `$t` показывает его как текст: маркер относится к множественному числу.
- Категория без собственной формы получает последнюю форму. Отрицательное или дробное число тоже получает последнюю форму.
- Это работает в любой локали: `=0 none | one | {count} many` в английском.
- Категория определяется по `iso` локали, иначе по её коду. Код, неизвестный `Intl`, откатывается к правилу по индексу, при этом маркер всё равно удаляется, так что результат никогда не зависит от машины.
- `<i18n-t :plural>` следует тому же правилу. Пользовательские [`plural`](/ru/api/module-options#plural) или `customPluralRule` получают исходное значение вместе с маркером и решают сами; если `plural` возвращает `null`, вызов передаётся встроенному правилу, которое учитывает маркер.

Без маркера шаблон использует правило по индексу, за одним исключением, которое читается однозначно: нулевая форма без плейсхолдера, затем по одной форме на категорию, с `{count}` в каждой форме, общей для нескольких чисел (`no files | {count} one | {count} few | {count} many` в `uk`).

Для собственных правил задайте [`plural`](/ru/api/module-options#plural).

```ts
// { "apples": "no apples | one apple | {count} apples" }
$tc('apples', 0) // 'no apples'
$tc('apples', 10) // '10 apples'
$tc('cart', { count: 2, name: 'Ada' }) // count and params in one object
```

Третий аргумент — это `defaultValue`, а не параметры.

### `$has` {#$has}

```ts
(key: string) => boolean
```

Разрешается ли ключ в активной локали. Используйте его для ветвления по необязательному тексту вместо
вывода необработанного ключа. Как и `$t`, он также видит ключи покидаемой страницы во время перехода
между страницами в той же локали.

```ts
if ($has('promo.banner')) show.value = true
```

## Форматирование {#formatting}

### `$tn` {#$tn}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

Форматирует число с помощью `Intl.NumberFormat` в активной локали. Ключ выбирает именованный формат
из конфигурации.

Именованные форматы берутся из [`numberFormats`](/ru/api/module-options#numberformats).

```ts
$tn(1234.5, { style: 'currency', currency: 'EUR' }) // '1.234,50 €' in de
$tn(1000, 'currency') // named format
$tn(1000, 'currency', 'de') // named format in another locale
```

### `$td` {#$td}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

Форматирует дату с помощью `Intl.DateTimeFormat` в активной локали. Ключ выбирает именованный формат
из конфигурации.

Именованные форматы берутся из [`datetimeFormats`](/ru/api/module-options#datetimeformats).

```ts
$td(new Date(), { dateStyle: 'long' })
$td(post.createdAt, 'short')
```

### `$tdr` {#$tdr}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

Форматирует дату как относительное время («3 дня назад») с помощью `Intl.RelativeTimeFormat`.

```ts
$tdr(Date.now() - 5 * 60_000) // '5 minutes ago' in en
```

## Переключение и ссылки {#switching-and-links}

### `$switchLocale` {#$switchlocale}

```ts
(locale: string) => Promise<boolean>
```

Переходит на текущую страницу в другой локали. В режиме `no_prefix` и в hash-режиме он загружает
переводы локали перед переходом; в режиме `no_prefix` маршрут заменяется на месте (без
новой записи в истории). Неизвестная локаль игнорируется.
Вызов асинхронный: используйте `await`, чтобы выполнить код после перехода. Он возвращает `true`, когда
словарь локали активен, и `false`, когда нет: чанк не загрузился (текущий
словарь сохраняется; вызовите снова, чтобы повторить попытку) или победило более новое переключение.

```ts
await $switchLocale('de')
```

### `$switchLocalePath` {#$switchlocalepath}

```ts
(locale: string) => string
```

Путь текущей страницы в другой локали, без перехода.

```vue
<NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
```

### `$switchLocaleRoute` {#$switchlocaleroute}

```ts
(locale: string) => RouteLocationRaw
```

Объект маршрута текущей страницы в другой локали, без перехода, или строка URL
для локали с собственным `baseUrl`. При `trailingSlash` объект содержит `path` и `fullPath`,
построенные по этому правилу, а `query` и `hash` остаются как есть, и `router.push` или ссылка их сохраняют.

### `$switchRoute` {#$switchroute}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => Promise<void>
```

Переходит на другой маршрут, сохраняя активную локаль или переключаясь на `toLocale`. Асинхронный, как
`$switchLocale`.

```ts
$switchRoute('/about') // active locale
$switchRoute({ name: 'about' }, 'de') // switch to de
```

### `$localePath` {#$localepath}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => string
```

Разрешает путь в указанной локали или в активной. Строка со схемой `http(s):`, `mailto:`
или `tel:` возвращается как есть: не передавайте пользовательский ввод в качестве цели ссылки без проверки.

Строковый путь трактуется как страница, которую он показывает, поэтому пользовательский путь локали тоже применяется.

```ts
$localePath('/about') // '/about' in en, '/de/ueber-uns' in de with localeRoutes
$localePath({ name: 'about' }, 'fr') // '/fr/about'
```

### `$localeRoute` {#$localeroute}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => RouteLocationResolved
```

Разрешает маршрут в указанной локали или в активной. Это обычный объект, который безопасно хранить в состоянии. Если параметр требует
экранирования, объект содержит `path`, `fullPath`, `query` и `hash`, но не `name` или `params`: именно путь передаёт маршрутизатору
закодированный URL. Для локали на другом домене `path` и `fullPath` абсолютные, а маршрутизатор их не принимает:
такая ссылка идёт через `<i18n-link>` или `$localePath`.

### `$getRouteName` {#$getroutename}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric, locale?: string) => string
```

Имя маршрута без префикса локали — имя, по которому сгруппированы переводы.

```ts
$getRouteName() // 'about' on /de/about
```

## Конфигурация страницы {#page-config}

### `$defineI18nRoute` {#$definei18nroute}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

Регистрирует конфигурацию локалей и переводы страницы изнутри компонента.
Объединяет их с активной локалью и применяет заново при смене локали.

Вызывайте его в `<script setup>` страницы, всегда деструктурируя из `useNuxtApp()`. Сборка читает из вызова `locales`, `localeRoutes` и `disableMeta`; во время выполнения важен только `locales` (встроенные переводы объединяются для активной локали). Полные правила: [Конфигурация страницы](/ru/guide/per-component-translations).

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: { en: '/about', de: '/ueber-uns' },
})
</script>
```

### `$setI18nRouteParams` {#$seti18nrouteparams}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

Задаёт параметры текущего маршрута для каждой локали, чтобы динамический сегмент мог различаться в разных языках.
Вызывайте его во время SSR, до рендеринга head.

Параметры очищаются, когда фиксируется переход на другой путь, в том числе с `/news/1` на `/news/4`, где имя маршрута сохраняется. Подробности: [Локализованные пути](/ru/guide/custom-locale-routes).

```ts
$setI18nRouteParams({
  en: { slug: 'my-post' },
  de: { slug: 'mein-beitrag' },
})
```

## Переводы во время выполнения {#runtime-translations}

### `$mergeTranslations` {#$mergetranslations}

```ts
(newTranslations: Translations) => void
```

Объединяет переводы с активной локалью во время выполнения, перекрывая загруженные.

Выполняет глубокое слияние с чанком текущей страницы активной локали; ключи, которые не упомянуты, сохраняются.

```ts
$mergeTranslations({ banner: { title: 'Sale' } })
```

### `$setTranslation` {#$settranslation}

```ts
(key: string, value: unknown) => void
```

Заменяет значение по ключу `key` в активном словаре. Это замена, а не слияние —
используйте `$mergeTranslations`, если соседние ключи должны сохраниться.

```ts
$setTranslation('banner', { title: 'Sale' }) // drops other keys under banner
$setTranslation('banner.title', 'Sale') // dotted path
```

### `$loadPageTranslations` {#$loadpagetranslations}

```ts
(locale: string, routeName: string, translations: Translations) => Promise<void>
```

Загружает переводы для страницы во время выполнения — для контента, ключи которого неизвестны на этапе сборки.

Объединяет их с чанком `(locale, routeName)` в памяти, и экран обновляется, когда этот чанк активен. Payload здесь не запрашивается: для ещё не загруженной страницы переводы ждут, а когда её файл загрузится, они остаются поверх него.

```ts
await $loadPageTranslations('en', 'about', { title: 'About us' })
```

### `$resolveTranslations` {#$resolvetranslations}

```ts
() => Translations
```

Все переводы, которые сейчас находятся в памяти для активной локали и маршрута, в виде дерева.
Представление только для чтения того, что `$t()` может разрешить прямо сейчас.

Считайте результат доступным только для чтения.

### `$setMissingHandler` {#$setmissinghandler}

```ts
(handler: MissingHandler | null) => void
```

Устанавливает колбэк, вызываемый для каждого неразрешённого ключа. Передайте `null`, чтобы удалить его.

Обработчик выполняется вместо предупреждения в режиме разработки.

```ts
$setMissingHandler((locale, key, routeName) => {
  console.error(`[i18n] missing ${key} in ${locale} (${routeName})`)
})
```

### `$clearCache` {#$clearcache}

```ts
() => void
```

Сбрасывает все закэшированные чанки переводов и перезагружает словарь текущей страницы. Страница
продолжает показывать текущие переводы, пока не придут новые. HMR в режиме разработки вызывает его при
каждом изменении файла переводов.

```ts
const { clearCache } = useI18n()
clearCache()
```

Неудачная перезагрузка сохраняет текущий словарь.
