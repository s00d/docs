# Справочник опций модуля

Все опции, которые принимает `nuxt-i18n-micro`, читаются на этапе сборки из интерфейса `ModuleOptions` в
[`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).
Ничего здесь не пишется вручную, поэтому справочник не может отстать от кода: типы, значения по умолчанию и описания берутся непосредственно из объявления.

О том, что эти опции *значат* вместе: какие комбинации имеют смысл, что меняется при смене стратегии, и разобранные примеры — читайте в [Конфигурации](/guides/configuration). Эта страница — исчерпывающий перечень, а та — объяснение.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Вложенные опции указываются под их точечным путём, поэтому `translationPayloads.mode` — это ключ `mode` внутри объекта `translationPayloads`.

## Локали и роутинг

Какие языки существуют и как они появляются в URL.

| Опция | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Список поддерживаемых локалей. Каждая запись задаёт код локали и опциональные метаданные (ISO, направление, отображаемое имя и т. д.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Стратегия роутинга для префиксов локалей. - `'no_prefix'` — локаль не в URL; хранится в cookie. - `'prefix_except_default'` — префикс у всех локалей, кроме локали по умолчанию. - `'prefix'` — префикс всегда, включая локаль по умолчанию. - `'prefix_and_default'` — как `prefix`, но локаль по умолчанию доступна и без префикса. |
| `defaultLocale` | `string` | `'en'` | Локаль, используемая, когда её нельзя определить по URL или предпочтениям пользователя. Также используется как fallback для отсутствующих переводов, если не задан `fallbackLocale`. |
| `localeCookie` | `string \| null` | `null` | Имя cookie, где сохраняется предпочтение локали между сессиями. `null` отключает cookie-хранение. Автоматически становится `'user-locale'` для стратегии `no_prefix`, если не задано. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Конфигурация локалей на уровне маршрутов. Позволяет ограничивать или настраивать маршруты локалей для отдельных страниц без правки их компонентов. - `false` — исключить маршрут из локализации. - `Record<LocaleCode, string>` — свои пути по локалям. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (используется встроенный паттерн на основе кодов локалей)` | Пользовательское регулярное выражение (или его строковое представление) для сопоставления кодов локалей в сегментах URL. Все коды локалей из `locales` должны совпадать с этим паттерном, иначе выводится предупреждение. |
| `noPrefixRedirect` | `boolean` | `false` | Для стратегии `no_prefix`: включить редирект с URL с префиксом локали (например, `/en/about`) на версию без префикса (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | URL-паттерны (строки или RegExp), которые полностью исключаются из обработки i18n. Совпадающие маршруты не получают префиксов локалей, редиректов и загрузки переводов. Внутренние пути Nuxt (`/__nuxt_error` и т. п.) всегда исключаются автоматически. |
| `routeLocales` | `Record<string, string[]>` | — | Ограничения локалей по маршрутам, извлекаемые из вызовов `defineI18nRoute()`. Сопоставляет путь маршрута (например, `'/about'`) массиву разрешённых кодов локалей. Маршруты, которых нет в списке, не имеют ограничений (разрешены все локали). |

## Переводы

Где живут файлы переводов и как разрешаются ключи.

| Опция | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Путь к каталогу с JSON-файлами переводов относительно корня проекта. |
| `disableWatcher` | `boolean` | `false` | Отключить file watcher, который автоматически создаёт недостающие файлы переводов в режиме разработки. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Сопоставление имён маршрутов другим именам, чтобы они использовали одни и те же файлы переводов. Например, `\{ 'about-us': 'about' \}` означает, что страница `about-us` будет использовать переводы страницы `about`, а не свои. |
| `plural` | `PluralFunc` | `встроенная плюрализация (индекс формы по count)` | Пользовательская функция плюрализации. Получает `(key, count, params, locale, getter)` и должна вернуть выбранную форму множественного числа как строку, либо `null`/`undefined`, чтобы откатиться на встроенную логику `defaultPlural` (можно переопределять только некоторые локали). Для модуля Nuxt функция сериализуется через `.toString()` в `.nuxt/i18n.plural.mjs` — она должна быть самодостаточной (без импортов и внешней области видимости). Строка с путём к файлу **не** поддерживается. |
| `disablePageLocales` | `boolean` | `false` | Отключить постраничные файлы переводов. При `true` загружаются только глобальные переводы (`\{locale\}.json`); постраничные файлы (`pages/\{page\}/\{locale\}.json`) не создаются и не загружаются. |
| `fallbackLocale` | `string` | `undefined (нет fallback; возвращается сырой ключ)` | Глобальный код fallback-локали. Когда ключ отсутствует в активной локали, модуль ищет его в этой локали, прежде чем вернуть сам ключ. |

## Payload'ы и кэширование

Как переводы доходят до браузера. Раздел [Производительность](/guides/performance) объясняет, что эти опции меняют в рантайме.

| Опция | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Предзагрузка переводов индексной страницы в глобальном middleware Nitro (только на сервере, приватная конфигурация). |
| `apiBaseUrl` | `string` | `'_locales'` | Сегмент базового URL для API-маршрута переводов (используется при SSR/SSG). Также задаётся переменной окружения `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Переопределяет хост, используемый клиентом при запросах переводов. Полезно, когда клиент обращается к серверу по хосту, отличному от того, что видит Nuxt. Также задаётся переменной `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Переопределяет хост, используемый сервером при запросах переводов. Полезно в контейнерных/микросервисных сетах, где сервер обращается к себе по внутреннему хосту. Также задаётся переменной `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Управляет тем, как эмитятся payload'ы переводов (Node: `public/<apiBaseUrl>`; Edge: Nitro `serverAssets`). - **Node**: `serverAssets` означает локальный SSR через `readFile` из `public/` (без Rollup `raw:`). - **Edge**: `serverAssets` регистрирует Nitro `serverAssets` (`assets:i18n`); не форсит копию в public. Для типовой сборки «всё в одном» оставляйте значения по умолчанию. Для больших каталогов на Edge предпочтительно `mode: 'source'`. Для деплоев с CDN отключите локальные выходы и задайте `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Стратегия payload'ов переводов. - `premerged`: build-time матрица `\{page\}/\{locale\}/data.json` (по умолчанию). - `source`: компактные исходники, объединяемые в рантайме (предпочтительно для Edge / больших каталогов). |
| `translationPayloads.serverAssets` | `boolean` | `true` | Локальные SSR payload'ы: Node читает `public/<apiBaseUrl>` (форсит копию в public); Edge встраивает их через Nitro `serverAssets`. - **Node**: нет Nitro `serverAssets` (избегаем Rollup `raw:`). SSR читает `public/<apiBaseUrl\|publicDir>` как `\{page\}/\{locale\}/data.json`; при `true` копия в public форсится, даже если `publicAssets` равен false. - **Edge** (`nitro.node === false`): Nitro `serverAssets` (`assets:i18n`) с той же раскладкой, что и `mode`. **Не** форсит копию в public — задайте `publicAssets: true` для CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Регистрирует встроенный серверный маршрут `/\{apiBaseUrl\}/:page/:locale/data.json`. Отключите, если payload'ы отдаются с внешнего хоста/CDN. |
| `translationPayloads.publicAssets` | `boolean` | `true в режиме premerged, false в режиме source` | Копировать payload'ы в public-выход Nitro. Premerged → `\{page\}/\{locale\}/data.json` под `apiBaseUrl`; source → компактное дерево. На Node это дерево также является источником SSR, когда `serverAssets` форсит копию в public. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Явно включить пререндер `/\{apiBaseUrl\}/.../data.json` в Nitro. Обычно избыточно, когда premerged `publicAssets` уже записал эти файлы. |
| `translationPayloads.publicDir` | `string` | — | Папка public-выхода относительно public-корня Nitro. По умолчанию равна `apiBaseUrl` (`_locales`), чтобы статические файлы совпадали с URL клиентских запросов (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Выводить предупреждение при сборке, если число сгенерированных файлов payload'ов превышает этот порог. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Выводить предупреждение при сборке, если суммарный размер payload'ов превышает этот порог в байтах. |

## SEO

Мета-теги, генерируемые для каждой локализованной страницы.

| Опция | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Автоматически генерировать SEO-мета-теги (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | Базовый URL для SEO-мета-тегов (canonical, og:url, hreflang). - Конкретная строка URL (например, `'https://example.com'`) — используется как есть (высший приоритет). - `undefined` — откат на `site.url` из `nuxt-site-config`, если модуль присутствует, иначе origin текущего запроса (`useRequestURL().origin` на сервере, `window.location.origin` на клиенте). |
| `metaTrustForwardedHost` | `boolean` | `true` | Доверять заголовку `X-Forwarded-Host` при определении базового URL для мета-тегов. Включайте, когда приложение работает за reverse proxy (nginx, Cloudflare, AWS ALB и т. п.), который выставляет этот заголовок в реальный клиентский хост. |
| `metaTrustForwardedProto` | `boolean` | `true` | Доверять заголовку `X-Forwarded-Proto` при определении протокола для мета-тегов. Включайте, когда приложение работает за прокси с терминацией TLS, чтобы canonical URL использовали `https://`, хотя само приложение слушает по HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Список имён query-параметров, сохраняемых в canonical и `og:url`. Параметры не из этого списка отбрасываются из canonical URL. |

## Определение локали и редиректы

Выбор локали для посетителя, который её ещё не выбрал.

| Опция | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Включить автоматические редиректы по локали. При `true` посетителей перенаправляют на их предпочтительную локаль (определённую по cookie, `Accept-Language` или по умолчанию) при первом заходе. |
| `autoDetectLanguage` | `boolean` | `true` | Автоматически определять предпочтительный язык пользователя из HTTP-заголовка `Accept-Language`. Используется в связке с `autoDetectPath`, чтобы решить, когда происходит определение. |
| `autoDetectPath` | `string` | `'/'` | Где могут срабатывать редиректы по cookie/Accept-Language (при включённых `redirects`). - `'/'` — только `/` (глубокие ссылки в локали по умолчанию остаются доступны; значение по умолчанию). - `'no_prefix'` — только пути без префикса локали. - `'*'` — любой путь, включая переписывание явного префикса локали (например, `/fr/about` → `/de/about`, когда cookie предпочитает `de`). - любая другая строка — точное совпадение пути (например, `'/welcome'`). Очистка при префиксных стратегиях (например, `/en` → `/` при `prefix_except_default`) не ограничивается. |
