На этой странице перечислены все ключи объекта `i18n` в `nuxt.config`. Используйте таблицы, чтобы найти тип или значение по умолчанию, а подробности ниже — для примеров и оговорок. Типы, значения по умолчанию и описания сгенерированы из интерфейса `ModuleOptions` в [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).

```ts nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
    ],
    defaultLocale: 'en',
  },
})
```

Вложенная опция указывается по пути через точку: `translationPayloads.mode` — это ключ `mode` в `translationPayloads`.

## Локали и маршрутизация {#locales-and-routing}

Какие языки существуют и как они отображаются в URL.

| Опция | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Список поддерживаемых локалей. Каждая запись задаёт код локали и необязательные метаданные (ISO, направление, отображаемое имя и т. д.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Стратегия маршрутизации URL для префиксов локалей. - `'no_prefix'` — локали нет в URL; локаль хранится в cookie. - `'prefix_except_default'` — префикс у всех локалей, кроме локали по умолчанию. - `'prefix'` — префикс всегда, включая локаль по умолчанию. - `'prefix_and_default'` — как `prefix`, но локаль по умолчанию доступна также без префикса. |
| `defaultLocale` | `string` | `'en'` | Локаль, используемая, когда её нельзя определить по URL или предпочтениям пользователя. Это не резервная локаль для переводов: для этого задайте `fallbackLocale`. |
| `localeCookie` | `string \| null` | `null` | Имя cookie для сохранения предпочитаемой пользователем локали между сессиями. Задайте `null`, чтобы отключить сохранение в cookie. Если не задано, для стратегии `no_prefix` автоматически устанавливается в `'user-locale'`; явный `null` в блоке конфигурации `i18n` отключает его и там. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `{}` | Глобальная конфигурация локалей на уровне маршрутов. Позволяет ограничивать или настраивать локализованные маршруты для отдельных страниц без изменения их компонентов. - `false` — исключить маршрут из локализации. - `Record<LocaleCode, string>` — собственные пути для каждой локали. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Собственное регулярное выражение (или его строковый исходник) для сопоставления кодов локалей в сегментах URL. Каждый код локали в `locales` должен целиком соответствовать шаблону без учёта флагов, иначе сборка завершится ошибкой. |
| `noPrefixRedirect` | `boolean` | `false` | Для стратегии `no_prefix`: если у локали по умолчанию есть собственный путь для страницы (`localeRoutes` / `globalLocaleRoutes`), перенаправлять с исходного пути страницы на собственный путь локали посетителя, а иначе — локали по умолчанию (например, `/about` → `/about-us`). Локаль без собственного пути остаётся на исходном пути. Страницы с динамическими сегментами не перенаправляются. |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Пути, исключаемые из i18n-маршрутизации: строка — это префикс пути (`/admin` охватывает `/admin/x`) или glob с `*` / `?`; RegExp проверяется на соответствие пути. Подходящие страницы не получают вариантов для локалей, перенаправлений по локали или 404 и исключаются из пререндеринга; при этом они по-прежнему отображаются с переводами. `/api`, `/_nuxt`, `/__*`, маршрут переводов и распространённые статические файлы (sitemap, robots.txt, favicon, ресурсы по расширению) исключаются всегда. |
| `routeLocales` | `Record<string, string[]>` | — | Ограничения локалей для отдельных маршрутов, извлекаемые на этапе сборки из вызовов `$defineI18nRoute()`. Сопоставляет путь маршрута (например, `'/about'`) с массивом разрешённых кодов локалей. Маршруты, которых нет в списке, не ограничены (разрешены все локали). |

## Переводы {#translations}

Где лежат файлы переводов и как разрешаются ключи.

| Опция | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Путь к директории с JSON-файлами переводов относительно корня проекта. |
| `disableWatcher` | `boolean` | `false` | Отключить наблюдатель файлов, который в режиме разработки автоматически создаёт отсутствующие файлы переводов. |
| `routesLocaleLinks` | `{ [key: string]: string }` | `{}` | Сопоставляет имена маршрутов с другими именами маршрутов, чтобы они использовали одни и те же файлы переводов. Например, `{ 'about-us': 'about' }` означает, что страница `about-us` будет использовать переводы страницы `about` вместо собственных. |
| `plural` | `PluralFunc` | ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)`` | Собственная функция плюрализации. Получает `(key, count, params, locale, getter)` и должна вернуть выбранную форму множественного числа в виде строки либо `null`/`undefined`, чтобы перейти к встроенной логике `defaultPlural` (так можно переопределить только некоторые локали). Для модуля Nuxt функция сериализуется через `.toString()` в `.nuxt/i18n.plural.mjs` — она должна быть самодостаточной (без импортов и внешней области видимости). Строка с путём к файлу **не** поддерживается. |
| `disablePageLocales` | `boolean` | `false` | Отключить файлы переводов для отдельных страниц. При `true` загружаются только глобальные переводы (`{locale}.json`); файлы для страниц (`pages/{page}/{locale}.json`) не генерируются и не загружаются. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Код глобальной резервной локали. Ключи, отсутствующие в локали, берутся из этой локали (подмешиваются в каждый payload при его сборке или загрузке); без неё отсутствующий ключ отображается как сам ключ. |

## Payload и кэширование {#payloads-and-caching}

Как переводы попадают в браузер. Что эти опции меняют во время выполнения, объясняется в разделе [Производительность](/ru/guide/performance).

| Опция | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Предзагружать переводы главной страницы в глобальном middleware Nitro (только сервер, приватная конфигурация). |
| `apiBaseUrl` | `string` | `'_locales'` | Базовый сегмент пути URL для API-маршрута переводов (используется при загрузке данных в SSR/SSG). Также можно задать через переменную окружения `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Переопределить хост для клиентских запросов переводов. Полезно, когда клиент обращается к серверу по другому имени хоста, чем то, которое видит Nuxt. Также можно задать через переменную окружения `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Переопределить хост для серверных запросов переводов. Полезно в контейнерных/микросервисных конфигурациях, где сервер обращается к самому себе по внутреннему имени хоста. Также можно задать через переменную окружения `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Управляет тем, как выпускаются payload переводов (сервер Node: `public/<apiBaseUrl>`; Edge / функции / inline: Nitro `serverAssets`). - **Сервер Node** (`node-server`, `node-cluster`, дисковый `serveStatic`): `serverAssets` означает локальный SSR через `readFile` в `public/` (без Rollup `raw:`). - **Edge, пресеты функций и `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …): `serverAssets` регистрирует Nitro `serverAssets` (`assets:i18n`),   поскольку `public/` недоступна для SSR на диске. Публичная копия принудительно не создаётся — задайте `publicAssets: true` для CDN/статики. Для обычной конфигурации «всё в одном» оставьте значения по умолчанию. Для больших каталогов на Edge лучше `mode: 'source'`. Для деплоев с CDN отключите локальный вывод и задайте `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Стратегия payload переводов. - `premerged`: матрица `{page}/{locale}/data.json`, собираемая на этапе сборки (по умолчанию) - `source`: компактные исходные файлы, объединяемые во время выполнения (предпочтительно для Edge / больших каталогов) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Локальные payload для SSR: сервер Node, отдающий `public/` с диска, читает это дерево (принудительно создаётся публичная копия); Edge, пресеты функций и `serveStatic: "inline"` встраивают данные через Nitro `serverAssets`. - **Сервер Node** (пресет сам отдаёт `public/`, например `node-server`): без Nitro `serverAssets` (избегает Rollup `raw:`). SSR читает   `public/<apiBaseUrl\|publicDir>` в виде `{page}/{locale}/data.json`; при значении `true`   публичная копия создаётся принудительно, даже если `publicAssets` равен false. - **Edge, пресеты функций и inline** (`nitro.node === false`, без дискового `serveStatic`, как у `vercel` /   `netlify` / `aws-lambda`, или `serveStatic: "inline"`, например winterjs): Nitro `serverAssets` (`assets:i18n`)   с той же структурой, что и `mode`. Публичная копия **не** создаётся принудительно — задайте `publicAssets: true` для CDN/статики. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Регистрировать встроенный серверный маршрут `/{apiBaseUrl}/:page/:locale/data.json`. Отключите, если payload переводов отдаются с внешнего хоста/CDN. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Копировать payload в публичный вывод Nitro. Premerged → `{page}/{locale}/data.json` в `apiBaseUrl`; source → компактное дерево. Когда SSR читает `public/` (`node-server` и подобные), `serverAssets: true` также принудительно создаёт эту копию. На пресетах Edge / функций / `serveStatic: "inline"` копирование происходит, только если значение `true` (SSR использует встраивание в Nitro). |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Включить пререндеринг `/{apiBaseUrl}/.../data.json` через Nitro. Обычно избыточно, если premerged `publicAssets` уже записал эти файлы. |
| `translationPayloads.publicDir` | `string` | — | Папка публичного вывода относительно публичного корня Nitro. По умолчанию `apiBaseUrl` (`_locales`), чтобы статические файлы совпадали с URL клиентских запросов (`/{apiBaseUrl}/{page}/{locale}/data.json`). |
| `translationPayloads.rootDelta` | `boolean` | `true` | Записывать один корневой файл на локаль, а в каждый файл страницы — только отличия от него. Клиент и SSR объединяют их; целый чанк по-прежнему работает везде, где читается файл. `false` сохраняет полный словарь в каждом файле страницы. Только для `premerged`; отключено при `disablePageLocales`. |
| `translationPayloads.warnFileCount` | `number` | `500` | Предупреждать во время сборки, если количество сгенерированных файлов payload превышает этот порог. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Предупреждать во время сборки, если общий размер сгенерированных payload превышает этот порог в байтах. |

## SEO {#seo}

Meta-теги, генерируемые для каждой локализованной страницы.

| Опция | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Автоматически генерировать SEO meta-теги (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | Базовый URL для SEO meta-тегов (canonical, og:url, hreflang). - Конкретная строка URL (например, `'https://example.com'`) — используется как есть (наивысший приоритет). - `undefined` — используется `site.url` из `nuxt-site-config`, если этот модуль   установлен, иначе origin текущего запроса   (`useRequestURL().origin` на сервере, `window.location.origin` на клиенте). |
| `metaTrustForwardedHost` | `boolean` | `true` | Доверять заголовку `X-Forwarded-Host` при определении базового URL для meta-тегов. Включайте, когда приложение работает за обратным прокси (nginx, Cloudflare, AWS ALB и т. д.), который устанавливает в этот заголовок реальное имя хоста, видимое клиенту. |
| `metaTrustForwardedProto` | `boolean` | `true` | Доверять заголовку `X-Forwarded-Proto` при определении протокола для meta-тегов. Включайте, когда приложение работает за прокси, завершающим TLS, чтобы canonical-URL использовали `https://`, даже если само приложение слушает HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Список имён query-параметров, сохраняемых в meta-тегах canonical и `og:url`. Параметры не из этого списка удаляются из canonical-URL. |

## Определение локали и перенаправления {#detection-and-redirects}

Выбор локали для посетителя, который её ещё не выбрал.

| Опция | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Включить автоматические перенаправления по локали (серверный плагин и клиентский route middleware). При `true` стратегии с префиксами перенаправляют URL без префикса на его локализованную форму. Локаль берётся из состояния приложения, cookie или `Accept-Language`, где это разрешает `autoDetectPath`, а иначе используется локаль по умолчанию. При `no_prefix` определение локали никогда не меняет URL (см. `noPrefixRedirect` для собственных путей). |
| `autoDetectLanguage` | `boolean` | `true` | Автоматически определять предпочитаемый язык пользователя по HTTP-заголовку `Accept-Language`. Используется вместе с `autoDetectPath`, чтобы решить, когда выполняется определение. |
| `autoDetectPath` | `string` | `'/'` | Где могут выполняться перенаправления по предпочтению из cookie / Accept-Language (когда включён `redirects`). - `'/'` — только `/` (глубокие ссылки на локаль по умолчанию остаются доступными; по умолчанию) - `'no_prefix'` — только пути без префикса локали - `'*'` — все пути, включая замену явного префикса локали   (например, `/fr/about` → `/de/about`, если cookie предпочитает `de`) - любая другая строка — этот путь без учёта завершающих слэшей (например, `'/welcome'`) При `prefix` URL без префикса вне разрешённых путей всё равно перенаправляется на форму локали по умолчанию (`/about` → `/en/about`). Локаль по умолчанию с префиксом при `prefix_except_default` (`/en`) — это 404, а не перенаправление. |

## Регистрация {#registration}

Части модуля, которые можно отключить.

| Опция | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Предоставлять `$defineI18nRoute()` во время выполнения. Сборка читает вызовы `$defineI18nRoute()` на страницах в любом случае. |
| `plugin` | `boolean` | `true` | Регистрировать основной плагин i18n, который предоставляет `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` и другие runtime-хелперы. |
| `hooks` | `boolean` | `true` | Вызывать хук приложения `i18n:register` при загрузке и при навигации, чтобы плагины могли добавлять переводы. |
| `components` | `boolean` | `true` | Регистрировать встроенные компоненты i18n (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Задайте `false`, чтобы отключить автоматическую регистрацию компонентов (например, если вы их не используете и хотите уменьшить размер модуля). |
| `types` | `boolean` | `true` | Генерировать объявления типов TypeScript для `useI18n`, `$t` и связанных хелперов на основе ключей переводов в файлах локали по умолчанию. |
| `debug` | `boolean` | `false` | Включить подробное отладочное логирование определения локали, генерации маршрутов и загрузки переводов. |

## Прочее {#other}

| Опция | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `trustForwardedHost` | `boolean` | `false` | Выбирать домен запроса (`locales[].baseUrl`) по `X-Forwarded-Host` вместо `Host`. Включайте только за прокси, который перезаписывает этот заголовок. |
| `hreflangBaseLanguage` | `boolean` | `false` | Дополнительно выводить `hreflang` только с языком, полученный из `iso` каждой локали (например, `es-ES` → также `es`). Первая региональная локаль в `locales` занимает такой тег для своего языка. Код маршрутизации `code` никогда не используется — только `iso \|\| code`. |
| `additionalTranslationDirs` | `string[]` | `[]` | Дополнительные директории (относительно корня проекта / корня каждого слоя Nuxt), чьи файлы верхнего уровня `{locale}.json` глубоко объединяются с глобальным словарём перед `translationDir`. Порядок слияния: каждая запись в порядке массива (по всем слоям), затем `translationDir` (побеждает при конфликтах). Читаются только корневые файлы `{locale}.json` — `pages/` в этих директориях игнорируется. Пример: `translationDir: 'frontend'`, `additionalTranslationDirs: ['common']` → `common/en.json`, затем `frontend/en.json`. |
| `vueDevtools` | `boolean` | `true` | Регистрировать инспектор и таймлайн Vue DevTools в режиме разработки (браузерное расширение). Не связано с собственной вкладкой в Nuxt DevTools. |
| `trailingSlash` | `'append' \| 'remove'` | `undefined (inherit from Nuxt)` | Завершающий слэш для `$localePath` / `$switchLocalePath` (как у NuxtLink). Если не задано, по умолчанию берётся `experimental.defaults.nuxtLink.trailingSlash`. Задайте явно, чтобы переопределить значение Nuxt по умолчанию для хелперов путей i18n. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Префикс, добавляемый к именам локализованных маршрутов (например, `'localized-index'`). Используется внутри модуля, чтобы отличать исходные маршруты от сгенерированных вариантов для локалей. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Отключение meta-тегов для отдельных маршрутов. Сопоставляет имя или путь маршрута с `true` (отключить все meta) или массивом кодов локалей, для которых meta нужно отключить. Сюда добавляются записи, найденные в вызовах `$defineI18nRoute()` на этапе сборки. |
| `missingWarn` | `boolean` | `true` | Показывать предупреждения в консоли при отсутствии ключа перевода (dev-сборка, в браузере). |
| `hmr` | `boolean` | `true` | Включить горячую замену модулей (HMR) для файлов переводов в режиме разработки. При `true` изменения в JSON-файлах переводов вызывают автоматическую перезагрузку без полного обновления страницы. |
| `cacheMaxSize` | `number` | `0` | Максимальное число записей в кэшах переводов в памяти. Кэши запросов и сервера вытесняют давно не использовавшуюся запись; карта словарей в браузере вытесняет самую старую (FIFO). `0` означает отсутствие ограничения в браузере; серверные кэши в этом случае хранят не более 1000 записей, чтобы URL запросов с выдуманными страницами не могли раздувать память сервера. |
| `cacheTtl` | `number` | `0` | Время жизни (в секундах) кэшей запросов и серверных кэшей переводов, отсчитываемое с момента сохранения записи (чтения его не продлевают), так что данные из `apiBaseServerHost` обновляются как минимум с этой частотой. Активные словари в браузере по нему не истекают. `0` означает, что записи никогда не истекают. |
| `cacheStorage` | `string` | — | Имя точки монтирования хранилища Nitro (`nitro.storage`, например `'redis'`), которое несколько серверных инстансов используют как общий кэш словарей; читается после кэша в процессе и перед источником. Окупается в основном с `apiBaseServerHost`: один запрос к бэкенду вместо одного на инстанс. Ключи записей содержат сборку и истекают через `cacheTtl` или через один день, если он равен `0`. Отключено в режиме разработки и при пререндеринге. При сбое хранилища используется источник. Не задано: общего кэша нет. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Именованные форматы чисел для каждой локали (совместимо с Vue I18n). Позволяет делать вызовы вида `$tn(1000, 'currency')`. |
| `timeZone` | `string` | `the runtime's zone` | Часовой пояс IANA для `$td` и `<i18n-t date>` (`Europe/Berlin`). Задайте, чтобы одна и та же дата отображалась одинаково на сервере и в каждом браузере; собственный `timeZone` именованного формата имеет приоритет. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Именованные форматы даты и времени для каждой локали (совместимые с Vue I18n `datetimeFormats`). Позволяет делать вызовы вида `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | HTTP `Cache-Control` max-age (в секундах) для `/{apiBaseUrl}/:page/:locale/data.json`. Применяется полностью, только пока `dateBuild` меняет URL (`?v=...`), что происходит по умолчанию: ответ тогда имеет вид `private, max-age=…, immutable`: браузер закрепляет его, а CDN, игнорирующий query, — нет (`public` при `httpCacheControl: false`). - `dateBuild: 0`/`''` — URL стабилен, поэтому эта длительность *не* соблюдается; вместо   этого ответ получает `public, max-age=0, must-revalidate`. Длинный `max-age` на   неизменном URL закрепил бы первый payload, который увидел браузер. - `0` — не устанавливать `Cache-Control` вообще (полезно при локальной отладке) - Не применяется в режиме разработки (`import.meta.dev`), чтобы кэш браузера не мешал HMR - Действует только на ответы, отдаваемые через Nitro. Payload, скопированные в `public/` и отдаваемые   хостинг-платформой, получают заголовки этой платформы — см. руководство по производительности. Аналог экспериментального `httpCacheDuration` из `@nuxtjs/i18n` (v10.2.0), но в виде явного заголовка ответа, а не maxAge из Nitro `defineCachedEventHandler`. |
| `httpCacheControl` | `string \| false` | `'public, max-age=60'` | `Cache-Control` файла payload, отдаваемого хостингом или правилом для всего пути, которые не видят `?v=`. На сервере Node ответ на текущий `?v=` закрепляется на `httpCacheDuration`, а любой другой перепроверяется; при `source`, `cacheTtl` или `apiBaseServerHost`, когда словарь меняется без сборки, каждый ответ получает этот заголовок. `false` оставляет каждый файл на `max-age=0, must-revalidate`. |
| `dateBuild` | `string \| number` | — | Значение для сброса кэша запросов переводов (`?v=...`). Если не задано, модуль использует хеш файлов переводов, поэтому значение меняется только при изменении переводов (`Date.now()`, если хеш вычислить невозможно). `0` или `''` отключает сброс кэша. Задайте стабильное значение (git SHA, номер сборки), чтобы закрепить его самостоятельно. `NUXT_I18N_DATE_BUILD` или `runtimeConfig.public.i18nRuntime.dateBuild` заменяет его во время выполнения после того, как словарь был заменён на месте: закреплённые URL остаются позади без пересборки. |
| `experimental` | `Record<string, unknown>` | — | Набор экспериментальных/нестабильных опций. Содержимое может измениться или быть удалено без предупреждения между минорными версиями. |

## Подробности опций {#option-details}

Опции, о которых нечего добавить сверх таблицы, здесь не повторяются.

### Локали и URL {#locales-and-urls}

#### `locales` {#locales}

**Тип** `Locale[]` · **По умолчанию** `[]`

Список поддерживаемых локалей.
Каждая запись задаёт код локали и необязательные метаданные (ISO, направление, отображаемое имя и т. д.).

Каждая запись — это объект `Locale`:

| Свойство | Тип | Описание |
| --- | --- | --- |
| `code` | `string` | **Обязательно.** Сегмент URL и имя файла (`en`, `de-at`). |
| `iso` | `string` | Тег BCP-47 для `<html lang>`, `hreflang`, форм множественного числа и `$tn` / `$td` / `$tdr` (`en-US`). |
| `displayName` | `string` | Подпись в `<i18n-switcher>` и `$getLocaleName()`. |
| `dir` | `'ltr' \| 'rtl' \| 'auto'` | `<html dir>`. Без него известные RTL-языки получают `rtl`, а все остальные локали — никакого атрибута. См. [SEO](/ru/guide/seo#text-direction). |
| `disabled` | `boolean` | Исключается из маршрутов, payload и переключения. Её префикс — 404, а ссылки на неё остаются на текущей странице. |
| `fallbackLocale` | `string` | Резервная локаль для этой локали; переопределяет глобальный `fallbackLocale`. |
| `seo` | `boolean` | `false` исключает локаль из `hreflang` и `og:locale:alternate`. |
| `og` | `string` | Значение `og:locale` (`ar_AE`); по умолчанию — преобразованный `iso`. |
| `baseUrl` | `string` | Собственный домен локали: его обслуживает одна сборка, а ссылки на него с других доменов абсолютные. |
| `baseDefault` | `boolean` | Вместе с `baseUrl`: локаль по умолчанию для своего хоста, без префикса `/<code>` в ссылках на неё (`prefix` его сохраняет). |

Прочие свойства сохраняются и возвращаются `$getLocales()`. Типизируйте их, расширив `Locale`:

```ts
// i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
  }
}
export {}
```

Модуль поднимает (hoist) `@i18n-micro/types`, поэтому это работает под pnpm без установки пакета.

#### `defaultLocale` {#defaultlocale}

**Тип** `string` · **По умолчанию** `'en'`

Локаль, используемая, когда её нельзя определить по URL или предпочтениям пользователя.
Это не резервная локаль для переводов: для этого задайте `fallbackLocale`.

#### `strategy` {#strategy}

**Тип** `Strategies` · **По умолчанию** `'prefix_except_default'`

Стратегия маршрутизации URL для префиксов локалей.

- `'no_prefix'` — локали нет в URL; локаль хранится в cookie.
- `'prefix_except_default'` — префикс у всех локалей, кроме локали по умолчанию.
- `'prefix'` — префикс всегда, включая локаль по умолчанию.
- `'prefix_and_default'` — как `prefix`, но локаль по умолчанию доступна также без префикса.

URL для каждой стратегии и перенаправления: [Стратегии маршрутизации](/ru/guide/strategy).

#### `globalLocaleRoutes` {#globallocaleroutes}

**Тип** `GlobalLocaleRoutes` · **По умолчанию** `{}`

Глобальная конфигурация локалей на уровне маршрутов.
Позволяет ограничивать или настраивать локализованные маршруты для отдельных страниц без
изменения их компонентов.

- `false` — исключить маршрут из локализации.
- `Record<LocaleCode, string>` — собственные пути для каждой локали.

Ключи — это имена или пути маршрутов. Обычно задаётся для каждой страницы через [`$defineI18nRoute`](/ru/guide/per-component-translations).

```ts
globalLocaleRoutes: {
  about: { en: '/about-us', de: '/ueber-uns' },
  'admin-dashboard': false, // not localized
}
```

Подробности, динамические сегменты и маршруты из `pages:extend`: [Локализованные пути](/ru/guide/custom-locale-routes).

#### `routeLocales` {#routelocales}

**Тип** `Record<string, string[]>` · **По умолчанию** —

Ограничения локалей для отдельных маршрутов, извлекаемые на этапе сборки из вызовов `$defineI18nRoute()`.
Сопоставляет путь маршрута (например, `'/about'`) с массивом разрешённых кодов локалей.
Маршруты, которых нет в списке, не ограничены (разрешены все локали).

#### `routeDisableMeta` {#routedisablemeta}

**Тип** `Record<string, boolean \| string[]>` · **По умолчанию** —

Отключение meta-тегов для отдельных маршрутов. Сопоставляет имя или путь маршрута с `true` (отключить все meta) или массивом
кодов локалей, для которых meta нужно отключить. Сюда добавляются записи, найденные в вызовах `$defineI18nRoute()`
на этапе сборки.

#### `customRegexMatcher` {#customregexmatcher}

**Тип** `string \| RegExp` · **По умолчанию** `undefined (uses built-in pattern based on locale codes)`

Собственное регулярное выражение (или его строковый исходник) для сопоставления кодов локалей в сегментах URL.
Каждый код локали в `locales` должен целиком соответствовать шаблону без учёта флагов, иначе сборка завершится ошибкой.

```ts
customRegexMatcher: '[a-z]{2}-[a-z]{2}', // en-us, de-at
```

#### `excludePatterns` {#excludepatterns}

**Тип** `(string \| RegExp)[]` · **По умолчанию** `undefined`

Пути, исключаемые из i18n-маршрутизации: строка — это префикс пути (`/admin` охватывает `/admin/x`)
или glob с `*` / `?`; RegExp проверяется на соответствие пути. Подходящие страницы не получают вариантов
для локалей, перенаправлений по локали или 404 и исключаются из пререндеринга; при этом они по-прежнему отображаются
с переводами. `/api`, `/_nuxt`, `/__*`, маршрут переводов и распространённые статические файлы
(sitemap, robots.txt, favicon, ресурсы по расширению) исключаются всегда.

```ts
excludePatterns: ['/admin', '/docs/*', /^\/preview\//],
```

Подробнее: [Исключение путей](/ru/guide/excluding-static-files).

#### `localizedRouteNamePrefix` {#localizedroutenameprefix}

**Тип** `string` · **По умолчанию** `'localized-'`

Префикс, добавляемый к именам локализованных маршрутов (например, `'localized-index'`).
Используется внутри модуля, чтобы отличать исходные маршруты от сгенерированных вариантов для локалей.

#### `trailingSlash` {#trailingslash}

**Тип** `'append' \| 'remove'` · **По умолчанию** `undefined (inherit from Nuxt)`

Завершающий слэш для `$localePath` / `$switchLocalePath` (как у NuxtLink).
Если не задано, по умолчанию берётся `experimental.defaults.nuxtLink.trailingSlash`.
Задайте явно, чтобы переопределить значение Nuxt по умолчанию для хелперов путей i18n.

### Переводы {#translations}

#### `translationDir` {#translationdir}

**Тип** `string` · **По умолчанию** `'locales'`

Путь к директории с JSON-файлами переводов относительно корня проекта.

Относительно корня каждого слоя, а не `app/` (`'app/locales'` для структуры Nuxt 4). Структура файлов: [Файлы переводов](/ru/guide/translations).

#### `additionalTranslationDirs` {#additionaltranslationdirs}

**Тип** `string[]` · **По умолчанию** `[]`

Дополнительные директории (относительно корня проекта / корня каждого слоя Nuxt), чьи файлы верхнего уровня
`{locale}.json` глубоко объединяются с глобальным словарём перед `translationDir`.

Порядок слияния: каждая запись в порядке массива (по всем слоям), затем `translationDir` (побеждает при конфликтах).
Читаются только корневые файлы `{locale}.json` — `pages/` в этих директориях игнорируется.

Пример: `translationDir: 'frontend'`, `additionalTranslationDirs: ['common']` → `common/en.json`, затем `frontend/en.json`.

#### `disablePageLocales` {#disablepagelocales}

**Тип** `boolean` · **По умолчанию** `false`

Отключить файлы переводов для отдельных страниц.
При `true` загружаются только глобальные переводы (`{locale}.json`);
файлы для страниц (`pages/{page}/{locale}.json`) не генерируются и не загружаются.

#### `fallbackLocale` {#fallbacklocale}

**Тип** `string` · **По умолчанию** `undefined (no fallback; returns the raw key)`

Код глобальной резервной локали.
Ключи, отсутствующие в локали, берутся из этой локали (подмешиваются в каждый payload при его
сборке или загрузке); без неё отсутствующий ключ отображается как сам ключ.

#### `routesLocaleLinks` {#routeslocalelinks}

**Тип** `{ [key: string]: string }` · **По умолчанию** `{}`

Сопоставляет имена маршрутов с другими именами маршрутов, чтобы они использовали одни и те же файлы переводов.
Например, `{ 'about-us': 'about' }` означает, что страница `about-us` будет использовать
переводы страницы `about` вместо собственных.

```ts
routesLocaleLinks: { 'products-id': 'products' },
```

#### `plural` {#plural}

**Тип** `PluralFunc` · **По умолчанию** ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)``

Собственная функция плюрализации.
Получает `(key, count, params, locale, getter)` и должна вернуть выбранную
форму множественного числа в виде строки либо `null`/`undefined`, чтобы перейти к встроенной
логике `defaultPlural` (так можно переопределить только некоторые локали).

Для модуля Nuxt функция сериализуется через `.toString()` в
`.nuxt/i18n.plural.mjs` — она должна быть самодостаточной (без импортов и внешней области видимости).
Строка с путём к файлу **не** поддерживается.

Встроенное правило и его маркер `=0 ` описаны в разделе [`$tc`](/ru/api/methods#$tc). Ваша функция заменяет его в тех случаях, на которые отвечает, получает сырое значение вместе с маркером, а `null` возвращает вызов встроенному правилу. Функция получает `(key, count, params, locale, getter)`; `getter(key)` возвращает сырую строку со всеми формами. Пишите её как самодостаточное выражение `function` или стрелочную функцию (без сокращённой записи методов, без импортов, без внешних переменных):

```ts
plural: function (key, count, params, locale, getter) {
  if (!locale.startsWith('en')) return null // built-in rule for other locales
  const forms = String(getter(key) ?? '').split('|').map((form) => form.trim())
  const index = count === 0 ? 0 : count === 1 ? 1 : 2
  return (forms[Math.min(index, forms.length - 1)] ?? '').replace('{count}', String(count))
},
```

```json
{ "apples": "no apples | one apple | {count} apples" }
```

#### `numberFormats` {#numberformats}

**Тип** `Record<string, Record<string, Intl.NumberFormatOptions>>` · **По умолчанию** —

Именованные форматы чисел для каждой локали (совместимо с Vue I18n).
Позволяет делать вызовы вида `$tn(1000, 'currency')`.

Используется в [`$tn`](/ru/api/methods#$tn).

#### `datetimeFormats` {#datetimeformats}

Именованные форматы даты и времени для каждой локали (совместимые с Vue I18n `datetimeFormats`).
Позволяет делать вызовы вида `$td(date, 'short')`.

Используется в [`$td`](/ru/api/methods#$td).

#### `timeZone` {#timezone}

**Тип** `string` · **По умолчанию** `the runtime's zone`

Часовой пояс IANA для `$td` и `<i18n-t date>` (`Europe/Berlin`). Задайте, чтобы одна и та же дата отображалась одинаково
на сервере и в каждом браузере; собственный `timeZone` именованного формата имеет приоритет.

#### `disableWatcher` {#disablewatcher}

**Тип** `boolean` · **По умолчанию** `false`

Отключить наблюдатель файлов, который в режиме разработки автоматически создаёт отсутствующие файлы переводов.

#### `missingWarn` {#missingwarn}

**Тип** `boolean` · **По умолчанию** `true`

Показывать предупреждения в консоли при отсутствии ключа перевода (dev-сборка, в браузере).

### Payload и кэширование {#payloads-and-caching}

#### `translationPayloads` {#translationpayloads}

**Тип** `TranslationPayloadOptions` · **По умолчанию** —

Управляет тем, как выпускаются payload переводов (сервер Node: `public/<apiBaseUrl>`; Edge / функции / inline: Nitro `serverAssets`).

- **Сервер Node** (`node-server`, `node-cluster`, дисковый `serveStatic`): `serverAssets` означает локальный SSR через `readFile` в `public/` (без Rollup `raw:`).
- **Edge, пресеты функций и `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …): `serverAssets` регистрирует Nitro `serverAssets` (`assets:i18n`),
  поскольку `public/` недоступна для SSR на диске. Публичная копия принудительно не создаётся — задайте `publicAssets: true` для CDN/статики.

Для обычной конфигурации «всё в одном» оставьте значения по умолчанию. Для больших каталогов на Edge лучше `mode: 'source'`.
Для деплоев с CDN отключите локальный вывод и задайте `apiBaseClientHost` / `apiBaseServerHost`.

Вложенные опции приведены в таблице [Payload и кэширование](#payloads-and-caching). Какое сочетание подходит для Node, serverless, Edge, статического хостинга или CDN: [Деплой](/ru/guide/deployment).

#### `apiBaseUrl` {#apibaseurl}

**Тип** `string` · **По умолчанию** `'_locales'`

Базовый сегмент пути URL для API-маршрута переводов (используется при загрузке данных в SSR/SSG).
Также можно задать через переменную окружения `NUXT_I18N_APP_BASE_URL`.

URL payload имеют вид `/{apiBaseUrl}/{page}/{locale}/data.json`.

#### `apiBaseClientHost` {#apibaseclienthost}

**Тип** `string` · **По умолчанию** `undefined`

Переопределить хост для клиентских запросов переводов.
Полезно, когда клиент обращается к серверу по другому имени хоста, чем то, которое видит Nuxt.
Также можно задать через переменную окружения `NUXT_I18N_APP_BASE_CLIENT_HOST`.

#### `apiBaseServerHost` {#apibaseserverhost}

**Тип** `string` · **По умолчанию** `undefined`

Переопределить хост для серверных запросов переводов.
Полезно в контейнерных/микросервисных конфигурациях, где сервер обращается к самому себе по внутреннему имени хоста.
Также можно задать через переменную окружения `NUXT_I18N_APP_BASE_SERVER_HOST`.

Хост должен отдавать те же ответы `/{apiBaseUrl}/{page}/{locale}/data.json`, что и встроенный маршрут.

#### `dateBuild` {#datebuild}

**Тип** `string \| number` · **По умолчанию** —

Значение для сброса кэша запросов переводов (`?v=...`).

Если не задано, модуль использует хеш файлов переводов, поэтому значение меняется
только при изменении переводов (`Date.now()`, если хеш вычислить невозможно). `0` или `''` отключает
сброс кэша. Задайте стабильное значение (git SHA, номер сборки), чтобы закрепить его самостоятельно.
`NUXT_I18N_DATE_BUILD` или `runtimeConfig.public.i18nRuntime.dateBuild` заменяет его во время выполнения после того, как словарь
был заменён на месте: закреплённые URL остаются позади без пересборки.

#### `httpCacheDuration` {#httpcacheduration}

**Тип** `number` · **По умолчанию** `31536000`

HTTP `Cache-Control` max-age (в секундах) для `/{apiBaseUrl}/:page/:locale/data.json`.

Применяется полностью, только пока `dateBuild` меняет URL (`?v=...`), что происходит по умолчанию:
ответ тогда имеет вид `private, max-age=…, immutable`: браузер закрепляет его, а CDN, игнорирующий query, — нет
(`public` при `httpCacheControl: false`).

- `dateBuild: 0`/`''` — URL стабилен, поэтому эта длительность *не* соблюдается; вместо этого
  ответ получает `public, max-age=0, must-revalidate`. Длинный `max-age` на
  неизменном URL закрепил бы первый payload, который увидел браузер.

- `0` — не устанавливать `Cache-Control` вообще (полезно при локальной отладке)
- Не применяется в режиме разработки (`import.meta.dev`), чтобы кэш браузера не мешал HMR
- Действует только на ответы, отдаваемые через Nitro. Payload, скопированные в `public/` и отдаваемые
  хостинг-платформой, получают заголовки этой платформы — см. руководство по производительности.

Аналог экспериментального `httpCacheDuration` из `@nuxtjs/i18n` (v10.2.0), но в виде
явного заголовка ответа, а не maxAge из Nitro `defineCachedEventHandler`.

#### `cacheMaxSize` {#cachemaxsize}

**Тип** `number` · **По умолчанию** `0`

Максимальное число записей в кэшах переводов в памяти. Кэши запросов и сервера
вытесняют давно не использовавшуюся запись; карта словарей в браузере вытесняет самую старую (FIFO).
`0` означает отсутствие ограничения в браузере; серверные кэши в этом случае хранят не более 1000 записей, чтобы URL
запросов с выдуманными страницами не могли раздувать память сервера.

#### `cacheTtl` {#cachettl}

**Тип** `number` · **По умолчанию** `0`

Время жизни (в секундах) кэшей запросов и серверных кэшей переводов, отсчитываемое с момента
сохранения записи (чтения его не продлевают), так что данные из `apiBaseServerHost` обновляются
как минимум с этой частотой. Активные словари в браузере по нему не истекают. `0` означает, что записи
никогда не истекают.

Что обе опции меняют во время выполнения: [Производительность](/ru/guide/performance).

#### `serverTranslationPreload` {#servertranslationpreload}

**Тип** `boolean` · **По умолчанию** `false`

Предзагружать переводы главной страницы в глобальном middleware Nitro (только сервер, приватная конфигурация).

### SEO {#seo}

#### `meta` {#meta}

**Тип** `boolean` · **По умолчанию** `true`

Автоматически генерировать SEO meta-теги (`hreflang`, `canonical`, `og:url`, `og:locale`).

Постраничные переопределения: [`useI18nHead`](/ru/composables/useI18nHead). Всё остальное: [SEO](/ru/guide/seo).

#### `metaBaseUrl` {#metabaseurl}

**Тип** `string` · **По умолчанию** `undefined`

Базовый URL для SEO meta-тегов (canonical, og:url, hreflang).

- Конкретная строка URL (например, `'https://example.com'`) — используется как есть (наивысший приоритет).
- `undefined` — используется `site.url` из `nuxt-site-config`, если этот модуль
  установлен, иначе origin текущего запроса
  (`useRequestURL().origin` на сервере, `window.location.origin` на клиенте).

#### `metaTrustForwardedHost` {#metatrustforwardedhost}

**Тип** `boolean` · **По умолчанию** `true`

Доверять заголовку `X-Forwarded-Host` при определении базового URL для meta-тегов.
Включайте, когда приложение работает за обратным прокси (nginx, Cloudflare, AWS ALB и т. д.),
который устанавливает в этот заголовок реальное имя хоста, видимое клиенту.

Читается, только если не заданы ни `metaBaseUrl`, ни `site.url`. Задайте `false`, если приложение доступно без прокси, перезаписывающего заголовок: иначе клиент сможет выбирать хост в ваших canonical-URL.

#### `metaTrustForwardedProto` {#metatrustforwardedproto}

**Тип** `boolean` · **По умолчанию** `true`

Доверять заголовку `X-Forwarded-Proto` при определении протокола для meta-тегов.
Включайте, когда приложение работает за прокси, завершающим TLS, чтобы
canonical-URL использовали `https://`, даже если само приложение слушает HTTP.

Та же область действия, что и у `metaTrustForwardedHost`.

#### `trustForwardedHost` {#trustforwardedhost}

**Тип** `boolean` · **По умолчанию** `false`

Выбирать домен запроса (`locales[].baseUrl`) по `X-Forwarded-Host` вместо
`Host`. Включайте только за прокси, который перезаписывает этот заголовок.

Не связано с `metaTrustForwardedHost` и по умолчанию выключено: здесь заголовок выбирал бы локали другого домена, а не только origin тега. См. [Слои и домены](/ru/guide/layers#multiple-domains).

#### `hreflangBaseLanguage` {#hreflangbaselanguage}

**Тип** `boolean` · **По умолчанию** `false`

Дополнительно выводить `hreflang` только с языком, полученный из `iso` каждой локали
(например, `es-ES` → также `es`). Первая региональная локаль в `locales` занимает
такой тег для своего языка. Код маршрутизации `code` никогда не используется — только `iso || code`.

#### `canonicalQueryWhitelist` {#canonicalquerywhitelist}

**Тип** `string[]` · **По умолчанию** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

Список имён query-параметров, сохраняемых в meta-тегах canonical и `og:url`.
Параметры не из этого списка удаляются из canonical-URL.

### Определение локали и перенаправления {#detection-and-redirects}

Правила, которые используют эти опции: [Определение локали](/ru/guide/locale-detection).

#### `redirects` {#redirects}

**Тип** `boolean` · **По умолчанию** `true`

Включить автоматические перенаправления по локали (серверный плагин и клиентский route middleware).
При `true` стратегии с префиксами перенаправляют URL без префикса на его локализованную форму. Локаль
берётся из состояния приложения, cookie или `Accept-Language`, где это разрешает `autoDetectPath`, а иначе
используется локаль по умолчанию. При `no_prefix` определение локали никогда не меняет URL (см. `noPrefixRedirect` для собственных путей).

При `false` клиентский middleware перенаправления не регистрируется. Серверный плагин по-прежнему возвращает 404 для недопустимых URL локалей и записывает cookie для URL с префиксом.

#### `autoDetectLanguage` {#autodetectlanguage}

**Тип** `boolean` · **По умолчанию** `true`

Автоматически определять предпочитаемый язык пользователя по HTTP-заголовку `Accept-Language`.
Используется вместе с `autoDetectPath`, чтобы решить, когда выполняется определение.

#### `autoDetectPath` {#autodetectpath}

**Тип** `string` · **По умолчанию** `'/'`

Где могут выполняться перенаправления по предпочтению из cookie / Accept-Language (когда включён `redirects`).

- `'/'` — только `/` (глубокие ссылки на локаль по умолчанию остаются доступными; по умолчанию)
- `'no_prefix'` — только пути без префикса локали
- `'*'` — все пути, включая замену явного префикса локали
  (например, `/fr/about` → `/de/about`, если cookie предпочитает `de`)

- любая другая строка — этот путь без учёта завершающих слэшей (например, `'/welcome'`)

При `prefix` URL без префикса вне разрешённых путей всё равно перенаправляется на форму локали
по умолчанию (`/about` → `/en/about`). Локаль по умолчанию с префиксом при
`prefix_except_default` (`/en`) — это 404, а не перенаправление.

#### `localeCookie` {#localecookie}

**Тип** `string \| null` · **По умолчанию** `null`

Имя cookie для сохранения предпочитаемой пользователем локали между сессиями.
Задайте `null`, чтобы отключить сохранение в cookie.
Если не задано, для стратегии `no_prefix` автоматически устанавливается в `'user-locale'`; явный
`null` в блоке конфигурации `i18n` отключает его и там.

Без cookie перенаправлениями по-прежнему управляет `Accept-Language`; cookie запоминает выбор между визитами.

#### `noPrefixRedirect` {#noprefixredirect}

**Тип** `boolean` · **По умолчанию** `false`

Для стратегии `no_prefix`: если у локали по умолчанию есть собственный путь для страницы
(`localeRoutes` / `globalLocaleRoutes`), перенаправлять с исходного пути страницы на собственный
путь локали посетителя, а иначе — локали по умолчанию (например, `/about` → `/about-us`).
Локаль без собственного пути остаётся на исходном пути. Страницы с динамическими
сегментами не перенаправляются.

### Регистрация и разработка {#registration-and-development}

#### `plugin` {#plugin}

**Тип** `boolean` · **По умолчанию** `true`

Регистрировать основной плагин i18n, который предоставляет `$t()`, `$tc()`, `$getLocale()`,
`$switchLocale()` и другие runtime-хелперы.

#### `define` {#define}

**Тип** `boolean` · **По умолчанию** `true`

Предоставлять `$defineI18nRoute()` во время выполнения. Сборка читает вызовы `$defineI18nRoute()` на страницах
в любом случае.

#### `hooks` {#hooks}

**Тип** `boolean` · **По умолчанию** `true`

Вызывать хук приложения `i18n:register` при загрузке и при навигации, чтобы плагины могли добавлять переводы.

См. [Хуки](/ru/api/events).

#### `components` {#components}

**Тип** `boolean` · **По умолчанию** `true`

Регистрировать встроенные компоненты i18n (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`).
Задайте `false`, чтобы отключить автоматическую регистрацию компонентов (например, если вы их не используете
и хотите уменьшить размер модуля).

#### `types` {#types}

**Тип** `boolean` · **По умолчанию** `true`

Генерировать объявления типов TypeScript для `useI18n`, `$t` и связанных хелперов
на основе ключей переводов в файлах локали по умолчанию.

Не связано с пакетом [`@i18n-micro/types-generator`](/ru/integrations/types-generator).

#### `hmr` {#hmr}

**Тип** `boolean` · **По умолчанию** `true`

Включить горячую замену модулей (HMR) для файлов переводов в режиме разработки.
При `true` изменения в JSON-файлах переводов вызывают автоматическую перезагрузку
без полного обновления страницы.

#### `debug` {#debug}

**Тип** `boolean` · **По умолчанию** `false`

Включить подробное отладочное логирование определения локали, генерации маршрутов и загрузки переводов.

#### `vueDevtools` {#vuedevtools}

**Тип** `boolean` · **По умолчанию** `true`

Регистрировать инспектор и таймлайн Vue DevTools в режиме разработки (браузерное расширение).
Не связано с собственной вкладкой в Nuxt DevTools.

#### `experimental` {#experimental}

**Тип** `Record<string, unknown>` · **По умолчанию** —

Набор экспериментальных/нестабильных опций.
Содержимое может измениться или быть удалено без предупреждения между минорными версиями.
