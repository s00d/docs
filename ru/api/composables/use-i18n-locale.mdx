# useI18nLocale

## Сигнатура

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getLocaleWithServerFallback: (serverLocale?: string | null) => string | null; getPreferredLocale: () => string | null; hashCookie: any; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: any; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Централизованная точка входа для управления локалью i18n.
Объединяет useState('i18n-locale'), cookie локали и утилиты синхронизации.

## Использование

```vue
<script setup>
const {
  locale,
  localeCookie,
  hashCookie,
  validLocales,
  getPreferredLocale,
  getLocale,
  getLocaleWithServerFallback,
  getEffectiveLocale,
  resolveInitialLocale,
  setLocale,
  syncLocale,
  isValidLocale,
} = useI18nLocale()

// Set locale (updates state and cookies)
setLocale('de')

// Get current locale (state → cookie)
const current = getLocale()

// Get valid preferred locale
const preferred = getPreferredLocale()
</script>
```

## API

| Свойство/Метод                                  | Тип                                 | Описание                                                                           |
| ----------------------------------------------- | ----------------------------------- | ---------------------------------------------------------------------------------- |
| `locale`                                        | `Ref<string \| null>`               | Реактивное состояние локали (`useState('i18n-locale')`)                            |
| `localeCookie`                                  | `Ref`                               | Cookie локали (когда включена опция `localeCookie`)                                |
| `hashCookie`                                    | `Ref`                               | Cookie, используемый при активном `hashMode`                                       |
| `validLocales`                                  | `string[]`                          | Коды включённых локалей из конфигурации модуля (исключая `disabled`)               |
| `getLocale()`                                   | `() => string \| null`              | Текущая локаль: state → cookie (или hash-cookie в hash-режиме)                     |
| `getPreferredLocale()`                          | `() => string \| null`              | Локаль из state/cookie, **проверенная** по `validLocales`, либо `null`             |
| `getLocaleWithServerFallback(serverLocale?)`    | `(serverLocale?) => string \| null` | State → cookie → опциональный серверный контекст (используется при init `no_prefix`) |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string`             | Локаль для загрузки переводов: в hash-режиме предпочитается state, иначе — из маршрута |
| `resolveInitialLocale(options)`                 | `(options) => string`               | Разрешает локаль: state → `serverLocale` → маршрут; синхронизирует state при необходимости |
| `setLocale(locale)`                             | `(locale: string \| null) => void`  | Устанавливает локаль и синхронизирует с cookie                                     |
| `syncLocale(locale)`                            | `(locale: string \| null) => void`  | Синхронизирует только cookie (без обновления state)                                |
| `isValidLocale(locale)`                         | `(locale) => boolean`               | Проверяет, входит ли строка в `validLocales`                                       |

### Опции `resolveInitialLocale`

```typescript
interface ResolveInitialLocaleOptions {
  route: unknown
  serverLocale?: string | null
  getLocaleFromRoute: (route?: unknown) => string
}
```

Используется внутренне основным плагином при запуске. Пользовательские плагины могут вызывать её при реализации альтернативных сценариев определения языка.

### `getEffectiveLocale`

```typescript
const { getEffectiveLocale } = useI18nLocale()
const { $getLocale } = useNuxtApp()

const locale = getEffectiveLocale(route, (r) => $getLocale(r))
```

Возвращает локаль, используемую для загрузки переводов и форматирования сообщений для заданного объекта маршрута.

## Программная установка локали

Предпочитайте `useI18nLocale()` прямому использованию `useState('i18n-locale')`:

```ts
// plugins/i18n-loader.server.ts
import { defineNuxtPlugin } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,

  setup() {
    const { setLocale } = useI18nLocale()
    const detectedLocale = 'ja' // Your detection logic here
    setLocale(detectedLocale)
  },
})
```

<Tip>
`setLocale()` обновляет только предпочтение локали (state + cookie). Чтобы дополнительно перезагрузить активный контекст переводов на клиенте, используйте `$switchLocale()` из `useNuxtApp()` или `useI18n()`. Это особенно важно для `no_prefix`, где URL не меняется. См. [FAQ — сменить локаль без изменения URL](/guides/faq#-switch-locale-without-changing-the-url).
</Tip>
