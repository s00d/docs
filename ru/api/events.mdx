Модуль вызывает один runtime-хук (хук приложения) — `i18n:register`. Используйте его, когда плагин или модуль добавляет переводы, которых нет в ваших файлах `locales/`. Ваш колбэк получает функцию `register`, которая объединяет переводы с отображаемой страницей.

## `i18n:register` {#i18nregister}

```ts
'i18n:register': (
  register: (translations: unknown, locale?: string) => void,
  locale: string,
) => HookResult
```

| Аргумент | Описание |
| --- | --- |
| `register(translations, locale?)` | Глубоко объединяет `translations` с чанком страницы загружаемого маршрута для `locale` (по умолчанию — `locale` хука). Уже существующие ключи перезаписываются. |
| `locale` | Локаль загружаемого маршрута. |

Хук типизирован через `RuntimeNuxtHooks`, поэтому `nuxtApp.hook('i18n:register', …)` не требует приведения типов.

## Когда он срабатывает {#when-it-fires}

Его вызывает плагин-загрузчик (`i18n-plugin-loader`):

1. один раз при запуске, когда все плагины отработали (`app:created`), и до рендеринга приложения;
2. в своём `router.beforeEach`, после загрузки переводов целевой страницы, когда меняется путь — при каждой навигации в режиме `no_prefix`.

Каждый колбэк и каждый вызов `register` ожидаются (await) до рендеринга приложения или продолжения навигации, поэтому страница рендерится уже с объединёнными ключами. При [`hooks: false`](/ru/api/module-options#hooks) хук никогда не вызывается.

## Пример {#example}

```ts
// plugins/i18n-extra.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('i18n:register', async (register, locale) => {
    const extra = await $fetch<Record<string, unknown>>(`/api/cms-strings/${locale}`)
    register(extra, locale)
  })
})
```

Это runtime-хук: регистрируйте его через `nuxtApp.hook` в плагине, а не через `nuxt.hook` в `nuxt.config` или в `setup` модуля. Модуль добавляет такой плагин с помощью `addPlugin`.
