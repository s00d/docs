**Дата**: 2026-05-14

**Версия**: `v3.20.0`

![Выпуск v3.20.0](/images/3.20.0.png)

В этом выпуске среда выполнения Nuxt переработана в отдельный слой **`NuxtI18n`**, обработка редиректов разделена на серверную и клиентскую, а также исправлено несколько регрессий SSR/гидратации. Публичные композаблы и опции `nuxt.config` для типичных приложений остаются прежними.

## Что нового? {#what’s-new}

### `NuxtI18n` и `NuxtTranslationLoader` {#nuxti18n-&-nuxttranslationloader}

Логика i18n во время выполнения вынесена из монолитного плагина в узконаправленные классы:

- **`NuxtI18n`** — слой активного представления переводов (`$t`, `$has`, контекст локали/маршрута, объединение/очистка при переходах)
- **`NuxtTranslationLoader`** — загружает чанки, переключает контекст при навигации, заполняет SSR payload
- **`createNuxtI18nPluginApi`** — тонкая поверхность плагина (`$switchLocale`, `$localeRoute` и т. д.)

См. обновлённые разделы [Архитектура кеша и хранилища](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api) и [Производительность](/ru/guide/performance).

### SSR payload через `useState('i18n-ssr-chunks')` {#ssr-payload-via-usestate‘i18n-ssr-chunks’}

Переводы SSR сериализуются через **состояние Nuxt**, а не через тег script `window.__I18N__`:

1. Сервер загружает чанки → `useState('i18n-ssr-chunks')`
2. Клиент выполняет гидратацию → `translationStorage.seedFromSsrChunks()`
3. Никаких дополнительных запросов при первой отрисовке

Устаревший путь чтения `window.__I18N__` **удалён**.

### Разделение архитектуры редиректов {#redirect-architecture-split}

Редиректы теперь зависят от окружения — это делает поведение понятнее и уменьшает подтормаживания на клиенте:

| Окружение      | Компонент                      | Роль                                       |
| -------------- | ------------------------------ | ------------------------------------------ |
| **Серверный SSR** | `06.redirect.ts` (только сервер) | 302 до рендеринга, проверки 404, синхронизация cookie |
| **Клиентский SPA** | `i18n-redirect.global.ts`      | Глобальный middleware маршрутов при навигации |

Клиентские редиректы определяют локаль по **целевому маршруту**, сохраняют **строку запроса и хеш** и учитывают `redirects: false` (middleware не регистрируется). См. [Определение локали — редиректы для каждой стратегии](/ru/guide/locale-detection#redirects-per-strategy).

### Время срабатывания хука `i18n:register` {#i18nregister-hook-timing}

Плагин **`05.hooks`** (`dependsOn: i18n-plugin-loader`) вызывает `i18n:register` после готовности загрузчика — при запуске и при навигации, — так что пользовательские плагины надёжно получают событие. Отключается через `hooks: false`. См. [События](/ru/api/events).

### Извлечение `defineI18nRoute` во время сборки {#build-time-definei18nroute-extraction}

Vite unplugin во время сборки сканирует `.vue`-файлы страниц и записывает мета-данные маршрутов для `@i18n-micro/route-strategy`. `$defineI18nRoute` во время выполнения в `script setup` остаётся для режима разработки и встроенной конфигурации. См. [Переводы на уровне компонентов](/ru/guide/per-component-translations).

## Исправления ошибок {#bug-fixes}

- **Гидратация SSR** — реактивные чанки SSR клонируются перед `Object.freeze` (исправляет падения клиента на `#locale` / 404)
- **Переключение локали** — слой представления заменяется при смене локали (никаких устаревших ключей от предыдущей локали)
- **Клиентский редирект** — локаль берётся из целевого маршрута; query/hash сохраняются при редиректе
- **`has()`** — проверяет только активную локаль; резервная локаль применяется в `$t()`, а не в `$has()`
- **Мета-данные `defineI18nRoute`** — кеш на каждый экземпляр плагина; самое длинное совпадение `rootDir`; правильные пути `pages/index` и `pages/index/index`

## Критические изменения {#breaking-changes}

Нет для стандартного использования `nuxt.config` + композаблов. Изменились внутренние пути и механизм внедрения SSR; приложения, которые полагались на ручное внедрение `window.__I18N__`, должны использовать вместо этого payload Nuxt / API модуля.

## Почему это важно {#why-it-matters}

- **Более надёжная передача от SSR к клиенту** — нативное состояние Nuxt вместо самодельных глобальных переменных
- **Более понятная модель редиректов** — серверный 302 до отрисовки; клиентский middleware только там, где он нужен
- **Проще сопровождать** — среда выполнения разделена на тестируемые модули с целевыми регрессионными тестами

Полный журнал изменений будет опубликован вместе с выпуском на [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
