## Nuxt I18n Micro v3.22.0 — форматы, кэш и Translation Memory {#nuxt-i18n-micro-v3-22-0-—-formats-cache-&-translation-memory}

**Дата**: 2026-07-30

**Версия**: `v3.22.0`

![Выпуск v3.22.0](/images/3.22.0.png)

Представляем **v3.22.0**: именованные форматы чисел и дат в стиле Vue I18n с кэшем форматтеров, кэширование payload переводов, удобное для CDN (отпечаток содержимого + `httpCacheDuration`), и Translation Memory API для чтения и замены активного словаря во время выполнения.

## Что нового? {#what’s-new}

### Именованные `numberFormats` / `datetimeFormats` + кэш форматтеров {#named-numberformats-/-datetimeformats-+-formatter-cache}

Именованные форматы, совместимые с Vue I18n, и более быстрое форматирование через Intl:

- Конфигурация: `numberFormats` / `datetimeFormats` для каждой локали
- API: `$tn(1000, 'currency')`, `$td(date, 'short')` (+ переопределение локали и слияние опций)
- `FormatService` кэширует `Intl.NumberFormat` / `DateTimeFormat` / `RelativeTimeFormat` по сочетанию локали и опций

См. [Методы — `$tn` / `$td`](/ru/api/methods#$tn) и [Опции модуля](/ru/api/module-options#numberformats).

### `dateBuild` по умолчанию — отпечаток содержимого {#datebuild-defaults-to-a-content-fingerprint}

Параметр `?v=` в запросах к `/_locales` раньше по умолчанию равнялся `Date.now()`, тогда как ответы отдаются как `immutable` на год. Поэтому каждая пересборка инвалидировала словарь у каждого клиента, даже если ни один перевод не менялся.

Теперь по умолчанию используется SHA-256-отпечаток исходников переводов в порядке слоёв. Пересборки с неизменёнными переводами сохраняют тот же URL. Явно заданный `dateBuild` по-прежнему имеет приоритет. См. [Опции модуля — `dateBuild`](/ru/api/module-options#datebuild).

### `httpCacheDuration` для payload `/_locales` {#httpcacheduration-for-/_locales-payloads}

Встроенный маршрут `/{apiBaseUrl}/:page/:locale/data.json` теперь отправляет HTTP-заголовок `Cache-Control` для браузеров и CDN:

- Опция: `httpCacheDuration` (в секундах, по умолчанию `31536000` / 1 год)
- Заголовок: `Cache-Control: public, max-age=…, immutable`
- Безопасно вместе с существующим сбросом кэша через `dateBuild` (`?v=...`); `0` отключает заголовок; в режиме разработки не применяется

Аналог `experimental.httpCacheDuration` из `@nuxtjs/i18n` v10.2.0, но в виде явного заголовка ответа.

### Сжатые публичные payload {#compressed-public-payloads}

`nitro.compressPublicAssets` теперь распространяется и на payload переводов, копируемые в публичную директорию (`.gz` + `.br`). Nitro сжимает публичные ресурсы до того, как происходит копирование, поэтому раньше payload были единственной несжатой частью статической сборки — 6,65 МБ в сыром виде против 1,01 МБ в gzip на индексе playground. Модуль по-прежнему никогда не включает сжатие сам. См. [Производительность](/ru/guide/performance#payload-size).

### `resolveTranslations()` и `setTranslation(key, value)` {#resolvetranslations-and-settranslationkey-value}

Runtime-хелперы для чтения и замены активного словаря переводов в памяти:

- **`resolveTranslations()`** возвращает полное дерево, из которого `$t()` читает данные для активной локали и маршрута, — полезно для DevTools, тестов и редакторов во время выполнения. Когда активен второй слой (резервная локаль или горячая перезагрузка при переходе страниц в Nuxt), дамп сохраняет вложенную структуру через `mergeTranslationLayers` и использует плоские ключи с точками только для конфликтов «скаляр против объекта», которые иначе нельзя выразить одним деревом.
- **`setTranslation(key, value)`** заменяет значение по ключу (верхнего уровня, путь через точку, объект, строка или скаляр). Это **замена**, а не слияние; используйте `$mergeTranslations`, если соседние ключи должны сохраниться.
- Доступно в `useI18n()`, `useNuxtApp()` и экземплярах i18n фреймворков, унаследованных от `@i18n-micro/core`.
- `@i18n-micro/test-utils` добавляет соответствующие хелперы `resolveTranslations` / `setTranslation` для модульных тестов.

### `getAllTranslations()` удалён из пакета Vue {#getalltranslations-removed-from-vue-package}

Используйте `resolveTranslations()` для активного дерева поиска. Для полного дампа хранилища во Vue используйте `getStorage()` или `getRouteCache()`.

## Критические изменения {#breaking-changes}

В публичной конфигурации нет ничего, что потребовало бы правок кода приложения при типичном использовании. Эти изменения важны, если вы обращались к внутренностям runtime:

- **SSR payload переехал из `useState('i18n-ssr-chunks')` в `nuxtApp.payload.data['i18n-ssr-chunks']`.** Он по-прежнему содержит **полные чанки переводов** для каждой пары `(locale, route)`, загруженной во время SSR, — те же словари, что и раньше, но в слоте, который Nuxt может вынести в `_payload.json` при пререндеринге. `useState('i18n-ssr-chunks')` теперь ничего не возвращает. Чтение переводов таким способом никогда не поддерживалось, но было описано в документации API кэша, поэтому упоминается здесь.
- **`NuxtTranslationLoaderOptions` предоставляет `setSsrChunk`.** Загрузчик записывает каждый объединённый чанк в `payload.data` на сервере по мере загрузки. `getSsrChunks` не используется.
- **`nitro.compressPublicAssets` теперь создаёт `.gz` / `.br` рядом со скопированными payload.** Если эта опция была включена, ожидайте больше файлов в публичном выводе. Инструментам деплоя, которые перечисляют директорию переводов, может потребоваться их учитывать.
- **URL payload однократно меняются при обновлении**, потому что `?v=` переключается с метки времени сборки на отпечаток содержимого. Клиенты заново загрузят словарь при первом запросе после обновления, а затем будут сохранять его между последующими деплоями — в этом и смысл.
- **`getAllTranslations()` удалён из `@i18n-micro/vue`.** Вместо него используйте `resolveTranslations()` / `getStorage()` / `getRouteCache()`.

## Исправления ошибок {#bug-fixes}

- **`<i18n-switcher>`** — пропускает локали с `disabled: true` в выпадающем списке. `$getLocales()` по-прежнему возвращает полный список для вашего кода, а встроенный SEO/meta-вывод исключает отключённые локали.
- **Стили переключателя** — `cursor: not-allowed` применяется к **текущей** локали через `activeLinkStyle` / `customActiveLinkStyle`; восстановлен `customDisabledLinkStyle` для обратной совместимости, и он применяется к кнопке переключателя, когда текущая локаль имеет `disabled: true`.
- **Dev HMR** — запись, не меняющая содержимое файла (сохранение редактора при потере фокуса, перезапись форматтером), больше не вызывает повторное слияние. Изменения корневой локали пересобирают все страницы этой локали, поэтому тратить это на пустую операцию было дорого.
- **Dev HMR** — при изменении корневой локали страницы пересобираются параллельно, а не одна за другой.
- **Переходы страниц** — навигация в пределах одной локали сохраняет уходящий чанк как сквозной слой до `page:transition:finish` вместо дорогого глубокого слияния при каждой навигации.

## Почему это важно {#why-it-matters}

- Форматирование в стиле Vue I18n без подключения более тяжёлого стека.
- Удобные для CDN URL переводов, которые остаются стабильными между пересборками, если словарь не менялся.
- Поддерживаемый runtime API для просмотра и изменения живого словаря — DevTools, тестам и редакторам больше не нужны приватные хелперы.

Полный список изменений будет опубликован вместе с выпуском на [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).

## Исправление: бесконечный цикл перенаправлений при `app.baseURL` + `strategy: 'prefix'` (#234) {#fix-infinite-redirect-loop-with-app-baseurl-+-strategy-‘prefix’-#234}

**Дата**: 2026-07-03

Серверный плагин перенаправления (`06.redirect.ts`) теперь удаляет `runtimeConfig.app.baseURL` из `getRequestURL(event).pathname` перед определением локали. Это исправляет `ERR_TOO_MANY_REDIRECTS`, когда приложение обслуживается по подпути (например, `/examples` → `/examples/ja` один раз, а не `/examples/ja/examples/ja/...`).
