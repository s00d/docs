**Дата**: 2026-11-03

**Версия**: `v4.0.0`

![Выпуск v4.0.0](/images/4.0.0.png)

Вышла **v4.0.0**. Маршрутизация, ядро переводов, файлы словарей, определение локали и все пакеты для фреймворков были переписаны. Опции, `$t`, `$localePath`, `$switchLocale`, компоненты и composables сохранили свои имена. Меняется поведение, и большинство этих изменений — исчезнувшие баги. Большинству приложений потребуется немного правок в коде, но перед обновлением прочитайте раздел [Критические изменения](#breaking-changes): URL, SEO-теги и API пакетов для фреймворков местами изменились. Все подробности — в разделе [Обновление](/ru/guide/upgrade).

## Что нового? {#what’s-new}

### Одна сборка для всех доменов {#one-build-for-every-domain}

`locales[].baseUrl` и `baseDefault` раньше влияли только на ссылки. Теперь они также маршрутизируют запросы — при всех четырёх стратегиях и в `nuxt generate`:

```ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'fr', baseUrl: 'https://example.com' },
      { code: 'de', baseUrl: 'https://example.de', baseDefault: true },
    ],
  },
})
```

- Хост обслуживает собственные локали. Ссылки на локаль другого домена становятся абсолютными URL на этом домене, а переключение на неё переходит туда.
- `trustForwardedHost` берёт домен из `X-Forwarded-Host` за прокси, который перезаписывает этот заголовок. По умолчанию выключено.
- `NUXT_I18N_DOMAIN` задаёт хост для `nuxt generate`: запускайте его один раз для каждого домена, и каждый результат будет содержать только страницы и словари этого домена.
- Приложение без `baseUrl` не включает ничего из этого кода.

См. [Слои и домены](/ru/guide/layers#multiple-domains) и [Развёртывание](/ru/guide/deployment).

### Маршрутизация, согласованная с роутером {#routing-that-agrees-with-the-router}

Сборка и среда выполнения больше не вычисляют локализованные URL по отдельности. Каждый ответ берётся из маршрутов, сгенерированных сборкой, поэтому ссылка, переключатель, `hreflang` и редирект не могут указывать на несуществующую страницу.

- Локаль, которая не обслуживает страницу, ссылается на свою главную, а не на страницу другой локали.
- `hreflang` перечисляет только локали, обслуживающие страницу.
- `$switchLocale` разрешается в `true` или `false`, так что можно узнать, что словарь не загрузился. Повторный вызов делает ещё одну попытку.
- `$setI18nRouteParams` и `useI18nHead`, заданные во время SSR, переживают гидратацию. Переключатель ссылается на переведённый slug, в том числе в серверном HTML.
- Навигация вступает в силу при фиксации: отменённая или заблокированная ничего не меняет.
- Режим hash работает при `prefix`.
- `<Greeting :locale="$getLocale()" />` на серверном компоненте задаёт локаль его рендеринга.

### Единое определение локали {#one-locale-detection}

Один порядок везде: на сервере, в браузере, в серверных API-хелперах и в Astro. `Accept-Language` учитывает значения `q`, региональное сопоставление больше не зависит от порядка `locales` и никогда не пересекает китайские письменности. Переопределения во время выполнения теперь влияют на маршрутизацию: `NUXT_I18N_DEFAULT_LOCALE` и заданный во время выполнения `disabledLocales` меняют то, что действительно обслуживается. См. [Определение локали](/ru/guide/locale-detection).

### Один словарь во всех режимах {#one-dictionary-in-every-mode}

Предварительно объединённые сборки, `mode: 'source'` и режим разработки раньше расходились на многих страницах. Теперь они дают одинаковый словарь.

- Слияние глубокое на всех уровнях, а цепочки резервных локалей (`fr` → `de` → `en`) проходятся до конца.
- Правки переводов в режиме разработки применяются на месте, без перезагрузки страницы. Удалённые ключи исчезают, а правка корневого файла доходит до каждой страницы.
- `$clearCache()` перезагружает текущую страницу и оставляет старый текст на экране, пока не придёт новый.
- Неудачно загруженный чанк сохраняет текущий словарь вместо показа сырых ключей.

### Файлы словарей меньшего размера {#smaller-dictionary-files}

- Файл страницы теперь содержит только то, что отличается от корня локали в `__root/<locale>/data.json`. Браузер загружает корень один раз и накладывает на него каждую страницу, поэтому занимаемое место на диске уменьшается, а следующая страница обходится в малую долю первой.
- URL словарей содержат версию. URL с текущим `?v=` закрепляется на год на Node-сервере, а статическая копия хостинга отвечает с `max-age=60`. См. [Заголовки кэширования](/ru/guide/deployment#cache-headers-and-datebuild).
- Каждая SSR-страница предзагружает свои файлы словарей, поэтому их загрузка начинается вместе с HTML.
- Неудачное чтение больше не залипает: следующий запрос читает заново. См. [Когда словарь не удаётся прочитать](/ru/guide/deployment#when-a-dictionary-cannot-be-read).

### Улучшенные `<i18n-t>`, множественное число и форматы {#better-&lt;i18n-t&gt;-plurals-and-formats}

- Слоты работают с `plural`, `number`, `date` и `relativeDate`, и заполняется каждый `{name}`, а не только первый.
- `<i18n-t>` — единый рендерер для Nuxt, Vue, React, Preact, Solid и Astro.
- Первая форма, начинающаяся с `=0 `, — явная форма для нуля, а остальные выбираются по `Intl.PluralRules`: `=0 no apples | one apple | {count} apples`. См. [`$tc`](/ru/api/methods#$tc).
- Новая опция `timeZone`: одна календарная дата на сервере и во всех браузерах.
- `{firstName}`, `{first-name}` и `{user.name}` — допустимые плейсхолдеры.
- `$tn`, `$td` и `$tdr` следуют `iso`, как и множественное число.
- `$tdr` выдаёт настоящие будущие даты: `in 3 days` или `tomorrow` с `numeric: 'auto'`.

### Безопаснее по умолчанию {#safer-by-default}

- `<i18n-t html>` экранирует `params`. Доверенной разметкой считается только перевод.
- Ни одна ссылка случайно не покидает origin: `//host`, `/\host` и пустые значения остаются на этом сайте.
- Серверный кэш переводов ограничен, поэтому URL с выдуманными именами страниц не могут раздувать память.
- Эндпоинты сохранения DevTools принимают только существующие файлы `.json` внутри ваших каталогов переводов и отклоняют межсайтовые запросы.

### Пакеты для фреймворков версии 2.0 {#framework-packages-at-2-0}

- **React, Preact, Solid:** `I18nT` принимает свойство `components` для форматированного текста. Новые `useT` и `useLocaleSwitch`, а также поддержка React Server Components через `@i18n-micro/react/server` и `/client`. Preact больше не нужен `preact/compat`.
- **Vue и VitePress:** `I18nLink` сохраняет `name`, `query` и `hash`, а VitePress учитывает `base`.
- **Astro:** `i18nIntegration` включает ваши словари в бандл и устанавливает middleware. Основная точка входа не импортирует `node:*`, поэтому работает на edge. `base` работает.
- **Node и runtime:** `fork(locale)` даёт дешёвый экземпляр на запрос, а `run(locale, fn)` в `@i18n-micro/node` привязывает его к запросу.
- **`@i18n-micro/types-generator`:** без сторонних зависимостей, обычный плагин для Vite и Rollup.
- **`@i18n-micro/devtools-ui`:** живые обновления через сокет Vite и приложение для тулбара Astro.

### `@i18n-micro/cli` {#@i18n-micro/cli}

CLI теперь живёт в монорепозитории как `@i18n-micro/cli`, переписанный: 16 команд вместо 28 и гораздо меньше зависимостей. `check` заменяет `validate`, `diff` и `check-duplicates`, с `--json` и кодами выхода для CI. Если `clean` не может доказать, что ключ не используется, он ничего не записывает. См. [CLI](/ru/guide/cli).

### Документация {#documentation}

Документация переписана по коду вокруг единого пути чтения: установка, первая переведённая страница, файлы переводов, маршрутизация, определение локали, затем руководства по задачам. Старые URL перенаправляются. В разделе [Обновление](/ru/guide/upgrade) подробно перечислены все изменения.

## Скорость и размер {#speed-and-size}

- Серверный рендеринг читает словари напрямую, без локального HTTP-запроса и повторного разбора.
- `dir="auto"` больше не используется по умолчанию. Браузеры тратят на него много времени на больших страницах: при 20 000 элементов `$t` DOMContentLoaded в Chromium сократился примерно с 980 мс до примерно 115 мс.
- `serverTranslationPreload` и `i18n:register` больше не замедляют каждый запрос.
- Клиентский бандл не включает `useCookie`, если cookie не настроен, а `@i18n-micro/path-strategy` составляет малую долю своего прежнего размера.

## Критические изменения {#breaking-changes}

### Требования {#requirements}

- **Nuxt 3.18 или новее** и **Node 20 или новее**.
- **`@i18n-micro/test-utils`** больше не устанавливается вместе с модулем. Добавьте его сами, если ваши тесты его импортируют.
- **`@i18n-micro/hmr`** удалён: HMR переводов встроен. Удалите пакет, если устанавливали его.
- **`@i18n-micro/react`** требует React 18 или новее.
- **`nuxt-i18n-micro-cli`** заменён на `@i18n-micro/cli`.

### Опции и конфигурация {#options-and-config}

- `i18n-plugin-hooks` и `i18n-plugin-define` в `dependsOn` больше ничего не ожидают, причём без ошибки. Используйте `i18n-plugin-loader`.
- Серверные автоимпорты: `useLocaleServerMiddleware`, `useTranslationServerMiddleware`, `loadTranslationsFromServer` и `detectCurrentLocale`. Остальные больше не импортируются автоматически.
- `resolveTranslationPayloadMode` и другие хелперы `resolveTranslationPayload*` удалены из `nuxt-i18n-micro`, как и `shouldCopyTranslationPayloadsToPublic` и `shouldRegisterNitroServerAssets`. Тип `TranslationPayloadMode` остаётся.
- `$getI18nConfig()` больше не содержит `isSSG`, `hmr`, `hooks`, `noPrefixRedirect`, `routeLocales`, `routeDisableMeta` и `globalLocaleRoutes`. Сами опции не изменились.
- `locales[].baseUrl` теперь маршрутизирует запросы: локаль другого домена на этом хосте возвращает 404, а ссылки на том же хосте относительные. В такой сборке `$getI18nConfig().locales` содержит то, что обслуживает хост, а `linkLocales` — все локали.
- `baseUrl` также задаёт origin на любом другом хосте: canonical и `hreflang` используют `metaBaseUrl`, если он задан, иначе `baseUrl` локали по умолчанию, а не origin запроса.
- `excludePatterns` сопоставляются с целыми сегментами (`'/admin'` больше не совпадает с `/administrator`), glob-шаблоны привязаны к началу и концу, а шаблоны `RegExp` теперь доходят до среды выполнения.
- Если `cacheMaxSize` не задан, на сервере хранится не более 1000 записей. `cacheTtl` отсчитывается с момента сохранения записи, и чтения больше его не продлевают.
- При `no_prefix` явный `localeCookie: null` в конфигурации `i18n` остаётся выключенным.
- При `prefix_except_default` и `prefix_and_default` заданный во время выполнения `defaultLocale` игнорируется с предупреждением. Заданный во время выполнения `fallbackLocale` должен быть включённой локалью.
- `routeDisableMeta` в `nuxt.config` учитывается, и запись в `nuxt.config` побеждает `$defineI18nRoute` при любой форме ключа.
- На сервере в режиме разработки разрешённая конфигурация заморожена: запись в неё выбрасывает исключение.
- Запись `locales` проекта побеждает запись слоя с тем же `code`.

### Composables и методы `$` {#composables-and-$-methods}

- `$switchLocale` разрешается в `true` или `false`, раньше он ничего не возвращал. `$switchRoute` типизирован как `Promise<void>`.
- `$localeRoute`, `$switchLocalePath` и переключатель ведут локаль, не обслуживающую страницу, на главную этой локали.
- `$localePath` возвращает строку со схемой `http(s):`, `mailto:` или `tel:` как есть, а `$localeRoute` передаёт её в `path` и `fullPath`. Не передавайте им непроверенное значение в качестве цели ссылки. `//host` и голые имена вроде `x.com` остаются путями на этом origin.
- Ссылка без пути остаётся на текущей странице: `$localePath('#top')`, `'?p=2'`, `''` и `{ query }`. Раньше `'#top'` отсчитывался от корня сайта. Голый `'about'` по-прежнему означает `/about`.
- `$switchRoute` остаётся в приложении. Покидают его только собственный `baseUrl` локали, `mailto:` и `tel:`.
- Ссылка на локаль с `baseUrl` создаётся через `$localePath` или `<i18n-link>`. `<NuxtLink :to="$localeRoute(x, 'fr')">` и `router.push($localeRoute(x, 'fr'))` остаются путями этого приложения. В коде используйте `navigateTo($localePath(x, 'fr'), { external: true })`.
- `$switchLocaleRoute` и редиректы следуют `trailingSlash`.
- `$setI18nRouteParams` и `useI18nHead`, заданные на сервере, сбрасываются, когда навигация меняет путь, включая переход с `/news/1` на `/news/4`: задайте их снова на новой странице.
- `$setI18nRouteParams`, прочитанный в setup, привязан к этой странице: поздний вызов со страницы, которую уже покинули, ничего не делает. У него нет сеттера, поэтому в тестах подменяйте сам `useI18n`.
- `useI18n()` возвращает один объект на приложение. Запись в него доходит до всех вызывающих.
- Словарь, локаль, параметры и head меняются при фиксации навигации. `beforeResolve`, `beforeRouteEnter` или более поздний глобальный guard видят старые значения. Route middleware это не затрагивает.
- `$switchLocale` восстанавливает сохранённую локаль, когда его навигация отменяется, при URL-стратегиях.
- `$t` интерполирует `defaultValue`: `$t('missing', { n: 1 }, 'Got {n}')` даёт `Got 1`. `$tc` тоже, а для пустого перевода отвечает `''`.
- `$has(key, route)` учитывает маршрут.
- `$clearCache()` перезагружает словарь текущей страницы.
- Плейсхолдер `{param}` читает только переданные вами параметры: `{constructor}` остаётся как написан.
- `$tc` с отрицательным, дробным или огромным количеством берёт последнюю форму с настоящим количеством. `{ count: null }` больше не выбрасывает исключение, а отсутствующий ключ множественного числа доходит до обработчика отсутствующих ключей.
- `$tdr` выдаёт `Invalid Date` для недопустимого ввода. Менее секунды в прошлом — `0 seconds ago`.
- `$tn`, `$td` и `$tdr` ориентируются на `iso`: `{ code: 'en', iso: 'en-GB' }` форматирует даты как `31/10/2026`. Код, неизвестный `Intl`, форматируется как `en`, а множественное число — по индексному правилу: задайте `iso` (`{ code: 'ua', iso: 'uk-UA' }`).
- `detectCurrentLocale` устарел: используйте `useLocaleServerMiddleware(event).current`.

### Множественное число {#plurals}

Шаблоны сохраняют свой смысл, за одним исключением. Форма для нуля без плейсхолдера, затем по одной форме на категорию, с `{count}` в каждой форме, которую разделяют несколько количеств, теперь выбирается по категории в локалях с тремя и более категориями (`ru`, `uk`, `pl`, `cs`, `ar` и другие): `none | {count} one | {count} few | {count} many` даёт `3 few` и `21 one` в `uk`. Чтобы использовать категории в любом другом шаблоне, добавьте маркер `=0 `. Пользовательское правило `plural` читает исходное значение, поэтому помеченный шаблон доходит до него с `=0 ` на месте. См. [таблицу в разделе «Обновление»](/ru/guide/upgrade#plurals-and-formatting).

### Компоненты {#components}

**`<i18n-t>`**

- `html` экранирует `params` во всех случаях и игнорирует все слоты.
- Слот побеждает параметр с тем же именем.
- `null` означает «не задано» для `plural`, `number`, `date` и `relativeDate`.
- `plural` считает как `$tc`, через `Number`: `1.5` остаётся `1.5`, `"2 items"` — `NaN`, `""` — `0`.
- `number`, `date` и `relativeDate` сохраняют `params`.
- `hideIfEmpty` применяется в каждой ветке, а `defaultValue` подставляется вместо отсутствующего ключа в каждой ветке.
- Отсутствующий ключ при `html` выводится экранированным текстом.
- Вывод `date` и `relativeDate` имеет `data-allow-mismatch="text"`, а рядом с именованным слотом текст помещается в собственный `<span>`.
- Атрибуты `.innerHTML` и `textContent` отбрасываются.
- Это функциональный компонент: `ref` на нём не даёт экземпляра.
- `<i18n-t>` и `<i18n-group>` читают активный словарь, как и `$t`.

**`<i18n-switcher>`**

- Ссылка — обычный `<a>`, вызывающий `$switchLocale`, поэтому классов `router-link-active` больше нет.
- Кнопка имеет `type="button"` и `aria-expanded`. Escape и клик снаружи закрывают выпадающий список.
- Новые классы `i18n-switcher-wrapper`, `i18n-switcher-dropdown` и `i18n-switcher-button`. Каждая ссылка имеет `lang`, а также `dir`, если локаль его задаёт.
- Стили по умолчанию используют логические CSS-свойства, а у выпадающего списка больший `z-index`, минимальная ширина и тень.
- Сервер переписывает его ссылки по окончании рендеринга на страницах с параметрами. Написанная вручную ссылка `$switchLocalePath` не переписывается.

**`<i18n-link>`**

- `https://`, `mailto:` и `tel:` распознаются в любом регистре. Голый `report.pdf` — маршрут, а `example.com` остаётся внешней ссылкой. Расширение файла, которое также является TLD (`example.md`), считается файлом: пишите `https://`.
- `activeStyle` игнорирует завершающий слэш, query и hash.

### Хуки и типы {#hooks-and-types}

- `i18n:register` — хук времени выполнения: `nuxtApp.hook('i18n:register', …)` в плагине.
- Экспортируемый тип `ModuleHooks` переименован в `ModuleRuntimeHooks`.
- `i18n:beforeLocaleSwitch` и `i18n:afterLocaleSwitch` никогда не вызывались и больше не документируются.
- `ModuleOptionsExtend.isSSG` необязателен и устарел: ничто его не задаёт.

### URL и редиректы {#urls-and-redirects}

- **`/en` и `/en/...` возвращают 404** при `prefix_except_default`, если `en` — локаль по умолчанию.
- **Префикс локали в другом регистре или написании возвращает 404** (`/DE/about`). Как и `/DE/x` при `[...slug]` и `/DE` рядом с `[slug]`, поэтому slug из CMS, совпадающий с кодом локали в другом регистре, теряет свою страницу.
- **Неизвестный URL остаётся 404** при `autoDetectPath: '*'` или `'no_prefix'`. `prefix` сохраняет редирект, как и `/` везде.
- **Пользовательский путь другой локали без префикса** при `prefix_except_default` даёт `302` на URL локали по умолчанию. При `prefix` редирект теперь ведёт на существующую страницу. `prefix_and_default` по-прежнему возвращает 404.
- **`prefix` с `redirects: false`** отвечает 404 на URL без префикса, включая исходный URL страницы с пользовательским путём по умолчанию.
- **`autoDetectPath: '*'`** применяет cookie и `Accept-Language` и к путям без префикса.
- **При `prefix`** URL без префикса сохраняет локаль посетителя на любом пути, что бы ни говорил `autoDetectPath`.
- **При `prefix_and_default`** URL без префикса — это локаль по умолчанию.
- **При `no_prefix`** пользовательский путь рендерит собственную локаль, страница с ограничениями рендерится в локали, которую она обслуживает, а локали с общим путём используют одну запись.
- **Редирект `routeRules` без страницы** не локализуется: `/de/old` возвращает 404, раньше это был пустой 200.
- **Правила маршрутов доходят до пользовательских путей** и копируются также при `no_prefix`. Статический соседний маршрут, такой как `/de/artikel/news`, совпадает с `/de/artikel/:slug`.
- **Локаль с `disabled: true`** сразу отвечает 404 на своём префиксе, а ссылки на неё остаются на странице.
- **Путь страницы в другом регистре** даёт `302` на её собственное написание: `/T/BASIC` ведёт на `/t/basic`.
- **Исходный URL страницы с пользовательским путём по умолчанию** при `prefix_except_default` даёт `302` на этот путь. Раньше это был 404.
- **`noPrefixRedirect`** ориентируется на локаль посетителя: при cookie `de` `/about` ведёт на `/ueber-uns`, а не на путь локали по умолчанию.
- **Собственный префикс хоста** возвращает 404 на его хосте с `baseDefault` при `prefix_except_default`: `/de/x` на хосте `de` раньше давал 200.
- **`customRegexMatcher`** больше не возвращает 404 для настоящей страницы, первый сегмент которой похож на локаль.
- **`nuxi generate`** пререндерит каждую статическую страницу в каждой обслуживающей её локали, если правило маршрута не задаёт `prerender: false`: в результате больше файлов. При `baseUrl` запускайте его один раз для каждого домена с `NUXT_I18N_DOMAIN`.
- **Клиентский редирект сохраняет режим своей навигации:** обычный `<NuxtLink>` добавляет запись в историю.
- **Имена локализованных маршрутов согласованы.** Затронут только код, жёстко прописывающий имена `localized-…` в `router.push({ name })`: передавайте в `$localeRoute` собственное имя страницы.
- **Безымянные страницы из `extendPages`** локализуются и получают имя.
- **При `prefix` ссылка на другой домен** сохраняет префикс локали.
- **Главная страница домена** везде записывается без завершающего слэша.
- **`?locale=`** учитывается на страницах только при `no_prefix`. `/about?locale=de` больше не рендерит немецкий текст под `lang="en"`.
- **`setLocale('de')` в плагине** на `/en/...` больше не загружает словарь `de`.

### SEO и HTML-вывод {#seo-and-html-output}

- `dir="auto"` больше не используется по умолчанию. Известный RTL-язык получает `dir="rtl"`, а любая другая локаль без `dir` не получает атрибута. Чтобы сохранить старый вывод, задайте `dir: 'auto'` ценой затрат на разбор на больших страницах. См. [Направление текста](/ru/guide/seo#text-direction).
- `disableMeta` теперь работает: у страницы нет `hreflang`, canonical и `og:locale`. `lang` и `dir` остаются.
- `hreflang` перечисляет только локали, обслуживающие страницу. `x-default` появляется, только если её обслуживает локаль по умолчанию.
- У нелокализованной страницы нет `hreflang` и `og:locale:alternate`.
- Страницы 404 имеют `<html lang dir>` в локали URL и не имеют canonical и `hreflang`.
- Canonical, `og:url` и `hreflang` сохраняют разрешённый query (`/about?page=2`), в том числе на сервере.
- Canonical и `hreflang` включают `app.baseURL`, когда origin берётся из запроса.
- Каждая SSR-страница содержит `<link rel="preload" as="fetch" crossorigin="anonymous">` для своих файлов словарей, включая страницы 404. Разрешите это в строгой CSP. При `apiBaseClientHost` этому хосту нужен CORS.
- `Vary` устанавливается на каждой странице при `no_prefix` и на редиректах локали при других стратегиях. Проверьте ключ кэша вашего CDN.
- Cookie локали записывается только обслуженной страницей.

### Определение локали и сервер {#detection-and-server}

- `Accept-Language` учитывает значения `q`, а `q=0` исключает язык.
- `useLocaleServerMiddleware` и `useTranslationServerMiddleware` используют один порядок на каждом маршруте (`?locale`, параметр `[locale]` или префикс, cookie, заголовок, значение по умолчанию), учитывают `localeCookie: null` и `autoDetectLanguage: false` и кэшируют словарь для каждой локали.
- Некорректный cookie локали игнорируется и остаётся как есть, вместо того чтобы ломать SSR.
- Режим hash читает только cookie `hash-locale`. Одиночный `user-locale=de` больше не учитывается.
- `NUXT_I18N_DEFAULT_LOCALE` и заданный во время выполнения `disabledLocales` меняют маршрутизацию.
- **Вывод `premerged` изменился.** `/{apiBaseUrl}/<page>/<locale>/data.json` содержит только то, что отличается от `__root/<locale>/data.json`. Всё, что читает эти файлы напрямую, должно объединять их. Полный словарь по-прежнему является допустимым файлом.
- **Словари следуют `app.cdnURL`.** Браузер загружает их из `<cdnURL>/_locales/...`, где раньше использовал `app.baseURL`. CDN должен хранить `_locales/` и разрешать origin вашего сайта. См. [App baseURL и хосты payload](/ru/guide/deployment#app-baseurl-and-payload-hosts).
- Кэша маршрутов Nitro для `/{apiBaseUrl}/**` нет, а заголовок `s-maxage=60, stale-while-revalidate` удалён. Если вы полагались на этот кэш, поставьте CDN перед маршрутом payload.
- `/{apiBaseUrl}/<page without a folder>/<locale>/data.json` отвечает корневым словарём, раньше это был `{}`. 404 хостинга теперь передаётся как 404, тогда как раньше ответом было `200 {}`.
- Пререндеринг, который не может загрузить свой словарь, завершается ошибкой 500 с предупреждением, и при `failOnError` Nuxt по умолчанию сборка завершается с кодом 1.
- Изменённый перевод без пересборки доходит до браузера, только когда меняется `v`: задайте `NUXT_I18N_DATE_BUILD`.
- SSR больше не запрашивает `/{apiBaseUrl}` по HTTP, если не задан `apiBaseServerHost`.

### Переводы {#translations}

- Слияние глубокое на всех уровнях, а цепочки резервных локалей проходятся до конца.
- Слияние идёт по локалям: корневой файл активной локали побеждает файл страницы резервной локали.
- Страница без собственной папки `pages/<name>/` в продакшене читает корневой словарь. Раньше она получала `{}`.
- `disablePageLocales: true` читает только корневые файлы.
- Ключи уходящей страницы перестают разрешаться после навигации. Если лейаут использовал ключи, которые были только в файле предыдущей страницы, перенесите их в корневой файл.
- Повреждённый файл локали выдаёт одно предупреждение с путём во всех режимах. Раньше режим разработки выбрасывал исключение.

### Пакеты `@i18n-micro/*` {#@i18n-micro/*-packages}

- `core`: `TranslationHelper` лишился `setCache`, `getGeneration` и `lookupIn` (используйте `lookup(chunkKey, key)`). `BaseI18n` лишился `ensurePinnedChunk` и `invalidatePin`. `useTranslationHelper(storage)` удалён: используйте `new TranslationHelper(storage)`.
- `path-strategy`: **`switchLocaleRoute(fromLocale, toLocale, route, options)` теперь `switchLocaleRoute(toLocale, route, options)`. Старый вызов из JavaScript возвращает неверный результат без ошибки.** `$switchLocaleRoute` в Nuxt это не затрагивает. Точки входа `/prefix`, `/no-prefix`, `/prefix-except-default` и `/prefix-and-default` удалены, как и `getRedirect` и `getCanonicalPath`. `RouterAdapter` требует `getRoutes`. `createPathStrategy` не строит абсолютные URL: используйте `new DomainPathStrategy(ctx)`, когда у локалей есть `baseUrl`.
- `route-strategy`: экспортируются только `RouteGenerator`, `generateRoutes`, `Rules` и хелперы путей.

## Миграция {#migration}

1. Проверьте требования: Nuxt 3.18, Node 20 и React 18, если вы используете `@i18n-micro/react`.
2. Обновите `nuxt-i18n-micro` и все пакеты `@i18n-micro/*` одновременно. Удалите `@i18n-micro/hmr`. Добавьте `@i18n-micro/test-utils` как dev-зависимость, если ваши тесты его импортируют. Замените `nuxt-i18n-micro-cli` на `@i18n-micro/cli` и следуйте [его таблице команд](/ru/guide/cli#moving-from-nuxt-i18n-micro-cli).
3. Найдите в коде `switchLocaleRoute(` из `@i18n-micro/path-strategy`, `i18n-plugin-hooks`, `i18n-plugin-define`, имена маршрутов `localized-`, `$getI18nConfig().globalLocaleRoutes` и другие удалённые ключи конфигурации, `ModuleHooks`, а также `@ts-expect-error` на `i18n:register`.
4. Перенесите разметку из params `<i18n-t html>` в перевод, а данные передавайте как params.
5. Если вы задаёте `baseUrl`: проверьте ссылки, построенные через `$localeRoute`, задайте `trustForwardedHost` за прокси и запускайте `nuxi generate` один раз для каждого домена с `NUXT_I18N_DOMAIN`.
6. Сверьте свои URL со своей стратегией: `/en` при `prefix_except_default`, slug из CMS, похожие на локали, редиректы `routeRules` и `excludePatterns`.
7. Проверьте ключ кэша CDN на `Vary` и разрешите preload-ссылку в строгой CSP. При `app.cdnURL` разместите `_locales/` на CDN и разрешите CORS.
8. Если какой-либо инструмент читает файлы `/_locales/...` напрямую, накладывайте файл страницы на `__root/<locale>/data.json`.
9. Если глобальный guard читает локаль или словарь, убедитесь, что он может выполняться до фиксации навигации. Перенесите ключи, которые лейаут брал из файла предыдущей страницы, в корневой файл.
10. Сравните вывод `nuxi generate` или обход sitemap до и после: `hreflang`, `x-default`, canonical и список страниц меняются намеренно.
11. Обновите импорты пакетов для фреймворков: `/router` для адаптеров React, Solid и Preact, `/node` для загрузчиков Astro и `I18nTypesPlugin(o)` для плагина типов.
12. Для Astro удалите `src/middleware.ts`, который лишь копирует настройку, и переименуйте словари в стиле `pages/blog-hello/` по их шаблону.
13. Обновите тесты, завязанные на `router-link-active`, `li button`, `▼` или старое поведение мока.

Подробности и все пограничные случаи: [Обновление](/ru/guide/upgrade).

## Почему это важно {#why-it-matters}

- **Корректность по построению:** ссылки, редиректы и SEO-теги берутся из маршрутов, которые действительно есть в приложении.
- **Один ответ везде:** сборка, режим source и режим разработки дают одинаковый словарь, и все вызывающие используют один порядок определения локали.
- **Домены:** одно развёртывание для всех доменов локалей без второй сборки.
- **Более безопасные значения по умолчанию:** экранированные параметры, ограниченные кэши, ссылки, остающиеся на вашем origin.
- **Меньше поставляемого кода:** файлы словарей меньшего размера, более компактные пакеты маршрутизации и общая логика в одном месте.

Полный список изменений см. в разделе [Обновление](/ru/guide/upgrade) и в [журнале изменений](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
