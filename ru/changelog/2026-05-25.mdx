**Дата**: 2026-05-25

**Версия**: `v3.19.0`

![v3.19.0 release](/images/3.19.0.png)

Этот выпуск посвящён **модуляризации внутренних утилит**, добавлению **компактного serverless-режима payload** и **повторному использованию общей логики** в Nuxt, Node, Astro и DevTools — без изменения публичного API модуля для типичных приложений.

## Что нового? {#what’s-new}

### `@i18n-micro/utils` — фреймворк-независимые утилиты {#@i18n-micro/utils-—-framework-agnostic-utilities}

Общая логика, ранее разбросанная по `src/runtime/utils/` и `src/module.ts`, теперь находится в отдельном пакете рабочего пространства с **гранулярными импортами по подпутям** (без громоздкого barrel-файла, удобно для tree-shaking):

- **Сборка** — `preMergeLocales`, `buildTranslationSourceLayers` (`@i18n-micro/utils/build`)
- **Payload** — разрешение `translationPayloads`, построение URL, хелперы загрузки, статистика (`payload-config`, `payload-url`, `payload-fetch`, `payload-stats`)
- **Режим source** — цепочки fallback, пути к исходным файлам, слияние во время выполнения (`merge-source`, `source-loader`)
- **Хелперы времени выполнения** — определение локали, cookie, разбор Accept-Language, хелперы маршрутов и meta (`resolve-locale`, `accept-language`, `cookie`, `route`, `route-pattern`, `runtime-config`)
- **Общие пути ФС** — классификация файлов переводов, вложенные пути страниц (`parse-path`)

Модуль Nuxt сохраняет тонкий связующий слой в `src/runtime/` и импортирует только нужные ему подпути.

### `@i18n-micro/hmr` — горячая перезагрузка переводов в разработке {#@i18n-micro/hmr-—-dev-translation-hot-reload}

HMR для разработки вынесен в `@i18n-micro/hmr`:

- **`watcher`** — обработка изменений файлов, инвалидация кэша, слияние source/premerged в режиме разработки
- **`generate-plugin`** — генерация клиентского HMR-плагина
- **`cache-keys`** — общие ключи `Symbol.for` для серверных кэшей и кэшей хранилища

Работает как с `translationPayloads.mode: 'premerged'`, так и с `'source'`.

### `translationPayloads.mode: 'source'` — компактные serverless-развёртывания {#translationpayloads-mode-‘source’-—-compact-serverless-deployments}

Новый режим payload для больших матриц локалей на serverless-платформах (Cloudflare Workers и т. п.):

```typescript
export default defineNuxtConfig({
  i18n: {
    translationPayloads: {
      mode: 'source',
    },
  },
})
```

- Упаковывает **компактные исходные файлы** в ассеты Nitro вместо полной предварительно объединённой матрицы
- Объединяет корневые, страничные и fallback-цепочки локалей **во время выполнения** через встроенный маршрут `/_locales/:page/:locale/data.json`
- По умолчанию устанавливает `publicAssets` и `prerenderRoutes` в `false` — идеально, когда вы полагаетесь на среду выполнения Nitro/edge, а не на чисто статический хостинг

См. [Развёртывание — serverless и Edge](/ru/guide/deployment#serverless-and-edge) и [Архитектура кэша и хранилища](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api).

### Общие утилиты в пакетах интеграций {#shared-utilities-across-integration-packages}

- **`@i18n-micro/node`** и **`@i18n-micro/astro`** — единый разбор путей переводов и глубокое слияние через `@i18n-micro/utils/parse-path`
- **`@i18n-micro/astro`** — `detectLocaleFromAcceptLanguage` из `@i18n-micro/utils/accept-language` (удалён дублирующийся парсер)
- **`@i18n-micro/devtools-ui`** — виртуальные пути файлов через хелперы `merge-source` + `parse-path`
- **Определение локали на сервере** — обработка Accept-Language согласована с общими утилитами

### Исправления HMR и DevTools {#hmr-&-devtools-fixes}

- Клиентский HMR-плагин теперь вызывает **`$loadPageTranslations`** (правильный API) вместо удалённого `$loadTranslations`
- Покрытие Playwright для наблюдателя переводов в режимах **premerged** и **source**

## Несовместимые изменения (продвинутые / внутренние) {#breaking-changes-advanced-/-internal}

Они затрагивают только проекты, импортировавшие **внутренние** пути модуля (не входящие в публичный API):

- Удалены из `src/runtime/utils/`: `route-utils.ts`, `runtime-i18n-config.ts` и другие утилиты, перенесённые в `@i18n-micro/utils/*`
- Удалены из `src/runtime/server/plugins/`: встроенные наблюдатель и генератор HMR — используйте `@i18n-micro/hmr/*`, если вы форкнули инструменты разработки
- **`nuxt-i18n-micro`** теперь зависит от пакетов рабочего пространства `@i18n-micro/utils` и `@i18n-micro/hmr` (устанавливаются автоматически вместе с модулем)

Типичное использование `nuxt.config` и composables не изменилось.

## Почему это важно {#why-it-matters}

- **Меньшие serverless-бандлы** — режим `source` избавляет от поставки предварительно объединённого файла на каждую пару локаль × страница
- **Единый источник истины** — одна реализация для разбора путей, слияния, определения локали и конфигурации payload
- **Более простое сопровождение** — фреймворк-независимый код тестируется в `@i18n-micro/utils` (более 50 модульных тестов) и переиспользуется везде
- **Лучший опыт разработки** — логика HMR изолирована, тестируема и единообразна для всех режимов payload

Полный список коммитов см. в [журнале изменений](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
