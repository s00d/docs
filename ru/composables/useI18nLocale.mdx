---
title: "useI18nLocale"
description: "useI18nLocale читает и записывает состояние локали и cookie локали — точка входа для пользовательского определения локали."
---

`useI18nLocale()` даёт доступ к локали, которую выбрало приложение: к состоянию `i18n-locale` и cookie локали. Используйте его в плагине, который сам определяет локаль (по домену, профилю пользователя, заголовку), вместо того чтобы вручную записывать `useState('i18n-locale')` или cookie. Проверки допустимости используют включённые локали с учётом переопределений во время выполнения.

## Сигнатура {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Централизованная точка входа для управления локалью i18n.
Объединяет useState('i18n-locale'), cookie локали и утилиты синхронизации.

## Возвращаемые значения {#returned-values}

| Член | Тип | Описание |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | Ref `useState('i18n-locale')`. |
| `localeCookie` | `Ref<string \| null>` | Cookie [`localeCookie`](/ru/api/module-options#localecookie); простой `{ value: null }`, если опция равна `null`. |
| `hashCookie` | `Ref<string \| null>` | Cookie `hash-locale` при hash-маршрутизации; в остальных случаях `{ value: null }`. |
| `validLocales` | `string[]` | Коды включённых локалей. |
| `setLocale(locale)` | `(locale: string \| null) => void` | Записывает состояние и cookie. Не проверяет значение и не загружает переводы. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | Записывает только cookie. |
| `getLocale()` | `() => string \| null` | Состояние, затем cookie предпочтения (hash-cookie при hash-маршрутизации). Без проверки. |
| `getPreferredLocale()` | `() => string \| null` | Первое **допустимое** значение из состояния и cookie предпочтения либо `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | Состояние при hash-маршрутизации, если оно задано; иначе `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, затем допустимое состояние, затем `options.serverLocale`, затем локаль маршрута. Сохраняет результат в состояние, если состояние недопустимо; на клиенте также записывает cookie. |
| `isValidLocale(locale)` | `(locale) => locale is string` | Входит ли `locale` в `validLocales`. |

Cookie живут один год, с `path: '/'` и `sameSite: 'lax'`.

## Пример {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

Плагин-загрузчик модуля читает состояние при запуске, поэтому плагин, который его устанавливает, должен выполняться раньше (`enforce: 'pre'`). Как состояние конкурирует с URL, cookie и `Accept-Language`: [Определение локали](/ru/guide/locale-detection). Полное пошаговое руководство: [Пользовательское определение](/ru/guide/custom-auto-detect).

`setLocale()` не переключает переводы на экране. Чтобы сменить локаль текущей страницы, вызовите [`$switchLocale()`](/ru/api/methods#$switchlocale).
