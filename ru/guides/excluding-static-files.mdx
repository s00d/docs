# Исключение статических файлов из i18n-роутинга

## Обзор

По умолчанию nuxt-i18n-micro автоматически исключает из i18n-роутинга распространённые статические файлы. Однако вы также можете настроить собственные шаблоны исключения, чтобы конкретные пути не обрабатывались системой i18n.

## Встроенные исключения

Модуль автоматически исключает следующие типы файлов и паттерны:

- **Sitemap'ы**: `/sitemap*.xml`, `/sitemap-en.xml` и т. п.
- **SEO-файлы**: `/robots.txt`, `/favicon.ico`
- **PWA-файлы**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Статические ассеты**: Файлы с расширениями `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Внутренние пути Nuxt**: Любой путь, начинающийся с `__` (например, `/__nuxt/`)

## Пользовательские шаблоны исключения

Свои шаблоны исключений задаются через опцию `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Типы шаблонов

### Строковые шаблоны

- **Точное совпадение**: `'/api/health'` — совпадает точно с `/api/health`
- **Совпадение по префиксу**: `'/admin'` — совпадает с `/admin` и `/admin/dashboard`
- **Wildcard'ы**: `'/api/*'` — совпадает с `/api/users`, но не с `/api/users/123`
- **Глубокие wildcard'ы**: `'/admin/**'` — совпадает с `/admin/users` и `/admin/users/123`

### Регулярные выражения

Используйте объекты RegExp для сложных совпадений:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Сценарии использования

### SEO-файлы

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API-маршруты

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Админ-панели

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Статические ассеты

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Как это работает

1. **Server Middleware**: Nitro-middleware запускается первым и проверяет шаблоны исключений
2. **Обработка страниц**: При разрешении страницы исключённые пути пропускаются
3. **Catch-all маршрут**: Fallback-маршрут проверяет исключения перед обработкой
4. **Пререндеринг**: Исключённые пути не попадают в список пререндеренных маршрутов

## Влияние на производительность

- Проверки исключений оптимизированы и выполняются рано в жизненном цикле запроса
- Встроенные шаблоны используют эффективное совпадение по регулярным выражениям
- Пользовательские шаблоны кешируются и переиспользуются
- Минимальные накладные расходы для исключённых путей

## Устранение неполадок

### Статические файлы всё ещё перехватываются

1. **Проверьте синтаксис шаблона**: Убедитесь, что шаблон совпадает с точной структурой пути
2. **Для сложных случаев используйте regex**: У строковых wildcard'ов есть ограничения
3. **Тестируйте шаблоны**: Проверяйте фактический путь запроса в dev-tools браузера
4. **Проверьте порядок**: Убедитесь, что шаблоны исключения заданы до остальной i18n-конфигурации

### Шаблон не работает

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Режим отладки

Включите режим отладки, чтобы увидеть, как обрабатываются исключения:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

В консоли будут логироваться решения об исключении.

## Миграция с обходных решений

Если раньше вы использовали обходы вроде route rules или middleware, теперь их можно заменить на `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Новый подход надёжнее и работает на нескольких уровнях системы маршрутизации.
