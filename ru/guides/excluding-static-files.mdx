# Исключение статических файлов из маршрутизации i18n

## Обзор

По умолчанию nuxt-i18n-micro автоматически исключает распространённые статические файлы из обработки маршрутизации i18n. Однако вы также можете настроить пользовательские шаблоны исключения, чтобы предотвратить обработку определённых путей системой i18n.

## Встроенные исключения

Модуль автоматически исключает следующие типы файлов и шаблоны:

- **Sitemaps**: `/sitemap*.xml`, `/sitemap-en.xml` и т. д.
- **SEO-файлы**: `/robots.txt`, `/favicon.ico`
- **PWA-файлы**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Статические ресурсы**: файлы с расширениями `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Внутренние пути Nuxt**: любой путь, начинающийся с `__` (например, `/__nuxt/`)

## Пользовательские шаблоны исключения

Вы можете определять пользовательские шаблоны исключения с помощью опции `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Типы шаблонов

### Строковые шаблоны

- **Точное совпадение**: `'/api/health'` — совпадает точно с `/api/health`
- **Совпадение по префиксу**: `'/admin'` — совпадает с `/admin` и `/admin/dashboard`
- **Wildcards**: `'/api/*'` — совпадает с `/api/users`, но не с `/api/users/123`
- **Глубокие wildcards**: `'/admin/**'` — совпадает с `/admin/users` и `/admin/users/123`

### Регулярные выражения

Используйте объекты RegExp для сложного сопоставления шаблонов:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Сценарии использования

### SEO-файлы

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API-маршруты

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Административные панели

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Статические ресурсы

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Как это работает

1. **Серверный middleware**: middleware Nitro запускается первым для проверки шаблонов исключения
2. **Обработка страниц**: во время резолюции страниц исключённые пути пропускаются
3. **Catch-all маршрут**: резервный маршрут проверяет исключения перед обработкой
4. **Предварительный рендеринг**: исключённые пути не включаются в предварительно отрендеренные маршруты

## Влияние на производительность

- Проверки исключений оптимизированы и выполняются на ранних этапах жизненного цикла запроса
- Встроенные шаблоны используют эффективное сопоставление с regex
- Пользовательские шаблоны кэшируются и переиспользуются
- Минимальные накладные расходы производительности для исключённых путей

## Устранение неполадок

### Статические файлы всё равно перехватываются

1. **Проверьте синтаксис шаблонов**: убедитесь, что ваши шаблоны точно соответствуют структуре пути
2. **Используйте regex для сложных шаблонов**: строковые wildcards имеют ограничения
3. **Тестируйте шаблоны**: используйте инструменты разработчика браузера для проверки фактического пути запроса
4. **Проверьте порядок**: убедитесь, что шаблоны исключения определены до других настроек i18n

### Шаблон не работает

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Режим отладки

Включите режим отладки, чтобы видеть процесс исключения:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Это будет логировать решения об исключении в консоли.

## Миграция с обходных путей

Если вы использовали обходные пути, такие как route rules или middleware, теперь их можно заменить на `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Новый подход более надёжен и работает на нескольких уровнях системы маршрутизации.
