# Использование переводов в компонентах

Как только модуль установлен и настроен, вы можете отображать переводы, вызывая `$t('your_key')` в шаблонах и скриптах Vue.

## 1. Корневые и постраничные файлы переводов

1. **Корневые** переводы находятся непосредственно в папке `/locales` (например, `/locales/en.json`, `/locales/fr.json`). На этапе сборки они автоматически объединяются с каждым файлом конкретной страницы и становятся доступны на всех страницах.
2. **Постраничные** переводы располагаются в `/locales/pages/...` и повторяют структуру каталога страниц Nuxt:

```text
locales/
├── en.json
├── fr.json
└── pages/
    └── dir1/
        ├── en.json
        └── fr.json

```

## 2. Использование `$t` в шаблоне

В файлах `.vue` можно напрямую использовать `$t` в шаблоне:

```vue
<template>
  <div>
    <!-- Root-level translation (available on all pages) -->
    <p>{{ $t('test_key') }}</p>
    <!-- Displays: Hello World! -->

    <!-- Page-specific translation (if this page is /dir1) -->
    <p>{{ $t('local_key') }}</p>
    <!-- Displays: This is a page-specific translation for /dir1. -->

    <!-- Nested key -->
    <p>{{ $t('nested.key.deeper') }}</p>
    <!-- Displays: Nested translation here -->

    <!-- Placeholder usage -->
    <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
    <!-- Displays: Hello, Alice! -->
  </div>
</template>

<script setup lang="ts">
// No need to import anything from 'nuxt-i18n-micro'.
// The plugin automatically provides `useI18n` and `$t`.
const { $t } = useI18n()

// You can now use $t in your script, for example:
console.log($t('test_key')) // "Hello World!"
</script>
```

<Tip>
`$t` может вернуть **объект**, если ключ указывает на вложенный JSON-узел (например, `$t('header')` → `\{ title: "Hi" \}`). В шаблонах это отрендерится как `[object Object]`. Используйте `$ts`, когда нужна гарантированная строка, или укажите более конкретный ключ, например `$t('header.title')`. Подробности см. в [Справочнике API — $t vs $ts](/api/methods#t).
</Tip>

## 3. Переключение текущей локали

Чтобы менять язык в приложении, получите `$locale` из `useI18n()` и присвойте ему новый код:

```vue
<template>
  <div>
    <button @click="$switchLocale('en')">English</button>
    <button @click="$switchLocale('fr')">Français</button>
  </div>
</template>

<script setup lang="ts">
// The plugin auto-injects these references
const { $t, $switchLocale } = useI18n()
</script>
```

## 4. Вложенные ключи и плейсхолдеры

- **Вложенные ключи** используют точечную нотацию, например `nested.key.deeper`.
- **Плейсхолдеры** позволяют подставлять динамические значения:
  ```json
  { "greeting": "Hello, {name}!" }
  ```
  ```vue
  <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
  <!-- Displays: Hello, Alice! -->
  ```

## 5. Советы и лучшие практики

- **Конфликтующие ключи**: Если постраничный файл содержит тот же ключ, что и корневой, приоритет получает постраничная версия (корневые переводы подмешиваются как база на этапе сборки).
- **Отключение постраничных файлов**: Если вы не хотите использовать постраничные переводы, установите `disablePageLocales: true` в конфигурации Nuxt. Тогда будут использоваться только файлы `/locales/*.json`.
- **Без прямых импортов**: Не нужно писать `import \{ useI18n \} from 'nuxt-i18n-micro'`. Автоинъекция модуля делает это за вас.

Вот и всё! С этими шагами вы быстро **начнёте получать переводы** из корневых или постраничных JSON-файлов и **отображать их** в вашем приложении Nuxt через `$t`.

## Дополнительные материалы

Чтобы изучить более продвинутые возможности, обязательно посмотрите:

1. **Компонент `<i18n-t>`**  
   Компонент `<i18n-t>` — мощная альтернатива `$t`, особенно полезная в ситуациях с вложенными элементами, продвинутым использованием плейсхолдеров и более сложными структурами переводов.

- **Документация**: [i18n-t](/api/components/i18n-t)

2. **Композабл `useI18n`**  
   Композабл `useI18n` предоставляет полный набор функций и реактивных свойств для управления переводами, переключения локалей, форматирования и не только.

- **Документация**: [useI18n](/api/composables/use-i18n)
