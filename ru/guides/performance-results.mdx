### Описание

Сравнивается **plain Nuxt** (baseline без модуля i18n), **i18n-micro** и **`@nuxtjs/i18n` v10.6** на одном и том же профиле словарей.

Фокус: время сборки, пиковый RSS, деплоящийся объём **кода vs переводов vs итога**, а также поведение сервера под Artillery + Autocannon.

### Заметки по методологии

- Метрики — **среднее по 3 последовательным запускам на фикстуру** (фикстура A ×3, затем B ×3, затем C ×3 — не чередуя).
- **Переводы** включают JSON локалей под `locales/` / `_locales/` / `translations/`, всё под `chunks/raw/` и соответствующие чанки локалей. Более старые отчёты, показывавшие у `@nuxtjs/i18n` «translations: 0 B» и огромную колонку «code», засчитывали чанки сообщений как код приложения.
- **plain-nuxt** отдаёт тот же объём листовых данных, что и статический `public/translations` JSON (а не статические JS-импорты). Под Artillery этот baseline упирается в I/O; это не «оверхед i18n», а стоимость выгрузки крупного JSON на каждый запрос.

### Запуски

Все метрики ниже — **среднее по 3 запускам**.

### Профиль фикстуры

| Параметр | Значение |
|------|-------|
| Локали | **4** (`en`, `de`, `ru`, `fr`) |
| Страницы | **2** (`index`, `page`) |
| Дерево index | глубина **5**, ветвление **7** → **16 807** листовых ключей на локаль |
| Второстепенные страницы | глубина **5**, ветвление **6** → **7 776** листовых ключей на страницу на локаль |
| Цель | Дефолтный профиль CLI (`--locales 4 --keys 10000`); увеличивайте параметры для регрессионных нагрузок |

Словари берутся из `test/fixtures/perf-shared/runtime.json` (пишется CLI), поэтому все три фикстуры выровнены.

## Заметки

- Общий профиль: 4 локали × 2 страницы × ~16.8k index-листьев.
- Artillery: 6s разогрева @6 VU/s + 60s основного @60 VU/s. Autocannon: 10 соединений × 10s.
- Перезапуск: `pnpm test:performance` или `pnpm -C scripts cli performance --locales N --keys K --only all|micro|i18n|plain --runs N`.
