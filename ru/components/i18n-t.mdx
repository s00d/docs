`<i18n-t>` рендерит один перевод в элемент. Используйте его, когда внутри перевода нужны компоненты (ссылка в предложении), форма множественного числа или отформатированное число или дата. Он разрешает ключ для текущего маршрута, как `$t`.

## Свойства {#props}

| Свойство | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `keypath` **\*** | `string` | — | Ключ перевода для рендеринга. |
| `plural` | `number \| string \| null` | — | Количество, выбирающее форму множественного числа. Задайте его, чтобы использовать `$tc` вместо `$t`. `null` означает «не задано». |
| `tag` | `string` | `'span'` | Элемент для рендеринга. |
| `params` | `Record<string, string \| number \| boolean>` | — | Значения интерполяции, подставляемые в перевод. |
| `defaultValue` | `string` | `''` | Рендерится вместо компонента, когда `hideIfEmpty` подавляет пустой перевод. |
| `html` | `boolean` | `false` | Рендерить перевод как HTML, а не как текст. Только для переводов, которые вы контролируете: `params` экранируются, перевод — нет. |
| `hideIfEmpty` | `boolean` | `false` | Ничего не рендерить, если перевод разрешается в пустую строку. |
| `customPluralRule` | `PluralFunc` | `null` | Правило множественного числа только для этого элемента, переопределяющее настроенное. Его ответ используется как есть; `null` рендерит пустоту. |
| `number` | `number \| string \| null` | — | Форматирует значение через `$tn` и передаёт его в перевод как `{number}` вместе с `params`. |
| `date` | `Date \| string \| number \| null` | — | Форматирует значение через `$td` и передаёт его в перевод как `{date}` вместе с `params`. |
| `relativeDate` | `Date \| string \| number \| null` | — | Форматирует значение через `$tdr` и передаёт его в перевод как `{relativeDate}` вместе с `params`. |

**\*** обязательно.

## Правила рендеринга {#rendering-rules}

Результат определяет первый подходящий случай:

1. `number` — перевод с `{ ...params, number: $tn(number) }`.
2. `date` — перевод с `{ ...params, date: $td(date) }`.
3. `relativeDate` — перевод с `{ ...params, relativeDate: $tdr(relativeDate) }`.
4. `plural` — форма, которую выбирает `$tc`, включая [маркер `=0 `](/ru/api/methods#$tc), с `{ ...params, count }`; или `customPluralRule(keypath, count, params, locale, t)`, если задано: оно читает исходное значение вместе с маркером, а его ответ используется как есть, причём `null` означает пустоту.
5. Иначе — перевод с `params`.

`null` считается незаданным значением. Во всех случаях:

- `defaultValue` подставляется вместо отсутствующего ключа в каждой ветке.
- `hideIfEmpty` рендерит `defaultValue` вместо пустого результата.
- `html` рендерит результат как HTML. `params` экранируются, перевод — нет; слоты игнорируются.
- Слот `default` получает `{ translation }`, а именованные слоты игнорируются.
- Иначе каждый именованный слот заменяет каждый плейсхолдер `{name}` раньше, чем параметр с тем же именем. Значение параметра, похожее на плейсхолдер, остаётся текстом.

Вывод `date` и `relativeDate` имеет атрибут `data-allow-mismatch="text"`, потому что часовой пояс и часы сервера не совпадают с браузерными. Задайте [`timeZone`](/ru/api/module-options#timezone), чтобы в обоих случаях рендерилась одна календарная дата; `relativeDate` зависит от часов, поэтому всё равно может отличаться.

## Пример {#example}

```json
{
  "terms": "I accept the {link}.",
  "termsLink": "terms of use",
  "items": "no items | one item | {count} items"
}
```

```vue
<template>
  <i18n-t keypath="terms" tag="p">
    <template #link>
      <NuxtLink :to="$localePath('/terms')">{{ $t('termsLink') }}</NuxtLink>
    </template>
  </i18n-t>

  <i18n-t keypath="items" :plural="cart.length" />
</template>
```

`html` устанавливает `innerHTML`: используйте его только для переводов, которые вы контролируете. `params` экранируются, поэтому пользовательские данные там безопасны, как и ключ, для которого перевод не найден.
