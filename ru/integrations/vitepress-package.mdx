`@i18n-micro/vitepress` добавляет на сайт VitePress словари, работающие во время выполнения: `$t` и `<I18nT>` внутри markdown, хелперы путей и SEO-теги, на основе [`@i18n-micro/vue`](/ru/integrations/vue-package). Используйте его, когда одни и те же строки интерфейса встречаются на многих страницах и вы не хотите дублировать их для каждой локали. Локаль следует собственным локалям путей VitePress (`/`, `/fr/`).

## Когда это использовать {#when-to-use-it}

| Потребность | Решение |
|------|----------|
| Дублирование `.md`, префиксы URL | `locales` VitePress |
| `$t` во время выполнения / компоненты / синхронизация путей / SEO в head | `@i18n-micro/vitepress` |
| Подписи элементов темы по умолчанию (`docFooter`, интерфейс поиска) | Собственный `themeConfig` для каждой локали |

<Tip>

**Песочница** — [`packages/vitepress/playground`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/vitepress/playground) — `pnpm -C packages/vitepress/playground dev`

</Tip>

## Установка {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vitepress
```

```bash npm
npm install @i18n-micro/vitepress
```

```bash yarn
yarn add @i18n-micro/vitepress
```

</CodeGroup>

Peer-зависимости: `vitepress` `>=1.0.0 || >=2.0.0-alpha.0`, `vue` `^3.3.0`. Node-скрипты используют `@i18n-micro/node`, который устанавливается вместе с пакетом и реэкспортируется через `/node`. Опубликованным типам нужен Vue 3.5.5 или новее при `skipLibCheck: false`; при `skipLibCheck: true`, обычной настройке шаблона, компилируются и более старые версии.

## Настройка {#setup}

```
locales/en.json
locales/fr.json
locales/pages/guide/demo/en.json   # optional page-scoped
locales/pages/guide/demo/fr.json
```

Файлы страниц сопоставляются с именами маршрутов так же, как в Nuxt/Astro (`guide/demo` → `guide-demo`).

### 1. Конфигурация — `@i18n-micro/vitepress/config` {#1-config-—-@i18n-micro/vitepress/config}

```ts
// .vitepress/config.mts
import { defineConfig } from 'vitepress'
import { withI18n, buildVitePressLocales } from '@i18n-micro/vitepress/config'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English', og: 'en_US' },
  { code: 'fr', iso: 'fr-FR', displayName: 'Français', og: 'fr_FR' },
]
const defaultLocale = 'en'

export default defineConfig(
  withI18n(
    {
      locales: buildVitePressLocales(locales, defaultLocale),
      // themeConfig.i18nRouting is injected automatically
    },
    {
      locale: defaultLocale,
      defaultLocale,
      locales,
      translationDir: 'locales',
      metaBaseUrl: 'https://example.com', // optional SEO head
    },
  ),
)
```

### 2. Тема — `@i18n-micro/vitepress/theme` {#2-theme-—-@i18n-micro/vitepress/theme}

```ts
// .vitepress/theme/index.ts
import DefaultTheme from 'vitepress/theme'
import { defineI18nTheme } from '@i18n-micro/vitepress/theme'

export default defineI18nTheme(DefaultTheme)
```

Начальная локаль берётся из текущего пути до установки (без мелькания локали по умолчанию на `/fr/…`).

### Продвинутый вариант: ручной `createI18n` {#advanced-manual-createi18n}

Одна фабрика для клиента: плагин Vue + методы путей + `enhanceApp` (без отдельных экспортов хелперов роутера).

```ts
import { createI18n, messagesFromGlob } from '@i18n-micro/vitepress'

const i18n = createI18n({
  locale: 'en',
  defaultLocale: 'en',
  locales: [{ code: 'en' }, { code: 'fr' }],
  messages: messagesFromGlob(import.meta.glob('../../locales/*.json', { eager: true })),
})

i18n.localizePath('/guide', 'fr')
// in theme enhanceApp:
i18n.enhanceApp({ app, router })
```

### Node-скрипты — `@i18n-micro/vitepress/node` {#node-scripts-—-@i18n-micro/vitepress/node}

Использует `createI18n` / `loadTranslations` из `@i18n-micro/node` (как Astro и CLI), а затем подключает методы путей VitePress через `BaseI18n.extend`:

```ts
import { createI18n } from '@i18n-micro/vitepress/node'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  translationDir: './locales',
  locales: ['en', 'fr'],
  defaultLocale: 'en',
})
await i18n.loadTranslations()
i18n.t('cta.readMore')
i18n.localizePath('/guide', 'fr')
```

Обычный Node без путей: `import { createI18n } from '@i18n-micro/node'`.

## Переводы на странице {#in-page-translations}

Каждый markdown-файл VitePress является SFC Vue.

### Глобальные компоненты и `$t` (рекомендуется в markdown) {#global-components-and-$t-recommended-in-markdown}

`createI18n` / `defineI18nTheme` устанавливают `@i18n-micro/vue`, который регистрирует `I18nT` / `I18nLink` / `I18nGroup` / `I18nSwitcher` и `$t` / `$tc` / `$ts`.

```md
{{ $t('cta.readMore') }}

<I18nT keypath="greeting" :params="{ name: 'VitePress' }" />

<I18nLink to="/guide/demo">Demo</I18nLink>
```

### `useI18n` в `<script setup>` {#usei18n-in-<script-setup>}

```md
<script setup>
import { useI18n } from '@i18n-micro/vitepress'
const { t, tc, locale, localePath, switchLocale } = useI18n()
</script>

# {{ t('section.title') }}
```

## Выпадающий список языков {#language-dropdown}

Когда в `locales` больше одного элемента, VitePress показывает собственное меню языков (`VPNavBarTranslations`). `withI18n` настраивает `themeConfig.i18nRouting`, чтобы значок глобуса соответствовал `<I18nSwitcher>` / хелперам путей.

Используйте `<I18nSwitcher>` только в пользовательских макетах, а не рядом со стандартным глобусом.

## Замечания по SSR {#ssr-notes}

- Локаль при пререндеринге берётся из пути URL, а не из cookie.
- Код темы не должен обращаться к `window` во время импорта.
- Импортируйте `defineI18nTheme` из `/theme`, чтобы при вычислении конфигурации в Node никогда не загружались `virtual:i18n-micro/*`.

## Поверхность API {#api-surface}

| Экспорт | Назначение |
|--------|------|
| `createI18n` (`.`) | Клиент: плагин Vue + методы путей + `enhanceApp` |
| `getLocaleFromPath` / `stripSiteBase` / `routeNameFromPath` (`.`) | Ручная синхронизация локали при `syncWithVitePress: false` |
| `createI18n` (`/node`) | Node: `@i18n-micro/node` + методы путей |
| `defineI18nTheme` (`/theme`) | Тема без шаблонного кода |
| `withI18n` (`/config`) | Конфигурация + виртуальные модули + опциональное SEO |
| `buildVitePressLocales` (`/config`) | Построение `locales` VitePress из `Locale[]` |
| `buildVitePressLocaleHead` (`/config`) | Ручное SEO в head (также используется `metaBaseUrl`) |
| `messagesFromGlob` | Опциональное преобразование glob → карта сообщений для `createI18n` |
| `useI18n` / `I18nT` / … | Реэкспорт из `@i18n-micro/vue` |
| `BaseI18n.extend` (`@i18n-micro/core`) | Подключение пользовательских методов к любому экземпляру i18n |

## Сайты в стиле OpenAPI (зафиксированные интеграционные сценарии) {#openapi-style-sites-integration-locks}

Набор регрессионных тестов: `packages/vitepress/tests/integration-openapi.test.ts` (глубокие пути, `base=/openapi_docs/`, отключённая синхронизация + ручная локаль, Node-генераторы, SEO).

| Сценарий | Что делать |
|---------|---------|
| Глубокие страницы `/…/{spec}/{op}`, только корневой JSON интерфейса | Предпочитайте `syncWithVitePress: true` по умолчанию (сохраняет `setRoute('index')`, если нет словаря страницы) **или** `syncWithVitePress: false` + `getLocaleFromPath` |
| Никогда не вызывайте `setRoute(deepName)` без словарей страниц | Корневые ключи интерфейса пропадают до вызова `setRoute('index')` |
| Генераторы / `getTranslation` | `createI18n` из `/node` + `await loadTranslations()` + `i18n.t(key)` (задайте `i18n.locale`) |
| Пользовательский canonical в `transformPageData` | Передайте `meta: false` в `withI18n` (чтобы избежать дублирования тегов) |
| SEO пакета с базовым путём сайта | `metaBaseUrl` + `base` VitePress → абсолютные URL включают base |
| Переименования по сравнению со старыми сборками пакета | `withI18nMicro` → `withI18n`, `createVitePressI18n` → `createI18n`, `loadMessages` → `createI18n` из node |
