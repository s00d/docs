`@i18n-micro/solid` даёт приложениям SolidJS экземпляр i18n на сигналах, провайдер, `useI18n()` и четыре компонента. Используйте его в приложении Solid, собранном без Nuxt. Вызовы `t()` внутри JSX или эффектов отслеживают локаль, маршрут и словари; общая модель описана в разделе [Фреймворки](/ru/integrations/overview).

## Установка {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer-зависимости: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (необязательно, только для `@i18n-micro/solid/router`). Solid 2 пока не поддерживается.

## Настройка {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` принимает `i18n`, `locales`, `defaultLocale` и `routingStrategy`; опущенное свойство сохраняет значение внешнего провайдера, включая экземпляр. `getLocaleName()` и `<I18nSwitcher>` читают `locales`; без них им нечего выводить. Опции описаны в разделе [экземпляр](/ru/integrations/overview#the-instance). Экземпляр — это экземпляр [runtime](/ru/integrations/runtime-package) с одним сигналом поверх его хранилища.

## Перевод {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Вызывайте методы внутри JSX или эффекта, чтобы Solid их отслеживал, — `localePath` и `getLocale` тоже; значение, прочитанное один раз в теле компонента, не обновляется. На экземпляре отслеживайте через `i18n.locale` и `i18n.currentRoute`: `i18n.getLocale()` остаётся неотслеживаемым, потому что его читают операции записи. Чтение локали реагирует только на локаль, поэтому эффект, который читает её и загружает словарь, выполняется один раз. Не деструктурируйте props и не храните результаты `t('key')` в обычных переменных.

`useI18n()` возвращает `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (аксессор: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` и `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Переключение локали {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Переключение ничего не загружает; сначала добавьте словарь локали.

`<I18nGroup>` передаёт `t` с префиксом дочерней функции. `<I18nT>` и `t()` внутри него префикс не получают:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Маршрутизация {#routing}

Адаптер для `@solidjs/router` находится в отдельном подпути, чтобы основная точка входа никогда не импортировала роутер. Вызывайте его внутри роутера, обычно в `root` роутера, где работают `useNavigate` и `useLocation`:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

Адаптер добавляет префикс ко всем локалям, кроме локали по умолчанию (`/about`, `/de/about`), и рендерит `<I18nLink>` как `<A>` роутера. `getCurrentPath` читает реактивное местоположение роутера, поэтому активные ссылки и переключатель следуют за ним; пользовательская стратегия добивается того же, читая там сигнал. Обратите внимание на порядок аргументов: `(locales, defaultLocale, navigate, location)`. Для других роутеров напишите адаптер с `getCurrentPath`, `push` и `replace` (все обязательны) — см. [Адаптер роутера](/ru/integrations/overview#router-adapter).

## SSR {#ssr}

Для серверного рендеринга собирайте с `vite-plugin-solid`: условие экспорта `solid` пакета передаёт ему исходники, чтобы они компилировались для сервера. Предсобранный `dist` предназначен только для браузера. У экземпляра нет `destroy()`; создавайте один на приложение или один на запрос на сервере и позвольте сборщику мусора его удалить.
