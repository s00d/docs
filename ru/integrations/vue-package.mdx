`@i18n-micro/vue` — это плагин Vue 3 с ядром перевода Nuxt I18n Micro: реактивный `t()`, глобальный `$t`, четыре компонента и необязательный адаптер vue-router. Используйте его в приложении Vue на Vite или с SSR, которое собрано не на Nuxt. Модель экземпляра, контракт роутера и пропсы компонентов общие с другими пакетами и описаны в разделе [Фреймворки](/ru/integrations/overview).

## Установка {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vue
```

```bash npm
npm install @i18n-micro/vue
```

```bash yarn
yarn add @i18n-micro/vue
```

</CodeGroup>

Peer-зависимости: `vue` `^3.3.0`; `vue-router` `^4.5.1 || ^5.0.0` (необязательно, только для `@i18n-micro/vue/router`). Опубликованным типам нужен Vue 3.5.5 или новее при `skipLibCheck: false`; при `skipLibCheck: true`, обычной настройке шаблонов, компилируются и более старые версии.

## Настройка {#setup}

```ts
// src/main.ts
import { createApp } from 'vue'
import { createI18n } from '@i18n-micro/vue'
import App from './App.vue'
import en from './locales/en.json'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales: [
    { code: 'en', iso: 'en-US', displayName: 'English' },
    { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
  ],
  defaultLocale: 'en',
})

createApp(App).use(i18n).mount('#app')
```

`locales` и `defaultLocale` обязательны для `useI18n()`: без них он выбрасывает `I18nLocalesKey not provided`. Передайте их в `createI18n` (как выше), в `useI18n({ locales, defaultLocale })` или через `app.provide(I18nLocalesKey, …)` и `app.provide(I18nDefaultLocaleKey, …)`.

Плагин глобально регистрирует `I18nT`, `I18nLink`, `I18nGroup` и `I18nSwitcher` и добавляет в шаблоны `$t`, `$ts`, `$tc`, `$tn`, `$td`, `$tdr`, `$has` и `$i18n`. Вне компонентов экземпляр доступен как `i18n.global`. Остальные опции описаны в разделе [Экземпляр](/ru/integrations/overview#the-instance); `routeMessages` во Vue недоступен, используйте `addRouteTranslations`.

## Перевод {#translate}

```vue
<script setup lang="ts">
import { useI18n } from '@i18n-micro/vue'

const { t, tc, tn } = useI18n()
</script>

<template>
  <h1>{{ t('greeting', { name: 'Ada' }) }}</h1>
  <!-- Hello, Ada! -->
  <p>{{ tc('apples', 3) }}</p>
  <!-- 3 apples -->
  <p>{{ $t('nav.home') }} · {{ tn(1234.5) }}</p>
</template>
```

`useI18n()` возвращает методы перевода (`t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`), `locale` (записываемый computed), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `localePath`, `localeRoute`, `switchLocale`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `mergeTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` и `instance`.

Дополнительные словари можно загружать в любой момент; каждый компонент, который их читает, перерисовывается:

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Переключение локали {#switch-locale}

```ts
const { locale, switchLocale } = useI18n()

locale.value = 'de' // only the locale
switchLocale('de') // the locale, then router.push to the localized current path
```

Загрузите словарь локали до или после переключения; само переключение ничего не запрашивает.

`<I18nGroup>` передаёт в свой слот `t` с префиксом. Ключи внутри `<I18nT>` или в обычном `t()` префикс не получают:

```vue
<I18nGroup prefix="profile" v-slot="{ t }">
  <h2>{{ t('title') }}</h2>
  <!-- profile.title -->
</I18nGroup>
```

## Маршрутизация {#routing}

Адаптер vue-router находится в подпути, поэтому основная точка входа никогда не импортирует `vue-router`:

```ts
// src/main.ts
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import { createI18n } from '@i18n-micro/vue'
import { createVueRouterAdapter } from '@i18n-micro/vue/router'
import App from './App.vue'
import Home from './pages/Home.vue'
import About from './pages/About.vue'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/:locale(de)?', component: Home },
    { path: '/:locale(de)?/about', component: About },
  ],
})

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales,
  defaultLocale: 'en',
  routingStrategy: createVueRouterAdapter(router, locales, 'en'),
})

createApp(App).use(router).use(i18n).mount('#app')
```

`createVueRouterAdapter(router, locales, defaultLocale)` добавляет префикс для каждой локали, кроме локали по умолчанию (`/about`, `/de/about`), и рендерит `<I18nLink>` как `RouterLink`. Считывайте локаль из маршрута самостоятельно, например в `router.beforeEach`, и устанавливайте `i18n.global.locale.value`. Адаптер также можно подключить позже через `i18n.setRoutingStrategy(adapter)`; о пользовательском адаптере см. [Адаптер роутера](/ru/integrations/overview#router-adapter).

## SSR {#ssr}

- Создавайте роутер, экземпляр i18n и приложение внутри функции рендеринга для каждого запроса. Один общий экземпляр передавал бы локаль одного посетителя другому.
- Используйте `createMemoryHistory()` на сервере, берите локаль из URL и загружайте её словарь (и словарь резервной локали) до `renderToString`.
- Передавайте локаль клиенту (например, в скрипте `window.__STATE__`) и создавайте клиентский экземпляр с той же `locale`, чтобы гидратация совпадала.
- `<I18nSwitcher>` читает `window.location` только когда выпадающий список открыт, поэтому он рендерится на сервере.

В `packages/vue/playground` есть полная пара `entry-server.ts` / `entry-client.ts`.

## SEO-заголовки {#seo-head}

`useLocaleHead(options)` формирует теги `lang`/`dir`, canonical, `hreflang` и `og:locale` на основе локалей и адаптера роутера. Вызывайте `updateMeta()` при смене маршрута и передавайте `metaObject` своему менеджеру head:

```ts
import { watch } from 'vue'
import { useRoute } from 'vue-router'
import { useHead } from '@unhead/vue'
import { useLocaleHead } from '@i18n-micro/vue'

const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
watch(() => route.fullPath, () => updateMeta(), { immediate: true })
useHead(metaObject)
```

Опции: `baseUrl` (строка или функция), `addDirAttribute` (по умолчанию `true`), `addSeoAttributes` (по умолчанию `true`), `identifierAttribute` (по умолчанию `'id'`), `hreflangBaseLanguage` (по умолчанию `false`). Локали с `disabled: true` или `seo: false` не получают альтернативной ссылки.

## API {#api}

| Экспорт | Точка входа |
| --- | --- |
| `createI18n`, `useI18n`, `useLocaleHead` | `@i18n-micro/vue` |
| `I18nT`, `I18nLink`, `I18nSwitcher`, `I18nGroup` | `@i18n-micro/vue` |
| `VueI18n` (класс экземпляра), `I18nInjectionKey`, `I18nLocalesKey`, `I18nDefaultLocaleKey` | `@i18n-micro/vue` |
| `defaultPlural`, `FormatService`, `interpolate` | `@i18n-micro/vue` |
| Типы: `I18nRoutingStrategy`, `Locale`, `Translations`, `PluralFunc`, `Params`, `Getter`, `CleanTranslation`, `LocaleCode`, `VueI18nOptions`, `UseI18nOptions`, `UseLocaleHeadOptions`, `I18nPlugin` | `@i18n-micro/vue` |
| `createVueRouterAdapter` | `@i18n-micro/vue/router` |

`TranslationKey` не реэкспортируется из `@i18n-micro/vue`; импортируйте его из `@i18n-micro/types`. Полные сигнатуры: [справочник пакета](/ru/api/packages/vue).
