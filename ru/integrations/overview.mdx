# Интеграции

Пакеты `@i18n-micro` — это лёгкие, специфичные для фреймворков версии Nuxt I18n Micro, предназначенные для интеграции в различные фреймворки и окружения. Они предоставляют базовую функциональность интернационализации с минимальным следом, концентрируясь на основных возможностях перевода и базовых компонентах.

## Обзор

Эти интеграционные пакеты — **миниатюрные версии** полного модуля Nuxt I18n Micro, содержащие только необходимую функциональность для интернационализации:

- **Основные возможности перевода** — базовые методы перевода, множественные формы и форматирование
- **Ключевые компоненты** — небольшой набор UI-компонентов для типовых задач i18n
- **Паттерн router-адаптера** — гибкая интеграция с роутингом через абстракцию адаптера
- **Поддержка TypeScript** — полные типы для типобезопасной разработки

В отличие от полного модуля Nuxt, эти пакеты:

- Не включают роутинг, специфичный для фреймворка
- Требуют реализации router-адаптера для функций маршрутизации
- Фокусируются на функционале перевода, а не на интеграции с фреймворком
- По возможности спроектированы легковесными и не привязанными к конкретному фреймворку

## Основные компоненты

Все пакеты для фреймворков содержат следующие ключевые компоненты:

### `<I18nT>`

Компонент перевода, отрисовывающий переведённый текст с поддержкой:

- **Интерполяции параметров** — подстановка плейсхолдеров динамическими значениями
- **Множественных форм** — автоматический выбор формы по количеству
- **Форматирования чисел** — форматирование по локали
- **Форматирования дат** — форматирование дат и относительного времени
- **Рендеринга HTML** — опциональный рендеринг HTML-содержимого
- **Значений по умолчанию** — текст-fallback, если перевод отсутствует

**Пример:**

```vue
<!-- Vue -->
<I18nT keypath="greeting" :params="{ name: 'World' }" />
```

```tsx
// React
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```tsx
// Solid
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```astro
<!-- Astro -->
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

### `<I18nLink>`

Локализованная ссылка, автоматически обрабатывающая префиксы локали в URL. Возможности:

- **Автоматическая локализация путей** — добавляет/удаляет префиксы локали в зависимости от стратегии роутинга
- **Определение активного состояния** — подсвечивает текущий маршрут
- **Поддержка внешних ссылок** — автоматически распознаёт и обрабатывает внешние URL
- **Интеграция с роутером** — использует link-компонент router-адаптера, когда он доступен
- **Собственная стилизация** — поддерживает active- и hover-состояния

**Пример:**

```vue
<!-- Vue -->
<I18nLink to="/about" active-class="active">
  About Us
</I18nLink>
```

```tsx
// React
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```tsx
// Solid
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```astro
<!-- Astro -->
<I18nLink href="/about" class="nav-link">
  About Us
</I18nLink>
```

### `<I18nSwitcher>`

Компонент переключения языков, предоставляющий dropdown или список для смены локали. Возможности:

- **Автоматический список локалей** — генерирует пункты из сконфигурированных локалей
- **Подсветка текущей локали** — визуально отмечает активный язык
- **Пользовательские подписи** — поддержка своих отображаемых имён для каждой локали
- **Интеграция с роутером** — автоматически переходит на локализованные пути
- **Доступность** — корректные ARIA-атрибуты и клавиатурная навигация

**Пример:**

```vue
<!-- Vue -->
<I18nSwitcher />
```

```tsx
// React
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```tsx
// Solid
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```astro
<!-- Astro -->
<I18nSwitcher />
```

### `<I18nGroup>`

Компонент для группировки переводов с общим префиксом, удобный для организации переводов по странице или функциональности. Возможности:

- **Скоуп префикса** — автоматически добавляет префикс ко всем ключам переводов внутри группы
- **Вложенные группы** — поддержка вложенных групп переводов
- **Чистая организация** — помогает поддерживать упорядоченные структуры переводов

**Пример:**

```vue
<!-- Vue -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

```tsx
// React
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```tsx
// Solid
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```astro
<!-- Astro -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

## Общие опции `createI18n` \{#create-i18n-options\}

Каждый пакет создаётся одинаково — отличается только имя типа опций, названного по фреймворку (`ReactI18nOptions`, `SolidI18nOptions` и так далее). Сами опции идентичны:

| Свойство         | Тип                                                        | Обязательно | По умолчанию      | Описание                                    |
| ---------------- | ---------------------------------------------------------- | -------- | ---------------- | ---------------------------------------------- |
| `locale`         | `string`                                                   | ✅       | -                | Код текущей локали (например, `'en'`)          |
| `fallbackLocale` | `string`                                                   | ❌       | Как у `locale`    | Fallback-локаль при отсутствии перевода         |
| `messages`       | `Record<string, Translations>`                             | ❌       | `\{\}`             | Начальные сообщения переводов                   |
| `plural`         | `PluralFunc`                                               | ❌       | `defaultPlural`  | Пользовательская функция множественного числа   |
| `missingWarn`    | `boolean`                                                  | ❌       | `true`           | Показывать в консоли предупреждения о пропущенных переводах |
| `missingHandler` | `(locale: string, key: string, routeName: string) => void` | ❌       | -                | Собственный обработчик пропущенных переводов    |

Всё, что за пределами этого списка, — специфично для фреймворка и описано на странице соответствующего пакета.

## Абстракция router-адаптера

Все пакеты используют **паттерн router-адаптера**, чтобы отвязать функциональность i18n от конкретных реализаций роутера. Такой подход даёт:

- **Гибкость** — использовать любой роутер или не использовать никакой
- **Независимость от фреймворка** — оставлять логику маршрутизации в приложении, а не в пакете i18n
- **Легковесное ядро** — пакет i18n остаётся небольшим и сфокусированным

### Реализация router-адаптера

Чтобы задействовать функции маршрутизации, реализуйте интерфейс `I18nRoutingStrategy`:

```typescript
interface I18nRoutingStrategy {
  getCurrentPath: () => string
  linkComponent?: Component
  push: (target: { path: string }) => void
  replace: (target: { path: string }) => void
  resolvePath?: (to: string | { path?: string }, locale: string) => string | { path?: string }
  getRoute?: () => { fullPath: string; query: Record<string, unknown> }
}
```

Документация каждого пакета содержит полные примеры реализации адаптеров для популярных роутеров:

- **Vue**: пример адаптера для Vue Router
- **React**: пример адаптера для React Router
- **Solid**: пример адаптера для Solid Router
- **Astro**: пример адаптера для файловой маршрутизации

## Основные возможности

Все пакеты имеют общий набор возможностей:

### Методы перевода

- `t()` — базовый перевод с интерполяцией параметров
- `ts()` — перевод, всегда возвращающий строку
- `tc()` — перевод с учётом множественных форм
- `tn()` — форматирование чисел
- `td()` — форматирование дат
- `tdr()` — форматирование относительного времени
- `has()` — проверка наличия ключа перевода

### Управление локалью

- **Переключение локали** — программная смена текущей локали
- **Fallback-локаль** — автоматический откат при отсутствии перевода
- **Переводы для конкретных маршрутов** — организация переводов на уровне страниц
- **Кэширование переводов** — умное кэширование ради производительности

### Поддержка TypeScript

Все пакеты предоставляют:

- Полные определения TypeScript
- Типобезопасные ключи переводов (с генератором типов)
- Поддержку IntelliSense в IDE
- Проверку ошибок на этапе компиляции

1. **Выберите пакет** — Подберите пакет под ваш фреймворк.

5. **Начните переводить** — Используйте компоненты и методы для добавления переводов.
