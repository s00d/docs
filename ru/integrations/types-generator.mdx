# 🔧 Генератор типов (`@i18n-micro/types-generator`)

Пакет `@i18n-micro/types-generator` обеспечивает автоматическую генерацию TypeScript-типов для ключей переводов. Он анализирует ваши JSON-файлы переводов и создаёт строгие типы, включая полную безопасность типов и автокомплит для ключей.

## 📖 Обзор

`@i18n-micro/types-generator` — опциональная dev-зависимость, которая улучшает разработку:

- 🔍 **Автоматическая генерация типов** — сканирует JSON-файлы переводов и создаёт TypeScript-типы.
- ✅ **Безопасность типов** — предотвращает опечатки и невалидные ключи ещё на этапе компиляции.
- 🎯 **Автокомплит** — полное автодополнение ключей в IDE.
- 🔄 **Hot Reload** — автоматически перегенерирует типы при изменении файлов переводов.
- 🚀 **Нулевые накладные расходы в рантайме** — типы только на этапе компиляции, размер бандла не растёт.

## 🎯 Быстрый старт

### Для проектов Nuxt

Добавьте модуль в `nuxt.config.ts`:

```typescript
import { defineNuxtConfig } from 'nuxt/config'

export default defineNuxtConfig({
  modules: [
    'nuxt-i18n-micro',
    '@i18n-micro/types-generator/nuxt', // Add types generator
  ],
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    translationDir: 'locales', // Path to your translation files
  },
})
```

Генератор автоматически:

- Просканирует все JSON-файлы в каталоге `locales`.
- Сгенерирует типы в `.nuxt/i18n-micro.d.ts`.
- Будет следить за изменениями и перегенерировать типы автоматически.

### Для проектов Vue/Vite

Добавьте плагин в `vite.config.ts`:

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { I18nTypesPlugin } from '@i18n-micro/types-generator'

export default defineConfig({
  plugins: [
    vue(),
    I18nTypesPlugin({
      srcDir: 'src',
      translationDir: 'locales',
      outputFile: 'src/i18n-types.d.ts', // Optional: custom output path
    }),
  ],
})
```

Не забудьте включить сгенерированный файл в `tsconfig.json`:

```json
{
  "include": ["src/**/*", "src/i18n-types.d.ts"]
}
```

## 📁 Структура файлов переводов

Генератор поддерживает плоскую и вложенную структуру переводов:

```
locales/
  en.json
  fr.json
  pages/
    home/
      en.json
      fr.json
    about/
      en.json
      fr.json
```

**Пример `locales/en.json`:**

```json
{
  "greeting": "Hello, {name}!",
  "header": {
    "title": "Welcome",
    "subtitle": "Subtitle"
  },
  "errors": {
    "404": "Not found",
    "500": "Server error"
  },
  "apples": "no apples | one apple | {count} apples"
}
```

Генератор создаст типы для всех ключей, включая вложенные:

```typescript
// Generated types
declare module '@i18n-micro/types' {
  export interface DefineLocaleMessage {
    greeting: string
    'header.title': string
    'header.subtitle': string
    'errors.404': string
    'errors.500': string
    apples: string
  }
}
```

## 💡 Использование

После генерации типов вы получаете полную безопасность типов:

```typescript
import { useI18n } from '@i18n-micro/vue'

const { t } = useI18n()

// ✅ Type-safe: autocomplete works
t('greeting', { name: 'World' })
t('header.title')
t('errors.404')

// ❌ Type error: key doesn't exist
t('invalid.key') // Error: Argument of type '"invalid.key"' is not assignable
```

### Заметка для Nuxt

**В Nuxt-проектах типобезопасность работает только с композаблом `useI18n`.** Сгенерированные типы применяются к возвращаемому композаблом значению, обеспечивая типобезопасность при использовании методов `t()`, `ts()`, `tc()` и `has()`.

```typescript
// ✅ Correct: Using useI18n composable
<script setup lang="ts">
import { useI18n } from '#imports'

const { t } = useI18n()
t('greeting') // Type-safe with autocomplete
</script>

// ❌ Not type-safe: Direct access to $i18n or other methods
// Type safety is only available through the useI18n composable
```

## 🔄 Динамические ключи

Иногда нужны динамические ключи (например, на основе пользовательского ввода или ответа API). Генератор предоставляет вспомогательный тип `ScopedKey` для безопасного использования динамических ключей.

### Почему не runtime type guards?

**Runtime type guards не рекомендуются** для i18n-micro, потому что:

1. **Размер бандла** — генерация JS-массива всех ключей раздула бы бандл.
2. **Производительность** — рантайм-проверки добавляют лишний оверхед.
3. **Философия** — i18n-micro задуман лёгким и быстрым.

### TypeScript-подход: приведение типов

Для динамических ключей используйте type assertion из TypeScript:

```typescript
import type { TranslationKey, ScopedKey } from '@i18n-micro/types'

// ❌ Type error: dynamic key
const status = 'pending'
t(`status.${status}`) // Error: string is not assignable to TranslationKey

// ✅ Solution 1: Type assertion (if you're sure the key exists)
t(`status.${status}` as TranslationKey)

// ✅ Solution 2: ScopedKey helper (safer, checks prefix exists)
function getStatusText(status: string) {
  return t(`status.${status}` as ScopedKey<'status'>)
  // TypeScript verifies that keys starting with 'status.' exist
}

// ✅ Solution 3: Runtime check with has()
if (has(`status.${status}`)) {
  t(`status.${status}` as TranslationKey)
}
```

### Хелпер ScopedKey

Тип `ScopedKey<Scope>` позволяет сужать динамические ключи по префиксу:

```typescript
import type { ScopedKey } from '@i18n-micro/types'

// Assuming you have keys: 'errors.404', 'errors.500', 'btn.save'

function getErrorText(code: string) {
  // ✅ Safer than plain TranslationKey
  // TypeScript verifies that 'errors.*' keys exist
  return t(`errors.${code}` as ScopedKey<'errors'>)
}

// ❌ Type error: 'btn' prefix doesn't match 'errors'
function getErrorTextWrong(code: string) {
  return t(`errors.${code}` as ScopedKey<'btn'>) // Error
}
```

## 🎨 Продвинутое использование

### Работа с постраничными переводами

Генератор автоматически подхватывает ключи из постраничных файлов переводов:

```
locales/
  en.json                    # Root-level translations
  pages/
    home/
      en.json               # Route-specific translations
    about/
      en.json
```

Все ключи из корневых и постраничных файлов попадут в сгенерированные типы.

### Отключение постраничных локалей

Если в конфигурации i18n установлено `disablePageLocales: true`, генератор будет считать все файлы (включая находящиеся в `pages/`) корневыми переводами.

## 🐛 Устранение неполадок

### Типы не обновляются

1. **Проверьте пути к файлам** — убедитесь, что `translationDir` указывает на нужный каталог.
2. **Перезапустите TypeScript-сервер** — в VS Code: `Cmd/Ctrl + Shift + P` → "TypeScript: Restart TS Server".
3. **Проверьте tsconfig.json** — убедитесь, что сгенерированный файл включён.

### Ошибки типов после добавления ключей

1. **Перегенерируйте типы** — они должны обновляться автоматически, но можно запустить вручную.
2. **Проверьте JSON-синтаксис** — невалидные JSON-файлы пропускаются с предупреждением.
3. **Перезапустите dev-сервер** — иногда нужно, чтобы изменения вступили в силу.

### Не работает автокомплит

1. **Убедитесь, что файл включён** — сгенерированный `.d.ts` должен быть в include tsconfig.json.
2. **Проверьте module augmentation** — сгенерированный файл должен использовать `declare module '@i18n-micro/types'`.
3. **Версия TypeScript** — требуется TypeScript 4.1+ для template literal types.

## 📚 Справочник API

### `generateTypes(options: GeneratorOptions)`

Ручная генерация типов (удобно для скриптов или CI):

```typescript
import { generateTypes } from '@i18n-micro/types-generator'

await generateTypes({
  srcDir: './src',
  translationDir: 'locales',
  outputFile: './src/i18n-types.d.ts',
})
```

### `flattenKeys(obj: Record<string, unknown>, prefix?: string)`

Утилита для «разворачивания» вложенных объектов переводов:

```typescript
import { flattenKeys } from '@i18n-micro/types-generator'

const keys = flattenKeys({
  header: { title: 'Title' },
  footer: { copyright: 'Copyright' },
})
// Returns: ['header.title', 'footer.copyright']
```

## 🔍 Как это работает

1. **Сканирование** — `globby` находит все `**/*.json` в каталоге переводов.
2. **Парсинг** — каждый JSON парсится, и все ключи извлекаются рекурсивным раскрытием.
3. **Дедупликация** — ключи из всех файлов объединяются в уникальный набор.
4. **Генерация** — создаётся `.d.ts` с `declare module`-аугментацией.
5. **Наблюдение** — в dev-режиме отслеживаются изменения файлов, типы перегенерируются.

Сгенерированный файл использует module augmentation TypeScript, расширяя `DefineLocaleMessage` в `@i18n-micro/types`, что автоматически обновляет тип `TranslationKey` во всём проекте.

## 🎯 Лучшие практики

1. **Держите переводы упорядоченными** — используйте вложенные объекты для связанных ключей.
2. **Соблюдайте единый нейминг** — придерживайтесь конвенций (`errors.*`, `buttons.*` и т. п.).
3. **Опирайтесь на ScopedKey** — используйте `ScopedKey` для динамических ключей вместо простых приведений.
4. **Проверяйте типы в CI** — запускайте проверку типов в CI-пайплайне.
5. **Не редактируйте сгенерированные файлы** — `.d.ts` пересоздаётся автоматически и будет перезаписан.
