**Ngày**: 2026-06-25

**Phiên bản**: `v3.21.0`

![v3.21.0 release](/images/3.21.0.png)

Bản phát hành này bổ sung **`useI18nHead`** — một composable cấp trang để ghi đè SEO i18n trên nền plugin `02.meta` tích hợp sẵn. Tùy chỉnh `hreflang`, canonical, `og:url` và các thẻ Open Graph theo từng route mà không cần plugin meta tùy chỉnh hay `meta: false`.

## Có gì mới? {#what’s-new}

### Composable `useI18nHead` {#usei18nhead-composable}

Gọi `useI18nHead` trong bất kỳ trang nào khi `meta: true` (mặc định). Module sẽ hợp nhất đầu vào của bạn sau `useLocaleHead` mỗi khi route cập nhật:

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

Hỗ trợ đối tượng tĩnh, getter phản ứng, nối thêm `meta` / `link`, `replace` cho các nhóm tích hợp sẵn và `disable` để loại bỏ các thẻ được tạo tự động. Xem [`useI18nHead`](/vi/composables/useI18nHead).

### Tiện ích `mergeI18nHead` (`@i18n-micro/utils`) {#mergei18nhead-utility-@i18n-micro/utils}

Logic hợp nhất không phụ thuộc framework nằm trong `@i18n-micro/utils/merge-i18n-head` — được plugin `02.meta` sử dụng và có thể kiểm thử độc lập. Các kiểu (`I18nHeadInput`, `I18nHeadLink`, `I18nHeadMeta`) được export từ `@i18n-micro/types`.

### Tích hợp plugin {#plugin-integration}

- **`02.meta`** — hợp nhất đầu ra của `useLocaleHead` với trạng thái trang từ `useI18nHead` thông qua `useHead`
- **`01.plugin`** — đặt lại các ghi đè của trang khi tên route thay đổi thông qua `resetPageHead()` (trạng thái dùng chung với composable)

### Tài liệu và kiểm thử {#documentation-&-tests}

- Hướng dẫn mới: [`useI18nHead`](/vi/composables/useI18nHead) với các ví dụ CMS/bài viết
- Cập nhật [SEO](/vi/guide/seo) và [`useLocaleHead`](/vi/composables/useLocaleHead) — khi nào dùng API nào
- Độ phủ Playwright + Vitest: SSR, điều hướng SPA, tải lại, `nuxi generate`, alternate một phần, `x-default`, tải phía client phản ứng

## Trường hợp sử dụng điển hình {#typical-use-cases}

| Tình huống                                   | Cách tiếp cận                                                  |
| -------------------------------------------- | -------------------------------------------------------------- |
| Blog/CMS với bản dịch một phần               | `replace.hreflang` + `replace.ogAlternates` từ locale của API  |
| Canonical tùy chỉnh từ CMS                   | `replace.canonical` + `replace.ogUrl`                          |
| Chỉ OG cho trang landing                     | `meta: [{ property: 'og:title', ... }]` — giữ hreflang của module |
| Không có hreflang trên một trang             | `disable: ['hreflang', 'x-default']`                           |
| Thay thế plugin tùy chỉnh (`i18nManualHreflang`) | `useI18nHead` cho mỗi trang nội dung + `meta: true`        |

**JSON-LD** vẫn nằm trong `useHead({ script: [...] })` — `useI18nHead` không tạo dữ liệu có cấu trúc.

## Thay đổi phá vỡ tương thích {#breaking-changes}

Không có đối với cách dùng `nuxt.config` tiêu chuẩn. Composable mới và subpath utils chỉ mang tính bổ sung.

## Tại sao điều này quan trọng {#why-it-matters}

- **Không cần plugin meta tùy chỉnh** cho bài viết CMS, tin tức hoặc hướng dẫn có URL theo từng locale
- **Một pipeline duy nhất** — mặc định của module + ghi đè của trang trong một lệnh gọi `useHead`
- **An toàn kiểu** — `I18nHeadInput` cho các helper như `buildArticleHead(content)`
