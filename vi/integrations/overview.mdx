Các package `@i18n-micro/*` mang lõi dịch thuật của Nuxt I18n Micro đến Vue, React, Preact, Solid, Astro, VitePress và JavaScript thuần. Hãy dùng chúng khi ứng dụng của bạn không phải là ứng dụng Nuxt, hoặc khi một script hay server bên ngoài Nuxt cần cùng các tệp bản dịch. Mọi package dùng chung một mô hình instance, một hợp đồng router adapter và cùng bốn component, được mô tả một lần trên trang này.

Mỗi package có một playground dưới `packages/<name>/playground` trong repository.

## Instance {#the-instance}

`createI18n(options)` trả về một instance chứa các từ điển, locale hiện tại và route hiện tại. Các tùy chọn giống nhau trong mọi package:

| Tùy chọn | Kiểu | Mặc định | Ghi chú |
| --- | --- | --- | --- |
| `locale` | `string` | bắt buộc | Locale đang hoạt động. |
| `fallbackLocale` | `string` | `locale` | Được tra cứu khi một khóa bị thiếu trong `locale`. |
| `messages` | `Record<locale, Translations>` | `{}` | Từ điển gốc (route `'index'`). |
| `routeMessages` | `Record<route, Record<locale, Translations>>` | `{}` | Từ điển của route. Chỉ có ở Runtime, React, Preact, Node và VitePress. |
| `plural` | `PluralFunc` | `defaultPlural` | Quy tắc số nhiều tùy chỉnh. |
| `missingWarn` | `boolean` | `true` | `console.warn` chỉ khi dev trong trình duyệt cho khóa bị thiếu. |
| `missingHandler` | `(locale, key, routeName) => void` | — | Được gọi thay cho cảnh báo. |
| `numberFormats` | `Record<locale, Record<name, Intl.NumberFormatOptions>>` | — | Định dạng có tên: `tn(9.5, 'currency')`. |
| `datetimeFormats` | `Record<locale, Record<name, Intl.DateTimeFormatOptions>>` | — | Định dạng có tên: `td(date, 'short')`. |
| `timeZone` | `string` | múi giờ của runtime | Múi giờ IANA cho ngày của `td`; không ảnh hưởng đến `tdr`. Đặt nó để server và trình duyệt render cùng một ngày. |
| `now` | `() => number` | `Date.now` | Đồng hồ của `tdr`. Truyền thời gian của server cho hydration để cả hai render cùng một văn bản. |
| `localeIso` | `Record<code, string>` | — | Thẻ BCP 47 dùng cho quy tắc số nhiều (`ua` → `uk-UA`). React, Preact và Solid lấy nó từ `iso` trong `locales` của provider. |

Các từ điển nằm trong `i18n.storage.translations`, một `Map` với khóa `locale:route` (`en:index`, `en:about`).

Một khóa được tra cứu trong từ điển của route hiện tại, rồi trong từ điển gốc, trước tiên cho `locale`, sau đó cho `fallbackLocale`. Một khóa bị thiếu trả về chính khóa đó (hoặc `defaultValue` mà bạn truyền vào).

```ts
i18n.addTranslations('en', { nav: { home: 'Home' } }) // root, deep-merged
i18n.addRouteTranslations('en', 'about', { title: 'About us' }) // route chunk
i18n.addTranslations('en', { nav: { home: 'Start' } }, false) // replace instead of merge
i18n.setRoute('about')
i18n.t('title') // 'About us'
i18n.t('nav.home') // 'Start' (root key, still visible on the route)
```

### Dịch và định dạng {#translate-and-format}

| Phương thức | Trả về |
| --- | --- |
| `t(key, params?, defaultValue?, routeName?)` | Giá trị (string, number, object) với `{param}` được nội suy. |
| `ts(...)` | Giống `t`, dưới dạng string. |
| `tc(key, count \| params, defaultValue?)` | Dạng số nhiều. |
| `tn(value, options \| name)` | `Intl.NumberFormat` theo locale đang hoạt động. |
| `td(value, options \| name)` | `Intl.DateTimeFormat`. |
| `tdr(value, options?)` | Thời gian tương đối (`3 days ago`). |
| `has(key, routeName?)` | `true` khi locale đang hoạt động có khóa (từ điển route hoặc gốc; fallback không được kiểm tra). |

`defaultPlural` tách giá trị theo `|` và chọn dạng ở chỉ số `count`, giới hạn ở dạng cuối cùng; một count âm, thập phân hoặc `NaN` sẽ chọn dạng cuối cùng.

Một `plural` tùy chỉnh nhận `(key, count, params, locale, getter)`. Hãy đọc giá trị qua `getter(key)`; đừng tách khóa:

```ts
import type { PluralFunc } from '@i18n-micro/vue'

const plural: PluralFunc = (key, count, params, _locale, getter) => {
  const value = getter(key)
  if (typeof value !== 'string') return null
  const forms = value.split('|').map((form) => form.trim())
  return (count === 1 ? forms[0] : forms[1] ?? forms[0])!.replace('{count}', String(count))
}
```

## Router adapter {#router-adapter}

Các package SPA không phụ thuộc vào router. Một router adapter (`I18nRoutingStrategy`) cho chúng biết cách đọc đường dẫn hiện tại, điều hướng và xây dựng đường dẫn bản địa hóa. Các adapter tích hợp sẵn thêm tiền tố cho mọi locale ngoại trừ `defaultLocale` (`/about`, `/de/about`).

| Thành viên | Bắt buộc | Được dùng bởi |
| --- | --- | --- |
| `getCurrentPath(): string` | có | kiểm tra link đang hoạt động (theo trang, query và hash không được tính), `switchLocale` (giữ nguyên chúng) |
| `push({ path }): void` | có | `switchLocale`, `<I18nLink>` không có `linkComponent`, `<I18nSwitcher>` |
| `replace({ path }): void` | có | — |
| `resolvePath(to, locale)` | không | `localePath`, `localeRoute`, `<I18nLink>`; nếu không có, đường dẫn được trả về nguyên trạng |
| `linkComponent` | không | `<I18nLink>` render nó (ví dụ `RouterLink`) thay vì `<a>` |
| `getRoute()` | không | `{ fullPath, query }` cho các hàm hỗ trợ SEO |

`push` và `replace` là bắt buộc trong Vue, React, Preact và Solid. Astro có adapter phía server riêng với `push`/`replace` tùy chọn (xem [Astro](/vi/integrations/astro-package#router-adapter)).

Một adapter tối thiểu cho bất kỳ router dựa trên history nào:

```ts
import type { I18nRoutingStrategy } from '@i18n-micro/react'

const locales = ['en', 'de']
const stripLocale = (path: string) => path.replace(/^\/(en|de)(?=\/|$)/, '') || '/'

export const historyAdapter: I18nRoutingStrategy = {
  getCurrentPath: () => window.location.pathname + window.location.search + window.location.hash,
  push: ({ path }) => window.history.pushState({}, '', path),
  replace: ({ path }) => window.history.replaceState({}, '', path),
  resolvePath: (to, locale) => {
    const path = stripLocale(typeof to === 'string' ? to : to.path || '/')
    return locale === 'en' ? path : `/${locale}${path === '/' ? '' : path}`
  },
}
```

## Component {#components}

Vue, React, Preact và Solid cung cấp cùng bốn component. Props của chúng giống nhau; React, Preact và Solid chuyển các props khác xuống phần tử gốc.

### `<I18nT>` {#&lt;i18nt&gt;}

| Prop | Kiểu | Ghi chú |
| --- | --- | --- |
| `keypath` | `string` | bắt buộc |
| `params` | `object` | giá trị nội suy |
| `plural` | `number \| string` | render `tc(keypath, count)` |
| `number` | `number \| string` | truyền `tn(number)` dưới dạng `{number}` |
| `date` | `Date \| string \| number` | truyền `td(date)` dưới dạng `{date}` |
| `relativeDate` | `Date \| string \| number` | truyền `tdr(relativeDate)` dưới dạng `{relativeDate}` |
| `tag` | `string` | phần tử bao bọc, mặc định `span` |
| `html` | `boolean` | render bản dịch dưới dạng HTML; bản dịch phải đáng tin cậy, các params được escape |
| `defaultValue` | `string` | thay thế cho khóa bị thiếu, và được render trần khi `hideIfEmpty` ẩn một giá trị rỗng |
| `hideIfEmpty` | `boolean` | không render gì cho bản dịch rỗng |
| `customPluralRule` | `PluralFunc` | quy tắc số nhiều cho phần tử này |

Chỉ một prop định dạng được áp dụng, được kiểm tra theo thứ tự: `number`, `date`, `relativeDate`, `plural`.

#### Rich text {#rich-text}

Một `{placeholder}` có thể chứa một phần tử. Trong Vue, đó là một named slot; trong React, Preact và Solid, prop `components` cung cấp các phần tử, hoặc các hàm trả về một phần tử, theo tên. Dù cách nào, nó cũng được ưu tiên hơn một param cùng tên, hoạt động trong mọi nhánh, và vẫn đúng khi một locale sắp xếp lại các placeholder.

```tsx
// { "terms": "I accept the {link} of {company}" }
<I18nT keypath="terms" params={{ company: 'ACME' }} components={{ link: <a href="/terms">terms</a> }} />
```

Trong Solid, hãy truyền một hàm khi một placeholder lặp lại: một node chỉ đứng ở một vị trí. `children` thay thế văn bản, khi là một hàm chúng nhận `{ translation }`, giống như default slot của Vue. `html` bỏ qua tất cả những điều này.

### `<I18nLink>` {#&lt;i18nlink&gt;}

| Prop | Kiểu | Ghi chú |
| --- | --- | --- |
| `to` | `string \| { path }` | được bản địa hóa qua `resolvePath` của adapter |
| `activeStyle` | style object | được hợp nhất lên trên `style` ở trang hiện tại; React, Preact và Solid cũng áp dụng nó cho một mục cấp trên |
| `localeRoute` | function | ghi đè `resolvePath` cho link này |

URL bên ngoài (`https://`, `mailto:`, `tel:`) được render thành `<a target="_blank" rel="noopener noreferrer">`; `target` hoặc `rel` của riêng bạn được ưu tiên. `onClick` luôn chạy. Một cú nhấp có phím bổ trợ, một nút chuột khác hoặc một `target` sẽ để trình duyệt xử lý.

### `<I18nSwitcher>` {#&lt;i18nswitcher&gt;}

Một dropdown các locale đang bật (các locale `disabled: true` bị ẩn) với style mặc định nội tuyến. Các mục của nó là các link, với `lang`, `hreflang` và `dir` lấy từ locale. Theo mặc định, nhấp vào một mục sẽ đặt locale và gọi `push` của adapter với đường dẫn hiện tại đã bản địa hóa; prop `switchLocale` thay thế hành động đó. Với một `localeRoute` và không có router, trình duyệt sẽ đi theo link. Phím Escape hoặc một cú nhấp bên ngoài sẽ đóng nó.

| Prop | Ghi chú |
| --- | --- |
| `locales`, `currentLocale`, `getLocaleName` | ghi đè các giá trị được cung cấp |
| `switchLocale(code)` | thay thế việc chuyển tích hợp sẵn |
| `localeRoute` | thay thế `resolvePath` |
| `customLabels` | `{ de: 'DE' }` |
| `customWrapperStyle`, `customButtonStyle`, `customDropdownStyle`, `customItemStyle`, `customLinkStyle`, `customActiveLinkStyle`, `customDisabledLinkStyle`, `customIconStyle` | ghi đè style |

### `<I18nGroup>` {#&lt;i18ngroup&gt;}

Một `<div class="i18n-group">` truyền một `t` có tiền tố cho các phần tử con. Nó **không** thêm tiền tố cho `<I18nT>` hoặc các lời gọi `t()` bên trong nó; chỉ `t` mà nó truyền xuống mới có tiền tố.

| Prop | Ghi chú |
| --- | --- |
| `prefix` | bắt buộc, ví dụ `'profile'` |
| `groupClass` | class bổ sung trên phần tử bao bọc |

`t` có tiền tố được cung cấp qua một scoped slot trong Vue (`v-slot="{ t }"`) và một render-prop con trong React, Preact và Solid (`{({ t }) => …}`).

## Khóa có kiểu {#typed-keys}

`t()` chấp nhận bất kỳ chuỗi nào. Để có tự động hoàn thành cho các khóa của bạn, hãy tạo một tệp khai báo bằng [types generator](/vi/integrations/types-generator). Các khóa được gợi ý, không bị bắt buộc, và params không được khai báo kiểu.

## So sánh với module Nuxt {#compared-with-the-nuxt-module}

Các package không có định tuyến dựa trên tệp, không có server middleware và không có trình tải bản dịch: bạn quyết định khi nào tải JSON (`import`, `fetch`, hoặc `@i18n-micro/node` trên server) và dùng router adapter nào. Phát hiện locale, SEO meta và tạo route là các tính năng của Nuxt; Astro có middleware riêng để phát hiện và `useLocaleHead` cho SEO.
