# Loại trừ tệp tĩnh khỏi định tuyến i18n

## Tổng quan

Theo mặc định, nuxt-i18n-micro tự động loại trừ các tệp tĩnh phổ biến khỏi xử lý định tuyến i18n. Tuy nhiên, bạn cũng có thể cấu hình các mẫu loại trừ tùy chỉnh để ngăn các đường dẫn cụ thể bị hệ thống i18n xử lý.

## Loại trừ tích hợp

Mô-đun tự động loại trừ các loại tệp và mẫu sau:

- **Sitemap**: `/sitemap*.xml`, `/sitemap-en.xml`, v.v.
- **Tệp SEO**: `/robots.txt`, `/favicon.ico`
- **Tệp PWA**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Tài nguyên tĩnh**: Các tệp có phần mở rộng như `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Đường dẫn Nuxt nội bộ**: Mọi đường dẫn bắt đầu bằng `__` (như `/__nuxt/`)

## Mẫu loại trừ tùy chỉnh

Bạn có thể định nghĩa các mẫu loại trừ tùy chỉnh bằng tùy chọn `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Các loại mẫu

### Mẫu chuỗi

- **Khớp chính xác**: `'/api/health'` - khớp chính xác `/api/health`
- **Khớp tiền tố**: `'/admin'` - khớp `/admin` và `/admin/dashboard`
- **Ký tự đại diện**: `'/api/*'` - khớp `/api/users` nhưng không khớp `/api/users/123`
- **Ký tự đại diện sâu**: `'/admin/**'` - khớp `/admin/users` và `/admin/users/123`

### Biểu thức chính quy

Dùng đối tượng RegExp cho việc khớp mẫu phức tạp:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Trường hợp sử dụng

### Tệp SEO

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### Route API

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Bảng quản trị

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Tài nguyên tĩnh

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Cách hoạt động

1. **Middleware máy chủ**: Một middleware Nitro chạy trước để kiểm tra các mẫu loại trừ
2. **Xử lý trang**: Trong quá trình phân giải trang, các đường dẫn bị loại trừ được bỏ qua
3. **Route catch-all**: Route dự phòng kiểm tra loại trừ trước khi xử lý
4. **Prerender**: Các đường dẫn bị loại trừ không được đưa vào các route được prerender

## Ảnh hưởng hiệu năng

- Kiểm tra loại trừ được tối ưu hóa và chạy sớm trong vòng đời yêu cầu
- Các mẫu tích hợp dùng khớp regex hiệu quả
- Các mẫu tùy chỉnh được lưu vào bộ nhớ đệm và tái sử dụng
- Chi phí hiệu năng tối thiểu cho các đường dẫn bị loại trừ

## Khắc phục sự cố

### Tệp tĩnh vẫn bị chặn

1. **Kiểm tra cú pháp mẫu**: Đảm bảo các mẫu khớp chính xác cấu trúc đường dẫn
2. **Dùng regex cho mẫu phức tạp**: Ký tự đại diện chuỗi có giới hạn
3. **Kiểm thử mẫu**: Dùng dev tools của trình duyệt để xác minh đường dẫn yêu cầu thực tế
4. **Kiểm tra thứ tự**: Đảm bảo các mẫu loại trừ được định nghĩa trước cấu hình i18n khác

### Mẫu không hoạt động

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Chế độ gỡ lỗi

Bật chế độ gỡ lỗi để xem xử lý loại trừ:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Điều này sẽ ghi log các quyết định loại trừ trong console.

## Chuyển từ giải pháp khắc phục tạm

Nếu bạn từng dùng các giải pháp khắc phục tạm như route rule hoặc middleware, bạn có thể thay chúng bằng `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Cách tiếp cận mới đáng tin cậy hơn và hoạt động ở nhiều cấp của hệ thống định tuyến.
