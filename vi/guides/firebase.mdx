# 🔥 Triển khai Firebase AppHosting

## 📖 Giới thiệu

Firebase AppHosting là một nền tảng mạnh mẽ để triển khai các ứng dụng Nuxt với hạ tầng serverless. Tuy nhiên, khi triển khai các ứng dụng với `nuxt-i18n-micro`, bạn có thể gặp các vấn đề cụ thể liên quan đến cách các tệp JSON bản dịch được phục vụ. Hướng dẫn này cung cấp các giải pháp toàn diện để đảm bảo các bản dịch của bạn hoạt động chính xác trong production.

## ⚠️ Các vấn đề phổ biến

### Tệp bản dịch không được áp dụng

**Triệu chứng:**

- ✅ Bản dịch hoạt động hoàn hảo trong development (`nuxt dev`)
- ❌ Sau khi triển khai lên Firebase AppHosting, các tệp JSON tải nhưng bản dịch không áp dụng
- ❌ Không có lỗi xuất hiện trong console
- ❌ Các tệp bản dịch hiển thị trong tab Network nhưng có `Content-Type: text/html` không chính xác thay vì `application/json`

**Nguyên nhân gốc rễ:**

Firebase AppHosting (và các nền tảng khác dùng Nitro prerendering) có thể phục vụ các tệp JSON được prerender với MIME type không chính xác. Khi trình duyệt nhận các tệp JSON với `Content-Type: text/html`, nó không thể phân tích chúng đúng cách, khiến bản dịch thất bại âm thầm.

## ✅ Giải pháp

### Giải pháp 1: Cấu hình Route Rules (Khuyến nghị)

Giải pháp đơn giản nhất là thêm các header rõ ràng cho các route bản dịch trong `nuxt.config.ts` của bạn:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**Lợi ích:**

- ✨ Cấu hình đơn giản
- 🚀 Cải thiện hiệu năng với caching phù hợp
- 🔒 Hoạt động trên tất cả các nền tảng triển khai

### Giải pháp 2: URL API tùy chỉnh

Nếu bạn đang dùng `apiBaseUrl` tùy chỉnh (chỉ path prefix), hãy điều chỉnh route rules tương ứng:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### Giải pháp 3: Cấu hình dành riêng cho Firebase

Tạo hoặc cập nhật tệp `firebase.json` trong thư mục gốc dự án:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```

### Giải pháp 4: Cấu hình Firebase Functions

Đối với triển khai Firebase Functions, đảm bảo `functions/package.json` của bạn bao gồm các phụ thuộc cần thiết:

```json
{

  "engines": {
    "node": "18"

  "dependencies": {
    "firebase-admin": "^12.0.0",

  }

```

## 🔍 Debug

### Bật chế độ Debug

Thêm ghi log debug để xác định vấn đề:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

Điều này sẽ output các log chi tiết về:

- 📝 Tải tệp bản dịch
- 🔄 Các thao tác cache
- ⚠️ Lỗi tải

### Kiểm tra tab Network

1. Mở DevTools → tab Network
2. Lọc theo "data.json"
3. Nhấp vào một request tệp bản dịch
4. Xác minh **Response Headers**:
   - ✅ `Content-Type: application/json` (đúng)
   - ❌ `Content-Type: text/html` (sai - cần sửa)

### Xác minh Prerender Output

Sau khi build, hãy kiểm tra các tệp bản dịch được tạo:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

Bạn nên thấy `data.json` cho mỗi locale dưới mỗi trang.

## 🚀 Cấu hình Build

### Nitro Preset

Đối với Firebase AppHosting, hãy đảm bảo bạn đang dùng preset chính xác:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### Cấu hình Prerender

Cấu hình prerendering để có hiệu năng tối ưu:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

## 📋 Cấu hình ví dụ đầy đủ

Đây là một cấu hình đầy đủ hoạt động cho Firebase AppHosting:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'es', iso: 'es-ES', dir: 'ltr' },
      { code: 'it', iso: 'it-IT', dir: 'ltr' },
      { code: 'pt', iso: 'pt-PT', dir: 'ltr' },
      { code: 'ru', iso: 'ru-RU', dir: 'ltr' },
      { code: 'zh', iso: 'zh-CN', dir: 'ltr' },
      { code: 'ko', iso: 'ko-KR', dir: 'ltr' },
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
    debug: false, // Enable in development if needed
  },

  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },

  nitro: {
    preset: 'firebase-app-hosting',
    prerender: {
      crawlLinks: true,
      routes: ['/'],
    },
  },
})
```

## ✅ Danh sách kiểm tra xác minh

Sau khi áp dụng các sửa lỗi, hãy xác minh mọi thứ hoạt động:

- [ ] Build hoàn thành mà không có lỗi
- [ ] Các tệp JSON bản dịch nằm trong `.output/public/_locales/\{page\}/\{locale\}/data.json`
- [ ] Tab Network hiển thị `Content-Type: application/json` cho các tệp bản dịch
- [ ] Bản dịch hiển thị đúng trong lần tải trang đầu tiên
- [ ] Không có sự cố hydration mismatch trong console
- [ ] Chuyển đổi ngôn ngữ hoạt động đúng
- [ ] Các thẻ meta SEO được tạo đúng cách

## 🔄 Quy trình triển khai

### 1. Chuẩn bị Build

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. Triển khai lên Firebase

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. Xác minh triển khai

1. Truy cập trang đã triển khai của bạn
2. Mở DevTools → tab Network
3. Điều hướng đến một trang
4. Kiểm tra rằng `/_locales/index/en/data.json` (hoặc locale mặc định của bạn) tải với:
   - Status: 200
   - Content-Type: application/json
   - Phản hồi chứa JSON hợp lệ

## 🔧 Xử lý sự cố

### Vấn đề: Lỗi 404 cho tệp bản dịch

**Giải pháp:** Đảm bảo các tệp bản dịch được sao chép vào thư mục output:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### Vấn đề: Bản dịch hoạt động trên một số trang nhưng không hoạt động trên các trang khác

**Giải pháp:** Kiểm tra xem các bản dịch theo trang có được tạo không:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

Nếu các bản dịch theo trang bị thiếu, hãy đảm bảo `disablePageLocales` không được đặt là `true`:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### Vấn đề: Bản dịch tải chậm

**Giải pháp:** Tối ưu hóa caching và preloading:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## 💡 Mẹo

1. **Luôn kiểm tra trong môi trường giống production** trước khi triển khai
2. **Dùng chế độ debug** trong quá trình thiết lập ban đầu để bắt các vấn đề sớm
3. **Theo dõi tỷ lệ cache hit** để tối ưu hóa hiệu năng
4. **Giữ các tệp bản dịch nhỏ** để tải nhanh hơn
5. **Dùng các header cache phù hợp** để giảm tải máy chủ

## ⚡ Tối ưu hóa hiệu năng

### Bật nén

Firebase tự động xử lý nén Gzip/Brotli, nhưng hãy đảm bảo bản build của bạn được tối ưu hóa:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### Tải bản dịch chậm

`Nuxt I18n Micro` tự động tải chậm các bản dịch theo từng trang. Bản dịch chỉ được tải khi cần, giảm kích thước bundle ban đầu. Đây là chức năng tích hợp sẵn - không cần cấu hình bổ sung.

Để tối ưu hóa hơn nữa:

- Dùng `disablePageLocales: false` (mặc định) để bật các bản dịch theo trang
- Giữ các bản dịch cấp gốc tối thiểu
- Dùng các tệp bản dịch theo route cho nội dung trang

<Tip>
Module tự động đặt các header `Content-Type` chính xác bắt đầu từ phiên bản **v3.0.0+**. Nếu bạn gặp vấn đề, hãy cập nhật lên phiên bản mới nhất:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
