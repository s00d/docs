---
title: "useI18nLocale"
description: "useI18nLocale はロケールの状態とロケール Cookie を読み書きします。カスタムロケール検出のエントリーポイントです。"
---

`useI18nLocale()` は、アプリが選択したロケール、つまり `i18n-locale` の状態とロケール Cookie へのアクセスを提供します。ロケールを独自に検出するプラグイン(ドメイン、ユーザープロフィール、ヘッダーなど)では、`useState('i18n-locale')` や Cookie を手動で書き込む代わりにこれを使用してください。有効性のチェックには、ランタイムでの上書きを含む、有効化されたロケールが使われます。

## シグネチャ {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

i18n のロケール管理のための一元化されたエントリーポイントです。
useState('i18n-locale')、ロケール Cookie、同期ユーティリティを組み合わせています。

## 戻り値 {#returned-values}

| メンバー | 型 | 説明 |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | `useState('i18n-locale')` の ref。 |
| `localeCookie` | `Ref<string \| null>` | [`localeCookie`](/ja-jp/api/module-options#localecookie) の Cookie。このオプションが `null` の場合は単なる `{ value: null }`。 |
| `hashCookie` | `Ref<string \| null>` | ハッシュルーティング時の `hash-locale` Cookie。それ以外の場合は `{ value: null }`。 |
| `validLocales` | `string[]` | 有効化されたロケールのコード。 |
| `setLocale(locale)` | `(locale: string \| null) => void` | 状態と Cookie を書き込みます。検証は行わず、翻訳も読み込みません。 |
| `syncLocale(locale)` | `(locale: string \| null) => void` | Cookie のみを書き込みます。 |
| `getLocale()` | `() => string \| null` | 状態、次に優先設定の Cookie(ハッシュルーティング時はハッシュ Cookie)。検証は行いません。 |
| `getPreferredLocale()` | `() => string \| null` | 状態と優先設定の Cookie のうち最初の**有効な**値、または `null`。 |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | ハッシュルーティング時に状態が設定されていればその状態、それ以外の場合は `getLocaleFromRoute(route)`。 |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`、次に有効な状態、次に `options.serverLocale`、次にルートのロケール。状態が有効でない場合は結果を状態に保存し、クライアントでは Cookie も書き込みます。 |
| `isValidLocale(locale)` | `(locale) => locale is string` | `locale` が `validLocales` に含まれるかどうか。 |

Cookie の有効期間は 1 年で、`path: '/'` と `sameSite: 'lax'` が設定されます。

## 例 {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

モジュールのローダープラグインは起動時に状態を読み取るため、状態を設定するプラグインはそれより先に実行される必要があります(`enforce: 'pre'`)。状態が URL、Cookie、`Accept-Language` とどのように競合するかについては [ロケール検出](/ja-jp/guide/locale-detection) を、詳しい手順については [カスタム検出](/ja-jp/guide/custom-auto-detect) を参照してください。

`setLocale()` は画面上の翻訳を切り替えません。現在のページのロケールを変更するには、[`$switchLocale()`](/ja-jp/api/methods#$switchlocale) を呼び出してください。
