# 🔧 Types Generator(`@i18n-micro/types-generator`)

`@i18n-micro/types-generator` パッケージは、翻訳キーに対する TypeScript 型を自動生成します。JSON 翻訳ファイルを解析して厳密な型を生成し、翻訳キーの完全な型安全性とオートコンプリートを実現します。

## 📖 概要

`@i18n-micro/types-generator` はオプションの開発時依存で、以下によって開発体験を向上させます:

- 🔍 **自動型生成** - JSON 翻訳ファイルをスキャンして TypeScript 型を生成
- ✅ **型安全性** - コンパイル時にタイプミスや無効な翻訳キーを防止
- 🎯 **オートコンプリート対応** - 翻訳キーに対する IDE の完全なオートコンプリート
- 🔄 **ホットリロード** - 翻訳ファイルが変更されると自動的に型を再生成
- 🚀 **ランタイムオーバーヘッドゼロ** - 型はコンパイル時のみで、バンドルサイズに影響しません

## 🎯 クイックスタート

### Nuxt プロジェクトの場合

`nuxt.config.ts` にモジュールを追加します:

```typescript
import { defineNuxtConfig } from 'nuxt/config'

export default defineNuxtConfig({
  modules: [
    'nuxt-i18n-micro',
    '@i18n-micro/types-generator/nuxt', // Add types generator
  ],
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    translationDir: 'locales', // Path to your translation files
  },
})
```

ジェネレータは自動的に以下を行います:

- `locales` ディレクトリ内のすべての JSON ファイルをスキャン
- `.nuxt/i18n-micro.d.ts` に型を生成
- 変更を監視して型を自動的に再生成

### Vue/Vite プロジェクトの場合

`vite.config.ts` にプラグインを追加します:

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { I18nTypesPlugin } from '@i18n-micro/types-generator'

export default defineConfig({
  plugins: [
    vue(),
    I18nTypesPlugin({
      srcDir: 'src',
      translationDir: 'locales',
      outputFile: 'src/i18n-types.d.ts', // Optional: custom output path
    }),
  ],
})
```

生成されたファイルを `tsconfig.json` に必ず含めてください:

```json
{
  "include": ["src/**/*", "src/i18n-types.d.ts"]
}
```

## 📁 翻訳ファイル構造

ジェネレータはフラットな構造とネストされた構造の両方をサポートします:

```
locales/
  en.json
  fr.json
  pages/
    home/
      en.json
      fr.json
    about/
      en.json
      fr.json
```

**`locales/en.json` の例:**

```json
{
  "greeting": "Hello, {name}!",
  "header": {
    "title": "Welcome",
    "subtitle": "Subtitle"
  },
  "errors": {
    "404": "Not found",
    "500": "Server error"
  },
  "apples": "no apples | one apple | {count} apples"
}
```

ジェネレータは、ネストされたものを含むすべてのキーに対して型を作成します:

```typescript
// Generated types
declare module '@i18n-micro/types' {
  export interface DefineLocaleMessage {
    greeting: string
    'header.title': string
    'header.subtitle': string
    'errors.404': string
    'errors.500': string
    apples: string
  }
}
```

## 💡 使い方

型が生成されると、完全な型安全性が得られます:

```typescript
import { useI18n } from '@i18n-micro/vue'

const { t } = useI18n()

// ✅ Type-safe: autocomplete works
t('greeting', { name: 'World' })
t('header.title')
t('errors.404')

// ❌ Type error: key doesn't exist
t('invalid.key') // Error: Argument of type '"invalid.key"' is not assignable
```

### Nuxt 固有の注意点

**Nuxt プロジェクトでは、型安全性は `useI18n` コンポーザブルでのみ機能します。** 生成された型はコンポーザブルの戻り値に適用され、`t()`、`ts()`、`tc()`、`has()` メソッドを使用する際に型安全性を保証します。

```typescript
// ✅ Correct: Using useI18n composable
<script setup lang="ts">
import { useI18n } from '#imports'

const { t } = useI18n()
t('greeting') // Type-safe with autocomplete
</script>

// ❌ Not type-safe: Direct access to $i18n or other methods
// Type safety is only available through the useI18n composable
```

## 🔄 動的キー

ユーザー入力や API レスポンスに基づく動的キーが必要な場合があります。ジェネレータは、動的キーを安全に使うための `ScopedKey` ヘルパー型を提供します。

### なぜランタイム型ガードではないのか?

**ランタイム型ガードは推奨されません**。理由は以下のとおりです:

1. **バンドルサイズ** - すべてのキーを含む JavaScript 配列を生成するとバンドルが肥大化します
2. **パフォーマンス** - ランタイムチェックは不要なオーバーヘッドを追加します
3. **設計思想** - i18n-micro は軽量かつ高速であるように設計されています

### TypeScript 流のやり方: 型アサーション

動的キーには、TypeScript の型アサーションを使用します:

```typescript
import type { TranslationKey, ScopedKey } from '@i18n-micro/types'

// ❌ Type error: dynamic key
const status = 'pending'
t(`status.${status}`) // Error: string is not assignable to TranslationKey

// ✅ Solution 1: Type assertion (if you're sure the key exists)
t(`status.${status}` as TranslationKey)

// ✅ Solution 2: ScopedKey helper (safer, checks prefix exists)
function getStatusText(status: string) {
  return t(`status.${status}` as ScopedKey<'status'>)
  // TypeScript verifies that keys starting with 'status.' exist
}

// ✅ Solution 3: Runtime check with has()
if (has(`status.${status}`)) {
  t(`status.${status}` as TranslationKey)
}
```

### ScopedKey ヘルパー

`ScopedKey<Scope>` 型を使うと、プレフィックスによって動的キーを絞り込めます:

```typescript
import type { ScopedKey } from '@i18n-micro/types'

// Assuming you have keys: 'errors.404', 'errors.500', 'btn.save'

function getErrorText(code: string) {
  // ✅ Safer than plain TranslationKey
  // TypeScript verifies that 'errors.*' keys exist
  return t(`errors.${code}` as ScopedKey<'errors'>)
}

// ❌ Type error: 'btn' prefix doesn't match 'errors'
function getErrorTextWrong(code: string) {
  return t(`errors.${code}` as ScopedKey<'btn'>) // Error
}
```

## 🎨 高度な使い方

### ルート固有の翻訳の扱い

ジェネレータは、ルート固有の翻訳ファイルからのキーも自動的に含めます:

```
locales/
  en.json                    # Root-level translations
  pages/
    home/
      en.json               # Route-specific translations
    about/
      en.json
```

ルートレベルとルート固有の両方のファイルからのキーすべてが、生成された型に含まれます。

### ページロケールの無効化

i18n 設定で `disablePageLocales: true` を使用すると、ジェネレータは(`pages/` 内のものも含む)すべてのファイルをルートレベルの翻訳として扱います。

## 🐛 トラブルシューティング

### 型が更新されない

1. **ファイルパスを確認** - `translationDir` が正しいディレクトリを指していることを確認します
2. **TypeScript サーバーを再起動** - VS Code の場合: `Cmd/Ctrl + Shift + P` → 「TypeScript: Restart TS Server」
3. **tsconfig.json を確認** - 生成されたファイルが含まれていることを確認します

### キーを追加した後の型エラー

1. **型を再生成** - ジェネレータは自動的に再生成するはずですが、手動でトリガーすることもできます
2. **JSON 構文を確認** - 無効な JSON ファイルは警告とともにスキップされます
3. **開発サーバーを再起動** - 変更を反映させるために必要な場合があります

### オートコンプリートが動作しない

1. **ファイルの include を確認** - 生成された `.d.ts` ファイルが `tsconfig.json` の include に含まれていることを確認します
2. **モジュール拡張を確認** - 生成されたファイルが `declare module '@i18n-micro/types'` を使用していることを確認します
3. **TypeScript のバージョン** - テンプレートリテラル型のために TypeScript 4.1 以上が必要です

## 📚 API リファレンス

### `generateTypes(options: GeneratorOptions)`

型を手動で生成します(スクリプトや CI で有用):

```typescript
import { generateTypes } from '@i18n-micro/types-generator'

await generateTypes({
  srcDir: './src',
  translationDir: 'locales',
  outputFile: './src/i18n-types.d.ts',
})
```

### `flattenKeys(obj: Record<string, unknown>, prefix?: string)`

ネストされた翻訳オブジェクトをフラット化するユーティリティ関数:

```typescript
import { flattenKeys } from '@i18n-micro/types-generator'

const keys = flattenKeys({
  header: { title: 'Title' },
  footer: { copyright: 'Copyright' },
})
// Returns: ['header.title', 'footer.copyright']
```

## 🔍 仕組み

1. **スキャン** - `globby` を使って翻訳ディレクトリ内のすべての `**/*.json` ファイルを検索します
2. **パース** - 各 JSON ファイルをパースし、再帰的にフラット化してすべてのキーを抽出します
3. **重複排除** - すべてのファイルからのキーを一意のセットにまとめます
4. **生成** - `declare module` による拡張を含む `.d.ts` ファイルを作成します
5. **監視** - 開発モードではファイル変更を監視して型を再生成します

生成されたファイルは、TypeScript のモジュール拡張を使って `@i18n-micro/types` 内の `DefineLocaleMessage` を拡張します。これにより、プロジェクト全体の `TranslationKey` 型が自動的に更新されます。

## 🎯 ベストプラクティス

1. **翻訳を整理する** - 関連するキーにはネストされたオブジェクトを使用します
2. **一貫した命名を使う** - 命名規約に従います(例: `errors.*`、`buttons.*`)
3. **ScopedKey を活用する** - 動的キーには単なるアサーションではなく `ScopedKey` を使用します
4. **CI で型をチェックする** - CI パイプラインで型チェックを実行します
5. **生成されたファイルを編集しない** - `.d.ts` ファイルは自動生成され、上書きされます
