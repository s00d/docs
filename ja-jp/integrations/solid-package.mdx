`@i18n-micro/solid` は、SolidJS アプリにシグナルベースの i18n インスタンス、プロバイダー、`useI18n()`、4 つのコンポーネントを提供します。Nuxt でビルドされていない Solid アプリで使用してください。JSX やエフェクト内での `t()` の読み取りは、ロケール、ルート、辞書を追跡します。共通のモデルは [フレームワーク](/ja-jp/integrations/overview) にあります。

## インストール {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

ピア依存関係: `solid-js` `^1.8.0`、`@solidjs/router` `^0.15.4 || ^1.0.0`(任意、`@i18n-micro/solid/router` を使う場合のみ)。Solid 2 はまだサポートされていません。

## セットアップ {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` は `i18n`、`locales`、`defaultLocale`、`routingStrategy` を受け取ります。省略した prop は外側のプロバイダーの値(インスタンスを含む)を引き継ぎます。`getLocaleName()` と `<I18nSwitcher>` は `locales` を読み取るため、これがないと列挙するものがありません。オプションは [インスタンス](/ja-jp/integrations/overview#the-instance) にあります。インスタンスは [ランタイム](/ja-jp/integrations/runtime-package) のもので、そのストアに 1 つのシグナルが付いています。

## 翻訳する {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Solid が追跡できるように、メソッドは JSX またはエフェクト内で呼び出してください。`localePath` と `getLocale` も同様です。コンポーネント本体で一度だけ読み取った値は更新されません。インスタンス上では `i18n.locale` と `i18n.currentRoute` で追跡します。`i18n.getLocale()` は書き込み処理がそれを読み取るため、通常の(非リアクティブな)ままです。ロケールの読み取りはロケールの変更のみで再実行されるため、ロケールを読み取って辞書を読み込むエフェクトは 1 回だけ実行されます。props を分割代入したり、`t('key')` の結果を通常の変数に保持したりしないでください。

`useI18n()` は `t`、`ts`、`tc`、`tn`、`td`、`tdr`、`has`、`locale`(アクセサー: `locale()`)、`getLocale`、`getLocales`、`defaultLocale()`、`getLocaleName`、`switchLocale`、`localePath`、`localeRoute`、`setRoute`、`getRoute`、`addTranslations`、`addRouteTranslations`、`resolveTranslations`、`setTranslation`、`clearCache`、`instance` を返します。

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## ロケールを切り替える {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

切り替えでは何も読み込まれません。先にそのロケールの辞書を追加してください。

`<I18nGroup>` は、プレフィックス付きの `t` を関数の子に渡します。その中の `<I18nT>` と `t()` にはプレフィックスは付きません:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## ルーティング {#routing}

`@solidjs/router` のアダプターはサブパスにあるため、メインのエントリーがルーターをインポートすることはありません。ルーターの配下、通常は `useNavigate` と `useLocation` が動作するルーターの `root` で呼び出してください:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

アダプターはデフォルト以外のすべてのロケールにプレフィックスを付け(`/about`、`/de/about`)、`<I18nLink>` をルーターの `<A>` としてレンダリングします。`getCurrentPath` はルーターのリアクティブな location を読み取るため、アクティブリンクとスイッチャーはそれに追従します。カスタム戦略でも、そこでシグナルを読み取れば同じ効果が得られます。引数の順序に注意してください: `(locales, defaultLocale, navigate, location)`。他のルーターの場合は、`getCurrentPath`、`push`、`replace`(すべて必須)を持つアダプターを作成してください。[ルーターアダプター](/ja-jp/integrations/overview#router-adapter)を参照してください。

## SSR {#ssr}

サーバーレンダリングでは、`vite-plugin-solid` でビルドしてください。パッケージの `solid` エクスポート条件がソースを渡すため、サーバー向けにコンパイルされます。ビルド済みの `dist` はブラウザー専用です。インスタンスには `destroy()` がありません。アプリごとに 1 つ、またはサーバーではリクエストごとに 1 つ作成し、ガベージコレクションに任せてください。
