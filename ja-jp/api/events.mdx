モジュールはランタイム（アプリ）フックを 1 つだけ呼び出します。それが `i18n:register` です。プラグインやモジュールが `locales/` ファイルにない翻訳を追加する場合に使用します。コールバックは `register` 関数を受け取り、表示中のページに翻訳をマージします。

## `i18n:register` {#i18nregister}

```ts
'i18n:register': (
  register: (translations: unknown, locale?: string) => void,
  locale: string,
) => HookResult
```

| 引数 | 説明 |
| --- | --- |
| `register(translations, locale?)` | 読み込み中のルートのページチャンクに、`locale`（デフォルト：フックの `locale`）向けの `translations` をディープマージします。既に存在するキーは上書きされます。 |
| `locale` | 読み込み中のルートのロケール。 |

このフックは `RuntimeNuxtHooks` によって型付けされているため、`nuxtApp.hook('i18n:register', …)` にキャストは不要です。

## 呼び出されるタイミング {#when-it-fires}

ローダープラグイン（`i18n-plugin-loader`）が次のタイミングで呼び出します。

1. 起動時に一度、すべてのプラグインの実行後（`app:created`）かつアプリのレンダリング前；
2. 自身の `router.beforeEach` 内で、遷移先ページの翻訳が読み込まれた後、パスが変わったとき — `no_prefix` ではナビゲーションのたびに。

アプリのレンダリングやナビゲーションの続行の前に、すべてのコールバックとすべての `register` 呼び出しが await されるため、ページはマージ済みのキーでレンダリングされます。[`hooks: false`](/ja-jp/api/module-options#hooks) の場合、このフックは呼び出されません。

## 例 {#example}

```ts
// plugins/i18n-extra.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('i18n:register', async (register, locale) => {
    const extra = await $fetch<Record<string, unknown>>(`/api/cms-strings/${locale}`)
    register(extra, locale)
  })
})
```

これはランタイムフックです。`nuxt.config` やモジュールの `setup` 内の `nuxt.hook` ではなく、プラグイン内で `nuxtApp.hook` を使って登録してください。モジュールは `addPlugin` でそのようなプラグインを追加します。
