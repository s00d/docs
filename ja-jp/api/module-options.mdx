このページでは、`nuxt.config` の `i18n` オブジェクトのすべてのキーを一覧にしています。型やデフォルト値は表で調べ、例や注意点は下の詳細を参照してください。型、デフォルト値、説明は [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts) の `ModuleOptions` インターフェースから生成されています。

```ts nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
    ],
    defaultLocale: 'en',
  },
})
```

ネストされたオプションはドット区切りのパスで表示されます：`translationPayloads.mode` は `translationPayloads` の `mode` キーです。

## ロケールとルーティング {#locales-and-routing}

どの言語が存在し、URL にどのように表示されるか。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | サポートするロケールのリスト。各エントリは、ロケールコードと任意のメタデータ（ISO、方向、表示名など）を定義します。 |
| `strategy` | `Strategies` | `'prefix_except_default'` | ロケール接頭辞の URL ルーティング戦略。 - `'no_prefix'` — URL にロケールを含めず、ロケールは Cookie に保存します。 - `'prefix_except_default'` — デフォルト以外のすべてのロケールに接頭辞を付けます。 - `'prefix'` — デフォルトロケールを含め、常に接頭辞を付けます。 - `'prefix_and_default'` — `prefix` と同様ですが、デフォルトロケールには接頭辞なしでもアクセスできます。 |
| `defaultLocale` | `string` | `'en'` | URL やユーザーの設定からロケールを判断できない場合に使用するロケール。翻訳のフォールバックではありません：それには `fallbackLocale` を設定してください。 |
| `localeCookie` | `string \| null` | `null` | セッションをまたいでユーザーのロケール設定を保持するための Cookie 名。`null` に設定すると Cookie による保持を無効にします。指定がない場合、`no_prefix` 戦略では自動的に `'user-locale'` が設定されます。`i18n` 設定ブロックで明示的に `null` を指定すると、そこでも無効のままになります。 |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `{}` | グローバルなルートレベルのロケール設定。コンポーネントを変更せずに、特定のページのロケールルートを制限またはカスタマイズできます。 - `false` — ルートをローカライズの対象外にします。 - `Record<LocaleCode, string>` — ロケールごとのカスタムパス。 |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | URL セグメント内のロケールコードを照合するためのカスタム正規表現（またはその文字列ソース）。`locales` のすべてのロケールコードが、フラグを除いたパターン全体に一致する必要があり、一致しない場合はビルドが失敗します。 |
| `noPrefixRedirect` | `boolean` | `false` | `no_prefix` 戦略の場合：デフォルトロケールがページのカスタムパスを持つとき（`localeRoutes` / `globalLocaleRoutes`）、ページの元のパスを訪問者のロケールのカスタムパス、なければデフォルトロケールのカスタムパスにリダイレクトします（例：`/about` → `/about-us`）。独自のカスタムパスを持たないロケールは元のパスのままです。動的セグメントを持つページはリダイレクトされません。 |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | i18n ルーティングから除外するパス：文字列はパスの接頭辞（`/admin` は `/admin/x` を含む）または `*` / `?` のグロブで、RegExp はパスに対してテストされます。一致したページにはロケールのバリアント、ロケールのリダイレクトや 404 がなく、プリレンダリングから除外されますが、翻訳付きで描画されます。`/api`、`/_nuxt`、`/__*`、翻訳ルート、一般的な静的ファイル（sitemap、robots.txt、favicon、拡張子によるアセット）は常に除外されます。 |
| `routeLocales` | `Record<string, string[]>` | — | ルートごとのロケール制限。ビルド時に `$defineI18nRoute()` の呼び出しから抽出されます。ルートパス（例：`'/about'`）を許可されたロケールコードの配列にマッピングします。記載のないルートには制限がありません（すべてのロケールが許可されます）。 |

## 翻訳 {#translations}

翻訳ファイルの配置場所と、キーの解決方法。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | 翻訳 JSON ファイルを含むディレクトリへの、プロジェクトルートからの相対パス。 |
| `disableWatcher` | `boolean` | `false` | 開発モードで不足している翻訳ファイルを自動作成するファイルウォッチャーを無効にします。 |
| `routesLocaleLinks` | `{ [key: string]: string }` | `{}` | ルート名を別のルート名にマッピングして、同じ翻訳ファイルを共有します。例えば、`{ 'about-us': 'about' }` は、`about-us` ページが自身の翻訳ではなく `about` ページの翻訳を使用することを意味します。 |
| `plural` | `PluralFunc` | ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)`` | カスタムの複数形関数。`(key, count, params, locale, getter)` を受け取り、選択された複数形を文字列で返すか、組み込みの `defaultPlural` ロジックにフォールバックする場合は `null`/`undefined` を返します（一部のロケールだけを上書きできます）。Nuxt モジュールでは、関数は `.toString()` で `.nuxt/i18n.plural.mjs` にシリアライズされます — 自己完結している必要があります（インポートや外側のスコープは不可）。ファイルパスの文字列はサポート**されません**。 |
| `disablePageLocales` | `boolean` | `false` | ページごとの翻訳ファイルを無効にします。`true` の場合、グローバルな翻訳（`{locale}.json`）のみが読み込まれ、ページ固有のファイル（`pages/{page}/{locale}.json`）は生成も読み込みもされません。 |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | グローバルなフォールバックロケールのコード。あるロケールで不足しているキーは、このロケールから取得されます（各ペイロードのビルド時または読み込み時にマージされます）。これがない場合、不足しているキーはキーそのものとして描画されます。 |

## ペイロードとキャッシュ {#payloads-and-caching}

翻訳がブラウザーに届く仕組み。これらがランタイムで何を変えるかは[パフォーマンス](/ja-jp/guide/performance)で説明しています。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Nitro のグローバルミドルウェアでインデックスページの翻訳をプリロードします（サーバー専用、プライベート設定）。 |
| `apiBaseUrl` | `string` | `'_locales'` | 翻訳 API ルートのベース URL パスセグメント（SSR/SSG のデータ取得で使用）。環境変数 `NUXT_I18N_APP_BASE_URL` でも設定できます。 |
| `apiBaseClientHost` | `string` | `undefined` | クライアントサイドの翻訳取得リクエストに使用するホストを上書きします。クライアントが Nuxt から見えるものとは異なるホスト名でサーバーにアクセスする場合に便利です。環境変数 `NUXT_I18N_APP_BASE_CLIENT_HOST` でも設定できます。 |
| `apiBaseServerHost` | `string` | `undefined` | サーバーサイドの翻訳取得リクエストに使用するホストを上書きします。サーバーが内部ホスト名で自身にアクセスするコンテナ／マイクロサービス構成で便利です。環境変数 `NUXT_I18N_APP_BASE_SERVER_HOST` でも設定できます。 |
| `translationPayloads` | `TranslationPayloadOptions` | — | 翻訳ペイロードの出力方法を制御します（Node サーバー：`public/<apiBaseUrl>`、Edge / function / inline：Nitro の `serverAssets`）。 - **Node サーバー**（`node-server`、`node-cluster`、ディスクの `serveStatic`）：`serverAssets` は `public/` 配下の `readFile` によるローカル SSR を意味します（Rollup の `raw:` なし）。 - **Edge、function プリセット、`serveStatic: "inline"`**（`vercel`、`netlify`、`aws-lambda`、winterjs など）：`serverAssets` は Nitro の `serverAssets`（`assets:i18n`）を登録します。SSR からディスク上の `public/` を利用できないためです。パブリックコピーは強制しません — CDN／静的配信には `publicAssets: true` を設定してください。通常のオールインワン構成ではデフォルトのままにしてください。大規模な Edge カタログでは `mode: 'source'` を推奨します。CDN を利用するデプロイでは、ローカル出力を無効にし、`apiBaseClientHost` / `apiBaseServerHost` を設定してください。 |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | 翻訳ペイロードの戦略。 - `premerged`：ビルド時の `{page}/{locale}/data.json` マトリクス（デフォルト） - `source`：ランタイムでマージされるコンパクトなソースファイル（Edge／大規模カタログで推奨） |
| `translationPayloads.serverAssets` | `boolean` | `true` | ローカル SSR のペイロード：ディスク上の `public/` を配信する Node サーバーはそのツリーを読み取り（パブリックコピーを強制）、Edge、function プリセット、`serveStatic: "inline"` は Nitro の `serverAssets` で埋め込みます。 - **Node サーバー**（プリセット自体が `public/` を配信するもの、例：`node-server`）：Nitro の `serverAssets` なし（Rollup の `raw:` を回避）。SSR は `public/<apiBaseUrl\|publicDir>` を `{page}/{locale}/data.json` として読み取ります。これが `true` の場合、`publicAssets` が false でもパブリックコピーが強制されます。 - **Edge、function プリセット、inline**（`nitro.node === false`、`vercel` / `netlify` / `aws-lambda` のようにディスクの `serveStatic` がないもの、または winterjs などの `serveStatic: "inline"`）：`mode` と同じレイアウトの Nitro `serverAssets`（`assets:i18n`）。パブリックコピーは強制**しません** — CDN／静的配信には `publicAssets: true` を設定してください。 |
| `translationPayloads.serverHandler` | `boolean` | `true` | `/{apiBaseUrl}/:page/:locale/data.json` に組み込みのサーバールートを登録します。翻訳ペイロードを外部ホスト／CDN から配信する場合は無効にしてください。 |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | ペイロードを Nitro のパブリック出力にコピーします。premerged → `apiBaseUrl` 配下の `{page}/{locale}/data.json`、source → コンパクトなツリー。SSR が `public/` を読み取る場合（`node-server` など）、`serverAssets: true` でもこのコピーが強制されます。Edge / function / `serveStatic: "inline"` プリセットでは、これが `true` の場合にのみコピーします（SSR は Nitro の埋め込みを使用します）。 |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | `/{apiBaseUrl}/.../data.json` の Nitro プリレンダリングにオプトインします。premerged の `publicAssets` がすでにそれらのファイルを書き出している場合、通常は不要です。 |
| `translationPayloads.publicDir` | `string` | — | Nitro のパブリックルートからの相対パスで指定するパブリック出力フォルダー。デフォルトは `apiBaseUrl`（`_locales`）です。これにより、静的ファイルがクライアントの取得 URL（`/{apiBaseUrl}/{page}/{locale}/data.json`）と一致します。 |
| `translationPayloads.rootDelta` | `boolean` | `true` | ロケールごとに 1 つのルートファイルを書き出し、各ページファイルにはそれとの差分のみを書き出します。クライアントと SSR がそれらをマージします。ファイルが読み込まれる場所ではどこでも、チャンク全体も引き続き機能します。`false` にすると、すべてのページファイルに辞書全体を保持します。`premerged` のみで、`disablePageLocales` では無効になります。 |
| `translationPayloads.warnFileCount` | `number` | `500` | 生成されたペイロードのファイル数がこのしきい値を超えると、ビルド中に警告します。 |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | 生成されたペイロードの合計サイズがこのしきい値（バイト単位）を超えると、ビルド中に警告します。 |

## SEO {#seo}

ローカライズされた各ページに生成されるメタタグ。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | SEO メタタグ（`hreflang`、`canonical`、`og:url`、`og:locale`）を自動的に生成します。 |
| `metaBaseUrl` | `string` | `undefined` | SEO メタタグ（canonical、og:url、hreflang）のベース URL。 - 具体的な URL 文字列（例：`'https://example.com'`） — そのまま使用されます（最優先）。 - `undefined` — `nuxt-site-config` モジュールが存在する場合はその `site.url` に、なければ現在のリクエストのオリジン（サーバーでは `useRequestURL().origin`、クライアントでは `window.location.origin`）にフォールバックします。 |
| `metaTrustForwardedHost` | `boolean` | `true` | メタタグのベース URL を解決する際に `X-Forwarded-Host` ヘッダーを信頼します。このヘッダーを実際のクライアント向けホスト名に設定するリバースプロキシ（nginx、Cloudflare、AWS ALB など）の背後でアプリが動作する場合に有効にしてください。 |
| `metaTrustForwardedProto` | `boolean` | `true` | メタタグのプロトコルを解決する際に `X-Forwarded-Proto` ヘッダーを信頼します。TLS を終端するプロキシの背後でアプリが動作する場合に有効にすると、アプリ自体が HTTP で待ち受けていても canonical URL に `https://` が使用されます。 |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | canonical および `og:url` メタタグに保持されるクエリパラメーター名のリスト。このリストにないパラメーターは canonical URL から取り除かれます。 |

## 検出とリダイレクト {#detection-and-redirects}

ロケールを選択していない訪問者のためのロケールの選び方。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | 自動的なロケールリダイレクト（サーバープラグインとクライアントのルートミドルウェア）を有効にします。`true` の場合、接頭辞を使う戦略では接頭辞のない URL をローカライズされた形にリダイレクトします。ロケールは、アプリの状態、Cookie、または `autoDetectPath` が許可する場所では `Accept-Language` から決まり、それ以外はデフォルトになります。`no_prefix` では検出によって URL が変わることはありません（カスタムパスについては `noPrefixRedirect` を参照）。 |
| `autoDetectLanguage` | `boolean` | `true` | `Accept-Language` HTTP ヘッダーからユーザーの優先言語を自動的に検出します。`autoDetectPath` と組み合わせて、検出を行うタイミングを決定します。 |
| `autoDetectPath` | `string` | `'/'` | Cookie / Accept-Language の設定によるリダイレクトを実行できる場所（`redirects` が有効な場合）。 - `'/'` — `/` のみ（デフォルトロケールのディープリンクには引き続きアクセス可能。デフォルト） - `'no_prefix'` — ロケール接頭辞のないパスのみ - `'*'` — 明示的なロケール接頭辞の書き換えを含むすべてのパス（例：Cookie が `de` を優先する場合、`/fr/about` → `/de/about`） - その他の文字列 — そのパス。末尾のスラッシュは無視されます（例：`'/welcome'`） `prefix` では、許可されたパス以外の接頭辞のない URL も、デフォルトロケールの形にリダイレクトされます（`/about` → `/en/about`）。`prefix_except_default` で接頭辞付きのデフォルトロケール（`/en`）は、リダイレクトではなく 404 になります。 |

## 登録 {#registration}

無効にできるモジュールの各部分。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | ランタイムで `$defineI18nRoute()` を提供します。いずれの場合も、ビルドはページ内の `$defineI18nRoute()` の呼び出しを読み取ります。 |
| `plugin` | `boolean` | `true` | `$t()`、`$tc()`、`$getLocale()`、`$switchLocale()` などのランタイムヘルパーを提供するコア i18n プラグインを登録します。 |
| `hooks` | `boolean` | `true` | 読み込み時とナビゲーション時に `i18n:register` アプリフックを呼び出し、プラグインが翻訳を追加できるようにします。 |
| `components` | `boolean` | `true` | 組み込みの i18n コンポーネント（`<i18n-link>`、`<i18n-switcher>`、`<i18n-t>`、`<i18n-group>`）を登録します。`false` に設定すると、コンポーネントの自動登録を無効にします（例：使用しておらず、モジュールのフットプリントを減らしたい場合）。 |
| `types` | `boolean` | `true` | デフォルトロケールのファイル内の翻訳キーに基づいて、`useI18n`、`$t`、関連ヘルパーの TypeScript 型宣言を生成します。 |
| `debug` | `boolean` | `false` | ロケール検出、ルート生成、翻訳の読み込みに関する詳細なデバッグログを有効にします。 |

## その他 {#other}

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `trustForwardedHost` | `boolean` | `false` | リクエストのドメイン（`locales[].baseUrl`）を `Host` ではなく `X-Forwarded-Host` から選択します。そのヘッダーを上書きするプロキシの背後でのみ有効にしてください。 |
| `hreflangBaseLanguage` | `boolean` | `false` | 各ロケールの `iso` から派生した、言語のみの `hreflang` も出力します（例：`es-ES` → `es` も）。`locales` 内で最初の地域ロケールが、その言語の言語のみのタグを担当します。ルーティング用の `code` は使用されません — `iso \|\| code` のみです。 |
| `additionalTranslationDirs` | `string[]` | `[]` | 追加のディレクトリ（プロジェクトルート／各 Nuxt レイヤーのルートからの相対パス）。そのトップレベルの `{locale}.json` ファイルは、`translationDir` より前にグローバル辞書へディープマージされます。マージ順：配列内の各エントリの順（レイヤーをまたいで）、次に `translationDir`（競合時に優先）。ルートの `{locale}.json` ファイルのみが読み込まれます — これらのディレクトリ配下の `pages/` は無視されます。例：`translationDir: 'frontend'`、`additionalTranslationDirs: ['common']` → `common/en.json`、次に `frontend/en.json`。 |
| `vueDevtools` | `boolean` | `true` | 開発時に Vue DevTools のインスペクターとタイムラインを登録します（ブラウザー拡張機能）。Nuxt DevTools のカスタムタブとは別です。 |
| `trailingSlash` | `'append' \| 'remove'` | `undefined (inherit from Nuxt)` | `$localePath` / `$switchLocalePath` の末尾スラッシュ（NuxtLink と同等）。未設定の場合は `experimental.defaults.nuxtLink.trailingSlash` がデフォルトになります。i18n のパスヘルパーで Nuxt のリンクのデフォルトを上書きするには、明示的に設定してください。 |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | ローカライズされたルート名の先頭に付加される接頭辞（例：`'localized-index'`）。元のルートと生成されたロケールのバリアントを区別するために内部で使用されます。 |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | ルートごとのメタタグの無効化。ルート名またはパスを `true`（すべてのメタを無効化）、またはメタを無効化するロケールコードの配列にマッピングします。ビルド時に `$defineI18nRoute()` の呼び出しで見つかったエントリが追加されます。 |
| `missingWarn` | `boolean` | `true` | 翻訳キーが見つからない場合にコンソールに警告を表示します（開発ビルド、ブラウザー内）。 |
| `hmr` | `boolean` | `true` | 開発時に翻訳ファイルの Hot Module Replacement を有効にします。`true` の場合、JSON 翻訳ファイルの変更により、ページ全体を更新することなく自動的に再読み込みされます。 |
| `cacheMaxSize` | `number` | `0` | メモリ内の翻訳キャッシュの最大エントリ数。fetch キャッシュとサーバーキャッシュは最も長く使われていないエントリを破棄し、ブラウザーの辞書マップは最も古いものを破棄します（FIFO）。`0` はブラウザーでは無制限を意味し、その場合サーバーキャッシュは最大 1000 エントリを保持するため、でっち上げのページ名を含むリクエスト URL によってサーバーのメモリが増えることはありません。 |
| `cacheTtl` | `number` | `0` | fetch とサーバーの翻訳キャッシュの有効期間（秒）。エントリが保存された時点から数えられ（読み取りでは延長されません）、`apiBaseServerHost` からのデータは少なくともその頻度で更新されます。ブラウザーのアクティブな辞書はこれによって期限切れになりません。`0` はエントリが期限切れにならないことを意味します。 |
| `cacheStorage` | `string` | — | 複数のサーバーインスタンスが辞書キャッシュとして共有する Nitro ストレージのマウント名（`nitro.storage`、例：`'redis'`）。プロセス内キャッシュの後、ソースの前に読み取られます。主に `apiBaseServerHost` で効果を発揮します：インスタンスごとではなく、バックエンドから 1 回だけ取得します。エントリはビルドごとのキーを持ち、`cacheTtl` の後、それが `0` の場合は 1 日後に期限切れになります。開発時とプリレンダリング時は無効です。ストレージが失敗した場合はソースにフォールバックします。未設定の場合：共有キャッシュなし。 |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | ロケールごとの名前付き数値フォーマット（Vue I18n 互換）。`$tn(1000, 'currency')` 形式の呼び出しを可能にします。 |
| `timeZone` | `string` | `the runtime's zone` | `$td` と `<i18n-t date>` の IANA タイムゾーン（`Europe/Berlin`）。サーバーとすべてのブラウザーで同じ日付を描画するために設定します。名前付きフォーマット自身の `timeZone` が優先されます。 |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | ロケールごとの名前付き日時フォーマット（Vue I18n 互換の `datetimeFormats`）。`$td(date, 'short')` 形式の呼び出しを可能にします。 |
| `httpCacheDuration` | `number` | `31536000` | `/{apiBaseUrl}/:page/:locale/data.json` の HTTP `Cache-Control` の max-age（秒）。`dateBuild` が URL をバスティングしている間（`?v=...`、これがデフォルトです）にのみ完全に適用されます：その場合レスポンスは `private, max-age=…, immutable` になります：ブラウザーはそれを固定しますが、クエリを無視する CDN は固定できません（`httpCacheControl: false` の場合は `public`）。 - `dateBuild: 0`/`''` — URL が安定しているため、この期間は尊重*されません*。代わりにレスポンスは `public, max-age=0, must-revalidate` になります。変わらない URL に長い `max-age` を付けると、ブラウザーが最初に見たペイロードが固定されてしまいます。 - `0` — `Cache-Control` をまったく設定しません（ローカルでのデバッグに便利） - 開発時（`import.meta.dev`）には適用されないため、HMR がブラウザーキャッシュと競合することはありません - Nitro を通じて配信されるレスポンスにのみ届きます。`public/` にコピーされ、ホスティングプラットフォームが配信するペイロードには、そのプラットフォームのヘッダーが適用されます — パフォーマンスガイドを参照してください。`@nuxtjs/i18n` の実験的な `httpCacheDuration`（v10.2.0）に相当しますが、Nitro の `defineCachedEventHandler` の maxAge ではなく、明示的なレスポンスヘッダーとして実装されています。 |
| `httpCacheControl` | `string \| false` | `'public, max-age=60'` | ホストまたはパス全体のルールによって応答されるペイロードファイルの `Cache-Control`。これらは `?v=` を認識できません。Node サーバーでは、現在の `?v=` へのレスポンスは `httpCacheDuration` の間固定され、それ以外は再検証されます。`source`、`cacheTtl`、または `apiBaseServerHost` のように辞書がビルドなしで変わる場合は、すべてのレスポンスがこのヘッダーを使用します。`false` にすると、すべてのファイルが `max-age=0, must-revalidate` のままになります。 |
| `dateBuild` | `string \| number` | — | 翻訳リクエストのキャッシュバスティングに使用する値（`?v=...`）。指定しない場合、モジュールは翻訳ファイルのハッシュを使用するため、値は翻訳が変わったときにのみ変わります（ハッシュを計算できない場合は `Date.now()`）。`0` または `''` でキャッシュバスティングを無効にします。自分で固定するには、安定した値（git の SHA、ビルド番号）を設定してください。辞書がその場で置き換えられた後、`NUXT_I18N_DATE_BUILD` または `runtimeConfig.public.i18nRuntime.dateBuild` がランタイムでこれを置き換えます：固定された URL は再ビルドなしで置き去りにされます。 |
| `experimental` | `Record<string, unknown>` | — | 実験的／不安定なオプションのための入れ物。内容はマイナーバージョン間で予告なく変更または削除される可能性があります。 |

### ロケールと URL {#locales-and-urls}

#### `locales` {#locales}

**型** `Locale[]` · **デフォルト** `[]`

サポートするロケールのリスト。
各エントリは、ロケールコードと任意のメタデータ（ISO、方向、表示名など）を定義します。

各エントリは `Locale` オブジェクトです。

| プロパティ | 型 | 説明 |
| --- | --- | --- |
| `code` | `string` | **必須。** URL セグメントとファイル名（`en`、`de-at`）。 |
| `iso` | `string` | `<html lang>`、`hreflang`、複数形、`$tn` / `$td` / `$tdr` で使用する BCP-47 タグ（`en-US`）。 |
| `displayName` | `string` | `<i18n-switcher>` と `$getLocaleName()` で使用するラベル。 |
| `dir` | `'ltr' \| 'rtl' \| 'auto'` | `<html dir>`。指定しない場合、既知の RTL 言語には `rtl` が設定され、それ以外のロケールには属性が付きません。[SEO](/ja-jp/guide/seo#text-direction) を参照してください。 |
| `disabled` | `boolean` | ルート、ペイロード、切り替えから除外されます。その接頭辞は 404 になり、そのロケールへのリンクは現在のページにとどまります。 |
| `fallbackLocale` | `string` | このロケールのフォールバック。グローバルな `fallbackLocale` を上書きします。 |
| `seo` | `boolean` | `false` にすると、`hreflang` と `og:locale:alternate` からこのロケールを除外します。 |
| `og` | `string` | `og:locale` の値（`ar_AE`）。デフォルト：`iso` を変換したもの。 |
| `baseUrl` | `string` | ロケール独自のドメイン：1 つのビルドがそれを配信し、他のドメインからそこへのリンクは絶対 URL になります。 |
| `baseDefault` | `boolean` | `baseUrl` と併用：そのホストのデフォルトロケールで、そこへのリンクには `/<code>` 接頭辞が付きません（`prefix` では付きます）。 |

その他のプロパティは保持され、`$getLocales()` によって返されます。`Locale` を拡張して型を付けてください。

```ts
// i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
  }
}
export {}
```

モジュールは `@i18n-micro/types` を巻き上げる（hoist）ため、pnpm でもパッケージをインストールせずにこれが機能します。

#### `defaultLocale` {#defaultlocale}

**型** `string` · **デフォルト** `'en'`

URL やユーザーの設定からロケールを判断できない場合に使用するロケール。
翻訳のフォールバックではありません：それには `fallbackLocale` を設定してください。

#### `strategy` {#strategy}

**型** `Strategies` · **デフォルト** `'prefix_except_default'`

ロケール接頭辞の URL ルーティング戦略。

- `'no_prefix'` — URL にロケールを含めず、ロケールは Cookie に保存します。
- `'prefix_except_default'` — デフォルト以外のすべてのロケールに接頭辞を付けます。
- `'prefix'` — デフォルトロケールを含め、常に接頭辞を付けます。
- `'prefix_and_default'` — `prefix` と同様ですが、デフォルトロケールには接頭辞なしでもアクセスできます。

戦略ごとの URL とリダイレクト：[ルーティング戦略](/ja-jp/guide/strategy)。

#### `globalLocaleRoutes` {#globallocaleroutes}

**型** `GlobalLocaleRoutes` · **デフォルト** `{}`

グローバルなルートレベルのロケール設定。
コンポーネントを変更せずに、特定のページのロケールルートを
制限またはカスタマイズできます。

- `false` — ルートをローカライズの対象外にします。
- `Record<LocaleCode, string>` — ロケールごとのカスタムパス。

キーはルート名またはパスです。通常は [`$defineI18nRoute`](/ja-jp/guide/per-component-translations) でページごとに設定します。

```ts
globalLocaleRoutes: {
  about: { en: '/about-us', de: '/ueber-uns' },
  'admin-dashboard': false, // not localized
}
```

詳細、動的セグメント、`pages:extend` のルート：[ローカライズされたパス](/ja-jp/guide/custom-locale-routes)。

#### `routeLocales` {#routelocales}

**型** `Record<string, string[]>` · **デフォルト** —

ルートごとのロケール制限。ビルド時に `$defineI18nRoute()` の呼び出しから抽出されます。
ルートパス（例：`'/about'`）を許可されたロケールコードの配列にマッピングします。
記載のないルートには制限がありません（すべてのロケールが許可されます）。

#### `routeDisableMeta` {#routedisablemeta}

**型** `Record<string, boolean \| string[]>` · **デフォルト** —

ルートごとのメタタグの無効化。ルート名またはパスを `true`（すべてのメタを無効化）、
またはメタを無効化するロケールコードの配列にマッピングします。ビルド時に `$defineI18nRoute()`
の呼び出しで見つかったエントリが追加されます。

#### `customRegexMatcher` {#customregexmatcher}

**型** `string \| RegExp` · **デフォルト** `undefined (uses built-in pattern based on locale codes)`

URL セグメント内のロケールコードを照合するためのカスタム正規表現（またはその文字列ソース）。
`locales` のすべてのロケールコードが、フラグを除いたパターン全体に一致する必要があり、一致しない場合はビルドが失敗します。

```ts
customRegexMatcher: '[a-z]{2}-[a-z]{2}', // en-us, de-at
```

#### `excludePatterns` {#excludepatterns}

**型** `(string \| RegExp)[]` · **デフォルト** `undefined`

i18n ルーティングから除外するパス：文字列はパスの接頭辞（`/admin` は `/admin/x` を含む）
または `*` / `?` のグロブで、RegExp はパスに対してテストされます。一致したページにはロケールの
バリアント、ロケールのリダイレクトや 404 がなく、プリレンダリングから除外されますが、
翻訳付きで描画されます。`/api`、`/_nuxt`、`/__*`、翻訳ルート、一般的な静的ファイル
（sitemap、robots.txt、favicon、拡張子によるアセット）は常に除外されます。

```ts
excludePatterns: ['/admin', '/docs/*', /^\/preview\//],
```

詳細：[パスの除外](/ja-jp/guide/excluding-static-files)。

#### `localizedRouteNamePrefix` {#localizedroutenameprefix}

**型** `string` · **デフォルト** `'localized-'`

ローカライズされたルート名の先頭に付加される接頭辞（例：`'localized-index'`）。
元のルートと生成されたロケールのバリアントを区別するために内部で使用されます。

#### `trailingSlash` {#trailingslash}

**型** `'append' \| 'remove'` · **デフォルト** `undefined (inherit from Nuxt)`

`$localePath` / `$switchLocalePath` の末尾スラッシュ（NuxtLink と同等）。
未設定の場合は `experimental.defaults.nuxtLink.trailingSlash` がデフォルトになります。
i18n のパスヘルパーで Nuxt のリンクのデフォルトを上書きするには、明示的に設定してください。

### 翻訳 {#translations}

#### `translationDir` {#translationdir}

**型** `string` · **デフォルト** `'locales'`

翻訳 JSON ファイルを含むディレクトリへの、プロジェクトルートからの相対パス。

`app/` ではなく、各レイヤーのルートからの相対パスです（Nuxt 4 のレイアウトでは `'app/locales'`）。ファイル構成：[翻訳ファイル](/ja-jp/guide/translations)。

#### `additionalTranslationDirs` {#additionaltranslationdirs}

**型** `string[]` · **デフォルト** `[]`

追加のディレクトリ（プロジェクトルート／各 Nuxt レイヤーのルートからの相対パス）。そのトップレベルの
`{locale}.json` ファイルは、`translationDir` より前にグローバル辞書へディープマージされます。

マージ順：配列内の各エントリの順（レイヤーをまたいで）、次に `translationDir`（競合時に優先）。
ルートの `{locale}.json` ファイルのみが読み込まれます — これらのディレクトリ配下の `pages/` は無視されます。

例：`translationDir: 'frontend'`、`additionalTranslationDirs: ['common']` → `common/en.json`、次に `frontend/en.json`。

#### `disablePageLocales` {#disablepagelocales}

**型** `boolean` · **デフォルト** `false`

ページごとの翻訳ファイルを無効にします。
`true` の場合、グローバルな翻訳（`{locale}.json`）のみが読み込まれ、
ページ固有のファイル（`pages/{page}/{locale}.json`）は生成も読み込みもされません。

#### `fallbackLocale` {#fallbacklocale}

**型** `string` · **デフォルト** `undefined (no fallback; returns the raw key)`

グローバルなフォールバックロケールのコード。
あるロケールで不足しているキーは、このロケールから取得されます（各ペイロードのビルド時または
読み込み時にマージされます）。これがない場合、不足しているキーはキーそのものとして描画されます。

#### `routesLocaleLinks` {#routeslocalelinks}

**型** `{ [key: string]: string }` · **デフォルト** `{}`

ルート名を別のルート名にマッピングして、同じ翻訳ファイルを共有します。
例えば、`{ 'about-us': 'about' }` は、`about-us` ページが自身の翻訳ではなく
`about` ページの翻訳を使用することを意味します。

```ts
routesLocaleLinks: { 'products-id': 'products' },
```

#### `plural` {#plural}

**型** `PluralFunc` · **デフォルト** ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)``

カスタムの複数形関数。
`(key, count, params, locale, getter)` を受け取り、選択された複数形を文字列で返すか、
組み込みの `defaultPlural` ロジックにフォールバックする場合は `null`/`undefined` を返します
（一部のロケールだけを上書きできます）。

Nuxt モジュールでは、関数は `.toString()` で `.nuxt/i18n.plural.mjs` に
シリアライズされます — 自己完結している必要があります（インポートや外側のスコープは不可）。
ファイルパスの文字列はサポート**されません**。

組み込みのルールとその `=0 ` マーカーについては [`$tc`](/ja-jp/api/methods#$tc) で説明しています。あなたの関数は、それが応答するものについて組み込みのルールを置き換え、マーカーを含む生の値を受け取ります。`null` を返すと呼び出しは組み込みのルールに戻されます。関数は `(key, count, params, locale, getter)` を受け取り、`getter(key)` はすべての形を含む生の文字列を返します。自己完結した `function` またはアロー関数式として記述してください（メソッドの短縮記法、インポート、外側の変数は不可）。

```ts
plural: function (key, count, params, locale, getter) {
  if (!locale.startsWith('en')) return null // built-in rule for other locales
  const forms = String(getter(key) ?? '').split('|').map((form) => form.trim())
  const index = count === 0 ? 0 : count === 1 ? 1 : 2
  return (forms[Math.min(index, forms.length - 1)] ?? '').replace('{count}', String(count))
},
```

```json
{ "apples": "no apples | one apple | {count} apples" }
```

#### `numberFormats` {#numberformats}

**型** `Record<string, Record<string, Intl.NumberFormatOptions>>` · **デフォルト** —

ロケールごとの名前付き数値フォーマット（Vue I18n 互換）。
`$tn(1000, 'currency')` 形式の呼び出しを可能にします。

[`$tn`](/ja-jp/api/methods#$tn) で使用されます。

#### `datetimeFormats` {#datetimeformats}

**型** `Record<string, Record<string, Intl.DateTimeFormatOptions>>` · **デフォルト** —

ロケールごとの名前付き日時フォーマット（Vue I18n 互換の `datetimeFormats`）。
`$td(date, 'short')` 形式の呼び出しを可能にします。

[`$td`](/ja-jp/api/methods#$td) で使用されます。

#### `timeZone` {#timezone}

**型** `string` · **デフォルト** `the runtime's zone`

`$td` と `<i18n-t date>` の IANA タイムゾーン（`Europe/Berlin`）。サーバーとすべてのブラウザーで

#### `disableWatcher` {#disablewatcher}

**型** `boolean` · **デフォルト** `false`

開発モードで不足している翻訳ファイルを自動作成するファイルウォッチャーを無効にします。

#### `missingWarn` {#missingwarn}

**型** `boolean` · **デフォルト** `true`

### ペイロードとキャッシュ {#payloads-and-caching}

#### `translationPayloads` {#translationpayloads}

**型** `TranslationPayloadOptions` · **デフォルト** —

翻訳ペイロードの出力方法を制御します（Node サーバー：`public/<apiBaseUrl>`、Edge / function / inline：Nitro の `serverAssets`）。

- **Node サーバー**（`node-server`、`node-cluster`、ディスクの `serveStatic`）：`serverAssets` は `public/` 配下の `readFile` によるローカル SSR を意味します（Rollup の `raw:` なし）。
- **Edge、function プリセット、`serveStatic: "inline"`**（`vercel`、`netlify`、`aws-lambda`、winterjs など）：`serverAssets` は Nitro の `serverAssets`（`assets:i18n`）を登録します。
  SSR からディスク上の `public/` を利用できないためです。パブリックコピーは強制しません — CDN／静的配信には `publicAssets: true` を設定してください。

通常のオールインワン構成ではデフォルトのままにしてください。大規模な Edge カタログでは `mode: 'source'` を推奨します。
CDN を利用するデプロイでは、ローカル出力を無効にし、`apiBaseClientHost` / `apiBaseServerHost` を設定してください。

サブオプションは[ペイロードとキャッシュ](#payloads-and-caching)の表にあります。Node、サーバーレス、Edge、静的ホスティング、CDN にどの組み合わせが適しているか：[デプロイ](/ja-jp/guide/deployment)。

#### `apiBaseUrl` {#apibaseurl}

**型** `string` · **デフォルト** `'_locales'`

翻訳 API ルートのベース URL パスセグメント（SSR/SSG のデータ取得で使用）。
環境変数 `NUXT_I18N_APP_BASE_URL` でも設定できます。

ペイロードの URL は `/{apiBaseUrl}/{page}/{locale}/data.json` です。

#### `apiBaseClientHost` {#apibaseclienthost}

**型** `string` · **デフォルト** `undefined`

クライアントサイドの翻訳取得リクエストに使用するホストを上書きします。
クライアントが Nuxt から見えるものとは異なるホスト名でサーバーにアクセスする場合に便利です。
環境変数 `NUXT_I18N_APP_BASE_CLIENT_HOST` でも設定できます。

#### `apiBaseServerHost` {#apibaseserverhost}

**型** `string` · **デフォルト** `undefined`

サーバーサイドの翻訳取得リクエストに使用するホストを上書きします。
サーバーが内部ホスト名で自身にアクセスするコンテナ／マイクロサービス構成で便利です。
環境変数 `NUXT_I18N_APP_BASE_SERVER_HOST` でも設定できます。

ホストは、組み込みのルートと同じ `/{apiBaseUrl}/{page}/{locale}/data.json` のレスポンスを提供する必要があります。

#### `dateBuild` {#datebuild}

**型** `string \| number` · **デフォルト** —

翻訳リクエストのキャッシュバスティングに使用する値（`?v=...`）。

指定しない場合、モジュールは翻訳ファイルのハッシュを使用するため、値は翻訳が変わったときにのみ
変わります（ハッシュを計算できない場合は `Date.now()`）。`0` または `''` でキャッシュバスティングを
無効にします。自分で固定するには、安定した値（git の SHA、ビルド番号）を設定してください。
辞書がその場で置き換えられた後、`NUXT_I18N_DATE_BUILD` または `runtimeConfig.public.i18nRuntime.dateBuild` がランタイムでこれを置き換えます：
固定された URL は再ビルドなしで置き去りにされます。

#### `httpCacheDuration` {#httpcacheduration}

**型** `number` · **デフォルト** `31536000`

`/{apiBaseUrl}/:page/:locale/data.json` の HTTP `Cache-Control` の max-age（秒）。

`dateBuild` が URL をバスティングしている間（`?v=...`、これがデフォルトです）にのみ完全に適用されます：
その場合レスポンスは `private, max-age=…, immutable` になります：ブラウザーはそれを固定しますが、クエリを無視する CDN は固定できません
（`httpCacheControl: false` の場合は `public`）。

- `dateBuild: 0`/`''` — URL が安定しているため、この期間は尊重*されません*。代わりに
  レスポンスは `public, max-age=0, must-revalidate` になります。変わらない URL に長い `max-age` を
  付けると、ブラウザーが最初に見たペイロードが固定されてしまいます。

- `0` — `Cache-Control` をまったく設定しません（ローカルでのデバッグに便利）
- 開発時（`import.meta.dev`）には適用されないため、HMR がブラウザーキャッシュと競合することはありません
- Nitro を通じて配信されるレスポンスにのみ届きます。`public/` にコピーされ、ホスティングプラットフォームが
  配信するペイロードには、そのプラットフォームのヘッダーが適用されます — パフォーマンスガイドを参照してください。

`@nuxtjs/i18n` の実験的な `httpCacheDuration`（v10.2.0）に相当しますが、Nitro の
`defineCachedEventHandler` の maxAge ではなく、明示的なレスポンスヘッダーとして実装されています。

#### `cacheMaxSize` {#cachemaxsize}

**型** `number` · **デフォルト** `0`

メモリ内の翻訳キャッシュの最大エントリ数。fetch キャッシュとサーバーキャッシュは
最も長く使われていないエントリを破棄し、ブラウザーの辞書マップは最も古いものを破棄します（FIFO）。
`0` はブラウザーでは無制限を意味し、その場合サーバーキャッシュは最大 1000 エントリを保持するため、
でっち上げのページ名を含むリクエスト URL によってサーバーのメモリが増えることはありません。

#### `cacheTtl` {#cachettl}

**型** `number` · **デフォルト** `0`

fetch とサーバーの翻訳キャッシュの有効期間（秒）。エントリが保存された時点から数えられ
（読み取りでは延長されません）、`apiBaseServerHost` からのデータは少なくともその頻度で
更新されます。ブラウザーのアクティブな辞書はこれによって期限切れになりません。`0` はエントリが
期限切れにならないことを意味します。

両者がランタイムで何を変えるか：[パフォーマンス](/ja-jp/guide/performance)。

#### `serverTranslationPreload` {#servertranslationpreload}

**型** `boolean` · **デフォルト** `false`

Nitro のグローバルミドルウェアでインデックスページの翻訳をプリロードします（サーバー専用、プライベート設定）。

### SEO {#seo}

#### `meta` {#meta}

**型** `boolean` · **デフォルト** `true`

SEO メタタグ（`hreflang`、`canonical`、`og:url`、`og:locale`）を自動的に生成します。

ページごとの上書き：[`useI18nHead`](/ja-jp/composables/useI18nHead)。その他すべて：[SEO](/ja-jp/guide/seo)。

#### `metaBaseUrl` {#metabaseurl}

**型** `string` · **デフォルト** `undefined`

SEO メタタグ（canonical、og:url、hreflang）のベース URL。

- 具体的な URL 文字列（例：`'https://example.com'`） — そのまま使用されます（最優先）。
- `undefined` — `nuxt-site-config` モジュールが存在する場合はその `site.url` に、
  なければ現在のリクエストのオリジン
  （サーバーでは `useRequestURL().origin`、クライアントでは `window.location.origin`）にフォールバックします。

#### `metaTrustForwardedHost` {#metatrustforwardedhost}

**型** `boolean` · **デフォルト** `true`

メタタグのベース URL を解決する際に `X-Forwarded-Host` ヘッダーを信頼します。
このヘッダーを実際のクライアント向けホスト名に設定するリバースプロキシ（nginx、Cloudflare、AWS ALB など）の
背後でアプリが動作する場合に有効にしてください。

`metaBaseUrl` も `site.url` も設定されていない場合にのみ読み取られます。ヘッダーを上書きするプロキシを経由せずにアプリにアクセスできる場合は `false` に設定してください：そうしないと、クライアントが canonical URL のホストを選択できてしまいます。

#### `metaTrustForwardedProto` {#metatrustforwardedproto}

**型** `boolean` · **デフォルト** `true`

メタタグのプロトコルを解決する際に `X-Forwarded-Proto` ヘッダーを信頼します。
TLS を終端するプロキシの背後でアプリが動作する場合に有効にすると、
アプリ自体が HTTP で待ち受けていても canonical URL に `https://` が使用されます。

適用範囲は `metaTrustForwardedHost` と同じです。

#### `trustForwardedHost` {#trustforwardedhost}

**型** `boolean` · **デフォルト** `false`

リクエストのドメイン（`locales[].baseUrl`）を `Host` ではなく `X-Forwarded-Host` から
選択します。そのヘッダーを上書きするプロキシの背後でのみ有効にしてください。

`metaTrustForwardedHost` とは別で、デフォルトでは無効です：ここではヘッダーがタグのオリジンだけでなく、別のドメインのロケールを選択することになるためです。[レイヤーとドメイン](/ja-jp/guide/layers#multiple-domains)を参照してください。

#### `hreflangBaseLanguage` {#hreflangbaselanguage}

**型** `boolean` · **デフォルト** `false`

各ロケールの `iso` から派生した、言語のみの `hreflang` も出力します
（例：`es-ES` → `es` も）。`locales` 内で最初の地域ロケールが、その言語の
言語のみのタグを担当します。ルーティング用の `code` は使用されません — `iso || code` のみです。

#### `canonicalQueryWhitelist` {#canonicalquerywhitelist}

**型** `string[]` · **デフォルト** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

canonical および `og:url` メタタグに保持されるクエリパラメーター名のリスト。
このリストにないパラメーターは canonical URL から取り除かれます。

### 検出とリダイレクト {#detection-and-redirects}

これらのオプションが関わるルール：[ロケール検出](/ja-jp/guide/locale-detection)。

#### `redirects` {#redirects}

**型** `boolean` · **デフォルト** `true`

自動的なロケールリダイレクト（サーバープラグインとクライアントのルートミドルウェア）を有効にします。
`true` の場合、接頭辞を使う戦略では接頭辞のない URL をローカライズされた形にリダイレクトします。ロケールは
アプリの状態、Cookie、または `autoDetectPath` が許可する場所では `Accept-Language` から決まり、それ以外は
デフォルトになります。`no_prefix` では検出によって URL が変わることはありません（カスタムパスについては `noPrefixRedirect` を参照）。

`false` の場合、クライアントのリダイレクトミドルウェアは登録されません。サーバープラグインは引き続き、無効なロケールの URL に 404 を返し、接頭辞付きの URL に対して Cookie を書き込みます。

#### `autoDetectLanguage` {#autodetectlanguage}

**型** `boolean` · **デフォルト** `true`

`Accept-Language` HTTP ヘッダーからユーザーの優先言語を自動的に検出します。
`autoDetectPath` と組み合わせて、検出を行うタイミングを決定します。

#### `autoDetectPath` {#autodetectpath}

**型** `string` · **デフォルト** `'/'`

Cookie / Accept-Language の設定によるリダイレクトを実行できる場所（`redirects` が有効な場合）。

- `'/'` — `/` のみ（デフォルトロケールのディープリンクには引き続きアクセス可能。デフォルト）
- `'no_prefix'` — ロケール接頭辞のないパスのみ
- `'*'` — 明示的なロケール接頭辞の書き換えを含むすべてのパス
  （例：Cookie が `de` を優先する場合、`/fr/about` → `/de/about`）

- その他の文字列 — そのパス。末尾のスラッシュは無視されます（例：`'/welcome'`）

`prefix` では、許可されたパス以外の接頭辞のない URL も、デフォルトロケールの形に
リダイレクトされます（`/about` → `/en/about`）。`prefix_except_default` で接頭辞付きの
デフォルトロケール（`/en`）は、リダイレクトではなく 404 になります。

#### `localeCookie` {#localecookie}

**型** `string \| null` · **デフォルト** `null`

セッションをまたいでユーザーのロケール設定を保持するための Cookie 名。
`null` に設定すると Cookie による保持を無効にします。
指定がない場合、`no_prefix` 戦略では自動的に `'user-locale'` が設定されます。`i18n` 設定ブロックで明示的に
`null` を指定すると、そこでも無効のままになります。

Cookie がなくても `Accept-Language` によってリダイレクトは行われます。Cookie は訪問をまたいで選択を記憶します。

#### `noPrefixRedirect` {#noprefixredirect}

**型** `boolean` · **デフォルト** `false`

`no_prefix` 戦略の場合：デフォルトロケールがページのカスタムパスを持つとき
（`localeRoutes` / `globalLocaleRoutes`）、ページの元のパスを訪問者のロケールのカスタムパス、
なければデフォルトロケールのカスタムパスにリダイレクトします（例：`/about` → `/about-us`）。
独自のカスタムパスを持たないロケールは元のパスのままです。動的セグメントを
持つページはリダイレクトされません。

### 登録と開発 {#registration-and-development}

#### `plugin` {#plugin}

**型** `boolean` · **デフォルト** `true`

`$t()`、`$tc()`、`$getLocale()`、`$switchLocale()` などのランタイムヘルパーを
提供するコア i18n プラグインを登録します。

#### `define` {#define}

**型** `boolean` · **デフォルト** `true`

ランタイムで `$defineI18nRoute()` を提供します。いずれの場合も、ビルドはページ内の
`$defineI18nRoute()` の呼び出しを読み取ります。

#### `hooks` {#hooks}

**型** `boolean` · **デフォルト** `true`

読み込み時とナビゲーション時に `i18n:register` アプリフックを呼び出し、プラグインが翻訳を追加できるようにします。

[フック](/ja-jp/api/events)を参照してください。

#### `components` {#components}

**型** `boolean` · **デフォルト** `true`

組み込みの i18n コンポーネント（`<i18n-link>`、`<i18n-switcher>`、`<i18n-t>`、`<i18n-group>`）を登録します。
`false` に設定すると、コンポーネントの自動登録を無効にします（例：使用しておらず、
モジュールのフットプリントを減らしたい場合）。

#### `types` {#types}

**型** `boolean` · **デフォルト** `true`

デフォルトロケールのファイル内の翻訳キーに基づいて、`useI18n`、`$t`、関連ヘルパーの
TypeScript 型宣言を生成します。

[`@i18n-micro/types-generator`](/ja-jp/integrations/types-generator) パッケージとは別のものです。

#### `hmr` {#hmr}

**型** `boolean` · **デフォルト** `true`

開発時に翻訳ファイルの Hot Module Replacement を有効にします。
`true` の場合、JSON 翻訳ファイルの変更により、ページ全体を更新することなく
自動的に再読み込みされます。

#### `debug` {#debug}

**型** `boolean` · **デフォルト** `false`

ロケール検出、ルート生成、翻訳の読み込みに関する詳細なデバッグログを有効にします。

#### `vueDevtools` {#vuedevtools}

**型** `boolean` · **デフォルト** `true`

開発時に Vue DevTools のインスペクターとタイムラインを登録します（ブラウザー拡張機能）。
Nuxt DevTools のカスタムタブとは別です。

#### `experimental` {#experimental}

**型** `Record<string, unknown>` · **デフォルト** —

実験的／不安定なオプションのための入れ物。
内容はマイナーバージョン間で予告なく変更または削除される可能性があります。
