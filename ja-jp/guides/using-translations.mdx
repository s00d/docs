# コンポーネントでの翻訳の使い方

モジュールをインストールして設定したら、Vue のテンプレートやスクリプト内で `$t('your_key')` を呼び出すことで翻訳を表示できます。

## 1. ルートレベルとページ固有の翻訳ファイル

1. **ルートレベル**の翻訳は `/locales` フォルダー直下に配置します(例: `/locales/en.json`、`/locales/fr.json`)。ビルド時に、これらは自動的にすべてのページ固有ファイルへマージされ、すべてのページで利用可能になります。
2. **ページ固有**の翻訳は、Nuxt のページフォルダー構造に対応する `/locales/pages/...` 配下に配置します:

```text
locales/
├── en.json
├── fr.json
└── pages/
    └── dir1/
        ├── en.json
        └── fr.json

```

## 2. テンプレート内での `$t` の使い方

`.vue` ファイル内では、テンプレートで `$t` を直接使用できます:

```vue
<template>
  <div>
    <!-- Root-level translation (available on all pages) -->
    <p>{{ $t('test_key') }}</p>
    <!-- Displays: Hello World! -->

    <!-- Page-specific translation (if this page is /dir1) -->
    <p>{{ $t('local_key') }}</p>
    <!-- Displays: This is a page-specific translation for /dir1. -->

    <!-- Nested key -->
    <p>{{ $t('nested.key.deeper') }}</p>
    <!-- Displays: Nested translation here -->

    <!-- Placeholder usage -->
    <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
    <!-- Displays: Hello, Alice! -->
  </div>
</template>

<script setup lang="ts">
// No need to import anything from 'nuxt-i18n-micro'.
// The plugin automatically provides `useI18n` and `$t`.
const { $t } = useI18n()

// You can now use $t in your script, for example:
console.log($t('test_key')) // "Hello World!"
</script>
```

<Tip>
`$t` は、キーがネストされた JSON ノード(例: `$t('header')` → `\{ title: "Hi" \}`)を指す場合、**オブジェクト**を返すことがあります。テンプレートでは `[object Object]` として表示されます。文字列を保証したい場合は `$ts` を使うか、`$t('header.title')` のようにより具体的なキーを指定してください。詳細は [API リファレンス — $t と $ts の比較](/api/methods#t) を参照してください。
</Tip>

## 3. 現在のロケールの切り替え

アプリケーションの言語を変更するには、`useI18n()` から `$locale` を取得し、新しいコードを割り当てます:

```vue
<template>
  <div>
    <button @click="$switchLocale('en')">English</button>
    <button @click="$switchLocale('fr')">Français</button>
  </div>
</template>

<script setup lang="ts">
// The plugin auto-injects these references
const { $t, $switchLocale } = useI18n()
</script>
```

## 4. ネストされたキーとプレースホルダー

- **ネストされたキー**はドット記法を使います(例: `nested.key.deeper`)。
- **プレースホルダー**を使うと動的な値を挿入できます:
  ```json
  { "greeting": "Hello, {name}!" }
  ```
  ```vue
  <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
  <!-- Displays: Hello, Alice! -->
  ```

## 5. ヒントとベストプラクティス

- **競合するキー**: ページ固有のファイルにルートレベルと同じキーが含まれている場合、ページ固有のバージョンが優先されます(ルート翻訳はビルド時にベースとしてマージされます)。
- **ページファイルを無効化する**: ページ固有の翻訳を使いたくない場合、Nuxt の設定で `disablePageLocales: true` を設定できます。これにより、`/locales/*.json` ファイルのみが使用されます。
- **直接インポート不要**: `import \{ useI18n \} from 'nuxt-i18n-micro'` を書く必要はありません。モジュールの自動注入機能が処理します。

以上です。この手順により、ルートレベルまたはページ固有の JSON ファイルから翻訳を取得し、`$t` を使って Nuxt アプリケーションに素早く**表示**できます。

## 追加リソース

より高度な機能を探求するには、以下も確認してください:

1. **`<i18n-t>` コンポーネント**  
   `<i18n-t>` コンポーネントは `$t` に代わる強力な手段で、特に入れ子要素、高度なプレースホルダーの使用、複雑な翻訳構造を扱う場合に便利です。

- **ドキュメント**: [i18n-t](/api/components/i18n-t)

2. **`useI18n` コンポーザブル**  
   `useI18n` コンポーザブルは、翻訳の管理、ロケール切り替え、書式設定などのための一通りの関数とリアクティブなプロパティを提供します。

- **ドキュメント**: [useI18n](/api/composables/use-i18n)
