# 静的ファイルを i18n ルーティングから除外する

## 概要

デフォルトで、nuxt-i18n-micro は一般的な静的ファイルを i18n ルーティング処理から自動的に除外します。ただし、特定のパスが i18n システムで処理されないように、カスタム除外パターンを設定することもできます。

## 組み込みの除外

モジュールは次のファイル種別とパターンを自動的に除外します:

- **サイトマップ**: `/sitemap*.xml`、`/sitemap-en.xml` など
- **SEO ファイル**: `/robots.txt`、`/favicon.ico`
- **PWA ファイル**: `/manifest.json`、`/sw.js`、`/workbox-*.js`
- **静的アセット**: `.xml`、`.txt`、`.ico`、`.json`、`.js`、`.css`、`.png`、`.jpg`、`.jpeg`、`.gif`、`.svg`、`.woff`、`.woff2`、`.ttf`、`.eot` などの拡張子を持つファイル
- **Nuxt 内部パス**: `__` で始まるパス(例: `/__nuxt/`)

## カスタム除外パターン

`excludePatterns` オプションを使用して、カスタムの除外パターンを定義できます:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## パターンの種類

### 文字列パターン

- **完全一致**: `'/api/health'` — `/api/health` に完全一致します
- **プレフィックス一致**: `'/admin'` — `/admin` と `/admin/dashboard` に一致します
- **ワイルドカード**: `'/api/*'` — `/api/users` に一致しますが、`/api/users/123` には一致しません
- **深いワイルドカード**: `'/admin/**'` — `/admin/users` と `/admin/users/123` に一致します

### 正規表現

複雑なパターンマッチングには RegExp オブジェクトを使用します:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## ユースケース

### SEO ファイル

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API ルート

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### 管理パネル

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### 静的アセット

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## 仕組み

1. **サーバーミドルウェア**: Nitro のミドルウェアが最初に実行され、除外パターンをチェックします
2. **ページ処理**: ページ解決の段階で、除外対象のパスはスキップされます
3. **キャッチオールルート**: フォールバックルートは、処理前に除外を確認します
4. **プリレンダリング**: 除外対象のパスはプリレンダリングされたルートに含まれません

## パフォーマンスへの影響

- 除外チェックは最適化されており、リクエストのライフサイクルの早い段階で実行されます
- 組み込みパターンは効率的な正規表現マッチングを使用します
- カスタムパターンはキャッシュされ、再利用されます
- 除外パスに対するパフォーマンスのオーバーヘッドは最小限です

## トラブルシューティング

### 静的ファイルが依然としてインターセプトされる

1. **パターン構文を確認する**: パターンが実際のパス構造と一致していることを確認してください
2. **複雑なパターンには正規表現を使用する**: 文字列ワイルドカードには制限があります
3. **パターンをテストする**: ブラウザの開発者ツールで実際のリクエストパスを確認してください
4. **順序を確認する**: 除外パターンが他の i18n 設定より前に定義されていることを確認してください

### パターンが機能しない

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### デバッグモード

デバッグモードを有効にすると、除外処理の様子を確認できます:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

これにより、除外の判定がコンソールにログとして出力されます。

## 回避策からの移行

route rules やミドルウェアなどの回避策を利用していた場合は、`excludePatterns` で置き換えられます:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

新しいアプローチはより信頼性が高く、ルーティングシステムの複数のレベルで動作します。
