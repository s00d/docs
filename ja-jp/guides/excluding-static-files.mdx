# 静的ファイルを i18n ルーティングから除外する

## 概要

nuxt-i18n-micro はデフォルトで、一般的な静的ファイルを自動的に i18n ルーティング処理から除外します。ただし、カスタム除外パターンを設定して、特定のパスが i18n システムで処理されないようにすることもできます。

## 組み込みの除外

モジュールは以下のファイル種別とパターンを自動的に除外します。

- **サイトマップ**: `/sitemap*.xml`、`/sitemap-en.xml` など
- **SEO ファイル**: `/robots.txt`、`/favicon.ico`
- **PWA ファイル**: `/manifest.json`、`/sw.js`、`/workbox-*.js`
- **静的アセット**: `.xml`、`.txt`、`.ico`、`.json`、`.js`、`.css`、`.png`、`.jpg`、`.jpeg`、`.gif`、`.svg`、`.woff`、`.woff2`、`.ttf`、`.eot` などの拡張子を持つファイル
- **Nuxt の内部パス**: `__` で始まる任意のパス(`/__nuxt/` など)

## カスタム除外パターン

`excludePatterns` オプションを使ってカスタム除外パターンを定義できます。

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // カスタム除外パターン
    excludePatterns: [
      // 文字列パターン(完全一致またはプレフィックス)
      '/api/health',
      '/admin',

      // ワイルドカード付き文字列パターン
      '/api/*',
      '/admin/**',

      // 正規表現
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## パターンの種類

### 文字列パターン

- **完全一致**: `'/api/health'` — `/api/health` と完全に一致します。
- **プレフィックス一致**: `'/admin'` — `/admin` と `/admin/dashboard` に一致します。
- **ワイルドカード**: `'/api/*'` — `/api/users` に一致しますが、`/api/users/123` には一致しません。
- **ディープワイルドカード**: `'/admin/**'` — `/admin/users` と `/admin/users/123` に一致します。

### 正規表現

複雑なパターンマッチングには RegExp オブジェクトを使用します。

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // バージョン付き API ルート
  /\.(pdf|doc|docx)$/, // ドキュメントファイル
  /^\/static\//, // 静的ディレクトリ
  /^\/[a-z]{2}\/api\//, // ローカライズされた API ルート
]
```

## ユースケース

### SEO ファイル

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API ルート

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### 管理パネル

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### 静的アセット

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## 動作の仕組み

1. **サーバーミドルウェア**: Nitro のミドルウェアが最初に実行され、除外パターンをチェックします。
2. **ページ処理**: ページ解決中、除外されたパスはスキップされます。
3. **キャッチオールルート**: フォールバックルートは処理前に除外を確認します。
4. **プリレンダリング**: 除外されたパスはプリレンダーされたルートに含まれません。

## パフォーマンスへの影響

- 除外チェックは最適化され、リクエストライフサイクルの早い段階で実行されます。
- 組み込みパターンは効率的な正規表現マッチングを使用します。
- カスタムパターンはキャッシュされて再利用されます。
- 除外されたパスに対するパフォーマンスオーバーヘッドは最小限です。

## トラブルシューティング

### 静的ファイルが依然としてインターセプトされる

1. **パターン構文の確認**: パターンが正確なパス構造と一致することを確認してください。
2. **複雑なパターンには正規表現を使用**: 文字列ワイルドカードには制限があります。
3. **パターンのテスト**: ブラウザの開発ツールで実際のリクエストパスを確認してください。
4. **順序の確認**: 他の i18n 設定より前に除外パターンが定義されていることを確認してください。

### パターンが機能しない

```typescript
// ❌ 誤り — これは動作しません
excludePatterns: ['sitemap.xml']

// ✅ 正しい — 先頭のスラッシュを含めます
excludePatterns: ['/sitemap.xml']

// ✅ より良い — 柔軟性のために正規表現を使用します
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### デバッグモード

除外処理を確認するにはデバッグモードを有効にします。

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

これにより、除外の判定がコンソールにログ出力されます。

## 回避策からの移行

ルートルールやミドルウェアなどの回避策を使用していた場合は、`excludePatterns` に置き換えられます。

```typescript
// ❌ 古い回避策
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ 新しいアプローチ
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

新しいアプローチはより信頼性が高く、ルーティングシステムの複数のレベルで機能します。
