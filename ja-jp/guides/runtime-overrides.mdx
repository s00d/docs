# ランタイム i18n オーバーライド

環境ごとに異なるロケールデフォルトで単一のビルド成果物を実行する必要がある場合(例: マルチテナントの複数インスタンス)には、このガイドを使用してください。

## ランタイムでオーバーライドできる項目

このモジュールは、次の項目について安全なランタイムオーバーライドをサポートしています:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

これらのオーバーライドは、`.nuxt/i18n.strategy.mjs` と `.nuxt/i18n.config.mjs` によるビルド時設定の上に適用されます。

## ランタイムでオーバーライドできない項目

`strategy`(`no_prefix`、`prefix`、`prefix_except_default`、`prefix_and_default`)は、生成されるルート挙動に影響するためビルド時の関心事です。

ランタイムで `strategy` のオーバーライドを渡した場合、無視され、警告が出力されます。

## RuntimeConfig ベースのオーバーライド

`runtimeConfig.public.i18nRuntime` にランタイム値を指定します:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## 環境変数によるオーバーライド

環境変数を通じてオーバーライドを設定することもできます:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES`(カンマ区切り、例: `fr,it`)

フォールバックのエイリアスもサポートされています:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## 検証ルール

ランタイムでは、モジュールが不整合な状態を防ぐためにオーバーライドを検証します:

- すべてのロケールを無効化することはできません。
- `defaultLocale` は有効なロケールを指す必要があります。
- `fallbackLocale` は宣言済みのロケールに存在する必要があります。

オーバーライドが無効な場合、モジュールは安全な値を保持し、警告をログに記録します。

## マルチインスタンスデプロイメント向けの注意事項

このランタイム機能は、再ビルドせずにインスタンスごとにロケールの有効化とデフォルトを設定することを目的としています。

インスタンスごとに異なる URL 戦略(`no_prefix` と `prefix` など)が必要な場合は、戦略ごとに別々のビルドを用意してください。

## 無効化されたロケールと静的ペイロード

`runtimeConfig.public.i18nRuntime.disabledLocales` はルーティング、スイッチャー、Nitro ペイロード**ハンドラー**を更新しますが、Nitro はそのハンドラーの**前に** `public/` 配下のファイルを配信します。

`translationPayloads.publicAssets`(または Node SSR で強制される public コピー)がすでに `/_locales/\{page\}/\{locale\}/data.json` を書き込んでいる場合、ランタイムでの無効化ではそのファイルを隠せません。ビルド時に `locale.disabled: true` を設定して、事前マージ時にそのロケールの静的ペイロードが生成されないようにするのが好ましいです。
