**日付**: 2026-11-03

**バージョン**: `v4.0.0`

![v4.0.0 release](/images/4.0.0.png)

**v4.0.0** をリリースしました。ルーティング、翻訳コア、辞書ファイル、ロケール検出、そしてすべてのフレームワークパッケージが書き直されました。オプション、`$t`、`$localePath`、`$switchLocale`、コンポーネント、コンポーザブルの名前はそのままです。変わるのは動作であり、その変更の大半はバグの解消です。ほとんどのアプリではコードの変更はわずかで済みますが、アップグレード前に[破壊的変更](#breaking-changes)をお読みください。URL、SEO タグ、フレームワークパッケージの API は一部変更されています。すべての詳細は[アップグレード](/ja-jp/guide/upgrade)にあります。

## 新機能 {#what’s-new}

### すべてのドメインに 1 つのビルド {#one-build-for-every-domain}

`locales[].baseUrl` と `baseDefault` は、以前はリンクの形成にのみ使われていました。現在は、4 つの戦略すべてと `nuxt generate` において、リクエストのルーティングにも使われます:

```ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'fr', baseUrl: 'https://example.com' },
      { code: 'de', baseUrl: 'https://example.de', baseDefault: true },
    ],
  },
})
```

- ホストは自身のロケールを配信します。他のドメインのロケールへのリンクはそのドメイン上の絶対 URL になり、そのロケールへ切り替えるとそこへ遷移します。
- `trustForwardedHost` は、`X-Forwarded-Host` を上書きするプロキシの背後で、そのヘッダーからドメインを選択します。デフォルトでは無効です。
- `NUXT_I18N_DOMAIN` は `nuxt generate` にホストを与えます。ドメインごとに 1 回実行すると、各出力にはそのドメインのページと辞書のみが含まれます。
- `baseUrl` のないアプリには、このコードは一切含まれません。

[レイヤーとドメイン](/ja-jp/guide/layers#multiple-domains)と[デプロイ](/ja-jp/guide/deployment)を参照してください。

### ルーターと一致するルーティング {#routing-that-agrees-with-the-router}

ビルドとランタイムが、ローカライズされた URL を別々に算出することはなくなりました。すべての答えはビルドが生成したルートから得られるため、リンク、スイッチャー、`hreflang`、リダイレクトが存在しないページを指すことはありません。

- あるページを配信しないロケールは、他のロケールのページではなく、自身のホームにリンクします。
- `hreflang` には、そのページを配信するロケールのみが列挙されます。
- `$switchLocale` は `true` または `false` で解決されるため、辞書の読み込みに失敗したことがわかります。再度呼び出すとリトライします。
- SSR 中に設定された `$setI18nRouteParams` と `useI18nHead` はハイドレーション後も維持されます。スイッチャーは、サーバー HTML でも翻訳済みのスラッグにリンクします。
- ナビゲーションは確定した時点で反映されます。キャンセルまたはブロックされたナビゲーションは何も変更しません。
- `prefix` でハッシュモードが動作します。
- サーバーコンポーネントでの `<Greeting :locale="$getLocale()" />` は、そのレンダリングロケールを設定します。

### 1 つのロケール検出 {#one-locale-detection}

サーバー、ブラウザー、サーバー API ヘルパー、Astro のどこでも同じ順序が使われます。`Accept-Language` は `q` 値を考慮し、地域による一致は `locales` の順序に依存しなくなり、中国語の異なる文字体系をまたいで一致することはありません。ランタイムオーバーライドがルーティングにも反映されるようになりました: `NUXT_I18N_DEFAULT_LOCALE` とランタイムの `disabledLocales` によって、実際に配信される内容が変わります。[ロケール検出](/ja-jp/guide/locale-detection)を参照してください。

### すべてのモードで 1 つの辞書 {#one-dictionary-in-every-mode}

事前マージされたビルド、`mode: 'source'`、開発環境では、多くのページで結果が食い違っていました。現在はすべて同じ辞書を返します。

- マージはすべての階層で深く行われ、フォールバックチェーン(`fr` → `de` → `en`)は最後まで辿られます。
- 開発環境での翻訳の編集は、ページをリロードせずにその場で反映されます。削除したキーは消え、ルートファイルの編集はすべてのページに反映されます。
- `$clearCache()` は現在のページを再読み込みし、新しいテキストが届くまで古いテキストを画面に残します。
- チャンクの読み込みに失敗しても、生のキーを表示する代わりに現在の辞書が維持されます。

### より小さな辞書ファイル {#smaller-dictionary-files}

- ページのファイルには、ロケールのルート(`__root/<locale>/data.json`)との差分のみが含まれるようになりました。ブラウザーはルートを一度だけ読み込み、各ページをその上にマージするため、ディスク使用量が減り、次のページのコストは最初のページのごく一部になります。
- 辞書の URL にはバージョンが付きます。現在の `?v=` を持つ URL は Node サーバー上で 1 年間固定され、ホストの静的コピーは `max-age=60` で応答します。[キャッシュヘッダー](/ja-jp/guide/deployment#cache-headers-and-datebuild)を参照してください。
- すべての SSR ページは辞書ファイルをプリロードするため、それらは HTML と同時に読み込みが始まります。
- 読み込みの失敗が残り続けることはなくなりました: 次のリクエストで再度読み込みます。[辞書を読み込めない場合](/ja-jp/guide/deployment#when-a-dictionary-cannot-be-read)を参照してください。

### より良い `<i18n-t>`、複数形、フォーマット {#better-&lt;i18n-t&gt;-plurals-and-formats}

- スロットが `plural`、`number`、`date`、`relativeDate` と組み合わせて動作し、最初のものだけでなくすべての `{name}` が埋められます。
- `<i18n-t>` は、Nuxt、Vue、React、Preact、Solid、Astro で共通の 1 つのレンダラーになりました。
- `=0 ` で始まる最初の形式は明示的なゼロ形式となり、残りは `Intl.PluralRules` に従います: `=0 no apples | one apple | {count} apples`。[`$tc`](/ja-jp/api/methods#$tc) を参照してください。
- 新しい `timeZone` オプション: サーバーとすべてのブラウザーで同じ暦日になります。
- `{firstName}`、`{first-name}`、`{user.name}` は有効なプレースホルダーです。
- `$tn`、`$td`、`$tdr` は、複数形と同様に `iso` に従います。
- `$tdr` は未来の日付を正しく返します: `in 3 days`、または `numeric: 'auto'` では `tomorrow`。

### デフォルトでより安全に {#safer-by-default}

- `<i18n-t html>` は `params` をエスケープします。信頼されたマークアップとして扱われるのは翻訳のみです。
- 意図せずオリジンの外へ出るリンクはありません: `//host`、`/\host`、空白はこのサイト内に留まります。
- サーバーの翻訳キャッシュには上限があるため、でっち上げたページ名を持つ URL でメモリが増え続けることはありません。
- DevTools の保存エンドポイントは、翻訳ディレクトリ内の既存の `.json` ファイルのみを受け付け、クロスサイトリクエストを拒否します。

### フレームワークパッケージが 2.0 に {#framework-packages-at-2-0}

- **React、Preact、Solid:** `I18nT` はリッチテキスト用の `components` prop を受け取ります。新しい `useT` と `useLocaleSwitch`、そして `@i18n-micro/react/server` と `/client` による React Server Components のサポート。Preact は `preact/compat` を必要としなくなりました。
- **Vue と VitePress:** `I18nLink` は `name`、`query`、`hash` を保持し、VitePress は `base` を尊重します。
- **Astro:** `i18nIntegration` が辞書をバンドルし、ミドルウェアをインストールします。メインのエントリーには `node:*` のインポートがないため、エッジで動作します。`base` も動作します。
- **Node と runtime:** `fork(locale)` は軽量なリクエストごとのインスタンスを返し、`@i18n-micro/node` の `run(locale, fn)` はインスタンスを 1 つのリクエストにスコープします。
- **`@i18n-micro/types-generator`:** サードパーティの依存関係がなくなり、プレーンな Vite および Rollup プラグインになりました。
- **`@i18n-micro/devtools-ui`:** Vite のソケットを通じたライブ更新と、Astro ツールバーアプリ。

### `@i18n-micro/cli` {#@i18n-micro/cli}

CLI はモノレポ内の `@i18n-micro/cli` に移り、28 個から 16 個のコマンドに書き直され、依存関係も大幅に減りました。`check` は `validate`、`diff`、`check-duplicates` を置き換え、CI 向けに `--json` と終了コードを備えています。キーが未使用であることを証明できない場合、`clean` は何も書き込みません。[CLI](/ja-jp/guide/cli) を参照してください。

### ドキュメント {#documentation}

ドキュメントは、インストール、最初の翻訳済みページ、翻訳ファイル、ルーティング、検出、そしてタスク別ガイドという 1 つの読み進め方に沿って、コードから書き直されました。古い URL はリダイレクトされます。[アップグレード](/ja-jp/guide/upgrade)にはすべての変更が詳しく列挙されています。

## 速度とサイズ {#speed-and-size}

- サーバーレンダリングは、ローカルの HTTP リクエストや再パースなしに、辞書を直接読み取ります。
- `dir="auto"` はデフォルトではなくなりました。大きなページではブラウザーがその処理に長い時間を費やします: 20,000 個の `$t` 要素がある場合、Chromium での DOMContentLoaded は約 980 ms から約 115 ms になりました。
- `serverTranslationPreload` と `i18n:register` がすべてのリクエストを遅くすることはなくなりました。
- Cookie が設定されていない場合、クライアントバンドルから `useCookie` が除かれ、`@i18n-micro/path-strategy` は以前のサイズのごく一部になりました。

**v3.30.3 との比較(テストアプリ)。** 生成された Nuxt アプリを 1 台の Node サーバーで、1 台の Mac 上で実行し、`wrk` で 24 接続・20 秒、ローテーションで 3 ラウンド、プレリリースビルドで計測しました。各行は別々の実行によるものなので、行内で比較してください。ハイドレーションは両方とも `dir: 'ltr'` を使用しています。

| 指標 | v3.30.3 | v4.0.0 |
| --- | ---: | ---: |
| 4 ロケール、10k カタログ: 1 秒あたりのリクエスト数 | 384-395 | 585-591 |
| 4 ロケール、10k カタログ: p95 レイテンシ | 106-110 ms | 70-72 ms |
| 4 ロケール、10k カタログ: リクエストあたりのサーバー CPU | 2.92-3.00 ms | 2.01-2.02 ms |
| 12 ロケール、100k カタログ: 1 秒あたりのリクエスト数 | 362-370 | 578-580 |
| 12 ロケール、100k カタログ: p95 レイテンシ | 115-117 ms | 72-73 ms |
| 12 ロケール、100k カタログ: リクエストあたりのサーバー CPU | 3.11-3.17 ms | 2.02-2.03 ms |
| ハイドレーション、100k ページ | 86-92 ms | 77-81 ms |
| このアプリのクライアント JS、gzip | 105.1 KB | 93.9 KB |
| `i18n:register` サブスクライバーありのリクエスト時間、100k チャンク | 96-108 ms | 1.7 ms |

100k カタログでの 30 分間の実行(より以前のプレリリースビルド)では、エラーなしで 113 万件のリクエストを処理し、ライブヒープは横ばいのままでした。

**v3.29.5(実際に稼働していたバージョン)との比較(3 つの本番アプリ)、** プレリリースビルドで計測。2 つは SSR サイト、1 つは SPA です。それぞれ 1 台の Node サーバーで、60 秒、8 接続、GET のみ、2 ラウンド実行しました。ビルド時間はそれぞれ 1 回の実行によるものです。

| 指標 | SSR アプリ 1 | SSR アプリ 2 | SPA アプリ |
| --- | ---: | ---: | ---: |
| ディスク上の辞書バイト数 | 6.37 MB → 1.52 MB(-76%) | 4.43 MB → 1.52 MB(-66%) | 15.40 MB → 1.69 MB(-89%) |
| `.output` サイズ | -22% | -14% | -29% |
| ビルド時間 | 27 s → 22 s | 23 s → 19 s | 41 s → 28 s |

**クライアント JS。** 独自のコードを持つ実際のアプリでは、上記のとおりわずかに増加します。共通の修正によりフレームワークパッケージも大きくなりました。別のプレリリースビルドで最小サイズの Vue、React、Preact、Solid アプリを使って計測したところ、gzip で約 1.4 KB から 2.5 KB の増加でした。React、Preact、Solid には共通のリッチテキストレンダラーも含まれます。

**辞書リクエスト。** 初回の読み込みでは、ルートとページの 2 つのファイルを取得するようになりました。バイト数は変わりません(2 つの SSR アプリでの 103 回と 89 回の初回読み込みで +0.3%)。同じドキュメント内の次のページでは小さなファイルを 1 つ取得するだけです: 計測した 2 ページでは、gzip で 4.7 KB → 1.5 KB、5.9 KB → 0.5 KB でした。SPA のログイン後の巡回では、辞書のバイト数が 21% 減少しました。

**エッジ。** 小さなデモアプリでは、Cloudflare Worker のアップロードサイズが gzip で 241.5 KiB から 250.3 KiB になりました(プレリリースビルド)。Edge バンドルに埋め込まれた辞書も同じルートファイルとページファイルを使いますが、大規模なカタログでの埋め込みは計測していません。

## 破壊的変更 {#breaking-changes}

### 要件 {#requirements}

- **Nuxt 3.18 以降**、および **Node 20 以降**。
- **`@i18n-micro/test-utils`** はモジュールと一緒にインストールされなくなりました。テストでインポートしている場合は自分で追加してください。
- **`@i18n-micro/hmr`** は廃止されました: 翻訳の HMR は組み込みになりました。インストールしている場合はパッケージを削除してください。
- **`@i18n-micro/react`** には React 18 以降が必要です。
- **`nuxt-i18n-micro-cli`** は `@i18n-micro/cli` に置き換えられました。

### オプションと設定 {#options-and-config}

- `dependsOn` 内の `i18n-plugin-hooks` と `i18n-plugin-define` は、エラーを出さずに何も待たなくなりました。`i18n-plugin-loader` を使用してください。
- サーバーの自動インポートは `useLocaleServerMiddleware`、`useTranslationServerMiddleware`、`loadTranslationsFromServer`、`detectCurrentLocale` です。それ以外は自動インポートされなくなりました。
- `resolveTranslationPayloadMode` およびその他の `resolveTranslationPayload*` ヘルパーは、`shouldCopyTranslationPayloadsToPublic` と `shouldRegisterNitroServerAssets` とともに `nuxt-i18n-micro` から削除されました。`TranslationPayloadMode` 型は残ります。
- `$getI18nConfig()` には `isSSG`、`hmr`、`hooks`、`noPrefixRedirect`、`routeLocales`、`routeDisableMeta`、`globalLocaleRoutes` がなくなりました。オプション自体は変更されていません。
- `locales[].baseUrl` はリクエストをルーティングするようになりました: 他のドメインのロケールはこのホストでは 404 となり、同じホスト上のリンクは相対リンクになります。このようなビルドでは、`$getI18nConfig().locales` はホストが配信するものを保持し、`linkLocales` はすべてを保持します。
- `baseUrl` はその他のホストでもオリジンを設定します: canonical と `hreflang` は、設定されていれば `metaBaseUrl` を、なければリクエストのオリジンではなくデフォルトロケールの `baseUrl` を使用します。
- `excludePatterns` はセグメント全体に一致し(`'/admin'` は `/administrator` に一致しなくなりました)、glob はアンカー付きとなり、`RegExp` パターンがランタイムにも届くようになりました。
- `cacheMaxSize` が未設定の場合、サーバーでは最大 1000 エントリを意味します。`cacheTtl` はエントリが保存された時点から数えられ、読み取りによって延長されなくなりました。
- `no_prefix` では、`i18n` 設定で明示的に `localeCookie: null` を指定すると無効のままになります。
- `prefix_except_default` と `prefix_and_default` では、ランタイムの `defaultLocale` は警告とともに無視されます。ランタイムの `fallbackLocale` は有効なロケールでなければなりません。
- `nuxt.config` の `routeDisableMeta` が尊重され、どのキー形式でも `nuxt.config` のエントリが `$defineI18nRoute` より優先されます。
- 開発環境のサーバーでは、解決済みの設定が凍結されます: 書き込むと例外がスローされます。
- 同じ `code` については、プロジェクトの `locales` エントリがレイヤーのものより優先されます。

### コンポーザブルと `$` メソッド {#composables-and-$-methods}

- `$switchLocale` は `true` または `false` で解決されます。以前は何も返しませんでした。`$switchRoute` の型は `Promise<void>` です。
- `$localeRoute`、`$switchLocalePath`、スイッチャーは、あるページを配信しないロケールについてはそのロケールのホームにリンクします。
- `$localePath` は `http(s):`、`mailto:`、`tel:` スキームを持つ文字列をそのまま返し、`$localeRoute` はそれを `path` と `fullPath` に含めます。未検証の値をリンク先としてこれらに渡さないでください。`//host` や `x.com` のような裸の名前は、このオリジン上のパスのままです。
- パスのないリンクは現在のページに留まります: `$localePath('#top')`、`'?p=2'`、`''`、`{ query }`。`'#top'` は以前はサイトのルートから解釈されていました。裸の `'about'` は引き続き `/about` を意味します。
- `$switchRoute` はアプリ内に留まります。アプリの外に出るのは、ロケール自身の `baseUrl`、`mailto:`、`tel:` のみです。
- `baseUrl` を持つロケールへのリンクは `$localePath` または `<i18n-link>` を通します。`<NuxtLink :to="$localeRoute(x, 'fr')">` と `router.push($localeRoute(x, 'fr'))` はこのアプリのパスのままです。コードでは `navigateTo($localePath(x, 'fr'), { external: true })` を使用してください。
- `$switchLocaleRoute` とリダイレクトは `trailingSlash` に従います。
- サーバーで設定された `$setI18nRouteParams` と `useI18nHead` は、ナビゲーションによってパスが変わると(`/news/1` から `/news/4` への変更も含む)破棄されます。新しいページで再度設定してください。
- setup 内で読み取った `$setI18nRouteParams` はそのページに紐付けられます: すでに離れたページからの遅れた呼び出しは何もしません。セッターはないため、テストでは `useI18n` 自体をスタブしてください。
- `useI18n()` はアプリごとに 1 つのオブジェクトを返します。それへの書き込みはすべての呼び出し元に届きます。
- 辞書、ロケール、パラメーター、head はナビゲーションが確定したときに変わります。`beforeResolve`、`beforeRouteEnter`、または後続のグローバルガードは古いものを参照します。ルートミドルウェアには影響しません。
- URL 戦略では、`$switchLocale` はそのナビゲーションがキャンセルされると保存されているロケールを復元します。
- `$t` は `defaultValue` を補間します: `$t('missing', { n: 1 }, 'Got {n}')` は `Got 1` を返します。`$tc` も同様で、空の翻訳に対しては `''` を返します。
- `$has(key, route)` はルートを考慮します。
- `$clearCache()` は現在のページの辞書を再読み込みします。
- `{param}` プレースホルダーは渡したパラメーターのみを読み取ります: `{constructor}` は記述されたままになります。
- 負の数、小数、または巨大な数を渡した `$tc` は、実際の数で最後の形式を使います。`{ count: null }` は例外をスローしなくなり、欠落している複数形キーは missing ハンドラーに届きます。
- `$tdr` は無効な入力に対して `Invalid Date` を返します。1 秒未満の過去は `0 seconds ago` です。
- `$tn`、`$td`、`$tdr` は `iso` に従います: `{ code: 'en', iso: 'en-GB' }` は日付を `31/10/2026` とフォーマットします。`Intl` が認識しないコードは `en` としてフォーマットされ、複数形はインデックスルールに従います: `iso` を設定してください(`{ code: 'ua', iso: 'uk-UA' }`)。
- `detectCurrentLocale` は非推奨です: `useLocaleServerMiddleware(event).current` を使用してください。

### 複数形 {#plurals}

テンプレートの意味は、1 つの例外を除いて変わりません。プレースホルダーのないゼロ形式の後にカテゴリーごとに 1 つの形式が続き、複数の数が共有する各形式に `{count}` があるテンプレートは、3 つ以上のカテゴリーを持つロケール(`ru`、`uk`、`pl`、`cs`、`ar` など)ではカテゴリーに従うようになりました: `uk` では `none | {count} one | {count} few | {count} many` は `3 few` と `21 one` を返します。その他のテンプレートでカテゴリーを使うには、`=0 ` マーカーを追加してください。カスタムの `plural` ルールは生の値を読み取るため、マーカー付きのテンプレートは `=0 ` が付いたままの状態でルールに渡されます。[アップグレードの表](/ja-jp/guide/upgrade#plurals-and-formatting)を参照してください。

### コンポーネント {#components}

**`<i18n-t>`**

- `html` はすべてのケースで `params` をエスケープし、すべてのスロットを無視します。
- スロットは同名のパラメーターより優先されます。
- `plural`、`number`、`date`、`relativeDate` では、`null` は未設定を意味します。
- `plural` は `$tc` と同様に `Number` で数えます: `1.5` は `1.5` のまま、`"2 items"` は `NaN`、`""` は `0` です。
- `number`、`date`、`relativeDate` は `params` を保持します。
- `hideIfEmpty` はすべての分岐で適用され、`defaultValue` はすべての分岐で欠落したキーの代わりになります。
- `html` 下で欠落したキーはエスケープされたテキストになります。
- `date` と `relativeDate` の出力には `data-allow-mismatch="text"` が付き、名前付きスロットの隣ではテキストが独自の `<span>` に入ります。
- `.innerHTML` と `textContent` 属性は破棄されます。
- 関数型コンポーネントです: `ref` を付けてもインスタンスは得られません。
- `<i18n-t>` と `<i18n-group>` は、`$t` と同様にアクティブな辞書を読み取ります。

**`<i18n-switcher>`**

- リンクは `$switchLocale` を呼び出すプレーンな `<a>` になったため、`router-link-active` クラスはなくなりました。
- ボタンは `aria-expanded` を持つ `type="button"` です。Escape キーと外側のクリックでドロップダウンが閉じます。
- 新しいクラス `i18n-switcher-wrapper`、`i18n-switcher-dropdown`、`i18n-switcher-button`。各リンクには `lang` があり、ロケールが設定している場合は `dir` もあります。
- デフォルトのスタイルは論理 CSS プロパティを使い、ドロップダウンにはより大きな `z-index`、最小幅、影があります。
- パラメーターのあるページでは、レンダリングの終了時にサーバーがリンクを書き換えます。手書きの `$switchLocalePath` リンクは書き換えられません。

**`<i18n-link>`**

- `https://`、`mailto:`、`tel:` は大文字小文字を問わず一致します。裸の `report.pdf` はルートとなり、`example.com` は外部リンクのままです。TLD でもあるファイル拡張子(`example.md`)はファイルとみなされます: `https://` を記述してください。
- `activeStyle` は末尾のスラッシュ、クエリ、ハッシュを無視します。

### フックと型 {#hooks-and-types}

- `i18n:register` はランタイムフックです: プラグイン内で `nuxtApp.hook('i18n:register', …)` とします。
- エクスポートされる型 `ModuleHooks` は `ModuleRuntimeHooks` に名前が変更されました。
- `i18n:beforeLocaleSwitch` と `i18n:afterLocaleSwitch` は一度も発火されたことがなく、ドキュメントから削除されました。
- `ModuleOptionsExtend.isSSG` は任意かつ非推奨です: 何もそれを設定しません。

### URL とリダイレクト {#urls-and-redirects}

- `en` がデフォルトの `prefix_except_default` では、**`/en` と `/en/...` は 404 になります**。
- **大文字小文字や綴りが異なるロケールプレフィックスは 404 になります**(`/DE/about`)。`[...slug]` 下の `/DE/x` や `[slug]` と並ぶ `/DE` も同様のため、別の大文字小文字でロケールコードと一致する CMS のスラッグはそのページを失います。
- `autoDetectPath: '*'` または `'no_prefix'` の場合、**未知の URL は 404 のままです**。`prefix` ではリダイレクトが維持され、`/` はどこでも同様です。
- **他のロケールのカスタムパスがプレフィックスなしの場合、** `prefix_except_default` ではデフォルトロケールの URL への `302` になります。`prefix` ではリダイレクトが実際に存在するページに届くようになりました。`prefix_and_default` では 404 のままです。
- **`redirects: false` を指定した `prefix`** は、プレフィックスなしの URL(カスタムのデフォルトパスを持つページの元の URL を含む)に 404 を返します。
- **`autoDetectPath: '*'`** は、プレフィックスなしのパスにも Cookie と `Accept-Language` を適用します。
- **`prefix` では、** `autoDetectPath` の設定にかかわらず、すべてのパスでプレフィックスなしの URL は訪問者のロケールを維持します。
- **`prefix_and_default` では、** プレフィックスなしの URL はデフォルトロケールです。
- **`no_prefix` では、** カスタムパスはそれ自身のロケールでレンダリングされ、制限されたページはそれが配信するロケールでレンダリングされ、パスを共有するロケールは 1 つのレコードを共有します。
- **ページのない `routeRules` リダイレクト**はローカライズされません: `/de/old` は 404 です。以前は空の 200 でした。
- **ルートルールはカスタムパスにも適用され、** `no_prefix` でもコピーされます。`/de/artikel/news` のような静的な兄弟ルートは `/de/artikel/:slug` に一致します。
- **`disabled: true` のロケール**は、そのプレフィックスで直ちに 404 を返し、そのロケールへのリンクはページに留まります。
- **大文字小文字が異なるページパス**は、そのページ本来の綴りへの `302` になります: `/T/BASIC` は `/t/basic` に移動します。
- **カスタムのデフォルトパスを持つページの元の URL** は、`prefix_except_default` ではそのパスへの `302` になります。以前は 404 でした。
- **`noPrefixRedirect`** は訪問者のロケールに従います: Cookie が `de` の場合、`/about` はデフォルトロケールのパスではなく `/ueber-uns` に移動します。
- **ホスト自身のプレフィックス**は、`prefix_except_default` ではその `baseDefault` ホスト上で 404 になります: `de` ホスト上の `/de/x` は以前 200 でした。
- **`customRegexMatcher`** は、最初のセグメントがロケールのように見える実在のページを 404 にしなくなりました。
- **`nuxi generate`** は、ルートルールで `prerender: false` が設定されていない限り、すべての静的ページをそれを配信する各ロケールでプリレンダリングします: 出力のファイル数が増えます。`baseUrl` を使う場合は、`NUXT_I18N_DOMAIN` を指定してドメインごとに 1 回実行してください。
- **クライアントのリダイレクトはそのナビゲーションのモードを維持します:** プレーンな `<NuxtLink>` は履歴エントリを追加します。
- **ローカライズされたルート名は一貫しています。** 影響を受けるのは、`router.push({ name })` で `localized-…` という名前をハードコードしているコードのみです: ページ自身の名前を `$localeRoute` に渡してください。
- **`extendPages` からの名前のないページ**はローカライズされ、名前が付けられます。
- **`prefix` では、他のドメインへのリンク**はロケールプレフィックスを保持します。
- **ドメインのホーム**は、どこでも末尾のスラッシュなしで記述されます。
- **`?locale=`** がページで考慮されるのは `no_prefix` の場合のみです。`/about?locale=de` が `lang="en"` のもとでドイツ語をレンダリングすることはなくなりました。
- `/en/...` での**プラグインの `setLocale('de')`** は、`de` の辞書を読み込まなくなりました。

### SEO と HTML 出力 {#seo-and-html-output}

- `dir="auto"` はデフォルトではなくなりました。既知の RTL 言語には `dir="rtl"` が付き、`dir` のないその他のロケールには属性が付きません。以前の出力を維持するには `dir: 'auto'` を設定してください。ただし大きなページではパースのコストがかかります。[テキストの方向](/ja-jp/guide/seo#text-direction)を参照してください。
- `disableMeta` が動作するようになりました: ページには `hreflang`、canonical、`og:locale` がなくなります。`lang` と `dir` は残ります。
- `hreflang` には、そのページを配信するロケールのみが列挙されます。`x-default` は、デフォルトロケールがそのページを配信する場合にのみ表示されます。
- ローカライズされていないページには `hreflang` も `og:locale:alternate` もありません。
- 404 ページには URL のロケールで `<html lang dir>` が付き、canonical や `hreflang` はありません。
- canonical、`og:url`、`hreflang` は、サーバーでもホワイトリストに登録されたクエリ(`/about?page=2`)を保持します。
- オリジンがリクエストから得られる場合、canonical と `hreflang` には `app.baseURL` が含まれます。
- すべての SSR ページには、404 ページも含め、辞書ファイル用の `<link rel="preload" as="fetch" crossorigin="anonymous">` があります。厳格な CSP ではこれを許可してください。`apiBaseClientHost` を使う場合、そのホストには CORS が必要です。
- `Vary` は、`no_prefix` ではすべてのページに、その他の戦略ではロケールのリダイレクトに設定されます。CDN のキャッシュキーを確認してください。
- ロケール Cookie は、配信されたページによってのみ書き込まれます。

### 検出とサーバー {#detection-and-server}

- `Accept-Language` は `q` 値を考慮し、`q=0` はその言語を除外します。
- `useLocaleServerMiddleware` と `useTranslationServerMiddleware` は、すべてのルートで同じ順序(`?locale`、`[locale]` パラメーターまたはプレフィックス、Cookie、ヘッダー、デフォルト)を使い、`localeCookie: null` と `autoDetectLanguage: false` を尊重し、ロケールごとに辞書をキャッシュします。
- 不正な形式のロケール Cookie は、SSR を失敗させる代わりに無視され、そのまま残されます。
- ハッシュモードは `hash-locale` Cookie のみを読み取ります。`user-locale=de` だけではカウントされなくなりました。
- `NUXT_I18N_DEFAULT_LOCALE` とランタイムの `disabledLocales` はルーティングを変更します。
- **`premerged` の出力が変わりました。** `/{apiBaseUrl}/<page>/<locale>/data.json` は `__root/<locale>/data.json` との差分のみを保持します。これらのファイルを直接読み取るものは、2 つをマージする必要があります。完全な辞書も引き続き有効なファイルです。
- **辞書は `app.cdnURL` に従います。** ブラウザーは、以前は `app.baseURL` を使っていたところを、`<cdnURL>/_locales/...` から取得します。CDN は `_locales/` を保持し、サイトのオリジンを許可する必要があります。[アプリの baseURL とペイロードホスト](/ja-jp/guide/deployment#app-baseurl-and-payload-hosts)を参照してください。
- `/{apiBaseUrl}/**` に Nitro のルートキャッシュはなく、`s-maxage=60, stale-while-revalidate` ヘッダーもなくなりました。そのキャッシュに依存していた場合は、ペイロードルートの前に CDN を置いてください。
- `/{apiBaseUrl}/<page without a folder>/<locale>/data.json` はルート辞書で応答します。以前は `{}` でした。ホストの 404 は、以前は `200 {}` で応答していましたが、404 としてそのまま通過するようになりました。
- 辞書を読み込めないプリレンダリングは、500 と警告で失敗し、Nuxt のデフォルトの `failOnError` ではビルドが 1 で終了します。
- 再ビルドせずに変更した翻訳がブラウザーに届くのは、`v` が変わった場合のみです: `NUXT_I18N_DATE_BUILD` を設定してください。
- `apiBaseServerHost` が設定されていない限り、SSR は HTTP で `/{apiBaseUrl}` をリクエストしなくなりました。

### 翻訳 {#translations}

- マージはすべての階層で深く行われ、フォールバックチェーンは最後まで辿られます。
- マージはロケール単位で行われます: アクティブなロケールのルートファイルは、フォールバックロケールのページファイルより優先されます。
- 自身の `pages/<name>/` フォルダーを持たないページは、本番環境ではルート辞書を読み取ります。以前は `{}` を受け取っていました。
- `disablePageLocales: true` はルートファイルのみを読み取ります。
- 離脱したページのキーは、ナビゲーション後に解決されなくなります。レイアウトが前のページのファイルにしかないキーを使っていた場合は、それらをルートファイルに移動してください。
- 壊れたロケールファイルは、すべてのモードでそのパスとともに 1 回警告を出します。以前は開発環境で例外がスローされていました。

### `@i18n-micro/*` パッケージ {#@i18n-micro/*-packages}

`@i18n-micro/types` と新しい `@i18n-micro/cli` を含め、すべての `@i18n-micro/*` パッケージが 2.0.0 になりました。

**`@i18n-micro/react`, `preact`, `solid`**

- ルーターアダプターは `/router` に移動しました: `createReactRouterAdapter`、`createSolidRouterAdapter`、および Preact の `createBrowserHistoryAdapter`。`createPreactRouterAdapter` は削除されました。
- `I18nT` は上記の `<i18n-t>` に従います。`dangerouslySetInnerHTML`、`innerHTML`、`textContent` 属性は破棄されます。
- `I18nSwitcher` は、`aria-current="page"`、`▾`、論理 CSS、ボタンへの `language-switcher` を伴う `<a href>` 項目をレンダリングします。`aria-haspopup` はありません。`className` は `i18n-switcher-wrapper` に追加されます。
- `/` またはロケールのルートへのリンクは、完全一致の場合にのみアクティブになります(React、Preact)。
- `I18nLink` はユーザーの `onClick` と `style` を保持し、修飾キー付きのクリックはブラウザーに任せます。アクティブ判定ではクエリとハッシュは考慮されません。ルーターがない場合、どのリンクもアクティブになりません。
- React と Preact: `I18nLocalesContext`、`I18nDefaultLocaleContext`、`I18nRouterContext` は 1 つの `I18nConfigContext` になりました。Solid: 1 つの `I18nContext` が `{ i18n, locales, defaultLocale, router }` を保持します。
- アダプターの `getCurrentPath` にはクエリとハッシュが含まれ、`getRoute().query` で繰り返されたキーは配列になります。
- `i18n` を持たないネストされた `I18nProvider` は外側のインスタンスを維持し、インスタンスがまったくないプロバイダーは例外をスローします。
- 値のない `defaultLocale()` は `fallbackLocale` です。
- Solid: `getCurrentPathAccessor` は削除されました。`useI18n()` は `locales` がなくても例外をスローしなくなりました。
- React: `use-sync-external-store` は依存関係ではなくなり、`react-dom` は任意のピア依存関係になりました。

**`@i18n-micro/vue`, `vitepress`**

- `I18nT` は関数型コンポーネントです。
- `I18nSwitcher` と `I18nLink` は上記のセクションに従います。`aria-haspopup` はなくなりました。
- `I18nLink` と `createVueRouterAdapter` は `name`、`query`、`hash` を解決します。未知の `name` は、`RouterLink` と同様に例外をスローします。
- `useLocaleHead` は `//de/` を生成しなくなりました。1 つのページの canonical と `hreflang` は一致し(`/de`)、ホワイトリストに登録されたクエリパラメーターがそれらに含まれます。
- `I18nRoutingStrategy.resolvePath` は、location オブジェクトや、クエリとハッシュを含むパスを受け取る場合があります。新しい任意の `toHref`。
- VitePress: リンク、スイッチャー、`push`、`replace` は `site.base` を含みます。

**`@i18n-micro/astro`**

- `i18nIntegration` は `translationDir` をバンドルし、ミドルウェアをインストールします: セットアップをコピーするだけの `src/middleware.ts` は削除するか、`middleware: false` を渡してください。独自の `src/middleware.ts` は `base: config.base` を渡します。
- `i18nIntegration` は `messages`、`plural`、`missingHandler`、`routingStrategy` を渡すと例外をスローします: これらは `middleware: false` とともに `createI18n` または `createI18nMiddleware` に渡してください。何の効果もなかったオプションは型から削除されました。
- `loadTranslationsFromDir` と `loadTranslationsIntoI18n` は `@i18n-micro/astro/node` に移動しました。これは ESM のみです。
- `getGlobalRoutingStrategy`、`setGlobalRoutingStrategy`、`runWithRoutingStrategy` は削除されました: `Astro.locals.routingStrategy` を読み取ってください。
- `clone()` は `fork()` になり、`_storage` オプションはなくなりました。
- 動的ページは 1 つのルートです: `/blog/hello` は `blog-slug` で、以前は `blog-hello` でした。`pages/blog-hello/` を `pages/blog-slug/` に移動してください。カスタムの `getRouteName` は 3 番目の引数としてパターンを受け取ります。
- ページのロケールは URL によって決まります。`autoDetect` は `/` から優先ロケールのホームへの 302 です。新しい `localeCookie` オプションが追加され、`redirectToDefault` が実装されました。
- 別のロケールの同一オリジンのページからのページビューは、ロケール Cookie を書き込み、リダイレクトしません。サーバーアイランドとアクションは決してリダイレクトせず、`Vary: Referer` を伴います。
- `config.localeCodes` は無効なロケールを除外し、`prepareLocaleRewrite` はそれらに対して 404 を返します。
- キーを指定しない `getI18nProps()` は、そのページで `t()` が応答できるすべてを送信し、20 KB を超えると開発時に警告を出します。アイランドが使うキーを渡してください。
- `useLocaleHead`: デフォルトの `baseUrl` は `site`、なければルート相対です。リンクとメタには `id` が付きます。
- `<I18nT html>` は `params` をエスケープし、空の翻訳は空としてレンダリングされます。
- `<I18nLink>` と `localizePath` は外部 URL、`#hash`、`?query` には手を付けず、末尾のスラッシュを保持します。
- `<I18nSwitcher>` はクエリを保持し、生成された id の代わりに `data-i18n-switcher` を使います。
- `@i18n-micro/astro/client` には `translate` と `hasTranslation` のみがあります: アダプターは `/client/vue`、`/client/react`、`/client/preact`、`/client/svelte` からインポートしてください。`client/vue` には `vue` のインストールが必要です。
- アイランド: `has()` はサブツリーに対して true、`t('')` は `''` です。`provideI18n` は新しい props に追従するためのゲッターを受け取ります。
- `getLocale` と `getDefaultLocale` はミドルウェアがないと例外をスローします。

**`@i18n-micro/runtime`, `node`**

- アクティブでもフォールバックでもないロケールへの書き込みは、サブスクライバーに通知しません。
- `addRouteTranslations(locale, route, messages, false)` はチャンクを置き換えます。
- `loadFromUrls` は並列に取得し、1 つでも失敗すると何も書き込みません。
- Node: `reload()` は辞書を先に空にするのではなく入れ替え、成功メッセージをログに出力しません。ディレクトリがなくなった場合は古い辞書を維持します。
- Node、Astro、VitePress: locales フォルダーの読み取り処理は 1 つに統一されました。フォルダーがない場合は警告し、JSON オブジェクトでないファイルは報告されてスキップされ、メッセージは `[i18n]` で始まります。

**`@i18n-micro/test-utils`**

- モックは実際の翻訳ルールに従います: `tc('a', 1.5)` は最後の形式を使い、`td('nope')` は `Invalid Date`、`t(miss, undefined, '')` はキーを返し、見つからない場合にログを出力しなくなりました。
- `createI18nTestContext` から `isolated` がなくなり、`./publish-smoke` は削除されました。

**`@i18n-micro/types-generator`**

- `I18nTypesPlugin(options)` はプレーンな Vite および Rollup プラグインです: `.vite()`、`.webpack()`、`.esbuild()` はありません。webpack や esbuild では、スクリプトで `generateTypes` を呼び出してください。
- `getTypesString` と `generateTypes` は同期関数です。`flattenKeys` と `isPlainTranslationObject` は削除されました。
- キーは `t()` が読み取るものです: オブジェクトのパスが追加され、ロケールのレイアウト外のファイルは除外されます。

**`@i18n-micro/devtools-ui`**

- 保存は `translationDir` 内の既存の `.json` のみを受け付け、ファイルを作成しなくなりました。クロスサイトリクエストは 403 になります。
- 到達可能なエンドポイントへの保存が失敗すると、例外をスローしてロールバックします。
- `createBridge` は `base` オプションを受け取ります。Astro は `i18nDevToolsIntegration` を使用します。

**`@i18n-micro/utils`, `core`, `path-strategy`, `route-strategy`**

カスタムアダプターとツール向けのみです。

- `utils`: サブパス `./route`、`./route-pattern`、`./build`、`./payload-stats`、`./payload-config` は、`resolveServerLocale` と `resolvePreferredLocale` とともに削除されました: `resolveLocale` を呼び出してください。`deepMergeTranslations` と `mergeRouteTranslationsWithRoot` はなくなりました: `deepMergeTranslationsRecursive` を使用してください。
- `core`: `TranslationHelper` から `setCache`、`getGeneration`、`lookupIn` が削除されました(`lookup(chunkKey, key)` を使用)。`BaseI18n` から `ensurePinnedChunk` と `invalidatePin` が削除されました。`useTranslationHelper(storage)` はなくなりました: `new TranslationHelper(storage)` を使用してください。
- `path-strategy`: **`switchLocaleRoute(fromLocale, toLocale, route, options)` は `switchLocaleRoute(toLocale, route, options)` になりました。古い JavaScript の呼び出しはエラーなしで誤った結果を返します。** Nuxt の `$switchLocaleRoute` は影響を受けません。`/prefix`、`/no-prefix`、`/prefix-except-default`、`/prefix-and-default` エントリは、`getRedirect` と `getCanonicalPath` とともになくなりました。`RouterAdapter` には `getRoutes` が必要です。`createPathStrategy` は絶対 URL を生成しません: ロケールに `baseUrl` がある場合は `new DomainPathStrategy(ctx)` を使用してください。
- `route-strategy`: エクスポートされるのは `RouteGenerator`、`generateRoutes`、`Rules`、パスヘルパーのみです。

## 移行 {#migration}

1. 要件を確認します: Nuxt 3.18、Node 20、`@i18n-micro/react` を使う場合は React 18。
2. `nuxt-i18n-micro` とすべての `@i18n-micro/*` パッケージを一緒に更新します。`@i18n-micro/hmr` を削除します。テストでインポートしている場合は `@i18n-micro/test-utils` を開発依存関係として追加します。`nuxt-i18n-micro-cli` を `@i18n-micro/cli` に置き換え、[そのコマンド対応表](/ja-jp/guide/cli#moving-from-nuxt-i18n-micro-cli)に従います。
3. コード内で、`@i18n-micro/path-strategy` の `switchLocaleRoute(`、`i18n-plugin-hooks`、`i18n-plugin-define`、`localized-` のルート名、`$getI18nConfig().globalLocaleRoutes` およびその他の削除された設定キー、`ModuleHooks`、`i18n:register` に付けた `@ts-expect-error` を検索します。
4. `<i18n-t html>` のパラメーター内のマークアップを翻訳に移し、データをパラメーターとして渡します。
5. `baseUrl` を設定している場合: `$localeRoute` で作成したリンクを見直し、プロキシの背後では `trustForwardedHost` を設定し、`NUXT_I18N_DOMAIN` を指定してドメインごとに 1 回 `nuxi generate` を実行します。
6. 戦略に照らして URL を確認します: `prefix_except_default` での `/en`、ロケールに似た CMS のスラッグ、`routeRules` のリダイレクト、`excludePatterns`。
7. CDN のキャッシュキーで `Vary` を確認し、厳格な CSP ではプリロードリンクを許可します。`app.cdnURL` を使う場合は、`_locales/` を CDN に置き、CORS を許可します。
8. ツールが `/_locales/...` ファイルを直接読み取る場合は、ページファイルを `__root/<locale>/data.json` の上にマージします。
9. グローバルガードがロケールや辞書を読み取る場合は、ナビゲーションの確定前に実行されても問題ないことを確認します。レイアウトが前のページのファイルから取っていたキーはルートファイルに移動します。
10. `nuxi generate` の出力やサイトマップのクロール結果を前後で比較します: `hreflang`、`x-default`、canonical、ページ一覧は意図的に変わります。
11. フレームワークパッケージのインポートを更新します: React、Solid、Preact のアダプターは `/router`、Astro のローダーは `/node`、型プラグインは `I18nTypesPlugin(o)`。
12. Astro では、セットアップをコピーするだけの `src/middleware.ts` を削除し、`pages/blog-hello/` 形式の辞書をそのパターン名に変更します。
13. `router-link-active`、`li button`、`▼`、または古いモックの動作に依存していたテストを更新します。

詳細とすべてのエッジケース: [アップグレード](/ja-jp/guide/upgrade)。

## なぜ重要なのか {#why-it-matters}

- **設計段階からの正確さ:** リンク、リダイレクト、SEO タグは、アプリに実際に存在するルートから生成されます。
- **どこでも 1 つの答え:** ビルド、ソースモード、開発環境は同じ辞書を返し、すべての呼び出し元が 1 つの検出順序を使います。
- **ドメイン:** すべてのロケールドメインに 1 つのデプロイで対応し、2 つ目のビルドは不要です。
- **より安全なデフォルト:** エスケープされたパラメーター、上限のあるキャッシュ、オリジン内に留まるリンク。
- **出荷するものが少ない:** より小さな辞書ファイル、より小さなルーティングパッケージ、1 か所に集約された共通ロジック。

変更の全一覧については、[アップグレード](/ja-jp/guide/upgrade)と[変更履歴](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md)を参照してください。
