## Nuxt I18n Micro v3.22.0 — フォーマット、キャッシュ、Translation Memory {#nuxt-i18n-micro-v3-22-0-—-formats-cache-&-translation-memory}

**日付**: 2026-07-30

**バージョン**: `v3.22.0`

![v3.22.0 リリース](/images/3.22.0.png)

**v3.22.0** をリリースしました。フォーマッターキャッシュを備えた Vue I18n スタイルの名前付き数値／日付フォーマット、CDN に適した翻訳ペイロードのキャッシュ（コンテンツフィンガープリント + `httpCacheDuration`）、そしてランタイムでアクティブな辞書を読み取り・置き換えるための Translation Memory API を搭載しています。

## 新機能 {#what’s-new}

### 名前付き `numberFormats` / `datetimeFormats` + フォーマッターキャッシュ {#named-numberformats-/-datetimeformats-+-formatter-cache}

Vue I18n 互換の名前付きフォーマットと、より高速な Intl フォーマット：

- 設定：ロケールごとの `numberFormats` / `datetimeFormats`
- API：`$tn(1000, 'currency')`、`$td(date, 'short')`（+ ロケールの上書きとオプションのマージ）
- `FormatService` は `Intl.NumberFormat` / `DateTimeFormat` / `RelativeTimeFormat` をロケール + オプションごとにキャッシュします

[メソッド — `$tn` / `$td`](/ja-jp/api/methods#$tn) と[モジュールオプション](/ja-jp/api/module-options#numberformats)を参照してください。

### `dateBuild` のデフォルトがコンテンツフィンガープリントに {#datebuild-defaults-to-a-content-fingerprint}

以前は `/_locales` リクエストの `?v=` のデフォルトが `Date.now()` でしたが、レスポンスは 1 年間 `immutable` として配信されていました。そのため、翻訳が何も変更されていなくても、再ビルドのたびにすべてのクライアントの辞書が無効化されていました。

現在のデフォルトは、レイヤー順に並べた翻訳ソースの SHA-256 フィンガープリントです。翻訳に変更のない再ビルドでは同じ URL が維持されます。`dateBuild` を明示的に設定した場合は、引き続きそちらが優先されます。[モジュールオプション — `dateBuild`](/ja-jp/api/module-options#datebuild) を参照してください。

### `/_locales` ペイロード向けの `httpCacheDuration` {#httpcacheduration-for-/_locales-payloads}

組み込みの `/{apiBaseUrl}/:page/:locale/data.json` ルートは、ブラウザーと CDN 向けに HTTP `Cache-Control` を送信するようになりました。

- オプション：`httpCacheDuration`（秒単位、デフォルトは `31536000` / 1 年）
- ヘッダー：`Cache-Control: public, max-age=…, immutable`
- 既存の `dateBuild` によるキャッシュバスティング（`?v=...`）と併用しても安全です。`0` でヘッダーを無効化します。開発環境では適用されません

`@nuxtjs/i18n` v10.2.0 の `experimental.httpCacheDuration` に相当するもので、明示的なレスポンスヘッダーとして実装されています。

### 圧縮されたパブリックペイロード {#compressed-public-payloads}

`nitro.compressPublicAssets` が、パブリックディレクトリにコピーされる翻訳ペイロード（`.gz` + `.br`）にも適用されるようになりました。Nitro はコピーが行われる前にパブリックアセットを圧縮するため、以前はペイロードが静的ビルドの中で唯一圧縮されない部分でした — playground のインデックスでは、未圧縮で 6.65 MB、gzip で 1.01 MB です。モジュールが独自に圧縮を有効化することは引き続きありません。[パフォーマンス](/ja-jp/guide/performance#payload-size)を参照してください。

### `resolveTranslations()` と `setTranslation(key, value)` {#resolvetranslations-and-settranslationkey-value}

メモリ上のアクティブな翻訳辞書を読み取り・置き換えるためのランタイムヘルパー：

- **`resolveTranslations()`** は、アクティブなロケールとルートについて `$t()` が参照するツリー全体を返します — DevTools、テスト、ランタイムエディターに便利です。2 つ目のレイヤーが有効な場合（フォールバックロケールや Nuxt のページトランジション時のホットリロード）、ダンプは `mergeTranslationLayers` によってネストされた形を保ち、単一のツリーでは表現できないスカラーとオブジェクトの衝突に対してのみ、フラットなドット区切りのキーを使用します。
- **`setTranslation(key, value)`** は、キーの値（トップレベル、ドット区切りのパス、オブジェクト、文字列、スカラー）を置き換えます。これはマージではなく**置き換え**です。兄弟要素を残したい場合は `$mergeTranslations` を使用してください。
- `useI18n()`、`useNuxtApp()`、および `@i18n-micro/core` を継承するフレームワークの i18n インスタンスで利用できます。
- `@i18n-micro/test-utils` には、ユニットテスト用に対応する `resolveTranslations` / `setTranslation` ヘルパーが追加されました。

### Vue パッケージから `getAllTranslations()` を削除 {#getalltranslations-removed-from-vue-package}

アクティブな参照ツリーには `resolveTranslations()` を使用してください。Vue でストレージ全体をダンプするには、`getStorage()` または `getRouteCache()` を使用してください。

## 破壊的変更 {#breaking-changes}

一般的な使い方であれば、公開されている設定項目でアプリのコードを修正する必要はありません。以下は、ランタイムの内部に手を入れていた場合に関係します。

- **SSR ペイロードが `useState('i18n-ssr-chunks')` から `nuxtApp.payload.data['i18n-ssr-chunks']` に移動しました。** SSR 中に読み込まれたすべての `(locale, route)` について、引き続き**完全な翻訳チャンク**を保持しています — 以前と同じ辞書ですが、プリレンダリング時に Nuxt が `_payload.json` に外部化できるスロットに格納されます。`useState('i18n-ssr-chunks')` は何も返さなくなりました。この方法での翻訳の読み取りは一度もサポートされていませんでしたが、キャッシュ API のドキュメントで説明されていたため、ここで明記しています。
- **`NuxtTranslationLoaderOptions` が `setSsrChunk` を公開するようになりました。** ローダーはサーバー上で読み込みながら、マージされた各チャンクを `payload.data` に書き込みます。`getSsrChunks` は使用されません。
- **`nitro.compressPublicAssets` が、コピーされたペイロードの隣に `.gz` / `.br` を出力するようになりました。** これを有効にしていた場合、パブリック出力のファイルが増えます。翻訳ディレクトリを列挙するデプロイツールでは、これらを考慮する必要があるかもしれません。
- **アップグレード時にペイロードの URL が一度だけ変わります。** `?v=` がビルドのタイムスタンプからコンテンツフィンガープリントに切り替わるためです。クライアントはアップグレード後の最初のリクエストで辞書を再ダウンロードし、その後のデプロイでもそれを保持し続けます — これこそが狙いです。
- **`@i18n-micro/vue` から `getAllTranslations()` を削除しました。** 代わりに `resolveTranslations()` / `getStorage()` / `getRouteCache()` を使用してください。

## バグ修正 {#bug-fixes}

- **`<i18n-switcher>`** — `disabled: true` のロケールをドロップダウンから除外するようになりました。`$getLocales()` は独自のコード向けに引き続き完全なリストを返しますが、組み込みの SEO/メタ出力では無効なロケールが除外されます。
- **スイッチャーのスタイル** — `cursor: not-allowed` は `activeLinkStyle` / `customActiveLinkStyle` を介して**現在の**ロケールに適用されます。後方互換性のために `customDisabledLinkStyle` を復活させ、現在のロケールが `disabled: true` の場合にスイッチャーのボタンに適用するようにしました。
- **開発時の HMR** — ファイル内容が変わらない書き込み（エディターのフォーカス外れ時の保存、フォーマッターによる書き換え）で再マージが発生しなくなりました。ルートロケールの変更はそのロケールのすべてのページを再ビルドするため、何も変わらない操作に費やすにはコストが高すぎました。
- **開発時の HMR** — ルートロケールの変更時に、ページを 1 つずつではなく並行して再マージするようになりました。
- **ページトランジション** — 同じロケール内のナビゲーションでは、ナビゲーションのたびにコストの高いディープマージを行う代わりに、`page:transition:finish` まで出ていくチャンクをフォールスルーレイヤーとして保持するようになりました。

## なぜ重要なのか {#why-it-matters}

- 重いスタックを導入せずに、Vue I18n スタイルのフォーマットを利用できます。
- 辞書が変更されていなければ再ビルド後も安定している、CDN に適した翻訳 URL。
- ライブの辞書を検査・パッチするための、サポートされたランタイム API — DevTools、テスト、エディターはもはやプライベートなヘルパーを必要としません。

完全な変更履歴は、リリース時に [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md) で公開されます。

## 修正：`app.baseURL` + `strategy: 'prefix'` での無限リダイレクトループ (#234) {#fix-infinite-redirect-loop-with-app-baseurl-+-strategy-‘prefix’-#234}

**日付**: 2026-07-03

サーバーサイドのリダイレクトプラグイン（`06.redirect.ts`）は、ロケール検出の前に `getRequestURL(event).pathname` から `runtimeConfig.app.baseURL` を取り除くようになりました。アプリがサブパスで配信されている場合の `ERR_TOO_MANY_REDIRECTS` を修正します（例：`/examples` → `/examples/ja` へ一度だけリダイレクトされ、`/examples/ja/examples/ja/...` にはなりません）。
