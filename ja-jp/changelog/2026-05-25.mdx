**日付**: 2026-05-25

**バージョン**: `v3.19.0`

![v3.19.0 release](/images/3.19.0.png)

このリリースでは、**内部ユーティリティのモジュール化**、**コンパクトなサーバーレスペイロードモード**の追加、そして Nuxt、Node、Astro、DevTools 間での**共通ロジックの再利用**に重点を置いています。一般的なアプリで使われる公開モジュール API は変更されていません。

## 新機能 {#what’s-new}

### `@i18n-micro/utils` — フレームワーク非依存のユーティリティ {#@i18n-micro/utils-—-framework-agnostic-utilities}

これまで `src/runtime/utils/` と `src/module.ts` に分散していた共通ロジックは、**細かなサブパスインポート**(巨大なバレルファイルなし、ツリーシェイキングに適した構成)を備えた専用のワークスペースパッケージに移されました:

- **ビルド** — `preMergeLocales`、`buildTranslationSourceLayers`(`@i18n-micro/utils/build`)
- **ペイロード** — `translationPayloads` の解決、URL の構築、フェッチヘルパー、統計(`payload-config`、`payload-url`、`payload-fetch`、`payload-stats`)
- **ソースモード** — フォールバックチェーン、ソースファイルのパス、ランタイムでのマージ(`merge-source`、`source-loader`)
- **ランタイムヘルパー** — ロケールの解決、Cookie、Accept-Language の解析、ルート/メタのヘルパー(`resolve-locale`、`accept-language`、`cookie`、`route`、`route-pattern`、`runtime-config`)
- **共通の FS パス** — 翻訳ファイルの分類、ネストされたページのパス(`parse-path`)

Nuxt モジュールは `src/runtime/` に薄いグルーコードだけを残し、必要なサブパスのみをインポートします。

### `@i18n-micro/hmr` — 開発時の翻訳ホットリロード {#@i18n-micro/hmr-—-dev-translation-hot-reload}

開発時の HMR は `@i18n-micro/hmr` に切り出されました:

- **`watcher`** — 開発時のファイル変更の処理、キャッシュの無効化、source/premerged のマージ
- **`generate-plugin`** — クライアント側 HMR プラグインの生成
- **`cache-keys`** — サーバー/ストレージキャッシュ用の共通 `Symbol.for` キー

`translationPayloads.mode: 'premerged'` と `'source'` の両方で動作します。

### `translationPayloads.mode: 'source'` — コンパクトなサーバーレスデプロイ {#translationpayloads-mode-‘source’-—-compact-serverless-deployments}

サーバーレスプラットフォーム(Cloudflare Workers など)上で大規模なロケールマトリクスを扱うための新しいペイロードモードです:

```typescript
export default defineNuxtConfig({
  i18n: {
    translationPayloads: {
      mode: 'source',
    },
  },
})
```

- 完全な事前マージ済みマトリクスの代わりに、**コンパクトなソースファイル**を Nitro アセットにバンドルします
- ルート、ページ、フォールバックロケールのチェーンを、組み込みの `/_locales/:page/:locale/data.json` ルートを通じて**ランタイムで**マージします
- `publicAssets` と `prerenderRoutes` のデフォルトは `false` です — 純粋な静的ホスティングではなく、Nitro/エッジランタイムに依存する場合に最適です

[デプロイ — サーバーレスとエッジ](/ja-jp/guide/deployment#serverless-and-edge)と[キャッシュとストレージのアーキテクチャ](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api)を参照してください。

### インテグレーションパッケージ間で共有されるユーティリティ {#shared-utilities-across-integration-packages}

- **`@i18n-micro/node`** と **`@i18n-micro/astro`** — `@i18n-micro/utils/parse-path` による翻訳パス解析とディープマージの統一
- **`@i18n-micro/astro`** — `@i18n-micro/utils/accept-language` の `detectLocaleFromAcceptLanguage` を使用(重複していたパーサーを削除)
- **`@i18n-micro/devtools-ui`** — `merge-source` + `parse-path` ヘルパーによる仮想ファイルパス
- **サーバーでのロケール検出** — Accept-Language の処理を共通ユーティリティに合わせて統一

### HMR と DevTools の修正 {#hmr-&-devtools-fixes}

- クライアントの HMR プラグインは、削除された `$loadTranslations` ではなく **`$loadPageTranslations`**(正しい API)を呼び出すようになりました
- **premerged** モードと **source** モードでの翻訳ウォッチャーに対する Playwright のテストカバレッジ

## 破壊的変更(上級者向け / 内部) {#breaking-changes-advanced-/-internal}

これらは、**内部**のモジュールパス(公開 API には含まれない)をインポートしていたプロジェクトにのみ影響します:

- `src/runtime/utils/` から削除: `route-utils.ts`、`runtime-i18n-config.ts`、および `@i18n-micro/utils/*` に移動したその他のユーティリティ
- `src/runtime/server/plugins/` から削除: インラインの HMR ウォッチャー/ジェネレーター — 開発ツールをフォークしている場合は `@i18n-micro/hmr/*` を使用してください
- **`nuxt-i18n-micro`** は `@i18n-micro/utils` と `@i18n-micro/hmr` のワークスペースパッケージに依存するようになりました(モジュールと一緒に自動でインストールされます)

一般的な `nuxt.config` とコンポーザブルの使い方は変わりません。

## なぜ重要なのか {#why-it-matters}

- **サーバーレスバンドルの縮小** — `source` モードでは、ロケール × ページごとの事前マージ済みファイルを同梱せずに済みます
- **信頼できる唯一の情報源** — パス解析、マージ、ロケール検出、ペイロード設定の実装が 1 つに集約されています
- **保守の容易さ** — フレームワーク非依存のコードは `@i18n-micro/utils` でテストされ(50 以上のユニットテスト)、あらゆる場所で再利用されます
- **開発体験の向上** — HMR のロジックが分離され、テスト可能になり、ペイロードモード間で一貫しています

コミットの完全な一覧は、[変更履歴](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md)を参照してください。
