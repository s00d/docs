---

[Crowdin](https://crowdin.com/) は翻訳プラットフォームです。デフォルトロケールのファイルをアップロードし、翻訳者が Crowdin 上で作業し、他のロケールをダウンロードして戻します。モジュールはプレーンな JSON ファイルを読み込むため、Crowdin CLI に必要なのは `locales/` と `locales/pages/` を正しくマッピングする `crowdin.yml` だけです。モジュールの設定を変更する必要はありません。

## crowdin.yml を設定する {#configure-crowdin-yml}

```yml
# crowdin.yml
project_id_env: CROWDIN_PROJECT_ID
api_token_env: CROWDIN_PERSONAL_TOKEN
base_path: ./locales
preserve_hierarchy: true

files:
  - source: /en.json
    translation: /%two_letters_code%.json
  - source: /pages/**/en.json
    translation: /pages/**/%two_letters_code%.json
```

- `en` はデフォルトロケールであり、そのファイルがソースになります。
- `project_id_env` / `api_token_env` は ID とトークンを環境変数から読み込むため、シークレットがコミットされることはありません。
- `preserve_hierarchy: true` は `pages/<page>/` フォルダーをそのまま維持します。
- 翻訳ファイルの名前は、`nuxt.config.ts` のロケールの `code` と一致している必要があります。`%two_letters_code%` は `de` のようなコードに適しています。`pt-BR` のようなコードには `%locale%` を使うか、`languages_mapping` で Crowdin のコードを自分のコードにマッピングしてください。

## アップロードとダウンロード {#upload-and-download}

```bash
npm install -g @crowdin/cli

export CROWDIN_PROJECT_ID=123456
export CROWDIN_PERSONAL_TOKEN=...   # from Crowdin account settings

crowdin upload sources   # push locales/en.json and locales/pages/**/en.json
crowdin download         # write locales/de.json, locales/pages/**/de.json, ...
```

ファイルを最新に保つため、両方を CI で実行してください。ダウンロードされたファイルは手動で編集したファイルと同様にリポジトリに配置され、次回のビルドまたは dev のリロード時に読み込まれます。

## アップロードの前に {#before-uploading}

翻訳者が使われていないキーに取り組まないよう、まずソースを整理してください: [`i18n-micro clean`](/ja-jp/api/cli#clean) は未使用のキーを削除し、[`i18n-micro check`](/ja-jp/api/cli#check) はダウンロード後に不足を報告します。CLI 自体には Crowdin との連携機能はなく、このページの方法がサポートされている手順です。
