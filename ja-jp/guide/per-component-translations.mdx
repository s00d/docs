---
title: "ページ設定"
description: "$defineI18nRoute で、ページを一部のロケールに限定したり、カスタムパス、インライン翻訳を与えたり、SEO タグを無効にしたりします。"
---

`$defineI18nRoute` は、ページ自体の中からそのページの i18n オプションを設定します。ページが一部のロケールにしか存在しない場合、独自のローカライズされたパスが必要な場合、独自の翻訳をいくつか持つ場合、または hreflang/canonical タグを付けてはいけない場合に使用します。モジュールはビルド時にこの呼び出しを読み取り、生成されるルートに組み込みます。

## ページを一部のロケールに限定する {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

デフォルトの `prefix_except_default` 戦略では、`/product` と `/de/product` のみが生成され、他のロケールにはこのページのルートが存在しません。同じことは `nuxt.config.ts` から [`routeLocales`](/ja-jp/api/module-options#routelocales) で設定することもできます。

`$defineI18nRoute` は Nuxt アプリのインジェクションであり、コンパイラマクロではありません。必ず `useNuxtApp()` から取得し、`$` 付きで呼び出してください。ビルドステップが認識するのは `$defineI18nRoute(` のみです。

## インライン翻訳を追加する {#add-inline-translations}

配列の代わりにオブジェクトを渡します。そのキーが許可されたロケールとなり、値はアクティブなロケールのページ辞書にマージされます。

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

インライン翻訳は、すべてのロケール分がページコンポーネント内に含まれて配信されます。数個のキーを超える場合は[ページ翻訳ファイル](/ja-jp/guide/translations)を推奨します。インラインのキーは自己完結したページやコンポーネントにとどめてください。

## ローカライズされたパスを設定する {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

`prefix_except_default` と `defaultLocale: 'en'` の場合、これにより `/welcome` と `/de/willkommen` が生成されます。インラインのロケールオブジェクト内の `path` も同じ働きをします：`locales: { de: { path: '/willkommen' } }`。動的パラメーター、ネストされたルート、設定レベルでの代替手段については[ローカライズされたパス](/ja-jp/guide/custom-locale-routes)で説明しています。

## SEO タグを無効にする {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

設定レベルでの代替手段は [`routeDisableMeta`](/ja-jp/api/module-options#routedisablemeta) です。タグの内容については [SEO](/ja-jp/guide/seo) ページを参照してください。

## ビルドが読み取れるもの {#what-the-build-can-read}

ビルドステップは各ページファイル内の呼び出しを見つけ、アプリを実行せずにその引数を評価します。設定が次のいずれかであれば動作します。

- リテラルオブジェクト（文字列、配列、ネストされたオブジェクト、テンプレートリテラル、`process.env.NODE_ENV` に対する三項演算子）；
- 同じ `<script setup>` 内で宣言された定数から構築されたもの（`const locales = ['en', 'de']`、スプレッドを含む）；
- `code` フィールドを持つオブジェクトの配列（`[{ code: 'en' }, { code: 'de' }]`）。

別のモジュールからインポートされた値や、実行時にアプリを必要とするもの（コンポーザブル、`await`、フェッチしたデータ）は読み取れません。その場合、ビルドは `Ignored the $defineI18nRoute() config in <file>` をログに出力し、ページはデフォルトのロケールとルートを保持します。

実行時には、この呼び出しは現在のロケールのインライン翻訳をマージするだけで、ロケールが変わると再マージします。`locales`、`localeRoutes`、`disableMeta` はビルドを通じてのみ反映されるため、変更には再ビルドが必要です（開発サーバーは保存時に再ビルドします）。
