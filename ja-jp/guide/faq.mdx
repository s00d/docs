よく遭遇する問題のうち、各トピックのページで直接扱っていない質問への短い回答です。各回答には、そのトピックを担当するページへのリンクがあります。お探しの質問がない場合は、ドキュメントを検索するか [issue](https://github.com/s00d/nuxt-i18n-micro/issues) を作成してください。

## 翻訳 {#translations}

### プラグインやユーティリティ関数で `$t` が失敗する {#$t-fails-in-a-plugin-or-a-utility-function}

コンポーザブルには Nuxt コンテキストが必要です。`setup` の外では、アプリからヘルパーを取得するか、`await` の後でそのコンテキスト内で実行します:

```ts
const nuxtApp = useNuxtApp()
const title = nuxtApp.$t('errors.unknown')
await nuxtApp.runWithContext(() => nuxtApp.$t('errors.unknown'))
```

アプリがまったく存在しないサービスでは、キーを渡してコンポーネント内で翻訳してください。

### 特定のページでだけキーが生のテキストとして表示される {#a-key-shows-as-raw-text-on-one-page-only}

そのキーは別のページのファイルにあります。ページから見えるのはルートファイルと自身の `locales/pages/<route-name>/` ファイルのみです。共有キーはルートファイルに移動してください。[翻訳ファイル](/ja-jp/guide/translations)を参照してください。

### ページ遷移中にキーがちらつく {#keys-flash-while-a-page-transition-runs}

本来はちらつかないはずです。離脱するページのキーは遷移が終わるまで解決されます。それでもちらつく場合、そのキーはどちらのページにも属さないページファイル(たとえばレイアウト)にのみ存在しています。ルートファイルに移動してください。

### Vercel、Netlify、Edge で SSR 中に翻訳が欠落する {#translations-are-missing-during-ssr-on-vercel-netlify-or-edge}

これらの環境ではサーバー関数が `public/` を読み取れないため、ペイロードはサーバーバンドルに埋め込まれます。これがデフォルトです。`translationPayloads.serverAssets` が無効になっていないか確認してください。ログに `public/ is not deployed next to the server` と表示される場合は、`nitro.serveStatic: false` を設定してください。[デプロイ](/ja-jp/guide/deployment)を参照してください。

### 翻訳された文の中にリンクを入れるには? {#how-do-i-put-a-link-inside-a-translated-sentence}

`<i18n-t>` を使用します。各名前付きスロットが同名の `{placeholder}` を埋めます。

```vue
<!-- "share": "Share your {link} with friends" -->
<i18n-t keypath="share">
  <template #link>
    <i18n-link :to="{ name: 'referral' }">{{ $t('referralLink') }}</i18n-link>
  </template>
</i18n-t>
```

[`<i18n-t>`](/ja-jp/components/i18n-t) を参照してください。vue-i18n のリンクメッセージや修飾子はサポートされていません。このようにテンプレート内で組み立ててください。

## ロケールと URL {#locales-and-urls}

### `/en/about` が 404 になる {#/en/about-is-a-404}

デフォルトの `prefix_except_default` では、デフォルトロケールにはプレフィックスが付きません。`/about` が英語です。`/en/...` を使いたい場合は `prefix` または `prefix_and_default` を使用してください。[ルーティング戦略](/ja-jp/guide/strategy)を参照してください。

### ディープリンクで訪問者がリダイレクトされない {#visitors-are-not-redirected-on-deep-links}

デフォルトでは `/` のみがブラウザーの言語や Cookie に従うため、共有されたリンクはその言語を保ちます。`autoDetectPath: 'no_prefix'` または `'*'` を設定してください。[ロケール検出](/ja-jp/guide/locale-detection#autodetectpath)を参照してください。

### リロード後に選択した言語が忘れられる {#the-chosen-language-is-forgotten-after-a-reload}

プレフィックス戦略ではロケール Cookie が無効になっています。`localeCookie: 'user-locale'` を設定してください。[ロケール検出](/ja-jp/guide/locale-detection#the-cookie)を参照してください。

### URL を変えずにロケールを切り替えられますか? {#can-i-switch-locale-without-changing-the-url}

`strategy: 'no_prefix'` の場合のみ可能です。この場合、`$switchLocale('de')` は同じパスで辞書を再読み込みします。プレフィックス戦略ではロケールが URL の一部であるため、切り替えるとナビゲーションが発生します。呼び出しではなくリンクにするには、`$switchLocalePath('de')` を使用してください。

### ロケールを切り替えるとページが先頭までスクロールする {#the-page-scrolls-to-the-top-when-i-switch-locale}

これはあらゆるナビゲーションに対する Nuxt の `scrollBehavior` です。`definePageMeta({ scrollToTop: false })` を設定し、位置は自分で復元してください。playground の [`SwitchLocalePreserve.vue`](https://github.com/s00d/nuxt-i18n-micro/blob/main/playground/components/SwitchLocalePreserve.vue) はコピーして使えるラッパーです([デモページ](https://github.com/s00d/nuxt-i18n-micro/blob/main/playground/pages/scroll-test.vue))。

## ビルドとインテグレーション {#build-and-integrations}

### `nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` {#nuxt-seodefaults-depends-on-nuxt-site-configi18n-but-they-are-not-registered}

古い `nuxt-site-config` は `@nuxtjs/i18n` しか認識しません。`@nuxtjs/seo` を 3 以降にアップグレードし、`modules` で `nuxt-i18n-micro` をその前に記述してください。[SEO](/ja-jp/guide/seo) を参照してください。

### Cloudflare で `@unhead/vue` に関するビルドエラーが発生する {#build-error-about-@unhead/vue-on-cloudflare}

プリレンダリングのステップで見つけられるよう、アプリに `@unhead/vue` をインストールしてください。モジュール自体は `nodejs_compat` を必要としません。アプリ内の他の何かが必要とする場合にのみ、`wrangler.toml` に `compatibility_flags = ["nodejs_compat"]` を追加してください。
