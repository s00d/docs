---

`meta: true`(デフォルト)の場合、ローカライズされたすべてのページに `<html lang dir>`、canonical リンク、`hreflang` の代替リンク、`x-default`、Open Graph のロケールタグが付与されます。このページは、公開オリジンを設定したい場合、タグに表示されるロケールを調整したい場合、または特定のページでタグを上書きしたい場合に必要です。ほとんどのサイトでは、`site.url` または `metaBaseUrl` と正しい `iso` コードがあれば十分です。

## 最小構成 {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

すると `/de/about` は次のようにレンダリングされます:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## テキストの方向 {#text-direction}

`<html dir>` はロケールの `dir` から決まります。指定がない場合、右から左に書く言語には `iso`(または `code`)から判定して `rtl` が付きます: アラビア語、ヘブライ語、ペルシア語、ウルドゥー語などいくつかの言語、および `az-Arab` のような RTL の文字体系を持つタグです。それ以外のロケールには `dir` 属性が付かず、ブラウザーは `ltr` として扱います。

<Warning>

**`dir: 'auto'` は大きなページでパース時間を増やします** — `<html>` に `auto` を指定すると、ブラウザーはパース中にコンテンツから方向を判断します。Chromium ではそのコストがページの大きさ以上に増加します: 要素数 5,000 で約 100 ms、20,000 で約 1 秒です。言語を特定できない小さなページにのみ使用してください。

</Warning>

## 出力されるタグ {#which-tags-you-get}

- **hreflang**: ページを提供するロケールごとに 1 つのタグ。値は `iso`(`iso` がない場合は `code`)で、URL には canonical と同じクエリが付きます。[ページ設定](/ja-jp/guide/per-component-translations)や `routeLocales` で制限されたページは、そのロケールのみを列挙します。[`hreflangBaseLanguage: true`](/ja-jp/api/module-options#hreflangbaselanguage) を指定すると、最初の地域ロケールについて地域なしの言語(`es-ES` → `es`)も追加されます。
- **x-default**: デフォルトロケールの URL。デフォルトロケールがそのページを提供する場合のみ出力されます。
- **og:locale**: `iso` から導出されます(`en-US` → `en_US`)。対応が直接的でない場合は、ロケールに `og` を設定してください。例: `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`。どちらもない場合、`og:locale` は書き出されず、開発モードで警告が出ます。
- **canonical / og:url**: クエリパラメーターを除いた現在の URL。ただし [`canonicalQueryWhitelist`](/ja-jp/api/module-options#canonicalquerywhitelist) に含まれるもの(デフォルトは `page`、`sort`、`filter`、`search`、`q`、`query`、`tag`)は残ります。

ストラテジー別:

| ストラテジー | hreflang と x-default | canonical、og:url、og:locale、html 属性 |
| --- | --- | --- |
| `prefix`、`prefix_except_default`、`prefix_and_default` | あり | あり |
| `no_prefix` | なし(1 つの URL がすべてのロケールを提供) | あり |

## 公開オリジンを設定する {#set-the-public-origin}

絶対 URL には、次のうち最初に見つかったものが使われます:

1. [`metaBaseUrl`](/ja-jp/api/module-options#metabaseurl)
2. `nuxt-site-config`(`@nuxtjs/seo` によってインストールされる)の `site.url`
3. リクエストのオリジンに `app.baseURL` を付加したもの

最初の 2 つのいずれかを固定してください。

<Warning>

リクエストオリジンへのフォールバックは `X-Forwarded-Host` と `X-Forwarded-Proto` を読み取ります。[`metaTrustForwardedHost`](/ja-jp/api/module-options#metatrustforwardedhost) と `metaTrustForwardedProto` のデフォルトが `true` だからです。これは、それらのヘッダーを上書きするプロキシの背後にある場合にのみ安全です。そうでない場合、クライアントが canonical リンクのホストを選べてしまい、キャッシュがそのページを他の訪問者に配信する可能性があります。

アプリに直接アクセスできる場合は `metaBaseUrl` を固定してください: 両方のオプションを `false` にする場合と異なり、偽造された `Host` も無視されます。[プロキシまたは CDN の背後](/ja-jp/guide/deployment#behind-a-proxy-or-cdn)を参照してください。

</Warning>

このフォールバックは、1 つのデプロイで複数のドメインに応答する場合に便利です: `https://site-a.com/en/about` と `https://site-b.com/en/about` は、それぞれ独自のオリジンを持ちます。

ロケールに `baseUrl` がある場合、既知のホストは `metaBaseUrl` や `site.url` よりも優先して自身の `baseUrl` を使います。そのため canonical と `og:url` はそのドメインに留まり、`hreflang` は各ロケールをそのドメインに向けます。それ以外のホストは `metaBaseUrl`、なければデフォルトロケールの `baseUrl`、なければ `site.url` を使うため、なりすましの `Host` がタグに影響することはありません。これらがいずれも設定されていない場合はリクエストオリジンへのフォールバックが残り、ビルド時に警告が出ます。[レイヤーとドメイン](/ja-jp/guide/layers#multiple-domains)を参照してください。

## ロケールやページを除外する {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

デフォルトロケールが `seo: false` の場合、`x-default` は書き出されません。特定のページでタグを無効にするには、[ページ設定](/ja-jp/guide/per-component-translations#turn-off-seo-tags)の `disableMeta`、または設定ファイルの [`routeDisableMeta`](/ja-jp/api/module-options#routedisablemeta) を使用してください。

## 特定のページでタグを上書きする {#override-tags-on-one-page}

一部の翻訳しか存在しない CMS コンテンツや、URL が API から得られる場合は、[`useI18nHead`](/ja-jp/composables/useI18nHead) で生成されたタグを置き換えます:

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` では `canonical`、`xDefault`、`ogLocale`、`ogUrl` の設定や削除もできます。`disable` はグループ全体(`'hreflang'`、`'x-default'`、`'canonical'`、`'og'`、`'og-alternates'`、`'html'`)を削除します。ロケール切り替え後に値が再計算されるよう、ゲッターを渡してください。ロケールごとのスラッグについては、先に `$setI18nRouteParams` を設定すれば([ローカライズされたパス](/ja-jp/guide/custom-locale-routes#per-locale-slugs))、生成される代替リンクはすでにそれを使用します。

## 末尾のスラッシュ {#trailing-slash}

`$localePath`、`$switchLocalePath`、`$switchLocaleRoute` のルートオブジェクト、`<i18n-link>`、`<i18n-switcher>`、ロケールのリダイレクト、そして SEO の URL は、1 つのスラッシュ規則に従います: デフォルトでは `experimental.defaults.nuxtLink.trailingSlash`、i18n のパスを別にしたい場合は i18n 設定の [`trailingSlash`](/ja-jp/api/module-options) です。

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/)(サイトマップ、robots、schema.org)は、`nuxt-site-config` 4 以上を介してこのモジュールと連携します。サイト設定がロケールを読み取れるよう `nuxt-i18n-micro` を先に記述し、`site.url` を一度だけ設定してください — これは上記のタグにも使われます。

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

翻訳されたサイト名と説明は、ロケールファイル内の `nuxtSiteConfig.name` / `nuxtSiteConfig.description` キーから取得されます。`Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` というエラーは、`@nuxtjs/seo` のバージョンが 3 より古いことを意味します。アップグレードしてください([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133))。
