このページでは、nuxt-i18n-micro とその `@i18n-micro/*` パッケージをアップグレードする際に、アプリに生じる変更を一覧にしています。依存関係のバージョンを上げる前に、移行元のバージョンに該当するセクションをお読みください。ほとんどのアプリでは、コードの変更はわずかです。

<Tip>

**`@nuxtjs/i18n` から移行しますか？** — [@nuxtjs/i18n からの移行](/ja-jp/guide/migration)を参照してください。

</Tip>

## 3.30.3 以降：メジャーリリース {#after-3-30-3-the-major-release}

モジュールオプション、`$t`、`$localePath`、`$switchLocale` などのヘルパー、コンポーネント、コンポーザブル、ドキュメント化されたサーバーユーティリティは名前が変わりません。変わったのは動作で、その大半はバグ修正です。アダプターパッケージとルーティングパッケージには実際の API の破壊的変更があります：[フレームワークパッケージ](#framework-packages)と[その他のパッケージ](#other-packages)を参照してください。

### 最初にやること {#do-this-first}

1. **バージョンを確認します。** モジュールには Nuxt 3.18 以降と Node 20 以降が必要です。Nuxt には独自の Node の最低要件があり、Nuxt 4.5 は `^22.19.0 || ^24.11.0 || >=26.0.0` を宣言しています。Nuxt 3.18.0 自体での `nuxt generate` は素の Nuxt でも失敗します（`[unstorage] Invalid key: "/"`）。3.21.11 は動作します。`@i18n-micro/react` には React 18 以降が必要です。
2. **インストール済みのパッケージを修正します。**
   - `@i18n-micro/hmr` を削除します。翻訳の HMR はモジュールに組み込まれています。
   - テストで `@i18n-micro/test-utils` をインポートしている場合は追加します：`npm install -D @i18n-micro/test-utils`。モジュールと一緒にはインストールされなくなりました。
   - `nuxt-i18n-micro-cli` を `@i18n-micro/cli` に置き換えます。28 個のコマンドは 16 個になり、そのうち 3 つは `check` に置き換わり、終了コードも変わります：[CLI ガイド](/ja-jp/guide/cli#moving-from-nuxt-i18n-micro-cli)を参照してください。
3. 以下の表の項目について**コードを検索します**。
4. **アプリの前段にあるものを確認します。** プロキシの背後でロケールに `baseUrl` を使っている場合は、[プロキシや CDN の背後](/ja-jp/guide/deployment#behind-a-proxy-or-cdn)を参照してください。CDN を使っている場合は、そのキャッシュキーを `Vary` ヘッダーと照らし合わせて確認します：[HTML のキャッシュ](/ja-jp/guide/deployment#caching-html)を参照してください。`apiBaseClientHost` や厳格な CSP を使っている場合は、新しい `preload` リンクを許可します：[SEO と head タグ](#seo-and-head-tags)を参照してください。
5. **スナップショットを更新します。** head のスナップショットには `preload` リンクが加わり、スイッチャーのマークアップが変わり（[`<i18n-switcher>` と `<i18n-link>`](#&lt;i18n-switcher>-and-&lt;i18n-link>)）、`$localeRoute` の出力に含まれるクエリ文字列のエンコード方法も変わりました。
6. **各ロケールでページを開き、生のキーが表示されていないか確認します。** 前のページのファイルのキーを使っていたレイアウトでは、それらが生のまま表示されるようになります。それらのキーはルートファイルに移動してください。

<Warning>

**`@i18n-micro/path-strategy` の `switchLocaleRoute` は第 1 引数がなくなりました** — `switchLocaleRoute(fromLocale, toLocale, route, options)` は `switchLocaleRoute(toLocale, route, options)` になりました。**古い JavaScript の呼び出しは失敗せず、誤った結果を返します。** `fromLocale` がターゲットとして、`toLocale` がルートとして読み取られるためです。これを教えてくれるのは TypeScript だけです。Nuxt の `$switchLocaleRoute` は影響を受けません。

</Warning>

| 検索する対象 | 対処法 |
| --- | --- |
| `@i18n-micro/path-strategy` の `switchLocaleRoute(` | 第 1 引数を削除します。上記を参照 |
| `dependsOn` 内の `i18n-plugin-hooks` または `i18n-plugin-define` | `i18n-plugin-loader` を使用します。古い名前ではエラーなしに何も待たなくなります |
| `router.push({ name })` 内の `localized-…` という名前 | ページ自身の名前を `$localeRoute` または `<i18n-link>` に渡します |
| `$localeRoute` や `$switchLocaleRoute` の結果に対する `.name` や `.params` | それらがない場合に対処します。[リンク](#links-and-route-objects)を参照 |
| ロケールに `baseUrl` がある状態での、`<NuxtLink :to>` や `router.push` 内の `$localeRoute(x, 'fr')` | `$localePath` を使用します。[ロケールドメイン](#locale-domains)を参照 |
| `$getI18nConfig().globalLocaleRoutes`、またはそこから取得する `isSSG`、`hmr`、`hooks`、`noPrefixRedirect`、`routeLocales`、`routeDisableMeta` | ランタイム設定から削除されました。これらを読むのはビルドだけで、オプション自体は変わっていません。`ModuleOptionsExtend.isSSG` は、何も設定しない非推奨のオプショナルプロパティとして残っています |
| `useLocaleServerMiddleware`、`useTranslationServerMiddleware`、`loadTranslationsFromServer`、`detectCurrentLocale` 以外のサーバー自動インポート | 削除します。`getI18nServerConfig`、`detectRequestLocale`、`getRequestLocale`、`loadLiveDevTranslations`、`getOrCreateServerTranslationCache`、`DEFAULT_SERVER_CACHE_SIZE`、およびウォッチャーのヘルパーは自動インポートされなくなりました |
| `nuxt-i18n-micro` からの `resolveTranslationPayloadMode`、`resolveTranslationPayloadOptions`、`resolveTranslationPayloadPublicDir`、`resolveTranslationPayloadPublicRel`、`shouldCopyTranslationPayloadsToPublic`、`shouldRegisterNitroServerAssets` | 削除します。`TranslationPayloadMode` 型は残ります |
| `params` にマークアップを含む `<i18n-t>` の `html` | マークアップを翻訳に移動します。[`<i18n-t>`](#&lt;i18n-t>) を参照 |
| `<i18n-t>` の `ref` | 関数型コンポーネントのため、`ref` ではインスタンスが得られません |
| `useI18n().$t = stub` などの書き込み | `useI18n()` はアプリごとに 1 つのオブジェクトなので、書き込みはすべての呼び出し元に及びます。`useI18n` 自体をスタブしてください |
| `ModuleHooks` 型 | `ModuleRuntimeHooks` に名前が変わりました |
| `@i18n-micro/utils/resolve-locale` からの `resolveServerLocale`、`resolvePreferredLocale` | `url`、`query`、`state`、`cookie`、`acceptLanguage` を指定して `resolveLocale` を呼び出します |

`detectCurrentLocale` は非推奨です。引き続き動作し、サーバー自動インポートでもあります。同じルールを適用する [`useLocaleServerMiddleware(event).current`](/ja-jp/guide/server-side-translations) を使用してください。

このドキュメントの 17 ページが移動しました。古い URL はリダイレクトされるため、それらへのリンクは引き続き機能します。

### URL とリダイレクト {#urls-and-redirects}

- **`prefix_except_default` では `/en` と `/en/...` は 404 になります**（`en` がデフォルトの場合）。ドキュメントに記載のとおりです。
- **大文字小文字や綴りが異なるロケールプレフィックスは 404 になります。** 以前は `/DE/about` がドイツ語のルートをデフォルトロケールでレンダリングするか、`/en/DE/about` にリダイレクトしていました。その URL に独自のページがある場合は、ページのままです。キャッチオールや `[slug]` のページはこれに該当しません。`[...slug]` の下の `/DE/x` や `[slug]` と並ぶ `/DE` も 404 になるため、大文字小文字の違うロケールコードと同じ CMS スラッグはページを失います。`ssr: false` の場合はサーバーが応答しないため、`/DE/about` はドイツ語のページを表示します。
- **大文字小文字の異なるページパスは、正しい綴りにリダイレクトされます。** `/T/BASIC` は 200 でしたが、現在は `/t/basic` への `302` です。
- **不明な URL は 404 のままです。** `autoDetectPath: '*'` または `'no_prefix'` の場合、`/nope` が先に `/de/nope` にリダイレクトされることはなくなりました。`prefix` ではリダイレクトが維持され（プレフィックスなしでは何も提供されないため）、どこでも `/` も同様です。
- **プレフィックスなしの他のロケールのカスタムパスは、`prefix_except_default` でそのページを見つけます。** `/a-propos` は 404 でしたが、現在はデフォルトロケールの URL（`/about`）への `302` です。`prefix` では同じリダイレクトが実在するページに到達するようになりました（`/en/about`。以前は 404 の `/en/a-propos` でした）。`prefix_and_default` は 404 のままです。
- **`redirects: false` を指定した `prefix` は、プレフィックスなしの URL に 404 を返します**（`/about` は `302` でした）。デフォルトのカスタムパスを持つページの元の URL も含みます。`$localePath('/about')` は引き続きそのページを見つけます。
- **`prefix_except_default` では、デフォルトのカスタムパスを持つページの元の URL がそのカスタムパスにリダイレクトされます。** 動的ページも含みます。`/dir/one` は 404 でしたが、現在は `/dir-one/one` への `302` です。
- **`autoDetectPath: '*'` は、プレフィックスなしのパスにも Cookie と `Accept-Language` を適用するようになりました**（`/about` → `/de/about`）。
- **`prefix` では、プレフィックスなしの URL は訪問者のロケールを維持します。** Cookie が `de` の場合、`/about` や素の `<NuxtLink to="/about">` は、`autoDetectPath` の設定にかかわらず、すべてのパスで `/de/about` に移動します。
- **`prefix_and_default` では、プレフィックスなしの URL はデフォルトロケールです。** 以前は `Accept-Language: de` の `/contact` がドイツ語でレンダリングされてから英語でハイドレートされていました。現在はデフォルトロケールでレンダリングされ、訪問者は `/de/...` からドイツ語にアクセスします。
- **`no_prefix` では、カスタムパスはそれ自身のロケールでレンダリングされ**（`/ueber-uns` はどの希望でもドイツ語）、限定されたページは提供するロケールのいずれかでレンダリングされます。複数のロケールが共有するパスは、希望するロケールがその中に含まれていればそのロケールでレンダリングされ、`baseUrl` の下ではそれぞれのドメイン上のページになります。それらのロケールは 1 つのレコード `localized-<page>-<first locale>` を共有します。
- **`noPrefixRedirect` は訪問者のロケールに従います。** Cookie が `de` の場合、`/about` はデフォルトロケールの `/about-us` ではなく `/ueber-uns` に移動し、ドイツ語でレンダリングされます。独自のカスタムパスを持たないロケールは `/about` にとどまります。
- **ページのない `routeRules` のリダイレクトはローカライズされません。** `/de/old` は空の 200 でしたが、現在は 404 です。必要であればプレフィックス付きのパスにルールを追加してください。他のロケールからそのようなルールへのリンクは、記述どおりのパスを保ち、ルールのターゲットに到達します。
- **ルートルールはカスタムパスにも適用されます。** `blog/[slug]` が `/de/artikel/:slug` というパスを持つ場合、`/blog/**` はそのパスにも適用され、ルールは `no_prefix` でもコピーされます。`/de/artikel/news` のような静的な兄弟ルートもそのパターンに一致します。既にロケールプレフィックスの下に書かれたルールは記述どおりのままです。
- **`disabled: true` のロケールは、そのプレフィックスに即座に 404 を返し**、そのロケールへのリンクは現在のページにとどまります。ランタイムで無効化されたロケールも同様です。以前はフォールバックロケールでレンダリングされていました。
- **モジュールの 404 は `Page Not Found` と表示されます。** 無効化されたロケールのプレフィックスや、ホスト自身のプレフィックスで、Nuxt が `Page not found: /de/about` と表示していた箇所です。ステータスは同じです。
- **`customRegexMatcher` は、最初のセグメントがロケールのように見える実在のページを 404 にしなくなりました。**
- **ローカライズされたルート名が一貫するようになりました。** 共有ロケールレコードの下の子はページの名前を保持し、`no_prefix` は `localizedRouteNamePrefix` を尊重し、index の子を持つ親は名前なしのままです。
- **モジュールが `name` なしで追加するページ**（`extendPages`）は、ローカライズされて名前が付き、ロケールのバリアントと `hreflang` を持ちます。以前はローカライズされないままでした。
- **`nuxt.config` のエントリは `$defineI18nRoute` より優先されます。** キーの形式（`about/team`、`/about/team`、`about-team`）にかかわりません。以前はどちらが優先されるかが綴りに依存していました。
- **新しいビルド警告：** 自身のロケールコードで始まる `localeRoutes` の値（`fr: '/fr/article'`）、および親の外にある子のカスタムパス。
- **ハッシュモードが `prefix` で動作します。** ドキュメントは `/` で、`/en` や `/about` はハッシュへリダイレクトされます。
- **`prefix_except_default` と `prefix_and_default` で、`/#/de/x` がドイツ語でレンダリングされます。** 以前はハイドレーションの不一致を伴って英語でレンダリングされていました。

### リンクとルートオブジェクト {#links-and-route-objects}

- **ページを提供しないロケールへのリンクは、そのロケールのホームを指します。** `$localeRoute`、`$switchLocalePath`、スイッチャーは、他のロケールのページを返さなくなりました。
- **不明なロケールコードはデフォルトロケールになります。** 以前は `$localePath(path, 'xx')` と `$localeRoute` が `/xx` を返していました。
- **`$localePath` は `http(s):`、`mailto:`、`tel:` スキームを持つ文字列をそのまま返し、`$localeRoute` の `path` と `fullPath` もそれを変更せずに保持します。** そのため、検証していない値（`?next=` パラメーターなど）をリンク先として渡さないでください。`//host` や `x.com` のような裸の名前はパスのままで、すべてのロケールでこのオリジン上にとどまり、それらから生成されるリンクがオリジンを離れることはありません：`/de//x.com` をデフォルトロケールにすると `/x.com` になります。バックスラッシュはスラッシュとして扱われます。
- **`$localePath` はパスをエンコードします：** `/a b` は `/a%20b` になります。
- **`$localeRoute` と `$switchLocaleRoute` はプレーンなオブジェクトを返します。** `ref`、`reactive`、`useState`、JSON、スプレッドで安全に使えます。パラメーターにエスケープが必要な場合、オブジェクトは `{ path, fullPath, query, hash }`（`$localeRoute` は `href` を追加）となり、`name` や `params` は含まれず、URL はリロードの前後で同じままです。通常の URL では両方が含まれます。`name` は新しく追加されたもので、古いオブジェクトには一度も含まれていませんでした。`.name` や `.params` を読むコードはそれらがない場合に対処する必要があり、どちらの形式になるかは値に依存します。
- **`trailingSlash` では、`$switchLocaleRoute` は常にそのパス形式を返し**（通常のスラッグも含む）、サーバーのリダイレクトも `trailingSlash` に従います。このオプションでは結果や `Location` ヘッダーが変わることがあります。
- **`$localeRoute` の出力に含まれるクエリ値は vue-router のエンコードを使用します：** `/` はそのまま残り、スペースは `+` になります（`?redirect=/v2`、以前は `%2Fv2`）。デコード後の値は同じですが、そのような `href` のスナップショットは変わります。
- **パスのないリンクは現在のページにとどまります。** `$localePath('#top')`、`'?p=2'`、`''`、`{ query }` は現在のページを維持します。以前は `'#top'` がサイトのルートから読み取られていました。裸の `'about'` は引き続き `/about` を意味します。
- **スプレッド。** `{ ...route, query }` と `{ ...route, hash }` は、`$switchRoute` を通しても変更を保持します。`$localeRoute`、`$localePath`、`$switchRoute` では新しい `path` が優先されます。`{ ...route, params }` は名前付きルートでは機能しますが、パス形式のルートではパスが優先されてパラメーターは無視され、vue-router の開発時警告が出ます。`$localeRoute({ name, params })` を使用してください。
- **`$switchRoute` はアプリ内にとどまります。** ロケール自身の `baseUrl`、`mailto:`、`tel:` はアプリを離れ、それ以外の文字列はパスとして扱われます。
- **`excludePatterns`** はセグメント全体に一致し（`'/admin'` は `/administrator` に一致しなくなりました）、glob はアンカーされます（`/docs/*` は `/en/docs/x` に一致しなくなりました）。`RegExp` パターンがランタイムに届くようになりました。以前はそこで失われていました。それらに一致するページはローカライズされません：`hreflang` はなく、`prefix_except_default` ではデフォルトロケールになります。パターンを[パスの除外](/ja-jp/guide/excluding-static-files)と照らし合わせて確認してください。

パラメーター内の `%` や `?` は、Nuxt 4.5.2 ではどのアプリでもサーバーレンダリングされたリロードを経ると保持されません。これはアップストリームの問題であり、モジュールの問題ではありません。

### ロケールドメイン {#locale-domains}

- **`locales[].baseUrl` がリクエストをルーティングするようになりました。** 1 つのビルドですべてのドメインを提供します：[レイヤーとドメイン](/ja-jp/guide/layers#multiple-domains)を参照してください。`baseUrl` が設定されている場合、別のドメインのロケールはこのホストでは 404 になり（`example.de` 上の `/en/about`）、同じホスト上のロケールへのリンクは相対リンクになります。`localhost` を含むその他のホストへのリクエストは以前と同じように動作します。ただし、canonical と `hreflang` はリクエストのオリジンではなく、設定されていれば `metaBaseUrl`、なければデフォルトロケールの `baseUrl` を使用します。
- **`Host` を書き換えるプロキシの背後では、** [`trustForwardedHost`](/ja-jp/api/module-options#trustforwardedhost) を設定するまで、すべてのリクエストがビルド時の設定にフォールバックします。`metaTrustForwardedHost` とは異なり、デフォルトは `false` です。[プロキシや CDN の背後](/ja-jp/guide/deployment#behind-a-proxy-or-cdn)を参照してください。
- **`baseUrl` を使う場合、`nuxi generate` にはドメインごとに 1 回ずつ `NUXT_I18N_DOMAIN` が必要です。** これがないとビルドは警告を出し、それらのロケールはページのないリンクになります。[静的サイト](/ja-jp/guide/deployment#static-site-(nuxi-generate))を参照してください。
- **`baseUrl` を持つロケールへのリンクは `$localePath` または `<i18n-link>` を通します。** `<NuxtLink :to="$localePath(x, 'fr')">` と `<i18n-link :to="$localeRoute(x, 'fr')">` はその絶対 URL になり、クリックするとそこに移動します。ルーターは絶対 URL のオブジェクトを受け付けません：`<NuxtLink :to="$localeRoute(x, 'fr')">` や `router.push($localeRoute(x, 'fr'))` は `/https://fr.example.com/...` というこのアプリのパスのままです。`localhost` やプレビューホストでは、`baseUrl` を持つすべてのロケールが（現在のロケールも含めて）このようなリンクになります。コード内では `navigateTo($localePath(x, 'fr'), { external: true })` を使用してください。
- **ドメインのホームは、リンク、canonical、`hreflang` のすべてで末尾のスラッシュなしで記述されます**（`https://example.de`）。
- **`prefix` では、別のドメインへのリンクは `baseDefault` の有無にかかわらずロケールプレフィックスを保持します。** リダイレクトするだけの `https://example.de/about` ではなく、`https://example.de/de/about` になります。
- **`prefix_except_default` で、ビルドのデフォルト以外のロケールに `baseDefault` がある場合、ルートはすべてのプレフィックスを保持します。** 他のドメインからリンクできるようにするためです。`/en` は引き続き 404 です。違いが見えるのは `router.getRoutes()` を読むコードだけです。
- **`prefix_except_default` では、ホスト自身のプレフィックスはその `baseDefault` ホスト上で 404 になります。** 以前は `de` ホスト上の `/de/x` が 200 でした。
- **`$getI18nConfig().locales` には、そのホストが提供するロケールだけが含まれます。** `linkLocales` にはすべてが含まれ、`$getLocales()` は完全なままです。

### ナビゲーションと `$switchLocale` {#navigation-and-$switchlocale}

- **ナビゲーションはコミット時に適用されます。** 辞書、ロケール、パラメーター、head は `router.afterEach` で変わるため、キャンセルまたはブロックされたナビゲーションは何も変えず、次のチャンクの読み込み中も古いページのリンクは有効なままです。`beforeResolve`、`beforeRouteEnter`、または後続のグローバルガードは、古い辞書とロケールを参照するようになりました。ルートミドルウェアは影響を受けません。
- **チャンクの読み込みに失敗しても現在の辞書は保持されます。** 以前はルートファイルの 5xx、ネットワークエラー、不正なボディで生のキーが表示されていました。現在は新しいページが古い文字列でレンダリングされ、次のナビゲーションで再試行されます。404、またはファイルの代わりに静的ホストの SPA シェルが返された場合は、次のリロードまでルート辞書が使われます。
- **`$switchLocale` は `true` または `false` で解決されます**（以前は何も返しませんでした）。ロケールの辞書が適用されなかった場合は `false` です。型は `Promise<boolean>` で、`$switchRoute` は `Promise<void>` です。
- **`$switchLocale` は明示的な選択です。** 到着時にロケールを保存し、404 の場合も保存します。ナビゲーションがブロック、キャンセル、または例外をスローした場合、保存された設定と状態は元のままで、例外は再スローされます。別のホストへ移動する場合は、先に保存します。`no_prefix` とハッシュモードでは、ナビゲーションがどうなっても切り替えは維持されます。すべてのロケールで 1 つの URL を持つページ（`excludePatterns`）では選択は取り消されず、次のページの URL が決定します：`prefix_except_default` では、プレフィックスなしのリンクはデフォルトロケールに戻ります。
- **`no_prefix` では、2 つのページがカスタムパスを共有している場合でも `$switchLocale` はそのページを維持します。** エスケープされたパラメーターでも同様です。そのような URL のリロードや、エスケープされたパラメーターを持つ `$localeRoute` は、最初のレコードに到達します。
- **クライアントリダイレクトは、そのナビゲーションのモードを維持します。** `prefix` での素の `<NuxtLink to="/about">` は、現在の履歴エントリを上書きする代わりに履歴エントリを追加します。`router.replace` は引き続き置き換えます。
- **サーバーからの `$setI18nRouteParams` と `useI18nHead` はハイドレーション後も保持されます。** ページが SSR 中にパラメーターを設定すると、`/news/2` に到着した後、スイッチャーがどこに置かれていても、サーバーの HTML でも、スイッチャーは `/de/news/2` ではなく翻訳されたスラッグ（`/de/news/2-zwei`）にリンクします。別のパスへのナビゲーションがコミットされると破棄されます（`/news/1` から `/news/4` への移動も含む）。新しいページで再度設定してください。
- **setup 内で読み取った `$setI18nRouteParams` は、そのページにバインドされます。** 既に離れたページからの遅れた呼び出しは何もしません。`useNuxtApp().$setI18nRouteParams` はアクセサーになり、2 回読み取ると 2 つの関数が得られます。セッターはありません：テストのスタブで行われるような `useI18n().$setI18nRouteParams = fn` は strict モードで例外をスローするため、`useI18n` 自体をスタブしてください。レイアウトや `app.vue` 内では、離れるものが何もないため、通常の関数です。
- **パラメーターを持つページでは、サーバーはレンダリング終了時に `<i18n-switcher>` のリンクを書き換えます。** レイアウト内のスイッチャーはページの非同期 setup より前にレンダリングされるためです。手書きの `$switchLocalePath` リンクは書き換えられません：[カスタムロケールルート](/ja-jp/guide/custom-locale-routes)を参照してください。Nuxt の SSR ストリーミングでは、最初の HTML は URL のパラメーターを保持します。
- **サーバーコンポーネントの `locale` という名前の prop は、そのレンダリングロケールを設定します。** そのため `<Greeting :locale="$getLocale()" />` は URL と切り替えに追従します。その中の `$getLocale()`、`$localePath`、`$getLocaleName` も prop に従います。[サーバーサイド翻訳](/ja-jp/guide/server-side-translations)を参照してください。prop がない場合は、引き続き Cookie またはデフォルトを使用します。
- **`keepalive` ページは、戻ったときにパラメーターと head を取り戻します。**
- **`prefix_except_default` で `false` に設定されたネストされたページには、ロケール URL がありません。** `globalLocaleRoutes: { 'parent-kid': false }` の場合の `/de/parent/kid` は提供されていましたが、現在は 404 です。ページは `/parent/kid` にとどまります。

### ロケール検出と Cookie {#locale-detection-and-the-cookie}

どこでも同じ 1 つの優先順位を使います。[ロケール検出](/ja-jp/guide/locale-detection)で説明しています。

- **ページで `?locale=` が評価されるのは `no_prefix` の場合だけです。** プレフィックス系の戦略では URL が決定します。`/about?locale=de` が `lang="en"` のままドイツ語でレンダリングされることはなくなりました。`?locale=de&locale=fr` は最初の値を読み取ります（以前は `"de,fr"` でした）。
- **`Accept-Language` は `q` 値を尊重します**（`fr;q=0.1, de;q=0.9` → `de`、`q=0` はその言語を除外）。地域ロケールの照合は `locales` の順序に依存しなくなり、中国語の文字体系をまたぐこともありません。
- **ページへのクライアントナビゲーションは、そのロケールを Cookie に保存します。デフォルトロケールのプレフィックスなしページでも同様です。** `localeCookie` が設定されている場合、`/about` へのリンクをクリックした訪問者は `user-locale=en` を持つようになり、その後ブラウザの言語を変えても `/` がリダイレクトされなくなります。その URL の初回読み込みでは何も保存されません。`no_prefix` とハッシュモードでは、ナビゲーションは変更があった場合にのみ保存します。
- **404 は Cookie を書き込みません：** どのモードでも、レスポンスでも、そこへの素のクライアントナビゲーションでも書き込みません。`no_prefix` では、プレフィックス付きに見える URL も書き込みません。
- **`no_prefix` で明示的に指定した `localeCookie: null` が尊重されます。** 以前は `user-locale` になっていました。`nuxt.config` の `i18n` ブロックで設定してください：`modules: [[name, opts]]` やレイヤー内の `null` は引き続き失われます。
- **ハッシュモードは `hash-locale` Cookie だけを読み取ります。** 単独の `user-locale=de` は評価されなくなりました。
- **不正なロケール Cookie は無視され、そのまま残ります。** すべての SSR ページが 500 で失敗することはなくなりました。リクエストのたびに削除されることもなくなり、プレフィックス付きのページがロケールを保存できなかった問題も解消されました。
- **URL のロケールが最優先です。** `/en/...` でのプラグインの `setLocale('de')` が `de` 辞書を読み込むことはなくなり、状態内の不明なコードは無視されます。
- **サーバー API ヘルパー**（`useLocaleServerMiddleware`、`useTranslationServerMiddleware`）は、すべてのルートで同じ順序を使います：`?locale` → `[locale]` パラメーターまたはプレフィックス → Cookie → ヘッダー → デフォルト。`localeCookie: null` と `autoDetectLanguage: false` を尊重するようになり、ロケールごとに辞書をキャッシュします。
- **ランタイムオーバーライドがルーティングに反映されます。** `NUXT_I18N_DEFAULT_LOCALE` とランタイムの `disabledLocales` は生成される戦略を変更するようになり（無効化されたロケールはルーティングを停止します）、ランタイムの `disabledLocales` はビルドのものに追加されます。`prefix_except_default` と `prefix_and_default` では、そのロケールのプレフィックスなしのルートがビルド時に生成されるため、ランタイムの `defaultLocale` は警告とともに無視されます。ランタイムの `fallbackLocale` は有効なロケールでなければなりません。そうでない場合は警告とともに破棄され、ビルドの値が有効であればそれが適用されます。[ランタイムオーバーライド](/ja-jp/guide/runtime-overrides)を参照してください。

### SEO と head タグ {#seo-and-head-tags}

- **`dir="auto"` はデフォルトではなくなりました。** 以前は `dir` のないロケールに `dir="auto"` が付与され、大きなページの解析が遅くなっていました。現在は、既知の RTL 言語には `dir="rtl"` が付与され、それ以外のロケールには属性が付与されません。これは Nuxt、`@i18n-micro/vue`、`astro`、`vitepress` に適用されます。以前の出力を維持するためにロケールに `dir: 'auto'` を設定すると、20,000 要素で約 1 秒の解析コストがかかります：[テキストの方向](/ja-jp/guide/seo#text-direction)を参照してください。
- **すべての SSR ページに新しいタグが加わります：** `<link rel="preload" as="fetch" crossorigin="anonymous" href="/_locales/...">`。404 ページも同様です。`apiBaseClientHost` の場合、`href` はそのホスト上になるため CORS が必要です。厳格な CSP ではこれを許可する必要があります。
- **`hreflang` には、そのページを提供するロケールだけが列挙されます。** `x-default` はデフォルトロケールがそのページを提供する場合にのみ出力されます。
- **ローカライズされていないページには `hreflang` も `og:locale:alternate` もありません。**
- **オリジンがリクエストから得られる場合、canonical と `hreflang` には `app.baseURL` が含まれます。** `metaBaseUrl` と `site.url` は記述どおりのままです。
- **404 ページは URL のロケールで `<html lang dir>` を持ちます。** canonical、`hreflang`、`og:url`、`og:locale`、代替リンクはありません。モジュール自体が一致したレコード（`/en/...`）で 404 を返す場合も同様です。`useI18nHead` の `replace` で渡したタグは残るため、エラーページではスキップしてください。
- **canonical、`og:url`、`hreflang` はホワイトリストに含まれるクエリを保持します**（`/about?page=2`）。サーバーでも同様です（以前は SSR 中に破棄されていました）。`page`、`sort`、`filter`、`search`、`q`、`query`、`tag` がデフォルトでホワイトリストに含まれます。[`canonicalQueryWhitelist`](/ja-jp/api/module-options#canonicalquerywhitelist) を参照してください。
- **解析できない `X-Forwarded-Host` は無視されます。** すべてのページが 500 になることはなくなりました。使用可能なホストがなく、`metaBaseUrl` も `site.url` もない場合、そのレスポンスの canonical と `hreflang` の URL は相対 URL になります。解析できない `Host` は、素の Nuxt アプリと同様に 500 のままです。
- **`disableMeta` が機能するようになりました。** `$defineI18nRoute` でも `routeDisableMeta` でも、`nuxt.config` で設定した場合も同様です：ページには `hreflang`、canonical、`og:locale` がありません。`lang` と `dir` は残ります。
- `useLocaleHead()` は、`useHead(() => build())` 用のゲッターである `build()` も返します。
- `metaBaseUrl` のない通常のビルドでは、以前と同様に `X-Forwarded-Host` がこれらのタグのホストを選択します。オリジンに直接アクセスできる場合は `metaBaseUrl` を固定してください：[プロキシや CDN の背後](/ja-jp/guide/deployment#behind-a-proxy-or-cdn)を参照してください。

### 翻訳 {#translations}

- **マージはすべての階層でディープマージになります。** ルート、ページ、フォールバックのファイルは 2 階層のマージを使っていたため、ソースモードと開発環境ではフォールバックやルートからの `a.b.c` が失われていました。現在はすべてのモードで同じ辞書が得られます。
- **フォールバックチェーンは、すべてのモードで最後までたどられます**（`fr` → `de` → `en`）。
- **マージはファイルの種類ではなくロケールに基づいて行われます。** アクティブなロケールのルートファイルが、フォールバックロケールのページファイルより優先されるようになりました。[フォールバックロケール](/ja-jp/guide/translations#fallback-locales)を参照してください。
- **同じ `code` に対しては、プロジェクトの `locales` エントリがレイヤーのものより優先されます。** レイヤーは不足分を補うだけです。
- **独自の `pages/<name>/` フォルダーを持たないページは、ルート辞書を読み取ります。** 子ページも同様です。以前は `{}` が得られ、生のキーが表示されていました。出力にはそのようなページごとのファイルと、ロケールごとの `__root/<locale>/data.json` が加わります：`/_locales/<any name>/en/data.json` はルートキーを含む 200 になります（以前は `{}` でした）。これは監視、静的ホストの許可リスト、ツリーを読み取るツールにとって重要です。
- **`disablePageLocales: true` はルートファイルだけを読み取ります。** `pages/index` はマージされなくなりました。
- **離れるページのキーは、その要素がドキュメントから離れると解決されなくなります。** 前のページのファイルにしかないキーをレイアウトが使っていた場合は、それらをルートファイルに移動してください。親のキーは、その子が表示されている間（`index` の子を持つ親も含む）、次のナビゲーションまで残ります。同じ親を持つ 2 つの子の間では、親自身のキーには子の辞書またはルートの辞書が必要です。
- **`$clearCache()` は現在のページの辞書を再読み込みし**、新しい辞書が届くまで古い辞書を画面に保持します。再読み込みに失敗した場合は古い辞書が保持され、クリア前にリクエストされたレスポンスは破棄され、離脱トランジション中のページは翻訳されたままです。
- **`$has(key, route)` はルートを尊重します。**
- **まだ訪問していないページでの `$loadPageTranslations` が、そのファイルの読み込みを妨げることはなくなりました。** ファイルは最初の訪問時に読み込まれ、あなたのキーはその上に保持されます。以前はリロードするまでページに生のキーが表示されていました。
- **翻訳の HMR は、ページをリロードせずにその場で編集を適用します。** 削除されたキーは消え、ルートの編集はすべてのページに反映されます。
- **壊れたロケールファイルは、すべてのモードでそのパスとともに一度だけ警告されます。** 以前は開発環境では例外をスローし、premerged では黙ってスキップしていたため、開発環境での強制的な失敗に頼っていたアプリではそれが見られなくなります。

### 複数形とフォーマット {#plurals-and-formatting}

- 負の数、小数、非常に大きな数を指定した `$tc` は、実際の数を使って最後の形式を選びます。`{ count: null }` は例外をスローしなくなりました。存在しない複数形キーは missing ハンドラーに到達します。
- `$tdr` は実際の未来の日付（`in 3 days`、または `numeric: 'auto'` で `tomorrow`）を返し、無効な入力には `Invalid Date` を返します。過去 1 秒未満は `0 seconds ago` です。
- **`$tn`、`$td`、`$tdr` は、複数形と同様に `iso` に従います：** `{ code: 'en', iso: 'en-GB' }` は日付を `31/10/2026` とフォーマットするようになりました。ロケールコード内の `_` は `-` として読み取られるため、`en_US` は例外をスローしなくなり、`Intl` が知らないコードはマシンのロケールに従うのではなく `en` としてフォーマットされます。名前付きフォーマットは引き続き `code` で検索されます。
- `{param}` プレースホルダーは、渡したパラメーターだけを読み取ります（`{constructor}` は記述どおりのままです）。
- `{placeholder}` の名前には、波括弧とスペース以外の任意の文字を含められます：`{firstName}`、`{first-name}`、`{user.name}` は `params` から読み取られます。そのようなパラメーターがない場合は、以前と同様に記述どおりのままです。
- `defaultValue` は `$t` と `$tc` で補間されます：`$t('missing', { n: 1 }, 'Got {n}')` は `Got 1` を返します（以前は `Got {n}` でした）。文字列でないデフォルト値はそのまま返されます。
- 空の翻訳に対する `$tc` は、`$t` と同様に `''` を返します。以前はデフォルト値またはキーを返していました。
- **複数形テンプレートの意味は、1 つの例外を除いて変わりません。** 表にすべての形式を示します。`Intl.PluralRules` のカテゴリを使うには、新しい [`=0 ` マーカー](/ja-jp/api/methods#$tc)で明示します：`=0 no apples | one apple | {count} apples`。

  | 形式 | 例（`uk` の場合） | 以前 | 現在 |
  | --- | --- | --- | --- |
  | 整数カテゴリが 1 つまたは 2 つのロケール（`en`、`de`、`fr`、`es`、`ja`...）での任意のテンプレート | `none \| one \| {count} many` | インデックスで | **変更なし** |
  | カテゴリごとに 1 つの形式 | `one \| few \| many` | インデックスで：21 → `many` | **変更なし**。21 → `one` にするにはマーカーを追加 |
  | ゼロ形式が先頭、3 つの形式 | `none \| one \| many` | インデックスで | **変更なし** |
  | その他のプレースホルダー | `no items \| {n} item \| {n} items` | インデックスで | **変更なし** |
  | すべての形式に `{count}` | `{count} many \| {count} one \| {count} few` | インデックスで | **変更なし** |
  | 以下より少ない、または多い形式 | `a \| b`, `none \| one \| two \| {count} many` | インデックスで | **変更なし** |
  | `lv`、`prg`、`blo`、`cv`、`ksh`、`lag` の場合 | `none \| one \| {count} many` | インデックスで | **変更なし** |
  | `=0 ` でマーク | `=0 none \| one \| many` | マーカーがテキストとして表示されていた | ゼロ形式、次にカテゴリ |
  | **プレースホルダーのないゼロ形式の後に、カテゴリごとに 1 つの形式が続き、複数の数が共有する各形式に `{count}` がある** | `none \| {count} one \| {count} few \| {count} many` | インデックスで：3 → `3 many`、21 → `21 many` | **カテゴリで**：3 → `3 few`、21 → `21 one`。0、1、2、および `many` にとどまるすべての数は同じ結果になります |

  最後の形式には 3 つ以上のカテゴリが必要です（`ru`、`uk`、`pl`、`cs`、`sk`、`hr`、`sr`、`lt`、`ro`、`sl`、`he`、`ar`、`cy`...）。`ar` では `one` と `two` は単一の数なので、それら 2 つの形式には数値は不要です。
- **`Intl` が知らないロケールコードには、マーカーのカテゴリの有無にかかわらずインデックスのルールが適用されます：** `ua` はマシンのロケールに従わなくなりました。`iso` を設定してください：`{ code: 'ua', iso: 'uk-UA' }` は、モジュールでも `@i18n-micro/vue` でもウクライナ語として複数形を扱います。
- **カスタムの `plural` ルールはシグネチャを維持し**、引き続きロケールコードを受け取ります。生の値を読み取るため、マークされたテンプレートは `=0 ` を含んだまま渡され、数は `Number` として渡されます：以前は `1` だったところが `1.5` になります。`null` を返すと、マーカーを尊重する組み込みルールにフォールバックします。
- **`timeZone` オプション。** これを設定すると（`Europe/Berlin`）、サーバーとすべてのブラウザで同じカレンダー日付をレンダリングします。時計に依存する `relativeDate` には影響しません。

### `<i18n-t>` {#&lt;i18n-t>}

このセクションでは、モジュールの `<i18n-t>` と `@i18n-micro/vue` の `I18nT` を扱います。その他のフレームワークについては[フレームワークパッケージ](#framework-packages)を参照してください。

- **`html` はどの場合でも `params` をエスケープし、すべてのスロットを無視します。** 信頼されるマークアップは翻訳だけです。意図的にマークアップを含めていたパラメーターはテキストとして表示されるようになります：マークアップは翻訳に入れてデータをパラメーターとして渡すか、`html` なしでスロットを使用してください。
- **スロットは `plural`、`number`、`date`、`relativeDate` と併用でき**、それらの場合も `default` スロットは `{ translation }` を受け取ります。最初のものだけでなく、すべての `{name}` が埋められます。
- **スロットは同名のパラメーターより優先されます。** プレースホルダーのように見えるパラメーター値はテキストのままです。`customPluralRule` やカスタムの `plural` の場合、ルールは完成した文字列を返すため、そこで補間されたパラメーターがプレースホルダーと見なされることがあります。
- **`plural`、`number`、`date`、`relativeDate` では、`null` は未設定を意味します。** 以前は `:plural="null"` でレンダリングが失敗し、`:date="null"` は 1970 年をレンダリングしていました。
- `plural` は `$tc` と同様に `Number` で数えます：`1.5` は `1.5` のままで最後の形式を選びます（以前は `1` に切り捨てられていました）。`"2 items"` は `NaN` です（以前は `2` でした）。`""` は `0` です。`customPluralRule` も `1.5` を受け取ります。それ以外の契約は変わりません：同じ引数を受け取り、その戻り値はそのまま使われ、`null` は空でレンダリングされます。
- `hideIfEmpty` は `plural`、`number`、`date`、`relativeDate` に適用されます。非表示の値は空のテキストノードではなくコメントをレンダリングするため、`''` を読んでいたテストは `<!---->` を参照することになります。
- **`html` でキーが存在しない場合はテキストになります。** 信頼されるのは翻訳だけで、キーはリクエストから来る可能性があるため、キーはエスケープされます。`defaultValue` はあなたが指定したものなので、マークアップのままです。
- `plural` では、`$tc` と同様に、見つからない場合は `defaultValue` またはキーがそのまま全体として使われます：`a | b` は分割されなくなりました。
- `defaultValue` は、すべての分岐でキーそのものではなく見つからないキーの代わりになり、`customPluralRule` は見つからない場合にゲッターを通じてそれを受け取ります。以前は `hideIfEmpty` の後でしか機能しませんでした。
- `number`、`date`、`relativeDate` を指定した `<i18n-t>` は `params` を保持し、それらはマージされます。
- `date` と `relativeDate` の出力には `data-allow-mismatch="text"` が付与されます：サーバーとブラウザで時計やタイムゾーンが異なっても、ハイドレーション中に警告が出なくなりました。名前付きスロットの隣では、Vue が要素の単一のテキストに対してのみ属性をチェックするため、スロットの周りのテキストは専用の `<span>` に入ります。
- `.innerHTML` と `textContent` 属性は `innerHTML` とともに削除されます。
- `<i18n-t>` と `<i18n-group>` は、ルートのチャンクではなく、`$t` と同様にアクティブな辞書を読み取ります。破棄されたチャンク（`cacheMaxSize`）で生のキーが表示されることはなくなりました。離脱トランジション中のページは、そこで `$t` が読むものを読むようになりました：新しいページの辞書を読み、見つからない場合は自身の辞書にフォールバックします。そのため、両方のページで定義されたキーは新しいテキストを表示し、ロケール切り替え後は、アンマウントされるまで自身のキーが生のまま表示されます。

### `<i18n-switcher>` と `<i18n-link>` {#&lt;i18n-switcher>-and-&lt;i18n-link>}

- **スイッチャーのリンクのクリックは 1 回のナビゲーションです。** `NuxtLink` とクリックハンドラーの組み合わせではなく、`$switchLocale` を呼び出す素の `<a>` であるため、`router-link-active` クラスはなくなりました。`href` には引き続き `app.baseURL` が含まれ、現在のロケールのリンクには引き続き `aria-current="page"` が付きます。Ctrl/cmd クリックは新しいタブを開き、現在のタブはそのままです。リンクはクエリとハッシュを保持します。
- ボタンは `type="button"` になったため、周囲のフォームを送信しなくなり、`aria-expanded` を持ちます。`aria-haspopup` はモジュール、`@i18n-micro/vue`、`@i18n-micro/astro` から削除されました：メニューを示唆していましたが、一覧はリンクです。Escape キーと外側のクリックでドロップダウンが閉じます。2 つのスイッチャーが同時に開いたままになることはなくなりました。
- ラッパーとドロップダウンには `i18n-switcher-wrapper` と `i18n-switcher-dropdown` クラスが付きます。ボタンには `language-switcher` に加えて `i18n-switcher-button` が付き、ラベルは `<span>` 内に置かれます。デフォルトのスタイルは論理 CSS プロパティ（`inset-inline-start`、`margin-inline-start`）を使用し、キャレットは `▾` です。ドロップダウンは `z-index: 1000`（以前は 10）、`min-width: 150px`、`box-shadow` を持ち、ラッパーは `vertical-align: middle` を持ちます。各リンクは `lang` を持ち、ロケールが設定している場合は `dir` も持ちます。
- `<i18n-link>`：`https://`、`mailto:`、`tel:` は大文字小文字を問わず照合されます（`HTTPS://x.com`、`Mailto:`）。裸の `report.pdf` や `index.html` は `https://report.pdf` ではなくルートとして扱われます。`example.com` と `example.com:8080` は外部リンクのままです。TLD でもあるファイル拡張子（`example.md`、`x.zip`）はファイルとして扱われるため、`https://` を書いてください。`activeStyle` は末尾のスラッシュ、クエリ、ハッシュを無視します。型が `CSSProperties` になったため、一部の型付きの値は変更が必要になる場合があります。

### フック、プラグイン、型 {#hooks-plugins-and-types}

- **`i18n:register` は起動時に `app:created` で実行されます。** プラグインの間ではなく、すべてのプラグインの後です。`order` が 1 より大きいプラグインや `enforce: 'post'` のプラグインも起動時にサブスクライバーが呼ばれるようになりましたが、自身の `setup` 内で登録済みのキーを読み取ることはできなくなりました。ナビゲーションでは、このフックは他のプラグインの `router.beforeEach` ガードより前に実行されるようになりました。
- **`i18n:register` は、それが埋めるページのロケールを受け取ります。** 以前は `hashMode` でロケールを変更するナビゲーションが古いロケールを渡し、キーが誤ったチャンクに入っていました。
- **`i18n:register` はランタイムフックです：** プラグイン内で `@ts-expect-error` なしに `nuxtApp.hook('i18n:register', …)` で登録してください。[フック](/ja-jp/api/events)を参照してください。
- **`hooks: false` と `define: false`** は引き続きそれぞれの機能をオフにします。
- **`plugin: false` の場合でも `$defineI18nRoute` は呼び出し可能なままで**、実行時には何もしません。以前はページがクラッシュしていました。
- `hooks` オプションのドキュメントから `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch` が削除されました。これらは一度も発行されていませんでした。
- ページ内の `const { $defineI18nRoute } = useNuxtApp()` は、変数を使う設定でも動作するようになりました。
- `useI18n()` に `clearCache`、`pluralFunc`、`pluralLocale` のキーが追加されました。`clearCache` は型にも含まれています。
- `$getRouteName(route)` は渡されたルートについて答えます。以前は空文字列を返していました。
- `useI18nLocale()` から `getLocaleWithServerFallback(serverLocale)` が削除されました：`getPreferredLocale() ?? serverLocale ?? null` と書いてください。
- **開発環境のサーバー上では `$getI18nConfig()` は読み取り専用です。** そこでの書き込みは例外をスローします。本番環境ではすべてのリクエストに影響してしまうためです。

### サーバー、ビルド、デプロイ {#server-build-and-deployment}

- **ページのペイロードファイルには、ロケールのルートとの差分だけが含まれます。** クライアントはルートを一度読み込み、各ページをその上にマージするため、ディスクと Edge のバンドルが小さくなり、2 ページ目のコストは 1 ページ目のごく一部になります。`premerged` は `__root/<locale>/data.json` を書き出すようになり、`/_locales/<page>/<locale>/data.json` には差分だけが含まれます：これらのファイルを直接読むものは、2 つをマージする必要があります。完全な辞書も有効なファイルなので、それを提供するホストや `source` モードは引き続き動作します。
- **辞書ファイルはバージョンごとにキャッシュされます。** 現在の `?v=` を持つ URL は Node サーバー上で 1 年間固定され、それ以外の URL は再検証され、ホストの静的コピーは `max-age=60` を返します：[キャッシュヘッダー](/ja-jp/guide/deployment#cache-headers-and-datebuild)を参照してください。`httpCacheControl: false` は `max-age=0` を維持します。再ビルドなしに変更された翻訳は、`v` が変わったときにのみブラウザに届きます：`NUXT_I18N_DATE_BUILD` を設定してください。
- **辞書は `app.cdnURL` に従います。** ブラウザは、以前 `app.baseURL` を使っていたところで、公開ペイロードファイルを `<cdnURL>/_locales/...` から取得します：CDN は `_locales/` を保持し、サイトのオリジンを許可（CORS）する必要があります。[App baseURL とペイロードホスト](/ja-jp/guide/deployment#app-baseurl-and-payload-hosts)を参照してください。
- **SSR は `/_locales` を HTTP 経由でリクエストしなくなりました。** そのため、そのルート上のサーバーミドルウェアやログには、レンダリング時の読み取りが見えなくなります。外部の `apiBaseServerHost` は引き続き HTTP を経由します。
- **失敗した読み取りは保持されなくなり、404 も同様です。** ホストからの 404 はそのファイルがないことを意味します：レンダリングはブラウザと同様にルート辞書を表示し、何も保持されず、ファイルが現れた時点で読み取られます。その他の失敗、JSON オブジェクトでない 200、読み取れないか破損したローカルファイルはキャッシュに入らず、次のリクエストで再度読み取られます：ページのレンダリングは警告をログに出し、生のキーを表示し、`no-store` と `Retry-After` を付けて `503` を返します。そのためルートルールや CDN は何も保持せず、ブラウザはハイドレーション時に辞書を読み取ります。`/_locales/...` は `no-store` を付けて `503` を返し、`useTranslationServerMiddleware` はキーまたはデフォルトを返す `t` を提供します。障害中はすべてのリクエストがホストに到達し、60 秒間レスポンスヘッダーを送らないホストは読み取りに失敗します。大きなファイルの遅いダウンロードには制限がありません。[辞書を読み取れない場合](/ja-jp/guide/deployment#when-a-dictionary-cannot-be-read)を参照してください。`/_locales` もその 404 をそのまま返します（以前は `200 {}` を返していました）。
- **辞書を読み込めないプリレンダリングは失敗します。** ホストにページのファイルもルートファイルもない場合も同様です。そのルートは 500 になり、警告がロケールとページを示し、ファイルは書き出されません。Nuxt のデフォルトの `failOnError` では、ビルドは終了コード 1 で終了します。独自のファイルを持たずルートファイルがあるページは、ルートでプリレンダリングされます。
- **ビルド時に設定したホストが SSR に応答します。** デフォルトの公開コピーの場合や、内部パス上のエラーページでも同様です。以前は公開ファイルが応答していました。実行時の `NUXT_I18N_APP_BASE_SERVER_HOST` は `/_locales` とサーバーローダーに届くようになり、レンダリングはそのローダーを通じてどちらのホストも読み取ります。
- **カスタムの `nitro.output.publicDir`、および `public/` がサーバーの隣にないその他のレイアウトでは、ペイロードが埋め込まれます。**
- **`nuxi build --preset <static preset>` は `nuxi generate` と同様にプリレンダリングします。** そのため、より多くのファイルを書き出す場合があります。`nuxi generate` は、ルートルールで `prerender: false` が設定されていない限り、リンクの有無にかかわらず、すべての静的ページをそれを提供する各ロケールでプリレンダリングします。
- **静的出力で `source` または `publicAssets: false` を使うと警告が出ます。** ブラウザが読み取るものが何もないためです。
- **埋め込みの警告はサイズチェックになりました。** ビルドはプラットフォームの制限を超えた場合にのみ警告します：[バンドルの制限](/ja-jp/guide/deployment#bundle-limits-on-edge)を参照してください。
- **訪問者が決定するすべての場所で `Vary` が設定されます：** `no_prefix` ではすべてのページで、また `/` や設定に基づいてリダイレクトしうるその他の URL で設定されます。Cookie が使われている場合は `Cookie` を含み、`autoDetectLanguage` の場合は `Accept-Language` を含みます。CDN のキャッシュキーを確認してください：[HTML のキャッシュ](/ja-jp/guide/deployment#caching-html)を参照してください。
- **`/_locales` のキャッシュが変わりました。** `/{apiBaseUrl}/**` には Nitro のルートキャッシュがなくなり、`s-maxage=60, stale-while-revalidate` ヘッダーもなくなりました。そのキャッシュに頼っていた場合は、ペイロードルートの前段に CDN を置いてください。空の辞書が `immutable` になることはありません。
- **サーバーキャッシュはデフォルトで上限があります：** `cacheMaxSize` が未設定の場合、最大 1000 エントリです。`cacheTtl` はエントリが保存された時点から数えられ、読み取りによって延長されなくなりました。
- **新しいオプションの [`cacheStorage`](/ja-jp/guide/performance#shared-cache-for-several-instances)：** 複数のインスタンスで共有する辞書キャッシュです。未設定の場合は何も変わりません。

## v2 から v3 へ {#from-v2-to-v3}

### 削除されたオプション {#removed-options}

```diff
 i18n: {
-  includeDefaultLocaleRoute: true,
+  strategy: 'prefix',
-  fallbackRedirectComponentPath: '~/components/MyRedirect.vue',
-  experimental: { hmr: true, previousPageFallback: true },
+  hmr: true,
 }
```

- `includeDefaultLocaleRoute: true` は `strategy: 'prefix'` に相当し、`false` はデフォルトの `prefix_except_default` に相当します。
- `fallbackRedirectComponentPath` は削除されました：リダイレクトはレンダリング前にサーバーで、またクライアントのルートミドルウェアで行われます。カスタムのリダイレクトロジックはロケールを設定するプラグインに記述します。[カスタムロケール検出](/ja-jp/guide/custom-auto-detect)を参照してください。
- `experimental.hmr` はルートレベルの `hmr` オプションになりました（デフォルトでオン）。
- `previousPageFallback` は削除されました：離れるページのキーは、オプションなしでそのトランジションが終わるまで解決されます。

### ロケールの状態 {#locale-state}

`useState('i18n-locale')` と `useCookie('user-locale')` の代わりに `useI18nLocale()` を使用します。

```diff
- useState('i18n-locale').value = 'fr'
- useCookie('user-locale').value = 'fr'
+ useI18nLocale().setLocale('fr') // state and cookie together
```

### 実行時の設定 {#config-at-runtime}

ランタイムオーバーライドを含む設定は `$getI18nConfig()` で読み取ります。

```diff
- const cookieName = useRuntimeConfig().public.i18nConfig?.localeCookie
+ const { $getI18nConfig } = useNuxtApp()
+ const cookieName = $getI18nConfig().localeCookie
```

### 内部の型エイリアス {#internal-type-aliases}

IDE や `vue-tsc` が `#i18n-internal/*` のインポートを解決できない場合は、`package.json` でそれらをマッピングします。Nuxt はビルド時にそれらを解決するため、これが必要になることはまれです。

```json
{
  "imports": {
    "#i18n-internal/plural": "nuxt-i18n-micro/internals",
    "#i18n-internal/strategy": "nuxt-i18n-micro/internals",
    "#i18n-internal/config": "nuxt-i18n-micro/internals"
  }
}
```
