# Référence des options du module

Toutes les options acceptées par `nuxt-i18n-micro`, lues au moment de la compilation depuis l'interface `ModuleOptions` dans
[`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).
Rien ici n'est écrit à la main; le contenu ne peut donc pas prendre du retard sur le code. Les types, valeurs par défaut et descriptions proviennent de la déclaration elle-même.

Pour comprendre ce que ces options *signifient* ensemble (quelles combinaisons ont du sens, ce qui change quand vous changez de stratégie, des exemples concrets), consultez [Configuration](/guides/configuration). Cette page est la liste exhaustive; l'autre est l'explication.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Les options imbriquées apparaissent sous leur chemin en pointillés. Ainsi, `translationPayloads.mode` est la clé `mode` à l'intérieur de l'objet `translationPayloads`.

## Langues et routage

Quelles langues existent et comment elles apparaissent dans l'URL.

| Option | Type | Valeur par défaut | Description |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Liste des langues prises en charge. Chaque entrée définit un code de langue et des métadonnées facultatives (ISO, direction, nom d'affichage, etc.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Stratégie de routage d'URL pour les préfixes de langue. - `'no_prefix'` : pas de langue dans l'URL; la langue est stockée dans un témoin. - `'prefix_except_default'` : préfixe toutes les langues sauf la langue par défaut. - `'prefix'` : toujours préfixer, y compris la langue par défaut. - `'prefix_and_default'` : comme `prefix`, mais la langue par défaut est aussi accessible sans préfixe. |
| `defaultLocale` | `string` | `'en'` | Langue à utiliser quand aucune langue ne peut être déterminée depuis l'URL ou les préférences de l'utilisateur. Sert aussi de langue de repli pour les traductions manquantes lorsque `fallbackLocale` n'est pas défini. |
| `localeCookie` | `string \| null` | `null` | Nom du témoin pour conserver la préférence linguistique de l'utilisateur entre les sessions. Définissez à `null` pour désactiver la persistance par témoin. Automatiquement défini à `'user-locale'` pour la stratégie `no_prefix` si non fourni. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Configuration globale des langues au niveau des routes. Permet de restreindre ou de personnaliser les routes de langue pour certaines pages sans modifier leurs composants. - `false` : exclure la route de la localisation. - `Record<LocaleCode, string>` : chemins personnalisés par langue. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (utilise un motif intégré basé sur les codes de langue)` | Expression régulière personnalisée (ou sa source sous forme de chaîne) pour identifier les codes de langue dans les segments d'URL. Tous les codes de langue définis dans `locales` doivent correspondre à ce motif, sinon un avertissement est émis. |
| `noPrefixRedirect` | `boolean` | `false` | Pour la stratégie `no_prefix` : active la redirection d'une URL avec préfixe de langue (par exemple `/en/about`) vers la version sans préfixe (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Motifs d'URL (chaînes ou RegExp) à exclure complètement du traitement i18n. Les routes correspondantes ne reçoivent pas de préfixe de langue, de redirection ni de chargement de traduction. Les chemins internes Nuxt (`/__nuxt_error`, etc.) sont toujours exclus automatiquement. |
| `routeLocales` | `Record<string, string[]>` | — | Restrictions de langue par route, extraites des appels à `defineI18nRoute()`. Associe un chemin de route (par exemple `'/about'`) à un tableau de codes de langue autorisés. Les routes non listées n'ont aucune restriction (toutes les langues sont permises). |

## Traductions

Où résident les fichiers de traduction et comment les clés sont résolues.

| Option | Type | Valeur par défaut | Description |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Chemin du répertoire contenant les fichiers JSON de traduction, relatif à la racine du projet. |
| `disableWatcher` | `boolean` | `false` | Désactive l'observateur de fichiers qui crée automatiquement les fichiers de traduction manquants en mode développement. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Associe des noms de routes à d'autres noms de routes afin de partager les mêmes fichiers de traduction. Par exemple, `\{ 'about-us': 'about' \}` signifie que la page `about-us` utilisera les traductions de la page `about` plutôt que les siennes. |
| `plural` | `PluralFunc` | `pluralisation intégrée (index de forme selon le compte)` | Fonction de pluralisation personnalisée. Elle reçoit `(key, count, params, locale, getter)` et doit retourner la forme plurielle choisie sous forme de chaîne, ou `null`/`undefined` pour retomber sur la logique intégrée `defaultPlural` (vous pouvez ainsi ne surcharger que certaines langues). Pour le module Nuxt, la fonction est sérialisée via `.toString()` dans `.nuxt/i18n.plural.mjs`; elle doit donc être autonome (pas d'imports ni de portée extérieure). Une chaîne de chemin de fichier n'est **pas** prise en charge. |
| `disablePageLocales` | `boolean` | `false` | Désactive les fichiers de traduction par page. Lorsque `true`, seules les traductions globales (`\{locale\}.json`) sont chargées; les fichiers propres aux pages (`pages/\{page\}/\{locale\}.json`) ne sont ni générés ni chargés. |
| `fallbackLocale` | `string` | `undefined (aucun repli; retourne la clé brute)` | Code de langue de repli global. Lorsqu'une clé de traduction est absente dans la langue active, le module la cherche dans cette langue avant de retourner la clé elle-même. |

## Charges utiles et mise en cache

Comment les traductions atteignent le navigateur. La page [Performance](/guides/performance) explique ce que ces options changent à l'exécution.

| Option | Type | Valeur par défaut | Description |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Précharger les traductions de la page d'index dans le middleware global Nitro (côté serveur uniquement, configuration privée). |
| `apiBaseUrl` | `string` | `'_locales'` | Segment de base d'URL pour la route API des traductions (utilisé lors de la récupération de données en SSR/SSG). Peut aussi être défini via la variable d'environnement `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Remplace l'hôte utilisé pour les requêtes de récupération de traductions côté client. Utile lorsque le client atteint le serveur via un nom d'hôte différent de celui vu par Nuxt. Peut aussi être défini via la variable d'environnement `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Remplace l'hôte utilisé pour les requêtes de récupération de traductions côté serveur. Utile dans les configurations de conteneurs ou de microservices où le serveur s'atteint lui-même via un nom d'hôte interne. Peut aussi être défini via la variable d'environnement `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Contrôle la manière dont les charges utiles de traduction sont émises (Node : `public/<apiBaseUrl>`; Edge : `serverAssets` Nitro). - **Node** : `serverAssets` signifie SSR local via `readFile` sous `public/` (pas de `raw:` Rollup). - **Edge** : `serverAssets` enregistre des `serverAssets` Nitro (`assets:i18n`); cela ne force pas une copie publique. Conservez les valeurs par défaut pour la configuration tout-en-un habituelle. Pour les gros catalogues Edge, préférez `mode: 'source'`. Pour les déploiements adossés à un CDN, désactivez les sorties locales et définissez `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Stratégie de charge utile de traduction. - `premerged` : matrice `\{page\}/\{locale\}/data.json` au moment de la compilation (par défaut) - `source` : fichiers sources compacts fusionnés à l'exécution (à privilégier en Edge / grands catalogues) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Charges utiles SSR locales : Node lit `public/<apiBaseUrl>` (force une copie publique); Edge intègre via `serverAssets` Nitro. - **Node** : pas de `serverAssets` Nitro (évite le `raw:` Rollup). Le SSR lit `public/<apiBaseUrl\|publicDir>` comme `\{page\}/\{locale\}/data.json`; lorsque cette option vaut `true`, une copie publique est forcée même si `publicAssets` est faux. - **Edge** (`nitro.node === false`) : `serverAssets` Nitro (`assets:i18n`) avec la même disposition que `mode`. Ne force **pas** une copie publique. Définissez `publicAssets: true` pour un CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Enregistre la route serveur intégrée à `/\{apiBaseUrl\}/:page/:locale/data.json`. Désactivez-la lorsque les charges utiles de traduction sont servies depuis un hôte ou un CDN externe. |
| `translationPayloads.publicAssets` | `boolean` | `true en mode premerged, false en mode source` | Copie les charges utiles dans la sortie publique Nitro. Premerged → `\{page\}/\{locale\}/data.json` sous `apiBaseUrl`; source → arborescence compacte. Sur Node, cette arborescence sert aussi de source SSR lorsque `serverAssets` force une copie publique. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Adhérer au pré-rendu Nitro `/\{apiBaseUrl\}/.../data.json`. Généralement redondant lorsque `publicAssets` en mode premerged a déjà écrit ces fichiers. |
| `translationPayloads.publicDir` | `string` | — | Dossier de sortie publique relatif à la racine publique Nitro. Défaut : `apiBaseUrl` (`_locales`). Ainsi, les fichiers statiques correspondent aux URL récupérées côté client (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Avertit à la compilation lorsque le nombre de fichiers de charge utile générés dépasse ce seuil. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 Mo)` | Avertit à la compilation lorsque la taille totale des charges utiles générées dépasse ce seuil en octets. |

## SEO

Balises meta générées pour chaque page localisée.

| Option | Type | Valeur par défaut | Description |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Génère automatiquement les balises meta SEO (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | URL de base pour les balises meta SEO (canonical, og:url, hreflang). - Une chaîne d'URL concrète (par exemple `'https://example.com'`) : utilisée telle quelle (priorité la plus haute). - `undefined` : retombe sur `site.url` de `nuxt-site-config` lorsque ce module est présent, sinon l'origine de la requête courante (`useRequestURL().origin` côté serveur, `window.location.origin` côté client). |
| `metaTrustForwardedHost` | `boolean` | `true` | Faire confiance à l'en-tête `X-Forwarded-Host` pour résoudre l'URL de base des balises meta. Activez-la lorsque l'application s'exécute derrière un proxy inverse (nginx, Cloudflare, AWS ALB, etc.) qui définit cet en-tête vers le nom d'hôte réel côté client. |
| `metaTrustForwardedProto` | `boolean` | `true` | Faire confiance à l'en-tête `X-Forwarded-Proto` pour résoudre le protocole des balises meta. Activez-la lorsque l'application s'exécute derrière un proxy terminant TLS afin que les URL canoniques utilisent `https://` même si l'application elle-même écoute en HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Liste des noms de paramètres de requête préservés dans les balises meta canonical et `og:url`. Les paramètres absents de cette liste sont retirés de l'URL canonique. |

## Détection et redirections

Choisir une langue pour un visiteur qui n'en a pas choisi.

| Option | Type | Valeur par défaut | Description |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Active les redirections automatiques basées sur la langue. Lorsque `true`, les visiteurs sont redirigés vers leur langue préférée (détectée depuis le témoin, l'en-tête `Accept-Language` ou la valeur par défaut) à la première visite. |
| `autoDetectLanguage` | `boolean` | `true` | Détecte automatiquement la langue préférée de l'utilisateur depuis l'en-tête HTTP `Accept-Language`. Utilisée en combinaison avec `autoDetectPath` pour décider quand la détection se produit. |
| `autoDetectPath` | `string` | `'/'` | Endroits où les redirections de préférence par témoin ou Accept-Language peuvent s'exécuter (lorsque `redirects` est activé). - `'/'` : uniquement `/` (les liens profonds dans la langue par défaut restent accessibles; défaut) - `'no_prefix'` : uniquement les chemins sans préfixe de langue - `'*'` : tous les chemins, y compris la réécriture d'un préfixe de langue explicite (par exemple `/fr/about` → `/de/about` lorsque le témoin préfère `de`) - toute autre chaîne : correspondance exacte du chemin (par exemple `'/welcome'`) Le nettoyage de la stratégie préfixée (par exemple `/en` → `/` sous `prefix_except_default`) n'est pas conditionné. |

## Enregistrement

Parties du module que vous pouvez désactiver.

| Option | Type | Valeur par défaut | Description |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Enregistre le plugin de macro `defineI18nRoute()`, activant les appels `defineI18nRoute()` par page. |
| `plugin` | `boolean` | `true` | Enregistre le plugin i18n principal qui fournit `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` et d'autres assistants d'exécution. |
| `hooks` | `boolean` | `true` | Enregistre le plugin i18n de hooks qui fournit les hooks `i18n:register`, `i18n:beforeLocaleSwitch` et `i18n:afterLocaleSwitch` au niveau de l'application. |
| `components` | `boolean` | `true` | Enregistre les composants i18n intégrés (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Définissez à `false` pour désactiver l'enregistrement automatique des composants (par exemple si vous ne les utilisez pas et souhaitez réduire l'empreinte du module). |
| `types` | `boolean` | `true` | Génère les déclarations de types TypeScript pour `useI18n`, `$t` et les assistants associés à partir des clés de traduction de vos fichiers de langue par défaut. |
| `debug` | `boolean` | `false` | Active la journalisation de débogage détaillée pour la détection de langue, la génération de routes et le chargement des traductions. |

## Autres

| Option | Type | Valeur par défaut | Description |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | Émet aussi un `hreflang` de langue nue dérivé du `iso` de chaque langue (par exemple `es-ES` → aussi `es`). La première langue régionale dans `locales` revendique la balise nue pour cette langue. Le `code` de routage n'est jamais utilisé; seulement `iso \|\| code`. |
| `vueDevtools` | `boolean` | `true` | Enregistre l'inspecteur Vue DevTools et la chronologie en dev (extension de navigateur). Séparé de l'onglet personnalisé Nuxt DevTools. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Préfixe ajouté aux noms des routes localisées (par exemple `'localized-index'`). Utilisé en interne pour distinguer les routes d'origine des variantes de langue générées. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Désactivation des balises meta par route, extraite des appels à `defineI18nRoute()`. Associe un chemin de route à `true` (désactiver toutes les meta) ou à un tableau de codes de langue pour lesquels les meta doivent être désactivées. |
| `missingWarn` | `boolean` | `true` | Affiche des avertissements dans la console lorsqu'une clé de traduction est manquante. |
| `hmr` | `boolean` | `true` | Active le remplacement de module à chaud pour les fichiers de traduction en développement. Lorsque `true`, les changements aux fichiers JSON de traduction déclenchent un rechargement automatique sans rafraîchissement complet de la page. |
| `cacheMaxSize` | `number` | `0` | Nombre maximal d'entrées dans le cache de traduction en mémoire. `0` signifie aucune limite. |
| `cacheTtl` | `number` | `0` | Durée de vie (en secondes) des entrées de cache de traduction. `0` signifie que les entrées n'expirent jamais. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Formats de nombres nommés par langue (compatibles Vue I18n). Active les appels de style `$tn(1000, 'currency')`. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Formats de date/heure nommés par langue (`datetimeFormats` compatibles Vue I18n). Active les appels de style `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | `max-age` HTTP `Cache-Control` (en secondes) pour `/\{apiBaseUrl\}/:page/:locale/data.json`. S'applique intégralement tant que `dateBuild` invalide l'URL (`?v=...`), ce qui est la valeur par défaut : la réponse est alors `public, max-age=…, immutable` et sûre pour les navigateurs et les CDN. - `dateBuild: 0`/`''` : l'URL est stable, donc cette durée n'est *pas* honorée; la réponse devient `public, max-age=0, must-revalidate` à la place. Un long `max-age` sur une URL invariable épingle la première charge utile qu'un navigateur a vue. - `0` : ne définit pas du tout `Cache-Control` (utile en débogage local) - Non appliqué en développement (`import.meta.dev`) afin que le HMR ne soit pas contrarié par le cache du navigateur - Ne concerne que les réponses servies via Nitro. Les charges utiles copiées dans `public/` et servies par la plateforme d'hébergement prennent les en-têtes de cette plateforme. Consultez le guide de performance. Analogue à `httpCacheDuration` expérimental de `@nuxtjs/i18n` (v10.2.0), mais en tant qu'en-tête de réponse explicite plutôt qu'en `maxAge` de `defineCachedEventHandler` Nitro. |
| `dateBuild` | `string \| number` | — | Valeur utilisée pour invalider le cache des requêtes de traduction (`?v=...`). En absence de valeur, le module retombe sur `Date.now()` (non déterministe). Pour des déploiements reproductibles ou progressifs, définissez une valeur stable (par exemple un SHA git ou un numéro de build). |
| `experimental` | `Record<string, unknown>` | — | Panier d'options expérimentales ou instables. Le contenu peut changer ou être retiré sans préavis entre les versions mineures. |
