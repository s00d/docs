# 🛠️ Méthodes

Cette page documente toutes les méthodes disponibles fournies par nuxt-i18n-micro. Les méthodes sont organisées par fonctionnalité pour faciliter la navigation.

Chaque assistant injecté par le plugin, lu depuis l'interface `PluginsInjections`, ce qui garantit que cette liste ne peut pas s'écarter de ce qui est réellement disponible.

### `$getI18nConfig`

{/* generated:method:$getI18nConfig — do not edit; run `pnpm run docs:generate` */}

```ts
() => ModuleOptionsExtend
```

Configuration du module résolue, telle que l'exécution la voit.

{/* /generated:method:$getI18nConfig */}

```typescript
const nuxtApp = useNuxtApp()
const { localeCookie, strategy, hooks } = nuxtApp.$getI18nConfig()
```

Pour la compilation ou les contextes non-Nuxt, utilisez plutôt `getI18nConfig()` depuis `#build/i18n.strategy.mjs`.

<Info>
`serverTranslationPreload` est une option de module privée exposée uniquement dans la configuration privée serveur (`#i18n-internal/config`). Elle ne fait pas partie de l'API d'exécution publique et peut changer sans préavis.
</Info>

## 🔍 Méthodes de traduction

Méthodes principales pour récupérer et gérer les traductions.

### `$t`

{/* generated:method:$t — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params?: Params, defaultValue?: string | null) => CleanTranslation
```

Traduit une clé, en y interpolant `params`. Retourne `defaultValue` lorsque la clé est absente, ou la clé elle-même si aucune valeur par défaut n'est fournie.

{/* /generated:method:$t */}

```typescript
const welcomeMessage = $t('welcome', { username: 'Alice', unreadCount: 5 })
// Output: "Welcome, Alice! You have 5 unread messages."
```

<Warning>
`$t` retourne `CleanTranslation`, soit `string | number | boolean | Translations | PluralTranslations | null`. Si la clé pointe vers un **objet imbriqué** dans votre JSON (par exemple `$t('header')` alors que le JSON contient `\{ "header": \{ "title": "Hi" \} \}`), la valeur de retour sera cet **objet**, pas une chaîne. L'utiliser directement dans un modèle Vue (<code v-pre>\{\{ $t('header') \}\}</code>) affichera `[object Object]`.

**Comment éviter cela :**

- Utilisez une clé plus spécifique : `$t('header.title')` → `"Hi"`
- Utilisez `$ts()` qui retourne toujours une chaîne (appelle `.toString()` sur les non-chaînes)
- Utilisez `$t` avec une clé imbriquée pour accéder intentionnellement aux sous-objets à des fins programmatiques
</Warning>

### `$ts`

{/* generated:method:$ts — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params?: Params, defaultValue?: string) => string
```

Comme `$t`, mais retourne toujours une chaîne : une valeur objet ou tableau est convertie en chaîne plutôt que retournée telle quelle.

{/* /generated:method:$ts */}

```typescript
const welcomeMessage = $ts('welcome', { username: 'Alice', unreadCount: 5 })
// Output: "Welcome, Alice! You have 5 unread messages."
```

### `$_t` et `$_ts`

{/* generated:method:$_t — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNormalizedLoaded) => (key: string, params?: Params, defaultValue?: string | null) => CleanTranslation
```

Lie `$t` à une route précise, pour traduire hors de la page courante. Par exemple, une mise en page affichant un lien vers une autre route.

{/* /generated:method:$_t */}

{/* generated:method:$_ts — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNormalizedLoaded) => (key: string, params?: Params, defaultValue?: string | null) => string
```

Lie `$ts` à une route précise. Voir `$_t`.

{/* /generated:method:$_ts */}

Variantes de `$t` et `$ts` liées à une route. Elles prennent d'abord une **route** et retournent une fonction de traduction verrouillée sur la langue et le contexte de page de cette route.

- **Accès** : `useNuxtApp()` (également réexporté par `useI18n()` sous `$_t` / `$_ts`)

Utilisez-les lorsque la route active pendant le SSR ou les transitions diffère de `router.currentRoute`. Par exemple, à l'intérieur de `<i18n-t>`, `<i18n-group>`, ou lors du rendu de contenu pour un objet `route` précis.

```typescript
import { useRoute, useNuxtApp } from '#imports'

const route = useRoute()
const { $_t, $_ts } = useNuxtApp()

const $t = $_t(route)
const title = $t('page.title')

// String-safe variant
const label = $_ts(route)('page.label')
```


### `$tc`

{/* generated:method:$tc — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params: number | Params, defaultValue?: string) => string
```

Traduit avec pluralisation. `params` peut être le compte lui-même ou un objet contenant `count`.

{/* /generated:method:$tc */}

**Format de traduction** : formes séparées par `|`. Placez les substituants dans **chaque** forme :

```json
{
  "apples": "no apples | one apple | {count} apples",
  "cart": "no items for {name} | one item for {name} | {count} items for {name}"
}
```

```typescript
$tc('apples', 0) // "no apples"
$tc('apples', 1) // "one apple"
$tc('apples', 10) // "10 apples"

// count + other params (second argument must be an object)
$tc('cart', { count: 10, name: 'Alice' }) // "10 items for Alice"
```


**Alternative par composant** : `<i18n-t keypath="cart" :plural="count" :params="\{ name \}" />` (fusionne `count` avec `params` en interne).


### `$mergeTranslations`

{/* generated:method:$mergeTranslations — do not edit; run `pnpm run docs:generate` */}

```ts
(newTranslations: Translations) => void
```

Fusionne des traductions dans la langue active à l'exécution, en écrasant ce qui est chargé.

{/* /generated:method:$mergeTranslations */}

```typescript
$mergeTranslations({
  welcome: 'Bienvenue, {username}!',
})
// Output: Updates the translation cache with the new French translation
```

### `$resolveTranslations`

{/* generated:method:$resolveTranslations — do not edit; run `pnpm run docs:generate` */}

```ts
() => Translations
```

Toutes les traductions actuellement en mémoire pour la langue et la route actives, sous forme d'arbre. Vue en lecture seule de ce que `$t()` peut résoudre en ce moment.

{/* /generated:method:$resolveTranslations */}

```typescript
const tree = $resolveTranslations()
// { aaa: { bbb: 'ccc' }, ddd: 1111 } — the same dictionary $t() reads from
```

Utilisez-le lorsque vous avez besoin du dictionnaire complet en mémoire (DevTools, tests, éditeurs à l'exécution). Traitez la valeur de retour comme étant en lecture seule; modifiez les valeurs via `$setTranslation` ou fusionnez des correctifs avec `$mergeTranslations`.

### `$setTranslation`

{/* generated:method:$setTranslation — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, value: unknown) => void
```

Remplace la valeur à `key` dans le dictionnaire actif. Il s'agit d'un remplacement, pas d'une fusion. Utilisez `$mergeTranslations` lorsque les frères existants doivent survivre.

{/* /generated:method:$setTranslation */}

```typescript
$setTranslation('aaa', { fff: 'ggg' }) // replaces the whole `aaa` subtree
$setTranslation('aaa', 'text')          // replaces `aaa` with a string
$setTranslation('ddd', 1111)            // scalar at the top level
$setTranslation('aaa.bbb', 'nested')    // dotted path
```

Il s'agit d'un **remplacement**, pas d'une fusion. Les frères existants sous la même clé sont retirés. Pour appliquer un correctif sans perdre les frères, utilisez `$mergeTranslations`.

### `$setMissingHandler`

{/* generated:method:$setMissingHandler — do not edit; run `pnpm run docs:generate` */}

```ts
(handler: MissingHandler | null) => void
```

Installe un rappel invoqué pour chaque clé non résolue. Passez `null` pour le retirer.

{/* /generated:method:$setMissingHandler */}

**Définition du type** :

```typescript
type MissingHandler = (locale: string, key: string, routeName: string, instance?: unknown, type?: string) => void
```

```typescript
// Set a custom handler
$setMissingHandler((locale, key, routeName) => {
  console.error(`Missing translation: ${key} in ${locale} for route ${routeName}`)
  // Send to Sentry or other error tracking service
  // Sentry.captureMessage(`Missing translation: ${key}`)
})

// Remove the handler
$setMissingHandler(null)
```

**Cas d'usage** :

- Journalisation des traductions manquantes vers des services de suivi d'erreurs (Sentry, LogRocket, etc.)
- Collecte de données analytiques sur les traductions manquantes
- Gestion d'erreurs personnalisée pour les clés de traduction manquantes

## 🔢 Formatage des nombres et des dates

Méthodes pour formater les nombres et les dates selon les conventions de la langue.

### `$tn`

{/* generated:method:$tn — do not edit; run `pnpm run docs:generate` */}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

Formate un nombre avec `Intl.NumberFormat` dans la langue active. Une clé sélectionne un format nommé de la configuration.

{/* /generated:method:$tn */}

```typescript
// Inline options
const formattedNumber = $tn(1234567.89, { style: 'currency', currency: 'USD' })
// "$1,234,567.89"

// Named format (from nuxt.config i18n.numberFormats)
const price = $tn(1000, 'currency')
const priceDe = $tn(1000, 'currency', 'de')
const compact = $tn(1000, 'currency', { notation: 'compact' })
```

Les clés de format nommé inconnues retombent sur les options par défaut de `Intl.NumberFormat`. En développement (client), un `console.warn` est émis lorsque `missingWarn` est activé (par défaut).

**Exemple de configuration** :

```ts
export default defineNuxtConfig({
  i18n: {
    numberFormats: {
      en: {
        currency: { style: 'currency', currency: 'USD' },
        decimal: { style: 'decimal', minimumFractionDigits: 2, maximumFractionDigits: 2 },
      },
      de: {
        currency: { style: 'currency', currency: 'EUR' },
      },
    },
  },
})
```

**Cas d'usage** :

- Formatage des nombres en devise, en pourcentage ou en décimal dans le format de la langue appropriée
- Réutilisation de formats nommés dans toute l'application (parité de migration Vue I18n)

### `$td`

{/* generated:method:$td — do not edit; run `pnpm run docs:generate` */}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

Formate une date avec `Intl.DateTimeFormat` dans la langue active. Une clé sélectionne un format nommé de la configuration.

{/* /generated:method:$td */}

```typescript
const formattedDate = $td(new Date(), { weekday: 'long', year: 'numeric', month: 'long', day: 'numeric' })
// "Friday, September 1, 2023"

const short = $td(new Date(), 'short')
const longDe = $td(new Date(), 'long', 'de')
```

Les clés de format nommé inconnues retombent sur les options par défaut de `Intl.DateTimeFormat`. En développement (client), un `console.warn` est émis lorsque `missingWarn` est activé (par défaut).

**Exemple de configuration** :

```ts
export default defineNuxtConfig({
  i18n: {
    datetimeFormats: {
      en: {
        short: { year: 'numeric', month: 'short', day: 'numeric' },
        long: { year: 'numeric', month: 'long', day: 'numeric', weekday: 'long' },
      },
    },
  },
})
```

**Cas d'usage** :

- Affichage des dates dans un format aligné avec la langue de l'utilisateur
- Partage de préréglages court/long/date-heure dans toute l'application

### `$tdr`

{/* generated:method:$tdr — do not edit; run `pnpm run docs:generate` */}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

Formate une date en durée relative (« il y a 3 jours ») avec `Intl.RelativeTimeFormat`.

{/* /generated:method:$tdr */}

```typescript
const relativeDate = $tdr(new Date(Date.now() - 1000 * 60 * 5))
// Output: "5 minutes ago" in the 'en-US' locale
```

## 🔄 Changement de route et de langue

Méthodes pour basculer entre les langues et les routes.

### `$switchLocale`

{/* generated:method:$switchLocale — do not edit; run `pnpm run docs:generate` */}

```ts
(locale: string) => void
```

Navigue vers la page courante dans une autre langue.

{/* /generated:method:$switchLocale */}

```typescript
$switchLocale('fr')
// Prefix strategies: navigates to the French version of the route
// no_prefix: updates locale and translations without changing the URL path
```

<Tip>
Consultez la [FAQ — changer de langue sans changer l'URL](/guides/faq#-switch-locale-without-changing-the-url). Pour les stratégies préfixées, utilisez `$switchLocalePath()` lorsque vous n'avez besoin que d'une cible de lien.
</Tip>

### `$switchLocaleRoute`

{/* generated:method:$switchLocaleRoute — do not edit; run `pnpm run docs:generate` */}

```ts
(locale: string) => RouteLocationRaw
```

Objet route de la page courante dans une autre langue, sans navigation.

{/* /generated:method:$switchLocaleRoute */}

```typescript
// on /en/news
const routeFr = $switchLocaleRoute('fr')
// Output: A route object with the new locale applied, e.g., { name: 'localized-news', params: { locale: 'fr' } }
```

### `$switchLocalePath`

{/* generated:method:$switchLocalePath — do not edit; run `pnpm run docs:generate` */}

```ts
(locale: string) => string
```

Chemin de la page courante dans une autre langue, sans navigation.

{/* /generated:method:$switchLocalePath */}

```typescript
// on /en/news
const routeFr = $switchLocalePath('fr')
window.location.href = routeFr
// Output: url with new locale applied, e.g., '/fr/nouvelles'
```

### `$switchRoute`

{/* generated:method:$switchRoute — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => void
```

Navigue vers une autre route, en conservant la langue active ou en basculant vers `toLocale`.

{/* /generated:method:$switchRoute */}

**Exemples** :

<CodeGroup>
```typescript String Path
// Switches to the given path with the current locale
$switchRoute('/about')
```

```typescript String Path with Locale
// Switches to the given path with French locale
$switchRoute('/about', 'fr')
```

```typescript Named Route
// Switches to a named route with the current locale
$switchRoute({ name: 'page' })
```

```typescript Named Route with Locale
// Switches to a named route and changes the locale to Spanish
$switchRoute({ name: 'page' }, 'es')
```
</CodeGroup>

## 🚦 Configuration des routes

Méthodes pour configurer le comportement des routes et le contrôle d'accès.

### `$defineI18nRoute`

{/* generated:method:$defineI18nRoute — do not edit; run `pnpm run docs:generate` */}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

Enregistre la configuration linguistique et les traductions par page depuis un composant. Fusionne dans la langue active et se réapplique quand la langue change.

{/* /generated:method:$defineI18nRoute */}

> [!IMPORTANT]
> `$defineI18nRoute` est fourni par le **plugin define** et est disponible sur `useNuxtApp()` uniquement. Il ne fait **pas** partie de l'objet retourné par `useI18n()`.
> Destructurez-le toujours depuis `useNuxtApp()` dans `script setup`. Appeler `$defineI18nRoute(...)` comme une variable globale nue lève `"$defineI18nRoute is not defined"` pendant le SSR ou le pré-rendu.

**Paramètres** :

- **locales** : `string[] | Record<string, Record<string, string>>` — Langues disponibles pour la route
- **localeRoutes** : `Record<string, string>` — Facultatif. Routes personnalisées pour des langues spécifiques
- **disableMeta** : `boolean | string[]` — Facultatif. Désactive les balises meta i18n pour toutes les langues ou pour des langues spécifiques

**Exemple de base** :

```typescript
import { useNuxtApp } from '#imports'

const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'fr', 'de'],
  localeRoutes: {
    en: '/welcome',
    fr: '/bienvenue',
    de: '/willkommen',
  },
  disableMeta: false,
})
```

> 📖 **Pour des exemples d'utilisation détaillés, des formats de configuration et des bonnes pratiques, consultez le [Guide des traductions par composant](/guides/per-component-translations).**

### `$setI18nRouteParams`

{/* generated:method:$setI18nRouteParams — do not edit; run `pnpm run docs:generate` */}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

Définit des params par langue pour la route courante, afin qu'un segment dynamique puisse différer selon la langue. Appelez-le pendant le SSR, avant que l'en-tête soit rendu.

{/* /generated:method:$setI18nRouteParams */}

```typescript
// in pages/news/[id].vue
// for en/news/1-first-article
const { $switchLocaleRoute, $setI18nRouteParams, $defineI18nRoute } = useNuxtApp()
$defineI18nRoute({
  localeRoutes: {
    en: '/news/:id()',
    fr: '/nouvelles/:id()',
    de: '/Nachricht/:id()',
  },
})
const { data: news } = await useAsyncData(`news-${params.id}`, async () => {
  let response = await $fetch("/api/getNews", {
    query: {
      id: params.id,
    },
  });
  if (response?.localeSlugs) {
    response.localeSlugs = {
      en: {
        id: '1-first-article'
      }
      fr: {
        id: '1-premier-article'
      }
      de: {
        id: '1-erster-Artikel'
      }
    }
    $setI18nRouteParams(response?.localeSlugs);
  }
  return response;
});
$switchLocalePath('fr') // === 'fr/nouvelles/1-premier-article'
$switchLocalePath('de') // === 'de/Nachricht/1-erster-Artikel'
```

## 🔧 Méthodes de cache et utilitaires

### `$has`

{/* generated:method:$has — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string) => boolean
```

Indique si une clé se résout dans la langue active. Utilisez-la pour créer une branche sur un texte facultatif au lieu d'afficher une clé brute.

{/* /generated:method:$has */}

Pendant les transitions de page dans la même langue, la v3 fusionne automatiquement en profondeur les traductions de la page qui quitte avec ce dictionnaire jusqu'à la fin de la transition. Les clés de la page précédente peuvent donc encore retourner `true` brièvement. Il n'y a pas d'option `previousPageFallback`; ce comportement est intégré. Consultez la [FAQ — transitions de page](/guides/faq#-why-do-translations-break-during-page-transitions-especially-with-defineasynccomponent).

```typescript
if ($has('welcome')) {
  console.log($t('welcome'))
} else {
  console.log('Key not found')
}
```

## 🧭 Composable `useI18nLocale`

Le composable centralisé pour la gestion de l'état linguistique. Utilisez-le plutôt que de manipuler directement `useState('i18n-locale')` ou `useCookie('user-locale')`.

```typescript
const {
  setLocale, // (locale: string) => void — updates state + cookie
  getLocale, // () => string | null — from state or cookie
  getPreferredLocale, // () => string | null — validated against locales list
  getEffectiveLocale, // (route, getLocaleFromRoute) => string
  resolveInitialLocale, // (options) => string
  isValidLocale, // (locale) => boolean
  locale, // Ref<string | null> — reactive state
  localeCookie, // CookieRef — reactive cookie
  syncLocale, // (locale) => void — sync to cookie only
  validLocales, // string[] — list of valid locale codes
} = useI18nLocale()
```

### Méthodes principales

| Méthode                 | Description                                                     |
| ----------------------- | --------------------------------------------------------------- |
| `setLocale(locale)`     | Définit la langue dans `useState` et le témoin de façon atomique |
| `getLocale()`           | Retourne la langue courante depuis l'état ou le témoin           |
| `getPreferredLocale()`  | Retourne la langue validée par rapport à la liste `locales`, ou `null` |
| `isValidLocale(locale)` | Vérifie si un code de langue est dans la liste `locales` configurée |

### Utilisation dans des plugins personnalisés

```typescript
// plugins/i18n-loader.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,
  setup() {
    const { setLocale } = useI18nLocale()
    // Detect locale from headers, domain, etc.
    setLocale('de')
  },
})
```

Consultez [Détection de langue personnalisée](/guides/custom-language-detection) pour des exemples détaillés.
