# 🌍 Composable `useLocaleHead`

Le composable `useLocaleHead` est un utilitaire de `Nuxt I18n Micro` qui vous aide à gérer les attributs SEO et les balises meta HTML pour les routes localisées. Il génère dynamiquement les attributs `lang` et `dir` du document HTML et crée les balises `meta` et `link` pour améliorer le SEO de votre contenu localisé.

## ⚙️ Options


Les balises SEO head pour la route courante : alternatifs `hreflang` pour chaque langue plus `x-default`, un lien canonique, `og:locale` et `lang`/`dir` sur `<html>`.

Nécessaires uniquement lorsque `meta` est désactivé ou que les valeurs par défaut doivent être ajustées. Avec `meta: true`, le module enregistre lui-même les mêmes balises.

## 🛠️ Valeurs retournées

Le composable `useLocaleHead` retourne un objet réactif et une fonction de mise à jour à appeler lorsque les données sources changent. Les deux formes se trouvent dans la signature ci-dessus, générée depuis la source.

### `metaObject`

Charge utile head réactive (html attrs, meta, link) prête pour `useHead(metaObject)`.

- **Exemple** :
  ```js
  const { metaObject } = useLocaleHead()
  useHead(metaObject)
  ```

### `updateMeta`

Recalcule `metaObject` en fonction de la route, de la langue et de la configuration courantes. Appelez-la lorsque les entrées changent (par exemple, à un changement de route).

- **Exemple** :
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  useHead(metaObject)
  watch(
    () => route.fullPath,
    () => updateMeta(),
    { immediate: true },
  )
  ```

### Accéder à `link` et `meta`

Les tableaux `link` et `meta` sont accessibles via `metaObject.value` :

- **Exemple** :
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  updateMeta()
  console.log(metaObject.value.link)
  // Output: [{ id: 'i18n-can', rel: 'canonical', href: 'https://example.com/about' }, ...]
  console.log(metaObject.value.meta)
  // Output: [{ id: 'i18n-og', property: 'og:locale', content: 'en_US' }, ...]
  ```

## 🛠️ Exemples d'utilisation

### Utilisation de base

Générez des attributs de head propres à la langue avec les options par défaut.

```js
const head = useLocaleHead()
```

### Personnaliser l'attribut identifiant

Utilisez un attribut identifiant personnalisé pour les balises générées.

```js
const head = useLocaleHead({ identifierAttribute: 'data-i18n' })
```

### Désactiver les attributs SEO

Générez des attributs de head sans ajouter de balises meta et link liées au SEO.

```js
const head = useLocaleHead({ addSeoAttributes: false })
```

### Spécifier une URL de base

Définissez une URL de base personnalisée pour les URL canoniques et alternatives.

```js
const head = useLocaleHead({ baseUrl: 'https://mywebsite.com' })
```

## 🚀 Fonctionnalités supplémentaires

### Balises meta et link pour le SEO

Lorsque `addSeoAttributes` est activé, le composable génère automatiquement les balises suivantes :

- `og:locale` pour la langue courante (`language_TERRITORY`, avec soulignement). Dérivé de `locale.og` ou converti depuis `locale.iso` lorsque c'est possible.
- `og:url` pour l'URL canonique de la page.
- `og:locale:alternate` pour les versions linguistiques alternatives.
- Liens `rel="canonical"` et `rel="alternate"` pour l'optimisation SEO.
- Lien `hreflang="x-default"` pointant vers l'URL de la langue par défaut. Il indique aux moteurs de recherche quelle URL afficher aux utilisateurs dont la langue ne correspond à aucune des langues définies.

### Langue et direction dynamiques

Le composable détermine dynamiquement les attributs `lang` et `dir` selon la langue de la route courante, ce qui garantit que votre document HTML est configuré correctement pour les utilisateurs internationaux.

### Gestion des routes localisées

Si vos routes sont préfixées de codes de langue (par exemple, `/en/about`), le composable ajuste intelligemment le chemin complet pour générer les URL, ce qui garantit que les attributs SEO sont exacts et pertinents.

Ce composable simplifie l'optimisation de votre application Nuxt pour des publics internationaux, garantissant que votre site est bien préparé pour les moteurs de recherche et les utilisateurs mondiaux.

## 🛠️ Exemple d'utilisation

L'exemple suivant montre comment utiliser le composable `useLocaleHead` dans un composant Vue avec les paramètres par défaut :

```vue
<script setup>
import { useRoute, watch } from '#imports'
const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({
  addDirAttribute: true,
  identifierAttribute: 'id',
  addSeoAttributes: true,
})
useHead(metaObject)
watch(
  () => route.fullPath,
  () => updateMeta(),
  { immediate: true },
)
</script>
```

### Explication du code

- **Composable `useLocaleHead`** : ce composable est appelé dans la section `<script setup>` et retourne un objet contenant `htmlAttrs`, `meta` et `link`.

- **Balise `<html>`** : les attributs `lang` et `dir` du document HTML sont déterminés dynamiquement selon la langue courante et sont appliqués à la balise `<html>`.

- **Section `<head>`** :
  - **Balises meta** : les balises meta liées au SEO sont générées, y compris `og:locale`, `og:url` et les balises `rel="canonical"` et `rel="alternate"` pour spécifier les versions linguistiques alternatives de la page.
  - **Balises link** : les liens canoniques, les liens vers les versions linguistiques alternatives et le lien `hreflang="x-default"` (pointant vers l'URL de la langue par défaut) sont inclus.

- **Section `<body>`** : le contenu principal de la page est affiché ici. Dans cet exemple, un simple en-tête et un paragraphe sont utilisés.

### 📝 Notes

1. **Attributs** : les attributs utilisés (`lang`, `dir`, `rel`, `href`, `hreflang`, `property`, `content`) sont extraits de l'objet retourné par `useLocaleHead`.

2. **Génération des balises SEO** : si l'option `addSeoAttributes` est définie à `true`, le composable génère automatiquement les balises SEO pour la langue courante.

3. **URL de base** : vous pouvez définir votre URL de base personnalisée avec l'option `baseUrl` pour générer correctement les liens canoniques et alternatifs.

Cet exemple montre à quel point il est simple d'intégrer `useLocaleHead` dans les composants de votre application pour garantir des attributs SEO corrects et améliorer l'indexation des pages localisées par les moteurs de recherche.

## 🧩 Personnalisation et cycle de vie

- `useLocaleHead` ne s'abonne pas aux changements de lui-même. Il retourne `metaObject` et `updateMeta`.
- Vous devez appeler `updateMeta()` lorsque les entrées changent (généralement à un changement de route), par exemple depuis un plugin :

```ts
// plugins/02.meta.ts
export default defineNuxtPlugin(() => {
  const route = useRoute()
  const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
  useHead(metaObject)
  if (import.meta.server) updateMeta()
  else
    watch(
      () => route.fullPath,
      () => updateMeta(),
      { immediate: true },
    )
})
```

## Quand utiliser `useI18nHead` plutôt

Lorsque `meta: true` (la valeur par défaut), préférez [`useI18nHead`](/api/composables/use-i18n-head) pour des surcharges **par page** (hreflang personnalisé, `og:title` supplémentaire, désactivation partielle). Utilisez `useLocaleHead` directement uniquement lorsque `meta: false` ou que vous gérez `useHead` vous-même.
