---
title: "useI18nLocale"
description: "useI18nLocale lit et écrit l'état de la locale et le témoin de locale — le point d'entrée pour la détection personnalisée de la locale."
---

`useI18nLocale()` donne accès à la locale choisie par l'application : l'état `i18n-locale` et le témoin de locale. Utilisez-le dans un plugiciel qui détecte lui-même la locale (domaine, profil de l'utilisateur, en-tête) au lieu d'écrire à la main `useState('i18n-locale')` ou le témoin. Ses vérifications de validité utilisent les locales activées, y compris les substitutions à l'exécution.

## Signature {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Point d'entrée centralisé pour la gestion de la locale i18n.
Combine useState('i18n-locale'), le témoin de locale et des utilitaires de synchronisation.

## Valeurs renvoyées {#returned-values}

| Membre | Type | Description |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | La ref `useState('i18n-locale')`. |
| `localeCookie` | `Ref<string \| null>` | Le témoin [`localeCookie`](/fr-CA/api/module-options#localecookie); un simple `{ value: null }` quand l'option vaut `null`. |
| `hashCookie` | `Ref<string \| null>` | Le témoin `hash-locale` en routage par hachage; `{ value: null }` sinon. |
| `validLocales` | `string[]` | Codes des locales activées. |
| `setLocale(locale)` | `(locale: string \| null) => void` | Écrit l'état et les témoins. Ne valide rien et ne charge pas les traductions. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | Écrit seulement les témoins. |
| `getLocale()` | `() => string \| null` | L'état, puis le témoin de préférence (le témoin de hachage en routage par hachage). Non validé. |
| `getPreferredLocale()` | `() => string \| null` | La première valeur **valide** entre l'état et le témoin de préférence, ou `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | L'état en routage par hachage lorsqu'il est défini; sinon `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, puis un état valide, puis `options.serverLocale`, puis la locale de la route. Enregistre le résultat dans l'état lorsque l'état n'est pas valide; côté client, écrit aussi le témoin. |
| `isValidLocale(locale)` | `(locale) => locale is string` | Indique si `locale` fait partie de `validLocales`. |

Les témoins durent un an, avec `path: '/'` et `sameSite: 'lax'`.

## Exemple {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

Le plugiciel de chargement du module lit l'état à son démarrage; un plugiciel qui le définit doit donc s'exécuter avant lui (`enforce: 'pre'`). Comment l'état se mesure à l'URL, au témoin et à `Accept-Language` : [Détection de la locale](/fr-CA/guide/locale-detection). Procédure complète : [Détection personnalisée](/fr-CA/guide/custom-auto-detect).

`setLocale()` ne change pas les traductions affichées à l'écran. Pour changer la locale de la page courante, appelez [`$switchLocale()`](/fr-CA/api/methods#$switchlocale).
