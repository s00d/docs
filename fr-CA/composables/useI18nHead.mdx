---
title: "useI18nHead"
description: "useI18nHead remplace les balises SEO i18n générées pour une seule page : remplacez ou retirez les balises canonical, hreflang et og, ou ajoutez les vôtres."
---

`useI18nHead()` modifie les balises SEO que le module génère, pour une seule page. Utilisez-le lorsqu'une page en sait plus que le routeur : un article de CMS qui n'existe que dans certaines locales, une URL canonique provenant d'une API, des balises `og:` supplémentaires. Vous obtenez les balises générées avec vos remplacements fusionnés par-dessus.

## Signature {#signature}

```ts
useI18nHead(input?: MaybeRefOrGetter<I18nHeadInput | null>): { pageHead: any; resetPageHead: () => void }
```

Enregistre des remplacements au niveau de la page pour les balises head SEO i18n.
Fusionnés par-dessus la sortie de `useLocaleHead` par le plugin `02.meta`.

Privilégiez un getter (`() => ({ … })`) lorsque les valeurs proviennent de `$t` / `t`, afin qu'elles
soient résolues de nouveau au changement de locale. Un objet simple est évalué une seule fois et reste figé.

| Paramètre | Type | Description |
| --- | --- | --- |
| `input` *(facultatif)* | `MaybeRefOrGetter<I18nHeadInput \| null>` |  |

Il fonctionne avec [`meta: true`](/fr-CA/api/module-options#meta) (la valeur par défaut) : le plugin meta du module fusionne l'entrée par-dessus la sortie de [`useLocaleHead`](/fr-CA/composables/useLocaleHead) à chaque rendu du head. Avec `meta: false`, rien ne la lit.

Le remplacement est réinitialisé lorsque le nom de la route change. Une page qui définit `disableMeta` n'obtient aucune balise i18n, remplacements compris.

## Entrée {#input}

`I18nHeadInput` (provenant de `@i18n-micro/types`) :

| Clé | Type | Effet |
| --- | --- | --- |
| `htmlAttrs` | `Record<string, string>` | Fusionné dans les attributs de `<html>` (`lang`, `dir`). |
| `meta` | `I18nHeadMeta[]` | Ajouté après les balises générées; remplace une balise ayant le même `id`, `property` ou `name`. |
| `link` | `I18nHeadLink[]` | Ajouté après les liens générés; remplace un lien ayant le même `id`, ou le même `rel` + `hreflang`. |
| `replace.canonical` | `string \| false` | Remplace le `href` canonique, ou retire le lien. |
| `replace.hreflang` | `I18nHeadLink[] \| false` | Remplace ou retire **tous** les liens `rel="alternate"`, `x-default` compris. |
| `replace.xDefault` | `I18nHeadLink \| false` | Remplace ou retire le lien `x-default`. |
| `replace.ogLocale` | `string \| false` | Remplace ou retire `og:locale`. |
| `replace.ogUrl` | `string \| false` | Remplace ou retire `og:url`. |
| `replace.ogAlternates` | `string[] \| false` | Reconstruit `og:locale:alternate` à partir de ces codes de locale (via `og` / `iso`), en ignorant la locale courante, les codes inconnus et les codes sans valeur `og` ni `iso`, ou les retire. |
| `disable` | `I18nHeadDisableGroup[]` | Retire des groupes générés : `'hreflang'` (sauf `x-default`), `'x-default'`, `'canonical'`, `'og'` (`og:locale` + `og:url`), `'og-alternates'`, `'html'`. |

Ordre d'application : `disable`, puis `replace`, puis `htmlAttrs`, `meta`, `link`.

## Exemple {#example}

Un article qui n'existe que dans certaines locales, avec des URL alternatives provenant de l'API :

```vue
<script setup lang="ts">
const route = useRoute()
const { t } = useI18n()
const { data: article } = await useFetch<{ title: string; urls: Record<string, string> }>(`/api/articles/${route.params.slug}`)

useI18nHead(() => {
  if (!article.value) return null
  const codes = Object.keys(article.value.urls)
  return {
    meta: [{ property: 'og:title', content: article.value.title || t('blog.title') }],
    replace: {
      hreflang: codes.map((code) => ({ rel: 'alternate', hreflang: code, href: article.value!.urls[code]! })),
      ogAlternates: codes,
    },
  }
})
</script>
```

Passez un getter, comme ici, lorsque les valeurs proviennent de `t()` ou de données asynchrones : il est réexécuté au changement de locale. Un objet simple n'est lu qu'une fois.
