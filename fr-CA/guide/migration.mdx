Cette page fait correspondre une application `@nuxtjs/i18n` à nuxt-i18n-micro : options, fonctions utilitaires et organisation des fichiers. Utilisez-la lorsque vous remplacez le module dans une application existante. Vous conservez vos URL (les noms de stratégies sont les mêmes) et vous déplacez les traductions dans des fichiers JSON par page.

<Tip>

**Vous mettez à niveau nuxt-i18n-micro lui-même?** — Consultez [Mise à niveau](/fr-CA/guide/upgrade).

</Tip>

## Remplacer le module {#swap-the-module}

```bash
npm uninstall @nuxtjs/i18n
npm install nuxt-i18n-micro
```

```ts
// nuxt.config.ts — before
export default defineNuxtConfig({
  modules: ['@nuxtjs/i18n'],
  i18n: {
    locales: [
      { code: 'en', language: 'en-US', file: 'en.json' },
      { code: 'de', language: 'de-DE', file: 'de.json' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    langDir: 'locales',
    detectBrowserLanguage: { useCookie: true, cookieKey: 'i18n_redirected', redirectOn: 'root' },
  },
})
```

```ts
// nuxt.config.ts — after
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    translationDir: 'locales',
    localeCookie: 'i18n_redirected',
    autoDetectPath: '/',
  },
})
```

## Options {#options}

| `@nuxtjs/i18n` | nuxt-i18n-micro |
| --- | --- |
| `locales[].code` | `locales[].code` |
| `locales[].language` (`iso` avant la v9) | `locales[].iso` |
| `locales[].name` | `locales[].displayName` |
| `locales[].dir` | `locales[].dir` |
| `locales[].domain` | `locales[].baseUrl` (une origine avec son schéma) |
| `locales[].domainDefault` | `locales[].baseDefault` |
| `differentDomains`, `multiDomainLocales` | inutiles : `baseUrl` suffit à acheminer selon l’hôte, consultez [Couches et domaines](/fr-CA/guide/layers#multiple-domains) |
| `locales[].file` / `files`, `langDir`, `lazy` | `translationDir`; les fichiers sont trouvés par leur nom et toujours chargés par page |
| `defaultLocale`, `strategy` | mêmes noms, mêmes quatre valeurs |
| `baseUrl` | `metaBaseUrl` |
| `customRoutes: 'config'` + `pages` | `globalLocaleRoutes` |
| `detectBrowserLanguage: false` | `redirects: false` (aucune redirection) ou `autoDetectLanguage: false` (ignorer l’en-tête) |
| `detectBrowserLanguage.useCookie` / `cookieKey` | `localeCookie: '<name>'` (`null` désactive le témoin) |
| `detectBrowserLanguage.redirectOn: 'root'` | `autoDetectPath: '/'` (par défaut) |
| `detectBrowserLanguage.redirectOn: 'no prefix'` | `autoDetectPath: 'no_prefix'` |
| `detectBrowserLanguage.redirectOn: 'all'` | `autoDetectPath: '*'` |
| Fichier de configuration `vueI18n` (`fallbackLocale`, `numberFormats`, `datetimeFormats`) | `fallbackLocale`, `numberFormats`, `datetimeFormats` dans `i18n` |

Il n’y a pas de `alwaysRedirect` : lorsqu’un témoin est défini, `/` le suit à chaque visite. La liste complète se trouve dans [Options du module](/fr-CA/api/module-options); les règles de détection sont décrites dans [Détection de la langue](/fr-CA/guide/locale-detection).

## Fonctions utilitaires et composables {#helpers-and-composables}

| `@nuxtjs/i18n` / vue-i18n | nuxt-i18n-micro (gabarit / `useI18n()`) |
| --- | --- |
| `const { t } = useI18n()` | `const { t } = useI18n()`, `$t` dans les gabarits |
| `t('key', count)`, `tc` | `$tc('key', count)` |
| `te('key')` | `$has('key')` |
| `n(value, 'currency')`, `d(date, 'short')` | `$tn(value, 'currency')`, `$td(date, 'short')` |
| — | `$tdr(date)` : temps relatif (« dans 3 jours ») |
| `locale.value` | `$getLocale()` |
| `locales.value` | `$getLocales()` |
| `setLocale('de')` | `$switchLocale('de')` |
| `useLocalePath()('about')` | `$localePath({ name: 'about' })` |
| `useLocaleRoute()` | `$localeRoute()` |
| `useSwitchLocalePath()('de')` | `$switchLocalePath('de')` |
| `useSetI18nParams()` | `$setI18nRouteParams()` |
| `useLocaleHead()` | automatique avec `meta: true`; [`useLocaleHead`](/fr-CA/composables/useLocaleHead) pour des en-têtes personnalisés |
| `defineI18nRoute({ paths: { de: '/ueber-uns' }, locales: [...] })` | `$defineI18nRoute({ localeRoutes: { de: '/ueber-uns' }, locales: [...] })` |
| `<NuxtLinkLocale to="about">` | `<i18n-link :to="{ name: 'about' }">` |
| `<i18n-t>` | `<i18n-t>` (les slots remplissent les espaces réservés `{name}`) |
| `$i18n` dans les routes serveur | `useTranslationServerMiddleware(event)`, consultez [Routes serveur et API](/fr-CA/guide/server-side-translations) |

`useI18n()` est importé automatiquement. `$defineI18nRoute` doit conserver son `$` : la compilation lit cet appel. Toutes les fonctions utilitaires : [Méthodes](/fr-CA/api/methods).

## Fichiers de traduction {#translation-files}

Déplacez les clés du gros fichier unique de chaque langue dans un fichier racine plus un fichier par page :

```text
locales/
├── en.json              # keys used on many pages (nav, footer)
├── de.json
└── pages/
    ├── index/en.json    # keys of pages/index.vue
    └── about/en.json    # keys of pages/about.vue
```

Tout garder dans les fichiers racine fonctionne aussi, et c’est la première étape la plus rapide. Définissez `disablePageLocales: true` jusqu’à ce que vous les divisiez. Consultez [Fichiers de traduction](/fr-CA/guide/translations).

### Syntaxe des messages {#message-syntax}

| vue-i18n | nuxt-i18n-micro |
| --- | --- |
| Interpolation nommée `{name}` | identique |
| `car \| cars` (2 formes : 1 → la première) | les formes sont choisies selon le nombre à partir de 0 : écrivez `no cars \| one car \| {count} cars` |
| Messages liés `@:other.key` | non pris en charge : répétez le texte ou composez dans le code |
| Modificateurs `@.upper:` | non pris en charge : formatez dans le code ou utilisez `<i18n-t>` |
| Échappements littéraux `{'@'}` | inutiles : seuls les jetons `{word}` sont remplacés |
| Fichiers de messages JS/TS | JSON uniquement |

La règle de pluriel peut être remplacée avec l’option [`plural`](/fr-CA/api/module-options#plural).

## Vérifications après le changement {#check-after-the-switch}

- Toutes vos URL existantes sont toujours résolues; les noms de stratégies correspondent, et les chemins personnalisés passent dans `globalLocaleRoutes` ou `$defineI18nRoute`.
- Les balises `hreflang`, canonique et `og:locale` sont fournies d’office avec `meta: true`; supprimez celles écrites à la main.
- Une erreur d’analyse JSON journalise le chemin du fichier; une clé manquante journalise un avertissement dans la console du navigateur en développement.
