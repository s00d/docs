---
title: "Configuration de page"
description: "Limitez une page à certaines locales, donnez-lui des chemins personnalisés, des traductions en ligne ou aucune balise SEO avec $defineI18nRoute."
---

`$defineI18nRoute` définit les options i18n d'une page depuis la page elle-même. Utilisez-le lorsqu'une page n'existe que dans certaines locales, a besoin de son propre chemin localisé, contient quelques traductions qui lui sont propres ou ne doit pas recevoir de balises hreflang/canonical. Le module lit l'appel à la compilation et l'intègre dans les routes générées.

## Limiter une page à certaines locales {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

Seules `/product` et `/de/product` sont générées avec la stratégie par défaut `prefix_except_default`; la page n'a de route dans aucune autre locale. La même chose peut être définie depuis `nuxt.config.ts` avec [`routeLocales`](/fr-CA/api/module-options#routelocales).

`$defineI18nRoute` est une injection de l'application Nuxt, et non une macro du compilateur : récupérez-la toujours depuis `useNuxtApp()` et appelez-la avec le `$`. Seul `$defineI18nRoute(` est reconnu par l'étape de compilation.

## Ajouter des traductions en ligne {#add-inline-translations}

Passez un objet au lieu d'un tableau. Ses clés sont les locales autorisées, et ses valeurs sont fusionnées dans le dictionnaire de la page pour la locale active.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Les traductions en ligne sont livrées dans le composant de page pour toutes les locales. Préférez les [fichiers de traduction de page](/fr-CA/guide/translations) pour tout ce qui dépasse quelques clés; réservez les clés en ligne aux pages et composants autonomes.

## Définir des chemins localisés {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

Avec `prefix_except_default` et `defaultLocale: 'en'`, cela produit `/welcome` et `/de/willkommen`. Un `path` dans un objet de locale en ligne fait la même chose : `locales: { de: { path: '/willkommen' } }`. Les paramètres dynamiques, les routes imbriquées et la solution de rechange au niveau de la configuration sont présentés dans [Chemins localisés](/fr-CA/guide/custom-locale-routes).

## Désactiver les balises SEO {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

La solution de rechange au niveau de la configuration est [`routeDisableMeta`](/fr-CA/api/module-options#routedisablemeta). La nature de ces balises est expliquée à la page [SEO](/fr-CA/guide/seo).

## Ce que la compilation peut lire {#what-the-build-can-read}

L'étape de compilation repère l'appel dans chaque fichier de page et évalue son argument sans exécuter votre application. Cela fonctionne lorsque la configuration est :

- un objet littéral (chaînes, tableaux, objets imbriqués, littéraux de gabarit, ternaires sur `process.env.NODE_ENV`);
- construite à partir de constantes déclarées dans le même `<script setup>` (`const locales = ['en', 'de']`, décompositions comprises);
- un tableau d'objets avec un champ `code` (`[{ code: 'en' }, { code: 'de' }]`).

Elle ne peut pas lire des valeurs importées d'un autre module, ni quoi que ce soit qui nécessite votre application à l'exécution (composables, `await`, données récupérées). Dans ce cas, la compilation journalise `Ignored the $defineI18nRoute() config in <file>` et la page conserve les locales et les routes par défaut.

À l'exécution, l'appel fusionne seulement les traductions en ligne pour la locale actuelle et les fusionne de nouveau lorsque la locale change. `locales`, `localeRoutes` et `disableMeta` ne prennent effet que par la compilation; les modifier nécessite donc une recompilation (le serveur de développement recompile à l'enregistrement).
