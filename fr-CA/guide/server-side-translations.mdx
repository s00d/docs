Les gestionnaires serveur de `server/api/` et de `server/routes/` peuvent traduire des chaînes et lire la locale de la requête grâce à deux utilitaires importés automatiquement. Utilisez-les pour les réponses d'API, les courriels, les flux ou tout ce qui est rendu en dehors d'une page Vue. Ils lisent les mêmes fichiers de traduction que vos pages et détectent la locale à partir de la requête.

## Traduire dans un gestionnaire {#translate-in-a-handler}

```ts
// server/api/greeting.get.ts
export default defineEventHandler(async (event) => {
  const t = await useTranslationServerMiddleware(event)
  return { message: t('greeting', { name: 'Ada' }) }
})
```

```bash
curl 'http://localhost:3000/api/greeting?locale=de'
# {"message":"Hallo, Ada!"}
```

`useTranslationServerMiddleware(event, defaultLocale?, locale?)` est asynchrone et retourne `t(key, params?, defaultValue?)`. `t` retourne la chaîne, interpole les paramètres `{name}` et, lorsque la clé est absente, retourne un `defaultValue` non vide, sinon la clé.

`t` ne voit que le bloc `index` : les fichiers racines (`locales/<locale>.json`) ainsi que `locales/pages/index/` s'il existe (seulement les fichiers racines avec `disablePageLocales`). Les clés des autres pages ne sont pas chargées. Pour celles-ci, chargez le bloc vous-même :

```ts
const { data } = await loadTranslationsFromServer('de', 'about') // Translations object of the about page
```

## Lire la locale de la requête {#read-the-request-locale}

```ts
// server/api/locale.get.ts
export default defineEventHandler((event) => {
  const { current, isDefault, locale } = useLocaleServerMiddleware(event)
  return { current, isDefault, dir: locale?.dir ?? 'ltr' }
})
```

`useLocaleServerMiddleware(event, defaultLocale?, locale?)` est synchrone et retourne :

```ts
interface LocaleInfo {
  current: string // detected locale code
  default: string // defaultLocale, runtime overrides included (fixed at build under prefix_except_default / prefix_and_default)
  fallback: string // fallbackLocale, else the default
  available: string[] // enabled locale codes
  locale: Locale | null // the config entry of `current`
  isDefault: boolean
  isFallback: boolean
}
```

## Choix de la locale {#how-the-locale-is-chosen}

Les deux utilitaires suivent le même ordre sur toutes les routes serveur, `/api` ou non :

1. la requête `?locale=` (la première valeur si elle est répétée);
2. un paramètre de route `[locale]`, ou un préfixe de locale dans le chemin (`/de/...`);
3. le témoin (cookie) de locale, lorsque [`localeCookie`](/fr-CA/api/module-options#localecookie) est défini (`hash-locale` avec `hashMode`);
4. `Accept-Language`, lorsque `autoDetectLanguage` est activé (les valeurs q sont respectées);
5. `defaultLocale`.

Les codes invalides et désactivés sont ignorés à chaque étape. C'est l'ordre de l'API; le rendu d'une page ignore `?locale=` avec les stratégies à préfixe. Les deux ordres sont comparés dans [Détection de la locale](/fr-CA/guide/locale-detection).

## Forcer une locale {#force-a-locale}

Passez le troisième argument pour sauter la détection, par exemple dans une tâche qui envoie un courriel dans la langue de l'utilisateur :

```ts
export default defineEventHandler(async (event) => {
  const user = await getUser(event) // your code
  const t = await useTranslationServerMiddleware(event, undefined, user.locale)
  return sendMail(user.email, t('mail.welcome.subject'))
})
```

Le deuxième argument remplace `defaultLocale` pour la détection de cet appel; il n'a donc aucun effet lorsqu'une locale est forcée. Les dictionnaires sont mis en cache par requête et par locale, et d'une requête à l'autre dans le cache de traductions du serveur; appeler un utilitaire plusieurs fois coûte donc peu.

## Composants serveur {#server-components}

Un composant serveur (`.server.vue`, `<NuxtIsland>`) est rendu à partir de sa propre URL, `/__nuxt_island/...`; il ne voit donc pas l'URL de la page, et Nuxt ne lui passe que ses props. Passez la locale dans une prop `locale`. Le composant est alors rendu dans cette locale, et un changement de locale le récupère de nouveau, puisque les props font partie de l'URL et de la clé de cache de l'îlot. Ce nom est réservé : tout code de locale activé dans une prop nommée `locale` définit la locale du rendu; donnez donc un autre nom à une prop qui signifie autre chose, comme un format de nombre :

```vue
<!-- components/Greeting.server.vue -->
<template><p>{{ $t('greeting') }}</p></template>
<script setup lang="ts">
defineProps<{ locale?: string }>()
</script>
```

```vue
<template>
  <Greeting :locale="$getLocale()" />
  <NuxtIsland name="Greeting" :props="{ locale: $getLocale() }" />
</template>
```

Sans la prop, il est rendu dans la locale du témoin, sinon dans la locale par défaut, peu importe l'URL, et il ne suit pas un changement de locale. Son `$t` voit le bloc `index` : les fichiers racines ainsi que `locales/pages/index/`.
