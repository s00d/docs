Avec `meta: true` (la valeur par défaut), chaque page localisée reçoit `<html lang dir>`, un lien canonique, des alternatives `hreflang`, `x-default` et des balises de locale Open Graph. Cette page vous sera utile si vous voulez définir l'origine publique, choisir quelles locales apparaissent dans les balises ou les remplacer pour une page. La plupart des sites n'ont besoin que d'un `site.url` ou d'un `metaBaseUrl` et de codes `iso` corrects.

## Configuration minimale {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

`/de/about` produit alors :

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Sens du texte {#text-direction}

`<html dir>` provient du `dir` de la locale. Sans cette valeur, une langue qui s'écrit de droite à gauche reçoit `rtl`, déduit de `iso` (ou de `code`) : l'arabe, l'hébreu, le persan, l'ourdou et quelques autres, ainsi que toute balise avec une écriture RTL comme `az-Arab`. Toutes les autres locales n'ont pas d'attribut `dir`, ce que les navigateurs interprètent comme `ltr`.

<Warning>

**`dir: 'auto'` coûte du temps d'analyse sur les grandes pages** — `auto` sur `<html>` oblige le navigateur à déterminer le sens à partir du contenu pendant l'analyse. Dans Chromium, ce coût augmente plus vite que la taille de la page : environ 100 ms à 5 000 éléments et 1 s à 20 000. Ne l'utilisez que pour une petite page dont vous ne pouvez pas connaître la langue.

</Warning>

## Balises obtenues {#which-tags-you-get}

- **hreflang** : une balise par locale qui sert la page, avec la valeur `iso` (ou `code` lorsque `iso` est absent) et son URL avec la même requête que l'URL canonique. Une page restreinte avec [Configuration de page](/fr-CA/guide/per-component-translations) ou `routeLocales` n'énumère que ses locales. [`hreflangBaseLanguage: true`](/fr-CA/api/module-options#hreflangbaselanguage) ajoute aussi la langue de base (`es-ES` → `es`) pour la première locale régionale.
- **x-default** : l'URL de la locale par défaut, seulement lorsque la locale par défaut sert la page.
- **og:locale** : dérivé de `iso` (`en-US` → `en_US`). Définissez `og` sur la locale lorsque la correspondance n'est pas directe, par exemple `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; sans l'un ni l'autre, aucun `og:locale` n'est écrit et le mode développement affiche un avertissement.
- **canonical / og:url** : l'URL courante sans paramètres de requête, sauf ceux de [`canonicalQueryWhitelist`](/fr-CA/api/module-options#canonicalquerywhitelist) (par défaut `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Selon la stratégie :

| Stratégie | hreflang et x-default | canonical, og:url, og:locale, attributs html |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | oui | oui |
| `no_prefix` | non (une seule URL sert toutes les locales) | oui |

## Définir l'origine publique {#set-the-public-origin}

Les URL absolues utilisent la première valeur disponible parmi :

1. [`metaBaseUrl`](/fr-CA/api/module-options#metabaseurl);
2. `site.url` de `nuxt-site-config` (installé par `@nuxtjs/seo`);
3. l'origine de la requête, à laquelle on ajoute `app.baseURL`.

Fixez l'une des deux premières.

<Warning>

Le repli sur l'origine de la requête lit `X-Forwarded-Host` et `X-Forwarded-Proto`, car [`metaTrustForwardedHost`](/fr-CA/api/module-options#metatrustforwardedhost) et `metaTrustForwardedProto` valent `true` par défaut. Ce n'est sûr que derrière un proxy qui écrase ces en-têtes; sinon, un client peut choisir l'hôte de vos liens canoniques, et un cache peut transmettre cette page à d'autres.

Si l'application est accessible directement, fixez `metaBaseUrl` : contrairement au fait de régler les deux options à `false`, cela ignore aussi un `Host` falsifié. Consultez [Derrière un proxy ou un CDN](/fr-CA/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

Le repli est utile pour un seul déploiement qui répond à plusieurs domaines : `https://site-a.com/en/about` et `https://site-b.com/en/about` obtiennent chacun leur propre origine.

Avec `baseUrl` sur les locales, un hôte connu utilise son propre `baseUrl`, avant `metaBaseUrl` et `site.url`; l'URL canonique et `og:url` restent donc sur ce domaine et `hreflang` dirige chaque locale vers son domaine. Tout autre hôte utilise `metaBaseUrl`, sinon le `baseUrl` de la locale par défaut, sinon `site.url`, de sorte qu'un `Host` usurpé ne peut pas atteindre vos balises. Si aucune de ces valeurs n'est définie, le repli sur l'origine de la requête demeure, et le build affiche un avertissement. Consultez [Couches et domaines](/fr-CA/guide/layers#multiple-domains).

## Exclure des locales ou des pages {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Si la locale par défaut a `seo: false`, aucun `x-default` n'est écrit. Pour désactiver les balises sur une page, utilisez `disableMeta` dans [Configuration de page](/fr-CA/guide/per-component-translations#turn-off-seo-tags), ou [`routeDisableMeta`](/fr-CA/api/module-options#routedisablemeta) dans la configuration.

## Remplacer les balises d'une page {#override-tags-on-one-page}

Pour du contenu de CMS dont seules certaines traductions existent, ou dont les URL proviennent d'une API, remplacez les balises générées avec [`useI18nHead`](/fr-CA/composables/useI18nHead) :

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` peut aussi définir ou retirer `canonical`, `xDefault`, `ogLocale` et `ogUrl`; `disable` retire des groupes entiers (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Passez un getter pour que les valeurs soient recalculées après un changement de locale. Pour les slugs par locale, définissez d'abord `$setI18nRouteParams` ([Chemins localisés](/fr-CA/guide/custom-locale-routes#per-locale-slugs)) : les alternatives générées les utilisent déjà.

## Barre oblique finale {#trailing-slash}

`$localePath`, `$switchLocalePath`, l'objet de route de `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, les redirections de locale et les URL SEO suivent une seule règle de barre oblique : `experimental.defaults.nuxtLink.trailingSlash` par défaut, ou [`trailingSlash`](/fr-CA/api/module-options) dans la configuration i18n lorsque les chemins i18n doivent être différents.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) fonctionne avec ce module grâce à `nuxt-site-config` 4+. Placez `nuxt-i18n-micro` en premier pour que la configuration du site puisse lire les locales, et définissez `site.url` une seule fois — cette valeur alimente aussi les balises ci-dessus.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Un nom et une description de site traduits proviennent des clés `nuxtSiteConfig.name` / `nuxtSiteConfig.description` de vos fichiers de locale. L'erreur `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` signifie que `@nuxtjs/seo` est antérieur à la version 3; mettez-le à jour ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
