Cette page fait passer une application Nuxt de zéro i18n à une page traduite avec un sélecteur de langue. Vous n'en avez besoin qu'une fois, au début d'un projet. Vous obtenez des URL localisées (`/about`, `/de/about`), un fichier JSON par locale et par page, et `$t` dans vos gabarits.

## Installation {#install}

Le module nécessite Nuxt 3.18 ou plus récent (Nuxt 4 fonctionne aussi) et Node 20 ou plus récent.

<CodeGroup>

```bash npm
npm install nuxt-i18n-micro
```

```bash pnpm
pnpm add nuxt-i18n-micro
```

```bash yarn
yarn add nuxt-i18n-micro
```

```bash bun
bun add nuxt-i18n-micro
```

</CodeGroup>

## Configurer les locales {#configure-the-locales}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
      { code: 'fr', iso: 'fr-FR', displayName: 'Français' },
    ],
    defaultLocale: 'en',
  },
})
```

C'est toute la configuration dont une première application a besoin. Les valeurs par défaut vous donnent :

- `strategy: 'prefix_except_default'` : la locale par défaut n'a pas de préfixe (`/about`), les autres en ont un (`/de/about`). Voir [Stratégies de routage](/fr-CA/guide/strategy).
- `translationDir: 'locales'` : les fichiers de traduction se trouvent dans `locales/` à la racine du projet, y compris avec la structure `app/` de Nuxt 4.
- `meta: true` : balises `hreflang`, canonical et `og:locale`, ainsi que `lang` et `dir` sur `<html>`. Voir [SEO](/fr-CA/guide/seo).
- Un visiteur qui ouvre `/` est redirigé vers la langue demandée par son navigateur (`Accept-Language`). Voir [Détection de la locale](/fr-CA/guide/locale-detection).

`iso` est l'étiquette de langue utilisée dans les balises SEO; `code` est ce qui apparaît dans l'URL. Toutes les options sont répertoriées dans [Options du module](/fr-CA/api/module-options).

## Ajouter des fichiers de traduction {#add-translation-files}

Démarrez le serveur de développement avec `nuxt dev`. Lorsque Nuxt résout les pages, le module crée un fichier vide `{}` pour chaque locale et chaque page qui n'en a pas (désactivez ce comportement avec [`disableWatcher`](/fr-CA/api/module-options#disablewatcher)) :

```text
locales/
├── en.json            # root: keys every page can use
├── de.json
├── fr.json
└── pages/
    ├── index/         # pages/index.vue
    │   ├── en.json
    │   ├── de.json
    │   └── fr.json
    └── about/         # pages/about.vue
        ├── en.json
        ├── de.json
        └── fr.json
```

Remplissez le fichier racine et un fichier de page :

```json
// locales/en.json
{ "nav": { "home": "Home", "about": "About" } }
```

```json
// locales/pages/index/en.json
{ "welcome": "Welcome, {name}!", "items": "no items | one item | {count} items" }
```

Une page voit les clés racines et ses propres clés; son propre fichier l'emporte en cas de conflit. Les noms de dossiers suivent le nom de la route (`pages/articles/[id].vue` correspond à `locales/pages/articles-id/`). [Fichiers de traduction](/fr-CA/guide/translations) couvre la structure, les replis et le chargement.

## Utiliser `$t` dans une page {#use-$t-on-a-page}

```vue
<!-- pages/index.vue -->
<script setup lang="ts">
const { t, tc, getLocale } = useI18n()

const title = t('nav.home') // 'Home'
</script>

<template>
  <h1>{{ $t('welcome', { name: 'Ada' }) }}</h1>
  <!-- Welcome, Ada! -->
  <p>{{ $tc('items', 3) }}</p>
  <!-- 3 items -->
  <p>{{ getLocale() }}</p>
  <!-- en -->
</template>
```

- Dans les gabarits, chaque fonction utilitaire est disponible avec un `$` (`$t`, `$tc`, `$localePath`, …).
- Dans `<script setup>`, `useI18n()` retourne les mêmes fonctions utilitaires, avec et sans le `$` (`t` et `$t` sont une seule et même fonction). Il est importé automatiquement.
- Les espaces réservés `{name}` sont remplis à partir de l'objet de paramètres. Les formes plurielles sont séparées par `|`; le nombre choisit la forme (0, 1, puis la dernière pour tout ce qui est supérieur).

Toutes les fonctions utilitaires sont répertoriées dans [Méthodes](/fr-CA/api/methods).

## Lier les pages et changer de locale {#link-between-pages-and-switch-locale}

```vue
<!-- components/AppHeader.vue -->
<template>
  <nav>
    <i18n-link :to="{ name: 'index' }">{{ $t('nav.home') }}</i18n-link>
    <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
    <i18n-switcher />
  </nav>
</template>
```

- [`<i18n-link>`](/fr-CA/components/i18n-link) est un `NuxtLink` qui pointe vers la page dans la locale courante : sur `/de`, le lien « about » mène à `/de/about`.
- [`<i18n-switcher>`](/fr-CA/components/i18n-switcher) est une liste déroulante des locales activées; il garde le visiteur sur la même page.
- Pour vos propres boutons, appelez `$switchLocale('de')`, qui navigue vers la page courante en allemand et mémorise le choix. Pour un `NuxtLink` simple, utilisez `$localePath({ name: 'about' })` ou `$switchLocalePath('de')`.

## Vérifier {#check-it}

Lancez `nuxt dev` et ouvrez :

| URL | Affiche |
| --- | --- |
| `/` | Accueil en anglais (ou une redirection vers `/de` lorsque votre navigateur préfère l'allemand) |
| `/de` | Accueil en allemand |
| `/de/about` | Page « about » en allemand |
| `/en/about` | 404 : la locale par défaut n'a pas de préfixe avec `prefix_except_default` |

Les modifications des fichiers JSON s'appliquent dans la page ouverte sans rechargement.
