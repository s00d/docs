**Date** : 2026-06-25

**Version** : `v3.21.0`

![v3.21.0 release](/images/3.21.0.png)

Cette version ajoute **`useI18nHead`** — un composable au niveau de la page pour personnaliser le SEO i18n par-dessus le plugin intégré `02.meta`. Personnalisez les balises `hreflang`, canonical, `og:url` et Open Graph par route, sans plugin meta personnalisé ni `meta: false`.

## Quoi de neuf? {#what’s-new}

### Composable `useI18nHead` {#usei18nhead-composable}

Appelez `useI18nHead` dans n'importe quelle page lorsque `meta: true` (par défaut). Le module fusionne vos valeurs après `useLocaleHead` à chaque mise à jour de route :

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

Prend en charge les objets statiques, les getters réactifs, l'ajout de `meta` / `link`, `replace` pour les groupes intégrés et `disable` pour retirer les balises générées automatiquement. Voir [`useI18nHead`](/fr-CA/composables/useI18nHead).

### Utilitaire `mergeI18nHead` (`@i18n-micro/utils`) {#mergei18nhead-utility-@i18n-micro/utils}

La logique de fusion, indépendante du framework, se trouve dans `@i18n-micro/utils/merge-i18n-head` — elle est utilisée par le plugin `02.meta` et testable de façon isolée. Les types (`I18nHeadInput`, `I18nHeadLink`, `I18nHeadMeta`) sont exportés depuis `@i18n-micro/types`.

### Intégration aux plugins {#plugin-integration}

- **`02.meta`** — fusionne la sortie de `useLocaleHead` avec l'état de la page provenant de `useI18nHead` via `useHead`
- **`01.plugin`** — réinitialise les personnalisations de la page lors d'un changement de nom de route via `resetPageHead()` (état partagé avec le composable)

## Cas d'utilisation typiques {#typical-use-cases}

| Scénario                                     | Approche                                                       |
| -------------------------------------------- | -------------------------------------------------------------- |
| Blogue/CMS avec traductions partielles       | `replace.hreflang` + `replace.ogAlternates` à partir des locales de l'API |
| Canonical personnalisé provenant du CMS      | `replace.canonical` + `replace.ogUrl`                          |
| Page d'accueil, OG seulement                 | `meta: [{ property: 'og:title', ... }]` — conserver le hreflang du module |
| Aucun hreflang sur une page                  | `disable: ['hreflang', 'x-default']`                           |
| Remplacer un plugin personnalisé (`i18nManualHreflang`) | `useI18nHead` par page de contenu + `meta: true`    |

Le **JSON-LD** reste dans `useHead({ script: [...] })` — `useI18nHead` ne génère pas de données structurées.

## Changements incompatibles {#breaking-changes}

Aucun pour une utilisation standard de `nuxt.config`. Le nouveau composable et le sous-chemin utils sont des ajouts.

## Pourquoi c'est important {#why-it-matters}

- **Aucun plugin meta personnalisé** pour les articles de CMS, les nouvelles ou les guides avec des URL par locale
- **Pipeline unique** — valeurs par défaut du module + personnalisations de la page dans un seul appel à `useHead`
- **Typage sûr** — `I18nHeadInput` pour des fonctions utilitaires comme `buildArticleHead(content)`
