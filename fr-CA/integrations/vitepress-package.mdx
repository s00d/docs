title: "VitePress"
description: "Traductions à l'exécution, $t dans le markdown, synchronisation de la locale et balises SEO pour les sites VitePress avec @i18n-micro/vitepress."
---

`@i18n-micro/vitepress` ajoute des dictionnaires d'exécution à un site VitePress : `$t` et `<I18nT>` dans le markdown, des fonctions utilitaires de chemin et des balises SEO, le tout construit sur [`@i18n-micro/vue`](/fr-CA/integrations/vue-package). Utilisez-le lorsque les mêmes chaînes d'interface apparaissent sur de nombreuses pages et que vous ne voulez pas les dupliquer pour chaque locale. La locale suit les locales de chemin propres à VitePress (`/`, `/fr/`).

## Quand l'utiliser {#when-to-use-it}

| Besoin | Solution |
|------|----------|
| Fichiers `.md` dupliqués, préfixes d'URL | `locales` de VitePress |
| `$t` à l'exécution / composants / synchronisation des chemins / en-tête SEO | `@i18n-micro/vitepress` |
| Libellés de l'interface du thème par défaut (`docFooter`, interface de recherche) | Votre propre `themeConfig` par locale |

<Tip>

**Bac à sable** — [`packages/vitepress/playground`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/vitepress/playground) — `pnpm -C packages/vitepress/playground dev`

</Tip>

## Installation {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vitepress
```

```bash npm
npm install @i18n-micro/vitepress
```

```bash yarn
yarn add @i18n-micro/vitepress
```

</CodeGroup>

Dépendances homologues (peer) : `vitepress` `>=1.0.0 || >=2.0.0-alpha.0`, `vue` `^3.3.0`. Les scripts Node utilisent `@i18n-micro/node`, installé avec le paquet et réexporté par `/node`. Les types publiés nécessitent Vue 3.5.5 ou une version ultérieure avec `skipLibCheck: false`; avec `skipLibCheck: true`, le réglage habituel des gabarits, les versions plus anciennes compilent aussi.

## Configuration {#setup}

```
locales/en.json
locales/fr.json
locales/pages/guide/demo/en.json   # optional page-scoped
locales/pages/guide/demo/fr.json
```

Les fichiers de page correspondent aux noms de route de la même façon qu'avec Nuxt/Astro (`guide/demo` → `guide-demo`).

### 1. Configuration — `@i18n-micro/vitepress/config` {#1-config-—-@i18n-micro/vitepress/config}

```ts
// .vitepress/config.mts
import { defineConfig } from 'vitepress'
import { withI18n, buildVitePressLocales } from '@i18n-micro/vitepress/config'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English', og: 'en_US' },
  { code: 'fr', iso: 'fr-FR', displayName: 'Français', og: 'fr_FR' },
]
const defaultLocale = 'en'

export default defineConfig(
  withI18n(
    {
      locales: buildVitePressLocales(locales, defaultLocale),
      // themeConfig.i18nRouting is injected automatically
    },
    {
      locale: defaultLocale,
      defaultLocale,
      locales,
      translationDir: 'locales',
      metaBaseUrl: 'https://example.com', // optional SEO head
    },
  ),
)
```

### 2. Thème — `@i18n-micro/vitepress/theme` {#2-theme-—-@i18n-micro/vitepress/theme}

```ts
// .vitepress/theme/index.ts
import DefaultTheme from 'vitepress/theme'
import { defineI18nTheme } from '@i18n-micro/vitepress/theme'

export default defineI18nTheme(DefaultTheme)
```

La locale initiale est tirée du chemin actuel avant l'installation (aucun affichage furtif de la locale par défaut sur `/fr/…`).

### Avancé : `createI18n` manuel {#advanced-manual-createi18n}

Une seule fabrique pour le client : plugin Vue + méthodes de chemin + `enhanceApp` (aucune exportation distincte de fonction utilitaire de routeur).

```ts
import { createI18n, messagesFromGlob } from '@i18n-micro/vitepress'

const i18n = createI18n({
  locale: 'en',
  defaultLocale: 'en',
  locales: [{ code: 'en' }, { code: 'fr' }],
  messages: messagesFromGlob(import.meta.glob('../../locales/*.json', { eager: true })),
})

i18n.localizePath('/guide', 'fr')
// in theme enhanceApp:
i18n.enhanceApp({ app, router })
```

### Scripts Node — `@i18n-micro/vitepress/node` {#node-scripts-—-@i18n-micro/vitepress/node}

Utilise `createI18n` / `loadTranslations` de `@i18n-micro/node` (comme Astro et la CLI), puis ajoute les méthodes de chemin VitePress avec `BaseI18n.extend` :

```ts
import { createI18n } from '@i18n-micro/vitepress/node'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  translationDir: './locales',
  locales: ['en', 'fr'],
  defaultLocale: 'en',
})
await i18n.loadTranslations()
i18n.t('cta.readMore')
i18n.localizePath('/guide', 'fr')
```

Node pur, sans chemins : `import { createI18n } from '@i18n-micro/node'`.

## Traductions dans la page {#in-page-translations}

Chaque fichier markdown VitePress est un SFC Vue.

### Composants globaux et `$t` (recommandé dans le markdown) {#global-components-and-$t-recommended-in-markdown}

`createI18n` / `defineI18nTheme` installent `@i18n-micro/vue`, qui enregistre `I18nT` / `I18nLink` / `I18nGroup` / `I18nSwitcher` et `$t` / `$tc` / `$ts`.

```md
{{ $t('cta.readMore') }}

<I18nT keypath="greeting" :params="{ name: 'VitePress' }" />

<I18nLink to="/guide/demo">Demo</I18nLink>
```

### `useI18n` dans `<script setup>` {#usei18n-in-<script-setup>}

```md
<script setup>
import { useI18n } from '@i18n-micro/vitepress'
const { t, tc, locale, localePath, switchLocale } = useI18n()
</script>

# {{ t('section.title') }}
```

## Menu déroulant des langues {#language-dropdown}

Lorsque `locales` contient plus d'une entrée, VitePress affiche son propre menu des langues (`VPNavBarTranslations`). `withI18n` configure `themeConfig.i18nRouting` afin que le globe corresponde à `<I18nSwitcher>` et aux fonctions utilitaires de chemin.

Utilisez `<I18nSwitcher>` uniquement dans des mises en page personnalisées, et non à côté du globe par défaut.

## Remarques sur le SSR {#ssr-notes}

- Lors du prérendu, la locale provient du chemin de l'URL, et non des témoins.
- Le code du thème ne doit pas accéder à `window` au moment de l'importation.
- Importez `defineI18nTheme` depuis `/theme` afin que l'évaluation de la configuration dans Node ne charge jamais `virtual:i18n-micro/*`.

## Surface de l'API {#api-surface}

| Exportation | Rôle |
|--------|------|
| `createI18n` (`.`) | Client : plugin Vue + méthodes de chemin + `enhanceApp` |
| `getLocaleFromPath` / `stripSiteBase` / `routeNameFromPath` (`.`) | Synchronisation manuelle de la locale lorsque `syncWithVitePress: false` |
| `createI18n` (`/node`) | Node : `@i18n-micro/node` + méthodes de chemin |
| `defineI18nTheme` (`/theme`) | Thème sans code passe-partout |
| `withI18n` (`/config`) | Configuration + modules virtuels + SEO facultatif |
| `buildVitePressLocales` (`/config`) | Construit les `locales` de VitePress à partir de `Locale[]` |
| `buildVitePressLocaleHead` (`/config`) | En-tête SEO manuel (aussi utilisé par `metaBaseUrl`) |
| `messagesFromGlob` | Correspondance facultative glob → messages pour `createI18n` |
| `useI18n` / `I18nT` / … | Réexportés depuis `@i18n-micro/vue` |
| `BaseI18n.extend` (`@i18n-micro/core`) | Ajoute des méthodes personnalisées à n'importe quelle instance i18n |

## Sites de type OpenAPI (verrous d'intégration) {#openapi-style-sites-integration-locks}

Suite de tests de régression : `packages/vitepress/tests/integration-openapi.test.ts` (chemins profonds, `base=/openapi_docs/`, synchronisation désactivée + locale manuelle, générateurs Node, SEO).

| Cas | Marche à suivre |
|---------|---------|
| Pages profondes `/…/{spec}/{op}`, seulement le JSON d'interface racine | Préférez `syncWithVitePress: true` par défaut (conserve `setRoute('index')` en l'absence de dictionnaire de page) **ou** `syncWithVitePress: false` + `getLocaleFromPath` |
| N'appelez jamais `setRoute(deepName)` sans dictionnaires de page | Les clés d'interface racine disparaissent jusqu'à `setRoute('index')` |
| Générateurs / `getTranslation` | `createI18n` depuis `/node` + `await loadTranslations()` + `i18n.t(key)` (définissez `i18n.locale`) |
| Canonique personnalisée dans `transformPageData` | Passez `meta: false` à `withI18n` (évite les balises en double) |
| SEO du paquet avec une base de site | `metaBaseUrl` + `base` de VitePress → les URL absolues incluent la base |
| Renommages depuis d'anciennes versions du paquet | `withI18nMicro` → `withI18n`, `createVitePressI18n` → `createI18n`, `loadMessages` → `createI18n` de node |
