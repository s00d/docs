`@i18n-micro/solid` fournit aux applications SolidJS une instance i18n reposant sur des signaux, un fournisseur, `useI18n()` et quatre composants. Utilisez-le dans une application Solid qui n’est pas construite avec Nuxt. Les lectures de `t()` dans le JSX ou dans des effets suivent la langue, la route et les dictionnaires; le modèle commun est décrit dans [Frameworks](/fr-CA/integrations/overview).

## Installation {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Dépendances pair : `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (facultative, seulement pour `@i18n-micro/solid/router`). Solid 2 n’est pas encore pris en charge.

## Configuration {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` accepte `i18n`, `locales`, `defaultLocale` et `routingStrategy`; une prop omise conserve la valeur du fournisseur parent, y compris l’instance. `getLocaleName()` et `<I18nSwitcher>` lisent `locales`; sans elles, ils n’ont rien à afficher. Les options sont décrites dans [l’instance](/fr-CA/integrations/overview#the-instance). L’instance est celle du [runtime](/fr-CA/integrations/runtime-package), avec un signal sur son magasin.

## Traduire {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Appelez les méthodes dans le JSX ou dans un effet pour que Solid les suive, `localePath` et `getLocale` aussi; une valeur lue une seule fois dans le corps du composant ne se met pas à jour. Sur l’instance, suivez avec `i18n.locale` et `i18n.currentRoute` : `i18n.getLocale()` reste non réactive, car les écritures la lisent. La lecture de la langue ne réagit qu’à la langue, donc un effet qui la lit et charge un dictionnaire s’exécute une seule fois. Ne déstructurez pas les props et ne conservez pas les résultats de `t('key')` dans de simples variables.

`useI18n()` renvoie `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (un accesseur : `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` et `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Changer de langue {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Le changement de langue ne charge rien; ajoutez d’abord le dictionnaire de la langue.

`<I18nGroup>` transmet une fonction `t` préfixée à un enfant de type fonction. `<I18nT>` et `t()` à l’intérieur ne sont pas préfixés :

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Routage {#routing}

L’adaptateur `@solidjs/router` se trouve dans un sous-chemin, pour que le point d’entrée principal n’importe jamais le routeur. Appelez-le sous le routeur, généralement dans le `root` du routeur, où `useNavigate` et `useLocation` fonctionnent :

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

L’adaptateur préfixe toutes les langues sauf celle par défaut (`/about`, `/de/about`) et affiche `<I18nLink>` sous la forme du `<A>` du routeur. `getCurrentPath` lit l’emplacement réactif du routeur, de sorte que les liens actifs et le sélecteur de langue le suivent; une stratégie personnalisée obtient le même résultat en y lisant un signal. Notez l’ordre des arguments : `(locales, defaultLocale, navigate, location)`. Pour d’autres routeurs, écrivez un adaptateur avec `getCurrentPath`, `push` et `replace` (tous obligatoires) — consultez [Adaptateur de routeur](/fr-CA/integrations/overview#router-adapter).

## SSR {#ssr}

Pour le rendu côté serveur, compilez avec `vite-plugin-solid` : la condition d’export `solid` du paquet lui fournit le code source, qu’il compile ainsi pour le serveur. Le `dist` précompilé est destiné au navigateur seulement. L’instance n’a pas de `destroy()`; créez-en une par application, ou une par requête côté serveur, et laissez le ramasse-miettes s’en occuper.
