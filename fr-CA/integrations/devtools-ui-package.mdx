`@i18n-micro/devtools-ui` est l'éditeur de traductions de l'onglet Nuxt DevTools, empaqueté sous forme de composant Web avec un plugiciel Vite. Ajoutez-le à un projet Vue, React, Preact, Solid ou Astro pour parcourir et modifier depuis le navigateur, pendant le développement, les fichiers JSON de votre dossier de traductions. Les applications Nuxt l'ont déjà dans [Nuxt DevTools](/fr-CA/guide/devtools).

![L'interface DevTools : une arborescence de fichiers et un éditeur affichant le texte de la locale par défaut à côté de chaque clé](/images/devtools/02-translations-editor-dark.webp)

## Installation {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/devtools-ui
```

```bash npm
npm install -D @i18n-micro/devtools-ui
```

```bash yarn
yarn add -D @i18n-micro/devtools-ui
```

</CodeGroup>

Aucune dépendance homologue.

## Configuration {#setup}

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import { i18nDevToolsPlugin } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  plugins: [i18nDevToolsPlugin({ translationDir: 'src/locales' })],
})
```

| Option | Valeur par défaut | Remarques |
| --- | --- | --- |
| `translationDir` | `'src/locales'` | Dossier contenant les fichiers JSON, relatif à la racine Vite. |
| `base` | `'/__i18n_api'` | Chemin de base des points de terminaison de l'API. |
| `injectButton` | `true` | Ajoute un bouton flottant aux pages servies par la transformation `index.html` de Vite. Astro n'a pas de telles pages : voir plus bas. |
| `defaultLocale` | premier fichier de locale dans `translationDir` | Renvoyée par `/config`. |
| `fallbackLocale` | `defaultLocale` | Renvoyée par `/config`. |

Le plugiciel s'exécute uniquement sur le serveur de développement (`apply: 'serve'`); un build de production n'en contient rien. Le bouton ouvre `/__i18n_devtools.html`, qui lit et enregistre les fichiers au moyen des points de terminaison du plugiciel :

| Point de terminaison | Rôle |
| --- | --- |
| `GET <base>/translations` | chaque dictionnaire sous `translationDir`, par chemin relatif |
| `POST <base>/save` | corps `{ file, content }`; écrase un `.json` existant dans `translationDir`, 403 pour tout le reste. Ne crée jamais de fichier |
| `GET <base>/config` | `{ defaultLocale, fallbackLocale, locales, translationDir }`; `locales` provient des fichiers racine de `translationDir` |

Les points de terminaison ne répondent qu'à la page des devtools : une requête provenant d'une autre origine ou d'un autre hôte reçoit un `403`, et `/save` n'accepte que `application/json` (`415`). La page est informée des modifications de fichiers par le socket HMR de Vite.

Dans Astro, ajoutez l'intégration plutôt que le plugiciel. Elle ajoute une application à la barre d'outils de développement :

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import { i18nDevToolsIntegration } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  integrations: [i18nDevToolsIntegration({ translationDir: 'src/locales' })],
})
```

L'enregistrement ne fait qu'écrire le fichier. Une application qui importe le JSON par Vite le reçoit par HMR; pour que les modifications s'appliquent directement à l'instance en cours d'exécution, utilisez un pont.

## Pont vers une instance active {#bridge-to-a-live-instance}

Pour intégrer l'éditeur dans votre propre page et appliquer immédiatement les modifications à l'instance en cours d'exécution, créez un pont à partir d'un adaptateur et passez-le à l'élément `<i18n-devtools-ui>` :

```ts
import { createBridge, register } from '@i18n-micro/devtools-ui'
import { i18n, locales } from './i18n' // a runtime, React, Preact or Solid instance

register() // defines <i18n-devtools-ui> once

const bridge = createBridge({
  adapter: {
    getRouteCache: () => Object.fromEntries(i18n.storage.translations),
    addTranslations: (locale, content, merge) => i18n.addTranslations(locale, content, merge),
    addRouteTranslations: (locale, route, content, merge) => i18n.addRouteTranslations(locale, route, content, merge),
    subscribe: (cb) => i18n.subscribe(cb),
    getCurrentLocale: () => i18n.locale,
  },
  locales,
  defaultLocale: 'en',
  translationDir: 'src/locales',
})

const el = document.createElement('i18n-devtools-ui') as HTMLElement & { bridge: typeof bridge }
el.bridge = bridge
document.body.append(el)
```

`getRouteCache` doit renvoyer les dictionnaires indexés par `locale:route` (`en:index`, `en:blog-post`), ce que contient justement `i18n.storage.translations`. Pour une instance Vue, utilisez `i18n.global.getRouteCache()` et `i18n.global.subscribeToChanges(cb)`.

`saveTranslation` met d'abord à jour l'instance, puis envoie un POST à `<base>/save`. Lorsqu'il n'y a pas de point de terminaison (un build d'aperçu statique) ou que le serveur de développement est injoignable, la modification est conservée dans `localStorage`; toute autre erreur d'enregistrement rétablit le dictionnaire précédent et lève une exception.

## API {#api}

| Exportation | Point d'entrée |
| --- | --- |
| `i18nDevToolsPlugin(options)`, `i18nDevToolsIntegration(options)` | `@i18n-micro/devtools-ui/vite` |
| `register()`, `I18nDevToolsElement` | `@i18n-micro/devtools-ui` |
| `createBridge(options)`, types `BridgeAdapter`, `CreateBridgeOptions` | `@i18n-micro/devtools-ui` (aussi `/bridge/create`) |
| type `I18nDevToolsBridge` | `@i18n-micro/devtools-ui` (aussi `/bridge`) |
| `createRpcClient`, `setupRpcHost` | `@i18n-micro/devtools-ui` |

Signatures complètes : [référence du paquet](/fr-CA/api/packages/devtools-ui).
