# 🔧 Générateur de types (`@i18n-micro/types-generator`)

Le paquet `@i18n-micro/types-generator` fournit la génération automatique de types TypeScript pour les clés de traduction. Il analyse vos fichiers JSON de traduction et génère des types stricts, offrant une sécurité de types complète et le support de l'autocomplétion pour les clés de traduction.

## 📖 Aperçu

`@i18n-micro/types-generator` est une dépendance de développement facultative qui améliore votre expérience de développement en :

- 🔍 **Génération automatique de types** : analyse les fichiers JSON de traduction et génère des types TypeScript
- ✅ **Sécurité des types** : empêche les fautes de frappe et les clés de traduction invalides à la compilation
- 🎯 **Support d'autocomplétion** : autocomplétion IDE complète pour les clés de traduction
- 🔄 **Rechargement à chaud** : régénère automatiquement les types quand les fichiers de traduction changent
- 🚀 **Aucun surcoût à l'exécution** : les types sont uniquement à la compilation, aucun impact sur la taille du bundle

## 🎯 Démarrage rapide

### Pour les projets Nuxt

Ajoutez le module à votre `nuxt.config.ts` :

```typescript
import { defineNuxtConfig } from 'nuxt/config'

export default defineNuxtConfig({
  modules: [
    'nuxt-i18n-micro',
    '@i18n-micro/types-generator/nuxt', // Add types generator
  ],
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    translationDir: 'locales', // Path to your translation files
  },
})
```

Le générateur va automatiquement :

- Analyser tous les fichiers JSON dans votre répertoire `locales`
- Générer les types dans `.nuxt/i18n-micro.d.ts`
- Surveiller les changements et régénérer les types automatiquement

### Pour les projets Vue/Vite

Ajoutez le plugin à votre `vite.config.ts` :

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { I18nTypesPlugin } from '@i18n-micro/types-generator'

export default defineConfig({
  plugins: [
    vue(),
    I18nTypesPlugin({
      srcDir: 'src',
      translationDir: 'locales',
      outputFile: 'src/i18n-types.d.ts', // Optional: custom output path
    }),
  ],
})
```

Assurez-vous d'inclure le fichier généré dans votre `tsconfig.json` :

```json
{
  "include": ["src/**/*", "src/i18n-types.d.ts"]
}
```

## 📁 Structure des fichiers de traduction

Le générateur prend en charge les structures de traduction à plat et imbriquées :

```
locales/
  en.json
  fr.json
  pages/
    home/
      en.json
      fr.json
    about/
      en.json
      fr.json
```

**Exemple `locales/en.json` :**

```json
{
  "greeting": "Hello, {name}!",
  "header": {
    "title": "Welcome",
    "subtitle": "Subtitle"
  },
  "errors": {
    "404": "Not found",
    "500": "Server error"
  },
  "apples": "no apples | one apple | {count} apples"
}
```

Le générateur créera des types pour toutes les clés, y compris imbriquées :

```typescript
// Generated types
declare module '@i18n-micro/types' {
  export interface DefineLocaleMessage {
    greeting: string
    'header.title': string
    'header.subtitle': string
    'errors.404': string
    'errors.500': string
    apples: string
  }
}
```

## 💡 Utilisation

Une fois les types générés, vous obtenez une sécurité de types complète :

```typescript
import { useI18n } from '@i18n-micro/vue'

const { t } = useI18n()

// ✅ Type-safe: autocomplete works
t('greeting', { name: 'World' })
t('header.title')
t('errors.404')

// ❌ Type error: key doesn't exist
t('invalid.key') // Error: Argument of type '"invalid.key"' is not assignable
```

### Note propre à Nuxt

**Dans les projets Nuxt, la sécurité des types fonctionne uniquement avec le composable `useI18n`.** Les types générés sont appliqués à la valeur de retour du composable, garantissant la sécurité des types lors de l'utilisation des méthodes `t()`, `ts()`, `tc()` et `has()`.

```typescript
// ✅ Correct: Using useI18n composable
<script setup lang="ts">
import { useI18n } from '#imports'

const { t } = useI18n()
t('greeting') // Type-safe with autocomplete
</script>

// ❌ Not type-safe: Direct access to $i18n or other methods
// Type safety is only available through the useI18n composable
```

## 🔄 Clés dynamiques

Parfois, vous avez besoin d'utiliser des clés dynamiques (par exemple, basées sur l'entrée utilisateur ou les réponses d'API). Le générateur fournit un type utilitaire `ScopedKey` pour une utilisation sécurisée des clés dynamiques.

### Pourquoi pas de gardes de type à l'exécution ?

**Les gardes de type à l'exécution ne sont pas recommandés** pour i18n-micro parce que :

1. **Taille du bundle** : générer un tableau JavaScript de toutes les clés gonflerait votre bundle
2. **Performance** : les vérifications à l'exécution ajoutent un surcoût inutile
3. **Philosophie** : i18n-micro est conçu pour être léger et rapide

### La méthode TypeScript : assertions de type

Pour les clés dynamiques, utilisez l'assertion de type TypeScript :

```typescript
import type { TranslationKey, ScopedKey } from '@i18n-micro/types'

// ❌ Type error: dynamic key
const status = 'pending'
t(`status.${status}`) // Error: string is not assignable to TranslationKey

// ✅ Solution 1: Type assertion (if you're sure the key exists)
t(`status.${status}` as TranslationKey)

// ✅ Solution 2: ScopedKey helper (safer, checks prefix exists)
function getStatusText(status: string) {
  return t(`status.${status}` as ScopedKey<'status'>)
  // TypeScript verifies that keys starting with 'status.' exist
}

// ✅ Solution 3: Runtime check with has()
if (has(`status.${status}`)) {
  t(`status.${status}` as TranslationKey)
}
```

### Assistant ScopedKey

Le type `ScopedKey<Scope>` vous permet de restreindre les clés dynamiques par préfixe :

```typescript
import type { ScopedKey } from '@i18n-micro/types'

// Assuming you have keys: 'errors.404', 'errors.500', 'btn.save'

function getErrorText(code: string) {
  // ✅ Safer than plain TranslationKey
  // TypeScript verifies that 'errors.*' keys exist
  return t(`errors.${code}` as ScopedKey<'errors'>)
}

// ❌ Type error: 'btn' prefix doesn't match 'errors'
function getErrorTextWrong(code: string) {
  return t(`errors.${code}` as ScopedKey<'btn'>) // Error
}
```

## 🎨 Utilisation avancée

### Gestion des traductions propres aux routes

Le générateur inclut automatiquement les clés des fichiers de traduction propres aux routes :

```
locales/
  en.json                    # Root-level translations
  pages/
    home/
      en.json               # Route-specific translations
    about/
      en.json
```

Toutes les clés des fichiers à la racine et propres aux routes sont incluses dans les types générés.

### Désactiver les langues de page

Si vous utilisez `disablePageLocales: true` dans votre configuration i18n, le générateur traitera tous les fichiers (y compris ceux dans `pages/`) comme des traductions à la racine.

## 🐛 Dépannage

### Les types ne se mettent pas à jour

1. **Vérifiez les chemins de fichiers** : assurez-vous que `translationDir` pointe vers le bon répertoire
2. **Redémarrez le serveur TypeScript** : dans VS Code, `Cmd/Ctrl + Maj + P` → « TypeScript: Restart TS Server »
3. **Vérifiez tsconfig.json** : assurez-vous que le fichier généré est inclus

### Erreurs de type après l'ajout de clés

1. **Régénérez les types** : le générateur devrait auto-régénérer, mais vous pouvez le déclencher manuellement
2. **Vérifiez la syntaxe JSON** : les fichiers JSON invalides sont ignorés avec un avertissement
3. **Redémarrez le serveur dev** : parfois nécessaire pour que les changements prennent effet

### L'autocomplétion ne fonctionne pas

1. **Vérifiez l'inclusion du fichier** : assurez-vous que le fichier `.d.ts` généré est dans l'`include` de votre `tsconfig.json`
2. **Vérifiez l'augmentation de module** : assurez-vous que le fichier généré utilise `declare module '@i18n-micro/types'`
3. **Version de TypeScript** : requiert TypeScript 4.1+ pour les types de littéraux de modèle

## 📚 Référence de l'API

### `generateTypes(options: GeneratorOptions)`

Génère manuellement les types (utile pour les scripts ou l'IC) :

```typescript
import { generateTypes } from '@i18n-micro/types-generator'

await generateTypes({
  srcDir: './src',
  translationDir: 'locales',
  outputFile: './src/i18n-types.d.ts',
})
```

### `flattenKeys(obj: Record<string, unknown>, prefix?: string)`

Fonction utilitaire pour aplatir les objets de traduction imbriqués :

```typescript
import { flattenKeys } from '@i18n-micro/types-generator'

const keys = flattenKeys({
  header: { title: 'Title' },
  footer: { copyright: 'Copyright' },
})
// Returns: ['header.title', 'footer.copyright']
```

## 🔍 Comment ça fonctionne

1. **Analyse** : utilise `globby` pour trouver tous les fichiers `**/*.json` dans le répertoire de traductions
2. **Parsing** : analyse chaque fichier JSON et extrait toutes les clés en aplatissant récursivement
3. **Déduplication** : combine les clés de tous les fichiers dans un ensemble unique
4. **Génération** : crée un fichier `.d.ts` avec une augmentation `declare module`
5. **Surveillance** : en mode dev, surveille les changements de fichiers et régénère les types

Le fichier généré utilise l'augmentation de module TypeScript pour étendre `DefineLocaleMessage` dans `@i18n-micro/types`, ce qui met automatiquement à jour le type `TranslationKey` dans tout votre projet.

## 🎯 Bonnes pratiques

1. **Gardez les traductions organisées** : utilisez des objets imbriqués pour les clés liées
2. **Utilisez un nommage cohérent** : suivez une convention de nommage (par exemple, `errors.*`, `buttons.*`)
3. **Tirez parti de ScopedKey** : utilisez `ScopedKey` pour les clés dynamiques plutôt que des assertions simples
4. **Vérifiez les types en IC** : exécutez la vérification des types dans votre pipeline d'IC
5. **N'éditez pas les fichiers générés** : le fichier `.d.ts` est auto-généré et sera écrasé
