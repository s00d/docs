`@i18n-micro/react` et `@i18n-micro/preact` enveloppent le [runtime](/fr-CA/integrations/runtime-package) indépendant du framework dans un fournisseur, un hook `useI18n()` et quatre composants. Utilisez-les dans une application React ou Preact qui n’est pas construite avec Nuxt. Les deux paquets ont la même API; la section [Preact](#preact) énumère les quelques différences, et le modèle commun est décrit dans [Frameworks](/fr-CA/integrations/overview).

## Installation {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/react
```

```bash npm
npm install @i18n-micro/react
```

```bash yarn
yarn add @i18n-micro/react
```

</CodeGroup>

Dépendances pair : `react` `^18.0.0 || ^19.0.0`; `react-dom` (facultative, pour le rendu); `react-router-dom` `^6.0.0 || ^7.0.0` (facultative, seulement pour `@i18n-micro/react/router`). Testé avec React 19.3 et 18.3, React Router 7.18 et 6.30.

## Configuration {#setup}

```tsx
// src/main.tsx
import { createRoot } from 'react-dom/client'
import { createI18n, I18nProvider } from '@i18n-micro/react'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

createRoot(document.getElementById('root')!).render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
    <App />
  </I18nProvider>,
)
```

<Warning>

Créez l’instance une seule fois, au niveau du module ou dans un initialiseur `useState`, jamais dans le corps d’un composant.

</Warning>

`<I18nProvider>` accepte `i18n`, `locales`, `defaultLocale` et `routingStrategy` :

- Une prop omise conserve la valeur d’un fournisseur parent, y compris l’instance.
- S’il n’y a aucune instance, il en construit une à partir des options de `createI18n` passées à côté, de sorte que les props restent de simples données : `<I18nProvider locale="de" messages={messages}>`.
- Une nouvelle prop `locale` construit une nouvelle instance avec les `messages` de ce rendu. Une telle instance vit dans le composant : si un élément au-dessus suspend pendant le montage, React la jette, avec tout ce qui y a été ajouté.

Toutes les options de `createI18n`, y compris `routeMessages`, sont décrites dans [l’instance](/fr-CA/integrations/overview#the-instance).

## Traduire {#translate}

```tsx
import { useI18n } from '@i18n-micro/react'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' })}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

`useI18n()` renvoie :

| Groupe | Membres |
| --- | --- |
| Traduction | `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` |
| Langue et route | `locale`, `fallbackLocale`, `currentRoute`, `setLocale`, `setRoute`, `getRoute`, `getLocales`, `defaultLocale()`, `getLocaleName` |
| Routage | `switchLocale`, `localePath`, `localeRoute` |
| Dictionnaires | `addTranslations`, `addRouteTranslations`, `clearCache` |

- Le composant est rendu de nouveau lorsque la langue, la route ou un dictionnaire lisible change, et lorsque le fournisseur reçoit un nouvel objet `locales` ou `routingStrategy`. Un dictionnaire d’une langue qui n’est ni active ni de repli ne provoque aucun rendu.
- `t` et les autres méthodes de traduction ne changent qu’avec le magasin; elles peuvent donc être utilisées sans danger dans `memo` et dans les dépendances d’effets.

`useT` fournit une seule chaîne comme valeur. Le composant n’est rendu que lorsque cette chaîne change, quoi qu’il arrive aux autres props du fournisseur; `<I18nT>` n’en dépend pas non plus :

```tsx
const title = useT('page.title')
```

Chargez d’autres dictionnaires à tout moment :

```tsx
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

useEffect(() => {
  import('./locales/de.json').then((m) => addTranslations('de', m.default))
  addRouteTranslations('en', 'about', { title: 'About us' })
  setRoute('about') // t('title') now reads the 'about' dictionary first
}, [])
```

L’instance elle-même dispose aussi de `loadFromUrl(url, { locale, routeName })` pour charger du JSON au moyen de `fetch`.

## Changer de langue {#switch-locale}

```tsx
const { setLocale, switchLocale } = useI18n()

setLocale('de') // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Le changement de langue ne charge rien; ajoutez d’abord le dictionnaire de la langue. Une écriture dans le magasin est synchrone pour React, même dans `startTransition`; un composant qui suspend en raison d’un dictionnaire manquant afficherait donc son contenu de repli. `useLocaleSwitch` charge d’abord et conserve l’ancienne interface jusqu’à ce que le dictionnaire soit chargé :

```tsx
const [switchTo, pending] = useLocaleSwitch((locale) => i18n.loadFromUrl(`/locales/${locale}.json`, { locale }))

<button disabled={pending} onClick={() => switchTo('de')}>Deutsch</button>
```

Le dernier appel l’emporte. Un chargement qui échoue est rejeté et laisse la langue inchangée.

`<I18nGroup>` transmet une fonction `t` préfixée à un enfant de type render prop. `<I18nT>` et `t()` à l’intérieur ne sont pas préfixés :

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Routage {#routing}

L’adaptateur React Router se trouve dans un sous-chemin, pour que le point d’entrée principal n’importe jamais `react-router-dom`. Il a besoin de `useLocation()` et de `useNavigate()`; créez-le donc dans un composant placé sous le routeur :

```tsx
// src/App.tsx
import { useMemo } from 'react'
import { BrowserRouter, Route, Routes, useLocation, useNavigate } from 'react-router-dom'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/react'
import { createReactRouterAdapter } from '@i18n-micro/react/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Localized() {
  const location = useLocation()
  const navigate = useNavigate()
  // memoized: a new object on every render re-renders every `useI18n()` consumer
  const routingStrategy = useMemo(() => createReactRouterAdapter(locales, 'en', location, navigate), [location, navigate])
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      <Routes>
        <Route path="/:locale?" element={<Home />} />
        <Route path="/:locale?/about" element={<About />} />
      </Routes>
    </I18nProvider>
  )
}

export default function App() {
  return (
    <BrowserRouter>
      <Localized />
    </BrowserRouter>
  )
}
```

L’adaptateur préfixe toutes les langues sauf celle par défaut (`/about`, `/de/about`) et affiche `<I18nLink>` sous la forme du `<Link>` de React Router. Définissez vous-même la langue à partir de l’URL (par exemple à partir de `useParams().locale` dans un effet). Pour tout autre routeur, écrivez un adaptateur avec `getCurrentPath`, `push` et `replace` (tous obligatoires) — consultez [Adaptateur de routeur](/fr-CA/integrations/overview#router-adapter).

## SSR {#ssr}

`renderToString` fonctionne : `useI18n()` dispose d’un instantané serveur. Créez une instance par requête et ajoutez-y ses dictionnaires avant le rendu, pour que les requêtes dans des langues différentes ne partagent pas d’état, ou transmettez de simples données au fournisseur.

### Hydratation {#hydration}

Les nombres, les pluriels et le texte s’hydratent tels quels. Une date dépend du fuseau horaire et une date relative dépend de l’horloge : définissez `timeZone` sur le serveur et dans le navigateur, et pour `tdr`, transmettez au navigateur l’heure du serveur avec `now`. `<I18nT>` avec `date` ou `relativeDate` définit `suppressHydrationWarning`, de sorte qu’une différence ne fait pas échouer l’hydratation, mais le texte du serveur reste affiché jusqu’à ce que le texte change. Cela ne s’applique qu’à un seul niveau : des `children` qui enveloppent la traduction dans un élément échouent quand même en cas de différence; donnez-leur donc le même `timeZone`.

### Server Components {#server-components}

Le paquet marque son code client avec `'use client'`. `@i18n-micro/react/server` fournit `createI18n` et un `I18nT` sans hooks qui reçoit l’instance en prop, de sorte que le texte reste hors du bundle client. Avec la condition `react-server`, comme dans l’App Router de Next.js, le point d’entrée principal y est aussi résolu, mais TypeScript ne le sait pas par défaut : importez depuis `/server`. `@i18n-micro/react/client` donne toujours le point d’entrée client.

```tsx
// app/[locale]/layout.tsx: a server component
import { cache } from 'react'
import { createI18n, I18nT } from '@i18n-micro/react/server'
import { I18nProvider } from '@i18n-micro/react/client'
import { loadMessages } from './messages'

const getI18n = cache(async (locale: string) => createI18n({ locale, messages: await loadMessages(locale) }))

export default async function Layout({ params, children }) {
  const { locale } = await params
  const i18n = await getI18n(locale)
  return (
    <I18nProvider locale={locale} messages={{ [locale]: i18n.resolveTranslations() }}>
      <h1>
        <I18nT i18n={i18n} keypath="title" />
      </h1>
      {children}
    </I18nProvider>
  )
}
```

Rendu au moyen de `react-server-dom-webpack`; cela n’a pas été testé dans une véritable application Next.js.

## Preact {#preact}

`@i18n-micro/preact` est construit à partir du même code source, sur Preact lui-même, sans `preact/compat` : même instance, même fournisseur, mêmes hooks et mêmes composants. Différences :

| | React | Preact |
| --- | --- | --- |
| Dépendance pair | `react` (+ `react-router-dom` facultatif) | `preact` `^10.0.0 \|\| ^11.0.0`, testé avec 10.29 et 11.1 |
| Classe de l’instance | `ReactI18n` | `PreactI18n` |
| Adaptateur de routeur | `createReactRouterAdapter` depuis `/router` | `createBrowserHistoryAdapter(locales, defaultLocale, ssrUrl?)` depuis `/router` |
| Nouveau rendu | `useSyncExternalStore` | un abonnement dans un layout effect qui revérifie le magasin |
| Server Components | `/server`, `/client` | aucun |

`createBrowserHistoryAdapter` fonctionne avec tout routeur basé sur l’API History (wouter, preact-router) : `push` et `replace` appellent `history.pushState` / `replaceState` et déclenchent `popstate`, et `<I18nLink>` affiche un simple `<a>` qui navigue au moyen de `push`. Un serveur n’a pas de barre d’adresse : transmettez l’URL de la requête dans `ssrUrl`, sinon les liens et le sélecteur de langue sont rendus comme sur `/`. Dans un navigateur, la barre d’adresse l’emporte.

```tsx
// src/main.tsx
import { render } from 'preact'
import { createI18n, I18nProvider } from '@i18n-micro/preact'
import { createBrowserHistoryAdapter } from '@i18n-micro/preact/router'
import { App } from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={createBrowserHistoryAdapter(locales, 'en')}>
    <App />
  </I18nProvider>,
  document.getElementById('app')!,
)
```
