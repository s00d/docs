# Remplacements i18n à l'exécution

Utilisez ce guide lorsque vous avez besoin qu'un même artefact de compilation s'exécute avec des valeurs de langue par défaut différentes selon l'environnement (par exemple : différentes instances de locataires).

## Ce qui peut être remplacé à l'exécution

Le module prend en charge des remplacements sûrs à l'exécution pour :

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Ces remplacements sont appliqués par-dessus la configuration issue de la compilation dans `.nuxt/i18n.strategy.mjs` et `.nuxt/i18n.config.mjs`.

## Ce qui ne peut pas être remplacé à l'exécution

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) est une préoccupation à la compilation, car cela influe sur le comportement des routes générées.

Si vous passez un remplacement de stratégie à l'exécution, il est ignoré et un avertissement est émis.

## Remplacements via RuntimeConfig

Fournissez les valeurs d'exécution sous `runtimeConfig.public.i18nRuntime` :

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Remplacements via variables d'environnement

Vous pouvez aussi configurer les remplacements via des variables d'environnement :

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (séparées par des virgules, p. ex. `fr,it`)

Des alias de repli sont aussi pris en charge :

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Règles de validation

À l'exécution, le module valide les remplacements afin d'éviter un état incohérent :

- Vous ne pouvez pas désactiver toutes les langues.
- `defaultLocale` doit pointer vers une langue activée.
- `fallbackLocale` doit exister dans les langues déclarées.

Si un remplacement est invalide, le module conserve une valeur sûre et journalise un avertissement.

## Notes pour les déploiements multi-instances

Cette fonctionnalité d'exécution est conçue pour l'activation et les valeurs par défaut de langues par instance sans avoir à recompiler.

Si des instances nécessitent des stratégies d'URL différentes (`no_prefix` vs `prefix`), utilisez des compilations séparées pour chaque stratégie.

## Langues désactivées et charges utiles statiques

`runtimeConfig.public.i18nRuntime.disabledLocales` met à jour le routage, le sélecteur et le **gestionnaire** de charge utile Nitro — mais Nitro sert les fichiers sous `public/` **avant** ce gestionnaire.

Si `translationPayloads.publicAssets` (ou la copie forcée dans `public/` du SSR Node) a déjà écrit `/_locales/\{page\}/\{locale\}/data.json`, une désactivation à l'exécution ne peut pas masquer ce fichier. Préférez `locale.disabled: true` à la compilation afin que le prémerge n'émette pas les charges utiles statiques de cette langue.
