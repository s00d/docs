# Surcharges i18n à l'exécution

Utilisez ce guide lorsque vous avez besoin qu'un même artefact de compilation s'exécute avec différentes valeurs par défaut de langue selon l'environnement (par exemple, différentes instances par client).

## Ce qui peut être surchargé à l'exécution

Le module prend en charge les surcharges d'exécution sûres pour :

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Ces surcharges sont appliquées par-dessus la configuration de compilation issue de `.nuxt/i18n.strategy.mjs` et `.nuxt/i18n.config.mjs`.

## Ce qui ne peut pas être surchargé à l'exécution

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) est une préoccupation de compilation puisqu'elle affecte le comportement des routes générées.

Si vous passez une surcharge de stratégie à l'exécution, elle est ignorée et un avertissement est émis.

## Surcharges via RuntimeConfig

Fournissez les valeurs d'exécution sous `runtimeConfig.public.i18nRuntime` :

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Surcharges par variables d'environnement

Vous pouvez aussi configurer les surcharges via des variables d'environnement :

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (séparées par des virgules, par exemple `fr,it`)

Des alias de repli sont aussi pris en charge :

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Règles de validation

À l'exécution, le module valide les surcharges pour éviter un état cassé :

- Vous ne pouvez pas désactiver toutes les langues.
- `defaultLocale` doit pointer vers une langue activée.
- `fallbackLocale` doit exister dans les langues déclarées.

Si une surcharge est invalide, le module conserve une valeur sûre et journalise un avertissement.

## Notes pour les déploiements multi-instances

Cette fonctionnalité d'exécution est conçue pour l'activation et les valeurs par défaut de langue par instance, sans recompiler.

Si des instances requièrent différentes stratégies d'URL (`no_prefix` vs `prefix`), utilisez des compilations distinctes pour chaque stratégie.

## Langues désactivées et charges utiles statiques

`runtimeConfig.public.i18nRuntime.disabledLocales` met à jour le routage, le sélecteur et le **gestionnaire** de charge utile Nitro. Toutefois, Nitro sert les fichiers sous `public/` **avant** ce gestionnaire.

Si `translationPayloads.publicAssets` (ou la copie publique forcée pour le SSR Node) a déjà écrit `/_locales/\{page\}/\{locale\}/data.json`, une désactivation à l'exécution ne peut pas cacher ce fichier. Préférez `locale.disabled: true` à la compilation afin que la préfusion n'émette pas les charges utiles statiques de cette langue.
