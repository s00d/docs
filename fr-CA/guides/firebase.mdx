# 🔥 Déploiement sur Firebase AppHosting

## 📖 Introduction

Firebase AppHosting est une plateforme puissante pour déployer des applications Nuxt avec une infrastructure sans serveur. Toutefois, en déployant des applications avec `nuxt-i18n-micro`, vous pouvez rencontrer des problèmes spécifiques liés à la façon dont les fichiers JSON de traduction sont servis. Ce guide fournit des solutions complètes pour garantir que vos traductions fonctionnent correctement en production.

## ⚠️ Problèmes courants

### Fichiers de traduction non appliqués

**Symptômes :**

- ✅ Les traductions fonctionnent parfaitement en développement (`nuxt dev`)
- ❌ Après déploiement sur Firebase AppHosting, les fichiers JSON se chargent mais les traductions ne s'appliquent pas
- ❌ Aucune erreur n'apparaît dans la console
- ❌ Les fichiers de traduction sont visibles dans l'onglet Réseau mais ont un `Content-Type: text/html` incorrect au lieu de `application/json`

**Cause principale :**

Firebase AppHosting (et d'autres plateformes utilisant le pré-rendu Nitro) peut servir les fichiers JSON pré-rendus avec des types MIME incorrects. Lorsque le navigateur reçoit des fichiers JSON avec `Content-Type: text/html`, il ne peut pas les analyser correctement, ce qui fait échouer les traductions silencieusement.

## ✅ Solutions

### Solution 1 : configuration des règles de routes (recommandé)

La solution la plus directe est d'ajouter des en-têtes explicites pour les routes de traduction dans votre `nuxt.config.ts` :

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**Avantages :**

- ✨ Configuration simple
- 🚀 Améliore la performance avec une mise en cache appropriée
- 🔒 Fonctionne sur toutes les plateformes de déploiement

### Solution 2 : URL de base d'API personnalisée

Si vous utilisez un `apiBaseUrl` personnalisé (préfixe de chemin uniquement), ajustez les règles de routes en conséquence :

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### Solution 3 : configuration propre à Firebase

Créez ou mettez à jour votre fichier `firebase.json` à la racine du projet :

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```


### Solution 4 : configuration des Firebase Functions

Pour un déploiement Firebase Functions, assurez-vous que votre `functions/package.json` inclut les dépendances nécessaires :

```json
{
  "name": "functions",
  "type": "module",
  "engines": {
    "node": "18"
  },
  "dependencies": {
    "firebase-admin": "^12.0.0",
    "firebase-functions": "^5.0.0"
  }
}
```

## 🔍 Débogage

### Activer le mode débogage

Ajoutez la journalisation de débogage pour identifier les problèmes :

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

Cela affichera des journaux détaillés sur :

- 📝 Le chargement des fichiers de traduction
- 🔄 Les opérations de cache
- ⚠️ Les erreurs de chargement

### Vérifier l'onglet Réseau

1. Ouvrez les DevTools → onglet Réseau
2. Filtrez par « data.json »
3. Cliquez sur une requête de fichier de traduction
4. Vérifiez les **en-têtes de réponse** :
   - ✅ `Content-Type: application/json` (correct)
   - ❌ `Content-Type: text/html` (incorrect, à corriger)

### Vérifier la sortie du pré-rendu

Après la compilation, vérifiez que les fichiers de traduction sont générés :

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

Vous devriez voir `data.json` pour chaque langue sous chaque page.

## 🚀 Configuration de compilation

### Préréglage Nitro

Pour Firebase AppHosting, assurez-vous d'utiliser le bon préréglage :

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### Configuration du pré-rendu

Configurez le pré-rendu pour une performance optimale :

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

    strategy: 'prefix_except_default',

## ✅ Liste de vérification

Après avoir appliqué les correctifs, vérifiez que tout fonctionne :

- [ ] La compilation se termine sans erreur
- [ ] Les fichiers JSON de traduction sont dans `.output/public/_locales/\{page\}/\{locale\}/data.json`
- [ ] L'onglet Réseau montre `Content-Type: application/json` pour les fichiers de traduction
- [ ] Les traductions s'affichent correctement au premier chargement de page
- [ ] Aucun décalage d'hydratation dans la console
- [ ] Le changement de langue fonctionne correctement
- [ ] Les balises meta SEO sont générées correctement

## 🔄 Flux de déploiement

### 1. Préparer la compilation

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. Déployer sur Firebase

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. Vérifier le déploiement

1. Visitez votre site déployé
2. Ouvrez les DevTools → onglet Réseau
3. Naviguez vers une page
4. Vérifiez que `/_locales/index/en/data.json` (ou votre langue par défaut) se charge avec :
   - Statut : 200
   - Content-Type : application/json
   - Réponse contenant un JSON valide

## 🔧 Dépannage

### Problème : erreurs 404 pour les fichiers de traduction

**Solution :** assurez-vous que les fichiers de traduction sont copiés dans le répertoire de sortie :

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### Problème : les traductions fonctionnent sur certaines pages mais pas sur d'autres

**Solution :** vérifiez que les traductions propres aux pages sont générées :

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

Si les traductions propres aux pages sont absentes, assurez-vous que `disablePageLocales` n'est pas défini à `true` :

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### Problème : chargement lent des traductions

**Solution :** optimisez la mise en cache et le préchargement :

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## ⚡ Optimisation de la performance

### Activer la compression

Firebase gère automatiquement la compression Gzip/Brotli, mais assurez-vous que votre compilation est optimisée :

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### Chargement paresseux des traductions

`Nuxt I18n Micro` charge automatiquement les traductions à la demande, par page. Les traductions sont chargées uniquement lorsque nécessaire, réduisant la taille initiale du bundle. C'est une fonctionnalité intégrée, aucune configuration supplémentaire n'est requise.

Pour optimiser davantage :

- Utilisez `disablePageLocales: false` (par défaut) pour activer les traductions propres aux pages
- Gardez les traductions à la racine minimales
- Utilisez des fichiers de traduction propres aux routes pour le contenu de page

<Tip>
Le module définit automatiquement les bons en-têtes `Content-Type` à partir de la version **v3.0.0+**. Si vous rencontrez des problèmes, mettez à jour vers la dernière version :

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
