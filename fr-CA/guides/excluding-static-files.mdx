# Exclure les fichiers statiques du routage i18n

## Aperçu

Par défaut, nuxt-i18n-micro exclut automatiquement les fichiers statiques courants du traitement du routage i18n. Cependant, vous pouvez aussi configurer des motifs d'exclusion personnalisés pour empêcher le traitement de chemins précis par le système i18n.

## Exclusions intégrées

Le module exclut automatiquement les types de fichiers et motifs suivants :

- **Plans de site** : `/sitemap*.xml`, `/sitemap-en.xml`, etc.
- **Fichiers SEO** : `/robots.txt`, `/favicon.ico`
- **Fichiers PWA** : `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Ressources statiques** : les fichiers avec des extensions comme `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Chemins internes Nuxt** : tout chemin commençant par `__` (comme `/__nuxt/`)

## Motifs d'exclusion personnalisés

Vous pouvez définir des motifs d'exclusion personnalisés en utilisant l'option `excludePatterns` :

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Types de motifs

### Motifs sous forme de chaîne

- **Correspondance exacte** : `'/api/health'` — correspond exactement à `/api/health`
- **Correspondance par préfixe** : `'/admin'` — correspond à `/admin` et à `/admin/dashboard`
- **Caractères génériques** : `'/api/*'` — correspond à `/api/users` mais pas à `/api/users/123`
- **Caractères génériques profonds** : `'/admin/**'` — correspond à `/admin/users` et à `/admin/users/123`

### Expressions régulières

Utilisez des objets RegExp pour des correspondances de motifs complexes :

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Cas d'usage

### Fichiers SEO

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### Routes d'API

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Panneaux d'administration

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Ressources statiques

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Fonctionnement

1. **Intergiciel serveur** : un intergiciel Nitro s'exécute en premier pour vérifier les motifs d'exclusion
2. **Traitement des pages** : durant la résolution des pages, les chemins exclus sont ignorés
3. **Route fourre-tout** : la route de repli vérifie les exclusions avant traitement
4. **Prérendu** : les chemins exclus ne sont pas inclus dans les routes prérendues

## Impact sur les performances

- Les vérifications d'exclusion sont optimisées et exécutées tôt dans le cycle de vie de la requête
- Les motifs intégrés utilisent une correspondance regex efficace
- Les motifs personnalisés sont mis en cache et réutilisés
- Frais généraux minimaux pour les chemins exclus

## Dépannage

### Les fichiers statiques sont encore interceptés

1. **Vérifiez la syntaxe des motifs** : assurez-vous que vos motifs correspondent exactement à la structure du chemin
2. **Utilisez des regex pour les motifs complexes** : les caractères génériques dans les chaînes ont des limites
3. **Testez les motifs** : utilisez les outils de développement du navigateur pour vérifier le chemin de requête réel
4. **Vérifiez l'ordre** : assurez-vous que les motifs d'exclusion sont définis avant les autres options i18n

### Motif qui ne fonctionne pas

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Mode débogage

Activez le mode débogage pour voir le traitement des exclusions :

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Cela journalisera les décisions d'exclusion dans la console.

## Migration depuis les contournements

Si vous utilisiez des contournements comme des règles de route ou des intergiciels, vous pouvez maintenant les remplacer par `excludePatterns` :

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

La nouvelle approche est plus fiable et fonctionne à plusieurs niveaux du système de routage.
