**日期**：2026-11-03

**版本**：`v4.0.0`

![v4.0.0 版本](/images/4.0.0.png)

**v4.0.0** 正式推出。路由、翻譯核心、字典檔案、語系偵測以及所有框架套件都經過重寫。選項、`$t`、`$localePath`、`$switchLocale`、元件與 composable 都保留原本的名稱。改變的是行為，而其中大部分的變更都是已消除的錯誤。大多數應用程式只需要少量程式碼變更，但升級前請先閱讀[重大變更](#breaking-changes)：URL、SEO 標籤與框架套件 API 在某些地方有所調整。[升級](/zh-Hant/guide/upgrade)頁面列出了所有細節。

## 有哪些新功能？ {#what’s-new}

### 一次建置支援所有網域 {#one-build-for-every-domain}

`locales[].baseUrl` 與 `baseDefault` 以前只會影響連結。現在它們也會路由請求，適用於全部四種策略以及 `nuxt generate`：

```ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'fr', baseUrl: 'https://example.com' },
      { code: 'de', baseUrl: 'https://example.de', baseDefault: true },
    ],
  },
})
```

- 每個主機提供自己的語系。指向其他網域語系的連結會變成該網域上的絕對 URL，切換到該語系時也會導覽到那裡。
- 在會覆寫 `X-Forwarded-Host` 的代理伺服器之後，`trustForwardedHost` 會從該標頭取得網域。預設關閉。
- `NUXT_I18N_DOMAIN` 為 `nuxt generate` 提供主機：每個網域各執行一次，每份輸出只包含該網域的頁面與字典。
- 沒有使用 `baseUrl` 的應用程式不會包含任何這部分的程式碼。

請參閱 [Layer 與網域](/zh-Hant/guide/layers#multiple-domains)與[部署](/zh-Hant/guide/deployment)。

### 與路由器一致的路由 {#routing-that-agrees-with-the-router}

建置與執行期不再各自計算在地化的 URL。所有結果都來自建置所產生的路由，因此連結、語言切換器、`hreflang` 與重新導向都不會指向不存在的頁面。

- 不提供某頁面的語系會連結到其首頁，絕不會連到其他語系的頁面。
- `hreflang` 只列出提供該頁面的語系。
- `$switchLocale` 會解析為 `true` 或 `false`，讓你知道字典何時載入失敗。重複呼叫會重試。
- 在 SSR 期間設定的 `$setI18nRouteParams` 與 `useI18nHead` 在 hydration 後仍會保留。語言切換器會連結到翻譯後的 slug，伺服器 HTML 中也是如此。
- 導覽會在提交（commit）時生效：被取消或被阻擋的導覽不會改變任何內容。
- Hash 模式可在 `prefix` 下運作。
- 在 server component 上使用 `<Greeting :locale="$getLocale()" />` 會設定其渲染語系。

### 統一的語系偵測 {#one-locale-detection}

在伺服器、瀏覽器、伺服器 API 輔助函式與 Astro 中都使用同一套順序。`Accept-Language` 會遵循 `q` 值，地區比對不再取決於 `locales` 的順序，而且絕不會跨越中文的不同書寫系統。執行期覆寫現在也會影響路由：`NUXT_I18N_DEFAULT_LOCALE` 與執行期的 `disabledLocales` 會改變實際提供的內容。請參閱[語系偵測](/zh-Hant/guide/locale-detection)。

### 所有模式使用同一份字典 {#one-dictionary-in-every-mode}

預先合併的建置、`mode: 'source'` 與開發環境以往在許多頁面上的結果不一致。現在它們會產生相同的字典。

- 每一層都進行深度合併，後備鏈（`fr` → `de` → `en`）會一路追蹤到底。
- 開發環境中的翻譯編輯會就地套用，無需重新載入頁面。刪除的鍵會消失，根檔案的編輯會影響所有頁面。
- `$clearCache()` 會重新載入目前的頁面，並在新文字載入前保留畫面上的舊文字。
- 載入失敗的 chunk 會保留目前的字典，而不會顯示原始鍵。

### 更小的字典檔案 {#smaller-dictionary-files}

- 頁面的檔案現在只包含與該語系根字典（位於 `__root/<locale>/data.json`）不同的部分。瀏覽器只會載入一次根字典，並將每個頁面合併在其上，因此磁碟用量下降，下一個頁面的成本只有第一個頁面的一小部分。
- 字典 URL 帶有版本號。帶有目前 `?v=` 的 URL 在 Node 伺服器上會被固定快取一年，而主機上的靜態副本會回應 `max-age=60`。請參閱[快取標頭](/zh-Hant/guide/deployment#cache-headers-and-datebuild)。
- 每個 SSR 頁面都會預先載入其字典檔案，讓它們與 HTML 一起開始下載。
- 讀取失敗不再被保留：下一個請求會重新讀取。請參閱[當字典無法讀取時](/zh-Hant/guide/deployment#when-a-dictionary-cannot-be-read)。

### 更好的 `<i18n-t>`、複數與格式 {#better-&lt;i18n-t&gt;-plurals-and-formats}

- 插槽可搭配 `plural`、`number`、`date` 與 `relativeDate` 使用，且每個 `{name}` 都會被填入，而不只是第一個。
- `<i18n-t>` 在 Nuxt、Vue、React、Preact、Solid 與 Astro 中使用同一個渲染器。
- 以 `=0 ` 開頭的第一種形式是明確的零形式，其餘則依 `Intl.PluralRules` 決定：`=0 no apples | one apple | {count} apples`。請參閱 [`$tc`](/zh-Hant/api/methods#$tc)。
- 新的 `timeZone` 選項：讓伺服器與所有瀏覽器顯示相同的日曆日期。
- `{firstName}`、`{first-name}` 與 `{user.name}` 都是有效的佔位符。
- `$tn`、`$td` 與 `$tdr` 會像複數一樣遵循 `iso`。
- `$tdr` 能正確表示未來日期：`in 3 days`，或搭配 `numeric: 'auto'` 時為 `tomorrow`。

### 預設更安全 {#safer-by-default}

- `<i18n-t html>` 會跳脫 `params`。只有翻譯本身被視為可信任的標記。
- 不會有連結意外離開 origin：`//host`、`/\host` 與空白值都會留在本站。
- 伺服器翻譯快取有上限，因此使用捏造頁面名稱的 URL 無法讓記憶體無限成長。
- DevTools 的儲存端點只接受翻譯目錄中既有的 `.json` 檔案，並會拒絕跨站請求。

### 框架套件升級至 2.0 {#framework-packages-at-2-0}

- **React、Preact、Solid：** `I18nT` 接受 `components` prop 以支援富文本。新增 `useT` 與 `useLocaleSwitch`，並透過 `@i18n-micro/react/server` 與 `/client` 支援 React Server Components。Preact 不再需要 `preact/compat`。
- **Vue 與 VitePress：** `I18nLink` 會保留 `name`、`query` 與 `hash`，VitePress 會遵循 `base`。
- **Astro：** `i18nIntegration` 會打包你的字典並安裝 middleware。主要進入點沒有任何 `node:*` import，因此可在邊緣環境執行。`base` 可正常運作。
- **Node 與 runtime：** `fork(locale)` 能以低成本為每個請求建立執行個體，而 `@i18n-micro/node` 上的 `run(locale, fn)` 會將執行個體限定於單一請求。
- **`@i18n-micro/types-generator`：** 沒有第三方相依套件，並且是一般的 Vite 與 Rollup 外掛。
- **`@i18n-micro/devtools-ui`：** 透過 Vite 的 socket 即時更新，並提供 Astro 工具列應用程式。

### `@i18n-micro/cli` {#@i18n-micro/cli}

CLI 現在以 `@i18n-micro/cli` 的形式存放於 monorepo 中，經過重寫後指令從 28 個精簡為 16 個，相依套件也大幅減少。`check` 取代了 `validate`、`diff` 與 `check-duplicates`，並提供 `--json` 與適用於 CI 的結束碼。當無法證明某個鍵未被使用時，`clean` 不會寫入任何內容。請參閱 [CLI](/zh-Hant/guide/cli)。

### 文件 {#documentation}

文件依據程式碼重新撰寫，並圍繞單一閱讀路徑編排：安裝、第一個翻譯頁面、翻譯檔案、路由、偵測，接著是各項任務指南。舊的 URL 會重新導向。[升級](/zh-Hant/guide/upgrade)頁面詳細列出了所有變更。

## 速度與大小 {#speed-and-size}

- 伺服器渲染會直接讀取字典，不需要本機 HTTP 請求，也不需要重新剖析。
- `dir="auto"` 不再是預設值。在大型頁面上，瀏覽器會在它上面花費大量時間：在有 20,000 個 `$t` 元素的情況下，Chromium 中的 DOMContentLoaded 從約 980 ms 降到約 115 ms。
- `serverTranslationPreload` 與 `i18n:register` 不再拖慢每個請求。
- 未設定 cookie 時，客戶端 bundle 會移除 `useCookie`，而 `@i18n-micro/path-strategy` 的大小只有以往的一小部分。

**測試應用程式與 v3.30.3 的比較。** 在一台 Mac 上的單一 Node 伺服器上執行一個產生的 Nuxt 應用程式，使用 `wrk` 以 24 個連線執行 20 秒，輪替三回合，使用預發布版本建置。各列來自不同的執行，因此請在同一列中比較。Hydration 兩邊都使用 `dir: 'ltr'`。

| 指標 | v3.30.3 | v4.0.0 |
| --- | ---: | ---: |
| 4 個語系、10k 目錄：每秒請求數 | 384-395 | 585-591 |
| 4 個語系、10k 目錄：p95 延遲 | 106-110 ms | 70-72 ms |
| 4 個語系、10k 目錄：每個請求的伺服器 CPU | 2.92-3.00 ms | 2.01-2.02 ms |
| 12 個語系、100k 目錄：每秒請求數 | 362-370 | 578-580 |
| 12 個語系、100k 目錄：p95 延遲 | 115-117 ms | 72-73 ms |
| 12 個語系、100k 目錄：每個請求的伺服器 CPU | 3.11-3.17 ms | 2.02-2.03 ms |
| Hydration，100k 頁面 | 86-92 ms | 77-81 ms |
| 此應用程式的客戶端 JS，gzip | 105.1 KB | 93.9 KB |
| 有 `i18n:register` 訂閱者時的請求時間，100k chunk | 96-108 ms | 1.7 ms |

在較早的預發布版本上，針對 100k 目錄執行 30 分鐘，共處理 113 萬個請求，沒有任何錯誤，且即時 heap 維持平穩。

**三個正式環境應用程式與 v3.29.5 的比較**（它們原本使用的版本），使用預發布版本建置。其中兩個是 SSR 網站，一個是 SPA。每個都在單一 Node 伺服器上執行 60 秒，8 個連線，僅 GET，兩回合。建置時間各執行一次。

| 指標 | SSR 應用程式 1 | SSR 應用程式 2 | SPA 應用程式 |
| --- | ---: | ---: | ---: |
| 磁碟上的字典位元組 | 6.37 MB 降至 1.52 MB（-76%） | 4.43 MB 降至 1.52 MB（-66%） | 15.40 MB 降至 1.69 MB（-89%） |
| `.output` 大小 | -22% | -14% | -29% |
| 建置時間 | 27 s 降至 22 s | 23 s 降至 19 s | 41 s 降至 28 s |
| 客戶端 JS，gzip | +1.7% | +0.9% | +0.5% |
| 每秒請求數 | 82 增至 88 | 237 增至 240，在誤差範圍內 | 233 增至 404，僅 SPA 外殼 |

**客戶端 JS。** 擁有自身程式碼的實際應用程式會略為增加，如上所示。共用的修正也讓框架套件變大了：在另一個預發布版本上，以最小規模的 Vue、React、Preact 與 Solid 應用程式測量，約增加 1.4 KB 到 2.5 KB gzip。React、Preact 與 Solid 也包含共用的富文本渲染器。

**字典請求。** 首次載入現在需要兩個檔案：根檔案與頁面檔案。其位元組數維持不變（在兩個 SSR 應用程式的 103 次與 89 次首次載入中為 +0.3%）。同一份文件中的下一個頁面只需要一個小檔案：在測量的兩個頁面上分別從 4.7 KB 降到 1.5 KB gzip，以及從 5.9 KB 降到 0.5 KB gzip。在 SPA 的登入後瀏覽流程中，字典位元組減少了 21%。

**邊緣環境。** 在一個小型示範應用程式上，使用預發布版本建置時，Cloudflare Worker 上傳大小從 241.5 KiB 增加到 250.3 KiB gzip。嵌入 Edge bundle 中的字典使用相同的根檔案與頁面檔案，但我們尚未在大型目錄上測量這種嵌入方式。

## 重大變更 {#breaking-changes}

### 需求 {#requirements}

- **Nuxt 3.18 或更新版本**，以及 **Node 20 或更新版本**。
- **`@i18n-micro/test-utils`** 不再隨模組一起安裝。如果你的測試會匯入它，請自行加入。
- **`@i18n-micro/hmr`** 已移除：翻譯 HMR 已內建。如果你有安裝這個套件，請將它移除。
- **`@i18n-micro/react`** 需要 React 18 或更新版本。
- **`nuxt-i18n-micro-cli`** 已由 `@i18n-micro/cli` 取代。

### 選項與設定 {#options-and-config}

- `dependsOn` 中的 `i18n-plugin-hooks` 與 `i18n-plugin-define` 不再等待任何東西，且不會產生錯誤。請使用 `i18n-plugin-loader`。
- 伺服器端自動匯入的有 `useLocaleServerMiddleware`、`useTranslationServerMiddleware`、`loadTranslationsFromServer` 與 `detectCurrentLocale`。其他項目不再自動匯入。
- `resolveTranslationPayloadMode` 與其他 `resolveTranslationPayload*` 輔助函式已從 `nuxt-i18n-micro` 中移除，`shouldCopyTranslationPayloadsToPublic` 與 `shouldRegisterNitroServerAssets` 也一併移除。`TranslationPayloadMode` 型別保留。
- `$getI18nConfig()` 不再包含 `isSSG`、`hmr`、`hooks`、`noPrefixRedirect`、`routeLocales`、`routeDisableMeta` 或 `globalLocaleRoutes`。這些選項本身沒有變更。
- `locales[].baseUrl` 現在會路由請求：其他網域的語系在此主機上會回傳 404，而同一主機上的連結為相對路徑。在這類建置中，`$getI18nConfig().locales` 包含該主機提供的語系，`linkLocales` 則包含所有語系。
- `baseUrl` 也會在任何其他主機上設定 origin：canonical 與 `hreflang` 會使用 `metaBaseUrl`（若有設定），否則使用預設語系的 `baseUrl`，而不是請求的 origin。
- `excludePatterns` 會比對完整區段（`'/admin'` 不再比對到 `/administrator`），glob 會被錨定，且 `RegExp` 模式現在也會傳遞到執行期。
- 未設定 `cacheMaxSize` 時，伺服器上最多 1000 筆項目。`cacheTtl` 從項目儲存時開始計算，讀取不再延長其時效。
- 在 `no_prefix` 下，`i18n` 設定中明確指定的 `localeCookie: null` 會保持關閉。
- 在 `prefix_except_default` 與 `prefix_and_default` 下，執行期的 `defaultLocale` 會被忽略並發出警告。執行期的 `fallbackLocale` 必須是已啟用的語系。
- 會遵循 `nuxt.config` 中的 `routeDisableMeta`，且無論鍵的形式為何，`nuxt.config` 的項目都優先於 `$defineI18nRoute`。
- 在開發環境的伺服器上，解析後的設定會被凍結：寫入它會擲出錯誤。
- 對於相同的 `code`，專案的 `locales` 項目優先於 layer 的項目。

### Composable 與 `$` 方法 {#composables-and-$-methods}

- `$switchLocale` 會解析為 `true` 或 `false`，以前不會解析出任何值。`$switchRoute` 的型別為 `Promise<void>`。
- `$localeRoute`、`$switchLocalePath` 與語言切換器會將不提供該頁面的語系連結到該語系的首頁。
- `$localePath` 會原樣回傳帶有 `http(s):`、`mailto:` 或 `tel:` 協定的字串，而 `$localeRoute` 會將它放在 `path` 與 `fullPath` 中。請勿將未經檢查的值作為連結目標傳給它們。`//host` 與像 `x.com` 這樣的裸名稱會保持為本 origin 上的路徑。
- 沒有路徑的連結會停留在目前頁面：`$localePath('#top')`、`'?p=2'`、`''` 與 `{ query }`。`'#top'` 以前會從網站根目錄解析。單純的 `'about'` 仍代表 `/about`。
- `$switchRoute` 會留在應用程式內。只有語系自己的 `baseUrl`、`mailto:` 與 `tel:` 會離開。
- 指向帶有 `baseUrl` 之語系的連結需透過 `$localePath` 或 `<i18n-link>`。`<NuxtLink :to="$localeRoute(x, 'fr')">` 與 `router.push($localeRoute(x, 'fr'))` 會保持為此應用程式的路徑。在程式碼中請使用 `navigateTo($localePath(x, 'fr'), { external: true })`。
- `$switchLocaleRoute` 與重新導向會遵循 `trailingSlash`。
- 在伺服器上設定的 `$setI18nRouteParams` 與 `useI18nHead`，在導覽改變路徑時（包括從 `/news/1` 到 `/news/4`）會被捨棄：請在新頁面上重新設定。
- 在 setup 中讀取的 `$setI18nRouteParams` 會綁定到該頁面：來自已離開頁面的延遲呼叫不會有任何作用。它沒有 setter，因此在測試中請直接 stub `useI18n`。
- `useI18n()` 在每個應用程式中回傳同一個物件。寫入它會影響所有呼叫者。
- 字典、語系、參數與 head 會在導覽提交時變更。`beforeResolve`、`beforeRouteEnter` 或較晚的全域守衛看到的是舊值。路由 middleware 不受影響。
- 在 URL 策略下，當導覽被取消時，`$switchLocale` 會還原已儲存的語系。
- `$t` 會對 `defaultValue` 進行插值：`$t('missing', { n: 1 }, 'Got {n}')` 會得到 `Got 1`。`$tc` 也是如此，且翻譯為空時會回傳 `''`。
- `$has(key, route)` 會遵循路由。
- `$clearCache()` 會重新載入目前頁面的字典。
- `{param}` 佔位符只會讀取你傳入的參數：`{constructor}` 會保持原樣。
- `$tc` 在數量為負數、小數或極大值時，會取最後一種形式並使用實際數量。`{ count: null }` 不再擲出錯誤，缺少的複數鍵會交給缺漏處理函式。
- `$tdr` 對無效的輸入會回傳 `Invalid Date`。過去不到一秒會是 `0 seconds ago`。
- `$tn`、`$td` 與 `$tdr` 依 `iso` 而定：`{ code: 'en', iso: 'en-GB' }` 會將日期格式化為 `31/10/2026`。`Intl` 不認得的代碼會以 `en` 格式化，複數則依索引規則處理：請設定 `iso`（`{ code: 'ua', iso: 'uk-UA' }`）。
- `detectCurrentLocale` 已棄用：請使用 `useLocaleServerMiddleware(event).current`。

### 複數 {#plurals}

範本會保留其原本的意義，只有一個例外。一個不含佔位符的零形式，接著每個類別各一種形式，且在多個數量共用的每個形式中都含有 `{count}` 的範本，現在在具有三個或更多類別的語系（`ru`、`uk`、`pl`、`cs`、`ar` 等）中會依類別決定：`none | {count} one | {count} few | {count} many` 在 `uk` 中會得到 `3 few` 與 `21 one`。若要在其他範本中使用類別，請加上 `=0 ` 標記。自訂的 `plural` 規則會讀取原始值，因此帶有標記的範本傳給它時會保留 `=0 `。請參閱[升級中的表格](/zh-Hant/guide/upgrade#plurals-and-formatting)。

### 元件 {#components}

**`<i18n-t>`**

- `html` 在所有情況下都會跳脫 `params`，並忽略所有插槽。
- 插槽優先於同名的參數。
- 對於 `plural`、`number`、`date` 與 `relativeDate`，`null` 表示未設定。
- `plural` 像 `$tc` 一樣以 `Number` 計算：`1.5` 維持 `1.5`，`"2 items"` 為 `NaN`，`""` 為 `0`。
- `number`、`date` 與 `relativeDate` 會保留 `params`。
- `hideIfEmpty` 在每個分支中都會套用，`defaultValue` 在每個分支中都會替代缺少的鍵。
- 在 `html` 下缺少的鍵會以跳脫後的文字呈現。
- `date` 與 `relativeDate` 的輸出帶有 `data-allow-mismatch="text"`，且在具名插槽旁的文字會放在獨立的 `<span>` 中。
- `.innerHTML` 與 `textContent` 屬性會被捨棄。
- 它是函式型元件：在其上使用 `ref` 不會取得執行個體。
- `<i18n-t>` 與 `<i18n-group>` 會像 `$t` 一樣讀取目前的字典。

**`<i18n-switcher>`**

- 連結是呼叫 `$switchLocale` 的一般 `<a>`，因此 `router-link-active` class 已不存在。
- 按鈕為 `type="button"` 並帶有 `aria-expanded`。按下 Escape 或點擊外部會關閉下拉選單。
- 新的 class：`i18n-switcher-wrapper`、`i18n-switcher-dropdown` 與 `i18n-switcher-button`。每個連結都有 `lang`，當語系有設定時也會有 `dir`。
- 預設樣式使用邏輯 CSS 屬性，下拉選單具有較大的 `z-index`、最小寬度與陰影。
- 在帶有參數的頁面上，伺服器會在渲染結束時改寫其連結。手寫的 `$switchLocalePath` 連結不會被改寫。

**`<i18n-link>`**

- `https://`、`mailto:` 與 `tel:` 不分大小寫皆可比對。單純的 `report.pdf` 是路由，而 `example.com` 保持為外部連結。同時也是 TLD 的副檔名（`example.md`）會被視為檔案：請寫上 `https://`。
- `activeStyle` 會忽略結尾斜線、query 與 hash。

### Hook 與型別 {#hooks-and-types}

- `i18n:register` 是執行期 hook：在外掛中使用 `nuxtApp.hook('i18n:register', …)`。
- 匯出的型別 `ModuleHooks` 已更名為 `ModuleRuntimeHooks`。
- `i18n:beforeLocaleSwitch` 與 `i18n:afterLocaleSwitch` 從未被發出，已不再列於文件中。
- `ModuleOptionsExtend.isSSG` 為選用且已棄用：沒有任何地方會設定它。

### URL 與重新導向 {#urls-and-redirects}

- 在 `prefix_except_default` 下且 `en` 為預設語系時，**`/en` 與 `/en/...` 會回傳 404**。
- **大小寫或拼寫不同的語系前綴會回傳 404**（`/DE/about`）。`[...slug]` 下的 `/DE/x` 以及 `[slug]` 旁的 `/DE` 也是如此，因此與語系代碼大小寫不同但相同的 CMS slug 會失去其頁面。
- 使用 `autoDetectPath: '*'` 或 `'no_prefix'` 時，**未知的 URL 仍會回傳 404**。`prefix` 會保留重新導向，所有情況下的 `/` 也是如此。
- **其他語系的自訂路徑（無前綴）**在 `prefix_except_default` 下會以 `302` 導向預設語系的 URL。在 `prefix` 下，重新導向現在會抵達實際存在的頁面。`prefix_and_default` 則仍回傳 404。
- **`prefix` 搭配 `redirects: false`** 時，無前綴的 URL 會回傳 404，包括具有自訂預設路徑之頁面的原始 URL。
- **`autoDetectPath: '*'`** 也會對無前綴的路徑套用 cookie 與 `Accept-Language`。
- **在 `prefix` 下**，無論 `autoDetectPath` 如何設定，無前綴的 URL 在所有路徑上都會保留訪客的語系。
- **在 `prefix_and_default` 下**，無前綴的 URL 即為預設語系。
- **在 `no_prefix` 下**，自訂路徑會以其自身的語系渲染，受限制的頁面會以其提供的語系渲染，而共用同一路徑的語系會共用同一筆記錄。
- **沒有頁面的 `routeRules` 重新導向**不會被在地化：`/de/old` 會回傳 404，以前是空的 200。
- **路由規則會套用到自訂路徑**，在 `no_prefix` 下也會被複製。像 `/de/artikel/news` 這樣的靜態同層路由會比對到 `/de/artikel/:slug`。
- **設定 `disabled: true` 的語系**會立即在其前綴上回傳 404，指向它的連結會停留在目前頁面。
- **大小寫不同的頁面路徑**會以 `302` 導向其正確拼寫：`/T/BASIC` 會導向 `/t/basic`。
- 在 `prefix_except_default` 下，**具有自訂預設路徑之頁面的原始 URL** 會以 `302` 導向該路徑。以前會回傳 404。
- **`noPrefixRedirect`** 依訪客的語系而定：cookie 為 `de` 時，`/about` 會導向 `/ueber-uns`，而不是預設語系的路徑。
- 在 `prefix_except_default` 下，**主機自己的前綴**在其 `baseDefault` 主機上會回傳 404：`de` 主機上的 `/de/x` 以前是 200。
- **`customRegexMatcher`** 不再讓第一個區段看起來像語系的實際頁面回傳 404。
- **`nuxi generate`** 會在每個提供該頁面的語系中預先渲染所有靜態頁面，除非路由規則設定了 `prerender: false`：輸出中會有更多檔案。使用 `baseUrl` 時，請搭配 `NUXT_I18N_DOMAIN` 為每個網域各執行一次。
- **客戶端重新導向會保留其導覽模式：** 一般的 `<NuxtLink>` 會新增一筆歷史記錄。
- **在地化的路由名稱保持一致。** 只有在 `router.push({ name })` 中寫死 `localized-…` 名稱的程式碼會受影響：請將頁面本身的名稱傳給 `$localeRoute`。
- **來自 `extendPages` 的未命名頁面**會被在地化並取得名稱。
- **在 `prefix` 下，指向其他網域的連結**會保留語系前綴。
- **網域的首頁**在所有地方都不帶結尾斜線。
- **`?locale=`** 只在 `no_prefix` 下的頁面上有效。`/about?locale=de` 不再在 `lang="en"` 下渲染德文。
- 在 `/en/...` 上，**外掛的 `setLocale('de')`** 不再載入 `de` 字典。

### SEO 與 HTML 輸出 {#seo-and-html-output}

- `dir="auto"` 不再是預設值。已知的 RTL 語言會得到 `dir="rtl"`，其他未設定 `dir` 的語系則不會有該屬性。若要保留舊的輸出，請設定 `dir: 'auto'`，但在大型頁面上會有剖析成本。請參閱[文字方向](/zh-Hant/guide/seo#text-direction)。
- `disableMeta` 現在可正常運作：頁面不會有 `hreflang`、canonical 或 `og:locale`。`lang` 與 `dir` 會保留。
- `hreflang` 只列出提供該頁面的語系。只有在預設語系提供該頁面時才會出現 `x-default`。
- 未在地化的頁面沒有 `hreflang` 或 `og:locale:alternate`。
- 404 頁面帶有 URL 語系的 `<html lang dir>`，且沒有 canonical 或 `hreflang`。
- Canonical、`og:url` 與 `hreflang` 會保留白名單中的 query（`/about?page=2`），在伺服器上也是如此。
- 當 origin 來自請求時，canonical 與 `hreflang` 會包含 `app.baseURL`。
- 每個 SSR 頁面（包括 404 頁面）都有針對其字典檔案的 `<link rel="preload" as="fetch" crossorigin="anonymous">`。在嚴格的 CSP 中請允許它。使用 `apiBaseClientHost` 時，該主機需要 CORS。
- 在 `no_prefix` 下的每個頁面，以及其他策略的語系重新導向上都會設定 `Vary`。請檢查你的 CDN 快取鍵。
- 語系 cookie 只會由實際提供的頁面寫入。

### 偵測與伺服器 {#detection-and-server}

- `Accept-Language` 會遵循 `q` 值，`q=0` 會排除某個語言。
- `useLocaleServerMiddleware` 與 `useTranslationServerMiddleware` 在每個路由上使用相同的順序（`?locale`、`[locale]` 參數或前綴、cookie、標頭、預設值），遵循 `localeCookie: null` 與 `autoDetectLanguage: false`，並為每個語系快取字典。
- 格式錯誤的語系 cookie 會被忽略並保持原樣，而不會導致 SSR 失敗。
- Hash 模式只讀取 `hash-locale` cookie。單獨的 `user-locale=de` 不再有效。
- `NUXT_I18N_DEFAULT_LOCALE` 與執行期的 `disabledLocales` 會改變路由。
- **`premerged` 輸出已變更。** `/{apiBaseUrl}/<page>/<locale>/data.json` 只包含與 `__root/<locale>/data.json` 不同的部分。任何直接讀取這些檔案的工具都必須合併兩者。完整的字典仍是有效的檔案。
- **字典會遵循 `app.cdnURL`。** 瀏覽器會從 `<cdnURL>/_locales/...` 擷取字典，以前使用的是 `app.baseURL`。CDN 必須存放 `_locales/` 並允許你網站的 origin。請參閱 [App baseURL 與 payload 主機](/zh-Hant/guide/deployment#app-baseurl-and-payload-hosts)。
- `/{apiBaseUrl}/**` 上不再有 Nitro 路由快取，`s-maxage=60, stale-while-revalidate` 標頭也已移除。如果你依賴該快取，請在 payload 路由前加上 CDN。
- `/{apiBaseUrl}/<page without a folder>/<locale>/data.json` 會回應根字典，以前是 `{}`。主機的 404 現在會以 404 傳遞，以前會回應 `200 {}`。
- 無法載入字典的預先渲染會以 500 失敗並發出警告，在 Nuxt 預設的 `failOnError` 下，建置會以 1 結束。
- 未重新建置而變更的翻譯，只有在 `v` 變動時才會傳到瀏覽器：請設定 `NUXT_I18N_DATE_BUILD`。
- 除非設定了 `apiBaseServerHost`，否則 SSR 不再透過 HTTP 請求 `/{apiBaseUrl}`。

### 翻譯 {#translations}

- 每一層都進行深度合併，後備鏈會一路追蹤到底。
- 合併依語系進行：目前語系的根檔案優先於後備語系的頁面檔案。
- 在正式環境中，沒有自己 `pages/<name>/` 資料夾的頁面會讀取根字典。以前會得到 `{}`。
- `disablePageLocales: true` 只會讀取根檔案。
- 導覽後，離開頁面的鍵會停止解析。如果 layout 使用了只有前一個頁面的檔案才有的鍵，請將它們移到根檔案。
- 損壞的語系檔案在所有模式下都會以其路徑發出一次警告。以前在開發環境中會擲出錯誤。

### `@i18n-micro/*` 套件 {#@i18n-micro/*-packages}

所有 `@i18n-micro/*` 套件都升級至 2.0.0，包括 `@i18n-micro/types` 與新的 `@i18n-micro/cli`。

**`@i18n-micro/react`、`preact`、`solid`**

- 路由器轉接器已移至 `/router`：`createReactRouterAdapter`、`createSolidRouterAdapter`，以及 Preact 的 `createBrowserHistoryAdapter`。`createPreactRouterAdapter` 已移除。
- `I18nT` 遵循上述 `<i18n-t>` 的行為。`dangerouslySetInnerHTML`、`innerHTML` 與 `textContent` 屬性會被捨棄。
- `I18nSwitcher` 會渲染帶有 `aria-current="page"` 的 `<a href>` 項目、`▾`、邏輯 CSS，並在按鈕上加上 `language-switcher`。沒有 `aria-haspopup`。`className` 會附加到 `i18n-switcher-wrapper`。

- `I18nLink` 會保留使用者的 `onClick` 與 `style`，並將帶修飾鍵的點擊交給瀏覽器處理。Query 與 hash 不納入啟用判斷。沒有路由器時，不會有任何連結處於啟用狀態。

- 沒有 `i18n` 的巢狀 `I18nProvider` 會沿用外層的執行個體，完全沒有執行個體的 provider 會擲出錯誤。

- Solid：`getCurrentPathAccessor` 已移除。沒有 `locales` 時，`useI18n()` 不再擲出錯誤。
- React：`use-sync-external-store` 不再是相依套件，`react-dom` 為選用的 peer。

**`@i18n-micro/vue`、`vitepress`**

- `I18nT` 是函式型元件。
- `I18nSwitcher` 與 `I18nLink` 遵循上述各節的行為。`aria-haspopup` 已移除。
- `I18nLink` 與 `createVueRouterAdapter` 會解析 `name`、`query` 與 `hash`。未知的 `name` 會像 `RouterLink` 一樣擲出錯誤。
- `useLocaleHead` 不再產生 `//de/`。同一頁面的 canonical 與 `hreflang` 會一致（`/de`），白名單中的 query 參數也會傳到它們。
- `I18nRoutingStrategy.resolvePath` 可能會收到 location 物件，以及帶有 query 與 hash 的路徑。新增選用的 `toHref`。
- VitePress：連結、語言切換器、`push` 與 `replace` 都會帶有 `site.base`。

**`@i18n-micro/astro`**

- `i18nIntegration` 會打包 `translationDir` 並安裝 middleware：請刪除只是複製設定的 `src/middleware.ts`，或傳入 `middleware: false`。你自己的 `src/middleware.ts` 需傳入 `base: config.base`。
- `i18nIntegration` 遇到 `messages`、`plural`、`missingHandler` 與 `routingStrategy` 時會擲出錯誤：請將它們傳給 `createI18n` 或 `createI18nMiddleware`，並搭配 `middleware: false`。從未有任何作用的選項已從其型別中移除。
- `loadTranslationsFromDir` 與 `loadTranslationsIntoI18n` 已移至 `@i18n-micro/astro/node`，且僅支援 ESM。
- `getGlobalRoutingStrategy`、`setGlobalRoutingStrategy` 與 `runWithRoutingStrategy` 已移除：請讀取 `Astro.locals.routingStrategy`。
- `clone()` 改為 `fork()`，`_storage` 選項已移除。
- 動態頁面是單一路由：`/blog/hello` 是 `blog-slug`，以前是 `blog-hello`。請將 `pages/blog-hello/` 移到 `pages/blog-slug/`。自訂的 `getRouteName` 會以第三個引數取得該模式。
- URL 決定頁面語系。`autoDetect` 是從 `/` 以 302 導向偏好語系首頁。新增 `localeCookie` 選項，並實作了 `redirectToDefault`。
- 從其他語系的同源頁面瀏覽頁面時，會寫入語系 cookie 且不會重新導向。Server islands 與 actions 絕不會重新導向，並帶有 `Vary: Referer`。
- `config.localeCodes` 不包含已停用的語系，`prepareLocaleRewrite` 會對它們回應 404。
- 不帶鍵的 `getI18nProps()` 會傳送 `t()` 在該頁面上能回應的所有內容，超過 20 KB 時會在開發環境中發出警告。請傳入 island 使用的鍵。
- `useLocaleHead`：預設的 `baseUrl` 為 `site`，否則為相對於根目錄的路徑。連結與 meta 都帶有 `id`。
- `<I18nT html>` 會跳脫 `params`，空白翻譯會渲染為空。
- `<I18nLink>` 與 `localizePath` 不會更動外部 URL、`#hash` 與 `?query`，並會保留結尾斜線。
- `<I18nSwitcher>` 會保留 query，並使用 `data-i18n-switcher` 取代自動產生的 id。
- `@i18n-micro/astro/client` 只提供 `translate` 與 `hasTranslation`：請從 `/client/vue`、`/client/react`、`/client/preact` 與 `/client/svelte` 匯入轉接器。`client/vue` 需要安裝 `vue`。
- Islands：`has()` 對子樹為 true，`t('')` 為 `''`。`provideI18n` 接受 getter 以追蹤新的 props。
- 沒有 middleware 時，`getLocale` 與 `getDefaultLocale` 會擲出錯誤。

**`@i18n-micro/runtime`、`node`**

- 寫入既非目前語系也非後備語系的語系時，不會通知訂閱者。
- `addRouteTranslations(locale, route, messages, false)` 會取代該 chunk。
- `loadFromUrls` 會平行擷取，只要有一個失敗就不會寫入任何內容。

僅適用於自訂轉接器與工具。

- `utils`：子路徑 `./route`、`./route-pattern`、`./build`、`./payload-stats` 與 `./payload-config` 已移除，`resolveServerLocale` 與 `resolvePreferredLocale` 也一併移除：請呼叫 `resolveLocale`。`deepMergeTranslations` 與 `mergeRouteTranslationsWithRoot` 已移除：請使用 `deepMergeTranslationsRecursive`。
- `core`：`TranslationHelper` 移除了 `setCache`、`getGeneration` 與 `lookupIn`（請使用 `lookup(chunkKey, key)`）。`BaseI18n` 移除了 `ensurePinnedChunk` 與 `invalidatePin`。`useTranslationHelper(storage)` 已移除：請使用 `new TranslationHelper(storage)`。
- `path-strategy`：**`switchLocaleRoute(fromLocale, toLocale, route, options)` 現在改為 `switchLocaleRoute(toLocale, route, options)`。舊的 JavaScript 呼叫會回傳錯誤的結果，且不會產生錯誤。** Nuxt 的 `$switchLocaleRoute` 不受影響。`/prefix`、`/no-prefix`、`/prefix-except-default` 與 `/prefix-and-default` 進入點已移除，`getRedirect` 與 `getCanonicalPath` 也是。`RouterAdapter` 需要 `getRoutes`。`createPathStrategy` 不會產生絕對 URL：當語系有 `baseUrl` 時，請使用 `new DomainPathStrategy(ctx)`。
- `route-strategy`：只匯出 `RouteGenerator`、`generateRoutes`、`Rules` 與路徑輔助函式。

## 遷移 {#migration}

1. 檢查需求：Nuxt 3.18、Node 20，若使用 `@i18n-micro/react` 則需要 React 18。
2. 同時更新 `nuxt-i18n-micro` 與所有 `@i18n-micro/*` 套件。移除 `@i18n-micro/hmr`。如果你的測試會匯入 `@i18n-micro/test-utils`，請將它加入為開發相依套件。將 `nuxt-i18n-micro-cli` 替換為 `@i18n-micro/cli`，並依照[其指令對照表](/zh-Hant/guide/cli#moving-from-nuxt-i18n-micro-cli)操作。
3. 在程式碼中搜尋來自 `@i18n-micro/path-strategy` 的 `switchLocaleRoute(`、`i18n-plugin-hooks`、`i18n-plugin-define`、`localized-` 路由名稱、`$getI18nConfig().globalLocaleRoutes` 與其他已移除的設定鍵、`ModuleHooks`，以及 `i18n:register` 上的 `@ts-expect-error`。
4. 將標記從 `<i18n-t html>` 的參數移到翻譯中，並以參數傳遞資料。
5. 如果你有設定 `baseUrl`：請檢查以 `$localeRoute` 建立的連結，在代理伺服器之後設定 `trustForwardedHost`，並搭配 `NUXT_I18N_DOMAIN` 為每個網域各執行一次 `nuxi generate`。
6. 依照你的策略檢查 URL：`prefix_except_default` 下的 `/en`、看起來像語系的 CMS slug、`routeRules` 重新導向，以及 `excludePatterns`。
7. 檢查 CDN 快取鍵是否考慮 `Vary`，並在嚴格的 CSP 中允許預先載入連結。使用 `app.cdnURL` 時，請將 `_locales/` 放到 CDN 上並允許 CORS。
8. 如果有工具直接讀取 `/_locales/...` 檔案，請將頁面檔案合併到 `__root/<locale>/data.json` 之上。
9. 如果有全域守衛會讀取語系或字典，請確認它可以在導覽提交之前執行。將 layout 從前一個頁面檔案取用的鍵移到根檔案。
10. 比較升級前後的 `nuxi generate` 輸出或 sitemap 爬取結果：`hreflang`、`x-default`、canonical 與頁面清單會依設計而改變。
11. 更新框架套件的 import：React、Solid 與 Preact 轉接器使用 `/router`，Astro 的載入器使用 `/node`，型別外掛使用 `I18nTypesPlugin(o)`。
12. 若使用 Astro，請刪除只是複製設定的 `src/middleware.ts`，並將 `pages/blog-hello/` 這類字典重新命名為其模式名稱。
13. 更新固定了 `router-link-active`、`li button`、`▼` 或舊 mock 行為的測試。

細節與所有邊界情況：[升級](/zh-Hant/guide/upgrade)。

## 為何重要 {#why-it-matters}

- **在設計上即正確：** 連結、重新導向與 SEO 標籤都來自應用程式實際擁有的路由。
- **到處都是同一個答案：** 建置、source 模式與開發環境都會產生相同的字典，所有呼叫者都使用同一套偵測順序。
- **網域：** 一次部署支援所有語系網域，無需第二次建置。
- **更安全的預設值：** 跳脫的參數、有上限的快取、留在你 origin 上的連結。
- **更少的傳輸量：** 更小的字典檔案、更小的路由套件，以及集中在一處的共用邏輯。

完整的變更清單請參閱[升級](/zh-Hant/guide/upgrade)與 [changelog](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md)。
