## Nuxt I18n Micro v3.22.0 — 格式、快取與翻譯記憶 {#nuxt-i18n-micro-v3-22-0-—-formats-cache-&-translation-memory}

**日期**：2026-07-30

**版本**：`v3.22.0`

![v3.22.0 發行](/images/3.22.0.png)

我們宣布推出 **v3.22.0**：Vue I18n 風格的具名數字／日期格式與格式化器快取、對 CDN 友善的翻譯 payload 快取（內容指紋 + `httpCacheDuration`），以及可在執行階段讀取並替換使用中字典的翻譯記憶（Translation Memory）API。

## 有什麼新功能？ {#what’s-new}

### 具名 `numberFormats` / `datetimeFormats` + 格式化器快取 {#named-numberformats-/-datetimeformats-+-formatter-cache}

與 Vue I18n 相容的具名格式，以及更快速的 Intl 格式化：

- 設定：每個 locale 的 `numberFormats` / `datetimeFormats`
- API：`$tn(1000, 'currency')`、`$td(date, 'short')`（+ locale 覆寫與選項合併）
- `FormatService` 依 locale + 選項快取 `Intl.NumberFormat` / `DateTimeFormat` / `RelativeTimeFormat`

請參閱[方法 — `$tn` / `$td`](/zh-Hant/api/methods#$tn) 與[模組選項](/zh-Hant/api/module-options#numberformats)。

### `dateBuild` 預設為內容指紋 {#datebuild-defaults-to-a-content-fingerprint}

`/_locales` 請求上的 `?v=` 過去預設為 `Date.now()`，而回應則以 `immutable` 提供一年。因此每次重新建置都會使所有用戶端的字典失效，即使沒有任何翻譯變更。

現在的預設值是翻譯來源（依 layer 順序）的 SHA-256 指紋。翻譯未變動的重新建置會保持相同的 URL。明確設定 `dateBuild` 仍然優先。請參閱[模組選項 — `dateBuild`](/zh-Hant/api/module-options#datebuild)。

### 適用於 `/_locales` payload 的 `httpCacheDuration` {#httpcacheduration-for-/_locales-payloads}

內建的 `/{apiBaseUrl}/:page/:locale/data.json` 路由現在會為瀏覽器與 CDN 傳送 HTTP `Cache-Control`：

- 選項：`httpCacheDuration`（秒，預設 `31536000` / 1 年）
- 標頭：`Cache-Control: public, max-age=…, immutable`
- 可安全搭配既有的 `dateBuild` 快取破壞（`?v=...`）；`0` 會停用此標頭；開發環境中不套用

相當於 `@nuxtjs/i18n` v10.2.0 的 `experimental.httpCacheDuration`，以明確的回應標頭實作。

### 壓縮的公開 payload {#compressed-public-payloads}

`nitro.compressPublicAssets` 現在也會作用於複製到公開目錄的翻譯 payload（`.gz` + `.br`）。Nitro 會在複製發生之前壓縮公開資產，因此先前這些 payload 是靜態建置中唯一未壓縮的部分 — 在 playground 首頁上，原始大小 6.65 MB，gzip 後為 1.01 MB。模組本身仍然不會自行啟用壓縮。請參閱[效能](/zh-Hant/guide/performance#payload-size)。

### `resolveTranslations()` 與 `setTranslation(key, value)` {#resolvetranslations-and-settranslationkey-value}

用於在記憶體中讀取並替換使用中翻譯字典的執行階段輔助函式：

- **`resolveTranslations()`** 回傳 `$t()` 針對目前 locale 與路由所讀取的完整樹狀結構 — 適用於 DevTools、測試與執行階段編輯器。當第二個 layer 處於作用中（fallback locale 或 Nuxt 頁面轉場熱重載）時，輸出會透過 `mergeTranslationLayers` 保持巢狀結構，只有在單一樹狀結構無法表達的純量與物件衝突時才使用扁平的點分隔鍵。
- **`setTranslation(key, value)`** 替換某個鍵的值（頂層、點分隔路徑、物件、字串或純量）。這是**替換**而非合併；若需保留同層的其他鍵，請使用 `$mergeTranslations`。
- 可在 `useI18n()`、`useNuxtApp()`，以及繼承自 `@i18n-micro/core` 的框架 i18n 實例上使用。
- `@i18n-micro/test-utils` 新增對應的 `resolveTranslations` / `setTranslation` 輔助函式，供單元測試使用。

### 從 Vue 套件移除 `getAllTranslations()` {#getalltranslations-removed-from-vue-package}

請使用 `resolveTranslations()` 取得使用中的查詢樹。若要在 Vue 中取得完整的儲存內容，請使用 `getStorage()` 或 `getRouteCache()`。

## 破壞性變更 {#breaking-changes}

一般使用情境下，公開設定介面中沒有任何變更需要修改應用程式程式碼。如果您直接存取了執行階段內部實作，以下事項就很重要：

- **SSR payload 從 `useState('i18n-ssr-chunks')` 移至 `nuxtApp.payload.data['i18n-ssr-chunks']`。** 它仍然攜帶 SSR 期間載入的每個 `(locale, route)` 的**完整翻譯區塊** — 與先前相同的字典，只是放在 Nuxt 可以在預渲染時外部化到 `_payload.json` 的位置。`useState('i18n-ssr-chunks')` 現在不會回傳任何內容。以這種方式讀取翻譯從未受到支援，但快取 API 文件中曾有描述，因此在此特別說明。
- **`NuxtTranslationLoaderOptions` 公開 `setSsrChunk`。** 載入器在伺服器上載入時，會將每個合併後的區塊寫入 `payload.data`。不再使用 `getSsrChunks`。
- **`nitro.compressPublicAssets` 現在會在複製的 payload 旁產生 `.gz` / `.br`。** 若您已啟用此選項，公開輸出中的檔案會變多。列舉翻譯目錄的部署工具可能需要將其納入考量。
- **升級時 payload URL 會變更一次**，因為 `?v=` 從建置時間戳記改為內容指紋。用戶端會在升級後的第一次請求重新下載字典，之後在後續部署中持續保留 — 這正是重點所在。
- **從 `@i18n-micro/vue` 移除 `getAllTranslations()`。** 請改用 `resolveTranslations()` / `getStorage()` / `getRouteCache()`。

## 錯誤修正 {#bug-fixes}

- **`<i18n-switcher>`** — 從下拉選單中省略 `disabled: true` 的 locale。`$getLocales()` 仍會為您自己的程式碼回傳完整清單，而內建的 SEO/meta 輸出則會排除已停用的 locale。
- **切換器樣式** — `cursor: not-allowed` 透過 `activeLinkStyle` / `customActiveLinkStyle` 套用於**目前**的 locale；為了向後相容而恢復 `customDisabledLinkStyle`，並在目前 locale 為 `disabled: true` 時將其套用於切換器按鈕。
- **Dev HMR** — 未改變檔案內容的寫入（編輯器失焦時儲存、格式化工具重寫）不再觸發重新合併。根 locale 的變更會重建該 locale 的每個頁面，因此花在無效操作上的成本很高。
- **Dev HMR** — 根 locale 變更時，頁面會並行重新合併，而非逐一處理。
- **頁面轉場** — 相同 locale 的導覽會將離開頁面的區塊保留為後備 layer，直到 `page:transition:finish`，而不是在每次導覽時進行昂貴的深度合併。

## 為何重要 {#why-it-matters}

- 無需引入更龐大的技術堆疊，即可使用 Vue I18n 風格的格式化。
- 對 CDN 友善的翻譯 URL，在字典未變更時於重新建置間保持穩定。
- 受支援的執行階段 API，可檢查並修補即時字典 — DevTools、測試與編輯器不再需要私有輔助函式。

完整的變更記錄將隨版本發布於 [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md)。

**日期**：2026-07-03

伺服器端重新導向外掛（`06.redirect.ts`）現在會在偵測 locale 之前，從 `getRequestURL(event).pathname` 中移除 `runtimeConfig.app.baseURL`。修正應用程式部署於子路徑時的 `ERR_TOO_MANY_REDIRECTS`（例如 `/examples` → `/examples/ja` 只發生一次，而非 `/examples/ja/examples/ja/...`）。
