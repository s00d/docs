**日期**：2026-05-25

**版本**：`v3.19.0`

![v3.19.0 發行](/images/3.19.0.png)

此版本著重於**將內部工具模組化**、新增**精簡的無伺服器酬載模式**，以及在 Nuxt、Node、Astro 與 DevTools 之間**重複使用共用邏輯** — 而一般應用程式所使用的公開模組 API 則維持不變。

## 有哪些新功能？ {#what’s-new}

### `@i18n-micro/utils` — 與框架無關的工具 {#@i18n-micro/utils-—-framework-agnostic-utilities}

先前分散在 `src/runtime/utils/` 與 `src/module.ts` 中的共用邏輯，現在集中於一個專用的 workspace 套件，並提供**細粒度的子路徑匯入**（沒有臃腫的 barrel 檔，有利於 tree-shaking）：

- **建置** — `preMergeLocales`、`buildTranslationSourceLayers`（`@i18n-micro/utils/build`）
- **酬載** — `translationPayloads` 解析、URL 建構、fetch 輔助函式、統計資料（`payload-config`、`payload-url`、`payload-fetch`、`payload-stats`）
- **Source 模式** — 備援鏈、來源檔案路徑、執行階段合併（`merge-source`、`source-loader`）
- **執行階段輔助函式** — locale 解析、cookie、Accept-Language 剖析、路由／meta 輔助函式（`resolve-locale`、`accept-language`、`cookie`、`route`、`route-pattern`、`runtime-config`）
- **共用的檔案系統路徑** — 翻譯檔案分類、巢狀頁面路徑（`parse-path`）

Nuxt 模組在 `src/runtime/` 中只保留精簡的銜接程式碼，並僅匯入所需的子路徑。

### `@i18n-micro/hmr` — 開發環境翻譯熱重載 {#@i18n-micro/hmr-—-dev-translation-hot-reload}

開發環境的 HMR 已抽離至 `@i18n-micro/hmr`：

- **`watcher`** — 開發環境中的檔案變更處理、快取失效、source／premerged 合併
- **`generate-plugin`** — 產生用戶端 HMR 外掛
- **`cache-keys`** — 供伺服器／儲存快取使用的共用 `Symbol.for` 鍵

同時支援 `translationPayloads.mode: 'premerged'` 與 `'source'`。

### `translationPayloads.mode: 'source'` — 精簡的無伺服器部署 {#translationpayloads-mode-‘source’-—-compact-serverless-deployments}

針對在無伺服器平台（Cloudflare Workers 等）上擁有大量 locale 組合的情況，新增的酬載模式：

```typescript
export default defineNuxtConfig({
  i18n: {
    translationPayloads: {
      mode: 'source',
    },
  },
})
```

- 將**精簡的來源檔案**打包進 Nitro 資產，而非完整的預先合併矩陣
- 透過內建的 `/_locales/:page/:locale/data.json` 路由，**在執行階段**合併根層級、頁面與備援 locale 鏈
- `publicAssets` 與 `prerenderRoutes` 預設為 `false` — 適合仰賴 Nitro／邊緣執行環境而非純靜態託管的情況

請參閱[部署 — 無伺服器與邊緣](/zh-Hant/guide/deployment#serverless-and-edge)以及[快取與儲存架構](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api)。

### 整合套件間的共用工具 {#shared-utilities-across-integration-packages}

- **`@i18n-micro/node`** 與 **`@i18n-micro/astro`** — 透過 `@i18n-micro/utils/parse-path` 統一翻譯路徑剖析與深層合併
- **`@i18n-micro/astro`** — 使用來自 `@i18n-micro/utils/accept-language` 的 `detectLocaleFromAcceptLanguage`（移除重複的剖析器）
- **`@i18n-micro/devtools-ui`** — 透過 `merge-source` + `parse-path` 輔助函式處理虛擬檔案路徑
- **伺服器 locale 偵測** — Accept-Language 處理與共用工具保持一致

### HMR 與 DevTools 修正 {#hmr-&-devtools-fixes}

- 用戶端 HMR 外掛現在呼叫 **`$loadPageTranslations`**（正確的 API），而非已移除的 `$loadTranslations`
- 為 **premerged** 與 **source** 模式下的翻譯監看器加入 Playwright 測試覆蓋

## 破壞性變更（進階／內部） {#breaking-changes-advanced-/-internal}

這些變更僅影響匯入了**內部**模組路徑（不屬於公開 API）的專案：

- 已從 `src/runtime/utils/` 移除：`route-utils.ts`、`runtime-i18n-config.ts`，以及其他已移至 `@i18n-micro/utils/*` 的工具
- 已從 `src/runtime/server/plugins/` 移除：內嵌的 HMR 監看器／產生器 — 若您 fork 了開發工具，請改用 `@i18n-micro/hmr/*`
- **`nuxt-i18n-micro`** 現在依賴 `@i18n-micro/utils` 與 `@i18n-micro/hmr` workspace 套件（會隨模組自動安裝）

一般的 `nuxt.config` + composables 用法維持不變。

## 為什麼這很重要 {#why-it-matters}

- **更小的無伺服器套件** — `source` 模式避免為每個 locale × 頁面都附帶一份預先合併的檔案
- **單一事實來源** — 路徑剖析、合併、locale 偵測與酬載設定都只有一套實作
- **更容易維護** — 與框架無關的程式碼在 `@i18n-micro/utils` 中經過測試（50 個以上的單元測試），並在各處重複使用
- **更好的開發體驗** — HMR 邏輯被隔離、可測試，且在不同酬載模式間保持一致

完整的提交清單請參閱[變更日誌](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md)。
