本頁列出升級 nuxt-i18n-micro 及其 `@i18n-micro/*` 套件時，你的應用程式會有哪些變化。在更新相依套件之前，請先閱讀你目前所用版本對應的章節。大多數應用程式只需要少量的程式碼變更。

<Tip>

**從 `@nuxtjs/i18n` 遷移過來？** — 請參閱[從 @nuxtjs/i18n 遷移](/zh-Hant/guide/migration)。

</Tip>

## 3.30.3 之後：主要版本 {#after-3-30-3-the-major-release}

模組選項、`$t`、`$localePath`、`$switchLocale` 及其他輔助函式、元件、composables 與文件中記載的伺服器工具都保留了原本的名稱。改變的是行為，大多是錯誤修正。轉接器套件與路由套件則有真正的 API 破壞性變更：請參閱[框架套件](#framework-packages)與[其他套件](#other-packages)。

### 優先處理事項 {#do-this-first}

1. **檢查版本。** 模組需要 Nuxt 3.18 或更新版本，以及 Node 20 或更新版本。Nuxt 本身有自己的 Node 最低版本要求：Nuxt 4.5 宣告為 `^22.19.0 || ^24.11.0 || >=26.0.0`。在 Nuxt 3.18.0 上執行 `nuxt generate`，即使是純 Nuxt 也會失敗（`[unstorage] Invalid key: "/"`）；3.21.11 則可正常運作。`@i18n-micro/react` 需要 React 18 或更新版本。
2. **修正已安裝的套件。**
   - 移除 `@i18n-micro/hmr`。翻譯 HMR 已內建於模組中。
   - 如果你的測試會匯入 `@i18n-micro/test-utils`，請將其加入：`npm install -D @i18n-micro/test-utils`。它不再隨模組一起安裝。
   - 將 `nuxt-i18n-micro-cli` 替換為 `@i18n-micro/cli`。28 個命令縮減為 16 個，`check` 取代了其中三個，而且結束代碼也有所變更：請參閱 [CLI 指南](/zh-Hant/guide/cli#moving-from-nuxt-i18n-micro-cli)。
3. **在程式碼中搜尋**下表所列的項目。
4. **檢查位於應用程式前方的服務。** 若在 proxy 後方的 locale 上使用 `baseUrl`，請參閱[位於 proxy 或 CDN 後方](/zh-Hant/guide/deployment#behind-a-proxy-or-cdn)。若使用 CDN，請對照 `Vary` 標頭檢查其快取鍵：請參閱[快取 HTML](/zh-Hant/guide/deployment#caching-html)。若使用 `apiBaseClientHost` 或嚴格的 CSP，請允許新的 `preload` 連結：請參閱 [SEO 與 head 標籤](#seo-and-head-tags)。
5. **更新快照。** head 快照會多出 `preload` 連結，切換器的標記已變更（[`<i18n-switcher>` 與 `<i18n-link>`](#&lt;i18n-switcher>-and-&lt;i18n-link>)），而 `$localeRoute` 輸出中的查詢字串編碼方式也不同了。
6. **以每個 locale 開啟你的頁面，檢查是否出現原始鍵。** 使用上一頁檔案中之鍵的版面配置，現在會直接顯示原始鍵：請將這些鍵移到根檔案中。

<Warning>

**`@i18n-micro/path-strategy` 的 `switchLocaleRoute` 移除了第一個參數** — `switchLocaleRoute(fromLocale, toLocale, route, options)` 現在變成 `switchLocaleRoute(toLocale, route, options)`。**舊的 JavaScript 呼叫不會失敗：它會回傳錯誤的結果，**因為 `fromLocale` 會被當作目標，而 `toLocale` 會被當作路由。只有 TypeScript 會提醒你。Nuxt 的 `$switchLocaleRoute` 不受影響。

</Warning>

| 搜尋 | 處理方式 |
| --- | --- |
| 來自 `@i18n-micro/path-strategy` 的 `switchLocaleRoute(` | 移除第一個參數，請見上方說明 |
| `dependsOn` 中的 `i18n-plugin-hooks` 或 `i18n-plugin-define` | 改用 `i18n-plugin-loader`。舊名稱不再等待任何東西，也不會出現錯誤 |
| `router.push({ name })` 中的 `localized-…` 名稱 | 將頁面本身的名稱傳給 `$localeRoute` 或 `<i18n-link>` |
| `$localeRoute` 或 `$switchLocaleRoute` 結果上的 `.name` 或 `.params` | 處理它們不存在的情況，請參閱[連結](#links-and-route-objects) |
| 在 locale 上使用 `baseUrl` 時，於 `<NuxtLink :to>` 或 `router.push` 中使用 `$localeRoute(x, 'fr')` | 改用 `$localePath`，請參閱 [Locale 網域](#locale-domains) |
| `$getI18nConfig().globalLocaleRoutes`，或從中讀取 `isSSG`、`hmr`、`hooks`、`noPrefixRedirect`、`routeLocales`、`routeDisableMeta` | 它們已從執行階段設定中移除。只有建置會讀取它們，而這些選項本身並未改變。`ModuleOptionsExtend.isSSG` 仍保留為選用、已棄用且不會被任何地方設定的屬性 |
| 除了 `useLocaleServerMiddleware`、`useTranslationServerMiddleware`、`loadTranslationsFromServer`、`detectCurrentLocale` 以外的伺服器自動匯入 | 移除它們。`getI18nServerConfig`、`detectRequestLocale`、`getRequestLocale`、`loadLiveDevTranslations`、`getOrCreateServerTranslationCache`、`DEFAULT_SERVER_CACHE_SIZE` 以及監看器輔助函式不再自動匯入 |
| 來自 `nuxt-i18n-micro` 的 `resolveTranslationPayloadMode`、`resolveTranslationPayloadOptions`、`resolveTranslationPayloadPublicDir`、`resolveTranslationPayloadPublicRel`、`shouldCopyTranslationPayloadsToPublic`、`shouldRegisterNitroServerAssets` | 移除它們。`TranslationPayloadMode` 型別仍保留 |
| 在 `<i18n-t>` 上使用 `html` 且 `params` 中含有標記 | 將標記移入翻譯中，請參閱 [`<i18n-t>`](#&lt;i18n-t>) |
| `<i18n-t>` 上的 `ref` | 它是函式型元件，因此 `ref` 不會取得任何實例 |
| `useI18n().$t = stub` 及類似的寫入 | `useI18n()` 在每個應用程式中是同一個物件，因此寫入會影響所有呼叫者。請直接 stub `useI18n` 本身 |
| `ModuleHooks` 型別 | 已重新命名為 `ModuleRuntimeHooks` |
| 來自 `@i18n-micro/utils/resolve-locale` 的 `resolveServerLocale`、`resolvePreferredLocale` | 以 `url`、`query`、`state`、`cookie` 與 `acceptLanguage` 呼叫 `resolveLocale` |

`detectCurrentLocale` 已棄用。它仍可運作，也仍是伺服器自動匯入；請改用 [`useLocaleServerMiddleware(event).current`](/zh-Hant/guide/server-side-translations)，它套用相同的規則。

本文件有 17 個頁面已搬移。舊 URL 會重新導向，因此指向它們的連結仍可正常運作。

### URL 與重新導向 {#urls-and-redirects}

- **在 `prefix_except_default` 下，`/en` 與 `/en/...` 會回傳 404**（`en` 為預設 locale），與文件記載一致。
- **大小寫或拼寫不同的 locale 前綴會回傳 404。** `/DE/about` 過去會以預設 locale 渲染德文路由，或重新導向至 `/en/DE/about`。若該 URL 本身就有對應的頁面，則仍會是該頁面。catch-all 或 `[slug]` 頁面不算：`[...slug]` 下的 `/DE/x` 以及 `[slug]` 旁的 `/DE` 也會回傳 404，因此與某個 locale 代碼僅大小寫不同的 CMS slug 會失去其頁面。使用 `ssr: false` 時沒有伺服器回應，因此 `/DE/about` 會顯示德文頁面。
- **大小寫不同的頁面路徑會重新導向至其正確拼寫。** `/T/BASIC` 過去回傳 200，現在會以 `302` 重新導向至 `/t/basic`。
- **未知的 URL 仍回傳 404。** 使用 `autoDetectPath: '*'` 或 `'no_prefix'` 時，`/nope` 不再先重新導向至 `/de/nope`。`prefix` 保留此重新導向（該策略下不提供任何無前綴的內容），所有策略下的 `/` 也一樣。
- **在 `prefix_except_default` 下，其他 locale 的無前綴自訂路徑可以找到其頁面。** `/a-propos` 過去回傳 404，現在會以 `302` 重新導向至預設 locale 的 URL（`/about`）。在 `prefix` 下，相同的重新導向現在會抵達實際存在的頁面（`/en/about`，過去是 `/en/a-propos`，回傳 404）。`prefix_and_default` 仍回傳 404。
- **`prefix` 搭配 `redirects: false` 時，無前綴的 URL 會回傳 404**（`/about` 過去是 `302`），包括在預設 locale 中具有自訂路徑之頁面的原始 URL。`$localePath('/about')` 仍能找到該頁面。
- **在 `prefix_except_default` 下，在預設 locale 中具有自訂路徑之頁面的原始 URL 會重新導向至該自訂路徑，**動態頁面也一樣。`/dir/one` 過去回傳 404，現在會以 `302` 重新導向至 `/dir-one/one`。
- **`autoDetectPath: '*'` 現在也會將 cookie 與 `Accept-Language` 套用到無前綴的路徑**（`/about` → `/de/about`）。
- **在 `prefix` 下，無前綴的 URL 會保留訪客的 locale。** cookie 為 `de` 時，`/about` 與一般的 `<NuxtLink to="/about">` 會前往 `/de/about`，在所有路徑上皆是如此，無論 `autoDetectPath` 如何設定。
- **在 `prefix_and_default` 下，無前綴的 URL 即為預設 locale。** 帶有 `Accept-Language: de` 的 `/contact` 過去會先以德文渲染，再以英文 hydrate。現在它會以預設 locale 渲染；訪客可透過 `/de/...` 進入德文版本。
- **在 `no_prefix` 下，自訂路徑會以其自身的 locale 渲染**（無論偏好為何，`/ueber-uns` 都是德文），而受限的頁面會以其所服務的 locale 渲染。多個 locale 共用的路徑若偏好是其中之一，就會以偏好渲染；在 `baseUrl` 下，它在每個對應網域上都是一個頁面。這些 locale 共用一筆紀錄：`localized-<page>-<first locale>`。
- **`noPrefixRedirect` 依訪客的 locale 決定。** cookie 為 `de` 時，`/about` 會前往 `/ueber-uns` 並以德文渲染，而不是前往預設 locale 的 `/about-us`。沒有自己自訂路徑的 locale 會留在 `/about`。
- **沒有頁面的 `routeRules` 重新導向不會被在地化。** `/de/old` 過去回傳空的 200，現在回傳 404：如有需要，請為帶前綴的路徑加入規則。從其他 locale 連結到這類規則時，會保留原本寫的路徑，並抵達規則的目標。
- **路由規則會套用到自訂路徑。** 當 `blog/[slug]` 擁有 `/de/artikel/:slug` 路徑時，`/blog/**` 也會套用到該路徑，而且在 `no_prefix` 下也會複製規則。像 `/de/artikel/news` 這樣的靜態同層路徑也會符合該模式。已經寫在 locale 前綴下的規則則維持原樣。
- **設定 `disabled: true` 的 locale 會立即在其前綴上回傳 404**，而指向它的連結會停留在目前頁面。在執行階段停用的 locale 也一樣：過去它會以 fallback locale 渲染。
- **模組的 404 顯示 `Page Not Found`**，適用於已停用 locale 的前綴以及主機自身的前綴，過去 Nuxt 顯示的是 `Page not found: /de/about`。狀態碼相同。
- **`customRegexMatcher` 不再讓第一個區段看起來像 locale 的真實頁面回傳 404。**
- **在地化路由名稱保持一致。** 位於共用 locale 紀錄下的子路由會保留頁面的名稱，`no_prefix` 會遵循 `localizedRouteNamePrefix`，而帶有 index 子路由的父路由會保持未命名。
- **由模組加入但沒有 `name` 的頁面**（`extendPages`）會被在地化並取得名稱，同時具有 locale 變體與 `hreflang`。過去它們會維持未在地化。
- **`nuxt.config` 中的項目優先於 `$defineI18nRoute`，**無論鍵的寫法為何（`about/team`、`/about/team`、`about-team`）。過去哪一個勝出取決於拼寫方式。
- **新的建置警告：** 以自身 locale 代碼開頭的 `localeRoutes` 值（`fr: '/fr/article'`），以及位於父路由之外的子路由自訂路徑。
- **Hash 模式可在 `prefix` 下運作。** 文件為 `/`，而 `/en` 或 `/about` 會重新導向至 hash 中。
- **在 `prefix_except_default` 與 `prefix_and_default` 下，`/#/de/x` 會以德文渲染。** 過去它會以英文渲染，並出現 hydration 不一致。

### 連結與路由物件 {#links-and-route-objects}

- **不提供某頁面的 locale 會連結到其首頁。** `$localeRoute`、`$switchLocalePath` 與切換器不再回傳其他 locale 的頁面。
- **未知的 locale 代碼會前往預設 locale。** `$localePath(path, 'xx')` 與 `$localeRoute` 過去會回傳 `/xx`。
- **`$localePath` 會原樣回傳帶有 `http(s):`、`mailto:` 或 `tel:` scheme 的字串，而 `$localeRoute` 的 `path` 與 `fullPath` 也會原封不動地保留它**，因此請勿將未經檢查的值（例如 `?next=` 參數）作為連結目標傳給它們。`//host` 以及像 `x.com` 這樣的裸名稱仍會被視為路徑，在每個 locale 中都位於此來源上，且由它們轉換而成的連結都不會離開此來源：`/de//x.com` 轉為預設 locale 時是 `/x.com`。反斜線會被視為斜線。
- **`$localePath` 會對路徑進行編碼：** `/a b` 會變成 `/a%20b`。
- **`$localeRoute` 與 `$switchLocaleRoute` 回傳純物件，**可安全用於 `ref`、`reactive`、`useState`、JSON 與展開運算。當參數需要跳脫時，物件為 `{ path, fullPath, query, hash }`（`$localeRoute` 另外加上 `href`），不含 `name` 或 `params`，且 URL 在重新載入前後保持不變。一般的 URL 則兩者皆有。`name` 是新的：舊物件從未有過它。讀取 `.name` 或 `.params` 的程式碼必須處理它們不存在的情況，而你取得的形式取決於值本身。
- **在 `trailingSlash` 下，`$switchLocaleRoute` 一律回傳該路徑形式，**一般的 slug 也一樣，且伺服器重新導向會遵循 `trailingSlash`。在該選項下，結果與 `Location` 標頭可能會改變。
- **`$localeRoute` 輸出中的查詢值使用 vue-router 的編碼方式：** `/` 保持原樣，空格為 `+`（`?redirect=/v2`，過去是 `%2Fv2`）。解碼後的值相同，但這類 `href` 的快照會改變。
- **沒有路徑的連結會停留在目前頁面。** `$localePath('#top')`、`'?p=2'`、`''` 與 `{ query }` 會保留所在的頁面；`'#top'` 過去會從網站根目錄解析。單純的 `'about'` 仍代表 `/about`。
- **展開運算。** `{ ...route, query }` 與 `{ ...route, hash }` 會保留變更，透過 `$switchRoute` 時也一樣。新的 `path` 在 `$localeRoute`、`$localePath` 與 `$switchRoute` 中優先。`{ ...route, params }` 適用於具名路由；在路徑形式的路由上則以路徑為準，params 會被忽略，並顯示 vue-router 的開發警告。請使用 `$localeRoute({ name, params })`。
- **`$switchRoute` 會留在應用程式內。** locale 自身的 `baseUrl`、`mailto:` 與 `tel:` 會離開應用程式；其他任何字串都會被視為路徑。
- **`excludePatterns`** 會比對完整區段（`'/admin'` 不再符合 `/administrator`），且 glob 會錨定（`/docs/*` 不再符合 `/en/docs/x`）。`RegExp` 模式現在會傳遞到執行階段；過去它們在那裡會遺失。被它們符合的頁面不會被在地化：沒有 `hreflang`，且在 `prefix_except_default` 下使用預設 locale。請對照[排除路徑](/zh-Hant/guide/excluding-static-files)檢查你的模式。

在 Nuxt 4.5.2 上，參數中的 `%` 或 `?` 無法在伺服器渲染的重新載入後保留，任何應用程式皆是如此：這是上游問題，並非模組造成。

### Locale 網域 {#locale-domains}

- **`locales[].baseUrl` 現在會路由請求。** 單一建置即可服務所有網域：請參閱[Layers 與網域](/zh-Hant/guide/layers#multiple-domains)。設定 `baseUrl` 後，屬於其他網域的 locale 在此主機上會回傳 404（`example.de` 上的 `/en/about`），而指向同一主機上 locale 的連結則為相對連結。任何其他主機（包括 `localhost`）上的請求行為與以往相同，只是 canonical 與 `hreflang` 會使用 `metaBaseUrl`（若有設定），否則使用預設 locale 的 `baseUrl`，而不再使用請求的來源。
- **位於會改寫 `Host` 的 proxy 後方時，**所有請求都會落到建置設定，直到你設定 [`trustForwardedHost`](/zh-Hant/api/module-options#trustforwardedhost)。它預設為 `false`，這點與 `metaTrustForwardedHost` 不同。請參閱[位於 proxy 或 CDN 後方](/zh-Hant/guide/deployment#behind-a-proxy-or-cdn)。
- **搭配 `baseUrl` 執行 `nuxi generate` 時需要 `NUXT_I18N_DOMAIN`，每個網域執行一次。** 若未設定，建置會發出警告，而那些 locale 只會是沒有頁面的連結。請參閱[靜態網站](/zh-Hant/guide/deployment#static-site-(nuxi-generate))。
- **指向具有 `baseUrl` 之 locale 的連結需透過 `$localePath` 或 `<i18n-link>`。** `<NuxtLink :to="$localePath(x, 'fr')">` 與 `<i18n-link :to="$localeRoute(x, 'fr')">` 會是該絕對 URL，點擊後即會前往。路由器不接受絕對物件：`<NuxtLink :to="$localeRoute(x, 'fr')">` 與 `router.push($localeRoute(x, 'fr'))` 會變成 `/https://fr.example.com/...`，也就是此應用程式的一個路徑。在 `localhost` 或預覽主機上，每個具有 `baseUrl` 的 locale 都是這樣的連結，包括目前的 locale。在程式碼中請使用 `navigateTo($localePath(x, 'fr'), { external: true })`。
- **網域的首頁在各處都不含結尾斜線**（`https://example.de`），包括連結、canonical 與 `hreflang`。
- **在 `prefix` 下，指向其他網域的連結會保留 locale 前綴，無論是否設定 `baseDefault`。** 是 `https://example.de/de/about`，而不是只會重新導向的 `https://example.de/about`。
- **在 `prefix_except_default` 下，若在建置預設以外的 locale 上設定 `baseDefault`，路由會保留所有前綴**，讓其他網域能連結到它們。`/en` 仍回傳 404。只有讀取 `router.getRoutes()` 的程式碼會察覺差異。
- **在 `prefix_except_default` 下，主機自身的前綴在其 `baseDefault` 主機上會回傳 404。** 過去 `de` 主機上的 `/de/x` 回傳 200。
- **`$getI18nConfig().locales` 只包含該主機所服務的 locale。** `linkLocales` 包含所有 locale，而 `$getLocales()` 仍是完整的。

### 導覽與 `$switchLocale` {#navigation-and-$switchlocale}

- **導覽會在確認（commit）時套用。** 字典、locale、參數與 head 會在 `router.afterEach` 中變更，因此被取消或被阻擋的導覽不會改變任何東西，而在載入下一個區塊期間，舊頁面的連結仍然有效。`beforeResolve`、`beforeRouteEnter` 或較晚的全域守衛現在會看到舊的字典與 locale。路由 middleware 不受影響。
- **區塊載入失敗時會保留目前的字典。** 根檔案發生 5xx、網路錯誤或內容損壞時，過去會顯示原始鍵。現在新頁面會以舊字串渲染，並在下一次導覽時重試。若是 404，或靜態主機在該檔案位置回傳 SPA 外殼，則在下次重新載入前會使用根字典。
- **`$switchLocale` 會 resolve 為 `true` 或 `false`**（過去不 resolve 任何值），當該 locale 的字典未套用時為 `false`。它的型別為 `Promise<boolean>`，而 `$switchRoute` 為 `Promise<void>`。
- **`$switchLocale` 是明確的選擇。** 抵達時它會儲存該 locale，遇到 404 時也一樣。若導覽被阻擋、取消或擲出錯誤，儲存的偏好與狀態會維持原樣，而錯誤會被重新擲出。移至其他主機時會先儲存。在 `no_prefix` 與 hash 模式下，無論導覽結果如何，切換都會生效。在所有 locale 共用同一 URL 的頁面上（`excludePatterns`），選擇不會被撤銷，而由下一個頁面的 URL 決定：在 `prefix_except_default` 下，無前綴的連結會回到預設 locale。
- **在 `no_prefix` 下，當兩個頁面共用一個自訂路徑時，`$switchLocale` 會保留其頁面，**包含跳脫過的參數。重新載入這類 URL，以及帶有跳脫參數的 `$localeRoute`，都會落在第一筆紀錄上。
- **用戶端重新導向會保留其導覽的模式。** 在 `prefix` 下，一般的 `<NuxtLink to="/about">` 會新增一筆歷史紀錄，而不是覆寫目前的紀錄；`router.replace` 仍會取代。
- **來自伺服器的 `$setI18nRouteParams` 與 `useI18nHead` 會在 hydration 後保留。** 抵達 `/news/2` 後，若頁面在 SSR 期間設定了參數，切換器會連結到翻譯後的 slug（`/de/news/2-zwei`），而不是 `/de/news/2`，在伺服器 HTML 中也是如此，無論切換器位於何處。當導覽至其他路徑確認時（包括從 `/news/1` 到 `/news/4`），它們會被丟棄：請在新頁面上再次設定。
- **在 setup 中讀取的 `$setI18nRouteParams` 會綁定到該頁面。** 從已離開的頁面延遲呼叫時不會有任何作用。`useNuxtApp().$setI18nRouteParams` 現在是存取器，兩次讀取會取得兩個不同的函式。它沒有 setter：像測試 stub 可能做的 `useI18n().$setI18nRouteParams = fn`，在嚴格模式下會擲出錯誤，因此請直接 stub `useI18n` 本身。在版面配置或 `app.vue` 中它是一般函式，因為那裡沒有任何東西會被離開。
- **伺服器會在渲染結束時改寫 `<i18n-switcher>` 的連結**，適用於帶有參數的頁面，因為版面配置中的切換器會在頁面的非同步 setup 之前渲染。手寫的 `$switchLocalePath` 連結不會被改寫：請參閱[自訂 locale 路由](/zh-Hant/guide/custom-locale-routes)。在 Nuxt 的 SSR 串流下，第一份 HTML 會保留 URL 的參數。
- **伺服器元件上名為 `locale` 的 prop 會設定其渲染 locale**，因此 `<Greeting :locale="$getLocale()" />` 會跟隨 URL 與切換。元件內的 `$getLocale()`、`$localePath` 與 `$getLocaleName` 也會跟隨該 prop。請參閱[伺服器端翻譯](/zh-Hant/guide/server-side-translations)。沒有該 prop 時，它仍會使用 cookie 或預設值。
- **`keepalive` 頁面在返回時會取回其參數與 head。**
- **在 `prefix_except_default` 下設為 `false` 的巢狀頁面沒有 locale URL。** 設定 `globalLocaleRoutes: { 'parent-kid': false }` 時，`/de/parent/kid` 過去會被提供，現在回傳 404：頁面會留在 `/parent/kid`。

### Locale 偵測與 cookie {#locale-detection-and-the-cookie}

所有地方都使用同一套優先順序，詳見 [Locale 偵測](/zh-Hant/guide/locale-detection)。

- **`?locale=` 僅在 `no_prefix` 下對頁面生效。** 在前綴類策略下由 URL 決定；`/about?locale=de` 不再於 `lang="en"` 下以德文渲染。`?locale=de&locale=fr` 會讀取第一個值，過去是 `"de,fr"`。
- **`Accept-Language` 會遵循 `q` 值**（`fr;q=0.1, de;q=0.9` → `de`；`q=0` 會排除某語言）。地區比對不再受 `locales` 順序影響，也絕不跨越中文書寫系統。
- **用戶端導覽至某頁面時，會將其 locale 儲存至 cookie，包括預設 locale 的無前綴頁面。** 設定 `localeCookie` 後，點擊連結前往 `/about` 的訪客現在會得到 `user-locale=en`，之後變更瀏覽器語言也不再會使 `/` 重新導向。首次載入該 URL 時不會儲存任何內容。在 `no_prefix` 與 hash 模式下，導覽只會儲存變更。
- **404 不會寫入 cookie：** 回應不會寫入，一般的用戶端導覽至 404 也不會寫入，在任何模式下皆然。在 `no_prefix` 下，看起來帶有前綴的 URL 也不會寫入。
- **在 `no_prefix` 下會遵循明確設定的 `localeCookie: null`。** 過去它會變成 `user-locale`。請在 `nuxt.config` 的 `i18n` 區塊中設定：在 `modules: [[name, opts]]` 或 layer 中設定的 `null` 仍會遺失。
- **Hash 模式只讀取 `hash-locale` cookie。** 單獨的 `user-locale=de` 不再生效。
- **格式錯誤的 locale cookie 會被忽略並保持原樣，**而不會讓每個 SSR 頁面都回傳 500。它不再於每次請求時被刪除，這個問題過去也會使帶前綴的頁面無法儲存其 locale。
- **URL 的 locale 優先。** 在 `/en/...` 上，外掛的 `setLocale('de')` 不再載入 `de` 字典，而狀態中的未知代碼會被忽略。
- **伺服器 API 輔助函式**（`useLocaleServerMiddleware`、`useTranslationServerMiddleware`）在每個路由上使用同一順序：`?locale` → `[locale]` 參數或前綴 → cookie → 標頭 → 預設值。它們現在會遵循 `localeCookie: null` 與 `autoDetectLanguage: false`，並為每個 locale 快取字典。
- **執行階段覆寫會影響路由。** `NUXT_I18N_DEFAULT_LOCALE` 與執行階段的 `disabledLocales` 現在會改變產生的策略（停用的 locale 會停止路由），且執行階段的 `disabledLocales` 會加到建置時的設定上。在 `prefix_except_default` 與 `prefix_and_default` 下，執行階段的 `defaultLocale` 會被忽略並顯示警告，因為該 locale 的無前綴路由是在建置時產生的。執行階段的 `fallbackLocale` 必須是已啟用的 locale：否則會被捨棄並顯示警告，若建置時的值已啟用則改用該值。請參閱[執行階段覆寫](/zh-Hant/guide/runtime-overrides)。

### SEO 與 head 標籤 {#seo-and-head-tags}

- **`dir="auto"` 不再是預設值。** 過去沒有 `dir` 的 locale 會得到 `dir="auto"`，這會拖慢大型頁面的解析速度。現在已知的 RTL 語言會得到 `dir="rtl"`，其他 locale 則不會有此屬性。這適用於 Nuxt、`@i18n-micro/vue`、`astro` 與 `vitepress`。若你在 locale 上設定 `dir: 'auto'` 以保留舊的輸出，在 20,000 個元素時約需多花 1 秒解析：請參閱[文字方向](/zh-Hant/guide/seo#text-direction)。
- **每個 SSR 頁面都有一個新標籤：** `<link rel="preload" as="fetch" crossorigin="anonymous" href="/_locales/...">`，404 頁面也一樣。使用 `apiBaseClientHost` 時，`href` 會位於該主機上，因此需要 CORS。嚴格的 CSP 必須允許它。
- **`hreflang` 只列出提供該頁面的 locale**；只有當預設 locale 提供該頁面時才會輸出 `x-default`。
- **未在地化的頁面沒有 `hreflang` 或 `og:locale:alternate`。**
- **當來源取自請求時，canonical 與 `hreflang` 會包含 `app.baseURL`。** `metaBaseUrl` 與 `site.url` 則維持原樣。
- **404 頁面會帶有 `<html lang dir>`**，使用 URL 的 locale。它們沒有 canonical、`hreflang`、`og:url`、`og:locale` 或替代連結，當模組本身在符合的紀錄上（`/en/...`）回應 404 時也一樣。你透過 `useI18nHead` 的 `replace` 傳入的標籤會保留，因此請在錯誤頁面上略過它們。
- **canonical、`og:url` 與 `hreflang` 會保留白名單中的查詢參數**（`/about?page=2`），在伺服器上也一樣：過去在 SSR 期間會被捨棄。`page`、`sort`、`filter`、`search`、`q`、`query` 與 `tag` 預設在白名單中；請參閱 [`canonicalQueryWhitelist`](/zh-Hant/api/module-options#canonicalquerywhitelist)。
- **無法解析的 `X-Forwarded-Host` 會被忽略**，而不會讓每個頁面都回傳 500。若沒有可用的主機，也沒有 `metaBaseUrl` 或 `site.url`，該回應中的 canonical 與 `hreflang` URL 會是相對路徑。無法解析的 `Host` 仍回傳 500，與一般 Nuxt 應用程式相同。
- **`disableMeta` 現在可以正常運作，**在 `$defineI18nRoute` 與 `routeDisableMeta` 中皆然，在 `nuxt.config` 中設定時也一樣：頁面不會有 `hreflang`、canonical 或 `og:locale`。`lang` 與 `dir` 會保留。
- `useLocaleHead()` 也會回傳 `build()`，這是供 `useHead(() => build())` 使用的 getter。
- 在未設定 `metaBaseUrl` 的一般建置中，`X-Forwarded-Host` 仍會像以前一樣決定這些標籤中的主機。若來源可被直接存取，請固定設定 `metaBaseUrl`：請參閱[位於 proxy 或 CDN 後方](/zh-Hant/guide/deployment#behind-a-proxy-or-cdn)。

### 翻譯 {#translations}

- **每一層都會進行深度合併。** 根、頁面與 fallback 檔案過去使用兩層合併，因此在 source 模式與開發模式下，來自 fallback 或根的 `a.b.c` 會遺失。現在所有模式都會產生相同的字典。
- **fallback 鏈會一路追蹤到底**（`fr` → `de` → `en`），在所有模式下皆然。
- **合併依 locale 進行，而非依檔案種類。** 目前 locale 的根檔案現在優先於 fallback locale 的頁面檔案。請參閱 [Fallback locales](/zh-Hant/guide/translations#fallback-locales)。
- **對於相同的 `code`，專案的 `locales` 項目優先於 layer 的項目**；layer 只會填補缺漏。
- **沒有自己 `pages/<name>/` 資料夾的頁面會讀取根字典，**子頁面也一樣。過去它會得到 `{}` 並顯示原始鍵。輸出中會為每個這類頁面多出一個檔案，並為每個 locale 多出 `__root/<locale>/data.json`：`/_locales/<any name>/en/data.json` 會回傳帶有根鍵的 200，過去是 `{}`。這會影響監控、靜態主機上的允許清單，以及讀取該樹狀結構的工具。
- **`disablePageLocales: true` 只會讀取根檔案；** `pages/index` 不再被合併進來。
- **離開頁面的鍵會在其元素離開文件時停止解析。** 如果版面配置使用了只有上一頁檔案才有的鍵，請將它們移到根檔案中。在子頁面顯示期間，父頁面的鍵會保留（包括帶有 `index` 子頁面的父頁面），直到下一次導覽為止。在同一父頁面的兩個子頁面之間切換時，父頁面自身的鍵需要子頁面的字典或根字典提供。
- **`$clearCache()` 會重新載入目前頁面的字典**，並在新字典抵達前保持舊字典顯示於畫面上。重新載入失敗時會保留舊字典，在清除前發出之請求的回應會被丟棄，而處於離開轉場中的頁面會保持已翻譯的狀態。
- **`$has(key, route)` 會遵循路由。**
- **在尚未造訪的頁面上呼叫 `$loadPageTranslations`，不再阻止其檔案載入。** 檔案會在第一次造訪時載入，而你的鍵會保持在其之上。過去頁面在重新載入前都會顯示原始鍵。
- **翻譯 HMR 會就地套用編輯**，不需重新載入頁面；被移除的鍵會消失，而根的編輯會影響每個頁面。
- **損壞的 locale 檔案會在所有模式下以其路徑警告一次。** 過去開發模式會擲出錯誤，而 premerged 模式會靜默略過，因此依賴開發模式嚴重失敗的應用程式將不再看到該行為。

### 複數與格式化 {#plurals-and-formatting}

- 對 `$tc` 傳入負數、小數或極大的數量時，會以實際數量取最後一種形式；`{ count: null }` 不再擲出錯誤；缺少的複數鍵會傳遞到 missing handler。
- `$tdr` 會正確產生未來日期（`in 3 days`，或在 `numeric: 'auto'` 時為 `tomorrow`），無效輸入則為 `Invalid Date`。過去未滿一秒時為 `0 seconds ago`。
- **`$tn`、`$td` 與 `$tdr` 依 `iso` 決定**，與複數相同：`{ code: 'en', iso: 'en-GB' }` 現在會將日期格式化為 `31/10/2026`。在 locale 代碼中 `_` 會被視為 `-`，因此 `en_US` 不再擲出錯誤，而 `Intl` 不認得的代碼會以 `en` 格式化，而非跟隨機器的 locale。具名格式仍依 `code` 查找。
- `{param}` 預留位置只會讀取你傳入的參數（`{constructor}` 維持原樣）。
- `{placeholder}` 名稱可以包含除大括號與空格以外的任何字元：`{firstName}`、`{first-name}` 與 `{user.name}` 都會從 `params` 讀取。若沒有對應的參數，它們會像以前一樣維持原樣。
- `defaultValue` 會在 `$t` 與 `$tc` 中進行插值：`$t('missing', { n: 1 }, 'Got {n}')` 會得到 `Got 1`，過去是 `Got {n}`。不是字串的預設值會原樣回傳。
- 對空翻譯呼叫 `$tc` 會回傳 `''`，與 `$t` 相同。過去它會回傳預設值或鍵。
- **複數範本保持原有意義，只有一個例外。** 下表列出所有形式。若要取得 `Intl.PluralRules` 類別，請使用新的 [`=0 ` 標記](/zh-Hant/api/methods#$tc)明確指定：`=0 no apples | one apple | {count} apples`。

  | 形式 | 範例（`uk`） | 之前 | 現在 |
  | --- | --- | --- | --- |
  | 在只有一或兩個整數類別的 locale（`en`、`de`、`fr`、`es`、`ja`...）中的任何範本 | `none \| one \| {count} many` | 依索引 | **不變** |
  | 每個類別一種形式 | `one \| few \| many` | 依索引：21 → `many` | **不變**。加上標記可得 21 → `one` |
  | 零形式在前，共三種形式 | `none \| one \| many` | 依索引 | **不變** |
  | 其他預留位置 | `no items \| {n} item \| {n} items` | 依索引 | **不變** |
  | 每種形式都有 `{count}` | `{count} many \| {count} one \| {count} few` | 依索引 | **不變** |
  | 形式數量少於或多於下方所列 | `a \| b`, `none \| one \| two \| {count} many` | 依索引 | **不變** |
  | 在 `lv`、`prg`、`blo`、`cv`、`ksh`、`lag` 中 | `none \| one \| {count} many` | 依索引 | **不變** |
  | 以 `=0 ` 標記 | `=0 none \| one \| many` | 標記會以文字顯示 | 零形式，接著是各類別 |
  | **不含預留位置的零形式，接著每個類別一種形式，且在多個數量共用的每種形式中都有 `{count}`** | `none \| {count} one \| {count} few \| {count} many` | 依索引：3 → `3 many`，21 → `21 many` | **依類別**：3 → `3 few`，21 → `21 one`。0、1、2 以及所有仍屬於 `many` 的數量結果相同 |

  最後一種形式需要三個或更多類別（`ru`、`uk`、`pl`、`cs`、`sk`、`hr`、`sr`、`lt`、`ro`、`sl`、`he`、`ar`、`cy`...）。在 `ar` 中，`one` 與 `two` 各對應單一數量，因此這兩種形式不需要數字。
- **`Intl` 不認得的 locale 代碼會使用索引規則**，無論是否使用標記的類別：`ua` 不再跟隨機器的 locale。請設定 `iso`：`{ code: 'ua', iso: 'uk-UA' }` 會以烏克蘭語的規則處理複數，在模組與 `@i18n-micro/vue` 中皆然。
- **自訂的 `plural` 規則保留其簽章**，且仍會取得 locale 代碼。它讀取的是原始值，因此帶有標記的範本傳到它時 `=0 ` 仍在原位，而它取得的數量為 `Number`：過去取得 `1` 的地方現在會是 `1.5`。回傳 `null` 會退回內建規則，而內建規則會遵循標記。
- **`timeZone` 選項。** 設定它（`Europe/Berlin`）可讓伺服器與每個瀏覽器渲染同一個日曆日期。它對 `relativeDate` 沒有影響，因為後者取決於時鐘。

### `<i18n-t>` {#&lt;i18n-t>}

本節涵蓋模組中的 `<i18n-t>` 與 `@i18n-micro/vue` 中的 `I18nT`。其他框架請參閱[框架套件](#framework-packages)。

- **`html` 在任何情況下都會跳脫 `params`，並忽略所有插槽。** 只有翻譯被視為可信任的標記。刻意包含標記的參數現在會以文字顯示：請將標記放入翻譯中並以參數傳入資料，或在不使用 `html` 的情況下改用插槽。
- **插槽可搭配 `plural`、`number`、`date` 與 `relativeDate` 使用，**在這些情況下 `default` 插槽也會收到 `{ translation }`。每個 `{name}` 都會被填入，而不只是第一個。
- **插槽優先於同名的參數。** 看起來像預留位置的參數值會維持為文字。使用 `customPluralRule` 或自訂 `plural` 時，規則會回傳已完成的字串，因此其中被插值的參數可能會被誤認為預留位置。
- **對 `plural`、`number`、`date` 與 `relativeDate` 而言，`null` 代表未設定。** `:plural="null"` 過去會導致渲染失敗，`:date="null"` 會渲染出 1970 年。
- `plural` 以 `Number` 計數，與 `$tc` 相同：`1.5` 會維持 `1.5` 並取最後一種形式，過去會被截斷為 `1`；`"2 items"` 為 `NaN`，過去是 `2`；`""` 為 `0`。`customPluralRule` 也會看到 `1.5`。它的其他約定不變：參數相同，其回傳值會原樣使用，`null` 會渲染為空。
- `hideIfEmpty` 適用於 `plural`、`number`、`date` 與 `relativeDate`。隱藏的值會渲染為註解，而非空的文字節點，因此讀取 `''` 的測試會看到 `<!---->`。
- **在 `html` 下缺少的鍵會以文字呈現。** 鍵會被跳脫，因為只有翻譯是可信任的，而鍵可能來自請求。`defaultValue` 由你提供，因此仍視為標記。
- 使用 `plural` 時，找不到翻譯時 `defaultValue` 或鍵會完整呈現，與 `$tc` 相同：`a | b` 不再被拆分。
- 在每個分支中，`defaultValue` 都會取代缺少的鍵，而不是顯示鍵本身；找不到翻譯時，`customPluralRule` 會透過其 getter 取得它。過去它只在 `hideIfEmpty` 之後才有作用。
- 帶有 `number`、`date` 或 `relativeDate` 的 `<i18n-t>` 會保留 `params`；它們會被合併進來。
- `date` 與 `relativeDate` 的輸出帶有 `data-allow-mismatch="text"`：伺服器與瀏覽器之間時鐘或時區不同時，hydration 期間不再發出警告。在具名插槽旁，插槽周圍的文字會放在自己的 `<span>` 中，因為 Vue 只會檢查元素單一文字上的該屬性。
- `.innerHTML` 與 `textContent` 屬性會與 `innerHTML` 一起被捨棄。
- `<i18n-t>` 與 `<i18n-group>` 會讀取目前啟用的字典，與 `$t` 相同，而不是路由的區塊。被逐出的區塊（`cacheMaxSize`）不再顯示原始鍵。處於離開轉場中的頁面現在會讀取 `$t` 在該處讀取的內容：新頁面的字典，找不到時再退回自己的字典，因此兩個頁面都定義的鍵會顯示新文字，而在切換 locale 後，其自身的鍵會以原始鍵顯示，直到它被卸載為止。

### `<i18n-switcher>` 與 `<i18n-link>` {#&lt;i18n-switcher>-and-&lt;i18n-link>}

- **點擊切換器連結只會產生一次導覽。** 它是一個呼叫 `$switchLocale` 的一般 `<a>`，而不是 `NuxtLink` 加上點擊處理器，因此 `router-link-active` 類別已移除。`href` 仍帶有 `app.baseURL`，而目前 locale 的連結仍帶有 `aria-current="page"`。Ctrl/cmd 點擊會開啟新分頁，且不影響目前的分頁。連結會保留查詢參數與 hash。
- 按鈕為 `type="button"`，因此不再提交外層的表單，並帶有 `aria-expanded`。`aria-haspopup` 已在模組、`@i18n-micro/vue` 與 `@i18n-micro/astro` 中移除：它暗示有選單，但清單其實是連結。按下 Escape 或點擊外部會關閉下拉選單；兩個切換器不再同時保持開啟。
- 外層容器與下拉選單分別帶有 `i18n-switcher-wrapper` 與 `i18n-switcher-dropdown` 類別；按鈕除了 `language-switcher` 外也帶有 `i18n-switcher-button`，其標籤位於 `<span>` 中。預設樣式使用邏輯 CSS 屬性（`inset-inline-start`、`margin-inline-start`），而插入符號為 `▾`。下拉選單具有 `z-index: 1000`（過去為 10）、`min-width: 150px` 與 `box-shadow`，外層容器具有 `vertical-align: middle`。每個連結都帶有 `lang`，當 locale 設定 `dir` 時也會帶有 `dir`。
- `<i18n-link>`：`https://`、`mailto:` 與 `tel:` 的比對不分大小寫（`HTTPS://x.com`、`Mailto:`）。單純的 `report.pdf` 或 `index.html` 會被視為路由，而不是 `https://report.pdf`；`example.com` 與 `example.com:8080` 仍是外部連結。同時也是 TLD 的檔案結尾（`example.md`、`x.zip`）會被視為檔案：請寫上 `https://`。`activeStyle` 會忽略結尾斜線、查詢參數與 hash。它現在的型別為 `CSSProperties`，因此某些有型別的值可能需要調整。

### Hooks、外掛與型別 {#hooks-plugins-and-types}

- **`i18n:register` 會在啟動時於 `app:created` 執行，**也就是在所有外掛之後，而不是在外掛之間。`order` 大於 1 或設定 `enforce: 'post'` 的外掛，其訂閱者現在也會在啟動時被呼叫，但不再能在自己的 `setup` 中讀取已註冊的鍵。在導覽時，此 hook 現在會在其他外掛的 `router.beforeEach` 守衛之前執行。
- **`i18n:register` 會取得其所填入之頁面的 locale。** 在 `hashMode` 下，改變 locale 的導覽過去會傳入舊的 locale，導致鍵落在錯誤的區塊中。
- **`i18n:register` 是執行階段 hook：** 請在外掛中以 `nuxtApp.hook('i18n:register', …)` 註冊，不需要 `@ts-expect-error`。請參閱 [Hooks](/zh-Hant/api/events)。
- **`hooks: false` 與 `define: false`** 仍會關閉各自負責的部分。
- **設定 `plugin: false` 時，`$defineI18nRoute` 仍可呼叫**，且在執行階段不會有任何作用。過去它會讓頁面當機。
- `hooks` 選項不再記載 `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`；它們從未被觸發過。
- 在頁面中使用 `const { $defineI18nRoute } = useNuxtApp()`，現在可搭配使用變數的設定。
- `useI18n()` 有更多鍵：`clearCache`、`pluralFunc`、`pluralLocale`。`clearCache` 已包含在其型別中。
- `$getRouteName(route)` 會針對傳入的路由回傳結果。過去它回傳空字串。
- `useI18nLocale()` 移除了 `getLocaleWithServerFallback(serverLocale)`：請改寫為 `getPreferredLocale() ?? serverLocale ?? null`。
- **在開發模式下，`$getI18nConfig()` 在伺服器上是唯讀的。** 在該處寫入會擲出錯誤，而在正式環境中，寫入會影響每個請求。

### 伺服器、建置與部署 {#server-build-and-deployment}

- **頁面的 payload 檔案只包含與該 locale 根不同的部分。** 用戶端會載入根一次，再將每個頁面合併於其上，因此磁碟與 Edge bundle 會縮小，而第二個頁面的成本只有第一個的一小部分。`premerged` 現在會寫入 `__root/<locale>/data.json`，而 `/_locales/<page>/<locale>/data.json` 只包含差異：任何直接讀取這些檔案的程式都必須合併兩者。完整的字典仍是有效的檔案，因此提供完整字典的主機或 `source` 模式仍可正常運作。
- **字典檔案依版本快取。** 帶有目前 `?v=` 的 URL 在 Node 伺服器上會被固定快取一年，其他 URL 會重新驗證，而主機的靜態副本回應 `max-age=60`：請參閱[快取標頭](/zh-Hant/guide/deployment#cache-headers-and-datebuild)。`httpCacheControl: false` 會保留 `max-age=0`。未重新建置而變更的翻譯，只有在 `v` 改變時才會傳到瀏覽器：請設定 `NUXT_I18N_DATE_BUILD`。
- **字典會跟隨 `app.cdnURL`。** 瀏覽器會從 `<cdnURL>/_locales/...` 擷取公開的 payload 檔案，過去使用的是 `app.baseURL`：CDN 必須包含 `_locales/` 並允許你網站的來源（CORS）。請參閱[App baseURL 與 payload 主機](/zh-Hant/guide/deployment#app-baseurl-and-payload-hosts)。
- **SSR 不再透過 HTTP 請求 `/_locales`，**因此該路由上的伺服器 middleware 或日誌將不再看到渲染時的讀取。外部的 `apiBaseServerHost` 仍會透過 HTTP。
- **讀取失敗不再被保留，404 也不會。** 主機回傳 404 表示它沒有該檔案：渲染會顯示根字典（與瀏覽器相同），不會保留任何內容，而檔案一出現就會被讀取。任何其他失敗、不是 JSON 物件的 200，或無法讀取或損毀的本機檔案都不會進入快取，下一個請求會再次讀取：頁面渲染會記錄警告、顯示原始鍵，並以帶有 `no-store` 與 `Retry-After` 的 `503` 回應，因此路由規則或 CDN 不會保留任何內容，而瀏覽器仍會在 hydration 時讀取字典；`/_locales/...` 會以帶有 `no-store` 的 `503` 回應，而 `useTranslationServerMiddleware` 會提供一個回傳鍵或預設值的 `t`。在服務中斷期間，每個請求都會抵達主機，而 60 秒內未送出任何回應標頭的主機會使讀取失敗。大型檔案的緩慢下載沒有時間限制。請參閱[無法讀取字典時](/zh-Hant/guide/deployment#when-a-dictionary-cannot-be-read)。`/_locales` 也會傳遞該 404，過去它回應的是 `200 {}`。
- **無法載入字典的預渲染會失敗，**主機既沒有頁面檔案也沒有根檔案時也一樣。該路由會回傳 500，警告訊息會指出 locale 與頁面，且不會寫入任何檔案；在 Nuxt 預設的 `failOnError` 下，建置會以 1 結束。沒有自己檔案但有根檔案的頁面會以根進行預渲染。
- **建置時設定的主機會回應 SSR，**搭配預設的公開副本時也一樣，在內部路徑的錯誤頁面上亦然。過去是由公開檔案回應。執行階段的 `NUXT_I18N_APP_BASE_SERVER_HOST` 現在會影響 `/_locales` 與伺服器載入器，而渲染會透過該載入器讀取任一主機。
- **自訂的 `nitro.output.publicDir`，以及任何 `public/` 不在伺服器旁的版面配置，都會嵌入 payload。**
- **`nuxi build --preset <static preset>` 會像 `nuxi generate` 一樣進行預渲染，**因此可能會寫入更多檔案。`nuxi generate` 會在每個提供該頁面的 locale 中預渲染每個靜態頁面，無論是否有連結，除非路由規則設定了 `prerender: false`。
- **在靜態輸出上使用 `source` 或 `publicAssets: false` 會發出警告。** 瀏覽器沒有任何可讀取的內容。
- **嵌入警告現在是大小檢查。** 只有超過平台限制時建置才會發出警告：請參閱 [Bundle 限制](/zh-Hant/guide/deployment#bundle-limits-on-edge)。
- **凡是由訪客決定的地方都會設定 `Vary`：** 在 `no_prefix` 下的每個頁面，以及 `/` 和任何其他可依偏好重新導向的 URL。使用 cookie 時它會包含 `Cookie`，啟用 `autoDetectLanguage` 時則包含 `Accept-Language`。請檢查你的 CDN 快取鍵：請參閱[快取 HTML](/zh-Hant/guide/deployment#caching-html)。
- **`/_locales` 的快取方式已變更。** `/{apiBaseUrl}/**` 上不再有 Nitro 路由快取，`s-maxage=60, stale-while-revalidate` 標頭也已移除。如果你依賴該快取，請在 payload 路由前方放置 CDN。空的字典永遠不會是 `immutable`。
- **伺服器快取預設有上限：** 未設定 `cacheMaxSize` 時最多 1000 個項目。`cacheTtl` 從項目儲存時開始計算；讀取不再延長它。
- **新的選用 [`cacheStorage`](/zh-Hant/guide/performance#shared-cache-for-several-instances)：** 由多個實例共用的字典快取。未設定時不會有任何變化。

## 從 v2 升級到 v3 {#from-v2-to-v3}

### 已移除的選項 {#removed-options}

```diff
 i18n: {
-  includeDefaultLocaleRoute: true,
+  strategy: 'prefix',
-  fallbackRedirectComponentPath: '~/components/MyRedirect.vue',
-  experimental: { hmr: true, previousPageFallback: true },
+  hmr: true,
 }
```

- `includeDefaultLocaleRoute: true` 即為 `strategy: 'prefix'`；`false` 即為預設的 `prefix_except_default`。
- `fallbackRedirectComponentPath` 已移除：重新導向會在渲染前於伺服器上進行，並在用戶端路由 middleware 中進行。自訂重新導向邏輯請放入設定 locale 的外掛中，請參閱[自訂 locale 偵測](/zh-Hant/guide/custom-auto-detect)。
- `experimental.hmr` 改為根層級的 `hmr` 選項（預設開啟）。
- `previousPageFallback` 已移除：離開頁面的鍵會持續解析，直到其轉場結束，不需要任何選項。

### Locale 狀態 {#locale-state}

請使用 `useI18nLocale()` 取代 `useState('i18n-locale')` 與 `useCookie('user-locale')`：

```diff
- useState('i18n-locale').value = 'fr'
- useCookie('user-locale').value = 'fr'
+ useI18nLocale().setLocale('fr') // state and cookie together
```

### 執行階段的設定 {#config-at-runtime}

使用 `$getI18nConfig()` 讀取設定（包含執行階段覆寫）：

```diff
- const cookieName = useRuntimeConfig().public.i18nConfig?.localeCookie
+ const { $getI18nConfig } = useNuxtApp()
+ const cookieName = $getI18nConfig().localeCookie
```

### 內部型別別名 {#internal-type-aliases}

如果你的 IDE 或 `vue-tsc` 無法解析 `#i18n-internal/*` 匯入，請在 `package.json` 中對應它們。Nuxt 會在建置時解析它們，因此很少需要這麼做：

```json
{
  "imports": {
    "#i18n-internal/plural": "nuxt-i18n-micro/internals",
    "#i18n-internal/strategy": "nuxt-i18n-micro/internals",
    "#i18n-internal/config": "nuxt-i18n-micro/internals"
  }
}
```
