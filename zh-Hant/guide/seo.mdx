title: "SEO"
description: "模組所加入的 lang、hreflang、canonical 與 og:locale 標籤、其 base URL 如何決定，以及如何針對個別頁面覆寫。"
---

在 `meta: true`（預設值）時，每個在地化頁面都會取得 `<html lang dir>`、canonical 連結、`hreflang` 替代連結、`x-default` 以及 Open Graph locale 標籤。當您想要設定公開的來源（origin）、調整標籤中出現哪些 locale，或為單一頁面覆寫標籤時，就需要閱讀本頁。大多數網站只需要設定 `site.url` 或 `metaBaseUrl`，以及正確的 `iso` 代碼。

## 最小設定 {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

接著 `/de/about` 會算繪出：

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## 文字方向 {#text-direction}

`<html dir>` 取自 locale 的 `dir`。若未設定，由右至左書寫的語言會根據 `iso`（或 `code`）取得 `rtl`：阿拉伯文、希伯來文、波斯文、烏都文等少數語言，以及任何使用 RTL 文字的標籤，例如 `az-Arab`。其他所有 locale 都不會有 `dir` 屬性，瀏覽器會將其視為 `ltr`。

<Warning>

**`dir: 'auto'` 在大型頁面上會耗費剖析時間** — `<html>` 上的 `auto` 會讓瀏覽器在剖析時根據內容判斷方向。在 Chromium 中，這項成本的成長速度比頁面本身更快：5,000 個元素時約 100 ms，20,000 個元素時約 1 秒。請只在無法得知語言的小型頁面上使用。

</Warning>

## 您會得到哪些標籤 {#which-tags-you-get}

- **hreflang**：每個提供該頁面的 locale 各一個標籤，值為 `iso`（若缺少 `iso` 則為 `code`），其 URL 帶有與 canonical 相同的查詢參數。透過[頁面設定](/zh-Hant/guide/per-component-translations)或 `routeLocales` 限制的頁面只會列出其 locale。[`hreflangBaseLanguage: true`](/zh-Hant/api/module-options#hreflangbaselanguage) 還會為第一個地區 locale 加入純語言標籤（`es-ES` → `es`）。
- **x-default**：預設 locale 的 URL，僅在預設 locale 提供該頁面時輸出。
- **og:locale**：由 `iso` 推導而來（`en-US` → `en_US`）。當對應關係不直接時，請在 locale 上設定 `og`，例如 `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`；兩者皆未設定時，不會寫入 `og:locale`，且開發模式會發出警告。
- **canonical／og:url**：不含查詢參數的目前 URL，但 [`canonicalQueryWhitelist`](/zh-Hant/api/module-options#canonicalquerywhitelist) 中的參數除外（預設為 `page`、`sort`、`filter`、`search`、`q`、`query`、`tag`）。

依策略區分：

| 策略 | hreflang 與 x-default | canonical、og:url、og:locale、html 屬性 |
| --- | --- | --- |
| `prefix`、`prefix_except_default`、`prefix_and_default` | 是 | 是 |
| `no_prefix` | 否（一個 URL 提供所有 locale） | 是 |

## 設定公開來源 {#set-the-public-origin}

絕對 URL 會使用下列第一個可用的項目：

1. [`metaBaseUrl`](/zh-Hant/api/module-options#metabaseurl)；
2. 來自 `nuxt-site-config` 的 `site.url`（由 `@nuxtjs/seo` 安裝）；
3. 請求的來源，並附加 `app.baseURL`。

請固定設定前兩者之一。

<Warning>

以請求來源作為備援時會讀取 `X-Forwarded-Host` 與 `X-Forwarded-Proto`，因為 [`metaTrustForwardedHost`](/zh-Hant/api/module-options#metatrustforwardedhost) 與 `metaTrustForwardedProto` 預設為 `true`。這只有在會覆寫這些標頭的代理伺服器之後才安全；否則用戶端可以選擇您 canonical 連結中的主機，而快取可能會將該頁面轉送給其他人。

如果應用程式可被直接存取，請固定設定 `metaBaseUrl`：與將兩個選項都設為 `false` 不同，它也會忽略偽造的 `Host`。請參閱[位於代理伺服器或 CDN 之後](/zh-Hant/guide/deployment#behind-a-proxy-or-cdn)。

</Warning>

此備援適用於一個部署同時回應多個網域的情況：`https://site-a.com/en/about` 與 `https://site-b.com/en/about` 各自取得自己的來源。

當 locale 上設定了 `baseUrl` 時，已知的主機會使用其自身的 `baseUrl`，優先於 `metaBaseUrl` 與 `site.url`，因此 canonical 與 `og:url` 會維持在該網域上，而 `hreflang` 會將每個 locale 指向其網域。其他任何主機則使用 `metaBaseUrl`，否則使用預設 locale 的 `baseUrl`，再否則使用 `site.url`，因此偽造的 `Host` 無法影響您的標籤。如果以上皆未設定，則會保留請求來源的備援，且建置時會發出警告。請參閱[Layers 與網域](/zh-Hant/guide/layers#multiple-domains)。

## 排除 locale 或頁面 {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

如果預設 locale 設定了 `seo: false`，就不會寫入 `x-default`。若要為單一頁面關閉標籤，請在[頁面設定](/zh-Hant/guide/per-component-translations#turn-off-seo-tags)中使用 `disableMeta`，或在設定檔中使用 [`routeDisableMeta`](/zh-Hant/api/module-options#routedisablemeta)。

## 在單一頁面上覆寫標籤 {#override-tags-on-one-page}

對於只有部分翻譯存在、或 URL 來自 API 的 CMS 內容，請使用 [`useI18nHead`](/zh-Hant/composables/useI18nHead) 取代產生的標籤：

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` 也可以設定或移除 `canonical`、`xDefault`、`ogLocale` 與 `ogUrl`；`disable` 會移除整個群組（`'hreflang'`、`'x-default'`、`'canonical'`、`'og'`、`'og-alternates'`、`'html'`）。請傳入 getter，讓值在切換 locale 後重新計算。若使用各 locale 專屬的 slug，請先設定 `$setI18nRouteParams`（[在地化路徑](/zh-Hant/guide/custom-locale-routes#per-locale-slugs)），產生的替代連結就會使用它們。

## 結尾斜線 {#trailing-slash}

`$localePath`、`$switchLocalePath`、`$switchLocaleRoute` 的路由物件、`<i18n-link>`、`<i18n-switcher>`、locale 重新導向以及 SEO URL 都遵循同一條斜線規則：預設為 `experimental.defaults.nuxtLink.trailingSlash`，或當 i18n 路徑需要不同設定時，使用 i18n 設定中的 [`trailingSlash`](/zh-Hant/api/module-options)。

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/)（sitemap、robots、schema.org）透過 `nuxt-site-config` 4+ 與本模組搭配運作。請將 `nuxt-i18n-micro` 列在最前面，讓 site config 能讀取 locale，並只需設定一次 `site.url` — 它也會供上述標籤使用。

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

翻譯後的網站名稱與描述來自您 locale 檔案中的 `nuxtSiteConfig.name`／`nuxtSiteConfig.description` 鍵。若出現錯誤 `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered`，表示 `@nuxtjs/seo` 的版本早於 3；請升級它（[#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)）。
