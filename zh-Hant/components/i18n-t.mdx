title: "<i18n-t>"
description: "<i18n-t> 元件可渲染單一翻譯，支援複數形式、數字與日期格式化，以及 HTML 與插槽插值。"
---

`<i18n-t>` 會將一則翻譯渲染到一個元素中。當翻譯內需要放入元件（例如句子中的連結）、需要複數形式，或需要格式化的數字或日期時，就可以使用它。它會像 `$t` 一樣，針對目前路由解析鍵。

## Props {#props}

| Prop | 型別 | 預設值 | 說明 |
| --- | --- | --- | --- |
| `keypath` **\*** | `string` | — | 要渲染的翻譯鍵。 |
| `plural` | `number \| string \| null` | — | 用於選擇複數形式的數量。設定後會改用 `$tc` 而非 `$t`。`null` 表示未設定。 |
| `tag` | `string` | `'span'` | 要渲染的元素。 |
| `params` | `Record<string, string \| number \| boolean>` | — | 代入翻譯中的插值數值。 |
| `defaultValue` | `string` | `''` | 當 `hideIfEmpty` 隱藏空白翻譯時，改為渲染此內容。 |
| `html` | `boolean` | `false` | 將翻譯以 HTML 而非文字渲染。僅適用於你能掌控的翻譯：`params` 會被跳脫，翻譯本身則不會。 |
| `hideIfEmpty` | `boolean` | `false` | 當翻譯解析為空字串時不渲染任何內容。 |
| `customPluralRule` | `PluralFunc` | `null` | 僅適用於此元素的複數規則，會覆寫全域設定的規則。其回傳值會原樣使用；`null` 會渲染為空。 |
| `number` | `number \| string \| null` | — | 以 `$tn` 格式化數值，並以 `{number}` 連同 `params` 一起傳入翻譯。 |
| `date` | `Date \| string \| number \| null` | — | 以 `$td` 格式化數值，並以 `{date}` 連同 `params` 一起傳入翻譯。 |
| `relativeDate` | `Date \| string \| number \| null` | — | 以 `$tdr` 格式化數值，並以 `{relativeDate}` 連同 `params` 一起傳入翻譯。 |

**\*** 必填。

## 渲染規則 {#rendering-rules}

第一個符合的情況決定輸出結果：

1. `number` — 使用 `{ ...params, number: $tn(number) }` 的翻譯。
2. `date` — 使用 `{ ...params, date: $td(date) }` 的翻譯。
3. `relativeDate` — 使用 `{ ...params, relativeDate: $tdr(relativeDate) }` 的翻譯。
4. `plural` — `$tc` 選出的形式（包含 [`=0 ` 標記](/zh-Hant/api/methods#$tc)），搭配 `{ ...params, count }`；若有設定 `customPluralRule(keypath, count, params, locale, t)`，則改用它，它會讀取包含標記在內的原始值，其回傳值會原樣使用，`null` 代表空白。
5. 其他情況則使用搭配 `params` 的翻譯。

`null` 視為未設定。在所有情況下：

- 在每個分支中，`defaultValue` 都會替代缺少的鍵。
- `hideIfEmpty` 會渲染 `defaultValue`，而不是空白結果。
- `html` 會將結果以 HTML 渲染。`params` 會被跳脫，翻譯本身則不會；插槽會被忽略。
- `default` 插槽會收到 `{ translation }`，具名插槽則會被忽略。
- 否則，每個具名插槽會取代所有 `{name}` 佔位符，且優先於同名的參數。看起來像佔位符的參數值會保持為文字。

`date` 與 `relativeDate` 的輸出帶有 `data-allow-mismatch="text"`，因為伺服器的時區與時鐘和瀏覽器不同。設定 [`timeZone`](/zh-Hant/api/module-options#timezone) 可讓兩端渲染出相同的日曆日期；`relativeDate` 取決於時鐘，因此仍可能不同。

## 範例 {#example}

```json
{
  "terms": "I accept the {link}.",
  "termsLink": "terms of use",
  "items": "no items | one item | {count} items"
}
```

```vue
<template>
  <i18n-t keypath="terms" tag="p">
    <template #link>
      <NuxtLink :to="$localePath('/terms')">{{ $t('termsLink') }}</NuxtLink>
    </template>
  </i18n-t>

  <i18n-t keypath="items" :plural="cart.length" />
</template>
```

`html` 會設定 `innerHTML`：僅在你能掌控的翻譯上使用。`params` 會被跳脫，因此使用者資料放在其中是安全的，找不到翻譯的鍵也同樣安全。
