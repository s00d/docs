模組會呼叫一個執行階段（app）hook：`i18n:register`。當外掛或模組要加入不在 `locales/` 檔案中的翻譯時，請使用它。你的回呼函式會收到一個 `register` 函式，它會把翻譯合併到正在顯示的頁面中。

## `i18n:register` {#i18nregister}

```ts
'i18n:register': (
  register: (translations: unknown, locale?: string) => void,
  locale: string,
) => HookResult
```

| 參數 | 說明 |
| --- | --- |
| `register(translations, locale?)` | 將 `translations` 深度合併到正在載入之路由的頁面區塊中，對應 `locale`（預設：hook 的 `locale`）。已存在的鍵會被覆寫。 |
| `locale` | 正在載入之路由的 locale。 |

此 hook 透過 `RuntimeNuxtHooks` 提供型別，因此 `nuxtApp.hook('i18n:register', …)` 不需要型別轉換。

## 觸發時機 {#when-it-fires}

載入器外掛（`i18n-plugin-loader`）會在以下時機呼叫它：

1. 啟動時呼叫一次，即所有外掛都已執行（`app:created`）之後、應用程式渲染之前；
2. 在其 `router.beforeEach` 中，當路徑改變且目標頁面的翻譯載入完成後呼叫——在 `no_prefix` 下則是每次導覽都會呼叫。

每個回呼函式與每次 `register` 呼叫都會在應用程式渲染或導覽繼續之前被 await，因此頁面會以合併後的鍵進行渲染。若設定 [`hooks: false`](/zh-Hant/api/module-options#hooks)，則此 hook 永遠不會被呼叫。

## 範例 {#example}

```ts
// plugins/i18n-extra.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('i18n:register', async (register, locale) => {
    const extra = await $fetch<Record<string, unknown>>(`/api/cms-strings/${locale}`)
    register(extra, locale)
  })
})
```

這是執行階段 hook：請在外掛中使用 `nuxtApp.hook` 註冊，而不是在 `nuxt.config` 或模組的 `setup` 中使用 `nuxt.hook`。模組可以透過 `addPlugin` 加入這樣的外掛。
