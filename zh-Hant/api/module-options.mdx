# 模組選項參考

`nuxt-i18n-micro` 接受的每個選項,於建置期由
[`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts)
中的 `ModuleOptions` 介面讀取。
本頁內容並非手工撰寫,因此不會落後於實作 —— 型別、預設值與說明都來自宣告本身。

若要了解這些選項一起使用時*代表*什麼意義 —— 哪些組合合理、切換策略時會有什麼變化、實務範例 —— 請閱讀[設定](/guides/configuration)。本頁是完整清單,那頁則是解說。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

巢狀選項會以點分隔路徑呈現,因此 `translationPayloads.mode` 就是 `translationPayloads` 物件內的 `mode` 鍵。

## 語系與路由

存在哪些語言,以及它們在 URL 中如何呈現。

| 選項 | 型別 | 預設 | 說明 |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | 支援的語系清單。每個項目定義一個語系代碼以及可選中繼資料(ISO、方向、顯示名稱等)。 |
| `strategy` | `Strategies` | `'prefix_except_default'` | 語系前綴的 URL 路由策略。 - `'no_prefix'` — URL 中不含語系;語系儲存於 cookie。 - `'prefix_except_default'` — 除預設語系外,所有語系皆加前綴。 - `'prefix'` — 一律加前綴,包含預設語系。 - `'prefix_and_default'` — 類似 `prefix`,但預設語系亦可透過無前綴形式存取。 |
| `defaultLocale` | `string` | `'en'` | 當無法從 URL 或使用者偏好判定語系時所使用的語系。若未設定 `fallbackLocale`,也作為缺失翻譯的 fallback。 |
| `localeCookie` | `string \| null` | `null` | 用於跨 session 保留使用者語系偏好的 cookie 名稱。設為 `null` 可停用 cookie 儲存。若未提供,`no_prefix` 策略會自動設為 `'user-locale'`。 |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | 全域的路由層級語系設定。可為特定頁面限制或自訂語系路由,而不修改其元件。 - `false` — 排除該路由於在地化之外。 - `Record<LocaleCode, string>` — 每語系的自訂路徑。 |
| `customRegexMatcher` | `string \| RegExp` | `undefined(使用基於語系代碼的內建模式)` | 用於比對 URL 段落中語系代碼的自訂正規表示式(或其字串來源)。`locales` 中定義的所有語系代碼都必須符合此模式,否則會發出警告。 |
| `noPrefixRedirect` | `boolean` | `false` | 針對 `no_prefix` 策略:啟用從帶語系前綴 URL(例如 `/en/about`)到無前綴版本(`/about`)的重新導向。 |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | 完全排除於 i18n 處理之外的 URL 模式(字串或 RegExp)。匹配的路由不會取得語系前綴、重新導向或翻譯載入。Nuxt 內部路徑(`/__nuxt_error` 等)一律自動排除。 |
| `routeLocales` | `Record<string, string[]>` | — | 從 `defineI18nRoute()` 呼叫擷取的每路由語系限制。將路由路徑(例如 `'/about'`)對應到允許的語系代碼陣列。未列出的路由沒有限制(允許所有語系)。 |

## 翻譯

翻譯檔的存放位置與鍵的解析方式。

| 選項 | 型別 | 預設 | 說明 |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | 相對於專案根目錄、包含翻譯 JSON 檔的目錄路徑。 |
| `disableWatcher` | `boolean` | `false` | 停用開發模式下自動建立缺失翻譯檔的檔案監看器。 |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | 將路由名稱對應到其他路由名稱以共用同一翻譯檔。例如 `\{ 'about-us': 'about' \}` 表示 `about-us` 頁面會使用 `about` 頁面的翻譯,而非自己的。 |
| `plural` | `PluralFunc` | `內建複數化(以計數為索引選擇形式)` | 自訂複數化函式。接收 `(key, count, params, locale, getter)`,應回傳選中的複數形式字串,或回傳 `null`/`undefined` 以退回內建 `defaultPlural`(因此可只覆寫部分語系)。Nuxt 模組會透過 `.toString()` 將此函式序列化到 `.nuxt/i18n.plural.mjs` —— 必須是自包含的(無 imports / 外部作用域)。**不支援**檔案路徑字串。 |
| `disablePageLocales` | `boolean` | `false` | 停用頁面專屬翻譯檔。若為 `true`,僅載入全域翻譯(`\{locale\}.json`);頁面專屬檔案(`pages/\{page\}/\{locale\}.json`)不會產生或載入。 |
| `fallbackLocale` | `string` | `undefined(無 fallback;回傳原始鍵)` | 全域 fallback 語系代碼。若當前語系缺少某個翻譯鍵,模組會先查此語系,再回傳鍵本身。 |

## Payload 與快取

翻譯如何到達瀏覽器。[效能](/guides/performance)說明這些選項在執行時會改變什麼。

| 選項 | 型別 | 預設 | 說明 |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | 在 Nitro 全域中介層中預先載入首頁翻譯(僅伺服器、私有設定)。 |
| `apiBaseUrl` | `string` | `'_locales'` | 翻譯 API 路由的基底 URL 路徑段(用於 SSR/SSG 資料抓取)。也可透過 `NUXT_I18N_APP_BASE_URL` 環境變數設定。 |
| `apiBaseClientHost` | `string` | `undefined` | 覆寫客戶端翻譯抓取請求所使用的主機。當客戶端經由與 Nuxt 所見不同的主機名連線至伺服器時很有用。也可透過 `NUXT_I18N_APP_BASE_CLIENT_HOST` 環境變數設定。 |
| `apiBaseServerHost` | `string` | `undefined` | 覆寫伺服器端翻譯抓取請求所使用的主機。在容器/微服務架構中,若伺服器透過內部主機名連線自己時相當實用。也可透過 `NUXT_I18N_APP_BASE_SERVER_HOST` 環境變數設定。 |
| `translationPayloads` | `TranslationPayloadOptions` | — | 控制翻譯 payload 的產出方式(Node:`public/<apiBaseUrl>`;Edge:Nitro `serverAssets`)。 - **Node**:`serverAssets` 代表本地 SSR 透過 `readFile` 從 `public/` 讀取(無 Rollup `raw:`)。 - **Edge**:`serverAssets` 註冊 Nitro `serverAssets`(`assets:i18n`);不強制產生 public 複本。一般全套設定請保留預設。大型 Edge 字典建議 `mode: 'source'`。CDN 部署則停用本地輸出並設定 `apiBaseClientHost` / `apiBaseServerHost`。 |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | 翻譯 payload 策略。 - `premerged`:建置期產生 `\{page\}/\{locale\}/data.json` 矩陣(預設) - `source`:精簡的來源檔於執行時合併(Edge / 大字典建議使用) |
| `translationPayloads.serverAssets` | `boolean` | `true` | 本地 SSR payload:Node 從 `public/<apiBaseUrl>` 讀取(強制產生 public 複本);Edge 透過 Nitro `serverAssets` 內嵌。 - **Node**:不使用 Nitro `serverAssets`(避免 Rollup `raw:`)。SSR 讀取 `public/<apiBaseUrl\|publicDir>` 下的 `\{page\}/\{locale\}/data.json`;此值為 `true` 時,即使 `publicAssets` 為 false,也會強制產生 public 複本。 - **Edge**(`nitro.node === false`):Nitro `serverAssets`(`assets:i18n`)使用與 `mode` 相同的佈局。**不**強制產生 public 複本 —— 若需供 CDN,請設 `publicAssets: true`。 |
| `translationPayloads.serverHandler` | `boolean` | `true` | 註冊內建伺服器路由於 `/\{apiBaseUrl\}/:page/:locale/data.json`。當翻譯 payload 由外部主機/CDN 提供時可停用。 |
| `translationPayloads.publicAssets` | `boolean` | `premerged 模式下為 true;source 模式下為 false` | 將 payload 複製到 Nitro public 輸出。Premerged → `apiBaseUrl` 下的 `\{page\}/\{locale\}/data.json`;source → 精簡樹。在 Node 上,當 `serverAssets` 強制產生 public 複本時,此樹亦為 SSR 來源。 |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | 加入 `/\{apiBaseUrl\}/.../data.json` 的 Nitro 預渲染。若 premerged 的 `publicAssets` 已寫入這些檔案,通常屬多餘。 |
| `translationPayloads.publicDir` | `string` | — | 相對於 Nitro public 根目錄的 public 輸出資料夾。預設為 `apiBaseUrl`(`_locales`)。因此靜態檔會對應到客戶端 fetch URL(`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`)。 |
| `translationPayloads.warnFileCount` | `number` | `500` | 建置期產生的 payload 檔案數超過此門檻時發出警告。 |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | 建置期產生的 payload 總大小(位元組)超過此門檻時發出警告。 |

## SEO

為每個在地化頁面產生的 meta 標籤。

| 選項 | 型別 | 預設 | 說明 |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | 自動產生 SEO meta 標籤(`hreflang`、`canonical`、`og:url`、`og:locale`)。 |
| `metaBaseUrl` | `string` | `undefined` | SEO meta 標籤(canonical、og:url、hreflang)的基底 URL。 - 具體的 URL 字串(例如 `'https://example.com'`)——直接使用(最高優先)。 - `undefined` — 若安裝了 `nuxt-site-config`,退回為其 `site.url`;否則使用當前請求來源(伺服器端 `useRequestURL().origin`、客戶端 `window.location.origin`)。 |
| `metaTrustForwardedHost` | `boolean` | `true` | 解析 meta 標籤基底 URL 時,信任 `X-Forwarded-Host` 標頭。當應用位於會將此標頭設為對外真實主機名的反向代理(nginx、Cloudflare、AWS ALB 等)後方時,請啟用。 |
| `metaTrustForwardedProto` | `boolean` | `true` | 解析 meta 標籤協定時,信任 `X-Forwarded-Proto` 標頭。當應用位於 TLS 終止代理後方時啟用,使 canonical URL 使用 `https://`,即使應用本身監聽 HTTP。 |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | 保留在 canonical 與 `og:url` meta 標籤中的查詢參數名稱清單。不在此清單的參數會從 canonical URL 中移除。 |

## 偵測與重新導向

為未主動選擇語系的訪客決定語系。

| 選項 | 型別 | 預設 | 說明 |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | 啟用基於語系的自動重新導向。若為 `true`,首次造訪時會依偏好語系(從 cookie、`Accept-Language` 標頭或預設判定)重新導向。 |
| `autoDetectLanguage` | `boolean` | `true` | 從 `Accept-Language` HTTP 標頭自動偵測使用者偏好的語言。搭配 `autoDetectPath` 決定何時執行偵測。 |
| `autoDetectPath` | `string` | `'/'` | 允許執行 cookie / Accept-Language 偏好重新導向的位置(當啟用 `redirects` 時)。 - `'/'` — 只在 `/`(預設語系的深連結仍可存取;預設值) - `'no_prefix'` — 只在沒有語系前綴的路徑 - `'*'` — 每個路徑,包括改寫明確的語系前綴(例如 cookie 偏好 `de` 時,`/fr/about` → `/de/about`) - 其他字串 — 完全相符的路徑(例如 `'/welcome'`) 前綴策略清理(例如 `prefix_except_default` 下 `/en` → `/`)不受此設定限制。 |

## 註冊

可關閉的模組部分。

| 選項 | 型別 | 預設 | 說明 |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | 註冊 `defineI18nRoute()` 巨集外掛,以便在頁面中呼叫 `defineI18nRoute()`。 |
| `plugin` | `boolean` | `true` | 註冊核心 i18n 外掛,提供 `$t()`、`$tc()`、`$getLocale()`、`$switchLocale()` 及其他執行時輔助函式。 |
| `hooks` | `boolean` | `true` | 註冊 i18n hooks 外掛,提供 `i18n:register`、`i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch` 應用層級 hook。 |
| `components` | `boolean` | `true` | 註冊內建 i18n 元件(`<i18n-link>`、`<i18n-switcher>`、`<i18n-t>`、`<i18n-group>`)。設為 `false` 可停用自動元件註冊(例如若不使用它們並希望減少模組佔用)。 |
| `types` | `boolean` | `true` | 根據預設語系檔中的翻譯鍵,為 `useI18n`、`$t` 及相關輔助函式產生 TypeScript 型別宣告。 |
| `debug` | `boolean` | `false` | 為語系偵測、路由產生與翻譯載入啟用詳細偵錯記錄。 |

## 其他

| 選項 | 型別 | 預設 | 說明 |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | 同時發出由每個語系 `iso` 衍生的純語言 `hreflang`(例如 `es-ES` → 也發出 `es`)。`locales` 中該語言的第一個地區語系會取得此純標籤。路由的 `code` 永不使用 —— 僅 `iso \|\| code`。 |
| `vueDevtools` | `boolean` | `true` | 於開發模式註冊 Vue DevTools 檢視器與時間軸(瀏覽器擴充功能)。與 Nuxt DevTools 自訂頁籤分離。 |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | 在地化路由名稱的前綴(例如 `'localized-index'`)。內部用於區分原始路由與產生的語系變體。 |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | 從 `defineI18nRoute()` 呼叫擷取的每路由 meta 標籤停用設定。將路由路徑對應到 `true`(全部 meta 皆停用)或應停用 meta 的語系代碼陣列。 |
| `missingWarn` | `boolean` | `true` | 翻譯鍵缺失時在主控台顯示警告。 |
| `hmr` | `boolean` | `true` | 於開發模式為翻譯檔案啟用 Hot Module Replacement。若為 `true`,JSON 翻譯檔的變更會觸發自動重新載入,而不需完整重新整理頁面。 |
| `cacheMaxSize` | `number` | `0` | 記憶體翻譯快取的最大項目數。`0` 表示無限制。 |
| `cacheTtl` | `number` | `0` | 快取翻譯項目的存活時間(秒)。`0` 表示永不過期。 |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | 每個語系的具名數字格式(與 Vue I18n 相容)。啟用 `$tn(1000, 'currency')` 的呼叫方式。 |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | 每個語系的具名日期時間格式(與 Vue I18n `datetimeFormats` 相容)。啟用 `$td(date, 'short')` 的呼叫方式。 |
| `httpCacheDuration` | `number` | `31536000` | `/\{apiBaseUrl\}/:page/:locale/data.json` 的 HTTP `Cache-Control` max-age(秒)。只有在 `dateBuild` 讓 URL 失效(`?v=...`)時(即預設)才完全套用:回應會是 `public, max-age=…, immutable`,對瀏覽器與 CDN 安全。 - `dateBuild: 0`/`''` — URL 為穩定值,此期限**不會**被套用;回應改為 `public, max-age=0, must-revalidate`。對不變 URL 使用長 `max-age` 會將瀏覽器最初看到的 payload 固定下來。 - `0` — 完全不設定 `Cache-Control`(本地偵錯時實用) - 在開發模式(`import.meta.dev`)下不套用,以免瀏覽器快取妨礙 HMR - 僅套用至透過 Nitro 提供的回應。被複製到 `public/` 並由代管平台提供的 payload 會採用該平台的標頭 —— 請見效能指南。類似 `@nuxtjs/i18n` 的實驗性 `httpCacheDuration`(v10.2.0),但為明確的回應標頭,而非 Nitro `defineCachedEventHandler` 的 maxAge。 |
| `dateBuild` | `string \| number` | — | 用於為翻譯請求進行快取失效(`?v=...`)的值。未提供時,模組會退回為 `Date.now()`(非確定性)。若希望可重現/滾動式部署,請將此設為穩定值(例如 git SHA 或 build number)。 |
| `experimental` | `Record<string, unknown>` | — | 實驗性/不穩定選項的容器。內容可能在次版本間變更或移除,恕不另行通知。 |
