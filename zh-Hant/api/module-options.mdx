# 模組選項參考

`nuxt-i18n-micro` 接受的每個選項都在此列出，這些內容在建置期讀取自 [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts) 中的 `ModuleOptions` 介面。此頁面並非手寫，因此不會與程式碼脫節：型別、預設值與說明皆來自型別宣告本身。

若想了解這些選項的實際*意義*、哪些組合合理、切換策略時會有什麼變化、以及實作範例，請閱讀[設定](/guides/configuration)。本頁是完整清單，該頁則是說明。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

巢狀選項會以其點路徑呈現，因此 `translationPayloads.mode` 表示 `translationPayloads` 物件內的 `mode` 鍵。

## 語系與路由

存在哪些語言、它們如何出現在 URL 中。

| 選項 | 型別 | 預設值 | 說明 |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | 支援的語系清單。每個項目定義一個語系代碼及選填的中繼資料（ISO、書寫方向、顯示名稱等）。 |
| `strategy` | `Strategies` | `'prefix_except_default'` | 用於語系前綴的 URL 路由策略。- `'no_prefix'`：URL 不含語系；語系儲存在 cookie 中。- `'prefix_except_default'`：除了預設語系以外，全部加前綴。- `'prefix'`：一律加前綴，包括預設語系。- `'prefix_and_default'`：類似 `prefix`，但預設語系也能透過不加前綴的形式存取。 |
| `defaultLocale` | `string` | `'en'` | 當無法由 URL 或使用者偏好判斷語系時使用的語系。若未設定 `fallbackLocale`，也會作為缺失翻譯的 fallback 語系。 |
| `localeCookie` | `string \| null` | `null` | 用來跨 session 保存使用者語系偏好的 cookie 名稱。設為 `null` 可停用 cookie 儲存。若未提供且策略為 `no_prefix`，會自動設定為 `'user-locale'`。 |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | 全域路由層級的語系設定。可為特定頁面限制或自訂語系路由，無需修改元件。- `false`：將該路由排除於在地化之外。- `Record<LocaleCode, string>`：各語系的自訂路徑。 |
| `customRegexMatcher` | `string \| RegExp` | `undefined（使用依語系代碼建構的內建 pattern）` | 用於在 URL 片段中比對語系代碼的自訂正規表達式（或其字串形式）。`locales` 中定義的所有語系代碼必須符合此 pattern，否則會發出警告。 |
| `noPrefixRedirect` | `boolean` | `false` | 用於 `no_prefix` 策略：啟用時會從帶語系前綴的 URL（例如 `/en/about`）重新導向到未加前綴的版本（`/about`）。 |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | 要完全排除於 i18n 處理之外的 URL pattern（字串或 RegExp）。符合的路由不會取得語系前綴、重新導向或翻譯載入。Nuxt 內部路徑（`/__nuxt_error` 等）一律自動排除。 |
| `routeLocales` | `Record<string, string[]>` | — | 逐路由的語系限制，由 `defineI18nRoute()` 呼叫抽取而來。將路由路徑（例如 `'/about'`）對應到允許的語系代碼陣列。未列出的路由沒有限制（所有語系皆允許）。 |

## 翻譯

翻譯檔存放的位置與鍵的解析方式。

| 選項 | 型別 | 預設值 | 說明 |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | 存放翻譯 JSON 檔的目錄路徑，相對於專案根目錄。 |
| `disableWatcher` | `boolean` | `false` | 停用開發模式下自動建立缺失翻譯檔的檔案 watcher。 |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | 將路由名稱對應到其他路由名稱，讓它們共用相同翻譯檔。例如 `\{ 'about-us': 'about' \}` 表示 `about-us` 頁面會使用 `about` 頁面的翻譯，而不使用自己的翻譯。 |
| `plural` | `PluralFunc` | `內建複數規則（依 count 決定形式索引）` | 自訂複數規則函式。接收 `(key, count, params, locale, getter)`，應回傳所選複數形式的字串；回傳 `null`／`undefined` 則會退回內建 `defaultPlural` 邏輯（讓你可以只覆寫部分語系）。在 Nuxt 模組中會透過 `.toString()` 序列化為 `.nuxt/i18n.plural.mjs`，因此該函式必須自成一體（不可有 imports 或外部 scope）。**不**支援檔案路徑字串。 |
| `disablePageLocales` | `boolean` | `false` | 停用逐頁翻譯檔。當設為 `true` 時，只載入全域翻譯（`\{locale\}.json`）；不會產生或載入頁面專屬檔案（`pages/\{page\}/\{locale\}.json`）。 |
| `fallbackLocale` | `string` | `undefined（沒有 fallback；直接回傳原始鍵）` | 全域 fallback 語系代碼。當目前語系中缺失翻譯鍵時，模組會先在此語系中查找，找不到才回傳鍵本身。 |

## Payload 與快取

翻譯如何送達瀏覽器。[效能](/guides/performance)一節說明這些選項在執行時實際改變了什麼。

| 選項 | 型別 | 預設值 | 說明 |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | 在 Nitro 全域 middleware 中預先載入首頁翻譯（僅伺服器端，屬私有設定）。 |
| `apiBaseUrl` | `string` | `'_locales'` | 翻譯 API 路由的基礎 URL 片段（用於 SSR/SSG 資料取得）。亦可透過 `NUXT_I18N_APP_BASE_URL` 環境變數設定。 |
| `apiBaseClientHost` | `string` | `undefined` | 覆寫用戶端翻譯 fetch 請求的 host。當用戶端使用與 Nuxt 所見不同的 hostname 存取伺服器時特別有用。亦可透過 `NUXT_I18N_APP_BASE_CLIENT_HOST` 環境變數設定。 |
| `apiBaseServerHost` | `string` | `undefined` | 覆寫伺服器端翻譯 fetch 請求的 host。在容器／微服務架構中，伺服器透過內部 hostname 存取自己時很有用。亦可透過 `NUXT_I18N_APP_BASE_SERVER_HOST` 環境變數設定。 |
| `translationPayloads` | `TranslationPayloadOptions` | — | 控制翻譯 payload 的產出方式（Node：`public/<apiBaseUrl>`；Edge：Nitro `serverAssets`）。- **Node**：`serverAssets` 表示本機 SSR 透過 `readFile` 從 `public/` 讀取（不使用 Rollup `raw:`）。- **Edge**：`serverAssets` 會註冊 Nitro `serverAssets`（`assets:i18n`），不會強制產生 public 副本。若使用一般的全包式設定，保留預設即可。若 Edge 上翻譯量很大，建議使用 `mode: 'source'`。若採 CDN 部署，可停用本地輸出並設定 `apiBaseClientHost`／`apiBaseServerHost`。 |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | 翻譯 payload 策略。- `premerged`：建置期產生 `\{page\}/\{locale\}/data.json` 矩陣（預設）- `source`：保留精簡原始檔，執行期再合併（Edge／大型翻譯集建議使用） |
| `translationPayloads.serverAssets` | `boolean` | `true` | 本機 SSR payload：Node 讀取 `public/<apiBaseUrl>`（強制複製到 public）；Edge 則透過 Nitro `serverAssets` 內嵌。- **Node**：不使用 Nitro `serverAssets`（避免 Rollup `raw:`）。SSR 讀取 `public/<apiBaseUrl\|publicDir>` 下的 `\{page\}/\{locale\}/data.json`；此值為 `true` 時，即使 `publicAssets` 為 false 也會強制複製到 public。- **Edge**（`nitro.node === false`）：Nitro `serverAssets`（`assets:i18n`），layout 與 `mode` 相同。**不**會強制複製到 public，若要供 CDN 使用，請設 `publicAssets: true`。 |
| `translationPayloads.serverHandler` | `boolean` | `true` | 註冊內建伺服器路由 `/\{apiBaseUrl\}/:page/:locale/data.json`。若翻譯 payload 由外部主機／CDN 提供，可停用此選項。 |
| `translationPayloads.publicAssets` | `boolean` | `premerged 模式為 true，source 模式為 false` | 是否將 payload 複製至 Nitro 的 public 輸出。Premerged → 在 `apiBaseUrl` 下產生 `\{page\}/\{locale\}/data.json`；source → 精簡樹狀結構。在 Node 上，若 `serverAssets` 強制複製到 public，此樹也會作為 SSR 來源。 |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | 是否透過 Nitro-prerender 預先產生 `/\{apiBaseUrl\}/.../data.json`。當 premerged 的 `publicAssets` 已寫出這些檔案時通常沒必要。 |
| `translationPayloads.publicDir` | `string` | — | 相對於 Nitro public 根目錄的公開輸出資料夾。預設等於 `apiBaseUrl`（`_locales`），如此靜態檔會對應到用戶端的 fetch URL（`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`）。 |
| `translationPayloads.warnFileCount` | `number` | `500` | 建置期產生的 payload 檔案數量超過此閾值時發出警告。 |
| `translationPayloads.warnSizeBytes` | `number` | `10485760（10 MB）` | 建置期產生的 payload 總大小（bytes）超過此閾值時發出警告。 |

## SEO

為每個多語系頁面產生的 meta 標籤。

| 選項 | 型別 | 預設值 | 說明 |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | 自動產生 SEO meta 標籤（`hreflang`、`canonical`、`og:url`、`og:locale`）。 |
| `metaBaseUrl` | `string` | `undefined` | SEO meta 標籤（canonical、og:url、hreflang）使用的基底 URL。- 具體 URL 字串（例如 `'https://example.com'`）：直接使用（優先權最高）。- `undefined`：若安裝了 `nuxt-site-config` 模組，會退回使用 `site.url`；否則使用當前請求的 origin（伺服器端 `useRequestURL().origin`、用戶端 `window.location.origin`）。 |
| `metaTrustForwardedHost` | `boolean` | `true` | 解析 meta 標籤基底 URL 時信任 `X-Forwarded-Host` 標頭。當應用在反向代理（nginx、Cloudflare、AWS ALB 等）之後，且此標頭代表真實對外的 hostname 時啟用。 |
| `metaTrustForwardedProto` | `boolean` | `true` | 解析 meta 標籤協定時信任 `X-Forwarded-Proto` 標頭。當應用位於 TLS 終端 proxy 之後，希望 canonical URL 使用 `https://`（即便應用本身以 HTTP 監聽）時啟用。 |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | canonical 與 `og:url` meta 標籤中會保留的查詢參數名稱清單。不在清單中的參數會從 canonical URL 中移除。 |

## 偵測與重新導向

為未指定偏好的訪客選擇語系。

| 選項 | 型別 | 預設值 | 說明 |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | 啟用基於語系的自動重新導向。當為 `true` 時，訪客首次造訪會被重新導向到偏好語系（由 cookie、`Accept-Language` 標頭或預設值偵測）。 |
| `autoDetectLanguage` | `boolean` | `true` | 自動從 `Accept-Language` HTTP 標頭偵測使用者偏好語言。搭配 `autoDetectPath` 決定何時執行偵測。 |
| `autoDetectPath` | `string` | `'/'` | cookie／Accept-Language 偏好重新導向可執行的路徑（需 `redirects` 啟用）。- `'/'`：只在 `/`（預設語系下的 deep link 仍可到達，為預設值）- `'no_prefix'`：只在無語系前綴的路徑上- `'*'`：所有路徑，包括改寫明確的語系前綴（例如 cookie 偏好 `de` 時 `/fr/about` → `/de/about`）- 其他字串：精確路徑比對（例如 `'/welcome'`）帶前綴策略的清理（例如 `prefix_except_default` 下 `/en` → `/`）不受此設定限制。 |

## 註冊

模組中可選擇性關閉的功能。

| 選項 | 型別 | 預設值 | 說明 |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | 註冊 `defineI18nRoute()` macro 外掛，啟用逐頁 `defineI18nRoute()` 呼叫。 |
| `plugin` | `boolean` | `true` | 註冊核心 i18n 外掛，提供 `$t()`、`$tc()`、`$getLocale()`、`$switchLocale()` 等執行時輔助方法。 |
| `hooks` | `boolean` | `true` | 註冊 i18n hooks 外掛，提供 `i18n:register` 與 `i18n:beforeLocaleSwitch`／`i18n:afterLocaleSwitch` 等應用層級 hook。 |
| `components` | `boolean` | `true` | 註冊內建 i18n 元件（`<i18n-link>`、`<i18n-switcher>`、`<i18n-t>`、`<i18n-group>`）。設為 `false` 可停用自動元件註冊（若你不使用它們並想減少模組足跡）。 |
| `types` | `boolean` | `true` | 依據預設語系檔案中的翻譯鍵，為 `useI18n`、`$t` 及相關輔助方法產生 TypeScript 型別宣告。 |
| `debug` | `boolean` | `false` | 為語系偵測、路由產生與翻譯載入啟用詳細除錯記錄。 |

## 其他

| 選項 | 型別 | 預設值 | 說明 |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | 額外根據每個語系的 `iso` 發出僅含語言的 `hreflang`（例如 `es-ES` → 也發出 `es`）。`locales` 中第一個帶地區的語系會取得該語言的裸標籤。永遠不使用路由 `code`，只使用 `iso \|\| code`。 |
| `vueDevtools` | `boolean` | `true` | 在開發模式下註冊 Vue DevTools inspector 與 timeline（瀏覽器擴充功能）。與 Nuxt DevTools 自訂分頁分開。 |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | 附加於多語系路由名稱前的前綴（例如 `'localized-index'`）。內部用於區分原始路由與產生的語系變體。 |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | 逐路由的 meta 標籤停用設定，由 `defineI18nRoute()` 呼叫抽取而來。將路由路徑對應到 `true`（停用所有 meta）或語系代碼陣列（要停用哪些語系的 meta）。 |
| `missingWarn` | `boolean` | `true` | 當翻譯鍵缺失時顯示 console 警告。 |
| `hmr` | `boolean` | `true` | 在開發模式下為翻譯檔案啟用 Hot Module Replacement。當為 `true` 時，JSON 翻譯檔的變更會觸發自動重新載入，而不需完整刷新頁面。 |
| `cacheMaxSize` | `number` | `0` | 記憶體翻譯快取的最大項目數。`0` 表示無上限。 |
| `cacheTtl` | `number` | `0` | 已快取翻譯的存活時間（秒）。`0` 表示項目永不過期。 |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | 逐語系的命名數字格式（相容於 Vue I18n）。可支援 `$tn(1000, 'currency')` 的用法。 |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | 逐語系的命名日期時間格式（相容於 Vue I18n 的 `datetimeFormats`）。可支援 `$td(date, 'short')` 的用法。 |
| `httpCacheDuration` | `number` | `31536000` | `/\{apiBaseUrl\}/:page/:locale/data.json` 的 HTTP `Cache-Control` max-age（秒）。只有在 `dateBuild` 破除 URL 快取（`?v=...`）時才會完整套用；此為預設行為，回應會是 `public, max-age=…, immutable`，對瀏覽器與 CDN 都安全。- `dateBuild: 0`／`''`：URL 為固定，此期限**不會**被套用；回應變為 `public, max-age=0, must-revalidate`。若對不變的 URL 設定長 `max-age`，會鎖住瀏覽器第一次看到的 payload。- `0`：完全不設 `Cache-Control`（本機除錯時很有用）- 開發模式（`import.meta.dev`）不會套用，避免瀏覽器快取干擾 HMR- 只影響透過 Nitro 提供的回應。複製到 `public/` 並由主機平台提供的 payload 會採用該平台的標頭，請參見效能指南。等同於 `@nuxtjs/i18n` 的實驗性 `httpCacheDuration`（v10.2.0），但採用明確的回應標頭，而非 Nitro 的 `defineCachedEventHandler` maxAge。 |
| `dateBuild` | `string \| number` | — | 用於破除翻譯請求快取的值（`?v=...`）。若未提供，模組會退回 `Date.now()`（非決定性）。若需可重現／滾動部署，請設為固定值（例如 git SHA 或 build 編號）。 |
| `experimental` | `Record<string, unknown>` | — | 實驗性／不穩定選項的容器。內容可能在 minor 版本間變動或被移除，恕不另行通知。 |
