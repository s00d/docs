`@i18n-micro/solid` 為 SolidJS 應用程式提供以 signal 為基礎的 i18n 執行個體、一個 provider、`useI18n()` 以及四個元件。請在非以 Nuxt 建置的 Solid 應用程式中使用它。在 JSX 或 effect 中讀取 `t()` 時，會追蹤語系、路由與字典；共用的模型請見[框架](/zh-Hant/integrations/overview)。

## 安裝 {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer dependency：`solid-js` `^1.8.0`；`@solidjs/router` `^0.15.4 || ^1.0.0`（選用，僅 `@i18n-micro/solid/router` 需要）。目前尚不支援 Solid 2。

## 設定 {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` 接受 `i18n`、`locales`、`defaultLocale` 與 `routingStrategy`；省略的 prop 會沿用外層 provider 的值，執行個體也是如此。`getLocaleName()` 與 `<I18nSwitcher>` 會讀取 `locales`；沒有它們就沒有可列出的內容。選項請見[執行個體](/zh-Hant/integrations/overview#the-instance)。此執行個體即為 [runtime](/zh-Hant/integrations/runtime-package) 的執行個體，並在其 store 上包了一個 signal。

## 翻譯 {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

請在 JSX 或 effect 中呼叫這些方法，讓 Solid 能追蹤它們，`localePath` 與 `getLocale` 也一樣；在元件主體中只讀取一次的值不會更新。在執行個體上，請以 `i18n.locale` 與 `i18n.currentRoute` 進行追蹤：`i18n.getLocale()` 保持為一般函式，因為寫入操作會讀取它。讀取語系只會在語系變更時觸發，因此讀取語系並載入字典的 effect 只會執行一次。請勿解構 props，也不要將 `t('key')` 的結果存放在一般變數中。

`useI18n()` 會回傳 `t`、`ts`、`tc`、`tn`、`td`、`tdr`、`has`、`locale`（accessor：`locale()`）、`getLocale`、`getLocales`、`defaultLocale()`、`getLocaleName`、`switchLocale`、`localePath`、`localeRoute`、`setRoute`、`getRoute`、`addTranslations`、`addRouteTranslations`、`resolveTranslations`、`setTranslation`、`clearCache` 與 `instance`。

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## 切換語系 {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

切換時不會載入任何內容；請先加入該語系的字典。

`<I18nGroup>` 會將加上前綴的 `t` 傳給函式子元素。其中的 `<I18nT>` 與 `t()` 不會加上前綴：

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## 路由 {#routing}

`@solidjs/router` 轉接器位於子路徑中，因此主要進入點永遠不會匯入路由器。請在路由器之下呼叫它，通常是在路由器的 `root` 中，因為那裡可以使用 `useNavigate` 與 `useLocation`：

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

轉接器會為預設語系以外的所有語系加上前綴（`/about`、`/de/about`），並將 `<I18nLink>` 渲染為路由器的 `<A>`。`getCurrentPath` 會讀取路由器的響應式 location，因此啟用中的連結與語言切換器會跟著它更新；自訂策略只要在該處讀取 signal 也能達到相同效果。請注意參數順序：`(locales, defaultLocale, navigate, location)`。若使用其他路由器，請撰寫包含 `getCurrentPath`、`push` 與 `replace`（皆為必要）的轉接器 — 請參閱[路由器轉接器](/zh-Hant/integrations/overview#router-adapter)。

## SSR {#ssr}

若要進行伺服器渲染，請使用 `vite-plugin-solid` 建置：套件的 `solid` export 條件會將原始碼交給它，使其能為伺服器編譯。預先建置的 `dist` 僅供瀏覽器使用。執行個體沒有 `destroy()`；請為每個應用程式建立一個，或在伺服器上為每個請求建立一個，並讓它被垃圾回收。
