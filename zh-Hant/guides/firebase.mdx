# 🔥 Firebase AppHosting 部署

## 📖 簡介

Firebase AppHosting 是強大的無伺服器平台,可用來部署 Nuxt 應用。然而,在部署使用 `nuxt-i18n-micro` 的應用時,你可能會遇到與翻譯 JSON 檔提供方式相關的特定問題。本指南提供完整解決方案,確保你的翻譯在生產環境中正常運作。

## ⚠️ 常見問題

### 翻譯檔未套用

**症狀:**

- ✅ 開發模式(`nuxt dev`)中翻譯完全正常
- ❌ 部署到 Firebase AppHosting 後,JSON 檔已載入但翻譯未套用
- ❌ 主控台沒有錯誤
- ❌ 翻譯檔在 Network 分頁可見,但 `Content-Type` 錯誤為 `text/html` 而非 `application/json`

**根本原因:**

Firebase AppHosting(以及使用 Nitro 預渲染的其他平台)可能以錯誤的 MIME 型別提供預渲染 JSON 檔。當瀏覽器收到 `Content-Type: text/html` 的 JSON 檔時,無法正確解析,導致翻譯默默失效。

## ✅ 解決方案

### 解法 1:路由規則設定(推薦)

最直接的解法是在 `nuxt.config.ts` 中為翻譯路由加入明確標頭:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**優點:**

- ✨ 設定簡單
- 🚀 藉由適當快取提升效能
- 🔒 適用於所有部署平台

### 解法 2:自訂 API Base URL

若你使用自訂 `apiBaseUrl`(僅路徑前綴),相應調整路由規則:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### 解法 3:Firebase 專屬設定

在專案根目錄建立或更新 `firebase.json`:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```

## 🔍 偵錯

### 啟用偵錯模式

新增偵錯記錄以協助找出問題:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

這會輸出以下詳細記錄:

- 📝 翻譯檔載入
- 🔄 快取操作
- ⚠️ 載入錯誤

### 檢查 Network 分頁

1. 開啟 DevTools → Network 分頁
2. 以「data.json」篩選
3. 點擊翻譯檔請求
4. 驗證 **Response Headers**:
   - ✅ `Content-Type: application/json`(正確)
   - ❌ `Content-Type: text/html`(不正確 — 需修復)

### 驗證預渲染輸出

建置後,確認翻譯檔已產生:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

每個頁面下的每個語系,你都應該能看到 `data.json`。

## 🚀 建置設定

### Nitro Preset

對於 Firebase AppHosting,請確保使用正確的 preset:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### 預渲染設定

設定預渲染以取得最佳效能:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

## 📋 完整範例設定

以下是 Firebase AppHosting 的完整可用設定:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'es', iso: 'es-ES', dir: 'ltr' },
      { code: 'it', iso: 'it-IT', dir: 'ltr' },
      { code: 'pt', iso: 'pt-PT', dir: 'ltr' },
      { code: 'ru', iso: 'ru-RU', dir: 'ltr' },
      { code: 'zh', iso: 'zh-CN', dir: 'ltr' },
      { code: 'ko', iso: 'ko-KR', dir: 'ltr' },
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
    debug: false, // Enable in development if needed
  },

  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },

  },

  nitro: {
    preset: 'firebase-app-hosting',
    prerender: {
      crawlLinks: true,
      routes: ['/'],
    },
  },
})
```

## ✅ 驗證檢查清單

套用修正後,請確認以下項目皆正常:

- [ ] 建置無錯誤完成
- [ ] 翻譯 JSON 檔位於 `.output/public/_locales/\{page\}/\{locale\}/data.json`
- [ ] Network 分頁顯示翻譯檔的 `Content-Type: application/json`
- [ ] 首次載入頁面時翻譯正確顯示
- [ ] 主控台沒有 hydration 不匹配
- [ ] 語言切換運作正常
- [ ] SEO meta 標籤正確產生

## 🔄 部署流程

### 1. 準備建置

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. 部署到 Firebase

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. 驗證部署

1. 造訪你已部署的網站
2. 開啟 DevTools → Network 分頁
3. 導覽到一個頁面
4. 檢查 `/_locales/index/en/data.json`(或你的預設語系)是否符合以下條件載入:
   - Status:200
   - Content-Type:application/json
   - Response 包含有效 JSON

## 🔧 疑難排解

### 問題:翻譯檔出現 404

**解法:**確認翻譯檔已複製到輸出目錄:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### 問題:部分頁面翻譯正常,部分不正常

**解法:**檢查是否正在產生頁面專屬翻譯:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

若缺少頁面專屬翻譯,請確認 `disablePageLocales` 未設為 `true`:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### 問題:翻譯載入緩慢

**解法:**最佳化快取與預先載入:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## ⚡ 效能最佳化

### 啟用壓縮

Firebase 會自動處理 Gzip/Brotli 壓縮,但請確保你的建置已最佳化:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### 延遲載入翻譯

`Nuxt I18n Micro` 會自動以頁面為單位延遲載入翻譯。只有在需要時才會載入,減少初始 bundle 體積。這是內建功能,無需額外設定。

若要進一步最佳化:

- 使用 `disablePageLocales: false`(預設)以啟用頁面專屬翻譯
- 保持根層級翻譯精簡
- 為頁面內容使用路由專屬翻譯檔

<Tip>
自 **v3.0.0+** 起,模組會自動設定正確的 `Content-Type` 標頭。若你遇到問題,請更新到最新版:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
