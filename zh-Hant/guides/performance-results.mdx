# 效能測試結果

- **[plain-nuxt](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/plain-nuxt)**:./test/fixtures/plain-nuxt

- **[CLI](https://github.com/s00d/nuxt-i18n-micro/tree/main/scripts/src/commands/performance.ts)**:`pnpm -C scripts cli performance` / `pnpm test:performance`

### 說明

在共同字典配置下,比較 **plain Nuxt**(不含 i18n 模組的基準)、**i18n-micro**,以及 **`@nuxtjs/i18n` v10.6**。

聚焦於:建置時間、峰值 RSS、可部署的**程式碼 vs 翻譯 vs 總量**,以及在 Artillery + Autocannon 下的伺服器行為。

### 方法說明

- 各項指標為 **每個 fixture 連續 3 次執行的平均值**(fixture A ×3,再 B ×3,再 C ×3 —— 非交錯執行)。
- **翻譯**涵蓋 `locales/` / `_locales/` / `translations/` 下的語系 JSON、`chunks/raw/` 下所有內容,以及對應的語系 chunks。舊版報告顯示 `@nuxtjs/i18n` 的「translations: 0 B」與異常大的「code」欄位,是因為誤把訊息 chunks 計為 app code。
- **plain-nuxt** 透過 `public/translations` JSON(而非靜態 JS import)提供相同體量的內容。在 Artillery 下,該基準的 I/O 負擔較重;那並非「i18n 開銷」,而是每次請求都要抓取大型 JSON 的成本。

### 執行

以下所有指標皆為 **3 次執行的平均**。
