# 🌐 Crowdin 整合指南

## 📖 簡介

將 Crowdin 整合到專案中,可簡化在地化與翻譯流程,更容易跨多種語言與平台管理翻譯。本指南提供逐步的教學,說明如何在你的專案中設定 Crowdin,包括設定、上傳來源檔以及下載翻譯。

## 🔧 安裝與設定

要開始使用 Crowdin,你需要在本機全域安裝 Crowdin CLI,並在專案目錄中進行初始化。

### 📦 安裝 Crowdin CLI

首先,使用 npm 全域安裝 Crowdin CLI:

```bash
npm install -g @crowdin/cli
```

### 🛠 在專案中初始化 Crowdin

在專案中執行以下指令初始化 Crowdin:

```bash
crowdin init
```

此指令會引導你完成設定流程,包括設定專案 ID、API token 及其他設定資訊。

## 🗂️ 設定指南

### 📄 Crowdin 設定檔(`crowdin.yml`)

Crowdin 設定檔(`crowdin.yml`)定義了來源檔的對應方式,以及翻譯應存放的位置。以下是一個設定範例:

```yml
'project_id': 'YOUR_PROJECT_ID'
'api_token': 'YOUR_API_TOKEN'
'base_path': './locales'
'base_url': 'https://api.crowdin.com'
'preserve_hierarchy': true

files:
  [
    { 'source': '/en.json', 'translation': '/%two_letters_code%.json' },
    { 'source': '/pages/**/en.json', 'translation': '/pages/**/%two_letters_code%.json' },
  ]
```

### 📂 關鍵設定參數

- **`project_id`**:你的 Crowdin 專案 ID。用於識別 Crowdin 上管理翻譯的專案。
- **`api_token`**:用於驗證的 API token。請確保此 token 具有上傳與下載翻譯的正確權限。
- **`base_path`**:指定來源檔的基底目錄。在此範例中,翻譯儲存於 `./locales` 目錄。
- **`base_url`**:Crowdin API 的基底 URL。
- **`preserve_hierarchy`**:設為 `true` 時,Crowdin 會在專案中保留來源檔的資料夾結構。

### 📂 檔案設定

`files` 區段將來源檔對應到翻譯儲存的路徑。例如:

- **來源路徑**:定義原始翻譯檔的位置。
- **翻譯路徑**:指定翻譯後檔案在 Crowdin 中的儲存位置。可使用 `%two_letters_code%` 之類的佔位符,在檔案路徑中動態填入語言代碼。

## ⬆️ 將來源檔上傳至 Crowdin

Crowdin 設定完成後,可使用下列指令上傳來源檔:

```bash
crowdin upload sources
```

此指令會將設定中指定的所有來源檔上傳至 Crowdin,以供翻譯使用。

## ⬇️ 從 Crowdin 下載翻譯

當翻譯在 Crowdin 上完成或更新後,可使用下列指令下載到專案:

```bash
crowdin download
```

此指令會從 Crowdin 取得最新翻譯,並依設定檔指定的路徑儲存到專案中。

## ⚙️ 最佳實務

### 🔑 一致的鍵命名

確保翻譯鍵在所有檔案中一致,以避免混淆與重複。

### 🧹 定期維護

定期檢視並清理未使用的翻譯鍵,讓檔案保持整潔且易於管理。

### 🛠 自動化上傳與下載

將 Crowdin CLI 指令整合至 CI/CD 管線,自動化來源檔上傳與翻譯下載,確保翻譯永遠保持最新。

依循本指南,你便能將 Crowdin 無縫整合到專案中,以有效且有條理的方式管理國際化工作。
