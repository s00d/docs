# 從 i18n 路由中排除靜態檔案

## 概觀

預設情況下,nuxt-i18n-micro 會自動將常見的靜態檔案排除於 i18n 路由處理之外。你也可以設定自訂的排除模式,防止特定路徑被 i18n 系統處理。

## 內建排除

模組會自動排除以下檔案類型與模式:

- **Sitemaps**:`/sitemap*.xml`、`/sitemap-en.xml` 等
- **SEO 檔案**:`/robots.txt`、`/favicon.ico`
- **PWA 檔案**:`/manifest.json`、`/sw.js`、`/workbox-*.js`
- **靜態資產**:具有以下副檔名的檔案:`.xml`、`.txt`、`.ico`、`.json`、`.js`、`.css`、`.png`、`.jpg`、`.jpeg`、`.gif`、`.svg`、`.woff`、`.woff2`、`.ttf`、`.eot`
- **Nuxt 內部路徑**:任何以 `__` 開頭的路徑(例如 `/__nuxt/`)

## 自訂排除模式

你可以使用 `excludePatterns` 選項定義自訂排除模式:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## 模式類型

### 字串模式

- **完全相符**:`'/api/health'` — 完全對應 `/api/health`
- **前綴相符**:`'/admin'` — 對應 `/admin` 與 `/admin/dashboard`
- **萬用字元**:`'/api/*'` — 對應 `/api/users`,但不對應 `/api/users/123`
- **深層萬用字元**:`'/admin/**'` — 對應 `/admin/users` 與 `/admin/users/123`

### 正規表示式

使用 RegExp 物件進行複雜的模式比對:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## 使用情境

### SEO 檔案

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API 路由

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### 管理後台

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### 靜態資產

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## 運作方式

1. **伺服器中介層**:Nitro 中介層會先執行,檢查排除模式
2. **頁面處理**:於頁面解析期間,被排除的路徑會被略過
3. **Catch-all 路由**:預設路由在處理前會檢查排除
4. **預渲染**:被排除的路徑不會納入預渲染路由

## 效能影響

- 排除檢查已最佳化,並在請求生命週期的早期執行
- 內建模式使用有效率的 regex 比對
- 自訂模式會被快取與重複使用
- 對排除路徑的效能開銷極小

## 疑難排解

### 靜態檔案仍被攔截

1. **檢查模式語法**:確保你的模式對應到確切的路徑結構
2. **使用 regex 處理複雜模式**:字串萬用字元有其限制
3. **測試模式**:使用瀏覽器開發者工具驗證實際的請求路徑
4. **確認順序**:確保排除模式在其他 i18n 設定之前定義

### 模式無效

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### 偵錯模式

啟用偵錯模式以查看排除處理:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

這會將排除決策記錄到主控台。

## 從變通做法遷移

若你原本使用路由規則或中介層作為變通,現在可以將它們替換為 `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

新做法更加可靠,並在路由系統的多個層級都有效。
