# 選項細節

此模組提供豐富的設定選項,可自訂你的國際化設定。

### 🌍 核心語系設定

#### `locales`

{/* generated:option:locales — do not edit; run `pnpm run docs:generate` */}

**型別** `Locale[]` · **預設** `[]`

支援的語系清單。
每個項目定義一個語系代碼以及可選的中繼資料(ISO、方向、顯示名稱等)。

{/* /generated:option:locales */}

每個語系物件支援:

| 屬性             | 型別      | 必要 | 說明                                                    |
| ---------------- | --------- | ---- | ------------------------------------------------------- |
| `code`           | `string`  | ✅   | 唯一識別碼(例如 `'en'`)                               |
| `displayName`    | `string`  | ❌   | 供切換器使用的人類可讀名稱(例如 `'English'`)          |
| `iso`            | `string`  | ❌   | ISO 代碼(例如 `'en-US'`)                              |
| `dir`            | `string`  | ❌   | 文字方向(`'ltr'` 或 `'rtl'`)                          |
| `disabled`       | `boolean` | ❌   | 若為 `true`,於下拉選單中停用                           |
| `baseUrl`        | `string`  | ❌   | 特定語系網域的基底 URL                                  |
| `baseDefault`    | `boolean` | ❌   | 從 URL 中移除語系前綴                                   |
| `fallbackLocale` | `string`  | ❌   | 語系專屬的 fallback(覆寫全域設定)                     |
| `[key: string]`  | `unknown` | ❌   | 任何自訂屬性(見下方)                                  |

**範例**:

```typescript
locales: [
  { code: 'en', iso: 'en-US', dir: 'ltr' },
  { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
  { code: 'ar', iso: 'ar-SA', dir: 'rtl', disabled: true },
  {
    code: 'de',
    iso: 'de-DE',
    dir: 'ltr',
    baseUrl: 'https://de.example.com',
    baseDefault: true,
  },
]
```

<Warning>
使用 `baseUrl` 可能導致內部路由被以外部連結形式重複,增加路由與維運的複雜度。可考慮直接為特定語系建立外部連結。
</Warning>

#### 自訂語系屬性

你可以為語系物件加入任意自訂屬性。它們會傳遞至執行時,並可透過 `$getLocales()` 取用:

```typescript
locales: [
  { code: 'en', iso: 'en-US', flag: '🇬🇧', currency: 'GBP' },
  { code: 'de', iso: 'de-DE', flag: '🇩🇪', currency: 'EUR' },
  { code: 'ru', iso: 'ru-RU', flag: '🇷🇺', currency: 'RUB' },
]
```

在元件中存取它們:

```vue
<template>
  <ul>
    <li v-for="locale in $getLocales()" :key="locale.code">{{ locale.flag }} {{ locale.displayName }} ({{ locale.currency }})</li>
  </ul>
</template>
```

預設情況下,自訂屬性的型別為 `unknown`。要獲得完整的 TypeScript 支援,請使用**模組擴充(module augmentation)**。建立一個宣告檔(例如 `app/i18n.d.ts` 或任何被 `tsconfig` 引入的 `.d.ts`):

```typescript
// app/i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
    currency?: string
  }
}
```

之後,所有自訂屬性就會有完整型別:

```typescript
const locales = $getLocales()
locales[0].flag // string | undefined ✅
locales[0].currency // string | undefined ✅
```

</Tip>
#### `defaultLocale`

{/* generated:option:defaultLocale — do not edit; run `pnpm run docs:generate` */}

**型別** `string` · **預設** `'en'`

當無法從 URL 或使用者偏好判定語系時所使用的語系。
若未設定 `fallbackLocale`,此設定也會作為缺失翻譯時的 fallback 語系。

{/* /generated:option:defaultLocale */}

```typescript
defaultLocale: 'en'
```
#### `strategy`

{/* generated:option:strategy — do not edit; run `pnpm run docs:generate` */}

**型別** `Strategies` · **預設** `'prefix_except_default'`

語系前綴的 URL 路由策略。

- `'no_prefix'` — URL 中不含語系;語系儲存於 cookie。
- `'prefix_except_default'` — 除預設語系外,所有語系皆加前綴。
- `'prefix'` — 一律加前綴,包含預設語系。
- `'prefix_and_default'` — 類似 `prefix`,但預設語系亦可透過無前綴形式存取。

{/* /generated:option:strategy */}

<CodeGroup>
```typescript no_prefix
strategy: 'no_prefix'
// Routes: /about, /contact
// Locale detection via browser/cookies
```

```typescript prefix_except_default
strategy: 'prefix_except_default'
// Default locale: /about, /contact
// Other locales: /fr/about, /de/contact
```

```typescript prefix
strategy: 'prefix'
// All locales: /en/about, /fr/about, /de/about
```

```typescript prefix_and_default
strategy: 'prefix_and_default'
// Both prefixed and non-prefixed versions for default locale
```
</CodeGroup>

### 📂 翻譯管理
#### `translationDir`

{/* generated:option:translationDir — do not edit; run `pnpm run docs:generate` */}

**型別** `string` · **預設** `'locales'`

相對於專案根目錄、包含翻譯 JSON 檔的目錄路徑。

{/* /generated:option:translationDir */}

```typescript
translationDir: 'i18n' // Custom directory
// Nuxt 4 colocation example:
// translationDir: 'app/locales'
```

路徑會從 Nuxt **專案根目錄**(`rootDir`)解析,而非從 `app/`。搭配 Nuxt 4 時的常見配置是使用 `app/pages/` 存放路由,並使用 `locales/`(或設定 `translationDir` 時使用 `app/locales`)存放 JSON 檔。
#### `disablePageLocales`

{/* generated:option:disablePageLocales — do not edit; run `pnpm run docs:generate` */}

**型別** `boolean` · **預設** `false`

停用頁面專屬翻譯檔。
若為 `true`,只載入全域翻譯(`\{locale\}.json`);
不會產生或載入頁面專屬檔案(`pages/\{page\}/\{locale\}.json`)。

{/* /generated:option:disablePageLocales */}

啟用後,只會使用根層級翻譯檔:

```tree
locales/
├── en.json
├── fr.json
└── ar.json
```
#### `fallbackLocale`

{/* generated:option:fallbackLocale — do not edit; run `pnpm run docs:generate` */}

**型別** `string` · **預設** `undefined(無 fallback;回傳原始鍵)`

全域 fallback 語系代碼。
若當前語系缺少某個翻譯鍵,模組會先在此語系查找,再回傳鍵本身。

{/* /generated:option:fallbackLocale */}

```typescript
fallbackLocale: 'en' // Global fallback
```
#### `types`

{/* generated:option:types — do not edit; run `pnpm run docs:generate` */}

**型別** `boolean` · **預設** `true`

根據預設語系檔案中的翻譯鍵,為 `useI18n`、`$t` 及相關輔助函式產生 TypeScript 型別宣告。

{/* /generated:option:types */}

啟用時,模組會在建置期發出 `.nuxt/i18n.d.ts`,包含具型別的翻譯鍵。若你偏好未具型別的輔助函式,或使用外部產生器,可設定為 `false`。

此內建產生器與可選的 [`@i18n-micro/types-generator`](/integrations/types-generator) 套件分離,後者可為 monorepo 與 CI 產生更嚴格或獨立的型別檔。

```typescript
types: false // Disable built-in key typing
```
#### `routeLocales`

{/* generated:option:routeLocales — do not edit; run `pnpm run docs:generate` */}

**型別** `Record<string, string[]>` · **預設** —

從 `defineI18nRoute()` 呼叫擷取的每路由語系限制。
將路由路徑(例如 `'/about'`)對應到允許的語系代碼陣列。
未列出的路由沒有限制(允許所有語系)。

{/* /generated:option:routeLocales */}

將路由路徑(例如 `'/about'`)對應到允許的語系代碼。未列出的路由允許所有已設定的語系。

一般會透過頁面中的 [`defineI18nRoute`](/guides/custom-locale-routes) 設定,而非在 `nuxt.config` 中配置。模組會在建置期將頁面層級的宣告合併到這張對應表中。
#### `routeDisableMeta`

{/* generated:option:routeDisableMeta — do not edit; run `pnpm run docs:generate` */}

**型別** `Record<string, boolean \| string[]>` · **預設** —

從 `defineI18nRoute()` 呼叫擷取的每路由 meta 標籤停用設定。
將路由路徑對應到 `true`(全部 meta 皆停用)或應停用 meta 的語系代碼陣列。

{/* /generated:option:routeDisableMeta */}

- `true` — 停用該路由的所有 SEO meta
- `string[]` — 僅停用列出的語系代碼的 meta

與 `routeLocales` 類似,通常在頁面元件中設定,而非在設定檔中手動指定。
#### `experimental`

{/* generated:option:experimental — do not edit; run `pnpm run docs:generate` */}

**型別** `Record<string, unknown>` · **預設** —

實驗性/不穩定選項的容器。
內容可能在次版本間變更或移除,恕不另行通知。

{/* /generated:option:experimental */}

大多數過去的 `experimental.*` 旗標在 v3 已提升為頂層選項(例如 `hmr`)。請優先使用已文件化的頂層選項。只有在遵循提及特定鍵的版本說明或遷移指南時,才使用 `experimental`。

### 🔍 SEO 與 Meta 標籤
#### `meta`

### 🔢 客製化
#### `plural`

{/* generated:option:plural — do not edit; run `pnpm run docs:generate` */}

**型別** `PluralFunc` · **預設** `內建複數規則(以計數為索引選擇形式)`

自訂複數化函式。
接收 `(key, count, params, locale, getter)`,應回傳被選中的複數形式字串,
或回傳 `null`/`undefined` 讓內建的 `defaultPlural` 邏輯處理
(因此你可以只覆寫部分語系)。

對於 Nuxt 模組,此函式會透過 `.toString()` 序列化到 `.nuxt/i18n.plural.mjs` —
必須是自包含的(不能有 imports / 外部作用域)。
**不支援**以檔案路徑字串設定。

{/* /generated:option:plural */}

##### 運作方式

翻譯使用 `|` 分隔複數形式:

```json
{
  "apples": "no apples | one apple | {count} apples"
}
```

需要多個參數(不只 `\{count\}`)時,使用 `$tc('apples', count)` 或 `$tc('cart', \{ count, name \})` —— **將 `count` 與其他參數一併放在第二個引數物件中**,而非作為第三個引數(第三個引數僅為 `defaultValue`)。

`$tc` 呼叫會執行 `plural` 函式,流程為:

1. 呼叫 `t(key)` 取得原始翻譯字串(例如 `"no apples | one apple | \{count\} apples"`)
2. 以 `|` 分割成形式陣列
3. 依 `count` 選擇一個形式
4. 將 `\{count\}` 替換為實際數字

**預設**實作以索引選擇:`count < forms.length ? forms[count] : forms[last]`。此方式適用於簡單情境(0 → 第一種形式,1 → 第二種,2+ → 最後一種)。

##### 自訂複數函式

對於複數規則較複雜的語言(例如俄文、阿拉伯文、波蘭文),請覆寫 `plural` 選項。

<Danger>
此函式會透過 `.toString()` 序列化,並在建置期注入虛擬模組。這代表:

- **必須使用 `function` 關鍵字** —— 不可用簡寫方法語法,也不可用引用外部的箭頭函式
- **不能有 imports 或外部參考** —— 函式必須完全自包含(例如 `plural: '~/i18n/plural.ts'` 的檔案路徑**不受支援**)
- **不能有僅 TypeScript 才有、無法通過 `.toString()` 的語法**(在 `nuxt.config.ts` 中可以使用型別註記,因為 Nuxt 會將其剝除)
- 回傳 `null` / `undefined` 會退回內建的 `defaultPlural`(適合僅對部分語系覆寫)
</Danger>

**範例:俄文複數**(4 種形式:zero、one、few、many):

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    plural: function (key, count, _params, _locale, t) {
      const translation = t(key)
      if (!translation) return key

      const forms = translation
        .toString()
        .split('|')
        .map(function (s) {
          return s.trim()
        })
      let idx

      if (count === 0) {
        idx = 0
      } else {
        const mod10 = count % 10
        const mod100 = count % 100
        if (mod10 === 1 && mod100 !== 11) {
          idx = 1
        } else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) {
          idx = 2
        } else {
          idx = 3
        }
      }

      if (idx >= forms.length) idx = forms.length - 1
      return (forms[idx] || '').replace('{count}', String(count))
    },
  },
})
```

搭配此翻譯:

```json
{
  "apples": "нет яблок | {count} яблоко | {count} яблока | {count} яблок"
}
```

結果:

- `$tc('apples', 0)` → `"нет яблок"`
- `$tc('apples', 1)` → `"1 яблоко"`
- `$tc('apples', 3)` → `"3 яблока"`
- `$tc('apples', 5)` → `"5 яблок"`
- `$tc('apples', 21)` → `"21 яблоко"`

**範例:簡單英文(預設行為)**:

```typescript
// This is the built-in default — you don't need to set it explicitly
plural: function (key, count, params, _locale, t) {
  const translation = t(key, params)
  if (!translation) return null

  const forms = translation.toString().split('|')
  if (forms.length === 0) return null
  const form = count < forms.length ? forms[count] : forms[forms.length - 1]
  if (!form) return null
  return form.trim().replace('{count}', count.toString())
}
```

```typescript
  mode: 'premerged',
  serverAssets: true,
  serverHandler: true,
  publicAssets: true,
  prerenderRoutes: false
}
```

在 **Node** 上,SSR 讀取被複製到 `public/<apiBaseUrl>/` 的相同樹狀結構(`readFile`)。在 **Edge** 上,Nitro `serverAssets` 會將其內嵌(不強制產生 public 複本 —— 若要供 CDN,請設 `publicAssets: true`)。`mode: 'premerged'` → 為每頁面/語系產出 `\{page\}/\{locale\}/data.json`;`mode: 'source'` → 精簡的來源檔 + 執行時合併。

在 **Node** 上,`serverAssets: true` 會強制產生 public 複本,即使 `publicAssets` 為 false。在 **Edge** 上只會註冊 Nitro 內嵌。大型字典在 Edge 上建議使用 `mode: 'source'`。若無本地 payload 且未設 `apiBaseServerHost`,建置將失敗。

本地的 `/\{apiBaseUrl\}/:page/:locale/data.json` 處理器、預渲染路由與 public 資產複本仍為可選輸出。

若要產生更精簡的 **public** / Edge payload:

```typescript
i18n: {
  translationPayloads: {
    mode: 'source',
  },
}
```

`mode: 'source'` 讓 layer 檔案保持精簡,並透過內建的 `/_locales` 路由(或 Edge `assets:i18n`)在執行時合併 root/page/fallback。預設情況下會停用 public 資產複本與預渲染的 payload 路由。

<Warning>
在 `mode: 'source'` 下,`publicAssets` 預設為 `false`(除非你明確啟用,`prerenderRoutes` 一律關閉)。因此沒有 Nitro/edge 執行時的純靜態代管無法在客戶端載入翻譯,除非你啟用其中一項輸出、保留執行時可用的 `serverHandler`,或改由外部代管 payload。

在預設 `mode: 'premerged'` 且 `publicAssets: true` 下,靜態檔已產生於 `public/<apiBaseUrl>/\{page\}/\{locale\}/data.json` —— 對應客戶端 `$fetch` 的 URL —— 因此靜態代管即使沒有 Nitro 也能提供服務。
</Warning>

<Warning>
當設定了 `apiBaseServerHost` 或 `apiBaseClientHost`,模組會從該來源抓取已合併的 JSON。外部主機必須提供與內建路由相同的 `/\{apiBaseUrl\}/:page/:locale/data.json` 回應。`mode: 'source'` 適用於本地 payload 目錄,不會套用至外部 CDN,除非該 CDN 也能提供在執行時合併的 payload。
</Warning>

你也可以手動停用重複的本地輸出,改由 CDN 或物件儲存服務提供翻譯 payload:

```typescript
i18n: {
  apiBaseClientHost: 'https://cdn.example.com',
  apiBaseServerHost: 'https://cdn.example.com',
  translationPayloads: {
    serverHandler: false,
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

若只想避免將 payload 寫入 public 輸出,但保留內建伺服器路由供 SSR/執行時請求使用,則同時停用兩種 public 輸出:

```typescript
i18n: {
  translationPayloads: {
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

在 **Node** 上,即使 `publicAssets` 為 false,`serverAssets: true` 仍會為 SSR 強制產生 public 複本 —— 若要完全沒有本地 payload 檔,請設定 `serverAssets: false` 並搭配 `apiBaseServerHost`。

當 payload 被複製時,可透過 `publicDir` 更改 public 輸出資料夾。預設為 `apiBaseUrl`(`_locales`)。在 premerged 模式下,`publicAssets` 會將 `\{page\}/\{locale\}/data.json` 寫入該路徑(與客戶端抓取的路徑相同)。`prerenderRoutes` 是處理器路由的可選 Nitro 預渲染 —— 當該樹狀結構已被複製時,通常屬多餘。

若停用所有本地 payload 輸出,你必須同時設定 `apiBaseServerHost`(SSR)與 `apiBaseClientHost`(客戶端導覽),否則翻譯會解析為空物件,UI 中的鍵可能顯示為未翻譯。

`warnFileCount` 與 `warnSizeBytes` 控制在預合併 payload 輸出過大時的建置期警告(預設:500 個檔案與 10 MB)。

#### `dateBuild`

{/* generated:option:dateBuild — do not edit; run `pnpm run docs:generate` */}

**型別** `string \| number` · **預設** —

用於為翻譯請求進行快取失效(`?v=...`)的值。

未提供時,模組會退回為 `Date.now()`(非確定性)。
若希望可重現/滾動式部署,請將此設為穩定值
(例如 git SHA 或 build number)。

{/* /generated:option:dateBuild */}

預設情況下,模組會對翻譯來源進行指紋計算(對每個 `<layer>/<translationDir>/**/*.json` 依層級順序計算 SHA-256),並以此為值。這個值只在翻譯實際變更時才會改變,因此重新建置或重新部署未變動的翻譯時,瀏覽器與 CDN 快取仍會保留 —— 若 `httpCacheDuration` 設為一年,使用建置時間戳反而會強迫每次部署所有客戶端重新下載整個字典。

只有在沒有翻譯檔可雜湊時,才會退回為 `Date.now()`。

若要明確掌控(例如將 payload URL 綁定至發佈版本而非內容):

```ts
export default defineNuxtConfig({
  i18n: {
    // Any stable string/number: git SHA, CI build number, release tag, etc.
    dateBuild: process.env.GIT_SHA ?? 'local-dev',
  },
})
```
#### `httpCacheDuration`

{/* generated:option:httpCacheDuration — do not edit; run `pnpm run docs:generate` */}

**型別** `number` · **預設** `31536000`

`/\{apiBaseUrl\}/:page/:locale/data.json` 的 HTTP `Cache-Control` max-age(秒)。

只有在 `dateBuild` 讓 URL 失效(`?v=...`)時(即預設情形)才完全套用:
回應會是 `public, max-age=…, immutable`,對瀏覽器與 CDN 而言安全。

- `dateBuild: 0`/`''` — URL 為穩定值,因此此期限**不會**被套用;回應會變為 `public, max-age=0, must-revalidate`。對不變的 URL 使用長 `max-age` 會將瀏覽器最初看到的 payload 固定下來。

- `0` — 完全不設定 `Cache-Control`(本地偵錯時實用)
- 在開發模式(`import.meta.dev`)下不會套用,以免瀏覽器快取妨礙 HMR
- 僅套用至透過 Nitro 提供的回應。被複製到 `public/` 並由代管平台提供的 payload 則採用該平台的標頭 —— 請參閱效能指南。

類似於 `@nuxtjs/i18n` 的實驗性 `httpCacheDuration`(v10.2.0),但改為明確的回應標頭,而非 Nitro `defineCachedEventHandler` 的 maxAge。

{/* /generated:option:httpCacheDuration */}

```ts
export default defineNuxtConfig({
  i18n: {
    // Per-build fallback (Date.now()) so immutable payloads never go stale when GIT_SHA is missing.
    dateBuild: process.env.GIT_SHA ?? String(Date.now()),
    httpCacheDuration: 86400, // 24 hours
    // httpCacheDuration: 0, // disable Cache-Control header
  },
})
```

#### `cacheTtl`

{/* generated:option:cacheTtl — do not edit; run `pnpm run docs:generate` */}

**型別** `number` · **預設** `0`

快取翻譯項目的存活時間(秒)。
`0` 表示永不過期。

{/* /generated:option:cacheTtl */}

```typescript
export default defineNuxtConfig({
  i18n: {
    // Limit cache to 1000 entries, each lives 10 minutes (refreshed on access)
    cacheMaxSize: 1000,
    cacheTtl: 600,
  },
})
```

<Tip>
對大多數專案而言,預設值(無上限、不過期)已足夠 —— 翻譯體積小且有限。然而,若你的專案有**上千個頁面**、`disablePageLocales: false`、且**多個語系**,伺服器快取可能顯著成長。在長時間執行的 Node.js 伺服器中,這可能造成過度記憶體使用。

- **`cacheMaxSize`** —— 限制快取項目數量。適合用來設定記憶體上限。
- **`cacheTtl`** —— 確保過時翻譯最終會從儲存體重新載入。適合無伺服器環境或翻譯在執行時會變動的情境。

**估算最大項目數的公式**:`number_of_locales × (number_of_pages + 1)`。例如 10 個語系 × 500 個頁面 = 約 5010 項。
</Tip>
