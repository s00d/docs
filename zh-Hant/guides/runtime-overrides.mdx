# 執行時 i18n 覆寫

當你需要以同一份建置產物，在不同環境（例如不同租戶實例）使用不同語系預設值時，可使用本指南。

## 執行時可覆寫的項目

模組支援以下項目的安全執行時覆寫：

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

這些覆寫會套用於 `.nuxt/i18n.strategy.mjs` 與 `.nuxt/i18n.config.mjs` 提供的建置期設定之上。

## 執行時無法覆寫的項目

`strategy`（`no_prefix`、`prefix`、`prefix_except_default`、`prefix_and_default`）屬於建置期關切的項目，因為它影響產生的路由行為。

若你傳入執行時的 strategy 覆寫，會被忽略並發出警告。

## 以 RuntimeConfig 進行覆寫

在 `runtimeConfig.public.i18nRuntime` 下提供執行時值：

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## 環境變數覆寫

你也可以透過環境變數設定覆寫：

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES`（以逗號分隔，例如 `fr,it`）

也支援以下 fallback 別名：

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## 驗證規則

執行時模組會驗證覆寫，避免出現失效狀態：

- 你不能停用所有語系。
- `defaultLocale` 必須指向已啟用的語系。
- `fallbackLocale` 必須存在於已宣告的語系中。

若覆寫無效，模組會保留安全值並記錄警告。

## 多實例部署備註

此執行時功能是為了逐實例的語系啟用與預設值調整，而不必重新建置。

若不同實例需要不同的 URL 策略（`no_prefix` 與 `prefix`），請為各策略建立獨立的建置。

## 停用語系與靜態 payload

`runtimeConfig.public.i18nRuntime.disabledLocales` 會更新路由、切換器與 Nitro payload **handler**，但 Nitro 會在該 handler **之前**先提供 `public/` 底下的檔案。

若 `translationPayloads.publicAssets`（或 Node SSR 強制產生的 public 副本）已寫出 `/_locales/\{page\}/\{locale\}/data.json`，執行時的停用設定無法隱藏該檔案。建議在建置期使用 `locale.disabled: true`，讓 premerge 不會為該語系產出靜態 payload。
