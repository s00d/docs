# 執行時的 i18n 覆寫

當你需要以單一建置產物在不同環境中執行不同語系預設時(例如:不同的租戶實例),請參考本指南。

## 執行時可覆寫的項目

模組支援安全的執行時覆寫,適用於:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

這些覆寫會套用於 `.nuxt/i18n.strategy.mjs` 與 `.nuxt/i18n.config.mjs` 的建置期設定之上。

## 執行時無法覆寫的項目

`strategy`(`no_prefix`、`prefix`、`prefix_except_default`、`prefix_and_default`)屬於建置期考量,因為會影響產生的路由行為。

若你傳入執行時的策略覆寫,將被忽略並發出警告。

## 基於 RuntimeConfig 的覆寫

在 `runtimeConfig.public.i18nRuntime` 提供執行時值:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## 環境變數覆寫

也可透過環境變數設定覆寫:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES`(以逗號分隔,例如 `fr,it`)

也支援 fallback 別名:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## 驗證規則

在執行時,模組會驗證覆寫以避免不正確的狀態:

- 不可停用所有語系。
- `defaultLocale` 必須指向已啟用的語系。
- `fallbackLocale` 必須存在於已宣告的語系中。

若覆寫無效,模組會保留安全值並記錄警告。

## 多實例部署的注意事項

此執行時功能旨在讓每個實例可有不同啟用語系與預設,而無需重新建置。

若不同實例需要不同的 URL 策略(`no_prefix` vs `prefix`),請為每個策略分別建置。

## 停用的語系與靜態 payload

`runtimeConfig.public.i18nRuntime.disabledLocales` 會更新路由、切換器與 Nitro payload **handler** —— 但 Nitro 提供 `public/` 下的檔案是**先於**該 handler 執行。

若 `translationPayloads.publicAssets`(或 Node SSR 強制的 public 複本)已寫入 `/_locales/\{page\}/\{locale\}/data.json`,執行時停用無法隱藏該檔案。建議在建置期使用 `locale.disabled: true`,讓 premerge 不為該語系發出靜態 payload。
