`@i18n-micro/react` と `@i18n-micro/preact` は、フレームワーク非依存の [runtime](/ja/integrations/runtime-package) を、プロバイダー、`useI18n()` フック、4 つのコンポーネントでラップします。Nuxt でビルドされていない React または Preact アプリで使用してください。両パッケージは同じ API を持ちます。いくつかの違いは [Preact](#preact) セクションに、共通のモデルは [フレームワーク](/ja/integrations/overview) にあります。

## インストール {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/react
```

```bash npm
npm install @i18n-micro/react
```

```bash yarn
yarn add @i18n-micro/react
```

</CodeGroup>

peer 依存関係: `react` `^18.0.0 || ^19.0.0`、`react-dom`（オプション、レンダリング用）、`react-router-dom` `^6.0.0 || ^7.0.0`（オプション、`@i18n-micro/react/router` にのみ必要）。React 19.3 と 18.3、React Router 7.18 と 6.30 でテストされています。

## セットアップ {#setup}

```tsx
// src/main.tsx
import { createRoot } from 'react-dom/client'
import { createI18n, I18nProvider } from '@i18n-micro/react'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

createRoot(document.getElementById('root')!).render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
    <App />
  </I18nProvider>,
)
```

<Warning>

インスタンスはモジュールレベルまたは `useState` の初期化関数内で一度だけ作成してください。コンポーネント本体では決して作成しないでください。

</Warning>

`<I18nProvider>` は `i18n`、`locales`、`defaultLocale`、`routingStrategy` を受け取ります:

- 省略した prop は外側のプロバイダーの値（インスタンスを含む）を引き継ぎます。
- インスタンスがまったくない場合は、併せて渡された `createI18n` のオプションからインスタンスを作成するため、props はプレーンなデータのままで済みます: `<I18nProvider locale="de" messages={messages}>`。
- 新しい `locale` prop は、そのレンダリング時の `messages` で新しいインスタンスを作成します。このようなインスタンスはコンポーネント内に存在するため、マウント中に上位の何かがサスペンドすると、React はそれを追加された内容ごと破棄します。

`routeMessages` を含むすべての `createI18n` オプションは [インスタンス](/ja/integrations/overview#the-instance) にあります。

## 翻訳する {#translate}

```tsx
import { useI18n } from '@i18n-micro/react'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' })}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

`useI18n()` が返すもの:

| グループ | メンバー |
| --- | --- |
| 翻訳 | `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` |
| ロケールとルート | `locale`, `fallbackLocale`, `currentRoute`, `setLocale`, `setRoute`, `getRoute`, `getLocales`, `defaultLocale()`, `getLocaleName` |
| ルーティング | `switchLocale`, `localePath`, `localeRoute` |
| 辞書 | `addTranslations`, `addRouteTranslations`, `clearCache` |

- コンポーネントは、ロケール、ルート、または読み取り可能な辞書が変更されたとき、およびプロバイダーが新しい `locales` または `routingStrategy` オブジェクトを受け取ったときに再レンダリングされます。アクティブでもフォールバックでもないロケールの辞書は再レンダリングを引き起こしません。
- `t` やその他の翻訳メソッドはストアが変わったときにのみ変化するため、`memo` やエフェクトの依存配列で安全に使用できます。

`useT` は 1 つの文字列を値として返します。プロバイダーの他の props に何が起きても、コンポーネントはその文字列が変わったときにのみレンダリングされます。`<I18nT>` もそれらに依存しません:

```tsx
const title = useT('page.title')
```

辞書はいつでも追加で読み込めます:

```tsx
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

useEffect(() => {
  import('./locales/de.json').then((m) => addTranslations('de', m.default))
  addRouteTranslations('en', 'about', { title: 'About us' })
  setRoute('about') // t('title') now reads the 'about' dictionary first
}, [])
```

インスタンス自体にも、`fetch` で JSON を取得する `loadFromUrl(url, { locale, routeName })` があります。

## ロケールを切り替える {#switch-locale}

```tsx
const { setLocale, switchLocale } = useI18n()

setLocale('de') // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

切り替えでは何も読み込まれません。先にそのロケールの辞書を追加してください。ストアへの書き込みは React にとって同期的であり、`startTransition` 内でも同様です。そのため、辞書がなくてサスペンドするコンポーネントはフォールバックを表示してしまいます。`useLocaleSwitch` は先に読み込みを行い、辞書が揃うまで古い UI を維持します:

```tsx
const [switchTo, pending] = useLocaleSwitch((locale) => i18n.loadFromUrl(`/locales/${locale}.json`, { locale }))

<button disabled={pending} onClick={() => switchTo('de')}>Deutsch</button>
```

最後の呼び出しが優先されます。読み込みに失敗すると reject され、ロケールは元のままになります。

`<I18nGroup>` は render-prop の子要素にプレフィックス付きの `t` を渡します。その中の `<I18nT>` と `t()` にはプレフィックスが付きません:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## ルーティング {#routing}

React Router アダプターはサブパスにあるため、メインエントリが `react-router-dom` をインポートすることはありません。`useLocation()` と `useNavigate()` が必要なので、ルーター配下のコンポーネント内で作成してください:

```tsx
// src/App.tsx
import { useMemo } from 'react'
import { BrowserRouter, Route, Routes, useLocation, useNavigate } from 'react-router-dom'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/react'
import { createReactRouterAdapter } from '@i18n-micro/react/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Localized() {
  const location = useLocation()
  const navigate = useNavigate()
  // memoized: a new object on every render re-renders every `useI18n()` consumer
  const routingStrategy = useMemo(() => createReactRouterAdapter(locales, 'en', location, navigate), [location, navigate])
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      <Routes>
        <Route path="/:locale?" element={<Home />} />
        <Route path="/:locale?/about" element={<About />} />
      </Routes>
    </I18nProvider>
  )
}

export default function App() {
  return (
    <BrowserRouter>
      <Localized />
    </BrowserRouter>
  )
}
```

アダプターはデフォルト以外のすべてのロケールにプレフィックスを付け（`/about`、`/de/about`）、`<I18nLink>` を React Router の `<Link>` としてレンダリングします。URL からのロケール設定は自分で行ってください（たとえばエフェクト内で `useParams().locale` から）。その他のルーターの場合は、`getCurrentPath`、`push`、`replace`（すべて必須）を持つアダプターを作成してください。[ルーターアダプター](/ja/integrations/overview#router-adapter) を参照してください。

## SSR {#ssr}

`renderToString` は動作します。`useI18n()` にはサーバースナップショットがあります。異なるロケールのリクエスト同士が状態を共有しないよう、リクエストごとに 1 つのインスタンスを作成してレンダリング前に辞書を追加するか、プロバイダーにプレーンなデータを渡してください。

### ハイドレーション {#hydration}

数値、複数形、テキストはそのままハイドレートされます。日付はタイムゾーンに、相対日付は時刻に依存します。サーバーとブラウザの両方で `timeZone` を設定し、`tdr` については `now` でサーバーの時刻をブラウザに渡してください。`date` または `relativeDate` を指定した `<I18nT>` は `suppressHydrationWarning` を設定するため、差異があってもハイドレーションは失敗しませんが、テキストが変わるまではサーバーのテキストが残ります。これは 1 階層にしか及びません。翻訳を要素でラップする `children` は差異があると依然として失敗するため、それらには同じ `timeZone` を指定してください。

### Server Components {#server-components}

パッケージはクライアントコードに `'use client'` を付けています。`@i18n-micro/react/server` には `createI18n` と、フックを使わずインスタンスを prop として受け取る `I18nT` があるため、テキストはクライアントバンドルに含まれません。Next.js の App Router のような `react-server` 条件下では、メインエントリもこれに解決されますが、TypeScript はデフォルトではそれを認識しないため、`/server` からインポートしてください。`@i18n-micro/react/client` は常にクライアントエントリを提供します。

```tsx
// app/[locale]/layout.tsx: a server component
import { cache } from 'react'
import { createI18n, I18nT } from '@i18n-micro/react/server'
import { I18nProvider } from '@i18n-micro/react/client'
import { loadMessages } from './messages'

const getI18n = cache(async (locale: string) => createI18n({ locale, messages: await loadMessages(locale) }))

export default async function Layout({ params, children }) {
  const { locale } = await params
  const i18n = await getI18n(locale)
  return (
    <I18nProvider locale={locale} messages={{ [locale]: i18n.resolveTranslations() }}>
      <h1>
        <I18nT i18n={i18n} keypath="title" />
      </h1>
      {children}
    </I18nProvider>
  )
}
```

`react-server-dom-webpack` を通じてレンダリングしています。Next.js アプリそのものではまだ実行検証されていません。

## Preact {#preact}

`@i18n-micro/preact` は同じソースから、`preact/compat` を使わず Preact 自体の上にビルドされています。インスタンス、プロバイダー、フック、コンポーネントは同じです。違い:

| | React | Preact |
| --- | --- | --- |
| peer 依存関係 | `react`（+ オプションの `react-router-dom`） | `preact` `^10.0.0 \|\| ^11.0.0`、10.29 と 11.1 でテスト済み |
| インスタンスクラス | `ReactI18n` | `PreactI18n` |
| ルーターアダプター | `/router` の `createReactRouterAdapter` | `/router` の `createBrowserHistoryAdapter(locales, defaultLocale, ssrUrl?)` |
| 再レンダリング | `useSyncExternalStore` | ストアを再チェックするレイアウトエフェクトの購読 |
| Server Components | `/server`, `/client` | なし |

`createBrowserHistoryAdapter` は History API を使う任意のルーター（wouter、preact-router）で動作します。`push` と `replace` は `history.pushState` / `replaceState` を呼び出して `popstate` をディスパッチし、`<I18nLink>` は `push` でナビゲートする通常の `<a>` をレンダリングします。サーバーにはアドレスバーがないため、リクエストの URL を `ssrUrl` として渡してください。渡さないと、リンクとスイッチャーは `/` にいるものとしてレンダリングされます。ブラウザではアドレスバーが優先されます。

```tsx
// src/main.tsx
import { render } from 'preact'
import { createI18n, I18nProvider } from '@i18n-micro/preact'
import { createBrowserHistoryAdapter } from '@i18n-micro/preact/router'
import { App } from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={createBrowserHistoryAdapter(locales, 'en')}>
    <App />
  </I18nProvider>,
  document.getElementById('app')!,
)
```

完全なシグネチャ: [Preact リファレンス](/ja/api/packages/preact)。
