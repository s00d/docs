`@i18n-micro/*` パッケージは、Nuxt I18n Micro の翻訳コアを Vue、React、Preact、Solid、Astro、VitePress、そしてプレーンな JavaScript にもたらします。アプリが Nuxt アプリではない場合や、Nuxt の外にあるスクリプトやサーバーで同じ翻訳ファイルが必要な場合に使用してください。すべてのパッケージは、1 つのインスタンスモデル、1 つのルーターアダプターの契約、そして同じ 4 つのコンポーネントを共有しており、それらはこのページでまとめて説明します。

## パッケージ {#packages}

| スタック | パッケージ | ルーターエントリー |
| --- | --- | --- |
| [Vue 3 SPA](/ja/integrations/vue-package) | `@i18n-micro/vue` | `@i18n-micro/vue/router` |
| [React](/ja/integrations/react-package) | `@i18n-micro/react` | `@i18n-micro/react/router` |
| [Preact](/ja/integrations/react-package#preact) | `@i18n-micro/preact` | — |
| [SolidJS](/ja/integrations/solid-package) | `@i18n-micro/solid` | `@i18n-micro/solid/router` |
| [Astro](/ja/integrations/astro-package)：SSR と[アイランド](/ja/integrations/astro-islands) | `@i18n-micro/astro` | — |
| [ブラウザーまたはエッジ](/ja/integrations/runtime-package)、フレームワークなし | `@i18n-micro/runtime` | — |
| [Node.js](/ja/integrations/nodejs-package) サーバー、CLI | `@i18n-micro/node` | — |
| [型付きキー](/ja/integrations/types-generator)、Vite または Nuxt | `@i18n-micro/types-generator` | — |
| 開発時の[翻訳エディター](/ja/integrations/devtools-ui-package) | `@i18n-micro/devtools-ui` | — |

ルーターエントリーは別のインポートになっているため、ルーターを使わないアプリにルーターがバンドルされることはありません。

`@i18n-micro/core`、`@i18n-micro/types`、`@i18n-micro/utils` はこれらのパッケージと一緒にインストールされます。直接インポートすることはほとんどありません。すべてのエクスポートのシグネチャは、生成された[パッケージリファレンス](/ja/api/packages/overview)にあります。

各パッケージには、リポジトリの `packages/<name>/playground` にプレイグラウンドがあります。

## インスタンス {#the-instance}

`createI18n(options)` は、辞書、現在のロケール、現在のルートを保持する 1 つのインスタンスを返します。オプションはすべてのパッケージで共通です：

| オプション | 型 | デフォルト | 備考 |
| --- | --- | --- | --- |
| `locale` | `string` | 必須 | アクティブなロケール。 |
| `fallbackLocale` | `string` | `locale` | `locale` にキーが存在しない場合に参照されます。 |
| `messages` | `Record<locale, Translations>` | `{}` | ルート辞書（`'index'` ルート）。 |
| `routeMessages` | `Record<route, Record<locale, Translations>>` | `{}` | ルートごとの辞書。Runtime、React、Preact、Node、VitePress のみ。 |
| `plural` | `PluralFunc` | `defaultPlural` | カスタムの複数形ルール。 |
| `missingWarn` | `boolean` | `true` | キーが存在しない場合に、ブラウザーで開発時のみ `console.warn` を出力します。 |
| `missingHandler` | `(locale, key, routeName) => void` | — | 警告の代わりに呼び出されます。 |
| `numberFormats` | `Record<locale, Record<name, Intl.NumberFormatOptions>>` | — | 名前付きフォーマット：`tn(9.5, 'currency')`。 |
| `datetimeFormats` | `Record<locale, Record<name, Intl.DateTimeFormatOptions>>` | — | 名前付きフォーマット：`td(date, 'short')`。 |
| `timeZone` | `string` | ランタイムのタイムゾーン | `td` の日付に使う IANA タイムゾーン。`tdr` には影響しません。サーバーとブラウザーで同じ日付をレンダリングするように設定してください。 |
| `now` | `() => number` | `Date.now` | `tdr` の時計。両方が同じテキストをレンダリングするよう、ハイドレーションにサーバーの時刻を渡してください。 |
| `localeIso` | `Record<code, string>` | — | 複数形ルールに使用される BCP 47 タグ（`ua` → `uk-UA`）。React、Preact、Solid はプロバイダーの `locales` の `iso` から取得します。 |

辞書は `i18n.storage.translations` に格納されます。これは `locale:route`（`en:index`、`en:about`）をキーとする `Map` です。

キーは、まず `locale` について、次に `fallbackLocale` について、現在のルートの辞書、続いてルート辞書の順に検索されます。存在しないキーはキーそのもの（または渡した `defaultValue`）を返します。

```ts
i18n.addTranslations('en', { nav: { home: 'Home' } }) // root, deep-merged
i18n.addRouteTranslations('en', 'about', { title: 'About us' }) // route chunk
i18n.addTranslations('en', { nav: { home: 'Start' } }, false) // replace instead of merge
i18n.setRoute('about')
i18n.t('title') // 'About us'
i18n.t('nav.home') // 'Start' (root key, still visible on the route)
```

### 翻訳とフォーマット {#translate-and-format}

| メソッド | 戻り値 |
| --- | --- |
| `t(key, params?, defaultValue?, routeName?)` | `{param}` を補間した値（文字列、数値、オブジェクト）。 |
| `ts(...)` | `t` と同じですが、文字列として返します。 |
| `tc(key, count \| params, defaultValue?)` | 複数形。 |
| `tn(value, options \| name)` | アクティブなロケールでの `Intl.NumberFormat`。 |
| `td(value, options \| name)` | `Intl.DateTimeFormat`。 |
| `tdr(value, options?)` | 相対時間（`3 days ago`）。 |
| `has(key, routeName?)` | アクティブなロケールにキーがある場合に `true`（ルート辞書またはルートの辞書。フォールバックは確認されません）。 |

`defaultPlural` は値を `|` で分割し、インデックス `count` の形を選びます（最後の形を上限とします）。負の数、小数、`NaN` の count は最後の形を選びます。

カスタムの `plural` は `(key, count, params, locale, getter)` を受け取ります。値は `getter(key)` で読み取り、キーを分割しないでください：

```ts
import type { PluralFunc } from '@i18n-micro/vue'

const plural: PluralFunc = (key, count, params, _locale, getter) => {
  const value = getter(key)
  if (typeof value !== 'string') return null
  const forms = value.split('|').map((form) => form.trim())
  return (count === 1 ? forms[0] : forms[1] ?? forms[0])!.replace('{count}', String(count))
}
```

## ルーターアダプター {#router-adapter}

SPA パッケージはルーターに依存しません。ルーターアダプター（`I18nRoutingStrategy`）が、現在のパスの読み取り方、ナビゲーションの方法、ローカライズされたパスの構築方法をパッケージに伝えます。組み込みのアダプターは、`defaultLocale` 以外のすべてのロケールにプレフィックスを付けます（`/about`、`/de/about`）。

| メンバー | 必須 | 使用箇所 |
| --- | --- | --- |
| `getCurrentPath(): string` | はい | アクティブリンクの判定（ページ単位で、クエリとハッシュは考慮しない）、`switchLocale`（それらを保持する） |
| `push({ path }): void` | はい | `switchLocale`、`linkComponent` なしの `<I18nLink>`、`<I18nSwitcher>` |
| `replace({ path }): void` | はい | — |
| `resolvePath(to, locale)` | いいえ | `localePath`、`localeRoute`、`<I18nLink>`。ない場合、パスはそのまま返されます |
| `linkComponent` | いいえ | `<I18nLink>` は `<a>` の代わりにこれ（例：`RouterLink`）をレンダリングします |
| `getRoute()` | いいえ | SEO ヘルパー用の `{ fullPath, query }` |

`push` と `replace` は Vue、React、Preact、Solid で必須です。Astro には、`push`/`replace` が任意の独自のサーバーサイドアダプターがあります（[Astro](/ja/integrations/astro-package#router-adapter) を参照）。

任意の履歴ベースのルーター向けの最小限のアダプター：

```ts
import type { I18nRoutingStrategy } from '@i18n-micro/react'

const locales = ['en', 'de']
const stripLocale = (path: string) => path.replace(/^\/(en|de)(?=\/|$)/, '') || '/'

export const historyAdapter: I18nRoutingStrategy = {
  getCurrentPath: () => window.location.pathname + window.location.search + window.location.hash,
  push: ({ path }) => window.history.pushState({}, '', path),
  replace: ({ path }) => window.history.replaceState({}, '', path),
  resolvePath: (to, locale) => {
    const path = stripLocale(typeof to === 'string' ? to : to.path || '/')
    return locale === 'en' ? path : `/${locale}${path === '/' ? '' : path}`
  },
}
```

## コンポーネント {#components}

Vue、React、Preact、Solid は同じ 4 つのコンポーネントを提供します。プロパティは共通で、React、Preact、Solid はその他のプロパティをルート要素にそのまま渡します。

### `<I18nT>` {#&lt;i18nt&gt;}

| プロパティ | 型 | 備考 |
| --- | --- | --- |
| `keypath` | `string` | 必須 |
| `params` | `object` | 補間する値 |
| `plural` | `number \| string` | `tc(keypath, count)` をレンダリングします |
| `number` | `number \| string` | `tn(number)` を `{number}` として渡します |
| `date` | `Date \| string \| number` | `td(date)` を `{date}` として渡します |
| `relativeDate` | `Date \| string \| number` | `tdr(relativeDate)` を `{relativeDate}` として渡します |
| `tag` | `string` | ラッパー要素。デフォルトは `span` |
| `html` | `boolean` | 翻訳を HTML としてレンダリングします。翻訳は信頼できるものである必要があり、パラメーターはエスケープされます |
| `defaultValue` | `string` | 存在しないキーの代わりに使われ、`hideIfEmpty` が空の値を非表示にする場合はそのままレンダリングされます |
| `hideIfEmpty` | `boolean` | 空の翻訳の場合は何もレンダリングしません |
| `customPluralRule` | `PluralFunc` | この要素の複数形ルール |

適用されるフォーマット用プロパティは 1 つだけで、`number`、`date`、`relativeDate`、`plural` の順に確認されます。

#### リッチテキスト {#rich-text}

`{placeholder}` には要素を入れることができます。Vue では名前付きスロットを使い、React、Preact、Solid では `components` プロパティで、要素または要素を返す関数を名前ごとに指定します。いずれの場合も同名のパラメーターより優先され、すべての分岐で動作し、プレースホルダーの順序が入れ替わるロケールでも維持されます。

```tsx
// { "terms": "I accept the {link} of {company}" }
<I18nT keypath="terms" params={{ company: 'ACME' }} components={{ link: <a href="/terms">terms</a> }} />
```

Solid では、プレースホルダーが繰り返される場合は関数を渡してください：1 つのノードは 1 か所にしか配置できません。`children` はテキストを置き換え、関数として渡すと、Vue のデフォルトスロットと同様に `{ translation }` を受け取ります。`html` はこれらすべてを無視します。

### `<I18nLink>` {#&lt;i18nlink&gt;}

| プロパティ | 型 | 備考 |
| --- | --- | --- |
| `to` | `string \| { path }` | アダプターの `resolvePath` を通じてローカライズされます |
| `activeStyle` | スタイルオブジェクト | 現在のページで `style` の上にマージされます。React、Preact、Solid では上位のセクションにも適用されます |
| `localeRoute` | 関数 | このリンクの `resolvePath` を上書きします |

外部 URL（`https://`、`mailto:`、`tel:`）は `<a target="_blank" rel="noopener noreferrer">` としてレンダリングされます。独自に指定した `target` や `rel` が優先されます。`onClick` は常に実行されます。修飾キー付きのクリック、他のマウスボタン、または `target` がある場合はブラウザーに処理を任せます。

### `<I18nSwitcher>` {#&lt;i18nswitcher&gt;}

有効なロケール（`disabled: true` のロケールは非表示）のドロップダウンで、インラインのデフォルトスタイルが付いています。項目はリンクで、ロケールから `lang`、`hreflang`、`dir` が設定されます。デフォルトでは、項目をクリックするとロケールが設定され、ローカライズされた現在のパスでアダプターの `push` が呼び出されます。`switchLocale` プロパティでこの動作を置き換えられます。`localeRoute` があってルーターがない場合は、ブラウザーがリンクをたどります。Escape キーまたは外側のクリックで閉じます。

| プロパティ | 備考 |
| --- | --- |
| `locales`、`currentLocale`、`getLocaleName` | 提供された値を上書きします |
| `switchLocale(code)` | 組み込みの切り替え処理を置き換えます |
| `localeRoute` | `resolvePath` を置き換えます |
| `customLabels` | `{ de: 'DE' }` |
| `customWrapperStyle`、`customButtonStyle`、`customDropdownStyle`、`customItemStyle`、`customLinkStyle`、`customActiveLinkStyle`、`customDisabledLinkStyle`、`customIconStyle` | スタイルの上書き |

### `<I18nGroup>` {#&lt;i18ngroup&gt;}

プレフィックス付きの `t` を子要素に渡す `<div class="i18n-group">` です。内部の `<I18nT>` や `t()` 呼び出しにはプレフィックスを付け**ません**。プレフィックスが付くのは、渡される `t` だけです。

| プロパティ | 備考 |
| --- | --- |
| `prefix` | 必須。例：`'profile'` |
| `groupClass` | ラッパーに追加するクラス |

プレフィックス付きの `t` は、Vue ではスコープ付きスロット（`v-slot="{ t }"`）、React、Preact、Solid ではレンダープロップの子（`{({ t }) => …}`）を通じて渡されます。

## 型付きキー {#typed-keys}

`t()` は任意の文字列を受け付けます。キーの自動補完を利用するには、[型ジェネレーター](/ja/integrations/types-generator)で宣言を生成してください。キーは候補として提示されるだけで強制はされず、パラメーターは型付けされません。

## Nuxt モジュールとの比較 {#compared-with-the-nuxt-module}

パッケージには、ファイルベースのルーティング、サーバーミドルウェア、翻訳ローダーがありません：JSON をいつ読み込むか（`import`、`fetch`、またはサーバーでの `@i18n-micro/node`）と、どのルーターアダプターを使うかは自分で決めます。ロケール検出、SEO メタ、ルート生成は Nuxt の機能です。Astro には検出用の独自ミドルウェアと SEO 用の `useLocaleHead` があります。
