このページでは、nuxt-i18n-micro とその `@i18n-micro/*` パッケージをアップグレードしたときにアプリで何が変わるかを一覧にしています。依存関係を更新する前に、移行元のバージョンのセクションをお読みください。ほとんどのアプリでは、コードの変更はわずかです。

<Tip>

**`@nuxtjs/i18n` から移行しますか？** — [@nuxtjs/i18n からの移行](/ja/guide/migration)を参照してください。

</Tip>

## 3.30.3 以降：メジャーリリース {#after-3-30-3-the-major-release}

モジュールオプション、`$t`、`$localePath`、`$switchLocale` などのヘルパー、コンポーネント、コンポーザブル、ドキュメント化されたサーバーユーティリティの名前は変わりません。変わったのは動作で、その大半はバグ修正です。アダプターパッケージとルーティングパッケージには実際の API の破壊的変更があります。[フレームワークパッケージ](#framework-packages)と[その他のパッケージ](#other-packages)を参照してください。

### 最初にやること {#do-this-first}

1. **バージョンを確認します。** モジュールには Nuxt 3.18 以降と Node 20 以降が必要です。Nuxt には独自の Node の最小要件があり、Nuxt 4.5 は `^22.19.0 || ^24.11.0 || >=26.0.0` を宣言しています。Nuxt 3.18.0 自体での `nuxt generate` は素の Nuxt でも失敗します（`[unstorage] Invalid key: "/"`）。3.21.11 は動作します。`@i18n-micro/react` には React 18 以降が必要です。
2. **インストール済みのパッケージを修正します。**
   - `@i18n-micro/hmr` を削除します。翻訳の HMR はモジュールに組み込まれています。
   - テストで `@i18n-micro/test-utils` をインポートしている場合は追加します：`npm install -D @i18n-micro/test-utils`。モジュールと一緒にはインストールされなくなりました。
   - `nuxt-i18n-micro-cli` を `@i18n-micro/cli` に置き換えます。28 個のコマンドが 16 個になり、`check` がそのうち 3 つを置き換え、終了コードも変わります。[CLI ガイド](/ja/guide/cli#moving-from-nuxt-i18n-micro-cli)を参照してください。
3. 下の表の項目を**コード内で検索します**。
4. **アプリの前段にあるものを確認します。** プロキシの背後でロケールに `baseUrl` を使っている場合は、[プロキシや CDN の背後](/ja/guide/deployment#behind-a-proxy-or-cdn)を参照してください。CDN を使っている場合は、そのキャッシュキーを `Vary` ヘッダーと照らし合わせてください：[HTML のキャッシュ](/ja/guide/deployment#caching-html)を参照してください。`apiBaseClientHost` や厳格な CSP を使っている場合は、新しい `preload` リンクを許可してください：[SEO と head タグ](#seo-and-head-tags)を参照してください。
5. **スナップショットを更新します。** head のスナップショットに `preload` リンクが追加され、スイッチャーのマークアップが変わり（[`<i18n-switcher>` と `<i18n-link>`](#&lt;i18n-switcher>-and-&lt;i18n-link>)）、`$localeRoute` の出力のクエリ文字列のエンコードも変わります。
6. **各ロケールでページを開き、生のキーが表示されていないか確認します。** 前のページのファイルのキーを使っていたレイアウトでは、それらが生のまま表示されるようになります。それらのキーをルートファイルに移動してください。

<Warning>

**`@i18n-micro/path-strategy` の `switchLocaleRoute` は第 1 引数がなくなりました** — `switchLocaleRoute(fromLocale, toLocale, route, options)` は `switchLocaleRoute(toLocale, route, options)` になりました。**古い JavaScript の呼び出しは失敗せず、誤った結果を返します。** `fromLocale` がターゲットとして、`toLocale` がルートとして読まれるためです。気づけるのは TypeScript だけです。Nuxt の `$switchLocaleRoute` は影響を受けません。

</Warning>

| 検索対象 | 対応 |
| --- | --- |
| `@i18n-micro/path-strategy` の `switchLocaleRoute(` | 第 1 引数を削除します。上記を参照 |
| `dependsOn` 内の `i18n-plugin-hooks` または `i18n-plugin-define` | `i18n-plugin-loader` を使用します。古い名前はもう何も待たず、エラーも出ません |
| `router.push({ name })` 内の `localized-…` という名前 | ページ自体の名前を `$localeRoute` または `<i18n-link>` に渡します |
| `$localeRoute` や `$switchLocaleRoute` の結果の `.name` や `.params` | それらがない場合に対応します。[リンク](#links-and-route-objects)を参照 |
| ロケールに `baseUrl` がある状態での `<NuxtLink :to>` や `router.push` 内の `$localeRoute(x, 'fr')` | `$localePath` を使用します。[ロケールドメイン](#locale-domains)を参照 |
| `$getI18nConfig().globalLocaleRoutes`、またはそこからの `isSSG`、`hmr`、`hooks`、`noPrefixRedirect`、`routeLocales`、`routeDisableMeta` | ランタイム設定から削除されました。読み取っていたのはビルドだけで、オプション自体は変わりません。`ModuleOptionsExtend.isSSG` は、何も設定しない非推奨のオプショナルプロパティとして残ります |
| `useLocaleServerMiddleware`、`useTranslationServerMiddleware`、`loadTranslationsFromServer`、`detectCurrentLocale` 以外のサーバー自動インポート | 削除します。`getI18nServerConfig`、`detectRequestLocale`、`getRequestLocale`、`loadLiveDevTranslations`、`getOrCreateServerTranslationCache`、`DEFAULT_SERVER_CACHE_SIZE` とウォッチャーヘルパーは自動インポートされなくなりました |
| `nuxt-i18n-micro` からの `resolveTranslationPayloadMode`、`resolveTranslationPayloadOptions`、`resolveTranslationPayloadPublicDir`、`resolveTranslationPayloadPublicRel`、`shouldCopyTranslationPayloadsToPublic`、`shouldRegisterNitroServerAssets` | 削除します。`TranslationPayloadMode` 型は残ります |
| `params` にマークアップを含む `<i18n-t>` の `html` | マークアップを翻訳に移動します。[`<i18n-t>`](#&lt;i18n-t>) を参照 |
| `<i18n-t>` の `ref` | 関数型コンポーネントのため、`ref` ではインスタンスを取得できません |
| `useI18n().$t = stub` などの書き込み | `useI18n()` はアプリごとに 1 つのオブジェクトなので、書き込みはすべての呼び出し元に及びます。`useI18n` 自体をスタブしてください |
| `ModuleHooks` 型 | `ModuleRuntimeHooks` に名前が変わりました |
| `@i18n-micro/utils/resolve-locale` からの `resolveServerLocale`、`resolvePreferredLocale` | `url`、`query`、`state`、`cookie`、`acceptLanguage` を指定して `resolveLocale` を呼び出します |

`detectCurrentLocale` は非推奨です。引き続き動作し、サーバーの自動インポートとしても残りますが、同じルールを適用する [`useLocaleServerMiddleware(event).current`](/ja/guide/server-side-translations) を使用してください。

このドキュメントの 17 ページが移動しました。古い URL はリダイレクトされるため、それらへのリンクは引き続き機能します。

### URL とリダイレクト {#urls-and-redirects}

- **`prefix_except_default` では `/en` と `/en/...` は 404 になります**（`en` がデフォルトの場合）。ドキュメントどおりの動作です。
- **大文字小文字や綴りが異なるロケールプレフィックスは 404 になります。** `/DE/about` は以前、ドイツ語のルートをデフォルトロケールでレンダリングするか、`/en/DE/about` にリダイレクトしていました。その URL に独自のページがある場合はページのままです。キャッチオールや `[slug]` ページはこれに当たりません。`[...slug]` 下の `/DE/x` や `[slug]` と並ぶ `/DE` も 404 になるため、大文字小文字の違うロケールコードと同じ CMS スラッグはページを失います。`ssr: false` の場合は応答するサーバーがないため、`/DE/about` はドイツ語のページを表示します。
- **大文字小文字の異なるページパスは、本来の綴りにリダイレクトされます。** `/T/BASIC` は以前 200 でしたが、現在は `/t/basic` への `302` です。
- **未知の URL は 404 のままです。** `autoDetectPath: '*'` または `'no_prefix'` の場合、`/nope` が先に `/de/nope` にリダイレクトされることはなくなりました。`prefix` ではリダイレクトが残り（そこではプレフィックスなしで提供されるものがないため）、すべての戦略で `/` も同様です。
- **プレフィックスなしの他のロケールのカスタムパスは、`prefix_except_default` でページを見つけます。** `/a-propos` は以前 404 でしたが、現在はデフォルトロケールの URL（`/about`）への `302` です。`prefix` では同じリダイレクトが実在するページに到達するようになりました（`/en/about`。以前は 404 の `/en/a-propos`）。`prefix_and_default` は 404 のままです。
- **`redirects: false` の `prefix` は、プレフィックスなしの URL に 404 で応答します**（`/about` は以前 `302`）。カスタムのデフォルトパスを持つページの元の URL も含みます。`$localePath('/about')` は引き続きそのページを見つけます。
- **`prefix_except_default` では、カスタムのデフォルトパスを持つページの元の URL はそのパスにリダイレクトされます**（動的ページも含む）。`/dir/one` は以前 404 でしたが、現在は `/dir-one/one` への `302` です。
- **`autoDetectPath: '*'` は、Cookie と `Accept-Language` をプレフィックスなしのパスにも適用するようになりました**（`/about` → `/de/about`）。
- **`prefix` では、プレフィックスなしの URL は訪問者のロケールを維持します。** Cookie が `de` の場合、`/about` と素の `<NuxtLink to="/about">` は、`autoDetectPath` の設定にかかわらず、すべてのパスで `/de/about` に移動します。
- **`prefix_and_default` では、プレフィックスなしの URL はデフォルトロケールです。** `Accept-Language: de` の `/contact` は以前、ドイツ語でレンダリングした後に英語でハイドレートしていました。現在はデフォルトロケールでレンダリングし、訪問者は `/de/...` を通じてドイツ語に到達します。
- **`no_prefix` では、カスタムパスはそのロケールでレンダリングされます**（`/ueber-uns` は希望にかかわらずドイツ語）。また、限定されたページは提供するロケールのいずれかでレンダリングされます。複数のロケールが共有するパスは、希望するロケールがその中にあればそれでレンダリングされ、`baseUrl` の下ではそれぞれのドメインのページになります。それらのロケールは 1 つのレコード `localized-<page>-<first locale>` を共有します。
- **`noPrefixRedirect` は訪問者のロケールに従います。** Cookie が `de` の場合、`/about` はデフォルトロケールの `/about-us` ではなく `/ueber-uns` に移動し、ドイツ語でレンダリングされます。独自のカスタムパスを持たないロケールは `/about` に留まります。
- **ページのない `routeRules` のリダイレクトはローカライズされません。** `/de/old` は以前は空の 200 でしたが、現在は 404 です。必要であればプレフィックス付きのパスにルールを追加してください。他のロケールからそのようなルールへのリンクは、記述どおりのパスを保ち、ルールのターゲットに到達します。
- **ルートルールはカスタムパスにも適用されます。** `blog/[slug]` がそのパスを持つ場合、`/blog/**` は `/de/artikel/:slug` にも適用され、ルールは `no_prefix` でもコピーされます。`/de/artikel/news` のような静的な兄弟ルートもそのパターンに一致します。既にロケールプレフィックス付きで記述されたルールはそのままです。
- **`disabled: true` のロケールは、そのプレフィックスに即座に 404 で応答し**、そのロケールへのリンクはページに留まります。ランタイムで無効化されたロケールも同様です。以前はフォールバックロケールでレンダリングされていました。
- **モジュールの 404 は `Page Not Found` と表示されます**。無効化されたロケールのプレフィックスや、ホスト自身のプレフィックスに対してで、以前 Nuxt は `Page not found: /de/about` と表示していました。ステータスは同じです。
- **`customRegexMatcher` は、最初のセグメントがロケールに見える実在のページを 404 にしなくなりました。**
- **ローカライズされたルート名は一貫しています。** 共有ロケールレコード下の子はページの名前を維持し、`no_prefix` は `localizedRouteNamePrefix` に従い、index の子を持つ親は名前なしのままです。
- **モジュールが `name` なしで追加するページ**（`extendPages`）はローカライズされ、ロケールのバリアントと `hreflang` を含む名前が付与されます。以前はローカライズされないままでした。
- **`nuxt.config` の項目は `$defineI18nRoute` より優先されます。** キーの形式（`about/team`、`/about/team`、`about-team`）を問いません。以前はどちらが優先されるかが綴りによって変わっていました。
- **新しいビルド警告：** 自身のロケールコードで始まる `localeRoutes` の値（`fr: '/fr/article'`）、および親の外にある子のカスタムパス。
- **ハッシュモードは `prefix` で動作します。** ドキュメントは `/` で、`/en` や `/about` はハッシュ内にリダイレクトされます。
- **`prefix_except_default` と `prefix_and_default` では、`/#/de/x` はドイツ語でレンダリングされます。** 以前はハイドレーションの不一致を伴って英語でレンダリングされていました。

### リンクとルートオブジェクト {#links-and-route-objects}

- **ページを提供しないロケールは、そのホームにリンクします。** `$localeRoute`、`$switchLocalePath`、スイッチャーは、他のロケールのページを返さなくなりました。
- **未知のロケールコードはデフォルトロケールになります。** `$localePath(path, 'xx')` と `$localeRoute` は以前 `/xx` を返していました。
- **`$localePath` は `http(s):`、`mailto:`、`tel:` スキームを持つ文字列をそのまま返し、`$localeRoute` の `path` と `fullPath` もそれを変更せずに保持します**。そのため、検証していない値（`?next=` パラメーター）をリンク先として渡さないでください。`//host` や `x.com` のような裸の名前はパスのままで、すべてのロケールでこのオリジン上にあり、それらから作られるリンクがオリジンを離れることはありません：デフォルトロケールへの `/de//x.com` は `/x.com` です。バックスラッシュはスラッシュとして扱われます。
- **`$localePath` はパスをエンコードします：** `/a b` は `/a%20b` になります。
- **`$localeRoute` と `$switchLocaleRoute` はプレーンなオブジェクトを返します。** `ref`、`reactive`、`useState`、JSON、スプレッドで安全に扱えます。パラメーターにエスケープが必要な場合、オブジェクトは `name` や `params` のない `{ path, fullPath, query, hash }`（`$localeRoute` は `href` を追加）になり、URL はリロードの前後で同じです。プレーンな URL は両方を持ちます。`name` は新しく、古いオブジェクトには一度もありませんでした。`.name` や `.params` を読むコードはそれらがない場合に対応する必要があり、どちらの形式になるかは値によって決まります。
- **`trailingSlash` では、`$switchLocaleRoute` は常にそのパス形式を返し**（プレーンなスラッグも含む）、サーバーリダイレクトも `trailingSlash` に従います。このオプションでは結果と `Location` ヘッダーが変わることがあります。
- **`$localeRoute` の出力のクエリ値は vue-router のエンコードを使います：** `/` はそのままで、スペースは `+` になります（`?redirect=/v2`。以前は `%2Fv2`）。デコードされた値は同じですが、そのような `href` のスナップショットは変わります。
- **パスのないリンクは現在のページに留まります。** `$localePath('#top')`、`'?p=2'`、`''`、`{ query }` は現在のページを維持します。`'#top'` は以前サイトのルートから読まれていました。裸の `'about'` は引き続き `/about` を意味します。
- **スプレッド。** `{ ...route, query }` と `{ ...route, hash }` は、`$switchRoute` を通しても変更を維持します。新しい `path` は `$localeRoute`、`$localePath`、`$switchRoute` で優先されます。`{ ...route, params }` は名前付きルートで機能しますが、パス形式のルートではパスが優先されてパラメーターは無視され、vue-router の開発時警告が出ます。`$localeRoute({ name, params })` を使用してください。
- **`$switchRoute` はアプリ内に留まります。** ロケール自身の `baseUrl`、`mailto:`、`tel:` はアプリを離れ、それ以外の文字列はパスです。
- **`excludePatterns`** はセグメント全体に一致し（`'/admin'` は `/administrator` に一致しなくなりました）、グロブはアンカーされます（`/docs/*` は `/en/docs/x` に一致しなくなりました）。`RegExp` パターンがランタイムに届くようになりました。以前はそこで失われていました。一致したページはローカライズされず、`hreflang` もなく、`prefix_except_default` ではデフォルトロケールになります。パターンを[パスの除外](/ja/guide/excluding-static-files)と照らし合わせて確認してください。

パラメーター内の `%` や `?` は、Nuxt 4.5.2 ではどのアプリでもサーバーレンダリングでのリロード後に保持されません。これはモジュールではなくアップストリームの問題です。

### ロケールドメイン {#locale-domains}

- **`locales[].baseUrl` がリクエストをルーティングするようになりました。** 1 つのビルドですべてのドメインを提供します：[レイヤーとドメイン](/ja/guide/layers#multiple-domains)を参照してください。`baseUrl` が設定されている場合、別ドメインのロケールはこのホストでは 404 になり（`example.de` 上の `/en/about`）、同じホスト上のロケールへのリンクは相対リンクになります。それ以外のホスト（`localhost` を含む）へのリクエストは以前と同様に動作しますが、canonical と `hreflang` は、リクエストのオリジンではなく、設定されていれば `metaBaseUrl`、なければデフォルトロケールの `baseUrl` を使用します。
- **`Host` を書き換えるプロキシの背後では、**[`trustForwardedHost`](/ja/api/module-options#trustforwardedhost) を設定するまで、すべてのリクエストがビルド設定にフォールバックします。`metaTrustForwardedHost` と異なり、デフォルトは `false` です。[プロキシや CDN の背後](/ja/guide/deployment#behind-a-proxy-or-cdn)を参照してください。
- **`baseUrl` を使った `nuxi generate` には、ドメインごとに 1 回ずつ `NUXT_I18N_DOMAIN` が必要です。** これがないとビルドは警告を出し、それらのロケールはページのないリンクになります。[静的サイト](/ja/guide/deployment#static-site-(nuxi-generate))を参照してください。
- **`baseUrl` を持つロケールへのリンクは、`$localePath` または `<i18n-link>` を通します。** `<NuxtLink :to="$localePath(x, 'fr')">` と `<i18n-link :to="$localeRoute(x, 'fr')">` はその絶対 URL になり、クリックするとそこに移動します。ルーターは絶対オブジェクトを受け付けません：`<NuxtLink :to="$localeRoute(x, 'fr')">` と `router.push($localeRoute(x, 'fr'))` は `/https://fr.example.com/...` というこのアプリのパスのままです。`localhost` やプレビューホストでは、`baseUrl` を持つすべてのロケールがそのようなリンクになり、現在のロケールも同様です。コード内では `navigateTo($localePath(x, 'fr'), { external: true })` を使用してください。
- **ドメインのホームは、リンク、canonical、`hreflang` のすべてで末尾のスラッシュなしで記述されます**（`https://example.de`）。
- **`prefix` では、別ドメインへのリンクは `baseDefault` の有無にかかわらずロケールプレフィックスを保持します。** リダイレクトするだけの `https://example.de/about` ではなく、`https://example.de/de/about` です。
- **`prefix_except_default` で、ビルドのデフォルト以外のロケールに `baseDefault` がある場合、他のドメインからリンクできるようにルートはすべてのプレフィックスを保持します。** `/en` は引き続き 404 です。違いが見えるのは `router.getRoutes()` を読むコードだけです。
- **`prefix_except_default` では、ホスト自身のプレフィックスは、その `baseDefault` ホストで 404 になります。** `de` ホスト上の `/de/x` は以前 200 でした。
- **`$getI18nConfig().locales` はホストが提供するものだけを保持します。** `linkLocales` はすべてを保持し、`$getLocales()` は完全なままです。

### ナビゲーションと `$switchLocale` {#navigation-and-$switchlocale}

- **ナビゲーションはコミット時に適用されます。** 辞書、ロケール、パラメーター、head は `router.afterEach` で変わるため、キャンセルまたはブロックされたナビゲーションは何も変更せず、次のチャンクの読み込み中も古いページのリンクは有効なままです。`beforeResolve`、`beforeRouteEnter`、または後続のグローバルガードは、古い辞書とロケールを参照するようになりました。ルートミドルウェアは影響を受けません。
- **チャンクの読み込みに失敗しても現在の辞書は保持されます。** ルートファイルでの 5xx、ネットワークエラー、不正なボディは、以前は生のキーを表示していました。現在は新しいページが古い文字列でレンダリングされ、次のナビゲーションで再試行されます。404、またはファイルの代わりに静的ホストの SPA シェルが返された場合は、次のリロードまでルートの辞書になります。
- **`$switchLocale` は `true` または `false` で解決されます**（以前は何も返しませんでした）。ロケールの辞書が適用されなかった場合は `false` です。型は `Promise<boolean>` で、`$switchRoute` は `Promise<void>` です。
- **`$switchLocale` は明示的な選択です。** 到着時にロケールを保存し、404 でも保存します。ナビゲーションがブロック、キャンセル、または例外を投げた場合、保存済みの設定と状態は元のままで、例外は再スローされます。別のホストへの移動では先に保存されます。`no_prefix` とハッシュモードでは、ナビゲーションの結果にかかわらず切り替えは維持されます。すべてのロケールで 1 つの URL を持つページ（`excludePatterns`）では選択は取り消されず、次のページの URL が決定します：`prefix_except_default` では、プレフィックスなしのリンクはデフォルトロケールに戻ります。
- **`no_prefix` では、2 つのページがカスタムパスを共有していても `$switchLocale` はそのページを維持します**（エスケープされたパラメーターでも同様）。そのような URL のリロードや、エスケープされたパラメーターを持つ `$localeRoute` は、最初のレコードに到達します。
- **クライアントリダイレクトは、そのナビゲーションのモードを維持します。** `prefix` での素の `<NuxtLink to="/about">` は、現在の履歴エントリを上書きする代わりに履歴エントリを追加します。`router.replace` は引き続き置き換えます。
- **サーバーからの `$setI18nRouteParams` と `useI18nHead` はハイドレーション後も保持されます。** `/news/2` に着地した後、スイッチャーは `/de/news/2` ではなく翻訳されたスラッグ（`/de/news/2-zwei`）にリンクします。ページが SSR 中にパラメーターを設定していれば、サーバーの HTML でも、スイッチャーがどこにあっても同様です。別のパスへのナビゲーションがコミットされると破棄されます（`/news/1` から `/news/4` も含む）。新しいページで再度設定してください。
- **setup 内で読み取った `$setI18nRouteParams` はそのページに紐づきます。** 既に離れたページからの遅れた呼び出しは何もしません。`useNuxtApp().$setI18nRouteParams` はアクセサーになり、2 回読み取ると 2 つの関数が返ります。セッターはありません：テストスタブで行うような `useI18n().$setI18nRouteParams = fn` は strict モードで例外を投げるため、`useI18n` 自体をスタブしてください。レイアウトや `app.vue` では、離れるものがないためプレーンな関数です。
- **パラメーターを持つページでは、サーバーはレンダリング終了時に `<i18n-switcher>` のリンクを書き換えます**。レイアウト内のスイッチャーはページの非同期 setup より前にレンダリングされるためです。手書きの `$switchLocalePath` リンクは書き換えられません：[カスタムロケールルート](/ja/guide/custom-locale-routes)を参照してください。Nuxt の SSR ストリーミングでは、最初の HTML は URL のパラメーターを保持します。
- **サーバーコンポーネントの `locale` という名前の prop は、そのレンダリングロケールを設定します**。そのため `<Greeting :locale="$getLocale()" />` は URL と切り替えに従います。その中の `$getLocale()`、`$localePath`、`$getLocaleName` も prop に従います。[サーバーサイド翻訳](/ja/guide/server-side-translations)を参照してください。prop がない場合は、引き続き Cookie またはデフォルトを使用します。
- **`keepalive` ページは、戻ったときにパラメーターと head を取り戻します。**
- **`prefix_except_default` で `false` に設定されたネストされたページには、ロケールの URL がありません。** `globalLocaleRoutes: { 'parent-kid': false }` の場合の `/de/parent/kid` は以前提供されていましたが、現在は 404 です。ページは `/parent/kid` に留まります。

### ロケール検出と Cookie {#locale-detection-and-the-cookie}

どこでも 1 つの優先順位を使います。[ロケール検出](/ja/guide/locale-detection)で説明しています。

- **`?locale=` がページで評価されるのは `no_prefix` のみです。** プレフィックス戦略では URL が決定し、`/about?locale=de` が `lang="en"` のままドイツ語でレンダリングされることはなくなりました。`?locale=de&locale=fr` は最初の値を読みます。以前は `"de,fr"` でした。
- **`Accept-Language` は `q` 値に従います**（`fr;q=0.1, de;q=0.9` → `de`。`q=0` は言語を除外）。地域ロケールの照合は `locales` の順序に依存しなくなり、中国語の文字体系をまたぐこともありません。
- **ページへのクライアントナビゲーションは、そのロケールを Cookie に保存します。デフォルトロケールのプレフィックスなしページでも同様です。** `localeCookie` が設定されている場合、`/about` へのリンクをクリックした訪問者は `user-locale=en` を持つようになり、後でブラウザの言語を変えても `/` がリダイレクトされなくなります。その URL の初回読み込みでは何も保存されません。`no_prefix` とハッシュモードでは、ナビゲーションは変更があった場合のみ保存します。
- **404 は Cookie を書き込みません：** どのモードでも、レスポンスでも、そこへの素のクライアントナビゲーションでも書き込みません。`no_prefix` では、プレフィックス付きに見える URL も書き込みません。
- **`no_prefix` で明示的な `localeCookie: null` が尊重されるようになりました。** 以前は `user-locale` になっていました。`nuxt.config` の `i18n` ブロックで設定してください：`modules: [[name, opts]]` やレイヤー内の `null` は引き続き失われます。
- **ハッシュモードは `hash-locale` Cookie のみを読みます。** 単独の `user-locale=de` は評価されなくなりました。
- **不正なロケール Cookie は無視され、そのまま残ります。** 以前はすべての SSR ページが 500 で失敗していました。リクエストのたびに削除されることもなくなり、これによりプレフィックス付きページがロケールを保存できなかった問題も解消されました。
- **URL のロケールが最優先です。** `/en/...` でのプラグインの `setLocale('de')` が `de` の辞書を読み込むことはなくなり、状態内の未知のコードは無視されます。
- **サーバー API ヘルパー**（`useLocaleServerMiddleware`、`useTranslationServerMiddleware`）はすべてのルートで 1 つの順序を使います：`?locale` → `[locale]` パラメーターまたはプレフィックス → Cookie → ヘッダー → デフォルト。`localeCookie: null` と `autoDetectLanguage: false` を尊重するようになり、ロケールごとに辞書をキャッシュします。
- **ランタイムオーバーライドがルーティングに反映されます。** `NUXT_I18N_DEFAULT_LOCALE` とランタイムの `disabledLocales` が生成される戦略を変更するようになり（無効化されたロケールはルーティングされなくなります）、ランタイムの `disabledLocales` はビルドのものに追加されます。`prefix_except_default` と `prefix_and_default` では、そのロケールのプレフィックスなしルートがビルド時に生成されるため、ランタイムの `defaultLocale` は警告とともに無視されます。ランタイムの `fallbackLocale` は有効なロケールである必要があります。そうでない場合は警告とともに破棄され、ビルドの値が有効であればそれが適用されます。[ランタイムオーバーライド](/ja/guide/runtime-overrides)を参照してください。

### SEO と head タグ {#seo-and-head-tags}

- **`dir="auto"` はデフォルトではなくなりました。** `dir` のないロケールには以前 `dir="auto"` が付与されていましたが、これは大きなページの解析を遅くします。現在は既知の RTL 言語に `dir="rtl"` が付与され、それ以外のロケールには属性が付きません。これは Nuxt、`@i18n-micro/vue`、`astro`、`vitepress` に適用されます。古い出力を維持するためにロケールに `dir: 'auto'` を設定すると、20,000 要素で約 1 秒の解析コストがかかります：[テキストの方向](/ja/guide/seo#text-direction)を参照してください。
- **すべての SSR ページに新しいタグが追加されます：** `<link rel="preload" as="fetch" crossorigin="anonymous" href="/_locales/...">`。404 ページも含みます。`apiBaseClientHost` を使う場合、`href` はそのホスト上になり、CORS が必要です。厳格な CSP ではこれを許可する必要があります。
- **`hreflang` はページを提供するロケールのみを列挙します**。`x-default` はデフォルトロケールがページを提供する場合にのみ出力されます。
- **ローカライズされていないページには `hreflang` も `og:locale:alternate` もありません。**
- **オリジンがリクエストから取得される場合、canonical と `hreflang` は `app.baseURL` を含みます。** `metaBaseUrl` と `site.url` は記述どおりのままです。
- **404 ページは URL のロケールで `<html lang dir>` を持ちます**。canonical、`hreflang`、`og:url`、`og:locale`、代替リンクはありません。モジュール自体が一致したレコード（`/en/...`）で 404 を返す場合も同様です。`useI18nHead` の `replace` で渡したタグは残るため、エラーページではスキップしてください。
- **canonical、`og:url`、`hreflang` はホワイトリストに登録されたクエリを保持します**（`/about?page=2`）。サーバーでも同様で、以前は SSR 中に破棄されていました。デフォルトでは `page`、`sort`、`filter`、`search`、`q`、`query`、`tag` がホワイトリストに登録されています。[`canonicalQueryWhitelist`](/ja/api/module-options#canonicalquerywhitelist) を参照してください。
- **解析できない `X-Forwarded-Host` は無視されます。** 以前はすべてのページが 500 になっていました。使用可能なホストがなく、`metaBaseUrl` も `site.url` もない場合、そのレスポンスの canonical と `hreflang` の URL は相対 URL になります。解析できない `Host` は、素の Nuxt アプリと同様に 500 のままです。
- **`disableMeta` が機能するようになりました。** `$defineI18nRoute` でも `routeDisableMeta` でも、`nuxt.config` で設定した場合も同様です：ページには `hreflang`、canonical、`og:locale` がありません。`lang` と `dir` は残ります。
- `useLocaleHead()` は `useHead(() => build())` 用のゲッターである `build()` も返します。
- `metaBaseUrl` のない素のビルドでは、これらのタグのホストは以前と同様に `X-Forwarded-Host` によって決まります。オリジンに直接アクセスできる場合は `metaBaseUrl` を固定してください：[プロキシや CDN の背後](/ja/guide/deployment#behind-a-proxy-or-cdn)を参照してください。

### 翻訳 {#translations}

- **マージはすべての階層でディープに行われます。** ルート、ページ、フォールバックのファイルは 2 階層のマージを使っていたため、フォールバックやルートの `a.b.c` はソースモードと開発時に失われていました。現在はすべてのモードで同じ辞書になります。
- **フォールバックチェーンは、すべてのモードで最後までたどられます**（`fr` → `de` → `en`）。
- **マージはファイルの種類ではなくロケールに従います。** アクティブなロケールのルートファイルが、フォールバックロケールのページファイルより優先されるようになりました。[フォールバックロケール](/ja/guide/translations#fallback-locales)を参照してください。
- **同じ `code` については、プロジェクトの `locales` 項目がレイヤーのものより優先されます**。レイヤーは不足分を埋めるだけです。
- **独自の `pages/<name>/` フォルダーを持たないページは、ルートの辞書を読みます**（子ページも含む）。以前は `{}` を受け取り、生のキーを表示していました。出力にはそのようなページごとのファイルと、ロケールごとの `__root/<locale>/data.json` が追加されます：`/_locales/<any name>/en/data.json` はルートのキーを含む 200 になります（以前は `{}`）。これは監視、静的ホストの許可リスト、ツリーを読み取るツールに影響します。
- **`disablePageLocales: true` はルートファイルのみを読みます。** `pages/index` はマージされなくなりました。
- **離れるページのキーは、その要素がドキュメントから離れると解決されなくなります。** レイアウトが前のページのファイルにしかないキーを使っていた場合は、それらをルートファイルに移動してください。親のキーは、その子が表示されている間（`index` の子を持つ親も含む）、次のナビゲーションまで残ります。同じ親の 2 つの子の間では、親自身のキーには子の辞書またはルートの辞書が必要です。
- **`$clearCache()` は現在のページの辞書を再読み込みし**、新しい辞書が届くまで古い辞書を画面に表示し続けます。再読み込みに失敗した場合は古い辞書が保持され、クリア前にリクエストしたレスポンスは破棄され、離れる遷移中のページは翻訳されたままです。
- **`$has(key, route)` はルートに従います。**
- **まだ訪問していないページへの `$loadPageTranslations` が、そのファイルの読み込みを止めることはなくなりました。** ファイルは初回訪問時に読み込まれ、あなたのキーはその上に残ります。以前はリロードするまでページに生のキーが表示されていました。
- **翻訳の HMR は、ページをリロードせずにその場で編集を適用します**。削除されたキーは消え、ルートの編集はすべてのページに反映されます。
- **壊れたロケールファイルは、すべてのモードでパス付きの警告を 1 回出します。** 以前は開発時は例外を投げ、premerged では黙ってスキップしていたため、開発時に強く失敗することに依存していたアプリではそれが見られなくなります。

### 複数形と書式 {#plurals-and-formatting}

- 負の数、小数、非常に大きなカウントを渡した `$tc` は、実際のカウントで最後の形式を使います。`{ count: null }` は例外を投げなくなりました。存在しない複数形キーは missing ハンドラーに届きます。
- `$tdr` は実際の未来の日付（`in 3 days`、または `numeric: 'auto'` で `tomorrow`）を返し、無効な入力には `Invalid Date` を返します。過去 1 秒未満は `0 seconds ago` です。
- **`$tn`、`$td`、`$tdr` は複数形と同様に `iso` に従います**：`{ code: 'en', iso: 'en-GB' }` は日付を `31/10/2026` と書式化するようになりました。ロケールコード内の `_` は `-` として読まれるため、`en_US` は例外を投げなくなり、`Intl` が知らないコードはマシンのロケールに従う代わりに `en` として書式化されます。名前付きフォーマットは引き続き `code` で検索されます。
- `{param}` プレースホルダーは、渡したパラメーターのみを読みます（`{constructor}` は記述どおりのままです）。
- `{placeholder}` の名前には波括弧とスペース以外の任意の文字を使えます：`{firstName}`、`{first-name}`、`{user.name}` は `params` から読まれます。該当するパラメーターがない場合は、以前と同様に記述どおりのままです。
- `defaultValue` は `$t` と `$tc` で補間されます：`$t('missing', { n: 1 }, 'Got {n}')` は `Got 1` を返します（以前は `Got {n}`）。文字列でないデフォルトはそのまま返されます。
- 空の翻訳に対する `$tc` は、`$t` と同様に `''` を返します。以前はデフォルト値またはキーを返していました。
- **複数形テンプレートの意味は、1 つの例外を除いて変わりません。** 表にすべての形を示します。`Intl.PluralRules` のカテゴリを使うには、新しい [`=0 ` マーカー](/ja/api/methods#$tc)で明示してください：`=0 no apples | one apple | {count} apples`。

  | 形 | 例（`uk`） | 以前 | 現在 |
  | --- | --- | --- | --- |
  | 整数カテゴリが 1 つまたは 2 つのロケール（`en`、`de`、`fr`、`es`、`ja`...）での任意のテンプレート | `none \| one \| {count} many` | インデックス順 | **変更なし** |
  | カテゴリごとに 1 つの形式 | `one \| few \| many` | インデックス順：21 → `many` | **変更なし**。21 → `one` にするにはマーカーを追加 |
  | 最初にゼロ形式、3 つの形式 | `none \| one \| many` | インデックス順 | **変更なし** |
  | その他のプレースホルダー | `no items \| {n} item \| {n} items` | インデックス順 | **変更なし** |
  | すべての形式に `{count}` | `{count} many \| {count} one \| {count} few` | インデックス順 | **変更なし** |
  | 下記より形式が少ないまたは多い | `a \| b`, `none \| one \| two \| {count} many` | インデックス順 | **変更なし** |
  | `lv`、`prg`、`blo`、`cv`、`ksh`、`lag` の場合 | `none \| one \| {count} many` | インデックス順 | **変更なし** |
  | `=0 ` でマーク | `=0 none \| one \| many` | マーカーがテキストとして表示されていた | ゼロ形式、続いてカテゴリ |
  | **プレースホルダーのないゼロ形式に続き、カテゴリごとに 1 つの形式があり、複数のカウントが共有する各形式に `{count}` がある** | `none \| {count} one \| {count} few \| {count} many` | インデックス順：3 → `3 many`、21 → `21 many` | **カテゴリ順**：3 → `3 few`、21 → `21 one`。0、1、2 および `many` に留まるすべてのカウントは同じ結果 |

  最後の形には 3 つ以上のカテゴリが必要です（`ru`、`uk`、`pl`、`cs`、`sk`、`hr`、`sr`、`lt`、`ro`、`sl`、`he`、`ar`、`cy`...）。`ar` では `one` と `two` は単一のカウントなので、これら 2 つの形式に数値は不要です。
- **`Intl` が知らないロケールコードはインデックスのルールになります**（マーカーのカテゴリの有無にかかわらず）：`ua` はマシンのロケールに従わなくなりました。`iso` を設定してください：`{ code: 'ua', iso: 'uk-UA' }` は、モジュールでも `@i18n-micro/vue` でもウクライナ語として複数形を処理します。
- **カスタムの `plural` ルールのシグネチャは変わらず**、引き続きロケールコードを受け取ります。生の値を読むため、マークされたテンプレートは `=0 ` が付いたまま届き、カウントは `Number` として受け取ります：以前 `1` を受け取っていた場所で `1.5` を受け取ります。`null` を返すと、マーカーに従う組み込みルールにフォールバックします。
- **`timeZone` オプション。** 設定すると（`Europe/Berlin`）、サーバーとすべてのブラウザで同じカレンダー日付をレンダリングします。時計に依存する `relativeDate` には効果がありません。

### `<i18n-t>` {#&lt;i18n-t>}

このセクションでは、モジュールの `<i18n-t>` と `@i18n-micro/vue` の `I18nT` を扱います。その他のフレームワークについては[フレームワークパッケージ](#framework-packages)を参照してください。

- **`html` はどの場合でも `params` をエスケープし、すべてのスロットを無視します。** 信頼されるマークアップは翻訳だけです。意図的にマークアップを含めていたパラメーターはテキストとして表示されるようになります：マークアップを翻訳に入れてデータをパラメーターとして渡すか、`html` なしでスロットを使用してください。
- **スロットは `plural`、`number`、`date`、`relativeDate` で機能し**、これらの場合も `default` スロットは `{ translation }` を受け取ります。最初のものだけでなく、すべての `{name}` が埋められます。
- **スロットは同じ名前のパラメーターより優先されます。** プレースホルダーのように見えるパラメーターの値はテキストのままです。`customPluralRule` やカスタムの `plural` では、ルールが完成した文字列を返すため、そこで補間されたパラメーターがプレースホルダーとみなされることがあります。
- **`plural`、`number`、`date`、`relativeDate` では、`null` は未設定を意味します。** `:plural="null"` は以前レンダリングを失敗させ、`:date="null"` は 1970 年をレンダリングしていました。
- `plural` は `$tc` と同様に `Number` でカウントします：`1.5` は `1.5` のままで最後の形式を使います（以前は `1` に切り捨て）。`"2 items"` は `NaN` です（以前は `2`）。`""` は `0` です。`customPluralRule` も `1.5` を受け取ります。それ以外の契約は変わりません：引数は同じで、その返り値はそのまま使われ、`null` は空をレンダリングします。
- `hideIfEmpty` は `plural`、`number`、`date`、`relativeDate` に適用されます。非表示の値は空のテキストノードではなくコメントをレンダリングするため、`''` を読んでいたテストは `<!---->` を見ることになります。
- **`html` での存在しないキーはテキストです。** 信頼されるのは翻訳だけで、キーはリクエストから来る可能性があるため、キーはエスケープされます。`defaultValue` はあなたのものなので、マークアップのままです。
- `plural` では、`$tc` と同様に、見つからない場合は `defaultValue` またはキーがそのまま全体として使われます：`a | b` は分割されなくなりました。
- `defaultValue` は、キー自体ではなく、すべての分岐で存在しないキーの代わりになり、`customPluralRule` は見つからない場合にそのゲッターを通じてそれを受け取ります。以前は `hideIfEmpty` の後でしか効果がありませんでした。
- `number`、`date`、`relativeDate` を持つ `<i18n-t>` は `params` を保持し、それらはマージされます。
- `date` と `relativeDate` の出力には `data-allow-mismatch="text"` が付きます：サーバーとブラウザで時計やタイムゾーンが異なっても、ハイドレーション時に警告が出なくなります。名前付きスロットの隣では、Vue は要素の単一テキストでしか属性をチェックしないため、スロットの周囲のテキストは独自の `<span>` に入ります。
- `.innerHTML` と `textContent` 属性は、`innerHTML` と同様に破棄されます。
- `<i18n-t>` と `<i18n-group>` は、`$t` と同様に、ルートのチャンクではなくアクティブな辞書を読みます。破棄されたチャンク（`cacheMaxSize`）で生のキーが表示されることはなくなりました。離れる遷移中のページは、そこで `$t` が読むものを読むようになりました：新しいページの辞書を読み、見つからなければ自身の辞書にフォールバックします。そのため、両方のページが定義するキーは新しいテキストを表示し、ロケール切り替え後は、アンマウントされるまで自身のキーが生のまま表示されます。

### `<i18n-switcher>` と `<i18n-link>` {#&lt;i18n-switcher>-and-&lt;i18n-link>}

- **スイッチャーのリンクのクリックは 1 回のナビゲーションです。** `NuxtLink` とクリックハンドラーではなく、`$switchLocale` を呼び出す素の `<a>` なので、`router-link-active` クラスはなくなりました。`href` は引き続き `app.baseURL` を含み、現在のロケールのリンクは引き続き `aria-current="page"` を持ちます。Ctrl/Cmd クリックは新しいタブを開き、このタブには影響しません。リンクはクエリとハッシュを保持します。
- ボタンは `type="button"` なので、囲んでいるフォームを送信しなくなり、`aria-expanded` を持ちます。`aria-haspopup` は、モジュール、`@i18n-micro/vue`、`@i18n-micro/astro` で削除されました：メニューであることを示していましたが、一覧はリンクです。Escape と外側のクリックでドロップダウンが閉じます。2 つのスイッチャーが同時に開いたままになることはなくなりました。
- ラッパーとドロップダウンには `i18n-switcher-wrapper` と `i18n-switcher-dropdown` クラスが付きます。ボタンには `language-switcher` に加えて `i18n-switcher-button` が付き、ラベルは `<span>` に入ります。デフォルトのスタイルは論理 CSS プロパティ（`inset-inline-start`、`margin-inline-start`）を使い、キャレットは `▾` です。ドロップダウンは `z-index: 1000`（以前は 10）、`min-width: 150px`、`box-shadow` を持ち、ラッパーは `vertical-align: middle` を持ちます。各リンクは `lang` を持ち、ロケールが設定していれば `dir` も持ちます。
- `<i18n-link>`：`https://`、`mailto:`、`tel:` は大文字小文字を問わず一致します（`HTTPS://x.com`、`Mailto:`）。裸の `report.pdf` や `index.html` は `https://report.pdf` ではなくルートです。`example.com` と `example.com:8080` は外部のままです。TLD でもあるファイル拡張子（`example.md`、`x.zip`）はファイルとして扱われるため、`https://` を記述してください。`activeStyle` は末尾のスラッシュ、クエリ、ハッシュを無視します。型が `CSSProperties` になったため、一部の型付きの値は変更が必要な場合があります。

### フック、プラグイン、型 {#hooks-plugins-and-types}

- **`i18n:register` は起動時に `app:created` で実行されます。** プラグインの間ではなく、すべてのプラグインの後です。`order` が 1 より大きい、または `enforce: 'post'` のプラグインも起動時にサブスクライバーが呼び出されるようになりましたが、自身の `setup` 内で登録されたキーを読むことはできなくなりました。ナビゲーションでは、このフックは他のプラグインの `router.beforeEach` ガードより前に実行されるようになりました。
- **`i18n:register` は、埋めるページのロケールを受け取ります。** `hashMode` では、ロケールを変更するナビゲーションが以前は古いロケールを渡し、キーが誤ったチャンクに入っていました。
- **`i18n:register` はランタイムフックです：** プラグイン内で `@ts-expect-error` なしに `nuxtApp.hook('i18n:register', …)` で登録してください。[フック](/ja/api/events)を参照してください。
- **`hooks: false` と `define: false`** は引き続きそれぞれの部分をオフにします。
- **`plugin: false` でも `$defineI18nRoute` は呼び出し可能なままで**、ランタイムでは何もしません。以前はページをクラッシュさせていました。
- `hooks` オプションのドキュメントから `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch` が削除されました。これらは一度も発行されていませんでした。
- ページ内の `const { $defineI18nRoute } = useNuxtApp()` は、変数を使う設定でも機能するようになりました。
- `useI18n()` にキーが追加されました：`clearCache`、`pluralFunc`、`pluralLocale`。`clearCache` は型にも含まれます。
- `$getRouteName(route)` は与えられたルートについて答えます。以前は空文字列を返していました。
- `useI18nLocale()` から `getLocaleWithServerFallback(serverLocale)` が削除されました：`getPreferredLocale() ?? serverLocale ?? null` と記述してください。
- **開発時、サーバー上の `$getI18nConfig()` は読み取り専用です。** そこでの書き込みは例外を投げます。本番環境では、書き込みはすべてのリクエストに及んでしまいます。

### サーバー、ビルド、デプロイ {#server-build-and-deployment}

- **ページのペイロードファイルは、ロケールのルートとの差分だけを保持します。** クライアントはルートを一度だけ読み込み、各ページをその上にマージするため、ディスクと Edge のバンドルが小さくなり、2 ページ目のコストは 1 ページ目のごく一部になります。`premerged` は `__root/<locale>/data.json` を書き出すようになり、`/_locales/<page>/<locale>/data.json` は差分だけを保持します：これらのファイルを直接読むものは、2 つをマージする必要があります。完全な辞書も引き続き有効なファイルなので、それを提供するホストや `source` モードは引き続き機能します。
- **辞書ファイルはバージョンごとにキャッシュされます。** 現在の `?v=` を持つ URL は Node サーバー上で 1 年間固定され、それ以外の URL は再検証され、ホストの静的コピーは `max-age=60` で応答します：[キャッシュヘッダー](/ja/guide/deployment#cache-headers-and-datebuild)を参照してください。`httpCacheControl: false` は `max-age=0` を維持します。再ビルドせずに変更した翻訳は、`v` が変わったときにのみブラウザに届きます：`NUXT_I18N_DATE_BUILD` を設定してください。
- **辞書は `app.cdnURL` に従います。** ブラウザは公開ペイロードファイルを、以前の `app.baseURL` ではなく `<cdnURL>/_locales/...` から取得します：CDN は `_locales/` を保持し、サイトのオリジンを許可（CORS）する必要があります。[App baseURL とペイロードホスト](/ja/guide/deployment#app-baseurl-and-payload-hosts)を参照してください。
- **SSR は HTTP 経由で `/_locales` をリクエストしなくなりました。** そのため、そのルート上のサーバーミドルウェアやログは、レンダリングの読み取りを見なくなります。外部の `apiBaseServerHost` は引き続き HTTP 経由です。
- **失敗した読み取りは保持されなくなり、404 も同様です。** ホストからの 404 は、そのようなファイルがないことを意味します：レンダリングはブラウザと同様にルートの辞書を表示し、何も保持されず、ファイルが現れた時点で読み込まれます。その他の失敗、JSON オブジェクトでない 200、読み取れないまたは破損したローカルファイルはキャッシュに入らず、次のリクエストで再度読み取られます：ページのレンダリングは警告をログに出力し、生のキーを表示し、`no-store` と `Retry-After` 付きの `503` で応答します。そのためルートルールや CDN は何も保持せず、ブラウザはハイドレーション時に引き続き辞書を読みます。`/_locales/...` は `no-store` 付きの `503` で応答し、`useTranslationServerMiddleware` はキーまたはデフォルトを返す `t` を提供します。障害中はすべてのリクエストがホストに到達し、60 秒間レスポンスヘッダーを送らないホストは読み取りに失敗します。大きなファイルの遅いダウンロードには制限がありません。[辞書を読み取れない場合](/ja/guide/deployment#when-a-dictionary-cannot-be-read)を参照してください。`/_locales` もその 404 をそのまま返すようになりました（以前は `200 {}` で応答）。
- **辞書を読み込めないプリレンダリングは失敗し**、ホストにページのファイルもルートファイルもない場合も同様です。ルートは 500 になり、警告がロケールとページを示し、ファイルは書き出されません。Nuxt のデフォルトの `failOnError` ではビルドは 1 で終了します。独自のファイルを持たずルートファイルがあるページは、ルートでプリレンダリングされます。
- **ビルド時に設定されたホストが SSR に応答します。** デフォルトの公開コピーの場合も、内部パス上のエラーページでも同様です。以前は公開ファイルが応答していました。ランタイムの `NUXT_I18N_APP_BASE_SERVER_HOST` が `/_locales` とサーバーローダーに届くようになり、レンダリングはそのローダーを通じてどちらのホストも読みます。
- **カスタムの `nitro.output.publicDir`、および `public/` がサーバーの隣にないその他のレイアウトでは、ペイロードが埋め込まれます。**
- **`nuxi build --preset <static preset>` は `nuxi generate` と同様にプリレンダリングする**ため、より多くのファイルを書き出す場合があります。`nuxi generate` は、ルートルールが `prerender: false` を設定しない限り、リンクされているかどうかにかかわらず、すべての静的ページをそれを提供する各ロケールでプリレンダリングします。
- **静的出力での `source` または `publicAssets: false` は警告を出します。** ブラウザが読むものがないためです。
- **埋め込みの警告はサイズチェックになりました。** ビルドはプラットフォームの制限を超えた場合にのみ警告します：[バンドルの制限](/ja/guide/deployment#bundle-limits-on-edge)を参照してください。
- **訪問者が決定するところではどこでも `Vary` が設定されます：** `no_prefix` のすべてのページ、および `/` と設定に基づいてリダイレクトしうるその他の URL です。Cookie を使用している場合は `Cookie` を含み、`autoDetectLanguage` の場合は `Accept-Language` を含みます。CDN のキャッシュキーを確認してください：[HTML のキャッシュ](/ja/guide/deployment#caching-html)を参照してください。
- **`/_locales` のキャッシュが変わりました。** `/{apiBaseUrl}/**` には Nitro のルートキャッシュがなく、`s-maxage=60, stale-while-revalidate` ヘッダーもなくなりました。そのキャッシュに依存していた場合は、ペイロードルートの前に CDN を置いてください。空の辞書が `immutable` になることはありません。
- **サーバーキャッシュはデフォルトで上限があります：** `cacheMaxSize` が未設定の場合、最大 1000 エントリです。`cacheTtl` はエントリが保存された時点から数えられ、読み取りで延長されることはなくなりました。
- **新しいオプションの [`cacheStorage`](/ja/guide/performance#shared-cache-for-several-instances)：** 複数のインスタンスで共有する辞書キャッシュです。未設定の場合は何も変わりません。

## v2 から v3 へ {#from-v2-to-v3}

### 削除されたオプション {#removed-options}

```diff
 i18n: {
-  includeDefaultLocaleRoute: true,
+  strategy: 'prefix',
-  fallbackRedirectComponentPath: '~/components/MyRedirect.vue',
-  experimental: { hmr: true, previousPageFallback: true },
+  hmr: true,
 }
```

- `includeDefaultLocaleRoute: true` は `strategy: 'prefix'` です。`false` はデフォルトの `prefix_except_default` です。
- `fallbackRedirectComponentPath` は削除されました：リダイレクトはレンダリング前のサーバーと、クライアントのルートミドルウェアで行われます。カスタムのリダイレクトロジックはロケールを設定するプラグインに入れてください。[カスタムロケール検出](/ja/guide/custom-auto-detect)を参照してください。
- `experimental.hmr` はルートの `hmr` オプションになりました（デフォルトでオン）。
- `previousPageFallback` は削除されました：離れるページのキーは、オプションなしで遷移が終わるまで解決されます。

### ロケールの状態 {#locale-state}

`useState('i18n-locale')` と `useCookie('user-locale')` の代わりに `useI18nLocale()` を使用してください：

```diff
- useState('i18n-locale').value = 'fr'
- useCookie('user-locale').value = 'fr'
+ useI18nLocale().setLocale('fr') // state and cookie together
```

### ランタイムでの設定 {#config-at-runtime}

ランタイムオーバーライドを含む設定は `$getI18nConfig()` で読み取ります：

```diff
- const cookieName = useRuntimeConfig().public.i18nConfig?.localeCookie
+ const { $getI18nConfig } = useNuxtApp()
+ const cookieName = $getI18nConfig().localeCookie
```

### 内部の型エイリアス {#internal-type-aliases}

IDE や `vue-tsc` が `#i18n-internal/*` のインポートを解決できない場合は、`package.json` でマッピングしてください。Nuxt はビルド時にそれらを解決するため、これが必要になることはまれです：

```json
{
  "imports": {
    "#i18n-internal/plural": "nuxt-i18n-micro/internals",
    "#i18n-internal/strategy": "nuxt-i18n-micro/internals",
    "#i18n-internal/config": "nuxt-i18n-micro/internals"
  }
}
```
