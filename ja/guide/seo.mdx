description: "モジュールが追加する lang、hreflang、canonical、og:locale タグ、そのベース URL の決定方法、およびページごとの上書き方法。"
---

`meta: true`（デフォルト）の場合、ローカライズされたすべてのページに `<html lang dir>`、canonical リンク、`hreflang` 代替リンク、`x-default`、Open Graph のロケールタグが付与されます。このページが必要になるのは、公開オリジンを設定したい場合、タグに含めるロケールを調整したい場合、または 1 つのページでタグを上書きしたい場合です。ほとんどのサイトでは、`site.url` または `metaBaseUrl` と正しい `iso` コードがあれば十分です。

## 最小構成 {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

この場合、`/de/about` は次のようにレンダリングされます：

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## テキストの方向 {#text-direction}

`<html dir>` はロケールの `dir` から決まります。指定がない場合、右から左に書く言語には `iso`（または `code`）から判断して `rtl` が設定されます：アラビア語、ヘブライ語、ペルシア語、ウルドゥー語などのほか、`az-Arab` のような RTL スクリプトを含むタグも対象です。その他のロケールには `dir` 属性が付与されず、ブラウザーは `ltr` として扱います。

<Warning>

**`dir: 'auto'` は大きなページで解析時間がかかります** — `<html>` に `auto` を指定すると、ブラウザーは解析中にコンテンツから方向を判断します。Chromium では、このコストはページの大きさ以上に増大します：要素 5,000 個で約 100 ms、20,000 個で約 1 秒です。言語を特定できない小さなページにのみ使用してください。

</Warning>

## 出力されるタグ {#which-tags-you-get}

- **hreflang**：ページを提供するロケールごとに 1 つのタグ。値は `iso`（`iso` がない場合は `code`）で、URL には canonical と同じクエリが付きます。[ページ設定](/ja/guide/per-component-translations)または `routeLocales` で制限されたページは、そのロケールのみを列挙します。[`hreflangBaseLanguage: true`](/ja/api/module-options#hreflangbaselanguage) を指定すると、最初の地域ロケールについて言語のみのタグ（`es-ES` → `es`）も追加されます。
- **x-default**：デフォルトロケールの URL。デフォルトロケールがそのページを提供する場合にのみ出力されます。
- **og:locale**：`iso` から導出されます（`en-US` → `en_US`）。対応関係が直接的でない場合は、ロケールに `og` を設定してください。例：`{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`。どちらもない場合、`og:locale` は出力されず、開発モードで警告が表示されます。
- **canonical / og:url**：クエリパラメーターを除いた現在の URL。ただし、[`canonicalQueryWhitelist`](/ja/api/module-options#canonicalquerywhitelist) に含まれるもの（デフォルトは `page`、`sort`、`filter`、`search`、`q`、`query`、`tag`）は除きません。

ストラテジー別：

| ストラテジー | hreflang と x-default | canonical、og:url、og:locale、html 属性 |
| --- | --- | --- |
| `prefix`、`prefix_except_default`、`prefix_and_default` | あり | あり |
| `no_prefix` | なし（1 つの URL ですべてのロケールを提供） | あり |

## 公開オリジンの設定 {#set-the-public-origin}

絶対 URL には、次のうち最初に見つかったものが使用されます：

1. [`metaBaseUrl`](/ja/api/module-options#metabaseurl)
2. `nuxt-site-config` の `site.url`（`@nuxtjs/seo` によってインストールされます）
3. リクエストのオリジンに `app.baseURL` を付加したもの

最初の 2 つのいずれかを固定してください。

<Warning>

[`metaTrustForwardedHost`](/ja/api/module-options#metatrustforwardedhost) と `metaTrustForwardedProto` のデフォルトが `true` であるため、リクエストオリジンへのフォールバックは `X-Forwarded-Host` と `X-Forwarded-Proto` を読み取ります。これが安全なのは、これらのヘッダーを上書きするプロキシの背後にある場合のみです。そうでない場合、クライアントが canonical リンクのホストを選べてしまい、キャッシュがそのページを他の訪問者に配信する可能性があります。

アプリに直接アクセスできる場合は、`metaBaseUrl` を固定してください：両方のオプションを `false` に設定するのとは異なり、偽装された `Host` も無視されます。[プロキシまたは CDN の背後](/ja/guide/deployment#behind-a-proxy-or-cdn)を参照してください。

</Warning>

このフォールバックは、1 つのデプロイで複数のドメインに応答する場合に便利です：`https://site-a.com/en/about` と `https://site-b.com/en/about` はそれぞれ独自のオリジンを取得します。

ロケールに `baseUrl` がある場合、既知のホストでは `metaBaseUrl` や `site.url` より優先して自身の `baseUrl` が使われます。そのため、canonical と `og:url` はそのドメインにとどまり、`hreflang` は各ロケールをそれぞれのドメインに向けます。それ以外のホストでは `metaBaseUrl`、なければデフォルトロケールの `baseUrl`、それもなければ `site.url` が使われるため、偽装された `Host` がタグに影響することはありません。いずれも設定されていない場合はリクエストオリジンへのフォールバックが残り、ビルド時に警告が出ます。[レイヤーとドメイン](/ja/guide/layers#multiple-domains)を参照してください。

## ロケールやページを除外する {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

デフォルトロケールに `seo: false` が設定されている場合、`x-default` は出力されません。1 つのページでタグを無効にするには、[ページ設定](/ja/guide/per-component-translations#turn-off-seo-tags)の `disableMeta`、または設定ファイルの [`routeDisableMeta`](/ja/api/module-options#routedisablemeta) を使用してください。

## 1 つのページでタグを上書きする {#override-tags-on-one-page}

一部の翻訳しか存在しない CMS コンテンツや、URL が API から提供される場合は、[`useI18nHead`](/ja/composables/useI18nHead) で生成されたタグを置き換えます：

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` では `canonical`、`xDefault`、`ogLocale`、`ogUrl` の設定や削除もできます。`disable` はグループ全体（`'hreflang'`、`'x-default'`、`'canonical'`、`'og'`、`'og-alternates'`、`'html'`）を削除します。ロケール切り替え後に値が再計算されるよう、ゲッターを渡してください。ロケールごとのスラッグについては、先に `$setI18nRouteParams` を設定すれば（[ローカライズされたパス](/ja/guide/custom-locale-routes#per-locale-slugs)）、生成される代替リンクがそれを使用します。

## 末尾のスラッシュ {#trailing-slash}

`$localePath`、`$switchLocalePath`、`$switchLocaleRoute` のルートオブジェクト、`<i18n-link>`、`<i18n-switcher>`、ロケールのリダイレクト、SEO の URL は、1 つのスラッシュルールに従います：デフォルトでは `experimental.defaults.nuxtLink.trailingSlash`、i18n のパスを別にしたい場合は i18n 設定の [`trailingSlash`](/ja/api/module-options) です。

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/)（サイトマップ、robots、schema.org）は、`nuxt-site-config` 4 以降を通じてこのモジュールと連携します。サイト設定がロケールを読み取れるよう `nuxt-i18n-micro` を先に記述し、`site.url` を一度設定してください — これは上記のタグにも使われます。

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

翻訳されたサイト名と説明は、ロケールファイルの `nuxtSiteConfig.name` / `nuxtSiteConfig.description` キーから取得されます。`Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` というエラーは、`@nuxtjs/seo` がバージョン 3 より古いことを意味します。アップグレードしてください（[#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)）。
