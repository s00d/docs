# パフォーマンステスト結果

## プロジェクト情報

- **[plain-nuxt](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/plain-nuxt)**: ./test/fixtures/plain-nuxt
- **[i18n-micro](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n-micro)**: ./test/fixtures/i18n-micro
- **[i18n](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n)**: ./test/fixtures/i18n
- **[CLI](https://github.com/s00d/nuxt-i18n-micro/tree/main/scripts/src/commands/performance.ts)**: `pnpm -C scripts cli performance` / `pnpm test:performance`

### 概要

**プレーンな Nuxt**(i18n モジュールなしのベースライン)、**i18n-micro**、**`@nuxtjs/i18n` v10.6** を、同一の共有辞書プロファイルで比較します。

観点: ビルド時間、ピーク時 RSS、デプロイ対象の **コード / 翻訳 / 合計**、および Artillery + Autocannon 負荷下でのサーバー挙動。

### 計測手順に関する注意

- 指標は**フィクスチャごとに連続 3 回実行した平均**です(フィクスチャ A ×3、次に B ×3、その後 C ×3 — 交互ではありません)。
- **翻訳** には、`locales/` / `_locales/` / `translations/` 配下のロケール JSON、`chunks/raw/` 配下のすべて、および該当するロケールチャンクが含まれます。以前のレポートで `@nuxtjs/i18n` が「translations: 0 B」で「code」列が極端に大きく見えたのは、メッセージチャンクをアプリコードとして数えていたためです。
- **plain-nuxt** は、同じ量のリーフを静的な `public/translations` JSON として配信します(静的な JS import ではありません)。Artillery 下では、このベースラインは I/O 中心です。これは「i18n のオーバーヘッド」ではなく、リクエストごとに大きな JSON を取得するコストです。

### 実行回数

以下の指標はすべて**3 回の実行の平均**です。

### フィクスチャのプロファイル

| 項目 | 値 |
|------|-------|
| ロケール数 | **4**(`en`、`de`、`ru`、`fr`) |
| ページ数 | **2**(`index`、`page`) |
| index ツリー | 深さ **5**、分岐 **7** → ロケールごとに **16,807** リーフキー |
| セカンダリページ | 深さ **5**、分岐 **6** → ページ/ロケールごとに **7,776** リーフキー |
| 目的 | デフォルトの CLI プロファイル(`--locales 4 --keys 10000`); リグレッションレーダー負荷では値を引き上げる |

辞書は `test/fixtures/perf-shared/runtime.json`(CLI によって書き込み)から取得されるため、3 つのフィクスチャすべてが揃った状態になります。

## 補足

- 共有プロファイル: 4 ロケール × 2 ページ × 約 16.8k の index リーフ。
- Artillery: 6 秒のウォームアップ @6 VU/s + 60 秒の本測定 @60 VU/s。Autocannon: 10 接続 × 10 秒。
- 再実行: `pnpm test:performance` または `pnpm -C scripts cli performance --locales N --keys K --only all|micro|i18n|plain --runs N`。
