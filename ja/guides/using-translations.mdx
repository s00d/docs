# コンポーネントでの翻訳の使用

モジュールをインストールして設定すると、Vue のテンプレートやスクリプト内で `$t('your_key')` を呼び出して翻訳を表示できます。

## 1. ルートレベルとページ固有の翻訳ファイル

1. **ルートレベル**の翻訳は `/locales` フォルダー直下に配置します(例: `/locales/en.json`、`/locales/fr.json`)。ビルド時にすべてのページ固有ファイルへ自動的にマージされ、すべてのページで利用可能になります。
2. **ページ固有**の翻訳は `/locales/pages/...` 配下に、Nuxt のページフォルダー構造に合わせて配置します。

```text
locales/
├── en.json
├── fr.json
└── pages/
    └── dir1/
        ├── en.json
        └── fr.json

```

## 2. テンプレートでの `$t` の使用

`.vue` ファイル内では、テンプレートで `$t` を直接使用できます。

```vue
<template>
  <div>
    <!-- ルートレベルの翻訳(すべてのページで利用可能) -->
    <p>{{ $t('test_key') }}</p>
    <!-- 表示: Hello World! -->

    <!-- ページ固有の翻訳(このページが /dir1 の場合) -->
    <p>{{ $t('local_key') }}</p>
    <!-- 表示: This is a page-specific translation for /dir1. -->

    <!-- ネストされたキー -->
    <p>{{ $t('nested.key.deeper') }}</p>
    <!-- 表示: Nested translation here -->

    <!-- プレースホルダーの使用 -->
    <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
    <!-- 表示: Hello, Alice! -->
  </div>
</template>

<script setup lang="ts">
// 'nuxt-i18n-micro' から何かをインポートする必要はありません。
// プラグインが `useI18n` と `$t` を自動的に提供します。
const { $t } = useI18n()

// スクリプト内で $t を使用できます。例:
console.log($t('test_key')) // "Hello World!"
</script>
```

<Tip>
`$t` は、キーがネストされた JSON ノードを指す場合に**オブジェクト**を返すことがあります(例: `$t('header')` → `\{ title: "Hi" \}`)。テンプレートではこれは `[object Object]` としてレンダリングされます。文字列が保証された値が必要な場合は `$ts` を使うか、`$t('header.title')` のようにより具体的なキーを指定してください。詳細は [API リファレンス — $t と $ts](/api/methods#t) を参照してください。
</Tip>

## 3. 現在のロケールの切り替え

アプリで言語を変更するには、`useI18n()` から `$locale` を取得し、新しいコードを代入します。

```vue
<template>
  <div>
    <button @click="$switchLocale('en')">English</button>
    <button @click="$switchLocale('fr')">Français</button>
  </div>
</template>

<script setup lang="ts">
// プラグインがこれらの参照を自動的に注入します
const { $t, $switchLocale } = useI18n()
</script>
```

## 4. ネストされたキーとプレースホルダー

- **ネストされたキー**はドット記法を使用します。例: `nested.key.deeper`。
- **プレースホルダー**を使うと動的な値を挿入できます。
  ```json
  { "greeting": "Hello, {name}!" }
  ```
  ```vue
  <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
  <!-- 表示: Hello, Alice! -->
  ```

## 5. ヒントとベストプラクティス

- **競合するキー**: ページ固有のファイルにルートレベルファイルと同じキーが含まれている場合、ページ固有のバージョンが優先されます(ルート翻訳はビルド時にベースとしてマージされます)。
- **ページファイルの無効化**: ページ固有の翻訳を使いたくない場合は、Nuxt 設定で `disablePageLocales: true` を設定します。これにより `/locales/*.json` ファイルのみが使用されます。
- **直接インポート不要**: `import \{ useI18n \} from 'nuxt-i18n-micro'` を書く必要はありません。モジュールの自動注入機能が処理します。

これで完了です。これらの手順で、ルートレベルまたはページ固有の JSON ファイルから**翻訳を素早く取得**し、Nuxt アプリケーションで `$t` を使って**表示**できます。

## 追加のリソース

より高度な機能を探索するには、以下も確認してください。

1. **`<i18n-t>` コンポーネント**  
   `<i18n-t>` コンポーネントは `$t` の強力な代替で、ネストされた要素、高度なプレースホルダーの使用、より複雑な翻訳構造を含む状況で特に便利です。

- **ドキュメント**: [i18n-t](/api/components/i18n-t)

2. **`useI18n` コンポーザブル**  
   `useI18n` コンポーザブルは、翻訳の管理、ロケール切り替え、フォーマットなどのための完全な関数とリアクティブプロパティのセットを提供します。

- **ドキュメント**: [useI18n](/api/composables/use-i18n)
