# 設定リファレンス

`nuxt.config` の `i18n` キー配下にあるすべてのオプションの完全なリファレンス。型とデフォルトは `@i18n-micro/types` の [`ModuleOptions`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts) に一致します。

## クイックリファレンス

`ModuleOptions` 型から、モジュールが受け付けるすべてのオプションです。以下のセクションでは、それらがどう連携するかを説明します。完全な説明は [Module Options リファレンス](/api/module-options) を参照してください。

# オプションの詳細

このモジュールは、国際化のセットアップをカスタマイズするための豊富な設定オプションを提供します。

### 🌍 コアロケール設定

#### `locales`

{/* generated:option:locales — do not edit; run `pnpm run docs:generate` */}

**型** `Locale[]` · **デフォルト** `[]`

サポートされているロケールのリスト。
各エントリはロケールコードと、オプションのメタデータ(ISO、方向、表示名など)を定義します。

{/* /generated:option:locales */}

各ロケールオブジェクトは以下をサポートします:

| プロパティ         | 型      | 必須 | 説明                                           |
| ---------------- | --------- | -------- | ----------------------------------------------------- |
| `code`           | `string`  | ✅       | 一意の識別子(例: `'en'`)                      |
| `displayName`    | `string`  | ❌       | スイッチャー用の人が読める名前(例: `'English'`) |
| `iso`            | `string`  | ❌       | ISO コード(例: `'en-US'`)                            |
| `dir`            | `string`  | ❌       | テキスト方向(`'ltr'` または `'rtl'`)                   |
| `disabled`       | `boolean` | ❌       | `true` の場合、ドロップダウンで無効化                         |
| `baseUrl`        | `string`  | ❌       | ロケール固有ドメインのベース URL                  |
| `baseDefault`    | `boolean` | ❌       | URL からロケールプレフィックスを削除                        |
| `fallbackLocale` | `string`  | ❌       | ロケール別のフォールバック(グローバルを上書き)                |
| `[key: string]`  | `unknown` | ❌       | 任意のカスタムプロパティ(下記参照)                     |

**例**:

```typescript
locales: [
  { code: 'en', iso: 'en-US', dir: 'ltr' },
  { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
  { code: 'ar', iso: 'ar-SA', dir: 'rtl', disabled: true },
  {
    code: 'de',
    iso: 'de-DE',
    dir: 'ltr',
    baseUrl: 'https://de.example.com',
    baseDefault: true,
  },
]
```

<Warning>
`baseUrl` を使うと、内部ルートが外部リンクとして重複することがあり、ルーティングと保守が複雑になります。代わりに、特定ロケール向けの外部リンクを直接作成することを検討してください。
</Warning>

#### カスタムロケールプロパティ

ロケールオブジェクトに任意のカスタムプロパティを追加できます。これらはランタイムに渡され、`$getLocales()` からアクセスできます:

```typescript
locales: [
  { code: 'en', iso: 'en-US', flag: '🇬🇧', currency: 'GBP' },
  { code: 'de', iso: 'de-DE', flag: '🇩🇪', currency: 'EUR' },
  { code: 'ru', iso: 'ru-RU', flag: '🇷🇺', currency: 'RUB' },
]
```

コンポーネントでアクセス:

```vue
<template>
  <ul>
    <li v-for="locale in $getLocales()" :key="locale.code">{{ locale.flag }} {{ locale.displayName }} ({{ locale.currency }})</li>
  </ul>
</template>
```

デフォルトでは、カスタムプロパティは `unknown` として型付けされます。完全な TypeScript サポートを得るには、**モジュール拡張**を使用します。宣言ファイル(例: `app/i18n.d.ts` または `tsconfig` に含まれる任意の `.d.ts`)を作成します:

```typescript
// app/i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
    currency?: string
  }
}
```

これにより、すべてのカスタムプロパティが完全に型付けされます:

```typescript
const locales = $getLocales()
locales[0].flag // string | undefined ✅
locales[0].currency // string | undefined ✅
```

<Tip>

</Tip>
#### `defaultLocale`

{/* generated:option:defaultLocale — do not edit; run `pnpm run docs:generate` */}

**型** `string` · **デフォルト** `'en'`

URL やユーザー設定からロケールを判定できないときに使用するロケール。
`fallbackLocale` が設定されていない場合、不足している翻訳のフォールバックロケールとしても使用されます。

{/* /generated:option:defaultLocale */}

```typescript
defaultLocale: 'en'
```
#### `strategy`

{/* generated:option:strategy — do not edit; run `pnpm run docs:generate` */}

**型** `Strategies` · **デフォルト** `'prefix_except_default'`

ロケールプレフィックス用の URL ルーティング戦略。

- `'no_prefix'` — URL にロケールなし。ロケールはクッキーに保存されます。
- `'prefix_except_default'` — デフォルト以外のすべてのロケールにプレフィックスを付与。
- `'prefix'` — デフォルトを含め常にプレフィックスを付与。
- `'prefix_and_default'` — `prefix` と同様だが、デフォルトロケールはプレフィックスなしでもアクセス可能。

{/* /generated:option:strategy */}

<CodeGroup>
```typescript no_prefix
strategy: 'no_prefix'
// Routes: /about, /contact
// Locale detection via browser/cookies
```

```typescript prefix_except_default
strategy: 'prefix_except_default'
// Default locale: /about, /contact
// Other locales: /fr/about, /de/contact
```

```typescript prefix
strategy: 'prefix'
// All locales: /en/about, /fr/about, /de/about
```

```typescript prefix_and_default
strategy: 'prefix_and_default'
// Both prefixed and non-prefixed versions for default locale
```
</CodeGroup>

### 📂 翻訳管理
#### `translationDir`

{/* generated:option:translationDir — do not edit; run `pnpm run docs:generate` */}

**型** `string` · **デフォルト** `'locales'`

翻訳 JSON ファイルを含むディレクトリのパス(プロジェクトルートからの相対)。

{/* /generated:option:translationDir */}

```typescript
translationDir: 'i18n' // Custom directory
// Nuxt 4 colocation example:
// translationDir: 'app/locales'
```

パスは Nuxt の**プロジェクトルート**(`rootDir`)から解決されます。`app/` からではありません。Nuxt 4 では、ルート用に `app/pages/`、JSON ファイル用に `locales/`(`translationDir` を設定した場合は `app/locales`)を使うのが一般的です。
#### `disablePageLocales`

{/* generated:option:disablePageLocales — do not edit; run `pnpm run docs:generate` */}

**型** `boolean` · **デフォルト** `false`

ページごとの翻訳ファイルを無効化します。
`true` の場合、グローバル翻訳(`\{locale\}.json`)のみが読み込まれ、
ページ固有ファイル(`pages/\{page\}/\{locale\}.json`)は生成・読み込みされません。

{/* /generated:option:disablePageLocales */}

有効にすると、ルートレベルの翻訳ファイルのみが使用されます:

```tree
locales/
├── en.json
├── fr.json
└── ar.json
```
#### `fallbackLocale`

{/* generated:option:fallbackLocale — do not edit; run `pnpm run docs:generate` */}

**型** `string` · **デフォルト** `undefined(フォールバックなし。生のキーを返す)`

グローバルフォールバックロケールコード。
翻訳キーがアクティブなロケールに存在しない場合、モジュールは
このロケールで検索し、それでも見つからなければキー自体を返します。

{/* /generated:option:fallbackLocale */}

```typescript
fallbackLocale: 'en' // Global fallback
```
#### `types`

{/* generated:option:types — do not edit; run `pnpm run docs:generate` */}

**型** `boolean` · **デフォルト** `true`

デフォルトロケールファイル内の翻訳キーに基づいて、`useI18n`、`$t`、および関連ヘルパーの
TypeScript 型宣言を生成します。

{/* /generated:option:types */}

有効な場合、モジュールはビルド中に型付けされた翻訳キー付きの `.nuxt/i18n.d.ts` を出力します。型なしヘルパーを好む場合や外部ジェネレーターを使う場合は `false` に設定してください。

この組み込みジェネレーターは、モノレポや CI 向けにより厳格またはスタンドアロンな型ファイルを生成できるオプションの [`@i18n-micro/types-generator`](/integrations/types-generator) パッケージとは別物です。

```typescript
types: false // Disable built-in key typing
```
#### `routeLocales`

{/* generated:option:routeLocales — do not edit; run `pnpm run docs:generate` */}

**型** `Record<string, string[]>` · **デフォルト** —

`defineI18nRoute()` 呼び出しから抽出された、ルートごとのロケール制限。
ルートパス(例: `'/about'`)を許可されたロケールコードの配列にマッピングします。
リストにないルートには制限がありません(すべてのロケールが許可されます)。

{/* /generated:option:routeLocales */}

ルートパス(例: `'/about'`)を許可されたロケールコードにマッピングします。リストにないルートは、設定されたすべてのロケールを許可します。

通常、これは `nuxt.config` ではなくページ内の [`defineI18nRoute`](/guides/custom-locale-routes) を通じて設定します。モジュールはビルド時にページレベルの宣言をこのマップにマージします。
#### `routeDisableMeta`

{/* generated:option:routeDisableMeta — do not edit; run `pnpm run docs:generate` */}

**型** `Record<string, boolean \| string[]>` · **デフォルト** —

### 🔢 カスタマイズ
#### `plural`

{/* generated:option:plural — do not edit; run `pnpm run docs:generate` */}

**型** `PluralFunc` · **デフォルト** `組み込みの複数形化(カウントによるフォームインデックス)`

カスタム複数形化関数。
`(key, count, params, locale, getter)` を受け取り、選択された複数形形式を
文字列として返す必要があります。組み込みの `defaultPlural` ロジックにフォールバックする
場合は `null`/`undefined` を返します(そのため、一部のロケールだけ上書きできます)。

Nuxt モジュールでは、関数は `.toString()` でシリアライズされて
`.nuxt/i18n.plural.mjs` に注入されます。自己完結型である必要があります(import や外部スコープなし)。
ファイルパス文字列は**サポートされません**。

{/* /generated:option:plural */}

##### 仕組み

翻訳では、複数形形式の区切りに `|` を使用します:

```json
{
  "apples": "no apples | one apple | {count} apples"
}
```

`$tc('apples', count)` を使うか、`\{count\}` 以上のパラメーターが必要な場合は `$tc('cart', \{ count, name \})` を使います — **`count` などのパラメーターは第 2 引数のオブジェクトで渡します**、第 3 引数ではありません(第 3 引数は `defaultValue` のみ)。

`$tc` の呼び出しは、`plural` 関数を呼び出します。この関数は:

1. `t(key)` を呼び出して生の翻訳文字列(例: `"no apples | one apple | \{count\} apples"`)を取得
2. `|` で分割して形式の配列を取得
3. `count` に基づいて形式を選択
4. `\{count\}` を実際の数値に置換

**デフォルト**の実装はインデックスで選択します: `count < forms.length ? forms[count] : forms[last]`。単純なケース(0 → 最初の形式、1 → 2 番目、2+ → 最後)で機能します。

##### カスタム plural 関数

複雑な複数形化ルールを持つ言語(例: ロシア語、アラビア語、ポーランド語)については、`plural` オプションを上書きします。

<Danger>
関数は `.toString()` でシリアライズされ、ビルド時に仮想モジュールに注入されます。これは:

- **`function` キーワードを使う必要があります** — 短縮メソッド構文や外部参照を持つアロー関数は NG
- **import や外部参照は不可** — 関数は完全に自己完結である必要があります(`plural: '~/i18n/plural.ts'` のようなファイルパスは**サポートされません**)
- **`.toString()` を通過しない TypeScript 専用構文は不可**(`nuxt.config.ts` の型注釈は Nuxt が剥がすため問題ありません)
- `null` / `undefined` を返すと組み込みの `defaultPlural` にフォールバックします(ロケール別のオーバーライドに便利)
</Danger>

**例: ロシア語の複数形化**(4 形式: zero、one、few、many):

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    plural: function (key, count, _params, _locale, t) {
      const translation = t(key)
      if (!translation) return key

      const forms = translation
        .toString()
        .split('|')
        .map(function (s) {
          return s.trim()
        })
      let idx

      if (count === 0) {
        idx = 0
      } else {
        const mod10 = count % 10
        const mod100 = count % 100
        if (mod10 === 1 && mod100 !== 11) {
          idx = 1
        } else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) {
          idx = 2
        } else {
          idx = 3
        }
      }

      if (idx >= forms.length) idx = forms.length - 1
      return (forms[idx] || '').replace('{count}', String(count))
    },
  },
})
```

この翻訳を使うと:

```json
{
  "apples": "нет яблок | {count} яблоко | {count} яблока | {count} яблок"
}
```

結果:

- `$tc('apples', 0)` → `"нет яблок"`
- `$tc('apples', 1)` → `"1 яблоко"`
- `$tc('apples', 3)` → `"3 яблока"`
- `$tc('apples', 5)` → `"5 яблок"`
- `$tc('apples', 21)` → `"21 яблоко"`

**例: 単純な英語(デフォルトの動作)**:

```typescript

plural: function (key, count, params, _locale, t) {
  const translation = t(key, params)
  if (!translation) return null

  const forms = translation.toString().split('|')
  if (forms.length === 0) return null

```

    else idx = 3

}

#### `translationPayloads`

{/* generated:option:translationPayloads — do not edit; run `pnpm run docs:generate` */}

**型** `TranslationPayloadOptions` · **デフォルト** —

翻訳ペイロードの出力方法を制御します(Node: `public/<apiBaseUrl>`; Edge: Nitro `serverAssets`)。

- **Node**: `serverAssets` は `public/` 配下の `readFile` によるローカル SSR を意味します(Rollup `raw:` なし)。
- **Edge**: `serverAssets` は Nitro `serverAssets`(`assets:i18n`)を登録します。public コピーは強制しません。

通常のオールインワンセットアップではデフォルトを維持してください。Edge の大きなカタログでは `mode: 'source'` を推奨します。
CDN 対応のデプロイメントでは、ローカル出力を無効化し、`apiBaseClientHost` / `apiBaseServerHost` を設定します。

{/* /generated:option:translationPayloads */}

```typescript
{
  mode?: 'premerged' | 'source'
  serverAssets?: boolean
  serverHandler?: boolean
  publicAssets?: boolean
  prerenderRoutes?: boolean
  publicDir?: string
  warnFileCount?: number
  warnSizeBytes?: number
}
```

**デフォルト**(`mode: 'premerged'`):

```typescript
{
  mode: 'premerged',
  serverAssets: true,
  serverHandler: true,
  publicAssets: true,
  prerenderRoutes: false
}
```

**Node** の SSR は、`public/<apiBaseUrl>/` にコピーされた同じツリーを読み込みます(`readFile`)。**Edge** では、Nitro `serverAssets` がそれを埋め込みます(public コピーは強制されない — CDN 用に `publicAssets: true` を設定してください)。`mode: 'premerged'` → ページ / ロケールごとの `\{page\}/\{locale\}/data.json`; `mode: 'source'` → コンパクトなソース + ランタイムマージ。

**Node** の `serverAssets: true` は、`publicAssets` が false でも public コピーを強制します。**Edge** では、Nitro 埋め込みを登録するだけです。Edge の大きなカタログでは `mode: 'source'` を推奨します。ローカルペイロードなし、`apiBaseServerHost` なしではビルドが失敗します。

ローカルの `/\{apiBaseUrl\}/:page/:locale/data.json` ハンドラー、プリレンダリングルート、および public アセットコピーはオプションの出力のままです。

コンパクトな **public** / Edge ペイロードのために:

```typescript
i18n: {
  translationPayloads: {
    mode: 'source',
  },
}
```

`mode: 'source'` はレイヤーファイルをコンパクトに保ち、組み込みの `/_locales` ルート(または Edge の `assets:i18n`)を通じて root / ページ / フォールバックをランタイムでマージします。デフォルトでは、public アセットコピーとプリレンダリングされたペイロードルートを無効化します。

<Warning>
`mode: 'source'` では、`publicAssets` はデフォルトで `false`(`prerenderRoutes` はオプトインしない限り常にオフ)になります。したがって、Nitro / エッジランタイムのない純粋な静的ホスティングでは、これらの出力のいずれかを有効化するか、`serverHandler` をランタイムで利用可能に保つか、ペイロードを外部でホストしない限り、クライアントで翻訳を読み込めません。

デフォルトの `mode: 'premerged'` と `publicAssets: true` では、静的ファイルはすでに `public/<apiBaseUrl>/\{page\}/\{locale\}/data.json` に配置されており(クライアントの `$fetch` URL と一致)、静的ホストは Nitro なしでそれらを配信できます。
</Warning>

<Warning>
`apiBaseServerHost` または `apiBaseClientHost` が設定されている場合、モジュールはそのオリジンからすでにマージされた JSON をフェッチします。外部ホストは、組み込みルートと同じ `/\{apiBaseUrl\}/:page/:locale/data.json` レスポンスを配信する必要があります。`mode: 'source'` はローカルのペイロードディレクトリに適用され、その CDN もランタイムでマージされたペイロードを配信しない限り、外部 CDN には適用されません。
</Warning>

重複したローカル出力を手動で無効化し、CDN またはオブジェクトストレージから翻訳ペイロードを配信することもできます:

```typescript
i18n: {
  apiBaseClientHost: 'https://cdn.example.com',
  apiBaseServerHost: 'https://cdn.example.com',
  translationPayloads: {
    serverHandler: false,
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

ペイロードを public 出力に書き込むのを避けつつ、SSR / ランタイムリクエスト用の組み込みサーバールートは維持したい場合は、両方の public 出力を無効化します:

```typescript
i18n: {
  translationPayloads: {
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

**Node** では、`publicAssets` が false でも `serverAssets: true` は SSR のために依然として public コピーを強制します — ローカルのペイロードファイルをゼロにしたい場合は、`serverAssets: false` と `apiBaseServerHost` を設定してください。

ペイロードがコピーされる際の public 出力フォルダーを変更するには `publicDir` を使います。デフォルトは `apiBaseUrl`(`_locales`)です。premerged モードでは、`publicAssets` はそこに `\{page\}/\{locale\}/data.json` を書き込みます(クライアントがフェッチする同じパス)。`prerenderRoutes` は、ハンドラールートのオプションの Nitro プリレンダリングです — そのツリーがすでにコピーされている場合は通常冗長です。

すべてのローカルペイロード出力を無効化する場合、`apiBaseServerHost`(SSR)と `apiBaseClientHost`(クライアントナビゲーション)の両方を設定する必要があります。それ以外の場合、翻訳は空のオブジェクトに解決され、UI のキーが翻訳されずに表示される可能性があります。

`warnFileCount` と `warnSizeBytes` は、事前マージされたペイロード出力が大きくなったときのビルド時警告を制御します(デフォルト: 500 ファイル、10 MB)。

#### `httpCacheDuration`

{/* generated:option:httpCacheDuration — do not edit; run `pnpm run docs:generate` */}

**型** `number` · **デフォルト** `31536000`

`/\{apiBaseUrl\}/:page/:locale/data.json` の HTTP `Cache-Control` max-age(秒)。

`dateBuild` が URL をバストする(`?v=...`)場合のみ完全に適用されます(デフォルトの動作):
その場合、レスポンスは `public, max-age=…, immutable` となり、ブラウザや CDN で安全です。

- `dateBuild: 0`/`''` — URL は安定しているため、この期間は*尊重されません*。
  レスポンスは代わりに `public, max-age=0, must-revalidate` になります。変わらない URL に長い
  `max-age` を付けると、ブラウザが最初に見たペイロードが固定されます。

- `0` — `Cache-Control` を全く設定しない(ローカルデバッグに有用)
- 開発時(`import.meta.dev`)には適用されないため、HMR がブラウザキャッシュと戦うことはありません
- Nitro を通じて配信されるレスポンスのみに到達します。`public/` にコピーされ、ホスティングプラットフォーム
  によって配信されるペイロードは、そのプラットフォームのヘッダーを取ります — パフォーマンスガイドを参照してください。

`@nuxtjs/i18n` の実験的 `httpCacheDuration`(v10.2.0)に類似していますが、Nitro `defineCachedEventHandler` の
maxAge ではなく、明示的なレスポンスヘッダーです。

{/* /generated:option:httpCacheDuration */}

```ts
export default defineNuxtConfig({
  i18n: {
    // Per-build fallback (Date.now()) so immutable payloads never go stale when GIT_SHA is missing.
    dateBuild: process.env.GIT_SHA ?? String(Date.now()),
    httpCacheDuration: 86400, // 24 hours
    // httpCacheDuration: 0, // disable Cache-Control header
  },
})
```

<Tip>
ほとんどのプロジェクトでは、デフォルト(制限なし、期限切れなし)で問題ありません — 翻訳は小さく有限だからです。ただし、プロジェクトに**数千のページ**があり `disablePageLocales: false` で**多くのロケール**を持つ場合、サーバーキャッシュは大幅に成長する可能性があります。長時間稼働の Node.js サーバーでは、これが過度のメモリ使用につながる可能性があります。

- **`cacheMaxSize`** — キャッシュエントリの数を制限します。メモリを制限するのに便利です。
- **`cacheTtl`** — 古い翻訳が最終的にストレージから再読み込みされるようにします。サーバーレス環境や翻訳がランタイムで変わる場合に有用です。

**最大エントリの推定式**: `ロケール数 × (ページ数 + 1)`。例えば、10 ロケール × 500 ページ = 約 5010 エントリ。
</Tip>
