# モジュールオプションリファレンス

`nuxt-i18n-micro` が受け付けるすべてのオプションは、ビルド時に [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts) の `ModuleOptions` インターフェースから読み取られます。ここには手書きの内容は一切ないため、コードから遅れることはありません。型、デフォルト値、説明はすべて宣言そのものから取得されています。

これらのオプションが**組み合わさって**何を意味するのか(どの組み合わせが理にかなうか、戦略を切り替えると何が変わるか、実例など)については、[設定](/guides/configuration) を参照してください。このページは網羅的なリストで、設定ページは説明です。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

ネストされたオプションは、ドット区切りのパスで表示されます。したがって `translationPayloads.mode` は `translationPayloads` オブジェクト内の `mode` キーを指します。

## ロケールとルーティング

どの言語が存在し、URL でどのように現れるかを制御します。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | サポートするロケールのリスト。各エントリはロケールコードとオプションのメタデータ(ISO、方向、表示名など)を定義します。 |
| `strategy` | `Strategies` | `'prefix_except_default'` | ロケールプレフィックス用の URL ルーティング戦略。- `'no_prefix'` — URL にロケールを含めず、Cookie に保存します。- `'prefix_except_default'` — デフォルト以外のすべてのロケールにプレフィックスを付けます。- `'prefix'` — デフォルトロケールを含め、常にプレフィックスを付けます。- `'prefix_and_default'` — `prefix` に似ますが、デフォルトロケールはプレフィックスなしでもアクセス可能です。 |
| `defaultLocale` | `string` | `'en'` | URL やユーザー設定からロケールが判定できない場合に使うロケール。`fallbackLocale` が設定されていない場合、翻訳が欠落したときのフォールバックとしても使用されます。 |
| `localeCookie` | `string \| null` | `null` | セッションをまたいでユーザーのロケール設定を保持するための Cookie 名。`null` に設定すると Cookie ベースの永続化が無効になります。指定がない場合、`no_prefix` 戦略では自動的に `'user-locale'` に設定されます。 |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | グローバルなルートレベルのロケール設定。コンポーネントを変更せずに、特定のページのロケールルートを制限またはカスタマイズできます。- `false` — そのルートをローカライズから除外します。- `Record<LocaleCode, string>` — ロケールごとのカスタムパス。 |
| `customRegexMatcher` | `string \| RegExp` | `undefined(ロケールコードに基づく組み込みパターンを使用)` | URL セグメント内のロケールコードにマッチさせるカスタム正規表現(またはそのソース文字列)。`locales` で定義されたすべてのロケールコードはこのパターンに一致する必要があり、そうでない場合は警告が出されます。 |
| `noPrefixRedirect` | `boolean` | `false` | `no_prefix` 戦略の場合、ロケールプレフィックス付き URL(例: `/en/about`)からプレフィックスなし版(`/about`)へのリダイレクトを有効にします。 |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | i18n 処理から完全に除外する URL パターン(文字列または RegExp)。一致するルートにはロケールプレフィックス、リダイレクト、翻訳読み込みが適用されません。Nuxt の内部パス(`/__nuxt_error` など)は常に自動的に除外されます。 |
| `routeLocales` | `Record<string, string[]>` | — | `defineI18nRoute()` の呼び出しから抽出された、ルート単位のロケール制限。ルートパス(例: `'/about'`)を許可されたロケールコードの配列にマッピングします。リストにないルートには制限がありません(すべてのロケールが許可されます)。 |

## 翻訳

翻訳ファイルの配置場所と、キーがどのように解決されるかを制御します。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | 翻訳 JSON ファイルを含むディレクトリのパス(プロジェクトルートからの相対)。 |
| `disableWatcher` | `boolean` | `false` | 開発モード時に欠落している翻訳ファイルを自動作成するファイルウォッチャーを無効にします。 |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | ルート名を別のルート名にマッピングし、同じ翻訳ファイルを共有させます。例えば `\{ 'about-us': 'about' \}` は、`about-us` ページが独自ではなく `about` ページの翻訳を使用することを意味します。 |
| `plural` | `PluralFunc` | `組み込みの複数形処理(カウントによるフォーム選択)` | カスタム複数形処理関数。`(key, count, params, locale, getter)` を受け取り、選択された複数形フォームを文字列として返す必要があります。組み込みの `defaultPlural` ロジックにフォールバックさせるには `null`/`undefined` を返します(これにより一部のロケールだけをオーバーライドできます)。Nuxt モジュールでは、関数は `.toString()` によって `.nuxt/i18n.plural.mjs` にシリアライズされます。そのため、関数は自己完結している必要があります(インポートや外部スコープの参照は不可)。ファイルパス文字列は**サポートされません**。 |
| `disablePageLocales` | `boolean` | `false` | ページ単位の翻訳ファイルを無効化します。`true` の場合、グローバル翻訳(`\{locale\}.json`)のみが読み込まれ、ページ固有ファイル(`pages/\{page\}/\{locale\}.json`)は生成も読み込みもされません。 |
| `fallbackLocale` | `string` | `undefined(フォールバックなし、生のキーを返す)` | グローバルなフォールバックロケールコード。翻訳キーがアクティブなロケールで見つからない場合、モジュールはキー自身を返す前にこのロケールで参照します。 |

## ペイロードとキャッシュ

翻訳がブラウザに届く仕組みを制御します。ランタイムで何が変わるかについては [パフォーマンス](/guides/performance) を参照してください。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Nitro のグローバルミドルウェアでインデックスページの翻訳を事前ロードします(サーバー専用、プライベート設定)。 |
| `apiBaseUrl` | `string` | `'_locales'` | 翻訳 API ルートのベース URL セグメント(SSR/SSG のデータ取得で使用)。環境変数 `NUXT_I18N_APP_BASE_URL` でも設定できます。 |
| `apiBaseClientHost` | `string` | `undefined` | クライアント側の翻訳フェッチリクエストで使用するホストを上書きします。Nuxt が認識しているホスト名とは異なるホスト名でクライアントがサーバーへ到達する場合に便利です。環境変数 `NUXT_I18N_APP_BASE_CLIENT_HOST` でも設定できます。 |
| `apiBaseServerHost` | `string` | `undefined` | サーバー側の翻訳フェッチリクエストで使用するホストを上書きします。コンテナやマイクロサービス構成で、サーバーが内部ホスト名を通じて自分自身へ到達する場合に便利です。環境変数 `NUXT_I18N_APP_BASE_SERVER_HOST` でも設定できます。 |
| `translationPayloads` | `TranslationPayloadOptions` | — | 翻訳ペイロードの出力方法を制御します(Node: `public/<apiBaseUrl>`、Edge: Nitro `serverAssets`)。- **Node**: `serverAssets` は `public/` 配下の `readFile` によるローカル SSR を意味します(Rollup `raw:` は使用しません)。- **Edge**: `serverAssets` は Nitro `serverAssets` (`assets:i18n`) を登録します。パブリックコピーを強制しません。通常のオールインワン構成ではデフォルトのままで問題ありません。大規模な Edge カタログでは `mode: 'source'` を推奨します。CDN バックアップのデプロイでは、ローカル出力を無効化し、`apiBaseClientHost` / `apiBaseServerHost` を設定してください。 |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | 翻訳ペイロード戦略。- `premerged`: ビルド時の `\{page\}/\{locale\}/data.json` マトリックス(デフォルト)- `source`: ランタイムでマージされるコンパクトなソースファイル(Edge や大規模カタログで推奨) |
| `translationPayloads.serverAssets` | `boolean` | `true` | ローカル SSR ペイロード: Node は `public/<apiBaseUrl>` から読み取り(パブリックコピーを強制)、Edge は Nitro `serverAssets` 経由で埋め込みます。- **Node**: Nitro `serverAssets` は使用しません(Rollup `raw:` を回避)。SSR は `public/<apiBaseUrl\|publicDir>` を `\{page\}/\{locale\}/data.json` として読み取ります。これが `true` の場合、`publicAssets` が false でもパブリックコピーが強制されます。- **Edge** (`nitro.node === false`): Nitro `serverAssets`(`assets:i18n`)を `mode` と同じレイアウトで使用します。パブリックコピーは強制**しません**。CDN の場合は `publicAssets: true` を設定してください。 |
| `translationPayloads.serverHandler` | `boolean` | `true` | 組み込みのサーバールート `/\{apiBaseUrl\}/:page/:locale/data.json` を登録します。翻訳ペイロードが外部ホスト/CDN から配信される場合は無効にしてください。 |
| `translationPayloads.publicAssets` | `boolean` | `premerged モードでは true、source モードでは false` | ペイロードを Nitro のパブリック出力にコピーします。premerged では `apiBaseUrl` 配下の `\{page\}/\{locale\}/data.json`、source ではコンパクトツリーです。Node では `serverAssets` がパブリックコピーを強制する場合、このツリーが SSR ソースにもなります。 |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Nitro のプリレンダーで `/\{apiBaseUrl\}/.../data.json` を対象にします。premerged の `publicAssets` がすでにこれらのファイルを書き込んでいる場合は通常不要です。 |
| `translationPayloads.publicDir` | `string` | — | Nitro のパブリックルートからの相対のパブリック出力フォルダー。デフォルトは `apiBaseUrl`(`_locales`)。これにより静的ファイルがクライアントのフェッチ URL(`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`)と一致します。 |
| `translationPayloads.warnFileCount` | `number` | `500` | 生成されるペイロードファイル数がこのしきい値を超えたときにビルド時に警告を出します。 |
| `translationPayloads.warnSizeBytes` | `number` | `10485760(10 MB)` | 生成されるペイロードの合計サイズがこのバイト数のしきい値を超えたときにビルド時に警告を出します。 |

## SEO

各ローカライズページで生成されるメタタグを制御します。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | SEO メタタグ(`hreflang`、`canonical`、`og:url`、`og:locale`)を自動生成します。 |
| `metaBaseUrl` | `string` | `undefined` | SEO メタタグ(canonical、og:url、hreflang)のベース URL。- 具体的な URL 文字列(例: `'https://example.com'`)— そのまま使用されます(最優先)。- `undefined` — `nuxt-site-config` モジュールが存在する場合はその `site.url` に、そうでない場合は現在のリクエストの origin(サーバーでは `useRequestURL().origin`、クライアントでは `window.location.origin`)にフォールバックします。 |
| `metaTrustForwardedHost` | `boolean` | `true` | メタタグのベース URL を解決する際に `X-Forwarded-Host` ヘッダーを信頼します。実際のクライアント向けホスト名を設定するリバースプロキシ(nginx、Cloudflare、AWS ALB など)の背後でアプリを実行する場合に有効化します。 |
| `metaTrustForwardedProto` | `boolean` | `true` | メタタグのプロトコルを解決する際に `X-Forwarded-Proto` ヘッダーを信頼します。TLS 終端プロキシの背後でアプリを実行する場合に有効化すると、アプリ自身が HTTP で listen していても canonical URL が `https://` を使うようになります。 |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | canonical と `og:url` メタタグに保持するクエリパラメーター名のリスト。このリストにないパラメーターは canonical URL から取り除かれます。 |

## 検出とリダイレクト

まだロケールを選んでいない訪問者に対してロケールを選ぶ仕組みを制御します。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | 自動のロケールベースのリダイレクトを有効にします。`true` の場合、初回訪問時に訪問者は好みのロケール(Cookie、`Accept-Language` ヘッダー、またはデフォルトから検出)にリダイレクトされます。 |
| `autoDetectLanguage` | `boolean` | `true` | `Accept-Language` HTTP ヘッダーからユーザーの希望言語を自動検出します。`autoDetectPath` と組み合わせて、検出が発生するタイミングを決定します。 |
| `autoDetectPath` | `string` | `'/'` | Cookie / Accept-Language の設定に基づくリダイレクトを実行できる場所(`redirects` が有効な場合)。- `'/'` — `/` のみ(デフォルトロケールのディープリンクは到達可能なまま、デフォルト)- `'no_prefix'` — ロケールプレフィックスがないパスのみ- `'*'` — すべてのパス。明示的なロケールプレフィックスの書き換えも含みます(例: Cookie が `de` を好む場合、`/fr/about` → `/de/about`)- その他の文字列 — 完全一致(例: `'/welcome'`)プレフィックス戦略のクリーンアップ(例: `prefix_except_default` の下での `/en` → `/`)はゲートされません。 |
