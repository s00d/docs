このページでは、`nuxt.config` 内の `i18n` オブジェクトのすべてのキーを掲載しています。型やデフォルト値は表で、例や注意点は下の詳細で確認してください。型、デフォルト値、説明は [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts) の `ModuleOptions` インターフェースから生成されています。

```ts nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
    ],
    defaultLocale: 'en',
  },
})
```

ネストされたオプションはドット区切りのパスで表記されます：`translationPayloads.mode` は `translationPayloads` の `mode` キーです。

## ロケールとルーティング {#locales-and-routing}

どの言語が存在し、それらが URL にどのように表れるか。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | サポートするロケールの一覧。各エントリーはロケールコードと、任意のメタデータ（ISO、方向、表示名など）を定義します。 |
| `strategy` | `Strategies` | `'prefix_except_default'` | ロケールプレフィックスの URL ルーティング戦略。- `'no_prefix'` — URL にロケールを含めず、ロケールは Cookie に保存されます。- `'prefix_except_default'` — デフォルト以外のすべてのロケールにプレフィックスを付けます。- `'prefix'` — デフォルトロケールを含め、常にプレフィックスを付けます。- `'prefix_and_default'` — `prefix` と同様ですが、デフォルトロケールにはプレフィックスなしでもアクセスできます。 |
| `defaultLocale` | `string` | `'en'` | URL やユーザーの設定からロケールを判定できない場合に使用するロケール。翻訳のフォールバックではありません：それには `fallbackLocale` を設定してください。 |
| `localeCookie` | `string \| null` | `null` | セッションをまたいでユーザーのロケール設定を保持するための Cookie 名。`null` に設定すると Cookie による保持を無効にします。`no_prefix` 戦略では、指定がなければ自動的に `'user-locale'` に設定されます。`i18n` 設定ブロックで明示的に `null` を指定すると、その場合も無効のままになります。 |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `{}` | グローバルなルートレベルのロケール設定。コンポーネントを変更せずに、特定のページのロケールルートを制限またはカスタマイズできます。- `false` — ルートをローカライズの対象から除外します。- `Record<LocaleCode, string>` — ロケールごとのカスタムパス。 |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | URL セグメント内のロケールコードを照合するためのカスタム正規表現（またはその文字列ソース）。`locales` 内のすべてのロケールコードが、フラグなしでパターン全体に一致する必要があります。一致しない場合はビルドが失敗します。 |
| `noPrefixRedirect` | `boolean` | `false` | `no_prefix` 戦略用：デフォルトロケールがページにカスタムパスを持つ場合（`localeRoutes` / `globalLocaleRoutes`）、ページの元のパスを訪問者のロケールのカスタムパスへ、それがなければデフォルトロケールのカスタムパスへリダイレクトします（例：`/about` → `/about-us`）。独自のカスタムパスを持たないロケールは元のパスのままです。動的セグメントを含むページはリダイレクトされません。 |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | i18n ルーティングから除外するパス：文字列はパスのプレフィックス（`/admin` は `/admin/x` を含む）または `*` / `?` のグロブで、RegExp はパスに対してテストされます。一致するページにはロケールのバリアント、ロケールのリダイレクトや 404 がなく、プリレンダーから除外されますが、翻訳付きで描画はされます。`/api`、`/_nuxt`、`/__*`、翻訳ルート、一般的な静的ファイル（sitemap、robots.txt、favicon、拡張子によるアセット）は常に除外されます。 |
| `routeLocales` | `Record<string, string[]>` | — | ルートごとのロケール制限。ビルド時に `$defineI18nRoute()` の呼び出しから抽出されます。ルートのパス（例：`'/about'`）を、許可されたロケールコードの配列にマッピングします。記載されていないルートには制限がありません（すべてのロケールが許可されます）。 |

## 翻訳 {#translations}

翻訳ファイルの置き場所と、キーの解決方法。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | 翻訳 JSON ファイルを含むディレクトリへのパス（プロジェクトルートからの相対パス）。 |
| `disableWatcher` | `boolean` | `false` | 開発モードで欠けている翻訳ファイルを自動作成するファイルウォッチャーを無効にします。 |
| `routesLocaleLinks` | `{ [key: string]: string }` | `{}` | ルート名を別のルート名にマッピングし、同じ翻訳ファイルを共有します。例えば、`{ 'about-us': 'about' }` は、`about-us` ページが独自の翻訳ではなく `about` ページの翻訳を使用することを意味します。 |
| `plural` | `PluralFunc` | ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)`` | カスタムの複数形関数。`(key, count, params, locale, getter)` を受け取り、選択した複数形を文字列として返すか、組み込みの `defaultPlural` ロジックにフォールバックする場合は `null`/`undefined` を返します（これにより一部のロケールだけを上書きできます）。Nuxt モジュールでは、関数は `.toString()` で `.nuxt/i18n.plural.mjs` にシリアライズされるため、自己完結している必要があります（import や外側のスコープは不可）。ファイルパスの文字列は**サポートされていません**。 |
| `disablePageLocales` | `boolean` | `false` | ページごとの翻訳ファイルを無効にします。`true` の場合、グローバルな翻訳（`{locale}.json`）のみが読み込まれ、ページ固有のファイル（`pages/{page}/{locale}.json`）は生成も読み込みもされません。 |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | グローバルなフォールバックロケールコード。あるロケールに欠けているキーはこのロケールから取得されます（ビルド時または読み込み時に各ペイロードにマージされます）。これがない場合、欠けているキーはキーそのものとして描画されます。 |

## ペイロードとキャッシュ {#payloads-and-caching}

翻訳がブラウザーに届く方法。これらが実行時に何を変えるかは[パフォーマンス](/ja/guide/performance)で説明しています。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Nitro のグローバルミドルウェアでインデックスページの翻訳をプリロードします（サーバー専用、プライベート設定）。 |
| `apiBaseUrl` | `string` | `'_locales'` | 翻訳 API ルートのベース URL パスセグメント（SSR/SSG のデータ取得で使用）。環境変数 `NUXT_I18N_APP_BASE_URL` でも設定できます。 |
| `apiBaseClientHost` | `string` | `undefined` | クライアントサイドの翻訳取得リクエストで使用するホストを上書きします。クライアントが Nuxt から見えるものとは異なるホスト名でサーバーにアクセスする場合に便利です。環境変数 `NUXT_I18N_APP_BASE_CLIENT_HOST` でも設定できます。 |
| `apiBaseServerHost` | `string` | `undefined` | サーバーサイドの翻訳取得リクエストで使用するホストを上書きします。サーバーが内部ホスト名で自身にアクセスするコンテナ／マイクロサービス構成で便利です。環境変数 `NUXT_I18N_APP_BASE_SERVER_HOST` でも設定できます。 |
| `translationPayloads` | `TranslationPayloadOptions` | — | 翻訳ペイロードの出力方法を制御します（Node サーバー：`public/<apiBaseUrl>`、Edge／関数／インライン：Nitro `serverAssets`）。- **Node サーバー**（`node-server`、`node-cluster`、ディスクの `serveStatic`）：`serverAssets` は `public/` 配下を `readFile` で読むローカル SSR を意味します（Rollup `raw:` なし）。- **Edge、関数プリセット、`serveStatic: "inline"`**（`vercel`、`netlify`、`aws-lambda`、winterjs など）：`public/` がディスク上で SSR から利用できないため、`serverAssets` は Nitro `serverAssets`（`assets:i18n`）を登録します。パブリックコピーは強制しません — CDN／静的配信には `publicAssets: true` を設定してください。通常のオールインワン構成ではデフォルトのままにしてください。大規模な Edge カタログでは `mode: 'source'` を推奨します。CDN を利用するデプロイでは、ローカル出力を無効にし、`apiBaseClientHost` / `apiBaseServerHost` を設定してください。 |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | 翻訳ペイロードの戦略。- `premerged`：ビルド時の `{page}/{locale}/data.json` マトリクス（デフォルト）- `source`：実行時にマージされるコンパクトなソースファイル（Edge／大規模カタログで推奨） |
| `translationPayloads.serverAssets` | `boolean` | `true` | ローカル SSR のペイロード：ディスクから `public/` を配信する Node サーバーはそのツリーを読み込み（パブリックコピーを強制）、Edge、関数プリセット、`serveStatic: "inline"` は Nitro `serverAssets` で埋め込みます。- **Node サーバー**（プリセット自体が `public/` を配信する、例：`node-server`）：Nitro `serverAssets` なし（Rollup `raw:` を回避）。SSR は `public/<apiBaseUrl\|publicDir>` を `{page}/{locale}/data.json` として読み込みます。これが `true` の場合、`publicAssets` が false でもパブリックコピーが強制されます。- **Edge、関数プリセット、インライン**（`nitro.node === false`、`vercel` / `netlify` / `aws-lambda` のようにディスクの `serveStatic` がない場合、または winterjs のような `serveStatic: "inline"`）：`mode` と同じレイアウトの Nitro `serverAssets`（`assets:i18n`）。パブリックコピーは強制**しません** — CDN／静的配信には `publicAssets: true` を設定してください。 |
| `translationPayloads.serverHandler` | `boolean` | `true` | `/{apiBaseUrl}/:page/:locale/data.json` に組み込みのサーバールートを登録します。翻訳ペイロードを外部のホスト／CDN から配信する場合は無効にしてください。 |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | ペイロードを Nitro のパブリック出力にコピーします。premerged → `apiBaseUrl` 配下の `{page}/{locale}/data.json`、source → コンパクトなツリー。SSR が `public/` を読み込む場合（`node-server` など）、`serverAssets: true` もこのコピーを強制します。Edge／関数／`serveStatic: "inline"` プリセットでは、これが `true` の場合のみコピーします（SSR は Nitro の埋め込みを使用）。 |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | `/{apiBaseUrl}/.../data.json` の Nitro プリレンダーを有効にします。premerged の `publicAssets` がすでにそれらのファイルを書き出している場合、通常は不要です。 |
| `translationPayloads.publicDir` | `string` | — | Nitro のパブリックルートからの相対パスで指定するパブリック出力フォルダー。デフォルトは `apiBaseUrl`（`_locales`）。これにより、静的ファイルがクライアントの取得 URL（`/{apiBaseUrl}/{page}/{locale}/data.json`）と一致します。 |
| `translationPayloads.rootDelta` | `boolean` | `true` | ロケールごとに 1 つのルートファイルを書き出し、各ページファイルにはそれとの差分のみを書き出します。クライアントと SSR がそれらをマージします。ファイルを読み込む箇所では、チャンク全体でも引き続き機能します。`false` にすると、すべてのページファイルに辞書全体を保持します。`premerged` のみで、`disablePageLocales` では無効です。 |
| `translationPayloads.warnFileCount` | `number` | `500` | 生成されたペイロードファイルの数がこのしきい値を超えると、ビルド時に警告します。 |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | 生成されたペイロードの合計サイズがこのしきい値（バイト）を超えると、ビルド時に警告します。 |

## SEO {#seo}

ローカライズされた各ページに生成されるメタタグ。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | SEO メタタグ（`hreflang`、`canonical`、`og:url`、`og:locale`）を自動生成します。 |
| `metaBaseUrl` | `string` | `undefined` | SEO メタタグ（canonical、og:url、hreflang）のベース URL。- 具体的な URL 文字列（例：`'https://example.com'`）— そのまま使用されます（最優先）。- `undefined` — `nuxt-site-config` モジュールがある場合はその `site.url` に、それ以外の場合は現在のリクエストのオリジン（サーバーでは `useRequestURL().origin`、クライアントでは `window.location.origin`）にフォールバックします。 |
| `metaTrustForwardedHost` | `boolean` | `true` | メタタグのベース URL を解決する際に `X-Forwarded-Host` ヘッダーを信頼します。このヘッダーに実際のクライアント向けホスト名を設定するリバースプロキシ（nginx、Cloudflare、AWS ALB など）の背後でアプリを実行する場合に有効にします。 |
| `metaTrustForwardedProto` | `boolean` | `true` | メタタグのプロトコルを解決する際に `X-Forwarded-Proto` ヘッダーを信頼します。TLS を終端するプロキシの背後でアプリを実行する場合に有効にすると、アプリ自体が HTTP で待ち受けていても canonical URL に `https://` が使われます。 |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | canonical と `og:url` メタタグで保持するクエリパラメーター名の一覧。この一覧にないパラメーターは canonical URL から削除されます。 |

## 検出とリダイレクト {#detection-and-redirects}

まだロケールを選んでいない訪問者のためのロケールの選択。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | 自動的なロケールリダイレクトを有効にします（サーバープラグインとクライアントのルートミドルウェア）。`true` の場合、プレフィックス戦略ではプレフィックスのない URL をローカライズされた形式にリダイレクトします。ロケールは、アプリの状態、`autoDetectPath` が許可する範囲での Cookie または `Accept-Language`、それ以外の場合はデフォルトから決まります。`no_prefix` では、検出によって URL が変わることはありません（カスタムパスについては `noPrefixRedirect` を参照）。 |
| `autoDetectLanguage` | `boolean` | `true` | `Accept-Language` HTTP ヘッダーからユーザーの優先言語を自動的に検出します。`autoDetectPath` と組み合わせて、検出を行うタイミングを決定します。 |
| `autoDetectPath` | `string` | `'/'` | Cookie／Accept-Language の設定によるリダイレクトを実行できる場所（`redirects` が有効な場合）。- `'/'` — `/` のみ（デフォルトロケールのディープリンクには引き続きアクセス可能。デフォルト）- `'no_prefix'` — ロケールプレフィックスのないパスのみ - `'*'` — 明示的なロケールプレフィックスの書き換えを含むすべてのパス（例：Cookie が `de` を優先する場合 `/fr/about` → `/de/about`）- その他の文字列 — そのパス。末尾のスラッシュは無視されます（例：`'/welcome'`）`prefix` では、許可されたパス以外のプレフィックスのない URL も、デフォルトロケールの形式にリダイレクトされます（`/about` → `/en/about`）。`prefix_except_default` でプレフィックス付きのデフォルトロケール（`/en`）はリダイレクトではなく 404 になります。 |

## 登録 {#registration}

無効にできるモジュールの部分。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | 実行時に `$defineI18nRoute()` を提供します。ビルドはいずれにしてもページ内の `$defineI18nRoute()` の呼び出しを読み取ります。 |
| `plugin` | `boolean` | `true` | `$t()`、`$tc()`、`$getLocale()`、`$switchLocale()` などのランタイムヘルパーを提供するコア i18n プラグインを登録します。 |
| `hooks` | `boolean` | `true` | 読み込み時とナビゲーション時に `i18n:register` アプリフックを呼び出し、プラグインが翻訳を追加できるようにします。 |
| `components` | `boolean` | `true` | 組み込みの i18n コンポーネント（`<i18n-link>`、`<i18n-switcher>`、`<i18n-t>`、`<i18n-group>`）を登録します。自動的なコンポーネント登録を無効にするには `false` に設定します（例：それらを使用せず、モジュールのフットプリントを減らしたい場合）。 |
| `types` | `boolean` | `true` | デフォルトロケールファイルの翻訳キーに基づいて、`useI18n`、`$t` および関連ヘルパーの TypeScript 型宣言を生成します。 |
| `debug` | `boolean` | `false` | ロケール検出、ルート生成、翻訳読み込みの詳細なデバッグログを有効にします。 |

## その他 {#other}

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `trustForwardedHost` | `boolean` | `false` | リクエストのドメイン（`locales[].baseUrl`）を `Host` ではなく `X-Forwarded-Host` から選択します。そのヘッダーを上書きするプロキシの背後でのみ有効にしてください。 |
| `hreflangBaseLanguage` | `boolean` | `false` | 各ロケールの `iso` から派生した、言語のみの `hreflang` も出力します（例：`es-ES` → `es` も）。`locales` 内で最初の地域ロケールが、その言語の言語のみのタグを担当します。ルーティング用の `code` は使用されず、`iso \|\| code` のみが使われます。 |
| `additionalTranslationDirs` | `string[]` | `[]` | 追加のディレクトリ（プロジェクトルート／各 Nuxt レイヤーのルートからの相対パス）。そのトップレベルの `{locale}.json` ファイルが、`translationDir` より前にグローバル辞書へディープマージされます。マージ順序：配列順の各エントリー（レイヤーをまたいで）、次に `translationDir`（競合時に優先）。ルートの `{locale}.json` ファイルのみが読み込まれ、これらのディレクトリ配下の `pages/` は無視されます。例：`translationDir: 'frontend'`、`additionalTranslationDirs: ['common']` → `common/en.json`、次に `frontend/en.json`。 |
| `vueDevtools` | `boolean` | `true` | 開発時に Vue DevTools のインスペクターとタイムラインを登録します（ブラウザー拡張機能）。Nuxt DevTools のカスタムタブとは別です。 |
| `trailingSlash` | `'append' \| 'remove'` | `undefined (inherit from Nuxt)` | `$localePath` / `$switchLocalePath` の末尾スラッシュ（NuxtLink と同等）。未設定の場合は `experimental.defaults.nuxtLink.trailingSlash` がデフォルトになります。i18n のパスヘルパーで Nuxt のリンクのデフォルトを上書きするには、明示的に設定してください。 |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | ローカライズされたルート名の先頭に付けるプレフィックス（例：`'localized-index'`）。元のルートと生成されたロケールのバリアントを区別するために内部で使用されます。 |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | ルートごとのメタタグの無効化。ルート名またはパスを、`true`（すべてのメタを無効化）またはメタを無効にするロケールコードの配列にマッピングします。ビルド時に `$defineI18nRoute()` の呼び出しで見つかったエントリーが追加されます。 |
| `missingWarn` | `boolean` | `true` | 翻訳キーが欠けている場合にコンソール警告を表示します（開発ビルド、ブラウザー内）。 |
| `hmr` | `boolean` | `true` | 開発時に翻訳ファイルのホットモジュールリプレースメントを有効にします。`true` の場合、JSON 翻訳ファイルの変更により、ページ全体を更新せずに自動的に再読み込みされます。 |
| `cacheMaxSize` | `number` | `0` | メモリ内の翻訳キャッシュの最大エントリー数。fetch キャッシュとサーバーキャッシュは最も長く使われていないエントリーを破棄し、ブラウザーの辞書マップは最も古いものを破棄します（FIFO）。`0` はブラウザーでは無制限を意味し、その場合サーバーキャッシュは最大 1000 エントリーを保持するため、でっち上げのページ名を含むリクエスト URL でサーバーのメモリが増え続けることはありません。 |
| `cacheTtl` | `number` | `0` | fetch とサーバーの翻訳キャッシュの有効期間（秒）。エントリーが保存された時点から数えられ（読み込みでは延長されません）、`apiBaseServerHost` からのデータは少なくともその頻度で更新されます。ブラウザーのアクティブな辞書はこれによって期限切れになりません。`0` はエントリーが期限切れにならないことを意味します。 |
| `cacheStorage` | `string` | — | 複数のサーバーインスタンスが辞書キャッシュとして共有する Nitro ストレージのマウント名（`nitro.storage`、例：`'redis'`）。プロセス内キャッシュの後、ソースの前に読み込まれます。主に `apiBaseServerHost` で効果を発揮します：インスタンスごとに 1 回ではなく、バックエンドから 1 回だけ取得します。エントリーはビルドごとにキー付けされ、`cacheTtl` 後、または `0` の場合は 1 日後に期限切れになります。開発時とプリレンダー時は無効です。ストレージが失敗した場合はソースにフォールバックします。未設定：共有キャッシュなし。 |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | ロケールごとの名前付き数値フォーマット（Vue I18n 互換）。`$tn(1000, 'currency')` 形式の呼び出しが可能になります。 |
| `timeZone` | `string` | `the runtime's zone` | `$td` と `<i18n-t date>` 用の IANA タイムゾーン（`Europe/Berlin`）。サーバーとすべてのブラウザーで同じ日付を描画するには設定してください。名前付きフォーマット自身の `timeZone` が優先されます。 |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | ロケールごとの名前付き日時フォーマット（Vue I18n 互換の `datetimeFormats`）。`$td(date, 'short')` 形式の呼び出しが可能になります。 |
| `httpCacheDuration` | `number` | `31536000` | `/{apiBaseUrl}/:page/:locale/data.json` の HTTP `Cache-Control` の max-age（秒）。`dateBuild` が URL をキャッシュバスティングしている間（`?v=...`、デフォルト）のみ完全に適用されます：その場合レスポンスは `private, max-age=…, immutable` となり、ブラウザーはそれを固定しますが、クエリを無視する CDN は固定できません（`httpCacheControl: false` の場合は `public`）。- `dateBuild: 0`/`''` — URL が固定されるため、この期間は*尊重されず*、レスポンスは代わりに `public, max-age=0, must-revalidate` になります。変わらない URL に長い `max-age` を設定すると、ブラウザーが最初に見たペイロードが固定されてしまいます。- `0` — `Cache-Control` をまったく設定しません（ローカルでのデバッグに便利）- 開発時（`import.meta.dev`）には適用されないため、HMR がブラウザーキャッシュに妨げられることはありません - Nitro を通じて配信されるレスポンスにのみ適用されます。`public/` にコピーされホスティングプラットフォームが配信するペイロードには、そのプラットフォームのヘッダーが適用されます — パフォーマンスガイドを参照してください。`@nuxtjs/i18n` の実験的な `httpCacheDuration`（v10.2.0）に相当しますが、Nitro `defineCachedEventHandler` の maxAge ではなく、明示的なレスポンスヘッダーとして提供されます。 |
| `httpCacheControl` | `string \| false` | `'public, max-age=60'` | ホストまたはパス全体のルールが応答するペイロードファイルの `Cache-Control`。これらは `?v=` を参照できません。Node サーバーでは、現在の `?v=` へのレスポンスは `httpCacheDuration` の間固定され、それ以外は再検証されます。`source`、`cacheTtl`、`apiBaseServerHost` のように、ビルドなしで辞書が変わる場合は、すべてのレスポンスにこのヘッダーが付きます。`false` にすると、すべてのファイルが `max-age=0, must-revalidate` のままになります。 |
| `dateBuild` | `string \| number` | — | 翻訳リクエストのキャッシュバスティング（`?v=...`）に使用する値。指定しない場合、モジュールは翻訳ファイルのハッシュを使用するため、値は翻訳が変わったときにのみ変わります（ハッシュを計算できない場合は `Date.now()`）。`0` または `''` でキャッシュバスティングを無効にします。自分で固定するには安定した値（git SHA、ビルド番号）を設定してください。`NUXT_I18N_DATE_BUILD` または `runtimeConfig.public.i18nRuntime.dateBuild` は、辞書がその場で置き換えられた後に、実行時にこれを置き換えます：固定された URL は再ビルドなしで置き去りにされます。 |
| `experimental` | `Record<string, unknown>` | — | 実験的／不安定なオプションの入れ物。内容はマイナーバージョン間で予告なく変更または削除される可能性があります。 |

## オプションの詳細 {#option-details}

表以上に付け加えることがないオプションは、ここでは繰り返しません。

### ロケールと URL {#locales-and-urls}

#### `locales` {#locales}

**型** `Locale[]` · **デフォルト** `[]`

サポートするロケールの一覧。
各エントリーはロケールコードと、任意のメタデータ（ISO、方向、表示名など）を定義します。

各エントリーは `Locale` オブジェクトです：

| プロパティ | 型 | 説明 |
| --- | --- | --- |
| `code` | `string` | **必須。** URL セグメントとファイル名（`en`、`de-at`）。 |
| `iso` | `string` | `<html lang>`、`hreflang`、複数形、`$tn` / `$td` / `$tdr` 用の BCP-47 タグ（`en-US`）。 |
| `displayName` | `string` | `<i18n-switcher>` と `$getLocaleName()` で使用するラベル。 |
| `dir` | `'ltr' \| 'rtl' \| 'auto'` | `<html dir>`。指定しない場合、既知の RTL 言語には `rtl` が設定され、その他のロケールには属性が付きません。[SEO](/ja/guide/seo#text-direction) を参照してください。 |
| `disabled` | `boolean` | ルート、ペイロード、切り替えから除外されます。そのプレフィックスは 404 になり、そのロケールへのリンクは現在のページにとどまります。 |
| `fallbackLocale` | `string` | このロケールのフォールバック。グローバルな `fallbackLocale` を上書きします。 |
| `seo` | `boolean` | `false` にすると、ロケールを `hreflang` と `og:locale:alternate` から除外します。 |
| `og` | `string` | `og:locale` の値（`ar_AE`）。デフォルト：`iso` を変換したもの。 |
| `baseUrl` | `string` | ロケール独自のドメイン：1 つのビルドがそれを配信し、他のドメインからそのロケールへのリンクは絶対 URL になります。 |
| `baseDefault` | `boolean` | `baseUrl` と併用：そのホストのデフォルトロケールで、そのロケールへのリンクには `/<code>` プレフィックスが付きません（`prefix` では付きます）。 |

その他のプロパティは保持され、`$getLocales()` で返されます。`Locale` を拡張して型を付けてください：

```ts
// i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
  }
}
export {}
```

モジュールは `@i18n-micro/types` をホイストするため、pnpm でもパッケージをインストールせずにこれが機能します。

#### `defaultLocale` {#defaultlocale}

**型** `string` · **デフォルト** `'en'`

URL やユーザーの設定からロケールを判定できない場合に使用するロケール。
翻訳のフォールバックではありません：それには `fallbackLocale` を設定してください。

#### `strategy` {#strategy}

**型** `Strategies` · **デフォルト** `'prefix_except_default'`

ロケールプレフィックスの URL ルーティング戦略。

- `'no_prefix'` — URL にロケールを含めず、ロケールは Cookie に保存されます。
- `'prefix_except_default'` — デフォルト以外のすべてのロケールにプレフィックスを付けます。
- `'prefix'` — デフォルトロケールを含め、常にプレフィックスを付けます。
- `'prefix_and_default'` — `prefix` と同様ですが、デフォルトロケールにはプレフィックスなしでもアクセスできます。

戦略ごとの URL とリダイレクト：[ルーティング戦略](/ja/guide/strategy)。

#### `globalLocaleRoutes` {#globallocaleroutes}

**型** `GlobalLocaleRoutes` · **デフォルト** `{}`

グローバルなルートレベルのロケール設定。
コンポーネントを変更せずに、特定のページのロケールルートを
制限またはカスタマイズできます。

- `false` — ルートをローカライズの対象から除外します。
- `Record<LocaleCode, string>` — ロケールごとのカスタムパス。

キーはルート名またはパスです。通常は [`$defineI18nRoute`](/ja/guide/per-component-translations) でページごとに設定します。

```ts
globalLocaleRoutes: {
  about: { en: '/about-us', de: '/ueber-uns' },
  'admin-dashboard': false, // not localized
}
```

詳細、動的セグメント、`pages:extend` のルート：[ローカライズされたパス](/ja/guide/custom-locale-routes)。

#### `routeLocales` {#routelocales}

**型** `Record<string, string[]>` · **デフォルト** —

ルートごとのロケール制限。ビルド時に `$defineI18nRoute()` の呼び出しから抽出されます。
ルートのパス（例：`'/about'`）を、許可されたロケールコードの配列にマッピングします。
記載されていないルートには制限がありません（すべてのロケールが許可されます）。

#### `routeDisableMeta` {#routedisablemeta}

**型** `Record<string, boolean \| string[]>` · **デフォルト** —

ルートごとのメタタグの無効化。ルート名またはパスを、`true`（すべてのメタを無効化）または
メタを無効にするロケールコードの配列にマッピングします。ビルド時に `$defineI18nRoute()` の
呼び出しで見つかったエントリーが追加されます。

#### `customRegexMatcher` {#customregexmatcher}

**型** `string \| RegExp` · **デフォルト** `undefined (uses built-in pattern based on locale codes)`

URL セグメント内のロケールコードを照合するためのカスタム正規表現（またはその文字列ソース）。
`locales` 内のすべてのロケールコードが、フラグなしでパターン全体に一致する必要があります。一致しない場合はビルドが失敗します。

```ts
customRegexMatcher: '[a-z]{2}-[a-z]{2}', // en-us, de-at
```

#### `excludePatterns` {#excludepatterns}

**型** `(string \| RegExp)[]` · **デフォルト** `undefined`

i18n ルーティングから除外するパス：文字列はパスのプレフィックス（`/admin` は `/admin/x` を含む）
または `*` / `?` のグロブで、RegExp はパスに対してテストされます。一致するページにはロケールの
バリアント、ロケールのリダイレクトや 404 がなく、プリレンダーから除外されますが、翻訳付きで
描画はされます。`/api`、`/_nuxt`、`/__*`、翻訳ルート、一般的な静的ファイル
（sitemap、robots.txt、favicon、拡張子によるアセット）は常に除外されます。

```ts
excludePatterns: ['/admin', '/docs/*', /^\/preview\//],
```

詳細：[パスの除外](/ja/guide/excluding-static-files)。

#### `localizedRouteNamePrefix` {#localizedroutenameprefix}

**型** `string` · **デフォルト** `'localized-'`

ローカライズされたルート名の先頭に付けるプレフィックス（例：`'localized-index'`）。
元のルートと生成されたロケールのバリアントを区別するために内部で使用されます。

#### `trailingSlash` {#trailingslash}

**型** `'append' \| 'remove'` · **デフォルト** `undefined (inherit from Nuxt)`

`$localePath` / `$switchLocalePath` の末尾スラッシュ（NuxtLink と同等）。
未設定の場合は `experimental.defaults.nuxtLink.trailingSlash` がデフォルトになります。
i18n のパスヘルパーで Nuxt のリンクのデフォルトを上書きするには、明示的に設定してください。

### 翻訳 {#translations}

#### `translationDir` {#translationdir}

**型** `string` · **デフォルト** `'locales'`

翻訳 JSON ファイルを含むディレクトリへのパス（プロジェクトルートからの相対パス）。

`app/` ではなく各レイヤーのルートからの相対パスです（Nuxt 4 のレイアウトでは `'app/locales'`）。ファイルレイアウト：[翻訳ファイル](/ja/guide/translations)。

#### `additionalTranslationDirs` {#additionaltranslationdirs}

**型** `string[]` · **デフォルト** `[]`

追加のディレクトリ（プロジェクトルート／各 Nuxt レイヤーのルートからの相対パス）。そのトップレベルの
`{locale}.json` ファイルが、`translationDir` より前にグローバル辞書へディープマージされます。

マージ順序：配列順の各エントリー（レイヤーをまたいで）、次に `translationDir`（競合時に優先）。
ルートの `{locale}.json` ファイルのみが読み込まれ、これらのディレクトリ配下の `pages/` は無視されます。

例：`translationDir: 'frontend'`、`additionalTranslationDirs: ['common']` → `common/en.json`、次に `frontend/en.json`。

#### `disablePageLocales` {#disablepagelocales}

**型** `boolean` · **デフォルト** `false`

ページごとの翻訳ファイルを無効にします。
`true` の場合、グローバルな翻訳（`{locale}.json`）のみが読み込まれ、
ページ固有のファイル（`pages/{page}/{locale}.json`）は生成も読み込みもされません。

#### `fallbackLocale` {#fallbacklocale}

**型** `string` · **デフォルト** `undefined (no fallback; returns the raw key)`

グローバルなフォールバックロケールコード。
あるロケールに欠けているキーはこのロケールから取得されます（ビルド時または読み込み時に
各ペイロードにマージされます）。これがない場合、欠けているキーはキーそのものとして描画されます。

#### `routesLocaleLinks` {#routeslocalelinks}

**型** `{ [key: string]: string }` · **デフォルト** `{}`

ルート名を別のルート名にマッピングし、同じ翻訳ファイルを共有します。
例えば、`{ 'about-us': 'about' }` は、`about-us` ページが独自の翻訳ではなく
`about` ページの翻訳を使用することを意味します。

```ts
routesLocaleLinks: { 'products-id': 'products' },
```

#### `plural` {#plural}

**型** `PluralFunc` · **デフォルト** ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)``

カスタムの複数形関数。
`(key, count, params, locale, getter)` を受け取り、選択した複数形を文字列として返すか、
組み込みの `defaultPlural` ロジックにフォールバックする場合は `null`/`undefined` を返します
（これにより一部のロケールだけを上書きできます）。

Nuxt モジュールでは、関数は `.toString()` で `.nuxt/i18n.plural.mjs` に
シリアライズされるため、自己完結している必要があります（import や外側のスコープは不可）。
ファイルパスの文字列は**サポートされていません**。

組み込みのルールとその `=0 ` マーカーについては [`$tc`](/ja/api/methods#$tc) で説明しています。独自の関数は、それが応答するものについて組み込みのルールを置き換え、マーカーを含んだままの生の値を受け取ります。`null` を返すと呼び出しは組み込みのルールに戻されます。関数は `(key, count, params, locale, getter)` を受け取り、`getter(key)` はすべての形式を含む生の文字列を返します。自己完結した `function` またはアロー式として記述してください（メソッドの省略記法、import、外側の変数は不可）：

```ts
plural: function (key, count, params, locale, getter) {
  if (!locale.startsWith('en')) return null // built-in rule for other locales
  const forms = String(getter(key) ?? '').split('|').map((form) => form.trim())
  const index = count === 0 ? 0 : count === 1 ? 1 : 2
  return (forms[Math.min(index, forms.length - 1)] ?? '').replace('{count}', String(count))
},
```

```json
{ "apples": "no apples | one apple | {count} apples" }
```

#### `numberFormats` {#numberformats}

**型** `Record<string, Record<string, Intl.NumberFormatOptions>>` · **デフォルト** —

ロケールごとの名前付き数値フォーマット（Vue I18n 互換）。
`$tn(1000, 'currency')` 形式の呼び出しが可能になります。

[`$tn`](/ja/api/methods#$tn) で使用されます。

#### `datetimeFormats` {#datetimeformats}

**型** `Record<string, Record<string, Intl.DateTimeFormatOptions>>` · **デフォルト** —

ロケールごとの名前付き日時フォーマット（Vue I18n 互換の `datetimeFormats`）。
`$td(date, 'short')` 形式の呼び出しが可能になります。

[`$td`](/ja/api/methods#$td) で使用されます。

#### `timeZone` {#timezone}

**型** `string` · **デフォルト** `the runtime's zone`

`$td` と `<i18n-t date>` 用の IANA タイムゾーン（`Europe/Berlin`）。サーバーとすべてのブラウザーで

#### `disableWatcher` {#disablewatcher}

**型** `boolean` · **デフォルト** `false`

開発モードで欠けている翻訳ファイルを自動作成するファイルウォッチャーを無効にします。

#### `missingWarn` {#missingwarn}

**型** `boolean` · **デフォルト** `true`

### ペイロードとキャッシュ {#payloads-and-caching}

#### `translationPayloads` {#translationpayloads}

**型** `TranslationPayloadOptions` · **デフォルト** —

翻訳ペイロードの出力方法を制御します（Node サーバー：`public/<apiBaseUrl>`、Edge／関数／インライン：Nitro `serverAssets`）。

- **Node サーバー**（`node-server`、`node-cluster`、ディスクの `serveStatic`）：`serverAssets` は `public/` 配下を `readFile` で読むローカル SSR を意味します（Rollup `raw:` なし）。
- **Edge、関数プリセット、`serveStatic: "inline"`**（`vercel`、`netlify`、`aws-lambda`、winterjs など）：`public/` がディスク上で SSR から利用できないため、
  `serverAssets` は Nitro `serverAssets`（`assets:i18n`）を登録します。パブリックコピーは強制しません — CDN／静的配信には `publicAssets: true` を設定してください。

通常のオールインワン構成ではデフォルトのままにしてください。大規模な Edge カタログでは `mode: 'source'` を推奨します。
CDN を利用するデプロイでは、ローカル出力を無効にし、`apiBaseClientHost` / `apiBaseServerHost` を設定してください。

サブオプションは[ペイロードとキャッシュ](#payloads-and-caching)の表にあります。Node、サーバーレス、Edge、静的ホスティング、CDN のそれぞれに適した組み合わせ：[デプロイ](/ja/guide/deployment)。

#### `apiBaseUrl` {#apibaseurl}

**型** `string` · **デフォルト** `'_locales'`

翻訳 API ルートのベース URL パスセグメント（SSR/SSG のデータ取得で使用）。
環境変数 `NUXT_I18N_APP_BASE_URL` でも設定できます。

ペイロードの URL は `/{apiBaseUrl}/{page}/{locale}/data.json` です。

#### `apiBaseClientHost` {#apibaseclienthost}

**型** `string` · **デフォルト** `undefined`

クライアントサイドの翻訳取得リクエストで使用するホストを上書きします。
クライアントが Nuxt から見えるものとは異なるホスト名でサーバーにアクセスする場合に便利です。
環境変数 `NUXT_I18N_APP_BASE_CLIENT_HOST` でも設定できます。

#### `apiBaseServerHost` {#apibaseserverhost}

**型** `string` · **デフォルト** `undefined`

サーバーサイドの翻訳取得リクエストで使用するホストを上書きします。
サーバーが内部ホスト名で自身にアクセスするコンテナ／マイクロサービス構成で便利です。
環境変数 `NUXT_I18N_APP_BASE_SERVER_HOST` でも設定できます。

ホストは、組み込みのルートと同じ `/{apiBaseUrl}/{page}/{locale}/data.json` のレスポンスを配信する必要があります。

#### `dateBuild` {#datebuild}

**型** `string \| number` · **デフォルト** —

翻訳リクエストのキャッシュバスティング（`?v=...`）に使用する値。

指定しない場合、モジュールは翻訳ファイルのハッシュを使用するため、値は翻訳が変わったときに
のみ変わります（ハッシュを計算できない場合は `Date.now()`）。`0` または `''` でキャッシュバスティングを
無効にします。自分で固定するには安定した値（git SHA、ビルド番号）を設定してください。
`NUXT_I18N_DATE_BUILD` または `runtimeConfig.public.i18nRuntime.dateBuild` は、辞書がその場で置き換えられた後に、
実行時にこれを置き換えます：固定された URL は再ビルドなしで置き去りにされます。

#### `httpCacheDuration` {#httpcacheduration}

**型** `number` · **デフォルト** `31536000`

`/{apiBaseUrl}/:page/:locale/data.json` の HTTP `Cache-Control` の max-age（秒）。

`dateBuild` が URL をキャッシュバスティングしている間（`?v=...`、デフォルト）のみ完全に適用されます：
その場合レスポンスは `private, max-age=…, immutable` となり、ブラウザーはそれを固定しますが、クエリを無視する CDN は固定できません
（`httpCacheControl: false` の場合は `public`）。

- `dateBuild: 0`/`''` — URL が固定されるため、この期間は*尊重されず*、
  レスポンスは代わりに `public, max-age=0, must-revalidate` になります。変わらない URL に
  長い `max-age` を設定すると、ブラウザーが最初に見たペイロードが固定されてしまいます。

- `0` — `Cache-Control` をまったく設定しません（ローカルでのデバッグに便利）
- 開発時（`import.meta.dev`）には適用されないため、HMR がブラウザーキャッシュに妨げられることはありません
- Nitro を通じて配信されるレスポンスにのみ適用されます。`public/` にコピーされホスティングプラットフォームが
  配信するペイロードには、そのプラットフォームのヘッダーが適用されます — パフォーマンスガイドを参照してください。

`@nuxtjs/i18n` の実験的な `httpCacheDuration`（v10.2.0）に相当しますが、
Nitro `defineCachedEventHandler` の maxAge ではなく、明示的なレスポンスヘッダーとして提供されます。

#### `cacheMaxSize` {#cachemaxsize}

**型** `number` · **デフォルト** `0`

メモリ内の翻訳キャッシュの最大エントリー数。fetch キャッシュとサーバーキャッシュは
最も長く使われていないエントリーを破棄し、ブラウザーの辞書マップは最も古いものを破棄します（FIFO）。
`0` はブラウザーでは無制限を意味し、その場合サーバーキャッシュは最大 1000 エントリーを保持するため、
でっち上げのページ名を含むリクエスト URL でサーバーのメモリが増え続けることはありません。

#### `cacheTtl` {#cachettl}

**型** `number` · **デフォルト** `0`

fetch とサーバーの翻訳キャッシュの有効期間（秒）。エントリーが保存された時点から数えられ
（読み込みでは延長されません）、`apiBaseServerHost` からのデータは少なくともその頻度で
更新されます。ブラウザーのアクティブな辞書はこれによって期限切れになりません。`0` はエントリーが
期限切れにならないことを意味します。

両者が実行時に何を変えるか：[パフォーマンス](/ja/guide/performance)。

#### `serverTranslationPreload` {#servertranslationpreload}

**型** `boolean` · **デフォルト** `false`

Nitro のグローバルミドルウェアでインデックスページの翻訳をプリロードします（サーバー専用、プライベート設定）。

### SEO {#seo}

#### `meta` {#meta}

**型** `boolean` · **デフォルト** `true`

SEO メタタグ（`hreflang`、`canonical`、`og:url`、`og:locale`）を自動生成します。

ページごとの上書き：[`useI18nHead`](/ja/composables/useI18nHead)。その他すべて：[SEO](/ja/guide/seo)。

#### `metaBaseUrl` {#metabaseurl}

**型** `string` · **デフォルト** `undefined`

SEO メタタグ（canonical、og:url、hreflang）のベース URL。

- 具体的な URL 文字列（例：`'https://example.com'`）— そのまま使用されます（最優先）。
- `undefined` — `nuxt-site-config` モジュールがある場合はその `site.url` に、
  それ以外の場合は現在のリクエストのオリジン
  （サーバーでは `useRequestURL().origin`、クライアントでは `window.location.origin`）にフォールバックします。

#### `metaTrustForwardedHost` {#metatrustforwardedhost}

**型** `boolean` · **デフォルト** `true`

メタタグのベース URL を解決する際に `X-Forwarded-Host` ヘッダーを信頼します。
このヘッダーに実際のクライアント向けホスト名を設定するリバースプロキシ（nginx、Cloudflare、AWS ALB など）の
背後でアプリを実行する場合に有効にします。

`metaBaseUrl` も `site.url` も設定されていない場合にのみ読み込まれます。ヘッダーを上書きするプロキシを経由せずにアプリにアクセスできる場合は `false` に設定してください：そうしないと、クライアントが canonical URL のホストを選択できてしまいます。

#### `metaTrustForwardedProto` {#metatrustforwardedproto}

**型** `boolean` · **デフォルト** `true`

メタタグのプロトコルを解決する際に `X-Forwarded-Proto` ヘッダーを信頼します。
TLS を終端するプロキシの背後でアプリを実行する場合に有効にすると、
アプリ自体が HTTP で待ち受けていても canonical URL に `https://` が使われます。

適用範囲は `metaTrustForwardedHost` と同じです。

#### `trustForwardedHost` {#trustforwardedhost}

**型** `boolean` · **デフォルト** `false`

リクエストのドメイン（`locales[].baseUrl`）を `Host` ではなく `X-Forwarded-Host` から
選択します。そのヘッダーを上書きするプロキシの背後でのみ有効にしてください。

`metaTrustForwardedHost` とは別で、デフォルトは無効です：ここではヘッダーがタグのオリジンだけでなく、別のドメインのロケールを選択することになります。[レイヤーとドメイン](/ja/guide/layers#multiple-domains)を参照してください。

#### `hreflangBaseLanguage` {#hreflangbaselanguage}

**型** `boolean` · **デフォルト** `false`

各ロケールの `iso` から派生した、言語のみの `hreflang` も出力します
（例：`es-ES` → `es` も）。`locales` 内で最初の地域ロケールが、
その言語の言語のみのタグを担当します。ルーティング用の `code` は使用されず、`iso || code` のみが使われます。

#### `canonicalQueryWhitelist` {#canonicalquerywhitelist}

**型** `string[]` · **デフォルト** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

canonical と `og:url` メタタグで保持するクエリパラメーター名の一覧。
この一覧にないパラメーターは canonical URL から削除されます。

### 検出とリダイレクト {#detection-and-redirects}

これらのオプションが使われるルール：[ロケール検出](/ja/guide/locale-detection)。

#### `redirects` {#redirects}

**型** `boolean` · **デフォルト** `true`

自動的なロケールリダイレクトを有効にします（サーバープラグインとクライアントのルートミドルウェア）。
`true` の場合、プレフィックス戦略ではプレフィックスのない URL をローカライズされた形式にリダイレクトします。ロケールは、
アプリの状態、`autoDetectPath` が許可する範囲での Cookie または `Accept-Language`、それ以外の場合は
デフォルトから決まります。`no_prefix` では、検出によって URL が変わることはありません（カスタムパスについては `noPrefixRedirect` を参照）。

`false` の場合、クライアントのリダイレクトミドルウェアは登録されません。サーバープラグインは引き続き、無効なロケールの URL に対して 404 を返し、プレフィックス付きの URL に対して Cookie を書き込みます。

#### `autoDetectLanguage` {#autodetectlanguage}

**型** `boolean` · **デフォルト** `true`

`Accept-Language` HTTP ヘッダーからユーザーの優先言語を自動的に検出します。
`autoDetectPath` と組み合わせて、検出を行うタイミングを決定します。

#### `autoDetectPath` {#autodetectpath}

**型** `string` · **デフォルト** `'/'`

Cookie／Accept-Language の設定によるリダイレクトを実行できる場所（`redirects` が有効な場合）。

- `'/'` — `/` のみ（デフォルトロケールのディープリンクには引き続きアクセス可能。デフォルト）
- `'no_prefix'` — ロケールプレフィックスのないパスのみ
- `'*'` — 明示的なロケールプレフィックスの書き換えを含むすべてのパス
  （例：Cookie が `de` を優先する場合 `/fr/about` → `/de/about`）

- その他の文字列 — そのパス。末尾のスラッシュは無視されます（例：`'/welcome'`）

`prefix` では、許可されたパス以外のプレフィックスのない URL も、デフォルトロケールの
形式にリダイレクトされます（`/about` → `/en/about`）。`prefix_except_default` で
プレフィックス付きのデフォルトロケール（`/en`）はリダイレクトではなく 404 になります。

#### `localeCookie` {#localecookie}

**型** `string \| null` · **デフォルト** `null`

セッションをまたいでユーザーのロケール設定を保持するための Cookie 名。
`null` に設定すると Cookie による保持を無効にします。
`no_prefix` 戦略では、指定がなければ自動的に `'user-locale'` に設定されます。`i18n` 設定ブロックで
明示的に `null` を指定すると、その場合も無効のままになります。

Cookie がなくても `Accept-Language` によってリダイレクトは行われます。Cookie は訪問をまたいで選択を記憶します。

#### `noPrefixRedirect` {#noprefixredirect}

**型** `boolean` · **デフォルト** `false`

`no_prefix` 戦略用：デフォルトロケールがページにカスタムパスを持つ場合
（`localeRoutes` / `globalLocaleRoutes`）、ページの元のパスを訪問者のロケールのカスタム
パスへ、それがなければデフォルトロケールのカスタムパスへリダイレクトします（例：`/about` → `/about-us`）。
独自のカスタムパスを持たないロケールは元のパスのままです。動的
セグメントを含むページはリダイレクトされません。

### 登録と開発 {#registration-and-development}

#### `plugin` {#plugin}

**型** `boolean` · **デフォルト** `true`

`$t()`、`$tc()`、`$getLocale()`、
`$switchLocale()` などのランタイムヘルパーを提供するコア i18n プラグインを登録します。

#### `define` {#define}

**型** `boolean` · **デフォルト** `true`

実行時に `$defineI18nRoute()` を提供します。ビルドはいずれにしてもページ内の
`$defineI18nRoute()` の呼び出しを読み取ります。

#### `hooks` {#hooks}

**型** `boolean` · **デフォルト** `true`

読み込み時とナビゲーション時に `i18n:register` アプリフックを呼び出し、プラグインが翻訳を追加できるようにします。

[フック](/ja/api/events)を参照してください。

#### `components` {#components}

**型** `boolean` · **デフォルト** `true`

組み込みの i18n コンポーネント（`<i18n-link>`、`<i18n-switcher>`、`<i18n-t>`、`<i18n-group>`）を登録します。
自動的なコンポーネント登録を無効にするには `false` に設定します（例：それらを使用せず、
モジュールのフットプリントを減らしたい場合）。

#### `types` {#types}

**型** `boolean` · **デフォルト** `true`

デフォルトロケールファイルの翻訳キーに基づいて、`useI18n`、`$t` および関連ヘルパーの
TypeScript 型宣言を生成します。

[`@i18n-micro/types-generator`](/ja/integrations/types-generator) パッケージとは別のものです。

#### `hmr` {#hmr}

**型** `boolean` · **デフォルト** `true`

開発時に翻訳ファイルのホットモジュールリプレースメントを有効にします。
`true` の場合、JSON 翻訳ファイルの変更により、ページ全体を更新せずに
自動的に再読み込みされます。

#### `debug` {#debug}

**型** `boolean` · **デフォルト** `false`

ロケール検出、ルート生成、翻訳読み込みの詳細なデバッグログを有効にします。

#### `vueDevtools` {#vuedevtools}

**型** `boolean` · **デフォルト** `true`

開発時に Vue DevTools のインスペクターとタイムラインを登録します（ブラウザー拡張機能）。
Nuxt DevTools のカスタムタブとは別です。

#### `experimental` {#experimental}

**型** `Record<string, unknown>` · **デフォルト** —

実験的／不安定なオプションの入れ物。
内容はマイナーバージョン間で予告なく変更または削除される可能性があります。
