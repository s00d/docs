---
title: "ヘルパー"
description: "モジュールが注入するすべてのランタイムヘルパー(`$t`、`$tc`、`$localePath`、`$switchLocale` など)とそのシグネチャ。"
---

モジュールは Nuxt アプリにランタイムヘルパーを注入します: `$t`、`$tc`、`$localePath`、`$switchLocale` などです。このページでヘルパーのシグネチャと動作を確認できます。シグネチャと説明は `src/runtime/plugins/01.plugin.ts` の `PluginsInjections` および `NuxtAppOnlyInjections` インターフェースに由来します。

## アクセス方法 {#access}

| 場所 | 方法 |
| --- | --- |
| テンプレート | `{{ $t('title') }}` — すべてのヘルパー、`$` 付き |
| `<script setup>` | `const { t, localePath } = useI18n()` — `PluginsInjections` のすべてのヘルパー、`$` の有無どちらでも |
| プラグイン、ミドルウェア、`<script setup>` | `const { $t, $defineI18nRoute } = useNuxtApp()` — すべて、`$` 付きのみ |

`$defineI18nRoute` は `useNuxtApp()` でのみ型付けされています。[`useI18n`](/ja/composables/useI18n) を参照してください。

```vue
<script setup lang="ts">
const { t, localePath } = useI18n()
</script>

<template>
  <NuxtLink :to="localePath('/about')">{{ t('nav.about') }}</NuxtLink>
</template>
```

## ロケール {#locale}

### `$getLocale` {#$getlocale}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric) => string
```

アクティブなロケールのコード。ルートを渡すと、そのルートが属するロケールを読み取ります。

```ts
$getLocale() // 'de' on /de/about
```

### `$getLocaleName` {#$getlocalename}

```ts
() => string | null
```

設定にあるアクティブなロケールの `displayName`。ない場合は `null` を返します。

### `$getLocales` {#$getlocales}

```ts
() => Locale[]
```

設定されたすべてのロケールとそのメタデータ。

ロケールオブジェクトのカスタムプロパティは書いたとおりに返されます。`Locale` の[モジュール拡張](/ja/api/module-options#locales)で型を付けてください。

### `$defaultLocale` {#$defaultlocale}

```ts
() => string | undefined
```

設定されたデフォルトロケールのコード。

### `$getI18nConfig` {#$geti18nconfig}

```ts
() => ResolvedI18nConfig
```

ランタイムから見た、解決済みのモジュール設定。

この値には[ランタイムでの上書き](/ja/guide/runtime-overrides)(`defaultLocale`、`fallbackLocale`、無効化されたロケール)が含まれます。

```ts
const { strategy, localeCookie } = useNuxtApp().$getI18nConfig()
```

## 翻訳 {#translation}

### `$t` {#$t}

```ts
TranslationFn<CleanTranslation>
```

キーを翻訳し、`params` を埋め込みます。キーが存在しない場合は `defaultValue` を、
デフォルトが指定されていない場合はキーそのものを返します。

```ts
// { "welcome": "Welcome, {name}!" }
$t('welcome', { name: 'Ada' }) // 'Welcome, Ada!'
$t('missing.key', {}, 'Fallback') // 'Fallback'
```

ネストされたオブジェクトを指すキーは、文字列ではなくそのオブジェクトを返します。テンプレートでは `[object Object]` と表示されるため、末端のキーを使ってください。

### `$ts` {#$ts}

```ts
TranslationFn<string>
```

`$t` と同様ですが、常に文字列を返します。値は `toString()` を通るため、ネストされた
オブジェクトは `'[object Object]'` になります。キーは末端を指すようにしてください。

### `$_t` {#$_t}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<CleanTranslation>
```

`$t` を特定のルートにバインドし、現在のページ以外の翻訳に使います。たとえば、別のルートへの
リンクを描画するレイアウトなどです。

```ts
const route = useRoute()
const t = useNuxtApp().$_t(route)
t('page.title')
```

### `$_ts` {#$_ts}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<string>
```

`$ts` を特定のルートにバインドします。`$_t` を参照してください。

### `$tc` {#$tc}

```ts
(key: TranslationKey, params: number | Params, defaultValue?: string) => string
```

複数形を考慮して翻訳します。`params` はカウントそのもの、または `count` を含む
オブジェクトです。

形は `|` で区切ります。組み込みルールでは、0 以上の整数のカウント `n` は形 `n` を選び、最後の形を上限とします。負数、小数、または `NaN` のカウントは最後の形になります。`{count}` やその他のパラメーターは選ばれた形に埋め込まれます。

複数形がカウントに従わない言語では、テンプレートを `=0 ` で始めます。すると最初の形が 0 用になり、残りは [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) のカテゴリーに従って `zero, one, two, few, many, other` の順に割り当てられます:

```json
{
  "apples": "=0 no apples | one apple | {count} apples",
  "files": "=0 no files | {count} one | {count} few | {count} many"
}
```

```ts
$tc('apples', 0) // 'no apples'
$tc('apples', 1) // 'one apple'
$tc('apples', 7) // '7 apples'

// In `uk` (categories `one, few, many, other`) the forms after the zero form follow those categories:
$tc('files', 21) // '21 one'
$tc('files', 22) // '22 few'
$tc('files', 25) // '25 many'
$tc('files', 2.5) // '2.5 many': no form for `other`, so the last one
```

- `=0 ` は値の先頭にスペース付きで置かれた場合にのみ有効です。`$t` ではテキストとして表示されます。これは複数形のための記法です。
- 独自の形を持たないカテゴリーは最後の形になります。負数や小数のカウントも最後の形になります。
- どのロケールでも動作します。英語なら `=0 none | one | {count} many` のように書けます。
- カテゴリーはロケールの `iso`、なければコードから決まります。`Intl` が知らないコードはインデックスルールにフォールバックし、マーカーはそれでも取り除かれるため、結果が実行環境に依存することはありません。
- `<i18n-t :plural>` も同じルールに従います。カスタムの [`plural`](/ja/api/module-options#plural) や `customPluralRule` はマーカーを含む生の値を受け取り、自分で判断します。`plural` が `null` を返すと、処理はマーカーを尊重する組み込みルールに戻されます。

マーカーがない場合、テンプレートはインデックスルールのままですが、一通りにしか解釈できない例外が 1 つあります。プレースホルダーのない 0 の形の後にカテゴリーごとに 1 つずつ形が続き、複数のカウントが共有する形にはそれぞれ `{count}` が含まれる場合です(`uk` での `no files | {count} one | {count} few | {count} many`)。

独自のルールを使うには [`plural`](/ja/api/module-options#plural) を設定してください。

```ts
// { "apples": "no apples | one apple | {count} apples" }
$tc('apples', 0) // 'no apples'
$tc('apples', 10) // '10 apples'
$tc('cart', { count: 2, name: 'Ada' }) // count and params in one object
```

第 3 引数は params ではなく `defaultValue` です。

### `$has` {#$has}

```ts
(key: string) => boolean
```

キーがアクティブなロケールで解決されるかどうか。生のキーを表示する代わりに、任意の文言の
分岐に使います。`$t` と同様に、同じロケール内でのページ遷移中は、離れようとしているページの
キーも参照します。

```ts
if ($has('promo.banner')) show.value = true
```

## フォーマット {#formatting}

### `$tn` {#$tn}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

アクティブなロケールで `Intl.NumberFormat` を使って数値をフォーマットします。キーを指定すると、
設定にある名前付きフォーマットを選択します。

名前付きフォーマットは [`numberFormats`](/ja/api/module-options#numberformats) で定義します。

```ts
$tn(1234.5, { style: 'currency', currency: 'EUR' }) // '1.234,50 €' in de
$tn(1000, 'currency') // named format
$tn(1000, 'currency', 'de') // named format in another locale
```

### `$td` {#$td}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

アクティブなロケールで `Intl.DateTimeFormat` を使って日付をフォーマットします。キーを指定すると、
設定にある名前付きフォーマットを選択します。

名前付きフォーマットは [`datetimeFormats`](/ja/api/module-options#datetimeformats) で定義します。

```ts
$td(new Date(), { dateStyle: 'long' })
$td(post.createdAt, 'short')
```

### `$tdr` {#$tdr}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

`Intl.RelativeTimeFormat` を使って日付を相対時間("3 日前")としてフォーマットします。

```ts
$tdr(Date.now() - 5 * 60_000) // '5 minutes ago' in en
```

## 切り替えとリンク {#switching-and-links}

### `$switchLocale` {#$switchlocale}

```ts
(locale: string) => Promise<boolean>
```

現在のページの別ロケール版へ移動します。`no_prefix` とハッシュモードでは、移動する前に
そのロケールの翻訳を読み込みます。`no_prefix` ではルートがその場で置き換えられます(新しい
履歴エントリーは作成されません)。未知のロケールは無視されます。
呼び出しは非同期です。移動後にコードを実行するには `await` してください。そのロケールの辞書が
アクティブになれば `true` で、そうでなければ `false` で解決されます。後者はチャンクの読み込みに失敗した場合(現在の
辞書は維持されるので、再試行するにはもう一度呼び出します)か、より新しい切り替えが優先された場合です。

```ts
await $switchLocale('de')
```

### `$switchLocalePath` {#$switchlocalepath}

```ts
(locale: string) => string
```

移動せずに、現在のページの別ロケール版のパスを返します。

```vue
<NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
```

### `$switchLocaleRoute` {#$switchlocaleroute}

```ts
(locale: string) => RouteLocationRaw
```

移動せずに、現在のページの別ロケール版のルートオブジェクトを返します。独自の `baseUrl` を持つ
ロケールの場合は URL 文字列を返します。`trailingSlash` のもとでは、オブジェクトはそのルールに従った `path` と `fullPath` を持ち、
`query` と `hash` はそのまま保持され、`router.push` やリンクでもそれらが維持されます。

### `$switchRoute` {#$switchroute}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => Promise<void>
```

アクティブなロケールを維持したまま、または `toLocale` に切り替えて、別のルートへ移動します。
`$switchLocale` と同様に非同期です。

```ts
$switchRoute('/about') // active locale
$switchRoute({ name: 'about' }, 'de') // switch to de
```

### `$localePath` {#$localepath}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => string
```

指定したロケール、またはアクティブなロケールでパスを解決します。`http(s):`、`mailto:`、
`tel:` スキームを持つ文字列はそのまま返されます。ユーザー入力を未検証のままリンク先として渡さないでください。

文字列のパスは、それが表示するページとして解釈されるため、ロケールのカスタムパスも適用されます。

```ts
$localePath('/about') // '/about' in en, '/de/ueber-uns' in de with localeRoutes
$localePath({ name: 'about' }, 'fr') // '/fr/about'
```

### `$localeRoute` {#$localeroute}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => RouteLocationResolved
```

指定したロケール、またはアクティブなロケールでルートを解決します。プレーンなオブジェクトなので、状態に保持しても安全です。パラメーターに
エスケープが必要な場合、`path`、`fullPath`、`query`、`hash` を持ちますが `name` や `params` は持ちません。ルーターに
エンコード済みの URL を渡すのはパスです。別ドメインのロケールでは `path` と `fullPath` は絶対 URL になり、ルーターはそれを扱えません。
そのようなリンクは `<i18n-link>` または `$localePath` を使ってください。

### `$getRouteName` {#$getroutename}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric, locale?: string) => string
```

ロケールのプレフィックスを除いたルート名。翻訳のキーとなる名前です。

```ts
$getRouteName() // 'about' on /de/about
```

## ページ設定 {#page-config}

### `$defineI18nRoute` {#$definei18nroute}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

コンポーネント内から、ページごとのロケール設定と翻訳を登録します。
アクティブなロケールにマージされ、ロケールが変わると再適用されます。

ページの `<script setup>` 内で、常に `useNuxtApp()` から分割代入して呼び出してください。ビルドは呼び出しから `locales`、`localeRoutes`、`disableMeta` を読み取ります。ランタイムでは `locales` のみが意味を持ちます(インライン翻訳はアクティブなロケールについてマージされます)。詳しいルール: [ページ設定](/ja/guide/per-component-translations)。

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: { en: '/about', de: '/ueber-uns' },
})
</script>
```

### `$setI18nRouteParams` {#$seti18nrouteparams}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

現在のルートにロケールごとのパラメーターを設定し、動的セグメントを言語ごとに変えられるようにします。
SSR 中、head が描画される前に呼び出してください。

パラメーターは、別のパスへのナビゲーションが確定するとクリアされます。ルート名が変わらない `/news/1` から `/news/4` への移動も含みます。詳細: [ローカライズされたパス](/ja/guide/custom-locale-routes)。

```ts
$setI18nRouteParams({
  en: { slug: 'my-post' },
  de: { slug: 'mein-beitrag' },
})
```

## ランタイム翻訳 {#runtime-translations}

### `$mergeTranslations` {#$mergetranslations}

```ts
(newTranslations: Translations) => void
```

ランタイムでアクティブなロケールに翻訳をマージし、読み込み済みの内容を上書きします。

アクティブなロケールの現在のページチャンクにディープマージします。指定されていないキーは残ります。

```ts
$mergeTranslations({ banner: { title: 'Sale' } })
```

### `$setTranslation` {#$settranslation}

```ts
(key: string, value: unknown) => void
```

アクティブな辞書の `key` の値を置き換えます。これはマージではなく置き換えです。
既存の兄弟キーを残したい場合は `$mergeTranslations` を使ってください。

```ts
$setTranslation('banner', { title: 'Sale' }) // drops other keys under banner
$setTranslation('banner.title', 'Sale') // dotted path
```

### `$loadPageTranslations` {#$loadpagetranslations}

```ts
(locale: string, routeName: string, translations: Translations) => Promise<void>
```

ビルド時にキーが分からないコンテンツ向けに、ランタイムでページの翻訳を読み込みます。

メモリ上の `(locale, routeName)` チャンクにマージし、そのチャンクがアクティブなら画面が更新されます。ここではペイロードは取得されません。まだ読み込まれていないページでは翻訳は待機し、そのファイルが読み込まれると、その上に重ねて適用されます。

```ts
await $loadPageTranslations('en', 'about', { title: 'About us' })
```

### `$resolveTranslations` {#$resolvetranslations}

```ts
() => Translations
```

アクティブなロケールとルートについて現在メモリにあるすべての翻訳を、ツリーとして返します。
`$t()` が今この時点で解決できる内容の読み取り専用ビューです。

結果は読み取り専用として扱ってください。

### `$setMissingHandler` {#$setmissinghandler}

```ts
(handler: MissingHandler | null) => void
```

未解決のキーごとに呼び出されるコールバックを登録します。削除するには `null` を渡します。

ハンドラーは開発時の警告の代わりに実行されます。

```ts
$setMissingHandler((locale, key, routeName) => {
  console.error(`[i18n] missing ${key} in ${locale} (${routeName})`)
})
```

### `$clearCache` {#$clearcache}

```ts
() => void
```

キャッシュされたすべての翻訳チャンクを破棄し、現在のページの辞書を再読み込みします。新しい翻訳が
届くまで、ページは現在の翻訳を表示し続けます。開発時の HMR は、翻訳ファイルが変更される
たびにこれを呼び出します。

```ts
const { clearCache } = useI18n()
clearCache()
```

再読み込みに失敗した場合、現在の辞書が維持されます。
