# 🛠️ メソッド

このページでは、nuxt-i18n-micro が提供するすべての利用可能なメソッドをドキュメント化しています。メソッドはナビゲーションしやすいよう機能ごとにまとめられています。

## 📊 API 概要

プラグインが注入するすべてのヘルパーは `PluginsInjections` インターフェースから読み取られます。したがって、このリストは実際に利用可能なものと乖離することはありません。

## 🔍 翻訳メソッド

翻訳を取得・管理するためのコアメソッドです。

### `$t`

{/* generated:method:$t — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params?: Params, defaultValue?: string | null) => CleanTranslation
```

キーを翻訳し、`params` を補間します。キーが見つからないときは `defaultValue` を返し、デフォルト値が指定されていない場合はキー自身を返します。

{/* /generated:method:$t */}

```typescript
const welcomeMessage = $t('welcome', { username: 'Alice', unreadCount: 5 })
// 出力: "Welcome, Alice! You have 5 unread messages."
```

<Warning>
`$t` は `CleanTranslation`(`string | number | boolean | Translations | PluralTranslations | null`)を返します。キーが JSON 内の**ネストされたオブジェクト**を指している場合(例: JSON が `\{ "header": \{ "title": "Hi" \} \}` のときの `$t('header')`)、戻り値は文字列ではなくその**オブジェクト**になります。Vue テンプレート内で直接使う(<code v-pre>\{\{ $t('header') \}\}</code>)と `[object Object]` としてレンダリングされます。

**回避方法:**

- より具体的なキーを使う: `$t('header.title')` → `"Hi"`
- 常に文字列を返す `$ts()` を使う(非文字列に対して `.toString()` を呼び出します)
- プログラム用途でサブオブジェクトに意図的にアクセスする場合にネストキーで `$t` を使う
</Warning>

### `$ts`

{/* generated:method:$ts — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params?: Params, defaultValue?: string) => string
```

`$t` と同様ですが、常に文字列を返します。オブジェクトや配列の値はそのままではなく、文字列化されます。

{/* /generated:method:$ts */}

```typescript
const welcomeMessage = $ts('welcome', { username: 'Alice', unreadCount: 5 })
// 出力: "Welcome, Alice! You have 5 unread messages."
```

### `$_t` および `$_ts`

{/* generated:method:$_t — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNormalizedLoaded) => (key: string, params?: Params, defaultValue?: string | null) => CleanTranslation
```

`$t` を特定のルートにバインドします。現在のページの外(たとえば別のルートへのリンクをレンダリングするレイアウトなど)を翻訳する場合に使用します。

{/* /generated:method:$_t */}

{/* generated:method:$_ts — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNormalizedLoaded) => (key: string, params?: Params, defaultValue?: string | null) => string
```

`$ts` を特定のルートにバインドします。`$_t` を参照してください。

{/* /generated:method:$_ts */}

`$t` と `$ts` のルートバインド版です。最初に**ルート**を受け取り、そのルートのロケール/ページコンテキストに固定された翻訳関数を返します。

- **アクセス**: `useNuxtApp()`(`useI18n()` からも `$_t` / `$_ts` として再エクスポートされます)

SSR や遷移中のアクティブルートが `router.currentRoute` と異なる場合(たとえば `<i18n-t>`、`<i18n-group>` の内部や、特定の `route` オブジェクトに対してコンテンツをレンダリングする場合など)に使用します。

```typescript
import { useRoute, useNuxtApp } from '#imports'

const route = useRoute()
const { $_t, $_ts } = useNuxtApp()

const $t = $_t(route)
const title = $t('page.title')

// 文字列安全な変形
const label = $_ts(route)('page.label')
```


### `$tc`

{/* generated:method:$tc — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params: number | Params, defaultValue?: string) => string
```

複数形を含む翻訳を行います。`params` はカウント自体、または `count` を含むオブジェクトです。

{/* /generated:method:$tc */}

**翻訳フォーマット**: フォームを `|` で区切ります。**各フォーム**にプレースホルダーを配置します。

```json
{
  "apples": "no apples | one apple | {count} apples",
  "cart": "no items for {name} | one item for {name} | {count} items for {name}"
}
```

```typescript
$tc('apples', 0) // "no apples"
$tc('apples', 1) // "one apple"
$tc('apples', 10) // "10 apples"

// count + その他のパラメーター(第 2 引数はオブジェクトである必要があります)
$tc('cart', { count: 10, name: 'Alice' }) // "10 items for Alice"
```


**コンポーネントによる代替** — `<i18n-t keypath="cart" :plural="count" :params="\{ name \}" />`(内部的に `count` と `params` をマージします)。


### `$mergeTranslations`

{/* generated:method:$mergeTranslations — do not edit; run `pnpm run docs:generate` */}

```ts
(newTranslations: Translations) => void
```

ランタイムでアクティブロケールに翻訳をマージし、読み込み済みの内容を上書きします。

{/* /generated:method:$mergeTranslations */}

```typescript
$mergeTranslations({
  welcome: 'Bienvenue, {username}!',
})
// 出力: 翻訳キャッシュを新しいフランス語翻訳で更新
```

### `$resolveTranslations`

{/* generated:method:$resolveTranslations — do not edit; run `pnpm run docs:generate` */}

```ts
() => Translations
```

アクティブなロケールとルートについて、現在メモリ上にあるすべての翻訳をツリー形式で返します。`$t()` が今解決できるものを読み取り専用で参照するためのビューです。

{/* /generated:method:$resolveTranslations */}

```typescript
const tree = $resolveTranslations()
// { aaa: { bbb: 'ccc' }, ddd: 1111 } — $t() が読み取るのと同じ辞書
```

インメモリ辞書全体が必要な場合(DevTools、テスト、ランタイムエディターなど)に使用します。戻り値は読み取り専用として扱い、値の変更は `$setTranslation` や `$mergeTranslations` を通じて行ってください。

### `$setTranslation`

{/* generated:method:$setTranslation — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, value: unknown) => void
```

アクティブな辞書の `key` の値を置き換えます。これはマージではなく置換です。既存の兄弟要素を保持したい場合は `$mergeTranslations` を使用してください。

{/* /generated:method:$setTranslation */}

```typescript
$setTranslation('aaa', { fff: 'ggg' }) // `aaa` のサブツリー全体を置換
$setTranslation('aaa', 'text')          // `aaa` を文字列で置換
$setTranslation('ddd', 1111)            // トップレベルのスカラー
$setTranslation('aaa.bbb', 'nested')    // ドット区切りのパス
```

これはマージではなく**置換**です。同じキー配下の既存の兄弟要素は削除されます。兄弟要素を失わずにパッチしたい場合は `$mergeTranslations` を使用してください。

### `$setMissingHandler`

{/* generated:method:$setMissingHandler — do not edit; run `pnpm run docs:generate` */}

```ts
(handler: MissingHandler | null) => void
```

未解決のキーごとに呼び出されるコールバックを設定します。削除するには `null` を渡してください。

{/* /generated:method:$setMissingHandler */}

**型定義**:

```typescript
type MissingHandler = (locale: string, key: string, routeName: string, instance?: unknown, type?: string) => void
```

```typescript
// カスタムハンドラーを設定
$setMissingHandler((locale, key, routeName) => {
  console.error(`Missing translation: ${key} in ${locale} for route ${routeName}`)
  // Sentry や他のエラートラッキングサービスに送信
  // Sentry.captureMessage(`Missing translation: ${key}`)
})

// ハンドラーを削除
$setMissingHandler(null)
```

**ユースケース**:

- エラートラッキングサービス(Sentry、LogRocket など)に欠落翻訳をログとして送信する
- 欠落翻訳に関する分析を収集する
- 欠落翻訳キーに対するカスタムエラー処理

## 🔢 数値と日付のフォーマット

ロケールの慣例に従って数値と日付をフォーマットするメソッドです。

### `$tn`

{/* generated:method:$tn — do not edit; run `pnpm run docs:generate` */}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

アクティブなロケールで `Intl.NumberFormat` を用いて数値をフォーマットします。キーを指定すると設定から名前付きフォーマットを選択します。

{/* /generated:method:$tn */}

```typescript
// インラインオプション
const formattedNumber = $tn(1234567.89, { style: 'currency', currency: 'USD' })
// "$1,234,567.89"

// 名前付きフォーマット(nuxt.config の i18n.numberFormats から)
const price = $tn(1000, 'currency')
const priceDe = $tn(1000, 'currency', 'de')
const compact = $tn(1000, 'currency', { notation: 'compact' })
```

未知の名前付きフォーマットキーは、デフォルトの `Intl.NumberFormat` オプションにフォールバックします。開発時(クライアント)には、`missingWarn` が有効(デフォルト)な場合、`console.warn` が出力されます。

**設定例**:

```ts
export default defineNuxtConfig({
  i18n: {
    numberFormats: {
      en: {
        currency: { style: 'currency', currency: 'USD' },
        decimal: { style: 'decimal', minimumFractionDigits: 2, maximumFractionDigits: 2 },
      },
      de: {
        currency: { style: 'currency', currency: 'EUR' },
      },
    },
  },
})
```

**ユースケース**:

- 適切なロケール形式で通貨、パーセンテージ、小数として数値をフォーマットする
- アプリ全体で名前付きフォーマットを再利用する(Vue I18n 移行との互換性)

### `$td`

{/* generated:method:$td — do not edit; run `pnpm run docs:generate` */}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

アクティブなロケールで `Intl.DateTimeFormat` を用いて日付をフォーマットします。キーを指定すると設定から名前付きフォーマットを選択します。

{/* /generated:method:$td */}

```typescript
const formattedDate = $td(new Date(), { weekday: 'long', year: 'numeric', month: 'long', day: 'numeric' })
// "Friday, September 1, 2023"

const short = $td(new Date(), 'short')
const longDe = $td(new Date(), 'long', 'de')
```

未知の名前付きフォーマットキーは、デフォルトの `Intl.DateTimeFormat` オプションにフォールバックします。開発時(クライアント)には、`missingWarn` が有効(デフォルト)な場合、`console.warn` が出力されます。

**設定例**:

```ts
export default defineNuxtConfig({
  i18n: {
    datetimeFormats: {
      en: {
        short: { year: 'numeric', month: 'short', day: 'numeric' },
        long: { year: 'numeric', month: 'long', day: 'numeric', weekday: 'long' },
      },
    },
  },
})
```

**ユースケース**:

- ユーザーのロケールに合わせた形式で日付を表示する
- アプリ全体で short/long/date-time のプリセットを共有する

### `$tdr`

{/* generated:method:$tdr — do not edit; run `pnpm run docs:generate` */}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

`Intl.RelativeTimeFormat` を使って日付を相対時間(「3 日前」など)としてフォーマットします。

{/* /generated:method:$tdr */}

```typescript
const relativeDate = $tdr(new Date(Date.now() - 1000 * 60 * 5))
// 出力: 'en-US' ロケールで "5 minutes ago"
```

遷移せずに、別のロケールでの現在のページのパスを返します。

```typescript
// 出力: 新しいロケールが適用された URL。例: '/fr/nouvelles'
```

## 🚦 ルート設定

ルート動作とアクセス制御を設定するためのメソッドです。

### `$defineI18nRoute`

{/* generated:method:$defineI18nRoute — do not edit; run `pnpm run docs:generate` */}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

コンポーネント内からページ単位のロケール設定と翻訳を登録します。アクティブなロケールにマージされ、ロケール変更時に再適用されます。

{/* /generated:method:$defineI18nRoute */}

> [!IMPORTANT]
> `$defineI18nRoute` は **define プラグイン**によって提供され、`useNuxtApp()` でのみ利用可能です。`useI18n()` の戻りオブジェクトには**含まれません**。
> `script setup` 内では常に `useNuxtApp()` から分割代入で取得してください。裸のグローバルとして `$defineI18nRoute(...)` を呼び出すと、SSR/プリレンダー中に `"$defineI18nRoute is not defined"` がスローされます。

**パラメーター**:

- **locales**: `string[] | Record<string, Record<string, string>>` — このルートで利用可能なロケール
- **localeRoutes**: `Record<string, string>` — オプション。特定のロケールに対するカスタムルート
- **disableMeta**: `boolean | string[]` — オプション。すべてまたは特定のロケールについて i18n メタタグを無効化

**基本的な例**:

```typescript
import { useNuxtApp } from '#imports'

const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'fr', 'de'],
  localeRoutes: {
    en: '/welcome',
    fr: '/bienvenue',
    de: '/willkommen',
  },
  disableMeta: false,
})
```

> 📖 **詳細な使用例、設定フォーマット、ベストプラクティスについては、[コンポーネント単位の翻訳ガイド](/guides/per-component-translations) を参照してください。**

### `$setI18nRouteParams`

{/* generated:method:$setI18nRouteParams — do not edit; run `pnpm run docs:generate` */}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

現在のルートに対してロケールごとのパラメーターを設定し、動的セグメントを言語ごとに変えられるようにします。SSR 中、head がレンダリングされる前に呼び出してください。

{/* /generated:method:$setI18nRouteParams */}

```typescript
// pages/news/[id].vue 内
// en/news/1-first-article 用
const { $switchLocaleRoute, $setI18nRouteParams, $defineI18nRoute } = useNuxtApp()
$defineI18nRoute({
  localeRoutes: {
    en: '/news/:id()',
    fr: '/nouvelles/:id()',
    de: '/Nachricht/:id()',
  },
})
const { data: news } = await useAsyncData(`news-${params.id}`, async () => {
  let response = await $fetch("/api/getNews", {
    query: {
      id: params.id,
    },
  });
  if (response?.localeSlugs) {
    response.localeSlugs = {
      en: {
        id: '1-first-article'
      }
      fr: {
        id: '1-premier-article'
      }
      de: {
        id: '1-erster-Artikel'
      }
    }
    $setI18nRouteParams(response?.localeSlugs);
  }
  return response;
});
$switchLocalePath('fr') // === 'fr/nouvelles/1-premier-article'
$switchLocalePath('de') // === 'de/Nachricht/1-erster-Artikel'
```

## 🧭 `useI18nLocale` コンポーザブル

ロケール状態を集中管理するためのコンポーザブルです。`useState('i18n-locale')` や `useCookie('user-locale')` を直接操作する代わりに、これを使用してください。

```typescript
const {
  setLocale, // (locale: string) => void — state と cookie を更新
  getLocale, // () => string | null — state または cookie から取得
  getPreferredLocale, // () => string | null — locales リストと照合済み
  getEffectiveLocale, // (route, getLocaleFromRoute) => string
  resolveInitialLocale, // (options) => string
  isValidLocale, // (locale) => boolean
  locale, // Ref<string | null> — リアクティブな状態
  localeCookie, // CookieRef — リアクティブな cookie
  syncLocale, // (locale) => void — cookie のみ同期
  validLocales, // string[] — 有効なロケールコードのリスト
} = useI18nLocale()
```

### 主なメソッド

| メソッド                  | 説明                                                 |
| ----------------------- | ----------------------------------------------------------- |
| `setLocale(locale)`     | `useState` と cookie の両方にロケールをアトミックに設定します。        |
| `getLocale()`           | state または cookie から現在のロケールを返します。                 |
| `getPreferredLocale()`  | `locales` リストで検証済みのロケール、または `null` を返します。  |
| `isValidLocale(locale)` | ロケールコードが設定された `locales` リストにあるかを確認します。 |

### カスタムプラグインでの使用

```typescript
// plugins/i18n-loader.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,
  setup() {
    const { setLocale } = useI18nLocale()
    // ヘッダーやドメインなどからロケールを検出
    setLocale('de')
  },
})
```

詳しい例は [カスタム言語検出](/guides/custom-language-detection) を参照してください。
