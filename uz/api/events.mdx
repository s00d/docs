Modul bitta runtime (ilova) hookini chaqiradi — `i18n:register`. Undan plagin yoki modul sizning `locales/` fayllaringizda bo'lmagan tarjimalarni qo'shganda foydalaning. Callback funksiyangiz `register` funksiyasini oladi, u tarjimalarni ko'rsatilayotgan sahifaga birlashtiradi.

## `i18n:register` {#i18nregister}

```ts
'i18n:register': (
  register: (translations: unknown, locale?: string) => void,
  locale: string,
) => HookResult
```

| Argument | Tavsif |
| --- | --- |
| `register(translations, locale?)` | `translations` ni yuklanayotgan marshrutning sahifa bo'lagiga `locale` uchun (standart: hookning `locale` qiymati) chuqur birlashtiradi. Mavjud kalitlar qayta yoziladi. |
| `locale` | Yuklanayotgan marshrutning lokali. |

Hook `RuntimeNuxtHooks` orqali tiplangan, shuning uchun `nuxtApp.hook('i18n:register', …)` tip o'zgartirishni talab qilmaydi.

## Qachon ishga tushadi {#when-it-fires}

Uni yuklovchi plagin (`i18n-plugin-loader`) chaqiradi:

1. ishga tushishda bir marta, barcha plaginlar ishlab bo'lgach (`app:created`) va ilova render qilinishidan oldin;
2. o'zining `router.beforeEach` ichida, maqsadli sahifa tarjimalari yuklangandan so'ng, yo'l o'zgarganda — `no_prefix` rejimida har bir navigatsiyada.

Har bir callback va har bir `register` chaqiruvi ilova render qilinishidan yoki navigatsiya davom etishidan oldin kutiladi, shuning uchun sahifa birlashtirilgan kalitlar bilan render qilinadi. [`hooks: false`](/uz/api/module-options#hooks) bilan hook hech qachon chaqirilmaydi.

## Misol {#example}

```ts
// plugins/i18n-extra.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('i18n:register', async (register, locale) => {
    const extra = await $fetch<Record<string, unknown>>(`/api/cms-strings/${locale}`)
    register(extra, locale)
  })
})
```

Bu runtime hooki: uni plagin ichida `nuxtApp.hook` bilan ro'yxatdan o'tkazing, `nuxt.config` yoki modulning `setup` qismida `nuxt.hook` bilan emas. Modul bunday plaginni `addPlugin` orqali qo'shadi.
