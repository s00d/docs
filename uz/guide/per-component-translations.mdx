`$defineI18nRoute` bitta sahifa uchun i18n sozlamalarini sahifaning o'zidan o'rnatadi. Undan sahifa faqat ba'zi lokallarda mavjud bo'lganda, o'zining lokallashtirilgan yo'li kerak bo'lganda, o'zining bir nechta tarjimalarini o'z ichiga olganda yoki hreflang/canonical teglarini olmasligi kerak bo'lganda foydalaning. Modul chaqiruvni build vaqtida o'qiydi va uni generatsiya qilinadigan marshrutlarga joylaydi.

## Sahifani ba'zi lokallar bilan cheklash {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

Standart `prefix_except_default` strategiyasida faqat `/product` va `/de/product` generatsiya qilinadi; sahifaning boshqa hech qaysi lokalda marshruti yo'q. Xuddi shuni `nuxt.config.ts` dan [`routeLocales`](/uz/api/module-options#routelocales) bilan o'rnatish mumkin.

`$defineI18nRoute` — bu Nuxt ilovasi injeksiyasi, kompilyator makrosi emas: uni har doim `useNuxtApp()` dan oling va `$` bilan chaqiring. Build bosqichi faqat `$defineI18nRoute(` ni taniydi.

## Ichki tarjimalar qo'shish {#add-inline-translations}

Massiv o'rniga obyekt bering. Uning kalitlari ruxsat etilgan lokallar, qiymatlari esa faol lokal uchun sahifa lug'atiga birlashtiriladi.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Ichki tarjimalar har bir lokal uchun sahifa komponenti ichida yetkaziladi. Bir nechta kalitdan kattaroq narsa uchun [sahifa tarjima fayllari](/uz/guide/translations)ni afzal ko'ring; ichki kalitlarni mustaqil sahifa va komponentlar uchun qoldiring.

## Lokallashtirilgan yo'llarni o'rnatish {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

`prefix_except_default` va `defaultLocale: 'en'` bilan bu `/welcome` va `/de/willkommen` ni hosil qiladi. Ichki lokal obyekti ichidagi `path` ham xuddi shunday ishlaydi: `locales: { de: { path: '/willkommen' } }`. Dinamik parametrlar, ichma-ich marshrutlar va konfiguratsiya darajasidagi muqobil [Lokallashtirilgan yo'llar](/uz/guide/custom-locale-routes) sahifasida yoritilgan.

## SEO teglarini o'chirish {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

Konfiguratsiya darajasidagi muqobil — [`routeDisableMeta`](/uz/api/module-options#routedisablemeta). Teglar nima ekanligi [SEO](/uz/guide/seo) sahifasida yozilgan.

## Build nimani o'qiy oladi {#what-the-build-can-read}

Build bosqichi har bir sahifa faylidagi chaqiruvni topadi va uning argumentini ilovangizni ishga tushirmasdan hisoblaydi. Bu konfiguratsiya quyidagicha bo'lganda ishlaydi:

- literal obyekt (satrlar, massivlar, ichma-ich obyektlar, template literallar, `process.env.NODE_ENV` bo'yicha ternarlar);
- o'sha `<script setup>` da e'lon qilingan konstantalardan tuzilgan (`const locales = ['en', 'de']`, spreadlar ham kiradi);
- `code` maydoniga ega obyektlar massivi (`[{ code: 'en' }, { code: 'de' }]`).

U boshqa moduldan import qilingan qiymatlarni yoki runtime'da ilovangizni talab qiladigan narsalarni (composable'lar, `await`, olib kelingan ma'lumotlar) o'qiy olmaydi. Bunday holda build `Ignored the $defineI18nRoute() config in <file>` ni log qiladi va sahifa standart lokallar va marshrutlarni saqlaydi.

Runtime'da chaqiruv faqat joriy lokal uchun ichki tarjimalarni birlashtiradi va lokal o'zgarganda ularni qayta birlashtiradi. `locales`, `localeRoutes` va `disableMeta` faqat build orqali kuchga kiradi, shuning uchun ularni o'zgartirish qayta build qilishni talab qiladi (dev server saqlashda qayta build qiladi).
