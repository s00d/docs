`server/api/` va `server/routes/` dagi server handler'lari ikkita avtomatik import qilinadigan yordamchi orqali satrlarni tarjima qilishi va so'rov lokalini o'qishi mumkin. Ulardan API javoblari, elektron xatlar, feed'lar yoki Vue sahifasidan tashqarida render qilinadigan har qanday narsa uchun foydalaning. Ular sahifalaringiz bilan bir xil tarjima fayllarini o'qiydi va lokalni so'rovdan aniqlaydi.

## Handler'da tarjima qilish {#translate-in-a-handler}

```ts
// server/api/greeting.get.ts
export default defineEventHandler(async (event) => {
  const t = await useTranslationServerMiddleware(event)
  return { message: t('greeting', { name: 'Ada' }) }
})
```

```bash
curl 'http://localhost:3000/api/greeting?locale=de'
# {"message":"Hallo, Ada!"}
```

`useTranslationServerMiddleware(event, defaultLocale?, locale?)` asinxron bo'lib, `t(key, params?, defaultValue?)` ni qaytaradi. `t` satrni qaytaradi, `{name}` parametrlarini interpolyatsiya qiladi, kalit mavjud bo'lmaganda esa bo'sh bo'lmagan `defaultValue` ni, aks holda kalitning o'zini qaytaradi.

`t` faqat `index` bo'lagini ko'radi: ildiz fayllari (`locales/<locale>.json`) hamda mavjud bo'lsa `locales/pages/index/` (`disablePageLocales` bilan faqat ildiz fayllari). Boshqa sahifalarning kalitlari yuklanmaydi. Ular uchun bo'lakni o'zingiz yuklang:

```ts
const { data } = await loadTranslationsFromServer('de', 'about') // Translations object of the about page
```

## So'rov lokalini o'qish {#read-the-request-locale}

```ts
// server/api/locale.get.ts
export default defineEventHandler((event) => {
  const { current, isDefault, locale } = useLocaleServerMiddleware(event)
  return { current, isDefault, dir: locale?.dir ?? 'ltr' }
})
```

`useLocaleServerMiddleware(event, defaultLocale?, locale?)` sinxron bo'lib, quyidagini qaytaradi:

```ts
interface LocaleInfo {
  current: string // detected locale code
  default: string // defaultLocale, runtime overrides included (fixed at build under prefix_except_default / prefix_and_default)
  fallback: string // fallbackLocale, else the default
  available: string[] // enabled locale codes
  locale: Locale | null // the config entry of `current`
  isDefault: boolean
  isFallback: boolean
}
```

## Lokal qanday tanlanadi {#how-the-locale-is-chosen}

Ikkala yordamchi ham har bir server route'ida, `/api` bo'ladimi yoki yo'qmi, bir xil tartibdan foydalanadi:

1. `?locale=` query (takrorlanganda birinchi qiymat);
2. `[locale]` route parametri yoki yo'ldagi lokal prefiksi (`/de/...`);
3. [`localeCookie`](/uz/api/module-options#localecookie) o'rnatilganda lokal cookie'si (`hashMode` ostida `hash-locale`);
4. `autoDetectLanguage` yoqilganda `Accept-Language` (q-qiymatlar hisobga olinadi);
5. `defaultLocale`.

Noto'g'ri va o'chirilgan kodlar har bir bosqichda o'tkazib yuboriladi. Bu API tartibi; sahifa renderi prefiks strategiyalari ostida `?locale=` ni e'tiborsiz qoldiradi. Ikkala tartib [Lokalni aniqlash](/uz/guide/locale-detection) sahifasida taqqoslangan.

## Lokalni majburlash {#force-a-locale}

Aniqlashni o'tkazib yuborish uchun uchinchi argumentni uzating, masalan, foydalanuvchi tilida xat yuboradigan vazifada:

```ts
export default defineEventHandler(async (event) => {
  const user = await getUser(event) // your code
  const t = await useTranslationServerMiddleware(event, undefined, user.locale)
  return sendMail(user.email, t('mail.welcome.subject'))
})
```

Ikkinchi argument ushbu chaqiruvning aniqlash jarayoni uchun `defaultLocale` ni almashtiradi, shuning uchun lokal majburlanganda uning ta'siri yo'q. Lug'atlar har bir so'rov va har bir lokal uchun, so'rovlar orasida esa serverning tarjima keshida keshlanadi, shuning uchun yordamchini bir necha marta chaqirish arzon.

## Server komponentlari {#server-components}

Server komponenti (`.server.vue`, `<NuxtIsland>`) o'zining `/__nuxt_island/...` URL'idan render qilinadi, shuning uchun u sahifa URL'ini ko'rmaydi va Nuxt unga faqat uning prop'larini uzatadi. Lokalni `locale` prop'i sifatida uzating. Shunda u o'sha lokalda render qilinadi va almashtirish uni qayta yuklaydi, chunki prop'lar island URL'i va kesh kalitining bir qismi. Bu nom band qilingan: `locale` deb nomlangan prop'dagi har qanday yoqilgan lokal kodi render lokalini o'rnatadi, shuning uchun boshqa ma'noni bildiradigan prop'ga, masalan, son formatiga, boshqa nom bering:

```vue
<!-- components/Greeting.server.vue -->
<template><p>{{ $t('greeting') }}</p></template>
<script setup lang="ts">
defineProps<{ locale?: string }>()
</script>
```

```vue
<template>
  <Greeting :locale="$getLocale()" />
  <NuxtIsland name="Greeting" :props="{ locale: $getLocale() }" />
</template>
```

Prop bo'lmasa, URL nima deyishidan qat'i nazar, u cookie lokalida, u bo'lmasa sukut bo'yicha lokalda render qilinadi va almashtirishga ergashmaydi. Uning `$t` si `index` bo'lagini ko'radi: ildiz fayllari hamda `locales/pages/index/`.
