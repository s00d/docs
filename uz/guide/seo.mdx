`meta: true` (sukut bo'yicha) bilan har bir lokallashtirilgan sahifa `<html lang dir>`, canonical havola, `hreflang` muqobillari, `x-default` va Open Graph lokal teglarini oladi. Bu sahifa sizga ommaviy origin'ni o'rnatmoqchi bo'lganingizda, teglarda qaysi lokallar paydo bo'lishini sozlamoqchi bo'lganingizda yoki ularni bitta sahifa uchun qayta belgilamoqchi bo'lganingizda kerak bo'ladi. Ko'pchilik saytlarga faqat `site.url` yoki `metaBaseUrl` va to'g'ri `iso` kodlari kerak.

## Minimal sozlash {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

Shunda `/de/about` quyidagicha render qilinadi:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Matn yo'nalishi {#text-direction}

`<html dir>` lokalning `dir` qiymatidan olinadi. U bo'lmasa, o'ngdan chapga yoziladigan til `iso` (yoki `code`) dan o'qilgan holda `rtl` ni oladi: arab, ibroniy, fors, urdu va yana bir nechta til, shuningdek `az-Arab` kabi RTL yozuvli har qanday teg. Boshqa barcha lokallar `dir` atributini olmaydi, brauzerlar buni `ltr` deb o'qiydi.

<Warning>

**`dir: 'auto'` katta sahifalarda tahlil vaqtini oshiradi** — `<html>` dagi `auto` brauzerni tahlil qilish paytida yo'nalishni kontentdan aniqlashga majbur qiladi. Chromium'da bu xarajat sahifadan tezroq o'sadi: 5000 elementda taxminan 100 ms va 20000 elementda 1 s. Undan faqat tilini bilish imkoni bo'lmagan kichik sahifa uchun foydalaning.

</Warning>

## Qaysi teglarni olasiz {#which-tags-you-get}

- **hreflang**: sahifani taqdim etadigan har bir lokal uchun bitta teg, qiymati `iso` (yoki `iso` yo'q bo'lsa `code`), URL'i canonical bilan bir xil query'ga ega. [Sahifa konfiguratsiyasi](/uz/guide/per-component-translations) yoki `routeLocales` bilan cheklangan sahifa faqat o'z lokallarini ro'yxatga oladi. [`hreflangBaseLanguage: true`](/uz/api/module-options#hreflangbaselanguage) birinchi mintaqaviy lokal uchun sof tilni (`es-ES` → `es`) ham qo'shadi.
- **x-default**: sukut bo'yicha lokalning URL'i, faqat sukut bo'yicha lokal sahifani taqdim etganda.
- **og:locale**: `iso` dan olinadi (`en-US` → `en_US`). Moslash to'g'ridan-to'g'ri bo'lmaganda lokalda `og` ni o'rnating, masalan, `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; ikkalasi ham bo'lmasa, `og:locale` yozilmaydi va dev rejimi ogohlantiradi.
- **canonical / og:url**: query parametrlarisiz joriy URL, [`canonicalQueryWhitelist`](/uz/api/module-options#canonicalquerywhitelist) dagilar bundan mustasno (sukut bo'yicha `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Strategiya bo'yicha:

| Strategiya | hreflang va x-default | canonical, og:url, og:locale, html atributlari |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | ha | ha |
| `no_prefix` | yo'q (bitta URL barcha lokallarni taqdim etadi) | ha |

## Ommaviy origin'ni o'rnatish {#set-the-public-origin}

Absolyut URL'lar quyidagilardan birinchisini ishlatadi:

1. [`metaBaseUrl`](/uz/api/module-options#metabaseurl);
2. `nuxt-site-config` dagi `site.url` (`@nuxtjs/seo` tomonidan o'rnatiladi);
3. `app.baseURL` qo'shilgan so'rov origin'i.

Dastlabki ikkitasidan birini qat'iy belgilang.

<Warning>

So'rov origin'iga asoslangan zaxira variant `X-Forwarded-Host` va `X-Forwarded-Proto` ni o'qiydi, chunki [`metaTrustForwardedHost`](/uz/api/module-options#metatrustforwardedhost) va `metaTrustForwardedProto` sukut bo'yicha `true`. Bu faqat ushbu sarlavhalarni qayta yozadigan proksi ortida xavfsiz; aks holda mijoz canonical havolalaringizdagi hostni tanlashi mumkin va kesh bu sahifani boshqalarga uzatishi mumkin.

Agar ilovaga to'g'ridan-to'g'ri kirish mumkin bo'lsa, `metaBaseUrl` ni qat'iy belgilang: ikkala parametrni `false` ga o'rnatishdan farqli o'laroq, u soxta `Host` ni ham e'tiborsiz qoldiradi. [Proksi yoki CDN ortida](/uz/guide/deployment#behind-a-proxy-or-cdn) sahifasiga qarang.

</Warning>

Zaxira variant bir nechta domenga javob beradigan bitta deploy uchun foydali: `https://site-a.com/en/about` va `https://site-b.com/en/about` har biri o'z origin'ini oladi.

Lokallarda `baseUrl` bo'lganda, ma'lum host `metaBaseUrl` va `site.url` dan ustun ravishda o'zining `baseUrl` qiymatidan foydalanadi, shuning uchun canonical va `og:url` shu domenda qoladi va `hreflang` har bir lokalni o'z domeniga yo'naltiradi. Boshqa har qanday host `metaBaseUrl` dan, u bo'lmasa sukut bo'yicha lokalning `baseUrl` qiymatidan, u ham bo'lmasa `site.url` dan foydalanadi, shuning uchun soxta `Host` teglaringizga yeta olmaydi. Agar ularning hech biri o'rnatilmagan bo'lsa, so'rov origin'iga asoslangan zaxira variant qoladi va build ogohlantiradi. [Qatlamlar va domenlar](/uz/guide/layers#multiple-domains) sahifasiga qarang.

## Lokallar yoki sahifalarni chiqarib tashlash {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Agar sukut bo'yicha lokalda `seo: false` bo'lsa, `x-default` yozilmaydi. Bitta sahifa uchun teglarni o'chirish uchun [Sahifa konfiguratsiyasi](/uz/guide/per-component-translations#turn-off-seo-tags) dagi `disableMeta` dan yoki konfiguratsiyadagi [`routeDisableMeta`](/uz/api/module-options#routedisablemeta) dan foydalaning.

## Bitta sahifada teglarni qayta belgilash {#override-tags-on-one-page}

Faqat ba'zi tarjimalar mavjud bo'lgan yoki URL'lar API'dan keladigan CMS kontenti uchun generatsiya qilingan teglarni [`useI18nHead`](/uz/composables/useI18nHead) bilan almashtiring:

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` shuningdek `canonical`, `xDefault`, `ogLocale` va `ogUrl` ni o'rnatishi yoki olib tashlashi mumkin; `disable` butun guruhlarni olib tashlaydi (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Lokal almashtirilgandan keyin qiymatlar qayta hisoblanishi uchun getter uzating. Lokalga xos slug'lar uchun avval `$setI18nRouteParams` ni o'rnating ([Lokallashtirilgan yo'llar](/uz/guide/custom-locale-routes#per-locale-slugs)), shunda generatsiya qilingan muqobillar ulardan allaqachon foydalanadi.

## Oxiridagi slash {#trailing-slash}

`$localePath`, `$switchLocalePath`, `$switchLocaleRoute` ning route obyekti, `<i18n-link>`, `<i18n-switcher>`, lokal yo'naltirishlari va SEO URL'lari bitta slash qoidasiga amal qiladi: sukut bo'yicha `experimental.defaults.nuxtLink.trailingSlash`, yoki i18n yo'llari farq qilishi kerak bo'lganda i18n konfiguratsiyasidagi [`trailingSlash`](/uz/api/module-options).

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) bu modul bilan `nuxt-site-config` 4+ orqali ishlaydi. Site config lokallarni o'qiy olishi uchun `nuxt-i18n-micro` ni birinchi qilib ro'yxatga oling va `site.url` ni bir marta o'rnating — u yuqoridagi teglarni ham ta'minlaydi.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Tarjima qilingan sayt nomi va tavsifi lokal fayllaringizdagi `nuxtSiteConfig.name` / `nuxtSiteConfig.description` kalitlaridan olinadi. `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` xatosi `@nuxtjs/seo` 3-versiyadan eski ekanligini bildiradi; uni yangilang ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
