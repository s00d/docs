`@i18n-micro/cli` Nuxt loyihasining lokal fayllarini boshqaradi. U `locales`, `defaultLocale`, `translationDir` va qatlamlaringizni `nuxt.config` dan o‘qiydi, shuning uchun unga alohida konfiguratsiya kerak emas.

![i18n-micro check ishga tushirilgan terminal: u bitta yo‘q, bitta aniqlanmagan va to‘rtta ishlatilmagan kalitni sanab, xato bilan tugaydi, keyin extract aniqlanmagan kalitni qo‘shadi, keyin clean --dryRun o‘chiradigan to‘rtta kalitni sanab o‘tadi](/images/cli/demo.gif)

| Buyruq | Nima uchun ishlatiladi |
| --- | --- |
| `check` | Lokal fayllarda biror xato bo‘lsa build’ni muvaffaqiyatsiz tugatish |
| `translate` | Yo‘q kalitlarni tarjima servisi orqali to‘ldirish |
| `clean` | Hech narsa ishlatmaydigan kalitlarni o‘chirish |
| `rename` | Kalitni yoki butun nomlar fazosini hamma joyda birdaniga ko‘chirish |

```bash
npm install -D @i18n-micro/cli
npx i18n-micro --help
```

Uni ilova ildizidan ishga tushiring yoki `--cwd` bilan unga ishora qiling. Har bir buyruqning har bir flagi [buyruqlar ma’lumotnomasi](/uz/api/cli) da.

<Tip>

**nuxt-i18n-micro-cli dan o‘tyapsizmi?** `@i18n-micro/cli` uni almashtiradi; `i18n-micro` va `i18n-micro-cli` bin’lari qoladi. [Eski buyruqlar jadvali](#moving-from-nuxt-i18n-micro-cli) ga qarang.

</Tip>

## CI’da foydalanish {#use-it-in-ci}

```bash
i18n-micro check
```

`check` — bu darvoza. U quyidagilar haqida xabar beradi:

| Tekshiruv | Ma’nosi |
| --- | --- |
| `missing` | Standart lokalning kaliti biror lokalda yo‘q |
| `empty` | Qiymat `''`. Ilova zaxira emas, bo‘sh joy ko‘rsatadi |
| `extra` | Lokalda standart lokalda yo‘q kalit bor |
| `placeholders` | `{name}` yo‘qolgan yoki qo‘shilgan, yoki ko‘plik o‘z shakllarini yo‘qotgan |
| `undefined` | Kod standart lokalda yo‘q kalitdan foydalanadi |
| `unused` | Loyihada hech narsa kalitdan foydalanmaydi |
| `duplicates` | Turli kalitlar ostida bir xil matn. Standart bo‘yicha o‘chirilgan: `--duplicates` ni uzating |

- `--only missing,placeholders` ba’zi tekshiruvlarni ishga tushiradi; `--only` da nomlangan, lekin ishga tushirib bo‘lmagan tekshiruv muvaffaqiyatsiz hisoblanadi.
- `--json` asboblar uchun hisobot beradi.
- `--ignore` manba fayllarni o‘tkazib yuboradi.
- Kalitlar runtime’da hisoblanayotgan bo‘lsa, `unused` o‘tkazib yuboriladi va hisobot sababini aytadi.

Har bir buyruq uchta koddan biri bilan tugaydi, shuning uchun pipeline tarjimalaringizdagi muammoni asbobdagi muammodan ajrata oladi:

| Chiqish kodi | Ma’nosi |
| --- | --- |
| `0` | Xabar beradigan narsa yo‘q |
| `1` | Topilmalar |
| `2` | Buyruqni ishga tushirib bo‘lmadi: foydalanish xatosi, buzilgan fayl, muvaffaqiyatsiz so‘rov |

CI bosqichiga arziydigan boshqa buyruqlar:

```bash
i18n-micro format --check      # fails if a file is not formatted
i18n-micro lint                # stray spaces, empty values, your own regex rules
i18n-micro stats --baseRef main
```

## Lokallarni bir xil holatda saqlash {#keep-locales-in-step}

| Buyruq | Nima qiladi |
| --- | --- |
| `extract` | Kod ishlatadigan, lekin hali matni yo‘q kalitlarni sanab o‘tadi. `$t('key', {}, 'Welcome')` dagidek standart matn standart lokalga yoziladi. |
| `sync` | Standart lokalda yo‘q kalitlarni o‘chiradi. Avval `--dryRun` ni sinab ko‘ring. |
| `clean` | Hech narsa ishlatmaydigan kalitlarni o‘chiradi. Avval `--dryRun` ni sinab ko‘ring. |
| `search` | Kalit va qiymatlarni topadi va har bir kalit qayerda ishlatilishini ko‘rsatadi. |
| `stats` | Har bir lokal bo‘yicha to‘liqlik; `--baseRef main` git ref bilan solishtiradi. |

`sync` ishlatilmasligini isbotlay olmaydigan kalitni o‘chirmoqchi bo‘lganda, shuningdek standart lokalda solishtiradigan narsa bo‘lmaganda `clean` kabi to‘xtaydi. O‘chiradigan narsa bo‘lmasa, u hech qachon to‘xtamaydi, shuning uchun yolg‘iz `$t(item.label)` ning o‘zi `--force` uchun sabab emas.

<Note>

`extract` va `sync` tarjimasiz kalit uchun hech qachon `''` yozmaydi. Kalit yo‘qligicha qoladi, shuning uchun runtime’da `fallbackLocale` qo‘llaniladi va `check` bu haqda xabar beradi. Bo‘sh satr aniqlangan qiymat bo‘lib, bo‘sh joy ko‘rsatgan bo‘lardi.

</Note>

### Buyruqlar nimani o‘qiydi {#what-the-commands-read}

`check`, `extract`, `sync`, `clean`, `search` va `rename` manba kodni papkalarning qat’iy ro‘yxatidan emas, butun loyiha bo‘ylab o‘qiydi:

- **O‘qiladi:** shablonlar va skriptlar parser orqali, `.html` va Pug matn sifatida, har bir qatlam va alias yoki `components` ishora qiladigan ildizdan tashqaridagi papkalar.
- **O‘tkazib yuboriladi:** `node_modules`, build natijasi va lokal fayllar. O‘zingiznikini `--ignore 'legacy/**,*.stories.ts'` bilan qo‘shing.
- **Test kodi** foydalanish hisoblanadi, shuning uchun `clean` va `check --only unused` faqat test o‘qiydigan kalitni saqlaydi. U hech qachon kalit qo‘shmaydi: `extract` bunday kalitlarni o‘tkazib yuboradi, `check` esa ularni aniqlanmagan deb xabar bermaydi.

Test kodi deganda ildizdagi `tests`, `test`, `__tests__`, `e2e`, `cypress` va `playwright` papkalari, shuningdek istalgan joydagi `.spec` va `.test` JavaScript va TypeScript fayllari (`.ts`, `.tsx`, `.mts`, `.js`, `.jsx`, `.mjs` va shu kabilar) tushuniladi. Quyidagi shubhalardan faqat ildiz papkalari ozod: `pages/tests/[id].vue` boshqa har qanday sahifa kabi sahifa, `public/` va minifikatsiya qilingan fayllar ham shunday, ularning kodi ilovaning bir qismi emas.

Buyruqlar quyidagilarni taniydi:

- `$t`, `$ts`, `$tc`, `$has` va `$_t(route)`;
- `useI18n()` va `useTranslationServerMiddleware()` dagi `t()`;
- shablonlar va JSX dagi `<i18n-t keypath>` hamda `<i18n-group prefix>`;
- `const { t: tr } = useI18n()` kabi aliaslar.

### `clean` qanday qaror qiladi {#how-clean-decides}

`clean` tirik kalitni o‘chirgandan ko‘ra o‘lik kalitni qoldirishni afzal ko‘radi. Quyidagilardan biri to‘g‘ri bo‘lsa kalit qoladi:

- chaqiruv undan yoki undan pastdagi yoki yuqoridagi kalitdan foydalanadi;
- koddagi satr unga teng: `const key = 'menu.home'`, `<Item label="menu.home" />`;
- loyihadagi JSON, YAML yoki Markdown fayl uni o‘z ichiga oladi;
- hisoblangan kalitning uni qamrab oladigan statik boshlanishi bor: `` $t(`status.${state}`) `` `status.` ostidagi hamma narsani saqlaydi;
- qatlam uni aniqlaydi.

`clean` bila olmaganda hech narsani o‘zgartirmasdan to‘xtaydi va sababini sanab o‘tadi:

- kalit to‘liq hisoblanadi, masalan `$t(name)`, `<i18n-t :keypath="name" />` yoki `<i18n-t v-bind="props" />`;
- `$t` qiymat sifatida uzatiladi, masalan `items.map($t)`;
- `t` deb nomlangan funksiya hisoblangan argument oladi va parametr, import yoki chaqiruvdan keladi: u haqiqiysi ustidagi o‘rovchi bo‘lishi mumkin. Shu faylning o‘zi aniqlagan funksiya hisobga olinmaydi, chunki o‘rovchi ichida o‘z chaqiruvi bo‘lardi;
- manba fayl tahlil qilinmaydi;
- hech bir fayl umuman hech qanday kalitdan foydalanmaydi, bu odatda noto‘g‘ri joyda qidirayotganini anglatadi;
- lokal fayl loyihadan tashqariga ko‘rsatuvchi symlink, shuning uchun uni boshqa ilova o‘qishi mumkin.

<Steps>

<Step title="Oldindan ko‘rish">

`i18n-micro clean --dryRun` ni ishga tushiring va u sanab o‘tgan narsalarni ko‘rib chiqing.

</Step>

<Step title="Kalitlarni himoyalash">

Faqat ishlatilmayotgandek ko‘rinadigan kalitlarni `--exclude '^errors\.'` bilan saqlang.

</Step>

<Step title="O‘chirish">

Uni `--force` bilan qayta ishga tushiring.

</Step>

</Steps>

## Yo‘q kalitlarni tarjima qilish {#translate-missing-keys}

```bash
i18n-micro translate --dryRun                     # keys and characters per locale, nothing sent
export I18N_TRANSLATE_TOKEN=...                   # or put it in .env
i18n-micro translate --service deepl --locale de,fr
```

- `translate` yo‘q yoki bo‘sh kalitlarni to‘ldiradi; `--replace` hammasini qaytadan tarjima qiladi.
- O‘rinbosarlar va ko‘plik shakllari himoyalangan. O‘rinbosarni yo‘qotgan tarjima yozilmaydi: kalit sanab o‘tiladi va buyruq `1` bilan tugaydi.
- Har bir paket keyingi so‘rov yuborilishidan oldin saqlanadi, shuning uchun xato faqat muvaffaqiyatsiz bo‘lgan so‘rovga tushadi.

| `--service` | Servis | `--token` | Foydali `--options` |
| --- | --- | --- | --- |
| `ai` | Vercel AI Gateway, OpenAI, Anthropic yoki har qanday OpenAI bilan mos server | API kaliti yoki `AI_GATEWAY_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` | `provider`, `model`, `baseUrl`, `maxTokens` |
| `azure` | Azure Translator | Obuna kaliti | `region` |
| `deepl` | DeepL, bepul kalitlar ham | Auth kaliti | `formality`, `glossaryId`, `context` |
| `google` | Google Cloud Translation v2 | API kaliti | `model` |
| `libretranslate` | LibreTranslate | Ixtiyoriy | `baseUrl` |
| `yandexcloud` | Yandex Cloud Translate | API kaliti yoki `authScheme:Bearer` bilan IAM token | `folderId`, `model` |

Opsiyalar `key:value` juftliklari: `--options provider:openai,model:gpt-4o-mini`. Barcha servislar `baseUrl`, `retries`, `retryDelayMs` va `timeoutMs` ni ham qabul qiladi. Tarjima so‘rovi allaqachon hisob-kitob qilingan bo‘lishi mumkin, shuning uchun u faqat `429` yoki `503` dan keyin takrorlanadi, servis bir daqiqadan ko‘proq kutishni so‘raganda esa takrorlanmaydi.

<Warning>

Flaglar shell tarixida va jarayonlar ro‘yxatida ko‘rinadi, shuning uchun tokenni muhit o‘zgaruvchisi orqali uzating. CLI o‘zi maxfiy deb biladigan narsalarni qayerda chop etmasin yashiradi, `--debug` ham shu jumladan: tokenlar, provayder kalitlari, Basic hisob ma’lumotlari va siz sozlagan URL’ning query va hisob ma’lumotlari. Kalitni qaytarishdan oldin qayta formatlaydigan server uning qo‘li yetmaydigan joyda, shuning uchun muvaffaqiyatsiz ishga tushirish loglariga ehtiyotkorlik bilan munosabatda bo‘ling.

</Warning>

`ai` servisi glossariyga amal qiladi. `.i18n-glossary.json` mavjud bo‘lsa, u flagsiz ishlatiladi; `--glossaryFile` boshqa faylni tanlaydi.

```json .i18n-glossary.json
{ "entries": [{ "source": "Cart", "target": "Warenkorb", "to": "de" }] }
```

## Qattiq kodlangan matnni kalitlarga aylantirish {#turn-hardcoded-text-into-keys}

```bash
i18n-micro text-to-i18n --dryRun   # list what would change
i18n-micro text-to-i18n            # rewrite the templates
```

```vue
<!-- before -->
<h1>Welcome to our site</h1>
<!-- after -->
<h1>{{ $t('pages.index.welcome-to-our') }}</h1>
```

Faqat loyihaning o‘zidagi `.vue` shablonlari qayta yoziladi, qatlam yoki alias manzilidagilar emas. Har bir qayta yozilgan fayl yozilishidan oldin qayta tahlil qilinadi. Quyidagilar sanab o‘tiladi va o‘z matnini saqlaydi:

- `.ts` fayllari va skriptlardagi matn, chunki `$t` hamma joyda mavjud emas;
- belgilash yoki interpolatsiya yonidagi matn, masalan `<p>Hello <b>world</b> today</p>`: yarim gapni alohida tarjima qilib bo‘lmaydi;
- boshqasi bilan to‘qnashadigan yaratilgan kalit, ota sahifa va uning bolasi bilan bo‘lishi mumkin bo‘lganidek;
- qo‘shtirnoqlar orasiga qo‘yib bo‘lmaydigan ma’lum kalit.

<Warning>

Avval commit qiling va diff’ni ko‘rib chiqing.

</Warning>

## Kalitni qayta nomlash {#rename-a-key}

```bash
i18n-micro rename --from common.save --to actions.save
i18n-micro rename --from settings --to account.settings   # a whole namespace
```

`rename` sintaksis daraxtini tahrirlaydi, shuning uchun izohlar va aloqasiz satrlar o‘z holicha qoladi, aliaslar va `:keypath` esa kuzatiladi. Qatlamning o‘z fayli hech qachon o‘zgartirilmaydi. U qayta yoza olmaydigan narsalar haqida ogohlantiradi va ularni tegmasdan qoldiradi:

- eski nom ostidagi hisoblangan kalit;
- unga teng har bir oddiy satr;
- Pug shabloni;
- qatlamdagi yoki loyihadan tashqaridagi papkadagi manba.

`--to` kodda yozilishi mumkin bo‘lgan kalit bo‘lishi kerak: qo‘shtirnoqsiz, teskari slesh’siz, bo‘sh segmentsiz, `__proto__` siz.

## Tarjimonlar bilan fayllar almashish {#exchange-files-with-translators}

```bash
i18n-micro export --format csv
i18n-micro import --format csv --dryRun
```

**`export`** har bir lokalning har bir kalitini, tarjima qilinmaganlarini ham, standart lokal matnini manba sifatida yozadi: CSV’da `Source` ustuni, PO’da `#.` izohi.

- `--dir` siz PO `pots` ga, CSV esa `csv_exports` ga tushadi.
- U nima yozganini chiqish papkasidagi `.i18n-export.json` da qayd etadi. Agar fayl o‘shandan beri o‘zgargan bo‘lsa va lokal fayllarda bo‘lmagan tarjimalarni, jumladan fuzzy PO yozuvlarini saqlasa, u to‘xtaydi; `--force` ularni qayta yozadi. Lokal fayllarning oddiy tahrirlari uni to‘xtatmaydi.

**`import`** birlashtiradi, bo‘sh kataklarni va `fuzzy` deb belgilangan PO yozuvlarini o‘tkazib yuboradi.

- Qiymatni qayta yozadigan kalit yoki butun kalitlar guruhi ustidagi qiymat sanab o‘tiladi va chetda qoldiriladi, buyruq esa `1` bilan tugaydi.
- U kutilmagan joydagi katalog, oxirgi eksport yozmagan sahifa katalogi, CSV’da noto‘g‘ri joydagi qo‘shtirnoq yoki `disablePageLocales` ostidagi sahifa yozuvida `2` chiqish kodi bilan to‘xtaydi.

Tarjima platformasi uchun uning o‘z CLI’sidan foydalaning: [Crowdin](/uz/guide/crowdin) sozlamasi JSON fayllarni, jumladan sahifa fayllarini sinxronlaydi.

## O‘z endpoint’ingiz bilan sinxronlash {#sync-with-your-own-endpoint}

`sync-remote` global lokal fayllarni siz ishga tushiradigan HTTP endpoint bilan almashadi. Sahifa fayllari mahalliy qoladi va buyruq buni aytadi. Endpoint’ni `.i18n-remote.json` da tavsiflang:

```json .i18n-remote.json
{ "url": "https://translations.example.com", "path": "translations" }
```

Endpoint `GET` va `PUT` ga `{ locale: messages }` obyekti bilan javob beradi. `auth: { username, password }` bilan autentifikatsiya qiling yoki bearer tokenni `I18N_REMOTE_TOKEN` ga qo‘ying.

| | Pull | Push |
| --- | --- | --- |
| Nima ko‘chadi | Sizda yo‘q narsalarni to‘ldiradi va faqat sizda bor kalitlarni saqlaydi | Qatlamnikini emas, loyihaning o‘z kalitlarini yuboradi va bo‘sh qiymatlaringizni chetda qoldiradi |
| Ziddiyatlar | Ikkala tomonda farq qiladigan kalit: hech narsa yozilmaydi, `1` bilan chiqadi; `--force` masofaviy qiymatni oladi | PUT hujjatni almashtiradi, shuning uchun push avval endpoint’ni o‘qiydi va unda sizda yo‘q matn bo‘lsa `1` bilan to‘xtaydi; `--force` uni qayta yozadi. `404` bilan javob beradigan endpoint’ning yo‘qotadigan narsasi yo‘q |
| `--dryRun` | Endpoint’dan o‘qiydi, o‘zgarishlarni sanab o‘tadi, hech narsa yozmaydi | Endpoint bilan bog‘lanmasdan nima yuborilishini aytadi |

Siz sozlamagan lokal o‘tkazib yuboriladi, bo‘sh masofaviy qiymat esa hech narsani tozalamaydi.

## nuxt-i18n-micro-cli dan o‘tish {#moving-from-nuxt-i18n-micro-cli}

| Eski buyruq | Endi |
| --- | --- |
| `validate` | `check` |
| `diff` | `check --only missing` |
| `check-duplicates` | `check --only duplicates` |
| `export-csv`, `import-csv` | `export --format csv`, `import --format csv` |
| `--potsDir`, `--csvDir` | `--dir` |
| `estimate` | `translate --dryRun` |
| `glossary` | `.i18n-glossary.json` ni tahrirlang; `translate` uni o‘zi o‘qiydi |
| `backup`, `restore` | Lokal fayllaringizni allaqachon saqlaydigan Git |
| `init` | `nuxi init`, keyin `nuxt-i18n-micro` ni `modules` ga qo‘shing |
| `split` | Olib tashlangan: modul bo‘lingan fayllarni o‘qimaydi |
| `optimize` | `check --only duplicates` |
| `replace-values` | Muharriringiz yoki `sed` |
| `stats --full` | `stats`; tafsilotlar [DevTools](/uz/guide/devtools) da |
| `search --hardcodedOnly` | `text-to-i18n --dryRun` |
| `search --preferUnused`, `--onlyVue` | Olib tashlangan |
| `lint` qoidalari `no-html-tags`, `no-special-chars`, `no-mixed-case`, `no-missing-punctuation`, `no-inconsistent-pluralization` | Olib tashlangan: ular oddiy matnni belgilardi. Kerak bo‘lsa `customRegexRules` yozuvini yozing |
| `text-to-i18n --extractOnlyDirs`, `--extractOnlyPatterns`, `--verbose` | Olib tashlangan: kod hech qachon qayta yozilmaydi |
| `--logLevel verbose` | Olib tashlangan: u hech narsa qilmasdi |

**Olib tashlangan servislar:** `googlefree`, `yandex` (`yandexcloud` dan foydalaning), `ibm`, `lingvatranslate`, `modernmt`, `lilt`, `unbabel`, `reverso`, `baidu`, `papago`, `tencent`, `systran`, `mymemory`.

**Olib tashlangan `sync-remote` turlari:** `github`, `gitlab`, `crowdin`, `lokalise`, `tolgee`, `weblate`. Platformaning o‘z CLI’sidan yoki endi `type` talab qilmaydigan `custom` dan foydalaning.

### O‘zgargan xatti-harakat {#changed-behaviour}

- `extract` va `sync` endi `''` yozmaydi. Kalitlar yo‘qligicha qoladi va `check` ular haqida xabar beradi. `extract` kalitni faqat kod uning matnini berganda yozadi.
- `extract` sahifa kalitlarini modul ularni o‘qiydigan `locales/pages/<route name>/` ga yozadi va Nuxt 4 da `app/` ni skanerlaydi. `pages/_about` va `pages/blog_` kabi kataloglardagi narsalarni ko‘chiring va adashgan `locales/pages/<locale>.json` ni o‘chiring.
- `nuxt.config` dagi `translationDir` hisobga olinadi; avval har bir buyruq jimgina `locales` dan foydalanardi.
- `defaultLocale` bo‘lmasa, modul kabi standart `en` bo‘ladi va `DEFAULT_LOCALE` hisobga olinadi. Avval bu birinchi lokal edi.
- `check` va `sync` standart lokalni mezon sifatida ishlatadi va sahifa fayllarini tekshiradi. `"a.b"` va `a: { b }` bitta kalit hisoblanadi.
- `clean` istalgan joyda, istalgan doirada ishlatilgan kalitni saqlaydi va foydalanishni isbotlab bo‘lmaganda to‘xtaydi. `--include` va `--exclude` nimani o‘chirish mumkinligini tanlaydi.
- `sync` ham xuddi shunday to‘xtaydi, shuningdek standart lokalda solishtiradigan kalitlar bo‘lmaganda. `--force` buni bekor qiladi. U `DEFAULT_LOCALE` `nuxt.config` dan boshqa mezonni tanlaganda ham to‘xtaydi.
- Bitta chiziqchali uzun flaglar va ortiqcha argumentlar xato hisoblanadi: `clean -dryRun` endi `clean` ni ishga tushirmaydi.
- Faqat o‘qish uchun mo‘ljallangan yoki UTF-8 bo‘lmagan faylni saqlab bo‘lmaydi: buyruq biror narsani o‘zgartirishdan oldin to‘xtaydi. Bunday faylni o‘qish mumkin. Takrorlangan kalit, `__proto__` deb nomlangan kalit va 2^53 dan katta butun son buyruqni to‘xtatadi, chunki saqlash ularni yo‘qotib qo‘yardi.
- Qiymat talab qiladigan va ortidan boshqa flag keladigan flag xato hisoblanadi; chiziqcha bilan boshlanadigan qiymat uchun `--flag=--value` deb yozing. Mantiqiy flag faqat `true` yoki `false` ni qabul qiladi.
- `export` hech qachon import qilinmagan tarjimalarni qayta yozish o‘rniga to‘xtaydi.
- Chiqish kodlari `0`, `1` va `2`; avval xatolar `1`, `diff` va `check-duplicates` esa har doim `0` edi.
- `lint --fix` endi `.bak` fayllarini qoldirmaydi.
- Saqlash faylning chekinishini, qator oxirlarini, yakuniy yangi qatorni, symlink va hard link’ni saqlaydi va o‘zgartirmagan fayllarga tegmaydi.
- Noto‘g‘ri yozilgan yoki olib tashlangan flag endi jimgina e’tiborsiz qoldirilmaydi, balki xato hisoblanadi.
- `--dir` kabi yo‘llar shell’ga emas, loyihaga nisbatan.
- `ai` endi `@ai-sdk/*` paketlarini yuklamaydi: `provider` uchun `gateway`, `openai` yoki `anthropic` dan, OpenAI bilan mos server uchun esa `baseUrl` dan foydalaning.
