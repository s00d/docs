`useI18n()` ni chaqiradigan komponentlarga unit testlarda i18n nusxasi kerak. `@i18n-micro/test-utils` haqiqiy tarjima, ko'plik shakli va formatlash mantiqiga ega soxta `useI18n()` ni beradi, shuning uchun komponentni o'z lug'atlaringiz bilan va Nuxt serverisiz mount qilishingiz mumkin. Marshrutlash va qayta yo'naltirishlar uchun haqiqiy modulni `@nuxt/test-utils` bilan end-to-end ishga tushiring.

Bu sahifa ilovangizni testlash haqida. Ushbu repozitoriy modulning o'zini qanday testlashi [Modulni testlash](https://s00d.github.io/nuxt-i18n-micro/contributing/testing) sahifasida yoritilgan.

## O'rnatish {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

```bash npm
npm install -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

## useI18n ni mock qilish {#mock-usei18n}

```ts
// tests/unit-setup.ts
import { setupNuxtI18nMock } from '@i18n-micro/test-utils'
import { mockNuxtImport } from '@nuxt/test-utils/runtime'
import { beforeEach, vi } from 'vitest'

export const { i18n, useI18n, setTranslationsFromJson } = setupNuxtI18nMock({
  spy: vi.fn, // every method becomes a vi.fn, so you can assert calls
  beforeEach, // reset state and reseed `translations` before each test
  translations: { welcome: 'Welcome' },
})

mockNuxtImport('useI18n', () => useI18n)
```

```ts
// vitest.config.ts
import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    environment: 'nuxt',
    setupFiles: ['./tests/unit-setup.ts'],
  },
})
```

`mockNuxtImport` ni sozlash faylida saqlang: `@nuxt/test-utils` uni transformatsiya qilishi kerak. `setupNuxtI18nMock` shaxsiy tarjima keshidan foydalanadi, shuning uchun parallel test fayllari holatni bo'lishmaydi.

## Test yozish {#write-a-test}

```vue
<!-- components/Greeting.vue -->
<script setup lang="ts">
const { $t } = useI18n()
</script>

<template>
  <p>{{ $t('welcome') }}</p>
</template>
```

```ts
// tests/greeting.spec.ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { expect, it } from 'vitest'
import Greeting from '~/components/Greeting.vue'
import de from '~/locales/de.json'
import { i18n, setTranslationsFromJson } from './unit-setup'

it('renders the German greeting', async () => {
  await setTranslationsFromJson('de', de)
  i18n.setLocale('de')

  const wrapper = await mountSuspended(Greeting)
  expect(wrapper.text()).toBe('Willkommen') // de.json: { "welcome": "Willkommen" }
})
```

Soxta obyekt haqiqiy `useI18n()` bilan bir xil metodlarni (`$t`, `$tc`, `$tn`, `$td`, `$has`, `$localePath`, …, `$` bilan va `$` siz) hamda testlar uchun setterlarni taqdim etadi: `setLocale`, `setLocales`, `setDefaultLocale`, `setRouteName`, `setTranslationsFromJson`, `loadPageTranslations`, `mergeTranslations`, `setMissingHandler`.

`$localePath` va `$switchLocalePath` — yo'lga `strategy` sozlamasiga muvofiq prefiks qo'shadigan stub'lar (haqiqiy router yo'q). Haqiqiy havolalar va qayta yo'naltirishlarni end-to-end testlang.

## Quyi darajadagi yordamchilar {#lower-level-helpers}

| Yordamchi | Nima uchun ishlatiladi |
| --- | --- |
| `createIsolatedFakeI18n(options)` | Nuxt `useI18n` ulanishisiz izolyatsiya qilingan soxta obyekt, masalan `global.mocks` bilan oddiy `@vue/test-utils` `mount` uchun. |
| `createFakeI18n(options)` | Umumiy modul keshidagi soxta obyekt (`beforeEach` da `resetI18n()` ni chaqiring) yoki `isolated: true` bilan izolyatsiya qilingan. |
| `createI18nTestContext(options)` | Bir nechta soxta obyekt kerak bo'lganda, ikkalasining asosidagi kontekst. |
| `t`, `tc`, `ts`, `tn`, `td`, `tdr`, `has` | Oddiy funksiyalarni testlash uchun umumiy kontekstga to'g'ridan-to'g'ri chaqiruvlar. |

Mock — bu `BaseI18n`: `t`, `tc`, `tn`, `td`, `tdr` va `has` haqiqiy lug'atlardagi haqiqiy metodlardir, shuning uchun test ilova ko'rsatadigan narsani ko'radi.

Yuqoridagi fabrika yordamchilari `locale`, `defaultLocale`, `locales`, `routeName`, `strategy`, `translations` va `messages` (har bir locale uchun lug'atlar) ni qabul qiladi. To'liq misol loyihasi [`packages/test-utils/example`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/test-utils/example) da joylashgan.

## End-to-end testlar {#end-to-end-tests}

Marshrutlash, qayta yo'naltirishlar, SEO teglari va payload yuklash uchun haqiqiy modul kerak. Ilovangizni `@nuxt/test-utils/e2e` bilan ishga tushiring:

```ts
// tests/e2e/locales.test.ts
import { $fetch, fetch, setup } from '@nuxt/test-utils/e2e'
import { describe, expect, it } from 'vitest'

describe('locales', async () => {
  await setup({ server: true })

  it('serves the German page', async () => {
    expect(await $fetch('/de')).toContain('lang="de-DE"')
  })

  it('redirects / for a German browser', async () => {
    const res = await fetch('/', { headers: { 'accept-language': 'de' }, redirect: 'manual' })
    expect(res.headers.get('location')).toBe('/de')
  })
})
```

Ikkinchi test `prefix` (yoki boshqa standart locale bilan `prefix_except_default`) ni nazarda tutadi; `/` qachon qayta yo'naltirishi haqida [Locale'ni aniqlash](/uz/guide/locale-detection) sahifasiga qarang.
