---

O'rnatilgan aniqlash URL, cookie va `Accept-Language`ni o'qiydi. Agar lokal boshqa narsaga bog'liq bo'lsa — domen, CDN o'rnatgan geo sarlavha, foydalanuvchi profili — uni i18n plaginidan oldin ishga tushadigan plaginda o'zingiz o'rnating. Shundan so'ng modul o'sha lokalning tarjimalarini yuklaydi va xuddi o'zi aniqlagandek yo'naltirishlar uchun undan foydalanadi. Tanlangan lokal qachon URL ustidan g'olib bo'lishini belgilovchi qoidalar [Lokalni aniqlash](/uz/guide/locale-detection) sahifasida keltirilgan; bu sahifa esa o'z manbangizni qanday ulashni ko'rsatadi.

## Lokalni server plaginida o'rnatish {#set-the-locale-in-a-server-plugin}

```ts
// plugins/i18n-locale.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10, // before the i18n plugin (order -5)
  setup() {
    const { setLocale } = useI18nLocale()
    const host = (useRequestHeaders(['host']).host ?? '').split(':')[0]! // without the port

    if (host.endsWith('.de')) setLocale('de')
    else if (host.endsWith('.fr')) setLocale('fr')
  },
})
```

`setLocale(code)` lokal holatini (`useState('i18n-locale')`) va, agar lokal cookie sozlangan bo'lsa, cookie'ni yozadi. `useState` yoki `useCookie`ni o'zingiz yozish o'rniga undan foydalaning. Faqat yoqilgan lokal kodlarini uzating.

So'rov sarlavhalarini o'qiyotgan bo'lsa, plaginni `.server.ts` qilib qoldiring: brauzerda ular mavjud emas. `localStorage` kabi faqat brauzerga tegishli manbalar uchun `.client.ts` plagini to'g'ri joy.

## O'rnatilgan Accept-Language bosqichini o'chirish {#turn-off-the-built-in-accept-language-step}

Plaginingiz va `Accept-Language` bir-biriga zid kelishi mumkin. Faqat sizning kodingiz (shuningdek URL va cookie) qaror qilishi uchun sarlavhani o'chiring:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    autoDetectLanguage: false,
  },
})
```

[`autoDetectLanguage`](/uz/api/module-options#autodetectlanguage) faqat sarlavha bosqichini boshqaradi. URL va yaroqli cookie baribir hisobga olinadi.

## Keyin nima bo'ladi {#what-happens-next}

`setLocale` ta'siri [strategiyaga](/uz/guide/strategy) bog'liq:

| Strategiya | Plagindagi `setLocale('de')` ta'siri |
| --- | --- |
| `no_prefix` | Sahifa nemis tilida render qilinadi; URL o'zgarmaydi. |
| `prefix`, `prefix_except_default` | [`autoDetectPath`](/uz/api/module-options#autodetectpath) yo'naltirishga ruxsat beradigan prefikssiz yo'lda (standart bo'yicha faqat `/`) server nemischa URL'ga `302` bilan javob beradi. Lokal prefiksi bor URL uni saqlab qoladi. |
| `prefix_and_default` | Yo'naltirish yo'q: prefikssiz URL standart lokalning yaroqli sahifasi hisoblanadi. |

Prefiksli strategiyalarda URL'dagi lokal foydalanuvchining tanlovi hisoblanadi va plaginingiz uni bekor qilmaydi. `autoDetectPath: '*'` bundan istisno: bunda server prefiksli URL'larni cookie va `Accept-Language` bo'yicha ko'chiradi va holatni e'tiborsiz qoldiradi, lekin `setLocale()` cookie sozlangan bo'lsa uni ham yozadi, shuning uchun keyingi so'rovdan boshlab plaginingiz tanlovi prefiksli URL'ni yo'naltirishi mumkin. Aniq lokal URL'lari ustun bo'lishi kerak bo'lsa, `'/'`ni qoldiring yoki `'no_prefix'`dan foydalaning. Plaginingizdan tashrif buyuruvchi qayerga tushishini tanlash uchun foydalaning, u bosgan havolalarni qayta yozish uchun emas.

## Foydalanuvchi tanlagan lokalni hurmat qilish {#respect-a-locale-the-user-picked}

Foydalanuvchi tilni almashtirgach, bu almashtirish cookie'ni yozadi. Yaroqli afzallik allaqachon mavjud bo'lsa, o'z aniqlashingizni o'tkazib yuboring:

```ts
// plugins/i18n-locale.server.ts
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10,
  setup() {
    const { getPreferredLocale, setLocale, validLocales } = useI18nLocale()
    if (getPreferredLocale()) return // valid state or cookie: keep it

    const country = useRequestHeaders(['x-country'])['x-country']
    if (country === 'JP') return setLocale('ja')

    const header = useRequestHeaders(['accept-language'])['accept-language']
    setLocale(detectLocaleFromAcceptLanguage(header, validLocales))
  },
})
```

`getPreferredLocale()` holat yoki cookie'ni faqat u yoqilgan lokal bo'lganda qaytaradi, shuning uchun eskirgan cookie aniqlashni to'xtatmaydi. `detectLocaleFromAcceptLanguage` — modulning o'zi ishlatadigan, q-qiymatlarni hisobga oluvchi moslashtiruvchi (uni import qilish uchun `@i18n-micro/utils`ni o'rnating); `setLocale(null)` hech narsa qilmaydi.

## Har bir lokal uchun bitta domen {#one-domain-per-locale}

Agar har bir domen o'z lokallariga xizmat qilishi kerak bo'lsa, plagin kerak emas: har bir lokalga `baseUrl` bering, har bir domenning standart lokalida `baseDefault: true` o'rnating va bir marta build qiling (statik sayt baribir har bir domen uchun `nuxi generate`ni ishga tushiradi). [Qatlamlar va domenlar](/uz/guide/layers#multiple-domains) sahifasiga qarang.
