Tarjimalar oddiy JSON fayllardir: umumiy kalitlar uchun har bir lokalga bitta ildiz fayl va shu sahifa kalitlari uchun har bir sahifa va lokalga bitta fayl. Buni sahifalar qo'shganingizda, ular o'rtasida kalitlarni baham ko'rganingizda yoki fallback'larni sozlaganingizda o'qing. Siz kalit qaysi faylga yozilishi kerakligini, sahifa nimani ko'ra olishini va har bir fayl qachon yuklanishini bilib olasiz.

## Tuzilma {#layout}

```text
locales/
├── en.json                 # root: menus, footer, buttons
├── de.json
└── pages/
    ├── index/              # pages/index.vue
    │   ├── en.json
    │   └── de.json
    ├── about/              # pages/about.vue
    │   ├── en.json
    │   └── de.json
    └── products-id/        # pages/products/[id].vue
        ├── en.json
        └── de.json
```

- `locales/pages/` ostidagi papka — sahifaning Nuxt **route nomi**: `pages/products/[id].vue` — `products-id`, `pages/blog/[slug]/comments.vue` — `blog-slug-comments`.
- Kalitlar istalgan chuqurlikda ichma-ich bo'lishi mumkin; `$t('auth.form.login')` `{ "auth": { "form": { "login": … } } }` ni o'qiydi.
- `translationDir` papkani ko'chiradi (sukut bo'yicha `'locales'`, loyiha ildiziga nisbatan, Nuxt 4 `app/` tuzilmasida ham).
- Nuxt sahifalarni aniqlaganda yo'q fayllar `{}` sifatida yaratiladi, agar [`disableWatcher`](/uz/api/module-options#disablewatcher) o'rnatilmagan bo'lsa.

## Sahifa nimani ko'radi {#what-a-page-sees}

![de lokalida /about sahifasidagi kalit uchun qidiruv tartibi: pages/about/de.json, de.json, pages/about/en.json, en.json. Ular $t o'qiydigan bitta about/de/data.json ga birlashadi](/images/diagrams/page-dictionary.svg)

Sahifa lug'ati — uning ildiz fayli bilan sahifa faylining chuqur (har bir darajada) birlashmasi. To'qnashuvda sahifa fayli ustun keladi:

```json
// locales/en.json
{ "title": "My shop", "nav": { "home": "Home", "cart": "Cart" } }
```

```json
// locales/pages/about/en.json
{ "title": "About us", "nav": { "cart": "Basket" } }
```

```ts
// on /about
t('title') // 'About us'
t('nav.home') // 'Home'   (root)
t('nav.cart') // 'Basket' (page wins)
// on any other page
t('title') // 'My shop'
```

O'z papkasi bo'lmagan sahifa faqat ildiz lug'atini oladi. Boshqa sahifalarning kalitlari ko'rinmaydi.

### Fallback lokallar {#fallback-locales}

Faol lokalda yo'q kalit kalitning o'zi ko'rsatilishidan oldin uning fallback lokalidan olinadi:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'de-at', iso: 'de-AT', fallbackLocale: 'de' },
    ],
    defaultLocale: 'en',
    fallbackLocale: 'en', // global, for every locale
  },
})
```

- Lokalning o'z `fallbackLocale` qiymati oxirigacha kuzatiladi: `de-at` → `de` → `en`.
- Global `fallbackLocale` — eng kuchsiz qatlam, barcha zanjirlar ostida.
- Zanjirdagi har bir lokal eng kuchsiz fallback'dan faol lokalgacha avval o'z ildiz faylini, keyin sahifa faylini qo'shadi. Shunday qilib, faol lokalning ildiz fayli fallback lokalning sahifa faylidan ustun keladi.

Fallback bo'lmasa, yo'q kalit kalitning o'zi (`'nav.home'`) sifatida render qilinadi va dev rejimida brauzer konsoliga ogohlantirish yozadi ([`missingWarn`](/uz/api/module-options#missingwarn)).

## Baham ko'rish va boshqa manbalar {#sharing-and-other-sources}

| Ehtiyoj | Parametr |
| --- | --- |
| Faqat ildiz fayllari, `pages/` papkalarisiz | [`disablePageLocales: true`](/uz/api/module-options#disablepagelocales) |
| Ikki sahifa bitta sahifa papkasini o'qiydi | [`routesLocaleLinks`](/uz/api/module-options#routeslocalelinks): `{ 'about-us': 'about' }` |
| Boshqa papkadagi umumiy ildiz fayllari | [`additionalTranslationDirs`](/uz/api/module-options#additionaltranslationdirs): `['common']` (asosiy `translationDir` ustun keladi) |
| Nuxt qatlamidan kelgan kalitlar | Qatlamlarning fayllari birlashadi, loyihaning o'z fayllari ustun keladi. [Qatlamlar](/uz/guide/layers) sahifasiga qarang |
| Runtime'da qo'shilgan kalitlar | [`i18n:register`](/uz/api/events) hook'i, `$mergeTranslations`, `$setTranslation` |
| Sahifa komponentidagi ichki kalitlar | `$defineI18nRoute({ locales: { en: { … } } })`, [Sahifa konfiguratsiyasi](/uz/guide/per-component-translations) sahifasiga qarang |

## Sahifa o'z lug'atini qanday yuklaydi {#how-a-page-loads-its-dictionary}

![Lokal JSON fayllari payload daraxtiga build qilinadi, Node'da public/ da yoki Edge'da server assetlarida saqlanadi, server loader tomonidan o'qiladi, so'ngra serverda $t tomonidan ishlatiladi va brauzerda $t uchun yuklab olinadi](/images/diagrams/translation-pipeline.svg)

Modul har bir sahifa va lokal uchun bitta payload quradi: `/{apiBaseUrl}/{page}/{locale}/data.json` (sukut bo'yicha `/_locales/about/de/data.json`).

1. **Server renderi.** Nitro lokalni aniqlaydi va sahifa o'z payload'ini HTTP so'rovisiz to'g'ridan-to'g'ri server loader'dan yuklaydi. Lug'at HTML payload'iga yozilmaydi, shuning uchun sahifalar kichik bo'lib qoladi.
2. **Gidratatsiya.** Brauzer xuddi shu payload'ni yuklab oladi. Server uning uchun allaqachon `<link rel="preload">` chiqargan, shuning uchun yuklash HTML bilan birga boshlanadi.
3. **Navigatsiya.** Keyingi sahifaning payload'i lug'atni almashtiradi. Chiqib ketayotgan sahifaning kalitlari u yo'qolguncha (sahifa o'tishi tugaguncha yoki `page:finish` gacha) aniqlanaveradi, shuning uchun so'nib borayotgan sahifada xom kalitlar miltillamaydi. Yuklab bo'lmagan bo'lak (tarmoq xatosi, 4xx yoki 5xx, obyekt bo'lmagan javob tanasi) joriy lug'atni joyida qoldiradi va keyingi navigatsiya uni qayta yuklaydi. Muvaffaqiyatsiz lokal almashtirish ham xuddi shunday: `$switchLocale` `false` bilan yakunlanadi va uni qayta chaqirish yoki almashtirgichni qayta bosish urinishni takrorlaydi. Prefiks strategiyalari ostida bu paytga kelib URL allaqachon o'zgargan bo'ladi, shuning uchun eski matnlar ekranda qolgan holda `lang` va `$getLocale()` URL lokalini ko'rsatadi.
4. **Kesh.** Yuklangan payload'lar serverda va brauzerda keshlanadi; hajm va TTL sozlamalari [Unumdorlik](/uz/guide/performance) sahifasida.

`translationPayloads.mode` payload'lar qanday qurilishini belgilaydi. `'premerged'` (sukut bo'yicha) build vaqtida har bir sahifa × lokal faylini yozadi. `'source'` manba fayllarini saqlaydi va har bir so'rovda birlashtiradi, bu Edge nishonlaridagi katta kataloglar uchun kichikroq. Ikkalasi ham bir xil lug'atlarni beradi. Har bir deploy nishoni uchun fayllar qayerga tushishi [Deploy](/uz/guide/deployment) sahifasida.

## Development rejimida tahrirlash {#editing-in-development}

`nuxt dev` fayllarni jonli o'qiydi. Tarjima faylini saqlash ochiq sahifaning lug'atini joyida yangilaydi: qayta yuklashsiz, olib tashlangan kalitlar yo'qoladi va ildiz fayldagi o'zgarish har bir sahifaga yetib boradi. Buzilgan JSON fayli o'z yo'li bilan ogohlantirish yozadi va bo'sh deb hisoblanadi. Buning o'rniga qo'lda yangilash uchun [`hmr: false`](/uz/api/module-options#hmr) ni o'rnating.
