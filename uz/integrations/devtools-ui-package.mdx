`@i18n-micro/devtools-ui` — bu Nuxt DevTools yorlig'idagi tarjima muharriri bo'lib, Vite plagini bilan web component sifatida paketlangan. Development paytida tarjimalar papkangizdagi JSON fayllarni brauzerdan ko'rib chiqish va tahrirlash uchun uni Vue, React, Preact, Solid yoki Astro loyihasiga qo'shing. Nuxt ilovalarida u [Nuxt DevTools](/uz/guide/devtools) ichida allaqachon mavjud.

![DevTools UI: fayllar daraxti va har bir kalit yonida standart locale matni ko'rsatilgan muharrir](/images/devtools/02-translations-editor-dark.webp)

## Sozlash {#setup}

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import { i18nDevToolsPlugin } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  plugins: [i18nDevToolsPlugin({ translationDir: 'src/locales' })],
})
```

| Parametr | Standart qiymat | Izohlar |
| --- | --- | --- |
| `translationDir` | `'src/locales'` | JSON fayllar joylashgan papka, Vite root'iga nisbatan. |
| `base` | `'/__i18n_api'` | API endpoint'larining asosiy yo'li. |
| `injectButton` | `true` | Vite'ning `index.html` transformatsiyasi orqali beriladigan sahifalarga suzuvchi tugma qo'shish. Astro'da bunday sahifalar yo'q: quyiga qarang. |
| `defaultLocale` | `translationDir` dagi birinchi locale fayli | `/config` tomonidan qaytariladi. |
| `fallbackLocale` | `defaultLocale` | `/config` tomonidan qaytariladi. |

Plagin faqat dev serverda ishlaydi (`apply: 'serve'`); production build'da undan hech narsa bo'lmaydi. Tugma `/__i18n_devtools.html` ni ochadi, u fayllarni plagin endpoint'lari orqali o'qiydi va saqlaydi:

| Endpoint | Vazifasi |
| --- | --- |
| `GET <base>/translations` | `translationDir` ostidagi barcha lug'atlar, nisbiy yo'l bo'yicha |
| `POST <base>/save` | tana `{ file, content }`; `translationDir` ichidagi mavjud `.json` ni qayta yozadi, boshqa har qanday narsa uchun 403. U hech qachon fayl yaratmaydi |
| `GET <base>/config` | `{ defaultLocale, fallbackLocale, locales, translationDir }`; `locales` `translationDir` dagi root fayllardan olinadi |

Endpoint'lar faqat devtools sahifasiga javob beradi: boshqa origin yoki host'dan kelgan so'rov `403` oladi, `/save` esa faqat `application/json` qabul qiladi (`415`). Sahifa fayl o'zgarishlari haqida Vite'ning HMR soketi orqali xabar topadi.

Astro'da plagin o'rniga integratsiyani qo'shing. U dev toolbar'ga ilova qo'shadi:

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import { i18nDevToolsIntegration } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  integrations: [i18nDevToolsIntegration({ translationDir: 'src/locales' })],
})
```

Saqlash faqat faylni yozadi. JSON ni Vite orqali import qiladigan ilova uni HMR orqali oladi; ishlayotgan nusxaga to'g'ridan-to'g'ri qo'llaniladigan tahrirlar uchun bridge'dan foydalaning.

## Ishlayotgan nusxaga bridge {#bridge-to-a-live-instance}

Muharrirni o'z sahifangizga joylashtirish va tahrirlarni ishlayotgan nusxaga darhol qo'llash uchun adapter'dan bridge yarating va uni `<i18n-devtools-ui>` elementiga uzating:

```ts
import { createBridge, register } from '@i18n-micro/devtools-ui'
import { i18n, locales } from './i18n' // a runtime, React, Preact or Solid instance

register() // defines <i18n-devtools-ui> once

const bridge = createBridge({
  adapter: {
    getRouteCache: () => Object.fromEntries(i18n.storage.translations),
    addTranslations: (locale, content, merge) => i18n.addTranslations(locale, content, merge),
    addRouteTranslations: (locale, route, content, merge) => i18n.addRouteTranslations(locale, route, content, merge),
    subscribe: (cb) => i18n.subscribe(cb),
    getCurrentLocale: () => i18n.locale,
  },
  locales,
  defaultLocale: 'en',
  translationDir: 'src/locales',
})

const el = document.createElement('i18n-devtools-ui') as HTMLElement & { bridge: typeof bridge }
el.bridge = bridge
document.body.append(el)
```

`getRouteCache` lug'atlarni `locale:route` kalitlari bilan (`en:index`, `en:blog-post`) qaytarishi kerak — `i18n.storage.translations` aynan shuni saqlaydi. Vue nusxasi uchun `i18n.global.getRouteCache()` va `i18n.global.subscribeToChanges(cb)` dan foydalaning.

`saveTranslation` avval nusxani yangilaydi, so'ng `<base>/save` ga POST yuboradi. Endpoint bo'lmasa (statik preview build) yoki dev serverga ulanib bo'lmasa, tahrir `localStorage` da saqlanadi; saqlashdagi boshqa har qanday xato oldingi lug'atni tiklaydi va xato tashlaydi.

## API {#api}

| Eksport | Kirish nuqtasi |
| --- | --- |
| `i18nDevToolsPlugin(options)`, `i18nDevToolsIntegration(options)` | `@i18n-micro/devtools-ui/vite` |
| `register()`, `I18nDevToolsElement` | `@i18n-micro/devtools-ui` |
| `createBridge(options)`, `BridgeAdapter`, `CreateBridgeOptions` tiplari | `@i18n-micro/devtools-ui` (shuningdek `/bridge/create`) |
| `I18nDevToolsBridge` tipi | `@i18n-micro/devtools-ui` (shuningdek `/bridge`) |
| `createRpcClient`, `setupRpcHost` | `@i18n-micro/devtools-ui` |
