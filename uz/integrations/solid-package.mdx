`@i18n-micro/solid` SolidJS ilovalariga signalga asoslangan i18n nusxasi, provider, `useI18n()` va to‘rtta komponent beradi. Undan Nuxt bilan qurilmagan Solid ilovasida foydalaning. JSX yoki effektlar ichida `t()` ni o‘qish lokal, marshrut va lug‘atlarni kuzatadi; umumiy model [Freymvorklar](/uz/integrations/overview) sahifasida.

## O‘rnatish {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer bog‘liqliklar: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (ixtiyoriy, faqat `@i18n-micro/solid/router` uchun). Solid 2 hozircha qo‘llab-quvvatlanmaydi.

## Sozlash {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` `i18n`, `locales`, `defaultLocale` va `routingStrategy` ni qabul qiladi; ko‘rsatilmagan prop tashqi providerning qiymatini, jumladan nusxani ham saqlaydi. `getLocaleName()` va `<I18nSwitcher>` `locales` ni o‘qiydi; ularsiz ro‘yxat qiladigan narsa bo‘lmaydi. Opsiyalar [nusxa](/uz/integrations/overview#the-instance) bo‘limida. Nusxa [runtime](/uz/integrations/runtime-package) nusxasi bo‘lib, uning store’i ustida bitta signal bor.

## Tarjima qilish {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Solid ularni kuzatishi uchun metodlarni JSX yoki effekt ichida chaqiring, `localePath` va `getLocale` ni ham; komponent tanasida bir marta o‘qilgan qiymat yangilanmaydi. Nusxada `i18n.locale` va `i18n.currentRoute` bilan kuzating: `i18n.getLocale()` oddiy qoladi, chunki yozuvlar uni o‘qiydi. Lokalni o‘qish faqat lokal o‘zgarganda uyg‘onadi, shuning uchun uni o‘qib lug‘at yuklaydigan effekt bir marta ishlaydi. Proplarni destrukturizatsiya qilmang va `t('key')` natijalarini oddiy o‘zgaruvchilarda saqlamang.

`useI18n()` `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` va `instance` ni qaytaradi.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Lokalni almashtirish {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Almashtirish hech narsa yuklamaydi; avval lokalning lug‘atini qo‘shing.

`<I18nGroup>` prefiksli `t` ni funksiya bolasiga uzatadi. Uning ichidagi `<I18nT>` va `t()` prefikslanmaydi:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Marshrutlash {#routing}

`@solidjs/router` adapteri asosiy kirish nuqtasi hech qachon routerni import qilmasligi uchun alohida subpath’da joylashgan. Uni router ostida, odatda routerning `root` ida chaqiring, u yerda `useNavigate` va `useLocation` ishlaydi:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

Adapter standartdan tashqari har bir lokalga prefiks qo‘shadi (`/about`, `/de/about`) va `<I18nLink>` ni routerning `<A>` komponenti sifatida render qiladi. `getCurrentPath` routerning reaktiv joylashuvini o‘qiydi, shuning uchun faol havolalar va almashtirgich unga amal qiladi; maxsus strategiya ham u yerda signalni o‘qib, xuddi shunday natijaga erishadi. Argumentlar tartibiga e’tibor bering: `(locales, defaultLocale, navigate, location)`. Boshqa routerlar uchun `getCurrentPath`, `push` va `replace` (barchasi majburiy) bilan adapter yozing — [Router adapteri](/uz/integrations/overview#router-adapter) ga qarang.

## SSR {#ssr}

Server tomonida render qilish uchun `vite-plugin-solid` bilan build qiling: paketning `solid` eksport sharti unga manba kodni beradi, shuning uchun u server uchun kompilyatsiya qilinadi. Oldindan build qilingan `dist` faqat brauzer uchun. Nusxada `destroy()` yo‘q; har bir ilova uchun bitta yoki serverda har bir so‘rov uchun bitta nusxa yarating va uni garbage collector tozalashiga qo‘ying.
