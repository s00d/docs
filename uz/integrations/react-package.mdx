`@i18n-micro/react` va `@i18n-micro/preact` freymvorkdan mustaqil [runtime](/uz/integrations/runtime-package) ni provider, `useI18n()` hook’i va to‘rtta komponentga o‘raydi. Ulardan Nuxt bilan qurilmagan React yoki Preact ilovasida foydalaning. Ikkala paket bir xil API’ga ega; [Preact](#preact) bloki bir nechta farqlarni sanab o‘tadi, umumiy model esa [Freymvorklar](/uz/integrations/overview) sahifasida.

## O‘rnatish {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/react
```

```bash npm
npm install @i18n-micro/react
```

```bash yarn
yarn add @i18n-micro/react
```

</CodeGroup>

Peer bog‘liqliklar: `react` `^18.0.0 || ^19.0.0`; `react-dom` (ixtiyoriy, render qilish uchun); `react-router-dom` `^6.0.0 || ^7.0.0` (ixtiyoriy, faqat `@i18n-micro/react/router` uchun). React 19.3 va 18.3, React Router 7.18 va 6.30 da sinovdan o‘tkazilgan.

## Sozlash {#setup}

```tsx
// src/main.tsx
import { createRoot } from 'react-dom/client'
import { createI18n, I18nProvider } from '@i18n-micro/react'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

createRoot(document.getElementById('root')!).render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
    <App />
  </I18nProvider>,
)
```

<Warning>

Nusxani bir marta, modul darajasida yoki `useState` initsializatorida yarating, hech qachon komponent tanasida emas.

</Warning>

`<I18nProvider>` `i18n`, `locales`, `defaultLocale` va `routingStrategy` ni qabul qiladi:

- Ko‘rsatilmagan prop tashqi providerning qiymatini, jumladan nusxani ham saqlaydi.
- Umuman nusxa bo‘lmasa, u yonidagi `createI18n` opsiyalaridan nusxa yaratadi, shuning uchun proplar oddiy ma’lumot bo‘lib qoladi: `<I18nProvider locale="de" messages={messages}>`.
- Yangi `locale` propi shu render’dagi `messages` bilan yangi nusxa yaratadi. Bunday nusxa komponent ichida yashaydi: agar undan yuqoridagi biror narsa mount paytida suspend bo‘lsa, React uni unga qo‘shilgan hamma narsa bilan birga tashlab yuboradi.

Barcha `createI18n` opsiyalari, jumladan `routeMessages`, [nusxa](/uz/integrations/overview#the-instance) bo‘limida.

## Tarjima qilish {#translate}

```tsx
import { useI18n } from '@i18n-micro/react'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' })}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

`useI18n()` quyidagilarni qaytaradi:

| Guruh | A’zolar |
| --- | --- |
| Tarjima | `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` |
| Lokal va marshrut | `locale`, `fallbackLocale`, `currentRoute`, `setLocale`, `setRoute`, `getRoute`, `getLocales`, `defaultLocale()`, `getLocaleName` |
| Marshrutlash | `switchLocale`, `localePath`, `localeRoute` |
| Lug‘atlar | `addTranslations`, `addRouteTranslations`, `clearCache` |

- Komponent lokal, marshrut yoki o‘qiladigan lug‘at o‘zgarganda va provider yangi `locales` yoki `routingStrategy` obyektini olganda qayta render qilinadi. Na faol, na zaxira bo‘lmagan lokalning lug‘ati hech narsani render qilmaydi.
- `t` va boshqa tarjima metodlari faqat store bilan o‘zgaradi, shuning uchun ular `memo` va effekt bog‘liqliklarida xavfsiz.

`useT` — qiymat sifatida bitta satr. Komponent provider’ning boshqa proplari bilan nima bo‘lishidan qat’i nazar, faqat shu satr o‘zgarganda render qilinadi; `<I18nT>` ham ularga bog‘liq emas:

```tsx
const title = useT('page.title')
```

Istalgan vaqtda qo‘shimcha lug‘atlarni yuklang:

```tsx
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

useEffect(() => {
  import('./locales/de.json').then((m) => addTranslations('de', m.default))
  addRouteTranslations('en', 'about', { title: 'About us' })
  setRoute('about') // t('title') now reads the 'about' dictionary first
}, [])
```

Nusxaning o‘zida `fetch` orqali JSON uchun `loadFromUrl(url, { locale, routeName })` ham bor.

## Lokalni almashtirish {#switch-locale}

```tsx
const { setLocale, switchLocale } = useI18n()

setLocale('de') // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Almashtirish hech narsa yuklamaydi; avval lokalning lug‘atini qo‘shing. Store’ga yozish React uchun sinxron, hatto `startTransition` ichida ham, shuning uchun yo‘q lug‘at tufayli suspend bo‘ladigan komponent o‘zining fallback’ini ko‘rsatadi. `useLocaleSwitch` avval yuklaydi va lug‘at kelguncha eski UI’ni saqlaydi:

```tsx
const [switchTo, pending] = useLocaleSwitch((locale) => i18n.loadFromUrl(`/locales/${locale}.json`, { locale }))

<button disabled={pending} onClick={() => switchTo('de')}>Deutsch</button>
```

Oxirgi chaqiruv ustun turadi. Muvaffaqiyatsiz yuklash rad etiladi va lokalni avvalgidek qoldiradi.

`<I18nGroup>` prefiksli `t` ni render-prop bolasiga uzatadi. Uning ichidagi `<I18nT>` va `t()` prefikslanmaydi:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Marshrutlash {#routing}

React Router adapteri asosiy kirish nuqtasi hech qachon `react-router-dom` ni import qilmasligi uchun alohida subpath’da joylashgan. Unga `useLocation()` va `useNavigate()` kerak, shuning uchun uni router ostidagi komponent ichida yarating:

```tsx
// src/App.tsx
import { useMemo } from 'react'
import { BrowserRouter, Route, Routes, useLocation, useNavigate } from 'react-router-dom'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/react'
import { createReactRouterAdapter } from '@i18n-micro/react/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Localized() {
  const location = useLocation()
  const navigate = useNavigate()
  // memoized: a new object on every render re-renders every `useI18n()` consumer
  const routingStrategy = useMemo(() => createReactRouterAdapter(locales, 'en', location, navigate), [location, navigate])
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      <Routes>
        <Route path="/:locale?" element={<Home />} />
        <Route path="/:locale?/about" element={<About />} />
      </Routes>
    </I18nProvider>
  )
}

export default function App() {
  return (
    <BrowserRouter>
      <Localized />
    </BrowserRouter>
  )
}
```

Adapter standartdan tashqari har bir lokalga prefiks qo‘shadi (`/about`, `/de/about`) va `<I18nLink>` ni React Router’ning `<Link>` komponenti sifatida render qiladi. Lokalni URL’dan o‘zingiz o‘rnating (masalan, effektda `useParams().locale` dan). Boshqa har qanday router uchun `getCurrentPath`, `push` va `replace` (barchasi majburiy) bilan adapter yozing — [Router adapteri](/uz/integrations/overview#router-adapter) ga qarang.

## SSR {#ssr}

`renderToString` ishlaydi: `useI18n()` server snapshot’iga ega. Har bir so‘rov uchun bitta nusxa yarating va render qilishdan oldin uning lug‘atlarini qo‘shing, shunda turli lokallardagi so‘rovlar holatni bo‘lishmaydi, yoki provider’ga oddiy ma’lumot uzating.

### Gidratatsiya {#hydration}

Sonlar, ko‘plik shakllari va matn o‘z holicha gidratatsiya qilinadi. Sana vaqt mintaqasiga, nisbiy sana esa soatga bog‘liq: serverda va brauzerda `timeZone` ni o‘rnating, `tdr` uchun esa brauzerga server vaqtini `now` bilan bering. `date` yoki `relativeDate` bilan `<I18nT>` `suppressHydrationWarning` ni o‘rnatadi, shuning uchun farq gidratatsiyani buzmaydi, lekin serverning matni matn o‘zgarguncha qoladi. Bu faqat bir darajaga yetadi: tarjimani elementga o‘raydigan `children` farq bo‘lganda baribir xato beradi, shuning uchun ularga ham bir xil `timeZone` bering.

### Server komponentlari {#server-components}

Paket o‘zining klient kodini `'use client'` bilan belgilaydi. `@i18n-micro/react/server` da `createI18n` va nusxani prop sifatida qabul qiladigan hook’siz `I18nT` bor, shuning uchun matn klient bundle’iga tushmaydi. `react-server` sharti ostida, masalan Next.js app router’da, asosiy kirish nuqtasi ham unga aniqlanadi, lekin TypeScript buni standart bo‘yicha bilmaydi: `/server` dan import qiling. `@i18n-micro/react/client` har doim klient kirish nuqtasini beradi.

```tsx
// app/[locale]/layout.tsx: a server component
import { cache } from 'react'
import { createI18n, I18nT } from '@i18n-micro/react/server'
import { I18nProvider } from '@i18n-micro/react/client'
import { loadMessages } from './messages'

const getI18n = cache(async (locale: string) => createI18n({ locale, messages: await loadMessages(locale) }))

export default async function Layout({ params, children }) {
  const { locale } = await params
  const i18n = await getI18n(locale)
  return (
    <I18nProvider locale={locale} messages={{ [locale]: i18n.resolveTranslations() }}>
      <h1>
        <I18nT i18n={i18n} keypath="title" />
      </h1>
      {children}
    </I18nProvider>
  )
}
```

`react-server-dom-webpack` orqali render qilingan; Next.js ilovasining o‘zi bunga qarshi ishga tushirib ko‘rilmagan.

## Preact {#preact}

`@i18n-micro/preact` xuddi shu manbadan, Preact’ning o‘zida, `preact/compat` siz build qilinadi: bir xil nusxa, provider, hook’lar va komponentlar. Farqlar:

| | React | Preact |
| --- | --- | --- |
| Peer bog‘liqlik | `react` (+ ixtiyoriy `react-router-dom`) | `preact` `^10.0.0 \|\| ^11.0.0`, 10.29 va 11.1 da sinovdan o‘tgan |
| Nusxa klassi | `ReactI18n` | `PreactI18n` |
| Router adapteri | `/router` dan `createReactRouterAdapter` | `/router` dan `createBrowserHistoryAdapter(locales, defaultLocale, ssrUrl?)` |
| Qayta render | `useSyncExternalStore` | store’ni qayta tekshiradigan layout-effekt obunasi |
| Server komponentlari | `/server`, `/client` | yo‘q |

`createBrowserHistoryAdapter` har qanday History API routeri (wouter, preact-router) bilan ishlaydi: `push` va `replace` `history.pushState` / `replaceState` ni chaqiradi va `popstate` ni yuboradi, `<I18nLink>` esa `push` orqali navigatsiya qiladigan oddiy `<a>` ni render qiladi. Serverda manzil satri yo‘q: so‘rovning URL’ini `ssrUrl` sifatida uzating, aks holda havolalar va almashtirgich `/` dagidek render qilinadi. Brauzerda manzil satri ustun turadi.

```tsx
// src/main.tsx
import { render } from 'preact'
import { createI18n, I18nProvider } from '@i18n-micro/preact'
import { createBrowserHistoryAdapter } from '@i18n-micro/preact/router'
import { App } from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={createBrowserHistoryAdapter(locales, 'en')}>
    <App />
  </I18nProvider>,
  document.getElementById('app')!,
)
```

To‘liq signaturalar: [Preact ma’lumotnomasi](/uz/api/packages/preact).
