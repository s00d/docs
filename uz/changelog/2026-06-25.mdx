Ushbu reliz **`useI18nHead`**ni qo'shadi — o'rnatilgan `02.meta` plagini ustidan i18n SEO sozlamalarini qayta belgilash uchun sahifa darajasidagi composable. Maxsus meta plagini yoki `meta: false` ishlatmasdan, har bir marshrut uchun `hreflang`, canonical, `og:url` va Open Graph teglarini sozlang.

## Nima yangi? {#what’s-new}

### `useI18nHead` composable {#usei18nhead-composable}

`meta: true` (standart) bo'lganda istalgan sahifada `useI18nHead`ni chaqiring. Modul har bir marshrut yangilanishida sizning kiritgan ma'lumotlaringizni `useLocaleHead`dan keyin birlashtiradi:

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

Statik obyektlar, reaktiv getterlar, `meta` / `link` qo'shish, o'rnatilgan guruhlar uchun `replace` va avtomatik yaratilgan teglarni olib tashlash uchun `disable` qo'llab-quvvatlanadi. [`useI18nHead`](/uz/composables/useI18nHead) sahifasiga qarang.

### `mergeI18nHead` yordamchi funksiyasi (`@i18n-micro/utils`) {#mergei18nhead-utility-@i18n-micro/utils}

Freymvorkka bog'liq bo'lmagan birlashtirish mantig'i `@i18n-micro/utils/merge-i18n-head` ichida joylashgan — u `02.meta` plagini tomonidan ishlatiladi va alohida test qilinishi mumkin. Turlar (`I18nHeadInput`, `I18nHeadLink`, `I18nHeadMeta`) `@i18n-micro/types`dan eksport qilinadi.

### Plagin integratsiyasi {#plugin-integration}

- **`02.meta`** — `useLocaleHead` natijasini `useI18nHead`dagi sahifa holati bilan `useHead` orqali birlashtiradi
- **`01.plugin`** — marshrut nomi o'zgarganda `resetPageHead()` orqali sahifa sozlamalarini tiklaydi (composable bilan umumiy holat)

### Hujjatlar va testlar {#documentation-&-tests}

- Yangi qo'llanma: CMS/maqola misollari bilan [`useI18nHead`](/uz/composables/useI18nHead)
- Yangilangan [SEO](/uz/guide/seo) va [`useLocaleHead`](/uz/composables/useLocaleHead) — qaysi API'ni qachon ishlatish kerak
- Playwright + Vitest qamrovi: SSR, SPA navigatsiyasi, qayta yuklash, `nuxi generate`, qisman muqobillar, `x-default`, reaktiv mijoz yuklanishi

## Odatiy foydalanish holatlari {#typical-use-cases}

| Holat                                          | Yondashuv                                                            |
| ---------------------------------------------- | -------------------------------------------------------------------- |
| Qisman tarjimalarga ega blog/CMS               | API lokallaridan `replace.hreflang` + `replace.ogAlternates`         |
| CMS'dan maxsus canonical                       | `replace.canonical` + `replace.ogUrl`                                |
| Faqat landing sahifa uchun OG                  | `meta: [{ property: 'og:title', ... }]` — modul hreflang'ini saqlang |
| Sahifada hreflang yo'q                         | `disable: ['hreflang', 'x-default']`                                 |
| Maxsus plaginni almashtirish (`i18nManualHreflang`) | Har bir kontent sahifasida `useI18nHead` + `meta: true`         |

**JSON-LD** `useHead({ script: [...] })` ichida qoladi — `useI18nHead` tuzilgan ma'lumotlarni yaratmaydi.

## Buzuvchi o'zgarishlar {#breaking-changes}

Standart `nuxt.config` foydalanishi uchun yo'q. Yangi composable va utils subpath qo'shimcha xususiyatlardir.

## Nima uchun bu muhim {#why-it-matters}

- CMS postlari, yangiliklar yoki har bir lokal uchun alohida URL'ga ega qo'llanmalar uchun **maxsus meta plagini kerak emas**
- **Yagona pipeline** — modul standartlari + sahifa sozlamalari bitta `useHead` chaqiruvida
- **Tur xavfsizligi** — `buildArticleHead(content)` kabi yordamchilar uchun `I18nHeadInput`

To'liq o'zgarishlar jurnali reliz bilan birga [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md)da e'lon qilinadi.
