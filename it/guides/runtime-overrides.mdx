# Override i18n a runtime

Usa questa guida quando ti serve un unico artefatto di build che gira con valori predefiniti di locale diversi per ambiente (ad esempio istanze di tenant differenti).

## Cosa può essere sovrascritto a runtime

Il modulo supporta override sicuri a runtime per:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Questi override vengono applicati sopra la config in fase di build da `.nuxt/i18n.strategy.mjs` e `.nuxt/i18n.config.mjs`.

## Cosa non può essere sovrascritto a runtime

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) è una responsabilità in fase di build perché influenza il comportamento delle route generate.

Se passi un override della strategia a runtime, viene ignorato e viene emesso un warning.

## Override basati su RuntimeConfig

Fornisci i valori runtime sotto `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Override tramite variabili d'ambiente

Puoi anche configurare gli override tramite variabili d'ambiente:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (separati da virgola, ad esempio `fr,it`)

Sono supportati anche gli alias di fallback:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Regole di validazione

A runtime, il modulo valida gli override per evitare stati rotti:

- Non puoi disabilitare tutte le locale.
- `defaultLocale` deve puntare a una locale abilitata.
- `fallbackLocale` deve esistere tra le locale dichiarate.

Se un override non è valido, il modulo mantiene un valore sicuro e registra un warning.

## Note per deploy multi-istanza

Questa funzionalità runtime è progettata per attivazione della locale e valori predefiniti per istanza senza ricompilare.

Se le istanze richiedono strategie URL diverse (`no_prefix` vs `prefix`), usa build separate per ogni strategia.

## Locale disabilitate e payload statici

`runtimeConfig.public.i18nRuntime.disabledLocales` aggiorna routing, switcher e l'**handler** del payload Nitro. Tuttavia Nitro serve i file sotto `public/` **prima** di quell'handler.

Se `translationPayloads.publicAssets` (o la copia pubblica forzata dell'SSR Node) ha già scritto `/_locales/\{page\}/\{locale\}/data.json`, una disabilitazione a runtime non può nascondere quel file. Preferisci `locale.disabled: true` in fase di build in modo che il premerge non emetta i payload statici di quella locale.
