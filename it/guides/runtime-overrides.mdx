# Override i18n a runtime

Usa questa guida quando hai bisogno che un singolo artefatto di build venga eseguito con impostazioni predefinite di locale differenti per ambiente (ad esempio: istanze di tenant diverse).

## Cosa può essere sovrascritto a runtime

Il modulo supporta override sicuri a runtime per:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Questi override vengono applicati sopra la configurazione di build da `.nuxt/i18n.strategy.mjs` e `.nuxt/i18n.config.mjs`.

## Cosa non può essere sovrascritto a runtime

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) è una questione di build-time perché influenza il comportamento delle rotte generate.

Se passi un override runtime della strategia, viene ignorato ed emesso un avviso.

## Override tramite RuntimeConfig

Fornisci valori runtime sotto `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Override tramite variabili d'ambiente

Puoi anche configurare gli override tramite variabili d'ambiente:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (separati da virgola, ad es. `fr,it`)

Sono supportati anche gli alias di fallback:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Regole di validazione

A runtime, il modulo valida gli override per evitare stati corrotti:

- Non puoi disabilitare tutte le locale.
- `defaultLocale` deve puntare a una locale abilitata.
- `fallbackLocale` deve esistere nelle locale dichiarate.

Se un override non è valido, il modulo mantiene un valore sicuro e registra un avviso.

## Note per i deployment multi-istanza

Questa funzionalità runtime è progettata per l'attivazione di locale e le impostazioni predefinite per singola istanza senza ricostruzione.

Se le istanze richiedono strategie URL differenti (`no_prefix` vs `prefix`), usa build separate per ciascuna strategia.

## Locale disabilitate e payload statici

`runtimeConfig.public.i18nRuntime.disabledLocales` aggiorna routing, switcher e l'**handler** del payload Nitro — ma Nitro serve i file sotto `public/` **prima** di quell'handler.

Se `translationPayloads.publicAssets` (o la copia pubblica forzata di Node SSR) ha già scritto `/_locales/\{page\}/\{locale\}/data.json`, un disable a runtime non può nascondere quel file. Preferisci `locale.disabled: true` in fase di build in modo che il premerge non emetta i payload statici di quella locale.
