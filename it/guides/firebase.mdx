# 🔥 Deployment su Firebase AppHosting

## 📖 Introduzione

Firebase AppHosting è una potente piattaforma per il deployment di applicazioni Nuxt con infrastruttura serverless. Tuttavia, quando si effettua il deploy di applicazioni con `nuxt-i18n-micro`, potresti incontrare problemi specifici legati al modo in cui vengono serviti i file JSON di traduzione. Questa guida fornisce soluzioni complete per assicurarsi che le traduzioni funzionino correttamente in produzione.

## ⚠️ Problemi comuni

### File di traduzione non applicati

**Sintomi:**

- ✅ Le traduzioni funzionano perfettamente in sviluppo (`nuxt dev`)
- ❌ Dopo il deploy su Firebase AppHosting, i file JSON si caricano ma le traduzioni non vengono applicate
- ❌ Nessun errore appare nella console
- ❌ I file di traduzione sono visibili nella scheda Network ma hanno `Content-Type: text/html` errato invece di `application/json`

**Causa principale:**

Firebase AppHosting (e altre piattaforme che usano il prerendering Nitro) possono servire i file JSON pre-renderizzati con tipi MIME errati. Quando il browser riceve file JSON con `Content-Type: text/html`, non può analizzarli correttamente, causando il fallimento silenzioso delle traduzioni.

## ✅ Soluzioni

### Soluzione 1: Configurazione delle route rules (consigliata)

La soluzione più semplice è aggiungere header espliciti per le rotte di traduzione nel tuo `nuxt.config.ts`:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**Benefici:**

- ✨ Configurazione semplice
- 🚀 Migliora le prestazioni con un caching adeguato
- 🔒 Funziona su tutte le piattaforme di deployment

### Soluzione 2: Base URL API personalizzato

Se stai usando un `apiBaseUrl` personalizzato (solo prefisso di percorso), regola le route rules di conseguenza:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### Soluzione 3: Configurazione specifica per Firebase

Crea o aggiorna il tuo file `firebase.json` nella root del progetto:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```

### Soluzione 4: Configurazione delle Firebase Functions

Per il deployment con Firebase Functions, assicurati che il tuo `functions/package.json` includa le dipendenze necessarie:

```json
{
  "name": "functions",

    "node": "18"
```

## 🔍 Debug

### Abilita la modalità debug

Aggiungi il logging di debug per identificare i problemi:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

Questo produrrà log dettagliati su:

- 📝 Caricamento dei file di traduzione
- 🔄 Operazioni di cache
- ⚠️ Errori di caricamento

### Controlla la scheda Network

1. Apri DevTools → scheda Network
2. Filtra per "data.json"
3. Clicca su una richiesta di file di traduzione
4. Verifica gli **header di risposta**:
   - ✅ `Content-Type: application/json` (corretto)
   - ❌ `Content-Type: text/html` (errato - da correggere)

### Verifica l'output di prerender

Dopo la build, controlla che i file di traduzione siano generati:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

Dovresti vedere `data.json` per ciascuna locale sotto ciascuna pagina.

## 🚀 Configurazione della build

### Preset Nitro

Per Firebase AppHosting, assicurati di usare il preset corretto:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### Configurazione di prerender

Configura il prerendering per prestazioni ottimali:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

## ✅ Checklist di verifica

Dopo aver applicato le correzioni, verifica che tutto funzioni:

- [ ] La build viene completata senza errori
- [ ] I file JSON di traduzione si trovano in `.output/public/_locales/\{page\}/\{locale\}/data.json`
- [ ] La scheda Network mostra `Content-Type: application/json` per i file di traduzione
- [ ] Le traduzioni vengono mostrate correttamente al primo caricamento della pagina
- [ ] Nessun mismatch di idratazione in console
- [ ] Il cambio di lingua funziona correttamente
- [ ] I meta tag SEO vengono generati correttamente

## 🔄 Flusso di deployment

### 1. Preparazione della build

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. Deploy su Firebase

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. Verifica del deployment

1. Visita il tuo sito deployato
2. Apri DevTools → scheda Network
3. Naviga a una pagina
4. Controlla che `/_locales/index/en/data.json` (o la tua locale predefinita) si carichi con:
   - Status: 200
   - Content-Type: application/json
   - La risposta contiene JSON valido

## 🔧 Risoluzione dei problemi

### Problema: errori 404 per i file di traduzione

**Soluzione:** Assicurati che i file di traduzione vengano copiati nella directory di output:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### Problema: le traduzioni funzionano su alcune pagine ma non su altre

**Soluzione:** Controlla se vengono generate traduzioni specifiche per pagina:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

Se le traduzioni specifiche per pagina mancano, assicurati che `disablePageLocales` non sia impostato a `true`:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### Problema: caricamento lento delle traduzioni

**Soluzione:** Ottimizza caching e preloading:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## 💡 Suggerimenti

1. **Testa sempre in un ambiente simile alla produzione** prima del deploy
2. **Usa la modalità debug** durante la configurazione iniziale per rilevare precocemente i problemi
3. **Monitora i tassi di cache hit** per ottimizzare le prestazioni
4. **Mantieni piccoli i file di traduzione** per un caricamento più veloce
5. **Usa header di cache adeguati** per ridurre il carico del server

## ⚡ Ottimizzazione delle prestazioni

### Abilita la compressione

Firebase gestisce automaticamente la compressione Gzip/Brotli, ma assicurati che la tua build sia ottimizzata:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### Lazy load delle traduzioni

`Nuxt I18n Micro` esegue automaticamente il lazy-load delle traduzioni per pagina. Le traduzioni vengono caricate solo quando necessario, riducendo la dimensione iniziale del bundle. Questa è una funzionalità integrata - non richiede configurazione aggiuntiva.

Per ottimizzare ulteriormente:

- Usa `disablePageLocales: false` (predefinito) per abilitare le traduzioni specifiche per pagina
- Mantieni minime le traduzioni di root
- Usa file di traduzione specifici per rotta per il contenuto della pagina

<Tip>
Il modulo imposta automaticamente header `Content-Type` corretti a partire dalla versione **v3.0.0+**. Se stai riscontrando problemi, aggiorna all'ultima versione:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
