# Dettagli delle opzioni

Il modulo fornisce ampie opzioni di configurazione per personalizzare la tua configurazione di internazionalizzazione.

### 🌍 Impostazioni di locale core

#### `locales`

{/* generated:option:locales — do not edit; run `pnpm run docs:generate` */}

**Tipo** `Locale[]` · **Predefinito** `[]`

Elenco delle locale supportate.
Ogni voce definisce un codice locale più metadati opzionali (ISO, direzione, display name, ecc.).

{/* /generated:option:locales */}

Ogni oggetto locale supporta:

| Proprietà         | Tipo      | Richiesta | Descrizione                                           |
| ---------------- | --------- | -------- | ----------------------------------------------------- |
| `code`           | `string`  | ✅       | Identificatore unico (ad es. `'en'`)                      |
| `displayName`    | `string`  | ❌       | Nome leggibile per switcher (ad es. `'English'`) |
| `iso`            | `string`  | ❌       | Codice ISO (ad es. `'en-US'`)                            |
| `dir`            | `string`  | ❌       | Direzione del testo (`'ltr'` o `'rtl'`)                   |
| `disabled`       | `boolean` | ❌       | Disabilita nel menu a discesa se `true`                         |
| `baseUrl`        | `string`  | ❌       | URL di base per domini specifici della locale                  |
| `baseDefault`    | `boolean` | ❌       | Rimuove il prefisso della locale dagli URL                        |
| `fallbackLocale` | `string`  | ❌       | Fallback per locale (sovrascrive il globale)                |
| `[key: string]`  | `unknown` | ❌       | Qualsiasi proprietà personalizzata (vedi sotto)                     |

**Esempio**:

```typescript
locales: [
  { code: 'en', iso: 'en-US', dir: 'ltr' },
  { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
  { code: 'ar', iso: 'ar-SA', dir: 'rtl', disabled: true },
  {
    code: 'de',
    iso: 'de-DE',
    dir: 'ltr',
    baseUrl: 'https://de.example.com',
    baseDefault: true,
  },
]
```

<Warning>
L'uso di `baseUrl` può portare alla duplicazione delle rotte interne come link esterni, complicando il routing e la manutenzione. Considera invece la creazione di link esterni direttamente per locale specifiche.
</Warning>

#### Proprietà locale personalizzate

Puoi aggiungere qualsiasi proprietà personalizzata agli oggetti locale. Vengono passate al runtime e accessibili tramite `$getLocales()`:

```typescript
locales: [
  { code: 'en', iso: 'en-US', flag: '🇬🇧', currency: 'GBP' },
  { code: 'de', iso: 'de-DE', flag: '🇩🇪', currency: 'EUR' },
  { code: 'ru', iso: 'ru-RU', flag: '🇷🇺', currency: 'RUB' },
]
```

Accedivi nei componenti:

```vue
<template>
  <ul>
    <li v-for="locale in $getLocales()" :key="locale.code">{{ locale.flag }} {{ locale.displayName }} ({{ locale.currency }})</li>
  </ul>
</template>
```

Per impostazione predefinita, le proprietà personalizzate sono tipizzate come `unknown`. Per ottenere pieno supporto TypeScript, usa la **module augmentation**. Crea un file di dichiarazione (ad es. `app/i18n.d.ts` o qualsiasi `.d.ts` incluso nel tuo `tsconfig`):

```typescript
// app/i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
    currency?: string
  }
}
```

Dopo di ciò, tutte le proprietà personalizzate sono completamente tipizzate:

```typescript
const locales = $getLocales()
locales[0].flag // string | undefined ✅
locales[0].currency // string | undefined ✅
```

#### `defaultLocale`

{/* generated:option:defaultLocale — do not edit; run `pnpm run docs:generate` */}

**Tipo** `string` · **Predefinito** `'en'`

La locale da usare quando non è possibile determinare una locale da URL o preferenze utente.

{/* /generated:option:defaultLocale */}

#### `strategy`

{/* generated:option:strategy — do not edit; run `pnpm run docs:generate` */}

**Tipo** `Strategies` · **Predefinito** `'prefix_except_default'`

Strategia di routing URL per i prefissi delle locale.

- `'no_prefix'` — nessuna locale nell'URL; locale memorizzata nel cookie.
- `'prefix_except_default'` — prefisso in tutte le locale eccetto quella predefinita.
- `'prefix'` — prefisso sempre, inclusa la locale predefinita.
- `'prefix_and_default'` — come `prefix`, ma la locale predefinita è accessibile anche senza prefisso.

{/* /generated:option:strategy */}

<CodeGroup>
```typescript no_prefix
strategy: 'no_prefix'
// Routes: /about, /contact
// Locale detection via browser/cookies
```

```typescript prefix_except_default
strategy: 'prefix_except_default'
// Default locale: /about, /contact
// Other locales: /fr/about, /de/contact
```

```typescript prefix
strategy: 'prefix'
// All locales: /en/about, /fr/about, /de/about
```

```typescript prefix_and_default
strategy: 'prefix_and_default'
// Both prefixed and non-prefixed versions for default locale
```
</CodeGroup>

### 📂 Gestione delle traduzioni
#### `translationDir`

{/* generated:option:translationDir — do not edit; run `pnpm run docs:generate` */}

**Tipo** `string` · **Predefinito** `'locales'`

Percorso della directory contenente i file JSON di traduzione, relativo alla root del progetto.

{/* /generated:option:translationDir */}

```typescript
translationDir: 'i18n' // Custom directory
// Nuxt 4 colocation example:
// translationDir: 'app/locales'
```

I percorsi vengono risolti dalla **root del progetto** Nuxt (`rootDir`), non da `app/`. Con Nuxt 4, la configurazione tipica è `app/pages/` per le rotte e `locales/` (o `app/locales` se imposti `translationDir`) per i file JSON.
#### `disablePageLocales`

{/* generated:option:disablePageLocales — do not edit; run `pnpm run docs:generate` */}

**Tipo** `boolean` · **Predefinito** `false`

Disabilita i file di traduzione per pagina.
Quando `true`, vengono caricate solo le traduzioni globali (`\{locale\}.json`);
i file specifici per pagina (`pages/\{page\}/\{locale\}.json`) non vengono generati o caricati.

{/* /generated:option:disablePageLocales */}

Quando abilitato, vengono usati solo i file di traduzione di root:

```tree
locales/
├── en.json
├── fr.json
└── ar.json
```
#### `fallbackLocale`

{/* generated:option:fallbackLocale — do not edit; run `pnpm run docs:generate` */}

**Tipo** `string` · **Predefinito** `undefined (nessun fallback; restituisce la chiave grezza)`

Codice locale di fallback globale.
Quando una chiave di traduzione manca nella locale attiva, il modulo la cerca
in questa locale prima di restituire la chiave stessa.

{/* /generated:option:fallbackLocale */}

```typescript
fallbackLocale: 'en' // Global fallback
```
#### `types`

{/* generated:option:types — do not edit; run `pnpm run docs:generate` */}

**Tipo** `boolean` · **Predefinito** `true`

Genera dichiarazioni di tipo TypeScript per `useI18n`, `$t` e helper correlati
basate sulle chiavi di traduzione nei tuoi file di locale predefiniti.

{/* /generated:option:types */}

Quando abilitato, il modulo emette `.nuxt/i18n.d.ts` durante la build con chiavi di traduzione tipizzate. Imposta a `false` se preferisci helper non tipizzati o usi un generatore esterno.

Questo generatore integrato è separato dal pacchetto opzionale [`@i18n-micro/types-generator`](/integrations/types-generator), che può produrre file di tipi più rigorosi o autonomi per monorepo e CI.

```typescript
types: false // Disable built-in key typing
```
#### `routeLocales`

{/* generated:option:routeLocales — do not edit; run `pnpm run docs:generate` */}

**Tipo** `Record<string, string[]>` · **Predefinito** —

Restrizioni di locale per rotta, estratte dalle chiamate `defineI18nRoute()`.
Mappa un percorso di rotta (ad es. `'/about'`) a un array di codici locale ammessi.
Le rotte non elencate non hanno restrizioni (tutte le locale ammesse).

{/* /generated:option:routeLocales */}

Mappa un percorso di rotta (ad es. `'/about'`) ai codici locale ammessi. Le rotte non elencate consentono tutte le locale configurate.

Normalmente configuri questo tramite [`defineI18nRoute`](/guides/custom-locale-routes) nelle pagine piuttosto che in `nuxt.config`. Il modulo unisce le dichiarazioni a livello di pagina in questa mappa in fase di build.
#### `routeDisableMeta`

{/* generated:option:routeDisableMeta — do not edit; run `pnpm run docs:generate` */}

**Tipo** `Record<string, boolean \| string[]>` · **Predefinito** —

Disabilitazione dei meta tag per rotta, estratta dalle chiamate `defineI18nRoute()`.
Mappa un percorso di rotta a `true` (disabilita tutti i meta) o a un array di codici locale
per i quali i meta dovrebbero essere disabilitati.

{/* /generated:option:routeDisableMeta */}

- `true` — disabilita tutti i meta SEO per la rotta
- `string[]` — disabilita i meta solo per i codici locale elencati

Come `routeLocales`, questo è tipicamente impostato nei componenti di pagina, non manualmente nella configurazione.
#### `experimental`

{/* generated:option:experimental — do not edit; run `pnpm run docs:generate` */}

**Tipo** `Record<string, unknown>` · **Predefinito** —

Contenitore per opzioni sperimentali/instabili.
I contenuti possono cambiare o essere rimossi senza preavviso tra versioni minor.

{/* /generated:option:experimental */}

La maggior parte dei precedenti flag `experimental.*` è stata promossa a opzioni top-level in v3 (ad esempio `hmr`). Preferisci le opzioni top-level documentate. Usa `experimental` solo quando segui una release note o una guida di migrazione che fa riferimento a una chiave specifica.

### 🔍 SEO e meta tag
#### `meta`

{/* generated:option:meta — do not edit; run `pnpm run docs:generate` */}

**Tipo** `boolean` · **Predefinito** `true`

Genera automaticamente i meta tag SEO (`hreflang`, `canonical`, `og:url`, `og:locale`).

{/* /generated:option:meta */}

```typescript
meta: true // Generate alternate links, canonical URLs, etc.
```
#### `metaBaseUrl`

{/* generated:option:metaBaseUrl — do not edit; run `pnpm run docs:generate` */}

**Tipo** `string` · **Predefinito** `undefined`

URL di base per i meta tag SEO (canonical, og:url, hreflang).

- Una stringa URL concreta (ad es. `'https://example.com'`) — usata così com'è (priorità massima).
- `undefined` — ricade su `site.url` da `nuxt-site-config` quando quel modulo è
  presente, altrimenti l'origine della richiesta corrente
  (`useRequestURL().origin` sul server, `window.location.origin` sul client).

{/* /generated:option:metaBaseUrl */}

Priorità quando non impostato: `site.url` da `nuxt-site-config` (se installato) → origine della richiesta
(`useRequestURL().origin` sul server con `X-Forwarded-Host` / `X-Forwarded-Proto`,
`window.location.origin` sul client). Ideale per **stack SEO** che impostano già `site.url`,
e per deployment **multi-dominio** quando `site.url` è omesso.

- Qualsiasi altra stringa — usata come URL di base statico (vince su `site.url`).

```typescript
// Prefer sharing the SEO stack origin — omit metaBaseUrl when site.url is set
site: { url: 'https://example.com' }

// Or pin an explicit override
metaBaseUrl: 'https://example.com'
```
#### `canonicalQueryWhitelist`

{/* generated:option:canonicalQueryWhitelist — do not edit; run `pnpm run docs:generate` */}

**Tipo** `string[]` · **Predefinito** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

Elenco di nomi di parametri di query preservati nei meta tag canonical e `og:url`.
I parametri non presenti in questo elenco vengono rimossi dall'URL canonico.

{/* /generated:option:canonicalQueryWhitelist */}

```typescript

```

### 🔄 Funzionalità avanzate
#### `globalLocaleRoutes`

{/* generated:option:globalLocaleRoutes — do not edit; run `pnpm run docs:generate` */}

**Tipo** `GlobalLocaleRoutes` · **Predefinito** `\{\}`

Configurazione delle locale a livello di rotta globale.
Consente di limitare o personalizzare le rotte di locale per pagine specifiche senza
modificarne i componenti.

- `false` — esclude la rotta dalla localizzazione.
- `Record<LocaleCode, string>` — percorsi personalizzati per locale.

{/* /generated:option:globalLocaleRoutes */}

```typescript
globalLocaleRoutes: {
  'about': {
    en: '/about-us',
    fr: '/a-propos',
    de: '/uber-uns'
  },
  'unlocalized': false // Disable localization entirely
}
```

### 🔢 Personalizzazione
#### `plural`

{/* generated:option:plural — do not edit; run `pnpm run docs:generate` */}

**Tipo** `PluralFunc` · **Predefinito** `pluralizzazione integrata (indice forma per conteggio)`

Funzione di pluralizzazione personalizzata.
Riceve `(key, count, params, locale, getter)` e deve restituire la forma plurale
selezionata come stringa, oppure `null`/`undefined` per ricadere sulla logica
integrata `defaultPlural` (così puoi sovrascrivere solo alcune locale).

Per il modulo Nuxt la funzione viene serializzata con `.toString()` in
`.nuxt/i18n.plural.mjs` — deve essere autonoma (nessun import / outer scope).
Un percorso file stringa **non** è supportato.

{/* /generated:option:plural */}

##### Come funziona

Le traduzioni usano `|` per separare le forme plurali:

```json
{
  "apples": "no apples | one apple | {count} apples"
}
```

Usa `$tc('apples', count)` o `$tc('cart', \{ count, name \})` quando una forma ha bisogno di più di `\{count\}` — passa **`count` e altri parametri nell'oggetto del secondo argomento**, non come terzo argomento (il terzo è solo `defaultValue`).

La chiamata a `$tc` invoca la funzione `plural`, che:

1. Chiama `t(key)` per ottenere la stringa di traduzione grezza (ad es. `"no apples | one apple | \{count\} apples"`)
2. Divide con `|` per ottenere l'array di forme
3. Seleziona una forma in base a `count`
4. Sostituisce `\{count\}` con il numero effettivo

L'implementazione **predefinita** seleziona per indice: `count < forms.length ? forms[count] : forms[last]`. Ciò funziona per casi semplici (0 → prima forma, 1 → seconda, 2+ → ultima).

##### Funzione plurale personalizzata

Per lingue con regole di pluralizzazione complesse (ad es. russo, arabo, polacco), sovrascrivi l'opzione `plural`.

<Danger>
La funzione viene serializzata tramite `.toString()` e iniettata in un modulo virtuale in fase di build. Ciò significa:

- **Deve usare la parola chiave `function`** — NON la sintassi shorthand dei metodi, NON arrow function con riferimenti esterni
- **Nessun import o riferimento esterno** — la funzione deve essere completamente autonoma (un percorso file come `plural: '~/i18n/plural.ts'` **non** è supportato)
- **Nessuna sintassi TypeScript-only** che non sopravvive a `.toString()` (le annotazioni di tipo vanno bene in `nuxt.config.ts` perché Nuxt le rimuove)
- Restituire `null` / `undefined` ricade sulla `defaultPlural` integrata (utile per override per locale)
</Danger>

**Esempio: Pluralizzazione russa** (4 forme: zero, uno, pochi, molti):

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    plural: function (key, count, _params, _locale, t) {
      const translation = t(key)
      if (!translation) return key

      const forms = translation
        .toString()
        .split('|')
        .map(function (s) {
          return s.trim()
        })
      let idx

      if (count === 0) {
        idx = 0
      } else {
        const mod10 = count % 10
        const mod100 = count % 100
        if (mod10 === 1 && mod100 !== 11) {
          idx = 1
        } else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) {
          idx = 2
        } else {
          idx = 3
        }
      }

      if (idx >= forms.length) idx = forms.length - 1
      return (forms[idx] || '').replace('{count}', String(count))
    },
  },
})
```

Con questa traduzione:

```json
{
  "apples": "нет яблок | {count} яблоко | {count} яблока | {count} яблок"
}
```

Risultati:

- `$tc('apples', 0)` → `"нет яблок"`
- `$tc('apples', 1)` → `"1 яблоко"`
- `$tc('apples', 3)` → `"3 яблока"`
- `$tc('apples', 5)` → `"5 яблок"`
- `$tc('apples', 21)` → `"21 яблоко"`

**Esempio: Inglese semplice (comportamento predefinito)**:

```typescript
// This is the built-in default — you don't need to set it explicitly
plural: function (key, count, params, _locale, t) {
  const translation = t(key, params)
  if (!translation) return null

  const forms = translation.toString().split('|')
  if (forms.length === 0) return null
  const form = count < forms.length ? forms[count] : forms[forms.length - 1]
  if (!form) return null
  return form.trim().replace('{count}', count.toString())
}
```

##### Pluralizzazione per locale

Se locale differenti necessitano di regole plurali differenti, ramifica su `locale` e restituisci `null`
per le locale che non personalizzi — la `defaultPlural` integrata gestisce il resto:

```typescript
plural: function (key, count, _params, locale, t) {
  // Only override Slavic locales; en/de/… keep the built-in rules
  if (locale !== 'ru' && locale !== 'uk') return null

  const translation = t(key)
  if (!translation) return null

  const forms = translation.toString().split('|').map(function (s) { return s.trim() })
  let idx
  if (count === 0) {
    idx = 0
  } else {
    const mod10 = count % 10
    const mod100 = count % 100
    if (mod10 === 1 && mod100 !== 11) idx = 1
    else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) idx = 2
    else idx = 3
  }
  if (idx >= forms.length) idx = forms.length - 1
  return (forms[idx] || '').replace('{count}', String(count))
}
```

`plural: '~/i18n/plural.ts'` (o qualsiasi percorso stringa) **non** è supportato. Il modulo Nuxt
serializza la funzione con `.toString()` in un file virtuale; gli import esterni e
gli helper di un altro modulo vengono rimossi e saranno `undefined` a runtime. Mantieni la
funzione completamente inline in `nuxt.config.ts` (vedi la nota di pericolo sopra).
</Warning>

#### `translationPayloads`

{/* generated:option:translationPayloads — do not edit; run `pnpm run docs:generate` */}

**Tipo** `TranslationPayloadOptions` · **Predefinito** —

Controlla come vengono emessi i payload di traduzione (Node: `public/<apiBaseUrl>`; Edge: `serverAssets` Nitro).

- **Node**: `serverAssets` significa SSR locale via `readFile` sotto `public/` (nessun `raw:` Rollup).
- **Edge**: `serverAssets` registra `serverAssets` Nitro (`assets:i18n`); non forza una copia pubblica.

Mantieni i predefiniti per la configurazione all-in-one usuale. Per cataloghi Edge grandi preferisci `mode: 'source'`.
Per deployment con CDN, disabilita gli output locali e imposta `apiBaseClientHost` / `apiBaseServerHost`.

{/* /generated:option:translationPayloads */}

```typescript
{
  mode?: 'premerged' | 'source'
  serverAssets?: boolean
  serverHandler?: boolean
  publicAssets?: boolean
  prerenderRoutes?: boolean
  publicDir?: string
  warnFileCount?: number
  warnSizeBytes?: number
}
```

**Predefinito** (`mode: 'premerged'`):

```typescript
{
  mode: 'premerged',
  serverAssets: true,
  serverHandler: true,
  publicAssets: true,
  prerenderRoutes: false
}
```

L'SSR su **Node** legge lo stesso albero copiato in `public/<apiBaseUrl>/` (`readFile`). Su **Edge**, `serverAssets` Nitro lo incorpora (nessuna copia pubblica forzata — imposta `publicAssets: true` per CDN). `mode: 'premerged'` → `\{page\}/\{locale\}/data.json` per pagina/locale; `mode: 'source'` → sorgente compatto + merge a runtime.

`serverAssets: true` su **Node** forza la copia pubblica anche se `publicAssets` è false. Su **Edge** registra solo l'embed Nitro. Preferisci `mode: 'source'` su Edge per cataloghi grandi. Senza payload locali e senza `apiBaseServerHost`, la build fallisce.

L'handler locale `/\{apiBaseUrl\}/:page/:locale/data.json`, le rotte prerender e le copie di asset pubblici rimangono output opzionali.

Per payload **pubblici** / Edge compatti:

```typescript
i18n: {
  translationPayloads: {
    mode: 'source',
  },
}
```

`mode: 'source'` mantiene compatti i file dei layer e unisce root/pagina/fallback a runtime tramite la rotta integrata `/_locales` (o `assets:i18n` di Edge). Per impostazione predefinita disabilita le copie di asset pubblici e le rotte payload pre-renderizzate.

<Warning>
Con `mode: 'source'`, `publicAssets` è `false` per impostazione predefinita (`prerenderRoutes` è sempre off a meno che tu non opti). L'hosting puramente statico senza un runtime Nitro/edge non può quindi caricare traduzioni sul client a meno che tu non abiliti uno di questi output, mantieni `serverHandler` disponibile a runtime o ospiti i payload esternamente.

Con il predefinito `mode: 'premerged'` e `publicAssets: true`, i file statici finiscono già in `public/<apiBaseUrl>/\{page\}/\{locale\}/data.json` — corrispondendo agli URL client `$fetch` — così un host statico può servirli senza Nitro.
</Warning>

<Warning>
Quando `apiBaseServerHost` o `apiBaseClientHost` è impostato, il modulo recupera JSON già uniti da quell'origine. Gli host esterni devono servire le stesse risposte `/\{apiBaseUrl\}/:page/:locale/data.json` della rotta integrata. `mode: 'source'` si applica alle directory di payload locali, non a una CDN esterna a meno che quella CDN non serva anche payload uniti a runtime.
</Warning>

Puoi anche disabilitare manualmente gli output locali duplicati e servire i payload di traduzione da una CDN o storage a oggetti:

```typescript
i18n: {
  apiBaseClientHost: 'https://cdn.example.com',
  apiBaseServerHost: 'https://cdn.example.com',
  translationPayloads: {
    serverHandler: false,
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

Se vuoi solo evitare di scrivere payload nell'output pubblico mantenendo la rotta server integrata per le richieste SSR/runtime, disabilita entrambi gli output pubblici:

```typescript
i18n: {
  translationPayloads: {
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

Su **Node**, `serverAssets: true` continua a forzare una copia pubblica per l'SSR anche quando `publicAssets` è false — imposta `serverAssets: false` e `apiBaseServerHost` se vuoi zero file di payload locali.

Usa `publicDir` per cambiare la cartella di output pubblica quando i payload vengono copiati. Predefinito a `apiBaseUrl` (`_locales`). In modalità premerged, `publicAssets` scrive lì `\{page\}/\{locale\}/data.json` (gli stessi percorsi che il client recupera). `prerenderRoutes` è un prerender Nitro opzionale delle rotte handler — di solito ridondante quando quell'albero è già stato copiato.

Se disabiliti tutti gli output di payload locali, devi configurare sia `apiBaseServerHost` (SSR) sia `apiBaseClientHost` (navigazione client). Altrimenti le traduzioni verranno risolte come oggetti vuoti e le chiavi UI potrebbero apparire non tradotte.

`warnFileCount` e `warnSizeBytes` controllano gli avvisi in fase di build quando l'output dei payload pre-uniti cresce molto (predefiniti: 500 file e 10 MB).

#### `dateBuild`

{/* generated:option:dateBuild — do not edit; run `pnpm run docs:generate` */}

**Tipo** `string \| number` · **Predefinito** —

Valore usato per il cache-busting delle richieste di traduzione (`?v=...`).

Quando non fornito, il modulo ricade su `Date.now()` (non deterministico).
Per deployment riproducibili/rolling, imposta questo su un valore stabile
(ad es. un git SHA o un numero di build).

{/* /generated:option:dateBuild */}

Per impostazione predefinita il modulo crea un fingerprint delle tue sorgenti di traduzione (SHA-256 su ogni
`<layer>/<translationDir>/**/*.json`, in ordine di layer) e usa quello. Il valore cambia solo quando una
traduzione cambia effettivamente, quindi ricostruire o riemettere il deploy di traduzioni intatte lascia intatte
le cache browser e CDN — con `httpCacheDuration` impostato a un anno, un timestamp di build invece
forzerebbe ogni client a scaricare nuovamente l'intero dizionario ad ogni deploy.

Ricade su `Date.now()` solo quando non ci sono file di traduzione da hashare.

Impostalo esplicitamente per prendere il controllo (ad es. per legare gli URL dei payload a una release piuttosto che al contenuto):

```ts
export default defineNuxtConfig({
  i18n: {
    // Any stable string/number: git SHA, CI build number, release tag, etc.
    dateBuild: process.env.GIT_SHA ?? 'local-dev',
  },
})
```
#### `httpCacheDuration`

{/* generated:option:httpCacheDuration — do not edit; run `pnpm run docs:generate` */}

**Tipo** `number` · **Predefinito** `31536000`

HTTP `Cache-Control` max-age (secondi) per `/\{apiBaseUrl\}/:page/:locale/data.json`.

Si applica interamente solo mentre `dateBuild` invalida l'URL (`?v=...`), che è il predefinito:
la risposta è quindi `public, max-age=…, immutable` e sicura per browser e CDN.

- `dateBuild: 0`/`''` — l'URL è stabile, quindi questa durata *non* viene onorata; la
  risposta diventa invece `public, max-age=0, must-revalidate`. Un lungo `max-age` su un
  URL che non cambia fissa il primo payload che un browser abbia mai visto.

- `0` — non impostare affatto `Cache-Control` (utile nel debug locale)
- Non applicato in sviluppo (`import.meta.dev`) in modo che l'HMR non sia contrastato dalla cache del browser
- Raggiunge solo le risposte servite tramite Nitro. I payload copiati in `public/` e serviti
  dalla piattaforma di hosting prendono gli header di quella piattaforma — vedi la Guida alle prestazioni.

Analogo all'`httpCacheDuration` sperimentale di `@nuxtjs/i18n` (v10.2.0), ma come header
di risposta esplicito piuttosto che come Nitro `defineCachedEventHandler` maxAge.

{/* /generated:option:httpCacheDuration */}

```ts
export default defineNuxtConfig({
  i18n: {
    // Per-build fallback (Date.now()) so immutable payloads never go stale when GIT_SHA is missing.
    dateBuild: process.env.GIT_SHA ?? String(Date.now()),
    httpCacheDuration: 86400, // 24 hours
    // httpCacheDuration: 0, // disable Cache-Control header
  },
})
```

#### `cacheTtl`

{/* generated:option:cacheTtl — do not edit; run `pnpm run docs:generate` */}

**Tipo** `number` · **Predefinito** `0`

Time-to-live (in secondi) per le voci di traduzione cacheate.
`0` significa che le voci non scadono mai.

{/* /generated:option:cacheTtl */}

```typescript
export default defineNuxtConfig({
  i18n: {
    // Limit cache to 1000 entries, each lives 10 minutes (refreshed on access)
    cacheMaxSize: 1000,
    cacheTtl: 600,
  },
})
```

<Tip>
Per la maggior parte dei progetti il predefinito (illimitato, senza scadenza) va bene — le traduzioni sono piccole e finite. Tuttavia, se il tuo progetto ha **migliaia di pagine** con `disablePageLocales: false` e **molte locale**, la cache server può crescere significativamente. In server Node.js di lunga durata ciò può portare a un uso eccessivo della memoria.

- **`cacheMaxSize`** — limita il numero di voci cacheate. Utile per limitare la memoria.
- **`cacheTtl`** — assicura che le traduzioni obsolete vengano eventualmente ricaricate dallo storage. Utile per ambienti serverless o quando le traduzioni cambiano a runtime.

**Formula per stimare le voci massime**: `numero_di_locale × (numero_di_pagine + 1)`. Ad esempio, 10 locale × 500 pagine = ~5010 voci.
</Tip>
