# Escludere file statici dal routing i18n

## Panoramica

Per impostazione predefinita, nuxt-i18n-micro esclude automaticamente i file statici comuni dall'elaborazione del routing i18n. Tuttavia, puoi anche configurare pattern di esclusione personalizzati per impedire che percorsi specifici vengano elaborati dal sistema i18n.

## Esclusioni integrate

Il modulo esclude automaticamente i seguenti tipi di file e pattern:

- **Sitemap**: `/sitemap*.xml`, `/sitemap-en.xml`, ecc.
- **File SEO**: `/robots.txt`, `/favicon.ico`
- **File PWA**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Asset statici**: file con estensioni come `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Percorsi interni di Nuxt**: qualsiasi percorso che inizia con `__` (come `/__nuxt/`)

## Pattern di esclusione personalizzati

Puoi definire pattern di esclusione personalizzati usando l'opzione `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Tipi di pattern

### Pattern stringa

- **Match esatto**: `'/api/health'` - corrisponde esattamente a `/api/health`
- **Match per prefisso**: `'/admin'` - corrisponde a `/admin` e `/admin/dashboard`
- **Wildcard**: `'/api/*'` - corrisponde a `/api/users` ma non a `/api/users/123`
- **Wildcard profonde**: `'/admin/**'` - corrisponde a `/admin/users` e `/admin/users/123`

### Espressioni regolari

Usa oggetti RegExp per il matching di pattern complessi:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Casi d'uso

### File SEO

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### Route API

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Pannelli di amministrazione

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Asset statici

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Come funziona

1. **Middleware server**: un middleware Nitro viene eseguito per primo per controllare i pattern di esclusione
2. **Elaborazione della pagina**: durante la risoluzione della pagina, i percorsi esclusi vengono saltati
3. **Route catch-all**: la route di fallback controlla le esclusioni prima dell'elaborazione
4. **Prerendering**: i percorsi esclusi non vengono inclusi nelle route pre-renderizzate

## Impatto sulle prestazioni

- I controlli di esclusione sono ottimizzati e vengono eseguiti presto nel ciclo di vita della richiesta
- I pattern integrati usano matching regex efficiente
- I pattern personalizzati vengono messi in cache e riutilizzati
- Overhead di prestazioni minimo per i percorsi esclusi

## Risoluzione dei problemi

### I file statici vengono ancora intercettati

1. **Controlla la sintassi del pattern**: assicurati che i tuoi pattern corrispondano alla struttura esatta del percorso
2. **Usa regex per pattern complessi**: le wildcard stringa hanno limitazioni
3. **Testa i pattern**: usa gli strumenti di sviluppo del browser per verificare il percorso di richiesta effettivo
4. **Controlla l'ordine**: assicurati che i pattern di esclusione siano definiti prima di altre configurazioni i18n

### Il pattern non funziona

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Modalità debug

Abilita la modalità debug per vedere l'elaborazione delle esclusioni:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Questo registrerà le decisioni di esclusione in console.

## Migrazione dai workaround

Se stavi usando workaround come route rule o middleware, ora puoi sostituirli con `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Il nuovo approccio è più affidabile e funziona a più livelli del sistema di routing.
