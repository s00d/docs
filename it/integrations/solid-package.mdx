`@i18n-micro/solid` fornisce alle app SolidJS un'istanza i18n basata su signal, un provider, `useI18n()` e quattro componenti. Usalo in un'app Solid non costruita con Nuxt. Le letture di `t()` all'interno di JSX o di effect tracciano il locale, la route e i dizionari; il modello condiviso è descritto in [Framework](/it/integrations/overview).

## Installazione {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer dependency: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (opzionale, solo per `@i18n-micro/solid/router`). Solid 2 non è ancora supportato.

## Configurazione {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` accetta `i18n`, `locales`, `defaultLocale` e `routingStrategy`; una prop omessa mantiene il valore del provider esterno, istanza compresa. `getLocaleName()` e `<I18nSwitcher>` leggono `locales`; senza di essi non hanno nulla da elencare. Le opzioni sono descritte in [l'istanza](/it/integrations/overview#the-instance). L'istanza è quella del [runtime](/it/integrations/runtime-package), con un signal sul suo store.

## Tradurre {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Chiama i metodi all'interno di JSX o di un effect così che Solid li tracci, anche `localePath` e `getLocale`; un valore letto una sola volta nel corpo del componente non si aggiorna. Sull'istanza, traccia con `i18n.locale` e `i18n.currentRoute`: `i18n.getLocale()` resta non reattivo, perché le scritture lo leggono. La lettura del locale si riattiva solo al cambio di locale, quindi un effect che lo legge e carica un dizionario viene eseguito una volta sola. Non destrutturare le props e non conservare i risultati di `t('key')` in semplici variabili.

`useI18n()` restituisce `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (un accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` e `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Cambiare locale {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Il cambio non carica nulla; aggiungi prima il dizionario del locale.

`<I18nGroup>` passa una `t` con prefisso a un figlio funzione. `<I18nT>` e `t()` al suo interno non hanno prefisso:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Routing {#routing}

L'adapter per `@solidjs/router` si trova in un subpath, così l'entry principale non importa mai il router. Richiamalo sotto il router, tipicamente nella `root` del router, dove `useNavigate` e `useLocation` funzionano:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

L'adapter aggiunge il prefisso a ogni locale tranne il predefinito (`/about`, `/de/about`), e renderizza `<I18nLink>` come `<A>` del router. `getCurrentPath` legge la location reattiva del router, così i link attivi e lo switcher la seguono; una strategia personalizzata ottiene lo stesso risultato leggendo lì un signal. Attenzione all'ordine degli argomenti: `(locales, defaultLocale, navigate, location)`. Per altri router scrivi un adapter con `getCurrentPath`, `push` e `replace` (tutti obbligatori) — vedi [Adapter del router](/it/integrations/overview#router-adapter).

## SSR {#ssr}

Per il rendering lato server, compila con `vite-plugin-solid`: la condizione di export `solid` del pacchetto gli fornisce il sorgente, così viene compilato per il server. Il `dist` precompilato è solo per il browser. L'istanza non ha `destroy()`; creane una per app, o una per richiesta sul server, e lasciala al garbage collector.
