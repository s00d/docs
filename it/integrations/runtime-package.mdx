`@i18n-micro/runtime` è l'istanza i18n indipendente dal framework: dizionari, `t()`, plurali, formattazione `Intl` e una sottoscrizione ai cambiamenti, senza `fs` e senza framework. Usala in TypeScript puro, in un web worker, in una funzione edge o come base per un tuo binding. I pacchetti React, Preact, Node e Astro estendono questa stessa classe.

## Installazione {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/runtime
```

```bash npm
npm install @i18n-micro/runtime
```

```bash yarn
yarn add @i18n-micro/runtime
```

</CodeGroup>

Nessuna dipendenza peer. Per i file di traduzione su disco usa [`@i18n-micro/node`](/it/integrations/nodejs-package).

## Configurazione {#setup}

```ts
import { createI18n } from '@i18n-micro/runtime'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: {
    en: { greeting: 'Hello, {name}!', apples: 'no apples | one apple | {count} apples' },
    de: { greeting: 'Hallo, {name}!' },
  },
  routeMessages: {
    about: { en: { title: 'About us' } },
  },
})
```

Tutte le opzioni (`plural`, `missingWarn`, `missingHandler`, `numberFormats`, `datetimeFormats`) sono elencate in [l'istanza](/it/integrations/overview#the-instance).

## Tradurre {#translate}

```ts
i18n.t('greeting', { name: 'Ada' }) // 'Hello, Ada!'
i18n.tc('apples', 5) // '5 apples'
i18n.tn(1234.5) // '1,234.5'

i18n.setRoute('about')
i18n.t('title') // 'About us' (route dictionary)
i18n.t('greeting', { name: 'Ada' }) // 'Hello, Ada!' (root, still visible)
```

Carica altri dizionari in seguito:

```ts
i18n.loadMessages({ fr: { greeting: 'Bonjour, {name} !' } }, { about: { fr: { title: 'À propos' } } })
i18n.addTranslations('fr', { nav: { home: 'Accueil' } }) // deep merge; pass false to replace

await i18n.loadFromUrl('/locales/fr.json', { locale: 'fr' })
await i18n.loadFromUrl('/locales/pages/about/fr.json', { locale: 'fr', routeName: 'about' })
await i18n.loadFromUrls([
  { url: '/locales/en.json', locale: 'en' },
  { url: '/locales/de.json', locale: 'de' },
])
```

`loadFromUrl` usa `fetch` (passa `init` per gli header) e lancia un errore se la risposta non è OK. `loadFromUrls` carica gli URL uno dopo l'altro.

## Cambiare locale {#switch-locale}

```ts
i18n.locale = 'de'
i18n.t('greeting', { name: 'Ada' }) // 'Hallo, Ada!'
```

I cambiamenti di locale, route e dizionario notificano i sottoscrittori, ed è così che i binding dei framework rieseguono il render:

```ts
const stop = i18n.subscribe(() => {
  document.querySelector('#greeting')!.textContent = i18n.t('greeting', { name: 'Ada' }) as string
})
i18n.locale = 'fr'
stop()
```

`getSnapshot()` restituisce una stringa che cambia a ogni notifica (per store in stile `useSyncExternalStore`).

## Per richiesta {#per-request}

L'istanza contiene un solo locale e una sola route. Su un server, non cambiare un'istanza condivisa per ogni richiesta: due richieste concorrenti vedrebbero l'una il locale dell'altra. `i18n.fork(locale)` fornisce a una richiesta la propria istanza: locale, fallback e route propri; gli stessi dizionari, formatter e regole. Il costo del fork è lo stesso indipendentemente dal numero di dizionari. Un fork vede le scritture del suo genitore fino alla sua prima scrittura propria, e le sue scritture restano al suo interno. [Node.js](/it/integrations/nodejs-package#per-request) aggiunge `run`.

## API {#api}

| Membro | Note |
| --- | --- |
| `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` | vedi [Tradurre e formattare](/it/integrations/overview#translate-and-format) |
| `locale`, `fallbackLocale` | get/set |
| `currentRoute`, `setRoute(name)`, `getRoute()` | route attiva, predefinita `'index'` |
| `loadMessages(messages?, routeMessages?)` | unisce molti locale e route in una volta |
| `addTranslations(locale, tree, merge = true)`, `addRouteTranslations(locale, route, tree, merge = true)` | |
| `loadFromUrl(url, { locale?, routeName?, init? })`, `loadFromUrls(entries)` | JSON tramite `fetch` |
| `hasTranslation(key)` | locale attivo, qualsiasi route (a differenza di `has`, che controlla la route attiva e il root) |
| `setTranslation(key, value)`, `resolveTranslations()` | scrive una chiave; legge l'albero unito |
| `clear()`, `clearCache()` | elimina tutti i dizionari |
| `subscribe(cb)`, `getSnapshot()` | notifiche di cambiamento |
| `storage` | `{ translations: Map<'locale:route', Translations> }` |

Un codice che non è un tag di lingua ottiene i suoi plurali da `localeIso: { ua: 'uk-UA' }`; `localeIsoMap(locales)` lo costruisce a partire dalle voci di un elenco di locale che hanno un `iso`.

Export del modulo: `createI18n`, `I18n`, `fetchJsonTranslations`, `FormatService`, `interpolate`, `localeIsoMap` e i tipi `I18nOptions`, `LoadFromUrlOptions`, `LoadFromUrlEntry`, `TranslationStorage`, `Translations`, `Locale`, `PluralFunc`. Firme complete: [riferimento del pacchetto](/it/api/packages/runtime).
