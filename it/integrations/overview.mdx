I pacchetti `@i18n-micro/*` portano il core di traduzione di Nuxt I18n Micro in Vue, React, Preact, Solid, Astro, VitePress e JavaScript puro. Usali quando la tua app non è un'app Nuxt, o quando uno script o un server esterno a Nuxt ha bisogno degli stessi file di traduzione. Tutti i pacchetti condividono un unico modello di istanza, un unico contratto per l'adattatore del router e gli stessi quattro componenti, descritti una sola volta in questa pagina.

L'entry del router è un import separato, quindi un'app senza router non ne include mai uno nel bundle.

`@i18n-micro/core`, `@i18n-micro/types` e `@i18n-micro/utils` vengono installati con questi pacchetti; raramente li importerai direttamente. Le firme di ogni export si trovano nel [riferimento dei pacchetti](/it/api/packages/overview) generato.

Ogni pacchetto ha un playground in `packages/<name>/playground` nel repository.

## L'istanza {#the-instance}

`createI18n(options)` restituisce un'istanza che contiene i dizionari, la locale corrente e la route corrente. Le opzioni sono le stesse in ogni pacchetto:

| Opzione | Tipo | Default | Note |
| --- | --- | --- | --- |
| `locale` | `string` | obbligatoria | Locale attiva. |
| `fallbackLocale` | `string` | `locale` | Consultata quando una chiave manca in `locale`. |
| `messages` | `Record<locale, Translations>` | `{}` | Dizionari root (route `'index'`). |
| `routeMessages` | `Record<route, Record<locale, Translations>>` | `{}` | Dizionari di route. Solo Runtime, React, Preact, Node e VitePress. |
| `plural` | `PluralFunc` | `defaultPlural` | Regola di pluralizzazione personalizzata. |
| `missingWarn` | `boolean` | `true` | `console.warn` nel browser, solo in sviluppo, per una chiave mancante. |
| `missingHandler` | `(locale, key, routeName) => void` | — | Chiamato al posto dell'avviso. |
| `numberFormats` | `Record<locale, Record<name, Intl.NumberFormatOptions>>` | — | Formati con nome: `tn(9.5, 'currency')`. |
| `datetimeFormats` | `Record<locale, Record<name, Intl.DateTimeFormatOptions>>` | — | Formati con nome: `td(date, 'short')`. |
| `timeZone` | `string` | fuso del runtime | Fuso IANA per le date di `td`; non influisce su `tdr`. Impostalo affinché server e browser renderizzino la stessa data. |
| `now` | `() => number` | `Date.now` | L'orologio di `tdr`. Passa all'idratazione l'ora del server così entrambi renderizzano lo stesso testo. |
| `localeIso` | `Record<code, string>` | — | Tag BCP 47 usato per le regole di pluralizzazione (`ua` → `uk-UA`). React, Preact e Solid lo prendono da `iso` nelle `locales` del provider. |

I dizionari risiedono in `i18n.storage.translations`, una `Map` con chiavi `locale:route` (`en:index`, `en:about`).

Una chiave viene cercata nel dizionario della route corrente, poi nel dizionario root, prima per `locale`, poi per `fallbackLocale`. Una chiave mancante restituisce la chiave stessa (o il `defaultValue` che passi).

```ts
i18n.addTranslations('en', { nav: { home: 'Home' } }) // root, deep-merged
i18n.addRouteTranslations('en', 'about', { title: 'About us' }) // route chunk
i18n.addTranslations('en', { nav: { home: 'Start' } }, false) // replace instead of merge
i18n.setRoute('about')
i18n.t('title') // 'About us'
i18n.t('nav.home') // 'Start' (root key, still visible on the route)
```

### Tradurre e formattare {#translate-and-format}

| Metodo | Restituisce |
| --- | --- |
| `t(key, params?, defaultValue?, routeName?)` | Il valore (stringa, numero, oggetto) con `{param}` interpolato. |
| `ts(...)` | Come `t`, ma come stringa. |
| `tc(key, count \| params, defaultValue?)` | Forma plurale. |
| `tn(value, options \| name)` | `Intl.NumberFormat` nella locale attiva. |
| `td(value, options \| name)` | `Intl.DateTimeFormat`. |
| `tdr(value, options?)` | Tempo relativo (`3 days ago`). |
| `has(key, routeName?)` | `true` quando la locale attiva ha la chiave (dizionario di route o root; il fallback non viene controllato). |

`defaultPlural` divide il valore su `|` e sceglie la forma all'indice `count`, limitato all'ultima; un conteggio negativo, frazionario o `NaN` sceglie l'ultima forma.

Una regola `plural` personalizzata riceve `(key, count, params, locale, getter)`. Leggi il valore tramite `getter(key)`; non dividere la chiave:

```ts
import type { PluralFunc } from '@i18n-micro/vue'

const plural: PluralFunc = (key, count, params, _locale, getter) => {
  const value = getter(key)
  if (typeof value !== 'string') return null
  const forms = value.split('|').map((form) => form.trim())
  return (count === 1 ? forms[0] : forms[1] ?? forms[0])!.replace('{count}', String(count))
}
```

## Adattatore del router {#router-adapter}

I pacchetti SPA non dipendono da un router. Un adattatore del router (`I18nRoutingStrategy`) indica loro come leggere il percorso corrente, navigare e costruire un percorso localizzato. Gli adattatori integrati aggiungono un prefisso a ogni locale tranne `defaultLocale` (`/about`, `/de/about`).

| Membro | Obbligatorio | Usato da |
| --- | --- | --- |
| `getCurrentPath(): string` | sì | verifica del link attivo (per pagina: query e hash non contano), `switchLocale` (li mantiene) |
| `push({ path }): void` | sì | `switchLocale`, `<I18nLink>` senza `linkComponent`, `<I18nSwitcher>` |
| `replace({ path }): void` | sì | — |
| `resolvePath(to, locale)` | no | `localePath`, `localeRoute`, `<I18nLink>`; senza di esso i percorsi vengono restituiti così come sono |
| `linkComponent` | no | `<I18nLink>` lo renderizza (ad es. `RouterLink`) al posto di `<a>` |
| `getRoute()` | no | `{ fullPath, query }` per gli helper SEO |

`push` e `replace` sono obbligatori in Vue, React, Preact e Solid. Astro ha un proprio adattatore lato server con `push`/`replace` opzionali (vedi [Astro](/it/integrations/astro-package#router-adapter)).

Un adattatore minimo per qualsiasi router basato sulla history:

```ts
import type { I18nRoutingStrategy } from '@i18n-micro/react'

const locales = ['en', 'de']
const stripLocale = (path: string) => path.replace(/^\/(en|de)(?=\/|$)/, '') || '/'

export const historyAdapter: I18nRoutingStrategy = {
  getCurrentPath: () => window.location.pathname + window.location.search + window.location.hash,
  push: ({ path }) => window.history.pushState({}, '', path),
  replace: ({ path }) => window.history.replaceState({}, '', path),
  resolvePath: (to, locale) => {
    const path = stripLocale(typeof to === 'string' ? to : to.path || '/')
    return locale === 'en' ? path : `/${locale}${path === '/' ? '' : path}`
  },
}
```

## Componenti {#components}

Vue, React, Preact e Solid forniscono gli stessi quattro componenti. Le loro prop coincidono; React, Preact e Solid passano le altre prop all'elemento radice.

### `<I18nT>` {#&lt;i18nt&gt;}

| Prop | Tipo | Note |
| --- | --- | --- |
| `keypath` | `string` | obbligatoria |
| `params` | `object` | valori di interpolazione |
| `plural` | `number \| string` | renderizza `tc(keypath, count)` |
| `number` | `number \| string` | passa `tn(number)` come `{number}` |
| `date` | `Date \| string \| number` | passa `td(date)` come `{date}` |
| `relativeDate` | `Date \| string \| number` | passa `tdr(relativeDate)` come `{relativeDate}` |
| `tag` | `string` | elemento wrapper, default `span` |
| `html` | `boolean` | renderizza la traduzione come HTML; deve essere affidabile, i parametri vengono sottoposti a escape |
| `defaultValue` | `string` | sostituisce una chiave mancante, e viene renderizzato senza wrapper quando `hideIfEmpty` nasconde un valore vuoto |
| `hideIfEmpty` | `boolean` | non renderizza nulla per una traduzione vuota |
| `customPluralRule` | `PluralFunc` | regola di pluralizzazione per questo elemento |

Si applica una sola prop di formattazione, verificate in questo ordine: `number`, `date`, `relativeDate`, `plural`.

#### Rich text {#rich-text}

Un `{placeholder}` può contenere un elemento. In Vue è uno slot con nome; in React, Preact e Solid la prop `components` fornisce per nome elementi, o funzioni che ne restituiscono uno. In entrambi i casi prevale su un parametro con lo stesso nome, funziona in ogni ramo e resiste a una locale che riordina i placeholder.

```tsx
// { "terms": "I accept the {link} of {company}" }
<I18nT keypath="terms" params={{ company: 'ACME' }} components={{ link: <a href="/terms">terms</a> }} />
```

In Solid passa una funzione quando un placeholder si ripete: un nodo può occupare un solo posto. I `children` sostituiscono il testo; come funzione ricevono `{ translation }`, come lo slot di default di Vue. `html` ignora tutto questo.

### `<I18nLink>` {#&lt;i18nlink&gt;}

| Prop | Tipo | Note |
| --- | --- | --- |
| `to` | `string \| { path }` | localizzato tramite il `resolvePath` dell'adattatore |
| `activeStyle` | oggetto di stile | unito sopra `style` sulla pagina corrente; React, Preact e Solid lo applicano anche a una sezione superiore |
| `localeRoute` | funzione | sostituisce `resolvePath` per questo link |

Gli URL esterni (`https://`, `mailto:`, `tel:`) vengono renderizzati come `<a target="_blank" rel="noopener noreferrer">`; un tuo `target` o `rel` ha la precedenza. `onClick` viene sempre eseguito. Un clic con modificatori, un altro pulsante del mouse o un `target` vengono lasciati al browser.

### `<I18nSwitcher>` {#&lt;i18nswitcher&gt;}

Un menu a tendina delle locale abilitate (le locale con `disabled: true` sono nascoste) con stili di default inline. Le sue voci sono link, con `lang`, `hreflang` e `dir` presi dalla locale. Per default, cliccarne una imposta la locale e chiama il `push` dell'adattatore con il percorso corrente localizzato; una prop `switchLocale` sostituisce questa azione. Con un `localeRoute` e senza router, il browser segue il link. Esc o un clic all'esterno lo chiudono.

| Prop | Note |
| --- | --- |
| `locales`, `currentLocale`, `getLocaleName` | sovrascrivono i valori forniti |
| `switchLocale(code)` | sostituisce il cambio integrato |
| `localeRoute` | sostituisce `resolvePath` |
| `customLabels` | `{ de: 'DE' }` |
| `customWrapperStyle`, `customButtonStyle`, `customDropdownStyle`, `customItemStyle`, `customLinkStyle`, `customActiveLinkStyle`, `customDisabledLinkStyle`, `customIconStyle` | sovrascritture di stile |

### `<I18nGroup>` {#&lt;i18ngroup&gt;}

Un `<div class="i18n-group">` che passa ai suoi figli un `t` con prefisso. **Non** aggiunge il prefisso alle chiamate `<I18nT>` o `t()` al suo interno; solo il `t` che passa ai figli ha il prefisso.

| Prop | Note |
| --- | --- |
| `prefix` | obbligatoria, ad es. `'profile'` |
| `groupClass` | classe aggiuntiva sul wrapper |

Il `t` con prefisso arriva tramite uno scoped slot in Vue (`v-slot="{ t }"`) e un figlio render-prop in React, Preact e Solid (`{({ t }) => …}`).

## Chiavi tipizzate {#typed-keys}

`t()` accetta qualsiasi stringa. Per ottenere l'autocompletamento delle tue chiavi, genera una dichiarazione con il [generatore di tipi](/it/integrations/types-generator). Le chiavi vengono suggerite, non imposte, e i parametri non sono tipizzati.

## Confronto con il modulo Nuxt {#compared-with-the-nuxt-module}

I pacchetti non hanno routing basato su file, middleware server né loader delle traduzioni: decidi tu quando caricare il JSON (`import`, `fetch` o `@i18n-micro/node` sul server) e quale adattatore del router usare. Rilevamento della locale, meta SEO e generazione delle route sono funzionalità di Nuxt; Astro ha un proprio middleware per il rilevamento e `useLocaleHead` per la SEO.
