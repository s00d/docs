# Integrazioni

I pacchetti `@i18n-micro` sono versioni leggere e specifiche per framework di Nuxt I18n Micro, progettate per l'integrazione in vari framework e ambienti. Questi pacchetti forniscono funzionalità core di internazionalizzazione con un footprint minimo, concentrandosi sulle funzionalità essenziali di traduzione e sui componenti di base.

## Panoramica

Questi pacchetti di integrazione sono **versioni in miniatura** del modulo completo Nuxt I18n Micro, che contengono solo la funzionalità essenziale necessaria per l'internazionalizzazione:

- **Funzionalità core di traduzione** — metodi di traduzione di base, pluralizzazione e formattazione
- **Componenti essenziali** — un piccolo set di componenti UI per attività i18n comuni
- **Pattern router adapter** — integrazione di routing flessibile tramite astrazione adapter
- **Supporto TypeScript** — definizioni di tipi complete per uno sviluppo type-safe

A differenza del modulo Nuxt completo, questi pacchetti:

- Non includono logica di routing specifica per framework
- Richiedono l'implementazione di un router adapter per le funzionalità di routing
- Si concentrano sulla funzionalità di traduzione piuttosto che sull'integrazione con il framework
- Sono progettati per essere leggeri e framework-agnostic dove possibile

## Componenti core

Tutti i pacchetti framework includono i seguenti componenti essenziali:

### `<I18nT>`

Un componente di traduzione che renderizza testo tradotto con supporto per:

- **Interpolazione di parametri** — sostituisci i placeholder con valori dinamici
- **Pluralizzazione** — selezione automatica della forma plurale in base al conteggio
- **Formattazione dei numeri** — formatta i numeri secondo la locale
- **Formattazione delle date** — formatta date e tempi relativi
- **Rendering HTML** — rendering opzionale di contenuto HTML
- **Valori predefiniti** — testo di fallback quando la traduzione manca

**Esempio:**

```vue
<!-- Vue -->
<I18nT keypath="greeting" :params="{ name: 'World' }" />
```

```tsx
// React
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```tsx
// Solid
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```astro
<!-- Astro -->
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

### `<I18nLink>`

Un componente link localizzato che gestisce automaticamente i prefissi di locale negli URL. Funzionalità:

- **Localizzazione automatica del path** — aggiunge/rimuove prefissi di locale in base alla strategia di routing
- **Rilevamento dello stato attivo** — evidenzia la route corrente
- **Supporto per link esterni** — rileva e gestisce automaticamente gli URL esterni
- **Integrazione router** — usa il componente link del router adapter quando disponibile
- **Stile personalizzato** — supporta stati attivi e hover

**Esempio:**

```vue
<!-- Vue -->
<I18nLink to="/about" active-class="active">
  About Us
</I18nLink>
```

```tsx
// React
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```tsx
// Solid
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```astro
<!-- Astro -->
<I18nLink href="/about" class="nav-link">
  About Us
</I18nLink>
```

### `<I18nSwitcher>`

Un componente selettore di lingua che fornisce un'interfaccia dropdown o a lista per cambiare locale. Funzionalità:

- **Elenco automatico delle locale** — genera opzioni dalle locale configurate
- **Evidenziazione della locale corrente** — indica visivamente la lingua attiva
- **Etichette personalizzate** — supporto per nomi visualizzati personalizzati per locale
- **Integrazione router** — naviga automaticamente a path localizzati
- **Accessibilità** — attributi ARIA corretti e navigazione da tastiera

**Esempio:**

```vue
<!-- Vue -->
<I18nSwitcher />
```

```tsx
// React
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```tsx
// Solid
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```astro
<!-- Astro -->
<I18nSwitcher />
```

### `<I18nGroup>`

Un componente per raggruppare traduzioni con un prefisso comune, utile per organizzare traduzioni per pagina o funzionalità. Funzionalità:

- **Ambito del prefisso** — antepone automaticamente il prefisso a tutte le chiavi di traduzione all'interno del gruppo
- **Gruppi annidati** — supporto per gruppi di traduzione annidati
- **Organizzazione pulita** — aiuta a mantenere strutture di traduzione organizzate

**Esempio:**

```vue
<!-- Vue -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

```tsx
// React
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```tsx
// Solid
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```astro
<!-- Astro -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

## Opzioni condivise di `createI18n` \{#create-i18n-options\}

Ogni pacchetto framework viene creato allo stesso modo. Solo il tipo delle opzioni prende il nome dal
framework (`ReactI18nOptions`, `SolidI18nOptions` e così via). Le opzioni stesse
sono identiche:

| Proprietà        | Tipo                                                       | Obbligatoria | Predefinito       | Descrizione                                    |
| ---------------- | ---------------------------------------------------------- | ------------ | ----------------- | ---------------------------------------------- |
| `locale`         | `string`                                                   | ✅           | -                 | Codice locale corrente (ad esempio, `'en'`)    |
| `fallbackLocale` | `string`                                                   | ❌           | Come `locale`     | Locale di fallback quando la traduzione manca  |
| `messages`       | `Record<string, Translations>`                             | ❌           | `\{\}`              | Messaggi di traduzione iniziali                |
| `plural`         | `PluralFunc`                                               | ❌           | `defaultPlural`   | Funzione di pluralizzazione personalizzata     |
| `missingWarn`    | `boolean`                                                  | ❌           | `true`            | Mostra avvisi in console per traduzioni mancanti |
| `missingHandler` | `(locale: string, key: string, routeName: string) => void` | ❌           | -                 | Handler personalizzato per traduzioni mancanti |

Qualsiasi cosa oltre a queste è specifica del framework ed è documentata nella pagina del pacchetto.

## Astrazione del router adapter

Tutti i pacchetti framework usano un **pattern router adapter** per disaccoppiare la funzionalità i18n da specifiche implementazioni di router. Questo design permette:

- **Flessibilità** — usa qualsiasi libreria di router o nessun router
- **Indipendenza dal framework** — mantieni la logica di routing nella tua applicazione, non nel pacchetto i18n
- **Core leggero** — il pacchetto i18n resta piccolo e focalizzato

### Implementare un router adapter

Per usare le funzionalità di routing, devi implementare l'interfaccia `I18nRoutingStrategy`:

```typescript
interface I18nRoutingStrategy {
  getCurrentPath: () => string
  linkComponent?: Component
  push: (target: { path: string }) => void
  replace: (target: { path: string }) => void
  resolvePath?: (to: string | { path?: string }, locale: string) => string | { path?: string }
  getRoute?: () => { fullPath: string; query: Record<string, unknown> }
}
```

Ogni documentazione di pacchetto include esempi completi per implementare adapter per i router più popolari:

- **Vue**: esempio di adapter per Vue Router
- **React**: esempio di adapter per React Router
- **Solid**: esempio di adapter per Solid Router
- **Astro**: esempio di adapter per routing basato su file

## Funzionalità core

Tutti i pacchetti condividono queste funzionalità core:

### Metodi di traduzione

- `t()` — traduzione di base con interpolazione di parametri
- `ts()` — traduzione che restituisce sempre una stringa
- `tc()` — traduzione con pluralizzazione
- `tn()` — formattazione dei numeri
- `td()` — formattazione delle date
- `tdr()` — formattazione dei tempi relativi
- `has()` — verifica se una chiave di traduzione esiste

### Gestione delle locale

- **Cambio di locale** — cambia la locale corrente in modo programmatico
- **Locale di fallback** — fallback automatico quando la traduzione manca
- **Traduzioni per route** — organizzazione delle traduzioni a livello di pagina
- **Caching delle traduzioni** — caching intelligente per le prestazioni

### Supporto TypeScript

Tutti i pacchetti forniscono:

- Definizioni TypeScript complete
- Chiavi di traduzione type-safe (con il generatore di tipi)
- Supporto IntelliSense negli IDE
- Controllo degli errori in fase di compilazione
