`@i18n-micro/vue` è un plugin Vue 3 con il core di traduzione di Nuxt I18n Micro: `t()` reattivo, `$t` globale, quattro componenti e un adapter opzionale per vue-router. Usalo in un'app Vue con Vite o SSR che non è costruita con Nuxt. Il modello dell'istanza, il contratto del router e le props dei componenti sono condivisi con gli altri pacchetti e descritti in [Framework](/it/integrations/overview).

## Installazione {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vue
```

```bash npm
npm install @i18n-micro/vue
```

```bash yarn
yarn add @i18n-micro/vue
```

</CodeGroup>

Peer dependency: `vue` `^3.3.0`; `vue-router` `^4.5.1 || ^5.0.0` (opzionale, solo per `@i18n-micro/vue/router`). I tipi pubblicati richiedono Vue 3.5.5 o successivo con `skipLibCheck: false`; con `skipLibCheck: true`, l'impostazione abituale dei template, compilano anche le versioni precedenti.

## Configurazione {#setup}

```ts
// src/main.ts
import { createApp } from 'vue'
import { createI18n } from '@i18n-micro/vue'
import App from './App.vue'
import en from './locales/en.json'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales: [
    { code: 'en', iso: 'en-US', displayName: 'English' },
    { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
  ],
  defaultLocale: 'en',
})

createApp(App).use(i18n).mount('#app')
```

`locales` e `defaultLocale` sono obbligatori per `useI18n()`: senza di essi lancia `I18nLocalesKey not provided`. Passali a `createI18n` (come sopra), a `useI18n({ locales, defaultLocale })`, oppure tramite `app.provide(I18nLocalesKey, …)` e `app.provide(I18nDefaultLocaleKey, …)`.

Il plugin registra globalmente `I18nT`, `I18nLink`, `I18nGroup` e `I18nSwitcher` e aggiunge `$t`, `$ts`, `$tc`, `$tn`, `$td`, `$tdr`, `$has` e `$i18n` ai template. Fuori dai componenti, l'istanza è `i18n.global`. Le altre opzioni sono in [l'istanza](/it/integrations/overview#the-instance); `routeMessages` non è disponibile in Vue, usa `addRouteTranslations`.

## Tradurre {#translate}

```vue
<script setup lang="ts">
import { useI18n } from '@i18n-micro/vue'

const { t, tc, tn } = useI18n()
</script>

<template>
  <h1>{{ t('greeting', { name: 'Ada' }) }}</h1>
  <!-- Hello, Ada! -->
  <p>{{ tc('apples', 3) }}</p>
  <!-- 3 apples -->
  <p>{{ $t('nav.home') }} · {{ tn(1234.5) }}</p>
</template>
```

`useI18n()` restituisce i metodi di traduzione (`t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`), `locale` (un computed scrivibile), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `localePath`, `localeRoute`, `switchLocale`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `mergeTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` e `instance`.

Carica altri dizionari in qualsiasi momento; ogni componente che li legge viene renderizzato di nuovo:

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Cambiare locale {#switch-locale}

```ts
const { locale, switchLocale } = useI18n()

locale.value = 'de' // only the locale
switchLocale('de') // the locale, then router.push to the localized current path
```

Carica il dizionario del locale prima o dopo il cambio; il cambio non scarica nulla.

`<I18nGroup>` fornisce al suo slot un `t` con prefisso. Le chiavi dentro `<I18nT>` o in un semplice `t()` non ricevono il prefisso:

```vue
<I18nGroup prefix="profile" v-slot="{ t }">
  <h2>{{ t('title') }}</h2>
  <!-- profile.title -->
</I18nGroup>
```

## Routing {#routing}

L'adapter per vue-router si trova in un sottopercorso, così l'entry principale non importa mai `vue-router`:

```ts
// src/main.ts
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import { createI18n } from '@i18n-micro/vue'
import { createVueRouterAdapter } from '@i18n-micro/vue/router'
import App from './App.vue'
import Home from './pages/Home.vue'
import About from './pages/About.vue'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/:locale(de)?', component: Home },
    { path: '/:locale(de)?/about', component: About },
  ],
})

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales,
  defaultLocale: 'en',
  routingStrategy: createVueRouterAdapter(router, locales, 'en'),
})

createApp(App).use(router).use(i18n).mount('#app')
```

`createVueRouterAdapter(router, locales, defaultLocale)` aggiunge un prefisso a ogni locale tranne quello predefinito (`/about`, `/de/about`) e renderizza `<I18nLink>` come `RouterLink`. Leggi tu stesso il locale dalla route, ad esempio in `router.beforeEach`, e imposta `i18n.global.locale.value`. Puoi anche collegare un adapter in seguito con `i18n.setRoutingStrategy(adapter)`; per un adapter personalizzato consulta [Adapter del router](/it/integrations/overview#router-adapter).

## SSR {#ssr}

- Crea il router, l'istanza i18n e l'app dentro la funzione di render per richiesta. Un'unica istanza condivisa farebbe trapelare il locale di un visitatore a un altro.
- Usa `createMemoryHistory()` sul server, prendi il locale dall'URL e carica il suo dizionario (e quello di fallback) prima di `renderToString`.
- Invia il locale al client (ad esempio in uno script `window.__STATE__`) e crea l'istanza client con lo stesso `locale`, così l'idratazione corrisponde.
- `<I18nSwitcher>` legge `window.location` solo quando il menu a tendina è aperto, quindi viene renderizzato sul server.

`packages/vue/playground` contiene una coppia completa `entry-server.ts` / `entry-client.ts`.

## Head SEO {#seo-head}

`useLocaleHead(options)` costruisce `lang`/`dir`, canonical, i tag `hreflang` e `og:locale` a partire dai locale e dall'adapter del router. Chiama `updateMeta()` quando la route cambia e passa `metaObject` al tuo gestore dell'head:

```ts
import { watch } from 'vue'
import { useRoute } from 'vue-router'
import { useHead } from '@unhead/vue'
import { useLocaleHead } from '@i18n-micro/vue'

const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
watch(() => route.fullPath, () => updateMeta(), { immediate: true })
useHead(metaObject)
```

Opzioni: `baseUrl` (stringa o funzione), `addDirAttribute` (predefinito `true`), `addSeoAttributes` (predefinito `true`), `identifierAttribute` (predefinito `'id'`), `hreflangBaseLanguage` (predefinito `false`). I locale con `disabled: true` o `seo: false` non ricevono alcun link alternate.
