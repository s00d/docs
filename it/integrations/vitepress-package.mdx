`@i18n-micro/vitepress` aggiunge dizionari a runtime a un sito VitePress: `$t` e `<I18nT>` all'interno del markdown, helper per i percorsi e tag SEO, basati su [`@i18n-micro/vue`](/it/integrations/vue-package). Usalo quando le stesse stringhe dell'interfaccia compaiono in molte pagine e non vuoi duplicarle per ogni locale. Il locale segue i locale di percorso propri di VitePress (`/`, `/fr/`).

## Quando usarlo {#when-to-use-it}

| Esigenza | Soluzione |
|------|----------|
| `.md` duplicati, prefissi negli URL | `locales` di VitePress |
| `$t` a runtime / componenti / sincronizzazione dei percorsi / head SEO | `@i18n-micro/vitepress` |
| Etichette dell'interfaccia del tema predefinito (`docFooter`, UI di ricerca) | Il tuo `themeConfig` per ogni locale |

<Tip>

**Playground** — [`packages/vitepress/playground`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/vitepress/playground) — `pnpm -C packages/vitepress/playground dev`

</Tip>

## Installazione {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vitepress
```

```bash npm
npm install @i18n-micro/vitepress
```

```bash yarn
yarn add @i18n-micro/vitepress
```

</CodeGroup>

Dipendenze peer: `vitepress` `>=1.0.0 || >=2.0.0-alpha.0`, `vue` `^3.3.0`. Gli script Node usano `@i18n-micro/node`, installato insieme al pacchetto e riesportato tramite `/node`. I tipi pubblicati richiedono Vue 3.5.5 o successivo con `skipLibCheck: false`; con `skipLibCheck: true`, l'impostazione abituale dei template, compilano anche le versioni precedenti.

## Configurazione {#setup}

```
locales/en.json
locales/fr.json
locales/pages/guide/demo/en.json   # optional page-scoped
locales/pages/guide/demo/fr.json
```

I file di pagina corrispondono ai nomi delle route allo stesso modo di Nuxt/Astro (`guide/demo` → `guide-demo`).

### 1. Configurazione — `@i18n-micro/vitepress/config` {#1-config-—-@i18n-micro/vitepress/config}

```ts
// .vitepress/config.mts
import { defineConfig } from 'vitepress'
import { withI18n, buildVitePressLocales } from '@i18n-micro/vitepress/config'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English', og: 'en_US' },
  { code: 'fr', iso: 'fr-FR', displayName: 'Français', og: 'fr_FR' },
]
const defaultLocale = 'en'

export default defineConfig(
  withI18n(
    {
      locales: buildVitePressLocales(locales, defaultLocale),
      // themeConfig.i18nRouting is injected automatically
    },
    {
      locale: defaultLocale,
      defaultLocale,
      locales,
      translationDir: 'locales',
      metaBaseUrl: 'https://example.com', // optional SEO head
    },
  ),
)
```

### 2. Tema — `@i18n-micro/vitepress/theme` {#2-theme-—-@i18n-micro/vitepress/theme}

```ts
// .vitepress/theme/index.ts
import DefaultTheme from 'vitepress/theme'
import { defineI18nTheme } from '@i18n-micro/vitepress/theme'

export default defineI18nTheme(DefaultTheme)
```

Il locale iniziale viene preso dal percorso corrente prima dell'installazione (nessun lampeggiamento del locale predefinito su `/fr/…`).

### Avanzato: `createI18n` manuale {#advanced-manual-createi18n}

Un'unica factory per il client: plugin Vue + metodi per i percorsi + `enhanceApp` (nessun export separato di helper per il router).

```ts
import { createI18n, messagesFromGlob } from '@i18n-micro/vitepress'

const i18n = createI18n({
  locale: 'en',
  defaultLocale: 'en',
  locales: [{ code: 'en' }, { code: 'fr' }],
  messages: messagesFromGlob(import.meta.glob('../../locales/*.json', { eager: true })),
})

i18n.localizePath('/guide', 'fr')
// in theme enhanceApp:
i18n.enhanceApp({ app, router })
```

### Script Node — `@i18n-micro/vitepress/node` {#node-scripts-—-@i18n-micro/vitepress/node}

Usa `createI18n` / `loadTranslations` di `@i18n-micro/node` (come Astro e la CLI), poi aggiunge i metodi per i percorsi di VitePress con `BaseI18n.extend`:

```ts
import { createI18n } from '@i18n-micro/vitepress/node'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  translationDir: './locales',
  locales: ['en', 'fr'],
  defaultLocale: 'en',
})
await i18n.loadTranslations()
i18n.t('cta.readMore')
i18n.localizePath('/guide', 'fr')
```

Node puro senza percorsi: `import { createI18n } from '@i18n-micro/node'`.

## Traduzioni nella pagina {#in-page-translations}

Ogni file markdown di VitePress è un SFC Vue.

### Componenti globali e `$t` (consigliati nel markdown) {#global-components-and-$t-recommended-in-markdown}

`createI18n` / `defineI18nTheme` installano `@i18n-micro/vue`, che registra `I18nT` / `I18nLink` / `I18nGroup` / `I18nSwitcher` e `$t` / `$tc` / `$ts`.

```md
{{ $t('cta.readMore') }}

<I18nT keypath="greeting" :params="{ name: 'VitePress' }" />

<I18nLink to="/guide/demo">Demo</I18nLink>
```

### `useI18n` in `<script setup>` {#usei18n-in-<script-setup>}

```md
<script setup>
import { useI18n } from '@i18n-micro/vitepress'
const { t, tc, locale, localePath, switchLocale } = useI18n()
</script>

# {{ t('section.title') }}
```

## Menu a tendina delle lingue {#language-dropdown}

Quando `locales` ha più di una voce, VitePress mostra il proprio menu delle lingue (`VPNavBarTranslations`). `withI18n` collega `themeConfig.i18nRouting` in modo che il globo corrisponda a `<I18nSwitcher>` / agli helper per i percorsi.

Usa `<I18nSwitcher>` solo nei layout personalizzati, non accanto al globo predefinito.

## Note sull'SSR {#ssr-notes}

- Il locale durante il prerender proviene dal percorso dell'URL, non dai cookie.
- Il codice del tema non deve accedere a `window` al momento dell'import.
- Importa `defineI18nTheme` da `/theme` affinché la valutazione della configurazione in Node non carichi mai `virtual:i18n-micro/*`.

## Superficie dell'API {#api-surface}

| Export | Ruolo |
|--------|------|
| `createI18n` (`.`) | Client: plugin Vue + metodi per i percorsi + `enhanceApp` |
| `getLocaleFromPath` / `stripSiteBase` / `routeNameFromPath` (`.`) | Sincronizzazione manuale del locale quando `syncWithVitePress: false` |
| `createI18n` (`/node`) | Node: `@i18n-micro/node` + metodi per i percorsi |
| `defineI18nTheme` (`/theme`) | Tema senza boilerplate |
| `withI18n` (`/config`) | Configurazione + moduli virtuali + SEO opzionale |
| `buildVitePressLocales` (`/config`) | Costruisce i `locales` di VitePress da `Locale[]` |
| `buildVitePressLocaleHead` (`/config`) | Head SEO manuale (usato anche da `metaBaseUrl`) |
| `messagesFromGlob` | Mappa opzionale glob → messaggi per `createI18n` |
| `useI18n` / `I18nT` / … | Riesportati da `@i18n-micro/vue` |
| `BaseI18n.extend` (`@i18n-micro/core`) | Aggiunge metodi personalizzati a qualsiasi istanza i18n |

## Siti in stile OpenAPI (vincoli di integrazione) {#openapi-style-sites-integration-locks}

Suite di regressione: `packages/vitepress/tests/integration-openapi.test.ts` (percorsi profondi, `base=/openapi_docs/`, sincronizzazione disattivata + locale manuale, generatori Node, SEO).

| Pattern | Cosa fare |
|---------|---------|
| Pagine profonde `/…/{spec}/{op}`, solo JSON dell'interfaccia root | Preferisci il valore predefinito `syncWithVitePress: true` (mantiene `setRoute('index')` quando non c'è un dizionario di pagina) **oppure** `syncWithVitePress: false` + `getLocaleFromPath` |
| Non chiamare mai `setRoute(deepName)` senza dizionari di pagina | Le chiavi dell'interfaccia root scompaiono fino a `setRoute('index')` |
| Generatori / `getTranslation` | `createI18n` da `/node` + `await loadTranslations()` + `i18n.t(key)` (imposta `i18n.locale`) |
| Canonical personalizzato in `transformPageData` | Passa `meta: false` a `withI18n` (evita tag doppi) |
| SEO del pacchetto con base del sito | `metaBaseUrl` + `base` di VitePress → gli URL assoluti includono la base |
| Rinominare da build precedenti del pacchetto | `withI18nMicro` → `withI18n`, `createVitePressI18n` → `createI18n`, `loadMessages` → `createI18n` di node |
