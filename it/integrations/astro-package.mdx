---

`@i18n-micro/astro` traduce le pagine Astro sul server: un middleware sceglie la lingua dall'URL e inserisce un'istanza per richiesta in `Astro.locals`, e `useI18n(Astro)` la legge. Usalo in un sito Astro che necessita di URL con prefisso di lingua (`/about`, `/fr/about`) e dizionari JSON condivisi. Ottieni componenti `.astro`, un reindirizzamento della home page alla lingua del visitatore, tag `hreflang` e props per le [isole](/it/integrations/astro-islands).

## Installazione {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/astro
```

```bash npm
npm install @i18n-micro/astro
```

```bash yarn
yarn add @i18n-micro/astro
```

</CodeGroup>

Dipendenze peer: `astro` `^5.0.0 || ^6.0.0 || ^7.0.0`. Opzionali, solo per le [isole](/it/integrations/astro-islands): `vue` `^3.3.0`, `react` `^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`, `preact` `^10.0.0 || ^11.0.0`, `svelte` `^4.0.0 || ^5.0.0`.

## Configurazione {#setup}

Aggiungi l'integrazione. Include i tuoi dizionari nel server e installa il middleware, quindi non serve alcun `src/middleware.ts`:

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import node from '@astrojs/node'
import { i18nIntegration } from '@i18n-micro/astro'

export default defineConfig({
  output: 'server',
  adapter: node({ mode: 'standalone' }),
  integrations: [
    i18nIntegration({
      locale: 'en',
      fallbackLocale: 'en',
      locales: [
        { code: 'en', iso: 'en-US', displayName: 'English' },
        { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
        { code: 'fr', iso: 'fr-FR', displayName: 'Français' },
      ],
      translationDir: 'src/locales',
    }),
  ],
})
```

I dizionari diventano codice in fase di build: il server non legge dal disco, quindi funziona anche sull'edge (Cloudflare, Vercel Edge). In `astro dev` una modifica a un file si applica alla richiesta successiva.

### Opzioni dell'integrazione {#integration-options}

| Opzione | Predefinito | Note |
| --- | --- | --- |
| `locale` | obbligatorio | Lingua predefinita. |
| `fallbackLocale` | `locale` | |
| `locales` | `[]` | Oggetti `Locale` completi. Una lingua `disabled` non è la lingua di alcun URL né una destinazione di reindirizzamento. `iso` è il tag in base a cui funzionano i plurali quando il codice non lo è (`ua` → `uk-UA`). |
| `translationDir` | nessuno | Cartella inclusa nel server, relativa alla radice del progetto. |
| `disablePageLocales` | `false` | I file di pagina contano come traduzioni radice. |
| `autoDetect` | `true` | Reindirizzamento della home page, vedi [Rilevamento della lingua](#locale-detection). |
| `redirectToDefault` | `false` | Anche `/` reindirizza quando nulla preferisce un'altra lingua. |
| `localeCookie` | `'i18n-locale'` | `null` disabilita il cookie. |
| `missingWarn` | `false` | |
| `middleware` | `true` | `false`: scrivi tu il middleware, vedi sotto. |

Le impostazioni di runtime sono pubblicate in `virtual:i18n-micro/config` (`config.base` è il `base` di Astro, `config.localeCodes` i codici abilitati), i dizionari in `virtual:i18n-micro/messages`.

### Il tuo middleware {#your-own-middleware}

Una regola di plurale, un handler per le chiavi mancanti e un adapter del router non possono passare dal processo di configurazione al bundle del server. Per questi casi, passa `middleware: false` e scrivi `src/middleware.ts`. La configurazione `i18n` di Astro viene allora impostata per te con `routing: 'manual'`, così `Astro.currentLocale` e `astro:i18n` funzionano. Astro non consente questa impostazione senza un `src/middleware.ts`, quindi con il middleware proprio dell'integrazione non funzionano.

```ts
// src/middleware.ts
import { config } from 'virtual:i18n-micro/config'
import { messages } from 'virtual:i18n-micro/messages'
import { createAstroRouterAdapter, createI18n, createI18nMiddleware, localeIsoMap } from '@i18n-micro/astro'

const i18n = createI18n({
  locale: config.defaultLocale,
  fallbackLocale: config.fallbackLocale,
  localeIso: localeIsoMap(config.locales),
  messages: messages.root,
  routeMessages: messages.routes,
  plural: myPluralRule,
})

export const onRequest = createI18nMiddleware({
  i18n,
  defaultLocale: config.defaultLocale,
  locales: config.localeCodes,
  localeObjects: config.locales,
  autoDetect: config.autoDetect,
  redirectToDefault: config.redirectToDefault,
  localeCookie: config.localeCookie,
  base: config.base,
  routingStrategy: createAstroRouterAdapter(config.locales, config.defaultLocale),
})
```

Per leggere invece la cartella a runtime, `loadTranslationsFromDir` e `loadTranslationsIntoI18n` si trovano in `@i18n-micro/astro/node` (solo Node).

### Opzioni del middleware {#middleware-options}

| Opzione | Predefinito | Note |
| --- | --- | --- |
| `i18n` | obbligatorio | Istanza globale; ogni richiesta riceve `i18n.fork(locale)`, che costa lo stesso indipendentemente dal numero di dizionari. |
| `defaultLocale` | obbligatorio | |
| `locales` | obbligatorio | Codici delle lingue. |
| `localeObjects` | `locales` come `{ code }` | Oggetti `Locale` completi per componenti e SEO. |
| `autoDetect` | `true` | Reindirizzamento della home page, vedi [Rilevamento della lingua](#locale-detection). |
| `redirectToDefault` | `false` | Anche `/` reindirizza quando nulla preferisce un'altra lingua, verso la home della lingua predefinita così come la risolve la strategia di routing. |
| `localeCookie` | `'i18n-locale'` | `null` disabilita il cookie. |
| `routingStrategy` | prefisso tranne la predefinita | Adapter del router. I metodi che omette provengono dall'adapter predefinito. |
| `base` | nessuno | Il `base` di Astro: `config.base`. |

I file di pagina (`src/locales/pages/blog/post/de.json`) corrispondono alla rotta `blog-post`: il percorso della pagina unito con `-`.

## Tradurre {#translate}

```astro
---
// src/pages/index.astro
import { useI18n } from '@i18n-micro/astro'
import I18nT from '@i18n-micro/astro/i18n-t'

const { t, tc, locale } = useI18n(Astro)
---

<h1>{t('greeting', { name: 'Ada' })}</h1>
<p>{tc('apples', 3)}</p>
<I18nT keypath="welcome" tag="p" />
<p>{locale}</p>
```

`useI18n(Astro)` restituisce `locale`, `defaultLocale`, `locales`, `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `getRoute`, `getRouteName(path?)`, `getLocaleFromPath(path?)`, `switchLocalePath(locale)`, `localizePath(path, locale?)`, `getBasePath(url?)`, `getI18n`, `addTranslations`, `addRouteTranslations`, `mergeTranslations` e `clearCache`. Lancia un errore quando il middleware non è stato eseguito. Gli helper `getI18n`, `getLocale`, `getDefaultLocale` e `getLocales` leggono lo stesso `Astro.locals`.

Il nome della rotta deriva dalla rotta senza la lingua: `/fr/blog/post` → `blog-post`, e ogni URL di `src/pages/blog/[slug].astro` → `blog-slug`, quindi un'unica cartella `locales/pages/blog-slug/` li serve tutti. `[...path]` diventa `path`. Con il `base` di Astro gli helper accettano e restituiscono URL del sito: `switchLocalePath` e `localizePath` lo includono, `getBasePath` no, perché `Astro.rewrite` accetta il percorso senza di esso.

### Componenti {#components}

Importali da `@i18n-micro/astro/<name>` (o `@i18n-micro/astro/components/<name>.astro`):

| Componente | Props |
| --- | --- |
| `i18n-t` | `keypath`, `params`, `plural`, `number`, `date`, `relativeDate`, `tag` (`span`, qualsiasi tag), `html`, `hideIfEmpty`, `defaultValue`; gli altri attributi vengono passati. Con `html` il risultato di ogni ramo viene renderizzato come HTML e i `params` vengono sottoposti a escape. Non ci sono slot |
| `i18n-link` | `href`, `locale` (lingua di destinazione, predefinita quella corrente), `class`; gli altri attributi vengono passati. URL esterni, `#hash` e `?query` restano come scritti; una rotta mantiene query, hash e slash finale |
| `i18n-switcher` | `class`, `activeClass` (`'active'`), `customLabels`; renderizza link alla pagina corrente in ogni lingua abilitata, con la sua query |
| `i18n-group` | nessuna che modifichi l'output: un `<div>` attorno al suo slot, nessun prefisso |

## Rotte con prefisso di lingua {#locale-prefixed-routes}

Mantieni una pagina per rotta in `src/pages/` e aggiungi sottili stub di rewrite in `src/pages/[locale]/`:

```
src/pages/
  index.astro
  about.astro
  [locale]/
    index.astro
    about.astro
```

```astro
---
// src/pages/[locale]/about.astro
import { prepareLocaleRewrite } from '@i18n-micro/astro'

const target = prepareLocaleRewrite(Astro)
if (target instanceof Response) return target
return Astro.rewrite(target)
---
```

`prepareLocaleRewrite` restituisce una risposta `404` per un `:locale` sconosciuto, altrimenti imposta la lingua su `Astro.locals` e restituisce il percorso senza il prefisso. Il middleware mantiene una lingua già presente in `locals`, quindi la pagina riscritta viene renderizzata in quella lingua. `getLocaleRewritePath(Astro)` restituisce solo il percorso, quando convalidi tu stesso la lingua.

## Rilevamento della lingua {#locale-detection}

L'URL decide la lingua della pagina:

1. Un prefisso di lingua (`/fr/about` → `fr`; anche `/en/about` è `en`).
2. Altrimenti ciò che restituisce `getLocaleFromPath` dell'adapter del router, se non è la predefinita.
3. Altrimenti la lingua predefinita. `/about` è sempre la pagina della lingua predefinita, qualunque cosa dica il cookie.

`autoDetect` è un suggerimento di reindirizzamento solo sulla home page:

- Una richiesta di `/` il cui cookie o `Accept-Language` preferisce un'altra lingua riceve un `302` verso la home di quella lingua (`/de`). I pesi q vengono rispettati; `de-DE` corrisponde a una lingua `de`, e `de` corrisponde a una `de-DE`.
- Con `redirectToDefault`, `/` reindirizza sempre: alla home della lingua preferita, altrimenti a quella della lingua predefinita.
- La risposta di `/` include `Vary: Cookie, Accept-Language` (solo `Accept-Language` quando `localeCookie` è `null`).
- Le pagine prerenderizzate non reindirizzano mai.

`detectLocale(pathname, cookies, headers, defaultLocale, locales, localeCookie?, routingStrategy?, autoDetect?)` restituisce la stessa lingua preferita per la tua logica.

Il cookie ricorda una scelta. Una visualizzazione di pagina proveniente da una pagina della stessa origine in un'altra lingua è un visitatore che cambia lingua, qualunque link lo abbia portato lì: la risposta HTML imposta il cookie sulla nuova lingua, e `/` non reindirizza, così un selettore raggiunge la home della lingua predefinita. Un endpoint, un'immagine, un 404, l'invio di un form e un prefetch non cambiano nulla. "Stessa origine" è ciò che il browser indica in `Sec-Fetch-Site`; senza quell'header l'host del `Referer` viene confrontato con quello della richiesta, quindi dietro un proxy imposta `security.allowedDomains` di Astro.

Una [server island](https://docs.astro.build/en/guides/server-islands/) o un'action non ha una lingua nel suo URL. Viene renderizzata per la pagina che l'ha richiesta, letta dal `Referer`, di cui conta solo il percorso, quindi un proxy davanti al server non cambia nulla, e non reindirizza mai. La sua risposta include `Vary: Referer`. Senza un `Referer` (una policy `no-referrer`) è nella lingua predefinita, e su una pagina dinamica la sua rotta deriva dall'URL, quindi i dizionari di pagina non la raggiungono.

## Adapter del router {#router-adapter}

`createAstroRouterAdapter(locales, defaultLocale)` aggiunge il prefisso a ogni lingua tranne la predefinita. Un adapter Astro richiede solo `getCurrentPath`; gli altri membri sono opzionali e ricadono sull'adapter predefinito: `getRouteName(path, locales, routePattern?)`, `getLocaleFromPath`, `switchLocalePath`, `localizePath`, `removeLocaleFromPath`, `resolvePath` (destinazione del reindirizzamento della home), `push`, `replace`, `getRoute`. Scrivine uno tuo per URL con sottodominio o suffisso e passalo a `createI18nMiddleware`.

## SEO {#seo}

```astro
---
// src/layouts/Layout.astro
import { useLocaleHead } from '@i18n-micro/astro'

const head = useLocaleHead(Astro, { baseUrl: 'https://example.com' })
---

<html lang={head.htmlAttrs.lang} dir={head.htmlAttrs.dir}>
  <head>
    {head.link.map((l) => <link rel={l.rel} href={l.href} hreflang={l.hreflang} />)}
    {head.meta.map((m) => <meta property={m.property} content={m.content} />)}
  </head>
  <body><slot /></body>
</html>
```

Restituisce `htmlAttrs` (`lang` da `iso`, `dir`), un link canonical (percorso senza query), alternate `hreflang` per ogni lingua abilitata con `seo !== false` più `x-default`, `og:locale`, `og:locale:alternate` e `og:url`. Opzioni: `baseUrl` (`site` dalla configurazione di Astro, altrimenti URL relativi alla radice), `addDirAttribute` (`true`), `addSeoAttributes` (`true`), `hreflangBaseLanguage` (`false`).
