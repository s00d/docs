`@i18n-micro/node` è l'istanza [runtime](/it/integrations/runtime-package) più un loader che legge una cartella di traduzioni dal disco. Usalo in un server Express o Fastify, in una CLI, in un generatore di email o PDF, o in qualsiasi script che abbia bisogno degli stessi file JSON della tua app Nuxt. Carichi i file una volta e traduci per ogni richiesta senza condividere stato mutabile tra le richieste.

## Installazione {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/node @i18n-micro/utils
```

```bash npm
npm install @i18n-micro/node @i18n-micro/utils
```

```bash yarn
yarn add @i18n-micro/node @i18n-micro/utils
```

</CodeGroup>

Nessuna peer dependency; Node.js `>=20`. `@i18n-micro/utils` serve solo per l'helper `Accept-Language` descritto più sotto.

## Configurazione {#setup}

Il loader legge la [struttura delle cartelle di Nuxt](/it/guide/translations): `locales/en.json` è un dizionario root, `locales/pages/blog/post/en.json` appartiene alla route `blog-post`.

```ts
import { createI18n } from '@i18n-micro/node'

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

i18n.t('greeting', { name: 'Ada' }) // 'Hello, Ada!'
i18n.t('title', undefined, undefined, 'blog-post') // from locales/pages/blog/post/en.json
```

Le opzioni sono quelle del runtime (vedi [l'istanza](/it/integrations/overview#the-instance)) più `translationDir` e `disablePageLocales` (tratta i file `pages/**` come dizionari root). `i18n.reload()` svuota ogni dizionario e rilegge la cartella, utile per un file watcher in sviluppo.

`loadTranslations(dir, disablePageLocales?)` è esportata anche separatamente e restituisce `{ root, routes }`:

```ts
import { loadTranslations } from '@i18n-micro/node'

const { root, routes } = await loadTranslations('./locales')
// root:   { en: {...}, de: {...} }
// routes: { 'blog-post': { en: {...}, de: {...} } }
```

## Per richiesta {#per-request}

Un'istanza contiene un solo locale e una sola route. Cambiare `i18n.locale` su un'istanza condivisa all'interno di un request handler crea race condition con le richieste concorrenti. `run` fornisce a ogni richiesta la propria:

```ts
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

// `() => next()`: `run` hands its callback the fork, and Express reads an argument of `next` as an error
app.use((req, res, next) => i18n.run(pickLocale(req), () => next()))

app.get('/', (req, res) => {
  res.send(i18n.t('greeting')) // the request's locale, in everything it awaits
})
```

All'interno di `run` l'istanza condivisa legge e imposta il locale e la route della richiesta (`AsyncLocalStorage`); il fork parte dalla route corrente, e `i18n.setRoute(...)` all'interno della callback cambia la route di quella richiesta. La callback riceve anche il fork della richiesta: i dizionari scritti su di esso restano nella richiesta, quelli scritti sull'istanza condivisa raggiungono tutti.

Senza `AsyncLocalStorage`, `i18n.fork(locale)` restituisce lo stesso tipo di istanza da passare in giro.

`reload()` rilegge la directory; i vecchi dizionari rispondono finché non sono pronti quelli nuovi.

## Scegliere il locale {#pick-the-locale}

`detectLocaleFromAcceptLanguage(header, locales)` rispetta i pesi `q` e associa `de-DE` a un locale `de` (e `de` a `de-DE`). Restituisce `null` quando non c'è alcuna corrispondenza.

```ts
import express from 'express'
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

const app = express()

app.get('/hello', (req, res) => {
  const locale = detectLocaleFromAcceptLanguage(req.headers['accept-language'], locales) ?? 'en'
  const i18n = byLocale.get(locale)!
  res.json({ message: i18n.t('greeting', { name: 'Ada' }) })
})
```

Per prefisso URL, cookie e header insieme, `resolveLocale({ defaultLocale, validLocales, url, cookie, acceptLanguage, autoDetectLanguage: true })` da `@i18n-micro/utils/resolve-locale` applica la precedenza del modulo: URL, poi cookie, poi `Accept-Language`, poi il predefinito. I valori non validi vengono saltati.

All'interno di un'app Nuxt non hai bisogno di questo pacchetto sul server: usa le [traduzioni lato server](/it/guide/server-side-translations) del modulo.

| --- | --- |
| `createI18n(options)`, `I18n` | istanza runtime + `translationDir`, `loadTranslations(dir?)`, `reload()` |
