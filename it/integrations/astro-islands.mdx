Un'isola viene eseguita nel browser, dove l'istanza i18n del server non esiste. `@i18n-micro/astro` permette alla pagina di scegliere le chiavi di cui un'isola ha bisogno, passarle come un'unica prop e leggerle nell'isola tramite un piccolo adattatore per il framework. Ottieni `t`, `tc`, `tn`, `td`, `tdr` e `has` nelle isole Vue, React, Preact e Svelte, con solo le stringhe scelte nell'HTML.

## Configurazione {#setup}

Configura prima l'[integrazione e il middleware di Astro](/it/integrations/astro-package#setup), poi aggiungi l'integrazione del framework che usi (`@astrojs/vue`, `@astrojs/react`, `@astrojs/preact`, `@astrojs/svelte`). Gli adattatori per le isole richiedono quel framework come peer: `vue` `^3.3.0`, `react` `^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`, `preact` `^10.0.0 || ^11.0.0` o `svelte` `^4.0.0 || ^5.0.0`.

## Passare le traduzioni a un'isola {#pass-translations-to-an-island}

```astro
---
// src/pages/index.astro
import { getI18nProps } from '@i18n-micro/astro'
import Counter from '../components/Counter.vue'

const i18n = getI18nProps(Astro, ['counter.title', 'counter.apples'])
---

<Counter client:load i18n={i18n} />
```

`getI18nProps(Astro, keys?)` restituisce `{ locale, fallbackLocale, currentRoute, translations }` (tipo `I18nClientProps`). Passa le chiavi che l'isola usa: ognuna viene risolta sul server come `t()` (dizionari di route, root e di fallback) e solo le chiavi trovate finiscono nell'HTML. Senza `keys`, viene inviato tutto ciò a cui `t()` può rispondere in questa pagina, in ogni isola, quindi 2000 chiavi root sono circa 100 KB per isola; in sviluppo un avviso lo segnala oltre i 20 KB.

Le isole traducono solo a partire da quell'oggetto. `t` restituisce la chiave per tutto ciò che non è stato passato, e i messaggi collegati non vengono risolti.

## Vue {#vue}

Chiama `provideI18n(() => props.i18n)` nel componente root dell'isola e `useAstroI18n()` nei suoi figli. L'`inject` di Vue non vede un valore fornito dallo stesso componente, quindi l'hook deve essere eseguito in un figlio, non nel root:

```vue
<!-- src/components/Counter.vue -->
<script setup lang="ts">
import { provideI18n } from '@i18n-micro/astro/client/vue'
import type { I18nClientProps } from '@i18n-micro/astro'
import CounterBody from './CounterBody.vue'

const props = defineProps<{ i18n: I18nClientProps }>()
provideI18n(() => props.i18n)
</script>

<template><CounterBody /></template>
```

```vue
<!-- src/components/CounterBody.vue -->
<script setup lang="ts">
import { ref } from 'vue'
import { useAstroI18n } from '@i18n-micro/astro/client/vue'

const { t, tc } = useAstroI18n()
const count = ref(0)
</script>

<template>
  <h3>{{ t('counter.title') }}</h3>
  <button @click="count++">{{ tc('counter.apples', count) }}</button>
</template>
```

## React e Preact {#react-and-preact}

```tsx
// src/components/Counter.tsx
import { useState } from 'react'
import { I18nProvider, useAstroI18n } from '@i18n-micro/astro/client/react'
import type { I18nClientProps } from '@i18n-micro/astro'

function Body() {
  const { t, tc } = useAstroI18n()
  const [count, setCount] = useState(0)
  return <button onClick={() => setCount(count + 1)}>{t('counter.title')}: {tc('counter.apples', count)}</button>
}

export default function Counter({ i18n }: { i18n: I18nClientProps }) {
  return (
    <I18nProvider value={i18n}>
      <Body />
    </I18nProvider>
  )
}
```

Per Preact importa `I18nProvider` e `useAstroI18n` da `@i18n-micro/astro/client/preact`; l'API è la stessa.

## Svelte {#svelte}

```svelte
<!-- src/components/Counter.svelte -->
<script lang="ts">
  import { createI18nStore, useAstroI18n } from '@i18n-micro/astro/client/svelte'
  import type { I18nClientProps } from '@i18n-micro/astro'

  export let i18n: I18nClientProps
  const { t, tc } = useAstroI18n(createI18nStore(i18n))
  let count = 0
</script>

<button on:click={() => count++}>{t('counter.title')}: {tc('counter.apples', count)}</button>
```

`useAstroI18n(store)` restituisce anche lo `store` per le letture `$store` nel template.

## Isole persistenti {#persisted-islands}

Un'isola con `transition:persist` riceve nuove prop dopo una navigazione. React, Preact e Vue (se gli passi un getter) le seguono. In Svelte, conserva lo store e passale a esso: `const store = createI18nStore(i18n)`, `const { t } = useAstroI18n(store)`, poi `$: store.set(i18n)` (con le runes, `$effect(() => store.set(i18n))`).

## API {#api}

| Entry | Export |
| --- | --- |
| `@i18n-micro/astro` | `getI18nProps`, tipo `I18nClientProps` |
| `@i18n-micro/astro/client/vue` | `provideI18n(props \| () => props)`, `useAstroI18n()` |
| `@i18n-micro/astro/client/react` | `I18nProvider` (prop `value`), `useAstroI18n()` |
| `@i18n-micro/astro/client/preact` | `I18nProvider` (prop `value`), `useAstroI18n()` |
| `@i18n-micro/astro/client/svelte` | `createI18nStore(props)`, `useAstroI18n(store)` |
| `@i18n-micro/astro/client` | le funzioni pure `translate`, `hasTranslation`, senza framework |

Ogni `useAstroI18n` restituisce `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `setLocale`, `setRoute` e il `locale`. Un'isola ha un unico dizionario unito, quindi il suo `has` è vero per qualsiasi chiave a cui `t` può rispondere, anche dal locale di fallback; sul server `has` considera solo il locale attivo.
