`@i18n-micro/devtools-ui` è l'editor di traduzioni della scheda di Nuxt DevTools, impacchettato come web component con un plugin Vite. Aggiungilo a un progetto Vue, React, Preact, Solid o Astro per sfogliare e modificare dal browser, durante lo sviluppo, i file JSON della cartella delle traduzioni. Le app Nuxt lo hanno già in [Nuxt DevTools](/it/guide/devtools).

![La DevTools UI: un albero dei file e un editor con il testo del locale predefinito accanto a ogni chiave](/images/devtools/02-translations-editor-dark.webp)

## Installazione {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/devtools-ui
```

```bash npm
npm install -D @i18n-micro/devtools-ui
```

```bash yarn
yarn add -D @i18n-micro/devtools-ui
```

</CodeGroup>

Nessuna peer dependency.

## Configurazione {#setup}

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import { i18nDevToolsPlugin } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  plugins: [i18nDevToolsPlugin({ translationDir: 'src/locales' })],
})
```

| Opzione | Predefinito | Note |
| --- | --- | --- |
| `translationDir` | `'src/locales'` | Cartella con i file JSON, relativa alla root di Vite. |
| `base` | `'/__i18n_api'` | Percorso base degli endpoint API. |
| `injectButton` | `true` | Aggiunge un pulsante flottante alle pagine servite tramite la trasformazione `index.html` di Vite. Astro non ha pagine di questo tipo: vedi sotto. |
| `defaultLocale` | primo file di locale in `translationDir` | Restituito da `/config`. |
| `fallbackLocale` | `defaultLocale` | Restituito da `/config`. |

Il plugin viene eseguito solo sul dev server (`apply: 'serve'`); una build di produzione non contiene nulla di esso. Il pulsante apre `/__i18n_devtools.html`, che legge e salva i file tramite gli endpoint del plugin:

| Endpoint | Cosa fa |
| --- | --- |
| `GET <base>/translations` | ogni dizionario sotto `translationDir`, per percorso relativo |
| `POST <base>/save` | body `{ file, content }`; sovrascrive un `.json` esistente dentro `translationDir`, 403 per qualsiasi altra cosa. Non crea mai un file |
| `GET <base>/config` | `{ defaultLocale, fallbackLocale, locales, translationDir }`; `locales` provengono dai file root in `translationDir` |

Gli endpoint rispondono solo alla pagina dei devtools: una richiesta da un'altra origine o da un altro host riceve un `403`, e `/save` accetta solo `application/json` (`415`). La pagina viene informata delle modifiche ai file tramite il socket HMR di Vite.

In Astro, aggiungi l'integrazione invece del plugin. Aggiunge un'app alla dev toolbar:

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import { i18nDevToolsIntegration } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  integrations: [i18nDevToolsIntegration({ translationDir: 'src/locales' })],
})
```

Il salvataggio scrive solo il file. Un'app che importa il JSON tramite Vite lo riceve tramite HMR; per modifiche applicate direttamente all'istanza in esecuzione, usa un bridge.

## Bridge verso un'istanza attiva {#bridge-to-a-live-instance}

Per incorporare l'editor in una tua pagina e far applicare subito le modifiche all'istanza in esecuzione, crea un bridge da un adapter e passalo all'elemento `<i18n-devtools-ui>`:

```ts
import { createBridge, register } from '@i18n-micro/devtools-ui'
import { i18n, locales } from './i18n' // a runtime, React, Preact or Solid instance

register() // defines <i18n-devtools-ui> once

const bridge = createBridge({
  adapter: {
    getRouteCache: () => Object.fromEntries(i18n.storage.translations),
    addTranslations: (locale, content, merge) => i18n.addTranslations(locale, content, merge),
    addRouteTranslations: (locale, route, content, merge) => i18n.addRouteTranslations(locale, route, content, merge),
    subscribe: (cb) => i18n.subscribe(cb),
    getCurrentLocale: () => i18n.locale,
  },
  locales,
  defaultLocale: 'en',
  translationDir: 'src/locales',
})

const el = document.createElement('i18n-devtools-ui') as HTMLElement & { bridge: typeof bridge }
el.bridge = bridge
document.body.append(el)
```

`getRouteCache` deve restituire i dizionari con chiavi `locale:route` (`en:index`, `en:blog-post`), che è ciò che contiene `i18n.storage.translations`. Per un'istanza Vue usa `i18n.global.getRouteCache()` e `i18n.global.subscribeToChanges(cb)`.

`saveTranslation` aggiorna prima l'istanza, poi invia un POST a `<base>/save`. Quando non c'è alcun endpoint (una build di anteprima statica) o il dev server non è raggiungibile, la modifica viene conservata in `localStorage`; qualsiasi altro errore di salvataggio ripristina il dizionario precedente e lancia un'eccezione.
