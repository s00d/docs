# useI18nLocale

## Firma

Punto di ingresso centralizzato per la gestione della locale i18n.
Combina useState('i18n-locale'), il cookie della locale e utility di sincronizzazione.

## Utilizzo

```vue
<script setup>
const {
  locale,
  localeCookie,
  hashCookie,
  validLocales,
  getPreferredLocale,
  getLocale,
  getLocaleWithServerFallback,
  getEffectiveLocale,
  resolveInitialLocale,
  setLocale,
  syncLocale,
  isValidLocale,
} = useI18nLocale()

// Set locale (updates state and cookies)
setLocale('de')

// Get current locale (state → cookie)
const current = getLocale()

// Get valid preferred locale
const preferred = getPreferredLocale()
</script>
```

## API

| Proprietà/Metodo                                | Tipo                                | Descrizione                                                                          |
| ----------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------ |
| `locale`                                        | `Ref<string \| null>`               | Stato reattivo della locale (`useState('i18n-locale')`)                              |
| `localeCookie`                                  | `Ref`                               | Cookie della locale (quando l'opzione `localeCookie` è abilitata)                    |
| `hashCookie`                                    | `Ref`                               | Cookie utilizzato quando `hashMode` è attivo                                         |
| `validLocales`                                  | `string[]`                          | Codici locale abilitati dalla config del modulo (esclude `disabled`)                 |
| `getLocale()`                                   | `() => string \| null`              | Locale corrente: state → cookie (o hash cookie in modalità hash)                     |
| `getPreferredLocale()`                          | `() => string \| null`              | Locale dallo state/cookie **validata** rispetto a `validLocales`, o `null`           |
| `getLocaleWithServerFallback(serverLocale?)`    | `(serverLocale?) => string \| null` | state → cookie → contesto server opzionale (usato durante l'init `no_prefix`)        |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string`             | Locale per caricare le traduzioni: la modalità hash preferisce lo state; altrimenti legge dalla route |
| `resolveInitialLocale(options)`                 | `(options) => string`               | Risolve la locale: state → `serverLocale` → route; sincronizza lo state quando necessario |
| `setLocale(locale)`                             | `(locale: string \| null) => void`  | Imposta la locale e sincronizza sui cookie                                           |
| `syncLocale(locale)`                            | `(locale: string \| null) => void`  | Sincronizza solo i cookie (nessun aggiornamento dello state)                         |
| `isValidLocale(locale)`                         | `(locale) => boolean`               | Verifica se la stringa è in `validLocales`                                           |

### Opzioni di `resolveInitialLocale`

```typescript
interface ResolveInitialLocaleOptions {
  route: unknown
  serverLocale?: string | null
  getLocaleFromRoute: (route?: unknown) => string
}
```

Utilizzato internamente dal plugin principale all'avvio. I plugin custom possono chiamarlo quando implementano flussi di rilevamento alternativi.

### `getEffectiveLocale`

```typescript
const { getEffectiveLocale } = useI18nLocale()
const { $getLocale } = useNuxtApp()

const locale = getEffectiveLocale(route, (r) => $getLocale(r))
```

Restituisce la locale usata per caricare le traduzioni e formattare i messaggi per un dato oggetto route.

## Impostazione programmatica della locale

Preferisci `useI18nLocale()` rispetto all'uso diretto di `useState('i18n-locale')`:

```ts
// plugins/i18n-loader.server.ts
import { defineNuxtPlugin } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,

  setup() {
    const { setLocale } = useI18nLocale()
    const detectedLocale = 'ja' // Your detection logic here
    setLocale(detectedLocale)
  },
})
```

<Tip>
`setLocale()` aggiorna solo la preferenza della locale (state + cookie). Per ricaricare anche il contesto di traduzione attivo sul client, usa `$switchLocale()` da `useNuxtApp()` o `useI18n()`. Questo è particolarmente importante per `no_prefix`, dove l'URL non cambia. Consulta [FAQ — cambia locale senza modificare l'URL](/guides/faq#-switch-locale-without-changing-the-url).
</Tip>
