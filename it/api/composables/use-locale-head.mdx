# 🌍 Composable `useLocaleHead`

Il composable `useLocaleHead` è un'utility di `Nuxt I18n Micro` che aiuta a gestire gli attributi SEO e i tag meta HTML per le route localizzate. Genera dinamicamente gli attributi `lang` e `dir` del documento HTML e crea tag `meta` e `link` per migliorare la SEO del contenuto localizzato.

I tag head SEO per la route corrente: alternate `hreflang` per ogni locale più
`x-default`, un link canonical, `og:locale` e `lang`/`dir` su `<html>`.

Necessario solo quando `meta` è disabilitato o i valori predefiniti richiedono aggiustamenti. Con `meta: true`
il modulo registra gli stessi tag da solo.

## 🛠️ Valori di ritorno

Il composable `useLocaleHead` restituisce un oggetto reattivo e una funzione updater che dovresti
chiamare quando i dati sorgente cambiano. Entrambe le forme sono nella firma sopra, generata dal
sorgente.

### `metaObject`

Payload head reattivo (html attrs, meta, link) adatto per `useHead(metaObject)`.

- **Esempio**:
  ```js
  const { metaObject } = useLocaleHead()
  useHead(metaObject)
  ```

### `updateMeta`

Ricalcola `metaObject` in base a route, locale e config correnti. Chiamalo quando gli input
cambiano, ad esempio al cambio di route.

- **Esempio**:
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  useHead(metaObject)
  watch(
    () => route.fullPath,
    () => updateMeta(),
    { immediate: true },
  )
  ```

### Accedere a `link` e `meta`

Gli array `link` e `meta` sono accessibili tramite `metaObject.value`:

- **Esempio**:
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  updateMeta()
  console.log(metaObject.value.link)
  // Output: [{ id: 'i18n-can', rel: 'canonical', href: 'https://example.com/about' }, ...]
  console.log(metaObject.value.meta)
  // Output: [{ id: 'i18n-og', property: 'og:locale', content: 'en_US' }, ...]
  ```

## 🛠️ Esempi d'uso

### Utilizzo di base

Genera attributi head specifici per locale con le opzioni predefinite.

```js
const head = useLocaleHead()
```

### Personalizzare l'attributo identificatore

Usa un attributo identificatore personalizzato per i tag generati.

```js
const head = useLocaleHead({ identifierAttribute: 'data-i18n' })
```

### Disabilitare gli attributi SEO

Genera attributi head senza aggiungere tag meta e link relativi al SEO.

```js
const head = useLocaleHead({ addSeoAttributes: false })
```

### Specificare un URL base

Imposta un URL base personalizzato per gli URL canonici e alternate.

```js
const head = useLocaleHead({ baseUrl: 'https://mywebsite.com' })
```

## 🚀 Funzionalità aggiuntive

### Tag meta e link SEO

Quando `addSeoAttributes` è abilitato, il composable genera automaticamente i seguenti tag:

- `og:locale` per la locale corrente (`language_TERRITORY`, con underscore). Derivato da `locale.og` o convertito da `locale.iso` quando possibile.
- `og:url` per l'URL canonico della pagina.
- `og:locale:alternate` per versioni di lingua alternative.
- Link `rel="canonical"` e `rel="alternate"` per l'ottimizzazione SEO.
- Link `hreflang="x-default"` che punta all'URL della locale predefinita. Indica ai motori di ricerca quale URL mostrare agli utenti la cui lingua non corrisponde a nessuna delle locale definite.

### Locale e direzione dinamiche

Il composable determina dinamicamente gli attributi `lang` e `dir` in base alla locale della route corrente, garantendo che il tuo documento HTML sia configurato correttamente per gli utenti internazionali.

### Gestione delle route localizzate

Se le tue route sono prefissate con codici locale (ad esempio `/en/about`), il composable regola in modo intelligente il full path per generare URL, assicurando che gli attributi SEO siano accurati e pertinenti.

Questo composable semplifica il processo di ottimizzazione della tua applicazione Nuxt per il pubblico internazionale, garantendo che il sito sia ben preparato per i motori di ricerca e gli utenti globali.

## 🛠️ Esempio d'uso

Il seguente esempio mostra come utilizzare il composable `useLocaleHead` all'interno di un componente Vue con le impostazioni predefinite:

```vue
<script setup>
import { useRoute, watch } from '#imports'
const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({
  addDirAttribute: true,
  identifierAttribute: 'id',
  addSeoAttributes: true,
})
useHead(metaObject)
watch(
  () => route.fullPath,
  () => updateMeta(),
  { immediate: true },
)
</script>
```

### Spiegazione del codice

- **Composable `useLocaleHead`**: viene chiamato nella sezione `<script setup>` e restituisce un oggetto contenente `htmlAttrs`, `meta` e `link`.

- **Tag `<html>`**: gli attributi `lang` e `dir` del documento HTML sono determinati dinamicamente in base alla locale corrente e vengono applicati al tag `<html>`.

- **Sezione `<head>`**:
  - **Tag meta**: vengono generati tag meta relativi a SEO, tra cui `og:locale`, `og:url` e tag `rel="canonical"` e `rel="alternate"` per specificare versioni di lingua alternative della pagina.
  - **Tag link**: sono inclusi link canonical, link a versioni di lingua alternative e il link `hreflang="x-default"` (che punta all'URL della locale predefinita).

- **Sezione `<body>`**: qui viene visualizzato il contenuto principale della pagina. In questo esempio, vengono utilizzati un semplice header e un paragrafo.

### 📝 Note

1. **Attributi**: gli attributi utilizzati (`lang`, `dir`, `rel`, `href`, `hreflang`, `property`, `content`) vengono estratti dall'oggetto restituito da `useLocaleHead`.

2. **Generazione dei tag SEO**: se l'opzione `addSeoAttributes` è impostata a `true`, il composable genera automaticamente tag SEO per la locale corrente.

3. **URL base**: puoi impostare il tuo URL base personalizzato usando l'opzione `baseUrl` per generare correttamente link canonici e alternate.

Questo esempio dimostra quanto sia facile integrare `useLocaleHead` nei componenti della tua applicazione per garantire attributi SEO corretti e migliorare l'indicizzazione nei motori di ricerca delle pagine localizzate.

## 🧩 Personalizzazione e ciclo di vita

- `useLocaleHead` non si sottoscrive alle modifiche da solo. Restituisce `metaObject` e `updateMeta`.
- Dovresti chiamare `updateMeta()` quando gli input cambiano (tipicamente al cambio di route), ad esempio da un plugin:

```ts
// plugins/02.meta.ts
export default defineNuxtPlugin(() => {
  const route = useRoute()
  const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
  useHead(metaObject)
  if (import.meta.server) updateMeta()
  else
    watch(
      () => route.fullPath,
      () => updateMeta(),
      { immediate: true },
    )
})
```

## Quando usare invece `useI18nHead`

Quando `meta: true` (predefinito), preferisci [`useI18nHead`](/api/composables/use-i18n-head) per override **per pagina** (hreflang personalizzati, `og:title` aggiuntivi, disabilitazione parziale). Usa `useLocaleHead` direttamente solo quando `meta: false` o gestisci `useHead` da solo.
