Il modulo inietta i suoi helper di runtime nell'app Nuxt: `$t`, `$tc`, `$localePath`, `$switchLocale` e gli altri. Usa questa pagina per consultare la firma e il comportamento di un helper. Firme e descrizioni provengono dalle interfacce `PluginsInjections` e `NuxtAppOnlyInjections` in `src/runtime/plugins/01.plugin.ts`.

## Accesso {#access}

| Dove | Come |
| --- | --- |
| Template | `{{ $t('title') }}` — ogni helper, con il `$` |
| `<script setup>` | `const { t, localePath } = useI18n()` — ogni helper in `PluginsInjections`, con e senza il `$` |
| Plugin, middleware, `<script setup>` | `const { $t, $defineI18nRoute } = useNuxtApp()` — tutto, solo con il `$` |

`$defineI18nRoute` è tipizzato solo su `useNuxtApp()`. Vedi [`useI18n`](/it/composables/useI18n).

```vue
<script setup lang="ts">
const { t, localePath } = useI18n()
</script>

<template>
  <NuxtLink :to="localePath('/about')">{{ t('nav.about') }}</NuxtLink>
</template>
```

## Lingua {#locale}

### `$getLocale` {#$getlocale}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric) => string
```

Codice della lingua attiva. Passa una rotta per leggere la lingua a cui appartiene quella rotta.

```ts
$getLocale() // 'de' on /de/about
```

### `$getLocaleName` {#$getlocalename}

```ts
() => string | null
```

Il `displayName` della lingua attiva dalla configurazione, o `null` se non ne ha uno.

### `$getLocales` {#$getlocales}

```ts
() => Locale[]
```

Ogni lingua configurata, con i suoi metadati.

Le proprietà personalizzate di un oggetto lingua vengono restituite così come sono state scritte; tipizzale con la [module augmentation](/it/api/module-options#locales) di `Locale`.

### `$defaultLocale` {#$defaultlocale}

```ts
() => string | undefined
```

Codice della lingua predefinita configurata.

### `$getI18nConfig` {#$geti18nconfig}

```ts
() => ResolvedI18nConfig
```

La configurazione risolta del modulo, così come la vede il runtime.

Il valore include le [sovrascritture di runtime](/it/guide/runtime-overrides) (`defaultLocale`, `fallbackLocale`, lingue disabilitate).

```ts
const { strategy, localeCookie } = useNuxtApp().$getI18nConfig()
```

## Traduzione {#translation}

### `$t` {#$t}

```ts
TranslationFn<CleanTranslation>
```

Traduce una chiave, interpolandovi `params`. Restituisce `defaultValue` quando la chiave
manca, o la chiave stessa quando non viene fornito un valore predefinito.

```ts
// { "welcome": "Welcome, {name}!" }
$t('welcome', { name: 'Ada' }) // 'Welcome, Ada!'
$t('missing.key', {}, 'Fallback') // 'Fallback'
```

Una chiave che punta a un oggetto annidato restituisce quell'oggetto, non una stringa. In un template viene renderizzata come `[object Object]`; usa una chiave foglia.

### `$ts` {#$ts}

```ts
TranslationFn<string>
```

Come `$t`, ma restituisce sempre una stringa: il valore passa per `toString()`, quindi un oggetto
annidato diventa `'[object Object]'`. Fai puntare la chiave a una foglia.

### `$_t` {#$_t}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<CleanTranslation>
```

Lega `$t` a una rotta specifica, per tradurre al di fuori della pagina corrente — ad esempio un layout
che renderizza un link a un'altra rotta.

```ts
const route = useRoute()
const t = useNuxtApp().$_t(route)
t('page.title')
```

### `$_ts` {#$_ts}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<string>
```

Lega `$ts` a una rotta specifica. Vedi `$_t`.

### `$tc` {#$tc}

```ts
(key: TranslationKey, params: number | Params, defaultValue?: string) => string
```

Traduce con pluralizzazione. `params` può essere il conteggio stesso, o un oggetto che contiene
`count`.

Le forme sono separate da `|`. Con la regola integrata un conteggio intero non negativo `n` sceglie la forma `n`, limitata all'ultima forma; un conteggio negativo, frazionario o `NaN` prende l'ultima forma. `{count}` e gli altri parametri vengono interpolati nella forma scelta.

Per le lingue i cui plurali non seguono il conteggio, inizia il template con `=0 `. La prima forma è allora per 0, e le altre seguono la categoria di [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules), nell'ordine `zero, one, two, few, many, other`:

```json
{
  "apples": "=0 no apples | one apple | {count} apples",
  "files": "=0 no files | {count} one | {count} few | {count} many"
}
```

```ts
$tc('apples', 0) // 'no apples'
$tc('apples', 1) // 'one apple'
$tc('apples', 7) // '7 apples'

// In `uk` (categories `one, few, many, other`) the forms after the zero form follow those categories:
$tc('files', 21) // '21 one'
$tc('files', 22) // '22 few'
$tc('files', 25) // '25 many'
$tc('files', 2.5) // '2.5 many': no form for `other`, so the last one
```

- `=0 ` conta solo all'inizio esatto del valore, con lo spazio. `$t` lo mostra come testo: appartiene ai plurali.
- Una categoria senza una propria forma prende l'ultima forma. Anche un conteggio negativo o frazionario prende l'ultima forma.
- Funziona in qualsiasi lingua: `=0 none | one | {count} many` in inglese.
- La categoria deriva dall'`iso` della lingua, altrimenti dal suo codice. Un codice che `Intl` non conosce ricade sulla regola dell'indice, con il marcatore comunque rimosso, così il risultato non dipende mai dalla macchina.
- `<i18n-t :plural>` segue la stessa regola. Un [`plural`](/it/api/module-options#plural) personalizzato o `customPluralRule` riceve il valore grezzo, marcatore incluso, e decide da sé; se `plural` restituisce `null` la chiamata torna alla regola integrata, che rispetta il marcatore.

Senza il marcatore un template resta sulla regola dell'indice, con un'eccezione che si può leggere in un solo modo: una forma zero senza segnaposto, poi una forma per categoria, con `{count}` in ogni forma condivisa da più conteggi (`no files | {count} one | {count} few | {count} many` in `uk`).

Per regole personalizzate imposta [`plural`](/it/api/module-options#plural).

```ts
// { "apples": "no apples | one apple | {count} apples" }
$tc('apples', 0) // 'no apples'
$tc('apples', 10) // '10 apples'
$tc('cart', { count: 2, name: 'Ada' }) // count and params in one object
```

Il terzo argomento è `defaultValue`, non params.

### `$has` {#$has}

```ts
(key: string) => boolean
```

Se una chiave viene risolta nella lingua attiva. Usalo per scegliere testi opzionali invece di
renderizzare una chiave grezza. Come `$t`, vede anche le chiavi della pagina che si sta lasciando durante una
transizione di pagina nella stessa lingua.

```ts
if ($has('promo.banner')) show.value = true
```

## Formattazione {#formatting}

### `$tn` {#$tn}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

Formatta un numero con `Intl.NumberFormat` nella lingua attiva. Una chiave seleziona un formato con nome
dalla configurazione.

I formati con nome provengono da [`numberFormats`](/it/api/module-options#numberformats).

```ts
$tn(1234.5, { style: 'currency', currency: 'EUR' }) // '1.234,50 €' in de
$tn(1000, 'currency') // named format
$tn(1000, 'currency', 'de') // named format in another locale
```

### `$td` {#$td}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

Formatta una data con `Intl.DateTimeFormat` nella lingua attiva. Una chiave seleziona un formato con nome
dalla configurazione.

I formati con nome provengono da [`datetimeFormats`](/it/api/module-options#datetimeformats).

```ts
$td(new Date(), { dateStyle: 'long' })
$td(post.createdAt, 'short')
```

### `$tdr` {#$tdr}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

Formatta una data come tempo relativo ("3 giorni fa") con `Intl.RelativeTimeFormat`.

```ts
$tdr(Date.now() - 5 * 60_000) // '5 minutes ago' in en
```

## Cambio di lingua e link {#switching-and-links}

### `$switchLocale` {#$switchlocale}

```ts
(locale: string) => Promise<boolean>
```

Naviga alla pagina corrente in un'altra lingua. Con `no_prefix` e in modalità hash carica le
traduzioni della lingua prima di navigare; con `no_prefix` la rotta viene sostituita sul posto (nessuna
nuova voce nella cronologia). Una lingua sconosciuta viene ignorata.
La chiamata è asincrona: usa `await` per eseguire codice dopo la navigazione. Si risolve con `true` quando il
dizionario della lingua è attivo, `false` quando non lo è: il chunk non è stato caricato (il dizionario
corrente resta; chiamala di nuovo per riprovare) oppure ha prevalso un cambio più recente.

```ts
await $switchLocale('de')
```

### `$switchLocalePath` {#$switchlocalepath}

```ts
(locale: string) => string
```

Il percorso della pagina corrente in un'altra lingua, senza navigare.

```vue
<NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
```

### `$switchLocaleRoute` {#$switchlocaleroute}

```ts
(locale: string) => RouteLocationRaw
```

L'oggetto rotta per la pagina corrente in un'altra lingua, senza navigare, o una stringa URL
per una lingua con il proprio `baseUrl`. Con `trailingSlash` l'oggetto ha `path` e `fullPath`
conformi alla regola, con `query` e `hash` invariati, e `router.push` o un link li mantengono.

### `$switchRoute` {#$switchroute}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => Promise<void>
```

Naviga a un'altra rotta, mantenendo la lingua attiva o passando a `toLocale`. Asincrona come
`$switchLocale`.

```ts
$switchRoute('/about') // active locale
$switchRoute({ name: 'about' }, 'de') // switch to de
```

### `$localePath` {#$localepath}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => string
```

Risolve un percorso nella lingua indicata, o in quella attiva. Una stringa con schema `http(s):`, `mailto:`
o `tel:` viene restituita così com'è: non passare input dell'utente come destinazione di un link senza controllarlo.

Un percorso stringa viene interpretato come la pagina che mostra, quindi viene applicato anche il percorso personalizzato di una lingua.

```ts
$localePath('/about') // '/about' in en, '/de/ueber-uns' in de with localeRoutes
$localePath({ name: 'about' }, 'fr') // '/fr/about'
```

### `$localeRoute` {#$localeroute}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => RouteLocationResolved
```

Risolve una rotta nella lingua indicata, o in quella attiva. Un oggetto semplice, sicuro da conservare nello stato. Quando un parametro richiede
l'escape ha `path`, `fullPath`, `query` e `hash` ma non `name` né `params`: è il percorso a fornire al router
l'URL codificato. Per una lingua su un altro dominio `path` e `fullPath` sono assoluti, cosa che il router non accetta:
un link del genere passa per `<i18n-link>`, o `$localePath`.

### `$getRouteName` {#$getroutename}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric, locale?: string) => string
```

Nome della rotta senza il prefisso della lingua — il nome con cui sono indicizzate le traduzioni.

```ts
$getRouteName() // 'about' on /de/about
```

## Configurazione della pagina {#page-config}

### `$defineI18nRoute` {#$definei18nroute}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

Registra la configurazione delle lingue e le traduzioni per pagina dall'interno di un componente.
Le unisce nella lingua attiva e le riapplica quando la lingua cambia.

Chiamalo nello `<script setup>` di una pagina, sempre destrutturato da `useNuxtApp()`. La build legge `locales`, `localeRoutes` e `disableMeta` dalla chiamata; a runtime conta solo `locales` (le traduzioni inline vengono unite per la lingua attiva). Regole complete: [Configurazione della pagina](/it/guide/per-component-translations).

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: { en: '/about', de: '/ueber-uns' },
})
</script>
```

### `$setI18nRouteParams` {#$seti18nrouteparams}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

Imposta parametri per lingua per la rotta corrente, così che un segmento dinamico possa differire per lingua.
Chiamalo durante l'SSR, prima che l'head venga renderizzato.

I parametri vengono azzerati quando viene confermata una navigazione verso un altro percorso, incluso da `/news/1` a `/news/4`, che mantiene il nome della rotta. Dettagli: [Percorsi localizzati](/it/guide/custom-locale-routes).

```ts
$setI18nRouteParams({
  en: { slug: 'my-post' },
  de: { slug: 'mein-beitrag' },
})
```

## Traduzioni a runtime {#runtime-translations}

### `$mergeTranslations` {#$mergetranslations}

```ts
(newTranslations: Translations) => void
```

Unisce traduzioni nella lingua attiva a runtime, sovrascrivendo ciò che è caricato.

Esegue un merge profondo nel chunk della pagina corrente della lingua attiva; le chiavi non menzionate restano.

```ts
$mergeTranslations({ banner: { title: 'Sale' } })
```

### `$setTranslation` {#$settranslation}

```ts
(key: string, value: unknown) => void
```

Sostituisce il valore in `key` nel dizionario attivo. È una sostituzione, non un merge —
usa `$mergeTranslations` quando le chiavi sorelle esistenti devono restare.

```ts
$setTranslation('banner', { title: 'Sale' }) // drops other keys under banner
$setTranslation('banner.title', 'Sale') // dotted path
```

### `$loadPageTranslations` {#$loadpagetranslations}

```ts
(locale: string, routeName: string, translations: Translations) => Promise<void>
```

Carica le traduzioni di una pagina a runtime, per contenuti le cui chiavi non sono note in fase di build.

Le unisce nel chunk in memoria `(locale, routeName)`, e lo schermo si aggiorna quando quel chunk è attivo. Qui non viene recuperato alcun payload: per una pagina non ancora caricata le traduzioni restano in attesa, e quando il suo file viene caricato rimangono sopra di esso.

```ts
await $loadPageTranslations('en', 'about', { title: 'About us' })
```

### `$resolveTranslations` {#$resolvetranslations}

```ts
() => Translations
```

Ogni traduzione attualmente in memoria per la lingua e la rotta attive, come albero.
Vista in sola lettura di ciò che `$t()` può risolvere in questo momento.

Tratta il risultato come di sola lettura.

### `$setMissingHandler` {#$setmissinghandler}

```ts
(handler: MissingHandler | null) => void
```

Installa una callback invocata per ogni chiave non risolta. Passa `null` per rimuoverla.

L'handler viene eseguito al posto dell'avviso di sviluppo.

```ts
$setMissingHandler((locale, key, routeName) => {
  console.error(`[i18n] missing ${key} in ${locale} (${routeName})`)
})
```

### `$clearCache` {#$clearcache}

```ts
() => void
```

Elimina ogni chunk di traduzione in cache e ricarica il dizionario della pagina corrente. La pagina
continua a mostrare le traduzioni attuali finché non arrivano quelle nuove. L'HMR di sviluppo la chiama a
ogni modifica di un file di traduzione.

```ts
const { clearCache } = useI18n()
clearCache()
```

Un ricaricamento non riuscito mantiene il dizionario corrente.
