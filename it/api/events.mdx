Il modulo chiama un solo hook runtime (dell'app), `i18n:register`. Usalo quando un plugin o un modulo aggiunge traduzioni che non si trovano nei tuoi file `locales/`. La tua callback riceve una funzione `register` che unisce le traduzioni nella pagina che viene mostrata.

## `i18n:register` {#i18nregister}

```ts
'i18n:register': (
  register: (translations: unknown, locale?: string) => void,
  locale: string,
) => HookResult
```

| Argomento | Descrizione |
| --- | --- |
| `register(translations, locale?)` | Unisce in profondità `translations` nel chunk di pagina della route in caricamento, per `locale` (predefinito: il `locale` dell'hook). Le chiavi già presenti vengono sovrascritte. |
| `locale` | Il locale della route in caricamento. |

L'hook è tipizzato tramite `RuntimeNuxtHooks`, quindi `nuxtApp.hook('i18n:register', …)` non richiede cast.

## Quando viene eseguito {#when-it-fires}

Il plugin loader (`i18n-plugin-loader`) lo chiama:

1. una volta all'avvio, quando tutti i plugin sono stati eseguiti (`app:created`) e prima che l'app venga renderizzata;
2. nel suo `router.beforeEach`, dopo che le traduzioni della pagina di destinazione sono state caricate, quando il percorso cambia — a ogni navigazione con `no_prefix`.

Ogni callback e ogni chiamata a `register` vengono attese prima che l'app venga renderizzata o che la navigazione prosegua, quindi la pagina viene renderizzata con le chiavi unite. Con [`hooks: false`](/it/api/module-options#hooks) l'hook non viene mai chiamato.

## Esempio {#example}

```ts
// plugins/i18n-extra.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('i18n:register', async (register, locale) => {
    const extra = await $fetch<Record<string, unknown>>(`/api/cms-strings/${locale}`)
    register(extra, locale)
  })
})
```

Questo è un hook runtime: registralo con `nuxtApp.hook` in un plugin, non con `nuxt.hook` in `nuxt.config` o nel `setup` di un modulo. Un modulo aggiunge un plugin di questo tipo con `addPlugin`.
