Questa pagina elenca ogni chiave dell'oggetto `i18n` in `nuxt.config`. Usa le tabelle per consultare un tipo o un valore predefinito, e i dettagli più sotto per esempi e avvertenze. Tipi, valori predefiniti e descrizioni sono generati dall'interfaccia `ModuleOptions` in [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).

```ts nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
    ],
    defaultLocale: 'en',
  },
})
```

Un'opzione annidata compare con il suo percorso puntato: `translationPayloads.mode` è la chiave `mode` di `translationPayloads`.

## Locale e routing {#locales-and-routing}

Quali lingue esistono e come compaiono nell'URL.

| Opzione | Tipo | Predefinito | Descrizione |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Elenco dei locale supportati. Ogni voce definisce un codice di locale più metadati opzionali (ISO, direzione, nome visualizzato, ecc.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Strategia di routing degli URL per i prefissi di locale. - `'no_prefix'` — nessun locale nell'URL; il locale è salvato in un cookie. - `'prefix_except_default'` — prefisso per tutti i locale tranne quello predefinito. - `'prefix'` — prefisso sempre, incluso il locale predefinito. - `'prefix_and_default'` — come `prefix`, ma il locale predefinito è accessibile anche senza prefisso. |
| `defaultLocale` | `string` | `'en'` | Il locale da usare quando non è possibile determinarne uno dall'URL o dalle preferenze dell'utente. Non è un fallback di traduzione: per quello imposta `fallbackLocale`. |
| `localeCookie` | `string \| null` | `null` | Nome del cookie per mantenere la preferenza di locale dell'utente tra le sessioni. Imposta `null` per disattivare la persistenza tramite cookie. Viene impostato automaticamente a `'user-locale'` per la strategia `no_prefix` se non specificato; un `null` esplicito nel blocco di configurazione `i18n` lo mantiene disattivato anche lì. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `{}` | Configurazione globale dei locale a livello di route. Permette di limitare o personalizzare le route localizzate di pagine specifiche senza modificarne i componenti. - `false` — esclude la route dalla localizzazione. - `Record<LocaleCode, string>` — percorsi personalizzati per locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Espressione regolare personalizzata (o la sua stringa sorgente) per riconoscere i codici di locale nei segmenti dell'URL. Ogni codice di locale in `locales` deve corrispondere all'intero pattern, senza i suoi flag, altrimenti la build fallisce. |
| `noPrefixRedirect` | `boolean` | `false` | Per la strategia `no_prefix`: quando il locale predefinito ha un percorso personalizzato per una pagina (`localeRoutes` / `globalLocaleRoutes`), reindirizza il percorso originale della pagina al percorso personalizzato del locale del visitatore, altrimenti a quello del locale predefinito (ad es. `/about` → `/about-us`). Un locale senza un proprio percorso personalizzato resta sul percorso originale. Le pagine con segmenti dinamici non vengono reindirizzate. |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Percorsi da escludere dal routing i18n: una stringa è un prefisso di percorso (`/admin` copre `/admin/x`) o un glob `*` / `?`; una RegExp viene testata sul percorso. Le pagine corrispondenti non hanno varianti di locale, né reindirizzamento di locale o 404, e vengono escluse dal prerender; vengono comunque renderizzate con le traduzioni. `/api`, `/_nuxt`, `/__*`, la route delle traduzioni e i comuni file statici (sitemap, robots.txt, favicon, asset per estensione) sono sempre esclusi. |
| `routeLocales` | `Record<string, string[]>` | — | Restrizioni di locale per route, estratte in fase di build dalle chiamate a `$defineI18nRoute()`. Associa un percorso di route (ad es. `'/about'`) a un array di codici di locale consentiti. Le route non elencate non hanno restrizioni (tutti i locale consentiti). |

## Traduzioni {#translations}

Dove si trovano i file di traduzione e come vengono risolte le chiavi.

| Opzione | Tipo | Predefinito | Descrizione |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Percorso della directory che contiene i file JSON di traduzione, relativo alla radice del progetto. |
| `disableWatcher` | `boolean` | `false` | Disattiva il file watcher che crea automaticamente i file di traduzione mancanti in modalità sviluppo. |
| `routesLocaleLinks` | `{ [key: string]: string }` | `{}` | Associa nomi di route ad altri nomi di route per condividere gli stessi file di traduzione. Ad esempio, `{ 'about-us': 'about' }` significa che la pagina `about-us` userà le traduzioni della pagina `about` invece delle proprie. |
| `plural` | `PluralFunc` | ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)`` | Funzione di pluralizzazione personalizzata. Riceve `(key, count, params, locale, getter)` e deve restituire la forma plurale selezionata come stringa, oppure `null`/`undefined` per ricadere sulla logica integrata `defaultPlural` (così puoi sovrascrivere solo alcuni locale). Per il modulo Nuxt la funzione viene serializzata con `.toString()` in `.nuxt/i18n.plural.mjs` — deve essere autonoma (nessun import / scope esterno). Un percorso di file come stringa **non** è supportato. |
| `disablePageLocales` | `boolean` | `false` | Disattiva i file di traduzione per pagina. Quando è `true`, vengono caricate solo le traduzioni globali (`{locale}.json`); i file specifici per pagina (`pages/{page}/{locale}.json`) non vengono generati né caricati. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Codice del locale di fallback globale. Le chiavi mancanti in un locale vengono prese da questo locale (unite in ogni payload quando viene generato o caricato); senza di esso una chiave mancante viene visualizzata come la chiave stessa. |

## Payload e caching {#payloads-and-caching}

Come le traduzioni arrivano al browser. [Prestazioni](/it/guide/performance) spiega cosa cambiano queste opzioni a runtime.

| Opzione | Tipo | Predefinito | Descrizione |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Precarica le traduzioni della pagina index nel middleware globale di Nitro (solo server, configurazione privata). |
| `apiBaseUrl` | `string` | `'_locales'` | Segmento di percorso dell'URL base per la route API delle traduzioni (usato nel recupero dati SSR/SSG). Può essere impostato anche tramite la variabile d'ambiente `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Sovrascrive l'host usato per le richieste di traduzione lato client. Utile quando il client raggiunge il server tramite un hostname diverso da quello visto da Nuxt. Può essere impostato anche tramite la variabile d'ambiente `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Sovrascrive l'host usato per le richieste di traduzione lato server. Utile in configurazioni con container/microservizi in cui il server raggiunge se stesso tramite un hostname interno. Può essere impostato anche tramite la variabile d'ambiente `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Controlla come vengono emessi i payload di traduzione (server Node: `public/<apiBaseUrl>`; Edge / function / inline: `serverAssets` di Nitro). - **Server Node** (`node-server`, `node-cluster`, `serveStatic` su disco): `serverAssets` significa SSR locale tramite `readFile` sotto `public/` (nessun `raw:` di Rollup). - **Edge, preset function e `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …): `serverAssets` registra i `serverAssets` di Nitro (`assets:i18n`),   perché `public/` non è disponibile su disco per l'SSR. Non forza una copia pubblica — imposta `publicAssets: true` per CDN/statico. Mantieni i valori predefiniti per la consueta configurazione tutto-in-uno. Per cataloghi Edge grandi preferisci `mode: 'source'`. Per deployment basati su CDN, disattiva gli output locali e imposta `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Strategia dei payload di traduzione. - `premerged`: matrice `{page}/{locale}/data.json` generata in fase di build (predefinita) - `source`: file sorgente compatti uniti a runtime (preferibile su Edge / cataloghi grandi) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Payload SSR locali: un server Node che serve `public/` dal disco legge quell'albero (forza la copia pubblica); Edge, preset function e `serveStatic: "inline"` incorporano tramite i `serverAssets` di Nitro. - **Server Node** (il preset serve `public/` da sé, ad es. `node-server`): nessun `serverAssets` di Nitro (evita il `raw:` di Rollup). L'SSR legge   `public/<apiBaseUrl\|publicDir>` come `{page}/{locale}/data.json`; quando questa opzione è `true`,   viene forzata una copia pubblica anche se `publicAssets` è false. - **Edge, preset function e inline** (`nitro.node === false`, nessun `serveStatic` su disco come `vercel` /   `netlify` / `aws-lambda`, oppure `serveStatic: "inline"` ad es. winterjs): `serverAssets` di Nitro (`assets:i18n`)   con lo stesso layout di `mode`. **Non** forza una copia pubblica — imposta `publicAssets: true` per CDN/statico. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Registra la route server integrata in `/{apiBaseUrl}/:page/:locale/data.json`. Disattivala quando i payload di traduzione sono serviti da un host/CDN esterno. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Copia i payload nell'output pubblico di Nitro. Premerged → `{page}/{locale}/data.json` sotto `apiBaseUrl`; source → albero compatto. Quando l'SSR legge `public/` (`node-server` e simili), anche `serverAssets: true` forza questa copia. Sui preset Edge / function / `serveStatic: "inline"`, copia solo quando questa opzione è `true` (l'SSR usa l'embed di Nitro). |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Abilita il prerender Nitro di `/{apiBaseUrl}/.../data.json`. Di solito superfluo quando `publicAssets` premerged ha già scritto quei file. |
| `translationPayloads.publicDir` | `string` | — | Cartella di output pubblica relativa alla radice pubblica di Nitro. Il valore predefinito è `apiBaseUrl` (`_locales`). Così i file statici corrispondono agli URL richiesti dal client (`/{apiBaseUrl}/{page}/{locale}/data.json`). |
| `translationPayloads.rootDelta` | `boolean` | `true` | Scrive un file radice per locale e, in ogni file di pagina, solo ciò che ne differisce. Il client e l'SSR li uniscono; un chunk intero funziona comunque ovunque venga letto un file. `false` mantiene un dizionario intero in ogni file di pagina. Solo `premerged`, e disattivato con `disablePageLocales`. |
| `translationPayloads.warnFileCount` | `number` | `500` | Mostra un avviso durante la build quando il numero di file di payload generati supera questa soglia. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Mostra un avviso durante la build quando la dimensione totale dei payload generati supera questa soglia in byte. |

## SEO {#seo}

Meta tag generati per ogni pagina localizzata.

| Opzione | Tipo | Predefinito | Descrizione |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Genera automaticamente i meta tag SEO (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | URL base per i meta tag SEO (canonical, og:url, hreflang). - Una stringa URL concreta (ad es. `'https://example.com'`) — usata così com'è (priorità massima). - `undefined` — ricade su `site.url` di `nuxt-site-config` quando quel modulo è   presente, altrimenti sull'origine della richiesta corrente   (`useRequestURL().origin` sul server, `window.location.origin` sul client). |
| `metaTrustForwardedHost` | `boolean` | `true` | Considera attendibile l'header `X-Forwarded-Host` nel determinare l'URL base per i meta tag. Abilitalo quando l'app gira dietro un reverse proxy (nginx, Cloudflare, AWS ALB, ecc.) che imposta questo header sul vero hostname esposto ai client. |
| `metaTrustForwardedProto` | `boolean` | `true` | Considera attendibile l'header `X-Forwarded-Proto` nel determinare il protocollo per i meta tag. Abilitalo quando l'app gira dietro un proxy che termina TLS, così gli URL canonical usano `https://` anche se l'app stessa è in ascolto su HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Elenco dei nomi dei parametri di query mantenuti nei meta tag canonical e `og:url`. I parametri non presenti in questo elenco vengono rimossi dall'URL canonical. |

## Rilevamento e reindirizzamenti {#detection-and-redirects}

Scegliere un locale per un visitatore che non ne ha selezionato uno.

| Opzione | Tipo | Predefinito | Descrizione |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Abilita i reindirizzamenti automatici di locale (plugin server e middleware di route client). Quando è `true`, le strategie con prefisso reindirizzano un URL senza prefisso alla sua forma localizzata. Il locale proviene dallo stato dell'app, dal cookie o da `Accept-Language` dove `autoDetectPath` lo consente, altrimenti è quello predefinito. Con `no_prefix` il rilevamento non cambia mai l'URL (vedi `noPrefixRedirect` per i percorsi personalizzati). |
| `autoDetectLanguage` | `boolean` | `true` | Rileva automaticamente la lingua preferita dell'utente dall'header HTTP `Accept-Language`. Usato insieme ad `autoDetectPath` per decidere quando avviene il rilevamento. |
| `autoDetectPath` | `string` | `'/'` | Dove possono avvenire i reindirizzamenti in base alla preferenza da cookie / Accept-Language (quando `redirects` è abilitato). - `'/'` — solo `/` (i deep link nel locale predefinito restano raggiungibili; predefinito) - `'no_prefix'` — solo i percorsi senza prefisso di locale - `'*'` — ogni percorso, inclusa la riscrittura di un prefisso di locale esplicito   (ad es. `/fr/about` → `/de/about` quando il cookie preferisce `de`) - qualsiasi altra stringa — quel percorso, ignorando gli slash finali (ad es. `'/welcome'`) Con `prefix`, un URL senza prefisso al di fuori dei percorsi consentiti reindirizza comunque alla forma del locale predefinito (`/about` → `/en/about`). Il locale predefinito con un prefisso sotto `prefix_except_default` (`/en`) è un 404, non un reindirizzamento. |

I payload copiati in `public/` e serviti   dalla piattaforma di hosting ricevono gli header di quella piattaforma — vedi la guida Prestazioni. Analogo a `httpCacheDuration` sperimentale di `@nuxtjs/i18n` (v10.2.0), ma come header di risposta esplicito invece del maxAge di `defineCachedEventHandler` di Nitro. |

Su un server Node una risposta al `?v=` corrente viene fissata per `httpCacheDuration` e qualsiasi altra viene riconvalidata; con `source`, `cacheTtl` o `apiBaseServerHost`, dove un dizionario cambia senza una build, ogni risposta riceve questo header. `false` mantiene ogni file su `max-age=0, must-revalidate`. |
| `dateBuild` | `string \| number` | — | Valore usato per il cache-busting delle richieste di traduzione (`?v=...`). Se non specificato, il modulo usa un hash dei file di traduzione, quindi il valore cambia solo quando cambiano le traduzioni (`Date.now()` quando non è possibile calcolare un hash). `0` o `''` disattiva il cache-busting. Imposta un valore stabile (uno SHA git, un numero di build) per fissarlo tu stesso. `NUXT_I18N_DATE_BUILD` o `runtimeConfig.public.i18nRuntime.dateBuild` lo sostituisce a runtime, dopo che un dizionario è stato sostituito sul posto: gli URL fissati vengono lasciati indietro, senza rebuild. |
| `experimental` | `Record<string, unknown>` | — | Contenitore per opzioni sperimentali/instabili. Il contenuto può cambiare o essere rimosso senza preavviso tra versioni minori. |

## Dettagli delle opzioni {#option-details}

Le opzioni che non hanno nulla da aggiungere oltre alla tabella non vengono ripetute qui.

### Locale e URL {#locales-and-urls}

#### `locales` {#locales}

**Tipo** `Locale[]` · **Predefinito** `[]`

Elenco dei locale supportati.
Ogni voce definisce un codice di locale più metadati opzionali (ISO, direzione, nome visualizzato, ecc.).

Ogni voce è un oggetto `Locale`:

| Proprietà | Tipo | Descrizione |
| --- | --- | --- |
| `code` | `string` | **Obbligatoria.** Segmento dell'URL e nome del file (`en`, `de-at`). |
| `iso` | `string` | Tag BCP-47 per `<html lang>`, `hreflang`, plurali e `$tn` / `$td` / `$tdr` (`en-US`). |
| `displayName` | `string` | Etichetta in `<i18n-switcher>` e `$getLocaleName()`. |
| `dir` | `'ltr' \| 'rtl' \| 'auto'` | `<html dir>`. Senza di essa, le lingue RTL note ricevono `rtl` e ogni altro locale non riceve alcun attributo. Vedi [SEO](/it/guide/seo#text-direction). |
| `disabled` | `boolean` | Escluso da route, payload e cambio di locale. Il suo prefisso è un 404 e i link verso di esso restano sulla pagina. |
| `fallbackLocale` | `string` | Fallback per questo locale; sovrascrive il `fallbackLocale` globale. |
| `seo` | `boolean` | `false` esclude il locale da `hreflang` e `og:locale:alternate`. |
| `og` | `string` | Valore di `og:locale` (`ar_AE`); predefinito: `iso` convertito. |
| `baseUrl` | `string` | Il dominio proprio del locale: una sola build lo serve, e i link verso di esso da altri domini sono assoluti. |
| `baseDefault` | `boolean` | Con `baseUrl`: il locale predefinito del suo host, senza prefisso `/<code>` nei link verso di esso (`prefix` lo mantiene). |

Le altre proprietà vengono conservate e restituite da `$getLocales()`. Tipizzale estendendo `Locale`:

```ts
// i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
  }
}
export {}
```

Il modulo effettua l'hoisting di `@i18n-micro/types`, quindi questo funziona con pnpm senza installare il pacchetto.

#### `defaultLocale` {#defaultlocale}

**Tipo** `string` · **Predefinito** `'en'`

Il locale da usare quando non è possibile determinarne uno dall'URL o dalle preferenze dell'utente.
Non è un fallback di traduzione: per quello imposta `fallbackLocale`.

#### `strategy` {#strategy}

**Tipo** `Strategies` · **Predefinito** `'prefix_except_default'`

Strategia di routing degli URL per i prefissi di locale.

- `'no_prefix'` — nessun locale nell'URL; il locale è salvato in un cookie.
- `'prefix_except_default'` — prefisso per tutti i locale tranne quello predefinito.
- `'prefix'` — prefisso sempre, incluso il locale predefinito.
- `'prefix_and_default'` — come `prefix`, ma il locale predefinito è accessibile anche senza prefisso.

URL per strategia e reindirizzamenti: [Strategie di routing](/it/guide/strategy).

#### `globalLocaleRoutes` {#globallocaleroutes}

**Tipo** `GlobalLocaleRoutes` · **Predefinito** `{}`

Configurazione globale dei locale a livello di route.
Permette di limitare o personalizzare le route localizzate di pagine specifiche senza
modificarne i componenti.

- `false` — esclude la route dalla localizzazione.
- `Record<LocaleCode, string>` — percorsi personalizzati per locale.

Le chiavi sono nomi o percorsi di route. Di solito si imposta per pagina con [`$defineI18nRoute`](/it/guide/per-component-translations).

```ts
globalLocaleRoutes: {
  about: { en: '/about-us', de: '/ueber-uns' },
  'admin-dashboard': false, // not localized
}
```

Dettagli, segmenti dinamici e route di `pages:extend`: [Percorsi localizzati](/it/guide/custom-locale-routes).

#### `routeLocales` {#routelocales}

**Tipo** `Record<string, string[]>` · **Predefinito** —

Restrizioni di locale per route, estratte in fase di build dalle chiamate a `$defineI18nRoute()`.
Associa un percorso di route (ad es. `'/about'`) a un array di codici di locale consentiti.
Le route non elencate non hanno restrizioni (tutti i locale consentiti).

#### `routeDisableMeta` {#routedisablemeta}

**Tipo** `Record<string, boolean \| string[]>` · **Predefinito** —

Disattivazione dei meta tag per route. Associa un nome o un percorso di route a `true` (disattiva tutti i meta) o a un array
di codici di locale per cui i meta devono essere disattivati. Le voci trovate nelle chiamate a `$defineI18nRoute()`
in fase di build vengono aggiunte qui.

#### `customRegexMatcher` {#customregexmatcher}

**Tipo** `string \| RegExp` · **Predefinito** `undefined (uses built-in pattern based on locale codes)`

Espressione regolare personalizzata (o la sua stringa sorgente) per riconoscere i codici di locale nei segmenti dell'URL.
Ogni codice di locale in `locales` deve corrispondere all'intero pattern, senza i suoi flag, altrimenti la build fallisce.

```ts
customRegexMatcher: '[a-z]{2}-[a-z]{2}', // en-us, de-at
```

#### `excludePatterns` {#excludepatterns}

**Tipo** `(string \| RegExp)[]` · **Predefinito** `undefined`

Percorsi da escludere dal routing i18n: una stringa è un prefisso di percorso (`/admin` copre `/admin/x`)
o un glob `*` / `?`; una RegExp viene testata sul percorso. Le pagine corrispondenti non hanno varianti
di locale, né reindirizzamento di locale o 404, e vengono escluse dal prerender; vengono comunque renderizzate con
le traduzioni. `/api`, `/_nuxt`, `/__*`, la route delle traduzioni e i comuni file statici
(sitemap, robots.txt, favicon, asset per estensione) sono sempre esclusi.

```ts
excludePatterns: ['/admin', '/docs/*', /^\/preview\//],
```

Altro: [Escludere percorsi](/it/guide/excluding-static-files).

#### `localizedRouteNamePrefix` {#localizedroutenameprefix}

**Tipo** `string` · **Predefinito** `'localized-'`

Prefisso anteposto ai nomi delle route localizzate (ad es. `'localized-index'`).
Usato internamente per distinguere le route originali dalle varianti di locale generate.

#### `trailingSlash` {#trailingslash}

**Tipo** `'append' \| 'remove'` · **Predefinito** `undefined (inherit from Nuxt)`

Slash finale per `$localePath` / `$switchLocalePath` (parità con NuxtLink).
Se non impostato, il valore predefinito è `experimental.defaults.nuxtLink.trailingSlash`.
Impostalo esplicitamente per sovrascrivere il valore predefinito dei link di Nuxt per gli helper di percorso i18n.

### Traduzioni {#translations}

#### `translationDir` {#translationdir}

**Tipo** `string` · **Predefinito** `'locales'`

Percorso della directory che contiene i file JSON di traduzione, relativo alla radice del progetto.

Relativo alla radice di ogni layer, non ad `app/` (`'app/locales'` per un layout Nuxt 4). Struttura dei file: [File di traduzione](/it/guide/translations).

#### `additionalTranslationDirs` {#additionaltranslationdirs}

**Tipo** `string[]` · **Predefinito** `[]`

Directory aggiuntive (relative alla radice del progetto / alla radice di ogni layer Nuxt) i cui file
`{locale}.json` di primo livello vengono uniti in profondità nel dizionario globale prima di `translationDir`.

Ordine di unione: ogni voce nell'ordine dell'array (tra i layer), poi `translationDir` (che prevale in caso di conflitti).
Vengono letti solo i file `{locale}.json` radice — `pages/` sotto queste directory viene ignorata.

Esempio: `translationDir: 'frontend'`, `additionalTranslationDirs: ['common']` → `common/en.json` poi `frontend/en.json`.

#### `disablePageLocales` {#disablepagelocales}

**Tipo** `boolean` · **Predefinito** `false`

Disattiva i file di traduzione per pagina.
Quando è `true`, vengono caricate solo le traduzioni globali (`{locale}.json`);
i file specifici per pagina (`pages/{page}/{locale}.json`) non vengono generati né caricati.

#### `fallbackLocale` {#fallbacklocale}

**Tipo** `string` · **Predefinito** `undefined (no fallback; returns the raw key)`

Codice del locale di fallback globale.
Le chiavi mancanti in un locale vengono prese da questo locale (unite in ogni payload quando viene
generato o caricato); senza di esso una chiave mancante viene visualizzata come la chiave stessa.

#### `routesLocaleLinks` {#routeslocalelinks}

**Tipo** `{ [key: string]: string }` · **Predefinito** `{}`

Associa nomi di route ad altri nomi di route per condividere gli stessi file di traduzione.
Ad esempio, `{ 'about-us': 'about' }` significa che la pagina `about-us` userà
le traduzioni della pagina `about` invece delle proprie.

```ts
routesLocaleLinks: { 'products-id': 'products' },
```

#### `plural` {#plural}

**Tipo** `PluralFunc` · **Predefinito** ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)``

Funzione di pluralizzazione personalizzata.
Riceve `(key, count, params, locale, getter)` e deve restituire la forma
plurale selezionata come stringa, oppure `null`/`undefined` per ricadere sulla logica
integrata `defaultPlural` (così puoi sovrascrivere solo alcuni locale).

Per il modulo Nuxt la funzione viene serializzata con `.toString()` in
`.nuxt/i18n.plural.mjs` — deve essere autonoma (nessun import / scope esterno).
Un percorso di file come stringa **non** è supportato.

La regola integrata e il suo marcatore `=0 ` sono descritti in [`$tc`](/it/api/methods#$tc). La tua funzione la sostituisce per ciò a cui risponde, riceve il valore grezzo con eventuali marcatori al loro posto, e `null` le restituisce la chiamata. La funzione riceve `(key, count, params, locale, getter)`; `getter(key)` restituisce la stringa grezza con tutte le forme. Scrivila come `function` autonoma o come arrow function (niente sintassi abbreviata dei metodi, niente import, niente variabili esterne):

```ts
plural: function (key, count, params, locale, getter) {
  if (!locale.startsWith('en')) return null // built-in rule for other locales
  const forms = String(getter(key) ?? '').split('|').map((form) => form.trim())
  const index = count === 0 ? 0 : count === 1 ? 1 : 2
  return (forms[Math.min(index, forms.length - 1)] ?? '').replace('{count}', String(count))
},
```

```json
{ "apples": "no apples | one apple | {count} apples" }
```

**Tipo** `Record<string, Record<string, Intl.NumberFormatOptions>>` · **Predefinito** —

Formati numerici con nome per locale (compatibili con Vue I18n).
Abilita chiamate come `$tn(1000, 'currency')`.

Usato da [`$tn`](/it/api/methods#$tn).

#### `datetimeFormats` {#datetimeformats}

**Tipo** `Record<string, Record<string, Intl.DateTimeFormatOptions>>` · **Predefinito** —

Abilita chiamate come `$td(date, 'short')`.

Usato da [`$td`](/it/api/methods#$td).

#### `timeZone` {#timezone}

**Tipo** `string` · **Predefinito** `the runtime's zone`

Fuso orario IANA per `$td` e `<i18n-t date>` (`Europe/Berlin`). Impostalo per visualizzare la stessa data sul
server e in ogni browser; il `timeZone` di un formato con nome ha la precedenza.

#### `disableWatcher` {#disablewatcher}

**Tipo** `boolean` · **Predefinito** `false`

Disattiva il file watcher che crea automaticamente i file di traduzione mancanti in modalità sviluppo.

#### `missingWarn` {#missingwarn}

### Payload e caching {#payloads-and-caching}

#### `translationPayloads` {#translationpayloads}

**Tipo** `TranslationPayloadOptions` · **Predefinito** —

Controlla come vengono emessi i payload di traduzione (server Node: `public/<apiBaseUrl>`; Edge / function / inline: `serverAssets` di Nitro).

- **Server Node** (`node-server`, `node-cluster`, `serveStatic` su disco): `serverAssets` significa SSR locale tramite `readFile` sotto `public/` (nessun `raw:` di Rollup).
- **Edge, preset function e `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …): `serverAssets` registra i `serverAssets` di Nitro (`assets:i18n`),
  perché `public/` non è disponibile su disco per l'SSR. Non forza una copia pubblica — imposta `publicAssets: true` per CDN/statico.

Mantieni i valori predefiniti per la consueta configurazione tutto-in-uno. Per cataloghi Edge grandi preferisci `mode: 'source'`.
Per deployment basati su CDN, disattiva gli output locali e imposta `apiBaseClientHost` / `apiBaseServerHost`.

Le sotto-opzioni sono nella tabella [Payload e caching](#payloads-and-caching). Quale combinazione si adatta a Node, serverless, Edge, hosting statico o CDN: [Deployment](/it/guide/deployment).

#### `apiBaseUrl` {#apibaseurl}

**Tipo** `string` · **Predefinito** `'_locales'`

Segmento di percorso dell'URL base per la route API delle traduzioni (usato nel recupero dati SSR/SSG).
Può essere impostato anche tramite la variabile d'ambiente `NUXT_I18N_APP_BASE_URL`.

Gli URL dei payload sono `/{apiBaseUrl}/{page}/{locale}/data.json`.

#### `apiBaseClientHost` {#apibaseclienthost}

**Tipo** `string` · **Predefinito** `undefined`

Sovrascrive l'host usato per le richieste di traduzione lato client.
Utile quando il client raggiunge il server tramite un hostname diverso da quello visto da Nuxt.
Può essere impostato anche tramite la variabile d'ambiente `NUXT_I18N_APP_BASE_CLIENT_HOST`.

#### `apiBaseServerHost` {#apibaseserverhost}

**Tipo** `string` · **Predefinito** `undefined`

Sovrascrive l'host usato per le richieste di traduzione lato server.
Utile in configurazioni con container/microservizi in cui il server raggiunge se stesso tramite un hostname interno.
Può essere impostato anche tramite la variabile d'ambiente `NUXT_I18N_APP_BASE_SERVER_HOST`.

Un host deve servire le stesse risposte `/{apiBaseUrl}/{page}/{locale}/data.json` della route integrata.

#### `dateBuild` {#datebuild}

**Tipo** `string \| number` · **Predefinito** —

Valore usato per il cache-busting delle richieste di traduzione (`?v=...`).

Se non specificato, il modulo usa un hash dei file di traduzione, quindi il valore cambia
solo quando cambiano le traduzioni (`Date.now()` quando non è possibile calcolare un hash). `0` o `''` disattiva
il cache-busting. Imposta un valore stabile (uno SHA git, un numero di build) per fissarlo tu stesso.
`NUXT_I18N_DATE_BUILD` o `runtimeConfig.public.i18nRuntime.dateBuild` lo sostituisce a runtime, dopo che un dizionario
è stato sostituito sul posto: gli URL fissati vengono lasciati indietro, senza rebuild.

#### `httpCacheDuration` {#httpcacheduration}

**Tipo** `number` · **Predefinito** `31536000`

max-age (in secondi) di `Cache-Control` HTTP per `/{apiBaseUrl}/:page/:locale/data.json`.

Si applica pienamente solo mentre `dateBuild` rende unico l'URL (`?v=...`), che è il comportamento predefinito:
la risposta è allora `private, max-age=…, immutable`: un browser la fissa, mentre una CDN che ignora la query non può farlo
(`public` con `httpCacheControl: false`).

- `dateBuild: 0`/`''` — l'URL è stabile, quindi questa durata *non* viene rispettata; la
  risposta diventa invece `public, max-age=0, must-revalidate`. Un `max-age` lungo su un
  URL invariato fissa il primo payload che un browser abbia mai visto.

- `0` — non impostare affatto `Cache-Control` (utile nel debug locale)
- Non applicato in sviluppo (`import.meta.dev`), così l'HMR non viene ostacolato dalla cache del browser
- Riguarda solo le risposte servite tramite Nitro. I payload copiati in `public/` e serviti
  dalla piattaforma di hosting ricevono gli header di quella piattaforma — vedi la guida Prestazioni.

Analogo a `httpCacheDuration` sperimentale di `@nuxtjs/i18n` (v10.2.0), ma come
header di risposta esplicito invece del maxAge di `defineCachedEventHandler` di Nitro.

#### `cacheMaxSize` {#cachemaxsize}

**Tipo** `number` · **Predefinito** `0`

Numero massimo di voci nelle cache di traduzione in memoria. Le cache di fetch e del server
eliminano la voce usata meno di recente; la mappa dei dizionari del browser elimina la più vecchia (FIFO).
`0` significa nessun limite nel browser; in quel caso le cache del server mantengono al massimo 1000 voci, così gli
URL di richiesta con pagine inventate non possono far crescere la memoria del server.

#### `cacheTtl` {#cachettl}

**Tipo** `number` · **Predefinito** `0`

Durata (in secondi) delle cache di traduzione di fetch e del server, contata dal momento in cui una
voce è stata salvata (le letture non la estendono), così i dati da `apiBaseServerHost` vengono aggiornati
almeno con quella frequenza. I dizionari attivi del browser non scadono per effetto di questa opzione. `0` significa che le voci
non scadono mai.

Cosa cambiano entrambe a runtime: [Prestazioni](/it/guide/performance).

#### `serverTranslationPreload` {#servertranslationpreload}

**Tipo** `boolean` · **Predefinito** `false`

Precarica le traduzioni della pagina index nel middleware globale di Nitro (solo server, configurazione privata).

### SEO {#seo}

#### `meta` {#meta}

**Tipo** `boolean` · **Predefinito** `true`

Genera automaticamente i meta tag SEO (`hreflang`, `canonical`, `og:url`, `og:locale`).

Override per pagina: [`useI18nHead`](/it/composables/useI18nHead). Tutto il resto: [SEO](/it/guide/seo).

#### `metaBaseUrl` {#metabaseurl}

**Tipo** `string` · **Predefinito** `undefined`

URL base per i meta tag SEO (canonical, og:url, hreflang).

- Una stringa URL concreta (ad es. `'https://example.com'`) — usata così com'è (priorità massima).
- `undefined` — ricade su `site.url` di `nuxt-site-config` quando quel modulo è
  presente, altrimenti sull'origine della richiesta corrente
  (`useRequestURL().origin` sul server, `window.location.origin` sul client).

#### `metaTrustForwardedHost` {#metatrustforwardedhost}

**Tipo** `boolean` · **Predefinito** `true`

Considera attendibile l'header `X-Forwarded-Host` nel determinare l'URL base per i meta tag.
Abilitalo quando l'app gira dietro un reverse proxy (nginx, Cloudflare, AWS ALB, ecc.)
che imposta questo header sul vero hostname esposto ai client.

Letto solo quando né `metaBaseUrl` né `site.url` sono impostati. Impostalo a `false` quando l'app è raggiungibile senza un proxy che sovrascrive l'header: altrimenti un client potrebbe scegliere l'host nei tuoi URL canonical.

#### `metaTrustForwardedProto` {#metatrustforwardedproto}

**Tipo** `boolean` · **Predefinito** `true`

Considera attendibile l'header `X-Forwarded-Proto` nel determinare il protocollo per i meta tag.
Abilitalo quando l'app gira dietro un proxy che termina TLS, così
gli URL canonical usano `https://` anche se l'app stessa è in ascolto su HTTP.

Stesso ambito di `metaTrustForwardedHost`.

#### `trustForwardedHost` {#trustforwardedhost}

**Tipo** `boolean` · **Predefinito** `false`

Sceglie il dominio di una richiesta (`locales[].baseUrl`) da `X-Forwarded-Host` invece che da
`Host`. Abilitalo solo dietro un proxy che sovrascrive quell'header.

Separato da `metaTrustForwardedHost` e disattivato per impostazione predefinita: qui l'header selezionerebbe i locale di un altro dominio, non solo l'origine di un tag. Vedi [Layer e domini](/it/guide/layers#multiple-domains).

#### `hreflangBaseLanguage` {#hreflangbaselanguage}

**Tipo** `boolean` · **Predefinito** `false`

Emette anche un `hreflang` con la sola lingua derivato dall'`iso` di ogni locale
(ad es. `es-ES` → anche `es`). Il primo locale regionale in `locales` si aggiudica
il tag della sola lingua per quella lingua. Il `code` di routing non viene mai usato — solo `iso || code`.

#### `canonicalQueryWhitelist` {#canonicalquerywhitelist}

**Tipo** `string[]` · **Predefinito** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

Elenco dei nomi dei parametri di query mantenuti nei meta tag canonical e `og:url`.
I parametri non presenti in questo elenco vengono rimossi dall'URL canonical.

### Rilevamento e reindirizzamenti {#detection-and-redirects}

Le regole che queste opzioni alimentano: [Rilevamento del locale](/it/guide/locale-detection).

#### `redirects` {#redirects}

**Tipo** `boolean` · **Predefinito** `true`

Abilita i reindirizzamenti automatici di locale (plugin server e middleware di route client).
Quando è `true`, le strategie con prefisso reindirizzano un URL senza prefisso alla sua forma localizzata. Il locale
proviene dallo stato dell'app, dal cookie o da `Accept-Language` dove `autoDetectPath` lo consente, altrimenti
è quello predefinito. Con `no_prefix` il rilevamento non cambia mai l'URL (vedi `noPrefixRedirect` per i percorsi personalizzati).

Con `false` il middleware di reindirizzamento client non viene registrato. Il plugin server restituisce comunque 404 per gli URL con locale non validi e scrive il cookie per un URL con prefisso.

#### `autoDetectLanguage` {#autodetectlanguage}

**Tipo** `boolean` · **Predefinito** `true`

Rileva automaticamente la lingua preferita dell'utente dall'header HTTP `Accept-Language`.
Usato insieme ad `autoDetectPath` per decidere quando avviene il rilevamento.

#### `autoDetectPath` {#autodetectpath}

**Tipo** `string` · **Predefinito** `'/'`

Dove possono avvenire i reindirizzamenti in base alla preferenza da cookie / Accept-Language (quando `redirects` è abilitato).

- `'/'` — solo `/` (i deep link nel locale predefinito restano raggiungibili; predefinito)
- `'no_prefix'` — solo i percorsi senza prefisso di locale
- `'*'` — ogni percorso, inclusa la riscrittura di un prefisso di locale esplicito
  (ad es. `/fr/about` → `/de/about` quando il cookie preferisce `de`)

- qualsiasi altra stringa — quel percorso, ignorando gli slash finali (ad es. `'/welcome'`)

Con `prefix`, un URL senza prefisso al di fuori dei percorsi consentiti reindirizza comunque alla forma del
locale predefinito (`/about` → `/en/about`). Il locale predefinito con un prefisso sotto
`prefix_except_default` (`/en`) è un 404, non un reindirizzamento.

#### `localeCookie` {#localecookie}

**Tipo** `string \| null` · **Predefinito** `null`

Nome del cookie per mantenere la preferenza di locale dell'utente tra le sessioni.
Imposta `null` per disattivare la persistenza tramite cookie.
Viene impostato automaticamente a `'user-locale'` per la strategia `no_prefix` se non specificato; un
`null` esplicito nel blocco di configurazione `i18n` lo mantiene disattivato anche lì.

Senza un cookie, `Accept-Language` guida comunque i reindirizzamenti; il cookie ricorda una scelta tra le visite.

#### `noPrefixRedirect` {#noprefixredirect}

**Tipo** `boolean` · **Predefinito** `false`

Per la strategia `no_prefix`: quando il locale predefinito ha un percorso personalizzato per una pagina
(`localeRoutes` / `globalLocaleRoutes`), reindirizza il percorso originale della pagina al percorso
personalizzato del locale del visitatore, altrimenti a quello del locale predefinito (ad es. `/about` → `/about-us`).
Un locale senza un proprio percorso personalizzato resta sul percorso originale. Le pagine con segmenti
dinamici non vengono reindirizzate.

Genera le dichiarazioni di tipo TypeScript per `useI18n`, `$t` e gli helper correlati
in base alle chiavi di traduzione nei file del locale predefinito.

Separato dal pacchetto [`@i18n-micro/types-generator`](/it/integrations/types-generator).

#### `hmr` {#hmr}

**Tipo** `boolean` · **Predefinito** `true`

Abilita l'Hot Module Replacement per i file di traduzione in sviluppo.
Quando è `true`, le modifiche ai file JSON di traduzione attivano un ricaricamento automatico
senza un refresh completo della pagina.

#### `debug` {#debug}

**Tipo** `boolean` · **Predefinito** `false`

Abilita il logging di debug dettagliato per il rilevamento del locale, la generazione delle route e il caricamento delle traduzioni.

#### `vueDevtools` {#vuedevtools}

**Tipo** `boolean` · **Predefinito** `true`

Registra l'inspector e la timeline di Vue DevTools in sviluppo (estensione del browser).
Separato dalla scheda personalizzata di Nuxt DevTools.

#### `experimental` {#experimental}

**Tipo** `Record<string, unknown>` · **Predefinito** —

Contenitore per opzioni sperimentali/instabili.
Il contenuto può cambiare o essere rimosso senza preavviso tra versioni minori.
