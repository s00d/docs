# Riferimento delle opzioni del modulo

Ogni opzione accettata da `nuxt-i18n-micro`, letta in fase di build dall'interfaccia `ModuleOptions`
in
[`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).
Nulla qui è scritto a mano, quindi non può rimanere indietro rispetto al codice. Tipi, valori predefiniti e
descrizioni provengono dalla dichiarazione stessa.

Per il *significato* di queste opzioni insieme (quali combinazioni hanno senso, cosa cambia quando
cambi strategia, esempi lavorati), leggi [Configurazione](/guides/configuration). Questa
pagina è l'elenco esaustivo; quella è la spiegazione.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Le opzioni annidate appaiono sotto il loro percorso puntato, quindi `translationPayloads.mode` è la
chiave `mode` all'interno dell'oggetto `translationPayloads`.

## Locale e routing

Quali lingue esistono e come appaiono nell'URL.

| Opzione | Tipo | Predefinito | Descrizione |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Lista delle locale supportate. Ogni voce definisce un codice locale più metadati opzionali (ISO, direzione, nome visualizzato, ecc.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Strategia di routing URL per i prefissi di locale. - `'no_prefix'` — nessun prefisso di locale nell'URL; locale memorizzata in un cookie. - `'prefix_except_default'` — prefisso su tutte le locale tranne quella predefinita. - `'prefix'` — sempre prefisso, inclusa la locale predefinita. - `'prefix_and_default'` — come `prefix`, ma la locale predefinita è accessibile anche senza prefisso. |
| `defaultLocale` | `string` | `'en'` | La locale da utilizzare quando non è possibile determinare la locale da URL o preferenze utente. Utilizzata anche come locale di fallback per le traduzioni mancanti quando `fallbackLocale` non è impostato. |
| `localeCookie` | `string \| null` | `null` | Nome del cookie per persistere la preferenza di locale dell'utente tra le sessioni. Imposta `null` per disabilitare la persistenza basata su cookie. Impostato automaticamente a `'user-locale'` per la strategia `no_prefix` se non fornito. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Configurazione locale globale a livello di route. Consente di limitare o personalizzare le route locale per pagine specifiche senza modificarne i componenti. - `false` — esclude la route dalla localizzazione. - `Record<LocaleCode, string>` — percorsi personalizzati per locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Espressione regolare personalizzata (o la sua stringa sorgente) per matchare i codici locale nei segmenti URL. Tutti i codici locale definiti in `locales` devono corrispondere a questo pattern, altrimenti viene emesso un avviso. |
| `noPrefixRedirect` | `boolean` | `false` | Per la strategia `no_prefix`: abilita il redirect da un URL con prefisso di locale (ad esempio `/en/about`) alla versione senza prefisso (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Pattern URL (stringhe o RegExp) da escludere completamente dall'elaborazione i18n. Le route corrispondenti non riceveranno prefissi di locale, redirect o caricamento di traduzioni. I percorsi interni di Nuxt (`/__nuxt_error`, ecc.) sono sempre esclusi automaticamente. |
| `routeLocales` | `Record<string, string[]>` | — | Restrizioni di locale per route, estratte dalle chiamate `defineI18nRoute()`. Mappa un percorso di route (ad esempio `'/about'`) a un array di codici locale consentiti. Le route non elencate non hanno restrizioni (tutte le locale sono consentite). |

## Traduzioni

Dove risiedono i file di traduzione e come vengono risolte le chiavi.

| Opzione | Tipo | Predefinito | Descrizione |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Percorso della directory contenente i file JSON di traduzione, relativo alla root del progetto. |
| `disableWatcher` | `boolean` | `false` | Disabilita il file watcher che crea automaticamente file di traduzione mancanti in modalità sviluppo. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Mappa i nomi di route ad altri nomi di route per condividere gli stessi file di traduzione. Ad esempio, `\{ 'about-us': 'about' \}` significa che la pagina `about-us` userà le traduzioni della pagina `about` invece delle proprie. |
| `plural` | `PluralFunc` | `built-in pluralization (form index by count)` | Funzione di pluralizzazione personalizzata. Riceve `(key, count, params, locale, getter)` e deve restituire la forma plurale selezionata come stringa, oppure `null`/`undefined` per fare fallback sulla logica `defaultPlural` integrata (così puoi sovrascrivere solo alcune locale). Per il modulo Nuxt la funzione viene serializzata con `.toString()` in `.nuxt/i18n.plural.mjs`. Deve essere autonoma (nessun import / scope esterno). Una stringa di path di file **non** è supportata. |
| `disablePageLocales` | `boolean` | `false` | Disabilita i file di traduzione per pagina. Quando `true`, vengono caricate solo le traduzioni globali (`\{locale\}.json`); i file specifici per pagina (`pages/\{page\}/\{locale\}.json`) non vengono generati né caricati. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Codice locale di fallback globale. Quando una chiave di traduzione manca nella locale attiva, il modulo la cerca in questa locale prima di restituire la chiave stessa. |

## Payload e caching

Come le traduzioni raggiungono il browser. [Performance](/guides/performance) spiega cosa cambia a runtime.

| Opzione | Tipo | Predefinito | Descrizione |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Precarica le traduzioni della pagina index nel middleware globale Nitro (solo server, config privata). |
| `apiBaseUrl` | `string` | `'_locales'` | Segmento URL base per la route API delle traduzioni (usato nel fetch dei dati SSR/SSG). Può anche essere impostato tramite la variabile d'ambiente `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Sovrascrive l'host usato per le richieste di fetch delle traduzioni lato client. Utile quando il client raggiunge il server tramite un hostname diverso da quello visto da Nuxt. Può anche essere impostato tramite la variabile d'ambiente `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Sovrascrive l'host usato per le richieste di fetch delle traduzioni lato server. Utile in setup container/microservizi dove il server si raggiunge tramite un hostname interno. Può anche essere impostato tramite la variabile d'ambiente `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Controlla come vengono emessi i payload di traduzione (Node: `public/<apiBaseUrl>`; Edge: `serverAssets` Nitro). - **Node**: `serverAssets` significa SSR locale via `readFile` sotto `public/` (nessun Rollup `raw:`). - **Edge**: `serverAssets` registra i `serverAssets` Nitro (`assets:i18n`); non forza una copia pubblica. Mantieni i valori predefiniti per il setup all-in-one usuale. Per grandi cataloghi Edge preferisci `mode: 'source'`. Per deploy con CDN, disabilita gli output locali e imposta `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Strategia del payload di traduzione. - `premerged`: matrice `\{page\}/\{locale\}/data.json` in fase di build (predefinito) - `source`: file sorgente compatti uniti a runtime (preferito su Edge / grandi cataloghi) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Payload SSR locali: Node legge `public/<apiBaseUrl>` (forza la copia pubblica); Edge incorpora tramite `serverAssets` Nitro. - **Node**: nessun `serverAssets` Nitro (evita Rollup `raw:`). SSR legge   `public/<apiBaseUrl\|publicDir>` come `\{page\}/\{locale\}/data.json`; quando questo è `true`,   una copia pubblica viene forzata anche se `publicAssets` è false. - **Edge** (`nitro.node === false`): `serverAssets` Nitro (`assets:i18n`) con lo stesso   layout di `mode`. **Non** forza una copia pubblica. Imposta `publicAssets: true` per CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Registra la route server integrata su `/\{apiBaseUrl\}/:page/:locale/data.json`. Disabilitalo quando i payload di traduzione sono serviti da un host/CDN esterno. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Copia i payload nell'output pubblico di Nitro. Premerged → `\{page\}/\{locale\}/data.json` sotto `apiBaseUrl`; source → albero compatto. Su Node questo albero è anche la sorgente SSR quando `serverAssets` forza una copia pubblica. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Opt-in per prerender Nitro di `/\{apiBaseUrl\}/.../data.json`. Solitamente ridondante quando `publicAssets` in modalità premerged ha già scritto questi file. |
| `translationPayloads.publicDir` | `string` | — | Cartella di output pubblica relativa alla root pubblica di Nitro. Predefinito a `apiBaseUrl` (`_locales`). Così i file statici corrispondono agli URL di fetch client (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Emette un warning durante la build quando il conteggio dei file di payload generati supera questa soglia. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Emette un warning durante la build quando la dimensione totale dei payload generati supera questa soglia in byte. |

## SEO

Meta tag generati per ogni pagina localizzata.

| Opzione | Tipo | Predefinito | Descrizione |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Genera automaticamente i meta tag SEO (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | URL base per i meta tag SEO (canonical, og:url, hreflang). - Una stringa URL concreta (ad esempio `'https://example.com'`) — usata così com'è (priorità più alta). - `undefined` — ricade su `site.url` di `nuxt-site-config` quando quel modulo è   presente, altrimenti sull'origine della richiesta corrente   (`useRequestURL().origin` sul server, `window.location.origin` sul client). |
| `metaTrustForwardedHost` | `boolean` | `true` | Fidati dell'header `X-Forwarded-Host` quando risolvi l'URL base per i meta tag. Abilitalo quando l'app gira dietro un reverse proxy (nginx, Cloudflare, AWS ALB, ecc.) che imposta questo header sull'hostname reale rivolto al client. |
| `metaTrustForwardedProto` | `boolean` | `true` | Fidati dell'header `X-Forwarded-Proto` quando risolvi il protocollo per i meta tag. Abilitalo quando l'app gira dietro un proxy che termina TLS, così gli URL canonici usano `https://` anche se l'app stessa ascolta su HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Lista di nomi di parametri di query preservati nei meta tag canonical e `og:url`. I parametri non in questa lista vengono rimossi dall'URL canonico. |

## Rilevamento e redirect

Scelta di una locale per un visitatore che non ne ha selezionata una.

| Opzione | Tipo | Predefinito | Descrizione |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Abilita i redirect automatici basati sulla locale. Quando `true`, i visitatori vengono reindirizzati alla loro locale preferita (rilevata da cookie, header `Accept-Language` o dal predefinito) alla prima visita. |
| `autoDetectLanguage` | `boolean` | `true` | Rileva automaticamente la lingua preferita dell'utente dall'header HTTP `Accept-Language`. Utilizzato in combinazione con `autoDetectPath` per decidere quando avviene il rilevamento. |
| `autoDetectPath` | `string` | `'/'` | Dove possono essere eseguiti i redirect basati su preferenza di cookie / Accept-Language (quando `redirects` è abilitato). - `'/'` — solo `/` (i deep link nella locale predefinita restano raggiungibili; predefinito) - `'no_prefix'` — solo percorsi senza prefisso di locale - `'*'` — ogni percorso, includendo la riscrittura di un prefisso di locale esplicito   (ad esempio `/fr/about` → `/de/about` quando il cookie preferisce `de`) - qualsiasi altra stringa — corrispondenza esatta del percorso (ad esempio `'/welcome'`) La pulizia della strategia con prefisso (ad esempio `/en` → `/` sotto `prefix_except_default`) non è vincolata. |

## Registrazione

Parti del modulo che puoi disattivare.

| Opzione | Tipo | Predefinito | Descrizione |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Registra il plugin macro `defineI18nRoute()`, abilitando le chiamate `defineI18nRoute()` per pagina. |
| `plugin` | `boolean` | `true` | Registra il plugin i18n core che fornisce `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` e altri helper runtime. |
| `hooks` | `boolean` | `true` | Registra il plugin degli hook i18n che fornisce gli hook a livello di app `i18n:register` e `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`. |
| `components` | `boolean` | `true` | Registra i componenti i18n integrati (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Imposta `false` per disabilitare la registrazione automatica dei componenti (ad esempio se non li usi e vuoi ridurre l'impronta del modulo). |
| `types` | `boolean` | `true` | Genera dichiarazioni di tipo TypeScript per `useI18n`, `$t` e helper correlati in base alle chiavi di traduzione nei file della locale predefinita. |
| `debug` | `boolean` | `false` | Abilita il logging di debug verboso per il rilevamento della locale, la generazione delle route e il caricamento delle traduzioni. |

| `cacheMaxSize` | `number` | `0` | Numero massimo di voci nella cache in memoria delle traduzioni. `0` significa nessun limite. |
| `cacheTtl` | `number` | `0` | Time-to-live (in secondi) per le voci in cache delle traduzioni. `0` significa che le voci non scadono mai. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Formati numerici named per locale (compatibili con Vue I18n). Abilita chiamate in stile `$tn(1000, 'currency')`. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Formati datetime named per locale (`datetimeFormats` compatibili con Vue I18n). Abilita chiamate in stile `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | `Cache-Control` HTTP max-age (secondi) per `/\{apiBaseUrl\}/:page/:locale/data.json`. Si applica per intero solo mentre `dateBuild` invalida l'URL (`?v=...`), che è il predefinito: la risposta è quindi `public, max-age=…, immutable` e sicura per browser e CDN. - `dateBuild: 0`/`''` — l'URL è stabile, quindi questa durata *non* viene rispettata; la   risposta diventa invece `public, max-age=0, must-revalidate`. Un `max-age` lungo su un   URL immutabile blocca il primo payload che un browser abbia mai visto. - `0` — non impostare `Cache-Control` per niente (utile in debug locale) - Non applicato in sviluppo (`import.meta.dev`) così l'HMR non si scontra con la cache del browser - Raggiunge solo le risposte servite tramite Nitro. I payload copiati in `public/` e serviti   dalla piattaforma di hosting prendono gli header di quella piattaforma. Consulta la guida Performance. Analogo all'opzione sperimentale `httpCacheDuration` di `@nuxtjs/i18n` (v10.2.0), ma come header di risposta esplicito piuttosto che maxAge di `defineCachedEventHandler` Nitro. |
| `dateBuild` | `string \| number` | — | Valore usato per il cache-busting delle richieste di traduzione (`?v=...`). Quando non fornito, il modulo ricade su `Date.now()` (non deterministico). Per deploy riproducibili/rolling, imposta un valore stabile (ad esempio uno SHA git o un numero di build). |
| `experimental` | `Record<string, unknown>` | — | Contenitore per opzioni sperimentali/instabili. I contenuti possono cambiare o essere rimossi senza preavviso tra versioni minor. |
