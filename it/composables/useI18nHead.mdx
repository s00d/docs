title: "useI18nHead"
description: "useI18nHead sovrascrive i tag SEO i18n generati per una singola pagina: sostituisci o rimuovi i tag canonical, hreflang e og, oppure aggiungi i tuoi."
---

`useI18nHead()` modifica i tag SEO generati dal modulo, solo per una pagina. Usalo quando una pagina ne sa più del router: un articolo di un CMS che esiste solo in alcune locale, un URL canonico proveniente da un'API, tag `og:` aggiuntivi. Ottieni i tag generati con le tue sovrascritture unite sopra.

## Firma {#signature}

```ts
useI18nHead(input?: MaybeRefOrGetter<I18nHeadInput | null>): { pageHead: any; resetPageHead: () => void }
```

Registra sovrascritture a livello di pagina per i tag head SEO i18n.
Vengono unite sopra l'output di `useLocaleHead` dal plugin `02.meta`.

Preferisci un getter (`() => ({ … })`) quando i valori provengono da `$t` / `t`, così
vengono risolti di nuovo al cambio di locale. Un oggetto semplice viene valutato una sola volta e resta congelato.

| Parametro | Tipo | Descrizione |
| --- | --- | --- |
| `input` *(opzionale)* | `MaybeRefOrGetter<I18nHeadInput \| null>` |  |

Funziona con [`meta: true`](/it/api/module-options#meta) (il default): il plugin meta del modulo unisce l'input sopra l'output di [`useLocaleHead`](/it/composables/useLocaleHead) a ogni render dell'head. Con `meta: false` nessuno lo legge.

La sovrascrittura viene azzerata quando cambia il nome della route. Una pagina che imposta `disableMeta` non riceve alcun tag i18n, sovrascritture comprese.

## Input {#input}

`I18nHeadInput` (da `@i18n-micro/types`):

| Chiave | Tipo | Effetto |
| --- | --- | --- |
| `htmlAttrs` | `Record<string, string>` | Unito agli attributi di `<html>` (`lang`, `dir`). |
| `meta` | `I18nHeadMeta[]` | Aggiunto dopo i tag generati; sostituisce un tag con lo stesso `id`, `property` o `name`. |
| `link` | `I18nHeadLink[]` | Aggiunto dopo i link generati; sostituisce un link con lo stesso `id`, oppure `rel` + `hreflang`. |
| `replace.canonical` | `string \| false` | Sostituisce l'`href` canonico, oppure rimuove il link. |
| `replace.hreflang` | `I18nHeadLink[] \| false` | Sostituisce o rimuove **tutti** i link `rel="alternate"`, `x-default` compreso. |
| `replace.xDefault` | `I18nHeadLink \| false` | Sostituisce o rimuove il link `x-default`. |
| `replace.ogLocale` | `string \| false` | Sostituisce o rimuove `og:locale`. |
| `replace.ogUrl` | `string \| false` | Sostituisce o rimuove `og:url`. |
| `replace.ogAlternates` | `string[] \| false` | Ricostruisce `og:locale:alternate` a partire da questi codici di locale (tramite `og` / `iso`), saltando la locale corrente, i codici sconosciuti e i codici senza un valore `og` o `iso`, oppure li rimuove. |
| `disable` | `I18nHeadDisableGroup[]` | Elimina gruppi generati: `'hreflang'` (non `x-default`), `'x-default'`, `'canonical'`, `'og'` (`og:locale` + `og:url`), `'og-alternates'`, `'html'`. |

Ordine di applicazione: `disable`, poi `replace`, poi `htmlAttrs`, `meta`, `link`.

## Esempio {#example}

Un articolo che esiste solo in alcune locale, con URL alternativi provenienti dall'API:

```vue
<script setup lang="ts">
const route = useRoute()
const { t } = useI18n()
const { data: article } = await useFetch<{ title: string; urls: Record<string, string> }>(`/api/articles/${route.params.slug}`)

useI18nHead(() => {
  if (!article.value) return null
  const codes = Object.keys(article.value.urls)
  return {
    meta: [{ property: 'og:title', content: article.value.title || t('blog.title') }],
    replace: {
      hreflang: codes.map((code) => ({ rel: 'alternate', hreflang: code, href: article.value!.urls[code]! })),
      ogAlternates: codes,
    },
  }
})
</script>
```

Passa un getter, come qui, quando i valori provengono da `t()` o da dati asincroni: viene rieseguito al cambio di locale. Un oggetto semplice viene letto una sola volta.
