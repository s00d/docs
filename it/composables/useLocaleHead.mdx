---
title: "useLocaleHead"
description: "useLocaleHead costruisce i tag SEO i18n (lang, dir, canonical, hreflang, og:locale) come oggetto da passare a useHead."
---

`useLocaleHead()` costruisce i tag head i18n per la route corrente: `lang` e `dir` su `<html>`, un link canonico, le alternative `hreflang` con `x-default`, `og:url`, `og:locale` e `og:locale:alternate`. Usalo quando imposti [`meta: false`](/it/api/module-options#meta) e gestisci `useHead` da solo; con `meta: true` il modulo registra già questi tag, e le modifiche per singola pagina passano da [`useI18nHead`](/it/composables/useI18nHead).

## Firma {#signature}

```ts
useLocaleHead(options: UseLocaleHeadOptions): { build: () => LocaleHead; metaObject: Ref<{ htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string; [key: string]: string | undefined }; link: ({ href: string; rel: "canonical"; [key: string]: string | undefined } | { href: string; hreflang: string; rel: "alternate"; [key: string]: string | undefined })[]; meta: { content: string; property: string; [key: string]: string }[] }, LocaleHead | { htmlAttrs: { dir?: "ltr" | "rtl" | "auto"; lang?: string; [key: string]: string | undefined }; link: ({ href: string; rel: "canonical"; [key: string]: string | undefined } | { href: string; hreflang: string; rel: "alternate"; [key: string]: string | undefined })[]; meta: { content: string; property: string; [key: string]: string }[] }>; updateMeta: () => void }
```

I tag head SEO per la route corrente: alternative `hreflang` per ogni locale più
`x-default`, un link canonico, `og:locale` e `lang`/`dir` su `<html>`.

Serve solo quando `meta` è disabilitato o i default vanno modificati: con `meta: true`
il modulo registra da solo gli stessi tag.

| Parametro | Tipo | Descrizione |
| --- | --- | --- |
| `options` | `UseLocaleHeadOptions` |  |

**Restituisce**: `metaObject`, un ref che contiene l'oggetto head pronto da passare a `useHead`; `updateMeta` lo aggiorna; `build` calcola l'oggetto head dalla route corrente (reattivo quando viene letto in un getter, ad es. `useHead(() => build())`)

```ts
const { metaObject } = useLocaleHead({ addSeoAttributes: true })
useHead(metaObject)
```

## Opzioni {#options}

| Opzione | Default | Descrizione |
| --- | --- | --- |
| `addDirAttribute` | `true` | Imposta `dir` su `<html>` dal `dir` della locale (`'auto'` se non ne ha uno). |
| `identifierAttribute` | `'id'` | Attributo che identifica ogni tag (`i18n-can`, `i18n-og`, `i18n-alternate-<hreflang>`, …), in modo che gli aggiornamenti sostituiscano i tag invece di aggiungerne. |
| `addSeoAttributes` | `true` | Emette i tag canonical, `hreflang` e `og:`. `false` mantiene solo `htmlAttrs`. |
| `baseUrl` | `'/'` | Origine unita a ogni URL. Lascia `'/'` per URL relativi; passa `'https://example.com'` per URL assoluti. |
| `autoUpdate` | `true` | Ricostruisce `metaObject` quando cambia la route o lo stato `i18n-locale`. |

## Cosa emette {#what-it-emits}

- Niente su una route senza corrispondenza (404) o con `disableMeta` per la locale attiva.
- Canonical e `og:url`: `$switchLocalePath(<active locale>)`, query ridotta a [`canonicalQueryWhitelist`](/it/api/module-options#canonicalquerywhitelist), con [`trailingSlash`](/it/api/module-options#trailingslash) applicato.
- `hreflang`: un link per ogni locale abilitata in cui esiste la pagina, `hreflang = iso || code`, saltando le locale con `seo: false`; con `hreflangBaseLanguage: true` la prima locale regionale di una lingua emette anche il tag della sola lingua. Nessuno con `no_prefix`.
- `x-default`: l'URL della locale di default, a meno che la strategia sia `no_prefix`, la locale di default abbia `seo: false` o la pagina non esista in essa.
- `og:locale` / `og:locale:alternate`: dall'`og` della locale, oppure dal suo `iso` convertito (`en-US` → `en_US`); saltato con un avviso in sviluppo quando nessuno dei due funziona.

## Esempio {#example}

```ts
// app.vue, with i18n.meta: false
const { metaObject } = useLocaleHead({ baseUrl: 'https://example.com' })
useHead(metaObject)
```

`build()` restituisce lo stesso oggetto senza il ref: `useHead(() => build())` resta reattivo senza un watcher.
