---
title: "useI18nLocale"
description: "useI18nLocale legge e scrive lo stato del locale e il cookie del locale — il punto di ingresso per il rilevamento personalizzato del locale."
---

`useI18nLocale()` dà accesso al locale scelto dall'app: lo stato `i18n-locale` e il cookie del locale. Usalo in un plugin che rileva da sé il locale (dominio, profilo utente, header) invece di scrivere a mano `useState('i18n-locale')` o il cookie. I suoi controlli di validità usano i locale abilitati, inclusi gli override di runtime.

## Firma {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Punto di ingresso centralizzato per la gestione del locale i18n.
Combina useState('i18n-locale'), il cookie del locale e le utility di sincronizzazione.

## Valori restituiti {#returned-values}

| Membro | Tipo | Descrizione |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | Il ref `useState('i18n-locale')`. |
| `localeCookie` | `Ref<string \| null>` | Il cookie [`localeCookie`](/it/api/module-options#localecookie); un semplice `{ value: null }` quando l'opzione è `null`. |
| `hashCookie` | `Ref<string \| null>` | Il cookie `hash-locale` con il routing hash; altrimenti `{ value: null }`. |
| `validLocales` | `string[]` | Codici dei locale abilitati. |
| `setLocale(locale)` | `(locale: string \| null) => void` | Scrive lo stato e i cookie. Non esegue validazione e non carica le traduzioni. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | Scrive solo i cookie. |
| `getLocale()` | `() => string \| null` | Lo stato, poi il cookie di preferenza (il cookie hash con il routing hash). Non validato. |
| `getPreferredLocale()` | `() => string \| null` | Il primo **valido** tra stato e cookie di preferenza, oppure `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | Lo stato con il routing hash, se impostato; altrimenti `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, poi uno stato valido, poi `options.serverLocale`, poi il locale della route. Salva il risultato nello stato quando lo stato non è valido; sul client scrive anche il cookie. |
| `isValidLocale(locale)` | `(locale) => locale is string` | Indica se `locale` è in `validLocales`. |

I cookie durano un anno, con `path: '/'` e `sameSite: 'lax'`.

## Esempio {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

Il plugin loader del modulo legge lo stato all'avvio, quindi un plugin che lo imposta deve essere eseguito prima (`enforce: 'pre'`). Come lo stato si rapporta all'URL, al cookie e ad `Accept-Language`: [Rilevamento del locale](/it/guide/locale-detection). Procedura completa: [Rilevamento personalizzato](/it/guide/custom-auto-detect).

`setLocale()` non cambia le traduzioni sullo schermo. Per cambiare il locale della pagina corrente, chiama [`$switchLocale()`](/it/api/methods#$switchlocale).
