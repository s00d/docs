Questa pagina mappa un'app `@nuxtjs/i18n` su nuxt-i18n-micro: opzioni, helper e struttura dei file. Usala quando sostituisci il modulo in un'app esistente. Mantieni i tuoi URL (i nomi delle strategie sono gli stessi) e sposti le traduzioni in file JSON per pagina.

<Tip>

**Stai aggiornando nuxt-i18n-micro stesso?** — Vedi [Aggiornamento](/it/guide/upgrade).

</Tip>

## Sostituire il modulo {#swap-the-module}

```bash
npm uninstall @nuxtjs/i18n
npm install nuxt-i18n-micro
```

```ts
// nuxt.config.ts — before
export default defineNuxtConfig({
  modules: ['@nuxtjs/i18n'],
  i18n: {
    locales: [
      { code: 'en', language: 'en-US', file: 'en.json' },
      { code: 'de', language: 'de-DE', file: 'de.json' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    langDir: 'locales',
    detectBrowserLanguage: { useCookie: true, cookieKey: 'i18n_redirected', redirectOn: 'root' },
  },
})
```

```ts
// nuxt.config.ts — after
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    translationDir: 'locales',
    localeCookie: 'i18n_redirected',
    autoDetectPath: '/',
  },
})
```

## Opzioni {#options}

| `@nuxtjs/i18n` | nuxt-i18n-micro |
| --- | --- |
| `locales[].code` | `locales[].code` |
| `locales[].language` (`iso` prima della v9) | `locales[].iso` |
| `locales[].name` | `locales[].displayName` |
| `locales[].dir` | `locales[].dir` |
| `locales[].domain` | `locales[].baseUrl` (un'origine con il suo schema) |
| `locales[].domainDefault` | `locales[].baseDefault` |
| `differentDomains`, `multiDomainLocales` | non necessari: `baseUrl` da solo instrada in base all'host, vedi [Layer e domini](/it/guide/layers#multiple-domains) |
| `locales[].file` / `files`, `langDir`, `lazy` | `translationDir`; i file vengono trovati per nome e sempre caricati per pagina |
| `defaultLocale`, `strategy` | stessi nomi, stessi quattro valori |
| `baseUrl` | `metaBaseUrl` |
| `customRoutes: 'config'` + `pages` | `globalLocaleRoutes` |
| `detectBrowserLanguage: false` | `redirects: false` (nessun redirect) o `autoDetectLanguage: false` (ignora l'header) |
| `detectBrowserLanguage.useCookie` / `cookieKey` | `localeCookie: '<name>'` (`null` disattiva il cookie) |
| `detectBrowserLanguage.redirectOn: 'root'` | `autoDetectPath: '/'` (predefinito) |
| `detectBrowserLanguage.redirectOn: 'no prefix'` | `autoDetectPath: 'no_prefix'` |
| `detectBrowserLanguage.redirectOn: 'all'` | `autoDetectPath: '*'` |
| file di configurazione `vueI18n` (`fallbackLocale`, `numberFormats`, `datetimeFormats`) | `fallbackLocale`, `numberFormats`, `datetimeFormats` in `i18n` |

Non esiste `alwaysRedirect`: con un cookie impostato, `/` lo segue a ogni visita. L'elenco completo è in [Opzioni del modulo](/it/api/module-options); le regole di rilevamento sono in [Rilevamento del locale](/it/guide/locale-detection).

## Helper e composable {#helpers-and-composables}

| `@nuxtjs/i18n` / vue-i18n | nuxt-i18n-micro (template / `useI18n()`) |
| --- | --- |
| `const { t } = useI18n()` | `const { t } = useI18n()`, `$t` nei template |
| `t('key', count)`, `tc` | `$tc('key', count)` |
| `te('key')` | `$has('key')` |
| `n(value, 'currency')`, `d(date, 'short')` | `$tn(value, 'currency')`, `$td(date, 'short')` |
| — | `$tdr(date)`: tempo relativo ("tra 3 giorni") |
| `locale.value` | `$getLocale()` |
| `locales.value` | `$getLocales()` |
| `setLocale('de')` | `$switchLocale('de')` |
| `useLocalePath()('about')` | `$localePath({ name: 'about' })` |
| `useLocaleRoute()` | `$localeRoute()` |
| `useSwitchLocalePath()('de')` | `$switchLocalePath('de')` |
| `useSetI18nParams()` | `$setI18nRouteParams()` |
| `useLocaleHead()` | automatico con `meta: true`; [`useLocaleHead`](/it/composables/useLocaleHead) per head personalizzati |
| `defineI18nRoute({ paths: { de: '/ueber-uns' }, locales: [...] })` | `$defineI18nRoute({ localeRoutes: { de: '/ueber-uns' }, locales: [...] })` |
| `<NuxtLinkLocale to="about">` | `<i18n-link :to="{ name: 'about' }">` |
| `<i18n-t>` | `<i18n-t>` (gli slot riempiono i segnaposto `{name}`) |
| `$i18n` nelle route server | `useTranslationServerMiddleware(event)`, vedi [Route server e API](/it/guide/server-side-translations) |

`useI18n()` viene importato automaticamente. `$defineI18nRoute` deve mantenere il suo `$`: la build legge quella chiamata. Tutti gli helper: [Metodi](/it/api/methods).

## File di traduzione {#translation-files}

Sposta le chiavi di un unico grande file per locale in un file root più un file per pagina:

```text
locales/
├── en.json              # keys used on many pages (nav, footer)
├── de.json
└── pages/
    ├── index/en.json    # keys of pages/index.vue
    └── about/en.json    # keys of pages/about.vue
```

Anche tenere tutto nei file root funziona, ed è il primo passo più rapido. Imposta `disablePageLocales: true` finché non li suddividi. Vedi [File di traduzione](/it/guide/translations).

### Sintassi dei messaggi {#message-syntax}

| vue-i18n | nuxt-i18n-micro |
| --- | --- |
| interpolazione con nome `{name}` | uguale |
| `car \| cars` (2 forme: 1 → la prima) | le forme vengono scelte in base al conteggio a partire da 0: scrivi `no cars \| one car \| {count} cars` |
| linked messages `@:other.key` | non supportati: ripeti il testo o componi nel codice |
| modificatori `@.upper:` | non supportati: formatta nel codice o usa `<i18n-t>` |
| escape letterali `{'@'}` | non necessari: vengono sostituiti solo i token `{word}` |
| file di messaggi JS/TS | solo JSON |

La regola plurale è sostituibile con l'opzione [`plural`](/it/api/module-options#plural).

## Verifiche dopo il passaggio {#check-after-the-switch}

- Ogni URL che avevi viene ancora risolto; i nomi delle strategie coincidono, i percorsi personalizzati passano a `globalLocaleRoutes` o `$defineI18nRoute`.
- `hreflang`, canonical e `og:locale` sono disponibili di default con `meta: true`; rimuovi quelli scritti a mano.
- Un errore di parsing JSON registra il percorso del file; una chiave mancante registra un avviso nella console del browser in sviluppo.
