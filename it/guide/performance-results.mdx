### Descrizione {#description}

Confronta **Nuxt semplice**, **i18n-micro** e **`@nuxtjs/i18n`** con un unico profilo di dizionario condiviso tramite `untestutils/perf`.

Focus: tempo di build, picco di RSS, **codice vs traduzioni (asset) vs totale** distribuibili e carico (Artillery).

### Note sulla metodologia {#methodology-notes}

- Le metriche sono **medie di 3 esecuzioni consecutive per fixture** (non alternate).
- **Artefatto**: `.output/server/index.mjs` del node-server Nitro dopo un `nuxi build` forzato; `nuxt-i18n-micro` è il **dist del modulo compilato** (non lo stub jiti di `dev:prepare`). Vedi la [metodologia dei benchmark](https://s00d.github.io/nuxt-i18n-micro/contributing/performance-methodology).
- **Traduzioni** = `bundle.asset` (JSON delle lingue, `chunks/raw/`, chunk di lingua corrispondenti tramite `isTranslationFile`).
- **Codice** esclude le source map (`*.map`): le fixture collegano il modulo dal repository, quindi Nitro scrive le mappe complete per esso e nessuna per le dipendenze npm.
- **plain-nuxt** serve lo stesso volume di foglie come JSON statico — pesante in I/O sotto carico, non “overhead di i18n”.
- Profilo di carico `--load full`: warm 6s@6 + main 60s@60 senza limite (storico).
- Pause di raffreddamento `--cool fast` (vedi il documento sulla metodologia).
- Ognuna delle build delle `runs` è **forzata** (nessun azzeramento del tempo di build dovuto alla cache calda).
- Il **tasso di errore** di Artillery nelle tabelle indica gli errori di stato HTTP dalle metriche di carico. I grafici riportano anche `vusers.failed` (timeout del client in saturazione); questi possono essere alti mentre il tasso di errore HTTP resta 0%.

## Note {#notes}

- Profilo condiviso: 4 lingue × 2 pagine × ~16.8k foglie index.
- Carico: solo Artillery programmatico — warm **6s@6** + main **60s@60**, VU senza limite (metodologia YAML storica). Percorsi dal profilo di runtime — vedi `scripts/src/perf/load.ts`.
- Pause di raffreddamento: 2s dopo la build, 3s tra le esecuzioni, 5s tra le fixture. Le build sono forzate a ogni esecuzione, quindi le medie non sono diluite dai cache hit.
- Riesecuzione quotidiana: `pnpm test:performance` (`--load short --cool fast`).
- Rigenerare questa pagina: `pnpm -C scripts cli performance --load full --only all --runs 3`.
- Flag: `--locales N --keys K --only all|micro|i18n|plain --runs N --skip-load --cool fast|strict`.
