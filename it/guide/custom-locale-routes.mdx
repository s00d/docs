---
title: "Percorsi localizzati"
description: "Assegna a una pagina un URL diverso per ogni locale con localeRoutes o globalLocaleRoutes, inclusi parametri dinamici e slug per locale."
---

Per default ogni locale serve una pagina allo stesso percorso: `/en/about`, `/de/about`. I percorsi localizzati permettono a ogni locale di usare le proprie parole, come `/de/ueber-uns`, mentre il file della pagina resta lo stesso. Li imposti nella pagina con `$defineI18nRoute`, oppure per molte pagine insieme in `nuxt.config.ts`.

## Nella pagina {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

Con `prefix_except_default` e `defaultLocale: 'en'` la pagina risponde a `/about`, `/de/ueber-uns` e `/fr/a-propos`. Una locale senza voce mantiene il percorso di default. Scrivi i percorsi senza il codice della locale: il prefisso viene aggiunto dalla [strategia](/it/guide/strategy), e un percorso che inizia con il codice della locale genera un avviso nei log. Cos'altro accetta la chiamata è descritto in [Configurazione della pagina](/it/guide/per-component-translations).

## In nuxt.config {#in-nuxt-config}

[`globalLocaleRoutes`](/it/api/module-options#globallocaleroutes) fa lo stesso per qualsiasi pagina, usando come chiave il suo percorso (o il nome della route, se scritto senza slash iniziale):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

Quando una pagina imposta `localeRoutes` e `globalLocaleRoutes` ha la stessa chiave, prevale la voce della configurazione.

## Parametri dinamici {#dynamic-params}

Scrivi i parametri in qualsiasi forma di Nuxt: `[id]`, `[[page]]`, `[...slug]` o `:id()`. I nomi dei parametri devono corrispondere al file della pagina.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

Le pagine annidate accettano un percorso figlio assoluto (`/ueber-uns/team`) o un percorso relativo al percorso localizzato del genitore (`team`).

## Link alle pagine localizzate {#linking-to-localized-pages}

I link si risolvono nel percorso localizzato della locale di destinazione, sia che passi un nome di route sia un percorso semplice:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

I nomi delle route derivano dal percorso del file (`pages/about/team.vue` diventa `about-team`), a meno che tu non ne imposti uno con `definePageMeta({ name })`.

## Slug per locale {#per-locale-slugs}

Quando lo slug stesso cambia a seconda della locale (`/our-products/red-shoe` rispetto a `/de/unsere-produkte/roter-schuh`), indica al selettore di lingua quali parametri usare con `$setI18nRouteParams` una volta caricati i dati:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

`$switchLocalePath('de')` e `<i18n-switcher>` puntano quindi a `/de/unsere-produkte/roter-schuh`. Le chiavi sono codici di locale, i valori sono parametri per nome (come nel file della pagina).

Un selettore nel layout viene renderizzato prima che il setup asincrono della pagina arrivi a questo punto, quindi al termine del render il modulo riscrive i link di `<i18n-switcher>`, sia in `app.vue` sia nella pagina. L'HTML del server, un visitatore senza JavaScript e il primo render client risultano così coerenti. Per questo, imposta i parametri durante l'SSR: con `lazy` o `server: false` i link cambiano solo dopo l'idratazione. Lo streaming SSR di Nuxt invia l'HTML prima che i parametri siano noti, quindi in quel caso i link nel primo HTML mantengono i parametri dell'URL stesso.

Vengono riscritti solo i link del selettore. Un link `$switchLocalePath` scritto a mano deve essere renderizzato dopo che i parametri sono stati impostati, quindi mettilo nella pagina che li imposta, anche dopo un `await`. In un layout viene renderizzato prima: il suo HTML del server mantiene i parametri dell'URL e l'idratazione segnala una discrepanza. Lì usa `<i18n-switcher>`, con i suoi slot e le prop `custom*Style` per l'aspetto.

I parametri appartengono alla pagina che li ha impostati:

- Vengono scartati quando viene confermata una navigazione verso un altro percorso, quindi ogni pagina imposta i propri. Una navigazione annullata li lascia invariati.
- Prendi `$setI18nRouteParams` da `useNuxtApp()` o `useI18n()` nel `setup`, anche quando lo chiami più tardi in un handler di `useAsyncData`. Ottenuta lì, la funzione conosce la sua pagina: se il visitatore se n'è andato, una chiamata tardiva non fa nulla.
- Con `keepalive`, una pagina ritrova i parametri che aveva impostato quando il visitatore ritorna. `useI18nHead` fa lo stesso.

## Route aggiunte in pages:extend {#routes-added-in-pagesextend}

Le route che aggiungi nell'hook `pages:extend` non hanno un file di pagina da cui leggere `$defineI18nRoute`, e spesso diverse di esse condividono un unico componente wrapper. Una route aggiunta senza `name` riceve il nome che Nuxt darebbe al suo percorso (`/a/:id()` diventa `a-id`), così i link di lingua la raggiungono, a meno che un'altra route abbia già quel nome; in tal caso assegnale un `name` esplicito. Mantieni un'unica lista e dividila in pagine e `globalLocaleRoutes` indicizzate per nome di route con `splitLocaleRoutes` da `@i18n-micro/utils/split-locale-routes` (aggiungi il pacchetto alle tue dipendenze):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

Non mettere percorsi localizzati in `route.meta`: finirebbero nella tabella delle route del client.
