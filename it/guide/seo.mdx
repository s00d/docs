Con `meta: true` (il default) ogni pagina localizzata riceve `<html lang dir>`, un link canonico, le alternative `hreflang`, `x-default` e i tag Open Graph della locale. Ti serve questa pagina quando vuoi impostare l'origine pubblica, regolare quali locale compaiono nei tag o sovrascriverli per una pagina. Alla maggior parte dei siti bastano un `site.url` o un `metaBaseUrl` e codici `iso` corretti.

## Configurazione minima {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

`/de/about` renderizza quindi:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Direzione del testo {#text-direction}

`<html dir>` deriva dal `dir` della locale. Se manca, una lingua scritta da destra a sinistra riceve `rtl`, ricavato da `iso` (o `code`): arabo, ebraico, persiano, urdu e poche altre, oltre a qualsiasi tag con uno script RTL come `az-Arab`. Tutte le altre locale non ricevono alcun attributo `dir`, che i browser interpretano come `ltr`.

<Warning>

**`dir: 'auto'` costa tempo di parsing sulle pagine grandi**: `auto` su `<html>` costringe il browser a determinare la direzione dal contenuto durante il parsing. In Chromium questo costo cresce più rapidamente della pagina: circa 100 ms a 5.000 elementi e 1 s a 20.000. Usalo solo per una pagina piccola di cui non puoi conoscere la lingua.

</Warning>

## Quali tag ottieni {#which-tags-you-get}

- **hreflang**: un tag per ogni locale che serve la pagina, con valore `iso` (o `code` quando `iso` manca) e il suo URL con la stessa query del canonical. Una pagina limitata con la [Configurazione della pagina](/it/guide/per-component-translations) o con `routeLocales` elenca solo le sue locale. [`hreflangBaseLanguage: true`](/it/api/module-options#hreflangbaselanguage) aggiunge anche la sola lingua (`es-ES` → `es`) per la prima locale regionale.
- **x-default**: l'URL della locale di default, solo quando la locale di default serve la pagina.
- **og:locale**: derivato da `iso` (`en-US` → `en_US`). Imposta `og` sulla locale quando la mappatura non è diretta, ad esempio `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; senza nessuno dei due, non viene scritto alcun `og:locale` e la modalità di sviluppo emette un avviso.
- **canonical / og:url**: l'URL corrente senza parametri di query, tranne quelli in [`canonicalQueryWhitelist`](/it/api/module-options#canonicalquerywhitelist) (default `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Per strategia:

| Strategia | hreflang e x-default | canonical, og:url, og:locale, attributi html |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | sì | sì |
| `no_prefix` | no (un solo URL serve tutte le locale) | sì |

## Impostare l'origine pubblica {#set-the-public-origin}

Gli URL assoluti usano la prima disponibile tra:

1. [`metaBaseUrl`](/it/api/module-options#metabaseurl);
2. `site.url` da `nuxt-site-config` (installato da `@nuxtjs/seo`);
3. l'origine della richiesta, con `app.baseURL` aggiunto in coda.

Fissa una delle prime due.

<Warning>

Il fallback sull'origine della richiesta legge `X-Forwarded-Host` e `X-Forwarded-Proto`, perché [`metaTrustForwardedHost`](/it/api/module-options#metatrustforwardedhost) e `metaTrustForwardedProto` sono `true` per default. Questo è sicuro solo dietro un proxy che sovrascrive quegli header; altrimenti un client può scegliere l'host nei tuoi link canonici, e una cache può propagare quella pagina.

Se l'app è raggiungibile direttamente, fissa `metaBaseUrl`: a differenza di impostare entrambe le opzioni a `false`, ignora anche un `Host` contraffatto. Vedi [Dietro un proxy o una CDN](/it/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

Il fallback è utile per un unico deployment che risponde a più domini: `https://site-a.com/en/about` e `https://site-b.com/en/about` ricevono ciascuno la propria origine.

Con `baseUrl` sulle locale, un host noto usa il proprio `baseUrl`, con precedenza su `metaBaseUrl` e `site.url`, così canonical e `og:url` restano su quel dominio e `hreflang` punta ogni locale al suo dominio. Qualsiasi altro host usa `metaBaseUrl`, altrimenti il `baseUrl` della locale di default, altrimenti `site.url`, così un `Host` falsificato non può raggiungere i tuoi tag. Se nessuno di questi è impostato, resta il fallback sull'origine della richiesta e la build emette un avviso. Vedi [Layer e domini](/it/guide/layers#multiple-domains).

## Escludere locale o pagine {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Se la locale di default ha `seo: false`, non viene scritto alcun `x-default`. Per disattivare i tag per una pagina, usa `disableMeta` nella [Configurazione della pagina](/it/guide/per-component-translations#turn-off-seo-tags), oppure [`routeDisableMeta`](/it/api/module-options#routedisablemeta) nella configurazione.

## Sovrascrivere i tag su una pagina {#override-tags-on-one-page}

Per contenuti CMS in cui esistono solo alcune traduzioni, o in cui gli URL provengono da un'API, sostituisci i tag generati con [`useI18nHead`](/it/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` può anche impostare o rimuovere `canonical`, `xDefault`, `ogLocale` e `ogUrl`; `disable` elimina interi gruppi (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Passa un getter così i valori vengono ricalcolati dopo un cambio di locale. Per gli slug per locale, imposta prima `$setI18nRouteParams` ([Percorsi localizzati](/it/guide/custom-locale-routes#per-locale-slugs)) e le alternative generate li useranno già.

## Slash finale {#trailing-slash}

`$localePath`, `$switchLocalePath`, l'oggetto route di `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, i redirect di locale e gli URL SEO seguono un'unica regola per lo slash: `experimental.defaults.nuxtLink.trailingSlash` per default, oppure [`trailingSlash`](/it/api/module-options) nella configurazione i18n quando i percorsi i18n devono differire.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) funziona con questo modulo tramite `nuxt-site-config` 4+. Elenca `nuxt-i18n-micro` per primo, così la configurazione del sito può leggere le locale, e imposta `site.url` una sola volta: alimenta anche i tag descritti sopra.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Un nome e una descrizione del sito tradotti provengono dalle chiavi `nuxtSiteConfig.name` / `nuxtSiteConfig.description` nei tuoi file di locale. L'errore `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` significa che `@nuxtjs/seo` è precedente alla versione 3; aggiornalo ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
