title: "Configurazione della pagina"
description: "Limita una pagina ad alcuni locale, assegnale percorsi personalizzati, traduzioni inline o nessun tag SEO con $defineI18nRoute."
---

`$defineI18nRoute` imposta le opzioni i18n per una singola pagina dall'interno della pagina stessa. Usalo quando una pagina esiste solo in alcuni locale, ha bisogno di un proprio percorso localizzato, contiene alcune traduzioni proprie o non deve ricevere i tag hreflang/canonical. Il modulo legge la chiamata in fase di build e la incorpora nelle route generate.

## Limitare una pagina ad alcuni locale {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

Con la strategia predefinita `prefix_except_default` vengono generati solo `/product` e `/de/product`; la pagina non ha alcuna route negli altri locale. Lo stesso si può impostare da `nuxt.config.ts` con [`routeLocales`](/it/api/module-options#routelocales).

`$defineI18nRoute` è un'iniezione dell'app Nuxt, non una macro del compilatore: prendila sempre da `useNuxtApp()` e chiamala con il `$`. Solo `$defineI18nRoute(` viene riconosciuto dalla fase di build.

## Aggiungere traduzioni inline {#add-inline-translations}

Passa un oggetto invece di un array. Le sue chiavi sono i locale consentiti, i suoi valori vengono uniti al dizionario della pagina per il locale attivo.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Le traduzioni inline vengono distribuite all'interno del componente della pagina per ogni locale. Preferisci i [file di traduzione della pagina](/it/guide/translations) per qualsiasi cosa superi poche chiavi; riserva le chiavi inline a pagine e componenti autonomi.

## Impostare percorsi localizzati {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

Con `prefix_except_default` e `defaultLocale: 'en'` questo produce `/welcome` e `/de/willkommen`. Un `path` all'interno di un oggetto locale inline fa lo stesso: `locales: { de: { path: '/willkommen' } }`. Parametri dinamici, route annidate e l'alternativa a livello di configurazione sono trattati in [Percorsi localizzati](/it/guide/custom-locale-routes).

## Disattivare i tag SEO {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

L'alternativa a livello di configurazione è [`routeDisableMeta`](/it/api/module-options#routedisablemeta). Cosa sono questi tag è spiegato nella pagina [SEO](/it/guide/seo).

## Cosa può leggere la build {#what-the-build-can-read}

La fase di build trova la chiamata in ogni file di pagina e ne valuta l'argomento senza eseguire la tua app. Funziona quando la configurazione è:

- un oggetto letterale (stringhe, array, oggetti annidati, template literal, ternari su `process.env.NODE_ENV`);
- costruita da costanti dichiarate nello stesso `<script setup>` (`const locales = ['en', 'de']`, spread inclusi);
- un array di oggetti con un campo `code` (`[{ code: 'en' }, { code: 'de' }]`).

Non può leggere valori importati da un altro modulo, né nulla che richieda la tua app a runtime (composable, `await`, dati recuperati). In tal caso la build registra `Ignored the $defineI18nRoute() config in <file>` e la pagina mantiene i locale e le route predefiniti.

A runtime la chiamata unisce solo le traduzioni inline per il locale corrente e le riunisce quando il locale cambia. `locales`, `localeRoutes` e `disableMeta` hanno effetto solo tramite la build, quindi modificarli richiede una nuova build (il server di sviluppo ricompila al salvataggio).
