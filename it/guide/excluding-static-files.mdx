---
title: "Esclusione dei percorsi"
description: "Tieni pagine e file fuori dal routing per locale con excludePatterns e scopri quali percorsi sono già esclusi."
---

Alcuni percorsi non devono mai ricevere un prefisso di locale o un reindirizzamento di locale: un'area di amministrazione, un health check, un feed generato. `excludePatterns` li contrassegna, e un elenco integrato copre già gli interni di Nuxt e i file statici più comuni. Una pagina esclusa mantiene esattamente il percorso che hai scritto e viene comunque renderizzata con `$t`.

## Escludere un percorso {#exclude-a-path}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    excludePatterns: [
      '/admin', // /admin and everything below it
      '/preview-*', // glob over the whole path
    ],
  },
})
```

Con questa configurazione `pages/admin/index.vue` risponde solo su `/admin`; non esiste `/de/admin`, e `/admin` non viene mai reindirizzato a `/de/admin`.

## Sintassi dei pattern {#pattern-syntax}

I pattern vengono confrontati con il percorso senza `app.baseURL`:

| Pattern | Corrisponde a | Non corrisponde a |
| --- | --- | --- |
| `'/admin'` | `/admin`, `/admin/users` | `/administrator`, `/de/admin` |
| `'/preview-*'` | `/preview-1`, `/preview-a/b` | `/de/preview-1` |
| `'/file-?'` | `/file-a` | `/file-ab` |
| `/^\/v\d+\//` | `/v2/docs` | `/docs` |

Una stringa senza `*` o `?` corrisponde al percorso e ai segmenti interi sotto di esso. Con `*` (qualsiasi sequenza di caratteri, barre incluse) o `?` (un carattere) deve corrispondere all'intero percorso. Inizia sempre le stringhe con `/`.

## Cosa è già escluso {#what-is-excluded-already}

Questi percorsi non ricevono mai route o reindirizzamenti di locale, senza alcuna configurazione:

- `/api` e `/_nuxt`, e tutto ciò che si trova sotto di essi;
- la route delle traduzioni, `/_locales` per impostazione predefinita ([`apiBaseUrl`](/it/api/module-options#apibaseurl));
- qualsiasi percorso con un segmento che inizia con `__` (`/__nuxt_content`, `/en/__og-image__`);
- `/sitemap*.xml`, `/robots.txt`, `/favicon.ico`, `/apple-touch-icon*.png`, `/manifest.json`, `/sw.js`, `/workbox-*.js`;
- qualsiasi percorso il cui ultimo segmento termina con un'estensione di file statico: `xml txt ico json js css png jpg jpeg gif svg webp avif pdf wasm map mp4 webm mp3 zip gz woff woff2 ttf eot`. Gli slug di pagina con punti come `/user/john.doe` e i percorsi `.html` restano pagine.

## Cosa fa un'esclusione {#what-an-exclusion-does}

- **Route:** non vengono generate varianti localizzate; la pagina viene mantenuta così come è scritta.
- **Reindirizzamenti e 404:** il plugin di reindirizzamento lato server e il middleware di reindirizzamento lato client ignorano il percorso.
- **Prerender:** i percorsi corrispondenti vengono rimossi dall'elenco delle route da prerenderizzare.

Non impedisce al middleware server di i18n di rilevare un locale per la richiesta, né impedisce alla pagina di usare le traduzioni. Per mantenere una pagina localizzata ma esclusa dai tag SEO, usa `disableMeta` ([Configurazione della pagina](/it/guide/per-component-translations#turn-off-seo-tags)). Per mantenere una pagina non localizzata da `nuxt.config.ts` in base al percorso, `globalLocaleRoutes: { '/admin': false }` ([Percorsi localizzati](/it/guide/custom-locale-routes#in-nuxt-config)) fa lo stesso per il routing.
