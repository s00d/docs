---
title: "Override a runtime"
description: "Modifica il locale predefinito, il locale di fallback o i locale disabilitati per ogni istanza di una stessa build, con variabili d'ambiente o runtimeConfig."
---

Gli override a runtime permettono a un unico artefatto di build di funzionare con impostazioni di locale diverse per ambiente o tenant, senza ricompilare. Puoi modificare il locale predefinito, il locale di fallback e quali locale sono disabilitati. Routing, redirect, rendering e helper lato server usano i valori sovrascritti, e lo stesso fa il browser su una pagina renderizzata dal server.

## Impostare gli override con variabili d'ambiente {#set-overrides-with-environment-variables}

```bash
NUXT_I18N_DEFAULT_LOCALE=de \
NUXT_I18N_FALLBACK_LOCALE=en \
NUXT_I18N_DISABLED_LOCALES=fr,it \
node .output/server/index.mjs
```

| Variabile | Alias |
| --- | --- |
| `NUXT_I18N_DEFAULT_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE` |
| `NUXT_I18N_FALLBACK_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE` |
| `NUXT_I18N_DISABLED_LOCALES` (separati da virgola) | `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES` |

Il server le legge una sola volta all'avvio; riavvialo per applicare una modifica. Su una pagina renderizzata dal server il browser riceve i valori risolti dal server. Con `ssr: false` non c'è rendering lato server e il browser non ha un ambiente: lì si applica solo `runtimeConfig.public.i18nRuntime`, e il browser registra gli avvisi descritti più sotto.

## Impostare gli override in runtimeConfig {#set-overrides-in-runtimeconfig}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

Un valore impostato in `runtimeConfig.public.i18nRuntime` prevale sulla variabile `NUXT_I18N_*` per lo stesso campo.

Da non confondere con la variabile `DEFAULT_LOCALE` usata al build, che sostituisce `defaultLocale` durante la build e non richiede supporto a runtime.

## Cosa può e cosa non può cambiare {#what-can-and-cannot-change}

| Impostazione | A runtime |
| --- | --- |
| `defaultLocale` | Sì con `prefix` e `no_prefix`. Con `prefix_except_default` e `prefix_and_default` è fissato al build (le sue pagine sono le route senza prefisso); un override viene ignorato con un avviso. |
| `fallbackLocale` | Sì. |
| `disabledLocales` | Si aggiunge ai locale disabilitati al build; non ne riabilita mai uno. Il locale predefinito della build non può essere disabilitato con `prefix_except_default` / `prefix_and_default`. |
| `strategy` | No. Una strategia a runtime viene ignorata con un avviso; crea un artefatto per ogni strategia. |

I valori non validi non rompono mai l'app. Ogni caso registra un avviso per processo server:

- disabilitare tutti i locale viene ignorato;
- un `defaultLocale` non abilitato ricade sul primo locale abilitato;
- un `fallbackLocale` non abilitato mantiene il valore della build se questo è abilitato, altrimenti non c'è fallback.

## Leggere la configurazione effettiva {#read-the-effective-config}

```vue
<script setup lang="ts">
const { $getI18nConfig } = useNuxtApp()
const config = $getI18nConfig() // build config with overrides applied
</script>
```

Trattala come di sola lettura: sul server è condivisa da tutte le richieste ed è congelata in sviluppo; la copia nel browser non è congelata. Importare la configurazione da `#build/i18n.strategy.mjs` restituisce i valori della build senza override.

## Locale disabilitati e file statici {#disabled-locales-and-static-files}

Un locale disabilitato a runtime risponde 404 sulle sue route e sulla sua route del payload, ma i suoi file di payload si trovano ancora in `.output/public/_locales/` e un file server statico li restituisce. Quando quei file non devono essere raggiungibili, disabilita il locale al build con `disabled: true`.
