L'opzione `strategy` decide se un locale compare nell'URL e per quali locale. Sceglila una volta sola, prima di pubblicare gli URL: cambiarla in seguito modifica ogni link. Il modulo genera poi le route localizzate in fase di build, e `$localePath`, `<i18n-link>` e lo switcher le leggono.

## Le quattro strategie {#the-four-strategies}

![La pagina /about in en (predefinito) e de con ciascuna strategia; gli stessi URL sono elencati nel testo qui sotto](/images/diagrams/strategies.svg)

**Tipo** `Strategies` · **Predefinito** `'prefix_except_default'`

Strategia di routing degli URL per i prefissi di locale.

- `'no_prefix'` — nessun locale nell'URL; il locale è memorizzato in un cookie.
- `'prefix_except_default'` — prefisso per tutti i locale tranne quello predefinito.
- `'prefix'` — prefisso sempre, incluso il locale predefinito.
- `'prefix_and_default'` — come `prefix`, ma il locale predefinito è accessibile anche senza prefisso.

URL per una pagina `about` con `defaultLocale: 'en'` e locale `en`, `de`:

| Strategia | Inglese | Tedesco | Non servito |
| --- | --- | --- | --- |
| `prefix_except_default` (predefinita) | `/about` | `/de/about` | `/en` e `/en/about` restituiscono 404 |
| `prefix` | `/en/about` | `/de/about` | `/about` reindirizza a un URL con prefisso |
| `prefix_and_default` | `/about` e `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | il locale non è nell'URL |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

La strategia è fissata in fase di build: un suo override a runtime viene ignorato con un avviso ([Override a runtime](/it/guide/runtime-overrides)).

## Quale scegliere {#which-one-to-choose}

- **`prefix_except_default`**: la maggior parte dei siti. Gli URL esistenti senza prefisso continuano a funzionare per la lingua predefinita.
- **`prefix`**: tutte le lingue sono alla pari; `/` porta sempre a una home con prefisso.
- **`prefix_and_default`**: ti serve che funzionino sia `/en/...` sia gli URL senza prefisso, per esempio durante il passaggio dall'uno all'altro. Gli URL senza prefisso non vengono mai reindirizzati.
- **`no_prefix`**: app dietro un login, oppure un solo URL per pagina per tutte le lingue. Il locale proviene da un cookie o da `?locale=`. I motori di ricerca vedono una lingua per URL, quindi non vengono emesse alternative `hreflang`.

Come viene scelto il locale per un URL, e quando un visitatore viene reindirizzato, è spiegato in [Rilevamento del locale](/it/guide/locale-detection).

## Route generate {#generated-routes}

In fase di build ogni pagina riceve i record di route di cui la sua strategia ha bisogno. Ogni record contiene `meta.i18n = { name, locales }`: la pagina che mostra e i locale che serve. Link, cambi di lingua e reindirizzamenti vengono tutti risolti a partire da questi record, quindi un URL fornito dal modulo è sempre uno che il router serve.

I locale che condividono il percorso della pagina condividono un record, `/:locale(de|fr)/about`. Un locale con un proprio percorso ottiene un proprio record, chiamato `localized-<page>-<locale>`:

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

Percorsi personalizzati, elenchi di locale per pagina ed esclusione di una pagina dalla localizzazione sono trattati in [Percorsi localizzati](/it/guide/custom-locale-routes) e [Configurazione della pagina](/it/guide/per-component-translations). Il prefisso `localized-` è [`localizedRouteNamePrefix`](/it/api/module-options#localizedroutenameprefix).

<Warning>

**I nomi delle route sono generati** — Non scrivere a mano i nomi `localized-…` in `router.push({ name })`. Passa il nome proprio della pagina a `$localeRoute` o `<i18n-link>`; sceglieranno il record corretto.

</Warning>

## Creare un link a una pagina in un locale {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- Funzionano sia le route con nome sia i percorsi. Un percorso viene confrontato con le route generate, quindi è accettata la sua forma in qualsiasi locale.
- Un locale che non serve la pagina (vedi `locales` in [Configurazione della pagina](/it/guide/per-component-translations)) rimanda alla home di quel locale invece che a una pagina mancante.
- I parametri per locale (uno slug tradotto) passano per `$setI18nRouteParams`, vedi [Percorsi localizzati](/it/guide/custom-locale-routes).

Le firme si trovano in [Metodi](/it/api/methods).

## Dettagli di `no_prefix` {#no_prefix-details}

- [`localeCookie`](/it/api/module-options#localecookie) vale `'user-locale'` per impostazione predefinita con `no_prefix`, quindi la scelta sopravvive a un ricaricamento.
- `$switchLocale('de')` carica il dizionario tedesco e sostituisce la voce corrente della cronologia; l'URL non cambia.
- I percorsi personalizzati per locale funzionano comunque: con `globalLocaleRoutes: { about: { de: '/ueber-uns' } }`, i lettori tedeschi ottengono `/ueber-uns`. Quell'URL viene sempre renderizzato in tedesco, qualunque sia la preferenza del visitatore, e una pagina limitata ad alcuni locale viene renderizzata in uno di essi. Un percorso condiviso da più locale (`en` e `de` entrambi su `/page/:id`) viene renderizzato nella lingua preferita quando è una di queste. La preferenza stessa rimane: la pagina successiva vi ritorna.
- [`noPrefixRedirect: true`](/it/api/module-options#noprefixredirect) reindirizza il percorso originale di una pagina con un percorso personalizzato nel locale predefinito: al percorso personalizzato del locale del visitatore, altrimenti a quello del locale predefinito (`/about` → `/about-us` quando `en` ha `/about-us`, → `/ueber-uns` con cookie `de`). Un locale senza un proprio percorso personalizzato resta sul percorso originale e viene renderizzato lì. Le pagine con parametri non vengono reindirizzate.

## App senza `pages/` {#apps-without-pages}

Con `pages: false` non ci sono route di pagina da localizzare. Usa solo file di traduzione root (`disablePageLocales: true`); il rilevamento, il cookie e `$switchLocale` continuano a funzionare. La variante `pages-false` di `test/fixtures/basic` nel repository è una configurazione funzionante.
