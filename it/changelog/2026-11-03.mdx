**Data**: 2026-11-03

**Versione**: `v4.0.0`

![Rilascio v4.0.0](/images/4.0.0.png)

**v4.0.0** è disponibile. Routing, core delle traduzioni, file dei dizionari, rilevamento del locale e ogni pacchetto per framework sono stati riscritti. Opzioni, `$t`, `$localePath`, `$switchLocale`, i componenti e i composable mantengono i loro nomi. Ciò che cambia è il comportamento, e la maggior parte di questi cambiamenti sono bug che non ci sono più. La maggior parte delle app richiede poche modifiche al codice, ma leggi le [Modifiche incompatibili](#breaking-changes) prima di aggiornare: URL, tag SEO e API dei pacchetti per framework sono cambiati in alcuni punti. [Aggiornamento](/it/guide/upgrade) contiene ogni dettaglio.

## Cosa c'è di nuovo? {#what’s-new}

### Un'unica build per ogni dominio {#one-build-for-every-domain}

`locales[].baseUrl` e `baseDefault` in passato determinavano solo i link. Ora instradano anche le richieste, con tutte e quattro le strategie e in `nuxt generate`:

```ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'fr', baseUrl: 'https://example.com' },
      { code: 'de', baseUrl: 'https://example.de', baseDefault: true },
    ],
  },
})
```

- Un host serve i propri locale. I link al locale di un altro dominio diventano URL assoluti su quel dominio, e passare a quel locale porta lì.
- `trustForwardedHost` ricava il dominio da `X-Forwarded-Host` dietro un proxy che lo sovrascrive. Disattivato per impostazione predefinita.
- `NUXT_I18N_DOMAIN` fornisce a `nuxt generate` il suo host: eseguilo una volta per dominio, e ogni output contiene solo le pagine e i dizionari di quel dominio.
- Un'app senza `baseUrl` non include nulla di questo codice.

Vedi [Layer e domini](/it/guide/layers#multiple-domains) e [Deployment](/it/guide/deployment).

### Un routing che concorda con il router {#routing-that-agrees-with-the-router}

La build e il runtime non calcolano più separatamente gli URL localizzati. Ogni risposta proviene dalle route generate dalla build, così un link, uno switcher, `hreflang` e un redirect non possono puntare a una pagina che non esiste.

- Un locale che non serve una pagina rimanda alla propria home, mai alla pagina di un altro locale.
- `hreflang` elenca solo i locale che servono la pagina.
- `$switchLocale` si risolve in `true` o `false`, così puoi sapere quando il caricamento di un dizionario è fallito. Una chiamata ripetuta riprova.
- `$setI18nRouteParams` e `useI18nHead` impostati durante l'SSR sopravvivono all'idratazione. Lo switcher rimanda allo slug tradotto, anche nell'HTML del server.
- Una navigazione ha effetto quando viene confermata: una annullata o bloccata non cambia nulla.
- La modalità hash funziona con `prefix`.
- `<Greeting :locale="$getLocale()" />` su un server component imposta il suo locale di rendering.

### Un unico rilevamento del locale {#one-locale-detection}

Un solo ordine ovunque: sul server, nel browser, negli helper delle API server e in Astro. `Accept-Language` rispetta i valori `q`, la corrispondenza regionale non dipende più dall'ordine di `locales`, e non mescola mai le scritture cinesi. Gli override a runtime ora raggiungono il routing: `NUXT_I18N_DEFAULT_LOCALE` e i `disabledLocales` a runtime cambiano ciò che viene effettivamente servito. Vedi [Rilevamento del locale](/it/guide/locale-detection).

### Un unico dizionario in ogni modalità {#one-dictionary-in-every-mode}

Le build premerged, `mode: 'source'` e lo sviluppo davano risultati diversi su molte pagine. Ora forniscono lo stesso dizionario.

- Le unioni sono profonde a ogni livello, e le catene di fallback (`fr` → `de` → `en`) vengono seguite fino in fondo.
- Le modifiche alle traduzioni in sviluppo si applicano sul posto, senza ricaricare la pagina. Le chiavi rimosse scompaiono, e la modifica di un file root raggiunge ogni pagina.
- `$clearCache()` ricarica la pagina corrente e mantiene il vecchio testo sullo schermo finché non arriva quello nuovo.
- Un chunk fallito mantiene il dizionario corrente invece di mostrare le chiavi grezze.

### File dei dizionari più piccoli {#smaller-dictionary-files}

- Il file di una pagina ora contiene solo ciò che differisce dalla root del locale, in `__root/<locale>/data.json`. Il browser carica la root una volta e unisce ogni pagina sopra di essa, così l'uso del disco diminuisce e la pagina successiva costa una frazione della prima.
- Gli URL dei dizionari includono una versione. Un URL con il `?v=` corrente viene fissato per un anno su un server Node, e la copia statica di un host risponde `max-age=60`. Vedi [Header di cache](/it/guide/deployment#cache-headers-and-datebuild).
- Ogni pagina SSR precarica i propri file di dizionario, così partono insieme all'HTML.
- Una lettura fallita non resta più bloccata: la richiesta successiva legge di nuovo. Vedi [Quando un dizionario non può essere letto](/it/guide/deployment#when-a-dictionary-cannot-be-read).

### `<i18n-t>`, plurali e formati migliorati {#better-&lt;i18n-t&gt;-plurals-and-formats}

- Gli slot funzionano con `plural`, `number`, `date` e `relativeDate`, e ogni `{name}` viene riempito, non solo il primo.
- `<i18n-t>` è un unico renderer per Nuxt, Vue, React, Preact, Solid e Astro.
- Una prima forma che inizia con `=0 ` è una forma zero esplicita, e le altre seguono `Intl.PluralRules`: `=0 no apples | one apple | {count} apples`. Vedi [`$tc`](/it/api/methods#$tc).
- Nuova opzione `timeZone`: un'unica data di calendario sul server e in ogni browser.
- `{firstName}`, `{first-name}` e `{user.name}` sono segnaposto validi.
- `$tn`, `$td` e `$tdr` seguono `iso`, come fanno i plurali.
- `$tdr` restituisce vere date future: `in 3 days`, oppure `tomorrow` con `numeric: 'auto'`.

### Più sicuro per impostazione predefinita {#safer-by-default}

- `<i18n-t html>` esegue l'escape dei `params`. Solo la traduzione è markup considerato affidabile.
- Nessun link lascia l'origine per errore: `//host`, `/\host` e i valori vuoti restano su questo sito.
- La cache delle traduzioni del server è limitata, così URL con nomi di pagina inventati non possono far crescere la memoria.
- Gli endpoint di salvataggio dei DevTools accettano solo file `.json` esistenti all'interno delle tue directory di traduzione, e rifiutano le richieste cross-site.

### Pacchetti per framework alla 2.0 {#framework-packages-at-2-0}

- **React, Preact, Solid:** `I18nT` accetta una prop `components` per il rich text. Nuovi `useT` e `useLocaleSwitch`, e supporto ai React Server Components tramite `@i18n-micro/react/server` e `/client`. Preact non ha più bisogno di `preact/compat`.
- **Vue e VitePress:** `I18nLink` mantiene `name`, `query` e `hash`, e VitePress rispetta `base`.
- **Astro:** `i18nIntegration` include i tuoi dizionari nel bundle e installa il middleware. L'entry principale non ha import `node:*`, quindi funziona sull'edge. `base` funziona.
- **Node e runtime:** `fork(locale)` fornisce un'istanza per richiesta economica, e `run(locale, fn)` su `@i18n-micro/node` ne limita una a una richiesta.
- **`@i18n-micro/types-generator`:** nessuna dipendenza di terze parti, e un semplice plugin Vite e Rollup.
- **`@i18n-micro/devtools-ui`:** aggiornamenti in tempo reale tramite il socket di Vite, e un'app per la toolbar di Astro.

### `@i18n-micro/cli` {#@i18n-micro/cli}

La CLI ora vive nel monorepo come `@i18n-micro/cli`, riscritta con 16 comandi invece di 28 e molte meno dipendenze. `check` sostituisce `validate`, `diff` e `check-duplicates`, con `--json` e codici di uscita per la CI. Quando non può dimostrare che una chiave è inutilizzata, `clean` non scrive nulla. Vedi [CLI](/it/guide/cli).

### Documentazione {#documentation}

La documentazione è stata riscritta a partire dal codice attorno a un unico percorso di lettura: installazione, prima pagina tradotta, file di traduzione, routing, rilevamento, poi guide per attività. I vecchi URL vengono reindirizzati. [Aggiornamento](/it/guide/upgrade) elenca ogni modifica in dettaglio.

## Velocità e dimensioni {#speed-and-size}

- Un render lato server legge direttamente i dizionari, senza richieste HTTP locali e senza nuovo parsing.
- `dir="auto"` non è più il valore predefinito. I browser impiegano molto tempo per elaborarlo su pagine grandi: con 20.000 elementi `$t`, il DOMContentLoaded in Chromium è passato da circa 980 ms a circa 115 ms.
- `serverTranslationPreload` e `i18n:register` non rallentano più ogni richiesta.
- Il bundle client elimina `useCookie` quando non è configurato alcun cookie, e `@i18n-micro/path-strategy` ha una frazione della sua vecchia dimensione.

**App di test rispetto a v3.30.3.** Un'app Nuxt generata su un unico server Node, su un unico Mac, `wrk` con 24 connessioni per 20 s, tre round a rotazione, su una build pre-release. Le righe provengono da esecuzioni separate, quindi confronta i valori all'interno di una riga. L'idratazione usa `dir: 'ltr'` da entrambe le parti.

React, Preact e Solid includono anche il renderer condiviso del rich text.

## Modifiche incompatibili {#breaking-changes}

### Requisiti {#requirements}

- **Nuxt 3.18 o successivo**, e **Node 20 o successivo**.
- **`@i18n-micro/test-utils`** non viene più installato con il modulo. Aggiungilo tu se i tuoi test lo importano.
- **`@i18n-micro/hmr`** non esiste più: l'HMR delle traduzioni è integrato. Rimuovi il pacchetto se lo avevi installato.
- **`@i18n-micro/react`** richiede React 18 o successivo.
- **`nuxt-i18n-micro-cli`** è sostituito da `@i18n-micro/cli`.

### Opzioni e configurazione {#options-and-config}

- `i18n-plugin-hooks` e `i18n-plugin-define` in un `dependsOn` non attendono più nulla, senza errori. Usa `i18n-plugin-loader`.
- Gli auto-import lato server sono `useLocaleServerMiddleware`, `useTranslationServerMiddleware`, `loadTranslationsFromServer` e `detectCurrentLocale`. Gli altri non vengono più importati automaticamente.
- `resolveTranslationPayloadMode` e gli altri helper `resolveTranslationPayload*` sono stati rimossi da `nuxt-i18n-micro`, insieme a `shouldCopyTranslationPayloadsToPublic` e `shouldRegisterNitroServerAssets`. Il tipo `TranslationPayloadMode` resta.
- `$getI18nConfig()` non ha più `isSSG`, `hmr`, `hooks`, `noPrefixRedirect`, `routeLocales`, `routeDisableMeta` o `globalLocaleRoutes`. Le opzioni stesse sono invariate.
- `locales[].baseUrl` ora instrada le richieste: un locale di un altro dominio restituisce 404 su questo host, e i link sullo stesso host sono relativi. In una build di questo tipo `$getI18nConfig().locales` contiene ciò che l'host serve, e `linkLocales` li contiene tutti.
- `baseUrl` imposta l'origine anche su qualsiasi altro host: canonical e `hreflang` usano `metaBaseUrl` se impostato, altrimenti il `baseUrl` del locale predefinito, non l'origine della richiesta.
- `excludePatterns` corrispondono a segmenti interi (`'/admin'` non corrisponde più a `/administrator`), i glob sono ancorati, e i pattern `RegExp` ora raggiungono il runtime.
- `cacheMaxSize` non impostato significa al massimo 1000 voci sul server. `cacheTtl` conta dal momento in cui una voce è stata memorizzata, e le letture non lo estendono più.
- Con `no_prefix` un `localeCookie: null` esplicito nella configurazione `i18n` resta disattivato.
- Con `prefix_except_default` e `prefix_and_default` un `defaultLocale` a runtime viene ignorato con un avviso. Un `fallbackLocale` a runtime deve essere un locale abilitato.
- `routeDisableMeta` in `nuxt.config` viene rispettato, e una voce di `nuxt.config` prevale su `$defineI18nRoute` con qualsiasi forma di chiave.
- Su un server in sviluppo, la configurazione risolta è congelata: una scrittura su di essa lancia un'eccezione.
- La voce `locales` di un progetto prevale su quella di un layer per lo stesso `code`.

### Composable e metodi `$` {#composables-and-$-methods}

- `$switchLocale` si risolve in `true` o `false`, prima non si risolveva in nulla. `$switchRoute` è tipizzato `Promise<void>`.
- `$localeRoute`, `$switchLocalePath` e lo switcher collegano un locale che non serve una pagina alla home di quel locale.
- `$localePath` restituisce così com'è una stringa con uno schema `http(s):`, `mailto:` o `tel:`, e `$localeRoute` la riporta in `path` e `fullPath`. Non passare loro un valore non verificato come destinazione di un link. `//host` e nomi semplici come `x.com` restano percorsi su questa origine.
- Un link senza percorso resta sulla pagina corrente: `$localePath('#top')`, `'?p=2'`, `''` e `{ query }`. `'#top'` prima veniva letto dalla root del sito. Un semplice `'about'` significa ancora `/about`.
- `$switchRoute` resta nell'app. Solo il `baseUrl` proprio di un locale, `mailto:` e `tel:` ne escono.
- Un link a un locale con un `baseUrl` passa per `$localePath` o `<i18n-link>`. `<NuxtLink :to="$localeRoute(x, 'fr')">` e `router.push($localeRoute(x, 'fr'))` restano percorsi di questa app. Nel codice usa `navigateTo($localePath(x, 'fr'), { external: true })`.
- `$switchLocaleRoute` e i redirect seguono `trailingSlash`.
- `$setI18nRouteParams` e `useI18nHead` impostati sul server vengono scartati quando una navigazione cambia il percorso, anche da `/news/1` a `/news/4`: impostali di nuovo nella nuova pagina.
- `$setI18nRouteParams` letto nel setup è legato a quella pagina: una chiamata tardiva da una pagina già lasciata non fa nulla. Non ha un setter, quindi nei test fai lo stub di `useI18n` stesso.
- `useI18n()` restituisce un unico oggetto per app. Scrivere su di esso raggiunge ogni chiamante.
- Dizionario, locale, parametri e head cambiano quando una navigazione viene confermata. Un `beforeResolve`, un `beforeRouteEnter` o una guard globale successiva vede quelli vecchi. Il route middleware non è interessato.
- `$switchLocale` ripristina il locale memorizzato quando la sua navigazione viene annullata, con le strategie basate sull'URL.
- `$t` interpola un `defaultValue`: `$t('missing', { n: 1 }, 'Got {n}')` restituisce `Got 1`. Lo fa anche `$tc`, e su una traduzione vuota risponde `''`.
- `$has(key, route)` rispetta la route.
- `$clearCache()` ricarica il dizionario della pagina corrente.
- Un segnaposto `{param}` legge solo i parametri che passi: `{constructor}` resta com'è scritto.
- `$tc` con un conteggio negativo, frazionario o enorme prende l'ultima forma con il conteggio reale. `{ count: null }` non lancia più eccezioni, e una chiave plurale mancante raggiunge il missing handler.
- `$tdr` restituisce `Invalid Date` per un input non valido. Meno di un secondo nel passato dà `0 seconds ago`.
- `$tn`, `$td` e `$tdr` si basano su `iso`: `{ code: 'en', iso: 'en-GB' }` formatta le date come `31/10/2026`. Un codice che `Intl` non conosce viene formattato come `en`, e i plurali seguono la regola dell'indice: imposta `iso` (`{ code: 'ua', iso: 'uk-UA' }`).
- `detectCurrentLocale` è deprecato: usa `useLocaleServerMiddleware(event).current`.

### Plurali {#plurals}

I template mantengono il loro significato, con un'eccezione. Una forma zero senza segnaposto, seguita da una forma per categoria, con `{count}` in ogni forma condivisa da più conteggi, ora segue le categorie nei locale con tre o più categorie (`ru`, `uk`, `pl`, `cs`, `ar` e altri): `none | {count} one | {count} few | {count} many` restituisce `3 few` e `21 one` in `uk`. Per usare le categorie in qualsiasi altro template, aggiungi il marcatore `=0 `. Una regola `plural` personalizzata legge il valore grezzo, quindi un template marcato le arriva con `=0 ` al suo posto. Vedi [la tabella in Aggiornamento](/it/guide/upgrade#plurals-and-formatting).

### Componenti {#components}

**`<i18n-t>`**

- `html` esegue l'escape dei `params` in ogni caso e ignora tutti gli slot.
- Uno slot prevale su un param con lo stesso nome.
- `null` significa non impostato per `plural`, `number`, `date` e `relativeDate`.
- `plural` conta come `$tc`, con `Number`: `1.5` resta `1.5`, `"2 items"` è `NaN`, `""` è `0`.
- `number`, `date` e `relativeDate` mantengono i `params`.
- `hideIfEmpty` si applica in ogni ramo, e `defaultValue` sostituisce una chiave mancante in ogni ramo.
- Una chiave mancante con `html` è testo con escape.
- L'output di `date` e `relativeDate` include `data-allow-mismatch="text"`, e accanto a uno slot con nome il testo si trova in un proprio `<span>`.
- Gli attributi `.innerHTML` e `textContent` vengono scartati.
- È un componente funzionale: un `ref` su di esso non fornisce alcuna istanza.
- `<i18n-t>` e `<i18n-group>` leggono il dizionario attivo, come fa `$t`.

**`<i18n-switcher>`**

- Un link è un semplice `<a>` che chiama `$switchLocale`, quindi le classi `router-link-active` non ci sono più.
- Il pulsante è `type="button"` con `aria-expanded`. Esc e un clic all'esterno chiudono il dropdown.
- Nuove classi `i18n-switcher-wrapper`, `i18n-switcher-dropdown` e `i18n-switcher-button`. Ogni link ha `lang`, e `dir` quando il locale lo imposta.
- Gli stili predefiniti usano proprietà CSS logiche, e il dropdown ha uno `z-index` più alto, una larghezza minima e un'ombra.
- Il server riscrive i suoi link al termine del render, nelle pagine con parametri. Un link `$switchLocalePath` scritto a mano non viene riscritto.

**`<i18n-link>`**

- `https://`, `mailto:` e `tel:` corrispondono indipendentemente da maiuscole e minuscole. Un semplice `report.pdf` è una route, e `example.com` resta esterno. Un'estensione di file che è anche un TLD (`example.md`) conta come file: scrivi `https://`.
- `activeStyle` ignora lo slash finale, la query e l'hash.

### Hook e tipi {#hooks-and-types}

- `i18n:register` è un hook di runtime: `nuxtApp.hook('i18n:register', …)` in un plugin.
- Il tipo esportato `ModuleHooks` è rinominato in `ModuleRuntimeHooks`.
- `i18n:beforeLocaleSwitch` e `i18n:afterLocaleSwitch` non sono mai stati emessi e non sono più documentati.
- `ModuleOptionsExtend.isSSG` è opzionale e deprecato: nulla lo imposta.

### URL e redirect {#urls-and-redirects}

- **`/en` e `/en/...` restituiscono 404** con `prefix_except_default`, con `en` come predefinito.
- **Un prefisso di locale con maiuscole/minuscole o grafia diverse restituisce 404** (`/DE/about`). Lo stesso vale per `/DE/x` sotto `[...slug]` e per `/DE` accanto a `[slug]`, quindi uno slug del CMS uguale a un codice di locale con maiuscole/minuscole diverse perde la sua pagina.
- **Un URL sconosciuto resta un 404** con `autoDetectPath: '*'` o `'no_prefix'`. `prefix` mantiene il redirect, così come `/` ovunque.
- **Il percorso personalizzato di un altro locale, senza prefisso,** è un `302` verso l'URL del locale predefinito con `prefix_except_default`. Con `prefix` il redirect ora raggiunge una pagina esistente. `prefix_and_default` resta un 404.
- **`prefix` con `redirects: false`** risponde 404 su un URL senza prefisso, compreso l'URL originale di una pagina con un percorso predefinito personalizzato.
- **`autoDetectPath: '*'`** applica il cookie e `Accept-Language` anche ai percorsi senza prefisso.
- **Con `prefix`** un URL senza prefisso mantiene il locale del visitatore, su ogni percorso, qualunque cosa dica `autoDetectPath`.
- **Con `prefix_and_default`** un URL senza prefisso corrisponde al locale predefinito.
- **Con `no_prefix`** un percorso personalizzato renderizza il proprio locale, una pagina con restrizioni viene renderizzata in un locale che serve, e i locale che condividono un percorso condividono un unico record.
- **Un redirect di `routeRules` senza pagina** non viene localizzato: `/de/old` restituisce 404, prima era un 200 vuoto.
- **Le route rule raggiungono i percorsi personalizzati,** e vengono copiate anche con `no_prefix`. Un fratello statico come `/de/artikel/news` corrisponde a `/de/artikel/:slug`.
- **Un locale con `disabled: true`** risponde subito 404 sul proprio prefisso, e i link verso di esso restano sulla pagina.
- **Il percorso di una pagina con maiuscole/minuscole diverse** è un `302` verso la propria grafia: `/T/BASIC` va a `/t/basic`.
- **L'URL originale di una pagina con un percorso predefinito personalizzato** è un `302` verso quel percorso con `prefix_except_default`. Prima era un 404.
- **`noPrefixRedirect`** si basa sul locale del visitatore: con il cookie `de`, `/about` va a `/ueber-uns`, non al percorso del locale predefinito.
- **Il prefisso proprio di un host** restituisce 404 sul suo host `baseDefault` con `prefix_except_default`: `/de/x` sull'host `de` era un 200.
- **`customRegexMatcher`** non restituisce più 404 per una pagina reale il cui primo segmento sembra un locale.
- **`nuxi generate`** prerenderizza ogni pagina statica in ciascun locale che la serve, a meno che una route rule imposti `prerender: false`: più file nell'output. Con `baseUrl`, eseguilo una volta per dominio con `NUXT_I18N_DOMAIN`.
- **Un redirect lato client mantiene la modalità della sua navigazione:** un semplice `<NuxtLink>` aggiunge una voce alla cronologia.
- **I nomi delle route localizzate sono coerenti.** È interessato solo il codice che inserisce a mano nomi `localized-…` in `router.push({ name })`: passa il nome proprio della pagina a `$localeRoute`.
- **Le pagine senza nome da `extendPages`** vengono localizzate e ricevono un nome.
- **Con `prefix`, un link verso un altro dominio** mantiene il prefisso del locale.
- **La home di un dominio** viene scritta senza slash finale ovunque.
- **`?locale=`** conta sulle pagine solo con `no_prefix`. `/about?locale=de` non renderizza più in tedesco sotto `lang="en"`.
- **Un `setLocale('de')` di un plugin** su `/en/...` non carica più il dizionario `de`.

### SEO e output HTML {#seo-and-html-output}

- `dir="auto"` non è più il valore predefinito. Una lingua RTL nota riceve `dir="rtl"`, e qualsiasi altro locale senza `dir` non riceve alcun attributo. Per mantenere il vecchio output imposta `dir: 'auto'`, a costo di un parsing più lento su pagine grandi. Vedi [Direzione del testo](/it/guide/seo#text-direction).
- `disableMeta` ora funziona: la pagina non ha `hreflang`, canonical né `og:locale`. `lang` e `dir` restano.
- `hreflang` elenca solo i locale che servono la pagina. `x-default` compare solo quando il locale predefinito la serve.
- Una pagina non localizzata non ha `hreflang` né `og:locale:alternate`.
- Le pagine 404 includono `<html lang dir>` nel locale dell'URL, e nessun canonical né `hreflang`.
- Canonical, `og:url` e `hreflang` mantengono una query in whitelist (`/about?page=2`), anche sul server.
- Canonical e `hreflang` includono `app.baseURL` quando l'origine proviene dalla richiesta.
- Ogni pagina SSR ha `<link rel="preload" as="fetch" crossorigin="anonymous">` per i propri file di dizionario, anche le pagine 404. Consentilo in una CSP restrittiva. Con `apiBaseClientHost` quell'host necessita di CORS.
- `Vary` viene impostato su ogni pagina con `no_prefix`, e sui redirect di locale delle altre strategie. Controlla la chiave di cache della tua CDN.
- Il cookie del locale viene scritto solo da una pagina servita.

### Rilevamento e server {#detection-and-server}

- `Accept-Language` rispetta i valori `q`, e `q=0` esclude una lingua.
- `useLocaleServerMiddleware` e `useTranslationServerMiddleware` usano un solo ordine su ogni route (`?locale`, parametro `[locale]` o prefisso, cookie, header, predefinito), rispettano `localeCookie: null` e `autoDetectLanguage: false`, e mettono in cache un dizionario per locale.
- Un cookie del locale malformato viene ignorato e lasciato com'è, invece di far fallire l'SSR.
- La modalità hash legge solo il cookie `hash-locale`. Un `user-locale=de` da solo non conta più.
- `NUXT_I18N_DEFAULT_LOCALE` e i `disabledLocales` a runtime cambiano il routing.
- **L'output `premerged` è cambiato.** `/{apiBaseUrl}/<page>/<locale>/data.json` contiene solo ciò che differisce da `__root/<locale>/data.json`. Qualsiasi cosa legga direttamente quei file deve unire i due. Un dizionario completo resta un file valido.
- **I dizionari seguono `app.cdnURL`.** Il browser li scarica da `<cdnURL>/_locales/...`, dove prima usava `app.baseURL`. La CDN deve contenere `_locales/` e consentire l'origine del tuo sito. Vedi [App baseURL e host dei payload](/it/guide/deployment#app-baseurl-and-payload-hosts).
- Nessuna cache delle route di Nitro su `/{apiBaseUrl}/**`, e l'header `s-maxage=60, stale-while-revalidate` non c'è più. Se ti affidavi a quella cache, metti una CDN davanti alla route dei payload.
- `/{apiBaseUrl}/<page without a folder>/<locale>/data.json` risponde con il dizionario root, prima era `{}`. Un 404 di un host ora passa come 404, mentre prima rispondeva `200 {}`.
- Un prerender che non riesce a caricare il proprio dizionario fallisce con un 500 e un avviso, e con il `failOnError` predefinito di Nuxt la build termina con 1.
- Una traduzione modificata senza ricompilare raggiunge un browser solo quando `v` cambia: imposta `NUXT_I18N_DATE_BUILD`.
- L'SSR non richiede più `/{apiBaseUrl}` via HTTP, a meno che non sia impostato `apiBaseServerHost`.

### Traduzioni {#translations}

- Le unioni sono profonde a ogni livello, e le catene di fallback vengono seguite fino in fondo.
- L'unione avviene per locale: il file root del locale attivo prevale sul file di pagina di un locale di fallback.
- Una pagina senza una propria cartella `pages/<name>/` legge il dizionario root in produzione. Prima riceveva `{}`.
- `disablePageLocales: true` legge solo i file root.
- Le chiavi della pagina in uscita smettono di essere risolte dopo la navigazione. Se un layout usava chiavi presenti solo nel file della pagina precedente, spostale nel file root.
- Un file di locale corrotto genera un solo avviso con il suo percorso in ogni modalità. In sviluppo prima lanciava un'eccezione.

### Pacchetti `@i18n-micro/*` {#@i18n-micro/*-packages}

Ogni pacchetto `@i18n-micro/*` è alla versione 2.0.0, compresi `@i18n-micro/types` e il nuovo `@i18n-micro/cli`.

**`@i18n-micro/react`, `preact`, `solid`**

- Gli adapter del router sono stati spostati in `/router`: `createReactRouterAdapter`, `createSolidRouterAdapter` e `createBrowserHistoryAdapter` di Preact. `createPreactRouterAdapter` è stato rimosso.
- `I18nT` segue `<i18n-t>` descritto sopra. Gli attributi `dangerouslySetInnerHTML`, `innerHTML` e `textContent` vengono scartati.
- `I18nSwitcher` renderizza elementi `<a href>` con `aria-current="page"`, `▾`, CSS logico e `language-switcher` sul pulsante. Nessun `aria-haspopup`. `className` si aggiunge a `i18n-switcher-wrapper`.
- Un link a `/` o alla root di un locale è attivo solo in caso di corrispondenza esatta (React, Preact).
- `I18nLink` mantiene `onClick` e `style` dell'utente, e lascia al browser un clic con modificatori. Query e hash non contano per il controllo dello stato attivo. Senza un router, nessun link è attivo.
- React e Preact: `I18nLocalesContext`, `I18nDefaultLocaleContext` e `I18nRouterContext` sono un unico `I18nConfigContext`. Solid: un unico `I18nContext` contiene `{ i18n, locales, defaultLocale, router }`.
- `getCurrentPath` degli adapter include query e hash, e una chiave ripetuta in `getRoute().query` è un array.
- Un `I18nProvider` annidato senza `i18n` mantiene l'istanza esterna, e un provider senza alcuna istanza lancia un'eccezione.
- `defaultLocale()` senza valore è `fallbackLocale`.
- Solid: `getCurrentPathAccessor` è stato rimosso. `useI18n()` non lancia più eccezioni senza `locales`.
- React: `use-sync-external-store` non è più una dipendenza, e `react-dom` è una peer opzionale.

**`@i18n-micro/vue`, `vitepress`**

- `I18nT` è un componente funzionale.
- `I18nSwitcher` e `I18nLink` seguono le sezioni precedenti. `aria-haspopup` non c'è più.
- `I18nLink` e `createVueRouterAdapter` risolvono `name`, `query` e `hash`. Un `name` sconosciuto lancia un'eccezione, come fa `RouterLink`.
- `useLocaleHead` non costruisce più `//de/`. Canonical e `hreflang` di una stessa pagina concordano (`/de`), e i parametri di query in whitelist li raggiungono.
- `I18nRoutingStrategy.resolvePath` può ricevere un oggetto location e un percorso con query e hash. Nuovo `toHref` opzionale.
- VitePress: link, switcher, `push` e `replace` includono `site.base`.

**`@i18n-micro/astro`**

- `i18nIntegration` include `translationDir` nel bundle e installa il middleware: elimina un `src/middleware.ts` che si limita a copiare la configurazione, oppure passa `middleware: false`. Un tuo `src/middleware.ts` passa `base: config.base`.
- `i18nIntegration` lancia un'eccezione con `messages`, `plural`, `missingHandler` e `routingStrategy`: passali a `createI18n` o `createI18nMiddleware`, con `middleware: false`. Le opzioni che non hanno mai fatto nulla sono state tolte dal suo tipo.
- `loadTranslationsFromDir` e `loadTranslationsIntoI18n` sono stati spostati in `@i18n-micro/astro/node`, che è solo ESM.
- `getGlobalRoutingStrategy`, `setGlobalRoutingStrategy` e `runWithRoutingStrategy` sono stati rimossi: leggi `Astro.locals.routingStrategy`.
- `clone()` è diventato `fork()`, e l'opzione `_storage` non c'è più.
- Le pagine dinamiche sono un'unica route: `/blog/hello` è `blog-slug`, prima era `blog-hello`. Sposta `pages/blog-hello/` in `pages/blog-slug/`. Un `getRouteName` personalizzato riceve il pattern come terzo argomento.
- L'URL decide il locale della pagina. `autoDetect` è un 302 da `/` alla home del locale preferito. Nuova opzione `localeCookie`, e `redirectToDefault` è implementato.
- La visualizzazione di una pagina provenendo da una pagina della stessa origine in un altro locale scrive il cookie del locale e non reindirizza. Server island e action non reindirizzano mai e includono `Vary: Referer`.
- `config.localeCodes` esclude i locale disabilitati, e `prepareLocaleRewrite` risponde 404 per essi.
- `getI18nProps()` senza chiavi invia tutto ciò a cui `t()` può rispondere nella pagina, con un avviso in sviluppo oltre i 20 KB. Passa le chiavi usate dall'island.
- `useLocaleHead`: il `baseUrl` predefinito è `site`, altrimenti relativo alla root. Link e meta includono `id`.
- `<I18nT html>` esegue l'escape dei `params`, e una traduzione vuota viene renderizzata vuota.
- `<I18nLink>` e `localizePath` lasciano invariati gli URL esterni, `#hash` e `?query` e mantengono lo slash finale.
- `<I18nSwitcher>` mantiene la query e usa `data-i18n-switcher` invece di id generati.
- `@i18n-micro/astro/client` ha solo `translate` e `hasTranslation`: importa gli adapter da `/client/vue`, `/client/react`, `/client/preact` e `/client/svelte`. `client/vue` richiede che `vue` sia installato.
- Island: `has()` è true per un sottoalbero, `t('')` è `''`. `provideI18n` accetta un getter per seguire le nuove props.
- `getLocale` e `getDefaultLocale` lanciano un'eccezione senza il middleware.

**`@i18n-micro/runtime`, `node`**

- Una scrittura su un locale che non è né attivo né di fallback non notifica i subscriber.
- `addRouteTranslations(locale, route, messages, false)` sostituisce il chunk.
- `loadFromUrls` scarica in parallelo e non scrive nulla se uno fallisce.
- Node: `reload()` scambia i dizionari invece di svuotarli prima, e non registra alcun messaggio di successo. Una directory che non esiste più mantiene quelli vecchi.
- Node, Astro, VitePress: un unico lettore di una cartella dei locale. Una cartella mancante genera un avviso, un file che non è un oggetto JSON viene segnalato e saltato, e i messaggi iniziano con `[i18n]`.

**`@i18n-micro/test-utils`**

- Il mock segue le vere regole di traduzione: `tc('a', 1.5)` prende l'ultima forma, `td('nope')` è `Invalid Date`, `t(miss, undefined, '')` è la chiave, e una chiave mancante non viene più registrata nel log.
- `isolated` non c'è più in `createI18nTestContext`, e `./publish-smoke` è stato rimosso.

**`@i18n-micro/types-generator`**

- `I18nTypesPlugin(options)` è un semplice plugin Vite e Rollup: niente `.vite()`, `.webpack()` o `.esbuild()`. Per webpack o esbuild, chiama `generateTypes` in uno script.
- `getTypesString` e `generateTypes` sono sincroni. `flattenKeys` e `isPlainTranslationObject` sono stati rimossi.
- Le chiavi sono ciò che `t()` legge: vengono aggiunti i percorsi degli oggetti, e i file esterni alla struttura dei locale vengono scartati.

**`@i18n-micro/devtools-ui`**

- Il salvataggio accetta solo un `.json` esistente all'interno di `translationDir`, e non crea più file. Una richiesta cross-site riceve un 403.
- Un salvataggio fallito verso un endpoint raggiungibile lancia un'eccezione ed esegue il rollback.
- `createBridge` accetta un'opzione `base`. Astro usa `i18nDevToolsIntegration`.

**`@i18n-micro/utils`, `core`, `path-strategy`, `route-strategy`**

Solo per adapter personalizzati e strumenti.

- `utils`: i subpath `./route`, `./route-pattern`, `./build`, `./payload-stats` e `./payload-config` sono stati rimossi, insieme a `resolveServerLocale` e `resolvePreferredLocale`: chiama `resolveLocale`. `deepMergeTranslations` e `mergeRouteTranslationsWithRoot` non ci sono più: usa `deepMergeTranslationsRecursive`.
- `core`: `TranslationHelper` elimina `setCache`, `getGeneration` e `lookupIn` (usa `lookup(chunkKey, key)`). `BaseI18n` elimina `ensurePinnedChunk` e `invalidatePin`. `useTranslationHelper(storage)` non c'è più: usa `new TranslationHelper(storage)`.
- `path-strategy`: **`switchLocaleRoute(fromLocale, toLocale, route, options)` ora è `switchLocaleRoute(toLocale, route, options)`. Una vecchia chiamata JavaScript restituisce un risultato errato senza alcun errore.** `$switchLocaleRoute` di Nuxt non è interessato. Le entry `/prefix`, `/no-prefix`, `/prefix-except-default` e `/prefix-and-default` non ci sono più, così come `getRedirect` e `getCanonicalPath`. `RouterAdapter` richiede `getRoutes`. `createPathStrategy` non costruisce URL assoluti: usa `new DomainPathStrategy(ctx)` quando i locale hanno `baseUrl`.
- `route-strategy`: vengono esportati solo `RouteGenerator`, `generateRoutes`, `Rules` e gli helper dei percorsi.

## Migrazione {#migration}

1. Verifica i requisiti: Nuxt 3.18, Node 20, e React 18 se usi `@i18n-micro/react`.
2. Aggiorna `nuxt-i18n-micro` e ogni pacchetto `@i18n-micro/*` insieme. Rimuovi `@i18n-micro/hmr`. Aggiungi `@i18n-micro/test-utils` come dipendenza di sviluppo se i tuoi test lo importano. Sostituisci `nuxt-i18n-micro-cli` con `@i18n-micro/cli` e segui [la sua tabella dei comandi](/it/guide/cli#moving-from-nuxt-i18n-micro-cli).
3. Cerca nel tuo codice `switchLocaleRoute(` da `@i18n-micro/path-strategy`, `i18n-plugin-hooks`, `i18n-plugin-define`, i nomi di route `localized-`, `$getI18nConfig().globalLocaleRoutes` e le altre chiavi di configurazione rimosse, `ModuleHooks`, e `@ts-expect-error` su `i18n:register`.
4. Sposta il markup dai params di `<i18n-t html>` nella traduzione, e passa i dati come params.
5. Se imposti `baseUrl`: rivedi i link costruiti con `$localeRoute`, imposta `trustForwardedHost` dietro un proxy, ed esegui `nuxi generate` una volta per dominio con `NUXT_I18N_DOMAIN`.
6. Verifica i tuoi URL rispetto alla tua strategia: `/en` con `prefix_except_default`, slug del CMS simili a locale, redirect di `routeRules`, ed `excludePatterns`.
7. Controlla la chiave di cache della tua CDN per `Vary`, e consenti il link di preload in una CSP restrittiva. Con `app.cdnURL`, metti `_locales/` sulla CDN e consenti CORS.
8. Se uno strumento legge direttamente i file `/_locales/...`, unisci il file di pagina sopra `__root/<locale>/data.json`.
9. Se una guard globale legge il locale o il dizionario, verifica che possa essere eseguita prima che la navigazione venga confermata. Sposta nel file root le chiavi che un layout prendeva dal file della pagina precedente.
10. Confronta un output di `nuxi generate` o una scansione della sitemap prima e dopo: `hreflang`, `x-default`, canonical e l'elenco delle pagine cambiano per scelta progettuale.
11. Aggiorna gli import dei pacchetti per framework: `/router` per gli adapter di React, Solid e Preact, `/node` per i loader di Astro, e `I18nTypesPlugin(o)` per il plugin dei tipi.
12. Per Astro, elimina un `src/middleware.ts` che si limita a copiare la configurazione, e rinomina i dizionari in stile `pages/blog-hello/` secondo il loro pattern.
13. Aggiorna i test che fissavano `router-link-active`, `li button`, `▼`, o il vecchio comportamento del mock.

Dettagli e ogni caso limite: [Aggiornamento](/it/guide/upgrade).

## Perché è importante {#why-it-matters}

- **Corretto per costruzione:** link, redirect e tag SEO derivano dalle route che l'app ha davvero.
- **Un'unica risposta ovunque:** una build, la modalità source e lo sviluppo forniscono lo stesso dizionario, e ogni chiamante usa un unico ordine di rilevamento.
- **Domini:** un unico deployment per ogni dominio di locale, senza una seconda build.
- **Impostazioni predefinite più sicure:** params con escape, cache limitate, link che restano sulla tua origine.
- **Meno da distribuire:** file dei dizionari più piccoli, pacchetti di routing più piccoli, e logica condivisa in un unico posto.

Per l'elenco completo delle modifiche, vedi [Aggiornamento](/it/guide/upgrade) e il [changelog](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
