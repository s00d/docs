**Data**: 2026-06-25

**Versione**: `v3.21.0`

![v3.21.0 release](/images/3.21.0.png)

Questa release aggiunge **`useI18nHead`** — un composable a livello di pagina per sovrascrivere la SEO i18n in aggiunta al plugin integrato `02.meta`. Personalizza i tag `hreflang`, canonical, `og:url` e Open Graph per ogni rotta senza un plugin meta personalizzato né `meta: false`.

## Novità {#what’s-new}

### Composable `useI18nHead` {#usei18nhead-composable}

Chiama `useI18nHead` in qualsiasi pagina quando `meta: true` (predefinito). Il modulo unisce il tuo input dopo `useLocaleHead` a ogni aggiornamento della rotta:

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

Supporta oggetti statici, getter reattivi, l'aggiunta di `meta` / `link`, `replace` per i gruppi integrati e `disable` per rimuovere i tag generati automaticamente. Vedi [`useI18nHead`](/it/composables/useI18nHead).

### Utility `mergeI18nHead` (`@i18n-micro/utils`) {#mergei18nhead-utility-@i18n-micro/utils}

La logica di unione indipendente dal framework si trova in `@i18n-micro/utils/merge-i18n-head` — usata dal plugin `02.meta` e testabile in isolamento. I tipi (`I18nHeadInput`, `I18nHeadLink`, `I18nHeadMeta`) sono esportati da `@i18n-micro/types`.

### Integrazione con i plugin {#plugin-integration}

- **`02.meta`** — unisce l'output di `useLocaleHead` con lo stato della pagina da `useI18nHead` tramite `useHead`
- **`01.plugin`** — reimposta le sovrascritture della pagina al cambio del nome della rotta tramite `resetPageHead()` (stato condiviso con il composable)

### Documentazione e test {#documentation-&-tests}

- Nuova guida: [`useI18nHead`](/it/composables/useI18nHead) con esempi per CMS/articoli
- Aggiornate [SEO](/it/guide/seo) e [`useLocaleHead`](/it/composables/useLocaleHead) — quando usare quale API
- Copertura Playwright + Vitest: SSR, navigazione SPA, ricaricamento, `nuxi generate`, alternate parziali, `x-default`, caricamento reattivo lato client

## Casi d'uso tipici {#typical-use-cases}

| Scenario                                     | Approccio                                                      |
| -------------------------------------------- | -------------------------------------------------------------- |
| Blog/CMS con traduzioni parziali             | `replace.hreflang` + `replace.ogAlternates` dalle lingue dell'API |
| Canonical personalizzato dal CMS             | `replace.canonical` + `replace.ogUrl`                          |
| Solo OG per la landing page                  | `meta: [{ property: 'og:title', ... }]` — mantieni l'hreflang del modulo |
| Nessun hreflang su una pagina                | `disable: ['hreflang', 'x-default']`                           |
| Sostituire un plugin personalizzato (`i18nManualHreflang`) | `useI18nHead` per ogni pagina di contenuto + `meta: true` |

**JSON-LD** resta in `useHead({ script: [...] })` — `useI18nHead` non genera dati strutturati.

## Breaking change {#breaking-changes}

Nessuna per l'uso standard di `nuxt.config`. Il nuovo composable e il sottopercorso di utils sono aggiuntivi.

## Perché è importante {#why-it-matters}

- **Nessun plugin meta personalizzato** per post CMS, notizie o guide con URL per lingua
- **Pipeline unica** — impostazioni predefinite del modulo + sovrascritture della pagina in una sola chiamata `useHead`
- **Type-safe** — `I18nHeadInput` per helper come `buildArticleHead(content)`

Il changelog completo sarà pubblicato con la release su [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
