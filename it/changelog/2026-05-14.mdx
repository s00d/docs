**Data**: 2026-05-14

**Versione**: `v3.20.0`

![Rilascio v3.20.0](/images/3.20.0.png)

Questa release rifattorizza il runtime Nuxt in un layer dedicato **`NuxtI18n`**, separa la gestione dei reindirizzamenti tra server e client e corregge diverse regressioni di SSR/idratazione. Per le app tipiche, i composable pubblici e le opzioni di `nuxt.config` restano invariati.

## Novità {#what’s-new}

### `NuxtI18n` & `NuxtTranslationLoader` {#nuxti18n-&-nuxttranslationloader}

La logica i18n di runtime esce dal plugin monolitico e passa a classi mirate:

- **`NuxtI18n`** — layer di visualizzazione delle traduzioni attive (`$t`, `$has`, contesto di locale/route, unione/pulizia durante le transizioni)
- **`NuxtTranslationLoader`** — carica i chunk, cambia contesto durante la navigazione, inizializza il payload SSR
- **`createNuxtI18nPluginApi`** — superficie sottile del plugin (`$switchLocale`, `$localeRoute`, ecc.)

Consulta le pagine aggiornate [Architettura di cache e storage](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api) e [Prestazioni](/it/guide/performance).

### Payload SSR tramite `useState('i18n-ssr-chunks')` {#ssr-payload-via-usestate‘i18n-ssr-chunks’}

Le traduzioni SSR vengono serializzate tramite lo **stato di Nuxt**, non tramite un tag script `window.__I18N__`:

1. Il server carica i chunk → `useState('i18n-ssr-chunks')`
2. Il client esegue l'idratazione → `translationStorage.seedFromSsrChunks()`
3. Zero fetch aggiuntivi al primo paint

Il vecchio percorso di lettura `window.__I18N__` è stato **rimosso**.

### Separazione dell'architettura dei reindirizzamenti {#redirect-architecture-split}

I reindirizzamenti ora sono specifici per ambiente, per un comportamento più chiaro e meno scatti lato client:

| Ambiente       | Componente                     | Ruolo                                      |
| -------------- | ------------------------------ | ------------------------------------------ |
| **SSR server** | `06.redirect.ts` (solo server) | 302 prima del render, controlli 404, sincronizzazione del cookie |
| **SPA client** | `i18n-redirect.global.ts`      | Middleware di route globale durante la navigazione |

I reindirizzamenti client ricavano il locale dalla **route di destinazione**, preservano **query string e hash** e rispettano `redirects: false` (middleware non registrato). Consulta [Rilevamento del locale — reindirizzamenti per strategia](/it/guide/locale-detection#redirects-per-strategy).

### Tempistica dell'hook `i18n:register` {#i18nregister-hook-timing}

Il plugin **`05.hooks`** (`dependsOn: i18n-plugin-loader`) emette `i18n:register` dopo che il loader è pronto — all'avvio e durante la navigazione — così i plugin utente ricevono l'evento in modo affidabile. Disattivalo con `hooks: false`. Consulta [Eventi](/it/api/events).

### Estrazione di `defineI18nRoute` in fase di build {#build-time-definei18nroute-extraction}

Un unplugin Vite analizza i file `.vue` delle pagine in fase di build e scrive i meta delle route per `@i18n-micro/route-strategy`. Il `$defineI18nRoute` di runtime in `script setup` rimane per lo sviluppo e la configurazione inline. Consulta [Traduzioni per componente](/it/guide/per-component-translations).

## Correzioni di bug {#bug-fixes}

- **Idratazione SSR** — clona i chunk SSR reattivi prima di `Object.freeze` (corregge i crash client su `#locale` / 404)
- **Cambio di locale** — sostituisce il layer di visualizzazione al cambio di locale (nessuna chiave obsoleta del locale precedente)
- **Reindirizzamento client** — locale dalla route di destinazione; query/hash preservati nel reindirizzamento
- **`has()`** — controlla solo il locale attivo; il fallback si applica in `$t()`, non in `$has()`
- **Meta di `defineI18nRoute`** — cache per istanza del plugin; corrispondenza con il `rootDir` più lungo; percorsi corretti tra `pages/index` e `pages/index/index`

## Modifiche incompatibili {#breaking-changes}

Nessuna per l'uso standard di `nuxt.config` + composable. I percorsi interni e il meccanismo di iniezione SSR sono cambiati; le app che si basavano sull'iniezione manuale di `window.__I18N__` devono invece usare il payload di Nuxt / le API del modulo.

## Perché è importante {#why-it-matters}

- **Passaggio SSR → client più affidabile** — stato nativo di Nuxt invece di variabili globali ad hoc
- **Modello di reindirizzamento più chiaro** — 302 dal server prima del paint; middleware client solo dove serve
- **Più facile da mantenere** — runtime suddiviso in unità testabili con test di regressione mirati
