**Data**: 2026-07-30

**Versione**: `v3.24.0`

![Rilascio v3.24.0](/images/3.24.0.png)

Le build di produzione Node non incorporano più i payload di traduzione come `serverAssets` di Nitro / `raw:` di Rollup (RSS di build di diversi GB con cataloghi grandi). L'SSR legge lo stesso albero `/{apiBaseUrl}/{page}/{locale}/data.json` che il client scarica — da `public/` tramite `readFile`. Edge mantiene un embed Nitro e dovrebbe preferire `mode: 'source'`.

## Novità {#what’s-new}

### Node: SSR da `public/<apiBaseUrl>` {#node-ssr-from-public/&lt;apibaseurl&gt;}

- I preset Node che servono `public/` dal disco **non** registrano i `serverAssets` di Nitro.
- I payload vengono copiati in `public/<apiBaseUrl>` (predefinito `_locales`) come `{page}/{locale}/data.json`.
- L'SSR li carica tramite `#i18n-internal/payload-source` → `readFile` (percorso di produzione accanto a `.output/server`).
- `translationPayloads.serverAssets: true` significa ancora “SSR locale” e **forza** quella copia pubblica anche se `publicAssets` è false.

Playground (rispetto al precedente embed `serverAssets`): ~**1,25 GB** / ~6–7 s / `raw`=0 contro ~**3 GB** / ~13 s / ~170 chunk raw.

### Edge: `serverAssets` solo quando necessario {#edge-serverassets-only-when-needed}

- Edge (`nitro.node === false`) incorpora ancora tramite i `serverAssets` di Nitro (`assets:i18n`) con lo stesso layout di `mode`.
- Edge **non** forza una copia pubblica — imposta `publicAssets: true` per CDN/statico.
- Mostra un avviso con Edge + `mode: 'premerged'` (preferisci `mode: 'source'` per cataloghi grandi).

### `publicDir` si allinea agli URL del client {#publicdir-aligns-with-client-urls}

- `translationPayloads.publicDir` ha come valore predefinito **`apiBaseUrl`** (non `translationDir`).
- L'albero premerged pubblico/Edge è `{page}/{locale}/data.json`, corrispondente a `$fetch('/_locales/...')`.
- I valori predefiniti del modulo non impostano più `publicAssets: true` annidato (il deep-merge di Nuxt forzava la copia pubblica anche per `mode: 'source'`).

Vedi [Opzioni del modulo — `translationPayloads`](/it/api/module-options#translationpayloads), [Deployment — serverless ed Edge](/it/guide/deployment#serverless-and-edge) e [Architettura di cache e storage](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api).

## Modifiche incompatibili {#breaking-changes}

- **Nessun dizionario nel payload HTML SSR di Nuxt.** `payload.data['i18n-ssr-chunks']`, `setSsrChunk` e `seedFromSsrChunks` sono stati **rimossi**. Stessa impostazione predefinita di `@nuxtjs/i18n` (`experimental.preload: false`): il server mantiene le traduzioni in memoria per l'SSR; il client carica `/{apiBaseUrl}/.../data.json` durante il setup del plugin (`await switchContext`).
- **`prerenderRoutes` ha come valore predefinito `false`.** Abilitalo solo se ti serve che Nitro materializzi le route degli handler quando `publicAssets` non ha già scritto l'albero (`publicAssets` premerged genera già `{page}/{locale}/data.json`).
- **Il valore predefinito di `publicDir` è `apiBaseUrl`**, non `translationDir`. L'output statico si sposta ad es. da `public/locales/...` a `public/_locales/{page}/{locale}/data.json`, a meno che tu non imposti `publicDir` esplicitamente.
- **Il layout dello storage premerged** è ora `{page}/{locale}/data.json` (prima era `pages/{page}/{locale}.json`). Tutto ciò che leggeva chiavi Nitro/storage o copiava alberi con la vecchia struttura deve essere aggiornato.
- **Su Node, `serverAssets: true` non significa più embed Nitro** — significa SSR locale tramite la copia pubblica. Il vero embed `raw:` di Rollup resta solo per Edge.

## Migrazione {#migration}

1. Rimuovi qualsiasi codice che leggeva `payload.data['i18n-ssr-chunks']` o chiamava `seedFromSsrChunks` / `setSsrChunk`.
2. Per host puramente statici: mantieni il premerged predefinito + `publicAssets` (i file finiscono in `/_locales/.../data.json`), oppure imposta `prerenderRoutes: true` / ospita i payload su una CDN.
3. Per Cloudflare / altri Edge: imposta `translationPayloads: { mode: 'source' }` con cataloghi grandi; aggiungi `publicAssets: true` solo se ti serve una copia statica/CDN.
4. Se dipendevi dai payload in `public/<translationDir>`, imposta `translationPayloads.publicDir` o indirizza i tuoi strumenti a `public/<apiBaseUrl>`.

## Correzione: salto dei locale disabilitati nei payload pubblici premerged {#fix-skip-disabled-locales-in-premerged-public-payloads}

`preMergeLocales` ora scrive `{page}/{locale}/data.json` solo per i locale passati al merge (`locale.disabled: true` in fase di build viene omesso). In precedenza ogni locale JSON su disco veniva copiato in `public/`, quindi lo static di Nitro serviva i locale disabilitati con 200 e scavalcava l'handler. `disabledLocales` a runtime non può comunque rimuovere dalla pubblicazione file già generati — usa `locale.disabled` in fase di build quando la copia `publicAssets` / SSR pubblico Node è attiva.

## Perché è importante {#why-it-matters}

- Le build Node restano snelle: nessun picco di diversi GB del `raw:` di Rollup dovuto ai cataloghi di traduzione.
- I file pubblici e gli URL `$fetch` del client condividono un unico layout di percorso — l'hosting statico funziona senza remapping speciali.
- Edge può ancora incorporare payload `source` compatti senza forzare un albero pubblico duplicato.
