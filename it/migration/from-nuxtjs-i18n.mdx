# 🔄 Migrating from `nuxt-i18n` to `Nuxt I18n Micro`

## Which guide do you need?

| You are migrating from…                | Guide                                            |
| -------------------------------------- | ------------------------------------------------ |
| `@nuxtjs/i18n` (vue-i18n based module) | **This page**                                    |
| `nuxt-i18n-micro` v2.x                 | [Upgrading from v2.x to v3.x](/migration/v2-to-v3) |

## Why Migrate?

- **Improved performance**: ~51% faster builds and ~54% less build memory vs `@nuxtjs/i18n` **v10.6** in our [benchmark fixtures](/guides/performance-results)
- **Simplified configuration**: Streamlined setup with sensible defaults
- **Better resource management**: Optimized handling of large translation files

## Key Differences

| Feature                 | `nuxt-i18n`                      | `Nuxt I18n Micro`                         |
| ----------------------- | -------------------------------- | ----------------------------------------- |
| Translation files       | JS/TS/JSON, loaded via `vueI18n` | JSON only, auto-generated in dev          |
| Route generation        | Runtime                          | Build-time (`@i18n-micro/route-strategy`) |
| Translation loading     | Bundled into JS                  | Lazy-loaded JSON per page                 |
| Locale state            | `useI18n()` from `vue-i18n`      | `useI18nLocale()` composable              |
| `detectBrowserLanguage` | Supported                        | Use `autoDetectLanguage` instead          |

## Step-by-Step

### 1. Install

```bash
npm install nuxt-i18n-micro
```

### 2. Update Configuration

**Before (nuxt-i18n):**

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    defaultLocale: 'en',
    vueI18n: './i18n.config.js',
    detectBrowserLanguage: { useCookie: true },
  },
})
```

**Dopo (Nuxt I18n Micro v3):**

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    localeCookie: 'user-locale',
    autoDetectLanguage: true,
  },
})
```

### 3. Riorganizza i file di traduzione

Sposta le traduzioni nella directory `locales` in formato JSON. Ecco un confronto completo del progetto:

**Before (`nuxt-i18n`):**

```text
my-app/
├── i18n/
│   └── locales/          # langDir
│       ├── en.json       # all translations in one file
│       ├── ru.json
│       └── de.json
├── pages/
│   ├── index.vue
│   └── page.vue
├── server/
│   └── tsconfig.json
├── nuxt.config.ts        # config will change
└── package.json
```

**After (Nuxt I18n Micro):**

```text
my-app/
├── locales/              # translationDir
│   ├── en.json           # root-level translations
│   ├── ru.json
│   ├── de.json
│   └── pages/            # page-specific
│       ├── index/
│       │   ├── en.json
│       │   ├── ru.json
│       │   └── de.json
│       └── page/
│           ├── en.json
│           ├── ru.json
│           └── de.json
├── pages/
│   ├── index.vue         # API changes
│   └── page.vue
├── server/
│   └── tsconfig.json
├── nuxt.config.ts        # new config
└── package.json
```

<Tip>
Missing page-specific translation files are **auto-generated** in development mode — just run `nuxt dev` and the module will create empty JSON files for each page and locale.
</Tip>

### 4. Update Navigation

```diff
- <nuxt-link :to="{ name: 'index' }">Home</nuxt-link>
+ <NuxtLink :to="$localeRoute({ name: 'index' })">Home</NuxtLink>
+ <!-- or use the built-in component -->
+ <i18n-link :to="{ name: 'index' }">Home</i18n-link>
```

### 5. Aggiorna il SEO

Rimuovi qualsiasi configurazione SEO manuale da `nuxt-i18n`. Nuxt I18n Micro genera automaticamente tag `hreflang`, URL canonici e Open Graph quando `meta: true` è impostato.

### 6. Testa

Testa a fondo le traduzioni, il cambio di locale, i redirect e i meta tag SEO.

## 🛡️ Problemi comuni e risoluzione

### ❌ File di traduzione non caricati

Assicurati che i file di traduzione siano nella directory corretta e seguano il formato JSON. Verifica che `translationDir` corrisponda alla posizione dei tuoi file.

### ⚠️ Errori "Route Not Found"

Controlla che tutti i codici locale nell'array `locales` siano corretti e che le rotte siano configurate correttamente.

### 🏷️ Tag SEO mancanti

Verifica che `meta: true` sia impostato e che ciascuna locale abbia un codice `iso` valido.

### 🔄 Mismatch di idratazione

Se usi la strategia `no_prefix`, imposta la locale in un plugin server con `order: -10` usando `useI18nLocale().setLocale()` per garantire che server e client concordino sulla locale. Consulta [Rilevamento personalizzato della lingua](/guides/custom-language-detection).

### 🍪 Redirect non funzionanti

Per le strategie con prefisso, assicurati che `localeCookie: 'user-locale'` sia impostato. Senza un cookie, il plugin di redirect server non ha modo di ricordare la locale preferita dell'utente tra i ricaricamenti di pagina.
