Los handlers de servidor en `server/api/` y `server/routes/` pueden traducir cadenas y leer el locale de la petición con dos helpers autoimportados. Úsalos para respuestas de API, correos electrónicos, feeds o cualquier cosa que se renderice fuera de una página Vue. Leen los mismos archivos de traducción que tus páginas y detectan el locale a partir de la petición.

## Traducir en un handler {#translate-in-a-handler}

```ts
// server/api/greeting.get.ts
export default defineEventHandler(async (event) => {
  const t = await useTranslationServerMiddleware(event)
  return { message: t('greeting', { name: 'Ada' }) }
})
```

```bash
curl 'http://localhost:3000/api/greeting?locale=de'
# {"message":"Hallo, Ada!"}
```

`useTranslationServerMiddleware(event, defaultLocale?, locale?)` es asíncrono y devuelve `t(key, params?, defaultValue?)`. `t` devuelve la cadena, interpola los parámetros `{name}` y, cuando falta la clave, devuelve un `defaultValue` no vacío o, en su defecto, la clave.

`t` solo ve el chunk `index`: los archivos raíz (`locales/<locale>.json`) más `locales/pages/index/` cuando existe (solo los archivos raíz con `disablePageLocales`). Las claves de otras páginas no se cargan. Para ellas, carga el chunk tú mismo:

```ts
const { data } = await loadTranslationsFromServer('de', 'about') // Translations object of the about page
```

## Leer el locale de la petición {#read-the-request-locale}

```ts
// server/api/locale.get.ts
export default defineEventHandler((event) => {
  const { current, isDefault, locale } = useLocaleServerMiddleware(event)
  return { current, isDefault, dir: locale?.dir ?? 'ltr' }
})
```

`useLocaleServerMiddleware(event, defaultLocale?, locale?)` es síncrono y devuelve:

```ts
interface LocaleInfo {
  current: string // detected locale code
  default: string // defaultLocale, runtime overrides included (fixed at build under prefix_except_default / prefix_and_default)
  fallback: string // fallbackLocale, else the default
  available: string[] // enabled locale codes
  locale: Locale | null // the config entry of `current`
  isDefault: boolean
  isFallback: boolean
}
```

## Cómo se elige el locale {#how-the-locale-is-chosen}

Ambos helpers usan el mismo orden en todas las rutas de servidor, sean `/api` o no:

1. la query `?locale=` (el primer valor si se repite);
2. un parámetro de ruta `[locale]`, o un prefijo de locale en la ruta (`/de/...`);
3. la cookie del locale, cuando [`localeCookie`](/es/api/module-options#localecookie) está definido (`hash-locale` con `hashMode`);
4. `Accept-Language`, cuando `autoDetectLanguage` está activado (se respetan los valores q);
5. `defaultLocale`.

Los códigos no válidos y deshabilitados se omiten en cada paso. Este es el orden de la API; el renderizado de una página ignora `?locale=` con las estrategias de prefijo. Ambos órdenes se comparan en [Detección del locale](/es/guide/locale-detection).

## Forzar un locale {#force-a-locale}

Pasa el tercer argumento para omitir la detección, por ejemplo en una tarea que envía correo en el idioma del usuario:

```ts
export default defineEventHandler(async (event) => {
  const user = await getUser(event) // your code
  const t = await useTranslationServerMiddleware(event, undefined, user.locale)
  return sendMail(user.email, t('mail.welcome.subject'))
})
```

El segundo argumento reemplaza a `defaultLocale` en la detección de esta llamada, así que no tiene efecto cuando se fuerza un locale. Los diccionarios se almacenan en caché por petición y por locale, y entre peticiones en la caché de traducciones del servidor, así que llamar a un helper varias veces es barato.

## Componentes de servidor {#server-components}

Un componente de servidor (`.server.vue`, `<NuxtIsland>`) se renderiza desde su propia URL, `/__nuxt_island/...`, así que no ve la URL de la página, y Nuxt solo le pasa sus props. Pasa el locale como prop `locale`. Así se renderiza en ese locale, y un cambio de locale lo vuelve a solicitar, ya que las props forman parte de la URL y de la clave de caché de la isla. El nombre está reservado: cualquier código de locale habilitado en una prop llamada `locale` define el locale del renderizado, así que da otro nombre a una prop que signifique otra cosa, como un formato numérico:

```vue
<!-- components/Greeting.server.vue -->
<template><p>{{ $t('greeting') }}</p></template>
<script setup lang="ts">
defineProps<{ locale?: string }>()
</script>
```

```vue
<template>
  <Greeting :locale="$getLocale()" />
  <NuxtIsland name="Greeting" :props="{ locale: $getLocale() }" />
</template>
```

Sin la prop, se renderiza en el locale de la cookie o, en su defecto, en el locale por defecto, diga lo que diga la URL, y no sigue los cambios de locale. Su `$t` ve el chunk `index`: los archivos raíz más `locales/pages/index/`.
