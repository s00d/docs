---
title: "Detección de locale personalizada"
description: "Elige el locale tú mismo — por dominio, cabecera o perfil de usuario — con un plugin de servidor y useI18nLocale().setLocale()."
---

La detección integrada lee la URL, una cookie y `Accept-Language`. Cuando el locale depende de otra cosa — el dominio, una cabecera geográfica establecida por tu CDN, un perfil de usuario — establécelo tú mismo en un plugin que se ejecute antes del plugin de i18n. El módulo carga entonces las traducciones de ese locale y lo usa para las redirecciones exactamente igual que si lo hubiera detectado. Las reglas que deciden cuándo un locale elegido prevalece sobre la URL están en [Detección de locale](/es/guide/locale-detection); esta página muestra cómo conectar tu propia fuente.

## Establecer el locale en un plugin de servidor {#set-the-locale-in-a-server-plugin}

```ts
// plugins/i18n-locale.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10, // before the i18n plugin (order -5)
  setup() {
    const { setLocale } = useI18nLocale()
    const host = (useRequestHeaders(['host']).host ?? '').split(':')[0]! // without the port

    if (host.endsWith('.de')) setLocale('de')
    else if (host.endsWith('.fr')) setLocale('fr')
  },
})
```

`setLocale(code)` escribe el estado del locale (`useState('i18n-locale')`) y, cuando hay una cookie de locale configurada, la cookie. Úsalo en lugar de escribir tú mismo `useState` o `useCookie`. Pasa solo códigos de locales habilitados.

Mantén el plugin como `.server.ts` cuando lea cabeceras de la petición: no existen en el navegador. Un plugin `.client.ts` es el lugar para fuentes exclusivas del navegador, como `localStorage`.

## Desactivar el paso integrado de Accept-Language {#turn-off-the-built-in-accept-language-step}

Tu plugin y `Accept-Language` pueden no coincidir. Para que solo decida tu código (además de la URL y la cookie), desactiva la cabecera:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    autoDetectLanguage: false,
  },
})
```

[`autoDetectLanguage`](/es/api/module-options#autodetectlanguage) solo controla el paso de la cabecera. La URL y una cookie válida siguen contando.

## Qué ocurre después {#what-happens-next}

El efecto de `setLocale` depende de la [estrategia](/es/guide/strategy):

| Estrategia | Efecto de `setLocale('de')` en el plugin |
| --- | --- |
| `no_prefix` | La página se renderiza en alemán; la URL no cambia. |
| `prefix`, `prefix_except_default` | En una ruta sin prefijo donde [`autoDetectPath`](/es/api/module-options#autodetectpath) permite redirecciones (por defecto solo `/`), el servidor responde `302` a la URL en alemán. Una URL con prefijo de locale lo conserva. |
| `prefix_and_default` | Sin redirección: la URL sin prefijo es una página válida del locale por defecto. |

Con las estrategias de prefijo, un locale en la URL es la elección del usuario y tu plugin no lo sobrescribe. `autoDetectPath: '*'` es la excepción: el servidor entonces mueve las URL con prefijo según la cookie y `Accept-Language` e ignora el estado, pero `setLocale()` también escribe la cookie cuando hay una configurada, así que a partir de la siguiente petición la elección de tu plugin puede redirigir una URL con prefijo. Mantén `'/'` o usa `'no_prefix'` cuando las URL con locale explícito deban prevalecer. Usa tu plugin para elegir dónde aterriza un visitante, no para reescribir los enlaces que ha seguido.

## Respetar el locale que eligió el usuario {#respect-a-locale-the-user-picked}

Cuando un usuario cambia de idioma, el cambio escribe la cookie. Omite tu propia detección cuando ya exista una preferencia válida:

```ts
// plugins/i18n-locale.server.ts
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10,
  setup() {
    const { getPreferredLocale, setLocale, validLocales } = useI18nLocale()
    if (getPreferredLocale()) return // valid state or cookie: keep it

    const country = useRequestHeaders(['x-country'])['x-country']
    if (country === 'JP') return setLocale('ja')

    const header = useRequestHeaders(['accept-language'])['accept-language']
    setLocale(detectLocaleFromAcceptLanguage(header, validLocales))
  },
})
```

`getPreferredLocale()` devuelve el estado o la cookie solo cuando es un locale habilitado, así que una cookie obsoleta no detiene la detección. `detectLocaleFromAcceptLanguage` es el comparador que tiene en cuenta los valores q y que usa el propio módulo (instala `@i18n-micro/utils` para importarlo); `setLocale(null)` no hace nada.

## Un dominio por locale {#one-domain-per-locale}

Si cada dominio debe servir sus propios locales, no necesitas un plugin: asigna a cada locale un `baseUrl`, establece `baseDefault: true` en el locale por defecto de cada dominio y compila una vez (un sitio estático sigue ejecutando `nuxi generate` por dominio). Consulta [Capas y dominios](/es/guide/layers#multiple-domains).
