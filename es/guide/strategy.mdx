---

La opción `strategy` decide si un locale aparece en la URL y para qué locales. Elígela una vez, antes de publicar URLs: cambiarla más tarde cambia todos los enlaces. Después, el módulo genera las rutas localizadas en tiempo de compilación, y `$localePath`, `<i18n-link>` y el selector de idioma las leen.

## Las cuatro estrategias {#the-four-strategies}

![La página /about en en (por defecto) y de con cada estrategia; las mismas URL se enumeran en el texto siguiente](/images/diagrams/strategies.svg)

**Tipo** `Strategies` · **Por defecto** `'prefix_except_default'`

Estrategia de enrutamiento de URL para los prefijos de locale.

- `'no_prefix'` — sin locale en la URL; el locale se guarda en una cookie.
- `'prefix_except_default'` — prefijo en todos los locales excepto el predeterminado.
- `'prefix'` — siempre con prefijo, incluido el locale predeterminado.
- `'prefix_and_default'` — como `prefix`, pero el locale predeterminado también es accesible sin prefijo.

URL de una página `about` con `defaultLocale: 'en'` y los locales `en`, `de`:

| Estrategia | Inglés | Alemán | No servido |
| --- | --- | --- | --- |
| `prefix_except_default` (por defecto) | `/about` | `/de/about` | `/en` y `/en/about` son un 404 |
| `prefix` | `/en/about` | `/de/about` | `/about` redirige a una URL con prefijo |
| `prefix_and_default` | `/about` y `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | el locale no está en la URL |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

La estrategia se fija en la compilación: un override en runtime se ignora con una advertencia ([Overrides en runtime](/es/guide/runtime-overrides)).

## Cuál elegir {#which-one-to-choose}

- **`prefix_except_default`**: la mayoría de los sitios. Las URL sin prefijo existentes siguen funcionando para el idioma predeterminado.
- **`prefix`**: todos los idiomas son iguales; `/` siempre lleva a una página de inicio con prefijo.
- **`prefix_and_default`**: necesitas que funcionen tanto `/en/...` como las URL sin prefijo, por ejemplo mientras migras de una a otra. Las URL sin prefijo nunca se redirigen.
- **`no_prefix`**: apps detrás de un login, o una sola URL por página para todos los idiomas. El locale viene de una cookie o de `?locale=`. Los buscadores ven un idioma por URL, así que no se emiten alternativas `hreflang`.

Cómo se elige el locale para una URL, y cuándo se redirige a un visitante, se explica en [Detección del locale](/es/guide/locale-detection).

## Rutas generadas {#generated-routes}

En tiempo de compilación, cada página recibe los registros de ruta que necesita su estrategia. Cada registro lleva `meta.i18n = { name, locales }`: la página que muestra y los locales que sirve. Los enlaces, los cambios de idioma y las redirecciones se resuelven a partir de esos registros, así que una URL que entrega el módulo es siempre una que el router sirve.

Los locales que comparten la ruta de la página comparten un registro, `/:locale(de|fr)/about`. Un locale con su propia ruta recibe su propio registro, llamado `localized-<page>-<locale>`:

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

Las rutas personalizadas, las listas de locales por página y la exclusión de una página de la localización se tratan en [Rutas localizadas](/es/guide/custom-locale-routes) y [Configuración de página](/es/guide/per-component-translations). El prefijo `localized-` es [`localizedRouteNamePrefix`](/es/api/module-options#localizedroutenameprefix).

<Warning>

**Los nombres de ruta se generan** — No escribas a mano nombres `localized-…` en `router.push({ name })`. Pasa el nombre propio de la página a `$localeRoute` o `<i18n-link>`; ellos eligen el registro correcto.

</Warning>

## Enlazar a una página en un locale {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- Funcionan tanto las rutas con nombre como las rutas por path. Un path se compara con las rutas generadas, así que se acepta su forma en cualquier locale.
- Un locale que no sirve la página (consulta `locales` en [Configuración de página](/es/guide/per-component-translations)) enlaza a la página de inicio de ese locale en lugar de a una página inexistente.
- Los parámetros por locale (un slug traducido) pasan por `$setI18nRouteParams`; consulta [Rutas localizadas](/es/guide/custom-locale-routes).

Las firmas están en [Métodos](/es/api/methods).

## Detalles de `no_prefix` {#no_prefix-details}

- [`localeCookie`](/es/api/module-options#localecookie) vale `'user-locale'` por defecto con `no_prefix`, así que la elección sobrevive a una recarga.
- `$switchLocale('de')` carga el diccionario alemán y reemplaza la entrada actual del historial; la URL no cambia.
- Las rutas personalizadas por locale siguen funcionando: con `globalLocaleRoutes: { about: { de: '/ueber-uns' } }`, los lectores en alemán obtienen `/ueber-uns`. Esa URL siempre se renderiza en alemán, prefiera lo que prefiera el visitante, y una página restringida a algunos locales se renderiza en uno de ellos. Una ruta que comparten varios locales (`en` y `de` ambos en `/page/:id`) se renderiza en el locale preferido cuando es uno de ellos. La preferencia en sí se mantiene: la siguiente página vuelve a ella.
- [`noPrefixRedirect: true`](/es/api/module-options#noprefixredirect) redirige la ruta original de una página con una ruta personalizada en el locale predeterminado: a la ruta personalizada del locale del visitante o, si no, a la del locale predeterminado (`/about` → `/about-us` cuando `en` tiene `/about-us`, → `/ueber-uns` con la cookie `de`). Un locale sin ruta personalizada propia se queda en la ruta original y se renderiza allí. Las páginas con parámetros no se redirigen.

## Apps sin `pages/` {#apps-without-pages/}

Con `pages: false` no hay rutas de página que localizar. Usa solo archivos de traducción raíz (`disablePageLocales: true`); la detección, la cookie y `$switchLocale` siguen funcionando. La variante `pages-false` de `test/fixtures/basic` en el repositorio es una configuración funcional.
