---

Con `meta: true` (el valor por defecto), cada página localizada recibe `<html lang dir>`, un enlace canónico, alternativas `hreflang`, `x-default` y etiquetas de locale de Open Graph. Necesitas esta página cuando quieres definir el origen público, ajustar qué locales aparecen en las etiquetas o sobrescribirlas para una página. La mayoría de los sitios solo necesitan un `site.url` o `metaBaseUrl` y códigos `iso` correctos.

## Configuración mínima {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

`/de/about` renderiza entonces:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Dirección del texto {#text-direction}

`<html dir>` proviene del `dir` del locale. Si no lo tiene, un idioma que se escribe de derecha a izquierda recibe `rtl`, leído de `iso` (o `code`): árabe, hebreo, persa, urdu y algunos otros, y cualquier etiqueta con una escritura RTL como `az-Arab`. Los demás locales no reciben atributo `dir`, lo que los navegadores interpretan como `ltr`.

<Warning>

**`dir: 'auto'` cuesta tiempo de análisis en páginas grandes**: `auto` en `<html>` hace que el navegador deduzca la dirección a partir del contenido mientras lo analiza. En Chromium ese coste crece más rápido que la página: unos 100 ms con 5.000 elementos y 1 s con 20.000. Úsalo solo para una página pequeña cuyo idioma no puedas conocer.

</Warning>

## Qué etiquetas obtienes {#which-tags-you-get}

- **hreflang**: una etiqueta por cada locale que sirve la página, con valor `iso` (o `code` cuando falta `iso`), y su URL con la misma query que la canónica. Una página restringida con [Configuración de página](/es/guide/per-component-translations) o `routeLocales` solo lista sus locales. [`hreflangBaseLanguage: true`](/es/api/module-options#hreflangbaselanguage) también añade el idioma base (`es-ES` → `es`) para el primer locale regional.
- **x-default**: la URL del locale por defecto, solo cuando el locale por defecto sirve la página.
- **og:locale**: derivado de `iso` (`en-US` → `en_US`). Define `og` en el locale cuando la correspondencia no es directa, por ejemplo `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; sin ninguno de los dos, no se escribe `og:locale` y el modo de desarrollo muestra un aviso.
- **canonical / og:url**: la URL actual sin parámetros de query, excepto los de [`canonicalQueryWhitelist`](/es/api/module-options#canonicalquerywhitelist) (por defecto `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Según la estrategia:

| Estrategia | hreflang y x-default | canonical, og:url, og:locale, atributos html |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | sí | sí |
| `no_prefix` | no (una sola URL sirve todos los locales) | sí |

## Definir el origen público {#set-the-public-origin}

Las URL absolutas usan el primero de:

1. [`metaBaseUrl`](/es/api/module-options#metabaseurl);
2. `site.url` de `nuxt-site-config` (instalado por `@nuxtjs/seo`);
3. el origen de la petición, con `app.baseURL` añadido.

Fija uno de los dos primeros.

<Warning>

El fallback al origen de la petición lee `X-Forwarded-Host` y `X-Forwarded-Proto`, porque [`metaTrustForwardedHost`](/es/api/module-options#metatrustforwardedhost) y `metaTrustForwardedProto` valen `true` por defecto. Esto solo es seguro detrás de un proxy que sobrescriba esas cabeceras; de lo contrario, un cliente puede elegir el host de tus enlaces canónicos y una caché puede propagar esa página.

Si la aplicación es accesible directamente, fija `metaBaseUrl`: a diferencia de poner ambas opciones a `false`, también ignora un `Host` falsificado. Consulta [Detrás de un proxy o CDN](/es/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

El fallback es útil cuando un mismo despliegue responde a varios dominios: `https://site-a.com/en/about` y `https://site-b.com/en/about` obtienen cada uno su propio origen.

Con `baseUrl` en los locales, un host conocido usa su propio `baseUrl`, por encima de `metaBaseUrl` y `site.url`, de modo que canonical y `og:url` permanecen en ese dominio y `hreflang` apunta cada locale a su dominio. Cualquier otro host usa `metaBaseUrl`, si no el `baseUrl` del locale por defecto, si no `site.url`, para que un `Host` falsificado no pueda llegar a tus etiquetas. Si no hay ninguno definido, se mantiene el fallback al origen de la petición y la compilación muestra un aviso. Consulta [Capas y dominios](/es/guide/layers#multiple-domains).

## Excluir locales o páginas {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Si el locale por defecto tiene `seo: false`, no se escribe `x-default`. Para desactivar las etiquetas en una página, usa `disableMeta` en [Configuración de página](/es/guide/per-component-translations#turn-off-seo-tags), o [`routeDisableMeta`](/es/api/module-options#routedisablemeta) en la configuración.

## Sobrescribir etiquetas en una página {#override-tags-on-one-page}

Para contenido de un CMS donde solo existen algunas traducciones, o cuando las URL provienen de una API, reemplaza las etiquetas generadas con [`useI18nHead`](/es/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` también puede definir o eliminar `canonical`, `xDefault`, `ogLocale` y `ogUrl`; `disable` elimina grupos completos (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Pasa un getter para que los valores se recalculen tras un cambio de locale. Para slugs por locale, define primero `$setI18nRouteParams` ([Rutas localizadas](/es/guide/custom-locale-routes#per-locale-slugs)) y las alternativas generadas ya los usarán.

## Barra final {#trailing-slash}

`$localePath`, `$switchLocalePath`, el objeto de ruta de `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, las redirecciones de locale y las URL de SEO siguen una única regla de barra final: `experimental.defaults.nuxtLink.trailingSlash` por defecto, o [`trailingSlash`](/es/api/module-options) en la configuración de i18n cuando las rutas de i18n deban ser distintas.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) funciona con este módulo a través de `nuxt-site-config` 4+. Pon `nuxt-i18n-micro` primero en la lista para que la configuración del sitio pueda leer los locales, y define `site.url` una sola vez: también alimenta las etiquetas anteriores.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

El nombre y la descripción traducidos del sitio provienen de las claves `nuxtSiteConfig.name` / `nuxtSiteConfig.description` de tus archivos de locale. El error `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` significa que `@nuxtjs/seo` es anterior a la versión 3; actualízalo ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
