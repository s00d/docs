---
title: "Rutas localizadas"
description: "Asigna a una página una URL distinta por locale con localeRoutes o globalLocaleRoutes, incluidos parámetros dinámicos y slugs por locale."
---

Por defecto, cada locale sirve una página en la misma ruta: `/en/about`, `/de/about`. Las rutas localizadas permiten que cada locale use sus propias palabras, como `/de/ueber-uns`, mientras el archivo de la página sigue siendo el mismo. Las defines en la página con `$defineI18nRoute`, o para muchas páginas a la vez en `nuxt.config.ts`.

## En la página {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

Con `prefix_except_default` y `defaultLocale: 'en'`, la página responde en `/about`, `/de/ueber-uns` y `/fr/a-propos`. Un locale sin entrada conserva la ruta por defecto. Escribe las rutas sin el código de locale: el prefijo lo añade la [estrategia](/es/guide/strategy), y una ruta que empieza por el código de locale registra un aviso. Lo demás que acepta la llamada está en [Configuración de página](/es/guide/per-component-translations).

## En nuxt.config {#in-nuxt-config}

[`globalLocaleRoutes`](/es/api/module-options#globallocaleroutes) hace lo mismo para cualquier página, usando como clave su ruta (o su nombre de ruta, cuando se escribe sin barra inicial):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

Cuando una página define `localeRoutes` y `globalLocaleRoutes` tiene la misma clave, gana la entrada de la configuración.

## Parámetros dinámicos {#dynamic-params}

Escribe los parámetros en cualquier forma de Nuxt: `[id]`, `[[page]]`, `[...slug]` o `:id()`. Los nombres de los parámetros deben coincidir con el archivo de la página.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

Las páginas anidadas aceptan una ruta hija absoluta (`/ueber-uns/team`) o una ruta relativa a la ruta localizada del padre (`team`).

## Enlazar a páginas localizadas {#linking-to-localized-pages}

Los enlaces se resuelven a la ruta localizada del locale de destino, tanto si pasas un nombre de ruta como una ruta simple:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

Los nombres de ruta provienen de la ruta del archivo (`pages/about/team.vue` es `about-team`), salvo que definas uno con `definePageMeta({ name })`.

## Slugs por locale {#per-locale-slugs}

Cuando el propio slug difiere por locale (`/our-products/red-shoe` frente a `/de/unsere-produkte/roter-schuh`), indica al selector de idioma qué parámetros usar con `$setI18nRouteParams` una vez cargados los datos:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

`$switchLocalePath('de')` y `<i18n-switcher>` enlazan entonces a `/de/unsere-produkte/roter-schuh`. Las claves son códigos de locale y los valores son parámetros por nombre (como en el archivo de la página).

Un selector en el layout se renderiza antes de que el setup asíncrono de la página llegue aquí, así que, al terminar el renderizado, el módulo reescribe los enlaces de `<i18n-switcher>`, tanto en `app.vue` como en la página. El HTML del servidor, un visitante sin JavaScript y el primer renderizado del cliente coinciden entonces. Para ello, define los parámetros durante el SSR: con `lazy` o `server: false` los enlaces solo cambian tras la hidratación. El streaming SSR de Nuxt envía el HTML antes de conocer los parámetros, así que con él los enlaces del primer HTML conservan los parámetros de la propia URL.

Solo se reescriben los enlaces propios del selector. Un enlace `$switchLocalePath` escrito a mano debe renderizarse después de definir los parámetros, así que colócalo en la página que los define, también después de un `await`. En un layout se renderiza primero: su HTML del servidor conserva los parámetros de la URL y la hidratación avisa de una discrepancia. Usa ahí `<i18n-switcher>`, con sus slots y sus props `custom*Style` para el aspecto.

Los parámetros pertenecen a la página que los definió:

- Se descartan cuando se confirma una navegación a otra ruta, así que cada página define los suyos. Una navegación cancelada los deja en su sitio.
- Obtén `$setI18nRouteParams` de `useNuxtApp()` o `useI18n()` en `setup`, también cuando lo llames más tarde en un handler de `useAsyncData`. Obtenida ahí, la función conoce su página: si el visitante ya se ha ido, una llamada tardía no hace nada.
- Con `keepalive`, una página recupera los parámetros que definió cuando el visitante vuelve. `useI18nHead` hace lo mismo.

## Rutas añadidas en pages:extend {#routes-added-in-pagesextend}

Las rutas que añades en el hook `pages:extend` no tienen un archivo de página del que leer `$defineI18nRoute`, y a menudo varias comparten un mismo componente envoltorio. Una ruta añadida sin `name` recibe el nombre que Nuxt daría a su ruta (`/a/:id()` se convierte en `a-id`), para que los enlaces de idioma la alcancen, salvo que otra ruta ya tenga ese nombre; en ese caso, dale un `name` explícito. Mantén una sola lista y divídela en páginas y en `globalLocaleRoutes` con clave por nombre de ruta mediante `splitLocaleRoutes` de `@i18n-micro/utils/split-locale-routes` (añade el paquete a tus dependencias):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

No pongas rutas localizadas en `route.meta`: se enviarían en la tabla de rutas del cliente.
