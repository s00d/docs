Esta página traslada una app con `@nuxtjs/i18n` a nuxt-i18n-micro: opciones, helpers y estructura de archivos. Úsala cuando cambies el módulo en una app existente. Conservas tus URL (los nombres de las estrategias son los mismos) y pasas las traducciones a archivos JSON por página.

<Tip>

**¿Vas a actualizar el propio nuxt-i18n-micro?** — Consulta [Actualización](/es/guide/upgrade).

</Tip>

## Cambiar el módulo {#swap-the-module}

```bash
npm uninstall @nuxtjs/i18n
npm install nuxt-i18n-micro
```

```ts
// nuxt.config.ts — before
export default defineNuxtConfig({
  modules: ['@nuxtjs/i18n'],
  i18n: {
    locales: [
      { code: 'en', language: 'en-US', file: 'en.json' },
      { code: 'de', language: 'de-DE', file: 'de.json' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    langDir: 'locales',
    detectBrowserLanguage: { useCookie: true, cookieKey: 'i18n_redirected', redirectOn: 'root' },
  },
})
```

```ts
// nuxt.config.ts — after
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix_except_default',
    translationDir: 'locales',
    localeCookie: 'i18n_redirected',
    autoDetectPath: '/',
  },
})
```

## Opciones {#options}

| `@nuxtjs/i18n` | nuxt-i18n-micro |
| --- | --- |
| `locales[].code` | `locales[].code` |
| `locales[].language` (`iso` antes de v9) | `locales[].iso` |
| `locales[].name` | `locales[].displayName` |
| `locales[].dir` | `locales[].dir` |
| `locales[].domain` | `locales[].baseUrl` (un origen con su esquema) |
| `locales[].domainDefault` | `locales[].baseDefault` |
| `differentDomains`, `multiDomainLocales` | no son necesarios: `baseUrl` por sí solo enruta por host, consulta [Capas y dominios](/es/guide/layers#multiple-domains) |
| `locales[].file` / `files`, `langDir`, `lazy` | `translationDir`; los archivos se encuentran por nombre y siempre se cargan por página |
| `defaultLocale`, `strategy` | mismos nombres, mismos cuatro valores |
| `baseUrl` | `metaBaseUrl` |
| `customRoutes: 'config'` + `pages` | `globalLocaleRoutes` |
| `detectBrowserLanguage: false` | `redirects: false` (sin redirecciones) o `autoDetectLanguage: false` (ignora la cabecera) |
| `detectBrowserLanguage.useCookie` / `cookieKey` | `localeCookie: '<name>'` (`null` desactiva la cookie) |
| `detectBrowserLanguage.redirectOn: 'root'` | `autoDetectPath: '/'` (por defecto) |
| `detectBrowserLanguage.redirectOn: 'no prefix'` | `autoDetectPath: 'no_prefix'` |
| `detectBrowserLanguage.redirectOn: 'all'` | `autoDetectPath: '*'` |
| Archivo de configuración `vueI18n` (`fallbackLocale`, `numberFormats`, `datetimeFormats`) | `fallbackLocale`, `numberFormats`, `datetimeFormats` en `i18n` |

No existe `alwaysRedirect`: con una cookie definida, `/` la sigue en cada visita. La lista completa está en [Opciones del módulo](/es/api/module-options); las reglas de detección están en [Detección de idioma](/es/guide/locale-detection).

## Helpers y composables {#helpers-and-composables}

| `@nuxtjs/i18n` / vue-i18n | nuxt-i18n-micro (plantilla / `useI18n()`) |
| --- | --- |
| `const { t } = useI18n()` | `const { t } = useI18n()`, `$t` en las plantillas |
| `t('key', count)`, `tc` | `$tc('key', count)` |
| `te('key')` | `$has('key')` |
| `n(value, 'currency')`, `d(date, 'short')` | `$tn(value, 'currency')`, `$td(date, 'short')` |
| — | `$tdr(date)`: tiempo relativo ("dentro de 3 días") |
| `locale.value` | `$getLocale()` |
| `locales.value` | `$getLocales()` |
| `setLocale('de')` | `$switchLocale('de')` |
| `useLocalePath()('about')` | `$localePath({ name: 'about' })` |
| `useLocaleRoute()` | `$localeRoute()` |
| `useSwitchLocalePath()('de')` | `$switchLocalePath('de')` |
| `useSetI18nParams()` | `$setI18nRouteParams()` |
| `useLocaleHead()` | automático con `meta: true`; [`useLocaleHead`](/es/composables/useLocaleHead) para heads personalizados |
| `defineI18nRoute({ paths: { de: '/ueber-uns' }, locales: [...] })` | `$defineI18nRoute({ localeRoutes: { de: '/ueber-uns' }, locales: [...] })` |
| `<NuxtLinkLocale to="about">` | `<i18n-link :to="{ name: 'about' }">` |
| `<i18n-t>` | `<i18n-t>` (los slots rellenan los marcadores `{name}`) |
| `$i18n` en rutas del servidor | `useTranslationServerMiddleware(event)`, consulta [Rutas del servidor y API](/es/guide/server-side-translations) |

`useI18n()` se importa automáticamente. `$defineI18nRoute` debe conservar su `$`: el build lee esa llamada. Todos los helpers: [Métodos](/es/api/methods).

## Archivos de traducción {#translation-files}

Pasa las claves de un único archivo grande por idioma a un archivo raíz más un archivo por página:

```text
locales/
├── en.json              # keys used on many pages (nav, footer)
├── de.json
└── pages/
    ├── index/en.json    # keys of pages/index.vue
    └── about/en.json    # keys of pages/about.vue
```

Mantenerlo todo en los archivos raíz también funciona, y es el primer paso más rápido. Establece `disablePageLocales: true` hasta que los dividas. Consulta [Archivos de traducción](/es/guide/translations).

### Sintaxis de los mensajes {#message-syntax}

| vue-i18n | nuxt-i18n-micro |
| --- | --- |
| Interpolación con nombre `{name}` | igual |
| `car \| cars` (2 formas: 1 → la primera) | las formas se eligen por cantidad empezando en 0: escribe `no cars \| one car \| {count} cars` |
| Mensajes enlazados `@:other.key` | no soportados: repite el texto o compón en código |
| Modificadores `@.upper:` | no soportados: formatea en código o usa `<i18n-t>` |
| Escapes literales `{'@'}` | no necesarios: solo se sustituyen los tokens `{word}` |
| Archivos de mensajes JS/TS | solo JSON |

La regla de plural se puede sustituir con la opción [`plural`](/es/api/module-options#plural).

## Comprobaciones tras el cambio {#check-after-the-switch}

- Todas las URL que tenías siguen resolviéndose; los nombres de las estrategias coinciden, y las rutas personalizadas pasan a `globalLocaleRoutes` o `$defineI18nRoute`.
- `hreflang`, canonical y `og:locale` se generan de serie con `meta: true`; elimina los que hayas escrito a mano.
- Un error de parseo de JSON registra la ruta del archivo; una clave inexistente registra una advertencia en la consola del navegador en desarrollo.
