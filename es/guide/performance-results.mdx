### Descripción {#description}

Compara **Nuxt sin i18n**, **i18n-micro** y **`@nuxtjs/i18n`** con un mismo perfil de diccionario compartido mediante `untestutils/perf`.

Enfoque: tiempo de compilación, RSS máximo, **código frente a traducciones (asset) frente a total** desplegable, y carga (Artillery).

### Notas de metodología {#methodology-notes}

- Las métricas son **medias de 3 ejecuciones consecutivas por fixture** (no intercaladas).
- **Artefacto**: `.output/server/index.mjs` del node-server de Nitro tras un `nuxi build` forzado; `nuxt-i18n-micro` es el **dist compilado del módulo** (no el stub jiti de `dev:prepare`). Consulta la [metodología de benchmarks](https://s00d.github.io/nuxt-i18n-micro/contributing/performance-methodology).
- **Traducciones** = `bundle.asset` (JSON de locales, `chunks/raw/`, fragmentos de locales que coinciden mediante `isTranslationFile`).
- **Código** excluye los source maps (`*.map`): los fixtures enlazan el módulo desde el repositorio, así que Nitro escribe maps completos para él y ninguno para las dependencias de npm.
- **plain-nuxt** sirve el mismo volumen de hojas como JSON estático — con mucha E/S bajo carga, no “sobrecarga de i18n”.
- Perfil de carga `--load full`: calentamiento 6s@6 + principal 60s@60 sin límite (histórico).
- Enfriamientos `--cool fast` (consulta el documento de metodología).
- Cada una de las compilaciones de `runs` es **forzada** (sin anular el tiempo de compilación por caché caliente).
- La **tasa de error** de Artillery en las tablas son errores de estado HTTP de las métricas de carga. Los gráficos también muestran `vusers.failed` (timeouts del cliente bajo saturación); estos pueden ser altos mientras la tasa de error HTTP se mantiene en 0%.
### Ejecuciones {#runs}

Todas las métricas siguientes son **medias de 3 ejecuciones**.

### Perfil de los fixtures {#fixture-profile}

| Parámetro | Valor |
|------|-------|
| Locales | **4** (`en`, `de`, `ru`, `fr`) |
| Páginas | **2** (`index`, `page`) |
| Árbol de index | profundidad **5**, ramificación **7** → **16,807** claves hoja / locale |
| Páginas secundarias | profundidad **5**, ramificación **6** → **7,776** claves hoja / página / locale |

Los diccionarios provienen de `scripts/perf-fixtures/perf-shared/runtime.json` (escrito por la CLI), de modo que los tres fixtures se mantienen alineados.

## Notas {#notes}

- Perfil compartido: 4 locales × 2 páginas × ~16.8k hojas de index.
- Carga: solo Artillery programático — calentamiento **6s@6** + principal **60s@60**, VU sin límite (metodología YAML histórica). Rutas del perfil de runtime — consulta `scripts/src/perf/load.ts`.
- Enfriamientos: 2s tras la compilación, 3s entre ejecuciones, 5s entre fixtures. Las compilaciones se fuerzan en cada ejecución para que las medias no se diluyan con aciertos de caché.
- Volver a ejecutar en el día a día: `pnpm test:performance` (`--load short --cool fast`).
- Regenerar esta página: `pnpm -C scripts cli performance --load full --only all --runs 3`.
- Flags: `--locales N --keys K --only all|micro|i18n|plain --runs N --skip-load --cool fast|strict`.
