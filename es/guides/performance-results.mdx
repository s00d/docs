# Resultados de pruebas de rendimiento

## Información del proyecto

- **[plain-nuxt](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/plain-nuxt)**: ./test/fixtures/plain-nuxt
- **[i18n-micro](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n-micro)**: ./test/fixtures/i18n-micro
- **[i18n](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n)**: ./test/fixtures/i18n
- **[CLI](https://github.com/s00d/nuxt-i18n-micro/tree/main/scripts/src/commands/performance.ts)**: `pnpm -C scripts cli performance` / `pnpm test:performance`

### Descripción

Compara **Nuxt plano** (línea base sin un módulo i18n), **i18n-micro** y **`@nuxtjs/i18n` v10.6** bajo un mismo perfil de diccionario compartido.

Enfoque: tiempo de compilación, RSS máximo, **código frente a traducciones frente a total** desplegables, y comportamiento del servidor bajo Artillery + Autocannon.

### Notas de metodología

- Las métricas son **medias de 3 ejecuciones consecutivas por fixture** (fixture A ×3, luego B ×3, luego C ×3. No intercalados).
- **Traducciones** incluyen JSON de idioma bajo `locales/` / `_locales/` / `translations/`, todo bajo `chunks/raw/` y los chunks de idioma correspondientes. Los informes antiguos que mostraban `@nuxtjs/i18n` "translations: 0 B" y una columna "code" enorme contaban chunks de mensajes como código de app.
- **plain-nuxt** sirve el mismo volumen hoja como JSON estático `public/translations` (no imports JS estáticos). Bajo Artillery esa línea base es intensiva en I/O; no es "sobrecarga i18n", es el coste de obtener JSON grandes por solicitud.

### Ejecuciones

Todas las métricas de abajo son **medias sobre 3 ejecuciones**.

### Perfil de la fixture

| Knob | Valor |
|------|-------|
| Idiomas | **4** (`en`, `de`, `ru`, `fr`) |
| Páginas | **2** (`index`, `page`) |
| Árbol de índice | profundidad **5**, rama **7** → **16,807** claves hoja / idioma |
| Páginas secundarias | profundidad **5**, rama **6** → **7,776** claves hoja / página / idioma |
| Objetivo | Perfil CLI por defecto (`--locales 4 --keys 10000`); sube knobs para cargas radar de regresión |

Los diccionarios provienen de `test/fixtures/perf-shared/runtime.json` (escrito por la CLI) para que las tres fixtures se mantengan alineadas.
