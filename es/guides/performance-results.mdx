# Resultados de pruebas de rendimiento

## Información del proyecto

- **[plain-nuxt](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/plain-nuxt)**: ./test/fixtures/plain-nuxt
- **[i18n-micro](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n-micro)**: ./test/fixtures/i18n-micro
- **[i18n](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n)**: ./test/fixtures/i18n
- **[CLI](https://github.com/s00d/nuxt-i18n-micro/tree/main/scripts/src/commands/performance.ts)**: `pnpm -C scripts cli performance` / `pnpm test:performance`

### Descripción

Compara **Nuxt plano** (línea base sin módulo i18n), **i18n-micro** y **`@nuxtjs/i18n` v10.6** bajo un mismo perfil de diccionario compartido.

Foco: tiempo de compilación, pico de RSS, **código frente a traducciones frente a total** desplegables, y comportamiento del servidor bajo Artillery + Autocannon.

### Notas metodológicas

- Las métricas son **medias de 3 ejecuciones consecutivas por fixture** (fixture A ×3, luego B ×3, luego C ×3, no intercaladas).
- Las **traducciones** incluyen los JSON de locales en `locales/` / `_locales/` / `translations/`, todo lo que hay en `chunks/raw/` y los chunks de locale correspondientes. Informes anteriores que mostraban «translations: 0 B» para `@nuxtjs/i18n` y una columna «code» enorme estaban contando los chunks de mensajes como código de la aplicación.
- **plain-nuxt** sirve el mismo volumen de hojas como JSON estático en `public/translations` (no como imports JS estáticos). Bajo Artillery, esa línea base es intensiva en E/S; no es «sobrecarga de i18n», es el coste de obtener JSON grandes por petición.

### Ejecuciones

Todas las métricas siguientes son **medias de 3 ejecuciones**.

---

### Perfil del fixture

| Parámetro | Valor |
|------|-------|
| Locales | **4** (`en`, `de`, `ru`, `fr`) |
| Páginas | **2** (`index`, `page`) |
| Árbol del índice | profundidad **5**, rama **7** → **16.807** claves hoja por locale |
| Páginas secundarias | profundidad **5**, rama **6** → **7.776** claves hoja por página y locale |
| Objetivo | Perfil de CLI predeterminado (`--locales 4 --keys 10000`); aumenta los parámetros para cargas de radar de regresión |

Los diccionarios provienen de `test/fixtures/perf-shared/runtime.json` (escrito por la CLI), de modo que los tres fixtures permanecen alineados.

## Notas

- Perfil compartido: 4 locales × 2 páginas × ~16,8k hojas de índice.
- Artillery: calentamiento de 6 s a 6 VU/s + 60 s principal a 60 VU/s. Autocannon: 10 conexiones × 10 s.
- Reejecutar: `pnpm test:performance` o `pnpm -C scripts cli performance --locales N --keys K --only all|micro|i18n|plain --runs N`.
