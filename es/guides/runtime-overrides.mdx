# Sobrescrituras de i18n en tiempo de ejecución

Utiliza esta guía cuando necesites que un mismo artefacto de compilación se ejecute con distintos valores predeterminados de locale según el entorno (por ejemplo: distintas instancias por inquilino).

## Qué puede sobrescribirse en tiempo de ejecución

El módulo admite sobrescrituras seguras en tiempo de ejecución para:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Estas sobrescrituras se aplican sobre la configuración de tiempo de compilación de `.nuxt/i18n.strategy.mjs` y `.nuxt/i18n.config.mjs`.

## Qué no puede sobrescribirse en tiempo de ejecución

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) es un asunto de tiempo de compilación porque afecta al comportamiento de las rutas generadas.

Si pasas una sobrescritura de `strategy` en tiempo de ejecución, se ignora y se emite una advertencia.

## Sobrescrituras basadas en RuntimeConfig

Proporciona los valores en tiempo de ejecución bajo `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Sobrescrituras mediante variables de entorno

También puedes configurar las sobrescrituras mediante variables de entorno:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (separadas por comas, por ejemplo, `fr,it`)

También se admiten alias alternativos:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Reglas de validación

En tiempo de ejecución, el módulo valida las sobrescrituras para evitar estados incorrectos:

- No puedes deshabilitar todos los locales.
- `defaultLocale` debe apuntar a un locale habilitado.
- `fallbackLocale` debe existir en los locales declarados.

Si una sobrescritura no es válida, el módulo conserva un valor seguro y registra una advertencia.

## Notas sobre despliegues con múltiples instancias

Esta funcionalidad en tiempo de ejecución está diseñada para la activación y los valores predeterminados de locale por instancia sin recompilar.

Si las instancias requieren distintas estrategias de URL (`no_prefix` frente a `prefix`), utiliza compilaciones separadas para cada estrategia.

## Locales deshabilitados y payloads estáticos

`runtimeConfig.public.i18nRuntime.disabledLocales` actualiza el enrutamiento, el switcher y el **handler** del payload de Nitro, pero Nitro sirve los archivos de `public/` **antes** de ese handler.

Si `translationPayloads.publicAssets` (o la copia pública forzada del SSR de Node) ya ha escrito `/_locales/\{page\}/\{locale\}/data.json`, deshabilitar en tiempo de ejecución no puede ocultar ese archivo. Es preferible usar `locale.disabled: true` en tiempo de compilación para que el premerge no emita los payloads estáticos de ese locale.
