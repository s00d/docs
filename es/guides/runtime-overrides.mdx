# Anulaciones i18n en runtime

Usa esta guía cuando necesites que un mismo artefacto de build se ejecute con distintos valores por defecto de idioma según el entorno (por ejemplo: distintas instancias de inquilino).

## Qué se puede anular en runtime

El módulo admite anulaciones seguras en runtime para:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Estas anulaciones se aplican encima de la configuración de tiempo de compilación de `.nuxt/i18n.strategy.mjs` y `.nuxt/i18n.config.mjs`.

## Qué no se puede anular en runtime

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) es un asunto de tiempo de compilación porque afecta al comportamiento de las rutas generadas.

Si pasas una anulación de estrategia en runtime, se ignora y se emite un aviso.

## Anulaciones basadas en RuntimeConfig

Proporciona los valores de runtime bajo `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Anulaciones por variables de entorno

También puedes configurar anulaciones mediante variables de entorno:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (separados por comas, por ejemplo, `fr,it`)

También se admiten alias de fallback:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Reglas de validación

En runtime, el módulo valida las anulaciones para evitar un estado inconsistente:

- No puedes desactivar todos los idiomas.
- `defaultLocale` debe apuntar a un idioma habilitado.
- `fallbackLocale` debe existir entre los idiomas declarados.

Si una anulación no es válida, el módulo conserva un valor seguro y registra un aviso.

## Notas para despliegues multi-instancia

Esta función de runtime está diseñada para la activación y valores por defecto de idioma por instancia sin necesidad de reconstruir.

Si las instancias requieren distintas estrategias de URL (`no_prefix` frente a `prefix`), usa builds separados para cada estrategia.

## Idiomas desactivados y payloads estáticos

`runtimeConfig.public.i18nRuntime.disabledLocales` actualiza el enrutamiento, el switcher y el **handler** de payloads de Nitro. Pero Nitro sirve archivos bajo `public/` **antes** que ese handler.

Si `translationPayloads.publicAssets` (o la copia pública forzada del SSR Node) ya escribió `/_locales/\{page\}/\{locale\}/data.json`, una desactivación en runtime no puede ocultar ese archivo. Prefiere `locale.disabled: true` en tiempo de build para que premerge no emita los payloads estáticos de ese idioma.
