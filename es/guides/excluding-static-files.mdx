# Excluir archivos estáticos del enrutamiento i18n

## Descripción general

Por defecto, nuxt-i18n-micro excluye automáticamente los archivos estáticos comunes del procesamiento de enrutamiento i18n. Sin embargo, también puedes configurar patrones de exclusión personalizados para evitar que rutas específicas sean procesadas por el sistema i18n.

## Exclusiones integradas

El módulo excluye automáticamente los siguientes tipos de archivos y patrones:

- **Sitemaps**: `/sitemap*.xml`, `/sitemap-en.xml`, etc.
- **Archivos SEO**: `/robots.txt`, `/favicon.ico`
- **Archivos PWA**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Assets estáticos**: archivos con extensiones como `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Rutas internas de Nuxt**: cualquier ruta que empiece por `__` (como `/__nuxt/`)

## Patrones de exclusión personalizados

Puedes definir patrones de exclusión personalizados usando la opción `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Tipos de patrones

### Patrones de cadena

- **Coincidencia exacta**: `'/api/health'` — coincide exactamente con `/api/health`
- **Coincidencia de prefijo**: `'/admin'` — coincide con `/admin` y `/admin/dashboard`
- **Comodines**: `'/api/*'` — coincide con `/api/users` pero no con `/api/users/123`
- **Comodines profundos**: `'/admin/**'` — coincide con `/admin/users` y `/admin/users/123`

### Expresiones regulares

Usa objetos RegExp para coincidencias de patrones complejos:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Casos de uso

### Archivos SEO

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### Rutas de API

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Paneles de administración

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Assets estáticos

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Cómo funciona

1. **Middleware del servidor**: un middleware de Nitro se ejecuta primero para comprobar los patrones de exclusión.
2. **Procesamiento de páginas**: durante la resolución de páginas, las rutas excluidas se omiten.
3. **Ruta catch-all**: la ruta de fallback comprueba las exclusiones antes de procesar.
4. **Prerenderizado**: las rutas excluidas no se incluyen en las rutas prerenderizadas.

## Impacto en el rendimiento

- Las comprobaciones de exclusión están optimizadas y se ejecutan temprano en el ciclo de vida de la solicitud.
- Los patrones integrados usan coincidencia regex eficiente.
- Los patrones personalizados se cachean y reutilizan.
- Sobrecarga mínima de rendimiento para las rutas excluidas.

## Solución de problemas

### Los archivos estáticos siguen siendo interceptados

1. **Comprueba la sintaxis del patrón**: asegúrate de que tus patrones coinciden con la estructura exacta de la ruta.
2. **Usa regex para patrones complejos**: los comodines de cadena tienen limitaciones.
3. **Prueba los patrones**: usa las herramientas de desarrollador del navegador para verificar la ruta real de la solicitud.
4. **Comprueba el orden**: asegúrate de que los patrones de exclusión estén definidos antes de otras configuraciones i18n.

### El patrón no funciona

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Modo de depuración

Activa el modo depuración para ver el procesamiento de exclusiones:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Esto registrará las decisiones de exclusión en la consola.

## Migrar desde soluciones alternativas

Si estabas usando soluciones alternativas como reglas de ruta o middleware, ahora puedes reemplazarlas con `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

El nuevo enfoque es más fiable y funciona en múltiples niveles del sistema de enrutamiento.
