# Referencia de opciones del módulo

Todas las opciones que acepta `nuxt-i18n-micro`, leídas en tiempo de compilación desde la interfaz `ModuleOptions` en [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts). Nada aquí se escribe a mano, por lo que no puede quedar desactualizado con respecto al código. Tipos, valores por defecto y descripciones provienen de la declaración misma.

Para saber qué *significan* estas opciones en conjunto (qué combinaciones tienen sentido, qué cambia cuando cambias de estrategia, ejemplos elaborados), lee [Configuración](/guides/configuration). Esta página es la lista exhaustiva; esa otra es la explicación.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Las opciones anidadas aparecen bajo su ruta con puntos, así que `translationPayloads.mode` es la clave `mode` dentro del objeto `translationPayloads`.

## Idiomas y enrutamiento

Qué idiomas existen y cómo aparecen en la URL.

| Opción | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Lista de idiomas admitidos. Cada entrada define un código de idioma más metadatos opcionales (ISO, dirección, nombre para mostrar, etc.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Estrategia de enrutamiento de URL para prefijos de idioma. - `'no_prefix'` — sin idioma en la URL; el idioma se almacena en cookie. - `'prefix_except_default'` — prefijo en todos los idiomas excepto el por defecto. - `'prefix'` — siempre con prefijo, incluido el idioma por defecto. - `'prefix_and_default'` — como `prefix`, pero el idioma por defecto también es accesible sin prefijo. |
| `defaultLocale` | `string` | `'en'` | El idioma que se usa cuando no puede determinarse a partir de la URL o las preferencias del usuario. También se usa como idioma de fallback para traducciones ausentes cuando no se establece `fallbackLocale`. |
| `localeCookie` | `string \| null` | `null` | Nombre de la cookie para persistir la preferencia de idioma del usuario entre sesiones. Establécelo en `null` para desactivar la persistencia basada en cookies. Se establece automáticamente en `'user-locale'` para la estrategia `no_prefix` si no se proporciona. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Configuración global de idioma a nivel de ruta. Permite restringir o personalizar las rutas de idioma para páginas específicas sin modificar sus componentes. - `false` — excluye la ruta de la localización. - `Record<LocaleCode, string>` — rutas personalizadas por idioma. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Expresión regular personalizada (o su código fuente en cadena) para encontrar códigos de idioma en los segmentos de URL. Todos los códigos de idioma definidos en `locales` deben coincidir con este patrón, o se emite un aviso. |
| `noPrefixRedirect` | `boolean` | `false` | Para la estrategia `no_prefix`: activa la redirección desde una URL con prefijo de idioma (por ejemplo, `/en/about`) a la versión sin prefijo (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Patrones de URL (cadenas o RegExp) para excluir por completo del procesamiento i18n. Las rutas coincidentes no recibirán prefijos de idioma, redirecciones ni carga de traducciones. Las rutas internas de Nuxt (`/__nuxt_error`, etc.) siempre se excluyen automáticamente. |
| `routeLocales` | `Record<string, string[]>` | — | Restricciones de idioma por ruta, extraídas de las llamadas a `defineI18nRoute()`. Asocia una ruta (por ejemplo, `'/about'`) a un arreglo de códigos de idioma permitidos. Las rutas no listadas no tienen restricciones (se permiten todos los idiomas). |

## Traducciones

Dónde residen los archivos de traducción y cómo se resuelven las claves.

| Opción | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Ruta al directorio que contiene los archivos JSON de traducción, relativa a la raíz del proyecto. |
| `disableWatcher` | `boolean` | `false` | Desactiva el watcher de archivos que crea automáticamente archivos de traducción ausentes en modo desarrollo. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Asocia nombres de ruta con otros nombres de ruta para compartir los mismos archivos de traducción. Por ejemplo, `\{ 'about-us': 'about' \}` significa que la página `about-us` usará las traducciones de la página `about` en lugar de las suyas propias. |
| `plural` | `PluralFunc` | `built-in pluralization (form index by count)` | Función de pluralización personalizada. Recibe `(key, count, params, locale, getter)` y debe devolver la forma plural seleccionada como cadena, o `null`/`undefined` para recurrir a la lógica integrada `defaultPlural` (para que puedas anular solo algunos idiomas). Para el módulo Nuxt, la función se serializa con `.toString()` en `.nuxt/i18n.plural.mjs`. Debe ser autocontenida (sin imports ni ámbito externo). Una cadena con ruta de archivo **no** está admitida. |
| `disablePageLocales` | `boolean` | `false` | Desactiva los archivos de traducción por página. Cuando es `true`, solo se cargan las traducciones globales (`\{locale\}.json`); los archivos específicos de página (`pages/\{page\}/\{locale\}.json`) no se generan ni se cargan. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Código de idioma de fallback global. Cuando falta una clave de traducción en el idioma activo, el módulo la busca en este idioma antes de devolver la propia clave. |

## Payloads y caché

Cómo llegan las traducciones al navegador. [Rendimiento](/guides/performance) explica qué cambian estos en runtime.

| Opción | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Precarga las traducciones de la página de índice en middleware global de Nitro (solo servidor, config privada). |
| `apiBaseUrl` | `string` | `'_locales'` | Segmento base de la ruta de la API de traducciones (usado en la obtención de datos SSR/SSG). También se puede establecer mediante la variable de entorno `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Anula el host usado para las solicitudes de obtención de traducciones del lado cliente. Útil cuando el cliente accede al servidor con un hostname distinto al que ve Nuxt. También se puede establecer mediante la variable de entorno `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Anula el host usado para las solicitudes de obtención de traducciones del lado servidor. Útil en configuraciones de contenedores/microservicios donde el servidor se accede a sí mismo con un hostname interno. También se puede establecer mediante la variable de entorno `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Controla cómo se emiten los payloads de traducción (Node: `public/<apiBaseUrl>`; Edge: `serverAssets` de Nitro). - **Node**: `serverAssets` significa SSR local mediante `readFile` bajo `public/` (sin `raw:` de Rollup). - **Edge**: `serverAssets` registra `serverAssets` de Nitro (`assets:i18n`); no fuerza una copia pública. Mantén los valores por defecto para la configuración habitual todo en uno. Para catálogos Edge grandes, prefiere `mode: 'source'`. Para despliegues respaldados por CDN, desactiva las salidas locales y establece `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Estrategia de payload de traducción. - `premerged`: matriz `\{page\}/\{locale\}/data.json` en tiempo de compilación (por defecto). - `source`: archivos fuente compactos fusionados en runtime (preferido en Edge / catálogos grandes). |
| `translationPayloads.serverAssets` | `boolean` | `true` | Payloads SSR locales: Node lee `public/<apiBaseUrl>` (fuerza copia pública); Edge incrusta mediante `serverAssets` de Nitro. - **Node**: sin `serverAssets` de Nitro (evita `raw:` de Rollup). SSR lee   `public/<apiBaseUrl\|publicDir>` como `\{page\}/\{locale\}/data.json`; cuando esto es `true`,   se fuerza una copia pública incluso si `publicAssets` es false. - **Edge** (`nitro.node === false`): `serverAssets` de Nitro (`assets:i18n`) con la misma   disposición que `mode`. **No** fuerza una copia pública. Establece `publicAssets: true` para CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Registra la ruta de servidor integrada en `/\{apiBaseUrl\}/:page/:locale/data.json`. Desactívalo cuando los payloads de traducción se sirvan desde un host/CDN externo. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Copia los payloads en la salida pública de Nitro. Premerged → `\{page\}/\{locale\}/data.json` bajo `apiBaseUrl`; source → árbol compacto. En Node este árbol es también la fuente SSR cuando `serverAssets` fuerza una copia pública. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Optar por Nitro-prerender de `/\{apiBaseUrl\}/.../data.json`. Normalmente redundante cuando `publicAssets` premerged ya ha escrito esos archivos. |
| `translationPayloads.publicDir` | `string` | — | Carpeta de salida pública relativa a la raíz pública de Nitro. Por defecto es `apiBaseUrl` (`_locales`). De modo que los archivos estáticos coincidan con las URLs de fetch del cliente (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Avisa durante la compilación cuando el número de archivos de payload generados supera este umbral. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Avisa durante la compilación cuando el tamaño total de payloads generados supera este umbral en bytes. |

## SEO

Etiquetas meta generadas para cada página localizada.

| Opción | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Genera etiquetas meta SEO (`hreflang`, `canonical`, `og:url`, `og:locale`) automáticamente. |
| `metaBaseUrl` | `string` | `undefined` | URL base para las etiquetas meta SEO (canonical, og:url, hreflang). - Una cadena de URL concreta (por ejemplo, `'https://example.com'`) — se usa tal cual (máxima prioridad). - `undefined` — recurre a `site.url` de `nuxt-site-config` cuando ese módulo está presente; de lo contrario, al origen de la solicitud actual   (`useRequestURL().origin` en servidor, `window.location.origin` en cliente). |
| `metaTrustForwardedHost` | `boolean` | `true` | Confía en el encabezado `X-Forwarded-Host` al resolver la URL base para las etiquetas meta. Actívalo cuando la app se ejecuta detrás de un proxy inverso (nginx, Cloudflare, AWS ALB, etc.) que establece este encabezado con el hostname real orientado al cliente. |
| `metaTrustForwardedProto` | `boolean` | `true` | Confía en el encabezado `X-Forwarded-Proto` al resolver el protocolo para las etiquetas meta. Actívalo cuando la app se ejecuta detrás de un proxy que termina TLS para que las URLs canónicas usen `https://` aunque la app escuche en HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Lista de nombres de parámetros de consulta que se preservan en las etiquetas meta canonical y `og:url`. Los parámetros que no estén en esta lista se eliminan de la URL canónica. |

## Detección y redirecciones

Elegir un idioma para un visitante que no ha elegido uno.

| Opción | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Activa las redirecciones automáticas basadas en idioma. Cuando es `true`, los visitantes son redirigidos a su idioma preferido (detectado desde cookie, encabezado `Accept-Language` o el por defecto) en la primera visita. |
| `autoDetectLanguage` | `boolean` | `true` | Detecta automáticamente el idioma preferido del usuario desde el encabezado HTTP `Accept-Language`. Se usa junto con `autoDetectPath` para decidir cuándo ocurre la detección. |
| `autoDetectPath` | `string` | `'/'` | Dónde pueden ejecutarse las redirecciones por preferencia de cookie / Accept-Language (cuando `redirects` está activado). - `'/'` — solo `/` (los enlaces profundos en el idioma por defecto siguen siendo accesibles; por defecto). - `'no_prefix'` — solo rutas sin prefijo de idioma. - `'*'` — cada ruta, incluyendo reescribir un prefijo de idioma explícito   (por ejemplo, `/fr/about` → `/de/about` cuando la cookie prefiere `de`). - cualquier otra cadena — coincidencia exacta de ruta (por ejemplo, `'/welcome'`). La limpieza de estrategia con prefijo (p. ej. `/en` → `/` en `prefix_except_default`) no está condicionada. |

## Registro

Partes del módulo que puedes desactivar.

| Opción | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Registra el plugin de macro `defineI18nRoute()`, permitiendo llamadas por página a `defineI18nRoute()`. |
| `plugin` | `boolean` | `true` | Registra el plugin i18n central que proporciona `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` y otros helpers de runtime. |
| `hooks` | `boolean` | `true` | Registra el plugin de hooks de i18n que proporciona los hooks a nivel de app `i18n:register` y `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`. |
| `components` | `boolean` | `true` | Registra los componentes integrados de i18n (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Ponlo en `false` para desactivar el registro automático de componentes (por ejemplo, si no los usas y quieres reducir el footprint del módulo). |
| `types` | `boolean` | `true` | Genera declaraciones de tipos TypeScript para `useI18n`, `$t` y helpers relacionados basándose en las claves de traducción de los archivos del idioma por defecto. |
| `debug` | `boolean` | `false` | Activa un registro de depuración verboso para detección de idioma, generación de rutas y carga de traducciones. |

## Otros

| Opción | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | Emite también un `hreflang` de idioma desnudo derivado del `iso` de cada idioma (por ejemplo, `es-ES` → también `es`). El primer idioma regional en `locales` reclama la etiqueta desnuda para ese idioma. El `code` de enrutamiento nunca se usa. Solo `iso \|\| code`. |
| `vueDevtools` | `boolean` | `true` | Registra el inspector y la línea de tiempo de Vue DevTools en dev (extensión de navegador). Independiente de la pestaña personalizada de Nuxt DevTools. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Prefijo añadido a los nombres de rutas localizadas (por ejemplo, `'localized-index'`). Se usa internamente para distinguir rutas originales de las variantes de idioma generadas. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Desactivación por ruta de etiquetas meta, extraída de las llamadas a `defineI18nRoute()`. Asocia una ruta a `true` (desactivar todas las meta) o un arreglo de códigos de idioma para los que deben desactivarse las meta. |
| `missingWarn` | `boolean` | `true` | Muestra avisos en consola cuando falta una clave de traducción. |
| `hmr` | `boolean` | `true` | Activa Hot Module Replacement para archivos de traducción en desarrollo. Cuando es `true`, los cambios en los archivos JSON de traducción disparan una recarga automática sin refresco completo de página. |
| `cacheMaxSize` | `number` | `0` | Número máximo de entradas en la caché de traducciones en memoria. `0` significa sin límite. |
| `cacheTtl` | `number` | `0` | Tiempo de vida (en segundos) para las entradas de traducción en caché. `0` significa que las entradas nunca expiran. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Formatos numéricos con nombre por idioma (compatibles con Vue I18n). Permite llamadas del estilo `$tn(1000, 'currency')`. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Formatos de fecha y hora con nombre por idioma (compatibles con `datetimeFormats` de Vue I18n). Permite llamadas del estilo `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | `max-age` de `Cache-Control` HTTP (segundos) para `/\{apiBaseUrl\}/:page/:locale/data.json`. Se aplica completamente solo mientras `dateBuild` invalida la URL (`?v=...`), lo cual es el por defecto: la respuesta es entonces `public, max-age=…, immutable` y segura para navegadores y CDN. - `dateBuild: 0`/`''` — la URL es estable, por lo que esta duración *no* se respeta;   la respuesta se convierte en `public, max-age=0, must-revalidate`. Un `max-age` largo en una   URL que no cambia fija el primer payload que un navegador vio jamás. - `0` — no establecer `Cache-Control` en absoluto (útil en depuración local). - No se aplica en desarrollo (`import.meta.dev`) para que la caché del navegador no combata al HMR. - Solo alcanza a las respuestas servidas a través de Nitro. Los payloads copiados a `public/` y servidos   por la plataforma de hosting toman los encabezados de esa plataforma. Consulta la guía de Rendimiento. Análogo al `httpCacheDuration` experimental de `@nuxtjs/i18n` (v10.2.0), pero como encabezado de respuesta explícito en lugar de `maxAge` de `defineCachedEventHandler` de Nitro. |
| `dateBuild` | `string \| number` | — | Valor usado para cache-busting de solicitudes de traducción (`?v=...`). Cuando no se proporciona, el módulo recurre a `Date.now()` (no determinista). Para despliegues reproducibles/graduales, establécelo en un valor estable (por ejemplo, un SHA de git o un número de compilación). |
| `experimental` | `Record<string, unknown>` | — | Contenedor para opciones experimentales/inestables. Los contenidos pueden cambiar o eliminarse sin previo aviso entre versiones menores. |
