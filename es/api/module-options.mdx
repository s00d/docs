# Referencia de opciones del módulo

Todas las opciones que acepta `nuxt-i18n-micro`, leídas en tiempo de compilación desde la interfaz `ModuleOptions` en
[`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).
Nada aquí se escribe a mano, por lo que no puede quedarse desactualizado respecto al código: los tipos, valores por defecto y descripciones provienen de la propia declaración.

Para entender lo que estas opciones *significan* en conjunto (qué combinaciones tienen sentido, qué cambia al cambiar de estrategia, ejemplos trabajados), consulta [Configuración](/guides/configuration). Esta página es el listado exhaustivo; la otra es la explicación.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Las opciones anidadas aparecen bajo su ruta con puntos, por lo que `translationPayloads.mode` es la clave `mode` dentro del objeto `translationPayloads`.

## Locales y enrutamiento

Qué idiomas existen y cómo aparecen en la URL.

| Opción | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Lista de locales admitidos. Cada entrada define un código de locale más metadatos opcionales (ISO, dirección, nombre para mostrar, etc.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Estrategia de enrutamiento de URL para los prefijos de locale. - `'no_prefix'`: sin locale en la URL; el locale se almacena en cookie. - `'prefix_except_default'`: añade prefijo a todos los locales excepto al predeterminado. - `'prefix'`: siempre añade prefijo, incluyendo el locale predeterminado. - `'prefix_and_default'`: como `prefix`, pero el locale predeterminado también es accesible sin prefijo. |
| `defaultLocale` | `string` | `'en'` | El locale que se usa cuando no puede determinarse desde la URL ni desde las preferencias del usuario. También se usa como locale de reserva para traducciones faltantes cuando no se establece `fallbackLocale`. |
| `localeCookie` | `string \| null` | `null` | Nombre de la cookie para persistir la preferencia de locale del usuario entre sesiones. Establece `null` para deshabilitar la persistencia basada en cookies. Se establece automáticamente en `'user-locale'` para la estrategia `no_prefix` si no se proporciona. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Configuración global de locale a nivel de ruta. Permite restringir o personalizar rutas de locale para páginas específicas sin modificar sus componentes. - `false`: excluye la ruta de la localización. - `Record<LocaleCode, string>`: rutas personalizadas por locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (usa el patrón integrado basado en los códigos de locale)` | Expresión regular personalizada (o su fuente como cadena) para coincidir con los códigos de locale en los segmentos de URL. Todos los códigos de locale definidos en `locales` deben coincidir con este patrón, o se emitirá una advertencia. |
| `noPrefixRedirect` | `boolean` | `false` | Para la estrategia `no_prefix`: habilita la redirección desde una URL con prefijo de locale (por ejemplo, `/en/about`) a la versión sin prefijo (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Patrones de URL (cadenas o RegExp) para excluir por completo del procesamiento de i18n. Las rutas coincidentes no recibirán prefijos de locale, redirecciones ni carga de traducciones. Las rutas internas de Nuxt (`/__nuxt_error`, etc.) siempre se excluyen automáticamente. |
| `routeLocales` | `Record<string, string[]>` | — | Restricciones de locale por ruta, extraídas de las llamadas a `defineI18nRoute()`. Mapea una ruta (por ejemplo, `'/about'`) a un array de códigos de locale permitidos. Las rutas no listadas no tienen restricciones (todos los locales permitidos). |

## Traducciones

Dónde residen los archivos de traducción y cómo se resuelven las claves.

| Opción | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Ruta al directorio que contiene los archivos JSON de traducción, relativa a la raíz del proyecto. |
| `disableWatcher` | `boolean` | `false` | Deshabilita el observador de archivos que crea automáticamente archivos de traducción faltantes en modo desarrollo. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Mapea nombres de ruta a otros nombres de ruta para compartir los mismos archivos de traducción. Por ejemplo, `\{ 'about-us': 'about' \}` significa que la página `about-us` usará las traducciones de la página `about` en lugar de las suyas propias. |
| `plural` | `PluralFunc` | `pluralización integrada (índice de forma según recuento)` | Función de pluralización personalizada. Recibe `(key, count, params, locale, getter)` y debe devolver la forma plural seleccionada como cadena, o `null`/`undefined` para recurrir a la lógica integrada `defaultPlural` (de modo que puedas sobrescribir solo algunos locales). Para el módulo de Nuxt, la función se serializa con `.toString()` en `.nuxt/i18n.plural.mjs`; debe ser autocontenida (sin imports ni ámbito externo). **No** se admite una cadena con ruta de archivo. |
| `disablePageLocales` | `boolean` | `false` | Deshabilita los archivos de traducción por página. Cuando es `true`, solo se cargan las traducciones globales (`\{locale\}.json`); los archivos específicos por página (`pages/\{page\}/\{locale\}.json`) no se generan ni se cargan. |
| `fallbackLocale` | `string` | `undefined (sin reserva; devuelve la clave sin traducir)` | Código de locale de reserva global. Cuando falta una clave de traducción en el locale activo, el módulo la busca en este locale antes de devolver la clave misma. |

## Payloads y caché

Cómo llegan las traducciones al navegador. [Rendimiento](/guides/performance) explica lo que cambian estas opciones en tiempo de ejecución.

| Opción | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Precarga las traducciones de la página de índice en el middleware global de Nitro (solo servidor, configuración privada). |
| `apiBaseUrl` | `string` | `'_locales'` | Segmento de ruta base para la ruta de la API de traducciones (usado en la obtención de datos SSR/SSG). También puede establecerse mediante la variable de entorno `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Sobrescribe el host usado para las peticiones de obtención de traducciones del lado del cliente. Útil cuando el cliente accede al servidor a través de un nombre de host distinto al que ve Nuxt. También puede establecerse mediante la variable de entorno `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Sobrescribe el host usado para las peticiones de obtención de traducciones del lado del servidor. Útil en configuraciones de contenedores/microservicios donde el servidor se accede a sí mismo mediante un nombre de host interno. También puede establecerse mediante la variable de entorno `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Controla cómo se emiten los payloads de traducción (Node: `public/<apiBaseUrl>`; Edge: `serverAssets` de Nitro). - **Node**: `serverAssets` implica SSR local mediante `readFile` bajo `public/` (sin `raw:` de Rollup). - **Edge**: `serverAssets` registra `serverAssets` de Nitro (`assets:i18n`); no fuerza una copia pública. Mantén los valores por defecto para la configuración habitual todo-en-uno. Para catálogos grandes en Edge, prefiere `mode: 'source'`. Para despliegues respaldados por CDN, deshabilita las salidas locales y establece `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Estrategia del payload de traducciones. - `premerged`: matriz `\{page\}/\{locale\}/data.json` en tiempo de compilación (predeterminado). - `source`: archivos fuente compactos fusionados en tiempo de ejecución (preferible en Edge / catálogos grandes). |
| `translationPayloads.serverAssets` | `boolean` | `true` | Payloads de SSR local: Node lee `public/<apiBaseUrl>` (fuerza la copia pública); Edge los embebe mediante `serverAssets` de Nitro. - **Node**: sin `serverAssets` de Nitro (evita `raw:` de Rollup). El SSR lee `public/<apiBaseUrl\|publicDir>` como `\{page\}/\{locale\}/data.json`; cuando esto es `true`, se fuerza una copia pública incluso si `publicAssets` es falso. - **Edge** (`nitro.node === false`): `serverAssets` de Nitro (`assets:i18n`) con la misma disposición que `mode`. **No** fuerza una copia pública; establece `publicAssets: true` para CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Registra la ruta de servidor integrada en `/\{apiBaseUrl\}/:page/:locale/data.json`. Deshabilítalo cuando los payloads de traducción se sirvan desde un host/CDN externo. |
| `translationPayloads.publicAssets` | `boolean` | `true en modo premerged, false en modo source` | Copia los payloads en la salida pública de Nitro. Premerged → `\{page\}/\{locale\}/data.json` bajo `apiBaseUrl`; source → árbol compacto. En Node, este árbol también es la fuente para SSR cuando `serverAssets` fuerza una copia pública. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Habilitar el prerenderizado de Nitro para `/\{apiBaseUrl\}/.../data.json`. Suele ser redundante cuando `publicAssets` en premerged ya ha escrito esos archivos. |
| `translationPayloads.publicDir` | `string` | — | Carpeta de salida pública relativa a la raíz pública de Nitro. Su valor por defecto es `apiBaseUrl` (`_locales`), de modo que los archivos estáticos coincidan con las URL de fetch del cliente (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Advertir durante la compilación cuando el recuento de archivos de payload generados supere este umbral. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Advertir durante la compilación cuando el tamaño total de los payloads generados supere este umbral en bytes. |

## SEO

Meta etiquetas generadas para cada página localizada.

| Opción | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Genera automáticamente meta etiquetas SEO (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | URL base para las meta etiquetas SEO (canonical, og:url, hreflang). - Una cadena con URL concreta (por ejemplo, `'https://example.com'`): se usa tal cual (máxima prioridad). - `undefined`: recurre a `site.url` de `nuxt-site-config` cuando ese módulo está presente; en caso contrario, al origen de la petición actual (`useRequestURL().origin` en el servidor, `window.location.origin` en el cliente). |
| `metaTrustForwardedHost` | `boolean` | `true` | Confía en la cabecera `X-Forwarded-Host` al resolver la URL base para las meta etiquetas. Habilítalo cuando la aplicación se ejecute detrás de un proxy inverso (nginx, Cloudflare, AWS ALB, etc.) que establece esta cabecera con el nombre de host real de cara al cliente. |
| `metaTrustForwardedProto` | `boolean` | `true` | Confía en la cabecera `X-Forwarded-Proto` al resolver el protocolo para las meta etiquetas. Habilítalo cuando la aplicación se ejecute detrás de un proxy que termina TLS, para que las URL canónicas usen `https://` aunque la aplicación escuche por HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Lista de nombres de parámetros de consulta preservados en las meta etiquetas canonical y `og:url`. Los parámetros que no estén en esta lista se eliminan de la URL canónica. |

## Detección y redirecciones

Elección de un locale para un visitante que aún no ha seleccionado uno.

| Opción | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Habilita las redirecciones automáticas basadas en el locale. Cuando es `true`, los visitantes son redirigidos a su locale preferido (detectado desde la cookie, la cabecera `Accept-Language` o el predeterminado) en la primera visita. |
| `autoDetectLanguage` | `boolean` | `true` | Detecta automáticamente el idioma preferido del usuario desde la cabecera HTTP `Accept-Language`. Se usa junto con `autoDetectPath` para decidir cuándo tiene lugar la detección. |
| `autoDetectPath` | `string` | `'/'` | Dónde pueden ejecutarse las redirecciones basadas en cookie / preferencia Accept-Language (cuando `redirects` está habilitado). - `'/'`: solo `/` (los enlaces profundos en el locale predeterminado siguen siendo accesibles; predeterminado). - `'no_prefix'`: solo rutas sin prefijo de locale. - `'*'`: todas las rutas, incluyendo la reescritura de un prefijo de locale explícito (por ejemplo, `/fr/about` → `/de/about` cuando la cookie prefiere `de`). - Cualquier otra cadena: coincidencia exacta de ruta (por ejemplo, `'/welcome'`). La limpieza en estrategias con prefijo (por ejemplo, `/en` → `/` con `prefix_except_default`) no está condicionada. |

## Registro

Partes del módulo que puedes desactivar.

| Opción | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Registra el plugin de macro `defineI18nRoute()`, habilitando llamadas `defineI18nRoute()` por página. |
| `plugin` | `boolean` | `true` | Registra el plugin principal de i18n que proporciona `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` y otros helpers de runtime. |
| `hooks` | `boolean` | `true` | Registra el plugin de hooks de i18n que proporciona los hooks a nivel de aplicación `i18n:register` e `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`. |
| `components` | `boolean` | `true` | Registra los componentes i18n integrados (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Establécelo en `false` para deshabilitar el registro automático de componentes (por ejemplo, si no los usas y quieres reducir la huella del módulo). |
| `types` | `boolean` | `true` | Genera declaraciones de tipos de TypeScript para `useI18n`, `$t` y helpers relacionados a partir de las claves de traducción en los archivos de tu locale predeterminado. |
| `debug` | `boolean` | `false` | Habilita el registro detallado de depuración para la detección de locale, la generación de rutas y la carga de traducciones. |

## Otros

| Opción | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | Emite también un `hreflang` de idioma sin región derivado del `iso` de cada locale (por ejemplo, `es-ES` → también `es`). El primer locale regional en `locales` reclama la etiqueta sin región para ese idioma. El `code` de enrutamiento nunca se usa; solo `iso \|\| code`. |
| `vueDevtools` | `boolean` | `true` | Registra el inspector y la línea de tiempo de Vue DevTools en desarrollo (extensión del navegador). Independiente de la pestaña personalizada de Nuxt DevTools. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Prefijo antepuesto a los nombres de ruta localizados (por ejemplo, `'localized-index'`). Se usa internamente para distinguir las rutas originales de las variantes de locale generadas. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Deshabilitación de meta etiquetas por ruta, extraída de las llamadas a `defineI18nRoute()`. Mapea una ruta a `true` (deshabilita todas las meta) o a un array de códigos de locale para los que las meta deben deshabilitarse. |
| `missingWarn` | `boolean` | `true` | Muestra advertencias en la consola cuando falta una clave de traducción. |
| `hmr` | `boolean` | `true` | Habilita Hot Module Replacement para archivos de traducción en desarrollo. Cuando es `true`, los cambios en archivos JSON de traducción disparan una recarga automática sin un refresco completo de página. |
| `cacheMaxSize` | `number` | `0` | Número máximo de entradas en la caché de traducciones en memoria. `0` significa sin límite. |
| `cacheTtl` | `number` | `0` | Tiempo de vida (en segundos) para las entradas de traducción cacheadas. `0` significa que las entradas nunca expiran. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Formatos de número con nombre por locale (compatibles con Vue I18n). Habilita llamadas al estilo `$tn(1000, 'currency')`. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Formatos de fecha/hora con nombre por locale (`datetimeFormats` compatible con Vue I18n). Habilita llamadas al estilo `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | HTTP `Cache-Control` max-age (segundos) para `/\{apiBaseUrl\}/:page/:locale/data.json`. Se aplica en su totalidad solo mientras `dateBuild` invalida la URL (`?v=...`), que es el valor predeterminado: entonces la respuesta es `public, max-age=…, immutable` y segura para navegadores y CDN. - `dateBuild: 0`/`''`: la URL es estable, por lo que esta duración *no* se respeta; la respuesta pasa a ser `public, max-age=0, must-revalidate`. Un `max-age` largo en una URL invariable ancla el primer payload que el navegador vio. - `0`: no establece `Cache-Control` en absoluto (útil en depuración local). - No se aplica en desarrollo (`import.meta.dev`) para que el HMR no luche contra la caché del navegador. - Alcanza solo respuestas servidas a través de Nitro. Los payloads copiados a `public/` y servidos por la plataforma de hosting toman las cabeceras de esa plataforma; consulta la guía de rendimiento. Análogo a `httpCacheDuration` experimental de `@nuxtjs/i18n` (v10.2.0), pero como cabecera de respuesta explícita en lugar de `maxAge` de `defineCachedEventHandler` de Nitro. |
| `dateBuild` | `string \| number` | — | Valor usado para invalidar la caché en las peticiones de traducciones (`?v=...`). Cuando no se proporciona, el módulo recurre a `Date.now()` (no determinista). Para despliegues reproducibles/rolling, establece un valor estable (por ejemplo, un SHA de git o un número de compilación). |
| `experimental` | `Record<string, unknown>` | — | Contenedor para opciones experimentales/inestables. El contenido puede cambiar o eliminarse sin previo aviso entre versiones menores. |
