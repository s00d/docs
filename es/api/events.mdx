# 📢 Eventos

## 🔄 `i18n:register`

El evento `i18n:register` en `Nuxt I18n Micro` permite añadir dinámicamente traducciones al contexto i18n de tu aplicación, haciendo que el proceso de internacionalización sea fluido y flexible. Este evento te permite integrar nuevas traducciones según sea necesario, mejorando las capacidades de localización de tu aplicación.

### 📝 Detalles del evento

- **Propósito**:
  - Permite incorporar dinámicamente traducciones adicionales al conjunto existente para un locale específico.

- **Payload**:
  - **`register`**:
    - Una función proporcionada por el evento que toma dos argumentos:
      - **`translations`** (`Translations`):
        - Un objeto que contiene pares clave-valor que representan traducciones, organizados según la interfaz `Translations`.
      - **`locale`** (`string`, opcional):
        - El código de locale (por ejemplo, `'en'`, `'ru'`) para el que se registran las traducciones. Toma como valor predeterminado el locale proporcionado por el evento si no se especifica.

- **Comportamiento**:
  - Al activarse, la función `register` fusiona las nuevas traducciones en el contexto actual para el locale especificado, actualizando las traducciones disponibles en la aplicación.

### ⏱️ Cuándo se dispara

El plugin de hooks del módulo (`05.hooks.ts`, `dependsOn: ['i18n-plugin-loader']`) llama a `nuxtApp.callHook('i18n:register', …)`:

1. **Una vez al inicio**: después de que el plugin i18n principal (`01.plugin.ts`) haya cargado las traducciones para la ruta inicial.
2. **En la navegación**: en `router.beforeEach` cuando la ruta cambia, o en cada navegación cuando `strategy: 'no_prefix'`.

Registra tu listener en un plugin normal de Nuxt con `nuxtApp.hook('i18n:register', …)`. El plugin de hooks se ejecuta después de que el loader esté listo, por lo que tu callback se invoca cuando las traducciones necesitan ampliarse.

Establece `hooks: false` en `nuxt.config` para deshabilitar las llamadas automáticas a `i18n:register` (consulta [Configuración — `hooks`](/guides/configuration#hooks)).

### 💡 Ejemplo de uso

El siguiente ejemplo muestra cómo usar el evento `i18n:register` para añadir traducciones dinámicamente:

```typescript
nuxt.hook('i18n:register', async (register: (translations: unknown, locale?: string) => void, locale: string) => {
  register(
    {
      greeting: 'Hello',
      farewell: 'Goodbye',
    },
    locale,
  )
})
```

### 🔗 Beneficios clave

- **Actualizaciones dinámicas**:
  - Actualiza o añade fácilmente traducciones sin necesidad de volver a desplegar toda la aplicación.

- **Flexibilidad de localización**:
  - Admite ajustes de localización en tiempo real basados en las necesidades del usuario o la aplicación.

Usando el evento `i18n:register`, puedes asegurar que la estrategia de localización de tu aplicación se mantenga flexible y adaptable, mejorando la experiencia general del usuario.

## 🛠️ Modificar traducciones con plugins

Para modificar traducciones dinámicamente en tu aplicación Nuxt, se recomienda usar plugins. Los plugins proporcionan una forma estructurada de gestionar actualizaciones de localización, especialmente cuando se trabaja con módulos o archivos de traducción externos.

### **Registrar el plugin**

Si usas un módulo, registra el plugin donde ocurrirán las modificaciones de traducción añadiéndolo a la configuración de tu módulo:

```javascript
addPlugin({
  src: resolve('./plugins/extend_locales'),
})
```

Esto registra el plugin ubicado en `./plugins/extend_locales`, que gestionará la carga y el registro dinámicos de traducciones.

### **Implementar el plugin**

En el plugin puedes gestionar las modificaciones de locale. Este es un ejemplo de implementación en un plugin de Nuxt:

```typescript
import { defineNuxtPlugin } from '#app'

export default defineNuxtPlugin(async (nuxtApp) => {
  // Function to load translations from JSON files and register them
  const loadTranslations = async (lang: string) => {
    try {
      const translations = await import(`../locales/${lang}.json`)
      return translations.default
    } catch (error) {
      console.error(`Error loading translations for language: ${lang}`, error)
      return null
    }
  }

  // Hook into the 'i18n:register' event to dynamically add translations
  // eslint-disable-next-line @typescript-eslint/ban-ts-comment
  // @ts-expect-error
  nuxtApp.hook('i18n:register', async (register: (translations: unknown, locale?: string) => void, locale: string) => {
    const translations = await loadTranslations(locale)
    if (translations) {
      register(translations, locale)
    }
  })
})
```

### 📝 Explicación detallada

1. **Carga de traducciones**:

- La función `loadTranslations` importa dinámicamente los archivos de traducción según el locale. Se espera que los archivos estén en el directorio `locales` y nombrados según los códigos de locale (por ejemplo, `en.json`, `de.json`).
- Si la carga tiene éxito, se devuelven las traducciones; de lo contrario, se registra un error.

2. **Registro de traducciones**:

- El plugin se engancha al evento `i18n:register` mediante `nuxtApp.hook`.
- Cuando se dispara el evento, se llama a la función `register` con las traducciones cargadas y el locale correspondiente.
- Esto fusiona las nuevas traducciones en el contexto de i18n para el locale especificado, actualizando las traducciones disponibles en toda la aplicación.

### 🔗 Beneficios de usar plugins para modificar traducciones

- **Separación de responsabilidades**:
  - Encapsula la lógica de localización separada del código principal de la aplicación, facilitando la gestión y el mantenimiento.

- **Dinámico y escalable**:
  - Al cargar y registrar traducciones dinámicamente, puedes actualizar el contenido sin necesidad de un redespliegue completo de la aplicación, lo cual es especialmente útil para aplicaciones con contenido frecuentemente actualizado o multilingüe.

- **Mayor flexibilidad de localización**:
  - Los plugins te permiten modificar o ampliar las traducciones según sea necesario, proporcionando una estrategia de localización más adaptable y receptiva que satisface las preferencias del usuario o los requisitos del negocio.

Al adoptar este enfoque, puedes expandir y modificar de manera eficiente la localización de tu aplicación mediante un proceso estructurado y mantenible con plugins, manteniendo la internacionalización adaptable a necesidades cambiantes y mejorando la experiencia general del usuario.
