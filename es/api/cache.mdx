# 🗄️ Arquitectura de caché y almacenamiento de traducciones

## 📖 Resumen

Nuxt I18n Micro v3 utiliza una arquitectura de caché multicapa para las traducciones. La carga del payload depende de `translationPayloads.mode`:

- **`premerged`** (predeterminado): los archivos de raíz, página, reserva y capas se fusionan en tiempo de compilación mediante `@i18n-micro/utils/build` en `\{page\}/\{locale\}/data.json`.
- **`source`**: se mantienen archivos fuente compactos para su fusión en tiempo de ejecución mediante `@i18n-micro/utils/source-loader` y `@i18n-micro/utils/merge-source` (Edge los embebe en `serverAssets` de Nitro; Node los lee desde `public/` cuando se copian).

Esta página describe cómo funciona la caché integrada y cómo extenderla para casos de uso personalizados (herramientas de administración, APIs externas, invalidación de caché).

## 🧱 Componentes principales

### 1. `TranslationStorage` (cliente + servidor)

**Archivo**: `src/runtime/utils/storage.ts`

Una clase singleton que proporciona almacenamiento unificado de traducciones tanto para cliente como para servidor. Utiliza `Symbol.for('__NUXT_I18N_STORAGE_CACHE__')` en `globalThis` para garantizar que solo exista una instancia, incluso cuando se cargan varios bundles.

**Métodos clave:**

| Método                              | Descripción                                                            |
| ----------------------------------- | ---------------------------------------------------------------------- |
| `getFromCache(locale, routeName?)`  | Comprobación síncrona: devuelve los datos cacheados en memoria o `null`. |
| `load(locale, routeName?, options)` | Carga asíncrona con caché: comprueba primero la caché y luego obtiene los datos mediante `$fetch`. |
| `clear()`                           | Limpia toda la caché.                                                  |

**Formato de la clave de caché**: `\{locale\}:\{routeName\}` (por ejemplo, `en:index`, `fr:about`).

```typescript
import { translationStorage } from '../utils/storage'

// Synchronous cache check
const cached = translationStorage.getFromCache('en', 'index')

// Async load (with automatic caching)
const result = await translationStorage.load('en', 'index', {
  apiBaseUrl: '_locales',
  baseURL: '/',
  dateBuild: '2024-01-01',
})
// result.data — merged translations
// result.cacheKey — cache key used
```

### ⚙️ Invalidación determinista de la caché (`i18n.dateBuild`)

De forma predeterminada, este módulo genera `dateBuild` en tiempo de compilación usando `Date.now()`. Luego se embebe en el `#build/i18n.strategy.mjs` generado y se usa como parámetro de consulta (`?v=...`) para invalidar las cachés de fetch de traducciones tras las recompilaciones.

Si necesitas compilaciones reproducibles (por ejemplo, para mejorar las tasas de acierto de caché de los chunks en despliegues rolling), establece un valor estable en `nuxt.config`:

```ts
export default defineNuxtConfig({
  i18n: {
    // Any stable string/number (git SHA, CI build number, release tag, etc.)
    dateBuild: process.env.GIT_SHA ?? 'local-dev',
  },
})
```

### 2. `loadTranslationsFromServer()` (solo servidor)

**Archivo**: `src/runtime/server/utils/server-loader.ts`

Carga las traducciones para un locale/página y almacena el resultado fusionado en una `CacheControl` global del proceso, indexada por `@i18n-micro/hmr/cache-keys` (`SERVER_CC_KEY`).

Comportamiento: el SSR carga desde `#i18n-internal/payload-source` — en **Node** con `readFile` bajo `public/<apiBaseUrl>` (`\{page\}/\{locale\}/data.json` en modo premerged), en **Edge** con `assets:i18n`. `premerged` lee un archivo; `source` fusiona raíz/página/reserva mediante `@i18n-micro/utils/source-loader`.

```typescript
import { loadTranslationsFromServer } from '../server/utils/server-loader'

// Returns { data: Translations, json: string }
const { data, json } = await loadTranslationsFromServer('en', 'index')
```

### 3. Carga del cliente (sin embed en HTML)

Los diccionarios **no** se escriben en `nuxtApp.payload`. El servidor los mantiene en memoria para el renderizado SSR; el plugin del cliente hace `await` de `switchContext`, que carga `/\{apiBaseUrl\}/:page/:locale/data.json` (misma postura por defecto que `@nuxtjs/i18n` con `experimental.preload: false`).

`NuxtI18n` mantiene el diccionario activo de la capa de vista usado por `$t()` y `$has()`. `NuxtTranslationLoader` cambia el contexto de locale/ruta y fusiona los chunks en esa capa.

### 4. Ruta de API del servidor

**Ruta**: `/_locales/\{page\}/\{locale\}/data.json`

**Archivo**: `src/runtime/server/routes/i18n.ts`

Esta ruta de Nitro sirve las traducciones fusionadas para el modo de payload activo. Llama a `loadTranslationsFromServer()` y devuelve el resultado como JSON.

En producción también establece:

```http
Cache-Control: public, max-age={httpCacheDuration}, immutable
```

El valor predeterminado de `httpCacheDuration` es `31536000` (1 año). Esto es seguro porque los clientes solicitan los payloads con invalidación de caché `?v=\{dateBuild\}`. Establece `httpCacheDuration: 0` para omitir la cabecera. La cabecera no se aplica en desarrollo.

## 📥 Extensión: carga personalizada de traducciones

### Leer desde la caché (ruta de servidor)

```ts
// server/api/i18n/load-cache.[post].ts
import { defineEventHandler, readBody } from 'h3'
import { loadTranslationsFromServer } from '#imports'

export default defineEventHandler(async (event) => {
  const { page, locale } = await readBody<{ page: string; locale: string }>(event)
  const { data } = await loadTranslationsFromServer(locale, page)
  return { locale, page, data }
})
```

### Actualizar traducciones (archivo + invalidar caché)

```ts
// server/api/i18n/update.[post].ts
import { defineEventHandler, readBody, createError } from 'h3'
import { join } from 'node:path'
import { readFile, writeFile } from 'node:fs/promises'
import { deepMergeTranslations } from '@i18n-micro/utils/deep-merge'

export default defineEventHandler(async (event) => {
  const { path, updates } = await readBody<{ path: string; updates: Record<string, unknown> }>(event)

  if (!path || !updates) {
    throw createError({ statusCode: 400, statusMessage: 'Missing path or updates' })
  }

  const fullPath = join('locales', path)
  let existing: Record<string, unknown> = {}

  try {
    const content = await readFile(fullPath, 'utf-8')
    existing = JSON.parse(content) as Record<string, unknown>
  } catch {
    // File does not exist — create new
  }

  const merged = deepMergeTranslations(existing, updates)
  await writeFile(fullPath, JSON.stringify(merged, null, 2), 'utf-8')

  return { success: true, path, updated: merged }
})
```

## 🧹 Limpiar la caché

### Limpieza programática de la caché (cliente)

Usa el método integrado `$clearCache`:

```vue
<script setup>
const { $clearCache } = useNuxtApp()

// Clears both TranslationStorage and plugin-level cache
$clearCache()
</script>
```

### Comportamiento de la caché del servidor

La caché del lado del servidor (`loadTranslationsFromServer`) es global al proceso y persiste hasta que:

- El proceso del servidor se reinicia.
- Se detecta un nuevo despliegue (valor distinto de `dateBuild`).

Para entornos serverless, cada arranque en frío tiene una caché nueva.

## ⚙️ Configuración serverless

Para entornos serverless (Cloudflare Workers, AWS Lambda), la caché integrada utiliza objetos `Map` en memoria. No se necesita configuración de almacenamiento externo para la caché de traducciones en sí.

Sin embargo, el almacenamiento de Nitro para los archivos fuente de traducción puede necesitar configuración:

```ts
export default defineNuxtConfig({
  nitro: {
    storage: {
      // Only needed if default file-system storage is unavailable
      'assets:server': {
        driver: 'cloudflare-kv-binding',
        binding: 'MY_KV_NAMESPACE',
      },
    },
  },
})
```

## 💡 Diferencias clave respecto a v2

| Aspecto           | v2                            | v3                                                                       |
| ---------------- | ----------------------------- | ------------------------------------------------------------------------ |
| Caché del cliente | `useStorage('cache')`         | Singleton `TranslationStorage` (Symbol.for en globalThis)                |
| Transferencia SSR | Runtime config                | Chunks completos vía `payload.data` (v3.0 usaba `useState`)              |
| Caché del servidor | Almacenamiento de caché de Nitro | `Map` global del proceso vía `Symbol.for`                                |
| Lógica de fusión  | Del lado del cliente          | En tiempo de compilación (`premerged`) o en tiempo de ejecución (`source`) vía `@i18n-micro/utils/*` |
| Formato de clave de caché | `i18n:merged:\{page\}:\{locale\}` | `\{locale\}:\{routeName\}`                                                   |
