# 🛠️ Métodos

Esta página documenta todos los métodos disponibles proporcionados por nuxt-i18n-micro. Los métodos están organizados por funcionalidad para facilitar la navegación.

## 📊 Descripción general de la API

Cada helper que el plugin inyecta, leído desde la interfaz `PluginsInjections`. Así esta lista no puede desviarse de lo que realmente está disponible.

| [`$_ts`](#_ts) | `(route: RouteLocationNormalizedLoaded) => (key: string, params?: Params, defaultValue?: string \| null) => string` | Enlaza `$ts` a una ruta específica. |

</Info>

### `$getI18nConfig`

{/* generated:method:$getI18nConfig — do not edit; run `pnpm run docs:generate` */}

```ts
() => ModuleOptionsExtend
```

La configuración del módulo resuelta, tal como la ve el runtime.

{/* /generated:method:$getI18nConfig */}

```typescript
const nuxtApp = useNuxtApp()
const { localeCookie, strategy, hooks } = nuxtApp.$getI18nConfig()
```

Para contextos en tiempo de compilación o sin Nuxt, usa en su lugar `getI18nConfig()` desde `#build/i18n.strategy.mjs`.

<Info>
`serverTranslationPreload` es una opción privada del módulo expuesta solo en la configuración privada del servidor (`#i18n-internal/config`). No forma parte de la API pública de runtime y puede cambiar sin previo aviso.
</Info>

## 🔍 Métodos de traducción

Métodos principales para obtener y gestionar traducciones.

### `$t`

{/* generated:method:$t — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params?: Params, defaultValue?: string | null) => CleanTranslation
```

Traduce una clave, interpolando `params` en ella. Devuelve `defaultValue` cuando la clave está ausente, o la propia clave cuando no se proporciona un valor por defecto.

{/* /generated:method:$t */}

```typescript
const welcomeMessage = $t('welcome', { username: 'Alice', unreadCount: 5 })
// Output: "Welcome, Alice! You have 5 unread messages."
```

<Warning>
`$t` devuelve `CleanTranslation`, que es `string | number | boolean | Translations | PluralTranslations | null`. Si la clave apunta a un **objeto anidado** en tu JSON (por ejemplo, `$t('header')` cuando el JSON contiene `\{ "header": \{ "title": "Hi" \} \}`), el valor de retorno será ese **objeto**, no una cadena. Usarlo directamente en una plantilla Vue (<code v-pre>\{\{ $t('header') \}\}</code>) se renderizará como `[object Object]`.

**Cómo evitarlo:**

- Usa una clave más específica: `$t('header.title')` → `"Hi"`.
- Usa `$ts()`, que siempre devuelve una cadena (llama a `.toString()` en no cadenas).
- Usa `$t` con una clave anidada para acceder intencionalmente a subobjetos para uso programático.
</Warning>

### `$ts`

{/* generated:method:$ts — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params?: Params, defaultValue?: string) => string
```

Como `$t`, pero siempre devuelve una cadena: un valor de objeto o arreglo se convierte a cadena en lugar de devolverse tal cual.

{/* /generated:method:$ts */}

```typescript
const welcomeMessage = $ts('welcome', { username: 'Alice', unreadCount: 5 })
// Output: "Welcome, Alice! You have 5 unread messages."
```

### `$_t` and `$_ts`

{/* generated:method:$_t — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNormalizedLoaded) => (key: string, params?: Params, defaultValue?: string | null) => CleanTranslation
```

Enlaza `$t` a una ruta específica, para traducir fuera de la página actual. Por ejemplo, un layout que renderiza un enlace a otra ruta.

{/* /generated:method:$_t */}

{/* generated:method:$_ts — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNormalizedLoaded) => (key: string, params?: Params, defaultValue?: string | null) => string
```

Enlaza `$ts` a una ruta específica. Consulta `$_t`.

{/* /generated:method:$_ts */}

Variantes de `$t` y `$ts` enlazadas a una ruta. Toman una **ruta** primero y devuelven una función de traducción bloqueada al idioma y al contexto de página de esa ruta.

- **Acceso**: `useNuxtApp()` (también reexportado por `useI18n()` como `$_t` / `$_ts`).

Usa estos cuando la ruta activa durante SSR o transiciones difiera de `router.currentRoute`. Por ejemplo, dentro de `<i18n-t>`, `<i18n-group>` o al renderizar contenido para un objeto `route` específico.

```typescript
import { useRoute, useNuxtApp } from '#imports'

const route = useRoute()
const { $_t, $_ts } = useNuxtApp()

const $t = $_t(route)
const title = $t('page.title')

// String-safe variant
const label = $_ts(route)('page.label')
```


### `$tc`

{/* generated:method:$tc — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params: number | Params, defaultValue?: string) => string
```

Traduce con pluralización. `params` puede ser el propio conteo o un objeto que contenga `count`.

{/* /generated:method:$tc */}

**Formato de traducción**: formas separadas por `|`. Coloca los placeholders en **cada** forma:

```json
{
  "apples": "no apples | one apple | {count} apples",
  "cart": "no items for {name} | one item for {name} | {count} items for {name}"
}
```

```typescript
$tc('apples', 0) // "no apples"
$tc('apples', 1) // "one apple"
$tc('apples', 10) // "10 apples"

// count + other params (second argument must be an object)
$tc('cart', { count: 10, name: 'Alice' }) // "10 items for Alice"
```


**Alternativa como componente** — `<i18n-t keypath="cart" :plural="count" :params="\{ name \}" />` (fusiona `count` con `params` internamente).


### `$mergeTranslations`

{/* generated:method:$mergeTranslations — do not edit; run `pnpm run docs:generate` */}

```ts
(newTranslations: Translations) => void
```

Fusiona traducciones en el idioma activo en runtime, sobrescribiendo lo cargado.

{/* /generated:method:$mergeTranslations */}

```typescript
$mergeTranslations({
  welcome: 'Bienvenue, {username}!',
})
// Output: Updates the translation cache with the new French translation
```

### `$resolveTranslations`

{/* generated:method:$resolveTranslations — do not edit; run `pnpm run docs:generate` */}

```ts
() => Translations
```

Todas las traducciones actualmente en memoria para el idioma y ruta activos, como un árbol. Vista de solo lectura de lo que `$t()` puede resolver ahora mismo.

{/* /generated:method:$resolveTranslations */}

```typescript
const tree = $resolveTranslations()
// { aaa: { bbb: 'ccc' }, ddd: 1111 } — the same dictionary $t() reads from
```

Usa esto cuando necesites el diccionario completo en memoria (DevTools, tests, editores en runtime). Trata el valor devuelto como de solo lectura; cambia valores mediante `$setTranslation` o aplica parches con `$mergeTranslations`.

### `$setTranslation`

{/* generated:method:$setTranslation — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, value: unknown) => void
```

Reemplaza el valor en `key` en el diccionario activo. Es un reemplazo, no una fusión. Usa `$mergeTranslations` cuando los hermanos existentes deban sobrevivir.

{/* /generated:method:$setTranslation */}

```typescript
$setTranslation('aaa', { fff: 'ggg' }) // replaces the whole `aaa` subtree
$setTranslation('aaa', 'text')          // replaces `aaa` with a string
$setTranslation('ddd', 1111)            // scalar at the top level
$setTranslation('aaa.bbb', 'nested')    // dotted path
```

Esto es un **reemplazo**, no una fusión. Los hermanos existentes bajo la misma clave se eliminan. Para parchear sin perder hermanos, usa `$mergeTranslations`.

### `$setMissingHandler`

{/* generated:method:$setMissingHandler — do not edit; run `pnpm run docs:generate` */}

```ts
(handler: MissingHandler | null) => void
```

Instala un callback invocado para cada clave no resuelta. Pasa `null` para eliminarlo.

{/* /generated:method:$setMissingHandler */}

**Definición de tipo**:

```typescript
type MissingHandler = (locale: string, key: string, routeName: string, instance?: unknown, type?: string) => void
```

```typescript
// Set a custom handler
$setMissingHandler((locale, key, routeName) => {
  console.error(`Missing translation: ${key} in ${locale} for route ${routeName}`)
  // Send to Sentry or other error tracking service
  // Sentry.captureMessage(`Missing translation: ${key}`)
})

// Remove the handler
$setMissingHandler(null)
```

**Casos de uso**:

- Registrar traducciones ausentes en servicios de seguimiento de errores (Sentry, LogRocket, etc.).
- Recoger analíticas sobre traducciones ausentes.
- Manejo de errores personalizado para claves de traducción ausentes.

## 🔢 Formato de números y fechas

Métodos para formatear números y fechas según las convenciones del idioma.

### `$tn`

{/* generated:method:$tn — do not edit; run `pnpm run docs:generate` */}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

Formatea un número con `Intl.NumberFormat` en el idioma activo. Una clave selecciona un formato con nombre desde la configuración.

{/* /generated:method:$tn */}

```typescript
// Inline options
const formattedNumber = $tn(1234567.89, { style: 'currency', currency: 'USD' })
// "$1,234,567.89"

// Named format (from nuxt.config i18n.numberFormats)
const price = $tn(1000, 'currency')
const priceDe = $tn(1000, 'currency', 'de')
const compact = $tn(1000, 'currency', { notation: 'compact' })
```

Las claves de formato con nombre desconocidas recurren a las opciones por defecto de `Intl.NumberFormat`. En desarrollo (cliente), se emite un `console.warn` cuando `missingWarn` está activo (por defecto).

**Ejemplo de configuración**:

```ts
export default defineNuxtConfig({
  i18n: {
    numberFormats: {
      en: {
        currency: { style: 'currency', currency: 'USD' },
        decimal: { style: 'decimal', minimumFractionDigits: 2, maximumFractionDigits: 2 },
      },
      de: {
        currency: { style: 'currency', currency: 'EUR' },
      },
    },
  },
})
```

**Casos de uso**:

- Formatear números como moneda, porcentajes o decimales en el formato de idioma adecuado.
- Reutilizar formatos con nombre en toda la app (paridad de migración con Vue I18n).

### `$td`

{/* generated:method:$td — do not edit; run `pnpm run docs:generate` */}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

Formatea una fecha con `Intl.DateTimeFormat` en el idioma activo. Una clave selecciona un formato con nombre desde la configuración.

{/* /generated:method:$td */}

```typescript
const formattedDate = $td(new Date(), { weekday: 'long', year: 'numeric', month: 'long', day: 'numeric' })
// "Friday, September 1, 2023"

const short = $td(new Date(), 'short')
const longDe = $td(new Date(), 'long', 'de')
```

Las claves de formato con nombre desconocidas recurren a las opciones por defecto de `Intl.DateTimeFormat`. En desarrollo (cliente), se emite un `console.warn` cuando `missingWarn` está activo (por defecto).

**Ejemplo de configuración**:

```ts
export default defineNuxtConfig({
  i18n: {
    datetimeFormats: {
      en: {
        short: { year: 'numeric', month: 'short', day: 'numeric' },
        long: { year: 'numeric', month: 'long', day: 'numeric', weekday: 'long' },
      },
    },
  },
})
```

**Casos de uso**:

- Mostrar fechas en un formato acorde al idioma del usuario.
- Compartir presets short/long/date-time en toda la app.

### `$tdr`

{/* generated:method:$tdr — do not edit; run `pnpm run docs:generate` */}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

Formatea una fecha como tiempo relativo ("hace 3 días") con `Intl.RelativeTimeFormat`.

{/* /generated:method:$tdr */}

```typescript
const relativeDate = $tdr(new Date(Date.now() - 1000 * 60 * 5))
// Output: "5 minutes ago" in the 'en-US' locale
```

```ts

```

La ruta de la página actual en otro idioma, sin navegar.

{/* /generated:method:$switchLocalePath */}

```typescript
const routeFr = $switchLocalePath('fr')
```

### `$switchRoute`

{/* generated:method:$switchRoute — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => void
```

Navega a otra ruta manteniendo el idioma activo o cambiando a `toLocale`.

{/* /generated:method:$switchRoute */}

**Ejemplos**:

<CodeGroup>
```typescript String Path

```


```typescript Named Route

$switchRoute({ name: 'page' })
```

```typescript Named Route with Locale
// Switches to a named route and changes the locale to Spanish

```
</CodeGroup>

## 🚦 Configuración de rutas

Métodos para configurar el comportamiento de las rutas y el control de acceso.

### `$defineI18nRoute`

{/* generated:method:$defineI18nRoute — do not edit; run `pnpm run docs:generate` */}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

Registra la configuración de idioma por página y las traducciones desde dentro de un componente. Fusiona en el idioma activo y se reaplica cuando el idioma cambia.

{/* /generated:method:$defineI18nRoute */}

> [!IMPORTANT]
> `$defineI18nRoute` lo proporciona el **plugin define** y está disponible solo en `useNuxtApp()`. **No** forma parte del objeto devuelto por `useI18n()`.
> Desestructúralo siempre desde `useNuxtApp()` dentro de `script setup`. Llamar a `$defineI18nRoute(...)` como global desnudo lanza `"$defineI18nRoute is not defined"` durante SSR/prerender.

**Parámetros**:

- **locales**: `string[] | Record<string, Record<string, string>>` — Idiomas disponibles para la ruta.
- **localeRoutes**: `Record<string, string>` — Opcional. Rutas personalizadas para idiomas específicos.
- **disableMeta**: `boolean | string[]` — Opcional. Desactiva las etiquetas meta de i18n para todos o algunos idiomas.

**Ejemplo básico**:

```typescript
import { useNuxtApp } from '#imports'
```

### `$setI18nRouteParams`

{/* generated:method:$setI18nRouteParams — do not edit; run `pnpm run docs:generate` */}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

Establece params por idioma para la ruta actual, para que un segmento dinámico pueda diferir por idioma. Llámalo durante SSR, antes de que se renderice el head.

{/* /generated:method:$setI18nRouteParams */}

```typescript
// in pages/news/[id].vue
// for en/news/1-first-article
const { $switchLocaleRoute, $setI18nRouteParams, $defineI18nRoute } = useNuxtApp()
$defineI18nRoute({
  localeRoutes: {
    en: '/news/:id()',
    fr: '/nouvelles/:id()',
    de: '/Nachricht/:id()',
  },
})
const { data: news } = await useAsyncData(`news-${params.id}`, async () => {
  let response = await $fetch("/api/getNews", {
    query: {
      id: params.id,
    },
  });
  if (response?.localeSlugs) {
    response.localeSlugs = {
      en: {
        id: '1-first-article'
      }
      fr: {
        id: '1-premier-article'
      }
      de: {
        id: '1-erster-Artikel'
      }
    }
    $setI18nRouteParams(response?.localeSlugs);
  }
  return response;
});
$switchLocalePath('fr') // === 'fr/nouvelles/1-premier-article'
$switchLocalePath('de') // === 'de/Nachricht/1-erster-Artikel'
```

## 🔧 Métodos de caché y utilidad

### `$has`

{/* generated:method:$has — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string) => boolean
```

Si una clave se resuelve en el idioma activo. Úsalo para bifurcar sobre texto opcional en lugar de renderizar una clave cruda.

{/* /generated:method:$has */}

Durante las transiciones de página en el mismo idioma, v3 fusiona en profundidad automáticamente las traducciones de la página saliente en este diccionario hasta que finaliza la transición. Así, las claves de la página anterior pueden seguir devolviendo `true` brevemente. No existe la opción `previousPageFallback`; este comportamiento está integrado. Consulta [FAQ — transiciones de página](/guides/faq#-why-do-translations-break-during-page-transitions-especially-with-defineasynccomponent).

```typescript
if ($has('welcome')) {
  console.log($t('welcome'))
} else {
  console.log('Key not found')
}
```

### `$clearCache`

{/* generated:method:$clearCache — do not edit; run `pnpm run docs:generate` */}

```ts
() => void
```

Descarta cada chunk en caché, en el cliente y en el diccionario activo.

{/* /generated:method:$clearCache */}

## 🧭 Composable `useI18nLocale`

El composable centralizado para la gestión del estado del idioma. Úsalo en lugar de manipular directamente `useState('i18n-locale')` o `useCookie('user-locale')`.

```typescript
const {
  setLocale, // (locale: string) => void — updates state + cookie
  getLocale, // () => string | null — from state or cookie
  getPreferredLocale, // () => string | null — validated against locales list
  getEffectiveLocale, // (route, getLocaleFromRoute) => string
  resolveInitialLocale, // (options) => string
  isValidLocale, // (locale) => boolean
  locale, // Ref<string | null> — reactive state
  localeCookie, // CookieRef — reactive cookie
  syncLocale, // (locale) => void — sync to cookie only
  validLocales, // string[] — list of valid locale codes
} = useI18nLocale()
```

### Métodos principales

| Método                  | Descripción                                                    |
| ----------------------- | -------------------------------------------------------------- |
| `setLocale(locale)`     | Establece el idioma en `useState` y en la cookie atómicamente. |
| `getLocale()`           | Devuelve el idioma actual desde el estado o la cookie.         |
| `getPreferredLocale()`  | Devuelve el idioma validado contra la lista `locales`, o `null`. |
| `isValidLocale(locale)` | Comprueba si un código de idioma está en la lista `locales` configurada. |
