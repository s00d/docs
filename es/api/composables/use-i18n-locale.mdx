# useI18nLocale

## Firma

{/* generated:symbol:useI18nLocale — do not edit; run `pnpm run docs:generate` */}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getLocaleWithServerFallback: (serverLocale?: string | null) => string | null; getPreferredLocale: () => string | null; hashCookie: any; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: any; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Punto de entrada centralizado para la gestión de locale de i18n. Combina `useState('i18n-locale')`, la cookie de locale y utilidades de sincronización.

## Uso

```vue
<script setup>
const {
  locale,
  localeCookie,
  hashCookie,
  validLocales,
  getPreferredLocale,
  getLocale,
  getLocaleWithServerFallback,
  getEffectiveLocale,
  resolveInitialLocale,
  setLocale,
  syncLocale,
  isValidLocale,
} = useI18nLocale()

// Set locale (updates state and cookies)
setLocale('de')

// Get current locale (state → cookie)
const current = getLocale()

// Get valid preferred locale
const preferred = getPreferredLocale()
</script>
```

## API

| Propiedad/Método                                 | Tipo                                | Descripción                                                                          |
| ----------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------ |
| `locale`                                        | `Ref<string \| null>`               | Estado reactivo del locale (`useState('i18n-locale')`).                              |
| `localeCookie`                                  | `Ref`                               | Cookie de locale (cuando la opción `localeCookie` está habilitada).                  |
| `hashCookie`                                    | `Ref`                               | Cookie usada cuando `hashMode` está activo.                                          |
| `validLocales`                                  | `string[]`                          | Códigos de locale habilitados desde la configuración del módulo (excluye `disabled`). |
| `getLocale()`                                   | `() => string \| null`              | Locale actual: state → cookie (o cookie hash en modo hash).                          |
| `getPreferredLocale()`                          | `() => string \| null`              | Locale desde state/cookie **validado** contra `validLocales`, o `null`.              |
| `getLocaleWithServerFallback(serverLocale?)`    | `(serverLocale?) => string \| null` | State → cookie → contexto de servidor opcional (usado durante la inicialización de `no_prefix`). |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string`             | Locale para cargar traducciones: el modo hash prefiere el state; en caso contrario, lee de la ruta. |
| `resolveInitialLocale(options)`                 | `(options) => string`               | Resuelve el locale: state → `serverLocale` → ruta; sincroniza el state cuando es necesario. |
| `setLocale(locale)`                             | `(locale: string \| null) => void`  | Establece el locale y sincroniza con las cookies.                                    |
| `syncLocale(locale)`                            | `(locale: string \| null) => void`  | Sincroniza solo las cookies (sin actualizar el state).                               |
| `isValidLocale(locale)`                         | `(locale) => boolean`               | Comprueba si la cadena está en `validLocales`.                                       |

### Opciones de `resolveInitialLocale`

```typescript
interface ResolveInitialLocaleOptions {
  route: unknown
  serverLocale?: string | null
  getLocaleFromRoute: (route?: unknown) => string
}
```

Usado internamente por el plugin principal al inicio. Los plugins personalizados pueden llamarlo cuando implementen flujos de detección alternativos.

### `getEffectiveLocale`

```typescript
const { getEffectiveLocale } = useI18nLocale()
const { $getLocale } = useNuxtApp()

const locale = getEffectiveLocale(route, (r) => $getLocale(r))
```

Devuelve el locale utilizado para cargar traducciones y formatear mensajes para un objeto de ruta determinado.

## Establecimiento programático del locale

Prefiere `useI18nLocale()` frente al uso directo de `useState('i18n-locale')`:

```ts
// plugins/i18n-loader.server.ts
import { defineNuxtPlugin } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,

  setup() {
    const { setLocale } = useI18nLocale()
    const detectedLocale = 'ja' // Your detection logic here
    setLocale(detectedLocale)
  },
})
```

<Tip>
`setLocale()` actualiza únicamente la preferencia de locale (state + cookie). Para recargar además el contexto de traducción activo en el cliente, usa `$switchLocale()` desde `useNuxtApp()` o `useI18n()`. Esto importa especialmente para `no_prefix`, donde la URL no cambia. Consulta [FAQ — cambiar de locale sin cambiar la URL](/guides/faq#-switch-locale-without-changing-the-url).
</Tip>
