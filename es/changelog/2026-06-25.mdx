**Fecha**: 2026-06-25

**Versión**: `v3.21.0`

![v3.21.0 release](/images/3.21.0.png)

Esta versión añade **`useI18nHead`**: un composable a nivel de página para sobrescribir el SEO de i18n por encima del plugin integrado `02.meta`. Personaliza `hreflang`, canonical, `og:url` y las etiquetas Open Graph por ruta sin un plugin de meta personalizado ni `meta: false`.

## ¿Qué hay de nuevo? {#what’s-new}

### Composable `useI18nHead` {#usei18nhead-composable}

Llama a `useI18nHead` en cualquier página cuando `meta: true` (por defecto). El módulo fusiona tu entrada después de `useLocaleHead` en cada actualización de ruta:

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

Admite objetos estáticos, getters reactivos, añadir `meta` / `link`, `replace` para los grupos integrados y `disable` para eliminar etiquetas generadas automáticamente. Consulta [`useI18nHead`](/es/composables/useI18nHead).

### Utilidad `mergeI18nHead` (`@i18n-micro/utils`) {#mergei18nhead-utility-@i18n-micro/utils}

La lógica de fusión independiente del framework vive en `@i18n-micro/utils/merge-i18n-head`: la usa el plugin `02.meta` y se puede probar de forma aislada. Los tipos (`I18nHeadInput`, `I18nHeadLink`, `I18nHeadMeta`) se exportan desde `@i18n-micro/types`.

### Integración con plugins {#plugin-integration}

- **`02.meta`**: fusiona la salida de `useLocaleHead` con el estado de la página de `useI18nHead` mediante `useHead`
- **`01.plugin`**: restablece las sobrescrituras de la página al cambiar el nombre de la ruta mediante `resetPageHead()` (estado compartido con el composable)

## Casos de uso típicos {#typical-use-cases}

| Escenario                                    | Enfoque                                                        |
| -------------------------------------------- | -------------------------------------------------------------- |
| Blog/CMS con traducciones parciales          | `replace.hreflang` + `replace.ogAlternates` a partir de los locales de la API |
| Canonical personalizado desde el CMS         | `replace.canonical` + `replace.ogUrl`                          |
| Solo OG en una landing page                  | `meta: [{ property: 'og:title', ... }]`: se mantiene el hreflang del módulo |
| Sin hreflang en una página                   | `disable: ['hreflang', 'x-default']`                           |
| Sustituir un plugin personalizado (`i18nManualHreflang`) | `useI18nHead` por página de contenido + `meta: true` |

**JSON-LD** permanece en `useHead({ script: [...] })`: `useI18nHead` no genera datos estructurados.

## Cambios incompatibles {#breaking-changes}

Ninguno para el uso estándar de `nuxt.config`. El nuevo composable y la subruta de utils son aditivos.

## Por qué es importante {#why-it-matters}

- **Sin plugin de meta personalizado** para publicaciones de CMS, noticias o guías con URL por locale
- **Un único pipeline**: valores por defecto del módulo + sobrescrituras de la página en una sola llamada a `useHead`
- **Con tipos seguros**: `I18nHeadInput` para helpers como `buildArticleHead(content)`
