---
title: "useI18nHead"
description: "useI18nHead sobrescribe las etiquetas SEO de i18n generadas para una página: reemplaza o elimina las etiquetas canonical, hreflang y og, o añade las tuyas."
---

`useI18nHead()` cambia las etiquetas SEO que genera el módulo, solo para una página. Úsalo cuando una página sabe más que el router: un artículo de un CMS que solo existe en algunos locales, una URL canónica que viene de una API, etiquetas `og:` adicionales. Obtienes las etiquetas generadas con tus sobrescrituras fusionadas encima.

## Firma {#signature}

```ts
useI18nHead(input?: MaybeRefOrGetter<I18nHeadInput | null>): { pageHead: any; resetPageHead: () => void }
```

Registra sobrescrituras a nivel de página para las etiquetas SEO de i18n del head.
El plugin `02.meta` las fusiona sobre la salida de `useLocaleHead`.

Prefiere un getter (`() => ({ … })`) cuando los valores provienen de `$t` / `t` para que
se vuelvan a resolver al cambiar de locale. Un objeto plano se evalúa una vez y queda congelado.

| Parámetro | Tipo | Descripción |
| --- | --- | --- |
| `input` *(opcional)* | `MaybeRefOrGetter<I18nHeadInput \| null>` |  |

Funciona con [`meta: true`](/es/api/module-options#meta) (el valor por defecto): el plugin de meta del módulo fusiona la entrada sobre la salida de [`useLocaleHead`](/es/composables/useLocaleHead) en cada renderizado del head. Con `meta: false` nada la lee.

La sobrescritura se restablece cuando cambia el nombre de la ruta. Una página que establece `disableMeta` no recibe ninguna etiqueta de i18n, sobrescrituras incluidas.

## Entrada {#input}

`I18nHeadInput` (de `@i18n-micro/types`):

| Clave | Tipo | Efecto |
| --- | --- | --- |
| `htmlAttrs` | `Record<string, string>` | Se fusiona en los atributos de `<html>` (`lang`, `dir`). |
| `meta` | `I18nHeadMeta[]` | Se añade después de las etiquetas generadas; reemplaza una etiqueta con el mismo `id`, `property` o `name`. |
| `link` | `I18nHeadLink[]` | Se añade después de los enlaces generados; reemplaza un enlace con el mismo `id`, o `rel` + `hreflang`. |
| `replace.canonical` | `string \| false` | Reemplaza el `href` canónico o elimina el enlace. |
| `replace.hreflang` | `I18nHeadLink[] \| false` | Reemplaza o elimina **todos** los enlaces `rel="alternate"`, `x-default` incluido. |
| `replace.xDefault` | `I18nHeadLink \| false` | Reemplaza o elimina el enlace `x-default`. |
| `replace.ogLocale` | `string \| false` | Reemplaza o elimina `og:locale`. |
| `replace.ogUrl` | `string \| false` | Reemplaza o elimina `og:url`. |
| `replace.ogAlternates` | `string[] \| false` | Reconstruye `og:locale:alternate` a partir de estos códigos de locale (mediante `og` / `iso`), omitiendo el locale actual, los códigos desconocidos y los códigos sin valor `og` o `iso`, o los elimina. |
| `disable` | `I18nHeadDisableGroup[]` | Elimina grupos generados: `'hreflang'` (no `x-default`), `'x-default'`, `'canonical'`, `'og'` (`og:locale` + `og:url`), `'og-alternates'`, `'html'`. |

Orden de aplicación: `disable`, luego `replace`, luego `htmlAttrs`, `meta`, `link`.

## Ejemplo {#example}

Un artículo que solo existe en algunos locales, con URL alternativas obtenidas de la API:

```vue
<script setup lang="ts">
const route = useRoute()
const { t } = useI18n()
const { data: article } = await useFetch<{ title: string; urls: Record<string, string> }>(`/api/articles/${route.params.slug}`)

useI18nHead(() => {
  if (!article.value) return null
  const codes = Object.keys(article.value.urls)
  return {
    meta: [{ property: 'og:title', content: article.value.title || t('blog.title') }],
    replace: {
      hreflang: codes.map((code) => ({ rel: 'alternate', hreflang: code, href: article.value!.urls[code]! })),
      ogAlternates: codes,
    },
  }
})
</script>
```

Pasa un getter, como aquí, cuando los valores provienen de `t()` o de datos asíncronos: se vuelve a ejecutar al cambiar de locale. Un objeto plano se lee una sola vez.
