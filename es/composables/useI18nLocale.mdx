---
title: "useI18nLocale"
description: "useI18nLocale lee y escribe el estado del locale y la cookie del locale — el punto de entrada para la detección personalizada del locale."
---

`useI18nLocale()` da acceso al locale que ha elegido la aplicación: el estado `i18n-locale` y la cookie del locale. Úsalo en un plugin que detecte el locale por sí mismo (dominio, perfil de usuario, cabecera) en lugar de escribir a mano `useState('i18n-locale')` o la cookie. Sus comprobaciones de validez usan los locales habilitados, incluidas las sobrescrituras en tiempo de ejecución.

## Firma {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Punto de entrada centralizado para la gestión del locale de i18n.
Combina useState('i18n-locale'), la cookie del locale y utilidades de sincronización.

## Valores devueltos {#returned-values}

| Miembro | Tipo | Descripción |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | La ref `useState('i18n-locale')`. |
| `localeCookie` | `Ref<string \| null>` | La cookie [`localeCookie`](/es/api/module-options#localecookie); un simple `{ value: null }` cuando la opción es `null`. |
| `hashCookie` | `Ref<string \| null>` | La cookie `hash-locale` con enrutamiento por hash; `{ value: null }` en caso contrario. |
| `validLocales` | `string[]` | Códigos de los locales habilitados. |
| `setLocale(locale)` | `(locale: string \| null) => void` | Escribe el estado y las cookies. No valida ni carga traducciones. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | Escribe solo las cookies. |
| `getLocale()` | `() => string \| null` | El estado y, después, la cookie de preferencia (la cookie de hash con enrutamiento por hash). Sin validar. |
| `getPreferredLocale()` | `() => string \| null` | El primer valor **válido** entre el estado y la cookie de preferencia, o `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | El estado con enrutamiento por hash, si está definido; en caso contrario, `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, después un estado válido, después `options.serverLocale` y, por último, el locale de la ruta. Guarda el resultado en el estado cuando el estado no es válido; en el cliente también escribe la cookie. |
| `isValidLocale(locale)` | `(locale) => locale is string` | Indica si `locale` está en `validLocales`. |

Las cookies duran un año, con `path: '/'` y `sameSite: 'lax'`.

## Ejemplo {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

El plugin loader del módulo lee el estado al arrancar, así que un plugin que lo establezca debe ejecutarse antes (`enforce: 'pre'`). Cómo compite el estado con la URL, la cookie y `Accept-Language`: [Detección del locale](/es/guide/locale-detection). Recorrido completo: [Detección personalizada](/es/guide/custom-auto-detect).

`setLocale()` no cambia las traducciones que se muestran en pantalla. Para cambiar el locale de la página actual, llama a [`$switchLocale()`](/es/api/methods#$switchlocale).
