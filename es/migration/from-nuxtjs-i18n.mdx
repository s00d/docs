# 🔄 Migración de `nuxt-i18n` a `Nuxt I18n Micro`

## ¿Qué guía necesitas?

| Estás migrando desde…                  | Guía                                             |
| -------------------------------------- | ------------------------------------------------ |
| `@nuxtjs/i18n` (módulo basado en vue-i18n) | **Esta página**                                  |
| `nuxt-i18n-micro` v2.x                 | [Actualización de v2.x a v3.x](/migration/v2-to-v3) |

## ¿Por qué migrar?

- **Rendimiento mejorado**: compilaciones ~51 % más rápidas y ~54 % menos memoria de compilación frente a `@nuxtjs/i18n` **v10.6** en nuestros [fixtures de benchmark](/guides/performance-results).
- **Configuración simplificada**: configuración optimizada con valores predeterminados sensatos.
- **Mejor gestión de recursos**: manejo optimizado de archivos de traducción grandes.

## Diferencias clave

| Característica          | `nuxt-i18n`                      | `Nuxt I18n Micro`                         |
| ----------------------- | -------------------------------- | ----------------------------------------- |
| Archivos de traducción  | JS/TS/JSON, cargados vía `vueI18n` | Solo JSON, autogenerados en desarrollo    |
| Generación de rutas     | En runtime                       | En tiempo de compilación (`@i18n-micro/route-strategy`) |
| Carga de traducciones   | Empaquetadas en JS               | JSON con carga diferida por página        |
| Estado de locale        | `useI18n()` de `vue-i18n`        | Composable `useI18nLocale()`              |
| `detectBrowserLanguage` | Compatible                       | Usa `autoDetectLanguage` en su lugar      |

## Paso a paso

### 1. Instalación

```bash
npm install nuxt-i18n-micro
```

### 2. Actualizar la configuración

**Antes (nuxt-i18n):**

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    defaultLocale: 'en',
    vueI18n: './i18n.config.js',
    detectBrowserLanguage: { useCookie: true },
  },
})
```

**Después (Nuxt I18n Micro v3):**

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    localeCookie: 'user-locale',
    autoDetectLanguage: true,
  },
})
```

### 3. Reorganizar los archivos de traducción

Mueve las traducciones al directorio `locales` en formato JSON. Aquí tienes una comparación completa del proyecto:

**Before (`nuxt-i18n`):**

```text
my-app/
├── i18n/
│   └── locales/          # langDir
│       ├── en.json       # all translations in one file
│       ├── ru.json
│       └── de.json
├── pages/
│   ├── index.vue
│   └── page.vue
├── server/
│   └── tsconfig.json
├── nuxt.config.ts        # config will change
└── package.json
```

**After (Nuxt I18n Micro):**

```text
my-app/
├── locales/              # translationDir
│   ├── en.json           # root-level translations
│   ├── ru.json
│   ├── de.json
│   └── pages/            # page-specific
│       ├── index/
│       │   ├── en.json
│       │   ├── ru.json
│       │   └── de.json
│       └── page/
│           ├── en.json
│           ├── ru.json
│           └── de.json
├── pages/
│   ├── index.vue         # API changes
│   └── page.vue
├── server/
│   └── tsconfig.json
├── nuxt.config.ts        # new config
└── package.json
```

<Tip>
Missing page-specific translation files are **auto-generated** in development mode — just run `nuxt dev` and the module will create empty JSON files for each page and locale.
</Tip>

### 4. Actualizar la navegación

```diff
- <nuxt-link :to="{ name: 'index' }">Home</nuxt-link>
+ <NuxtLink :to="$localeRoute({ name: 'index' })">Home</NuxtLink>
+ <!-- or use the built-in component -->
+ <i18n-link :to="{ name: 'index' }">Home</i18n-link>
```

### 5. Actualizar el SEO

Elimina cualquier configuración SEO manual de `nuxt-i18n`. Nuxt I18n Micro genera `hreflang`, URLs canónicas y etiquetas Open Graph automáticamente cuando `meta: true` está establecido.

### 6. Probar

Prueba exhaustivamente las traducciones, el cambio de locale, las redirecciones y las meta etiquetas SEO.

## 🛡️ Problemas comunes y resolución de problemas

### ❌ Los archivos de traducción no se cargan

Asegúrate de que los archivos de traducción estén en el directorio correcto y sigan el formato JSON. Verifica que `translationDir` coincida con la ubicación de tus archivos.

### ⚠️ Errores de ruta no encontrada

Comprueba que todos los códigos de locale del array `locales` sean correctos y que las rutas estén configuradas adecuadamente.

### 🏷️ Etiquetas SEO faltantes

Verifica que `meta: true` esté establecido y que cada locale tenga un código `iso` válido.

### 🔄 Desajustes de hidratación

Si usas la estrategia `no_prefix`, establece el locale en un plugin de servidor con `order: -10` usando `useI18nLocale().setLocale()` para asegurar que servidor y cliente coincidan en el locale. Consulta [Detección de idioma personalizada](/guides/custom-language-detection).

### 🍪 Redirecciones que no funcionan

Para las estrategias con prefijo, asegúrate de establecer `localeCookie: 'user-locale'`. Sin una cookie, el plugin de redirección de servidor no tiene forma de recordar el locale preferido del usuario entre recargas de página.
