`@i18n-micro/solid` proporciona a las apps SolidJS una instancia i18n basada en signals, un provider, `useI18n()` y cuatro componentes. Úsalo en una app Solid que no esté construida con Nuxt. Las lecturas de `t()` dentro de JSX o de efectos siguen el idioma, la ruta y los diccionarios; el modelo común está en [Frameworks](/es/integrations/overview).

## Instalación {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Dependencias peer: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (opcional, solo para `@i18n-micro/solid/router`). Solid 2 todavía no está soportado.

## Configuración {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` acepta `i18n`, `locales`, `defaultLocale` y `routingStrategy`; una prop omitida conserva el valor del provider exterior, incluida la instancia. `getLocaleName()` y `<I18nSwitcher>` leen `locales`; sin ellos no tienen nada que listar. Las opciones están en [la instancia](/es/integrations/overview#the-instance). La instancia es la del [runtime](/es/integrations/runtime-package), con un signal sobre su store.

## Traducir {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Llama a los métodos dentro de JSX o de un efecto para que Solid los siga, también `localePath` y `getLocale`; un valor leído una sola vez en el cuerpo del componente no se actualiza. En la instancia, haz el seguimiento con `i18n.locale` e `i18n.currentRoute`: `i18n.getLocale()` no es reactivo, porque las escrituras lo leen. Leer el idioma solo reacciona a cambios de idioma, así que un efecto que lo lee y carga un diccionario se ejecuta una vez. No desestructures las props ni guardes los resultados de `t('key')` en variables normales.

`useI18n()` devuelve `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (un accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` e `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Cambiar de idioma {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Cambiar de idioma no carga nada; añade primero el diccionario del idioma.

`<I18nGroup>` pasa un `t` con prefijo a un hijo de tipo función. `<I18nT>` y `t()` dentro de él no llevan prefijo:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Enrutamiento {#routing}

El adaptador de `@solidjs/router` está en un subpath para que la entrada principal nunca importe el router. Llámalo dentro del router, normalmente en el `root` del router, donde `useNavigate` y `useLocation` funcionan:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

El adaptador añade prefijo a todos los idiomas excepto al idioma por defecto (`/about`, `/de/about`) y renderiza `<I18nLink>` como el `<A>` del router. `getCurrentPath` lee la ubicación reactiva del router, de modo que los enlaces activos y el selector la siguen; una estrategia personalizada consigue lo mismo leyendo un signal allí. Fíjate en el orden de los argumentos: `(locales, defaultLocale, navigate, location)`. Para otros routers, escribe un adaptador con `getCurrentPath`, `push` y `replace` (todos obligatorios); consulta [Adaptador de router](/es/integrations/overview#router-adapter).

## SSR {#ssr}

Para el renderizado en el servidor, compila con `vite-plugin-solid`: la condición de exportación `solid` del paquete le entrega el código fuente, así que se compila para el servidor. El `dist` precompilado es solo para el navegador. La instancia no tiene `destroy()`; crea una por app, o una por petición en el servidor, y deja que el recolector de basura la elimine.
