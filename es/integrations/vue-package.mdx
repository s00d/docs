`@i18n-micro/vue` es un plugin de Vue 3 con el núcleo de traducción de Nuxt I18n Micro: `t()` reactivo, `$t` global, cuatro componentes y un adaptador opcional para vue-router. Úsalo en una aplicación Vue con Vite o SSR que no esté construida con Nuxt. El modelo de instancia, el contrato del router y las props de los componentes se comparten con los demás paquetes y se describen en [Frameworks](/es/integrations/overview).

## Instalación {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vue
```

```bash npm
npm install @i18n-micro/vue
```

```bash yarn
yarn add @i18n-micro/vue
```

</CodeGroup>

Dependencias peer: `vue` `^3.3.0`; `vue-router` `^4.5.1 || ^5.0.0` (opcional, solo para `@i18n-micro/vue/router`). Los tipos publicados necesitan Vue 3.5.5 o posterior con `skipLibCheck: false`; con `skipLibCheck: true`, el ajuste habitual de las plantillas, también compilan las versiones anteriores.

## Configuración {#setup}

```ts
// src/main.ts
import { createApp } from 'vue'
import { createI18n } from '@i18n-micro/vue'
import App from './App.vue'
import en from './locales/en.json'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales: [
    { code: 'en', iso: 'en-US', displayName: 'English' },
    { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
  ],
  defaultLocale: 'en',
})

createApp(App).use(i18n).mount('#app')
```

`locales` y `defaultLocale` son obligatorios para `useI18n()`: sin ellos lanza `I18nLocalesKey not provided`. Pásalos a `createI18n` (como arriba), a `useI18n({ locales, defaultLocale })`, o mediante `app.provide(I18nLocalesKey, …)` y `app.provide(I18nDefaultLocaleKey, …)`.

El plugin registra `I18nT`, `I18nLink`, `I18nGroup` e `I18nSwitcher` de forma global y añade `$t`, `$ts`, `$tc`, `$tn`, `$td`, `$tdr`, `$has` y `$i18n` a las plantillas. Fuera de los componentes, la instancia es `i18n.global`. Las demás opciones están en [la instancia](/es/integrations/overview#the-instance); `routeMessages` no está disponible en Vue, usa `addRouteTranslations`.

## Traducir {#translate}

```vue
<script setup lang="ts">
import { useI18n } from '@i18n-micro/vue'

const { t, tc, tn } = useI18n()
</script>

<template>
  <h1>{{ t('greeting', { name: 'Ada' }) }}</h1>
  <!-- Hello, Ada! -->
  <p>{{ tc('apples', 3) }}</p>
  <!-- 3 apples -->
  <p>{{ $t('nav.home') }} · {{ tn(1234.5) }}</p>
</template>
```

`useI18n()` devuelve los métodos de traducción (`t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`), `locale` (un computed escribible), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `localePath`, `localeRoute`, `switchLocale`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `mergeTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` e `instance`.

Carga más diccionarios en cualquier momento; todos los componentes que los leen se vuelven a renderizar:

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Cambiar de locale {#switch-locale}

```ts
const { locale, switchLocale } = useI18n()

locale.value = 'de' // only the locale
switchLocale('de') // the locale, then router.push to the localized current path
```

Carga el diccionario del locale antes o después de cambiar; el cambio no descarga nada.

`<I18nGroup>` proporciona a su slot un `t` con prefijo. Las claves dentro de `<I18nT>` o de un `t()` normal no llevan prefijo:

```vue
<I18nGroup prefix="profile" v-slot="{ t }">
  <h2>{{ t('title') }}</h2>
  <!-- profile.title -->
</I18nGroup>
```

## Enrutamiento {#routing}

El adaptador de vue-router está en una subruta, de modo que la entrada principal nunca importa `vue-router`:

```ts
// src/main.ts
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import { createI18n } from '@i18n-micro/vue'
import { createVueRouterAdapter } from '@i18n-micro/vue/router'
import App from './App.vue'
import Home from './pages/Home.vue'
import About from './pages/About.vue'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/:locale(de)?', component: Home },
    { path: '/:locale(de)?/about', component: About },
  ],
})

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales,
  defaultLocale: 'en',
  routingStrategy: createVueRouterAdapter(router, locales, 'en'),
})

createApp(App).use(router).use(i18n).mount('#app')
```

`createVueRouterAdapter(router, locales, defaultLocale)` añade prefijo a todos los locales excepto al predeterminado (`/about`, `/de/about`) y renderiza `<I18nLink>` como `RouterLink`. Lee tú mismo el locale de la ruta, por ejemplo en `router.beforeEach`, y establece `i18n.global.locale.value`. También puedes conectar un adaptador más tarde con `i18n.setRoutingStrategy(adapter)`; para un adaptador personalizado, consulta [Adaptador de router](/es/integrations/overview#router-adapter).

## SSR {#ssr}

- Crea el router, la instancia de i18n y la aplicación dentro de la función de renderizado por solicitud. Una única instancia compartida filtraría el locale de un visitante a otro.
- Usa `createMemoryHistory()` en el servidor, toma el locale de la URL y carga su diccionario (y el del fallback) antes de `renderToString`.
- Envía el locale al cliente (por ejemplo, en un script `window.__STATE__`) y crea la instancia del cliente con el mismo `locale` para que la hidratación coincida.
- `<I18nSwitcher>` solo lee `window.location` cuando el desplegable está abierto, así que se renderiza en el servidor.

`packages/vue/playground` contiene un par completo `entry-server.ts` / `entry-client.ts`.

## Head para SEO {#seo-head}

`useLocaleHead(options)` construye las etiquetas `lang`/`dir`, canonical, `hreflang` y `og:locale` a partir de los locales y del adaptador de router. Llama a `updateMeta()` cuando cambie la ruta y pasa `metaObject` a tu gestor de head:

```ts
import { watch } from 'vue'
import { useRoute } from 'vue-router'
import { useHead } from '@unhead/vue'
import { useLocaleHead } from '@i18n-micro/vue'

const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
watch(() => route.fullPath, () => updateMeta(), { immediate: true })
useHead(metaObject)
```

Opciones: `baseUrl` (cadena o función), `addDirAttribute` (predeterminado `true`), `addSeoAttributes` (predeterminado `true`), `identifierAttribute` (predeterminado `'id'`), `hreflangBaseLanguage` (predeterminado `false`). Los locales con `disabled: true` o `seo: false` no reciben enlace alternativo.
