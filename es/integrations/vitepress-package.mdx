`@i18n-micro/vitepress` añade diccionarios en runtime a un sitio VitePress: `$t` e `<I18nT>` dentro del markdown, helpers de rutas y etiquetas SEO, construido sobre [`@i18n-micro/vue`](/es/integrations/vue-package). Úsalo cuando las mismas cadenas de interfaz aparecen en muchas páginas y no quieres duplicarlas por locale. El locale sigue los locales por ruta propios de VitePress (`/`, `/fr/`).

## Cuándo usarlo {#when-to-use-it}

| Necesidad | Solución |
|------|----------|
| `.md` duplicados, prefijos de URL | `locales` de VitePress |
| `$t` en runtime / componentes / sincronización de rutas / head SEO | `@i18n-micro/vitepress` |
| Etiquetas de la interfaz del tema por defecto (`docFooter`, interfaz de búsqueda) | Tu propio `themeConfig` por locale |

<Tip>

**Playground** — [`packages/vitepress/playground`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/vitepress/playground) — `pnpm -C packages/vitepress/playground dev`

</Tip>

## Instalación {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vitepress
```

```bash npm
npm install @i18n-micro/vitepress
```

```bash yarn
yarn add @i18n-micro/vitepress
```

</CodeGroup>

Dependencias peer: `vitepress` `>=1.0.0 || >=2.0.0-alpha.0`, `vue` `^3.3.0`. Los scripts de Node usan `@i18n-micro/node`, que se instala con el paquete y se reexporta a través de `/node`. Los tipos publicados necesitan Vue 3.5.5 o posterior con `skipLibCheck: false`; con `skipLibCheck: true`, el ajuste habitual de las plantillas, también compilan las versiones anteriores.

## Configuración {#setup}

```
locales/en.json
locales/fr.json
locales/pages/guide/demo/en.json   # optional page-scoped
locales/pages/guide/demo/fr.json
```

Los archivos de página se asignan a nombres de ruta del mismo modo que en Nuxt/Astro (`guide/demo` → `guide-demo`).

### 1. Configuración — `@i18n-micro/vitepress/config` {#1-config-—-@i18n-micro/vitepress/config}

```ts
// .vitepress/config.mts
import { defineConfig } from 'vitepress'
import { withI18n, buildVitePressLocales } from '@i18n-micro/vitepress/config'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English', og: 'en_US' },
  { code: 'fr', iso: 'fr-FR', displayName: 'Français', og: 'fr_FR' },
]
const defaultLocale = 'en'

export default defineConfig(
  withI18n(
    {
      locales: buildVitePressLocales(locales, defaultLocale),
      // themeConfig.i18nRouting is injected automatically
    },
    {
      locale: defaultLocale,
      defaultLocale,
      locales,
      translationDir: 'locales',
      metaBaseUrl: 'https://example.com', // optional SEO head
    },
  ),
)
```

### 2. Tema — `@i18n-micro/vitepress/theme` {#2-theme-—-@i18n-micro/vitepress/theme}

```ts
// .vitepress/theme/index.ts
import DefaultTheme from 'vitepress/theme'
import { defineI18nTheme } from '@i18n-micro/vitepress/theme'

export default defineI18nTheme(DefaultTheme)
```

El locale inicial se toma de la ruta actual antes de la instalación (sin destello del locale por defecto en `/fr/…`).

### Avanzado: `createI18n` manual {#advanced-manual-createi18n}

Una sola factoría para el cliente: plugin de Vue + métodos de rutas + `enhanceApp` (sin exportaciones separadas de helpers del router).

```ts
import { createI18n, messagesFromGlob } from '@i18n-micro/vitepress'

const i18n = createI18n({
  locale: 'en',
  defaultLocale: 'en',
  locales: [{ code: 'en' }, { code: 'fr' }],
  messages: messagesFromGlob(import.meta.glob('../../locales/*.json', { eager: true })),
})

i18n.localizePath('/guide', 'fr')
// in theme enhanceApp:
i18n.enhanceApp({ app, router })
```

### Scripts de Node — `@i18n-micro/vitepress/node` {#node-scripts-—-@i18n-micro/vitepress/node}

Usa `createI18n` / `loadTranslations` de `@i18n-micro/node` (igual que Astro y la CLI) y luego añade los métodos de rutas de VitePress con `BaseI18n.extend`:

```ts
import { createI18n } from '@i18n-micro/vitepress/node'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  translationDir: './locales',
  locales: ['en', 'fr'],
  defaultLocale: 'en',
})
await i18n.loadTranslations()
i18n.t('cta.readMore')
i18n.localizePath('/guide', 'fr')
```

Node puro sin rutas: `import { createI18n } from '@i18n-micro/node'`.

## Traducciones en la página {#in-page-translations}

Cada archivo markdown de VitePress es un SFC de Vue.

### Componentes globales y `$t` (recomendado en markdown) {#global-components-and-$t-recommended-in-markdown}

`createI18n` / `defineI18nTheme` instalan `@i18n-micro/vue`, que registra `I18nT` / `I18nLink` / `I18nGroup` / `I18nSwitcher` y `$t` / `$tc` / `$ts`.

```md
{{ $t('cta.readMore') }}

<I18nT keypath="greeting" :params="{ name: 'VitePress' }" />

<I18nLink to="/guide/demo">Demo</I18nLink>
```

### `useI18n` en `<script setup>` {#usei18n-in-<script-setup>}

```md
<script setup>
import { useI18n } from '@i18n-micro/vitepress'
const { t, tc, locale, localePath, switchLocale } = useI18n()
</script>

# {{ t('section.title') }}
```

## Desplegable de idioma {#language-dropdown}

Cuando `locales` tiene más de una entrada, VitePress muestra su propio menú de idiomas (`VPNavBarTranslations`). `withI18n` conecta `themeConfig.i18nRouting` para que el globo coincida con `<I18nSwitcher>` / los helpers de rutas.

Usa `<I18nSwitcher>` solo en layouts personalizados, no junto al globo por defecto.

## Notas sobre SSR {#ssr-notes}

- En el prerenderizado, el locale proviene de la ruta de la URL, no de las cookies.
- El código del tema no debe tocar `window` en el momento de la importación.
- Importa `defineI18nTheme` desde `/theme` para que la evaluación de la configuración en Node nunca cargue `virtual:i18n-micro/*`.

## Superficie de la API {#api-surface}

| Exportación | Función |
|--------|------|
| `createI18n` (`.`) | Cliente: plugin de Vue + métodos de rutas + `enhanceApp` |
| `getLocaleFromPath` / `stripSiteBase` / `routeNameFromPath` (`.`) | Sincronización manual del locale cuando `syncWithVitePress: false` |
| `createI18n` (`/node`) | Node: `@i18n-micro/node` + métodos de rutas |
| `defineI18nTheme` (`/theme`) | Tema sin código repetitivo |
| `withI18n` (`/config`) | Configuración + módulos virtuales + SEO opcional |
| `buildVitePressLocales` (`/config`) | Construye los `locales` de VitePress a partir de `Locale[]` |
| `buildVitePressLocaleHead` (`/config`) | Head SEO manual (también lo usa `metaBaseUrl`) |
| `messagesFromGlob` | Glob opcional → mapa de mensajes para `createI18n` |
| `useI18n` / `I18nT` / … | Reexportados desde `@i18n-micro/vue` |
| `BaseI18n.extend` (`@i18n-micro/core`) | Añade métodos personalizados a cualquier instancia de i18n |

## Sitios de estilo OpenAPI (garantías de integración) {#openapi-style-sites-integration-locks}

Suite de regresión: `packages/vitepress/tests/integration-openapi.test.ts` (rutas profundas, `base=/openapi_docs/`, sincronización desactivada + locale manual, generadores de Node, SEO).

| Patrón | Haz esto |
|---------|---------|
| Páginas profundas `/…/{spec}/{op}`, solo JSON de UI raíz | Prefiere el valor por defecto `syncWithVitePress: true` (mantiene `setRoute('index')` cuando no hay diccionario de página) **o** `syncWithVitePress: false` + `getLocaleFromPath` |
| Nunca llames a `setRoute(deepName)` sin diccionarios de página | Las claves de UI raíz desaparecen hasta `setRoute('index')` |
| Generadores / `getTranslation` | `createI18n` desde `/node` + `await loadTranslations()` + `i18n.t(key)` (define `i18n.locale`) |
| Canonical personalizado en `transformPageData` | Pasa `meta: false` a `withI18n` (evita etiquetas duplicadas) |
| SEO del paquete con base del sitio | `metaBaseUrl` + `base` de VitePress → las URL absolutas incluyen la base |
| Cambios de nombre respecto a versiones anteriores del paquete | `withI18nMicro` → `withI18n`, `createVitePressI18n` → `createI18n`, `loadMessages` → `createI18n` de node |
