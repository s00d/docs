`@i18n-micro/node` es la instancia del [runtime](/es/integrations/runtime-package) más un cargador que lee una carpeta de traducciones desde disco. Úsalo en un servidor Express o Fastify, en una CLI, en un generador de correos o PDF, o en cualquier script que necesite los mismos archivos JSON que tu app Nuxt. Cargas los archivos una vez y traduces por petición sin compartir estado mutable entre peticiones.

## Instalación {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/node @i18n-micro/utils
```

```bash npm
npm install @i18n-micro/node @i18n-micro/utils
```

```bash yarn
yarn add @i18n-micro/node @i18n-micro/utils
```

</CodeGroup>

Sin dependencias peer; Node.js `>=20`. `@i18n-micro/utils` solo es necesario para el helper de `Accept-Language` que se muestra más abajo.

## Configuración {#setup}

El cargador lee la [estructura de carpetas de Nuxt](/es/guide/translations): `locales/en.json` es un diccionario raíz, `locales/pages/blog/post/en.json` pertenece a la ruta `blog-post`.

```ts
import { createI18n } from '@i18n-micro/node'

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

i18n.t('greeting', { name: 'Ada' }) // 'Hello, Ada!'
i18n.t('title', undefined, undefined, 'blog-post') // from locales/pages/blog/post/en.json
```

Las opciones son las del runtime (consulta [la instancia](/es/integrations/overview#the-instance)) más `translationDir` y `disablePageLocales` (trata los archivos `pages/**` como diccionarios raíz). `i18n.reload()` vacía todos los diccionarios y vuelve a leer la carpeta, pensado para un vigilante de archivos en desarrollo.

`loadTranslations(dir, disablePageLocales?)` también se exporta por separado y devuelve `{ root, routes }`:

```ts
import { loadTranslations } from '@i18n-micro/node'

const { root, routes } = await loadTranslations('./locales')
// root:   { en: {...}, de: {...} }
// routes: { 'blog-post': { en: {...}, de: {...} } }
```

## Por petición {#per-request}

Una instancia contiene un idioma y una ruta. Cambiar `i18n.locale` en una instancia compartida dentro de un manejador de peticiones provoca condiciones de carrera con las peticiones concurrentes. `run` da a cada petición su propia instancia:

```ts
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

// `() => next()`: `run` hands its callback the fork, and Express reads an argument of `next` as an error
app.use((req, res, next) => i18n.run(pickLocale(req), () => next()))

app.get('/', (req, res) => {
  res.send(i18n.t('greeting')) // the request's locale, in everything it awaits
})
```

Dentro de `run`, la instancia compartida lee y establece el idioma y la ruta de la petición (`AsyncLocalStorage`); el fork empieza en la ruta actual, y `i18n.setRoute(...)` dentro del callback cambia la ruta de esa petición. El callback también recibe el fork de la petición: los diccionarios escritos en él se quedan en la petición, mientras que los escritos en la instancia compartida llegan a todos.

Sin `AsyncLocalStorage`, `i18n.fork(locale)` devuelve el mismo tipo de instancia para pasarla de un lado a otro.

`reload()` vuelve a leer el directorio; los diccionarios antiguos siguen respondiendo hasta que los nuevos están cargados.

## Elegir el idioma {#pick-the-locale}

`detectLocaleFromAcceptLanguage(header, locales)` respeta los pesos `q` y asocia `de-DE` con un idioma `de` (y `de` con `de-DE`). Devuelve `null` cuando nada coincide.

```ts
import express from 'express'
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

const app = express()

app.get('/hello', (req, res) => {
  const locale = detectLocaleFromAcceptLanguage(req.headers['accept-language'], locales) ?? 'en'
  const i18n = byLocale.get(locale)!
  res.json({ message: i18n.t('greeting', { name: 'Ada' }) })
})
```

Para combinar prefijo de URL, cookie y cabecera, `resolveLocale({ defaultLocale, validLocales, url, cookie, acceptLanguage, autoDetectLanguage: true })` de `@i18n-micro/utils/resolve-locale` aplica la precedencia del módulo: URL, luego cookie, luego `Accept-Language` y, por último, el idioma por defecto. Los valores no válidos se omiten.

Dentro de una app Nuxt no necesitas este paquete en el servidor: usa las [traducciones del lado del servidor](/es/guide/server-side-translations) del módulo.

## API {#api}

| Export | Notas |
| --- | --- |
| `createI18n(options)`, `I18n` | instancia del runtime + `translationDir`, `loadTranslations(dir?)`, `reload()` |
| `loadTranslations(dir, disablePageLocales?)` | `{ root, routes }` |
| `loadRootTranslations(dir, disablePageLocales?)` | solo `root` |
| `FormatService`, `interpolate` | de core |
| Tipos: `I18nOptions`, `LoadedTranslations`, `Translations`, `Locale`, `PluralFunc`, `Params` | |

Los métodos de la instancia se enumeran en [Runtime](/es/integrations/runtime-package#api). Firmas completas: [referencia del paquete](/es/api/packages/node).
