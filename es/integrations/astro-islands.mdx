title: "Islas de Astro"
description: "Traducciones dentro de islas de Vue, React, Preact y Svelte con @i18n-micro/astro."
---

Una isla se ejecuta en el navegador, donde no existe la instancia de i18n del servidor. `@i18n-micro/astro` permite que la página elija las claves que necesita una isla, las pase como una sola prop y las lea en la isla mediante un pequeño adaptador para cada framework. Obtienes `t`, `tc`, `tn`, `td`, `tdr` y `has` en islas de Vue, React, Preact y Svelte, con solo las cadenas elegidas en el HTML.

## Configuración {#setup}

Configura primero la [integración de Astro y el middleware](/es/integrations/astro-package#setup) y luego añade la integración del framework que uses (`@astrojs/vue`, `@astrojs/react`, `@astrojs/preact`, `@astrojs/svelte`). Los adaptadores de islas necesitan ese framework como peer: `vue` `^3.3.0`, `react` `^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`, `preact` `^10.0.0 || ^11.0.0` o `svelte` `^4.0.0 || ^5.0.0`.

## Pasar traducciones a una isla {#pass-translations-to-an-island}

```astro
---
// src/pages/index.astro
import { getI18nProps } from '@i18n-micro/astro'
import Counter from '../components/Counter.vue'

const i18n = getI18nProps(Astro, ['counter.title', 'counter.apples'])
---

<Counter client:load i18n={i18n} />
```

`getI18nProps(Astro, keys?)` devuelve `{ locale, fallbackLocale, currentRoute, translations }` (tipo `I18nClientProps`). Pasa las claves que usa la isla: cada una se resuelve en el servidor como `t()` (diccionarios de ruta, raíz y de respaldo) y solo las claves encontradas van al HTML. Sin `keys`, se envía todo lo que `t()` puede responder en esta página, en cada isla, así que 2000 claves raíz suponen unos 100 KB por isla; en desarrollo, una advertencia lo indica por encima de 20 KB.

Las islas traducen solo a partir de ese objeto. `t` devuelve la clave para cualquier cosa que no se haya pasado, y los mensajes enlazados no se resuelven.

## Vue {#vue}

Llama a `provideI18n(() => props.i18n)` en el componente raíz de la isla y a `useAstroI18n()` en sus hijos. El `inject` de Vue no ve un valor proporcionado por el mismo componente, así que el hook debe ejecutarse en un hijo, no en la raíz:

```vue
<!-- src/components/Counter.vue -->
<script setup lang="ts">
import { provideI18n } from '@i18n-micro/astro/client/vue'
import type { I18nClientProps } from '@i18n-micro/astro'
import CounterBody from './CounterBody.vue'

const props = defineProps<{ i18n: I18nClientProps }>()
provideI18n(() => props.i18n)
</script>

<template><CounterBody /></template>
```

```vue
<!-- src/components/CounterBody.vue -->
<script setup lang="ts">
import { ref } from 'vue'
import { useAstroI18n } from '@i18n-micro/astro/client/vue'

const { t, tc } = useAstroI18n()
const count = ref(0)
</script>

<template>
  <h3>{{ t('counter.title') }}</h3>
  <button @click="count++">{{ tc('counter.apples', count) }}</button>
</template>
```

## React y Preact {#react-and-preact}

```tsx
// src/components/Counter.tsx
import { useState } from 'react'
import { I18nProvider, useAstroI18n } from '@i18n-micro/astro/client/react'
import type { I18nClientProps } from '@i18n-micro/astro'

function Body() {
  const { t, tc } = useAstroI18n()
  const [count, setCount] = useState(0)
  return <button onClick={() => setCount(count + 1)}>{t('counter.title')}: {tc('counter.apples', count)}</button>
}

export default function Counter({ i18n }: { i18n: I18nClientProps }) {
  return (
    <I18nProvider value={i18n}>
      <Body />
    </I18nProvider>
  )
}
```

Para Preact, importa `I18nProvider` y `useAstroI18n` desde `@i18n-micro/astro/client/preact`; la API es la misma.

## Svelte {#svelte}

```svelte
<!-- src/components/Counter.svelte -->
<script lang="ts">
  import { createI18nStore, useAstroI18n } from '@i18n-micro/astro/client/svelte'
  import type { I18nClientProps } from '@i18n-micro/astro'

  export let i18n: I18nClientProps
  const { t, tc } = useAstroI18n(createI18nStore(i18n))
  let count = 0
</script>

<button on:click={() => count++}>{t('counter.title')}: {tc('counter.apples', count)}</button>
```

`useAstroI18n(store)` también devuelve el `store` para lecturas con `$store` en la plantilla.

## Islas persistentes {#persisted-islands}

Una isla con `transition:persist` recibe props nuevas tras una navegación. React, Preact y Vue (si se le pasa un getter) las siguen. En Svelte, conserva el store y pásaselas: `const store = createI18nStore(i18n)`, `const { t } = useAstroI18n(store)`, y después `$: store.set(i18n)` (con runes, `$effect(() => store.set(i18n))`).

## API {#api}

| Entrada | Exportaciones |
| --- | --- |
| `@i18n-micro/astro` | `getI18nProps`, tipo `I18nClientProps` |
| `@i18n-micro/astro/client/vue` | `provideI18n(props \| () => props)`, `useAstroI18n()` |
| `@i18n-micro/astro/client/react` | `I18nProvider` (prop `value`), `useAstroI18n()` |
| `@i18n-micro/astro/client/preact` | `I18nProvider` (prop `value`), `useAstroI18n()` |
| `@i18n-micro/astro/client/svelte` | `createI18nStore(props)`, `useAstroI18n(store)` |
| `@i18n-micro/astro/client` | las funciones puras `translate` y `hasTranslation`, sin framework |

Cada `useAstroI18n` devuelve `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `setLocale`, `setRoute` y el `locale`. Una isla tiene un único diccionario fusionado, así que su `has` es verdadero para cualquier clave que `t` pueda responder, también desde el locale de respaldo; en el servidor, `has` solo mira el locale activo.
