## Nuxt I18n Micro v3.22.0 — Formatos, cache e Translation Memory {#nuxt-i18n-micro-v3-22-0-—-formats-cache-&-translation-memory}

**Data**: 2026-07-30

**Versão**: `v3.22.0`

![Versão v3.22.0](/images/3.22.0.png)

Anunciamos a **v3.22.0**: formatos nomeados de números/datas no estilo Vue I18n com cache de formatadores, cache de payloads de tradução amigável a CDN (fingerprint de conteúdo + `httpCacheDuration`) e uma API de Translation Memory para ler e substituir o dicionário ativo em runtime.

## O que há de novo? {#what’s-new}

### `numberFormats` / `datetimeFormats` nomeados + cache de formatadores {#named-numberformats-/-datetimeformats-+-formatter-cache}

Formatos nomeados compatíveis com Vue I18n e formatação Intl mais rápida:

- Configuração: `numberFormats` / `datetimeFormats` por locale
- API: `$tn(1000, 'currency')`, `$td(date, 'short')` (+ substituição de locale e mesclagem de opções)
- `FormatService` armazena em cache `Intl.NumberFormat` / `DateTimeFormat` / `RelativeTimeFormat` por locale+opções

Veja [Métodos — `$tn` / `$td`](/pt-BR/api/methods#$tn) e [Opções do módulo](/pt-BR/api/module-options#numberformats).

### `dateBuild` passa a usar por padrão um fingerprint de conteúdo {#datebuild-defaults-to-a-content-fingerprint}

O `?v=` nas requisições a `/_locales` usava por padrão `Date.now()`, enquanto as respostas são servidas como `immutable` por um ano. Assim, cada rebuild invalidava o dicionário de todos os clientes, mesmo quando nenhuma tradução havia mudado.

O padrão agora é um fingerprint SHA-256 das fontes de tradução, na ordem das camadas. Rebuilds com traduções inalteradas mantêm a mesma URL. Definir `dateBuild` explicitamente continua tendo prioridade. Veja [Opções do módulo — `dateBuild`](/pt-BR/api/module-options#datebuild).

### `httpCacheDuration` para payloads de `/_locales` {#httpcacheduration-for-/_locales-payloads}

A rota integrada `/{apiBaseUrl}/:page/:locale/data.json` agora envia o cabeçalho HTTP `Cache-Control` para navegadores e CDN:

- Opção: `httpCacheDuration` (segundos, padrão `31536000` / 1 ano)
- Cabeçalho: `Cache-Control: public, max-age=…, immutable`
- Seguro com o cache-busting existente de `dateBuild` (`?v=...`); `0` desativa o cabeçalho; não é aplicado em desenvolvimento

Equivalente ao `experimental.httpCacheDuration` do `@nuxtjs/i18n` v10.2.0, como um cabeçalho de resposta explícito.

### Payloads públicos comprimidos {#compressed-public-payloads}

`nitro.compressPublicAssets` agora alcança os payloads de tradução copiados para o diretório público (`.gz` + `.br`). O Nitro comprime os assets públicos antes de a cópia acontecer, então antes os payloads eram a única parte não comprimida de um build estático — 6,65 MB brutos contra 1,01 MB em gzip no índice do playground. O módulo continua nunca ativando a compressão por conta própria. Veja [Desempenho](/pt-BR/guide/performance#payload-size).

### `resolveTranslations()` e `setTranslation(key, value)` {#resolvetranslations-and-settranslationkey-value}

Helpers de runtime para ler e substituir o dicionário de tradução ativo em memória:

- **`resolveTranslations()`** retorna a árvore completa da qual `$t()` lê para o locale e a rota ativos — útil para DevTools, testes e editores em runtime. Quando uma segunda camada está ativa (locale de fallback ou hot-reload de transição de página do Nuxt), o dump mantém a forma aninhada via `mergeTranslationLayers` e só usa chaves planas com pontos para colisões entre escalar e objeto que uma única árvore não consegue expressar de outra forma.
- **`setTranslation(key, value)`** substitui o valor em uma chave (nível superior, caminho com pontos, objeto, string ou escalar). Isto é uma **substituição**, não uma mesclagem; use `$mergeTranslations` quando as chaves irmãs devem ser preservadas.
- Disponível em `useI18n()`, `useNuxtApp()` e nas instâncias i18n dos frameworks herdadas de `@i18n-micro/core`.
- `@i18n-micro/test-utils` adiciona os helpers correspondentes `resolveTranslations` / `setTranslation` para testes unitários.

### `getAllTranslations()` removido do pacote Vue {#getalltranslations-removed-from-vue-package}

Use `resolveTranslations()` para a árvore de busca ativa. Para um dump completo do armazenamento no Vue, use `getStorage()` ou `getRouteCache()`.

## Mudanças incompatíveis {#breaking-changes}

Nada na superfície pública de configuração exige edições no código da aplicação para o uso típico. Estes pontos importam se você acessava internals do runtime:

- **O payload de SSR mudou de `useState('i18n-ssr-chunks')` para `nuxtApp.payload.data['i18n-ssr-chunks']`.** Ele ainda carrega **chunks de tradução completos** para cada `(locale, route)` carregado durante o SSR — os mesmos dicionários de antes, em um slot que o Nuxt pode externalizar para `_payload.json` no prerender. `useState('i18n-ssr-chunks')` agora não retorna nada. Ler traduções dessa forma nunca foi suportado, mas isso estava descrito na documentação da API de cache, por isso é mencionado aqui.
- **`NuxtTranslationLoaderOptions` expõe `setSsrChunk`.** O loader grava cada chunk mesclado em `payload.data` no servidor à medida que carrega. `getSsrChunks` não é usado.
- **`nitro.compressPublicAssets` agora emite `.gz` / `.br` ao lado dos payloads copiados.** Espere mais arquivos na saída pública se você o tinha ativado. Ferramentas de deploy que enumeram o diretório de traduções podem precisar levá-los em conta.
- **As URLs dos payloads mudam uma vez na atualização**, porque `?v=` passa de um timestamp de build para um fingerprint de conteúdo. Os clientes baixam novamente o dicionário na primeira requisição após a atualização e depois o mantêm entre deploys subsequentes — que é justamente o objetivo.
- **`getAllTranslations()` removido de `@i18n-micro/vue`.** Use `resolveTranslations()` / `getStorage()` / `getRouteCache()` em vez disso.

## Correções de bugs {#bug-fixes}

- **`<i18n-switcher>`** — omite do dropdown os locales com `disabled: true`. `$getLocales()` continua retornando a lista completa para o seu próprio código, enquanto a saída integrada de SEO/meta exclui os locales desativados.
- **Estilos do switcher** — `cursor: not-allowed` se aplica ao locale **atual** via `activeLinkStyle` / `customActiveLinkStyle`; `customDisabledLinkStyle` foi restaurado para compatibilidade retroativa e é aplicado ao botão do switcher quando o locale atual tem `disabled: true`.
- **HMR em dev** — uma gravação que deixa o conteúdo do arquivo inalterado (salvar ao perder o foco no editor, reescrita do formatador) não dispara mais uma nova mesclagem. Mudanças no locale raiz reconstroem todas as páginas desse locale, então isso era caro demais para gastar com uma operação sem efeito.
- **HMR em dev** — as páginas são mescladas novamente de forma concorrente em uma mudança do locale raiz, em vez de uma após a outra.
- **Transições de página** — a navegação no mesmo locale mantém o chunk de saída como camada de fallthrough até `page:transition:finish`, em vez de fazer uma mesclagem profunda cara a cada navegação.

## Por que isso importa {#why-it-matters}

- Formatação no estilo Vue I18n sem trazer uma stack mais pesada.
- URLs de tradução amigáveis a CDN que permanecem estáveis entre rebuilds quando o dicionário não mudou.
- Uma API de runtime suportada para inspecionar e modificar o dicionário ativo — DevTools, testes e editores não precisam mais de helpers privados.

O changelog completo será publicado com a versão no [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).

## Correção: loop de redirecionamento infinito com `app.baseURL` + `strategy: 'prefix'` (#234) {#fix-infinite-redirect-loop-with-app-baseurl-+-strategy-‘prefix’-#234}

**Data**: 2026-07-03

O plugin de redirecionamento do lado do servidor (`06.redirect.ts`) agora remove `runtimeConfig.app.baseURL` de `getRequestURL(event).pathname` antes da detecção de locale. Corrige `ERR_TOO_MANY_REDIRECTS` quando a aplicação é servida em um subcaminho (por exemplo, `/examples` → `/examples/ja` uma única vez, e não `/examples/ja/examples/ja/...`).
