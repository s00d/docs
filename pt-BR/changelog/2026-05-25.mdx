**Data**: 2026-05-25

**Versão**: `v3.19.0`

![Versão v3.19.0](/images/3.19.0.png)

Esta versão se concentra em **modularizar utilitários internos**, adicionar um **modo de payload compacto para serverless** e **reutilizar lógica compartilhada** entre Nuxt, Node, Astro e DevTools — sem alterar a API pública do módulo para apps típicos.

## O que há de novo? {#what’s-new}

### `@i18n-micro/utils` — Utilitários independentes de framework {#@i18n-micro/utils-—-framework-agnostic-utilities}

A lógica compartilhada que antes estava espalhada por `src/runtime/utils/` e `src/module.ts` agora vive em um pacote dedicado do workspace, com **imports granulares por subcaminho** (sem barrel inchado, compatível com tree-shaking):

- **Build** — `preMergeLocales`, `buildTranslationSourceLayers` (`@i18n-micro/utils/build`)
- **Payloads** — resolução de `translationPayloads`, construção de URLs, helpers de fetch, estatísticas (`payload-config`, `payload-url`, `payload-fetch`, `payload-stats`)
- **Modo source** — cadeias de fallback, caminhos de arquivos de origem, mesclagem em tempo de execução (`merge-source`, `source-loader`)
- **Helpers de runtime** — resolução de locale, cookies, parsing de Accept-Language, helpers de rota/meta (`resolve-locale`, `accept-language`, `cookie`, `route`, `route-pattern`, `runtime-config`)
- **Caminhos de FS compartilhados** — classificação de arquivos de tradução, caminhos de páginas aninhadas (`parse-path`)

O módulo Nuxt mantém apenas uma camada fina de integração em `src/runtime/` e importa só os subcaminhos de que precisa.

### `@i18n-micro/hmr` — Hot reload de traduções em desenvolvimento {#@i18n-micro/hmr-—-dev-translation-hot-reload}

O HMR de desenvolvimento foi extraído para `@i18n-micro/hmr`:

- **`watcher`** — tratamento de alterações de arquivos, invalidação de cache, mesclagem source/premerged em dev
- **`generate-plugin`** — geração do plugin de HMR no lado do cliente
- **`cache-keys`** — chaves `Symbol.for` compartilhadas para caches de servidor/armazenamento

Funciona tanto com `translationPayloads.mode: 'premerged'` quanto com `'source'`.

### `translationPayloads.mode: 'source'` — Deploys serverless compactos {#translationpayloads-mode-‘source’-—-compact-serverless-deployments}

Novo modo de payload para grandes matrizes de locales em plataformas serverless (Cloudflare Workers etc.):

```typescript
export default defineNuxtConfig({
  i18n: {
    translationPayloads: {
      mode: 'source',
    },
  },
})
```

- Empacota **arquivos de origem compactos** nos assets do Nitro em vez de uma matriz completa pré-mesclada
- Mescla as cadeias de locale raiz, de página e de fallback **em tempo de execução** por meio da rota embutida `/_locales/:page/:locale/data.json`
- Define `publicAssets` e `prerenderRoutes` como `false` por padrão — ideal quando você depende de um runtime Nitro/edge em vez de hospedagem puramente estática

Veja [Deploy — serverless e Edge](/pt-BR/guide/deployment#serverless-and-edge) e [Arquitetura de cache e armazenamento](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api).

### Utilitários compartilhados entre pacotes de integração {#shared-utilities-across-integration-packages}

- **`@i18n-micro/node`** e **`@i18n-micro/astro`** — parsing de caminhos de tradução e deep merge unificados via `@i18n-micro/utils/parse-path`
- **`@i18n-micro/astro`** — `detectLocaleFromAcceptLanguage` de `@i18n-micro/utils/accept-language` (parser duplicado removido)
- **`@i18n-micro/devtools-ui`** — caminhos de arquivos virtuais via helpers `merge-source` + `parse-path`
- **Detecção de locale no servidor** — tratamento de Accept-Language alinhado aos utils compartilhados

### Correções de HMR e DevTools {#hmr-&-devtools-fixes}

- O plugin de HMR do cliente agora chama **`$loadPageTranslations`** (a API correta) em vez do removido `$loadTranslations`
- Cobertura com Playwright para o watcher de traduções nos modos **premerged** e **source**

## Mudanças incompatíveis (avançado / interno) {#breaking-changes-advanced-/-internal}

Afetam apenas projetos que importavam caminhos **internos** do módulo (que não fazem parte da API pública):

- Removidos de `src/runtime/utils/`: `route-utils.ts`, `runtime-i18n-config.ts` e outros utilitários movidos para `@i18n-micro/utils/*`
- Removidos de `src/runtime/server/plugins/`: watcher/gerador de HMR embutido — use `@i18n-micro/hmr/*` se você fez fork das ferramentas de desenvolvimento
- **`nuxt-i18n-micro`** agora depende dos pacotes de workspace `@i18n-micro/utils` e `@i18n-micro/hmr` (instalados automaticamente com o módulo)

O uso típico de `nuxt.config` + composables não muda.

## Por que isso importa {#why-it-matters}

- **Bundles serverless menores** — o modo `source` evita enviar um arquivo pré-mesclado por locale × página
- **Fonte única da verdade** — uma única implementação para parsing de caminhos, mesclagem, detecção de locale e configuração de payload
- **Manutenção mais fácil** — o código independente de framework é testado em `@i18n-micro/utils` (mais de 50 testes unitários) e reutilizado em todo lugar
- **Melhor DX em desenvolvimento** — a lógica de HMR é isolada, testável e consistente entre os modos de payload
