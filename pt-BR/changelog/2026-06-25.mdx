**Data**: 2026-06-25

**Versão**: `v3.21.0`

![v3.21.0 release](/images/3.21.0.png)

Esta versão adiciona o **`useI18nHead`** — um composable em nível de página para sobrescritas de SEO de i18n sobre o plugin integrado `02.meta`. Personalize `hreflang`, canonical, `og:url` e tags Open Graph por rota sem um plugin de meta personalizado nem `meta: false`.

## O que há de novo? {#what’s-new}

### Composable `useI18nHead` {#usei18nhead-composable}

Chame `useI18nHead` em qualquer página quando `meta: true` (padrão). O módulo mescla sua entrada após `useLocaleHead` a cada atualização de rota:

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

Suporta objetos estáticos, getters reativos, acréscimo de `meta` / `link`, `replace` para grupos integrados e `disable` para remover tags geradas automaticamente. Veja [`useI18nHead`](/pt-BR/composables/useI18nHead).

### Utilitário `mergeI18nHead` (`@i18n-micro/utils`) {#mergei18nhead-utility-@i18n-micro/utils}

A lógica de mesclagem independente de framework fica em `@i18n-micro/utils/merge-i18n-head` — usada pelo plugin `02.meta` e testável isoladamente. Os tipos (`I18nHeadInput`, `I18nHeadLink`, `I18nHeadMeta`) são exportados de `@i18n-micro/types`.

### Integração com plugins {#plugin-integration}

- **`02.meta`** — mescla a saída de `useLocaleHead` com o estado da página de `useI18nHead` via `useHead`
- **`01.plugin`** — redefine as sobrescritas da página na mudança de nome de rota via `resetPageHead()` (estado compartilhado com o composable)

### Documentação e testes {#documentation-&-tests}

- Novo guia: [`useI18nHead`](/pt-BR/composables/useI18nHead) com exemplos de CMS/artigos
- Atualizados [SEO](/pt-BR/guide/seo) e [`useLocaleHead`](/pt-BR/composables/useLocaleHead) — quando usar cada API

## Casos de uso típicos {#typical-use-cases}

| Cenário                                      | Abordagem                                                      |
| -------------------------------------------- | -------------------------------------------------------------- |
| Blog/CMS com traduções parciais              | `replace.hreflang` + `replace.ogAlternates` a partir dos locales da API |
| Canonical personalizado vindo do CMS         | `replace.canonical` + `replace.ogUrl`                          |
| Apenas OG em landing page                    | `meta: [{ property: 'og:title', ... }]` — mantém o hreflang do módulo |
| Sem hreflang em uma página                   | `disable: ['hreflang', 'x-default']`                           |
| Substituir plugin personalizado (`i18nManualHreflang`) | `useI18nHead` por página de conteúdo + `meta: true`  |

**JSON-LD** permanece em `useHead({ script: [...] })` — `useI18nHead` não gera dados estruturados.

## Mudanças incompatíveis {#breaking-changes}

Nenhuma para o uso padrão de `nuxt.config`. O novo composable e o subcaminho de utils são aditivos.

## Por que isso importa {#why-it-matters}

- **Sem plugin de meta personalizado** para posts de CMS, notícias ou guias com URLs por locale
- **Pipeline único** — padrões do módulo + sobrescritas da página em uma única chamada `useHead`
- **Type-safe** — `I18nHeadInput` para helpers como `buildArticleHead(content)`
