---
title: "useI18nHead"
description: "useI18nHead sobrescreve as tags de SEO i18n geradas para uma página: substitua ou remova as tags canonical, hreflang e og, ou adicione as suas."
---

`useI18nHead()` altera as tags de SEO que o módulo gera, apenas para uma página. Use-o quando uma página sabe mais que o router: um artigo de CMS que existe só em alguns locales, uma URL canônica vinda de uma API, tags `og:` extras. Você recebe as tags geradas com as suas sobrescritas mescladas por cima.

## Assinatura {#signature}

```ts
useI18nHead(input?: MaybeRefOrGetter<I18nHeadInput | null>): { pageHead: any; resetPageHead: () => void }
```

Registra sobrescritas no nível da página para as tags de head de SEO i18n.
São mescladas sobre a saída de `useLocaleHead` pelo plugin `02.meta`.

Prefira um getter (`() => ({ … })`) quando os valores vêm de `$t` / `t`, para que eles
sejam resolvidos novamente quando o locale mudar. Um objeto simples é avaliado uma vez e permanece congelado.

| Parâmetro | Tipo | Descrição |
| --- | --- | --- |
| `input` *(opcional)* | `MaybeRefOrGetter<I18nHeadInput \| null>` |  |

Funciona com [`meta: true`](/pt-BR/api/module-options#meta) (o padrão): o plugin de meta do módulo mescla a entrada sobre a saída de [`useLocaleHead`](/pt-BR/composables/useLocaleHead) a cada renderização do head. Com `meta: false`, nada a lê.

A sobrescrita é redefinida quando o nome da rota muda. Uma página que define `disableMeta` não recebe nenhuma tag i18n, incluindo as sobrescritas.

## Entrada {#input}

`I18nHeadInput` (de `@i18n-micro/types`):

| Chave | Tipo | Efeito |
| --- | --- | --- |
| `htmlAttrs` | `Record<string, string>` | Mesclado nos atributos de `<html>` (`lang`, `dir`). |
| `meta` | `I18nHeadMeta[]` | Adicionado após as tags geradas; substitui uma tag com o mesmo `id`, `property` ou `name`. |
| `link` | `I18nHeadLink[]` | Adicionado após os links gerados; substitui um link com o mesmo `id`, ou `rel` + `hreflang`. |
| `replace.canonical` | `string \| false` | Substitui o `href` canônico ou remove o link. |
| `replace.hreflang` | `I18nHeadLink[] \| false` | Substitui ou remove **todos** os links `rel="alternate"`, incluindo `x-default`. |
| `replace.xDefault` | `I18nHeadLink \| false` | Substitui ou remove o link `x-default`. |
| `replace.ogLocale` | `string \| false` | Substitui ou remove `og:locale`. |
| `replace.ogUrl` | `string \| false` | Substitui ou remove `og:url`. |
| `replace.ogAlternates` | `string[] \| false` | Reconstrói `og:locale:alternate` a partir desses códigos de locale (via `og` / `iso`), ignorando o locale atual, códigos desconhecidos e códigos sem valor `og` ou `iso`, ou os remove. |
| `disable` | `I18nHeadDisableGroup[]` | Remove grupos gerados: `'hreflang'` (não `x-default`), `'x-default'`, `'canonical'`, `'og'` (`og:locale` + `og:url`), `'og-alternates'`, `'html'`. |

Ordem de aplicação: `disable`, depois `replace`, depois `htmlAttrs`, `meta`, `link`.

## Exemplo {#example}

Um artigo que existe apenas em alguns locales, com URLs alternativas vindas da API:

```vue
<script setup lang="ts">
const route = useRoute()
const { t } = useI18n()
const { data: article } = await useFetch<{ title: string; urls: Record<string, string> }>(`/api/articles/${route.params.slug}`)

useI18nHead(() => {
  if (!article.value) return null
  const codes = Object.keys(article.value.urls)
  return {
    meta: [{ property: 'og:title', content: article.value.title || t('blog.title') }],
    replace: {
      hreflang: codes.map((code) => ({ rel: 'alternate', hreflang: code, href: article.value!.urls[code]! })),
      ogAlternates: codes,
    },
  }
})
</script>
```

Passe um getter, como aqui, quando os valores vierem de `t()` ou de dados assíncronos: ele é executado novamente quando o locale muda. Um objeto simples é lido uma única vez.
