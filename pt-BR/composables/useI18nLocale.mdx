---
title: "useI18nLocale"
description: "useI18nLocale lê e grava o estado do locale e o cookie de locale — o ponto de entrada para a detecção de locale personalizada."
---

`useI18nLocale()` dá acesso ao locale escolhido pela aplicação: o estado `i18n-locale` e o cookie de locale. Use-o em um plugin que detecta o locale por conta própria (domínio, perfil do usuário, header) em vez de gravar `useState('i18n-locale')` ou o cookie manualmente. Suas verificações de validade usam os locales habilitados, incluindo as substituições em tempo de execução.

## Assinatura {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Ponto de entrada centralizado para o gerenciamento do locale de i18n.
Combina useState('i18n-locale'), o cookie de locale e utilitários de sincronização.

## Valores retornados {#returned-values}

| Membro | Tipo | Descrição |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | A ref `useState('i18n-locale')`. |
| `localeCookie` | `Ref<string \| null>` | O cookie [`localeCookie`](/pt-BR/api/module-options#localecookie); um simples `{ value: null }` quando a opção é `null`. |
| `hashCookie` | `Ref<string \| null>` | O cookie `hash-locale` com roteamento por hash; `{ value: null }` caso contrário. |
| `validLocales` | `string[]` | Códigos dos locales habilitados. |
| `setLocale(locale)` | `(locale: string \| null) => void` | Grava o estado e os cookies. Não valida e não carrega traduções. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | Grava apenas os cookies. |
| `getLocale()` | `() => string \| null` | O estado e, em seguida, o cookie de preferência (o cookie de hash com roteamento por hash). Não validado. |
| `getPreferredLocale()` | `() => string \| null` | O primeiro valor **válido** entre o estado e o cookie de preferência, ou `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | O estado, com roteamento por hash, quando definido; caso contrário, `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, depois um estado válido, depois `options.serverLocale` e, por fim, o locale da rota. Armazena o resultado no estado quando o estado não é válido; no cliente, também grava o cookie. |
| `isValidLocale(locale)` | `(locale) => locale is string` | Indica se `locale` está em `validLocales`. |

Os cookies duram um ano, com `path: '/'` e `sameSite: 'lax'`.

## Exemplo {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

O plugin loader do módulo lê o estado ao iniciar, então um plugin que o define deve ser executado antes (`enforce: 'pre'`). Como o estado concorre com a URL, o cookie e o `Accept-Language`: [Detecção de locale](/pt-BR/guide/locale-detection). Passo a passo completo: [Detecção personalizada](/pt-BR/guide/custom-auto-detect).

`setLocale()` não troca as traduções exibidas na tela. Para mudar o locale da página atual, chame [`$switchLocale()`](/pt-BR/api/methods#$switchlocale).
