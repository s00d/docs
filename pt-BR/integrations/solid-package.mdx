`@i18n-micro/solid` fornece às aplicações SolidJS uma instância de i18n baseada em signals, um provider, `useI18n()` e quatro componentes. Use-o em uma aplicação Solid que não é construída com Nuxt. Leituras de `t()` dentro de JSX ou de effects rastreiam o locale, a rota e os dicionários; o modelo compartilhado está em [Frameworks](/pt-BR/integrations/overview).

## Instalação {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer dependencies: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (opcional, apenas para `@i18n-micro/solid/router`). Solid 2 ainda não é suportado.

## Configuração {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` recebe `i18n`, `locales`, `defaultLocale` e `routingStrategy`; uma prop omitida mantém o valor do provider externo, inclusive a instância. `getLocaleName()` e `<I18nSwitcher>` leem `locales`; sem eles, não têm nada para listar. As opções estão em [a instância](/pt-BR/integrations/overview#the-instance). A instância é a do [runtime](/pt-BR/integrations/runtime-package), com um signal sobre o seu store.

## Traduzir {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Chame os métodos dentro de JSX ou de um effect para que o Solid os rastreie, incluindo `localePath` e `getLocale`; um valor lido uma única vez no corpo do componente não é atualizado. Na instância, rastreie com `i18n.locale` e `i18n.currentRoute`: `i18n.getLocale()` permanece simples, porque as escritas o leem. Ler o locale reage apenas ao locale, então um effect que o lê e carrega um dicionário roda uma vez. Não desestruture props nem guarde resultados de `t('key')` em variáveis simples.

`useI18n()` retorna `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (um accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` e `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Trocar de locale {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Trocar não carrega nada; adicione primeiro o dicionário do locale.

`<I18nGroup>` passa um `t` com prefixo para um filho do tipo função. `<I18nT>` e `t()` dentro dele não recebem prefixo:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Roteamento {#routing}

O adaptador de `@solidjs/router` fica em um subpath para que a entrada principal nunca importe o router. Chame-o abaixo do router, normalmente no `root` do router, onde `useNavigate` e `useLocation` funcionam:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

O adaptador adiciona prefixo a todos os locales exceto o padrão (`/about`, `/de/about`) e renderiza `<I18nLink>` como o `<A>` do router. `getCurrentPath` lê a localização reativa do router, então os links ativos e o seletor a acompanham; uma estratégia personalizada obtém o mesmo lendo um signal ali. Observe a ordem dos argumentos: `(locales, defaultLocale, navigate, location)`. Para outros routers, escreva um adaptador com `getCurrentPath`, `push` e `replace` (todos obrigatórios) — veja [Adaptador de router](/pt-BR/integrations/overview#router-adapter).

## SSR {#ssr}

Para renderização no servidor, faça o build com `vite-plugin-solid`: a condição de export `solid` do pacote entrega o código-fonte a ele, para que seja compilado para o servidor. O `dist` pré-compilado é apenas para o navegador. A instância não tem `destroy()`; crie uma por aplicação, ou uma por requisição no servidor, e deixe o garbage collector cuidar dela.
