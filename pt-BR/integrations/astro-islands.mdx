title: "Ilhas do Astro"
description: "Traduções dentro de ilhas Vue, React, Preact e Svelte com @i18n-micro/astro."
---

Uma ilha é executada no navegador, onde a instância de i18n do servidor não existe. `@i18n-micro/astro` permite que a página escolha as chaves de que uma ilha precisa, passe-as como uma única prop e as leia na ilha por meio de um pequeno adaptador do framework. Você obtém `t`, `tc`, `tn`, `td`, `tdr` e `has` em ilhas Vue, React, Preact e Svelte, com apenas as strings escolhidas no HTML.

## Configuração {#setup}

Primeiro configure a [integração e o middleware do Astro](/pt-BR/integrations/astro-package#setup) e depois adicione a integração do framework que você usa (`@astrojs/vue`, `@astrojs/react`, `@astrojs/preact`, `@astrojs/svelte`). Os adaptadores de ilha precisam desse framework como peer: `vue` `^3.3.0`, `react` `^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`, `preact` `^10.0.0 || ^11.0.0` ou `svelte` `^4.0.0 || ^5.0.0`.

## Passar traduções para uma ilha {#pass-translations-to-an-island}

```astro
---
// src/pages/index.astro
import { getI18nProps } from '@i18n-micro/astro'
import Counter from '../components/Counter.vue'

const i18n = getI18nProps(Astro, ['counter.title', 'counter.apples'])
---

<Counter client:load i18n={i18n} />
```

`getI18nProps(Astro, keys?)` retorna `{ locale, fallbackLocale, currentRoute, translations }` (tipo `I18nClientProps`). Passe as chaves que a ilha usa: cada uma é resolvida no servidor como `t()` (dicionários da rota, raiz e de fallback) e apenas as chaves encontradas vão para o HTML. Sem `keys`, tudo o que `t()` consegue responder nesta página é enviado, em cada ilha, então 2000 chaves raiz somam cerca de 100 KB por ilha; em dev, um aviso indica isso acima de 20 KB.

As ilhas traduzem apenas a partir desse objeto. `t` retorna a própria chave para qualquer coisa que não tenha sido passada, e mensagens vinculadas não são resolvidas.

## Vue {#vue}

Chame `provideI18n(() => props.i18n)` no componente raiz da ilha e `useAstroI18n()` nos seus filhos. O `inject` do Vue não enxerga um valor fornecido pelo mesmo componente, então o hook precisa rodar em um filho, não na raiz:

```vue
<!-- src/components/Counter.vue -->
<script setup lang="ts">
import { provideI18n } from '@i18n-micro/astro/client/vue'
import type { I18nClientProps } from '@i18n-micro/astro'
import CounterBody from './CounterBody.vue'

const props = defineProps<{ i18n: I18nClientProps }>()
provideI18n(() => props.i18n)
</script>

<template><CounterBody /></template>
```

```vue
<!-- src/components/CounterBody.vue -->
<script setup lang="ts">
import { ref } from 'vue'
import { useAstroI18n } from '@i18n-micro/astro/client/vue'

const { t, tc } = useAstroI18n()
const count = ref(0)
</script>

<template>
  <h3>{{ t('counter.title') }}</h3>
  <button @click="count++">{{ tc('counter.apples', count) }}</button>
</template>
```

## React e Preact {#react-and-preact}

```tsx
// src/components/Counter.tsx
import { useState } from 'react'
import { I18nProvider, useAstroI18n } from '@i18n-micro/astro/client/react'
import type { I18nClientProps } from '@i18n-micro/astro'

function Body() {
  const { t, tc } = useAstroI18n()
  const [count, setCount] = useState(0)
  return <button onClick={() => setCount(count + 1)}>{t('counter.title')}: {tc('counter.apples', count)}</button>
}

export default function Counter({ i18n }: { i18n: I18nClientProps }) {
  return (
    <I18nProvider value={i18n}>
      <Body />
    </I18nProvider>
  )
}
```

Para Preact, importe `I18nProvider` e `useAstroI18n` de `@i18n-micro/astro/client/preact`; a API é a mesma.

## Svelte {#svelte}

```svelte
<!-- src/components/Counter.svelte -->
<script lang="ts">
  import { createI18nStore, useAstroI18n } from '@i18n-micro/astro/client/svelte'
  import type { I18nClientProps } from '@i18n-micro/astro'

  export let i18n: I18nClientProps
  const { t, tc } = useAstroI18n(createI18nStore(i18n))
  let count = 0
</script>

<button on:click={() => count++}>{t('counter.title')}: {tc('counter.apples', count)}</button>
```

`useAstroI18n(store)` também retorna o `store` para leituras com `$store` no template.

## Ilhas persistidas {#persisted-islands}

Uma ilha com `transition:persist` recebe novas props após uma navegação. React, Preact e Vue (quando recebe um getter) as acompanham. No Svelte, mantenha o store e repasse-as: `const store = createI18nStore(i18n)`, `const { t } = useAstroI18n(store)`, depois `$: store.set(i18n)` (com runes, `$effect(() => store.set(i18n))`).

## API {#api}

| Entrada | Exportações |
| --- | --- |
| `@i18n-micro/astro` | `getI18nProps`, tipo `I18nClientProps` |
| `@i18n-micro/astro/client/vue` | `provideI18n(props \| () => props)`, `useAstroI18n()` |
| `@i18n-micro/astro/client/react` | `I18nProvider` (prop `value`), `useAstroI18n()` |
| `@i18n-micro/astro/client/preact` | `I18nProvider` (prop `value`), `useAstroI18n()` |
| `@i18n-micro/astro/client/svelte` | `createI18nStore(props)`, `useAstroI18n(store)` |
| `@i18n-micro/astro/client` | as funções puras `translate`, `hasTranslation`, sem framework |

Todo `useAstroI18n` retorna `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `setLocale`, `setRoute` e o `locale`. Uma ilha tem um único dicionário mesclado, então seu `has` é verdadeiro para uma chave que `t` consegue responder, inclusive a partir do locale de fallback; no servidor, `has` considera apenas o locale ativo.
