`@i18n-micro/node` é a instância do [runtime](/pt-BR/integrations/runtime-package) mais um loader que lê uma pasta de traduções do disco. Use-o em um servidor Express ou Fastify, em uma CLI, em um gerador de e-mails ou PDFs, ou em qualquer script que precise dos mesmos arquivos JSON da sua aplicação Nuxt. Você carrega os arquivos uma vez e traduz por requisição sem compartilhar estado mutável entre requisições.

## Instalação {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/node @i18n-micro/utils
```

```bash npm
npm install @i18n-micro/node @i18n-micro/utils
```

```bash yarn
yarn add @i18n-micro/node @i18n-micro/utils
```

</CodeGroup>

Sem peer dependencies; Node.js `>=20`. `@i18n-micro/utils` só é necessário para o helper de `Accept-Language` abaixo.

## Configuração {#setup}

O loader lê a [estrutura de pastas do Nuxt](/pt-BR/guide/translations): `locales/en.json` é um dicionário raiz, `locales/pages/blog/post/en.json` pertence à rota `blog-post`.

```ts
import { createI18n } from '@i18n-micro/node'

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

i18n.t('greeting', { name: 'Ada' }) // 'Hello, Ada!'
i18n.t('title', undefined, undefined, 'blog-post') // from locales/pages/blog/post/en.json
```

As opções são as do runtime (veja [a instância](/pt-BR/integrations/overview#the-instance)) mais `translationDir` e `disablePageLocales` (tratar arquivos `pages/**` como dicionários raiz). `i18n.reload()` limpa todos os dicionários e lê a pasta novamente, para um file watcher em desenvolvimento.

`loadTranslations(dir, disablePageLocales?)` também é exportado separadamente e retorna `{ root, routes }`:

```ts
import { loadTranslations } from '@i18n-micro/node'

const { root, routes } = await loadTranslations('./locales')
// root:   { en: {...}, de: {...} }
// routes: { 'blog-post': { en: {...}, de: {...} } }
```

## Por requisição {#per-request}

Uma instância mantém um locale e uma rota. Trocar `i18n.locale` em uma instância compartilhada dentro de um handler de requisição gera condição de corrida com requisições concorrentes. `run` dá a cada requisição a sua própria:

```ts
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

// `() => next()`: `run` hands its callback the fork, and Express reads an argument of `next` as an error
app.use((req, res, next) => i18n.run(pickLocale(req), () => next()))

app.get('/', (req, res) => {
  res.send(i18n.t('greeting')) // the request's locale, in everything it awaits
})
```

Dentro de `run`, a instância compartilhada lê e define o locale e a rota da requisição (`AsyncLocalStorage`); o fork começa na rota atual, e `i18n.setRoute(...)` dentro do callback altera a rota dessa requisição. O callback também recebe o fork da requisição: dicionários escritos nele ficam na requisição, dicionários escritos na instância compartilhada chegam a todos.

Sem `AsyncLocalStorage`, `i18n.fork(locale)` retorna o mesmo tipo de instância para ser repassada.

`reload()` lê o diretório novamente; os dicionários antigos respondem até que os novos estejam carregados.

## Escolher o locale {#pick-the-locale}

`detectLocaleFromAcceptLanguage(header, locales)` respeita os pesos `q` e associa `de-DE` a um locale `de` (e `de` a `de-DE`). Retorna `null` quando nada corresponde.

```ts
import express from 'express'
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

const app = express()

app.get('/hello', (req, res) => {
  const locale = detectLocaleFromAcceptLanguage(req.headers['accept-language'], locales) ?? 'en'
  const i18n = byLocale.get(locale)!
  res.json({ message: i18n.t('greeting', { name: 'Ada' }) })
})
```

Para prefixo de URL, cookie e cabeçalho juntos, `resolveLocale({ defaultLocale, validLocales, url, cookie, acceptLanguage, autoDetectLanguage: true })` de `@i18n-micro/utils/resolve-locale` aplica a precedência do módulo: URL, depois cookie, depois `Accept-Language`, depois o padrão. Valores inválidos são ignorados.

Dentro de uma aplicação Nuxt você não precisa deste pacote no servidor: use as [traduções no lado do servidor](/pt-BR/guide/server-side-translations) do módulo.

## API {#api}

| Export | Observações |
| --- | --- |
| `createI18n(options)`, `I18n` | instância do runtime + `translationDir`, `loadTranslations(dir?)`, `reload()` |
| `loadTranslations(dir, disablePageLocales?)` | `{ root, routes }` |
| `loadRootTranslations(dir, disablePageLocales?)` | apenas `root` |
| `FormatService`, `interpolate` | do core |
| Tipos: `I18nOptions`, `LoadedTranslations`, `Translations`, `Locale`, `PluralFunc`, `Params` | |

Os métodos da instância estão listados em [Runtime](/pt-BR/integrations/runtime-package#api). Assinaturas completas: [referência do pacote](/pt-BR/api/packages/node).
