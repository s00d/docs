---

`@i18n-micro/astro` traduz páginas Astro no servidor: um middleware escolhe o locale a partir da URL e coloca uma instância por requisição em `Astro.locals`, e `useI18n(Astro)` a lê. Use-o em um site Astro que precisa de URLs com prefixo de locale (`/about`, `/fr/about`) e dicionários JSON compartilhados. Você obtém componentes `.astro`, um redirecionamento da página inicial para o idioma do visitante, tags `hreflang` e props para [islands](/pt-BR/integrations/astro-islands).

## Instalação {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/astro
```

```bash npm
npm install @i18n-micro/astro
```

```bash yarn
yarn add @i18n-micro/astro
```

</CodeGroup>

Dependências peer: `astro` `^5.0.0 || ^6.0.0 || ^7.0.0`. Opcionais, apenas para [islands](/pt-BR/integrations/astro-islands): `vue` `^3.3.0`, `react` `^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`, `preact` `^10.0.0 || ^11.0.0`, `svelte` `^4.0.0 || ^5.0.0`.

## Configuração {#setup}

Adicione a integração. Ela empacota seus dicionários no servidor e instala o middleware, então nenhum `src/middleware.ts` é necessário:

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import node from '@astrojs/node'
import { i18nIntegration } from '@i18n-micro/astro'

export default defineConfig({
  output: 'server',
  adapter: node({ mode: 'standalone' }),
  integrations: [
    i18nIntegration({
      locale: 'en',
      fallbackLocale: 'en',
      locales: [
        { code: 'en', iso: 'en-US', displayName: 'English' },
        { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
        { code: 'fr', iso: 'fr-FR', displayName: 'Français' },
      ],
      translationDir: 'src/locales',
    }),
  ],
})
```

Os dicionários se tornam código em tempo de build: o servidor não lê nada do disco, então ele também roda no edge (Cloudflare, Vercel Edge). No `astro dev`, uma edição em um arquivo é aplicada na próxima requisição.

### Opções da integração {#integration-options}

| Opção | Padrão | Observações |
| --- | --- | --- |
| `locale` | obrigatório | Locale padrão. |
| `fallbackLocale` | `locale` | |
| `locales` | `[]` | Objetos `Locale` completos. Um locale `disabled` não é o locale de nenhuma URL nem destino de redirecionamento. `iso` é a tag usada pelos plurais quando o código não é uma tag válida (`ua` → `uk-UA`). |
| `translationDir` | nenhum | Pasta empacotada no servidor, relativa à raiz do projeto. |
| `disablePageLocales` | `false` | Os arquivos de página contam como traduções raiz. |
| `autoDetect` | `true` | Redirecionamento da página inicial, veja [Detecção de locale](#locale-detection). |
| `redirectToDefault` | `false` | `/` também redireciona quando nada prefere outro locale. |
| `localeCookie` | `'i18n-locale'` | `null` desativa o cookie. |
| `missingWarn` | `false` | |
| `middleware` | `true` | `false`: escreva o middleware você mesmo, veja abaixo. |

As configurações de runtime são publicadas em `virtual:i18n-micro/config` (`config.base` é o `base` do Astro, `config.localeCodes` os códigos habilitados), e os dicionários em `virtual:i18n-micro/messages`.

### Seu próprio middleware {#your-own-middleware}

Uma regra de plural, um handler de chave ausente e um adaptador de roteador não conseguem passar do processo de configuração para o bundle do servidor. Para esses casos, passe `middleware: false` e escreva `src/middleware.ts`. A configuração `i18n` do Astro é então definida para você com `routing: 'manual'`, de modo que `Astro.currentLocale` e `astro:i18n` funcionam. O Astro não permite essa configuração sem um `src/middleware.ts`, então com o middleware próprio da integração eles não funcionam.

```ts
// src/middleware.ts
import { config } from 'virtual:i18n-micro/config'
import { messages } from 'virtual:i18n-micro/messages'
import { createAstroRouterAdapter, createI18n, createI18nMiddleware, localeIsoMap } from '@i18n-micro/astro'

const i18n = createI18n({
  locale: config.defaultLocale,
  fallbackLocale: config.fallbackLocale,
  localeIso: localeIsoMap(config.locales),
  messages: messages.root,
  routeMessages: messages.routes,
  plural: myPluralRule,
})

export const onRequest = createI18nMiddleware({
  i18n,
  defaultLocale: config.defaultLocale,
  locales: config.localeCodes,
  localeObjects: config.locales,
  autoDetect: config.autoDetect,
  redirectToDefault: config.redirectToDefault,
  localeCookie: config.localeCookie,
  base: config.base,
  routingStrategy: createAstroRouterAdapter(config.locales, config.defaultLocale),
})
```

Para ler a pasta em runtime, `loadTranslationsFromDir` e `loadTranslationsIntoI18n` estão em `@i18n-micro/astro/node` (somente Node).

### Opções do middleware {#middleware-options}

| Opção | Padrão | Observações |
| --- | --- | --- |
| `i18n` | obrigatório | Instância global; cada requisição recebe `i18n.fork(locale)`, que custa o mesmo independentemente de quantos dicionários existam. |
| `defaultLocale` | obrigatório | |
| `locales` | obrigatório | Códigos de locale. |
| `localeObjects` | `locales` como `{ code }` | Objetos `Locale` completos para componentes e SEO. |
| `autoDetect` | `true` | Redirecionamento da página inicial, veja [Detecção de locale](#locale-detection). |
| `redirectToDefault` | `false` | `/` também redireciona quando nada prefere outro locale, para a página inicial do locale padrão conforme a estratégia de roteamento a resolve. |
| `localeCookie` | `'i18n-locale'` | `null` desativa o cookie. |
| `routingStrategy` | prefixo exceto o padrão | Adaptador de roteador. Os métodos que ele omite vêm do adaptador padrão. |
| `base` | nenhum | O `base` do Astro: `config.base`. |

Os arquivos de página (`src/locales/pages/blog/post/de.json`) correspondem à rota `blog-post`: o caminho da página unido com `-`.

## Traduzir {#translate}

```astro
---
// src/pages/index.astro
import { useI18n } from '@i18n-micro/astro'
import I18nT from '@i18n-micro/astro/i18n-t'

const { t, tc, locale } = useI18n(Astro)
---

<h1>{t('greeting', { name: 'Ada' })}</h1>
<p>{tc('apples', 3)}</p>
<I18nT keypath="welcome" tag="p" />
<p>{locale}</p>
```

`useI18n(Astro)` retorna `locale`, `defaultLocale`, `locales`, `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `getRoute`, `getRouteName(path?)`, `getLocaleFromPath(path?)`, `switchLocalePath(locale)`, `localizePath(path, locale?)`, `getBasePath(url?)`, `getI18n`, `addTranslations`, `addRouteTranslations`, `mergeTranslations` e `clearCache`. Ele lança um erro quando o middleware não foi executado. Os helpers `getI18n`, `getLocale`, `getDefaultLocale` e `getLocales` leem o mesmo `Astro.locals`.

O nome da rota vem da rota sem o seu locale: `/fr/blog/post` → `blog-post`, e toda URL de `src/pages/blog/[slug].astro` → `blog-slug`, de modo que uma única pasta `locales/pages/blog-slug/` atende a todas. `[...path]` é `path`. Sob o `base` do Astro, os helpers recebem e retornam URLs do site: `switchLocalePath` e `localizePath` o incluem, `getBasePath` não, porque `Astro.rewrite` recebe o caminho sem ele.

### Componentes {#components}

Importe-os de `@i18n-micro/astro/<name>` (ou `@i18n-micro/astro/components/<name>.astro`):

| Componente | Props |
| --- | --- |
| `i18n-t` | `keypath`, `params`, `plural`, `number`, `date`, `relativeDate`, `tag` (`span`, qualquer tag), `html`, `hideIfEmpty`, `defaultValue`; outros atributos são repassados. Com `html`, o resultado de cada ramo é renderizado como HTML e os `params` são escapados. Não há slots |
| `i18n-link` | `href`, `locale` (locale de destino, padrão o atual), `class`; outros atributos são repassados. URLs externas, `#hash` e `?query` permanecem como escritos; uma rota mantém sua query, hash e barra final |
| `i18n-switcher` | `class`, `activeClass` (`'active'`), `customLabels`; renderiza links para a página atual em cada locale habilitado, com sua query |
| `i18n-group` | nenhuma que altere a saída: uma `<div>` ao redor do seu slot, sem prefixo |

## Rotas com prefixo de locale {#locale-prefixed-routes}

Mantenha uma página por rota em `src/pages/` e adicione stubs de rewrite enxutos em `src/pages/[locale]/`:

```
src/pages/
  index.astro
  about.astro
  [locale]/
    index.astro
    about.astro
```

```astro
---
// src/pages/[locale]/about.astro
import { prepareLocaleRewrite } from '@i18n-micro/astro'

const target = prepareLocaleRewrite(Astro)
if (target instanceof Response) return target
return Astro.rewrite(target)
---
```

`prepareLocaleRewrite` retorna uma resposta `404` para um `:locale` desconhecido; caso contrário, define o locale em `Astro.locals` e retorna o caminho sem o prefixo. O middleware mantém um locale que já esteja em `locals`, então a página reescrita é renderizada nele. `getLocaleRewritePath(Astro)` retorna apenas o caminho, para quando você mesmo valida o locale.

## Detecção de locale {#locale-detection}

A URL decide o locale da página:

1. Um prefixo de locale (`/fr/about` → `fr`; `/en/about` também é `en`).
2. Caso contrário, o que o `getLocaleFromPath` do adaptador de roteador retornar, se não for o padrão.
3. Caso contrário, o locale padrão. `/about` é sempre a página do locale padrão, independentemente do que o cookie diga.

`autoDetect` é uma dica de redirecionamento apenas na página inicial:

- Uma requisição para `/` cujo cookie ou `Accept-Language` prefere outro locale recebe um `302` para a página inicial desse locale (`/de`). Os pesos q são respeitados; `de-DE` corresponde a um locale `de`, e `de` corresponde a um `de-DE`.
- Com `redirectToDefault`, `/` sempre redireciona: para a página inicial do locale preferido ou, caso contrário, para a do locale padrão.
- A resposta de `/` carrega `Vary: Cookie, Accept-Language` (apenas `Accept-Language` quando `localeCookie` é `null`).
- Páginas pré-renderizadas nunca redirecionam.

`detectLocale(pathname, cookies, headers, defaultLocale, locales, localeCookie?, routingStrategy?, autoDetect?)` retorna o mesmo locale preferido para a sua própria lógica.

O cookie lembra uma escolha. Uma visualização de página que vem de uma página de mesma origem em outro locale é um visitante trocando de idioma, seja qual for o link que o levou até lá: a resposta HTML define o cookie com o novo locale, e `/` não redireciona, então um seletor alcança a página inicial do locale padrão. Um endpoint, uma imagem, um 404, um envio de formulário e um prefetch não alteram nada. "Mesma origem" é o que o navegador informa em `Sec-Fetch-Site`; sem esse cabeçalho, o host do `Referer` é comparado com o da requisição, então, atrás de um proxy, defina o `security.allowedDomains` do Astro.

Uma [server island](https://docs.astro.build/en/guides/server-islands/) ou uma action não tem locale em sua URL. Ela é renderizada para a página que a solicitou, lida a partir do `Referer`, cujo caminho é tudo o que conta, então um proxy na frente do servidor não muda nada, e ela nunca redireciona. Sua resposta carrega `Vary: Referer`. Sem um `Referer` (uma política `no-referrer`), ela fica no locale padrão, e em uma página dinâmica sua rota vem da URL, então os dicionários de página não a alcançam.

## Adaptador de roteador {#router-adapter}

`createAstroRouterAdapter(locales, defaultLocale)` adiciona prefixo a todos os locales, exceto o padrão. Um adaptador Astro precisa apenas de `getCurrentPath`; os outros membros são opcionais e recorrem ao adaptador padrão: `getRouteName(path, locales, routePattern?)`, `getLocaleFromPath`, `switchLocalePath`, `localizePath`, `removeLocaleFromPath`, `resolvePath` (destino do redirecionamento da página inicial), `push`, `replace`, `getRoute`. Escreva o seu próprio para URLs com subdomínio ou sufixo e passe-o para `createI18nMiddleware`.

## SEO {#seo}

```astro
---
// src/layouts/Layout.astro
import { useLocaleHead } from '@i18n-micro/astro'

const head = useLocaleHead(Astro, { baseUrl: 'https://example.com' })
---

<html lang={head.htmlAttrs.lang} dir={head.htmlAttrs.dir}>
  <head>
    {head.link.map((l) => <link rel={l.rel} href={l.href} hreflang={l.hreflang} />)}
    {head.meta.map((m) => <meta property={m.property} content={m.content} />)}
  </head>
  <body><slot /></body>
</html>
```

Ele retorna `htmlAttrs` (`lang` a partir de `iso`, `dir`), um link canonical (caminho sem query), alternates `hreflang` para cada locale habilitado com `seo !== false` mais `x-default`, `og:locale`, `og:locale:alternate` e `og:url`. Opções: `baseUrl` (`site` da configuração do Astro ou, caso contrário, URLs relativas à raiz), `addDirAttribute` (`true`), `addSeoAttributes` (`true`), `hreflangBaseLanguage` (`false`).
