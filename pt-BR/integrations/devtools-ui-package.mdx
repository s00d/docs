`@i18n-micro/devtools-ui` é o editor de traduções da aba do Nuxt DevTools, empacotado como um web component com um plugin Vite. Adicione-o a um projeto Vue, React, Preact, Solid ou Astro para navegar e editar os arquivos JSON da sua pasta de traduções pelo navegador durante o desenvolvimento. Aplicações Nuxt já o têm no [Nuxt DevTools](/pt-BR/guide/devtools).

![A DevTools UI: uma árvore de arquivos e um editor com o texto do locale padrão ao lado de cada chave](/images/devtools/02-translations-editor-dark.webp)

## Instalação {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/devtools-ui
```

```bash npm
npm install -D @i18n-micro/devtools-ui
```

```bash yarn
yarn add -D @i18n-micro/devtools-ui
```

</CodeGroup>

Sem peer dependencies.

## Configuração {#setup}

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import { i18nDevToolsPlugin } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  plugins: [i18nDevToolsPlugin({ translationDir: 'src/locales' })],
})
```

| Opção | Padrão | Observações |
| --- | --- | --- |
| `translationDir` | `'src/locales'` | Pasta com os arquivos JSON, relativa à raiz do Vite. |
| `base` | `'/__i18n_api'` | Caminho base dos endpoints da API. |
| `injectButton` | `true` | Adiciona um botão flutuante às páginas servidas pela transformação do `index.html` do Vite. O Astro não tem essas páginas: veja abaixo. |
| `defaultLocale` | primeiro arquivo de locale em `translationDir` | Informado por `/config`. |
| `fallbackLocale` | `defaultLocale` | Informado por `/config`. |

O plugin é executado apenas no servidor de desenvolvimento (`apply: 'serve'`); um build de produção não contém nada dele. O botão abre `/__i18n_devtools.html`, que lê e salva arquivos pelos endpoints do plugin:

| Endpoint | Faz |
| --- | --- |
| `GET <base>/translations` | todos os dicionários em `translationDir`, por caminho relativo |
| `POST <base>/save` | corpo `{ file, content }`; sobrescreve um `.json` existente dentro de `translationDir`, 403 para qualquer outra coisa. Nunca cria um arquivo |
| `GET <base>/config` | `{ defaultLocale, fallbackLocale, locales, translationDir }`; `locales` vêm dos arquivos da raiz de `translationDir` |

Os endpoints respondem apenas à página do devtools: uma requisição de outra origem ou host recebe `403`, e `/save` aceita apenas `application/json` (`415`). A página é notificada sobre mudanças nos arquivos pelo socket de HMR do Vite.

No Astro, adicione a integração em vez do plugin. Ela adiciona um app à barra de ferramentas de desenvolvimento:

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import { i18nDevToolsIntegration } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  integrations: [i18nDevToolsIntegration({ translationDir: 'src/locales' })],
})
```

Salvar apenas grava o arquivo. Uma aplicação que importa o JSON pelo Vite o recebe via HMR; para edições aplicadas diretamente à instância em execução, use uma bridge.

## Bridge para uma instância em execução {#bridge-to-a-live-instance}

Para incorporar o editor na sua própria página e ter as edições aplicadas imediatamente à instância em execução, crie uma bridge a partir de um adapter e passe-a para o elemento `<i18n-devtools-ui>`:

```ts
import { createBridge, register } from '@i18n-micro/devtools-ui'
import { i18n, locales } from './i18n' // a runtime, React, Preact or Solid instance

register() // defines <i18n-devtools-ui> once

const bridge = createBridge({
  adapter: {
    getRouteCache: () => Object.fromEntries(i18n.storage.translations),
    addTranslations: (locale, content, merge) => i18n.addTranslations(locale, content, merge),
    addRouteTranslations: (locale, route, content, merge) => i18n.addRouteTranslations(locale, route, content, merge),
    subscribe: (cb) => i18n.subscribe(cb),
    getCurrentLocale: () => i18n.locale,
  },
  locales,
  defaultLocale: 'en',
  translationDir: 'src/locales',
})

const el = document.createElement('i18n-devtools-ui') as HTMLElement & { bridge: typeof bridge }
el.bridge = bridge
document.body.append(el)
```

`getRouteCache` deve retornar os dicionários com chaves `locale:route` (`en:index`, `en:blog-post`), que é o que `i18n.storage.translations` contém. Para uma instância Vue, use `i18n.global.getRouteCache()` e `i18n.global.subscribeToChanges(cb)`.

`saveTranslation` atualiza primeiro a instância e depois faz um POST para `<base>/save`. Quando não há endpoint (um build estático de preview) ou o servidor de desenvolvimento não pode ser alcançado, a edição é mantida no `localStorage`; qualquer outro erro ao salvar restaura o dicionário anterior e lança uma exceção.

## API {#api}

| Exportação | Entrada |
| --- | --- |
| `i18nDevToolsPlugin(options)`, `i18nDevToolsIntegration(options)` | `@i18n-micro/devtools-ui/vite` |
| `register()`, `I18nDevToolsElement` | `@i18n-micro/devtools-ui` |
| `createBridge(options)`, tipos `BridgeAdapter`, `CreateBridgeOptions` | `@i18n-micro/devtools-ui` (também `/bridge/create`) |
| tipo `I18nDevToolsBridge` | `@i18n-micro/devtools-ui` (também `/bridge`) |
| `createRpcClient`, `setupRpcHost` | `@i18n-micro/devtools-ui` |
