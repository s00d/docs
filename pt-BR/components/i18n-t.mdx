title: "<i18n-t>"
description: "O componente <i18n-t> renderiza uma tradução, com formas de plural, formatação de números e datas, e interpolação de HTML e slots."
---

`<i18n-t>` renderiza uma tradução dentro de um elemento. Use-o quando uma tradução precisa de componentes dentro dela (um link em uma frase), de uma forma de plural ou de um número ou data formatados. Ele resolve a chave para a rota atual, como `$t`.

## Props {#props}

| Prop | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `keypath` **\*** | `string` | — | Chave de tradução a renderizar. |
| `plural` | `number \| string \| null` | — | Contagem que seleciona a forma de plural. Defina-a para usar `$tc` em vez de `$t`. `null` significa não definido. |
| `tag` | `string` | `'span'` | Elemento a renderizar. |
| `params` | `Record<string, string \| number \| boolean>` | — | Valores de interpolação substituídos na tradução. |
| `defaultValue` | `string` | `''` | Renderizado no lugar do componente quando `hideIfEmpty` suprime uma tradução vazia. |
| `html` | `boolean` | `false` | Renderiza a tradução como HTML em vez de texto. Apenas para traduções que você controla: `params` são escapados, a tradução não. |
| `hideIfEmpty` | `boolean` | `false` | Não renderiza nada quando a tradução resulta em uma string vazia. |
| `customPluralRule` | `PluralFunc` | `null` | Regra de plural apenas para este elemento, sobrescrevendo a configurada. Sua resposta é usada como está; `null` renderiza vazio. |
| `number` | `number \| string \| null` | — | Formata o valor com `$tn` e o passa para a tradução como `{number}`, junto com `params`. |
| `date` | `Date \| string \| number \| null` | — | Formata o valor com `$td` e o passa para a tradução como `{date}`, junto com `params`. |
| `relativeDate` | `Date \| string \| number \| null` | — | Formata o valor com `$tdr` e o passa para a tradução como `{relativeDate}`, junto com `params`. |

**\*** obrigatório.

## Regras de renderização {#rendering-rules}

O primeiro caso que corresponder decide a saída:

1. `number` — a tradução com `{ ...params, number: $tn(number) }`.
2. `date` — a tradução com `{ ...params, date: $td(date) }`.
3. `relativeDate` — a tradução com `{ ...params, relativeDate: $tdr(relativeDate) }`.
4. `plural` — a forma que `$tc` escolhe, incluindo o [marcador `=0 `](/pt-BR/api/methods#$tc), com `{ ...params, count }`; ou `customPluralRule(keypath, count, params, locale, t)` quando definida, que lê o valor bruto, marcador incluído, e cuja resposta é usada como está, sendo `null` vazio.
5. Caso contrário, a tradução com `params`.

`null` conta como não definido. Em todos os casos:

- `defaultValue` substitui uma chave ausente, em todos os ramos.
- `hideIfEmpty` renderiza `defaultValue` em vez de um resultado em branco.
- `html` renderiza o resultado como HTML. `params` são escapados, a tradução não; os slots são ignorados.
- Um slot `default` recebe `{ translation }`, e os slots nomeados são ignorados.
- Caso contrário, cada slot nomeado substitui todo placeholder `{name}`, antes de um param com esse nome. Um valor de param que parece um placeholder permanece como texto.

A saída de `date` e `relativeDate` carrega `data-allow-mismatch="text"`, porque o fuso horário e o relógio do servidor não são os do navegador. Defina [`timeZone`](/pt-BR/api/module-options#timezone) para renderizar a mesma data de calendário em ambos; `relativeDate` depende do relógio, então ainda pode diferir.

## Exemplo {#example}

```json
{
  "terms": "I accept the {link}.",
  "termsLink": "terms of use",
  "items": "no items | one item | {count} items"
}
```

```vue
<template>
  <i18n-t keypath="terms" tag="p">
    <template #link>
      <NuxtLink :to="$localePath('/terms')">{{ $t('termsLink') }}</NuxtLink>
    </template>
  </i18n-t>

  <i18n-t keypath="items" :plural="cart.length" />
</template>
```

`html` define `innerHTML`: use-o apenas para traduções que você controla. `params` são escapados, então dados do usuário são seguros ali, assim como uma chave que não encontrou tradução.
