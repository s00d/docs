# Referência de opções do módulo

Todas as opções que o `nuxt-i18n-micro` aceita, lidas em tempo de build a partir da interface `ModuleOptions` em [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts). Nada aqui é escrito à mão, portanto não pode ficar defasado em relação ao código. Tipos, valores padrão e descrições vêm da própria declaração.

Para entender o que essas opções *significam* em conjunto (quais combinações fazem sentido, o que muda quando você troca de estratégia, exemplos práticos), leia [Configuração](/guides/configuration). Esta página é a lista exaustiva; aquela é a explicação.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Opções aninhadas aparecem sob seu caminho pontuado, então `translationPayloads.mode` é a chave `mode` dentro do objeto `translationPayloads`.

## Locales e roteamento

Quais idiomas existem e como aparecem na URL.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Lista de locales suportados. Cada entrada define um código de locale mais metadados opcionais (ISO, direção, nome de exibição, etc.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Estratégia de roteamento por URL para prefixos de locale. - `'no_prefix'` sem locale na URL; locale armazenado em cookie. - `'prefix_except_default'` prefixa todos os locales exceto o padrão. - `'prefix'` sempre prefixa, incluindo o locale padrão. - `'prefix_and_default'` como `prefix`, mas o locale padrão também é acessível sem prefixo. |
| `defaultLocale` | `string` | `'en'` | O locale a ser usado quando nenhum locale puder ser determinado a partir da URL ou das preferências do usuário. Também usado como locale de fallback para traduções ausentes quando `fallbackLocale` não está definido. |
| `localeCookie` | `string \| null` | `null` | Nome do cookie para persistir a preferência de locale do usuário entre sessões. Defina como `null` para desabilitar a persistência por cookie. Definido automaticamente como `'user-locale'` para a estratégia `no_prefix` se não fornecido. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Configuração global de locale por rota. Permite restringir ou personalizar rotas de locale para páginas específicas sem modificar seus componentes. - `false` exclui a rota da localização. - `Record<LocaleCode, string>` caminhos personalizados por locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Expressão regular personalizada (ou sua string de origem) para casar códigos de locale em segmentos de URL. Todos os códigos de locale definidos em `locales` devem casar com esse padrão, ou um aviso é emitido. |
| `noPrefixRedirect` | `boolean` | `false` | Para a estratégia `no_prefix`: habilita o redirecionamento de uma URL prefixada com locale (por exemplo, `/en/about`) para a versão sem prefixo (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Padrões de URL (strings ou RegExp) a serem excluídos totalmente do processamento de i18n. Rotas correspondentes não receberão prefixos de locale, redirecionamentos ou carregamento de traduções. Paths internos do Nuxt (`/__nuxt_error`, etc.) são sempre excluídos automaticamente. |
| `routeLocales` | `Record<string, string[]>` | — | Restrições de locale por rota, extraídas de chamadas `defineI18nRoute()`. Mapeia um caminho de rota (por exemplo, `'/about'`) para um array de códigos de locale permitidos. Rotas não listadas não têm restrições (todos os locales permitidos). |

## Traduções

Onde os arquivos de tradução ficam e como as chaves são resolvidas.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Caminho para o diretório contendo os arquivos JSON de tradução, relativo à raiz do projeto. |
| `disableWatcher` | `boolean` | `false` | Desabilita o watcher de arquivos que cria automaticamente arquivos de tradução ausentes em modo de desenvolvimento. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Mapeia nomes de rota para outros nomes de rota para compartilhar os mesmos arquivos de tradução. Por exemplo, `\{ 'about-us': 'about' \}` significa que a página `about-us` usará as traduções da página `about` em vez das próprias. |
| `plural` | `PluralFunc` | `built-in pluralization (form index by count)` | Função de pluralização personalizada. Recebe `(key, count, params, locale, getter)` e deve retornar a forma plural selecionada como string, ou `null`/`undefined` para recorrer à lógica `defaultPlural` interna (para que você possa sobrescrever apenas alguns locales). Para o módulo Nuxt, a função é serializada com `.toString()` em `.nuxt/i18n.plural.mjs` e deve ser autocontida (sem imports / escopo externo). Uma string de caminho de arquivo **não** é suportada. |
| `disablePageLocales` | `boolean` | `false` | Desabilita arquivos de tradução por página. Quando `true`, apenas as traduções globais (`\{locale\}.json`) são carregadas; arquivos específicos de página (`pages/\{page\}/\{locale\}.json`) não são gerados nem carregados. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Código do locale de fallback global. Quando uma chave de tradução está ausente no locale ativo, o módulo a busca nesse locale antes de retornar a própria chave. |

## Payloads e cache

Como as traduções chegam ao navegador. [Desempenho](/guides/performance) explica o que essas opções mudam em runtime.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Pré-carrega as traduções da página inicial no middleware global do Nitro (apenas servidor, config privada). |
| `apiBaseUrl` | `string` | `'_locales'` | Segmento do caminho da URL base para a rota da API de traduções (usada em fetching de dados em SSR/SSG). Também pode ser definida via variável de ambiente `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Sobrescreve o host usado para requisições de fetch de tradução do lado do cliente. Útil quando o cliente alcança o servidor por um hostname diferente do que o Nuxt vê. Também pode ser definido via variável de ambiente `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Sobrescreve o host usado para requisições de fetch de tradução do lado do servidor. Útil em setups de container/microsserviço onde o servidor se alcança via um hostname interno. Também pode ser definido via variável de ambiente `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Controla como os payloads de tradução são emitidos (Node: `public/<apiBaseUrl>`; Edge: `serverAssets` do Nitro). - **Node**: `serverAssets` significa SSR local via `readFile` em `public/` (sem Rollup `raw:`). - **Edge**: `serverAssets` registra `serverAssets` do Nitro (`assets:i18n`); não força uma cópia pública. Mantenha os padrões para o setup all-in-one usual. Para catálogos grandes em Edge prefira `mode: 'source'`. Para deploys apoiados por CDN, desabilite as saídas locais e defina `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Estratégia de payload de tradução. - `premerged`: matriz `\{page\}/\{locale\}/data.json` em tempo de build (padrão) - `source`: arquivos-fonte compactos mesclados em runtime (prefira em Edge / catálogos grandes) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Payloads de SSR local: o Node lê `public/<apiBaseUrl>` (força cópia pública); o Edge embute via `serverAssets` do Nitro. - **Node**: sem `serverAssets` do Nitro (evita Rollup `raw:`). SSR lê `public/<apiBaseUrl\|publicDir>` como `\{page\}/\{locale\}/data.json`; quando isso é `true`, uma cópia pública é forçada mesmo se `publicAssets` for false. - **Edge** (`nitro.node === false`): `serverAssets` do Nitro (`assets:i18n`) com o mesmo layout de `mode`. **Não** força cópia pública. Defina `publicAssets: true` para CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Registra a rota de servidor integrada em `/\{apiBaseUrl\}/:page/:locale/data.json`. Desabilite quando os payloads de tradução forem servidos a partir de um host/CDN externo. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Copia payloads para a saída pública do Nitro. Premerged → `\{page\}/\{locale\}/data.json` sob `apiBaseUrl`; source → árvore compacta. No Node, essa árvore também é a origem SSR quando `serverAssets` força cópia pública. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Ativar prerender do Nitro para `/\{apiBaseUrl\}/.../data.json`. Geralmente redundante quando `publicAssets` premerged já escreveu esses arquivos. |
| `translationPayloads.publicDir` | `string` | — | Pasta de saída pública relativa à raiz pública do Nitro. Por padrão é `apiBaseUrl` (`_locales`). Assim, arquivos estáticos correspondem às URLs de fetch do cliente (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Avisa durante o build quando a contagem de arquivos de payload gerados exceder esse limite. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Avisa durante o build quando o tamanho total dos payloads gerados exceder esse limite em bytes. |

## SEO

Meta tags geradas para cada página localizada.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Gera meta tags de SEO (`hreflang`, `canonical`, `og:url`, `og:locale`) automaticamente. |
| `metaBaseUrl` | `string` | `undefined` | URL base para meta tags de SEO (canonical, og:url, hreflang). - Uma string de URL concreta (ex.: `'https://example.com'`) usada como está (prioridade mais alta). - `undefined` recorre a `site.url` do `nuxt-site-config` quando esse módulo está presente, caso contrário à origem da requisição atual (`useRequestURL().origin` no servidor, `window.location.origin` no cliente). |
| `metaTrustForwardedHost` | `boolean` | `true` | Confia no cabeçalho `X-Forwarded-Host` ao resolver a URL base para as meta tags. Habilite quando o app rodar atrás de um reverse proxy (nginx, Cloudflare, AWS ALB, etc.) que define esse cabeçalho para o hostname real voltado ao cliente. |
| `metaTrustForwardedProto` | `boolean` | `true` | Confia no cabeçalho `X-Forwarded-Proto` ao resolver o protocolo para as meta tags. Habilite quando o app rodar atrás de um proxy que faz terminação TLS para que URLs canônicas usem `https://` embora o app em si escute em HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Lista de nomes de parâmetros de query preservados nas meta tags canonical e `og:url`. Parâmetros não presentes nesta lista são removidos da URL canônica. |

## Detecção e redirecionamentos

Escolher um locale para um visitante que ainda não escolheu.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Habilita redirecionamentos automáticos baseados em locale. Quando `true`, os visitantes são redirecionados para o locale preferido deles (detectado por cookie, cabeçalho `Accept-Language` ou pelo padrão) na primeira visita. |
| `autoDetectLanguage` | `boolean` | `true` | Detecta automaticamente o idioma preferido do usuário a partir do cabeçalho HTTP `Accept-Language`. Usado em combinação com `autoDetectPath` para decidir quando a detecção ocorre. |
| `autoDetectPath` | `string` | `'/'` | Onde redirecionamentos de preferência (cookie / Accept-Language) podem ser executados (quando `redirects` estiver habilitado). - `'/'` apenas `/` (deep links no locale padrão permanecem acessíveis; padrão) - `'no_prefix'` apenas caminhos sem prefixo de locale - `'*'` todo caminho, incluindo reescrever um prefixo de locale explícito (ex.: `/fr/about` → `/de/about` quando o cookie prefere `de`) - qualquer outra string correspondência exata de caminho (ex.: `'/welcome'`) A limpeza de estratégias prefixadas (ex.: `/en` → `/` em `prefix_except_default`) não é limitada. |

## Registro

Partes do módulo que você pode desativar.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Registra o plugin do macro `defineI18nRoute()`, habilitando chamadas `defineI18nRoute()` por página. |
| `plugin` | `boolean` | `true` | Registra o plugin principal de i18n que fornece `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` e outros helpers de runtime. |
| `hooks` | `boolean` | `true` | Registra o plugin de hooks de i18n que fornece os hooks em nível de app `i18n:register` e `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`. |
| `components` | `boolean` | `true` | Registra componentes de i18n integrados (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Defina como `false` para desabilitar o registro automático de componentes (por exemplo, se você não os usa e quer reduzir a superfície do módulo). |
| `types` | `boolean` | `true` | Gera declarações de tipos TypeScript para `useI18n`, `$t` e helpers relacionados com base nas chaves de tradução dos seus arquivos de locale padrão. |
| `debug` | `boolean` | `false` | Habilita logs de debug verbosos para detecção de locale, geração de rotas e carregamento de traduções. |

## Outros

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | Também emite um `hreflang` de idioma puro derivado do `iso` de cada locale (ex.: `es-ES` → também `es`). O primeiro locale regional em `locales` reivindica a tag pura para aquele idioma. O `code` de roteamento nunca é usado. Somente `iso \|\| code`. |
| `vueDevtools` | `boolean` | `true` | Registra o inspector e a timeline do Vue DevTools em dev (extensão do navegador). Separado da aba personalizada do Nuxt DevTools. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Prefixo adicionado a nomes de rotas localizadas (ex.: `'localized-index'`). Usado internamente para distinguir rotas originais das variantes de locale geradas. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Desativação de meta tags por rota, extraída de chamadas `defineI18nRoute()`. Mapeia um caminho de rota para `true` (desabilita todas as metas) ou um array de códigos de locale para os quais as metas devem ser desabilitadas. |
| `missingWarn` | `boolean` | `true` | Mostra avisos no console quando uma chave de tradução está ausente. |
| `hmr` | `boolean` | `true` | Habilita Hot Module Replacement para arquivos de tradução em desenvolvimento. Quando `true`, mudanças em arquivos JSON de tradução disparam um recarregamento automático sem um refresh completo da página. |
| `cacheMaxSize` | `number` | `0` | Número máximo de entradas no cache em memória de traduções. `0` significa sem limite. |
| `cacheTtl` | `number` | `0` | Tempo de vida (em segundos) para as entradas de tradução em cache. `0` significa que as entradas nunca expiram. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Formatos de número nomeados por locale (compatível com Vue I18n). Habilita chamadas no estilo `$tn(1000, 'currency')`. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Formatos de data/hora nomeados por locale (compatível com `datetimeFormats` do Vue I18n). Habilita chamadas no estilo `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | `Cache-Control` HTTP `max-age` (segundos) para `/\{apiBaseUrl\}/:page/:locale/data.json`. Aplica-se por completo apenas enquanto `dateBuild` faz cache-bust na URL (`?v=...`), que é o padrão: a resposta então é `public, max-age=…, immutable` e segura para navegadores e CDNs. - `dateBuild: 0`/`''` a URL é estável, então essa duração *não* é respeitada; a resposta se torna `public, max-age=0, must-revalidate`. Um `max-age` longo em uma URL imutável fixa o primeiro payload que um navegador viu. - `0` não define `Cache-Control` (útil em depuração local) - Não aplicado em desenvolvimento (`import.meta.dev`) para que o HMR não seja atrapalhado pelo cache do navegador - Atinge apenas respostas servidas via Nitro. Payloads copiados para `public/` e servidos pela plataforma de hospedagem usam os headers dessa plataforma. Veja o guia de Desempenho. Análogo ao `httpCacheDuration` experimental do `@nuxtjs/i18n` (v10.2.0), mas como header de resposta explícito em vez do maxAge de `defineCachedEventHandler` do Nitro. |
| `dateBuild` | `string \| number` | — | Valor usado para cache-busting das requisições de tradução (`?v=...`). Quando não fornecido, o módulo recorre a `Date.now()` (não determinístico). Para deploys reproduzíveis/rolling, defina isso para um valor estável (por exemplo, um git SHA ou número de build). |
| `experimental` | `Record<string, unknown>` | — | Balde para opções experimentais/instáveis. O conteúdo pode mudar ou ser removido sem aviso entre versões minor. |
