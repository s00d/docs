Esta página lista todas as chaves do objeto `i18n` no `nuxt.config`. Use as tabelas para consultar um tipo ou um valor padrão, e os detalhes abaixo para exemplos e ressalvas. Tipos, valores padrão e descrições são gerados a partir da interface `ModuleOptions` em [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).

```ts nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
    ],
    defaultLocale: 'en',
  },
})
```

Uma opção aninhada aparece sob seu caminho com pontos: `translationPayloads.mode` é a chave `mode` de `translationPayloads`.

## Locales e roteamento {#locales-and-routing}

Quais idiomas existem e como eles aparecem na URL.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Lista de locales suportados. Cada entrada define um código de locale mais metadados opcionais (ISO, direção, nome de exibição etc.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Estratégia de roteamento de URL para prefixos de locale. - `'no_prefix'` — sem locale na URL; o locale é armazenado em cookie. - `'prefix_except_default'` — prefixa todos os locales, exceto o padrão. - `'prefix'` — sempre prefixa, inclusive o locale padrão. - `'prefix_and_default'` — como `prefix`, mas o locale padrão também fica acessível sem prefixo. |
| `defaultLocale` | `string` | `'en'` | O locale usado quando nenhum locale pode ser determinado a partir da URL ou das preferências do usuário. Não é um fallback de tradução: defina `fallbackLocale` para isso. |
| `localeCookie` | `string \| null` | `null` | Nome do cookie para persistir a preferência de locale do usuário entre sessões. Defina como `null` para desativar a persistência baseada em cookie. É definido automaticamente como `'user-locale'` para a estratégia `no_prefix` se não for informado; um `null` explícito no bloco de configuração `i18n` também o mantém desativado nesse caso. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `{}` | Configuração global de locales por rota. Permite restringir ou personalizar as rotas de locale de páginas específicas sem modificar seus componentes. - `false` — exclui a rota da localização. - `Record<LocaleCode, string>` — caminhos personalizados por locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Expressão regular personalizada (ou sua string de origem) para identificar códigos de locale nos segmentos da URL. Todo código de locale em `locales` deve corresponder ao padrão inteiro, sem suas flags, ou o build falha. |
| `noPrefixRedirect` | `boolean` | `false` | Para a estratégia `no_prefix`: quando o locale padrão tem um caminho personalizado para uma página (`localeRoutes` / `globalLocaleRoutes`), redireciona o caminho original da página para o caminho personalizado do locale do visitante, ou do locale padrão caso contrário (por exemplo, `/about` → `/about-us`). Um locale sem caminho personalizado próprio permanece no caminho original. Páginas com segmentos dinâmicos não são redirecionadas. |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Caminhos a deixar fora do roteamento i18n: uma string é um prefixo de caminho (`/admin` abrange `/admin/x`) ou um glob com `*` / `?`; uma RegExp é testada contra o caminho. As páginas correspondentes não recebem variantes de locale, nem redirecionamento de locale ou 404, e são retiradas do prerender; elas ainda renderizam com traduções. `/api`, `/_nuxt`, `/__*`, a rota de traduções e arquivos estáticos comuns (sitemap, robots.txt, favicon, assets por extensão) são sempre excluídos. |
| `routeLocales` | `Record<string, string[]>` | — | Restrições de locale por rota, extraídas em tempo de build das chamadas a `$defineI18nRoute()`. Mapeia um caminho de rota (por exemplo, `'/about'`) para um array de códigos de locale permitidos. Rotas não listadas não têm restrições (todos os locales permitidos). |

## Traduções {#translations}

Onde ficam os arquivos de tradução e como as chaves são resolvidas.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Caminho para o diretório que contém os arquivos JSON de tradução, relativo à raiz do projeto. |
| `disableWatcher` | `boolean` | `false` | Desativa o file watcher que cria automaticamente arquivos de tradução ausentes no modo de desenvolvimento. |
| `routesLocaleLinks` | `{ [key: string]: string }` | `{}` | Mapeia nomes de rotas para outros nomes de rotas para compartilhar os mesmos arquivos de tradução. Por exemplo, `{ 'about-us': 'about' }` significa que a página `about-us` usará as traduções da página `about` em vez das suas próprias. |
| `plural` | `PluralFunc` | ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)`` | Função de pluralização personalizada. Recebe `(key, count, params, locale, getter)` e deve retornar a forma plural selecionada como string, ou `null`/`undefined` para recorrer à lógica integrada `defaultPlural` (assim você pode substituir apenas alguns locales). Para o módulo Nuxt, a função é serializada com `.toString()` em `.nuxt/i18n.plural.mjs` — ela deve ser autocontida (sem imports / escopo externo). Uma string com caminho de arquivo **não** é suportada. |
| `disablePageLocales` | `boolean` | `false` | Desativa os arquivos de tradução por página. Quando `true`, apenas as traduções globais (`{locale}.json`) são carregadas; os arquivos específicos de página (`pages/{page}/{locale}.json`) não são gerados nem carregados. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Código do locale de fallback global. As chaves ausentes em um locale são obtidas deste locale (mescladas em cada payload quando ele é gerado ou carregado); sem ele, uma chave ausente é renderizada como a própria chave. |

## Payloads e cache {#payloads-and-caching}

Como as traduções chegam ao navegador. [Desempenho](/pt-BR/guide/performance) explica o que estas opções alteram em runtime.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Pré-carrega as traduções da página index no middleware global do Nitro (somente servidor, configuração privada). |
| `apiBaseUrl` | `string` | `'_locales'` | Segmento base do caminho de URL para a rota da API de traduções (usado na busca de dados em SSR/SSG). Também pode ser definido pela variável de ambiente `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Substitui o host usado nas requisições de tradução do lado do cliente. Útil quando o cliente alcança o servidor por um hostname diferente daquele que o Nuxt vê. Também pode ser definido pela variável de ambiente `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Substitui o host usado nas requisições de tradução do lado do servidor. Útil em configurações com contêineres/microsserviços nas quais o servidor alcança a si mesmo por um hostname interno. Também pode ser definido pela variável de ambiente `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Controla como os payloads de tradução são emitidos (servidor Node: `public/<apiBaseUrl>`; Edge / function / inline: `serverAssets` do Nitro). - **Servidor Node** (`node-server`, `node-cluster`, `serveStatic` em disco): `serverAssets` significa SSR local via `readFile` em `public/` (sem `raw:` do Rollup). - **Edge, presets de function e `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …): `serverAssets` registra `serverAssets` do Nitro (`assets:i18n`),   porque `public/` não está disponível em disco para o SSR. Não força uma cópia pública — defina `publicAssets: true` para CDN/estático. Mantenha os padrões para a configuração usual tudo-em-um. Para catálogos grandes no Edge, prefira `mode: 'source'`. Para deploys com CDN, desative as saídas locais e defina `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Estratégia de payload de tradução. - `premerged`: matriz `{page}/{locale}/data.json` gerada em tempo de build (padrão) - `source`: arquivos-fonte compactos mesclados em runtime (preferível no Edge / em catálogos grandes) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Payloads para SSR local: um servidor Node que serve `public/` a partir do disco lê essa árvore (força a cópia pública); Edge, presets de function e `serveStatic: "inline"` incorporam via `serverAssets` do Nitro. - **Servidor Node** (o preset serve o próprio `public/`, por exemplo `node-server`): sem `serverAssets` do Nitro (evita o `raw:` do Rollup). O SSR lê   `public/<apiBaseUrl\|publicDir>` como `{page}/{locale}/data.json`; quando isto é `true`,   uma cópia pública é forçada mesmo que `publicAssets` seja false. - **Edge, presets de function e inline** (`nitro.node === false`, sem `serveStatic` em disco, como `vercel` /   `netlify` / `aws-lambda`, ou `serveStatic: "inline"`, por exemplo winterjs): `serverAssets` do Nitro (`assets:i18n`)   com o mesmo layout de `mode`. **Não** força uma cópia pública — defina `publicAssets: true` para CDN/estático. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Registra a rota de servidor integrada em `/{apiBaseUrl}/:page/:locale/data.json`. Desative isto quando os payloads de tradução forem servidos a partir de um host/CDN externo. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Copia os payloads para a saída pública do Nitro. Premerged → `{page}/{locale}/data.json` em `apiBaseUrl`; source → árvore compacta. Quando o SSR lê `public/` (`node-server` e similares), `serverAssets: true` também força esta cópia. Em presets Edge / function / `serveStatic: "inline"`, copia apenas quando isto é `true` (o SSR usa a incorporação do Nitro). |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Ativa o prerender pelo Nitro de `/{apiBaseUrl}/.../data.json`. Geralmente redundante quando o `publicAssets` pré-mesclado já gravou esses arquivos. |
| `translationPayloads.publicDir` | `string` | — | Pasta de saída pública relativa à raiz pública do Nitro. O padrão é `apiBaseUrl` (`_locales`). Assim, os arquivos estáticos correspondem às URLs de busca do cliente (`/{apiBaseUrl}/{page}/{locale}/data.json`). |
| `translationPayloads.rootDelta` | `boolean` | `true` | Grava um arquivo raiz por locale e, em cada arquivo de página, apenas o que difere dele. O cliente e o SSR os mesclam; um chunk inteiro ainda funciona onde quer que um arquivo seja lido. `false` mantém um dicionário inteiro em cada arquivo de página. Apenas para `premerged`, e desativado com `disablePageLocales`. |
| `translationPayloads.warnFileCount` | `number` | `500` | Emite um aviso durante o build quando a quantidade de arquivos de payload gerados excede este limite. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Emite um aviso durante o build quando o tamanho total dos payloads gerados excede este limite em bytes. |

## SEO {#seo}

Meta tags geradas para cada página localizada.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Gera automaticamente meta tags de SEO (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | URL base para as meta tags de SEO (canonical, og:url, hreflang). - Uma string de URL concreta (por exemplo, `'https://example.com'`) — usada como está (maior prioridade). - `undefined` — recorre a `site.url` do `nuxt-site-config` quando esse módulo está   presente; caso contrário, à origem da requisição atual   (`useRequestURL().origin` no servidor, `window.location.origin` no cliente). |
| `metaTrustForwardedHost` | `boolean` | `true` | Confia no cabeçalho `X-Forwarded-Host` ao resolver a URL base das meta tags. Ative quando a aplicação roda atrás de um proxy reverso (nginx, Cloudflare, AWS ALB etc.) que define esse cabeçalho com o hostname real voltado ao cliente. |
| `metaTrustForwardedProto` | `boolean` | `true` | Confia no cabeçalho `X-Forwarded-Proto` ao resolver o protocolo das meta tags. Ative quando a aplicação roda atrás de um proxy que termina o TLS, para que as URLs canônicas usem `https://` mesmo que a própria aplicação escute em HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Lista de nomes de parâmetros de query preservados nas meta tags canonical e `og:url`. Parâmetros fora desta lista são removidos da URL canônica. |

## Detecção e redirecionamentos {#detection-and-redirects}

Escolha de um locale para um visitante que ainda não escolheu um.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Ativa redirecionamentos automáticos de locale (plugin de servidor e middleware de rota no cliente). Quando `true`, as estratégias com prefixo redirecionam uma URL sem prefixo para sua forma localizada. O locale vem do estado da aplicação, do cookie ou de `Accept-Language` onde `autoDetectPath` permitir; caso contrário, do padrão. Em `no_prefix`, a detecção nunca altera a URL (veja `noPrefixRedirect` para caminhos personalizados). |
| `autoDetectLanguage` | `boolean` | `true` | Detecta automaticamente o idioma preferido do usuário a partir do cabeçalho HTTP `Accept-Language`. Usado em combinação com `autoDetectPath` para decidir quando a detecção ocorre. |
| `autoDetectPath` | `string` | `'/'` | Onde os redirecionamentos por preferência de cookie / Accept-Language podem ocorrer (quando `redirects` está ativado). - `'/'` — apenas `/` (links diretos no locale padrão continuam acessíveis; padrão) - `'no_prefix'` — apenas caminhos sem prefixo de locale - `'*'` — todos os caminhos, inclusive reescrevendo um prefixo de locale explícito   (por exemplo, `/fr/about` → `/de/about` quando o cookie prefere `de`) - qualquer outra string — esse caminho, ignorando barras finais (por exemplo, `'/welcome'`) Em `prefix`, uma URL sem prefixo fora dos caminhos permitidos ainda redireciona para a forma do locale padrão (`/about` → `/en/about`). O locale padrão com prefixo em `prefix_except_default` (`/en`) é um 404, não um redirecionamento. |

| `types` | `boolean` | `true` | Gera declarações de tipos TypeScript para `useI18n`, `$t` e helpers relacionados com base nas chaves de tradução dos arquivos do seu locale padrão. |

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `trustForwardedHost` | `boolean` | `false` | Escolhe o domínio de uma requisição (`locales[].baseUrl`) a partir de `X-Forwarded-Host` em vez de `Host`. Ative apenas atrás de um proxy que sobrescreve esse cabeçalho. |

O primeiro locale regional em `locales` reivindica a tag simples desse idioma. O `code` de roteamento nunca é usado — apenas `iso \|\| code`. |
| `additionalTranslationDirs` | `string[]` | `[]` | Diretórios extras (relativos à raiz do projeto / à raiz de cada camada Nuxt) cujos arquivos `{locale}.json` de nível superior são mesclados profundamente no dicionário global antes de `translationDir`. Ordem de mesclagem: cada entrada na ordem do array (entre camadas), depois `translationDir` (prevalece em conflitos). Apenas os arquivos raiz `{locale}.json` são lidos — `pages/` nesses diretórios é ignorado. Exemplo: `translationDir: 'frontend'`, `additionalTranslationDirs: ['common']` → `common/en.json` e depois `frontend/en.json`. |
| `vueDevtools` | `boolean` | `true` | Registra o inspetor e a linha do tempo do Vue DevTools em dev (extensão do navegador). Separado da aba personalizada do Nuxt DevTools. |
| `trailingSlash` | `'append' \| 'remove'` | `undefined (inherit from Nuxt)` | Barra final para `$localePath` / `$switchLocalePath` (paridade com NuxtLink). Quando não definido, usa `experimental.defaults.nuxtLink.trailingSlash`. Defina explicitamente para substituir o padrão de links do Nuxt nos helpers de caminho do i18n. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Prefixo adicionado aos nomes de rotas localizadas (por exemplo, `'localized-index'`). Usado internamente para distinguir as rotas originais das variantes de locale geradas. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Desativação de meta tags por rota. Mapeia um nome ou caminho de rota para `true` (desativa todas as meta tags) ou para um array de códigos de locale para os quais as meta tags devem ser desativadas. As entradas encontradas em chamadas a `$defineI18nRoute()` em tempo de build são adicionadas a ele. |
| `missingWarn` | `boolean` | `true` | Mostra avisos no console quando uma chave de tradução está ausente (build de desenvolvimento, no navegador). |
| `hmr` | `boolean` | `true` | Ativa o Hot Module Replacement para arquivos de tradução em desenvolvimento. Quando `true`, alterações nos arquivos JSON de tradução disparam um recarregamento automático sem atualizar a página inteira. |
| `cacheMaxSize` | `number` | `0` | Número máximo de entradas nos caches de tradução em memória. Os caches de fetch e de servidor descartam a entrada usada menos recentemente; o mapa de dicionários do navegador descarta a mais antiga (FIFO). `0` significa sem limite no navegador; nesse caso, os caches do servidor mantêm no máximo 1000 entradas, para que URLs de requisição com páginas inventadas não possam aumentar a memória do servidor. |
| `cacheTtl` | `number` | `0` | Tempo de vida (em segundos) dos caches de tradução de fetch e de servidor, contado a partir do momento em que uma entrada foi armazenada (leituras não o estendem), para que os dados de `apiBaseServerHost` sejam atualizados pelo menos com essa frequência. Os dicionários ativos do navegador não expiram por ele. `0` significa que as entradas nunca expiram. |
| `cacheStorage` | `string` | — | Nome de uma montagem de storage do Nitro (`nitro.storage`, por exemplo `'redis'`) que várias instâncias de servidor compartilham como cache de dicionários, lido após o cache em processo e antes da fonte. Compensa principalmente com `apiBaseServerHost`: uma busca no backend em vez de uma por instância. As entradas são indexadas por build e expiram após `cacheTtl`, ou após um dia quando ele é `0`. Desativado em dev e no prerender. Um storage com falha recorre à fonte. Não definido: sem cache compartilhado. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Formatos de número nomeados por locale (compatível com Vue I18n). Permite chamadas no estilo `$tn(1000, 'currency')`. |
| `timeZone` | `string` | `the runtime's zone` | Fuso horário IANA para `$td` e `<i18n-t date>` (`Europe/Berlin`). Defina-o para renderizar a mesma data no servidor e em todos os navegadores; o `timeZone` próprio de um formato nomeado tem prioridade. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Formatos de data e hora nomeados por locale (`datetimeFormats` compatível com Vue I18n). Permite chamadas no estilo `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | max-age (em segundos) do HTTP `Cache-Control` para `/{apiBaseUrl}/:page/:locale/data.json`. Aplica-se integralmente apenas enquanto `dateBuild` invalida a URL (`?v=...`), que é o padrão: a resposta é então `private, max-age=…, immutable`: um navegador a fixa, e uma CDN que ignora a query não pode fazê-lo (`public` com `httpCacheControl: false`). - `dateBuild: 0`/`''` — a URL é estável, então esta duração *não* é respeitada; a   resposta passa a ser `public, max-age=0, must-revalidate`. Um `max-age` longo em uma   URL que não muda fixa o primeiro payload que um navegador viu. - `0` — não define `Cache-Control` (útil na depuração local) - Não é aplicado em desenvolvimento (`import.meta.dev`), para que o HMR não seja atrapalhado pelo cache do navegador - Alcança apenas respostas servidas pelo Nitro. Payloads copiados para `public/` e servidos   pela plataforma de hospedagem recebem os cabeçalhos dessa plataforma — veja o guia de Desempenho. Análogo ao `httpCacheDuration` experimental do `@nuxtjs/i18n` (v10.2.0), mas como um cabeçalho de resposta explícito em vez do maxAge de `defineCachedEventHandler` do Nitro. |
| `httpCacheControl` | `string \| false` | `'public, max-age=60'` | `Cache-Control` de um arquivo de payload respondido por um host ou por uma regra para todo o caminho, que não consegue ver `?v=`. Em um servidor Node, uma resposta ao `?v=` atual é fixada por `httpCacheDuration` e qualquer outra é revalidada; com `source`, `cacheTtl` ou `apiBaseServerHost`, onde um dicionário muda sem build, toda resposta recebe este cabeçalho. `false` mantém todos os arquivos em `max-age=0, must-revalidate`. |
| `dateBuild` | `string \| number` | — | Valor usado para cache-busting das requisições de tradução (`?v=...`). Quando não informado, o módulo usa um hash dos arquivos de tradução, então o valor muda apenas quando as traduções mudam (`Date.now()` quando nenhum hash pode ser calculado). `0` ou `''` desativa o cache-busting. Defina um valor estável (um SHA do git, um número de build) para fixá-lo você mesmo. `NUXT_I18N_DATE_BUILD` ou `runtimeConfig.public.i18nRuntime.dateBuild` o substitui em runtime, depois que um dicionário foi substituído no local: URLs fixadas ficam para trás, sem rebuild. |
| `experimental` | `Record<string, unknown>` | — | Espaço para opções experimentais/instáveis. O conteúdo pode mudar ou ser removido sem aviso entre versões minor. |

## Detalhes das opções {#option-details}

Opções sem nada a acrescentar além da tabela não são repetidas aqui.

### Locales e URLs {#locales-and-urls}

#### `locales` {#locales}

**Tipo** `Locale[]` · **Padrão** `[]`

Lista de locales suportados.
Cada entrada define um código de locale mais metadados opcionais (ISO, direção, nome de exibição etc.).

Cada entrada é um objeto `Locale`:

| Propriedade | Tipo | Descrição |
| --- | --- | --- |
| `code` | `string` | **Obrigatório.** Segmento da URL e nome do arquivo (`en`, `de-at`). |
| `iso` | `string` | Tag BCP-47 para `<html lang>`, `hreflang`, plurais e `$tn` / `$td` / `$tdr` (`en-US`). |
| `displayName` | `string` | Rótulo no `<i18n-switcher>` e em `$getLocaleName()`. |
| `dir` | `'ltr' \| 'rtl' \| 'auto'` | `<html dir>`. Sem ele, idiomas RTL conhecidos recebem `rtl` e todos os outros locales não recebem o atributo. Veja [SEO](/pt-BR/guide/seo#text-direction). |
| `disabled` | `boolean` | Excluído das rotas, dos payloads e da troca de locale. Seu prefixo é um 404, e os links para ele permanecem na página. |
| `fallbackLocale` | `string` | Fallback para este locale; substitui o `fallbackLocale` global. |
| `seo` | `boolean` | `false` deixa o locale fora de `hreflang` e `og:locale:alternate`. |
| `og` | `string` | Valor de `og:locale` (`ar_AE`); padrão: `iso` convertido. |
| `baseUrl` | `string` | O domínio próprio do locale: um único build o serve, e os links para ele a partir de outros domínios são absolutos. |
| `baseDefault` | `boolean` | Com `baseUrl`: o locale padrão do seu host, sem prefixo `/<code>` nos links para ele (`prefix` o mantém). |

Outras propriedades são mantidas e retornadas por `$getLocales()`. Tipe-as estendendo `Locale`:

```ts
// i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
  }
}
export {}
```

O módulo faz o hoist de `@i18n-micro/types`, então isso funciona com pnpm sem instalar o pacote.

#### `defaultLocale` {#defaultlocale}

**Tipo** `string` · **Padrão** `'en'`

O locale usado quando nenhum locale pode ser determinado a partir da URL ou das preferências do usuário.
Não é um fallback de tradução: defina `fallbackLocale` para isso.

#### `strategy` {#strategy}

**Tipo** `Strategies` · **Padrão** `'prefix_except_default'`

Estratégia de roteamento de URL para prefixos de locale.

- `'no_prefix'` — sem locale na URL; o locale é armazenado em cookie.
- `'prefix_except_default'` — prefixa todos os locales, exceto o padrão.
- `'prefix'` — sempre prefixa, inclusive o locale padrão.
- `'prefix_and_default'` — como `prefix`, mas o locale padrão também fica acessível sem prefixo.

URLs por estratégia e redirecionamentos: [Estratégias de roteamento](/pt-BR/guide/strategy).

#### `globalLocaleRoutes` {#globallocaleroutes}

**Tipo** `GlobalLocaleRoutes` · **Padrão** `{}`

Configuração global de locales por rota.
Permite restringir ou personalizar as rotas de locale de páginas específicas sem
modificar seus componentes.

- `false` — exclui a rota da localização.
- `Record<LocaleCode, string>` — caminhos personalizados por locale.

As chaves são nomes ou caminhos de rotas. Normalmente definido por página com [`$defineI18nRoute`](/pt-BR/guide/per-component-translations).

```ts
globalLocaleRoutes: {
  about: { en: '/about-us', de: '/ueber-uns' },
  'admin-dashboard': false, // not localized
}
```

Detalhes, segmentos dinâmicos e rotas de `pages:extend`: [Caminhos localizados](/pt-BR/guide/custom-locale-routes).

#### `routeLocales` {#routelocales}

**Tipo** `Record<string, string[]>` · **Padrão** —

Restrições de locale por rota, extraídas em tempo de build das chamadas a `$defineI18nRoute()`.
Mapeia um caminho de rota (por exemplo, `'/about'`) para um array de códigos de locale permitidos.
Rotas não listadas não têm restrições (todos os locales permitidos).

#### `routeDisableMeta` {#routedisablemeta}

**Tipo** `Record<string, boolean \| string[]>` · **Padrão** —

Desativação de meta tags por rota. Mapeia um nome ou caminho de rota para `true` (desativa todas as meta tags) ou para um array
de códigos de locale para os quais as meta tags devem ser desativadas. As entradas encontradas em chamadas a `$defineI18nRoute()`
em tempo de build são adicionadas a ele.

#### `customRegexMatcher` {#customregexmatcher}

**Tipo** `string \| RegExp` · **Padrão** `undefined (uses built-in pattern based on locale codes)`

Expressão regular personalizada (ou sua string de origem) para identificar códigos de locale nos segmentos da URL.
Todo código de locale em `locales` deve corresponder ao padrão inteiro, sem suas flags, ou o build falha.

```ts
customRegexMatcher: '[a-z]{2}-[a-z]{2}', // en-us, de-at
```

#### `excludePatterns` {#excludepatterns}

**Tipo** `(string \| RegExp)[]` · **Padrão** `undefined`

Caminhos a deixar fora do roteamento i18n: uma string é um prefixo de caminho (`/admin` abrange `/admin/x`)
ou um glob com `*` / `?`; uma RegExp é testada contra o caminho. As páginas correspondentes não recebem variantes
de locale, nem redirecionamento de locale ou 404, e são retiradas do prerender; elas ainda renderizam com
traduções. `/api`, `/_nuxt`, `/__*`, a rota de traduções e arquivos estáticos comuns
(sitemap, robots.txt, favicon, assets por extensão) são sempre excluídos.

```ts
excludePatterns: ['/admin', '/docs/*', /^\/preview\//],
```

Mais: [Excluindo caminhos](/pt-BR/guide/excluding-static-files).

#### `localizedRouteNamePrefix` {#localizedroutenameprefix}

**Tipo** `string` · **Padrão** `'localized-'`

Prefixo adicionado aos nomes de rotas localizadas (por exemplo, `'localized-index'`).
Usado internamente para distinguir as rotas originais das variantes de locale geradas.

#### `trailingSlash` {#trailingslash}

**Tipo** `'append' \| 'remove'` · **Padrão** `undefined (inherit from Nuxt)`

Barra final para `$localePath` / `$switchLocalePath` (paridade com NuxtLink).
Quando não definido, usa `experimental.defaults.nuxtLink.trailingSlash`.
Defina explicitamente para substituir o padrão de links do Nuxt nos helpers de caminho do i18n.

### Traduções {#translations}

#### `translationDir` {#translationdir}

**Tipo** `string` · **Padrão** `'locales'`

Caminho para o diretório que contém os arquivos JSON de tradução, relativo à raiz do projeto.

Relativo à raiz de cada camada, não a `app/` (`'app/locales'` para um layout do Nuxt 4). Estrutura dos arquivos: [Arquivos de tradução](/pt-BR/guide/translations).

#### `additionalTranslationDirs` {#additionaltranslationdirs}

**Tipo** `string[]` · **Padrão** `[]`

Diretórios extras (relativos à raiz do projeto / à raiz de cada camada Nuxt) cujos arquivos
`{locale}.json` de nível superior são mesclados profundamente no dicionário global antes de `translationDir`.

Ordem de mesclagem: cada entrada na ordem do array (entre camadas), depois `translationDir` (prevalece em conflitos).
Apenas os arquivos raiz `{locale}.json` são lidos — `pages/` nesses diretórios é ignorado.

Exemplo: `translationDir: 'frontend'`, `additionalTranslationDirs: ['common']` → `common/en.json` e depois `frontend/en.json`.

#### `disablePageLocales` {#disablepagelocales}

**Tipo** `boolean` · **Padrão** `false`

Desativa os arquivos de tradução por página.
Quando `true`, apenas as traduções globais (`{locale}.json`) são carregadas;
os arquivos específicos de página (`pages/{page}/{locale}.json`) não são gerados nem carregados.

#### `fallbackLocale` {#fallbacklocale}

**Tipo** `string` · **Padrão** `undefined (no fallback; returns the raw key)`

Código do locale de fallback global.
As chaves ausentes em um locale são obtidas deste locale (mescladas em cada payload quando ele é
gerado ou carregado); sem ele, uma chave ausente é renderizada como a própria chave.

#### `routesLocaleLinks` {#routeslocalelinks}

**Tipo** `{ [key: string]: string }` · **Padrão** `{}`

Mapeia nomes de rotas para outros nomes de rotas para compartilhar os mesmos arquivos de tradução.
Por exemplo, `{ 'about-us': 'about' }` significa que a página `about-us` usará
as traduções da página `about` em vez das suas próprias.

```ts
routesLocaleLinks: { 'products-id': 'products' },
```

#### `plural` {#plural}

**Tipo** `PluralFunc` · **Padrão** ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)``

Função de pluralização personalizada.
Recebe `(key, count, params, locale, getter)` e deve retornar a forma
plural selecionada como string, ou `null`/`undefined` para recorrer à lógica
integrada `defaultPlural` (assim você pode substituir apenas alguns locales).

Para o módulo Nuxt, a função é serializada com `.toString()` em
`.nuxt/i18n.plural.mjs` — ela deve ser autocontida (sem imports / escopo externo).
Uma string com caminho de arquivo **não** é suportada.

A regra integrada e seu marcador `=0 ` estão descritos em [`$tc`](/pt-BR/api/methods#$tc). Sua função a substitui naquilo que responder, recebe o valor bruto com qualquer marcador no lugar, e `null` devolve a chamada para ela. A função recebe `(key, count, params, locale, getter)`; `getter(key)` retorna a string bruta com todas as formas. Escreva-a como uma expressão `function` ou arrow autocontida (sem a forma abreviada de método, sem imports, sem variáveis externas):

```ts
plural: function (key, count, params, locale, getter) {
  if (!locale.startsWith('en')) return null // built-in rule for other locales
  const forms = String(getter(key) ?? '').split('|').map((form) => form.trim())
  const index = count === 0 ? 0 : count === 1 ? 1 : 2
  return (forms[Math.min(index, forms.length - 1)] ?? '').replace('{count}', String(count))
},
```

```json
{ "apples": "no apples | one apple | {count} apples" }
```

#### `numberFormats` {#numberformats}

**Tipo** `Record<string, Record<string, Intl.NumberFormatOptions>>` · **Padrão** —

Formatos de número nomeados por locale (compatível com Vue I18n).
Permite chamadas no estilo `$tn(1000, 'currency')`.

Usado por [`$tn`](/pt-BR/api/methods#$tn).

#### `datetimeFormats` {#datetimeformats}

**Tipo** `Record<string, Record<string, Intl.DateTimeFormatOptions>>` · **Padrão** —

Formatos de data e hora nomeados por locale (`datetimeFormats` compatível com Vue I18n).
Permite chamadas no estilo `$td(date, 'short')`.

Usado por [`$td`](/pt-BR/api/methods#$td).

#### `timeZone` {#timezone}

**Tipo** `string` · **Padrão** `the runtime's zone`

Fuso horário IANA para `$td` e `<i18n-t date>` (`Europe/Berlin`). Defina-o para renderizar a mesma data no
servidor e em todos os navegadores; o `timeZone` próprio de um formato nomeado tem prioridade.

#### `disableWatcher` {#disablewatcher}

**Tipo** `boolean` · **Padrão** `false`

Desativa o file watcher que cria automaticamente arquivos de tradução ausentes no modo de desenvolvimento.

#### `missingWarn` {#missingwarn}

**Tipo** `boolean` · **Padrão** `true`

Para reportar chaves ausentes em vez disso, use [`$setMissingHandler`](/pt-BR/api/methods#$setmissinghandler).

### Payloads e cache {#payloads-and-caching}

#### `translationPayloads` {#translationpayloads}

**Tipo** `TranslationPayloadOptions` · **Padrão** —

Controla como os payloads de tradução são emitidos (servidor Node: `public/<apiBaseUrl>`; Edge / function / inline: `serverAssets` do Nitro).

- **Servidor Node** (`node-server`, `node-cluster`, `serveStatic` em disco): `serverAssets` significa SSR local via `readFile` em `public/` (sem `raw:` do Rollup).
- **Edge, presets de function e `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …): `serverAssets` registra `serverAssets` do Nitro (`assets:i18n`),
  porque `public/` não está disponível em disco para o SSR. Não força uma cópia pública — defina `publicAssets: true` para CDN/estático.

Mantenha os padrões para a configuração usual tudo-em-um. Para catálogos grandes no Edge, prefira `mode: 'source'`.
Para deploys com CDN, desative as saídas locais e defina `apiBaseClientHost` / `apiBaseServerHost`.

As subopções estão na tabela [Payloads e cache](#payloads-and-caching). Qual combinação se adequa a Node, serverless, Edge, hospedagem estática ou CDN: [Deploy](/pt-BR/guide/deployment).

#### `apiBaseUrl` {#apibaseurl}

**Tipo** `string` · **Padrão** `'_locales'`

Segmento base do caminho de URL para a rota da API de traduções (usado na busca de dados em SSR/SSG).
Também pode ser definido pela variável de ambiente `NUXT_I18N_APP_BASE_URL`.

As URLs dos payloads são `/{apiBaseUrl}/{page}/{locale}/data.json`.

#### `apiBaseClientHost` {#apibaseclienthost}

**Tipo** `string` · **Padrão** `undefined`

Substitui o host usado nas requisições de tradução do lado do cliente.
Útil quando o cliente alcança o servidor por um hostname diferente daquele que o Nuxt vê.
Também pode ser definido pela variável de ambiente `NUXT_I18N_APP_BASE_CLIENT_HOST`.

#### `apiBaseServerHost` {#apibaseserverhost}

**Tipo** `string` · **Padrão** `undefined`

Substitui o host usado nas requisições de tradução do lado do servidor.
Útil em configurações com contêineres/microsserviços nas quais o servidor alcança a si mesmo por um hostname interno.
Também pode ser definido pela variável de ambiente `NUXT_I18N_APP_BASE_SERVER_HOST`.

Um host deve servir as mesmas respostas `/{apiBaseUrl}/{page}/{locale}/data.json` que a rota integrada.

#### `dateBuild` {#datebuild}

**Tipo** `string \| number` · **Padrão** —

Valor usado para cache-busting das requisições de tradução (`?v=...`).

Quando não informado, o módulo usa um hash dos arquivos de tradução, então o valor muda
apenas quando as traduções mudam (`Date.now()` quando nenhum hash pode ser calculado). `0` ou `''` desativa
o cache-busting. Defina um valor estável (um SHA do git, um número de build) para fixá-lo você mesmo.
`NUXT_I18N_DATE_BUILD` ou `runtimeConfig.public.i18nRuntime.dateBuild` o substitui em runtime, depois que um dicionário
foi substituído no local: URLs fixadas ficam para trás, sem rebuild.

#### `httpCacheDuration` {#httpcacheduration}

**Tipo** `number` · **Padrão** `31536000`

max-age (em segundos) do HTTP `Cache-Control` para `/{apiBaseUrl}/:page/:locale/data.json`.

Aplica-se integralmente apenas enquanto `dateBuild` invalida a URL (`?v=...`), que é o padrão:
a resposta é então `private, max-age=…, immutable`: um navegador a fixa, e uma CDN que ignora a query não pode fazê-lo
(`public` com `httpCacheControl: false`).

- `dateBuild: 0`/`''` — a URL é estável, então esta duração *não* é respeitada; a
  resposta passa a ser `public, max-age=0, must-revalidate`. Um `max-age` longo em uma
  URL que não muda fixa o primeiro payload que um navegador viu.

- `0` — não define `Cache-Control` (útil na depuração local)
- Não é aplicado em desenvolvimento (`import.meta.dev`), para que o HMR não seja atrapalhado pelo cache do navegador
- Alcança apenas respostas servidas pelo Nitro. Payloads copiados para `public/` e servidos
  pela plataforma de hospedagem recebem os cabeçalhos dessa plataforma — veja o guia de Desempenho.

Análogo ao `httpCacheDuration` experimental do `@nuxtjs/i18n` (v10.2.0), mas como um
cabeçalho de resposta explícito em vez do maxAge de `defineCachedEventHandler` do Nitro.

#### `cacheMaxSize` {#cachemaxsize}

**Tipo** `number` · **Padrão** `0`

Número máximo de entradas nos caches de tradução em memória. Os caches de fetch e de servidor
descartam a entrada usada menos recentemente; o mapa de dicionários do navegador descarta a mais antiga (FIFO).
`0` significa sem limite no navegador; nesse caso, os caches do servidor mantêm no máximo 1000 entradas, para que URLs
de requisição com páginas inventadas não possam aumentar a memória do servidor.

#### `cacheTtl` {#cachettl}

**Tipo** `number` · **Padrão** `0`

Tempo de vida (em segundos) dos caches de tradução de fetch e de servidor, contado a partir do momento em que uma
entrada foi armazenada (leituras não o estendem), para que os dados de `apiBaseServerHost` sejam atualizados pelo
menos com essa frequência. Os dicionários ativos do navegador não expiram por ele. `0` significa que as entradas
nunca expiram.

O que ambos alteram em runtime: [Desempenho](/pt-BR/guide/performance).

#### `serverTranslationPreload` {#servertranslationpreload}

**Tipo** `boolean` · **Padrão** `false`

Pré-carrega as traduções da página index no middleware global do Nitro (somente servidor, configuração privada).

### SEO {#seo}

#### `meta` {#meta}

**Tipo** `boolean` · **Padrão** `true`

Gera automaticamente meta tags de SEO (`hreflang`, `canonical`, `og:url`, `og:locale`).

Substituições por página: [`useI18nHead`](/pt-BR/composables/useI18nHead). Todo o resto: [SEO](/pt-BR/guide/seo).

#### `metaBaseUrl` {#metabaseurl}

**Tipo** `string` · **Padrão** `undefined`

URL base para as meta tags de SEO (canonical, og:url, hreflang).

- Uma string de URL concreta (por exemplo, `'https://example.com'`) — usada como está (maior prioridade).
- `undefined` — recorre a `site.url` do `nuxt-site-config` quando esse módulo está
  presente; caso contrário, à origem da requisição atual
  (`useRequestURL().origin` no servidor, `window.location.origin` no cliente).

#### `metaTrustForwardedHost` {#metatrustforwardedhost}

**Tipo** `boolean` · **Padrão** `true`

Confia no cabeçalho `X-Forwarded-Host` ao resolver a URL base das meta tags.
Ative quando a aplicação roda atrás de um proxy reverso (nginx, Cloudflare, AWS ALB etc.)
que define esse cabeçalho com o hostname real voltado ao cliente.

Lido apenas quando nem `metaBaseUrl` nem `site.url` estão definidos. Defina-o como `false` quando a aplicação for acessível sem um proxy que sobrescreva o cabeçalho: caso contrário, um cliente poderia escolher o host nas suas URLs canônicas.

#### `metaTrustForwardedProto` {#metatrustforwardedproto}

**Tipo** `boolean` · **Padrão** `true`

Confia no cabeçalho `X-Forwarded-Proto` ao resolver o protocolo das meta tags.
Ative quando a aplicação roda atrás de um proxy que termina o TLS, para que
as URLs canônicas usem `https://` mesmo que a própria aplicação escute em HTTP.

Mesmo escopo de `metaTrustForwardedHost`.

#### `trustForwardedHost` {#trustforwardedhost}

**Tipo** `boolean` · **Padrão** `false`

Escolhe o domínio de uma requisição (`locales[].baseUrl`) a partir de `X-Forwarded-Host` em vez de
`Host`. Ative apenas atrás de um proxy que sobrescreve esse cabeçalho.

Separado de `metaTrustForwardedHost` e desativado por padrão: aqui o cabeçalho selecionaria os locales de outro domínio, não apenas a origem de uma tag. Veja [Camadas e domínios](/pt-BR/guide/layers#multiple-domains).

#### `hreflangBaseLanguage` {#hreflangbaselanguage}

**Tipo** `boolean` · **Padrão** `false`

Também emite um `hreflang` só com o idioma, derivado do `iso` de cada locale
(por exemplo, `es-ES` → também `es`). O primeiro locale regional em `locales` reivindica
a tag simples desse idioma. O `code` de roteamento nunca é usado — apenas `iso || code`.

#### `canonicalQueryWhitelist` {#canonicalquerywhitelist}

**Tipo** `string[]` · **Padrão** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

Lista de nomes de parâmetros de query preservados nas meta tags canonical e `og:url`.
Parâmetros fora desta lista são removidos da URL canônica.

### Detecção e redirecionamentos {#detection-and-redirects}

As regras que estas opções alimentam: [Detecção de locale](/pt-BR/guide/locale-detection).

#### `redirects` {#redirects}

**Tipo** `boolean` · **Padrão** `true`

Ativa redirecionamentos automáticos de locale (plugin de servidor e middleware de rota no cliente).
Quando `true`, as estratégias com prefixo redirecionam uma URL sem prefixo para sua forma localizada. O locale
vem do estado da aplicação, do cookie ou de `Accept-Language` onde `autoDetectPath` permitir; caso contrário,
do padrão. Em `no_prefix`, a detecção nunca altera a URL (veja `noPrefixRedirect` para caminhos personalizados).

Com `false`, o middleware de redirecionamento do cliente não é registrado. O plugin de servidor ainda retorna 404 para URLs com locale inválido e grava o cookie para uma URL com prefixo.

#### `autoDetectLanguage` {#autodetectlanguage}

**Tipo** `boolean` · **Padrão** `true`

Detecta automaticamente o idioma preferido do usuário a partir do cabeçalho HTTP `Accept-Language`.
Usado em combinação com `autoDetectPath` para decidir quando a detecção ocorre.

#### `autoDetectPath` {#autodetectpath}

**Tipo** `string` · **Padrão** `'/'`

Onde os redirecionamentos por preferência de cookie / Accept-Language podem ocorrer (quando `redirects` está ativado).

- `'/'` — apenas `/` (links diretos no locale padrão continuam acessíveis; padrão)
- `'no_prefix'` — apenas caminhos sem prefixo de locale
- `'*'` — todos os caminhos, inclusive reescrevendo um prefixo de locale explícito
  (por exemplo, `/fr/about` → `/de/about` quando o cookie prefere `de`)

- qualquer outra string — esse caminho, ignorando barras finais (por exemplo, `'/welcome'`)

Em `prefix`, uma URL sem prefixo fora dos caminhos permitidos ainda redireciona para a forma do locale
padrão (`/about` → `/en/about`). O locale padrão com prefixo em
`prefix_except_default` (`/en`) é um 404, não um redirecionamento.

#### `localeCookie` {#localecookie}

**Tipo** `string \| null` · **Padrão** `null`

Nome do cookie para persistir a preferência de locale do usuário entre sessões.
Defina como `null` para desativar a persistência baseada em cookie.
É definido automaticamente como `'user-locale'` para a estratégia `no_prefix` se não for informado; um
`null` explícito no bloco de configuração `i18n` também o mantém desativado nesse caso.

Sem cookie, `Accept-Language` ainda conduz os redirecionamentos; o cookie lembra uma escolha entre visitas.

#### `noPrefixRedirect` {#noprefixredirect}

**Tipo** `boolean` · **Padrão** `false`

Para a estratégia `no_prefix`: quando o locale padrão tem um caminho personalizado para uma página
(`localeRoutes` / `globalLocaleRoutes`), redireciona o caminho original da página para o caminho
personalizado do locale do visitante, ou do locale padrão caso contrário (por exemplo, `/about` → `/about-us`).
Um locale sem caminho personalizado próprio permanece no caminho original. Páginas com segmentos
dinâmicos não são redirecionadas.

Ativa logs de depuração detalhados para detecção de locale, geração de rotas e carregamento de traduções.

#### `vueDevtools` {#vuedevtools}

**Tipo** `boolean` · **Padrão** `true`

Registra o inspetor e a linha do tempo do Vue DevTools em dev (extensão do navegador).
Separado da aba personalizada do Nuxt DevTools.

#### `experimental` {#experimental}

**Tipo** `Record<string, unknown>` · **Padrão** —

Espaço para opções experimentais/instáveis.
O conteúdo pode mudar ou ser removido sem aviso entre versões minor.
