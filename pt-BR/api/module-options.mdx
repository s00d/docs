# Referência das opções do módulo

Todas as opções aceitas por `nuxt-i18n-micro`, lidas em tempo de build da interface `ModuleOptions` em
[`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).
Nada aqui é escrito manualmente, então não pode ficar defasado em relação ao código — tipos, padrões e descrições vêm da própria declaração.

Para entender o *significado* dessas opções em conjunto — quais combinações fazem sentido, o que muda quando você troca de strategy, exemplos práticos — leia [Configuração](/guides/configuration). Esta página é a lista exaustiva; a outra é a explicação.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Opções aninhadas aparecem sob seu caminho pontuado, então `translationPayloads.mode` é a chave `mode` dentro do objeto `translationPayloads`.

## Locales e roteamento

Quais idiomas existem e como aparecem na URL.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Lista dos locales suportados. Cada entrada define um código de locale e metadados opcionais (ISO, direção, nome de exibição, etc.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Estratégia de roteamento de URL para prefixos de locale. - `'no_prefix'` — sem locale na URL; locale armazenado em cookie. - `'prefix_except_default'` — prefixa todos os locales exceto o padrão. - `'prefix'` — sempre prefixa, incluindo o locale padrão. - `'prefix_and_default'` — como `prefix`, mas o locale padrão também está acessível sem prefixo. |
| `defaultLocale` | `string` | `'en'` | O locale a ser usado quando nenhum locale puder ser determinado pela URL ou pelas preferências do usuário. Também usado como locale de fallback para traduções ausentes quando `fallbackLocale` não estiver definido. |
| `localeCookie` | `string \| null` | `null` | Nome do cookie para persistir a preferência de locale do usuário entre sessões. Defina como `null` para desabilitar a persistência por cookie. Automaticamente definido como `'user-locale'` para a estratégia `no_prefix` se não fornecido. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Configuração global de locale no nível de rota. Permite restringir ou personalizar rotas de locale para páginas específicas sem modificar seus componentes. - `false` — exclui a rota da localização. - `Record<LocaleCode, string>` — caminhos personalizados por locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Expressão regular personalizada (ou sua string) para casar códigos de locale em segmentos de URL. Todos os códigos de locale definidos em `locales` devem casar com esse padrão, senão um aviso é emitido. |
| `noPrefixRedirect` | `boolean` | `false` | Para a estratégia `no_prefix`: habilita redirecionamento de uma URL com prefixo de locale (ex.: `/en/about`) para a versão sem prefixo (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Padrões de URL (strings ou RegExp) a excluir totalmente do processamento de i18n. Rotas correspondentes não recebem prefixos de locale, redirecionamentos ou carregamento de tradução. Caminhos internos do Nuxt (`/__nuxt_error`, etc.) são sempre excluídos automaticamente. |
| `routeLocales` | `Record<string, string[]>` | — | Restrições de locale por rota, extraídas das chamadas a `defineI18nRoute()`. Mapeia um caminho de rota (ex.: `'/about'`) para um array de códigos de locale permitidos. Rotas não listadas não têm restrições (todos os locales permitidos). |

## Traduções

Onde ficam os arquivos de tradução e como as chaves são resolvidas.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Caminho para o diretório contendo os arquivos JSON de tradução, relativo à raiz do projeto. |
| `disableWatcher` | `boolean` | `false` | Desabilita o watcher de arquivos que cria automaticamente arquivos de tradução ausentes em modo de desenvolvimento. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Mapeia nomes de rota para outros nomes de rota para compartilhar os mesmos arquivos de tradução. Por exemplo, `\{ 'about-us': 'about' \}` significa que a página `about-us` usará as traduções da página `about` em vez das próprias. |
| `plural` | `PluralFunc` | `built-in pluralization (form index by count)` | Função de pluralização personalizada. Recebe `(key, count, params, locale, getter)` e deve retornar a forma plural selecionada como string, ou `null`/`undefined` para cair no fallback da lógica `defaultPlural` embutida (permitindo sobrescrever apenas alguns locales). Para o módulo Nuxt, a função é serializada com `.toString()` para `.nuxt/i18n.plural.mjs` — ela deve ser autocontida (sem imports / escopo externo). Uma string com caminho de arquivo **não** é suportada. |
| `disablePageLocales` | `boolean` | `false` | Desabilita arquivos de tradução por página. Quando `true`, apenas traduções globais (`\{locale\}.json`) são carregadas; arquivos específicos de página (`pages/\{page\}/\{locale\}.json`) não são gerados nem carregados. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Código do locale de fallback global. Quando uma chave de tradução está ausente no locale ativo, o módulo tenta encontrá-la neste locale antes de retornar a própria chave. |

## Payloads e cache

Como as traduções chegam ao navegador. [Performance](/guides/performance) explica o que essas opções mudam em runtime.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Pré-carrega traduções da página inicial no middleware global do Nitro (apenas servidor, config privada). |
| `apiBaseUrl` | `string` | `'_locales'` | Segmento de URL base para a rota de API de traduções (usado em fetch de dados via SSR/SSG). Também pode ser definido via variável de ambiente `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Sobrescreve o host usado para requisições de fetch de tradução no lado do cliente. Útil quando o cliente alcança o servidor por um hostname diferente daquele que o Nuxt enxerga. Também pode ser definido via variável de ambiente `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Sobrescreve o host usado para requisições de fetch de tradução no lado do servidor. Útil em setups com contêineres/microsserviços em que o servidor se alcança por um hostname interno. Também pode ser definido via variável de ambiente `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Controla como os payloads de tradução são emitidos (Node: `public/<apiBaseUrl>`; Edge: `serverAssets` do Nitro). - **Node**: `serverAssets` significa SSR local via `readFile` sob `public/` (sem `raw:` do Rollup). - **Edge**: `serverAssets` registra `serverAssets` do Nitro (`assets:i18n`); não força uma cópia pública. Mantenha os padrões para o setup all-in-one usual. Para catálogos Edge grandes, prefira `mode: 'source'`. Para deploys com CDN, desabilite saídas locais e defina `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Estratégia de payload de tradução. - `premerged`: matriz `\{page\}/\{locale\}/data.json` em tempo de build (padrão) - `source`: arquivos fonte compactos mesclados em runtime (prefira em Edge / catálogos grandes) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Payloads locais de SSR: Node lê `public/<apiBaseUrl>` (força cópia pública); Edge embute via `serverAssets` do Nitro. - **Node**: sem `serverAssets` do Nitro (evita `raw:` do Rollup). SSR lê `public/<apiBaseUrl\|publicDir>` como `\{page\}/\{locale\}/data.json`; quando `true`, uma cópia pública é forçada mesmo que `publicAssets` seja false. - **Edge** (`nitro.node === false`): `serverAssets` do Nitro (`assets:i18n`) com o mesmo layout do `mode`. **Não** força cópia pública — defina `publicAssets: true` para CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Registra a rota de servidor embutida em `/\{apiBaseUrl\}/:page/:locale/data.json`. Desabilite quando os payloads de tradução forem servidos por um host/CDN externo. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Copia payloads para a saída pública do Nitro. Premerged → `\{page\}/\{locale\}/data.json` sob `apiBaseUrl`; source → árvore compacta. No Node essa árvore também é a fonte para SSR quando `serverAssets` força uma cópia pública. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Opta por pré-renderizar via Nitro `/\{apiBaseUrl\}/.../data.json`. Geralmente redundante quando `publicAssets` no modo premerged já escreveu esses arquivos. |
| `translationPayloads.publicDir` | `string` | — | Pasta de saída pública relativa à raiz pública do Nitro. Assume `apiBaseUrl` como padrão (`_locales`). Assim os arquivos estáticos casam com as URLs de fetch do cliente (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Avisa durante o build quando a contagem de arquivos de payload gerados excede esse limite. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Avisa durante o build quando o tamanho total dos payloads gerados excede esse limite em bytes. |

## SEO

Meta tags geradas para cada página localizada.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Gera meta tags de SEO (`hreflang`, `canonical`, `og:url`, `og:locale`) automaticamente. |
| `metaBaseUrl` | `string` | `undefined` | URL base para meta tags de SEO (canonical, og:url, hreflang). - Uma string de URL concreta (ex.: `'https://example.com'`) — usada como está (maior prioridade). - `undefined` — cai no fallback para `site.url` do `nuxt-site-config` quando esse módulo está presente, senão a origem da requisição atual (`useRequestURL().origin` no servidor, `window.location.origin` no cliente). |
| `metaTrustForwardedHost` | `boolean` | `true` | Confia no header `X-Forwarded-Host` ao resolver a URL base para meta tags. Habilite quando a aplicação rodar atrás de um proxy reverso (nginx, Cloudflare, AWS ALB, etc.) que define esse header com o hostname real voltado ao cliente. |
| `metaTrustForwardedProto` | `boolean` | `true` | Confia no header `X-Forwarded-Proto` ao resolver o protocolo para meta tags. Habilite quando a aplicação rodar atrás de um proxy que termina TLS, de modo que URLs canônicas usem `https://` mesmo que o app escute em HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Lista de nomes de parâmetros de query preservados nas meta tags canonical e `og:url`. Parâmetros fora dessa lista são removidos da URL canônica. |

## Detecção e redirecionamentos

Escolhendo um locale para um visitante que ainda não escolheu.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Habilita redirecionamentos automáticos baseados em locale. Quando `true`, visitantes são redirecionados ao locale preferido (detectado por cookie, header `Accept-Language` ou o padrão) na primeira visita. |
| `autoDetectLanguage` | `boolean` | `true` | Detecta automaticamente o idioma preferido do usuário pelo header HTTP `Accept-Language`. Usado em combinação com `autoDetectPath` para decidir quando a detecção ocorre. |
| `autoDetectPath` | `string` | `'/'` | Onde redirecionamentos baseados em cookie / Accept-Language podem executar (quando `redirects` está habilitado). - `'/'` — apenas `/` (deep links no locale padrão continuam alcançáveis; padrão) - `'no_prefix'` — apenas caminhos sem prefixo de locale - `'*'` — todo caminho, incluindo reescrever um prefixo de locale explícito (ex.: `/fr/about` → `/de/about` quando o cookie prefere `de`) - qualquer outra string — casamento exato de caminho (ex.: `'/welcome'`) Limpezas de estratégias com prefixo (ex.: `/en` → `/` sob `prefix_except_default`) não são condicionadas. |

## Registro

Partes do módulo que você pode desligar.

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Registra o plugin do macro `defineI18nRoute()`, habilitando chamadas `defineI18nRoute()` por página. |
| `plugin` | `boolean` | `true` | Registra o plugin de i18n principal que fornece `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` e outros helpers de runtime. |
| `hooks` | `boolean` | `true` | Registra o plugin de hooks de i18n que fornece `i18n:register` e os hooks de aplicação `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`. |
| `components` | `boolean` | `true` | Registra os componentes de i18n embutidos (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Defina como `false` para desabilitar o registro automático de componentes (ex.: se você não os usa e quer reduzir o footprint do módulo). |
| `types` | `boolean` | `true` | Gera declarações de tipos TypeScript para `useI18n`, `$t` e helpers relacionados com base nas chaves de tradução dos seus arquivos de locale padrão. |
| `debug` | `boolean` | `false` | Habilita logging verboso de debug para detecção de locale, geração de rotas e carregamento de traduções. |

## Outros

| Opção | Tipo | Padrão | Descrição |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | Também emite um `hreflang` só-idioma derivado do `iso` de cada locale (ex.: `es-ES` → também `es`). O primeiro locale regional em `locales` reivindica a tag simples para aquele idioma. O `code` de roteamento nunca é usado — apenas `iso \|\| code`. |
| `vueDevtools` | `boolean` | `true` | Registra o inspector e a timeline do Vue DevTools em dev (extensão de navegador). Separado da aba customizada do Nuxt DevTools. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Prefixo prepend aos nomes de rotas localizadas (ex.: `'localized-index'`). Usado internamente para distinguir rotas originais das variantes de locale geradas. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Desabilitação de meta tags por rota, extraída de chamadas `defineI18nRoute()`. Mapeia um caminho de rota para `true` (desabilita todas as meta) ou um array de códigos de locale para os quais meta deve ser desabilitada. |
| `missingWarn` | `boolean` | `true` | Mostra avisos no console quando uma chave de tradução está ausente. |
| `hmr` | `boolean` | `true` | Habilita Hot Module Replacement para arquivos de tradução em desenvolvimento. Quando `true`, mudanças em arquivos JSON de tradução disparam recarga automática sem refresh de página completo. |
| `cacheMaxSize` | `number` | `0` | Número máximo de entradas no cache de tradução em memória. `0` significa sem limite. |
| `cacheTtl` | `number` | `0` | Time-to-live (em segundos) para entradas de tradução em cache. `0` significa que entradas nunca expiram. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Formatos de número nomeados por locale (compatível com Vue I18n). Habilita chamadas no estilo `$tn(1000, 'currency')`. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Formatos de data/hora nomeados por locale (`datetimeFormats` compatível com Vue I18n). Habilita chamadas no estilo `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | HTTP `Cache-Control` max-age (segundos) para `/\{apiBaseUrl\}/:page/:locale/data.json`. Aplica-se integralmente apenas enquanto `dateBuild` faz cache-bust na URL (`?v=...`), que é o padrão: a resposta se torna `public, max-age=…, immutable` e é segura para navegadores e CDNs. - `dateBuild: 0`/`''` — a URL é estável, então essa duração *não* é honrada; a resposta se torna `public, max-age=0, must-revalidate`. Um `max-age` longo em uma URL invariável trava o primeiro payload que o navegador viu. - `0` — não define `Cache-Control` em nada (útil em debug local) - Não aplicado em desenvolvimento (`import.meta.dev`) para que o HMR não seja combatido pelo cache do navegador - Alcança apenas respostas servidas pelo Nitro. Payloads copiados para `public/` e servidos pela plataforma de hospedagem usam os headers dela — veja o guia de Performance. Análogo ao experimental `httpCacheDuration` do `@nuxtjs/i18n` (v10.2.0), mas como header de resposta explícito, e não como `maxAge` do `defineCachedEventHandler` do Nitro. |
| `dateBuild` | `string \| number` | — | Valor usado para cache-busting nas requisições de tradução (`?v=...`). Quando não fornecido, o módulo cai no fallback `Date.now()` (não determinístico). Para deploys reprodutíveis/rolling, defina como um valor estável (ex.: um SHA de git ou número de build). |
| `experimental` | `Record<string, unknown>` | — | Bucket para opções experimentais/instáveis. O conteúdo pode mudar ou ser removido sem aviso entre versões menores. |
