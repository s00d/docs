# 📢 Eventos

## 🔄 `i18n:register`

O evento `i18n:register` do `Nuxt I18n Micro` permite a adição dinâmica de traduções ao contexto de i18n da sua aplicação, tornando o processo de internacionalização transparente e flexível. Esse evento permite integrar novas traduções conforme necessário, ampliando as capacidades de localização da sua aplicação.

### 📝 Detalhes do evento

- **Objetivo**:
  - Permite incorporar dinamicamente traduções adicionais ao conjunto existente para um locale específico.

- **Payload**:
  - **`register`**:
    - Uma função fornecida pelo evento que recebe dois argumentos:
      - **`translations`** (`Translations`):
        - Um objeto contendo pares chave-valor representando traduções, organizado segundo a interface `Translations`.
      - **`locale`** (`string`, opcional):
        - O código do locale (ex.: `'en'`, `'ru'`) para o qual as traduções são registradas. O padrão é o locale fornecido pelo evento, se não especificado.

- **Comportamento**:
  - Quando disparado, a função `register` mescla as novas traduções ao contexto atual do locale especificado, atualizando as traduções disponíveis em toda a aplicação.

### ⏱️ Quando dispara

O plugin de hooks do módulo (`05.hooks.ts`, `dependsOn: ['i18n-plugin-loader']`) chama `nuxtApp.callHook('i18n:register', …)`:

1. **Uma vez na inicialização** — após o plugin principal de i18n (`01.plugin.ts`) ter carregado as traduções para a rota inicial
2. **Na navegação** — em `router.beforeEach` quando o caminho muda, ou em toda navegação quando `strategy: 'no_prefix'`

Registre seu listener em um plugin Nuxt comum com `nuxtApp.hook('i18n:register', …)`. O plugin de hooks executa depois que o loader está pronto, então seu callback é invocado quando as traduções precisam ser estendidas.

Defina `hooks: false` em `nuxt.config` para desabilitar chamadas automáticas de `i18n:register` (veja [Configuração — `hooks`](/guides/configuration#hooks)).

### 💡 Exemplo de uso

O exemplo a seguir demonstra como usar o evento `i18n:register` para adicionar traduções dinamicamente:

```typescript
nuxt.hook('i18n:register', async (register: (translations: unknown, locale?: string) => void, locale: string) => {
  register(
    {
      greeting: 'Hello',
      farewell: 'Goodbye',
    },
    locale,
  )
})
```

  - O plugin de hooks (`05.hooks.ts`) dispara `i18n:register` depois que o loader principal está pronto e em navegações relevantes.

  - O exemplo registra traduções em inglês para `"greeting"` e `"farewell"`.
  - A função `register` mescla essas traduções ao conjunto existente para o locale fornecido.

### 🔗 Principais benefícios

- **Atualizações dinâmicas**:
  - Atualize ou adicione traduções facilmente sem precisar redeployar toda a aplicação.

- **Flexibilidade de localização**:
  - Suporta ajustes de localização em tempo real com base em necessidades do usuário ou da aplicação.

Usando o evento `i18n:register`, você garante que a estratégia de localização da sua aplicação continue flexível e adaptável, melhorando a experiência geral do usuário.

## 🛠️ Modificando traduções com plugins

Para modificar traduções dinamicamente na sua aplicação Nuxt, é recomendado usar plugins. Plugins fornecem uma maneira estruturada de lidar com atualizações de localização, especialmente ao trabalhar com módulos ou arquivos de tradução externos.

### **Registrando o plugin**

Se estiver usando um módulo, registre o plugin onde ocorrerão as modificações de tradução adicionando-o à configuração do seu módulo:

```javascript
addPlugin({
  src: resolve('./plugins/extend_locales'),
})
```

Isso registra o plugin localizado em `./plugins/extend_locales`, que cuidará do carregamento e registro dinâmicos de traduções.

### **Implementando o plugin**

No plugin, você pode gerenciar modificações de locale. Aqui está um exemplo de implementação em um plugin Nuxt:

```typescript
import { defineNuxtPlugin } from '#app'

export default defineNuxtPlugin(async (nuxtApp) => {
  // Function to load translations from JSON files and register them
  const loadTranslations = async (lang: string) => {
    try {
      const translations = await import(`../locales/${lang}.json`)
      return translations.default
    } catch (error) {
      console.error(`Error loading translations for language: ${lang}`, error)
      return null
    }
  }

  // Hook into the 'i18n:register' event to dynamically add translations
  // eslint-disable-next-line @typescript-eslint/ban-ts-comment
  // @ts-expect-error
  nuxtApp.hook('i18n:register', async (register: (translations: unknown, locale?: string) => void, locale: string) => {
    const translations = await loadTranslations(locale)
    if (translations) {
      register(translations, locale)
    }
  })
})
```

### 📝 Explicação detalhada

1. **Carregando traduções**:

- A função `loadTranslations` importa dinamicamente arquivos de tradução com base no locale. Os arquivos devem estar no diretório `locales` e nomeados conforme os códigos de locale (ex.: `en.json`, `de.json`).
- Em caso de carregamento bem-sucedido, as traduções são retornadas; caso contrário, um erro é registrado.

2. **Registrando traduções**:

- O plugin engancha no evento `i18n:register` usando `nuxtApp.hook`.
- Quando o evento é disparado, a função `register` é chamada com as traduções carregadas e o locale correspondente.
- Isso mescla as novas traduções ao contexto do i18n para o locale especificado, atualizando as traduções disponíveis em toda a aplicação.

### 🔗 Benefícios de usar plugins para modificações de tradução

- **Separação de responsabilidades**:
  - Encapsule a lógica de localização separadamente do código principal da aplicação, facilitando gerenciamento e manutenção.

- **Dinâmica e escalável**:
  - Ao carregar e registrar traduções dinamicamente, você pode atualizar conteúdo sem exigir um redeploy completo, o que é especialmente útil para aplicações com conteúdo multilíngue frequentemente atualizado.

- **Maior flexibilidade de localização**:
  - Plugins permitem modificar ou estender traduções conforme necessário, fornecendo uma estratégia de localização mais adaptável e responsiva às preferências dos usuários ou requisitos de negócio.

Ao adotar essa abordagem, você pode expandir e modificar a localização da sua aplicação com eficiência por meio de um processo estruturado e sustentável usando plugins, mantendo a internacionalização adaptável às necessidades em mudança e melhorando a experiência geral do usuário.
