# useI18nLocale

## Assinatura

{/* generated:symbol:useI18nLocale — do not edit; run `pnpm run docs:generate` */}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getLocaleWithServerFallback: (serverLocale?: string | null) => string | null; getPreferredLocale: () => string | null; hashCookie: any; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: any; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Ponto de entrada centralizado para o gerenciamento de locale i18n.
Combina `useState('i18n-locale')`, cookie de locale e utilitários de sincronização.

{/* /generated:symbol:useI18nLocale */}

## Uso

```vue
<script setup>
const {
  locale,
  localeCookie,
  hashCookie,
  validLocales,
  getPreferredLocale,
  getLocale,
  getLocaleWithServerFallback,
  getEffectiveLocale,
  resolveInitialLocale,
  setLocale,
  syncLocale,
  isValidLocale,
} = useI18nLocale()

// Set locale (updates state and cookies)
setLocale('de')

// Get current locale (state → cookie)
const current = getLocale()

// Get valid preferred locale
const preferred = getPreferredLocale()
</script>
```

## API

| Propriedade/Método                              | Tipo                                | Descrição                                                                            |
| ----------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------ |
| `locale`                                        | `Ref<string \| null>`               | Estado reativo do locale (`useState('i18n-locale')`)                                 |
| `localeCookie`                                  | `Ref`                               | Cookie do locale (quando a opção `localeCookie` está habilitada)                     |
| `hashCookie`                                    | `Ref`                               | Cookie usado quando `hashMode` está ativo                                            |
| `validLocales`                                  | `string[]`                          | Códigos de locale habilitados na config do módulo (exclui `disabled`)                |
| `getLocale()`                                   | `() => string \| null`              | Locale atual: estado → cookie (ou hash cookie no modo hash)                          |
| `getPreferredLocale()`                          | `() => string \| null`              | Locale de estado/cookie **validado** contra `validLocales`, ou `null`                |
| `getLocaleWithServerFallback(serverLocale?)`    | `(serverLocale?) => string \| null` | Estado → cookie → contexto de servidor opcional (usado durante init de `no_prefix`)  |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string`             | Locale para carregar traduções: modo hash prefere estado; caso contrário lê da rota  |
| `resolveInitialLocale(options)`                 | `(options) => string`               | Resolve o locale: estado → `serverLocale` → rota; sincroniza o estado quando necessário |
| `setLocale(locale)`                             | `(locale: string \| null) => void`  | Define o locale e sincroniza os cookies                                              |
| `syncLocale(locale)`                            | `(locale: string \| null) => void`  | Sincroniza apenas os cookies (sem atualização do estado)                             |
| `isValidLocale(locale)`                         | `(locale) => boolean`               | Verifica se a string está em `validLocales`                                          |

### Opções de `resolveInitialLocale`

```typescript
interface ResolveInitialLocaleOptions {
  route: unknown
  serverLocale?: string | null
  getLocaleFromRoute: (route?: unknown) => string
}
```

Usado internamente pelo plugin principal na inicialização. Plugins personalizados podem chamá-lo ao implementar fluxos alternativos de detecção.

### `getEffectiveLocale`

```typescript
const { getEffectiveLocale } = useI18nLocale()
const { $getLocale } = useNuxtApp()

const locale = getEffectiveLocale(route, (r) => $getLocale(r))
```

Retorna o locale usado para carregar traduções e formatar mensagens para um determinado objeto de rota.

## Definição programática do locale

Prefira `useI18nLocale()` em vez de usar `useState('i18n-locale')` diretamente:

```ts
// plugins/i18n-loader.server.ts
import { defineNuxtPlugin } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,

  setup() {
    const { setLocale } = useI18nLocale()
    const detectedLocale = 'ja' // Your detection logic here
    setLocale(detectedLocale)
  },
})
```

<Tip>
`setLocale()` atualiza apenas a preferência de locale (estado + cookie). Para também recarregar o contexto de tradução ativo no cliente, use `$switchLocale()` de `useNuxtApp()` ou `useI18n()`. Isso é especialmente importante para `no_prefix`, onde a URL não muda. Consulte [FAQ — trocar de locale sem alterar a URL](/guides/faq#-switch-locale-without-changing-the-url).
</Tip>
