Com `meta: true` (o padrão), toda página localizada recebe `<html lang dir>`, um link canônico, alternativas `hreflang`, `x-default` e tags de locale do Open Graph. Você precisa desta página quando quer definir a origem pública, ajustar quais locales aparecem nas tags ou sobrescrevê-las em uma página. A maioria dos sites só precisa de um `site.url` ou `metaBaseUrl` e de códigos `iso` corretos.

## Configuração mínima {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

`/de/about` então renderiza:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Direção do texto {#text-direction}

`<html dir>` vem do `dir` do locale. Sem ele, um idioma escrito da direita para a esquerda recebe `rtl`, lido a partir de `iso` (ou `code`): árabe, hebraico, persa, urdu e alguns outros, além de qualquer tag com um script RTL, como `az-Arab`. Todos os outros locales ficam sem o atributo `dir`, que os navegadores interpretam como `ltr`.

<Warning>

**`dir: 'auto'` custa tempo de parsing em páginas grandes** — `auto` em `<html>` faz o navegador deduzir a direção a partir do conteúdo enquanto faz o parsing. No Chromium, esse custo cresce mais rápido que a página: cerca de 100 ms com 5.000 elementos e 1 s com 20.000. Use-o apenas em uma página pequena cujo idioma você não tem como saber.

</Warning>

## Quais tags você recebe {#which-tags-you-get}

- **hreflang**: uma tag por locale que serve a página, com valor `iso` (ou `code` quando `iso` não existe), e sua URL com a mesma query do canonical. Uma página restrita com [Configuração da página](/pt-BR/guide/per-component-translations) ou `routeLocales` lista apenas os seus locales. [`hreflangBaseLanguage: true`](/pt-BR/api/module-options#hreflangbaselanguage) também adiciona o idioma base (`es-ES` → `es`) para o primeiro locale regional.
- **x-default**: a URL do locale padrão, apenas quando o locale padrão serve a página.
- **og:locale**: derivado de `iso` (`en-US` → `en_US`). Defina `og` no locale quando o mapeamento não for direto, por exemplo `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; sem nenhum dos dois, nenhum `og:locale` é escrito e o modo dev emite um aviso.
- **canonical / og:url**: a URL atual sem parâmetros de query, exceto os de [`canonicalQueryWhitelist`](/pt-BR/api/module-options#canonicalquerywhitelist) (padrão `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Por estratégia:

| Estratégia | hreflang e x-default | canonical, og:url, og:locale, atributos html |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | sim | sim |
| `no_prefix` | não (uma URL serve todos os locales) | sim |

## Definir a origem pública {#set-the-public-origin}

As URLs absolutas usam o primeiro disponível entre:

1. [`metaBaseUrl`](/pt-BR/api/module-options#metabaseurl);
2. `site.url` do `nuxt-site-config` (instalado pelo `@nuxtjs/seo`);
3. a origem da requisição, com `app.baseURL` anexado.

Fixe um dos dois primeiros.

<Warning>

O fallback para a origem da requisição lê `X-Forwarded-Host` e `X-Forwarded-Proto`, porque [`metaTrustForwardedHost`](/pt-BR/api/module-options#metatrustforwardedhost) e `metaTrustForwardedProto` são `true` por padrão. Isso só é seguro atrás de um proxy que sobrescreve esses headers; caso contrário, um cliente pode escolher o host dos seus links canônicos, e um cache pode repassar essa página.

Se o app puder ser acessado diretamente, fixe `metaBaseUrl`: diferentemente de definir as duas opções como `false`, isso também ignora um `Host` forjado. Veja [Atrás de um proxy ou CDN](/pt-BR/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

O fallback é útil para um único deploy que atende vários domínios: `https://site-a.com/en/about` e `https://site-b.com/en/about` recebem cada um a sua própria origem.

Com `baseUrl` nos locales, um host conhecido usa o seu próprio `baseUrl`, acima de `metaBaseUrl` e `site.url`, então o canonical e o `og:url` permanecem nesse domínio e o `hreflang` aponta cada locale para o seu domínio. Qualquer outro host usa `metaBaseUrl`, senão o `baseUrl` do locale padrão, senão `site.url`, de modo que um `Host` falsificado não consegue chegar às suas tags. Se nenhum deles estiver definido, o fallback para a origem da requisição permanece e o build emite um aviso. Veja [Layers e domínios](/pt-BR/guide/layers#multiple-domains).

## Deixar locales ou páginas de fora {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Se o locale padrão tiver `seo: false`, nenhum `x-default` é escrito. Para desativar as tags em uma página, use `disableMeta` em [Configuração da página](/pt-BR/guide/per-component-translations#turn-off-seo-tags), ou [`routeDisableMeta`](/pt-BR/api/module-options#routedisablemeta) na configuração.

## Sobrescrever tags em uma página {#override-tags-on-one-page}

Para conteúdo de CMS em que só existem algumas traduções, ou em que as URLs vêm de uma API, substitua as tags geradas com [`useI18nHead`](/pt-BR/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` também pode definir ou remover `canonical`, `xDefault`, `ogLocale` e `ogUrl`; `disable` remove grupos inteiros (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Passe um getter para que os valores sejam recalculados após a troca de locale. Para slugs por locale, defina `$setI18nRouteParams` primeiro ([Caminhos localizados](/pt-BR/guide/custom-locale-routes#per-locale-slugs)) e as alternativas geradas já os usarão.

## Barra final {#trailing-slash}

`$localePath`, `$switchLocalePath`, o objeto de rota de `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, os redirecionamentos de locale e as URLs de SEO seguem uma única regra de barra: `experimental.defaults.nuxtLink.trailingSlash` por padrão, ou [`trailingSlash`](/pt-BR/api/module-options) na configuração do i18n quando os caminhos do i18n devem ser diferentes.

## Nuxt SEO {#nuxt-seo}

O [`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) funciona com este módulo por meio do `nuxt-site-config` 4+. Liste `nuxt-i18n-micro` primeiro para que a configuração do site possa ler os locales e defina `site.url` uma única vez — ele também alimenta as tags acima.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

O nome e a descrição traduzidos do site vêm das chaves `nuxtSiteConfig.name` / `nuxtSiteConfig.description` nos seus arquivos de locale. O erro `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` significa que o `@nuxtjs/seo` é anterior à versão 3; atualize-o ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
