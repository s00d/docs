A opção `strategy` decide se um locale aparece na URL e para quais locales. Escolha-a uma vez, antes de publicar URLs: alterá-la depois muda todos os links. O módulo então gera as rotas localizadas em tempo de build, e `$localePath`, `<i18n-link>` e o seletor de idioma as leem.

## As quatro estratégias {#the-four-strategies}

![A página /about em en (padrão) e de em cada estratégia; as mesmas URLs estão listadas no texto abaixo](/images/diagrams/strategies.svg)

**Tipo** `Strategies` · **Padrão** `'prefix_except_default'`

Estratégia de roteamento de URL para prefixos de locale.

- `'no_prefix'` — nenhum locale na URL; o locale é armazenado em um cookie.
- `'prefix_except_default'` — prefixa todos os locales, exceto o padrão.
- `'prefix'` — sempre prefixa, inclusive o locale padrão.
- `'prefix_and_default'` — como `prefix`, mas o locale padrão também é acessível sem prefixo.

URLs para uma página `about` com `defaultLocale: 'en'` e os locales `en`, `de`:

| Estratégia | Inglês | Alemão | Não servido |
| --- | --- | --- | --- |
| `prefix_except_default` (padrão) | `/about` | `/de/about` | `/en` e `/en/about` são um 404 |
| `prefix` | `/en/about` | `/de/about` | `/about` redireciona para uma URL com prefixo |
| `prefix_and_default` | `/about` e `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | o locale não está na URL |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

A estratégia é fixada no build: uma substituição dela em runtime é ignorada com um aviso ([Substituições em runtime](/pt-BR/guide/runtime-overrides)).

## Qual escolher {#which-one-to-choose}

- **`prefix_except_default`**: a maioria dos sites. URLs existentes sem prefixo continuam funcionando para o idioma padrão.
- **`prefix`**: todos os idiomas são iguais; `/` sempre leva a uma home com prefixo.
- **`prefix_and_default`**: você precisa que `/en/...` e as URLs sem prefixo funcionem ao mesmo tempo, por exemplo, durante a migração de uma para a outra. URLs sem prefixo nunca são redirecionadas.
- **`no_prefix`**: apps atrás de um login, ou uma URL por página para todos os idiomas. O locale vem de um cookie ou de `?locale=`. Os mecanismos de busca veem um idioma por URL, então nenhuma alternativa `hreflang` é emitida.

Como o locale é escolhido para uma URL, e quando um visitante é redirecionado, está em [Detecção de locale](/pt-BR/guide/locale-detection).

## Rotas geradas {#generated-routes}

Em tempo de build, cada página recebe os registros de rota de que sua estratégia precisa. Cada registro carrega `meta.i18n = { name, locales }`: a página que ele mostra e os locales que ele serve. Links, trocas de locale e redirecionamentos são todos resolvidos a partir desses registros, então uma URL fornecida pelo módulo é sempre uma que o router serve.

Locales que compartilham o caminho da página compartilham um registro, `/:locale(de|fr)/about`. Um locale com seu próprio caminho recebe seu próprio registro, chamado `localized-<page>-<locale>`:

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

Caminhos personalizados, listas de locales por página e a exclusão de uma página da localização estão em [Caminhos localizados](/pt-BR/guide/custom-locale-routes) e [Configuração da página](/pt-BR/guide/per-component-translations). O prefixo `localized-` é [`localizedRouteNamePrefix`](/pt-BR/api/module-options#localizedroutenameprefix).

<Warning>

**Os nomes de rota são gerados** — Não fixe nomes `localized-…` no código em `router.push({ name })`. Passe o nome da própria página para `$localeRoute` ou `<i18n-link>`; eles escolhem o registro certo.

</Warning>

## Criando links para uma página em um locale {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- Rotas nomeadas e caminhos funcionam. Um caminho é comparado com as rotas geradas, então a forma dele em qualquer locale é aceita.
- Um locale que não serve a página (veja `locales` em [Configuração da página](/pt-BR/guide/per-component-translations)) leva à home desse locale em vez de a uma página inexistente.
- Parâmetros por locale (um slug traduzido) passam por `$setI18nRouteParams`; veja [Caminhos localizados](/pt-BR/guide/custom-locale-routes).

As assinaturas estão em [Métodos](/pt-BR/api/methods).

## Detalhes de `no_prefix` {#no_prefix-details}

- [`localeCookie`](/pt-BR/api/module-options#localecookie) tem como padrão `'user-locale'` com `no_prefix`, para que a escolha sobreviva a um recarregamento.
- `$switchLocale('de')` carrega o dicionário alemão e substitui a entrada atual do histórico; a URL não muda.
- Caminhos personalizados por locale continuam funcionando: com `globalLocaleRoutes: { about: { de: '/ueber-uns' } }`, leitores em alemão recebem `/ueber-uns`. Essa URL sempre renderiza em alemão, seja qual for a preferência do visitante, e uma página restrita a alguns locales renderiza em um deles. Um caminho compartilhado por vários locales (`en` e `de` ambos em `/page/:id`) renderiza a preferência quando ela é um deles. A preferência em si permanece: a próxima página volta a ela.
- [`noPrefixRedirect: true`](/pt-BR/api/module-options#noprefixredirect) redireciona o caminho original de uma página com caminho personalizado no locale padrão: para o caminho personalizado do locale do visitante ou, caso contrário, para o do locale padrão (`/about` → `/about-us` quando `en` tem `/about-us`, → `/ueber-uns` com o cookie `de`). Um locale sem caminho personalizado próprio permanece no caminho original e renderiza ali. Páginas com parâmetros não são redirecionadas.

## Apps sem `pages/` {#apps-without-pages/}

Com `pages: false` não há rotas de página para localizar. Use apenas arquivos de tradução raiz (`disablePageLocales: true`); a detecção, o cookie e `$switchLocale` continuam funcionando. A variante `pages-false` de `test/fixtures/basic` no repositório é uma configuração funcional.
