---
title: "Configuração da página"
description: "Restrinja uma página a alguns locales, dê a ela caminhos personalizados, traduções inline ou nenhuma tag de SEO com $defineI18nRoute."
---

`$defineI18nRoute` define opções de i18n para uma página a partir da própria página. Use-o quando uma página existe apenas em alguns locales, precisa de seu próprio caminho localizado, carrega algumas traduções próprias ou não deve receber tags hreflang/canonical. O módulo lê a chamada em tempo de build e a incorpora às rotas geradas.

## Restringir uma página a alguns locales {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

Somente `/product` e `/de/product` são gerados com a estratégia padrão `prefix_except_default`; a página não tem rota em nenhum outro locale. O mesmo pode ser definido a partir do `nuxt.config.ts` com [`routeLocales`](/pt-BR/api/module-options#routelocales).

`$defineI18nRoute` é uma injeção do app Nuxt, não uma macro do compilador: sempre obtenha-a de `useNuxtApp()` e chame-a com o `$`. Apenas `$defineI18nRoute(` é reconhecido pela etapa de build.

## Adicionar traduções inline {#add-inline-translations}

Passe um objeto em vez de um array. Suas chaves são os locales permitidos, e seus valores são mesclados no dicionário da página para o locale ativo.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Traduções inline são enviadas dentro do componente da página para todos os locales. Prefira [arquivos de tradução de página](/pt-BR/guide/translations) para qualquer coisa maior que algumas chaves; mantenha chaves inline para páginas e componentes autocontidos.

## Definir caminhos localizados {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

Com `prefix_except_default` e `defaultLocale: 'en'`, isso produz `/welcome` e `/de/willkommen`. Um `path` dentro de um objeto de locale inline faz o mesmo: `locales: { de: { path: '/willkommen' } }`. Parâmetros dinâmicos, rotas aninhadas e a alternativa no nível da configuração são abordados em [Caminhos localizados](/pt-BR/guide/custom-locale-routes).

## Desativar as tags de SEO {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

A alternativa no nível da configuração é [`routeDisableMeta`](/pt-BR/api/module-options#routedisablemeta). O que são essas tags está explicado na página de [SEO](/pt-BR/guide/seo).

## O que o build consegue ler {#what-the-build-can-read}

A etapa de build encontra a chamada em cada arquivo de página e avalia seu argumento sem executar seu app. Funciona quando a configuração é:

- um objeto literal (strings, arrays, objetos aninhados, template literals, ternários sobre `process.env.NODE_ENV`);
- construída a partir de constantes declaradas no mesmo `<script setup>` (`const locales = ['en', 'de']`, incluindo spreads);
- um array de objetos com um campo `code` (`[{ code: 'en' }, { code: 'de' }]`).

Ela não consegue ler valores importados de outro módulo, nem nada que precise do seu app em runtime (composables, `await`, dados buscados). Nesse caso, o build registra `Ignored the $defineI18nRoute() config in <file>` e a página mantém os locales e rotas padrão.

Em runtime, a chamada apenas mescla as traduções inline do locale atual e as mescla novamente quando o locale muda. `locales`, `localeRoutes` e `disableMeta` só têm efeito por meio do build, então alterá-los exige um novo build (o servidor de desenvolvimento refaz o build ao salvar).
