---
title: "Caminhos localizados"
description: "Dê a uma página uma URL diferente por locale com localeRoutes ou globalLocaleRoutes, incluindo params dinâmicos e slugs por locale."
---

Por padrão, todo locale serve uma página no mesmo caminho: `/en/about`, `/de/about`. Os caminhos localizados permitem que cada locale use as próprias palavras, como `/de/ueber-uns`, enquanto o arquivo da página continua o mesmo. Você os define na página com `$defineI18nRoute` ou, para várias páginas de uma vez, em `nuxt.config.ts`.

## Na página {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

Com `prefix_except_default` e `defaultLocale: 'en'`, a página responde em `/about`, `/de/ueber-uns` e `/fr/a-propos`. Um locale sem entrada mantém o caminho padrão. Escreva os caminhos sem o código do locale: o prefixo é adicionado pela [estratégia](/pt-BR/guide/strategy), e um caminho que começa com o código do locale gera um aviso no log. O que mais a chamada aceita está em [Configuração da página](/pt-BR/guide/per-component-translations).

## No nuxt.config {#in-nuxt-config}

[`globalLocaleRoutes`](/pt-BR/api/module-options#globallocaleroutes) faz o mesmo para qualquer página, usando como chave o caminho dela (ou o nome da rota, quando escrito sem barra inicial):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

Quando uma página define `localeRoutes` e `globalLocaleRoutes` tem a mesma chave, a entrada da configuração prevalece.

## Params dinâmicos {#dynamic-params}

Escreva os params em qualquer forma do Nuxt: `[id]`, `[[page]]`, `[...slug]` ou `:id()`. Os nomes dos params devem corresponder ao arquivo da página.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

Páginas aninhadas recebem um caminho filho absoluto (`/ueber-uns/team`) ou um caminho relativo ao caminho localizado do pai (`team`).

## Links para páginas localizadas {#linking-to-localized-pages}

Os links são resolvidos para o caminho localizado do locale de destino, seja passando um nome de rota ou um caminho simples:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

Os nomes das rotas vêm do caminho do arquivo (`pages/about/team.vue` é `about-team`), a menos que você defina um com `definePageMeta({ name })`.

## Slugs por locale {#per-locale-slugs}

Quando o próprio slug difere por locale (`/our-products/red-shoe` vs `/de/unsere-produkte/roter-schuh`), informe ao seletor de idioma quais params usar com `$setI18nRouteParams` assim que os dados forem carregados:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

`$switchLocalePath('de')` e `<i18n-switcher>` passam então a apontar para `/de/unsere-produkte/roter-schuh`. As chaves são códigos de locale, e os valores são params por nome (como no arquivo da página).

Um seletor no layout é renderizado antes que o setup assíncrono da página chegue a esse ponto, então, quando a renderização termina, o módulo reescreve os links de `<i18n-switcher>`, tanto em `app.vue` quanto na página. O HTML do servidor, um visitante sem JavaScript e a primeira renderização no cliente ficam então de acordo. Para isso, defina os params durante o SSR: com `lazy` ou `server: false`, os links só mudam após a hidratação. O streaming de SSR do Nuxt envia o HTML antes que os params sejam conhecidos, então, nesse caso, os links no primeiro HTML mantêm os params da própria URL.

Apenas os links do próprio seletor são reescritos. Um link `$switchLocalePath` escrito à mão precisa ser renderizado depois que os params são definidos, então coloque-o na página que os define, também depois de um `await`. Em um layout ele é renderizado primeiro: o HTML do servidor mantém os params da URL, e a hidratação avisa sobre uma incompatibilidade. Use `<i18n-switcher>` nesse caso, com seus slots e as props `custom*Style` para a aparência.

Os params pertencem à página que os definiu:

- Eles são descartados quando uma navegação para outro caminho é concluída, então cada página define os seus. Uma navegação cancelada os mantém.
- Obtenha `$setI18nRouteParams` de `useNuxtApp()` ou `useI18n()` no `setup`, inclusive quando você o chamar depois em um handler de `useAsyncData`. Obtida ali, a função conhece sua página: se o visitante já saiu, uma chamada tardia não faz nada.
- Com `keepalive`, uma página recebe de volta os params que definiu quando o visitante retorna. `useI18nHead` faz o mesmo.

## Rotas adicionadas em pages:extend {#routes-added-in-pagesextend}

As rotas que você adiciona no hook `pages:extend` não têm um arquivo de página de onde ler `$defineI18nRoute`, e várias delas costumam compartilhar um mesmo componente wrapper. Uma rota adicionada sem `name` recebe o nome que o Nuxt daria ao seu caminho (`/a/:id()` vira `a-id`), para que os links de idioma a alcancem, a menos que outra rota já tenha esse nome; nesse caso, dê a ela um `name` explícito. Mantenha uma única lista e divida-a em páginas e em `globalLocaleRoutes` com chave pelo nome da rota usando `splitLocaleRoutes` de `@i18n-micro/utils/split-locale-routes` (adicione o pacote às suas dependências):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

Não coloque caminhos localizados em `route.meta`: eles seriam enviados na tabela de rotas do cliente.
