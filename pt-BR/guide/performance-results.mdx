### Descrição {#description}

Compara **Nuxt puro**, **i18n-micro** e **`@nuxtjs/i18n`** com um mesmo perfil de dicionário compartilhado via `untestutils/perf`.

Foco: tempo de build, pico de RSS, **código vs traduções (asset) vs total** implantável, e carga (Artillery).

### Notas de metodologia {#methodology-notes}

- As métricas são **médias de 3 execuções consecutivas por fixture** (não intercaladas).
- **Artefato**: `.output/server/index.mjs` do node-server do Nitro após `nuxi build` forçado; `nuxt-i18n-micro` é o **dist do módulo compilado** (não o stub jiti de `dev:prepare`). Veja a [metodologia de benchmark](https://s00d.github.io/nuxt-i18n-micro/contributing/performance-methodology).
- **Traduções** = `bundle.asset` (JSON de locales, `chunks/raw/`, chunks de locale correspondentes via `isTranslationFile`).
- **Código** exclui source maps (`*.map`): as fixtures vinculam o módulo a partir do repositório, então o Nitro escreve maps completos para ele e nenhum para as dependências npm.
- **plain-nuxt** serve o mesmo volume de folhas como JSON estático — pesado em I/O sob carga, não "overhead de i18n".
- Perfil de carga `--load full`: aquecimento 6s@6 + principal 60s@60 sem limite (histórico).
- Pausas de resfriamento `--cool fast` (veja o documento de metodologia).
- Cada um dos builds de `runs` é **forçado** (sem zerar o tempo de build por cache aquecido).
- A **taxa de erro** do Artillery nas tabelas corresponde a erros de status HTTP das métricas de carga. Os gráficos também plotam `vusers.failed` (timeouts do cliente sob saturação); esses podem ser altos enquanto a taxa de erro HTTP permanece em 0%.

## Notas {#notes}

- Perfil compartilhado: 4 locales × 2 páginas × ~16,8 mil folhas no index.
- Carga: apenas Artillery programático — aquecimento **6s@6** + principal **60s@60**, VUs sem limite (metodologia YAML histórica). Caminhos do perfil de runtime — veja `scripts/src/perf/load.ts`.
- Pausas de resfriamento: 2s após o build, 3s entre execuções, 5s entre fixtures. Os builds são forçados a cada execução para que as médias não sejam diluídas por acertos de cache.
- Para reexecutar no dia a dia: `pnpm test:performance` (`--load short --cool fast`).
- Para regenerar esta página: `pnpm -C scripts cli performance --load full --only all --runs 3`.
- Flags: `--locales N --keys K --only all|micro|i18n|plain --runs N --skip-load --cool fast|strict`.
