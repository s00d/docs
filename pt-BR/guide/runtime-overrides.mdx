---
title: "Sobrescritas em tempo de execução"
description: "Altere o locale padrão, o locale de fallback ou os locales desativados por instância de um mesmo build, com variáveis de ambiente ou runtimeConfig."
---

As sobrescritas em tempo de execução permitem que um único artefato de build rode com configurações de locale diferentes por ambiente ou tenant, sem rebuild. Você pode alterar o locale padrão, o locale de fallback e quais locales ficam desativados. Roteamento, redirecionamentos, renderização e helpers do servidor usam os valores sobrescritos, assim como o navegador em uma página renderizada no servidor.

## Definir sobrescritas com variáveis de ambiente {#set-overrides-with-environment-variables}

```bash
NUXT_I18N_DEFAULT_LOCALE=de \
NUXT_I18N_FALLBACK_LOCALE=en \
NUXT_I18N_DISABLED_LOCALES=fr,it \
node .output/server/index.mjs
```

| Variável | Alias |
| --- | --- |
| `NUXT_I18N_DEFAULT_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE` |
| `NUXT_I18N_FALLBACK_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE` |
| `NUXT_I18N_DISABLED_LOCALES` (separados por vírgula) | `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES` |

O servidor as lê uma vez na inicialização; reinicie para aplicar uma alteração. Em uma página renderizada no servidor, o navegador recebe os valores resolvidos do servidor. Com `ssr: false` não há renderização no servidor e o navegador não tem ambiente: apenas `runtimeConfig.public.i18nRuntime` se aplica ali, e o navegador registra os avisos descritos abaixo.

## Definir sobrescritas no runtimeConfig {#set-overrides-in-runtimeconfig}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

Um valor definido em `runtimeConfig.public.i18nRuntime` tem prioridade sobre a variável `NUXT_I18N_*` do mesmo campo.

Não confunda com a variável `DEFAULT_LOCALE` de tempo de build, que substitui `defaultLocale` durante o build e não precisa de suporte em tempo de execução.

## O que pode e o que não pode mudar {#what-can-and-cannot-change}

| Configuração | Em tempo de execução |
| --- | --- |
| `defaultLocale` | Sim com `prefix` e `no_prefix`. Com `prefix_except_default` e `prefix_and_default` ele é fixado no build (suas páginas são as rotas sem prefixo); uma sobrescrita é ignorada com um aviso. |
| `fallbackLocale` | Sim. |
| `disabledLocales` | Soma-se aos locales desativados no build; nunca reativa um. O padrão do build não pode ser desativado com `prefix_except_default` / `prefix_and_default`. |
| `strategy` | Não. Uma estratégia em tempo de execução é ignorada com um aviso; gere um artefato por estratégia. |

Valores inválidos nunca quebram a aplicação. Cada caso registra um aviso por processo do servidor:

- desativar todos os locales é ignorado;
- um `defaultLocale` que não está ativado cai para o primeiro locale ativado;
- um `fallbackLocale` que não está ativado mantém o valor do build se este estiver ativado; caso contrário, não há fallback.

## Ler a configuração efetiva {#read-the-effective-config}

```vue
<script setup lang="ts">
const { $getI18nConfig } = useNuxtApp()
const config = $getI18nConfig() // build config with overrides applied
</script>
```

Trate-a como somente leitura: no servidor ela é compartilhada por todas as requisições e congelada em desenvolvimento; a cópia do navegador não é congelada. Importar a configuração de `#build/i18n.strategy.mjs` fornece os valores do build sem as sobrescritas.

## Locales desativados e arquivos estáticos {#disabled-locales-and-static-files}

Um locale desativado em tempo de execução responde 404 em suas rotas e na rota de payload, mas seus arquivos de payload continuam em `.output/public/_locales/` e um servidor de arquivos estáticos os retorna. Quando esses arquivos não puderem ficar acessíveis, desative o locale em tempo de build com `disabled: true`.
