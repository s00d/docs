Os handlers de servidor em `server/api/` e `server/routes/` podem traduzir strings e ler o locale da requisição com dois helpers auto-importados. Use-os para respostas de API, e-mails, feeds ou qualquer coisa renderizada fora de uma página Vue. Eles leem os mesmos arquivos de tradução que as suas páginas e detectam o locale a partir da requisição.

## Traduzir em um handler {#translate-in-a-handler}

```ts
// server/api/greeting.get.ts
export default defineEventHandler(async (event) => {
  const t = await useTranslationServerMiddleware(event)
  return { message: t('greeting', { name: 'Ada' }) }
})
```

```bash
curl 'http://localhost:3000/api/greeting?locale=de'
# {"message":"Hallo, Ada!"}
```

`useTranslationServerMiddleware(event, defaultLocale?, locale?)` é assíncrono e retorna `t(key, params?, defaultValue?)`. `t` retorna a string, interpola params `{name}` e, quando a chave não existe, retorna um `defaultValue` não vazio ou, caso contrário, a própria chave.

`t` enxerga apenas o chunk `index`: os arquivos raiz (`locales/<locale>.json`) mais `locales/pages/index/` quando existir (apenas os arquivos raiz com `disablePageLocales`). As chaves de outras páginas não são carregadas. Para elas, carregue o chunk você mesmo:

```ts
const { data } = await loadTranslationsFromServer('de', 'about') // Translations object of the about page
```

## Ler o locale da requisição {#read-the-request-locale}

```ts
// server/api/locale.get.ts
export default defineEventHandler((event) => {
  const { current, isDefault, locale } = useLocaleServerMiddleware(event)
  return { current, isDefault, dir: locale?.dir ?? 'ltr' }
})
```

`useLocaleServerMiddleware(event, defaultLocale?, locale?)` é síncrono e retorna:

```ts
interface LocaleInfo {
  current: string // detected locale code
  default: string // defaultLocale, runtime overrides included (fixed at build under prefix_except_default / prefix_and_default)
  fallback: string // fallbackLocale, else the default
  available: string[] // enabled locale codes
  locale: Locale | null // the config entry of `current`
  isDefault: boolean
  isFallback: boolean
}
```

## Como o locale é escolhido {#how-the-locale-is-chosen}

Os dois helpers usam a mesma ordem em todas as rotas de servidor, sejam `/api` ou não:

1. a query `?locale=` (o primeiro valor quando repetida);
2. um param de rota `[locale]` ou um prefixo de locale no caminho (`/de/...`);
3. o cookie de locale, quando [`localeCookie`](/pt-BR/api/module-options#localecookie) está definido (`hash-locale` com `hashMode`);
4. `Accept-Language`, quando `autoDetectLanguage` está ativado (respeitando os q-values);
5. `defaultLocale`.

Códigos inválidos e desativados são ignorados em todas as etapas. Esta é a ordem da API; a renderização de uma página ignora `?locale=` nas estratégias com prefixo. As duas ordens são comparadas em [Detecção de locale](/pt-BR/guide/locale-detection).

## Forçar um locale {#force-a-locale}

Passe o terceiro argumento para pular a detecção, por exemplo em um job que envia e-mails no idioma do usuário:

```ts
export default defineEventHandler(async (event) => {
  const user = await getUser(event) // your code
  const t = await useTranslationServerMiddleware(event, undefined, user.locale)
  return sendMail(user.email, t('mail.welcome.subject'))
})
```

O segundo argumento substitui `defaultLocale` na detecção desta chamada, então não tem efeito quando um locale é forçado. Os dicionários são armazenados em cache por requisição e por locale, e entre requisições no cache de traduções do servidor, então chamar um helper várias vezes tem custo baixo.

## Componentes de servidor {#server-components}

Um componente de servidor (`.server.vue`, `<NuxtIsland>`) é renderizado a partir da sua própria URL, `/__nuxt_island/...`, então ele não vê a URL da página, e o Nuxt passa a ele apenas as suas props. Passe o locale como uma prop `locale`. Ele então é renderizado nesse locale, e uma troca o busca novamente, já que as props fazem parte da URL e da chave de cache da island. O nome é reservado: qualquer código de locale habilitado em uma prop chamada `locale` define o locale da renderização, então dê outro nome a uma prop que signifique outra coisa, como um formato numérico:

```vue
<!-- components/Greeting.server.vue -->
<template><p>{{ $t('greeting') }}</p></template>
<script setup lang="ts">
defineProps<{ locale?: string }>()
</script>
```

```vue
<template>
  <Greeting :locale="$getLocale()" />
  <NuxtIsland name="Greeting" :props="{ locale: $getLocale() }" />
</template>
```

Sem a prop, ele é renderizado no locale do cookie ou, na falta dele, no locale padrão, independentemente da URL, e não acompanha uma troca. O seu `$t` enxerga o chunk `index`: os arquivos raiz mais `locales/pages/index/`.
