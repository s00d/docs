# Resultados de testes de desempenho

## Informações do projeto

- **[plain-nuxt](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/plain-nuxt)**: ./test/fixtures/plain-nuxt
- **[i18n-micro](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n-micro)**: ./test/fixtures/i18n-micro
- **[i18n](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n)**: ./test/fixtures/i18n
- **[CLI](https://github.com/s00d/nuxt-i18n-micro/tree/main/scripts/src/commands/performance.ts)**: `pnpm -C scripts cli performance` / `pnpm test:performance`

### Descrição

Compara **Nuxt puro** (baseline sem módulo i18n), **i18n-micro** e **`@nuxtjs/i18n` v10.6** sob um mesmo perfil de dicionário compartilhado.

Foco: tempo de build, RSS de pico, **código vs traduções vs total** implantável e comportamento do servidor sob Artillery + Autocannon.

### Notas de metodologia

- As métricas são **médias de 3 execuções consecutivas por fixture** (fixture A ×3, depois B ×3, depois C ×3, não intercaladas).
- As **traduções** incluem JSON de locale em `locales/` / `_locales/` / `translations/`, tudo em `chunks/raw/` e chunks de locale correspondentes. Relatórios antigos que mostravam `@nuxtjs/i18n` "translations: 0 B" e uma coluna "code" enorme contavam chunks de mensagem como código do app.
- O **plain-nuxt** serve o mesmo volume de folhas que JSON estático em `public/translations` (não como imports JS estáticos). Sob Artillery, esse baseline é I/O-heavy. Não é "overhead de i18n". É o custo de buscar JSON grande por requisição.

### Execuções

Todas as métricas abaixo são **médias de 3 execuções**.

### Perfil da fixture

| Parâmetro | Valor |
|------|-------|
| Locales | **4** (`en`, `de`, `ru`, `fr`) |
| Páginas | **2** (`index`, `page`) |
| Árvore do index | profundidade **5**, ramificação **7** → **16.807** chaves-folha / locale |
| Páginas secundárias | profundidade **5**, ramificação **6** → **7.776** chaves-folha / página / locale |
| Objetivo | Perfil padrão da CLI (`--locales 4 --keys 10000`); aumente os parâmetros para cargas de regression-radar |

Os dicionários vêm de `test/fixtures/perf-shared/runtime.json` (escrito pela CLI) para que todas as três fixtures fiquem alinhadas.

## Notas

- Perfil compartilhado: 4 locales × 2 páginas × ~16,8k folhas de index.
- Artillery: 6s de aquecimento @6 VU/s + 60s principal @60 VU/s. Autocannon: 10 conexões × 10s.
- Reexecutar: `pnpm test:performance` ou `pnpm -C scripts cli performance --locales N --keys K --only all|micro|i18n|plain --runs N`.
