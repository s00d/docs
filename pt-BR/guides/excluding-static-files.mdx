# Excluindo arquivos estáticos do roteamento i18n

## Visão geral

Por padrão, o nuxt-i18n-micro exclui automaticamente arquivos estáticos comuns do processamento de roteamento i18n. No entanto, você também pode configurar padrões personalizados de exclusão para impedir que caminhos específicos sejam processados pelo sistema i18n.

## Exclusões integradas

O módulo exclui automaticamente os seguintes tipos de arquivos e padrões:

- **Sitemaps**: `/sitemap*.xml`, `/sitemap-en.xml`, etc.
- **Arquivos de SEO**: `/robots.txt`, `/favicon.ico`
- **Arquivos PWA**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Assets estáticos**: arquivos com extensões como `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Paths internos do Nuxt**: qualquer path começando com `__` (como `/__nuxt/`)

## Padrões de exclusão personalizados

Você pode definir padrões de exclusão personalizados usando a opção `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Tipos de padrão

### Padrões de string

- **Correspondência exata**: `'/api/health'` corresponde exatamente a `/api/health`
- **Correspondência por prefixo**: `'/admin'` corresponde a `/admin` e `/admin/dashboard`
- **Wildcards**: `'/api/*'` corresponde a `/api/users`, mas não a `/api/users/123`
- **Wildcards profundos**: `'/admin/**'` corresponde a `/admin/users` e `/admin/users/123`

### Expressões regulares

Use objetos RegExp para correspondência de padrões complexos:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Casos de uso

### Arquivos de SEO

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### Rotas de API

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Painéis administrativos

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Assets estáticos

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Como funciona

1. **Middleware de servidor**: um middleware Nitro é executado primeiro para verificar padrões de exclusão
2. **Processamento de página**: durante a resolução de página, caminhos excluídos são pulados
3. **Rota catch-all**: a rota de fallback verifica exclusões antes do processamento
4. **Prerender**: caminhos excluídos não são incluídos em rotas prerenderizadas

## Impacto no desempenho

- Verificações de exclusão são otimizadas e executadas cedo no ciclo de requisição
- Padrões integrados usam correspondência de regex eficiente
- Padrões personalizados são cacheados e reutilizados
- Overhead de desempenho mínimo para paths excluídos

## Resolução de problemas

### Arquivos estáticos ainda sendo interceptados

1. **Verifique a sintaxe do padrão**: garanta que seus padrões correspondam à estrutura exata do path
2. **Use regex para padrões complexos**: wildcards de string têm limitações
3. **Teste os padrões**: use as dev tools do navegador para verificar o path real da requisição
4. **Verifique a ordem**: garanta que padrões de exclusão sejam definidos antes de outras configs i18n

### Padrão não funciona

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Modo debug

Habilite o modo debug para ver o processamento de exclusão:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Isso registrará as decisões de exclusão no console.

## Migração a partir de workarounds

Se você estava usando workarounds como route rules ou middleware, agora pode substituí-los por `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

A nova abordagem é mais confiável e funciona em múltiplos níveis do sistema de roteamento.
