# Excluindo arquivos estáticos do roteamento de i18n

## Visão geral

Por padrão, o nuxt-i18n-micro exclui automaticamente arquivos estáticos comuns do processamento de roteamento de i18n. No entanto, você também pode configurar padrões de exclusão customizados para impedir que caminhos específicos sejam processados pelo sistema de i18n.

## Exclusões embutidas

O módulo exclui automaticamente os seguintes tipos e padrões de arquivo:

- **Sitemaps**: `/sitemap*.xml`, `/sitemap-en.xml`, etc.
- **Arquivos de SEO**: `/robots.txt`, `/favicon.ico`
- **Arquivos de PWA**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Assets estáticos**: Arquivos com extensões como `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Caminhos internos do Nuxt**: Qualquer caminho começando com `__` (como `/__nuxt/`)

## Padrões de exclusão customizados

Você pode definir padrões de exclusão customizados usando a opção `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Tipos de padrão

### Padrões de string

- **Casamento exato**: `'/api/health'` - casa exatamente com `/api/health`
- **Casamento de prefixo**: `'/admin'` - casa com `/admin` e `/admin/dashboard`
- **Wildcards**: `'/api/*'` - casa com `/api/users` mas não com `/api/users/123`
- **Wildcards profundos**: `'/admin/**'` - casa com `/admin/users` e `/admin/users/123`

### Expressões regulares

Use objetos RegExp para casamento de padrões complexos:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Casos de uso

### Arquivos de SEO

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### Rotas de API

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Painéis admin

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Assets estáticos

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Como funciona

1. **Middleware do servidor**: Um middleware do Nitro roda primeiro para verificar padrões de exclusão
2. **Processamento de página**: Durante a resolução de página, caminhos excluídos são ignorados
3. **Rota catch-all**: A rota de fallback verifica exclusões antes de processar
4. **Pré-renderização**: Caminhos excluídos não são incluídos nas rotas pré-renderizadas

## Impacto na performance

- Verificações de exclusão são otimizadas e executam cedo no ciclo de vida da requisição
- Padrões embutidos usam casamento por regex eficiente
- Padrões customizados são cacheados e reutilizados
- Overhead de performance mínimo para caminhos excluídos

## Solução de problemas

### Arquivos estáticos continuam sendo interceptados

1. **Verifique a sintaxe do padrão**: Garanta que seus padrões casem com a estrutura de caminho exata
2. **Use regex para padrões complexos**: Wildcards de string têm limitações
3. **Teste padrões**: Use as dev tools do navegador para verificar o caminho real da requisição
4. **Verifique a ordem**: Garanta que os padrões de exclusão sejam definidos antes de outras configurações de i18n

### Padrão não funciona

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Modo debug

Habilite o modo debug para ver o processamento de exclusão:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Isso registrará decisões de exclusão no console.

## Migrando de contornos

Se você estava usando contornos como route rules ou middleware, agora pode substituí-los por `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

A nova abordagem é mais confiável e funciona em múltiplos níveis do sistema de roteamento.
