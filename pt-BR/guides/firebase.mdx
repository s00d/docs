# 🔥 Deploy no Firebase AppHosting

## 📖 Introdução

O Firebase AppHosting é uma plataforma poderosa para fazer deploy de aplicações Nuxt com infraestrutura serverless. No entanto, ao fazer deploy de aplicações com `nuxt-i18n-micro`, você pode encontrar problemas específicos relacionados a como os arquivos JSON de tradução são servidos. Este guia oferece soluções abrangentes para garantir que suas traduções funcionem corretamente em produção.

## ⚠️ Problemas comuns

### Arquivos de tradução não são aplicados

**Sintomas:**

- ✅ As traduções funcionam perfeitamente em desenvolvimento (`nuxt dev`)
- ❌ Após o deploy no Firebase AppHosting, os arquivos JSON carregam, mas as traduções não são aplicadas
- ❌ Nenhum erro aparece no console
- ❌ Os arquivos de tradução são visíveis na aba Network, mas têm `Content-Type: text/html` em vez de `application/json`

**Causa raiz:**

O Firebase AppHosting (e outras plataformas usando prerender do Nitro) pode servir arquivos JSON pré-renderizados com MIME types incorretos. Quando o navegador recebe arquivos JSON com `Content-Type: text/html`, ele não consegue parseá-los corretamente, fazendo com que as traduções falhem silenciosamente.

## ✅ Soluções

### Solução 1: configuração de route rules (recomendada)

A solução mais direta é adicionar cabeçalhos explícitos para as rotas de tradução em seu `nuxt.config.ts`:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**Benefícios:**

- ✨ Configuração simples
- 🚀 Melhora o desempenho com cache adequado
- 🔒 Funciona em todas as plataformas de deploy

### Solução 2: URL base de API personalizada

Se você está usando um `apiBaseUrl` personalizado (apenas prefixo de path), ajuste as route rules de acordo:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### Solução 3: configuração específica do Firebase

Crie ou atualize seu arquivo `firebase.json` na raiz do projeto:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```


### Solução 4: configuração de Firebase Functions

Para deploy em Firebase Functions, garanta que seu `functions/package.json` inclua as dependências necessárias:

```json
{
  "name": "functions",
  "type": "module",
  "engines": {
    "node": "18"
  },
  "dependencies": {
    "firebase-admin": "^12.0.0",
    "firebase-functions": "^5.0.0"
  }
}
```

## 🔍 Depuração

### Habilitar modo debug

Adicione logging de debug para identificar problemas:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

Isso emitirá logs detalhados sobre:

- 📝 Carregamento de arquivos de tradução
- 🔄 Operações de cache
- ⚠️ Erros de carregamento

### Verifique a aba Network

1. Abra as DevTools → aba Network
2. Filtre por "data.json"
3. Clique em uma requisição de arquivo de tradução
4. Verifique os **Response Headers**:
   - ✅ `Content-Type: application/json` (correto)
   - ❌ `Content-Type: text/html` (incorreto. Precisa de correção)

### Verifique a saída do prerender

Após o build, verifique se os arquivos de tradução foram gerados:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

Você deve ver `data.json` para cada locale sob cada página.

## 🚀 Configuração de build

### Preset do Nitro

Para o Firebase AppHosting, garanta que você esteja usando o preset correto:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### Configuração de prerender

Configure o prerender para desempenho ideal:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

## 📋 Exemplo completo de configuração

Aqui está uma configuração completa funcionando para o Firebase AppHosting:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'es', iso: 'es-ES', dir: 'ltr' },
      { code: 'it', iso: 'it-IT', dir: 'ltr' },
      { code: 'pt', iso: 'pt-PT', dir: 'ltr' },
      { code: 'ru', iso: 'ru-RU', dir: 'ltr' },
      { code: 'zh', iso: 'zh-CN', dir: 'ltr' },
      { code: 'ko', iso: 'ko-KR', dir: 'ltr' },
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
    debug: false, // Enable in development if needed
  },

  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',

  },

  nitro: {
    preset: 'firebase-app-hosting',
    prerender: {
      crawlLinks: true,
      routes: ['/'],
    },
  },
})
```

## ✅ Checklist de verificação

Após aplicar as correções, verifique se tudo funciona:

- [ ] O build completa sem erros
- [ ] Os arquivos JSON de tradução estão em `.output/public/_locales/\{page\}/\{locale\}/data.json`
- [ ] A aba Network mostra `Content-Type: application/json` para arquivos de tradução
- [ ] Traduções aparecem corretamente no primeiro load de página
- [ ] Sem divergências de hidratação no console
- [ ] A troca de idioma funciona corretamente
- [ ] Meta tags de SEO são geradas corretamente

## 🔄 Fluxo de deploy

### 1. Prepare o build

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. Faça deploy no Firebase

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. Verifique o deploy

1. Visite seu site deployado
2. Abra DevTools → aba Network
3. Navegue para uma página
4. Verifique que `/_locales/index/en/data.json` (ou seu locale padrão) carrega com:
   - Status: 200
   - Content-Type: application/json
   - Response contém JSON válido

## 🔧 Resolução de problemas

### Problema: erros 404 para arquivos de tradução

**Solução:** garanta que os arquivos de tradução estão sendo copiados para o diretório de saída:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### Problema: traduções funcionam em algumas páginas mas não em outras

**Solução:** verifique se traduções específicas de página estão sendo geradas:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

Se traduções específicas de página estiverem faltando, garanta que `disablePageLocales` não está definido como `true`:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### Problema: carregamento lento de traduções

**Solução:** otimize o cache e o preload:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## ⚡ Otimização de desempenho

### Habilitar compressão

O Firebase lida automaticamente com compressão Gzip/Brotli, mas garanta que seu build está otimizado:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### Lazy load de traduções

O `Nuxt I18n Micro` faz lazy-load das traduções automaticamente por página. As traduções só são carregadas quando necessárias, reduzindo o tamanho inicial do bundle. Isso é funcionalidade integrada. Nenhuma configuração adicional é necessária.

Para otimizar ainda mais:

- Use `disablePageLocales: false` (padrão) para habilitar traduções específicas de página
- Mantenha traduções em nível raiz minimalistas
- Use arquivos de tradução específicos de rota para conteúdo de página

<Tip>
O módulo define automaticamente cabeçalhos `Content-Type` adequados a partir da versão **v3.0.0+**. Se você está enfrentando problemas, atualize para a última versão:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
