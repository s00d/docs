# 🔧 Detecção de idioma personalizada no Nuxt I18n Micro

## 📖 Visão geral

O Nuxt I18n Micro v3 oferece um composable centralizado — `useI18nLocale()` — para todo o gerenciamento de locale. Isso substitui os padrões manuais com `useState`/`useCookie` da v2. Ao usar `useI18nLocale().setLocale()` em um plugin de servidor, você pode implementar qualquer lógica de detecção customizada mantendo compatibilidade total com os sistemas de redirecionamento e cookie do módulo.

## 🏗️ Arquitetura

```mermaid

```

**Princípio-chave**: Chame `useI18nLocale().setLocale()` em um plugin de servidor com `order: -10`. Isso atualiza tanto `useState('i18n-locale')` quanto o cookie de locale atomicamente, para que o plugin de i18n (`order: -5`) e o plugin de redirect no servidor (`order: 10`) vejam o locale correto já na primeira requisição de SSR. Redirecionamentos automáticos no lado do cliente rodam no middleware de rota global nas navegações subsequentes.

## 🛠️ Desabilitando a detecção automática embutida

Se você quer controle total sobre a detecção de locale, desabilite o mecanismo embutido:

```ts
export default defineNuxtConfig({
  i18n: {
    autoDetectLanguage: false,
  },
})
```

## ✨ Exemplo: detecção no servidor com `useI18nLocale`

Esta é a **abordagem recomendada** para todas as estratégias.

### Passo 1: configure `nuxt.config.ts`

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    strategy: 'no_prefix', // Works with ANY strategy
    defaultLocale: 'en',
    localeCookie: 'user-locale',
    autoDetectLanguage: false,
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'ja', iso: 'ja-JP' },
    ],
  },
})
```

### Passo 2: crie `plugins/i18n-loader.server.ts`

```ts
import { defineNuxtPlugin, useRequestHeaders } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10, // Execute BEFORE the i18n plugin (which has order -5)

  setup() {
    const { setLocale } = useI18nLocale()
    const headers = useRequestHeaders(['host', 'x-country', 'accept-language'])
    let detectedLocale = 'en'

    // --- YOUR DETECTION LOGIC ---

    // Example 1: By domain
    const host = headers['host']
    if (host?.includes('example.de')) {
      detectedLocale = 'de'
    }
    // Example 2: By custom header
    else if (headers['x-country'] === 'JP') {
      detectedLocale = 'ja'
    }
    // Example 3: By Accept-Language header
    else if (headers['accept-language']?.includes('de')) {
      detectedLocale = 'de'
    }

    // --- APPLY THE LOCALE ---
    setLocale(detectedLocale)
  },
})
```

### Como funciona

```mermaid
flowchart TB
    subgraph Request["1. Server Request"]
        A[Receive request] --> B[Read headers]
        B --> C["x-country"]
        B --> D["accept-language"]
        B --> E["host"]
    end

    subgraph Detect["2. Locale Detection"]
        C --> F{Country match?}
        E --> G{Domain match?}
        D --> H{Language match?}
        F -->|Yes| I[Use detected locale]
        G -->|Yes| I
        H -->|Yes| I
        F & G & H -->|No match| J[Use defaultLocale]
    end

    subgraph Apply["3. Apply via useI18nLocale"]
        I --> K["setLocale(locale)"]
        J --> K
        K --> L["Updates useState + cookie"]
        L --> M["i18n plugin reads locale"]
        M --> N["Server redirect plugin uses locale"]
        M --> O["Client middleware on next navigation"]
    end
```

1. **O plugin roda primeiro** (`order: -10`) — detecta o locale a partir de headers, domínio ou outras fontes
2. **`setLocale()` atualiza ambos** `useState('i18n-locale')` e cookie — garante visibilidade imediata para todos os plugins subsequentes
3. **Plugin de i18n** (`order: -5`) lê o locale e carrega as traduções corretas
4. **Plugin de redirect no servidor** (`order: 10`) usa o locale para decisões de redirect no SSR
5. **Middleware de rota do cliente** (`i18n-redirect`) aplica redirecionamentos em navegação SPA quando o locale da URL não corresponde à preferência

## 🌐 Comportamento específico por strategy

`useI18nLocale().setLocale()` funciona com **todas as estratégias**. O comportamento de redirect depende da strategy:

<Tip>
| Strategy | Efeito de `setLocale('de')` |
|----------|---------------------------|
| `no_prefix` | Renderiza em alemão, sem mudança de URL |
| `prefix` | 302 → `/de/` (redirect no servidor) |
| `prefix_except_default` | 302 → `/de/` se `de` ≠ padrão; sem redirect se `de` = padrão |
| `prefix_and_default` | Sem redirect (ambos `/` e `/de/` são válidos) |
</Tip>

**Notas importantes:**

- A detecção de locale por cookie está desabilitada por padrão (`localeCookie: null`)
- Defina `localeCookie: 'user-locale'` para habilitar persistência via cookie
- Se o valor do cookie/state não estiver na lista `locales`, ele cai no `defaultLocale`

## 🏢 Avançado: detecção por domínio

Para setups multi-domínio em que cada domínio serve um locale diferente:

```ts
import { defineNuxtPlugin, useRequestHeaders } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-domain-loader',
  enforce: 'pre',
  order: -10,

  setup() {
    const { setLocale } = useI18nLocale()
    const headers = useRequestHeaders(['host'])
    const host = headers['host'] || ''

    let detectedLocale = 'en'

    if (host.endsWith('.de') || host.includes('german.')) {
      detectedLocale = 'de'
    } else if (host.endsWith('.fr') || host.includes('french.')) {
      detectedLocale = 'fr'
    } else if (host.endsWith('.jp') || host.includes('japanese.')) {
      detectedLocale = 'ja'
    }

    setLocale(detectedLocale)
  },
})
```

## 🔄 Avançado: respeitando a preferência do usuário

Se os usuários podem trocar de idioma manualmente, respeite a escolha deles em vez da detecção automática:

```ts
import { defineNuxtPlugin, useRequestHeaders } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-smart-loader',
  enforce: 'pre',
  order: -10,

  setup() {
    const { getLocale, setLocale } = useI18nLocale()

    // If user already has a preference (from cookie), respect it
    if (getLocale()) {
      return
    }

    // Otherwise, detect locale from headers
    const headers = useRequestHeaders(['accept-language'])
    let detectedLocale = 'en'

    const acceptLanguage = headers['accept-language'] || ''
    if (acceptLanguage.includes('de')) {
      detectedLocale = 'de'
    } else if (acceptLanguage.includes('ja')) {
      detectedLocale = 'ja'
    }

    setLocale(detectedLocale)
  },
})
```

## ⚙️ Plugins apenas de servidor ou apenas de cliente

Use [convenções de nome de arquivo do Nuxt](https://nuxt.com/docs/getting-started/directory-structure#plugins) para controlar onde seu plugin roda:

- **Apenas no servidor**: `i18n-loader.server.ts` — roda apenas durante SSR (recomendado para detecção baseada em headers)
- **Apenas no cliente**: `i18n-loader.client.ts` — roda apenas no navegador (para detecção via `localStorage` ou DOM)

## ✅ Resumo

| Recurso                                | Descrição                                                       |
| -------------------------------------- | ----------------------------------------------------------------- |
| `useI18nLocale().setLocale()`          | Atualiza `useState` + cookie atomicamente; funciona com todas as estratégias |
| `useI18nLocale().getLocale()`          | Retorna o locale atual do state ou cookie                       |
| `useI18nLocale().getPreferredLocale()` | Retorna o locale preferido (validado contra a lista `locales`)       |
| Plugin `order: -10`                    | Garante que seu plugin rode antes da inicialização do i18n               |
| `enforce: 'pre'`                       | Roda no grupo "pre" de plugins                                    |

**NÃO faça:**

- Usar `useCookie('user-locale')` diretamente — `useI18nLocale()` gerencia cookies internamente
- Usar `useState('i18n-locale')` diretamente — use `useI18nLocale().setLocale()`
- Definir `order` >= -5 — seu plugin deve rodar antes do plugin de i18n
