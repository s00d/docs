# Sobrescritas de i18n em runtime

Use este guia quando precisar que um único artefato de build seja executado com padrões de locale diferentes por ambiente (por exemplo: instâncias de tenants diferentes).

## O que pode ser sobrescrito em runtime

O módulo suporta sobrescritas seguras em runtime para:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Essas sobrescritas são aplicadas por cima da config em tempo de build de `.nuxt/i18n.strategy.mjs` e `.nuxt/i18n.config.mjs`.

## O que não pode ser sobrescrito em runtime

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) é uma preocupação de tempo de build porque afeta o comportamento das rotas geradas.

Se você passar uma sobrescrita de strategy em runtime, ela é ignorada e um aviso é emitido.

## Sobrescritas baseadas em RuntimeConfig

Forneça valores de runtime em `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Sobrescritas via variáveis de ambiente

Você também pode configurar sobrescritas via variáveis de ambiente:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (separado por vírgulas, ex.: `fr,it`)

Aliases de fallback também são suportados:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Regras de validação

Em runtime, o módulo valida as sobrescritas para evitar estados quebrados:

- Você não pode desabilitar todos os locales.
- `defaultLocale` deve apontar para um locale habilitado.
- `fallbackLocale` deve existir nos locales declarados.

Se uma sobrescrita for inválida, o módulo mantém um valor seguro e registra um aviso.

## Notas para deploys multi-instância

Este recurso de runtime foi projetado para ativação de locale por instância e padrões sem rebuild.

Se as instâncias exigem estratégias de URL diferentes (`no_prefix` vs `prefix`), use builds separados para cada estratégia.

## Locales desabilitados e payloads estáticos

`runtimeConfig.public.i18nRuntime.disabledLocales` atualiza roteamento, switcher e o **handler** de payload do Nitro, mas o Nitro serve arquivos sob `public/` **antes** desse handler.

Se `translationPayloads.publicAssets` (ou a cópia pública forçada do SSR no Node) já escreveu `/_locales/\{page\}/\{locale\}/data.json`, uma desabilitação em runtime não pode ocultar esse arquivo. Prefira `locale.disabled: true` em build para que o premerge não emita os payloads estáticos daquele locale.
