`@i18n-micro/solid` antaa SolidJS-sovelluksille signaaleihin perustuvan i18n-instanssin, providerin, `useI18n()`-funktion ja neljä komponenttia. Käytä sitä Solid-sovelluksessa, jota ei ole rakennettu Nuxtilla. `t()`-luvut JSX:n tai efektien sisällä seuraavat lokaalia, reittiä ja sanakirjoja; yhteinen malli on kuvattu sivulla [Kehykset](/fi/integrations/overview).

## Asennus {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer-riippuvuudet: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (valinnainen, vain `@i18n-micro/solid/router`-polkua varten). Solid 2:ta ei vielä tueta.

## Käyttöönotto {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` ottaa propsit `i18n`, `locales`, `defaultLocale` ja `routingStrategy`; pois jätetty prop säilyttää ulomman providerin arvon, instanssi mukaan lukien. `getLocaleName()` ja `<I18nSwitcher>` lukevat `locales`-arvoa; ilman sitä niillä ei ole mitään listattavaa. Asetukset ovat kohdassa [instanssi](/fi/integrations/overview#the-instance). Instanssi on [runtimen](/fi/integrations/runtime-package) instanssi, jonka storen päällä on yksi signaali.

## Kääntäminen {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Kutsu metodeja JSX:n tai efektin sisällä, jotta Solid seuraa niitä, myös `localePath` ja `getLocale`; komponentin rungossa kerran luettu arvo ei päivity. Instanssissa seuraa arvoja `i18n.locale` ja `i18n.currentRoute`: `i18n.getLocale()` pysyy tavallisena, koska kirjoitukset lukevat sitä. Lokaalin lukeminen herää vain lokaalin muuttuessa, joten efekti, joka lukee sen ja lataa sanakirjan, suoritetaan kerran. Älä destrukturoi propseja äläkä säilytä `t('key')`-tuloksia tavallisissa muuttujissa.

`useI18n()` palauttaa `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` ja `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Lokaalin vaihtaminen {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Vaihtaminen ei lataa mitään; lisää lokaalin sanakirja ensin.

`<I18nGroup>` välittää etuliitteellisen `t`-funktion funktiolapselle. Sen sisällä `<I18nT>` ja `t()` eivät saa etuliitettä:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Reititys {#routing}

`@solidjs/router`-adapteri on alipolussa, jotta pääsisääntulo ei koskaan tuo reititintä. Kutsu sitä reitittimen alla, tyypillisesti reitittimen `root`-komponentissa, jossa `useNavigate` ja `useLocation` toimivat:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

Adapteri lisää etuliitteen jokaiselle lokaalille paitsi oletukselle (`/about`, `/de/about`) ja renderöi `<I18nLink>`-komponentin reitittimen `<A>`-komponenttina. `getCurrentPath` lukee reitittimen reaktiivista sijaintia, joten aktiiviset linkit ja kielenvaihdin seuraavat sitä; mukautettu strategia saa saman lukemalla siellä signaalia. Huomaa argumenttien järjestys: `(locales, defaultLocale, navigate, location)`. Muille reitittimille kirjoita adapteri, jossa on `getCurrentPath`, `push` ja `replace` (kaikki pakollisia) — katso [Reititinadapteri](/fi/integrations/overview#router-adapter).

## SSR {#ssr}

Palvelinrenderöintiä varten käännä `vite-plugin-solid`-lisäosalla: paketin `solid`-vientiehto antaa sille lähdekoodin, joten se kääntyy palvelimelle. Valmiiksi käännetty `dist` on vain selaimelle. Instanssilla ei ole `destroy()`-metodia; luo yksi sovellusta kohden tai palvelimella yksi pyyntöä kohden ja anna roskienkerääjän hoitaa se.
