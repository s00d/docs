`@i18n-micro/react` ja `@i18n-micro/preact` käärivät kehysriippumattoman [runtimen](/fi/integrations/runtime-package) provideriin, `useI18n()`-hookiin ja neljään komponenttiin. Käytä niitä React- tai Preact-sovelluksessa, jota ei ole rakennettu Nuxtilla. Molemmilla paketeilla on sama API; [Preact](#preact)-osio luettelee muutamat erot, ja yhteinen malli on kuvattu sivulla [Kehykset](/fi/integrations/overview).

## Asennus {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/react
```

```bash npm
npm install @i18n-micro/react
```

```bash yarn
yarn add @i18n-micro/react
```

</CodeGroup>

Peer-riippuvuudet: `react` `^18.0.0 || ^19.0.0`; `react-dom` (valinnainen, renderöintiin); `react-router-dom` `^6.0.0 || ^7.0.0` (valinnainen, vain `@i18n-micro/react/router`-polkua varten). Testattu Reactin versioilla 19.3 ja 18.3 sekä React Routerin versioilla 7.18 ja 6.30.

## Käyttöönotto {#setup}

```tsx
// src/main.tsx
import { createRoot } from 'react-dom/client'
import { createI18n, I18nProvider } from '@i18n-micro/react'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

createRoot(document.getElementById('root')!).render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
    <App />
  </I18nProvider>,
)
```

<Warning>

Luo instanssi kerran, moduulitasolla tai `useState`-alustajassa, ei koskaan komponentin rungossa.

</Warning>

`<I18nProvider>` ottaa propsit `i18n`, `locales`, `defaultLocale` ja `routingStrategy`:

- Pois jätetty prop säilyttää ulomman providerin arvon, instanssi mukaan lukien.
- Jos instanssia ei ole lainkaan, se rakentaa sellaisen vieressä olevista `createI18n`-asetuksista, joten propsit pysyvät tavallisena datana: `<I18nProvider locale="de" messages={messages}>`.
- Uusi `locale`-prop rakentaa uuden instanssin kyseisen renderöinnin `messages`-arvoilla. Tällainen instanssi elää komponentissa: jos jokin sen yläpuolella keskeyttää (suspend) mountin aikana, React heittää sen pois kaikkineen, mitä siihen on lisätty.

Kaikki `createI18n`-asetukset, `routeMessages` mukaan lukien, ovat kohdassa [instanssi](/fi/integrations/overview#the-instance).

## Kääntäminen {#translate}

```tsx
import { useI18n } from '@i18n-micro/react'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' })}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

`useI18n()` palauttaa:

| Ryhmä | Jäsenet |
| --- | --- |
| Kääntäminen | `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` |
| Lokaali ja reitti | `locale`, `fallbackLocale`, `currentRoute`, `setLocale`, `setRoute`, `getRoute`, `getLocales`, `defaultLocale()`, `getLocaleName` |
| Reititys | `switchLocale`, `localePath`, `localeRoute` |
| Sanakirjat | `addTranslations`, `addRouteTranslations`, `clearCache` |

- Komponentti renderöityy uudelleen, kun lokaali, reitti tai luettava sanakirja muuttuu, sekä kun provider saa uuden `locales`- tai `routingStrategy`-objektin. Lokaalin sanakirja, joka ei ole aktiivinen eikä varalokaali, ei renderöi mitään.
- `t` ja muut käännösmetodit muuttuvat vain storen mukana, joten ne ovat turvallisia `memo`- ja efektiriippuvuuksissa.

`useT` on yksi merkkijono arvona. Komponentti renderöityy vain, kun tuo merkkijono muuttuu, tapahtuipa providerin muille propseille mitä tahansa; myöskään `<I18nT>` ei riipu niistä:

```tsx
const title = useT('page.title')
```

Lataa lisää sanakirjoja milloin tahansa:

```tsx
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

useEffect(() => {
  import('./locales/de.json').then((m) => addTranslations('de', m.default))
  addRouteTranslations('en', 'about', { title: 'About us' })
  setRoute('about') // t('title') now reads the 'about' dictionary first
}, [])
```

Instanssilla itsellään on myös `loadFromUrl(url, { locale, routeName })` JSONin hakemiseen `fetch`-kutsulla.

## Lokaalin vaihtaminen {#switch-locale}

```tsx
const { setLocale, switchLocale } = useI18n()

setLocale('de') // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Vaihtaminen ei lataa mitään; lisää lokaalin sanakirja ensin. Storeen kirjoittaminen on Reactille synkroninen, myös `startTransition`-kutsun sisällä, joten puuttuvaan sanakirjaan keskeyttävä komponentti näyttäisi varasisältönsä. `useLocaleSwitch` lataa ensin ja pitää vanhan käyttöliittymän, kunnes sanakirja on ladattu:

```tsx
const [switchTo, pending] = useLocaleSwitch((locale) => i18n.loadFromUrl(`/locales/${locale}.json`, { locale }))

<button disabled={pending} onClick={() => switchTo('de')}>Deutsch</button>
```

Viimeinen kutsu voittaa. Epäonnistunut lataus hylätään (reject), ja lokaali jää ennalleen.

`<I18nGroup>` välittää etuliitteellisen `t`-funktion render-prop-lapselle. Sen sisällä `<I18nT>` ja `t()` eivät saa etuliitettä:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Reititys {#routing}

React Router -adapteri on alipolussa, jotta pääsisääntulo ei koskaan tuo `react-router-dom`-pakettia. Se tarvitsee `useLocation()`- ja `useNavigate()`-funktiot, joten luo se reitittimen alla olevassa komponentissa:

```tsx
// src/App.tsx
import { useMemo } from 'react'
import { BrowserRouter, Route, Routes, useLocation, useNavigate } from 'react-router-dom'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/react'
import { createReactRouterAdapter } from '@i18n-micro/react/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Localized() {
  const location = useLocation()
  const navigate = useNavigate()
  // memoized: a new object on every render re-renders every `useI18n()` consumer
  const routingStrategy = useMemo(() => createReactRouterAdapter(locales, 'en', location, navigate), [location, navigate])
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      <Routes>
        <Route path="/:locale?" element={<Home />} />
        <Route path="/:locale?/about" element={<About />} />
      </Routes>
    </I18nProvider>
  )
}

export default function App() {
  return (
    <BrowserRouter>
      <Localized />
    </BrowserRouter>
  )
}
```

Adapteri lisää etuliitteen jokaiselle lokaalille paitsi oletukselle (`/about`, `/de/about`) ja renderöi `<I18nLink>`-komponentin React Routerin `<Link>`-komponenttina. Aseta lokaali URL-osoitteesta itse (esimerkiksi `useParams().locale`-arvosta efektissä). Mille tahansa muulle reitittimelle kirjoita adapteri, jossa on `getCurrentPath`, `push` ja `replace` (kaikki pakollisia) — katso [Reititinadapteri](/fi/integrations/overview#router-adapter).

## SSR {#ssr}

`renderToString` toimii: `useI18n()`-funktiolla on palvelinsnapshot. Luo yksi instanssi pyyntöä kohden ja lisää sen sanakirjat ennen renderöintiä, jotta eri lokaalien pyynnöt eivät jaa tilaa, tai välitä providerille tavallista dataa.

### Hydraatio {#hydration}

Luvut, monikot ja teksti hydratoituvat sellaisinaan. Päivämäärä riippuu aikavyöhykkeestä ja suhteellinen päivämäärä kellosta: aseta `timeZone` palvelimella ja selaimessa, ja `tdr`:lle anna selaimelle palvelimen aika `now`-arvolla. `<I18nT>` `date`- tai `relativeDate`-propin kanssa asettaa `suppressHydrationWarning`-arvon, joten ero ei kaada hydraatiota, mutta palvelimen teksti pysyy, kunnes teksti muuttuu. Tämä ulottuu vain yhdelle tasolle: `children`, jotka käärivät käännöksen elementtiin, epäonnistuvat silti erossa, joten anna niille sama `timeZone`.

### Server Components {#server-components}

Paketti merkitsee asiakaskoodinsa `'use client'`-direktiivillä. `@i18n-micro/react/server` sisältää `createI18n`-funktion ja hookittoman `I18nT`-komponentin, joka ottaa instanssin propina, joten teksti pysyy poissa asiakasbundlesta. `react-server`-ehdolla, kuten Next.js:n app routerissa, myös pääsisääntulo ratkeaa siihen, mutta TypeScript ei oletuksena tiedä sitä: tuo polusta `/server`. `@i18n-micro/react/client` antaa aina asiakassisääntulon.

```tsx
// app/[locale]/layout.tsx: a server component
import { cache } from 'react'
import { createI18n, I18nT } from '@i18n-micro/react/server'
import { I18nProvider } from '@i18n-micro/react/client'
import { loadMessages } from './messages'

const getI18n = cache(async (locale: string) => createI18n({ locale, messages: await loadMessages(locale) }))

export default async function Layout({ params, children }) {
  const { locale } = await params
  const i18n = await getI18n(locale)
  return (
    <I18nProvider locale={locale} messages={{ [locale]: i18n.resolveTranslations() }}>
      <h1>
        <I18nT i18n={i18n} keypath="title" />
      </h1>
      {children}
    </I18nProvider>
  )
}
```

Renderöity `react-server-dom-webpack`-paketin kautta; varsinaista Next.js-sovellusta ei ole ajettu tätä vasten.

## Preact {#preact}

`@i18n-micro/preact` rakennetaan samasta lähdekoodista Preactin päälle ilman `preact/compat`-kerrosta: sama instanssi, provider, hookit ja komponentit. Erot:

| | React | Preact |
| --- | --- | --- |
| Peer-riippuvuus | `react` (+ valinnainen `react-router-dom`) | `preact` `^10.0.0 \|\| ^11.0.0`, testattu versioilla 10.29 ja 11.1 |
| Instanssiluokka | `ReactI18n` | `PreactI18n` |
| Reititinadapteri | `createReactRouterAdapter` polusta `/router` | `createBrowserHistoryAdapter(locales, defaultLocale, ssrUrl?)` polusta `/router` |
| Uudelleenrenderöinti | `useSyncExternalStore` | layout-efektitilaus, joka tarkistaa storen uudelleen |
| Server Components | `/server`, `/client` | ei ole |

`createBrowserHistoryAdapter` toimii minkä tahansa History API -reitittimen kanssa (wouter, preact-router): `push` ja `replace` kutsuvat `history.pushState` / `replaceState` ja lähettävät `popstate`-tapahtuman, ja `<I18nLink>` renderöi tavallisen `<a>`-elementin, joka navigoi `push`-kutsun kautta. Palvelimella ei ole osoiteriviä: välitä pyynnön URL `ssrUrl`-arvona, muuten linkit ja kielenvaihdin renderöityvät kuin polulla `/`. Selaimessa osoiterivi voittaa.

```tsx
// src/main.tsx
import { render } from 'preact'
import { createI18n, I18nProvider } from '@i18n-micro/preact'
import { createBrowserHistoryAdapter } from '@i18n-micro/preact/router'
import { App } from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={createBrowserHistoryAdapter(locales, 'en')}>
    <App />
  </I18nProvider>,
  document.getElementById('app')!,
)
```

Täydet signatuurit: [Preact-viite](/fi/api/packages/preact).
