# 🔥 Firebase AppHosting -käyttöönotto

## 📖 Johdanto

Firebase AppHosting on tehokas alusta Nuxt-sovellusten käyttöönottoon serverless-infrastruktuurilla. Kuitenkin `nuxt-i18n-micro`-moduulia käyttäviä sovelluksia käyttöönotettaessa saattaa esiintyä erityisiä ongelmia, jotka liittyvät siihen, miten käännös-JSON-tiedostoja tarjoillaan. Tämä opas tarjoaa kattavat ratkaisut sen varmistamiseksi, että käännöksesi toimivat oikein tuotannossa.

## ⚠️ Yleiset ongelmat

### Käännöstiedostoja ei sovelleta

**Oireet:**

- ✅ Käännökset toimivat täydellisesti kehityksessä (`nuxt dev`)
- ❌ Käyttöönoton jälkeen Firebase AppHostingissa JSON-tiedostot latautuvat, mutta käännöksiä ei sovelleta
- ❌ Konsolissa ei näy virheitä
- ❌ Käännöstiedostot näkyvät Network-välilehdellä, mutta niillä on virheellinen `Content-Type: text/html` oikean `application/json`-arvon sijaan

**Perussyy:**

Firebase AppHosting (ja muut Nitro-esirenderöintiä käyttävät alustat) voivat tarjoilla esirenderöityjä JSON-tiedostoja virheellisillä MIME-tyypeillä. Kun selain vastaanottaa JSON-tiedostot arvolla `Content-Type: text/html`, se ei voi jäsentää niitä oikein, jolloin käännökset epäonnistuvat hiljaisesti.

## ✅ Ratkaisut

### Ratkaisu 1: Reittisääntöjen konfiguraatio (suositeltu)

Yksinkertaisin ratkaisu on lisätä eksplisiittiset otsakkeet käännösreiteille tiedostoosi `nuxt.config.ts`:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**Hyödyt:**

- ✨ Yksinkertainen konfiguraatio
- 🚀 Parantaa suorituskykyä asianmukaisella välimuistituksella
- 🔒 Toimii kaikilla käyttöönottoalustoilla

### Ratkaisu 2: Mukautettu API-base-URL

Jos käytät mukautettua `apiBaseUrl`-asetusta (vain polkuprefiksi), säädä reittisääntöjä sen mukaisesti:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### Ratkaisu 3: Firebase-kohtainen konfiguraatio

Luo tai päivitä `firebase.json`-tiedostosi projektin juuressa:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```

### Ratkaisu 4: Firebase Functions -konfiguraatio

Firebase Functions -käyttöönottoa varten varmista, että `functions/package.json` sisältää tarvittavat riippuvuudet:

## 🔍 Vianmääritys

### Ota debug-tila käyttöön

Lisää debug-lokitus ongelmien tunnistamiseksi:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

Tämä tulostaa yksityiskohtaiset lokit seuraavista:

- 📝 Käännöstiedostojen lataus
- 🔄 Välimuistioperaatiot
- ⚠️ Latausvirheet

### Tarkista Network-välilehti

1. Avaa DevTools → Network-välilehti
2. Suodata "data.json" -kyselyllä
3. Klikkaa käännöstiedoston pyyntöä
4. Varmista **vastauksen otsakkeet**:
   - ✅ `Content-Type: application/json` (oikea)
   - ❌ `Content-Type: text/html` (virheellinen — tarvitsee korjauksen)

### Varmista esirenderöinnin tuotos

Kun olet buildannut, tarkista että käännöstiedostot on generoitu:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

Sinun pitäisi nähdä `data.json`-tiedosto jokaiselle kielelle jokaisen sivun alla.

## 🚀 Build-konfiguraatio

### Nitro-preset

Firebase AppHostingia varten varmista, että käytät oikeaa presettiä:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### Esirenderöintikonfiguraatio

Määritä esirenderöinti optimaalista suorituskykyä varten:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

Tässä on täydellinen toimiva konfiguraatio Firebase AppHostingille:

      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'es', iso: 'es-ES', dir: 'ltr' },

      { code: 'pt', iso: 'pt-PT', dir: 'ltr' },
      { code: 'ru', iso: 'ru-RU', dir: 'ltr' },
      { code: 'zh', iso: 'zh-CN', dir: 'ltr' },
      { code: 'ko', iso: 'ko-KR', dir: 'ltr' },
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
    debug: false, // Enable in development if needed
  },

  routeRules: {
    '/_locales/**': {

        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',

    preset: 'firebase-app-hosting',
    prerender: {
      crawlLinks: true,
      routes: ['/'],
    },
  },
})

## ✅ Vahvistuslista

Kun olet soveltanut korjaukset, varmista että kaikki toimii:

- [ ] Build valmistuu ilman virheitä
- [ ] Käännös-JSON-tiedostot ovat polussa `.output/public/_locales/\{page\}/\{locale\}/data.json`
- [ ] Network-välilehti näyttää `Content-Type: application/json`-arvon käännöstiedostoille
- [ ] Käännökset näkyvät oikein ensimmäisellä sivun latauksella
- [ ] Konsolissa ei ole hydraatioristiriitoja
- [ ] Kielen vaihtaminen toimii oikein
- [ ] SEO-metatagit generoidaan asianmukaisesti

## 🔄 Käyttöönoton työnkulku

### 1. Valmistele build

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. Ota käyttöön Firebasessa

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. Varmista käyttöönotto

1. Vieraile käyttöönotetulla sivustollasi
2. Avaa DevTools → Network-välilehti
3. Navigoi sivulle
4. Tarkista, että `/_locales/index/en/data.json` (tai oletuskielesi vastine) latautuu seuraavilla:
   - Status: 200
   - Content-Type: application/json
   - Vastaus sisältää validia JSON:ia

## 🔧 Vianmääritys

### Ongelma: 404-virheet käännöstiedostoille

**Ratkaisu:** Varmista, että käännöstiedostot kopioidaan tuotoshakemistoon:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### Ongelma: Käännökset toimivat joillakin sivuilla mutta eivät muilla

**Ratkaisu:** Tarkista, generoidaanko sivukohtaiset käännökset:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

Jos sivukohtaiset käännökset puuttuvat, varmista että `disablePageLocales`-asetus ei ole `true`:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### Ongelma: Käännösten hidas lataus

**Ratkaisu:** Optimoi välimuistitus ja esilataus:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## ⚡ Suorituskyvyn optimointi

### Ota pakkaus käyttöön

Firebase käsittelee automaattisesti Gzip/Brotli-pakkauksen, mutta varmista että buildisi on optimoitu:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### Laiskasti ladatut käännökset

`Nuxt I18n Micro` lataa käännökset automaattisesti laiskasti sivukohtaisesti. Käännökset ladataan vain tarvittaessa, mikä pienentää alkuperäistä bundle-kokoa. Tämä on sisäänrakennettu toiminnallisuus - lisäasetuksia ei tarvita.

Optimoinnin tehostamiseksi:

- Käytä `disablePageLocales: false` (oletus) ottaaksesi sivukohtaiset käännökset käyttöön
- Pidä juuritason käännökset minimaalisina
- Käytä reittikohtaisia käännöstiedostoja sivun sisältöön

<Tip>
Moduuli asettaa asianmukaiset `Content-Type`-otsakkeet automaattisesti alkaen versiosta **v3.0.0+**. Jos kohtaat ongelmia, päivitä uusimpaan versioon:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
