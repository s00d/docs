Nuxt-kerros voi kuljettaa i18n-konfiguraation ja `locales/`-kansion useille sovelluksille, ja jokainen sovellus lisää tai ohittaa tarvitsemansa. Tämä sivu näyttää, miten se tehdään ja miten yksi build palvelee useita verkkotunnuksia.

## Konfiguraation ja käännösten jakaminen {#share-config-and-translations}

```ts
// base/nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    defaultLocale: 'en',
  },
})
```

```ts
// shop/nuxt.config.ts
export default defineNuxtConfig({
  extends: ['../base'], // a layer directory or package, not a nuxt.config file
  i18n: {
    locales: [
      { code: 'es', iso: 'es-ES' }, // added
      { code: 'fr', disabled: true }, // the base layer's fr, switched off here
    ],
  },
})
```

- **Konfiguraatio:** sovelluksen skalaariasetukset korvaavat kerroksen asetukset. Kaikkien kerrosten `locales`-taulukot yhdistetään, ja saman `code`-arvon merkinnät yhdistyvät yhdeksi sovelluksen kenttien voittaessa, joten sovellus voi lisätä lokaalin tai asettaa perityille lokaaleille kenttiä, kuten `disabled: true`.
- **Käännökset:** jokaisen kerroksen `locales/` yhdistetään avain kerrallaan, kerros ensin ja sovellus viimeisenä, joten avain tiedostossa `shop/locales/en.json` ohittaa saman avaimen tiedostossa `base/locales/en.json`. Sivutiedostot (`locales/pages/<page>/`) yhdistyvät samalla tavalla.
- **Sivut:** `$defineI18nRoute` luetaan jokaisen kerroksen sivuilta.

Yhdistääksesi kansioita, jotka eivät kuulu kerrokseen, listaa ne asetuksessa [`additionalTranslationDirs`](/fi/api/module-options#additionaltranslationdirs).

## Useat verkkotunnukset {#multiple-domains}

Yksi build palvelee kaikkia verkkotunnuksia. Listaa jokainen lokaali verkkotunnuksineen; `baseDefault` tekee siitä kyseisen isännän oletuksen:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'de', iso: 'de-DE', baseUrl: 'https://example.de', baseDefault: true },
      { code: 'nl', iso: 'nl-NL', baseUrl: 'https://example.de' },
      { code: 'fr', iso: 'fr-FR' },
    ],
  },
})
```

Osoita molemmat verkkotunnukset samaan palvelimeen. Pyynnön isäntä ratkaisee loput:

- **Oletus:** isännän `baseDefault`-lokaali. Jos sellaista ei ole, buildin oletus, jos isäntä tarjoilee sen, muuten isännän ensimmäinen lokaali.
- **Tarjoillut lokaalit:** kyseisen isännän lokaalit sekä jokainen lokaali ilman `baseUrl`-arvoa. Isännällä `example.de` ne ovat `de`, `nl` ja `fr`.
- **Muiden verkkotunnusten lokaalit** ovat linkkikohteita. `$localePath`, `$localeRoute`, `$switchLocalePath`, `<i18n-switcher>` ja `hreflang` antavat absoluuttiset URL-osoitteet niiden `baseUrl`-osoitteeseen, ja `$switchLocale` navigoi sinne. Tällä isännällä niiden URL-osoitteet palauttavat 404, eikä eväste tai `Accept-Language` voi valita niitä.
- **Linkki toiseen verkkotunnukseen** kulkee `$localePath`- tai `<i18n-link>`-kautta: `<NuxtLink :to="$localePath('/contact', 'de')">`, `<i18n-link :to="$localeRoute('/contact', 'de')">`. Reititin ei ota absoluuttista objektia, joten `<NuxtLink :to="$localeRoute(...)">` ja `router.push($localeRoute(...))` pysyvät tässä originissa. `localhost`-isännällä tai esikatseluisännällä jokainen `baseUrl`-lokaali on tällainen linkki, myös nykyinen. Koodissa käytä `navigateTo($localePath('/contact', 'de'), { external: true })` tai `$switchRoute`.
- **Mikä tahansa muu isäntä** saa buildin konfiguraation, ja jokainen `baseUrl`-lokaali on linkkikohde. Pyynnöstä ei toisteta mitään: canonical ja `hreflang` käyttävät `metaBaseUrl`-arvoa, muuten buildin oletuksen `baseUrl`-arvoa (oletus ilman `baseUrl`-arvoa tarvitsee `metaBaseUrl`- tai `site.url`-arvon, katso [SEO](/fi/guide/seo#set-the-public-origin)).
- **Payload-tiedostot** `public/`-hakemistossa ovat staattisia: mikä tahansa isäntä palauttaa minkä tahansa lokaalin tiedoston. Verkkotunnuskohtainen [generate](/fi/guide/deployment#static-site-(nuxi-generate)) julkaisee vain kyseisen verkkotunnuksen tiedostot.

`example.de` kullakin strategialla, kun `de: '/kontakt'` on reitin `contact` mukautettu polku:

| Strategia | `/` | Oletuslokaalin sivu | Muut URL-osoitteet |
| --- | --- | --- | --- |
| `prefix_except_default` | `de` | `/kontakt` | `/de/kontakt` ja `/en/contact` palauttavat 404, `/contact` ohjaa osoitteeseen `/kontakt` |
| `prefix_and_default` | `de` | `/kontakt` ja `/de/kontakt`, linkit käyttävät `/kontakt` | `/en/contact` ja `/contact` palauttavat 404 |
| `prefix` | ohjaa osoitteeseen `/de` | `/de/kontakt` | `/kontakt` ohjaa osoitteeseen `/de/kontakt`, `/en/contact` palauttaa 404 |
| `no_prefix` | `de` | `/kontakt` | toisen verkkotunnuksen lokaalin mukautettu polku palauttaa 404 |

Strategialla `prefix` linkki toisesta verkkotunnuksesta säilyttää etuliitteen, koska etuliitteetön URL vain ohjaisi uudelleen. Strategialla `no_prefix` linkki toiseen verkkotunnukseen päätyy kyseisen isännän oletuslokaaliin: URL ei voi nimetä toista.

Hyvä tietää:

- **Välityspalvelimen takana** isäntä tulee `Host`-otsakkeesta. Jos välityspalvelin laittaa julkisen isännän sen sijaan `X-Forwarded-Host`-otsakkeeseen, aseta [`trustForwardedHost`](/fi/api/module-options#trustforwardedhost), ja vain jos välityspalvelin ylikirjoittaa kyseisen otsakkeen. Välityspalvelin, joka ei lähetä kumpaakaan, ei voi palvella verkkotunnusbuildia. Katso [Välityspalvelimen tai CDN:n takana](/fi/guide/deployment#behind-a-proxy-or-cdn).
- **`app.baseURL`** kuuluu myös `baseUrl`-arvoon: `baseUrl: 'https://example.de/shop'` yhdessä `app.baseURL: '/shop'` kanssa.
- **Isännät täsmätään tarkasti.** `www.example.de` on eri isäntä: ohjaa se uudelleen reunalla tai aseta se `baseUrl`-arvoksi lokaalille. Vain yksi isäntä lokaalia kohden.
- **Välimuistien on käytettävä isäntää avaimena.** CDN tekee sen yleensä. Nitron reittivälimuisti käyttää avaimena polkua, joten verkkotunnusbuildissa moduuli lisää `host`-arvon jokaisen `swr`- ja `cache`-säännön `cache.varies`-asetukseen sekä `x-forwarded-host`-arvon, kun `trustForwardedHost` on käytössä. Sääntö, jossa on `cache: false`, pysyy kirjoitetun mukaisena. `isr` on alustan välimuisti: tarkista, että se käyttää isäntää avaimena.
- **Kahden isännän oletusten mukautetut polut eivät saa törmätä.** Etuliitteettömät tietueet jakavat yhden reitittimen, joten `/x` ei voi olla yksi sivu isännällä `example.de` ja toinen isännällä `example.com`.
- **Esirenderöidyt sivut:** `prerender: true` -reittisääntö `nuxt build` -komennossa renderöi kerran ilman isäntää, ja tiedosto vastaa jokaiselle verkkotunnukselle. Jätä verkkotunnuksittain eroavat sivut palvelimelle tai [generoi verkkotunnuksittain](/fi/guide/deployment#static-site-(nuxi-generate)).
- **`noPrefixRedirect`** toimii isännän ja vierailijan lokaalin mukaan jokaisella isännällä.
- **`hashMode`:** isäntä valitsee renderöinnin kuten yllä, ja linkit toiseen verkkotunnukseen kuljettavat reitin hashissa (`https://example.com/#/contact`).
- **`ssr: false`:** selain lukee verkkotunnuksen `location.host`-arvosta, joten isäntä ilman palvelinta ratkeaa silti.
- **[Ajonaikaiset ohitukset](/fi/guide/runtime-overrides)** sovelletaan ensin. Ajonaikainen `disabledLocales` pätee jokaisella isännällä yhtä poikkeusta lukuun ottamatta: strategioilla `prefix_except_default` ja `prefix_and_default` isännän oletus pysyy käytössä omalla isännällään, koska sen sivut ovat etuliitteettömät tietueet. Strategioilla `prefix` ja `no_prefix` isäntä siirtyy seuraavaan tarjoilemaansa lokaaliin. Ajonaikainen `defaultLocale` koskee vain tuntemattomia isäntiä.

[Staattiselle sivustolle](/fi/guide/deployment#static-site-(nuxi-generate)) generoi kerran verkkotunnusta kohden.

### Yksi sovellus verkkotunnusta kohden {#one-app-per-domain}

Jaettu kerros ja yksi pieni sovellus verkkotunnusta kohden toimii edelleen, kun verkkotunnukset tarvitsevat eri sivuja tai moduuleja. Jokainen sovellus asettaa oman `defaultLocale`-arvonsa saman `locales`-luettelon päälle. Toisen verkkotunnuksen lokaali palauttaa kyseisessä sovelluksessa 404, kuten yllä.

### Lokaalin valitseminen koodissa {#choosing-the-locale-in-code}

Yksittäiselle instanssille, joka vastaa kaikille verkkotunnuksille pyynnön omalla originilla SEO-tageissa, katso [SEO](/fi/guide/seo#set-the-public-origin); lokaalin valitsemiseksi isännän perusteella koodissa katso [Mukautettu lokaalin tunnistus](/fi/guide/custom-auto-detect).
