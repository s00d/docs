`@i18n-micro/cli` hallitsee Nuxt-projektin lokaalitiedostoja. Se lukee `locales`-, `defaultLocale`- ja `translationDir`-asetukset sekä kerroksesi `nuxt.config`-tiedostosta, joten se ei tarvitse omaa konfiguraatiota.

![Pääte, jossa ajetaan i18n-micro check, joka listaa puuttuvan, määrittelemättömän ja neljä käyttämätöntä avainta ja epäonnistuu, sitten extract, joka lisää määrittelemättömän avaimen, ja sitten clean --dryRun, joka listaa neljä avainta, jotka se poistaisi](/images/cli/demo.gif)

| Komento | Käytä sitä |
| --- | --- |
| `check` | Kaatamaan build, jos lokaalitiedostoissa on jotain vialla |
| `translate` | Täyttämään puuttuvat avaimet käännöspalvelun avulla |
| `clean` | Poistamaan avaimet, joita mikään ei käytä |
| `rename` | Siirtämään avaimen tai kokonaisen nimiavaruuden kaikkialla kerralla |

```bash
npm install -D @i18n-micro/cli
npx i18n-micro --help
```

Aja se sovelluksen juuresta tai osoita siihen `--cwd`-lipulla. Jokaisen komennon jokainen lippu on [komentoviitteessä](/fi/api/cli).

<Tip>

**Siirrytkö nuxt-i18n-micro-cli:stä?** `@i18n-micro/cli` korvaa sen; binäärit `i18n-micro` ja `i18n-micro-cli` säilyvät. Katso [vanhojen komentojen taulukko](#moving-from-nuxt-i18n-micro-cli).

</Tip>

## Käyttö CI:ssä {#use-it-in-ci}

```bash
i18n-micro check
```

`check` on portinvartija. Se raportoi:

| Tarkistus | Merkitys |
| --- | --- |
| `missing` | Oletuslokaalin avain puuttuu lokaalista |
| `empty` | Arvo on `''`. Sovellus näyttää tyhjän, ei varakäännöstä |
| `extra` | Lokaalissa on avain, jota oletuslokaalissa ei ole |
| `placeholders` | `{name}` katosi tai lisättiin, tai monikko menetti muotonsa |
| `undefined` | Koodi käyttää avainta, jota oletuslokaalissa ei ole |
| `unused` | Mikään projektissa ei käytä avainta |
| `duplicates` | Sama teksti eri avaimilla. Oletuksena pois päältä: anna `--duplicates` |

- `--only missing,placeholders` ajaa osan tarkistuksista; `--only`-lipussa nimetty tarkistus, jota ei voitu ajaa, epäonnistuu.
- `--json` antaa raportin työkaluja varten.
- `--ignore` ohittaa lähdetiedostoja.
- Kun avaimia lasketaan ajonaikana, `unused` ohitetaan ja raportti kertoo syyn.

Jokainen komento päättyy yhdellä kolmesta koodista, joten putki erottaa käännösten ongelman työkalun ongelmasta:

| Paluukoodi | Merkitys |
| --- | --- |
| `0` | Ei raportoitavaa |
| `1` | Löydöksiä |
| `2` | Komentoa ei voitu ajaa: käyttövirhe, rikkinäinen tiedosto, epäonnistunut pyyntö |

Muita CI-vaiheen arvoisia komentoja:

```bash
i18n-micro format --check      # fails if a file is not formatted
i18n-micro lint                # stray spaces, empty values, your own regex rules
i18n-micro stats --baseRef main
```

## Lokaalien pitäminen tahdissa {#keep-locales-in-step}

| Komento | Mitä se tekee |
| --- | --- |
| `extract` | Listaa koodin käyttämät avaimet, joilla ei vielä ole tekstiä. Oletusteksti, kuten `$t('key', {}, 'Welcome')`, menee oletuslokaaliin. |
| `sync` | Poistaa avaimet, joita oletuslokaalissa ei ole. Kokeile ensin `--dryRun`. |
| `clean` | Poistaa avaimet, joita mikään ei käytä. Kokeile ensin `--dryRun`. |
| `search` | Etsii avaimia ja arvoja ja näyttää, missä kutakin avainta käytetään. |
| `stats` | Valmiusaste lokaaleittain; `--baseRef main` vertaa git-viitteeseen. |

`sync` pysähtyy kuten `clean`, kun se poistaisi avaimen, jonka käyttämättömyyttä se ei voi todistaa, sekä silloin, kun oletuslokaalissa ei ole mitään verrattavaa. Kun poistettavaa ei ole, se ei koskaan pysähdy, joten pelkkä `$t(item.label)` ei ole syy `--force`-lipulle.

<Note>

`extract` ja `sync` eivät koskaan kirjoita `''` avaimelle, jolla ei ole käännöstä. Avain jää puuttumaan, joten `fallbackLocale` pätee ajonaikana ja `check` raportoi sen. Tyhjä merkkijono olisi määritelty arvo ja näyttäisi tyhjää.

</Note>

### Mitä komennot lukevat {#what-the-commands-read}

`check`, `extract`, `sync`, `clean`, `search` ja `rename` lukevat lähdekoodia koko projektista, eivät kiinteästä kansioluettelosta:

- **Luetaan:** mallit ja skriptit jäsentimen kautta, `.html` ja Pug tekstinä, jokainen kerros sekä juuren ulkopuoliset kansiot, joihin alias tai `components` osoittaa.
- **Ohitetaan:** `node_modules`, build-tuloste ja lokaalitiedostot. Lisää omasi lipulla `--ignore 'legacy/**,*.stories.ts'`.
- **Testikoodi** lasketaan käytöksi, joten `clean` ja `check --only unused` säilyttävät avaimen, jota vain testi lukee. Se ei koskaan lisää avainta: `extract` ohittaa tällaiset avaimet, eikä `check` raportoi niitä määrittelemättöminä.

Testikoodilla tarkoitetaan juurikansioita `tests`, `test`, `__tests__`, `e2e`, `cypress` ja `playwright` sekä `.spec`- ja `.test`-JavaScript- ja TypeScript-tiedostoja (`.ts`, `.tsx`, `.mts`, `.js`, `.jsx`, `.mjs` ja vastaavat) missä tahansa. Vain juurikansiot on vapautettu alla kuvatuista epäilyistä: `pages/tests/[id].vue` on sivu kuten mikä tahansa muu, ja samoin `public/` ja minifioidut tiedostot, joiden koodi ei ole osa sovellusta.

Komennot tunnistavat:

- `$t`, `$ts`, `$tc`, `$has` ja `$_t(route)`;
- `t()` funktioista `useI18n()` ja `useTranslationServerMiddleware()`;
- `<i18n-t keypath>` malleissa ja JSX:ssä sekä `<i18n-group prefix>`;
- aliakset, kuten `const { t: tr } = useI18n()`.

### Miten `clean` päättää {#how-clean-decides}

`clean` jättää mieluummin kuolleen avaimen kuin poistaa elävän. Avain säilyy, kun jokin seuraavista pitää paikkansa:

- kutsu käyttää sitä tai sen ala- tai yläpuolista avainta;
- koodissa oleva merkkijono on sama kuin se: `const key = 'menu.home'`, `<Item label="menu.home" />`;
- jokin projektin JSON-, YAML- tai Markdown-tiedosto sisältää sen;
- lasketulla avaimella on staattinen alku, joka kattaa sen: `` $t(`status.${state}`) `` säilyttää kaiken `status.`-etuliitteen alla;
- jokin kerros määrittelee sen.

`clean` pysähtyy muuttamatta mitään, kun se ei voi tietää, ja listaa syyt:

- avain on kokonaan laskettu, kuten `$t(name)`, `<i18n-t :keypath="name" />` tai `<i18n-t v-bind="props" />`;
- `$t` välitetään arvona, kuten `items.map($t)`;
- `t`-niminen funktio saa lasketun argumentin ja tulee parametrista, importista tai kutsusta: se voi olla kääre oikean ympärillä. Saman tiedoston määrittelemää funktiota ei lasketa, koska kääreellä olisi oma kutsunsa sisällään;
- lähdetiedosto ei jäsenny;
- mikään tiedosto ei käytä yhtään avainta, mikä yleensä tarkoittaa, että se etsii väärästä paikasta;
- lokaalitiedosto on symbolinen linkki projektin ulkopuolelle, joten toinen sovellus voi lukea sitä.

<Steps>

<Step title="Esikatselu">

Aja `i18n-micro clean --dryRun` ja tarkista, mitä se listaa.

</Step>

<Step title="Avainten suojaaminen">

Säilytä avaimet, jotka vain näyttävät käyttämättömiltä, lipulla `--exclude '^errors\.'`.

</Step>

<Step title="Poistaminen">

Aja se uudelleen `--force`-lipulla.

</Step>

</Steps>

## Puuttuvien avainten kääntäminen {#translate-missing-keys}

```bash
i18n-micro translate --dryRun                     # keys and characters per locale, nothing sent
export I18N_TRANSLATE_TOKEN=...                   # or put it in .env
i18n-micro translate --service deepl --locale de,fr
```

- `translate` täyttää puuttuvat tai tyhjät avaimet; `--replace` kääntää kaiken uudelleen.
- Paikkamerkit ja monikkomuodot on suojattu. Käännöstä, josta paikkamerkki on kadonnut, ei kirjoiteta: avain listataan ja komento päättyy koodiin `1`.
- Jokainen erä tallennetaan ennen seuraavan pyynnön lähettämistä, joten epäonnistuminen maksaa vain epäonnistuneen pyynnön.

| `--service` | Palvelu | `--token` | Hyödyllisiä `--options`-arvoja |
| --- | --- | --- | --- |
| `ai` | Vercel AI Gateway, OpenAI, Anthropic tai mikä tahansa OpenAI-yhteensopiva palvelin | API-avain tai `AI_GATEWAY_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` | `provider`, `model`, `baseUrl`, `maxTokens` |
| `azure` | Azure Translator | Tilausavain | `region` |
| `deepl` | DeepL, myös Free-avaimet | Todennusavain | `formality`, `glossaryId`, `context` |
| `google` | Google Cloud Translation v2 | API-avain | `model` |
| `libretranslate` | LibreTranslate | Valinnainen | `baseUrl` |
| `yandexcloud` | Yandex Cloud Translate | API-avain tai IAM-token asetuksella `authScheme:Bearer` | `folderId`, `model` |

Asetukset ovat `key:value`-pareja: `--options provider:openai,model:gpt-4o-mini`. Kaikki palvelut ottavat myös `baseUrl`-, `retries`-, `retryDelayMs`- ja `timeoutMs`-asetukset. Käännöspyyntö voi jo olla laskutettu, joten se toistetaan vain `429`- tai `503`-vastauksen jälkeen, eikä silloin, kun palvelu pyytää odottamaan yli minuutin.

<Warning>

Liput näkyvät komentotulkin historiassa ja prosessilistoissa, joten välitä token ympäristömuuttujan kautta. CLI peittää salaisiksi tietämänsä arvot kaikkialla, missä se tulostaa ne, `--debug` mukaan lukien: tokenit, palveluntarjoajien avaimet, Basic-tunnukset sekä määrittämäsi URL-osoitteen kyselyn ja tunnukset. Palvelin, joka muotoilee avaimen uudelleen ennen sen toistamista, on sen ulottumattomissa, joten käsittele epäonnistuneen ajon lokeja huolella.

</Warning>

`ai`-palvelu noudattaa sanastoa. Kun `.i18n-glossary.json` on olemassa, sitä käytetään ilman lippua; `--glossaryFile` valitsee toisen tiedoston.

```json .i18n-glossary.json
{ "entries": [{ "source": "Cart", "target": "Warenkorb", "to": "de" }] }
```

## Kovakoodatun tekstin muuttaminen avaimiksi {#turn-hardcoded-text-into-keys}

```bash
i18n-micro text-to-i18n --dryRun   # list what would change
i18n-micro text-to-i18n            # rewrite the templates
```

```vue
<!-- before -->
<h1>Welcome to our site</h1>
<!-- after -->
<h1>{{ $t('pages.index.welcome-to-our') }}</h1>
```

Vain projektin omat `.vue`-mallit kirjoitetaan uudelleen, eivät kerroksen tai aliaksen kohteen mallit. Jokainen uudelleenkirjoitettu tiedosto jäsennetään uudelleen ennen kirjoittamista. Nämä listataan ja ne säilyttävät tekstinsä:

- teksti `.ts`-tiedostoissa ja skripteissä, koska `$t` ei ole kaikkialla käytettävissä;
- teksti merkinnän tai interpoloinnin vieressä, kuten `<p>Hello <b>world</b> today</p>`: puolikasta lausetta ei voi kääntää yksinään;
- generoitu avain, joka törmäisi toiseen, kuten yläsivulle ja sen alasivulle voi käydä;
- tunnettu avain, jota ei voi laittaa lainausmerkkien väliin.

<Warning>

Tee ensin commit ja tarkista diff.

</Warning>

## Avaimen nimeäminen uudelleen {#rename-a-key}

```bash
i18n-micro rename --from common.save --to actions.save
i18n-micro rename --from settings --to account.settings   # a whole namespace
```

`rename` muokkaa syntaksipuuta, joten kommentit ja asiaan liittymättömät merkkijonot säilyvät ennallaan, ja aliaksia sekä `:keypath`-arvoja seurataan. Kerroksen omaa tiedostoa ei koskaan muuteta. Se varoittaa siitä, mitä se ei voi kirjoittaa uudelleen, ja jättää sen rauhaan:

- vanhan nimen alla oleva laskettu avain;
- jokainen sen kanssa samanlainen tavallinen merkkijono;
- Pug-malli;
- lähde kerroksessa tai projektin ulkopuolisessa kansiossa.

`--to`-arvon on oltava avain, joka voidaan kirjoittaa koodiin: ei lainausmerkkejä, ei kenoviivaa, ei tyhjää segmenttiä, ei `__proto__`.

## Tiedostojen vaihtaminen kääntäjien kanssa {#exchange-files-with-translators}

```bash
i18n-micro export --format csv
i18n-micro import --format csv --dryRun
```

**`export`** kirjoittaa jokaisen lokaalin jokaisen avaimen, kääntämättömät mukaan lukien, ja oletuslokaalin tekstin lähteenä: CSV:ssä `Source`-sarake, PO:ssa `#.`-kommentti.

- Ilman `--dir`-lippua PO menee hakemistoon `pots` ja CSV hakemistoon `csv_exports`.
- Se kirjaa kirjoittamansa tiedostoon `.i18n-export.json` tulostekansiossa. Se pysähtyy, kun tiedosto on muuttunut sen jälkeen ja sisältää käännöksiä, joita lokaalitiedostoissa ei ole, epävarmat (fuzzy) PO-merkinnät mukaan lukien; `--force` ylikirjoittaa ne. Lokaalitiedostojen tavalliset muokkaukset eivät pysäytä sitä.

**`import`** yhdistää, ohittaa tyhjät solut ja ohittaa `fuzzy`-merkityt PO-merkinnät.

- Avain, joka ylikirjoittaisi arvon, tai arvo kokonaisen avainryhmän päälle, listataan ja jätetään pois, ja komento päättyy koodiin `1`.
- Se pysähtyy koodilla `2`, jos katalogi on odottamattomassa sijainnissa, sivun katalogi ei ole viimeisimmän viennin kirjoittama, CSV:ssä on lainausmerkki väärässä paikassa tai sivumerkintä on `disablePageLocales`-asetuksen alla.

Käännösalustalle käytä sen omaa CLI:tä: [Crowdin](/fi/guide/crowdin)-asetukset synkronoivat JSON-tiedostot, sivutiedostot mukaan lukien.

## Synkronointi omaan päätepisteeseen {#sync-with-your-own-endpoint}

`sync-remote` vaihtaa globaalit lokaalitiedostot ylläpitämäsi HTTP-päätepisteen kanssa. Sivutiedostot pysyvät paikallisina, ja komento kertoo sen. Kuvaa päätepiste tiedostossa `.i18n-remote.json`:

```json .i18n-remote.json
{ "url": "https://translations.example.com", "path": "translations" }
```

Päätepiste vastaa `GET`- ja `PUT`-pyyntöihin `{ locale: messages }`-objektilla. Todenna asetuksella `auth: { username, password }` tai laita bearer-token muuttujaan `I18N_REMOTE_TOKEN`.

| | Pull | Push |
| --- | --- | --- |
| Mitä siirtyy | Täyttää sen, mitä sinulla ei ole, ja säilyttää avaimet, jotka ovat vain sinulla | Lähettää projektin omat avaimet, ei kerroksen avaimia, ja jättää tyhjäsi pois |
| Ristiriidat | Avain, joka eroaa molemmilla puolilla: mitään ei kirjoiteta, koodi `1`; `--force` ottaa etäarvon | PUT korvaa dokumentin, joten push lukee ensin päätepisteen ja pysähtyy koodilla `1`, kun siinä on tekstiä, jota sinulla ei ole; `--force` ylikirjoittaa sen. Päätepisteellä, joka vastaa `404`, ei ole mitään menetettävää |
| `--dryRun` | Lukee päätepisteestä, listaa muutokset, ei kirjoita mitään | Kertoo, mitä lähetettäisiin, ottamatta yhteyttä päätepisteeseen |

Lokaali, jota et ole määrittänyt, ohitetaan, eikä tyhjä etäarvo tyhjennä mitään.

## Siirtyminen nuxt-i18n-micro-cli:stä {#moving-from-nuxt-i18n-micro-cli}

| Vanha komento | Nyt |
| --- | --- |
| `validate` | `check` |
| `diff` | `check --only missing` |
| `check-duplicates` | `check --only duplicates` |
| `export-csv`, `import-csv` | `export --format csv`, `import --format csv` |
| `--potsDir`, `--csvDir` | `--dir` |
| `estimate` | `translate --dryRun` |
| `glossary` | Muokkaa tiedostoa `.i18n-glossary.json`; `translate` lukee sen itse |
| `backup`, `restore` | Git, joka jo säilyttää lokaalitiedostosi |
| `init` | `nuxi init`, lisää sitten `nuxt-i18n-micro` `modules`-taulukkoon |
| `split` | Poistettu: moduuli ei lue jaettuja tiedostoja |
| `optimize` | `check --only duplicates` |
| `replace-values` | Editorisi tai `sed` |
| `stats --full` | `stats`; [DevTools](/fi/guide/devtools) näyttää yksityiskohdat |
| `search --hardcodedOnly` | `text-to-i18n --dryRun` |
| `search --preferUnused`, `--onlyVue` | Poistettu |
| `lint`-säännöt `no-html-tags`, `no-special-chars`, `no-mixed-case`, `no-missing-punctuation`, `no-inconsistent-pluralization` | Poistettu: ne merkitsivät tavallista tekstiä. Kirjoita `customRegexRules`-merkintä, jos tarvitset sellaisen |
| `text-to-i18n --extractOnlyDirs`, `--extractOnlyPatterns`, `--verbose` | Poistettu: koodia ei koskaan kirjoiteta uudelleen |
| `--logLevel verbose` | Poistettu: se ei tehnyt mitään |

**Poistetut palvelut:** `googlefree`, `yandex` (käytä `yandexcloud`), `ibm`, `lingvatranslate`, `modernmt`, `lilt`, `unbabel`, `reverso`, `baidu`, `papago`, `tencent`, `systran`, `mymemory`.

**Poistetut `sync-remote`-tyypit:** `github`, `gitlab`, `crowdin`, `lokalise`, `tolgee`, `weblate`. Käytä alustan omaa CLI:tä tai `custom`-tyyppiä, joka ei enää tarvitse `type`-arvoa.

### Muuttunut toiminta {#changed-behaviour}

- `extract` ja `sync` eivät enää kirjoita `''`. Avaimet jäävät puuttumaan, ja `check` raportoi ne. `extract` kirjoittaa avaimen vain, kun koodi antaa sen tekstin.
- `extract` kirjoittaa sivuavaimet hakemistoon `locales/pages/<route name>/`, josta moduuli lukee ne, ja skannaa `app/`-hakemiston Nuxt 4:ssä. Siirrä kaikki hakemistoista, kuten `pages/_about` ja `pages/blog_`, ja poista ylimääräinen `locales/pages/<locale>.json`.
- `nuxt.config`-tiedoston `translationDir` huomioidaan; aiemmin jokainen komento käytti hiljaa `locales`-hakemistoa.
- Ilman `defaultLocale`-asetusta oletus on `en`, kuten moduulissa, ja `DEFAULT_LOCALE` huomioidaan. Aiemmin se oli ensimmäinen lokaali.
- `check` ja `sync` käyttävät oletuslokaalia vertailukohtana ja tarkistavat sivutiedostot. `"a.b"` ja `a: { b }` lasketaan yhdeksi avaimeksi.
- `clean` säilyttää avaimen, jota käytetään missä tahansa, missä tahansa näkyvyysalueessa, ja pysähtyy, kun käyttöä ei voida todistaa. `--include` ja `--exclude` valitsevat, mitä saa poistaa.
- `sync` pysähtyy samalla tavalla sekä silloin, kun oletuslokaalissa ei ole avaimia verrattavaksi. `--force` ohittaa sen. Se pysähtyy myös, kun `DEFAULT_LOCALE` valitsi eri vertailukohdan kuin `nuxt.config`.
- Yhden viivan pitkät liput ja ylimääräiset argumentit ovat virheitä: `clean -dryRun` ei enää aja `clean`-komentoa.
- Vain luku -tiedostoa tai tiedostoa, joka ei ole UTF-8:aa, ei voi tallentaa: komento pysähtyy ennen kuin se muuttaa mitään. Tällaisen tiedoston lukeminen on kunnossa. Toistuva avain, `__proto__`-niminen avain ja kokonaisluku, joka on suurempi kuin 2^53, pysäyttävät komennon, koska tallennus menettäisi ne.
- Lippu, joka tarvitsee arvon ja jota seuraa toinen lippu, on virhe; kirjoita `--flag=--value` viivalla alkavalle arvolle. Totuusarvolippu ottaa vain arvon `true` tai `false`.
- `export` pysähtyy mieluummin kuin ylikirjoittaa käännöksiä, joita ei koskaan tuotu.
- Paluukoodit ovat `0`, `1` ja `2`; aiemmin epäonnistumiset olivat `1`, ja `diff` sekä `check-duplicates` aina `0`.
- `lint --fix` ei enää jätä `.bak`-tiedostoja.
- Tallennus säilyttää tiedoston sisennyksen, rivinvaihdot, loppurivinvaihdon, symbolisen linkin ja kovan linkin, ja jättää muuttamattomat tiedostot rauhaan.
- Väärin kirjoitettu tai poistettu lippu on nyt virhe, eikä sitä ohiteta hiljaa.
- Polut, kuten `--dir`, ovat suhteessa projektiin, eivät komentotulkkiin.
- `ai` ei enää lataa `@ai-sdk/*`-paketteja: käytä `provider`-arvoa `gateway`, `openai` tai `anthropic`, tai `baseUrl`-arvoa OpenAI-yhteensopivalle palvelimelle.
