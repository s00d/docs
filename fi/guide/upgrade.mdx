<Tip>

**Tuletko paketista `@nuxtjs/i18n`?** — Katso [Siirtyminen paketista @nuxtjs/i18n](/fi/guide/migration).

## 3.30.3:n jälkeen: pääversio {#after-3-30-3-the-major-release}

Moduulin asetukset, `$t`, `$localePath`, `$switchLocale` ja muut apufunktiot, komponentit, composablet ja dokumentoidut palvelinapuohjelmat säilyttävät nimensä. Muuttunut on käyttäytyminen, enimmäkseen korjattuja bugeja. Adapteripaketeissa ja reitityspaketeissa on todellisia API-katkoksia: katso [Kehyspaketit](#framework-packages) ja [Muut paketit](#other-packages).

### Tee tämä ensin {#do-this-first}

1. **Tarkista versiosi.** Moduuli vaatii Nuxt 3.18:n tai uudemman ja Node 20:n tai uudemman. Nuxtilla on oma Node-vähimmäisversionsa: Nuxt 4.5 ilmoittaa `^22.19.0 || ^24.11.0 || >=26.0.0`. `nuxt generate` epäonnistuu itse Nuxt 3.18.0:lla myös pelkässä Nuxtissa (`[unstorage] Invalid key: "/"`); 3.21.11 toimii. `@i18n-micro/react` vaatii Reactin 18 tai uudemman.
2. **Korjaa asennetut paketit.**
   - Poista `@i18n-micro/hmr`. Käännösten HMR on sisäänrakennettu moduuliin.
   - Jos testisi tuovat paketin `@i18n-micro/test-utils`, lisää se: `npm install -D @i18n-micro/test-utils`. Sitä ei enää asenneta moduulin mukana.
   - Korvaa `nuxt-i18n-micro-cli` paketilla `@i18n-micro/cli`. 28 komennosta tuli 16, `check` korvaa niistä kolme, ja paluukoodit muuttuvat: katso [CLI-opas](/fi/guide/cli#moving-from-nuxt-i18n-micro-cli).
3. **Etsi koodistasi** alla olevan taulukon merkinnät.
4. **Tarkista, mitä sovelluksen edessä on.** Jos localeilla on `baseUrl` proxyn takana, katso [Proxyn tai CDN:n takana](/fi/guide/deployment#behind-a-proxy-or-cdn). Jos käytät CDN:ää, tarkista sen välimuistiavain `Vary`-otsaketta vasten: katso [HTML:n välimuistitus](/fi/guide/deployment#caching-html). Jos käytät `apiBaseClientHost`-asetusta tai tiukkaa CSP:tä, salli uusi `preload`-linkki: katso [SEO ja head-tagit](#seo-and-head-tags).
5. **Päivitä snapshotit.** Head-snapshotteihin tulee `preload`-linkki, kielenvaihtimen merkintäkoodi muuttui ([`<i18n-switcher>` ja `<i18n-link>`](#&lt;i18n-switcher>-and-&lt;i18n-link>)), ja `$localeRoute`-tulosteen kyselymerkkijonot enkoodataan eri tavalla.
6. **Avaa sivusi jokaisella localella ja etsi raakoja avaimia.** Layoutit, jotka käyttivät edellisen sivun tiedoston avaimia, näyttävät ne nyt raakoina: siirrä nämä avaimet juuritiedostoon.

<Warning>

**Paketin `@i18n-micro/path-strategy` `switchLocaleRoute` menetti ensimmäisen argumenttinsa** — `switchLocaleRoute(fromLocale, toLocale, route, options)` on nyt `switchLocaleRoute(toLocale, route, options)`. **Vanha JavaScript-kutsu ei epäonnistu: se palauttaa väärän tuloksen,** koska `fromLocale` luetaan kohteeksi ja `toLocale` reitiksi. Vain TypeScript kertoo sen. Nuxtin `$switchLocaleRoute` ei muutu.

</Warning>

### URL:t ja uudelleenohjaukset {#urls-and-redirects}

- **`/en` ja `/en/...` antavat 404:n strategiassa `prefix_except_default`** (kun `en` on oletus), kuten dokumentoitu.
- **Locale-etuliite eri kirjainkoossa tai kirjoitusasussa antaa 404:n.** `/DE/about` renderöi aiemmin saksankielisen reitin oletuslocalella tai ohjasi osoitteeseen `/en/DE/about`. Oma sivu kyseisessä URL:ssä pysyy sivuna. Catch-all- tai `[slug]`-sivu ei ole sellainen: `/DE/x` sivun `[...slug]` alla ja `/DE` sivun `[slug]` rinnalla antavat myös 404:n, joten CMS-slug, joka vastaa locale-koodia eri kirjainkoossa, menettää sivunsa. Asetuksella `ssr: false` mikään palvelin ei vastaa, joten `/DE/about` näyttää saksankielisen sivun.
- **Sivun polku eri kirjainkoossa ohjautuu omaan kirjoitusasuunsa.** `/T/BASIC` antoi 200:n ja on nyt `302`-ohjaus osoitteeseen `/t/basic`.
- **Tuntematon URL pysyy 404:nä.** Asetuksilla `autoDetectPath: '*'` tai `'no_prefix'` `/nope` ei enää ensin ohjaudu osoitteeseen `/de/nope`. `prefix` säilyttää uudelleenohjauksen (siellä mitään ei tarjoilla ilman etuliitettä), kuten myös `/` kaikkialla.
- **Toisen localen mukautettu polku ilman etuliitettä löytää sivunsa strategiassa `prefix_except_default`.** `/a-propos` antoi 404:n ja on nyt `302`-ohjaus oletuslocalen URL:ään (`/about`). Strategiassa `prefix` sama uudelleenohjaus päätyy nyt toimivalle sivulle (`/en/about`, aiemmin `/en/a-propos`, joka antoi 404:n). `prefix_and_default` antaa edelleen 404:n.
- **`prefix` asetuksella `redirects: false` vastaa 404:llä etuliitteettömään URL:ään** (`/about` oli `302`), mukaan lukien sellaisen sivun alkuperäinen URL, jolla on mukautettu oletuspolku. `$localePath('/about')` löytää sivun edelleen.
- **Strategiassa `prefix_except_default` sellaisen sivun alkuperäinen URL, jolla on mukautettu oletuspolku, ohjautuu siihen,** dynaamiset sivut mukaan lukien. `/dir/one` antoi 404:n ja on nyt `302`-ohjaus osoitteeseen `/dir-one/one`.
- **`autoDetectPath: '*'` soveltaa nyt evästettä ja `Accept-Language`-otsaketta myös etuliitteettömiin polkuihin** (`/about` → `/de/about`).
- **Strategiassa `prefix` etuliitteetön URL säilyttää vierailijan localen.** Evästeellä `de` sekä `/about` että tavallinen `<NuxtLink to="/about">` menevät osoitteeseen `/de/about` jokaisella polulla riippumatta `autoDetectPath`-asetuksesta.
- **Strategiassa `prefix_and_default` etuliitteetön URL on oletuslocale.** `/contact` otsakkeella `Accept-Language: de` renderöityi aiemmin saksaksi ja hydratoitui sitten englanniksi. Nyt se renderöidään oletuslocalella; vierailijat pääsevät saksankieliseen versioon osoitteiden `/de/...` kautta.
- **Strategiassa `no_prefix` mukautettu polku renderöidään omalla localellaan** (`/ueber-uns` on saksankielinen millä tahansa preferenssillä), ja rajattu sivu renderöidään localella, jota se palvelee. Polku, jonka useampi locale jakaa, renderöidään preferenssin mukaan, kun se on jokin niistä, ja `baseUrl`-asetuksella se on sivu jokaisen niistä verkkotunnuksella. Nämä localet jakavat yhden tietueen, `localized-<page>-<first locale>`.
- **`noPrefixRedirect` toimii vierailijan localen mukaan.** Evästeellä `de` `/about` menee osoitteeseen `/ueber-uns` ja renderöityy saksaksi, ei oletuslocalen osoitteeseen `/about-us`. Locale, jolla ei ole omaa mukautettua polkua, pysyy polulla `/about`.
- **`routeRules`-uudelleenohjausta ilman sivua ei lokalisoida.** `/de/old` oli tyhjä 200, nyt se on 404: lisää sääntö etuliitteelliselle polulle, jos tarvitset sellaisen. Linkki toisesta localesta tällaiseen sääntöön säilyttää polun kirjoitetun mukaisena ja päätyy säännön kohteeseen.
- **Reittisäännöt ulottuvat mukautettuihin polkuihin.** `/blog/**` koskee myös polkua `/de/artikel/:slug`, kun sivulla `blog/[slug]` on tämä polku, ja säännöt kopioidaan myös `no_prefix`-strategiassa. Staattinen sisarsivu, kuten `/de/artikel/news`, vastaa myös tätä kuviota. Jo locale-etuliitteen alle kirjoitettu sääntö säilyy kirjoitetun mukaisena.
- **Locale, jolla on `disabled: true`, vastaa 404:llä etuliitteessään** heti, ja siihen osoittavat linkit pysyvät sivulla. Ajon aikana pois käytöstä otettu locale toimii samoin: aiemmin se renderöityi varalocalella.
- **Moduulin 404-sivulla lukee `Page Not Found`** pois käytöstä otetun localen etuliitteessä ja isännän omassa etuliitteessä, missä Nuxt sanoi `Page not found: /de/about`. Tilakoodi on sama.
- **`customRegexMatcher` ei enää anna 404:ää todelliselle sivulle**, jonka ensimmäinen segmentti näyttää localelta.
- **Lokalisoitujen reittien nimet ovat johdonmukaisia.** Jaetun locale-tietueen alla oleva lapsi säilyttää sivun nimen, `no_prefix` noudattaa `localizedRouteNamePrefix`-asetusta, ja vanhempi, jolla on index-lapsi, pysyy nimettömänä.
- **Sivut, jotka moduuli lisää ilman `name`-arvoa** (`extendPages`), lokalisoidaan ja saavat nimen, locale-variantit ja `hreflang`-tagit. Aiemmin ne jäivät lokalisoimatta.
- **`nuxt.config`-merkintä voittaa `$defineI18nRoute`-kutsun** missä tahansa avainmuodossa (`about/team`, `/about/team`, `about-team`). Aiemmin voittaja riippui kirjoitusasusta.
- **Uusia build-varoituksia:** `localeRoutes`-arvo, joka alkaa omalla locale-koodillaan (`fr: '/fr/article'`), sekä lapsen mukautettu polku vanhempansa ulkopuolella.
- **Hash-tila toimii strategiassa `prefix`.** Dokumentti on `/`, ja `/en` tai `/about` ohjautuvat hashiin.
- **`/#/de/x` renderöityy saksaksi** strategioissa `prefix_except_default` ja `prefix_and_default`. Aiemmin se renderöityi englanniksi hydraatioristiriidan kera.

### Linkit ja reittiobjektit {#links-and-route-objects}

- **Locale, joka ei palvele sivua, linkittää etusivulleen.** `$localeRoute`, `$switchLocalePath` ja kielenvaihdin eivät enää palauta toisen localen sivua.
- **Tuntematon locale-koodi menee oletuslocalelle.** `$localePath(path, 'xx')` ja `$localeRoute` antoivat aiemmin `/xx`.
- **`$localePath` palauttaa `http(s):`-, `mailto:`- tai `tel:`-skeemallisen merkkijonon sellaisenaan, ja `$localeRoute`-tuloksen `path` ja `fullPath` kantavat sen muuttamattomana**, joten älä anna niille tarkistamatonta arvoa (`?next=`-parametri) linkin kohteeksi. `//host` ja paljaat nimet kuten `x.com` pysyvät polkuina tällä originilla jokaisella localella, eikä mikään niistä muodostettu linkki poistu siltä: `/de//x.com` oletuslocalelle on `/x.com`. Kenoviivat lasketaan kauttaviivoiksi.
- **`$localePath` enkoodaa polun:** `/a b` antaa `/a%20b`.
- **`$localeRoute` ja `$switchLocaleRoute` palauttavat tavallisia objekteja,** jotka ovat turvallisia `ref`-, `reactive`- ja `useState`-käytössä, JSONissa ja spreadeissa. Kun parametri vaatii escapointia, objekti on `{ path, fullPath, query, hash }` (`$localeRoute` lisää `href`-kentän) ilman `name`- tai `params`-kenttää, ja URL pysyy samana ennen uudelleenlatausta ja sen jälkeen. Tavallisessa URL:ssä on molemmat. `name` on uusi: vanhoissa objekteissa sitä ei koskaan ollut. Koodin, joka lukee `.name`- tai `.params`-kenttää, on käsiteltävä niiden puuttuminen, ja saamasi muoto riippuu arvosta.
- **`trailingSlash`-asetuksella `$switchLocaleRoute` palauttaa aina tämän polkumuodon,** myös tavallisille slugeille, ja palvelimen uudelleenohjaukset noudattavat `trailingSlash`-asetusta. Tulokset ja `Location`-otsakkeet voivat muuttua tällä asetuksella.
- **`$localeRoute`-tulosteen kyselyarvot käyttävät vue-routerin enkoodausta:** `/` pysyy literaalina ja välilyönti on `+` (`?redirect=/v2`, aiemmin `%2Fv2`). Dekoodattu arvo on sama, mutta tällaisen `href`-arvon snapshot muuttuu.
- **Linkki ilman polkua pysyy nykyisellä sivulla.** `$localePath('#top')`, `'?p=2'`, `''` ja `{ query }` säilyttävät sivun, jolla ne ovat; `'#top'` luettiin aiemmin sivuston juuresta. Paljas `'about'` tarkoittaa edelleen `/about`.
- **Spreadit.** `{ ...route, query }` ja `{ ...route, hash }` säilyttävät muutoksen, myös `$switchRoute`-funktion kautta. Uusi `path` voittaa funktioissa `$localeRoute`, `$localePath` ja `$switchRoute`. `{ ...route, params }` toimii nimetyllä reitillä; polkumuotoisella reitillä polku voittaa ja parametrit ohitetaan vue-routerin kehitystilan varoituksen kera. Käytä `$localeRoute({ name, params })`.
- **`$switchRoute` pysyy sovelluksessa.** Localen oma `baseUrl`, `mailto:` ja `tel:` poistuvat siitä; mikä tahansa muu merkkijono on polku.
- **`excludePatterns`** vastaavat kokonaisia segmenttejä (`'/admin'` ei enää vastaa polkua `/administrator`), ja globit ankkuroidaan (`/docs/*` ei enää vastaa polkua `/en/docs/x`). `RegExp`-kuviot päätyvät nyt ajonaikaan; aiemmin ne katosivat siellä. Sivu, jota ne vastaavat, on lokalisoimaton: ei `hreflang`-tageja, ja oletuslocale strategiassa `prefix_except_default`. Tarkista kuviosi sivua [Polkujen poissulkeminen](/fi/guide/excluding-static-files) vasten.

Parametrissa oleva `%` tai `?` ei säily palvelinrenderöidyssä uudelleenlatauksessa Nuxt 4.5.2:lla missään sovelluksessa: kyse on upstreamista, ei moduulista.

### Locale-verkkotunnukset {#locale-domains}

- **`locales[].baseUrl` reitittää nyt pyyntöjä.** Yksi build palvelee jokaista verkkotunnusta: katso [Kerrokset ja verkkotunnukset](/fi/guide/layers#multiple-domains). Kun `baseUrl` on asetettu, toisen verkkotunnuksen locale antaa tällä isännällä 404:n (`/en/about` osoitteessa `example.de`), ja linkit saman isännän localeen ovat suhteellisia. Pyynnöt millä tahansa muulla isännällä, `localhost` mukaan lukien, toimivat kuten ennenkin, paitsi että canonical ja `hreflang` käyttävät `metaBaseUrl`-arvoa, jos se on asetettu, muuten oletuslocalen `baseUrl`-arvoa, eivätkä pyynnön originia.
- **`Host`-otsakkeen uudelleenkirjoittavan proxyn takana** jokainen pyyntö putoaa build-konfiguraatioon, kunnes asetat [`trustForwardedHost`](/fi/api/module-options#trustforwardedhost)-asetuksen. Sen oletus on `false`, toisin kuin `metaTrustForwardedHost`. Katso [Proxyn tai CDN:n takana](/fi/guide/deployment#behind-a-proxy-or-cdn).
- **`nuxi generate` `baseUrl`-asetuksen kanssa vaatii `NUXT_I18N_DOMAIN`-muuttujan, kerran verkkotunnusta kohden.** Ilman sitä build varoittaa, ja kyseiset localet ovat linkkejä ilman sivuja. Katso [Staattinen sivusto](/fi/guide/deployment#static-site-(nuxi-generate)).
- **Linkki localeen, jolla on `baseUrl`, kulkee `$localePath`-funktion tai `<i18n-link>`-komponentin kautta.** `<NuxtLink :to="$localePath(x, 'fr')">` ja `<i18n-link :to="$localeRoute(x, 'fr')">` ovat tuo absoluuttinen URL, ja klikkaus vie sinne. Reititin ei ota absoluuttista objektia: `<NuxtLink :to="$localeRoute(x, 'fr')">` ja `router.push($localeRoute(x, 'fr'))` jäävät muotoon `/https://fr.example.com/...`, joka on tämän sovelluksen polku. Osoitteessa `localhost` tai esikatseluisännällä jokainen locale, jolla on `baseUrl`, on tällainen linkki, myös nykyinen. Koodissa käytä `navigateTo($localePath(x, 'fr'), { external: true })`.
- **Verkkotunnuksen etusivu kirjoitetaan kaikkialla ilman loppukauttaviivaa** (`https://example.de`), linkeissä, canonicalissa ja `hreflang`-tageissa.
- **Strategiassa `prefix` linkki toiseen verkkotunnukseen säilyttää locale-etuliitteen, `baseDefault`-asetuksella tai ilman.** `https://example.de/de/about`, ei `https://example.de/about`, joka vain ohjaa uudelleen.
- **Strategiassa `prefix_except_default`, kun `baseDefault` on muulla kuin buildin oletuslocalella, reitit säilyttävät jokaisen etuliitteen,** jotta muut verkkotunnukset voivat linkittää niihin. `/en` antaa edelleen 404:n. Vain `router.getRoutes()`-tulosta lukeva koodi huomaa eron.
- **Strategiassa `prefix_except_default` isännän oma etuliite antaa 404:n sen `baseDefault`-isännällä.** `/de/x` `de`-isännällä antoi 200:n.
- **`$getI18nConfig().locales` sisältää vain sen, mitä isäntä palvelee.** `linkLocales` sisältää ne kaikki, ja `$getLocales()` pysyy täydellisenä.

### Navigointi ja `$switchLocale` {#navigation-and-$switchlocale}

- **Navigointi tulee voimaan, kun se vahvistetaan.** Sanakirja, locale, parametrit ja head muuttuvat `router.afterEach`-vaiheessa, joten peruttu tai estetty navigointi ei muuta mitään, ja vanhan sivun linkit pysyvät voimassa, kun seuraava osa latautuu. `beforeResolve`, `beforeRouteEnter` tai myöhempi globaali guard näkee nyt vanhan sanakirjan ja localen. Reittimiddleware ei muutu.
- **Epäonnistunut osa säilyttää nykyisen sanakirjan.** 5xx, verkkovirhe tai virheellinen runko juuritiedostossa näytti aiemmin raakoja avaimia. Uusi sivu renderöidään nyt vanhoilla merkkijonoilla, ja seuraava navigointi yrittää uudelleen. 404 tai staattisen isännän SPA-kuori tiedoston paikalla antaa juurisanakirjan seuraavaan uudelleenlataukseen asti.
- **`$switchLocale` ratkeaa arvoon `true` tai `false`** (aiemmin se ei ratkennut mihinkään), `false`, kun localen sanakirja ei tullut voimaan. Sen tyyppi on `Promise<boolean>`, ja `$switchRoute`-funktion `Promise<void>`.
- **`$switchLocale` on eksplisiittinen valinta.** Saapuessa se tallentaa localen, myös 404-sivulla. Jos navigointi estetään, perutaan tai heittää virheen, tallennettu preferenssi ja tila pysyvät ennallaan, ja virhe heitetään uudelleen. Siirtyminen toiselle isännälle tallentaa sen ensin. Strategiassa `no_prefix` ja hash-tilassa vaihto pysyy, teki navigointi mitä tahansa. Sivulla, jolla on yksi URL kaikille localeille (`excludePatterns`), valintaa ei peruta, ja seuraavan sivun URL ratkaisee: strategiassa `prefix_except_default` etuliitteetön linkki palaa oletuslocaleen.
- **Strategiassa `no_prefix` `$switchLocale` säilyttää sivunsa, kun kaksi sivua jakaa mukautetun polun,** myös escapoiduilla parametreilla. Tällaisen URL:n uudelleenlataus ja `$localeRoute` escapoidulla parametrilla päätyvät ensimmäiseen tietueeseen.
- **Asiakkaan uudelleenohjaus säilyttää navigointinsa tilan.** Tavallinen `<NuxtLink to="/about">` strategiassa `prefix` lisää historiamerkinnän nykyisen korvaamisen sijaan; `router.replace` korvaa edelleen.
- **Palvelimelta tulevat `$setI18nRouteParams` ja `useI18nHead` säilyvät hydraation yli.** Kun sivulle `/news/2` saavutaan, kielenvaihdin linkittää käännettyyn slugiin (`/de/news/2-zwei`), ei osoitteeseen `/de/news/2`, myös palvelimen HTML:ssä, missä tahansa kielenvaihdin sijaitsee, kun sivu asettaa parametrit SSR:n aikana. Ne pudotetaan, kun navigointi toiseen polkuun vahvistetaan, mukaan lukien `/news/1` → `/news/4`: aseta ne uudelleen uudella sivulla.
- **Setupissa luettu `$setI18nRouteParams` on sidottu kyseiseen sivuun.** Myöhäinen kutsu jo poistutulta sivulta ei tee mitään. `useNuxtApp().$setI18nRouteParams` on nyt accessor, ja kaksi lukua antavat kaksi funktiota. Sillä ei ole setteriä: `useI18n().$setI18nRouteParams = fn`, kuten testitynkä saattaisi tehdä, heittää virheen strict-tilassa, joten tynkää itse `useI18n`. Layoutissa tai `app.vue`-tiedostossa se on tavallinen funktio, koska sieltä ei poistuta.
- **Palvelin kirjoittaa `<i18n-switcher>`-komponentin linkit uudelleen renderöinnin päättyessä** parametrillisilla sivuilla, koska layoutissa oleva kielenvaihdin renderöidään ennen sivun asynkronista setupia. Käsin kirjoitettua `$switchLocalePath`-linkkiä ei kirjoiteta uudelleen: katso [mukautetut locale-reitit](/fi/guide/custom-locale-routes). Nuxtin SSR-streamingissa ensimmäinen HTML säilyttää URL:n parametrit.
- **Palvelinkomponentin `locale`-niminen prop asettaa sen renderöintilocalen**, joten `<Greeting :locale="$getLocale()" />` seuraa URL:ää ja vaihtoa. Sen sisällä myös `$getLocale()`, `$localePath` ja `$getLocaleName` seuraavat propia. Katso [palvelinpuolen käännökset](/fi/guide/server-side-translations). Ilman propia se käyttää edelleen evästettä tai oletusta.
- **`keepalive`-sivut saavat parametrinsa ja headinsa takaisin** palatessa.
- **Strategiassa `prefix_except_default` arvoon `false` asetetulla sisäkkäisellä sivulla ei ole locale-URL:ää.** `/de/parent/kid` asetuksella `globalLocaleRoutes: { 'parent-kid': false }` tarjoiltiin, ja nyt se antaa 404:n: sivu pysyy polulla `/parent/kid`.

### Localen tunnistus ja eväste {#locale-detection-and-the-cookie}

Yksi etusijajärjestys kaikkialla, kuvattu sivulla [Localen tunnistus](/fi/guide/locale-detection).

- **`?locale=` huomioidaan sivuilla vain strategiassa `no_prefix`.** Etuliitestrategioissa URL ratkaisee; `/about?locale=de` ei enää renderöidy saksaksi `lang="en"`-attribuutin alla. `?locale=de&locale=fr` lukee ensimmäisen arvon, aiemmin se oli `"de,fr"`.
- **`Accept-Language` noudattaa `q`-arvoja** (`fr;q=0.1, de;q=0.9` → `de`; `q=0` sulkee kielen pois). Alueellinen vastaavuus ei enää riipu `locales`-listan järjestyksestä eikä koskaan ylitä kiinalaisten kirjoitusjärjestelmien rajaa.
- **Asiakkaan navigointi sivulle tallentaa sen localen evästeeseen, myös oletuslocalen etuliitteettömällä sivulla.** Kun `localeCookie` on asetettu, vierailijalla, joka klikkaa linkkiä osoitteeseen `/about`, on nyt `user-locale=en`, eikä selaimen kielen myöhempi muutos enää ohjaa polkua `/` uudelleen. Kyseisen URL:n ensimmäinen lataus ei tallenna mitään. Strategiassa `no_prefix` ja hash-tilassa navigointi tallentaa vain muutoksen.
- **404 ei kirjoita evästettä:** ei vastaus, eikä tavallinen asiakkaan navigointi siihen, missään tilassa. Strategiassa `no_prefix` etuliitteelliseltä näyttävä URL ei myöskään kirjoita evästettä.
- **Strategiassa `no_prefix` eksplisiittistä `localeCookie: null` -asetusta noudatetaan.** Aiemmin siitä tuli `user-locale`. Aseta se `nuxt.config`-tiedoston `i18n`-lohkossa: `null` kohdassa `modules: [[name, opts]]` tai kerroksessa katoaa edelleen.
- **Hash-tila lukee vain `hash-locale`-evästeen.** Pelkkä `user-locale=de` ei enää vaikuta.
- **Väärin muotoiltu locale-eväste ohitetaan ja jätetään ennalleen** sen sijaan, että jokainen SSR-sivu epäonnistuisi 500:lla. Sitä ei enää poisteta jokaisella pyynnöllä, mikä myös esti etuliitteellistä sivua tallentamasta localeaan.
- **URL:n locale on ensimmäinen.** Pluginin `setLocale('de')` polulla `/en/...` ei enää lataa `de`-sanakirjaa, ja tilassa oleva tuntematon koodi ohitetaan.
- **Palvelimen API-apufunktiot** (`useLocaleServerMiddleware`, `useTranslationServerMiddleware`) käyttävät yhtä järjestystä jokaisella reitillä: `?locale` → `[locale]`-parametri tai etuliite → eväste → otsake → oletus. Ne noudattavat nyt asetuksia `localeCookie: null` ja `autoDetectLanguage: false` ja tallentavat sanakirjan välimuistiin localea kohden.
- **Ajonaikaiset ohitukset ulottuvat reititykseen.** `NUXT_I18N_DEFAULT_LOCALE` ja ajonaikaiset `disabledLocales` muuttavat nyt generoitua strategiaa (pois käytöstä otettu locale lopettaa reitityksen), ja ajonaikaiset `disabledLocales` lisätään buildin vastaaviin. Strategioissa `prefix_except_default` ja `prefix_and_default` ajonaikainen `defaultLocale` ohitetaan varoituksen kera, koska kyseisen localen etuliitteettömät reitit generoidaan buildissa. Ajonaikaisen `fallbackLocale`-arvon on oltava käytössä oleva locale: muuten se pudotetaan varoituksen kera ja buildin arvo on voimassa, jos se on käytössä. Katso [Ajonaikaiset ohitukset](/fi/guide/runtime-overrides).

### SEO ja head-tagit {#seo-and-head-tags}

- **`dir="auto"` ei ole enää oletus.** Locale ilman `dir`-arvoa sai aiemmin `dir="auto"`, mikä hidastaa suurten sivujen jäsentämistä. Nyt tunnettu RTL-kieli saa `dir="rtl"`, eikä mikään muu locale saa attribuuttia. Tämä koskee Nuxtia, `@i18n-micro/vue`-, `astro`- ja `vitepress`-paketteja. Jos asetat localelle `dir: 'auto'` säilyttääksesi vanhan tulosteen, se maksaa noin 1 s jäsentämistä 20 000 elementillä: katso [Tekstin suunta](/fi/guide/seo#text-direction).
- **Jokaisella SSR-sivulla on uusi tagi:** `<link rel="preload" as="fetch" crossorigin="anonymous" href="/_locales/...">`, myös 404-sivuilla. `apiBaseClientHost`-asetuksella `href` on kyseisellä isännällä, mikä vaatii CORSin. Tiukan CSP:n on sallittava se.
- **`hreflang` luettelee vain localet, jotka palvelevat sivua**; `x-default` tuotetaan vain, kun oletuslocale palvelee sitä.
- **Lokalisoimattomalla sivulla ei ole `hreflang`- eikä `og:locale:alternate`-tageja.**
- **Canonical ja `hreflang` sisältävät `app.baseURL`-osan**, kun origin tulee pyynnöstä. `metaBaseUrl` ja `site.url` pysyvät kirjoitetun mukaisina.
- **404-sivuilla on `<html lang dir>`** URL:n localella. Niillä ei ole canonicalia, `hreflang`-, `og:url`- tai `og:locale`-tageja eikä vaihtoehtoja, myöskään kun moduuli itse vastaa 404:llä vastaavaan tietueeseen (`/en/...`). `useI18nHead`-funktion `replace`-kautta välittämäsi tagit säilyvät, joten jätä ne pois virhesivuilta.
- **Canonical, `og:url` ja `hreflang` säilyttävät sallitut kyselyparametrit** (`/about?page=2`), myös palvelimella: SSR:n aikana ne pudotettiin. `page`, `sort`, `filter`, `search`, `q`, `query` ja `tag` ovat oletuksena sallittuja; katso [`canonicalQueryWhitelist`](/fi/api/module-options#canonicalquerywhitelist).
- **Jäsentymätön `X-Forwarded-Host` ohitetaan** sen sijaan, että jokainen sivu antaisi 500:n. Ilman käyttökelpoista isäntää ja ilman `metaBaseUrl`- tai `site.url`-arvoa kyseisen vastauksen canonical- ja `hreflang`-URL:t ovat suhteellisia. Jäsentymätön `Host` antaa edelleen 500:n, kuten tavallisessa Nuxt-sovelluksessa.
- **`disableMeta` toimii nyt,** sekä `$defineI18nRoute`-kutsussa että `routeDisableMeta`-asetuksessa, myös `nuxt.config`-tiedostossa asetettuna: sivulla ei ole `hreflang`-, canonical- tai `og:locale`-tageja. `lang` ja `dir` säilyvät.
- `useLocaleHead()` palauttaa myös `build()`-funktion, getterin käytettäväksi muodossa `useHead(() => build())`.
- Tavallisessa buildissa ilman `metaBaseUrl`-asetusta `X-Forwarded-Host` valitsee edelleen näiden tagien isännän, kuten ennenkin. Kiinnitä `metaBaseUrl`, jos origin on suoraan tavoitettavissa: katso [Proxyn tai CDN:n takana](/fi/guide/deployment#behind-a-proxy-or-cdn).

### Käännökset {#translations}

- **Yhdistämiset ovat syviä joka tasolla.** Juuri-, sivu- ja varatiedostot käyttivät 2-tasoista yhdistämistä, joten `a.b.c` vara- tai juuritiedostosta katosi source-tilassa ja kehitystilassa. Kaikki tilat antavat nyt saman sanakirjan.
- **Varaketjuja seurataan loppuun asti** (`fr` → `de` → `en`) jokaisessa tilassa.
- **Yhdistäminen tapahtuu localen, ei tiedostotyypin mukaan.** Aktiivisen localen juuritiedosto voittaa nyt varalocalen sivutiedoston. Katso [Varalocalet](/fi/guide/translations#fallback-locales).
- **Projektin `locales`-merkintä voittaa kerroksen merkinnän** samalla `code`-arvolla; kerros vain täyttää aukot.
- **Sivu, jolla ei ole omaa `pages/<name>/`-kansiota, lukee juurisanakirjaa,** myös lapsisivut. Aiemmin se sai `{}` ja näytti raakoja avaimia. Tulosteeseen tulee tiedosto jokaista tällaista sivua kohden ja `__root/<locale>/data.json` jokaista localea kohden: `/_locales/<any name>/en/data.json` antaa 200:n juuriavaimilla, aiemmin se oli `{}`. Tällä on merkitystä valvonnalle, staattisten isäntien sallittujen listoille ja työkaluille, jotka lukevat puuta.
- **`disablePageLocales: true` lukee vain juuritiedostot;** `pages/index`-tiedostoa ei enää yhdistetä mukaan.
- **Poistuvan sivun avaimet lakkaavat ratkeamasta, kun sen elementti poistuu dokumentista.** Jos layout käytti avaimia, jotka olivat vain edellisen sivun tiedostossa, siirrä ne juuritiedostoon. Vanhemman avaimet säilyvät, kun sen lapsi on näkyvissä, mukaan lukien vanhempi, jolla on `index`-lapsi, seuraavaan navigointiin asti. Saman vanhemman kahden lapsen välillä vanhemman omat avaimet tarvitsevat lapsen sanakirjan tai juurisanakirjan.
- **`$clearCache()` lataa nykyisen sivun sanakirjan uudelleen** ja pitää vanhan näytöllä, kunnes uusi saapuu. Epäonnistunut uudelleenlataus säilyttää vanhan sanakirjan, ennen tyhjennystä pyydetty vastaus hylätään, ja poistumissiirtymässä oleva sivu pysyy käännettynä.
- **`$has(key, route)` noudattaa reittiä.**
- **`$loadPageTranslations` sivulla, jolla ei ole vielä käyty, ei enää estä sen tiedoston latautumista.** Tiedosto latautuu ensimmäisellä käynnillä, ja avaimesi pysyvät sen päällä. Aiemmin sivu näytti raakoja avaimia uudelleenlataukseen asti.
- **Käännösten HMR soveltaa muokkaukset paikallaan** ilman sivun uudelleenlatausta; poistetut avaimet katoavat ja juurimuokkaukset ulottuvat jokaiselle sivulle.
- **Rikkinäinen locale-tiedosto varoittaa kerran polkunsa kera jokaisessa tilassa.** Kehitystila heitti aiemmin virheen ja premerged ohitti sen hiljaa, joten sovellus, joka luotti kehitystilan kovaan epäonnistumiseen, ei enää näe sitä.

### Monikot ja muotoilu {#plurals-and-formatting}

- `$tc` negatiivisella, murtoluku- tai valtavalla lukumäärällä ottaa viimeisen muodon todellisella lukumäärällä; `{ count: null }` ei enää heitä virhettä; puuttuva monikkoavain päätyy puuttuvien käsittelijälle.
- `$tdr` antaa todelliset tulevat päivämäärät (`in 3 days` tai `tomorrow` asetuksella `numeric: 'auto'`) ja `Invalid Date` virheelliselle syötteelle. Alle sekunti menneisyydessä on `0 seconds ago`.
- **`$tn`, `$td` ja `$tdr` toimivat `iso`-arvon mukaan**, kuten monikot: `{ code: 'en', iso: 'en-GB' }` muotoilee nyt päivämäärät muotoon `31/10/2026`. Locale-koodissa `_` luetaan merkkinä `-`, joten `en_US` ei enää heitä virhettä, ja koodi, jota `Intl` ei tunne, muotoillaan kuten `en` sen sijaan, että se seuraisi koneen localea. Nimettyjä muotoja haetaan edelleen `code`-arvon perusteella.
- `{param}`-paikkamerkki lukee vain antamasi parametrit (`{constructor}` pysyy kirjoitetun mukaisena).
- `{placeholder}`-nimet voivat sisältää mitä tahansa merkkejä paitsi aaltosulkeita ja välilyöntejä: `{firstName}`, `{first-name}` ja `{user.name}` luetaan `params`-objektista. Ilman tällaista parametria ne pysyvät kirjoitetun mukaisina, kuten ennenkin.
- `defaultValue` interpoloidaan, sekä `$t`- että `$tc`-funktiossa: `$t('missing', { n: 1 }, 'Got {n}')` antaa `Got 1`, aiemmin se antoi `Got {n}`. Oletusarvo, joka ei ole merkkijono, palautetaan sellaisenaan.
- `$tc` tyhjälle käännökselle vastaa `''`, kuten `$t`. Aiemmin se vastasi oletusarvon tai avaimen.
- **Monikkotemplatet säilyttävät merkityksensä, yhtä poikkeusta lukuun ottamatta.** Taulukko luettelee jokaisen muodon. Saadaksesi `Intl.PluralRules`-kategoriat ilmoita siitä uudella [`=0 `-merkillä](/fi/api/methods#$tc): `=0 no apples | one apple | {count} apples`.

  | Muoto | Esimerkki (localella `uk`) | Ennen | Nyt |
  | --- | --- | --- | --- |
  | Mikä tahansa template localella, jolla on yksi tai kaksi kokonaislukukategoriaa (`en`, `de`, `fr`, `es`, `ja`...) | `none \| one \| {count} many` | indeksin mukaan | **ennallaan** |
  | Yksi muoto kategoriaa kohden | `one \| few \| many` | indeksin mukaan: 21 → `many` | **ennallaan**. Lisää merkki, jotta 21 → `one` |
  | Nollamuoto ensin, kolme muotoa | `none \| one \| many` | indeksin mukaan | **ennallaan** |
  | Muut paikkamerkit | `no items \| {n} item \| {n} items` | indeksin mukaan | **ennallaan** |
  | `{count}` jokaisessa muodossa | `{count} many \| {count} one \| {count} few` | indeksin mukaan | **ennallaan** |
  | Vähemmän tai enemmän muotoja kuin alla | `a \| b`, `none \| one \| two \| {count} many` | indeksin mukaan | **ennallaan** |
  | Localeilla `lv`, `prg`, `blo`, `cv`, `ksh`, `lag` | `none \| one \| {count} many` | indeksin mukaan | **ennallaan** |
  | Merkitty merkillä `=0 ` | `=0 none \| one \| many` | merkki näytettiin tekstinä | nollamuoto, sitten kategoriat |
  | **Nollamuoto ilman paikkamerkkiä, sitten yksi muoto kategoriaa kohden, ja `{count}` jokaisessa muodossa, jonka useampi lukumäärä jakaa** | `none \| {count} one \| {count} few \| {count} many` | indeksin mukaan: 3 → `3 many`, 21 → `21 many` | **kategorian mukaan**: 3 → `3 few`, 21 → `21 one`. 0, 1, 2 ja jokainen `many`-kategoriaan jäävä lukumäärä antavat saman tuloksen |

  Viimeinen muoto vaatii kolme tai useampia kategorioita (`ru`, `uk`, `pl`, `cs`, `sk`, `hr`, `sr`, `lt`, `ro`, `sl`, `he`, `ar`, `cy`...). Localella `ar` `one` ja `two` ovat yksittäisiä lukumääriä, joten nämä kaksi muotoa eivät tarvitse numeroa.
- **Locale-koodi, jota `Intl` ei tunne, saa indeksisäännön**, merkin kategorioilla tai ilman: `ua` ei enää seuraa koneen localea. Aseta `iso`: `{ code: 'ua', iso: 'uk-UA' }` taivuttaa monikot ukrainan mukaan, moduulissa ja paketissa `@i18n-micro/vue`.
- **Mukautettu `plural`-sääntö säilyttää allekirjoituksensa** ja saa edelleen locale-koodin. Se lukee raaka-arvon, joten merkitty template saapuu sille `=0 `-merkki paikallaan, ja se saa lukumäärän `Number`-tyyppisenä: `1.5`, kun se aiemmin sai `1`. `null`-arvon palauttaminen palaa sisäänrakennettuun sääntöön, joka noudattaa merkkiä.
- **`timeZone`-asetus.** Aseta se (`Europe/Berlin`), jotta palvelimella ja jokaisessa selaimessa renderöidään sama kalenteripäivä. Sillä ei ole vaikutusta `relativeDate`-arvoon, joka riippuu kellosta.

### `<i18n-t>` {#&lt;i18n-t>}

Tämä osio käsittelee moduulin `<i18n-t>`-komponenttia ja paketin `@i18n-micro/vue` `I18nT`-komponenttia. Muut kehykset: katso [Kehyspaketit](#framework-packages).

- **`html` escapoi `params`-arvot kaikissa tapauksissa ja ohittaa kaikki slotit.** Vain käännös on luotettua merkintäkoodia. Parametri, joka tarkoituksella sisälsi merkintäkoodia, näkyy nyt tekstinä: laita merkintäkoodi käännökseen ja välitä data parametreina, tai käytä slotteja ilman `html`-propia.
- **Slotit toimivat propien `plural`, `number`, `date` ja `relativeDate` kanssa,** ja `default`-slot saa `{ translation }` myös näissä tapauksissa. Jokainen `{name}` täytetään, ei vain ensimmäinen.
- **Slot voittaa samannimisen parametrin.** Parametrin arvo, joka näyttää paikkamerkiltä, pysyy tekstinä. `customPluralRule`-säännöllä tai mukautetulla `plural`-säännöllä sääntö palauttaa valmiin merkkijonon, joten sen interpoloimaa parametria voidaan siellä luulla paikkamerkiksi.
- **`null` tarkoittaa asettamatonta** propeille `plural`, `number`, `date` ja `relativeDate`. `:plural="null"` kaatoi aiemmin renderöinnin, `:date="null"` renderöi vuoden 1970.
- `plural` laskee kuten `$tc`, `Number`-funktiolla: `1.5` pysyy arvona `1.5` ja ottaa viimeisen muodon, aiemmin se katkaistiin arvoon `1`; `"2 items"` on `NaN`, aiemmin `2`; `""` on `0`. Myös `customPluralRule` näkee arvon `1.5`. Sen muu sopimus on ennallaan: samat argumentit, sen vastausta käytetään sellaisenaan, `null` renderöi tyhjän.
- `hideIfEmpty` koskee propeja `plural`, `number`, `date` ja `relativeDate`. Piilotettu arvo renderöi kommentin, ei tyhjää tekstisolmua, joten testi, joka luki `''`, näkee `<!---->`.
- **Puuttuva avain `html`-propin kanssa on tekstiä.** Avain escapoidaan, koska vain käännös on luotettu ja avain voi tulla pyynnöstä. `defaultValue` on sinun ja pysyy merkintäkoodina.
- `plural`-propin kanssa `defaultValue` tai avain näytetään kokonaisena, kun käännöstä ei löydy, kuten `$tc`-funktiossa: `a | b` ei enää jaeta.
- `defaultValue` korvaa puuttuvan avaimen jokaisessa haarassa, ei avainta itseään, ja `customPluralRule` saa sen getterinsä kautta, kun käännöstä ei löydy. Aiemmin se teki jotain vasta `hideIfEmpty`-propin jälkeen.
- `<i18n-t>` propien `number`, `date` tai `relativeDate` kanssa säilyttää `params`-arvot; ne yhdistetään mukaan.
- `date`- ja `relativeDate`-tuloste sisältää `data-allow-mismatch="text"`: palvelimen ja selaimen välillä eroava kello tai aikavyöhyke ei enää varoita hydraation aikana. Nimetyn slotin vieressä slotin ympärillä oleva teksti on omassa `<span>`-elementissään, koska Vue tarkistaa attribuutin vain elementin ainoasta tekstistä.
- `.innerHTML`- ja `textContent`-attribuutit pudotetaan `innerHTML`-attribuutin mukana.
- `<i18n-t>` ja `<i18n-group>` lukevat aktiivista sanakirjaa, kuten `$t`, eivät reitin osaa. Häädetyt osat (`cacheMaxSize`) eivät enää näytä raakoja avaimia. Poistumissiirtymässä oleva sivu lukee nyt sen, mitä `$t` siellä lukee: uuden sivun sanakirjan, josta puuttuvat haetaan sen omasta, joten molempien sivujen määrittelemä avain näyttää uuden tekstin, ja localen vaihdon jälkeen sen omat avaimet näkyvät raakoina, kunnes se irrotetaan.

### `<i18n-switcher>` ja `<i18n-link>` {#&lt;i18n-switcher>-and-&lt;i18n-link>}

- **Klikkaus kielenvaihtimen linkkiin on yksi navigointi.** Se on tavallinen `<a>`, joka kutsuu `$switchLocale`-funktiota, ei `NuxtLink` plus klikkauskäsittelijä, joten `router-link-active`-luokat ovat poissa. `href` sisältää edelleen `app.baseURL`-osan, ja nykyisen localen linkillä on edelleen `aria-current="page"`. Ctrl/cmd-klikkaus avaa uuden välilehden ja jättää tämän välilehden rauhaan. Linkit säilyttävät kyselyn ja hashin.
- Painike on `type="button"`, joten se ei enää lähetä ympäröivää lomaketta, ja sillä on `aria-expanded`. `aria-haspopup` on poistettu moduulista, paketista `@i18n-micro/vue` ja paketista `@i18n-micro/astro`: se lupasi valikon, ja lista koostuu linkeistä. Escape ja klikkaus ulkopuolelle sulkevat pudotusvalikon; kaksi kielenvaihdinta eivät enää pysy auki yhtä aikaa.
- Kääreellä ja pudotusvalikolla on luokat `i18n-switcher-wrapper` ja `i18n-switcher-dropdown`; painikkeella on `i18n-switcher-button` sekä `language-switcher`, ja sen nimike on `<span>`-elementissä. Oletustyylit käyttävät loogisia CSS-ominaisuuksia (`inset-inline-start`, `margin-inline-start`), ja nuoli on `▾`. Pudotusvalikolla on `z-index: 1000` (aiemmin 10), `min-width: 150px` ja `box-shadow`, kääreellä `vertical-align: middle`. Jokaisella linkillä on `lang` sekä `dir`, kun locale asettaa sen.
- `<i18n-link>`: `https://`, `mailto:` ja `tel:` tunnistetaan kirjainkoosta riippumatta (`HTTPS://x.com`, `Mailto:`). Paljas `report.pdf` tai `index.html` on reitti, ei `https://report.pdf`; `example.com` ja `example.com:8080` pysyvät ulkoisina. Tiedostopääte, joka on myös TLD (`example.md`, `x.zip`), lasketaan tiedostoksi: kirjoita `https://`. `activeStyle` ohittaa loppukauttaviivan, kyselyn ja hashin. Sen tyyppi on nyt `CSSProperties`, joten jotkin tyypitetyt arvot saattavat vaatia muutosta.

### Hookit, pluginit ja tyypit {#hooks-plugins-and-types}

- **`i18n:register` suoritetaan käynnistyksessä vaiheessa `app:created`,** jokaisen pluginin jälkeen niiden välissä suorittamisen sijaan. Pluginin, jonka `order` on yli 1 tai jolla on `enforce: 'post'`, tilaajaa kutsutaan nyt myös käynnistyksessä, mutta se ei enää lue rekisteröityjä avaimia omassa `setup`-funktiossaan. Navigoinnissa hook suoritetaan nyt ennen muiden pluginien `router.beforeEach`-guardeja.
- **`i18n:register` saa täyttämänsä sivun localen.** `hashMode`-tilassa localea vaihtava navigointi välitti aiemmin vanhan localen, ja avaimet päätyivät väärään osaan.
- **`i18n:register` on ajonaikainen hook:** rekisteröi se kutsulla `nuxtApp.hook('i18n:register', …)` pluginissa ilman `@ts-expect-error`-kommenttia. Katso [Hookit](/fi/api/events).
- **`hooks: false` ja `define: false`** kytkevät edelleen osansa pois.
- **Asetuksella `plugin: false` `$defineI18nRoute` pysyy kutsuttavana** eikä tee ajon aikana mitään. Aiemmin se kaatoi sivun.
- `hooks`-asetus ei enää dokumentoi hookeja `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`; niitä ei koskaan laukaistu.
- `const { $defineI18nRoute } = useNuxtApp()` sivulla toimii nyt konfiguraatioilla, jotka käyttävät muuttujia.
- `useI18n()`-funktiolla on enemmän avaimia: `clearCache`, `pluralFunc`, `pluralLocale`. `clearCache` on sen tyypissä.
- `$getRouteName(route)` vastaa sille annetulle reitille. Aiemmin se palautti tyhjän merkkijonon.
- `useI18nLocale()` pudottaa `getLocaleWithServerFallback(serverLocale)`-funktion: kirjoita `getPreferredLocale() ?? serverLocale ?? null`.
- **`$getI18nConfig()` on palvelimella kehitystilassa vain luku -tilassa.** Kirjoitus heittää siellä virheen, ja tuotannossa se ulottuisi jokaiseen pyyntöön.

### Palvelin, build ja käyttöönotto {#server-build-and-deployment}

- **Sivun payload-tiedosto sisältää vain sen, mikä eroaa localen juuresta.** Asiakas lataa juuren kerran ja yhdistää jokaisen sivun sen päälle, joten levy- ja Edge-paketit pienenevät ja toinen sivu maksaa murto-osan ensimmäisestä. `premerged` kirjoittaa nyt tiedoston `__root/<locale>/data.json`, ja `/_locales/<page>/<locale>/data.json` sisältää vain eron: kaiken, mikä lukee näitä tiedostoja suoraan, on yhdistettävä nämä kaksi. Täydellinen sanakirja on edelleen kelvollinen tiedosto, joten isäntä tai `source`-tila, joka tarjoilee sellaisen, toimii edelleen.
- **Sanakirjatiedostot tallennetaan välimuistiin version mukaan.** URL, jossa on nykyinen `?v=`, kiinnitetään vuodeksi Node-palvelimella, muut URL:t validoidaan uudelleen, ja isännän staattinen kopio vastaa `max-age=60`: katso [Välimuistiotsakkeet](/fi/guide/deployment#cache-headers-and-datebuild). `httpCacheControl: false` säilyttää `max-age=0`. Ilman uutta buildia muutettu käännös päätyy selaimeen vasta, kun `v` muuttuu: aseta `NUXT_I18N_DATE_BUILD`.
- **Sanakirjat seuraavat `app.cdnURL`-asetusta.** Selain hakee julkiset payload-tiedostot osoitteesta `<cdnURL>/_locales/...`, kun se aiemmin käytti `app.baseURL`-arvoa: CDN:llä on oltava `_locales/` ja sen on sallittava sivustosi origin (CORS). Katso [Sovelluksen baseURL ja payload-isännät](/fi/guide/deployment#app-baseurl-and-payload-hosts).
- **SSR ei enää pyydä `/_locales`-polkua HTTP:n yli,** joten palvelinmiddleware tai loki kyseisellä reitillä lakkaa näkemästä renderöinnin lukuja. Ulkoinen `apiBaseServerHost` kulkee edelleen HTTP:n yli.
- **Epäonnistunut luku ei enää jää pysyväksi, eikä myöskään 404.** Isännän 404 tarkoittaa, ettei sillä ole tällaista tiedostoa: renderöinti näyttää juurisanakirjan, kuten selain, mitään ei säilytetä, ja tiedosto luetaan heti, kun se ilmestyy. Mikä tahansa muu virhe, 200-vastaus, joka ei ole JSON-objekti, tai lukukelvoton tai vioittunut paikallinen tiedosto ei päädy mihinkään välimuistiin, ja seuraava pyyntö lukee uudelleen: sivun renderöinti kirjaa varoituksen, näyttää raakoja avaimia ja vastaa `503` otsakkeilla `no-store` ja `Retry-After`, joten reittisääntö tai CDN ei säilytä siitä mitään, kun taas selain lukee sanakirjan edelleen hydraatiossa, `/_locales/...` vastaa `503` otsakkeella `no-store`, ja `useTranslationServerMiddleware` antaa `t`-funktion, joka vastaa avaimella tai oletusarvolla. Katkoksen aikana jokainen pyyntö päätyy isännälle, ja isäntä, joka ei lähetä vastausotsakkeita 60 sekuntiin, epäonnistuttaa luvun. Suuren tiedoston hitaalla latauksella ei ole rajaa. Katso [Kun sanakirjaa ei voida lukea](/fi/guide/deployment#when-a-dictionary-cannot-be-read). `/_locales` välittää myös tämän 404:n eteenpäin, kun se aiemmin vastasi `200 {}`.
- **Esirenderöinti, joka ei pysty lataamaan sanakirjaansa, epäonnistuu,** samoin kuin sellainen, jonka isännällä ei ole sivun tiedostoa eikä juuritiedostoa. Reitti on 500, varoitus nimeää localen ja sivun, eikä tiedostoa kirjoiteta; Nuxtin oletusarvoisella `failOnError`-asetuksella build päättyy koodilla 1. Sivu, jolla ei ole omaa tiedostoa juuritiedoston päällä, esirenderöidään juuren kanssa.
- **Build-vaiheessa asetettu isäntä vastaa SSR:ään,** myös oletusarvoisella julkisella kopiolla ja sisäisen polun virhesivulla. Aiemmin julkinen tiedosto vastasi. Ajonaikainen `NUXT_I18N_APP_BASE_SERVER_HOST` ulottuu nyt polkuun `/_locales` ja palvelimen lataajaan, ja renderöinti lukee kumpaa tahansa isäntää kyseisen lataajan kautta.
- **Mukautettu `nitro.output.publicDir` ja mikä tahansa muu rakenne, jossa `public/` ei ole palvelimen vieressä, upottaa payloadit.**
- **`nuxi build --preset <static preset>` esirenderöi kuten `nuxi generate`,** joten se voi kirjoittaa enemmän tiedostoja. `nuxi generate` esirenderöi jokaisen staattisen sivun jokaisella localella, joka sitä palvelee, linkitettynä tai ei, ellei reittisääntö aseta `prerender: false`.
- **`source` tai `publicAssets: false` staattisessa tulosteessa varoittaa.** Selaimelle ei ole mitään luettavaa.
- **Upotusvaroitus on nyt kokotarkistus.** Build varoittaa vain alustan rajan ylittyessä: katso [Pakettirajat](/fi/guide/deployment#bundle-limits-on-edge).
- **`Vary` asetetaan aina, kun vierailija ratkaisee:** jokaisella sivulla strategiassa `no_prefix` sekä polulla `/` ja millä tahansa muulla URL:llä, joka voi ohjautua preferenssin mukaan. Se sisältää `Cookie`, kun evästettä käytetään, ja `autoDetectLanguage`-asetuksella `Accept-Language`. Tarkista CDN:si välimuistiavain: katso [HTML:n välimuistitus](/fi/guide/deployment#caching-html).
- **`/_locales`-välimuistitus muuttui.** Polulla `/{apiBaseUrl}/**` ei ole Nitron reittivälimuistia, ja `s-maxage=60, stale-while-revalidate` -otsake on poistettu. Jos luotit tähän välimuistiin, laita CDN payload-reitin eteen. Tyhjä sanakirja ei ole koskaan `immutable`.
- **Palvelimen välimuisti on oletuksena rajattu:** enintään 1000 merkintää, kun `cacheMaxSize` on asettamatta. `cacheTtl` lasketaan merkinnän tallennushetkestä; luvut eivät enää pidennä sitä.
- **Uusi valinnainen [`cacheStorage`](/fi/guide/performance#shared-cache-for-several-instances):** sanakirjavälimuisti, jonka useampi instanssi jakaa. Asettamattomana mikään ei muutu.

## v2:sta v3:een {#from-v2-to-v3}

### Poistetut asetukset {#removed-options}

```diff
 i18n: {
-  includeDefaultLocaleRoute: true,
+  strategy: 'prefix',
-  fallbackRedirectComponentPath: '~/components/MyRedirect.vue',
-  experimental: { hmr: true, previousPageFallback: true },
+  hmr: true,
 }
```

- `includeDefaultLocaleRoute: true` on `strategy: 'prefix'`; `false` on oletus `prefix_except_default`.
- `fallbackRedirectComponentPath` on poistettu: uudelleenohjaukset tapahtuvat palvelimella ennen renderöintiä ja asiakkaan reittimiddlewaressa. Mukautettu uudelleenohjauslogiikka kuuluu pluginiin, joka asettaa localen, katso [Mukautettu localen tunnistus](/fi/guide/custom-auto-detect).
- `experimental.hmr` on juuritason `hmr`-asetus (oletuksena päällä).
- `previousPageFallback` on poistettu: poistuvan sivun avaimet ratkeavat, kunnes sen siirtymä päättyy, ilman asetusta.

### Locale-tila {#locale-state}

Käytä `useI18nLocale()`-funktiota `useState('i18n-locale')`- ja `useCookie('user-locale')`-kutsujen sijaan:

```diff
- useState('i18n-locale').value = 'fr'
- useCookie('user-locale').value = 'fr'
+ useI18nLocale().setLocale('fr') // state and cookie together
```

### Konfiguraatio ajon aikana {#config-at-runtime}

Lue konfiguraatio, ajonaikaiset ohitukset mukaan lukien, `$getI18nConfig()`-funktiolla:

```diff
- const cookieName = useRuntimeConfig().public.i18nConfig?.localeCookie
+ const { $getI18nConfig } = useNuxtApp()
+ const cookieName = $getI18nConfig().localeCookie
```

### Sisäiset tyyppialiakset {#internal-type-aliases}

Jos IDE:si tai `vue-tsc` ei pysty ratkaisemaan `#i18n-internal/*`-importteja, määritä ne `package.json`-tiedostossasi. Nuxt ratkaisee ne build-vaiheessa, joten tätä tarvitaan harvoin:

```json
{
  "imports": {
    "#i18n-internal/plural": "nuxt-i18n-micro/internals",
    "#i18n-internal/strategy": "nuxt-i18n-micro/internals",
    "#i18n-internal/config": "nuxt-i18n-micro/internals"
  }
}
```
