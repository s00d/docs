title: "Sivun konfiguraatio"
description: "Rajaa sivu tiettyihin localeihin, anna sille omat polut, inline-käännökset tai poista SEO-tagit $defineI18nRoute-funktiolla."
---

`$defineI18nRoute` asettaa yhden sivun i18n-asetukset sivun sisältä. Käytä sitä, kun sivu on olemassa vain joillakin localeilla, tarvitsee oman lokalisoidun polkunsa, sisältää muutaman oman käännöksen tai ei saa saada hreflang- tai canonical-tageja. Moduuli lukee kutsun build-vaiheessa ja leipoo sen generoituihin reitteihin.

## Sivun rajaaminen tiettyihin localeihin {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

Oletusstrategialla `prefix_except_default` generoidaan vain `/product` ja `/de/product`; sivulla ei ole reittiä millään muulla localella. Saman voi asettaa `nuxt.config.ts`-tiedostosta asetuksella [`routeLocales`](/fi/api/module-options#routelocales).

`$defineI18nRoute` on Nuxt-sovelluksen injektio, ei kääntäjämakro: ota se aina `useNuxtApp()`-funktiosta ja kutsu sitä `$`-merkin kanssa. Build-vaihe tunnistaa vain muodon `$defineI18nRoute(`.

## Inline-käännösten lisääminen {#add-inline-translations}

Anna taulukon sijaan objekti. Sen avaimet ovat sallitut localet, ja sen arvot yhdistetään aktiivisen localen sivukohtaiseen sanakirjaan.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Inline-käännökset toimitetaan sivukomponentin sisällä jokaiselle localelle. Suosi [sivukohtaisia käännöstiedostoja](/fi/guide/translations) kaikessa, mikä on muutamaa avainta laajempaa; käytä inline-avaimia itsenäisissä sivuissa ja komponenteissa.

## Lokalisoitujen polkujen asettaminen {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

Asetuksilla `prefix_except_default` ja `defaultLocale: 'en'` tämä tuottaa polut `/welcome` ja `/de/willkommen`. Inline-locale-objektin sisällä oleva `path` tekee saman: `locales: { de: { path: '/willkommen' } }`. Dynaamiset parametrit, sisäkkäiset reitit ja konfiguraatiotason vaihtoehto käsitellään sivulla [Lokalisoidut polut](/fi/guide/custom-locale-routes).

## SEO-tagien poistaminen käytöstä {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

Konfiguraatiotason vaihtoehto on [`routeDisableMeta`](/fi/api/module-options#routedisablemeta). Mitä tagit ovat, kerrotaan [SEO](/fi/guide/seo)-sivulla.

## Mitä build pystyy lukemaan {#what-the-build-can-read}

Build-vaihe löytää kutsun jokaisesta sivutiedostosta ja evaluoi sen argumentin suorittamatta sovellustasi. Se toimii, kun konfiguraatio on:

- literaaliobjekti (merkkijonot, taulukot, sisäkkäiset objektit, template-literaalit, ternäärilausekkeet `process.env.NODE_ENV`-arvon perusteella);
- koottu samassa `<script setup>`-lohkossa määritellyistä vakioista (`const locales = ['en', 'de']`, spread-operaattorit mukaan lukien);
- taulukko objekteja, joilla on `code`-kenttä (`[{ code: 'en' }, { code: 'de' }]`).

Se ei pysty lukemaan toisesta moduulista tuotuja arvoja eikä mitään, mikä vaatii sovellustasi ajon aikana (composablet, `await`, haettu data). Siinä tapauksessa build kirjaa lokiin `Ignored the $defineI18nRoute() config in <file>`, ja sivu säilyttää oletuslocalet ja -reitit.

Ajon aikana kutsu vain yhdistää nykyisen localen inline-käännökset ja yhdistää ne uudelleen, kun locale vaihtuu. `locales`, `localeRoutes` ja `disableMeta` vaikuttavat vain buildin kautta, joten niiden muuttaminen vaatii uuden buildin (kehityspalvelin rakentaa uudelleen tallennettaessa).
