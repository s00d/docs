A modul egyetlen futásidejű (alkalmazás-) hookot hív meg: az `i18n:register`-t. Akkor használd, ha egy plugin vagy modul olyan fordításokat ad hozzá, amelyek nincsenek a `locales/` fájljaidban. A callbacked kap egy `register` függvényt, amely a fordításokat a megjelenített oldalba olvasztja.

## `i18n:register` {#i18nregister}

```ts
'i18n:register': (
  register: (translations: unknown, locale?: string) => void,
  locale: string,
) => HookResult
```

| Argumentum | Leírás |
| --- | --- |
| `register(translations, locale?)` | Mélyen beolvasztja a `translations` objektumot a betöltés alatt álló útvonal oldalchunkjába a `locale` számára (alapértelmezés: a hook `locale` értéke). A már meglévő kulcsok felülíródnak. |
| `locale` | A betöltés alatt álló útvonal locale-ja. |

A hook típusát a `RuntimeNuxtHooks` adja, így a `nuxtApp.hook('i18n:register', …)` hívás nem igényel típuskényszerítést.

## Mikor fut le {#when-it-fires}

A betöltő plugin (`i18n-plugin-loader`) hívja meg:

1. egyszer induláskor, amikor minden plugin lefutott (`app:created`), és még mielőtt az alkalmazás renderelne;
2. a saját `router.beforeEach` hookjában, miután a céloldal fordításai betöltődtek, amikor az útvonal megváltozik — `no_prefix` esetén minden navigációnál.

Minden callbacket és minden `register` hívást megvár, mielőtt az alkalmazás renderelne vagy a navigáció folytatódna, így az oldal már a beolvasztott kulcsokkal renderelődik. [`hooks: false`](/hu/api/module-options#hooks) esetén a hook soha nem hívódik meg.

## Példa {#example}

```ts
// plugins/i18n-extra.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('i18n:register', async (register, locale) => {
    const extra = await $fetch<Record<string, unknown>>(`/api/cms-strings/${locale}`)
    register(extra, locale)
  })
})
```

Ez egy futásidejű hook: egy pluginban regisztráld a `nuxtApp.hook` segítségével, ne a `nuxt.hook`-kal a `nuxt.config`-ban vagy egy modul `setup` függvényében. Egy modul az `addPlugin` segítségével adhat hozzá ilyen plugint.
