# useI18nLocale

## Szignatúra

{/* generated:symbol:useI18nLocale — do not edit; run `pnpm run docs:generate` */}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getLocaleWithServerFallback: (serverLocale?: string | null) => string | null; getPreferredLocale: () => string | null; hashCookie: any; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: any; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Központosított belépési pont az i18n területkezeléshez.
Egyesíti a `useState('i18n-locale')`-t, a területi sütit és a szinkronizációs segédeket.

{/* /generated:symbol:useI18nLocale */}

## Használat

```vue
<script setup>
const {
  locale,
  localeCookie,
  hashCookie,
  validLocales,
  getPreferredLocale,
  getLocale,
  getLocaleWithServerFallback,
  getEffectiveLocale,
  resolveInitialLocale,
  setLocale,
  syncLocale,
  isValidLocale,
} = useI18nLocale()

// Set locale (updates state and cookies)
setLocale('de')

// Get current locale (state → cookie)
const current = getLocale()

// Get valid preferred locale
const preferred = getPreferredLocale()
</script>
```

## API

| Tulajdonság/metódus                             | Típus                               | Leírás                                                                               |
| ----------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------ |
| `locale`                                        | `Ref<string \| null>`               | Reaktív területi állapot (`useState('i18n-locale')`)                                 |
| `localeCookie`                                  | `Ref`                               | Területi süti (ha a `localeCookie` opció engedélyezve van)                           |
| `hashCookie`                                    | `Ref`                               | Süti, amelyet aktív `hashMode` esetén használunk                                     |
| `validLocales`                                  | `string[]`                          | Engedélyezett területkódok a modul konfigurációjából (a `disabled` kizárva)          |
| `getLocale()`                                   | `() => string \| null`              | Aktuális terület: state → süti (vagy hash-süti hash módban)                          |
| `getPreferredLocale()`                          | `() => string \| null`              | A state/süti területe **érvényesítve** a `validLocales` alapján, vagy `null`         |
| `getLocaleWithServerFallback(serverLocale?)`    | `(serverLocale?) => string \| null` | State → süti → opcionális szerverkontextus (a `no_prefix` init során használva)      |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string`             | Fordítások betöltéséhez használt terület: hash módban a state elsőbbséget élvez; egyébként az útvonalból |
| `resolveInitialLocale(options)`                 | `(options) => string`               | Feloldja a területet: state → `serverLocale` → útvonal; szinkronizálja a state-et, ha kell |
| `setLocale(locale)`                             | `(locale: string \| null) => void`  | Beállítja a területet és szinkronizálja a sütikbe                                    |
| `syncLocale(locale)`                            | `(locale: string \| null) => void`  | Csak a sütiket szinkronizálja (nem frissíti a state-et)                              |
| `isValidLocale(locale)`                         | `(locale) => boolean`               | Ellenőrzi, hogy a sztring benne van-e a `validLocales`-ben                           |

### `resolveInitialLocale` opciók

```typescript
interface ResolveInitialLocaleOptions {
  route: unknown
  serverLocale?: string | null
  getLocaleFromRoute: (route?: unknown) => string
}
```

Belsőleg a fő plugin használja indításkor. Egyedi pluginek is meghívhatják, ha alternatív felismerési folyamatot valósítanak meg.

### `getEffectiveLocale`

```typescript
const { getEffectiveLocale } = useI18nLocale()
const { $getLocale } = useNuxtApp()

const locale = getEffectiveLocale(route, (r) => $getLocale(r))
```

Az adott útvonal-objektumhoz visszaadja a fordítások betöltéséhez és üzenetek formázásához használt területet.

## Terület programozott beállítása

Előnyben részesítsd a `useI18nLocale()`-t a közvetlen `useState('i18n-locale')` használat helyett:

```ts
// plugins/i18n-loader.server.ts
import { defineNuxtPlugin } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,

  setup() {
    const { setLocale } = useI18nLocale()
    const detectedLocale = 'ja' // Your detection logic here
    setLocale(detectedLocale)
  },
})
```

<Tip>
A `setLocale()` csak a területi preferenciát frissíti (state + süti). Ha a kliensen az aktív fordítási kontextust is újra szeretnéd tölteni, használd a `$switchLocale()`-t a `useNuxtApp()`-ból vagy a `useI18n()`-ből. Ez különösen a `no_prefix` esetén számít, ahol az URL nem változik. Lásd a [GYIK — területváltás az URL módosítása nélkül](/guides/faq#-switch-locale-without-changing-the-url) részt.
</Tip>
