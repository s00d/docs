# useI18nLocale

## Aláírás

{/* generated:symbol:useI18nLocale — do not edit; run `pnpm run docs:generate` */}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getLocaleWithServerFallback: (serverLocale?: string | null) => string | null; getPreferredLocale: () => string | null; hashCookie: any; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: any; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Központosított belépési pont az i18n területi kezeléshez.
Egyesíti a useState('i18n-locale')-t, a területi sütit és a szinkronizálási segédeket.

{/* /generated:symbol:useI18nLocale */}

## Használat

```vue
<script setup>
const {
  locale,
  localeCookie,
  hashCookie,
  validLocales,
  getPreferredLocale,
  getLocale,
  getLocaleWithServerFallback,
  getEffectiveLocale,
  resolveInitialLocale,
  setLocale,
  syncLocale,
  isValidLocale,
} = useI18nLocale()

// Set locale (updates state and cookies)
setLocale('de')

// Get current locale (state → cookie)
const current = getLocale()

// Get valid preferred locale
const preferred = getPreferredLocale()
</script>
```

## API

| Tulajdonság/metódus                             | Típus                               | Leírás                                                                               |
| ----------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------ |
| `locale`                                        | `Ref<string \| null>`               | Reaktív területi állapot (`useState('i18n-locale')`)                                 |
| `localeCookie`                                  | `Ref`                               | Területi süti (amikor a `localeCookie` opció engedélyezve van)                       |
| `hashCookie`                                    | `Ref`                               | Süti, amelyet a `hashMode` aktív állapotában használunk                              |
| `validLocales`                                  | `string[]`                          | Engedélyezett területi kódok a modul konfigurációból (a `disabled` kizárva)          |
| `getLocale()`                                   | `() => string \| null`              | Aktuális területi beállítás: állapot → süti (vagy hash süti hash módban)             |
| `getPreferredLocale()`                          | `() => string \| null`              | Területi beállítás állapotból/sütiből **érvényesítve** a `validLocales` ellen, vagy `null` |
| `getLocaleWithServerFallback(serverLocale?)`    | `(serverLocale?) => string \| null` | Állapot → süti → opcionális szerver kontextus (a `no_prefix` inicializálás során használt) |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string`             | Területi beállítás a fordítások betöltéséhez: hash mód az állapotot preferálja. Egyébként az útvonalból olvas |
| `resolveInitialLocale(options)`                 | `(options) => string`               | Területi beállítás feloldása: állapot → `serverLocale` → útvonal. Szükség szerint szinkronizálja az állapotot |
| `setLocale(locale)`                             | `(locale: string \| null) => void`  | Beállítja a területi beállítást és szinkronizálja a sütikkel                         |
| `syncLocale(locale)`                            | `(locale: string \| null) => void`  | Csak sütiket szinkronizál (nincs állapot frissítés)                                  |
| `isValidLocale(locale)`                         | `(locale) => boolean`               | Ellenőrzi, hogy a karakterlánc szerepel-e a `validLocales`-ben                       |

### `resolveInitialLocale` opciók

```typescript
interface ResolveInitialLocaleOptions {
  route: unknown
  serverLocale?: string | null
  getLocaleFromRoute: (route?: unknown) => string
}
```

Belsőleg használatos a fő bővítmény által indításkor. Az egyéni bővítmények meghívhatják, amikor alternatív észlelési folyamatokat implementálnak.

### `getEffectiveLocale`

```typescript
const { getEffectiveLocale } = useI18nLocale()
const { $getLocale } = useNuxtApp()

const locale = getEffectiveLocale(route, (r) => $getLocale(r))
```

Visszaadja azt a területi beállítást, amelyet a fordítások betöltéséhez és az üzenetek formázásához használnak egy adott útvonal objektumhoz.

## Programozott területi beállítás

Előnyben részesítsd a `useI18nLocale()`-t a közvetlen `useState('i18n-locale')` használattal szemben:

```ts
// plugins/i18n-loader.server.ts
import { defineNuxtPlugin } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,

  setup() {
    const { setLocale } = useI18nLocale()
    const detectedLocale = 'ja' // Your detection logic here
    setLocale(detectedLocale)
  },
})
```

<Tip>
A `setLocale()` csak a területi beállítás preferenciáját frissíti (állapot + süti). Ahhoz, hogy az aktív fordítási kontextust is újratöltsd a kliensen, használd a `$switchLocale()` metódust a `useNuxtApp()` vagy `useI18n()` segítségével. Ez különösen fontos a `no_prefix` esetén, ahol az URL nem változik. Lásd [GYIK — területi váltás az URL megváltoztatása nélkül](/guides/faq#-switch-locale-without-changing-the-url).
</Tip>
