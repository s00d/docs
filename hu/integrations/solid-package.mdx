Az `@i18n-micro/solid` signalokra épülő i18n-példányt, egy providert, a `useI18n()` függvényt és négy komponenst ad a SolidJS-alkalmazásoknak. Olyan Solid-alkalmazásban használd, amely nem Nuxttal készül. A `t()` JSX-en vagy effecteken belüli olvasásai követik a locale-t, az útvonalat és a szótárakat; a közös modell a [Keretrendszerek](/hu/integrations/overview) oldalon található.

## Telepítés {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer-függőségek: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (opcionális, csak az `@i18n-micro/solid/router` számára). A Solid 2 még nem támogatott.

## Beállítás {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

Az `<I18nProvider>` az `i18n`, `locales`, `defaultLocale` és `routingStrategy` propokat fogadja; egy elhagyott prop megtartja a külső provider értékét, a példányt is beleértve. A `getLocaleName()` és az `<I18nSwitcher>` a `locales` értéket olvassa; nélküle nincs mit felsorolniuk. Az opciók [a példány](/hu/integrations/overview#the-instance) részben találhatók. A példány a [runtime](/hu/integrations/runtime-package) példánya, egyetlen signallal a tárolója felett.

## Fordítás {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

A metódusokat JSX-en vagy egy effecten belül hívd, hogy a Solid követhesse őket, a `localePath` és a `getLocale` függvényt is; a komponens törzsében egyszer kiolvasott érték nem frissül. A példányon az `i18n.locale` és az `i18n.currentRoute` segítségével követhetsz: az `i18n.getLocale()` egyszerű marad, mert az írások olvassák. A locale olvasása csak a locale változására ébred, így egy olyan effect, amely kiolvassa és betölt egy szótárat, egyszer fut le. Ne bontsd szét (destructure) a propokat, és ne tárold a `t('key')` eredményeit egyszerű változókban.

A `useI18n()` a következőket adja vissza: `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (egy accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` és `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Locale váltása {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

A váltás nem tölt be semmit; előbb add hozzá a locale szótárát.

Az `<I18nGroup>` egy prefixelt `t` függvényt ad át egy függvény-gyermeknek. Az `<I18nT>` és a benne lévő `t()` nincs prefixelve:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Útválasztás {#routing}

Az `@solidjs/router` adapter egy alútvonalon található, így a fő belépési pont soha nem importálja a routert. A routeren belül hívd meg, jellemzően a router `root` komponensében, ahol a `useNavigate` és a `useLocation` működik:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

Az adapter az alapértelmezett kivételével minden locale-t prefixel (`/about`, `/de/about`), és az `<I18nLink>` komponenst a router `<A>` elemeként rendereli. A `getCurrentPath` a router reaktív location értékét olvassa, így az aktív linkek és a nyelvváltó követik azt; egy egyéni stratégia ugyanezt éri el, ha ott egy signalt olvas. Figyelj az argumentumok sorrendjére: `(locales, defaultLocale, navigate, location)`. Más routerekhez írj adaptert `getCurrentPath`, `push` és `replace` függvénnyel (mindhárom kötelező) — lásd: [Router-adapter](/hu/integrations/overview#router-adapter).

## SSR {#ssr}

Szerveroldali rendereléshez a `vite-plugin-solid` segítségével buildelj: a csomag `solid` export-feltétele a forráskódot adja át neki, így az a szerverre fordul. Az előre buildelt `dist` csak a böngészőhöz készült. A példánynak nincs `destroy()` metódusa; alkalmazásonként egyet hozz létre, vagy a szerveren kérésenként egyet, és hagyd, hogy a szemétgyűjtő eltakarítsa.
