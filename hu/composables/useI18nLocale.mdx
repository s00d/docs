---
title: "useI18nLocale"
description: "A useI18nLocale olvassa és írja a locale-állapotot és a locale-sütit — ez az egyéni locale-felismerés belépési pontja."
---

A `useI18nLocale()` hozzáférést ad az alkalmazás által választott locale-hoz: az `i18n-locale` állapothoz és a locale-sütihez. Olyan pluginban használd, amely maga ismeri fel a locale-t (domain, felhasználói profil, fejléc), ahelyett, hogy kézzel írnád a `useState('i18n-locale')` értékét vagy a sütit. Az érvényességi ellenőrzések az engedélyezett locale-okat használják, a futásidejű felülírásokat is beleértve.

## Szignatúra {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Központosított belépési pont az i18n locale-kezeléshez.
Egyesíti a useState('i18n-locale') állapotot, a locale-sütit és a szinkronizálási segédeszközöket.

## Visszaadott értékek {#returned-values}

| Tag | Típus | Leírás |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | A `useState('i18n-locale')` ref. |
| `localeCookie` | `Ref<string \| null>` | A [`localeCookie`](/hu/api/module-options#localecookie) süti; egyszerű `{ value: null }`, ha az opció értéke `null`. |
| `hashCookie` | `Ref<string \| null>` | A `hash-locale` süti hash alapú útválasztásnál; egyébként `{ value: null }`. |
| `validLocales` | `string[]` | Az engedélyezett locale-ok kódjai. |
| `setLocale(locale)` | `(locale: string \| null) => void` | Az állapot és a sütik írása. Nem validál, és nem tölt be fordításokat. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | Csak a sütik írása. |
| `getLocale()` | `() => string \| null` | Az állapot, majd a preferencia-süti (hash alapú útválasztásnál a hash-süti). Nincs validálva. |
| `getPreferredLocale()` | `() => string \| null` | Az állapot és a preferencia-süti közül az első **érvényes**, vagy `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | Hash alapú útválasztásnál az állapot, ha be van állítva; egyébként `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, majd egy érvényes állapot, majd `options.serverLocale`, végül az útvonal locale-ja. Az eredményt eltárolja az állapotban, ha az állapot nem érvényes; a kliensen a sütit is beírja. |
| `isValidLocale(locale)` | `(locale) => locale is string` | Megadja, hogy a `locale` szerepel-e a `validLocales` listában. |

A sütik egy évig érvényesek, `path: '/'` és `sameSite: 'lax'` beállítással.

## Példa {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

A modul loader pluginja induláskor beolvassa az állapotot, ezért az azt beállító pluginnak előbb kell lefutnia (`enforce: 'pre'`). Hogyan versenyez az állapot az URL-lel, a sütivel és az `Accept-Language` fejléccel: [Locale-felismerés](/hu/guide/locale-detection). Teljes bemutató: [Egyéni felismerés](/hu/guide/custom-auto-detect).

A `setLocale()` nem váltja át a képernyőn látható fordításokat. Az aktuális oldal locale-jának megváltoztatásához hívd meg a [`$switchLocale()`](/hu/api/methods#$switchlocale) metódust.
