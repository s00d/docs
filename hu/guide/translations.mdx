A fordítások egyszerű JSON-fájlok: locale-onként egy gyökérfájl a közös kulcsokhoz, valamint oldalanként és locale-onként egy fájl az adott oldal kulcsaihoz. Akkor olvasd el, ha oldalakat adsz hozzá, kulcsokat osztasz meg közöttük, vagy tartalékokat állítasz be. Megtudod, melyik fájlba kell egy kulcsnak kerülnie, mit lát egy oldal, és mikor töltődik be az egyes fájlok.

## Felépítés {#layout}

```text
locales/
├── en.json                 # root: menus, footer, buttons
├── de.json
└── pages/
    ├── index/              # pages/index.vue
    │   ├── en.json
    │   └── de.json
    ├── about/              # pages/about.vue
    │   ├── en.json
    │   └── de.json
    └── products-id/        # pages/products/[id].vue
        ├── en.json
        └── de.json
```

- A `locales/pages/` alatti mappa az oldal Nuxt **route neve**: a `pages/products/[id].vue` neve `products-id`, a `pages/blog/[slug]/comments.vue` neve `blog-slug-comments`.
- A kulcsok tetszőleges mélységig egymásba ágyazhatók; a `$t('auth.form.login')` a `{ "auth": { "form": { "login": … } } }` értéket olvassa.
- A `translationDir` áthelyezi a mappát (alapértelmezés `'locales'`, a projekt gyökeréhez képest, a Nuxt 4 `app/` felépítésében is).
- A hiányzó fájlok `{}` tartalommal jönnek létre, amikor a Nuxt feloldja az oldalakat, hacsak nincs beállítva a [`disableWatcher`](/hu/api/module-options#disablewatcher).

## Mit lát egy oldal {#what-a-page-sees}

![Egy kulcs keresési sorrendje a /about oldalon de locale-ban: pages/about/de.json, de.json, pages/about/en.json, en.json. Ezek egyetlen about/de/data.json fájllá fésülődnek össze, amelyet a $t olvas](/images/diagrams/page-dictionary.svg)

Egy oldal szótára a gyökérfájlja és az oldalfájlja mélyen (minden szinten) összefésülve. Ütközéskor az oldalfájl győz:

```json
// locales/en.json
{ "title": "My shop", "nav": { "home": "Home", "cart": "Cart" } }
```

```json
// locales/pages/about/en.json
{ "title": "About us", "nav": { "cart": "Basket" } }
```

```ts
// on /about
t('title') // 'About us'
t('nav.home') // 'Home'   (root)
t('nav.cart') // 'Basket' (page wins)
// on any other page
t('title') // 'My shop'
```

A saját mappa nélküli oldal csak a gyökérszótárt kapja meg. Más oldalak kulcsai nem láthatók.

### Tartalék locale-ok {#fallback-locales}

Az aktív locale-ban hiányzó kulcsot a modul a tartalék locale-ból veszi, mielőtt magát a kulcsot jelenítené meg:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'de-at', iso: 'de-AT', fallbackLocale: 'de' },
    ],
    defaultLocale: 'en',
    fallbackLocale: 'en', // global, for every locale
  },
})
```

- Egy locale saját `fallbackLocale` értékét a modul a lánc végéig követi: `de-at` → `de` → `en`.
- A globális `fallbackLocale` a leggyengébb réteg, minden lánc alatt.
- A lánc minden locale-ja hozzáadja a gyökérfájlját, majd az oldalfájlját, a leggyengébb tartaléktól az aktív locale felé haladva. Így az aktív locale gyökérfájlja erősebb, mint egy tartalék locale oldalfájlja.

Tartalék nélkül egy hiányzó kulcs magaként a kulcsként renderelődik (`'nav.home'`), és fejlesztéskor figyelmeztetést naplóz a böngészőkonzolban ([`missingWarn`](/hu/api/module-options#missingwarn)).

## Megosztás és más források {#sharing-and-other-sources}

| Igény | Beállítás |
| --- | --- |
| Csak gyökérfájlok, `pages/` mappák nélkül | [`disablePageLocales: true`](/hu/api/module-options#disablepagelocales) |
| Két oldal egyetlen oldalmappát olvas | [`routesLocaleLinks`](/hu/api/module-options#routeslocalelinks): `{ 'about-us': 'about' }` |
| Közös gyökérfájlok egy másik mappában | [`additionalTranslationDirs`](/hu/api/module-options#additionaltranslationdirs): `['common']` (a fő `translationDir` győz) |
| Kulcsok egy Nuxt rétegből | A rétegek fájljai összefésülődnek, a projekt saját fájljai győznek. Lásd: [Rétegek](/hu/guide/layers) |
| Futásidőben hozzáadott kulcsok | az [`i18n:register`](/hu/api/events) hook, `$mergeTranslations`, `$setTranslation` |
| Kulcsok közvetlenül egy oldalkomponensben | `$defineI18nRoute({ locales: { en: { … } } })`, lásd: [Oldalkonfiguráció](/hu/guide/per-component-translations) |

## Hogyan tölti be egy oldal a szótárát {#how-a-page-loads-its-dictionary}

![A locale JSON-fájlokból payload-fa épül, amely Node-on a public/ mappában, Edge-en a szerver assetek között tárolódik, egy szerveroldali betöltő olvassa, majd a szerveren a $t használja, a böngészőben pedig a $t számára lekérődik](/images/diagrams/translation-pipeline.svg)

A modul oldalanként és locale-onként egy payloadot épít: `/{apiBaseUrl}/{page}/{locale}/data.json` (alapértelmezés szerint `/_locales/about/de/data.json`).

1. **Szerveroldali renderelés.** A Nitro felismeri a locale-t, az oldal pedig közvetlenül a szerveroldali betöltőből tölti be a payloadját, HTTP-kérés nélkül. A szótár nem kerül bele a HTML payloadba, így az oldalak kicsik maradnak.
2. **Hidratálás.** A böngésző lekéri ugyanazt a payloadot. A szerver már kiírt hozzá egy `<link rel="preload">` taget, így a lekérés a HTML-lel együtt indul.
3. **Navigáció.** A következő oldal payloadja lecseréli a szótárt. A távozó oldal kulcsai addig feloldódnak, amíg el nem tűnik (az oldalátmenet végéig vagy a `page:finish` eseményig), így egy elhalványuló oldalon nem villannak fel nyers kulcsok. Egy be nem töltődő chunk (hálózati hiba, 4xx vagy 5xx, nem objektum törzs) a helyén hagyja az aktuális szótárt, és a következő navigáció újra betölti. A sikertelen locale-váltás ugyanígy viselkedik: a `$switchLocale` `false` értékkel oldódik fel, és újrahívása, vagy a nyelvváltóra való újabb kattintás újrapróbálja. Az előtagos stratégiáknál az URL addigra már megváltozott, így a `lang` és a `$getLocale()` az URL locale-ját mutatja, miközben a régi szövegek a képernyőn maradnak.
4. **Gyorsítótár.** A betöltött payloadok a szerveren és a böngészőben is gyorsítótárazódnak; a méret- és TTL-beállítások a [Teljesítmény](/hu/guide/performance) oldalon találhatók.

A `translationPayloads.mode` dönti el, hogyan épülnek a payloadok. A `'premerged'` (alapértelmezés) buildeléskor minden oldal × locale fájlt kiír. A `'source'` megtartja a forrásfájlokat, és kérésenként fésüli össze őket, ami nagy katalógusoknál Edge célpontokon kisebb méretet eredményez. Mindkettő ugyanazokat a szótárakat adja. Hogy a fájlok az egyes telepítési célpontokon hová kerülnek, az a [Telepítés](/hu/guide/deployment) oldalon olvasható.

## Szerkesztés fejlesztés közben {#editing-in-development}

A `nuxt dev` élőben olvassa a fájlokat. Egy fordítási fájl mentése helyben frissíti a nyitott oldal szótárát: nincs újratöltés, az eltávolított kulcsok eltűnnek, és egy gyökérfájl módosítása minden oldalra eljut. Egy hibás JSON-fájl az útvonalával együtt figyelmeztetést naplóz, és üresként kezelődik. Állítsd be a [`hmr: false`](/hu/api/module-options#hmr) értéket, ha inkább kézzel frissítenél.
