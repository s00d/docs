title: "Oldalkonfiguráció"
description: "Korlátozz egy oldalt bizonyos locale-okra, adj neki egyéni útvonalakat, beágyazott fordításokat, vagy kapcsold ki a SEO-címkéit a $defineI18nRoute segítségével."
---

A `$defineI18nRoute` egyetlen oldal i18n-beállításait adja meg magából az oldalból. Akkor használd, ha egy oldal csak bizonyos locale-okban létezik, saját lokalizált útvonalra van szüksége, néhány saját fordítást tartalmaz, vagy nem kaphat hreflang/canonical címkéket. A modul build időben beolvassa a hívást, és beépíti a generált útvonalakba.

## Oldal korlátozása bizonyos locale-okra {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

Az alapértelmezett `prefix_except_default` stratégia mellett csak a `/product` és a `/de/product` generálódik; az oldalnak egyetlen más locale-ban sincs útvonala. Ugyanez a `nuxt.config.ts`-ből is beállítható a [`routeLocales`](/hu/api/module-options#routelocales) segítségével.

A `$defineI18nRoute` egy Nuxt alkalmazás-injekció, nem fordítói makró: mindig a `useNuxtApp()`-ból vedd, és a `$` jellel hívd meg. A build lépés csak a `$defineI18nRoute(` alakot ismeri fel.

## Beágyazott fordítások hozzáadása {#add-inline-translations}

Tömb helyett adj át egy objektumot. A kulcsai az engedélyezett locale-ok, az értékei pedig beolvadnak az oldal szótárába az aktív locale-hoz.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

A beágyazott fordítások minden locale esetén az oldalkomponensen belül kerülnek kiszállításra. Néhány kulcsnál nagyobb mennyiséghez inkább [oldalfordítási fájlokat](/hu/guide/translations) használj; a beágyazott kulcsokat tartsd meg az önálló oldalakhoz és komponensekhez.

## Lokalizált útvonalak beállítása {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

`prefix_except_default` és `defaultLocale: 'en'` esetén ez a `/welcome` és a `/de/willkommen` útvonalakat hozza létre. Egy beágyazott locale-objektumon belüli `path` ugyanezt teszi: `locales: { de: { path: '/willkommen' } }`. A dinamikus paramétereket, a beágyazott útvonalakat és a konfigurációs szintű alternatívát a [Lokalizált útvonalak](/hu/guide/custom-locale-routes) oldal tárgyalja.

## SEO-címkék kikapcsolása {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

A konfigurációs szintű alternatíva a [`routeDisableMeta`](/hu/api/module-options#routedisablemeta). Hogy mik ezek a címkék, azt a [SEO](/hu/guide/seo) oldal ismerteti.

## Mit tud beolvasni a build {#what-the-build-can-read}

A build lépés minden oldalfájlban megkeresi a hívást, és az alkalmazás futtatása nélkül kiértékeli az argumentumát. Akkor működik, ha a konfiguráció:

- literális objektum (karakterláncok, tömbök, beágyazott objektumok, template literálok, ternáris kifejezések a `process.env.NODE_ENV` alapján);
- ugyanabban a `<script setup>` blokkban deklarált konstansokból épül fel (`const locales = ['en', 'de']`, a spread operátort is beleértve);
- `code` mezővel rendelkező objektumok tömbje (`[{ code: 'en' }, { code: 'de' }]`).

Nem tudja beolvasni a más modulból importált értékeket, sem semmit, amihez futás közben az alkalmazásodra van szükség (composable-ök, `await`, lekért adatok). Ilyenkor a build a `Ignored the $defineI18nRoute() config in <file>` üzenetet naplózza, és az oldal megtartja az alapértelmezett locale-okat és útvonalakat.

Futásidőben a hívás csak az aktuális locale beágyazott fordításait olvasztja be, és a locale változásakor újra beolvasztja őket. A `locales`, a `localeRoutes` és a `disableMeta` csak a buildon keresztül lép érvénybe, így módosításuk újrabuildelést igényel (a fejlesztői szerver mentéskor újrabuildel).
