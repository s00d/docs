`meta: true` esetén (ez az alapértelmezés) minden lokalizált oldal megkapja a `<html lang dir>` attribútumokat, egy canonical linket, `hreflang` alternatívákat, `x-default` linket és Open Graph locale tageket. Erre az oldalra akkor van szükséged, ha be akarod állítani a nyilvános origint, finomhangolnád, mely locale-ok jelenjenek meg a tagekben, vagy egy oldalon felülírnád őket. A legtöbb oldalnak csak egy `site.url` vagy `metaBaseUrl` beállításra és helyes `iso` kódokra van szüksége.

## Minimális beállítás {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

Ekkor a `/de/about` ezt rendereli:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Szövegirány {#text-direction}

A `<html dir>` a locale `dir` értékéből származik. Ha nincs ilyen, a jobbról balra írt nyelvek `rtl` értéket kapnak, az `iso` (vagy a `code`) alapján: arab, héber, perzsa, urdu és néhány további, valamint minden RTL írásrendszerű tag, például az `az-Arab`. Minden más locale nem kap `dir` attribútumot, amit a böngészők `ltr`-ként értelmeznek.

<Warning>

**A `dir: 'auto'` nagy oldalakon feldolgozási időbe kerül** — a `<html>` elemen lévő `auto` miatt a böngészőnek feldolgozás közben a tartalomból kell kitalálnia az irányt. Chromiumban ez a költség gyorsabban nő, mint az oldal: körülbelül 100 ms 5000 elemnél és 1 s 20 000 elemnél. Csak olyan kis oldalon használd, amelynek nyelvét nem ismerheted.

</Warning>

## Milyen tageket kapsz {#which-tags-you-get}

- **hreflang**: egy tag minden olyan locale-hoz, amely kiszolgálja az oldalt, értéke az `iso` (vagy a `code`, ha az `iso` hiányzik), az URL-je ugyanazzal a queryvel, mint a canonical. Az [Oldalkonfigurációval](/hu/guide/per-component-translations) vagy `routeLocales` beállítással korlátozott oldal csak a saját locale-jait sorolja fel. A [`hreflangBaseLanguage: true`](/hu/api/module-options#hreflangbaselanguage) az első regionális locale-hoz a puszta nyelvet is hozzáadja (`es-ES` → `es`).
- **x-default**: az alapértelmezett locale URL-je, csak ha az alapértelmezett locale kiszolgálja az oldalt.
- **og:locale**: az `iso` értékből származtatva (`en-US` → `en_US`). Állítsd be az `og` értéket a locale-on, ha a leképezés nem közvetlen, például `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; ha egyik sincs megadva, nem íródik ki `og:locale`, és fejlesztői módban figyelmeztetés jelenik meg.
- **canonical / og:url**: az aktuális URL query paraméterek nélkül, kivéve a [`canonicalQueryWhitelist`](/hu/api/module-options#canonicalquerywhitelist) listában szereplőket (alapértelmezés: `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Stratégia szerint:

| Stratégia | hreflang és x-default | canonical, og:url, og:locale, html attribútumok |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | igen | igen |
| `no_prefix` | nem (egyetlen URL szolgál ki minden locale-t) | igen |

## A nyilvános origin beállítása {#set-the-public-origin}

Az abszolút URL-ek az alábbiak közül az elsőt használják:

1. [`metaBaseUrl`](/hu/api/module-options#metabaseurl);
2. `site.url` a `nuxt-site-config` csomagból (az `@nuxtjs/seo` telepíti);
3. a kérés originje, hozzáfűzve az `app.baseURL` értéket.

Rögzítsd az első kettő egyikét.

<Warning>

A kérés originjére épülő tartalék megoldás az `X-Forwarded-Host` és az `X-Forwarded-Proto` fejlécet olvassa, mert a [`metaTrustForwardedHost`](/hu/api/module-options#metatrustforwardedhost) és a `metaTrustForwardedProto` alapértéke `true`. Ez csak olyan proxy mögött biztonságos, amely felülírja ezeket a fejléceket; különben egy kliens választhatja meg a hosztot a canonical linkjeidben, és egy gyorsítótár továbbadhatja ezt az oldalt.

Ha az alkalmazás közvetlenül elérhető, rögzítsd a `metaBaseUrl` értéket: szemben azzal, ha mindkét beállítást `false` értékre állítod, ez a hamisított `Host` fejlécet is figyelmen kívül hagyja. Lásd: [Proxy vagy CDN mögött](/hu/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

A tartalék megoldás akkor hasznos, ha egyetlen telepítés több domainre válaszol: a `https://site-a.com/en/about` és a `https://site-b.com/en/about` egyaránt a saját originjét kapja.

Ha a locale-okon `baseUrl` van megadva, egy ismert hoszt a saját `baseUrl` értékét használja a `metaBaseUrl` és a `site.url` helyett, így a canonical és az `og:url` azon a domainen marad, a `hreflang` pedig minden locale-t a saját domainjére irányít. Bármely más hoszt a `metaBaseUrl` értéket használja, ennek hiányában az alapértelmezett locale `baseUrl` értékét, ennek hiányában a `site.url` értéket, így egy hamisított `Host` nem érheti el a tageidet. Ha egyik sincs beállítva, a kérés originjére épülő tartalék megoldás marad, és a build figyelmeztet. Lásd: [Rétegek és domainek](/hu/guide/layers#multiple-domains).

## Locale-ok vagy oldalak kihagyása {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Ha az alapértelmezett locale `seo: false` beállítású, nem íródik ki `x-default`. A tagek egy oldalon történő kikapcsolásához használd a `disableMeta` beállítást az [Oldalkonfigurációban](/hu/guide/per-component-translations#turn-off-seo-tags), vagy a [`routeDisableMeta`](/hu/api/module-options#routedisablemeta) beállítást a konfigurációban.

## Tagek felülírása egy oldalon {#override-tags-on-one-page}

Olyan CMS-tartalomnál, ahol csak néhány fordítás létezik, vagy az URL-ek egy API-ból jönnek, cseréld le a generált tageket a [`useI18nHead`](/hu/composables/useI18nHead) segítségével:

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

A `replace` a `canonical`, `xDefault`, `ogLocale` és `ogUrl` értékeket is beállíthatja vagy eltávolíthatja; a `disable` teljes csoportokat távolít el (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Adj át gettert, hogy az értékek locale-váltás után újraszámolódjanak. Locale-onkénti slugokhoz először állítsd be a `$setI18nRouteParams` értéket ([Lokalizált útvonalak](/hu/guide/custom-locale-routes#per-locale-slugs)), és a generált alternatívák már azokat használják.

## Záró perjel {#trailing-slash}

A `$localePath`, a `$switchLocalePath`, a `$switchLocaleRoute` route objektuma, az `<i18n-link>`, az `<i18n-switcher>`, a locale-átirányítások és a SEO URL-ek egyetlen perjelszabályt követnek: alapértelmezés szerint az `experimental.defaults.nuxtLink.trailingSlash` értéket, vagy az i18n konfiguráció [`trailingSlash`](/hu/api/module-options) beállítását, ha az i18n útvonalaknak el kell térniük.

## Nuxt SEO {#nuxt-seo}

A [`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) a `nuxt-site-config` 4+ verzióján keresztül működik együtt ezzel a modullal. A `nuxt-i18n-micro` modult sorold fel elsőként, hogy a site config beolvashassa a locale-okat, és egyszer állítsd be a `site.url` értéket — ez a fenti tageket is táplálja.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

A lefordított oldalnév és leírás a locale-fájljaid `nuxtSiteConfig.name` / `nuxtSiteConfig.description` kulcsaiból származik. A `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` hiba azt jelenti, hogy az `@nuxtjs/seo` 3-asnál régebbi; frissítsd ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
