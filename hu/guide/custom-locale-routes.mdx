title: "Lokalizált útvonalak"
description: "Adj egy oldalnak locale-onként eltérő URL-t a localeRoutes vagy a globalLocaleRoutes segítségével, dinamikus paraméterekkel és locale-onkénti slugokkal együtt."
---

Alapértelmezés szerint minden locale ugyanazon az útvonalon szolgálja ki az oldalt: `/en/about`, `/de/about`. A lokalizált útvonalakkal minden locale a saját szavait használhatja, például `/de/ueber-uns`, miközben az oldalfájl ugyanaz marad. Ezeket az oldalban a `$defineI18nRoute` segítségével állíthatod be, vagy egyszerre több oldalra a `nuxt.config.ts` fájlban.

## Az oldalban {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

`prefix_except_default` és `defaultLocale: 'en'` esetén az oldal a `/about`, a `/de/ueber-uns` és a `/fr/a-propos` címen válaszol. Az a locale, amelyhez nincs bejegyzés, megtartja az alapértelmezett útvonalat. Az útvonalakat a locale-kód nélkül írd: az előtagot a [stratégia](/hu/guide/strategy) adja hozzá, a locale-kóddal kezdődő útvonal pedig figyelmeztetést naplóz. Hogy a hívás még mit fogad el, az [Oldalkonfiguráció](/hu/guide/per-component-translations) oldalon olvasható.

## A nuxt.config fájlban {#in-nuxt-config}

A [`globalLocaleRoutes`](/hu/api/module-options#globallocaleroutes) ugyanezt teszi bármely oldalra, az útvonala szerint kulcsolva (vagy a route neve szerint, ha kezdő perjel nélkül írod):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

Ha egy oldal beállítja a `localeRoutes` értéket, és a `globalLocaleRoutes` ugyanazzal a kulccsal rendelkezik, a konfigurációs bejegyzés győz.

## Dinamikus paraméterek {#dynamic-params}

A paramétereket bármely Nuxt-formában írhatod: `[id]`, `[[page]]`, `[...slug]` vagy `:id()`. A paraméterneveknek egyezniük kell az oldalfájléval.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

A beágyazott oldalak abszolút gyermekútvonalat (`/ueber-uns/team`) vagy a szülő lokalizált útvonalához képest relatív útvonalat (`team`) kapnak.

## Hivatkozás lokalizált oldalakra {#linking-to-localized-pages}

A linkek a cél locale lokalizált útvonalára oldódnak fel, akár route nevet, akár egyszerű útvonalat adsz át:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

A route nevek a fájlútvonalból származnak (a `pages/about/team.vue` neve `about-team`), hacsak nem adsz meg egyet a `definePageMeta({ name })` segítségével.

## Locale-onkénti slugok {#per-locale-slugs}

Ha maga a slug is locale-onként eltér (`/our-products/red-shoe` vs. `/de/unsere-produkte/roter-schuh`), az adatok betöltése után a `$setI18nRouteParams` segítségével add meg a nyelvváltónak, mely paramétereket használja:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

Ezután a `$switchLocalePath('de')` és az `<i18n-switcher>` a `/de/unsere-produkte/roter-schuh` címre hivatkozik. A kulcsok locale-kódok, az értékek név szerinti paraméterek (ahogy az oldalfájlban).

A layoutban lévő nyelvváltó azelőtt renderelődik, hogy az oldal aszinkron setupja idáig érne, ezért a renderelés végén a modul átírja az `<i18n-switcher>` linkjeit, az `app.vue` fájlban és az oldalban egyaránt. Így a szerver HTML-je, a JavaScript nélküli látogató és az első kliensoldali renderelés megegyezik. Ehhez a paramétereket SSR közben állítsd be: `lazy` vagy `server: false` esetén a linkek csak a hidratálás után változnak. A Nuxt SSR streaming a HTML-t a paraméterek ismerete előtt küldi el, így ebben az esetben az első HTML linkjei az URL saját paramétereit tartják meg.

Csak a nyelvváltó saját linkjei íródnak át. Egy kézzel írt `$switchLocalePath` linknek a paraméterek beállítása után kell renderelődnie, ezért abba az oldalba tedd, amely beállítja őket, egy `await` után. Egy layoutban először renderelődik: a szerver HTML-je az URL paramétereit tartja meg, és a hidratálás eltérésre figyelmeztet. Ott az `<i18n-switcher>` komponenst használd, a megjelenéshez a slotjaival és a `custom*Style` propjaival.

A paraméterek ahhoz az oldalhoz tartoznak, amely beállította őket:

- Eldobódnak, amikor egy másik útvonalra való navigáció véglegesül, így minden oldal a sajátját állítja be. Egy megszakított navigáció a helyükön hagyja őket.
- A `$setI18nRouteParams` függvényt a `setup` során vedd a `useNuxtApp()` vagy a `useI18n()` hívásból, akkor is, ha később egy `useAsyncData` handlerben hívod. Így a függvény ismeri az oldalát: ha a látogató már távozott, egy késői hívás nem csinál semmit.
- `keepalive` esetén egy oldal visszakapja az általa beállított paramétereket, amikor a látogató visszatér. A `useI18nHead` ugyanígy működik.

## A pages:extend hookban hozzáadott route-ok {#routes-added-in-pagesextend}

A `pages:extend` hookban hozzáadott route-oknak nincs oldalfájljuk, amelyből a `$defineI18nRoute` olvasható lenne, és gyakran többen osztoznak egyetlen wrapper komponensen. Egy `name` nélkül hozzáadott route azt a nevet kapja, amelyet a Nuxt az útvonalának adna (a `/a/:id()` neve `a-id` lesz), így a nyelvi linkek elérik, kivéve ha egy másik route-nak már ez a neve; ilyenkor adj meg explicit `name` értéket. Tarts egyetlen listát, és bontsd oldalakra és route név szerint kulcsolt `globalLocaleRoutes` bejegyzésekre az `@i18n-micro/utils/split-locale-routes` csomag `splitLocaleRoutes` függvényével (add hozzá a csomagot a függőségeidhez):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

Ne tegyél lokalizált útvonalakat a `route.meta` objektumba: bekerülnének a kliensoldali route-táblába.
