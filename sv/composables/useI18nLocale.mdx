---
title: "useI18nLocale"
description: "useI18nLocale läser och skriver locale-tillståndet och locale-cookien — ingångspunkten för anpassad identifiering av locale."
---

`useI18nLocale()` ger åtkomst till den locale som appen har valt: tillståndet `i18n-locale` och locale-cookien. Använd den i ett plugin som själv identifierar locale (domän, användarprofil, header) i stället för att skriva `useState('i18n-locale')` eller cookien för hand. Dess giltighetskontroller använder de aktiverade locales, inklusive åsidosättningar vid körning.

## Signatur {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Centraliserad ingångspunkt för hantering av locale i i18n.
Kombinerar useState('i18n-locale'), locale-cookien och synkroniseringsverktyg.

## Returnerade värden {#returned-values}

| Medlem | Typ | Beskrivning |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | Ref-objektet `useState('i18n-locale')`. |
| `localeCookie` | `Ref<string \| null>` | Cookien [`localeCookie`](/sv/api/module-options#localecookie); ett enkelt `{ value: null }` när alternativet är `null`. |
| `hashCookie` | `Ref<string \| null>` | Cookien `hash-locale` vid hash-routning; annars `{ value: null }`. |
| `validLocales` | `string[]` | Koderna för de aktiverade locales. |
| `setLocale(locale)` | `(locale: string \| null) => void` | Skriver tillståndet och cookies. Validerar inte och läser inte in översättningar. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | Skriver endast cookies. |
| `getLocale()` | `() => string \| null` | Tillståndet, sedan preferenscookien (hash-cookien vid hash-routning). Valideras inte. |
| `getPreferredLocale()` | `() => string \| null` | Den första **giltiga** av tillståndet och preferenscookien, eller `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | Tillståndet vid hash-routning när det är satt; annars `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, sedan ett giltigt tillstånd, sedan `options.serverLocale`, sedan routens locale. Sparar resultatet i tillståndet när tillståndet inte är giltigt; på klienten skrivs även cookien. |
| `isValidLocale(locale)` | `(locale) => locale is string` | Om `locale` finns i `validLocales`. |

Cookies gäller i ett år, med `path: '/'` och `sameSite: 'lax'`.

## Exempel {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

Modulens laddarplugin läser tillståndet när det startar, så ett plugin som sätter det måste köras först (`enforce: 'pre'`). Hur tillståndet konkurrerar med URL:en, cookien och `Accept-Language`: [Identifiering av locale](/sv/guide/locale-detection). Fullständig genomgång: [Anpassad identifiering](/sv/guide/custom-auto-detect).

`setLocale()` byter inte översättningarna på skärmen. För att ändra locale för den aktuella sidan anropar du [`$switchLocale()`](/sv/api/methods#$switchlocale).
