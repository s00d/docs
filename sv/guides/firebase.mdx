# 🔥 Distribution till Firebase AppHosting

## 📖 Introduktion

Firebase AppHosting är en kraftfull plattform för att distribuera Nuxt-applikationer med serverlös infrastruktur. När du distribuerar applikationer med `nuxt-i18n-micro` kan du dock stöta på specifika problem relaterade till hur JSON-översättningsfiler levereras. Denna guide tillhandahåller omfattande lösningar för att säkerställa att dina översättningar fungerar korrekt i produktion.

## ⚠️ Vanliga problem

### Översättningsfiler tillämpas inte

**Symptom:**

- ✅ Översättningar fungerar perfekt i utveckling (`nuxt dev`)
- ❌ Efter distribution till Firebase AppHosting laddas JSON-filer men översättningar tillämpas inte
- ❌ Inga fel visas i konsolen
- ❌ Översättningsfiler syns i Network-fliken men har felaktig `Content-Type: text/html` i stället för `application/json`

**Grundorsak:**

Firebase AppHosting (och andra plattformar som använder Nitro-prerendering) kan leverera prerendrade JSON-filer med felaktiga MIME-typer. När webbläsaren tar emot JSON-filer med `Content-Type: text/html` kan den inte tolka dem korrekt, vilket gör att översättningar misslyckas tyst.

## ✅ Lösningar

### Lösning 1: Konfiguration av route-regler (rekommenderas)

Den enklaste lösningen är att lägga till explicita headers för översättningsrutter i din `nuxt.config.ts`:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**Fördelar:**

- ✨ Enkel konfiguration
- 🚀 Förbättrar prestandan med korrekt caching
- 🔒 Fungerar över alla distributionsplattformar

### Lösning 2: Anpassad API-bas-URL

Om du använder en anpassad `apiBaseUrl` (endast sökvägsprefix), justera route-reglerna därefter:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### Lösning 3: Firebase-specifik konfiguration

Skapa eller uppdatera din `firebase.json`-fil i projektroten:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```


### Lösning 4: Konfiguration av Firebase Functions

För distribution med Firebase Functions, se till att din `functions/package.json` inkluderar nödvändiga beroenden:

```json
{
  "name": "functions",
  "type": "module",
  "engines": {
    "node": "18"
  },
  "dependencies": {
    "firebase-admin": "^12.0.0",
    "firebase-functions": "^5.0.0"
  }
}
```

## 🔍 Felsökning

### Aktivera felsökningsläge

Lägg till felsökningsloggning för att identifiera problem:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

Detta ger detaljerade loggar om:

- 📝 Laddning av översättningsfiler
- 🔄 Cache-operationer
- ⚠️ Laddningsfel

### Kontrollera Network-fliken

1. Öppna DevTools → Network-fliken
2. Filtrera efter "data.json"
3. Klicka på en översättningsfilförfrågan
4. Verifiera **Response Headers**:
   - ✅ `Content-Type: application/json` (korrekt)
   - ❌ `Content-Type: text/html` (felaktig — behöver åtgärdas)

### Verifiera prerender-utdata

Efter bygget, kontrollera att översättningsfiler har genererats:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

Du bör se `data.json` för varje lokal under varje sida.

## 🚀 Byggkonfiguration

### Nitro-preset

För Firebase AppHosting, se till att du använder rätt preset:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### Prerender-konfiguration

Konfigurera prerendering för optimal prestanda:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

      { code: 'zh', iso: 'zh-CN', dir: 'ltr' },
      { code: 'ko', iso: 'ko-KR', dir: 'ltr' },
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',

## ✅ Kontrollistan för verifiering

Efter att ha tillämpat åtgärderna, verifiera att allt fungerar:

- [ ] Bygget slutförs utan fel
- [ ] JSON-översättningsfiler ligger i `.output/public/_locales/\{page\}/\{locale\}/data.json`
- [ ] Network-fliken visar `Content-Type: application/json` för översättningsfiler
- [ ] Översättningar visas korrekt vid första sidladdning
- [ ] Inga hydration-mismatches i konsolen
- [ ] Språkbyte fungerar korrekt
- [ ] SEO-metataggar genereras korrekt

## 🔄 Distributionsflöde

### 1. Förbered bygget

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. Distribuera till Firebase

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. Verifiera distributionen

1. Besök din distribuerade webbplats
2. Öppna DevTools → Network-fliken
3. Navigera till en sida
4. Kontrollera att `/_locales/index/en/data.json` (eller din standardlokal) laddas med:
   - Status: 200
   - Content-Type: application/json
   - Svaret innehåller giltig JSON

## 🔧 Felsökning

### Problem: 404-fel för översättningsfiler

**Lösning:** Se till att översättningsfiler kopieras till utdatakatalogen:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### Problem: Översättningar fungerar på vissa sidor men inte andra

**Lösning:** Kontrollera om sidspecifika översättningar genereras:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

Om sidspecifika översättningar saknas, se till att `disablePageLocales` inte är satt till `true`:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### Problem: Långsam laddning av översättningar

**Lösning:** Optimera caching och förladdning:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## 💡 Tips

1. **Testa alltid i en produktionsliknande miljö** innan distribution
2. **Använd felsökningsläge** under initial uppsättning för att fånga problem tidigt
3. **Övervaka cache-träffkvoter** för att optimera prestandan
4. **Håll översättningsfiler små** för snabbare laddning
5. **Använd korrekta cache-headers** för att minska serverbelastningen

## ⚡ Prestandaoptimering

### Aktivera komprimering

Firebase hanterar automatiskt Gzip/Brotli-komprimering, men se till att ditt bygge är optimerat:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### Lazy-ladda översättningar

`Nuxt I18n Micro` lazy-laddar automatiskt översättningar per sida. Översättningar laddas endast när de behövs, vilket minskar den initiala bundle-storleken. Detta är inbyggd funktionalitet — ingen ytterligare konfiguration krävs.

För att optimera ytterligare:

- Använd `disablePageLocales: false` (standard) för att aktivera sidspecifika översättningar
- Håll rotnivåöversättningar minimala
- Använd ruttspecifika översättningsfiler för sidinnehåll

<Tip>
Modulen sätter automatiskt korrekta `Content-Type`-headers från och med version **v3.0.0+**. Om du upplever problem, uppdatera till senaste versionen:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
