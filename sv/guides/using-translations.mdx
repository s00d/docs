# Använda översättningar i komponenter

När modulen är installerad och konfigurerad kan du visa översättningar genom att anropa `$t('your_key')` i dina Vue-mallar och skript.

## 1. Rotnivåfiler och sidspecifika översättningsfiler

1. **Rotnivåöversättningar** ligger direkt under mappen `/locales` (till exempel `/locales/en.json`, `/locales/fr.json`). Vid byggtid slås de automatiskt samman med varje sidspecifik fil så att de är tillgängliga på alla sidor.
2. **Sidspecifika** översättningar ligger under `/locales/pages/...`, som matchar din Nuxt-sidmappstruktur:

```text
locales/
├── en.json
├── fr.json
└── pages/
    └── dir1/
        ├── en.json
        └── fr.json

```

## 2. Mallanvändning med `$t`

I dina `.vue`-filer kan du använda `$t` direkt i mallen:

```vue
<template>
  <div>
    <!-- Root-level translation (available on all pages) -->
    <p>{{ $t('test_key') }}</p>
    <!-- Displays: Hello World! -->

    <!-- Page-specific translation (if this page is /dir1) -->
    <p>{{ $t('local_key') }}</p>
    <!-- Displays: This is a page-specific translation for /dir1. -->

    <!-- Nested key -->
    <p>{{ $t('nested.key.deeper') }}</p>
    <!-- Displays: Nested translation here -->

    <!-- Placeholder usage -->
    <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
    <!-- Displays: Hello, Alice! -->
  </div>
</template>

<script setup lang="ts">
// No need to import anything from 'nuxt-i18n-micro'.
// The plugin automatically provides `useI18n` and `$t`.
const { $t } = useI18n()

// You can now use $t in your script, for example:
console.log($t('test_key')) // "Hello World!"
</script>
```

<Tip>
`$t` kan returnera **objekt** om nyckeln pekar på en nästlad JSON-nod (till exempel `$t('header')` → `\{ title: "Hi" \}`). I mallar renderas detta som `[object Object]`. Använd `$ts` när du behöver en garanterad sträng, eller ange en mer specifik nyckel som `$t('header.title')`. Se [API-referens — $t kontra $ts](/api/methods#t) för detaljer.
</Tip>

## 3. Byta aktuell lokal

För att ändra språk i din app kan du hämta `$locale` från `useI18n()` och tilldela den en ny kod:

```vue
<template>
  <div>
    <button @click="$switchLocale('en')">English</button>
    <button @click="$switchLocale('fr')">Français</button>
  </div>
</template>

<script setup lang="ts">
// The plugin auto-injects these references
const { $t, $switchLocale } = useI18n()
</script>
```

## 4. Nästlade nycklar och platshållare

- **Nästlade nycklar** använder punktnotation, till exempel `nested.key.deeper`.
- **Platshållare** låter dig infoga dynamiska värden:
  ```json
  { "greeting": "Hello, {name}!" }
  ```
  ```vue
  <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
  <!-- Displays: Hello, Alice! -->
  ```

## 5. Tips och bästa praxis

- **Motstridiga nycklar**: Om en sidspecifik fil innehåller samma nyckel som en rotnivåfil har den sidspecifika versionen företräde (rot-översättningar slås samman som en bas vid byggtid).
- **Inaktivera sidfiler**: Om du hellre inte vill använda sidspecifika översättningar kan du sätta `disablePageLocales: true` i din Nuxt-konfiguration. Då används endast `/locales/*.json`-filerna.
- **Inga direktimporter**: Du behöver inte göra `import \{ useI18n \} from 'nuxt-i18n-micro'`; modulens autoinjektionsfunktion sköter det åt dig.

Det var allt! Med dessa steg kan du snabbt **börja hämta översättningar** från rotnivåfiler eller sidspecifika JSON-filer och **visa dem** i din Nuxt-applikation med `$t`.

## Ytterligare resurser

För att utforska mer avancerade funktioner, se till att titta på:

1. **Komponenten `<i18n-t>`**  
   Komponenten `<i18n-t>` är ett kraftfullt alternativ till `$t`, särskilt användbar i situationer med nästlade element, avancerad platshållaranvändning och mer komplexa översättningsstrukturer.

- **Dokumentation**: [i18n-t](/api/components/i18n-t)

2. **Composablen `useI18n`**  
   Composablen `useI18n` erbjuder en komplett uppsättning funktioner och reaktiva egenskaper för att hantera översättningar, lokalbyten, formatering och mer.

- **Dokumentation**: [useI18n](/api/composables/use-i18n)
