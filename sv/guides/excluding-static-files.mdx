# Utesluta statiska filer från i18n-routing

## Översikt

Som standard utesluter nuxt-i18n-micro automatiskt vanliga statiska filer från i18n-routingbearbetning. Du kan dock även konfigurera anpassade uteslutningsmönster för att förhindra att specifika sökvägar bearbetas av i18n-systemet.

## Inbyggda uteslutningar

Modulen utesluter automatiskt följande filtyper och mönster:

- **Sitemaps**: `/sitemap*.xml`, `/sitemap-en.xml` osv.
- **SEO-filer**: `/robots.txt`, `/favicon.ico`
- **PWA-filer**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Statiska tillgångar**: Filer med tillägg som `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Interna Nuxt-sökvägar**: Alla sökvägar som börjar med `__` (som `/__nuxt/`)

## Anpassade uteslutningsmönster

Du kan definiera anpassade uteslutningsmönster med alternativet `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Mönstertyper

### Strängmönster

- **Exakt matchning**: `'/api/health'` – matchar exakt `/api/health`
- **Prefixmatchning**: `'/admin'` – matchar `/admin` och `/admin/dashboard`
- **Jokertecken**: `'/api/*'` – matchar `/api/users` men inte `/api/users/123`
- **Djupa jokertecken**: `'/admin/**'` – matchar `/admin/users` och `/admin/users/123`

### Reguljära uttryck

Använd RegExp-objekt för komplex mönstermatchning:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Användningsfall

### SEO-filer

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API-rutter

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Adminpaneler

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Statiska tillgångar

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Så fungerar det

1. **Servermellanprogram**: En Nitro-mellanvara körs först för att kontrollera uteslutningsmönster
2. **Sidbearbetning**: Under sidupplösning hoppas uteslutna sökvägar över
3. **Catch-all-rutt**: Fallback-rutten kontrollerar uteslutningar innan bearbetning
4. **Prerendering**: Uteslutna sökvägar inkluderas inte i förrenderade rutter

## Prestandapåverkan

- Uteslutningskontroller är optimerade och körs tidigt i förfrågans livscykel
- Inbyggda mönster använder effektiv regex-matchning
- Anpassade mönster cachas och återanvänds
- Minimal prestandaoverhead för uteslutna sökvägar

## Felsökning

### Statiska filer fångas fortfarande upp

1. **Kontrollera mönstersyntaxen**: Se till att dina mönster matchar den exakta sökvägsstrukturen
2. **Använd regex för komplexa mönster**: Sträng-jokertecken har begränsningar
3. **Testa mönster**: Använd webbläsarens utvecklarverktyg för att verifiera den faktiska förfrågningssökvägen
4. **Kontrollera ordningen**: Se till att uteslutningsmönster definieras före annan i18n-konfiguration

### Mönstret fungerar inte

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Debugläge

Aktivera debugläge för att se uteslutningsbearbetning:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Detta loggar uteslutningsbeslut i konsolen.

## Migrering från workarounds

Om du använde workarounds som route rules eller mellanvara kan du nu ersätta dem med `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Det nya tillvägagångssättet är mer tillförlitligt och fungerar på flera nivåer av routingsystemet.
