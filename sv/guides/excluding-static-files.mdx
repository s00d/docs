# Exkludera statiska filer från i18n-routing

## Översikt

Som standard exkluderar nuxt-i18n-micro automatiskt vanliga statiska filer från i18n-routing-bearbetningen. Du kan dock även konfigurera anpassade exkluderingsmönster för att förhindra att specifika sökvägar bearbetas av i18n-systemet.

## Inbyggda exkluderingar

Modulen exkluderar automatiskt följande filtyper och mönster:

- **Sitemaps**: `/sitemap*.xml`, `/sitemap-en.xml`, med flera.
- **SEO-filer**: `/robots.txt`, `/favicon.ico`
- **PWA-filer**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Statiska tillgångar**: Filer med filändelser som `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Interna Nuxt-sökvägar**: Alla sökvägar som börjar med `__` (som `/__nuxt/`)

## Anpassade exkluderingsmönster

Du kan definiera anpassade exkluderingsmönster med alternativet `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Mönstertyper

### Strängmönster

- **Exakt matchning**: `'/api/health'` - matchar exakt `/api/health`
- **Prefix-matchning**: `'/admin'` - matchar `/admin` och `/admin/dashboard`
- **Wildcards**: `'/api/*'` - matchar `/api/users` men inte `/api/users/123`
- **Djupa wildcards**: `'/admin/**'` - matchar `/admin/users` och `/admin/users/123`

### Reguljära uttryck

Använd RegExp-objekt för komplex mönstermatchning:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Användningsfall

### SEO-filer

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API-rutter

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Administratörspaneler

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Statiska tillgångar

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Så fungerar det

1. **Server-middleware**: En Nitro-middleware körs först för att kontrollera exkluderingsmönster
2. **Sidbearbetning**: Under sidupplösning hoppas exkluderade sökvägar över
3. **Catch-all-rutt**: Fallback-rutten kontrollerar exkluderingar innan bearbetning
4. **Prerendering**: Exkluderade sökvägar inkluderas inte i prerendrade rutter

## Prestandapåverkan

- Exkluderingskontroller är optimerade och körs tidigt i begärans livscykel
- Inbyggda mönster använder effektiv regex-matchning
- Anpassade mönster cachas och återanvänds
- Minimal prestanda-overhead för exkluderade sökvägar

## Felsökning

### Statiska filer fortfarande fångade upp

1. **Kontrollera mönstersyntax**: Se till att dina mönster matchar den exakta sökvägsstrukturen
2. **Använd regex för komplexa mönster**: Sträng-wildcards har begränsningar
3. **Testa mönster**: Använd webbläsarens utvecklarverktyg för att verifiera den faktiska begärans sökväg
4. **Kontrollera ordning**: Se till att exkluderingsmönster definieras före annan i18n-konfiguration

### Mönster fungerar inte

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Felsökningsläge

Aktivera felsökningsläge för att se exkluderingsbearbetningen:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Detta loggar exkluderingsbeslut i konsolen.

## Migrera från lösningar

Om du använde lösningar som route-regler eller middleware kan du nu ersätta dem med `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Det nya tillvägagångssättet är mer tillförlitligt och fungerar på flera nivåer i routing-systemet.
