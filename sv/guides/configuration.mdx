# Alternativdetaljer

Modulen tillhandahåller omfattande konfigurationsalternativ för att anpassa din i18n-uppsättning.

### 🌍 Grundläggande lokalinställningar

#### `locales`

{/* generated:option:locales — do not edit; run `pnpm run docs:generate` */}

**Typ** `Locale[]` · **Standard** `[]`

Lista över lokaler som stöds. Varje post definierar en lokalkod plus valfri metadata (ISO, riktning, visningsnamn med mera).

{/* /generated:option:locales */}

Varje lokalobjekt stöder:

| Egenskap         | Typ       | Krävs | Beskrivning                                              |
| ---------------- | --------- | ----- | -------------------------------------------------------- |
| `code`           | `string`  | ✅    | Unik identifierare (till exempel `'en'`)                 |
| `displayName`    | `string`  | ❌    | Läsbart namn för växlare (till exempel `'English'`)      |
| `iso`            | `string`  | ❌    | ISO-kod (till exempel `'en-US'`)                         |
| `dir`            | `string`  | ❌    | Textriktning (`'ltr'` eller `'rtl'`)                     |
| `disabled`       | `boolean` | ❌    | Inaktivera i rullgardin om `true`                        |
| `baseUrl`        | `string`  | ❌    | Bas-URL för lokalspecifika domäner                       |
| `baseDefault`    | `boolean` | ❌    | Ta bort lokalprefix från URL:er                          |
| `fallbackLocale` | `string`  | ❌    | Per-lokal fallback (åsidosätter global)                  |
| `[key: string]`  | `unknown` | ❌    | Alla anpassade egenskaper (se nedan)                     |

**Exempel**:

```typescript
locales: [
  { code: 'en', iso: 'en-US', dir: 'ltr' },
  { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
  { code: 'ar', iso: 'ar-SA', dir: 'rtl', disabled: true },
  {
    code: 'de',
    iso: 'de-DE',
    dir: 'ltr',
    baseUrl: 'https://de.example.com',
    baseDefault: true,
  },
]
```

<Warning>
Att använda `baseUrl` kan leda till duplicering av interna rutter som externa länkar och komplicera routing och underhåll. Överväg i stället att skapa externa länkar direkt för specifika lokaler.
</Warning>

#### Anpassade lokalegenskaper

Du kan lägga till valfria anpassade egenskaper till lokalobjekt. De skickas vidare till runtime och är tillgängliga via `$getLocales()`:

```typescript
locales: [
  { code: 'en', iso: 'en-US', flag: '🇬🇧', currency: 'GBP' },
  { code: 'de', iso: 'de-DE', flag: '🇩🇪', currency: 'EUR' },
  { code: 'ru', iso: 'ru-RU', flag: '🇷🇺', currency: 'RUB' },
]
```

Kom åt dem i komponenter:

```vue
<template>
  <ul>
    <li v-for="locale in $getLocales()" :key="locale.code">{{ locale.flag }} {{ locale.displayName }} ({{ locale.currency }})</li>
  </ul>
</template>
```

Som standard typas anpassade egenskaper som `unknown`. För fullständigt TypeScript-stöd, använd **modul-augmentering**. Skapa en deklarationsfil (till exempel `app/i18n.d.ts` eller någon `.d.ts` som ingår i din `tsconfig`):

```typescript
// app/i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
    currency?: string
  }
}
```

Efter detta är alla anpassade egenskaper fullt typade:

```typescript
const locales = $getLocales()
locales[0].flag // string | undefined ✅
locales[0].currency // string | undefined ✅
```

#### `defaultLocale`

{/* generated:option:defaultLocale — do not edit; run `pnpm run docs:generate` */}

**Typ** `string` · **Standard** `'en'`

Lokalen som ska användas när ingen lokal kan bestämmas från URL eller användarpreferenser. Används även som fallback-lokal för saknade översättningar när `fallbackLocale` inte är satt.

{/* /generated:option:defaultLocale */}

```typescript
defaultLocale: 'en'
```
#### `strategy`

{/* generated:option:strategy — do not edit; run `pnpm run docs:generate` */}

**Typ** `Strategies` · **Standard** `'prefix_except_default'`

URL-routingstrategi för lokalprefix.

- `'no_prefix'` — ingen lokal i URL; lokalen lagras i cookie.
- `'prefix_except_default'` — prefixera alla lokaler utom standardlokalen.
- `'prefix'` — prefixera alltid, inklusive standardlokalen.
- `'prefix_and_default'` — som `prefix`, men standardlokalen är också tillgänglig utan prefix.

{/* /generated:option:strategy */}

<CodeGroup>
```typescript no_prefix
strategy: 'no_prefix'
// Routes: /about, /contact
// Locale detection via browser/cookies
```

```typescript prefix_except_default
strategy: 'prefix_except_default'
// Default locale: /about, /contact
// Other locales: /fr/about, /de/contact
```

```typescript prefix
strategy: 'prefix'
// All locales: /en/about, /fr/about, /de/about
```

```typescript prefix_and_default
strategy: 'prefix_and_default'
// Both prefixed and non-prefixed versions for default locale
```
</CodeGroup>

### 📂 Översättningshantering
#### `translationDir`

{/* generated:option:translationDir — do not edit; run `pnpm run docs:generate` */}

**Typ** `string` · **Standard** `'locales'`

Sökväg till katalogen som innehåller JSON-översättningsfiler, relativt projektroten.

{/* /generated:option:translationDir */}

```typescript
translationDir: 'i18n' // Custom directory
// Nuxt 4 colocation example:
// translationDir: 'app/locales'
```

Sökvägar resolvas från Nuxts **projektrot** (`rootDir`), inte från `app/`. Med Nuxt 4 är den vanliga uppsättningen `app/pages/` för rutter och `locales/` (eller `app/locales` om du sätter `translationDir`) för JSON-filer.
#### `disablePageLocales`

{/* generated:option:disablePageLocales — do not edit; run `pnpm run docs:generate` */}

**Typ** `boolean` · **Standard** `false`

Inaktivera sidspecifika översättningsfiler. När `true` laddas endast globala översättningar (`\{locale\}.json`); sidspecifika filer (`pages/\{page\}/\{locale\}.json`) genereras eller laddas inte.

{/* /generated:option:disablePageLocales */}

När aktiverat används endast rotnivåöversättningsfiler:

```tree
locales/
├── en.json
├── fr.json
└── ar.json
```
#### `fallbackLocale`

{/* generated:option:fallbackLocale — do not edit; run `pnpm run docs:generate` */}

**Typ** `string` · **Standard** `undefined (ingen fallback; returnerar rå nyckel)`

Global fallback-lokalkod. När en översättningsnyckel saknas i den aktiva lokalen letar modulen upp den i denna lokal innan själva nyckeln returneras.

{/* /generated:option:fallbackLocale */}

```typescript
fallbackLocale: 'en' // Global fallback
```
#### `types`

{/* generated:option:types — do not edit; run `pnpm run docs:generate` */}

**Typ** `boolean` · **Standard** `true`

Generera TypeScript-typdeklarationer för `useI18n`, `$t` och relaterade hjälpare baserat på översättningsnycklarna i dina standardlokalfiler.

{/* /generated:option:types */}

När aktiverat emitterar modulen `.nuxt/i18n.d.ts` under bygget med typade översättningsnycklar. Sätt till `false` om du föredrar otypade hjälpare eller använder en extern generator.

Denna inbyggda generator är separat från det valfria paketet [`@i18n-micro/types-generator`](/integrations/types-generator), som kan producera striktare eller fristående typfiler för monorepon och CI.

```typescript
types: false // Disable built-in key typing
```
#### `routeLocales`

{/* generated:option:routeLocales — do not edit; run `pnpm run docs:generate` */}

**Typ** `Record<string, string[]>` · **Standard** —

Per-rutt-lokalbegränsningar, extraherade från `defineI18nRoute()`-anrop. Mappar en ruttsökväg (till exempel `'/about'`) till en array av tillåtna lokalkoder. Rutter som inte listas har inga begränsningar (alla lokaler tillåts).

{/* /generated:option:routeLocales */}

Mappar en ruttsökväg (till exempel `'/about'`) till tillåtna lokalkoder. Rutter som inte listas tillåter alla konfigurerade lokaler.

Du konfigurerar detta normalt via [`defineI18nRoute`](/guides/custom-locale-routes) i sidor snarare än i `nuxt.config`. Modulen slår samman deklarationer på sidnivå in i denna karta vid byggtid.
#### `routeDisableMeta`

{/* generated:option:routeDisableMeta — do not edit; run `pnpm run docs:generate` */}

**Typ** `Record<string, boolean \| string[]>` · **Standard** —

Per-rutt-inaktivering av metataggar, extraherad från `defineI18nRoute()`-anrop. Mappar en ruttsökväg till `true` (inaktivera all meta) eller en array av lokalkoder för vilka meta ska inaktiveras.

{/* /generated:option:routeDisableMeta */}

- `true` — inaktivera all SEO-meta för rutten
- `string[]` — inaktivera meta endast för listade lokalkoder

Precis som `routeLocales` sätts detta vanligtvis i sidkomponenter, inte manuellt i konfig.
#### `experimental`

{/* generated:option:experimental — do not edit; run `pnpm run docs:generate` */}

**Typ** `Record<string, unknown>` · **Standard** —

Hink för experimentella/instabila alternativ. Innehållet kan ändras eller tas bort utan förvarning mellan mindre versioner.

{/* /generated:option:experimental */}

De flesta tidigare `experimental.*`-flaggor befordrades till alternativ på översta nivån i v3 (till exempel `hmr`). Föredra dokumenterade alternativ på översta nivån. Använd `experimental` endast när du följer en release-not eller migreringsguide som refererar till en specifik nyckel.

### 🔍 SEO och metataggar
#### `meta`

{/* generated:option:meta — do not edit; run `pnpm run docs:generate` */}

**Typ** `boolean` · **Standard** `true`

Generera SEO-metataggar (`hreflang`, `canonical`, `og:url`, `og:locale`) automatiskt.

{/* /generated:option:meta */}

```typescript
meta: true // Generate alternate links, canonical URLs, etc.
```
#### `metaBaseUrl`

{/* generated:option:metaBaseUrl — do not edit; run `pnpm run docs:generate` */}

**Typ** `string` · **Standard** `undefined`

Bas-URL för SEO-metataggar (canonical, og:url, hreflang).

- En konkret URL-sträng (till exempel `'https://example.com'`) — används som den är (högsta prioritet).
- `undefined` — faller tillbaka på `site.url` från `nuxt-site-config` när den modulen är närvarande, annars den aktuella begärans origin (`useRequestURL().origin` på server, `window.location.origin` på klient).

{/* /generated:option:metaBaseUrl */}

Prioritet när osatt: `site.url` från `nuxt-site-config` (om installerad) → förfrågans origin (`useRequestURL().origin` på servern med `X-Forwarded-Host` / `X-Forwarded-Proto`, `window.location.origin` på klienten). Idealisk för **SEO-stackar** som redan sätter `site.url`, och för **flerdomänsdistributioner** när `site.url` utelämnas.

- Vilken annan sträng som helst — används som en statisk bas-URL (vinner över `site.url`).

```typescript
// Prefer sharing the SEO stack origin — omit metaBaseUrl when site.url is set
site: { url: 'https://example.com' }

// Or pin an explicit override
metaBaseUrl: 'https://example.com'
```
#### `canonicalQueryWhitelist`

{/* generated:option:canonicalQueryWhitelist — do not edit; run `pnpm run docs:generate` */}

**Typ** `string[]` · **Standard** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

Lista över query-parameternamn som bevaras i canonical- och `og:url`-metataggar. Parametrar som inte finns i denna lista tas bort från canonical-URL:en.

{/* /generated:option:canonicalQueryWhitelist */}

```typescript
canonicalQueryWhitelist: ['page', 'sort', 'category']
```

### 🔄 Avancerade funktioner
#### `globalLocaleRoutes`

{/* generated:option:globalLocaleRoutes — do not edit; run `pnpm run docs:generate` */}

**Typ** `GlobalLocaleRoutes` · **Standard** `\{\}`

Global lokalkonfiguration på ruttnivå. Tillåter att begränsa eller anpassa lokalrutter för specifika sidor utan att ändra deras komponenter.

- `false` — exkludera rutten från lokalisering.
- `Record<LocaleCode, string>` — anpassade per-lokala sökvägar.

{/* /generated:option:globalLocaleRoutes */}

```typescript
globalLocaleRoutes: {
  'about': {
    en: '/about-us',
    fr: '/a-propos',
    de: '/uber-uns'
  },
  'unlocalized': false // Disable localization entirely
}
```

<Tip>
För rutter som läggs till i `pages:extend` (särskilt många som delar en wrapper-SFC), bygg både `pages` och `globalLocaleRoutes` från en lista med [`splitLocaleRoutes`](/guides/custom-locale-routes#programmatic-routes-pagesextend--244) — nyckelade efter ruttens **namn**, inte filsökväg.
</Tip>

#### `routesLocaleLinks`

{/* generated:option:routesLocaleLinks — do not edit; run `pnpm run docs:generate` */}

**Typ** `\{ [key: string]: string \}` · **Standard** `\{\}`

Mappa ruttnamn till andra ruttnamn för att dela samma översättningsfiler. Till exempel betyder `\{ 'about-us': 'about' \}` att sidan `about-us` använder översättningar från sidan `about` i stället för sina egna.

{/* /generated:option:routesLocaleLinks */}

```typescript
routesLocaleLinks: {
  'products-id': 'products',
  'about-us': 'about'
}
```
#### `customRegexMatcher`

{/* generated:option:customRegexMatcher — do not edit; run `pnpm run docs:generate` */}

**Typ** `string \| RegExp` · **Standard** `undefined (använder inbyggt mönster baserat på lokalkoder)`

Anpassat reguljärt uttryck (eller dess strängkälla) för att matcha lokalkoder i URL-segment. Alla lokalkoder som definieras i `locales` måste matcha detta mönster, annars skickas en varning.

{/* /generated:option:customRegexMatcher */}

<Danger>
Vid byggtid **validerar** modulen att varje lokalkod i din `locales`-lista matchar mönstret `customRegexMatcher`. Om någon lokalkod inte matchar **misslyckas bygget** med felet:

> `Nuxt-i18n-micro: Some locale codes does not match customRegexMatcher`

Verifiera alltid ditt regex mot alla dina lokalkoder innan distribution.
</Danger>

```typescript
// ✅ Correct: matches 'en-us', 'de-de', 'fr-fr'
customRegexMatcher: '[a-z]{2}-[a-z]{2}'

// ✅ Correct: matches 'en', 'de', 'fr', 'zh'
customRegexMatcher: '[a-z]{2}'

// ❌ Wrong: won't match 'zh-Hant' (uppercase letter)
// This will FAIL the build if 'zh-Hant' is in your locales list
customRegexMatcher: '[a-z]{2}-[a-z]{2}'
```

### 🔢 Anpassning
#### `plural`

{/* generated:option:plural — do not edit; run `pnpm run docs:generate` */}

**Typ** `PluralFunc` · **Standard** `inbyggd pluralisering (formindex efter antal)`

Anpassad pluraliseringsfunktion. Tar emot `(key, count, params, locale, getter)` och ska returnera den valda pluralformen som en sträng, eller `null`/`undefined` för att falla tillbaka till den inbyggda `defaultPlural`-logiken (så att du kan åsidosätta endast vissa lokaler).

För Nuxt-modulen serialiseras funktionen med `.toString()` in i `.nuxt/i18n.plural.mjs` — den måste vara självständig (inga importer/yttre scope). En filsökväg som sträng stöds **inte**.

{/* /generated:option:plural */}

##### Så fungerar det

Översättningar använder `|` för att separera pluralformer:

```json
{
  "apples": "no apples | one apple | {count} apples"
}
```

Använd `$tc('apples', count)` eller `$tc('cart', \{ count, name \})` när en form behöver mer än `\{count\}` — skicka **`count` och andra parametrar i det andra argumentobjektet**, inte som ett tredje argument (det tredje är endast `defaultValue`).

`$tc`-anropet anropar `plural`-funktionen, som:

1. Anropar `t(key)` för att få den råa översättningssträngen (till exempel `"no apples | one apple | \{count\} apples"`)
2. Delar med `|` för att få form-arrayen
3. Väljer en form baserat på `count`
4. Ersätter `\{count\}` med det faktiska talet

**Standard**-implementationen väljer efter index: `count < forms.length ? forms[count] : forms[last]`. Detta fungerar för enkla fall (0 → första formen, 1 → andra, 2+ → sista).

##### Anpassad pluralfunktion

För språk med komplexa pluraliseringsregler (till exempel ryska, arabiska, polska) åsidosätt alternativet `plural`.

<Danger>
Funktionen serialiseras via `.toString()` och injiceras i en virtuell modul vid byggtid. Detta innebär:

- **Måste använda nyckelordet `function`** — INTE genvägs-metod-syntax, INTE arrow-funktioner med externa referenser
- **Inga importer eller externa referenser** — funktionen måste vara helt självständig (en filsökväg som `plural: '~/i18n/plural.ts'` stöds **inte**)
- **Ingen TypeScript-endast-syntax** som inte överlever `.toString()` (typannoteringar är okej i `nuxt.config.ts` eftersom Nuxt tar bort dem)
- Att returnera `null` / `undefined` faller tillbaka till den inbyggda `defaultPlural` (användbart för per-lokala överskrivningar)
</Danger>

**Exempel: Rysk pluralisering** (4 former: noll, en, få, många):

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    plural: function (key, count, _params, _locale, t) {
      const translation = t(key)
      if (!translation) return key

      const forms = translation
        .toString()
        .split('|')
        .map(function (s) {
          return s.trim()
        })
      let idx

      if (count === 0) {
        idx = 0
      } else {
        const mod10 = count % 10
        const mod100 = count % 100
        if (mod10 === 1 && mod100 !== 11) {
          idx = 1
        } else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) {
          idx = 2
        } else {
          idx = 3
        }
      }

      if (idx >= forms.length) idx = forms.length - 1
      return (forms[idx] || '').replace('{count}', String(count))
    },
  },
})
```

Med denna översättning:

```json
{
  "apples": "нет яблок | {count} яблоко | {count} яблока | {count} яблок"
}
```

Resultat:

- `$tc('apples', 0)` → `"нет яблок"`
- `$tc('apples', 1)` → `"1 яблоко"`
- `$tc('apples', 3)` → `"3 яблока"`
- `$tc('apples', 5)` → `"5 яблок"`
- `$tc('apples', 21)` → `"21 яблоко"`

**Exempel: Enkel engelska (standardbeteende)**:

```typescript
// This is the built-in default — you don't need to set it explicitly
plural: function (key, count, params, _locale, t) {
  const translation = t(key, params)
  if (!translation) return null

  const forms = translation.toString().split('|')
  if (forms.length === 0) return null
  const form = count < forms.length ? forms[count] : forms[forms.length - 1]
  if (!form) return null
  return form.trim().replace('{count}', count.toString())
}
```

##### Pluralisering per lokal

Om olika lokaler behöver olika pluralregler, förgrena på `locale` och returnera `null` för lokaler som du inte anpassar — den inbyggda `defaultPlural` hanterar resten:

```typescript
plural: function (key, count, _params, locale, t) {
  // Only override Slavic locales; en/de/… keep the built-in rules
  if (locale !== 'ru' && locale !== 'uk') return null

  const translation = t(key)
  if (!translation) return null

  const forms = translation.toString().split('|').map(function (s) { return s.trim() })
  let idx
  if (count === 0) {
    idx = 0
  } else {
    const mod10 = count % 10
    const mod100 = count % 100
    if (mod10 === 1 && mod100 !== 11) idx = 1
    else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) idx = 2
    else idx = 3
  }
  if (idx >= forms.length) idx = forms.length - 1
  return (forms[idx] || '').replace('{count}', String(count))
}
```

<Warning>
`plural: '~/i18n/plural.ts'` (eller någon sträng-sökväg) stöds **inte**. Nuxt-modulen serialiserar funktionen med `.toString()` in i en virtuell fil; externa importer och hjälpare från en annan modul tas bort och är `undefined` vid runtime. Behåll funktionen helt inline i `nuxt.config.ts` (se faranoten ovan).
</Warning>

#### `translationPayloads`

{/* generated:option:translationPayloads — do not edit; run `pnpm run docs:generate` */}

**Typ** `TranslationPayloadOptions` · **Standard** —

Styr hur översättnings-payloads emitteras (Node: `public/<apiBaseUrl>`; Edge: Nitro `serverAssets`).

- **Node**: `serverAssets` betyder lokal SSR via `readFile` under `public/` (ingen Rollup `raw:`).
- **Edge**: `serverAssets` registrerar Nitro `serverAssets` (`assets:i18n`); det tvingar inte en publik kopia.

Behåll standardvärdena för den vanliga allt-i-ett-uppsättningen. För stora Edge-kataloger, föredra `mode: 'source'`. För CDN-baserade distributioner, inaktivera lokala utdata och sätt `apiBaseClientHost` / `apiBaseServerHost`.

{/* /generated:option:translationPayloads */}

```typescript
{
  mode?: 'premerged' | 'source'
  serverAssets?: boolean
  serverHandler?: boolean
  publicAssets?: boolean
  prerenderRoutes?: boolean
  publicDir?: string
  warnFileCount?: number
  warnSizeBytes?: number
}
```

**Standard** (`mode: 'premerged'`):

```typescript
{
  mode: 'premerged',
  serverAssets: true,
  serverHandler: true,
  publicAssets: true,
  prerenderRoutes: false
}
```

SSR på **Node** läser samma träd som kopierats till `public/<apiBaseUrl>/` (`readFile`). På **Edge** bäddar Nitro `serverAssets` in det (ingen tvingad publik kopia — sätt `publicAssets: true` för CDN). `mode: 'premerged'` → `\{page\}/\{locale\}/data.json` per sida/lokal; `mode: 'source'` → kompakt källa + runtime-sammanslagning.

`serverAssets: true` på **Node** tvingar en publik kopia även om `publicAssets` är false. På **Edge** registrerar den bara Nitro-inbäddningen. Föredra `mode: 'source'` på Edge för stora kataloger. Utan lokala payloads och utan `apiBaseServerHost` misslyckas bygget.

Den lokala hanteraren `/\{apiBaseUrl\}/:page/:locale/data.json`, prerender-rutter och publika tillgångskopior förblir valfria utdata.

För kompakta **publika** / Edge-payloads:

```typescript
i18n: {
  translationPayloads: {
    mode: 'source',
  },
}
```

`mode: 'source'` håller lagerfiler kompakta och slår samman rot/sida/fallback vid runtime via den inbyggda `/_locales`-rutten (eller Edge `assets:i18n`). Som standard inaktiverar den publika tillgångskopior och prerenderade payload-rutter.

<Warning>
Med `mode: 'source'` är `publicAssets` som standard `false` (`prerenderRoutes` är alltid av om du inte väljer in). Ren statisk hosting utan en Nitro/edge-runtime kan därför inte ladda översättningar på klienten om du inte aktiverar en av dessa utdata, behåller `serverHandler` tillgänglig vid runtime eller hostar payloads externt.

Med standard `mode: 'premerged'` och `publicAssets: true` landar statiska filer redan på `public/<apiBaseUrl>/\{page\}/\{locale\}/data.json` — som matchar klientens `$fetch`-URL:er — så en statisk värd kan leverera dem utan Nitro.
</Warning>

<Warning>
När `apiBaseServerHost` eller `apiBaseClientHost` är satt hämtar modulen redan sammanslagen JSON från den origin. Externa värdar måste leverera samma `/\{apiBaseUrl\}/:page/:locale/data.json`-svar som den inbyggda rutten. `mode: 'source'` gäller lokala payload-kataloger, inte en extern CDN om inte den CDN:en också levererar runtime-sammanslagna payloads.
</Warning>

Du kan även inaktivera duplicerade lokala utdata manuellt och leverera översättnings-payloads från en CDN eller objektlagring:

```typescript
i18n: {
  apiBaseClientHost: 'https://cdn.example.com',
  apiBaseServerHost: 'https://cdn.example.com',
  translationPayloads: {
    serverHandler: false,
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

Om du bara vill undvika att skriva payloads till publik utdata och behålla den inbyggda serverrutten för SSR/runtime-förfrågningar, inaktivera båda publika utdata:

```typescript
i18n: {
  translationPayloads: {
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

På **Node** tvingar `serverAssets: true` fortfarande en publik kopia för SSR även när `publicAssets` är false — sätt `serverAssets: false` och `apiBaseServerHost` om du vill ha noll lokala payload-filer.

Använd `publicDir` för att ändra den publika utdatamappen när payloads kopieras. Den är som standard `apiBaseUrl` (`_locales`). I premerged-läge skriver `publicAssets` `\{page\}/\{locale\}/data.json` där (samma sökvägar som klienten hämtar). `prerenderRoutes` är en valfri Nitro-prerender av hanterarrutterna — vanligtvis överflödigt när det trädet redan kopierats.

Om du inaktiverar alla lokala payload-utdata måste du konfigurera både `apiBaseServerHost` (SSR) och `apiBaseClientHost` (klientnavigering). Annars resolvas översättningar till tomma objekt och UI-nycklar kan visas oöversatta.

`warnFileCount` och `warnSizeBytes` styr byggtidsvarningar när pre-mergad payload-utdata växer stor (standardvärden: 500 filer och 10 MB).

#### `httpCacheDuration`

{/* generated:option:httpCacheDuration — do not edit; run `pnpm run docs:generate` */}

**Typ** `number` · **Standard** `31536000`

HTTP `Cache-Control` max-age (sekunder) för `/\{apiBaseUrl\}/:page/:locale/data.json`.

Gäller fullt ut endast medan `dateBuild` bustar URL:en (`?v=...`), vilket är standard: svaret är då `public, max-age=…, immutable` och säkert för webbläsare och CDN:er.

- `dateBuild: 0`/`''` — URL:en är stabil, så denna varaktighet respekteras *inte*; svaret blir i stället `public, max-age=0, must-revalidate`. En lång `max-age` på en oföränderlig URL låser fast den första payload som en webbläsare någonsin såg.

- `0` — sätt inte `Cache-Control` alls (användbart vid lokal felsökning)
- Tillämpas inte i utveckling (`import.meta.dev`) så HMR inte motarbetas av webbläsarcachen
- Når endast svar som levereras via Nitro. Payloads som kopieras till `public/` och levereras av hostingplattformen får den plattformens headers — se prestandaguiden.

Analog med `@nuxtjs/i18n` experimentella `httpCacheDuration` (v10.2.0), men som en explicit svarshead snarare än Nitro `defineCachedEventHandler` maxAge.

{/* /generated:option:httpCacheDuration */}

```ts
export default defineNuxtConfig({
  i18n: {
    // Per-build fallback (Date.now()) so immutable payloads never go stale when GIT_SHA is missing.
    dateBuild: process.env.GIT_SHA ?? String(Date.now()),
    httpCacheDuration: 86400, // 24 hours
    // httpCacheDuration: 0, // disable Cache-Control header
  },
})
```

<Tip>
För de flesta projekt är standardvärdena (obegränsat, ingen utgång) bra — översättningar är små och ändliga. Men om ditt projekt har **tusentals sidor** med `disablePageLocales: false` och **många lokaler** kan servercachen växa avsevärt. I långlivade Node.js-servrar kan detta leda till överdriven minnesanvändning.

- **`cacheMaxSize`** — begränsar antalet cachade poster. Användbart för att begränsa minnet.
- **`cacheTtl`** — säkerställer att inaktuella översättningar så småningom laddas om från lagring. Användbart för serverlösa miljöer eller när översättningar ändras vid runtime.

**Formel för att uppskatta max antal poster**: `antal_lokaler × (antal_sidor + 1)`. Till exempel 10 lokaler × 500 sidor = ~5010 poster.
</Tip>
