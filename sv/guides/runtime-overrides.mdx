# Runtime-överskrivningar för i18n

Använd denna guide när du behöver att en enda byggartefakt körs med olika standardvärden för lokaler per miljö (till exempel: olika hyresgästinstanser).

## Vad som kan åsidosättas vid runtime

Modulen stöder säkra runtime-överskrivningar för:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Dessa överskrivningar tillämpas ovanpå byggkonfigurationen från `.nuxt/i18n.strategy.mjs` och `.nuxt/i18n.config.mjs`.

## Vad som inte kan åsidosättas vid runtime

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) är en byggtidsfråga eftersom den påverkar det genererade ruttbeteendet.

Om du skickar en runtime-överskrivning för strategi ignoreras den och en varning skickas.

## Överskrivningar via RuntimeConfig

Ange runtime-värden under `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Överskrivningar via miljövariabler

Du kan även konfigurera överskrivningar via miljövariabler:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (kommaseparerade, till exempel `fr,it`)

Fallback-alias stöds också:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Valideringsregler

Vid runtime validerar modulen överskrivningar för att undvika trasigt tillstånd:

- Du kan inte inaktivera alla lokaler.
- `defaultLocale` måste peka på en aktiverad lokal.
- `fallbackLocale` måste finnas i deklarerade lokaler.

Om en överskrivning är ogiltig behåller modulen ett säkert värde och loggar en varning.

## Anmärkningar för distributioner med flera instanser

Denna runtime-funktion är utformad för aktivering och standardvärden av lokaler per instans utan omgörning.

Om instanser kräver olika URL-strategier (`no_prefix` kontra `prefix`), använd separata byggen för varje strategi.

## Inaktiverade lokaler och statiska payloads

`runtimeConfig.public.i18nRuntime.disabledLocales` uppdaterar routing, växlare och Nitro-payload-**hanteraren** — men Nitro levererar filer under `public/` **innan** den hanteraren körs.

Om `translationPayloads.publicAssets` (eller Node SSR:s tvingade publika kopia) redan har skrivit `/_locales/\{page\}/\{locale\}/data.json`, kan en runtime-inaktivering inte dölja den filen. Föredra `locale.disabled: true` vid byggtid så att premerge inte emitterar den lokalens statiska payloads.
