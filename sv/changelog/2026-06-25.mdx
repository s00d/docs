**Datum**: 2026-06-25

**Version**: `v3.21.0`

![v3.21.0 release](/images/3.21.0.png)

Den här versionen lägger till **`useI18nHead`** — en composable på sidnivå för i18n-SEO-åsidosättningar ovanpå det inbyggda pluginet `02.meta`. Anpassa `hreflang`, canonical, `og:url` och Open Graph-taggar per route utan ett eget meta-plugin eller `meta: false`.

## Vad är nytt? {#what’s-new}

### Composable `useI18nHead` {#usei18nhead-composable}

Anropa `useI18nHead` på valfri sida när `meta: true` (standard). Modulen slår ihop din indata efter `useLocaleHead` vid varje route-uppdatering:

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

Stöder statiska objekt, reaktiva getters, tillägg via `meta` / `link`, `replace` för inbyggda grupper och `disable` för att ta bort automatiskt genererade taggar. Se [`useI18nHead`](/sv/composables/useI18nHead).

### Verktyget `mergeI18nHead` (`@i18n-micro/utils`) {#mergei18nhead-utility-@i18n-micro/utils}

Ramverksoberoende sammanslagningslogik finns i `@i18n-micro/utils/merge-i18n-head` — den används av pluginet `02.meta` och kan testas isolerat. Typer (`I18nHeadInput`, `I18nHeadLink`, `I18nHeadMeta`) exporteras från `@i18n-micro/types`.

### Plugin-integration {#plugin-integration}

- **`02.meta`** — slår ihop utdata från `useLocaleHead` med sidtillståndet från `useI18nHead` via `useHead`
- **`01.plugin`** — återställer sidåsidosättningar när route-namnet ändras via `resetPageHead()` (delat tillstånd med composablen)

### Dokumentation och tester {#documentation-&-tests}

- Ny guide: [`useI18nHead`](/sv/composables/useI18nHead) med exempel för CMS/artiklar
- Uppdaterade [SEO](/sv/guide/seo) och [`useLocaleHead`](/sv/composables/useLocaleHead) — när du ska använda vilket API

## Typiska användningsfall {#typical-use-cases}

| Scenario | Tillvägagångssätt |
| -------------------------------------------- | -------------------------------------------------------------- |
| Blogg/CMS med partiella översättningar | `replace.hreflang` + `replace.ogAlternates` från API:ets locales |
| Egen canonical från CMS | `replace.canonical` + `replace.ogUrl` |
| Endast OG på landningssida | `meta: [{ property: 'og:title', ... }]` — behåll modulens hreflang |
| Ingen hreflang på en sida | `disable: ['hreflang', 'x-default']` |
| Ersätt eget plugin (`i18nManualHreflang`) | `useI18nHead` per innehållssida + `meta: true` |

**JSON-LD** ligger kvar i `useHead({ script: [...] })` — `useI18nHead` genererar inte strukturerad data.

## Brytande ändringar {#breaking-changes}

Inga för vanlig användning av `nuxt.config`. Den nya composablen och utils-undersökvägen är tillägg.

## Varför det spelar roll {#why-it-matters}

- **Inget eget meta-plugin** för CMS-inlägg, nyheter eller guider med URL:er per locale
- **En enda pipeline** — modulens standardvärden + sidåsidosättningar i ett `useHead`-anrop
- **Typsäkert** — `I18nHeadInput` för hjälpfunktioner som `buildArticleHead(content)`

Den fullständiga ändringsloggen publiceras tillsammans med versionen på [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
