`$defineI18nRoute` anger i18n-alternativ för en sida inifrån själva sidan. Använd den när en sida bara finns i vissa locales, behöver en egen lokaliserad sökväg, har några egna översättningar eller inte ska få hreflang-/canonical-taggar. Modulen läser anropet vid byggtid och bakar in det i de genererade routes.

## Begränsa en sida till vissa locales {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

Endast `/product` och `/de/product` genereras under standardstrategin `prefix_except_default`; sidan har ingen route i någon annan locale. Samma sak kan anges från `nuxt.config.ts` med [`routeLocales`](/sv/api/module-options#routelocales).

`$defineI18nRoute` är en injektion i Nuxt-appen, inte ett kompilatormakro: hämta den alltid från `useNuxtApp()` och anropa den med `$`. Endast `$defineI18nRoute(` känns igen av byggsteget.

## Lägg till inline-översättningar {#add-inline-translations}

Skicka ett objekt i stället för en array. Dess nycklar är de tillåtna locales, dess värden slås samman med sidans ordlista för den aktiva locale.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Inline-översättningar levereras inuti sidkomponenten för varje locale. Föredra [sidöversättningsfiler](/sv/guide/translations) för allt som är större än några få nycklar; behåll inline-nycklar för fristående sidor och komponenter.

## Ange lokaliserade sökvägar {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

Med `prefix_except_default` och `defaultLocale: 'en'` ger detta `/welcome` och `/de/willkommen`. En `path` inuti ett inline-locale-objekt gör samma sak: `locales: { de: { path: '/willkommen' } }`. Dynamiska parametrar, nästlade routes och alternativet på konfigurationsnivå beskrivs i [Lokaliserade sökvägar](/sv/guide/custom-locale-routes).

## Stäng av SEO-taggar {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

Alternativet på konfigurationsnivå är [`routeDisableMeta`](/sv/api/module-options#routedisablemeta). Vilka taggarna är beskrivs på sidan [SEO](/sv/guide/seo).

## Vad bygget kan läsa {#what-the-build-can-read}

Byggsteget hittar anropet i varje sidfil och utvärderar dess argument utan att köra din app. Det fungerar när konfigurationen är:

- ett literalt objekt (strängar, arrayer, nästlade objekt, template literals, ternära uttryck på `process.env.NODE_ENV`);
- byggd av konstanter deklarerade i samma `<script setup>` (`const locales = ['en', 'de']`, inklusive spreads);
- en array av objekt med ett `code`-fält (`[{ code: 'en' }, { code: 'de' }]`).

Det kan inte läsa värden som importeras från en annan modul, eller något som kräver din app vid körning (composables, `await`, hämtad data). I så fall loggar bygget `Ignored the $defineI18nRoute() config in <file>` och sidan behåller standard-locales och routes.

Vid körning slår anropet bara samman inline-översättningarna för aktuell locale och slår samman dem igen när locale ändras. `locales`, `localeRoutes` och `disableMeta` får effekt endast via bygget, så att ändra dem kräver ett nytt bygge (utvecklingsservern bygger om när du sparar).
