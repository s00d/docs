---
title: "Anpassad identifiering av locale"
description: "Välj locale själv — efter domän, header eller användarprofil — med ett serverplugin och useI18nLocale().setLocale()."
---

Den inbyggda identifieringen läser URL:en, en cookie och `Accept-Language`. När locale beror på något annat — domänen, en geo-header som sätts av ditt CDN, en användarprofil — sätter du den själv i ett plugin som körs före i18n-pluginet. Modulen laddar sedan översättningarna för den locale och använder den för omdirigeringar precis som om den själv hade identifierat den. Reglerna för när en vald locale vinner över URL:en finns på [Identifiering av locale](/sv/guide/locale-detection); den här sidan visar hur du kopplar in din egen källa.

## Sätt locale i ett serverplugin {#set-the-locale-in-a-server-plugin}

```ts
// plugins/i18n-locale.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10, // before the i18n plugin (order -5)
  setup() {
    const { setLocale } = useI18nLocale()
    const host = (useRequestHeaders(['host']).host ?? '').split(':')[0]! // without the port

    if (host.endsWith('.de')) setLocale('de')
    else if (host.endsWith('.fr')) setLocale('fr')
  },
})
```

`setLocale(code)` skriver locale-tillståndet (`useState('i18n-locale')`) och, när en locale-cookie är konfigurerad, cookien. Använd den i stället för att skriva `useState` eller `useCookie` själv. Skicka bara koder för aktiverade locales.

Behåll pluginet som `.server.ts` när det läser request-headers: de finns inte i webbläsaren. Ett `.client.ts`-plugin är platsen för källor som bara finns i webbläsaren, till exempel `localStorage`.

## Stäng av det inbyggda Accept-Language-steget {#turn-off-the-built-in-accept-language-step}

Ditt plugin och `Accept-Language` kan vara oense. För att bara låta din kod (plus URL:en och cookien) avgöra, stänger du av headern:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    autoDetectLanguage: false,
  },
})
```

[`autoDetectLanguage`](/sv/api/module-options#autodetectlanguage) styr bara header-steget. URL:en och en giltig cookie räknas fortfarande.

## Vad som händer sedan {#what-happens-next}

Effekten av `setLocale` beror på [strategin](/sv/guide/strategy):

| Strategi | Effekt av `setLocale('de')` i pluginet |
| --- | --- |
| `no_prefix` | Sidan renderas på tyska; URL:en ändras inte. |
| `prefix`, `prefix_except_default` | På en sökväg utan prefix där [`autoDetectPath`](/sv/api/module-options#autodetectpath) tillåter omdirigeringar (som standard bara `/`) svarar servern `302` till den tyska URL:en. En URL med locale-prefix behåller det. |
| `prefix_and_default` | Ingen omdirigering: URL:en utan prefix är en giltig sida för standard-locale. |

Under prefixstrategierna är en locale i URL:en användarens val och ditt plugin åsidosätter den inte. `autoDetectPath: '*'` är undantaget: servern flyttar då URL:er med prefix utifrån cookie och `Accept-Language` och ignorerar tillståndet, men `setLocale()` skriver också cookien när en sådan är konfigurerad, så från nästa request kan ditt plugins val omdirigera en URL med prefix. Behåll `'/'` eller använd `'no_prefix'` när explicita locale-URL:er måste vinna. Använd ditt plugin för att välja var en besökare landar, inte för att skriva om länkar som besökaren har följt.

## Respektera en locale som användaren valt {#respect-a-locale-the-user-picked}

När en användare byter språk skriver bytet cookien. Hoppa över din egen identifiering när det redan finns en giltig preferens:

```ts
// plugins/i18n-locale.server.ts
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10,
  setup() {
    const { getPreferredLocale, setLocale, validLocales } = useI18nLocale()
    if (getPreferredLocale()) return // valid state or cookie: keep it

    const country = useRequestHeaders(['x-country'])['x-country']
    if (country === 'JP') return setLocale('ja')

    const header = useRequestHeaders(['accept-language'])['accept-language']
    setLocale(detectLocaleFromAcceptLanguage(header, validLocales))
  },
})
```

`getPreferredLocale()` returnerar tillståndet eller cookien bara när det är en aktiverad locale, så en inaktuell cookie stoppar inte identifieringen. `detectLocaleFromAcceptLanguage` är den q-värdesmedvetna matchare som modulen själv använder (installera `@i18n-micro/utils` för att importera den); `setLocale(null)` gör ingenting.

## En domän per locale {#one-domain-per-locale}

Om varje domän ska servera sina egna locales behöver du inget plugin: ge varje locale en `baseUrl`, sätt `baseDefault: true` på varje domäns standard-locale och bygg en gång (en statisk webbplats kör fortfarande `nuxi generate` per domän). Se [Lager och domäner](/sv/guide/layers#multiple-domains).
