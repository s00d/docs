Alternativet `strategy` avgör om en locale visas i URL:en och för vilka locales. Välj den en gång, innan du publicerar URL:er: att ändra den senare ändrar varje länk. Modulen genererar sedan de lokaliserade routes vid byggtid, och `$localePath`, `<i18n-link>` och språkväljaren läser dem.

## De fyra strategierna {#the-four-strategies}

![Sidan /about på en (standard) och de under varje strategi; samma URL:er listas i texten nedan](/images/diagrams/strategies.svg)

**Typ** `Strategies` · **Standard** `'prefix_except_default'`

URL-routingstrategi för locale-prefix.

- `'no_prefix'` — ingen locale i URL:en; locale lagras i en cookie.
- `'prefix_except_default'` — prefix för alla locales utom standard.
- `'prefix'` — alltid prefix, även för standard-locale.
- `'prefix_and_default'` — som `prefix`, men standard-locale är också åtkomlig utan prefix.

URL:er för en `about`-sida med `defaultLocale: 'en'` och locales `en`, `de`:

| Strategi | Engelska | Tyska | Serveras inte |
| --- | --- | --- | --- |
| `prefix_except_default` (standard) | `/about` | `/de/about` | `/en` och `/en/about` ger 404 |
| `prefix` | `/en/about` | `/de/about` | `/about` omdirigerar till en URL med prefix |
| `prefix_and_default` | `/about` och `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | locale finns inte i URL:en |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

Strategin fastställs vid bygget: en runtime-åsidosättning av den ignoreras med en varning ([Runtime-åsidosättningar](/sv/guide/runtime-overrides)).

## Vilken du ska välja {#which-one-to-choose}

- **`prefix_except_default`**: de flesta webbplatser. Befintliga URL:er utan prefix fortsätter att fungera för standardspråket.
- **`prefix`**: alla språk är likvärdiga; `/` leder alltid till en startsida med prefix.
- **`prefix_and_default`**: du behöver att både `/en/...` och URL:erna utan prefix fungerar, till exempel medan du flyttar från det ena till det andra. URL:er utan prefix omdirigeras aldrig.
- **`no_prefix`**: appar bakom inloggning, eller en URL per sida för alla språk. Locale kommer från en cookie eller `?locale=`. Sökmotorer ser ett språk per URL, så inga `hreflang`-alternativ genereras.

Hur locale väljs för en URL, och när en besökare omdirigeras, beskrivs i [Identifiering av locale](/sv/guide/locale-detection).

## Genererade routes {#generated-routes}

Vid byggtid får varje sida de route-poster som dess strategi behöver. Varje post har `meta.i18n = { name, locales }`: sidan den visar och de locales den serverar. Länkar, byten och omdirigeringar besvaras alla utifrån dessa poster, så en URL som modulen delar ut är alltid en som routern serverar.

Locales som delar sidans sökväg delar en post, `/:locale(de|fr)/about`. En locale med en egen sökväg får en egen post, med namnet `localized-<page>-<locale>`:

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

Anpassade sökvägar, locale-listor per sida och att exkludera en sida från lokalisering beskrivs i [Lokaliserade sökvägar](/sv/guide/custom-locale-routes) och [Sidkonfiguration](/sv/guide/per-component-translations). Prefixet `localized-` är [`localizedRouteNamePrefix`](/sv/api/module-options#localizedroutenameprefix).

<Warning>

**Route-namn genereras** — Hårdkoda inte `localized-…`-namn i `router.push({ name })`. Skicka sidans eget namn till `$localeRoute` eller `<i18n-link>`; de väljer rätt post.

</Warning>

## Länka till en sida i en locale {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- Både namngivna routes och sökvägar fungerar. En sökväg matchas mot de genererade routes, så varje locales form av den accepteras.
- En locale som inte serverar sidan (se `locales` i [Sidkonfiguration](/sv/guide/per-component-translations)) länkar till den locales startsida i stället för till en sida som saknas.
- Parametrar per locale (en översatt slug) går via `$setI18nRouteParams`, se [Lokaliserade sökvägar](/sv/guide/custom-locale-routes).

Signaturer finns i [Metoder](/sv/api/methods).

## Detaljer om `no_prefix` {#no_prefix-details}

- [`localeCookie`](/sv/api/module-options#localecookie) har standardvärdet `'user-locale'` under `no_prefix`, så valet överlever en omladdning.
- `$switchLocale('de')` läser in den tyska ordlistan och ersätter den aktuella historikposten; URL:en ändras inte.
- Anpassade sökvägar per locale fungerar fortfarande: med `globalLocaleRoutes: { about: { de: '/ueber-uns' } }` får tyska läsare `/ueber-uns`. Den URL:en renderas alltid på tyska, oavsett vad besökaren föredrar, och en sida som är begränsad till vissa locales renderas i en av dem. En sökväg som flera locales delar (`en` och `de` båda på `/page/:id`) renderar preferensen när den är en av dem. Själva preferensen kvarstår: nästa sida återgår till den.
- [`noPrefixRedirect: true`](/sv/api/module-options#noprefixredirect) omdirigerar den ursprungliga sökvägen för en sida med en anpassad sökväg i standard-locale: till den anpassade sökvägen för besökarens locale, annars standard-locales (`/about` → `/about-us` när `en` har `/about-us`, → `/ueber-uns` med cookien `de`). En locale utan egen anpassad sökväg stannar på den ursprungliga sökvägen och renderas där. Sidor med parametrar omdirigeras inte.

## Appar utan `pages/` {#apps-without-pages/}

Med `pages: false` finns inga sid-routes att lokalisera. Använd endast rotöversättningsfiler (`disablePageLocales: true`); identifiering, cookien och `$switchLocale` fungerar fortfarande. Varianten `pages-false` av `test/fixtures/basic` i repositoryt är en fungerande uppsättning.
