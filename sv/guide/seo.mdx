Med `meta: true` (standard) får varje lokaliserad sida `<html lang dir>`, en canonical-länk, `hreflang`-alternativ, `x-default` och Open Graph-taggar för locale. Du behöver den här sidan när du vill ange den publika originen, justera vilka locales som visas i taggarna eller åsidosätta dem för en enskild sida. De flesta webbplatser behöver bara en `site.url` eller `metaBaseUrl` och korrekta `iso`-koder.

## Minimal konfiguration {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

`/de/about` renderar då:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Textriktning {#text-direction}

`<html dir>` kommer från locale:ns `dir`. Utan ett sådant får ett språk som skrivs från höger till vänster `rtl`, utläst från `iso` (eller `code`): arabiska, hebreiska, persiska, urdu och några till, samt alla taggar med en RTL-skrift som `az-Arab`. Alla andra locales får inget `dir`-attribut, vilket webbläsare tolkar som `ltr`.

<Warning>

**`dir: 'auto'` kostar tolkningstid på stora sidor** — `auto` på `<html>` får webbläsaren att räkna ut riktningen från innehållet medan den tolkar sidan. I Chromium växer den kostnaden snabbare än sidan: cirka 100 ms vid 5 000 element och 1 s vid 20 000. Använd det bara för en liten sida vars språk du inte kan känna till.

</Warning>

## Vilka taggar du får {#which-tags-you-get}

- **hreflang**: en tagg per locale som serverar sidan, med värdet `iso` (eller `code` när `iso` saknas), och dess URL med samma query som canonical. En sida som begränsats med [Sidkonfiguration](/sv/guide/per-component-translations) eller `routeLocales` listar bara sina locales. [`hreflangBaseLanguage: true`](/sv/api/module-options#hreflangbaselanguage) lägger även till det rena språket (`es-ES` → `es`) för den första regionala locale:n.
- **x-default**: standard-locale:ns URL, bara när standard-locale:n serverar sidan.
- **og:locale**: härleds från `iso` (`en-US` → `en_US`). Sätt `og` på locale:n när mappningen inte är direkt, till exempel `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; utan någon av dem skrivs ingen `og:locale` och dev-läget varnar.
- **canonical / og:url**: den aktuella URL:en utan query-parametrar, förutom de i [`canonicalQueryWhitelist`](/sv/api/module-options#canonicalquerywhitelist) (standard `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Per strategi:

| Strategi | hreflang och x-default | canonical, og:url, og:locale, html-attribut |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | ja | ja |
| `no_prefix` | nej (en URL serverar alla locales) | ja |

## Ange den publika originen {#set-the-public-origin}

Absoluta URL:er använder det första av:

1. [`metaBaseUrl`](/sv/api/module-options#metabaseurl);
2. `site.url` från `nuxt-site-config` (installeras av `@nuxtjs/seo`);
3. förfrågans origin, med `app.baseURL` tillagd.

Lås ett av de två första.

<Warning>

Reservlösningen med förfrågans origin läser `X-Forwarded-Host` och `X-Forwarded-Proto`, eftersom [`metaTrustForwardedHost`](/sv/api/module-options#metatrustforwardedhost) och `metaTrustForwardedProto` har standardvärdet `true`. Det är bara säkert bakom en proxy som skriver över de headrarna; annars kan en klient välja värden i dina canonical-länkar, och en cache kan föra den sidan vidare.

Om appen kan nås direkt, lås `metaBaseUrl`: till skillnad från att sätta båda alternativen till `false` ignorerar det även en förfalskad `Host`. Se [Bakom en proxy eller CDN](/sv/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

Reservlösningen är användbar när en driftsättning svarar för flera domäner: `https://site-a.com/en/about` och `https://site-b.com/en/about` får var sin origin.

Med `baseUrl` på locales använder en känd värd sin egen `baseUrl`, före `metaBaseUrl` och `site.url`, så att canonical och `og:url` stannar på den domänen och `hreflang` pekar varje locale till dess domän. Alla andra värdar använder `metaBaseUrl`, annars standard-locale:ns `baseUrl`, annars `site.url`, så att en förfalskad `Host` inte kan nå dina taggar. Om inget av dessa är satt används reservlösningen med förfrågans origin, och bygget varnar. Se [Lager och domäner](/sv/guide/layers#multiple-domains).

## Utelämna locales eller sidor {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Om standard-locale:n har `seo: false` skrivs ingen `x-default`. För att stänga av taggarna för en enskild sida använder du `disableMeta` i [Sidkonfiguration](/sv/guide/per-component-translations#turn-off-seo-tags), eller [`routeDisableMeta`](/sv/api/module-options#routedisablemeta) i konfigurationen.

## Åsidosätt taggar på en sida {#override-tags-on-one-page}

För CMS-innehåll där bara vissa översättningar finns, eller där URL:er kommer från ett API, ersätter du de genererade taggarna med [`useI18nHead`](/sv/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` kan också sätta eller ta bort `canonical`, `xDefault`, `ogLocale` och `ogUrl`; `disable` tar bort hela grupper (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Skicka en getter så att värdena beräknas om efter ett byte av locale. För slugs per locale, sätt `$setI18nRouteParams` först ([Lokaliserade sökvägar](/sv/guide/custom-locale-routes#per-locale-slugs)) så använder de genererade alternativen dem redan.

## Avslutande snedstreck {#trailing-slash}

`$localePath`, `$switchLocalePath`, route-objektet från `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, locale-omdirigeringar och SEO-URL:erna följer en och samma regel för snedstreck: `experimental.defaults.nuxtLink.trailingSlash` som standard, eller [`trailingSlash`](/sv/api/module-options) i i18n-konfigurationen när i18n-sökvägar ska skilja sig.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) fungerar med den här modulen via `nuxt-site-config` 4+. Lista `nuxt-i18n-micro` först så att site config kan läsa locales, och ange `site.url` en gång — den matar även taggarna ovan.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Ett översatt webbplatsnamn och en översatt beskrivning kommer från nycklarna `nuxtSiteConfig.name` / `nuxtSiteConfig.description` i dina locale-filer. Felet `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` betyder att `@nuxtjs/seo` är äldre än 3; uppgradera den ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
