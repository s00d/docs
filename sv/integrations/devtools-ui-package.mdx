`@i18n-micro/devtools-ui` är översättningsredigeraren från fliken i Nuxt DevTools, paketerad som en webbkomponent med ett Vite-plugin. Lägg till den i ett Vue-, React-, Preact-, Solid- eller Astro-projekt för att bläddra bland och redigera JSON-filerna i din översättningsmapp från webbläsaren under utveckling. Nuxt-appar har den redan i [Nuxt DevTools](/sv/guide/devtools).

![DevTools UI: ett filträd och en redigerare med standard-locales text bredvid varje nyckel](/images/devtools/02-translations-editor-dark.webp)

<CodeGroup>

Inga peer-beroenden.

## Konfiguration {#setup}

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import { i18nDevToolsPlugin } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  plugins: [i18nDevToolsPlugin({ translationDir: 'src/locales' })],
})
```

| Alternativ | Standard | Anmärkningar |
| --- | --- | --- |
| `translationDir` | `'src/locales'` | Mapp med JSON-filerna, relativt Vite-roten. |
| `base` | `'/__i18n_api'` | Bassökväg för API-slutpunkterna. |
| `injectButton` | `true` | Lägg till en flytande knapp på sidor som serveras via Vites `index.html`-transformering. Astro har inga sådana sidor: se nedan. |
| `defaultLocale` | första locale-filen i `translationDir` | Rapporteras av `/config`. |
| `fallbackLocale` | `defaultLocale` | Rapporteras av `/config`. |

Pluginet körs endast på utvecklingsservern (`apply: 'serve'`); ett produktionsbygge innehåller ingenting från det. Knappen öppnar `/__i18n_devtools.html`, som läser och sparar filer via pluginets slutpunkter:

| Slutpunkt | Gör |
| --- | --- |
| `GET <base>/translations` | alla ordlistor under `translationDir`, efter relativ sökväg |
| `POST <base>/save` | body `{ file, content }`; skriver över en befintlig `.json` i `translationDir`, 403 för allt annat. Den skapar aldrig en fil |
| `GET <base>/config` | `{ defaultLocale, fallbackLocale, locales, translationDir }`; `locales` kommer från rotfilerna i `translationDir` |

Slutpunkterna svarar endast devtools-sidan: en begäran från ett annat ursprung eller en annan värd ger `403`, och `/save` tar endast emot `application/json` (`415`). Sidan får veta om filändringar via Vites HMR-socket.

I Astro lägger du till integrationen i stället för pluginet. Den lägger till en app i utvecklingsverktygsfältet:

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import { i18nDevToolsIntegration } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  integrations: [i18nDevToolsIntegration({ translationDir: 'src/locales' })],
})
```

Att spara skriver bara filen. En app som importerar JSON-filen via Vite får den via HMR; för att ändringar ska tillämpas direkt på den körande instansen använder du en brygga.

## Brygga till en körande instans {#bridge-to-a-live-instance}

För att bädda in redigeraren på din egen sida och få ändringar tillämpade direkt på den körande instansen skapar du en brygga från en adapter och skickar den till elementet `<i18n-devtools-ui>`:

```ts
import { createBridge, register } from '@i18n-micro/devtools-ui'
import { i18n, locales } from './i18n' // a runtime, React, Preact or Solid instance

register() // defines <i18n-devtools-ui> once

const bridge = createBridge({
  adapter: {
    getRouteCache: () => Object.fromEntries(i18n.storage.translations),
    addTranslations: (locale, content, merge) => i18n.addTranslations(locale, content, merge),
    addRouteTranslations: (locale, route, content, merge) => i18n.addRouteTranslations(locale, route, content, merge),
    subscribe: (cb) => i18n.subscribe(cb),
    getCurrentLocale: () => i18n.locale,
  },
  locales,
  defaultLocale: 'en',
  translationDir: 'src/locales',
})

const el = document.createElement('i18n-devtools-ui') as HTMLElement & { bridge: typeof bridge }
el.bridge = bridge
document.body.append(el)
```

`getRouteCache` måste returnera ordlistorna med nycklar på formen `locale:route` (`en:index`, `en:blog-post`), vilket är vad `i18n.storage.translations` innehåller. För en Vue-instans använder du `i18n.global.getRouteCache()` och `i18n.global.subscribeToChanges(cb)`.

`saveTranslation` uppdaterar först instansen och skickar sedan en POST till `<base>/save`. När det inte finns någon slutpunkt (ett statiskt förhandsgranskningsbygge) eller utvecklingsservern inte kan nås sparas ändringen i `localStorage`; alla andra fel vid sparande återställer den föregående ordlistan och kastar ett undantag.
