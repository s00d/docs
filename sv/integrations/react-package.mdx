`@i18n-micro/react` och `@i18n-micro/preact` kapslar in den ramverksoberoende [runtime](/sv/integrations/runtime-package) i en provider, en `useI18n()`-hook och fyra komponenter. Använd dem i en React- eller Preact-app som inte är byggd med Nuxt. Båda paketen har samma API; blocket [Preact](#preact) listar de få skillnaderna, och den gemensamma modellen finns i [Ramverk](/sv/integrations/overview).

## Installation {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/react
```

```bash npm
npm install @i18n-micro/react
```

```bash yarn
yarn add @i18n-micro/react
```

</CodeGroup>

Peer-beroenden: `react` `^18.0.0 || ^19.0.0`; `react-dom` (valfritt, för rendering); `react-router-dom` `^6.0.0 || ^7.0.0` (valfritt, endast för `@i18n-micro/react/router`). Testat på React 19.3 och 18.3, React Router 7.18 och 6.30.

## Konfiguration {#setup}

```tsx
// src/main.tsx
import { createRoot } from 'react-dom/client'
import { createI18n, I18nProvider } from '@i18n-micro/react'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

createRoot(document.getElementById('root')!).render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
    <App />
  </I18nProvider>,
)
```

<Warning>

Skapa instansen en gång, på modulnivå eller i en `useState`-initierare, aldrig i en komponentkropp.

</Warning>

`<I18nProvider>` tar `i18n`, `locales`, `defaultLocale` och `routingStrategy`:

- En utelämnad prop behåller värdet från en yttre provider, inklusive instansen.
- Utan någon instans alls bygger den en från `createI18n`-alternativen bredvid dem, så att props förblir rena data: `<I18nProvider locale="de" messages={messages}>`.
- En ny `locale`-prop bygger en ny instans med den renderingens `messages`. En sådan instans lever i komponenten: om något ovanför den suspenderar under montering kastar React bort den, tillsammans med allt som lagts till i den.

Alla `createI18n`-alternativ, inklusive `routeMessages`, finns i [instansen](/sv/integrations/overview#the-instance).

## Översätt {#translate}

```tsx
import { useI18n } from '@i18n-micro/react'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' })}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

`useI18n()` returnerar:

| Grupp | Medlemmar |
| --- | --- |
| Översätt | `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` |
| Locale och route | `locale`, `fallbackLocale`, `currentRoute`, `setLocale`, `setRoute`, `getRoute`, `getLocales`, `defaultLocale()`, `getLocaleName` |
| Routing | `switchLocale`, `localePath`, `localeRoute` |
| Ordlistor | `addTranslations`, `addRouteTranslations`, `clearCache` |

- Komponenten renderas om när locale, route eller en läsbar ordlista ändras, och när providern får ett nytt `locales`- eller `routingStrategy`-objekt. En ordlista för en locale som varken är aktiv eller reserv renderar ingenting.
- `t` och de andra översättningsmetoderna ändras bara med store, så de är säkra i `memo` och effektberoenden.

`useT` är en enda sträng som värde. Komponenten renderas bara när den strängen ändras, oavsett vad som händer med providerns övriga props; `<I18nT>` beror inte heller på dem:

```tsx
const title = useT('page.title')
```

Ladda fler ordlistor när som helst:

```tsx
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

useEffect(() => {
  import('./locales/de.json').then((m) => addTranslations('de', m.default))
  addRouteTranslations('en', 'about', { title: 'About us' })
  setRoute('about') // t('title') now reads the 'about' dictionary first
}, [])
```

Instansen själv har också `loadFromUrl(url, { locale, routeName })` för JSON via `fetch`.

## Byt locale {#switch-locale}

```tsx
const { setLocale, switchLocale } = useI18n()

setLocale('de') // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Ett byte laddar ingenting; lägg till locales ordlista först. En skrivning till store är synkron för React, även inuti `startTransition`, så en komponent som suspenderar på en saknad ordlista skulle visa sin fallback. `useLocaleSwitch` laddar först och behåller det gamla gränssnittet tills ordlistan är på plats:

```tsx
const [switchTo, pending] = useLocaleSwitch((locale) => i18n.loadFromUrl(`/locales/${locale}.json`, { locale }))

<button disabled={pending} onClick={() => switchTo('de')}>Deutsch</button>
```

Det sista anropet vinner. En misslyckad laddning avvisas och lämnar locale som den var.

`<I18nGroup>` skickar en `t` med prefix till ett render-prop-barn. `<I18nT>` och `t()` inuti den får inget prefix:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Routing {#routing}

Adaptern för React Router ligger i en undersökväg så att huvudingången aldrig importerar `react-router-dom`. Den behöver `useLocation()` och `useNavigate()`, så skapa den i en komponent under routern:

```tsx
// src/App.tsx
import { useMemo } from 'react'
import { BrowserRouter, Route, Routes, useLocation, useNavigate } from 'react-router-dom'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/react'
import { createReactRouterAdapter } from '@i18n-micro/react/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Localized() {
  const location = useLocation()
  const navigate = useNavigate()
  // memoized: a new object on every render re-renders every `useI18n()` consumer
  const routingStrategy = useMemo(() => createReactRouterAdapter(locales, 'en', location, navigate), [location, navigate])
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      <Routes>
        <Route path="/:locale?" element={<Home />} />
        <Route path="/:locale?/about" element={<About />} />
      </Routes>
    </I18nProvider>
  )
}

export default function App() {
  return (
    <BrowserRouter>
      <Localized />
    </BrowserRouter>
  )
}
```

Adaptern ger prefix till varje locale utom standard (`/about`, `/de/about`) och renderar `<I18nLink>` som React Routers `<Link>`. Sätt locale från URL:en själv (till exempel från `useParams().locale` i en effekt). För alla andra routers, skriv en adapter med `getCurrentPath`, `push` och `replace` (alla obligatoriska) — se [Router-adapter](/sv/integrations/overview#router-adapter).

## SSR {#ssr}

`renderToString` fungerar: `useI18n()` har en server-snapshot. Skapa en instans per förfrågan och lägg till dess ordlistor innan du renderar, så att förfrågningar på olika locales inte delar tillstånd, eller skicka rena data till providern.

### Hydrering {#hydration}

Tal, pluralformer och text hydreras som de är. Ett datum beror på tidszonen och ett relativt datum på klockan: sätt `timeZone` på servern och i webbläsaren, och för `tdr`, ge webbläsaren serverns tid med `now`. `<I18nT>` med `date` eller `relativeDate` sätter `suppressHydrationWarning`, så en skillnad får inte hydreringen att misslyckas, men serverns text ligger kvar tills texten ändras. Det når bara en nivå: `children` som omsluter översättningen i ett element misslyckas fortfarande vid en skillnad, så ge dem samma `timeZone`.

### Server Components {#server-components}

Paketet markerar sin klientkod med `'use client'`. `@i18n-micro/react/server` har `createI18n` och en `I18nT` utan hooks som tar instansen som prop, så texten hålls utanför klientpaketet. Under villkoret `react-server`, som i Next.js app router, löses även huvudingången till den, men TypeScript vet inte det som standard: importera från `/server`. `@i18n-micro/react/client` ger alltid klientingången.

```tsx
// app/[locale]/layout.tsx: a server component
import { cache } from 'react'
import { createI18n, I18nT } from '@i18n-micro/react/server'
import { I18nProvider } from '@i18n-micro/react/client'
import { loadMessages } from './messages'

const getI18n = cache(async (locale: string) => createI18n({ locale, messages: await loadMessages(locale) }))

export default async function Layout({ params, children }) {
  const { locale } = await params
  const i18n = await getI18n(locale)
  return (
    <I18nProvider locale={locale} messages={{ [locale]: i18n.resolveTranslations() }}>
      <h1>
        <I18nT i18n={i18n} keypath="title" />
      </h1>
      {children}
    </I18nProvider>
  )
}
```

Renderat via `react-server-dom-webpack`; en Next.js-app i sig har inte körts mot detta.

## Preact {#preact}

`@i18n-micro/preact` byggs från samma källkod, på Preact självt, utan `preact/compat`: samma instans, provider, hooks och komponenter. Skillnader:

| | React | Preact |
| --- | --- | --- |
| Peer-beroende | `react` (+ valfritt `react-router-dom`) | `preact` `^10.0.0 \|\| ^11.0.0`, testat på 10.29 och 11.1 |
| Instansklass | `ReactI18n` | `PreactI18n` |
| Router-adapter | `createReactRouterAdapter` från `/router` | `createBrowserHistoryAdapter(locales, defaultLocale, ssrUrl?)` från `/router` |
| Omrendering | `useSyncExternalStore` | en layout-effect-prenumeration som kontrollerar store igen |
| Server Components | `/server`, `/client` | inga |

`createBrowserHistoryAdapter` fungerar med vilken History API-router som helst (wouter, preact-router): `push` och `replace` anropar `history.pushState` / `replaceState` och skickar `popstate`, och `<I18nLink>` renderar en vanlig `<a>` som navigerar via `push`. En server har inget adressfält: skicka förfrågans URL som `ssrUrl`, annars renderas länkar och språkväljaren som på `/`. I en webbläsare vinner adressfältet.

```tsx
// src/main.tsx
import { render } from 'preact'
import { createI18n, I18nProvider } from '@i18n-micro/preact'
import { createBrowserHistoryAdapter } from '@i18n-micro/preact/router'
import { App } from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={createBrowserHistoryAdapter(locales, 'en')}>
    <App />
  </I18nProvider>,
  document.getElementById('app')!,
)
```
