`@i18n-micro/solid` ger SolidJS-appar en signalbaserad i18n-instans, en provider, `useI18n()` och fyra komponenter. Använd den i en Solid-app som inte är byggd med Nuxt. Läsningar av `t()` i JSX eller effekter spårar locale, route och ordlistorna; den gemensamma modellen finns i [Ramverk](/sv/integrations/overview).

## Installation {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer-beroenden: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (valfritt, endast för `@i18n-micro/solid/router`). Solid 2 stöds inte ännu.

## Konfiguration {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` tar `i18n`, `locales`, `defaultLocale` och `routingStrategy`; en utelämnad prop behåller den yttre providerns värde, inklusive instansen. `getLocaleName()` och `<I18nSwitcher>` läser `locales`; utan dem har de inget att lista. Alternativen finns i [instansen](/sv/integrations/overview#the-instance). Instansen är [runtime](/sv/integrations/runtime-package)-instansen, med en signal över dess store.

## Översätt {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Anropa metoderna i JSX eller en effekt så att Solid spårar dem, även `localePath` och `getLocale`; ett värde som läses en gång i komponentkroppen uppdateras inte. På instansen, spåra med `i18n.locale` och `i18n.currentRoute`: `i18n.getLocale()` förblir vanlig, eftersom skrivningar läser den. Att läsa locale reagerar bara på locale, så en effekt som läser den och laddar en ordlista körs en gång. Destrukturera inte props och spara inte `t('key')`-resultat i vanliga variabler.

`useI18n()` returnerar `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (en accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` och `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Byt locale {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Ett byte laddar ingenting; lägg till locales ordlista först.

`<I18nGroup>` skickar en `t` med prefix till ett funktionsbarn. `<I18nT>` och `t()` inuti den får inget prefix:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Routing {#routing}

Adaptern för `@solidjs/router` ligger i en undersökväg så att huvudingången aldrig importerar routern. Anropa den under routern, vanligtvis i routerns `root`, där `useNavigate` och `useLocation` fungerar:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

Adaptern ger prefix till varje locale utom standard (`/about`, `/de/about`) och renderar `<I18nLink>` som routerns `<A>`. `getCurrentPath` läser routerns reaktiva location, så aktiva länkar och språkväljaren följer den; en anpassad strategi får samma sak genom att läsa en signal där. Observera argumentordningen: `(locales, defaultLocale, navigate, location)`. För andra routers, skriv en adapter med `getCurrentPath`, `push` och `replace` (alla obligatoriska) — se [Router-adapter](/sv/integrations/overview#router-adapter).

## SSR {#ssr}

För serverrendering, bygg med `vite-plugin-solid`: paketets exportvillkor `solid` ger den källkoden, så den kompileras för servern. Den förbyggda `dist` är endast för webbläsaren. Instansen har ingen `destroy()`; skapa en per app, eller en per förfrågan på servern, och låt den skräpsamlas.
