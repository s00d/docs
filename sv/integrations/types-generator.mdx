# 🔧 Types-generator (`@i18n-micro/types-generator`)

Paketet `@i18n-micro/types-generator` tillhandahåller automatisk generering av TypeScript-typer för översättningsnycklar. Det analyserar dina JSON-översättningsfiler och genererar strikta typer, vilket möjliggör fullständig typsäkerhet och autokompletteringsstöd för översättningsnycklar.

## 📖 Översikt

`@i18n-micro/types-generator` är ett valfritt dev-beroende som förbättrar din utvecklarupplevelse genom att:

- 🔍 **Automatisk typgenerering** - Skannar JSON-översättningsfiler och genererar TypeScript-typer
- ✅ **Typsäkerhet** - Förhindrar typos och ogiltiga översättningsnycklar vid kompilering
- 🎯 **Autokompletteringsstöd** - Fullständig IDE-autokomplettering för översättningsnycklar
- 🔄 **Hot reload** - Regenererar automatiskt typer när översättningsfiler ändras
- 🚀 **Noll runtime-overhead** - Typer finns endast vid kompilering, ingen påverkan på bundle-storlek

## 🎯 Snabbstart

### För Nuxt-projekt

Lägg till modulen i din `nuxt.config.ts`:

```typescript
import { defineNuxtConfig } from 'nuxt/config'

export default defineNuxtConfig({
  modules: [
    'nuxt-i18n-micro',
    '@i18n-micro/types-generator/nuxt', // Add types generator
  ],
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    translationDir: 'locales', // Path to your translation files
  },
})
```

Generatorn kommer automatiskt att:

- Skanna alla JSON-filer i din `locales`-katalog
- Generera typer i `.nuxt/i18n-micro.d.ts`
- Bevaka ändringar och regenerera typer automatiskt

### För Vue/Vite-projekt

Lägg till pluginen i din `vite.config.ts`:

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { I18nTypesPlugin } from '@i18n-micro/types-generator'

export default defineConfig({
  plugins: [
    vue(),
    I18nTypesPlugin({
      srcDir: 'src',
      translationDir: 'locales',
      outputFile: 'src/i18n-types.d.ts', // Optional: custom output path
    }),
  ],
})
```

Se till att inkludera den genererade filen i din `tsconfig.json`:

```json
{
  "include": ["src/**/*", "src/i18n-types.d.ts"]
}
```

## 📁 Struktur för översättningsfiler

Generatorn stöder både platta och nästlade översättningsstrukturer:

```
locales/
  en.json
  fr.json
  pages/
    home/
      en.json
      fr.json
    about/
      en.json
      fr.json
```

**Exempel `locales/en.json`:**

```json
{
  "greeting": "Hello, {name}!",
  "header": {
    "title": "Welcome",
    "subtitle": "Subtitle"
  },
  "errors": {
    "404": "Not found",
    "500": "Server error"
  },
  "apples": "no apples | one apple | {count} apples"
}
```

Generatorn skapar typer för alla nycklar, inklusive nästlade:

```typescript
// Generated types
declare module '@i18n-micro/types' {
  export interface DefineLocaleMessage {
    greeting: string
    'header.title': string
    'header.subtitle': string
    'errors.404': string
    'errors.500': string
    apples: string
  }
}
```

## 💡 Användning

När typerna är genererade får du fullständig typsäkerhet:

```typescript
import { useI18n } from '@i18n-micro/vue'

const { t } = useI18n()

// ✅ Type-safe: autocomplete works
t('greeting', { name: 'World' })
t('header.title')
t('errors.404')

// ❌ Type error: key doesn't exist
t('invalid.key') // Error: Argument of type '"invalid.key"' is not assignable
```

### Nuxt-specifik anmärkning

**I Nuxt-projekt fungerar typsäkerhet endast med composablen `useI18n`.** De genererade typerna tillämpas på composablens returvärde och säkerställer typsäkerhet vid användning av metoderna `t()`, `ts()`, `tc()` och `has()`.

```typescript
// ✅ Correct: Using useI18n composable
<script setup lang="ts">
import { useI18n } from '#imports'

const { t } = useI18n()
t('greeting') // Type-safe with autocomplete
</script>

// ❌ Not type-safe: Direct access to $i18n or other methods
// Type safety is only available through the useI18n composable
```

## 🔄 Dynamiska nycklar

Ibland behöver du använda dynamiska nycklar (till exempel baserat på användarinmatning eller API-svar). Generatorn tillhandahåller en hjälptyp `ScopedKey` för säker användning av dynamiska nycklar.

### Varför inte runtime-typkontroller?

**Runtime-typkontroller rekommenderas inte** för i18n-micro eftersom:

1. **Bundle-storlek** - Att generera en JavaScript-array med alla nycklar skulle blåsa upp din bundle
2. **Prestanda** - Runtime-kontroller lägger till onödig overhead
3. **Filosofi** - i18n-micro är utformad för att vara lättviktig och snabb

### TypeScript-sättet: Typassertion

För dynamiska nycklar, använd TypeScripts typassertion:

```typescript
import type { TranslationKey, ScopedKey } from '@i18n-micro/types'

// ❌ Type error: dynamic key
const status = 'pending'
t(`status.${status}`) // Error: string is not assignable to TranslationKey

// ✅ Solution 1: Type assertion (if you're sure the key exists)
t(`status.${status}` as TranslationKey)

// ✅ Solution 2: ScopedKey helper (safer, checks prefix exists)
function getStatusText(status: string) {
  return t(`status.${status}` as ScopedKey<'status'>)
  // TypeScript verifies that keys starting with 'status.' exist
}

// ✅ Solution 3: Runtime check with has()
if (has(`status.${status}`)) {
  t(`status.${status}` as TranslationKey)
}
```

### ScopedKey-hjälpare

Typen `ScopedKey<Scope>` låter dig begränsa dynamiska nycklar efter prefix:

```typescript
import type { ScopedKey } from '@i18n-micro/types'

// Assuming you have keys: 'errors.404', 'errors.500', 'btn.save'

function getErrorText(code: string) {
  // ✅ Safer than plain TranslationKey
  // TypeScript verifies that 'errors.*' keys exist
  return t(`errors.${code}` as ScopedKey<'errors'>)
}

// ❌ Type error: 'btn' prefix doesn't match 'errors'
function getErrorTextWrong(code: string) {
  return t(`errors.${code}` as ScopedKey<'btn'>) // Error
}
```

## 🎨 Avancerad användning

### Hantera ruttspecifika översättningar

Generatorn inkluderar automatiskt nycklar från ruttspecifika översättningsfiler:

```
locales/
  en.json                    # Root-level translations
  pages/
    home/
      en.json               # Route-specific translations
    about/
      en.json
```

Alla nycklar från både rotnivåfiler och ruttspecifika filer inkluderas i de genererade typerna.

### Inaktivera sidlokaler

Om du använder `disablePageLocales: true` i din i18n-konfiguration kommer generatorn att behandla alla filer (inklusive de i `pages/`) som rotnivåöversättningar.

## 🐛 Felsökning

### Typer uppdateras inte

1. **Kontrollera filsökvägar** - Se till att `translationDir` pekar på rätt katalog
2. **Starta om TypeScript-servern** - I VS Code: `Cmd/Ctrl + Shift + P` → "TypeScript: Restart TS Server"
3. **Kontrollera tsconfig.json** - Se till att den genererade filen är inkluderad

### Typfel efter tillägg av nycklar

1. **Regenerera typer** - Generatorn bör auto-regenerera, men du kan trigga det manuellt
2. **Kontrollera JSON-syntax** - Ogiltiga JSON-filer hoppas över med en varning
3. **Starta om dev-servern** - Ibland behövs för att ändringar ska träda i kraft

### Autokomplettering fungerar inte

1. **Verifiera filinkludering** - Kontrollera att den genererade `.d.ts`-filen är i din `tsconfig.json` include
2. **Kontrollera modul-augmentering** - Se till att den genererade filen använder `declare module '@i18n-micro/types'`
3. **TypeScript-version** - Kräver TypeScript 4.1+ för template literal-typer

## 📚 API-referens

### `generateTypes(options: GeneratorOptions)`

Generera typer manuellt (användbart för skript eller CI):

```typescript
import { generateTypes } from '@i18n-micro/types-generator'

await generateTypes({
  srcDir: './src',
  translationDir: 'locales',
  outputFile: './src/i18n-types.d.ts',
})
```

### `flattenKeys(obj: Record<string, unknown>, prefix?: string)`

Verktygsfunktion för att platta ut nästlade översättningsobjekt:

```typescript
import { flattenKeys } from '@i18n-micro/types-generator'

const keys = flattenKeys({
  header: { title: 'Title' },
  footer: { copyright: 'Copyright' },
})
// Returns: ['header.title', 'footer.copyright']
```

## 🔍 Så fungerar det

1. **Skanning** - Använder `globby` för att hitta alla `**/*.json`-filer i översättningskatalogen
2. **Parsning** - Parsar varje JSON-fil och extraherar alla nycklar med rekursiv utplattning
3. **Deduplicering** - Kombinerar nycklar från alla filer till en unik uppsättning
4. **Generering** - Skapar en `.d.ts`-fil med `declare module`-augmentering
5. **Bevakning** - I dev-läge bevakar den filändringar och regenererar typer

Den genererade filen använder TypeScripts modul-augmentering för att utöka `DefineLocaleMessage` i `@i18n-micro/types`, vilket automatiskt uppdaterar typen `TranslationKey` i hela ditt projekt.

## 🎯 Bästa praxis

1. **Håll översättningar organiserade** - Använd nästlade objekt för relaterade nycklar
2. **Använd konsekvent namngivning** - Följ en namngivningskonvention (till exempel `errors.*`, `buttons.*`)
3. **Utnyttja ScopedKey** - Använd `ScopedKey` för dynamiska nycklar i stället för vanliga assertions
4. **Kontrollera typer i CI** - Kör typkontroll i din CI-pipeline
5. **Redigera inte genererade filer** - `.d.ts`-filen är autogenererad och kommer att skrivas över
