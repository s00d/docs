title: "Hooks"
description: "Runtime-hooken i18n:register: lägg till översättningar från ett Nuxt-plugin vid inläsning och vid navigering."
---

Modulen anropar en runtime-hook (app-hook), `i18n:register`. Använd den när ett plugin eller en modul lägger till översättningar som inte finns i dina `locales/`-filer. Din callback får en `register`-funktion som slår samman översättningar med sidan som visas.

## `i18n:register` {#i18nregister}

```ts
'i18n:register': (
  register: (translations: unknown, locale?: string) => void,
  locale: string,
) => HookResult
```

| Argument | Beskrivning |
| --- | --- |
| `register(translations, locale?)` | Djupsammanfogar `translations` med sidchunken för routen som läses in, för `locale` (standard: hookens `locale`). Nycklar som redan finns skrivs över. |
| `locale` | Locale för routen som läses in. |

Hooken är typad via `RuntimeNuxtHooks`, så `nuxtApp.hook('i18n:register', …)` behöver ingen typomvandling.

## När den körs {#when-it-fires}

Loader-pluginet (`i18n-plugin-loader`) anropar den:

1. en gång vid uppstart, när alla plugins har körts (`app:created`) och innan appen renderas;
2. i sin `router.beforeEach`, efter att målsidans översättningar har lästs in, när sökvägen ändras — vid varje navigering under `no_prefix`.

Varje callback och varje `register`-anrop inväntas innan appen renderas eller navigeringen fortsätter, så sidan renderas med de sammanfogade nycklarna. Med [`hooks: false`](/sv/api/module-options#hooks) anropas hooken aldrig.

## Exempel {#example}

```ts
// plugins/i18n-extra.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('i18n:register', async (register, locale) => {
    const extra = await $fetch<Record<string, unknown>>(`/api/cms-strings/${locale}`)
    register(extra, locale)
  })
})
```

Detta är en runtime-hook: registrera den med `nuxtApp.hook` i ett plugin, inte med `nuxt.hook` i `nuxt.config` eller i en moduls `setup`. En modul lägger till ett sådant plugin med `addPlugin`.
