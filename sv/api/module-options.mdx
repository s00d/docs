# Referens för modulalternativ

Varje alternativ som `nuxt-i18n-micro` accepterar, läst vid byggtid från gränssnittet `ModuleOptions` i [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts). Ingenting här är handskrivet, så det kan inte hamna efter koden. Typer, standardvärden och beskrivningar kommer från själva deklarationen.

För vad dessa alternativ *betyder* tillsammans — vilka kombinationer som är meningsfulla, vad som förändras när du byter strategi, med praktiska exempel — läs [Konfiguration](/guides/configuration). Denna sida är den uttömmande listan; den andra är förklaringen.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Nästlade alternativ visas under sin punktade sökväg, så `translationPayloads.mode` är nyckeln `mode` inuti objektet `translationPayloads`.

## Lokaler och routing

Vilka språk som finns och hur de visas i URL:en.

| Alternativ | Typ | Standard | Beskrivning |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Lista över lokaler som stöds. Varje post definierar en lokalkod plus valfri metadata (ISO, riktning, visningsnamn med mera). |
| `strategy` | `Strategies` | `'prefix_except_default'` | URL-routingstrategi för lokalprefix. - `'no_prefix'` — ingen lokal i URL; lokalen lagras i cookie. - `'prefix_except_default'` — prefixera alla lokaler utom standardlokalen. - `'prefix'` — prefixera alltid, inklusive standardlokalen. - `'prefix_and_default'` — som `prefix`, men standardlokalen är också tillgänglig utan prefix. |
| `defaultLocale` | `string` | `'en'` | Lokalen som ska användas när ingen lokal kan bestämmas från URL eller användarpreferenser. Används även som fallback-lokal för saknade översättningar när `fallbackLocale` inte är satt. |
| `localeCookie` | `string \| null` | `null` | Cookienamn för att bevara användarens lokalpreferens mellan sessioner. Sätt till `null` för att inaktivera cookiebaserad beständighet. Sätts automatiskt till `'user-locale'` för strategin `no_prefix` om inget värde ges. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Global lokalkonfiguration på ruttnivå. Tillåter att begränsa eller anpassa lokalrutter för specifika sidor utan att ändra deras komponenter. - `false` — exkludera rutten från lokalisering. - `Record<LocaleCode, string>` — anpassade per-lokala sökvägar. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Anpassat reguljärt uttryck (eller dess strängkälla) för att matcha lokalkoder i URL-segment. Alla lokalkoder som definieras i `locales` måste matcha detta mönster, annars skickas en varning. |
| `noPrefixRedirect` | `boolean` | `false` | För `no_prefix`-strategin: aktivera omdirigering från en lokalprefixerad URL (till exempel `/en/about`) till den oprefixerade versionen (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | URL-mönster (strängar eller RegExp) som ska exkluderas helt från i18n-bearbetning. Matchande rutter får inte lokalprefix, omdirigeringar eller översättningsladdning. Interna Nuxt-sökvägar (`/__nuxt_error` med flera) exkluderas alltid automatiskt. |
| `routeLocales` | `Record<string, string[]>` | — | Per-rutt-lokalbegränsningar, extraherade från `defineI18nRoute()`-anrop. Mappar en ruttsökväg (till exempel `'/about'`) till en array av tillåtna lokalkoder. Rutter som inte listas har inga begränsningar (alla lokaler tillåts). |

## Översättningar

Var översättningsfiler ligger och hur nycklar resolvas.

| Alternativ | Typ | Standard | Beskrivning |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Sökväg till katalogen som innehåller JSON-översättningsfiler, relativt projektroten. |
| `disableWatcher` | `boolean` | `false` | Inaktivera filbevakaren som automatiskt skapar saknade översättningsfiler i utvecklingsläge. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Mappa ruttnamn till andra ruttnamn för att dela samma översättningsfiler. Till exempel betyder `\{ 'about-us': 'about' \}` att sidan `about-us` använder översättningar från sidan `about` i stället för sina egna. |
| `plural` | `PluralFunc` | `built-in pluralization (form index by count)` | Anpassad pluraliseringsfunktion. Tar emot `(key, count, params, locale, getter)` och ska returnera den valda pluralformen som en sträng, eller `null`/`undefined` för att falla tillbaka på den inbyggda `defaultPlural`-logiken (så att du kan åsidosätta endast vissa lokaler). För Nuxt-modulen serialiseras funktionen med `.toString()` in i `.nuxt/i18n.plural.mjs`. Den måste vara självständig (inga importer eller yttre scope). En filsökväg som sträng stöds **inte**. |
| `disablePageLocales` | `boolean` | `false` | Inaktivera sidspecifika översättningsfiler. När `true` laddas endast globala översättningar (`\{locale\}.json`); sidspecifika filer (`pages/\{page\}/\{locale\}.json`) genereras eller laddas inte. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Global fallback-lokalkod. När en översättningsnyckel saknas i den aktiva lokalen letar modulen upp den i denna lokal innan själva nyckeln returneras. |

## Payloads och caching

Hur översättningar når webbläsaren. [Prestanda](/guides/performance) förklarar vad dessa ändrar vid runtime.

| Alternativ | Typ | Standard | Beskrivning |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Förladda översättningar för indexsidan i global Nitro-middleware (endast server, privat konfig). |
| `apiBaseUrl` | `string` | `'_locales'` | Bas-URL-segment för översättnings-API-rutten (används i SSR/SSG-datahämtning). Kan även sättas via miljövariabeln `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Åsidosätter värden som används för hämtningsförfrågningar av översättningar på klientsidan. Användbart när klienten når servern via ett annat värdnamn än det Nuxt ser. Kan även sättas via miljövariabeln `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Åsidosätter värden som används för serverbaserade översättningshämtningsförfrågningar. Användbart i container/microservice-uppsättningar där servern når sig själv via ett internt värdnamn. Kan även sättas via miljövariabeln `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Styr hur översättnings-payloads emitteras (Node: `public/<apiBaseUrl>`; Edge: Nitro `serverAssets`). - **Node**: `serverAssets` betyder lokal SSR via `readFile` under `public/` (ingen Rollup `raw:`). - **Edge**: `serverAssets` registrerar Nitro `serverAssets` (`assets:i18n`); det tvingar inte en publik kopia. Behåll standardvärdena för den vanliga allt-i-ett-uppsättningen. För stora Edge-kataloger, föredra `mode: 'source'`. För CDN-baserade distributioner, inaktivera lokala utdata och sätt `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Strategi för översättnings-payload. - `premerged`: `\{page\}/\{locale\}/data.json`-matris vid byggtid (standard) - `source`: kompakta källfiler som slås samman vid runtime (föredra på Edge / stora kataloger) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Lokala SSR-payloads: Node läser `public/<apiBaseUrl>` (tvingar publik kopia); Edge bäddar in via Nitro `serverAssets`. - **Node**: ingen Nitro `serverAssets` (undviker Rollup `raw:`). SSR läser   `public/<apiBaseUrl\|publicDir>` som `\{page\}/\{locale\}/data.json`; när detta är `true`,   tvingas en publik kopia även om `publicAssets` är false. - **Edge** (`nitro.node === false`): Nitro `serverAssets` (`assets:i18n`) med samma   layout som `mode`. Tvingar **inte** en publik kopia — sätt `publicAssets: true` för CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Registrera den inbyggda serverrutten på `/\{apiBaseUrl\}/:page/:locale/data.json`. Inaktivera detta när översättnings-payloads levereras från en extern värd/CDN. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Kopiera payloads till Nitros publika utdata. Premerged → `\{page\}/\{locale\}/data.json` under `apiBaseUrl`; source → kompakt träd. På Node är detta träd också SSR-källan när `serverAssets` tvingar en publik kopia. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Välj in Nitro-prerender för `/\{apiBaseUrl\}/.../data.json`. Vanligtvis överflödigt när premerged `publicAssets` redan skrivit dessa filer. |
| `translationPayloads.publicDir` | `string` | — | Publik utdatamapp relativ till Nitros publika rot. Standardvärdet är `apiBaseUrl` (`_locales`). Så statiska filer matchar klientens hämtnings-URL:er (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Varna vid byggning när antalet genererade payload-filer överskrider detta tröskelvärde. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Varna vid byggning när den totala storleken på genererade payloads överskrider detta tröskelvärde i byte. |

## SEO

Metataggar som genereras för varje lokaliserad sida.

| Alternativ | Typ | Standard | Beskrivning |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Generera SEO-metataggar (`hreflang`, `canonical`, `og:url`, `og:locale`) automatiskt. |
| `metaBaseUrl` | `string` | `undefined` | Bas-URL för SEO-metataggar (canonical, og:url, hreflang). - En konkret URL-sträng (till exempel `'https://example.com'`) — används som den är (högsta prioritet). - `undefined` — faller tillbaka på `site.url` från `nuxt-site-config` när den modulen är   närvarande, annars den aktuella begärans origin   (`useRequestURL().origin` på server, `window.location.origin` på klient). |
| `metaTrustForwardedHost` | `boolean` | `true` | Lita på headern `X-Forwarded-Host` när bas-URL för metataggar resolvas. Aktivera när appen körs bakom en omvänd proxy (nginx, Cloudflare, AWS ALB och andra) som sätter denna header till det verkliga klientvända värdnamnet. |
| `metaTrustForwardedProto` | `boolean` | `true` | Lita på headern `X-Forwarded-Proto` när protokollet för metataggar resolvas. Aktivera när appen körs bakom en TLS-terminerande proxy så att kanoniska URL:er använder `https://` även om själva appen lyssnar på HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Lista över query-parameternamn som bevaras i canonical- och `og:url`-metataggar. Parametrar som inte finns i denna lista tas bort från canonical-URL:en. |

## Detektering och omdirigeringar

Att välja en lokal för en besökare som inte har valt en.

| Alternativ | Typ | Standard | Beskrivning |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Aktivera automatiska lokalbaserade omdirigeringar. När `true` omdirigeras besökare till sin föredragna lokal (upptäckt från cookie, `Accept-Language`-header eller standarden) vid första besöket. |
| `autoDetectLanguage` | `boolean` | `true` | Upptäck automatiskt användarens föredragna språk från HTTP-headern `Accept-Language`. Används tillsammans med `autoDetectPath` för att avgöra när detektering sker. |
| `autoDetectPath` | `string` | `'/'` | Var cookie/Accept-Language-preferensomdirigeringar kan köras (när `redirects` är aktiverat). - `'/'` — endast `/` (djuplänkar i standardlokalen förblir nåbara; standard) - `'no_prefix'` — endast sökvägar utan lokalprefix - `'*'` — varje sökväg, inklusive omskrivning av ett explicit lokalprefix   (till exempel `/fr/about` → `/de/about` när cookien föredrar `de`) - vilken annan sträng som helst — exakt sökvägsmatch (till exempel `'/welcome'`) Rensning av prefixerad strategi (till exempel `/en` → `/` under `prefix_except_default`) är inte spärrad. |

## Registrering

Delar av modulen som du kan stänga av.

| Alternativ | Typ | Standard | Beskrivning |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Registrera makro-pluginen för `defineI18nRoute()`, vilket möjliggör per-sida-anrop till `defineI18nRoute()`. |
| `plugin` | `boolean` | `true` | Registrera i18n-kärnpluginen som tillhandahåller `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` och andra runtime-hjälpare. |
| `hooks` | `boolean` | `true` | Registrera i18n-hooks-pluginen som tillhandahåller `i18n:register` samt `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch` på appnivå. |
| `components` | `boolean` | `true` | Registrera inbyggda i18n-komponenter (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Sätt till `false` för att inaktivera automatisk komponentregistrering (till exempel om du inte använder dem och vill minska modulens fotavtryck). |
| `types` | `boolean` | `true` | Generera TypeScript-typdeklarationer för `useI18n`, `$t` och relaterade hjälpare baserat på översättningsnycklarna i dina standardlokalfiler. |
| `debug` | `boolean` | `false` | Aktivera utförlig felsökningslogg för lokaldetektering, ruttgenerering och översättningsladdning. |

## Övrigt

| Alternativ | Typ | Standard | Beskrivning |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | Emittera även en `hreflang` med enbart språk härledd från varje lokals `iso` (till exempel `es-ES` → även `es`). Den första regionala lokalen i `locales` gör anspråk på den nakna taggen för det språket. Routing-`code` används aldrig — endast `iso \|\| code`. |
| `vueDevtools` | `boolean` | `true` | Registrera Vue DevTools-inspektor och tidslinje i utveckling (webbläsartillägg). Separat från den anpassade Nuxt DevTools-fliken. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Prefix som läggs till före lokaliserade ruttnamn (till exempel `'localized-index'`). Används internt för att skilja ursprungliga rutter från genererade lokalvarianter. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Per-rutt-inaktivering av metataggar, extraherad från `defineI18nRoute()`-anrop. Mappar en ruttsökväg till `true` (inaktivera all meta) eller en array av lokalkoder för vilka meta ska inaktiveras. |
| `missingWarn` | `boolean` | `true` | Visa konsollvarningar när en översättningsnyckel saknas. |
| `hmr` | `boolean` | `true` | Aktivera Hot Module Replacement för översättningsfiler i utveckling. När `true` triggar ändringar i JSON-översättningsfiler en automatisk omladdning utan full sidomladdning. |
| `cacheMaxSize` | `number` | `0` | Maximalt antal poster i den in-memory-baserade översättningscachen. `0` betyder ingen gräns. |
| `cacheTtl` | `number` | `0` | Time-to-live (i sekunder) för cachade översättningsposter. `0` betyder att poster aldrig går ut. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Namngivna nummerformat per lokal (Vue I18n-kompatibla). Möjliggör anrop i stil med `$tn(1000, 'currency')`. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Namngivna datetime-format per lokal (Vue I18n-kompatibla `datetimeFormats`). Möjliggör anrop i stil med `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | HTTP `Cache-Control` max-age (sekunder) för `/\{apiBaseUrl\}/:page/:locale/data.json`. Gäller fullt ut endast medan `dateBuild` bustar URL:en (`?v=...`), vilket är standard: svaret är då `public, max-age=…, immutable` och säkert för webbläsare och CDN:er. - `dateBuild: 0`/`''` — URL:en är stabil, så denna varaktighet respekteras *inte*; svaret blir i stället `public, max-age=0, must-revalidate`. En lång `max-age` på en oföränderlig URL låser fast den första payload som en webbläsare någonsin såg. - `0` — sätt inte `Cache-Control` alls (användbart vid lokal felsökning) - Tillämpas inte i utveckling (`import.meta.dev`) så HMR inte motarbetas av webbläsarcachen - Når endast svar som levereras via Nitro. Payloads som kopieras till `public/` och levereras   av hostingplattformen får den plattformens headers — se prestandaguiden. Analog med `@nuxtjs/i18n` experimentella `httpCacheDuration` (v10.2.0), men som en explicit svarshead snarare än Nitro `defineCachedEventHandler` maxAge. |
| `dateBuild` | `string \| number` | — | Värde som används för cache-busting av översättningsförfrågningar (`?v=...`). När inget anges faller modulen tillbaka till `Date.now()` (icke-deterministisk). För reproducerbara/rullande distributioner, sätt detta till ett stabilt värde (till exempel en git-SHA eller byggnummer). |
| `experimental` | `Record<string, unknown>` | — | Hink för experimentella/instabila alternativ. Innehållet kan ändras eller tas bort utan förvarning mellan mindre versioner. |
