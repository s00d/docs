**日期**：2026-11-03

**版本**：`v4.0.0`

![v4.0.0 版本](/images/4.0.0.png)

**v4.0.0** 正式發佈。路由、翻譯核心、字典檔案、locale 偵測以及每個框架套件都已重寫。選項、`$t`、`$localePath`、`$switchLocale`、元件與 composables 都保留原本的名稱。改變的是行為，而其中大多數變更是修正了既有的錯誤。大多數 app 只需要少量程式碼變更，但升級前請先閱讀[破壞性變更](#breaking-changes)：URL、SEO 標籤與框架套件 API 有部分變動。[升級](/zh-TW/guide/upgrade)列出了所有細節。

## 有哪些新功能？ {#what’s-new}

### 一次建置支援所有網域 {#one-build-for-every-domain}

`locales[].baseUrl` 與 `baseDefault` 以前只會影響連結。現在它們也會路由請求，適用於全部四種策略以及 `nuxt generate`：

```ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'fr', baseUrl: 'https://example.com' },
      { code: 'de', baseUrl: 'https://example.de', baseDefault: true },
    ],
  },
})
```

- 每個主機提供它自己的 locale。連到其他網域 locale 的連結會變成該網域上的絕對 URL，切換到該 locale 時會導覽到那裡。
- 在會覆寫 `X-Forwarded-Host` 的 proxy 後方，`trustForwardedHost` 會從該標頭取得網域。預設關閉。
- `NUXT_I18N_DOMAIN` 會提供 `nuxt generate` 所用的主機：請為每個網域各執行一次，每份輸出只會包含該網域的頁面與字典。
- 沒有 `baseUrl` 的 app 不會包含任何這部分的程式碼。

請參閱 [Layers 與網域](/zh-TW/guide/layers#multiple-domains)與[部署](/zh-TW/guide/deployment)。

### 與路由器一致的路由 {#routing-that-agrees-with-the-router}

建置與執行階段不再各自計算在地化 URL。所有結果都來自建置時產生的路由，因此連結、切換器、`hreflang` 與重新導向都不會指向不存在的頁面。

- 不提供某個頁面的 locale 會連結到它的首頁，永遠不會連到其他 locale 的頁面。
- `hreflang` 只會列出提供該頁面的 locale。
- `$switchLocale` 會解析為 `true` 或 `false`，讓你知道字典何時載入失敗。重複呼叫會重試。
- 在 SSR 期間設定的 `$setI18nRouteParams` 與 `useI18nHead` 在 hydration 後仍會保留。切換器會連結到翻譯後的 slug，伺服器 HTML 中也是如此。
- 導覽會在 commit 時生效：被取消或被阻擋的導覽不會改變任何東西。
- Hash 模式可在 `prefix` 下運作。
- 在伺服器元件上使用 `<Greeting :locale="$getLocale()" />` 會設定其渲染 locale。

### 統一的 Locale 偵測 {#one-locale-detection}

在伺服器、瀏覽器、伺服器 API 輔助函式以及 Astro 中，都使用同一個順序。`Accept-Language` 會遵循 `q` 值，地區比對不再取決於 `locales` 的順序，也永遠不會跨越不同的中文書寫系統。執行階段覆寫現在也會影響路由：`NUXT_I18N_DEFAULT_LOCALE` 與執行階段的 `disabledLocales` 會改變實際提供的內容。請參閱 [Locale 偵測](/zh-TW/guide/locale-detection)。

### 所有模式使用同一份字典 {#one-dictionary-in-every-mode}

預先合併的建置、`mode: 'source'` 與開發模式以前在許多頁面上結果不一致。現在它們會產生相同的字典。

- 每一層都會進行深度合併，備援鏈（`fr` → `de` → `en`）會一路追蹤到底。
- 開發模式中的翻譯編輯會就地套用，不需要重新載入頁面。被移除的鍵會消失，根檔案的編輯會影響每個頁面。
- `$clearCache()` 會重新載入目前頁面，並在新文字到達前保留畫面上的舊文字。
- chunk 載入失敗時會保留目前的字典，而不是顯示原始的鍵。

### 更小的字典檔案 {#smaller-dictionary-files}

- 頁面檔案現在只包含與該 locale 根字典（位於 `__root/<locale>/data.json`）不同的內容。瀏覽器只會載入一次根字典，再將每個頁面合併上去，因此磁碟用量下降，下一個頁面的成本只是第一個頁面的一小部分。
- 字典 URL 帶有版本。帶有目前 `?v=` 的 URL 在 Node 伺服器上會被快取一年，而主機的靜態副本會回應 `max-age=60`。請參閱[快取標頭](/zh-TW/guide/deployment#cache-headers-and-datebuild)。
- 每個 SSR 頁面都會預先載入其字典檔案，讓它們與 HTML 一起開始下載。
- 讀取失敗不再被記住：下一個請求會重新讀取。請參閱[無法讀取字典時](/zh-TW/guide/deployment#when-a-dictionary-cannot-be-read)。

### 更好的 `<i18n-t>`、複數與格式 {#better-&lt;i18n-t&gt;-plurals-and-formats}

- Slot 可搭配 `plural`、`number`、`date` 與 `relativeDate` 使用，且每個 `{name}` 都會被填入，而不只是第一個。
- `<i18n-t>` 在 Nuxt、Vue、React、Preact、Solid 與 Astro 中使用同一個渲染器。
- 以 `=0 ` 開頭的第一個形式是明確的零形式，其餘則依 `Intl.PluralRules` 決定：`=0 no apples | one apple | {count} apples`。請參閱 [`$tc`](/zh-TW/api/methods#$tc)。
- 新的 `timeZone` 選項：在伺服器與所有瀏覽器上顯示相同的日曆日期。
- `{firstName}`、`{first-name}` 與 `{user.name}` 都是有效的佔位符。
- `$tn`、`$td` 與 `$tdr` 會像複數一樣遵循 `iso`。
- `$tdr` 會產生真正的未來日期：`in 3 days`，或在 `numeric: 'auto'` 時為 `tomorrow`。

### 預設更安全 {#safer-by-default}

- `<i18n-t html>` 會跳脫 `params`。只有翻譯本身被視為可信任的標記。
- 不會有連結意外離開 origin：`//host`、`/\host` 與空白值都會留在本站。
- 伺服器翻譯快取有大小上限，因此帶有虛構頁面名稱的 URL 無法讓記憶體無限成長。
- DevTools 的儲存端點只接受翻譯目錄中既有的 `.json` 檔案，並會拒絕跨站請求。

### 框架套件升級至 2.0 {#framework-packages-at-2-0}

- **React、Preact、Solid：** `I18nT` 接受 `components` prop 以支援富文本。新增 `useT` 與 `useLocaleSwitch`，並透過 `@i18n-micro/react/server` 與 `/client` 支援 React Server Components。Preact 不再需要 `preact/compat`。
- **Vue 與 VitePress：** `I18nLink` 會保留 `name`、`query` 與 `hash`，VitePress 會遵循 `base`。
- **Astro：** `i18nIntegration` 會打包你的字典並安裝 middleware。主要入口沒有任何 `node:*` import，因此可在 edge 上執行。`base` 可正常運作。
- **Node 與 runtime：** `fork(locale)` 提供低成本的每請求實例，而 `@i18n-micro/node` 上的 `run(locale, fn)` 會將實例限定於單一請求。
- **`@i18n-micro/types-generator`：** 沒有第三方相依套件，並提供單純的 Vite 與 Rollup 外掛。
- **`@i18n-micro/devtools-ui`：** 透過 Vite 的 socket 即時更新，並提供 Astro 工具列 app。

### `@i18n-micro/cli` {#@i18n-micro/cli}

CLI 現在以 `@i18n-micro/cli` 的形式位於 monorepo 中，已重寫為 16 個指令（原為 28 個），相依套件也大幅減少。`check` 取代了 `validate`、`diff` 與 `check-duplicates`，並提供 `--json` 與適用於 CI 的結束代碼。當無法證明某個鍵未被使用時，`clean` 不會寫入任何內容。請參閱 [CLI](/zh-TW/guide/cli)。

### 文件 {#documentation}

文件已依據程式碼重寫，並圍繞單一閱讀路徑：安裝、第一個翻譯頁面、翻譯檔案、路由、偵測，然後是各項任務指南。舊的 URL 會重新導向。[升級](/zh-TW/guide/upgrade)詳細列出了所有變更。

## 速度與大小 {#speed-and-size}

- 伺服器渲染會直接讀取字典，不需要本機 HTTP 請求，也不需要重新解析。
- `dir="auto"` 不再是預設值。在大型頁面上瀏覽器會為此花費大量時間：在有 20,000 個 `$t` 元素的情況下，Chromium 的 DOMContentLoaded 從約 980 ms 降到約 115 ms。
- `serverTranslationPreload` 與 `i18n:register` 不再拖慢每個請求。
- 未設定 cookie 時，客戶端 bundle 會移除 `useCookie`，而 `@i18n-micro/path-strategy` 只剩原本大小的一小部分。

**與 v3.30.3 比較的測試 app。** 一個產生的 Nuxt app，在一台 Node 伺服器、一台 Mac 上，以 `wrk` 使用 24 個連線執行 20 秒，輪替三輪，使用預發佈版本建置。各列來自不同的執行，因此請在同一列內比較。Hydration 兩邊都使用 `dir: 'ltr'`。

| 指標 | v3.30.3 | v4.0.0 |
| --- | ---: | ---: |
| 4 個 locale、10k 目錄：每秒請求數 | 384-395 | 585-591 |
| 4 個 locale、10k 目錄：p95 延遲 | 106-110 ms | 70-72 ms |
| 4 個 locale、10k 目錄：每請求伺服器 CPU | 2.92-3.00 ms | 2.01-2.02 ms |
| 12 個 locale、100k 目錄：每秒請求數 | 362-370 | 578-580 |
| 12 個 locale、100k 目錄：p95 延遲 | 115-117 ms | 72-73 ms |
| 12 個 locale、100k 目錄：每請求伺服器 CPU | 3.11-3.17 ms | 2.02-2.03 ms |
| Hydration，100k 頁面 | 86-92 ms | 77-81 ms |
| 此 app 的客戶端 JS，gzip | 105.1 KB | 93.9 KB |
| 有 `i18n:register` 訂閱者時的請求時間，100k chunk | 96-108 ms | 1.7 ms |

在較早的預發佈版本上，對 100k 目錄進行 30 分鐘的測試，共處理 113 萬個請求，沒有任何錯誤，且即時 heap 維持平穩。

**與 v3.29.5（它們原本執行的版本）比較的三個正式環境 app，** 使用預發佈版本建置。其中兩個是 SSR 網站，一個是 SPA。每個都在一台 Node 伺服器上執行 60 秒、8 個連線、僅 GET、兩輪。建置時間各執行一次。

| 指標 | SSR app 1 | SSR app 2 | SPA app |
| --- | ---: | ---: | ---: |
| 磁碟上的字典位元組 | 6.37 MB 降至 1.52 MB（-76%） | 4.43 MB 降至 1.52 MB（-66%） | 15.40 MB 降至 1.69 MB（-89%） |
| `.output` 大小 | -22% | -14% | -29% |
| 建置時間 | 27 秒降至 22 秒 | 23 秒降至 19 秒 | 41 秒降至 28 秒 |
| 客戶端 JS，gzip | +1.7% | +0.9% | +0.5% |
| 每秒請求數 | 82 增至 88 | 237 增至 240，在誤差範圍內 | 233 增至 404，僅 SPA shell |

**客戶端 JS。** 如上所示，帶有自身程式碼的實際 app 會略為增加。共用的修正也讓框架套件變大，在另一個預發佈版本上以最小規模的 Vue、React、Preact 與 Solid app 測量：gzip 後約增加 1.4 KB 至 2.5 KB。React、Preact 與 Solid 也包含共用的富文本渲染器。

**字典請求。** 首次載入現在需要兩個檔案：根檔案與頁面檔案。其位元組數維持不變（在兩個 SSR app 上分別針對 103 次與 89 次首次載入測得 +0.3%）。同一文件中的下一個頁面只需要一個小檔案：在測量的兩個頁面上，分別從 gzip 4.7 KB 降至 1.5 KB，以及從 gzip 5.9 KB 降至 0.5 KB。在已登入狀態下瀏覽 SPA 的過程中，字典位元組減少了 21%。

**Edge。** 在一個小型示範 app 上，使用預發佈版本時，Cloudflare Worker 的上傳大小從 gzip 241.5 KiB 增加到 250.3 KiB。嵌入 Edge bundle 中的字典使用相同的根檔案與頁面檔案，但我們尚未在大型目錄上測量這種嵌入方式。

## 破壞性變更 {#breaking-changes}

### 需求 {#requirements}

- **Nuxt 3.18 或更新版本**，以及 **Node 20 或更新版本**。
- **`@i18n-micro/test-utils`** 不再隨模組一起安裝。如果你的測試會匯入它，請自行加入。
- **`@i18n-micro/hmr`** 已移除：翻譯 HMR 已內建。如果你有安裝此套件，請將它移除。
- **`@i18n-micro/react`** 需要 React 18 或更新版本。
- **`nuxt-i18n-micro-cli`** 已由 `@i18n-micro/cli` 取代。

### 選項與設定 {#options-and-config}

- `dependsOn` 中的 `i18n-plugin-hooks` 與 `i18n-plugin-define` 不再等待任何東西，且不會報錯。請使用 `i18n-plugin-loader`。
- 伺服器自動匯入的項目為 `useLocaleServerMiddleware`、`useTranslationServerMiddleware`、`loadTranslationsFromServer` 與 `detectCurrentLocale`。其他項目不再自動匯入。
- `resolveTranslationPayloadMode` 與其他 `resolveTranslationPayload*` 輔助函式已從 `nuxt-i18n-micro` 移除，`shouldCopyTranslationPayloadsToPublic` 與 `shouldRegisterNitroServerAssets` 也一併移除。`TranslationPayloadMode` 型別保留。
- `$getI18nConfig()` 不再包含 `isSSG`、`hmr`、`hooks`、`noPrefixRedirect`、`routeLocales`、`routeDisableMeta` 或 `globalLocaleRoutes`。選項本身沒有變更。
- `locales[].baseUrl` 現在會路由請求：其他網域的 locale 在此主機上會回傳 404，而同一主機上的連結為相對路徑。在這種建置中，`$getI18nConfig().locales` 包含該主機提供的 locale，而 `linkLocales` 包含全部 locale。
- `baseUrl` 也會設定其他任何主機上的 origin：canonical 與 `hreflang` 會在有設定時使用 `metaBaseUrl`，否則使用預設 locale 的 `baseUrl`，而不是請求的 origin。
- `excludePatterns` 會比對完整區段（`'/admin'` 不再比對到 `/administrator`），glob 會被錨定，而 `RegExp` 模式現在也會傳到執行階段。
- 未設定 `cacheMaxSize` 時，伺服器上最多 1000 個項目。`cacheTtl` 從項目儲存時開始計算，讀取不再延長它。
- 在 `no_prefix` 下，`i18n` 設定中明確的 `localeCookie: null` 會保持關閉。
- 在 `prefix_except_default` 與 `prefix_and_default` 下，執行階段的 `defaultLocale` 會被忽略並發出警告。執行階段的 `fallbackLocale` 必須是已啟用的 locale。
- 會遵循 `nuxt.config` 中的 `routeDisableMeta`，且無論鍵的形式為何，`nuxt.config` 中的項目都優先於 `$defineI18nRoute`。
- 在開發環境的伺服器上，解析後的設定會被凍結：寫入時會拋出錯誤。
- 對於相同的 `code`，專案的 `locales` 項目優先於 layer 的項目。

### Composables 與 `$` 方法 {#composables-and-$-methods}

- `$switchLocale` 會解析為 `true` 或 `false`，以前不會解析出任何值。`$switchRoute` 的型別為 `Promise<void>`。
- `$localeRoute`、`$switchLocalePath` 與切換器會將不提供某頁面的 locale 連結到該 locale 的首頁。
- `$localePath` 會原樣回傳帶有 `http(s):`、`mailto:` 或 `tel:` scheme 的字串，而 `$localeRoute` 會將其放在 `path` 與 `fullPath` 中。請勿將未經檢查的值作為連結目標傳給它們。`//host` 與 `x.com` 之類的裸名稱會保持為此 origin 上的路徑。
- 沒有路徑的連結會留在目前頁面：`$localePath('#top')`、`'?p=2'`、`''` 與 `{ query }`。`'#top'` 以前會從網站根目錄解析。單純的 `'about'` 仍然表示 `/about`。
- `$switchRoute` 會留在 app 中。只有 locale 自己的 `baseUrl`、`mailto:` 與 `tel:` 會離開 app。
- 連到帶有 `baseUrl` 之 locale 的連結要透過 `$localePath` 或 `<i18n-link>`。`<NuxtLink :to="$localeRoute(x, 'fr')">` 與 `router.push($localeRoute(x, 'fr'))` 會保持為此 app 的路徑。在程式碼中請使用 `navigateTo($localePath(x, 'fr'), { external: true })`。
- `$switchLocaleRoute` 與重新導向會遵循 `trailingSlash`。
- 在伺服器上設定的 `$setI18nRouteParams` 與 `useI18nHead`，會在導覽改變路徑時被捨棄，包括從 `/news/1` 到 `/news/4`：請在新頁面上重新設定。
- 在 setup 中讀取的 `$setI18nRouteParams` 會綁定於該頁面：從已離開的頁面延遲呼叫不會有任何作用。它沒有 setter，因此在測試中請直接 stub `useI18n` 本身。
- `useI18n()` 每個 app 回傳同一個物件。寫入它會影響每個呼叫者。
- 字典、locale、params 與 head 會在導覽 commit 時變更。`beforeResolve`、`beforeRouteEnter` 或之後的全域守衛會看到舊的值。路由 middleware 不受影響。
- 在 URL 策略下，當 `$switchLocale` 的導覽被取消時，會還原已儲存的 locale。
- `$t` 會對 `defaultValue` 進行插值：`$t('missing', { n: 1 }, 'Got {n}')` 會得到 `Got 1`。`$tc` 也是如此，且翻譯為空時會回傳 `''`。
- `$has(key, route)` 會遵循 route。
- `$clearCache()` 會重新載入目前頁面的字典。
- `{param}` 佔位符只會讀取你傳入的 params：`{constructor}` 會保持原樣。
- `$tc` 搭配負數、小數或極大的數量時，會使用最後一個形式並帶入實際數量。`{ count: null }` 不再拋出錯誤，缺少的複數鍵會交給 missing handler 處理。
- `$tdr` 對無效輸入會回傳 `Invalid Date`。過去不到一秒會顯示 `0 seconds ago`。
- `$tn`、`$td` 與 `$tdr` 會依 `iso` 處理：`{ code: 'en', iso: 'en-GB' }` 會將日期格式化為 `31/10/2026`。`Intl` 不認得的代碼會以 `en` 格式化，複數則依索引規則：請設定 `iso`（`{ code: 'ua', iso: 'uk-UA' }`）。
- `detectCurrentLocale` 已棄用：請使用 `useLocaleServerMiddleware(event).current`。

### 複數 {#plurals}

模板保留原本的意義，只有一個例外。若零形式不含佔位符，接著每個類別各一個形式，且多個數量共用的每個形式中都有 `{count}`，那麼在具有三個以上類別的 locale（`ru`、`uk`、`pl`、`cs`、`ar` 等）中，現在會依類別處理：在 `uk` 中，`none | {count} one | {count} few | {count} many` 會產生 `3 few` 與 `21 one`。若要在其他模板中使用類別，請加上 `=0 ` 標記。自訂的 `plural` 規則會讀取原始值，因此帶標記的模板傳入時 `=0 ` 會保留在原處。請參閱[升級指南中的表格](/zh-TW/guide/upgrade#plurals-and-formatting)。

### 元件 {#components}

**`<i18n-t>`**

- `html` 在所有情況下都會跳脫 `params`，並忽略所有 slot。
- Slot 優先於同名的 param。
- 對於 `plural`、`number`、`date` 與 `relativeDate`，`null` 表示未設定。
- `plural` 會像 `$tc` 一樣以 `Number` 計算：`1.5` 維持 `1.5`，`"2 items"` 為 `NaN`，`""` 為 `0`。
- `number`、`date` 與 `relativeDate` 會保留 `params`。
- `hideIfEmpty` 在每個分支中都會套用，`defaultValue` 在每個分支中都會替代缺少的鍵。
- 在 `html` 下缺少的鍵會成為跳脫後的文字。
- `date` 與 `relativeDate` 的輸出帶有 `data-allow-mismatch="text"`，而在具名 slot 旁邊時，文字會放在自己的 `<span>` 中。
- `.innerHTML` 與 `textContent` 屬性會被捨棄。
- 它是函式元件：在它上面使用 `ref` 不會取得實例。
- `<i18n-t>` 與 `<i18n-group>` 會像 `$t` 一樣讀取作用中的字典。

**`<i18n-switcher>`**

- 連結是呼叫 `$switchLocale` 的一般 `<a>`，因此 `router-link-active` class 已不存在。
- 按鈕為 `type="button"` 並帶有 `aria-expanded`。按下 Escape 或在外部點擊會關閉下拉選單。
- 新增 class `i18n-switcher-wrapper`、`i18n-switcher-dropdown` 與 `i18n-switcher-button`。每個連結都有 `lang`，當 locale 有設定時也會有 `dir`。
- 預設樣式使用邏輯 CSS 屬性，下拉選單有更大的 `z-index`、最小寬度與陰影。
- 在帶有 params 的頁面上，伺服器會在渲染結束時改寫其連結。手動撰寫的 `$switchLocalePath` 連結不會被改寫。

**`<i18n-link>`**

- `https://`、`mailto:` 與 `tel:` 不區分大小寫比對。單純的 `report.pdf` 是路由，而 `example.com` 維持為外部連結。同時也是 TLD 的副檔名（`example.md`）會被視為檔案：請寫上 `https://`。
- `activeStyle` 會忽略結尾斜線、query 與 hash。

### Hooks 與型別 {#hooks-and-types}

- `i18n:register` 是執行階段 hook：請在外掛中使用 `nuxtApp.hook('i18n:register', …)`。
- 匯出的型別 `ModuleHooks` 已重新命名為 `ModuleRuntimeHooks`。
- `i18n:beforeLocaleSwitch` 與 `i18n:afterLocaleSwitch` 從未被觸發過，現已不再列入文件。
- `ModuleOptionsExtend.isSSG` 改為選用並已棄用：沒有任何東西會設定它。

### URL 與重新導向 {#urls-and-redirects}

- 在 `prefix_except_default` 下，若 `en` 為預設，**`/en` 與 `/en/...` 會回傳 404**。
- **大小寫或拼寫不同的 locale 前綴會回傳 404**（`/DE/about`）。在 `[...slug]` 下的 `/DE/x` 以及 `[slug]` 旁的 `/DE` 也是如此，因此與某個 locale 代碼僅大小寫不同的 CMS slug 會失去其頁面。
- 在 `autoDetectPath: '*'` 或 `'no_prefix'` 下，**未知的 URL 仍會回傳 404**。`prefix` 保留重新導向，各處的 `/` 也是如此。
- 在 `prefix_except_default` 下，**其他 locale 的無前綴自訂路徑** 會以 `302` 重新導向至預設 locale 的 URL。在 `prefix` 下，重新導向現在會到達實際存在的頁面。`prefix_and_default` 仍回傳 404。
- **`prefix` 搭配 `redirects: false`** 時，無前綴的 URL 會回傳 404，包括帶有自訂預設路徑之頁面的原始 URL。
- **`autoDetectPath: '*'`** 也會將 cookie 與 `Accept-Language` 套用到無前綴的路徑。
- **在 `prefix` 下**，無論 `autoDetectPath` 如何設定，無前綴的 URL 在每個路徑上都會保留訪客的 locale。
- **在 `prefix_and_default` 下**，無前綴的 URL 即為預設 locale。
- **在 `no_prefix` 下**，自訂路徑會以其自身的 locale 渲染，受限的頁面會以它提供的 locale 渲染，而共用路徑的 locale 會共用同一筆紀錄。
- **沒有頁面的 `routeRules` 重新導向** 不會被在地化：`/de/old` 會回傳 404，以前則是空白的 200。
- **路由規則會套用到自訂路徑**，在 `no_prefix` 下也會被複製。`/de/artikel/news` 等靜態同層路徑會比對到 `/de/artikel/:slug`。
- **帶有 `disabled: true` 的 locale** 會立即在其前綴上回傳 404，連到它的連結會停留在目前頁面。
- **大小寫不同的頁面路徑** 會以 `302` 重新導向至其正確拼寫：`/T/BASIC` 會導向 `/t/basic`。
- 在 `prefix_except_default` 下，**帶有自訂預設路徑之頁面的原始 URL** 會以 `302` 重新導向至該路徑。以前是 404。
- **`noPrefixRedirect`** 會依訪客的 locale 處理：cookie 為 `de` 時，`/about` 會導向 `/ueber-uns`，而不是預設 locale 的路徑。
- 在 `prefix_except_default` 下，**主機自己的前綴** 在其 `baseDefault` 主機上會回傳 404：`de` 主機上的 `/de/x` 以前是 200。
- **`customRegexMatcher`** 不再對第一個區段看似 locale 的真實頁面回傳 404。
- **`nuxi generate`** 會為每個提供該頁面的 locale 預先渲染每個靜態頁面，除非路由規則設定了 `prerender: false`：輸出中會有更多檔案。使用 `baseUrl` 時，請搭配 `NUXT_I18N_DOMAIN` 為每個網域各執行一次。
- **客戶端重新導向會保留其導覽的模式：** 一般的 `<NuxtLink>` 會新增一筆歷史紀錄。
- **在地化路由名稱保持一致。** 只有在 `router.push({ name })` 中寫死 `localized-…` 名稱的程式碼會受影響：請將頁面自己的名稱傳給 `$localeRoute`。
- **來自 `extendPages` 的未命名頁面** 會被在地化並取得名稱。
- **在 `prefix` 下，連到其他網域的連結** 會保留 locale 前綴。
- **網域的首頁** 在各處都不帶結尾斜線。
- **`?locale=`** 只有在 `no_prefix` 下才會在頁面上生效。`/about?locale=de` 不再於 `lang="en"` 下渲染德文。
- 在 `/en/...` 上，**外掛中的 `setLocale('de')`** 不再載入 `de` 字典。

### SEO 與 HTML 輸出 {#seo-and-html-output}

- `dir="auto"` 不再是預設值。已知的 RTL 語言會得到 `dir="rtl"`，其他未設定 `dir` 的 locale 則不會有此屬性。若要保留舊的輸出，請設定 `dir: 'auto'`，但在大型頁面上會有解析成本。請參閱[文字方向](/zh-TW/guide/seo#text-direction)。
- `disableMeta` 現在可以正常運作：頁面不會有 `hreflang`、canonical 或 `og:locale`。`lang` 與 `dir` 會保留。
- `hreflang` 只會列出提供該頁面的 locale。只有當預設 locale 提供該頁面時才會出現 `x-default`。
- 未在地化的頁面不會有 `hreflang` 或 `og:locale:alternate`。
- 404 頁面帶有 URL 所屬 locale 的 `<html lang dir>`，且沒有 canonical 或 `hreflang`。
- Canonical、`og:url` 與 `hreflang` 會保留白名單中的 query（`/about?page=2`），伺服器端也是如此。
- 當 origin 來自請求時，canonical 與 `hreflang` 會包含 `app.baseURL`。
- 每個 SSR 頁面（包括 404 頁面）都會為其字典檔案加上 `<link rel="preload" as="fetch" crossorigin="anonymous">`。在嚴格的 CSP 中請允許它。使用 `apiBaseClientHost` 時，該主機需要 CORS。
- 在 `no_prefix` 下每個頁面都會設定 `Vary`，其他策略則在 locale 重新導向上設定。請檢查你的 CDN 快取鍵。
- Locale cookie 只會由實際提供的頁面寫入。

### 偵測與伺服器 {#detection-and-server}

- `Accept-Language` 會遵循 `q` 值，`q=0` 會排除某個語言。
- `useLocaleServerMiddleware` 與 `useTranslationServerMiddleware` 在每個路由上使用相同的順序（`?locale`、`[locale]` param 或前綴、cookie、標頭、預設值），會遵循 `localeCookie: null` 與 `autoDetectLanguage: false`，並為每個 locale 快取一份字典。
- 格式錯誤的 locale cookie 會被忽略並保持原樣，而不會導致 SSR 失敗。
- Hash 模式只會讀取 `hash-locale` cookie。單獨的 `user-locale=de` 不再有效。
- `NUXT_I18N_DEFAULT_LOCALE` 與執行階段的 `disabledLocales` 會改變路由。
- **`premerged` 輸出已變更。** `/{apiBaseUrl}/<page>/<locale>/data.json` 只包含與 `__root/<locale>/data.json` 不同的內容。任何直接讀取這些檔案的程式都必須合併兩者。完整的字典仍是有效的檔案。
- **字典會遵循 `app.cdnURL`。** 瀏覽器會從 `<cdnURL>/_locales/...` 取得字典，以前則使用 `app.baseURL`。CDN 必須包含 `_locales/` 並允許你網站的 origin。請參閱 [App baseURL 與 payload 主機](/zh-TW/guide/deployment#app-baseurl-and-payload-hosts)。
- `/{apiBaseUrl}/**` 不再使用 Nitro 路由快取，`s-maxage=60, stale-while-revalidate` 標頭也已移除。如果你依賴該快取，請在 payload 路由前方放置 CDN。
- `/{apiBaseUrl}/<page without a folder>/<locale>/data.json` 會回應根字典，以前是 `{}`。主機的 404 現在會以 404 傳遞，以前則回應 `200 {}`。
- 無法載入字典的預先渲染會以 500 失敗並發出警告，在 Nuxt 預設的 `failOnError` 下，建置會以 1 結束。
- 未重新建置而變更的翻譯，只有在 `v` 變動時才會到達瀏覽器：請設定 `NUXT_I18N_DATE_BUILD`。
- 除非設定了 `apiBaseServerHost`，SSR 不再透過 HTTP 請求 `/{apiBaseUrl}`。

### 翻譯 {#translations}

- 每一層都會進行深度合併，備援鏈會一路追蹤到底。
- 合併依 locale 進行：作用中 locale 的根檔案優先於備援 locale 的頁面檔案。
- 沒有自己 `pages/<name>/` 資料夾的頁面在正式環境中會讀取根字典。以前會得到 `{}`。
- `disablePageLocales: true` 只會讀取根檔案。
- 導覽後，離開頁面的鍵會停止解析。如果 layout 使用了只有前一個頁面檔案才有的鍵，請將它們移到根檔案。
- 損壞的 locale 檔案在所有模式中都只會警告一次並附上其路徑。開發模式以前會拋出錯誤。

### `@i18n-micro/*` 套件 {#@i18n-micro/*-packages}

**`@i18n-micro/astro`**

- `i18nIntegration` 會打包 `translationDir` 並安裝 middleware：請刪除只是複製設定的 `src/middleware.ts`，或傳入 `middleware: false`。你自己的 `src/middleware.ts` 請傳入 `base: config.base`。

- `utils`：子路徑 `./route`、`./route-pattern`、`./build`、`./payload-stats` 與 `./payload-config` 已移除，`resolveServerLocale` 與 `resolvePreferredLocale` 也一併移除：請呼叫 `resolveLocale`。`deepMergeTranslations` 與 `mergeRouteTranslationsWithRoot` 已移除：請使用 `deepMergeTranslationsRecursive`。
- `core`：`TranslationHelper` 移除了 `setCache`、`getGeneration` 與 `lookupIn`（請使用 `lookup(chunkKey, key)`）。`BaseI18n` 移除了 `ensurePinnedChunk` 與 `invalidatePin`。`useTranslationHelper(storage)` 已移除：請使用 `new TranslationHelper(storage)`。
- `path-strategy`：**`switchLocaleRoute(fromLocale, toLocale, route, options)` 現在改為 `switchLocaleRoute(toLocale, route, options)`。舊的 JavaScript 呼叫會回傳錯誤的結果，且不會報錯。** Nuxt 的 `$switchLocaleRoute` 不受影響。`/prefix`、`/no-prefix`、`/prefix-except-default` 與 `/prefix-and-default` 入口已移除，`getRedirect` 與 `getCanonicalPath` 也一樣。`RouterAdapter` 需要 `getRoutes`。`createPathStrategy` 不會產生絕對 URL：當 locale 有 `baseUrl` 時，請使用 `new DomainPathStrategy(ctx)`。
- `route-strategy`：只匯出 `RouteGenerator`、`generateRoutes`、`Rules` 與路徑輔助函式。

## 遷移 {#migration}

1. 檢查需求：Nuxt 3.18、Node 20，若使用 `@i18n-micro/react` 則需要 React 18。
2. 同時更新 `nuxt-i18n-micro` 與每個 `@i18n-micro/*` 套件。移除 `@i18n-micro/hmr`。若你的測試會匯入 `@i18n-micro/test-utils`，請將它加入為開發相依套件。將 `nuxt-i18n-micro-cli` 替換為 `@i18n-micro/cli`，並依照[其指令對照表](/zh-TW/guide/cli#moving-from-nuxt-i18n-micro-cli)操作。
3. 在程式碼中搜尋來自 `@i18n-micro/path-strategy` 的 `switchLocaleRoute(`、`i18n-plugin-hooks`、`i18n-plugin-define`、`localized-` 路由名稱、`$getI18nConfig().globalLocaleRoutes` 與其他已移除的設定鍵、`ModuleHooks`，以及 `i18n:register` 上的 `@ts-expect-error`。
4. 將 `<i18n-t html>` params 中的標記移到翻譯中，並以 params 傳遞資料。
5. 若你有設定 `baseUrl`：請檢查以 `$localeRoute` 建立的連結，在 proxy 後方設定 `trustForwardedHost`，並搭配 `NUXT_I18N_DOMAIN` 為每個網域各執行一次 `nuxi generate`。
6. 依你的策略檢查 URL：`prefix_except_default` 下的 `/en`、類似 locale 的 CMS slug、`routeRules` 重新導向，以及 `excludePatterns`。
7. 檢查 CDN 快取鍵是否處理 `Vary`，並在嚴格的 CSP 中允許 preload 連結。使用 `app.cdnURL` 時，請將 `_locales/` 放到 CDN 上並允許 CORS。
8. 若有工具直接讀取 `/_locales/...` 檔案，請將頁面檔案合併到 `__root/<locale>/data.json` 之上。
9. 若有全域守衛讀取 locale 或字典，請確認它能在導覽 commit 之前執行。將 layout 從前一個頁面檔案取用的鍵移到根檔案。
10. 比較變更前後的 `nuxi generate` 輸出或 sitemap 爬取結果：`hreflang`、`x-default`、canonical 與頁面清單的變化是刻意設計的。
11. 更新框架套件的 import：React、Solid 與 Preact adapter 使用 `/router`，Astro 的載入器使用 `/node`，型別外掛使用 `I18nTypesPlugin(o)`。
12. 若使用 Astro，請刪除只是複製設定的 `src/middleware.ts`，並將 `pages/blog-hello/` 這類字典重新命名為其模式名稱。
13. 更新依賴 `router-link-active`、`li button`、`▼` 或舊 mock 行為的測試。

詳細內容與所有邊界情況：[升級](/zh-TW/guide/upgrade)。

## 為什麼這很重要 {#why-it-matters}

- **設計上即正確：** 連結、重新導向與 SEO 標籤都來自 app 實際擁有的路由。
- **到處都是同一個答案：** 建置、source 模式與開發模式會產生相同的字典，且每個呼叫者都使用同一個偵測順序。
- **網域：** 一次部署即可支援所有 locale 網域，不需要第二次建置。
- **更安全的預設值：** 跳脫的 params、有上限的快取，以及停留在你 origin 上的連結。
- **更少需要發佈的內容：** 更小的字典檔案、更小的路由套件，以及集中在一處的共用邏輯。

完整的變更清單請參閱[升級](/zh-TW/guide/upgrade)與 [changelog](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md)。
