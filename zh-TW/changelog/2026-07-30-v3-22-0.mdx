## Nuxt I18n Micro v3.22.0 — 格式、快取與翻譯記憶 {#nuxt-i18n-micro-v3-22-0-—-formats-cache-&-translation-memory}

**日期**：2026-07-30

**版本**：`v3.22.0`

![v3.22.0 版本](/images/3.22.0.png)

我們宣布推出 **v3.22.0**：Vue I18n 風格的具名數字／日期格式並搭配格式化器快取、對 CDN 友善的翻譯 payload 快取（內容指紋 + `httpCacheDuration`），以及可在執行階段讀取與取代目前字典的翻譯記憶 API。

## 有什麼新功能？ {#what’s-new}

### 具名 `numberFormats` / `datetimeFormats` + 格式化器快取 {#named-numberformats-/-datetimeformats-+-formatter-cache}

與 Vue I18n 相容的具名格式，以及更快速的 Intl 格式化：

- 設定：每個 locale 的 `numberFormats` / `datetimeFormats`
- API：`$tn(1000, 'currency')`、`$td(date, 'short')`（+ locale 覆寫與選項合併）
- `FormatService` 依 locale + 選項快取 `Intl.NumberFormat` / `DateTimeFormat` / `RelativeTimeFormat`

請參閱[方法 — `$tn` / `$td`](/zh-TW/api/methods#$tn) 與[模組選項](/zh-TW/api/module-options#numberformats)。

### `dateBuild` 預設為內容指紋 {#datebuild-defaults-to-a-content-fingerprint}

過去 `/_locales` 請求上的 `?v=` 預設為 `Date.now()`，而回應卻以 `immutable` 提供長達一年。因此每次重新建置都會使所有用戶端的字典失效，即使沒有任何翻譯變更。

現在的預設值是翻譯來源（依 layer 順序）的 SHA-256 指紋。翻譯未變更的重新建置會保留相同的 URL。明確設定 `dateBuild` 仍會優先採用。請參閱[模組選項 — `dateBuild`](/zh-TW/api/module-options#datebuild)。

### 適用於 `/_locales` payload 的 `httpCacheDuration` {#httpcacheduration-for-/_locales-payloads}

內建的 `/{apiBaseUrl}/:page/:locale/data.json` 路由現在會為瀏覽器與 CDN 傳送 HTTP `Cache-Control`：

- 選項：`httpCacheDuration`（秒，預設 `31536000` / 1 年）
- 標頭：`Cache-Control: public, max-age=…, immutable`
- 可與既有的 `dateBuild` 快取破壞機制（`?v=...`）安全搭配；`0` 會停用此標頭；開發模式下不套用

相當於 `@nuxtjs/i18n` v10.2.0 的 `experimental.httpCacheDuration`，但以明確的回應標頭實作。

### 壓縮的公開 payload {#compressed-public-payloads}

`nitro.compressPublicAssets` 現在也會作用於複製到公開目錄的翻譯 payload（`.gz` + `.br`）。Nitro 會在複製發生之前壓縮公開資源，因此過去這些 payload 是靜態建置中唯一未壓縮的部分——在 playground 首頁上，原始大小 6.65 MB，gzip 後為 1.01 MB。本模組仍然不會自行啟用壓縮。請參閱[效能](/zh-TW/guide/performance#payload-size)。

### `resolveTranslations()` 與 `setTranslation(key, value)` {#resolvetranslations-and-settranslationkey-value}

用於在記憶體中讀取與取代目前翻譯字典的執行階段輔助函式：

- **`resolveTranslations()`** 會回傳 `$t()` 針對目前 locale 與路由所讀取的完整樹狀結構——適用於 DevTools、測試與執行階段編輯器。當第二個 layer 處於作用中（fallback locale 或 Nuxt 頁面轉場熱重載）時，輸出會透過 `mergeTranslationLayers` 保留巢狀結構，只有在單一樹狀結構無法表達的純量與物件衝突時，才會使用扁平的點分隔鍵。
- **`setTranslation(key, value)`** 會取代某個鍵的值（頂層、點分隔路徑、物件、字串或純量）。這是**取代**而非合併；若要保留同層的其他值，請使用 `$mergeTranslations`。
- 可在 `useI18n()`、`useNuxtApp()` 以及繼承自 `@i18n-micro/core` 的框架 i18n 實例上使用。
- `@i18n-micro/test-utils` 新增了對應的 `resolveTranslations` / `setTranslation` 輔助函式，供單元測試使用。

### 從 Vue 套件移除 `getAllTranslations()` {#getalltranslations-removed-from-vue-package}

請使用 `resolveTranslations()` 取得目前的查找樹。若要在 Vue 中完整傾印儲存內容，請使用 `getStorage()` 或 `getRouteCache()`。

## 破壞性變更 {#breaking-changes}

在一般用法下，公開設定介面中沒有任何變更需要修改應用程式程式碼。以下內容僅在你直接存取執行階段內部時才有影響：

- **SSR payload 已從 `useState('i18n-ssr-chunks')` 移至 `nuxtApp.payload.data['i18n-ssr-chunks']`。** 它仍然包含 SSR 期間載入之每個 `(locale, route)` 的**完整翻譯區塊**——與之前相同的字典，只是放在 Nuxt 可於預先渲染時外部化至 `_payload.json` 的位置。`useState('i18n-ssr-chunks')` 現在不會回傳任何內容。以這種方式讀取翻譯從未受到支援，但快取 API 文件中曾經描述過，因此在此特別說明。
- **`NuxtTranslationLoaderOptions` 公開了 `setSsrChunk`。** 載入器在伺服器端載入時，會將每個合併後的區塊寫入 `payload.data`。不再使用 `getSsrChunks`。
- **`nitro.compressPublicAssets` 現在會在複製的 payload 旁產生 `.gz` / `.br`。** 若你已啟用此選項，公開輸出中的檔案會變多。列舉翻譯目錄的部署工具可能需要將它們納入考量。
- **升級時 payload URL 會變更一次**，因為 `?v=` 從建置時間戳記改為內容指紋。用戶端會在升級後的第一次請求重新下載字典，之後在後續部署中都會保留——這正是此變更的目的。
- **已從 `@i18n-micro/vue` 移除 `getAllTranslations()`。** 請改用 `resolveTranslations()` / `getStorage()` / `getRouteCache()`。

## 錯誤修正 {#bug-fixes}

- **`<i18n-switcher>`** — 下拉選單中會略過 `disabled: true` 的 locale。`$getLocales()` 仍會為你自己的程式碼回傳完整清單，而內建的 SEO／meta 輸出則會排除已停用的 locale。
- **切換器樣式** — `cursor: not-allowed` 透過 `activeLinkStyle` / `customActiveLinkStyle` 套用於**目前**的 locale；為了向下相容恢復了 `customDisabledLinkStyle`，並在目前 locale 為 `disabled: true` 時將其套用於切換器按鈕。
- **開發模式 HMR** — 檔案內容未變更的寫入（編輯器失焦時儲存、格式化工具重寫）不再觸發重新合併。根 locale 變更會重建該 locale 的每個頁面，因此把這種成本花在無實際變更的操作上相當昂貴。
- **開發模式 HMR** — 根 locale 變更時，頁面會並行重新合併，而不是逐一處理。
- **頁面轉場** — 同一 locale 內的導覽會將離開頁面的區塊保留為後備 layer，直到 `page:transition:finish`，而不是在每次導覽時進行昂貴的深度合併。

## 為什麼重要 {#why-it-matters}

- 提供 Vue I18n 風格的格式化，而不必引入更龐大的技術堆疊。
- 對 CDN 友善的翻譯 URL，在字典未變更時於重新建置之間保持穩定。
- 提供受支援的執行階段 API 來檢查與修補即時字典——DevTools、測試與編輯器不再需要私有輔助函式。

完整的變更紀錄將隨版本發布於 [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md)。
