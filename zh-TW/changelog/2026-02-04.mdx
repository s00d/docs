**日期**：2026-02-04

**版本**：`v3.0.0`

![v3.0.0 release](/images/3.0.0.png)

我們正式推出 **v3.0.0**，帶來**重大的架構翻新**：為追求最佳效能而完全重寫翻譯儲存系統、將路由產生與執行階段路徑邏輯拆分為專屬套件，並重新設計重新導向流程，以提升可靠性與 Serverless 相容性。

## 有哪些新功能？ {#what’s-new}

### 效能最佳化 — 全新的翻譯儲存架構 {#performance-optimization-—-new-translation-storage-architecture}

翻譯載入與快取系統已完全重寫，以達到最佳效能：

- **集中式 TranslationStorage 類別** — 新的 `TranslationStorage` 類別（`src/runtime/utils/storage.ts`）為用戶端與伺服器提供統一的儲存空間。它使用 `globalThis` 搭配 `Symbol.for`，確保在整個 Node.js 行程中都是真正的單例，避免在打包後的各模組之間重複快取。

- **最佳化的 `$t()` 函式（tFast）** — 翻譯函式直接在單一作用中的字典上查詢：
  1. 所有翻譯（根層級 + 頁面專屬 + 備援）皆在建置時預先合併為每個頁面一個檔案
  2. 在相同 locale 內導覽時，新頁面的翻譯會累積合併到作用中的字典（避免轉場動畫期間鍵值閃爍）
  3. 支援巢狀鍵（`key.subkey.subsubkey`），並採用最佳化的路徑解析
  4. 每次呼叫時不進行 Map 查詢或 locale／路由計算 — 改用預先計算的上下文

- **透過 `window.__I18N__` 進行伺服器端注入** — SSR 期間載入的翻譯會以 script 標籤注入 HTML。用戶端在初次載入時直接從 `window.__I18N__` 讀取，避免重複請求。

- **外掛中的本機區塊快取** — 外掛維護一個本機 `loadedChunks` Map，儲存所有已載入的翻譯區塊。翻譯一旦載入，在頁面生命週期內就不會再次請求。

- **建置時預先合併** — `module.ts` 中的 `preMergeLocales` 步驟會在建置時將所有 layer、備援 locale 鏈與根層級翻譯合併到每個頁面檔案中。伺服器載入器只需讀取單一預先建置的檔案 — 不需要在執行階段合併。

**效能提升：**

- 降低每個請求的記憶體配置（每次呼叫 `$t()` 時不再重新建立物件）
- 降低垃圾回收壓力
- 在負載下有更快的回應時間
- 穩定的記憶體使用模式（不再有「跳動」的圖表）

### Route 與 Path Strategy 套件 {#route-&-path-strategy-packages}

- **@i18n-micro/route-strategy** — 建置時的路由產生：以在地化路由擴充 Nuxt 頁面，並依各 strategy 處理別名、巢狀路由與自訂路徑。單一進入點：`new RouteGenerator(options)` 與 `extendPages(pages)`。各 strategy（`no_prefix`、`prefix`、`prefix_except_default`、`prefix_and_default`）實作為獨立的類別，並透過工廠選取。
- **@i18n-micro/path-strategy** — 執行階段的路徑與 locale 處理：提供 `PathStrategy`，用於建構在地化路徑、解析重新導向與切換 locale。可 tree-shake 的子路徑匯出（`/prefix`、`/no-prefix` 等），因此只會打包所選的 strategy。使用純函式進行路由解析，並以預先計算的上下文旗標將配置降到最低。
- **結構化的套件配置** — 路由邏輯位於 `@i18n-micro/route-strategy`，含 `core/`、`strategies/`。路徑 strategy 位於 `@i18n-micro/path-strategy`，採扁平的 `src/` 結構：`types.ts`、`path.ts`、`resolver.ts`、`helpers.ts` 與 `strategies/`。
- **一致的行為** — 別名處理、父子路徑串接、自訂的 `globalLocaleRoutes`／`filesLocaleRoutes`／`routeLocales`，以及不可變性保證，皆由專屬的測試套件涵蓋。

### 重新導向架構翻新 {#redirect-architecture-overhaul}

- **伺服器中介軟體** — 重新導向與 404 處理在 Nitro 中介軟體（`i18n.global.ts`）中執行。它在 Nuxt 渲染之前執行，因此當存在 locale cookie 時，從 `/` 到 `/<locale>/` 的重新導向不會出現錯誤閃爍。
- **用戶端外掛（client-side）** — 僅限用戶端的外掛（`06.client-redirect.client.ts`）會在 hydration 之後執行，並在 `useI18nLocale()` 或 cookie 設定了非預設 locale 時處理重新導向。Nitro 在 Nuxt 之前執行，因此伺服器看不到使用者外掛對 cookie／狀態所做的變更；用戶端外掛負責處理這種情況。
- **不再有備援元件** — 已移除 `locale-redirect.vue` 備援元件與 `fallbackRedirectComponentPath` 選項。重新導向邏輯完全由伺服器中介軟體與用戶端外掛處理。
- **自訂路徑支援** — 像德文的 `/kontakt` 這類路徑（透過 `globalLocaleRoutes`）在沒有 locale 前綴的情況下也能正確辨識為有效路徑，避免在預先渲染時出現錯誤的 404。
- **customRegexMatcher 修正** — 使用 `customRegexMatcher` 時，模式現在會比對**整個**第一個路徑區段（加上 `^` 與 `$` 錨點）。這可避免像 `/locale-test` 這類路由出現錯誤的 404，先前模式 `[a-z]{2}-[a-z]{2}` 會比對到子字串。
- **autoDetectPath 修正** — `autoDetectPath` 選項現在會正確地與原始 URL 路徑比較，避免在明確導覽至帶有 locale 前綴的 URL 時發生不必要的重新導向。

### useI18nLocale Composable {#usei18nlocale-composable}

- **集中式 locale 管理** — 新的 `useI18nLocale()` composable 取代 `useLocaleCookies`，為 locale 狀態、cookie 與同步工具提供單一進入點。
- **API** — `locale`、`localeCookie`、`hashCookie`、`getLocale()`、`getPreferredLocale()`、`setLocale()`、`syncLocale()`、`isValidLocale()`、`getEffectiveLocale()`、`resolveInitialLocale()`。
- **以程式設定 locale** — 在伺服器外掛中使用 `useI18nLocale().setLocale(locale)` 取代 `useState('i18n-locale')`，讓 locale 處理更簡潔、更集中。

### 自訂自動偵測與設定 {#custom-auto-detection-&-configuration}

- **`getI18nConfig()`** — 自訂外掛（例如用於 locale 偵測）應改用來自 `#build/i18n.strategy.mjs` 的 `getI18nConfig()`，而非 `useRuntimeConfig().public.i18nConfig`。這樣可以直接存取解析後的 i18n 設定（例如 `localeCookie`），不必依賴 runtime config。
- **Cookie 名稱** — 實作自訂偵測邏輯時，請使用 `getI18nConfig().localeCookie ?? 'user-locale'`。

### 簡化的整合套件 {#simplified-integration-packages}

所有整合套件（`@i18n-micro/vue`、`@i18n-micro/astro`、`@i18n-micro/node`、`@i18n-micro/react`、`@i18n-micro/preact`、`@i18n-micro/solid`）皆已簡化並最佳化，共用相同的核心翻譯邏輯。

### 設定變更 {#configuration-changes}

- **移除 `previousPageFallback`** — 不再需要此選項。新的累積合併策略會在轉場動畫期間自動保留上一頁的翻譯，並在 `page:transition:finish` hook 中將其清除。
- **`hmr`** — 從 `experimental.hmr` 移至頂層選項。控制翻譯檔案的伺服器端 HMR（開發環境中預設啟用）。

```typescript
// Before (v2.x)
export default defineNuxtConfig({
  i18n: {
    experimental: {
      hmr: true,
    },
  },
})

// After (v3.0.0)
export default defineNuxtConfig({
  i18n: {
    hmr: true,
  },
})
```

## 破壞性變更 {#breaking-changes}

- **`fallbackRedirectComponentPath`** — 已移除。模組不再使用備援路由元件進行重新導向。若你曾設定自訂元件路徑，請將其從設定中移除。
- **`useLocaleCookies`** — 已移除。請改用 `useI18nLocale()`。新的 composable 提供 `locale`、`localeCookie`、`hashCookie`、`setLocale()`、`syncLocale()` 等。
- **`experimental.i18nPreviousPageFallback`／`previousPageFallback`** — 已完全移除。累積合併策略會自動處理轉場時的閃爍。請將此選項從設定中移除。
- **`experimental.hmr`** — 已移至 `hmr`。若你曾使用此選項，請更新設定。
- **自訂外掛** — 若你的自訂 locale 偵測外掛使用了 `useRuntimeConfig().public.i18nConfig`，請改用來自 `#build/i18n.strategy.mjs` 的 `getI18nConfig()`。建議使用 `useI18nLocale().setLocale()` 而非 `useState('i18n-locale')`。更新後的範例請參閱[自訂語言偵測](/zh-TW/guide/custom-auto-detect)。
- **內部檔案變更** — 已移除 `load-from-storage.ts` 與 `translation-loader.ts`，並以 `storage.ts` 與 `server-loader.ts` 取代。若你曾直接從這些檔案匯入（不建議），請更新你的匯入。

## 為何重要 {#why-it-matters}

- **效能**：集中式的單例快取消除了每個請求的物件建立，並降低 GC 壓力。
- **可維護性**：路由與路徑邏輯位於專屬套件中，具有清楚的邊界與型別。
- **測試**：strategy 行為與邊界情況可獨立測試。
- **可靠性**：將伺服器（Nitro）與用戶端的重新導向邏輯分開，可避免使用者外掛設定 cookie／useState 時的時序問題。
- **支援 Serverless**：Nitro 外掛與 Nitro handler 在相同的上下文中執行，相容於 Edge／Workers。
- **文件**：路由行為記載於 [Strategy 指南](/zh-TW/guide/strategy)，以及 [path-strategy](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/path-strategy) 與 [route-strategy](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/route-strategy) 套件中。

升級說明與完整的變更清單，請參閱 [changelog](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md)。
