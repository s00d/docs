`@i18n-micro/devtools-ui` 是 Nuxt DevTools 分頁中的翻譯編輯器，打包為 Web Component 並附帶 Vite 外掛。將它加入 Vue、React、Preact、Solid 或 Astro 專案，即可在開發期間從瀏覽器瀏覽及編輯翻譯資料夾中的 JSON 檔案。Nuxt 應用程式已在 [Nuxt DevTools](/zh-TW/guide/devtools) 中內建此功能。

![The DevTools UI: a file tree and an editor with the default-locale text next to each key](/images/devtools/02-translations-editor-dark.webp)

## 安裝 {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/devtools-ui
```

```bash npm
npm install -D @i18n-micro/devtools-ui
```

```bash yarn
yarn add -D @i18n-micro/devtools-ui
```

</CodeGroup>

沒有 peer 相依套件。

## 設定 {#setup}

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import { i18nDevToolsPlugin } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  plugins: [i18nDevToolsPlugin({ translationDir: 'src/locales' })],
})
```

| 選項 | 預設值 | 備註 |
| --- | --- | --- |
| `translationDir` | `'src/locales'` | 存放 JSON 檔案的資料夾，相對於 Vite 根目錄。 |
| `base` | `'/__i18n_api'` | API 端點的基礎路徑。 |
| `injectButton` | `true` | 在透過 Vite 的 `index.html` 轉換所提供的頁面上加入浮動按鈕。Astro 沒有這類頁面：請見下方說明。 |
| `defaultLocale` | `translationDir` 中的第一個 locale 檔案 | 由 `/config` 回報。 |
| `fallbackLocale` | `defaultLocale` | 由 `/config` 回報。 |

此外掛只在開發伺服器上執行（`apply: 'serve'`）；正式版建置不會包含它的任何內容。按鈕會開啟 `/__i18n_devtools.html`，該頁面透過外掛的端點讀取與儲存檔案：

| 端點 | 功能 |
| --- | --- |
| `GET <base>/translations` | `translationDir` 下的每個字典，以相對路徑區分 |
| `POST <base>/save` | 主體為 `{ file, content }`；覆寫 `translationDir` 內既有的 `.json`，其他情況一律回傳 403。它絕不會建立檔案 |
| `GET <base>/config` | `{ defaultLocale, fallbackLocale, locales, translationDir }`；`locales` 來自 `translationDir` 中的根層級檔案 |

這些端點只回應 devtools 頁面：來自其他來源或主機的請求會回傳 `403`，且 `/save` 只接受 `application/json`（否則回傳 `415`）。頁面會透過 Vite 的 HMR socket 得知檔案變更。

在 Astro 中，請改為加入 integration 而非外掛。它會在開發工具列中新增一個應用程式：

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import { i18nDevToolsIntegration } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  integrations: [i18nDevToolsIntegration({ translationDir: 'src/locales' })],
})
```

儲存只會寫入檔案。透過 Vite 匯入 JSON 的應用程式會經由 HMR 取得更新；若要將編輯直接套用到執行中的實例，請使用橋接器。

## 橋接到執行中的實例 {#bridge-to-a-live-instance}

若要將編輯器嵌入你自己的頁面，並讓編輯立即套用到執行中的實例，請從 adapter 建立橋接器，並將其傳給 `<i18n-devtools-ui>` 元素：

```ts
import { createBridge, register } from '@i18n-micro/devtools-ui'
import { i18n, locales } from './i18n' // a runtime, React, Preact or Solid instance

register() // defines <i18n-devtools-ui> once

const bridge = createBridge({
  adapter: {
    getRouteCache: () => Object.fromEntries(i18n.storage.translations),
    addTranslations: (locale, content, merge) => i18n.addTranslations(locale, content, merge),
    addRouteTranslations: (locale, route, content, merge) => i18n.addRouteTranslations(locale, route, content, merge),
    subscribe: (cb) => i18n.subscribe(cb),
    getCurrentLocale: () => i18n.locale,
  },
  locales,
  defaultLocale: 'en',
  translationDir: 'src/locales',
})

const el = document.createElement('i18n-devtools-ui') as HTMLElement & { bridge: typeof bridge }
el.bridge = bridge
document.body.append(el)
```

`getRouteCache` 必須回傳以 `locale:route`（`en:index`、`en:blog-post`）為鍵的字典，這正是 `i18n.storage.translations` 所保存的內容。若是 Vue 實例，請使用 `i18n.global.getRouteCache()` 與 `i18n.global.subscribeToChanges(cb)`。

`saveTranslation` 會先更新實例，再 POST 到 `<base>/save`。若沒有端點（靜態預覽建置）或無法連線到開發伺服器，編輯會保存在 `localStorage` 中；其他任何儲存錯誤則會還原先前的字典並擲出錯誤。

## API {#api}

| 匯出 | 進入點 |
| --- | --- |
| `i18nDevToolsPlugin(options)`, `i18nDevToolsIntegration(options)` | `@i18n-micro/devtools-ui/vite` |
| `register()`, `I18nDevToolsElement` | `@i18n-micro/devtools-ui` |
| `createBridge(options)`、型別 `BridgeAdapter`, `CreateBridgeOptions` | `@i18n-micro/devtools-ui`（也可用 `/bridge/create`） |
| 型別 `I18nDevToolsBridge` | `@i18n-micro/devtools-ui`（也可用 `/bridge`） |
| `createRpcClient`, `setupRpcHost` | `@i18n-micro/devtools-ui` |

完整簽章：[套件參考](/zh-TW/api/packages/devtools-ui)。
