---
title: "型別產生器"
description: "在 Nuxt 或任何 Vite 專案中，從 JSON 檔案為翻譯鍵產生 TypeScript 自動完成。"
---

`@i18n-micro/types-generator` 會讀取翻譯資料夾中的每個 JSON 檔案，並寫出一個列出所有鍵的宣告檔。當你希望編輯器在 `t()`、`$t()` 與 `<I18nT keypath>` 中建議鍵時，請加入它。它可作為 Nuxt 模組，也可作為 Vite 或 Rollup 外掛使用，並會在檔案變更時重新產生。

## 安裝 {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/types-generator
```

```bash npm
npm install -D @i18n-micro/types-generator
```

```bash yarn
yarn add -D @i18n-micro/types-generator
```

</CodeGroup>

對等相依套件：`@nuxt/kit` `^3.18.0 || ^4.0.0`。只有 `/nuxt` 進入點會匯入它；在僅使用 Vite 的專案中，可忽略對等相依的警告。

## Nuxt {#nuxt}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@i18n-micro/types-generator/nuxt'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    translationDir: 'locales',
  },
})
```

此模組會寫出 `.nuxt/types/i18n-micro.d.ts`，而 Nuxt 會將它加入型別上下文；無需手動引入。它會讀取 `i18nTypes.translationDir`，否則使用 `nuxt-i18n-micro` 讀取翻譯的位置：每個 layer 中的 `translationDir`（來自 `i18n` 或內嵌的模組選項，預設為 `'locales'`），以及 `additionalTranslationDirs`。在 `nuxi dev` 中編輯該資料夾下的 JSON 檔案會重新產生型別。在 Nuxt 中會忽略 `i18nTypes.outputFile`（並會顯示警告）。

## Vite {#vite}

`I18nTypesPlugin` 是一個 Vite 外掛，Rollup 也能使用。若使用其他打包工具，請在腳本中呼叫 `generateTypes`。

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { I18nTypesPlugin } from '@i18n-micro/types-generator'

export default defineConfig({
  plugins: [
    vue(),
    I18nTypesPlugin({
      srcDir: process.cwd(),
      translationDir: 'src/locales',
      outputFile: 'src/i18n-micro.d.ts',
    }),
  ],
})
```

| 選項 | 必填 | 說明 |
| --- | --- | --- |
| `srcDir` | 是 | 基準目錄；`translationDir` 會相對於它解析。 |
| `translationDir` | 是 | 存放 JSON 檔案的資料夾（包含 `pages/` 等子資料夾），或資料夾陣列。 |
| `outputFile` | 否 | 宣告檔的寫入位置；預設為 `<srcDir>/i18n-micro.d.ts`。 |

外掛會在建置開始時產生一次，並在開發伺服器上，於資料夾變更 300 ms 後重新產生。請確認你的 `tsconfig.json` 的 `include` 涵蓋輸出檔案。

## 使用這些鍵 {#use-the-keys}

產生的檔案會擴充 `@i18n-micro/types` 中的 `DefineLocaleMessage`，讓 `TranslationKey` 變成你的鍵：

```ts
declare module '@i18n-micro/types' {
  export interface DefineLocaleMessage {
    nav: object
    'nav.home': string
    'profile.title': string
  }
}
```

這些鍵就是 `t()` 會回應的鍵（包含物件），來自每個語系與每個頁面檔案，並帶有其 JSON 值的型別。`TranslationKey` 是這些鍵與任意字串的聯集，因此你得到的是自動完成，而不是錯誤：拼錯或動態的鍵仍然可以編譯。參數與回傳值則沒有型別。

對於已知前綴下的動態鍵，`ScopedKey<'prefix'>` 會縮小範圍至符合的鍵：

```ts
import type { ScopedKey } from '@i18n-micro/types'

const statusText = (status: string) => t(`status.${status}` as ScopedKey<'status'>)
```

`TranslationKey` 與 `ScopedKey` 來自 `@i18n-micro/types`（React、Preact 與 Solid 會重新匯出 `TranslationKey`；Vue 則不會）。

## API {#api}

| 匯出 | 進入點 | 說明 |
| --- | --- | --- |
| `I18nTypesPlugin(options)` | `@i18n-micro/types-generator` | Vite 與 Rollup 外掛 |
| `generateTypes(options)` | `@i18n-micro/types-generator` | 寫出檔案，回傳其路徑 |
| `getTypesString(options)` | `@i18n-micro/types-generator` | 回傳宣告內容而不寫入檔案 |
| `formatKeyProperty(key)` | `@i18n-micro/types-generator` | 輔助函式 |
| Nuxt 模組（`configKey: 'i18nTypes'`） | `@i18n-micro/types-generator/nuxt` | 選項 `translationDir` |

完整簽章：[套件參考](/zh-TW/api/packages/types-generator)。
