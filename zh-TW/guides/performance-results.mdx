### 說明

在同一份共用字典 profile 下，比較 **plain Nuxt**（無 i18n 模組的基準）、**i18n-micro** 與 **`@nuxtjs/i18n` v10.6**。

聚焦於：建置時間、尖峰 RSS、部署後的**程式碼 vs 翻譯 vs 總大小**，以及在 Artillery + Autocannon 下的伺服器行為。

### 方法備註

- 指標為**每個 fixture 連續 3 次的平均**（fixture A ×3、再 B ×3、再 C ×3，不交錯執行）。
- **翻譯**包含 `locales/`／`_locales/`／`translations/` 下的語系 JSON、`chunks/raw/` 下的所有內容以及對應的語系 chunk。舊版報告顯示 `@nuxtjs/i18n`「translations: 0 B」及很大的「code」欄位，是把訊息 chunk 算成應用程式碼。
- **plain-nuxt** 以靜態 `public/translations` JSON（而非靜態 JS import）提供相同的葉節點量。在 Artillery 下這個基準是 I/O 導向的，並非 i18n 開銷，而是每次請求都下載大型 JSON 的成本。

### 執行次數

以下所有指標皆為 **3 次執行的平均**。

字典來自 `test/fixtures/perf-shared/runtime.json`（由 CLI 寫入），確保三個 fixture 相互對齊。

## 備註

- 共用 profile：4 語系 × 2 頁面 × 約 16.8k index 葉節點鍵。
- Artillery：6 秒熱身 @6 VU/s + 60 秒主測試 @60 VU/s。Autocannon：10 連線 × 10 秒。
- 重新執行：`pnpm test:performance` 或 `pnpm -C scripts cli performance --locales N --keys K --only all|micro|i18n|plain --runs N`。
