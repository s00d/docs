# 從 i18n 路由排除靜態檔案

## 總覽

預設情況下，nuxt-i18n-micro 會自動將常見靜態檔案排除於 i18n 路由處理之外。此外，你也可以設定自訂排除模式，避免特定路徑被 i18n 系統處理。

## 內建排除項目

模組會自動排除以下檔案類型與模式：

- **Sitemap**：`/sitemap*.xml`、`/sitemap-en.xml` 等。
- **SEO 檔案**：`/robots.txt`、`/favicon.ico`
- **PWA 檔案**：`/manifest.json`、`/sw.js`、`/workbox-*.js`
- **靜態資產**：副檔名如 `.xml`、`.txt`、`.ico`、`.json`、`.js`、`.css`、`.png`、`.jpg`、`.jpeg`、`.gif`、`.svg`、`.woff`、`.woff2`、`.ttf`、`.eot` 的檔案
- **Nuxt 內部路徑**：任何以 `__` 開頭的路徑（如 `/__nuxt/`）

## 自訂排除模式

你可以透過 `excludePatterns` 選項定義自訂排除模式：

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## 模式類型

### 字串模式

- **完全比對**：`'/api/health'`：完全對應 `/api/health`
- **前綴比對**：`'/admin'`：對應 `/admin` 與 `/admin/dashboard`
- **萬用字元**：`'/api/*'`：對應 `/api/users`，不對應 `/api/users/123`
- **深度萬用字元**：`'/admin/**'`：對應 `/admin/users` 與 `/admin/users/123`

### 正規表達式

使用 RegExp 物件進行複雜的模式比對：

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## 使用情境

### SEO 檔案

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API 路由

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### 後台管理

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### 靜態資產

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## 運作方式

1. **伺服器 middleware**：Nitro middleware 會先執行以檢查排除模式
2. **頁面處理**：頁面解析期間會略過被排除的路徑
3. **Catch-all 路由**：fallback 路由在處理前會先檢查排除設定
4. **預先渲染**：被排除的路徑不會出現在預先渲染的路由中

## 效能影響

- 排除檢查已最佳化，會在請求生命週期早期執行
- 內建模式使用有效率的 regex 比對
- 自訂模式會被快取並重複使用
- 對被排除路徑而言，效能負擔極低

## 疑難排解

### 靜態檔案仍被攔截

1. **檢查模式語法**：確保你的模式符合實際路徑結構
2. **對複雜模式使用 regex**：字串萬用字元有其限制
3. **測試模式**：使用瀏覽器開發工具驗證實際請求路徑
4. **檢查順序**：確保排除模式在其他 i18n 設定之前定義

### 模式無效

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### 除錯模式

啟用除錯模式可看到排除處理過程：

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

這會在 console 記錄排除的判斷。

## 從變通方案遷移

若你先前使用 route rules 或 middleware 之類的變通方式，現在可用 `excludePatterns` 取代：

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

新做法更可靠，且能在路由系統的多層之中生效。
