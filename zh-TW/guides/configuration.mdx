# 選項細節

模組提供豐富的設定選項以自訂國際化流程。

### 🌍 核心語系設定

#### `locales`

{/* generated:option:locales — do not edit; run `pnpm run docs:generate` */}

**型別** `Locale[]` · **預設值** `[]`

支援的語系清單。
每個項目定義一個語系代碼及選填的中繼資料（ISO、書寫方向、顯示名稱等）。

{/* /generated:option:locales */}

每個 locale 物件支援：

| 屬性             | 型別      | 必填  | 說明                                                     |
| ---------------- | --------- | ----- | -------------------------------------------------------- |
| `code`           | `string`  | ✅    | 唯一識別（例如 `'en'`）                                    |
| `displayName`    | `string`  | ❌    | 用於切換器的可讀名稱（例如 `'English'`）                   |
| `iso`            | `string`  | ❌    | ISO 代碼（例如 `'en-US'`）                                 |
| `dir`            | `string`  | ❌    | 文字方向（`'ltr'` 或 `'rtl'`）                             |
| `disabled`       | `boolean` | ❌    | 為 `true` 時在下拉中停用                                   |
| `baseUrl`        | `string`  | ❌    | 特定語系網域的基底 URL                                     |
| `baseDefault`    | `boolean` | ❌    | 從 URL 中移除語系前綴                                      |
| `fallbackLocale` | `string`  | ❌    | 逐語系的 fallback（覆寫全域）                              |
| `[key: string]`  | `unknown` | ❌    | 任意自訂屬性（見下方）                                     |

**範例**：

```typescript
locales: [
  { code: 'en', iso: 'en-US', dir: 'ltr' },
  { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
  { code: 'ar', iso: 'ar-SA', dir: 'rtl', disabled: true },
  {
    code: 'de',
    iso: 'de-DE',
    dir: 'ltr',
    baseUrl: 'https://de.example.com',
    baseDefault: true,
  },
]
```

<Warning>
使用 `baseUrl` 可能會導致內部路由重複成為外部連結，讓路由與維護變得複雜。建議直接為特定語系建立外部連結。
</Warning>

#### 自訂 Locale 屬性

你可以在 locale 物件上加入任何自訂屬性，這些屬性會傳遞到執行時，並可透過 `$getLocales()` 存取：

```typescript
locales: [
  { code: 'en', iso: 'en-US', flag: '🇬🇧', currency: 'GBP' },
  { code: 'de', iso: 'de-DE', flag: '🇩🇪', currency: 'EUR' },
  { code: 'ru', iso: 'ru-RU', flag: '🇷🇺', currency: 'RUB' },
]
```

在元件中存取：

```vue
<template>
  <ul>
    <li v-for="locale in $getLocales()" :key="locale.code">{{ locale.flag }} {{ locale.displayName }} ({{ locale.currency }})</li>
  </ul>
</template>
```

預設情況下，自訂屬性的型別為 `unknown`。若要獲得完整的 TypeScript 支援，可使用**模組擴充**。建立宣告檔（例如 `app/i18n.d.ts` 或任何被 `tsconfig` 包含的 `.d.ts`）：

```typescript
// app/i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
    currency?: string
  }
}
```

之後，所有自訂屬性都會有完整型別：

```typescript
const locales = $getLocales()
locales[0].flag // string | undefined ✅
locales[0].currency // string | undefined ✅
```

#### `defaultLocale`

{/* generated:option:defaultLocale — do not edit; run `pnpm run docs:generate` */}

**型別** `string` · **預設值** `'en'`

當無法由 URL 或使用者偏好判斷語系時使用的語系。
若未設定 `fallbackLocale`，也會作為缺失翻譯的 fallback 語系。

{/* /generated:option:defaultLocale */}

```typescript
defaultLocale: 'en'
```
#### `strategy`

{/* generated:option:strategy — do not edit; run `pnpm run docs:generate` */}

**型別** `Strategies` · **預設值** `'prefix_except_default'`

用於語系前綴的 URL 路由策略。

- `'no_prefix'`：URL 不含語系；語系儲存在 cookie 中。
- `'prefix_except_default'`：除了預設語系以外，全部加前綴。
- `'prefix'`：一律加前綴，包括預設語系。
- `'prefix_and_default'`：類似 `prefix`，但預設語系也能透過不加前綴的形式存取。

{/* /generated:option:strategy */}

<CodeGroup>
```typescript no_prefix
strategy: 'no_prefix'
// Routes: /about, /contact
// Locale detection via browser/cookies
```

```typescript prefix_except_default
strategy: 'prefix_except_default'
// Default locale: /about, /contact
// Other locales: /fr/about, /de/contact
```

```typescript prefix
strategy: 'prefix'
// All locales: /en/about, /fr/about, /de/about
```

```typescript prefix_and_default
strategy: 'prefix_and_default'
// Both prefixed and non-prefixed versions for default locale
```
</CodeGroup>

### 📂 翻譯管理
#### `translationDir`

{/* generated:option:translationDir — do not edit; run `pnpm run docs:generate` */}

**型別** `string` · **預設值** `'locales'`

存放翻譯 JSON 檔的目錄路徑，相對於專案根目錄。

{/* /generated:option:translationDir */}

```typescript
translationDir: 'i18n' // Custom directory
// Nuxt 4 colocation example:
// translationDir: 'app/locales'
```

路徑會從 Nuxt 的**專案根目錄**（`rootDir`）解析，而不是從 `app/`。在 Nuxt 4 中，通常做法是 `app/pages/` 存放路由，而 `locales/`（若你設定 `translationDir` 也可為 `app/locales`）存放 JSON 檔。
#### `disablePageLocales`

{/* generated:option:disablePageLocales — do not edit; run `pnpm run docs:generate` */}

**型別** `boolean` · **預設值** `false`

停用逐頁翻譯檔。
當設為 `true` 時，只載入全域翻譯（`\{locale\}.json`）；不會產生或載入頁面專屬檔案（`pages/\{page\}/\{locale\}.json`）。

{/* /generated:option:disablePageLocales */}

啟用後只會使用根層翻譯檔：

```tree
locales/
├── en.json
├── fr.json
└── ar.json
```
#### `fallbackLocale`

{/* generated:option:fallbackLocale — do not edit; run `pnpm run docs:generate` */}

**型別** `string` · **預設值** `undefined（沒有 fallback；直接回傳原始鍵）`

全域 fallback 語系代碼。
當目前語系中缺失翻譯鍵時，模組會先在此語系中查找，找不到才回傳鍵本身。

{/* /generated:option:fallbackLocale */}

```typescript
fallbackLocale: 'en' // Global fallback
```
#### `types`

{/* generated:option:types — do not edit; run `pnpm run docs:generate` */}

**型別** `boolean` · **預設值** `true`

依據預設語系檔案中的翻譯鍵，為 `useI18n`、`$t` 及相關輔助方法產生 TypeScript 型別宣告。

{/* /generated:option:types */}

啟用後，模組會在建置期產生 `.nuxt/i18n.d.ts`，其中包含帶型別的翻譯鍵。若你偏好不帶型別的輔助方法或使用外部產生器，可設為 `false`。

此內建產生器與選用的 [`@i18n-micro/types-generator`](/integrations/types-generator) 套件分離，後者可為 monorepo 與 CI 產生更嚴格或獨立的型別檔案。

```typescript
types: false // Disable built-in key typing
```
#### `routeLocales`

{/* generated:option:routeLocales — do not edit; run `pnpm run docs:generate` */}

**型別** `Record<string, string[]>` · **預設值** —

逐路由的語系限制，由 `defineI18nRoute()` 呼叫抽取而來。
將路由路徑（例如 `'/about'`）對應到允許的語系代碼陣列。未列出的路由沒有限制（所有語系皆允許）。

{/* /generated:option:routeLocales */}

將路由路徑（例如 `'/about'`）對應到允許的語系代碼。未列出的路由會允許所有已設定的語系。

通常你會透過頁面中的 [`defineI18nRoute`](/guides/custom-locale-routes) 設定，而不是直接在 `nuxt.config` 中設定。模組會在建置期將頁面層級宣告合併進此對應。
#### `routeDisableMeta`

{/* generated:option:routeDisableMeta — do not edit; run `pnpm run docs:generate` */}

**型別** `Record<string, boolean \| string[]>` · **預設值** —

逐路由的 meta 標籤停用設定，由 `defineI18nRoute()` 呼叫抽取而來。
將路由路徑對應到 `true`（停用所有 meta）或語系代碼陣列（要停用哪些語系的 meta）。

{/* /generated:option:routeDisableMeta */}

- `true`：為該路由停用所有 SEO meta
- `string[]`：僅停用列出的語系代碼的 meta

與 `routeLocales` 相同，這通常是在頁面元件中設定，而不是手動在 config 中設定。
#### `experimental`

{/* generated:option:experimental — do not edit; run `pnpm run docs:generate` */}

**型別** `Record<string, unknown>` · **預設值** —

實驗性／不穩定選項的容器。
內容可能在 minor 版本間變動或被移除，恕不另行通知。

{/* /generated:option:experimental */}

#### `customRegexMatcher`

{/* generated:option:customRegexMatcher — do not edit; run `pnpm run docs:generate` */}

**型別** `string \| RegExp` · **預設值** `undefined（使用依語系代碼建構的內建 pattern）`

<Danger>

> `Nuxt-i18n-micro: Some locale codes does not match customRegexMatcher`

請在部署前先驗證你的 regex 是否能正確比對所有語系代碼。
</Danger>

```typescript
// ✅ Correct: matches 'en-us', 'de-de', 'fr-fr'
customRegexMatcher: '[a-z]{2}-[a-z]{2}'

// ✅ Correct: matches 'en', 'de', 'fr', 'zh'
customRegexMatcher: '[a-z]{2}'

// ❌ Wrong: won't match 'zh-Hant' (uppercase letter)
// This will FAIL the build if 'zh-Hant' is in your locales list
customRegexMatcher: '[a-z]{2}-[a-z]{2}'
```

### 🔢 自訂
#### `plural`

{/* generated:option:plural — do not edit; run `pnpm run docs:generate` */}

**型別** `PluralFunc` · **預設值** `內建複數規則（依 count 決定形式索引）`

自訂複數規則函式。
接收 `(key, count, params, locale, getter)`，應回傳所選複數形式的字串；回傳 `null`／`undefined` 則會退回內建 `defaultPlural` 邏輯（讓你可以只覆寫部分語系）。

在 Nuxt 模組中會透過 `.toString()` 序列化為 `.nuxt/i18n.plural.mjs`，因此該函式必須自成一體（不可有 imports 或外部 scope）。**不**支援檔案路徑字串。

{/* /generated:option:plural */}

##### 運作方式

翻譯以 `|` 分隔複數形式：

```json
{
  "apples": "no apples | one apple | {count} apples"
}
```

當某個形式除了 `\{count\}` 之外還需要其他參數時，使用 `$tc('apples', count)` 或 `$tc('cart', \{ count, name \})`：**請在第二個引數物件中同時傳入 `count` 與其他參數**，不要作為第三個引數（第三個引數僅為 `defaultValue`）。

`$tc` 呼叫會觸發 `plural` 函式，該函式會：

1. 呼叫 `t(key)` 取得原始翻譯字串（例如 `"no apples | one apple | \{count\} apples"`）
2. 以 `|` 分割取得形式陣列
3. 依 `count` 選擇形式
4. 將 `\{count\}` 替換為實際數字

**預設**實作以索引選擇：`count < forms.length ? forms[count] : forms[last]`。適用於簡單情境（0 → 第一種形式、1 → 第二種、2+ → 最後一種）。

##### 自訂複數函式

若語言有較複雜的複數規則（例如俄文、阿拉伯文、波蘭文），可覆寫 `plural` 選項。

<Danger>
此函式會在建置期透過 `.toString()` 序列化並注入到虛擬模組中。這代表：

- **必須使用 `function` 關鍵字**：不能使用簡寫方法語法，也不能使用參考外部變數的箭頭函式
- **不可有 imports 或外部參考**：函式必須完全自成一體（`plural: '~/i18n/plural.ts'` 這類檔案路徑**不**支援）
- **不可使用無法通過 `.toString()` 的 TypeScript-only 語法**（型別註記在 `nuxt.config.ts` 中沒問題，因為 Nuxt 會將其移除）
- 回傳 `null` / `undefined` 會退回內建 `defaultPlural`（適合逐語系覆寫）
</Danger>

**範例：俄文複數**（4 種形式：zero、one、few、many）：

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  i18n: {
    plural: function (key, count, _params, _locale, t) {
      const translation = t(key)
      if (!translation) return key

      const forms = translation
        .toString()
        .split('|')
        .map(function (s) {
          return s.trim()
        })
      let idx

      if (count === 0) {
        idx = 0
      } else {
        const mod10 = count % 10
        const mod100 = count % 100
        if (mod10 === 1 && mod100 !== 11) {
          idx = 1
        } else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) {
          idx = 2
        } else {
          idx = 3
        }
      }

      if (idx >= forms.length) idx = forms.length - 1
      return (forms[idx] || '').replace('{count}', String(count))
    },
  },
})
```

搭配以下翻譯：

```json
{
  "apples": "нет яблок | {count} яблоко | {count} яблока | {count} яблок"
}
```

結果：

- `$tc('apples', 0)` → `"нет яблок"`
- `$tc('apples', 1)` → `"1 яблоко"`
- `$tc('apples', 3)` → `"3 яблока"`
- `$tc('apples', 5)` → `"5 яблок"`
- `$tc('apples', 21)` → `"21 яблоко"`

**範例：簡單英文（預設行為）**：

```typescript
// This is the built-in default — you don't need to set it explicitly
plural: function (key, count, params, _locale, t) {
  const translation = t(key, params)
  if (!translation) return null

  const forms = translation.toString().split('|')
  if (forms.length === 0) return null
  const form = count < forms.length ? forms[count] : forms[forms.length - 1]
  if (!form) return null
  return form.trim().replace('{count}', count.toString())
}
```

##### 逐語系複數規則

若不同語系需要不同複數規則，可依 `locale` 分支，並對不自訂的語系回傳 `null`，讓內建 `defaultPlural` 處理其餘部分：

```typescript
plural: function (key, count, _params, locale, t) {
  // Only override Slavic locales; en/de/… keep the built-in rules
  if (locale !== 'ru' && locale !== 'uk') return null

  const translation = t(key)
  if (!translation) return null

  const forms = translation.toString().split('|').map(function (s) { return s.trim() })
  let idx
  if (count === 0) {
    idx = 0
  } else {
    const mod10 = count % 10
    const mod100 = count % 100
    if (mod10 === 1 && mod100 !== 11) idx = 1
    else if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) idx = 2
    else idx = 3
  }
  if (idx >= forms.length) idx = forms.length - 1
  return (forms[idx] || '').replace('{count}', String(count))
}
```

<Warning>
**不**支援 `plural: '~/i18n/plural.ts'`（或任何字串路徑）。Nuxt 模組會以 `.toString()` 將函式序列化到虛擬檔案中；來自其他模組的外部 imports 與輔助工具會被移除，執行時會是 `undefined`。請將函式完全內聯在 `nuxt.config.ts` 中（見上方危險提示）。
</Warning>
#### `localeCookie`

{/* generated:option:localeCookie — do not edit; run `pnpm run docs:generate` */}

**型別** `string \| null` · **預設值** `null`

用來跨 session 保存使用者語系偏好的 cookie 名稱。
設為 `null` 可停用 cookie 儲存。
若未提供且策略為 `no_prefix`，會自動設定為 `'user-locale'`。

{/* /generated:option:localeCookie */}

<Warning>
雖然設定的預設值為 `null`（停用），但使用 `strategy: 'no_prefix'` 時，模組會**自動覆寫**為 `'user-locale'`。這代表：

- **`no_prefix`**：cookie **始終啟用**（`'user-locale'`），即使你未明確設定。這是必要的，因為 URL 中不含語系資訊。
- **其他所有策略**：cookie 預設為 `null`（停用），除非你明確設定。

若你明確設定 `localeCookie`，無論策略為何都會使用你的值。
</Warning>

<Warning>
搭配 `redirects: true`（預設）使用 prefix 策略（`prefix`、`prefix_except_default`、`prefix_and_default`）時，你**必須**設定 `localeCookie`，重新導向行為才會正確運作。若沒有 cookie，重新導向外掛無法在頁面重新載入間記住使用者的語系偏好，僅能依 `Accept-Language` 標頭（若 `autoDetectLanguage: true`）或 `defaultLocale` 進行重新導向。
</Warning>

```typescript
// Enable cookie (recommended when using redirects with prefix strategies)
localeCookie: 'user-locale'

// Enable cookie with custom name
localeCookie: 'my-locale-cookie'

// Disable cookie (default) - locale won't persist across reloads
localeCookie: null
```

**`localeCookie` 啟用後可提供：**

- 跨頁面重新載入保存使用者的語系偏好
- 使用者回訪站點時記住語系
- `no_prefix` 策略正確運作的必要條件
- prefix 策略下重新導向行為的**必要條件**（當 `redirects: true` 時）

#### `translationPayloads`

{/* generated:option:translationPayloads — do not edit; run `pnpm run docs:generate` */}

**型別** `TranslationPayloadOptions` · **預設值** —

控制翻譯 payload 的產出方式（Node：`public/<apiBaseUrl>`；Edge：Nitro `serverAssets`）。

```typescript
{
  mode?: 'premerged' | 'source'
  serverAssets?: boolean
  serverHandler?: boolean
  publicAssets?: boolean
  prerenderRoutes?: boolean
  publicDir?: string
  warnFileCount?: number
  warnSizeBytes?: number
}
```

**預設**（`mode: 'premerged'`）：

```typescript
{
  mode: 'premerged',
  serverAssets: true,
  serverHandler: true,
  publicAssets: true,
  prerenderRoutes: false
}
```

**Node** 上的 SSR 會讀取複製到 `public/<apiBaseUrl>/` 的同一份 tree（`readFile`）。**Edge** 上則透過 Nitro `serverAssets` 內嵌（不會強制產生 public 副本，若要供 CDN 使用請將 `publicAssets: true`）。`mode: 'premerged'` → 逐頁／逐語系 `\{page\}/\{locale\}/data.json`；`mode: 'source'` → 精簡原始檔 + 執行期合併。

**Node** 上的 `serverAssets: true` 會強制產生 public 副本，即使 `publicAssets` 為 false。**Edge** 上則只註冊 Nitro 內嵌。Edge 上大型翻譯集建議使用 `mode: 'source'`。若沒有本地 payload 也沒有 `apiBaseServerHost`，建置會失敗。

本地的 `/\{apiBaseUrl\}/:page/:locale/data.json` handler、prerender 路由與 public 資產副本皆為選填輸出。

若要產出更精簡的 **public**／Edge payload：

```typescript
i18n: {
  translationPayloads: {
    mode: 'source',
  },
}
```

`mode: 'source'` 讓 layer 檔案維持精簡，並在執行期透過內建的 `/_locales` 路由（或 Edge 的 `assets:i18n`）合併根層／頁面／fallback。預設會停用 public 資產副本與 prerender payload 路由。

<Warning>
使用 `mode: 'source'` 時，`publicAssets` 預設為 `false`（`prerenderRoutes` 也永遠關閉，除非你明確啟用）。因此純靜態託管（無 Nitro／edge 執行時）在用戶端無法載入翻譯，除非你啟用這些輸出、讓 `serverHandler` 在執行時可用，或以外部方式託管 payload。

搭配預設 `mode: 'premerged'` 與 `publicAssets: true` 時，靜態檔案已放在 `public/<apiBaseUrl>/\{page\}/\{locale\}/data.json`（對應用戶端 `$fetch` URL），因此靜態主機無需 Nitro 也能提供。
</Warning>

<Warning>
當設定 `apiBaseServerHost` 或 `apiBaseClientHost` 時，模組會直接從該 origin 取得已合併的 JSON。外部主機必須提供與內建路由相同的 `/\{apiBaseUrl\}/:page/:locale/data.json` 回應。`mode: 'source'` 只適用於本地 payload 目錄，除非外部 CDN 也能提供執行期合併後的 payload。
</Warning>

你也可以手動停用本地輸出，改由 CDN 或物件儲存提供翻譯 payload：

```typescript
i18n: {
  apiBaseClientHost: 'https://cdn.example.com',
  apiBaseServerHost: 'https://cdn.example.com',
  translationPayloads: {
    serverHandler: false,
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

若只想避免將 payload 寫入 public 輸出，但保留內建伺服器路由供 SSR／執行期請求使用，可將兩個 public 輸出都停用：

```typescript
i18n: {
  translationPayloads: {
    publicAssets: false,
    prerenderRoutes: false
  }
}
```

在 **Node** 上，即使 `publicAssets` 為 false，`serverAssets: true` 仍會強制為 SSR 產生 public 副本。若你希望完全沒有本地 payload 檔案，請設 `serverAssets: false` 並提供 `apiBaseServerHost`。

當 payload 需要被複製時，可使用 `publicDir` 變更 public 輸出資料夾。預設值等於 `apiBaseUrl`（`_locales`）。在 premerged 模式下，`publicAssets` 會在該處寫出 `\{page\}/\{locale\}/data.json`（與用戶端 fetch 相同的路徑）。`prerenderRoutes` 為選填的 Nitro handler 路由預先渲染，通常在該 tree 已複製時沒必要。

若停用所有本地 payload 輸出，你必須同時設定 `apiBaseServerHost`（SSR）與 `apiBaseClientHost`（用戶端導覽），否則翻譯會解析為空物件，UI 鍵可能顯示為未翻譯狀態。

`warnFileCount` 與 `warnSizeBytes` 用於控制建置期預先合併 payload 增長時的警告（預設：500 個檔案、10 MB）。

#### `dateBuild`

{/* generated:option:dateBuild — do not edit; run `pnpm run docs:generate` */}

**型別** `string \| number` · **預設值** —

用於破除翻譯請求快取的值（`?v=...`）。

若未提供，模組會退回 `Date.now()`（非決定性）。
若需可重現／滾動部署，請設為固定值（例如 git SHA 或 build 編號）。

{/* /generated:option:dateBuild */}

模組預設會為翻譯來源產生指紋（依 layer 順序對每個 `<layer>/<translationDir>/**/*.json` 計算 SHA-256）並使用該值。只有在翻譯真正變更時，該值才會變動，因此重新建置或部署未變動的翻譯不會導致瀏覽器與 CDN 快取失效。若把 `httpCacheDuration` 設為一年，改用 build timestamp 反而會強迫每個用戶端在每次部署後重新下載整份字典。

只有在沒有翻譯檔案可雜湊時，才會退回 `Date.now()`。

若你想主導這個行為（例如讓 payload URL 綁定於發行版本，而非內容），可明確設定：

```ts
export default defineNuxtConfig({
  i18n: {
    // Any stable string/number: git SHA, CI build number, release tag, etc.
    dateBuild: process.env.GIT_SHA ?? 'local-dev',
  },
})
```
#### `httpCacheDuration`

{/* generated:option:httpCacheDuration — do not edit; run `pnpm run docs:generate` */}

**型別** `number` · **預設值** `31536000`

`/\{apiBaseUrl\}/:page/:locale/data.json` 的 HTTP `Cache-Control` max-age（秒）。

只有在 `dateBuild` 破除 URL 快取（`?v=...`）時才會完整套用；此為預設行為，回應會是 `public, max-age=…, immutable`，對瀏覽器與 CDN 都安全。

- `dateBuild: 0`／`''`：URL 為固定，此期限**不會**被套用；回應變為 `public, max-age=0, must-revalidate`。若對不變的 URL 設定長 `max-age`，會鎖住瀏覽器第一次看到的 payload。

- `0`：完全不設 `Cache-Control`（本機除錯時很有用）
- 開發模式（`import.meta.dev`）不會套用，避免瀏覽器快取干擾 HMR
- 只影響透過 Nitro 提供的回應。複製到 `public/` 並由主機平台提供的 payload 會採用該平台的標頭，請參見效能指南。

等同於 `@nuxtjs/i18n` 的實驗性 `httpCacheDuration`（v10.2.0），但採用明確的回應標頭，而非 Nitro 的 `defineCachedEventHandler` maxAge。

{/* /generated:option:httpCacheDuration */}

```ts
export default defineNuxtConfig({
  i18n: {
    // Per-build fallback (Date.now()) so immutable payloads never go stale when GIT_SHA is missing.
    dateBuild: process.env.GIT_SHA ?? String(Date.now()),
    httpCacheDuration: 86400, // 24 hours
    // httpCacheDuration: 0, // disable Cache-Control header
  },
})
```

#### `cacheTtl`

{/* generated:option:cacheTtl — do not edit; run `pnpm run docs:generate` */}

**型別** `number` · **預設值** `0`

已快取翻譯的存活時間（秒）。
`0` 表示項目永不過期。

{/* /generated:option:cacheTtl */}

```typescript
export default defineNuxtConfig({
  i18n: {
    // Limit cache to 1000 entries, each lives 10 minutes (refreshed on access)
    cacheMaxSize: 1000,
    cacheTtl: 600,
  },
})
```

<Tip>
對大多數專案而言，預設值（無上限、不過期）是合適的：翻譯內容小且有限。然而，若你的專案有**成千上萬個頁面**且 `disablePageLocales: false`，並支援**眾多語系**，伺服器端快取可能會顯著增長。在長時間執行的 Node.js 伺服器中，這可能造成過度記憶體使用。

- **`cacheMaxSize`**：限制已快取項目數，適合用於限縮記憶體上限。
- **`cacheTtl`**：確保過期翻譯最終會從儲存重新載入，適用於 serverless 環境或執行期會變更的翻譯。

**估算最大項目數的公式**：`語系數 × (頁面數 + 1)`。例如 10 語系 × 500 頁面 = 約 5010 項。
</Tip>
