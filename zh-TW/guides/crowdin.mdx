# 🌐 Crowdin 整合指南

## 📖 介紹

將 Crowdin 整合到你的專案能簡化在地化與翻譯流程，讓你更輕鬆地跨多種語言與平台管理翻譯。本指南提供一步步操作說明，涵蓋 Crowdin 設定、上傳原始檔與下載翻譯。

## 🔧 安裝與設定

要開始使用 Crowdin，你需要在本機全域安裝 Crowdin CLI，並在專案目錄中初始化。

### 📦 安裝 Crowdin CLI

首先使用 npm 全域安裝 Crowdin CLI：

```bash
npm install -g @crowdin/cli
```

### 🛠 在專案中初始化 Crowdin

執行以下指令在專案中初始化 Crowdin：

```bash
crowdin init
```

該指令會引導你完成設定流程，包括設定專案 ID、API token 及其他細節。

## 🗂️ 設定指南

### 📄 Crowdin 設定檔（`crowdin.yml`）

Crowdin 設定檔（`crowdin.yml`）定義原始檔如何對應，以及翻譯應放置何處。以下是範例設定：

```yml
'project_id': 'YOUR_PROJECT_ID'
'api_token': 'YOUR_API_TOKEN'
'base_path': './locales'
'base_url': 'https://api.crowdin.com'
'preserve_hierarchy': true

files:
  [
    { 'source': '/en.json', 'translation': '/%two_letters_code%.json' },
    { 'source': '/pages/**/en.json', 'translation': '/pages/**/%two_letters_code%.json' },
  ]
```

### 📂 主要設定參數

- **`project_id`**：你的 Crowdin 專案 ID，用於識別翻譯所屬的專案。
- **`api_token`**：用於身分驗證的 API token，請確保它擁有上傳與下載翻譯的正確權限。
- **`base_path`**：指定原始檔的基底目錄。範例中翻譯存放於 `./locales` 目錄。
- **`base_url`**：Crowdin API 的基底 URL。
- **`preserve_hierarchy`**：設為 `true` 時，Crowdin 會在專案中保留原始檔的資料夾結構。

### 📂 檔案設定

`files` 區塊將原始檔對應到翻譯要存放的路徑。例如：

- **原始檔路徑**：定義原始翻譯檔的位置。
- **翻譯路徑**：指定翻譯後的檔案在 Crowdin 上的存放位置。`%two_letters_code%` 這類 placeholder 用於在路徑中動態填入語言代碼。

## ⬆️ 上傳原始檔至 Crowdin

設定完成後，你可以使用以下指令上傳原始檔：

```bash
crowdin upload sources
```

該指令會上傳設定中指定的所有原始檔，讓它們可以進行翻譯。

## ⬇️ 從 Crowdin 下載翻譯

翻譯在 Crowdin 上完成或更新後，可使用以下指令下載到專案：

```bash
crowdin download
```

該指令會取得 Crowdin 上最新翻譯，並依設定檔指定路徑儲存到專案中。

## ⚙️ 最佳實務

### 🔑 一致的鍵命名

確保翻譯鍵在所有檔案中保持一致，避免混淆與重複。

### 🧹 定期維護

定期檢視並清理未使用的翻譯鍵，讓檔案保持整齊、易於管理。

### 🛠 自動化上傳與下載

將 Crowdin CLI 指令整合到 CI/CD 流程中，自動化原始檔上傳與翻譯下載，確保翻譯永遠保持最新。

依循本指南，你就能將 Crowdin 無縫整合進專案，以更有效率、更有條理的方式管理國際化工作。
