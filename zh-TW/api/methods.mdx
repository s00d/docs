---

模組會將其執行階段輔助函式注入 Nuxt 應用程式：`$t`、`$tc`、`$localePath`、`$switchLocale` 等。請使用本頁查詢輔助函式的簽章與行為。簽章與說明來自 `src/runtime/plugins/01.plugin.ts` 中的 `PluginsInjections` 與 `NuxtAppOnlyInjections` 介面。

## 存取方式 {#access}

| 位置 | 方式 |
| --- | --- |
| 範本 | `{{ $t('title') }}` — 所有輔助函式，帶 `$` |
| `<script setup>` | `const { t, localePath } = useI18n()` — `PluginsInjections` 中的所有輔助函式，有無 `$` 皆可 |
| 外掛、中介軟體、`<script setup>` | `const { $t, $defineI18nRoute } = useNuxtApp()` — 全部，只能帶 `$` |

`$defineI18nRoute` 只在 `useNuxtApp()` 上有型別。請參閱 [`useI18n`](/zh-TW/composables/useI18n)。

```vue
<script setup lang="ts">
const { t, localePath } = useI18n()
</script>

<template>
  <NuxtLink :to="localePath('/about')">{{ t('nav.about') }}</NuxtLink>
</template>
```

## 語系 {#locale}

### `$getLocale` {#$getlocale}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric) => string
```

目前語系的代碼。傳入路由即可讀取該路由所屬的語系。

```ts
$getLocale() // 'de' on /de/about
```

### `$getLocaleName` {#$getlocalename}

```ts
() => string | null
```

設定中目前語系的 `displayName`，若沒有則為 `null`。

### `$getLocales` {#$getlocales}

```ts
() => Locale[]
```

所有已設定的語系及其中繼資料。

語系物件上的自訂屬性會原樣回傳；請透過對 `Locale` 進行[模組擴充](/zh-TW/api/module-options#locales)來為它們加上型別。

### `$defaultLocale` {#$defaultlocale}

```ts
() => string | undefined
```

已設定的預設語系代碼。

### `$getI18nConfig` {#$geti18nconfig}

```ts
() => ResolvedI18nConfig
```

執行階段所看到的、已解析的模組設定。

此值包含[執行階段覆寫](/zh-TW/guide/runtime-overrides)（`defaultLocale`、`fallbackLocale`、停用的語系）。

```ts
const { strategy, localeCookie } = useNuxtApp().$getI18nConfig()
```

## 翻譯 {#translation}

### `$t` {#$t}

```ts
TranslationFn<CleanTranslation>
```

翻譯一個鍵，並將 `params` 插入其中。當鍵不存在時回傳 `defaultValue`，若未提供預設值則回傳鍵本身。

```ts
// { "welcome": "Welcome, {name}!" }
$t('welcome', { name: 'Ada' }) // 'Welcome, Ada!'
$t('missing.key', {}, 'Fallback') // 'Fallback'
```

指向巢狀物件的鍵會回傳該物件，而非字串。在範本中它會呈現為 `[object Object]`；請使用葉節點鍵。

### `$ts` {#$ts}

```ts
TranslationFn<string>
```

與 `$t` 相同，但一律回傳字串：值會經過 `toString()`，因此巢狀物件會變成 `'[object Object]'`。請將鍵指向葉節點。

### `$_t` {#$_t}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<CleanTranslation>
```

將 `$t` 綁定到特定路由，以便在目前頁面之外進行翻譯 — 例如在版面配置中呈現指向其他路由的連結。

```ts
const route = useRoute()
const t = useNuxtApp().$_t(route)
t('page.title')
```

### `$_ts` {#$_ts}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<string>
```

將 `$ts` 綁定到特定路由。請參閱 `$_t`。

### `$tc` {#$tc}

```ts
(key: TranslationKey, params: number | Params, defaultValue?: string) => string
```

帶複數處理的翻譯。`params` 可以是數量本身，或包含 `count` 的物件。

各形式以 `|` 分隔。使用內建規則時，非負整數的數量 `n` 會選擇第 `n` 個形式，超出時取最後一個形式；負數、小數或 `NaN` 的數量會使用最後一個形式。`{count}` 與其他參數會插入所選的形式中。

對於複數不依循數量的語言，請以 `=0 ` 作為範本開頭。此時第一個形式用於 0，其餘形式則依 [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) 類別，依 `zero, one, two, few, many, other` 的順序排列：

```json
{
  "apples": "=0 no apples | one apple | {count} apples",
  "files": "=0 no files | {count} one | {count} few | {count} many"
}
```

```ts
$tc('apples', 0) // 'no apples'
$tc('apples', 1) // 'one apple'
$tc('apples', 7) // '7 apples'

// In `uk` (categories `one, few, many, other`) the forms after the zero form follow those categories:
$tc('files', 21) // '21 one'
$tc('files', 22) // '22 few'
$tc('files', 25) // '25 many'
$tc('files', 2.5) // '2.5 many': no form for `other`, so the last one
```

- `=0 ` 只有在值的最開頭且帶有空格時才有效。`$t` 會將它顯示為文字：它屬於複數處理。
- 沒有專屬形式的類別會使用最後一個形式。負數或小數的數量也會使用最後一個形式。
- 它適用於任何語系：英文中為 `=0 none | one | {count} many`。
- 類別來自語系的 `iso`，否則使用其代碼。`Intl` 不認得的代碼會回退至索引規則，標記仍會被移除，因此結果永遠不會因機器而異。
- `<i18n-t :plural>` 遵循相同的規則。自訂的 [`plural`](/zh-TW/api/module-options#plural) 或 `customPluralRule` 會取得原始值（包含標記），並自行決定；`plural` 回傳 `null` 時會將呼叫交還給內建規則，而內建規則會遵循標記。

沒有標記時，範本會維持使用索引規則，只有一個例外，且只能以一種方式解讀：一個沒有佔位符的零形式，接著每個類別一個形式，且在多個數量共用的每個形式中都含有 `{count}`（在 `uk` 中為 `no files | {count} one | {count} few | {count} many`）。

若要使用自己的規則，請設定 [`plural`](/zh-TW/api/module-options#plural)。

```ts
// { "apples": "no apples | one apple | {count} apples" }
$tc('apples', 0) // 'no apples'
$tc('apples', 10) // '10 apples'
$tc('cart', { count: 2, name: 'Ada' }) // count and params in one object
```

第三個引數是 `defaultValue`，而非參數。

### `$has` {#$has}

```ts
(key: string) => boolean
```

某個鍵在目前語系中是否能解析。可用它來依選擇性文案進行分支，而不是呈現原始鍵。與 `$t` 相同，在相同語系的頁面轉場期間，它也看得到正在離開之頁面的鍵。

```ts
if ($has('promo.banner')) show.value = true
```

## 格式化 {#formatting}

### `$tn` {#$tn}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

以目前語系使用 `Intl.NumberFormat` 格式化數字。鍵會從設定中選擇具名格式。

具名格式來自 [`numberFormats`](/zh-TW/api/module-options#numberformats)。

```ts
$tn(1234.5, { style: 'currency', currency: 'EUR' }) // '1.234,50 €' in de
$tn(1000, 'currency') // named format
$tn(1000, 'currency', 'de') // named format in another locale
```

### `$td` {#$td}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

以目前語系使用 `Intl.DateTimeFormat` 格式化日期。鍵會從設定中選擇具名格式。

具名格式來自 [`datetimeFormats`](/zh-TW/api/module-options#datetimeformats)。

```ts
$td(new Date(), { dateStyle: 'long' })
$td(post.createdAt, 'short')
```

### `$tdr` {#$tdr}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

使用 `Intl.RelativeTimeFormat` 將日期格式化為相對時間（「3 天前」）。

```ts
$tdr(Date.now() - 5 * 60_000) // '5 minutes ago' in en
```

## 切換與連結 {#switching-and-links}

### `$switchLocale` {#$switchlocale}

```ts
(locale: string) => Promise<boolean>
```

導覽至目前頁面的另一個語系版本。在 `no_prefix` 與 hash 模式下，它會在導覽前先載入該語系的翻譯；在 `no_prefix` 下，路由會就地取代（不會新增歷史紀錄）。未知的語系會被忽略。
此呼叫為非同步：請 `await` 它，以便在導覽後執行程式碼。當該語系的字典已生效時，它會以 `true` 解析；未生效時則為 `false`：可能是 chunk 載入失敗（目前的字典會保留；再次呼叫即可重試），或是有更新的切換勝出。

```ts
await $switchLocale('de')
```

### `$switchLocalePath` {#$switchlocalepath}

```ts
(locale: string) => string
```

目前頁面在另一個語系中的路徑，不會進行導覽。

```vue
<NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
```

### `$switchLocaleRoute` {#$switchlocaleroute}

```ts
(locale: string) => RouteLocationRaw
```

目前頁面在另一個語系中的路由物件，不會進行導覽；若該語系有自己的 `baseUrl`，則為 URL 字串。在 `trailingSlash` 下，物件會依規則帶有 `path` 與 `fullPath`，`query` 與 `hash` 則維持原樣，而 `router.push` 或連結會保留它們。

### `$switchRoute` {#$switchroute}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => Promise<void>
```

導覽至另一個路由，保留目前語系或切換至 `toLocale`。與 `$switchLocale` 一樣是非同步的。

```ts
$switchRoute('/about') // active locale
$switchRoute({ name: 'about' }, 'de') // switch to de
```

### `$localePath` {#$localepath}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => string
```

以指定語系（或目前語系）解析路徑。帶有 `http(s):`、`mailto:` 或 `tel:` 協定的字串會原樣回傳：請勿未經檢查就將使用者輸入作為連結目標。

字串路徑會被解讀為它所顯示的頁面，因此語系的自訂路徑也會被套用。

```ts
$localePath('/about') // '/about' in en, '/de/ueber-uns' in de with localeRoutes
$localePath({ name: 'about' }, 'fr') // '/fr/about'
```

### `$localeRoute` {#$localeroute}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => RouteLocationResolved
```

以指定語系（或目前語系）解析路由。回傳一般物件，可安全地保存在狀態中。當參數需要跳脫時，它會帶有 `path`、`fullPath`、`query` 與 `hash`，但沒有 `name` 或 `params`：由路徑提供路由器編碼後的 URL。對於位於另一個網域的語系，`path` 與 `fullPath` 是絕對路徑，路由器無法接受：這類連結請透過 `<i18n-link>` 或 `$localePath`。

### `$getRouteName` {#$getroutename}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric, locale?: string) => string
```

去除語系前綴的路由名稱 — 即翻譯所使用的鍵名。

```ts
$getRouteName() // 'about' on /de/about
```

## 頁面設定 {#page-config}

### `$defineI18nRoute` {#$definei18nroute}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

從元件內部註冊每個頁面的語系設定與翻譯。會合併到目前語系，並在語系變更時重新套用。

請在頁面的 `<script setup>` 中呼叫它，且一律從 `useNuxtApp()` 解構取得。建置時會從呼叫中讀取 `locales`、`localeRoutes` 與 `disableMeta`；在執行階段只有 `locales` 有作用（內嵌翻譯會合併到目前語系）。完整規則：[頁面設定](/zh-TW/guide/per-component-translations)。

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: { en: '/about', de: '/ueber-uns' },
})
</script>
```

### `$setI18nRouteParams` {#$seti18nrouteparams}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

為目前路由設定各語系的參數，讓動態區段可以依語言而不同。請在 SSR 期間、head 呈現之前呼叫它。

當導覽至另一個路徑完成時，參數會被清除，包括從 `/news/1` 到 `/news/4` 這種保留路由名稱的情況。詳情：[在地化路徑](/zh-TW/guide/custom-locale-routes)。

```ts
$setI18nRouteParams({
  en: { slug: 'my-post' },
  de: { slug: 'mein-beitrag' },
})
```

## 執行階段翻譯 {#runtime-translations}

### `$mergeTranslations` {#$mergetranslations}

```ts
(newTranslations: Translations) => void
```

在執行階段將翻譯合併到目前語系，覆寫已載入的內容。

會深度合併到目前語系的當前頁面 chunk；未提及的鍵會保留。

```ts
$mergeTranslations({ banner: { title: 'Sale' } })
```

### `$setTranslation` {#$settranslation}

```ts
(key: string, value: unknown) => void
```

取代目前字典中 `key` 的值。這是取代而非合併 — 當既有的同層鍵需要保留時，請使用 `$mergeTranslations`。

```ts
$setTranslation('banner', { title: 'Sale' }) // drops other keys under banner
$setTranslation('banner.title', 'Sale') // dotted path
```

### `$loadPageTranslations` {#$loadpagetranslations}

```ts
(locale: string, routeName: string, translations: Translations) => Promise<void>
```

在執行階段為頁面載入翻譯，適用於建置時無法得知鍵的內容。

會合併到記憶體中的 `(locale, routeName)` chunk，當該 chunk 生效時畫面就會更新。這裡不會擷取任何 payload：對於尚未載入的頁面，翻譯會等待，而當其檔案載入時，這些翻譯會覆蓋在檔案內容之上。

```ts
await $loadPageTranslations('en', 'about', { title: 'About us' })
```

### `$resolveTranslations` {#$resolvetranslations}

```ts
() => Translations
```

目前語系與路由在記憶體中的所有翻譯，以樹狀結構呈現。這是 `$t()` 此刻能解析之內容的唯讀檢視。

請將結果視為唯讀。

### `$setMissingHandler` {#$setmissinghandler}

```ts
(handler: MissingHandler | null) => void
```

安裝一個回呼，每遇到無法解析的鍵就會呼叫。傳入 `null` 即可移除。

處理函式會取代開發環境的警告執行。

```ts
$setMissingHandler((locale, key, routeName) => {
  console.error(`[i18n] missing ${key} in ${locale} (${routeName})`)
})
```

### `$clearCache` {#$clearcache}

```ts
() => void
```

捨棄所有已快取的翻譯 chunk，並重新載入目前頁面的字典。在新翻譯抵達之前，頁面會繼續顯示目前的翻譯。開發環境的 HMR 會在每次翻譯檔案變更時呼叫它。

```ts
const { clearCache } = useI18n()
clearCache()
```

重新載入失敗時會保留目前的字典。
