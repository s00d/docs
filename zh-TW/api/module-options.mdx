本頁列出 `nuxt.config` 中 `i18n` 物件的每個鍵。可使用表格查詢型別或預設值，並參閱下方的詳細說明以取得範例與注意事項。型別、預設值與說明皆由 [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts) 中的 `ModuleOptions` 介面產生。

```ts nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
    ],
    defaultLocale: 'en',
  },
})
```

巢狀選項會以點分隔路徑表示：`translationPayloads.mode` 即 `translationPayloads` 的 `mode` 鍵。

## Locale 與路由 {#locales-and-routing}

有哪些語言，以及它們如何出現在 URL 中。

| 選項 | 型別 | 預設值 | 說明 |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | 支援的 locale 清單。每個項目定義一個 locale 代碼以及選用的中繼資料（ISO、方向、顯示名稱等）。 |
| `strategy` | `Strategies` | `'prefix_except_default'` | locale 前綴的 URL 路由策略。- `'no_prefix'` — URL 中沒有 locale；locale 儲存在 cookie 中。- `'prefix_except_default'` — 除了預設 locale 之外，所有 locale 都加上前綴。- `'prefix'` — 一律加上前綴，包含預設 locale。- `'prefix_and_default'` — 與 `prefix` 相同，但預設 locale 也可以不帶前綴存取。 |
| `defaultLocale` | `string` | `'en'` | 無法從 URL 或使用者偏好判斷 locale 時所使用的 locale。它不是翻譯的 fallback：若需要，請設定 `fallbackLocale`。 |
| `localeCookie` | `string \| null` | `null` | 用於在不同工作階段間保存使用者 locale 偏好的 cookie 名稱。設為 `null` 可停用以 cookie 保存。在 `no_prefix` 策略下若未提供，會自動設為 `'user-locale'`；在 `i18n` 設定區塊中明確設為 `null`，則在該策略下也會保持關閉。 |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `{}` | 全域的路由層級 locale 設定。可在不修改元件的情況下，限制或自訂特定頁面的 locale 路由。- `false` — 將該路由排除在在地化之外。- `Record<LocaleCode, string>` — 每個 locale 的自訂路徑。 |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | 用於比對 URL 區段中 locale 代碼的自訂正規表示式（或其字串來源）。`locales` 中的每個 locale 代碼都必須完整符合該模式（不含旗標），否則建置會失敗。 |
| `noPrefixRedirect` | `boolean` | `false` | 適用於 `no_prefix` 策略：當預設 locale 對某頁面有自訂路徑（`localeRoutes` / `globalLocaleRoutes`）時，將該頁面的原始路徑重新導向至訪客 locale 的自訂路徑，否則導向預設 locale 的自訂路徑（例如 `/about` → `/about-us`）。沒有自己自訂路徑的 locale 會停留在原始路徑。含動態區段的頁面不會被重新導向。 |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | 要排除在 i18n 路由之外的路徑：字串為路徑前綴（`/admin` 涵蓋 `/admin/x`）或 `*` / `?` glob；RegExp 則會對路徑進行測試。符合的頁面不會產生 locale 變體、不會有 locale 重新導向或 404，且會從預先渲染中移除；它們仍會以翻譯渲染。`/api`、`/_nuxt`、`/__*`、翻譯路由以及常見的靜態檔案（sitemap、robots.txt、favicon、依副檔名判斷的資源）一律排除。 |
| `routeLocales` | `Record<string, string[]>` | — | 每個路由的 locale 限制，於建置時從 `$defineI18nRoute()` 呼叫中擷取。將路由路徑（例如 `'/about'`）對應至允許的 locale 代碼陣列。未列出的路由沒有限制（允許所有 locale）。 |

## 翻譯 {#translations}

翻譯檔的位置，以及鍵如何解析。

| 選項 | 型別 | 預設值 | 說明 |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | 包含翻譯 JSON 檔之目錄的路徑，相對於專案根目錄。 |
| `disableWatcher` | `boolean` | `false` | 停用在開發模式下自動建立缺少翻譯檔的檔案監看器。 |
| `routesLocaleLinks` | `{ [key: string]: string }` | `{}` | 將路由名稱對應到其他路由名稱，以共用相同的翻譯檔。例如，`{ 'about-us': 'about' }` 表示 `about-us` 頁面會使用 `about` 頁面的翻譯，而不是它自己的翻譯。 |
| `plural` | `PluralFunc` | ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)`` | 自訂複數處理函式。接收 `(key, count, params, locale, getter)`，應以字串回傳選定的複數形式，或回傳 `null`/`undefined` 以退回內建的 `defaultPlural` 邏輯（因此你可以只覆寫部分 locale）。在 Nuxt 模組中，此函式會以 `.toString()` 序列化至 `.nuxt/i18n.plural.mjs`——它必須是自給自足的（不可有 import／外部作用域）。**不**支援檔案路徑字串。 |
| `disablePageLocales` | `boolean` | `false` | 停用每頁翻譯檔。當為 `true` 時，只會載入全域翻譯（`{locale}.json`）；頁面專屬檔案（`pages/{page}/{locale}.json`）不會被產生或載入。 |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | 全域 fallback locale 代碼。某個 locale 中缺少的鍵會從此 locale 取得（在建置或載入每個 payload 時合併進去）；若未設定，缺少的鍵會直接顯示為鍵本身。 |

## Payload 與快取 {#payloads-and-caching}

翻譯如何送達瀏覽器。[效能](/zh-TW/guide/performance)說明了這些選項在執行階段會改變什麼。

| 選項 | 型別 | 預設值 | 說明 |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | 在 Nitro 全域中介軟體中預先載入首頁翻譯（僅限伺服器，私有設定）。 |
| `apiBaseUrl` | `string` | `'_locales'` | 翻譯 API 路由的基礎 URL 路徑區段（用於 SSR/SSG 資料擷取）。也可以透過 `NUXT_I18N_APP_BASE_URL` 環境變數設定。 |
| `apiBaseClientHost` | `string` | `undefined` | 覆寫用戶端翻譯擷取請求所使用的主機。當用戶端透過與 Nuxt 所見不同的主機名稱存取伺服器時很有用。也可以透過 `NUXT_I18N_APP_BASE_CLIENT_HOST` 環境變數設定。 |
| `apiBaseServerHost` | `string` | `undefined` | 覆寫伺服器端翻譯擷取請求所使用的主機。在伺服器透過內部主機名稱存取自身的容器／微服務架構中很有用。也可以透過 `NUXT_I18N_APP_BASE_SERVER_HOST` 環境變數設定。 |
| `translationPayloads` | `TranslationPayloadOptions` | — | 控制翻譯 payload 的輸出方式（Node 伺服器：`public/<apiBaseUrl>`；Edge／函式／inline：Nitro `serverAssets`）。- **Node 伺服器**（`node-server`、`node-cluster`、磁碟 `serveStatic`）：`serverAssets` 代表透過 `readFile` 從 `public/` 進行本機 SSR（不使用 Rollup `raw:`）。- **Edge、函式 preset 與 `serveStatic: "inline"`**（`vercel`、`netlify`、`aws-lambda`、winterjs……）：`serverAssets` 會註冊 Nitro `serverAssets`（`assets:i18n`），因為 SSR 無法在磁碟上存取 `public/`。不會強制建立公開副本——若需要 CDN／靜態檔案，請設定 `publicAssets: true`。一般的一體式架構請保留預設值。大型 Edge 目錄請優先使用 `mode: 'source'`。對於以 CDN 為後端的部署，請停用本機輸出並設定 `apiBaseClientHost` / `apiBaseServerHost`。 |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | 翻譯 payload 策略。- `premerged`：建置時產生的 `{page}/{locale}/data.json` 矩陣（預設）- `source`：於執行階段合併的精簡來源檔（Edge／大型目錄建議使用） |
| `translationPayloads.serverAssets` | `boolean` | `true` | 本機 SSR payload：從磁碟提供 `public/` 的 Node 伺服器會讀取該樹狀結構（強制建立公開副本）；Edge、函式 preset 與 `serveStatic: "inline"` 則透過 Nitro `serverAssets` 嵌入。- **Node 伺服器**（preset 自行提供 `public/`，例如 `node-server`）：不使用 Nitro `serverAssets`（避免 Rollup `raw:`）。SSR 會以 `{page}/{locale}/data.json` 讀取 `public/<apiBaseUrl\|publicDir>`；當此值為 `true` 時，即使 `publicAssets` 為 false 也會強制建立公開副本。- **Edge、函式 preset 與 inline**（`nitro.node === false`，沒有磁碟 `serveStatic`，例如 `vercel` / `netlify` / `aws-lambda`，或 `serveStatic: "inline"`，例如 winterjs）：Nitro `serverAssets`（`assets:i18n`），佈局與 `mode` 相同。**不會**強制建立公開副本——若需要 CDN／靜態檔案，請設定 `publicAssets: true`。 |
| `translationPayloads.serverHandler` | `boolean` | `true` | 在 `/{apiBaseUrl}/:page/:locale/data.json` 註冊內建的伺服器路由。當翻譯 payload 由外部主機／CDN 提供時，請停用此選項。 |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | 將 payload 複製到 Nitro 公開輸出。premerged → 在 `apiBaseUrl` 下的 `{page}/{locale}/data.json`；source → 精簡樹狀結構。當 SSR 讀取 `public/` 時（`node-server` 等），`serverAssets: true` 也會強制建立此副本。在 Edge／函式／`serveStatic: "inline"` preset 上，只有在此值為 `true` 時才會複製（SSR 使用 Nitro 嵌入）。 |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | 選擇啟用以 Nitro 預先渲染 `/{apiBaseUrl}/.../data.json`。當 premerged 的 `publicAssets` 已寫出這些檔案時，通常是多餘的。 |
| `translationPayloads.publicDir` | `string` | — | 相對於 Nitro 公開根目錄的公開輸出資料夾。預設為 `apiBaseUrl`（`_locales`），因此靜態檔案會與用戶端擷取的 URL（`/{apiBaseUrl}/{page}/{locale}/data.json`）一致。 |
| `translationPayloads.rootDelta` | `boolean` | `true` | 每個 locale 寫出一個根檔案，而每個頁面檔案只寫入與其不同的部分。用戶端與 SSR 會將它們合併；在任何讀取檔案的地方，完整的區塊仍然可用。`false` 會在每個頁面檔案中保留完整的字典。僅適用於 `premerged`，且在 `disablePageLocales` 時關閉。 |
| `translationPayloads.warnFileCount` | `number` | `500` | 當產生的 payload 檔案數超過此門檻時，於建置期間發出警告。 |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | 當產生的 payload 總大小（位元組）超過此門檻時，於建置期間發出警告。 |

## SEO {#seo}

為每個在地化頁面產生的 meta 標籤。

| 選項 | 型別 | 預設值 | 說明 |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | 自動產生 SEO meta 標籤（`hreflang`、`canonical`、`og:url`、`og:locale`）。 |
| `metaBaseUrl` | `string` | `undefined` | SEO meta 標籤（canonical、og:url、hreflang）的基礎 URL。- 具體的 URL 字串（例如 `'https://example.com'`）— 直接使用（最高優先順序）。- `undefined` — 若有 `nuxt-site-config` 模組，則退回使用其 `site.url`，否則使用目前請求的來源（伺服器上為 `useRequestURL().origin`，用戶端為 `window.location.origin`）。 |
| `metaTrustForwardedHost` | `boolean` | `true` | 解析 meta 標籤的基礎 URL 時信任 `X-Forwarded-Host` 標頭。當應用程式在會將此標頭設為實際面向用戶端之主機名稱的反向代理（nginx、Cloudflare、AWS ALB 等）後方執行時啟用。 |
| `metaTrustForwardedProto` | `boolean` | `true` | 解析 meta 標籤的協定時信任 `X-Forwarded-Proto` 標頭。當應用程式在終止 TLS 的代理後方執行時啟用，如此即使應用程式本身監聽 HTTP，canonical URL 仍會使用 `https://`。 |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | 在 canonical 與 `og:url` meta 標籤中保留的查詢參數名稱清單。不在此清單中的參數會從 canonical URL 中移除。 |

## 偵測與重新導向 {#detection-and-redirects}

為尚未選擇 locale 的訪客選擇 locale。

| 選項 | 型別 | 預設值 | 說明 |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | 啟用自動 locale 重新導向（伺服器外掛與用戶端路由中介軟體）。當為 `true` 時，前綴策略會將未帶前綴的 URL 重新導向至其在地化形式。locale 來自應用程式狀態、cookie，或在 `autoDetectPath` 允許時來自 `Accept-Language`，否則使用預設值。在 `no_prefix` 下，偵測永遠不會改變 URL（自訂路徑請參閱 `noPrefixRedirect`）。 |
| `autoDetectLanguage` | `boolean` | `true` | 從 `Accept-Language` HTTP 標頭自動偵測使用者偏好的語言。與 `autoDetectPath` 搭配使用，以決定何時進行偵測。 |
| `autoDetectPath` | `string` | `'/'` | cookie／Accept-Language 偏好重新導向可執行的位置（當 `redirects` 啟用時）。- `'/'` — 僅 `/`（預設 locale 的深層連結仍可存取；預設）- `'no_prefix'` — 僅限沒有 locale 前綴的路徑 - `'*'` — 所有路徑，包含改寫明確的 locale 前綴（例如當 cookie 偏好 `de` 時，`/fr/about` → `/de/about`）- 任何其他字串 — 該路徑，忽略結尾斜線（例如 `'/welcome'`）在 `prefix` 下，允許路徑以外的未帶前綴 URL 仍會重新導向至預設 locale 的形式（`/about` → `/en/about`）。在 `prefix_except_default` 下帶有前綴的預設 locale（`/en`）會是 404，而非重新導向。 |

## 註冊 {#registration}

模組中可以關閉的部分。

| 選項 | 型別 | 預設值 | 說明 |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | 在執行階段提供 `$defineI18nRoute()`。無論如何，建置都會讀取頁面中的 `$defineI18nRoute()` 呼叫。 |
| `plugin` | `boolean` | `true` | 註冊提供 `$t()`、`$tc()`、`$getLocale()`、`$switchLocale()` 與其他執行階段輔助函式的核心 i18n 外掛。 |
| `hooks` | `boolean` | `true` | 在載入與導覽時呼叫 `i18n:register` app hook，讓外掛可以加入翻譯。 |
| `components` | `boolean` | `true` | 註冊內建的 i18n 元件（`<i18n-link>`、`<i18n-switcher>`、`<i18n-t>`、`<i18n-group>`）。設為 `false` 可停用自動元件註冊（例如你沒有使用它們，並希望減少模組占用）。 |
| `types` | `boolean` | `true` | 根據預設 locale 檔案中的翻譯鍵，為 `useI18n`、`$t` 與相關輔助函式產生 TypeScript 型別宣告。 |
| `debug` | `boolean` | `false` | 為 locale 偵測、路由產生與翻譯載入啟用詳細的除錯記錄。 |

## 其他 {#other}

| 選項 | 型別 | 預設值 | 說明 |
| --- | --- | --- | --- |
| `trustForwardedHost` | `boolean` | `false` | 從 `X-Forwarded-Host` 而非 `Host` 選擇請求的網域（`locales[].baseUrl`）。只有在會覆寫該標頭的代理後方才啟用。 |
| `hreflangBaseLanguage` | `boolean` | `false` | 另外輸出由每個 locale 的 `iso` 衍生的純語言 `hreflang`（例如 `es-ES` → 另外輸出 `es`）。`locales` 中第一個地區性 locale 會取得該語言的純語言標籤。永遠不會使用路由 `code`——只使用 `iso \|\| code`。 |
| `additionalTranslationDirs` | `string[]` | `[]` | 額外的目錄（相對於專案根目錄／每個 Nuxt layer 根目錄），其頂層的 `{locale}.json` 檔會在 `translationDir` 之前深度合併至全域字典。合併順序：依陣列順序處理每個項目（跨 layer），接著是 `translationDir`（衝突時優先）。只會讀取根層級的 `{locale}.json` 檔——這些目錄下的 `pages/` 會被忽略。範例：`translationDir: 'frontend'`、`additionalTranslationDirs: ['common']` → 先 `common/en.json` 再 `frontend/en.json`。 |
| `vueDevtools` | `boolean` | `true` | 在開發模式下註冊 Vue DevTools 檢查器與時間軸（瀏覽器擴充功能）。與 Nuxt DevTools 自訂分頁分開。 |
| `trailingSlash` | `'append' \| 'remove'` | `undefined (inherit from Nuxt)` | `$localePath` / `$switchLocalePath` 的結尾斜線（與 NuxtLink 一致）。未設定時預設為 `experimental.defaults.nuxtLink.trailingSlash`。明確設定可為 i18n 路徑輔助函式覆寫 Nuxt 的連結預設值。 |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | 加在在地化路由名稱前的前綴（例如 `'localized-index'`）。內部用於區分原始路由與產生的 locale 變體。 |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | 逐路由停用 meta 標籤。將路由名稱或路徑對應至 `true`（停用所有 meta）或應停用 meta 的 locale 代碼陣列。建置時在 `$defineI18nRoute()` 呼叫中找到的項目會被加入其中。 |
| `missingWarn` | `boolean` | `true` | 當翻譯鍵缺少時顯示主控台警告（開發建置，於瀏覽器中）。 |
| `hmr` | `boolean` | `true` | 在開發模式下為翻譯檔啟用熱模組替換。當為 `true` 時，JSON 翻譯檔的變更會觸發自動重新載入，而不需整頁重新整理。 |
| `cacheMaxSize` | `number` | `0` | 記憶體內翻譯快取的最大項目數。擷取快取與伺服器快取會淘汰最近最少使用的項目；瀏覽器的字典對應表則淘汰最舊的項目（FIFO）。`0` 表示瀏覽器中無上限；此時伺服器快取最多保留 1000 個項目，因此指定虛構頁面的請求 URL 無法使伺服器記憶體增長。 |
| `cacheTtl` | `number` | `0` | 擷取快取與伺服器翻譯快取的存活時間（秒），從項目儲存時起算（讀取不會延長），因此來自 `apiBaseServerHost` 的資料至少會以此頻率重新整理。瀏覽器中作用中的字典不會因此到期。`0` 表示項目永不到期。 |
| `cacheStorage` | `string` | — | 多個伺服器執行個體共用作為字典快取的 Nitro storage 掛載名稱（`nitro.storage`，例如 `'redis'`），會在程序內快取之後、來源之前讀取。主要在使用 `apiBaseServerHost` 時有效益：從後端只擷取一次，而非每個執行個體各一次。項目以建置作為鍵，並在 `cacheTtl` 後到期，若其為 `0` 則在一天後到期。在開發模式與預先渲染中關閉。storage 失敗時會退回來源。未設定：沒有共用快取。 |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | 每個 locale 的具名數字格式（與 Vue I18n 相容）。可使用 `$tn(1000, 'currency')` 形式的呼叫。 |
| `timeZone` | `string` | `the runtime's zone` | `$td` 與 `<i18n-t date>` 的 IANA 時區（`Europe/Berlin`）。設定後可在伺服器與每個瀏覽器中渲染相同的日期；具名格式自身的 `timeZone` 優先。 |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | 每個 locale 的具名日期時間格式（與 Vue I18n 相容的 `datetimeFormats`）。可使用 `$td(date, 'short')` 形式的呼叫。 |
| `httpCacheDuration` | `number` | `31536000` | `/{apiBaseUrl}/:page/:locale/data.json` 的 HTTP `Cache-Control` max-age（秒）。只有在 `dateBuild` 破壞 URL 快取（`?v=...`）時才會完整套用，這是預設行為：此時回應為 `private, max-age=…, immutable`：瀏覽器會固定保存它，而忽略查詢字串的 CDN 則不會（搭配 `httpCacheControl: false` 時為 `public`）。- `dateBuild: 0`/`''` — URL 是穩定的，因此*不會*採用此期間；回應會改為 `public, max-age=0, must-revalidate`。在不變的 URL 上設定很長的 `max-age`，會讓瀏覽器固定保存它第一次看到的 payload。- `0` — 完全不設定 `Cache-Control`（在本機除錯時很有用）- 開發模式（`import.meta.dev`）下不套用，以免瀏覽器快取干擾 HMR - 只會作用於透過 Nitro 提供的回應。複製到 `public/` 並由託管平台提供的 payload 會使用該平台的標頭——請參閱效能指南。類似於 `@nuxtjs/i18n` 的實驗性 `httpCacheDuration`（v10.2.0），但以明確的回應標頭實作，而非 Nitro `defineCachedEventHandler` 的 maxAge。 |
| `httpCacheControl` | `string \| false` | `'public, max-age=60'` | 由主機或路徑全域規則回應之 payload 檔案的 `Cache-Control`，這些無法看到 `?v=`。在 Node 伺服器上，對目前 `?v=` 的回應會在 `httpCacheDuration` 期間被固定保存，其他則會重新驗證；使用 `source`、`cacheTtl` 或 `apiBaseServerHost` 時，字典會在未重新建置的情況下變更，因此每個回應都會使用此標頭。`false` 會讓每個檔案保持 `max-age=0, must-revalidate`。 |
| `dateBuild` | `string \| number` | — | 用於翻譯請求快取破壞的值（`?v=...`）。未提供時，模組會使用翻譯檔的雜湊值，因此只有在翻譯變更時值才會改變（無法計算雜湊時使用 `Date.now()`）。`0` 或 `''` 會關閉快取破壞。設定一個穩定的值（git SHA、建置編號）可自行固定它。在就地取代字典之後，`NUXT_I18N_DATE_BUILD` 或 `runtimeConfig.public.i18nRuntime.dateBuild` 會在執行階段取代它：已固定的 URL 會被捨棄，無需重新建置。 |
| `experimental` | `Record<string, unknown>` | — | 實驗性／不穩定選項的集合。其內容可能在次要版本之間變更或移除，恕不另行通知。 |

## 選項詳細說明 {#option-details}

除了表格內容外沒有其他補充的選項，不會在此重複列出。

### Locale 與 URL {#locales-and-urls}

#### `locales` {#locales}

**型別** `Locale[]` · **預設值** `[]`

支援的 locale 清單。
每個項目定義一個 locale 代碼以及選用的中繼資料（ISO、方向、顯示名稱等）。

每個項目都是一個 `Locale` 物件：

| 屬性 | 型別 | 說明 |
| --- | --- | --- |
| `code` | `string` | **必填。** URL 區段與檔案名稱（`en`、`de-at`）。 |
| `iso` | `string` | 用於 `<html lang>`、`hreflang`、複數與 `$tn` / `$td` / `$tdr` 的 BCP-47 標籤（`en-US`）。 |
| `displayName` | `string` | `<i18n-switcher>` 與 `$getLocaleName()` 中的標籤。 |
| `dir` | `'ltr' \| 'rtl' \| 'auto'` | `<html dir>`。未設定時，已知的 RTL 語言會取得 `rtl`，其他所有 locale 則不會有此屬性。請參閱 [SEO](/zh-TW/guide/seo#text-direction)。 |
| `disabled` | `boolean` | 從路由、payload 與切換中排除。其前綴會是 404，且指向它的連結會停留在目前頁面。 |
| `fallbackLocale` | `string` | 此 locale 的 fallback；會覆寫全域的 `fallbackLocale`。 |
| `seo` | `boolean` | `false` 會將此 locale 排除在 `hreflang` 與 `og:locale:alternate` 之外。 |
| `og` | `string` | `og:locale` 值（`ar_AE`）；預設：由 `iso` 轉換而來。 |
| `baseUrl` | `string` | 此 locale 自己的網域：由同一個建置提供，且從其他網域指向它的連結為絕對網址。 |
| `baseDefault` | `boolean` | 搭配 `baseUrl`：作為其主機的預設 locale，指向它的連結不帶 `/<code>` 前綴（`prefix` 會保留前綴）。 |

其他屬性會被保留，並由 `$getLocales()` 回傳。可透過擴充 `Locale` 為它們定義型別：

```ts
// i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
  }
}
export {}
```

本模組會提升 `@i18n-micro/types`，因此在 pnpm 下無需安裝該套件即可運作。

#### `defaultLocale` {#defaultlocale}

**型別** `string` · **預設值** `'en'`

無法從 URL 或使用者偏好判斷 locale 時所使用的 locale。
它不是翻譯的 fallback：若需要，請設定 `fallbackLocale`。

#### `strategy` {#strategy}

**型別** `Strategies` · **預設值** `'prefix_except_default'`

locale 前綴的 URL 路由策略。

- `'no_prefix'` — URL 中沒有 locale；locale 儲存在 cookie 中。
- `'prefix_except_default'` — 除了預設 locale 之外，所有 locale 都加上前綴。
- `'prefix'` — 一律加上前綴，包含預設 locale。
- `'prefix_and_default'` — 與 `prefix` 相同，但預設 locale 也可以不帶前綴存取。

各策略的 URL 與重新導向：[路由策略](/zh-TW/guide/strategy)。

#### `globalLocaleRoutes` {#globallocaleroutes}

**型別** `GlobalLocaleRoutes` · **預設值** `{}`

全域的路由層級 locale 設定。
可在不修改元件的情況下，限制或自訂特定頁面的 locale 路由。

- `false` — 將該路由排除在在地化之外。
- `Record<LocaleCode, string>` — 每個 locale 的自訂路徑。

鍵為路由名稱或路徑。通常會在每個頁面以 [`$defineI18nRoute`](/zh-TW/guide/per-component-translations) 設定。

```ts
globalLocaleRoutes: {
  about: { en: '/about-us', de: '/ueber-uns' },
  'admin-dashboard': false, // not localized
}
```

詳細說明、動態區段與 `pages:extend` 路由：[在地化路徑](/zh-TW/guide/custom-locale-routes)。

#### `routeLocales` {#routelocales}

**型別** `Record<string, string[]>` · **預設值** —

每個路由的 locale 限制，於建置時從 `$defineI18nRoute()` 呼叫中擷取。
將路由路徑（例如 `'/about'`）對應至允許的 locale 代碼陣列。
未列出的路由沒有限制（允許所有 locale）。

#### `routeDisableMeta` {#routedisablemeta}

**型別** `Record<string, boolean \| string[]>` · **預設值** —

逐路由停用 meta 標籤。將路由名稱或路徑對應至 `true`（停用所有 meta）或應停用 meta 的
locale 代碼陣列。建置時在 `$defineI18nRoute()` 呼叫中找到的項目會被加入其中。

#### `customRegexMatcher` {#customregexmatcher}

**型別** `string \| RegExp` · **預設值** `undefined (uses built-in pattern based on locale codes)`

用於比對 URL 區段中 locale 代碼的自訂正規表示式（或其字串來源）。
`locales` 中的每個 locale 代碼都必須完整符合該模式（不含旗標），否則建置會失敗。

```ts
customRegexMatcher: '[a-z]{2}-[a-z]{2}', // en-us, de-at
```

#### `excludePatterns` {#excludepatterns}

**型別** `(string \| RegExp)[]` · **預設值** `undefined`

要排除在 i18n 路由之外的路徑：字串為路徑前綴（`/admin` 涵蓋 `/admin/x`）
或 `*` / `?` glob；RegExp 則會對路徑進行測試。符合的頁面不會產生 locale
變體、不會有 locale 重新導向或 404，且會從預先渲染中移除；它們仍會以
翻譯渲染。`/api`、`/_nuxt`、`/__*`、翻譯路由以及常見的靜態檔案
（sitemap、robots.txt、favicon、依副檔名判斷的資源）一律排除。

```ts
excludePatterns: ['/admin', '/docs/*', /^\/preview\//],
```

更多內容：[排除路徑](/zh-TW/guide/excluding-static-files)。

#### `localizedRouteNamePrefix` {#localizedroutenameprefix}

**型別** `string` · **預設值** `'localized-'`

加在在地化路由名稱前的前綴（例如 `'localized-index'`）。
內部用於區分原始路由與產生的 locale 變體。

#### `trailingSlash` {#trailingslash}

**型別** `'append' \| 'remove'` · **預設值** `undefined (inherit from Nuxt)`

`$localePath` / `$switchLocalePath` 的結尾斜線（與 NuxtLink 一致）。
未設定時預設為 `experimental.defaults.nuxtLink.trailingSlash`。
明確設定可為 i18n 路徑輔助函式覆寫 Nuxt 的連結預設值。

### 翻譯 {#translations}

#### `translationDir` {#translationdir}

**型別** `string` · **預設值** `'locales'`

包含翻譯 JSON 檔之目錄的路徑，相對於專案根目錄。

相對於每個 layer 的根目錄，而不是 `app/`（Nuxt 4 佈局請使用 `'app/locales'`）。檔案佈局：[翻譯檔](/zh-TW/guide/translations)。

#### `additionalTranslationDirs` {#additionaltranslationdirs}

**型別** `string[]` · **預設值** `[]`

額外的目錄（相對於專案根目錄／每個 Nuxt layer 根目錄），其頂層的
`{locale}.json` 檔會在 `translationDir` 之前深度合併至全域字典。

合併順序：依陣列順序處理每個項目（跨 layer），接著是 `translationDir`（衝突時優先）。
只會讀取根層級的 `{locale}.json` 檔——這些目錄下的 `pages/` 會被忽略。

範例：`translationDir: 'frontend'`、`additionalTranslationDirs: ['common']` → 先 `common/en.json` 再 `frontend/en.json`。

#### `disablePageLocales` {#disablepagelocales}

**型別** `boolean` · **預設值** `false`

停用每頁翻譯檔。
當為 `true` 時，只會載入全域翻譯（`{locale}.json`）；
頁面專屬檔案（`pages/{page}/{locale}.json`）不會被產生或載入。

#### `fallbackLocale` {#fallbacklocale}

**型別** `string` · **預設值** `undefined (no fallback; returns the raw key)`

全域 fallback locale 代碼。
某個 locale 中缺少的鍵會從此 locale 取得（在建置或載入每個 payload 時
合併進去）；若未設定，缺少的鍵會直接顯示為鍵本身。

#### `routesLocaleLinks` {#routeslocalelinks}

**型別** `{ [key: string]: string }` · **預設值** `{}`

將路由名稱對應到其他路由名稱，以共用相同的翻譯檔。
例如，`{ 'about-us': 'about' }` 表示 `about-us` 頁面會使用
`about` 頁面的翻譯，而不是它自己的翻譯。

```ts
routesLocaleLinks: { 'products-id': 'products' },
```

#### `plural` {#plural}

**型別** `PluralFunc` · **預設值** ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)``

自訂複數處理函式。
接收 `(key, count, params, locale, getter)`，應以字串回傳選定的
複數形式，或回傳 `null`/`undefined` 以退回內建的
`defaultPlural` 邏輯（因此你可以只覆寫部分 locale）。

在 Nuxt 模組中，此函式會以 `.toString()` 序列化至
`.nuxt/i18n.plural.mjs`——它必須是自給自足的（不可有 import／外部作用域）。
**不**支援檔案路徑字串。

內建規則及其 `=0 ` 標記的說明請參閱 [`$tc`](/zh-TW/api/methods#$tc)。你的函式會在它回應的情況下取代內建規則，接收保留任何標記的原始值，而回傳 `null` 則會將呼叫交還給內建規則。此函式接收 `(key, count, params, locale, getter)`；`getter(key)` 會回傳包含所有形式的原始字串。請將它寫成自給自足的 `function` 或箭頭函式運算式（不可使用方法簡寫、import 或外部變數）：

```ts
plural: function (key, count, params, locale, getter) {
  if (!locale.startsWith('en')) return null // built-in rule for other locales
  const forms = String(getter(key) ?? '').split('|').map((form) => form.trim())
  const index = count === 0 ? 0 : count === 1 ? 1 : 2
  return (forms[Math.min(index, forms.length - 1)] ?? '').replace('{count}', String(count))
},
```

```json
{ "apples": "no apples | one apple | {count} apples" }
```

#### `numberFormats` {#numberformats}

**型別** `Record<string, Record<string, Intl.NumberFormatOptions>>` · **預設值** —

每個 locale 的具名數字格式（與 Vue I18n 相容）。
可使用 `$tn(1000, 'currency')` 形式的呼叫。

由 [`$tn`](/zh-TW/api/methods#$tn) 使用。

#### `datetimeFormats` {#datetimeformats}

**型別** `Record<string, Record<string, Intl.DateTimeFormatOptions>>` · **預設值** —

每個 locale 的具名日期時間格式（與 Vue I18n 相容的 `datetimeFormats`）。
可使用 `$td(date, 'short')` 形式的呼叫。

由 [`$td`](/zh-TW/api/methods#$td) 使用。

#### `timeZone` {#timezone}

**型別** `string` · **預設值** `the runtime's zone`

`$td` 與 `<i18n-t date>` 的 IANA 時區（`Europe/Berlin`）。設定後可在伺服器與每個瀏覽器中
渲染相同的日期；具名格式自身的 `timeZone` 優先。

#### `disableWatcher` {#disablewatcher}

**型別** `boolean` · **預設值** `false`

停用在開發模式下自動建立缺少翻譯檔的檔案監看器。

#### `missingWarn` {#missingwarn}

**型別** `boolean` · **預設值** `true`

當翻譯鍵缺少時顯示主控台警告（開發建置，於瀏覽器中）。

若要改為回報缺少的鍵，請使用 [`$setMissingHandler`](/zh-TW/api/methods#$setmissinghandler)。

### Payload 與快取 {#payloads-and-caching}

#### `translationPayloads` {#translationpayloads}

**型別** `TranslationPayloadOptions` · **預設值** —

控制翻譯 payload 的輸出方式（Node 伺服器：`public/<apiBaseUrl>`；Edge／函式／inline：Nitro `serverAssets`）。

- **Node 伺服器**（`node-server`、`node-cluster`、磁碟 `serveStatic`）：`serverAssets` 代表透過 `readFile` 從 `public/` 進行本機 SSR（不使用 Rollup `raw:`）。
- **Edge、函式 preset 與 `serveStatic: "inline"`**（`vercel`、`netlify`、`aws-lambda`、winterjs……）：`serverAssets` 會註冊 Nitro `serverAssets`（`assets:i18n`），
  因為 SSR 無法在磁碟上存取 `public/`。不會強制建立公開副本——若需要 CDN／靜態檔案，請設定 `publicAssets: true`。

一般的一體式架構請保留預設值。大型 Edge 目錄請優先使用 `mode: 'source'`。
對於以 CDN 為後端的部署，請停用本機輸出並設定 `apiBaseClientHost` / `apiBaseServerHost`。

子選項列於 [Payload 與快取](#payloads-and-caching)表格中。哪種組合適合 Node、serverless、Edge、靜態託管或 CDN：[部署](/zh-TW/guide/deployment)。

#### `apiBaseUrl` {#apibaseurl}

**型別** `string` · **預設值** `'_locales'`

翻譯 API 路由的基礎 URL 路徑區段（用於 SSR/SSG 資料擷取）。
也可以透過 `NUXT_I18N_APP_BASE_URL` 環境變數設定。

Payload URL 為 `/{apiBaseUrl}/{page}/{locale}/data.json`。

#### `apiBaseClientHost` {#apibaseclienthost}

**型別** `string` · **預設值** `undefined`

覆寫用戶端翻譯擷取請求所使用的主機。
當用戶端透過與 Nuxt 所見不同的主機名稱存取伺服器時很有用。
也可以透過 `NUXT_I18N_APP_BASE_CLIENT_HOST` 環境變數設定。

#### `apiBaseServerHost` {#apibaseserverhost}

**型別** `string` · **預設值** `undefined`

覆寫伺服器端翻譯擷取請求所使用的主機。
在伺服器透過內部主機名稱存取自身的容器／微服務架構中很有用。
也可以透過 `NUXT_I18N_APP_BASE_SERVER_HOST` 環境變數設定。

主機必須提供與內建路由相同的 `/{apiBaseUrl}/{page}/{locale}/data.json` 回應。

#### `dateBuild` {#datebuild}

**型別** `string \| number` · **預設值** —

用於翻譯請求快取破壞的值（`?v=...`）。

未提供時，模組會使用翻譯檔的雜湊值，因此只有在翻譯變更時值才會改變
（無法計算雜湊時使用 `Date.now()`）。`0` 或 `''` 會關閉
快取破壞。設定一個穩定的值（git SHA、建置編號）可自行固定它。
在就地取代字典之後，`NUXT_I18N_DATE_BUILD` 或 `runtimeConfig.public.i18nRuntime.dateBuild` 會在執行階段取代它：
已固定的 URL 會被捨棄，無需重新建置。

#### `httpCacheDuration` {#httpcacheduration}

**型別** `number` · **預設值** `31536000`

`/{apiBaseUrl}/:page/:locale/data.json` 的 HTTP `Cache-Control` max-age（秒）。

只有在 `dateBuild` 破壞 URL 快取（`?v=...`）時才會完整套用，這是預設行為：
此時回應為 `private, max-age=…, immutable`：瀏覽器會固定保存它，而忽略查詢字串的 CDN 則不會
（搭配 `httpCacheControl: false` 時為 `public`）。

- `dateBuild: 0`/`''` — URL 是穩定的，因此*不會*採用此期間；
  回應會改為 `public, max-age=0, must-revalidate`。在不變的 URL 上設定很長的 `max-age`，
  會讓瀏覽器固定保存它第一次看到的 payload。

- `0` — 完全不設定 `Cache-Control`（在本機除錯時很有用）
- 開發模式（`import.meta.dev`）下不套用，以免瀏覽器快取干擾 HMR
- 只會作用於透過 Nitro 提供的回應。複製到 `public/` 並由託管平台提供的
  payload 會使用該平台的標頭——請參閱效能指南。

類似於 `@nuxtjs/i18n` 的實驗性 `httpCacheDuration`（v10.2.0），但以
明確的回應標頭實作，而非 Nitro `defineCachedEventHandler` 的 maxAge。

#### `cacheMaxSize` {#cachemaxsize}

**型別** `number` · **預設值** `0`

記憶體內翻譯快取的最大項目數。擷取快取與伺服器快取
會淘汰最近最少使用的項目；瀏覽器的字典對應表則淘汰最舊的項目（FIFO）。
`0` 表示瀏覽器中無上限；此時伺服器快取最多保留 1000 個項目，因此指定
虛構頁面的請求 URL 無法使伺服器記憶體增長。

#### `cacheTtl` {#cachettl}

**型別** `number` · **預設值** `0`

擷取快取與伺服器翻譯快取的存活時間（秒），從項目
儲存時起算（讀取不會延長），因此來自 `apiBaseServerHost` 的資料至少會以
此頻率重新整理。瀏覽器中作用中的字典不會因此到期。`0` 表示項目
永不到期。

兩者在執行階段會改變什麼：[效能](/zh-TW/guide/performance)。

#### `serverTranslationPreload` {#servertranslationpreload}

**型別** `boolean` · **預設值** `false`

在 Nitro 全域中介軟體中預先載入首頁翻譯（僅限伺服器，私有設定）。

### SEO {#seo}

#### `meta` {#meta}

**型別** `boolean` · **預設值** `true`

自動產生 SEO meta 標籤（`hreflang`、`canonical`、`og:url`、`og:locale`）。

逐頁覆寫：[`useI18nHead`](/zh-TW/composables/useI18nHead)。其他所有內容：[SEO](/zh-TW/guide/seo)。

#### `metaBaseUrl` {#metabaseurl}

**型別** `string` · **預設值** `undefined`

SEO meta 標籤（canonical、og:url、hreflang）的基礎 URL。

- 具體的 URL 字串（例如 `'https://example.com'`）— 直接使用（最高優先順序）。
- `undefined` — 若有 `nuxt-site-config` 模組，則退回使用其 `site.url`，
  否則使用目前請求的來源
  （伺服器上為 `useRequestURL().origin`，用戶端為 `window.location.origin`）。

#### `metaTrustForwardedHost` {#metatrustforwardedhost}

**型別** `boolean` · **預設值** `true`

解析 meta 標籤的基礎 URL 時信任 `X-Forwarded-Host` 標頭。
當應用程式在會將此標頭設為實際面向用戶端之主機名稱的反向代理（nginx、Cloudflare、AWS ALB 等）
後方執行時啟用。

只有在 `metaBaseUrl` 與 `site.url` 皆未設定時才會讀取。若應用程式可以在沒有覆寫該標頭之代理的情況下被存取，請將其設為 `false`：否則用戶端可能決定你 canonical URL 中的主機。

#### `metaTrustForwardedProto` {#metatrustforwardedproto}

**型別** `boolean` · **預設值** `true`

解析 meta 標籤的協定時信任 `X-Forwarded-Proto` 標頭。
當應用程式在終止 TLS 的代理後方執行時啟用，如此
即使應用程式本身監聽 HTTP，canonical URL 仍會使用 `https://`。

適用範圍與 `metaTrustForwardedHost` 相同。

#### `trustForwardedHost` {#trustforwardedhost}

**型別** `boolean` · **預設值** `false`

從 `X-Forwarded-Host` 而非 `Host` 選擇請求的網域（`locales[].baseUrl`）。
只有在會覆寫該標頭的代理後方才啟用。

與 `metaTrustForwardedHost` 分開且預設關閉：在這裡，該標頭會選擇另一個網域的 locale，而不只是標籤的來源。請參閱 [Layer 與網域](/zh-TW/guide/layers#multiple-domains)。

#### `hreflangBaseLanguage` {#hreflangbaselanguage}

**型別** `boolean` · **預設值** `false`

另外輸出由每個 locale 的 `iso` 衍生的純語言 `hreflang`
（例如 `es-ES` → 另外輸出 `es`）。`locales` 中第一個地區性 locale 會取得
該語言的純語言標籤。永遠不會使用路由 `code`——只使用 `iso || code`。

#### `canonicalQueryWhitelist` {#canonicalquerywhitelist}

**型別** `string[]` · **預設值** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

在 canonical 與 `og:url` meta 標籤中保留的查詢參數名稱清單。
不在此清單中的參數會從 canonical URL 中移除。

### 偵測與重新導向 {#detection-and-redirects}

這些選項所影響的規則：[Locale 偵測](/zh-TW/guide/locale-detection)。

#### `redirects` {#redirects}

**型別** `boolean` · **預設值** `true`

啟用自動 locale 重新導向（伺服器外掛與用戶端路由中介軟體）。
當為 `true` 時，前綴策略會將未帶前綴的 URL 重新導向至其在地化形式。locale
來自應用程式狀態、cookie，或在 `autoDetectPath` 允許時來自 `Accept-Language`，否則
使用預設值。在 `no_prefix` 下，偵測永遠不會改變 URL（自訂路徑請參閱 `noPrefixRedirect`）。

設為 `false` 時，不會註冊用戶端重新導向中介軟體。伺服器外掛仍會對無效的 locale URL 回傳 404，並為帶前綴的 URL 寫入 cookie。

#### `autoDetectLanguage` {#autodetectlanguage}

**型別** `boolean` · **預設值** `true`

從 `Accept-Language` HTTP 標頭自動偵測使用者偏好的語言。
與 `autoDetectPath` 搭配使用，以決定何時進行偵測。

#### `autoDetectPath` {#autodetectpath}

**型別** `string` · **預設值** `'/'`

cookie／Accept-Language 偏好重新導向可執行的位置（當 `redirects` 啟用時）。

- `'/'` — 僅 `/`（預設 locale 的深層連結仍可存取；預設）
- `'no_prefix'` — 僅限沒有 locale 前綴的路徑
- `'*'` — 所有路徑，包含改寫明確的 locale 前綴
  （例如當 cookie 偏好 `de` 時，`/fr/about` → `/de/about`）

- 任何其他字串 — 該路徑，忽略結尾斜線（例如 `'/welcome'`）

在 `prefix` 下，允許路徑以外的未帶前綴 URL 仍會重新導向至預設
locale 的形式（`/about` → `/en/about`）。在 `prefix_except_default` 下帶有前綴的
預設 locale（`/en`）會是 404，而非重新導向。

#### `localeCookie` {#localecookie}

**型別** `string \| null` · **預設值** `null`

用於在不同工作階段間保存使用者 locale 偏好的 cookie 名稱。
設為 `null` 可停用以 cookie 保存。
在 `no_prefix` 策略下若未提供，會自動設為 `'user-locale'`；在 `i18n` 設定區塊中
明確設為 `null`，則在該策略下也會保持關閉。

沒有 cookie 時，`Accept-Language` 仍會驅動重新導向；cookie 則會在多次造訪之間記住使用者的選擇。

#### `noPrefixRedirect` {#noprefixredirect}

**型別** `boolean` · **預設值** `false`

適用於 `no_prefix` 策略：當預設 locale 對某頁面有自訂路徑
（`localeRoutes` / `globalLocaleRoutes`）時，將該頁面的原始路徑重新導向至訪客 locale 的
自訂路徑，否則導向預設 locale 的自訂路徑（例如 `/about` → `/about-us`）。
沒有自己自訂路徑的 locale 會停留在原始路徑。含動態
區段的頁面不會被重新導向。

### 註冊與開發 {#registration-and-development}

#### `plugin` {#plugin}

**型別** `boolean` · **預設值** `true`

註冊提供 `$t()`、`$tc()`、`$getLocale()`、
`$switchLocale()` 與其他執行階段輔助函式的核心 i18n 外掛。

#### `define` {#define}

**型別** `boolean` · **預設值** `true`

在執行階段提供 `$defineI18nRoute()`。無論如何，建置都會讀取頁面中的
`$defineI18nRoute()` 呼叫。

#### `hooks` {#hooks}

**型別** `boolean` · **預設值** `true`

在載入與導覽時呼叫 `i18n:register` app hook，讓外掛可以加入翻譯。

請參閱 [Hooks](/zh-TW/api/events)。

#### `components` {#components}

**型別** `boolean` · **預設值** `true`

註冊內建的 i18n 元件（`<i18n-link>`、`<i18n-switcher>`、`<i18n-t>`、`<i18n-group>`）。
設為 `false` 可停用自動元件註冊（例如你沒有使用它們，
並希望減少模組占用）。

#### `types` {#types}

**型別** `boolean` · **預設值** `true`

根據預設 locale 檔案中的翻譯鍵，為 `useI18n`、`$t` 與相關輔助函式
產生 TypeScript 型別宣告。

與 [`@i18n-micro/types-generator`](/zh-TW/integrations/types-generator) 套件分開。

#### `hmr` {#hmr}

**型別** `boolean` · **預設值** `true`

在開發模式下為翻譯檔啟用熱模組替換。
當為 `true` 時，JSON 翻譯檔的變更會觸發自動重新載入，
而不需整頁重新整理。

#### `debug` {#debug}

**型別** `boolean` · **預設值** `false`

為 locale 偵測、路由產生與翻譯載入啟用詳細的除錯記錄。

#### `vueDevtools` {#vuedevtools}

**型別** `boolean` · **預設值** `true`

在開發模式下註冊 Vue DevTools 檢查器與時間軸（瀏覽器擴充功能）。
與 Nuxt DevTools 自訂分頁分開。

#### `experimental` {#experimental}

**型別** `Record<string, unknown>` · **預設值** —

實驗性／不穩定選項的集合。
其內容可能在次要版本之間變更或移除，恕不另行通知。
