`strategy` 選項決定 locale 是否會出現在 URL 中，以及針對哪些 locale。請在發佈 URL 之前一次選定：之後再變更會改變每個連結。接著模組會在建置時產生在地化路由，而 `$localePath`、`<i18n-link>` 與語言切換器都會讀取這些路由。

## 四種策略 {#the-four-strategies}

![en（預設）與 de 下的 /about 頁面在各策略中的情況；相同的 URL 也列於下方文字中](/images/diagrams/strategies.svg)

**型別** `Strategies` · **預設值** `'prefix_except_default'`

用於 locale 前綴的 URL 路由策略。

- `'no_prefix'` — URL 中沒有 locale；locale 儲存在 cookie 中。
- `'prefix_except_default'` — 除了預設 locale 之外，所有 locale 都加上前綴。
- `'prefix'` — 一律加上前綴，包含預設 locale。
- `'prefix_and_default'` — 與 `prefix` 相同，但預設 locale 也可以在沒有前綴的情況下存取。

在 `defaultLocale: 'en'` 且 locale 為 `en`、`de` 時，`about` 頁面的 URL：

| 策略 | 英文 | 德文 | 不提供 |
| --- | --- | --- | --- |
| `prefix_except_default`（預設） | `/about` | `/de/about` | `/en` 與 `/en/about` 會回傳 404 |
| `prefix` | `/en/about` | `/de/about` | `/about` 會重新導向至有前綴的 URL |
| `prefix_and_default` | `/about` 與 `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | locale 不在 URL 中 |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

策略在建置時即已固定：執行階段對它的覆寫會被忽略並發出警告（[執行階段覆寫](/zh-TW/guide/runtime-overrides)）。

## 該選擇哪一種 {#which-one-to-choose}

- **`prefix_except_default`**：適用於大多數網站。既有的無前綴 URL 會繼續為預設語言運作。
- **`prefix`**：每種語言地位相同；`/` 一律導向有前綴的首頁。
- **`prefix_and_default`**：你需要 `/en/...` 與無前綴的 URL 同時運作，例如在兩者之間遷移的期間。無前綴的 URL 永遠不會被重新導向。
- **`no_prefix`**：位於登入之後的應用程式，或每個頁面在所有語言下只用一個 URL。locale 來自 cookie 或 `?locale=`。搜尋引擎在每個 URL 只會看到一種語言，因此不會輸出 `hreflang` 替代連結。

URL 如何選定 locale，以及訪客何時會被重新導向，請參閱 [Locale 偵測](/zh-TW/guide/locale-detection)。

## 產生的路由 {#generated-routes}

在建置時，每個頁面都會取得其策略所需的路由記錄。每筆記錄都帶有 `meta.i18n = { name, locales }`：它所顯示的頁面以及它所服務的 locale。連結、切換與重新導向都依據這些記錄回應，因此模組所提供的 URL 一定是路由器會服務的 URL。

與頁面共用相同路徑的 locale 會共用一筆記錄，例如 `/:locale(de|fr)/about`。擁有自己路徑的 locale 會取得自己的記錄，名稱為 `localized-<page>-<locale>`：

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

自訂路徑、各頁面的 locale 清單，以及將頁面排除於在地化之外，請參閱[在地化路徑](/zh-TW/guide/custom-locale-routes)與[頁面設定](/zh-TW/guide/per-component-translations)。`localized-` 前綴由 [`localizedRouteNamePrefix`](/zh-TW/api/module-options#localizedroutenameprefix) 設定。

<Warning>

**路由名稱是自動產生的** — 請勿在 `router.push({ name })` 中寫死 `localized-…` 名稱。請將頁面本身的名稱傳給 `$localeRoute` 或 `<i18n-link>`；它們會選擇正確的記錄。

</Warning>

## 連結到特定 locale 的頁面 {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- 具名路由與路徑皆可使用。路徑會與產生的路由進行比對，因此任何 locale 形式的路徑都會被接受。
- 若某個 locale 不提供該頁面（請參閱[頁面設定](/zh-TW/guide/per-component-translations)中的 `locales`），連結會改為指向該 locale 的首頁，而不是不存在的頁面。
- 各 locale 專屬的參數（翻譯過的 slug）透過 `$setI18nRouteParams` 處理，請參閱[在地化路徑](/zh-TW/guide/custom-locale-routes)。

函式簽章請參閱[方法](/zh-TW/api/methods)。

## `no_prefix` 詳細說明 {#no_prefix-details}

- 在 `no_prefix` 下，[`localeCookie`](/zh-TW/api/module-options#localecookie) 預設為 `'user-locale'`，因此選擇在重新載入後仍會保留。
- `$switchLocale('de')` 會載入德文字典並取代目前的歷史記錄項目；URL 不會改變。
- 各 locale 的自訂路徑仍然有效：使用 `globalLocaleRoutes: { about: { de: '/ueber-uns' } }` 時，德文讀者會看到 `/ueber-uns`。無論訪客的偏好為何，該 URL 一律以德文渲染；而限制於部分 locale 的頁面會以其中一種 locale 渲染。多個 locale 共用的路徑（`en` 與 `de` 都在 `/page/:id`）在偏好屬於其中之一時，會以偏好渲染。偏好本身會保留：下一個頁面會回到偏好的語言。
- [`noPrefixRedirect: true`](/zh-TW/api/module-options#noprefixredirect) 會重新導向在預設 locale 中具有自訂路徑之頁面的原始路徑：導向訪客 locale 的自訂路徑，否則導向預設 locale 的自訂路徑（當 `en` 有 `/about-us` 時，`/about` → `/about-us`；cookie 為 `de` 時 → `/ueber-uns`）。沒有自己自訂路徑的 locale 會留在原始路徑並在該處渲染。帶有參數的頁面不會被重新導向。

## 沒有 `pages/` 的應用程式 {#apps-without-pages/}

使用 `pages: false` 時，沒有可在地化的頁面路由。請只使用根翻譯檔案（`disablePageLocales: true`）；偵測、cookie 與 `$switchLocale` 仍然有效。儲存庫中 `test/fixtures/basic` 的 `pages-false` 變體即為可運作的設定範例。
