呼叫 `useI18n()` 的元件在單元測試中需要一個 i18n 實例。`@i18n-micro/test-utils` 提供一個假的 `useI18n()`，具備真實的翻譯、複數與格式化邏輯，讓你可以用自己的字典掛載元件，而不需要 Nuxt 伺服器。至於路由與重新導向，請使用 `@nuxt/test-utils` 以端對端方式執行真正的模組。

本頁介紹如何測試你的應用程式。本儲存庫如何測試模組本身，請參閱[測試模組](https://s00d.github.io/nuxt-i18n-micro/contributing/testing)。

## 安裝 {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

```bash npm
npm install -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

</CodeGroup>

## 模擬 useI18n {#mock-usei18n}

```ts
// tests/unit-setup.ts
import { setupNuxtI18nMock } from '@i18n-micro/test-utils'
import { mockNuxtImport } from '@nuxt/test-utils/runtime'
import { beforeEach, vi } from 'vitest'

export const { i18n, useI18n, setTranslationsFromJson } = setupNuxtI18nMock({
  spy: vi.fn, // every method becomes a vi.fn, so you can assert calls
  beforeEach, // reset state and reseed `translations` before each test
  translations: { welcome: 'Welcome' },
})

mockNuxtImport('useI18n', () => useI18n)
```

```ts
// vitest.config.ts
import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    environment: 'nuxt',
    setupFiles: ['./tests/unit-setup.ts'],
  },
})
```

請將 `mockNuxtImport` 保留在設定檔中：`@nuxt/test-utils` 必須轉換它。`setupNuxtI18nMock` 使用私有的翻譯快取，因此平行執行的測試檔不會共用狀態。

## 撰寫測試 {#write-a-test}

```vue
<!-- components/Greeting.vue -->
<script setup lang="ts">
const { $t } = useI18n()
</script>

<template>
  <p>{{ $t('welcome') }}</p>
</template>
```

```ts
// tests/greeting.spec.ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { expect, it } from 'vitest'
import Greeting from '~/components/Greeting.vue'
import de from '~/locales/de.json'
import { i18n, setTranslationsFromJson } from './unit-setup'

it('renders the German greeting', async () => {
  await setTranslationsFromJson('de', de)
  i18n.setLocale('de')

  const wrapper = await mountSuspended(Greeting)
  expect(wrapper.text()).toBe('Willkommen') // de.json: { "welcome": "Willkommen" }
})
```

此假物件公開與真正的 `useI18n()` 相同的方法（`$t`、`$tc`、`$tn`、`$td`、`$has`、`$localePath`……，含與不含 `$` 前綴），另外還有供測試使用的 setter：`setLocale`、`setLocales`、`setDefaultLocale`、`setRouteName`、`setTranslationsFromJson`、`loadPageTranslations`、`mergeTranslations`、`setMissingHandler`。

`$localePath` 與 `$switchLocalePath` 是依據 `strategy` 選項為路徑加上前綴的 stub（沒有真正的 router）。真正的連結與重新導向請以端對端方式測試。

## 低階輔助函式 {#lower-level-helpers}

| 輔助函式 | 用途 |
| --- | --- |
| `createIsolatedFakeI18n(options)` | 不含 Nuxt `useI18n` 串接的隔離假物件，例如搭配 `global.mocks` 用於一般的 `@vue/test-utils` `mount`。 |
| `createFakeI18n(options)` | 使用共用模組快取的假物件（請在 `beforeEach` 中呼叫 `resetI18n()`），或以 `isolated: true` 隔離。 |
| `createI18nTestContext(options)` | 兩者背後的 context，適用於需要多個假物件時。 |
| `t`, `tc`, `ts`, `tn`, `td`, `tdr`, `has` | 直接在共用 context 上呼叫，用於測試一般函式。 |

此模擬物件是一個 `BaseI18n`：`t`、`tc`、`tn`、`td`、`tdr` 與 `has` 都是真正的實作，並作用於真實的字典，因此測試看到的就是應用程式顯示的內容。

上述工廠輔助函式接受 `locale`、`defaultLocale`、`locales`、`routeName`、`strategy`、`translations` 與 `messages`（每個 locale 的字典）。完整的範例專案位於 [`packages/test-utils/example`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/test-utils/example)。

## 端對端測試 {#end-to-end-tests}

路由、重新導向、SEO 標籤與 payload 載入都需要真正的模組。請使用 `@nuxt/test-utils/e2e` 啟動你的應用程式：

```ts
// tests/e2e/locales.test.ts
import { $fetch, fetch, setup } from '@nuxt/test-utils/e2e'
import { describe, expect, it } from 'vitest'

describe('locales', async () => {
  await setup({ server: true })

  it('serves the German page', async () => {
    expect(await $fetch('/de')).toContain('lang="de-DE"')
  })

  it('redirects / for a German browser', async () => {
    const res = await fetch('/', { headers: { 'accept-language': 'de' }, redirect: 'manual' })
    expect(res.headers.get('location')).toBe('/de')
  })
})
```

第二個測試假設使用 `prefix`（或搭配其他預設 locale 的 `prefix_except_default`）；關於 `/` 何時會重新導向，請參閱 [Locale 偵測](/zh-TW/guide/locale-detection)。
