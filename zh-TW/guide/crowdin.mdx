[Crowdin](https://crowdin.com/) 是一個翻譯平台：你上傳預設語系的檔案，譯者在 Crowdin 中進行翻譯，然後你再把其他語系下載回來。本模組讀取的是一般 JSON 檔案，因此 Crowdin CLI 只需要一份能正確對應 `locales/` 與 `locales/pages/` 的 `crowdin.yml`。不需要變更任何模組設定。

## 設定 crowdin.yml {#configure-crowdin-yml}

```yml
# crowdin.yml
project_id_env: CROWDIN_PROJECT_ID
api_token_env: CROWDIN_PERSONAL_TOKEN
base_path: ./locales
preserve_hierarchy: true

files:
  - source: /en.json
    translation: /%two_letters_code%.json
  - source: /pages/**/en.json
    translation: /pages/**/%two_letters_code%.json
```

- `en` 是你的預設語系；它的檔案就是來源檔。
- `project_id_env` / `api_token_env` 會從環境變數讀取 ID 與 token，因此不會提交任何機密。
- `preserve_hierarchy: true` 會讓 `pages/<page>/` 資料夾維持原樣。
- 翻譯後的檔案名稱必須與 `nuxt.config.ts` 中的語系 `code` 相同。`%two_letters_code%` 適用於 `de` 這類代碼；對於 `pt-BR` 這類代碼，請使用 `%locale%`，或透過 `languages_mapping` 將 Crowdin 的代碼對應到你的代碼。

## 上傳與下載 {#upload-and-download}

```bash
npm install -g @crowdin/cli

export CROWDIN_PROJECT_ID=123456
export CROWDIN_PERSONAL_TOKEN=...   # from Crowdin account settings

crowdin upload sources   # push locales/en.json and locales/pages/**/en.json
crowdin download         # write locales/de.json, locales/pages/**/de.json, ...
```

在 CI 中執行這兩個指令以保持檔案為最新。下載的檔案會像手動編輯的檔案一樣存放在你的儲存庫中；下一次建置或開發重新載入時就會套用。

## 上傳之前 {#before-uploading}

先清理來源檔，避免譯者翻譯已失效的鍵：[`i18n-micro clean`](/zh-TW/api/cli#clean) 會移除未使用的鍵，[`i18n-micro check`](/zh-TW/api/cli#check) 會在下載後回報缺漏。CLI 本身沒有內建 Crowdin 整合：本頁所述即為官方支援的做法。
