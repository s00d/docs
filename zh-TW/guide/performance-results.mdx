### 說明 {#description}

透過 `untestutils/perf`，在同一份共用字典設定下比較 **plain Nuxt**、**i18n-micro** 與 **`@nuxtjs/i18n`**。

重點：建置時間、峰值 RSS、可部署的**程式碼 vs 翻譯（asset）vs 總計**，以及負載（Artillery）。

### 方法說明 {#methodology-notes}

- 指標為**每個測試專案連續 3 次執行的平均值**（非交錯執行）。
- **產出物**：強制執行 `nuxi build` 後的 Nitro node-server `.output/server/index.mjs`；`nuxt-i18n-micro` 使用**建置後的模組 dist**（而非 `dev:prepare` 的 jiti stub）。請參閱[基準測試方法](https://s00d.github.io/nuxt-i18n-micro/contributing/performance-methodology)。
- **翻譯** = `bundle.asset`（語系 JSON、`chunks/raw/`，以及透過 `isTranslationFile` 比對出的語系 chunk）。
- **程式碼**不包含 source map（`*.map`）：測試專案從儲存庫連結模組，因此 Nitro 會為它寫出完整的 map，而 npm 相依套件則沒有。
- **plain-nuxt** 以靜態 JSON 提供相同數量的葉節點 — 在負載下 I/O 密集，而非「i18n 額外負擔」。
- 負載設定 `--load full`：暖機 6s@6 + 主要 60s@60，不設上限（沿用既有做法）。
- 冷卻 `--cool fast`（請參閱方法文件）。
- `runs` 中的每次建置都是**強制**執行（不會因暖快取而使建置時間歸零）。
- 表格中的 Artillery **Error rate** 是來自負載指標的 HTTP 狀態錯誤。圖表也會繪製 `vusers.failed`（飽和狀態下的用戶端逾時）；這些值可能很高，而 HTTP 錯誤率仍維持 0%。

## 附註 {#notes}

- 共用設定：4 個語系 × 2 個頁面 × 約 16.8k 個 index 葉節點。
- 負載：僅使用程式化的 Artillery — 暖機 **6s@6** + 主要 **60s@60**，VU 不設上限（沿用既有的 YAML 方法）。路徑來自執行階段設定 — 請參閱 `scripts/src/perf/load.ts`。
- 冷卻：建置後 2s、每次執行之間 3s、測試專案之間 5s。每次執行都會強制建置，因此平均值不會被快取命中稀釋。
- 日常重新執行：`pnpm test:performance`（`--load short --cool fast`）。
- 重新產生此頁面：`pnpm -C scripts cli performance --load full --only all --runs 3`。
- 旗標：`--locales N --keys K --only all|micro|i18n|plain --runs N --skip-load --cool fast|strict`。
