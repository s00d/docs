### 说明 {#description}

通过 `untestutils/perf`，在同一个共享词典配置下比较 **plain Nuxt**、**i18n-micro** 和 **`@nuxtjs/i18n`**。

关注点：构建时间、峰值 RSS、可部署的**代码 vs 翻译（资源）vs 总计**，以及负载（Artillery）。

### 方法说明 {#methodology-notes}

- 指标是**每个夹具连续 3 次运行的平均值**（非交错运行）。
- **产物**：强制执行 `nuxi build` 后的 Nitro node-server `.output/server/index.mjs`；`nuxt-i18n-micro` 使用的是**构建后的模块 dist**（而非 `dev:prepare` 的 jiti 桩）。参见[基准测试方法](https://s00d.github.io/nuxt-i18n-micro/contributing/performance-methodology)。
- **翻译** = `bundle.asset`（locale JSON、`chunks/raw/`，以及通过 `isTranslationFile` 匹配的 locale 块）。
- **代码**不包含 source map（`*.map`）：夹具从仓库链接该模块，因此 Nitro 会为它写出完整的 map，而不会为 npm 依赖写出。
- **plain-nuxt** 以静态 JSON 提供相同数量的叶子数据——在负载下 I/O 密集，并非"i18n 开销"。
- 负载配置 `--load full`：预热 6s@6 + 主阶段 60s@60，不设上限（沿用历史方法）。
- 冷却时间 `--cool fast`（参见方法文档）。
- `runs` 次构建中的每一次都是**强制**构建（构建时间不会因缓存预热而归零）。
- 表格中的 Artillery **错误率**是负载指标中的 HTTP 状态错误。图表还绘制了 `vusers.failed`（饱和时的客户端超时）；即使 HTTP 错误率保持 0%，该值也可能很高。
### 运行 {#runs}

以下所有指标均为 **3 次运行的平均值**。

## 备注 {#notes}

- 共享配置：4 个 locale × 2 个页面 × 约 16.8k 个 index 叶子。
- 负载：仅使用编程方式调用的 Artillery——预热 **6s@6** + 主阶段 **60s@60**，VU 不设上限（沿用历史 YAML 方法）。路径来自运行时配置——参见 `scripts/src/perf/load.ts`。
- 冷却时间：构建后 2s，两次运行之间 3s，两个夹具之间 5s。每次运行都强制构建，因此平均值不会被缓存命中稀释。
- 日常重新运行：`pnpm test:performance`（`--load short --cool fast`）。
- 重新生成本页：`pnpm -C scripts cli performance --load full --only all --runs 3`。
- 参数：`--locales N --keys K --only all|micro|i18n|plain --runs N --skip-load --cool fast|strict`。
