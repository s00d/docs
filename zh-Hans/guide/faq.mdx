这里简要解答大家最常遇到、而各主题页面没有直接回答的问题。每个答案都会链接到负责该主题的页面。如果你的问题不在这里，请搜索文档或提交一个 [issue](https://github.com/s00d/nuxt-i18n-micro/issues)。

## 翻译 {#translations}

### `$t` 在插件或工具函数中失效 {#$t-fails-in-a-plugin-or-a-utility-function}

组合式函数需要 Nuxt 上下文。在 `setup` 之外，请从应用中获取辅助方法，或在 `await` 之后于其上下文中运行：

```ts
const nuxtApp = useNuxtApp()
const title = nuxtApp.$t('errors.unknown')
await nuxtApp.runWithContext(() => nuxtApp.$t('errors.unknown'))
```

在完全没有应用的服务中，请传递键，并在组件中翻译它们。

### 某个键只在一个页面上显示为原始文本 {#a-key-shows-as-raw-text-on-one-page-only}

该键位于另一个页面的文件中。页面只能看到根文件和它自己的 `locales/pages/<route-name>/` 文件；请把共享的键移到根文件中。参见[翻译文件](/zh-Hans/guide/translations)。

### 页面过渡期间键闪现 {#keys-flash-while-a-page-transition-runs}

这本不应该发生：在过渡结束之前，离开页面的键仍然可以解析。如果仍然闪现，说明该键只存在于两个页面都不拥有的页面文件中（例如在布局中使用）；请把它移到根文件中。

### 在 Vercel、Netlify 或 Edge 上 SSR 时翻译缺失 {#translations-are-missing-during-ssr-on-vercel-netlify-or-edge}

在这些平台上，服务器函数无法读取 `public/`，因此 payload 会嵌入到服务端包中。这是默认行为；请检查 `translationPayloads.serverAssets` 没有被关闭。如果日志显示 `public/ is not deployed next to the server`，请设置 `nitro.serveStatic: false`。参见[部署](/zh-Hans/guide/deployment)。

### 如何在翻译后的句子中放入链接？ {#how-do-i-put-a-link-inside-a-translated-sentence}

使用 `<i18n-t>`：每个具名插槽会填充同名的 `{placeholder}`。

```vue
<!-- "share": "Share your {link} with friends" -->
<i18n-t keypath="share">
  <template #link>
    <i18n-link :to="{ name: 'referral' }">{{ $t('referralLink') }}</i18n-link>
  </template>
</i18n-t>
```

参见 [`<i18n-t>`](/zh-Hans/components/i18n-t)。不支持 vue-i18n 的链接消息和修饰符；请像这样在模板中组合。

## Locale 与 URL {#locales-and-urls}

### `/en/about` 返回 404 {#/en/about-is-a-404}

在默认的 `prefix_except_default` 下，默认 locale 没有前缀：`/about` 就是英文。如果想要 `/en/...`，请使用 `prefix` 或 `prefix_and_default`。参见[路由策略](/zh-Hans/guide/strategy)。

### 深层链接不会重定向访问者 {#visitors-are-not-redirected-on-deep-links}

默认情况下只有 `/` 会依据浏览器语言或 cookie 进行跳转，因此分享的链接会保持其语言。请设置 `autoDetectPath: 'no_prefix'` 或 `'*'`。参见 [Locale 检测](/zh-Hans/guide/locale-detection#autodetectpath)。

### 刷新后所选语言被遗忘 {#the-chosen-language-is-forgotten-after-a-reload}

在前缀类策略下，locale cookie 是关闭的。请设置 `localeCookie: 'user-locale'`。参见 [Locale 检测](/zh-Hans/guide/locale-detection#the-cookie)。

### 能否在不改变 URL 的情况下切换 locale？ {#can-i-switch-locale-without-changing-the-url}

只有在 `strategy: 'no_prefix'` 下可以，此时 `$switchLocale('de')` 会在同一路径上重新加载字典。在前缀类策略下，locale 是 URL 的一部分，因此切换就是导航。如果需要链接而不是调用，请使用 `$switchLocalePath('de')`。

### 切换 locale 时页面滚动到顶部 {#the-page-scrolls-to-the-top-when-i-switch-locale}

这是 Nuxt 对任何导航都会应用的 `scrollBehavior`。请设置 `definePageMeta({ scrollToTop: false })` 并自行恢复滚动位置。playground 中的 [`SwitchLocalePreserve.vue`](https://github.com/s00d/nuxt-i18n-micro/blob/main/playground/components/SwitchLocalePreserve.vue) 是一个可直接复制的包装组件（[演示页面](https://github.com/s00d/nuxt-i18n-micro/blob/main/playground/pages/scroll-test.vue)）。

## 构建与集成 {#build-and-integrations}

### `nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` {#nuxt-seodefaults-depends-on-nuxt-site-configi18n-but-they-are-not-registered}

旧版的 `nuxt-site-config` 只认识 `@nuxtjs/i18n`。请将 `@nuxtjs/seo` 升级到 3 或更高版本，并在 `modules` 中把 `nuxt-i18n-micro` 列在它之前。参见 [SEO](/zh-Hans/guide/seo)。

### Cloudflare 上关于 `@unhead/vue` 的构建错误 {#build-error-about-@unhead/vue-on-cloudflare}

在应用中安装 `@unhead/vue`，以便预渲染步骤能找到它。模块本身不需要 `nodejs_compat`：只有当应用中的其他部分需要时，才在 `wrangler.toml` 中添加 `compatibility_flags = ["nodejs_compat"]`。
