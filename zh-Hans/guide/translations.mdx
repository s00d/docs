翻译是普通的 JSON 文件：每种语言一个根文件用于共享键，每个页面和语言一个文件用于该页面的键。当你添加页面、在页面之间共享键或设置回退语言时，请阅读本页。你将了解某个键应该放在哪个文件中、页面能看到什么，以及每个文件何时被加载。

## 目录结构 {#layout}

```text
locales/
├── en.json                 # root: menus, footer, buttons
├── de.json
└── pages/
    ├── index/              # pages/index.vue
    │   ├── en.json
    │   └── de.json
    ├── about/              # pages/about.vue
    │   ├── en.json
    │   └── de.json
    └── products-id/        # pages/products/[id].vue
        ├── en.json
        └── de.json
```

- `locales/pages/` 下的文件夹名是页面的 Nuxt **路由名称**：`pages/products/[id].vue` 对应 `products-id`，`pages/blog/[slug]/comments.vue` 对应 `blog-slug-comments`。
- 键可以嵌套任意深度；`$t('auth.form.login')` 读取的是 `{ "auth": { "form": { "login": … } } }`。
- `translationDir` 用于移动该文件夹（默认为 `'locales'`，相对于项目根目录，在 Nuxt 4 的 `app/` 布局下也是如此）。
- 当 Nuxt 解析页面时，缺失的文件会被创建为 `{}`，除非设置了 [`disableWatcher`](/zh-Hans/api/module-options#disablewatcher)。

## 页面能看到什么 {#what-a-page-sees}

![Lookup order for a key on /about in de: pages/about/de.json, de.json, pages/about/en.json, en.json. They merge into one about/de/data.json that $t reads](/images/diagrams/page-dictionary.svg)

页面的字典是其根文件与页面文件的深度合并（每一层级）。发生冲突时以页面文件为准：

```json
// locales/en.json
{ "title": "My shop", "nav": { "home": "Home", "cart": "Cart" } }
```

```json
// locales/pages/about/en.json
{ "title": "About us", "nav": { "cart": "Basket" } }
```

```ts
// on /about
t('title') // 'About us'
t('nav.home') // 'Home'   (root)
t('nav.cart') // 'Basket' (page wins)
// on any other page
t('title') // 'My shop'
```

没有自己文件夹的页面只会获得根字典。其他页面的键不可见。

### 回退语言 {#fallback-locales}

当前语言中缺失的键，会先从其回退语言中获取，然后才会显示键本身：

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'de-at', iso: 'de-AT', fallbackLocale: 'de' },
    ],
    defaultLocale: 'en',
    fallbackLocale: 'en', // global, for every locale
  },
})
```

- 语言自身的 `fallbackLocale` 会被一直追溯到底：`de-at` → `de` → `en`。
- 全局 `fallbackLocale` 是最弱的一层，位于每条链之下。
- 链中的每种语言都会添加其根文件，然后是页面文件，从最弱的回退语言一直到当前语言。因此，当前语言的根文件优先于回退语言的页面文件。

没有回退语言时，缺失的键会渲染为键本身（`'nav.home'`），并在开发环境下于浏览器控制台中记录警告（[`missingWarn`](/zh-Hans/api/module-options#missingwarn)）。

## 共享与其他来源 {#sharing-and-other-sources}

| 需求 | 选项 |
| --- | --- |
| 只使用根文件，不使用 `pages/` 文件夹 | [`disablePageLocales: true`](/zh-Hans/api/module-options#disablepagelocales) |
| 两个页面读取同一个页面文件夹 | [`routesLocaleLinks`](/zh-Hans/api/module-options#routeslocalelinks)：`{ 'about-us': 'about' }` |
| 位于其他文件夹中的共享根文件 | [`additionalTranslationDirs`](/zh-Hans/api/module-options#additionaltranslationdirs)：`['common']`（以主 `translationDir` 为准） |
| 来自 Nuxt layer 的键 | 各 layer 的文件会合并，以项目自身的文件为准。参见 [Layers](/zh-Hans/guide/layers) |
| 运行时添加的键 | [`i18n:register`](/zh-Hans/api/events) 钩子、`$mergeTranslations`、`$setTranslation` |
| 页面组件中的内联键 | `$defineI18nRoute({ locales: { en: { … } } })`，参见[页面配置](/zh-Hans/guide/per-component-translations) |

## 页面如何加载其字典 {#how-a-page-loads-its-dictionary}

![Locale JSON files are built into a payload tree, stored in public/ on Node or in server assets on Edge, read by a server loader, then used by $t on the server and fetched for $t in the browser](/images/diagrams/translation-pipeline.svg)

模块为每个页面和语言构建一个载荷：`/{apiBaseUrl}/{page}/{locale}/data.json`（默认为 `/_locales/about/de/data.json`）。

1. **服务器渲染。** Nitro 检测语言，页面直接从服务器加载器加载其载荷，不发起 HTTP 请求。字典不会写入 HTML 载荷，因此页面保持精简。
2. **Hydration。** 浏览器获取同一个载荷。服务器已经为它输出了 `<link rel="preload">`，因此获取会随 HTML 一同开始。
3. **导航。** 下一个页面的载荷会替换字典。离开页面的键在页面完全消失之前（页面过渡结束或 `page:finish`）仍然可以解析，因此正在淡出的页面不会闪现原始键。加载失败的分块（网络错误、4xx 或 5xx、响应体不是对象）会保留当前字典，下一次导航时会再次加载。语言切换失败也是如此：`$switchLocale` 解析为 `false`，再次调用它或再次点击切换器即可重试。在前缀策略下，此时 URL 已经改变，因此 `lang` 和 `$getLocale()` 会显示 URL 中的语言，而屏幕上仍保留旧的文本。
4. **缓存。** 已加载的载荷会缓存在服务器和浏览器中；大小和 TTL 的配置项见[性能](/zh-Hans/guide/performance)。

`translationPayloads.mode` 决定载荷的构建方式。`'premerged'`（默认）在构建时写入每个页面 × 语言的文件。`'source'` 保留源文件并按请求合并，对于 Edge 目标上的大型翻译目录，这种方式体积更小。两者生成的字典相同。各部署目标下文件最终存放的位置见[部署](/zh-Hans/guide/deployment)。

## 开发环境中的编辑 {#editing-in-development}

`nuxt dev` 会实时读取文件。保存翻译文件会就地刷新当前打开页面的字典：无需重新加载，已删除的键会消失，对根文件的更改会作用到每个页面。损坏的 JSON 文件会记录一条带有其路径的警告，并被视为空文件。如需改为手动刷新，请设置 [`hmr: false`](/zh-Hans/api/module-options#hmr)。
