本页列出了升级 nuxt-i18n-micro 及其 `@i18n-micro/*` 包时应用会发生的变化。在升级依赖之前，请阅读与你当前版本对应的章节。大多数应用只需少量代码修改。

<Tip>

**从 `@nuxtjs/i18n` 迁移？** — 请参阅[从 @nuxtjs/i18n 迁移](/zh-Hans/guide/migration)。

</Tip>

## 3.30.3 之后：主版本发布 {#after-3-30-3-the-major-release}

模块选项、`$t`、`$localePath`、`$switchLocale` 及其他辅助函数、组件、composable 和文档中列出的服务端工具都保持原名。变化的是行为，主要是修复了 bug。适配器包和路由包存在真正的 API 破坏性变更：请参阅[框架包](#framework-packages)和[其他包](#other-packages)。

### 首先要做的事 {#do-this-first}

1. **检查版本。** 模块需要 Nuxt 3.18 或更高版本以及 Node 20 或更高版本。Nuxt 自身也有 Node 最低版本要求：Nuxt 4.5 声明为 `^22.19.0 || ^24.11.0 || >=26.0.0`。在 Nuxt 3.18.0 本身上运行 `nuxt generate`，即使是纯 Nuxt 也会失败（`[unstorage] Invalid key: "/"`）；3.21.11 可以正常工作。`@i18n-micro/react` 需要 React 18 或更高版本。
2. **修正已安装的包。**
   - 移除 `@i18n-micro/hmr`。翻译 HMR 已内置在模块中。
   - 如果你的测试导入了 `@i18n-micro/test-utils`，请添加它：`npm install -D @i18n-micro/test-utils`。它不再随模块一起安装。
   - 将 `nuxt-i18n-micro-cli` 替换为 `@i18n-micro/cli`。28 个命令精简为 16 个，`check` 取代了其中三个，退出码也有变化：请参阅 [CLI 指南](/zh-Hans/guide/cli#moving-from-nuxt-i18n-micro-cli)。
3. **在代码中搜索**下表中的条目。
4. **检查应用前面部署了什么。** 如果在代理后面为 locale 使用了 `baseUrl`，请参阅[位于代理或 CDN 之后](/zh-Hans/guide/deployment#behind-a-proxy-or-cdn)。如果使用 CDN，请对照 `Vary` 响应头检查其缓存键：请参阅[缓存 HTML](/zh-Hans/guide/deployment#caching-html)。如果使用了 `apiBaseClientHost` 或严格的 CSP，请允许新的 `preload` 链接：请参阅 [SEO 和 head 标签](#seo-and-head-tags)。
5. **更新快照。** head 快照新增了 `preload` 链接，切换器的标记发生了变化（[`<i18n-switcher>` 和 `<i18n-link>`](#&lt;i18n-switcher>-and-&lt;i18n-link>)），并且 `$localeRoute` 输出中的查询字符串编码方式也不同了。
6. **在每个 locale 下打开你的页面，查找原始键。** 使用了上一个页面文件中的键的布局，现在会直接显示原始键：请将这些键移到根文件中。

<Warning>

**`@i18n-micro/path-strategy` 的 `switchLocaleRoute` 去掉了第一个参数** — `switchLocaleRoute(fromLocale, toLocale, route, options)` 现在变为 `switchLocaleRoute(toLocale, route, options)`。**旧的 JavaScript 调用不会报错：它会返回错误的结果，**因为 `fromLocale` 会被当作目标 locale，而 `toLocale` 会被当作路由。只有 TypeScript 会提示你。Nuxt 的 `$switchLocaleRoute` 不受影响。

</Warning>

### URL 和重定向 {#urls-and-redirects}

- **在 `prefix_except_default` 下，`/en` 和 `/en/...` 返回 404**（`en` 为默认 locale），与文档描述一致。
- **大小写或拼写不同的 locale 前缀返回 404。** `/DE/about` 以前会以默认 locale 渲染德语路由，或重定向到 `/en/DE/about`。该 URL 上若有自己的页面，则仍然是页面。catch-all 或 `[slug]` 页面不算：`[...slug]` 下的 `/DE/x` 和 `[slug]` 旁的 `/DE` 同样返回 404，因此与某个 locale 代码仅大小写不同的 CMS slug 会失去其页面。使用 `ssr: false` 时没有服务端响应，因此 `/DE/about` 会显示德语页面。
- **大小写不同的页面路径会重定向到其自身的拼写。** `/T/BASIC` 以前返回 200，现在会 `302` 到 `/t/basic`。
- **未知 URL 保持 404。** 使用 `autoDetectPath: '*'` 或 `'no_prefix'` 时，`/nope` 不再先重定向到 `/de/nope`。`prefix` 保留该重定向（那里没有无前缀的内容），`/` 在所有情况下也是如此。
- **在 `prefix_except_default` 下，其他 locale 的无前缀自定义路径能找到其页面。** `/a-propos` 以前返回 404，现在会 `302` 到默认 locale 的 URL（`/about`）。在 `prefix` 下，同样的重定向现在会到达一个有效页面（`/en/about`，以前是 `/en/a-propos`，返回 404）。`prefix_and_default` 仍返回 404。
- **`prefix` 搭配 `redirects: false` 时，无前缀 URL 返回 404**（`/about` 以前是 `302`），包括带有默认自定义路径的页面的原始 URL。`$localePath('/about')` 仍然能找到该页面。
- **在 `prefix_except_default` 下，带有默认自定义路径的页面的原始 URL 会重定向到该自定义路径，**包括动态页面。`/dir/one` 以前返回 404，现在会 `302` 到 `/dir-one/one`。
- **`autoDetectPath: '*'` 现在也会将 cookie 和 `Accept-Language` 应用于无前缀路径**（`/about` → `/de/about`）。
- **在 `prefix` 下，无前缀 URL 会保留访问者的 locale。** cookie 为 `de` 时，`/about` 和普通的 `<NuxtLink to="/about">` 都会跳转到 `/de/about`，在所有路径上都是如此，不论 `autoDetectPath` 如何设置。
- **在 `prefix_and_default` 下，无前缀 URL 即为默认 locale。** 带有 `Accept-Language: de` 的 `/contact` 以前会先渲染德语，然后以英语水合。现在它渲染默认 locale；访问者通过 `/de/...` 访问德语。
- **在 `no_prefix` 下，自定义路径以其自身的 locale 渲染**（无论偏好如何，`/ueber-uns` 都是德语），受限页面会以其服务的某个 locale 渲染。多个 locale 共享的路径在偏好属于其中之一时按偏好渲染，并且在 `baseUrl` 下，它在每个对应域名上都是一个页面。这些 locale 共用一条记录，`localized-<page>-<first locale>`。
- **`noPrefixRedirect` 按访问者的 locale 处理。** cookie 为 `de` 时，`/about` 会跳转到 `/ueber-uns` 并渲染德语，而不是跳转到默认 locale 的 `/about-us`。没有自己自定义路径的 locale 会停留在 `/about`。
- **没有页面的 `routeRules` 重定向不会被本地化。** `/de/old` 以前返回空的 200，现在返回 404：如有需要，请为带前缀的路径添加规则。从其他 locale 指向此类规则的链接会保持原样的路径，并落到规则的目标上。
- **路由规则会作用于自定义路径。** 当 `blog/[slug]` 有对应路径时，`/blog/**` 也会应用于 `/de/artikel/:slug`，并且规则在 `no_prefix` 下同样会被复制。像 `/de/artikel/news` 这样的静态同级路径也会匹配该模式。已经写在 locale 前缀下的规则保持原样。
- **设置了 `disabled: true` 的 locale 在其前缀上立即返回 404**，指向它的链接会停留在当前页面。运行时禁用的 locale 也是如此：它以前会以回退 locale 渲染。
- **模块的 404 显示 `Page Not Found`**，适用于已禁用 locale 的前缀以及主机自身的前缀，而 Nuxt 以前显示的是 `Page not found: /de/about`。状态码相同。
- **`customRegexMatcher` 不再让第一个路径段看起来像 locale 的真实页面返回 404。**
- **本地化路由名称保持一致。** 共享 locale 记录下的子路由保留页面的名称，`no_prefix` 遵循 `localizedRouteNamePrefix`，带有 index 子路由的父路由保持无名称。
- **其他模块添加的没有 `name` 的页面**（`extendPages`）会被本地化并获得名称，带有 locale 变体和 `hreflang`。它们以前保持未本地化状态。
- **`nuxt.config` 中的条目优先于 `$defineI18nRoute`，**无论键采用何种形式（`about/team`、`/about/team`、`about-team`）。以前哪个生效取决于拼写方式。
- **新的构建警告：** 以自身 locale 代码开头的 `localeRoutes` 值（`fr: '/fr/article'`），以及位于父路由之外的子路由自定义路径。
- **hash 模式可在 `prefix` 下工作。** 文档为 `/`，`/en` 或 `/about` 会重定向到 hash 中。
- **在 `prefix_except_default` 和 `prefix_and_default` 下，`/#/de/x` 渲染德语。** 以前它会渲染英语并出现水合不匹配。

### 链接和路由对象 {#links-and-route-objects}

- **不提供某页面的 locale 会链接到其首页。** `$localeRoute`、`$switchLocalePath` 和切换器不再返回其他 locale 的页面。
- **未知的 locale 代码会指向默认 locale。** `$localePath(path, 'xx')` 和 `$localeRoute` 以前会给出 `/xx`。
- **`$localePath` 会原样返回带有 `http(s):`、`mailto:` 或 `tel:` 协议的字符串，`$localeRoute` 的 `path` 和 `fullPath` 也会原样保留它**，因此不要将未经检查的值（例如 `?next=` 参数）作为链接目标传给它们。`//host` 以及像 `x.com` 这样的裸名称仍被视为路径，在每个 locale 中都位于当前源站上，由它们生成的链接也不会离开当前源站：`/de//x.com` 指向默认 locale 时为 `/x.com`。反斜杠被视为斜杠。
- **`$localePath` 会对路径进行编码：** `/a b` 会得到 `/a%20b`。
- **`$localeRoute` 和 `$switchLocaleRoute` 返回普通对象，**可以安全地用于 `ref`、`reactive`、`useState`、JSON 和展开语法。当某个参数需要转义时，对象为 `{ path, fullPath, query, hash }`（`$localeRoute` 额外添加 `href`），不含 `name` 或 `params`，且 URL 在刷新前后保持一致。普通 URL 则两者都有。`name` 是新增的：旧对象从未包含它。读取 `.name` 或 `.params` 的代码必须处理它们不存在的情况，得到哪种形式取决于具体值。
- **在 `trailingSlash` 下，`$switchLocaleRoute` 始终返回该路径形式，**普通 slug 也是如此，服务端重定向也遵循 `trailingSlash`。在该选项下，结果和 `Location` 响应头可能会变化。
- **`$localeRoute` 输出中的查询值使用 vue-router 的编码方式：** `/` 保持字面形式，空格为 `+`（`?redirect=/v2`，以前是 `%2Fv2`）。解码后的值相同，但此类 `href` 的快照会变化。
- **没有路径的链接停留在当前页面。** `$localePath('#top')`、`'?p=2'`、`''` 和 `{ query }` 会保持在当前页面；`'#top'` 以前会从站点根开始解析。单独的 `'about'` 仍表示 `/about`。
- **展开语法。** `{ ...route, query }` 和 `{ ...route, hash }` 会保留变更，通过 `$switchRoute` 时也是如此。在 `$localeRoute`、`$localePath` 和 `$switchRoute` 中，新的 `path` 优先。`{ ...route, params }` 适用于命名路由；在路径形式的路由上，路径优先、params 会被忽略，并伴随 vue-router 的开发警告。请使用 `$localeRoute({ name, params })`。
- **`$switchRoute` 停留在应用内。** locale 自己的 `baseUrl`、`mailto:` 和 `tel:` 会离开应用；其他任何字符串都被视为路径。
- **`excludePatterns`** 按完整路径段匹配（`'/admin'` 不再匹配 `/administrator`），并且 glob 是锚定的（`/docs/*` 不再匹配 `/en/docs/x`）。`RegExp` 模式现在会传递到运行时；以前它们在那里会丢失。被匹配的页面不会被本地化：没有 `hreflang`，在 `prefix_except_default` 下使用默认 locale。请对照[排除路径](/zh-Hans/guide/excluding-static-files)检查你的模式。

在 Nuxt 4.5.2 上，参数中的 `%` 或 `?` 在服务端渲染的刷新后无法保留，任何应用都是如此：这是上游问题，与模块无关。

### Locale 域名 {#locale-domains}

- **`locales[].baseUrl` 现在会参与请求路由。** 一次构建即可服务所有域名：请参阅[层和域名](/zh-Hans/guide/layers#multiple-domains)。设置 `baseUrl` 后，其他域名的 locale 在当前主机上返回 404（`example.de` 上的 `/en/about`），指向同一主机上 locale 的链接为相对链接。任何其他主机（包括 `localhost`）上的请求行为与以前相同，只是 canonical 和 `hreflang` 会使用 `metaBaseUrl`（如已设置），否则使用默认 locale 的 `baseUrl`，而不是请求的源站。
- **在会重写 `Host` 的代理之后，**所有请求都会回退到构建配置，直到你设置 [`trustForwardedHost`](/zh-Hans/api/module-options#trustforwardedhost)。它默认为 `false`，这一点与 `metaTrustForwardedHost` 不同。请参阅[位于代理或 CDN 之后](/zh-Hans/guide/deployment#behind-a-proxy-or-cdn)。
- **带有 `baseUrl` 的 `nuxi generate` 需要 `NUXT_I18N_DOMAIN`，每个域名运行一次。** 没有它时，构建会发出警告，这些 locale 只会成为没有页面的链接。请参阅[静态站点](/zh-Hans/guide/deployment#static-site-(nuxi-generate))。
- **指向带有 `baseUrl` 的 locale 的链接需通过 `$localePath` 或 `<i18n-link>`。** `<NuxtLink :to="$localePath(x, 'fr')">` 和 `<i18n-link :to="$localeRoute(x, 'fr')">` 会是该绝对 URL，点击即跳转。路由器不接受绝对对象：`<NuxtLink :to="$localeRoute(x, 'fr')">` 和 `router.push($localeRoute(x, 'fr'))` 会变成 `/https://fr.example.com/...`，即本应用的一个路径。在 `localhost` 或预览主机上，每个带有 `baseUrl` 的 locale 都是这样的链接，当前 locale 也不例外。在代码中请使用 `navigateTo($localePath(x, 'fr'), { external: true })`。
- **域名首页在所有地方都不带结尾斜杠**（`https://example.de`），包括链接、canonical 和 `hreflang`。
- **在 `prefix` 下，指向其他域名的链接会保留 locale 前缀，无论是否设置 `baseDefault`。** 即 `https://example.de/de/about`，而不是只会重定向的 `https://example.de/about`。
- **在 `prefix_except_default` 下，若在非构建默认 locale 上设置了 `baseDefault`，路由会保留所有前缀**，以便其他域名可以链接到它们。`/en` 仍然返回 404。只有读取 `router.getRoutes()` 的代码才能看出差别。
- **在 `prefix_except_default` 下，主机自身的前缀在其 `baseDefault` 主机上返回 404。** `de` 主机上的 `/de/x` 以前返回 200。
- **`$getI18nConfig().locales` 只包含当前主机所服务的 locale。** `linkLocales` 包含全部 locale，`$getLocales()` 仍然是完整的。

### 导航和 `$switchLocale` {#navigation-and-$switchlocale}

- **导航在提交时生效。** 字典、locale、参数和 head 在 `router.afterEach` 中变化，因此被取消或被阻止的导航不会改变任何内容，并且在加载下一个 chunk 期间，旧页面的链接仍然有效。`beforeResolve`、`beforeRouteEnter` 或之后的全局守卫现在看到的是旧的字典和 locale。路由中间件不受影响。
- **chunk 加载失败时保留当前字典。** 根文件出现 5xx、网络错误或响应体错误时，以前会显示原始键。现在新页面会使用旧字符串渲染，下一次导航时会重试。若返回 404，或静态主机用 SPA 外壳替代了该文件，则在下次刷新之前使用根字典。
- **`$switchLocale` 解析为 `true` 或 `false`**（以前不解析任何值），当 locale 的字典未生效时为 `false`。它的类型为 `Promise<boolean>`，`$switchRoute` 为 `Promise<void>`。
- **`$switchLocale` 是显式选择。** 到达目标后会存储该 locale，即使是 404 也会存储。如果导航被阻止、取消或抛出错误，已存储的偏好和状态保持不变，抛出的错误会被重新抛出。跳转到其他主机前会先存储。在 `no_prefix` 和 hash 模式下，无论导航结果如何，切换都会生效。在所有 locale 共用一个 URL 的页面上（`excludePatterns`），选择不会被撤销，由下一个页面的 URL 决定：在 `prefix_except_default` 下，无前缀链接会回到默认 locale。
- **在 `no_prefix` 下，当两个页面共享一个自定义路径时，`$switchLocale` 会保持在当前页面，**带有转义参数时也是如此。刷新此类 URL，以及带有转义参数的 `$localeRoute`，会落到第一条记录上。
- **客户端重定向保留其导航的模式。** 在 `prefix` 下，普通的 `<NuxtLink to="/about">` 会新增一条历史记录，而不是覆盖当前记录；`router.replace` 仍然是替换。
- **来自服务端的 `$setI18nRouteParams` 和 `useI18nHead` 在水合后依然保留。** 当页面在 SSR 期间设置了参数时，落地到 `/news/2` 后，切换器会链接到翻译后的 slug（`/de/news/2-zwei`），而不是 `/de/news/2`，服务端 HTML 中也是如此，无论切换器位于何处。当导航到其他路径并提交时（包括从 `/news/1` 到 `/news/4`），它们会被丢弃：请在新页面上重新设置。
- **在 setup 中读取的 `$setI18nRouteParams` 绑定到该页面。** 来自已离开页面的延迟调用不会产生任何效果。`useNuxtApp().$setI18nRouteParams` 现在是一个访问器，两次读取会得到两个函数。它没有 setter：像测试 stub 可能做的那样执行 `useI18n().$setI18nRouteParams = fn`，在严格模式下会抛出错误，因此请直接 stub `useI18n` 本身。在布局或 `app.vue` 中它是普通函数，因为那里不存在离开的情况。
- **服务端会在渲染结束时重写 `<i18n-switcher>` 的链接**，适用于带参数的页面，因为布局中的切换器会在页面的异步 setup 之前渲染。手写的 `$switchLocalePath` 链接不会被重写：请参阅[自定义 locale 路由](/zh-Hans/guide/custom-locale-routes)。在 Nuxt 的 SSR 流式渲染下，首个 HTML 保留 URL 中的参数。
- **服务端组件上名为 `locale` 的 prop 会设置其渲染 locale**，因此 `<Greeting :locale="$getLocale()" />` 会跟随 URL 和切换。其中的 `$getLocale()`、`$localePath` 和 `$getLocaleName` 也会跟随该 prop。请参阅[服务端翻译](/zh-Hans/guide/server-side-translations)。没有该 prop 时，它仍然使用 cookie 或默认值。
- **`keepalive` 页面在返回时会恢复其参数和 head。**
- **在 `prefix_except_default` 下设置为 `false` 的嵌套页面没有 locale URL。** 使用 `globalLocaleRoutes: { 'parent-kid': false }` 时，`/de/parent/kid` 以前会被提供，现在返回 404：该页面保持在 `/parent/kid`。

### Locale 检测和 cookie {#locale-detection-and-the-cookie}

所有地方使用同一套优先级，详见 [Locale 检测](/zh-Hans/guide/locale-detection)。

- **`?locale=` 仅在 `no_prefix` 下对页面生效。** 在前缀策略下由 URL 决定；`/about?locale=de` 不再在 `lang="en"` 下渲染德语。`?locale=de&locale=fr` 读取第一个值，以前是 `"de,fr"`。
- **`Accept-Language` 遵循 `q` 值**（`fr;q=0.1, de;q=0.9` → `de`；`q=0` 排除某种语言）。地区匹配不再依赖 `locales` 的顺序，并且永远不会跨越中文书写系统。
- **客户端导航到某个页面时会将其 locale 存储到 cookie 中，包括默认 locale 的无前缀页面。** 设置了 `localeCookie` 时，点击指向 `/about` 链接的访问者现在会得到 `user-locale=en`，之后更改浏览器语言也不再会重定向 `/`。首次加载该 URL 不会存储任何内容。在 `no_prefix` 和 hash 模式下，导航只会存储变化。
- **404 不写入 cookie：** 无论是响应本身，还是指向它的普通客户端导航，在任何模式下都不会写入。在 `no_prefix` 下，看起来带前缀的 URL 也不会写入。
- **在 `no_prefix` 下，显式设置的 `localeCookie: null` 会被遵循。** 以前它会变成 `user-locale`。请在 `nuxt.config` 的 `i18n` 块中设置：在 `modules: [[name, opts]]` 或层中设置的 `null` 仍然会丢失。
- **hash 模式只读取 `hash-locale` cookie。** 单独的 `user-locale=de` 不再生效。
- **格式错误的 locale cookie 会被忽略并保持原样，**而不是让每个 SSR 页面都返回 500。它也不再在每个请求中被删除，这同时也修复了带前缀的页面无法存储其 locale 的问题。
- **URL 中的 locale 优先。** 插件在 `/en/...` 上调用 `setLocale('de')` 不再加载 `de` 字典，状态中的未知代码会被忽略。
- **服务端 API 辅助函数**（`useLocaleServerMiddleware`、`useTranslationServerMiddleware`）在每个路由上使用同一顺序：`?locale` → `[locale]` 参数或前缀 → cookie → 请求头 → 默认值。它们现在遵循 `localeCookie: null` 和 `autoDetectLanguage: false`，并按 locale 缓存字典。
- **运行时覆盖会影响路由。** `NUXT_I18N_DEFAULT_LOCALE` 和运行时 `disabledLocales` 现在会改变生成的策略（被禁用的 locale 停止参与路由），运行时 `disabledLocales` 会追加到构建时的配置中。在 `prefix_except_default` 和 `prefix_and_default` 下，运行时 `defaultLocale` 会被忽略并输出警告，因为该 locale 的无前缀路由是在构建时生成的。运行时 `fallbackLocale` 必须是已启用的 locale：否则它会被丢弃并输出警告，若构建时的值已启用则使用该值。请参阅[运行时覆盖](/zh-Hans/guide/runtime-overrides)。

### SEO 和 head 标签 {#seo-and-head-tags}

- **`dir="auto"` 不再是默认值。** 没有 `dir` 的 locale 以前会得到 `dir="auto"`，这会拖慢大页面的解析。现在已知的 RTL 语言会得到 `dir="rtl"`，其他任何 locale 不会得到该属性。这适用于 Nuxt、`@i18n-micro/vue`、`astro` 和 `vitepress`。如果你在 locale 上设置 `dir: 'auto'` 以保留旧输出，在 20,000 个元素时大约需要 1 秒的解析时间：请参阅[文本方向](/zh-Hans/guide/seo#text-direction)。
- **每个 SSR 页面都有一个新标签：** `<link rel="preload" as="fetch" crossorigin="anonymous" href="/_locales/...">`，404 页面也有。使用 `apiBaseClientHost` 时，`href` 位于该主机上，需要配置 CORS。严格的 CSP 必须允许它。
- **`hreflang` 只列出服务该页面的 locale**；只有当默认 locale 服务该页面时才会输出 `x-default`。
- **未本地化的页面没有 `hreflang` 或 `og:locale:alternate`。**
- **当源站来自请求时，canonical 和 `hreflang` 包含 `app.baseURL`。** `metaBaseUrl` 和 `site.url` 保持原样。
- **404 页面带有 `<html lang dir>`**，使用 URL 中的 locale。它们没有 canonical、`hreflang`、`og:url`、`og:locale` 或替代链接，即使是模块自身在匹配到的记录上返回 404（`/en/...`）时也是如此。通过 `useI18nHead` 的 `replace` 传入的标签会保留，因此请在错误页面上跳过它们。
- **canonical、`og:url` 和 `hreflang` 会保留白名单中的查询参数**（`/about?page=2`），服务端也是如此：以前在 SSR 期间会被丢弃。默认白名单包括 `page`、`sort`、`filter`、`search`、`q`、`query` 和 `tag`；请参阅 [`canonicalQueryWhitelist`](/zh-Hans/api/module-options#canonicalquerywhitelist)。
- **无法解析的 `X-Forwarded-Host` 会被忽略**，而不是让每个页面都返回 500。当没有可用的主机，也没有 `metaBaseUrl` 或 `site.url` 时，该响应中的 canonical 和 `hreflang` URL 为相对 URL。无法解析的 `Host` 仍然返回 500，与普通 Nuxt 应用相同。
- **`disableMeta` 现在可以正常工作，**在 `$defineI18nRoute` 和 `routeDisableMeta` 中都是如此，在 `nuxt.config` 中设置时也一样：页面没有 `hreflang`、canonical 或 `og:locale`。`lang` 和 `dir` 保留。
- `useLocaleHead()` 还会返回 `build()`，这是一个用于 `useHead(() => build())` 的 getter。
- 在没有 `metaBaseUrl` 的普通构建中，`X-Forwarded-Host` 仍然像以前一样决定这些标签中的主机。如果源站可以被直接访问，请固定 `metaBaseUrl`：请参阅[位于代理或 CDN 之后](/zh-Hans/guide/deployment#behind-a-proxy-or-cdn)。

### 翻译 {#translations}

- **合并在每一层级都是深度合并。** 根文件、页面文件和回退文件以前使用两层合并，因此在 source 模式和开发环境中，来自回退文件或根文件的 `a.b.c` 会丢失。现在所有模式都会得到相同的字典。
- **回退链会被一直追踪到底**（`fr` → `de` → `en`），所有模式都是如此。
- **合并按 locale 进行，而不是按文件类型。** 当前 locale 的根文件现在优先于回退 locale 的页面文件。请参阅[回退 locale](/zh-Hans/guide/translations#fallback-locales)。
- **对于相同的 `code`，项目的 `locales` 条目优先于层中的条目**；层只填补空缺。
- **没有自己 `pages/<name>/` 文件夹的页面会读取根字典，**子页面也是如此。以前它会得到 `{}` 并显示原始键。输出中会为每个此类页面新增一个文件，并为每个 locale 新增 `__root/<locale>/data.json`：`/_locales/<any name>/en/data.json` 会返回带有根键的 200，以前返回 `{}`。这对监控、静态主机上的允许列表以及读取该目录树的工具都有影响。
- **`disablePageLocales: true` 只读取根文件；** `pages/index` 不再被合并进来。
- **离开页面的键在其元素离开文档时停止解析。** 如果布局使用了只有上一个页面文件才有的键，请将它们移到根文件中。显示子页面时，父页面的键会保留（包括带有 `index` 子页面的父页面），直到下一次导航。在同一父页面的两个子页面之间切换时，父页面自己的键需要来自子页面的字典或根字典。
- **`$clearCache()` 会重新加载当前页面的字典**，并在新字典到达之前保持旧字典显示在屏幕上。重新加载失败时保留旧字典，清除前发出的请求的响应会被丢弃，处于离开过渡中的页面保持已翻译状态。
- **`$has(key, route)` 会遵循 route 参数。**
- **在尚未访问的页面上调用 `$loadPageTranslations` 不再阻止其文件加载。** 文件会在首次访问时加载，你的键会覆盖在其之上。以前该页面在刷新之前会显示原始键。
- **翻译 HMR 会就地应用编辑**，无需刷新页面；被删除的键会消失，根文件的编辑会作用到每个页面。
- **损坏的 locale 文件在所有模式下都会带着路径警告一次。** 以前开发环境会抛出错误，而 premerged 模式会静默跳过，因此依赖开发环境硬失败的应用将不再看到这种行为。

### 复数和格式化 {#plurals-and-formatting}

- 使用负数、小数或极大计数的 `$tc` 会使用最后一种形式并带上真实计数；`{ count: null }` 不再抛出错误；缺失的复数键会交给缺失处理函数。
- `$tdr` 会给出真正的未来日期（`in 3 days`，或在 `numeric: 'auto'` 下为 `tomorrow`），对无效输入给出 `Invalid Date`。过去不到一秒为 `0 seconds ago`。
- **`$tn`、`$td` 和 `$tdr` 按 `iso` 处理**，与复数相同：`{ code: 'en', iso: 'en-GB' }` 现在会将日期格式化为 `31/10/2026`。在 locale 代码中 `_` 被视为 `-`，因此 `en_US` 不再抛出错误，而 `Intl` 不认识的代码会按 `en` 格式化，而不是跟随机器的 locale。命名格式仍按 `code` 查找。
- `{param}` 占位符只读取你传入的参数（`{constructor}` 保持原样）。
- `{placeholder}` 名称可以包含除花括号和空格之外的任何字符：`{firstName}`、`{first-name}` 和 `{user.name}` 都从 `params` 中读取。没有对应参数时，它们像以前一样保持原样。
- `defaultValue` 会在 `$t` 和 `$tc` 中进行插值：`$t('missing', { n: 1 }, 'Got {n}')` 会得到 `Got 1`，以前会得到 `Got {n}`。非字符串的默认值会原样返回。
- 对空翻译调用 `$tc` 会返回 `''`，与 `$t` 相同。以前它会返回默认值或键。
- **复数模板保持原有含义，只有一个例外。** 下表列出了所有形式。若要使用 `Intl.PluralRules` 类别，请使用新的 [`=0 ` 标记](/zh-Hans/api/methods#$tc)明确指定：`=0 no apples | one apple | {count} apples`。

  | 形式 | 示例（`uk` 中） | 之前 | 现在 |
  | --- | --- | --- | --- |
  | 在只有一个或两个整数类别的 locale 中（`en`、`de`、`fr`、`es`、`ja`...）的任何模板 | `none \| one \| {count} many` | 按索引 | **不变** |
  | 每个类别一种形式 | `one \| few \| many` | 按索引：21 → `many` | **不变**。添加标记可使 21 → `one` |
  | 零形式在前，共三种形式 | `none \| one \| many` | 按索引 | **不变** |
  | 其他占位符 | `no items \| {n} item \| {n} items` | 按索引 | **不变** |
  | 每种形式都含 `{count}` | `{count} many \| {count} one \| {count} few` | 按索引 | **不变** |
  | 形式数量少于或多于下方 | `a \| b`, `none \| one \| two \| {count} many` | 按索引 | **不变** |
  | 在 `lv`、`prg`、`blo`、`cv`、`ksh`、`lag` 中 | `none \| one \| {count} many` | 按索引 | **不变** |
  | 带有 `=0 ` 标记 | `=0 none \| one \| many` | 标记会被显示为文本 | 先零形式，再按类别 |
  | **不含占位符的零形式，然后每个类别一种形式，且多个计数共享的每种形式中都含 `{count}`** | `none \| {count} one \| {count} few \| {count} many` | 按索引：3 → `3 many`，21 → `21 many` | **按类别**：3 → `3 few`，21 → `21 one`。0、1、2 以及所有仍属于 `many` 的计数结果相同 |

  最后一种形式需要三个或更多类别（`ru`、`uk`、`pl`、`cs`、`sk`、`hr`、`sr`、`lt`、`ro`、`sl`、`he`、`ar`、`cy`...）。在 `ar` 中，`one` 和 `two` 都只对应单个计数，因此这两种形式不需要数字。
- **`Intl` 不认识的 locale 代码使用索引规则**，无论是否使用标记的类别：`ua` 不再跟随机器的 locale。请设置 `iso`：`{ code: 'ua', iso: 'uk-UA' }` 会按乌克兰语处理复数，在模块和 `@i18n-micro/vue` 中都是如此。
- **自定义 `plural` 规则保持其签名**，并且仍然获得 locale 代码。它读取原始值，因此带标记的模板传给它时 `=0 ` 仍然保留，并且它获得的计数是 `Number`：以前得到 `1` 的地方现在得到 `1.5`。返回 `null` 会回退到内置规则，内置规则会遵循该标记。
- **`timeZone` 选项。** 设置它（`Europe/Berlin`）可以在服务端和每个浏览器中渲染同一个日历日期。它对依赖时钟的 `relativeDate` 没有影响。

### `<i18n-t>` {#&lt;i18n-t>}

本节涵盖模块中的 `<i18n-t>` 以及 `@i18n-micro/vue` 中的 `I18nT`。其他框架请参阅[框架包](#framework-packages)。

- **`html` 在任何情况下都会转义 `params`，并忽略所有插槽。** 只有翻译被视为可信的标记。有意包含标记的参数现在会显示为文本：请将标记放在翻译中，并将数据作为参数传入，或在不使用 `html` 的情况下使用插槽。
- **插槽可以与 `plural`、`number`、`date` 和 `relativeDate` 一起使用，**并且在这些情况下 `default` 插槽也会收到 `{ translation }`。每个 `{name}` 都会被填充，而不仅仅是第一个。
- **插槽优先于同名参数。** 看起来像占位符的参数值保持为文本。使用 `customPluralRule` 或自定义 `plural` 时，规则返回的是最终字符串，因此在那里它插值进去的参数可能会被当作占位符。
- **对于 `plural`、`number`、`date` 和 `relativeDate`，`null` 表示未设置。** `:plural="null"` 以前会导致渲染失败，`:date="null"` 会渲染为 1970 年。
- `plural` 的计数方式与 `$tc` 相同，使用 `Number`：`1.5` 保持为 `1.5` 并使用最后一种形式，以前会被截断为 `1`；`"2 items"` 为 `NaN`，以前为 `2`；`""` 为 `0`。`customPluralRule` 也会看到 `1.5`。它的其他约定不变：参数相同，其返回值被原样使用，`null` 渲染为空。
- `hideIfEmpty` 适用于 `plural`、`number`、`date` 和 `relativeDate`。被隐藏的值会渲染为注释，而不是空文本节点，因此读取 `''` 的测试会看到 `<!---->`。
- **`html` 下缺失的键是文本。** 键会被转义，因为只有翻译是可信的，而键可能来自请求。`defaultValue` 由你提供，保持为标记。
- 使用 `plural` 时，缺失情况下 `defaultValue` 或键会整体显示，与 `$tc` 相同：`a | b` 不再被拆分。
- 在每个分支中，`defaultValue` 都会代替缺失的键显示，而不是显示键本身；缺失时 `customPluralRule` 会通过其 getter 获得它。以前它只在 `hideIfEmpty` 之后才起作用。
- 带有 `number`、`date` 或 `relativeDate` 的 `<i18n-t>` 会保留 `params`；它们会被合并进来。
- `date` 和 `relativeDate` 的输出带有 `data-allow-mismatch="text"`：服务端与浏览器之间时钟或时区不同时，水合期间不再发出警告。在命名插槽旁边，插槽周围的文本会放在单独的 `<span>` 中，因为 Vue 只在元素的单一文本上检查该属性。
- `.innerHTML` 和 `textContent` 属性会与 `innerHTML` 一起被丢弃。
- `<i18n-t>` 和 `<i18n-group>` 读取当前字典，与 `$t` 相同，而不是路由的 chunk。被淘汰的 chunk（`cacheMaxSize`）不再显示原始键。处于离开过渡中的页面现在读取 `$t` 在那里读取的内容：新页面的字典，缺失时回退到它自己的字典，因此两个页面都定义的键会显示新文本，而在切换 locale 之后，它自己的键会显示为原始键，直到它被卸载。

### `<i18n-switcher>` 和 `<i18n-link>` {#&lt;i18n-switcher>-and-&lt;i18n-link>}

- **点击切换器链接只产生一次导航。** 它是一个调用 `$switchLocale` 的普通 `<a>`，而不是 `NuxtLink` 加点击处理函数，因此 `router-link-active` 类不再存在。`href` 仍然带有 `app.baseURL`，当前 locale 的链接仍然带有 `aria-current="page"`。Ctrl/cmd 点击会打开新标签页，并且不影响当前标签页。链接会保留查询参数和 hash。
- 按钮为 `type="button"`，因此不再提交外层表单，并带有 `aria-expanded`。`aria-haspopup` 已在模块、`@i18n-micro/vue` 和 `@i18n-micro/astro` 中移除：它暗示存在菜单，而列表实际上是链接。按 Escape 键或点击外部会关闭下拉菜单；两个切换器不会再同时保持打开。
- 包装元素和下拉菜单具有 `i18n-switcher-wrapper` 和 `i18n-switcher-dropdown` 类；按钮除 `language-switcher` 外还具有 `i18n-switcher-button` 类，其标签位于 `<span>` 中。默认样式使用逻辑 CSS 属性（`inset-inline-start`、`margin-inline-start`），箭头为 `▾`。下拉菜单具有 `z-index: 1000`（以前为 10）、`min-width: 150px` 和 `box-shadow`，包装元素具有 `vertical-align: middle`。每个链接都有 `lang`，当 locale 设置了 `dir` 时还会有 `dir`。
- `<i18n-link>`：`https://`、`mailto:` 和 `tel:` 不区分大小写匹配（`HTTPS://x.com`、`Mailto:`）。单独的 `report.pdf` 或 `index.html` 是路由，而不是 `https://report.pdf`；`example.com` 和 `example.com:8080` 仍为外部链接。同时也是顶级域名的文件后缀（`example.md`、`x.zip`）被视为文件：请写上 `https://`。`activeStyle` 会忽略结尾斜杠、查询参数和 hash。它现在的类型为 `CSSProperties`，因此某些有类型的值可能需要调整。

### Hook、插件和类型 {#hooks-plugins-and-types}

- **`i18n:register` 在启动时于 `app:created` 运行，**在所有插件之后，而不是在插件之间。`order` 大于 1 或 `enforce: 'post'` 的插件，其订阅者现在在启动时也会被调用，但不再能在自身的 `setup` 中读取已注册的键。在导航中，该 hook 现在会在其他插件的 `router.beforeEach` 守卫之前运行。
- **`i18n:register` 获得的是它所填充页面的 locale。** 在 `hashMode` 下，改变 locale 的导航以前会传入旧的 locale，导致键落到错误的 chunk 中。
- **`i18n:register` 是运行时 hook：** 在插件中使用 `nuxtApp.hook('i18n:register', …)` 注册，无需 `@ts-expect-error`。请参阅 [Hooks](/zh-Hans/api/events)。
- **`hooks: false` 和 `define: false`** 仍会关闭各自对应的部分。
- **使用 `plugin: false` 时，`$defineI18nRoute` 仍可调用**，在运行时不执行任何操作。以前它会导致页面崩溃。
- `hooks` 选项不再记录 `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`；它们从未被触发过。
- 在页面中使用 `const { $defineI18nRoute } = useNuxtApp()` 现在可以配合使用变量的配置。
- `useI18n()` 新增了一些键：`clearCache`、`pluralFunc`、`pluralLocale`。`clearCache` 已包含在其类型中。
- `$getRouteName(route)` 会针对传入的路由给出结果。以前它返回空字符串。
- `useI18nLocale()` 移除了 `getLocaleWithServerFallback(serverLocale)`：请改写为 `getPreferredLocale() ?? serverLocale ?? null`。
- **在开发环境中，`$getI18nConfig()` 在服务端是只读的。** 在那里写入会抛出错误，而在生产环境中写入会影响每个请求。

### 服务端、构建和部署 {#server,-build-and-deployment}

- **页面的 payload 文件只包含与 locale 根文件不同的内容。** 客户端只加载一次根文件，并将每个页面合并到其之上，因此磁盘占用和 Edge 包体积都会缩小，第二个页面的开销只是第一个页面的一小部分。`premerged` 现在会写入 `__root/<locale>/data.json`，而 `/_locales/<page>/<locale>/data.json` 只包含差异：任何直接读取这些文件的程序都必须将两者合并。完整字典仍然是有效文件，因此提供完整字典的主机或 `source` 模式仍可正常工作。
- **字典文件按版本缓存。** 在 Node 服务器上，带有当前 `?v=` 的 URL 会被固定缓存一年，其他 URL 会重新验证，主机的静态副本响应 `max-age=60`：请参阅[缓存头](/zh-Hans/guide/deployment#cache-headers-and-datebuild)。`httpCacheControl: false` 保持 `max-age=0`。未重新构建而修改的翻译只有在 `v` 变化时才会到达浏览器：请设置 `NUXT_I18N_DATE_BUILD`。
- **字典遵循 `app.cdnURL`。** 浏览器从 `<cdnURL>/_locales/...` 获取公共 payload 文件，以前使用的是 `app.baseURL`：CDN 必须包含 `_locales/` 并允许你站点的源站（CORS）。请参阅 [App baseURL 和 payload 主机](/zh-Hans/guide/deployment#app-baseurl-and-payload-hosts)。
- **SSR 不再通过 HTTP 请求 `/_locales`，**因此该路由上的服务端中间件或日志将不再看到渲染时的读取。外部的 `apiBaseServerHost` 仍然通过 HTTP。
- **读取失败不再被缓存，404 也不再被缓存。** 主机返回 404 表示它没有该文件：渲染会显示根字典（与浏览器相同），不会保留任何内容，文件一旦出现就会被读取。任何其他失败、非 JSON 对象的 200 响应，或无法读取或已损坏的本地文件都不会进入缓存，下一个请求会重新读取：页面渲染会记录警告、显示原始键，并返回带有 `no-store` 和 `Retry-After` 的 `503`，因此路由规则或 CDN 不会保留它，而浏览器仍会在水合时读取字典；`/_locales/...` 返回带有 `no-store` 的 `503`；`useTranslationServerMiddleware` 给出的 `t` 会返回键或默认值。故障期间每个请求都会到达主机，60 秒内未发送任何响应头的主机会导致读取失败。大文件的慢速下载没有时间限制。请参阅[无法读取字典时](/zh-Hans/guide/deployment#when-a-dictionary-cannot-be-read)。`/_locales` 也会透传该 404，以前它返回 `200 {}`。
- **无法加载字典的预渲染会失败，**主机既没有页面文件也没有根文件时同样会失败。该路由返回 500，警告中会指明 locale 和页面，且不会写入任何文件；在 Nuxt 默认的 `failOnError` 下，构建以退出码 1 结束。没有自己文件但有根文件的页面会使用根文件预渲染。
- **构建时设置的主机会响应 SSR，**使用默认公共副本时也是如此，内部路径上的错误页面也一样。以前是由公共文件响应。运行时的 `NUXT_I18N_APP_BASE_SERVER_HOST` 现在会作用于 `/_locales` 和服务端加载器，渲染会通过该加载器读取任一主机。
- **自定义的 `nitro.output.publicDir`，以及任何 `public/` 不在服务端旁边的布局，都会嵌入 payload。**
- **`nuxi build --preset <static preset>` 会像 `nuxi generate` 一样进行预渲染，**因此可能会写入更多文件。`nuxi generate` 会在服务每个静态页面的每个 locale 中预渲染该页面，无论是否被链接，除非路由规则设置了 `prerender: false`。
- **在静态输出上使用 `source` 或 `publicAssets: false` 会发出警告。** 浏览器没有可读取的内容。
- **嵌入警告现在是大小检查。** 只有超过平台限制时构建才会发出警告：请参阅[包大小限制](/zh-Hans/guide/deployment#bundle-limits-on-edge)。
- **凡是由访问者决定的地方都会设置 `Vary`：** `no_prefix` 下的每个页面，以及 `/` 和任何可能按偏好重定向的 URL。使用 cookie 时它包含 `Cookie`，启用 `autoDetectLanguage` 时还包含 `Accept-Language`。请检查 CDN 的缓存键：请参阅[缓存 HTML](/zh-Hans/guide/deployment#caching-html)。
- **`/_locales` 的缓存方式已改变。** `/{apiBaseUrl}/**` 上不再有 Nitro 路由缓存，`s-maxage=60, stale-while-revalidate` 响应头也已移除。如果你依赖该缓存，请在 payload 路由前放置 CDN。空字典永远不会是 `immutable`。
- **服务端缓存默认有上限：** 未设置 `cacheMaxSize` 时最多 1000 个条目。`cacheTtl` 从条目存储时开始计算；读取不再延长它。
- **新增可选的 [`cacheStorage`](/zh-Hans/guide/performance#shared-cache-for-several-instances)：** 一个可由多个实例共享的字典缓存。未设置时没有任何变化。

| runtime | 对既非当前 locale 也非回退 locale 的写入不会发出通知 | 想要接收每次预加载的监听器：请在 locale 变化时读取 store |
| runtime | 新增 `fork(locale)`；`storage` 是 getter；`loadFromUrls` 并行获取，如果有一个失败则不写入任何内容 | — |
| runtime, vue, node, astro | `addRouteTranslations(locale, route, messages, false)` 会替换 chunk。以前它会合并 | 传入 `true` 或使用默认值以进行合并 |

## 从 v2 升级到 v3 {#from-v2-to-v3}

### 已移除的选项 {#removed-options}

```diff
 i18n: {
-  includeDefaultLocaleRoute: true,
+  strategy: 'prefix',
-  fallbackRedirectComponentPath: '~/components/MyRedirect.vue',
-  experimental: { hmr: true, previousPageFallback: true },
+  hmr: true,
 }
```

- `includeDefaultLocaleRoute: true` 即 `strategy: 'prefix'`；`false` 即默认的 `prefix_except_default`。
- `fallbackRedirectComponentPath` 已移除：重定向在渲染前于服务端进行，并在客户端路由中间件中进行。自定义重定向逻辑应放在设置 locale 的插件中，请参阅[自定义 locale 检测](/zh-Hans/guide/custom-auto-detect)。
- `experimental.hmr` 变为根级的 `hmr` 选项（默认开启）。
- `previousPageFallback` 已移除：离开页面的键会一直解析到其过渡结束，无需任何选项。

### Locale 状态 {#locale-state}

使用 `useI18nLocale()` 代替 `useState('i18n-locale')` 和 `useCookie('user-locale')`：

```diff
- useState('i18n-locale').value = 'fr'
- useCookie('user-locale').value = 'fr'
+ useI18nLocale().setLocale('fr') // state and cookie together
```

### 运行时配置 {#config-at-runtime}

使用 `$getI18nConfig()` 读取配置（包括运行时覆盖）：

```diff
- const cookieName = useRuntimeConfig().public.i18nConfig?.localeCookie
+ const { $getI18nConfig } = useNuxtApp()
+ const cookieName = $getI18nConfig().localeCookie
```

### 内部类型别名 {#internal-type-aliases}

如果你的 IDE 或 `vue-tsc` 无法解析 `#i18n-internal/*` 导入，请在 `package.json` 中为其设置映射。Nuxt 会在构建时解析它们，因此很少需要这样做：

```json
{
  "imports": {
    "#i18n-internal/plural": "nuxt-i18n-micro/internals",
    "#i18n-internal/strategy": "nuxt-i18n-micro/internals",
    "#i18n-internal/config": "nuxt-i18n-micro/internals"
  }
}
```
