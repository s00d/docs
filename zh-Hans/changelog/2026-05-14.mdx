**日期**：2026-05-14

**版本**：`v3.20.0`

![v3.20.0 release](/images/3.20.0.png)

此版本将 Nuxt 运行时重构为独立的 **`NuxtI18n`** 层，拆分了服务端/客户端的重定向处理，并修复了多个 SSR/hydration 回归问题。对于典型应用，公开的组合式函数和 `nuxt.config` 选项保持不变。

## 新功能 {#what’s-new}

### `NuxtI18n` 与 `NuxtTranslationLoader` {#nuxti18n-&-nuxttranslationloader}

运行时 i18n 逻辑从单体插件中移出，拆分为职责明确的类：

- **`NuxtI18n`** — 活动翻译视图层（`$t`、`$has`、locale/路由上下文、过渡合并/清理）
- **`NuxtTranslationLoader`** — 加载分块、在导航时切换上下文、填充 SSR payload
- **`createNuxtI18nPluginApi`** — 精简的插件接口（`$switchLocale`、`$localeRoute` 等）

请参阅更新后的 [Cache & Storage Architecture](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api) 和[性能](/zh-Hans/guide/performance)。

### 通过 `useState('i18n-ssr-chunks')` 传递 SSR Payload {#ssr-payload-via-usestate‘i18n-ssr-chunks’}

SSR 翻译通过 **Nuxt state** 进行序列化，而不是通过 `window.__I18N__` script 标签：

1. 服务端加载分块 → `useState('i18n-ssr-chunks')`
2. 客户端 hydration → `translationStorage.seedFromSsrChunks()`
3. 首次绘制时零额外请求

旧的 `window.__I18N__` 读取路径已被**移除**。

### 重定向架构拆分 {#redirect-architecture-split}

重定向现在按环境区分，行为更清晰，客户端卡顿更少：

| 环境    | 组件                      | 职责                                       |
| -------------- | ------------------------------ | ------------------------------------------ |
| **服务端 SSR** | `06.redirect.ts`（仅服务端） | 渲染前 302、404 检查、cookie 同步 |
| **客户端 SPA** | `i18n-redirect.global.ts`      | 导航时的全局路由中间件      |

客户端重定向从**目标路由**推导 locale，保留**查询字符串和 hash**，并遵循 `redirects: false`（不注册中间件）。请参阅 [Locale 检测 — 各 strategy 的重定向](/zh-Hans/guide/locale-detection#redirects-per-strategy)。

### `i18n:register` Hook 的触发时机 {#i18nregister-hook-timing}

**`05.hooks`** 插件（`dependsOn: i18n-plugin-loader`）会在加载器就绪后触发 `i18n:register` — 在启动时和导航时 — 因此用户插件能够可靠地接收到该事件。使用 `hooks: false` 可将其禁用。请参阅[事件](/zh-Hans/api/events)。

### 构建时提取 `defineI18nRoute` {#build-time-definei18nroute-extraction}

一个 Vite unplugin 会在构建时扫描页面 `.vue` 文件，并为 `@i18n-micro/route-strategy` 写入路由 meta。`script setup` 中的运行时 `$defineI18nRoute` 仍保留，用于开发和内联配置。请参阅[组件级翻译](/zh-Hans/guide/per-component-translations)。

## 错误修复 {#bug-fixes}

- **SSR hydration** — 在 `Object.freeze` 之前克隆响应式 SSR 分块（修复客户端 `#locale` / 404 崩溃）
- **Locale 切换** — 在 locale 变更时替换视图层（不会残留上一个 locale 的旧键）
- **客户端重定向** — 从目标路由获取 locale；重定向时保留 query/hash
- **`has()`** — 仅检查当前 locale；回退在 `$t()` 中生效，而不在 `$has()` 中生效
- **`defineI18nRoute` meta** — 每个插件实例独立缓存；匹配最长的 `rootDir`；正确区分 `pages/index` 与 `pages/index/index` 路径

## 破坏性变更 {#breaking-changes}

对于标准的 `nuxt.config` + 组合式函数用法，没有破坏性变更。内部路径和 SSR 注入机制已更改；依赖手动注入 `window.__I18N__` 的应用必须改用 Nuxt payload / 模块 API。

## 为何重要 {#why-it-matters}

- **更可靠的 SSR → 客户端交接** — 使用 Nuxt 原生 state，而不是临时的全局变量
- **更清晰的重定向模型** — 服务端在绘制前返回 302；仅在需要时使用客户端中间件
- **更易于维护** — 运行时拆分为可测试的单元，并配有针对性的回归测试
