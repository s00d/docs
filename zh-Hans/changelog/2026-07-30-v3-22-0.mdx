## Nuxt I18n Micro v3.22.0 — 格式、缓存与翻译内存 {#nuxt-i18n-micro-v3-22-0-—-formats-cache-&-translation-memory}

**日期**：2026-07-30

**版本**：`v3.22.0`

![v3.22.0 发布](/images/3.22.0.png)

我们宣布 **v3.22.0** 发布：带格式化器缓存的 Vue I18n 风格命名数字/日期格式、对 CDN 友好的翻译负载缓存（内容指纹 + `httpCacheDuration`），以及用于在运行时读取和替换当前字典的翻译内存 API。

## 新功能 {#what’s-new}

### 命名 `numberFormats` / `datetimeFormats` + 格式化器缓存 {#named-numberformats-/-datetimeformats-+-formatter-cache}

兼容 Vue I18n 的命名格式，以及更快的 Intl 格式化：

- 配置：按 locale 设置 `numberFormats` / `datetimeFormats`
- API：`$tn(1000, 'currency')`、`$td(date, 'short')`（支持覆盖 locale 和合并选项）
- `FormatService` 按 locale+选项缓存 `Intl.NumberFormat` / `DateTimeFormat` / `RelativeTimeFormat`

参见[方法 — `$tn` / `$td`](/zh-Hans/api/methods#$tn) 和[模块选项](/zh-Hans/api/module-options#numberformats)。

### `dateBuild` 默认使用内容指纹 {#datebuild-defaults-to-a-content-fingerprint}

`/_locales` 请求上的 `?v=` 以前默认为 `Date.now()`，而响应以 `immutable` 方式缓存一年。因此，即使没有任何翻译发生变化，每次重新构建也会使所有客户端的字典失效。

现在默认值是按层顺序计算的翻译源 SHA-256 指纹。翻译未改动时，重新构建会保持相同的 URL。显式设置 `dateBuild` 仍然优先。参见[模块选项 — `dateBuild`](/zh-Hans/api/module-options#datebuild)。

### 用于 `/_locales` 负载的 `httpCacheDuration` {#httpcacheduration-for-/_locales-payloads}

内置的 `/{apiBaseUrl}/:page/:locale/data.json` 路由现在会为浏览器和 CDN 发送 HTTP `Cache-Control`：

- 选项：`httpCacheDuration`（秒，默认 `31536000` / 1 年）
- 响应头：`Cache-Control: public, max-age=…, immutable`
- 可与现有的 `dateBuild` 缓存失效机制（`?v=...`）安全配合；`0` 会禁用该响应头；开发模式下不生效

相当于 `@nuxtjs/i18n` v10.2.0 的 `experimental.httpCacheDuration`，以显式响应头的形式实现。

### 压缩的公共负载 {#compressed-public-payloads}

`nitro.compressPublicAssets` 现在也会作用于复制到 public 目录中的翻译负载（`.gz` + `.br`）。Nitro 会在复制发生之前压缩公共资源，因此以前这些负载是静态构建中唯一未被压缩的部分 —— 在 playground 首页上，原始大小为 6.65 MB，而 gzip 后为 1.01 MB。模块本身仍然不会主动启用压缩。参见[性能](/zh-Hans/guide/performance#payload-size)。

### `resolveTranslations()` 和 `setTranslation(key, value)` {#resolvetranslations-and-settranslationkey-value}

用于在内存中读取和替换当前翻译字典的运行时辅助函数：

- **`resolveTranslations()`** 返回 `$t()` 针对当前 locale 和路由读取的完整树 —— 适用于 DevTools、测试和运行时编辑器。当第二层处于活动状态时（回退 locale 或 Nuxt 页面过渡热重载），导出结果会通过 `mergeTranslationLayers` 保持嵌套结构，只有在单棵树无法表达的标量与对象冲突时才使用扁平的点分隔键。
- **`setTranslation(key, value)`** 替换某个键上的值（顶层键、点分隔路径、对象、字符串或标量）。这是**替换**，而不是合并；如需保留同级键，请使用 `$mergeTranslations`。
- 可在 `useI18n()`、`useNuxtApp()` 以及继承自 `@i18n-micro/core` 的框架 i18n 实例上使用。
- `@i18n-micro/test-utils` 新增了对应的 `resolveTranslations` / `setTranslation` 辅助函数，用于单元测试。

### 从 Vue 包中移除 `getAllTranslations()` {#getalltranslations-removed-from-vue-package}

使用 `resolveTranslations()` 获取当前查找树。如需在 Vue 中导出完整存储，请使用 `getStorage()` 或 `getRouteCache()`。

## 破坏性变更 {#breaking-changes}

在典型用法下，公共配置层面没有任何需要修改应用代码的内容。如果你直接访问了运行时内部实现，以下内容需要注意：

- **SSR 负载从 `useState('i18n-ssr-chunks')` 移到了 `nuxtApp.payload.data['i18n-ssr-chunks']`。** 它仍然携带 SSR 期间加载的每个 `(locale, route)` 的**完整翻译块** —— 与之前相同的字典，只是放在了 Nuxt 预渲染时可以外置到 `_payload.json` 的位置。`useState('i18n-ssr-chunks')` 现在不返回任何内容。以这种方式读取翻译从未被正式支持，但缓存 API 文档中曾描述过，因此在此特别说明。
- **`NuxtTranslationLoaderOptions` 暴露了 `setSsrChunk`。** 加载器在服务端加载时会将每个合并后的块写入 `payload.data`。不再使用 `getSsrChunks`。
- **`nitro.compressPublicAssets` 现在会在复制的负载旁生成 `.gz` / `.br` 文件。** 如果你启用了它，public 输出中会出现更多文件。枚举翻译目录的部署工具可能需要考虑这些文件。
- **升级后负载 URL 会变化一次**，因为 `?v=` 从构建时间戳改为内容指纹。客户端在升级后的首次请求时会重新下载字典，之后在后续部署中一直保留 —— 这正是目的所在。
- **从 `@i18n-micro/vue` 中移除了 `getAllTranslations()`。** 请改用 `resolveTranslations()` / `getStorage()` / `getRouteCache()`。

## 问题修复 {#bug-fixes}

- **`<i18n-switcher>`** —— 下拉菜单中会省略 `disabled: true` 的 locale。`$getLocales()` 仍然为你自己的代码返回完整列表，而内置的 SEO/meta 输出会排除被禁用的 locale。
- **切换器样式** —— `cursor: not-allowed` 通过 `activeLinkStyle` / `customActiveLinkStyle` 应用于**当前** locale；为了向后兼容恢复了 `customDisabledLinkStyle`，并在当前 locale 为 `disabled: true` 时将其应用到切换器按钮上。
- **开发环境 HMR** —— 不改变文件内容的写入（编辑器失焦保存、格式化工具重写）不再触发重新合并。根 locale 的变更会重建该 locale 的所有页面，因此在无实际变化时执行代价很高。
- **开发环境 HMR** —— 根 locale 变更时，各页面会并发重新合并，而不是逐个处理。
- **页面过渡** —— 同一 locale 内导航时，会保留离开页面的块作为回退层，直到 `page:transition:finish`，而不是在每次导航时执行代价高昂的深度合并。

## 为什么重要 {#why-it-matters}

- 无需引入更重的技术栈即可获得 Vue I18n 风格的格式化。
- 对 CDN 友好的翻译 URL，在字典未变化时跨重新构建保持稳定。
- 提供受支持的运行时 API 来检查和修补实时字典 —— DevTools、测试和编辑器不再需要私有辅助函数。

完整的更新日志将随版本发布在 [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md) 上。

## 修复：`app.baseURL` + `strategy: 'prefix'` 导致的无限重定向循环 (#234) {#fix-infinite-redirect-loop-with-app-baseurl-+-strategy-‘prefix’-#234}

**日期**：2026-07-03

服务端重定向插件（`06.redirect.ts`）现在会在 locale 检测之前从 `getRequestURL(event).pathname` 中去除 `runtimeConfig.app.baseURL`。修复了应用部署在子路径下时出现的 `ERR_TOO_MANY_REDIRECTS`（例如 `/examples` → `/examples/ja` 只跳转一次，而不是 `/examples/ja/examples/ja/...`）。
