`@i18n-micro/solid` 为 SolidJS 应用提供一个基于 signal 的 i18n 实例、一个 provider、`useI18n()` 和四个组件。在不基于 Nuxt 构建的 Solid 应用中使用它。在 JSX 或 effect 中读取 `t()` 会追踪 locale、路由和字典；共享模型见[框架](/zh-Hans/integrations/overview)。

## 安装 {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer 依赖：`solid-js` `^1.8.0`；`@solidjs/router` `^0.15.4 || ^1.0.0`（可选，仅用于 `@i18n-micro/solid/router`）。暂不支持 Solid 2。

## 配置 {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` 接受 `i18n`、`locales`、`defaultLocale` 和 `routingStrategy`；省略的 prop 会沿用外层 provider 的值，实例也一样。`getLocaleName()` 和 `<I18nSwitcher>` 读取 `locales`；没有它们就没有可列出的内容。选项见[实例](/zh-Hans/integrations/overview#the-instance)。该实例就是 [runtime](/zh-Hans/integrations/runtime-package) 的实例，在其存储之上加了一个 signal。

## 翻译 {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

请在 JSX 或 effect 中调用这些方法，以便 Solid 追踪它们，`localePath` 和 `getLocale` 也是如此；在组件主体中读取一次的值不会更新。在实例上，请通过 `i18n.locale` 和 `i18n.currentRoute` 进行追踪：`i18n.getLocale()` 保持为普通读取，因为写入操作会读取它。读取 locale 只会因 locale 变化而触发，因此读取 locale 并加载字典的 effect 只会运行一次。不要解构 props，也不要把 `t('key')` 的结果保存在普通变量中。

`useI18n()` 返回 `t`、`ts`、`tc`、`tn`、`td`、`tdr`、`has`、`locale`（一个访问器：`locale()`）、`getLocale`、`getLocales`、`defaultLocale()`、`getLocaleName`、`switchLocale`、`localePath`、`localeRoute`、`setRoute`、`getRoute`、`addTranslations`、`addRouteTranslations`、`resolveTranslations`、`setTranslation`、`clearCache` 和 `instance`。

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## 切换 locale {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

切换不会加载任何内容；请先添加该 locale 的字典。

`<I18nGroup>` 会把带前缀的 `t` 传给函数子元素。其中的 `<I18nT>` 和 `t()` 不带前缀：

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## 路由 {#routing}

`@solidjs/router` 适配器位于一个子路径中，因此主入口从不导入路由器。请在路由器之下调用它，通常是在路由器的 `root` 中，那里 `useNavigate` 和 `useLocation` 可用：

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

该适配器为除默认 locale 之外的每个 locale 添加前缀（`/about`、`/de/about`），并把 `<I18nLink>` 渲染为路由器的 `<A>`。`getCurrentPath` 读取路由器的响应式 location，因此激活链接和切换器会随之更新；自定义策略在那里读取一个 signal 也能达到同样效果。注意参数顺序：`(locales, defaultLocale, navigate, location)`。对于其他路由器，请编写一个带有 `getCurrentPath`、`push` 和 `replace`（均为必需）的适配器 — 参见[路由适配器](/zh-Hans/integrations/overview#router-adapter)。

## SSR {#ssr}

如需服务端渲染，请使用 `vite-plugin-solid` 构建：该包的 `solid` 导出条件会把源码交给它，从而为服务端编译。预构建的 `dist` 仅供浏览器使用。该实例没有 `destroy()`；每个应用创建一个，或在服务端每个请求创建一个，然后让它被垃圾回收。
