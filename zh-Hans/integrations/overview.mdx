# 集成

`@i18n-micro` 系列是 Nuxt I18n Micro 的轻量、面向具体框架的版本,便于集成到各种框架与运行环境中。这些包以极小的体积提供核心国际化能力,重点覆盖必要的翻译特性与基础组件。

## 概览

这些集成包是完整 Nuxt I18n Micro 模块的**精简版**,只包含国际化所需的关键功能:

- **核心翻译能力** —— 基础翻译方法、复数与格式化
- **必要组件** —— 常见 i18n 场景使用的一小组 UI 组件
- **路由适配器模式** —— 通过适配器抽象实现灵活的路由集成
- **TypeScript 支持** —— 完整的类型定义,支持类型安全的开发

与完整的 Nuxt 模块不同,这些包:

- 不包含框架特定的路由逻辑
- 若需要路由能力,需由你实现路由适配器
- 更关注翻译功能,而非框架深度集成
- 设计上尽可能保持轻量与框架无关

## 核心组件

所有框架包都包含以下必要组件:

### `<I18nT>`

用于渲染已翻译文本的翻译组件,支持:

- **参数插值** —— 用动态值替换占位符
- **复数处理** —— 根据数量自动选择复数形式
- **数字格式化** —— 按语言格式化数字
- **日期格式化** —— 格式化日期与相对时间
- **HTML 渲染** —— 可选的 HTML 内容渲染
- **默认值** —— 缺失翻译时的回退文本

**示例:**

```vue
<!-- Vue -->
<I18nT keypath="greeting" :params="{ name: 'World' }" />
```

```tsx
// React
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```tsx
// Solid
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```astro
<!-- Astro -->
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

### `<I18nLink>`

本地化链接组件,可自动处理 URL 中的语言前缀。特性:

- **自动路径本地化** —— 根据路由策略添加/移除语言前缀
- **激活态检测** —— 高亮显示当前路由
- **外部链接支持** —— 自动识别并处理外部 URL
- **路由集成** —— 若可用,则使用路由适配器的链接组件
- **自定义样式** —— 支持激活态与悬停态

**示例:**

```vue
<!-- Vue -->
<I18nLink to="/about" active-class="active">
  About Us
</I18nLink>
```

```tsx
// React
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```tsx
// Solid
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```astro
<!-- Astro -->
<I18nLink href="/about" class="nav-link">
  About Us
</I18nLink>
```

### `<I18nSwitcher>`

语言切换器组件,提供下拉或列表形式的语言切换界面。特性:

- **自动语言列表** —— 从已配置的语言生成选项
- **当前语言高亮** —— 视觉上标示当前活动语言
- **自定义标签** —— 支持按语言自定义显示名
- **路由集成** —— 自动导航到本地化路径
- **可访问性** —— 提供正确的 ARIA 属性与键盘导航

**示例:**

```vue
<!-- Vue -->
<I18nSwitcher />
```

```tsx
// React
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```tsx
// Solid
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```astro
<!-- Astro -->
<I18nSwitcher />
```

### `<I18nGroup>`

用于以共同前缀对翻译进行分组的组件,便于按页面或功能组织翻译。特性:

- **前缀作用域** —— 自动为分组内所有翻译键添加前缀
- **嵌套分组** —— 支持嵌套的翻译分组
- **清晰组织** —— 便于维护整洁的翻译结构

**示例:**

```vue
<!-- Vue -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

```tsx
// React
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```tsx
// Solid
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```astro
<!-- Astro -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

## 共享的 `createI18n` 选项 \{#create-i18n-options\}

每个框架包的创建方式都是相同的 —— 只有 options 类型以对应框架命名(`ReactI18nOptions`、`SolidI18nOptions` 等)。选项本身完全一致:

| 属性         | 类型                                                       | 是否必填 | 默认值          | 说明                                    |
| ---------------- | ---------------------------------------------------------- | -------- | ---------------- | ---------------------------------------------- |
| `locale`         | `string`                                                   | ✅       | -                | 当前语言代码(例如 `'en'`)             |
| `fallbackLocale` | `string`                                                   | ❌       | 与 `locale` 相同 | 缺失翻译时的回退语言    |
| `messages`       | `Record<string, Translations>`                             | ❌       | `\{\}`             | 初始翻译消息                   |
| `plural`         | `PluralFunc`                                               | ❌       | `defaultPlural`  | 自定义复数处理函数                  |
| `missingWarn`    | `boolean`                                                  | ❌       | `true`           | 是否为缺失翻译输出控制台警告 |
| `missingHandler` | `(locale: string, key: string, routeName: string) => void` | ❌       | -                | 缺失翻译的自定义处理器        |

超出这些之外的任何内容都是框架特定的,会在各包对应页面中说明。

## 路由适配器抽象

所有框架包都使用**路由适配器模式**,将 i18n 功能与具体的路由实现解耦。这一设计带来:

- **灵活性** —— 你可以使用任何路由库,或完全不使用路由
- **框架独立** —— 路由逻辑保留在应用中,而不是 i18n 包里
- **精简核心** —— i18n 包本身保持小巧、专注

### 实现路由适配器

若要使用路由能力,需要实现 `I18nRoutingStrategy` 接口:

```typescript
interface I18nRoutingStrategy {
  getCurrentPath: () => string
  linkComponent?: Component
  push: (target: { path: string }) => void
  replace: (target: { path: string }) => void
  resolvePath?: (to: string | { path?: string }, locale: string) => string | { path?: string }
  getRoute?: () => { fullPath: string; query: Record<string, unknown> }
}
```

各包文档都包含针对主流路由库的完整适配器实现示例:

- **Vue**:Vue Router 适配器示例
- **React**:React Router 适配器示例
- **Solid**:Solid Router 适配器示例
- **Astro**:基于文件路由的适配器示例

## 核心特性

所有包都共享以下核心特性:

### 翻译方法

- `t()` —— 带参数插值的基础翻译
- `ts()` —— 始终返回字符串的翻译
- `tc()` —— 支持复数的翻译
- `tn()` —— 数字格式化
- `td()` —— 日期格式化
- `tdr()` —— 相对时间格式化
- `has()` —— 检查翻译键是否存在

### 语言管理

- **语言切换** —— 以编程方式更改当前语言
- **回退语言** —— 缺失翻译时自动回退
- **按路由的翻译** —— 页面级翻译组织
- **翻译缓存** —— 面向性能的智能缓存

### TypeScript 支持

所有包提供:

- 完整的 TypeScript 定义
- 类型安全的翻译键(需搭配类型生成器)
- IDE 中的 IntelliSense 支持
- 编译期错误检查
