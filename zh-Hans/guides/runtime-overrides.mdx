# 运行时 i18n 覆盖

当你需要一份构建产物在不同环境下运行并使用不同的语言默认值时(例如:不同租户的实例),请参考本指南。

## 运行时可覆盖的项

本模块支持在运行时安全地覆盖以下项:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

这些覆盖会应用在 `.nuxt/i18n.strategy.mjs` 与 `.nuxt/i18n.config.mjs` 中的构建期配置之上。

## 运行时不可覆盖的项

`strategy`(`no_prefix`、`prefix`、`prefix_except_default`、`prefix_and_default`)是构建期的关注点,因为它会影响生成的路由行为。

若在运行时传入 `strategy` 覆盖,将被忽略并输出警告。

## 基于 RuntimeConfig 的覆盖

在 `runtimeConfig.public.i18nRuntime` 下提供运行时的值:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## 环境变量覆盖

你也可以通过环境变量来配置覆盖:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES`(以逗号分隔,例如 `fr,it`)

同时支持以下别名回退:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## 校验规则

在运行时,本模块会对覆盖进行校验以避免出现损坏状态:

- 不能禁用所有语言。
- `defaultLocale` 必须指向一个已启用的语言。
- `fallbackLocale` 必须存在于已声明的语言中。

如果某项覆盖不合法,本模块会保留一个安全的值并记录警告。

## 多实例部署注意事项

此运行时特性用于在不重新构建的情况下按实例激活语言并设定默认值。

如果不同实例需要不同的 URL 策略(`no_prefix` 与 `prefix`),请为每种策略分别构建。

## 已禁用语言与静态 payload

`runtimeConfig.public.i18nRuntime.disabledLocales` 会更新路由、切换器以及 Nitro 的 payload **处理器**——但 Nitro 会在该处理器**之前**提供 `public/` 下的文件。

如果 `translationPayloads.publicAssets`(或 Node SSR 强制的 public 复制)已经写出了 `/_locales/\{page\}/\{locale\}/data.json`,运行时禁用无法隐藏该文件。建议在构建时使用 `locale.disabled: true`,这样预合并阶段不会为该语言输出静态 payload。
