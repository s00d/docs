# 运行时 i18n 覆盖

当你需要用一份构建产物在不同环境（例如不同租户实例）中运行、但各自使用不同语言默认值时，请参考本指南。

## 可在运行时覆盖的内容

模块支持对以下项进行安全的运行时覆盖：

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

这些覆盖会叠加在 `.nuxt/i18n.strategy.mjs` 和 `.nuxt/i18n.config.mjs` 提供的构建期配置之上。

## 不能在运行时覆盖的内容

`strategy`（`no_prefix`、`prefix`、`prefix_except_default`、`prefix_and_default`）属于构建期设置，因为它会影响所生成路由的行为。

如果传入运行时策略覆盖，会被忽略，并输出警告。

## 通过 RuntimeConfig 进行覆盖

在 `runtimeConfig.public.i18nRuntime` 下提供运行时值：

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## 通过环境变量进行覆盖

你也可以通过环境变量配置覆盖：

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES`（逗号分隔，例如 `fr,it`）

同时也支持回退别名：

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## 校验规则

在运行时，模块会校验覆盖以避免出现非法状态：

- 不能禁用所有语言。
- `defaultLocale` 必须指向一个已启用的语言。
- `fallbackLocale` 必须存在于已声明的语言列表中。

如果覆盖不合法，模块会保留安全值并输出警告。

## 多实例部署的注意事项

该运行时特性专为不重建即可按实例激活语言并调整默认值而设计。

如果各实例需要不同的 URL 策略（例如 `no_prefix` 与 `prefix`），请为每种策略分别构建。

## 已禁用的语言与静态 payload

`runtimeConfig.public.i18nRuntime.disabledLocales` 会更新路由、切换器以及 Nitro 的 payload **处理器**——但 Nitro 在到达该处理器**之前**会先服务 `public/` 下的文件。

如果 `translationPayloads.publicAssets`（或 Node SSR 强制的 public 副本）已经写出了 `/_locales/\{page\}/\{locale\}/data.json`，运行时禁用无法隐藏该文件。请在构建期使用 `locale.disabled: true`，让预合并阶段不再生成该语言的静态 payload。
