# 在 i18n 路由中排除静态文件

## 概述

默认情况下,nuxt-i18n-micro 会自动将常见的静态文件从 i18n 路由处理中排除。此外,你还可以配置自定义排除模式,以防止特定路径被 i18n 系统处理。

## 内置排除

本模块会自动排除以下文件类型和路径模式:

- **站点地图**:`/sitemap*.xml`、`/sitemap-en.xml` 等。
- **SEO 文件**:`/robots.txt`、`/favicon.ico`
- **PWA 文件**:`/manifest.json`、`/sw.js`、`/workbox-*.js`
- **静态资源**:扩展名为 `.xml`、`.txt`、`.ico`、`.json`、`.js`、`.css`、`.png`、`.jpg`、`.jpeg`、`.gif`、`.svg`、`.woff`、`.woff2`、`.ttf`、`.eot` 的文件
- **Nuxt 内部路径**:任何以 `__` 开头的路径(例如 `/__nuxt/`)

## 自定义排除模式

你可以使用 `excludePatterns` 选项自定义排除模式:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## 模式类型

### 字符串模式

- **精确匹配**:`'/api/health'` —— 精确匹配 `/api/health`
- **前缀匹配**:`'/admin'` —— 匹配 `/admin` 与 `/admin/dashboard`
- **通配符**:`'/api/*'` —— 匹配 `/api/users`,但不匹配 `/api/users/123`
- **深度通配符**:`'/admin/**'` —— 匹配 `/admin/users` 与 `/admin/users/123`

### 正则表达式

使用 RegExp 对象进行复杂的模式匹配:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## 使用场景

### SEO 文件

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API 路由

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### 管理后台

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### 静态资源

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## 工作原理

1. **服务端中间件**:一个 Nitro 中间件会首先运行,用于检查排除模式
2. **页面处理**:在页面解析过程中会跳过被排除的路径
3. **兜底路由**:兜底路由在处理之前也会检查排除项
4. **预渲染**:被排除的路径不会包含在预渲染路由中

## 性能影响

- 排除检查经过优化,会在请求生命周期的早期执行
- 内置模式使用高效的正则匹配
- 自定义模式会被缓存并复用
- 对被排除路径的性能开销极小

## 疑难排查

### 静态文件仍被拦截

1. **检查模式语法**:确保模式与实际路径结构精确匹配
2. **对复杂模式使用正则**:字符串通配符存在局限
3. **测试模式**:使用浏览器开发者工具确认实际的请求路径
4. **检查顺序**:确保排除模式定义在其他 i18n 配置之前

### 模式不生效

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### 调试模式

启用调试模式以查看排除处理过程:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

这样会在控制台输出排除决策日志。

## 从变通方案迁移

如果你之前使用 route rules 或中间件等变通方案,现在可以用 `excludePatterns` 替代它们:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

新方式更加可靠,可以在路由系统的多个层级同时生效。
