# 🔥 Firebase AppHosting 部署

## 📖 简介

Firebase AppHosting 是一个功能强大的平台,可用于以 serverless 架构部署 Nuxt 应用。但在部署使用 `nuxt-i18n-micro` 的应用时,你可能会遇到与翻译 JSON 文件如何被提供相关的特定问题。本指南提供了全面的解决方案,以确保你的翻译在生产环境中正常工作。

## ⚠️ 常见问题

### 翻译文件不生效

**现象:**

- ✅ 开发环境(`nuxt dev`)中翻译工作正常
- ❌ 部署到 Firebase AppHosting 后,JSON 文件能加载,但翻译不生效
- ❌ 控制台没有报错
- ❌ 网络面板中可见翻译文件,但 `Content-Type: text/html`(错误)而非 `application/json`

**根本原因:**

Firebase AppHosting(以及其他使用 Nitro 预渲染的平台)可能会以错误的 MIME 类型提供预渲染的 JSON 文件。当浏览器收到 `Content-Type: text/html` 的 JSON 文件时,无法正确解析,从而导致翻译静默失败。

## ✅ 解决方案

### 方案 1:配置 Route Rules(推荐)

最直接的方式是在 `nuxt.config.ts` 中为翻译路由显式添加响应头:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**优点:**

- ✨ 配置简单
- 🚀 通过合理的缓存提升性能
- 🔒 适用于所有部署平台

### 方案 2:自定义 API Base URL

如果你使用了自定义的 `apiBaseUrl`(仅路径前缀),请相应调整 route rules:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### 方案 3:Firebase 专属配置

在项目根目录创建或更新 `firebase.json` 文件:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```

## 🔍 调试

### 启用调试模式

添加调试日志以定位问题:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

它会输出以下方面的详细日志:

- 📝 翻译文件加载
- 🔄 缓存操作
- ⚠️ 加载错误

### 检查网络面板

1. 打开 DevTools → Network 面板
2. 按 "data.json" 过滤
3. 点击某个翻译文件请求
4. 检查**响应头**:
   - ✅ `Content-Type: application/json`(正确)
   - ❌ `Content-Type: text/html`(错误 —— 需要修复)

### 验证预渲染输出

构建后,请检查翻译文件是否已生成:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

每个页面下每种语言都应该看到 `data.json`。

## 🚀 构建配置

### Nitro 预设

对于 Firebase AppHosting,请确保使用正确的预设:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### 预渲染配置

配置预渲染以获得最佳性能:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

      { code: 'zh', iso: 'zh-CN', dir: 'ltr' },
      { code: 'ko', iso: 'ko-KR', dir: 'ltr' },
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,

## 🔄 部署流程

### 1. 准备构建

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. 部署到 Firebase

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. 验证部署

1. 访问部署后的站点
2. 打开 DevTools → Network 面板
3. 导航到某个页面
4. 检查 `/_locales/index/en/data.json`(或你的默认语言)加载信息:
   - 状态:200
   - Content-Type:application/json
   - 响应包含有效的 JSON

## 🔧 疑难排查

### 问题:翻译文件返回 404

**解决方案:** 确认翻译文件已被复制到输出目录:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### 问题:某些页面翻译正常,其他页面不正常

**解决方案:** 检查页面级翻译是否已生成:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

如果页面级翻译缺失,请确保 `disablePageLocales` 未被设置为 `true`:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### 问题:翻译加载较慢

**解决方案:** 优化缓存与预加载:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## ⚡ 性能优化

### 启用压缩

Firebase 会自动处理 Gzip/Brotli 压缩,但请确保你的构建已优化:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### 懒加载翻译

`Nuxt I18n Micro` 会自动按页面懒加载翻译。仅在需要时才加载翻译,从而减小初始打包体积。此功能开箱即用 —— 无需额外配置。

进一步优化:

- 使用 `disablePageLocales: false`(默认)以启用页面级翻译
- 让根级翻译保持精简
- 使用路由级翻译文件承载页面内容

<Tip>
自 **v3.0.0+** 起,模块会自动设置正确的 `Content-Type` 响应头。如果你仍遇到相关问题,请更新到最新版本:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
