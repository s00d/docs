# 🌐 Crowdin 集成指南

## 📖 简介

将 Crowdin 集成到项目中可以简化本地化和翻译流程,让跨多语言、多平台的翻译管理更为轻松。本指南将逐步介绍如何在项目中配置 Crowdin,包括基础配置、上传源文件与下载翻译。

## 🔧 安装与设置

要开始使用 Crowdin,你需要在本机全局安装 Crowdin CLI,并在项目目录内进行初始化。

### 📦 安装 Crowdin CLI

首先使用 npm 全局安装 Crowdin CLI:

```bash
npm install -g @crowdin/cli
```

### 🛠 在项目中初始化 Crowdin

在项目中运行以下命令初始化 Crowdin:

```bash
crowdin init
```

该命令将引导你完成配置过程,包括设置项目 ID、API 令牌以及其他配置细节。

## 🗂️ 配置指南

### 📄 Crowdin 配置文件(`crowdin.yml`)

Crowdin 配置文件(`crowdin.yml`)定义了源文件的映射方式以及翻译的存放位置。以下是一个示例配置:

```yml
'project_id': 'YOUR_PROJECT_ID'
'api_token': 'YOUR_API_TOKEN'
'base_path': './locales'
'base_url': 'https://api.crowdin.com'
'preserve_hierarchy': true

files:
  [
    { 'source': '/en.json', 'translation': '/%two_letters_code%.json' },
    { 'source': '/pages/**/en.json', 'translation': '/pages/**/%two_letters_code%.json' },
  ]
```

### 📂 关键配置参数

- **`project_id`**:你的 Crowdin 项目 ID,用于标识 Crowdin 中管理翻译的项目。
- **`api_token`**:用于身份验证的 API 令牌。请确保该令牌具备上传和下载翻译的相应权限。
- **`base_path`**:指定源文件的基础目录。在此示例中,翻译存放在 `./locales` 目录下。
- **`base_url`**:Crowdin API 的基础 URL。
- **`preserve_hierarchy`**:设为 `true` 时,Crowdin 将在项目中保留源文件的目录结构。

### 📂 Files 配置

`files` 部分将源文件映射到翻译文件将要存放的路径。例如:

- **源路径**:定义原始翻译文件的位置。
- **翻译路径**:指定翻译后的文件在 Crowdin 中的存储位置。可以使用像 `%two_letters_code%` 这样的占位符,在文件路径中动态设置语言代码。

## ⬆️ 上传源文件到 Crowdin

配置好 Crowdin 后,你可以使用以下命令上传源文件:

```bash
crowdin upload sources
```

该命令会将配置中指定的所有源文件上传到 Crowdin,供翻译使用。

## ⬇️ 从 Crowdin 下载翻译

在 Crowdin 中完成或更新翻译后,你可以使用以下命令将其下载到项目中:

```bash
crowdin download
```

该命令会从 Crowdin 获取最新翻译,并按照配置文件中指定的路径保存到本地。

## ⚙️ 最佳实践

### 🔑 一致的键命名

请确保所有文件中的翻译键保持一致,以避免混淆与重复。

### 🧹 定期维护

定期审查并清理未使用的翻译键,以保持文件的整洁与可维护性。

### 🛠 自动化上传与下载

将 Crowdin CLI 命令集成到 CI/CD 流水线中,自动化源文件上传与翻译下载,确保翻译始终保持最新。

按照本指南操作,你可以将 Crowdin 无缝集成到项目中,以高效、有序的方式管理国际化工作。
