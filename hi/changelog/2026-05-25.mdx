यह रिलीज़ **आंतरिक utilities को मॉड्यूलर बनाने**, एक **कॉम्पैक्ट serverless payload मोड** जोड़ने, और Nuxt, Node, Astro और DevTools में **साझा लॉजिक के पुन: उपयोग** पर केंद्रित है — सामान्य ऐप्स के लिए सार्वजनिक मॉड्यूल API को बदले बिना।

## नया क्या है? {#what’s-new}

### `@i18n-micro/utils` — फ़्रेमवर्क-स्वतंत्र utilities {#@i18n-micro/utils-—-framework-agnostic-utilities}

जो साझा लॉजिक पहले `src/runtime/utils/` और `src/module.ts` में बिखरा हुआ था, वह अब **granular subpath imports** (कोई भारी barrel नहीं, tree-shake के अनुकूल) वाले एक समर्पित workspace पैकेज में है:

- **Build** — `preMergeLocales`, `buildTranslationSourceLayers` (`@i18n-micro/utils/build`)
- **Payloads** — `translationPayloads` resolution, URL बनाना, fetch helpers, stats (`payload-config`, `payload-url`, `payload-fetch`, `payload-stats`)
- **Source मोड** — fallback chains, source फ़ाइल पाथ, रनटाइम merge (`merge-source`, `source-loader`)
- **रनटाइम helpers** — locale resolution, cookies, Accept-Language पार्सिंग, route/meta helpers (`resolve-locale`, `accept-language`, `cookie`, `route`, `route-pattern`, `runtime-config`)
- **साझा FS पाथ** — अनुवाद फ़ाइल वर्गीकरण, nested पेज पाथ (`parse-path`)

Nuxt मॉड्यूल `src/runtime/` में केवल पतला glue कोड रखता है और सिर्फ़ उन्हीं subpaths को import करता है जिनकी उसे ज़रूरत है।

### `@i18n-micro/hmr` — Dev में अनुवाद hot reload {#@i18n-micro/hmr-—-dev-translation-hot-reload}

Development HMR को `@i18n-micro/hmr` में अलग किया गया है:

- **`watcher`** — फ़ाइल बदलाव हैंडलिंग, कैश invalidation, dev में source/premerged merge
- **`generate-plugin`** — क्लाइंट-साइड HMR प्लगइन जनरेशन
- **`cache-keys`** — server/storage caches के लिए साझा `Symbol.for` keys

`translationPayloads.mode: 'premerged'` और `'source'` दोनों के साथ काम करता है।

### `translationPayloads.mode: 'source'` — कॉम्पैक्ट serverless deployments {#translationpayloads-mode-‘source’-—-compact-serverless-deployments}

serverless प्लेटफ़ॉर्म (Cloudflare Workers आदि) पर बड़े locale matrices के लिए नया payload मोड:

```typescript
export default defineNuxtConfig({
  i18n: {
    translationPayloads: {
      mode: 'source',
    },
  },
})
```

- पूरे pre-merged matrix के बजाय **कॉम्पैक्ट source फ़ाइलों** को Nitro assets में bundle करता है
- built-in `/_locales/:page/:locale/data.json` रूट के ज़रिए root, page और fallback locale chains को **रनटाइम पर** मर्ज करता है
- `publicAssets` और `prerenderRoutes` का डिफ़ॉल्ट `false` रखता है — तब आदर्श जब आप शुद्ध static hosting के बजाय Nitro/edge रनटाइम पर निर्भर हों

देखें [Deployment — serverless और Edge](/hi/guide/deployment#serverless-and-edge) और [Cache & Storage Architecture](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api)।

### इंटीग्रेशन पैकेजों में साझा utilities {#shared-utilities-across-integration-packages}

- **`@i18n-micro/node`** और **`@i18n-micro/astro`** — `@i18n-micro/utils/parse-path` के ज़रिए एकीकृत अनुवाद पाथ पार्सिंग और deep merge
- **`@i18n-micro/astro`** — `@i18n-micro/utils/accept-language` से `detectLocaleFromAcceptLanguage` (डुप्लिकेट पार्सर हटाया गया)
- **`@i18n-micro/devtools-ui`** — `merge-source` + `parse-path` helpers के ज़रिए virtual फ़ाइल पाथ
- **सर्वर locale detection** — Accept-Language हैंडलिंग को साझा utils के अनुरूप किया गया

### HMR और DevTools सुधार {#hmr-&-devtools-fixes}

- क्लाइंट HMR प्लगइन अब हटाए गए `$loadTranslations` के बजाय **`$loadPageTranslations`** (सही API) को कॉल करता है
- **premerged** और **source** मोड में translation watcher के लिए Playwright coverage

## Breaking changes (उन्नत / आंतरिक) {#breaking-changes-advanced-/-internal}

ये केवल उन प्रोजेक्ट्स को प्रभावित करते हैं जिन्होंने मॉड्यूल के **आंतरिक** पाथ import किए थे (सार्वजनिक API का हिस्सा नहीं):

- `src/runtime/utils/` से हटाए गए: `route-utils.ts`, `runtime-i18n-config.ts`, और अन्य utilities जो `@i18n-micro/utils/*` में ले जाई गईं
- `src/runtime/server/plugins/` से हटाया गया: inline HMR watcher/generator — अगर आपने dev tooling को fork किया है तो `@i18n-micro/hmr/*` इस्तेमाल करें
- **`nuxt-i18n-micro`** अब `@i18n-micro/utils` और `@i18n-micro/hmr` workspace पैकेजों पर निर्भर है (मॉड्यूल के साथ अपने आप इंस्टॉल होते हैं)

सामान्य `nuxt.config` + composables का उपयोग अपरिवर्तित है।

## यह क्यों मायने रखता है {#why-it-matters}

- **छोटे serverless bundles** — `source` मोड हर locale × page के लिए pre-merged फ़ाइल भेजने से बचाता है
- **सत्य का एकल स्रोत** — पाथ पार्सिंग, merge, locale detection और payload config के लिए एक ही implementation
- **आसान रखरखाव** — फ़्रेमवर्क-स्वतंत्र कोड का `@i18n-micro/utils` में परीक्षण होता है (50+ unit tests) और हर जगह पुन: उपयोग होता है
- **बेहतर dev UX** — HMR लॉजिक अलग, परीक्षण योग्य और सभी payload मोड में एकसमान है
