यह रिलीज़ **`useI18nHead`** जोड़ती है — बिल्ट-इन `02.meta` प्लगइन के ऊपर i18n SEO ओवरराइड के लिए एक पेज-स्तरीय composable। किसी कस्टम meta प्लगइन या `meta: false` के बिना प्रति रूट `hreflang`, canonical, `og:url` और Open Graph टैग कस्टमाइज़ करें।

## नया क्या है? {#what’s-new}

### `useI18nHead` Composable {#usei18nhead-composable}

जब `meta: true` (डिफ़ॉल्ट) हो, तो किसी भी पेज में `useI18nHead` कॉल करें। मॉड्यूल हर रूट अपडेट पर `useLocaleHead` के बाद आपके इनपुट को मर्ज करता है:

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

स्टैटिक ऑब्जेक्ट, रिएक्टिव getter, `meta` / `link` append, बिल्ट-इन समूहों के लिए `replace`, और स्वतः-जनित टैग हटाने के लिए `disable` समर्थित हैं। देखें [`useI18nHead`](/hi/composables/useI18nHead)।

### `mergeI18nHead` यूटिलिटी (`@i18n-micro/utils`) {#mergei18nhead-utility-@i18n-micro/utils}

फ़्रेमवर्क-स्वतंत्र मर्ज लॉजिक `@i18n-micro/utils/merge-i18n-head` में है — इसे `02.meta` प्लगइन उपयोग करता है और इसे अलग से टेस्ट किया जा सकता है। टाइप्स (`I18nHeadInput`, `I18nHeadLink`, `I18nHeadMeta`) `@i18n-micro/types` से एक्सपोर्ट किए जाते हैं।

### प्लगइन इंटीग्रेशन {#plugin-integration}

- **`02.meta`** — `useHead` के माध्यम से `useLocaleHead` आउटपुट को `useI18nHead` की पेज स्थिति के साथ मर्ज करता है
- **`01.plugin`** — रूट नाम बदलने पर `resetPageHead()` के माध्यम से पेज ओवरराइड रीसेट करता है (composable के साथ साझा स्थिति)

### दस्तावेज़ और टेस्ट {#documentation-&-tests}

- नई गाइड: CMS/लेख उदाहरणों के साथ [`useI18nHead`](/hi/composables/useI18nHead)
- अपडेट किए गए [SEO](/hi/guide/seo) और [`useLocaleHead`](/hi/composables/useLocaleHead) — कब कौन-सा API उपयोग करें
- Playwright + Vitest कवरेज: SSR, SPA नेविगेशन, रीलोड, `nuxi generate`, आंशिक alternates, `x-default`, रिएक्टिव क्लाइंट लोड

## सामान्य उपयोग के मामले {#typical-use-cases}

| परिदृश्य                                     | तरीका                                                       |
| -------------------------------------------- | -------------------------------------------------------------- |
| आंशिक अनुवादों वाला ब्लॉग/CMS           | API लोकेल से `replace.hreflang` + `replace.ogAlternates`   |
| CMS से कस्टम canonical                    | `replace.canonical` + `replace.ogUrl`                          |
| केवल लैंडिंग पेज OG                         | `meta: [{ property: 'og:title', ... }]` — मॉड्यूल hreflang बनाए रखें |
| किसी पेज पर hreflang नहीं                        | `disable: ['hreflang', 'x-default']`                           |
| कस्टम प्लगइन (`i18nManualHreflang`) बदलें | प्रति कंटेंट पेज `useI18nHead` + `meta: true`                  |

**JSON-LD** `useHead({ script: [...] })` में ही रहता है — `useI18nHead` स्ट्रक्चर्ड डेटा जनरेट नहीं करता।

## ब्रेकिंग बदलाव {#breaking-changes}

मानक `nuxt.config` उपयोग के लिए कोई नहीं। नया composable और utils subpath केवल जोड़ हैं।

## यह क्यों महत्वपूर्ण है {#why-it-matters}

- प्रति-लोकेल URL वाले CMS पोस्ट, समाचार या गाइड के लिए **कोई कस्टम meta प्लगइन नहीं**
- **एकल पाइपलाइन** — एक ही `useHead` कॉल में मॉड्यूल डिफ़ॉल्ट + पेज ओवरराइड
- **टाइप-सेफ़** — `buildArticleHead(content)` जैसे हेल्पर के लिए `I18nHeadInput`
