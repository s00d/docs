`@i18n-micro/vitepress` किसी VitePress साइट में रनटाइम डिक्शनरी जोड़ता है: मार्कडाउन के अंदर `$t` और `<I18nT>`, पाथ हेल्पर्स और SEO टैग, जो [`@i18n-micro/vue`](/hi/integrations/vue-package) पर बने हैं। इसका उपयोग तब करें जब समान UI स्ट्रिंग्स कई पेजों पर दिखाई देती हैं और आप उन्हें हर लोकेल के लिए दोहराना नहीं चाहते। लोकेल VitePress के अपने पाथ लोकेल (`/`, `/fr/`) का अनुसरण करता है।

## इसका उपयोग कब करें {#when-to-use-it}

| आवश्यकता | समाधान |
|------|----------|
| डुप्लिकेट `.md`, URL प्रीफ़िक्स | VitePress `locales` |
| रनटाइम `$t` / कंपोनेंट्स / पाथ सिंक / SEO head | `@i18n-micro/vitepress` |
| डिफ़ॉल्ट थीम के क्रोम लेबल (`docFooter`, सर्च UI) | प्रति लोकेल आपका अपना `themeConfig` |

<Tip>

**प्लेग्राउंड** — [`packages/vitepress/playground`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/vitepress/playground) — `pnpm -C packages/vitepress/playground dev`

</Tip>

## इंस्टॉल करें {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vitepress
```

```bash npm
npm install @i18n-micro/vitepress
```

```bash yarn
yarn add @i18n-micro/vitepress
```

</CodeGroup>

पीयर डिपेंडेंसी: `vitepress` `>=1.0.0 || >=2.0.0-alpha.0`, `vue` `^3.3.0`। Node स्क्रिप्ट्स `@i18n-micro/node` का उपयोग करती हैं, जो पैकेज के साथ इंस्टॉल होता है और `/node` के माध्यम से फिर से एक्सपोर्ट किया जाता है। प्रकाशित टाइप्स को `skipLibCheck: false` के साथ Vue 3.5.5 या बाद के संस्करण की आवश्यकता होती है; `skipLibCheck: true` के साथ, जो सामान्य टेम्पलेट सेटिंग है, पुराने संस्करण भी कंपाइल होते हैं।

## सेटअप {#setup}

```
locales/en.json
locales/fr.json
locales/pages/guide/demo/en.json   # optional page-scoped
locales/pages/guide/demo/fr.json
```

पेज फ़ाइलें Nuxt/Astro की तरह ही रूट नामों से मैप होती हैं (`guide/demo` → `guide-demo`)।

### 1. कॉन्फ़िग — `@i18n-micro/vitepress/config` {#1-config-—-@i18n-micro/vitepress/config}

```ts
// .vitepress/config.mts
import { defineConfig } from 'vitepress'
import { withI18n, buildVitePressLocales } from '@i18n-micro/vitepress/config'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English', og: 'en_US' },
  { code: 'fr', iso: 'fr-FR', displayName: 'Français', og: 'fr_FR' },
]
const defaultLocale = 'en'

export default defineConfig(
  withI18n(
    {
      locales: buildVitePressLocales(locales, defaultLocale),
      // themeConfig.i18nRouting is injected automatically
    },
    {
      locale: defaultLocale,
      defaultLocale,
      locales,
      translationDir: 'locales',
      metaBaseUrl: 'https://example.com', // optional SEO head
    },
  ),
)
```

### 2. थीम — `@i18n-micro/vitepress/theme` {#2-theme-—-@i18n-micro/vitepress/theme}

```ts
// .vitepress/theme/index.ts
import DefaultTheme from 'vitepress/theme'
import { defineI18nTheme } from '@i18n-micro/vitepress/theme'

export default defineI18nTheme(DefaultTheme)
```

प्रारंभिक लोकेल इंस्टॉल से पहले वर्तमान पाथ से लिया जाता है (`/fr/…` पर डिफ़ॉल्ट-लोकेल की झलक नहीं दिखती)।

### उन्नत: मैनुअल `createI18n` {#advanced-manual-createi18n}

क्लाइंट के लिए एक फ़ैक्टरी: Vue प्लगइन + पाथ मेथड्स + `enhanceApp` (कोई अलग राउटर हेल्पर एक्सपोर्ट नहीं)।

```ts
import { createI18n, messagesFromGlob } from '@i18n-micro/vitepress'

const i18n = createI18n({
  locale: 'en',
  defaultLocale: 'en',
  locales: [{ code: 'en' }, { code: 'fr' }],
  messages: messagesFromGlob(import.meta.glob('../../locales/*.json', { eager: true })),
})

i18n.localizePath('/guide', 'fr')
// in theme enhanceApp:
i18n.enhanceApp({ app, router })
```

### Node स्क्रिप्ट्स — `@i18n-micro/vitepress/node` {#node-scripts-—-@i18n-micro/vitepress/node}

`@i18n-micro/node` के `createI18n` / `loadTranslations` का उपयोग करता है (Astro और CLI की तरह), फिर `BaseI18n.extend` के साथ VitePress पाथ मेथड्स जोड़ता है:

```ts
import { createI18n } from '@i18n-micro/vitepress/node'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  translationDir: './locales',
  locales: ['en', 'fr'],
  defaultLocale: 'en',
})
await i18n.loadTranslations()
i18n.t('cta.readMore')
i18n.localizePath('/guide', 'fr')
```

पाथ के बिना सादा Node: `import { createI18n } from '@i18n-micro/node'`।

## पेज के अंदर अनुवाद {#in-page-translations}

हर VitePress मार्कडाउन फ़ाइल एक Vue SFC है।

### ग्लोबल कंपोनेंट्स और `$t` (मार्कडाउन में अनुशंसित) {#global-components-and-$t-recommended-in-markdown}

`createI18n` / `defineI18nTheme` `@i18n-micro/vue` इंस्टॉल करते हैं, जो `I18nT` / `I18nLink` / `I18nGroup` / `I18nSwitcher` और `$t` / `$tc` / `$ts` रजिस्टर करता है।

```md
{{ $t('cta.readMore') }}

<I18nT keypath="greeting" :params="{ name: 'VitePress' }" />

<I18nLink to="/guide/demo">Demo</I18nLink>
```

### `<script setup>` में `useI18n` {#usei18n-in-<script-setup>}

```md
<script setup>
import { useI18n } from '@i18n-micro/vitepress'
const { t, tc, locale, localePath, switchLocale } = useI18n()
</script>

# {{ t('section.title') }}
```

## भाषा ड्रॉपडाउन {#language-dropdown}

जब `locales` में एक से अधिक प्रविष्टियाँ होती हैं, तो VitePress अपना स्वयं का भाषा मेनू (`VPNavBarTranslations`) दिखाता है। `withI18n` `themeConfig.i18nRouting` को जोड़ता है ताकि ग्लोब `<I18nSwitcher>` / पाथ हेल्पर्स से मेल खाए।

`<I18nSwitcher>` का उपयोग केवल कस्टम लेआउट में करें, डिफ़ॉल्ट ग्लोब के बगल में नहीं।

## SSR टिप्पणियाँ {#ssr-notes}

- प्रीरेंडर पर लोकेल URL पाथ से आता है, कुकीज़ से नहीं।
- थीम कोड को इंपोर्ट के समय `window` को नहीं छूना चाहिए।
- `defineI18nTheme` को `/theme` से इंपोर्ट करें ताकि Node कॉन्फ़िग मूल्यांकन कभी `virtual:i18n-micro/*` लोड न करे।

## API सतह {#api-surface}

| एक्सपोर्ट | भूमिका |
|--------|------|
| `createI18n` (`.`) | क्लाइंट: Vue प्लगइन + पाथ मेथड्स + `enhanceApp` |
| `getLocaleFromPath` / `stripSiteBase` / `routeNameFromPath` (`.`) | `syncWithVitePress: false` होने पर मैनुअल लोकेल सिंक |
| `createI18n` (`/node`) | Node: `@i18n-micro/node` + पाथ मेथड्स |
| `defineI18nTheme` (`/theme`) | बिना बॉयलरप्लेट वाली थीम |
| `withI18n` (`/config`) | कॉन्फ़िग + वर्चुअल मॉड्यूल + वैकल्पिक SEO |
| `buildVitePressLocales` (`/config`) | `Locale[]` से VitePress `locales` बनाएँ |
| `buildVitePressLocaleHead` (`/config`) | मैनुअल SEO head (`metaBaseUrl` द्वारा भी उपयोग किया जाता है) |
| `messagesFromGlob` | `createI18n` के लिए वैकल्पिक glob → messages मैप |
| `useI18n` / `I18nT` / … | `@i18n-micro/vue` से फिर से एक्सपोर्ट किए गए |
| `BaseI18n.extend` (`@i18n-micro/core`) | किसी भी i18n इंस्टेंस पर कस्टम मेथड्स जोड़ें |

## OpenAPI-शैली की साइटें (इंटीग्रेशन लॉक) {#openapi-style-sites-integration-locks}

रिग्रेशन सूट: `packages/vitepress/tests/integration-openapi.test.ts` (डीप पाथ, `base=/openapi_docs/`, सिंक बंद + मैनुअल लोकेल, Node जनरेटर, SEO)।

| पैटर्न | यह करें |
|---------|---------|
| डीप `/…/{spec}/{op}` पेज, केवल रूट UI JSON | डिफ़ॉल्ट `syncWithVitePress: true` को प्राथमिकता दें (पेज डिक्शनरी न होने पर `setRoute('index')` बनाए रखता है) **या** `syncWithVitePress: false` + `getLocaleFromPath` |
| पेज डिक्शनरी के बिना कभी `setRoute(deepName)` कॉल न करें | रूट UI कुंजियाँ `setRoute('index')` तक गायब हो जाती हैं |
| जनरेटर / `getTranslation` | `/node` से `createI18n` + `await loadTranslations()` + `i18n.t(key)` (`i18n.locale` सेट करें) |
| `transformPageData` में कस्टम canonical | `withI18n` को `meta: false` पास करें (दोहरे टैग से बचें) |
| साइट base के साथ पैकेज SEO | `metaBaseUrl` + VitePress `base` → पूर्ण URL में base शामिल होता है |
| पुराने पैकेज बिल्ड से नाम बदलना | `withI18nMicro` → `withI18n`, `createVitePressI18n` → `createI18n`, `loadMessages` → node `createI18n` |
