`@i18n-micro/react` और `@i18n-micro/preact` फ़्रेमवर्क-स्वतंत्र [रनटाइम](/hi/integrations/runtime-package) को एक provider, एक `useI18n()` hook और चार कॉम्पोनेंट में लपेटते हैं। इनका उपयोग ऐसे React या Preact ऐप में करें जो Nuxt से नहीं बना है। दोनों पैकेज का API एक जैसा है; [Preact](#preact) ब्लॉक कुछ अंतरों को सूचीबद्ध करता है, और साझा मॉडल [फ़्रेमवर्क](/hi/integrations/overview) में है।

## इंस्टॉल करें {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/react
```

```bash npm
npm install @i18n-micro/react
```

```bash yarn
yarn add @i18n-micro/react
```

</CodeGroup>

Peer dependencies: `react` `^18.0.0 || ^19.0.0`; `react-dom` (वैकल्पिक, रेंडरिंग के लिए); `react-router-dom` `^6.0.0 || ^7.0.0` (वैकल्पिक, केवल `@i18n-micro/react/router` के लिए)। React 19.3 और 18.3, React Router 7.18 और 6.30 पर परीक्षण किया गया।

## सेटअप {#setup}

```tsx
// src/main.tsx
import { createRoot } from 'react-dom/client'
import { createI18n, I18nProvider } from '@i18n-micro/react'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

createRoot(document.getElementById('root')!).render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
    <App />
  </I18nProvider>,
)
```

<Warning>

इंस्टेंस एक बार बनाएँ, मॉड्यूल स्तर पर या किसी `useState` initializer में, कभी भी कॉम्पोनेंट बॉडी में नहीं।

</Warning>

`<I18nProvider>` `i18n`, `locales`, `defaultLocale` और `routingStrategy` लेता है:

- छोड़ा गया prop किसी बाहरी provider का मान रखता है, इंस्टेंस सहित।
- यदि कोई इंस्टेंस ही नहीं है, तो यह उनके साथ दिए गए `createI18n` विकल्पों से एक बनाता है, ताकि props सादा डेटा रहें: `<I18nProvider locale="de" messages={messages}>`।
- नया `locale` prop उस रेंडर के `messages` के साथ एक नया इंस्टेंस बनाता है। ऐसा इंस्टेंस कॉम्पोनेंट में रहता है: यदि mount के दौरान उसके ऊपर कुछ suspend होता है, तो React उसे फेंक देता है, उसमें जोड़ी गई हर चीज़ के साथ।

`routeMessages` सहित सभी `createI18n` विकल्प [इंस्टेंस](/hi/integrations/overview#the-instance) में हैं।

## अनुवाद करें {#translate}

```tsx
import { useI18n } from '@i18n-micro/react'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' })}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

`useI18n()` लौटाता है:

| समूह | सदस्य |
| --- | --- |
| अनुवाद | `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` |
| लोकेल और रूट | `locale`, `fallbackLocale`, `currentRoute`, `setLocale`, `setRoute`, `getRoute`, `getLocales`, `defaultLocale()`, `getLocaleName` |
| रूटिंग | `switchLocale`, `localePath`, `localeRoute` |
| शब्दकोश | `addTranslations`, `addRouteTranslations`, `clearCache` |

- कॉम्पोनेंट तब फिर से रेंडर होता है जब लोकेल, रूट या कोई पठनीय शब्दकोश बदलता है, और जब provider को नया `locales` या `routingStrategy` ऑब्जेक्ट मिलता है। ऐसे लोकेल का शब्दकोश जो न सक्रिय है न फ़ॉलबैक, कुछ भी रेंडर नहीं करता।
- `t` और अन्य अनुवाद मेथड केवल store के साथ बदलते हैं, इसलिए वे `memo` और effect deps में सुरक्षित हैं।

`useT` एक मान के रूप में एक स्ट्रिंग है। कॉम्पोनेंट केवल तब रेंडर होता है जब वह स्ट्रिंग बदलती है, provider के अन्य props के साथ चाहे जो हो; `<I18nT>` भी उन पर निर्भर नहीं करता:

```tsx
const title = useT('page.title')
```

किसी भी समय और शब्दकोश लोड करें:

```tsx
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

useEffect(() => {
  import('./locales/de.json').then((m) => addTranslations('de', m.default))
  addRouteTranslations('en', 'about', { title: 'About us' })
  setRoute('about') // t('title') now reads the 'about' dictionary first
}, [])
```

इंस्टेंस में `fetch` पर JSON के लिए `loadFromUrl(url, { locale, routeName })` भी है।

## लोकेल बदलें {#switch-locale}

```tsx
const { setLocale, switchLocale } = useI18n()

setLocale('de') // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

बदलने से कुछ भी लोड नहीं होता; पहले लोकेल का शब्दकोश जोड़ें। React के लिए store write समकालिक होता है, `startTransition` के अंदर भी, इसलिए जो कॉम्पोनेंट गायब शब्दकोश पर suspend होता है वह अपना fallback दिखाएगा। `useLocaleSwitch` पहले लोड करता है और शब्दकोश आने तक पुराना UI बनाए रखता है:

```tsx
const [switchTo, pending] = useLocaleSwitch((locale) => i18n.loadFromUrl(`/locales/${locale}.json`, { locale }))

<button disabled={pending} onClick={() => switchTo('de')}>Deutsch</button>
```

अंतिम कॉल जीतती है। विफल लोड reject होता है और लोकेल को पहले जैसा छोड़ देता है।

`<I18nGroup>` किसी render-prop child को प्रीफ़िक्स वाला `t` देता है। उसके अंदर `<I18nT>` और `t()` प्रीफ़िक्स नहीं होते:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## रूटिंग {#routing}

React Router एडेप्टर एक subpath में रहता है ताकि मुख्य entry कभी `react-router-dom` को इम्पोर्ट न करे। इसे `useLocation()` और `useNavigate()` चाहिए, इसलिए इसे राउटर के अंतर्गत किसी कॉम्पोनेंट के अंदर बनाएँ:

```tsx
// src/App.tsx
import { useMemo } from 'react'
import { BrowserRouter, Route, Routes, useLocation, useNavigate } from 'react-router-dom'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/react'
import { createReactRouterAdapter } from '@i18n-micro/react/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Localized() {
  const location = useLocation()
  const navigate = useNavigate()
  // memoized: a new object on every render re-renders every `useI18n()` consumer
  const routingStrategy = useMemo(() => createReactRouterAdapter(locales, 'en', location, navigate), [location, navigate])
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      <Routes>
        <Route path="/:locale?" element={<Home />} />
        <Route path="/:locale?/about" element={<About />} />
      </Routes>
    </I18nProvider>
  )
}

export default function App() {
  return (
    <BrowserRouter>
      <Localized />
    </BrowserRouter>
  )
}
```

एडेप्टर डिफ़ॉल्ट को छोड़कर हर लोकेल पर प्रीफ़िक्स लगाता है (`/about`, `/de/about`) और `<I18nLink>` को React Router के `<Link>` के रूप में रेंडर करता है। URL से लोकेल स्वयं सेट करें (उदाहरण के लिए किसी effect में `useParams().locale` से)। किसी भी अन्य राउटर के लिए `getCurrentPath`, `push` और `replace` (सभी आवश्यक) के साथ एक एडेप्टर लिखें — देखें [राउटर एडेप्टर](/hi/integrations/overview#router-adapter)।

## SSR {#ssr}

`renderToString` काम करता है: `useI18n()` के पास एक server snapshot है। हर अनुरोध के लिए एक इंस्टेंस बनाएँ और रेंडर करने से पहले उसके शब्दकोश जोड़ें, ताकि अलग-अलग लोकेल के अनुरोध स्टेट साझा न करें, या provider को सादा डेटा पास करें।

### Hydration {#hydration}

संख्याएँ, बहुवचन और टेक्स्ट जैसे हैं वैसे ही hydrate होते हैं। तारीख टाइम ज़ोन पर निर्भर करती है और सापेक्ष तारीख घड़ी पर: सर्वर और ब्राउज़र में `timeZone` सेट करें, और `tdr` के लिए `now` से ब्राउज़र को सर्वर का समय दें। `date` या `relativeDate` के साथ `<I18nT>` `suppressHydrationWarning` सेट करता है, इसलिए अंतर से hydration विफल नहीं होता, लेकिन टेक्स्ट बदलने तक सर्वर का टेक्स्ट बना रहता है। यह केवल एक स्तर तक पहुँचता है: जो `children` अनुवाद को किसी एलिमेंट में लपेटते हैं वे अंतर पर अब भी विफल होते हैं, इसलिए उन्हें वही `timeZone` दें।

### Server Components {#server-components}

पैकेज अपने client कोड को `'use client'` से चिह्नित करता है। `@i18n-micro/react/server` में `createI18n` और hooks के बिना एक `I18nT` है जो इंस्टेंस को prop के रूप में लेता है, ताकि टेक्स्ट client बंडल से बाहर रहे। `react-server` condition के अंतर्गत, जैसे Next.js app router में, मुख्य entry भी उसी पर हल होती है, लेकिन TypeScript डिफ़ॉल्ट रूप से यह नहीं जानता: `/server` से इम्पोर्ट करें। `@i18n-micro/react/client` हमेशा client entry देता है।

```tsx
// app/[locale]/layout.tsx: a server component
import { cache } from 'react'
import { createI18n, I18nT } from '@i18n-micro/react/server'
import { I18nProvider } from '@i18n-micro/react/client'
import { loadMessages } from './messages'

const getI18n = cache(async (locale: string) => createI18n({ locale, messages: await loadMessages(locale) }))

export default async function Layout({ params, children }) {
  const { locale } = await params
  const i18n = await getI18n(locale)
  return (
    <I18nProvider locale={locale} messages={{ [locale]: i18n.resolveTranslations() }}>
      <h1>
        <I18nT i18n={i18n} keypath="title" />
      </h1>
      {children}
    </I18nProvider>
  )
}
```

`react-server-dom-webpack` के माध्यम से रेंडर किया गया; किसी Next.js ऐप पर इसे स्वयं नहीं चलाया गया है।

## Preact {#preact}

`@i18n-micro/preact` उसी सोर्स से, स्वयं Preact पर, `preact/compat` के बिना बनाया गया है: वही इंस्टेंस, provider, hooks और कॉम्पोनेंट। अंतर:

| | React | Preact |
| --- | --- | --- |
| Peer dependency | `react` (+ वैकल्पिक `react-router-dom`) | `preact` `^10.0.0 \|\| ^11.0.0`, 10.29 और 11.1 पर परीक्षण किया गया |
| इंस्टेंस क्लास | `ReactI18n` | `PreactI18n` |
| राउटर एडेप्टर | `/router` से `createReactRouterAdapter` | `/router` से `createBrowserHistoryAdapter(locales, defaultLocale, ssrUrl?)` |
| री-रेंडर | `useSyncExternalStore` | एक layout-effect subscription जो store को फिर से जाँचता है |
| Server Components | `/server`, `/client` | कोई नहीं |

`createBrowserHistoryAdapter` किसी भी History API राउटर (wouter, preact-router) के साथ काम करता है: `push` और `replace` `history.pushState` / `replaceState` कॉल करते हैं और `popstate` dispatch करते हैं, और `<I18nLink>` एक सादा `<a>` रेंडर करता है जो `push` के माध्यम से नेविगेट करता है। सर्वर पर कोई एड्रेस बार नहीं होता: अनुरोध का URL `ssrUrl` के रूप में पास करें, वरना लिंक और स्विचर `/` की तरह रेंडर होते हैं। ब्राउज़र में एड्रेस बार जीतता है।

```tsx
// src/main.tsx
import { render } from 'preact'
import { createI18n, I18nProvider } from '@i18n-micro/preact'
import { createBrowserHistoryAdapter } from '@i18n-micro/preact/router'
import { App } from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={createBrowserHistoryAdapter(locales, 'en')}>
    <App />
  </I18nProvider>,
  document.getElementById('app')!,
)
```
