`@i18n-micro/astro` Astro पेजों का अनुवाद सर्वर पर करता है: एक middleware URL से लोकेल चुनता है और `Astro.locals` में प्रति-रिक्वेस्ट एक इंस्टेंस रखता है, और `useI18n(Astro)` उसे पढ़ता है। इसका उपयोग ऐसी Astro साइट में करें जिसे लोकेल-प्रीफ़िक्स वाले URL (`/about`, `/fr/about`) और साझा JSON डिक्शनरी चाहिए। आपको `.astro` कंपोनेंट, विज़िटर की भाषा पर होम-पेज रीडायरेक्ट, `hreflang` टैग, और [islands](/hi/integrations/astro-islands) के लिए props मिलते हैं।

## इंस्टॉल करें {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/astro
```

```bash npm
npm install @i18n-micro/astro
```

```bash yarn
yarn add @i18n-micro/astro
```

</CodeGroup>

Peer निर्भरताएँ: `astro` `^5.0.0 || ^6.0.0 || ^7.0.0`। वैकल्पिक, केवल [islands](/hi/integrations/astro-islands) के लिए: `vue` `^3.3.0`, `react` `^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`, `preact` `^10.0.0 || ^11.0.0`, `svelte` `^4.0.0 || ^5.0.0`।

## सेटअप {#setup}

इंटीग्रेशन जोड़ें। यह आपकी डिक्शनरी को सर्वर में बंडल करता है और middleware इंस्टॉल करता है, इसलिए `src/middleware.ts` की आवश्यकता नहीं है:

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import node from '@astrojs/node'
import { i18nIntegration } from '@i18n-micro/astro'

export default defineConfig({
  output: 'server',
  adapter: node({ mode: 'standalone' }),
  integrations: [
    i18nIntegration({
      locale: 'en',
      fallbackLocale: 'en',
      locales: [
        { code: 'en', iso: 'en-US', displayName: 'English' },
        { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
        { code: 'fr', iso: 'fr-FR', displayName: 'Français' },
      ],
      translationDir: 'src/locales',
    }),
  ],
})
```

बिल्ड के समय डिक्शनरी कोड बन जाती हैं: सर्वर डिस्क से कुछ नहीं पढ़ता, इसलिए यह edge (Cloudflare, Vercel Edge) पर भी चलता है। `astro dev` में किसी फ़ाइल में किया गया बदलाव अगली रिक्वेस्ट पर लागू होता है।

### इंटीग्रेशन विकल्प {#integration-options}

| विकल्प | डिफ़ॉल्ट | नोट्स |
| --- | --- | --- |
| `locale` | आवश्यक | डिफ़ॉल्ट लोकेल। |
| `fallbackLocale` | `locale` | |
| `locales` | `[]` | पूर्ण `Locale` ऑब्जेक्ट। `disabled` लोकेल किसी URL का लोकेल नहीं होता और न ही रीडायरेक्ट लक्ष्य। `iso` वह टैग है जिसके अनुसार बहुवचन तय होते हैं जब कोड स्वयं टैग न हो (`ua` → `uk-UA`)। |
| `translationDir` | कोई नहीं | सर्वर में बंडल किया गया फ़ोल्डर, प्रोजेक्ट रूट के सापेक्ष। |
| `disablePageLocales` | `false` | पेज फ़ाइलें रूट अनुवाद मानी जाती हैं। |
| `autoDetect` | `true` | होम-पेज रीडायरेक्ट, देखें [लोकेल डिटेक्शन](#locale-detection)। |
| `redirectToDefault` | `false` | जब कुछ भी किसी अन्य लोकेल को प्राथमिकता नहीं देता, तब भी `/` रीडायरेक्ट करता है। |
| `localeCookie` | `'i18n-locale'` | `null` कुकी को अक्षम करता है। |
| `missingWarn` | `false` | |
| `middleware` | `true` | `false`: middleware स्वयं लिखें, नीचे देखें। |

रनटाइम सेटिंग्स `virtual:i18n-micro/config` में प्रकाशित होती हैं (`config.base` Astro का `base` है, `config.localeCodes` सक्षम कोड), डिक्शनरी `virtual:i18n-micro/messages` में।

### आपका अपना middleware {#your-own-middleware}

बहुवचन नियम, missing-key हैंडलर और router adapter कॉन्फ़िग प्रोसेस से सर्वर बंडल तक नहीं पहुँच सकते। इनके लिए, `middleware: false` पास करें और `src/middleware.ts` लिखें। तब Astro का `i18n` कॉन्फ़िग आपके लिए `routing: 'manual'` के साथ सेट हो जाता है, इसलिए `Astro.currentLocale` और `astro:i18n` काम करते हैं। Astro `src/middleware.ts` के बिना यह सेटिंग अनुमति नहीं देता, इसलिए इंटीग्रेशन के अपने middleware के साथ ये काम नहीं करते।

```ts
// src/middleware.ts
import { config } from 'virtual:i18n-micro/config'
import { messages } from 'virtual:i18n-micro/messages'
import { createAstroRouterAdapter, createI18n, createI18nMiddleware, localeIsoMap } from '@i18n-micro/astro'

const i18n = createI18n({
  locale: config.defaultLocale,
  fallbackLocale: config.fallbackLocale,
  localeIso: localeIsoMap(config.locales),
  messages: messages.root,
  routeMessages: messages.routes,
  plural: myPluralRule,
})

export const onRequest = createI18nMiddleware({
  i18n,
  defaultLocale: config.defaultLocale,
  locales: config.localeCodes,
  localeObjects: config.locales,
  autoDetect: config.autoDetect,
  redirectToDefault: config.redirectToDefault,
  localeCookie: config.localeCookie,
  base: config.base,
  routingStrategy: createAstroRouterAdapter(config.locales, config.defaultLocale),
})
```

इसके बजाय रनटाइम पर फ़ोल्डर पढ़ने के लिए, `loadTranslationsFromDir` और `loadTranslationsIntoI18n` `@i18n-micro/astro/node` में हैं (केवल Node)।

### Middleware विकल्प {#middleware-options}

| विकल्प | डिफ़ॉल्ट | नोट्स |
| --- | --- | --- |
| `i18n` | आवश्यक | ग्लोबल इंस्टेंस; हर रिक्वेस्ट को `i18n.fork(locale)` मिलता है, जिसकी लागत समान रहती है चाहे कितनी भी डिक्शनरी हों। |
| `defaultLocale` | आवश्यक | |
| `locales` | आवश्यक | लोकेल कोड। |
| `localeObjects` | `{ code }` के रूप में `locales` | कंपोनेंट और SEO के लिए पूर्ण `Locale` ऑब्जेक्ट। |
| `autoDetect` | `true` | होम-पेज रीडायरेक्ट, देखें [लोकेल डिटेक्शन](#locale-detection)। |
| `redirectToDefault` | `false` | जब कुछ भी किसी अन्य लोकेल को प्राथमिकता नहीं देता, तब भी `/` रीडायरेक्ट करता है, डिफ़ॉल्ट लोकेल के होम पर जैसा routing strategy उसे resolve करती है। |
| `localeCookie` | `'i18n-locale'` | `null` कुकी को अक्षम करता है। |
| `routingStrategy` | डिफ़ॉल्ट को छोड़कर prefix | Router adapter। जो मेथड यह छोड़ देता है वे डिफ़ॉल्ट adapter से आते हैं। |
| `base` | कोई नहीं | Astro का `base`: `config.base`। |

पेज फ़ाइलें (`src/locales/pages/blog/post/de.json`) रूट `blog-post` हैं: पेज पाथ `-` से जोड़ा गया।

## अनुवाद करें {#translate}

```astro
---
// src/pages/index.astro
import { useI18n } from '@i18n-micro/astro'
import I18nT from '@i18n-micro/astro/i18n-t'

const { t, tc, locale } = useI18n(Astro)
---

<h1>{t('greeting', { name: 'Ada' })}</h1>
<p>{tc('apples', 3)}</p>
<I18nT keypath="welcome" tag="p" />
<p>{locale}</p>
```

`useI18n(Astro)` लौटाता है `locale`, `defaultLocale`, `locales`, `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `getRoute`, `getRouteName(path?)`, `getLocaleFromPath(path?)`, `switchLocalePath(locale)`, `localizePath(path, locale?)`, `getBasePath(url?)`, `getI18n`, `addTranslations`, `addRouteTranslations`, `mergeTranslations` और `clearCache`। जब middleware नहीं चला हो तो यह त्रुटि फेंकता है। हेल्पर `getI18n`, `getLocale`, `getDefaultLocale` और `getLocales` वही `Astro.locals` पढ़ते हैं।

रूट नाम लोकेल के बिना रूट से आता है: `/fr/blog/post` → `blog-post`, और `src/pages/blog/[slug].astro` का हर URL → `blog-slug`, इसलिए एक फ़ोल्डर `locales/pages/blog-slug/` उन सभी को सर्व करता है। `[...path]` है `path`। Astro के `base` के तहत हेल्पर साइट के URL लेते और लौटाते हैं: `switchLocalePath` और `localizePath` उसे शामिल करते हैं, `getBasePath` नहीं करता, क्योंकि `Astro.rewrite` उसके बिना पाथ लेता है।

### कंपोनेंट {#components}

इन्हें `@i18n-micro/astro/<name>` (या `@i18n-micro/astro/components/<name>.astro`) से इम्पोर्ट करें:

| कंपोनेंट | Props |
| --- | --- |
| `i18n-t` | `keypath`, `params`, `plural`, `number`, `date`, `relativeDate`, `tag` (`span`, कोई भी टैग), `html`, `hideIfEmpty`, `defaultValue`; अन्य attributes आगे पास होते हैं। `html` के साथ हर शाखा का परिणाम HTML के रूप में रेंडर होता है और `params` escape किए जाते हैं। कोई slots नहीं हैं |
| `i18n-link` | `href`, `locale` (लक्ष्य लोकेल, डिफ़ॉल्ट वर्तमान), `class`; अन्य attributes आगे पास होते हैं। बाहरी URL, `#hash` और `?query` जैसे लिखे हैं वैसे ही रहते हैं; एक रूट अपनी query, hash और अंतिम स्लैश बनाए रखता है |
| `i18n-switcher` | `class`, `activeClass` (`'active'`), `customLabels`; हर सक्षम लोकेल में वर्तमान पेज के लिंक रेंडर करता है, उसकी query के साथ |
| `i18n-group` | आउटपुट बदलने वाला कोई नहीं: इसके slot के चारों ओर एक `<div>`, कोई प्रीफ़िक्स नहीं |

## लोकेल-प्रीफ़िक्स वाले रूट {#locale-prefixed-routes}

`src/pages/` में प्रति रूट एक पेज रखें और `src/pages/[locale]/` के अंतर्गत पतले rewrite stub जोड़ें:

```
src/pages/
  index.astro
  about.astro
  [locale]/
    index.astro
    about.astro
```

```astro
---
// src/pages/[locale]/about.astro
import { prepareLocaleRewrite } from '@i18n-micro/astro'

const target = prepareLocaleRewrite(Astro)
if (target instanceof Response) return target
return Astro.rewrite(target)
---
```

`prepareLocaleRewrite` अज्ञात `:locale` के लिए `404` रिस्पॉन्स लौटाता है, अन्यथा `Astro.locals` पर लोकेल सेट करता है और प्रीफ़िक्स के बिना पाथ लौटाता है। Middleware `locals` में पहले से मौजूद लोकेल को बनाए रखता है, इसलिए rewrite किया गया पेज उसी में रेंडर होता है। जब आप लोकेल को स्वयं validate करते हैं, तो `getLocaleRewritePath(Astro)` केवल पाथ लौटाता है।

## लोकेल डिटेक्शन {#locale-detection}

URL पेज का लोकेल तय करता है:

1. एक लोकेल प्रीफ़िक्स (`/fr/about` → `fr`; `/en/about` भी `en` है)।
2. अन्यथा router adapter का `getLocaleFromPath` जो लौटाता है, यदि वह डिफ़ॉल्ट नहीं है।
3. अन्यथा डिफ़ॉल्ट लोकेल। `/about` हमेशा डिफ़ॉल्ट लोकेल का पेज होता है, कुकी चाहे जो कहे।

`autoDetect` केवल होम पेज पर एक रीडायरेक्ट संकेत है:

- `/` के लिए वह रिक्वेस्ट जिसकी कुकी या `Accept-Language` किसी अन्य लोकेल को प्राथमिकता देता है, उस लोकेल के होम (`/de`) पर `302` पाती है। q-weights का सम्मान किया जाता है; `de-DE` एक `de` लोकेल से मेल खाता है, और `de` एक `de-DE` लोकेल से।
- `redirectToDefault` के साथ, `/` हमेशा रीडायरेक्ट करता है: पसंदीदा लोकेल के होम पर, अन्यथा डिफ़ॉल्ट लोकेल के होम पर।
- `/` रिस्पॉन्स में `Vary: Cookie, Accept-Language` होता है (केवल `Accept-Language` जब `localeCookie` `null` हो)।
- Prerender किए गए पेज कभी रीडायरेक्ट नहीं करते।

`detectLocale(pathname, cookies, headers, defaultLocale, locales, localeCookie?, routingStrategy?, autoDetect?)` आपके अपने लॉजिक के लिए वही पसंदीदा लोकेल लौटाता है।

कुकी एक पसंद को याद रखती है। किसी अन्य लोकेल के same-origin पेज से आने वाला पेज व्यू विज़िटर का लोकेल बदलना है, चाहे कोई भी लिंक उन्हें वहाँ ले गया हो: HTML रिस्पॉन्स कुकी को नए लोकेल पर सेट करता है, और `/` रीडायरेक्ट नहीं करता, इसलिए एक स्विचर डिफ़ॉल्ट लोकेल के होम तक पहुँचता है। एक endpoint, एक इमेज, एक 404, एक form post और एक prefetch कुछ नहीं बदलते। "Same origin" वह है जो ब्राउज़र `Sec-Fetch-Site` में बताता है; उस हेडर के बिना `Referer` के host की तुलना रिक्वेस्ट के host से की जाती है, इसलिए प्रॉक्सी के पीछे Astro का `security.allowedDomains` सेट करें।

एक [server island](https://docs.astro.build/en/guides/server-islands/) या एक action के URL में कोई लोकेल नहीं होता। यह उस पेज के लिए रेंडर होता है जिसने अनुरोध किया था, जिसे `Referer` से पढ़ा जाता है, जिसका केवल पाथ मायने रखता है, इसलिए सर्वर के सामने प्रॉक्सी कुछ नहीं बदलता, और यह कभी रीडायरेक्ट नहीं करता। इसके रिस्पॉन्स में `Vary: Referer` होता है। `Referer` के बिना (`no-referrer` नीति) यह डिफ़ॉल्ट लोकेल में होता है, और डायनेमिक पेज पर इसका रूट URL से आता है, इसलिए पेज डिक्शनरी इस तक नहीं पहुँचतीं।

## Router adapter {#router-adapter}

`createAstroRouterAdapter(locales, defaultLocale)` डिफ़ॉल्ट को छोड़कर हर लोकेल पर प्रीफ़िक्स लगाता है। एक Astro adapter को केवल `getCurrentPath` चाहिए; अन्य सदस्य वैकल्पिक हैं और डिफ़ॉल्ट adapter पर फ़ॉलबैक करते हैं: `getRouteName(path, locales, routePattern?)`, `getLocaleFromPath`, `switchLocalePath`, `localizePath`, `removeLocaleFromPath`, `resolvePath` (होम रीडायरेक्ट लक्ष्य), `push`, `replace`, `getRoute`। सबडोमेन या suffix URL के लिए अपना स्वयं का adapter लिखें और उसे `createI18nMiddleware` को पास करें।

## SEO {#seo}

```astro
---
// src/layouts/Layout.astro
import { useLocaleHead } from '@i18n-micro/astro'

const head = useLocaleHead(Astro, { baseUrl: 'https://example.com' })
---

<html lang={head.htmlAttrs.lang} dir={head.htmlAttrs.dir}>
  <head>
    {head.link.map((l) => <link rel={l.rel} href={l.href} hreflang={l.hreflang} />)}
    {head.meta.map((m) => <meta property={m.property} content={m.content} />)}
  </head>
  <body><slot /></body>
</html>
```

यह लौटाता है `htmlAttrs` (`iso` से `lang`, `dir`), एक canonical लिंक (query के बिना पाथ), `seo !== false` वाले हर सक्षम लोकेल के लिए `hreflang` alternates और साथ में `x-default`, `og:locale`, `og:locale:alternate` और `og:url`। विकल्प: `baseUrl` (Astro कॉन्फ़िग से `site`, अन्यथा root-relative URL), `addDirAttribute` (`true`), `addSeoAttributes` (`true`), `hreflangBaseLanguage` (`false`)।
