`@i18n-micro/solid` SolidJS ऐप को signal-आधारित i18n इंस्टेंस, एक provider, `useI18n()` और चार कॉम्पोनेंट देता है। इसका उपयोग ऐसे Solid ऐप में करें जो Nuxt से नहीं बना है। JSX या effects के अंदर `t()` के रीड लोकेल, रूट और शब्दकोशों को ट्रैक करते हैं; साझा मॉडल [फ़्रेमवर्क](/hi/integrations/overview) में है।

## इंस्टॉल करें {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer dependencies: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (वैकल्पिक, केवल `@i18n-micro/solid/router` के लिए)। Solid 2 अभी समर्थित नहीं है।

## सेटअप {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` `i18n`, `locales`, `defaultLocale` और `routingStrategy` लेता है; छोड़ा गया prop बाहरी provider का मान रखता है, इंस्टेंस सहित। `getLocaleName()` और `<I18nSwitcher>` `locales` पढ़ते हैं; उनके बिना उनके पास सूचीबद्ध करने को कुछ नहीं होता। विकल्प [इंस्टेंस](/hi/integrations/overview#the-instance) में हैं। इंस्टेंस [रनटाइम](/hi/integrations/runtime-package) का ही है, उसके store पर एक signal के साथ।

## अनुवाद करें {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

मेथड को JSX या किसी effect के अंदर कॉल करें ताकि Solid उन्हें ट्रैक करे, `localePath` और `getLocale` को भी; कॉम्पोनेंट बॉडी में एक बार पढ़ा गया मान अपडेट नहीं होता। इंस्टेंस पर `i18n.locale` और `i18n.currentRoute` से ट्रैक करें: `i18n.getLocale()` सादा रहता है, क्योंकि writes उसे पढ़ते हैं। लोकेल पढ़ना केवल लोकेल पर जागता है, इसलिए जो effect उसे पढ़ता है और शब्दकोश लोड करता है वह एक बार चलता है। props को destructure न करें या `t('key')` के परिणामों को सादे वेरिएबल में न रखें।

`useI18n()` `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (एक accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` और `instance` लौटाता है।

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## लोकेल बदलें {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

बदलने से कुछ भी लोड नहीं होता; पहले लोकेल का शब्दकोश जोड़ें।

`<I18nGroup>` किसी फ़ंक्शन child को प्रीफ़िक्स वाला `t` देता है। उसके अंदर `<I18nT>` और `t()` प्रीफ़िक्स नहीं होते:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## रूटिंग {#routing}

`@solidjs/router` एडेप्टर एक subpath में रहता है ताकि मुख्य entry कभी राउटर को इम्पोर्ट न करे। इसे राउटर के अंतर्गत कॉल करें, आमतौर पर राउटर के `root` में, जहाँ `useNavigate` और `useLocation` काम करते हैं:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

एडेप्टर डिफ़ॉल्ट को छोड़कर हर लोकेल पर प्रीफ़िक्स लगाता है (`/about`, `/de/about`), और `<I18nLink>` को राउटर के `<A>` के रूप में रेंडर करता है। `getCurrentPath` राउटर की reactive location पढ़ता है, इसलिए active लिंक और स्विचर उसका अनुसरण करते हैं; कस्टम रणनीति वहाँ एक signal पढ़कर यही पाती है। तर्कों के क्रम पर ध्यान दें: `(locales, defaultLocale, navigate, location)`। अन्य राउटर के लिए `getCurrentPath`, `push` और `replace` (सभी आवश्यक) के साथ एक एडेप्टर लिखें — देखें [राउटर एडेप्टर](/hi/integrations/overview#router-adapter)।

## SSR {#ssr}

सर्वर रेंडरिंग के लिए, `vite-plugin-solid` के साथ बिल्ड करें: पैकेज की `solid` export condition उसे सोर्स देती है, इसलिए वह सर्वर के लिए कम्पाइल होता है। पहले से बना `dist` केवल ब्राउज़र के लिए है। इंस्टेंस में कोई `destroy()` नहीं है; हर ऐप के लिए एक बनाएँ, या सर्वर पर हर अनुरोध के लिए एक, और उसे garbage-collect होने दें।
