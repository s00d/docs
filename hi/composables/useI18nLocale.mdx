---
title: "useI18nLocale"
description: "useI18nLocale लोकेल state और लोकेल कुकी को पढ़ता और लिखता है — कस्टम लोकेल डिटेक्शन का एंट्री पॉइंट।"
---

`useI18nLocale()` उस लोकेल तक पहुँच देता है जिसे ऐप ने चुना है: `i18n-locale` state और लोकेल कुकी। इसका उपयोग ऐसे प्लगइन में करें जो लोकेल को खुद पहचानता है (डोमेन, यूज़र प्रोफ़ाइल, हेडर), बजाय इसके कि `useState('i18n-locale')` या कुकी को हाथ से लिखें। इसकी वैधता जाँच सक्षम लोकेल का उपयोग करती है, जिसमें रनटाइम ओवरराइड भी शामिल हैं।

## सिग्नेचर {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

i18n लोकेल प्रबंधन के लिए केंद्रीकृत एंट्री पॉइंट।
useState('i18n-locale'), लोकेल कुकी और सिंक यूटिलिटी को जोड़ता है।

## लौटाए गए मान {#returned-values}

| सदस्य | टाइप | विवरण |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | `useState('i18n-locale')` ref। |
| `localeCookie` | `Ref<string \| null>` | [`localeCookie`](/hi/api/module-options#localecookie) कुकी; जब विकल्प `null` हो तो एक साधारण `{ value: null }`। |
| `hashCookie` | `Ref<string \| null>` | hash रूटिंग में `hash-locale` कुकी; अन्यथा `{ value: null }`। |
| `validLocales` | `string[]` | सक्षम लोकेल के कोड। |
| `setLocale(locale)` | `(locale: string \| null) => void` | state और कुकी लिखें। यह न तो वैधता जाँचता है और न ही अनुवाद लोड करता है। |
| `syncLocale(locale)` | `(locale: string \| null) => void` | केवल कुकी लिखें। |
| `getLocale()` | `() => string \| null` | state, फिर प्राथमिकता कुकी (hash रूटिंग में hash कुकी)। वैधता नहीं जाँची जाती। |
| `getPreferredLocale()` | `() => string \| null` | state और प्राथमिकता कुकी में से पहला **वैध** मान, या `null`। |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | hash रूटिंग में सेट होने पर state; अन्यथा `getLocaleFromRoute(route)`। |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, फिर एक वैध state, फिर `options.serverLocale`, फिर रूट का लोकेल। state वैध न होने पर परिणाम को state में संग्रहीत करता है; क्लाइंट पर यह कुकी भी लिखता है। |
| `isValidLocale(locale)` | `(locale) => locale is string` | क्या `locale`, `validLocales` में है। |

कुकी एक साल तक चलती हैं, `path: '/'` और `sameSite: 'lax'` के साथ।

## उदाहरण {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

मॉड्यूल का loader प्लगइन शुरू होते समय state पढ़ता है, इसलिए जो प्लगइन इसे सेट करता है उसे पहले चलना चाहिए (`enforce: 'pre'`)। state, URL, कुकी और `Accept-Language` के साथ कैसे प्रतिस्पर्धा करता है: [लोकेल डिटेक्शन](/hi/guide/locale-detection)। पूरा walkthrough: [कस्टम डिटेक्शन](/hi/guide/custom-auto-detect)।

`setLocale()` स्क्रीन पर अनुवाद नहीं बदलता। वर्तमान पेज का लोकेल बदलने के लिए, [`$switchLocale()`](/hi/api/methods#$switchlocale) कॉल करें।
