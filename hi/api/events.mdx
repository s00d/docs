मॉड्यूल एक रनटाइम (ऐप) हुक, `i18n:register`, को कॉल करता है। इसका उपयोग तब करें जब कोई प्लगइन या मॉड्यूल ऐसे अनुवाद जोड़ता है जो आपकी `locales/` फ़ाइलों में नहीं हैं। आपके कॉलबैक को एक `register` फ़ंक्शन मिलता है जो अनुवादों को दिखाए जा रहे पेज में मर्ज करता है।

## `i18n:register` {#i18nregister}

```ts
'i18n:register': (
  register: (translations: unknown, locale?: string) => void,
  locale: string,
) => HookResult
```

| आर्ग्युमेंट | विवरण |
| --- | --- |
| `register(translations, locale?)` | `translations` को लोड हो रहे रूट के पेज चंक में `locale` के लिए डीप-मर्ज करता है (डिफ़ॉल्ट: हुक का `locale`)। पहले से मौजूद कुंजियाँ ओवरराइड हो जाती हैं। |
| `locale` | लोड हो रहे रूट का लोकेल। |

हुक `RuntimeNuxtHooks` के माध्यम से टाइप किया गया है, इसलिए `nuxtApp.hook('i18n:register', …)` को किसी कास्ट की आवश्यकता नहीं है।

## यह कब चलता है {#when-it-fires}

लोडर प्लगइन (`i18n-plugin-loader`) इसे कॉल करता है:

1. स्टार्टअप पर एक बार, जब हर प्लगइन चल चुका हो (`app:created`) और ऐप के रेंडर होने से पहले;
2. अपने `router.beforeEach` में, लक्ष्य पेज के अनुवाद लोड होने के बाद, जब पाथ बदलता है — `no_prefix` के अंतर्गत हर नेविगेशन पर।

ऐप के रेंडर होने या नेविगेशन आगे बढ़ने से पहले हर कॉलबैक और हर `register` कॉल की प्रतीक्षा (await) की जाती है, इसलिए पेज मर्ज की गई कुंजियों के साथ रेंडर होता है। [`hooks: false`](/hi/api/module-options#hooks) के साथ हुक कभी कॉल नहीं होता।

## उदाहरण {#example}

```ts
// plugins/i18n-extra.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('i18n:register', async (register, locale) => {
    const extra = await $fetch<Record<string, unknown>>(`/api/cms-strings/${locale}`)
    register(extra, locale)
  })
})
```

यह एक रनटाइम हुक है: इसे किसी प्लगइन में `nuxtApp.hook` के साथ रजिस्टर करें, न कि `nuxt.config` में या किसी मॉड्यूल के `setup` में `nuxt.hook` के साथ। कोई मॉड्यूल ऐसा प्लगइन `addPlugin` के साथ जोड़ता है।
