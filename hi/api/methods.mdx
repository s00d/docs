मॉड्यूल अपने रनटाइम हेल्पर Nuxt ऐप में इंजेक्ट करता है: `$t`, `$tc`, `$localePath`, `$switchLocale` और बाकी। किसी हेल्पर का सिग्नेचर और व्यवहार देखने के लिए इस पेज का उपयोग करें। सिग्नेचर और विवरण `src/runtime/plugins/01.plugin.ts` में `PluginsInjections` और `NuxtAppOnlyInjections` इंटरफ़ेस से आते हैं।

## एक्सेस {#access}

| कहाँ | कैसे |
| --- | --- |
| टेम्पलेट | `{{ $t('title') }}` — हर हेल्पर, `$` के साथ |
| `<script setup>` | `const { t, localePath } = useI18n()` — `PluginsInjections` का हर हेल्पर, `$` के साथ और उसके बिना |
| प्लगइन, middleware, `<script setup>` | `const { $t, $defineI18nRoute } = useNuxtApp()` — सब कुछ, केवल `$` के साथ |

`$defineI18nRoute` केवल `useNuxtApp()` पर टाइप किया गया है। देखें [`useI18n`](/hi/composables/useI18n)।

```vue
<script setup lang="ts">
const { t, localePath } = useI18n()
</script>

<template>
  <NuxtLink :to="localePath('/about')">{{ t('nav.about') }}</NuxtLink>
</template>
```

## लोकेल {#locale}

### `$getLocale` {#$getlocale}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric) => string
```

सक्रिय लोकेल का कोड। जिस लोकेल से कोई रूट संबंधित है उसे पढ़ने के लिए एक रूट पास करें।

```ts
$getLocale() // 'de' on /de/about
```

### `$getLocaleName` {#$getlocalename}

```ts
() => string | null
```

कॉन्फ़िग से सक्रिय लोकेल का `displayName`, या `null` जब उसका कोई न हो।

### `$getLocales` {#$getlocales}

```ts
() => Locale[]
```

हर कॉन्फ़िगर किया गया लोकेल, उसके मेटाडेटा के साथ।

लोकेल ऑब्जेक्ट पर कस्टम properties जैसी लिखी गई हैं वैसी ही वापस आती हैं; उन्हें `Locale` के [module augmentation](/hi/api/module-options#locales) से टाइप करें।

### `$defaultLocale` {#$defaultlocale}

```ts
() => string | undefined
```

कॉन्फ़िगर किए गए डिफ़ॉल्ट लोकेल का कोड।

### `$getI18nConfig` {#$geti18nconfig}

```ts
() => ResolvedI18nConfig
```

resolve किया गया मॉड्यूल कॉन्फ़िगरेशन, जैसा रनटाइम उसे देखता है।

मान में [रनटाइम ओवरराइड](/hi/guide/runtime-overrides) (`defaultLocale`, `fallbackLocale`, अक्षम लोकेल) शामिल हैं।

```ts
const { strategy, localeCookie } = useNuxtApp().$getI18nConfig()
```

## अनुवाद {#translation}

### `$t` {#$t}

```ts
TranslationFn<CleanTranslation>
```

एक कुंजी का अनुवाद करें, उसमें `params` इंटरपोलेट करते हुए। कुंजी के न होने पर `defaultValue` लौटाता है,
या कोई डिफ़ॉल्ट न दिए जाने पर स्वयं कुंजी।

```ts
// { "welcome": "Welcome, {name}!" }
$t('welcome', { name: 'Ada' }) // 'Welcome, Ada!'
$t('missing.key', {}, 'Fallback') // 'Fallback'
```

nested ऑब्जेक्ट की ओर इशारा करने वाली कुंजी वह ऑब्जेक्ट लौटाती है, string नहीं। टेम्पलेट में यह `[object Object]` के रूप में रेंडर होता है; leaf कुंजी का उपयोग करें।

### `$ts` {#$ts}

```ts
TranslationFn<string>
```

`$t` की तरह, लेकिन हमेशा एक string लौटाता है: मान `toString()` से गुज़रता है, इसलिए एक nested
ऑब्जेक्ट `'[object Object]'` बन जाता है। कुंजी को किसी leaf की ओर इंगित करें।

### `$_t` {#$_t}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<CleanTranslation>
```

`$t` को किसी विशिष्ट रूट से बाँधें, वर्तमान पेज के बाहर अनुवाद करने के लिए — उदाहरण के लिए, किसी अन्य
रूट का लिंक रेंडर करने वाला लेआउट।

```ts
const route = useRoute()
const t = useNuxtApp().$_t(route)
t('page.title')
```

### `$_ts` {#$_ts}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<string>
```

`$ts` को किसी विशिष्ट रूट से बाँधें। देखें `$_t`।

### `$tc` {#$tc}

```ts
(key: TranslationKey, params: number | Params, defaultValue?: string) => string
```

बहुवचन के साथ अनुवाद करें। `params` स्वयं गिनती हो सकता है, या `count` वाला
एक ऑब्जेक्ट।

रूप `|` से अलग किए जाते हैं। बिल्ट-इन नियम के साथ एक गैर-ऋणात्मक पूर्णांक गिनती `n` रूप `n` चुनती है, अंतिम रूप तक सीमित; ऋणात्मक, भिन्नात्मक या `NaN` गिनती अंतिम रूप लेती है। `{count}` और अन्य params चुने गए रूप में इंटरपोलेट किए जाते हैं।

उन भाषाओं के लिए जिनके बहुवचन गिनती का पालन नहीं करते, टेम्पलेट को `=0 ` से शुरू करें। तब पहला रूप 0 के लिए होता है, और बाकी [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) श्रेणी के अनुसार, क्रम `zero, one, two, few, many, other` में चलते हैं:

```json
{
  "apples": "=0 no apples | one apple | {count} apples",
  "files": "=0 no files | {count} one | {count} few | {count} many"
}
```

```ts
$tc('apples', 0) // 'no apples'
$tc('apples', 1) // 'one apple'
$tc('apples', 7) // '7 apples'

// In `uk` (categories `one, few, many, other`) the forms after the zero form follow those categories:
$tc('files', 21) // '21 one'
$tc('files', 22) // '22 few'
$tc('files', 25) // '25 many'
$tc('files', 2.5) // '2.5 many': no form for `other`, so the last one
```

- `=0 ` केवल मान की बिल्कुल शुरुआत में, स्पेस के साथ, मायने रखता है। `$t` इसे टेक्स्ट के रूप में दिखाता है: यह बहुवचन से संबंधित है।
- जिस श्रेणी का अपना कोई रूप नहीं है वह अंतिम रूप लेती है। ऋणात्मक या भिन्नात्मक गिनती भी अंतिम रूप लेती है।
- यह किसी भी लोकेल में काम करता है: अंग्रेज़ी में `=0 none | one | {count} many`।
- श्रेणी लोकेल के `iso` से आती है, अन्यथा उसके कोड से। जिस कोड को `Intl` नहीं जानता वह index नियम पर फ़ॉलबैक करता है, marker फिर भी हटाया जाता है, इसलिए परिणाम कभी मशीन पर निर्भर नहीं करता।
- `<i18n-t :plural>` उसी नियम का पालन करता है। एक कस्टम [`plural`](/hi/api/module-options#plural) या `customPluralRule` marker सहित कच्चा मान पाता है, और स्वयं निर्णय लेता है; `null` लौटाने वाला `plural` कॉल को बिल्ट-इन नियम को वापस सौंप देता है, जो marker का सम्मान करता है।

marker के बिना टेम्पलेट index नियम पर ही रहता है, एक अपवाद के साथ जिसे केवल एक ही तरह से पढ़ा जा सकता है: बिना प्लेसहोल्डर वाला एक शून्य रूप, फिर प्रति श्रेणी एक रूप, उस हर रूप में `{count}` के साथ जिसे कई गिनतियाँ साझा करती हैं (`uk` में `no files | {count} one | {count} few | {count} many`)।

अपने स्वयं के नियमों के लिए [`plural`](/hi/api/module-options#plural) सेट करें।

```ts
// { "apples": "no apples | one apple | {count} apples" }
$tc('apples', 0) // 'no apples'
$tc('apples', 10) // '10 apples'
$tc('cart', { count: 2, name: 'Ada' }) // count and params in one object
```

तीसरा आर्गुमेंट `defaultValue` है, params नहीं।

### `$has` {#$has}

```ts
(key: string) => boolean
```

क्या कोई कुंजी सक्रिय लोकेल में resolve होती है। कच्ची कुंजी रेंडर करने के बजाय वैकल्पिक कॉपी पर
branch करने के लिए इसका उपयोग करें। `$t` की तरह, यह same-locale पेज ट्रांज़िशन के दौरान छोड़े जा रहे
पेज की कुंजियाँ भी देखता है।

```ts
if ($has('promo.banner')) show.value = true
```

## फ़ॉर्मैटिंग {#formatting}

### `$tn` {#$tn}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

सक्रिय लोकेल में `Intl.NumberFormat` के साथ एक संख्या फ़ॉर्मैट करें। एक कुंजी कॉन्फ़िग से एक नामित फ़ॉर्मैट
चुनती है।

नामित फ़ॉर्मैट [`numberFormats`](/hi/api/module-options#numberformats) से आते हैं।

```ts
$tn(1234.5, { style: 'currency', currency: 'EUR' }) // '1.234,50 €' in de
$tn(1000, 'currency') // named format
$tn(1000, 'currency', 'de') // named format in another locale
```

### `$td` {#$td}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

सक्रिय लोकेल में `Intl.DateTimeFormat` के साथ एक तारीख फ़ॉर्मैट करें। एक कुंजी कॉन्फ़िग से एक नामित फ़ॉर्मैट
चुनती है।

नामित फ़ॉर्मैट [`datetimeFormats`](/hi/api/module-options#datetimeformats) से आते हैं।

```ts
$td(new Date(), { dateStyle: 'long' })
$td(post.createdAt, 'short')
```

### `$tdr` {#$tdr}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

`Intl.RelativeTimeFormat` के साथ एक तारीख को सापेक्ष समय ("3 दिन पहले") के रूप में फ़ॉर्मैट करें।

```ts
$tdr(Date.now() - 5 * 60_000) // '5 minutes ago' in en
```

## स्विचिंग और लिंक {#switching-and-links}

### `$switchLocale` {#$switchlocale}

```ts
(locale: string) => Promise<boolean>
```

किसी अन्य लोकेल में वर्तमान पेज पर नेविगेट करें। `no_prefix` और hash मोड के तहत यह नेविगेट करने से पहले
लोकेल के अनुवाद लोड करता है; `no_prefix` के तहत रूट उसी स्थान पर बदला जाता है (कोई
नई history प्रविष्टि नहीं)। अज्ञात लोकेल को अनदेखा किया जाता है।
कॉल async है: नेविगेशन के बाद कोड चलाने के लिए इसे `await` करें। यह `true` resolve करता है जब
लोकेल की डिक्शनरी सक्रिय हो, `false` जब न हो: chunk लोड होने में विफल रहा (वर्तमान
डिक्शनरी बनी रहती है; फिर से प्रयास करने के लिए इसे दोबारा कॉल करें) या किसी नए स्विच ने जगह ले ली।

```ts
await $switchLocale('de')
```

### `$switchLocalePath` {#$switchlocalepath}

```ts
(locale: string) => string
```

किसी अन्य लोकेल में वर्तमान पेज का पाथ, बिना नेविगेट किए।

```vue
<NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
```

### `$switchLocaleRoute` {#$switchlocaleroute}

```ts
(locale: string) => RouteLocationRaw
```

किसी अन्य लोकेल में वर्तमान पेज का रूट ऑब्जेक्ट, बिना नेविगेट किए, या अपने स्वयं के `baseUrl` वाले
लोकेल के लिए एक URL string। `trailingSlash` के तहत ऑब्जेक्ट में नियम का पालन करते हुए `path` और `fullPath` होते हैं,
`query` और `hash` जैसे हैं वैसे ही, और `router.push` या एक लिंक उन्हें बनाए रखते हैं।

### `$switchRoute` {#$switchroute}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => Promise<void>
```

किसी अन्य रूट पर नेविगेट करें, सक्रिय लोकेल बनाए रखते हुए या `toLocale` पर स्विच करते हुए। `$switchLocale` की तरह
async।

```ts
$switchRoute('/about') // active locale
$switchRoute({ name: 'about' }, 'de') // switch to de
```

### `$localePath` {#$localepath}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => string
```

दिए गए लोकेल, या सक्रिय लोकेल में एक पाथ resolve करें। `http(s):`, `mailto:`
या `tel:` scheme वाली string जैसी है वैसी ही वापस आती है: उपयोगकर्ता इनपुट को बिना जाँचे लिंक लक्ष्य के रूप में पास न करें।

एक string पाथ को उस पेज के रूप में पढ़ा जाता है जिसे वह दिखाता है, इसलिए लोकेल का कस्टम पाथ भी लागू होता है।

```ts
$localePath('/about') // '/about' in en, '/de/ueber-uns' in de with localeRoutes
$localePath({ name: 'about' }, 'fr') // '/fr/about'
```

### `$localeRoute` {#$localeroute}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => RouteLocationResolved
```

दिए गए लोकेल, या सक्रिय लोकेल में एक रूट resolve करें। एक सादा ऑब्जेक्ट, स्थिति में रखने के लिए सुरक्षित। जब किसी param को
escape करने की आवश्यकता हो तो इसमें `path`, `fullPath`, `query` और `hash` होते हैं लेकिन `name` या `params` नहीं: पाथ ही router को
encoded URL देता है। किसी अन्य डोमेन पर स्थित लोकेल के लिए `path` और `fullPath` absolute होते हैं, जिन्हें router नहीं ले सकता:
ऐसा लिंक `<i18n-link>`, या `$localePath` से होकर जाता है।

### `$getRouteName` {#$getroutename}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric, locale?: string) => string
```

लोकेल प्रीफ़िक्स हटाकर रूट नाम — वह नाम जिससे अनुवाद key किए जाते हैं।

```ts
$getRouteName() // 'about' on /de/about
```

## पेज कॉन्फ़िग {#page-config}

### `$defineI18nRoute` {#$definei18nroute}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

किसी कंपोनेंट के भीतर से प्रति-पेज लोकेल कॉन्फ़िगरेशन और अनुवाद रजिस्टर करें।
सक्रिय लोकेल में मर्ज करता है और लोकेल बदलने पर फिर से लागू होता है।

इसे किसी पेज के `<script setup>` में कॉल करें, हमेशा `useNuxtApp()` से destructure करके। बिल्ड कॉल से `locales`, `localeRoutes` और `disableMeta` पढ़ता है; रनटाइम पर केवल `locales` मायने रखता है (इनलाइन अनुवाद सक्रिय लोकेल के लिए मर्ज किए जाते हैं)। पूर्ण नियम: [पेज कॉन्फ़िग](/hi/guide/per-component-translations)।

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: { en: '/about', de: '/ueber-uns' },
})
</script>
```

### `$setI18nRouteParams` {#$seti18nrouteparams}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

वर्तमान रूट के लिए प्रति-लोकेल params सेट करें, ताकि एक डायनेमिक सेगमेंट हर भाषा में अलग हो सके।
इसे SSR के दौरान, head रेंडर होने से पहले कॉल करें।

किसी अन्य पाथ पर नेविगेशन commit होने पर params साफ़ हो जाते हैं, जिसमें `/news/1` से `/news/4` भी शामिल है, जो रूट नाम बनाए रखता है। विवरण: [स्थानीयकृत पाथ](/hi/guide/custom-locale-routes)।

```ts
$setI18nRouteParams({
  en: { slug: 'my-post' },
  de: { slug: 'mein-beitrag' },
})
```

## रनटाइम अनुवाद {#runtime-translations}

### `$mergeTranslations` {#$mergetranslations}

```ts
(newTranslations: Translations) => void
```

रनटाइम पर सक्रिय लोकेल में अनुवाद मर्ज करें, जो लोड है उसे ओवरराइड करते हुए।

सक्रिय लोकेल के वर्तमान पेज chunk में deep-merge करता है; जिन कुंजियों का यह उल्लेख नहीं करता वे बनी रहती हैं।

```ts
$mergeTranslations({ banner: { title: 'Sale' } })
```

### `$setTranslation` {#$settranslation}

```ts
(key: string, value: unknown) => void
```

सक्रिय डिक्शनरी में `key` पर मान बदलें। यह replace है, merge नहीं —
जब मौजूदा sibling कुंजियाँ बनी रहनी चाहिए तो `$mergeTranslations` का उपयोग करें।

```ts
$setTranslation('banner', { title: 'Sale' }) // drops other keys under banner
$setTranslation('banner.title', 'Sale') // dotted path
```

### `$loadPageTranslations` {#$loadpagetranslations}

```ts
(locale: string, routeName: string, translations: Translations) => Promise<void>
```

रनटाइम पर किसी पेज के लिए अनुवाद लोड करें, ऐसे कंटेंट के लिए जिसकी कुंजियाँ बिल्ड के समय ज्ञात नहीं हैं।

इन-मेमोरी `(locale, routeName)` chunk में मर्ज करता है, और जब वह chunk सक्रिय होता है तो स्क्रीन अपडेट होती है। यहाँ कोई payload fetch नहीं किया जाता: जो पेज अभी लोड नहीं हुआ उसके लिए अनुवाद प्रतीक्षा करते हैं, और जब उसकी फ़ाइल लोड होती है तो वे उसके ऊपर बने रहते हैं।

```ts
await $loadPageTranslations('en', 'about', { title: 'About us' })
```

### `$resolveTranslations` {#$resolvetranslations}

```ts
() => Translations
```

सक्रिय लोकेल और रूट के लिए वर्तमान में मेमोरी में मौजूद हर अनुवाद, एक ट्री के रूप में।
`$t()` इस समय क्या resolve कर सकता है उसका केवल-पढ़ने योग्य दृश्य।

परिणाम को केवल-पढ़ने योग्य मानें।

### `$setMissingHandler` {#$setmissinghandler}

```ts
(handler: MissingHandler | null) => void
```

हर unresolved कुंजी के लिए बुलाया जाने वाला callback इंस्टॉल करें। इसे हटाने के लिए `null` पास करें।

हैंडलर dev चेतावनी के बजाय चलता है।

```ts
$setMissingHandler((locale, key, routeName) => {
  console.error(`[i18n] missing ${key} in ${locale} (${routeName})`)
})
```

### `$clearCache` {#$clearcache}

```ts
() => void
```

हर कैश किया गया अनुवाद chunk हटाएँ और वर्तमान पेज की डिक्शनरी फिर से लोड करें। पेज
नए अनुवाद आने तक अपने वर्तमान अनुवाद दिखाता रहता है। Dev HMR इसे हर अनुवाद फ़ाइल
बदलाव पर कॉल करता है।

```ts
const { clearCache } = useI18n()
clearCache()
```

विफल रीलोड वर्तमान डिक्शनरी को बनाए रखता है।
