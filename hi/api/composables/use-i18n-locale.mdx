## API

| Property/Method                                 | Type                                | विवरण                                                                          |
| ----------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------ |
| `locale`                                        | `Ref<string \| null>`               | Reactive locale state (`useState('i18n-locale')`)                                    |
| `localeCookie`                                  | `Ref`                               | Locale cookie (जब `localeCookie` विकल्प सक्षम होता है)                                |
| `hashCookie`                                    | `Ref`                               | Cookie जब `hashMode` सक्रिय होता है तब उपयोग किया जाता है                                                |
| `validLocales`                                  | `string[]`                          | मॉड्यूल config से सक्षम locale codes (`disabled` को छोड़कर)                        |
| `getLocale()`                                   | `() => string \| null`              | वर्तमान locale: state → cookie (या hash mode में hash cookie)                         |
| `getPreferredLocale()`                          | `() => string \| null`              | state/cookie से locale जो `validLocales` के विरुद्ध **validated** है, या `null`             |
| `getLocaleWithServerFallback(serverLocale?)`    | `(serverLocale?) => string \| null` | State → cookie → वैकल्पिक server context (`no_prefix` init के दौरान उपयोग किया जाता है)              |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string`             | अनुवाद लोड करने के लिए locale: hash mode state को प्राथमिकता देता है; अन्यथा route से पढ़ता है |
| `resolveInitialLocale(options)`                 | `(options) => string`               | Locale resolve करता है: state → `serverLocale` → route; आवश्यक होने पर state को sync करता है             |
| `setLocale(locale)`                             | `(locale: string \| null) => void`  | Locale सेट करें और cookies में sync करें                                                       |
| `syncLocale(locale)`                            | `(locale: string \| null) => void`  | केवल cookies sync करें (कोई state update नहीं)                                                  |
| `isValidLocale(locale)`                         | `(locale) => boolean`               | जाँच करें कि string `validLocales` में है या नहीं                                                |

### `resolveInitialLocale` विकल्प

```typescript
interface ResolveInitialLocaleOptions {
  route: unknown
  serverLocale?: string | null
  getLocaleFromRoute: (route?: unknown) => string
}
```

Startup पर main plugin द्वारा आंतरिक रूप से उपयोग किया जाता है। Custom plugins वैकल्पिक detection flows को लागू करते समय इसे कॉल कर सकते हैं।

### `getEffectiveLocale`

```typescript
const { getEffectiveLocale } = useI18nLocale()
const { $getLocale } = useNuxtApp()

const locale = getEffectiveLocale(route, (r) => $getLocale(r))
```

एक दिए गए route object के लिए अनुवाद लोड करने और messages format करने के लिए उपयोग किया गया locale लौटाता है।

## Programmatic Locale Setting

`useState('i18n-locale')` के प्रत्यक्ष उपयोग पर `useI18nLocale()` को प्राथमिकता दें:

```ts
// plugins/i18n-loader.server.ts
import { defineNuxtPlugin } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,

  setup() {
    const { setLocale } = useI18nLocale()
    const detectedLocale = 'ja' // Your detection logic here
    setLocale(detectedLocale)
  },
})
```

<Tip>
`setLocale()` केवल locale preference (state + cookie) अपडेट करता है। Client पर सक्रिय अनुवाद संदर्भ को भी पुनः लोड करने के लिए, `useNuxtApp()` या `useI18n()` से `$switchLocale()` का उपयोग करें। यह विशेष रूप से `no_prefix` के लिए महत्वपूर्ण है, जहाँ URL नहीं बदलता। [FAQ — URL बदले बिना locale स्विच करें](/guides/faq#-switch-locale-without-changing-the-url) देखें।
</Tip>
