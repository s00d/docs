`@i18n-micro/cli` किसी Nuxt प्रोजेक्ट की लोकेल फ़ाइलों का प्रबंधन करता है। यह `nuxt.config` से `locales`, `defaultLocale`, `translationDir` और आपकी लेयर पढ़ता है, इसलिए इसे अपने किसी कॉन्फ़िगरेशन की ज़रूरत नहीं है।

![i18n-micro check चलाता एक टर्मिनल, जो एक गायब, एक अपरिभाषित और चार अप्रयुक्त कुंजियाँ सूचीबद्ध करता है और विफल होता है, फिर extract, जो अपरिभाषित कुंजी जोड़ता है, फिर clean --dryRun, जो वे चार कुंजियाँ सूचीबद्ध करता है जिन्हें वह हटाएगा](/images/cli/demo.gif)

| कमांड | इसका उपयोग करें |
| --- | --- |
| `check` | लोकेल फ़ाइलों में किसी भी गड़बड़ी पर बिल्ड विफल करने के लिए |
| `translate` | अनुवाद सेवा के माध्यम से गायब कुंजियाँ भरने के लिए |
| `clean` | उन कुंजियों को हटाने के लिए जिनका कोई उपयोग नहीं करता |
| `rename` | किसी कुंजी, या पूरे namespace, को हर जगह एक साथ स्थानांतरित करने के लिए |

```bash
npm install -D @i18n-micro/cli
npx i18n-micro --help
```

इसे ऐप रूट से चलाएँ, या `--cwd` से उसकी ओर इंगित करें। हर कमांड का हर फ़्लैग [कमांड संदर्भ](/hi/api/cli) पर है।

<Tip>

**nuxt-i18n-micro-cli से आ रहे हैं?** `@i18n-micro/cli` उसकी जगह लेता है; bins `i18n-micro` और `i18n-micro-cli` बने रहते हैं। देखें [पुराने कमांड की तालिका](#moving-from-nuxt-i18n-micro-cli)।

</Tip>

## इसे CI में उपयोग करें {#use-it-in-ci}

```bash
i18n-micro check
```

`check` गेट है। यह रिपोर्ट करता है:

| जाँच | अर्थ |
| --- | --- |
| `missing` | डिफ़ॉल्ट लोकेल की कोई कुंजी किसी लोकेल में मौजूद नहीं है |
| `empty` | कोई मान `''` है। ऐप फ़ॉलबैक नहीं, खाली जगह दिखाता है |
| `extra` | किसी लोकेल में ऐसी कुंजी है जो डिफ़ॉल्ट लोकेल में नहीं है |
| `placeholders` | `{name}` खो गया या जोड़ा गया, या किसी बहुवचन ने अपने रूप खो दिए |
| `undefined` | कोड ऐसी कुंजी का उपयोग करता है जो डिफ़ॉल्ट लोकेल में नहीं है |
| `unused` | प्रोजेक्ट में कोई भी किसी कुंजी का उपयोग नहीं करता |
| `duplicates` | अलग-अलग कुंजियों के अंतर्गत एक ही टेक्स्ट। डिफ़ॉल्ट रूप से बंद: `--duplicates` पास करें |

- `--only missing,placeholders` कुछ जाँचें चलाता है; `--only` में नामित कोई जाँच जो नहीं चल सकी, विफल होती है।
- `--json` टूलिंग के लिए एक रिपोर्ट देता है।
- `--ignore` सोर्स फ़ाइलें छोड़ देता है।
- जब कुंजियाँ रनटाइम पर गणना की जाती हैं, तो `unused` छोड़ दिया जाता है और रिपोर्ट कारण बताती है।

हर कमांड तीन में से किसी एक कोड के साथ बाहर निकलता है, ताकि पाइपलाइन आपके अनुवादों की समस्या और टूल की समस्या में अंतर कर सके:

| Exit कोड | अर्थ |
| --- | --- |
| `0` | रिपोर्ट करने को कुछ नहीं |
| `1` | निष्कर्ष |
| `2` | कमांड नहीं चल सका: उपयोग त्रुटि, टूटी फ़ाइल, विफल अनुरोध |

अन्य कमांड जो CI चरण के योग्य हैं:

```bash
i18n-micro format --check      # fails if a file is not formatted
i18n-micro lint                # stray spaces, empty values, your own regex rules
i18n-micro stats --baseRef main
```

## लोकेल को तालमेल में रखें {#keep-locales-in-step}

| कमांड | यह क्या करता है |
| --- | --- |
| `extract` | उन कुंजियों को सूचीबद्ध करता है जिनका कोड उपयोग करता है लेकिन जिनका अभी कोई टेक्स्ट नहीं है। डिफ़ॉल्ट टेक्स्ट, जैसे `$t('key', {}, 'Welcome')` में, डिफ़ॉल्ट लोकेल में जाता है। |
| `sync` | उन कुंजियों को हटाता है जो डिफ़ॉल्ट लोकेल में नहीं हैं। पहले `--dryRun` आज़माएँ। |
| `clean` | उन कुंजियों को हटाता है जिनका कोई उपयोग नहीं करता। पहले `--dryRun` आज़माएँ। |
| `search` | कुंजियाँ और मान खोजता है, और दिखाता है कि हर कुंजी कहाँ उपयोग होती है। |
| `stats` | हर लोकेल की पूर्णता; `--baseRef main` किसी git ref से तुलना करता है। |

`sync` भी `clean` की तरह रुक जाता है जब वह कोई ऐसी कुंजी हटाने वाला हो जिसका अप्रयुक्त होना वह सिद्ध नहीं कर सकता, और तब भी जब डिफ़ॉल्ट लोकेल के पास तुलना के लिए कुछ नहीं होता। हटाने को कुछ न हो तो यह कभी नहीं रुकता, इसलिए केवल `$t(item.label)` `--force` का कारण नहीं है।

<Note>

`extract` और `sync` बिना अनुवाद वाली कुंजी के लिए कभी `''` नहीं लिखते। कुंजी अनुपस्थित रहती है, इसलिए रनटाइम पर `fallbackLocale` लागू होता है और `check` उसे रिपोर्ट करता है। खाली स्ट्रिंग एक परिभाषित मान होगी और खाली जगह दिखाएगी।

</Note>

### कमांड क्या पढ़ते हैं {#what-the-commands-read}

`check`, `extract`, `sync`, `clean`, `search` और `rename` फ़ोल्डरों की किसी तय सूची के बजाय पूरे प्रोजेक्ट का सोर्स कोड पढ़ते हैं:

- **पढ़ा जाता है:** parser के माध्यम से टेम्पलेट और स्क्रिप्ट, `.html` और Pug टेक्स्ट के रूप में, हर लेयर, और रूट के बाहर के फ़ोल्डर जिनकी ओर कोई alias या `components` इंगित करता है।
- **छोड़ा जाता है:** `node_modules`, बिल्ड आउटपुट और लोकेल फ़ाइलें। `--ignore 'legacy/**,*.stories.ts'` से अपनी फ़ाइलें जोड़ें।
- **टेस्ट कोड** उपयोग माना जाता है, इसलिए `clean` और `check --only unused` उस कुंजी को रखते हैं जिसे केवल एक टेस्ट पढ़ता है। यह कभी कोई कुंजी नहीं जोड़ता: `extract` ऐसी कुंजियाँ छोड़ देता है, और `check` उन्हें अपरिभाषित के रूप में रिपोर्ट नहीं करता।

टेस्ट कोड का अर्थ है रूट फ़ोल्डर `tests`, `test`, `__tests__`, `e2e`, `cypress` और `playwright`, साथ ही कहीं भी `.spec` और `.test` JavaScript और TypeScript फ़ाइलें (`.ts`, `.tsx`, `.mts`, `.js`, `.jsx`, `.mjs` आदि)। केवल रूट फ़ोल्डर नीचे दिए गए संदेहों से मुक्त हैं: `pages/tests/[id].vue` किसी अन्य पेज जैसा ही पेज है, और ऐसे ही `public/` और minified फ़ाइलें हैं, जिनका कोड ऐप का हिस्सा नहीं है।

कमांड पहचानते हैं:

- `$t`, `$ts`, `$tc`, `$has` और `$_t(route)`;
- `useI18n()` और `useTranslationServerMiddleware()` से `t()`;
- टेम्पलेट और JSX में `<i18n-t keypath>`, और `<i18n-group prefix>`;
- `const { t: tr } = useI18n()` जैसे aliases।

### `clean` कैसे तय करता है {#how-clean-decides}

`clean` किसी जीवित कुंजी को हटाने के बजाय किसी मृत कुंजी को छोड़ देना पसंद करता है। कुंजी तब बनी रहती है जब इनमें से कोई भी सही हो:

- कोई कॉल उसका, या उसके नीचे या ऊपर की किसी कुंजी का उपयोग करती है;
- कोड में कोई स्ट्रिंग उसके बराबर है: `const key = 'menu.home'`, `<Item label="menu.home" />`;
- प्रोजेक्ट में कोई JSON, YAML या Markdown फ़ाइल उसे शामिल करती है;
- किसी गणना की गई कुंजी की स्थिर शुरुआत उसे कवर करती है: `` $t(`status.${state}`) `` `status.` के नीचे सब कुछ रखता है;
- कोई लेयर उसे परिभाषित करती है।

जब `clean` जान नहीं सकता, तो वह कुछ भी बदले बिना रुक जाता है, और कारण सूचीबद्ध करता है:

- कोई कुंजी पूरी तरह गणना की गई है, जैसे `$t(name)`, `<i18n-t :keypath="name" />` या `<i18n-t v-bind="props" />` में;
- `$t` एक मान के रूप में पास किया जाता है, जैसे `items.map($t)` में;
- `t` नामक कोई फ़ंक्शन गणना किया गया तर्क पाता है और किसी parameter, import या कॉल से आता है: यह असली फ़ंक्शन के चारों ओर एक wrapper हो सकता है। वही फ़ाइल जिस फ़ंक्शन को परिभाषित करती है वह नहीं गिना जाता, क्योंकि wrapper के अंदर उसकी अपनी कॉल होगी;
- कोई सोर्स फ़ाइल parse नहीं होती;
- कोई भी फ़ाइल किसी भी कुंजी का उपयोग नहीं करती, जिसका आमतौर पर अर्थ है कि वह गलत जगह देख रहा है;
- कोई लोकेल फ़ाइल प्रोजेक्ट के बाहर का symlink है, इसलिए कोई अन्य ऐप उसे पढ़ सकता है।

<Steps>

<Step title="पूर्वावलोकन">

`i18n-micro clean --dryRun` चलाएँ और जो वह सूचीबद्ध करता है उसकी समीक्षा करें।

</Step>

<Step title="कुंजियों को सुरक्षित रखें">

जो कुंजियाँ केवल अप्रयुक्त दिखती हैं उन्हें `--exclude '^errors\.'` से बनाए रखें।

</Step>

<Step title="हटाएँ">

इसे `--force` के साथ फिर से चलाएँ।

</Step>

</Steps>

## गायब कुंजियों का अनुवाद करें {#translate-missing-keys}

```bash
i18n-micro translate --dryRun                     # keys and characters per locale, nothing sent
export I18N_TRANSLATE_TOKEN=...                   # or put it in .env
i18n-micro translate --service deepl --locale de,fr
```

- `translate` गायब या खाली कुंजियाँ भरता है; `--replace` सब कुछ फिर से अनुवाद करता है।
- प्लेसहोल्डर और बहुवचन रूप सुरक्षित रहते हैं। जिस अनुवाद ने कोई प्लेसहोल्डर खो दिया वह लिखा नहीं जाता: कुंजी सूचीबद्ध होती है और कमांड `1` के साथ बाहर निकलता है।
- अगला अनुरोध जाने से पहले हर बैच सहेजा जाता है, इसलिए विफलता से केवल वही अनुरोध व्यर्थ जाता है जो विफल हुआ।

| `--service` | सेवा | `--token` | उपयोगी `--options` |
| --- | --- | --- | --- |
| `ai` | Vercel AI Gateway, OpenAI, Anthropic या कोई भी OpenAI-संगत सर्वर | API कुंजी, या `AI_GATEWAY_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` | `provider`, `model`, `baseUrl`, `maxTokens` |
| `azure` | Azure Translator | Subscription कुंजी | `region` |
| `deepl` | DeepL, Free कुंजियों सहित | Auth कुंजी | `formality`, `glossaryId`, `context` |
| `google` | Google Cloud Translation v2 | API कुंजी | `model` |
| `libretranslate` | LibreTranslate | वैकल्पिक | `baseUrl` |
| `yandexcloud` | Yandex Cloud Translate | API कुंजी, या `authScheme:Bearer` के साथ IAM टोकन | `folderId`, `model` |

विकल्प `key:value` जोड़े हैं: `--options provider:openai,model:gpt-4o-mini`। सभी सेवाएँ `baseUrl`, `retries`, `retryDelayMs` और `timeoutMs` भी लेती हैं। किसी अनुवाद अनुरोध का बिल पहले ही बन चुका हो सकता है, इसलिए उसे केवल `429` या `503` के बाद दोहराया जाता है, और तब नहीं जब सेवा एक मिनट से अधिक प्रतीक्षा करने को कहे।

<Warning>

फ़्लैग shell history और process lists में दिखाई देते हैं, इसलिए टोकन को एनवायरनमेंट वेरिएबल के माध्यम से पास करें। CLI जो कुछ गुप्त जानता है उसे जहाँ भी प्रिंट करता है वहाँ मास्क करता है, `--debug` सहित: टोकन, provider कुंजियाँ, Basic credentials, और आपके द्वारा कॉन्फ़िगर किए गए URL की query और credentials। जो सर्वर किसी कुंजी को वापस दोहराने से पहले उसका फ़ॉर्मेट बदल देता है वह उसकी पहुँच से बाहर है, इसलिए विफल रन के लॉग को सावधानी से संभालें।

</Warning>

`ai` सेवा एक glossary का पालन करती है। जब `.i18n-glossary.json` मौजूद होती है तो बिना फ़्लैग के उसका उपयोग होता है; `--glossaryFile` कोई दूसरी फ़ाइल चुनता है।

```json .i18n-glossary.json
{ "entries": [{ "source": "Cart", "target": "Warenkorb", "to": "de" }] }
```

## हार्डकोडेड टेक्स्ट को कुंजियों में बदलें {#turn-hardcoded-text-into-keys}

```bash
i18n-micro text-to-i18n --dryRun   # list what would change
i18n-micro text-to-i18n            # rewrite the templates
```

```vue
<!-- before -->
<h1>Welcome to our site</h1>
<!-- after -->
<h1>{{ $t('pages.index.welcome-to-our') }}</h1>
```

केवल प्रोजेक्ट के अपने `.vue` टेम्पलेट फिर से लिखे जाते हैं, किसी लेयर या alias लक्ष्य के नहीं। हर फिर से लिखी गई फ़ाइल को लिखने से पहले फिर से parse किया जाता है। ये सूचीबद्ध होते हैं और अपना टेक्स्ट बनाए रखते हैं:

- `.ts` फ़ाइलों और स्क्रिप्ट में टेक्स्ट, क्योंकि `$t` हर जगह scope में नहीं है;
- मार्कअप या किसी इंटरपोलेशन के बगल का टेक्स्ट, जैसे `<p>Hello <b>world</b> today</p>`: आधे वाक्य का अलग से अनुवाद नहीं किया जा सकता;
- कोई जनरेट की गई कुंजी जो किसी दूसरी से टकराएगी, जैसा कि एक parent पेज और उसका child कर सकते हैं;
- कोई ज्ञात कुंजी जो quotes के बीच नहीं जा सकती।

</Warning>

## किसी कुंजी का नाम बदलें {#rename-a-key}

```bash
i18n-micro rename --from common.save --to actions.save
i18n-micro rename --from settings --to account.settings   # a whole namespace
```

`rename` syntax tree संपादित करता है, इसलिए comments और असंबंधित स्ट्रिंग जैसी हैं वैसी रहती हैं, और aliases और `:keypath` का अनुसरण किया जाता है। किसी लेयर की अपनी फ़ाइल कभी नहीं बदली जाती। जो यह फिर से नहीं लिख सकता उसके बारे में चेतावनी देता है, और उसे वैसा ही छोड़ देता है:

- पुराने नाम के अंतर्गत कोई गणना की गई कुंजी;
- उसके बराबर हर सादी स्ट्रिंग;
- कोई Pug टेम्पलेट;
- किसी लेयर में या प्रोजेक्ट के बाहर किसी फ़ोल्डर में कोई सोर्स।

`--to` ऐसी कुंजी होनी चाहिए जो कोड में लिखी जा सके: कोई quotes नहीं, कोई backslash नहीं, कोई खाली segment नहीं, कोई `__proto__` नहीं।

## अनुवादकों के साथ फ़ाइलें साझा करें {#exchange-files-with-translators}

```bash
i18n-micro export --format csv
i18n-micro import --format csv --dryRun
```

**`export`** हर लोकेल की हर कुंजी लिखता है, बिना अनुवाद वाली सहित, डिफ़ॉल्ट-लोकेल टेक्स्ट को सोर्स के रूप में रखते हुए: CSV में एक `Source` कॉलम, PO में एक `#.` comment।

- `--dir` के बिना, PO `pots` में और CSV `csv_exports` में जाता है।
- यह आउटपुट फ़ोल्डर में `.i18n-export.json` में दर्ज करता है कि उसने क्या लिखा। जब कोई फ़ाइल तब से बदल गई हो और उसमें ऐसे अनुवाद हों जो लोकेल फ़ाइलों में नहीं हैं, fuzzy PO प्रविष्टियों सहित, तो यह रुक जाता है; `--force` उन्हें ओवरराइट करता है। लोकेल फ़ाइलों के सामान्य संपादन इसे नहीं रोकते।

**`import`** मर्ज करता है, खाली सेल छोड़ देता है, और `fuzzy` चिह्नित PO प्रविष्टियाँ छोड़ देता है।

- जो कुंजी किसी मान को ओवरराइट करेगी, या कुंजियों के पूरे समूह के ऊपर कोई मान, सूचीबद्ध होकर छोड़ दी जाती है, और कमांड `1` के साथ बाहर निकलता है।
- यह exit `2` के साथ रुक जाता है जब catalog अप्रत्याशित स्थान पर हो, किसी पेज का ऐसा catalog हो जिसे पिछले export ने नहीं लिखा, CSV में कोई quote गलत जगह हो, या `disablePageLocales` के अंतर्गत कोई पेज प्रविष्टि हो।

किसी अनुवाद प्लेटफ़ॉर्म के लिए, उसकी अपनी CLI का उपयोग करें: [Crowdin](/hi/guide/crowdin) सेटअप JSON फ़ाइलों को सिंक करता है, पेज फ़ाइलों सहित।

## अपने स्वयं के endpoint के साथ सिंक करें {#sync-with-your-own-endpoint}

`sync-remote` वैश्विक लोकेल फ़ाइलों को आपके द्वारा चलाए जाने वाले HTTP endpoint के साथ साझा करता है। पेज फ़ाइलें स्थानीय रहती हैं, और कमांड यह बताता है। `.i18n-remote.json` में endpoint का वर्णन करें:

```json .i18n-remote.json
{ "url": "https://translations.example.com", "path": "translations" }
```

Endpoint `GET` और `PUT` का उत्तर `{ locale: messages }` ऑब्जेक्ट के साथ देता है। `auth: { username, password }` से प्रमाणीकरण करें, या `I18N_REMOTE_TOKEN` में एक bearer टोकन रखें।

| | Pull | Push |
| --- | --- | --- |
| क्या जाता है | जो आपके पास नहीं है उसे भरता है और वे कुंजियाँ रखता है जो केवल आपके पास हैं | प्रोजेक्ट की अपनी कुंजियाँ भेजता है, किसी लेयर की नहीं, और आपकी खाली कुंजियाँ छोड़ देता है |
| टकराव | दोनों तरफ़ अलग कुंजी: कुछ नहीं लिखा जाता, exit `1`; `--force` remote मान लेता है | PUT दस्तावेज़ को बदल देता है, इसलिए push पहले endpoint पढ़ता है और exit `1` के साथ रुकता है जब उसमें ऐसा टेक्स्ट हो जो आपके पास नहीं है; `--force` उसे ओवरराइट करता है। `404` का उत्तर देने वाले endpoint के पास खोने को कुछ नहीं है |
| `--dryRun` | endpoint से पढ़ता है, बदलाव सूचीबद्ध करता है, कुछ नहीं लिखता | बताता है कि क्या भेजा जाएगा, endpoint से संपर्क किए बिना |

जो लोकेल आपने कॉन्फ़िगर नहीं किया वह छोड़ दिया जाता है, और खाली remote मान कुछ भी साफ़ नहीं करता।

## nuxt-i18n-micro-cli से आना {#moving-from-nuxt-i18n-micro-cli}

| पुराना कमांड | अब |
| --- | --- |
| `validate` | `check` |
| `diff` | `check --only missing` |
| `check-duplicates` | `check --only duplicates` |
| `export-csv`, `import-csv` | `export --format csv`, `import --format csv` |
| `--potsDir`, `--csvDir` | `--dir` |
| `estimate` | `translate --dryRun` |
| `glossary` | `.i18n-glossary.json` संपादित करें; `translate` उसे स्वयं पढ़ता है |
| `backup`, `restore` | Git, जो पहले से आपकी लोकेल फ़ाइलें रखता है |
| `init` | `nuxi init`, फिर `modules` में `nuxt-i18n-micro` जोड़ें |
| `split` | हटाया गया: मॉड्यूल split फ़ाइलें नहीं पढ़ता |
| `optimize` | `check --only duplicates` |
| `replace-values` | आपका एडिटर या `sed` |
| `stats --full` | `stats`; विवरण [DevTools](/hi/guide/devtools) में है |
| `search --hardcodedOnly` | `text-to-i18n --dryRun` |
| `search --preferUnused`, `--onlyVue` | हटाया गया |
| `lint` नियम `no-html-tags`, `no-special-chars`, `no-mixed-case`, `no-missing-punctuation`, `no-inconsistent-pluralization` | हटाए गए: वे सामान्य टेक्स्ट को चिह्नित करते थे। ज़रूरत हो तो एक `customRegexRules` प्रविष्टि लिखें |
| `text-to-i18n --extractOnlyDirs`, `--extractOnlyPatterns`, `--verbose` | हटाए गए: कोड कभी फिर से नहीं लिखा जाता |
| `--logLevel verbose` | हटाया गया: यह कुछ नहीं करता था |

**हटाई गई सेवाएँ:** `googlefree`, `yandex` (`yandexcloud` का उपयोग करें), `ibm`, `lingvatranslate`, `modernmt`, `lilt`, `unbabel`, `reverso`, `baidu`, `papago`, `tencent`, `systran`, `mymemory`।

**हटाए गए `sync-remote` टाइप:** `github`, `gitlab`, `crowdin`, `lokalise`, `tolgee`, `weblate`। प्लेटफ़ॉर्म की अपनी CLI का उपयोग करें, या `custom`, जिसे अब किसी `type` की ज़रूरत नहीं है।

### बदला हुआ व्यवहार {#changed-behaviour}

- `extract` और `sync` अब `''` नहीं लिखते। कुंजियाँ अनुपस्थित रहती हैं, और `check` उन्हें रिपोर्ट करता है। `extract` कोई कुंजी केवल तब लिखता है जब कोड उसका टेक्स्ट देता है।
- `extract` पेज कुंजियों को `locales/pages/<route name>/` में लिखता है, जहाँ मॉड्यूल उन्हें पढ़ता है, और Nuxt 4 पर `app/` को स्कैन करता है। `pages/_about` और `pages/blog_` जैसी डायरेक्टरी से सब कुछ स्थानांतरित करें, और कोई भटकी हुई `locales/pages/<locale>.json` हटा दें।
- `nuxt.config` से `translationDir` का सम्मान किया जाता है; पहले हर कमांड चुपचाप `locales` का उपयोग करता था।
- `defaultLocale` के बिना, डिफ़ॉल्ट `en` है, मॉड्यूल की तरह, और `DEFAULT_LOCALE` का सम्मान किया जाता है। पहले यह पहला लोकेल हुआ करता था।
- `check` और `sync` डिफ़ॉल्ट लोकेल को संदर्भ के रूप में उपयोग करते हैं और पेज फ़ाइलें जाँचते हैं। `"a.b"` और `a: { b }` एक ही कुंजी गिने जाते हैं।
- `clean` कहीं भी, किसी भी scope में उपयोग की गई कुंजी रखता है, और जब उपयोग सिद्ध नहीं किया जा सकता तो रुक जाता है। `--include` और `--exclude` चुनते हैं कि क्या हटाया जा सकता है।
- `sync` भी इसी तरह रुकता है, और तब भी जब डिफ़ॉल्ट लोकेल के पास तुलना के लिए कोई कुंजी नहीं होती। `--force` इसे ओवरराइड करता है। यह तब भी रुकता है जब `DEFAULT_LOCALE` ने `nuxt.config` से अलग संदर्भ चुना हो।
- एकल-डैश लंबे फ़्लैग और भटके हुए तर्क त्रुटियाँ हैं: `clean -dryRun` अब `clean` नहीं चलाता।
- कोई read-only फ़ाइल, या ऐसी फ़ाइल जो UTF-8 नहीं है, सहेजी नहीं जा सकती: कमांड कुछ भी बदलने से पहले रुक जाता है। ऐसी फ़ाइल पढ़ना ठीक है। दोहराई गई कुंजी, `__proto__` नामक कुंजी और 2^53 से बड़ा पूर्णांक किसी कमांड को रोक देते हैं, क्योंकि सहेजने पर वे खो जाएँगे।
- ऐसा फ़्लैग जिसे मान चाहिए और जिसके बाद कोई दूसरा फ़्लैग आता है, एक त्रुटि है; डैश से शुरू होने वाले मान के लिए `--flag=--value` लिखें। boolean फ़्लैग केवल `true` या `false` लेता है।
- `export` उन अनुवादों को ओवरराइट करने के बजाय रुक जाता है जो कभी import नहीं हुए।
- Exit कोड `0`, `1` और `2` हैं; पहले विफलताएँ `1` होती थीं, और `diff` और `check-duplicates` हमेशा `0`।
- `lint --fix` अब `.bak` फ़ाइलें नहीं छोड़ता।
- सहेजना किसी फ़ाइल का indentation, line endings, अंतिम newline, symlink और hard link बनाए रखता है, और जिन फ़ाइलों को उसने नहीं बदला उन्हें वैसा ही छोड़ देता है।
- गलत टाइप किया गया या हटाया गया फ़्लैग अब एक त्रुटि है, चुपचाप अनदेखा नहीं किया जाता।
- `--dir` जैसे पाथ प्रोजेक्ट के सापेक्ष हैं, shell के नहीं।
- `ai` अब `@ai-sdk/*` पैकेज लोड नहीं करता: `provider` `gateway`, `openai` या `anthropic` का उपयोग करें, या OpenAI-संगत सर्वर के लिए `baseUrl`।
