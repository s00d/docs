---

डिफ़ॉल्ट रूप से हर locale किसी पेज को एक ही पाथ पर दिखाता है: `/en/about`, `/de/about`। स्थानीयकृत पाथ हर locale को अपने शब्द इस्तेमाल करने देते हैं, जैसे `/de/ueber-uns`, जबकि पेज फ़ाइल वही रहती है। आप इन्हें पेज में `$defineI18nRoute` से सेट करते हैं, या एक साथ कई पेजों के लिए `nuxt.config.ts` में।

## पेज में {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

`prefix_except_default` और `defaultLocale: 'en'` के साथ पेज `/about`, `/de/ueber-uns` और `/fr/a-propos` पर जवाब देता है। जिस locale की कोई entry नहीं है वह डिफ़ॉल्ट पाथ रखता है। पाथ locale code के बिना लिखें: prefix [strategy](/hi/guide/strategy) जोड़ती है, और locale code से शुरू होने वाला पाथ एक चेतावनी लॉग करता है। यह कॉल और क्या-क्या स्वीकार करता है, वह [पेज कॉन्फ़िगरेशन](/hi/guide/per-component-translations) पर है।

## nuxt.config में {#in-nuxt-config}

[`globalLocaleRoutes`](/hi/api/module-options#globallocaleroutes) किसी भी पेज के लिए यही करता है, उसके पाथ को key बनाकर (या बिना आगे के slash के लिखे जाने पर उसके route name को key बनाकर):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

जब कोई पेज `localeRoutes` सेट करता है और `globalLocaleRoutes` में वही key होती है, तो config की entry मान्य होती है।

## Dynamic params {#dynamic-params}

params को Nuxt के किसी भी रूप में लिखें: `[id]`, `[[page]]`, `[...slug]`, या `:id()`। param के नाम पेज फ़ाइल से मेल खाने चाहिए।

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

Nested पेज एक absolute child पाथ (`/ueber-uns/team`) या parent के स्थानीयकृत पाथ के सापेक्ष पाथ (`team`) लेते हैं।

## स्थानीयकृत पेजों से लिंक करना {#linking-to-localized-pages}

लिंक लक्ष्य locale के स्थानीयकृत पाथ पर resolve होते हैं, चाहे आप route name पास करें या सादा पाथ:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

Route names फ़ाइल पाथ से आते हैं (`pages/about/team.vue` का नाम `about-team` है), जब तक कि आप `definePageMeta({ name })` से कोई नाम सेट न करें।

## प्रति-locale slugs {#per-locale-slugs}

जब slug ख़ुद हर locale में अलग हो (`/our-products/red-shoe` बनाम `/de/unsere-produkte/roter-schuh`), तो डेटा लोड होने के बाद `$setI18nRouteParams` से भाषा switcher को बताएँ कि कौन-से params इस्तेमाल करने हैं:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

इसके बाद `$switchLocalePath('de')` और `<i18n-switcher>` `/de/unsere-produkte/roter-schuh` पर लिंक करते हैं। Keys locale codes हैं, values नाम के अनुसार params हैं (जैसे पेज फ़ाइल में)।

Layout में मौजूद switcher पेज के async setup के यहाँ पहुँचने से पहले render होता है, इसलिए render ख़त्म होने पर मॉड्यूल `<i18n-switcher>` के links को फिर से लिखता है, चाहे वह `app.vue` में हो या पेज में। इससे सर्वर HTML, बिना JavaScript वाला विज़िटर और पहला क्लाइंट render एकमत रहते हैं। इसके लिए params को SSR के दौरान सेट करें: `lazy` या `server: false` के साथ links केवल hydration के बाद बदलते हैं। Nuxt की SSR streaming params ज्ञात होने से पहले ही HTML भेज देती है, इसलिए उसके तहत पहले HTML में links URL के अपने params ही रखते हैं।

केवल switcher के अपने links फिर से लिखे जाते हैं। हाथ से लिखा `$switchLocalePath` link params सेट होने के बाद render होना चाहिए, इसलिए उसे उसी पेज में रखें जो उन्हें सेट करता है, और वह भी किसी `await` के बाद। Layout में वह पहले render होता है: उसका सर्वर HTML URL के params रखता है, और hydration एक mismatch की चेतावनी देता है। वहाँ `<i18n-switcher>` इस्तेमाल करें, और रूप-रंग के लिए उसके slots और `custom*Style` props का उपयोग करें।

Params उसी पेज के होते हैं जिसने उन्हें सेट किया:

- किसी दूसरे पाथ पर navigation commit होने पर वे हटा दिए जाते हैं, इसलिए हर पेज अपने params ख़ुद सेट करता है। रद्द किया गया navigation उन्हें जस का तस छोड़ देता है।
- `$setI18nRouteParams` को `setup` में `useNuxtApp()` या `useI18n()` से लें, तब भी जब आप उसे बाद में किसी `useAsyncData` handler में कॉल करते हैं। वहाँ लिए जाने पर फ़ंक्शन अपने पेज को जानता है: अगर विज़िटर जा चुका है, तो देर से हुआ कॉल कुछ नहीं करता।
- `keepalive` के साथ, विज़िटर के लौटने पर पेज को उसके सेट किए हुए params वापस मिल जाते हैं। `useI18nHead` भी ऐसा ही करता है।

## pages:extend में जोड़े गए रूट {#routes-added-in-pagesextend}

`pages:extend` hook में आप जो रूट push करते हैं, उनके पास कोई पेज फ़ाइल नहीं होती जिससे `$defineI18nRoute` पढ़ा जा सके, और अक्सर उनमें से कई एक ही wrapper component साझा करते हैं। बिना `name` के push किए गए रूट को वह नाम मिलता है जो Nuxt उसके पाथ को देता (`/a/:id()` बन जाता है `a-id`), ताकि भाषा links उस तक पहुँचें, जब तक कि किसी दूसरे रूट के पास पहले से वह नाम न हो; तब उसे एक स्पष्ट `name` दें। एक ही सूची रखें और `@i18n-micro/utils/split-locale-routes` के `splitLocaleRoutes` से उसे pages और route name को key बनाकर `globalLocaleRoutes` में बाँटें (पैकेज को अपनी dependencies में जोड़ें):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

स्थानीयकृत पाथ `route.meta` में न रखें: वे क्लाइंट route table में चले जाएँगे।
