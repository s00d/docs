`$defineI18nRoute` किसी एक पेज के लिए i18n विकल्प उस पेज के अंदर से ही सेट करता है। इसका उपयोग तब करें जब कोई पेज केवल कुछ लोकेल में मौजूद हो, उसे अपने स्वयं के स्थानीयकृत पाथ की आवश्यकता हो, उसके अपने कुछ अनुवाद हों, या उसे hreflang/canonical टैग नहीं मिलने चाहिए। मॉड्यूल बिल्ड के समय इस कॉल को पढ़ता है और इसे जनरेट किए गए रूट्स में शामिल कर देता है।

## किसी पेज को कुछ लोकेल तक सीमित करें {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

डिफ़ॉल्ट `prefix_except_default` रणनीति के अंतर्गत केवल `/product` और `/de/product` जनरेट होते हैं; किसी अन्य लोकेल में पेज का कोई रूट नहीं होता। यही बात `nuxt.config.ts` से [`routeLocales`](/hi/api/module-options#routelocales) के साथ सेट की जा सकती है।

`$defineI18nRoute` एक Nuxt ऐप इंजेक्शन है, कंपाइलर मैक्रो नहीं: इसे हमेशा `useNuxtApp()` से लें और `$` के साथ कॉल करें। बिल्ड चरण द्वारा केवल `$defineI18nRoute(` पहचाना जाता है।

## इनलाइन अनुवाद जोड़ें {#add-inline-translations}

ऐरे के बजाय एक ऑब्जेक्ट पास करें। इसकी कुंजियाँ अनुमत लोकेल हैं, इसके मान सक्रिय लोकेल के लिए पेज की डिक्शनरी में मर्ज किए जाते हैं।

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

इनलाइन अनुवाद हर लोकेल के लिए पेज कंपोनेंट के अंदर शिप होते हैं। कुछ कुंजियों से बड़ी किसी भी चीज़ के लिए [पेज अनुवाद फ़ाइलों](/hi/guide/translations) को प्राथमिकता दें; इनलाइन कुंजियों को आत्मनिर्भर पेजों और कंपोनेंट्स के लिए रखें।

## स्थानीयकृत पाथ सेट करें {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

`prefix_except_default` और `defaultLocale: 'en'` के साथ यह `/welcome` और `/de/willkommen` बनाता है। इनलाइन लोकेल ऑब्जेक्ट के अंदर एक `path` भी यही करता है: `locales: { de: { path: '/willkommen' } }`। डायनामिक पैरामीटर, नेस्टेड रूट और कॉन्फ़िग-स्तर का विकल्प [स्थानीयकृत पाथ](/hi/guide/custom-locale-routes) में बताए गए हैं।

## SEO टैग बंद करें {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

कॉन्फ़िग-स्तर का विकल्प [`routeDisableMeta`](/hi/api/module-options#routedisablemeta) है। टैग क्या हैं, यह [SEO](/hi/guide/seo) पेज पर बताया गया है।

## बिल्ड क्या पढ़ सकता है {#what-the-build-can-read}

बिल्ड चरण हर पेज फ़ाइल में कॉल को ढूँढता है और आपका ऐप चलाए बिना उसके आर्ग्युमेंट का मूल्यांकन करता है। यह तब काम करता है जब कॉन्फ़िग:

- एक लिटरल ऑब्जेक्ट हो (स्ट्रिंग्स, ऐरे, नेस्टेड ऑब्जेक्ट, टेम्पलेट लिटरल, `process.env.NODE_ENV` पर टर्नरी);
- उसी `<script setup>` में घोषित कॉन्स्टेंट से बना हो (`const locales = ['en', 'de']`, स्प्रेड सहित);
- `code` फ़ील्ड वाले ऑब्जेक्ट्स का ऐरे हो (`[{ code: 'en' }, { code: 'de' }]`)।

यह किसी अन्य मॉड्यूल से इंपोर्ट किए गए मान, या ऐसी कोई भी चीज़ नहीं पढ़ सकता जिसे रनटाइम पर आपके ऐप की आवश्यकता हो (composables, `await`, फ़ेच किया गया डेटा)। ऐसे में बिल्ड `Ignored the $defineI18nRoute() config in <file>` लॉग करता है और पेज डिफ़ॉल्ट लोकेल और रूट रखता है।

रनटाइम पर यह कॉल केवल वर्तमान लोकेल के इनलाइन अनुवादों को मर्ज करता है और लोकेल बदलने पर उन्हें फिर से मर्ज करता है। `locales`, `localeRoutes` और `disableMeta` केवल बिल्ड के माध्यम से प्रभावी होते हैं, इसलिए उन्हें बदलने के लिए रीबिल्ड की आवश्यकता होती है (डेव सर्वर सेव करने पर रीबिल्ड करता है)।
