`useI18n()` को कॉल करने वाले कंपोनेंट को यूनिट टेस्ट में एक i18n इंस्टेंस की आवश्यकता होती है। `@i18n-micro/test-utils` आपको वास्तविक अनुवाद, बहुवचन और फ़ॉर्मेटिंग लॉजिक वाला एक नकली `useI18n()` देता है, ताकि आप अपने स्वयं के शब्दकोशों के साथ और बिना Nuxt सर्वर के किसी कंपोनेंट को माउंट कर सकें। रूटिंग और रीडायरेक्ट के लिए, `@nuxt/test-utils` के साथ वास्तविक मॉड्यूल को एंड-टू-एंड चलाएँ।

यह पेज आपके एप्लिकेशन के परीक्षण के बारे में है। यह रिपॉज़िटरी स्वयं मॉड्यूल का परीक्षण कैसे करती है, यह [मॉड्यूल का परीक्षण](https://s00d.github.io/nuxt-i18n-micro/contributing/testing) पर है।

## इंस्टॉल करें {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

```bash npm
npm install -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

</CodeGroup>

## useI18n को मॉक करें {#mock-usei18n}

```ts
// tests/unit-setup.ts
import { setupNuxtI18nMock } from '@i18n-micro/test-utils'
import { mockNuxtImport } from '@nuxt/test-utils/runtime'
import { beforeEach, vi } from 'vitest'

export const { i18n, useI18n, setTranslationsFromJson } = setupNuxtI18nMock({
  spy: vi.fn, // every method becomes a vi.fn, so you can assert calls
  beforeEach, // reset state and reseed `translations` before each test
  translations: { welcome: 'Welcome' },
})

mockNuxtImport('useI18n', () => useI18n)
```

```ts
// vitest.config.ts
import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    environment: 'nuxt',
    setupFiles: ['./tests/unit-setup.ts'],
  },
})
```

`mockNuxtImport` को सेटअप फ़ाइल में रखें: `@nuxt/test-utils` को इसे ट्रांसफ़ॉर्म करना होता है। `setupNuxtI18nMock` एक निजी अनुवाद कैश का उपयोग करता है, इसलिए समानांतर टेस्ट फ़ाइलें स्थिति साझा नहीं करतीं।

## एक टेस्ट लिखें {#write-a-test}

```vue
<!-- components/Greeting.vue -->
<script setup lang="ts">
const { $t } = useI18n()
</script>

<template>
  <p>{{ $t('welcome') }}</p>
</template>
```

```ts
// tests/greeting.spec.ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { expect, it } from 'vitest'
import Greeting from '~/components/Greeting.vue'
import de from '~/locales/de.json'
import { i18n, setTranslationsFromJson } from './unit-setup'

it('renders the German greeting', async () => {
  await setTranslationsFromJson('de', de)
  i18n.setLocale('de')

  const wrapper = await mountSuspended(Greeting)
  expect(wrapper.text()).toBe('Willkommen') // de.json: { "welcome": "Willkommen" }
})
```

नकली इंस्टेंस वास्तविक `useI18n()` जैसे ही मेथड उपलब्ध कराता है (`$t`, `$tc`, `$tn`, `$td`, `$has`, `$localePath`, …, `$` के साथ और बिना) और साथ ही टेस्ट के लिए सेटर: `setLocale`, `setLocales`, `setDefaultLocale`, `setRouteName`, `setTranslationsFromJson`, `loadPageTranslations`, `mergeTranslations`, `setMissingHandler`.

`$localePath` और `$switchLocalePath` ऐसे स्टब हैं जो `strategy` विकल्प के अनुसार पाथ में उपसर्ग जोड़ते हैं (कोई वास्तविक राउटर नहीं)। वास्तविक लिंक और रीडायरेक्ट का एंड-टू-एंड परीक्षण करें।

## निचले स्तर के हेल्पर {#lower-level-helpers}

| हेल्पर | किसके लिए उपयोग करें |
| --- | --- |
| `createIsolatedFakeI18n(options)` | Nuxt `useI18n` वायरिंग के बिना एक पृथक नकली इंस्टेंस, जैसे `global.mocks` के साथ साधारण `@vue/test-utils` `mount` के लिए। |
| `createFakeI18n(options)` | साझा मॉड्यूल कैश पर एक नकली इंस्टेंस (`beforeEach` में `resetI18n()` कॉल करें), या `isolated: true` के साथ पृथक। |
| `createI18nTestContext(options)` | दोनों के पीछे का कॉन्टेक्स्ट, जब आपको कई नकली इंस्टेंस चाहिए। |
| `t`, `tc`, `ts`, `tn`, `td`, `tdr`, `has` | साधारण फ़ंक्शन के परीक्षण के लिए साझा कॉन्टेक्स्ट पर सीधे कॉल। |

मॉक एक `BaseI18n` है: `t`, `tc`, `tn`, `td`, `tdr` और `has` वास्तविक हैं, वास्तविक शब्दकोशों पर, इसलिए टेस्ट वही देखता है जो ऐप दिखाता है।

ऊपर दिए गए फ़ैक्टरी हेल्पर `locale`, `defaultLocale`, `locales`, `routeName`, `strategy`, `translations` और `messages` (प्रति locale शब्दकोश) स्वीकार करते हैं। एक पूरा उदाहरण प्रोजेक्ट यहाँ है: [`packages/test-utils/example`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/test-utils/example)।

## एंड-टू-एंड टेस्ट {#end-to-end-tests}

रूटिंग, रीडायरेक्ट, SEO टैग और पेलोड लोडिंग के लिए वास्तविक मॉड्यूल आवश्यक है। अपने ऐप को `@nuxt/test-utils/e2e` के साथ शुरू करें:

```ts
// tests/e2e/locales.test.ts
import { $fetch, fetch, setup } from '@nuxt/test-utils/e2e'
import { describe, expect, it } from 'vitest'

describe('locales', async () => {
  await setup({ server: true })

  it('serves the German page', async () => {
    expect(await $fetch('/de')).toContain('lang="de-DE"')
  })

  it('redirects / for a German browser', async () => {
    const res = await fetch('/', { headers: { 'accept-language': 'de' }, redirect: 'manual' })
    expect(res.headers.get('location')).toBe('/de')
  })
})
```

दूसरा टेस्ट `prefix` (या किसी अन्य डिफ़ॉल्ट locale के साथ `prefix_except_default`) मानता है; `/` कब रीडायरेक्ट करता है, इसके लिए [Locale डिटेक्शन](/hi/guide/locale-detection) देखें।
