एक Nuxt लेयर कई ऐप के लिए i18n कॉन्फ़िग और `locales/` फ़ोल्डर रख सकती है, और हर ऐप जो उसे चाहिए वह जोड़ता या ओवरराइड करता है। यह पेज वही दिखाता है, और यह भी कि एक बिल्ड कई डोमेन को कैसे सर्व करता है।

## कॉन्फ़िग और अनुवाद साझा करें {#share-config-and-translations}

```ts
// base/nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    defaultLocale: 'en',
  },
})
```

```ts
// shop/nuxt.config.ts
export default defineNuxtConfig({
  extends: ['../base'], // a layer directory or package, not a nuxt.config file
  i18n: {
    locales: [
      { code: 'es', iso: 'es-ES' }, // added
      { code: 'fr', disabled: true }, // the base layer's fr, switched off here
    ],
  },
})
```

- **कॉन्फ़िग:** ऐप के स्केलर विकल्प लेयर के विकल्पों को बदल देते हैं। सभी लेयर की `locales` ऐरे मिला दी जाती हैं, और एक ही `code` वाली प्रविष्टियाँ एक में मर्ज होती हैं जिसमें ऐप के फ़ील्ड जीतते हैं, इसलिए कोई ऐप एक लोकेल जोड़ सकता है या विरासत में मिले लोकेल पर `disabled: true` जैसे फ़ील्ड सेट कर सकता है।
- **अनुवाद:** हर लेयर के `locales/` कुंजी-दर-कुंजी मर्ज होते हैं, पहले लेयर और अंत में ऐप, इसलिए `shop/locales/en.json` की कोई कुंजी `base/locales/en.json` की उसी कुंजी को ओवरराइड करती है। पेज फ़ाइलें (`locales/pages/<page>/`) भी इसी तरह मर्ज होती हैं।
- **पेज:** `$defineI18nRoute` हर लेयर के पेजों से पढ़ा जाता है।

जो फ़ोल्डर किसी लेयर का हिस्सा नहीं हैं, उन्हें मर्ज करने के लिए उन्हें [`additionalTranslationDirs`](/hi/api/module-options#additionaltranslationdirs) में सूचीबद्ध करें।

## कई डोमेन {#multiple-domains}

एक बिल्ड हर डोमेन को सर्व करता है। हर लोकेल को उसके डोमेन के साथ सूचीबद्ध करें; `baseDefault` उसे उस होस्ट का डिफ़ॉल्ट बनाता है:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'de', iso: 'de-DE', baseUrl: 'https://example.de', baseDefault: true },
      { code: 'nl', iso: 'nl-NL', baseUrl: 'https://example.de' },
      { code: 'fr', iso: 'fr-FR' },
    ],
  },
})
```

दोनों डोमेन को एक ही सर्वर की ओर इंगित करें। बाकी अनुरोध का होस्ट तय करता है:

- **डिफ़ॉल्ट:** होस्ट का `baseDefault` लोकेल। उसके बिना, बिल्ड डिफ़ॉल्ट यदि होस्ट उसे सर्व करता है, अन्यथा होस्ट का पहला लोकेल।
- **सर्व किए गए लोकेल:** उस होस्ट के लोकेल, साथ ही हर वह लोकेल जिसका कोई `baseUrl` नहीं है। `example.de` पर ये `de`, `nl` और `fr` हैं।
- **अन्य डोमेन के लोकेल** लिंक लक्ष्य हैं। `$localePath`, `$localeRoute`, `$switchLocalePath`, `<i18n-switcher>` और `hreflang` उनके `baseUrl` पर पूर्ण URL देते हैं, और `$switchLocale` वहाँ नेविगेट करता है। इस होस्ट पर उनके URL 404 हैं, और कुकी या `Accept-Language` उन्हें नहीं चुन सकते।
- **किसी अन्य डोमेन का लिंक** `$localePath` या `<i18n-link>` से होकर जाता है: `<NuxtLink :to="$localePath('/contact', 'de')">`, `<i18n-link :to="$localeRoute('/contact', 'de')">`। राउटर कोई पूर्ण ऑब्जेक्ट नहीं लेता, इसलिए `<NuxtLink :to="$localeRoute(...)">` और `router.push($localeRoute(...))` इसी origin पर रहते हैं। `localhost` या किसी प्रीव्यू होस्ट पर `baseUrl` वाला हर लोकेल ऐसा लिंक है, वर्तमान वाला भी। कोड में `navigateTo($localePath('/contact', 'de'), { external: true })`, या `$switchRoute` का उपयोग करें।
- **कोई भी अन्य होस्ट** बिल्ड कॉन्फ़िग पाता है, जिसमें `baseUrl` वाला हर लोकेल एक लिंक लक्ष्य है। अनुरोध से कुछ भी वापस नहीं दोहराया जाता: canonical और `hreflang` `metaBaseUrl` का उपयोग करते हैं, अन्यथा बिल्ड डिफ़ॉल्ट का `baseUrl` (बिना `baseUrl` वाले डिफ़ॉल्ट को `metaBaseUrl` या `site.url` चाहिए, देखें [SEO](/hi/guide/seo#set-the-public-origin))।
- `public/` में **पेलोड फ़ाइलें** स्टैटिक हैं: कोई भी होस्ट किसी भी लोकेल की फ़ाइल लौटाता है। हर डोमेन का [generate](/hi/guide/deployment#static-site-(nuxi-generate)) केवल उसी डोमेन की फ़ाइलें प्रकाशित करता है।

हर रणनीति के अंतर्गत `example.de`, `contact` के कस्टम पाथ के रूप में `de: '/kontakt'` के साथ:

| रणनीति | `/` | डिफ़ॉल्ट लोकेल का पेज | अन्य URL |
| --- | --- | --- | --- |
| `prefix_except_default` | `de` | `/kontakt` | `/de/kontakt` और `/en/contact` 404 हैं, `/contact` `/kontakt` पर रीडायरेक्ट होता है |
| `prefix_and_default` | `de` | `/kontakt` और `/de/kontakt`, लिंक `/kontakt` का उपयोग करते हैं | `/en/contact` और `/contact` 404 हैं |
| `prefix` | `/de` पर रीडायरेक्ट होता है | `/de/kontakt` | `/kontakt` `/de/kontakt` पर रीडायरेक्ट होता है, `/en/contact` 404 है |
| `no_prefix` | `de` | `/kontakt` | किसी अन्य डोमेन के लोकेल का कस्टम पाथ 404 है |

`prefix` के अंतर्गत किसी अन्य डोमेन का लिंक प्रीफ़िक्स बनाए रखता है, क्योंकि बिना प्रीफ़िक्स वाला URL केवल रीडायरेक्ट करेगा। `no_prefix` के अंतर्गत किसी अन्य डोमेन का लिंक उस होस्ट के डिफ़ॉल्ट लोकेल पर पहुँचता है: URL किसी दूसरे लोकेल का नाम नहीं ले सकता।

जानने योग्य बातें:

- **प्रॉक्सी के पीछे** होस्ट `Host` से आता है। यदि प्रॉक्सी सार्वजनिक होस्ट को इसके बजाय `X-Forwarded-Host` में रखता है, तो [`trustForwardedHost`](/hi/api/module-options#trustforwardedhost) सेट करें, और केवल तभी जब प्रॉक्सी उस हेडर को ओवरराइट करता हो। जो प्रॉक्सी दोनों में से कोई नहीं भेजता, वह डोमेन बिल्ड सर्व नहीं कर सकता। देखें [प्रॉक्सी या CDN के पीछे](/hi/guide/deployment#behind-a-proxy-or-cdn)।
- **`app.baseURL`** भी `baseUrl` में होना चाहिए: `app.baseURL: '/shop'` के साथ `baseUrl: 'https://example.de/shop'`।
- **होस्ट बिल्कुल सटीक मेल खाते हैं।** `www.example.de` एक अलग होस्ट है: उसे edge पर रीडायरेक्ट करें, या लोकेल पर वह `baseUrl` सेट करें। हर लोकेल के लिए केवल एक होस्ट।
- **कैश को होस्ट पर key करना चाहिए।** CDN आमतौर पर ऐसा करता है। Nitro का रूट कैश पाथ पर key करता है, इसलिए डोमेन बिल्ड में मॉड्यूल हर `swr` और `cache` नियम के `cache.varies` में `host` जोड़ता है, और `trustForwardedHost` के साथ `x-forwarded-host`। `cache: false` वाला नियम जैसा लिखा है वैसा ही रहता है। `isr` प्लेटफ़ॉर्म का कैश है: जाँचें कि वह होस्ट पर key करता है।
- **दो होस्ट डिफ़ॉल्ट के कस्टम पाथ टकराने नहीं चाहिए।** बिना प्रीफ़िक्स वाले रिकॉर्ड एक ही राउटर साझा करते हैं, इसलिए `/x` `example.de` पर एक पेज और `example.com` पर दूसरा पेज नहीं हो सकता।
- **प्री-रेंडर किए गए पेज:** `nuxt build` में `prerender: true` रूट नियम एक बार, बिना होस्ट के रेंडर होता है, और वह फ़ाइल हर डोमेन को उत्तर देती है। जो पेज हर डोमेन के लिए अलग हैं उन्हें सर्वर पर छोड़ें, या [हर डोमेन के लिए generate करें](/hi/guide/deployment#static-site-(nuxi-generate))।
- **`noPrefixRedirect`** हर होस्ट पर, होस्ट और विज़िटर के लोकेल के अनुसार चलता है।
- **`hashMode`:** होस्ट ऊपर की तरह रेंडर चुनता है, किसी अन्य डोमेन के लिंक हैश में रूट ले जाते हैं (`https://example.com/#/contact`)।
- **`ssr: false`:** ब्राउज़र डोमेन को `location.host` से पढ़ता है, इसलिए बिना सर्वर वाला होस्ट भी हल होता है।
- **[रनटाइम ओवरराइड](/hi/guide/runtime-overrides)** पहले लागू होते हैं। रनटाइम `disabledLocales` हर होस्ट पर लागू रहता है, एक अपवाद के साथ: `prefix_except_default` और `prefix_and_default` के अंतर्गत किसी होस्ट का डिफ़ॉल्ट अपने होस्ट पर सक्षम रहता है, क्योंकि उसके पेज बिना प्रीफ़िक्स वाले रिकॉर्ड हैं। `prefix` और `no_prefix` के अंतर्गत होस्ट अपने द्वारा सर्व किए जाने वाले अगले लोकेल पर चला जाता है। रनटाइम `defaultLocale` केवल अज्ञात होस्ट पर लागू होता है।

[स्टैटिक साइट](/hi/guide/deployment#static-site-(nuxi-generate)) के लिए, हर डोमेन के लिए एक बार generate करें।

### हर डोमेन के लिए एक ऐप {#one-app-per-domain}

जब डोमेन को अलग पेज या मॉड्यूल चाहिए, तब हर डोमेन के लिए एक छोटे ऐप के साथ साझा लेयर अब भी काम करती है। हर ऐप उसी `locales` सूची के ऊपर अपना `defaultLocale` सेट करता है। किसी अन्य डोमेन का लोकेल उस ऐप में 404 है, जैसा ऊपर बताया गया है।

### कोड में लोकेल चुनना {#choosing-the-locale-in-code}

SEO टैग में अनुरोध के अपने origin के साथ हर डोमेन को उत्तर देने वाले एकल इंस्टेंस के लिए, देखें [SEO](/hi/guide/seo#set-the-public-origin); कोड में होस्ट से लोकेल चुनने के लिए, देखें [कस्टम लोकेल पहचान](/hi/guide/custom-auto-detect)।
