अनुवाद सादी JSON फ़ाइलें हैं: साझा keys के लिए हर locale की एक root फ़ाइल, और उस पेज की keys के लिए हर पेज और locale की एक फ़ाइल। इसे तब पढ़ें जब आप पेज जोड़ते हैं, उनके बीच keys साझा करते हैं या fallbacks सेट करते हैं। आप जानेंगे कि कोई key किस फ़ाइल में जानी चाहिए, कोई पेज क्या देख सकता है, और हर फ़ाइल कब लोड होती है।

## लेआउट {#layout}

```text
locales/
├── en.json                 # root: menus, footer, buttons
├── de.json
└── pages/
    ├── index/              # pages/index.vue
    │   ├── en.json
    │   └── de.json
    ├── about/              # pages/about.vue
    │   ├── en.json
    │   └── de.json
    └── products-id/        # pages/products/[id].vue
        ├── en.json
        └── de.json
```

- `locales/pages/` के अंदर का फ़ोल्डर पेज का Nuxt **route name** है: `pages/products/[id].vue` का `products-id` है, `pages/blog/[slug]/comments.vue` का `blog-slug-comments`।
- Keys किसी भी गहराई तक nested हो सकती हैं; `$t('auth.form.login')` `{ "auth": { "form": { "login": … } } }` पढ़ता है।
- `translationDir` फ़ोल्डर को स्थानांतरित करता है (डिफ़ॉल्ट `'locales'`, प्रोजेक्ट root के सापेक्ष, Nuxt 4 `app/` लेआउट में भी)।
- जब Nuxt पेजों को resolve करता है तो गायब फ़ाइलें `{}` के रूप में बना दी जाती हैं, जब तक कि [`disableWatcher`](/hi/api/module-options#disablewatcher) सेट न हो।

## पेज क्या देखता है {#what-a-page-sees}

![de में /about पर किसी key के लिए lookup क्रम: pages/about/de.json, de.json, pages/about/en.json, en.json। ये एक about/de/data.json में मर्ज होते हैं जिसे $t पढ़ता है](/images/diagrams/page-dictionary.svg)

किसी पेज की dictionary उसकी root फ़ाइल और उसकी page फ़ाइल का deep (हर स्तर पर) merge है। टकराव होने पर page फ़ाइल मान्य होती है:

```json
// locales/en.json
{ "title": "My shop", "nav": { "home": "Home", "cart": "Cart" } }
```

```json
// locales/pages/about/en.json
{ "title": "About us", "nav": { "cart": "Basket" } }
```

```ts
// on /about
t('title') // 'About us'
t('nav.home') // 'Home'   (root)
t('nav.cart') // 'Basket' (page wins)
// on any other page
t('title') // 'My shop'
```

जिस पेज का अपना फ़ोल्डर नहीं है उसे केवल root dictionary मिलती है। दूसरे पेजों की keys दिखाई नहीं देतीं।

### Fallback locales {#fallback-locales}

सक्रिय locale में गायब key, key को ख़ुद दिखाने से पहले, उसके fallback locale से ली जाती है:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'de-at', iso: 'de-AT', fallbackLocale: 'de' },
    ],
    defaultLocale: 'en',
    fallbackLocale: 'en', // global, for every locale
  },
})
```

- किसी locale का अपना `fallbackLocale` अंत तक अनुसरित होता है: `de-at` → `de` → `en`।
- global `fallbackLocale` सबसे कमज़ोर परत है, हर chain के नीचे।
- chain का हर locale अपनी root फ़ाइल, फिर अपनी page फ़ाइल जोड़ता है, सबसे कमज़ोर fallback से सक्रिय locale तक। इसलिए सक्रिय locale की root फ़ाइल fallback locale की page फ़ाइल पर भारी पड़ती है।

fallback के बिना, गायब key key के रूप में render होती है (`'nav.home'`) और dev में ब्राउज़र console में एक चेतावनी लॉग करती है ([`missingWarn`](/hi/api/module-options#missingwarn))।

## साझा करना और अन्य स्रोत {#sharing-and-other-sources}

| ज़रूरत | विकल्प |
| --- | --- |
| केवल root फ़ाइलें, कोई `pages/` फ़ोल्डर नहीं | [`disablePageLocales: true`](/hi/api/module-options#disablepagelocales) |
| दो पेज एक ही page फ़ोल्डर पढ़ें | [`routesLocaleLinks`](/hi/api/module-options#routeslocalelinks): `{ 'about-us': 'about' }` |
| किसी अन्य फ़ोल्डर में साझा root फ़ाइलें | [`additionalTranslationDirs`](/hi/api/module-options#additionaltranslationdirs): `['common']` (मुख्य `translationDir` मान्य होता है) |
| किसी Nuxt layer से keys | Layers की फ़ाइलें मर्ज होती हैं, प्रोजेक्ट की अपनी फ़ाइलें मान्य होती हैं। देखें [Layers](/hi/guide/layers) |
| रनटाइम पर जोड़ी गई keys | [`i18n:register`](/hi/api/events) hook, `$mergeTranslations`, `$setTranslation` |
| page component में inline keys | `$defineI18nRoute({ locales: { en: { … } } })`, देखें [पेज कॉन्फ़िगरेशन](/hi/guide/per-component-translations) |

## पेज अपनी dictionary कैसे लोड करता है {#how-a-page-loads-its-dictionary}

![Locale JSON फ़ाइलें एक payload tree में बनाई जाती हैं, Node पर public/ में या Edge पर server assets में संग्रहीत होती हैं, server loader द्वारा पढ़ी जाती हैं, फिर सर्वर पर $t द्वारा उपयोग की जाती हैं और ब्राउज़र में $t के लिए fetch की जाती हैं](/images/diagrams/translation-pipeline.svg)

मॉड्यूल हर पेज और locale के लिए एक payload बनाता है: `/{apiBaseUrl}/{page}/{locale}/data.json` (डिफ़ॉल्ट रूप से `/_locales/about/de/data.json`)।

1. **सर्वर render.** Nitro locale का पता लगाता है और पेज बिना किसी HTTP रिक्वेस्ट के सीधे server loader से अपना payload लोड करता है। dictionary HTML payload में नहीं लिखी जाती, इसलिए पेज छोटे रहते हैं।
2. **Hydration.** ब्राउज़र वही payload fetch करता है। सर्वर ने इसके लिए पहले ही एक `<link rel="preload">` जनरेट कर दिया है, इसलिए fetch HTML के साथ ही शुरू हो जाता है।
3. **Navigation.** अगले पेज का payload dictionary की जगह लेता है। जाने वाले पेज की keys उसके हटने तक (page transition का अंत, या `page:finish`) resolve होती रहती हैं, इसलिए fade-out हो रहा पेज कच्ची keys नहीं दिखाता। जो chunk लोड होने में विफल रहता है (network error, 4xx या 5xx, ऐसा body जो ऑब्जेक्ट नहीं है) वह वर्तमान dictionary को जस का तस छोड़ देता है, और अगला navigation उसे फिर से लोड करता है। विफल locale switch भी ऐसा ही है: `$switchLocale` `false` resolve करता है, और उसे फिर से कॉल करना, या switcher पर फिर से क्लिक करना, दोबारा प्रयास करता है। prefix strategies के तहत तब तक URL बदल चुका होता है, इसलिए `lang` और `$getLocale()` URL के locale का नाम बताते हैं जबकि पुराने टेक्स्ट स्क्रीन पर बने रहते हैं।
4. **Cache.** लोड किए गए payloads सर्वर और ब्राउज़र में कैश होते हैं; size और TTL के विकल्प [प्रदर्शन](/hi/guide/performance) पर हैं।

`translationPayloads.mode` तय करता है कि payloads कैसे बनाए जाएँ। `'premerged'` (डिफ़ॉल्ट) बिल्ड के समय हर page × locale फ़ाइल लिखता है। `'source'` source फ़ाइलें रखता है और प्रति रिक्वेस्ट मर्ज करता है, जो Edge targets पर बड़े catalogs के लिए छोटा होता है। दोनों एक जैसी dictionaries देते हैं। हर deploy target के लिए फ़ाइलें कहाँ पहुँचती हैं, यह [Deployment](/hi/guide/deployment) पर है।

## Development में संपादन {#editing-in-development}

`nuxt dev` फ़ाइलों को live पढ़ता है। किसी अनुवाद फ़ाइल को सहेजने पर खुले पेज की dictionary उसी जगह रीफ़्रेश होती है: कोई reload नहीं, हटाई गई keys गायब हो जाती हैं, और root फ़ाइल में बदलाव हर पेज तक पहुँचता है। टूटी हुई JSON फ़ाइल अपने पाथ के साथ एक चेतावनी लॉग करती है और ख़ाली मानी जाती है। इसके बजाय हाथ से रीफ़्रेश करने के लिए [`hmr: false`](/hi/api/module-options#hmr) सेट करें।
