`meta: true` (डिफ़ॉल्ट) के साथ हर स्थानीयकृत पेज को `<html lang dir>`, एक canonical link, `hreflang` alternates, `x-default` और Open Graph locale टैग मिलते हैं। आपको यह पेज तब चाहिए जब आप सार्वजनिक origin सेट करना चाहते हैं, यह तय करना चाहते हैं कि टैग में कौन-से locales दिखें, या किसी एक पेज के लिए उन्हें ओवरराइड करना चाहते हैं। ज़्यादातर साइटों को केवल `site.url` या `metaBaseUrl` और सही `iso` codes की ज़रूरत होती है।

## न्यूनतम सेटअप {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

इसके बाद `/de/about` यह render करता है:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## टेक्स्ट दिशा {#text-direction}

`<html dir>` locale के `dir` से आता है। उसके बिना, दाएँ से बाएँ लिखी जाने वाली भाषा को `rtl` मिलता है, जो `iso` (या `code`) से पढ़ा जाता है: अरबी, हिब्रू, फ़ारसी, उर्दू और कुछ अन्य, और RTL लिपि वाला कोई भी टैग जैसे `az-Arab`। बाकी हर locale को कोई `dir` attribute नहीं मिलता, जिसे ब्राउज़र `ltr` मानते हैं।

<Warning>

**बड़े पेजों पर `dir: 'auto'` parse समय बढ़ाता है** — `<html>` पर `auto` ब्राउज़र को parse करते समय सामग्री से दिशा तय करने पर मजबूर करता है। Chromium में यह लागत पेज से तेज़ी से बढ़ती है: 5,000 elements पर लगभग 100 ms और 20,000 पर 1 s। इसका उपयोग केवल ऐसे छोटे पेज के लिए करें जिसकी भाषा आप नहीं जान सकते।

</Warning>

## आपको कौन-से टैग मिलते हैं {#which-tags-you-get}

- **hreflang**: हर उस locale के लिए एक टैग जो पेज दिखाता है, मान `iso` (या `iso` न होने पर `code`), उसका URL canonical जैसी ही query के साथ। [पेज कॉन्फ़िगरेशन](/hi/guide/per-component-translations) या `routeLocales` से सीमित किया गया पेज केवल अपने locales सूचीबद्ध करता है। [`hreflangBaseLanguage: true`](/hi/api/module-options#hreflangbaselanguage) पहले क्षेत्रीय locale के लिए केवल-भाषा (`es-ES` → `es`) भी जोड़ता है।
- **x-default**: डिफ़ॉल्ट locale का URL, केवल तब जब डिफ़ॉल्ट locale पेज दिखाता हो।
- **og:locale**: `iso` से निकाला जाता है (`en-US` → `en_US`)। जब mapping सीधी न हो तो locale पर `og` सेट करें, उदाहरण के लिए `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; दोनों के बिना कोई `og:locale` नहीं लिखा जाता और dev मोड चेतावनी देता है।
- **canonical / og:url**: query parameters के बिना वर्तमान URL, सिवाय उनके जो [`canonicalQueryWhitelist`](/hi/api/module-options#canonicalquerywhitelist) में हैं (डिफ़ॉल्ट `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`)।

Strategy के अनुसार:

| Strategy | hreflang और x-default | canonical, og:url, og:locale, html attrs |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | हाँ | हाँ |
| `no_prefix` | नहीं (एक URL हर locale को दिखाता है) | हाँ |

## सार्वजनिक origin सेट करें {#set-the-public-origin}

Absolute URLs इनमें से पहला उपलब्ध मान इस्तेमाल करते हैं:

1. [`metaBaseUrl`](/hi/api/module-options#metabaseurl);
2. `nuxt-site-config` से `site.url` (`@nuxtjs/seo` द्वारा इंस्टॉल किया गया);
3. रिक्वेस्ट का origin, `app.baseURL` जोड़कर।

पहले दो में से किसी एक को निश्चित करें।

<Warning>

रिक्वेस्ट-origin fallback `X-Forwarded-Host` और `X-Forwarded-Proto` पढ़ता है, क्योंकि [`metaTrustForwardedHost`](/hi/api/module-options#metatrustforwardedhost) और `metaTrustForwardedProto` का डिफ़ॉल्ट `true` है। यह केवल ऐसे proxy के पीछे सुरक्षित है जो इन headers को overwrite करता है; अन्यथा कोई क्लाइंट आपके canonical links में host चुन सकता है, और कोई cache उस पेज को आगे बढ़ा सकता है।

अगर ऐप सीधे पहुँच योग्य है, तो `metaBaseUrl` निश्चित करें: दोनों विकल्पों को `false` करने के विपरीत, यह जाली `Host` को भी अनदेखा करता है। देखें [proxy या CDN के पीछे](/hi/guide/deployment#behind-a-proxy-or-cdn)।

</Warning>

यह fallback तब उपयोगी है जब एक ही deployment कई domains पर जवाब देता है: `https://site-a.com/en/about` और `https://site-b.com/en/about` दोनों को अपना-अपना origin मिलता है।

Locales पर `baseUrl` होने पर, ज्ञात host `metaBaseUrl` और `site.url` के ऊपर अपना `baseUrl` इस्तेमाल करता है, ताकि canonical और `og:url` उसी domain पर रहें और `hreflang` हर locale को उसके domain पर इंगित करे। कोई अन्य host `metaBaseUrl`, अन्यथा डिफ़ॉल्ट locale का `baseUrl`, अन्यथा `site.url` इस्तेमाल करता है, ताकि जाली `Host` आपके टैग तक न पहुँच सके। अगर इनमें से कुछ भी सेट नहीं है, तो रिक्वेस्ट-origin fallback बना रहता है, और बिल्ड चेतावनी देता है। देखें [Layers और domains](/hi/guide/layers#multiple-domains)।

## Locales या पेजों को बाहर रखें {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

अगर डिफ़ॉल्ट locale में `seo: false` है, तो कोई `x-default` नहीं लिखा जाता। किसी एक पेज के लिए टैग बंद करने के लिए [पेज कॉन्फ़िगरेशन](/hi/guide/per-component-translations#turn-off-seo-tags) में `disableMeta`, या config में [`routeDisableMeta`](/hi/api/module-options#routedisablemeta) इस्तेमाल करें।

## एक पेज पर टैग ओवरराइड करें {#override-tags-on-one-page}

ऐसी CMS सामग्री के लिए जहाँ केवल कुछ अनुवाद मौजूद हैं, या URLs किसी API से आते हैं, जनरेट किए गए टैग को [`useI18nHead`](/hi/composables/useI18nHead) से बदलें:

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` `canonical`, `xDefault`, `ogLocale` और `ogUrl` को सेट या हटा भी सकता है; `disable` पूरे समूह हटाता है (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`)। getter पास करें ताकि locale बदलने के बाद मान फिर से गणना हों। प्रति-locale slugs के लिए पहले `$setI18nRouteParams` सेट करें ([स्थानीयकृत पाथ](/hi/guide/custom-locale-routes#per-locale-slugs)), फिर जनरेट किए गए alternates पहले से उनका उपयोग करते हैं।

## Trailing slash {#trailing-slash}

`$localePath`, `$switchLocalePath`, `$switchLocaleRoute` का route ऑब्जेक्ट, `<i18n-link>`, `<i18n-switcher>`, locale redirects और SEO URLs एक ही slash नियम का पालन करते हैं: डिफ़ॉल्ट रूप से `experimental.defaults.nuxtLink.trailingSlash`, या जब i18n पाथ अलग होने चाहिए तब i18n config में [`trailingSlash`](/hi/api/module-options)।

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) `nuxt-site-config` 4+ के ज़रिए इस मॉड्यूल के साथ काम करता है। `nuxt-i18n-micro` को पहले सूचीबद्ध करें ताकि site config locales पढ़ सके, और `site.url` एक बार सेट करें — यह ऊपर के टैग को भी मान देता है।

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

अनूदित साइट नाम और विवरण आपकी locale फ़ाइलों की `nuxtSiteConfig.name` / `nuxtSiteConfig.description` keys से आते हैं। त्रुटि `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` का मतलब है कि `@nuxtjs/seo` 3 से पुराना है; उसे अपग्रेड करें ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133))।
