`strategy` विकल्प तय करता है कि URL में लोकेल दिखाई देता है या नहीं और किन लोकेल के लिए। URL प्रकाशित करने से पहले इसे एक बार चुनें: बाद में इसे बदलने से हर लिंक बदल जाता है। इसके बाद मॉड्यूल बिल्ड के समय स्थानीयकृत रूट जनरेट करता है, और `$localePath`, `<i18n-link>` और स्विचर उन्हें पढ़ते हैं।

## चार रणनीतियाँ {#the-four-strategies}

![हर रणनीति के अंतर्गत en (डिफ़ॉल्ट) और de में /about पेज; वही URL नीचे टेक्स्ट में सूचीबद्ध हैं](/images/diagrams/strategies.svg)

**टाइप** `Strategies` · **डिफ़ॉल्ट** `'prefix_except_default'`

लोकेल प्रीफ़िक्स के लिए URL रूटिंग रणनीति।

- `'no_prefix'` — URL में कोई लोकेल नहीं; लोकेल कुकी में संग्रहीत होता है।
- `'prefix_except_default'` — डिफ़ॉल्ट को छोड़कर सभी लोकेल पर प्रीफ़िक्स।
- `'prefix'` — हमेशा प्रीफ़िक्स, डिफ़ॉल्ट लोकेल सहित।
- `'prefix_and_default'` — `prefix` की तरह, लेकिन डिफ़ॉल्ट लोकेल प्रीफ़िक्स के बिना भी उपलब्ध है।

`defaultLocale: 'en'` और लोकेल `en`, `de` के साथ एक `about` पेज के URL:

| रणनीति | अंग्रेज़ी | जर्मन | सर्व नहीं किया जाता |
| --- | --- | --- | --- |
| `prefix_except_default` (डिफ़ॉल्ट) | `/about` | `/de/about` | `/en` और `/en/about` 404 हैं |
| `prefix` | `/en/about` | `/de/about` | `/about` प्रीफ़िक्स वाले URL पर रीडायरेक्ट होता है |
| `prefix_and_default` | `/about` और `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | लोकेल URL में नहीं है |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

रणनीति बिल्ड के समय तय होती है: इसका रनटाइम ओवरराइड एक चेतावनी के साथ अनदेखा कर दिया जाता है ([रनटाइम ओवरराइड](/hi/guide/runtime-overrides))।

## कौन सी चुनें {#which-one-to-choose}

- **`prefix_except_default`**: अधिकांश साइटें। मौजूदा बिना प्रीफ़िक्स वाले URL डिफ़ॉल्ट भाषा के लिए काम करते रहते हैं।
- **`prefix`**: हर भाषा समान है; `/` हमेशा प्रीफ़िक्स वाले होम पर ले जाता है।
- **`prefix_and_default`**: आपको `/en/...` और बिना प्रीफ़िक्स वाले URL दोनों का काम करना ज़रूरी है, उदाहरण के लिए एक से दूसरे पर जाते समय। बिना प्रीफ़िक्स वाले URL कभी रीडायरेक्ट नहीं होते।
- **`no_prefix`**: लॉगिन के पीछे के ऐप, या हर भाषा के लिए प्रति पेज एक URL। लोकेल कुकी या `?locale=` से आता है। सर्च इंजन प्रति URL एक भाषा देखते हैं, इसलिए कोई `hreflang` विकल्प उत्सर्जित नहीं होते।

किसी URL के लिए लोकेल कैसे चुना जाता है, और विज़िटर को कब रीडायरेक्ट किया जाता है, यह [लोकेल पहचान](/hi/guide/locale-detection) पर है।

## जनरेट किए गए रूट {#generated-routes}

बिल्ड के समय हर पेज को वे रूट रिकॉर्ड मिलते हैं जिनकी उसकी रणनीति को आवश्यकता होती है। हर रिकॉर्ड में `meta.i18n = { name, locales }` होता है: वह पेज जो यह दिखाता है और वे लोकेल जिन्हें यह सर्व करता है। लिंक, स्विच और रीडायरेक्ट सभी का उत्तर इन्हीं रिकॉर्ड से दिया जाता है, इसलिए मॉड्यूल द्वारा दिया गया URL हमेशा ऐसा होता है जिसे राउटर सर्व करता है।

जो लोकेल पेज का पाथ साझा करते हैं वे एक रिकॉर्ड साझा करते हैं, `/:locale(de|fr)/about`। अपने स्वयं के पाथ वाले लोकेल को अपना रिकॉर्ड मिलता है, जिसका नाम `localized-<page>-<locale>` होता है:

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

कस्टम पाथ, प्रति-पेज लोकेल सूचियाँ और किसी पेज को स्थानीयकरण से बाहर रखना [स्थानीयकृत पाथ](/hi/guide/custom-locale-routes) और [पेज कॉन्फ़िग](/hi/guide/per-component-translations) पर हैं। `localized-` प्रीफ़िक्स [`localizedRouteNamePrefix`](/hi/api/module-options#localizedroutenameprefix) है।

<Warning>

**रूट नाम जनरेट किए जाते हैं** — `router.push({ name })` में `localized-…` नामों को हार्ड-कोड न करें। पेज का अपना नाम `$localeRoute` या `<i18n-link>` को पास करें; वे सही रिकॉर्ड चुनते हैं।

</Warning>

## किसी लोकेल में पेज से लिंक करना {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- नामित रूट और पाथ दोनों काम करते हैं। पाथ का मिलान जनरेट किए गए रूट से किया जाता है, इसलिए किसी भी लोकेल का उसका रूप स्वीकार किया जाता है।
- जो लोकेल पेज को सर्व नहीं करता ([पेज कॉन्फ़िग](/hi/guide/per-component-translations) में `locales` देखें), वह गायब पेज के बजाय उस लोकेल के होम से लिंक करता है।
- प्रति-लोकेल पैरामीटर (अनुवादित स्लग) `$setI18nRouteParams` से होकर जाते हैं, [स्थानीयकृत पाथ](/hi/guide/custom-locale-routes) देखें।

सिग्नेचर [मेथड्स](/hi/api/methods) में हैं।

## `no_prefix` विवरण {#no_prefix-details}

- `no_prefix` के अंतर्गत [`localeCookie`](/hi/api/module-options#localecookie) का डिफ़ॉल्ट `'user-locale'` है, इसलिए पसंद रीलोड के बाद भी बनी रहती है।
- `$switchLocale('de')` जर्मन डिक्शनरी लोड करता है और वर्तमान हिस्ट्री प्रविष्टि को बदल देता है; URL नहीं बदलता।
- कस्टम प्रति-लोकेल पाथ फिर भी काम करते हैं: `globalLocaleRoutes: { about: { de: '/ueber-uns' } }` के साथ, जर्मन पाठकों को `/ueber-uns` मिलता है। वह URL हमेशा जर्मन रेंडर करता है, विज़िटर चाहे जो पसंद करे, और कुछ लोकेल तक सीमित पेज उनमें से किसी एक में रेंडर होता है। कई लोकेल द्वारा साझा किया गया पाथ (`en` और `de` दोनों `/page/:id` पर) पसंद को रेंडर करता है जब वह उनमें से एक हो। पसंद स्वयं बनी रहती है: अगला पेज उसी पर लौटता है।
- [`noPrefixRedirect: true`](/hi/api/module-options#noprefixredirect) डिफ़ॉल्ट लोकेल में कस्टम पाथ वाले पेज के मूल पाथ को रीडायरेक्ट करता है: विज़िटर के लोकेल के कस्टम पाथ पर, अन्यथा डिफ़ॉल्ट लोकेल के पाथ पर (`/about` → `/about-us` जब `en` के पास `/about-us` हो, कुकी `de` के साथ → `/ueber-uns`)। जिस लोकेल का अपना कोई कस्टम पाथ नहीं है वह मूल पाथ पर रहता है और वहीं रेंडर होता है। पैरामीटर वाले पेज रीडायरेक्ट नहीं होते।

## `pages/` के बिना ऐप {#apps-without-pages/}

`pages: false` के साथ स्थानीयकृत करने के लिए कोई पेज रूट नहीं होते। केवल रूट अनुवाद फ़ाइलों का उपयोग करें (`disablePageLocales: true`); पहचान, कुकी और `$switchLocale` फिर भी काम करते हैं। रिपॉज़िटरी में `test/fixtures/basic` का `pages-false` वेरिएंट एक काम करने वाला सेटअप है।
