---

बिल्ट-इन डिटेक्शन URL, एक कुकी और `Accept-Language` को पढ़ता है। जब लोकेल किसी और चीज़ पर निर्भर करता है — डोमेन, आपके CDN द्वारा सेट किया गया geo हेडर, उपयोगकर्ता प्रोफ़ाइल — तो उसे स्वयं एक ऐसे प्लगइन में सेट करें जो i18n प्लगइन से पहले चलता है। इसके बाद मॉड्यूल उस लोकेल के अनुवाद लोड करता है और रीडायरेक्ट के लिए उसका ठीक वैसे ही उपयोग करता है जैसे उसने उसे स्वयं डिटेक्ट किया हो। चुना गया लोकेल कब URL पर प्राथमिकता पाता है, यह तय करने वाले नियम [लोकेल डिटेक्शन](/hi/guide/locale-detection) पर हैं; यह पेज दिखाता है कि अपना स्वयं का स्रोत कैसे जोड़ें।

## सर्वर प्लगइन में लोकेल सेट करें {#set-the-locale-in-a-server-plugin}

```ts
// plugins/i18n-locale.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10, // before the i18n plugin (order -5)
  setup() {
    const { setLocale } = useI18nLocale()
    const host = (useRequestHeaders(['host']).host ?? '').split(':')[0]! // without the port

    if (host.endsWith('.de')) setLocale('de')
    else if (host.endsWith('.fr')) setLocale('fr')
  },
})
```

`setLocale(code)` लोकेल स्थिति (`useState('i18n-locale')`) लिखता है और, जब कोई लोकेल कुकी कॉन्फ़िगर हो, तो कुकी भी। स्वयं `useState` या `useCookie` लिखने के बजाय इसका उपयोग करें। केवल सक्षम लोकेल कोड पास करें।

जब प्लगइन रिक्वेस्ट हेडर पढ़ता है तो उसे `.server.ts` ही रखें: ब्राउज़र में वे मौजूद नहीं होते। `localStorage` जैसे केवल-ब्राउज़र स्रोतों के लिए `.client.ts` प्लगइन सही जगह है।

## बिल्ट-इन Accept-Language चरण बंद करें {#turn-off-the-built-in-accept-language-step}

आपका प्लगइन और `Accept-Language` असहमत हो सकते हैं। केवल आपके कोड (साथ ही URL और कुकी) को निर्णय लेने देने के लिए, हेडर बंद करें:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    autoDetectLanguage: false,
  },
})
```

[`autoDetectLanguage`](/hi/api/module-options#autodetectlanguage) केवल हेडर चरण को नियंत्रित करता है। URL और एक वैध कुकी फिर भी मायने रखते हैं।

## आगे क्या होता है {#what-happens-next}

`setLocale` का प्रभाव [strategy](/hi/guide/strategy) पर निर्भर करता है:

| Strategy | प्लगइन में `setLocale('de')` का प्रभाव |
| --- | --- |
| `no_prefix` | पेज जर्मन में रेंडर होता है; URL नहीं बदलता। |
| `prefix`, `prefix_except_default` | बिना प्रीफ़िक्स वाले पाथ पर जहाँ [`autoDetectPath`](/hi/api/module-options#autodetectpath) रीडायरेक्ट की अनुमति देता है (डिफ़ॉल्ट रूप से केवल `/`), सर्वर जर्मन URL पर `302` से जवाब देता है। लोकेल प्रीफ़िक्स वाला URL उसे बनाए रखता है। |
| `prefix_and_default` | कोई रीडायरेक्ट नहीं: बिना प्रीफ़िक्स वाला URL एक वैध डिफ़ॉल्ट-लोकेल पेज है। |

प्रीफ़िक्स strategies के तहत URL में लोकेल उपयोगकर्ता की पसंद है और आपका प्लगइन उसे ओवरराइड नहीं करता। `autoDetectPath: '*'` अपवाद है: तब सर्वर प्रीफ़िक्स वाले URL को कुकी और `Accept-Language` के आधार पर स्थानांतरित करता है और स्थिति को अनदेखा करता है, लेकिन कुकी कॉन्फ़िगर होने पर `setLocale()` कुकी भी लिखता है, इसलिए अगली रिक्वेस्ट से आपके प्लगइन की पसंद प्रीफ़िक्स वाले URL को रीडायरेक्ट कर सकती है। जब स्पष्ट लोकेल URL को प्राथमिकता मिलनी चाहिए, तो `'/'` रखें या `'no_prefix'` का उपयोग करें। अपने प्लगइन का उपयोग यह चुनने के लिए करें कि विज़िटर कहाँ पहुँचे, न कि उनके द्वारा फ़ॉलो किए गए लिंक को फिर से लिखने के लिए।

## उपयोगकर्ता द्वारा चुने गए लोकेल का सम्मान करें {#respect-a-locale-the-user-picked}

जब उपयोगकर्ता भाषा बदलता है, तो यह बदलाव कुकी लिखता है। जब पहले से कोई वैध प्राथमिकता हो तो अपना डिटेक्शन छोड़ दें:

```ts
// plugins/i18n-locale.server.ts
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10,
  setup() {
    const { getPreferredLocale, setLocale, validLocales } = useI18nLocale()
    if (getPreferredLocale()) return // valid state or cookie: keep it

    const country = useRequestHeaders(['x-country'])['x-country']
    if (country === 'JP') return setLocale('ja')

    const header = useRequestHeaders(['accept-language'])['accept-language']
    setLocale(detectLocaleFromAcceptLanguage(header, validLocales))
  },
})
```

`getPreferredLocale()` स्थिति या कुकी केवल तभी लौटाता है जब वह एक सक्षम लोकेल हो, इसलिए पुरानी कुकी डिटेक्शन को नहीं रोकती। `detectLocaleFromAcceptLanguage` वही q-value-सचेत मैचर है जिसका मॉड्यूल स्वयं उपयोग करता है (इसे इम्पोर्ट करने के लिए `@i18n-micro/utils` इंस्टॉल करें); `setLocale(null)` कुछ नहीं करता।

## प्रति लोकेल एक डोमेन {#one-domain-per-locale}

यदि हर डोमेन को अपने स्वयं के लोकेल सर्व करने चाहिए, तो आपको प्लगइन की आवश्यकता नहीं है: हर लोकेल को एक `baseUrl` दें, हर डोमेन के डिफ़ॉल्ट लोकेल पर `baseDefault: true` सेट करें, और एक बार बिल्ड करें (स्टैटिक साइट फिर भी प्रति डोमेन `nuxi generate` चलाती है)। देखें [लेयर्स और डोमेन](/hi/guide/layers#multiple-domains)।
