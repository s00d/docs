रनटाइम ओवरराइड एक ही बिल्ड आर्टिफ़ैक्ट को बिना दोबारा बिल्ड किए हर एनवायरनमेंट या टेनेंट के लिए अलग लोकेल सेटिंग के साथ चलाने देते हैं। आप डिफ़ॉल्ट लोकेल, फ़ॉलबैक लोकेल और कौन-से लोकेल अक्षम हैं, यह बदल सकते हैं। रूटिंग, रीडायरेक्ट, रेंडरिंग और सर्वर हेल्पर ओवरराइड किए गए मानों का उपयोग करते हैं, और सर्वर-रेंडर किए गए पेज पर ब्राउज़र भी।

## एनवायरनमेंट वेरिएबल से ओवरराइड सेट करें {#set-overrides-with-environment-variables}

```bash
NUXT_I18N_DEFAULT_LOCALE=de \
NUXT_I18N_FALLBACK_LOCALE=en \
NUXT_I18N_DISABLED_LOCALES=fr,it \
node .output/server/index.mjs
```

| वेरिएबल | उपनाम |
| --- | --- |
| `NUXT_I18N_DEFAULT_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE` |
| `NUXT_I18N_FALLBACK_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE` |
| `NUXT_I18N_DISABLED_LOCALES` (अल्पविराम से अलग) | `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES` |

सर्वर इन्हें शुरू होते समय एक बार पढ़ता है; बदलाव लागू करने के लिए रीस्टार्ट करें। सर्वर-रेंडर किए गए पेज पर ब्राउज़र को हल किए गए मान सर्वर से मिलते हैं। `ssr: false` के साथ कोई सर्वर रेंडर नहीं होता और ब्राउज़र के पास कोई एनवायरनमेंट नहीं होता: वहाँ केवल `runtimeConfig.public.i18nRuntime` लागू होता है, और ब्राउज़र नीचे दी गई चेतावनियाँ लॉग करता है।

## runtimeConfig में ओवरराइड सेट करें {#set-overrides-in-runtimeconfig}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

`runtimeConfig.public.i18nRuntime` में सेट किया गया मान उसी फ़ील्ड के `NUXT_I18N_*` वेरिएबल पर प्राथमिकता पाता है।

इसे बिल्ड-टाइम `DEFAULT_LOCALE` वेरिएबल से न मिलाएँ, जो बिल्ड करते समय `defaultLocale` को बदलता है और जिसे रनटाइम समर्थन की ज़रूरत नहीं होती।

## क्या बदल सकता है और क्या नहीं {#what-can-and-cannot-change}

| सेटिंग | रनटाइम पर |
| --- | --- |
| `defaultLocale` | `prefix` और `no_prefix` के अंतर्गत हाँ। `prefix_except_default` और `prefix_and_default` के अंतर्गत यह बिल्ड पर तय होता है (इसके पेज बिना प्रीफ़िक्स वाले रूट हैं); ओवरराइड चेतावनी के साथ अनदेखा किया जाता है। |
| `fallbackLocale` | हाँ। |
| `disabledLocales` | बिल्ड पर अक्षम किए गए लोकेल में जोड़ता है; किसी को फिर से सक्षम कभी नहीं करता। `prefix_except_default` / `prefix_and_default` के अंतर्गत बिल्ड डिफ़ॉल्ट को अक्षम नहीं किया जा सकता। |
| `strategy` | नहीं। रनटाइम रणनीति चेतावनी के साथ अनदेखी की जाती है; हर रणनीति के लिए एक आर्टिफ़ैक्ट बिल्ड करें। |

अमान्य मान ऐप को कभी नहीं तोड़ते। हर मामला हर सर्वर प्रोसेस में एक चेतावनी लॉग करता है:

- हर लोकेल को अक्षम करना अनदेखा किया जाता है;
- ऐसा `defaultLocale` जो सक्षम नहीं है, पहले सक्षम लोकेल पर फ़ॉलबैक करता है;
- ऐसा `fallbackLocale` जो सक्षम नहीं है, बिल्ड मान रखता है यदि वह सक्षम है, अन्यथा कोई फ़ॉलबैक नहीं होता।

## प्रभावी कॉन्फ़िग पढ़ें {#read-the-effective-config}

```vue
<script setup lang="ts">
const { $getI18nConfig } = useNuxtApp()
const config = $getI18nConfig() // build config with overrides applied
</script>
```

इसे केवल-पढ़ने योग्य मानें: सर्वर पर यह हर अनुरोध द्वारा साझा किया जाता है और डेवलपमेंट में फ़्रीज़ होता है; ब्राउज़र की कॉपी फ़्रीज़ नहीं होती। `#build/i18n.strategy.mjs` से कॉन्फ़िग इम्पोर्ट करने पर ओवरराइड के बिना बिल्ड मान मिलते हैं।

## अक्षम लोकेल और स्टैटिक फ़ाइलें {#disabled-locales-and-static-files}

रनटाइम पर अक्षम किया गया लोकेल अपने रूट और पेलोड रूट पर 404 देता है, लेकिन उसकी पेलोड फ़ाइलें अब भी `.output/public/_locales/` में होती हैं और कोई स्टैटिक फ़ाइल सर्वर उन्हें लौटाता है। जब उन फ़ाइलों तक पहुँच नहीं होनी चाहिए, तो लोकेल को बिल्ड के समय `disabled: true` से अक्षम करें।
