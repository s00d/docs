# i18n रूटिंग से Static Files को बाहर करना

## अवलोकन

डिफ़ॉल्ट रूप से, nuxt-i18n-micro सामान्य static files को i18n रूटिंग प्रोसेसिंग से स्वचालित रूप से बाहर कर देता है। हालाँकि, आप विशिष्ट paths को i18n सिस्टम द्वारा संसाधित होने से रोकने के लिए custom exclusion patterns भी कॉन्फ़िगर कर सकते हैं।

## अंतर्निहित Exclusions

मॉड्यूल स्वचालित रूप से निम्नलिखित फ़ाइल प्रकारों और patterns को बाहर करता है:

- **Sitemaps**: `/sitemap*.xml`, `/sitemap-en.xml`, आदि।
- **SEO files**: `/robots.txt`, `/favicon.ico`
- **PWA files**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Static assets**: `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot` जैसे extensions वाली फ़ाइलें
- **आंतरिक Nuxt paths**: `__` से शुरू होने वाला कोई भी path (जैसे `/__nuxt/`)

## Custom Exclusion Patterns

आप `excludePatterns` विकल्प का उपयोग करके custom exclusion patterns परिभाषित कर सकते हैं:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Pattern के प्रकार

### String Patterns

- **सटीक मिलान**: `'/api/health'` - बिल्कुल `/api/health` से मेल खाता है
- **Prefix मिलान**: `'/admin'` - `/admin` और `/admin/dashboard` से मेल खाता है
- **Wildcards**: `'/api/*'` - `/api/users` से मेल खाता है लेकिन `/api/users/123` से नहीं
- **Deep wildcards**: `'/admin/**'` - `/admin/users` और `/admin/users/123` से मेल खाता है

### Regular Expressions

जटिल pattern matching के लिए RegExp objects का उपयोग करें:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## उपयोग के मामले

### SEO Files

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API Routes

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Admin Panels

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Static Assets

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## यह कैसे काम करता है

1. **Server Middleware**: exclusion patterns की जाँच करने के लिए एक Nitro middleware पहले चलता है
2. **Page Processing**: page resolution के दौरान, बाहर किए गए paths को छोड़ दिया जाता है
3. **Catch-all Route**: fallback route processing से पहले exclusions की जाँच करता है
4. **Prerendering**: बाहर किए गए paths prerendered routes में शामिल नहीं होते

## प्रदर्शन प्रभाव

- Exclusion checks अनुकूलित हैं और request lifecycle में जल्दी चलते हैं
- अंतर्निहित patterns कुशल regex matching का उपयोग करते हैं
- Custom patterns cached और पुन: उपयोग किए जाते हैं
- बाहर किए गए paths के लिए न्यूनतम प्रदर्शन ओवरहेड

## समस्या निवारण

### Static Files अभी भी Intercept हो रही हैं

1. **Pattern syntax जाँचें**: सुनिश्चित करें कि आपके patterns सटीक path संरचना से मेल खाते हैं
2. **जटिल patterns के लिए regex का उपयोग करें**: String wildcards की सीमाएँ होती हैं
3. **Patterns का परीक्षण करें**: वास्तविक request path सत्यापित करने के लिए browser dev tools का उपयोग करें
4. **क्रम जाँचें**: सुनिश्चित करें कि exclusion patterns अन्य i18n config से पहले परिभाषित हैं

### Pattern काम नहीं कर रहा

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Debug Mode

exclusion processing देखने के लिए debug mode सक्षम करें:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

यह console में exclusion decisions लॉग करेगा।

## Workarounds से माइग्रेशन

यदि आप route rules या middleware जैसे workarounds का उपयोग कर रहे थे, तो अब आप उन्हें `excludePatterns` से बदल सकते हैं:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

नया दृष्टिकोण अधिक विश्वसनीय है और रूटिंग सिस्टम के कई स्तरों पर काम करता है।
