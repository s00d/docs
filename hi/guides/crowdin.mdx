# 🌐 Crowdin एकीकरण गाइड

## 📖 परिचय

Crowdin को अपने प्रोजेक्ट में एकीकृत करने से स्थानीयकरण और अनुवाद प्रक्रिया सुव्यवस्थित होती है, जिससे कई भाषाओं और प्लेटफ़ॉर्म पर अनुवादों का प्रबंधन आसान हो जाता है। यह गाइड आपके प्रोजेक्ट के साथ Crowdin सेटअप करने पर एक चरण-दर-चरण walkthrough प्रदान करता है, जिसमें कॉन्फ़िगरेशन, स्रोतों को अपलोड करना, और अनुवाद डाउनलोड करना शामिल है।

## 🔧 इंस्टॉलेशन और सेटअप

Crowdin के साथ शुरुआत करने के लिए, आपको अपनी मशीन पर Crowdin CLI को वैश्विक रूप से इंस्टॉल करने और अपनी प्रोजेक्ट डायरेक्टरी के भीतर इसे initialize करने की आवश्यकता होगी।

### 📦 Crowdin CLI इंस्टॉल करना

पहले, npm का उपयोग करके Crowdin CLI को वैश्विक रूप से इंस्टॉल करें:

```bash
npm install -g @crowdin/cli
```

### 🛠 अपने प्रोजेक्ट में Crowdin को Initialize करना

अपने प्रोजेक्ट में Crowdin को initialize करने के लिए चलाएँ:

```bash
crowdin init
```

यह कमांड आपको सेटअप प्रक्रिया के माध्यम से मार्गदर्शन करेगी, जिसमें आपके प्रोजेक्ट ID, API token, और अन्य कॉन्फ़िगरेशन विवरण सेट करना शामिल है।

## 🗂️ कॉन्फ़िगरेशन गाइड

### 📄 Crowdin कॉन्फ़िगरेशन फ़ाइल (`crowdin.yml`)

Crowdin कॉन्फ़िगरेशन फ़ाइल (`crowdin.yml`) परिभाषित करती है कि आपकी स्रोत फ़ाइलें कैसे मैप की जाती हैं और अनुवाद कहाँ रखे जाने चाहिए। नीचे एक उदाहरण कॉन्फ़िगरेशन है:

```yml
'project_id': 'YOUR_PROJECT_ID'
'api_token': 'YOUR_API_TOKEN'
'base_path': './locales'
'base_url': 'https://api.crowdin.com'
'preserve_hierarchy': true

files:
  [
    { 'source': '/en.json', 'translation': '/%two_letters_code%.json' },
    { 'source': '/pages/**/en.json', 'translation': '/pages/**/%two_letters_code%.json' },
  ]
```

### 📂 मुख्य कॉन्फ़िगरेशन पैरामीटर

- **`project_id`**: आपका Crowdin प्रोजेक्ट ID। यह Crowdin के भीतर उस प्रोजेक्ट की पहचान करता है जहाँ अनुवादों का प्रबंधन किया जाता है।
- **`api_token`**: प्रमाणीकरण के लिए उपयोग किया जाने वाला API token। सुनिश्चित करें कि इस token के पास अनुवाद अपलोड और डाउनलोड करने की सही अनुमति है।
- **`base_path`**: स्रोत फ़ाइलों के लिए आधार डायरेक्टरी निर्दिष्ट करता है। इस उदाहरण में, अनुवाद `./locales` डायरेक्टरी में संग्रहीत हैं।
- **`base_url`**: Crowdin API के लिए बेस URL।
- **`preserve_hierarchy`**: जब `true` सेट किया जाता है, तो Crowdin आपकी स्रोत फ़ाइलों की फ़ोल्डर संरचना को प्रोजेक्ट में बनाए रखेगा।

### 📂 फ़ाइलें कॉन्फ़िगरेशन

`files` अनुभाग आपकी स्रोत फ़ाइलों को उन पथों पर मैप करता है जहाँ अनुवाद संग्रहीत किए जाएँगे। उदाहरण के लिए:

- **Source Path**: मूल अनुवाद फ़ाइलों के स्थान को परिभाषित करता है।
- **Translation Path**: Crowdin में अनुवादित फ़ाइलें कहाँ संग्रहीत की जाएँगी, यह निर्दिष्ट करता है। फ़ाइल पथ में भाषा कोड को गतिशील रूप से सेट करने के लिए `%two_letters_code%` जैसे placeholders का उपयोग किया जाता है।

## ⬆️ स्रोत फ़ाइलों को Crowdin पर अपलोड करना

एक बार जब आपका Crowdin कॉन्फ़िगरेशन सेट हो जाए, तो आप निम्न कमांड का उपयोग करके अपनी स्रोत फ़ाइलें अपलोड कर सकते हैं:

```bash
crowdin upload sources
```

यह कमांड आपके कॉन्फ़िगरेशन में निर्दिष्ट सभी स्रोत फ़ाइलों को Crowdin पर अपलोड करता है, जिससे वे अनुवाद के लिए उपलब्ध हो जाती हैं।

## ⬇️ Crowdin से अनुवाद डाउनलोड करना

Crowdin में अनुवाद पूरा या अपडेट होने के बाद, आप उन्हें अपने प्रोजेक्ट में डाउनलोड कर सकते हैं:

```bash
crowdin download
```

यह कमांड Crowdin से नवीनतम अनुवाद लाता है और उन्हें आपकी कॉन्फ़िगरेशन फ़ाइल में निर्दिष्ट पथों के अनुसार सहेजता है।

## ⚙️ सर्वोत्तम प्रथाएँ

### 🔑 सुसंगत Key नामकरण

भ्रम और दोहराव से बचने के लिए सुनिश्चित करें कि अनुवाद keys सभी फ़ाइलों में सुसंगत हैं।

### 🧹 नियमित रखरखाव

अपनी फ़ाइलों को व्यवस्थित और प्रबंधनीय रखने के लिए समय-समय पर अप्रयुक्त अनुवाद keys की समीक्षा करें और उन्हें साफ़ करें।

### 🛠 अपलोड और डाउनलोड को स्वचालित करें

अपने CI/CD पाइपलाइन में Crowdin CLI कमांड्स को एकीकृत करें ताकि स्रोत फ़ाइलों के अपलोड और अनुवादों के डाउनलोड को स्वचालित किया जा सके, यह सुनिश्चित करते हुए कि आपके अनुवाद हमेशा अद्यतित रहें।

इस गाइड का पालन करके, आप Crowdin को अपने प्रोजेक्ट में सहज रूप से एकीकृत कर सकेंगे, अपने अंतर्राष्ट्रीयकरण प्रयासों के प्रबंधन के लिए एक कुशल और व्यवस्थित दृष्टिकोण सुनिश्चित करते हुए।
