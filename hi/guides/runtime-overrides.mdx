# रनटाइम i18n Overrides

इस गाइड का उपयोग तब करें जब आपको एक बिल्ड आर्टिफ़ैक्ट को विभिन्न वातावरणों में अलग-अलग लोकेल डिफ़ॉल्ट्स के साथ चलाना हो (उदाहरण के लिए: विभिन्न tenant instances)।

## रनटाइम पर क्या override किया जा सकता है

मॉड्यूल इन के लिए सुरक्षित रनटाइम overrides का समर्थन करता है:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

ये overrides `.nuxt/i18n.strategy.mjs` और `.nuxt/i18n.config.mjs` से बिल्ड-टाइम कॉन्फ़िग के ऊपर लागू होते हैं।

## रनटाइम पर क्या override नहीं किया जा सकता

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) एक बिल्ड-टाइम मामला है क्योंकि यह जनरेट किए गए route व्यवहार को प्रभावित करता है।

यदि आप एक रनटाइम strategy override पास करते हैं, तो इसे अनदेखा कर दिया जाता है और एक चेतावनी जारी की जाती है।

## RuntimeConfig-आधारित overrides

`runtimeConfig.public.i18nRuntime` के अंतर्गत रनटाइम मान प्रदान करें:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## पर्यावरण चर overrides

आप पर्यावरण चरों के माध्यम से भी overrides कॉन्फ़िगर कर सकते हैं:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (अल्पविराम-पृथक्, जैसे `fr,it`)

Fallback aliases भी समर्थित हैं:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Validation नियम

रनटाइम पर, टूटी हुई स्थिति से बचने के लिए मॉड्यूल overrides को validate करता है:

- आप सभी लोकेल्स को disable नहीं कर सकते।
- `defaultLocale` को enabled लोकेल की ओर इंगित करना चाहिए।
- `fallbackLocale` घोषित लोकेल्स में मौजूद होना चाहिए।

यदि कोई override अमान्य है, तो मॉड्यूल एक सुरक्षित मान रखता है और एक चेतावनी लॉग करता है।

## Multi-instance डिप्लॉयमेंट्स के लिए नोट्स

यह रनटाइम फ़ीचर बिना rebuild किए प्रति-instance लोकेल activation और डिफ़ॉल्ट्स के लिए डिज़ाइन किया गया है।

यदि instances को अलग-अलग URL strategies (`no_prefix` बनाम `prefix`) की आवश्यकता है, तो प्रत्येक strategy के लिए अलग-अलग बिल्ड का उपयोग करें।

## Disabled locales और static payloads

`runtimeConfig.public.i18nRuntime.disabledLocales` रूटिंग, switcher, और Nitro payload **handler** को अद्यतन करता है — लेकिन Nitro उस handler से **पहले** `public/` के अंतर्गत फ़ाइलें serve करता है।

यदि `translationPayloads.publicAssets` (या Node SSR का forced public copy) पहले ही `/_locales/\{page\}/\{locale\}/data.json` लिख चुका है, तो एक रनटाइम disable उस फ़ाइल को छिपा नहीं सकता। बिल्ड पर `locale.disabled: true` को प्राथमिकता दें ताकि premerge उस लोकेल की static payloads उत्पन्न न करे।
