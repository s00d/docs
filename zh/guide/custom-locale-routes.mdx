---
title: "本地化路径"
description: "使用 localeRoutes 或 globalLocaleRoutes 为页面在每个区域设置下指定不同的 URL，包括动态参数和按区域设置的 slug。"
---

默认情况下，每个区域设置都在相同的路径上提供页面：`/en/about`、`/de/about`。本地化路径让每个区域设置可以使用自己的词语，例如 `/de/ueber-uns`，而页面文件保持不变。你可以在页面中通过 `$defineI18nRoute` 设置，也可以在 `nuxt.config.ts` 中一次性为多个页面设置。

## 在页面中 {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

使用 `prefix_except_default` 且 `defaultLocale: 'en'` 时，该页面会响应 `/about`、`/de/ueber-uns` 和 `/fr/a-propos`。没有配置条目的区域设置保留默认路径。编写路径时不要带区域设置代码：前缀由[策略](/zh/guide/strategy)添加，以区域设置代码开头的路径会输出警告。该调用接受的其他参数请参见[页面配置](/zh/guide/per-component-translations)。

## 在 nuxt.config 中 {#in-nuxt-config}

[`globalLocaleRoutes`](/zh/api/module-options#globallocaleroutes) 可以为任意页面实现同样的效果，以页面路径作为键（不带前导斜杠时则以路由名称作为键）：

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

当页面设置了 `localeRoutes`，而 `globalLocaleRoutes` 中有相同的键时，以配置中的条目为准。

## 动态参数 {#dynamic-params}

参数可以使用任意 Nuxt 形式书写：`[id]`、`[[page]]`、`[...slug]` 或 `:id()`。参数名称必须与页面文件一致。

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

嵌套页面可以使用绝对子路径（`/ueber-uns/team`），也可以使用相对于父级本地化路径的路径（`team`）。

## 链接到本地化页面 {#linking-to-localized-pages}

无论传入路由名称还是普通路径，链接都会解析为目标区域设置的本地化路径：

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

路由名称来自文件路径（`pages/about/team.vue` 对应 `about-team`），除非你通过 `definePageMeta({ name })` 自行设置。

## 按区域设置的 slug {#per-locale-slugs}

当 slug 本身因区域设置而异时（`/our-products/red-shoe` 与 `/de/unsere-produkte/roter-schuh`），请在数据加载完成后通过 `$setI18nRouteParams` 告诉语言切换器使用哪些参数：

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

之后 `$switchLocalePath('de')` 和 `<i18n-switcher>` 就会链接到 `/de/unsere-produkte/roter-schuh`。键是区域设置代码，值是按名称指定的参数（与页面文件中一致）。

布局中的切换器会在页面的异步 setup 执行到这里之前渲染，因此在渲染结束时，模块会重写 `<i18n-switcher>` 的链接，无论它位于 `app.vue` 还是页面中。这样服务器 HTML、未启用 JavaScript 的访问者以及首次客户端渲染的结果就会保持一致。为此请在 SSR 期间设置参数：使用 `lazy` 或 `server: false` 时，链接只会在 hydration 之后才改变。Nuxt 的 SSR 流式传输会在参数确定之前发送 HTML，因此在这种模式下，首个 HTML 中的链接会保留 URL 自身的参数。

只有切换器自身的链接会被重写。手写的 `$switchLocalePath` 链接必须在参数设置之后渲染，因此请将其放在设置参数的页面中，并且同样放在 `await` 之后。如果放在布局中，它会先渲染：其服务器 HTML 保留 URL 的参数，并且 hydration 会发出不匹配警告。在布局中请使用 `<i18n-switcher>`，并通过其插槽和 `custom*Style` 属性调整外观。

这些参数属于设置它们的页面：

- 当导航到其他路径的操作提交后，它们会被丢弃，因此每个页面都要设置自己的参数。被取消的导航会保留它们。
- 请在 `setup` 中从 `useNuxtApp()` 或 `useI18n()` 获取 `$setI18nRouteParams`，即使你之后才在 `useAsyncData` 处理函数中调用它。在那里获取的函数知道自己属于哪个页面：如果访问者已经离开，延迟的调用不会产生任何效果。
- 使用 `keepalive` 时，访问者返回页面后，页面会恢复它之前设置的参数。`useI18nHead` 也是如此。

## 在 pages:extend 中添加的路由 {#routes-added-in-pagesextend}

你在 `pages:extend` 钩子中添加的路由没有可供读取 `$defineI18nRoute` 的页面文件，而且其中多个路由常常共享同一个包装组件。添加时未指定 `name` 的路由会获得 Nuxt 根据其路径生成的名称（`/a/:id()` 变为 `a-id`），因此语言链接可以找到它；但如果其他路由已经使用了该名称，就需要为它显式指定 `name`。维护一份列表，然后使用 `@i18n-micro/utils/split-locale-routes` 中的 `splitLocaleRoutes` 将其拆分为页面和以路由名称为键的 `globalLocaleRoutes`（需要将该包添加到依赖中）：

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

不要将本地化路径放在 `route.meta` 中：它们会被包含在客户端路由表中一起发送。
