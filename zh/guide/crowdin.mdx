[Crowdin](https://crowdin.com/) 是一个翻译平台：你上传默认区域设置的文件，译者在 Crowdin 中工作，然后你再把其他区域设置的文件下载回来。模块读取的是普通 JSON 文件，因此 Crowdin CLI 只需要一个能正确映射 `locales/` 和 `locales/pages/` 的 `crowdin.yml`。无需修改任何模块设置。

## 配置 crowdin.yml {#configure-crowdin-yml}

```yml
# crowdin.yml
project_id_env: CROWDIN_PROJECT_ID
api_token_env: CROWDIN_PERSONAL_TOKEN
base_path: ./locales
preserve_hierarchy: true

files:
  - source: /en.json
    translation: /%two_letters_code%.json
  - source: /pages/**/en.json
    translation: /pages/**/%two_letters_code%.json
```

- `en` 是你的默认区域设置；它的文件就是源文件。
- `project_id_env` / `api_token_env` 从环境变量中读取 ID 和令牌，因此不会提交任何密钥。
- `preserve_hierarchy: true` 会保持 `pages/<page>/` 文件夹的原有结构。
- 翻译后的文件名必须与 `nuxt.config.ts` 中的区域设置 `code` 一致。`%two_letters_code%` 适用于 `de` 这样的代码；对于 `pt-BR` 这样的代码，请使用 `%locale%`，或通过 `languages_mapping` 将 Crowdin 的代码映射为你的代码。

## 上传和下载 {#upload-and-download}

```bash
npm install -g @crowdin/cli

export CROWDIN_PROJECT_ID=123456
export CROWDIN_PERSONAL_TOKEN=...   # from Crowdin account settings

crowdin upload sources   # push locales/en.json and locales/pages/**/en.json
crowdin download         # write locales/de.json, locales/pages/**/de.json, ...
```

在 CI 中运行这两个命令，以保持文件最新。下载的文件会像手动编辑的文件一样进入你的仓库；下一次构建或开发环境重新加载时就会读取它们。

## 上传之前 {#before-uploading}

先清理源文件，以免译者在无用的键上浪费精力：[`i18n-micro clean`](/zh/api/cli#clean) 会移除未使用的键，[`i18n-micro check`](/zh/api/cli#check) 会在下载后报告缺失项。CLI 本身没有 Crowdin 集成：本页介绍的就是官方支持的方式。
