`strategy` 选项决定 locale 是否出现在 URL 中，以及对哪些 locale 出现。请在发布 URL 之前确定好它：之后再修改会改变所有链接。模块随后会在构建时生成本地化路由，`$localePath`、`<i18n-link>` 和语言切换器都会读取这些路由。

## 四种策略 {#the-four-strategies}

![各策略下 en（默认）和 de 的 /about 页面；相同的 URL 也列在下方正文中](/images/diagrams/strategies.svg)

**类型** `Strategies` · **默认值** `'prefix_except_default'`

用于 locale 前缀的 URL 路由策略。

- `'no_prefix'` — URL 中没有 locale；locale 存储在 Cookie 中。
- `'prefix_except_default'` — 除默认 locale 外，所有 locale 都带前缀。
- `'prefix'` — 始终带前缀，包括默认 locale。
- `'prefix_and_default'` — 与 `prefix` 相同，但默认 locale 也可以不带前缀访问。

在 `defaultLocale: 'en'`、locale 为 `en`、`de` 时，`about` 页面的 URL：

| 策略 | 英语 | 德语 | 不提供 |
| --- | --- | --- | --- |
| `prefix_except_default`（默认） | `/about` | `/de/about` | `/en` 和 `/en/about` 返回 404 |
| `prefix` | `/en/about` | `/de/about` | `/about` 重定向到带前缀的 URL |
| `prefix_and_default` | `/about` 和 `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | locale 不在 URL 中 |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

策略在构建时固定：运行时对它的覆盖会被忽略并给出警告（[运行时覆盖](/zh/guide/runtime-overrides)）。

## 如何选择 {#which-one-to-choose}

- **`prefix_except_default`**：适用于大多数网站。现有的无前缀 URL 对默认语言仍然有效。
- **`prefix`**：所有语言地位平等；`/` 始终指向带前缀的首页。
- **`prefix_and_default`**：需要 `/en/...` 和无前缀 URL 同时可用，例如在从一种形式迁移到另一种形式期间。无前缀 URL 永远不会被重定向。
- **`no_prefix`**：需要登录的应用，或每个页面对所有语言只使用一个 URL。locale 来自 Cookie 或 `?locale=`。搜索引擎每个 URL 只能看到一种语言，因此不会输出 `hreflang` 备用链接。

如何为 URL 选择 locale，以及访客何时会被重定向，请参阅 [Locale 检测](/zh/guide/locale-detection)。

## 生成的路由 {#generated-routes}

在构建时，每个页面都会获得其策略所需的路由记录。每条记录都带有 `meta.i18n = { name, locales }`：它显示的页面以及它服务的 locale。链接、切换和重定向都依据这些记录来处理，因此模块给出的 URL 一定是路由器能够提供的。

共享页面路径的多个 locale 共用一条记录，`/:locale(de|fr)/about`。拥有自己路径的 locale 会获得自己的记录，命名为 `localized-<page>-<locale>`：

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

自定义路径、按页面设置的 locale 列表以及将页面排除在本地化之外，请参阅[本地化路径](/zh/guide/custom-locale-routes)和[页面配置](/zh/guide/per-component-translations)。`localized-` 前缀由 [`localizedRouteNamePrefix`](/zh/api/module-options#localizedroutenameprefix) 设置。

<Warning>

**路由名称是生成的** — 不要在 `router.push({ name })` 中硬编码 `localized-…` 名称。请将页面自身的名称传给 `$localeRoute` 或 `<i18n-link>`；它们会选择正确的记录。

</Warning>

## 链接到某个 locale 下的页面 {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- 命名路由和路径都可以使用。路径会与生成的路由进行匹配，因此任何 locale 形式的路径都可以被接受。
- 如果某个 locale 不提供该页面（参见[页面配置](/zh/guide/per-component-translations)中的 `locales`），链接会指向该 locale 的首页，而不是一个不存在的页面。
- 按 locale 区分的参数（翻译后的 slug）通过 `$setI18nRouteParams` 设置，参见[本地化路径](/zh/guide/custom-locale-routes)。

签名请参阅[方法](/zh/api/methods)。

## `no_prefix` 细节 {#no_prefix-details}

- 在 `no_prefix` 下，[`localeCookie`](/zh/api/module-options#localecookie) 默认为 `'user-locale'`，因此选择在刷新后仍会保留。
- `$switchLocale('de')` 会加载德语字典并替换当前的历史记录条目；URL 不会改变。
- 按 locale 自定义的路径仍然有效：使用 `globalLocaleRoutes: { about: { de: '/ueber-uns' } }` 时，德语读者会得到 `/ueber-uns`。无论访客偏好什么，该 URL 始终渲染德语；限制为部分 locale 的页面会以其中之一渲染。多个 locale 共享的路径（`en` 和 `de` 都在 `/page/:id`）在偏好属于其中之一时按偏好渲染。偏好本身保持不变：下一个页面会回到该偏好。
- [`noPrefixRedirect: true`](/zh/api/module-options#noprefixredirect) 会重定向在默认 locale 中有自定义路径的页面的原始路径：重定向到访客 locale 的自定义路径，否则重定向到默认 locale 的自定义路径（当 `en` 有 `/about-us` 时，`/about` → `/about-us`；Cookie 为 `de` 时 → `/ueber-uns`）。没有自己自定义路径的 locale 会停留在原始路径上并在那里渲染。带参数的页面不会被重定向。

## 没有 `pages/` 的应用 {#apps-without-pages}

使用 `pages: false` 时，没有可本地化的页面路由。请只使用根翻译文件（`disablePageLocales: true`）；检测、Cookie 和 `$switchLocale` 仍然有效。仓库中 `test/fixtures/basic` 的 `pages-false` 变体是一个可用的示例配置。
