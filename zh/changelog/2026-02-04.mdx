**日期**：2026-02-04

**版本**：`v3.0.0`

![v3.0.0 release](/images/3.0.0.png)

我们正式发布 **v3.0.0**，带来一次**重大架构重构**：为追求极致性能完全重写了翻译存储系统，路由生成和运行时路径逻辑现已拆分为独立的包，重定向流程也经过重新设计，以提升可靠性并兼容 Serverless。

## 有哪些新内容？ {#what’s-new}

### 性能优化 — 全新的翻译存储架构 {#performance-optimization-—-new-translation-storage-architecture}

翻译加载和缓存系统已完全重写，以实现最高性能：

- **集中式 TranslationStorage 类** — 新的 `TranslationStorage` 类（`src/runtime/utils/storage.ts`）为客户端和服务端提供统一的存储。它结合 `globalThis` 与 `Symbol.for`，保证在整个 Node.js 进程中是真正的单例，避免在打包后的各模块之间重复缓存。

- **优化后的 `$t()` 函数（tFast）** — 翻译函数直接在单个活动字典中查找：
  1. 所有翻译（根级 + 页面级 + 回退）在构建时预先合并为每个页面一个文件
  2. 在同一语言环境内导航时，新页面的翻译会累积合并到活动字典中（防止过渡动画期间键闪烁）
  3. 支持嵌套键（`key.subkey.subsubkey`），并对路径解析进行了优化
  4. 每次调用都不进行 Map 查找或语言环境/路由计算 — 使用预先计算的上下文

- **通过 `window.__I18N__` 进行服务端注入** — SSR 期间加载的翻译以 script 标签的形式注入到 HTML 中。客户端在首次加载时直接读取 `window.__I18N__`，避免重复请求。

- **插件中的本地分块缓存** — 插件维护一个本地的 `loadedChunks` Map，存储所有已加载的翻译分块。一旦加载，翻译在页面生命周期内不会再次请求。

- **构建时预合并** — `module.ts` 中的 `preMergeLocales` 步骤会在构建时把所有层、回退语言环境链和根级翻译合并到每个页面文件中。server-loader 只需读取一个预先构建的文件 — 无需在运行时合并。

**性能提升：**

- 降低每个请求的内存分配（每次调用 `$t()` 都不再重新创建对象）
- 降低垃圾回收压力
- 负载下响应更快
- 内存使用模式稳定（图表不再"跳动"）

### 路由与路径策略包 {#route-&-path-strategy-packages}

- **@i18n-micro/route-strategy** — 构建时路由生成：用本地化路由扩展 Nuxt 页面，并按策略处理别名、嵌套路由和自定义路径。单一入口：`new RouteGenerator(options)` 和 `extendPages(pages)`。各策略（`no_prefix`、`prefix`、`prefix_except_default`、`prefix_and_default`）实现为独立的类，并通过工厂选择。
- **@i18n-micro/path-strategy** — 运行时路径和语言环境处理：提供 `PathStrategy`，用于构建本地化路径、解析重定向和切换语言环境。支持 tree-shaking 的子路径导出（`/prefix`、`/no-prefix` 等），因此只会打包所选的策略。使用纯函数进行路由解析，并使用预先计算的上下文标志将内存分配降到最低。
- **结构化的包布局** — 路由逻辑位于 `@i18n-micro/route-strategy`，包含 `core/`、`strategies/`。路径策略位于 `@i18n-micro/path-strategy`，采用扁平的 `src/` 结构：`types.ts`、`path.ts`、`resolver.ts`、`helpers.ts` 和 `strategies/`。
- **行为一致** — 别名处理、父子路径拼接、自定义 `globalLocaleRoutes` / `filesLocaleRoutes` / `routeLocales` 以及不可变性保证都由专门的测试套件覆盖。

### 重定向架构重构 {#redirect-architecture-overhaul}

- **服务端中间件** — 重定向和 404 处理在 Nitro 中间件（`i18n.global.ts`）中运行。它在 Nuxt 渲染之前执行，因此当存在语言环境 cookie 时，从 `/` 到 `/<locale>/` 的重定向不会出现错误闪烁。
- **客户端插件（客户端）** — 一个仅限客户端的插件（`06.client-redirect.client.ts`）在水合之后运行，并在 `useI18nLocale()` 或 cookie 设置了非默认语言环境时处理重定向。Nitro 在 Nuxt 之前运行，因此服务端看不到用户插件对 cookie/state 的修改；客户端插件覆盖了这种情况。
- **不再有回退组件** — `locale-redirect.vue` 回退组件和 `fallbackRedirectComponentPath` 选项已被移除。重定向逻辑完全由服务端中间件和客户端插件处理。
- **支持自定义路径** — 诸如德语的 `/kontakt`（通过 `globalLocaleRoutes`）这样的路径即使没有语言环境前缀也能被正确识别为有效路径，避免预渲染时出现错误的 404。
- **customRegexMatcher 修复** — 使用 `customRegexMatcher` 时，模式现在会匹配**整个**第一个路径段（带有 `^` 和 `$` 锚点）。这避免了 `/locale-test` 之类的路由出现误报 404，而此前模式 `[a-z]{2}-[a-z]{2}` 会匹配其子串。
- **autoDetectPath 修复** — `autoDetectPath` 选项现在会正确地与原始 URL 路径进行比较，避免在显式导航到带语言环境前缀的 URL 时发生不必要的重定向。

### useI18nLocale 组合式函数 {#usei18nlocale-composable}

- **集中式语言环境管理** — 新的 `useI18nLocale()` 组合式函数取代了 `useLocaleCookies`，为语言环境状态、cookie 和同步工具提供单一入口。
- **API** — `locale`、`localeCookie`、`hashCookie`、`getLocale()`、`getPreferredLocale()`、`setLocale()`、`syncLocale()`、`isValidLocale()`、`getEffectiveLocale()`、`resolveInitialLocale()`。
- **以编程方式设置语言环境** — 在服务端插件中使用 `useI18nLocale().setLocale(locale)` 代替 `useState('i18n-locale')`，使语言环境处理更简洁、更集中。

### 自定义自动检测与配置 {#custom-auto-detection-&-configuration}

- **`getI18nConfig()`** — 自定义插件（例如用于语言环境检测的插件）应使用 `#build/i18n.strategy.mjs` 中的 `getI18nConfig()`，而不是 `useRuntimeConfig().public.i18nConfig`。它可直接访问解析后的 i18n 配置（例如 `localeCookie`），无需依赖运行时配置。
- **Cookie 名称** — 实现自定义检测逻辑时，请使用 `getI18nConfig().localeCookie ?? 'user-locale'`。

### 简化的集成包 {#simplified-integration-packages}

所有集成包（`@i18n-micro/vue`、`@i18n-micro/astro`、`@i18n-micro/node`、`@i18n-micro/react`、`@i18n-micro/preact`、`@i18n-micro/solid`）都经过简化和优化，共享相同的核心翻译逻辑。

### 配置变更 {#configuration-changes}

- **移除 `previousPageFallback`** — 不再需要此选项。新的累积合并策略会在过渡动画期间自动保留上一页的翻译，然后通过 `page:transition:finish` 钩子清理它们。
- **`hmr`** — 从 `experimental.hmr` 移至顶层选项。控制翻译文件的服务端 HMR（开发环境下默认启用）。

```typescript
// Before (v2.x)
export default defineNuxtConfig({
  i18n: {
    experimental: {
      hmr: true,
    },
  },
})

// After (v3.0.0)
export default defineNuxtConfig({
  i18n: {
    hmr: true,
  },
})
```

## 破坏性变更 {#breaking-changes}

- **`fallbackRedirectComponentPath`** — 已移除。模块不再使用回退路由组件进行重定向。如果你配置了自定义组件路径，请将其从配置中删除。
- **`useLocaleCookies`** — 已移除。请改用 `useI18nLocale()`。新的组合式函数提供 `locale`、`localeCookie`、`hashCookie`、`setLocale()`、`syncLocale()` 等。
- **`experimental.i18nPreviousPageFallback` / `previousPageFallback`** — 已完全移除。累积合并策略会自动处理过渡时的闪烁。请从配置中删除此选项。
- **`experimental.hmr`** — 已移至 `hmr`。如果你使用了此选项，请更新配置。
- **自定义插件** — 如果你的自定义语言环境检测插件使用了 `useRuntimeConfig().public.i18nConfig`，请改用 `#build/i18n.strategy.mjs` 中的 `getI18nConfig()`。优先使用 `useI18nLocale().setLocale()`，而不是 `useState('i18n-locale')`。更新后的示例请参见[自定义语言检测](/zh/guide/custom-auto-detect)。
- **内部文件变更** — `load-from-storage.ts` 和 `translation-loader.ts` 已被移除，并由 `storage.ts` 和 `server-loader.ts` 取代。如果你直接从这些文件导入（不推荐），请更新导入。

## 为什么重要 {#why-it-matters}

- **性能**：集中式单例缓存消除了每个请求的对象创建，并降低了 GC 压力。
- **可维护性**：路由和路径逻辑位于独立的包中，边界和类型清晰。
- **测试**：策略行为和边界情况可以独立测试。
- **可靠性**：将服务端（Nitro）和客户端的重定向逻辑分开，避免了用户插件设置 cookie/useState 时的时序问题。
- **适用于 Serverless**：Nitro 插件与 Nitro 处理器在同一上下文中运行，兼容 Edge/Workers。
- **文档**：路由行为记录在[策略指南](/zh/guide/strategy)以及 [path-strategy](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/path-strategy) 和 [route-strategy](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/route-strategy) 包中。

有关升级说明和完整的变更列表，请参见[变更日志](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md)。
