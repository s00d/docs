# 运行时 i18n 覆盖

当你需要让一份构建产物在不同环境下使用不同的区域默认值（例如：不同租户实例）时，请参考本指南。

## 可以在运行时覆盖的内容

模块支持对以下项进行安全的运行时覆盖：

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

这些覆盖会应用在 `.nuxt/i18n.strategy.mjs` 和 `.nuxt/i18n.config.mjs` 提供的构建时配置之上。

## 不能在运行时覆盖的内容

`strategy`（`no_prefix`、`prefix`、`prefix_except_default`、`prefix_and_default`）属于构建时配置，因为它会影响生成的路由行为。

如果你在运行时传入 strategy 覆盖，则会被忽略并输出警告。

## 基于 RuntimeConfig 的覆盖

在 `runtimeConfig.public.i18nRuntime` 下提供运行时值：

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## 通过环境变量覆盖

你也可以通过环境变量配置覆盖：

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES`（逗号分隔，例如 `fr,it`）

同时支持以下备用别名：

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## 校验规则

在运行时，模块会校验覆盖以避免出现无效状态：

- 不能禁用所有区域。
- `defaultLocale` 必须指向一个已启用的区域。
- `fallbackLocale` 必须存在于已声明的 locales 中。

如果覆盖无效，模块会保留安全值并记录警告。

## 关于多实例部署的说明

此运行时功能旨在实现按实例激活区域和设置默认值而无需重新构建。

如果不同实例需要不同的 URL 策略（`no_prefix` 对 `prefix`），请为每种策略使用单独的构建。

## 禁用的区域与静态载荷

`runtimeConfig.public.i18nRuntime.disabledLocales` 会更新路由、切换器以及 Nitro 载荷**处理器** —— 但 Nitro 会在该处理器之前提供 `public/` 下的文件。

如果 `translationPayloads.publicAssets`（或 Node SSR 强制的 public 复制）已经写入了 `/_locales/\{page\}/\{locale\}/data.json`，则运行时禁用无法隐藏该文件。请在构建时使用 `locale.disabled: true`，让预合并不会为该区域生成静态载荷。
