# 🌐 Crowdin 集成指南

## 📖 引言

将 Crowdin 集成到你的项目中可以简化本地化和翻译流程，让跨多语言和多平台的翻译管理更加轻松。本指南将逐步介绍如何在项目中设置 Crowdin，包括配置、上传源文件和下载翻译。

## 🔧 安装与设置

要开始使用 Crowdin，你需要在机器上全局安装 Crowdin CLI 并在项目目录中初始化。

### 📦 安装 Crowdin CLI

首先，使用 npm 全局安装 Crowdin CLI：

```bash
npm install -g @crowdin/cli
```

### 🛠 在项目中初始化 Crowdin

在你的项目中运行以下命令初始化 Crowdin：

```bash
crowdin init
```

该命令将指导你完成设置流程，包括设置项目 ID、API token 和其他配置细节。

## 🗂️ 配置指南

### 📄 Crowdin 配置文件（`crowdin.yml`）

Crowdin 配置文件（`crowdin.yml`）定义了源文件的映射方式以及翻译文件的放置位置。下面是一个配置示例：

```yml
'project_id': 'YOUR_PROJECT_ID'
'api_token': 'YOUR_API_TOKEN'
'base_path': './locales'
'base_url': 'https://api.crowdin.com'
'preserve_hierarchy': true

files:
  [
    { 'source': '/en.json', 'translation': '/%two_letters_code%.json' },
    { 'source': '/pages/**/en.json', 'translation': '/pages/**/%two_letters_code%.json' },
  ]
```

### 📂 关键配置参数

- **`project_id`**：你的 Crowdin 项目 ID。用于标识 Crowdin 中管理翻译的项目。
- **`api_token`**：用于身份验证的 API token。请确保该 token 拥有上传和下载翻译的正确权限。
- **`base_path`**：指定源文件的基础目录。在此示例中，翻译存储在 `./locales` 目录下。
- **`base_url`**：Crowdin API 的基础 URL。
- **`preserve_hierarchy`**：设为 `true` 时，Crowdin 会在项目中保持源文件的目录结构。

### 📂 Files 配置

`files` 部分将源文件映射到翻译文件的存储路径。例如：

- **Source Path**：定义原始翻译文件的位置。
- **Translation Path**：指定翻译文件将存储在 Crowdin 中的位置。占位符（如 `%two_letters_code%`）用于在文件路径中动态设置语言代码。

## ⬆️ 上传源文件到 Crowdin

Crowdin 配置完成后，你可以使用以下命令上传源文件：

```bash
crowdin upload sources
```

该命令会将配置中指定的所有源文件上传到 Crowdin，使其可供翻译。

## ⬇️ 从 Crowdin 下载翻译

在 Crowdin 中翻译完成或更新后，你可以使用以下命令将其下载到项目中：

```bash
crowdin download
```

该命令会从 Crowdin 获取最新翻译，并按照配置文件中指定的路径保存。

## ⚙️ 最佳实践

### 🔑 一致的键命名

确保所有文件中的翻译键保持一致，避免混淆和重复。

### 🧹 定期维护

定期审查并清理未使用的翻译键，保持文件的组织性和可维护性。

### 🛠 自动化上传和下载

将 Crowdin CLI 命令集成到 CI/CD 流水线中，自动化源文件的上传和翻译的下载，确保翻译始终保持最新。

按照本指南操作，你就能将 Crowdin 无缝集成到项目中，为国际化工作提供高效有序的管理方式。
