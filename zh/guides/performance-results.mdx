# 性能测试结果

## 项目信息

- **[plain-nuxt](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/plain-nuxt)**: ./test/fixtures/plain-nuxt
- **[i18n-micro](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n-micro)**: ./test/fixtures/i18n-micro
- **[i18n](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n)**: ./test/fixtures/i18n
- **[CLI](https://github.com/s00d/nuxt-i18n-micro/tree/main/scripts/src/commands/performance.ts)**: `pnpm -C scripts cli performance` / `pnpm test:performance`

### 说明

在一个共享的词典配置下，比较 **plain Nuxt**（未使用 i18n 模块的基线）、**i18n-micro** 以及 **`@nuxtjs/i18n` v10.6**。

关注点：构建时间、峰值 RSS、可部署的 **代码 / 翻译 / 总体** 大小，以及在 Artillery + Autocannon 下的服务器行为。

### 方法论说明

- 各项指标为**每个 fixture 连续运行 3 次的均值**（fixture A ×3，随后 B ×3，再 C ×3 — 不交叉运行）。
- **翻译**包括 `locales/` / `_locales/` / `translations/` 下的区域 JSON、`chunks/raw/` 下的一切内容，以及匹配的区域 chunk。之前显示 `@nuxtjs/i18n` "翻译：0 B" 与巨大 "代码" 列的报告是把消息 chunk 当作应用代码进行统计的。
- **plain-nuxt** 提供与静态 `public/translations` JSON 相同的叶子文件体量（而不是静态 JS 导入）。在 Artillery 下这一基线的 I/O 负担较重；它并不是 "i18n 开销"，而是每次请求都要获取大 JSON 的成本。

### 运行

以下所有指标均为**3 次运行的均值**。

### Fixture 配置

| 参数 | 值 |
|------|-------|
| Locales | **4**（`en`、`de`、`ru`、`fr`） |
| 页面 | **2**（`index`、`page`） |
| Index 树 | 深度 **5**，分支 **7** → 每 locale **16,807** 个叶键 |
| 其他页面 | 深度 **5**，分支 **6** → 每页每 locale **7,776** 个叶键 |
| 目标 | 默认 CLI 配置（`--locales 4 --keys 10000`）；提高参数用于回归监控负载 |

词典来自 `test/fixtures/perf-shared/runtime.json`（由 CLI 写入），因此三个 fixture 保持一致。

## test/fixtures/plain-nuxt 的构建性能

- **构建时间**：5.32 秒
- **打包大小**：8.33 MB（代码：1.53 MB，翻译：6.8 MB）
- **代码包**：客户端：201.88 KB，服务端：1.33 MB

## test/fixtures/i18n 的构建性能
