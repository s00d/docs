# 从 i18n 路由中排除静态文件

## 概述

默认情况下，nuxt-i18n-micro 会自动将常见静态文件从 i18n 路由处理中排除。此外，你还可以配置自定义排除规则，防止特定路径被 i18n 系统处理。

## 内置排除项

模块会自动排除以下文件类型和路径：

- **Sitemap**：`/sitemap*.xml`、`/sitemap-en.xml` 等。
- **SEO 文件**：`/robots.txt`、`/favicon.ico`
- **PWA 文件**：`/manifest.json`、`/sw.js`、`/workbox-*.js`
- **静态资源**：扩展名为 `.xml`、`.txt`、`.ico`、`.json`、`.js`、`.css`、`.png`、`.jpg`、`.jpeg`、`.gif`、`.svg`、`.woff`、`.woff2`、`.ttf`、`.eot` 的文件
- **Nuxt 内部路径**：任何以 `__` 开头的路径（如 `/__nuxt/`）

## 自定义排除规则

你可以使用 `excludePatterns` 选项定义自定义排除规则：

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## 规则类型

### 字符串规则

- **精确匹配**：`'/api/health'` — 精确匹配 `/api/health`
- **前缀匹配**：`'/admin'` — 匹配 `/admin` 与 `/admin/dashboard`
- **通配符**：`'/api/*'` — 匹配 `/api/users`，但不匹配 `/api/users/123`
- **深度通配符**：`'/admin/**'` — 匹配 `/admin/users` 与 `/admin/users/123`

### 正则表达式

对于复杂的匹配，请使用 RegExp 对象：

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## 用例

### SEO 文件

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API 路由

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### 后台管理面板

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### 静态资源

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## 工作原理

1. **服务端中间件**：Nitro 中间件会首先运行以检查排除规则
2. **页面处理**：在页面解析过程中，被排除的路径会被跳过
3. **catch-all 路由**：兜底路由在处理前会检查排除规则
4. **预渲染**：被排除的路径不会包含在预渲染路由中

## 性能影响

- 排除检查经过优化，在请求生命周期的早期阶段执行
- 内置规则使用高效的正则匹配
- 自定义规则会被缓存并重复使用
- 被排除路径的性能开销极小

## 故障排查

### 静态文件仍被拦截

1. **检查规则语法**：确保规则与实际路径结构精确匹配
2. **对复杂规则使用正则**：字符串通配符存在限制
3. **测试规则**：使用浏览器开发者工具核对实际请求路径
4. **检查顺序**：确保排除规则在其他 i18n 配置之前定义

### 规则不生效

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### 调试模式

启用调试模式以查看排除处理过程：

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

这会在控制台输出排除决策日志。

## 从变通方案迁移

如果你之前使用 route rules 或中间件等变通方案，现在可以将其替换为 `excludePatterns`：

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

新方式更加可靠，并且在路由系统的多个层面都能生效。
