# 模块选项参考

`nuxt-i18n-micro` 接受的每个选项都在此列出，由构建时从 [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts) 中的 `ModuleOptions` 接口读取生成。此处的内容不是手写的，因此不会落后于代码 — 类型、默认值和描述均来自声明本身。

若想理解这些选项协同工作的含义 — 哪些组合合理、切换 strategy 时会发生什么、可运行的示例 — 请阅读[配置](/guides/configuration)。本页是详尽的列表；那一页是相应的解释。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

嵌套选项会以带点的路径出现，例如 `translationPayloads.mode` 是 `translationPayloads` 对象内的 `mode` 键。

## 区域与路由

存在哪些语言，以及它们在 URL 中如何呈现。

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | 支持的区域列表。每个条目定义一个区域代码以及可选的元数据（ISO、方向、显示名称等）。 |
| `strategy` | `Strategies` | `'prefix_except_default'` | 区域前缀的 URL 路由策略。 - `'no_prefix'` — URL 中不含区域；区域存储在 cookie 中。 - `'prefix_except_default'` — 除默认区域外的所有区域都添加前缀。 - `'prefix'` — 始终添加前缀，包括默认区域。 - `'prefix_and_default'` — 类似 `prefix`，但默认区域也可以在没有前缀的情况下访问。 |
| `defaultLocale` | `string` | `'en'` | 当无法从 URL 或用户偏好确定区域时使用的区域。当 `fallbackLocale` 未设置时，也用作缺失翻译的回退区域。 |
| `localeCookie` | `string \| null` | `null` | 用于跨会话保存用户区域偏好的 cookie 名称。设为 `null` 可禁用基于 cookie 的持久化。若未提供，对于 `no_prefix` 策略会自动设置为 `'user-locale'`。 |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | 全局路由级区域配置。可在不修改页面组件的情况下限制或自定义特定页面的区域路由。 - `false` — 将该路由排除在本地化之外。 - `Record<LocaleCode, string>` — 每个区域的自定义路径。 |
| `customRegexMatcher` | `string \| RegExp` | `undefined（使用基于区域代码的内置模式）` | 用于匹配 URL 段中区域代码的自定义正则表达式（或其字符串源）。`locales` 中定义的所有区域代码都必须匹配此模式，否则会发出警告。 |
| `noPrefixRedirect` | `boolean` | `false` | 对于 `no_prefix` 策略：启用从带区域前缀的 URL（例如 `/en/about`）重定向到不带前缀的版本（`/about`）。 |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | 完全排除在 i18n 处理之外的 URL 规则（字符串或 RegExp）。匹配的路由不会获得区域前缀、重定向或翻译加载。Nuxt 内部路径（`/__nuxt_error` 等）总是自动排除。 |
| `routeLocales` | `Record<string, string[]>` | — | 按路由的区域限制，从 `defineI18nRoute()` 调用中提取。将路由路径（例如 `'/about'`）映射到允许的区域代码数组。未列出的路由没有限制（所有区域允许）。 |

## 翻译

翻译文件存放位置以及键的解析方式。

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | 存放翻译 JSON 文件的目录路径，相对于项目根目录。 |
| `disableWatcher` | `boolean` | `false` | 禁用开发模式下自动创建缺失翻译文件的文件监视器。 |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | 将路由名映射到其他路由名以共享相同的翻译文件。例如 `\{ 'about-us': 'about' \}` 表示 `about-us` 页面将使用 `about` 页面的翻译，而不是自己的。 |
| `plural` | `PluralFunc` | `内置复数（按数量选择形式索引）` | 自定义复数函数。接收 `(key, count, params, locale, getter)`，应以字符串形式返回选中的复数形式，或返回 `null`/`undefined` 以回退到内置的 `defaultPlural` 逻辑（这样你可以仅覆盖部分区域）。在 Nuxt 模块中，函数会通过 `.toString()` 序列化到 `.nuxt/i18n.plural.mjs` — 它必须是自包含的（无 import / 外层作用域）。**不**支持文件路径字符串。 |
| `disablePageLocales` | `boolean` | `false` | 禁用页面级翻译文件。为 `true` 时，只加载全局翻译（`\{locale\}.json`）；不会生成或加载页面级文件（`pages/\{page\}/\{locale\}.json`）。 |
| `fallbackLocale` | `string` | `undefined（无回退；返回原始键）` | 全局回退区域代码。当活动区域中缺少翻译键时，模块会先在该区域查找，然后再返回键本身。 |

## 载荷与缓存

翻译如何到达浏览器。[性能](/guides/performance)解释了这些选项在运行时的影响。

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | 在 Nitro 全局中间件中预加载 index 页翻译（仅服务端，私有配置）。 |
| `apiBaseUrl` | `string` | `'_locales'` | 翻译 API 路由的 base URL 路径段（用于 SSR/SSG 数据获取）。也可通过 `NUXT_I18N_APP_BASE_URL` 环境变量设置。 |
| `apiBaseClientHost` | `string` | `undefined` | 覆盖客户端翻译 fetch 请求使用的主机。当客户端通过与 Nuxt 所见不同的主机名访问服务器时有用。也可通过 `NUXT_I18N_APP_BASE_CLIENT_HOST` 环境变量设置。 |
| `apiBaseServerHost` | `string` | `undefined` | 覆盖服务端翻译 fetch 请求使用的主机。在容器/微服务部署中，当服务器通过内部主机名访问自身时有用。也可通过 `NUXT_I18N_APP_BASE_SERVER_HOST` 环境变量设置。 |
| `translationPayloads` | `TranslationPayloadOptions` | — | 控制翻译载荷的输出方式（Node：`public/<apiBaseUrl>`；Edge：Nitro `serverAssets`）。 - **Node**：`serverAssets` 表示本地 SSR 通过 `readFile` 从 `public/` 读取（无 Rollup `raw:`）。 - **Edge**：`serverAssets` 注册 Nitro `serverAssets`（`assets:i18n`）；它不会强制 public 副本。对常见的一体化部署保持默认即可。对大型 Edge 词典，请优先使用 `mode: 'source'`。对 CDN 部署，禁用本地输出并设置 `apiBaseClientHost` / `apiBaseServerHost`。 |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | 翻译载荷策略。 - `premerged`：构建时生成 `\{page\}/\{locale\}/data.json` 矩阵（默认） - `source`：运行时合并的紧凑源文件（在 Edge / 大型词典上优先使用） |
| `translationPayloads.serverAssets` | `boolean` | `true` | 本地 SSR 载荷：Node 从 `public/<apiBaseUrl>` 读取（强制 public 副本）；Edge 通过 Nitro `serverAssets` 嵌入。 - **Node**：不使用 Nitro `serverAssets`（避免 Rollup `raw:`）。SSR 从 `public/<apiBaseUrl\|publicDir>` 以 `\{page\}/\{locale\}/data.json` 读取；此值为 `true` 时，即使 `publicAssets` 为 false 也会强制 public 副本。 - **Edge**（`nitro.node === false`）：Nitro `serverAssets`（`assets:i18n`），布局与 `mode` 相同。**不**强制 public 副本 — 若需要 CDN，请设置 `publicAssets: true`。 |
| `translationPayloads.serverHandler` | `boolean` | `true` | 注册位于 `/\{apiBaseUrl\}/:page/:locale/data.json` 的内置服务端路由。当翻译载荷从外部主机/CDN 提供时禁用该项。 |
| `translationPayloads.publicAssets` | `boolean` | `premerged 模式为 true，source 模式为 false` | 将载荷复制到 Nitro 的 public 输出。Premerged → 在 `apiBaseUrl` 下生成 `\{page\}/\{locale\}/data.json`；source → 紧凑树。在 Node 上，当 `serverAssets` 强制 public 副本时，该树也是 SSR 源。 |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | 加入 Nitro 预渲染 `/\{apiBaseUrl\}/.../data.json`。当 premerged `publicAssets` 已经写入这些文件时通常是多余的。 |
| `translationPayloads.publicDir` | `string` | — | 相对于 Nitro public 根目录的输出目录。默认为 `apiBaseUrl`（`_locales`）。这样静态文件与客户端 fetch URL 匹配（`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`）。 |
| `translationPayloads.warnFileCount` | `number` | `500` | 当生成的载荷文件数量超过此阈值时，在构建期间发出警告。 |
| `translationPayloads.warnSizeBytes` | `number` | `10485760（10 MB）` | 当生成的载荷总大小（字节）超过此阈值时，在构建期间发出警告。 |

## SEO

为每个本地化页面生成的元标签。

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | 自动生成 SEO 元标签（`hreflang`、`canonical`、`og:url`、`og:locale`）。 |
| `metaBaseUrl` | `string` | `undefined` | SEO 元标签（canonical、og:url、hreflang）的 base URL。 - 具体 URL 字符串（例如 `'https://example.com'`）— 原样使用（优先级最高）。 - `undefined` — 当存在 `nuxt-site-config` 模块时回退到其 `site.url`，否则使用当前请求源（服务端 `useRequestURL().origin`，客户端 `window.location.origin`）。 |
| `metaTrustForwardedHost` | `boolean` | `true` | 解析元标签的 base URL 时信任 `X-Forwarded-Host` 头。当应用在反向代理（nginx、Cloudflare、AWS ALB 等）后面运行且该代理将真实客户端主机名设置到此头时启用。 |
| `metaTrustForwardedProto` | `boolean` | `true` | 解析元标签的协议时信任 `X-Forwarded-Proto` 头。当应用运行在终止 TLS 的代理后面时启用，以便 canonical URL 使用 `https://`，即便应用自身监听 HTTP。 |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | 在 canonical 与 `og:url` 元标签中保留的查询参数名列表。不在此列表中的参数会从 canonical URL 中去除。 |

## 检测与重定向

为未选择区域的访客选择区域。

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | 启用基于区域的自动重定向。为 `true` 时，访客在首次访问时会被重定向到其偏好区域（从 cookie、`Accept-Language` 头或默认值检测得到）。 |
| `autoDetectLanguage` | `boolean` | `true` | 自动从 `Accept-Language` HTTP 头检测用户偏好语言。与 `autoDetectPath` 结合使用，决定何时检测。 |
| `autoDetectPath` | `string` | `'/'` | Cookie / Accept-Language 偏好重定向可以运行的路径（当启用 `redirects` 时）。 - `'/'` — 仅 `/`（默认区域的深链接仍可访问；默认） - `'no_prefix'` — 仅不带区域前缀的路径 - `'*'` — 所有路径，包括重写显式的区域前缀（例如当 cookie 偏好 `de` 时，`/fr/about` → `/de/about`） - 任意其他字符串 — 精确路径匹配（例如 `'/welcome'`） 前缀策略清理（例如 `prefix_except_default` 下的 `/en` → `/`）不受此设置限制。 |

## 注册

模块中可关闭的部分。

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | 注册 `defineI18nRoute()` 宏插件，启用页面级 `defineI18nRoute()` 调用。 |
| `plugin` | `boolean` | `true` | 注册提供 `$t()`、`$tc()`、`$getLocale()`、`$switchLocale()` 及其他运行时辅助方法的核心 i18n 插件。 |
| `hooks` | `boolean` | `true` | 注册提供 `i18n:register` 与 `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch` 应用级 hooks 的 i18n hooks 插件。 |
| `components` | `boolean` | `true` | 注册内置 i18n 组件（`<i18n-link>`、`<i18n-switcher>`、`<i18n-t>`、`<i18n-group>`）。设为 `false` 可禁用自动组件注册（例如你不使用它们，希望减少模块占用时）。 |
| `types` | `boolean` | `true` | 根据默认区域文件中的翻译键，为 `useI18n`、`$t` 及相关辅助方法生成 TypeScript 类型声明。 |
| `debug` | `boolean` | `false` | 为区域检测、路由生成和翻译加载启用详细的调试日志。 |

## 其他

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | 同时从每个区域的 `iso` 派生一个纯语言 `hreflang`（例如 `es-ES` → 也生成 `es`）。`locales` 中第一个匹配地区的区域声明该语言的纯标签。绝不使用路由 `code` — 仅使用 `iso \|\| code`。 |
| `vueDevtools` | `boolean` | `true` | 在开发模式下注册 Vue DevTools inspector 与 timeline（浏览器扩展）。与 Nuxt DevTools 自定义面板独立。 |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | 为本地化路由名添加的前缀（例如 `'localized-index'`）。内部用于区分原始路由和生成的区域变体。 |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | 从 `defineI18nRoute()` 调用中提取的按路由禁用元标签。将路由路径映射到 `true`（禁用所有 meta）或应禁用 meta 的区域代码数组。 |
| `missingWarn` | `boolean` | `true` | 当翻译键缺失时在控制台显示警告。 |
| `hmr` | `boolean` | `true` | 在开发环境中为翻译文件启用热模块替换。为 `true` 时，JSON 翻译文件的更改会触发自动重载而无需完整刷新页面。 |
| `cacheMaxSize` | `number` | `0` | 内存翻译缓存中的最大条目数。`0` 表示不限。 |
| `cacheTtl` | `number` | `0` | 缓存翻译条目的存活时间（秒）。`0` 表示条目永不过期。 |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | 每个区域的命名数字格式（与 Vue I18n 兼容）。启用 `$tn(1000, 'currency')` 风格调用。 |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | 每个区域的命名日期时间格式（与 Vue I18n 的 `datetimeFormats` 兼容）。启用 `$td(date, 'short')` 风格调用。 |
| `httpCacheDuration` | `number` | `31536000` | 用于 `/\{apiBaseUrl\}/:page/:locale/data.json` 的 HTTP `Cache-Control` max-age（秒）。仅当 `dateBuild` 通过 `?v=...` 打破 URL 时完全生效（默认如此）：响应会是 `public, max-age=…, immutable`，对浏览器和 CDN 安全。 - `dateBuild: 0`/`''` — URL 稳定，该时长*不*生效；响应变为 `public, max-age=0, must-revalidate`。在从不变化的 URL 上设置长 `max-age` 会永久锁定浏览器首次看到的载荷。 - `0` — 完全不设置 `Cache-Control`（在本地调试中有用） - 在开发环境（`import.meta.dev`）中不应用，以免与浏览器缓存冲突干扰 HMR - 仅对通过 Nitro 提供的响应生效。复制到 `public/` 并由托管平台提供的载荷会使用该平台的头部 — 参见性能指南。 类似于 `@nuxtjs/i18n` 的实验性 `httpCacheDuration`（v10.2.0），但作为显式响应头，而非 Nitro `defineCachedEventHandler` 的 maxAge。 |
| `dateBuild` | `string \| number` | — | 用于翻译请求缓存破坏（`?v=...`）的值。未提供时，模块回退到 `Date.now()`（非确定性）。对于可复现/滚动部署，请将其设置为稳定值（例如 git SHA 或构建号）。 |
| `experimental` | `Record<string, unknown>` | — | 实验性 / 不稳定选项的容器。其内容可能在次要版本之间无预警地更改或移除。 |
