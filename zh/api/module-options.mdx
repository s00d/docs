本页列出了 `nuxt.config` 中 `i18n` 对象的每个键。使用表格查找类型或默认值，使用下方的详细说明查看示例和注意事项。类型、默认值和描述由 [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts) 中的 `ModuleOptions` 接口生成。

```ts nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
    ],
    defaultLocale: 'en',
  },
})
```

嵌套选项以点分路径显示：`translationPayloads.mode` 是 `translationPayloads` 的 `mode` 键。

## Locale 与路由 {#locales-and-routing}

存在哪些语言，以及它们如何出现在 URL 中。

| 选项 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | 支持的 locale 列表。每个条目定义一个 locale 代码以及可选的元数据（ISO、方向、显示名称等）。 |
| `strategy` | `Strategies` | `'prefix_except_default'` | locale 前缀的 URL 路由策略。- `'no_prefix'` — URL 中不包含 locale；locale 存储在 cookie 中。- `'prefix_except_default'` — 除默认 locale 外，所有 locale 都加前缀。- `'prefix'` — 始终加前缀，包括默认 locale。- `'prefix_and_default'` — 与 `prefix` 相同，但默认 locale 也可以不带前缀访问。 |
| `defaultLocale` | `string` | `'en'` | 当无法从 URL 或用户偏好中确定 locale 时使用的 locale。它不是翻译回退：翻译回退请设置 `fallbackLocale`。 |
| `localeCookie` | `string \| null` | `null` | 用于在会话之间持久保存用户 locale 偏好的 cookie 名称。设为 `null` 可禁用基于 cookie 的持久化。对于 `no_prefix` 策略，如果未提供则自动设为 `'user-locale'`；在 `i18n` 配置块中显式设置 `null` 也会使其在该策略下保持关闭。 |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `{}` | 全局路由级别的 locale 配置。可以在不修改组件的情况下，为特定页面限制或自定义 locale 路由。- `false` — 将该路由排除在本地化之外。- `Record<LocaleCode, string>` — 按 locale 自定义路径。 |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | 用于匹配 URL 片段中 locale 代码的自定义正则表达式（或其字符串源）。`locales` 中的每个 locale 代码都必须完整匹配该模式（不含其标志），否则构建会失败。 |
| `noPrefixRedirect` | `boolean` | `false` | 用于 `no_prefix` 策略：当默认 locale 为某个页面设置了自定义路径（`localeRoutes` / `globalLocaleRoutes`）时，将该页面的原始路径重定向到访问者 locale 的自定义路径，否则重定向到默认 locale 的自定义路径（例如 `/about` → `/about-us`）。自身没有自定义路径的 locale 保持在原始路径上。带有动态片段的页面不会被重定向。 |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | 要排除在 i18n 路由之外的路径：字符串表示路径前缀（`/admin` 涵盖 `/admin/x`）或 `*` / `?` 通配模式；RegExp 会针对路径进行测试。匹配的页面不会生成 locale 变体，不会进行 locale 重定向或返回 404，并会从预渲染中移除；它们仍然会使用翻译进行渲染。`/api`、`/_nuxt`、`/__*`、翻译路由和常见静态文件（sitemap、robots.txt、favicon、按扩展名识别的资源）始终会被排除。 |
| `routeLocales` | `Record<string, string[]>` | — | 按路由的 locale 限制，在构建时从 `$defineI18nRoute()` 调用中提取。将路由路径（例如 `'/about'`）映射到允许的 locale 代码数组。未列出的路由没有限制（允许所有 locale）。 |

## 翻译 {#translations}

翻译文件的存放位置以及键的解析方式。

| 选项 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | 包含翻译 JSON 文件的目录路径，相对于项目根目录。 |
| `disableWatcher` | `boolean` | `false` | 禁用在开发模式下自动创建缺失翻译文件的文件监听器。 |
| `routesLocaleLinks` | `{ [key: string]: string }` | `{}` | 将路由名称映射到其他路由名称，以共享相同的翻译文件。例如，`{ 'about-us': 'about' }` 表示 `about-us` 页面将使用 `about` 页面的翻译，而不是它自己的翻译。 |
| `plural` | `PluralFunc` | ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)`` | 自定义复数函数。接收 `(key, count, params, locale, getter)`，应以字符串形式返回所选的复数形式，或返回 `null`/`undefined` 以回退到内置的 `defaultPlural` 逻辑（因此你可以只覆盖部分 locale）。对于 Nuxt 模块，该函数会通过 `.toString()` 序列化到 `.nuxt/i18n.plural.mjs` 中——它必须是自包含的（不能有导入 / 外部作用域）。**不**支持文件路径字符串。 |
| `disablePageLocales` | `boolean` | `false` | 禁用按页面的翻译文件。为 `true` 时，只加载全局翻译（`{locale}.json`）；不会生成或加载页面专属文件（`pages/{page}/{locale}.json`）。 |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | 全局回退 locale 代码。某个 locale 中缺失的键会从该 locale 中获取（在构建或加载每个载荷时合并进去）；没有它时，缺失的键会渲染为键本身。 |

## 载荷与缓存 {#payloads-and-caching}

翻译如何到达浏览器。[性能](/zh/guide/performance)解释了这些选项在运行时会改变什么。

| 选项 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | 在 Nitro 全局中间件中预加载首页翻译（仅服务端，私有配置）。 |
| `apiBaseUrl` | `string` | `'_locales'` | 翻译 API 路由的基础 URL 路径片段（用于 SSR/SSG 数据获取）。也可以通过 `NUXT_I18N_APP_BASE_URL` 环境变量设置。 |
| `apiBaseClientHost` | `string` | `undefined` | 覆盖客户端翻译获取请求使用的主机。当客户端通过与 Nuxt 所见不同的主机名访问服务器时很有用。也可以通过 `NUXT_I18N_APP_BASE_CLIENT_HOST` 环境变量设置。 |
| `apiBaseServerHost` | `string` | `undefined` | 覆盖服务端翻译获取请求使用的主机。在服务器通过内部主机名访问自身的容器/微服务部署中很有用。也可以通过 `NUXT_I18N_APP_BASE_SERVER_HOST` 环境变量设置。 |
| `translationPayloads` | `TranslationPayloadOptions` | — | 控制翻译载荷的输出方式（Node 服务器：`public/<apiBaseUrl>`；Edge / 函数 / inline：Nitro `serverAssets`）。- **Node 服务器**（`node-server`、`node-cluster`、磁盘 `serveStatic`）：`serverAssets` 表示通过 `public/` 下的 `readFile` 进行本地 SSR（不使用 Rollup `raw:`）。- **Edge、函数预设以及 `serveStatic: "inline"`**（`vercel`、`netlify`、`aws-lambda`、winterjs 等）：`serverAssets` 会注册 Nitro `serverAssets`（`assets:i18n`），因为 SSR 无法在磁盘上访问 `public/`。不会强制生成 public 副本——如需 CDN/静态托管，请设置 `publicAssets: true`。常规的一体化部署请保留默认值。对于大型 Edge 目录，优先使用 `mode: 'source'`。对于基于 CDN 的部署，请禁用本地输出并设置 `apiBaseClientHost` / `apiBaseServerHost`。 |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | 翻译载荷策略。- `premerged`：构建时生成的 `{page}/{locale}/data.json` 矩阵（默认）- `source`：在运行时合并的紧凑源文件（在 Edge / 大型目录上优先使用） |
| `translationPayloads.serverAssets` | `boolean` | `true` | 本地 SSR 载荷：从磁盘提供 `public/` 的 Node 服务器读取该目录树（强制生成 public 副本）；Edge、函数预设和 `serveStatic: "inline"` 通过 Nitro `serverAssets` 嵌入。- **Node 服务器**（预设自身提供 `public/`，例如 `node-server`）：不使用 Nitro `serverAssets`（避免 Rollup `raw:`）。SSR 以 `{page}/{locale}/data.json` 的形式读取 `public/<apiBaseUrl\|publicDir>`；当此项为 `true` 时，即使 `publicAssets` 为 false 也会强制生成 public 副本。- **Edge、函数预设和 inline**（`nitro.node === false`，没有磁盘 `serveStatic`，如 `vercel` / `netlify` / `aws-lambda`，或 `serveStatic: "inline"`，例如 winterjs）：使用 Nitro `serverAssets`（`assets:i18n`），布局与 `mode` 相同。**不会**强制生成 public 副本——如需 CDN/静态托管，请设置 `publicAssets: true`。 |
| `translationPayloads.serverHandler` | `boolean` | `true` | 在 `/{apiBaseUrl}/:page/:locale/data.json` 注册内置服务端路由。当翻译载荷由外部主机/CDN 提供时禁用此项。 |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | 将载荷复制到 Nitro public 输出中。premerged → `apiBaseUrl` 下的 `{page}/{locale}/data.json`；source → 紧凑目录树。当 SSR 读取 `public/` 时（`node-server` 及类似预设），`serverAssets: true` 也会强制生成此副本。在 Edge / 函数 / `serveStatic: "inline"` 预设上，只有当此项为 `true` 时才会复制（SSR 使用 Nitro 嵌入）。 |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | 选择启用 Nitro 预渲染 `/{apiBaseUrl}/.../data.json`。当 premerged 的 `publicAssets` 已经写入这些文件时，通常是多余的。 |
| `translationPayloads.publicDir` | `string` | — | 相对于 Nitro public 根目录的 public 输出文件夹。默认为 `apiBaseUrl`（`_locales`）。这样静态文件与客户端获取的 URL（`/{apiBaseUrl}/{page}/{locale}/data.json`）一致。 |
| `translationPayloads.rootDelta` | `boolean` | `true` | 为每个 locale 写入一个根文件，并在每个页面文件中只写入与其不同的部分。客户端和 SSR 会将它们合并；在任何读取文件的地方，完整的块仍然可用。`false` 会在每个页面文件中保留完整字典。仅适用于 `premerged`，并且在 `disablePageLocales` 下关闭。 |
| `translationPayloads.warnFileCount` | `number` | `500` | 当生成的载荷文件数量超过此阈值时，在构建期间发出警告。 |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | 当生成的载荷总大小（字节）超过此阈值时，在构建期间发出警告。 |

## SEO {#seo}

为每个本地化页面生成的 meta 标签。

| 选项 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | 自动生成 SEO meta 标签（`hreflang`、`canonical`、`og:url`、`og:locale`）。 |
| `metaBaseUrl` | `string` | `undefined` | SEO meta 标签（canonical、og:url、hreflang）的基础 URL。- 具体的 URL 字符串（例如 `'https://example.com'`）——按原样使用（最高优先级）。- `undefined` — 当存在 `nuxt-site-config` 模块时回退到其 `site.url`，否则使用当前请求的 origin（服务端为 `useRequestURL().origin`，客户端为 `window.location.origin`）。 |
| `metaTrustForwardedHost` | `boolean` | `true` | 在解析 meta 标签的基础 URL 时信任 `X-Forwarded-Host` 请求头。当应用运行在会将此请求头设置为真实面向客户端主机名的反向代理（nginx、Cloudflare、AWS ALB 等）之后时启用。 |
| `metaTrustForwardedProto` | `boolean` | `true` | 在解析 meta 标签的协议时信任 `X-Forwarded-Proto` 请求头。当应用运行在终止 TLS 的代理之后时启用，这样即使应用本身监听 HTTP，canonical URL 也会使用 `https://`。 |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | 在 canonical 和 `og:url` meta 标签中保留的查询参数名称列表。不在此列表中的参数会从 canonical URL 中移除。 |

## 检测与重定向 {#detection-and-redirects}

为尚未选择 locale 的访问者选择 locale。

| 选项 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | 启用自动 locale 重定向（服务端插件和客户端路由中间件）。为 `true` 时，前缀类策略会将不带前缀的 URL 重定向到其本地化形式。locale 来自应用状态、cookie，或在 `autoDetectPath` 允许的情况下来自 `Accept-Language`，否则使用默认 locale。在 `no_prefix` 下，检测永远不会改变 URL（自定义路径请参见 `noPrefixRedirect`）。 |
| `autoDetectLanguage` | `boolean` | `true` | 从 `Accept-Language` HTTP 请求头自动检测用户的首选语言。与 `autoDetectPath` 配合使用，以决定何时进行检测。 |
| `autoDetectPath` | `string` | `'/'` | cookie / Accept-Language 偏好重定向可以在哪些位置执行（当启用 `redirects` 时）。- `'/'` — 仅 `/`（默认 locale 下的深层链接保持可访问；默认值）- `'no_prefix'` — 仅不带 locale 前缀的路径 - `'*'` — 所有路径，包括重写显式的 locale 前缀（例如当 cookie 偏好 `de` 时，`/fr/about` → `/de/about`）- 任何其他字符串 — 该路径，忽略末尾斜杠（例如 `'/welcome'`）在 `prefix` 下，允许路径之外的不带前缀 URL 仍会重定向到默认 locale 的形式（`/about` → `/en/about`）。在 `prefix_except_default` 下，带前缀的默认 locale（`/en`）返回 404，而不是重定向。 |

## 注册 {#registration}

可以关闭的模块组成部分。

| 选项 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | 在运行时提供 `$defineI18nRoute()`。无论如何，构建都会读取页面中的 `$defineI18nRoute()` 调用。 |
| `plugin` | `boolean` | `true` | 注册核心 i18n 插件，提供 `$t()`、`$tc()`、`$getLocale()`、`$switchLocale()` 以及其他运行时辅助函数。 |
| `hooks` | `boolean` | `true` | 在加载和导航时调用 `i18n:register` 应用钩子，以便插件可以添加翻译。 |
| `components` | `boolean` | `true` | 注册内置 i18n 组件（`<i18n-link>`、`<i18n-switcher>`、`<i18n-t>`、`<i18n-group>`）。设为 `false` 可禁用组件自动注册（例如当你不使用它们并希望减小模块占用时）。 |
| `types` | `boolean` | `true` | 根据默认 locale 文件中的翻译键，为 `useI18n`、`$t` 及相关辅助函数生成 TypeScript 类型声明。 |
| `debug` | `boolean` | `false` | 为 locale 检测、路由生成和翻译加载启用详细的调试日志。 |

## 其他 {#other}

| 选项 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `trustForwardedHost` | `boolean` | `false` | 根据 `X-Forwarded-Host` 而不是 `Host` 选择请求的域名（`locales[].baseUrl`）。仅在会覆盖该请求头的代理之后启用。 |
| `hreflangBaseLanguage` | `boolean` | `false` | 额外输出一个根据每个 locale 的 `iso` 派生的纯语言 `hreflang`（例如 `es-ES` → 同时输出 `es`）。`locales` 中第一个地区 locale 会占用该语言的纯语言标签。永远不会使用路由 `code`——只使用 `iso \|\| code`。 |
| `additionalTranslationDirs` | `string[]` | `[]` | 额外的目录（相对于项目根目录 / 每个 Nuxt 层的根目录），其顶层 `{locale}.json` 文件会在 `translationDir` 之前深度合并到全局字典中。合并顺序：按数组顺序依次合并每个条目（跨层），然后是 `translationDir`（冲突时优先）。只读取根目录的 `{locale}.json` 文件——这些目录下的 `pages/` 会被忽略。示例：`translationDir: 'frontend'`、`additionalTranslationDirs: ['common']` → 先 `common/en.json`，再 `frontend/en.json`。 |
| `vueDevtools` | `boolean` | `true` | 在开发环境中注册 Vue DevTools 检查器和时间线（浏览器扩展）。与 Nuxt DevTools 自定义标签页相互独立。 |
| `trailingSlash` | `'append' \| 'remove'` | `undefined (inherit from Nuxt)` | `$localePath` / `$switchLocalePath` 的末尾斜杠（与 NuxtLink 保持一致）。未设置时默认为 `experimental.defaults.nuxtLink.trailingSlash`。显式设置可为 i18n 路径辅助函数覆盖 Nuxt 的链接默认值。 |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | 添加到本地化路由名称前的前缀（例如 `'localized-index'`）。在内部用于区分原始路由与生成的 locale 变体。 |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | 按路由禁用 meta 标签。将路由名称或路径映射到 `true`（禁用所有 meta）或应禁用 meta 的 locale 代码数组。构建时在 `$defineI18nRoute()` 调用中找到的条目会被添加进来。 |
| `missingWarn` | `boolean` | `true` | 当翻译键缺失时显示控制台警告（开发构建，在浏览器中）。 |
| `hmr` | `boolean` | `true` | 在开发环境中为翻译文件启用热模块替换。为 `true` 时，对 JSON 翻译文件的更改会触发自动重新加载，而无需整页刷新。 |
| `cacheMaxSize` | `number` | `0` | 内存中翻译缓存的最大条目数。获取缓存和服务端缓存会淘汰最近最少使用的条目；浏览器的字典映射会淘汰最早的条目（FIFO）。`0` 表示浏览器中不限制；此时服务端缓存最多保留 1000 个条目，因此指向虚构页面的请求 URL 无法使服务器内存增长。 |
| `cacheTtl` | `number` | `0` | 获取缓存和服务端翻译缓存的存活时间（秒），从条目存储时开始计算（读取不会延长它），因此来自 `apiBaseServerHost` 的数据至少会以该频率刷新。浏览器中当前使用的字典不受其过期影响。`0` 表示条目永不过期。 |
| `cacheStorage` | `string` | — | Nitro 存储挂载的名称（`nitro.storage`，例如 `'redis'`），多个服务器实例将其作为共享字典缓存，在进程内缓存之后、数据源之前读取。主要在使用 `apiBaseServerHost` 时有收益：每个字典只需从后端获取一次，而不是每个实例一次。条目按构建作为键，并在 `cacheTtl` 后过期，当其为 `0` 时则在一天后过期。在开发环境和预渲染中关闭。存储失败时回退到数据源。未设置：没有共享缓存。 |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | 按 locale 的命名数字格式（与 Vue I18n 兼容）。支持 `$tn(1000, 'currency')` 风格的调用。 |
| `timeZone` | `string` | `the runtime's zone` | 用于 `$td` 和 `<i18n-t date>` 的 IANA 时区（`Europe/Berlin`）。设置它可以在服务器和每个浏览器中渲染相同的日期；命名格式自身的 `timeZone` 优先。 |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | 按 locale 的命名日期时间格式（与 Vue I18n 的 `datetimeFormats` 兼容）。支持 `$td(date, 'short')` 风格的调用。 |
| `httpCacheDuration` | `number` | `31536000` | `/{apiBaseUrl}/:page/:locale/data.json` 的 HTTP `Cache-Control` max-age（秒）。只有当 `dateBuild` 使 URL 失效（`?v=...`）时才完全生效，这也是默认情况：此时响应为 `private, max-age=…, immutable`：浏览器会固定缓存它，而忽略查询参数的 CDN 则不能（使用 `httpCacheControl: false` 时为 `public`）。- `dateBuild: 0`/`''` — URL 是稳定的，因此*不会*遵循该时长；响应改为 `public, max-age=0, must-revalidate`。在不变的 URL 上设置较长的 `max-age` 会让浏览器固定缓存它见到的第一个载荷。- `0` — 完全不设置 `Cache-Control`（在本地调试时很有用）- 在开发环境（`import.meta.dev`）中不生效，以免浏览器缓存干扰 HMR - 只影响通过 Nitro 提供的响应。复制到 `public/` 并由托管平台提供的载荷使用该平台的响应头——参见性能指南。类似于 `@nuxtjs/i18n` 的实验性 `httpCacheDuration`（v10.2.0），但以显式响应头实现，而不是 Nitro `defineCachedEventHandler` 的 maxAge。 |
| `httpCacheControl` | `string \| false` | `'public, max-age=60'` | 由主机或路径级规则响应的载荷文件的 `Cache-Control`，这些响应无法识别 `?v=`。在 Node 服务器上，对当前 `?v=` 的响应会被固定缓存 `httpCacheDuration`，其他响应则重新验证；在使用 `source`、`cacheTtl` 或 `apiBaseServerHost` 时（字典会在不重新构建的情况下变化），每个响应都使用此响应头。`false` 会让每个文件保持 `max-age=0, must-revalidate`。 |
| `dateBuild` | `string \| number` | — | 用于翻译请求缓存失效的值（`?v=...`）。未提供时，模块使用翻译文件的哈希值，因此只有翻译变化时该值才会改变（无法计算哈希时使用 `Date.now()`）。`0` 或 `''` 会关闭缓存失效。设置一个稳定的值（git SHA、构建号）可自行固定它。`NUXT_I18N_DATE_BUILD` 或 `runtimeConfig.public.i18nRuntime.dateBuild` 会在运行时替换它，适用于字典被原地替换之后：无需重新构建即可抛弃已固定的 URL。 |
| `experimental` | `Record<string, unknown>` | — | 实验性/不稳定选项的容器。其内容可能在次要版本之间更改或移除，恕不另行通知。 |

## 选项详情 {#option-details}

除表格内容外没有更多补充的选项不在此重复。

### Locale 与 URL {#locales-and-urls}

#### `locales` {#locales}

**类型** `Locale[]` · **默认值** `[]`

支持的 locale 列表。
每个条目定义一个 locale 代码以及可选的元数据（ISO、方向、显示名称等）。

每个条目都是一个 `Locale` 对象：

| 属性 | 类型 | 描述 |
| --- | --- | --- |
| `code` | `string` | **必需。** URL 片段和文件名（`en`、`de-at`）。 |
| `iso` | `string` | 用于 `<html lang>`、`hreflang`、复数以及 `$tn` / `$td` / `$tdr` 的 BCP-47 标签（`en-US`）。 |
| `displayName` | `string` | 在 `<i18n-switcher>` 和 `$getLocaleName()` 中显示的标签。 |
| `dir` | `'ltr' \| 'rtl' \| 'auto'` | `<html dir>`。未设置时，已知的 RTL 语言会得到 `rtl`，其他所有 locale 都不设置该属性。参见 [SEO](/zh/guide/seo#text-direction)。 |
| `disabled` | `boolean` | 从路由、载荷和切换中排除。其前缀返回 404，指向它的链接会停留在当前页面。 |
| `fallbackLocale` | `string` | 该 locale 的回退 locale；覆盖全局 `fallbackLocale`。 |
| `seo` | `boolean` | `false` 会将该 locale 排除在 `hreflang` 和 `og:locale:alternate` 之外。 |
| `og` | `string` | `og:locale` 的值（`ar_AE`）；默认：由 `iso` 转换而来。 |
| `baseUrl` | `string` | 该 locale 自己的域名：由同一个构建提供服务，从其他域名指向它的链接为绝对地址。 |
| `baseDefault` | `boolean` | 与 `baseUrl` 一起使用：作为其主机的默认 locale，指向它的链接不带 `/<code>` 前缀（`prefix` 策略下保留前缀）。 |

其他属性会被保留，并由 `$getLocales()` 返回。通过扩展 `Locale` 为它们添加类型：

```ts
// i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
  }
}
export {}
```

模块会提升 `@i18n-micro/types`，因此在 pnpm 下无需安装该包即可使用。

#### `defaultLocale` {#defaultlocale}

**类型** `string` · **默认值** `'en'`

当无法从 URL 或用户偏好中确定 locale 时使用的 locale。
它不是翻译回退：翻译回退请设置 `fallbackLocale`。

#### `strategy` {#strategy}

**类型** `Strategies` · **默认值** `'prefix_except_default'`

locale 前缀的 URL 路由策略。

- `'no_prefix'` — URL 中不包含 locale；locale 存储在 cookie 中。
- `'prefix_except_default'` — 除默认 locale 外，所有 locale 都加前缀。
- `'prefix'` — 始终加前缀，包括默认 locale。
- `'prefix_and_default'` — 与 `prefix` 相同，但默认 locale 也可以不带前缀访问。

各策略对应的 URL 及重定向：[路由策略](/zh/guide/strategy)。

#### `globalLocaleRoutes` {#globallocaleroutes}

**类型** `GlobalLocaleRoutes` · **默认值** `{}`

全局路由级别的 locale 配置。
可以在不修改组件的情况下，为特定页面限制或自定义 locale 路由。

- `false` — 将该路由排除在本地化之外。
- `Record<LocaleCode, string>` — 按 locale 自定义路径。

键为路由名称或路径。通常使用 [`$defineI18nRoute`](/zh/guide/per-component-translations) 按页面设置。

```ts
globalLocaleRoutes: {
  about: { en: '/about-us', de: '/ueber-uns' },
  'admin-dashboard': false, // not localized
}
```

详细说明、动态片段以及 `pages:extend` 路由：[本地化路径](/zh/guide/custom-locale-routes)。

#### `routeLocales` {#routelocales}

**类型** `Record<string, string[]>` · **默认值** —

按路由的 locale 限制，在构建时从 `$defineI18nRoute()` 调用中提取。
将路由路径（例如 `'/about'`）映射到允许的 locale 代码数组。
未列出的路由没有限制（允许所有 locale）。

#### `routeDisableMeta` {#routedisablemeta}

**类型** `Record<string, boolean \| string[]>` · **默认值** —

按路由禁用 meta 标签。将路由名称或路径映射到 `true`（禁用所有 meta）或应禁用 meta 的
locale 代码数组。构建时在 `$defineI18nRoute()` 调用中找到的条目会被添加进来。

#### `customRegexMatcher` {#customregexmatcher}

**类型** `string \| RegExp` · **默认值** `undefined (uses built-in pattern based on locale codes)`

用于匹配 URL 片段中 locale 代码的自定义正则表达式（或其字符串源）。
`locales` 中的每个 locale 代码都必须完整匹配该模式（不含其标志），否则构建会失败。

```ts
customRegexMatcher: '[a-z]{2}-[a-z]{2}', // en-us, de-at
```

#### `excludePatterns` {#excludepatterns}

**类型** `(string \| RegExp)[]` · **默认值** `undefined`

要排除在 i18n 路由之外的路径：字符串表示路径前缀（`/admin` 涵盖 `/admin/x`）
或 `*` / `?` 通配模式；RegExp 会针对路径进行测试。匹配的页面不会生成 locale
变体，不会进行 locale 重定向或返回 404，并会从预渲染中移除；它们仍然会使用
翻译进行渲染。`/api`、`/_nuxt`、`/__*`、翻译路由和常见静态文件
（sitemap、robots.txt、favicon、按扩展名识别的资源）始终会被排除。

```ts
excludePatterns: ['/admin', '/docs/*', /^\/preview\//],
```

更多内容：[排除路径](/zh/guide/excluding-static-files)。

#### `localizedRouteNamePrefix` {#localizedroutenameprefix}

**类型** `string` · **默认值** `'localized-'`

添加到本地化路由名称前的前缀（例如 `'localized-index'`）。
在内部用于区分原始路由与生成的 locale 变体。

#### `trailingSlash` {#trailingslash}

**类型** `'append' \| 'remove'` · **默认值** `undefined (inherit from Nuxt)`

`$localePath` / `$switchLocalePath` 的末尾斜杠（与 NuxtLink 保持一致）。
未设置时默认为 `experimental.defaults.nuxtLink.trailingSlash`。
显式设置可为 i18n 路径辅助函数覆盖 Nuxt 的链接默认值。

### 翻译 {#translations}

#### `translationDir` {#translationdir}

**类型** `string` · **默认值** `'locales'`

包含翻译 JSON 文件的目录路径，相对于项目根目录。

相对于每个层的根目录，而不是 `app/`（Nuxt 4 目录结构下为 `'app/locales'`）。文件布局：[翻译文件](/zh/guide/translations)。

#### `additionalTranslationDirs` {#additionaltranslationdirs}

**类型** `string[]` · **默认值** `[]`

额外的目录（相对于项目根目录 / 每个 Nuxt 层的根目录），其顶层
`{locale}.json` 文件会在 `translationDir` 之前深度合并到全局字典中。

合并顺序：按数组顺序依次合并每个条目（跨层），然后是 `translationDir`（冲突时优先）。
只读取根目录的 `{locale}.json` 文件——这些目录下的 `pages/` 会被忽略。

示例：`translationDir: 'frontend'`、`additionalTranslationDirs: ['common']` → 先 `common/en.json`，再 `frontend/en.json`。

#### `disablePageLocales` {#disablepagelocales}

**类型** `boolean` · **默认值** `false`

禁用按页面的翻译文件。
为 `true` 时，只加载全局翻译（`{locale}.json`）；
不会生成或加载页面专属文件（`pages/{page}/{locale}.json`）。

#### `fallbackLocale` {#fallbacklocale}

**类型** `string` · **默认值** `undefined (no fallback; returns the raw key)`

全局回退 locale 代码。
某个 locale 中缺失的键会从该 locale 中获取（在构建或加载每个载荷时
合并进去）；没有它时，缺失的键会渲染为键本身。

#### `routesLocaleLinks` {#routeslocalelinks}

**类型** `{ [key: string]: string }` · **默认值** `{}`

将路由名称映射到其他路由名称，以共享相同的翻译文件。
例如，`{ 'about-us': 'about' }` 表示 `about-us` 页面将使用
`about` 页面的翻译，而不是它自己的翻译。

```ts
routesLocaleLinks: { 'products-id': 'products' },
```

#### `plural` {#plural}

**类型** `PluralFunc` · **默认值** ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)``

自定义复数函数。
接收 `(key, count, params, locale, getter)`，应以字符串形式返回所选的
复数形式，或返回 `null`/`undefined` 以回退到内置的
`defaultPlural` 逻辑（因此你可以只覆盖部分 locale）。

对于 Nuxt 模块，该函数会通过 `.toString()` 序列化到
`.nuxt/i18n.plural.mjs` 中——它必须是自包含的（不能有导入 / 外部作用域）。
**不**支持文件路径字符串。

内置规则及其 `=0 ` 标记在 [`$tc`](/zh/api/methods#$tc) 中有说明。你的函数会在其能够给出结果的情况下替代内置规则，接收保留任何标记的原始值，返回 `null` 则将调用交还给内置规则。该函数接收 `(key, count, params, locale, getter)`；`getter(key)` 返回包含所有形式的原始字符串。请将其写成自包含的 `function` 或箭头函数表达式（不能使用方法简写、导入或外部变量）：

```ts
plural: function (key, count, params, locale, getter) {
  if (!locale.startsWith('en')) return null // built-in rule for other locales
  const forms = String(getter(key) ?? '').split('|').map((form) => form.trim())
  const index = count === 0 ? 0 : count === 1 ? 1 : 2
  return (forms[Math.min(index, forms.length - 1)] ?? '').replace('{count}', String(count))
},
```

```json
{ "apples": "no apples | one apple | {count} apples" }
```

#### `numberFormats` {#numberformats}

**类型** `Record<string, Record<string, Intl.NumberFormatOptions>>` · **默认值** —

按 locale 的命名数字格式（与 Vue I18n 兼容）。
支持 `$tn(1000, 'currency')` 风格的调用。

由 [`$tn`](/zh/api/methods#$tn) 使用。

#### `datetimeFormats` {#datetimeformats}

**类型** `Record<string, Record<string, Intl.DateTimeFormatOptions>>` · **默认值** —

按 locale 的命名日期时间格式（与 Vue I18n 的 `datetimeFormats` 兼容）。
支持 `$td(date, 'short')` 风格的调用。

由 [`$td`](/zh/api/methods#$td) 使用。

#### `timeZone` {#timezone}

**类型** `string` · **默认值** `the runtime's zone`

用于 `$td` 和 `<i18n-t date>` 的 IANA 时区（`Europe/Berlin`）。设置它可以在服务器和
每个浏览器中渲染相同的日期；命名格式自身的 `timeZone` 优先。

#### `disableWatcher` {#disablewatcher}

**类型** `boolean` · **默认值** `false`

禁用在开发模式下自动创建缺失翻译文件的文件监听器。

#### `missingWarn` {#missingwarn}

**类型** `boolean` · **默认值** `true`

当翻译键缺失时显示控制台警告（开发构建，在浏览器中）。

如果要上报缺失的键，请使用 [`$setMissingHandler`](/zh/api/methods#$setmissinghandler)。

### 载荷与缓存 {#payloads-and-caching}

#### `translationPayloads` {#translationpayloads}

**类型** `TranslationPayloadOptions` · **默认值** —

控制翻译载荷的输出方式（Node 服务器：`public/<apiBaseUrl>`；Edge / 函数 / inline：Nitro `serverAssets`）。

- **Node 服务器**（`node-server`、`node-cluster`、磁盘 `serveStatic`）：`serverAssets` 表示通过 `public/` 下的 `readFile` 进行本地 SSR（不使用 Rollup `raw:`）。
- **Edge、函数预设以及 `serveStatic: "inline"`**（`vercel`、`netlify`、`aws-lambda`、winterjs 等）：`serverAssets` 会注册 Nitro `serverAssets`（`assets:i18n`），
  因为 SSR 无法在磁盘上访问 `public/`。不会强制生成 public 副本——如需 CDN/静态托管，请设置 `publicAssets: true`。

常规的一体化部署请保留默认值。对于大型 Edge 目录，优先使用 `mode: 'source'`。
对于基于 CDN 的部署，请禁用本地输出并设置 `apiBaseClientHost` / `apiBaseServerHost`。

子选项见[载荷与缓存](#payloads-and-caching)表格。哪种组合适合 Node、serverless、Edge、静态托管或 CDN：[部署](/zh/guide/deployment)。

#### `apiBaseUrl` {#apibaseurl}

**类型** `string` · **默认值** `'_locales'`

翻译 API 路由的基础 URL 路径片段（用于 SSR/SSG 数据获取）。
也可以通过 `NUXT_I18N_APP_BASE_URL` 环境变量设置。

载荷 URL 为 `/{apiBaseUrl}/{page}/{locale}/data.json`。

#### `apiBaseClientHost` {#apibaseclienthost}

**类型** `string` · **默认值** `undefined`

覆盖客户端翻译获取请求使用的主机。
当客户端通过与 Nuxt 所见不同的主机名访问服务器时很有用。
也可以通过 `NUXT_I18N_APP_BASE_CLIENT_HOST` 环境变量设置。

#### `apiBaseServerHost` {#apibaseserverhost}

**类型** `string` · **默认值** `undefined`

覆盖服务端翻译获取请求使用的主机。
在服务器通过内部主机名访问自身的容器/微服务部署中很有用。
也可以通过 `NUXT_I18N_APP_BASE_SERVER_HOST` 环境变量设置。

主机必须提供与内置路由相同的 `/{apiBaseUrl}/{page}/{locale}/data.json` 响应。

#### `dateBuild` {#datebuild}

**类型** `string \| number` · **默认值** —

用于翻译请求缓存失效的值（`?v=...`）。

未提供时，模块使用翻译文件的哈希值，因此只有翻译变化时
该值才会改变（无法计算哈希时使用 `Date.now()`）。`0` 或 `''` 会关闭
缓存失效。设置一个稳定的值（git SHA、构建号）可自行固定它。
`NUXT_I18N_DATE_BUILD` 或 `runtimeConfig.public.i18nRuntime.dateBuild` 会在运行时替换它，适用于字典
被原地替换之后：无需重新构建即可抛弃已固定的 URL。

#### `httpCacheDuration` {#httpcacheduration}

**类型** `number` · **默认值** `31536000`

`/{apiBaseUrl}/:page/:locale/data.json` 的 HTTP `Cache-Control` max-age（秒）。

只有当 `dateBuild` 使 URL 失效（`?v=...`）时才完全生效，这也是默认情况：
此时响应为 `private, max-age=…, immutable`：浏览器会固定缓存它，而忽略查询参数的 CDN 则不能
（使用 `httpCacheControl: false` 时为 `public`）。

- `dateBuild: 0`/`''` — URL 是稳定的，因此*不会*遵循该时长；
  响应改为 `public, max-age=0, must-revalidate`。在不变的 URL 上设置较长的 `max-age`
  会让浏览器固定缓存它见到的第一个载荷。

- `0` — 完全不设置 `Cache-Control`（在本地调试时很有用）
- 在开发环境（`import.meta.dev`）中不生效，以免浏览器缓存干扰 HMR
- 只影响通过 Nitro 提供的响应。复制到 `public/` 并由托管平台提供的
  载荷使用该平台的响应头——参见性能指南。

类似于 `@nuxtjs/i18n` 的实验性 `httpCacheDuration`（v10.2.0），但以
显式响应头实现，而不是 Nitro `defineCachedEventHandler` 的 maxAge。

#### `cacheMaxSize` {#cachemaxsize}

**类型** `number` · **默认值** `0`

内存中翻译缓存的最大条目数。获取缓存和服务端缓存
会淘汰最近最少使用的条目；浏览器的字典映射会淘汰最早的条目（FIFO）。
`0` 表示浏览器中不限制；此时服务端缓存最多保留 1000 个条目，因此指向
虚构页面的请求 URL 无法使服务器内存增长。

#### `cacheTtl` {#cachettl}

**类型** `number` · **默认值** `0`

获取缓存和服务端翻译缓存的存活时间（秒），从条目
存储时开始计算（读取不会延长它），因此来自 `apiBaseServerHost` 的数据至少会以
该频率刷新。浏览器中当前使用的字典不受其过期影响。`0` 表示条目
永不过期。

两者在运行时会改变什么：[性能](/zh/guide/performance)。

#### `serverTranslationPreload` {#servertranslationpreload}

**类型** `boolean` · **默认值** `false`

在 Nitro 全局中间件中预加载首页翻译（仅服务端，私有配置）。

### SEO {#seo}

#### `meta` {#meta}

**类型** `boolean` · **默认值** `true`

自动生成 SEO meta 标签（`hreflang`、`canonical`、`og:url`、`og:locale`）。

按页面覆盖：[`useI18nHead`](/zh/composables/useI18nHead)。其他所有内容：[SEO](/zh/guide/seo)。

#### `metaBaseUrl` {#metabaseurl}

**类型** `string` · **默认值** `undefined`

SEO meta 标签（canonical、og:url、hreflang）的基础 URL。

- 具体的 URL 字符串（例如 `'https://example.com'`）——按原样使用（最高优先级）。
- `undefined` — 当存在 `nuxt-site-config` 模块时回退到其 `site.url`，
  否则使用当前请求的 origin
  （服务端为 `useRequestURL().origin`，客户端为 `window.location.origin`）。

#### `metaTrustForwardedHost` {#metatrustforwardedhost}

**类型** `boolean` · **默认值** `true`

在解析 meta 标签的基础 URL 时信任 `X-Forwarded-Host` 请求头。
当应用运行在会将此请求头设置为真实面向客户端主机名的
反向代理（nginx、Cloudflare、AWS ALB 等）之后时启用。

仅当 `metaBaseUrl` 和 `site.url` 都未设置时才会读取。当应用可以在没有覆盖该请求头的代理的情况下被访问时，请将其设为 `false`：否则客户端可以决定你的 canonical URL 中的主机。

#### `metaTrustForwardedProto` {#metatrustforwardedproto}

**类型** `boolean` · **默认值** `true`

在解析 meta 标签的协议时信任 `X-Forwarded-Proto` 请求头。
当应用运行在终止 TLS 的代理之后时启用，这样即使应用本身监听 HTTP，
canonical URL 也会使用 `https://`。

作用范围与 `metaTrustForwardedHost` 相同。

#### `trustForwardedHost` {#trustforwardedhost}

**类型** `boolean` · **默认值** `false`

根据 `X-Forwarded-Host` 而不是 `Host` 选择请求的域名（`locales[].baseUrl`）。
仅在会覆盖该请求头的代理之后启用。

与 `metaTrustForwardedHost` 相互独立，且默认关闭：在这里，该请求头会选择另一个域名的 locale，而不仅仅是标签的 origin。参见[层与域名](/zh/guide/layers#multiple-domains)。

#### `hreflangBaseLanguage` {#hreflangbaselanguage}

**类型** `boolean` · **默认值** `false`

额外输出一个根据每个 locale 的 `iso` 派生的纯语言 `hreflang`
（例如 `es-ES` → 同时输出 `es`）。`locales` 中第一个地区 locale 会占用
该语言的纯语言标签。永远不会使用路由 `code`——只使用 `iso || code`。

#### `canonicalQueryWhitelist` {#canonicalquerywhitelist}

**类型** `string[]` · **默认值** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

在 canonical 和 `og:url` meta 标签中保留的查询参数名称列表。
不在此列表中的参数会从 canonical URL 中移除。

### 检测与重定向 {#detection-and-redirects}

这些选项所服务的规则：[Locale 检测](/zh/guide/locale-detection)。

#### `redirects` {#redirects}

**类型** `boolean` · **默认值** `true`

启用自动 locale 重定向（服务端插件和客户端路由中间件）。
为 `true` 时，前缀类策略会将不带前缀的 URL 重定向到其本地化形式。locale
来自应用状态、cookie，或在 `autoDetectPath` 允许的情况下来自 `Accept-Language`，否则
使用默认 locale。在 `no_prefix` 下，检测永远不会改变 URL（自定义路径请参见 `noPrefixRedirect`）。

设为 `false` 时，不会注册客户端重定向中间件。服务端插件仍会对无效的 locale URL 返回 404，并为带前缀的 URL 写入 cookie。

#### `autoDetectLanguage` {#autodetectlanguage}

**类型** `boolean` · **默认值** `true`

从 `Accept-Language` HTTP 请求头自动检测用户的首选语言。
与 `autoDetectPath` 配合使用，以决定何时进行检测。

#### `autoDetectPath` {#autodetectpath}

**类型** `string` · **默认值** `'/'`

cookie / Accept-Language 偏好重定向可以在哪些位置执行（当启用 `redirects` 时）。

- `'/'` — 仅 `/`（默认 locale 下的深层链接保持可访问；默认值）
- `'no_prefix'` — 仅不带 locale 前缀的路径
- `'*'` — 所有路径，包括重写显式的 locale 前缀
  （例如当 cookie 偏好 `de` 时，`/fr/about` → `/de/about`）

- 任何其他字符串 — 该路径，忽略末尾斜杠（例如 `'/welcome'`）

在 `prefix` 下，允许路径之外的不带前缀 URL 仍会重定向到默认
locale 的形式（`/about` → `/en/about`）。在 `prefix_except_default` 下，
带前缀的默认 locale（`/en`）返回 404，而不是重定向。

#### `localeCookie` {#localecookie}

**类型** `string \| null` · **默认值** `null`

用于在会话之间持久保存用户 locale 偏好的 cookie 名称。
设为 `null` 可禁用基于 cookie 的持久化。
对于 `no_prefix` 策略，如果未提供则自动设为 `'user-locale'`；在 `i18n` 配置块中显式设置
`null` 也会使其在该策略下保持关闭。

没有 cookie 时，`Accept-Language` 仍然会驱动重定向；cookie 会在多次访问之间记住用户的选择。

#### `noPrefixRedirect` {#noprefixredirect}

**类型** `boolean` · **默认值** `false`

用于 `no_prefix` 策略：当默认 locale 为某个页面设置了自定义路径
（`localeRoutes` / `globalLocaleRoutes`）时，将该页面的原始路径重定向到访问者 locale 的
自定义路径，否则重定向到默认 locale 的自定义路径（例如 `/about` → `/about-us`）。
自身没有自定义路径的 locale 保持在原始路径上。带有动态
片段的页面不会被重定向。

### 注册与开发 {#registration-and-development}

#### `plugin` {#plugin}

**类型** `boolean` · **默认值** `true`

注册核心 i18n 插件，提供 `$t()`、`$tc()`、`$getLocale()`、
`$switchLocale()` 以及其他运行时辅助函数。

#### `define` {#define}

**类型** `boolean` · **默认值** `true`

在运行时提供 `$defineI18nRoute()`。无论如何，构建都会读取页面中的
`$defineI18nRoute()` 调用。

#### `hooks` {#hooks}

**类型** `boolean` · **默认值** `true`

在加载和导航时调用 `i18n:register` 应用钩子，以便插件可以添加翻译。

参见[钩子](/zh/api/events)。

#### `components` {#components}

**类型** `boolean` · **默认值** `true`

注册内置 i18n 组件（`<i18n-link>`、`<i18n-switcher>`、`<i18n-t>`、`<i18n-group>`）。
设为 `false` 可禁用组件自动注册（例如当你不使用它们
并希望减小模块占用时）。

#### `types` {#types}

**类型** `boolean` · **默认值** `true`

根据默认 locale 文件中的翻译键，为 `useI18n`、`$t` 及相关辅助函数
生成 TypeScript 类型声明。

与 [`@i18n-micro/types-generator`](/zh/integrations/types-generator) 包相互独立。

#### `hmr` {#hmr}

**类型** `boolean` · **默认值** `true`

在开发环境中为翻译文件启用热模块替换。
为 `true` 时，对 JSON 翻译文件的更改会触发自动重新加载，
而无需整页刷新。

#### `debug` {#debug}

**类型** `boolean` · **默认值** `false`

为 locale 检测、路由生成和翻译加载启用详细的调试日志。

#### `vueDevtools` {#vuedevtools}

**类型** `boolean` · **默认值** `true`

在开发环境中注册 Vue DevTools 检查器和时间线（浏览器扩展）。
与 Nuxt DevTools 自定义标签页相互独立。

#### `experimental` {#experimental}

**类型** `Record<string, unknown>` · **默认值** —

实验性/不稳定选项的容器。
其内容可能在次要版本之间更改或移除，恕不另行通知。
