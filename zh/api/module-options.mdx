# 模块选项参考

`nuxt-i18n-micro` 接受的所有选项均在构建期从 [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts) 中的 `ModuleOptions` 接口读取。本页内容全部由脚本生成，因此不会落后于代码本身——类型、默认值和描述都来自声明本身。

若想理解这些选项的**含义**——哪些组合合理、切换策略后会有哪些变化、以及具体示例——请阅读[配置](/guides/configuration)。本页是详尽的选项清单，那里则是解释。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

嵌套选项以点号分隔的路径展示，因此 `translationPayloads.mode` 表示 `translationPayloads` 对象里的 `mode` 键。

## 语言与路由

存在哪些语言以及它们在 URL 中如何呈现。

| 选项 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | 支持的语言列表。每一项定义一个语言代码，并可附带可选元数据（ISO、书写方向、显示名称等）。 |
| `strategy` | `Strategies` | `'prefix_except_default'` | 语言前缀的 URL 路由策略。 - `'no_prefix'`——URL 中不包含语言前缀；语言存储在 cookie 中。 - `'prefix_except_default'`——除默认语言外的所有语言都加前缀。 - `'prefix'`——始终加前缀，包括默认语言。 - `'prefix_and_default'`——与 `prefix` 类似，但默认语言也可以在无前缀的情况下访问。 |
| `defaultLocale` | `string` | `'en'` | 当无法从 URL 或用户偏好确定语言时使用的语言。当未设置 `fallbackLocale` 时，也用作缺失翻译的回退语言。 |
| `localeCookie` | `string \| null` | `null` | 用于跨会话持久化用户语言偏好的 cookie 名称。设置为 `null` 可禁用基于 cookie 的持久化。若未提供，`no_prefix` 策略会自动使用 `'user-locale'`。 |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | 全局的路由级语言配置。允许在不修改组件的情况下为特定页面限制或自定义语言路由。 - `false`——将该路由从本地化中排除。 - `Record<LocaleCode, string>`——按语言指定的自定义路径。 |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | 用于匹配 URL 片段中语言代码的自定义正则表达式（或其字符串形式）。`locales` 中定义的所有语言代码都必须匹配此模式，否则会输出警告。 |
| `noPrefixRedirect` | `boolean` | `false` | 用于 `no_prefix` 策略：启用后会将带语言前缀的 URL（例如 `/en/about`）重定向到不带前缀的版本（`/about`）。 |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | 完全排除在 i18n 处理之外的 URL 模式（字符串或正则）。匹配的路由不会带语言前缀，也不会进行重定向或加载翻译。Nuxt 的内部路径（`/__nuxt_error` 等）会自动始终排除。 |
| `routeLocales` | `Record<string, string[]>` | — | 从 `defineI18nRoute()` 调用中提取的按路由的语言限制。将路由路径（例如 `'/about'`）映射到允许的语言代码数组。未列出的路由不受限制（所有语言均可）。 |

## 翻译

翻译文件的存放位置以及键的解析方式。

| 选项 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | 存放翻译 JSON 文件的目录路径，相对于项目根目录。 |
| `disableWatcher` | `boolean` | `false` | 禁用开发模式下自动创建缺失翻译文件的文件监听器。 |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | 将路由名映射到其他路由名，以共享同一份翻译文件。例如 `\{ 'about-us': 'about' \}` 表示 `about-us` 页面会使用 `about` 页面的翻译，而不是自己的翻译。 |
| `plural` | `PluralFunc` | `built-in pluralization (form index by count)` | 自定义复数函数。接收 `(key, count, params, locale, getter)` 并返回选中的复数形式字符串，或返回 `null`/`undefined` 以回退到内置的 `defaultPlural` 逻辑（这样你只需覆盖某些语言）。对于 Nuxt 模块，该函数会通过 `.toString()` 序列化到 `.nuxt/i18n.plural.mjs`——它必须是自包含的（不能引入导入或外部作用域）。**不支持**通过文件路径字符串传入。 |
| `disablePageLocales` | `boolean` | `false` | 禁用按页面的翻译文件。设为 `true` 时只加载全局翻译（`\{locale\}.json`）；不会生成或加载按页面的文件（`pages/\{page\}/\{locale\}.json`）。 |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | 全局回退语言代码。当活跃语言中缺失某个键时，模块会先在此语言中查找，然后再返回键本身。 |

## Payload 与缓存

翻译如何抵达浏览器。[性能](/guides/performance)一节解释了这些选项在运行时的差异。

| 选项 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | 在 Nitro 全局中间件中预加载首页翻译（仅服务端，属于私有配置）。 |
| `apiBaseUrl` | `string` | `'_locales'` | 翻译 API 路由使用的基础 URL 段（SSR/SSG 数据获取会用到）。也可通过 `NUXT_I18N_APP_BASE_URL` 环境变量设置。 |
| `apiBaseClientHost` | `string` | `undefined` | 覆盖客户端翻译请求所用的 host。当客户端访问服务器时使用的主机名与 Nuxt 看到的不同时非常有用。也可通过 `NUXT_I18N_APP_BASE_CLIENT_HOST` 环境变量设置。 |
| `apiBaseServerHost` | `string` | `undefined` | 覆盖服务端翻译请求所用的 host。在容器/微服务架构中，当服务端通过内部主机名访问自身时非常有用。也可通过 `NUXT_I18N_APP_BASE_SERVER_HOST` 环境变量设置。 |
| `translationPayloads` | `TranslationPayloadOptions` | — | 控制翻译 payload 的产出方式（Node：`public/<apiBaseUrl>`；Edge：Nitro `serverAssets`）。 - **Node**：`serverAssets` 表示通过 `readFile` 从 `public/` 进行本地 SSR（不使用 Rollup `raw:`）。 - **Edge**：`serverAssets` 会注册 Nitro 的 `serverAssets`（`assets:i18n`），但并不会强制产出 public 副本。 常规一体化配置保持默认值即可。Edge 上目录较大时建议使用 `mode: 'source'`。CDN 部署时可关闭本地产物，并设置 `apiBaseClientHost` / `apiBaseServerHost`。 |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | 翻译 payload 策略。 - `premerged`：构建期产出 `\{page\}/\{locale\}/data.json` 矩阵（默认） - `source`：保留精简源文件并在运行时合并（Edge / 大型目录推荐） |
| `translationPayloads.serverAssets` | `boolean` | `true` | 本地 SSR payload：Node 从 `public/<apiBaseUrl>` 读取（强制产出 public 副本）；Edge 则通过 Nitro `serverAssets` 嵌入。 - **Node**：不使用 Nitro `serverAssets`（避免 Rollup `raw:`）。SSR 从 `public/<apiBaseUrl\|publicDir>` 读取 `\{page\}/\{locale\}/data.json`；当该值为 `true` 时，即使 `publicAssets` 为 false 也会强制产出 public 副本。 - **Edge**（`nitro.node === false`）：注册 Nitro `serverAssets`（`assets:i18n`），布局与 `mode` 一致。**不会**强制产出 public 副本——若要走 CDN，请设置 `publicAssets: true`。 |
| `translationPayloads.serverHandler` | `boolean` | `true` | 注册内置的服务器路由 `/\{apiBaseUrl\}/:page/:locale/data.json`。当翻译 payload 来自外部 host/CDN 时，请将其关闭。 |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | 是否把 payload 拷贝进 Nitro 的 public 产物目录。Premerged → `apiBaseUrl` 下的 `\{page\}/\{locale\}/data.json`；source → 精简源码树。在 Node 上，当 `serverAssets` 强制产出 public 副本时，这也是 SSR 的数据源。 |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | 主动让 Nitro 预渲染 `/\{apiBaseUrl\}/.../data.json`。当 premerged 的 `publicAssets` 已生成这些文件时通常无必要。 |
| `translationPayloads.publicDir` | `string` | — | 相对于 Nitro public 根目录的输出目录。默认为 `apiBaseUrl`（`_locales`），从而使静态文件路径与客户端请求 URL（`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`）一致。 |
| `translationPayloads.warnFileCount` | `number` | `500` | 当生成的 payload 文件数量超过该阈值时，在构建期发出警告。 |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | 当生成的 payload 总大小超过该字节阈值时，在构建期发出警告。 |

## SEO

为每个本地化页面生成的 meta 标签。

| 选项 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | 自动生成 SEO meta 标签（`hreflang`、`canonical`、`og:url`、`og:locale`）。 |
| `metaBaseUrl` | `string` | `undefined` | SEO meta 标签（canonical、og:url、hreflang）使用的基础 URL。 - 具体 URL 字符串（例如 `'https://example.com'`）——直接使用（优先级最高）。 - `undefined`——若已启用 `nuxt-site-config` 模块，则回退到 `site.url`；否则回退到当前请求来源（服务端 `useRequestURL().origin`，客户端 `window.location.origin`）。 |
| `metaTrustForwardedHost` | `boolean` | `true` | 解析 meta 标签的基础 URL 时信任 `X-Forwarded-Host` 头。当应用位于设置了该头的反向代理（nginx、Cloudflare、AWS ALB 等）之后时启用。 |
| `metaTrustForwardedProto` | `boolean` | `true` | 解析 meta 标签的协议时信任 `X-Forwarded-Proto` 头。当应用位于 TLS 终止代理之后时启用，这样即使应用本身监听 HTTP，canonical URL 也会使用 `https://`。 |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | canonical 和 `og:url` meta 标签中保留的查询参数名列表。不在此列表中的参数会从 canonical URL 中被去除。 |

## 检测与重定向

为尚未选择语言的访客选择语言。

| 选项 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | 启用基于语言的自动重定向。当为 `true` 时，访客在首次访问时会被重定向到其偏好语言（通过 cookie、`Accept-Language` 头或默认语言检测）。 |
| `autoDetectLanguage` | `boolean` | `true` | 从 HTTP 请求头 `Accept-Language` 自动检测用户偏好语言。与 `autoDetectPath` 结合使用以决定何时进行检测。 |
| `autoDetectPath` | `string` | `'/'` | 何时可以运行 cookie / Accept-Language 偏好重定向（在启用 `redirects` 时）。 - `'/'`——只针对 `/`（默认语言下的深链接仍可访问；默认值） - `'no_prefix'`——只针对不带语言前缀的路径 - `'*'`——所有路径，包括改写已有的语言前缀（例如 cookie 偏好 `de` 时，`/fr/about` → `/de/about`） - 任何其他字符串——精确路径匹配（例如 `'/welcome'`） 前缀策略下的清理（例如 `prefix_except_default` 下的 `/en` → `/`）不受此选项限制。 |

## 注册

模块中可关闭的部分。

| 选项 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | 注册 `defineI18nRoute()` 宏插件，从而允许按页面调用 `defineI18nRoute()`。 |
| `plugin` | `boolean` | `true` | 注册核心 i18n 插件，提供 `$t()`、`$tc()`、`$getLocale()`、`$switchLocale()` 等运行时辅助函数。 |
| `hooks` | `boolean` | `true` | 注册 i18n hooks 插件，提供 `i18n:register` 与 `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch` 等应用级 hook。 |
| `components` | `boolean` | `true` | 注册内置 i18n 组件（`<i18n-link>`、`<i18n-switcher>`、`<i18n-t>`、`<i18n-group>`）。设为 `false` 可禁用自动组件注册（如果你不使用它们并希望减小模块体积）。 |
| `types` | `boolean` | `true` | 基于默认语言文件中的翻译键，为 `useI18n`、`$t` 及相关辅助函数生成 TypeScript 类型声明。 |
| `debug` | `boolean` | `false` | 为语言检测、路由生成和翻译加载启用详细调试日志。 |

## 其他

| 选项 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | 额外输出从每个语言的 `iso` 派生的裸语言 `hreflang`（例如 `es-ES` → 同时输出 `es`）。`locales` 中该语言下的第一个地区语言会占用其裸标签。路由 `code` 不会参与——只使用 `iso \|\| code`。 |
| `vueDevtools` | `boolean` | `true` | 在开发模式下注册 Vue DevTools 检查器和 timeline（浏览器扩展）。与 Nuxt DevTools 自定义 tab 无关。 |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | 本地化路由名前缀（例如 `'localized-index'`）。内部用于区分原始路由和生成的语言变体。 |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | 按路由禁用 meta 标签的配置，来自 `defineI18nRoute()` 调用。将路由路径映射到 `true`（全部禁用）或数组（指定要禁用 meta 的语言代码）。 |
| `missingWarn` | `boolean` | `true` | 缺失翻译键时在控制台输出警告。 |
| `hmr` | `boolean` | `true` | 为翻译文件启用开发期的热模块替换。设为 `true` 时，修改 JSON 翻译文件会触发自动重载，而无需完整刷新页面。 |
| `cacheMaxSize` | `number` | `0` | 内存中翻译缓存的最大条目数。`0` 表示无上限。 |
| `cacheTtl` | `number` | `0` | 缓存翻译条目的 TTL（秒）。`0` 表示永不过期。 |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | 按语言配置的命名数字格式（兼容 Vue I18n）。可用于 `$tn(1000, 'currency')` 之类的调用。 |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | 按语言配置的命名日期时间格式（与 Vue I18n `datetimeFormats` 兼容）。可用于 `$td(date, 'short')` 之类的调用。 |
| `httpCacheDuration` | `number` | `31536000` | `/\{apiBaseUrl\}/:page/:locale/data.json` 的 HTTP `Cache-Control` max-age（秒）。仅当 `dateBuild` 用于打破 URL 缓存（`?v=...`）时才完全生效——这是默认情形：响应会是 `public, max-age=…, immutable`，对浏览器和 CDN 都安全。 - `dateBuild: 0`/`''`——URL 稳定不变，此时该值*不*生效；响应改为 `public, max-age=0, must-revalidate`。给稳定 URL 设置很长的 `max-age` 会把用户首次看到的 payload 长期固定住。 - `0`——完全不设置 `Cache-Control`（本地调试时有用） - 开发模式（`import.meta.dev`）下不应用，避免浏览器缓存干扰 HMR - 只作用于经由 Nitro 提供的响应。被复制到 `public/` 并由托管平台提供的 payload 使用平台自身的响应头——参见性能指南。 与 `@nuxtjs/i18n` v10.2.0 的实验性 `httpCacheDuration` 类似，但这里是显式的响应头，而不是 Nitro `defineCachedEventHandler` 的 maxAge。 |
| `dateBuild` | `string \| number` | — | 用于翻译请求缓存清理（`?v=...`）的值。若未提供，模块会回退到 `Date.now()`（非确定性）。为了可复现/滚动部署，请将其设置为稳定值（例如 git SHA 或构建号）。 |
| `experimental` | `Record<string, unknown>` | — | 实验性/不稳定选项的容器。其内容可能在小版本之间发生变化或被移除，不另行通知。 |
