---
title: "辅助函数"
description: "模块注入的每个运行时辅助函数 —— `$t`、`$tc`、`$localePath`、`$switchLocale` 等 —— 及其签名。"
---

模块会将其运行时辅助函数注入到 Nuxt 应用中：`$t`、`$tc`、`$localePath`、`$switchLocale` 等。使用本页查询辅助函数的签名和行为。签名和描述来自 `src/runtime/plugins/01.plugin.ts` 中的 `PluginsInjections` 和 `NuxtAppOnlyInjections` 接口。

## 访问方式 {#access}

| 位置 | 方式 |
| --- | --- |
| 模板 | `{{ $t('title') }}` —— 所有辅助函数，带 `$` |
| `<script setup>` | `const { t, localePath } = useI18n()` —— `PluginsInjections` 中的所有辅助函数，带或不带 `$` 均可 |
| 插件、中间件、`<script setup>` | `const { $t, $defineI18nRoute } = useNuxtApp()` —— 全部辅助函数，仅带 `$` |

`$defineI18nRoute` 仅在 `useNuxtApp()` 上有类型定义。参见 [`useI18n`](/zh/composables/useI18n)。

```vue
<script setup lang="ts">
const { t, localePath } = useI18n()
</script>

<template>
  <NuxtLink :to="localePath('/about')">{{ t('nav.about') }}</NuxtLink>
</template>
```

| --- | --- | --- |

| [`$_ts`](#$_ts) | `(route: RouteLocationNormalizedLoaded) => TranslationFn<string>` | 将 `$ts` 绑定到特定路由。 |
| [`$clearCache`](#$clearcache) | `() => void` | 丢弃所有已缓存的翻译块，并重新加载当前页面的字典。 |
| [`$defaultLocale`](#$defaultlocale) | `() => string \| undefined` | 配置的默认 locale 代码。 |
| [`$getI18nConfig`](#$geti18nconfig) | `() => ResolvedI18nConfig` | 运行时所见的已解析模块配置。 |
| [`$getLocale`](#$getlocale) | `(route?: RouteLocationNormalizedLoaded \| RouteLocationResolvedGeneric) => string` | 当前 locale 的代码。 |
| [`$getLocaleName`](#$getlocalename) | `() => string \| null` | 配置中当前 locale 的 `displayName`，未设置时为 `null`。 |
| [`$getLocales`](#$getlocales) | `() => Locale[]` | 所有已配置的 locale 及其元数据。 |
| [`$getRouteName`](#$getroutename) | `(route?: RouteLocationNormalizedLoaded \| RouteLocationResolvedGeneric, locale?: string) => string` | 去掉 locale 前缀后的路由名称 —— 即翻译所使用的键名。 |
| [`$has`](#$has) | `(key: string) => boolean` | 某个键在当前 locale 中是否能解析。 |

| `$pluralFunc` | `PluralFunc` | `$tc` 使用的复数规则：`<i18n-t>` 会调用它，从原始翻译中挑选一种形式。 |
| `$pluralLocale` | `() => string` | `$tc` 进行复数处理所依据的标签：locale 有 `iso` 时使用 `iso`，否则使用其代码。 |
| [`$resolveTranslations`](#$resolvetranslations) | `() => Translations` | 当前 locale 和路由在内存中的所有翻译，以树形结构返回。 |

## Locale {#locale}

### `$getLocale` {#$getlocale}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric) => string
```

当前 locale 的代码。传入一个路由可读取该路由所属的 locale。

```ts
$getLocale() // 'de' on /de/about
```

### `$getLocaleName` {#$getlocalename}

```ts
() => string | null
```

配置中当前 locale 的 `displayName`，未设置时为 `null`。

### `$getLocales` {#$getlocales}

```ts
() => Locale[]
```

所有已配置的 locale 及其元数据。

locale 对象上的自定义属性会按原样返回；可通过对 `Locale` 进行[模块扩充](/zh/api/module-options#locales)来为其添加类型。

### `$defaultLocale` {#$defaultlocale}

```ts
() => string | undefined
```

配置的默认 locale 代码。

### `$getI18nConfig` {#$geti18nconfig}

```ts
() => ResolvedI18nConfig
```

运行时所见的已解析模块配置。

该值包含[运行时覆盖](/zh/guide/runtime-overrides)（`defaultLocale`、`fallbackLocale`、已禁用的 locale）。

```ts
const { strategy, localeCookie } = useNuxtApp().$getI18nConfig()
```

## 翻译 {#translation}

### `$t` {#$t}

```ts
TranslationFn<CleanTranslation>
```

翻译一个键，并将 `params` 插值到其中。键缺失时返回 `defaultValue`；
若未提供默认值，则返回键本身。

```ts
// { "welcome": "Welcome, {name}!" }
$t('welcome', { name: 'Ada' }) // 'Welcome, Ada!'
$t('missing.key', {}, 'Fallback') // 'Fallback'
```

指向嵌套对象的键会返回该对象，而不是字符串。在模板中它会渲染为 `[object Object]`；请使用叶子键。

### `$ts` {#$ts}

```ts
TranslationFn<string>
```

与 `$t` 类似，但始终返回字符串：值会经过 `toString()`，因此嵌套
对象会变成 `'[object Object]'`。请让键指向叶子节点。

### `$_t` {#$_t}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<CleanTranslation>
```

将 `$t` 绑定到特定路由，用于在当前页面之外进行翻译 —— 例如布局中渲染
指向另一路由的链接。

```ts
const route = useRoute()
const t = useNuxtApp().$_t(route)
t('page.title')
```

### `$_ts` {#$_ts}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<string>
```

将 `$ts` 绑定到特定路由。参见 `$_t`。

### `$tc` {#$tc}

```ts
(key: TranslationKey, params: number | Params, defaultValue?: string) => string
```

带复数处理的翻译。`params` 可以是计数本身，也可以是包含
`count` 的对象。

各形式之间用 `|` 分隔。使用内置规则时，非负整数计数 `n` 会选择第 `n` 种形式，超出时取最后一种形式；负数、小数或 `NaN` 计数取最后一种形式。`{count}` 和其他参数会插值到所选形式中。

对于复数不随计数变化的语言，请以 `=0 ` 开头编写模板。此时第一种形式用于 0，其余形式按 [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) 类别排列，顺序为 `zero, one, two, few, many, other`：

```json
{
  "apples": "=0 no apples | one apple | {count} apples",
  "files": "=0 no files | {count} one | {count} few | {count} many"
}
```

```ts
$tc('apples', 0) // 'no apples'
$tc('apples', 1) // 'one apple'
$tc('apples', 7) // '7 apples'

// In `uk` (categories `one, few, many, other`) the forms after the zero form follow those categories:
$tc('files', 21) // '21 one'
$tc('files', 22) // '22 few'
$tc('files', 25) // '25 many'
$tc('files', 2.5) // '2.5 many': no form for `other`, so the last one
```

- `=0 ` 仅在值的最开头且带空格时才有效。`$t` 会将其作为文本显示：它属于复数功能。
- 没有自己形式的类别取最后一种形式。负数或小数计数同样取最后一种形式。
- 它适用于任何 locale：英语中可写作 `=0 none | one | {count} many`。
- 类别来自 locale 的 `iso`，否则来自其代码。`Intl` 不认识的代码会回退到索引规则，但标记仍会被移除，因此结果绝不会因机器而异。
- `<i18n-t :plural>` 遵循相同的规则。自定义的 [`plural`](/zh/api/module-options#plural) 或 `customPluralRule` 会收到包括标记在内的原始值，并自行决定；`plural` 返回 `null` 时会将调用交还给内置规则，由内置规则处理该标记。

没有标记时，模板沿用索引规则，只有一种只能以一种方式解读的例外情况：一个不含占位符的零形式，后跟每个类别各一种形式，且在多个计数共享的每种形式中都包含 `{count}`（如 `uk` 中的 `no files | {count} one | {count} few | {count} many`）。

如需自定义规则，请设置 [`plural`](/zh/api/module-options#plural)。

```ts
// { "apples": "no apples | one apple | {count} apples" }
$tc('apples', 0) // 'no apples'
$tc('apples', 10) // '10 apples'
$tc('cart', { count: 2, name: 'Ada' }) // count and params in one object
```

第三个参数是 `defaultValue`，而不是参数。

### `$has` {#$has}

```ts
(key: string) => boolean
```

某个键在当前 locale 中是否能解析。可用它根据可选文案进行分支判断，而不是
渲染原始键。与 `$t` 一样，在同一 locale 的页面过渡期间，它也能看到正在离开的
页面的键。

```ts
if ($has('promo.banner')) show.value = true
```

## 格式化 {#formatting}

### `$tn` {#$tn}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

使用 `Intl.NumberFormat` 按当前 locale 格式化数字。传入键可从配置中选择
一个命名格式。

命名格式来自 [`numberFormats`](/zh/api/module-options#numberformats)。

```ts
$tn(1234.5, { style: 'currency', currency: 'EUR' }) // '1.234,50 €' in de
$tn(1000, 'currency') // named format
$tn(1000, 'currency', 'de') // named format in another locale
```

### `$td` {#$td}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

使用 `Intl.DateTimeFormat` 按当前 locale 格式化日期。传入键可从配置中选择
一个命名格式。

命名格式来自 [`datetimeFormats`](/zh/api/module-options#datetimeformats)。

```ts
$td(new Date(), { dateStyle: 'long' })
$td(post.createdAt, 'short')
```

### `$tdr` {#$tdr}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

使用 `Intl.RelativeTimeFormat` 将日期格式化为相对时间（"3 天前"）。

```ts
$tdr(Date.now() - 5 * 60_000) // '5 minutes ago' in en
```

## 切换与链接 {#switching-and-links}

### `$switchLocale` {#$switchlocale}

```ts
(locale: string) => Promise<boolean>
```

导航到当前页面的另一个 locale 版本。在 `no_prefix` 和 hash 模式下，它会在导航前
加载该 locale 的翻译；在 `no_prefix` 下，路由会被原地替换（不会新增
历史记录）。未知的 locale 会被忽略。
该调用是异步的：使用 `await` 以便在导航完成后运行代码。当该 locale 的字典
处于活动状态时，它解析为 `true`，否则为 `false`：可能是翻译块加载失败（当前
字典保持不变；再次调用即可重试），或是有更新的切换操作胜出。

```ts
await $switchLocale('de')
```

### `$switchLocalePath` {#$switchlocalepath}

```ts
(locale: string) => string
```

当前页面在另一个 locale 下的路径，不进行导航。

```vue
<NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
```

### `$switchLocaleRoute` {#$switchlocaleroute}

```ts
(locale: string) => RouteLocationRaw
```

当前页面在另一个 locale 下的路由对象，不进行导航；对于拥有独立 `baseUrl` 的
locale，则返回 URL 字符串。在 `trailingSlash` 下，该对象的 `path` 和 `fullPath`
遵循该规则，`query` 和 `hash` 保持原样，`router.push` 或链接都会保留它们。

### `$switchRoute` {#$switchroute}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => Promise<void>
```

导航到另一个路由，保持当前 locale 或切换到 `toLocale`。与
`$switchLocale` 一样是异步的。

```ts
$switchRoute('/about') // active locale
$switchRoute({ name: 'about' }, 'de') // switch to de
```

### `$localePath` {#$localepath}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => string
```

解析指定 locale（或当前 locale）下的路径。带有 `http(s):`、`mailto:`
或 `tel:` 协议的字符串会原样返回：不要未经检查就将用户输入作为链接目标传入。

字符串路径会被解读为它所展示的页面，因此 locale 的自定义路径同样会被应用。

```ts
$localePath('/about') // '/about' in en, '/de/ueber-uns' in de with localeRoutes
$localePath({ name: 'about' }, 'fr') // '/fr/about'
```

### `$localeRoute` {#$localeroute}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => RouteLocationResolved
```

解析指定 locale（或当前 locale）下的路由。返回一个普通对象，可以安全地保存在状态中。当某个参数需要
转义时，该对象包含 `path`、`fullPath`、`query` 和 `hash`，但没有 `name` 或 `params`：由路径为路由器
提供编码后的 URL。对于位于其他域名上的 locale，`path` 和 `fullPath` 是绝对地址，路由器无法接受：
这类链接应通过 `<i18n-link>` 或 `$localePath` 生成。

### `$getRouteName` {#$getroutename}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric, locale?: string) => string
```

去掉 locale 前缀后的路由名称 —— 即翻译所使用的键名。

```ts
$getRouteName() // 'about' on /de/about
```

## 页面配置 {#page-config}

### `$defineI18nRoute` {#$definei18nroute}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

在组件内部注册按页面的 locale 配置和翻译。
会合并到当前 locale 中，并在 locale 变化时重新应用。

请在页面的 `<script setup>` 中调用它，并始终从 `useNuxtApp()` 中解构获取。构建时会从调用中读取 `locales`、`localeRoutes` 和 `disableMeta`；运行时只有 `locales` 起作用（内联翻译会合并到当前 locale）。完整规则：[页面配置](/zh/guide/per-component-translations)。

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: { en: '/about', de: '/ueber-uns' },
})
</script>
```

### `$setI18nRouteParams` {#$seti18nrouteparams}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

为当前路由设置按 locale 区分的参数，使动态段可以随语言不同而不同。
请在 SSR 期间、head 渲染之前调用它。

当导航到另一个路径并提交时，这些参数会被清除，包括从 `/news/1` 到 `/news/4` 这种路由名称不变的情况。详情：[本地化路径](/zh/guide/custom-locale-routes)。

```ts
$setI18nRouteParams({
  en: { slug: 'my-post' },
  de: { slug: 'mein-beitrag' },
})
```

## 运行时翻译 {#runtime-translations}

### `$mergeTranslations` {#$mergetranslations}

```ts
(newTranslations: Translations) => void
```

在运行时将翻译合并到当前 locale 中，覆盖已加载的内容。

深度合并到当前 locale 的当前页面翻译块中；未提及的键会保留。

```ts
$mergeTranslations({ banner: { title: 'Sale' } })
```

### `$setTranslation` {#$settranslation}

```ts
(key: string, value: unknown) => void
```

替换当前字典中 `key` 处的值。这是替换而不是合并 ——
如果需要保留已有的同级键，请使用 `$mergeTranslations`。

```ts
$setTranslation('banner', { title: 'Sale' }) // drops other keys under banner
$setTranslation('banner.title', 'Sale') // dotted path
```

### `$loadPageTranslations` {#$loadpagetranslations}

```ts
(locale: string, routeName: string, translations: Translations) => Promise<void>
```

在运行时为页面加载翻译，适用于构建时无法确定键的内容。

合并到内存中的 `(locale, routeName)` 翻译块，当该翻译块处于活动状态时屏幕会更新。这里不会获取任何 payload：对于尚未加载的页面，这些翻译会等待，当其文件加载后，它们会叠加在文件内容之上。

```ts
await $loadPageTranslations('en', 'about', { title: 'About us' })
```

### `$resolveTranslations` {#$resolvetranslations}

```ts
() => Translations
```

当前 locale 和路由在内存中的所有翻译，以树形结构返回。
这是 `$t()` 当前能够解析的内容的只读视图。

请将结果视为只读。

### `$setMissingHandler` {#$setmissinghandler}

```ts
(handler: MissingHandler | null) => void
```

安装一个回调，在每个无法解析的键上调用。传入 `null` 可将其移除。

该处理函数会代替开发环境警告运行。

```ts
$setMissingHandler((locale, key, routeName) => {
  console.error(`[i18n] missing ${key} in ${locale} (${routeName})`)
})
```

### `$clearCache` {#$clearcache}

```ts
() => void
```

丢弃所有已缓存的翻译块，并重新加载当前页面的字典。在新的翻译到达之前，
页面会继续显示当前的翻译。开发环境的 HMR 会在每次翻译文件变更时
调用它。

```ts
const { clearCache } = useI18n()
clearCache()
```

重新加载失败时会保留当前字典。
