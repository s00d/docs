# 🔧 Types Generator（`@i18n-micro/types-generator`）

`@i18n-micro/types-generator` 包为翻译键提供自动的 TypeScript 类型生成。它会分析你的 JSON 翻译文件并生成严格类型，让翻译键获得完整的类型安全性和自动补全支持。

## 📖 概述

`@i18n-micro/types-generator` 是一个可选的 dev 依赖，通过以下方式提升你的开发体验：

- 🔍 **自动类型生成** - 扫描 JSON 翻译文件并生成 TypeScript 类型
- ✅ **类型安全** - 在编译时防止拼写错误和无效翻译键
- 🎯 **自动补全支持** - 对翻译键提供完整的 IDE 自动补全
- 🔄 **热重载** - 翻译文件变更时自动重新生成类型
- 🚀 **零运行时开销** - 类型仅在编译时使用，不影响打包体积

## 🎯 快速开始

### 对于 Nuxt 项目

将模块添加到 `nuxt.config.ts`：

```typescript
import { defineNuxtConfig } from 'nuxt/config'

export default defineNuxtConfig({
  modules: [
    'nuxt-i18n-micro',
    '@i18n-micro/types-generator/nuxt', // Add types generator
  ],
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    translationDir: 'locales', // Path to your translation files
  },
})
```

生成器会自动：

- 扫描 `locales` 目录中的所有 JSON 文件
- 在 `.nuxt/i18n-micro.d.ts` 中生成类型
- 监视变化并自动重新生成类型

### 对于 Vue/Vite 项目

将插件添加到 `vite.config.ts`：

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { I18nTypesPlugin } from '@i18n-micro/types-generator'

export default defineConfig({
  plugins: [
    vue(),
    I18nTypesPlugin({
      srcDir: 'src',
      translationDir: 'locales',
      outputFile: 'src/i18n-types.d.ts', // Optional: custom output path
    }),
  ],
})
```

请确保将生成的文件包含到 `tsconfig.json` 中：

```json
{
  "include": ["src/**/*", "src/i18n-types.d.ts"]
}
```

## 📁 翻译文件结构

生成器同时支持扁平和嵌套的翻译结构：

```
locales/
  en.json
  fr.json
  pages/
    home/
      en.json
      fr.json
    about/
      en.json
      fr.json
```

**示例 `locales/en.json`：**

```json
{
  "greeting": "Hello, {name}!",
  "header": {
    "title": "Welcome",
    "subtitle": "Subtitle"
  },
  "errors": {
    "404": "Not found",
    "500": "Server error"
  },
  "apples": "no apples | one apple | {count} apples"
}
```

生成器会为所有键（包括嵌套键）创建类型：

```typescript
// Generated types
declare module '@i18n-micro/types' {
  export interface DefineLocaleMessage {
    greeting: string
    'header.title': string
    'header.subtitle': string
    'errors.404': string
    'errors.500': string
    apples: string
  }
}
```

## 💡 用法

类型生成完成后，你将获得完整的类型安全性：

```typescript
import { useI18n } from '@i18n-micro/vue'

const { t } = useI18n()

// ✅ Type-safe: autocomplete works
t('greeting', { name: 'World' })
t('header.title')
t('errors.404')

// ❌ Type error: key doesn't exist
t('invalid.key') // Error: Argument of type '"invalid.key"' is not assignable
```

### Nuxt 特有说明

**在 Nuxt 项目中，类型安全仅适用于 `useI18n` 组合式函数。** 生成的类型应用于该组合式函数的返回值，确保使用 `t()`、`ts()`、`tc()` 与 `has()` 方法时具备类型安全。

```typescript
// ✅ Correct: Using useI18n composable
<script setup lang="ts">
import { useI18n } from '#imports'

const { t } = useI18n()
t('greeting') // Type-safe with autocomplete
</script>

// ❌ Not type-safe: Direct access to $i18n or other methods
// Type safety is only available through the useI18n composable
```

## 🔄 动态键

有时你需要使用动态键（例如基于用户输入或 API 响应）。生成器提供 `ScopedKey` 辅助类型，用于安全地使用动态键。

### 为什么不使用运行时类型守卫？

**运行时类型守卫不推荐**用于 i18n-micro，因为：

1. **打包体积** - 生成包含所有键的 JavaScript 数组会使包变大
2. **性能** - 运行时检查会带来不必要的开销
3. **理念** - i18n-micro 的设计目标是轻量与高速

### TypeScript 方式：类型断言

对于动态键，请使用 TypeScript 的类型断言：

```typescript
import type { TranslationKey, ScopedKey } from '@i18n-micro/types'

// ❌ Type error: dynamic key
const status = 'pending'
t(`status.${status}`) // Error: string is not assignable to TranslationKey

// ✅ Solution 1: Type assertion (if you're sure the key exists)
t(`status.${status}` as TranslationKey)

// ✅ Solution 2: ScopedKey helper (safer, checks prefix exists)
function getStatusText(status: string) {
  return t(`status.${status}` as ScopedKey<'status'>)
  // TypeScript verifies that keys starting with 'status.' exist
}

// ✅ Solution 3: Runtime check with has()
if (has(`status.${status}`)) {
  t(`status.${status}` as TranslationKey)
}
```

### ScopedKey 辅助类型

`ScopedKey<Scope>` 类型允许你按前缀收窄动态键：

```typescript
import type { ScopedKey } from '@i18n-micro/types'

// Assuming you have keys: 'errors.404', 'errors.500', 'btn.save'

function getErrorText(code: string) {
  // ✅ Safer than plain TranslationKey
  // TypeScript verifies that 'errors.*' keys exist
  return t(`errors.${code}` as ScopedKey<'errors'>)
}

// ❌ Type error: 'btn' prefix doesn't match 'errors'
function getErrorTextWrong(code: string) {
  return t(`errors.${code}` as ScopedKey<'btn'>) // Error
}
```

## 🎨 进阶用法

### 处理路由特定翻译

生成器会自动包含路由特定翻译文件中的键：

```
locales/
  en.json                    # Root-level translations
  pages/
    home/
      en.json               # Route-specific translations
    about/
      en.json
```

来自根级和路由特定文件的所有键都会包含在生成的类型中。

### 禁用页面级翻译

如果你在 i18n 配置中使用 `disablePageLocales: true`，生成器会将所有文件（包括 `pages/` 下的文件）视为根级翻译。

## 🐛 故障排查

### 类型未更新

1. **检查文件路径** - 确保 `translationDir` 指向正确的目录
2. **重启 TypeScript 服务器** - 在 VS Code：`Cmd/Ctrl + Shift + P` → "TypeScript: Restart TS Server"
3. **检查 tsconfig.json** - 确保生成的文件已被包含

### 添加键后出现类型错误

1. **重新生成类型** - 生成器应自动重新生成，但你也可以手动触发
2. **检查 JSON 语法** - 无效的 JSON 文件会被跳过并给出警告
3. **重启开发服务器** - 有时需要重启才能使更改生效

### 自动补全不生效

1. **确认文件包含** - 检查生成的 `.d.ts` 文件是否在 `tsconfig.json` 的 include 中
2. **检查模块增强** - 确保生成文件使用 `declare module '@i18n-micro/types'`
3. **TypeScript 版本** - 需要 TypeScript 4.1+ 才能支持模板字面量类型

## 📚 API 参考

### `generateTypes(options: GeneratorOptions)`

手动生成类型（适用于脚本或 CI）：

```typescript
import { generateTypes } from '@i18n-micro/types-generator'

await generateTypes({
  srcDir: './src',
  translationDir: 'locales',
  outputFile: './src/i18n-types.d.ts',
})
```

### `flattenKeys(obj: Record<string, unknown>, prefix?: string)`

用于扁平化嵌套翻译对象的工具函数：

```typescript
import { flattenKeys } from '@i18n-micro/types-generator'

const keys = flattenKeys({
  header: { title: 'Title' },
  footer: { copyright: 'Copyright' },
})
// Returns: ['header.title', 'footer.copyright']
```

## 🔍 工作原理

1. **扫描** - 使用 `globby` 在翻译目录中查找所有 `**/*.json` 文件
2. **解析** - 解析每个 JSON 文件并通过递归扁平化提取所有键
3. **去重** - 将来自所有文件的键合并为唯一集合
4. **生成** - 通过 `declare module` 增强创建 `.d.ts` 文件
5. **监视** - 在开发模式下，监视文件变更并重新生成类型

生成的文件通过 TypeScript 的模块增强扩展了 `@i18n-micro/types` 中的 `DefineLocaleMessage`，这会自动更新整个项目中的 `TranslationKey` 类型。

## 🎯 最佳实践

1. **保持翻译有序** - 为相关键使用嵌套对象
2. **使用一致的命名** - 遵循命名约定（例如 `errors.*`、`buttons.*`）
3. **利用 ScopedKey** - 对动态键使用 `ScopedKey` 而不是纯断言
4. **在 CI 中进行类型检查** - 在 CI 流水线中运行类型检查
5. **不要编辑生成的文件** - `.d.ts` 文件是自动生成的，会被覆盖
