# 从 i18n 路由中排除静态文件

## 概述

默认情况下，nuxt-i18n-micro 会自动把常见的静态文件从 i18n 路由处理中排除。此外，你也可以配置自定义排除模式，防止特定路径被 i18n 系统处理。

## 内置排除

模块会自动排除以下文件类型和路径：

- **Sitemap**：`/sitemap*.xml`、`/sitemap-en.xml` 等
- **SEO 文件**：`/robots.txt`、`/favicon.ico`
- **PWA 文件**：`/manifest.json`、`/sw.js`、`/workbox-*.js`
- **静态资源**：扩展名为 `.xml`、`.txt`、`.ico`、`.json`、`.js`、`.css`、`.png`、`.jpg`、`.jpeg`、`.gif`、`.svg`、`.woff`、`.woff2`、`.ttf`、`.eot` 的文件
- **Nuxt 内部路径**：任何以 `__` 开头的路径（例如 `/__nuxt/`）

## 自定义排除模式

你可以通过 `excludePatterns` 选项定义自定义排除模式：

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## 模式类型

### 字符串模式

- **精确匹配**：`'/api/health'` —— 精确匹配 `/api/health`
- **前缀匹配**：`'/admin'` —— 匹配 `/admin` 与 `/admin/dashboard`
- **通配符**：`'/api/*'` —— 匹配 `/api/users`，但不匹配 `/api/users/123`
- **深层通配符**：`'/admin/**'` —— 匹配 `/admin/users` 与 `/admin/users/123`

### 正则表达式

对复杂匹配请使用 RegExp 对象：

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## 使用场景

### SEO 文件

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API 路由

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### 管理面板

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### 静态资源

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## 工作方式

1. **服务器中间件**：一个 Nitro 中间件会最先运行，用于检查排除模式
2. **页面处理**：在页面解析过程中，被排除的路径会被跳过
3. **通配路由**：兜底路由在处理前会先检查排除
4. **预渲染**：被排除的路径不会包含在预渲染的路由列表中

## 性能影响

- 排除检查经过优化，会在请求生命周期早期运行
- 内置模式使用高效的正则匹配
- 自定义模式会被缓存和复用
- 被排除路径的性能开销极小

## 疑难解答

### 静态文件仍被拦截

1. **检查模式语法**：确保模式匹配的是准确的路径结构
2. **复杂模式请使用正则**：字符串通配符有一定限制
3. **测试模式**：使用浏览器开发者工具确认实际的请求路径
4. **注意顺序**：确保排除模式在其他 i18n 配置之前定义

### 模式无效

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### 调试模式

启用调试模式可以查看排除处理的过程：

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

这会在控制台输出排除相关的决策。

## 从既有变通方案迁移

如果之前你依赖 route rules 或中间件来实现排除，现在可以改用 `excludePatterns`：

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

新的方案更可靠，且在路由系统的多个层次都能生效。
