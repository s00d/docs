# 🌐 Crowdin 集成指南

## 📖 简介

将 Crowdin 集成到项目中可以简化本地化和翻译流程，让跨多语言、多平台的翻译管理更容易。本指南将逐步引导你完成在项目中设置 Crowdin 的全过程，包括配置、上传源文件与下载翻译。

## 🔧 安装与配置

要开始使用 Crowdin，你需要在本机全局安装 Crowdin CLI，并在项目目录中进行初始化。

### 📦 安装 Crowdin CLI

首先，通过 npm 全局安装 Crowdin CLI：

```bash
npm install -g @crowdin/cli
```

### 🛠 在项目中初始化 Crowdin

运行以下命令在项目中初始化 Crowdin：

```bash
crowdin init
```

该命令会引导你完成设置流程，包括填写项目 ID、API token 和其他配置。

## 🗂️ 配置指南

### 📄 Crowdin 配置文件（`crowdin.yml`）

Crowdin 配置文件（`crowdin.yml`）定义了源文件的映射方式以及翻译文件的落地位置。下面是一个示例配置：

```yml
'project_id': 'YOUR_PROJECT_ID'
'api_token': 'YOUR_API_TOKEN'
'base_path': './locales'
'base_url': 'https://api.crowdin.com'
'preserve_hierarchy': true

files:
  [
    { 'source': '/en.json', 'translation': '/%two_letters_code%.json' },
    { 'source': '/pages/**/en.json', 'translation': '/pages/**/%two_letters_code%.json' },
  ]
```

### 📂 关键配置参数

- **`project_id`**：你的 Crowdin 项目 ID，用于标识翻译所属的项目。
- **`api_token`**：用于鉴权的 API token。请确保该 token 具备上传和下载翻译的权限。
- **`base_path`**：指定源文件的基础目录。示例中翻译文件位于 `./locales` 目录。
- **`base_url`**：Crowdin API 的基础 URL。
- **`preserve_hierarchy`**：设为 `true` 时，Crowdin 会在项目中保留源文件的目录层级。

### 📂 Files 配置

`files` 部分把源文件映射到翻译文件的存放路径。例如：

- **源路径**：定义原始翻译文件的位置。
- **翻译路径**：指定翻译文件在 Crowdin 中的存放位置。`%two_letters_code%` 等占位符用于在路径中动态生成语言代码。

## ⬆️ 向 Crowdin 上传源文件

配置好 Crowdin 后，可以使用以下命令上传源文件：

```bash
crowdin upload sources
```

该命令会把配置中指定的所有源文件上传到 Crowdin，供翻译使用。

## ⬇️ 从 Crowdin 下载翻译

Crowdin 中的翻译完成或更新后，可以使用以下命令下载到项目中：

```bash
crowdin download
```

该命令会拉取最新的翻译，并按配置文件中的路径保存到本地。

## ⚙️ 最佳实践

### 🔑 一致的键命名

确保所有文件中的翻译键命名保持一致，避免混淆和重复。

### 🧹 定期维护

定期审阅并清理未使用的翻译键，让文件保持整洁、易于管理。

### 🛠 自动化上传与下载

把 Crowdin CLI 命令集成到 CI/CD 流水线中，自动上传源文件、下载翻译，确保翻译始终保持最新。

按照本指南操作，你就能将 Crowdin 无缝集成到项目中，为国际化工作提供高效、有序的管理方式。
