这里简要解答大家最常遇到的问题，主要针对各主题页面没有直接回答的疑问。每个答案都链接到负责该主题的页面。如果没有找到你的问题，请搜索文档或提交 [issue](https://github.com/s00d/nuxt-i18n-micro/issues)。

## 翻译 {#translations}

### `$t` 在插件或工具函数中失效 {#$t-fails-in-a-plugin-or-a-utility-function}

组合式函数需要 Nuxt 上下文。在 `setup` 之外，请从 app 中获取辅助函数，或在 `await` 之后于其上下文中运行：

```ts
const nuxtApp = useNuxtApp()
const title = nuxtApp.$t('errors.unknown')
await nuxtApp.runWithContext(() => nuxtApp.$t('errors.unknown'))
```

在完全没有 app 的服务中，请传递键，然后在组件中进行翻译。

### 某个键只在一个页面上显示为原始文本 {#a-key-shows-as-raw-text-on-one-page-only}

该键位于另一个页面的文件中。一个页面只能看到根文件和它自己的 `locales/pages/<route-name>/` 文件；请将共享的键移到根文件中。参见[翻译文件](/zh-CN/guide/translations)。

### 页面过渡期间键会闪烁 {#keys-flash-while-a-page-transition-runs}

正常情况下不应如此：离开页面的键会一直解析到过渡结束。如果仍然闪烁，说明该键只存在于两个页面都不拥有的页面文件中（例如在布局中）；请将其移到根文件中。

### 在 Vercel、Netlify 或 Edge 上 SSR 时缺少翻译 {#translations-are-missing-during-ssr-on-vercel-netlify-or-edge}

在这些平台上服务器函数无法读取 `public/`，因此数据包会被嵌入到服务器 bundle 中。这是默认行为；请检查 `translationPayloads.serverAssets` 是否被关闭。如果日志显示 `public/ is not deployed next to the server`，请设置 `nitro.serveStatic: false`。参见[部署](/zh-CN/guide/deployment)。

### 如何在翻译后的句子中放入链接？ {#how-do-i-put-a-link-inside-a-translated-sentence}

使用 `<i18n-t>`：每个具名插槽会填充同名的 `{placeholder}`。

```vue
<!-- "share": "Share your {link} with friends" -->
<i18n-t keypath="share">
  <template #link>
    <i18n-link :to="{ name: 'referral' }">{{ $t('referralLink') }}</i18n-link>
  </template>
</i18n-t>
```

参见 [`<i18n-t>`](/zh-CN/components/i18n-t)。不支持 vue-i18n 的链接消息和修饰符；请像这样在模板中进行组合。

## 语言环境与 URL {#locales-and-urls}

### `/en/about` 返回 404 {#/en/about-is-a-404}

在默认的 `prefix_except_default` 策略下，默认语言环境没有前缀：`/about` 就是英文页面。如果你想要 `/en/...`，请使用 `prefix` 或 `prefix_and_default`。参见[路由策略](/zh-CN/guide/strategy)。

### 访问深层链接时访客没有被重定向 {#visitors-are-not-redirected-on-deep-links}

默认情况下只有 `/` 会依据浏览器语言或 cookie 进行跳转，因此分享出去的链接会保持原有语言。请设置 `autoDetectPath: 'no_prefix'` 或 `'*'`。参见[语言环境检测](/zh-CN/guide/locale-detection#autodetectpath)。

### 刷新后所选语言丢失 {#the-chosen-language-is-forgotten-after-a-reload}

在前缀类策略下，语言环境 cookie 默认关闭。请设置 `localeCookie: 'user-locale'`。参见[语言环境检测](/zh-CN/guide/locale-detection#the-cookie)。

### 能否在不改变 URL 的情况下切换语言环境？ {#can-i-switch-locale-without-changing-the-url}

只有在 `strategy: 'no_prefix'` 下才可以，此时 `$switchLocale('de')` 会在同一路径上重新加载词典。在前缀类策略下，语言环境是 URL 的一部分，因此切换会触发导航。如果需要链接而不是函数调用，请使用 `$switchLocalePath('de')`。

### 切换语言环境时页面滚动到顶部 {#the-page-scrolls-to-the-top-when-i-switch-locale}

这是 Nuxt 针对任何导航的 `scrollBehavior`。请设置 `definePageMeta({ scrollToTop: false })` 并自行恢复滚动位置。playground 中的 [`SwitchLocalePreserve.vue`](https://github.com/s00d/nuxt-i18n-micro/blob/main/playground/components/SwitchLocalePreserve.vue) 是一个可直接复制使用的封装组件（[演示页面](https://github.com/s00d/nuxt-i18n-micro/blob/main/playground/pages/scroll-test.vue)）。

## 构建与集成 {#build-and-integrations}

### `nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` {#nuxt-seodefaults-depends-on-nuxt-site-configi18n-but-they-are-not-registered}

旧版 `nuxt-site-config` 只认识 `@nuxtjs/i18n`。请将 `@nuxtjs/seo` 升级到 3 或更高版本，并在 `modules` 中将 `nuxt-i18n-micro` 列在它之前。参见 [SEO](/zh-CN/guide/seo)。

### 在 Cloudflare 上出现关于 `@unhead/vue` 的构建错误 {#build-error-about-@unhead/vue-on-cloudflare}

在应用中安装 `@unhead/vue`，以便预渲染步骤能够找到它。模块本身不需要 `nodejs_compat`：只有当应用中的其他部分需要时，才在 `wrangler.toml` 中添加 `compatibility_flags = ["nodejs_compat"]`。
