在 `meta: true`（默认值）下，每个本地化页面都会获得 `<html lang dir>`、canonical 链接、`hreflang` 备用链接、`x-default` 以及 Open Graph 语言环境标签。当你想设置公开源地址、调整哪些语言环境出现在标签中，或为单个页面覆盖这些标签时，就需要阅读本页。大多数站点只需要一个 `site.url` 或 `metaBaseUrl` 以及正确的 `iso` 代码。

## 最小配置 {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

此时 `/de/about` 会渲染出：

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## 文本方向 {#text-direction}

`<html dir>` 来自语言环境的 `dir`。未设置时，从右向左书写的语言会根据 `iso`（或 `code`）获得 `rtl`：阿拉伯语、希伯来语、波斯语、乌尔都语以及其他少数语言，还有任何使用 RTL 文字的标签，例如 `az-Arab`。其他语言环境不会获得 `dir` 属性，浏览器会将其视为 `ltr`。

<Warning>

**在大型页面上，`dir: 'auto'` 会增加解析时间** — `<html>` 上的 `auto` 会让浏览器在解析时根据内容推断方向。在 Chromium 中，这项开销的增长速度快于页面规模：5,000 个元素时约 100 ms，20,000 个元素时约 1 s。仅在无法预知语言的小页面上使用它。

</Warning>

## 你会获得哪些标签 {#which-tags-you-get}

- **hreflang**：每个提供该页面的语言环境各一个标签，值为 `iso`（缺少 `iso` 时为 `code`），其 URL 带有与 canonical 相同的查询参数。通过[页面配置](/zh-CN/guide/per-component-translations)或 `routeLocales` 限制的页面只会列出其语言环境。[`hreflangBaseLanguage: true`](/zh-CN/api/module-options#hreflangbaselanguage) 还会为第一个地区语言环境添加纯语言标签（`es-ES` → `es`）。
- **x-default**：默认语言环境的 URL，仅当默认语言环境提供该页面时才输出。
- **og:locale**：由 `iso` 派生（`en-US` → `en_US`）。当映射关系不直接时，请在语言环境上设置 `og`，例如 `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`；两者都没有时，不会写入 `og:locale`，并在开发模式下发出警告。
- **canonical / og:url**：不带查询参数的当前 URL，[`canonicalQueryWhitelist`](/zh-CN/api/module-options#canonicalquerywhitelist) 中的参数除外（默认为 `page`、`sort`、`filter`、`search`、`q`、`query`、`tag`）。

按策略：

| 策略 | hreflang 与 x-default | canonical、og:url、og:locale、html 属性 |
| --- | --- | --- |
| `prefix`、`prefix_except_default`、`prefix_and_default` | 是 | 是 |
| `no_prefix` | 否（一个 URL 服务所有语言环境） | 是 |

## 设置公开源地址 {#set-the-public-origin}

绝对 URL 使用以下来源中的第一个：

1. [`metaBaseUrl`](/zh-CN/api/module-options#metabaseurl)；
2. 来自 `nuxt-site-config`（由 `@nuxtjs/seo` 安装）的 `site.url`；
3. 请求源地址，并附加 `app.baseURL`。

请固定前两者之一。

<Warning>

请求源地址回退会读取 `X-Forwarded-Host` 和 `X-Forwarded-Proto`，因为 [`metaTrustForwardedHost`](/zh-CN/api/module-options#metatrustforwardedhost) 和 `metaTrustForwardedProto` 默认为 `true`。只有在会覆盖这些请求头的代理之后，这才是安全的；否则客户端可以决定你的 canonical 链接中的主机，而缓存可能会将该页面传递给其他人。

如果应用可以被直接访问，请固定 `metaBaseUrl`：与将两个选项都设为 `false` 不同，它还会忽略伪造的 `Host`。参见[位于代理或 CDN 之后](/zh-CN/guide/deployment#behind-a-proxy-or-cdn)。

</Warning>

对于一个部署响应多个域名的情况，回退非常有用：`https://site-a.com/en/about` 和 `https://site-b.com/en/about` 各自获得自己的源地址。

在语言环境上设置 `baseUrl` 时，已知主机会使用自己的 `baseUrl`，优先于 `metaBaseUrl` 和 `site.url`，因此 canonical 和 `og:url` 会保持在该域名上，而 `hreflang` 会将每个语言环境指向其域名。其他任何主机会使用 `metaBaseUrl`，否则使用默认语言环境的 `baseUrl`，再否则使用 `site.url`，因此伪造的 `Host` 无法影响你的标签。如果这些都未设置，请求源地址回退仍然有效，并且构建时会发出警告。参见[层与域名](/zh-CN/guide/layers#multiple-domains)。

## 排除语言环境或页面 {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

如果默认语言环境设置了 `seo: false`，则不会写入 `x-default`。要为单个页面关闭这些标签，请在[页面配置](/zh-CN/guide/per-component-translations#turn-off-seo-tags)中使用 `disableMeta`，或在配置中使用 [`routeDisableMeta`](/zh-CN/api/module-options#routedisablemeta)。

## 在单个页面上覆盖标签 {#override-tags-on-one-page}

对于只有部分翻译存在的 CMS 内容，或 URL 来自 API 的情况，请使用 [`useI18nHead`](/zh-CN/composables/useI18nHead) 替换生成的标签：

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` 还可以设置或移除 `canonical`、`xDefault`、`ogLocale` 和 `ogUrl`；`disable` 会删除整个分组（`'hreflang'`、`'x-default'`、`'canonical'`、`'og'`、`'og-alternates'`、`'html'`）。请传入 getter，以便在切换语言环境后重新计算值。对于按语言环境区分的 slug，请先设置 `$setI18nRouteParams`（[本地化路径](/zh-CN/guide/custom-locale-routes#per-locale-slugs)），生成的备用链接就会自动使用它们。

## 尾部斜杠 {#trailing-slash}

`$localePath`、`$switchLocalePath`、`$switchLocaleRoute` 的路由对象、`<i18n-link>`、`<i18n-switcher>`、语言环境重定向以及 SEO URL 都遵循同一条斜杠规则：默认使用 `experimental.defaults.nuxtLink.trailingSlash`，当 i18n 路径需要不同规则时，则使用 i18n 配置中的 [`trailingSlash`](/zh-CN/api/module-options)。

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/)（sitemap、robots、schema.org）通过 `nuxt-site-config` 4+ 与本模块协同工作。请将 `nuxt-i18n-micro` 列在前面，以便站点配置能够读取语言环境，并只需设置一次 `site.url`——它也会用于上述标签。

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

翻译后的站点名称和描述来自语言环境文件中的 `nuxtSiteConfig.name` / `nuxtSiteConfig.description` 键。错误 `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` 表示 `@nuxtjs/seo` 的版本低于 3；请升级它（[#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)）。
