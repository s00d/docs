`@i18n-micro/devtools-ui` 是 Nuxt DevTools 标签页中的翻译编辑器，被打包为一个 Web 组件并附带 Vite 插件。将它添加到 Vue、React、Preact、Solid 或 Astro 项目中，即可在开发期间通过浏览器浏览和编辑翻译文件夹中的 JSON 文件。Nuxt 应用的 [Nuxt DevTools](/zh-CN/guide/devtools) 中已经内置了它。

![DevTools UI：文件树，以及在每个键旁显示默认语言环境文本的编辑器](/images/devtools/02-translations-editor-dark.webp)

## 安装 {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/devtools-ui
```

```bash npm
npm install -D @i18n-micro/devtools-ui
```

```bash yarn
yarn add -D @i18n-micro/devtools-ui
```

</CodeGroup>

没有 peer 依赖。

## 设置 {#setup}

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import { i18nDevToolsPlugin } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  plugins: [i18nDevToolsPlugin({ translationDir: 'src/locales' })],
})
```

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| `translationDir` | `'src/locales'` | 存放 JSON 文件的文件夹，相对于 Vite 根目录。 |
| `base` | `'/__i18n_api'` | API 端点的基础路径。 |
| `injectButton` | `true` | 为通过 Vite 的 `index.html` 转换提供的页面添加一个悬浮按钮。Astro 没有这类页面：见下文。 |
| `defaultLocale` | `translationDir` 中的第一个语言环境文件 | 由 `/config` 报告。 |
| `fallbackLocale` | `defaultLocale` | 由 `/config` 报告。 |

该插件只在开发服务器上运行（`apply: 'serve'`）；生产构建中不包含它的任何内容。按钮会打开 `/__i18n_devtools.html`，该页面通过插件的端点读取和保存文件：

| 端点 | 作用 |
| --- | --- |
| `GET <base>/translations` | `translationDir` 下的所有字典，按相对路径组织 |
| `POST <base>/save` | 请求体 `{ file, content }`；覆盖 `translationDir` 内已有的 `.json` 文件，其他情况返回 403。它从不创建文件 |
| `GET <base>/config` | `{ defaultLocale, fallbackLocale, locales, translationDir }`；`locales` 来自 `translationDir` 中的根级文件 |

这些端点只响应 devtools 页面：来自其他源或主机的请求返回 `403`，并且 `/save` 只接受 `application/json`（否则返回 `415`）。页面通过 Vite 的 HMR socket 获知文件变化。

在 Astro 中，请添加集成而不是插件。它会在开发工具栏中添加一个应用：

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import { i18nDevToolsIntegration } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  integrations: [i18nDevToolsIntegration({ translationDir: 'src/locales' })],
})
```

保存操作只会写入文件。通过 Vite 导入 JSON 的应用会经由 HMR 获取更新；若要将编辑直接应用到运行中的实例，请使用桥接器。

## 桥接到运行中的实例 {#bridge-to-a-live-instance}

要将编辑器嵌入到你自己的页面中，并让编辑立即应用到运行中的实例，请基于适配器创建桥接器，并将其传给 `<i18n-devtools-ui>` 元素：

```ts
import { createBridge, register } from '@i18n-micro/devtools-ui'
import { i18n, locales } from './i18n' // a runtime, React, Preact or Solid instance

register() // defines <i18n-devtools-ui> once

const bridge = createBridge({
  adapter: {
    getRouteCache: () => Object.fromEntries(i18n.storage.translations),
    addTranslations: (locale, content, merge) => i18n.addTranslations(locale, content, merge),
    addRouteTranslations: (locale, route, content, merge) => i18n.addRouteTranslations(locale, route, content, merge),
    subscribe: (cb) => i18n.subscribe(cb),
    getCurrentLocale: () => i18n.locale,
  },
  locales,
  defaultLocale: 'en',
  translationDir: 'src/locales',
})

const el = document.createElement('i18n-devtools-ui') as HTMLElement & { bridge: typeof bridge }
el.bridge = bridge
document.body.append(el)
```

`getRouteCache` 必须返回以 `locale:route` 为键的字典（`en:index`、`en:blog-post`），这正是 `i18n.storage.translations` 中保存的内容。对于 Vue 实例，请使用 `i18n.global.getRouteCache()` 和 `i18n.global.subscribeToChanges(cb)`。

`saveTranslation` 会先更新实例，然后向 `<base>/save` 发送 POST 请求。当没有端点（静态预览构建）或无法连接开发服务器时，编辑内容会保存在 `localStorage` 中；其他任何保存错误都会恢复之前的字典并抛出异常。

## API {#api}

| 导出 | 入口 |
| --- | --- |
| `i18nDevToolsPlugin(options)`、`i18nDevToolsIntegration(options)` | `@i18n-micro/devtools-ui/vite` |
| `register()`、`I18nDevToolsElement` | `@i18n-micro/devtools-ui` |
| `createBridge(options)`，类型 `BridgeAdapter`、`CreateBridgeOptions` | `@i18n-micro/devtools-ui`（也可用 `/bridge/create`） |
| 类型 `I18nDevToolsBridge` | `@i18n-micro/devtools-ui`（也可用 `/bridge`） |
| `createRpcClient`、`setupRpcHost` | `@i18n-micro/devtools-ui` |

完整签名：[包参考](/zh-CN/api/packages/devtools-ui)。
