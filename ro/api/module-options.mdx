Această pagină listează fiecare cheie a obiectului `i18n` din `nuxt.config`. Folosiți tabelele pentru a căuta un tip sau o valoare implicită, iar detaliile de mai jos pentru exemple și avertismente. Tipurile, valorile implicite și descrierile sunt generate din interfața `ModuleOptions` din [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).

```ts nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
    ],
    defaultLocale: 'en',
  },
})
```

O opțiune imbricată apare sub calea sa cu puncte: `translationPayloads.mode` este cheia `mode` a lui `translationPayloads`.

## Locale-uri și rutare {#locales-and-routing}

Ce limbi există și cum apar acestea în URL.

| Opțiune | Tip | Implicit | Descriere |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Lista locale-urilor suportate. Fiecare intrare definește un cod de locale plus metadate opționale (ISO, direcție, nume afișat etc.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Strategia de rutare URL pentru prefixele de locale. - `'no_prefix'` — fără locale în URL; locale-ul este stocat în cookie. - `'prefix_except_default'` — prefix pentru toate locale-urile, cu excepția celui implicit. - `'prefix'` — întotdeauna prefix, inclusiv pentru locale-ul implicit. - `'prefix_and_default'` — ca `prefix`, dar locale-ul implicit este accesibil și fără prefix. |
| `defaultLocale` | `string` | `'en'` | Locale-ul folosit când niciun locale nu poate fi determinat din URL sau din preferințele utilizatorului. Nu este o rezervă pentru traduceri: setați `fallbackLocale` pentru asta. |
| `localeCookie` | `string \| null` | `null` | Numele cookie-ului pentru păstrarea preferinței de locale a utilizatorului între sesiuni. Setați la `null` pentru a dezactiva persistența bazată pe cookie. Setat automat la `'user-locale'` pentru strategia `no_prefix` dacă nu este furnizat; un `null` explicit în blocul de configurare `i18n` îl menține dezactivat și acolo. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `{}` | Configurare globală a locale-urilor la nivel de rută. Permite restricționarea sau personalizarea rutelor de locale pentru anumite pagini fără a modifica componentele acestora. - `false` — exclude ruta de la localizare. - `Record<LocaleCode, string>` — căi personalizate per locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Expresie regulată personalizată (sau sursa sa ca șir) pentru potrivirea codurilor de locale în segmentele URL. Fiecare cod de locale din `locales` trebuie să se potrivească cu întregul tipar, fără flag-urile sale, altfel build-ul eșuează. |
| `noPrefixRedirect` | `boolean` | `false` | Pentru strategia `no_prefix`: când locale-ul implicit are o cale personalizată pentru o pagină (`localeRoutes` / `globalLocaleRoutes`), redirecționează calea originală a paginii către calea personalizată a locale-ului vizitatorului, altfel către cea a locale-ului implicit (de ex. `/about` → `/about-us`). Un locale fără cale personalizată proprie rămâne pe calea originală. Paginile cu segmente dinamice nu sunt redirecționate. |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Căi de exclus din rutarea i18n: un șir este un prefix de cale (`/admin` acoperă `/admin/x`) sau un glob `*` / `?`; un RegExp este testat pe cale. Paginile potrivite nu primesc variante de locale, redirecționare de locale sau 404 și sunt excluse din prerender; se randează în continuare cu traduceri. `/api`, `/_nuxt`, `/__*`, ruta traducerilor și fișierele statice comune (sitemap, robots.txt, favicon, resurse după extensie) sunt întotdeauna excluse. |
| `routeLocales` | `Record<string, string[]>` | — | Restricții de locale per rută, extrase la build din apelurile `$defineI18nRoute()`. Mapează o cale de rută (de ex. `'/about'`) la un array de coduri de locale permise. Rutele nelistate nu au restricții (toate locale-urile sunt permise). |

## Traduceri {#translations}

Unde se află fișierele de traduceri și cum sunt rezolvate cheile.

| Opțiune | Tip | Implicit | Descriere |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Calea către directorul care conține fișierele JSON de traduceri, relativă la rădăcina proiectului. |
| `disableWatcher` | `boolean` | `false` | Dezactivează watcher-ul de fișiere care creează automat fișierele de traduceri lipsă în modul de dezvoltare. |
| `routesLocaleLinks` | `{ [key: string]: string }` | `{}` | Mapează nume de rute la alte nume de rute pentru a partaja aceleași fișiere de traduceri. De exemplu, `{ 'about-us': 'about' }` înseamnă că pagina `about-us` va folosi traducerile paginii `about` în locul propriilor traduceri. |
| `plural` | `PluralFunc` | ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)`` | Funcție de pluralizare personalizată. Primește `(key, count, params, locale, getter)` și trebuie să returneze forma de plural selectată ca șir sau `null`/`undefined` pentru a reveni la logica integrată `defaultPlural` (astfel puteți suprascrie doar unele locale-uri). Pentru modulul Nuxt, funcția este serializată cu `.toString()` în `.nuxt/i18n.plural.mjs` — trebuie să fie autonomă (fără importuri / scope exterior). Un șir cu calea unui fișier **nu** este suportat. |
| `disablePageLocales` | `boolean` | `false` | Dezactivează fișierele de traduceri per pagină. Când este `true`, se încarcă doar traducerile globale (`{locale}.json`); fișierele specifice paginilor (`pages/{page}/{locale}.json`) nu sunt generate și nici încărcate. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Codul locale-ului de rezervă global. Cheile lipsă dintr-un locale sunt preluate din acest locale (combinate în fiecare payload când este construit sau încărcat); fără el, o cheie lipsă se randează ca cheia însăși. |

## Payload-uri și cache {#payloads-and-caching}

Cum ajung traducerile în browser. [Performanță](/ro/guide/performance) explică ce modifică acestea la runtime.

| Opțiune | Tip | Implicit | Descriere |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Preîncarcă traducerile paginii index în middleware-ul global Nitro (doar pe server, configurare privată). |
| `apiBaseUrl` | `string` | `'_locales'` | Segmentul de cale URL de bază pentru ruta API a traducerilor (folosit la preluarea datelor SSR/SSG). Poate fi setat și prin variabila de mediu `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Suprascrie host-ul folosit pentru cererile de traduceri pe partea de client. Util când clientul ajunge la server printr-un hostname diferit de cel pe care îl vede Nuxt. Poate fi setat și prin variabila de mediu `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Suprascrie host-ul folosit pentru cererile de traduceri pe partea de server. Util în configurații cu containere/microservicii, unde serverul ajunge la el însuși printr-un hostname intern. Poate fi setat și prin variabila de mediu `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Controlează modul în care sunt emise payload-urile de traduceri (server Node: `public/<apiBaseUrl>`; Edge / function / inline: `serverAssets` Nitro). - **Server Node** (`node-server`, `node-cluster`, `serveStatic` de pe disc): `serverAssets` înseamnă SSR local prin `readFile` sub `public/` (fără Rollup `raw:`). - **Edge, preset-uri function și `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …): `serverAssets` înregistrează `serverAssets` Nitro (`assets:i18n`),   deoarece `public/` nu este disponibil pe disc pentru SSR. Nu forțează o copie publică — setați `publicAssets: true` pentru CDN/static. Păstrați valorile implicite pentru configurația obișnuită all-in-one. Pentru cataloage Edge mari, preferați `mode: 'source'`. Pentru deployment-uri bazate pe CDN, dezactivați output-urile locale și setați `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Strategia pentru payload-urile de traduceri. - `premerged`: matrice `{page}/{locale}/data.json` la build (implicit) - `source`: fișiere sursă compacte combinate la runtime (preferat pe Edge / cataloage mari) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Payload-uri SSR locale: un server Node care servește `public/` de pe disc citește acel arbore (forțează copia publică); Edge, preset-urile function și `serveStatic: "inline"` încorporează prin `serverAssets` Nitro. - **Server Node** (preset-ul servește singur `public/`, de ex. `node-server`): fără `serverAssets` Nitro (evită Rollup `raw:`). SSR citește   `public/<apiBaseUrl\|publicDir>` ca `{page}/{locale}/data.json`; când aceasta este `true`,   o copie publică este forțată chiar dacă `publicAssets` este false. - **Edge, preset-uri function și inline** (`nitro.node === false`, fără `serveStatic` de pe disc, precum `vercel` /   `netlify` / `aws-lambda`, sau `serveStatic: "inline"`, de ex. winterjs): `serverAssets` Nitro (`assets:i18n`)   cu aceeași structură ca `mode`. **Nu** forțează o copie publică — setați `publicAssets: true` pentru CDN/static. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Înregistrează ruta de server integrată la `/{apiBaseUrl}/:page/:locale/data.json`. Dezactivați-o când payload-urile de traduceri sunt servite de un host/CDN extern. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Copiază payload-urile în output-ul public Nitro. Premerged → `{page}/{locale}/data.json` sub `apiBaseUrl`; source → arbore compact. Când SSR citește `public/` (`node-server` și similare), `serverAssets: true` forțează și această copie. Pe preset-urile Edge / function / `serveStatic: "inline"`, copiază doar când aceasta este `true` (SSR folosește încorporarea Nitro). |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Activează prerender-ul Nitro pentru `/{apiBaseUrl}/.../data.json`. De obicei redundant când `publicAssets` premerged a scris deja acele fișiere. |
| `translationPayloads.publicDir` | `string` | — | Folderul de output public relativ la rădăcina publică Nitro. Implicit `apiBaseUrl` (`_locales`). Astfel, fișierele statice corespund URL-urilor de fetch ale clientului (`/{apiBaseUrl}/{page}/{locale}/data.json`). |
| `translationPayloads.rootDelta` | `boolean` | `true` | Scrie un fișier rădăcină per locale, iar în fiecare fișier de pagină doar ce diferă de acesta. Clientul și SSR le combină; un chunk întreg funcționează în continuare oriunde este citit un fișier. `false` păstrează un dicționar întreg în fiecare fișier de pagină. Doar `premerged` și dezactivat cu `disablePageLocales`. |
| `translationPayloads.warnFileCount` | `number` | `500` | Afișează un avertisment la build când numărul de fișiere de payload generate depășește acest prag. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Afișează un avertisment la build când dimensiunea totală a payload-urilor generate depășește acest prag în octeți. |

## SEO {#seo}

Meta tag-urile generate pentru fiecare pagină localizată.

| Opțiune | Tip | Implicit | Descriere |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Generează automat meta tag-uri SEO (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | URL-ul de bază pentru meta tag-urile SEO (canonical, og:url, hreflang). - Un șir URL concret (de ex. `'https://example.com'`) — folosit ca atare (prioritate maximă). - `undefined` — revine la `site.url` din `nuxt-site-config` când acel modul este   prezent, altfel la originea cererii curente   (`useRequestURL().origin` pe server, `window.location.origin` pe client). |
| `metaTrustForwardedHost` | `boolean` | `true` | Are încredere în header-ul `X-Forwarded-Host` la rezolvarea URL-ului de bază pentru meta tag-uri. Activați-l când aplicația rulează în spatele unui reverse proxy (nginx, Cloudflare, AWS ALB etc.) care setează acest header la hostname-ul real văzut de client. |
| `metaTrustForwardedProto` | `boolean` | `true` | Are încredere în header-ul `X-Forwarded-Proto` la rezolvarea protocolului pentru meta tag-uri. Activați-l când aplicația rulează în spatele unui proxy care termină TLS, astfel încât URL-urile canonice să folosească `https://` chiar dacă aplicația ascultă pe HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Lista numelor de parametri de query păstrați în meta tag-urile canonical și `og:url`. Parametrii care nu sunt în această listă sunt eliminați din URL-ul canonic. |

## Detectare și redirecționări {#detection-and-redirects}

Alegerea unui locale pentru un vizitator care nu a ales unul.

| Opțiune | Tip | Implicit | Descriere |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Activează redirecționările automate de locale (plugin de server și middleware de rută pe client). Când este `true`, strategiile cu prefix redirecționează un URL fără prefix către forma sa localizată. Locale-ul provine din starea aplicației, din cookie sau din `Accept-Language` unde permite `autoDetectPath`, altfel cel implicit. Sub `no_prefix`, detectarea nu modifică niciodată URL-ul (vedeți `noPrefixRedirect` pentru căi personalizate). |
| `autoDetectLanguage` | `boolean` | `true` | Detectează automat limba preferată a utilizatorului din header-ul HTTP `Accept-Language`. Folosit în combinație cu `autoDetectPath` pentru a decide când are loc detectarea. |
| `autoDetectPath` | `string` | `'/'` | Unde pot rula redirecționările după preferința din cookie / Accept-Language (când `redirects` este activat). - `'/'` — doar `/` (link-urile directe în locale-ul implicit rămân accesibile; implicit) - `'no_prefix'` — doar căile fără prefix de locale - `'*'` — fiecare cale, inclusiv rescrierea unui prefix de locale explicit   (de ex. `/fr/about` → `/de/about` când cookie-ul preferă `de`) - orice alt șir — acea cale, ignorând slash-urile finale (de ex. `'/welcome'`) Sub `prefix`, un URL fără prefix din afara căilor permise redirecționează în continuare către forma locale-ului implicit (`/about` → `/en/about`). Locale-ul implicit cu prefix sub `prefix_except_default` (`/en`) este un 404, nu o redirecționare. |

## Înregistrare {#registration}

Părți ale modulului pe care le puteți dezactiva.

| Opțiune | Tip | Implicit | Descriere |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Furnizează `$defineI18nRoute()` la runtime. Build-ul citește oricum apelurile `$defineI18nRoute()` din pagini. |
| `plugin` | `boolean` | `true` | Înregistrează plugin-ul i18n de bază care furnizează `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` și alți helperi de runtime. |
| `hooks` | `boolean` | `true` | Apelează hook-ul de aplicație `i18n:register` la încărcare și la navigare, astfel încât plugin-urile să poată adăuga traduceri. |
| `components` | `boolean` | `true` | Înregistrează componentele i18n integrate (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Setați la `false` pentru a dezactiva înregistrarea automată a componentelor (de ex. dacă nu le folosiți și doriți să reduceți amprenta modulului). |
| `types` | `boolean` | `true` | Generează declarații de tipuri TypeScript pentru `useI18n`, `$t` și helperii aferenți, pe baza cheilor de traducere din fișierele locale-ului implicit. |
| `debug` | `boolean` | `false` | Activează logarea detaliată de depanare pentru detectarea locale-ului, generarea rutelor și încărcarea traducerilor. |

## Altele {#other}

| Opțiune | Tip | Implicit | Descriere |
| --- | --- | --- | --- |
| `trustForwardedHost` | `boolean` | `false` | Alege domeniul unei cereri (`locales[].baseUrl`) din `X-Forwarded-Host` în loc de `Host`. Activați-l doar în spatele unui proxy care suprascrie acel header. |
| `hreflangBaseLanguage` | `boolean` | `false` | Emite și un `hreflang` doar cu limba, derivat din `iso` al fiecărui locale (de ex. `es-ES` → și `es`). Primul locale regional din `locales` revendică tag-ul simplu pentru acea limbă. `code` de rutare nu este folosit niciodată — doar `iso \|\| code`. |
| `additionalTranslationDirs` | `string[]` | `[]` | Directoare suplimentare (relative la rădăcina proiectului / rădăcina fiecărui layer Nuxt) ale căror fișiere `{locale}.json` de nivel superior sunt combinate profund în dicționarul global înainte de `translationDir`. Ordinea combinării: fiecare intrare în ordinea din array (între layer-e), apoi `translationDir` (câștigă la conflicte). Se citesc doar fișierele `{locale}.json` rădăcină — `pages/` din aceste directoare este ignorat. Exemplu: `translationDir: 'frontend'`, `additionalTranslationDirs: ['common']` → `common/en.json`, apoi `frontend/en.json`. |
| `vueDevtools` | `boolean` | `true` | Înregistrează inspectorul și cronologia Vue DevTools în dev (extensie de browser). Separat de fila personalizată Nuxt DevTools. |
| `trailingSlash` | `'append' \| 'remove'` | `undefined (inherit from Nuxt)` | Slash-ul final pentru `$localePath` / `$switchLocalePath` (paritate cu NuxtLink). Implicit `experimental.defaults.nuxtLink.trailingSlash` când nu este setat. Setați-l explicit pentru a suprascrie valoarea implicită a link-urilor Nuxt pentru helperii de căi i18n. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Prefixul adăugat înaintea numelor rutelor localizate (de ex. `'localized-index'`). Folosit intern pentru a distinge rutele originale de variantele de locale generate. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Dezactivarea meta tag-urilor per rută. Mapează un nume sau o cale de rută la `true` (dezactivează toate meta tag-urile) sau la un array de coduri de locale pentru care meta tag-urile trebuie dezactivate. Intrările găsite în apelurile `$defineI18nRoute()` la build sunt adăugate. |
| `missingWarn` | `boolean` | `true` | Afișează avertismente în consolă când lipsește o cheie de traducere (build de dezvoltare, în browser). |
| `hmr` | `boolean` | `true` | Activează Hot Module Replacement pentru fișierele de traduceri în dezvoltare. Când este `true`, modificările fișierelor JSON de traduceri declanșează o reîncărcare automată fără reîmprospătarea completă a paginii. |
| `cacheMaxSize` | `number` | `0` | Numărul maxim de intrări în cache-urile de traduceri din memorie. Cache-urile de fetch și de server elimină intrarea cel mai puțin recent folosită; harta de dicționare a browserului o elimină pe cea mai veche (FIFO). `0` înseamnă fără limită în browser; cache-urile de server păstrează atunci cel mult 1000 de intrări, astfel încât URL-urile de cereri cu pagini inventate nu pot crește memoria serverului. |
| `cacheTtl` | `number` | `0` | Durata de viață (în secunde) a cache-urilor de traduceri de fetch și de server, numărată de la momentul stocării unei intrări (citirile nu o prelungesc), astfel încât datele de la `apiBaseServerHost` sunt reîmprospătate cel puțin atât de des. Dicționarele active ale browserului nu expiră din cauza ei. `0` înseamnă că intrările nu expiră niciodată. |
| `cacheStorage` | `string` | — | Numele unei montări de stocare Nitro (`nitro.storage`, de ex. `'redis'`) pe care mai multe instanțe de server o partajează ca cache de dicționare, citită după cache-ul din proces și înaintea sursei. Merită mai ales cu `apiBaseServerHost`: o singură descărcare din backend în loc de una per instanță. Intrările au chei după build și expiră după `cacheTtl` sau după o zi când acesta este `0`. Dezactivat în dev și la prerender. O stocare defectă revine la sursă. Nesetat: fără cache comun. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Formate de numere denumite per locale (compatibile cu Vue I18n). Permite apeluri de tipul `$tn(1000, 'currency')`. |
| `timeZone` | `string` | `the runtime's zone` | Fusul orar IANA pentru `$td` și `<i18n-t date>` (`Europe/Berlin`). Setați-l pentru a randa aceeași dată pe server și în fiecare browser; `timeZone` propriu al unui format denumit are prioritate. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Formate de dată/oră denumite per locale (`datetimeFormats` compatibil cu Vue I18n). Permite apeluri de tipul `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | max-age `Cache-Control` HTTP (secunde) pentru `/{apiBaseUrl}/:page/:locale/data.json`. Se aplică integral doar cât timp `dateBuild` invalidează URL-ul (`?v=...`), ceea ce este implicit: răspunsul este atunci `private, max-age=…, immutable`: un browser îl fixează, iar un CDN care ignoră query-ul nu poate (`public` cu `httpCacheControl: false`). - `dateBuild: 0`/`''` — URL-ul este stabil, deci această durată *nu* este respectată; răspunsul devine   în schimb `public, max-age=0, must-revalidate`. Un `max-age` lung pe un   URL care nu se schimbă fixează primul payload văzut vreodată de un browser. - `0` — nu setează deloc `Cache-Control` (util la depanarea locală) - Nu se aplică în dezvoltare (`import.meta.dev`), astfel încât HMR nu intră în conflict cu cache-ul browserului - Ajunge doar la răspunsurile servite prin Nitro. Payload-urile copiate în `public/` și servite   de platforma de hosting primesc header-ele acelei platforme — vedeți ghidul de performanță. Analog cu `httpCacheDuration` experimental din `@nuxtjs/i18n` (v10.2.0), dar ca header de răspuns explicit în loc de maxAge din `defineCachedEventHandler` Nitro. |
| `httpCacheControl` | `string \| false` | `'public, max-age=60'` | `Cache-Control` al unui fișier de payload servit de un host sau de o regulă la nivel de cale, care nu poate vedea `?v=`. Pe un server Node, un răspuns la `?v=` curent este fixat pentru `httpCacheDuration`, iar oricare altul se revalidează; cu `source`, `cacheTtl` sau `apiBaseServerHost`, unde un dicționar se schimbă fără build, fiecare răspuns primește acest header. `false` menține fiecare fișier pe `max-age=0, must-revalidate`. |
| `dateBuild` | `string \| number` | — | Valoarea folosită pentru cache-busting-ul cererilor de traduceri (`?v=...`). Când nu este furnizată, modulul folosește un hash al fișierelor de traduceri, astfel încât valoarea se schimbă doar când se schimbă traducerile (`Date.now()` când nu se poate calcula niciun hash). `0` sau `''` dezactivează cache-busting-ul. Setați o valoare stabilă (un SHA git, un număr de build) pentru a o fixa singuri. `NUXT_I18N_DATE_BUILD` sau `runtimeConfig.public.i18nRuntime.dateBuild` o înlocuiește la runtime, după ce un dicționar a fost înlocuit pe loc: URL-urile fixate sunt lăsate în urmă, fără rebuild. |
| `experimental` | `Record<string, unknown>` | — | Spațiu pentru opțiuni experimentale/instabile. Conținutul se poate schimba sau poate fi eliminat fără notificare între versiunile minore. |

### Locale-uri și URL-uri {#locales-and-urls}

#### `locales` {#locales}

**Tip** `Locale[]` · **Implicit** `[]`

Lista locale-urilor suportate.
Fiecare intrare definește un cod de locale plus metadate opționale (ISO, direcție, nume afișat etc.).

Fiecare intrare este un obiect `Locale`:

| Proprietate | Tip | Descriere |
| --- | --- | --- |
| `code` | `string` | **Obligatoriu.** Segmentul URL și numele fișierului (`en`, `de-at`). |
| `iso` | `string` | Tag BCP-47 pentru `<html lang>`, `hreflang`, plurale și `$tn` / `$td` / `$tdr` (`en-US`). |
| `displayName` | `string` | Eticheta din `<i18n-switcher>` și `$getLocaleName()`. |
| `dir` | `'ltr' \| 'rtl' \| 'auto'` | `<html dir>`. Fără el, limbile RTL cunoscute primesc `rtl`, iar orice alt locale nu primește atributul. Vedeți [SEO](/ro/guide/seo#text-direction). |
| `disabled` | `boolean` | Exclus din rute, payload-uri și comutare. Prefixul său este un 404, iar link-urile către el rămân pe pagină. |
| `fallbackLocale` | `string` | Rezerva pentru acest locale; suprascrie `fallbackLocale` global. |
| `seo` | `boolean` | `false` exclude locale-ul din `hreflang` și `og:locale:alternate`. |
| `og` | `string` | Valoarea `og:locale` (`ar_AE`); implicit: `iso` convertit. |
| `baseUrl` | `string` | Domeniul propriu al locale-ului: un singur build îl servește, iar link-urile către el din alte domenii sunt absolute. |
| `baseDefault` | `boolean` | Cu `baseUrl`: locale-ul implicit al host-ului său, fără prefix `/<code>` în link-urile către el (`prefix` îl păstrează). |

Celelalte proprietăți sunt păstrate și returnate de `$getLocales()`. Tipizați-le prin augmentarea `Locale`:

```ts
// i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
  }
}
export {}
```

Modulul ridică (hoist) `@i18n-micro/types`, așa că aceasta funcționează sub pnpm fără a instala pachetul.

#### `defaultLocale` {#defaultlocale}

**Tip** `string` · **Implicit** `'en'`

Locale-ul folosit când niciun locale nu poate fi determinat din URL sau din preferințele utilizatorului.
Nu este o rezervă pentru traduceri: setați `fallbackLocale` pentru asta.

#### `strategy` {#strategy}

**Tip** `Strategies` · **Implicit** `'prefix_except_default'`

Strategia de rutare URL pentru prefixele de locale.

- `'no_prefix'` — fără locale în URL; locale-ul este stocat în cookie.
- `'prefix_except_default'` — prefix pentru toate locale-urile, cu excepția celui implicit.
- `'prefix'` — întotdeauna prefix, inclusiv pentru locale-ul implicit.
- `'prefix_and_default'` — ca `prefix`, dar locale-ul implicit este accesibil și fără prefix.

URL-urile pentru fiecare strategie și redirecționările: [Strategii de rutare](/ro/guide/strategy).

#### `globalLocaleRoutes` {#globallocaleroutes}

**Tip** `GlobalLocaleRoutes` · **Implicit** `{}`

Configurare globală a locale-urilor la nivel de rută.
Permite restricționarea sau personalizarea rutelor de locale pentru anumite pagini fără
a modifica componentele acestora.

- `false` — exclude ruta de la localizare.
- `Record<LocaleCode, string>` — căi personalizate per locale.

Cheile sunt nume sau căi de rute. De obicei se setează per pagină cu [`$defineI18nRoute`](/ro/guide/per-component-translations).

```ts
globalLocaleRoutes: {
  about: { en: '/about-us', de: '/ueber-uns' },
  'admin-dashboard': false, // not localized
}
```

Detalii, segmente dinamice și rute `pages:extend`: [Căi localizate](/ro/guide/custom-locale-routes).

#### `routeLocales` {#routelocales}

**Tip** `Record<string, string[]>` · **Implicit** —

Restricții de locale per rută, extrase la build din apelurile `$defineI18nRoute()`.
Mapează o cale de rută (de ex. `'/about'`) la un array de coduri de locale permise.
Rutele nelistate nu au restricții (toate locale-urile sunt permise).

#### `routeDisableMeta` {#routedisablemeta}

**Tip** `Record<string, boolean \| string[]>` · **Implicit** —

Dezactivarea meta tag-urilor per rută. Mapează un nume sau o cale de rută la `true` (dezactivează toate meta tag-urile) sau la un array
de coduri de locale pentru care meta tag-urile trebuie dezactivate. Intrările găsite în apelurile `$defineI18nRoute()`
la build sunt adăugate.

#### `customRegexMatcher` {#customregexmatcher}

**Tip** `string \| RegExp` · **Implicit** `undefined (uses built-in pattern based on locale codes)`

Expresie regulată personalizată (sau sursa sa ca șir) pentru potrivirea codurilor de locale în segmentele URL.
Fiecare cod de locale din `locales` trebuie să se potrivească cu întregul tipar, fără flag-urile sale, altfel build-ul eșuează.

```ts
customRegexMatcher: '[a-z]{2}-[a-z]{2}', // en-us, de-at
```

#### `excludePatterns` {#excludepatterns}

**Tip** `(string \| RegExp)[]` · **Implicit** `undefined`

Căi de exclus din rutarea i18n: un șir este un prefix de cale (`/admin` acoperă `/admin/x`)
sau un glob `*` / `?`; un RegExp este testat pe cale. Paginile potrivite nu primesc variante
de locale, redirecționare de locale sau 404 și sunt excluse din prerender; se randează în continuare cu
traduceri. `/api`, `/_nuxt`, `/__*`, ruta traducerilor și fișierele statice comune
(sitemap, robots.txt, favicon, resurse după extensie) sunt întotdeauna excluse.

```ts
excludePatterns: ['/admin', '/docs/*', /^\/preview\//],
```

Mai multe: [Excluderea căilor](/ro/guide/excluding-static-files).

#### `localizedRouteNamePrefix` {#localizedroutenameprefix}

**Tip** `string` · **Implicit** `'localized-'`

Prefixul adăugat înaintea numelor rutelor localizate (de ex. `'localized-index'`).
Folosit intern pentru a distinge rutele originale de variantele de locale generate.

#### `trailingSlash` {#trailingslash}

**Tip** `'append' \| 'remove'` · **Implicit** `undefined (inherit from Nuxt)`

Slash-ul final pentru `$localePath` / `$switchLocalePath` (paritate cu NuxtLink).
Implicit `experimental.defaults.nuxtLink.trailingSlash` când nu este setat.
Setați-l explicit pentru a suprascrie valoarea implicită a link-urilor Nuxt pentru helperii de căi i18n.

### Traduceri {#translations}

#### `translationDir` {#translationdir}

**Tip** `string` · **Implicit** `'locales'`

Calea către directorul care conține fișierele JSON de traduceri, relativă la rădăcina proiectului.

Relativă la rădăcina fiecărui layer, nu la `app/` (`'app/locales'` pentru o structură Nuxt 4). Structura fișierelor: [Fișiere de traduceri](/ro/guide/translations).

#### `additionalTranslationDirs` {#additionaltranslationdirs}

**Tip** `string[]` · **Implicit** `[]`

Directoare suplimentare (relative la rădăcina proiectului / rădăcina fiecărui layer Nuxt) ale căror fișiere
`{locale}.json` de nivel superior sunt combinate profund în dicționarul global înainte de `translationDir`.

Ordinea combinării: fiecare intrare în ordinea din array (între layer-e), apoi `translationDir` (câștigă la conflicte).
Se citesc doar fișierele `{locale}.json` rădăcină — `pages/` din aceste directoare este ignorat.

Exemplu: `translationDir: 'frontend'`, `additionalTranslationDirs: ['common']` → `common/en.json`, apoi `frontend/en.json`.

#### `disablePageLocales` {#disablepagelocales}

**Tip** `boolean` · **Implicit** `false`

Dezactivează fișierele de traduceri per pagină.
Când este `true`, se încarcă doar traducerile globale (`{locale}.json`);
fișierele specifice paginilor (`pages/{page}/{locale}.json`) nu sunt generate și nici încărcate.

#### `fallbackLocale` {#fallbacklocale}

**Tip** `string` · **Implicit** `undefined (no fallback; returns the raw key)`

Codul locale-ului de rezervă global.
Cheile lipsă dintr-un locale sunt preluate din acest locale (combinate în fiecare payload când este
construit sau încărcat); fără el, o cheie lipsă se randează ca cheia însăși.

#### `routesLocaleLinks` {#routeslocalelinks}

**Tip** `{ [key: string]: string }` · **Implicit** `{}`

Mapează nume de rute la alte nume de rute pentru a partaja aceleași fișiere de traduceri.
De exemplu, `{ 'about-us': 'about' }` înseamnă că pagina `about-us` va folosi
traducerile paginii `about` în locul propriilor traduceri.

```ts
routesLocaleLinks: { 'products-id': 'products' },
```

#### `plural` {#plural}

**Tip** `PluralFunc` · **Implicit** ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)``

Funcție de pluralizare personalizată.
Primește `(key, count, params, locale, getter)` și trebuie să returneze forma de plural
selectată ca șir sau `null`/`undefined` pentru a reveni la logica integrată
`defaultPlural` (astfel puteți suprascrie doar unele locale-uri).

Pentru modulul Nuxt, funcția este serializată cu `.toString()` în
`.nuxt/i18n.plural.mjs` — trebuie să fie autonomă (fără importuri / scope exterior).
Un șir cu calea unui fișier **nu** este suportat.

Regula integrată și marcajul său `=0 ` sunt descrise la [`$tc`](/ro/api/methods#$tc). Funcția voastră o înlocuiește pentru ce răspunde, primește valoarea brută cu orice marcaj păstrat, iar `null` predă apelul înapoi regulii integrate. Funcția primește `(key, count, params, locale, getter)`; `getter(key)` returnează șirul brut cu toate formele. Scrieți-o ca o expresie `function` sau arrow autonomă (fără sintaxa scurtă de metodă, fără importuri, fără variabile exterioare):

```ts
plural: function (key, count, params, locale, getter) {
  if (!locale.startsWith('en')) return null // built-in rule for other locales
  const forms = String(getter(key) ?? '').split('|').map((form) => form.trim())
  const index = count === 0 ? 0 : count === 1 ? 1 : 2
  return (forms[Math.min(index, forms.length - 1)] ?? '').replace('{count}', String(count))
},
```

```json
{ "apples": "no apples | one apple | {count} apples" }
```

Formate de numere denumite per locale (compatibile cu Vue I18n).

Folosit de [`$tn`](/ro/api/methods#$tn).

Folosit de [`$td`](/ro/api/methods#$td).

#### `disableWatcher` {#disablewatcher}

**Tip** `boolean` · **Implicit** `false`

### Payload-uri și cache {#payloads-and-caching}

#### `translationPayloads` {#translationpayloads}

**Tip** `TranslationPayloadOptions` · **Implicit** —

Controlează modul în care sunt emise payload-urile de traduceri (server Node: `public/<apiBaseUrl>`; Edge / function / inline: `serverAssets` Nitro).

- **Server Node** (`node-server`, `node-cluster`, `serveStatic` de pe disc): `serverAssets` înseamnă SSR local prin `readFile` sub `public/` (fără Rollup `raw:`).
- **Edge, preset-uri function și `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …): `serverAssets` înregistrează `serverAssets` Nitro (`assets:i18n`),
  deoarece `public/` nu este disponibil pe disc pentru SSR. Nu forțează o copie publică — setați `publicAssets: true` pentru CDN/static.

Păstrați valorile implicite pentru configurația obișnuită all-in-one. Pentru cataloage Edge mari, preferați `mode: 'source'`.
Pentru deployment-uri bazate pe CDN, dezactivați output-urile locale și setați `apiBaseClientHost` / `apiBaseServerHost`.

Sub-opțiunile se află în tabelul [Payload-uri și cache](#payloads-and-caching). Ce combinație se potrivește pentru Node, serverless, Edge, hosting static sau un CDN: [Deployment](/ro/guide/deployment).

#### `apiBaseUrl` {#apibaseurl}

**Tip** `string` · **Implicit** `'_locales'`

Segmentul de cale URL de bază pentru ruta API a traducerilor (folosit la preluarea datelor SSR/SSG).
Poate fi setat și prin variabila de mediu `NUXT_I18N_APP_BASE_URL`.

URL-urile payload-urilor sunt `/{apiBaseUrl}/{page}/{locale}/data.json`.

#### `apiBaseClientHost` {#apibaseclienthost}

**Tip** `string` · **Implicit** `undefined`

Suprascrie host-ul folosit pentru cererile de traduceri pe partea de client.
Util când clientul ajunge la server printr-un hostname diferit de cel pe care îl vede Nuxt.
Poate fi setat și prin variabila de mediu `NUXT_I18N_APP_BASE_CLIENT_HOST`.

#### `apiBaseServerHost` {#apibaseserverhost}

**Tip** `string` · **Implicit** `undefined`

Suprascrie host-ul folosit pentru cererile de traduceri pe partea de server.
Util în configurații cu containere/microservicii, unde serverul ajunge la el însuși printr-un hostname intern.
Poate fi setat și prin variabila de mediu `NUXT_I18N_APP_BASE_SERVER_HOST`.

Un host trebuie să servească aceleași răspunsuri `/{apiBaseUrl}/{page}/{locale}/data.json` ca ruta integrată.

#### `dateBuild` {#datebuild}

**Tip** `string \| number` · **Implicit** —

Valoarea folosită pentru cache-busting-ul cererilor de traduceri (`?v=...`).

Când nu este furnizată, modulul folosește un hash al fișierelor de traduceri, astfel încât valoarea se schimbă
doar când se schimbă traducerile (`Date.now()` când nu se poate calcula niciun hash). `0` sau `''` dezactivează
cache-busting-ul. Setați o valoare stabilă (un SHA git, un număr de build) pentru a o fixa singuri.
`NUXT_I18N_DATE_BUILD` sau `runtimeConfig.public.i18nRuntime.dateBuild` o înlocuiește la runtime, după ce un dicționar
a fost înlocuit pe loc: URL-urile fixate sunt lăsate în urmă, fără rebuild.

#### `httpCacheDuration` {#httpcacheduration}

**Tip** `number` · **Implicit** `31536000`

max-age `Cache-Control` HTTP (secunde) pentru `/{apiBaseUrl}/:page/:locale/data.json`.

Se aplică integral doar cât timp `dateBuild` invalidează URL-ul (`?v=...`), ceea ce este implicit:
răspunsul este atunci `private, max-age=…, immutable`: un browser îl fixează, iar un CDN care ignoră query-ul nu poate
(`public` cu `httpCacheControl: false`).

- `dateBuild: 0`/`''` — URL-ul este stabil, deci această durată *nu* este respectată; răspunsul
  devine în schimb `public, max-age=0, must-revalidate`. Un `max-age` lung pe un
  URL care nu se schimbă fixează primul payload văzut vreodată de un browser.

- `0` — nu setează deloc `Cache-Control` (util la depanarea locală)
- Nu se aplică în dezvoltare (`import.meta.dev`), astfel încât HMR nu intră în conflict cu cache-ul browserului
- Ajunge doar la răspunsurile servite prin Nitro. Payload-urile copiate în `public/` și servite
  de platforma de hosting primesc header-ele acelei platforme — vedeți ghidul de performanță.

Analog cu `httpCacheDuration` experimental din `@nuxtjs/i18n` (v10.2.0), dar ca
header de răspuns explicit în loc de maxAge din `defineCachedEventHandler` Nitro.

#### `cacheMaxSize` {#cachemaxsize}

**Tip** `number` · **Implicit** `0`

Numărul maxim de intrări în cache-urile de traduceri din memorie. Cache-urile de fetch și de server
elimină intrarea cel mai puțin recent folosită; harta de dicționare a browserului o elimină pe cea mai veche (FIFO).
`0` înseamnă fără limită în browser; cache-urile de server păstrează atunci cel mult 1000 de intrări, astfel încât
URL-urile de cereri cu pagini inventate nu pot crește memoria serverului.

#### `cacheTtl` {#cachettl}

**Tip** `number` · **Implicit** `0`

Durata de viață (în secunde) a cache-urilor de traduceri de fetch și de server, numărată de la momentul
stocării unei intrări (citirile nu o prelungesc), astfel încât datele de la `apiBaseServerHost` sunt reîmprospătate
cel puțin atât de des. Dicționarele active ale browserului nu expiră din cauza ei. `0` înseamnă că intrările
nu expiră niciodată.

Ce modifică ambele la runtime: [Performanță](/ro/guide/performance).

#### `serverTranslationPreload` {#servertranslationpreload}

**Tip** `boolean` · **Implicit** `false`

Preîncarcă traducerile paginii index în middleware-ul global Nitro (doar pe server, configurare privată).

### SEO {#seo}

#### `meta` {#meta}

**Tip** `boolean` · **Implicit** `true`

Generează automat meta tag-uri SEO (`hreflang`, `canonical`, `og:url`, `og:locale`).

Suprascrieri per pagină: [`useI18nHead`](/ro/composables/useI18nHead). Tot restul: [SEO](/ro/guide/seo).

#### `metaBaseUrl` {#metabaseurl}

**Tip** `string` · **Implicit** `undefined`

URL-ul de bază pentru meta tag-urile SEO (canonical, og:url, hreflang).

- Un șir URL concret (de ex. `'https://example.com'`) — folosit ca atare (prioritate maximă).
- `undefined` — revine la `site.url` din `nuxt-site-config` când acel modul este
  prezent, altfel la originea cererii curente
  (`useRequestURL().origin` pe server, `window.location.origin` pe client).

#### `metaTrustForwardedHost` {#metatrustforwardedhost}

**Tip** `boolean` · **Implicit** `true`

Are încredere în header-ul `X-Forwarded-Host` la rezolvarea URL-ului de bază pentru meta tag-uri.
Activați-l când aplicația rulează în spatele unui reverse proxy (nginx, Cloudflare, AWS ALB etc.)
care setează acest header la hostname-ul real văzut de client.

Este citit doar când nici `metaBaseUrl`, nici `site.url` nu sunt setate. Setați-l la `false` când aplicația este accesibilă fără un proxy care suprascrie header-ul: altfel, un client ar putea alege host-ul din URL-urile voastre canonice.

#### `metaTrustForwardedProto` {#metatrustforwardedproto}

**Tip** `boolean` · **Implicit** `true`

Are încredere în header-ul `X-Forwarded-Proto` la rezolvarea protocolului pentru meta tag-uri.
Activați-l când aplicația rulează în spatele unui proxy care termină TLS, astfel încât
URL-urile canonice să folosească `https://` chiar dacă aplicația însăși ascultă pe HTTP.

Același domeniu de aplicare ca `metaTrustForwardedHost`.

#### `trustForwardedHost` {#trustforwardedhost}

**Tip** `boolean` · **Implicit** `false`

Alege domeniul unei cereri (`locales[].baseUrl`) din `X-Forwarded-Host` în loc de
`Host`. Activați-l doar în spatele unui proxy care suprascrie acel header.

Separat de `metaTrustForwardedHost` și dezactivat implicit: aici header-ul ar selecta locale-urile altui domeniu, nu doar originea unui tag. Vedeți [Layer-e și domenii](/ro/guide/layers#multiple-domains).

#### `hreflangBaseLanguage` {#hreflangbaselanguage}

**Tip** `boolean` · **Implicit** `false`

Emite și un `hreflang` doar cu limba, derivat din `iso` al fiecărui locale
(de ex. `es-ES` → și `es`). Primul locale regional din `locales` revendică
tag-ul simplu pentru acea limbă. `code` de rutare nu este folosit niciodată — doar `iso || code`.

#### `canonicalQueryWhitelist` {#canonicalquerywhitelist}

**Tip** `string[]` · **Implicit** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

Lista numelor de parametri de query păstrați în meta tag-urile canonical și `og:url`.
Parametrii care nu sunt în această listă sunt eliminați din URL-ul canonic.

### Detectare și redirecționări {#detection-and-redirects}

Regulile pe care le alimentează aceste opțiuni: [Detectarea locale-ului](/ro/guide/locale-detection).

#### `redirects` {#redirects}

**Tip** `boolean` · **Implicit** `true`

Activează redirecționările automate de locale (plugin de server și middleware de rută pe client).
Când este `true`, strategiile cu prefix redirecționează un URL fără prefix către forma sa localizată. Locale-ul
provine din starea aplicației, din cookie sau din `Accept-Language` unde permite `autoDetectPath`, altfel
cel implicit. Sub `no_prefix`, detectarea nu modifică niciodată URL-ul (vedeți `noPrefixRedirect` pentru căi personalizate).

Cu `false`, middleware-ul de redirecționare de pe client nu este înregistrat. Plugin-ul de server returnează în continuare 404 pentru URL-urile cu locale invalid și scrie cookie-ul pentru un URL cu prefix.

#### `autoDetectLanguage` {#autodetectlanguage}

**Tip** `boolean` · **Implicit** `true`

Detectează automat limba preferată a utilizatorului din header-ul HTTP `Accept-Language`.
Folosit în combinație cu `autoDetectPath` pentru a decide când are loc detectarea.

#### `autoDetectPath` {#autodetectpath}

**Tip** `string` · **Implicit** `'/'`

Unde pot rula redirecționările după preferința din cookie / Accept-Language (când `redirects` este activat).

- `'/'` — doar `/` (link-urile directe în locale-ul implicit rămân accesibile; implicit)
- `'no_prefix'` — doar căile fără prefix de locale
- `'*'` — fiecare cale, inclusiv rescrierea unui prefix de locale explicit
  (de ex. `/fr/about` → `/de/about` când cookie-ul preferă `de`)

- orice alt șir — acea cale, ignorând slash-urile finale (de ex. `'/welcome'`)

Sub `prefix`, un URL fără prefix din afara căilor permise redirecționează în continuare către forma
locale-ului implicit (`/about` → `/en/about`). Locale-ul implicit cu prefix sub
`prefix_except_default` (`/en`) este un 404, nu o redirecționare.

#### `localeCookie` {#localecookie}

**Tip** `string \| null` · **Implicit** `null`

Numele cookie-ului pentru păstrarea preferinței de locale a utilizatorului între sesiuni.
Setați la `null` pentru a dezactiva persistența bazată pe cookie.
Setat automat la `'user-locale'` pentru strategia `no_prefix` dacă nu este furnizat; un
`null` explicit în blocul de configurare `i18n` îl menține dezactivat și acolo.

Fără cookie, `Accept-Language` determină în continuare redirecționările; cookie-ul reține o alegere între vizite.

#### `noPrefixRedirect` {#noprefixredirect}

**Tip** `boolean` · **Implicit** `false`

Pentru strategia `no_prefix`: când locale-ul implicit are o cale personalizată pentru o pagină
(`localeRoutes` / `globalLocaleRoutes`), redirecționează calea originală a paginii către calea
personalizată a locale-ului vizitatorului, altfel către cea a locale-ului implicit (de ex. `/about` → `/about-us`).
Un locale fără cale personalizată proprie rămâne pe calea originală. Paginile cu segmente
dinamice nu sunt redirecționate.

### Înregistrare și dezvoltare {#registration-and-development}

#### `plugin` {#plugin}

**Tip** `boolean` · **Implicit** `true`

Înregistrează plugin-ul i18n de bază care furnizează `$t()`, `$tc()`, `$getLocale()`,
`$switchLocale()` și alți helperi de runtime.

#### `define` {#define}

**Tip** `boolean` · **Implicit** `true`

Furnizează `$defineI18nRoute()` la runtime. Build-ul citește oricum apelurile `$defineI18nRoute()`
din pagini.

#### `hooks` {#hooks}

**Tip** `boolean` · **Implicit** `true`

Apelează hook-ul de aplicație `i18n:register` la încărcare și la navigare, astfel încât plugin-urile să poată adăuga traduceri.

Vedeți [Hook-uri](/ro/api/events).

#### `components` {#components}

**Tip** `boolean` · **Implicit** `true`

Înregistrează componentele i18n integrate (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`).
Setați la `false` pentru a dezactiva înregistrarea automată a componentelor (de ex. dacă nu le folosiți
și doriți să reduceți amprenta modulului).

#### `types` {#types}

**Tip** `boolean` · **Implicit** `true`

Generează declarații de tipuri TypeScript pentru `useI18n`, `$t` și helperii aferenți,
pe baza cheilor de traducere din fișierele locale-ului implicit.

Separat de pachetul [`@i18n-micro/types-generator`](/ro/integrations/types-generator).

#### `hmr` {#hmr}

**Tip** `boolean` · **Implicit** `true`

Activează Hot Module Replacement pentru fișierele de traduceri în dezvoltare.
Când este `true`, modificările fișierelor JSON de traduceri declanșează o reîncărcare automată
fără reîmprospătarea completă a paginii.

#### `debug` {#debug}

**Tip** `boolean` · **Implicit** `false`

Activează logarea detaliată de depanare pentru detectarea locale-ului, generarea rutelor și încărcarea traducerilor.

#### `vueDevtools` {#vuedevtools}

**Tip** `boolean` · **Implicit** `true`

Înregistrează inspectorul și cronologia Vue DevTools în dev (extensie de browser).
Separat de fila personalizată Nuxt DevTools.

#### `experimental` {#experimental}

**Tip** `Record<string, unknown>` · **Implicit** —

Spațiu pentru opțiuni experimentale/instabile.
Conținutul se poate schimba sau poate fi eliminat fără notificare între versiunile minore.
