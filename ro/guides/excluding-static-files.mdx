# Excluderea fișierelor statice din rutarea i18n

## Prezentare generală

Implicit, nuxt-i18n-micro exclude automat fișierele statice comune din procesarea rutării i18n. Totuși, poți configura și pattern-uri de excludere personalizate pentru a împiedica anumite căi să fie procesate de sistemul i18n.

## Excluderi încorporate

Modulul exclude automat următoarele tipuri de fișiere și pattern-uri:

- **Sitemap-uri**: `/sitemap*.xml`, `/sitemap-en.xml`, etc.
- **Fișiere SEO**: `/robots.txt`, `/favicon.ico`
- **Fișiere PWA**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Assets statice**: Fișiere cu extensii precum `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Căi interne Nuxt**: Orice cale care începe cu `__` (precum `/__nuxt/`)

## Pattern-uri de excludere personalizate

Poți defini pattern-uri de excludere personalizate folosind opțiunea `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Tipuri de pattern-uri

### Pattern-uri de tip string

- **Potrivire exactă**: `'/api/health'` - se potrivește exact cu `/api/health`
- **Potrivire prefix**: `'/admin'` - se potrivește cu `/admin` și `/admin/dashboard`
- **Wildcard-uri**: `'/api/*'` - se potrivește cu `/api/users`, dar nu cu `/api/users/123`
- **Wildcard-uri profunde**: `'/admin/**'` - se potrivește cu `/admin/users` și `/admin/users/123`

### Expresii regulate

Folosește obiecte RegExp pentru potriviri de pattern-uri complexe:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Cazuri de utilizare

### Fișiere SEO

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### Rute API

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Panouri de administrare

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Assets statice

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Cum funcționează

1. **Middleware de server**: Un middleware Nitro rulează primul pentru a verifica pattern-urile de excludere.
2. **Procesarea paginilor**: În timpul rezolvării paginilor, căile excluse sunt omise.
3. **Rută catch-all**: Ruta de rezervă verifică excluderile înainte de procesare.
4. **Prerender**: Căile excluse nu sunt incluse în rutele prerenderate.

## Impact asupra performanței

- Verificările de excludere sunt optimizate și rulează devreme în ciclul de viață al cererii.
- Pattern-urile încorporate folosesc potrivire regex eficientă.
- Pattern-urile personalizate sunt puse în cache și reutilizate.
- Overhead minim de performanță pentru căile excluse.

## Depanare

### Fișierele statice încă sunt interceptate

1. **Verifică sintaxa pattern-ului**: Asigură-te că pattern-urile tale se potrivesc structurii exacte a căii.
2. **Folosește regex pentru pattern-uri complexe**: Wildcard-urile de tip string au limitări.
3. **Testează pattern-urile**: Folosește instrumentele de dezvoltare din browser pentru a verifica calea reală a cererii.
4. **Verifică ordinea**: Asigură-te că pattern-urile de excludere sunt definite înainte de alte configurări i18n.

### Pattern-ul nu funcționează

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Mod de depanare

Activează modul de depanare pentru a vedea procesarea excluderilor:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Acest lucru va înregistra deciziile de excludere în consolă.

## Migrare de la workaround-uri

Dacă foloseai workaround-uri precum reguli de rutare sau middleware, acum le poți înlocui cu `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Noua abordare este mai fiabilă și funcționează la mai multe niveluri ale sistemului de rutare.
