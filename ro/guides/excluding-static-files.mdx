# Excluderea fișierelor statice din rutarea i18n

## Prezentare generală

În mod implicit, nuxt-i18n-micro exclude automat fișierele statice comune din procesarea rutării i18n. Totuși, poți configura și modele de excludere personalizate pentru a împiedica anumite căi să fie procesate de sistemul i18n.

## Excluderi încorporate

Modulul exclude automat următoarele tipuri de fișiere și modele:

- **Sitemap-uri**: `/sitemap*.xml`, `/sitemap-en.xml` etc.
- **Fișiere SEO**: `/robots.txt`, `/favicon.ico`
- **Fișiere PWA**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Asset-uri statice**: Fișiere cu extensii precum `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Căi Nuxt interne**: Orice cale care începe cu `__` (precum `/__nuxt/`)

## Modele de excludere personalizate

Poți defini modele de excludere personalizate folosind opțiunea `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Tipuri de modele

### Modele de string

- **Potrivire exactă**: `'/api/health'` - se potrivește exact cu `/api/health`
- **Potrivire de prefix**: `'/admin'` - se potrivește cu `/admin` și `/admin/dashboard`
- **Wildcard-uri**: `'/api/*'` - se potrivește cu `/api/users`, dar nu cu `/api/users/123`
- **Wildcard-uri adânci**: `'/admin/**'` - se potrivește cu `/admin/users` și `/admin/users/123`

### Expresii regulate

Folosește obiecte RegExp pentru potriviri de modele complexe:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Cazuri de utilizare

### Fișiere SEO

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### Rute API

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Panouri de administrare

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Asset-uri statice

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Cum funcționează

1. **Middleware server**: Un middleware Nitro rulează primul pentru a verifica modelele de excludere
2. **Procesarea paginii**: În timpul rezolvării paginii, căile excluse sunt sărite
3. **Rută catch-all**: Ruta de fallback verifică excluderile înainte de procesare
4. **Prerender**: Căile excluse nu sunt incluse în rutele prerenderate

## Impactul asupra performanței

- Verificările de excludere sunt optimizate și rulează devreme în ciclul de viață al cererii
- Modelele încorporate folosesc potriviri regex eficiente
- Modelele personalizate sunt puse în cache și reutilizate
- Overhead minim de performanță pentru căile excluse

## Depanare

### Fișiere statice sunt încă interceptate

1. **Verifică sintaxa modelului**: Asigură-te că modelele tale se potrivesc cu structura exactă a căii
2. **Folosește regex pentru modele complexe**: Wildcard-urile de string au limitări
3. **Testează modelele**: Folosește instrumentele de dev din browser pentru a verifica calea reală a cererii
4. **Verifică ordinea**: Asigură-te că modelele de excludere sunt definite înaintea altor configurații i18n

### Modelul nu funcționează

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Modul de depanare

Activează modul de depanare pentru a vedea procesarea excluderilor:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Aceasta va înregistra deciziile de excludere în consolă.

## Migrare de la workaround-uri

Dacă ai folosit workaround-uri precum reguli de rută sau middleware, le poți înlocui acum cu `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Noua abordare este mai fiabilă și funcționează la multiple niveluri ale sistemului de rutare.
