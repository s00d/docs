# Suprascrieri i18n la runtime

Folosește acest ghid când ai nevoie ca un singur artefact de build să ruleze cu setări implicite diferite de locale în funcție de mediu (de exemplu: instanțe diferite pentru tenant-uri).

## Ce poate fi suprascris la runtime

Modulul suportă suprascrieri sigure la runtime pentru:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Aceste suprascrieri se aplică peste configurarea de build-time din `.nuxt/i18n.strategy.mjs` și `.nuxt/i18n.config.mjs`.

## Ce nu poate fi suprascris la runtime

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) este o preocupare de build-time, deoarece afectează comportamentul rutelor generate.

Dacă transmiți o suprascriere de strategie la runtime, este ignorată și se emite un avertisment.

## Suprascrieri bazate pe RuntimeConfig

Oferă valorile de runtime sub `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Suprascrieri prin variabile de mediu

Poți configura suprascrieri și prin variabile de mediu:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (separate prin virgulă, de exemplu, `fr,it`)

Sunt suportate și alias-uri de fallback:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Reguli de validare

La runtime, modulul validează suprascrierile pentru a evita o stare defectă:

- Nu poți dezactiva toate locale-urile.
- `defaultLocale` trebuie să indice către un locale activat.
- `fallbackLocale` trebuie să existe în locale-urile declarate.

Dacă o suprascriere este invalidă, modulul păstrează o valoare sigură și înregistrează un avertisment.

## Note pentru implementări multi-instanță

Această funcționalitate de runtime este proiectată pentru activarea locale-urilor per instanță și pentru valori implicite fără rebuild.

Dacă instanțele necesită strategii URL diferite (`no_prefix` vs `prefix`), folosește build-uri separate pentru fiecare strategie.

## Locale dezactivate și payload-uri statice

`runtimeConfig.public.i18nRuntime.disabledLocales` actualizează rutarea, switcher-ul și **handler-ul** de payload Nitro — dar Nitro servește fișierele din `public/` **înainte** de acel handler.

Dacă `translationPayloads.publicAssets` (sau copia publică forțată din SSR-ul Node) a scris deja `/_locales/\{page\}/\{locale\}/data.json`, o dezactivare la runtime nu poate ascunde acel fișier. Preferă `locale.disabled: true` la build, pentru ca premerge-ul să nu emită payload-urile statice pentru acel locale.
