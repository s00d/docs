# Rezultatele testelor de performanță

## Informații despre proiect

- **[plain-nuxt](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/plain-nuxt)**: ./test/fixtures/plain-nuxt
- **[i18n-micro](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n-micro)**: ./test/fixtures/i18n-micro
- **[i18n](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n)**: ./test/fixtures/i18n
- **[CLI](https://github.com/s00d/nuxt-i18n-micro/tree/main/scripts/src/commands/performance.ts)**: `pnpm -C scripts cli performance` / `pnpm test:performance`

### Descriere

Compară **Nuxt simplu** (bază fără un modul i18n), **i18n-micro** și **`@nuxtjs/i18n` v10.6** sub un singur profil de dicționar partajat.

Focus: timp de build, RSS maxim, **cod vs traduceri vs total** deployabil și comportamentul serverului sub Artillery + Autocannon.

### Note despre metodologie

- Metricile sunt **medii ale câte 3 rulări consecutive per fixture** (fixture A ×3, apoi B ×3, apoi C ×3 — nu intercalate).
- **Traducerile** includ JSON-ul de locale sub `locales/` / `_locales/` / `translations/`, tot ce se află sub `chunks/raw/` și chunk-urile de locale corespunzătoare. Rapoartele mai vechi care arătau la `@nuxtjs/i18n` „translations: 0 B” și o coloană uriașă „code” numărau chunk-urile de mesaje drept cod de aplicație.
- **plain-nuxt** servește același volum de frunze ca JSON static din `public/translations` (nu import-uri statice de JS). Sub Artillery, acea bază este intensivă la I/O; nu este „overhead i18n”, ci costul preluării de JSON mare per cerere.

### Rulări

Toate metricile de mai jos sunt **medii pe 3 rulări**.

### Profil fixture

| Setare | Valoare |
|------|-------|
| Locale-uri | **4** (`en`, `de`, `ru`, `fr`) |
| Pagini | **2** (`index`, `page`) |
| Arborele index | adâncime **5**, ramură **7** → **16.807** chei frunză / locale |
| Pagini secundare | adâncime **5**, ramură **6** → **7.776** chei frunză / pagină / locale |
| Obiectiv | Profil CLI implicit (`--locales 4 --keys 10000`); crește setările pentru încărcări de regression-radar |

Dicționarele provin din `test/fixtures/perf-shared/runtime.json` (scris de CLI), astfel încât toate cele trei fixture-uri să rămână aliniate.
