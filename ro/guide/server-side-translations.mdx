description: "Traduceți șiruri și citiți limba cererii în rutele de server Nitro și în handler-ele API."
---

Handler-ele de server din `server/api/` și `server/routes/` pot traduce șiruri și pot citi limba cererii cu doi helperi importați automat. Folosiți-i pentru răspunsuri API, e-mailuri, feed-uri sau orice este randat în afara unei pagini Vue. Ei citesc aceleași fișiere de traducere ca paginile dumneavoastră și detectează limba din cerere.

## Traducerea într-un handler {#translate-in-a-handler}

```ts
// server/api/greeting.get.ts
export default defineEventHandler(async (event) => {
  const t = await useTranslationServerMiddleware(event)
  return { message: t('greeting', { name: 'Ada' }) }
})
```

```bash
curl 'http://localhost:3000/api/greeting?locale=de'
# {"message":"Hallo, Ada!"}
```

`useTranslationServerMiddleware(event, defaultLocale?, locale?)` este asincron și returnează `t(key, params?, defaultValue?)`. `t` returnează șirul, interpolează parametrii `{name}` și, când cheia lipsește, returnează un `defaultValue` nevid, altfel cheia.

`t` vede doar chunk-ul `index`: fișierele rădăcină (`locales/<locale>.json`) plus `locales/pages/index/` când există (doar fișierele rădăcină cu `disablePageLocales`). Cheile altor pagini nu sunt încărcate. Pentru acestea, încărcați singur chunk-ul:

```ts
const { data } = await loadTranslationsFromServer('de', 'about') // Translations object of the about page
```

## Citirea limbii cererii {#read-the-request-locale}

```ts
// server/api/locale.get.ts
export default defineEventHandler((event) => {
  const { current, isDefault, locale } = useLocaleServerMiddleware(event)
  return { current, isDefault, dir: locale?.dir ?? 'ltr' }
})
```

`useLocaleServerMiddleware(event, defaultLocale?, locale?)` este sincron și returnează:

```ts
interface LocaleInfo {
  current: string // detected locale code
  default: string // defaultLocale, runtime overrides included (fixed at build under prefix_except_default / prefix_and_default)
  fallback: string // fallbackLocale, else the default
  available: string[] // enabled locale codes
  locale: Locale | null // the config entry of `current`
  isDefault: boolean
  isFallback: boolean
}
```

## Cum este aleasă limba {#how-the-locale-is-chosen}

Ambii helperi folosesc aceeași ordine pe fiecare rută de server, fie ea `/api` sau nu:

1. query-ul `?locale=` (prima valoare, când se repetă);
2. un parametru de rută `[locale]` sau un prefix de limbă în cale (`/de/...`);
3. cookie-ul de limbă, când [`localeCookie`](/ro/api/module-options#localecookie) este setat (`hash-locale` sub `hashMode`);
4. `Accept-Language`, când `autoDetectLanguage` este activat (valorile q sunt respectate);
5. `defaultLocale`.

Codurile invalide și cele dezactivate sunt omise la fiecare pas. Aceasta este ordinea pentru API; o randare de pagină ignoră `?locale=` sub strategiile cu prefix. Cele două ordini sunt comparate în [Detectarea limbii](/ro/guide/locale-detection).

## Forțarea unei limbi {#force-a-locale}

Transmiteți al treilea argument pentru a sări peste detectare, de exemplu într-un job care trimite e-mailuri în limba utilizatorului:

```ts
export default defineEventHandler(async (event) => {
  const user = await getUser(event) // your code
  const t = await useTranslationServerMiddleware(event, undefined, user.locale)
  return sendMail(user.email, t('mail.welcome.subject'))
})
```

Al doilea argument înlocuiește `defaultLocale` pentru detectarea din acest apel, așa că nu are efect când o limbă este forțată. Dicționarele sunt păstrate în cache per cerere și per limbă, iar între cereri în cache-ul de traduceri al serverului, așa că apelarea unui helper de mai multe ori este ieftină.

## Componente de server {#server-components}

O componentă de server (`.server.vue`, `<NuxtIsland>`) se randează de la propriul URL, `/__nuxt_island/...`, așa că nu vede URL-ul paginii, iar Nuxt îi transmite doar proprietățile ei. Transmiteți limba ca proprietate `locale`. Componenta se randează apoi în acea limbă, iar o schimbare de limbă o solicită din nou, deoarece proprietățile fac parte din URL-ul și cheia de cache ale insulei. Numele este rezervat: orice cod de limbă activat dintr-o proprietate numită `locale` setează limba randării, așa că dați alt nume unei proprietăți care înseamnă altceva, de exemplu un format numeric:

```vue
<!-- components/Greeting.server.vue -->
<template><p>{{ $t('greeting') }}</p></template>
<script setup lang="ts">
defineProps<{ locale?: string }>()
</script>
```

```vue
<template>
  <Greeting :locale="$getLocale()" />
  <NuxtIsland name="Greeting" :props="{ locale: $getLocale() }" />
</template>
```

Fără această proprietate, componenta se randează în limba din cookie, altfel în limba implicită, indiferent de URL, și nu urmează o schimbare de limbă. `$t`-ul ei vede chunk-ul `index`: fișierele rădăcină plus `locales/pages/index/`.
