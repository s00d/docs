`@i18n-micro/cli` gestionează fișierele de limbă ale unui proiect Nuxt. Citește `locales`, `defaultLocale`, `translationDir` și straturile dumneavoastră din `nuxt.config`, deci nu necesită o configurație proprie.

![Un terminal care rulează i18n-micro check, care listează o cheie lipsă, una nedefinită și patru nefolosite și eșuează, apoi extract, care adaugă cheia nedefinită, apoi clean --dryRun, care listează cele patru chei pe care le-ar elimina](/images/cli/demo.gif)

| Comandă | Folosiți-o pentru a |
| --- | --- |
| `check` | Face un build să eșueze la orice problemă a fișierelor de limbă |
| `translate` | Completa cheile lipsă printr-un serviciu de traducere |
| `clean` | Elimina cheile pe care nu le folosește nimic |
| `rename` | Muta o cheie, sau un întreg namespace, peste tot deodată |

```bash
npm install -D @i18n-micro/cli
npx i18n-micro --help
```

Rulați-l din rădăcina aplicației sau indicați-o cu `--cwd`. Fiecare flag al fiecărei comenzi se află în [referința comenzilor](/ro/api/cli).

<Tip>

**Treceți de la nuxt-i18n-micro-cli?** `@i18n-micro/cli` îl înlocuiește; executabilele `i18n-micro` și `i18n-micro-cli` rămân. Vedeți [tabelul comenzilor vechi](#moving-from-nuxt-i18n-micro-cli).

</Tip>

## Utilizare în CI {#use-it-in-ci}

```bash
i18n-micro check
```

`check` este poarta de control. Raportează:

| Verificare | Înseamnă |
| --- | --- |
| `missing` | O cheie a limbii implicite lipsește dintr-o limbă |
| `empty` | O valoare este `''`. Aplicația afișează un gol, nu valoarea de rezervă |
| `extra` | O limbă are o cheie pe care limba implicită nu o are |
| `placeholders` | `{name}` a fost pierdut sau adăugat, ori un plural și-a pierdut formele |
| `undefined` | Codul folosește o cheie pe care limba implicită nu o are |
| `unused` | Nimic din proiect nu folosește o cheie |
| `duplicates` | Același text sub chei diferite. Dezactivată implicit: transmiteți `--duplicates` |

- `--only missing,placeholders` rulează doar unele verificări; o verificare numită în `--only` care nu a putut rula eșuează.
- `--json` oferă un raport pentru instrumente.
- `--ignore` omite fișiere sursă.
- Cât timp cheile sunt calculate la runtime, `unused` este omisă, iar raportul spune de ce.

Fiecare comandă se încheie cu unul din trei coduri, astfel încât un pipeline poate distinge o problemă a traducerilor de o problemă a instrumentului:

| Cod de ieșire | Semnificație |
| --- | --- |
| `0` | Nimic de raportat |
| `1` | Constatări |
| `2` | Comanda nu a putut rula: o eroare de utilizare, un fișier corupt, o cerere eșuată |

Alte comenzi care merită un pas în CI:

```bash
i18n-micro format --check      # fails if a file is not formatted
i18n-micro lint                # stray spaces, empty values, your own regex rules
i18n-micro stats --baseRef main
```

## Menținerea limbilor sincronizate {#keep-locales-in-step}

| Comandă | Ce face |
| --- | --- |
| `extract` | Listează cheile folosite de cod care nu au încă text. Un text implicit, ca în `$t('key', {}, 'Welcome')`, merge în limba implicită. |
| `sync` | Elimină cheile pe care limba implicită nu le are. Încercați mai întâi `--dryRun`. |
| `clean` | Elimină cheile pe care nu le folosește nimic. Încercați mai întâi `--dryRun`. |
| `search` | Găsește chei și valori și arată unde este folosită fiecare cheie. |
| `stats` | Gradul de completare per limbă; `--baseRef main` compară cu o referință git. |

`sync` se oprește la fel ca `clean` atunci când ar elimina o cheie despre care nu poate dovedi că este nefolosită, precum și atunci când limba implicită nu are nimic cu care să compare. Când nu are nimic de eliminat nu se oprește niciodată, așa că `$t(item.label)` singur nu este un motiv pentru `--force`.

<Note>

`extract` și `sync` nu scriu niciodată `''` pentru o cheie fără traducere. Cheia rămâne absentă, astfel încât `fallbackLocale` se aplică la runtime, iar `check` o raportează. Un șir gol ar fi o valoare definită și ar afișa un gol.

</Note>

### Ce citesc comenzile {#what-the-commands-read}

`check`, `extract`, `sync`, `clean`, `search` și `rename` citesc codul sursă din întregul proiect, nu dintr-o listă fixă de foldere:

- **Citite:** șabloanele și scripturile printr-un parser, `.html` și Pug ca text, fiecare strat și folderele din afara rădăcinii către care indică un alias sau `components`.
- **Omise:** `node_modules`, rezultatul build-ului și fișierele de limbă. Adăugați-le pe ale dumneavoastră cu `--ignore 'legacy/**,*.stories.ts'`.
- **Codul de test** contează ca utilizare, așa că `clean` și `check --only unused` păstrează o cheie citită doar de un test. Nu adaugă niciodată o cheie: `extract` omite astfel de chei, iar `check` nu le raportează ca nedefinite.

Cod de test înseamnă folderele rădăcină `tests`, `test`, `__tests__`, `e2e`, `cypress` și `playwright`, plus fișierele JavaScript și TypeScript `.spec` și `.test` (`.ts`, `.tsx`, `.mts`, `.js`, `.jsx`, `.mjs` și altele asemenea) oriunde. Doar folderele rădăcină sunt exceptate de la îndoielile de mai jos: `pages/tests/[id].vue` este o pagină ca oricare alta, la fel și `public/` și fișierele minificate, al căror cod nu face parte din aplicație.

Comenzile recunosc:

- `$t`, `$ts`, `$tc`, `$has` și `$_t(route)`;
- `t()` din `useI18n()` și `useTranslationServerMiddleware()`;
- `<i18n-t keypath>` în șabloane și JSX, precum și `<i18n-group prefix>`;
- aliasuri precum `const { t: tr } = useI18n()`.

### Cum decide `clean` {#how-clean-decides}

`clean` preferă să lase o cheie moartă decât să elimine una vie. O cheie rămâne când oricare dintre următoarele este adevărată:

- un apel o folosește, sau folosește o cheie de sub sau de deasupra ei;
- un șir din cod este egal cu ea: `const key = 'menu.home'`, `<Item label="menu.home" />`;
- un fișier JSON, YAML sau Markdown din proiect o conține;
- o cheie calculată are un început static care o acoperă: `` $t(`status.${state}`) `` păstrează tot ce se află sub `status.`;
- un strat o definește.

`clean` se oprește fără să modifice nimic când nu poate ști și listează motivul:

- o cheie este complet calculată, ca în `$t(name)`, `<i18n-t :keypath="name" />` sau `<i18n-t v-bind="props" />`;
- `$t` este transmis ca valoare, ca în `items.map($t)`;
- o funcție numită `t` primește un argument calculat și provine dintr-un parametru, un import sau un apel: ar putea fi un wrapper în jurul celei reale. O funcție definită în același fișier nu contează, deoarece un wrapper ar avea propriul apel în interior;
- un fișier sursă nu poate fi parsat;
- niciun fișier nu folosește nicio cheie, ceea ce de obicei înseamnă că se caută în locul greșit;
- un fișier de limbă este un symlink în afara proiectului, deci o altă aplicație l-ar putea citi.

<Step title="Previzualizare">

Rulați `i18n-micro clean --dryRun` și examinați ce listează.

</Step>

<Step title="Protejarea cheilor">

</Step>

## Traducerea cheilor lipsă {#translate-missing-keys}

```bash
i18n-micro translate --dryRun                     # keys and characters per locale, nothing sent
export I18N_TRANSLATE_TOKEN=...                   # or put it in .env
i18n-micro translate --service deepl --locale de,fr
```

- `translate` completează cheile lipsă sau goale; `--replace` traduce totul din nou.
- Placeholder-ele și formele de plural sunt protejate. O traducere care a pierdut un placeholder nu este scrisă: cheia este listată, iar comanda se încheie cu `1`.
- Fiecare lot este salvat înainte de trimiterea cererii următoare, astfel încât un eșec costă doar cererea care a eșuat.

| `--service` | Serviciu | `--token` | `--options` utile |
| --- | --- | --- | --- |
| `ai` | Vercel AI Gateway, OpenAI, Anthropic sau orice server compatibil OpenAI | Cheie API, sau `AI_GATEWAY_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` | `provider`, `model`, `baseUrl`, `maxTokens` |
| `azure` | Azure Translator | Cheie de abonament | `region` |
| `deepl` | DeepL, inclusiv cheile Free | Cheie de autentificare | `formality`, `glossaryId`, `context` |
| `google` | Google Cloud Translation v2 | Cheie API | `model` |
| `libretranslate` | LibreTranslate | Opțional | `baseUrl` |
| `yandexcloud` | Yandex Cloud Translate | Cheie API, sau token IAM cu `authScheme:Bearer` | `folderId`, `model` |

Opțiunile sunt perechi `key:value`: `--options provider:openai,model:gpt-4o-mini`. Toate serviciile acceptă și `baseUrl`, `retries`, `retryDelayMs` și `timeoutMs`. O cerere de traducere poate fi deja facturată, așa că este repetată doar după un `429` sau `503`, și nu atunci când serviciul cere o așteptare mai lungă de un minut.

<Warning>

Flag-urile sunt vizibile în istoricul shell-ului și în listele de procese, așa că transmiteți token-ul prin variabila de mediu. CLI-ul maschează ceea ce știe că este secret oriunde îl afișează, inclusiv cu `--debug`: token-uri, chei ale furnizorilor, credențiale Basic, precum și query-ul și credențialele unui URL configurat de dumneavoastră. Un server care reformatează o cheie înainte de a o afișa nu este sub controlul lui, așa că tratați cu grijă jurnalele unei rulări eșuate.

</Warning>

Serviciul `ai` respectă un glosar. Când există `.i18n-glossary.json`, este folosit fără flag; `--glossaryFile` alege alt fișier.

```json .i18n-glossary.json
{ "entries": [{ "source": "Cart", "target": "Warenkorb", "to": "de" }] }
```

## Transformarea textului hardcodat în chei {#turn-hardcoded-text-into-keys}

```bash
i18n-micro text-to-i18n --dryRun   # list what would change
i18n-micro text-to-i18n            # rewrite the templates
```

```vue
<!-- before -->
<h1>Welcome to our site</h1>
<!-- after -->
<h1>{{ $t('pages.index.welcome-to-our') }}</h1>
```

Sunt rescrise doar șabloanele `.vue` ale proiectului însuși, nu cele ale unui strat sau ale unei ținte de alias. Fiecare fișier rescris este parsat din nou înainte de a fi scris. Următoarele sunt listate și își păstrează textul:

- textul din fișierele `.ts` și din scripturi, deoarece `$t` nu este disponibil peste tot;
- textul de lângă markup sau o interpolare, precum `<p>Hello <b>world</b> today</p>`: o jumătate de propoziție nu poate fi tradusă separat;
- o cheie generată care s-ar suprapune cu alta, cum se poate întâmpla la o pagină părinte și copilul ei;
- o cheie cunoscută care nu poate fi pusă între ghilimele.

<Warning>

Faceți mai întâi commit și examinați diff-ul.

</Warning>

## Redenumirea unei chei {#rename-a-key}

```bash
i18n-micro rename --from common.save --to actions.save
i18n-micro rename --from settings --to account.settings   # a whole namespace
```

`rename` editează arborele sintactic, astfel încât comentariile și șirurile fără legătură rămân neschimbate, iar aliasurile și `:keypath` sunt urmărite. Fișierul propriu al unui strat nu este modificat niciodată. Avertizează despre ce nu poate rescrie și lasă neatins:

- o cheie calculată sub vechiul nume;
- fiecare șir simplu egal cu ea;
- un șablon Pug;
- o sursă dintr-un strat sau dintr-un folder din afara proiectului.

`--to` trebuie să fie o cheie care poate fi scrisă în cod: fără ghilimele, fără backslash, fără segment gol, fără `__proto__`.

## Schimbul de fișiere cu traducătorii {#exchange-files-with-translators}

```bash
i18n-micro export --format csv
i18n-micro import --format csv --dryRun
```

**`export`** scrie fiecare cheie a fiecărei limbi, inclusiv cele netraduse, cu textul limbii implicite ca sursă: o coloană `Source` în CSV, un comentariu `#.` în PO.

- Fără `--dir`, PO merge în `pots`, iar CSV în `csv_exports`.
- Înregistrează ce a scris în `.i18n-export.json`, în folderul de ieșire. Se oprește când un fișier s-a modificat de atunci și conține traduceri pe care fișierele de limbă nu le au, inclusiv intrări PO fuzzy; `--force` le suprascrie. Editările obișnuite ale fișierelor de limbă nu îl opresc.

**`import`** îmbină, omite celulele goale și omite intrările PO marcate `fuzzy`.

- O cheie care ar suprascrie o valoare, sau o valoare peste un întreg grup de chei, este listată și lăsată deoparte, iar comanda se încheie cu `1`.
- Se oprește cu codul `2` la un catalog într-o locație neașteptată, la catalogul unei pagini pe care ultimul export nu l-a scris, la ghilimele plasate greșit într-un CSV sau la o intrare de pagină sub `disablePageLocales`.

Pentru o platformă de traducere, folosiți propriul ei CLI: configurația [Crowdin](/ro/guide/crowdin) sincronizează fișierele JSON, inclusiv fișierele de pagină.

## Sincronizarea cu propriul endpoint {#sync-with-your-own-endpoint}

`sync-remote` schimbă fișierele de limbă globale cu un endpoint HTTP pe care îl rulați. Fișierele de pagină rămân locale, iar comanda specifică acest lucru. Descrieți endpoint-ul în `.i18n-remote.json`:

```json .i18n-remote.json
{ "url": "https://translations.example.com", "path": "translations" }
```

Endpoint-ul răspunde la `GET` și `PUT` cu un obiect `{ locale: messages }`. Autentificați-vă cu `auth: { username, password }` sau puneți un bearer token în `I18N_REMOTE_TOKEN`.

| | Pull | Push |
| --- | --- | --- |
| Ce se transferă | Completează ce nu aveți și păstrează cheile pe care doar dumneavoastră le aveți | Trimite cheile proprii ale proiectului, nu pe cele ale unui strat, și lasă deoparte golurile dumneavoastră |
| Conflicte | O cheie care diferă pe ambele părți: nu se scrie nimic, cod `1`; `--force` preia valoarea de la distanță | Un PUT înlocuiește documentul, așa că un push citește mai întâi endpoint-ul și se oprește cu codul `1` când acesta conține text pe care nu îl aveți; `--force` îl suprascrie. Un endpoint care răspunde `404` nu are nimic de pierdut |
| `--dryRun` | Citește de la endpoint, listează modificările, nu scrie nimic | Spune ce ar fi trimis, fără a contacta endpoint-ul |

O limbă pe care nu ați configurat-o este omisă, iar o valoare goală de la distanță nu șterge nimic.

## Trecerea de la nuxt-i18n-micro-cli {#moving-from-nuxt-i18n-micro-cli}

| Comanda veche | Acum |
| --- | --- |
| `validate` | `check` |
| `diff` | `check --only missing` |
| `check-duplicates` | `check --only duplicates` |
| `export-csv`, `import-csv` | `export --format csv`, `import --format csv` |
| `--potsDir`, `--csvDir` | `--dir` |
| `estimate` | `translate --dryRun` |
| `glossary` | Editați `.i18n-glossary.json`; `translate` îl citește singur |
| `backup`, `restore` | Git, care vă păstrează deja fișierele de limbă |
| `init` | `nuxi init`, apoi adăugați `nuxt-i18n-micro` în `modules` |
| `split` | Eliminată: modulul nu citește fișiere împărțite |
| `optimize` | `check --only duplicates` |
| `replace-values` | Editorul dumneavoastră sau `sed` |
| `stats --full` | `stats`; [DevTools](/ro/guide/devtools) are detaliile |
| `search --hardcodedOnly` | `text-to-i18n --dryRun` |
| `search --preferUnused`, `--onlyVue` | Eliminate |
| regulile `lint` `no-html-tags`, `no-special-chars`, `no-mixed-case`, `no-missing-punctuation`, `no-inconsistent-pluralization` | Eliminate: semnalau text normal. Scrieți o intrare `customRegexRules` dacă aveți nevoie de una |
| `text-to-i18n --extractOnlyDirs`, `--extractOnlyPatterns`, `--verbose` | Eliminate: codul nu este niciodată rescris |
| `--logLevel verbose` | Eliminat: nu făcea nimic |

**Servicii eliminate:** `googlefree`, `yandex` (folosiți `yandexcloud`), `ibm`, `lingvatranslate`, `modernmt`, `lilt`, `unbabel`, `reverso`, `baidu`, `papago`, `tencent`, `systran`, `mymemory`.

**Tipuri `sync-remote` eliminate:** `github`, `gitlab`, `crowdin`, `lokalise`, `tolgee`, `weblate`. Folosiți propriul CLI al platformei sau `custom`, care nu mai necesită `type`.

### Comportament modificat {#changed-behaviour}

- `extract` și `sync` nu mai scriu `''`. Cheile rămân absente, iar `check` le raportează. `extract` scrie o cheie doar când codul îi oferă textul.
- `extract` scrie cheile de pagină în `locales/pages/<route name>/`, unde le citește modulul, și scanează `app/` pe Nuxt 4. Mutați tot ce se află în directoare precum `pages/_about` și `pages/blog_` și ștergeți un `locales/pages/<locale>.json` rătăcit.
- `translationDir` din `nuxt.config` este respectat; înainte, fiecare comandă folosea în tăcere `locales`.
- Fără `defaultLocale`, limba implicită este `en`, ca în modul, iar `DEFAULT_LOCALE` este respectat. Înainte era prima limbă.
- `check` și `sync` folosesc limba implicită ca referință și verifică fișierele de pagină. `"a.b"` și `a: { b }` sunt considerate o singură cheie.
- `clean` păstrează o cheie folosită oriunde, în orice scope, și se oprește când utilizarea nu poate fi dovedită. `--include` și `--exclude` aleg ce poate fi eliminat.
- `sync` se oprește în același mod, precum și atunci când limba implicită nu are chei cu care să compare. `--force` anulează acest comportament. Se oprește și atunci când `DEFAULT_LOCALE` a ales o altă referință decât `nuxt.config`.
- Flag-urile lungi cu o singură liniuță și argumentele rătăcite sunt erori: `clean -dryRun` nu mai rulează `clean`.
- Un fișier doar-citire sau un fișier care nu este UTF-8 nu poate fi salvat: comanda se oprește înainte de a modifica ceva. Citirea unui astfel de fișier este în regulă. O cheie repetată, o cheie numită `__proto__` și un întreg mai mare de 2^53 opresc o comandă, deoarece o salvare le-ar pierde.
- Un flag care necesită o valoare și este urmat de un alt flag este o eroare; scrieți `--flag=--value` pentru o valoare care începe cu o liniuță. Un flag boolean acceptă doar `true` sau `false`.
- `export` se oprește în loc să suprascrie traduceri care nu au fost niciodată importate.
- Codurile de ieșire sunt `0`, `1` și `2`; înainte eșecurile erau `1`, iar `diff` și `check-duplicates` returnau mereu `0`.
- `lint --fix` nu mai lasă fișiere `.bak`.
- O salvare păstrează indentarea fișierului, terminațiile de linie, newline-ul final, symlink-ul și hard link-ul și lasă neatinse fișierele pe care nu le-a modificat.
- Un flag scris greșit sau eliminat este acum o eroare, nu este ignorat în tăcere.
- Căile precum `--dir` sunt relative la proiect, nu la shell.
- `ai` nu mai încarcă pachetele `@ai-sdk/*`: folosiți `provider` `gateway`, `openai` sau `anthropic`, ori `baseUrl` pentru un server compatibil OpenAI.
