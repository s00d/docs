---
title: "Detectarea personalizată a limbii"
description: "Alege tu limba — după domeniu, header sau profilul utilizatorului — cu un plugin de server și useI18nLocale().setLocale()."
---

Detectarea încorporată citește URL-ul, un cookie și `Accept-Language`. Când limba depinde de altceva — domeniul, un header geografic setat de CDN-ul tău, un profil de utilizator — seteaz-o tu într-un plugin care rulează înaintea plugin-ului i18n. Modulul încarcă apoi traducerile acelei limbi și o folosește pentru redirecționări exact ca și cum ar fi detectat-o el însuși. Regulile care decid când o limbă aleasă are prioritate față de URL se află în [Detectarea limbii](/ro/guide/locale-detection); această pagină arată cum să conectezi propria sursă.

## Setarea limbii într-un plugin de server {#set-the-locale-in-a-server-plugin}

```ts
// plugins/i18n-locale.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10, // before the i18n plugin (order -5)
  setup() {
    const { setLocale } = useI18nLocale()
    const host = (useRequestHeaders(['host']).host ?? '').split(':')[0]! // without the port

    if (host.endsWith('.de')) setLocale('de')
    else if (host.endsWith('.fr')) setLocale('fr')
  },
})
```

`setLocale(code)` scrie starea limbii (`useState('i18n-locale')`) și, când este configurat un cookie de limbă, cookie-ul. Folosește-l în loc să scrii tu `useState` sau `useCookie`. Transmite doar coduri de limbi activate.

Păstrează plugin-ul ca `.server.ts` când citește headere ale cererii: acestea nu există în browser. Un plugin `.client.ts` este locul potrivit pentru surse disponibile doar în browser, precum `localStorage`.

## Dezactivarea pasului încorporat Accept-Language {#turn-off-the-built-in-accept-language-step}

Plugin-ul tău și `Accept-Language` pot fi în dezacord. Pentru ca doar codul tău (plus URL-ul și cookie-ul) să decidă, dezactivează header-ul:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    autoDetectLanguage: false,
  },
})
```

[`autoDetectLanguage`](/ro/api/module-options#autodetectlanguage) controlează doar pasul header-ului. URL-ul și un cookie valid contează în continuare.

## Ce se întâmplă în continuare {#what-happens-next}

Efectul lui `setLocale` depinde de [strategie](/ro/guide/strategy):

| Strategie | Efectul lui `setLocale('de')` în plugin |
| --- | --- |
| `no_prefix` | Pagina se randează în germană; URL-ul nu se schimbă. |
| `prefix`, `prefix_except_default` | Pe o cale fără prefix unde [`autoDetectPath`](/ro/api/module-options#autodetectpath) permite redirecționări (implicit doar `/`), serverul răspunde cu `302` către URL-ul în germană. Un URL cu prefix de limbă îl păstrează. |
| `prefix_and_default` | Nicio redirecționare: URL-ul fără prefix este o pagină validă în limba implicită. |

În strategiile cu prefix, o limbă din URL este alegerea utilizatorului, iar plugin-ul tău nu o suprascrie. `autoDetectPath: '*'` este excepția: serverul mută atunci URL-urile cu prefix după cookie și `Accept-Language` și ignoră starea, dar `setLocale()` scrie și cookie-ul când unul este configurat, așa că de la următoarea cerere alegerea plugin-ului tău poate redirecționa un URL cu prefix. Păstrează `'/'` sau folosește `'no_prefix'` când URL-urile cu limbă explicită trebuie să aibă prioritate. Folosește plugin-ul pentru a alege unde ajunge un vizitator, nu pentru a rescrie linkurile pe care le-a urmat.

## Respectarea limbii alese de utilizator {#respect-a-locale-the-user-picked}

Odată ce un utilizator schimbă limba, schimbarea scrie cookie-ul. Sari peste propria detectare când există deja o preferință validă:

```ts
// plugins/i18n-locale.server.ts
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10,
  setup() {
    const { getPreferredLocale, setLocale, validLocales } = useI18nLocale()
    if (getPreferredLocale()) return // valid state or cookie: keep it

    const country = useRequestHeaders(['x-country'])['x-country']
    if (country === 'JP') return setLocale('ja')

    const header = useRequestHeaders(['accept-language'])['accept-language']
    setLocale(detectLocaleFromAcceptLanguage(header, validLocales))
  },
})
```

`getPreferredLocale()` returnează starea sau cookie-ul doar când acesta este o limbă activată, astfel încât un cookie învechit nu oprește detectarea. `detectLocaleFromAcceptLanguage` este comparatorul care ține cont de valorile q și pe care îl folosește modulul însuși (instalează `@i18n-micro/utils` pentru a-l importa); `setLocale(null)` nu face nimic.

## Un domeniu pentru fiecare limbă {#one-domain-per-locale}

Dacă fiecare domeniu trebuie să servească propriile limbi, nu ai nevoie de un plugin: dă fiecărei limbi un `baseUrl`, setează `baseDefault: true` pe limba implicită a fiecărui domeniu și construiește o singură dată (un site static rulează în continuare `nuxi generate` pentru fiecare domeniu). Vezi [Straturi și domenii](/ro/guide/layers#multiple-domains).
