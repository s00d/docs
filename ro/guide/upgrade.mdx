Această pagină enumeră ce se schimbă pentru aplicația dvs. când actualizați nuxt-i18n-micro și pachetele sale `@i18n-micro/*`. Citiți secțiunea pentru versiunea de la care porniți înainte de a actualiza dependența. Majoritatea aplicațiilor au nevoie de puține modificări de cod.

<Tip>

**Veniți de la `@nuxtjs/i18n`?** — Vedeți [Migrarea de la @nuxtjs/i18n](/ro/guide/migration).

</Tip>

## După 3.30.3: versiunea majoră {#after-3-30-3-the-major-release}

Opțiunile modulului, `$t`, `$localePath`, `$switchLocale` și ceilalți helperi, componentele, composables și utilitarele de server documentate își păstrează numele. Ce s-a schimbat este comportamentul, în mare parte bug-uri corectate. Pachetele adaptor și pachetele de rutare au modificări reale de API incompatibile: vedeți [Pachete pentru framework-uri](#framework-packages) și [Alte pachete](#other-packages).

### Faceți mai întâi acest lucru {#do-this-first}

1. **Verificați versiunile.** Modulul necesită Nuxt 3.18 sau mai nou și Node 20 sau mai nou. Nuxt are propriul minim pentru Node: Nuxt 4.5 declară `^22.19.0 || ^24.11.0 || >=26.0.0`. `nuxt generate` pe Nuxt 3.18.0 în sine eșuează și în Nuxt simplu (`[unstorage] Invalid key: "/"`); 3.21.11 funcționează. `@i18n-micro/react` necesită React 18 sau mai nou.
2. **Corectați pachetele instalate.**
   - Eliminați `@i18n-micro/hmr`. HMR pentru traduceri este încorporat în modul.
   - Dacă testele importă `@i18n-micro/test-utils`, adăugați-l: `npm install -D @i18n-micro/test-utils`. Nu mai este instalat odată cu modulul.
   - Înlocuiți `nuxt-i18n-micro-cli` cu `@i18n-micro/cli`. 28 de comenzi au devenit 16, `check` înlocuiește trei dintre ele, iar codurile de ieșire se schimbă: vedeți [ghidul CLI](/ro/guide/cli#moving-from-nuxt-i18n-micro-cli).
3. **Căutați în cod** intrările din tabelul de mai jos.
4. **Verificați ce se află în fața aplicației.** Cu `baseUrl` pe locale-uri în spatele unui proxy, vedeți [În spatele unui proxy sau CDN](/ro/guide/deployment#behind-a-proxy-or-cdn). Cu un CDN, verificați cheia sa de cache în raport cu antetul `Vary`: vedeți [Cache-ul HTML](/ro/guide/deployment#caching-html). Cu `apiBaseClientHost` sau un CSP strict, permiteți noul link `preload`: vedeți [SEO și etichete head](#seo-and-head-tags).
5. **Actualizați snapshot-urile.** Snapshot-urile head primesc linkul `preload`, markup-ul selectorului de limbă s-a schimbat ([`<i18n-switcher>` și `<i18n-link>`](#&lt;i18n-switcher>-and-&lt;i18n-link>)), iar query string-urile din rezultatul `$localeRoute` sunt codificate diferit.
6. **Deschideți paginile în fiecare locale și căutați chei brute.** Layout-urile care foloseau chei din fișierul paginii anterioare le afișează acum brute: mutați acele chei în fișierul de la rădăcină.

<Warning>

**`switchLocaleRoute` din `@i18n-micro/path-strategy` și-a pierdut primul argument** — `switchLocaleRoute(fromLocale, toLocale, route, options)` este acum `switchLocaleRoute(toLocale, route, options)`. **Un apel JavaScript vechi nu eșuează: returnează un rezultat greșit,** deoarece `fromLocale` este citit ca țintă, iar `toLocale` ca rută. Doar TypeScript vă semnalează acest lucru. `$switchLocaleRoute` din Nuxt nu este afectat.

</Warning>

### URL-uri și redirecționări {#urls-and-redirects}

- **`/en` și `/en/...` dau 404 în cazul `prefix_except_default`** (`en` fiind locale-ul implicit), așa cum este documentat.
- **Un prefix de locale scris cu alte majuscule sau altfel dă 404.** `/DE/about` randa ruta germană în locale-ul implicit sau redirecționa către `/en/DE/about`. O pagină proprie pe acel URL rămâne o pagină. O pagină catch-all sau `[slug]` nu este una: `/DE/x` sub `[...slug]` și `/DE` lângă `[slug]` dau și ele 404, deci un slug de CMS egal cu un cod de locale scris cu alte majuscule își pierde pagina. Cu `ssr: false` nu răspunde niciun server, deci `/DE/about` afișează pagina germană.
- **O cale de pagină scrisă cu alte majuscule redirecționează către forma sa proprie.** `/T/BASIC` era un 200 și este acum un `302` către `/t/basic`.
- **Un URL necunoscut rămâne 404.** Cu `autoDetectPath: '*'` sau `'no_prefix'`, `/nope` nu mai redirecționează mai întâi către `/de/nope`. `prefix` păstrează redirecționarea (acolo nu se servește nimic fără prefix), la fel ca `/` peste tot.
- **Calea personalizată a altui locale, fără prefix, își găsește pagina în cazul `prefix_except_default`.** `/a-propos` era un 404 și este acum un `302` către URL-ul locale-ului implicit (`/about`). În cazul `prefix`, aceeași redirecționare ajunge acum la o pagină existentă (`/en/about`; era `/en/a-propos`, un 404). `prefix_and_default` rămâne 404.
- **`prefix` cu `redirects: false` răspunde cu 404 pe un URL fără prefix** (`/about` era un `302`), inclusiv pe URL-ul original al unei pagini cu o cale implicită personalizată. `$localePath('/about')` găsește în continuare acea pagină.
- **În cazul `prefix_except_default`, URL-ul original al unei pagini cu o cale implicită personalizată redirecționează către aceasta,** inclusiv paginile dinamice. `/dir/one` era un 404 și este acum un `302` către `/dir-one/one`.
- **`autoDetectPath: '*'` aplică acum cookie-ul și `Accept-Language` și căilor fără prefix** (`/about` → `/de/about`).
- **În cazul `prefix`, un URL fără prefix păstrează locale-ul vizitatorului.** Cu cookie-ul `de`, `/about` și un simplu `<NuxtLink to="/about">` merg la `/de/about`, pe fiecare cale, indiferent de `autoDetectPath`.
- **În cazul `prefix_and_default`, un URL fără prefix este locale-ul implicit.** `/contact` cu `Accept-Language: de` randa în germană și apoi hidrata în engleză. Acum randează locale-ul implicit; vizitatorii ajung la germană prin `/de/...`.
- **În cazul `no_prefix`, o cale personalizată randează propriul locale** (`/ueber-uns` este în germană indiferent de preferință), iar o pagină restricționată randează într-un locale pe care îl servește. O cale partajată de mai multe locale-uri randează locale-ul preferat atunci când acesta este unul dintre ele, iar cu `baseUrl` este o pagină pe fiecare dintre domeniile lor. Acele locale-uri partajează o singură înregistrare, `localized-<page>-<first locale>`.
- **`noPrefixRedirect` se ghidează după locale-ul vizitatorului.** Cu cookie-ul `de`, `/about` merge la `/ueber-uns` și randează în germană, nu la `/about-us` al locale-ului implicit. Un locale fără propria cale personalizată rămâne pe `/about`.
- **O redirecționare `routeRules` fără pagină nu este localizată.** `/de/old` era un 200 gol, acum este un 404: adăugați o regulă pentru calea cu prefix dacă aveți nevoie de una. Un link din alt locale către o astfel de regulă păstrează calea așa cum este scrisă și ajunge la ținta regulii.
- **Regulile de rută ajung la căile personalizate.** `/blog/**` se aplică și pentru `/de/artikel/:slug` când `blog/[slug]` are acea cale, iar regulile sunt copiate și în cazul `no_prefix`. O rută statică vecină, precum `/de/artikel/news`, se potrivește și ea cu acel model. O regulă deja scrisă sub un prefix de locale rămâne așa cum este scrisă.
- **Un locale cu `disabled: true` răspunde imediat cu 404 pe prefixul său**, iar linkurile către el rămân pe pagină. Un locale dezactivat la runtime face la fel: înainte randa în locale-ul de rezervă.
- **Pagina 404 a modulului afișează `Page Not Found`** pe prefixul unui locale dezactivat și pe prefixul propriu al unui host, unde Nuxt afișa `Page not found: /de/about`. Statusul este același.
- **`customRegexMatcher` nu mai dă 404 pentru o pagină reală** al cărei prim segment arată ca un locale.
- **Numele rutelor localizate sunt consecvente.** Un copil sub o înregistrare de locale partajată păstrează numele paginii, `no_prefix` respectă `localizedRouteNamePrefix`, iar un părinte cu un copil index rămâne fără nume.
- **Paginile pe care un modul le adaugă fără `name`** (`extendPages`) sunt localizate și primesc un nume, cu variante de locale și `hreflang`. Înainte rămâneau nelocalizate.
- **O intrare din `nuxt.config` are prioritate față de `$defineI18nRoute`,** sub orice formă a cheii (`about/team`, `/about/team`, `about-team`). Care dintre ele câștiga depindea înainte de scriere.
- **Avertismente noi la build:** o valoare `localeRoutes` care începe cu propriul cod de locale (`fr: '/fr/article'`) și calea personalizată a unui copil în afara părintelui său.
- **Modul hash funcționează în cazul `prefix`.** Documentul este `/`, iar `/en` sau `/about` redirecționează în hash.
- **`/#/de/x` randează în germană** în cazul `prefix_except_default` și `prefix_and_default`. Înainte randa în engleză, cu o nepotrivire la hidratare.

### Linkuri și obiecte de rută {#links-and-route-objects}

- **Un locale care nu servește o pagină duce la pagina sa principală.** `$localeRoute`, `$switchLocalePath` și selectorul de limbă nu mai returnează pagina altui locale.
- **Un cod de locale necunoscut duce la locale-ul implicit.** `$localePath(path, 'xx')` și `$localeRoute` dădeau înainte `/xx`.
- **`$localePath` returnează nemodificat un șir cu schema `http(s):`, `mailto:` sau `tel:`, iar `path` și `fullPath` din `$localeRoute` îl conțin neschimbat**, deci nu le transmiteți o valoare neverificată (un parametru `?next=`) ca țintă a unui link. `//host` și numele simple precum `x.com` rămân căi, pe această origine în fiecare locale, și niciun link în care se transformă nu o părăsește: `/de//x.com` către locale-ul implicit este `/x.com`. Barele oblice inverse contează ca bare oblice.
- **`$localePath` codifică o cale:** `/a b` dă `/a%20b`.
- **`$localeRoute` și `$switchLocaleRoute` returnează obiecte simple,** sigure în `ref`, `reactive`, `useState`, JSON și spread-uri. Când un parametru necesită escaping, obiectul este `{ path, fullPath, query, hash }` (`$localeRoute` adaugă `href`), fără `name` sau `params`, iar URL-ul rămâne același înainte și după o reîncărcare. Un URL simplu le are pe amândouă. `name` este nou: obiectele vechi nu îl aveau niciodată. Codul care citește `.name` sau `.params` trebuie să trateze absența lor, iar forma primită depinde de valoare.
- **Cu `trailingSlash`, `$switchLocaleRoute` returnează întotdeauna acea formă a căii,** inclusiv pentru slug-uri simple, iar redirecționările de pe server respectă `trailingSlash`. Rezultatele și antetele `Location` se pot schimba cu acea opțiune.
- **Valorile query din rezultatul `$localeRoute` folosesc codificarea vue-router:** `/` rămâne literal, iar un spațiu este `+` (`?redirect=/v2`; era `%2Fv2`). Valoarea decodificată este aceeași, dar un snapshot al unui astfel de `href` se schimbă.
- **Un link fără cale rămâne pe pagina curentă.** `$localePath('#top')`, `'?p=2'`, `''` și `{ query }` păstrează pagina pe care se află; `'#top'` era citit înainte de la rădăcina site-ului. Un simplu `'about'` înseamnă în continuare `/about`.
- **Spread-uri.** `{ ...route, query }` și `{ ...route, hash }` păstrează modificarea, inclusiv prin `$switchRoute`. Un `path` nou are prioritate în `$localeRoute`, `$localePath` și `$switchRoute`. `{ ...route, params }` funcționează pe o rută cu nume; pe o rută sub formă de cale, calea are prioritate și parametrii sunt ignorați, cu avertismentul de dezvoltare al vue-router. Folosiți `$localeRoute({ name, params })`.
- **`$switchRoute` rămâne în aplicație.** `baseUrl` propriu al unui locale, `mailto:` și `tel:` o părăsesc; orice alt șir este o cale.
- **`excludePatterns`** se potrivesc cu segmente întregi (`'/admin'` nu mai se potrivește cu `/administrator`), iar glob-urile sunt ancorate (`/docs/*` nu mai se potrivește cu `/en/docs/x`). Modelele `RegExp` ajung acum la runtime; înainte se pierdeau acolo. O pagină cu care se potrivesc este nelocalizată: fără `hreflang` și cu locale-ul implicit în cazul `prefix_except_default`. Verificați-vă modelele cu [Excluderea căilor](/ro/guide/excluding-static-files).

Un `%` sau `?` într-un parametru nu supraviețuiește unei reîncărcări randate pe server în Nuxt 4.5.2, în nicio aplicație: aceasta este o problemă upstream, nu a modulului.

### Domenii pentru locale-uri {#locale-domains}

- **`locales[].baseUrl` rutează acum cererile.** Un singur build servește toate domeniile: vedeți [Layere și domenii](/ro/guide/layers#multiple-domains). Cu `baseUrl` setat, un locale al altui domeniu dă 404 pe acest host (`/en/about` pe `example.de`), iar linkurile către un locale de pe același host sunt relative. Cererile pe orice alt host, inclusiv `localhost`, se comportă ca înainte, cu excepția faptului că canonical și `hreflang` folosesc `metaBaseUrl` dacă este setat, altfel `baseUrl` al locale-ului implicit, și nu originea cererii.
- **În spatele unui proxy care rescrie `Host`,** fiecare cerere revine la configurația de build până când setați [`trustForwardedHost`](/ro/api/module-options#trustforwardedhost). Implicit este `false`, spre deosebire de `metaTrustForwardedHost`. Vedeți [În spatele unui proxy sau CDN](/ro/guide/deployment#behind-a-proxy-or-cdn).
- **`nuxi generate` cu `baseUrl` necesită `NUXT_I18N_DOMAIN`, o dată pentru fiecare domeniu.** Fără acesta, build-ul afișează un avertisment, iar acele locale-uri sunt linkuri fără pagini. Vedeți [Site static](/ro/guide/deployment#static-site-(nuxi-generate)).
- **Un link către un locale cu `baseUrl` trece prin `$localePath` sau `<i18n-link>`.** `<NuxtLink :to="$localePath(x, 'fr')">` și `<i18n-link :to="$localeRoute(x, 'fr')">` sunt acel URL absolut, iar un clic duce acolo. Router-ul nu acceptă un obiect absolut: `<NuxtLink :to="$localeRoute(x, 'fr')">` și `router.push($localeRoute(x, 'fr'))` rămân `/https://fr.example.com/...`, o cale a acestei aplicații. Pe `localhost` sau pe un host de previzualizare, fiecare locale cu `baseUrl` este un astfel de link, inclusiv cel curent. În cod, folosiți `navigateTo($localePath(x, 'fr'), { external: true })`.
- **Pagina principală a unui domeniu este scrisă peste tot fără bară oblică la final** (`https://example.de`), în linkuri, canonical și `hreflang`.
- **În cazul `prefix`, un link către alt domeniu păstrează prefixul de locale, cu sau fără `baseDefault`.** `https://example.de/de/about`, nu `https://example.de/about`, care doar redirecționează.
- **În cazul `prefix_except_default` cu `baseDefault` pe un alt locale decât cel implicit de la build, rutele păstrează toate prefixele**, astfel încât alte domenii să le poată referi. `/en` dă în continuare 404. Doar codul care citește `router.getRoutes()` vede diferența.
- **În cazul `prefix_except_default`, prefixul propriu al unui host dă 404 pe host-ul său `baseDefault`.** `/de/x` pe host-ul `de` era un 200.
- **`$getI18nConfig().locales` conține doar ce servește host-ul.** `linkLocales` le conține pe toate, iar `$getLocales()` rămâne complet.

### Navigarea și `$switchLocale` {#navigation-and-$switchlocale}

- **O navigare se aplică atunci când este confirmată (commit).** Dicționarul, locale-ul, parametrii și head-ul se schimbă în `router.afterEach`, deci o navigare anulată sau blocată nu schimbă nimic, iar linkurile paginii vechi rămân valide cât timp se încarcă fragmentul următor. Un `beforeResolve`, un `beforeRouteEnter` sau un guard global ulterior vede acum dicționarul și locale-ul vechi. Middleware-ul de rută nu este afectat.
- **Un fragment eșuat păstrează dicționarul curent.** Un 5xx, o eroare de rețea sau un conținut invalid în fișierul de la rădăcină afișa înainte chei brute. Pagina nouă este acum randată cu șirurile vechi, iar următoarea navigare reîncearcă. Un 404 sau shell-ul SPA al unui host static în locul fișierului dă dicționarul de la rădăcină până la următoarea reîncărcare.
- **`$switchLocale` se rezolvă cu `true` sau `false`** (înainte nu se rezolva cu nimic), `false` atunci când dicționarul locale-ului nu s-a aplicat. Este tipizat `Promise<boolean>`, iar `$switchRoute` `Promise<void>`.
- **`$switchLocale` este o alegere explicită.** La sosire stochează locale-ul, inclusiv pe un 404. Dacă navigarea este blocată, anulată sau aruncă o eroare, preferința stocată și starea rămân cum erau, iar eroarea este rearuncată. O mutare pe alt host îl stochează mai întâi. În cazul `no_prefix` și în modul hash, comutarea rămâne valabilă indiferent de ce face navigarea. Pe o pagină cu un singur URL pentru toate locale-urile (`excludePatterns`), alegerea nu este anulată, iar URL-ul paginii următoare decide: în cazul `prefix_except_default`, un link fără prefix revine la locale-ul implicit.
- **În cazul `no_prefix`, `$switchLocale` își păstrează pagina când două pagini partajează o cale personalizată,** inclusiv cu parametri care necesită escaping. O reîncărcare a unui astfel de URL și un `$localeRoute` cu un parametru cu escaping ajung pe prima înregistrare.
- **O redirecționare pe client păstrează modul navigării sale.** Un simplu `<NuxtLink to="/about">` în cazul `prefix` adaugă o intrare în istoric în loc să o suprascrie pe cea curentă; `router.replace` înlocuiește în continuare.
- **`$setI18nRouteParams` și `useI18nHead` de pe server supraviețuiesc hidratării.** După ajungerea pe `/news/2`, selectorul de limbă duce la slug-ul tradus (`/de/news/2-zwei`), nu la `/de/news/2`, inclusiv în HTML-ul de pe server, oriunde s-ar afla selectorul, atunci când pagina setează parametrii în timpul SSR. Aceștia sunt eliminați când este confirmată o navigare către o altă cale, inclusiv de la `/news/1` la `/news/4`: setați-i din nou pe pagina nouă.
- **`$setI18nRouteParams` citit în setup este legat de acea pagină.** Un apel întârziat dintr-o pagină deja părăsită nu face nimic. `useNuxtApp().$setI18nRouteParams` este acum un accesor, iar două citiri dau două funcții. Nu are setter: `useI18n().$setI18nRouteParams = fn`, cum ar putea face un stub de test, aruncă o eroare în modul strict, deci faceți stub pentru `useI18n` însuși. Într-un layout sau în `app.vue` este funcția simplă, deoarece acolo nu se părăsește nimic.
- **Serverul rescrie linkurile din `<i18n-switcher>` la finalul randării**, pe paginile cu parametri, deoarece un selector din layout este randat înaintea setup-ului asincron al paginii. Un link `$switchLocalePath` scris manual nu este rescris: vedeți [rute de locale personalizate](/ro/guide/custom-locale-routes). Cu streaming-ul SSR din Nuxt, primul HTML păstrează parametrii URL-ului.
- **Un prop numit `locale` pe o componentă de server setează locale-ul ei de randare**, deci `<Greeting :locale="$getLocale()" />` urmează URL-ul și o comutare. `$getLocale()`, `$localePath` și `$getLocaleName` din interiorul ei urmează și ele prop-ul. Vedeți [traducerile pe server](/ro/guide/server-side-translations). Fără prop, folosește în continuare cookie-ul sau valoarea implicită.
- **Paginile `keepalive` își recapătă parametrii și head-ul** la revenire.
- **O pagină imbricată setată la `false` în cazul `prefix_except_default` nu are URL de locale.** `/de/parent/kid` cu `globalLocaleRoutes: { 'parent-kid': false }` era servit și acum dă 404: pagina rămâne pe `/parent/kid`.

### Detectarea locale-ului și cookie-ul {#locale-detection-and-the-cookie}

O singură ordine de prioritate peste tot, descrisă în [Detectarea locale-ului](/ro/guide/locale-detection).

- **`?locale=` contează pe pagini doar în cazul `no_prefix`.** Cu strategiile cu prefix, URL-ul decide; `/about?locale=de` nu mai randează în germană sub `lang="en"`. `?locale=de&locale=fr` citește prima valoare; era `"de,fr"`.
- **`Accept-Language` respectă valorile `q`** (`fr;q=0.1, de;q=0.9` → `de`; `q=0` exclude o limbă). Potrivirea regională nu mai depinde de ordinea din `locales` și nu amestecă niciodată scrierile chinezești.
- **O navigare pe client către o pagină îi stochează locale-ul în cookie, inclusiv pe o pagină fără prefix a locale-ului implicit.** Cu `localeCookie` setat, un vizitator care face clic pe un link către `/about` are acum `user-locale=en`, iar o schimbare ulterioară a limbii browserului nu mai redirecționează `/`. Prima încărcare a acelui URL nu stochează nimic. În cazul `no_prefix` și în modul hash, o navigare stochează doar o schimbare.
- **Un 404 nu scrie niciun cookie:** nici răspunsul, nici o navigare simplă pe client către el, în niciun mod. În cazul `no_prefix`, un URL care arată ca având prefix nu scrie nici el.
- **În cazul `no_prefix`, un `localeCookie: null` explicit este respectat.** Înainte devenea `user-locale`. Setați-l în blocul `i18n` din `nuxt.config`: un `null` în `modules: [[name, opts]]` sau într-un layer se pierde în continuare.
- **Modul hash citește doar cookie-ul `hash-locale`.** Un `user-locale=de` singur nu mai contează.
- **Un cookie de locale incorect este ignorat și rămâne așa cum este,** în loc să facă fiecare pagină SSR să eșueze cu un 500. Nu mai este șters la fiecare cerere, ceea ce împiedica și o pagină cu prefix să își stocheze locale-ul.
- **Locale-ul din URL are prioritate.** Un `setLocale('de')` dintr-un plugin pe `/en/...` nu mai încarcă dicționarul `de`, iar un cod necunoscut din stare este ignorat.
- **Helperii API de server** (`useLocaleServerMiddleware`, `useTranslationServerMiddleware`) folosesc o singură ordine pe fiecare rută: `?locale` → parametrul `[locale]` sau prefixul → cookie → antet → valoarea implicită. Acum respectă `localeCookie: null` și `autoDetectLanguage: false` și păstrează în cache un dicționar per locale.
- **Suprascrierile la runtime ajung la rutare.** `NUXT_I18N_DEFAULT_LOCALE` și `disabledLocales` de la runtime modifică acum strategia generată (un locale dezactivat oprește rutarea), iar `disabledLocales` de la runtime se adaugă la cele de la build. În cazul `prefix_except_default` și `prefix_and_default`, un `defaultLocale` de la runtime este ignorat, cu un avertisment, deoarece rutele fără prefix ale acelui locale sunt generate la build. Un `fallbackLocale` de la runtime trebuie să fie un locale activat: altfel este eliminat, cu un avertisment, și se aplică valoarea de la build, dacă aceasta este activată. Vedeți [Suprascrieri la runtime](/ro/guide/runtime-overrides).

### SEO și etichete head {#seo-and-head-tags}

- **`dir="auto"` nu mai este implicit.** Un locale fără `dir` primea înainte `dir="auto"`, ceea ce încetinește parsarea paginilor mari. Acum o limbă RTL cunoscută primește `dir="rtl"`, iar orice alt locale nu primește niciun atribut. Acest lucru se aplică pentru Nuxt, `@i18n-micro/vue`, `astro` și `vitepress`. Dacă setați `dir: 'auto'` pe un locale pentru a păstra rezultatul vechi, costă aproximativ 1 s de parsare la 20.000 de elemente: vedeți [Direcția textului](/ro/guide/seo#text-direction).
- **Fiecare pagină SSR are o etichetă nouă:** `<link rel="preload" as="fetch" crossorigin="anonymous" href="/_locales/...">`, inclusiv paginile 404. Cu `apiBaseClientHost`, `href` este pe acel host, care necesită CORS. Un CSP strict trebuie să îl permită.
- **`hreflang` enumeră doar locale-urile care servesc pagina**; `x-default` este emis doar atunci când locale-ul implicit o servește.
- **O pagină nelocalizată nu are `hreflang` sau `og:locale:alternate`.**
- **Canonical și `hreflang` includ `app.baseURL`** când originea provine din cerere. `metaBaseUrl` și `site.url` rămân așa cum sunt scrise.
- **Paginile 404 au `<html lang dir>`**, în locale-ul URL-ului. Nu au canonical, `hreflang`, `og:url`, `og:locale` sau alternative, inclusiv atunci când modulul însuși răspunde cu 404 pe o înregistrare potrivită (`/en/...`). Etichetele transmise prin `replace` din `useI18nHead` rămân, deci omiteți-le pe paginile de eroare.
- **Canonical, `og:url` și `hreflang` păstrează un query aflat pe lista permisă** (`/about?page=2`), inclusiv pe server: înainte era eliminat în timpul SSR. `page`, `sort`, `filter`, `search`, `q`, `query` și `tag` sunt pe lista permisă implicit; vedeți [`canonicalQueryWhitelist`](/ro/api/module-options#canonicalquerywhitelist).
- **Un `X-Forwarded-Host` care nu poate fi parsat este ignorat**, în loc de un 500 pe fiecare pagină. Fără un host utilizabil și fără `metaBaseUrl` sau `site.url`, URL-urile canonical și `hreflang` din acel răspuns sunt relative. Un `Host` care nu poate fi parsat rămâne un 500, ca într-o aplicație Nuxt simplă.
- **`disableMeta` funcționează acum,** atât în `$defineI18nRoute`, cât și în `routeDisableMeta`, inclusiv când este setat în `nuxt.config`: pagina nu are `hreflang`, canonical sau `og:locale`. `lang` și `dir` rămân.
- `useLocaleHead()` returnează și `build()`, un getter pentru `useHead(() => build())`.
- Pe un build simplu fără `metaBaseUrl`, `X-Forwarded-Host` alege în continuare host-ul din aceste etichete, ca înainte. Fixați `metaBaseUrl` dacă originea este accesibilă direct: vedeți [În spatele unui proxy sau CDN](/ro/guide/deployment#behind-a-proxy-or-cdn).

### Traduceri {#translations}

- **Îmbinările sunt în profunzime la fiecare nivel.** Fișierele de la rădăcină, de pagină și de rezervă foloseau o îmbinare pe 2 niveluri, deci `a.b.c` dintr-un fișier de rezervă sau de la rădăcină se pierdea în modul sursă și în dezvoltare. Toate modurile dau acum același dicționar.
- **Lanțurile de rezervă sunt urmate până la capăt** (`fr` → `de` → `en`) în fiecare mod.
- **Îmbinarea se face după locale, nu după tipul fișierului.** Fișierul de la rădăcină al locale-ului activ are acum prioritate față de fișierul de pagină al unui locale de rezervă. Vedeți [Locale-uri de rezervă](/ro/guide/translations#fallback-locales).
- **O intrare `locales` a proiectului are prioritate față de cea a unui layer** pentru același `code`; un layer doar completează golurile.
- **O pagină fără propriul dosar `pages/<name>/` citește dicționarul de la rădăcină,** inclusiv paginile copil. Înainte primea `{}` și afișa chei brute. Rezultatul build-ului primește câte un fișier pentru fiecare astfel de pagină și `__root/<locale>/data.json` pentru fiecare locale: `/_locales/<any name>/en/data.json` este un 200 cu cheile de la rădăcină; era `{}`. Acest lucru contează pentru monitorizare, pentru listele permise de pe host-urile statice și pentru instrumentele care citesc arborele.
- **`disablePageLocales: true` citește doar fișierele de la rădăcină;** `pages/index` nu mai este îmbinat.
- **Cheile paginii care este părăsită nu mai sunt rezolvate când elementul ei părăsește documentul.** Dacă un layout folosea chei pe care le avea doar fișierul paginii anterioare, mutați-le în fișierul de la rădăcină. Cheile unui părinte rămân cât timp este afișat copilul său, inclusiv pentru un părinte cu un copil `index`, până la următoarea navigare. Între doi copii ai aceluiași părinte, cheile proprii ale părintelui necesită dicționarul copilului sau pe cel de la rădăcină.
- **`$clearCache()` reîncarcă dicționarul paginii curente** și îl păstrează pe ecran pe cel vechi până când sosește cel nou. O reîncărcare eșuată păstrează dicționarul vechi, un răspuns cerut înainte de golire este ignorat, iar o pagină aflată în tranziția de părăsire rămâne tradusă.
- **`$has(key, route)` respectă ruta.**
- **`$loadPageTranslations` pe o pagină încă nevizitată nu mai împiedică încărcarea fișierului acesteia.** Fișierul se încarcă la prima vizită, iar cheile dvs. rămân deasupra lui. Înainte, pagina afișa chei brute până la o reîncărcare.
- **HMR pentru traduceri aplică modificările pe loc**, fără reîncărcarea paginii; cheile eliminate dispar, iar modificările de la rădăcină ajung pe fiecare pagină.
- **Un fișier de locale defect afișează un avertisment o singură dată, cu calea sa, în fiecare mod.** În dezvoltare arunca înainte o eroare, iar modul premerged îl ignora în tăcere, deci o aplicație care se baza pe eșecul brusc din dezvoltare nu mai vede acest lucru.

### Plurale și formatare {#plurals-and-formatting}

- `$tc` cu un număr negativ, fracționar sau foarte mare ia ultima formă cu numărul real; `{ count: null }` nu mai aruncă o eroare; o cheie de plural lipsă ajunge la handler-ul pentru chei lipsă.
- `$tdr` dă date viitoare reale (`in 3 days` sau `tomorrow` cu `numeric: 'auto'`) și `Invalid Date` pentru o intrare invalidă. Sub o secundă în trecut este `0 seconds ago`.
- **`$tn`, `$td` și `$tdr` se ghidează după `iso`**, la fel ca pluralele: `{ code: 'en', iso: 'en-GB' }` formatează acum datele ca `31/10/2026`. Într-un cod de locale, `_` este citit ca `-`, deci `en_US` nu mai aruncă o eroare, iar un cod pe care `Intl` nu îl cunoaște formatează ca `en`, în loc să urmeze locale-ul mașinii. Formatele cu nume sunt căutate în continuare după `code`.
- Un placeholder `{param}` citește doar parametrii pe care îi transmiteți (`{constructor}` rămâne așa cum este scris).
- Numele `{placeholder}` pot conține orice caracter, cu excepția acoladelor și a spațiilor: `{firstName}`, `{first-name}` și `{user.name}` sunt citite din `params`. Fără un astfel de parametru, rămân așa cum sunt scrise, ca înainte.
- Un `defaultValue` este interpolat, în `$t` și `$tc`: `$t('missing', { n: 1 }, 'Got {n}')` dă `Got 1`; înainte dădea `Got {n}`. O valoare implicită care nu este un șir este returnată ca atare.
- `$tc` pe o traducere goală răspunde `''`, la fel ca `$t`. Înainte răspundea cu valoarea implicită sau cu cheia.
- **Șabloanele de plural își păstrează semnificația, cu o singură excepție.** Tabelul enumeră fiecare formă. Pentru a obține categoriile `Intl.PluralRules`, indicați acest lucru cu noul [marcaj `=0 `](/ro/api/methods#$tc): `=0 no apples | one apple | {count} apples`.

  | Formă | Exemplu (în `uk`) | Înainte | Acum |
  | --- | --- | --- | --- |
  | Orice șablon într-un locale cu una sau două categorii pentru numere întregi (`en`, `de`, `fr`, `es`, `ja`...) | `none \| one \| {count} many` | după index | **neschimbat** |
  | O formă pentru fiecare categorie | `one \| few \| many` | după index: 21 → `many` | **neschimbat**. Adăugați marcajul pentru 21 → `one` |
  | Forma pentru zero prima, trei forme | `none \| one \| many` | după index | **neschimbat** |
  | Alți placeholderi | `no items \| {n} item \| {n} items` | după index | **neschimbat** |
  | `{count}` în fiecare formă | `{count} many \| {count} one \| {count} few` | după index | **neschimbat** |
  | Mai puține sau mai multe forme decât mai jos | `a \| b`, `none \| one \| two \| {count} many` | după index | **neschimbat** |
  | În `lv`, `prg`, `blo`, `cv`, `ksh`, `lag` | `none \| one \| {count} many` | după index | **neschimbat** |
  | Marcat cu `=0 ` | `=0 none \| one \| many` | marcajul era afișat ca text | forma pentru zero, apoi categoriile |
  | **O formă pentru zero fără placeholder, apoi o formă pentru fiecare categorie, cu `{count}` în fiecare formă pe care o partajează mai multe numere** | `none \| {count} one \| {count} few \| {count} many` | după index: 3 → `3 many`, 21 → `21 many` | **după categorie**: 3 → `3 few`, 21 → `21 one`. 0, 1, 2 și fiecare număr care rămâne în `many` dau același rezultat |

  Ultima formă necesită trei sau mai multe categorii (`ru`, `uk`, `pl`, `cs`, `sk`, `hr`, `sr`, `lt`, `ro`, `sl`, `he`, `ar`, `cy`...). În `ar`, `one` și `two` sunt numere unice, deci acele două forme nu au nevoie de număr.
- **Un cod de locale pe care `Intl` nu îl cunoaște primește regula după index**, cu sau fără categoriile marcajului: `ua` nu mai urmează locale-ul mașinii. Setați `iso`: `{ code: 'ua', iso: 'uk-UA' }` formează pluralul ca în ucraineană, în modul și în `@i18n-micro/vue`.
- **O regulă `plural` personalizată își păstrează semnătura** și primește în continuare codul de locale. Citește valoarea brută, deci un șablon marcat ajunge la ea cu `=0 ` pe loc, și primește numărul ca `Number`: `1.5`, unde înainte primea `1`. Returnarea `null` revine la regula încorporată, care respectă marcajul.
- **Opțiunea `timeZone`.** Setați-o (`Europe/Berlin`) pentru a randa aceeași dată calendaristică pe server și în fiecare browser. Nu are efect asupra `relativeDate`, care depinde de ceas.

### `<i18n-t>` {#&lt;i18n-t>}

Această secțiune acoperă `<i18n-t>` din modul și `I18nT` din `@i18n-micro/vue`. Pentru celelalte framework-uri, vedeți [Pachete pentru framework-uri](#framework-packages).

- **`html` aplică escaping pentru `params`, în fiecare caz, și ignoră toate sloturile.** Doar traducerea este markup de încredere. Un parametru care conținea intenționat markup apare acum ca text: puneți markup-ul în traducere și transmiteți datele ca parametri sau folosiți sloturi fără `html`.
- **Sloturile funcționează cu `plural`, `number`, `date` și `relativeDate`,** iar un slot `default` primește `{ translation }` și în aceste cazuri. Fiecare `{name}` este completat, nu doar primul.
- **Un slot are prioritate față de un parametru cu același nume.** O valoare de parametru care arată ca un placeholder rămâne text. Cu un `customPluralRule` sau un `plural` personalizat, regula returnează un șir finalizat, deci un parametru pe care l-a interpolat poate fi luat drept placeholder acolo.
- **`null` înseamnă nesetat** pentru `plural`, `number`, `date` și `relativeDate`. `:plural="null"` făcea înainte ca randarea să eșueze, iar `:date="null"` randa 1970.
- `plural` numără ca `$tc`, cu `Number`: `1.5` rămâne `1.5` și ia ultima formă (înainte era trunchiat la `1`); `"2 items"` este `NaN` (înainte era `2`); `""` este `0`. Un `customPluralRule` vede și el `1.5`. Celelalte aspecte ale contractului său sunt neschimbate: aceleași argumente, răspunsul său este folosit ca atare, `null` randează gol.
- `hideIfEmpty` se aplică pentru `plural`, `number`, `date` și `relativeDate`. O valoare ascunsă randează un comentariu, nu un nod text gol, deci un test care citea `''` vede `<!---->`.
- **O cheie lipsă cu `html` este text.** Cheii i se aplică escaping, deoarece doar o traducere este de încredere, iar o cheie poate proveni dintr-o cerere. Un `defaultValue` vă aparține și rămâne markup.
- Cu `plural`, un `defaultValue` sau cheia rămâne întreg(ă) când lipsește traducerea, ca în `$tc`: `a | b` nu mai este împărțit.
- `defaultValue` înlocuiește o cheie lipsă în fiecare ramură, nu cheia însăși, iar un `customPluralRule` îl primește prin getter-ul său când lipsește traducerea. Înainte avea efect doar după `hideIfEmpty`.
- `<i18n-t>` cu `number`, `date` sau `relativeDate` păstrează `params`; acestea sunt îmbinate.
- Rezultatul pentru `date` și `relativeDate` conține `data-allow-mismatch="text"`: un ceas sau un fus orar care diferă între server și browser nu mai generează avertismente în timpul hidratării. Lângă un slot cu nume, textul din jurul slotului se află într-un `<span>` propriu, deoarece Vue verifică atributul doar pe textul unic al unui element.
- Atributele `.innerHTML` și `textContent` sunt eliminate împreună cu `innerHTML`.
- `<i18n-t>` și `<i18n-group>` citesc dicționarul activ, la fel ca `$t`, nu fragmentul rutei. Fragmentele evacuate (`cacheMaxSize`) nu mai afișează chei brute. O pagină aflată în tranziția de părăsire citește acum ce citește `$t` acolo: dicționarul paginii noi, revenind la propriul dicționar când lipsește o cheie, deci o cheie definită de ambele pagini afișează textul nou, iar după o comutare de locale propriile chei apar brute până la demontare.

### `<i18n-switcher>` și `<i18n-link>` {#&lt;i18n-switcher>-and-&lt;i18n-link>}

- **Un clic pe un link al selectorului de limbă este o singură navigare.** Este un simplu `<a>` care apelează `$switchLocale`, nu un `NuxtLink` plus un handler de clic, deci clasele `router-link-active` au dispărut. `href` conține în continuare `app.baseURL`, iar linkul locale-ului curent are în continuare `aria-current="page"`. Ctrl/cmd-clic deschide o filă nouă și lasă fila curentă neschimbată. Linkurile păstrează query-ul și hash-ul.
- Butonul este `type="button"`, deci nu mai trimite un formular înconjurător, și are `aria-expanded`. `aria-haspopup` a dispărut, în modul, `@i18n-micro/vue` și `@i18n-micro/astro`: promitea un meniu, iar lista este formată din linkuri. Escape și un clic în afară închid lista derulantă; două selectoare nu mai rămân deschise simultan.
- Wrapper-ul și lista derulantă au clasele `i18n-switcher-wrapper` și `i18n-switcher-dropdown`; butonul are `i18n-switcher-button`, pe lângă `language-switcher`, iar eticheta sa se află într-un `<span>`. Stilurile implicite folosesc proprietăți CSS logice (`inset-inline-start`, `margin-inline-start`), iar săgeata este `▾`. Lista derulantă are `z-index: 1000` (era 10), `min-width: 150px` și un `box-shadow`, iar wrapper-ul `vertical-align: middle`. Fiecare link are `lang` și `dir`, atunci când locale-ul îl setează.
- `<i18n-link>`: `https://`, `mailto:` și `tel:` sunt recunoscute indiferent de majuscule (`HTTPS://x.com`, `Mailto:`). Un simplu `report.pdf` sau `index.html` este o rută, nu `https://report.pdf`; `example.com` și `example.com:8080` rămân externe. O terminație de fișier care este și TLD (`example.md`, `x.zip`) contează ca fișier: scrieți `https://`. `activeStyle` ignoră bara oblică de la final, query-ul și hash-ul. Este acum tipizat `CSSProperties`, deci unele valori tipizate ar putea necesita o modificare.

### Hook-uri, plugin-uri și tipuri {#hooks-plugins-and-types}

- **`i18n:register` rulează la `app:created` la pornire,** după toate plugin-urile, în loc de între ele. Un plugin cu `order` peste 1 sau `enforce: 'post'` are acum abonatul apelat și la pornire, dar nu mai citește cheile înregistrate în propriul `setup`. Într-o navigare, hook-ul rulează acum înaintea guard-urilor `router.beforeEach` ale altor plugin-uri.
- **`i18n:register` primește locale-ul paginii pe care o completează.** În cazul `hashMode`, o navigare care schimbă locale-ul îl transmitea pe cel vechi, iar cheile ajungeau în fragmentul greșit.
- **`i18n:register` este un hook runtime:** înregistrați-l cu `nuxtApp.hook('i18n:register', …)` într-un plugin, fără `@ts-expect-error`. Vedeți [Hook-uri](/ro/api/events).
- **`hooks: false` și `define: false`** dezactivează în continuare părțile lor.
- **Cu `plugin: false`, `$defineI18nRoute` rămâne apelabil** și nu face nimic la runtime. Înainte făcea pagina să se blocheze.
- Opțiunea `hooks` nu mai documentează `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`; nu au fost emise niciodată.
- `const { $defineI18nRoute } = useNuxtApp()` într-o pagină funcționează acum cu configurații care folosesc variabile.
- `useI18n()` are mai multe chei: `clearCache`, `pluralFunc`, `pluralLocale`. `clearCache` este pe tipul său.
- `$getRouteName(route)` răspunde pentru ruta primită. Înainte returna un șir gol.
- `useI18nLocale()` elimină `getLocaleWithServerFallback(serverLocale)`: scrieți `getPreferredLocale() ?? serverLocale ?? null`.
- **`$getI18nConfig()` este doar pentru citire pe server în dezvoltare.** O scriere aruncă o eroare acolo, iar în producție ar ajunge la fiecare cerere.

### Server, build și deployment {#server-build-and-deployment}

- **Fișierul de payload al unei pagini conține doar ce diferă față de rădăcina locale-ului.** Clientul încarcă rădăcina o singură dată și îmbină fiecare pagină peste ea, astfel încât pachetele de pe disc și Edge se micșorează, iar o a doua pagină costă o fracțiune din prima. `premerged` scrie acum `__root/<locale>/data.json`, iar `/_locales/<page>/<locale>/data.json` conține doar diferența: orice citește direct acele fișiere trebuie să le îmbine pe cele două. Un dicționar complet este în continuare un fișier valid, deci un host sau modul `source` care servește unul continuă să funcționeze.
- **Fișierele de dicționar sunt puse în cache după versiune.** Un URL cu `?v=` curent este fixat pentru un an pe un server Node, celelalte URL-uri sunt revalidate, iar copia statică a unui host răspunde cu `max-age=60`: vedeți [Antete de cache](/ro/guide/deployment#cache-headers-and-datebuild). `httpCacheControl: false` păstrează `max-age=0`. O traducere modificată fără rebuild ajunge la un browser doar când `v` se schimbă: setați `NUXT_I18N_DATE_BUILD`.
- **Dicționarele urmează `app.cdnURL`.** Browserul preia fișierele de payload publice de la `<cdnURL>/_locales/...`, unde înainte folosea `app.baseURL`: CDN-ul trebuie să conțină `_locales/` și să permită originea site-ului (CORS). Vedeți [App baseURL și host-uri pentru payload](/ro/guide/deployment#app-baseurl-and-payload-hosts).
- **SSR nu mai cere `/_locales` prin HTTP,** deci un middleware de server sau un log pe acea rută nu mai vede citirile randării. Un `apiBaseServerHost` extern trece în continuare prin HTTP.
- **O citire eșuată nu mai rămâne memorată, la fel nici un 404.** Un 404 de la un host înseamnă că nu are un astfel de fișier: randarea afișează dicționarul de la rădăcină, la fel ca browserul, nimic nu este păstrat, iar fișierul este citit odată ce apare. Orice alt eșec, un 200 care nu este un obiect JSON sau un fișier local ilizibil sau corupt nu ajunge în niciun cache, iar următoarea cerere citește din nou: o randare de pagină afișează un avertisment în log, afișează chei brute și răspunde cu `503`, cu `no-store` și `Retry-After`, astfel încât o regulă de rută sau un CDN nu păstrează nimic din ea, în timp ce browserul citește în continuare dicționarul la hidratare; `/_locales/...` răspunde cu `503` cu `no-store`, iar `useTranslationServerMiddleware` oferă un `t` care răspunde cu cheia sau cu valoarea implicită. În timpul unei întreruperi, fiecare cerere ajunge la host, iar un host care nu trimite antete de răspuns timp de 60 de secunde face citirea să eșueze. O descărcare lentă a unui fișier mare nu are limită. Vedeți [Când un dicționar nu poate fi citit](/ro/guide/deployment#when-a-dictionary-cannot-be-read). `/_locales` transmite și el acel 404, unde înainte răspundea `200 {}`.
- **O prerandare care nu își poate încărca dicționarul eșuează,** la fel ca una al cărei host nu are nici fișierul paginii, nici fișierul de la rădăcină. Ruta este un 500, un avertisment numește locale-ul și pagina și nu se scrie niciun fișier; cu `failOnError` implicit din Nuxt, build-ul se termină cu codul 1. O pagină fără propriul fișier, peste un fișier de la rădăcină, este prerandată cu rădăcina.
- **Un host setat la build răspunde pentru SSR,** inclusiv cu copia publică implicită și pe o pagină de eroare pe o cale internă. Înainte răspundea fișierul public. `NUXT_I18N_APP_BASE_SERVER_HOST` la runtime ajunge acum la `/_locales` și la încărcătorul de server, iar randarea citește oricare host prin acel încărcător.
- **Un `nitro.output.publicDir` personalizat și orice altă structură în care `public/` nu se află lângă server încorporează payload-urile.**
- **`nuxi build --preset <static preset>` prerandează la fel ca `nuxi generate`,** deci poate scrie mai multe fișiere. `nuxi generate` prerandează fiecare pagină statică în fiecare locale care o servește, cu sau fără linkuri către ea, cu excepția cazului în care o regulă de rută setează `prerender: false`.
- **`source` sau `publicAssets: false` pe un rezultat static generează un avertisment.** Nu există nimic de citit pentru browser.
- **Avertismentul despre încorporare este acum o verificare de dimensiune.** Build-ul afișează un avertisment doar peste limita unei platforme: vedeți [Limitele pachetelor](/ro/guide/deployment#bundle-limits-on-edge).
- **`Vary` este setat oriunde decide vizitatorul:** pe fiecare pagină în cazul `no_prefix` și pe `/` și orice alt URL care poate redirecționa după preferință. Conține `Cookie` când se folosește un cookie și, cu `autoDetectLanguage`, `Accept-Language`. Verificați cheia de cache a CDN-ului: vedeți [Cache-ul HTML](/ro/guide/deployment#caching-html).
- **Cache-ul pentru `/_locales` s-a schimbat.** Nu mai există un cache de rută Nitro pe `/{apiBaseUrl}/**`, iar antetul `s-maxage=60, stale-while-revalidate` a dispărut. Dacă vă bazați pe acel cache, puneți un CDN în fața rutei de payload. Un dicționar gol nu este niciodată `immutable`.
- **Cache-ul de pe server este limitat implicit:** cel mult 1000 de intrări când `cacheMaxSize` nu este setat. `cacheTtl` se numără de la momentul în care a fost stocată o intrare; citirile nu o mai prelungesc.
- **Nou, opțional, [`cacheStorage`](/ro/guide/performance#shared-cache-for-several-instances):** un cache de dicționare partajat de mai multe instanțe. Dacă nu este setat, nu se schimbă nimic.

| devtools-ui | `/files` și `/file` sunt înlocuite de `/translations`; o cerere cross-site sau de pe un host străin primește 403, `/save` necesită `application/json`; actualizările vin prin socket-ul Vite, fără interogare la 2 s; Astro folosește `i18nDevToolsIntegration`. `vite` este un peer opțional | — |
| devtools-ui | `createBridge` acceptă o opțiune `base`; o salvare eșuată către un endpoint accesibil aruncă o eroare și anulează modificările | Transmiteți `base` dacă ați schimbat `base` al plugin-ului |
| devtools-ui | `/save` acceptă doar un `.json` existent din `translationDir` și nu mai creează fișiere | Creați singuri fișierele de locale noi |

## De la v2 la v3 {#from-v2-to-v3}

### Opțiuni eliminate {#removed-options}

```diff
 i18n: {
-  includeDefaultLocaleRoute: true,
+  strategy: 'prefix',
-  fallbackRedirectComponentPath: '~/components/MyRedirect.vue',
-  experimental: { hmr: true, previousPageFallback: true },
+  hmr: true,
 }
```

- `includeDefaultLocaleRoute: true` este `strategy: 'prefix'`; `false` este valoarea implicită `prefix_except_default`.
- `fallbackRedirectComponentPath` a dispărut: redirecționările au loc pe server înainte de randare și într-un middleware de rută pe client. Logica personalizată de redirecționare se pune într-un plugin care setează locale-ul, vedeți [Detectarea personalizată a locale-ului](/ro/guide/custom-auto-detect).
- `experimental.hmr` este opțiunea `hmr` de la rădăcină (activată implicit).
- `previousPageFallback` a dispărut: cheile paginii părăsite sunt rezolvate până la finalul tranziției sale, fără nicio opțiune.

### Starea locale-ului {#locale-state}

Folosiți `useI18nLocale()` în loc de `useState('i18n-locale')` și `useCookie('user-locale')`:

```diff
- useState('i18n-locale').value = 'fr'
- useCookie('user-locale').value = 'fr'
+ useI18nLocale().setLocale('fr') // state and cookie together
```

### Configurația la runtime {#config-at-runtime}

Citiți configurația, inclusiv suprascrierile la runtime, cu `$getI18nConfig()`:

```diff
- const cookieName = useRuntimeConfig().public.i18nConfig?.localeCookie
+ const { $getI18nConfig } = useNuxtApp()
+ const cookieName = $getI18nConfig().localeCookie
```

### Aliasuri interne de tip {#internal-type-aliases}

Dacă IDE-ul sau `vue-tsc` nu poate rezolva importurile `#i18n-internal/*`, mapați-le în `package.json`. Nuxt le rezolvă la build, deci acest lucru este rareori necesar:

```json
{
  "imports": {
    "#i18n-internal/plural": "nuxt-i18n-micro/internals",
    "#i18n-internal/strategy": "nuxt-i18n-micro/internals",
    "#i18n-internal/config": "nuxt-i18n-micro/internals"
  }
}
```
