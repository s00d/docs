### Descriere {#description}

Compară **Nuxt simplu**, **i18n-micro** și **`@nuxtjs/i18n`** sub un singur profil de dicționar comun, prin `untestutils/perf`.

Accent: timpul de build, RSS maxim, **cod vs traduceri (asset) vs total** livrabil și sarcina (Artillery).

### Note despre metodologie {#methodology-notes}

- Metricile sunt **medii a 3 rulări consecutive pentru fiecare fixture** (nu intercalate).
- **Artefact**: Nitro node-server `.output/server/index.mjs` după `nuxi build` forțat; `nuxt-i18n-micro` este **dist-ul compilat al modulului** (nu stub-ul jiti din `dev:prepare`). Vezi [metodologia benchmark-ului](https://s00d.github.io/nuxt-i18n-micro/contributing/performance-methodology).
- **Traduceri** = `bundle.asset` (JSON-ul limbilor, `chunks/raw/`, chunk-urile de limbă potrivite prin `isTranslationFile`).
- **Codul** exclude source maps (`*.map`): fixture-urile leagă modulul din repo, așa că Nitro scrie hărți complete pentru el și niciuna pentru dependențele npm.
- **plain-nuxt** servește același volum de frunze ca JSON static — intens I/O sub sarcină, nu „overhead i18n”.
- Profil de sarcină `--load full`: încălzire 6s@6 + principal 60s@60 fără limită (istoric).
- Pauze de răcire `--cool fast` (vezi documentul de metodologie).
- Fiecare dintre build-urile din `runs` este **forțat** (fără reducerea timpului de build prin cache cald).
- **Rata de erori** Artillery din tabele reprezintă erorile de status HTTP din metricile de sarcină. Graficele afișează și `vusers.failed` (timeout-uri ale clientului la saturație); acestea pot fi ridicate în timp ce rata de erori HTTP rămâne 0%.
### Rulări {#runs}

Toate metricile de mai jos sunt **medii pe 3 rulări**.

## Note {#notes}

- Profil comun: 4 limbi × 2 pagini × ~16.8k frunze index.
- Sarcină: doar Artillery programatic — încălzire **6s@6** + principal **60s@60**, VU fără limită (metodologie YAML istorică). Căile provin din profilul runtime — vezi `scripts/src/perf/load.ts`.
- Pauze de răcire: 2s după build, 3s între rulări, 5s între fixture-uri. Build-urile sunt forțate la fiecare rulare, astfel încât mediile nu sunt diluate de cache hit-uri.
- Re-rulare zilnică: `pnpm test:performance` (`--load short --cool fast`).
- Regenerarea acestei pagini: `pnpm -C scripts cli performance --load full --only all --runs 3`.
- Flag-uri: `--locales N --keys K --only all|micro|i18n|plain --runs N --skip-load --cool fast|strict`.
