---
title: "Căi localizate"
description: "Dați unei pagini un URL diferit pentru fiecare limbă cu localeRoutes sau globalLocaleRoutes, inclusiv parametri dinamici și slug-uri per limbă."
---

În mod implicit, fiecare limbă servește o pagină la aceeași cale: `/en/about`, `/de/about`. Căile localizate permit fiecărei limbi să folosească propriile cuvinte, de exemplu `/de/ueber-uns`, în timp ce fișierul paginii rămâne același. Le setați în pagină cu `$defineI18nRoute`, sau pentru mai multe pagini deodată în `nuxt.config.ts`.

## În pagină {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

Cu `prefix_except_default` și `defaultLocale: 'en'`, pagina răspunde la `/about`, `/de/ueber-uns` și `/fr/a-propos`. O limbă fără intrare păstrează calea implicită. Scrieți căile fără codul limbii: prefixul este adăugat de [strategie](/ro/guide/strategy), iar o cale care începe cu codul limbii generează un avertisment. Ce altceva acceptă apelul găsiți în [Configurarea paginii](/ro/guide/per-component-translations).

## În nuxt.config {#in-nuxt-config}

[`globalLocaleRoutes`](/ro/api/module-options#globallocaleroutes) face același lucru pentru orice pagină, cu cheia dată de calea ei (sau de numele rutei, când este scris fără slash la început):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

Când o pagină setează `localeRoutes` și `globalLocaleRoutes` are aceeași cheie, intrarea din configurație are prioritate.

## Parametri dinamici {#dynamic-params}

Scrieți parametrii în orice formă Nuxt: `[id]`, `[[page]]`, `[...slug]` sau `:id()`. Numele parametrilor trebuie să corespundă fișierului paginii.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

Paginile imbricate primesc o cale copil absolută (`/ueber-uns/team`) sau o cale relativă la calea localizată a părintelui (`team`).

## Link-uri către pagini localizate {#linking-to-localized-pages}

Link-urile se rezolvă la calea localizată a limbii țintă, fie că transmiteți un nume de rută, fie o cale simplă:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

Numele rutelor provin din calea fișierului (`pages/about/team.vue` devine `about-team`), cu excepția cazului în care setați unul cu `definePageMeta({ name })`.

## Slug-uri per limbă {#per-locale-slugs}

Când slug-ul însuși diferă de la o limbă la alta (`/our-products/red-shoe` vs `/de/unsere-produkte/roter-schuh`), indicați selectorului de limbă ce parametri să folosească cu `$setI18nRouteParams`, după ce datele s-au încărcat:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

`$switchLocalePath('de')` și `<i18n-switcher>` vor face apoi link către `/de/unsere-produkte/roter-schuh`. Cheile sunt coduri de limbă, valorile sunt parametri după nume (ca în fișierul paginii).

Un selector din layout se randează înainte ca setup-ul asincron al paginii să ajungă aici, așa că, la finalul randării, modulul rescrie link-urile din `<i18n-switcher>`, atât în `app.vue`, cât și în pagină. HTML-ul de pe server, un vizitator fără JavaScript și prima randare pe client sunt astfel în acord. Pentru aceasta, setați parametrii în timpul SSR: cu `lazy` sau `server: false`, link-urile se schimbă doar după hidratare. Streaming-ul SSR al Nuxt trimite HTML-ul înainte ca parametrii să fie cunoscuți, așa că în acest caz link-urile din primul HTML păstrează parametrii din URL.

Doar link-urile proprii ale selectorului sunt rescrise. Un link `$switchLocalePath` scris manual trebuie să se randeze după ce parametrii sunt setați, așa că puneți-l în pagina care îi setează, tot după un `await`. Într-un layout se randează primul: HTML-ul său de pe server păstrează parametrii din URL, iar hidratarea avertizează despre o nepotrivire. Folosiți acolo `<i18n-switcher>`, cu slot-urile sale și proprietățile `custom*Style` pentru aspect.

Parametrii aparțin paginii care i-a setat:

- Sunt eliminați când se finalizează o navigare către o altă cale, așa că fiecare pagină își setează propriii parametri. O navigare anulată îi lasă pe loc.
- Luați `$setI18nRouteParams` din `useNuxtApp()` sau `useI18n()` în `setup`, chiar și când îl apelați mai târziu într-un handler `useAsyncData`. Preluată acolo, funcția își cunoaște pagina: dacă vizitatorul a plecat, un apel întârziat nu face nimic.
- Cu `keepalive`, o pagină își primește înapoi parametrii setați când vizitatorul revine. `useI18nHead` face același lucru.

## Rute adăugate în pages:extend {#routes-added-in-pages-extend}

Rutele pe care le adăugați în hook-ul `pages:extend` nu au un fișier de pagină din care să se citească `$defineI18nRoute`, iar mai multe dintre ele împart adesea o singură componentă wrapper. O rută adăugată fără `name` primește numele pe care Nuxt l-ar da căii sale (`/a/:id()` devine `a-id`), astfel încât link-urile de limbă ajung la ea, cu excepția cazului în care o altă rută are deja acel nume; atunci dați-i un `name` explicit. Păstrați o singură listă și împărțiți-o în pagini și `globalLocaleRoutes` cu cheia numele rutei, folosind `splitLocaleRoutes` din `@i18n-micro/utils/split-locale-routes` (adăugați pachetul la dependențe):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

Nu puneți căi localizate în `route.meta`: ar ajunge în tabelul de rute de pe client.
