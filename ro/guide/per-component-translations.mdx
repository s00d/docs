---
title: "Configurația paginii"
description: "Restricționați o pagină la anumite locale, dați-i căi personalizate, traduceri inline sau dezactivați etichetele SEO cu $defineI18nRoute."
---

`$defineI18nRoute` setează opțiunile i18n pentru o singură pagină, din interiorul paginii. Folosiți-l atunci când o pagină există doar în anumite locale, are nevoie de propria cale localizată, conține câteva traduceri proprii sau nu trebuie să primească etichete hreflang/canonical. Modulul citește apelul la build și îl include în rutele generate.

## Restricționarea unei pagini la anumite locale {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

Cu strategia implicită `prefix_except_default` sunt generate doar `/product` și `/de/product`; pagina nu are rută în niciun alt locale. Același lucru poate fi setat din `nuxt.config.ts` cu [`routeLocales`](/ro/api/module-options#routelocales).

`$defineI18nRoute` este o injecție a aplicației Nuxt, nu un macro de compilator: luați-l întotdeauna din `useNuxtApp()` și apelați-l cu `$`. Pasul de build recunoaște doar `$defineI18nRoute(`.

## Adăugarea de traduceri inline {#add-inline-translations}

Transmiteți un obiect în loc de un array. Cheile sale sunt locale-urile permise, iar valorile sunt îmbinate în dicționarul paginii pentru locale-ul activ.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Traducerile inline sunt livrate în componenta paginii pentru fiecare locale. Preferați [fișierele de traducere ale paginii](/ro/guide/translations) pentru orice depășește câteva chei; păstrați cheile inline pentru pagini și componente autonome.

## Setarea căilor localizate {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

Cu `prefix_except_default` și `defaultLocale: 'en'`, acest lucru produce `/welcome` și `/de/willkommen`. Un `path` într-un obiect de locale inline face același lucru: `locales: { de: { path: '/willkommen' } }`. Parametrii dinamici, rutele imbricate și alternativa la nivel de configurație sunt descrise în [Căi localizate](/ro/guide/custom-locale-routes).

## Dezactivarea etichetelor SEO {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

Alternativa la nivel de configurație este [`routeDisableMeta`](/ro/api/module-options#routedisablemeta). Ce sunt aceste etichete se explică pe pagina [SEO](/ro/guide/seo).

## Ce poate citi build-ul {#what-the-build-can-read}

Pasul de build găsește apelul în fiecare fișier de pagină și îi evaluează argumentul fără a rula aplicația. Funcționează atunci când configurația este:

- un obiect literal (șiruri, array-uri, obiecte imbricate, template literals, operatori ternari pe `process.env.NODE_ENV`);
- construită din constante declarate în același `<script setup>` (`const locales = ['en', 'de']`, inclusiv spread-uri);
- un array de obiecte cu un câmp `code` (`[{ code: 'en' }, { code: 'de' }]`).

Nu poate citi valori importate din alt modul și nici nimic care are nevoie de aplicație la runtime (composables, `await`, date preluate). În acest caz, build-ul afișează în log `Ignored the $defineI18nRoute() config in <file>`, iar pagina păstrează locale-urile și rutele implicite.

La runtime, apelul doar îmbină traducerile inline pentru locale-ul curent și le reîmbină atunci când locale-ul se schimbă. `locales`, `localeRoutes` și `disableMeta` au efect doar prin build, deci modificarea lor necesită un rebuild (serverul de dezvoltare face rebuild la salvare).
