title: "SEO"
description: "Tag-urile lang, hreflang, canonical și og:locale pe care le adaugă modulul, cum este ales URL-ul lor de bază și cum le suprascrieți pe o pagină."
---

Cu `meta: true` (valoarea implicită), fiecare pagină localizată primește `<html lang dir>`, un link canonical, alternative `hreflang`, `x-default` și tag-uri Open Graph pentru limbă. Aveți nevoie de această pagină când doriți să setați originea publică, să ajustați ce limbi apar în tag-uri sau să le suprascrieți pentru o pagină. Majoritatea site-urilor au nevoie doar de un `site.url` sau `metaBaseUrl` și de coduri `iso` corecte.

## Configurare minimă {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

`/de/about` randează apoi:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Direcția textului {#text-direction}

`<html dir>` provine din `dir`-ul limbii. Fără acesta, o limbă scrisă de la dreapta la stânga primește `rtl`, determinat din `iso` (sau `code`): araba, ebraica, persana, urdu și câteva altele, precum și orice tag cu o scriere RTL, cum ar fi `az-Arab`. Toate celelalte limbi nu primesc atributul `dir`, pe care browserele îl interpretează ca `ltr`.

<Warning>

**`dir: 'auto'` costă timp de parsare pe paginile mari** — `auto` pe `<html>` obligă browserul să deducă direcția din conținut în timpul parsării. În Chromium, acest cost crește mai repede decât pagina: aproximativ 100 ms la 5.000 de elemente și 1 s la 20.000. Folosiți-l doar pentru o pagină mică a cărei limbă nu o puteți cunoaște.

</Warning>

## Ce tag-uri primiți {#which-tags-you-get}

- **hreflang**: câte un tag pentru fiecare limbă care servește pagina, cu valoarea `iso` (sau `code` când `iso` lipsește) și URL-ul său cu același query ca cel canonical. O pagină restricționată prin [Configurarea paginii](/ro/guide/per-component-translations) sau `routeLocales` listează doar limbile sale. [`hreflangBaseLanguage: true`](/ro/api/module-options#hreflangbaselanguage) adaugă și limba de bază (`es-ES` → `es`) pentru prima limbă regională.
- **x-default**: URL-ul limbii implicite, doar când limba implicită servește pagina.
- **og:locale**: derivat din `iso` (`en-US` → `en_US`). Setați `og` pe limbă când maparea nu este directă, de exemplu `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; fără niciuna dintre ele, nu se scrie niciun `og:locale`, iar modul de dezvoltare afișează un avertisment.
- **canonical / og:url**: URL-ul curent fără parametri de query, cu excepția celor din [`canonicalQueryWhitelist`](/ro/api/module-options#canonicalquerywhitelist) (implicit `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

În funcție de strategie:

| Strategie | hreflang și x-default | canonical, og:url, og:locale, atribute html |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | da | da |
| `no_prefix` | nu (un singur URL servește toate limbile) | da |

## Setarea originii publice {#set-the-public-origin}

URL-urile absolute folosesc prima variantă disponibilă dintre:

1. [`metaBaseUrl`](/ro/api/module-options#metabaseurl);
2. `site.url` din `nuxt-site-config` (instalat de `@nuxtjs/seo`);
3. originea cererii, la care se adaugă `app.baseURL`.

Fixați una dintre primele două.

<Warning>

Varianta de rezervă bazată pe originea cererii citește `X-Forwarded-Host` și `X-Forwarded-Proto`, deoarece [`metaTrustForwardedHost`](/ro/api/module-options#metatrustforwardedhost) și `metaTrustForwardedProto` au implicit valoarea `true`. Acest lucru este sigur doar în spatele unui proxy care suprascrie aceste headere; altfel, un client poate alege host-ul din link-urile dumneavoastră canonical, iar un cache poate transmite pagina respectivă mai departe.

Dacă aplicația este accesibilă direct, fixați `metaBaseUrl`: spre deosebire de setarea ambelor opțiuni la `false`, aceasta ignoră și un `Host` falsificat. Consultați [În spatele unui proxy sau CDN](/ro/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

Varianta de rezervă este utilă pentru o singură implementare care răspunde pe mai multe domenii: `https://site-a.com/en/about` și `https://site-b.com/en/about` primesc fiecare propria origine.

Cu `baseUrl` pe limbi, un host cunoscut folosește propriul `baseUrl`, înaintea lui `metaBaseUrl` și `site.url`, astfel încât canonical și `og:url` rămân pe acel domeniu, iar `hreflang` trimite fiecare limbă către domeniul ei. Orice alt host folosește `metaBaseUrl`, altfel `baseUrl`-ul limbii implicite, altfel `site.url`, astfel încât un `Host` falsificat nu poate ajunge în tag-urile dumneavoastră. Dacă niciuna dintre acestea nu este setată, rămâne varianta de rezervă bazată pe originea cererii, iar build-ul afișează un avertisment. Consultați [Straturi și domenii](/ro/guide/layers#multiple-domains).

## Excluderea limbilor sau a paginilor {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Dacă limba implicită are `seo: false`, nu se scrie niciun `x-default`. Pentru a dezactiva tag-urile pe o pagină, folosiți `disableMeta` în [Configurarea paginii](/ro/guide/per-component-translations#turn-off-seo-tags), sau [`routeDisableMeta`](/ro/api/module-options#routedisablemeta) în configurație.

## Suprascrierea tag-urilor pe o pagină {#override-tags-on-one-page}

Pentru conținut din CMS unde există doar unele traduceri, sau când URL-urile provin dintr-un API, înlocuiți tag-urile generate cu [`useI18nHead`](/ro/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` poate de asemenea seta sau elimina `canonical`, `xDefault`, `ogLocale` și `ogUrl`; `disable` elimină grupuri întregi (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Transmiteți un getter, astfel încât valorile să fie recalculate după o schimbare de limbă. Pentru slug-uri per limbă, setați mai întâi `$setI18nRouteParams` ([Căi localizate](/ro/guide/custom-locale-routes#per-locale-slugs)), iar alternativele generate le vor folosi deja.

## Slash final {#trailing-slash}

`$localePath`, `$switchLocalePath`, obiectul de rută al `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, redirecționările de limbă și URL-urile SEO urmează o singură regulă pentru slash: implicit `experimental.defaults.nuxtLink.trailingSlash`, sau [`trailingSlash`](/ro/api/module-options) din configurația i18n când căile i18n trebuie să difere.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) funcționează cu acest modul prin `nuxt-site-config` 4+. Listați mai întâi `nuxt-i18n-micro`, astfel încât configurația site-ului să poată citi limbile, și setați `site.url` o singură dată — acesta alimentează și tag-urile de mai sus.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Un nume și o descriere traduse ale site-ului provin din cheile `nuxtSiteConfig.name` / `nuxtSiteConfig.description` din fișierele dumneavoastră de limbă. Eroarea `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` înseamnă că `@nuxtjs/seo` este mai vechi decât versiunea 3; actualizați-l ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
