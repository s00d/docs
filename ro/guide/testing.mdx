Componentele care apelează `useI18n()` au nevoie de o instanță i18n în testele unitare. `@i18n-micro/test-utils` vă oferă un `useI18n()` fals cu logică reală de traducere, plural și formatare, astfel încât puteți monta o componentă cu propriile dicționare și fără server Nuxt. Pentru rutare și redirecționări, rulați modulul real end-to-end cu `@nuxt/test-utils`.

Această pagină se referă la testarea aplicației voastre. Modul în care acest repository testează modulul însuși este descris în [Testarea modulului](https://s00d.github.io/nuxt-i18n-micro/contributing/testing).

## Instalare {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

```bash npm

```

## Mock pentru useI18n {#mock-usei18n}

```ts
// tests/unit-setup.ts
import { setupNuxtI18nMock } from '@i18n-micro/test-utils'
import { mockNuxtImport } from '@nuxt/test-utils/runtime'
import { beforeEach, vi } from 'vitest'

export const { i18n, useI18n, setTranslationsFromJson } = setupNuxtI18nMock({
  spy: vi.fn, // every method becomes a vi.fn, so you can assert calls
  beforeEach, // reset state and reseed `translations` before each test
  translations: { welcome: 'Welcome' },
})

mockNuxtImport('useI18n', () => useI18n)
```

```ts
// vitest.config.ts
import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    environment: 'nuxt',
    setupFiles: ['./tests/unit-setup.ts'],
  },
})
```

Păstrați `mockNuxtImport` în fișierul de setup: `@nuxt/test-utils` trebuie să îl transforme. `setupNuxtI18nMock` folosește un cache de traduceri privat, așa că fișierele de test paralele nu împart starea.

## Scrierea unui test {#write-a-test}

```vue
<!-- components/Greeting.vue -->
<script setup lang="ts">
const { $t } = useI18n()
</script>

<template>
  <p>{{ $t('welcome') }}</p>
</template>
```

```ts
// tests/greeting.spec.ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { expect, it } from 'vitest'
import Greeting from '~/components/Greeting.vue'
import de from '~/locales/de.json'
import { i18n, setTranslationsFromJson } from './unit-setup'

it('renders the German greeting', async () => {
  await setTranslationsFromJson('de', de)
  i18n.setLocale('de')

  const wrapper = await mountSuspended(Greeting)
  expect(wrapper.text()).toBe('Willkommen') // de.json: { "welcome": "Willkommen" }
})
```

Falsul expune aceleași metode ca `useI18n()` real (`$t`, `$tc`, `$tn`, `$td`, `$has`, `$localePath`, …, cu și fără `$`) plus setteri pentru teste: `setLocale`, `setLocales`, `setDefaultLocale`, `setRouteName`, `setTranslationsFromJson`, `loadPageTranslations`, `mergeTranslations`, `setMissingHandler`.

`$localePath` și `$switchLocalePath` sunt stub-uri care adaugă prefixul la cale conform opțiunii `strategy` (fără router real). Testați link-urile și redirecționările reale end-to-end.

## Helperi de nivel inferior {#lower-level-helpers}

| Helper | Folosiți-l pentru |
| --- | --- |
| `createIsolatedFakeI18n(options)` | Un fals izolat fără conectarea Nuxt `useI18n`, de ex. pentru `mount` simplu din `@vue/test-utils` cu `global.mocks`. |
| `createFakeI18n(options)` | Un fals pe cache-ul comun al modulului (apelați `resetI18n()` în `beforeEach`) sau izolat cu `isolated: true`. |
| `createI18nTestContext(options)` | Contextul din spatele ambelor, când aveți nevoie de mai multe falsuri. |
| `t`, `tc`, `ts`, `tn`, `td`, `tdr`, `has` | Apeluri directe pe contextul comun, pentru testarea funcțiilor simple. |

Mock-ul este un `BaseI18n`: `t`, `tc`, `tn`, `td`, `tdr` și `has` sunt cele reale, pe dicționare reale, astfel încât un test vede ce afișează aplicația.

Helperii factory de mai sus acceptă `locale`, `defaultLocale`, `locales`, `routeName`, `strategy`, `translations` și `messages` (dicționare per locale). Un proiect exemplu complet se află în [`packages/test-utils/example`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/test-utils/example).

## Teste end-to-end {#end-to-end-tests}

Rutarea, redirecționările, tag-urile SEO și încărcarea payload-urilor necesită modulul real. Porniți aplicația cu `@nuxt/test-utils/e2e`:

```ts
// tests/e2e/locales.test.ts
import { $fetch, fetch, setup } from '@nuxt/test-utils/e2e'
import { describe, expect, it } from 'vitest'

describe('locales', async () => {
  await setup({ server: true })

  it('serves the German page', async () => {
    expect(await $fetch('/de')).toContain('lang="de-DE"')
  })

  it('redirects / for a German browser', async () => {
    const res = await fetch('/', { headers: { 'accept-language': 'de' }, redirect: 'manual' })
    expect(res.headers.get('location')).toBe('/de')
  })
})
```

Al doilea test presupune `prefix` (sau `prefix_except_default` cu alt locale implicit); vedeți [Detectarea locale-ului](/ro/guide/locale-detection) pentru situațiile în care `/` redirecționează.
