---
title: "Suprascrieri la runtime"
description: "Schimbați limba implicită, limba de rezervă sau limbile dezactivate per instanță a aceluiași build, cu variabile de mediu sau runtimeConfig."
---

Suprascrierile la runtime permit ca un singur artefact de build să ruleze cu setări de limbă diferite pentru fiecare mediu sau tenant, fără rebuild. Puteți schimba limba implicită, limba de rezervă și limbile dezactivate. Rutarea, redirecționările, randarea și helperii de server folosesc valorile suprascrise, la fel și browserul pe o pagină randată pe server.

## Setarea suprascrierilor cu variabile de mediu {#set-overrides-with-environment-variables}

```bash
NUXT_I18N_DEFAULT_LOCALE=de \
NUXT_I18N_FALLBACK_LOCALE=en \
NUXT_I18N_DISABLED_LOCALES=fr,it \
node .output/server/index.mjs
```

| Variabilă | Alias |
| --- | --- |
| `NUXT_I18N_DEFAULT_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE` |
| `NUXT_I18N_FALLBACK_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE` |
| `NUXT_I18N_DISABLED_LOCALES` (separate prin virgulă) | `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES` |

Serverul le citește o singură dată la pornire; reporniți pentru a aplica o modificare. Pe o pagină randată pe server, browserul primește valorile rezolvate de la server. Cu `ssr: false` nu există randare pe server, iar browserul nu are mediu: acolo se aplică doar `runtimeConfig.public.i18nRuntime`, iar browserul afișează avertismentele de mai jos.

## Setarea suprascrierilor în runtimeConfig {#set-overrides-in-runtimeconfig}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

O valoare setată în `runtimeConfig.public.i18nRuntime` are prioritate față de variabila `NUXT_I18N_*` pentru același câmp.

A nu se confunda cu variabila `DEFAULT_LOCALE` de la build, care înlocuiește `defaultLocale` în timpul build-ului și nu necesită suport la runtime.

## Ce se poate și ce nu se poate schimba {#what-can-and-cannot-change}

| Setare | La runtime |
| --- | --- |
| `defaultLocale` | Da, sub `prefix` și `no_prefix`. Sub `prefix_except_default` și `prefix_and_default` este fixată la build (paginile ei sunt rutele fără prefix); o suprascriere este ignorată cu un avertisment. |
| `fallbackLocale` | Da. |
| `disabledLocales` | Se adaugă la limbile dezactivate la build; nu reactivează niciodată una. Limba implicită de la build nu poate fi dezactivată sub `prefix_except_default` / `prefix_and_default`. |
| `strategy` | Nu. O strategie la runtime este ignorată cu un avertisment; construiți câte un artefact pentru fiecare strategie. |

Valorile invalide nu strică niciodată aplicația. Fiecare caz afișează un singur avertisment per proces de server:

- dezactivarea tuturor limbilor este ignorată;
- un `defaultLocale` care nu este activat revine la prima limbă activată;
- un `fallbackLocale` care nu este activat păstrează valoarea de la build dacă aceasta este activată, altfel nu există limbă de rezervă.

## Citirea configurației efective {#read-the-effective-config}

```vue
<script setup lang="ts">
const { $getI18nConfig } = useNuxtApp()
const config = $getI18nConfig() // build config with overrides applied
</script>
```

Tratați-o ca doar-citire: pe server este partajată de toate cererile și înghețată în dezvoltare; copia din browser nu este înghețată. Importul configurației din `#build/i18n.strategy.mjs` oferă valorile de la build fără suprascrieri.

## Limbi dezactivate și fișiere statice {#disabled-locales-and-static-files}

O limbă dezactivată la runtime răspunde cu 404 pe rutele sale și pe ruta de payload, dar fișierele sale de payload se află în continuare în `.output/public/_locales/`, iar un server de fișiere statice le returnează. Când acele fișiere nu trebuie să fie accesibile, dezactivați limba la build cu `disabled: true`.
