**Data**: 2026-05-14

**Versiunea**: `v3.20.0`

![Lansarea v3.20.0](/images/3.20.0.png)

Această versiune refactorizează runtime-ul Nuxt într-un strat dedicat **`NuxtI18n`**, separă gestionarea redirecționărilor pe server și pe client și corectează mai multe regresii de SSR/hidratare. Composable-urile publice și opțiunile din `nuxt.config` rămân aceleași pentru aplicațiile obișnuite.

## Ce este nou? {#what’s-new}

### `NuxtI18n` și `NuxtTranslationLoader` {#nuxti18n-&-nuxttranslationloader}

Logica i18n de runtime este mutată din plugin-ul monolitic în clase specializate:

- **`NuxtI18n`** — stratul de vizualizare a traducerilor active (`$t`, `$has`, contextul locale/rută, îmbinarea/curățarea la tranziții)
- **`NuxtTranslationLoader`** — încarcă chunk-urile, schimbă contextul la navigare, inițializează payload-ul SSR
- **`createNuxtI18nPluginApi`** — o suprafață subțire de plugin (`$switchLocale`, `$localeRoute` etc.)

Consultați [Arhitectura cache și stocare](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api) actualizată și [Performanță](/ro/guide/performance).

### Payload SSR prin `useState('i18n-ssr-chunks')` {#ssr-payload-via-usestate'i18n-ssr-chunks'}

Traducerile SSR sunt serializate prin **starea Nuxt**, nu printr-un tag script `window.__I18N__`:

1. Serverul încarcă chunk-urile → `useState('i18n-ssr-chunks')`
2. Clientul face hidratarea → `translationStorage.seedFromSsrChunks()`
3. Zero cereri suplimentare la prima randare

Calea veche de citire `window.__I18N__` a fost **eliminată**.

### Separarea arhitecturii de redirecționare {#redirect-architecture-split}

Redirecționările sunt acum specifice mediului, pentru un comportament mai clar și mai puține sacadări pe client:

| Mediu          | Componentă                     | Rol                                        |
| -------------- | ------------------------------ | ------------------------------------------ |
| **Server SSR** | `06.redirect.ts` (doar server) | 302 înainte de randare, verificări 404, sincronizarea cookie-ului |
| **Client SPA** | `i18n-redirect.global.ts`      | Middleware global de rută la navigare      |

Redirecționările pe client deduc locale-ul din **ruta țintă**, păstrează **query string-ul și hash-ul** și respectă `redirects: false` (middleware-ul nu este înregistrat). Consultați [Detectarea locale-ului — redirecționări pentru fiecare strategie](/ro/guide/locale-detection#redirects-per-strategy).

### Momentul hook-ului `i18n:register` {#i18nregister-hook-timing}

Plugin-ul **`05.hooks`** (`dependsOn: i18n-plugin-loader`) declanșează `i18n:register` după ce loader-ul este gata — la pornire și la navigare — astfel încât plugin-urile utilizatorului primesc evenimentul în mod fiabil. Dezactivați cu `hooks: false`. Consultați [Evenimente](/ro/api/events).

### Extragerea `defineI18nRoute` la build {#build-time-definei18nroute-extraction}

Un unplugin Vite scanează fișierele `.vue` ale paginilor la build și scrie meta-ul rutelor pentru `@i18n-micro/route-strategy`. `$defineI18nRoute` la runtime în `script setup` rămâne pentru dev și configurația inline. Consultați [Traduceri per componentă](/ro/guide/per-component-translations).

## Corecții de erori {#bug-fixes}

- **Hidratarea SSR** — clonează chunk-urile SSR reactive înainte de `Object.freeze` (corectează crash-urile `#locale` / 404 pe client)
- **Schimbarea locale-ului** — înlocuiește stratul de vizualizare la schimbarea locale-ului (fără chei învechite din locale-ul anterior)
- **Redirecționarea pe client** — locale-ul din ruta țintă; query/hash păstrate la redirecționare
- **`has()`** — verifică doar locale-ul activ; fallback-ul se aplică în `$t()`, nu în `$has()`
- **Meta `defineI18nRoute`** — cache per instanță de plugin; potrivirea `rootDir` cea mai lungă; căi corecte `pages/index` vs `pages/index/index`

## Modificări incompatibile {#breaking-changes}

Niciuna pentru utilizarea standard `nuxt.config` + composable-uri. Căile interne și mecanismul de injectare SSR s-au schimbat; aplicațiile care se bazau pe injectarea manuală `window.__I18N__` trebuie să folosească în schimb payload-ul Nuxt / API-urile modulului.

## De ce contează {#why-it-matters}

- **Predare SSR → client mai fiabilă** — stare nativă Nuxt în loc de variabile globale ad-hoc
- **Model de redirecționare mai clar** — 302 pe server înainte de randare; middleware pe client doar unde este nevoie
- **Mai ușor de întreținut** — runtime-ul este împărțit în unități testabile, cu teste de regresie specializate
