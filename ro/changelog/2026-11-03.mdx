**Data**: 2026-11-03

**Versiunea**: `v4.0.0`

![v4.0.0 release](/images/4.0.0.png)

**v4.0.0** a fost lansat. Rutarea, nucleul de traducere, fișierele de dicționar, detectarea limbii și fiecare pachet pentru framework-uri au fost rescrise. Opțiunile, `$t`, `$localePath`, `$switchLocale`, componentele și composables își păstrează numele. Ceea ce se schimbă este comportamentul, iar majoritatea acestor schimbări sunt bug-uri care au dispărut. Majoritatea aplicațiilor necesită puține modificări de cod, dar citiți [Modificări incompatibile](#breaking-changes) înainte de actualizare: URL-urile, etichetele SEO și API-urile pachetelor pentru framework-uri s-au schimbat pe alocuri. [Actualizare](/ro/guide/upgrade) conține toate detaliile.

## Ce este nou? {#what’s-new}

### Un singur build pentru fiecare domeniu {#one-build-for-every-domain}

`locales[].baseUrl` și `baseDefault` modelau înainte doar linkurile. Acum rutează și cererile, sub toate cele patru strategii și în `nuxt generate`:

```ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'fr', baseUrl: 'https://example.com' },
      { code: 'de', baseUrl: 'https://example.de', baseDefault: true },
    ],
  },
})
```

- Un host își servește propriile limbi. Linkurile către limba altui domeniu devin URL-uri absolute pe acel domeniu, iar comutarea la ea navighează acolo.
- `trustForwardedHost` alege domeniul din `X-Forwarded-Host` în spatele unui proxy care îl suprascrie. Dezactivat implicit.
- `NUXT_I18N_DOMAIN` îi oferă lui `nuxt generate` host-ul: rulați-l o dată pentru fiecare domeniu, iar fiecare rezultat conține doar paginile și dicționarele acelui domeniu.
- O aplicație fără `baseUrl` nu include deloc acest cod.

Vedeți [Straturi și domenii](/ro/guide/layers#multiple-domains) și [Implementare](/ro/guide/deployment).

### Rutare în acord cu router-ul {#routing-that-agrees-with-the-router}

Build-ul și runtime-ul nu mai calculează separat URL-urile localizate. Fiecare răspuns provine din rutele generate de build, astfel încât un link, un comutator, `hreflang` și o redirecționare nu pot indica o pagină care nu există.

- O limbă care nu servește o pagină trimite către pagina ei principală, niciodată către pagina altei limbi.
- `hreflang` listează doar limbile care servesc pagina.
- `$switchLocale` se rezolvă cu `true` sau `false`, astfel încât puteți ști când un dicționar nu s-a încărcat. Un apel repetat reîncearcă.
- `$setI18nRouteParams` și `useI18nHead` setate în timpul SSR supraviețuiesc hidratării. Comutatorul trimite către slug-ul tradus, inclusiv în HTML-ul de pe server.
- O navigare are efect când este confirmată: una anulată sau blocată nu schimbă nimic.
- Modul hash funcționează sub `prefix`.
- `<Greeting :locale="$getLocale()" />` pe o componentă de server setează limba ei de randare.

### O singură detectare a limbii {#one-locale-detection}

O singură ordine peste tot: pe server, în browser, în helperii API de server și în Astro. `Accept-Language` respectă valorile `q`, potrivirea regională nu mai depinde de ordinea din `locales` și nu trece niciodată între scrierile chinezești. Suprascrierile la runtime ajung acum la rutare: `NUXT_I18N_DEFAULT_LOCALE` și `disabledLocales` la runtime schimbă ce se servește efectiv. Vedeți [Detectarea limbii](/ro/guide/locale-detection).

### Un singur dicționar în fiecare mod {#one-dictionary-in-every-mode}

Build-urile premerged, `mode: 'source'` și dezvoltarea dădeau rezultate diferite pe multe pagini. Acum oferă același dicționar.

- Îmbinările sunt profunde la fiecare nivel, iar lanțurile de rezervă (`fr` → `de` → `en`) sunt urmate până la capăt.
- Editările traducerilor în dezvoltare se aplică pe loc, fără reîncărcarea paginii. Cheile eliminate dispar, iar o editare a unui fișier rădăcină ajunge la fiecare pagină.
- `$clearCache()` reîncarcă pagina curentă și păstrează vechiul text pe ecran până când sosește noul text.
- Un chunk eșuat păstrează dicționarul curent în loc să afișeze chei brute.

### Fișiere de dicționar mai mici {#smaller-dictionary-files}

- Fișierul unei pagini conține acum doar ce diferă de rădăcina limbii, aflată în `__root/<locale>/data.json`. Browserul încarcă rădăcina o singură dată și îmbină fiecare pagină peste ea, așa că spațiul pe disc scade, iar pagina următoare costă o fracțiune din prima.
- URL-urile dicționarelor poartă o versiune. Un URL cu `?v=` curent este fixat timp de un an pe un server Node, iar copia statică a unui host răspunde cu `max-age=60`. Vedeți [Headere de cache](/ro/guide/deployment#cache-headers-and-datebuild).
- Fiecare pagină SSR își preîncarcă fișierele de dicționar, astfel încât acestea pornesc odată cu HTML-ul.
- O citire eșuată nu mai rămâne blocată: cererea următoare citește din nou. Vedeți [Când un dicționar nu poate fi citit](/ro/guide/deployment#when-a-dictionary-cannot-be-read).

### `<i18n-t>`, plurale și formate mai bune {#better-&lt;i18n-t&gt;-plurals-and-formats}

- Sloturile funcționează cu `plural`, `number`, `date` și `relativeDate`, iar fiecare `{name}` este completat, nu doar primul.
- `<i18n-t>` este un singur renderer pentru Nuxt, Vue, React, Preact, Solid și Astro.
- O primă formă care începe cu `=0 ` este o formă explicită pentru zero, iar restul urmează `Intl.PluralRules`: `=0 no apples | one apple | {count} apples`. Vedeți [`$tc`](/ro/api/methods#$tc).
- Opțiune nouă `timeZone`: aceeași dată calendaristică pe server și în fiecare browser.
- `{firstName}`, `{first-name}` și `{user.name}` sunt placeholder-e valide.
- `$tn`, `$td` și `$tdr` urmează `iso`, la fel ca pluralele.
- `$tdr` oferă date reale în viitor: `in 3 days` sau `tomorrow` cu `numeric: 'auto'`.

### Mai sigur implicit {#safer-by-default}

- `<i18n-t html>` escapează `params`. Doar traducerea este considerată markup de încredere.
- Niciun link nu părăsește originea din greșeală: `//host`, `/\host` și valorile goale rămân pe acest site.
- Cache-ul de traduceri de pe server este limitat, astfel încât URL-urile cu nume de pagini inventate nu pot crește memoria.
- Endpoint-urile de salvare din DevTools acceptă doar fișiere `.json` existente din directoarele dumneavoastră de traduceri și refuză cererile cross-site.

### Pachetele pentru framework-uri la 2.0 {#framework-packages-at-2-0}

- **React, Preact, Solid:** `I18nT` primește o proprietate `components` pentru rich text. Noi `useT` și `useLocaleSwitch`, plus suport pentru React Server Components prin `@i18n-micro/react/server` și `/client`. Preact nu mai are nevoie de `preact/compat`.
- **Vue și VitePress:** `I18nLink` păstrează `name`, `query` și `hash`, iar VitePress respectă `base`.
- **Astro:** `i18nIntegration` include dicționarele dumneavoastră și instalează middleware-ul. Intrarea principală nu are niciun import `node:*`, deci rulează pe edge. `base` funcționează.
- **Node și runtime:** `fork(locale)` oferă o instanță ieftină per cerere, iar `run(locale, fn)` din `@i18n-micro/node` limitează una la o cerere.
- **`@i18n-micro/types-generator`:** fără dependențe terțe și un simplu plugin Vite și Rollup.
- **`@i18n-micro/devtools-ui`:** actualizări live prin socket-ul Vite și o aplicație pentru toolbar-ul Astro.

### `@i18n-micro/cli` {#@i18n-micro/cli}

CLI-ul se află acum în monorepo ca `@i18n-micro/cli`, rescris cu 16 comenzi în loc de 28 și cu mult mai puține dependențe. `check` înlocuiește `validate`, `diff` și `check-duplicates`, cu `--json` și coduri de ieșire pentru CI. Când nu poate dovedi că o cheie este nefolosită, `clean` nu scrie nimic. Vedeți [CLI](/ro/guide/cli).

### Documentație {#documentation}

Documentația a fost rescrisă pornind de la cod, în jurul unui singur parcurs de lectură: instalare, prima pagină tradusă, fișiere de traducere, rutare, detectare, apoi ghiduri pe sarcini. URL-urile vechi redirecționează. [Actualizare](/ro/guide/upgrade) listează fiecare schimbare în detaliu.

## Viteză și dimensiune {#speed-and-size}

- O randare pe server citește dicționarele direct, fără cerere HTTP locală și fără re-parsare.
- `dir="auto"` nu mai este implicit. Browserele petrec mult timp cu el pe paginile mari: cu 20.000 de elemente `$t`, DOMContentLoaded în Chromium a scăzut de la circa 980 ms la circa 115 ms.
- `serverTranslationPreload` și `i18n:register` nu mai încetinesc fiecare cerere.
- Bundle-ul de client renunță la `useCookie` când nu este configurat niciun cookie, iar `@i18n-micro/path-strategy` are o fracțiune din dimensiunea anterioară.

**Aplicație de test față de v3.30.3.** O aplicație Nuxt generată, pe un singur server Node, pe un singur Mac, `wrk` cu 24 de conexiuni timp de 20 s, trei runde rotite, pe un build pre-release. Rândurile provin din rulări separate, deci comparați în cadrul aceluiași rând. Hidratarea folosește `dir: 'ltr'` în ambele cazuri.

| --- | ---: | ---: |
| 4 limbi, catalog de 10k: cereri pe secundă | 384-395 | 585-591 |
| 4 limbi, catalog de 10k: latență p95 | 106-110 ms | 70-72 ms |
| 4 limbi, catalog de 10k: CPU de server per cerere | 2.92-3.00 ms | 2.01-2.02 ms |
| 12 limbi, catalog de 100k: cereri pe secundă | 362-370 | 578-580 |
| 12 limbi, catalog de 100k: latență p95 | 115-117 ms | 72-73 ms |
| 12 limbi, catalog de 100k: CPU de server per cerere | 3.11-3.17 ms | 2.02-2.03 ms |

O rulare de 30 de minute pe catalogul de 100k, pe un build pre-release anterior, a servit 1,13 milioane de cereri fără erori, iar heap-ul activ a rămas constant.

**Trei aplicații de producție față de v3.29.5,** versiunea pe care o rulau, pe un build pre-release. Două sunt site-uri SSR și una este un SPA. Fiecare a rulat pe un singur server Node, 60 s, 8 conexiuni, doar GET, două runde. Timpul de build provine dintr-o singură rulare pentru fiecare.

**JS de client.** O aplicație reală cu propriul cod câștigă puțin, ca mai sus. Corecturile comune au mărit și pachetele pentru framework-uri, măsurate cu aplicații Vue, React, Preact și Solid de dimensiune minimă pe un alt build pre-release: cu aproximativ 1,4 KB până la 2,5 KB gzip mai mult. React, Preact și Solid includ și renderer-ul comun de rich text.

**Cereri de dicționar.** O primă încărcare necesită acum două fișiere, rădăcina și pagina. Octeții ei rămân aceiași (+0.3% pe 103 și 89 de prime încărcări în cele două aplicații SSR). Pagina următoare din același document necesită un singur fișier mic: de la 4.7 KB la 1.5 KB gzip și de la 5.9 KB la 0.5 KB gzip pe cele două pagini măsurate. Pe parcursul unei navigări autentificate prin SPA, octeții de dicționar au scăzut cu 21%.

**Edge.** Pe o aplicație demo mică, upload-ul Cloudflare Worker a crescut de la 241.5 KiB la 250.3 KiB gzip, pe un build pre-release. Dicționarele încorporate într-un bundle Edge folosesc aceleași fișiere de rădăcină și de pagină, dar nu am măsurat această încorporare pe un catalog mare.

## Modificări incompatibile {#breaking-changes}

### Cerințe {#requirements}

- **Nuxt 3.18 sau mai nou** și **Node 20 sau mai nou**.
- **`@i18n-micro/test-utils`** nu mai este instalat odată cu modulul. Adăugați-l singur dacă testele dumneavoastră îl importă.
- **`@i18n-micro/hmr`** a dispărut: HMR pentru traduceri este integrat. Eliminați pachetul dacă l-ați instalat.
- **`@i18n-micro/react`** necesită React 18 sau mai nou.
- **`nuxt-i18n-micro-cli`** este înlocuit de `@i18n-micro/cli`.

### Opțiuni și configurație {#options-and-config}

- `i18n-plugin-hooks` și `i18n-plugin-define` într-un `dependsOn` nu mai așteaptă nimic, fără nicio eroare. Folosiți `i18n-plugin-loader`.
- Importurile automate de server sunt `useLocaleServerMiddleware`, `useTranslationServerMiddleware`, `loadTranslationsFromServer` și `detectCurrentLocale`. Celelalte nu mai sunt importate automat.
- `resolveTranslationPayloadMode` și ceilalți helperi `resolveTranslationPayload*` au dispărut din `nuxt-i18n-micro`, împreună cu `shouldCopyTranslationPayloadsToPublic` și `shouldRegisterNitroServerAssets`. Tipul `TranslationPayloadMode` rămâne.
- `$getI18nConfig()` nu mai are `isSSG`, `hmr`, `hooks`, `noPrefixRedirect`, `routeLocales`, `routeDisableMeta` sau `globalLocaleRoutes`. Opțiunile în sine nu s-au schimbat.
- `locales[].baseUrl` rutează acum cererile: o limbă a altui domeniu returnează 404 pe acest host, iar linkurile de pe același host sunt relative. Pe un astfel de build, `$getI18nConfig().locales` conține ce servește host-ul, iar `linkLocales` le conține pe toate.
- `baseUrl` setează și originea pe orice alt host: canonical și `hreflang` folosesc `metaBaseUrl` dacă este setat, altfel `baseUrl`-ul limbii implicite, nu originea cererii.
- `excludePatterns` se potrivesc pe segmente întregi (`'/admin'` nu mai potrivește `/administrator`), glob-urile sunt ancorate, iar tiparele `RegExp` ajung acum la runtime.
- `cacheMaxSize` nesetat înseamnă cel mult 1000 de intrări pe server. `cacheTtl` se numără de la momentul stocării unei intrări, iar citirile nu îl mai prelungesc.
- Sub `no_prefix`, un `localeCookie: null` explicit în configurația `i18n` rămâne dezactivat.
- Sub `prefix_except_default` și `prefix_and_default`, un `defaultLocale` la runtime este ignorat cu un avertisment. Un `fallbackLocale` la runtime trebuie să fie o limbă activată.
- `routeDisableMeta` din `nuxt.config` este respectat, iar o intrare din `nuxt.config` are prioritate față de `$defineI18nRoute` sub orice formă de cheie.
- Pe un server în dezvoltare, configurația rezolvată este înghețată: o scriere în ea aruncă o eroare.
- Intrarea `locales` a unui proiect are prioritate față de cea a unui strat pentru același `code`.

### Composables și metode `$` {#composables-and-$-methods}

- `$switchLocale` se rezolvă cu `true` sau `false`; înainte nu se rezolva cu nimic. `$switchRoute` are tipul `Promise<void>`.
- `$localeRoute`, `$switchLocalePath` și comutatorul trimit o limbă care nu servește o pagină către pagina principală a acelei limbi.
- `$localePath` returnează ca atare un șir cu schema `http(s):`, `mailto:` sau `tel:`, iar `$localeRoute` îl poartă în `path` și `fullPath`. Nu le transmiteți o valoare neverificată ca țintă de link. `//host` și numele simple precum `x.com` rămân căi pe această origine.
- Un link fără cale rămâne pe pagina curentă: `$localePath('#top')`, `'?p=2'`, `''` și `{ query }`. `'#top'` se citea înainte de la rădăcina site-ului. Un simplu `'about'` înseamnă în continuare `/about`.
- `$switchRoute` rămâne în aplicație. Doar `baseUrl`-ul propriu al unei limbi, `mailto:` și `tel:` o părăsesc.
- Un link către o limbă cu `baseUrl` trece prin `$localePath` sau `<i18n-link>`. `<NuxtLink :to="$localeRoute(x, 'fr')">` și `router.push($localeRoute(x, 'fr'))` rămân căi ale acestei aplicații. În cod folosiți `navigateTo($localePath(x, 'fr'), { external: true })`.
- `$switchLocaleRoute` și redirecționările urmează `trailingSlash`.
- `$setI18nRouteParams` și `useI18nHead` setate pe server sunt abandonate când o navigare schimbă calea, inclusiv de la `/news/1` la `/news/4`: setați-le din nou pe noua pagină.
- `$setI18nRouteParams` citit în setup este legat de acea pagină: un apel întârziat de pe o pagină deja părăsită nu face nimic. Nu are setter, așa că în teste faceți stub pentru `useI18n` însuși.
- `useI18n()` returnează un singur obiect per aplicație. O scriere în el ajunge la fiecare apelant.
- Dicționarul, limba, parametrii și head-ul se schimbă când o navigare este confirmată. Un `beforeResolve`, un `beforeRouteEnter` sau un guard global ulterior le vede pe cele vechi. Middleware-ul de rută nu este afectat.
- `$switchLocale` restaurează limba stocată când navigarea sa este anulată, sub strategiile bazate pe URL.
- `$t` interpolează un `defaultValue`: `$t('missing', { n: 1 }, 'Got {n}')` oferă `Got 1`. La fel și `$tc`, iar pentru o traducere goală răspunde `''`.
- `$has(key, route)` respectă ruta.
- `$clearCache()` reîncarcă dicționarul paginii curente.
- Un placeholder `{param}` citește doar parametrii pe care îi transmiteți: `{constructor}` rămâne așa cum este scris.
- `$tc` cu un număr negativ, fracționar sau uriaș ia ultima formă, cu numărul real. `{ count: null }` nu mai aruncă o eroare, iar o cheie de plural lipsă ajunge la handler-ul pentru chei lipsă.
- `$tdr` oferă `Invalid Date` pentru o intrare invalidă. Sub o secundă în trecut înseamnă `0 seconds ago`.
- `$tn`, `$td` și `$tdr` se ghidează după `iso`: `{ code: 'en', iso: 'en-GB' }` formatează datele ca `31/10/2026`. Un cod pe care `Intl` nu îl cunoaște formatează ca `en`, iar pluralele după regula indexului: setați `iso` (`{ code: 'ua', iso: 'uk-UA' }`).
- `detectCurrentLocale` este depreciat: folosiți `useLocaleServerMiddleware(event).current`.

### Plurale {#plurals}

Șabloanele își păstrează semnificația, cu o singură excepție. O formă pentru zero fără placeholder, urmată de câte o formă pentru fiecare categorie, cu `{count}` în fiecare formă pe care o împart mai multe numere, se ghidează acum după categorie în limbile cu trei sau mai multe categorii (`ru`, `uk`, `pl`, `cs`, `ar` și altele): `none | {count} one | {count} few | {count} many` oferă `3 few` și `21 one` în `uk`. Pentru a folosi categoriile în orice alt șablon, adăugați markerul `=0 `. O regulă `plural` personalizată citește valoarea brută, astfel încât un șablon marcat ajunge la ea cu `=0 ` pe loc. Vedeți [tabelul din Actualizare](/ro/guide/upgrade#plurals-and-formatting).

### Componente {#components}

**`<i18n-t>`**

- `html` escapează `params` în toate cazurile și ignoră toate sloturile.
- Un slot are prioritate față de un parametru cu același nume.
- `null` înseamnă nesetat pentru `plural`, `number`, `date` și `relativeDate`.
- `plural` numără ca `$tc`, cu `Number`: `1.5` rămâne `1.5`, `"2 items"` este `NaN`, `""` este `0`.
- `number`, `date` și `relativeDate` păstrează `params`.
- `hideIfEmpty` se aplică în fiecare ramură, iar `defaultValue` înlocuiește o cheie lipsă în fiecare ramură.
- O cheie lipsă sub `html` este text escapat.
- Rezultatul pentru `date` și `relativeDate` poartă `data-allow-mismatch="text"`, iar lângă un slot numit textul stă în propriul `<span>`.
- Atributele `.innerHTML` și `textContent` sunt eliminate.
- Este o componentă funcțională: un `ref` pe ea nu oferă nicio instanță.
- `<i18n-t>` și `<i18n-group>` citesc dicționarul activ, la fel ca `$t`.

**`<i18n-switcher>`**

- Un link este un simplu `<a>` care apelează `$switchLocale`, așa că clasele `router-link-active` au dispărut.
- Butonul este `type="button"` cu `aria-expanded`. Escape și un clic în afară închid meniul derulant.
- Clase noi `i18n-switcher-wrapper`, `i18n-switcher-dropdown` și `i18n-switcher-button`. Fiecare link are `lang`, și `dir` când limba îl setează.
- Stilurile implicite folosesc proprietăți CSS logice, iar meniul derulant are un `z-index` mai mare, o lățime minimă și o umbră.
- Serverul îi rescrie linkurile la finalul randării, pe paginile cu parametri. Un link `$switchLocalePath` scris manual nu este rescris.

**`<i18n-link>`**

- `https://`, `mailto:` și `tel:` se potrivesc indiferent de majuscule. Un simplu `report.pdf` este o rută, iar `example.com` rămâne extern. O terminație de fișier care este și TLD (`example.md`) contează ca fișier: scrieți `https://`.
- `activeStyle` ignoră un slash final, query-ul și hash-ul.

### Hook-uri și tipuri {#hooks-and-types}

- `i18n:register` este un hook de runtime: `nuxtApp.hook('i18n:register', …)` într-un plugin.
- Tipul exportat `ModuleHooks` este redenumit `ModuleRuntimeHooks`.
- `i18n:beforeLocaleSwitch` și `i18n:afterLocaleSwitch` nu au fost niciodată emise și nu mai sunt documentate.
- `ModuleOptionsExtend.isSSG` este opțional și depreciat: nimic nu îl setează.

### URL-uri și redirecționări {#urls-and-redirects}

- **`/en` și `/en/...` returnează 404** sub `prefix_except_default`, cu `en` ca limbă implicită.
- **Un prefix de limbă cu alte majuscule sau altă ortografie returnează 404** (`/DE/about`). La fel `/DE/x` sub `[...slug]` și `/DE` lângă `[slug]`, așa că un slug CMS egal cu un cod de limbă cu alte majuscule își pierde pagina.
- **Un URL necunoscut rămâne 404** cu `autoDetectPath: '*'` sau `'no_prefix'`. `prefix` păstrează redirecționarea, la fel ca `/` peste tot.
- **Calea personalizată a altei limbi, fără prefix,** este un `302` către URL-ul limbii implicite sub `prefix_except_default`. Sub `prefix`, redirecționarea ajunge acum la o pagină existentă. `prefix_and_default` rămâne 404.
- **`prefix` cu `redirects: false`** răspunde cu 404 la un URL fără prefix, inclusiv la URL-ul original al unei pagini cu o cale implicită personalizată.
- **`autoDetectPath: '*'`** aplică cookie-ul și `Accept-Language` și căilor fără prefix.
- **Sub `prefix`**, un URL fără prefix păstrează limba vizitatorului, pe orice cale, indiferent ce spune `autoDetectPath`.
- **Sub `prefix_and_default`**, un URL fără prefix este limba implicită.
- **Sub `no_prefix`**, o cale personalizată își randează propria limbă, o pagină restricționată se randează într-o limbă pe care o servește, iar limbile care împart o cale împart o singură înregistrare.
- **O redirecționare `routeRules` fără pagină** nu este localizată: `/de/old` returnează 404; înainte era un 200 gol.
- **Regulile de rută ajung la căile personalizate** și sunt copiate și sub `no_prefix`. Un frate static precum `/de/artikel/news` se potrivește cu `/de/artikel/:slug`.
- **O limbă cu `disabled: true`** răspunde imediat cu 404 pe prefixul ei, iar linkurile către ea rămân pe pagină.
- **Calea unei pagini cu alte majuscule** este un `302` către propria ortografie: `/T/BASIC` merge la `/t/basic`.
- **URL-ul original al unei pagini cu o cale implicită personalizată** este un `302` către acea cale sub `prefix_except_default`. Înainte era 404.
- **`noPrefixRedirect`** se ghidează după limba vizitatorului: cu cookie-ul `de`, `/about` merge la `/ueber-uns`, nu la calea limbii implicite.
- **Prefixul propriu al unui host** returnează 404 pe host-ul său `baseDefault` sub `prefix_except_default`: `/de/x` pe host-ul `de` era 200.
- **`customRegexMatcher`** nu mai returnează 404 pentru o pagină reală al cărei prim segment arată ca o limbă.
- **`nuxi generate`** prerandează fiecare pagină statică în fiecare limbă care o servește, cu excepția cazului în care o regulă de rută setează `prerender: false`: mai multe fișiere în rezultat. Cu `baseUrl`, rulați-l o dată pentru fiecare domeniu cu `NUXT_I18N_DOMAIN`.
- **O redirecționare pe client păstrează modul navigării sale:** un simplu `<NuxtLink>` adaugă o intrare în istoric.
- **Numele rutelor localizate sunt consecvente.** Este afectat doar codul care hardcodează nume `localized-…` în `router.push({ name })`: transmiteți numele propriu al paginii lui `$localeRoute`.
- **Paginile fără nume din `extendPages`** sunt localizate și primesc un nume.
- **Sub `prefix`, un link către alt domeniu** păstrează prefixul de limbă.
- **Pagina principală a unui domeniu** este scrisă fără slash final peste tot.
- **`?locale=`** contează pe pagini doar sub `no_prefix`. `/about?locale=de` nu mai randează germană sub `lang="en"`.
- **Un `setLocale('de')` dintr-un plugin** pe `/en/...` nu mai încarcă dicționarul `de`.

### SEO și rezultatul HTML {#seo-and-html-output}

- `dir="auto"` nu mai este implicit. O limbă RTL cunoscută primește `dir="rtl"`, iar orice altă limbă fără `dir` nu primește atributul. Pentru a păstra rezultatul vechi, setați `dir: 'auto'`, cu un cost de parsare pe paginile mari. Vedeți [Direcția textului](/ro/guide/seo#text-direction).
- `disableMeta` funcționează acum: pagina nu are `hreflang`, canonical sau `og:locale`. `lang` și `dir` rămân.
- `hreflang` listează doar limbile care servesc pagina. `x-default` apare doar când limba implicită o servește.
- O pagină nelocalizată nu are `hreflang` sau `og:locale:alternate`.
- Paginile 404 poartă `<html lang dir>` în limba URL-ului și nu au canonical sau `hreflang`.
- Canonical, `og:url` și `hreflang` păstrează un query din lista permisă (`/about?page=2`), inclusiv pe server.
- Canonical și `hreflang` includ `app.baseURL` când originea provine din cerere.
- Fiecare pagină SSR are `<link rel="preload" as="fetch" crossorigin="anonymous">` pentru fișierele sale de dicționar, inclusiv paginile 404. Permiteți-l într-un CSP strict. Cu `apiBaseClientHost`, acel host necesită CORS.
- `Vary` este setat pe fiecare pagină sub `no_prefix` și pe redirecționările de limbă ale celorlalte strategii. Verificați cheia de cache a CDN-ului dumneavoastră.
- Cookie-ul de limbă este scris doar de o pagină servită.

### Detectare și server {#detection-and-server}

- `Accept-Language` respectă valorile `q`, iar `q=0` exclude o limbă.
- `useLocaleServerMiddleware` și `useTranslationServerMiddleware` folosesc o singură ordine pe fiecare rută (`?locale`, parametrul `[locale]` sau prefixul, cookie, header, limba implicită), respectă `localeCookie: null` și `autoDetectLanguage: false` și păstrează în cache un dicționar per limbă.
- Un cookie de limbă malformat este ignorat și lăsat așa cum este, în loc să facă SSR-ul să eșueze.
- Modul hash citește doar cookie-ul `hash-locale`. Un `user-locale=de` singur nu mai contează.
- `NUXT_I18N_DEFAULT_LOCALE` și `disabledLocales` la runtime schimbă rutarea.
- **Rezultatul `premerged` s-a schimbat.** `/{apiBaseUrl}/<page>/<locale>/data.json` conține doar ce diferă de `__root/<locale>/data.json`. Orice citește aceste fișiere direct trebuie să le îmbine pe cele două. Un dicționar complet este în continuare un fișier valid.
- **Dicționarele urmează `app.cdnURL`.** Browserul le preia din `<cdnURL>/_locales/...`, unde înainte folosea `app.baseURL`. CDN-ul trebuie să conțină `_locales/` și să permită originea site-ului dumneavoastră. Vedeți [App baseURL și host-uri pentru payload](/ro/guide/deployment#app-baseurl-and-payload-hosts).
- Nu există cache de rute Nitro pe `/{apiBaseUrl}/**`, iar header-ul `s-maxage=60, stale-while-revalidate` a dispărut. Dacă vă bazați pe acel cache, puneți un CDN în fața rutei de payload.
- `/{apiBaseUrl}/<page without a folder>/<locale>/data.json` răspunde cu dicționarul rădăcină; înainte era `{}`. Un 404 al unui host trece acum mai departe ca 404, unde înainte răspundea `200 {}`.
- O prerandare care nu își poate încărca dicționarul eșuează cu un 500 și un avertisment, iar cu `failOnError` implicit al Nuxt build-ul se încheie cu 1.
- O traducere modificată fără rebuild ajunge la un browser doar când `v` se schimbă: setați `NUXT_I18N_DATE_BUILD`.
- SSR nu mai solicită `/{apiBaseUrl}` prin HTTP, cu excepția cazului în care `apiBaseServerHost` este setat.

### Traduceri {#translations}

- Îmbinările sunt profunde la fiecare nivel, iar lanțurile de rezervă sunt urmate până la capăt.
- Îmbinarea se face după limbă: fișierul rădăcină al limbii active are prioritate față de fișierul de pagină al unei limbi de rezervă.
- O pagină fără propriul folder `pages/<name>/` citește dicționarul rădăcină în producție. Înainte primea `{}`.
- `disablePageLocales: true` citește doar fișierele rădăcină.
- Cheile paginii părăsite nu se mai rezolvă după navigare. Dacă un layout folosea chei pe care le avea doar fișierul paginii anterioare, mutați-le în fișierul rădăcină.
- Un fișier de limbă corupt avertizează o singură dată, cu calea lui, în fiecare mod. În dezvoltare înainte arunca o eroare.

### Pachetele `@i18n-micro/*` {#@i18n-micro/*-packages}

Fiecare pachet `@i18n-micro/*` este la 2.0.0, inclusiv `@i18n-micro/types` și noul `@i18n-micro/cli`.

**`@i18n-micro/react`, `preact`, `solid`**

- Adaptoarele de router s-au mutat în `/router`: `createReactRouterAdapter`, `createSolidRouterAdapter` și `createBrowserHistoryAdapter` din Preact. `createPreactRouterAdapter` este eliminat.
- `I18nT` urmează `<i18n-t>` de mai sus. Atributele `dangerouslySetInnerHTML`, `innerHTML` și `textContent` sunt eliminate.
- `I18nSwitcher` randează elemente `<a href>` cu `aria-current="page"`, `▾`, CSS logic și `language-switcher` pe buton. Fără `aria-haspopup`. `className` se adaugă la `i18n-switcher-wrapper`.
- Un link către `/` sau către rădăcina unei limbi este activ doar la potrivire exactă (React, Preact).
- `I18nLink` păstrează un `onClick` și un `style` ale utilizatorului și lasă browserului un clic modificat. Query-ul și hash-ul nu contează pentru verificarea stării active. Fără router, niciun link nu este activ.
- React și Preact: `I18nLocalesContext`, `I18nDefaultLocaleContext` și `I18nRouterContext` sunt un singur `I18nConfigContext`. Solid: un singur `I18nContext` conține `{ i18n, locales, defaultLocale, router }`.
- `getCurrentPath` al adaptoarelor include query-ul și hash-ul, iar o cheie repetată în `getRoute().query` este un array.
- Un `I18nProvider` imbricat fără `i18n` păstrează instanța exterioară, iar un provider fără nicio instanță aruncă o eroare.
- `defaultLocale()` fără valoare este `fallbackLocale`.
- Solid: `getCurrentPathAccessor` este eliminat. `useI18n()` nu mai aruncă o eroare fără `locales`.
- React: `use-sync-external-store` nu mai este o dependență, iar `react-dom` este o dependență peer opțională.

**`@i18n-micro/vue`, `vitepress`**

- `I18nT` este o componentă funcțională.
- `I18nSwitcher` și `I18nLink` urmează secțiunile de mai sus. `aria-haspopup` a dispărut.
- `I18nLink` și `createVueRouterAdapter` rezolvă `name`, `query` și `hash`. Un `name` necunoscut aruncă o eroare, la fel ca `RouterLink`.
- `useLocaleHead` nu mai construiește `//de/`. Canonical și `hreflang` ale unei pagini coincid (`/de`), iar parametrii de query din lista permisă ajung la ele.
- `I18nRoutingStrategy.resolvePath` poate primi un obiect de locație și o cale cu query și hash. Nou, opțional: `toHref`.
- VitePress: linkurile, comutatorul, `push` și `replace` poartă `site.base`.

**`@i18n-micro/astro`**

- `i18nIntegration` include `translationDir` și instalează middleware-ul: ștergeți un `src/middleware.ts` care doar copiază configurația sau transmiteți `middleware: false`. Un `src/middleware.ts` propriu transmite `base: config.base`.
- `i18nIntegration` aruncă o eroare la `messages`, `plural`, `missingHandler` și `routingStrategy`: transmiteți-le lui `createI18n` sau `createI18nMiddleware`, cu `middleware: false`. Opțiunile care nu au făcut niciodată nimic au fost scoase din tipul său.
- `loadTranslationsFromDir` și `loadTranslationsIntoI18n` s-au mutat în `@i18n-micro/astro/node`, care este doar ESM.
- `getGlobalRoutingStrategy`, `setGlobalRoutingStrategy` și `runWithRoutingStrategy` sunt eliminate: citiți `Astro.locals.routingStrategy`.
- `clone()` este `fork()`, iar opțiunea `_storage` a dispărut.
- Paginile dinamice sunt o singură rută: `/blog/hello` este `blog-slug`; înainte era `blog-hello`. Mutați `pages/blog-hello/` în `pages/blog-slug/`. Un `getRouteName` personalizat primește tiparul ca al treilea argument.
- URL-ul decide limba paginii. `autoDetect` este un 302 de la `/` către pagina principală a limbii preferate. Opțiune nouă `localeCookie`, iar `redirectToDefault` este implementat.
- O vizualizare de pagină venind de pe o pagină cu aceeași origine dar în altă limbă scrie cookie-ul de limbă și nu redirecționează. Server islands și actions nu redirecționează niciodată și poartă `Vary: Referer`.
- `config.localeCodes` exclude limbile dezactivate, iar `prepareLocaleRewrite` răspunde cu 404 pentru ele.
- `getI18nProps()` fără chei trimite tot ce poate răspunde `t()` pe pagină, cu un avertisment în dezvoltare peste 20 KB. Transmiteți cheile pe care le folosește island-ul.
- `useLocaleHead`: `baseUrl` implicit este `site`, altfel relativ la rădăcină. Linkurile și meta poartă `id`.
- `<I18nT html>` escapează `params`, iar o traducere goală se randează gol.
- `<I18nLink>` și `localizePath` lasă neatinse URL-urile externe, `#hash` și `?query` și păstrează un slash final.
- `<I18nSwitcher>` păstrează query-ul și folosește `data-i18n-switcher` în loc de id-uri generate.
- `@i18n-micro/astro/client` are doar `translate` și `hasTranslation`: importați adaptoarele din `/client/vue`, `/client/react`, `/client/preact` și `/client/svelte`. `client/vue` necesită `vue` instalat.
- Islands: `has()` este true pentru un subarbore, `t('')` este `''`. `provideI18n` primește un getter pentru a urmări props noi.
- `getLocale` și `getDefaultLocale` aruncă o eroare fără middleware.

**`@i18n-micro/runtime`, `node`**

- O scriere într-o limbă care nu este nici activă, nici de rezervă nu notifică abonații.
- `addRouteTranslations(locale, route, messages, false)` înlocuiește chunk-ul.
- `loadFromUrls` preia în paralel și nu scrie nimic dacă unul eșuează.
- Node: `reload()` înlocuiește dicționarele în loc să le golească mai întâi și nu afișează niciun mesaj de succes. Un director care a dispărut le păstrează pe cele vechi.
- Node, Astro, VitePress: un singur cititor al unui folder de limbi. Un folder lipsă generează un avertisment, un fișier care nu este un obiect JSON este raportat și omis, iar mesajele încep cu `[i18n]`.

**`@i18n-micro/test-utils`**

- Mock-ul urmează regulile reale de traducere: `tc('a', 1.5)` ia ultima formă, `td('nope')` este `Invalid Date`, `t(miss, undefined, '')` este cheia, iar o cheie lipsă nu mai este înregistrată în jurnal.
- `isolated` a dispărut din `createI18nTestContext`, iar `./publish-smoke` este eliminat.

**`@i18n-micro/types-generator`**

- `I18nTypesPlugin(options)` este un simplu plugin Vite și Rollup: fără `.vite()`, `.webpack()` sau `.esbuild()`. Pentru webpack sau esbuild, apelați `generateTypes` într-un script.
- `getTypesString` și `generateTypes` sunt sincrone. `flattenKeys` și `isPlainTranslationObject` sunt eliminate.
- Cheile sunt cele pe care le citește `t()`: căile de obiect sunt adăugate, iar fișierele din afara structurii de limbi sunt eliminate.

**`@i18n-micro/devtools-ui`**

- Salvarea acceptă doar un `.json` existent în `translationDir` și nu mai creează fișiere. O cerere cross-site primește 403.
- O salvare eșuată către un endpoint accesibil aruncă o eroare și revine la starea anterioară.
- `createBridge` primește o opțiune `base`. Astro folosește `i18nDevToolsIntegration`.

**`@i18n-micro/utils`, `core`, `path-strategy`, `route-strategy`**

Doar pentru adaptoare și instrumente personalizate.

- `utils`: subpath-urile `./route`, `./route-pattern`, `./build`, `./payload-stats` și `./payload-config` sunt eliminate, împreună cu `resolveServerLocale` și `resolvePreferredLocale`: apelați `resolveLocale`. `deepMergeTranslations` și `mergeRouteTranslationsWithRoot` au dispărut: folosiți `deepMergeTranslationsRecursive`.
- `core`: `TranslationHelper` renunță la `setCache`, `getGeneration` și `lookupIn` (folosiți `lookup(chunkKey, key)`). `BaseI18n` renunță la `ensurePinnedChunk` și `invalidatePin`. `useTranslationHelper(storage)` a dispărut: folosiți `new TranslationHelper(storage)`.
- `path-strategy`: **`switchLocaleRoute(fromLocale, toLocale, route, options)` este acum `switchLocaleRoute(toLocale, route, options)`. Un apel JavaScript vechi returnează un rezultat greșit fără nicio eroare.** `$switchLocaleRoute` din Nuxt nu este afectat. Intrările `/prefix`, `/no-prefix`, `/prefix-except-default` și `/prefix-and-default` au dispărut, la fel `getRedirect` și `getCanonicalPath`. `RouterAdapter` necesită `getRoutes`. `createPathStrategy` nu construiește URL-uri absolute: folosiți `new DomainPathStrategy(ctx)` când limbile au `baseUrl`.
- `route-strategy`: sunt exportate doar `RouteGenerator`, `generateRoutes`, `Rules` și helperii de cale.

## Migrare {#migration}

1. Verificați cerințele: Nuxt 3.18, Node 20 și React 18 dacă folosiți `@i18n-micro/react`.
2. Actualizați `nuxt-i18n-micro` și fiecare pachet `@i18n-micro/*` împreună. Eliminați `@i18n-micro/hmr`. Adăugați `@i18n-micro/test-utils` ca dependență de dezvoltare dacă testele dumneavoastră îl importă. Înlocuiți `nuxt-i18n-micro-cli` cu `@i18n-micro/cli` și urmați [tabelul său de comenzi](/ro/guide/cli#moving-from-nuxt-i18n-micro-cli).
3. Căutați în cod `switchLocaleRoute(` din `@i18n-micro/path-strategy`, `i18n-plugin-hooks`, `i18n-plugin-define`, nume de rute `localized-`, `$getI18nConfig().globalLocaleRoutes` și celelalte chei de configurație eliminate, `ModuleHooks` și `@ts-expect-error` pe `i18n:register`.
4. Mutați markup-ul din parametrii `<i18n-t html>` în traducere și transmiteți datele ca parametri.
5. Dacă setați `baseUrl`: revizuiți linkurile construite cu `$localeRoute`, setați `trustForwardedHost` în spatele unui proxy și rulați `nuxi generate` o dată pentru fiecare domeniu cu `NUXT_I18N_DOMAIN`.
6. Verificați URL-urile în raport cu strategia dumneavoastră: `/en` sub `prefix_except_default`, slug-uri CMS care arată ca limbi, redirecționări `routeRules` și `excludePatterns`.
7. Verificați cheia de cache a CDN-ului pentru `Vary` și permiteți linkul de preload într-un CSP strict. Cu `app.cdnURL`, puneți `_locales/` pe CDN și permiteți CORS.
8. Dacă un instrument citește direct fișierele `/_locales/...`, îmbinați fișierul de pagină peste `__root/<locale>/data.json`.
9. Dacă un guard global citește limba sau dicționarul, confirmați că poate rula înainte ca navigarea să fie confirmată. Mutați în fișierul rădăcină cheile pe care un layout le lua din fișierul paginii anterioare.
10. Comparați un rezultat `nuxi generate` sau o parcurgere a sitemap-ului înainte și după: `hreflang`, `x-default`, canonical și lista de pagini se schimbă intenționat.
11. Actualizați importurile pentru pachetele de framework-uri: `/router` pentru adaptoarele React, Solid și Preact, `/node` pentru loader-ele Astro și `I18nTypesPlugin(o)` pentru plugin-ul de tipuri.
12. Pentru Astro, ștergeți un `src/middleware.ts` care doar copiază configurația și redenumiți dicționarele de tipul `pages/blog-hello/` după tiparul lor.
13. Actualizați testele care fixau `router-link-active`, `li button`, `▼` sau comportamentul vechi al mock-ului.

Detalii și fiecare caz limită: [Actualizare](/ro/guide/upgrade).

## De ce contează {#why-it-matters}

- **Corect prin construcție:** linkurile, redirecționările și etichetele SEO provin din rutele pe care aplicația le are cu adevărat.
- **Un singur răspuns peste tot:** un build, modul source și dezvoltarea oferă același dicționar, iar fiecare apelant folosește o singură ordine de detectare.
- **Domenii:** o singură implementare pentru fiecare domeniu de limbă, fără un al doilea build.
- **Valori implicite mai sigure:** parametri escapați, cache-uri limitate, linkuri care rămân pe originea dumneavoastră.
- **Mai puțin de livrat:** fișiere de dicționar mai mici, pachete de rutare mai mici și logică comună într-un singur loc.

Pentru lista completă a modificărilor, vedeți [Actualizare](/ro/guide/upgrade) și [changelog-ul](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
