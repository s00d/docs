## Nuxt I18n Micro v3.22.0 — Formate, cache și Translation Memory {#nuxt-i18n-micro-v3-22-0-—-formats-cache-&-translation-memory}

**Data**: 2026-07-30

**Versiunea**: `v3.22.0`

![Lansarea v3.22.0](/images/3.22.0.png)

Anunțăm **v3.22.0**: formate denumite pentru numere/date în stilul Vue I18n, cu cache pentru formatatori, cache prietenos cu CDN-ul pentru payload-urile de traduceri (amprentă de conținut + `httpCacheDuration`) și un API Translation Memory pentru citirea și înlocuirea dicționarului activ la runtime.

## Ce este nou? {#what’s-new}

### `numberFormats` / `datetimeFormats` denumite + cache pentru formatatori {#named-numberformats-/-datetimeformats-+-formatter-cache}

Formate denumite compatibile cu Vue I18n și formatare Intl mai rapidă:

- Configurare: `numberFormats` / `datetimeFormats` per locale
- API: `$tn(1000, 'currency')`, `$td(date, 'short')` (+ suprascrierea locale-ului și combinarea opțiunilor)
- `FormatService` păstrează în cache `Intl.NumberFormat` / `DateTimeFormat` / `RelativeTimeFormat` după locale+opțiuni

Vedeți [Metode — `$tn` / `$td`](/ro/api/methods#$tn) și [Opțiunile modulului](/ro/api/module-options#numberformats).

### `dateBuild` folosește implicit o amprentă de conținut {#datebuild-defaults-to-a-content-fingerprint}

Parametrul `?v=` din cererile `/_locales` avea implicit valoarea `Date.now()`, în timp ce răspunsurile sunt servite `immutable` timp de un an. Astfel, fiecare rebuild invalida dicționarul fiecărui client, chiar dacă nicio traducere nu se schimbase.

Valoarea implicită este acum o amprentă SHA-256 a surselor de traduceri, în ordinea layer-elor. Rebuild-urile cu traduceri neatinse păstrează același URL. Setarea explicită a `dateBuild` are în continuare prioritate. Vedeți [Opțiunile modulului — `dateBuild`](/ro/api/module-options#datebuild).

### `httpCacheDuration` pentru payload-urile `/_locales` {#httpcacheduration-for-/_locales-payloads}

Ruta integrată `/{apiBaseUrl}/:page/:locale/data.json` trimite acum `Cache-Control` HTTP pentru browsere și CDN:

- Opțiune: `httpCacheDuration` (secunde, implicit `31536000` / 1 an)
- Header: `Cache-Control: public, max-age=…, immutable`
- Sigur în combinație cu cache-busting-ul existent prin `dateBuild` (`?v=...`); `0` dezactivează header-ul; nu se aplică în development

Analog cu `experimental.httpCacheDuration` din `@nuxtjs/i18n` v10.2.0, sub forma unui header de răspuns explicit.

### Payload-uri publice comprimate {#compressed-public-payloads}

`nitro.compressPublicAssets` ajunge acum și la payload-urile de traduceri copiate în directorul public (`.gz` + `.br`). Nitro comprimă resursele publice înainte de copiere, așa că anterior payload-urile erau singura parte necomprimată a unui build static — 6,65 MB brut față de 1,01 MB gzip pe indexul din playground. Modulul tot nu activează niciodată compresia de unul singur. Vedeți [Performanță](/ro/guide/performance#payload-size).

### `resolveTranslations()` și `setTranslation(key, value)` {#resolvetranslations-and-settranslationkey-value}

Helperi de runtime pentru citirea și înlocuirea dicționarului de traduceri activ din memorie:

- **`resolveTranslations()`** returnează întregul arbore din care citește `$t()` pentru locale-ul și ruta active — util pentru DevTools, teste și editoare la runtime. Când un al doilea layer este activ (locale de rezervă sau hot-reload la tranziția de pagină Nuxt), dump-ul păstrează forma imbricată prin `mergeTranslationLayers` și folosește chei plate cu puncte doar pentru coliziunile scalar-vs-obiect pe care un singur arbore nu le poate exprima altfel.
- **`setTranslation(key, value)`** înlocuiește valoarea de la o cheie (de nivel superior, cale cu puncte, obiect, șir sau scalar). Aceasta este o **înlocuire**, nu o combinare; folosiți `$mergeTranslations` când elementele vecine trebuie păstrate.
- Disponibil pe `useI18n()`, `useNuxtApp()` și pe instanțele i18n ale framework-urilor moștenite din `@i18n-micro/core`.
- `@i18n-micro/test-utils` adaugă helperii corespunzători `resolveTranslations` / `setTranslation` pentru testele unitare.

### `getAllTranslations()` eliminat din pachetul Vue {#getalltranslations-removed-from-vue-package}

Folosiți `resolveTranslations()` pentru arborele de căutare activ. Pentru un dump complet al stocării în Vue, folosiți `getStorage()` sau `getRouteCache()`.

## Modificări incompatibile {#breaking-changes}

Nimic din suprafața publică de configurare nu necesită modificări ale codului aplicației pentru utilizarea obișnuită. Acestea contează dacă ați accesat detalii interne ale runtime-ului:

- **Payload-ul SSR s-a mutat din `useState('i18n-ssr-chunks')` în `nuxtApp.payload.data['i18n-ssr-chunks']`.** Încă transportă **chunk-uri complete de traduceri** pentru fiecare `(locale, route)` încărcat în timpul SSR — aceleași dicționare ca înainte, într-un slot pe care Nuxt îl poate externaliza în `_payload.json` la prerender. `useState('i18n-ssr-chunks')` nu mai returnează nimic. Citirea traducerilor în acest fel nu a fost niciodată suportată, dar era descrisă în documentația API-ului de cache, așa că este menționată aici.
- **`NuxtTranslationLoaderOptions` expune `setSsrChunk`.** Loader-ul scrie fiecare chunk combinat în `payload.data` pe server pe măsură ce îl încarcă. `getSsrChunks` nu este folosit.
- **`nitro.compressPublicAssets` emite acum `.gz` / `.br` lângă payload-urile copiate.** Așteptați-vă la mai multe fișiere în output-ul public dacă aveați opțiunea activată. Instrumentele de deploy care enumeră directorul de traduceri ar putea fi nevoite să țină cont de ele.
- **URL-urile payload-urilor se schimbă o singură dată la actualizare**, deoarece `?v=` trece de la un timestamp de build la o amprentă de conținut. Clienții descarcă din nou dicționarul la prima cerere după actualizare și apoi îl păstrează între deploy-urile ulterioare — exact acesta este scopul.
- **`getAllTranslations()` eliminat din `@i18n-micro/vue`.** Folosiți în schimb `resolveTranslations()` / `getStorage()` / `getRouteCache()`.

## Remedieri de erori {#bug-fixes}

- **`<i18n-switcher>`** — omite din meniul derulant locale-urile cu `disabled: true`. `$getLocales()` returnează în continuare lista completă pentru propriul cod, în timp ce output-ul SEO/meta integrat exclude locale-urile dezactivate.
- **Stilurile switcher-ului** — `cursor: not-allowed` se aplică locale-ului **curent** prin `activeLinkStyle` / `customActiveLinkStyle`; a fost restaurat `customDisabledLinkStyle` pentru compatibilitate retroactivă și se aplică butonului switcher-ului când locale-ul curent are `disabled: true`.
- **HMR în dev** — o scriere care lasă conținutul fișierului neschimbat (salvare la pierderea focusului în editor, rescriere de către formatter) nu mai declanșează o recombinare. Modificările locale-ului rădăcină reconstruiesc fiecare pagină pentru acel locale, deci era costisitor pentru o operație fără efect.
- **HMR în dev** — paginile sunt recombinate concurent la o modificare a locale-ului rădăcină, în loc de una după alta.
- **Tranziții de pagină** — navigarea în același locale păstrează chunk-ul anterior ca layer de rezervă până la `page:transition:finish`, în loc de o combinare profundă costisitoare la fiecare navigare.

## De ce contează {#why-it-matters}

- Formatare în stilul Vue I18n fără a aduce o stivă mai grea.
- URL-uri de traduceri prietenoase cu CDN-ul, care rămân stabile între rebuild-uri când dicționarul nu s-a schimbat.
- Un API de runtime suportat pentru inspectarea și modificarea dicționarului activ — DevTools, testele și editoarele nu mai au nevoie de helperi privați.
