`@i18n-micro/solid` oferă aplicațiilor SolidJS o instanță i18n bazată pe semnale, un provider, `useI18n()` și patru componente. Folosiți-l într-o aplicație Solid care nu este construită cu Nuxt. Citirile lui `t()` în JSX sau în efecte urmăresc limba, ruta și dicționarele; modelul comun este descris în [Framework-uri](/ro/integrations/overview).

## Instalare {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Dependențe peer: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (opțional, doar pentru `@i18n-micro/solid/router`). Solid 2 nu este încă acceptat.

## Configurare {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` primește `i18n`, `locales`, `defaultLocale` și `routingStrategy`; o proprietate omisă păstrează valoarea provider-ului exterior, inclusiv instanța. `getLocaleName()` și `<I18nSwitcher>` citesc `locales`; fără ele nu au ce lista. Opțiunile sunt descrise în [instanța](/ro/integrations/overview#the-instance). Instanța este cea a [runtime-ului](/ro/integrations/runtime-package), cu un semnal peste store-ul ei.

## Traducere {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Apelați metodele în JSX sau într-un efect pentru ca Solid să le urmărească, inclusiv `localePath` și `getLocale`; o valoare citită o singură dată în corpul componentei nu se actualizează. Pe instanță, urmăriți prin `i18n.locale` și `i18n.currentRoute`: `i18n.getLocale()` rămâne simplu, deoarece scrierile îl citesc. Citirea limbii reacționează doar la limbă, așa că un efect care o citește și încarcă un dicționar rulează o singură dată. Nu destructurați props și nu păstrați rezultatele `t('key')` în variabile simple.

`useI18n()` returnează `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (un accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` și `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Schimbarea limbii {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Schimbarea nu încarcă nimic; adăugați mai întâi dicționarul limbii.

`<I18nGroup>` transmite un `t` cu prefix unui copil de tip funcție. `<I18nT>` și `t()` din interiorul lui nu primesc prefix:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Rutare {#routing}

Adaptorul pentru `@solidjs/router` se află într-un subpath, astfel încât intrarea principală nu importă niciodată router-ul. Apelați-l sub router, de obicei în `root`-ul router-ului, unde funcționează `useNavigate` și `useLocation`:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

Adaptorul adaugă prefix fiecărei limbi cu excepția celei implicite (`/about`, `/de/about`) și randează `<I18nLink>` ca `<A>` al router-ului. `getCurrentPath` citește locația reactivă a router-ului, astfel încât linkurile active și comutatorul o urmează; o strategie personalizată obține același efect citind acolo un semnal. Atenție la ordinea argumentelor: `(locales, defaultLocale, navigate, location)`. Pentru alte routere, scrieți un adaptor cu `getCurrentPath`, `push` și `replace` (toate obligatorii) — vedeți [Adaptor de router](/ro/integrations/overview#router-adapter).

## SSR {#ssr}

Pentru randarea pe server, faceți build cu `vite-plugin-solid`: condiția de export `solid` a pachetului îi furnizează sursa, astfel încât aceasta se compilează pentru server. `dist` precompilat este doar pentru browser. Instanța nu are `destroy()`; creați una per aplicație, sau una per cerere pe server, și lăsați garbage collector-ul să o elibereze.
