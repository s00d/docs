`@i18n-micro/node` este instanța [runtime](/ro/integrations/runtime-package) plus un loader care citește un folder de traduceri de pe disc. Folosiți-l într-un server Express sau Fastify, într-un CLI, într-un generator de e-mailuri sau PDF-uri ori în orice script care are nevoie de aceleași fișiere JSON ca aplicația dumneavoastră Nuxt. Încărcați fișierele o singură dată și traduceți per cerere, fără a partaja stare mutabilă între cereri.

## Instalare {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/node @i18n-micro/utils
```

```bash npm
npm install @i18n-micro/node @i18n-micro/utils
```

```bash yarn
yarn add @i18n-micro/node @i18n-micro/utils
```

</CodeGroup>

Fără dependențe peer; Node.js `>=20`. `@i18n-micro/utils` este necesar doar pentru helper-ul `Accept-Language` de mai jos.

## Configurare {#setup}

Loader-ul citește [structura de foldere Nuxt](/ro/guide/translations): `locales/en.json` este un dicționar rădăcină, `locales/pages/blog/post/en.json` aparține rutei `blog-post`.

```ts
import { createI18n } from '@i18n-micro/node'

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

i18n.t('greeting', { name: 'Ada' }) // 'Hello, Ada!'
i18n.t('title', undefined, undefined, 'blog-post') // from locales/pages/blog/post/en.json
```

Opțiunile sunt cele ale runtime-ului (vedeți [instanța](/ro/integrations/overview#the-instance)) plus `translationDir` și `disablePageLocales` (tratează fișierele `pages/**` ca dicționare rădăcină). `i18n.reload()` golește fiecare dicționar și citește din nou folderul, pentru un watcher de fișiere în dezvoltare.

`loadTranslations(dir, disablePageLocales?)` este exportat și separat și returnează `{ root, routes }`:

```ts
import { loadTranslations } from '@i18n-micro/node'

const { root, routes } = await loadTranslations('./locales')
// root:   { en: {...}, de: {...} }
// routes: { 'blog-post': { en: {...}, de: {...} } }
```

## Per cerere {#per-request}

O instanță reține o singură limbă și o singură rută. Schimbarea `i18n.locale` pe o instanță partajată în interiorul unui handler de cerere intră în conflict cu cererile concurente. `run` oferă fiecărei cereri propria instanță:

```ts
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

// `() => next()`: `run` hands its callback the fork, and Express reads an argument of `next` as an error
app.use((req, res, next) => i18n.run(pickLocale(req), () => next()))

app.get('/', (req, res) => {
  res.send(i18n.t('greeting')) // the request's locale, in everything it awaits
})
```

În interiorul `run`, instanța partajată citește și setează limba și ruta cererii (`AsyncLocalStorage`); fork-ul pornește pe ruta curentă, iar `i18n.setRoute(...)` în interiorul callback-ului schimbă ruta acelei cereri. Callback-ul primește și fork-ul cererii: dicționarele scrise în el rămân în cerere, dicționarele scrise în instanța partajată ajung la toată lumea.

Fără `AsyncLocalStorage`, `i18n.fork(locale)` returnează același tip de instanță, pe care o puteți transmite mai departe.

`reload()` citește din nou directorul; dicționarele vechi răspund până când cele noi sunt încărcate.

## Alegerea limbii {#pick-the-locale}

`detectLocaleFromAcceptLanguage(header, locales)` respectă ponderile `q` și potrivește `de-DE` cu o limbă `de` (și `de` cu `de-DE`). Returnează `null` când nu se potrivește nimic.

```ts
import express from 'express'
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

const app = express()

app.get('/hello', (req, res) => {
  const locale = detectLocaleFromAcceptLanguage(req.headers['accept-language'], locales) ?? 'en'
  const i18n = byLocale.get(locale)!
  res.json({ message: i18n.t('greeting', { name: 'Ada' }) })
})
```

Pentru prefixul URL, cookie și header împreună, `resolveLocale({ defaultLocale, validLocales, url, cookie, acceptLanguage, autoDetectLanguage: true })` din `@i18n-micro/utils/resolve-locale` aplică ordinea de prioritate a modulului: URL, apoi cookie, apoi `Accept-Language`, apoi limba implicită. Valorile invalide sunt omise.

Într-o aplicație Nuxt nu aveți nevoie de acest pachet pe server: folosiți [traducerile pe server](/ro/guide/server-side-translations) ale modulului.

## API {#api}

| Export | Note |
| --- | --- |
| `createI18n(options)`, `I18n` | instanță runtime + `translationDir`, `loadTranslations(dir?)`, `reload()` |
| `loadTranslations(dir, disablePageLocales?)` | `{ root, routes }` |
| `loadRootTranslations(dir, disablePageLocales?)` | doar `root` |
| `FormatService`, `interpolate` | din core |
| Tipuri: `I18nOptions`, `LoadedTranslations`, `Translations`, `Locale`, `PluralFunc`, `Params` | |

Metodele instanței sunt listate în [Runtime](/ro/integrations/runtime-package#api). Semnăturile complete: [referința pachetului](/ro/api/packages/node).
