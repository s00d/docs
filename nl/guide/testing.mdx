Componenten die `useI18n()` aanroepen hebben in unittests een i18n-instantie nodig. `@i18n-micro/test-utils` geeft je een nep-`useI18n()` met echte logica voor vertaling, meervoud en opmaak, zodat je een component kunt mounten met je eigen woordenboeken en zonder Nuxt-server. Voor routing en redirects draai je de echte module end-to-end met `@nuxt/test-utils`.

Deze pagina gaat over het testen van je applicatie. Hoe deze repository de module zelf test, staat op [De module testen](https://s00d.github.io/nuxt-i18n-micro/contributing/testing).

## Installeren {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

```bash npm
npm install -D @i18n-micro/test-utils @nuxt/test-utils vitest @vue/test-utils happy-dom
```

</CodeGroup>

## useI18n mocken {#mock-usei18n}

```ts
// tests/unit-setup.ts
import { setupNuxtI18nMock } from '@i18n-micro/test-utils'
import { mockNuxtImport } from '@nuxt/test-utils/runtime'
import { beforeEach, vi } from 'vitest'

export const { i18n, useI18n, setTranslationsFromJson } = setupNuxtI18nMock({
  spy: vi.fn, // every method becomes a vi.fn, so you can assert calls
  beforeEach, // reset state and reseed `translations` before each test
  translations: { welcome: 'Welcome' },
})

mockNuxtImport('useI18n', () => useI18n)
```

```ts
// vitest.config.ts
import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    environment: 'nuxt',
    setupFiles: ['./tests/unit-setup.ts'],
  },
})
```

Houd `mockNuxtImport` in het setupbestand: `@nuxt/test-utils` moet het transformeren. `setupNuxtI18nMock` gebruikt een private vertaalcache, dus parallelle testbestanden delen geen status.

## Een test schrijven {#write-a-test}

```vue
<!-- components/Greeting.vue -->
<script setup lang="ts">
const { $t } = useI18n()
</script>

<template>
  <p>{{ $t('welcome') }}</p>
</template>
```

```ts
// tests/greeting.spec.ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { expect, it } from 'vitest'
import Greeting from '~/components/Greeting.vue'
import de from '~/locales/de.json'
import { i18n, setTranslationsFromJson } from './unit-setup'

it('renders the German greeting', async () => {
  await setTranslationsFromJson('de', de)
  i18n.setLocale('de')

  const wrapper = await mountSuspended(Greeting)
  expect(wrapper.text()).toBe('Willkommen') // de.json: { "welcome": "Willkommen" }
})
```

De nepversie biedt dezelfde methoden als de echte `useI18n()` (`$t`, `$tc`, `$tn`, `$td`, `$has`, `$localePath`, …, met en zonder `$`) plus setters voor tests: `setLocale`, `setLocales`, `setDefaultLocale`, `setRouteName`, `setTranslationsFromJson`, `loadPageTranslations`, `mergeTranslations`, `setMissingHandler`.

`$localePath` en `$switchLocalePath` zijn stubs die het pad een prefix geven volgens de optie `strategy` (geen echte router). Test echte links en redirects end-to-end.

## Helpers op lager niveau {#lower-level-helpers}

| Helper | Gebruik het voor |
| --- | --- |
| `createIsolatedFakeI18n(options)` | Een geïsoleerde nepversie zonder de Nuxt-`useI18n`-koppeling, bijv. voor een gewone `mount` van `@vue/test-utils` met `global.mocks`. |
| `createFakeI18n(options)` | Een nepversie op de gedeelde modulecache (roep `resetI18n()` aan in `beforeEach`), of geïsoleerd met `isolated: true`. |
| `createI18nTestContext(options)` | De context achter beide, wanneer je meerdere nepversies nodig hebt. |
| `t`, `tc`, `ts`, `tn`, `td`, `tdr`, `has` | Directe aanroepen op de gedeelde context, om gewone functies te testen. |

De mock is een `BaseI18n`: `t`, `tc`, `tn`, `td`, `tdr` en `has` zijn de echte, op echte woordenboeken, dus een test ziet wat de app toont.

De factory-helpers hierboven accepteren `locale`, `defaultLocale`, `locales`, `routeName`, `strategy`, `translations` en `messages` (woordenboeken per locale). Een volledig voorbeeldproject staat in [`packages/test-utils/example`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/test-utils/example).

## End-to-end-tests {#end-to-end-tests}

Routing, redirects, SEO-tags en het laden van payloads hebben de echte module nodig. Start je app met `@nuxt/test-utils/e2e`:

```ts
// tests/e2e/locales.test.ts
import { $fetch, fetch, setup } from '@nuxt/test-utils/e2e'
import { describe, expect, it } from 'vitest'

describe('locales', async () => {
  await setup({ server: true })

  it('serves the German page', async () => {
    expect(await $fetch('/de')).toContain('lang="de-DE"')
  })

  it('redirects / for a German browser', async () => {
    const res = await fetch('/', { headers: { 'accept-language': 'de' }, redirect: 'manual' })
    expect(res.headers.get('location')).toBe('/de')
  })
})
```

De tweede test gaat uit van `prefix` (of `prefix_except_default` met een andere standaardlocale); zie [Locale-detectie](/nl/guide/locale-detection) voor wanneer `/` een redirect geeft.
