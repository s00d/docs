Serverhandlers in `server/api/` en `server/routes/` kunnen strings vertalen en de locale van het verzoek lezen met twee automatisch geïmporteerde helpers. Gebruik ze voor API-responses, e-mails, feeds of alles wat buiten een Vue-pagina wordt gerenderd. Ze lezen dezelfde vertaalbestanden als je pagina's en detecteren de locale uit het verzoek.

## Vertalen in een handler {#translate-in-a-handler}

```ts
// server/api/greeting.get.ts
export default defineEventHandler(async (event) => {
  const t = await useTranslationServerMiddleware(event)
  return { message: t('greeting', { name: 'Ada' }) }
})
```

```bash
curl 'http://localhost:3000/api/greeting?locale=de'
# {"message":"Hallo, Ada!"}
```

`useTranslationServerMiddleware(event, defaultLocale?, locale?)` is asynchroon en retourneert `t(key, params?, defaultValue?)`. `t` geeft de string terug, interpoleert `{name}`-parameters, en geeft bij een ontbrekende sleutel een niet-lege `defaultValue` terug, anders de sleutel zelf.

`t` ziet alleen de `index`-chunk: de rootbestanden (`locales/<locale>.json`) plus `locales/pages/index/` als die bestaat (alleen rootbestanden met `disablePageLocales`). Sleutels van andere pagina's worden niet geladen. Laad voor die sleutels de chunk zelf:

```ts
const { data } = await loadTranslationsFromServer('de', 'about') // Translations object of the about page
```

## De locale van het verzoek lezen {#read-the-request-locale}

```ts
// server/api/locale.get.ts
export default defineEventHandler((event) => {
  const { current, isDefault, locale } = useLocaleServerMiddleware(event)
  return { current, isDefault, dir: locale?.dir ?? 'ltr' }
})
```

`useLocaleServerMiddleware(event, defaultLocale?, locale?)` is synchroon en retourneert:

```ts
interface LocaleInfo {
  current: string // detected locale code
  default: string // defaultLocale, runtime overrides included (fixed at build under prefix_except_default / prefix_and_default)
  fallback: string // fallbackLocale, else the default
  available: string[] // enabled locale codes
  locale: Locale | null // the config entry of `current`
  isDefault: boolean
  isFallback: boolean
}
```

## Hoe de locale wordt gekozen {#how-the-locale-is-chosen}

Beide helpers gebruiken op elke serverroute dezelfde volgorde, `/api` of niet:

1. de query `?locale=` (de eerste waarde bij herhaling);
2. een routeparameter `[locale]`, of een locale-prefix in het pad (`/de/...`);
3. de locale-cookie, wanneer [`localeCookie`](/nl/api/module-options#localecookie) is ingesteld (`hash-locale` onder `hashMode`);
4. `Accept-Language`, wanneer `autoDetectLanguage` aan staat (q-waarden worden gerespecteerd);
5. `defaultLocale`.

Ongeldige en uitgeschakelde codes worden bij elke stap overgeslagen. Dit is de volgorde voor de API; een paginarender negeert `?locale=` onder de prefix-strategieën. Beide volgordes worden vergeleken op [Locale-detectie](/nl/guide/locale-detection).

## Een locale afdwingen {#force-a-locale}

Geef het derde argument mee om detectie over te slaan, bijvoorbeeld in een taak die e-mail verstuurt in de taal van de gebruiker:

```ts
export default defineEventHandler(async (event) => {
  const user = await getUser(event) // your code
  const t = await useTranslationServerMiddleware(event, undefined, user.locale)
  return sendMail(user.email, t('mail.welcome.subject'))
})
```

Het tweede argument vervangt `defaultLocale` voor de detectie van deze aanroep, dus het heeft geen effect wanneer een locale wordt afgedwongen. Woordenboeken worden per verzoek en per locale gecachet, en over verzoeken heen in de vertaalcache van de server, dus een helper meerdere keren aanroepen is goedkoop.

## Servercomponenten {#server-components}

Een servercomponent (`.server.vue`, `<NuxtIsland>`) rendert vanaf zijn eigen URL, `/__nuxt_island/...`, dus hij ziet de URL van de pagina niet, en Nuxt geeft hem alleen zijn props mee. Geef de locale mee als prop `locale`. Hij rendert dan in die locale, en bij een wissel wordt hij opnieuw opgehaald, omdat de props deel uitmaken van de URL en de cachesleutel van de island. De naam is gereserveerd: elke ingeschakelde locale-code in een prop met de naam `locale` bepaalt de locale van de render, dus geef een prop die iets anders betekent, zoals een getalnotatie, een andere naam:

```vue
<!-- components/Greeting.server.vue -->
<template><p>{{ $t('greeting') }}</p></template>
<script setup lang="ts">
defineProps<{ locale?: string }>()
</script>
```

```vue
<template>
  <Greeting :locale="$getLocale()" />
  <NuxtIsland name="Greeting" :props="{ locale: $getLocale() }" />
</template>
```

Zonder de prop rendert hij in de locale van de cookie, anders in de standaardlocale, ongeacht wat de URL zegt, en volgt hij geen wissel. Zijn `$t` ziet de `index`-chunk: de rootbestanden plus `locales/pages/index/`.
