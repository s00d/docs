### Beschrijving {#description}

Vergelijkt **plain Nuxt**, **i18n-micro** en **`@nuxtjs/i18n`** onder één gedeeld woordenboekprofiel via `untestutils/perf`.

Focus: buildtijd, piek-RSS, deploybare **code vs vertalingen (asset) vs totaal**, en belasting (Artillery).

### Opmerkingen over de methodologie {#methodology-notes}

- Metingen zijn **gemiddelden van 3 opeenvolgende runs per fixture** (niet afgewisseld).
- **Artefact**: Nitro node-server `.output/server/index.mjs` na een geforceerde `nuxi build`; `nuxt-i18n-micro` is de **gebouwde module-dist** (niet de jiti-stub van `dev:prepare`). Zie [benchmarkmethodologie](https://s00d.github.io/nuxt-i18n-micro/contributing/performance-methodology).
- **Vertalingen** = `bundle.asset` (locale-JSON, `chunks/raw/`, overeenkomende locale-chunks via `isTranslationFile`).
- **Code** sluit source maps (`*.map`) uit: de fixtures linken de module vanuit de repo, dus Nitro schrijft er volledige maps voor en geen voor npm-afhankelijkheden.
- **plain-nuxt** serveert hetzelfde volume aan bladeren als statische JSON — I/O-zwaar onder belasting, geen "i18n-overhead".
- Belastingsprofiel `--load full`: opwarmen 6s@6 + hoofdfase 60s@60 zonder limiet (historisch).
- Afkoelperiodes `--cool fast` (zie het methodologiedocument).
- Elk van de `runs`-builds is **geforceerd** (geen warme cache die de buildtijd op nul zet).
- Het Artillery-**foutpercentage** in de tabellen zijn HTTP-statusfouten uit de belastingsmetingen. Grafieken tonen ook `vusers.failed` (client-time-outs bij verzadiging); die kunnen hoog zijn terwijl het HTTP-foutpercentage op 0% blijft.
### Runs {#runs}

Alle onderstaande metingen zijn **gemiddelden over 3 runs**.

## Opmerkingen {#notes}

- Gedeeld profiel: 4 locales × 2 pagina's × ~16.8k indexbladeren.
- Belasting: alleen programmatische Artillery — opwarmen **6s@6** + hoofdfase **60s@60**, VU zonder limiet (historische YAML-methodologie). Paden uit het runtimeprofiel — zie `scripts/src/perf/load.ts`.
- Afkoelperiodes: 2s na de build, 3s tussen runs, 5s tussen fixtures. Builds worden elke run geforceerd, zodat de gemiddelden niet worden vertekend door cache-hits.
- Dagelijks opnieuw draaien: `pnpm test:performance` (`--load short --cool fast`).
- Deze pagina opnieuw genereren: `pnpm -C scripts cli performance --load full --only all --runs 3`.
- Flags: `--locales N --keys K --only all|micro|i18n|plain --runs N --skip-load --cool fast|strict`.
