---
title: "Eigen localedetectie"
description: "Kies de locale zelf — op basis van domein, header of gebruikersprofiel — met een serverplugin en useI18nLocale().setLocale()."
---

De ingebouwde detectie leest de URL, een cookie en `Accept-Language`. Wanneer de locale van iets anders afhangt — het domein, een geo-header die je CDN instelt, een gebruikersprofiel — stel je hem zelf in via een plugin die vóór de i18n-plugin draait. De module laadt dan de vertalingen van die locale en gebruikt hem voor redirects, precies alsof hij hem zelf had gedetecteerd. De regels die bepalen wanneer een gekozen locale voorrang krijgt op de URL staan op [Localedetectie](/nl/guide/locale-detection); deze pagina laat zien hoe je je eigen bron inplugt.

## De locale instellen in een serverplugin {#set-the-locale-in-a-server-plugin}

```ts
// plugins/i18n-locale.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10, // before the i18n plugin (order -5)
  setup() {
    const { setLocale } = useI18nLocale()
    const host = (useRequestHeaders(['host']).host ?? '').split(':')[0]! // without the port

    if (host.endsWith('.de')) setLocale('de')
    else if (host.endsWith('.fr')) setLocale('fr')
  },
})
```

`setLocale(code)` schrijft de locale-state (`useState('i18n-locale')`) en, wanneer een locale-cookie is geconfigureerd, de cookie. Gebruik dit in plaats van zelf `useState` of `useCookie` te schrijven. Geef alleen codes van ingeschakelde locales mee.

Houd de plugin `.server.ts` wanneer hij request-headers leest: die bestaan niet in de browser. Een `.client.ts`-plugin is de plek voor bronnen die alleen in de browser bestaan, zoals `localStorage`.

## De ingebouwde Accept-Language-stap uitschakelen {#turn-off-the-built-in-accept-language-step}

Je plugin en `Accept-Language` kunnen het oneens zijn. Om alleen je eigen code (plus de URL en cookie) te laten beslissen, schakel je de header uit:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    autoDetectLanguage: false,
  },
})
```

[`autoDetectLanguage`](/nl/api/module-options#autodetectlanguage) bepaalt alleen de header-stap. De URL en een geldige cookie tellen nog steeds mee.

## Wat er daarna gebeurt {#what-happens-next}

Het effect van `setLocale` hangt af van de [strategie](/nl/guide/strategy):

| Strategie | Effect van `setLocale('de')` in de plugin |
| --- | --- |
| `no_prefix` | De pagina wordt in het Duits gerenderd; de URL verandert niet. |
| `prefix`, `prefix_except_default` | Op een pad zonder prefix waar [`autoDetectPath`](/nl/api/module-options#autodetectpath) redirects toestaat (standaard alleen `/`), antwoordt de server met `302` naar de Duitse URL. Een URL met een locale-prefix behoudt die. |
| `prefix_and_default` | Geen redirect: de URL zonder prefix is een geldige pagina in de standaardlocale. |

Onder de prefix-strategieën is een locale in de URL de keuze van de gebruiker en overschrijft je plugin die niet. `autoDetectPath: '*'` is de uitzondering: de server verplaatst dan URL's met prefix op basis van cookie en `Accept-Language` en negeert de state, maar `setLocale()` schrijft ook de cookie wanneer die is geconfigureerd, dus vanaf het volgende request kan de keuze van je plugin een URL met prefix omleiden. Houd `'/'` aan of gebruik `'no_prefix'` wanneer expliciete locale-URL's moeten winnen. Gebruik je plugin om te kiezen waar een bezoeker terechtkomt, niet om links te herschrijven die hij heeft gevolgd.

## Een door de gebruiker gekozen locale respecteren {#respect-a-locale-the-user-picked}

Zodra een gebruiker van taal wisselt, schrijft de wissel de cookie. Sla je eigen detectie over wanneer er al een geldige voorkeur is:

```ts
// plugins/i18n-locale.server.ts
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10,
  setup() {
    const { getPreferredLocale, setLocale, validLocales } = useI18nLocale()
    if (getPreferredLocale()) return // valid state or cookie: keep it

    const country = useRequestHeaders(['x-country'])['x-country']
    if (country === 'JP') return setLocale('ja')

    const header = useRequestHeaders(['accept-language'])['accept-language']
    setLocale(detectLocaleFromAcceptLanguage(header, validLocales))
  },
})
```

`getPreferredLocale()` geeft de state of cookie alleen terug wanneer het een ingeschakelde locale is, zodat een verouderde cookie de detectie niet tegenhoudt. `detectLocaleFromAcceptLanguage` is de matcher met ondersteuning voor q-waarden die de module zelf gebruikt (installeer `@i18n-micro/utils` om hem te importeren); `setLocale(null)` doet niets.

## Eén domein per locale {#one-domain-per-locale}

Als elk domein zijn eigen locales moet bedienen, heb je geen plugin nodig: geef elke locale een `baseUrl`, stel `baseDefault: true` in op de standaardlocale van elk domein en build één keer (een statische site draait nog steeds `nuxi generate` per domein). Zie [Layers en domeinen](/nl/guide/layers#multiple-domains).
