`$defineI18nRoute` stelt i18n-opties voor één pagina in vanuit de pagina zelf. Gebruik het wanneer een pagina alleen in sommige locales bestaat, een eigen gelokaliseerd pad nodig heeft, een paar eigen vertalingen bevat of geen hreflang-/canonical-tags mag krijgen. De module leest de aanroep tijdens de build en verwerkt hem in de gegenereerde routes.

## Een pagina beperken tot bepaalde locales {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

Onder de standaardstrategie `prefix_except_default` worden alleen `/product` en `/de/product` gegenereerd; de pagina heeft in geen enkele andere locale een route. Hetzelfde kan vanuit `nuxt.config.ts` worden ingesteld met [`routeLocales`](/nl/api/module-options#routelocales).

`$defineI18nRoute` is een injectie van de Nuxt-app, geen compilermacro: haal hem altijd uit `useNuxtApp()` en roep hem aan met de `$`. Alleen `$defineI18nRoute(` wordt door de buildstap herkend.

## Inline vertalingen toevoegen {#add-inline-translations}

Geef een object door in plaats van een array. De sleutels zijn de toegestane locales, de waarden worden samengevoegd in het woordenboek van de pagina voor de actieve locale.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Inline vertalingen worden voor elke locale meegeleverd in de paginacomponent. Gebruik bij voorkeur [paginavertaalbestanden](/nl/guide/translations) voor alles wat groter is dan een paar sleutels; bewaar inline sleutels voor op zichzelf staande pagina's en componenten.

## Gelokaliseerde paden instellen {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

Met `prefix_except_default` en `defaultLocale: 'en'` levert dit `/welcome` en `/de/willkommen` op. Een `path` binnen een inline locale-object doet hetzelfde: `locales: { de: { path: '/willkommen' } }`. Dynamische parameters, geneste routes en het alternatief op configniveau worden behandeld in [Gelokaliseerde paden](/nl/guide/custom-locale-routes).

## SEO-tags uitschakelen {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

Het alternatief op configniveau is [`routeDisableMeta`](/nl/api/module-options#routedisablemeta). Wat de tags zijn, staat op de pagina [SEO](/nl/guide/seo).

## Wat de build kan lezen {#what-the-build-can-read}

De buildstap vindt de aanroep in elk paginabestand en evalueert het argument zonder je app uit te voeren. Dat werkt wanneer de config:

- een letterlijk object is (strings, arrays, geneste objecten, template literals, ternaries op `process.env.NODE_ENV`);
- is opgebouwd uit constanten die in dezelfde `<script setup>` zijn gedeclareerd (`const locales = ['en', 'de']`, spreads inbegrepen);
- een array van objecten met een `code`-veld is (`[{ code: 'en' }, { code: 'de' }]`).

Hij kan geen waarden lezen die uit een andere module zijn geïmporteerd, of iets dat je app tijdens runtime nodig heeft (composables, `await`, opgehaalde data). In dat geval logt de build `Ignored the $defineI18nRoute() config in <file>` en houdt de pagina de standaard-locales en -routes.

Tijdens runtime voegt de aanroep alleen de inline vertalingen voor de huidige locale samen en voegt ze opnieuw samen wanneer de locale verandert. `locales`, `localeRoutes` en `disableMeta` werken alleen via de build, dus om ze te wijzigen is een nieuwe build nodig (de dev-server bouwt opnieuw bij opslaan).
