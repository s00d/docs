---
title: "Gelokaliseerde paden"
description: "Geef een pagina per locale een andere URL met localeRoutes of globalLocaleRoutes, inclusief dynamische parameters en slugs per locale."
---

Standaard serveert elke locale een pagina op hetzelfde pad: `/en/about`, `/de/about`. Met gelokaliseerde paden kan elke locale eigen woorden gebruiken, zoals `/de/ueber-uns`, terwijl het paginabestand hetzelfde blijft. Je stelt ze in op de pagina met `$defineI18nRoute`, of voor veel pagina's tegelijk in `nuxt.config.ts`.

## Op de pagina {#in-the-page}

```vue
<!-- pages/about.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  localeRoutes: {
    de: '/ueber-uns',
    fr: '/a-propos',
  },
})
</script>
```

Met `prefix_except_default` en `defaultLocale: 'en'` reageert de pagina op `/about`, `/de/ueber-uns` en `/fr/a-propos`. Een locale zonder vermelding behoudt het standaardpad. Schrijf paden zonder de locale-code: het prefix wordt toegevoegd door de [strategie](/nl/guide/strategy), en een pad dat met de locale-code begint, logt een waarschuwing. Wat de aanroep verder accepteert, staat op [Paginaconfiguratie](/nl/guide/per-component-translations).

## In nuxt.config {#in-nuxt-config}

[`globalLocaleRoutes`](/nl/api/module-options#globallocaleroutes) doet hetzelfde voor elke pagina, met het pad als sleutel (of de routenaam, wanneer geschreven zonder beginnende slash):

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    globalLocaleRoutes: {
      '/about': { de: '/ueber-uns' },
      '/about/team': { de: '/ueber-uns/team' },
      '/admin': false, // not localized: one /admin route, no locale prefix
    },
  },
})
```

Wanneer een pagina `localeRoutes` instelt en `globalLocaleRoutes` dezelfde sleutel heeft, wint de vermelding in de config.

## Dynamische parameters {#dynamic-params}

Schrijf parameters in elke Nuxt-vorm: `[id]`, `[[page]]`, `[...slug]` of `:id()`. De parameternamen moeten overeenkomen met het paginabestand.

```ts
// pages/products/[...slug].vue
$defineI18nRoute({
  localeRoutes: {
    en: '/our-products/[...slug]',
    de: '/unsere-produkte/[...slug]',
  },
})
```

Geneste pagina's nemen een absoluut kindpad (`/ueber-uns/team`) of een pad relatief aan het gelokaliseerde pad van de ouder (`team`).

## Linken naar gelokaliseerde pagina's {#linking-to-localized-pages}

Links worden omgezet naar het gelokaliseerde pad van de doellocale, of je nu een routenaam of een gewoon pad meegeeft:

```vue
<template>
  <i18n-link :to="{ name: 'about' }">About</i18n-link>
  <i18n-link to="/about">About</i18n-link>
  <!-- de: both render /de/ueber-uns -->
  <NuxtLink :to="$localePath('/about', 'de')">Deutsch</NuxtLink>
</template>
```

Routenamen komen uit het bestandspad (`pages/about/team.vue` wordt `about-team`), tenzij je er een instelt met `definePageMeta({ name })`.

## Slugs per locale {#per-locale-slugs}

Wanneer de slug zelf per locale verschilt (`/our-products/red-shoe` versus `/de/unsere-produkte/roter-schuh`), vertel de taalwisselaar dan welke parameters hij moet gebruiken met `$setI18nRouteParams` zodra de data geladen is:

```vue
<script setup lang="ts">
const { $setI18nRouteParams } = useNuxtApp()
const route = useRoute()

const { data: product } = await useFetch(`/api/products/${route.params.slug}`)

if (product.value) {
  $setI18nRouteParams({
    en: { slug: product.value.slugEn },
    de: { slug: product.value.slugDe },
  })
}
</script>
```

`$switchLocalePath('de')` en `<i18n-switcher>` linken dan naar `/de/unsere-produkte/roter-schuh`. Sleutels zijn locale-codes, waarden zijn parameters op naam (zoals in het paginabestand).

Een wisselaar in de layout wordt gerenderd voordat de asynchrone setup van de pagina hier aankomt, dus aan het einde van de render herschrijft de module de links van `<i18n-switcher>`, zowel in `app.vue` als in de pagina. De server-HTML, een bezoeker zonder JavaScript en de eerste client-render komen dan overeen. Stel de parameters hiervoor in tijdens SSR: met `lazy` of `server: false` veranderen de links pas na hydratatie. De SSR-streaming van Nuxt verstuurt de HTML voordat de parameters bekend zijn, dus daarbij behouden de links in de eerste HTML de eigen parameters van de URL.

Alleen de eigen links van de wisselaar worden herschreven. Een handgeschreven `$switchLocalePath`-link moet renderen nadat de parameters zijn ingesteld, dus zet hem op de pagina die ze instelt, ook na een `await`. In een layout rendert hij eerst: zijn server-HTML behoudt de parameters van de URL, en hydratatie waarschuwt voor een mismatch. Gebruik daar `<i18n-switcher>`, met zijn slots en `custom*Style`-props voor het uiterlijk.

De parameters horen bij de pagina die ze heeft ingesteld:

- Ze worden verwijderd wanneer een navigatie naar een ander pad wordt doorgevoerd, dus elke pagina stelt haar eigen parameters in. Een geannuleerde navigatie laat ze staan.
- Haal `$setI18nRouteParams` uit `useNuxtApp()` of `useI18n()` in `setup`, ook wanneer je het later in een `useAsyncData`-handler aanroept. Zo opgehaald kent de functie haar pagina: als de bezoeker al weg is, doet een late aanroep niets.
- Met `keepalive` krijgt een pagina de parameters die ze had ingesteld terug wanneer de bezoeker terugkeert. `useI18nHead` doet hetzelfde.

## Routes toegevoegd in pages:extend {#routes-added-in-pages-extend}

Routes die je in de hook `pages:extend` toevoegt, hebben geen paginabestand waaruit `$defineI18nRoute` gelezen kan worden, en vaak delen meerdere ervan één wrappercomponent. Een route die zonder `name` wordt toegevoegd, krijgt de naam die Nuxt aan zijn pad zou geven (`/a/:id()` wordt `a-id`), zodat taallinks hem bereiken, tenzij een andere route die naam al heeft; geef hem dan een expliciete `name`. Houd één lijst bij en splits die in pagina's en `globalLocaleRoutes` met de routenaam als sleutel met `splitLocaleRoutes` uit `@i18n-micro/utils/split-locale-routes` (voeg het pakket toe aan je dependencies):

```ts
// nuxt.config.ts
import { splitLocaleRoutes } from '@i18n-micro/utils/split-locale-routes'

const dynamic = splitLocaleRoutes([
  { name: 'products-tag', path: '/products/:tag', file: '~/pages/_dynamic.vue', paths: { de: '/produkte/:tag' } },
  { name: 'internal', path: '/internal', file: '~/pages/_dynamic.vue', paths: false }, // not localized
])

export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  hooks: {
    'pages:extend'(pages) {
      pages.push(...dynamic.pages)
    },
  },
  i18n: {
    globalLocaleRoutes: dynamic.globalLocaleRoutes,
  },
})
```

Zet gelokaliseerde paden niet in `route.meta`: dan zouden ze in de client-routetabel worden meegeleverd.
