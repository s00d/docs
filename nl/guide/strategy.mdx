De optie `strategy` bepaalt of een locale in de URL verschijnt en voor welke locales. Kies hem één keer, voordat je URL's publiceert: als je hem later wijzigt, verandert elke link. De module genereert vervolgens de gelokaliseerde routes tijdens de build, en `$localePath`, `<i18n-link>` en de switcher lezen ze.

## De vier strategieën {#the-four-strategies}

![De pagina /about in en (standaard) en de onder elke strategie; dezelfde URL's staan in de tekst hieronder](/images/diagrams/strategies.svg)

**Type** `Strategies` · **Standaard** `'prefix_except_default'`

URL-routingstrategie voor locale-prefixen.

- `'no_prefix'` — geen locale in de URL; de locale wordt in een cookie opgeslagen.
- `'prefix_except_default'` — prefix voor alle locales behalve de standaard.
- `'prefix'` — altijd een prefix, ook voor de standaard-locale.
- `'prefix_and_default'` — zoals `prefix`, maar de standaard-locale is ook zonder prefix bereikbaar.

URL's voor een `about`-pagina met `defaultLocale: 'en'` en de locales `en`, `de`:

| Strategie | Engels | Duits | Niet geserveerd |
| --- | --- | --- | --- |
| `prefix_except_default` (standaard) | `/about` | `/de/about` | `/en` en `/en/about` geven een 404 |
| `prefix` | `/en/about` | `/de/about` | `/about` stuurt door naar een URL met prefix |
| `prefix_and_default` | `/about` en `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | de locale staat niet in de URL |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

De strategie ligt vast bij de build: een runtime-override ervan wordt met een waarschuwing genegeerd ([Runtime-overrides](/nl/guide/runtime-overrides)).

## Welke je kiest {#which-one-to-choose}

- **`prefix_except_default`**: de meeste sites. Bestaande URL's zonder prefix blijven werken voor de standaardtaal.
- **`prefix`**: elke taal is gelijkwaardig; `/` leidt altijd naar een startpagina met prefix.
- **`prefix_and_default`**: je wilt dat zowel `/en/...` als de URL's zonder prefix werken, bijvoorbeeld tijdens de overstap van het ene naar het andere. URL's zonder prefix worden nooit doorgestuurd.
- **`no_prefix`**: apps achter een login, of één URL per pagina voor elke taal. De locale komt uit een cookie of `?locale=`. Zoekmachines zien één taal per URL, dus er worden geen `hreflang`-alternatieven uitgegeven.

Hoe de locale voor een URL wordt gekozen, en wanneer een bezoeker wordt doorgestuurd, staat op [Locale-detectie](/nl/guide/locale-detection).

## Gegenereerde routes {#generated-routes}

Tijdens de build krijgt elke pagina de routerecords die haar strategie nodig heeft. Elk record bevat `meta.i18n = { name, locales }`: de pagina die het toont en de locales die het bedient. Links, wissels en redirects worden allemaal vanuit die records beantwoord, dus een URL die de module uitgeeft is altijd een URL die de router bedient.

Locales die het pad van de pagina delen, delen één record, `/:locale(de|fr)/about`. Een locale met een eigen pad krijgt een eigen record, met de naam `localized-<page>-<locale>`:

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

Aangepaste paden, locale-lijsten per pagina en het uitsluiten van een pagina van lokalisatie staan op [Gelokaliseerde paden](/nl/guide/custom-locale-routes) en [Paginaconfig](/nl/guide/per-component-translations). Het prefix `localized-` is [`localizedRouteNamePrefix`](/nl/api/module-options#localizedroutenameprefix).

<Warning>

**Routenamen worden gegenereerd** — Codeer `localized-…`-namen niet hard in `router.push({ name })`. Geef de eigen naam van de pagina door aan `$localeRoute` of `<i18n-link>`; die kiezen het juiste record.

</Warning>

## Naar een pagina in een locale linken {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- Benoemde routes en paden werken allebei. Een pad wordt vergeleken met de gegenereerde routes, dus de vorm ervan in elke locale wordt geaccepteerd.
- Een locale die de pagina niet bedient (zie `locales` in [Paginaconfig](/nl/guide/per-component-translations)) linkt in plaats van naar een ontbrekende pagina naar de startpagina van die locale.
- Parameters per locale (een vertaalde slug) lopen via `$setI18nRouteParams`, zie [Gelokaliseerde paden](/nl/guide/custom-locale-routes).

Signaturen staan in [Methoden](/nl/api/methods).

## Details van `no_prefix` {#no_prefix-details}

- [`localeCookie`](/nl/api/module-options#localecookie) is onder `no_prefix` standaard `'user-locale'`, zodat de keuze een herlaadactie overleeft.
- `$switchLocale('de')` laadt het Duitse woordenboek en vervangt het huidige item in de geschiedenis; de URL verandert niet.
- Aangepaste paden per locale werken nog steeds: met `globalLocaleRoutes: { about: { de: '/ueber-uns' } }` krijgen Duitse lezers `/ueber-uns`. Die URL rendert altijd in het Duits, ongeacht de voorkeur van de bezoeker, en een pagina die tot bepaalde locales is beperkt, rendert in een daarvan. Een pad dat meerdere locales delen (`en` en `de` allebei op `/page/:id`) rendert de voorkeur wanneer die er een van is. De voorkeur zelf blijft behouden: de volgende pagina keert ernaar terug.
- [`noPrefixRedirect: true`](/nl/api/module-options#noprefixredirect) stuurt het oorspronkelijke pad van een pagina met een aangepast pad in de standaard-locale door: naar het aangepaste pad van de locale van de bezoeker, anders naar dat van de standaard-locale (`/about` → `/about-us` wanneer `en` `/about-us` heeft, → `/ueber-uns` met cookie `de`). Een locale zonder eigen aangepast pad blijft op het oorspronkelijke pad en rendert daar. Pagina's met parameters worden niet doorgestuurd.

## Apps zonder `pages/` {#apps-without-pages/}

Met `pages: false` zijn er geen paginaroutes om te lokaliseren. Gebruik alleen root-vertaalbestanden (`disablePageLocales: true`); detectie, de cookie en `$switchLocale` werken nog steeds. De variant `pages-false` van `test/fixtures/basic` in de repository is een werkende opzet.
