---
title: "Runtime-overrides"
description: "Wijzig de standaard-locale, fallback-locale of uitgeschakelde locales per instantie van één build, met omgevingsvariabelen of runtimeConfig."
---

Met runtime-overrides draait één build-artefact met verschillende locale-instellingen per omgeving of tenant, zonder opnieuw te builden. Je kunt de standaard-locale, de fallback-locale en de uitgeschakelde locales wijzigen. Routing, redirects, rendering en server-helpers gebruiken de overschreven waarden, en de browser op een server-gerenderde pagina ook.

## Overrides instellen met omgevingsvariabelen {#set-overrides-with-environment-variables}

```bash
NUXT_I18N_DEFAULT_LOCALE=de \
NUXT_I18N_FALLBACK_LOCALE=en \
NUXT_I18N_DISABLED_LOCALES=fr,it \
node .output/server/index.mjs
```

| Variabele | Alias |
| --- | --- |
| `NUXT_I18N_DEFAULT_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE` |
| `NUXT_I18N_FALLBACK_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE` |
| `NUXT_I18N_DISABLED_LOCALES` (kommagescheiden) | `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES` |

De server leest ze één keer bij het starten; herstart om een wijziging toe te passen. Op een server-gerenderde pagina krijgt de browser de opgeloste waarden van de server. Met `ssr: false` is er geen server-render en heeft de browser geen omgeving: daar geldt alleen `runtimeConfig.public.i18nRuntime`, en de browser logt de waarschuwingen hieronder.

## Overrides instellen in runtimeConfig {#set-overrides-in-runtimeconfig}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

Een waarde in `runtimeConfig.public.i18nRuntime` wint van de `NUXT_I18N_*`-variabele voor hetzelfde veld.

Niet te verwarren met de build-time-variabele `DEFAULT_LOCALE`, die `defaultLocale` tijdens het builden vervangt en geen runtime-ondersteuning nodig heeft.

## Wat wel en niet kan veranderen {#what-can-and-cannot-change}

| Instelling | Tijdens runtime |
| --- | --- |
| `defaultLocale` | Ja onder `prefix` en `no_prefix`. Onder `prefix_except_default` en `prefix_and_default` ligt het vast bij de build (de pagina's ervan zijn de routes zonder prefix); een override wordt genegeerd met een waarschuwing. |
| `fallbackLocale` | Ja. |
| `disabledLocales` | Voegt toe aan de locales die bij de build zijn uitgeschakeld; schakelt er nooit een opnieuw in. De build-standaard kan niet worden uitgeschakeld onder `prefix_except_default` / `prefix_and_default`. |
| `strategy` | Nee. Een runtime-strategie wordt genegeerd met een waarschuwing; build één artefact per strategie. |

Ongeldige waarden breken de app nooit. Elk geval logt één waarschuwing per serverproces:

- het uitschakelen van elke locale wordt genegeerd;
- een `defaultLocale` die niet is ingeschakeld, valt terug op de eerste ingeschakelde locale;
- een `fallbackLocale` die niet is ingeschakeld, behoudt de build-waarde als die is ingeschakeld; anders is er geen fallback.

## De effectieve config lezen {#read-the-effective-config}

```vue
<script setup lang="ts">
const { $getI18nConfig } = useNuxtApp()
const config = $getI18nConfig() // build config with overrides applied
</script>
```

Behandel hem als alleen-lezen: op de server wordt hij gedeeld door elk request en is hij in development bevroren; de kopie in de browser is niet bevroren. De config importeren uit `#build/i18n.strategy.mjs` geeft de build-waarden zonder overrides.

## Uitgeschakelde locales en statische bestanden {#disabled-locales-and-static-files}

Een tijdens runtime uitgeschakelde locale antwoordt 404 op zijn routes en payload-route, maar zijn payload-bestanden staan nog steeds in `.output/public/_locales/` en een statische bestandsserver geeft ze terug. Als die bestanden niet bereikbaar mogen zijn, schakel de locale dan tijdens de build uit met `disabled: true`.
