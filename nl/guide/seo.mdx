Met `meta: true` (de standaard) krijgt elke gelokaliseerde pagina `<html lang dir>`, een canonical link, `hreflang`-alternatieven, `x-default` en Open Graph-localetags. Je hebt deze pagina nodig wanneer je de publieke origin wilt instellen, wilt bepalen welke locales in de tags verschijnen, of ze voor één pagina wilt overschrijven. De meeste sites hebben alleen een `site.url` of `metaBaseUrl` en correcte `iso`-codes nodig.

## Minimale configuratie {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

`/de/about` rendert dan:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Tekstrichting {#text-direction}

`<html dir>` komt uit de `dir` van de locale. Zonder `dir` krijgt een taal die van rechts naar links wordt geschreven `rtl`, afgeleid uit `iso` (of `code`): Arabisch, Hebreeuws, Perzisch, Urdu en enkele andere, plus elke tag met een RTL-schrift zoals `az-Arab`. Alle andere locales krijgen geen `dir`-attribuut, wat browsers als `ltr` lezen.

<Warning>

**`dir: 'auto'` kost parseertijd op grote pagina's** — `auto` op `<html>` laat de browser de richting tijdens het parsen uit de inhoud afleiden. In Chromium groeien die kosten sneller dan de pagina: ongeveer 100 ms bij 5.000 elementen en 1 s bij 20.000. Gebruik het alleen voor een kleine pagina waarvan je de taal niet kunt weten.

</Warning>

## Welke tags je krijgt {#which-tags-you-get}

- **hreflang**: één tag per locale die de pagina serveert, met waarde `iso` (of `code` als `iso` ontbreekt) en een URL met dezelfde query als de canonical. Een pagina die beperkt is met [Paginaconfiguratie](/nl/guide/per-component-translations) of `routeLocales` vermeldt alleen haar eigen locales. [`hreflangBaseLanguage: true`](/nl/api/module-options#hreflangbaselanguage) voegt voor de eerste regionale locale ook de kale taal toe (`es-ES` → `es`).
- **x-default**: de URL van de standaardlocale, alleen wanneer de standaardlocale de pagina serveert.
- **og:locale**: afgeleid van `iso` (`en-US` → `en_US`). Stel `og` in op de locale wanneer de omzetting niet direct is, bijvoorbeeld `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; zonder een van beide wordt er geen `og:locale` geschreven en waarschuwt de dev-modus.
- **canonical / og:url**: de huidige URL zonder queryparameters, behalve die in [`canonicalQueryWhitelist`](/nl/api/module-options#canonicalquerywhitelist) (standaard `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Per strategie:

| Strategie | hreflang en x-default | canonical, og:url, og:locale, html-attributen |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | ja | ja |
| `no_prefix` | nee (één URL serveert elke locale) | ja |

## De publieke origin instellen {#set-the-public-origin}

Absolute URL's gebruiken de eerste van:

1. [`metaBaseUrl`](/nl/api/module-options#metabaseurl);
2. `site.url` uit `nuxt-site-config` (geïnstalleerd door `@nuxtjs/seo`);
3. de origin van het verzoek, met `app.baseURL` erachter.

Leg een van de eerste twee vast.

<Warning>

De fallback op de origin van het verzoek leest `X-Forwarded-Host` en `X-Forwarded-Proto`, omdat [`metaTrustForwardedHost`](/nl/api/module-options#metatrustforwardedhost) en `metaTrustForwardedProto` standaard `true` zijn. Dat is alleen veilig achter een proxy die die headers overschrijft; anders kan een client de host in je canonical links kiezen, en kan een cache die pagina doorgeven.

Als de app direct bereikbaar is, leg dan `metaBaseUrl` vast: in tegenstelling tot het op `false` zetten van beide opties negeert dit ook een vervalste `Host`. Zie [Achter een proxy of CDN](/nl/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

De fallback is handig voor één deployment die meerdere domeinen bedient: `https://site-a.com/en/about` en `https://site-b.com/en/about` krijgen elk hun eigen origin.

Met `baseUrl` op de locales gebruikt een bekende host zijn eigen `baseUrl`, boven `metaBaseUrl` en `site.url`, zodat canonical en `og:url` op dat domein blijven en `hreflang` elke locale naar haar domein laat wijzen. Elke andere host gebruikt `metaBaseUrl`, anders de `baseUrl` van de standaardlocale, anders `site.url`, zodat een vervalste `Host` je tags niet kan bereiken. Als geen daarvan is ingesteld, blijft de fallback op de origin van het verzoek bestaan en waarschuwt de build. Zie [Layers en domeinen](/nl/guide/layers#multiple-domains).

## Locales of pagina's weglaten {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Als de standaardlocale `seo: false` heeft, wordt er geen `x-default` geschreven. Om de tags voor één pagina uit te schakelen, gebruik je `disableMeta` in [Paginaconfiguratie](/nl/guide/per-component-translations#turn-off-seo-tags), of [`routeDisableMeta`](/nl/api/module-options#routedisablemeta) in de config.

## Tags op één pagina overschrijven {#override-tags-on-one-page}

Voor CMS-inhoud waarvan maar enkele vertalingen bestaan, of waarvan de URL's uit een API komen, vervang je de gegenereerde tags met [`useI18nHead`](/nl/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` kan ook `canonical`, `xDefault`, `ogLocale` en `ogUrl` instellen of verwijderen; `disable` laat hele groepen weg (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Geef een getter mee, zodat waarden na een locale-wissel opnieuw worden berekend. Stel voor slugs per locale eerst `$setI18nRouteParams` in ([Gelokaliseerde paden](/nl/guide/custom-locale-routes#per-locale-slugs)); de gegenereerde alternatieven gebruiken ze dan al.

## Afsluitende slash {#trailing-slash}

`$localePath`, `$switchLocalePath`, het route-object van `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, locale-redirects en de SEO-URL's volgen één slash-regel: standaard `experimental.defaults.nuxtLink.trailingSlash`, of [`trailingSlash`](/nl/api/module-options) in de i18n-config wanneer i18n-paden moeten afwijken.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) werkt met deze module via `nuxt-site-config` 4+. Zet `nuxt-i18n-micro` als eerste in de lijst, zodat de siteconfiguratie de locales kan lezen, en stel `site.url` één keer in — die voedt ook de tags hierboven.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Een vertaalde sitenaam en -beschrijving komen uit de sleutels `nuxtSiteConfig.name` / `nuxtSiteConfig.description` in je localebestanden. De fout `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` betekent dat `@nuxtjs/seo` ouder is dan versie 3; upgrade het ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
