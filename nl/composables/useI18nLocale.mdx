---
title: "useI18nLocale"
description: "useI18nLocale leest en schrijft de localestate en de locale-cookie — het toegangspunt voor aangepaste localedetectie."
---

`useI18nLocale()` geeft toegang tot de locale die de app heeft gekozen: de `i18n-locale`-state en de locale-cookie. Gebruik het in een plugin die de locale zelf detecteert (domein, gebruikersprofiel, header) in plaats van `useState('i18n-locale')` of de cookie handmatig te schrijven. De geldigheidscontroles gebruiken de ingeschakelde locales, inclusief runtime-overrides.

## Signatuur {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Gecentraliseerd toegangspunt voor het beheer van de i18n-locale.
Combineert useState('i18n-locale'), de locale-cookie en synchronisatiehulpmiddelen.

## Geretourneerde waarden {#returned-values}

| Lid | Type | Beschrijving |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | De `useState('i18n-locale')`-ref. |
| `localeCookie` | `Ref<string \| null>` | De [`localeCookie`](/nl/api/module-options#localecookie)-cookie; een gewoon `{ value: null }` wanneer de optie `null` is. |
| `hashCookie` | `Ref<string \| null>` | De `hash-locale`-cookie bij hashrouting; anders `{ value: null }`. |
| `validLocales` | `string[]` | Codes van de ingeschakelde locales. |
| `setLocale(locale)` | `(locale: string \| null) => void` | Schrijft de state en de cookies. Valideert niet en laadt geen vertalingen. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | Schrijft alleen de cookies. |
| `getLocale()` | `() => string \| null` | De state, daarna de voorkeurscookie (hashcookie bij hashrouting). Niet gevalideerd. |
| `getPreferredLocale()` | `() => string \| null` | De eerste **geldige** waarde van state en voorkeurscookie, of `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | De state bij hashrouting, als die is ingesteld; anders `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, daarna een geldige state, daarna `options.serverLocale`, daarna de locale van de route. Slaat het resultaat op in de state wanneer de state niet geldig is; op de client schrijft het ook de cookie. |
| `isValidLocale(locale)` | `(locale) => locale is string` | Of `locale` in `validLocales` staat. |

De cookies blijven één jaar geldig, met `path: '/'` en `sameSite: 'lax'`.

## Voorbeeld {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

De loaderplugin van de module leest de state bij het starten, dus een plugin die de state instelt moet eerst draaien (`enforce: 'pre'`). Hoe de state concurreert met de URL, de cookie en `Accept-Language`: [Localedetectie](/nl/guide/locale-detection). Volledige uitleg: [Aangepaste detectie](/nl/guide/custom-auto-detect).

`setLocale()` wisselt de vertalingen op het scherm niet. Roep [`$switchLocale()`](/nl/api/methods#$switchlocale) aan om de locale van de huidige pagina te wijzigen.
