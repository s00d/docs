**Datum**: 2026-07-30

**Versie**: `v3.24.0`

![v3.24.0-release](/images/3.24.0.png)

Node-productiebuilds embedden vertaalpayloads niet langer als Nitro-`serverAssets` / Rollup-`raw:` (RSS van meerdere GB tijdens de build bij grote catalogi). SSR leest dezelfde boom `/{apiBaseUrl}/{page}/{locale}/data.json` die de client ophaalt — uit `public/` via `readFile`. Edge behoudt een Nitro-embed en zou bij voorkeur `mode: 'source'` moeten gebruiken.

## Wat is er nieuw? {#what’s-new}

### Node: SSR vanuit `public/<apiBaseUrl>` {#node-ssr-from-public/&lt;apibaseurl&gt;}

- Node-presets die `public/` vanaf schijf serveren registreren **geen** Nitro-`serverAssets`.
- Payloads worden naar `public/<apiBaseUrl>` (standaard `_locales`) gekopieerd als `{page}/{locale}/data.json`.
- SSR laadt ze via `#i18n-internal/payload-source` → `readFile` (productiepad naast `.output/server`).
- `translationPayloads.serverAssets: true` betekent nog steeds "lokale SSR" en **forceert** die publieke kopie, zelfs als `publicAssets` false is.

Playground (vs de vorige `serverAssets`-embed): ~**1,25 GB** / ~6–7 s / `raw`=0 vs ~**3 GB** / ~13 s / ~170 raw-chunks.

### Edge: `serverAssets` alleen wanneer nodig {#edge-serverassets-only-when-needed}

- Edge (`nitro.node === false`) embedt nog steeds via Nitro-`serverAssets` (`assets:i18n`) met dezelfde indeling als `mode`.
- Edge forceert **geen** publieke kopie — stel `publicAssets: true` in voor CDN/statisch.
- Geeft een waarschuwing bij Edge + `mode: 'premerged'` (gebruik bij grote catalogi bij voorkeur `mode: 'source'`).

### `publicDir` sluit aan op client-URL's {#publicdir-aligns-with-client-urls}

- `translationPayloads.publicDir` is standaard **`apiBaseUrl`** (niet `translationDir`).
- De premerged publieke/Edge-boom is `{page}/{locale}/data.json`, overeenkomend met `$fetch('/_locales/...')`.
- De standaardwaarden van de module stellen niet langer geneste `publicAssets: true` in (de deep-merge van Nuxt forceerde een publieke kopie, zelfs voor `mode: 'source'`).

Zie [Moduleopties — `translationPayloads`](/nl/api/module-options#translationpayloads), [Deployment — serverless en Edge](/nl/guide/deployment#serverless-and-edge) en [Cache- en opslagarchitectuur](https://s00d.github.io/nuxt-i18n-micro/v3/api/i18n-cache-api).

## Breaking changes {#breaking-changes}

- **Geen woordenboeken in de Nuxt-SSR-HTML-payload.** `payload.data['i18n-ssr-chunks']`, `setSsrChunk` en `seedFromSsrChunks` zijn **verwijderd**. Dezelfde standaardhouding als `@nuxtjs/i18n` (`experimental.preload: false`): de server houdt vertalingen in het geheugen voor SSR; de client laadt `/{apiBaseUrl}/.../data.json` tijdens de setup van de plugin (`await switchContext`).
- **`prerenderRoutes` is standaard `false`.** Schakel het alleen in als Nitro handler-routes moet materialiseren wanneer `publicAssets` de boom nog niet heeft geschreven (premerged `publicAssets` genereert al `{page}/{locale}/data.json`).
- **De standaardwaarde van `publicDir` is `apiBaseUrl`**, niet `translationDir`. Statische output verhuist van bijv. `public/locales/...` naar `public/_locales/{page}/{locale}/data.json`, tenzij je `publicDir` expliciet instelt.
- **De premerged opslagindeling** is nu `{page}/{locale}/data.json` (was `pages/{page}/{locale}.json`). Alles wat Nitro-/opslagsleutels las of bomen in de oude vorm kopieerde, moet worden bijgewerkt.
- **Op Node betekent `serverAssets: true` niet langer een Nitro-embed** — het betekent lokale SSR via de publieke kopie. Een echte Rollup-`raw:`-embed blijft alleen voor Edge.

## Migratie {#migration}

1. Verwijder alle code die `payload.data['i18n-ssr-chunks']` las of `seedFromSsrChunks` / `setSsrChunk` aanriep.
2. Voor puur statische hosts: behoud de standaard premerged + `publicAssets` (bestanden komen terecht op `/_locales/.../data.json`), of stel `prerenderRoutes: true` in / host payloads op een CDN.
3. Voor Cloudflare / andere Edge: stel bij grote catalogi `translationPayloads: { mode: 'source' }` in; voeg `publicAssets: true` alleen toe als je een statische/CDN-kopie nodig hebt.
4. Als je afhankelijk was van payloads onder `public/<translationDir>`, stel dan `translationPayloads.publicDir` in of richt tooling op `public/<apiBaseUrl>`.

## Fix: uitgeschakelde locales overslaan in premerged publieke payloads {#fix-skip-disabled-locales-in-premerged-public-payloads}

`preMergeLocales` schrijft `{page}/{locale}/data.json` nu alleen voor locales die aan de samenvoeging worden doorgegeven (`locale.disabled: true` tijdens de build wordt weggelaten). Voorheen werd elke JSON-locale op schijf naar `public/` gekopieerd, waardoor Nitro static uitgeschakelde locales met 200 serveerde en de handler omzeilde. Runtime-`disabledLocales` kan bestanden die al gebouwd zijn nog steeds niet depubliceren — gebruik `locale.disabled` tijdens de build wanneer `publicAssets` / de publieke kopie voor Node-SSR aan staat.

## Waarom het ertoe doet {#why-it-matters}

- Node-builds blijven slank: geen Rollup-`raw:`-piek van meerdere GB door vertaalcatalogi.
- Publieke bestanden en `$fetch`-URL's van de client delen één padindeling — statische hosting werkt zonder speciale remapping.
- Edge kan nog steeds compacte `source`-payloads embedden zonder een dubbele publieke boom af te dwingen.
