# Referentie module-opties

Elke optie die `nuxt-i18n-micro` accepteert, tijdens build gelezen uit de `ModuleOptions`-
interface in
[`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).
Niets hier wordt met de hand geschreven, dus het kan niet achterlopen op de code — types, standaardwaarden en
beschrijvingen komen uit de declaratie zelf.

Voor wat deze opties *samen betekenen* — welke combinaties zinvol zijn, wat verandert wanneer
je van strategie wisselt, uitgewerkte voorbeelden — lees [Configuratie](/guides/configuration). Deze
pagina is de volledige lijst; die is de uitleg.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Geneste opties verschijnen onder hun gestippelde pad, dus `translationPayloads.mode` is de
`mode`-sleutel binnen het object `translationPayloads`.

## Locales en routing

Welke talen bestaan en hoe ze in de URL verschijnen.

| Optie | Type | Standaard | Beschrijving |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Lijst met ondersteunde locales. Elke entry definieert een localecode plus optionele metadata (ISO, richting, weergavenaam, enz.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | URL-routingstrategie voor localeprefixes. - `'no_prefix'` — geen locale in URL; locale opgeslagen in cookie. - `'prefix_except_default'` — prefix alle locales behalve de standaard. - `'prefix'` — altijd prefixen, inclusief de standaardlocale. - `'prefix_and_default'` — zoals `prefix`, maar de standaardlocale is ook zonder prefix toegankelijk. |
| `defaultLocale` | `string` | `'en'` | De locale die wordt gebruikt wanneer er geen locale kan worden bepaald uit URL of gebruikersvoorkeuren. Ook gebruikt als fallback-locale voor ontbrekende vertalingen wanneer `fallbackLocale` niet is ingesteld. |
| `localeCookie` | `string \| null` | `null` | Cookienaam voor het behouden van de localevoorkeur van de gebruiker over sessies heen. Zet op `null` om cookiegebaseerde persistentie uit te schakelen. Automatisch ingesteld op `'user-locale'` voor de `no_prefix`-strategie als niet opgegeven. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Route-level locale-configuratie op globaal niveau. Maakt het mogelijk om localeroutes voor specifieke pagina's te beperken of aan te passen zonder de componenten te wijzigen. - `false` — sluit de route uit van lokalisatie. - `Record<LocaleCode, string>` — aangepaste paden per locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (gebruikt ingebouwd patroon op basis van localecodes)` | Aangepaste reguliere expressie (of de string-source ervan) voor het matchen van localecodes in URL-segmenten. Alle localecodes in `locales` moeten aan dit patroon voldoen, anders wordt een waarschuwing uitgezonden. |
| `noPrefixRedirect` | `boolean` | `false` | Voor `no_prefix`-strategie: schakel redirect in van een locale-geprefixte URL (bijv. `/en/about`) naar de niet-geprefixte versie (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | URL-patronen (strings of RegExp) om volledig uit te sluiten van i18n-verwerking. Overeenkomende routes krijgen geen localeprefixes, redirects of vertalingsladen. Interne Nuxt-paden (`/__nuxt_error`, enz.) worden altijd automatisch uitgesloten. |
| `routeLocales` | `Record<string, string[]>` | — | Localebeperkingen per route, geëxtraheerd uit `defineI18nRoute()`-aanroepen. Koppelt een routepad (bijv. `'/about'`) aan een array van toegestane localecodes. Routes die niet worden vermeld, hebben geen beperkingen (alle locales toegestaan). |

## Vertalingen

Waar vertaalbestanden staan en hoe sleutels worden opgelost.

| Optie | Type | Standaard | Beschrijving |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Pad naar de map met vertaal-JSON-bestanden, relatief aan de projectroot. |
| `disableWatcher` | `boolean` | `false` | Schakel de bestandswatcher uit die ontbrekende vertaalbestanden automatisch aanmaakt in ontwikkelingsmodus. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Koppel routenamen aan andere routenamen om dezelfde vertaalbestanden te delen. Bijv. `\{ 'about-us': 'about' \}` betekent dat de pagina `about-us` vertalingen van de pagina `about` gebruikt in plaats van eigen. |
| `plural` | `PluralFunc` | `ingebouwde pluralisatie (vormindex op basis van telling)` | Aangepaste pluralisatiefunctie. Ontvangt `(key, count, params, locale, getter)` en moet de geselecteerde meervoudsvorm als string retourneren, of `null`/`undefined` om terug te vallen op de ingebouwde `defaultPlural`-logica (zodat je alleen sommige locales kunt overschrijven). Voor de Nuxt-module wordt de functie geserialiseerd via `.toString()` naar `.nuxt/i18n.plural.mjs` — deze moet zelfstandig zijn (geen imports / externe scope). Een string van een bestandspad wordt **niet** ondersteund. |
| `disablePageLocales` | `boolean` | `false` | Schakel vertaalbestanden per pagina uit. Wanneer `true`, worden alleen globale vertalingen (`\{locale\}.json`) geladen; pagina-specifieke bestanden (`pages/\{page\}/\{locale\}.json`) worden niet gegenereerd of geladen. |
| `fallbackLocale` | `string` | `undefined (geen fallback; retourneert de kale sleutel)` | Globale fallback-localecode. Wanneer een vertaalsleutel ontbreekt in de actieve locale, zoekt de module deze op in deze locale voordat de sleutel zelf wordt geretourneerd. |

## Payloads en caching

Hoe vertalingen de browser bereiken. [Performance](/guides/performance) legt uit wat dit tijdens runtime verandert.

| Optie | Type | Standaard | Beschrijving |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Preload index-paginavertalingen in Nitro globale middleware (alleen server, private config). |
| `apiBaseUrl` | `string` | `'_locales'` | Base-URL-padsegment voor de vertalings-API-route (gebruikt in SSR/SSG-datafetching). Kan ook worden ingesteld via de omgevingsvariabele `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Overschrijf de host die wordt gebruikt voor client-side vertaal-fetch-verzoeken. Nuttig wanneer de client de server bereikt via een andere hostname dan die Nuxt ziet. Kan ook worden ingesteld via de omgevingsvariabele `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Overschrijf de host die wordt gebruikt voor server-side vertaal-fetch-verzoeken. Nuttig in container/microservice-setups waarin de server zichzelf bereikt via een interne hostname. Kan ook worden ingesteld via de omgevingsvariabele `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Bepaalt hoe vertaalpayloads worden uitgezonden (Node: `public/<apiBaseUrl>`; Edge: Nitro `serverAssets`). - **Node**: `serverAssets` betekent lokale SSR via `readFile` onder `public/` (geen Rollup `raw:`). - **Edge**: `serverAssets` registreert Nitro `serverAssets` (`assets:i18n`); dit forceert geen publieke kopie. Houd de standaardwaarden aan voor de gebruikelijke all-in-one-opzet. Voor grote Edge-catalogi geef je de voorkeur aan `mode: 'source'`. Voor CDN-backed deployments schakel je lokale outputs uit en stel je `apiBaseClientHost` / `apiBaseServerHost` in. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Vertaalpayload-strategie. - `premerged`: buildtime `\{page\}/\{locale\}/data.json`-matrix (standaard) - `source`: compacte bronbestanden samengevoegd tijdens runtime (voorkeur op Edge / grote catalogi) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Lokale SSR-payloads: Node leest `public/<apiBaseUrl>` (forceert publieke kopie); Edge embedded via Nitro `serverAssets`. - **Node**: geen Nitro `serverAssets` (vermijdt Rollup `raw:`). SSR leest   `public/<apiBaseUrl\|publicDir>` als `\{page\}/\{locale\}/data.json`; wanneer dit `true` is,   wordt een publieke kopie geforceerd, zelfs als `publicAssets` false is. - **Edge** (`nitro.node === false`): Nitro `serverAssets` (`assets:i18n`) met dezelfde   layout als `mode`. Forceert **geen** publieke kopie — stel `publicAssets: true` in voor CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Registreer de ingebouwde serverroute op `/\{apiBaseUrl\}/:page/:locale/data.json`. Schakel dit uit wanneer vertaalpayloads worden geserveerd vanaf een externe host/CDN. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged-modus, false in source-modus` | Kopieer payloads naar Nitro publieke output. Premerged → `\{page\}/\{locale\}/data.json` onder `apiBaseUrl`; source → compacte boom. Op Node is deze boom ook de SSR-bron wanneer `serverAssets` een publieke kopie forceert. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Opt-in om Nitro te prerenderen `/\{apiBaseUrl\}/.../data.json`. Meestal overbodig wanneer premerged `publicAssets` die bestanden al heeft geschreven. |
| `translationPayloads.publicDir` | `string` | — | Publieke output-map relatief aan Nitro-publieke-root. Standaard `apiBaseUrl` (`_locales`). Zo komen statische bestanden overeen met client-fetch-URL's (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Waarschuwen tijdens build wanneer het aantal gegenereerde payload-bestanden deze drempel overschrijdt. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Waarschuwen tijdens build wanneer de totale gegenereerde payloadgrootte deze drempel in bytes overschrijdt. |

## SEO

Metatags gegenereerd voor elke gelokaliseerde pagina.

| Optie | Type | Standaard | Beschrijving |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Genereer automatisch SEO-metatags (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | Base-URL voor SEO-metatags (canonical, og:url, hreflang). - Een concrete URL-string (bijv. `'https://example.com'`) — wordt zo gebruikt (hoogste prioriteit). - `undefined` — valt terug op `site.url` uit `nuxt-site-config` wanneer die module   aanwezig is, anders de huidige request-origin   (`useRequestURL().origin` op server, `window.location.origin` op client). |
| `metaTrustForwardedHost` | `boolean` | `true` | Vertrouw de `X-Forwarded-Host`-header bij het oplossen van de base-URL voor metatags. Schakel in wanneer de app achter een reverse proxy draait (nginx, Cloudflare, AWS ALB, enz.) die deze header instelt op de daadwerkelijke client-hostname. |
| `metaTrustForwardedProto` | `boolean` | `true` | Vertrouw de `X-Forwarded-Proto`-header bij het oplossen van het protocol voor metatags. Schakel in wanneer de app achter een TLS-terminerende proxy draait zodat canonieke URL's `https://` gebruiken, ook al luistert de app zelf op HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Lijst met queryparameternamen die behouden blijven in canonical- en `og:url`-metatags. Parameters die niet in deze lijst staan, worden uit de canonieke URL verwijderd. |

## Detectie en redirects

Een locale kiezen voor een bezoeker die er nog geen heeft gekozen.

| Optie | Type | Standaard | Beschrijving |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Schakel automatische locale-gebaseerde redirects in. Wanneer `true`, worden bezoekers bij het eerste bezoek geredirect naar hun voorkeurslocale (gedetecteerd uit cookie, `Accept-Language`-header of standaard). |
| `autoDetectLanguage` | `boolean` | `true` | Detecteer automatisch de voorkeurstaal van de gebruiker uit de HTTP-header `Accept-Language`. Wordt gecombineerd met `autoDetectPath` om te bepalen wanneer detectie plaatsvindt. |
| `autoDetectPath` | `string` | `'/'` | Waar cookie- / Accept-Language-voorkeur-redirects mogen draaien (wanneer `redirects` is ingeschakeld). - `'/'` — alleen `/` (deep links in de standaardlocale blijven bereikbaar; standaard) - `'no_prefix'` — alleen paden zonder localeprefix - `'*'` — elk pad, inclusief het herschrijven van een expliciete localeprefix   (bijv. `/fr/about` → `/de/about` wanneer de cookie `de` verkiest) - elke andere string — exacte padmatch (bijv. `'/welcome'`) Opruimen van geprefixte strategieën (bijv. `/en` → `/` onder `prefix_except_default`) wordt niet gefilterd. |

| `plugin` | `boolean` | `true` | Registreer de core-i18n-plugin die `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` en andere runtime-helpers levert. |
| `hooks` | `boolean` | `true` | Registreer de i18n-hooks-plugin die `i18n:register`, `i18n:beforeLocaleSwitch` en `i18n:afterLocaleSwitch` app-level hooks levert. |
| `components` | `boolean` | `true` | Registreer ingebouwde i18n-componenten (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Zet op `false` om automatische componentregistratie uit te schakelen (bijv. als je ze niet gebruikt en de module-footprint wilt verkleinen). |
| `types` | `boolean` | `true` | Genereer TypeScript-typedeclaraties voor `useI18n`, `$t` en gerelateerde helpers op basis van de vertaalsleutels in je standaardlocalebestanden. |
| `debug` | `boolean` | `false` | Schakel uitgebreide debuglogging in voor localedetectie, routegeneratie en vertalingsladen. |

## Overig

| Optie | Type | Standaard | Beschrijving |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | Zend ook een kale-taal-`hreflang` uit afgeleid van de `iso` van elke locale (bijv. `es-ES` → ook `es`). De eerste regionale locale in `locales` claimt de kale tag voor die taal. Routing-`code` wordt nooit gebruikt — alleen `iso \|\| code`. |
| `vueDevtools` | `boolean` | `true` | Registreer Vue DevTools-inspector en tijdlijn in dev (browserextensie). Los van het custom Nuxt DevTools-tabblad. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Prefix die vooraan gelokaliseerde routenamen wordt gezet (bijv. `'localized-index'`). Intern gebruikt om originele routes te onderscheiden van gegenereerde locale-varianten. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Metatag-uitschakeling per route, geëxtraheerd uit `defineI18nRoute()`-aanroepen. Koppelt een routepad aan `true` (alle meta uitschakelen) of aan een array van localecodes waarvoor meta moet worden uitgeschakeld. |
| `missingWarn` | `boolean` | `true` | Toon consolewaarschuwingen wanneer een vertaalsleutel ontbreekt. |
| `hmr` | `boolean` | `true` | Schakel Hot Module Replacement voor vertaalbestanden in tijdens ontwikkeling. Wanneer `true`, activeren wijzigingen aan JSON-vertaalbestanden een automatische reload zonder volledige paginaverversing. |
| `cacheMaxSize` | `number` | `0` | Maximaal aantal entries in de in-memory vertaalcache. `0` betekent geen limiet. |
| `cacheTtl` | `number` | `0` | Time-to-live (in seconden) voor gecachete vertaalentries. `0` betekent dat entries nooit verlopen. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Benoemde getalformaten per locale (Vue I18n-compatibel). Maakt aanroepen in de stijl `$tn(1000, 'currency')` mogelijk. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Benoemde datetime-formaten per locale (Vue I18n-compatibele `datetimeFormats`). Maakt aanroepen in de stijl `$td(date, 'short')` mogelijk. |
| `httpCacheDuration` | `number` | `31536000` | HTTP-`Cache-Control` max-age (seconden) voor `/\{apiBaseUrl\}/:page/:locale/data.json`. Volledig van toepassing zolang `dateBuild` de URL bust (`?v=...`), wat de standaard is: de response is dan `public, max-age=…, immutable` en veilig voor browsers en CDN's. - `dateBuild: 0`/`''` — de URL is stabiel, dus deze duur wordt *niet* toegepast; de   response wordt in plaats daarvan `public, max-age=0, must-revalidate`. Een lange `max-age` op een   onveranderlijke URL pint de eerste payload die een browser ooit zag. - `0` — stel `Cache-Control` helemaal niet in (nuttig bij lokaal debuggen) - Niet toegepast in ontwikkeling (`import.meta.dev`) zodat HMR niet wordt tegengewerkt door de browsercache - Bereikt alleen responses die via Nitro worden geserveerd. Payloads gekopieerd naar `public/` en geserveerd   door het hostingplatform nemen de headers van dat platform aan — zie de Performance-gids. Analoog aan het experimentele `httpCacheDuration` van `@nuxtjs/i18n` (v10.2.0), maar als een expliciete response-header in plaats van Nitro `defineCachedEventHandler` maxAge. |
| `dateBuild` | `string \| number` | — | Waarde gebruikt voor cache-busting van vertaalverzoeken (`?v=...`). Wanneer niet opgegeven, valt de module terug op `Date.now()` (niet-deterministisch). Voor reproduceerbare/rollende deployments, stel dit in op een stabiele waarde (bijv. een git SHA of buildnummer). |
| `experimental` | `Record<string, unknown>` | — | Bucket voor experimentele/onstabiele opties. Inhoud kan zonder waarschuwing tussen minor-versies veranderen of verwijderd worden. |
