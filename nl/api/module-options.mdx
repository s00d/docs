# Referentie van module-opties

Elke optie die `nuxt-i18n-micro` accepteert, tijdens de build gelezen uit de `ModuleOptions`-interface in
[`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).
Niets hiervan is handmatig geschreven, dus het kan niet achterlopen op de code. Types, standaardwaarden en beschrijvingen komen uit de declaratie zelf.

Voor wat deze opties *samen betekenen* — welke combinaties zinvol zijn, wat er verandert wanneer je van strategie wisselt, uitgewerkte voorbeelden — lees je [Configuratie](/guides/configuration). Deze pagina is de volledige lijst; die andere is de uitleg.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Geneste opties verschijnen onder hun gepunt pad. Dus `translationPayloads.mode` is de sleutel `mode` binnen het object `translationPayloads`.

## Locales en routering

Welke talen bestaan en hoe ze in de URL verschijnen.

| Optie | Type | Standaard | Beschrijving |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Lijst van ondersteunde locales. Elk item definieert een locale-code plus optionele metadata (ISO, richting, weergavenaam, enzovoort). |
| `strategy` | `Strategies` | `'prefix_except_default'` | URL-routeringsstrategie voor locale-prefixen. - `'no_prefix'` — geen locale in de URL; locale opgeslagen in een cookie. - `'prefix_except_default'` — prefix alle locales behalve de standaard. - `'prefix'` — altijd prefixen, inclusief de standaardlocale. - `'prefix_and_default'` — zoals `prefix`, maar de standaardlocale is ook toegankelijk zonder prefix. |
| `defaultLocale` | `string` | `'en'` | De locale die wordt gebruikt wanneer er geen locale uit de URL of gebruikersvoorkeuren kan worden afgeleid. Wordt ook gebruikt als fallback-locale voor ontbrekende vertalingen wanneer `fallbackLocale` niet is ingesteld. |
| `localeCookie` | `string \| null` | `null` | Cookienaam voor het bewaren van de localevoorkeur van de gebruiker over sessies heen. Zet op `null` om cookie-persistentie uit te schakelen. Wordt automatisch ingesteld op `'user-locale'` voor de `no_prefix`-strategie als deze niet is opgegeven. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Globale locale-configuratie op routeniveau. Hiermee kun je locale-routes voor specifieke pagina's beperken of aanpassen zonder hun componenten te wijzigen. - `false` — sluit de route uit van lokalisatie. - `Record<LocaleCode, string>` — aangepaste paden per locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (gebruikt het ingebouwde patroon op basis van locale-codes)` | Aangepaste reguliere expressie (of de string-bron ervan) om locale-codes in URL-segmenten te matchen. Alle locale-codes die in `locales` zijn gedefinieerd, moeten overeenkomen met dit patroon, anders wordt een waarschuwing gegeven. |
| `noPrefixRedirect` | `boolean` | `false` | Voor de `no_prefix`-strategie: schakel redirect in van een URL met locale-prefix (bijvoorbeeld `/en/about`) naar de versie zonder prefix (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | URL-patronen (strings of RegExp) om volledig uit te sluiten van i18n-verwerking. Overeenkomstige routes krijgen geen locale-prefix, redirects of vertaal-laden. Interne Nuxt-paden (`/__nuxt_error`, enzovoort) worden altijd automatisch uitgesloten. |
| `routeLocales` | `Record<string, string[]>` | — | Locale-beperkingen per route, gehaald uit `defineI18nRoute()`-aanroepen. Koppelt een routepad (bijvoorbeeld `'/about'`) aan een array van toegestane locale-codes. Routes die niet worden vermeld, hebben geen beperkingen (alle locales toegestaan). |

## Vertalingen

Waar vertaalbestanden staan en hoe sleutels worden opgelost.

| Optie | Type | Standaard | Beschrijving |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Pad naar de map met vertaal-JSON-bestanden, relatief aan de projectroot. |
| `disableWatcher` | `boolean` | `false` | Schakel de file watcher uit die ontbrekende vertaalbestanden in de dev-modus automatisch aanmaakt. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Map routenamen aan andere routenamen om dezelfde vertaalbestanden te delen. Bijvoorbeeld `\{ 'about-us': 'about' \}` betekent dat de pagina `about-us` de vertalingen van de pagina `about` gebruikt in plaats van eigen. |
| `plural` | `PluralFunc` | `ingebouwde meervoudsvorming (formulierindex op basis van count)` | Aangepaste meervoudsfunctie. Ontvangt `(key, count, params, locale, getter)` en moet de gekozen meervoudsvorm als string retourneren, of `null`/`undefined` om terug te vallen op de ingebouwde `defaultPlural`-logica (zodat je alleen sommige locales kunt overschrijven). Voor de Nuxt-module wordt de functie geserialiseerd met `.toString()` in `.nuxt/i18n.plural.mjs`. Ze moet zelfstandig zijn (geen imports of externe scope). Een pad-string wordt **niet** ondersteund. |
| `disablePageLocales` | `boolean` | `false` | Schakel per-pagina vertaalbestanden uit. Bij `true` worden alleen globale vertalingen (`\{locale\}.json`) geladen; paginaspecifieke bestanden (`pages/\{page\}/\{locale\}.json`) worden niet gegenereerd of geladen. |
| `fallbackLocale` | `string` | `undefined (geen fallback; retourneert de kale sleutel)` | Globale fallback-locale-code. Wanneer een vertaalsleutel ontbreekt in de actieve locale, zoekt de module deze op in deze locale voordat de sleutel zelf wordt geretourneerd. |

## Payloads en caching

Hoe vertalingen de browser bereiken. [Performance](/guides/performance) legt uit wat deze tijdens runtime veranderen.

| Optie | Type | Standaard | Beschrijving |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Preload vertalingen van de indexpagina in Nitro global middleware (alleen server, private config). |
| `apiBaseUrl` | `string` | `'_locales'` | Basissegment voor de vertaal-API-route (gebruikt bij SSR/SSG-data-fetching). Kan ook worden ingesteld via de omgevingsvariabele `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Overschrijf de host die wordt gebruikt voor client-side vertaal-fetches. Handig wanneer de client de server bereikt via een andere hostname dan die Nuxt ziet. Kan ook worden ingesteld via de omgevingsvariabele `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Overschrijf de host die wordt gebruikt voor server-side vertaal-fetches. Handig in container-/microservice-setups waarbij de server zichzelf bereikt via een interne hostname. Kan ook worden ingesteld via de omgevingsvariabele `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Bepaalt hoe vertaalpayloads worden uitgezonden (Node: `public/<apiBaseUrl>`; Edge: Nitro `serverAssets`). - **Node**: `serverAssets` betekent lokale SSR via `readFile` onder `public/` (geen Rollup `raw:`). - **Edge**: `serverAssets` registreert Nitro `serverAssets` (`assets:i18n`); dit forceert geen publieke kopie. Behoud de standaardwaarden voor de gebruikelijke all-in-one setup. Voor grote Edge-catalogi geef je de voorkeur aan `mode: 'source'`. Voor deployments achter een CDN schakel je lokale outputs uit en stel je `apiBaseClientHost` / `apiBaseServerHost` in. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Payload-strategie voor vertalingen. - `premerged`: build-time-matrix `\{page\}/\{locale\}/data.json` (standaard). - `source`: compacte bronbestanden die tijdens runtime worden samengevoegd (aanbevolen voor Edge of grote catalogi). |
| `translationPayloads.serverAssets` | `boolean` | `true` | Lokale SSR-payloads: Node leest `public/<apiBaseUrl>` (forceert publieke kopie); Edge embed via Nitro `serverAssets`. - **Node**: geen Nitro `serverAssets` (vermijdt Rollup `raw:`). SSR leest `public/<apiBaseUrl\|publicDir>` als `\{page\}/\{locale\}/data.json`; wanneer dit `true` is, wordt een publieke kopie geforceerd, zelfs als `publicAssets` false is. - **Edge** (`nitro.node === false`): Nitro `serverAssets` (`assets:i18n`) met dezelfde indeling als `mode`. Forceert **geen** publieke kopie — zet `publicAssets: true` voor CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Registreer de ingebouwde server-route op `/\{apiBaseUrl\}/:page/:locale/data.json`. Schakel dit uit wanneer vertaalpayloads worden geserveerd vanaf een externe host of CDN. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged-modus, false in source-modus` | Kopieer payloads naar de publieke output van Nitro. Premerged → `\{page\}/\{locale\}/data.json` onder `apiBaseUrl`; source → compacte structuur. Op Node is deze boom ook de SSR-bron wanneer `serverAssets` een publieke kopie forceert. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Opt-in voor Nitro-prerender van `/\{apiBaseUrl\}/.../data.json`. Meestal overbodig wanneer premerged `publicAssets` die bestanden al heeft geschreven. |
| `translationPayloads.publicDir` | `string` | — | Publieke outputmap relatief aan de Nitro public root. Valt terug op `apiBaseUrl` (`_locales`), zodat statische bestanden overeenkomen met client-fetch-URL's (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Waarschuw tijdens de build wanneer het aantal gegenereerde payload-bestanden deze drempel overschrijdt. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Waarschuw tijdens de build wanneer de totale grootte van gegenereerde payloads deze drempel in bytes overschrijdt. |

## SEO

Metatags die voor elke gelokaliseerde pagina worden gegenereerd.

| Optie | Type | Standaard | Beschrijving |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Genereer automatisch SEO-metatags (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | Basis-URL voor SEO-metatags (canonical, og:url, hreflang). - Een concrete URL-string (bijvoorbeeld `'https://example.com'`) — wordt as-is gebruikt (hoogste prioriteit). - `undefined` — valt terug op `site.url` uit `nuxt-site-config` wanneer die module aanwezig is; anders op de huidige request-origin (`useRequestURL().origin` op de server, `window.location.origin` op de client). |
| `metaTrustForwardedHost` | `boolean` | `true` | Vertrouw de `X-Forwarded-Host`-header bij het bepalen van de basis-URL voor metatags. Inschakelen wanneer de app achter een reverse proxy (nginx, Cloudflare, AWS ALB, enzovoort) draait die deze header op de echte client-hostname zet. |
| `metaTrustForwardedProto` | `boolean` | `true` | Vertrouw de `X-Forwarded-Proto`-header bij het bepalen van het protocol voor metatags. Inschakelen wanneer de app achter een TLS-terminerende proxy draait, zodat canonieke URL's `https://` gebruiken terwijl de app zelf op HTTP luistert. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Lijst van queryparameternamen die in canonical- en `og:url`-metatags behouden blijven. Parameters die niet in deze lijst staan, worden uit de canonieke URL verwijderd. |

## Detectie en redirects

Een locale kiezen voor een bezoeker die er geen heeft gekozen.

| Optie | Type | Standaard | Beschrijving |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Schakel automatische redirects op basis van locale in. Bij `true` worden bezoekers bij hun eerste bezoek doorgestuurd naar hun voorkeurslocale (gedetecteerd uit cookie, `Accept-Language`-header of de standaard). |
| `autoDetectLanguage` | `boolean` | `true` | Detecteer de voorkeurstaal van de gebruiker automatisch uit de `Accept-Language`-HTTP-header. Wordt in combinatie met `autoDetectPath` gebruikt om te bepalen wanneer detectie plaatsvindt. |
| `autoDetectPath` | `string` | `'/'` | Waar cookie- en Accept-Language-voorkeur-redirects mogen draaien (wanneer `redirects` is ingeschakeld). - `'/'` — alleen `/` (deeplinks in de standaardlocale blijven bereikbaar; standaard). - `'no_prefix'` — alleen paden zonder locale-prefix. - `'*'` — elk pad, inclusief het herschrijven van een expliciete locale-prefix (bijvoorbeeld `/fr/about` → `/de/about` wanneer de cookie `de` prefereert). - elke andere string — exacte padmatch (bijvoorbeeld `'/welcome'`). Opschonen van prefix-strategieën (bijvoorbeeld `/en` → `/` onder `prefix_except_default`) is niet afhankelijk van deze instelling. |

## Registratie

Delen van de module die je kunt uitschakelen.

| Optie | Type | Standaard | Beschrijving |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Registreer de macroplugin `defineI18nRoute()`, zodat per pagina `defineI18nRoute()`-aanroepen mogelijk zijn. |
| `plugin` | `boolean` | `true` | Registreer de core-i18n-plugin die `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` en andere runtime-helpers biedt. |
| `hooks` | `boolean` | `true` | Registreer de i18n-hooks-plugin die de app-level-hooks `i18n:register` en `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch` biedt. |
| `components` | `boolean` | `true` | Registreer ingebouwde i18n-componenten (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Zet op `false` om automatische registratie uit te schakelen (bijvoorbeeld wanneer je ze niet gebruikt en de module-footprint wilt verkleinen). |
| `types` | `boolean` | `true` | Genereer TypeScript-typedeclaraties voor `useI18n`, `$t` en gerelateerde helpers op basis van de vertaalsleutels in je standaard localebestanden. |
| `debug` | `boolean` | `false` | Schakel uitgebreide debug-logging in voor localedetectie, routegeneratie en het laden van vertalingen. |

## Overig

| Optie | Type | Standaard | Beschrijving |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | Zend ook een kale-taal-`hreflang` uit, afgeleid van de `iso` van elke locale (bijvoorbeeld `es-ES` → ook `es`). De eerste regionale locale in `locales` claimt de kale tag voor die taal. De routing-`code` wordt nooit gebruikt; alleen `iso \|\| code`. |
| `vueDevtools` | `boolean` | `true` | Registreer de Vue DevTools-inspector en -timeline in dev (browserextensie). Los van het aangepaste tabblad van Nuxt DevTools. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Prefix die aan gelokaliseerde routenamen wordt voorgevoegd (bijvoorbeeld `'localized-index'`). Wordt intern gebruikt om originele routes te onderscheiden van gegenereerde locale-varianten. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Uitschakelen van metatags per route, gehaald uit `defineI18nRoute()`-aanroepen. Koppelt een routepad aan `true` (alle meta uitgeschakeld) of aan een array van locale-codes waarvoor meta moet worden uitgeschakeld. |
| `missingWarn` | `boolean` | `true` | Toon console-waarschuwingen wanneer een vertaalsleutel ontbreekt. |
| `hmr` | `boolean` | `true` | Schakel Hot Module Replacement in voor vertaalbestanden in development. Bij `true` veroorzaken wijzigingen aan JSON-vertaalbestanden een automatische reload zonder volledige paginaverversing. |
| `cacheMaxSize` | `number` | `0` | Maximaal aantal invoeren in de in-memory vertaalcache. `0` betekent geen limiet. |
| `cacheTtl` | `number` | `0` | Time-to-live (in seconden) voor gecachte vertaalinvoeren. `0` betekent dat invoeren nooit verlopen. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Benoemde numberformats per locale (Vue I18n-compatibel). Maakt aanroepen als `$tn(1000, 'currency')` mogelijk. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Benoemde datetime-formats per locale (Vue I18n-compatibele `datetimeFormats`). Maakt aanroepen als `$td(date, 'short')` mogelijk. |
| `httpCacheDuration` | `number` | `31536000` | HTTP-`Cache-Control`-max-age (seconden) voor `/\{apiBaseUrl\}/:page/:locale/data.json`. Wordt volledig toegepast zolang `dateBuild` de URL bust (`?v=...`), wat de standaardinstelling is: de response is dan `public, max-age=…, immutable` en veilig voor browsers en CDN's. - `dateBuild: 0`/`''` — de URL is stabiel, dus deze duur wordt *niet* gerespecteerd; de response wordt in plaats daarvan `public, max-age=0, must-revalidate`. Een lange `max-age` op een onveranderlijke URL fixeert de eerste payload die een browser ooit heeft gezien. - `0` — stel helemaal geen `Cache-Control` in (nuttig voor lokale debugging). - Niet toegepast in development (`import.meta.dev`), zodat de browsercache HMR niet dwarsboomt. - Werkt alleen op responses die via Nitro worden geserveerd. Payloads die naar `public/` worden gekopieerd en door het hostingplatform worden geserveerd, krijgen de headers van dat platform. Zie de Performance-gids. Vergelijkbaar met de experimentele `httpCacheDuration` van `@nuxtjs/i18n` (v10.2.0), maar als expliciete response-header in plaats van `defineCachedEventHandler`-maxAge van Nitro. |
| `dateBuild` | `string \| number` | — | Waarde die wordt gebruikt voor cache-busting van vertaal-requests (`?v=...`). Wanneer niet opgegeven, valt de module terug op `Date.now()` (niet-deterministisch). Voor reproduceerbare/rolling deployments stel je dit in op een stabiele waarde (bijvoorbeeld een git-SHA of buildnummer). |
| `experimental` | `Record<string, unknown>` | — | Bucket voor experimentele/onstabiele opties. De inhoud kan zonder aankondiging tussen minor-versies wijzigen of verdwijnen. |
