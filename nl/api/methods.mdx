## 🔍 Vertaalmethoden

Kernmethoden voor het ophalen en beheren van vertalingen.

### `$t`

{/* generated:method:$t — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params?: Params, defaultValue?: string | null) => CleanTranslation
```

Vertaal een sleutel en interpoleer `params` erin. Retourneert `defaultValue` wanneer de sleutel ontbreekt, of de sleutel zelf wanneer er geen standaardwaarde is opgegeven.

{/* /generated:method:$t */}

```typescript
const welcomeMessage = $t('welcome', { username: 'Alice', unreadCount: 5 })
// Uitvoer: "Welcome, Alice! You have 5 unread messages."
```

<Warning>
`$t` retourneert `CleanTranslation`, wat `string | number | boolean | Translations | PluralTranslations | null` is. Als de sleutel naar een **genest object** in je JSON verwijst (bijvoorbeeld `$t('header')` terwijl de JSON `\{ "header": \{ "title": "Hi" \} \}` bevat), zal de retourwaarde dat **object** zijn, geen string. Rechtstreeks gebruik in een Vue-template (<code v-pre>\{\{ $t('header') \}\}</code>) rendert dan als `[object Object]`.

**Zo voorkom je dit:**

- Gebruik een specifiekere sleutel: `$t('header.title')` → `"Hi"`
- Gebruik `$ts()` die altijd een string retourneert (roept `.toString()` aan op niet-strings).
- Gebruik `$t` met een geneste sleutel om bewust sub-objecten programmatisch te benaderen.
</Warning>

### `$ts`

{/* generated:method:$ts — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params?: Params, defaultValue?: string) => string
```

Zoals `$t`, maar retourneert altijd een string: een object- of array-waarde wordt gestringificeerd in plaats van as-is teruggegeven.

{/* /generated:method:$ts */}

```typescript
const welcomeMessage = $ts('welcome', { username: 'Alice', unreadCount: 5 })
// Uitvoer: "Welcome, Alice! You have 5 unread messages."
```

### `$_t` en `$_ts`

{/* generated:method:$_t — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNormalizedLoaded) => (key: string, params?: Params, defaultValue?: string | null) => CleanTranslation
```

Bind `$t` aan een specifieke route om te vertalen buiten de huidige pagina, bijvoorbeeld in een layout die een link naar een andere route rendert.

{/* /generated:method:$_t */}

{/* generated:method:$_ts — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNormalizedLoaded) => (key: string, params?: Params, defaultValue?: string | null) => string
```

Bind `$ts` aan een specifieke route. Zie `$_t`.

{/* /generated:method:$_ts */}

Route-gebonden varianten van `$t` en `$ts`. Ze nemen eerst een **route** en retourneren een vertaalfunctie die aan de locale- en pagina-context van die route is vastgezet.

- **Toegang**: `useNuxtApp()` (ook opnieuw geëxporteerd door `useI18n()` als `$_t` / `$_ts`)

Gebruik ze wanneer de actieve route tijdens SSR of transities verschilt van `router.currentRoute`, bijvoorbeeld binnen `<i18n-t>`, `<i18n-group>`, of wanneer je inhoud rendert voor een specifiek `route`-object.

```typescript
import { useRoute, useNuxtApp } from '#imports'

const route = useRoute()
const { $_t, $_ts } = useNuxtApp()

const $t = $_t(route)
const title = $t('page.title')

// Stringveilige variant
const label = $_ts(route)('page.label')
```


### `$tc`

{/* generated:method:$tc — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params: number | Params, defaultValue?: string) => string
```

Vertaal met meervoudsvorming. `params` kan de count zelf zijn, of een object dat `count` bevat.

{/* /generated:method:$tc */}

**Vertaalformaat**: vormen gescheiden door `|`. Zet placeholders in **elke** vorm:

```json
{
  "apples": "no apples | one apple | {count} apples",
  "cart": "no items for {name} | one item for {name} | {count} items for {name}"
}
```

```typescript
$tc('apples', 0) // "no apples"
$tc('apples', 1) // "one apple"
$tc('apples', 10) // "10 apples"

// count + andere params (tweede argument moet een object zijn)
$tc('cart', { count: 10, name: 'Alice' }) // "10 items for Alice"
```


**Component-alternatief** — `<i18n-t keypath="cart" :plural="count" :params="\{ name \}" />` (voegt `count` intern samen met `params`).


### `$mergeTranslations`

{/* generated:method:$mergeTranslations — do not edit; run `pnpm run docs:generate` */}

```ts
(newTranslations: Translations) => void
```

Voeg vertalingen samen met de actieve locale tijdens runtime en overschrijf wat is geladen.

{/* /generated:method:$mergeTranslations */}

```typescript
$mergeTranslations({
  welcome: 'Bienvenue, {username}!',
})
// Uitvoer: werkt de vertaalcache bij met de nieuwe Franse vertaling
```

### `$resolveTranslations`

{/* generated:method:$resolveTranslations — do not edit; run `pnpm run docs:generate` */}

```ts
() => Translations
```

Elke vertaling die momenteel in het geheugen staat voor de actieve locale en route, als boom.
Alleen-lezen weergave van wat `$t()` op dit moment kan oplossen.

{/* /generated:method:$resolveTranslations */}

```typescript
const tree = $resolveTranslations()
// { aaa: { bbb: 'ccc' }, ddd: 1111 } — hetzelfde woordenboek dat $t() leest
```

Gebruik dit wanneer je het volledige in-memory-woordenboek nodig hebt (DevTools, tests, runtime-editors). Behandel de retourwaarde als alleen-lezen; wijzig waarden via `$setTranslation` of pas patches toe met `$mergeTranslations`.

### `$setTranslation`

{/* generated:method:$setTranslation — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, value: unknown) => void
```

Vervang de waarde bij `key` in het actieve woordenboek. Dit is een vervanging, geen samenvoeging.
Gebruik `$mergeTranslations` wanneer bestaande siblings behouden moeten blijven.

{/* /generated:method:$setTranslation */}

```typescript
$setTranslation('aaa', { fff: 'ggg' }) // vervangt de hele `aaa`-subboom
$setTranslation('aaa', 'text')          // vervangt `aaa` door een string
$setTranslation('ddd', 1111)            // scalar op het hoogste niveau
$setTranslation('aaa.bbb', 'nested')    // dot-notatie-pad
```

Dit is een **vervanging**, geen samenvoeging. Bestaande siblings onder dezelfde sleutel worden verwijderd. Gebruik `$mergeTranslations` om te patchen zonder siblings te verliezen.

### `$setMissingHandler`

{/* generated:method:$setMissingHandler — do not edit; run `pnpm run docs:generate` */}

```ts
(handler: MissingHandler | null) => void
```

Installeer een callback die wordt aangeroepen voor elke niet-opgeloste sleutel. Geef `null` mee om deze te verwijderen.

{/* /generated:method:$setMissingHandler */}

**Typedefinitie**:

```typescript
type MissingHandler = (locale: string, key: string, routeName: string, instance?: unknown, type?: string) => void
```

```typescript
// Stel een aangepaste handler in
$setMissingHandler((locale, key, routeName) => {
  console.error(`Missing translation: ${key} in ${locale} for route ${routeName}`)
  // Verstuur naar Sentry of een andere error-tracking-service
  // Sentry.captureMessage(`Missing translation: ${key}`)
})

// Verwijder de handler
$setMissingHandler(null)
```

**Toepassingen**:

- Ontbrekende vertalingen loggen naar error-tracking-services (Sentry, LogRocket, enzovoort).
- Analytics verzamelen over ontbrekende vertalingen.
- Aangepaste foutafhandeling voor ontbrekende vertaalsleutels.

## 🔢 Getal- en datumformattering

Methoden voor het formatteren van getallen en datums volgens locale-conventies.

### `$tn`

{/* generated:method:$tn — do not edit; run `pnpm run docs:generate` */}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

Formatteer een getal met `Intl.NumberFormat` in de actieve locale. Een sleutel selecteert een benoemde format uit de configuratie.

{/* /generated:method:$tn */}

```typescript
// Inline opties
const formattedNumber = $tn(1234567.89, { style: 'currency', currency: 'USD' })
// "$1,234,567.89"

// Benoemde format (uit nuxt.config i18n.numberFormats)
const price = $tn(1000, 'currency')
const priceDe = $tn(1000, 'currency', 'de')
const compact = $tn(1000, 'currency', { notation: 'compact' })
```

Onbekende benoemde format-sleutels vallen terug op de standaardopties van `Intl.NumberFormat`. In development (client) wordt een `console.warn` uitgezonden wanneer `missingWarn` is ingeschakeld (standaard).

**Configuratievoorbeeld**:

```ts
export default defineNuxtConfig({
  i18n: {
    numberFormats: {
      en: {
        currency: { style: 'currency', currency: 'USD' },
        decimal: { style: 'decimal', minimumFractionDigits: 2, maximumFractionDigits: 2 },
      },
      de: {
        currency: { style: 'currency', currency: 'EUR' },
      },
    },
  },
})
```

**Toepassingen**:

- Getallen formatteren als valuta, percentages of decimalen in het juiste locale-formaat.
- Benoemde formats hergebruiken in de hele app (pariteit met Vue I18n-migratie).

### `$td`

{/* generated:method:$td — do not edit; run `pnpm run docs:generate` */}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

Formatteer een datum met `Intl.DateTimeFormat` in de actieve locale. Een sleutel selecteert een benoemde format uit de configuratie.

{/* /generated:method:$td */}

```typescript
const formattedDate = $td(new Date(), { weekday: 'long', year: 'numeric', month: 'long', day: 'numeric' })
// "Friday, September 1, 2023"

const short = $td(new Date(), 'short')
const longDe = $td(new Date(), 'long', 'de')
```

Onbekende benoemde format-sleutels vallen terug op de standaardopties van `Intl.DateTimeFormat`. In development (client) wordt een `console.warn` uitgezonden wanneer `missingWarn` is ingeschakeld (standaard).

**Configuratievoorbeeld**:

```ts
export default defineNuxtConfig({
  i18n: {
    datetimeFormats: {
      en: {
        short: { year: 'numeric', month: 'short', day: 'numeric' },
        long: { year: 'numeric', month: 'long', day: 'numeric', weekday: 'long' },
      },
    },
  },
})
```

**Toepassingen**:

- Datums tonen in een formaat dat aansluit bij de locale van de gebruiker.
- Short/long/date-time-presets in de hele app delen.

## 🚦 Routeconfiguratie

Methoden om routegedrag en toegangscontrole te configureren.

### `$defineI18nRoute`

{/* generated:method:$defineI18nRoute — do not edit; run `pnpm run docs:generate` */}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

Registreer locale-configuratie en vertalingen per pagina vanuit een component.
Voegt samen met de actieve locale en past opnieuw toe wanneer de locale verandert.

{/* /generated:method:$defineI18nRoute */}

> [!IMPORTANT]
> `$defineI18nRoute` wordt geleverd door de **define-plugin** en is alleen beschikbaar op `useNuxtApp()` — het maakt **geen** deel uit van het return-object van `useI18n()`.
> Destructureer het altijd uit `useNuxtApp()` binnen `script setup`. Het aanroepen van `$defineI18nRoute(...)` als kale global gooit tijdens SSR/prerender `"$defineI18nRoute is not defined"`.

**Parameters**:

- **locales**: `string[] | Record<string, Record<string, string>>` — Beschikbare locales voor de route.
- **localeRoutes**: `Record<string, string>` — Optioneel. Aangepaste routes voor specifieke locales.
- **disableMeta**: `boolean | string[]` — Optioneel. Schakelt i18n-metatags uit voor alle of specifieke locales.

**Basisvoorbeeld**:

```typescript
import { useNuxtApp } from '#imports'

const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'fr', 'de'],
  localeRoutes: {
    en: '/welcome',
    fr: '/bienvenue',
    de: '/willkommen',
  },
  disableMeta: false,
})
```

> 📖 **Voor gedetailleerde gebruiksvoorbeelden, configuratie-indelingen en best practices, zie de [Gids Vertalingen per component](/guides/per-component-translations).**

### `$setI18nRouteParams`

{/* generated:method:$setI18nRouteParams — do not edit; run `pnpm run docs:generate` */}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

Stel parameters per locale in voor de huidige route, zodat een dynamisch segment per taal kan verschillen.
Roep het aan tijdens SSR, voordat de head wordt gerenderd.

{/* /generated:method:$setI18nRouteParams */}

```typescript
// in pages/news/[id].vue
// voor en/news/1-first-article
const { $switchLocaleRoute, $setI18nRouteParams, $defineI18nRoute } = useNuxtApp()
$defineI18nRoute({
  localeRoutes: {
    en: '/news/:id()',
    fr: '/nouvelles/:id()',
    de: '/Nachricht/:id()',
  },
})
const { data: news } = await useAsyncData(`news-${params.id}`, async () => {
  let response = await $fetch("/api/getNews", {
    query: {
      id: params.id,
    },
  });
  if (response?.localeSlugs) {
    response.localeSlugs = {
      en: {
        id: '1-first-article'
      }
      fr: {
        id: '1-premier-article'
      }
      de: {
        id: '1-erster-Artikel'
      }
    }
    $setI18nRouteParams(response?.localeSlugs);
  }
  return response;
});
$switchLocalePath('fr') // === 'fr/nouvelles/1-premier-article'
$switchLocalePath('de') // === 'de/Nachricht/1-erster-Artikel'
```

## 💻 Gebruiksvoorbeelden

### Basis: gebruik in een component

```vue
<template>
  <div>
    <p>{{ $t('key2.key2.key2.key2.key2') }}</p>
    <p>Huidige locale: {{ $getLocale() }}</p>

    <div>
      {{ $t('welcome', { username: 'Alice', unreadCount: 5 }) }}
    </div>
    <div>
      {{ $tc('apples', 10) }}
    </div>

    <div>
      <button v-for="locale in $getLocales()" :key="locale.code" :disabled="locale.code === $getLocale()" @click="() => $switchLocale(locale.code)">
        Wissel naar {{ locale.code }}
      </button>
    </div>

    <div>
      <NuxtLink :to="$localeRoute({ name: 'index' })"> Ga naar Index </NuxtLink>
    </div>
  </div>
</template>

<script setup>
import { useI18n } from '#imports'

const { $getLocale, $switchLocale, $getLocales, $localeRoute, $t, $tc } = useI18n()
</script>
```

### Gebruik met useNuxtApp

```typescript
import { useNuxtApp } from '#imports'

### Gebruik met de useI18n-composable

```

## 🔧 Cache- en utility-methoden

### `$has`

{/* generated:method:$has — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string) => boolean
```

Of een sleutel oplost in de actieve locale. Gebruik het om te vertakken op optionele copy in plaats van een kale sleutel te renderen.

{/* /generated:method:$has */}

Tijdens page-overgangen binnen dezelfde locale voegt v3 automatisch diep vertalingen samen van de vertrekpagina in dit woordenboek totdat de overgang klaar is. Sleutels van de vorige pagina kunnen dus kortstondig nog `true` retourneren. Er is geen `previousPageFallback`-optie; dit gedrag is ingebouwd. Zie [FAQ — page-overgangen](/guides/faq#-why-do-translations-break-during-page-transitions-especially-with-defineasynccomponent).

```typescript
if ($has('welcome')) {
  console.log($t('welcome'))
} else {
  console.log('Key not found')
}
```

### `$clearCache`

{/* generated:method:$clearCache — do not edit; run `pnpm run docs:generate` */}

```ts
() => void
```

Verwijder elke gecachte chunk, op de client en in het actieve woordenboek.

{/* /generated:method:$clearCache */}

**Toegang**: `useNuxtApp().$clearCache`. Gedeclareerd in `NuxtAppOnlyInjections` in plaats van `PluginsInjections`, dus getypeerd maar bewust afwezig in het helper-object van `useI18n()`:

```typescript
const { $clearCache } = useNuxtApp()
// Alle gecachte vertalingen worden verwijderd; de volgende render haalt ze opnieuw op
$clearCache()
```

## 🧭 `useI18nLocale`-composable

De gecentraliseerde composable voor localestate-beheer. Gebruik deze in plaats van rechtstreeks te werken met `useState('i18n-locale')` of `useCookie('user-locale')`.

```typescript
const {
  setLocale, // (locale: string) => void — werkt state + cookie bij
  getLocale, // () => string | null — uit state of cookie
  getPreferredLocale, // () => string | null — gevalideerd tegen locales-lijst
  getEffectiveLocale, // (route, getLocaleFromRoute) => string
  resolveInitialLocale, // (options) => string
  isValidLocale, // (locale) => boolean
  locale, // Ref<string | null> — reactieve state
  localeCookie, // CookieRef — reactieve cookie
  syncLocale, // (locale) => void — alleen naar cookie synchroniseren
  validLocales, // string[] — lijst van geldige locale-codes
} = useI18nLocale()
```

### Belangrijkste methoden

| Methode                 | Beschrijving                                                            |
| ----------------------- | ----------------------------------------------------------------------- |
| `setLocale(locale)`     | Stelt de locale atomair in `useState` én in de cookie in                |
| `getLocale()`           | Retourneert de huidige locale uit state of cookie                       |
| `getPreferredLocale()`  | Retourneert een tegen `locales` gevalideerde locale, of `null`          |
| `isValidLocale(locale)` | Controleert of een locale-code in de geconfigureerde `locales` staat    |

### Gebruik in aangepaste plugins

```typescript
// plugins/i18n-loader.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,
  setup() {
    const { setLocale } = useI18nLocale()
    // Detecteer locale uit headers, domein, enzovoort.
    setLocale('de')
  },
})
```

Zie [Aangepaste taaldetectie](/guides/custom-language-detection) voor uitgewerkte voorbeelden.
