# useI18nLocale

Centraal instappunt voor i18n-localebeheer.
Combineert `useState('i18n-locale')`, locale-cookie en synchronisatie-utilities.

## API

| Eigenschap/methode                                 | Type                                | Beschrijving                                                                          |
| ----------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------ |
| `locale`                                        | `Ref<string \| null>`               | Reactieve locale-state (`useState('i18n-locale')`)                                    |
| `localeCookie`                                  | `Ref`                               | Locale-cookie (wanneer optie `localeCookie` is ingeschakeld)                                |
| `hashCookie`                                    | `Ref`                               | Cookie die wordt gebruikt wanneer `hashMode` actief is                                                |
| `validLocales`                                  | `string[]`                          | Ingeschakelde localecodes uit moduleconfiguratie (sluit `disabled` uit)                        |
| `getLocale()`                                   | `() => string \| null`              | Huidige locale: state → cookie (of hash-cookie in hashmodus)                         |
| `getPreferredLocale()`                          | `() => string \| null`              | Locale uit state/cookie **gevalideerd** tegen `validLocales`, of `null`             |
| `getLocaleWithServerFallback(serverLocale?)`    | `(serverLocale?) => string \| null` | State → cookie → optionele server-context (gebruikt tijdens `no_prefix`-init)              |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string`             | Locale voor het laden van vertalingen: hashmodus geeft voorkeur aan state; anders leest uit route |
| `resolveInitialLocale(options)`                 | `(options) => string`               | Lost locale op: state → `serverLocale` → route; synchroniseert state indien nodig             |
| `setLocale(locale)`                             | `(locale: string \| null) => void`  | Stelt locale in en synct met cookies                                                       |
| `syncLocale(locale)`                            | `(locale: string \| null) => void`  | Synct alleen cookies (geen state-update)                                                  |
| `isValidLocale(locale)`                         | `(locale) => boolean`               | Controleert of string in `validLocales` staat                                                 |

### Opties van `resolveInitialLocale`

```typescript
interface ResolveInitialLocaleOptions {
  route: unknown
  serverLocale?: string | null
  getLocaleFromRoute: (route?: unknown) => string
}
```

Wordt intern gebruikt door de hoofdplugin bij het opstarten. Aangepaste plugins kunnen deze aanroepen bij het implementeren van alternatieve detectieflows.

### `getEffectiveLocale`

```typescript
const { getEffectiveLocale } = useI18nLocale()
const { $getLocale } = useNuxtApp()

const locale = getEffectiveLocale(route, (r) => $getLocale(r))
```

Retourneert de locale die wordt gebruikt om vertalingen te laden en berichten te formatteren voor een gegeven route-object.

## Programmatische localeinstelling

Geef de voorkeur aan `useI18nLocale()` boven direct gebruik van `useState('i18n-locale')`:

```ts
// plugins/i18n-loader.server.ts
import { defineNuxtPlugin } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,

  setup() {
    const { setLocale } = useI18nLocale()
    const detectedLocale = 'ja' // Your detection logic here
    setLocale(detectedLocale)
  },
})
```

<Tip>
`setLocale()` werkt alleen de localevoorkeur bij (state + cookie). Om ook de actieve vertaalcontext op de client te herladen, gebruik `$switchLocale()` van `useNuxtApp()` of `useI18n()`. Dit is vooral belangrijk voor `no_prefix`, waar de URL niet verandert. Zie [FAQ — locale wisselen zonder URL-wijziging](/guides/faq#-switch-locale-without-changing-the-url).
</Tip>
