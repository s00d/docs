# useI18nLocale

## Signature

{/* generated:symbol:useI18nLocale — do not edit; run `pnpm run docs:generate` */}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getLocaleWithServerFallback: (serverLocale?: string | null) => string | null; getPreferredLocale: () => string | null; hashCookie: any; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: any; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Gecentraliseerd instappunt voor localebeheer in i18n.
Combineert useState('i18n-locale'), de locale-cookie en synchronisatie-utilities.

{/* /generated:symbol:useI18nLocale */}

## Gebruik

```vue
<script setup>
const {
  locale,
  localeCookie,
  hashCookie,
  validLocales,
  getPreferredLocale,
  getLocale,
  getLocaleWithServerFallback,
  getEffectiveLocale,
  resolveInitialLocale,
  setLocale,
  syncLocale,
  isValidLocale,
} = useI18nLocale()

// Stel locale in (werkt state en cookies bij)
setLocale('de')

// Haal huidige locale op (state → cookie)
const current = getLocale()

// Haal geldige voorkeurslocale op
const preferred = getPreferredLocale()
</script>
```

## API

| Eigenschap/Methode                              | Type                                | Beschrijving                                                                         |
| ----------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------ |
| `locale`                                        | `Ref<string \| null>`               | Reactieve locale-state (`useState('i18n-locale')`)                                   |
| `localeCookie`                                  | `Ref`                               | Locale-cookie (wanneer de optie `localeCookie` is ingeschakeld)                      |
| `hashCookie`                                    | `Ref`                               | Cookie die wordt gebruikt wanneer `hashMode` actief is                               |
| `validLocales`                                  | `string[]`                          | Ingeschakelde locale-codes uit de moduleconfiguratie (sluit `disabled` uit)          |
| `getLocale()`                                   | `() => string \| null`              | Huidige locale: state → cookie (of hash-cookie in hash-modus)                        |
| `getPreferredLocale()`                          | `() => string \| null`              | Locale uit state/cookie **gevalideerd** tegen `validLocales`, of `null`              |
| `getLocaleWithServerFallback(serverLocale?)`    | `(serverLocale?) => string \| null` | State → cookie → optionele servercontext (gebruikt tijdens `no_prefix`-initialisatie) |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string`             | Locale voor het laden van vertalingen: in hash-modus wint de state; anders uit de route |
| `resolveInitialLocale(options)`                 | `(options) => string`               | Bepaalt de locale: state → `serverLocale` → route; synchroniseert state waar nodig   |
| `setLocale(locale)`                             | `(locale: string \| null) => void`  | Stel locale in en synchroniseer met cookies                                          |
| `syncLocale(locale)`                            | `(locale: string \| null) => void`  | Alleen cookies synchroniseren (geen state-update)                                    |
| `isValidLocale(locale)`                         | `(locale) => boolean`               | Controleert of de string in `validLocales` staat                                     |

### `resolveInitialLocale`-opties

```typescript
interface ResolveInitialLocaleOptions {
  route: unknown
  serverLocale?: string | null
  getLocaleFromRoute: (route?: unknown) => string
}
```

Wordt intern gebruikt door de hoofdplugin bij het opstarten. Aangepaste plugins kunnen dit aanroepen wanneer ze alternatieve detectieflows implementeren.

### `getEffectiveLocale`

```typescript
const { getEffectiveLocale } = useI18nLocale()
const { $getLocale } = useNuxtApp()

const locale = getEffectiveLocale(route, (r) => $getLocale(r))
```

Retourneert de locale die wordt gebruikt om vertalingen te laden en berichten op te maken voor een gegeven route-object.

## Programmatisch locale instellen

Geef de voorkeur aan `useI18nLocale()` boven direct gebruik van `useState('i18n-locale')`:

```ts
// plugins/i18n-loader.server.ts
import { defineNuxtPlugin } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,

  setup() {
    const { setLocale } = useI18nLocale()
    const detectedLocale = 'ja' // Je detectielogica hier
    setLocale(detectedLocale)
  },
})
```

<Tip>
`setLocale()` werkt alleen de localevoorkeur bij (state en cookie). Om ook de actieve vertaalcontext op de client opnieuw te laden, gebruik je `$switchLocale()` uit `useNuxtApp()` of `useI18n()`. Dit is vooral belangrijk voor `no_prefix`, waar de URL niet verandert. Zie [FAQ — locale wisselen zonder de URL te veranderen](/guides/faq#-switch-locale-without-changing-the-url).
</Tip>
