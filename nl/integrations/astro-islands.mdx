Een island draait in de browser, waar de i18n-instantie van de server niet bestaat. Met `@i18n-micro/astro` kiest de pagina de sleutels die een island nodig heeft, geeft ze door als één prop en leest ze in de island via een kleine framework-adapter. Je krijgt `t`, `tc`, `tn`, `td`, `tdr` en `has` in Vue-, React-, Preact- en Svelte-islands, met alleen de gekozen strings in de HTML.

## Installatie {#setup}

Stel eerst de [Astro-integratie en middleware](/nl/integrations/astro-package#setup) in en voeg dan de framework-integratie toe die je gebruikt (`@astrojs/vue`, `@astrojs/react`, `@astrojs/preact`, `@astrojs/svelte`). De island-adapters hebben dat framework nodig als peer: `vue` `^3.3.0`, `react` `^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`, `preact` `^10.0.0 || ^11.0.0` of `svelte` `^4.0.0 || ^5.0.0`.

## Vertalingen doorgeven aan een island {#pass-translations-to-an-island}

```astro
---
// src/pages/index.astro
import { getI18nProps } from '@i18n-micro/astro'
import Counter from '../components/Counter.vue'

const i18n = getI18nProps(Astro, ['counter.title', 'counter.apples'])
---

<Counter client:load i18n={i18n} />
```

`getI18nProps(Astro, keys?)` retourneert `{ locale, fallbackLocale, currentRoute, translations }` (type `I18nClientProps`). Geef de sleutels door die de island gebruikt: elke sleutel wordt op de server opgelost zoals `t()` (route-, root- en fallback-woordenboeken) en alleen gevonden sleutels komen in de HTML. Zonder `keys` wordt alles wat `t()` op deze pagina kan beantwoorden in elke island meegestuurd, dus 2000 root-sleutels zijn ongeveer 100 KB per island; in dev geeft een waarschuwing dat aan boven 20 KB.

Islands vertalen alleen vanuit dat object. `t` retourneert de sleutel voor alles wat niet is doorgegeven, en gekoppelde berichten worden niet opgelost.

## Vue {#vue}

Roep `provideI18n(() => props.i18n)` aan in de rootcomponent van de island en `useAstroI18n()` in de onderliggende componenten. Vue's `inject` ziet geen waarde die door dezelfde component wordt geleverd, dus de hook moet in een kindcomponent draaien, niet in de root:

```vue
<!-- src/components/Counter.vue -->
<script setup lang="ts">
import { provideI18n } from '@i18n-micro/astro/client/vue'
import type { I18nClientProps } from '@i18n-micro/astro'
import CounterBody from './CounterBody.vue'

const props = defineProps<{ i18n: I18nClientProps }>()
provideI18n(() => props.i18n)
</script>

<template><CounterBody /></template>
```

```vue
<!-- src/components/CounterBody.vue -->
<script setup lang="ts">
import { ref } from 'vue'
import { useAstroI18n } from '@i18n-micro/astro/client/vue'

const { t, tc } = useAstroI18n()
const count = ref(0)
</script>

<template>
  <h3>{{ t('counter.title') }}</h3>
  <button @click="count++">{{ tc('counter.apples', count) }}</button>
</template>
```

## React en Preact {#react-and-preact}

```tsx
// src/components/Counter.tsx
import { useState } from 'react'
import { I18nProvider, useAstroI18n } from '@i18n-micro/astro/client/react'
import type { I18nClientProps } from '@i18n-micro/astro'

function Body() {
  const { t, tc } = useAstroI18n()
  const [count, setCount] = useState(0)
  return <button onClick={() => setCount(count + 1)}>{t('counter.title')}: {tc('counter.apples', count)}</button>
}

export default function Counter({ i18n }: { i18n: I18nClientProps }) {
  return (
    <I18nProvider value={i18n}>
      <Body />
    </I18nProvider>
  )
}
```

Importeer voor Preact `I18nProvider` en `useAstroI18n` uit `@i18n-micro/astro/client/preact`; de API is hetzelfde.

## Svelte {#svelte}

```svelte
<!-- src/components/Counter.svelte -->
<script lang="ts">
  import { createI18nStore, useAstroI18n } from '@i18n-micro/astro/client/svelte'
  import type { I18nClientProps } from '@i18n-micro/astro'

  export let i18n: I18nClientProps
  const { t, tc } = useAstroI18n(createI18nStore(i18n))
  let count = 0
</script>

<button on:click={() => count++}>{t('counter.title')}: {tc('counter.apples', count)}</button>
```

`useAstroI18n(store)` retourneert ook de `store` voor `$store`-leesacties in de template.

## Persistente islands {#persisted-islands}

Een island met `transition:persist` krijgt na een navigatie nieuwe props. React, Preact en Vue (met een getter) volgen ze. Houd in Svelte de store vast en geef ze door: `const store = createI18nStore(i18n)`, `const { t } = useAstroI18n(store)`, daarna `$: store.set(i18n)` (met runes: `$effect(() => store.set(i18n))`).

## API {#api}

| Entry | Exports |
| --- | --- |
| `@i18n-micro/astro` | `getI18nProps`, type `I18nClientProps` |
| `@i18n-micro/astro/client/vue` | `provideI18n(props \| () => props)`, `useAstroI18n()` |
| `@i18n-micro/astro/client/react` | `I18nProvider` (prop `value`), `useAstroI18n()` |
| `@i18n-micro/astro/client/preact` | `I18nProvider` (prop `value`), `useAstroI18n()` |
| `@i18n-micro/astro/client/svelte` | `createI18nStore(props)`, `useAstroI18n(store)` |
| `@i18n-micro/astro/client` | de pure `translate`, `hasTranslation`, zonder framework |

Elke `useAstroI18n` retourneert `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `setLocale`, `setRoute` en de `locale`. Een island heeft één samengevoegd woordenboek, dus de `has` ervan is waar voor een sleutel die `t` kan beantwoorden, ook vanuit de fallback-locale; op de server kijkt `has` alleen naar de actieve locale.
