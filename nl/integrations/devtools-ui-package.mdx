`@i18n-micro/devtools-ui` is de vertaaleditor uit het Nuxt DevTools-tabblad, verpakt als webcomponent met een Vite-plugin. Voeg hem toe aan een Vue-, React-, Preact-, Solid- of Astro-project om tijdens development vanuit de browser de JSON-bestanden in je vertalingsmap te bekijken en te bewerken. Nuxt-apps hebben hem al in [Nuxt DevTools](/nl/guide/devtools).

![De DevTools UI: een bestandsboom en een editor met de tekst van de standaardlocale naast elke key](/images/devtools/02-translations-editor-dark.webp)

## Installeren {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/devtools-ui
```

```bash npm
npm install -D @i18n-micro/devtools-ui
```

```bash yarn
yarn add -D @i18n-micro/devtools-ui
```

</CodeGroup>

Geen peer dependencies.

## Instellen {#setup}

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import { i18nDevToolsPlugin } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  plugins: [i18nDevToolsPlugin({ translationDir: 'src/locales' })],
})
```

| Optie | Standaard | Opmerkingen |
| --- | --- | --- |
| `translationDir` | `'src/locales'` | Map met de JSON-bestanden, relatief ten opzichte van de Vite-root. |
| `base` | `'/__i18n_api'` | Basispad van de API-endpoints. |
| `injectButton` | `true` | Voegt een zwevende knop toe aan pagina's die via de `index.html`-transformatie van Vite worden geserveerd. Astro heeft zulke pagina's niet: zie hieronder. |
| `defaultLocale` | eerste localebestand in `translationDir` | Gerapporteerd door `/config`. |
| `fallbackLocale` | `defaultLocale` | Gerapporteerd door `/config`. |

De plugin draait alleen op de devserver (`apply: 'serve'`); een productiebuild bevat er niets van. De knop opent `/__i18n_devtools.html`, die bestanden leest en opslaat via de endpoints van de plugin:

| Endpoint | Doet |
| --- | --- |
| `GET <base>/translations` | elk woordenboek onder `translationDir`, op relatief pad |
| `POST <base>/save` | body `{ file, content }`; overschrijft een bestaand `.json`-bestand binnen `translationDir`, 403 voor al het andere. Maakt nooit een bestand aan |
| `GET <base>/config` | `{ defaultLocale, fallbackLocale, locales, translationDir }`; `locales` komen uit de rootbestanden in `translationDir` |

De endpoints beantwoorden alleen de devtools-pagina: een verzoek van een andere origin of host krijgt een `403`, en `/save` accepteert alleen `application/json` (`415`). De pagina hoort over bestandswijzigingen via de HMR-socket van Vite.

Voeg in Astro de integratie toe in plaats van de plugin. Die voegt een app toe aan de dev toolbar:

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config'
import { i18nDevToolsIntegration } from '@i18n-micro/devtools-ui/vite'

export default defineConfig({
  integrations: [i18nDevToolsIntegration({ translationDir: 'src/locales' })],
})
```

Opslaan schrijft alleen het bestand. Een app die de JSON via Vite importeert, krijgt hem via HMR; gebruik een bridge om bewerkingen direct op de draaiende instantie toe te passen.

## Bridge naar een live instantie {#bridge-to-a-live-instance}

Om de editor in je eigen pagina in te bedden en bewerkingen meteen op de draaiende instantie toe te passen, maak je een bridge vanuit een adapter en geef je die door aan het `<i18n-devtools-ui>`-element:

```ts
import { createBridge, register } from '@i18n-micro/devtools-ui'
import { i18n, locales } from './i18n' // a runtime, React, Preact or Solid instance

register() // defines <i18n-devtools-ui> once

const bridge = createBridge({
  adapter: {
    getRouteCache: () => Object.fromEntries(i18n.storage.translations),
    addTranslations: (locale, content, merge) => i18n.addTranslations(locale, content, merge),
    addRouteTranslations: (locale, route, content, merge) => i18n.addRouteTranslations(locale, route, content, merge),
    subscribe: (cb) => i18n.subscribe(cb),
    getCurrentLocale: () => i18n.locale,
  },
  locales,
  defaultLocale: 'en',
  translationDir: 'src/locales',
})

const el = document.createElement('i18n-devtools-ui') as HTMLElement & { bridge: typeof bridge }
el.bridge = bridge
document.body.append(el)
```

`getRouteCache` moet de woordenboeken teruggeven met keys in de vorm `locale:route` (`en:index`, `en:blog-post`), precies wat `i18n.storage.translations` bevat. Gebruik voor een Vue-instantie `i18n.global.getRouteCache()` en `i18n.global.subscribeToChanges(cb)`.

`saveTranslation` werkt eerst de instantie bij en doet daarna een POST naar `<base>/save`. Als er geen endpoint is (een statische preview-build) of de devserver niet bereikbaar is, wordt de bewerking bewaard in `localStorage`; elke andere fout bij het opslaan herstelt het vorige woordenboek en gooit een fout.
