`@i18n-micro/vitepress` voegt runtime-woordenboeken toe aan een VitePress-site: `$t` en `<I18nT>` in markdown, padhelpers en SEO-tags, gebouwd op [`@i18n-micro/vue`](/nl/integrations/vue-package). Gebruik het wanneer dezelfde UI-strings op veel pagina's voorkomen en je ze niet per locale wilt dupliceren. De locale volgt de eigen padlocales van VitePress (`/`, `/fr/`).

## Wanneer gebruik je het {#when-to-use-it}

| Behoefte | Oplossing |
|------|----------|
| Gedupliceerde `.md`, URL-prefixen | VitePress `locales` |
| Runtime-`$t` / componenten / padsynchronisatie / SEO-head | `@i18n-micro/vitepress` |
| Labels van het standaardthema (`docFooter`, zoek-UI) | Je eigen `themeConfig` per locale |

<Tip>

**Playground** — [`packages/vitepress/playground`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/vitepress/playground) — `pnpm -C packages/vitepress/playground dev`

</Tip>

## Installeren {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vitepress
```

```bash npm
npm install @i18n-micro/vitepress
```

```bash yarn
yarn add @i18n-micro/vitepress
```

</CodeGroup>

Peer dependencies: `vitepress` `>=1.0.0 || >=2.0.0-alpha.0`, `vue` `^3.3.0`. Node-scripts gebruiken `@i18n-micro/node`, dat met het package wordt geïnstalleerd en via `/node` opnieuw wordt geëxporteerd. De gepubliceerde types vereisen Vue 3.5.5 of later met `skipLibCheck: false`; met `skipLibCheck: true`, de gebruikelijke template-instelling, compileren oudere versies ook.

## Installatie {#setup}

```
locales/en.json
locales/fr.json
locales/pages/guide/demo/en.json   # optional page-scoped
locales/pages/guide/demo/fr.json
```

Paginabestanden worden op dezelfde manier aan routenamen gekoppeld als bij Nuxt/Astro (`guide/demo` → `guide-demo`).

### 1. Config — `@i18n-micro/vitepress/config` {#1-config-—-@i18n-micro/vitepress/config}

```ts
// .vitepress/config.mts
import { defineConfig } from 'vitepress'
import { withI18n, buildVitePressLocales } from '@i18n-micro/vitepress/config'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English', og: 'en_US' },
  { code: 'fr', iso: 'fr-FR', displayName: 'Français', og: 'fr_FR' },
]
const defaultLocale = 'en'

export default defineConfig(
  withI18n(
    {
      locales: buildVitePressLocales(locales, defaultLocale),
      // themeConfig.i18nRouting is injected automatically
    },
    {
      locale: defaultLocale,
      defaultLocale,
      locales,
      translationDir: 'locales',
      metaBaseUrl: 'https://example.com', // optional SEO head
    },
  ),
)
```

### 2. Thema — `@i18n-micro/vitepress/theme` {#2-theme-—-@i18n-micro/vitepress/theme}

```ts
// .vitepress/theme/index.ts
import DefaultTheme from 'vitepress/theme'
import { defineI18nTheme } from '@i18n-micro/vitepress/theme'

export default defineI18nTheme(DefaultTheme)
```

De initiële locale wordt vóór de installatie uit het huidige pad gehaald (geen flits van de standaard-locale op `/fr/…`).

### Geavanceerd: handmatige `createI18n` {#advanced-manual-createi18n}

Eén factory voor de client: Vue-plugin + padmethoden + `enhanceApp` (geen aparte exports van routerhelpers).

```ts
import { createI18n, messagesFromGlob } from '@i18n-micro/vitepress'

const i18n = createI18n({
  locale: 'en',
  defaultLocale: 'en',
  locales: [{ code: 'en' }, { code: 'fr' }],
  messages: messagesFromGlob(import.meta.glob('../../locales/*.json', { eager: true })),
})

i18n.localizePath('/guide', 'fr')
// in theme enhanceApp:
i18n.enhanceApp({ app, router })
```

### Node-scripts — `@i18n-micro/vitepress/node` {#node-scripts-—-@i18n-micro/vitepress/node}

Gebruikt `createI18n` / `loadTranslations` van `@i18n-micro/node` (hetzelfde als Astro en de CLI) en koppelt daarna de VitePress-padmethoden met `BaseI18n.extend`:

```ts
import { createI18n } from '@i18n-micro/vitepress/node'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  translationDir: './locales',
  locales: ['en', 'fr'],
  defaultLocale: 'en',
})
await i18n.loadTranslations()
i18n.t('cta.readMore')
i18n.localizePath('/guide', 'fr')
```

Gewone Node zonder paden: `import { createI18n } from '@i18n-micro/node'`.

## Vertalingen in de pagina {#in-page-translations}

Elk VitePress-markdownbestand is een Vue-SFC.

### Globale componenten en `$t` (aanbevolen in markdown) {#global-components-and-$t-recommended-in-markdown}

`createI18n` / `defineI18nTheme` installeren `@i18n-micro/vue`, dat `I18nT` / `I18nLink` / `I18nGroup` / `I18nSwitcher` en `$t` / `$tc` / `$ts` registreert.

```md
{{ $t('cta.readMore') }}

<I18nT keypath="greeting" :params="{ name: 'VitePress' }" />

<I18nLink to="/guide/demo">Demo</I18nLink>
```

### `useI18n` in `<script setup>` {#usei18n-in-<script-setup>}

```md
<script setup>
import { useI18n } from '@i18n-micro/vitepress'
const { t, tc, locale, localePath, switchLocale } = useI18n()
</script>

# {{ t('section.title') }}
```

## Taalmenu {#language-dropdown}

Wanneer `locales` meer dan één item heeft, toont VitePress zijn eigen taalmenu (`VPNavBarTranslations`). `withI18n` koppelt `themeConfig.i18nRouting`, zodat de wereldbol overeenkomt met `<I18nSwitcher>` / de padhelpers.

Gebruik `<I18nSwitcher>` alleen in aangepaste layouts, niet naast de standaardwereldbol.

## SSR-opmerkingen {#ssr-notes}

- De locale bij prerenderen komt uit het URL-pad, niet uit cookies.
- Themacode mag `window` niet aanraken tijdens het importeren.
- Importeer `defineI18nTheme` uit `/theme`, zodat de evaluatie van de Node-config nooit `virtual:i18n-micro/*` laadt.

## API-oppervlak {#api-surface}

| Export | Rol |
|--------|------|
| `createI18n` (`.`) | Client: Vue-plugin + padmethoden + `enhanceApp` |
| `getLocaleFromPath` / `stripSiteBase` / `routeNameFromPath` (`.`) | Handmatige locale-synchronisatie wanneer `syncWithVitePress: false` |
| `createI18n` (`/node`) | Node: `@i18n-micro/node` + padmethoden |
| `defineI18nTheme` (`/theme`) | Thema zonder boilerplate |
| `withI18n` (`/config`) | Config + virtuele modules + optionele SEO |
| `buildVitePressLocales` (`/config`) | VitePress-`locales` bouwen uit `Locale[]` |
| `buildVitePressLocaleHead` (`/config`) | Handmatige SEO-head (ook gebruikt door `metaBaseUrl`) |
| `messagesFromGlob` | Optionele glob → messages-map voor `createI18n` |
| `useI18n` / `I18nT` / … | Opnieuw geëxporteerd uit `@i18n-micro/vue` |
| `BaseI18n.extend` (`@i18n-micro/core`) | Aangepaste methoden koppelen aan elke i18n-instantie |

## Sites in OpenAPI-stijl (integratievastleggingen) {#openapi-style-sites-integration-locks}

Regressiesuite: `packages/vitepress/tests/integration-openapi.test.ts` (diepe paden, `base=/openapi_docs/`, synchronisatie uit + handmatige locale, Node-generators, SEO).

| Patroon | Doe dit |
|---------|---------|
| Diepe `/…/{spec}/{op}`-pagina's, alleen root-UI-JSON | Gebruik bij voorkeur de standaard `syncWithVitePress: true` (behoudt `setRoute('index')` wanneer er geen paginawoordenboek is) **of** `syncWithVitePress: false` + `getLocaleFromPath` |
| Roep nooit `setRoute(deepName)` aan zonder paginawoordenboeken | Root-UI-sleutels verdwijnen tot `setRoute('index')` |
| Generators / `getTranslation` | `createI18n` uit `/node` + `await loadTranslations()` + `i18n.t(key)` (stel `i18n.locale` in) |
| Aangepaste canonical in `transformPageData` | Geef `meta: false` door aan `withI18n` (voorkom dubbele tags) |
| Package-SEO met sitebase | `metaBaseUrl` + VitePress-`base` → absolute URL's bevatten de base |
| Hernoemingen uit oudere package-builds | `withI18nMicro` → `withI18n`, `createVitePressI18n` → `createI18n`, `loadMessages` → node-`createI18n` |
