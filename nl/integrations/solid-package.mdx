`@i18n-micro/solid` geeft SolidJS-apps een i18n-instantie op basis van signals, een provider, `useI18n()` en vier componenten. Gebruik het in een Solid-app die niet met Nuxt is gebouwd. Leesacties van `t()` binnen JSX of effects volgen de locale, de route en de woordenboeken; het gedeelde model staat in [Frameworks](/nl/integrations/overview).

## Installatie {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer dependencies: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (optioneel, alleen voor `@i18n-micro/solid/router`). Solid 2 wordt nog niet ondersteund.

## Setup {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` accepteert `i18n`, `locales`, `defaultLocale` en `routingStrategy`; een weggelaten prop behoudt de waarde van de buitenste provider, inclusief de instantie. `getLocaleName()` en `<I18nSwitcher>` lezen `locales`; zonder die hebben ze niets om te tonen. De opties staan bij [de instantie](/nl/integrations/overview#the-instance). De instantie is die van de [runtime](/nl/integrations/runtime-package), met één signal over zijn store.

## Vertalen {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Roep de methoden aan binnen JSX of een effect zodat Solid ze volgt, ook `localePath` en `getLocale`; een waarde die één keer in de body van de component wordt gelezen, wordt niet bijgewerkt. Volg op de instantie `i18n.locale` en `i18n.currentRoute`: `i18n.getLocale()` blijft gewoon, omdat schrijfacties het lezen. Het lezen van de locale reageert alleen op de locale, dus een effect dat hem leest en een woordenboek laadt, draait één keer. Destructureer geen props en bewaar `t('key')`-resultaten niet in gewone variabelen.

`useI18n()` geeft `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (een accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` en `instance` terug.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Locale wisselen {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Wisselen laadt niets; voeg eerst het woordenboek van de locale toe.

`<I18nGroup>` geeft een `t` met prefix door aan een functie-child. `<I18nT>` en `t()` daarbinnen krijgen geen prefix:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Routing {#routing}

De `@solidjs/router`-adapter staat in een subpad, zodat de hoofd-entry de router nooit importeert. Roep hem aan onder de router, meestal in de `root` van de router, waar `useNavigate` en `useLocation` werken:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

De adapter geeft elke locale behalve de standaard een prefix (`/about`, `/de/about`), en rendert `<I18nLink>` als de `<A>` van de router. `getCurrentPath` leest de reactieve location van de router, zodat actieve links en de switcher die volgen; een aangepaste strategie krijgt hetzelfde door daar een signal te lezen. Let op de volgorde van de argumenten: `(locales, defaultLocale, navigate, location)`. Schrijf voor andere routers een adapter met `getCurrentPath`, `push` en `replace` (alle drie verplicht) — zie [Router-adapter](/nl/integrations/overview#router-adapter).

## SSR {#ssr}

Build voor server-rendering met `vite-plugin-solid`: de `solid`-exportconditie van het package geeft het de broncode, zodat het voor de server compileert. De vooraf gebouwde `dist` is alleen voor de browser. De instantie heeft geen `destroy()`; maak er één per app aan, of één per request op de server, en laat de garbage collector hem opruimen.
