`@i18n-micro/react` en `@i18n-micro/preact` verpakken de framework-onafhankelijke [runtime](/nl/integrations/runtime-package) in een provider, een `useI18n()`-hook en vier componenten. Gebruik ze in een React- of Preact-app die niet met Nuxt is gebouwd. Beide packages hebben dezelfde API; het blok [Preact](#preact) somt de paar verschillen op, en het gedeelde model staat in [Frameworks](/nl/integrations/overview).

## Installatie {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/react
```

```bash npm
npm install @i18n-micro/react
```

```bash yarn
yarn add @i18n-micro/react
```

</CodeGroup>

Peer dependencies: `react` `^18.0.0 || ^19.0.0`; `react-dom` (optioneel, voor rendering); `react-router-dom` `^6.0.0 || ^7.0.0` (optioneel, alleen voor `@i18n-micro/react/router`). Getest op React 19.3 en 18.3, React Router 7.18 en 6.30.

## Setup {#setup}

```tsx
// src/main.tsx
import { createRoot } from 'react-dom/client'
import { createI18n, I18nProvider } from '@i18n-micro/react'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

createRoot(document.getElementById('root')!).render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
    <App />
  </I18nProvider>,
)
```

<Warning>

Maak de instantie één keer aan, op moduleniveau of in een `useState`-initializer, nooit in de body van een component.

</Warning>

`<I18nProvider>` accepteert `i18n`, `locales`, `defaultLocale` en `routingStrategy`:

- Een weggelaten prop behoudt de waarde van een buitenste provider, inclusief de instantie.
- Zonder enige instantie bouwt hij er een uit de `createI18n`-opties ernaast, zodat de props gewone data blijven: `<I18nProvider locale="de" messages={messages}>`.
- Een nieuwe `locale`-prop bouwt een nieuwe instantie met de `messages` van die render. Zo'n instantie leeft in de component: als iets erboven tijdens het mounten suspendt, gooit React hem weg, met alles wat eraan was toegevoegd.

Alle `createI18n`-opties, inclusief `routeMessages`, staan bij [de instantie](/nl/integrations/overview#the-instance).

## Vertalen {#translate}

```tsx
import { useI18n } from '@i18n-micro/react'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' })}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

`useI18n()` geeft terug:

| Groep | Leden |
| --- | --- |
| Vertalen | `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` |
| Locale en route | `locale`, `fallbackLocale`, `currentRoute`, `setLocale`, `setRoute`, `getRoute`, `getLocales`, `defaultLocale()`, `getLocaleName` |
| Routing | `switchLocale`, `localePath`, `localeRoute` |
| Woordenboeken | `addTranslations`, `addRouteTranslations`, `clearCache` |

- De component rendert opnieuw wanneer de locale, de route of een leesbaar woordenboek verandert, en wanneer de provider een nieuw `locales`- of `routingStrategy`-object krijgt. Een woordenboek van een locale die actief noch fallback is, veroorzaakt geen render.
- `t` en de andere vertaalmethoden veranderen alleen met de store, dus ze zijn veilig in `memo` en effect-deps.

`useT` is één string als waarde. De component rendert alleen wanneer die string verandert, wat er ook gebeurt met de andere props van de provider; `<I18nT>` hangt er ook niet van af:

```tsx
const title = useT('page.title')
```

Laad op elk moment meer woordenboeken:

```tsx
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

useEffect(() => {
  import('./locales/de.json').then((m) => addTranslations('de', m.default))
  addRouteTranslations('en', 'about', { title: 'About us' })
  setRoute('about') // t('title') now reads the 'about' dictionary first
}, [])
```

De instantie zelf heeft ook `loadFromUrl(url, { locale, routeName })` voor JSON via `fetch`.

## Locale wisselen {#switch-locale}

```tsx
const { setLocale, switchLocale } = useI18n()

setLocale('de') // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Wisselen laadt niets; voeg eerst het woordenboek van de locale toe. Een schrijfactie naar de store is voor React synchroon, zelfs binnen `startTransition`, dus een component die suspendt op een ontbrekend woordenboek zou zijn fallback tonen. `useLocaleSwitch` laadt eerst en behoudt de oude UI tot het woordenboek binnen is:

```tsx
const [switchTo, pending] = useLocaleSwitch((locale) => i18n.loadFromUrl(`/locales/${locale}.json`, { locale }))

<button disabled={pending} onClick={() => switchTo('de')}>Deutsch</button>
```

De laatste aanroep wint. Een mislukte load wordt rejected en laat de locale zoals hij was.

`<I18nGroup>` geeft een `t` met prefix door aan een render-prop-child. `<I18nT>` en `t()` daarbinnen krijgen geen prefix:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Routing {#routing}

De React Router-adapter staat in een subpad, zodat de hoofd-entry `react-router-dom` nooit importeert. Hij heeft `useLocation()` en `useNavigate()` nodig, dus maak hem aan binnen een component onder de router:

```tsx
// src/App.tsx
import { useMemo } from 'react'
import { BrowserRouter, Route, Routes, useLocation, useNavigate } from 'react-router-dom'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/react'
import { createReactRouterAdapter } from '@i18n-micro/react/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Localized() {
  const location = useLocation()
  const navigate = useNavigate()
  // memoized: a new object on every render re-renders every `useI18n()` consumer
  const routingStrategy = useMemo(() => createReactRouterAdapter(locales, 'en', location, navigate), [location, navigate])
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      <Routes>
        <Route path="/:locale?" element={<Home />} />
        <Route path="/:locale?/about" element={<About />} />
      </Routes>
    </I18nProvider>
  )
}

export default function App() {
  return (
    <BrowserRouter>
      <Localized />
    </BrowserRouter>
  )
}
```

De adapter geeft elke locale behalve de standaard een prefix (`/about`, `/de/about`) en rendert `<I18nLink>` als de `<Link>` van React Router. Zet de locale zelf op basis van de URL (bijvoorbeeld vanuit `useParams().locale` in een effect). Schrijf voor elke andere router een adapter met `getCurrentPath`, `push` en `replace` (alle drie verplicht) — zie [Router-adapter](/nl/integrations/overview#router-adapter).

## SSR {#ssr}

`renderToString` werkt: `useI18n()` heeft een server-snapshot. Maak één instantie per request aan en voeg de woordenboeken ervan toe voordat je rendert, zodat requests in verschillende locales geen state delen, of geef gewone data door aan de provider.

### Hydratatie {#hydration}

Getallen, meervouden en tekst hydrateren zoals ze zijn. Een datum hangt af van de tijdzone en een relatieve datum van de klok: zet `timeZone` op de server en in de browser, en geef de browser voor `tdr` de tijd van de server mee met `now`. `<I18nT>` met `date` of `relativeDate` zet `suppressHydrationWarning`, zodat een verschil de hydratatie niet laat mislukken, maar de tekst van de server blijft staan tot de tekst verandert. Dat werkt maar één niveau diep: `children` die de vertaling in een element verpakken, falen nog steeds bij een verschil, dus geef die dezelfde `timeZone`.

### Server Components {#server-components}

Het package markeert zijn clientcode met `'use client'`. `@i18n-micro/react/server` heeft `createI18n` en een `I18nT` zonder hooks die de instantie als prop accepteert, zodat de tekst buiten de clientbundel blijft. Onder de `react-server`-conditie, zoals in de Next.js-app-router, resolvet de hoofd-entry er ook naar, maar TypeScript weet dat standaard niet: importeer uit `/server`. `@i18n-micro/react/client` geeft altijd de client-entry.

```tsx
// app/[locale]/layout.tsx: a server component
import { cache } from 'react'
import { createI18n, I18nT } from '@i18n-micro/react/server'
import { I18nProvider } from '@i18n-micro/react/client'
import { loadMessages } from './messages'

const getI18n = cache(async (locale: string) => createI18n({ locale, messages: await loadMessages(locale) }))

export default async function Layout({ params, children }) {
  const { locale } = await params
  const i18n = await getI18n(locale)
  return (
    <I18nProvider locale={locale} messages={{ [locale]: i18n.resolveTranslations() }}>
      <h1>
        <I18nT i18n={i18n} keypath="title" />
      </h1>
      {children}
    </I18nProvider>
  )
}
```

Gerenderd via `react-server-dom-webpack`; een Next.js-app zelf is hier niet tegen getest.

## Preact {#preact}

`@i18n-micro/preact` wordt uit dezelfde broncode gebouwd, op Preact zelf, zonder `preact/compat`: dezelfde instantie, provider, hooks en componenten. Verschillen:

| | React | Preact |
| --- | --- | --- |
| Peer dependency | `react` (+ optioneel `react-router-dom`) | `preact` `^10.0.0 \|\| ^11.0.0`, getest op 10.29 en 11.1 |
| Instantieklasse | `ReactI18n` | `PreactI18n` |
| Router-adapter | `createReactRouterAdapter` uit `/router` | `createBrowserHistoryAdapter(locales, defaultLocale, ssrUrl?)` uit `/router` |
| Opnieuw renderen | `useSyncExternalStore` | een layout-effect-subscription die de store opnieuw controleert |
| Server Components | `/server`, `/client` | geen |

`createBrowserHistoryAdapter` werkt met elke router op basis van de History API (wouter, preact-router): `push` en `replace` roepen `history.pushState` / `replaceState` aan en dispatchen `popstate`, en `<I18nLink>` rendert een gewone `<a>` die via `push` navigeert. Een server heeft geen adresbalk: geef de URL van het request door als `ssrUrl`, anders renderen links en de switcher alsof ze op `/` staan. In een browser wint de adresbalk.

```tsx
// src/main.tsx
import { render } from 'preact'
import { createI18n, I18nProvider } from '@i18n-micro/preact'
import { createBrowserHistoryAdapter } from '@i18n-micro/preact/router'
import { App } from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={createBrowserHistoryAdapter(locales, 'en')}>
    <App />
  </I18nProvider>,
  document.getElementById('app')!,
)
```
