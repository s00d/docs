`@i18n-micro/vue` is een Vue 3-plugin met de vertaalkern van Nuxt I18n Micro: reactieve `t()`, globale `$t`, vier componenten en een optionele vue-router-adapter. Gebruik het in een Vite- of SSR-Vue-app die niet met Nuxt is gebouwd. Het instantiemodel, het routercontract en de componentprops worden gedeeld met de andere pakketten en zijn beschreven in [Frameworks](/nl/integrations/overview).

## Installeren {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vue
```

```bash npm
npm install @i18n-micro/vue
```

```bash yarn
yarn add @i18n-micro/vue
```

</CodeGroup>

Peer dependencies: `vue` `^3.3.0`; `vue-router` `^4.5.1 || ^5.0.0` (optioneel, alleen voor `@i18n-micro/vue/router`). De gepubliceerde types vereisen Vue 3.5.5 of later met `skipLibCheck: false`; met `skipLibCheck: true`, de gebruikelijke templateinstelling, compileren oudere versies ook.

## Instellen {#setup}

```ts
// src/main.ts
import { createApp } from 'vue'
import { createI18n } from '@i18n-micro/vue'
import App from './App.vue'
import en from './locales/en.json'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales: [
    { code: 'en', iso: 'en-US', displayName: 'English' },
    { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
  ],
  defaultLocale: 'en',
})

createApp(App).use(i18n).mount('#app')
```

`locales` en `defaultLocale` zijn vereist voor `useI18n()`: zonder deze waarden gooit het `I18nLocalesKey not provided`. Geef ze door aan `createI18n` (zoals hierboven), aan `useI18n({ locales, defaultLocale })`, of via `app.provide(I18nLocalesKey, …)` en `app.provide(I18nDefaultLocaleKey, …)`.

De plugin registreert `I18nT`, `I18nLink`, `I18nGroup` en `I18nSwitcher` globaal en voegt `$t`, `$ts`, `$tc`, `$tn`, `$td`, `$tdr`, `$has` en `$i18n` toe aan templates. Buiten componenten is de instantie `i18n.global`. Andere opties staan bij [de instantie](/nl/integrations/overview#the-instance); `routeMessages` is niet beschikbaar in Vue, gebruik `addRouteTranslations`.

## Vertalen {#translate}

```vue
<script setup lang="ts">
import { useI18n } from '@i18n-micro/vue'

const { t, tc, tn } = useI18n()
</script>

<template>
  <h1>{{ t('greeting', { name: 'Ada' }) }}</h1>
  <!-- Hello, Ada! -->
  <p>{{ tc('apples', 3) }}</p>
  <!-- 3 apples -->
  <p>{{ $t('nav.home') }} · {{ tn(1234.5) }}</p>
</template>
```

`useI18n()` geeft de vertaalmethoden terug (`t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`), `locale` (een schrijfbare computed), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `localePath`, `localeRoute`, `switchLocale`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `mergeTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` en `instance`.

Laad op elk moment meer woordenboeken; elke component die ze leest, wordt opnieuw gerenderd:

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Locale wisselen {#switch-locale}

```ts
const { locale, switchLocale } = useI18n()

locale.value = 'de' // only the locale
switchLocale('de') // the locale, then router.push to the localized current path
```

Laad het woordenboek van de locale vóór of na het wisselen; wisselen haalt zelf niets op.

`<I18nGroup>` geeft zijn slot een `t` met prefix. Keys binnen `<I18nT>` of een gewone `t()` krijgen geen prefix:

```vue
<I18nGroup prefix="profile" v-slot="{ t }">
  <h2>{{ t('title') }}</h2>
  <!-- profile.title -->
</I18nGroup>
```

## Routing {#routing}

De vue-router-adapter staat in een subpath, zodat het hoofdentrypoint `vue-router` nooit importeert:

```ts
// src/main.ts
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import { createI18n } from '@i18n-micro/vue'
import { createVueRouterAdapter } from '@i18n-micro/vue/router'
import App from './App.vue'
import Home from './pages/Home.vue'
import About from './pages/About.vue'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/:locale(de)?', component: Home },
    { path: '/:locale(de)?/about', component: About },
  ],
})

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales,
  defaultLocale: 'en',
  routingStrategy: createVueRouterAdapter(router, locales, 'en'),
})

createApp(App).use(router).use(i18n).mount('#app')
```

`createVueRouterAdapter(router, locales, defaultLocale)` geeft elke locale behalve de standaardlocale een prefix (`/about`, `/de/about`) en rendert `<I18nLink>` als `RouterLink`. Lees de locale zelf uit de route, bijvoorbeeld in `router.beforeEach`, en stel `i18n.global.locale.value` in. Je kunt een adapter ook later koppelen met `i18n.setRoutingStrategy(adapter)`; zie [Routeradapter](/nl/integrations/overview#router-adapter) voor een aangepaste adapter.

## SSR {#ssr}

- Maak de router, de i18n-instantie en de app aan binnen de renderfunctie per verzoek. Eén gedeelde instantie zou de locale van de ene bezoeker naar de andere lekken.
- Gebruik `createMemoryHistory()` op de server, haal de locale uit de URL en laad het bijbehorende woordenboek (en dat van de fallback) vóór `renderToString`.
- Stuur de locale naar de client (bijvoorbeeld in een `window.__STATE__`-script) en maak de clientinstantie aan met dezelfde `locale`, zodat de hydratatie overeenkomt.
- `<I18nSwitcher>` leest `window.location` alleen wanneer de dropdown open is, dus hij rendert op de server.

`packages/vue/playground` bevat een volledig paar `entry-server.ts` / `entry-client.ts`.

## SEO-head {#seo-head}

`useLocaleHead(options)` bouwt `lang`/`dir`-, canonical-, `hreflang`- en `og:locale`-tags op basis van de locales en de routeradapter. Roep `updateMeta()` aan wanneer de route verandert en geef `metaObject` door aan je headmanager:

```ts
import { watch } from 'vue'
import { useRoute } from 'vue-router'
import { useHead } from '@unhead/vue'
import { useLocaleHead } from '@i18n-micro/vue'

const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
watch(() => route.fullPath, () => updateMeta(), { immediate: true })
useHead(metaObject)
```

Opties: `baseUrl` (string of functie), `addDirAttribute` (standaard `true`), `addSeoAttributes` (standaard `true`), `identifierAttribute` (standaard `'id'`), `hreflangBaseLanguage` (standaard `false`). Locales met `disabled: true` of `seo: false` krijgen geen alternate-link.
