`@i18n-micro/node` is de [runtime](/nl/integrations/runtime-package)-instantie plus een loader die een vertaalmap van schijf leest. Gebruik het in een Express- of Fastify-server, een CLI, een e-mail- of PDF-generator, of elk script dat dezelfde JSON-bestanden nodig heeft als je Nuxt-app. Je laadt de bestanden één keer en vertaalt per request zonder veranderlijke state tussen requests te delen.

## Installatie {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/node @i18n-micro/utils
```

```bash npm
npm install @i18n-micro/node @i18n-micro/utils
```

```bash yarn
yarn add @i18n-micro/node @i18n-micro/utils
```

</CodeGroup>

Geen peer dependencies; Node.js `>=20`. `@i18n-micro/utils` is alleen nodig voor de `Accept-Language`-helper hieronder.

## Setup {#setup}

De loader leest de [Nuxt-mapindeling](/nl/guide/translations): `locales/en.json` is een rootwoordenboek, `locales/pages/blog/post/en.json` hoort bij de route `blog-post`.

```ts
import { createI18n } from '@i18n-micro/node'

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

i18n.t('greeting', { name: 'Ada' }) // 'Hello, Ada!'
i18n.t('title', undefined, undefined, 'blog-post') // from locales/pages/blog/post/en.json
```

De opties zijn die van de runtime (zie [de instantie](/nl/integrations/overview#the-instance)) plus `translationDir` en `disablePageLocales` (behandel `pages/**`-bestanden als rootwoordenboeken). `i18n.reload()` wist elk woordenboek en leest de map opnieuw, voor een file watcher in development.

`loadTranslations(dir, disablePageLocales?)` wordt ook los geëxporteerd en geeft `{ root, routes }` terug:

```ts
import { loadTranslations } from '@i18n-micro/node'

const { root, routes } = await loadTranslations('./locales')
// root:   { en: {...}, de: {...} }
// routes: { 'blog-post': { en: {...}, de: {...} } }
```

## Per request {#per-request}

Een instantie bevat één locale en één route. `i18n.locale` wijzigen op een gedeelde instantie binnen een request-handler leidt tot race conditions met gelijktijdige requests. `run` geeft een request een eigen instantie:

```ts
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

// `() => next()`: `run` hands its callback the fork, and Express reads an argument of `next` as an error
app.use((req, res, next) => i18n.run(pickLocale(req), () => next()))

app.get('/', (req, res) => {
  res.send(i18n.t('greeting')) // the request's locale, in everything it awaits
})
```

Binnen `run` leest en zet de gedeelde instantie de locale en route van het request (`AsyncLocalStorage`); de fork start op de huidige route, en `i18n.setRoute(...)` binnen de callback wijzigt de route van dat request. De callback krijgt ook de fork van het request: woordenboeken die daarnaar worden geschreven blijven in het request, woordenboeken die naar de gedeelde instantie worden geschreven bereiken iedereen.

Zonder `AsyncLocalStorage` geeft `i18n.fork(locale)` hetzelfde soort instantie terug om door te geven.

`reload()` leest de map opnieuw; de oude woordenboeken antwoorden tot de nieuwe binnen zijn.

## De locale kiezen {#pick-the-locale}

`detectLocaleFromAcceptLanguage(header, locales)` respecteert `q`-gewichten en matcht `de-DE` met een `de`-locale (en `de` met `de-DE`). Het geeft `null` terug wanneer niets matcht.

```ts
import express from 'express'
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

const app = express()

app.get('/hello', (req, res) => {
  const locale = detectLocaleFromAcceptLanguage(req.headers['accept-language'], locales) ?? 'en'
  const i18n = byLocale.get(locale)!
  res.json({ message: i18n.t('greeting', { name: 'Ada' }) })
})
```

Voor URL-prefix, cookie en header samen past `resolveLocale({ defaultLocale, validLocales, url, cookie, acceptLanguage, autoDetectLanguage: true })` uit `@i18n-micro/utils/resolve-locale` de voorrangsregels van de module toe: URL, dan cookie, dan `Accept-Language`, dan de standaard. Ongeldige waarden worden overgeslagen.

Binnen een Nuxt-app heb je dit package op de server niet nodig: gebruik de [server-side vertalingen](/nl/guide/server-side-translations) van de module.
