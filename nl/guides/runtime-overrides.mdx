# Runtime i18n-overrides

Gebruik deze gids wanneer één build-artefact met verschillende localestandaarden per omgeving moet draaien (bijvoorbeeld: verschillende tenant-instanties).

## Wat kan er tijdens runtime worden overschreven

De module ondersteunt veilige runtime-overrides voor:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Deze overrides worden toegepast bovenop de build-time configuratie uit `.nuxt/i18n.strategy.mjs` en `.nuxt/i18n.config.mjs`.

## Wat kan niet tijdens runtime worden overschreven

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) is een build-time-aangelegenheid omdat het het gegenereerde routegedrag beïnvloedt.

Als je een runtime-strategy-override doorgeeft, wordt deze genegeerd en verschijnt er een waarschuwing.

## RuntimeConfig-gebaseerde overrides

Geef runtime-waarden op onder `runtimeConfig.public.i18nRuntime`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Overrides via omgevingsvariabelen

Je kunt overrides ook via omgevingsvariabelen configureren:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (kommagescheiden, bijv. `fr,it`)

Fallback-aliassen worden ook ondersteund:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Validatieregels

Tijdens runtime valideert de module overrides om een kapotte staat te voorkomen:

- Je kunt niet alle locales uitschakelen.
- `defaultLocale` moet naar een ingeschakelde locale verwijzen.
- `fallbackLocale` moet in de gedeclareerde locales bestaan.

Als een override ongeldig is, houdt de module een veilige waarde aan en logt een waarschuwing.

## Opmerkingen voor multi-instance-deployments

Deze runtime-functie is ontworpen voor localeactivering en -standaarden per instance, zonder opnieuw te bouwen.

Als instances verschillende URL-strategieën vereisen (`no_prefix` versus `prefix`), gebruik dan aparte builds voor elke strategie.

## Uitgeschakelde locales en statische payloads

`runtimeConfig.public.i18nRuntime.disabledLocales` werkt routing, switcher en de Nitro-payload-**handler** bij — maar Nitro serveert bestanden onder `public/` **vóór** die handler.

Als `translationPayloads.publicAssets` (of Node SSR's geforceerde publieke kopie) al `/_locales/\{page\}/\{locale\}/data.json` heeft geschreven, kan een runtime-uitschakeling dat bestand niet verbergen. Geef bij het builden de voorkeur aan `locale.disabled: true` zodat premerge geen statische payloads voor die locale uitstuurt.
