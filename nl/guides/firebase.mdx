# 🔥 Firebase AppHosting-deployment

## 📖 Inleiding

Firebase AppHosting is een krachtig platform voor het deployen van Nuxt-applicaties met serverless-infrastructuur. Bij het deployen van applicaties met `nuxt-i18n-micro` kun je echter specifieke problemen tegenkomen die te maken hebben met hoe vertaal-JSON-bestanden worden geserveerd. Deze gids biedt uitgebreide oplossingen om ervoor te zorgen dat je vertalingen correct werken in productie.

## ⚠️ Veelvoorkomende problemen

### Vertaalbestanden worden niet toegepast

**Symptomen:**

- ✅ Vertalingen werken perfect in ontwikkeling (`nuxt dev`)
- ❌ Na deployment naar Firebase AppHosting laden JSON-bestanden, maar worden vertalingen niet toegepast
- ❌ Er verschijnen geen fouten in de console
- ❌ Vertaalbestanden zijn zichtbaar in het Network-tabblad, maar hebben onjuiste `Content-Type: text/html` in plaats van `application/json`

**Oorzaak:**

Firebase AppHosting (en andere platforms die Nitro-prerendering gebruiken) kunnen prerenderde JSON-bestanden met onjuiste MIME-types serveren. Wanneer de browser JSON-bestanden ontvangt met `Content-Type: text/html`, kan hij ze niet correct parsen, waardoor vertalingen stilletjes falen.

## ✅ Oplossingen

### Oplossing 1: routeregelconfiguratie (aanbevolen)

De meest eenvoudige oplossing is expliciete headers voor vertaalroutes toevoegen in je `nuxt.config.ts`:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      // ... other locales
    ],
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    metaBaseUrl: 'https://your-domain.com',
  },

  // Add route rules for translation files
  routeRules: {
    '/_locales/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600, s-maxage=3600',
      },
    },
  },
})
```

**Voordelen:**

- ✨ Eenvoudige configuratie
- 🚀 Verbetert prestaties met correcte caching
- 🔒 Werkt op alle deploymentplatforms

### Oplossing 2: aangepaste API-base-URL

Als je een aangepaste `apiBaseUrl` gebruikt (alleen padprefix), pas dan de routeregels dienovereenkomstig aan:

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    apiBaseUrl: '/api/translations', // Path prefix only, not a full URL
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },

  routeRules: {
    '/api/translations/**': {
      headers: {
        'Content-Type': 'application/json',
        'Cache-Control': 'public, max-age=3600',
      },
    },
  },
})
```

### Oplossing 3: Firebase-specifieke configuratie

Maak of update je `firebase.json`-bestand in de projectroot:

```json
{
  "hosting": {
    "public": ".output/public",
    "cleanUrls": true,
    "rewrites": [
      {
        "source": "**",
        "function": "server"
      }
    ],
    "headers": [
      {
        "source": "/_locales/**/*.json",
        "headers": [
          {
            "key": "Content-Type",
            "value": "application/json"
          },
          {
            "key": "Cache-Control",
            "value": "public, max-age=3600, immutable"
          },
          {
            "key": "Access-Control-Allow-Origin",
            "value": "*"
          }
        ]
      }
    ]
  },
  "functions": {
    "source": ".output/server"
  }
}
```

## 🔍 Debuggen

### Schakel debug-modus in

Voeg debug-logging toe om problemen te identificeren:

```typescript
export default defineNuxtConfig({
  i18n: {
    debug: true,
    // Your other config...
  },
})
```

Dit geeft gedetailleerde logs over:

- 📝 Vertaalbestanden laden
- 🔄 Cache-operaties
- ⚠️ Laadfouten

### Controleer het Network-tabblad

1. Open DevTools → Network-tabblad
2. Filter op "data.json"
3. Klik op een vertaalbestand-verzoek
4. Verifieer **Response Headers**:
   - ✅ `Content-Type: application/json` (correct)
   - ❌ `Content-Type: text/html` (onjuist — moet worden opgelost)

### Verifieer de prerender-output

Controleer na het builden of vertaalbestanden zijn gegenereerd:

```bash
pnpm build

# Check public payload copy (premerged layout)
ls -la .output/public/_locales/index/en/
# → data.json
```

Je zou `data.json` moeten zien voor elke locale onder elke pagina.

## 🚀 Buildconfiguratie

### Nitro-preset

Zorg voor Firebase AppHosting dat je de juiste preset gebruikt:

```typescript
export default defineNuxtConfig({
  nitro: {
    preset: 'firebase-app-hosting',
    firebase: {
      gen: 2,
      httpsOptions: {
        region: 'us-central1',
        maxInstances: 3,
      },
    },
  },
})
```

### Prerender-configuratie

Configureer prerendering voor optimale prestaties:

```typescript
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/'],
      ignore: ['/api/**', '/admin/**'],
    },
  },
})
```

## ✅ Verificatie-checklist

Verifieer na het toepassen van de fixes dat alles werkt:

- [ ] Build voltooit zonder fouten
- [ ] Vertaal-JSON-bestanden staan in `.output/public/_locales/\{page\}/\{locale\}/data.json`
- [ ] Network-tabblad toont `Content-Type: application/json` voor vertaalbestanden
- [ ] Vertalingen worden correct weergegeven bij het eerste laden van een pagina
- [ ] Geen hydratie-mismatches in de console
- [ ] Taalwisseling werkt correct
- [ ] SEO-metatags worden correct gegenereerd

## 🔄 Deployment-workflow

### 1. Bereid de build voor

```bash
# Install dependencies
pnpm install

# Build for production
pnpm build

# Verify public payload copy
ls -la .output/public/_locales/index/en/data.json
```

### 2. Deploy naar Firebase

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize Firebase (first time only)
firebase init hosting

# Deploy
firebase deploy --only hosting,functions
```

### 3. Verifieer de deployment

1. Bezoek je gedeployde site
2. Open DevTools → Network-tabblad
3. Navigeer naar een pagina
4. Controleer of `/_locales/index/en/data.json` (of je standaardlocale) laadt met:
   - Status: 200
   - Content-Type: application/json
   - Response bevat geldige JSON

## 🔧 Troubleshooting

### Probleem: 404-fouten voor vertaalbestanden

**Oplossing:** Zorg ervoor dat vertaalbestanden worden gekopieerd naar de outputmap:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: {
    publicAssets: [
      {
        dir: 'locales',
        maxAge: 60 * 60 * 24 * 365, // 1 year
      },
    ],
  },
})
```

### Probleem: vertalingen werken op sommige pagina's, maar niet op andere

**Oplossing:** Controleer of pagina-specifieke vertalingen worden gegenereerd:

```bash
# Should show data.json for each page/locale
ls -la .output/public/_locales/index/en/
ls -la .output/public/_locales/about/en/
```

Als pagina-specifieke vertalingen ontbreken, zorg ervoor dat `disablePageLocales` niet is ingesteld op `true`:

```typescript
i18n: {
  disablePageLocales: false, // Ensure this is false
}
```

### Probleem: langzaam laden van vertalingen

**Oplossing:** Optimaliseer caching en preloading:

```typescript
routeRules: {
  '/_locales/**': {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=31536000, immutable',
      'X-Content-Type-Options': 'nosniff'
    },
    prerender: true
  }
}
```

## ⚡ Prestatie-optimalisatie

### Schakel compressie in

Firebase handelt Gzip/Brotli-compressie automatisch af, maar zorg ervoor dat je build geoptimaliseerd is:

```typescript
export default defineNuxtConfig({
  vite: {
    build: {
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: true,
        },
      },
    },
  },
})
```

### Vertalingen lazy laden

`Nuxt I18n Micro` laadt vertalingen automatisch lazy op paginabasis. Vertalingen worden alleen geladen wanneer nodig, wat de initiële bundelgrootte vermindert. Dit is ingebouwde functionaliteit — geen extra configuratie nodig.

Om verder te optimaliseren:

- Gebruik `disablePageLocales: false` (standaard) om pagina-specifieke vertalingen in te schakelen
- Houd root-level vertalingen minimaal
- Gebruik route-specifieke vertaalbestanden voor pagina-inhoud

<Tip>
De module stelt vanaf versie **v3.0.0+** automatisch de juiste `Content-Type`-headers in. Update naar de nieuwste versie als je problemen ondervindt:

```bash
pnpm update nuxt-i18n-micro@latest
```
</Tip>
