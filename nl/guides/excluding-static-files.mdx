# Statische bestanden uitsluiten van i18n-routering

## Overzicht

Standaard sluit nuxt-i18n-micro veelvoorkomende statische bestanden automatisch uit van i18n-routeringsverwerking. Je kunt echter ook aangepaste uitsluitingspatronen configureren om specifieke paden te vrijwaren van verwerking door het i18n-systeem.

## Ingebouwde uitsluitingen

De module sluit automatisch de volgende bestandstypen en patronen uit:

- **Sitemaps**: `/sitemap*.xml`, `/sitemap-en.xml`, enzovoort.
- **SEO-bestanden**: `/robots.txt`, `/favicon.ico`
- **PWA-bestanden**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Statische assets**: Bestanden met extensies als `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Interne Nuxt-paden**: Elk pad dat begint met `__` (zoals `/__nuxt/`)

## Aangepaste uitsluitingspatronen

Je kunt aangepaste uitsluitingspatronen definiëren via de optie `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Aangepaste uitsluitingspatronen
    excludePatterns: [
      // String-patronen (exacte match of prefix)
      '/api/health',
      '/admin',

      // String-patronen met wildcards
      '/api/*',
      '/admin/**',

      // Reguliere expressies
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Patrooncategorieën

### String-patronen

- **Exacte match**: `'/api/health'` — matcht exact `/api/health`
- **Prefixmatch**: `'/admin'` — matcht `/admin` en `/admin/dashboard`
- **Wildcards**: `'/api/*'` — matcht `/api/users` maar niet `/api/users/123`
- **Diepe wildcards**: `'/admin/**'` — matcht `/admin/users` en `/admin/users/123`

### Reguliere expressies

Gebruik RegExp-objecten voor complexe patroonmatching:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API-routes met versies
  /\.(pdf|doc|docx)$/, // Documentbestanden
  /^\/static\//, // Statische map
  /^\/[a-z]{2}\/api\//, // Gelokaliseerde API-routes
]
```

## Toepassingen

### SEO-bestanden

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API-routes

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Beheerpanelen

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Statische assets

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Hoe het werkt

1. **Server-middleware**: Nitro-middleware draait eerst om uitsluitingspatronen te controleren.
2. **Paginaverwerking**: Tijdens route-resolutie worden uitgesloten paden overgeslagen.
3. **Catch-all-route**: De fallback-route controleert uitsluitingen voordat verwerking plaatsvindt.
4. **Prerendering**: Uitgesloten paden worden niet opgenomen in pre-gerenderde routes.

## Impact op prestaties

- Uitsluitingscontroles zijn geoptimaliseerd en draaien vroeg in de request-lifecycle.
- Ingebouwde patronen gebruiken efficiënte regex-matching.
- Aangepaste patronen worden gecached en hergebruikt.
- Minimale prestatie-overhead voor uitgesloten paden.

## Troubleshooting

### Statische bestanden worden nog steeds onderschept

1. **Controleer de patroon-syntax**: Zorg dat je patronen overeenkomen met de exacte padstructuur.
2. **Gebruik regex voor complexe patronen**: String-wildcards hebben beperkingen.
3. **Test patronen**: Gebruik de dev tools van de browser om het werkelijke request-pad te verifiëren.
4. **Controleer de volgorde**: Zorg dat uitsluitingspatronen vóór andere i18n-configuraties worden gedefinieerd.

### Patroon werkt niet

```typescript
// ❌ Fout — dit werkt niet
excludePatterns: ['sitemap.xml']

// ✅ Correct — inclusief de leidende slash
excludePatterns: ['/sitemap.xml']

// ✅ Beter — gebruik regex voor meer flexibiliteit
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Debugmodus

Schakel debugmodus in om de uitsluitingsverwerking te zien:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Dit logt uitsluitingsbeslissingen in de console.

## Migratie vanaf workarounds

Als je workarounds gebruikte zoals routeregels of middleware, kun je die nu vervangen door `excludePatterns`:

```typescript
// ❌ Oude workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ Nieuwe aanpak
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

De nieuwe aanpak is betrouwbaarder en werkt op meerdere niveaus van het routeringssysteem.
