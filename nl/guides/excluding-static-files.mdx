# Statische bestanden uitsluiten van i18n-routing

## Overzicht

Standaard sluit nuxt-i18n-micro veelvoorkomende statische bestanden automatisch uit van i18n-routingverwerking. Je kunt echter ook aangepaste uitsluitingspatronen configureren om te voorkomen dat specifieke paden door het i18n-systeem worden verwerkt.

## Ingebouwde uitsluitingen

De module sluit automatisch de volgende bestandstypen en patronen uit:

- **Sitemaps**: `/sitemap*.xml`, `/sitemap-en.xml`, enz.
- **SEO-bestanden**: `/robots.txt`, `/favicon.ico`
- **PWA-bestanden**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Statische assets**: Bestanden met extensies zoals `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Interne Nuxt-paden**: Elk pad dat met `__` begint (zoals `/__nuxt/`)

## Aangepaste uitsluitingspatronen

Je kunt aangepaste uitsluitingspatronen definiëren via de optie `excludePatterns`:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Patrooncategorieën

### Stringpatronen

- **Exacte match**: `'/api/health'` - komt exact overeen met `/api/health`
- **Prefix-match**: `'/admin'` - komt overeen met `/admin` en `/admin/dashboard`
- **Wildcards**: `'/api/*'` - komt overeen met `/api/users` maar niet met `/api/users/123`
- **Diepe wildcards**: `'/admin/**'` - komt overeen met `/admin/users` en `/admin/users/123`

### Reguliere expressies

Gebruik RegExp-objecten voor complexe patroonherkenning:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Use-cases

### SEO-bestanden

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API-routes

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Beheerderspanelen

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Statische assets

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Hoe het werkt

1. **Server Middleware**: Een Nitro-middleware draait eerst om uitsluitingspatronen te controleren
2. **Paginaverwerking**: Tijdens paginaresolutie worden uitgesloten paden overgeslagen
3. **Catch-all-route**: De fallbackroute controleert uitsluitingen voordat er verwerking plaatsvindt
4. **Prerendering**: Uitgesloten paden worden niet in prerender-routes opgenomen

## Prestatie-impact

- Uitsluitingscontroles zijn geoptimaliseerd en draaien vroeg in de request-levenscyclus
- Ingebouwde patronen gebruiken efficiënte regex-matching
- Aangepaste patronen worden gecachet en hergebruikt
- Minimale prestatie-overhead voor uitgesloten paden

## Troubleshooting

### Statische bestanden worden nog steeds onderschept

1. **Controleer patroonsyntaxis**: Zorg ervoor dat je patronen exact overeenkomen met de padstructuur
2. **Gebruik regex voor complexe patronen**: String-wildcards hebben beperkingen
3. **Test patronen**: Gebruik browser-devtools om het werkelijke request-pad te verifiëren
4. **Controleer volgorde**: Zorg dat uitsluitingspatronen worden gedefinieerd vóór andere i18n-configuratie

### Patroon werkt niet

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Debug-modus

Schakel debug-modus in om uitsluitingsverwerking te bekijken:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Hiermee worden uitsluitingsbeslissingen in de console gelogd.

## Migratie van workarounds

Als je workarounds gebruikte zoals route-regels of middleware, kun je ze nu vervangen door `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

De nieuwe aanpak is betrouwbaarder en werkt op meerdere niveaus van het routingsysteem.
