---
title: "页面配置"
description: "使用 $defineI18nRoute 将页面限制为部分 locale、为其设置自定义路径、内联翻译或禁用 SEO 标签。"
---

`$defineI18nRoute` 在页面内部为单个页面设置 i18n 选项。当页面只存在于部分 locale 中、需要自己的本地化路径、自带少量翻译，或者不能输出 hreflang/canonical 标签时，请使用它。模块会在构建时读取该调用，并将其固化到生成的路由中。

## 将页面限制为部分 locale {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

在默认的 `prefix_except_default` 策略下，只会生成 `/product` 和 `/de/product`；该页面在其他任何 locale 中都没有路由。也可以在 `nuxt.config.ts` 中通过 [`routeLocales`](/cn/api/module-options#routelocales) 进行相同的设置。

`$defineI18nRoute` 是 Nuxt 应用注入，而不是编译器宏：请始终从 `useNuxtApp()` 中获取它，并带 `$` 调用。构建步骤只识别 `$defineI18nRoute(`。

## 添加内联翻译 {#add-inline-translations}

传入对象而不是数组。对象的键是允许的 locale，值会合并到当前 locale 的页面字典中。

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

内联翻译会随页面组件一起为每个 locale 发送。对于超过几个键的内容，建议使用[页面翻译文件](/cn/guide/translations)；内联键适合自包含的页面和组件。

## 设置本地化路径 {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

使用 `prefix_except_default` 和 `defaultLocale: 'en'` 时，这会生成 `/welcome` 和 `/de/willkommen`。在内联 locale 对象中使用 `path` 效果相同：`locales: { de: { path: '/willkommen' } }`。动态参数、嵌套路由以及配置层面的替代方案请参阅[本地化路径](/cn/guide/custom-locale-routes)。

## 关闭 SEO 标签 {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

配置层面的替代方案是 [`routeDisableMeta`](/cn/api/module-options#routedisablemeta)。这些标签的具体内容请参阅 [SEO](/cn/guide/seo) 页面。

## 构建能读取的内容 {#what-the-build-can-read}

构建步骤会在每个页面文件中找到该调用，并在不运行应用的情况下对其参数求值。当配置满足以下条件时可以正常工作：

- 字面量对象（字符串、数组、嵌套对象、模板字符串、基于 `process.env.NODE_ENV` 的三元表达式）；
- 由同一 `<script setup>` 中声明的常量构建（`const locales = ['en', 'de']`，包括展开语法）；
- 带有 `code` 字段的对象数组（`[{ code: 'en' }, { code: 'de' }]`）。

它无法读取从其他模块导入的值，也无法读取任何需要在运行时依赖应用的内容（composable、`await`、获取的数据）。这种情况下，构建会输出 `Ignored the $defineI18nRoute() config in <file>`，页面将保留默认的 locale 和路由。

在运行时，该调用只会合并当前 locale 的内联翻译，并在 locale 变化时重新合并。`locales`、`localeRoutes` 和 `disableMeta` 只通过构建生效，因此修改它们需要重新构建（开发服务器会在保存时重新构建）。
