一个 Nuxt layer 可以为多个应用承载 i18n 配置和 `locales/` 文件夹，每个应用再添加或覆盖自己需要的内容。本页介绍这种用法，以及如何用一次构建服务多个域名。

## 共享配置和翻译 {#share-config-and-translations}

```ts
// base/nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    defaultLocale: 'en',
  },
})
```

```ts
// shop/nuxt.config.ts
export default defineNuxtConfig({
  extends: ['../base'], // a layer directory or package, not a nuxt.config file
  i18n: {
    locales: [
      { code: 'es', iso: 'es-ES' }, // added
      { code: 'fr', disabled: true }, // the base layer's fr, switched off here
    ],
  },
})
```

- **配置：** 应用中的标量选项会替换 layer 中的值。所有 layer 的 `locales` 数组会合并在一起，`code` 相同的条目会合并为一条，且应用的字段优先，因此应用可以添加 locale，或在继承来的 locale 上设置 `disabled: true` 等字段。
- **翻译：** 每个 layer 的 `locales/` 会按键逐一合并，layer 在前、应用在后，因此 `shop/locales/en.json` 中的键会覆盖 `base/locales/en.json` 中的同名键。页面文件（`locales/pages/<page>/`）也以同样方式合并。
- **页面：** 会从每个 layer 的页面中读取 `$defineI18nRoute`。

要合并不属于任何 layer 的文件夹，请将它们列在 [`additionalTranslationDirs`](/cn/api/module-options#additionaltranslationdirs) 中。

## 多域名 {#multiple-domains}

一次构建即可服务所有域名。为每个 locale 列出其域名；`baseDefault` 将其设为该主机的默认 locale：

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    strategy: 'prefix_except_default',
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'de', iso: 'de-DE', baseUrl: 'https://example.de', baseDefault: true },
      { code: 'nl', iso: 'nl-NL', baseUrl: 'https://example.de' },
      { code: 'fr', iso: 'fr-FR' },
    ],
  },
})
```

将两个域名都指向同一台服务器。其余由请求的主机决定：

- **默认 locale：** 该主机的 `baseDefault` locale。如果没有，则在该主机提供构建默认 locale 时使用它，否则使用该主机的第一个 locale。
- **提供的 locale：** 该主机的 locale，加上所有没有 `baseUrl` 的 locale。在 `example.de` 上即为 `de`、`nl` 和 `fr`。
- **其他域名的 locale** 是链接目标。`$localePath`、`$localeRoute`、`$switchLocalePath`、`<i18n-switcher>` 和 `hreflang` 会给出位于其 `baseUrl` 上的绝对 URL，`$switchLocale` 会导航到那里。在当前主机上，它们的 URL 返回 404，cookie 或 `Accept-Language` 也无法选中它们。
- **指向其他域名的链接** 需要通过 `$localePath` 或 `<i18n-link>`：`<NuxtLink :to="$localePath('/contact', 'de')">`、`<i18n-link :to="$localeRoute('/contact', 'de')">`。路由器不接受绝对路径对象，因此 `<NuxtLink :to="$localeRoute(...)">` 和 `router.push($localeRoute(...))` 会停留在当前源。在 `localhost` 或预览主机上，每个带 `baseUrl` 的 locale 都属于这种链接，当前 locale 也不例外。在代码中请使用 `navigateTo($localePath('/contact', 'de'), { external: true })` 或 `$switchRoute`。
- **其他任何主机** 都使用构建配置，所有带 `baseUrl` 的 locale 都作为链接目标。不会回显请求中的任何内容：canonical 和 `hreflang` 使用 `metaBaseUrl`，否则使用构建默认 locale 的 `baseUrl`（没有 `baseUrl` 的默认 locale 需要 `metaBaseUrl` 或 `site.url`，参见 [SEO](/cn/guide/seo#set-the-public-origin)）。
- **`public/` 中的 payload 文件** 是静态的：任何主机都会返回任意 locale 的文件。按域名[生成](/cn/guide/deployment#static-site-(nuxi-generate))则只会发布该域名的文件。

各策略下的 `example.de`，其中 `de: '/kontakt'` 是 `contact` 的自定义路径：

| 策略 | `/` | 默认 locale 的页面 | 其他 URL |
| --- | --- | --- | --- |
| `prefix_except_default` | `de` | `/kontakt` | `/de/kontakt` 和 `/en/contact` 返回 404，`/contact` 重定向到 `/kontakt` |
| `prefix_and_default` | `de` | `/kontakt` 和 `/de/kontakt`，链接使用 `/kontakt` | `/en/contact` 和 `/contact` 返回 404 |
| `prefix` | 重定向到 `/de` | `/de/kontakt` | `/kontakt` 重定向到 `/de/kontakt`，`/en/contact` 返回 404 |
| `no_prefix` | `de` | `/kontakt` | 其他域名上 locale 的自定义路径返回 404 |

在 `prefix` 下，来自其他域名的链接会保留前缀，因为无前缀的 URL 只会被重定向。在 `no_prefix` 下，指向其他域名的链接会落在该主机的默认 locale 上：URL 无法指定第二个 locale。

需要注意的事项：

- **在代理之后**，主机来自 `Host`。如果代理将公共主机放在 `X-Forwarded-Host` 中，请设置 [`trustForwardedHost`](/cn/api/module-options#trustforwardedhost)，并且仅在代理会覆盖该请求头时才这样做。两者都不发送的代理无法服务多域名构建。参见[在代理或 CDN 之后](/cn/guide/deployment#behind-a-proxy-or-cdn)。
- **`app.baseURL`** 也要写进 `baseUrl`：`baseUrl: 'https://example.de/shop'` 搭配 `app.baseURL: '/shop'`。
- **主机必须精确匹配。** `www.example.de` 是另一个主机：请在边缘将其重定向，或在 locale 上设置该 `baseUrl`。每个 locale 只能有一个主机。
- **缓存必须以主机作为键。** CDN 通常会这样做。Nitro 的路由缓存以路径为键，因此在多域名构建中，模块会将 `host` 添加到每条 `swr` 和 `cache` 规则的 `cache.varies` 中，启用 `trustForwardedHost` 时还会添加 `x-forwarded-host`。带 `cache: false` 的规则保持原样。`isr` 使用平台的缓存：请确认它以主机为键。
- **两个主机默认 locale 的自定义路径不能冲突。** 无前缀的路由记录共享同一个路由器，因此 `/x` 不能在 `example.de` 上是一个页面、在 `example.com` 上又是另一个页面。
- **预渲染页面：** `nuxt build` 中带 `prerender: true` 的路由规则只渲染一次，且没有主机，生成的文件会响应所有域名。请将因域名而异的页面交给服务器处理，或[按域名生成](/cn/guide/deployment#static-site-(nuxi-generate))。
- **`noPrefixRedirect`** 在每个主机上都依据该主机和访客的 locale 进行。
- **`hashMode`：** 主机按上述方式选择渲染，指向其他域名的链接会将路由放在 hash 中（`https://example.com/#/contact`）。
- **`ssr: false`：** 浏览器从 `location.host` 读取域名，因此没有服务器的主机也能正常解析。
- **[运行时覆盖](/cn/guide/runtime-overrides)** 最先生效。运行时的 `disabledLocales` 在每个主机上都生效，但有一个例外：在 `prefix_except_default` 和 `prefix_and_default` 下，主机的默认 locale 在其自身主机上保持启用，因为它的页面就是无前缀的路由记录。在 `prefix` 和 `no_prefix` 下，主机会退而使用它提供的下一个 locale。运行时的 `defaultLocale` 只对未知主机生效。

对于[静态站点](/cn/guide/deployment#static-site-(nuxi-generate))，请为每个域名生成一次。

### 每个域名一个应用 {#one-app-per-domain}

当各域名需要不同的页面或模块时，使用一个共享 layer 加上每个域名一个小应用的方式依然可行。每个应用在同一份 `locales` 列表之上设置自己的 `defaultLocale`。与上文相同，其他域名上的 locale 在该应用中返回 404。

### 在代码中选择 locale {#choosing-the-locale-in-code}

如果要用单个实例响应所有域名，并在 SEO 标签中使用请求自身的源，参见 [SEO](/cn/guide/seo#set-the-public-origin)；如果要在代码中根据主机选择 locale，参见[自定义 locale 检测](/cn/guide/custom-auto-detect)。
