title: "Locale 检测"
description: "如何为页面或 API 请求选择 locale：URL、查询参数、状态、cookie、Accept-Language 和默认值，以及访客何时会被重定向。"
---

每个请求都会得到一个 locale，在服务端和浏览器中均按相同的顺序从相同的来源列表中选出。当你需要决定首次访问者落在哪种语言、是否记住他们的选择，以及你的服务端 API 看到什么时，请阅读本文。你将了解优先级、每种策略执行的重定向，以及开启或关闭各个来源的选项。

<Tip>

**前置知识** — [路由策略](/cn/guide/strategy)

</Tip>

## 优先级 {#the-precedence}

第一个给出**已启用** locale 的来源胜出。无效或格式错误的值（未知的代码、损坏的 cookie）会被跳过，由下一个来源决定。

| # | 来源 | 生效条件 |
| --- | --- | --- |
| 1 | URL 前缀（`/de/about`） | 前缀策略。在 `prefix_except_default` 和 `prefix_and_default` 下，无前缀的 URL 即为默认 locale |
| 2 | `?locale=de` | 页面：仅 `no_prefix`。服务端 API 辅助函数：始终生效，且优先于 URL |
| 3 | 应用设置的 locale 状态（`useI18nLocale().setLocale()`） | URL 中没有 locale |
| 4 | Cookie | 设置了 [`localeCookie`](/cn/api/module-options#localecookie)（在 `no_prefix` 下自动为 `'user-locale'`） |
| 5 | `Accept-Language` 请求头 | [`autoDetectLanguage`](/cn/api/module-options#autodetectlanguage) 为 `true`（默认） |
| 6 | [`defaultLocale`](/cn/api/module-options#defaultlocale) | 始终 |

因此在前缀策略下，由 URL 决定页面显示的内容；偏好来源（3–5）只决定访客被**重定向**到哪里，且仅限于 `autoDetectPath` 允许的路径。在 `no_prefix` 下没有可重定向的目标，由偏好来源决定页面显示的内容。

![决策流程：URL 中有 locale 前缀时渲染该 locale。没有前缀时，no_prefix 根据偏好来源渲染，prefix_and_default 渲染默认 locale，prefix 或 prefix_except_default 在 autoDetectPath 允许该路径时按偏好重定向](/images/diagrams/locale-detection.svg)

## 各策略的重定向 {#redirects-per-strategy}

重定向为 `302`，在页面渲染前由服务端执行，客户端导航则由路由中间件执行。查询参数和 hash 会被保留。设置 [`redirects: false`](/cn/api/module-options#redirects) 时不会发生任何重定向；错误的前缀仍会返回 404。

访客偏好 `de`（cookie 或请求头），`defaultLocale: 'en'`，默认 `autoDetectPath: '/'`：

| 请求 | `prefix_except_default` | `prefix` | `prefix_and_default` | `no_prefix` |
| --- | --- | --- | --- | --- |
| `/` | → `/de` | → `/de` | `/`，使用 `en` | `/`，使用 `de` |
| `/about` | `/about`，使用 `en` | → `/de/about` | `/about`，使用 `en` | `/about`，使用 `de` |
| `/fr/about` | `/fr/about` | `/fr/about` | `/fr/about` | — |
| `/en/about` | 404 | `/en/about` | `/en/about` | — |

`prefix_and_default` 从不重定向：无前缀的 URL 属于默认 locale，其他 locale 位于各自的前缀下。在 `prefix_except_default` 下，偏好 `en` 的访客不会从 `/` 被重定向。重定向目标不带尾部斜杠（`/de`，而不是 `/de/`），并遵循自定义路径（`/about` → `/de/ueber-uns`）。

凡是由 cookie 或请求头决定的地方（从 `/` 的重定向、`no_prefix` 下的每个页面），响应都会带有 `Vary: Cookie, Accept-Language`，以便 CDN 区分不同的响应。

### `autoDetectPath` {#autodetectpath}

偏好来源可以将访客移动到哪里：

| 值 | 偏好生效的路径 |
| --- | --- |
| `'/'`（默认） | 仅 `/`。深层链接保持 URL 中的语言 |
| `'no_prefix'` | 所有没有 locale 前缀的路径（`/about` → `/de/about`） |
| `'/welcome'` | 仅该确切路径（忽略尾部斜杠） |
| `'*'` | 所有路径，包括带前缀的路径：当访客偏好 `de` 时，`/about` 和 `/fr/about` → `/de/about` |

- 在不允许的路径上，无前缀的 URL 被视为默认 locale。
- `prefix` 是例外：它没有无前缀的页面，因此 `/about` 始终跳转到访客的 locale（cookie 为 `de` 时跳转到 `/de/about`，没有偏好时跳转到 `/en/about`）。
- 使用 `'*'` 时，服务端会忽略应用的状态，带前缀的 URL 也不再将自身的 locale 记录到 cookie 中；cookie 只在访客通过 `$switchLocale` 切换时改变。

<Warning>

使用 `'*'` 时，分享的链接会以读者的语言打开，这可能会让人感到意外。除非这正是你想要的，否则请优先使用 `'/'` 或 `'no_prefix'`。

</Warning>

## Accept-Language {#accept-language}

该请求头按照 RFC 9110 的定义读取，并与配置中的 locale **代码**进行匹配：

- 按 `q` 值从高到低依次尝试各条目（`fr;q=0.1, de;q=0.9` → `de`）。`q=0` 表示"不要这种语言"；`q` 格式错误的条目会被忽略。`*` 不匹配任何内容。
- `_` 按 `-` 读取（`en_US` = `en-US`）。
- 对每个条目：先匹配确切代码，再匹配较短形式（`de-AT` → `de`），然后匹配同一语言的地区 locale（`en` → `en-US`）。确切形式和较短形式与 `locales` 的顺序无关；当有多个地区匹配时，`locales` 中的第一个胜出。
- 绝不跨文字体系匹配：`zh-TW` 和 `zh-HK` 意味着繁体，`zh-CN` 意味着简体，因此 `zh-CN` 永远不会匹配 `zh-Hant` locale。
- 已禁用的 locale 永远不会被匹配。

```ts
// locales: [{ code: 'en' }, { code: 'de' }, { code: 'zh-Hant' }]
// 'de-CH,de;q=0.9,en;q=0.8'  → 'de'
// 'en-GB'                    → 'en'
// 'zh-TW'                    → 'zh-Hant'
// 'zh-CN'                    → no match, next source
```

使用 `autoDetectLanguage: false` 关闭请求头检测；cookie 和状态仍然有效。

## Cookie {#the-cookie}

- 对于前缀策略，**默认关闭**（`localeCookie: null`）。此时重定向仅依据请求头，且选择不会在多次访问之间被记住。设置 `localeCookie: 'user-locale'` 即可记住它。
- 在 `no_prefix` 下，除非你设置了其他名称，否则它为 `'user-locale'`。`localeCookie: null` 在这里同样会将其关闭。
- 它会在访客切换时写入（`$switchLocale`、`<i18n-switcher>`、`useI18nLocale().setLocale()`），也会在服务端渲染带前缀的页面时写入（`/fr/about` 会存储 `fr`；但在开启重定向且 `autoDetectPath: '*'` 时不会，因为此时 URL 仍可能变化）。客户端导航到某个页面时也会存储该页面的 locale，包括默认 locale 的无前缀页面；而首次加载该 URL 时则不会。在 `no_prefix` 和 hash 模式下，导航只会存储变化。404 不会存储任何内容，除非是 `$switchLocale` 跳转到了 404。
- 有效期为一年（`path=/`、`SameSite=Lax`）。
- 在 `hashMode` 下，偏好改为存储在 `hash-locale` cookie 中；服务端和客户端读取同一个 cookie。服务端渲染该 locale，并且在 `prefix` 之外从不重定向；hash 中的 locale（`/#/de`）优先于它，并在 hydration 之后立即生效。在 `prefix` 下，`/` 上没有页面，因此 `/` 在浏览器中渲染，浏览器先根据 cookie、再根据浏览器语言（`autoDetectLanguage`）跳转到 `/#/de`；任何其他文档（`/about`、`/de`）都会重定向到 hash 中。

请使用 [`useI18nLocale`](/cn/composables/useI18nLocale) 读取和设置偏好，而不要直接使用 `useCookie` 或 `useState`。

## 自定义检测 {#your-own-detection}

如果要自行选择 locale（用户设置、子域名），请在一个先于模块插件运行的插件中调用 `useI18nLocale().setLocale(code)`。它将成为来源 3，即应用的状态。[自定义 locale 检测](/cn/guide/custom-auto-detect)提供了完整的方案，包括如何关闭内置检测。

## 服务端 API 路由 {#server-api-routes}

[`useLocaleServerMiddleware`](/cn/guide/server-side-translations) 和 `useTranslationServerMiddleware` 使用各自的顺序，因为 API URL 很少被本地化：

1. `?locale=`
2. `[locale]` 路由参数，或路径中的 locale 前缀
3. cookie（设置了 `localeCookie` 时）
4. `Accept-Language`（开启 `autoDetectLanguage` 时）
5. `defaultLocale`

`localeCookie: null` 和 `autoDetectLanguage: false` 在这里同样会关闭来源 3 和 4。

## 运行时覆盖 {#runtime-overrides}

[运行时覆盖](/cn/guide/runtime-overrides)会改变来源所匹配的列表：

- 运行时的 `disabledLocales` 会从每个步骤中移除：指向它们的 cookie 或请求头会被跳过。
- 在 `prefix` 和 `no_prefix` 下，运行时的 `defaultLocale` 即为第 6 步。
- 在 `prefix_except_default` 和 `prefix_and_default` 下，默认 locale 在构建时固定（它的页面是无前缀的路由）。运行时的 `defaultLocale`，或禁用构建时的默认 locale，都会被忽略并给出警告。
