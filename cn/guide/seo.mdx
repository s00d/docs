使用 `meta: true`（默认值）时，每个本地化页面都会获得 `<html lang dir>`、canonical 链接、`hreflang` 备用链接、`x-default` 以及 Open Graph locale 标签。当你想设置公开源地址、调整哪些 locale 出现在标签中，或为某个页面覆盖这些标签时，就需要阅读本页。大多数站点只需要 `site.url` 或 `metaBaseUrl` 以及正确的 `iso` 代码。

## 最小配置 {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

此时 `/de/about` 会渲染：

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## 文本方向 {#text-direction}

`<html dir>` 来自 locale 的 `dir`。未设置时，从右向左书写的语言会根据 `iso`（或 `code`）获得 `rtl`：阿拉伯语、希伯来语、波斯语、乌尔都语及其他少数语言，以及任何使用 RTL 书写系统的标签，例如 `az-Arab`。其他所有 locale 都不会获得 `dir` 属性，浏览器会将其视为 `ltr`。

<Warning>

**在大型页面上，`dir: 'auto'` 会增加解析时间** — `<html>` 上的 `auto` 会让浏览器在解析时根据内容推断方向。在 Chromium 中，这一开销的增长速度快于页面规模：5,000 个元素时约 100 ms，20,000 个元素时约 1 s。仅在你无法得知语言的小型页面上使用它。

</Warning>

## 你会得到哪些标签 {#which-tags-you-get}

- **hreflang**：为提供该页面的每个 locale 生成一个标签，值为 `iso`（缺少 `iso` 时为 `code`），其 URL 与 canonical 带有相同的查询参数。通过[页面配置](/cn/guide/per-component-translations)或 `routeLocales` 限制的页面只列出其所属的 locale。[`hreflangBaseLanguage: true`](/cn/api/module-options#hreflangbaselanguage) 还会为第一个地区性 locale 添加纯语言标签（`es-ES` → `es`）。
- **x-default**：默认 locale 的 URL，仅当默认 locale 提供该页面时生成。
- **og:locale**：由 `iso` 推导（`en-US` → `en_US`）。当映射关系不直接时，在 locale 上设置 `og`，例如 `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`；两者都没有时，不会写入 `og:locale`，并且开发模式下会给出警告。
- **canonical / og:url**：不带查询参数的当前 URL，[`canonicalQueryWhitelist`](/cn/api/module-options#canonicalquerywhitelist) 中的参数除外（默认为 `page`、`sort`、`filter`、`search`、`q`、`query`、`tag`）。

按策略区分：

| 策略 | hreflang 和 x-default | canonical、og:url、og:locale、html 属性 |
| --- | --- | --- |
| `prefix`、`prefix_except_default`、`prefix_and_default` | 是 | 是 |
| `no_prefix` | 否（一个 URL 服务所有 locale） | 是 |

## 设置公开源地址 {#set-the-public-origin}

绝对 URL 使用以下来源中的第一个：

1. [`metaBaseUrl`](/cn/api/module-options#metabaseurl)；
2. 来自 `nuxt-site-config`（由 `@nuxtjs/seo` 安装）的 `site.url`；
3. 请求的源地址，并附加 `app.baseURL`。

请固定前两者之一。

<Warning>

请求源地址回退会读取 `X-Forwarded-Host` 和 `X-Forwarded-Proto`，因为 [`metaTrustForwardedHost`](/cn/api/module-options#metatrustforwardedhost) 和 `metaTrustForwardedProto` 默认为 `true`。只有在会覆盖这些请求头的代理之后才是安全的；否则客户端可以自行选择 canonical 链接中的主机，而缓存可能会把该页面传播出去。

如果应用可以被直接访问，请固定 `metaBaseUrl`：与将这两个选项都设为 `false` 不同，它还会忽略伪造的 `Host`。参见[位于代理或 CDN 之后](/cn/guide/deployment#behind-a-proxy-or-cdn)。

</Warning>

当一个部署同时响应多个域名时，这种回退很有用：`https://site-a.com/en/about` 和 `https://site-b.com/en/about` 各自获得自己的源地址。

在 locale 上设置了 `baseUrl` 时，已知主机会使用它自己的 `baseUrl`，优先于 `metaBaseUrl` 和 `site.url`，因此 canonical 和 `og:url` 会保持在该域名上，`hreflang` 则将每个 locale 指向其对应的域名。其他任何主机使用 `metaBaseUrl`，否则使用默认 locale 的 `baseUrl`，再否则使用 `site.url`，因此伪造的 `Host` 无法影响你的标签。如果这些都没有设置，则保留请求源地址回退，并且构建时会给出警告。参见[层与域名](/cn/guide/layers#multiple-domains)。

## 排除 locale 或页面 {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

如果默认 locale 设置了 `seo: false`，则不会写入 `x-default`。要为某个页面关闭这些标签，请在[页面配置](/cn/guide/per-component-translations#turn-off-seo-tags)中使用 `disableMeta`，或在配置中使用 [`routeDisableMeta`](/cn/api/module-options#routedisablemeta)。

## 在单个页面上覆盖标签 {#override-tags-on-one-page}

对于只有部分翻译存在、或 URL 来自 API 的 CMS 内容，请使用 [`useI18nHead`](/cn/composables/useI18nHead) 替换生成的标签：

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` 还可以设置或删除 `canonical`、`xDefault`、`ogLocale` 和 `ogUrl`；`disable` 会删除整组标签（`'hreflang'`、`'x-default'`、`'canonical'`、`'og'`、`'og-alternates'`、`'html'`）。传入 getter，使值在切换 locale 后重新计算。对于按 locale 区分的 slug，请先设置 `$setI18nRouteParams`（[本地化路径](/cn/guide/custom-locale-routes#per-locale-slugs)），生成的备用链接就会直接使用它们。

## 尾部斜杠 {#trailing-slash}

`$localePath`、`$switchLocalePath`、`$switchLocaleRoute` 的路由对象、`<i18n-link>`、`<i18n-switcher>`、locale 重定向以及 SEO URL 都遵循同一条斜杠规则：默认使用 `experimental.defaults.nuxtLink.trailingSlash`，当 i18n 路径需要不同规则时，则使用 i18n 配置中的 [`trailingSlash`](/cn/api/module-options)。

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/)（sitemap、robots、schema.org）通过 `nuxt-site-config` 4+ 与本模块协同工作。请将 `nuxt-i18n-micro` 列在前面，以便站点配置能够读取 locale，并只设置一次 `site.url`——它也会用于上述标签。

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

翻译后的站点名称和描述来自 locale 文件中的 `nuxtSiteConfig.name` / `nuxtSiteConfig.description` 键。错误 `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` 表示 `@nuxtjs/seo` 的版本低于 3；请升级它（[#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)）。
