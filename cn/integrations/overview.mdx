# 集成

`@i18n-micro` 系列包是 Nuxt I18n Micro 面向各种框架和环境的轻量级版本,便于在不同框架中集成。这些包体积小巧,聚焦于核心的国际化能力——基础的翻译特性与常用组件。

## 概述

这些集成包是完整 Nuxt I18n Micro 模块的**精简版**,仅保留国际化所需的必要能力:

- **核心翻译能力** —— 基础翻译方法、复数与格式化
- **必要组件** —— 常见 i18n 场景所需的一小组 UI 组件
- **路由适配器模式** —— 通过适配器抽象实现灵活的路由集成
- **TypeScript 支持** —— 完整类型定义,保证类型安全

与完整的 Nuxt 模块不同,这些包:

- 不包含框架特定的路由逻辑
- 需要你自行实现路由适配器以启用路由功能
- 更关注翻译能力而非框架集成
- 尽可能设计得轻量、框架无关

## 核心组件

所有框架包都包含以下必要组件:

### `<I18nT>`

用于渲染已翻译文本的翻译组件,支持:

- **参数插值** —— 用动态值替换占位符
- **复数** —— 根据数量自动选择复数形式
- **数字格式化** —— 按语言习惯格式化数字
- **日期格式化** —— 格式化日期与相对时间
- **HTML 渲染** —— 可选地将内容作为 HTML 渲染
- **默认值** —— 翻译缺失时提供兜底文本

**示例:**

```vue
<!-- Vue -->
<I18nT keypath="greeting" :params="{ name: 'World' }" />
```

```tsx
// React
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```tsx
// Solid
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

```astro
<!-- Astro -->
<I18nT keypath="greeting" params={{ name: 'World' }} />
```

### `<I18nLink>`

本地化链接组件,可自动处理 URL 中的语言前缀。特性:

- **自动路径本地化** —— 根据路由策略添加或移除语言前缀
- **活动状态检测** —— 高亮当前路由
- **外部链接支持** —— 自动识别并处理外部 URL
- **路由集成** —— 若有可用适配器,则使用其 link 组件
- **自定义样式** —— 支持 active 与 hover 状态

**示例:**

```vue
<!-- Vue -->
<I18nLink to="/about" active-class="active">
  About Us
</I18nLink>
```

```tsx
// React
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```tsx
// Solid
<I18nLink to="/about" activeStyle={{ fontWeight: 'bold' }}>
  About Us
</I18nLink>
```

```astro
<!-- Astro -->
<I18nLink href="/about" class="nav-link">
  About Us
</I18nLink>
```

### `<I18nSwitcher>`

语言切换组件,提供用于切换语言的下拉或列表界面。特性:

- **自动语言列表** —— 根据配置中的语言生成选项
- **高亮当前语言** —— 直观显示当前使用的语言
- **自定义标签** —— 支持为每种语言指定显示名称
- **路由集成** —— 自动跳转到本地化的路径
- **无障碍** —— 提供 ARIA 属性并支持键盘导航

**示例:**

```vue
<!-- Vue -->
<I18nSwitcher />
```

```tsx
// React
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```tsx
// Solid
<I18nSwitcher locales={locales} currentLocale={locale} switchLocale={switchLocale} />
```

```astro
<!-- Astro -->
<I18nSwitcher />
```

### `<I18nGroup>`

用于将翻译分组到共同前缀之下的组件,便于按页面或功能组织翻译。特性:

- **前缀作用域** —— 自动为组内所有键添加前缀
- **嵌套分组** —— 支持嵌套的翻译分组
- **良好的组织性** —— 有助于保持整洁的翻译结构

**示例:**

```vue
<!-- Vue -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

```tsx
// React
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```tsx
// Solid
<I18nGroup prefix="home">
  <I18nT keypath="title" /> {/* Uses "home.title" */}
  <I18nT keypath="description" /> {/* Uses "home.description" */}
</I18nGroup>
```

```astro
<!-- Astro -->
<I18nGroup prefix="home">
  <I18nT keypath="title" /> <!-- Uses "home.title" -->
  <I18nT keypath="description" /> <!-- Uses "home.description" -->
</I18nGroup>
```

## 共享的 `createI18n` 选项 \{#create-i18n-options\}

每个框架包的创建方式相同——只是选项类型的命名会按框架不同而不同(如 `ReactI18nOptions`、`SolidI18nOptions` 等)。选项本身完全一致:

| 属性         | 类型                                                       | 必填 | 默认值          | 说明                                    |
| ---------------- | ---------------------------------------------------------- | -------- | ---------------- | ---------------------------------------------- |
| `locale`         | `string`                                                   | ✅       | -                | 当前语言 code(例如 `'en'`) |
| `fallbackLocale` | `string`                                                   | ❌       | 与 `locale` 相同 | 翻译缺失时的 fallback 语言 |
| `messages`       | `Record<string, Translations>`                             | ❌       | `\{\}`             | 初始翻译消息 |
| `plural`         | `PluralFunc`                                               | ❌       | `defaultPlural`  | 自定义复数函数 |
| `missingWarn`    | `boolean`                                                  | ❌       | `true`           | 翻译缺失时输出控制台警告 |
| `missingHandler` | `(locale: string, key: string, routeName: string) => void` | ❌       | -                | 自定义的缺失翻译处理器 |

除此之外的选项均为框架特定,请参见各包对应的文档页。

## 路由适配器抽象

所有框架包都采用**路由适配器模式**,将 i18n 能力与具体的路由实现解耦。这种设计带来:

- **灵活性** —— 可以使用任意路由库,甚至完全不用路由
- **框架独立** —— 路由逻辑保留在应用中,而非 i18n 包内
- **核心轻量** —— i18n 包保持精简、聚焦

### 实现路由适配器

若要使用路由功能,需要实现 `I18nRoutingStrategy` 接口:

```typescript
interface I18nRoutingStrategy {
  getCurrentPath: () => string
  linkComponent?: Component
  push: (target: { path: string }) => void
  replace: (target: { path: string }) => void
  resolvePath?: (to: string | { path?: string }, locale: string) => string | { path?: string }
  getRoute?: () => { fullPath: string; query: Record<string, unknown> }
}
```

每个包的文档中都包含面向常见路由库的完整适配器示例:

- **Vue**:Vue Router 适配器示例
- **React**:React Router 适配器示例
- **Solid**:Solid Router 适配器示例
- **Astro**:基于文件路由的适配器示例

## 核心特性

所有包共享如下核心特性:

### 翻译方法

- `t()` —— 支持参数插值的基本翻译
- `ts()` —— 始终返回字符串的翻译
- `tc()` —— 支持复数的翻译
- `tn()` —— 数字格式化
- `td()` —— 日期格式化
- `tdr()` —— 相对时间格式化
- `has()` —— 检查翻译键是否存在

### 语言管理

- **语言切换** —— 通过代码切换当前语言
- **fallback 语言** —— 翻译缺失时自动回退
- **按路由的翻译** —— 面向页面的翻译组织方式
- **翻译缓存** —— 兼顾性能的智能缓存

### TypeScript 支持

所有包都提供:

- 完整的 TypeScript 定义
- 类型安全的翻译键(配合类型生成器)
- IDE 中的 IntelliSense 支持
- 编译期错误检查
