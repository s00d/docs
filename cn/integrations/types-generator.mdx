---
title: "类型生成器"
description: "在 Nuxt 或任意 Vite 项目中，根据 JSON 文件为翻译键生成 TypeScript 自动补全。"
---

`@i18n-micro/types-generator` 会读取翻译文件夹中的每个 JSON 文件，并写入一个列出所有键的声明文件。当你希望编辑器在 `t()`、`$t()` 和 `<I18nT keypath>` 中提示键时，请添加它。它既可以作为 Nuxt 模块使用，也可以作为 Vite 或 Rollup 插件使用，并会在文件变化时重新生成。

## 安装 {#install}

<CodeGroup>

```bash pnpm
pnpm add -D @i18n-micro/types-generator
```

```bash npm
npm install -D @i18n-micro/types-generator
```

```bash yarn
yarn add -D @i18n-micro/types-generator
```

</CodeGroup>

对等依赖：`@nuxt/kit` `^3.18.0 || ^4.0.0`。只有 `/nuxt` 入口会导入它；在仅使用 Vite 的项目中可以忽略对等依赖警告。

## Nuxt {#nuxt}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@i18n-micro/types-generator/nuxt'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    translationDir: 'locales',
  },
})
```

该模块会写入 `.nuxt/types/i18n-micro.d.ts`，Nuxt 会将其加入类型上下文；无需手动包含。它读取 `i18nTypes.translationDir`，否则读取 `nuxt-i18n-micro` 读取翻译的位置：每个层中的 `translationDir`（来自 `i18n` 或内联模块选项，默认为 `'locales'`），以及 `additionalTranslationDirs`。在 `nuxi dev` 中编辑该文件夹下的 JSON 文件会重新生成类型。`i18nTypes.outputFile` 在 Nuxt 中会被忽略（会有警告提示）。

## Vite {#vite}

`I18nTypesPlugin` 是一个 Vite 插件，Rollup 也可以使用它。对于其他打包工具，请在脚本中调用 `generateTypes`。

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { I18nTypesPlugin } from '@i18n-micro/types-generator'

export default defineConfig({
  plugins: [
    vue(),
    I18nTypesPlugin({
      srcDir: process.cwd(),
      translationDir: 'src/locales',
      outputFile: 'src/i18n-micro.d.ts',
    }),
  ],
})
```

| 选项 | 必填 | 说明 |
| --- | --- | --- |
| `srcDir` | 是 | 基础目录；`translationDir` 相对于它解析。 |
| `translationDir` | 是 | 包含 JSON 文件的文件夹（包括 `pages/` 等子文件夹），或文件夹数组。 |
| `outputFile` | 否 | 声明文件的写入位置；默认为 `<srcDir>/i18n-micro.d.ts`。 |

插件会在构建开始时生成一次，并在开发服务器上于文件夹发生变化 300 ms 后重新生成。请确保 `tsconfig.json` 的 `include` 覆盖了输出文件。

## 使用键 {#use-the-keys}

生成的文件会扩展 `@i18n-micro/types` 中的 `DefineLocaleMessage`，从而使 `TranslationKey` 变为你的键：

```ts
declare module '@i18n-micro/types' {
  export interface DefineLocaleMessage {
    nav: object
    'nav.home': string
    'profile.title': string
  }
}
```

这些键就是 `t()` 能够响应的键（包括对象），来自每个语言区域和每个页面文件，类型为其 JSON 值的类型。`TranslationKey` 是这些键与任意字符串的联合类型，因此你得到的是自动补全而非错误：拼写错误的键或动态键仍然可以编译。参数和返回值没有类型。

对于已知前缀下的动态键，`ScopedKey<'prefix'>` 会收窄为匹配的键：

```ts
import type { ScopedKey } from '@i18n-micro/types'

const statusText = (status: string) => t(`status.${status}` as ScopedKey<'status'>)
```

`TranslationKey` 和 `ScopedKey` 来自 `@i18n-micro/types`（React、Preact 和 Solid 会重新导出 `TranslationKey`；Vue 不会）。

## API {#api}

| 导出 | 入口 | 说明 |
| --- | --- | --- |
| `I18nTypesPlugin(options)` | `@i18n-micro/types-generator` | Vite 和 Rollup 插件 |
| `generateTypes(options)` | `@i18n-micro/types-generator` | 写入文件，返回其路径 |
| `getTypesString(options)` | `@i18n-micro/types-generator` | 返回声明内容而不写入文件 |
| `formatKeyProperty(key)` | `@i18n-micro/types-generator` | 辅助函数 |
| Nuxt 模块（`configKey: 'i18nTypes'`） | `@i18n-micro/types-generator/nuxt` | 选项 `translationDir` |

完整签名：[包参考](/cn/api/packages/types-generator)。
