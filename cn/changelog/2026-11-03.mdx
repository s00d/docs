**日期**：2026-11-03

**版本**：`v4.0.0`

![v4.0.0 发布](/images/4.0.0.png)

**v4.0.0** 已发布。路由、翻译核心、字典文件、locale 检测以及所有框架包都已重写。选项、`$t`、`$localePath`、`$switchLocale`、组件和组合式函数的名称保持不变。变化的是行为，而其中大多数变化都是已修复的 bug。大多数应用只需少量代码改动，但升级前请阅读[破坏性变更](#breaking-changes)：URL、SEO 标签和框架包 API 在一些地方有所变动。[升级](/cn/guide/upgrade)中包含所有细节。

## 有哪些新功能？ {#what’s-new}

### 一次构建服务所有域名 {#one-build-for-every-domain}

`locales[].baseUrl` 和 `baseDefault` 过去只影响链接。现在它们也会路由请求，适用于全部四种策略以及 `nuxt generate`：

```ts
export default defineNuxtConfig({
  i18n: {
    locales: [
      { code: 'en', baseUrl: 'https://example.com', baseDefault: true },
      { code: 'fr', baseUrl: 'https://example.com' },
      { code: 'de', baseUrl: 'https://example.de', baseDefault: true },
    ],
  },
})
```

- 每个主机提供自己的 locale。指向其他域名 locale 的链接会变成该域名上的绝对 URL，切换到该 locale 会导航到那里。
- `trustForwardedHost` 在会覆盖 `X-Forwarded-Host` 的代理之后从该请求头中获取域名。默认关闭。
- `NUXT_I18N_DOMAIN` 为 `nuxt generate` 指定主机：每个域名运行一次，每份输出只包含该域名的页面和字典。
- 没有 `baseUrl` 的应用不会包含任何这部分代码。

参见 [Layer 与域名](/cn/guide/layers#multiple-domains)和[部署](/cn/guide/deployment)。

### 与路由器保持一致的路由 {#routing-that-agrees-with-the-router}

构建和运行时不再分别计算本地化 URL。所有结果都来自构建生成的路由，因此链接、切换器、`hreflang` 和重定向都不会指向不存在的页面。

- 不提供某个页面的 locale 会链接到自己的首页，而不会链接到其他 locale 的页面。
- `hreflang` 只列出提供该页面的 locale。
- `$switchLocale` 会 resolve 为 `true` 或 `false`，因此你可以知道字典何时加载失败。重复调用会重试。
- 在 SSR 期间设置的 `$setI18nRouteParams` 和 `useI18nHead` 在水合后依然保留。切换器会链接到翻译后的 slug，服务端 HTML 中也是如此。
- 导航在提交（commit）时才生效：被取消或被阻止的导航不会改变任何东西。
- Hash 模式在 `prefix` 下可用。
- 在服务端组件上使用 `<Greeting :locale="$getLocale()" />` 会设置其渲染 locale。

### 统一的 locale 检测 {#one-locale-detection}

在服务端、浏览器、服务端 API 辅助函数和 Astro 中都使用同一种顺序。`Accept-Language` 会遵循 `q` 值，区域匹配不再依赖 `locales` 的顺序，并且永远不会跨越中文书写体系。运行时覆盖现在会作用于路由：`NUXT_I18N_DEFAULT_LOCALE` 和运行时的 `disabledLocales` 会改变实际提供的内容。参见 [Locale 检测](/cn/guide/locale-detection)。

### 所有模式下一致的字典 {#one-dictionary-in-every-mode}

预合并构建、`mode: 'source'` 和开发模式过去在许多页面上给出不同的结果。现在它们会给出相同的字典。

- 每一层级都进行深度合并，回退链（`fr` → `de` → `en`）会一直追溯到底。
- 开发环境中的翻译修改会就地生效，无需重新加载页面。删除的键会消失，根文件的修改会作用于每个页面。
- `$clearCache()` 会重新加载当前页面，并在新文本到达之前保留屏幕上的旧文本。
- 加载失败的 chunk 会保留当前字典，而不是显示原始键。

### 更小的字典文件 {#smaller-dictionary-files}

- 页面文件现在只保存与该 locale 根字典（位于 `__root/<locale>/data.json`）不同的内容。浏览器只加载一次根字典，并将每个页面合并到其上，因此磁盘占用下降，下一个页面的开销只有第一个页面的一小部分。
- 字典 URL 带有版本号。带有当前 `?v=` 的 URL 在 Node 服务器上会被缓存一年，而主机的静态副本返回 `max-age=60`。参见[缓存头](/cn/guide/deployment#cache-headers-and-datebuild)。
- 每个 SSR 页面都会预加载其字典文件，因此它们会与 HTML 同时开始加载。
- 读取失败不再被缓存：下一个请求会重新读取。参见[字典无法读取时](/cn/guide/deployment#when-a-dictionary-cannot-be-read)。

### 更好的 `<i18n-t>`、复数和格式化 {#better-&lt;i18n-t&gt;-plurals-and-formats}

- 插槽可以与 `plural`、`number`、`date` 和 `relativeDate` 一起使用，并且每个 `{name}` 都会被填充，而不只是第一个。
- `<i18n-t>` 在 Nuxt、Vue、React、Preact、Solid 和 Astro 中使用同一个渲染器。
- 以 `=0 ` 开头的第一种形式是显式的零形式，其余形式按 `Intl.PluralRules` 选择：`=0 no apples | one apple | {count} apples`。参见 [`$tc`](/cn/api/methods#$tc)。
- 新增 `timeZone` 选项：在服务端和所有浏览器中显示同一个日历日期。
- `{firstName}`、`{first-name}` 和 `{user.name}` 都是有效的占位符。
- `$tn`、`$td` 和 `$tdr` 与复数一样遵循 `iso`。
- `$tdr` 能给出真正的未来日期：`in 3 days`，或在 `numeric: 'auto'` 时给出 `tomorrow`。

### 默认更安全 {#safer-by-default}

- `<i18n-t html>` 会转义 `params`。只有翻译本身被视为可信标记。
- 不会有链接意外离开当前源：`//host`、`/\host` 和空白值都会留在本站。
- 服务端翻译缓存有上限，因此带有虚构页面名称的 URL 无法让内存持续增长。
- DevTools 的保存端点只接受翻译目录中已存在的 `.json` 文件，并拒绝跨站请求。

### 框架包升级到 2.0 {#framework-packages-at-2-0}

- **React、Preact、Solid：** `I18nT` 接受 `components` prop 用于富文本。新增 `useT` 和 `useLocaleSwitch`，并通过 `@i18n-micro/react/server` 和 `/client` 支持 React Server Components。Preact 不再需要 `preact/compat`。
- **Vue 和 VitePress：** `I18nLink` 会保留 `name`、`query` 和 `hash`，VitePress 会遵循 `base`。
- **Astro：** `i18nIntegration` 会打包你的字典并安装中间件。主入口没有任何 `node:*` 导入，因此可以在边缘运行。`base` 可用。
- **Node 和 runtime：** `fork(locale)` 提供低成本的按请求实例，`@i18n-micro/node` 上的 `run(locale, fn)` 将实例限定在单个请求内。
- **`@i18n-micro/types-generator`：** 没有第三方依赖，并且是一个普通的 Vite 和 Rollup 插件。
- **`@i18n-micro/devtools-ui`：** 通过 Vite 的 socket 实时更新，并提供 Astro 工具栏应用。

### `@i18n-micro/cli` {#@i18n-micro/cli}

CLI 现在作为 `@i18n-micro/cli` 位于 monorepo 中，经过重写后命令从 28 个减少到 16 个，依赖也大幅减少。`check` 取代了 `validate`、`diff` 和 `check-duplicates`，并为 CI 提供 `--json` 和退出码。当无法证明某个键未被使用时，`clean` 不会写入任何内容。参见 [CLI](/cn/guide/cli)。

### 文档 {#documentation}

文档根据代码重写，围绕一条阅读路径展开：安装、第一个翻译页面、翻译文件、路由、检测，然后是任务指南。旧 URL 会重定向。[升级](/cn/guide/upgrade)详细列出了所有变更。

## 速度与体积 {#speed-and-size}

- 服务端渲染直接读取字典，无需本地 HTTP 请求，也无需重复解析。
- `dir="auto"` 不再是默认值。在大型页面上浏览器会在它上面花费大量时间：在包含 20,000 个 `$t` 元素的页面上，Chromium 中的 DOMContentLoaded 从约 980 ms 降到约 115 ms。
- `serverTranslationPreload` 和 `i18n:register` 不再拖慢每个请求。
- 未配置 cookie 时，客户端 bundle 会去掉 `useCookie`，`@i18n-micro/path-strategy` 的体积也只有原来的一小部分。

**测试应用对比 v3.30.3。** 一个生成的 Nuxt 应用，运行在一台 Mac 上的单个 Node 服务器上，使用 `wrk` 以 24 个连接压测 20 秒，轮换进行三轮，基于预发布构建。各行来自不同的运行，因此请在同一行内比较。水合测试两侧均使用 `dir: 'ltr'`。

| 指标 | v3.30.3 | v4.0.0 |
| --- | ---: | ---: |
| 4 个 locale，10k 词条：每秒请求数 | 384-395 | 585-591 |
| 4 个 locale，10k 词条：p95 延迟 | 106-110 ms | 70-72 ms |
| 4 个 locale，10k 词条：每个请求的服务端 CPU | 2.92-3.00 ms | 2.01-2.02 ms |
| 12 个 locale，100k 词条：每秒请求数 | 362-370 | 578-580 |
| 12 个 locale，100k 词条：p95 延迟 | 115-117 ms | 72-73 ms |
| 12 个 locale，100k 词条：每个请求的服务端 CPU | 3.11-3.17 ms | 2.02-2.03 ms |
| 水合，100k 页面 | 86-92 ms | 77-81 ms |
| 该应用的客户端 JS，gzip | 105.1 KB | 93.9 KB |
| 有 `i18n:register` 订阅者时的请求时间，100k chunk | 96-108 ms | 1.7 ms |

在更早的一个预发布构建上，对 100k 词条进行的 30 分钟运行共处理了 113 万个请求，没有任何错误，存活堆内存保持平稳。

**三个生产应用对比 v3.29.5**（它们当时运行的版本），基于预发布构建。其中两个是 SSR 站点，一个是 SPA。每个应用运行在单个 Node 服务器上，60 秒，8 个连接，仅 GET，两轮。构建时间各运行一次。

| 指标 | SSR 应用 1 | SSR 应用 2 | SPA 应用 |
| --- | ---: | ---: | ---: |
| 磁盘上的字典字节数 | 6.37 MB 降至 1.52 MB（-76%） | 4.43 MB 降至 1.52 MB（-66%） | 15.40 MB 降至 1.69 MB（-89%） |
| `.output` 体积 | -22% | -14% | -29% |
| 构建时间 | 27 s 降至 22 s | 23 s 降至 19 s | 41 s 降至 28 s |
| 客户端 JS，gzip | +1.7% | +0.9% | +0.5% |
| 每秒请求数 | 82 到 88 | 237 到 240，在误差范围内 | 233 到 404，仅 SPA 外壳 |

**客户端 JS。** 包含自身代码的真实应用会略有增加，如上所示。共享的修复也让框架包有所增大，在另一个预发布构建上用最小体积的 Vue、React、Preact 和 Solid 应用测得：gzip 后增加约 1.4 KB 到 2.5 KB。React、Preact 和 Solid 还包含共享的富文本渲染器。

**字典请求。** 首次加载现在需要两个文件：根文件和页面文件。其字节数保持不变（在两个 SSR 应用上分别对 103 次和 89 次首次加载测得 +0.3%）。同一文档中的下一个页面只需一个小文件：在测量的两个页面上分别从 gzip 4.7 KB 降至 1.5 KB，以及从 gzip 5.9 KB 降至 0.5 KB。在 SPA 的一次登录后浏览中，字典字节数下降了 21%。

**边缘环境。** 在一个小型演示应用上，基于预发布构建，Cloudflare Worker 上传体积从 gzip 241.5 KiB 增加到 250.3 KiB。嵌入 Edge bundle 的字典使用相同的根文件和页面文件，但我们尚未在大型词条库上测量这种嵌入。

## 破坏性变更 {#breaking-changes}

### 环境要求 {#requirements}

- **Nuxt 3.18 或更高版本**，以及 **Node 20 或更高版本**。
- **`@i18n-micro/test-utils`** 不再随模块一起安装。如果你的测试导入了它，请自行添加。
- **`@i18n-micro/hmr`** 已移除：翻译 HMR 已内置。如果安装过该包，请将其移除。
- **`@i18n-micro/react`** 需要 React 18 或更高版本。
- **`nuxt-i18n-micro-cli`** 已被 `@i18n-micro/cli` 取代。

### 选项与配置 {#options-and-config}

- `dependsOn` 中的 `i18n-plugin-hooks` 和 `i18n-plugin-define` 不再等待任何东西，也不会报错。请使用 `i18n-plugin-loader`。
- 服务端自动导入的是 `useLocaleServerMiddleware`、`useTranslationServerMiddleware`、`loadTranslationsFromServer` 和 `detectCurrentLocale`。其他函数不再自动导入。
- `resolveTranslationPayloadMode` 和其他 `resolveTranslationPayload*` 辅助函数已从 `nuxt-i18n-micro` 中移除，`shouldCopyTranslationPayloadsToPublic` 和 `shouldRegisterNitroServerAssets` 也一并移除。`TranslationPayloadMode` 类型保留。
- `$getI18nConfig()` 不再包含 `isSSG`、`hmr`、`hooks`、`noPrefixRedirect`、`routeLocales`、`routeDisableMeta` 或 `globalLocaleRoutes`。这些选项本身没有变化。
- `locales[].baseUrl` 现在会路由请求：其他域名的 locale 在当前主机上返回 404，同一主机上的链接为相对链接。在这类构建中，`$getI18nConfig().locales` 保存当前主机提供的 locale，`linkLocales` 保存全部 locale。
- `baseUrl` 也会在其他任何主机上设置源：canonical 和 `hreflang` 在设置了 `metaBaseUrl` 时使用它，否则使用默认 locale 的 `baseUrl`，而不是请求的源。
- `excludePatterns` 按完整路径段匹配（`'/admin'` 不再匹配 `/administrator`），glob 会锚定，`RegExp` 模式现在也会作用于运行时。
- 未设置 `cacheMaxSize` 时，服务端最多保存 1000 个条目。`cacheTtl` 从条目存入时开始计时，读取不再延长它。
- 在 `no_prefix` 下，`i18n` 配置中显式设置的 `localeCookie: null` 会保持关闭。
- 在 `prefix_except_default` 和 `prefix_and_default` 下，运行时的 `defaultLocale` 会被忽略并输出警告。运行时的 `fallbackLocale` 必须是已启用的 locale。
- `nuxt.config` 中的 `routeDisableMeta` 会被遵循，并且无论使用哪种键形式，`nuxt.config` 中的条目都优先于 `$defineI18nRoute`。
- 在开发环境的服务端，解析后的配置会被冻结：写入会抛出错误。
- 对于相同的 `code`，项目的 `locales` 条目优先于 layer 的条目。

### 组合式函数与 `$` 方法 {#composables-and-$-methods}

- `$switchLocale` 会 resolve 为 `true` 或 `false`，以前不返回任何值。`$switchRoute` 的类型为 `Promise<void>`。
- `$localeRoute`、`$switchLocalePath` 和切换器会将不提供某页面的 locale 链接到该 locale 的首页。
- `$localePath` 会原样返回带有 `http(s):`、`mailto:` 或 `tel:` 协议的字符串，`$localeRoute` 会将其放在 `path` 和 `fullPath` 中。不要将未经检查的值作为链接目标传给它们。`//host` 以及 `x.com` 这样的裸名称会作为当前源上的路径保留。
- 没有路径的链接会停留在当前页面：`$localePath('#top')`、`'?p=2'`、`''` 和 `{ query }`。`'#top'` 以前会从站点根目录解析。单独的 `'about'` 仍然表示 `/about`。
- `$switchRoute` 会停留在应用内。只有 locale 自身的 `baseUrl`、`mailto:` 和 `tel:` 会离开应用。
- 指向带 `baseUrl` 的 locale 的链接需要通过 `$localePath` 或 `<i18n-link>`。`<NuxtLink :to="$localeRoute(x, 'fr')">` 和 `router.push($localeRoute(x, 'fr'))` 会作为本应用的路径保留。在代码中请使用 `navigateTo($localePath(x, 'fr'), { external: true })`。
- `$switchLocaleRoute` 和重定向会遵循 `trailingSlash`。
- 在服务端设置的 `$setI18nRouteParams` 和 `useI18nHead` 会在导航改变路径时被丢弃，包括从 `/news/1` 到 `/news/4`：请在新页面上重新设置。
- 在 setup 中读取的 `$setI18nRouteParams` 绑定到该页面：已离开页面的延迟调用不会产生任何效果。它没有 setter，因此请在测试中直接 stub `useI18n`。
- `useI18n()` 每个应用返回同一个对象。对它的写入会影响所有调用方。
- 字典、locale、参数和 head 会在导航提交时改变。`beforeResolve`、`beforeRouteEnter` 或之后的全局守卫看到的是旧值。路由中间件不受影响。
- 在 URL 类策略下，当 `$switchLocale` 的导航被取消时，它会恢复已存储的 locale。
- `$t` 会对 `defaultValue` 进行插值：`$t('missing', { n: 1 }, 'Got {n}')` 得到 `Got 1`。`$tc` 也是如此，并且在翻译为空时返回 `''`。
- `$has(key, route)` 会遵循 route 参数。
- `$clearCache()` 会重新加载当前页面的字典。
- `{param}` 占位符只读取你传入的参数：`{constructor}` 会原样保留。
- `$tc` 在数量为负数、小数或极大值时会选择最后一种形式，并使用真实数量。`{ count: null }` 不再抛出错误，缺失的复数键会交给缺失处理函数。
- `$tdr` 对无效输入返回 `Invalid Date`。过去不到一秒的时间为 `0 seconds ago`。
- `$tn`、`$td` 和 `$tdr` 遵循 `iso`：`{ code: 'en', iso: 'en-GB' }` 会将日期格式化为 `31/10/2026`。`Intl` 不认识的代码会按 `en` 格式化，复数则按索引规则处理：请设置 `iso`（`{ code: 'ua', iso: 'uk-UA' }`）。
- `detectCurrentLocale` 已弃用：请使用 `useLocaleServerMiddleware(event).current`。

### 复数 {#plurals}

模板保持原有含义，只有一个例外。如果模板是一个不含占位符的零形式，后面每个类别各一种形式，且多个数量共用的每种形式中都含有 `{count}`，那么在具有三个或更多类别的 locale（`ru`、`uk`、`pl`、`cs`、`ar` 等）中，现在会按类别选择：在 `uk` 中，`none | {count} one | {count} few | {count} many` 会给出 `3 few` 和 `21 one`。要在其他模板中使用类别，请添加 `=0 ` 标记。自定义 `plural` 规则读取的是原始值，因此带标记的模板传给它时会保留 `=0 `。参见[升级中的表格](/cn/guide/upgrade#plurals-and-formatting)。

### 组件 {#components}

**`<i18n-t>`**

- `html` 在所有情况下都会转义 `params`，并忽略所有插槽。
- 插槽优先于同名参数。
- 对于 `plural`、`number`、`date` 和 `relativeDate`，`null` 表示未设置。
- `plural` 像 `$tc` 一样使用 `Number` 计数：`1.5` 保持为 `1.5`，`"2 items"` 为 `NaN`，`""` 为 `0`。
- `number`、`date` 和 `relativeDate` 会保留 `params`。
- `hideIfEmpty` 在每个分支中都生效，`defaultValue` 在每个分支中都会替代缺失的键。
- `html` 下缺失的键会作为转义文本输出。
- `date` 和 `relativeDate` 的输出带有 `data-allow-mismatch="text"`，在命名插槽旁边时文本会放在单独的 `<span>` 中。
- `.innerHTML` 和 `textContent` 属性会被丢弃。
- 它是一个函数式组件：在其上使用 `ref` 不会得到实例。
- `<i18n-t>` 和 `<i18n-group>` 像 `$t` 一样读取当前生效的字典。

**`<i18n-switcher>`**

- 链接是调用 `$switchLocale` 的普通 `<a>`，因此 `router-link-active` class 已不存在。
- 按钮为 `type="button"` 并带有 `aria-expanded`。按 Escape 键或点击外部会关闭下拉菜单。
- 新增 class `i18n-switcher-wrapper`、`i18n-switcher-dropdown` 和 `i18n-switcher-button`。每个链接都带有 `lang`，当 locale 设置了 `dir` 时也带有 `dir`。
- 默认样式使用 CSS 逻辑属性，下拉菜单具有更大的 `z-index`、最小宽度和阴影。
- 在带参数的页面上，服务端会在渲染结束时重写其链接。手写的 `$switchLocalePath` 链接不会被重写。

**`<i18n-link>`**

- `https://`、`mailto:` 和 `tel:` 不区分大小写匹配。单独的 `report.pdf` 是路由，`example.com` 保持为外部链接。同时也是顶级域名的文件扩展名（`example.md`）会被视为文件：请写上 `https://`。
- `activeStyle` 会忽略末尾斜杠、query 和 hash。

### 钩子与类型 {#hooks-and-types}

- `i18n:register` 是运行时钩子：在插件中使用 `nuxtApp.hook('i18n:register', …)`。
- 导出的类型 `ModuleHooks` 重命名为 `ModuleRuntimeHooks`。
- `i18n:beforeLocaleSwitch` 和 `i18n:afterLocaleSwitch` 从未被触发过，不再出现在文档中。
- `ModuleOptionsExtend.isSSG` 变为可选并已弃用：没有任何地方设置它。

### URL 与重定向 {#urls-and-redirects}

- **在 `prefix_except_default` 下，当 `en` 为默认 locale 时，`/en` 和 `/en/...` 返回 404**。
- **大小写或拼写不同的 locale 前缀返回 404**（`/DE/about`）。`[...slug]` 下的 `/DE/x` 和 `[slug]` 旁的 `/DE` 也是如此，因此与某个 locale 代码仅大小写不同的 CMS slug 会失去其页面。
- **在 `autoDetectPath: '*'` 或 `'no_prefix'` 下，未知 URL 仍然返回 404**。`prefix` 保留重定向，所有策略下的 `/` 也是如此。
- **不带前缀的其他 locale 自定义路径** 在 `prefix_except_default` 下会 `302` 到默认 locale 的 URL。在 `prefix` 下，重定向现在会到达一个实际存在的页面。`prefix_and_default` 仍然返回 404。
- **带 `redirects: false` 的 `prefix`** 对不带前缀的 URL 返回 404，包括具有自定义默认路径的页面的原始 URL。
- **`autoDetectPath: '*'`** 也会对不带前缀的路径应用 cookie 和 `Accept-Language`。
- **在 `prefix` 下**，无论 `autoDetectPath` 如何设置，不带前缀的 URL 在每个路径上都会保留访客的 locale。
- **在 `prefix_and_default` 下**，不带前缀的 URL 为默认 locale。
- **在 `no_prefix` 下**，自定义路径会以其自身的 locale 渲染，受限页面会以其提供的 locale 渲染，共享同一路径的 locale 共用一条路由记录。
- **没有对应页面的 `routeRules` 重定向** 不会被本地化：`/de/old` 返回 404，以前是空的 200。
- **路由规则会作用于自定义路径**，在 `no_prefix` 下也会被复制。像 `/de/artikel/news` 这样的静态同级路径会匹配 `/de/artikel/:slug`。
- **带 `disabled: true` 的 locale** 会立即在其前缀上返回 404，指向它的链接会停留在当前页面。
- **大小写不同的页面路径** 会 `302` 到其正确的拼写：`/T/BASIC` 跳转到 `/t/basic`。
- **具有自定义默认路径的页面的原始 URL** 在 `prefix_except_default` 下会 `302` 到该路径。以前返回 404。
- **`noPrefixRedirect`** 依据访客的 locale：当 cookie 为 `de` 时，`/about` 会跳转到 `/ueber-uns`，而不是默认 locale 的路径。
- **主机自身的前缀** 在 `prefix_except_default` 下于其 `baseDefault` 主机上返回 404：`de` 主机上的 `/de/x` 以前返回 200。
- **`customRegexMatcher`** 不再对第一个路径段看起来像 locale 的真实页面返回 404。
- **`nuxi generate`** 会为每个提供某静态页面的 locale 预渲染该页面，除非路由规则设置了 `prerender: false`：输出中的文件会更多。使用 `baseUrl` 时，请通过 `NUXT_I18N_DOMAIN` 为每个域名运行一次。
- **客户端重定向会保持其导航的模式：** 普通的 `<NuxtLink>` 会添加一条历史记录。
- **本地化路由名称保持一致。** 只有在 `router.push({ name })` 中硬编码 `localized-…` 名称的代码会受影响：请将页面自身的名称传给 `$localeRoute`。
- **来自 `extendPages` 的未命名页面** 会被本地化并获得名称。
- **在 `prefix` 下，指向其他域名的链接** 会保留 locale 前缀。
- **域名的首页** 在所有地方都不带末尾斜杠。
- **`?locale=`** 只有在 `no_prefix` 下才对页面生效。`/about?locale=de` 不再在 `lang="en"` 下渲染德语。
- **插件中的 `setLocale('de')`** 在 `/en/...` 上不再加载 `de` 字典。

### SEO 与 HTML 输出 {#seo-and-html-output}

- `dir="auto"` 不再是默认值。已知的 RTL 语言会得到 `dir="rtl"`，其他未设置 `dir` 的 locale 不会得到该属性。要保留旧的输出，请设置 `dir: 'auto'`，但大型页面会有解析开销。参见[文本方向](/cn/guide/seo#text-direction)。
- `disableMeta` 现在可用：页面不会有 `hreflang`、canonical 或 `og:locale`。`lang` 和 `dir` 保留。
- `hreflang` 只列出提供该页面的 locale。只有当默认 locale 提供该页面时才会出现 `x-default`。
- 未本地化的页面没有 `hreflang` 或 `og:locale:alternate`。
- 404 页面带有 URL 所对应 locale 的 `<html lang dir>`，且没有 canonical 或 `hreflang`。
- Canonical、`og:url` 和 `hreflang` 会保留白名单中的 query（`/about?page=2`），服务端也是如此。
- 当源来自请求时，canonical 和 `hreflang` 会包含 `app.baseURL`。
- 每个 SSR 页面（包括 404 页面）都会为其字典文件添加 `<link rel="preload" as="fetch" crossorigin="anonymous">`。请在严格的 CSP 中允许它。使用 `apiBaseClientHost` 时，该主机需要支持 CORS。
- 在 `no_prefix` 下每个页面都会设置 `Vary`，在其他策略下 locale 重定向也会设置。请检查你的 CDN 缓存键。
- 只有实际提供的页面才会写入 locale cookie。

### 检测与服务端 {#detection-and-server}

- `Accept-Language` 会遵循 `q` 值，`q=0` 会排除某种语言。
- `useLocaleServerMiddleware` 和 `useTranslationServerMiddleware` 在每个路由上使用同一顺序（`?locale`、`[locale]` 参数或前缀、cookie、请求头、默认值），遵循 `localeCookie: null` 和 `autoDetectLanguage: false`，并按 locale 缓存字典。
- 格式错误的 locale cookie 会被忽略并保持原样，而不会导致 SSR 失败。
- Hash 模式只读取 `hash-locale` cookie。单独的 `user-locale=de` 不再生效。
- `NUXT_I18N_DEFAULT_LOCALE` 和运行时的 `disabledLocales` 会改变路由。
- **`premerged` 输出已改变。** `/{apiBaseUrl}/<page>/<locale>/data.json` 只保存与 `__root/<locale>/data.json` 不同的内容。任何直接读取这些文件的程序都必须将两者合并。完整的字典仍然是有效的文件。
- **字典遵循 `app.cdnURL`。** 浏览器会从 `<cdnURL>/_locales/...` 获取字典，以前使用的是 `app.baseURL`。CDN 必须包含 `_locales/` 并允许你站点的源。参见 [App baseURL 与 payload 主机](/cn/guide/deployment#app-baseurl-and-payload-hosts)。
- `/{apiBaseUrl}/**` 上不再有 Nitro 路由缓存，`s-maxage=60, stale-while-revalidate` 响应头也已移除。如果你依赖该缓存，请在 payload 路由前放置 CDN。
- `/{apiBaseUrl}/<page without a folder>/<locale>/data.json` 会返回根字典，以前是 `{}`。主机的 404 现在会作为 404 透传，以前返回 `200 {}`。
- 无法加载字典的预渲染会以 500 和一条警告失败，在 Nuxt 默认的 `failOnError` 下构建会以 1 退出。
- 未重新构建而修改的翻译只有在 `v` 变化时才会到达浏览器：请设置 `NUXT_I18N_DATE_BUILD`。
- SSR 不再通过 HTTP 请求 `/{apiBaseUrl}`，除非设置了 `apiBaseServerHost`。

### 翻译 {#translations}

- 每一层级都进行深度合并，回退链会一直追溯到底。
- 合并按 locale 进行：当前 locale 的根文件优先于回退 locale 的页面文件。
- 在生产环境中，没有自己 `pages/<name>/` 文件夹的页面会读取根字典。以前得到的是 `{}`。
- `disablePageLocales: true` 只读取根文件。
- 导航后，离开页面的键不再解析。如果某个布局使用了只存在于上一个页面文件中的键，请将它们移到根文件中。
- 损坏的 locale 文件在所有模式下都只会带着其路径警告一次。开发环境以前会抛出错误。

## 迁移 {#migration}

1. 检查环境要求：Nuxt 3.18、Node 20，如果使用 `@i18n-micro/react` 则需要 React 18。
2. 同时更新 `nuxt-i18n-micro` 和所有 `@i18n-micro/*` 包。移除 `@i18n-micro/hmr`。如果你的测试导入了 `@i18n-micro/test-utils`，请将其添加为开发依赖。用 `@i18n-micro/cli` 替换 `nuxt-i18n-micro-cli`，并参照[其命令对照表](/cn/guide/cli#moving-from-nuxt-i18n-micro-cli)。
3. 在代码中搜索来自 `@i18n-micro/path-strategy` 的 `switchLocaleRoute(`、`i18n-plugin-hooks`、`i18n-plugin-define`、`localized-` 路由名称、`$getI18nConfig().globalLocaleRoutes` 及其他已移除的配置键、`ModuleHooks`，以及 `i18n:register` 上的 `@ts-expect-error`。
4. 将 `<i18n-t html>` 参数中的标记移到翻译中，并以参数形式传递数据。
5. 如果设置了 `baseUrl`：检查使用 `$localeRoute` 构建的链接，在代理之后设置 `trustForwardedHost`，并通过 `NUXT_I18N_DOMAIN` 为每个域名运行一次 `nuxi generate`。
6. 根据你的策略检查 URL：`prefix_except_default` 下的 `/en`、类似 locale 代码的 CMS slug、`routeRules` 重定向以及 `excludePatterns`。
7. 检查 CDN 缓存键是否考虑了 `Vary`，并在严格的 CSP 中允许 preload 链接。使用 `app.cdnURL` 时，请将 `_locales/` 放到 CDN 上并允许 CORS。
8. 如果有工具直接读取 `/_locales/...` 文件，请将页面文件合并到 `__root/<locale>/data.json` 之上。
9. 如果某个全局守卫读取 locale 或字典，请确认它可以在导航提交之前运行。将布局从上一个页面文件中取用的键移到根文件中。
10. 比较升级前后的 `nuxi generate` 输出或站点地图抓取结果：`hreflang`、`x-default`、canonical 和页面列表会按设计发生变化。
11. 更新框架包的导入：React、Solid 和 Preact 适配器使用 `/router`，Astro 的加载器使用 `/node`，类型插件使用 `I18nTypesPlugin(o)`。
12. 对于 Astro，删除仅复制设置的 `src/middleware.ts`，并将 `pages/blog-hello/` 形式的字典重命名为其路由模式。
13. 更新那些固定了 `router-link-active`、`li button`、`▼` 或旧 mock 行为的测试。

细节和所有边缘情况：[升级](/cn/guide/upgrade)。

## 为什么这很重要 {#why-it-matters}

- **从设计上保证正确：** 链接、重定向和 SEO 标签都来自应用实际拥有的路由。
- **处处一致：** 构建、source 模式和开发模式给出相同的字典，所有调用方都使用同一种检测顺序。
- **域名：** 一次部署服务所有 locale 域名，无需第二次构建。
- **更安全的默认值：** 转义的参数、有上限的缓存、停留在你的源上的链接。
- **更少的发布体积：** 更小的字典文件、更小的路由包，以及集中在一处的共享逻辑。
