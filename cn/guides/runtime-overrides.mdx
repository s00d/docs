# 运行时 i18n 覆盖

当你希望同一份构建产物在不同环境中运行时使用不同的语言默认值(例如:不同的多租户实例),可以参考本指南。

## 可在运行时覆盖的内容

模块支持在运行时安全覆盖以下配置:

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

这些覆盖会在 `.nuxt/i18n.strategy.mjs` 与 `.nuxt/i18n.config.mjs` 中的构建期配置之上生效。

## 不可在运行时覆盖的内容

`strategy`(`no_prefix`、`prefix`、`prefix_except_default`、`prefix_and_default`)属于构建期设置,因为它会影响生成的路由行为。

若传入运行时的 strategy 覆盖,将被忽略并触发一条警告。

## 基于 runtimeConfig 的覆盖

在 `runtimeConfig.public.i18nRuntime` 下提供运行时值:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## 通过环境变量覆盖

你也可以通过环境变量配置这些覆盖:

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES`(逗号分隔,例如 `fr,it`)

同时也支持以下备用别名:

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## 校验规则

在运行时,模块会对覆盖值进行校验,以避免出现异常状态:

- 不能禁用所有语言。
- `defaultLocale` 必须指向一种已启用的语言。
- `fallbackLocale` 必须存在于已声明的语言中。

若覆盖无效,模块会保留一个安全值并记录警告。

## 多实例部署注意事项

该运行时特性适用于在不重新构建的情况下,按实例激活不同的语言和默认值。

若不同实例需要使用不同的 URL 策略(如 `no_prefix` 与 `prefix`),请分别为每种策略构建独立版本。

## 禁用的语言与静态 payload

`runtimeConfig.public.i18nRuntime.disabledLocales` 会更新路由、切换器以及 Nitro 的 payload **处理器**——但 Nitro 会在该处理器之前,先从 `public/` 中提供文件。

若 `translationPayloads.publicAssets`(或 Node SSR 强制的公共副本)已经写入 `/_locales/\{page\}/\{locale\}/data.json`,运行时的禁用无法隐藏该文件。推荐在构建期设置 `locale.disabled: true`,这样 premerge 不会为该语言输出静态 payload。
