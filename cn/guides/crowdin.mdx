# 🌐 Crowdin 集成指南

## 📖 简介

将 Crowdin 集成到项目中,可以简化本地化与翻译流程,让跨多语言与多平台的翻译管理变得更容易。本指南将逐步演示如何在你的项目中配置 Crowdin,包括初始化、上传源文件以及下载翻译。

## 🔧 安装与设置

要开始使用 Crowdin,首先需要在本地全局安装 Crowdin CLI,并在项目目录中初始化它。

### 📦 安装 Crowdin CLI

使用 npm 全局安装 Crowdin CLI:

```bash
npm install -g @crowdin/cli
```

### 🛠 在项目中初始化 Crowdin

在项目中运行以下命令来初始化 Crowdin:

```bash
crowdin init
```

该命令会引导你完成设置流程,包括填写项目 ID、API token 及其他配置项。

## 🗂️ 配置指南

### 📄 Crowdin 配置文件(`crowdin.yml`)

Crowdin 的配置文件(`crowdin.yml`)定义了源文件如何映射,以及翻译文件应存放的位置。以下是一个示例配置:

```yml
'project_id': 'YOUR_PROJECT_ID'
'api_token': 'YOUR_API_TOKEN'
'base_path': './locales'
'base_url': 'https://api.crowdin.com'
'preserve_hierarchy': true

files:
  [
    { 'source': '/en.json', 'translation': '/%two_letters_code%.json' },
    { 'source': '/pages/**/en.json', 'translation': '/pages/**/%two_letters_code%.json' },
  ]
```

### 📂 主要配置参数

- **`project_id`**:你的 Crowdin 项目 ID,用于在 Crowdin 中定位管理翻译的项目。
- **`api_token`**:用于身份验证的 API token。请确保该 token 拥有上传和下载翻译所需的权限。
- **`base_path`**:源文件的基础目录。示例中翻译文件存放于 `./locales` 目录下。
- **`base_url`**:Crowdin API 的基础 URL。
- **`preserve_hierarchy`**:设为 `true` 时,Crowdin 会在项目中保留源文件的目录结构。

### 📂 files 配置

`files` 部分将你的源文件映射到翻译文件将要存放的路径。例如:

- **源路径**:定义原始翻译文件的位置。
- **译文路径**:指定翻译后的文件在 Crowdin 中的存放位置。可以使用 `%two_letters_code%` 之类的占位符,在文件路径中动态填入语言 code。

## ⬆️ 上传源文件到 Crowdin

在完成 Crowdin 配置后,可用以下命令上传源文件:

```bash
crowdin upload sources
```

该命令会将配置中指定的所有源文件上传到 Crowdin,以便进行翻译。

## ⬇️ 从 Crowdin 下载翻译

Crowdin 中的翻译完成或更新后,可以用以下命令将其下载到项目:

```bash
crowdin download
```

该命令会从 Crowdin 拉取最新翻译,并按配置文件中指定的路径保存到项目中。

## ⚙️ 最佳实践

### 🔑 键命名保持一致

请确保所有文件中的翻译键命名一致,以避免混淆和重复。

### 🧹 定期维护

定期审查并清理未使用的翻译键,保持文件的整洁和可维护性。

### 🛠 自动化上传与下载

将 Crowdin CLI 命令集成到 CI/CD 流程中,自动上传源文件与下载翻译,确保翻译始终为最新。

按本指南操作,你就能顺利地将 Crowdin 集成到项目中,使国际化工作井然有序、高效可控。
