# 性能测试结果

- **[CLI](https://github.com/s00d/nuxt-i18n-micro/tree/main/scripts/src/commands/performance.ts)**: `pnpm -C scripts cli performance` / `pnpm test:performance`

### 说明

在同一份共享字典配置下,对比 **plain Nuxt**(不使用 i18n 模块的基线)、**i18n-micro** 以及 **`@nuxtjs/i18n` v10.6**。

关注点:构建时间、峰值 RSS、可部署产物的 **代码 vs 翻译 vs 总量**,以及在 Artillery + Autocannon 下的服务端表现。

### 方法说明

- 各项指标均为**每个用例连续运行 3 次的均值**(先 A ×3,再 B ×3,再 C ×3——不交叉运行)。
- **翻译**包括 `locales/` / `_locales/` / `translations/` 下的语言 JSON、`chunks/raw/` 下的所有内容以及匹配的语言分片。旧版报告中 `@nuxtjs/i18n` 出现 "translations: 0 B" 而 "code" 列却很大的情况,是把消息分片当作了应用代码。
- **plain-nuxt** 通过静态 `public/translations` JSON(而非静态 JS 导入)提供同等数量的叶子数据。在 Artillery 下,该基线是 I/O 密集型的;这不是 "i18n 开销",而是每次请求都要拉取大 JSON 的成本。

### 运行次数

下方所有指标均为 **3 次运行的均值**。

### 测试用例配置

| 参数 | 值 |
|------|-------|
| 语言数 | **4**(`en`、`de`、`ru`、`fr`) |
| 页面数 | **2**(`index`、`page`) |
| Index 树 | 深度 **5**、分支 **7** → 每种语言 **16,807** 个叶子键 |
| 次级页面 | 深度 **5**、分支 **6** → 每个页面每种语言 **7,776** 个叶子键 |
| 目标 | 默认 CLI 配置(`--locales 4 --keys 10000`);对回归雷达负载可提高参数 |

字典来自 `test/fixtures/perf-shared/runtime.json`(由 CLI 生成),以确保三个用例保持一致。

## test/fixtures/plain-nuxt 的构建性能

- **构建时间**: 5.32 seconds
- **包体积**: 8.33 MB (code: 1.53 MB, translations: 6.8 MB)
- **代码包**: client: 201.88 KB, server: 1.33 MB
- **最大 / 平均 CPU**: 207.10% / 166.29%
- **最大 / 平均内存**: 810.26 MB / 585.14 MB

## test/fixtures/i18n 的构建性能

- **构建时间**: 8.34 seconds
- **包体积**: 9.37 MB (code: 2.16 MB, translations: 7.21 MB)
- **代码包**: client: 315.17 KB, server: 1.86 MB
- **最大 / 平均 CPU**: 203.97% / 164.39%
- **最大 / 平均内存**: 1820.57 MB / 1177.11 MB

## test/fixtures/i18n-micro 的构建性能

- **构建时间**: 5.34 seconds
