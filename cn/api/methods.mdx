---
title: "辅助方法"
description: "模块注入的每个运行时辅助方法——`$t`、`$tc`、`$localePath`、`$switchLocale` 等——及其签名。"
---

模块会将其运行时辅助方法注入到 Nuxt 应用中：`$t`、`$tc`、`$localePath`、`$switchLocale` 等。可通过本页查阅辅助方法的签名和行为。签名和描述来自 `src/runtime/plugins/01.plugin.ts` 中的 `PluginsInjections` 和 `NuxtAppOnlyInjections` 接口。

## 访问方式 {#access}

| 位置 | 方式 |
| --- | --- |
| 模板 | `{{ $t('title') }}` —— 所有辅助方法，带 `$` |
| `<script setup>` | `const { t, localePath } = useI18n()` —— `PluginsInjections` 中的所有辅助方法，带或不带 `$` 均可 |
| 插件、中间件、`<script setup>` | `const { $t, $defineI18nRoute } = useNuxtApp()` —— 全部，仅带 `$` |

`$defineI18nRoute` 仅在 `useNuxtApp()` 上有类型定义。参见 [`useI18n`](/cn/composables/useI18n)。

```vue
<script setup lang="ts">
const { t, localePath } = useI18n()
</script>

<template>
  <NuxtLink :to="localePath('/about')">{{ t('nav.about') }}</NuxtLink>
</template>
```

## 语言区域 {#locale}

### `$getLocale` {#$getlocale}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric) => string
```

当前语言区域的代码。传入一个路由可读取该路由所属的语言区域。

```ts
$getLocale() // 'de' on /de/about
```

### `$getLocaleName` {#$getlocalename}

```ts
() => string | null
```

配置中当前语言区域的 `displayName`，未设置时为 `null`。

### `$getLocales` {#$getlocales}

```ts
() => Locale[]
```

所有已配置的语言区域及其元数据。

语言区域对象上的自定义属性会按原样返回；可通过对 `Locale` 进行[模块扩展](/cn/api/module-options#locales)来为它们添加类型。

### `$defaultLocale` {#$defaultlocale}

```ts
() => string | undefined
```

所配置的默认语言区域的代码。

### `$getI18nConfig` {#$geti18nconfig}

```ts
() => ResolvedI18nConfig
```

运行时所看到的、已解析的模块配置。

该值包含[运行时覆盖](/cn/guide/runtime-overrides)（`defaultLocale`、`fallbackLocale`、已禁用的语言区域）。

```ts
const { strategy, localeCookie } = useNuxtApp().$getI18nConfig()
```

## 翻译 {#translation}

### `$t` {#$t}

```ts
TranslationFn<CleanTranslation>
```

翻译一个键，并将 `params` 插值到其中。键缺失时返回 `defaultValue`，未提供默认值时返回键本身。

```ts
// { "welcome": "Welcome, {name}!" }
$t('welcome', { name: 'Ada' }) // 'Welcome, Ada!'
$t('missing.key', {}, 'Fallback') // 'Fallback'
```

指向嵌套对象的键会返回该对象，而不是字符串。在模板中它会渲染为 `[object Object]`；请使用叶子键。

### `$ts` {#$ts}

```ts
TranslationFn<string>
```

与 `$t` 类似，但始终返回字符串：值会经过 `toString()`，因此嵌套对象会变成 `'[object Object]'`。请让键指向叶子节点。

### `$_t` {#$_t}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<CleanTranslation>
```

将 `$t` 绑定到特定路由，用于在当前页面之外进行翻译——例如在布局中渲染指向另一个路由的链接。

```ts
const route = useRoute()
const t = useNuxtApp().$_t(route)
t('page.title')
```

### `$_ts` {#$_ts}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<string>
```

将 `$ts` 绑定到特定路由。参见 `$_t`。

### `$tc` {#$tc}

```ts
(key: TranslationKey, params: number | Params, defaultValue?: string) => string
```

带复数处理的翻译。`params` 可以是计数本身，也可以是包含 `count` 的对象。

各形式之间用 `|` 分隔。使用内置规则时，非负整数计数 `n` 会选择第 `n` 个形式，超出时取最后一个形式；负数、小数或 `NaN` 计数取最后一个形式。`{count}` 和其他参数会插值到所选形式中。

对于复数形式不按计数排列的语言，请以 `=0 ` 开头编写模板。此时第一个形式用于 0，其余形式按 [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) 类别排列，顺序为 `zero, one, two, few, many, other`：

```json
{
  "apples": "=0 no apples | one apple | {count} apples",
  "files": "=0 no files | {count} one | {count} few | {count} many"
}
```

```ts
$tc('apples', 0) // 'no apples'
$tc('apples', 1) // 'one apple'
$tc('apples', 7) // '7 apples'

// In `uk` (categories `one, few, many, other`) the forms after the zero form follow those categories:
$tc('files', 21) // '21 one'
$tc('files', 22) // '22 few'
$tc('files', 25) // '25 many'
$tc('files', 2.5) // '2.5 many': no form for `other`, so the last one
```

- `=0 ` 只有出现在值的最开头且带有空格时才生效。`$t` 会将其显示为文本：它属于复数处理。
- 没有自己形式的类别取最后一个形式。负数或小数计数同样取最后一个形式。
- 它适用于任何语言区域：英语中可写作 `=0 none | one | {count} many`。
- 类别来自语言区域的 `iso`，否则来自其代码。`Intl` 无法识别的代码会回退到索引规则，标记仍会被移除，因此结果不会因机器而异。
- `<i18n-t :plural>` 遵循相同的规则。自定义的 [`plural`](/cn/api/module-options#plural) 或 `customPluralRule` 会收到包含标记的原始值，并自行决定；`plural` 返回 `null` 时会将调用交还给内置规则，内置规则会识别该标记。

没有标记时，模板保持使用索引规则，只有一种仅能按一种方式理解的例外：一个不含占位符的零形式，然后每个类别一个形式，并且在多个计数共享的每个形式中都包含 `{count}`（`uk` 中的 `no files | {count} one | {count} few | {count} many`）。

如需自定义规则，请设置 [`plural`](/cn/api/module-options#plural)。

```ts
// { "apples": "no apples | one apple | {count} apples" }
$tc('apples', 0) // 'no apples'
$tc('apples', 10) // '10 apples'
$tc('cart', { count: 2, name: 'Ada' }) // count and params in one object
```

第三个参数是 `defaultValue`，而不是 params。

### `$has` {#$has}

```ts
(key: string) => boolean
```

某个键在当前语言区域中能否解析。可用它根据可选文案进行分支，而不是渲染原始键。与 `$t` 一样，在同一语言区域的页面切换过程中，它也能看到正在离开的页面的键。

```ts
if ($has('promo.banner')) show.value = true
```

## 格式化 {#formatting}

### `$tn` {#$tn}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

使用 `Intl.NumberFormat` 按当前语言区域格式化数字。传入键可从配置中选择一个命名格式。

命名格式来自 [`numberFormats`](/cn/api/module-options#numberformats)。

```ts
$tn(1234.5, { style: 'currency', currency: 'EUR' }) // '1.234,50 €' in de
$tn(1000, 'currency') // named format
$tn(1000, 'currency', 'de') // named format in another locale
```

### `$td` {#$td}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

使用 `Intl.DateTimeFormat` 按当前语言区域格式化日期。传入键可从配置中选择一个命名格式。

命名格式来自 [`datetimeFormats`](/cn/api/module-options#datetimeformats)。

```ts
$td(new Date(), { dateStyle: 'long' })
$td(post.createdAt, 'short')
```

### `$tdr` {#$tdr}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

使用 `Intl.RelativeTimeFormat` 将日期格式化为相对时间（“3 天前”）。

```ts
$tdr(Date.now() - 5 * 60_000) // '5 minutes ago' in en
```

## 切换与链接 {#switching-and-links}

### `$switchLocale` {#$switchlocale}

```ts
(locale: string) => Promise<boolean>
```

导航到当前页面的另一语言区域版本。在 `no_prefix` 和 hash 模式下，它会在导航前加载该语言区域的翻译；在 `no_prefix` 下，路由会被原地替换（不会新增历史记录）。未知的语言区域会被忽略。
该调用是异步的：`await` 它即可在导航完成后执行代码。当该语言区域的词典处于活动状态时解析为 `true`，否则为 `false`：chunk 加载失败（当前词典保持不变；再次调用即可重试）或有更新的切换操作胜出。

```ts
await $switchLocale('de')
```

### `$switchLocalePath` {#$switchlocalepath}

```ts
(locale: string) => string
```

当前页面在另一语言区域中的路径，不进行导航。

```vue
<NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
```

### `$switchLocaleRoute` {#$switchlocaleroute}

```ts
(locale: string) => RouteLocationRaw
```

当前页面在另一语言区域中的路由对象，不进行导航；对于拥有独立 `baseUrl` 的语言区域则为 URL 字符串。在 `trailingSlash` 下，该对象的 `path` 和 `fullPath` 会遵循该规则，`query` 和 `hash` 保持原样，`router.push` 或链接会保留它们。

### `$switchRoute` {#$switchroute}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => Promise<void>
```

导航到另一个路由，保持当前语言区域或切换到 `toLocale`。与 `$switchLocale` 一样是异步的。

```ts
$switchRoute('/about') // active locale
$switchRoute({ name: 'about' }, 'de') // switch to de
```

### `$localePath` {#$localepath}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => string
```

在指定语言区域（或当前语言区域）中解析路径。带有 `http(s):`、`mailto:` 或 `tel:` 协议的字符串会原样返回：不要将未经检查的用户输入作为链接目标传入。

字符串路径会被视为它所展示的页面，因此语言区域的自定义路径也会被应用。

```ts
$localePath('/about') // '/about' in en, '/de/ueber-uns' in de with localeRoutes
$localePath({ name: 'about' }, 'fr') // '/fr/about'
```

### `$localeRoute` {#$localeroute}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => RouteLocationResolved
```

在指定语言区域（或当前语言区域）中解析路由。返回一个普通对象，可以安全地保存在状态中。当某个参数需要转义时，它包含 `path`、`fullPath`、`query` 和 `hash`，但没有 `name` 或 `params`：由路径为路由器提供编码后的 URL。对于位于其他域名上的语言区域，`path` 和 `fullPath` 是绝对地址，路由器无法接收：这类链接需要通过 `<i18n-link>` 或 `$localePath`。

### `$getRouteName` {#$getroutename}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric, locale?: string) => string
```

去掉语言区域前缀的路由名称——即翻译所使用的键名。

```ts
$getRouteName() // 'about' on /de/about
```

## 页面配置 {#page-config}

### `$defineI18nRoute` {#$definei18nroute}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

在组件内部注册按页面的语言区域配置和翻译。会合并到当前语言区域，并在语言区域变化时重新应用。

请在页面的 `<script setup>` 中调用它，并始终从 `useNuxtApp()` 中解构。构建时会从调用中读取 `locales`、`localeRoutes` 和 `disableMeta`；运行时只有 `locales` 起作用（内联翻译会合并到当前语言区域）。完整规则：[页面配置](/cn/guide/per-component-translations)。

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: { en: '/about', de: '/ueber-uns' },
})
</script>
```

### `$setI18nRouteParams` {#$seti18nrouteparams}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

为当前路由设置按语言区域区分的参数，使动态片段可以因语言而异。请在 SSR 期间、head 渲染之前调用它。

当导航到另一个路径提交时，这些参数会被清除，包括从 `/news/1` 到 `/news/4` 这种保持路由名称不变的情况。详情：[本地化路径](/cn/guide/custom-locale-routes)。

```ts
$setI18nRouteParams({
  en: { slug: 'my-post' },
  de: { slug: 'mein-beitrag' },
})
```

## 运行时翻译 {#runtime-translations}

### `$mergeTranslations` {#$mergetranslations}

```ts
(newTranslations: Translations) => void
```

在运行时将翻译合并到当前语言区域，覆盖已加载的内容。

深度合并到当前语言区域的当前页面 chunk 中；未涉及的键会保留。

```ts
$mergeTranslations({ banner: { title: 'Sale' } })
```

### `$setTranslation` {#$settranslation}

```ts
(key: string, value: unknown) => void
```

替换当前词典中 `key` 处的值。这是替换而不是合并——当需要保留已有的同级键时，请使用 `$mergeTranslations`。

```ts
$setTranslation('banner', { title: 'Sale' }) // drops other keys under banner
$setTranslation('banner.title', 'Sale') // dotted path
```

### `$loadPageTranslations` {#$loadpagetranslations}

```ts
(locale: string, routeName: string, translations: Translations) => Promise<void>
```

在运行时为页面加载翻译，适用于构建时无法确定键的内容。

合并到内存中的 `(locale, routeName)` chunk，当该 chunk 处于活动状态时界面会更新。这里不会获取 payload：对于尚未加载的页面，这些翻译会等待，在其文件加载后会叠加在文件内容之上。

```ts
await $loadPageTranslations('en', 'about', { title: 'About us' })
```

### `$resolveTranslations` {#$resolvetranslations}

```ts
() => Translations
```

当前语言区域和路由在内存中的所有翻译，以树形结构返回。这是 `$t()` 此刻能够解析的内容的只读视图。

请将结果视为只读。

### `$setMissingHandler` {#$setmissinghandler}

```ts
(handler: MissingHandler | null) => void
```

安装一个回调，每遇到一个未解析的键就会调用。传入 `null` 可将其移除。

该处理函数会替代开发环境中的警告运行。

```ts
$setMissingHandler((locale, key, routeName) => {
  console.error(`[i18n] missing ${key} in ${locale} (${routeName})`)
})
```

### `$clearCache` {#$clearcache}

```ts
() => void
```

丢弃所有已缓存的翻译 chunk，并重新加载当前页面的词典。在新翻译到达之前，页面会继续显示当前的翻译。开发环境的 HMR 会在每次翻译文件变化时调用它。

```ts
const { clearCache } = useI18n()
clearCache()
```

重新加载失败时会保留当前词典。
