# 🌍 `useLocaleHead`-composable

Composablen `useLocaleHead` er et verktøy i `Nuxt I18n Micro` som hjelper deg med å administrere SEO-attributter og HTML-metatagger for lokaliserte ruter. Den genererer dynamisk attributter for `lang` og `dir` i HTML-dokumentet og oppretter `meta`- og `link`-tagger for å forbedre SEO for ditt lokaliserte innhold.

## 🛠️ Returverdier

`useLocaleHead`-composablen returnerer et reaktivt objekt og en oppdateringsfunksjon som du bør
kalle når kildedata endres. Begge formene er i signaturen over, generert fra
kilden.

### `metaObject`

Reaktiv head-payload (html-attrs, meta, link) egnet for `useHead(metaObject)`.

- **Eksempel**:
  ```js
  const { metaObject } = useLocaleHead()
  useHead(metaObject)
  ```

### `updateMeta`

Beregner `metaObject` på nytt basert på gjeldende rute, lokale og konfigurasjon. Kall den når input
endres — for eksempel ved en ruteendring.

- **Eksempel**:
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  useHead(metaObject)
  watch(
    () => route.fullPath,
    () => updateMeta(),
    { immediate: true },
  )
  ```

### Tilgang til `link` og `meta`

`link`- og `meta`-arrayene er tilgjengelige via `metaObject.value`:

- **Eksempel**:
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  updateMeta()
  console.log(metaObject.value.link)
  // Output: [{ id: 'i18n-can', rel: 'canonical', href: 'https://example.com/about' }, ...]
  console.log(metaObject.value.meta)
  // Output: [{ id: 'i18n-og', property: 'og:locale', content: 'en_US' }, ...]
  ```

## 🛠️ Eksempelbruk

### Grunnleggende bruk

Generer lokale-spesifikke head-attributter med standardalternativer.

```js
const head = useLocaleHead()
```

### Tilpasse identifikator-attributt

Bruk et egendefinert identifikator-attributt for de genererte taggene.

```js
const head = useLocaleHead({ identifierAttribute: 'data-i18n' })
```

### Deaktiver SEO-attributter

Generer head-attributter uten å legge til SEO-relaterte meta- og link-tagger.

```js
const head = useLocaleHead({ addSeoAttributes: false })
```

### Angi en basis-URL

Sett en egendefinert basis-URL for canonical og alternate-URL-er.

```js
const head = useLocaleHead({ baseUrl: 'https://mywebsite.com' })
```

## 🚀 Tilleggsfunksjoner

### SEO-meta- og link-tagger

Når `addSeoAttributes` er aktivert, genererer composablen automatisk følgende tagger:

- `og:locale` for gjeldende lokale (`language_TERRITORY`, understrek). Avledet fra `locale.og` eller konvertert fra `locale.iso` når mulig.
- `og:url` for canonical-URL-en til siden.
- `og:locale:alternate` for alternative språkversjoner.
- `rel="canonical"`- og `rel="alternate"`-lenker for SEO-optimalisering.
- `hreflang="x-default"`-lenke som peker til standardlokalens URL. Dette forteller søkemotorer hvilken URL de skal vise til brukere hvis språk ikke samsvarer med noen av de definerte lokalene.

### Dynamisk lokale og retning

Composablen bestemmer dynamisk `lang`- og `dir`-attributtene basert på gjeldende rutes lokale, og sikrer at HTML-dokumentet er korrekt konfigurert for internasjonale brukere.

### Håndtere lokaliserte ruter

Hvis rutene dine er prefikset med lokale-koder (f.eks. `/en/about`), justerer composablen intelligent hele stien for å generere URL-er, og sikrer at SEO-attributter er nøyaktige og relevante.

Denne composablen forenkler prosessen med å optimalisere Nuxt-applikasjonen din for internasjonale målgrupper, og sikrer at nettstedet er godt forberedt for globale søkemotorer og brukere.

## 🛠️ Eksempelbruk

Følgende eksempel viser hvordan du bruker `useLocaleHead`-composablen inne i en Vue-komponent med standardinnstillinger:

```vue
<script setup>
import { useRoute, watch } from '#imports'
const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({
  addDirAttribute: true,
  identifierAttribute: 'id',
  addSeoAttributes: true,
})
useHead(metaObject)
watch(
  () => route.fullPath,
  () => updateMeta(),
  { immediate: true },
)
</script>
```

### Forklaring av koden

- **`useLocaleHead`-composable**: Denne composablen kalles i `<script setup>`-seksjonen og returnerer et objekt som inneholder `htmlAttrs`, `meta` og `link`.

- **`<html>`-tag**: `lang`- og `dir`-attributtene for HTML-dokumentet bestemmes dynamisk basert på gjeldende lokale og anvendes på `<html>`-taggen.

- **`<head>`-seksjon**:
  - **Metatagger**: SEO-relaterte metatagger genereres, inkludert `og:locale`, `og:url` og `rel="canonical"`- og `rel="alternate"`-tagger for å spesifisere alternative språkversjoner av siden.
  - **Link-tagger**: Canonical-lenker, lenker til alternative språkversjoner og `hreflang="x-default"`-lenken (som peker til standardlokale-URL-en) inkluderes.

- **`<body>`-seksjon**: Hovedinnholdet på siden vises her. I dette eksempelet brukes en enkel header og et avsnitt.

### 📝 Merknader

1. **Attributter**: Attributtene som brukes (`lang`, `dir`, `rel`, `href`, `hreflang`, `property`, `content`) er hentet fra objektet som returneres av `useLocaleHead`.

2. **Generering av SEO-tagger**: Hvis `addSeoAttributes`-alternativet er satt til `true`, genererer composablen automatisk SEO-tagger for gjeldende lokale.

3. **Basis-URL**: Du kan sette din egendefinerte basis-URL med `baseUrl`-alternativet for korrekt å generere canonical- og alternate-lenker.

Dette eksempelet viser hvor enkelt det er å integrere `useLocaleHead` i applikasjonens komponenter for å sikre korrekte SEO-attributter og forbedre søkemotorindeksering av lokaliserte sider.

## 🧩 Tilpasning og livssyklus

- `useLocaleHead` abonnerer ikke på endringer selv. Den returnerer `metaObject` og `updateMeta`.
- Du bør kalle `updateMeta()` når input endres (typisk ved ruteendring), for eksempel fra en plugin:

```ts
// plugins/02.meta.ts
export default defineNuxtPlugin(() => {
  const route = useRoute()
  const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
  useHead(metaObject)
  if (import.meta.server) updateMeta()
  else
    watch(
      () => route.fullPath,
      () => updateMeta(),
      { immediate: true },
    )
})
```

## Når du skal bruke `useI18nHead` i stedet

Når `meta: true` (standard), foretrekk [`useI18nHead`](/api/composables/use-i18n-head) for **per-side**-overstyringer (egendefinert hreflang, ekstra `og:title`, delvis deaktivering). Bruk `useLocaleHead` direkte bare når `meta: false` eller du håndterer `useHead` selv.
