**Dato**: 2026-06-25

**Versjon**: `v3.21.0`

![v3.21.0 release](/images/3.21.0.png)

Denne utgivelsen legger til **`useI18nHead`** — en composable på sidenivå for i18n-SEO-overstyringer oppå den innebygde `02.meta`-pluginen. Tilpass `hreflang`, canonical, `og:url` og Open Graph-tagger per rute uten en egen meta-plugin eller `meta: false`.

## Hva er nytt? {#what’s-new}

### `useI18nHead`-composable {#usei18nhead-composable}

Kall `useI18nHead` på hvilken som helst side når `meta: true` (standard). Modulen slår sammen input-en din etter `useLocaleHead` ved hver ruteoppdatering:

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

Støtter statiske objekter, reaktive gettere, tillegg via `meta` / `link`, `replace` for innebygde grupper og `disable` for å fjerne automatisk genererte tagger. Se [`useI18nHead`](/no/composables/useI18nHead).

### `mergeI18nHead`-verktøy (`@i18n-micro/utils`) {#mergei18nhead-utility-@i18n-micro/utils}

Rammeverksuavhengig sammenslåingslogikk ligger i `@i18n-micro/utils/merge-i18n-head` — brukt av `02.meta`-pluginen og kan testes isolert. Typer (`I18nHeadInput`, `I18nHeadLink`, `I18nHeadMeta`) eksporteres fra `@i18n-micro/types`.

### Plugin-integrasjon {#plugin-integration}

- **`02.meta`** — slår sammen utdata fra `useLocaleHead` med sidetilstand fra `useI18nHead` via `useHead`
- **`01.plugin`** — tilbakestiller sideoverstyringer ved endring av rutenavn via `resetPageHead()` (delt tilstand med composablen)

### Dokumentasjon og tester {#documentation-&-tests}

- Ny veiledning: [`useI18nHead`](/no/composables/useI18nHead) med CMS-/artikkeleksempler
- Oppdatert [SEO](/no/guide/seo) og [`useLocaleHead`](/no/composables/useLocaleHead) — når du skal bruke hvilket API
- Dekning med Playwright + Vitest: SSR, SPA-navigasjon, omlasting, `nuxi generate`, delvise alternativer, `x-default`, reaktiv lasting på klienten

## Typiske brukstilfeller {#typical-use-cases}

| Scenario                                     | Tilnærming                                                     |
| -------------------------------------------- | -------------------------------------------------------------- |
| Blogg/CMS med delvise oversettelser          | `replace.hreflang` + `replace.ogAlternates` fra API-språk      |
| Egendefinert canonical fra CMS               | `replace.canonical` + `replace.ogUrl`                          |
| Kun OG på landingsside                       | `meta: [{ property: 'og:title', ... }]` — behold modulens hreflang |
| Ingen hreflang på en side                    | `disable: ['hreflang', 'x-default']`                           |
| Erstatte egen plugin (`i18nManualHreflang`)  | `useI18nHead` per innholdsside + `meta: true`                  |

**JSON-LD** forblir i `useHead({ script: [...] })` — `useI18nHead` genererer ikke strukturerte data.

## Endringer som bryter kompatibilitet {#breaking-changes}

Ingen for standard bruk av `nuxt.config`. Den nye composablen og utils-understien er rene tillegg.

## Hvorfor det betyr noe {#why-it-matters}

- **Ingen egen meta-plugin** for CMS-innlegg, nyheter eller veiledninger med URL-er per språk
- **Én enkelt pipeline** — modulstandarder + sideoverstyringer i ett `useHead`-kall
- **Typesikker** — `I18nHeadInput` for hjelpefunksjoner som `buildArticleHead(content)`

Fullstendig endringslogg publiseres sammen med utgivelsen på [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
