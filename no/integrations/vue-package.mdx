`@i18n-micro/vue` er en Vue 3-plugin med oversettelseskjernen fra Nuxt I18n Micro: reaktiv `t()`, global `$t`, fire komponenter og en valgfri vue-router-adapter. Bruk den i en Vite- eller SSR-Vue-app som ikke er bygd med Nuxt. Instansmodellen, router-kontrakten og komponentenes props deles med de andre pakkene og er beskrevet i [Rammeverk](/no/integrations/overview).

## Installer {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vue
```

```bash npm
npm install @i18n-micro/vue
```

```bash yarn
yarn add @i18n-micro/vue
```

</CodeGroup>

Peer-avhengigheter: `vue` `^3.3.0`; `vue-router` `^4.5.1 || ^5.0.0` (valgfri, bare for `@i18n-micro/vue/router`). De publiserte typene krever Vue 3.5.5 eller nyere med `skipLibCheck: false`; med `skipLibCheck: true`, den vanlige malinnstillingen, kompilerer også eldre versjoner.

## Oppsett {#setup}

```ts
// src/main.ts
import { createApp } from 'vue'
import { createI18n } from '@i18n-micro/vue'
import App from './App.vue'
import en from './locales/en.json'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales: [
    { code: 'en', iso: 'en-US', displayName: 'English' },
    { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
  ],
  defaultLocale: 'en',
})

createApp(App).use(i18n).mount('#app')
```

`locales` og `defaultLocale` kreves for `useI18n()`: den kaster `I18nLocalesKey not provided` uten dem. Send dem til `createI18n` (som ovenfor), til `useI18n({ locales, defaultLocale })`, eller via `app.provide(I18nLocalesKey, …)` og `app.provide(I18nDefaultLocaleKey, …)`.

Pluginen registrerer `I18nT`, `I18nLink`, `I18nGroup` og `I18nSwitcher` globalt og legger til `$t`, `$ts`, `$tc`, `$tn`, `$td`, `$tdr`, `$has` og `$i18n` i maler. Instansen er `i18n.global` utenfor komponenter. Andre alternativer finnes under [instansen](/no/integrations/overview#the-instance); `routeMessages` er ikke tilgjengelig i Vue, bruk `addRouteTranslations`.

## Oversett {#translate}

```vue
<script setup lang="ts">
import { useI18n } from '@i18n-micro/vue'

const { t, tc, tn } = useI18n()
</script>

<template>
  <h1>{{ t('greeting', { name: 'Ada' }) }}</h1>
  <!-- Hello, Ada! -->
  <p>{{ tc('apples', 3) }}</p>
  <!-- 3 apples -->
  <p>{{ $t('nav.home') }} · {{ tn(1234.5) }}</p>
</template>
```

`useI18n()` returnerer oversettelsesmetodene (`t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`), `locale` (en skrivbar computed), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `localePath`, `localeRoute`, `switchLocale`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `mergeTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` og `instance`.

Last inn flere ordbøker når som helst; alle komponenter som leser dem, rendres på nytt:

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Bytt locale {#switch-locale}

```ts
const { locale, switchLocale } = useI18n()

locale.value = 'de' // only the locale
switchLocale('de') // the locale, then router.push to the localized current path
```

Last inn ordboken for localet før eller etter byttet; byttet henter ingenting.

`<I18nGroup>` gir sloten sin en `t` med prefiks. Nøkler inne i `<I18nT>` eller en vanlig `t()` får ikke prefiks:

```vue
<I18nGroup prefix="profile" v-slot="{ t }">
  <h2>{{ t('title') }}</h2>
  <!-- profile.title -->
</I18nGroup>
```

## Ruting {#routing}

vue-router-adapteren ligger i en underbane, slik at hovedinngangen aldri importerer `vue-router`:

```ts
// src/main.ts
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import { createI18n } from '@i18n-micro/vue'
import { createVueRouterAdapter } from '@i18n-micro/vue/router'
import App from './App.vue'
import Home from './pages/Home.vue'
import About from './pages/About.vue'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/:locale(de)?', component: Home },
    { path: '/:locale(de)?/about', component: About },
  ],
})

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales,
  defaultLocale: 'en',
  routingStrategy: createVueRouterAdapter(router, locales, 'en'),
})

createApp(App).use(router).use(i18n).mount('#app')
```

`createVueRouterAdapter(router, locales, defaultLocale)` gir prefiks til alle locales unntatt standard (`/about`, `/de/about`) og rendrer `<I18nLink>` som `RouterLink`. Les localet fra ruten selv, for eksempel i `router.beforeEach`, og sett `i18n.global.locale.value`. Du kan også koble til en adapter senere med `i18n.setRoutingStrategy(adapter)`; for en egendefinert adapter, se [Router-adapter](/no/integrations/overview#router-adapter).

## SSR {#ssr}

- Opprett routeren, i18n-instansen og appen inne i render-funksjonen per forespørsel. Én delt instans ville lekket én besøkendes locale til en annen.
- Bruk `createMemoryHistory()` på serveren, hent localet fra URL-en, og last inn ordboken for det (og for reserve-localet) før `renderToString`.
- Send localet til klienten (for eksempel i et `window.__STATE__`-script) og opprett klientinstansen med samme `locale`, slik at hydreringen samsvarer.
- `<I18nSwitcher>` leser `window.location` bare når nedtrekksmenyen er åpen, så den rendres på serveren.

`packages/vue/playground` har et komplett par av `entry-server.ts` / `entry-client.ts`.

## SEO-head {#seo-head}

`useLocaleHead(options)` bygger `lang`/`dir`, canonical, `hreflang`- og `og:locale`-tagger fra localene og router-adapteren. Kall `updateMeta()` når ruten endres, og send `metaObject` til head-håndtereren din:

```ts
import { watch } from 'vue'
import { useRoute } from 'vue-router'
import { useHead } from '@unhead/vue'
import { useLocaleHead } from '@i18n-micro/vue'

const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
watch(() => route.fullPath, () => updateMeta(), { immediate: true })
useHead(metaObject)
```

Alternativer: `baseUrl` (streng eller funksjon), `addDirAttribute` (standard `true`), `addSeoAttributes` (standard `true`), `identifierAttribute` (standard `'id'`), `hreflangBaseLanguage` (standard `false`). Locales med `disabled: true` eller `seo: false` får ingen alternativ lenke.

## API {#api}

| Eksport | Inngang |
| --- | --- |
| `createI18n`, `useI18n`, `useLocaleHead` | `@i18n-micro/vue` |
| `I18nT`, `I18nLink`, `I18nSwitcher`, `I18nGroup` | `@i18n-micro/vue` |
| `VueI18n` (instansklasse), `I18nInjectionKey`, `I18nLocalesKey`, `I18nDefaultLocaleKey` | `@i18n-micro/vue` |
| `defaultPlural`, `FormatService`, `interpolate` | `@i18n-micro/vue` |
| Typer: `I18nRoutingStrategy`, `Locale`, `Translations`, `PluralFunc`, `Params`, `Getter`, `CleanTranslation`, `LocaleCode`, `VueI18nOptions`, `UseI18nOptions`, `UseLocaleHeadOptions`, `I18nPlugin` | `@i18n-micro/vue` |
| `createVueRouterAdapter` | `@i18n-micro/vue/router` |

`TranslationKey` re-eksporteres ikke fra `@i18n-micro/vue`; importer den fra `@i18n-micro/types`. Fullstendige signaturer: [pakkereferanse](/no/api/packages/vue).
