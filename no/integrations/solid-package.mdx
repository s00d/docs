`@i18n-micro/solid` gir SolidJS-apper en signalbasert i18n-instans, en provider, `useI18n()` og fire komponenter. Bruk den i en Solid-app som ikke er bygget med Nuxt. Lesinger av `t()` inne i JSX eller effekter sporer locale, ruten og ordbøkene; den felles modellen er beskrevet i [Rammeverk](/no/integrations/overview).

## Installasjon {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/solid
```

```bash npm
npm install @i18n-micro/solid
```

```bash yarn
yarn add @i18n-micro/solid
```

</CodeGroup>

Peer-avhengigheter: `solid-js` `^1.8.0`; `@solidjs/router` `^0.15.4 || ^1.0.0` (valgfri, bare for `@i18n-micro/solid/router`). Solid 2 støttes ikke ennå.

## Oppsett {#setup}

```tsx
// src/index.tsx
import { render } from 'solid-js/web'
import { createI18n, I18nProvider } from '@i18n-micro/solid'
import App from './App'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', messages: { en } })

render(
  () => (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en">
      <App />
    </I18nProvider>
  ),
  document.getElementById('root')!,
)
```

`<I18nProvider>` tar `i18n`, `locales`, `defaultLocale` og `routingStrategy`; en utelatt prop beholder verdien fra den ytre provideren, instansen inkludert. `getLocaleName()` og `<I18nSwitcher>` leser `locales`; uten dem har de ingenting å liste opp. Alternativene står i [instansen](/no/integrations/overview#the-instance). Instansen er den fra [runtime](/no/integrations/runtime-package), med ett signal over lageret.

## Oversett {#translate}

```tsx
import { useI18n } from '@i18n-micro/solid'

export function Greeting() {
  const { t, tc, tn } = useI18n()
  return (
    <>
      <h1>{t('greeting', { name: 'Ada' }) as string}</h1> {/* Hello, Ada! */}
      <p>{tc('apples', 3)}</p> {/* 3 apples */}
      <p>{tn(1234.5)}</p>
    </>
  )
}
```

Kall metodene inne i JSX eller en effekt slik at Solid sporer dem, også `localePath` og `getLocale`; en verdi som leses én gang i komponentkroppen, oppdateres ikke. På instansen sporer du med `i18n.locale` og `i18n.currentRoute`: `i18n.getLocale()` forblir vanlig, fordi skrivinger leser den. Lesing av locale vekkes bare av locale, så en effekt som leser den og laster en ordbok, kjører én gang. Ikke destrukturer props eller hold `t('key')`-resultater i vanlige variabler.

`useI18n()` returnerer `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`, `locale` (en accessor: `locale()`), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `switchLocale`, `localePath`, `localeRoute`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` og `instance`.

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Bytt locale {#switch-locale}

```ts
const { instance, switchLocale } = useI18n()

instance.locale = 'de' // only the locale
switchLocale('de') // the locale, then the adapter's push to the localized current path
```

Bytting laster ingenting; legg til ordboken for locale først.

`<I18nGroup>` sender en `t` med prefiks til et funksjonsbarn. `<I18nT>` og `t()` inne i den får ikke prefiks:

```tsx
<I18nGroup prefix="profile">{({ t }) => <h2>{t('title')}</h2> /* profile.title */}</I18nGroup>
```

## Ruting {#routing}

`@solidjs/router`-adapteren ligger i en understi, slik at hovedinngangen aldri importerer ruteren. Kall den under ruteren, vanligvis i ruterens `root`, der `useNavigate` og `useLocation` fungerer:

```tsx
// src/App.tsx
import { Route, Router, useLocation, useNavigate, type RouteSectionProps } from '@solidjs/router'
import { I18nLink, I18nProvider, I18nSwitcher } from '@i18n-micro/solid'
import { createSolidRouterAdapter } from '@i18n-micro/solid/router'
import { i18n, locales } from './i18n'
import { About, Home } from './pages'

function Root(props: RouteSectionProps) {
  const routingStrategy = createSolidRouterAdapter(locales, 'en', useNavigate(), useLocation())
  return (
    <I18nProvider i18n={i18n} locales={locales} defaultLocale="en" routingStrategy={routingStrategy}>
      <I18nLink to="/about">About</I18nLink>
      <I18nSwitcher />
      {props.children}
    </I18nProvider>
  )
}

export default function App() {
  return (
    <Router root={Root}>
      <Route path="/:locale?" component={Home} />
      <Route path="/:locale?/about" component={About} />
    </Router>
  )
}
```

Adapteren gir prefiks til alle locales unntatt standarden (`/about`, `/de/about`), og gjengir `<I18nLink>` som ruterens `<A>`. `getCurrentPath` leser ruterens reaktive plassering, så aktive lenker og språkvelgeren følger den; en egendefinert strategi får det samme ved å lese et signal der. Merk rekkefølgen på argumentene: `(locales, defaultLocale, navigate, location)`. For andre rutere skriver du en adapter med `getCurrentPath`, `push` og `replace` (alle påkrevd) — se [Ruteradapter](/no/integrations/overview#router-adapter).

## SSR {#ssr}

For servergjengivelse bygger du med `vite-plugin-solid`: pakkens eksportbetingelse `solid` gir den kildekoden, slik at den kompileres for serveren. Den forhåndsbygde `dist` er bare for nettleseren. Instansen har ingen `destroy()`; opprett én per app, eller én per forespørsel på serveren, og la den bli søppeltømt.
