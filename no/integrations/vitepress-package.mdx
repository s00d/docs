---

`@i18n-micro/vitepress` legger til runtime-ordbøker på et VitePress-nettsted: `$t` og `<I18nT>` inne i markdown, stihjelpere og SEO-tagger, bygget på [`@i18n-micro/vue`](/no/integrations/vue-package). Bruk den når de samme UI-strengene dukker opp på mange sider og du ikke vil duplisere dem per locale. Localet følger VitePress' egne sti-locales (`/`, `/fr/`).

## Når du bør bruke den {#when-to-use-it}

| Behov | Løsning |
|------|----------|
| Duplisert `.md`, URL-prefikser | VitePress `locales` |
| Runtime-`$t` / komponenter / stisynkronisering / SEO-head | `@i18n-micro/vitepress` |
| Etiketter i standardtemaets ramme (`docFooter`, søke-UI) | Din egen `themeConfig` per locale |

<Tip>

**Playground** — [`packages/vitepress/playground`](https://github.com/s00d/nuxt-i18n-micro/tree/main/packages/vitepress/playground) — `pnpm -C packages/vitepress/playground dev`

</Tip>

## Installasjon {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vitepress
```

```bash npm
npm install @i18n-micro/vitepress
```

```bash yarn
yarn add @i18n-micro/vitepress
```

</CodeGroup>

Peer-avhengigheter: `vitepress` `>=1.0.0 || >=2.0.0-alpha.0`, `vue` `^3.3.0`. Node-skript bruker `@i18n-micro/node`, som installeres sammen med pakken og re-eksporteres via `/node`. De publiserte typene krever Vue 3.5.5 eller nyere med `skipLibCheck: false`; med `skipLibCheck: true`, den vanlige malinnstillingen, kompilerer også eldre versjoner.

## Oppsett {#setup}

```
locales/en.json
locales/fr.json
locales/pages/guide/demo/en.json   # optional page-scoped
locales/pages/guide/demo/fr.json
```

Sidefiler tilordnes rutenavn på samme måte som i Nuxt/Astro (`guide/demo` → `guide-demo`).

### 1. Konfigurasjon — `@i18n-micro/vitepress/config` {#1-config-—-@i18n-micro/vitepress/config}

```ts
// .vitepress/config.mts
import { defineConfig } from 'vitepress'
import { withI18n, buildVitePressLocales } from '@i18n-micro/vitepress/config'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English', og: 'en_US' },
  { code: 'fr', iso: 'fr-FR', displayName: 'Français', og: 'fr_FR' },
]
const defaultLocale = 'en'

export default defineConfig(
  withI18n(
    {
      locales: buildVitePressLocales(locales, defaultLocale),
      // themeConfig.i18nRouting is injected automatically
    },
    {
      locale: defaultLocale,
      defaultLocale,
      locales,
      translationDir: 'locales',
      metaBaseUrl: 'https://example.com', // optional SEO head
    },
  ),
)
```

### 2. Tema — `@i18n-micro/vitepress/theme` {#2-theme-—-@i18n-micro/vitepress/theme}

```ts
// .vitepress/theme/index.ts
import DefaultTheme from 'vitepress/theme'
import { defineI18nTheme } from '@i18n-micro/vitepress/theme'

export default defineI18nTheme(DefaultTheme)
```

Det første localet hentes fra gjeldende sti før installasjon (ingen glimt av standard-localet på `/fr/…`).

### Avansert: manuell `createI18n` {#advanced-manual-createi18n}

Én fabrikk for klienten: Vue-plugin + stimetoder + `enhanceApp` (ingen separate eksporter av router-hjelpere).

```ts
import { createI18n, messagesFromGlob } from '@i18n-micro/vitepress'

const i18n = createI18n({
  locale: 'en',
  defaultLocale: 'en',
  locales: [{ code: 'en' }, { code: 'fr' }],
  messages: messagesFromGlob(import.meta.glob('../../locales/*.json', { eager: true })),
})

i18n.localizePath('/guide', 'fr')
// in theme enhanceApp:
i18n.enhanceApp({ app, router })
```

### Node-skript — `@i18n-micro/vitepress/node` {#node-scripts-—-@i18n-micro/vitepress/node}

Bruker `createI18n` / `loadTranslations` fra `@i18n-micro/node` (samme som Astro og CLI), og kobler deretter på VitePress-stimetoder med `BaseI18n.extend`:

```ts
import { createI18n } from '@i18n-micro/vitepress/node'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  translationDir: './locales',
  locales: ['en', 'fr'],
  defaultLocale: 'en',
})
await i18n.loadTranslations()
i18n.t('cta.readMore')
i18n.localizePath('/guide', 'fr')
```

Ren Node uten stier: `import { createI18n } from '@i18n-micro/node'`.

## Oversettelser på siden {#in-page-translations}

Hver VitePress-markdownfil er en Vue-SFC.

### Globale komponenter og `$t` (anbefalt i markdown) {#global-components-and-$t-recommended-in-markdown}

`createI18n` / `defineI18nTheme` installerer `@i18n-micro/vue`, som registrerer `I18nT` / `I18nLink` / `I18nGroup` / `I18nSwitcher` og `$t` / `$tc` / `$ts`.

```md
{{ $t('cta.readMore') }}

<I18nT keypath="greeting" :params="{ name: 'VitePress' }" />

<I18nLink to="/guide/demo">Demo</I18nLink>
```

### `useI18n` i `<script setup>` {#usei18n-in-<script-setup>}

```md
<script setup>
import { useI18n } from '@i18n-micro/vitepress'
const { t, tc, locale, localePath, switchLocale } = useI18n()
</script>

# {{ t('section.title') }}
```

## Språkmeny {#language-dropdown}

Når `locales` har mer enn én oppføring, viser VitePress sin egen språkmeny (`VPNavBarTranslations`). `withI18n` kobler opp `themeConfig.i18nRouting` slik at globusen samsvarer med `<I18nSwitcher>` / stihjelperne.

Bruk `<I18nSwitcher>` bare i egendefinerte layouter, ikke ved siden av standardglobusen.

## SSR-merknader {#ssr-notes}

- Locale ved prerendering kommer fra URL-stien, ikke fra informasjonskapsler.
- Temakode må ikke røre `window` ved import.
- Importer `defineI18nTheme` fra `/theme` slik at evaluering av Node-konfigurasjonen aldri laster `virtual:i18n-micro/*`.

## API-overflate {#api-surface}

| Eksport | Rolle |
|--------|------|
| `createI18n` (`.`) | Klient: Vue-plugin + stimetoder + `enhanceApp` |
| `getLocaleFromPath` / `stripSiteBase` / `routeNameFromPath` (`.`) | Manuell locale-synkronisering når `syncWithVitePress: false` |
| `createI18n` (`/node`) | Node: `@i18n-micro/node` + stimetoder |
| `defineI18nTheme` (`/theme`) | Tema uten boilerplate |
| `withI18n` (`/config`) | Konfigurasjon + virtuelle moduler + valgfri SEO |
| `buildVitePressLocales` (`/config`) | Bygg VitePress-`locales` fra `Locale[]` |
| `buildVitePressLocaleHead` (`/config`) | Manuell SEO-head (brukes også av `metaBaseUrl`) |
| `messagesFromGlob` | Valgfri glob → meldingskart for `createI18n` |
| `useI18n` / `I18nT` / … | Re-eksportert fra `@i18n-micro/vue` |
| `BaseI18n.extend` (`@i18n-micro/core`) | Koble egendefinerte metoder på en hvilken som helst i18n-instans |

## Nettsteder i OpenAPI-stil (integrasjonslåser) {#openapi-style-sites-integration-locks}

Regresjonstester: `packages/vitepress/tests/integration-openapi.test.ts` (dype stier, `base=/openapi_docs/`, synkronisering av + manuelt locale, Node-generatorer, SEO).

| Mønster | Gjør dette |
|---------|---------|
| Dype `/…/{spec}/{op}`-sider, bare rot-UI-JSON | Foretrekk standard `syncWithVitePress: true` (beholder `setRoute('index')` når det ikke finnes noen sideordbok) **eller** `syncWithVitePress: false` + `getLocaleFromPath` |
| Kall aldri `setRoute(deepName)` uten sideordbøker | Rot-UI-nøkler forsvinner til `setRoute('index')` |
| Generatorer / `getTranslation` | `createI18n` fra `/node` + `await loadTranslations()` + `i18n.t(key)` (sett `i18n.locale`) |
| Egendefinert canonical i `transformPageData` | Send `meta: false` til `withI18n` (unngå doble tagger) |
| Pakkens SEO med nettstedets base | `metaBaseUrl` + VitePress `base` → absolutte URL-er inkluderer base |
| Navnebytte fra eldre pakkebygg | `withI18nMicro` → `withI18n`, `createVitePressI18n` → `createI18n`, `loadMessages` → node `createI18n` |
