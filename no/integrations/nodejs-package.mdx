`@i18n-micro/node` er [runtime](/no/integrations/runtime-package)-instansen pluss en laster som leser en oversettelsesmappe fra disk. Bruk den i en Express- eller Fastify-server, en CLI, en e-post- eller PDF-generator, eller ethvert skript som trenger de samme JSON-filene som Nuxt-appen din. Du laster filene én gang og oversetter per forespørsel uten å dele muterbar tilstand mellom forespørsler.

## Installasjon {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/node @i18n-micro/utils
```

```bash npm
npm install @i18n-micro/node @i18n-micro/utils
```

```bash yarn
yarn add @i18n-micro/node @i18n-micro/utils
```

</CodeGroup>

Ingen peer-avhengigheter; Node.js `>=20`. `@i18n-micro/utils` trengs bare for `Accept-Language`-hjelperen nedenfor.

## Oppsett {#setup}

Lasteren leser [Nuxt-mappeoppsettet](/no/guide/translations): `locales/en.json` er en rotordbok, `locales/pages/blog/post/en.json` tilhører ruten `blog-post`.

```ts
import { createI18n } from '@i18n-micro/node'

const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

i18n.t('greeting', { name: 'Ada' }) // 'Hello, Ada!'
i18n.t('title', undefined, undefined, 'blog-post') // from locales/pages/blog/post/en.json
```

Alternativene er de samme som for runtime (se [instansen](/no/integrations/overview#the-instance)) pluss `translationDir` og `disablePageLocales` (behandle `pages/**`-filer som rotordbøker). `i18n.reload()` tømmer alle ordbøker og leser mappen på nytt, for en filovervåker under utvikling.

`loadTranslations(dir, disablePageLocales?)` eksporteres også separat og returnerer `{ root, routes }`:

```ts
import { loadTranslations } from '@i18n-micro/node'

const { root, routes } = await loadTranslations('./locales')
// root:   { en: {...}, de: {...} }
// routes: { 'blog-post': { en: {...}, de: {...} } }
```

## Per forespørsel {#per-request}

En instans har én locale og én rute. Å bytte `i18n.locale` på en delt instans inne i en forespørselshåndterer gir kappløp med samtidige forespørsler. `run` gir en forespørsel sin egen:

```ts
const i18n = createI18n({ locale: 'en', fallbackLocale: 'en', translationDir: './locales' })
await i18n.loadTranslations()

// `() => next()`: `run` hands its callback the fork, and Express reads an argument of `next` as an error
app.use((req, res, next) => i18n.run(pickLocale(req), () => next()))

app.get('/', (req, res) => {
  res.send(i18n.t('greeting')) // the request's locale, in everything it awaits
})
```

Inne i `run` leser og setter den delte instansen forespørselens locale og rute (`AsyncLocalStorage`); forken starter på gjeldende rute, og `i18n.setRoute(...)` inne i callbacken endrer ruten for den forespørselen. Callbacken får også forespørselens fork: ordbøker som skrives til den, blir i forespørselen, ordbøker som skrives til den delte instansen, når alle.

Uten `AsyncLocalStorage` returnerer `i18n.fork(locale)` samme type instans som du kan sende rundt.

`reload()` leser katalogen på nytt; de gamle ordbøkene svarer til de nye er på plass.

## Velg locale {#pick-the-locale}

`detectLocaleFromAcceptLanguage(header, locales)` respekterer `q`-vekter og matcher `de-DE` med en `de`-locale (og `de` med `de-DE`). Den returnerer `null` når ingenting matcher.

```ts
import express from 'express'
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

const app = express()

app.get('/hello', (req, res) => {
  const locale = detectLocaleFromAcceptLanguage(req.headers['accept-language'], locales) ?? 'en'
  const i18n = byLocale.get(locale)!
  res.json({ message: i18n.t('greeting', { name: 'Ada' }) })
})
```

For URL-prefiks, informasjonskapsel og header samlet bruker `resolveLocale({ defaultLocale, validLocales, url, cookie, acceptLanguage, autoDetectLanguage: true })` fra `@i18n-micro/utils/resolve-locale` modulens prioritet: URL, deretter informasjonskapsel, deretter `Accept-Language`, deretter standard. Ugyldige verdier hoppes over.

Inne i en Nuxt-app trenger du ikke denne pakken på serveren: bruk modulens [oversettelser på serversiden](/no/guide/server-side-translations).

## API {#api}

| Eksport | Merknader |
| --- | --- |
| `createI18n(options)`, `I18n` | runtime-instans + `translationDir`, `loadTranslations(dir?)`, `reload()` |
| `loadTranslations(dir, disablePageLocales?)` | `{ root, routes }` |
| `loadRootTranslations(dir, disablePageLocales?)` | bare `root` |
| `FormatService`, `interpolate` | fra core |
| Typer: `I18nOptions`, `LoadedTranslations`, `Translations`, `Locale`, `PluralFunc`, `Params` | |

Instansmetodene er listet på [Runtime](/no/integrations/runtime-package#api). Fullstendige signaturer: [pakkereferanse](/no/api/packages/node).
