---
title: "Egendefinert språkgjenkjenning"
description: "Velg språket selv — etter domene, header eller brukerprofil — med en serverplugin og useI18nLocale().setLocale()."
---

Den innebygde gjenkjenningen leser URL-en, en informasjonskapsel og `Accept-Language`. Når språket avhenger av noe annet — domenet, en geo-header satt av CDN-et ditt, en brukerprofil — setter du det selv i en plugin som kjører før i18n-pluginen. Modulen laster deretter oversettelsene for det språket og bruker det til omdirigeringer akkurat som om den hadde gjenkjent det selv. Reglene for når et valgt språk vinner over URL-en finner du under [Språkgjenkjenning](/no/guide/locale-detection); denne siden viser hvordan du kobler inn din egen kilde.

## Sett språket i en serverplugin {#set-the-locale-in-a-server-plugin}

```ts
// plugins/i18n-locale.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10, // before the i18n plugin (order -5)
  setup() {
    const { setLocale } = useI18nLocale()
    const host = (useRequestHeaders(['host']).host ?? '').split(':')[0]! // without the port

    if (host.endsWith('.de')) setLocale('de')
    else if (host.endsWith('.fr')) setLocale('fr')
  },
})
```

`setLocale(code)` skriver språktilstanden (`useState('i18n-locale')`) og, når en språkinformasjonskapsel er konfigurert, informasjonskapselen. Bruk den i stedet for å skrive `useState` eller `useCookie` selv. Send bare inn aktiverte språkkoder.

Behold pluginen som `.server.ts` når den leser request-headere: de finnes ikke i nettleseren. En `.client.ts`-plugin er stedet for kilder som bare finnes i nettleseren, for eksempel `localStorage`.

## Slå av det innebygde Accept-Language-steget {#turn-off-the-built-in-accept-language-step}

Pluginen din og `Accept-Language` kan være uenige. For å la bare koden din (pluss URL-en og informasjonskapselen) avgjøre, slår du av headeren:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    autoDetectLanguage: false,
  },
})
```

[`autoDetectLanguage`](/no/api/module-options#autodetectlanguage) styrer bare header-steget. URL-en og en gyldig informasjonskapsel teller fortsatt.

## Hva skjer videre {#what-happens-next}

Effekten av `setLocale` avhenger av [strategien](/no/guide/strategy):

| Strategi | Effekt av `setLocale('de')` i pluginen |
| --- | --- |
| `no_prefix` | Siden gjengis på tysk; URL-en endres ikke. |
| `prefix`, `prefix_except_default` | På en sti uten prefiks der [`autoDetectPath`](/no/api/module-options#autodetectpath) tillater omdirigeringer (som standard bare `/`), svarer serveren med `302` til den tyske URL-en. En URL med språkprefiks beholder det. |
| `prefix_and_default` | Ingen omdirigering: URL-en uten prefiks er en gyldig side for standardspråket. |

Under prefiksstrategiene er et språk i URL-en brukerens valg, og pluginen din overstyrer det ikke. `autoDetectPath: '*'` er unntaket: serveren flytter da URL-er med prefiks basert på informasjonskapsel og `Accept-Language` og ignorerer tilstanden, men `setLocale()` skriver også informasjonskapselen når en er konfigurert, så fra neste forespørsel kan pluginens valg omdirigere en URL med prefiks. Behold `'/'` eller bruk `'no_prefix'` når eksplisitte språk-URL-er må vinne. Bruk pluginen til å velge hvor en besøkende havner, ikke til å skrive om lenker de har fulgt.

## Respekter et språk brukeren har valgt {#respect-a-locale-the-user-picked}

Når en bruker bytter språk, skriver byttet informasjonskapselen. Hopp over din egen gjenkjenning når det allerede finnes en gyldig preferanse:

```ts
// plugins/i18n-locale.server.ts
import { detectLocaleFromAcceptLanguage } from '@i18n-micro/utils/accept-language'

export default defineNuxtPlugin({
  name: 'i18n-custom-locale',
  enforce: 'pre',
  order: -10,
  setup() {
    const { getPreferredLocale, setLocale, validLocales } = useI18nLocale()
    if (getPreferredLocale()) return // valid state or cookie: keep it

    const country = useRequestHeaders(['x-country'])['x-country']
    if (country === 'JP') return setLocale('ja')

    const header = useRequestHeaders(['accept-language'])['accept-language']
    setLocale(detectLocaleFromAcceptLanguage(header, validLocales))
  },
})
```

`getPreferredLocale()` returnerer tilstanden eller informasjonskapselen bare når den er et aktivert språk, så en utdatert informasjonskapsel stopper ikke gjenkjenningen. `detectLocaleFromAcceptLanguage` er den q-verdi-bevisste matcheren modulen selv bruker (installer `@i18n-micro/utils` for å importere den); `setLocale(null)` gjør ingenting.

## Ett domene per språk {#one-domain-per-locale}

Hvis hvert domene skal levere sine egne språk, trenger du ingen plugin: gi hvert språk en `baseUrl`, sett `baseDefault: true` på standardspråket for hvert domene, og bygg én gang (et statisk nettsted kjører fortsatt `nuxi generate` per domene). Se [Lag og domener](/no/guide/layers#multiple-domains).
