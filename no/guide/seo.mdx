---

Med `meta: true` (standard) får hver lokaliserte side `<html lang dir>`, en canonical-lenke, `hreflang`-alternativer, `x-default` og Open Graph-tagger for locale. Du trenger denne siden når du vil angi den offentlige opprinnelsen (origin), justere hvilke locales som vises i taggene, eller overstyre dem for én side. De fleste nettsteder trenger bare en `site.url` eller `metaBaseUrl` og riktige `iso`-koder.

## Minimalt oppsett {#minimal-setup}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
      { code: 'ar', iso: 'ar-SA', dir: 'rtl' },
    ],
    defaultLocale: 'en',
    metaBaseUrl: 'https://example.com',
  },
})
```

`/de/about` rendrer da:

```html
<html lang="de-DE" dir="ltr">
<link rel="canonical" href="https://example.com/de/about">
<link rel="alternate" hreflang="en-US" href="https://example.com/about">
<link rel="alternate" hreflang="de-DE" href="https://example.com/de/about">
<link rel="alternate" hreflang="ar-SA" href="https://example.com/ar/about">
<link rel="alternate" hreflang="x-default" href="https://example.com/about">
<meta property="og:locale" content="de_DE">
<meta property="og:url" content="https://example.com/de/about">
<meta property="og:locale:alternate" content="en_US">
<meta property="og:locale:alternate" content="ar_SA">
```

## Tekstretning {#text-direction}

`<html dir>` kommer fra locale-ens `dir`. Uten en slik verdi får et språk som skrives fra høyre mot venstre `rtl`, lest fra `iso` (eller `code`): arabisk, hebraisk, persisk, urdu og noen få andre, samt enhver tagg med et RTL-skriftsystem, som `az-Arab`. Alle andre locales får ikke noe `dir`-attributt, noe nettlesere tolker som `ltr`.

<Warning>

**`dir: 'auto'` koster parsetid på store sider** — `auto` på `<html>` får nettleseren til å finne retningen ut fra innholdet mens den parser. I Chromium vokser denne kostnaden raskere enn siden: rundt 100 ms ved 5 000 elementer og 1 s ved 20 000. Bruk det bare for en liten side der du ikke kan vite språket.

</Warning>

## Hvilke tagger du får {#which-tags-you-get}

- **hreflang**: én tagg per locale som serverer siden, med verdien `iso` (eller `code` når `iso` mangler), og URL-en med samme spørrestreng som canonical. En side som er begrenset med [Sidekonfigurasjon](/no/guide/per-component-translations) eller `routeLocales`, lister bare sine locales. [`hreflangBaseLanguage: true`](/no/api/module-options#hreflangbaselanguage) legger også til basisspråket (`es-ES` → `es`) for den første regionale locale-en.
- **x-default**: URL-en til standard-locale, bare når standard-locale serverer siden.
- **og:locale**: avledet fra `iso` (`en-US` → `en_US`). Sett `og` på locale-en når kartleggingen ikke er direkte, for eksempel `{ code: 'zh', iso: 'zh-Hans', og: 'zh_CN' }`; uten noen av dem skrives ingen `og:locale`, og utviklingsmodus gir en advarsel.
- **canonical / og:url**: gjeldende URL uten spørreparametere, bortsett fra dem i [`canonicalQueryWhitelist`](/no/api/module-options#canonicalquerywhitelist) (standard `page`, `sort`, `filter`, `search`, `q`, `query`, `tag`).

Etter strategi:

| Strategi | hreflang og x-default | canonical, og:url, og:locale, html-attributter |
| --- | --- | --- |
| `prefix`, `prefix_except_default`, `prefix_and_default` | ja | ja |
| `no_prefix` | nei (én URL serverer alle locales) | ja |

## Angi den offentlige opprinnelsen {#set-the-public-origin}

Absolutte URL-er bruker den første av:

1. [`metaBaseUrl`](/no/api/module-options#metabaseurl);
2. `site.url` fra `nuxt-site-config` (installert av `@nuxtjs/seo`);
3. forespørselens opprinnelse, med `app.baseURL` lagt til.

Lås en av de to første.

<Warning>

Reserveløsningen med forespørselens opprinnelse leser `X-Forwarded-Host` og `X-Forwarded-Proto`, fordi [`metaTrustForwardedHost`](/no/api/module-options#metatrustforwardedhost) og `metaTrustForwardedProto` som standard er `true`. Det er bare trygt bak en proxy som overskriver disse headerne; ellers kan en klient velge verten i canonical-lenkene dine, og en cache kan videreformidle den siden.

Hvis appen kan nås direkte, lås `metaBaseUrl`: i motsetning til å sette begge alternativene til `false` ignorerer dette også en forfalsket `Host`. Se [Bak en proxy eller CDN](/no/guide/deployment#behind-a-proxy-or-cdn).

</Warning>

Reserveløsningen er nyttig når én utrulling svarer for flere domener: `https://site-a.com/en/about` og `https://site-b.com/en/about` får hver sin egen opprinnelse.

Med `baseUrl` på locales bruker en kjent vert sin egen `baseUrl`, foran `metaBaseUrl` og `site.url`, slik at canonical og `og:url` blir værende på det domenet og `hreflang` peker hver locale til sitt domene. Enhver annen vert bruker `metaBaseUrl`, ellers standard-locale sin `baseUrl`, ellers `site.url`, slik at en forfalsket `Host` ikke kan nå taggene dine. Hvis ingen av disse er satt, gjelder reserveløsningen med forespørselens opprinnelse, og bygget gir en advarsel. Se [Lag og domener](/no/guide/layers#multiple-domains).

## Utelat locales eller sider {#leave-locales-or-pages-out}

```ts
i18n: {
  locales: [
    { code: 'en', iso: 'en-US' },
    { code: 'ru', iso: 'ru-RU', seo: false }, // routable, but not in hreflang / og:locale:alternate
    { code: 'fr', iso: 'fr-FR', disabled: true }, // no routes, no switching, no tags
  ],
}
```

Hvis standard-locale har `seo: false`, skrives ingen `x-default`. For å slå av taggene for én side bruker du `disableMeta` i [Sidekonfigurasjon](/no/guide/per-component-translations#turn-off-seo-tags), eller [`routeDisableMeta`](/no/api/module-options#routedisablemeta) i konfigurasjonen.

## Overstyr tagger på én side {#override-tags-on-one-page}

For CMS-innhold der bare noen oversettelser finnes, eller URL-er kommer fra et API, erstatter du de genererte taggene med [`useI18nHead`](/no/composables/useI18nHead):

```vue
<script setup lang="ts">
const { data: article } = await useFetch('/api/articles/hello')
// article.value.urls = { en: 'https://example.com/blog/hello', de: 'https://example.com/de/artikel/hallo' }

useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title ?? '' }],
  replace: {
    hreflang: Object.entries(article.value?.urls ?? {}).map(([locale, href]) => ({ rel: 'alternate', hreflang: locale, href })),
    ogAlternates: Object.keys(article.value?.urls ?? {}),
  },
}))
</script>
```

`replace` kan også sette eller fjerne `canonical`, `xDefault`, `ogLocale` og `ogUrl`; `disable` fjerner hele grupper (`'hreflang'`, `'x-default'`, `'canonical'`, `'og'`, `'og-alternates'`, `'html'`). Send inn en getter slik at verdiene beregnes på nytt etter et locale-bytte. For slugs per locale setter du `$setI18nRouteParams` først ([Lokaliserte stier](/no/guide/custom-locale-routes#per-locale-slugs)), så bruker de genererte alternativene dem allerede.

## Avsluttende skråstrek {#trailing-slash}

`$localePath`, `$switchLocalePath`, ruteobjektet fra `$switchLocaleRoute`, `<i18n-link>`, `<i18n-switcher>`, locale-omdirigeringer og SEO-URL-ene følger én regel for skråstrek: `experimental.defaults.nuxtLink.trailingSlash` som standard, eller [`trailingSlash`](/no/api/module-options) i i18n-konfigurasjonen når i18n-stiene skal være annerledes.

## Nuxt SEO {#nuxt-seo}

[`@nuxtjs/seo`](https://nuxtseo.com/) (sitemap, robots, schema.org) fungerer med denne modulen via `nuxt-site-config` 4+. List `nuxt-i18n-micro` først, slik at site config kan lese locales, og sett `site.url` én gang — den mater også taggene ovenfor.

```ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro', '@nuxtjs/seo'],
  site: { url: 'https://example.com', name: 'My Site' },
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
  },
})
```

Et oversatt nettstedsnavn og en oversatt beskrivelse kommer fra nøklene `nuxtSiteConfig.name` / `nuxtSiteConfig.description` i locale-filene dine. Feilen `Plugin nuxt-seo:defaults depends on nuxt-site-config:i18n but they are not registered` betyr at `@nuxtjs/seo` er eldre enn 3; oppgrader den ([#133](https://github.com/s00d/nuxt-i18n-micro/issues/133)).
