Alternativet `strategy` bestemmer om et locale vises i URL-en, og for hvilke locales. Velg det én gang, før du publiserer URL-er: å endre det senere endrer hver lenke. Modulen genererer deretter de lokaliserte rutene ved bygging, og `$localePath`, `<i18n-link>` og språkvelgeren leser dem.

## De fire strategiene {#the-four-strategies}

![/about-siden på en (standard) og de under hver strategi; de samme URL-ene er listet i teksten nedenfor](/images/diagrams/strategies.svg)

**Type** `Strategies` · **Standard** `'prefix_except_default'`

URL-rutingstrategi for locale-prefikser.

- `'no_prefix'` — ikke noe locale i URL-en; locale lagres i en informasjonskapsel.
- `'prefix_except_default'` — prefiks på alle locales unntatt standard.
- `'prefix'` — alltid prefiks, også for standard-localet.
- `'prefix_and_default'` — som `prefix`, men standard-localet er også tilgjengelig uten prefiks.

URL-er for en `about`-side med `defaultLocale: 'en'` og locales `en`, `de`:

| Strategi | Engelsk | Tysk | Serveres ikke |
| --- | --- | --- | --- |
| `prefix_except_default` (standard) | `/about` | `/de/about` | `/en` og `/en/about` gir 404 |
| `prefix` | `/en/about` | `/de/about` | `/about` omdirigerer til en URL med prefiks |
| `prefix_and_default` | `/about` og `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | localet er ikke i URL-en |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

Strategien fastsettes ved bygging: en runtime-overstyring av den ignoreres med en advarsel ([Runtime-overstyringer](/no/guide/runtime-overrides)).

## Hvilken du bør velge {#which-one-to-choose}

- **`prefix_except_default`**: de fleste nettsteder. Eksisterende URL-er uten prefiks fortsetter å fungere for standardspråket.
- **`prefix`**: alle språk er likestilte; `/` fører alltid til en startside med prefiks.
- **`prefix_and_default`**: du trenger at både `/en/...` og URL-ene uten prefiks fungerer, for eksempel mens du går over fra det ene til det andre. URL-er uten prefiks omdirigeres aldri.
- **`no_prefix`**: apper bak innlogging, eller én URL per side for alle språk. Localet kommer fra en informasjonskapsel eller `?locale=`. Søkemotorer ser ett språk per URL, så ingen `hreflang`-alternativer genereres.

Hvordan localet velges for en URL, og når en besøkende blir omdirigert, står i [Locale-deteksjon](/no/guide/locale-detection).

## Genererte ruter {#generated-routes}

Ved bygging får hver side de ruteoppføringene strategien krever. Hver oppføring har `meta.i18n = { name, locales }`: siden den viser og de locales den betjener. Lenker, bytter og omdirigeringer besvares alle ut fra disse oppføringene, så en URL modulen deler ut, er alltid en som routeren betjener.

Locales som deler sidens sti, deler én oppføring, `/:locale(de|fr)/about`. Et locale med sin egen sti får sin egen oppføring, kalt `localized-<page>-<locale>`:

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

Egendefinerte stier, locale-lister per side og hvordan du ekskluderer en side fra lokalisering, står i [Lokaliserte stier](/no/guide/custom-locale-routes) og [Sidekonfigurasjon](/no/guide/per-component-translations). Prefikset `localized-` er [`localizedRouteNamePrefix`](/no/api/module-options#localizedroutenameprefix).

<Warning>

**Rutenavn genereres** — Ikke hardkod `localized-…`-navn i `router.push({ name })`. Send sidens eget navn til `$localeRoute` eller `<i18n-link>`; de velger riktig oppføring.

</Warning>

## Lenke til en side på et locale {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- Både navngitte ruter og stier fungerer. En sti matches mot de genererte rutene, så ethvert locales variant av den godtas.
- Et locale som ikke betjener siden (se `locales` i [Sidekonfigurasjon](/no/guide/per-component-translations)), lenker til startsiden for det localet i stedet for til en manglende side.
- Parametere per locale (en oversatt slug) går gjennom `$setI18nRouteParams`, se [Lokaliserte stier](/no/guide/custom-locale-routes).

Signaturene står i [Metoder](/no/api/methods).

## Detaljer om `no_prefix` {#no_prefix-details}

- [`localeCookie`](/no/api/module-options#localecookie) er som standard `'user-locale'` under `no_prefix`, så valget overlever en ny innlasting.
- `$switchLocale('de')` laster den tyske ordboken og erstatter gjeldende historikkoppføring; URL-en endres ikke.
- Egendefinerte stier per locale fungerer fortsatt: med `globalLocaleRoutes: { about: { de: '/ueber-uns' } }` får tyske lesere `/ueber-uns`. Den URL-en rendres alltid på tysk, uansett hva den besøkende foretrekker, og en side begrenset til enkelte locales rendres på ett av dem. En sti som flere locales deler (`en` og `de` begge på `/page/:id`), rendres med preferansen når den er ett av dem. Selve preferansen består: neste side går tilbake til den.
- [`noPrefixRedirect: true`](/no/api/module-options#noprefixredirect) omdirigerer den opprinnelige stien til en side med egendefinert sti i standard-localet: til den egendefinerte stien for den besøkendes locale, ellers til standard-localets (`/about` → `/about-us` når `en` har `/about-us`, → `/ueber-uns` med informasjonskapsel `de`). Et locale uten egen egendefinert sti blir på den opprinnelige stien og rendres der. Sider med parametere omdirigeres ikke.

## Apper uten `pages/` {#apps-without-pages}

Med `pages: false` finnes det ingen sideruter å lokalisere. Bruk bare rotoversettelsesfiler (`disablePageLocales: true`); deteksjon, informasjonskapselen og `$switchLocale` fungerer fortsatt. Varianten `pages-false` av `test/fixtures/basic` i repositoriet er et fungerende oppsett.
