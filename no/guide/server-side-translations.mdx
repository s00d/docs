---

Serverhandlere i `server/api/` og `server/routes/` kan oversette strenger og lese forespørselens locale med to automatisk importerte hjelpere. Bruk dem for API-svar, e-poster, feeder eller alt som rendres utenfor en Vue-side. De leser de samme oversettelsesfilene som sidene dine og oppdager locale fra forespørselen.

## Oversett i en handler {#translate-in-a-handler}

```ts
// server/api/greeting.get.ts
export default defineEventHandler(async (event) => {
  const t = await useTranslationServerMiddleware(event)
  return { message: t('greeting', { name: 'Ada' }) }
})
```

```bash
curl 'http://localhost:3000/api/greeting?locale=de'
# {"message":"Hallo, Ada!"}
```

`useTranslationServerMiddleware(event, defaultLocale?, locale?)` er asynkron og returnerer `t(key, params?, defaultValue?)`. `t` returnerer strengen, interpolerer `{name}`-parametere, og returnerer en ikke-tom `defaultValue`, ellers nøkkelen, når nøkkelen mangler.

`t` ser bare `index`-delen (chunk): rotfilene (`locales/<locale>.json`) pluss `locales/pages/index/` når den finnes (bare rotfilene med `disablePageLocales`). Nøkler for andre sider lastes ikke. For dem laster du delen selv:

```ts
const { data } = await loadTranslationsFromServer('de', 'about') // Translations object of the about page
```

## Les forespørselens locale {#read-the-request-locale}

```ts
// server/api/locale.get.ts
export default defineEventHandler((event) => {
  const { current, isDefault, locale } = useLocaleServerMiddleware(event)
  return { current, isDefault, dir: locale?.dir ?? 'ltr' }
})
```

`useLocaleServerMiddleware(event, defaultLocale?, locale?)` er synkron og returnerer:

```ts
interface LocaleInfo {
  current: string // detected locale code
  default: string // defaultLocale, runtime overrides included (fixed at build under prefix_except_default / prefix_and_default)
  fallback: string // fallbackLocale, else the default
  available: string[] // enabled locale codes
  locale: Locale | null // the config entry of `current`
  isDefault: boolean
  isFallback: boolean
}
```

## Hvordan locale velges {#how-the-locale-is-chosen}

Begge hjelperne bruker samme rekkefølge på alle serverruter, enten de er under `/api` eller ikke:

1. spørreparameteren `?locale=` (første verdi når den gjentas);
2. en `[locale]`-ruteparameter, eller et locale-prefiks i stien (`/de/...`);
3. locale-informasjonskapselen, når [`localeCookie`](/no/api/module-options#localecookie) er satt (`hash-locale` under `hashMode`);
4. `Accept-Language`, når `autoDetectLanguage` er på (q-verdier respekteres);
5. `defaultLocale`.

Ugyldige og deaktiverte koder hoppes over i hvert trinn. Dette er rekkefølgen for API-et; en siderendring ignorerer `?locale=` under prefiksstrategiene. Begge rekkefølgene sammenlignes på [Locale-deteksjon](/no/guide/locale-detection).

## Tving en locale {#force-a-locale}

Send inn det tredje argumentet for å hoppe over deteksjon, for eksempel i en jobb som sender e-post på brukerens språk:

```ts
export default defineEventHandler(async (event) => {
  const user = await getUser(event) // your code
  const t = await useTranslationServerMiddleware(event, undefined, user.locale)
  return sendMail(user.email, t('mail.welcome.subject'))
})
```

Det andre argumentet erstatter `defaultLocale` for deteksjonen i dette kallet, så det har ingen effekt når en locale tvinges. Ordbøker mellomlagres per forespørsel og per locale, og på tvers av forespørsler i serverens oversettelsescache, så det er billig å kalle en hjelper flere ganger.

## Serverkomponenter {#server-components}

En serverkomponent (`.server.vue`, `<NuxtIsland>`) rendres fra sin egen URL, `/__nuxt_island/...`, så den ser ikke sidens URL, og Nuxt sender den bare dens props. Send locale som en `locale`-prop. Da rendres den i den locale-en, og et bytte henter den på nytt, siden propsene er en del av øyas URL og cache-nøkkel. Navnet er reservert: enhver aktivert locale-kode i en prop kalt `locale` setter rendringens locale, så gi en prop som betyr noe annet, for eksempel et tallformat, et annet navn:

```vue
<!-- components/Greeting.server.vue -->
<template><p>{{ $t('greeting') }}</p></template>
<script setup lang="ts">
defineProps<{ locale?: string }>()
</script>
```

```vue
<template>
  <Greeting :locale="$getLocale()" />
  <NuxtIsland name="Greeting" :props="{ locale: $getLocale() }" />
</template>
```

Uten propen rendres den i locale-en fra informasjonskapselen, ellers i standard-locale, uansett hva URL-en sier, og den følger ikke et bytte. Dens `$t` ser `index`-delen: rotfilene pluss `locales/pages/index/`.
