---
title: "Sidekonfigurasjon"
description: "Begrens en side til enkelte locales, gi den egendefinerte stier, innebygde oversettelser eller ingen SEO-tagger med $defineI18nRoute."
---

`$defineI18nRoute` setter i18n-alternativer for én side fra selve siden. Bruk det når en side bare finnes på enkelte locales, trenger sin egen lokaliserte sti, har noen få egne oversettelser eller ikke skal få hreflang-/canonical-tagger. Modulen leser kallet ved bygging og bygger det inn i de genererte rutene.

## Begrense en side til enkelte locales {#restrict-a-page-to-some-locales}

```vue
<!-- pages/product/index.vue -->
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
})
</script>
```

Bare `/product` og `/de/product` genereres under standardstrategien `prefix_except_default`; siden har ingen rute på noe annet locale. Det samme kan settes fra `nuxt.config.ts` med [`routeLocales`](/no/api/module-options#routelocales).

`$defineI18nRoute` er en Nuxt-appinjeksjon, ikke en kompilatormakro: hent den alltid fra `useNuxtApp()` og kall den med `$`. Bare `$defineI18nRoute(` gjenkjennes av byggetrinnet.

## Legge til innebygde oversettelser {#add-inline-translations}

Send inn et objekt i stedet for en array. Nøklene er de tillatte locales, og verdiene flettes inn i sidens ordbok for det aktive localet.

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: {
    en: { greeting: 'Hello' },
    de: { greeting: 'Hallo' },
    fr: {}, // allowed, no inline keys
  },
})
</script>

<template>
  <h1>{{ $t('greeting') }}</h1>
</template>
```

Innebygde oversettelser leveres inne i sidekomponenten for alle locales. Foretrekk [sideoversettelsesfiler](/no/guide/translations) for alt som er større enn noen få nøkler; behold innebygde nøkler for selvstendige sider og komponenter.

## Angi lokaliserte stier {#set-localized-paths}

```ts
$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: {
    en: '/welcome',
    de: '/willkommen',
  },
})
```

Med `prefix_except_default` og `defaultLocale: 'en'` gir dette `/welcome` og `/de/willkommen`. En `path` inne i et innebygd locale-objekt gjør det samme: `locales: { de: { path: '/willkommen' } }`. Dynamiske parametere, nestede ruter og alternativet på konfigurasjonsnivå er beskrevet i [Lokaliserte stier](/no/guide/custom-locale-routes).

## Slå av SEO-tagger {#turn-off-seo-tags}

```ts
$defineI18nRoute({
  disableMeta: true, // no hreflang, canonical or og:locale tags on this page
})

$defineI18nRoute({
  disableMeta: ['de'], // only the de version has no tags
})
```

Alternativet på konfigurasjonsnivå er [`routeDisableMeta`](/no/api/module-options#routedisablemeta). Hva taggene er, står på [SEO](/no/guide/seo)-siden.

## Hva byggingen kan lese {#what-the-build-can-read}

Byggetrinnet finner kallet i hver sidefil og evaluerer argumentet uten å kjøre appen din. Det fungerer når konfigurasjonen er:

- et literalt objekt (strenger, arrayer, nestede objekter, template literals, ternære uttrykk på `process.env.NODE_ENV`);
- bygget av konstanter deklarert i samme `<script setup>` (`const locales = ['en', 'de']`, spredning inkludert);
- en array av objekter med et `code`-felt (`[{ code: 'en' }, { code: 'de' }]`).

Det kan ikke lese verdier importert fra en annen modul, eller noe som trenger appen din ved kjøretid (composables, `await`, hentede data). I så fall logger byggingen `Ignored the $defineI18nRoute() config in <file>`, og siden beholder standard locales og ruter.

Ved kjøretid fletter kallet bare inn de innebygde oversettelsene for gjeldende locale og fletter dem inn på nytt når localet endres. `locales`, `localeRoutes` og `disableMeta` får bare effekt gjennom byggingen, så endringer i dem krever en ny bygging (utviklingsserveren bygger på nytt ved lagring).
