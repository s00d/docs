# 🌐 Guide til Crowdin-integrasjon

## 📖 Innledning

Å integrere Crowdin i prosjektet ditt strømlinjeformer lokaliserings- og oversettelsesprosessen, og gjør det enklere å håndtere oversettelser på tvers av flere språk og plattformer. Denne guiden gir en trinnvis gjennomgang av hvordan du setter opp Crowdin med prosjektet ditt, inkludert konfigurasjon, opplasting av kilder og nedlasting av oversettelser.

## 🔧 Installasjon og oppsett

For å komme i gang med Crowdin må du installere Crowdin CLI globalt på maskinen din og initialisere det i prosjektmappen.

### 📦 Installere Crowdin CLI

Installer først Crowdin CLI globalt med npm:

```bash
npm install -g @crowdin/cli
```

### 🛠 Initialisere Crowdin i prosjektet

Initialiser Crowdin i prosjektet ved å kjøre:

```bash
crowdin init
```

Denne kommandoen veileder deg gjennom oppsettsprosessen, inkludert å angi prosjekt-ID, API-token og andre konfigurasjonsdetaljer.

## 🗂️ Konfigurasjonsguide

### 📄 Crowdin-konfigurasjonsfil (`crowdin.yml`)

Crowdin-konfigurasjonsfilen (`crowdin.yml`) definerer hvordan kildefilene dine mappes og hvor oversettelser skal plasseres. Under vises en eksempelkonfigurasjon:

```yml
'project_id': 'YOUR_PROJECT_ID'
'api_token': 'YOUR_API_TOKEN'
'base_path': './locales'
'base_url': 'https://api.crowdin.com'
'preserve_hierarchy': true

files:
  [
    { 'source': '/en.json', 'translation': '/%two_letters_code%.json' },
    { 'source': '/pages/**/en.json', 'translation': '/pages/**/%two_letters_code%.json' },
  ]
```

### 📂 Viktige konfigurasjonsparametere

- **`project_id`**: Din Crowdin-prosjekt-ID. Den identifiserer prosjektet i Crowdin der oversettelsene administreres.
- **`api_token`**: API-tokenet som brukes for autentisering. Sørg for at tokenet har riktige rettigheter til å laste opp og laste ned oversettelser.
- **`base_path`**: Angir basemappen for kildefiler. I dette eksempelet lagres oversettelser i mappen `./locales`.
- **`base_url`**: Base-URL for Crowdin-API-et.
- **`preserve_hierarchy`**: Når satt til `true`, opprettholder Crowdin mappestrukturen for kildefilene dine i prosjektet.

### 📂 Fil-konfigurasjon

`files`-seksjonen mapper kildefilene dine til stier der oversettelsene skal lagres. For eksempel:

- **Kildesti**: Definerer plasseringen av de originale oversettelsesfilene.
- **Oversettelsessti**: Angir hvor de oversatte filene skal lagres i Crowdin. Plassholdere som `%two_letters_code%` brukes til å sette språkkoden dynamisk i filstiene.

## ⬆️ Laste opp kildefiler til Crowdin

Når Crowdin-konfigurasjonen er satt opp, kan du laste opp kildefilene med følgende kommando:

```bash
crowdin upload sources
```

Denne kommandoen laster opp alle spesifiserte kildefiler i konfigurasjonen din til Crowdin, slik at de blir tilgjengelige for oversettelse.

## ⬇️ Laste ned oversettelser fra Crowdin

Når oversettelser er fullført eller oppdatert i Crowdin, kan du laste dem ned til prosjektet med:

```bash
crowdin download
```

Denne kommandoen henter de nyeste oversettelsene fra Crowdin og lagrer dem i henhold til stiene som er spesifisert i konfigurasjonsfilen.

## ⚙️ Beste praksis

### 🔑 Konsistent nøkkelnavngivning

Sørg for at oversettelsesnøkler er konsistente på tvers av alle filer for å unngå forvirring og duplisering.

### 🧹 Regelmessig vedlikehold

Gå gjennom og rydd opp i ubrukte oversettelsesnøkler jevnlig for å holde filene organisert og håndterbare.

### 🛠 Automatiser opplasting og nedlasting

Integrer Crowdin CLI-kommandoene i CI/CD-pipelinen din for å automatisere opplasting av kildefiler og nedlasting av oversettelser, slik at oversettelsene alltid er oppdatert.

Ved å følge denne guiden kan du sømløst integrere Crowdin i prosjektet ditt og sikre en effektiv og organisert tilnærming til internasjonaliseringsarbeidet.
