# Bruk av oversettelser i komponenter

Når modulen er installert og konfigurert, kan du vise oversettelser ved å kalle `$t('your_key')` i Vue-templates og skript.

## 1. Oversettelsesfiler på rotnivå og per side

1. **Rotnivå**-oversettelser ligger direkte under mappen `/locales` (f.eks. `/locales/en.json`, `/locales/fr.json`). Ved byggetid slås de automatisk sammen med hver sidespesifikk fil, slik at de er tilgjengelige på alle sider.
2. **Sidespesifikke** oversettelser ligger under `/locales/pages/...` og speiler mappestrukturen for Nuxt-sidene:

```text
locales/
├── en.json
├── fr.json
└── pages/
    └── dir1/
        ├── en.json
        └── fr.json

```

## 2. Bruk i template med `$t`

I `.vue`-filer kan du bruke `$t` direkte i templaten:

```vue
<template>
  <div>
    <!-- Root-level translation (available on all pages) -->
    <p>{{ $t('test_key') }}</p>
    <!-- Displays: Hello World! -->

    <!-- Page-specific translation (if this page is /dir1) -->
    <p>{{ $t('local_key') }}</p>
    <!-- Displays: This is a page-specific translation for /dir1. -->

    <!-- Nested key -->
    <p>{{ $t('nested.key.deeper') }}</p>
    <!-- Displays: Nested translation here -->

    <!-- Placeholder usage -->
    <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
    <!-- Displays: Hello, Alice! -->
  </div>
</template>

<script setup lang="ts">
// No need to import anything from 'nuxt-i18n-micro'.
// The plugin automatically provides `useI18n` and `$t`.
const { $t } = useI18n()

// You can now use $t in your script, for example:
console.log($t('test_key')) // "Hello World!"
</script>
```

<Tip>
`$t` kan returnere **objekter** hvis nøkkelen peker til en nøstet JSON-node (f.eks. `$t('header')` → `\{ title: "Hi" \}`). I templates rendres dette som `[object Object]`. Bruk `$ts` når du trenger en garantert streng, eller angi en mer spesifikk nøkkel som `$t('header.title')`. Se [API-referanse — $t vs $ts](/api/methods#t) for detaljer.
</Tip>

## 3. Bytte gjeldende locale

For å endre språk i appen kan du hente `$locale` fra `useI18n()` og tildele en ny kode:

```vue
<template>
  <div>
    <button @click="$switchLocale('en')">English</button>
    <button @click="$switchLocale('fr')">Français</button>
  </div>
</template>

<script setup lang="ts">
// The plugin auto-injects these references
const { $t, $switchLocale } = useI18n()
</script>
```

## 4. Nøstede nøkler og plassholdere

- **Nøstede nøkler** bruker punktnotasjon, f.eks. `nested.key.deeper`.
- **Plassholdere** lar deg sette inn dynamiske verdier:
  ```json
  { "greeting": "Hello, {name}!" }
  ```
  ```vue
  <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
  <!-- Displays: Hello, Alice! -->
  ```

## 5. Tips og beste praksis

- **Nøkler som kolliderer**: Hvis en sidespesifikk fil inneholder samme nøkkel som en fil på rotnivå, prioriteres den sidespesifikke versjonen (rot-oversettelser slås sammen som en base ved byggetid).
- **Deaktivere sidefiler**: Hvis du heller ikke vil bruke sidespesifikke oversettelser, kan du sette `disablePageLocales: true` i Nuxt-konfigurasjonen. Da brukes kun filene `/locales/*.json`.
- **Ingen direkte imports**: Du trenger ikke å gjøre `import \{ useI18n \} from 'nuxt-i18n-micro'`; modulens auto-injeksjon håndterer det for deg.

Det var det! Med disse stegene kan du raskt **begynne å hente oversettelser** fra rotnivå eller sidespesifikke JSON-filer og **vise dem** i Nuxt-applikasjonen din med `$t`.

## Ytterligere ressurser

For å utforske flere avanserte funksjoner bør du se på:

1. **`<i18n-t>`-komponenten**  
   Komponenten `<i18n-t>` er et kraftig alternativ til `$t`, spesielt nyttig i situasjoner med nøstede elementer, avansert bruk av plassholdere og mer komplekse oversettelsesstrukturer.

- **Dokumentasjon**: [i18n-t](/api/components/i18n-t)

2. **Composable `useI18n`**  
   `useI18n` tilbyr et komplett sett av funksjoner og reaktive egenskaper for å administrere oversettelser, bytte locale, formatering og mer.

- **Dokumentasjon**: [useI18n](/api/composables/use-i18n)
