# Bruk av oversettelser i komponenter

Når modulen er installert og konfigurert, kan du vise oversettelser ved å kalle `$t('din_nokkel')` i Vue-malene og -skriptene dine.

## 1. Rot- og sidespesifikke oversettelsesfiler

1. **Rot-oversettelser** ligger direkte under `/locales`-mappen (f.eks. `/locales/en.json`, `/locales/fr.json`). Ved byggetid flettes de automatisk inn i hver sidespesifikke fil, slik at de er tilgjengelige på alle sider.
2. **Sidespesifikke** oversettelser ligger under `/locales/pages/...`, tilsvarende Nuxt-mappestrukturen din:

```text
locales/
├── en.json
├── fr.json
└── pages/
    └── dir1/
        ├── en.json
        └── fr.json

```

## 2. Malbruk med `$t`

I `.vue`-filene dine kan du bruke `$t` direkte i malen:

```vue
<template>
  <div>
    <!-- Root-level translation (available on all pages) -->
    <p>{{ $t('test_key') }}</p>
    <!-- Displays: Hello World! -->

    <!-- Page-specific translation (if this page is /dir1) -->
    <p>{{ $t('local_key') }}</p>
    <!-- Displays: This is a page-specific translation for /dir1. -->

    <!-- Nested key -->
    <p>{{ $t('nested.key.deeper') }}</p>
    <!-- Displays: Nested translation here -->

    <!-- Placeholder usage -->
    <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
    <!-- Displays: Hello, Alice! -->
  </div>
</template>

<script setup lang="ts">
// No need to import anything from 'nuxt-i18n-micro'.
// The plugin automatically provides `useI18n` and `$t`.
const { $t } = useI18n()

// You can now use $t in your script, for example:
console.log($t('test_key')) // "Hello World!"
</script>
```

<Tip>
`$t` kan returnere **objekter** hvis nøkkelen peker på en nøstet JSON-node (f.eks. `$t('header')` → `\{ title: "Hi" \}`). I maler rendres dette som `[object Object]`. Bruk `$ts` når du trenger en garantert streng, eller oppgi en mer spesifikk nøkkel som `$t('header.title')`. Se [API-referanse — $t vs $ts](/api/methods#t) for detaljer.
</Tip>

## 3. Bytte gjeldende lokale

For å endre språk i appen, kan du hente `$locale` fra `useI18n()` og tilordne den en ny kode:

```vue
<template>
  <div>
    <button @click="$switchLocale('en')">English</button>
    <button @click="$switchLocale('fr')">Français</button>
  </div>
</template>

<script setup lang="ts">
// The plugin auto-injects these references
const { $t, $switchLocale } = useI18n()
</script>
```

## 4. Nøstede nøkler og plassholdere

- **Nøstede nøkler** bruker punktnotasjon, f.eks. `nested.key.deeper`.
- **Plassholdere** lar deg sette inn dynamiske verdier:
  ```json
  { "greeting": "Hello, {name}!" }
  ```
  ```vue
  <p>{{ $t('greeting', { name: 'Alice' }) }}</p>
  <!-- Displays: Hello, Alice! -->
  ```

## 5. Tips og beste praksis

- **Konflikter i nøkler**: Hvis en sidespesifikk fil inneholder samme nøkkel som en rot-fil, har den sidespesifikke versjonen prioritet (rot-oversettelser flettes inn som en base ved byggetid).
- **Deaktivere sidefiler**: Hvis du heller ikke vil bruke sidespesifikke oversettelser, kan du sette `disablePageLocales: true` i Nuxt-konfigurasjonen. Da brukes bare `/locales/*.json`-filene.
- **Ingen direkte imports**: Du trenger ikke å skrive `import \{ useI18n \} from 'nuxt-i18n-micro'`; modulens auto-injeksjonsfunksjon håndterer det for deg.

Det var det! Med disse stegene kan du raskt **komme i gang med å hente oversettelser** fra rot-filer eller sidespesifikke JSON-filer og **vise dem** i Nuxt-applikasjonen din med `$t`.

## Tilleggsressurser

For å utforske mer avanserte funksjoner, sjekk ut:

1. **`<i18n-t>`-komponent**  
   `<i18n-t>`-komponenten er et kraftig alternativ til `$t`, spesielt nyttig for situasjoner med nøstede elementer, avansert bruk av plassholdere og mer komplekse oversettelsesstrukturer.

- **Dokumentasjon**: [i18n-t](/api/components/i18n-t)

2. **`useI18n`-composable**  
   `useI18n`-composablen tilbyr et komplett sett med funksjoner og reaktive egenskaper for å administrere oversettelser, håndtere lokale-veksling, formatering og mer.

- **Dokumentasjon**: [useI18n](/api/composables/use-i18n)
