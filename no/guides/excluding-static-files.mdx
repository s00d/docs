# Ekskludere statiske filer fra i18n-ruting

## Oversikt

Som standard ekskluderer nuxt-i18n-micro automatisk vanlige statiske filer fra i18n-rutingsbehandling. Du kan imidlertid også konfigurere egendefinerte ekskluderingsmønstre for å hindre at bestemte stier behandles av i18n-systemet.

## Innebygde ekskluderinger

Modulen ekskluderer automatisk følgende filtyper og mønstre:

- **Sitemaps**: `/sitemap*.xml`, `/sitemap-en.xml` osv.
- **SEO-filer**: `/robots.txt`, `/favicon.ico`
- **PWA-filer**: `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Statiske ressurser**: Filer med endelser som `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Interne Nuxt-stier**: Enhver sti som starter med `__` (som `/__nuxt/`)

## Egendefinerte ekskluderingsmønstre

Du kan definere egendefinerte ekskluderingsmønstre med `excludePatterns`-alternativet:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Mønstertyper

### Strengmønstre

- **Eksakt match**: `'/api/health'` — matcher nøyaktig `/api/health`
- **Prefiks-match**: `'/admin'` — matcher `/admin` og `/admin/dashboard`
- **Wildcards**: `'/api/*'` — matcher `/api/users`, men ikke `/api/users/123`
- **Dype wildcards**: `'/admin/**'` — matcher `/admin/users` og `/admin/users/123`

### Regulære uttrykk

Bruk RegExp-objekter for kompleks mønster-matching:

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Brukstilfeller

### SEO-filer

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### API-ruter

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Adminpaneler

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Statiske ressurser

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Slik fungerer det

1. **Server-mellomvare**: En Nitro-mellomvare kjører først for å sjekke ekskluderingsmønstre
2. **Sidebehandling**: Under rute-oppløsning hoppes ekskluderte stier over
3. **Catch-all-rute**: Fallback-ruten sjekker ekskluderinger før behandling
4. **Prerendering**: Ekskluderte stier inkluderes ikke i prerenderede ruter

## Ytelsespåvirkning

- Ekskluderingssjekker er optimalisert og kjøres tidlig i request-livssyklusen
- Innebygde mønstre bruker effektiv regex-matching
- Egendefinerte mønstre caches og gjenbrukes
- Minimal ytelses-overhead for ekskluderte stier

## Feilsøking

### Statiske filer fanges fortsatt opp

1. **Sjekk mønstersyntaks**: Sørg for at mønstrene matcher den eksakte stistrukturen
2. **Bruk regex for komplekse mønstre**: Streng-wildcards har begrensninger
3. **Test mønstre**: Bruk nettleserens dev-verktøy for å verifisere den faktiske forespørselsstien
4. **Sjekk rekkefølge**: Sørg for at ekskluderingsmønstre er definert før annen i18n-konfigurasjon

### Mønster fungerer ikke

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Debug-modus

Aktiver debug-modus for å se ekskluderingsbehandlingen:

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Dette logger ekskluderingsbeslutninger i konsollen.

## Migrere fra omveier

Hvis du brukte omveier som rute-regler eller mellomvare, kan du nå erstatte dem med `excludePatterns`:

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

Den nye tilnærmingen er mer pålitelig og fungerer på flere nivåer av rutingsystemet.
