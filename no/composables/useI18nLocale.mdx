---
title: "useI18nLocale"
description: "useI18nLocale leser og skriver locale-tilstanden og locale-informasjonskapselen — inngangspunktet for egendefinert locale-gjenkjenning."
---

`useI18nLocale()` gir tilgang til localet appen har valgt: tilstanden `i18n-locale` og locale-informasjonskapselen. Bruk den i en plugin som selv gjenkjenner localet (domene, brukerprofil, header) i stedet for å skrive `useState('i18n-locale')` eller informasjonskapselen for hånd. Gyldighetskontrollene bruker de aktiverte localene, inkludert overstyringer under kjøring.

## Signatur {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Sentralisert inngangspunkt for håndtering av i18n-locale.
Kombinerer useState('i18n-locale'), locale-informasjonskapselen og synkroniseringsverktøy.

## Returnerte verdier {#returned-values}

| Medlem | Type | Beskrivelse |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | Ref-en `useState('i18n-locale')`. |
| `localeCookie` | `Ref<string \| null>` | Informasjonskapselen [`localeCookie`](/no/api/module-options#localecookie); et enkelt `{ value: null }` når alternativet er `null`. |
| `hashCookie` | `Ref<string \| null>` | Informasjonskapselen `hash-locale` ved hash-ruting; ellers `{ value: null }`. |
| `validLocales` | `string[]` | Kodene til de aktiverte localene. |
| `setLocale(locale)` | `(locale: string \| null) => void` | Skriv tilstanden og informasjonskapslene. Validerer ikke og laster ikke oversettelser. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | Skriv bare informasjonskapslene. |
| `getLocale()` | `() => string \| null` | Tilstanden, deretter preferanse-informasjonskapselen (hash-informasjonskapselen ved hash-ruting). Ikke validert. |
| `getPreferredLocale()` | `() => string \| null` | Den første **gyldige** av tilstanden og preferanse-informasjonskapselen, eller `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | Tilstanden ved hash-ruting når den er satt; ellers `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, deretter en gyldig tilstand, deretter `options.serverLocale`, deretter rutens locale. Lagrer resultatet i tilstanden når tilstanden ikke er gyldig; på klienten skriver den også informasjonskapselen. |
| `isValidLocale(locale)` | `(locale) => locale is string` | Om `locale` finnes i `validLocales`. |

Informasjonskapslene varer i ett år, med `path: '/'` og `sameSite: 'lax'`.

## Eksempel {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

Modulens loader-plugin leser tilstanden når den starter, så en plugin som setter den må kjøre først (`enforce: 'pre'`). Hvordan tilstanden konkurrerer med URL-en, informasjonskapselen og `Accept-Language`: [Locale-gjenkjenning](/no/guide/locale-detection). Fullstendig gjennomgang: [Egendefinert gjenkjenning](/no/guide/custom-auto-detect).

`setLocale()` bytter ikke oversettelsene på skjermen. For å endre localet for den gjeldende siden, kall [`$switchLocale()`](/no/api/methods#$switchlocale).
