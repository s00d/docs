---
title: "useI18nHead"
description: "useI18nHead overstyrer de genererte i18n-SEO-taggene for én side: erstatt eller fjern canonical-, hreflang- og og-tagger, eller legg til dine egne."
---

`useI18nHead()` endrer SEO-taggene som modulen genererer, kun for én side. Bruk den når en side vet bedre enn ruteren: en CMS-artikkel som bare finnes i noen locales, en canonical-URL fra et API, ekstra `og:`-tagger. Du får de genererte taggene med overstyringene dine slått sammen oppå.

## Signatur {#signature}

```ts
useI18nHead(input?: MaybeRefOrGetter<I18nHeadInput | null>): { pageHead: any; resetPageHead: () => void }
```

Registrer overstyringer på sidenivå for i18n-SEO-tagger i head.
Slås sammen oppå resultatet fra `useLocaleHead` av pluginen `02.meta`.

Foretrekk en getter (`() => ({ … })`) når verdiene kommer fra `$t` / `t`, slik at de
løses på nytt når locale endres. Et vanlig objekt evalueres én gang og forblir frosset.

| Parameter | Type | Beskrivelse |
| --- | --- | --- |
| `input` *(valgfri)* | `MaybeRefOrGetter<I18nHeadInput \| null>` |  |

Den fungerer med [`meta: true`](/no/api/module-options#meta) (standard): modulens meta-plugin slår sammen input over resultatet fra [`useLocaleHead`](/no/composables/useLocaleHead) ved hver rendring av head. Med `meta: false` er det ingenting som leser den.

Overstyringen tilbakestilles når rutenavnet endres. En side som setter `disableMeta` får ingen i18n-tagger i det hele tatt, heller ikke overstyringer.

## Input {#input}

`I18nHeadInput` (fra `@i18n-micro/types`):

| Nøkkel | Type | Effekt |
| --- | --- | --- |
| `htmlAttrs` | `Record<string, string>` | Slås sammen med attributtene på `<html>` (`lang`, `dir`). |
| `meta` | `I18nHeadMeta[]` | Legges til etter de genererte taggene; erstatter en tagg med samme `id`, `property` eller `name`. |
| `link` | `I18nHeadLink[]` | Legges til etter de genererte lenkene; erstatter en lenke med samme `id`, eller `rel` + `hreflang`. |
| `replace.canonical` | `string \| false` | Erstatt canonical-`href`, eller fjern lenken. |
| `replace.hreflang` | `I18nHeadLink[] \| false` | Erstatt eller fjern **alle** `rel="alternate"`-lenker, inkludert `x-default`. |
| `replace.xDefault` | `I18nHeadLink \| false` | Erstatt eller fjern `x-default`-lenken. |
| `replace.ogLocale` | `string \| false` | Erstatt eller fjern `og:locale`. |
| `replace.ogUrl` | `string \| false` | Erstatt eller fjern `og:url`. |
| `replace.ogAlternates` | `string[] \| false` | Bygg `og:locale:alternate` på nytt fra disse locale-kodene (via `og` / `iso`), og hopp over gjeldende locale, ukjente koder og koder uten en `og`- eller `iso`-verdi, eller fjern dem. |
| `disable` | `I18nHeadDisableGroup[]` | Fjern genererte grupper: `'hreflang'` (ikke `x-default`), `'x-default'`, `'canonical'`, `'og'` (`og:locale` + `og:url`), `'og-alternates'`, `'html'`. |

Rekkefølge for anvendelse: `disable`, deretter `replace`, deretter `htmlAttrs`, `meta`, `link`.

## Eksempel {#example}

En artikkel som bare finnes i noen locales, med alternative URL-er fra API-et:

```vue
<script setup lang="ts">
const route = useRoute()
const { t } = useI18n()
const { data: article } = await useFetch<{ title: string; urls: Record<string, string> }>(`/api/articles/${route.params.slug}`)

useI18nHead(() => {
  if (!article.value) return null
  const codes = Object.keys(article.value.urls)
  return {
    meta: [{ property: 'og:title', content: article.value.title || t('blog.title') }],
    replace: {
      hreflang: codes.map((code) => ({ rel: 'alternate', hreflang: code, href: article.value!.urls[code]! })),
      ogAlternates: codes,
    },
  }
})
</script>
```

Send inn en getter, som her, når verdiene kommer fra `t()` eller asynkrone data: den kjøres på nytt når locale endres. Et vanlig objekt leses én gang.
