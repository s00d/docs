---
title: "Exclure des chemins"
description: "Tenir des pages et des fichiers à l'écart du routage par locale avec excludePatterns, et voir quels chemins sont déjà exclus."
---

Certains chemins ne doivent jamais recevoir de préfixe de locale ni de redirection de locale : une zone d'administration, un contrôle de santé, un flux généré. `excludePatterns` les signale, et une liste intégrée couvre déjà les éléments internes de Nuxt et les fichiers statiques courants. Une page exclue conserve exactement le chemin que vous avez écrit et s'affiche toujours avec `$t`.

## Exclure un chemin {#exclude-a-path}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    excludePatterns: [
      '/admin', // /admin and everything below it
      '/preview-*', // glob over the whole path
    ],
  },
})
```

Avec cette configuration, `pages/admin/index.vue` ne répond qu'à `/admin` ; il n'existe pas de `/de/admin`, et `/admin` n'est jamais redirigé vers `/de/admin`.

## Syntaxe des motifs {#pattern-syntax}

Les motifs sont comparés au chemin sans `app.baseURL` :

| Motif | Correspond à | Ne correspond pas à |
| --- | --- | --- |
| `'/admin'` | `/admin`, `/admin/users` | `/administrator`, `/de/admin` |
| `'/preview-*'` | `/preview-1`, `/preview-a/b` | `/de/preview-1` |
| `'/file-?'` | `/file-a` | `/file-ab` |
| `/^\/v\d+\//` | `/v2/docs` | `/docs` |

Une chaîne sans `*` ni `?` correspond au chemin et aux segments entiers situés en dessous. Avec `*` (n'importe quelle suite de caractères, barres obliques comprises) ou `?` (un caractère), elle doit correspondre au chemin entier. Commencez toujours les chaînes par `/`.

## Ce qui est déjà exclu {#what-is-excluded-already}

Ces chemins n'obtiennent jamais de routes ni de redirections de locale, sans aucune configuration :

- `/api` et `/_nuxt`, ainsi que tout ce qui se trouve en dessous ;
- la route des traductions, `/_locales` par défaut ([`apiBaseUrl`](/fr/api/module-options#apibaseurl)) ;
- tout chemin comportant un segment qui commence par `__` (`/__nuxt_content`, `/en/__og-image__`) ;
- `/sitemap*.xml`, `/robots.txt`, `/favicon.ico`, `/apple-touch-icon*.png`, `/manifest.json`, `/sw.js`, `/workbox-*.js` ;
- tout chemin dont le dernier segment se termine par une extension de fichier statique : `xml txt ico json js css png jpg jpeg gif svg webp avif pdf wasm map mp4 webm mp3 zip gz woff woff2 ttf eot`. Les slugs de page contenant un point comme `/user/john.doe` et les chemins `.html` restent des pages.

## Effets d'une exclusion {#what-an-exclusion-does}

- **Routes :** aucune variante localisée n'est générée ; la page est conservée telle qu'écrite.
- **Redirections et 404 :** le plugin de redirection serveur et le middleware de redirection client ignorent le chemin.
- **Prérendu :** les chemins correspondants sont retirés de la liste des routes à prérendre.

Cela n'empêche pas le middleware serveur i18n de détecter une locale pour la requête, ni la page d'utiliser les traductions. Pour garder une page localisée mais sans balises SEO, utilisez `disableMeta` ([Configuration de page](/fr/guide/per-component-translations#turn-off-seo-tags)). Pour garder une page non localisée par son chemin depuis `nuxt.config.ts`, `globalLocaleRoutes: { '/admin': false }` ([Chemins localisés](/fr/guide/custom-locale-routes#in-nuxt-config)) produit le même effet sur le routage.
