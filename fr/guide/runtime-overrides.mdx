---
title: "Surcharges à l’exécution"
description: "Modifiez la locale par défaut, la locale de repli ou les locales désactivées pour chaque instance d’un même build, avec des variables d’environnement ou runtimeConfig."
---

Les surcharges à l’exécution permettent à un même artefact de build de s’exécuter avec des paramètres de locale différents selon l’environnement ou le tenant, sans rebuild. Vous pouvez modifier la locale par défaut, la locale de repli et les locales désactivées. Le routage, les redirections, le rendu et les helpers serveur utilisent les valeurs surchargées, tout comme le navigateur sur une page rendue côté serveur.

## Définir les surcharges avec des variables d’environnement {#set-overrides-with-environment-variables}

```bash
NUXT_I18N_DEFAULT_LOCALE=de \
NUXT_I18N_FALLBACK_LOCALE=en \
NUXT_I18N_DISABLED_LOCALES=fr,it \
node .output/server/index.mjs
```

| Variable | Alias |
| --- | --- |
| `NUXT_I18N_DEFAULT_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE` |
| `NUXT_I18N_FALLBACK_LOCALE` | `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE` |
| `NUXT_I18N_DISABLED_LOCALES` (séparées par des virgules) | `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES` |

Le serveur les lit une seule fois au démarrage ; redémarrez pour appliquer une modification. Sur une page rendue côté serveur, le navigateur reçoit les valeurs résolues depuis le serveur. Avec `ssr: false`, il n’y a pas de rendu serveur et le navigateur n’a pas d’environnement : seul `runtimeConfig.public.i18nRuntime` s’applique alors, et le navigateur journalise les avertissements ci-dessous.

## Définir les surcharges dans runtimeConfig {#set-overrides-in-runtimeconfig}

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

Une valeur définie dans `runtimeConfig.public.i18nRuntime` l’emporte sur la variable `NUXT_I18N_*` du même champ.

À ne pas confondre avec la variable de build `DEFAULT_LOCALE`, qui remplace `defaultLocale` pendant le build et ne nécessite aucune prise en charge à l’exécution.

## Ce qui peut changer et ce qui ne le peut pas {#what-can-and-cannot-change}

| Paramètre | À l’exécution |
| --- | --- |
| `defaultLocale` | Oui avec `prefix` et `no_prefix`. Avec `prefix_except_default` et `prefix_and_default`, elle est fixée au build (ses pages sont les routes sans préfixe) ; une surcharge est ignorée avec un avertissement. |
| `fallbackLocale` | Oui. |
| `disabledLocales` | S’ajoute aux locales désactivées au build ; n’en réactive jamais aucune. La locale par défaut du build ne peut pas être désactivée avec `prefix_except_default` / `prefix_and_default`. |
| `strategy` | Non. Une stratégie définie à l’exécution est ignorée avec un avertissement ; produisez un artefact par stratégie. |

Les valeurs invalides ne cassent jamais l’application. Chaque cas journalise un avertissement par processus serveur :

- désactiver toutes les locales est ignoré ;
- une `defaultLocale` non activée se replie sur la première locale activée ;
- une `fallbackLocale` non activée conserve la valeur du build si celle-ci est activée, sinon il n’y a pas de repli.

## Lire la configuration effective {#read-the-effective-config}

```vue
<script setup lang="ts">
const { $getI18nConfig } = useNuxtApp()
const config = $getI18nConfig() // build config with overrides applied
</script>
```

Considérez-la comme en lecture seule : côté serveur, elle est partagée par toutes les requêtes et gelée en développement ; la copie du navigateur n’est pas gelée. Importer la configuration depuis `#build/i18n.strategy.mjs` donne les valeurs du build sans les surcharges.

## Locales désactivées et fichiers statiques {#disabled-locales-and-static-files}

Une locale désactivée à l’exécution répond 404 sur ses routes et sur sa route de payload, mais ses fichiers de payload restent dans `.output/public/_locales/` et un serveur de fichiers statiques les renvoie. Lorsque ces fichiers ne doivent pas être accessibles, désactivez la locale au build avec `disabled: true`.
