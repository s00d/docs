title: "Stratégies de routage"
description: "Les quatre stratégies d'URL, les routes localisées qu'elles génèrent et comment créer un lien vers une page dans n'importe quelle locale."
---

L'option `strategy` détermine si une locale apparaît dans l'URL et pour quelles locales. Choisissez-la une fois pour toutes, avant de publier vos URL : la modifier plus tard change tous les liens. Le module génère ensuite les routes localisées au moment du build, et `$localePath`, `<i18n-link>` et le sélecteur de langue les lisent.

## Les quatre stratégies {#the-four-strategies}

![La page /about en en (par défaut) et en de sous chaque stratégie ; les mêmes URL sont listées dans le texte ci-dessous](/images/diagrams/strategies.svg)

**Type** `Strategies` · **Par défaut** `'prefix_except_default'`

Stratégie de routage des URL pour les préfixes de locale.

- `'no_prefix'` — pas de locale dans l'URL ; la locale est stockée dans un cookie.
- `'prefix_except_default'` — préfixe toutes les locales sauf celle par défaut.
- `'prefix'` — préfixe toujours, y compris la locale par défaut.
- `'prefix_and_default'` — comme `prefix`, mais la locale par défaut est aussi accessible sans préfixe.

URL d'une page `about` avec `defaultLocale: 'en'` et les locales `en`, `de` :

| Stratégie | Anglais | Allemand | Non servi |
| --- | --- | --- | --- |
| `prefix_except_default` (par défaut) | `/about` | `/de/about` | `/en` et `/en/about` renvoient une 404 |
| `prefix` | `/en/about` | `/de/about` | `/about` redirige vers une URL préfixée |
| `prefix_and_default` | `/about` et `/en/about` | `/de/about` | — |
| `no_prefix` | `/about` | `/about` | la locale ne figure pas dans l'URL |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'de', iso: 'de-DE' },
    ],
    defaultLocale: 'en',
    strategy: 'prefix',
  },
})
```

La stratégie est fixée au build : une surcharge à l'exécution est ignorée avec un avertissement ([Surcharges à l'exécution](/fr/guide/runtime-overrides)).

## Laquelle choisir {#which-one-to-choose}

- **`prefix_except_default`** : la plupart des sites. Les URL existantes sans préfixe continuent de fonctionner pour la langue par défaut.
- **`prefix`** : toutes les langues sont sur un pied d'égalité ; `/` mène toujours à une page d'accueil préfixée.
- **`prefix_and_default`** : vous avez besoin que `/en/...` et les URL sans préfixe fonctionnent toutes les deux, par exemple pendant une transition de l'une à l'autre. Les URL sans préfixe ne sont jamais redirigées.
- **`no_prefix`** : applications derrière une connexion, ou une seule URL par page pour toutes les langues. La locale provient d'un cookie ou de `?locale=`. Les moteurs de recherche voient une langue par URL, donc aucune alternative `hreflang` n'est émise.

La façon dont la locale est choisie pour une URL, et quand un visiteur est redirigé, est décrite dans [Détection de la locale](/fr/guide/locale-detection).

## Routes générées {#generated-routes}

Au moment du build, chaque page reçoit les enregistrements de route dont sa stratégie a besoin. Chaque enregistrement porte `meta.i18n = { name, locales }` : la page qu'il affiche et les locales qu'il sert. Les liens, les changements de locale et les redirections sont tous résolus à partir de ces enregistrements, de sorte qu'une URL fournie par le module est toujours une URL que le routeur sert.

Les locales qui partagent le chemin de la page partagent un seul enregistrement, `/:locale(de|fr)/about`. Une locale qui a son propre chemin obtient son propre enregistrement, nommé `localized-<page>-<locale>` :

```ts
// nuxt.config.ts: German has its own path for the about page
i18n: {
  globalLocaleRoutes: { about: { de: '/ueber-uns' } },
}
// prefix_except_default, locales en (default), de, fr:
// about                 /about
// localized-about       /:locale(fr)/about
// localized-about-de    /:locale(de)/ueber-uns
```

Les chemins personnalisés, les listes de locales par page et l'exclusion d'une page de la localisation sont traités dans [Chemins localisés](/fr/guide/custom-locale-routes) et [Configuration de page](/fr/guide/per-component-translations). Le préfixe `localized-` correspond à [`localizedRouteNamePrefix`](/fr/api/module-options#localizedroutenameprefix).

<Warning>

**Les noms de route sont générés** — Ne codez pas en dur les noms `localized-…` dans `router.push({ name })`. Passez le nom propre de la page à `$localeRoute` ou à `<i18n-link>` ; ils choisissent le bon enregistrement.

</Warning>

## Créer un lien vers une page dans une locale {#linking-to-a-page-in-a-locale}

```vue
<script setup lang="ts">
const { localePath, localeRoute, switchLocalePath } = useI18n()

localePath({ name: 'about' }) // '/de/ueber-uns' while the page is German
localePath({ name: 'about' }, 'en') // '/about'
localePath('/about', 'de') // '/de/ueber-uns': a path is read as the page it shows
localeRoute({ name: 'products-id', params: { id: '42' } }, 'de') // resolved route: name, params, fullPath
switchLocalePath('fr') // the current page in French
</script>

<template>
  <i18n-link :to="{ name: 'about' }">{{ $t('nav.about') }}</i18n-link>
  <NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
</template>
```

- Les routes nommées et les chemins fonctionnent tous deux. Un chemin est comparé aux routes générées, donc sa forme dans n'importe quelle locale est acceptée.
- Une locale qui ne sert pas la page (voir `locales` dans [Configuration de page](/fr/guide/per-component-translations)) renvoie vers la page d'accueil de cette locale au lieu d'une page inexistante.
- Les paramètres propres à chaque locale (un slug traduit) passent par `$setI18nRouteParams`, voir [Chemins localisés](/fr/guide/custom-locale-routes).

Les signatures se trouvent dans [Méthodes](/fr/api/methods).

## Détails de `no_prefix` {#no_prefix-details}

- [`localeCookie`](/fr/api/module-options#localecookie) vaut par défaut `'user-locale'` sous `no_prefix`, de sorte que le choix survit à un rechargement.
- `$switchLocale('de')` charge le dictionnaire allemand et remplace l'entrée courante de l'historique ; l'URL ne change pas.
- Les chemins personnalisés par locale fonctionnent toujours : avec `globalLocaleRoutes: { about: { de: '/ueber-uns' } }`, les lecteurs germanophones obtiennent `/ueber-uns`. Cette URL s'affiche toujours en allemand, quelle que soit la préférence du visiteur, et une page restreinte à certaines locales s'affiche dans l'une d'elles. Un chemin partagé par plusieurs locales (`en` et `de` toutes deux sur `/page/:id`) s'affiche dans la locale préférée lorsqu'elle en fait partie. La préférence elle-même est conservée : la page suivante y revient.
- [`noPrefixRedirect: true`](/fr/api/module-options#noprefixredirect) redirige le chemin d'origine d'une page ayant un chemin personnalisé dans la locale par défaut : vers le chemin personnalisé de la locale du visiteur, sinon vers celui de la locale par défaut (`/about` → `/about-us` lorsque `en` a `/about-us`, → `/ueber-uns` avec le cookie `de`). Une locale sans chemin personnalisé propre reste sur le chemin d'origine et s'y affiche. Les pages avec paramètres ne sont pas redirigées.

## Applications sans `pages/` {#apps-without-pages/}

Avec `pages: false`, il n'y a pas de routes de page à localiser. Utilisez uniquement des fichiers de traduction racine (`disablePageLocales: true`) ; la détection, le cookie et `$switchLocale` fonctionnent toujours. La variante `pages-false` de `test/fixtures/basic` dans le dépôt est une configuration fonctionnelle.
