`@i18n-micro/runtime` est l'instance i18n indépendante de tout framework : dictionnaires, `t()`, pluriels, formatage `Intl` et abonnement aux changements, sans `fs` et sans framework. Utilisez-la en TypeScript pur, dans un web worker, une fonction edge, ou comme base de votre propre binding. Les packages React, Preact, Node et Astro étendent cette même classe.

## Installation {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/runtime
```

```bash npm
npm install @i18n-micro/runtime
```

```bash yarn
yarn add @i18n-micro/runtime
```

</CodeGroup>

Aucune dépendance peer. Pour des fichiers de traduction sur disque, utilisez [`@i18n-micro/node`](/fr/integrations/nodejs-package).

## Configuration {#setup}

```ts
import { createI18n } from '@i18n-micro/runtime'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: {
    en: { greeting: 'Hello, {name}!', apples: 'no apples | one apple | {count} apples' },
    de: { greeting: 'Hallo, {name}!' },
  },
  routeMessages: {
    about: { en: { title: 'About us' } },
  },
})
```

Toutes les options (`plural`, `missingWarn`, `missingHandler`, `numberFormats`, `datetimeFormats`) sont listées dans [l'instance](/fr/integrations/overview#the-instance).

## Traduire {#translate}

```ts
i18n.t('greeting', { name: 'Ada' }) // 'Hello, Ada!'
i18n.tc('apples', 5) // '5 apples'
i18n.tn(1234.5) // '1,234.5'

i18n.setRoute('about')
i18n.t('title') // 'About us' (route dictionary)
i18n.t('greeting', { name: 'Ada' }) // 'Hello, Ada!' (root, still visible)
```

Charger d'autres dictionnaires plus tard :

```ts
i18n.loadMessages({ fr: { greeting: 'Bonjour, {name} !' } }, { about: { fr: { title: 'À propos' } } })
i18n.addTranslations('fr', { nav: { home: 'Accueil' } }) // deep merge; pass false to replace

await i18n.loadFromUrl('/locales/fr.json', { locale: 'fr' })
await i18n.loadFromUrl('/locales/pages/about/fr.json', { locale: 'fr', routeName: 'about' })
await i18n.loadFromUrls([
  { url: '/locales/en.json', locale: 'en' },
  { url: '/locales/de.json', locale: 'de' },
])
```

`loadFromUrl` utilise `fetch` (passez `init` pour les en-têtes) et lève une erreur sur une réponse non OK. `loadFromUrls` charge les fichiers les uns après les autres.

## Changer de locale {#switch-locale}

```ts
i18n.locale = 'de'
i18n.t('greeting', { name: 'Ada' }) // 'Hallo, Ada!'
```

Les changements de locale, de route et de dictionnaire notifient les abonnés, c'est ainsi que les bindings de framework déclenchent un nouveau rendu :

```ts
const stop = i18n.subscribe(() => {
  document.querySelector('#greeting')!.textContent = i18n.t('greeting', { name: 'Ada' }) as string
})
i18n.locale = 'fr'
stop()
```

`getSnapshot()` renvoie une chaîne qui change à chaque notification (pour les stores de style `useSyncExternalStore`).

## Par requête {#per-request}

L'instance contient une locale et une route. Sur un serveur, ne changez pas la locale d'une instance partagée à chaque requête : deux requêtes simultanées verraient la locale l'une de l'autre. `i18n.fork(locale)` donne à une requête sa propre instance : sa propre locale, sa locale de repli et sa route ; les mêmes dictionnaires, formateurs et règles. Le coût d'un fork est le même quel que soit le nombre de dictionnaires. Un fork voit les écritures de son parent jusqu'à sa première écriture propre, et ses écritures restent en lui. [Node.js](/fr/integrations/nodejs-package#per-request) ajoute `run`.

## API {#api}

| Membre | Remarques |
| --- | --- |
| `t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has` | voir [Traduire et formater](/fr/integrations/overview#translate-and-format) |
| `locale`, `fallbackLocale` | lecture/écriture |
| `currentRoute`, `setRoute(name)`, `getRoute()` | route active, `'index'` par défaut |
| `loadMessages(messages?, routeMessages?)` | fusionne plusieurs locales et routes à la fois |
| `addTranslations(locale, tree, merge = true)`, `addRouteTranslations(locale, route, tree, merge = true)` | |
| `loadFromUrl(url, { locale?, routeName?, init? })`, `loadFromUrls(entries)` | JSON via `fetch` |
| `hasTranslation(key)` | locale active, n'importe quelle route (contrairement à `has`, qui vérifie la route active et la racine) |
| `setTranslation(key, value)`, `resolveTranslations()` | écrire une clé ; lire l'arbre fusionné |
| `clear()`, `clearCache()` | supprimer tous les dictionnaires |
| `subscribe(cb)`, `getSnapshot()` | notifications de changement |
| `storage` | `{ translations: Map<'locale:route', Translations> }` |

Un code qui n'est pas une étiquette de langue obtient ses pluriels via `localeIso: { ua: 'uk-UA' }` ; `localeIsoMap(locales)` construit cela à partir des entrées d'une liste de locales qui ont un `iso`.

Exports du module : `createI18n`, `I18n`, `fetchJsonTranslations`, `FormatService`, `interpolate`, `localeIsoMap` et les types `I18nOptions`, `LoadFromUrlOptions`, `LoadFromUrlEntry`, `TranslationStorage`, `Translations`, `Locale`, `PluralFunc`. Signatures complètes : [référence du package](/fr/api/packages/runtime).
