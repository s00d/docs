Les paquets `@i18n-micro/*` apportent le cœur de traduction de Nuxt I18n Micro à Vue, React, Preact, Solid, Astro, VitePress et au JavaScript pur. Utilisez-les lorsque votre application n'est pas une application Nuxt, ou lorsqu'un script ou un serveur en dehors de Nuxt a besoin des mêmes fichiers de traduction. Tous les paquets partagent un même modèle d'instance, un même contrat d'adaptateur de routeur et les mêmes quatre composants, décrits une seule fois sur cette page.

L'entrée routeur est un import séparé, de sorte qu'une application sans routeur n'en embarque jamais.

`@i18n-micro/core`, `@i18n-micro/types` et `@i18n-micro/utils` sont installés avec ces paquets ; vous les importez rarement directement. Les signatures de chaque export figurent dans la [référence des paquets](/fr/api/packages/overview) générée.

Chaque paquet dispose d'un playground sous `packages/<name>/playground` dans le dépôt.

## L'instance {#the-instance}

`createI18n(options)` renvoie une instance qui contient les dictionnaires, la locale courante et la route courante. Les options sont les mêmes dans tous les paquets :

| Option | Type | Défaut | Remarques |
| --- | --- | --- | --- |
| `locale` | `string` | obligatoire | Locale active. |
| `fallbackLocale` | `string` | `locale` | Consultée lorsqu'une clé est absente dans `locale`. |
| `messages` | `Record<locale, Translations>` | `{}` | Dictionnaires racine (route `'index'`). |
| `routeMessages` | `Record<route, Record<locale, Translations>>` | `{}` | Dictionnaires de route. Runtime, React, Preact, Node et VitePress uniquement. |
| `plural` | `PluralFunc` | `defaultPlural` | Règle de pluriel personnalisée. |
| `missingWarn` | `boolean` | `true` | `console.warn` dans le navigateur pour une clé manquante, en développement uniquement. |
| `missingHandler` | `(locale, key, routeName) => void` | — | Appelé à la place de l'avertissement. |
| `numberFormats` | `Record<locale, Record<name, Intl.NumberFormatOptions>>` | — | Formats nommés : `tn(9.5, 'currency')`. |
| `datetimeFormats` | `Record<locale, Record<name, Intl.DateTimeFormatOptions>>` | — | Formats nommés : `td(date, 'short')`. |
| `timeZone` | `string` | fuseau du runtime | Fuseau IANA pour les dates de `td` ; n'affecte pas `tdr`. Définissez-le pour que le serveur et le navigateur rendent la même date. |
| `now` | `() => number` | `Date.now` | L'horloge de `tdr`. Transmettez l'heure du serveur à l'hydratation pour que les deux rendent le même texte. |
| `localeIso` | `Record<code, string>` | — | Balise BCP 47 utilisée pour les règles de pluriel (`ua` → `uk-UA`). React, Preact et Solid la prennent depuis `iso` dans les `locales` du provider. |

Les dictionnaires se trouvent dans `i18n.storage.translations`, une `Map` indexée par `locale:route` (`en:index`, `en:about`).

Une clé est recherchée dans le dictionnaire de la route courante, puis dans le dictionnaire racine, d'abord pour `locale`, puis pour `fallbackLocale`. Une clé manquante renvoie la clé elle-même (ou le `defaultValue` que vous passez).

```ts
i18n.addTranslations('en', { nav: { home: 'Home' } }) // root, deep-merged
i18n.addRouteTranslations('en', 'about', { title: 'About us' }) // route chunk
i18n.addTranslations('en', { nav: { home: 'Start' } }, false) // replace instead of merge
i18n.setRoute('about')
i18n.t('title') // 'About us'
i18n.t('nav.home') // 'Start' (root key, still visible on the route)
```

### Traduire et formater {#translate-and-format}

| Méthode | Renvoie |
| --- | --- |
| `t(key, params?, defaultValue?, routeName?)` | La valeur (chaîne, nombre, objet) avec les `{param}` interpolés. |
| `ts(...)` | Identique à `t`, sous forme de chaîne. |
| `tc(key, count \| params, defaultValue?)` | Forme plurielle. |
| `tn(value, options \| name)` | `Intl.NumberFormat` dans la locale active. |
| `td(value, options \| name)` | `Intl.DateTimeFormat`. |
| `tdr(value, options?)` | Temps relatif (`3 days ago`). |
| `has(key, routeName?)` | `true` lorsque la locale active possède la clé (dictionnaire de route ou racine ; le fallback n'est pas vérifié). |

`defaultPlural` découpe la valeur sur `|` et choisit la forme à l'index `count`, plafonné à la dernière ; un `count` négatif, fractionnaire ou `NaN` choisit la dernière forme.

Une règle `plural` personnalisée reçoit `(key, count, params, locale, getter)`. Lisez la valeur via `getter(key)` ; ne découpez pas la clé :

```ts
import type { PluralFunc } from '@i18n-micro/vue'

const plural: PluralFunc = (key, count, params, _locale, getter) => {
  const value = getter(key)
  if (typeof value !== 'string') return null
  const forms = value.split('|').map((form) => form.trim())
  return (count === 1 ? forms[0] : forms[1] ?? forms[0])!.replace('{count}', String(count))
}
```

## Adaptateur de routeur {#router-adapter}

Les paquets SPA ne dépendent d'aucun routeur. Un adaptateur de routeur (`I18nRoutingStrategy`) leur indique comment lire le chemin courant, naviguer et construire un chemin localisé. Les adaptateurs intégrés préfixent toutes les locales sauf `defaultLocale` (`/about`, `/de/about`).

| Membre | Obligatoire | Utilisé par |
| --- | --- | --- |
| `getCurrentPath(): string` | oui | vérification du lien actif (par page ; la query et le hash ne comptent pas), `switchLocale` (les conserve) |
| `push({ path }): void` | oui | `switchLocale`, `<I18nLink>` sans `linkComponent`, `<I18nSwitcher>` |
| `replace({ path }): void` | oui | — |
| `resolvePath(to, locale)` | non | `localePath`, `localeRoute`, `<I18nLink>` ; sans lui, les chemins sont renvoyés tels quels |
| `linkComponent` | non | `<I18nLink>` le rend (par ex. `RouterLink`) au lieu de `<a>` |
| `getRoute()` | non | `{ fullPath, query }` pour les helpers SEO |

`push` et `replace` sont obligatoires dans Vue, React, Preact et Solid. Astro possède son propre adaptateur côté serveur, avec `push`/`replace` optionnels (voir [Astro](/fr/integrations/astro-package#router-adapter)).

Un adaptateur minimal pour n'importe quel routeur basé sur l'historique :

```ts
import type { I18nRoutingStrategy } from '@i18n-micro/react'

const locales = ['en', 'de']
const stripLocale = (path: string) => path.replace(/^\/(en|de)(?=\/|$)/, '') || '/'

export const historyAdapter: I18nRoutingStrategy = {
  getCurrentPath: () => window.location.pathname + window.location.search + window.location.hash,
  push: ({ path }) => window.history.pushState({}, '', path),
  replace: ({ path }) => window.history.replaceState({}, '', path),
  resolvePath: (to, locale) => {
    const path = stripLocale(typeof to === 'string' ? to : to.path || '/')
    return locale === 'en' ? path : `/${locale}${path === '/' ? '' : path}`
  },
}
```

## Composants {#components}

Vue, React, Preact et Solid fournissent les mêmes quatre composants. Leurs props sont identiques ; React, Preact et Solid transmettent les autres props à l'élément racine.

### `<I18nT>` {#&lt;i18nt&gt;}

| Prop | Type | Remarques |
| --- | --- | --- |
| `keypath` | `string` | obligatoire |
| `params` | `object` | valeurs d'interpolation |
| `plural` | `number \| string` | rend `tc(keypath, count)` |
| `number` | `number \| string` | passe `tn(number)` en tant que `{number}` |
| `date` | `Date \| string \| number` | passe `td(date)` en tant que `{date}` |
| `relativeDate` | `Date \| string \| number` | passe `tdr(relativeDate)` en tant que `{relativeDate}` |
| `tag` | `string` | élément conteneur, `span` par défaut |
| `html` | `boolean` | rend la traduction en HTML ; elle doit être fiable, les paramètres sont échappés |
| `defaultValue` | `string` | remplace une clé manquante, et est rendu seul lorsque `hideIfEmpty` masque une valeur vide |
| `hideIfEmpty` | `boolean` | ne rend rien pour une traduction vide |
| `customPluralRule` | `PluralFunc` | règle de pluriel pour cet élément |

Une seule prop de formatage s'applique, vérifiées dans cet ordre : `number`, `date`, `relativeDate`, `plural`.

#### Texte enrichi {#rich-text}

Un `{placeholder}` peut contenir un élément. Dans Vue, c'est un slot nommé ; dans React, Preact et Solid, la prop `components` fournit des éléments, ou des fonctions en renvoyant un, par nom. Dans les deux cas, il l'emporte sur un paramètre du même nom, fonctionne dans toutes les branches et résiste à une locale qui réordonne les placeholders.

```tsx
// { "terms": "I accept the {link} of {company}" }
<I18nT keypath="terms" params={{ company: 'ACME' }} components={{ link: <a href="/terms">terms</a> }} />
```

Dans Solid, passez une fonction lorsqu'un placeholder se répète : un nœud ne peut occuper qu'un seul emplacement. Les `children` remplacent le texte ; sous forme de fonction, ils reçoivent `{ translation }`, comme le slot par défaut de Vue. `html` ignore tout cela.

### `<I18nLink>` {#&lt;i18nlink&gt;}

| Prop | Type | Remarques |
| --- | --- | --- |
| `to` | `string \| { path }` | localisé via le `resolvePath` de l'adaptateur |
| `activeStyle` | objet de style | fusionné par-dessus `style` sur la page courante ; React, Preact et Solid l'appliquent aussi à une section parente |
| `localeRoute` | fonction | remplace `resolvePath` pour ce lien |

Les URL externes (`https://`, `mailto:`, `tel:`) sont rendues sous la forme `<a target="_blank" rel="noopener noreferrer">` ; vos propres `target` ou `rel` l'emportent. `onClick` s'exécute toujours. Un clic avec modificateur, un autre bouton de souris ou un `target` sont laissés au navigateur.

### `<I18nSwitcher>` {#&lt;i18nswitcher&gt;}

Une liste déroulante des locales activées (les locales `disabled: true` sont masquées) avec des styles par défaut inline. Ses éléments sont des liens, avec `lang`, `hreflang` et `dir` issus de la locale. Par défaut, un clic sur l'un d'eux définit la locale et appelle le `push` de l'adaptateur avec le chemin courant localisé ; une prop `switchLocale` remplace cette action. Avec un `localeRoute` et sans routeur, le navigateur suit le lien. Échap ou un clic à l'extérieur la ferme.

| Prop | Remarques |
| --- | --- |
| `locales`, `currentLocale`, `getLocaleName` | remplacent les valeurs fournies |
| `switchLocale(code)` | remplace le changement intégré |
| `localeRoute` | remplace `resolvePath` |
| `customLabels` | `{ de: 'DE' }` |
| `customWrapperStyle`, `customButtonStyle`, `customDropdownStyle`, `customItemStyle`, `customLinkStyle`, `customActiveLinkStyle`, `customDisabledLinkStyle`, `customIconStyle` | surcharges de style |

### `<I18nGroup>` {#&lt;i18ngroup&gt;}

Un `<div class="i18n-group">` qui transmet un `t` préfixé à ses enfants. Il ne préfixe **pas** les `<I18nT>` ni les appels `t()` qu'il contient ; seul le `t` qu'il transmet est préfixé.

| Prop | Remarques |
| --- | --- |
| `prefix` | obligatoire, par ex. `'profile'` |
| `groupClass` | classe supplémentaire sur le conteneur |

Le `t` préfixé est fourni via un slot scopé dans Vue (`v-slot="{ t }"`) et via un enfant render-prop dans React, Preact et Solid (`{({ t }) => …}`).

## Clés typées {#typed-keys}

`t()` accepte n'importe quelle chaîne. Pour obtenir l'autocomplétion de vos clés, générez une déclaration avec le [générateur de types](/fr/integrations/types-generator). Les clés sont suggérées, pas imposées, et les paramètres ne sont pas typés.

## Comparaison avec le module Nuxt {#compared-with-the-nuxt-module}

Les paquets n'ont ni routage basé sur les fichiers, ni middleware serveur, ni loader de traductions : vous décidez quand charger le JSON (`import`, `fetch`, ou `@i18n-micro/node` sur le serveur) et quel adaptateur de routeur utiliser. La détection de la locale, les meta SEO et la génération des routes sont des fonctionnalités de Nuxt ; Astro possède son propre middleware pour la détection et `useLocaleHead` pour le SEO.
