`@i18n-micro/vue` est un plugin Vue 3 qui embarque le cœur de traduction de Nuxt I18n Micro : `t()` réactif, `$t` global, quatre composants et un adaptateur vue-router facultatif. Utilisez-le dans une application Vue Vite ou SSR qui n'est pas construite avec Nuxt. Le modèle d'instance, le contrat du routeur et les props des composants sont partagés avec les autres packages et décrits dans [Frameworks](/fr/integrations/overview).

## Installation {#install}

<CodeGroup>

```bash pnpm
pnpm add @i18n-micro/vue
```

```bash npm
npm install @i18n-micro/vue
```

```bash yarn
yarn add @i18n-micro/vue
```

</CodeGroup>

Dépendances peer : `vue` `^3.3.0` ; `vue-router` `^4.5.1 || ^5.0.0` (facultatif, uniquement pour `@i18n-micro/vue/router`). Les types publiés nécessitent Vue 3.5.5 ou une version ultérieure avec `skipLibCheck: false` ; avec `skipLibCheck: true`, le réglage habituel des templates, les versions plus anciennes compilent aussi.

## Configuration {#setup}

```ts
// src/main.ts
import { createApp } from 'vue'
import { createI18n } from '@i18n-micro/vue'
import App from './App.vue'
import en from './locales/en.json'

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales: [
    { code: 'en', iso: 'en-US', displayName: 'English' },
    { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
  ],
  defaultLocale: 'en',
})

createApp(App).use(i18n).mount('#app')
```

`locales` et `defaultLocale` sont obligatoires pour `useI18n()` : sans eux, il lève `I18nLocalesKey not provided`. Passez-les à `createI18n` (comme ci-dessus), à `useI18n({ locales, defaultLocale })`, ou via `app.provide(I18nLocalesKey, …)` et `app.provide(I18nDefaultLocaleKey, …)`.

Le plugin enregistre globalement `I18nT`, `I18nLink`, `I18nGroup` et `I18nSwitcher`, et ajoute `$t`, `$ts`, `$tc`, `$tn`, `$td`, `$tdr`, `$has` et `$i18n` aux templates. En dehors des composants, l'instance est `i18n.global`. Les autres options sont décrites dans [l'instance](/fr/integrations/overview#the-instance) ; `routeMessages` n'est pas disponible dans Vue, utilisez `addRouteTranslations`.

## Traduire {#translate}

```vue
<script setup lang="ts">
import { useI18n } from '@i18n-micro/vue'

const { t, tc, tn } = useI18n()
</script>

<template>
  <h1>{{ t('greeting', { name: 'Ada' }) }}</h1>
  <!-- Hello, Ada! -->
  <p>{{ tc('apples', 3) }}</p>
  <!-- 3 apples -->
  <p>{{ $t('nav.home') }} · {{ tn(1234.5) }}</p>
</template>
```

`useI18n()` renvoie les méthodes de traduction (`t`, `ts`, `tc`, `tn`, `td`, `tdr`, `has`), `locale` (un computed modifiable), `getLocale`, `getLocales`, `defaultLocale()`, `getLocaleName`, `localePath`, `localeRoute`, `switchLocale`, `setRoute`, `getRoute`, `addTranslations`, `addRouteTranslations`, `mergeTranslations`, `resolveTranslations`, `setTranslation`, `clearCache` et `instance`.

Chargez d'autres dictionnaires à tout moment ; chaque composant qui les lit se réaffiche :

```ts
const { addTranslations, addRouteTranslations, setRoute } = useI18n()

addTranslations('de', (await import('./locales/de.json')).default)
addRouteTranslations('en', 'about', { title: 'About us' })
setRoute('about') // t('title') now reads the 'about' dictionary first
```

## Changer de locale {#switch-locale}

```ts
const { locale, switchLocale } = useI18n()

locale.value = 'de' // only the locale
switchLocale('de') // the locale, then router.push to the localized current path
```

Chargez le dictionnaire de la locale avant ou après le changement ; le changement ne récupère rien.

`<I18nGroup>` fournit à son slot un `t` préfixé. Les clés à l'intérieur de `<I18nT>` ou d'un simple `t()` ne sont pas préfixées :

```vue
<I18nGroup prefix="profile" v-slot="{ t }">
  <h2>{{ t('title') }}</h2>
  <!-- profile.title -->
</I18nGroup>
```

## Routage {#routing}

L'adaptateur vue-router se trouve dans un sous-chemin, de sorte que le point d'entrée principal n'importe jamais `vue-router` :

```ts
// src/main.ts
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import { createI18n } from '@i18n-micro/vue'
import { createVueRouterAdapter } from '@i18n-micro/vue/router'
import App from './App.vue'
import Home from './pages/Home.vue'
import About from './pages/About.vue'
import en from './locales/en.json'

const locales = [
  { code: 'en', iso: 'en-US', displayName: 'English' },
  { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
]

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/:locale(de)?', component: Home },
    { path: '/:locale(de)?/about', component: About },
  ],
})

const i18n = createI18n({
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
  locales,
  defaultLocale: 'en',
  routingStrategy: createVueRouterAdapter(router, locales, 'en'),
})

createApp(App).use(router).use(i18n).mount('#app')
```

`createVueRouterAdapter(router, locales, defaultLocale)` préfixe toutes les locales sauf celle par défaut (`/about`, `/de/about`) et rend `<I18nLink>` sous forme de `RouterLink`. Lisez vous-même la locale depuis la route, par exemple dans `router.beforeEach`, et définissez `i18n.global.locale.value`. Vous pouvez aussi attacher un adaptateur plus tard avec `i18n.setRoutingStrategy(adapter)` ; pour un adaptateur personnalisé, voir [Adaptateur de routeur](/fr/integrations/overview#router-adapter).

## SSR {#ssr}

- Créez le routeur, l'instance i18n et l'application dans la fonction de rendu exécutée à chaque requête. Une instance partagée ferait fuiter la locale d'un visiteur vers un autre.
- Utilisez `createMemoryHistory()` côté serveur, prenez la locale depuis l'URL, et chargez son dictionnaire (ainsi que celui du fallback) avant `renderToString`.
- Envoyez la locale au client (par exemple dans un script `window.__STATE__`) et créez l'instance client avec la même `locale` pour que l'hydratation corresponde.
- `<I18nSwitcher>` ne lit `window.location` que lorsque le menu déroulant est ouvert ; il s'affiche donc côté serveur.

`packages/vue/playground` contient une paire complète `entry-server.ts` / `entry-client.ts`.

## Head SEO {#seo-head}

`useLocaleHead(options)` construit les balises `lang`/`dir`, canonical, `hreflang` et `og:locale` à partir des locales et de l'adaptateur de routeur. Appelez `updateMeta()` lorsque la route change et passez `metaObject` à votre gestionnaire de head :

```ts
import { watch } from 'vue'
import { useRoute } from 'vue-router'
import { useHead } from '@unhead/vue'
import { useLocaleHead } from '@i18n-micro/vue'

const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
watch(() => route.fullPath, () => updateMeta(), { immediate: true })
useHead(metaObject)
```

Options : `baseUrl` (chaîne ou fonction), `addDirAttribute` (par défaut `true`), `addSeoAttributes` (par défaut `true`), `identifierAttribute` (par défaut `'id'`), `hreflangBaseLanguage` (par défaut `false`). Les locales avec `disabled: true` ou `seo: false` n'obtiennent pas de lien alternate.

## API {#api}

| Export | Point d'entrée |
| --- | --- |
| `createI18n`, `useI18n`, `useLocaleHead` | `@i18n-micro/vue` |
| `I18nT`, `I18nLink`, `I18nSwitcher`, `I18nGroup` | `@i18n-micro/vue` |
| `VueI18n` (classe d'instance), `I18nInjectionKey`, `I18nLocalesKey`, `I18nDefaultLocaleKey` | `@i18n-micro/vue` |
| `defaultPlural`, `FormatService`, `interpolate` | `@i18n-micro/vue` |
| Types : `I18nRoutingStrategy`, `Locale`, `Translations`, `PluralFunc`, `Params`, `Getter`, `CleanTranslation`, `LocaleCode`, `VueI18nOptions`, `UseI18nOptions`, `UseLocaleHeadOptions`, `I18nPlugin` | `@i18n-micro/vue` |
| `createVueRouterAdapter` | `@i18n-micro/vue/router` |

`TranslationKey` n'est pas réexporté depuis `@i18n-micro/vue` ; importez-le depuis `@i18n-micro/types`. Signatures complètes : [référence du package](/fr/api/packages/vue).
