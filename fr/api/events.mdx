# 📢 Événements

## 🔄 `i18n:register`

L'événement `i18n:register` de `Nuxt I18n Micro` permet l'ajout dynamique de traductions au contexte i18n de votre application, rendant le processus d'internationalisation fluide et flexible. Cet événement vous permet d'intégrer de nouvelles traductions au besoin, en enrichissant les capacités de localisation de votre application.

### 📝 Détails de l'événement

- **Objectif** :
  - Permet d'incorporer dynamiquement des traductions supplémentaires dans l'ensemble existant pour une locale donnée.

- **Charge utile** :
  - **`register`** :
    - Une fonction fournie par l'événement qui prend deux arguments :
      - **`translations`** (`Translations`) :
        - Un objet contenant des paires clé-valeur représentant les traductions, organisées selon l'interface `Translations`.
      - **`locale`** (`string`, optionnel) :
        - Le code de locale (par exemple, `'en'`, `'ru'`) pour lequel les traductions sont enregistrées. Par défaut, la locale fournie par l'événement si non spécifiée.

- **Comportement** :
  - Lorsqu'elle est déclenchée, la fonction `register` fusionne les nouvelles traductions dans le contexte courant pour la locale spécifiée, mettant à jour les traductions disponibles dans toute l'application.

### ⏱️ Quand il se déclenche

Le plugin hooks du module (`05.hooks.ts`, `dependsOn: ['i18n-plugin-loader']`) appelle `nuxtApp.callHook('i18n:register', …)` :

1. **Une fois au démarrage** — après que le plugin i18n principal (`01.plugin.ts`) a chargé les traductions pour la route initiale.
2. **À la navigation** — dans `router.beforeEach` lorsque le chemin change, ou à chaque navigation lorsque `strategy: 'no_prefix'`.

Enregistrez votre écouteur dans un plugin Nuxt normal avec `nuxtApp.hook('i18n:register', …)`. Le plugin hooks s'exécute après que le loader est prêt, si bien que votre callback est invoqué lorsque les traductions doivent être étendues.

Définissez `hooks: false` dans `nuxt.config` pour désactiver les appels automatiques à `i18n:register` (voir [Configuration — `hooks`](/guides/configuration#hooks)).

### 💡 Exemple d'utilisation

L'exemple suivant montre comment utiliser l'événement `i18n:register` pour ajouter dynamiquement des traductions :

```typescript
nuxt.hook('i18n:register', async (register: (translations: unknown, locale?: string) => void, locale: string) => {
  register(
    {
      greeting: 'Hello',
      farewell: 'Goodbye',
    },
    locale,
  )
})
```

- **Déclenchement de l'événement** :
  - Le plugin hooks (`05.hooks.ts`) déclenche `i18n:register` après que le loader principal est prêt et lors des navigations pertinentes.

- **Ajout de traductions** :
  - L'exemple enregistre des traductions anglaises pour `"greeting"` et `"farewell"`.
  - La fonction `register` fusionne ces traductions dans l'ensemble existant pour la locale fournie.

### 🔗 Bénéfices clés

- **Mises à jour dynamiques** :
  - Mettez à jour ou ajoutez facilement des traductions sans redéployer toute votre application.

- **Souplesse de localisation** :
  - Permet des ajustements de localisation en temps réel en fonction des besoins de l'utilisateur ou de l'application.

En utilisant l'événement `i18n:register`, vous pouvez garantir que la stratégie de localisation de votre application reste flexible et adaptable, améliorant l'expérience utilisateur globale.

## 🛠️ Modifier les traductions avec des plugins

Pour modifier les traductions dynamiquement dans votre application Nuxt, l'utilisation de plugins est recommandée. Les plugins fournissent un moyen structuré de gérer les mises à jour de localisation, en particulier lorsque vous travaillez avec des modules ou des fichiers de traduction externes.

### **Enregistrer le plugin**

Si vous utilisez un module, enregistrez le plugin où les modifications de traduction auront lieu en l'ajoutant à la configuration de votre module :

```javascript
addPlugin({
  src: resolve('./plugins/extend_locales'),
})
```

Cela enregistre le plugin situé à `./plugins/extend_locales`, qui prendra en charge le chargement et l'enregistrement dynamiques des traductions.

### **Implémenter le plugin**

Dans le plugin, vous pouvez gérer les modifications de locale. Voici un exemple d'implémentation dans un plugin Nuxt :

```typescript
import { defineNuxtPlugin } from '#app'

export default defineNuxtPlugin(async (nuxtApp) => {
  // Function to load translations from JSON files and register them
  const loadTranslations = async (lang: string) => {
    try {
      const translations = await import(`../locales/${lang}.json`)
      return translations.default
    } catch (error) {
      console.error(`Error loading translations for language: ${lang}`, error)
      return null
    }
  }

  // Hook into the 'i18n:register' event to dynamically add translations
  // eslint-disable-next-line @typescript-eslint/ban-ts-comment
  // @ts-expect-error
  nuxtApp.hook('i18n:register', async (register: (translations: unknown, locale?: string) => void, locale: string) => {
    const translations = await loadTranslations(locale)
    if (translations) {
      register(translations, locale)
    }
  })
})
```

### 📝 Explication détaillée

1. **Chargement des traductions** :

- La fonction `loadTranslations` importe dynamiquement les fichiers de traduction en fonction de la locale. Les fichiers sont censés se trouver dans le dossier `locales` et être nommés selon les codes de locale (par exemple, `en.json`, `de.json`).
- En cas de chargement réussi, les traductions sont renvoyées ; sinon, une erreur est enregistrée.

2. **Enregistrement des traductions** :

- Le plugin s'abonne à l'événement `i18n:register` via `nuxtApp.hook`.
- Lorsque l'événement se déclenche, la fonction `register` est appelée avec les traductions chargées et la locale correspondante.
- Cela fusionne les nouvelles traductions dans le contexte i18n pour la locale spécifiée, en mettant à jour les traductions disponibles dans toute l'application.

### 🔗 Avantages d'utiliser des plugins pour modifier les traductions

- **Séparation des responsabilités** :
  - Encapsulez la logique de localisation séparément du code principal de l'application, ce qui simplifie la gestion et la maintenance.

- **Dynamique et scalable** :
  - En chargeant et enregistrant les traductions dynamiquement, vous pouvez mettre à jour le contenu sans redéploiement complet, particulièrement utile pour les applications au contenu fréquemment mis à jour ou multilingue.

- **Souplesse de localisation renforcée** :
  - Les plugins vous permettent de modifier ou d'étendre les traductions au besoin, offrant une stratégie de localisation plus adaptable et plus réactive qui répond aux préférences des utilisateurs ou aux exigences métier.

En adoptant cette approche, vous pouvez étendre et modifier efficacement la localisation de votre application via un processus structuré et maintenable basé sur des plugins, en gardant l'internationalisation adaptable aux besoins changeants et en améliorant l'expérience utilisateur globale.
