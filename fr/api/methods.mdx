---

Le module injecte ses helpers d’exécution dans l’application Nuxt : `$t`, `$tc`, `$localePath`, `$switchLocale` et les autres. Utilisez cette page pour consulter la signature et le comportement d’un helper. Les signatures et descriptions proviennent des interfaces `PluginsInjections` et `NuxtAppOnlyInjections` de `src/runtime/plugins/01.plugin.ts`.

## Accès {#access}

| Où | Comment |
| --- | --- |
| Template | `{{ $t('title') }}` — tous les helpers, avec le `$` |
| `<script setup>` | `const { t, localePath } = useI18n()` — tous les helpers de `PluginsInjections`, avec et sans le `$` |
| Plugin, middleware, `<script setup>` | `const { $t, $defineI18nRoute } = useNuxtApp()` — tout, uniquement avec `$` |

`$defineI18nRoute` n’est typé que sur `useNuxtApp()`. Voir [`useI18n`](/fr/composables/useI18n).

```vue
<script setup lang="ts">
const { t, localePath } = useI18n()
</script>

<template>
  <NuxtLink :to="localePath('/about')">{{ t('nav.about') }}</NuxtLink>
</template>
```

## Locale {#locale}

### `$getLocale` {#$getlocale}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric) => string
```

Code de la locale active. Passez une route pour lire la locale à laquelle cette route appartient.

```ts
$getLocale() // 'de' on /de/about
```

### `$getLocaleName` {#$getlocalename}

```ts
() => string | null
```

Le `displayName` de la locale active issu de la configuration, ou `null` si elle n’en a pas.

### `$getLocales` {#$getlocales}

```ts
() => Locale[]
```

Toutes les locales configurées, avec leurs métadonnées.

Les propriétés personnalisées d’un objet locale sont renvoyées telles qu’écrites ; typez-les par [augmentation de module](/fr/api/module-options#locales) de `Locale`.

### `$defaultLocale` {#$defaultlocale}

```ts
() => string | undefined
```

Code de la locale par défaut configurée.

### `$getI18nConfig` {#$geti18nconfig}

```ts
() => ResolvedI18nConfig
```

La configuration résolue du module, telle que le runtime la voit.

La valeur inclut les [surcharges à l’exécution](/fr/guide/runtime-overrides) (`defaultLocale`, `fallbackLocale`, locales désactivées).

```ts
const { strategy, localeCookie } = useNuxtApp().$getI18nConfig()
```

## Traduction {#translation}

### `$t` {#$t}

```ts
TranslationFn<CleanTranslation>
```

Traduit une clé en y interpolant `params`. Renvoie `defaultValue` lorsque la clé est
absente, ou la clé elle-même si aucune valeur par défaut n’est fournie.

```ts
// { "welcome": "Welcome, {name}!" }
$t('welcome', { name: 'Ada' }) // 'Welcome, Ada!'
$t('missing.key', {}, 'Fallback') // 'Fallback'
```

Une clé qui pointe vers un objet imbriqué renvoie cet objet, et non une chaîne. Dans un template, il s’affiche sous la forme `[object Object]` ; utilisez une clé feuille.

### `$ts` {#$ts}

```ts
TranslationFn<string>
```

Comme `$t`, mais renvoie toujours une chaîne : la valeur passe par `toString()`, donc un objet
imbriqué devient `'[object Object]'`. Faites pointer la clé vers une feuille.

### `$_t` {#$_t}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<CleanTranslation>
```

Lie `$t` à une route précise, pour traduire en dehors de la page courante — par exemple un layout
qui affiche un lien vers une autre route.

```ts
const route = useRoute()
const t = useNuxtApp().$_t(route)
t('page.title')
```

### `$_ts` {#$_ts}

```ts
(route: RouteLocationNormalizedLoaded) => TranslationFn<string>
```

Lie `$ts` à une route précise. Voir `$_t`.

### `$tc` {#$tc}

```ts
(key: TranslationKey, params: number | Params, defaultValue?: string) => string
```

Traduit avec gestion du pluriel. `params` peut être le nombre lui-même, ou un objet contenant
`count`.

Les formes sont séparées par `|`. Avec la règle intégrée, un nombre entier positif ou nul `n` sélectionne la forme `n`, limitée à la dernière forme ; un nombre négatif, fractionnaire ou `NaN` prend la dernière forme. `{count}` et les autres paramètres sont interpolés dans la forme choisie.

Pour les langues dont les pluriels ne suivent pas le nombre, commencez le modèle par `=0 `. La première forme sert alors pour 0, et les autres suivent la catégorie [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules), dans l’ordre `zero, one, two, few, many, other` :

```json
{
  "apples": "=0 no apples | one apple | {count} apples",
  "files": "=0 no files | {count} one | {count} few | {count} many"
}
```

```ts
$tc('apples', 0) // 'no apples'
$tc('apples', 1) // 'one apple'
$tc('apples', 7) // '7 apples'

// In `uk` (categories `one, few, many, other`) the forms after the zero form follow those categories:
$tc('files', 21) // '21 one'
$tc('files', 22) // '22 few'
$tc('files', 25) // '25 many'
$tc('files', 2.5) // '2.5 many': no form for `other`, so the last one
```

- `=0 ` n’est pris en compte qu’au tout début de la valeur, avec l’espace. `$t` l’affiche comme du texte : il est réservé aux pluriels.
- Une catégorie sans forme propre prend la dernière forme. Un nombre négatif ou fractionnaire prend aussi la dernière forme.
- Cela fonctionne dans n’importe quelle locale : `=0 none | one | {count} many` en anglais.
- La catégorie provient de l’`iso` de la locale, sinon de son code. Un code inconnu d’`Intl` revient à la règle par index, le marqueur étant tout de même retiré, de sorte que le résultat ne dépend jamais de la machine.
- `<i18n-t :plural>` suit la même règle. Un [`plural`](/fr/api/module-options#plural) ou `customPluralRule` personnalisé reçoit la valeur brute, marqueur compris, et décide lui-même ; un `plural` qui renvoie `null` rend la main à la règle intégrée, qui respecte le marqueur.

Sans le marqueur, un modèle reste sur la règle par index, à une exception près qui ne peut se lire que d’une seule façon : une forme zéro sans placeholder, puis une forme par catégorie, avec `{count}` dans chaque forme partagée par plusieurs nombres (`no files | {count} one | {count} few | {count} many` en `uk`).

Pour vos propres règles, définissez [`plural`](/fr/api/module-options#plural).

```ts
// { "apples": "no apples | one apple | {count} apples" }
$tc('apples', 0) // 'no apples'
$tc('apples', 10) // '10 apples'
$tc('cart', { count: 2, name: 'Ada' }) // count and params in one object
```

Le troisième argument est `defaultValue`, pas des paramètres.

### `$has` {#$has}

```ts
(key: string) => boolean
```

Indique si une clé se résout dans la locale active. Utilisez-le pour conditionner l’affichage d’un texte optionnel plutôt que
d’afficher une clé brute. Comme `$t`, il voit aussi les clés de la page quittée lors d’une transition
de page dans la même locale.

```ts
if ($has('promo.banner')) show.value = true
```

## Formatage {#formatting}

### `$tn` {#$tn}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

Formate un nombre avec `Intl.NumberFormat` dans la locale active. Une clé sélectionne un format nommé
issu de la configuration.

Les formats nommés proviennent de [`numberFormats`](/fr/api/module-options#numberformats).

```ts
$tn(1234.5, { style: 'currency', currency: 'EUR' }) // '1.234,50 €' in de
$tn(1000, 'currency') // named format
$tn(1000, 'currency', 'de') // named format in another locale
```

### `$td` {#$td}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

Formate une date avec `Intl.DateTimeFormat` dans la locale active. Une clé sélectionne un format nommé
issu de la configuration.

Les formats nommés proviennent de [`datetimeFormats`](/fr/api/module-options#datetimeformats).

```ts
$td(new Date(), { dateStyle: 'long' })
$td(post.createdAt, 'short')
```

### `$tdr` {#$tdr}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

Formate une date en temps relatif (« il y a 3 jours ») avec `Intl.RelativeTimeFormat`.

```ts
$tdr(Date.now() - 5 * 60_000) // '5 minutes ago' in en
```

## Changement de locale et liens {#switching-and-links}

### `$switchLocale` {#$switchlocale}

```ts
(locale: string) => Promise<boolean>
```

Navigue vers la page courante dans une autre locale. En `no_prefix` et en mode hash, il charge les
traductions de la locale avant de naviguer ; en `no_prefix`, la route est remplacée sur place (aucune
nouvelle entrée d’historique). Une locale inconnue est ignorée.
L’appel est asynchrone : utilisez `await` pour exécuter du code après la navigation. Il se résout à `true` lorsque le
dictionnaire de la locale est actif, à `false` sinon : le chunk n’a pas pu être chargé (le dictionnaire
courant est conservé ; rappelez-le pour réessayer) ou un changement plus récent l’a emporté.

```ts
await $switchLocale('de')
```

### `$switchLocalePath` {#$switchlocalepath}

```ts
(locale: string) => string
```

Le chemin de la page courante dans une autre locale, sans naviguer.

```vue
<NuxtLink :to="$switchLocalePath('de')">Deutsch</NuxtLink>
```

### `$switchLocaleRoute` {#$switchlocaleroute}

```ts
(locale: string) => RouteLocationRaw
```

L’objet route de la page courante dans une autre locale, sans naviguer, ou une URL sous forme de chaîne
pour une locale ayant son propre `baseUrl`. Avec `trailingSlash`, l’objet possède `path` et `fullPath`,
conformes à la règle, avec `query` et `hash` inchangés, et `router.push` ou un lien les conservent.

### `$switchRoute` {#$switchroute}

```ts
(route: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, toLocale?: string) => Promise<void>
```

Navigue vers une autre route, en conservant la locale active ou en passant à `toLocale`. Asynchrone comme
`$switchLocale`.

```ts
$switchRoute('/about') // active locale
$switchRoute({ name: 'about' }, 'de') // switch to de
```

### `$localePath` {#$localepath}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => string
```

Résout un chemin dans la locale donnée, ou dans la locale active. Une chaîne avec un schéma `http(s):`, `mailto:`
ou `tel:` est renvoyée telle quelle : ne passez pas une saisie utilisateur comme cible de lien sans la vérifier.

Un chemin sous forme de chaîne est interprété comme la page qu’il affiche, donc le chemin personnalisé d’une locale est aussi appliqué.

```ts
$localePath('/about') // '/about' in en, '/de/ueber-uns' in de with localeRoutes
$localePath({ name: 'about' }, 'fr') // '/fr/about'
```

### `$localeRoute` {#$localeroute}

```ts
(to: RouteLocationNamedRaw | RouteLocationResolvedGeneric | string, locale?: string) => RouteLocationResolved
```

Résout une route dans la locale donnée, ou dans la locale active. Un objet simple, qu’on peut conserver dans un état sans risque. Lorsqu’un paramètre doit être
échappé, il possède `path`, `fullPath`, `query` et `hash` mais ni `name` ni `params` : c’est le chemin qui fournit au routeur
l’URL encodée. Pour une locale sur un autre domaine, `path` et `fullPath` sont absolus, ce que le routeur ne peut pas accepter :
un tel lien passe par `<i18n-link>`, ou par `$localePath`.

### `$getRouteName` {#$getroutename}

```ts
(route?: RouteLocationNormalizedLoaded | RouteLocationResolvedGeneric, locale?: string) => string
```

Nom de la route sans le préfixe de locale — le nom qui sert de clé aux traductions.

```ts
$getRouteName() // 'about' on /de/about
```

## Configuration de page {#page-config}

### `$defineI18nRoute` {#$definei18nroute}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

Enregistre la configuration de locale et les traductions propres à une page depuis un composant.
Fusionne dans la locale active et se réapplique lorsque la locale change.

Appelez-le dans le `<script setup>` d’une page, toujours déstructuré depuis `useNuxtApp()`. Le build lit `locales`, `localeRoutes` et `disableMeta` dans l’appel ; à l’exécution, seul `locales` compte (les traductions en ligne sont fusionnées pour la locale active). Règles complètes : [Configuration de page](/fr/guide/per-component-translations).

```vue
<script setup lang="ts">
const { $defineI18nRoute } = useNuxtApp()

$defineI18nRoute({
  locales: ['en', 'de'],
  localeRoutes: { en: '/about', de: '/ueber-uns' },
})
</script>
```

### `$setI18nRouteParams` {#$seti18nrouteparams}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

Définit des paramètres par locale pour la route courante, afin qu’un segment dynamique puisse différer selon la langue.
Appelez-le pendant le SSR, avant le rendu du head.

Les paramètres sont effacés lorsqu’une navigation vers un autre chemin est validée, y compris de `/news/1` vers `/news/4`, qui conserve le nom de route. Détails : [Chemins localisés](/fr/guide/custom-locale-routes).

```ts
$setI18nRouteParams({
  en: { slug: 'my-post' },
  de: { slug: 'mein-beitrag' },
})
```

## Traductions à l’exécution {#runtime-translations}

### `$mergeTranslations` {#$mergetranslations}

```ts
(newTranslations: Translations) => void
```

Fusionne des traductions dans la locale active à l’exécution, en écrasant ce qui est chargé.

Fusion profonde dans le chunk de la page courante de la locale active ; les clés non mentionnées sont conservées.

```ts
$mergeTranslations({ banner: { title: 'Sale' } })
```

### `$setTranslation` {#$settranslation}

```ts
(key: string, value: unknown) => void
```

Remplace la valeur de `key` dans le dictionnaire actif. Il s’agit d’un remplacement, pas d’une fusion —
utilisez `$mergeTranslations` lorsque les clés voisines existantes doivent être conservées.

```ts
$setTranslation('banner', { title: 'Sale' }) // drops other keys under banner
$setTranslation('banner.title', 'Sale') // dotted path
```

### `$loadPageTranslations` {#$loadpagetranslations}

```ts
(locale: string, routeName: string, translations: Translations) => Promise<void>
```

Charge les traductions d’une page à l’exécution, pour un contenu dont les clés ne sont pas connues au build.

Fusionne dans le chunk `(locale, routeName)` en mémoire, et l’affichage se met à jour lorsque ce chunk est actif. Aucun payload n’est récupéré ici : pour une page pas encore chargée, les traductions attendent, et lorsque son fichier se charge, elles restent appliquées par-dessus.

```ts
await $loadPageTranslations('en', 'about', { title: 'About us' })
```

### `$resolveTranslations` {#$resolvetranslations}

```ts
() => Translations
```

Toutes les traductions actuellement en mémoire pour la locale et la route actives, sous forme d’arbre.
Vue en lecture seule de ce que `$t()` peut résoudre à cet instant.

Traitez le résultat en lecture seule.

### `$setMissingHandler` {#$setmissinghandler}

```ts
(handler: MissingHandler | null) => void
```

Installe un callback appelé pour chaque clé non résolue. Passez `null` pour le retirer.

Le handler s’exécute à la place de l’avertissement de développement.

```ts
$setMissingHandler((locale, key, routeName) => {
  console.error(`[i18n] missing ${key} in ${locale} (${routeName})`)
})
```

### `$clearCache` {#$clearcache}

```ts
() => void
```

Supprime tous les chunks de traduction en cache et recharge le dictionnaire de la page courante. La page
continue d’afficher ses traductions actuelles jusqu’à l’arrivée des nouvelles. Le HMR de développement l’appelle à
chaque modification d’un fichier de traduction.

```ts
const { clearCache } = useI18n()
clearCache()
```

Un rechargement en échec conserve le dictionnaire courant.
