# 🛠️ Méthodes

Cette page documente toutes les méthodes disponibles fournies par nuxt-i18n-micro. Les méthodes sont organisées par fonctionnalité pour faciliter la navigation.

## 🔍 Méthodes de traduction

Méthodes principales pour récupérer et gérer les traductions.

### `$t`

{/* generated:method:$t — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params?: Params, defaultValue?: string | null) => CleanTranslation
```

Traduit une clé, en y interpolant `params`. Renvoie `defaultValue` quand la clé est manquante, ou la clé elle-même quand aucune valeur par défaut n'est fournie.

{/* /generated:method:$t */}

```typescript
const welcomeMessage = $t('welcome', { username: 'Alice', unreadCount: 5 })
// Output: "Welcome, Alice! You have 5 unread messages."
```

<Warning>
`$t` renvoie `CleanTranslation`, qui est `string | number | boolean | Translations | PluralTranslations | null`. Si la clé pointe vers un **objet imbriqué** dans votre JSON (par exemple `$t('header')` quand le JSON contient `\{ "header": \{ "title": "Hi" \} \}`), la valeur de retour sera cet **objet**, pas une chaîne. L'utiliser directement dans un template Vue (<code v-pre>\{\{ $t('header') \}\}</code>) affichera `[object Object]`.

**Comment l'éviter :**

- Utilisez une clé plus spécifique : `$t('header.title')` → `"Hi"`
- Utilisez `$ts()` qui renvoie toujours une chaîne (appelle `.toString()` sur les non-chaînes)
- Utilisez `$t` avec une clé imbriquée pour accéder intentionnellement aux sous-objets à des fins programmatiques
</Warning>

### `$ts`

{/* generated:method:$ts — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params?: Params, defaultValue?: string) => string
```

Comme `$t`, mais renvoie toujours une chaîne : une valeur objet ou tableau est stringifiée plutôt que renvoyée telle quelle.

{/* /generated:method:$ts */}

```typescript
const welcomeMessage = $ts('welcome', { username: 'Alice', unreadCount: 5 })
// Output: "Welcome, Alice! You have 5 unread messages."
```

### `$_t` et `$_ts`

{/* generated:method:$_t — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNormalizedLoaded) => (key: string, params?: Params, defaultValue?: string | null) => CleanTranslation
```

Lie `$t` à une route spécifique, pour traduire en dehors de la page courante. Par exemple, un layout affichant un lien vers une autre route.

{/* /generated:method:$_t */}

{/* generated:method:$_ts — do not edit; run `pnpm run docs:generate` */}

```ts
(route: RouteLocationNormalizedLoaded) => (key: string, params?: Params, defaultValue?: string | null) => string
```

Lie `$ts` à une route spécifique. Voir `$_t`.

{/* /generated:method:$_ts */}

Variantes liées à une route de `$t` et `$ts`. Elles prennent d'abord une **route** et renvoient une fonction de traduction verrouillée sur la locale et le contexte de page de cette route.

- **Accès** : `useNuxtApp()` (également réexporté par `useI18n()` en tant que `$_t` / `$_ts`)

Utilisez-les lorsque la route active lors du SSR ou d'une transition diffère de `router.currentRoute`. Par exemple à l'intérieur de `<i18n-t>`, `<i18n-group>`, ou lors du rendu de contenu pour un objet `route` spécifique.

```typescript
import { useRoute, useNuxtApp } from '#imports'

const route = useRoute()
const { $_t, $_ts } = useNuxtApp()

const $t = $_t(route)
const title = $t('page.title')

// String-safe variant
const label = $_ts(route)('page.label')
```


### `$tc`

{/* generated:method:$tc — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, params: number | Params, defaultValue?: string) => string
```

Traduit avec pluralisation. `params` peut être le compte lui-même, ou un objet contenant `count`.

{/* /generated:method:$tc */}

**Format de traduction** : formes séparées par `|`. Placez des placeholders dans **chaque** forme :

```json
{
  "apples": "no apples | one apple | {count} apples",
  "cart": "no items for {name} | one item for {name} | {count} items for {name}"
}
```

```typescript
$tc('apples', 0) // "no apples"
$tc('apples', 1) // "one apple"
$tc('apples', 10) // "10 apples"

// count + other params (second argument must be an object)
$tc('cart', { count: 10, name: 'Alice' }) // "10 items for Alice"
```


**Alternative avec composant** — `<i18n-t keypath="cart" :plural="count" :params="\{ name \}" />` (fusionne `count` avec `params` en interne).


### `$mergeTranslations`

{/* generated:method:$mergeTranslations — do not edit; run `pnpm run docs:generate` */}

```ts
(newTranslations: Translations) => void
```

Fusionne des traductions dans la locale active à l'exécution, en surchargeant ce qui est chargé.

{/* /generated:method:$mergeTranslations */}

```typescript
$mergeTranslations({
  welcome: 'Bienvenue, {username}!',
})
// Output: Updates the translation cache with the new French translation
```

### `$resolveTranslations`

{/* generated:method:$resolveTranslations — do not edit; run `pnpm run docs:generate` */}

```ts
() => Translations
```

Toutes les traductions actuellement en mémoire pour la locale et la route actives, sous forme d'arbre.
Vue en lecture seule de ce que `$t()` peut résoudre pour le moment.

{/* /generated:method:$resolveTranslations */}

```typescript
const tree = $resolveTranslations()
// { aaa: { bbb: 'ccc' }, ddd: 1111 } — the same dictionary $t() reads from
```

Utilisez cette méthode lorsque vous avez besoin du dictionnaire complet en mémoire (DevTools, tests, éditeurs runtime). Traitez la valeur de retour comme lecture seule ; modifiez les valeurs via `$setTranslation` ou fusionnez des patches avec `$mergeTranslations`.

### `$setTranslation`

{/* generated:method:$setTranslation — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string, value: unknown) => void
```

Remplace la valeur à la clé `key` dans le dictionnaire actif. Il s'agit d'un remplacement, pas d'une fusion. Utilisez `$mergeTranslations` lorsque des frères et sœurs existants doivent survivre.

{/* /generated:method:$setTranslation */}

```typescript
$setTranslation('aaa', { fff: 'ggg' }) // replaces the whole `aaa` subtree
$setTranslation('aaa', 'text')          // replaces `aaa` with a string
$setTranslation('ddd', 1111)            // scalar at the top level
$setTranslation('aaa.bbb', 'nested')    // dotted path
```

Il s'agit d'un **remplacement**, pas d'une fusion. Les frères et sœurs existants sous la même clé sont supprimés. Pour patcher sans perdre les frères et sœurs, utilisez `$mergeTranslations`.

### `$setMissingHandler`

{/* generated:method:$setMissingHandler — do not edit; run `pnpm run docs:generate` */}

```ts
(handler: MissingHandler | null) => void
```

Installe un callback invoqué pour chaque clé non résolue. Passez `null` pour le retirer.

{/* /generated:method:$setMissingHandler */}

**Définition de type** :

```typescript
type MissingHandler = (locale: string, key: string, routeName: string, instance?: unknown, type?: string) => void
```

```typescript
// Set a custom handler
$setMissingHandler((locale, key, routeName) => {
  console.error(`Missing translation: ${key} in ${locale} for route ${routeName}`)
  // Send to Sentry or other error tracking service
  // Sentry.captureMessage(`Missing translation: ${key}`)
})

// Remove the handler
$setMissingHandler(null)
```

**Cas d'usage** :

- Enregistrer les traductions manquantes vers des services de suivi d'erreurs (Sentry, LogRocket, etc.)
- Collecter des statistiques sur les traductions manquantes
- Gestion d'erreurs personnalisée pour les clés de traduction manquantes

## 🔢 Formatage des nombres et des dates

Méthodes pour formater les nombres et les dates selon les conventions de la locale.

### `$tn`

{/* generated:method:$tn — do not edit; run `pnpm run docs:generate` */}

```ts
{ (value: number, options?: Intl.NumberFormatOptions): string (value: number, key: string, overrides?: Intl.NumberFormatOptions): string (value: number, key: string, locale: string, overrides?: Intl.NumberFormatOptions): string }
```

Formate un nombre avec `Intl.NumberFormat` dans la locale active. Une clé sélectionne un format nommé depuis la config.

{/* /generated:method:$tn */}

```typescript
// Inline options
const formattedNumber = $tn(1234567.89, { style: 'currency', currency: 'USD' })
// "$1,234,567.89"

// Named format (from nuxt.config i18n.numberFormats)
const price = $tn(1000, 'currency')
const priceDe = $tn(1000, 'currency', 'de')
const compact = $tn(1000, 'currency', { notation: 'compact' })
```

Les clés de formats nommés inconnues retombent sur les options par défaut de `Intl.NumberFormat`. En développement (client), un `console.warn` est émis lorsque `missingWarn` est activé (par défaut).

**Exemple de config** :

```ts
export default defineNuxtConfig({
  i18n: {
    numberFormats: {
      en: {
        currency: { style: 'currency', currency: 'USD' },
        decimal: { style: 'decimal', minimumFractionDigits: 2, maximumFractionDigits: 2 },
      },
      de: {
        currency: { style: 'currency', currency: 'EUR' },
      },
    },
  },
})
```

**Cas d'usage** :

- Formater des nombres comme devise, pourcentage ou décimal dans le format adapté à la locale
- Réutiliser des formats nommés dans toute l'application (parité de migration Vue I18n)

### `$td`

{/* generated:method:$td — do not edit; run `pnpm run docs:generate` */}

```ts
{ (value: Date | number | string, options?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, overrides?: Intl.DateTimeFormatOptions): string (value: Date | number | string, key: string, locale: string, overrides?: Intl.DateTimeFormatOptions): string }
```

Formate une date avec `Intl.DateTimeFormat` dans la locale active. Une clé sélectionne un format nommé depuis la config.

{/* /generated:method:$td */}

```typescript
const formattedDate = $td(new Date(), { weekday: 'long', year: 'numeric', month: 'long', day: 'numeric' })
// "Friday, September 1, 2023"

const short = $td(new Date(), 'short')
const longDe = $td(new Date(), 'long', 'de')
```

Les clés de formats nommés inconnues retombent sur les options par défaut de `Intl.DateTimeFormat`. En développement (client), un `console.warn` est émis lorsque `missingWarn` est activé (par défaut).

**Exemple de config** :

```ts
export default defineNuxtConfig({
  i18n: {
    datetimeFormats: {
      en: {
        short: { year: 'numeric', month: 'short', day: 'numeric' },
        long: { year: 'numeric', month: 'long', day: 'numeric', weekday: 'long' },
      },
    },
  },
})
```

**Cas d'usage** :

- Afficher des dates dans un format qui s'aligne sur la locale de l'utilisateur
- Partager des préréglages date/heure courts/longs à l'échelle de l'application

### `$tdr`

{/* generated:method:$tdr — do not edit; run `pnpm run docs:generate` */}

```ts
(value: Date | number | string, options?: Intl.RelativeTimeFormatOptions) => string
```

Formate une date en temps relatif (« il y a 3 jours ») avec `Intl.RelativeTimeFormat`.

{/* /generated:method:$tdr */}

```typescript
const relativeDate = $tdr(new Date(Date.now() - 1000 * 60 * 5))
// Output: "5 minutes ago" in the 'en-US' locale
```

### `$switchRoute`

{/* generated:method:$switchRoute — do not edit; run `pnpm run docs:generate` */}

```ts

```

Navigue vers une autre route, en conservant la locale active ou en basculant vers `toLocale`.

{/* /generated:method:$switchRoute */}

**Exemples** :

<CodeGroup>
```typescript String Path

```

```typescript String Path with Locale

```

```typescript Named Route

```

```typescript Named Route with Locale
// Switches to a named route and changes the locale to Spanish

```
</CodeGroup>

## 🚦 Configuration de route

Méthodes pour configurer le comportement et le contrôle d'accès des routes.

### `$defineI18nRoute`

{/* generated:method:$defineI18nRoute — do not edit; run `pnpm run docs:generate` */}

```ts
(routeDefinition: DefineI18nRouteConfig) => Promise<void>
```

Enregistre la configuration de locale et les traductions par page depuis l'intérieur d'un composant.
Fusionne dans la locale active et se réapplique lorsque la locale change.

{/* /generated:method:$defineI18nRoute */}

> [!IMPORTANT]
> `$defineI18nRoute` est fourni par le **plugin define** et n'est disponible que sur `useNuxtApp()`. Il **ne fait pas** partie de l'objet renvoyé par `useI18n()`.
> Déstructurez-le toujours depuis `useNuxtApp()` à l'intérieur de `script setup`. Appeler `$defineI18nRoute(...)` comme un global lève `"$defineI18nRoute is not defined"` lors du SSR/prerender.

**Paramètres** :

- **locales** : `string[] | Record<string, Record<string, string>>` — Locales disponibles pour la route
- **localeRoutes** : `Record<string, string>` — Optionnel. Routes personnalisées pour des locales spécifiques
- **disableMeta** : `boolean | string[]` — Optionnel. Désactive les balises meta i18n pour toutes ou pour certaines locales

**Exemple de base** :

```typescript
import { useNuxtApp } from '#imports'

const { $defineI18nRoute } = useNuxtApp()
```

### `$setI18nRouteParams`

{/* generated:method:$setI18nRouteParams — do not edit; run `pnpm run docs:generate` */}

```ts
(value: I18nRouteParams) => I18nRouteParams
```

Définit des paramètres par locale pour la route courante, afin qu'un segment dynamique puisse différer par langue.
Appelez-la pendant le SSR, avant que le head ne soit rendu.

{/* /generated:method:$setI18nRouteParams */}

```typescript
// in pages/news/[id].vue
// for en/news/1-first-article
const { $switchLocaleRoute, $setI18nRouteParams, $defineI18nRoute } = useNuxtApp()
$defineI18nRoute({
  localeRoutes: {
    en: '/news/:id()',
    fr: '/nouvelles/:id()',
    de: '/Nachricht/:id()',
  },
})
const { data: news } = await useAsyncData(`news-${params.id}`, async () => {
  let response = await $fetch("/api/getNews", {
    query: {
      id: params.id,
    },
  });
  if (response?.localeSlugs) {
    response.localeSlugs = {
      en: {
        id: '1-first-article'
      }
      fr: {
        id: '1-premier-article'
      }
      de: {
        id: '1-erster-Artikel'
      }
    }
    $setI18nRouteParams(response?.localeSlugs);
  }
  return response;
});
$switchLocalePath('fr') // === 'fr/nouvelles/1-premier-article'
$switchLocalePath('de') // === 'de/Nachricht/1-erster-Artikel'
```

## 🔧 Méthodes de cache et utilitaires

### `$has`

{/* generated:method:$has — do not edit; run `pnpm run docs:generate` */}

```ts
(key: string) => boolean
```

Indique si une clé se résout dans la locale active. Utilisez-la pour brancher sur du contenu optionnel plutôt que d'afficher une clé brute.

{/* /generated:method:$has */}

Lors des transitions de page dans la même locale, la v3 fusionne automatiquement en profondeur les traductions de la page quittée dans ce dictionnaire jusqu'à la fin de la transition. Les clés de la page précédente peuvent donc renvoyer `true` brièvement. Il n'y a pas d'option `previousPageFallback` ; ce comportement est intégré. Voir [FAQ — transitions de page](/guides/faq#-why-do-translations-break-during-page-transitions-especially-with-defineasynccomponent).

```typescript
if ($has('welcome')) {
  console.log($t('welcome'))
} else {
  console.log('Key not found')
}
```

### `$clearCache`

{/* generated:method:$clearCache — do not edit; run `pnpm run docs:generate` */}

```ts
() => void
```

Supprime tous les fragments en cache, côté client et dans le dictionnaire actif.

{/* /generated:method:$clearCache */}

**Accès** : `useNuxtApp().$clearCache`. Déclaré dans `NuxtAppOnlyInjections` plutôt que `PluginsInjections`, il est donc typé mais délibérément absent de l'objet d'aides `useI18n()` :

```typescript
const { $clearCache } = useNuxtApp()
// All cached translations are removed; next render will re-fetch them
$clearCache()
```

## 🧭 Composable `useI18nLocale`

Le composable centralisé pour la gestion de l'état de locale. Utilisez-le plutôt que de manipuler directement `useState('i18n-locale')` ou `useCookie('user-locale')`.

```typescript
const {
  setLocale, // (locale: string) => void — updates state + cookie
  getLocale, // () => string | null — from state or cookie
  getPreferredLocale, // () => string | null — validated against locales list
  getEffectiveLocale, // (route, getLocaleFromRoute) => string
  resolveInitialLocale, // (options) => string
  isValidLocale, // (locale) => boolean
  locale, // Ref<string | null> — reactive state
  localeCookie, // CookieRef — reactive cookie
  syncLocale, // (locale) => void — sync to cookie only
  validLocales, // string[] — list of valid locale codes
} = useI18nLocale()
```

### Méthodes clés

| Méthode                 | Description                                                 |
| ----------------------- | ----------------------------------------------------------- |
| `setLocale(locale)`     | Définit la locale atomiquement dans `useState` et le cookie |
| `getLocale()`           | Renvoie la locale courante depuis l'état ou le cookie       |
| `getPreferredLocale()`  | Renvoie la locale validée contre la liste `locales`, ou `null` |
| `isValidLocale(locale)` | Vérifie qu'un code de locale figure dans la liste `locales` configurée |

### Utilisation dans des plugins personnalisés

```typescript
// plugins/i18n-loader.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,
  setup() {
    const { setLocale } = useI18nLocale()
    // Detect locale from headers, domain, etc.
    setLocale('de')
  },
})
```

Voir [Détection de langue personnalisée](/guides/custom-language-detection) pour des exemples détaillés.
