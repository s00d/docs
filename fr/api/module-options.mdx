# Référence des options du module

Toutes les options acceptées par `nuxt-i18n-micro`, lues au moment du build depuis l'interface `ModuleOptions` dans [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).
Rien ici n'est écrit à la main, donc ce document ne peut pas prendre du retard sur le code — les types, valeurs par défaut et descriptions proviennent de la déclaration elle-même.

Pour ce que *signifient* ces options ensemble — quelles combinaisons ont un sens, ce qui change quand vous passez d'une stratégie à une autre, des exemples concrets — consultez [Configuration](/guides/configuration). Cette page est la liste exhaustive ; celle-là est l'explication.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Les options imbriquées apparaissent sous leur chemin pointé ; ainsi `translationPayloads.mode` est la clé `mode` à l'intérieur de l'objet `translationPayloads`.

## Locales et routage

Quelles langues existent et comment elles apparaissent dans l'URL.

| Option | Type | Valeur par défaut | Description |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Liste des locales prises en charge. Chaque entrée définit un code de locale ainsi que des métadonnées optionnelles (ISO, direction, nom d'affichage, etc.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Stratégie de routage d'URL pour les préfixes de locale. - `'no_prefix'` — pas de locale dans l'URL ; locale stockée dans un cookie. - `'prefix_except_default'` — préfixer toutes les locales sauf celle par défaut. - `'prefix'` — toujours préfixer, y compris la locale par défaut. - `'prefix_and_default'` — comme `prefix`, mais la locale par défaut est aussi accessible sans préfixe. |
| `defaultLocale` | `string` | `'en'` | Locale utilisée lorsqu'aucune locale ne peut être déterminée depuis l'URL ou les préférences utilisateur. Sert également de locale de repli pour les traductions manquantes lorsque `fallbackLocale` n'est pas défini. |
| `localeCookie` | `string \| null` | `null` | Nom du cookie servant à persister la préférence de locale de l'utilisateur entre les sessions. Mettez à `null` pour désactiver la persistance par cookie. Automatiquement défini à `'user-locale'` pour la stratégie `no_prefix` s'il n'est pas fourni. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Configuration globale de locale au niveau des routes. Permet de restreindre ou personnaliser les routes localisées pour des pages spécifiques sans modifier leurs composants. - `false` — exclure la route de la localisation. - `Record<LocaleCode, string>` — chemins personnalisés par locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (utilise un motif intégré basé sur les codes de locale)` | Expression régulière personnalisée (ou sa source sous forme de chaîne) pour reconnaître les codes de locale dans les segments d'URL. Tous les codes de locale définis dans `locales` doivent correspondre à ce motif, sinon un avertissement est émis. |
| `noPrefixRedirect` | `boolean` | `false` | Pour la stratégie `no_prefix` : active la redirection depuis une URL préfixée par une locale (par ex. `/en/about`) vers la version sans préfixe (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Motifs d'URL (chaînes ou RegExp) à exclure entièrement du traitement i18n. Les routes correspondantes n'obtiendront pas de préfixes de locale, de redirections ni de chargement de traductions. Les chemins internes de Nuxt (`/__nuxt_error`, etc.) sont toujours exclus automatiquement. |
| `routeLocales` | `Record<string, string[]>` | — | Restrictions de locales par route, extraites des appels à `defineI18nRoute()`. Associe un chemin de route (par ex. `'/about'`) à un tableau de codes de locale autorisés. Les routes non listées n'ont aucune restriction (toutes les locales sont autorisées). |

## Traductions

Où se trouvent les fichiers de traduction et comment les clés sont résolues.

| Option | Type | Valeur par défaut | Description |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Chemin vers le répertoire contenant les fichiers JSON de traduction, relatif à la racine du projet. |
| `disableWatcher` | `boolean` | `false` | Désactive le watcher qui crée automatiquement les fichiers de traduction manquants en mode développement. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Fait correspondre des noms de routes à d'autres noms de routes afin de partager les mêmes fichiers de traduction. Par exemple, `\{ 'about-us': 'about' \}` signifie que la page `about-us` utilisera les traductions de la page `about` plutôt que les siennes. |
| `plural` | `PluralFunc` | `pluralisation intégrée (index de forme selon le nombre)` | Fonction de pluralisation personnalisée. Reçoit `(key, count, params, locale, getter)` et doit renvoyer la forme plurielle sélectionnée sous forme de chaîne, ou `null`/`undefined` pour retomber sur la logique intégrée `defaultPlural` (ce qui vous permet de surcharger uniquement certaines locales). Pour le module Nuxt, la fonction est sérialisée avec `.toString()` dans `.nuxt/i18n.plural.mjs` — elle doit être autonome (pas d'imports / de portée externe). Une chaîne représentant un chemin de fichier n'est **pas** prise en charge. |
| `disablePageLocales` | `boolean` | `false` | Désactive les fichiers de traduction par page. Lorsque `true`, seules les traductions globales (`\{locale\}.json`) sont chargées ; les fichiers spécifiques aux pages (`pages/\{page\}/\{locale\}.json`) ne sont ni générés ni chargés. |
| `fallbackLocale` | `string` | `undefined (aucun repli ; retourne la clé brute)` | Code de locale de repli global. Lorsqu'une clé de traduction est absente dans la locale active, le module la recherche dans cette locale avant de renvoyer la clé elle-même. |

## Payloads et mise en cache

Comment les traductions atteignent le navigateur. [Performance](/guides/performance) explique ce que ces options changent à l'exécution.

| Option | Type | Valeur par défaut | Description |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Précharge les traductions de la page d'index dans le middleware global Nitro (côté serveur uniquement, configuration privée). |
| `apiBaseUrl` | `string` | `'_locales'` | Segment de chemin URL de base pour la route API des traductions (utilisé lors du fetch de données SSR/SSG). Peut aussi être défini via la variable d'environnement `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Remplace l'hôte utilisé pour les requêtes de fetch de traduction côté client. Utile quand le client atteint le serveur via un nom d'hôte différent de celui que voit Nuxt. Peut aussi être défini via la variable d'environnement `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Remplace l'hôte utilisé pour les requêtes de fetch de traduction côté serveur. Utile dans les configurations conteneur/microservice où le serveur se joint via un nom d'hôte interne. Peut aussi être défini via la variable d'environnement `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Contrôle la manière dont les payloads de traduction sont émis (Node : `public/<apiBaseUrl>` ; Edge : `serverAssets` de Nitro). - **Node** : `serverAssets` signifie SSR local via `readFile` sous `public/` (pas de Rollup `raw:`). - **Edge** : `serverAssets` enregistre les `serverAssets` de Nitro (`assets:i18n`) ; il ne force pas une copie publique. Conservez les valeurs par défaut pour la configuration tout-en-un habituelle. Pour les gros catalogues Edge, préférez `mode: 'source'`. Pour les déploiements adossés à un CDN, désactivez les sorties locales et définissez `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Stratégie de payload de traduction. - `premerged` : matrice `\{page\}/\{locale\}/data.json` construite au moment du build (par défaut) - `source` : fichiers source compacts fusionnés à l'exécution (préférable sur Edge / gros catalogues) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Payloads SSR locaux : Node lit `public/<apiBaseUrl>` (force une copie publique) ; Edge intègre via les `serverAssets` de Nitro. - **Node** : pas de `serverAssets` Nitro (évite Rollup `raw:`). Le SSR lit `public/<apiBaseUrl\|publicDir>` sous la forme `\{page\}/\{locale\}/data.json` ; lorsque ceci vaut `true`, une copie publique est forcée même si `publicAssets` est à false. - **Edge** (`nitro.node === false`) : `serverAssets` Nitro (`assets:i18n`) avec la même disposition que `mode`. Ne force **pas** une copie publique — définissez `publicAssets: true` pour un CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Enregistre la route serveur intégrée à `/\{apiBaseUrl\}/:page/:locale/data.json`. Désactivez-la lorsque les payloads de traduction sont servis depuis un hôte/CDN externe. |
| `translationPayloads.publicAssets` | `boolean` | `true en mode premerged, false en mode source` | Copie les payloads dans la sortie publique de Nitro. Premerged → `\{page\}/\{locale\}/data.json` sous `apiBaseUrl` ; source → arborescence compacte. Sur Node, cette arborescence est aussi la source SSR lorsque `serverAssets` force une copie publique. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Active la prérendu Nitro de `/\{apiBaseUrl\}/.../data.json`. Généralement redondant lorsque `publicAssets` en mode premerged a déjà écrit ces fichiers. |
| `translationPayloads.publicDir` | `string` | — | Dossier de sortie public relatif à la racine publique Nitro. Par défaut, `apiBaseUrl` (`_locales`). Ainsi, les fichiers statiques correspondent aux URLs de fetch client (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Avertit pendant le build lorsque le nombre de fichiers de payload générés dépasse ce seuil. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 Mo)` | Avertit pendant le build lorsque la taille totale des payloads générés dépasse ce seuil en octets. |

## SEO

Balises meta générées pour chaque page localisée.

| Option | Type | Valeur par défaut | Description |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Génère automatiquement les balises meta SEO (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | URL de base pour les balises meta SEO (canonical, og:url, hreflang). - Une chaîne d'URL concrète (par ex. `'https://example.com'`) — utilisée telle quelle (priorité maximale). - `undefined` — retombe sur `site.url` de `nuxt-site-config` si ce module est présent, sinon sur l'origine de la requête courante (`useRequestURL().origin` côté serveur, `window.location.origin` côté client). |
| `metaTrustForwardedHost` | `boolean` | `true` | Faire confiance à l'en-tête `X-Forwarded-Host` lors de la résolution de l'URL de base pour les balises meta. Activez lorsque l'application tourne derrière un reverse proxy (nginx, Cloudflare, AWS ALB, etc.) qui définit cet en-tête avec le nom d'hôte réel côté client. |
| `metaTrustForwardedProto` | `boolean` | `true` | Faire confiance à l'en-tête `X-Forwarded-Proto` lors de la résolution du protocole pour les balises meta. Activez lorsque l'application tourne derrière un proxy terminant TLS afin que les URLs canoniques utilisent `https://` même si l'application elle-même écoute en HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Liste des noms de paramètres de requête préservés dans les balises meta canonical et `og:url`. Les paramètres ne figurant pas dans cette liste sont retirés de l'URL canonique. |

## Détection et redirections

Choisir une locale pour un visiteur qui n'en a pas encore choisi une.

| Option | Type | Valeur par défaut | Description |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Active les redirections automatiques basées sur la locale. Lorsque `true`, les visiteurs sont redirigés vers leur locale préférée (détectée depuis le cookie, l'en-tête `Accept-Language` ou la valeur par défaut) lors de la première visite. |
| `autoDetectLanguage` | `boolean` | `true` | Détecte automatiquement la langue préférée de l'utilisateur depuis l'en-tête HTTP `Accept-Language`. Utilisé en combinaison avec `autoDetectPath` pour décider quand la détection a lieu. |
| `autoDetectPath` | `string` | `'/'` | Où les redirections basées sur cookie / Accept-Language peuvent s'exécuter (lorsque `redirects` est activé). - `'/'` — uniquement `/` (les liens profonds dans la locale par défaut restent accessibles ; défaut) - `'no_prefix'` — uniquement les chemins sans préfixe de locale - `'*'` — tous les chemins, y compris la réécriture d'un préfixe de locale explicite (par ex. `/fr/about` → `/de/about` lorsque le cookie préfère `de`) - toute autre chaîne — correspondance exacte du chemin (par ex. `'/welcome'`) Le nettoyage des stratégies préfixées (par ex. `/en` → `/` sous `prefix_except_default`) n'est pas conditionné. |

## Enregistrement

Parties du module que vous pouvez désactiver.

| Option | Type | Valeur par défaut | Description |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Enregistre le plugin de macro `defineI18nRoute()`, autorisant les appels `defineI18nRoute()` par page. |
| `plugin` | `boolean` | `true` | Enregistre le plugin i18n de base qui fournit `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` et d'autres helpers d'exécution. |
| `hooks` | `boolean` | `true` | Enregistre le plugin de hooks i18n qui fournit les hooks d'application `i18n:register` et `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`. |
| `components` | `boolean` | `true` | Enregistre les composants i18n intégrés (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Mettez à `false` pour désactiver l'enregistrement automatique des composants (par ex. si vous ne les utilisez pas et souhaitez réduire l'empreinte du module). |
| `types` | `boolean` | `true` | Génère les déclarations de types TypeScript pour `useI18n`, `$t` et les helpers associés à partir des clés de traduction de vos fichiers de locale par défaut. |
| `debug` | `boolean` | `false` | Active la journalisation verbeuse de débogage pour la détection de locale, la génération de routes et le chargement des traductions. |

## Autres

| `hreflangBaseLanguage` | `boolean` | `false` | Émet également un `hreflang` de langue nue dérivé de l'`iso` de chaque locale (par ex. `es-ES` → aussi `es`). La première locale régionale de `locales` s'approprie l'étiquette nue pour cette langue. Le `code` de routage n'est jamais utilisé — seulement `iso \|\| code`. |
| `vueDevtools` | `boolean` | `true` | Enregistre l'inspecteur et la timeline Vue DevTools en développement (extension navigateur). Distinct de l'onglet personnalisé Nuxt DevTools. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Préfixe préfixé aux noms de routes localisées (par ex. `'localized-index'`). Utilisé en interne pour distinguer les routes d'origine des variantes de locale générées. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Désactivation des balises meta par route, extraite des appels à `defineI18nRoute()`. Associe un chemin de route à `true` (désactive toutes les balises meta) ou à un tableau de codes de locale pour lesquels les balises meta doivent être désactivées. |
| `missingWarn` | `boolean` | `true` | Affiche des avertissements console lorsqu'une clé de traduction est manquante. |
| `hmr` | `boolean` | `true` | Active le Hot Module Replacement pour les fichiers de traduction en développement. Lorsque `true`, les modifications des fichiers JSON de traduction déclenchent un rechargement automatique sans rafraîchissement complet de la page. |
| `cacheMaxSize` | `number` | `0` | Nombre maximum d'entrées dans le cache de traduction en mémoire. `0` signifie aucune limite. |
| `cacheTtl` | `number` | `0` | Durée de vie (en secondes) des entrées du cache de traduction. `0` signifie que les entrées n'expirent jamais. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Formats de nombres nommés par locale (compatible Vue I18n). Permet des appels de style `$tn(1000, 'currency')`. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Formats date/heure nommés par locale (compatible `datetimeFormats` de Vue I18n). Permet des appels de style `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | `Cache-Control` HTTP max-age (en secondes) pour `/\{apiBaseUrl\}/:page/:locale/data.json`. S'applique en totalité uniquement tant que `dateBuild` casse l'URL (`?v=...`), ce qui est le comportement par défaut : la réponse est alors `public, max-age=…, immutable` et sûre pour les navigateurs et les CDN. - `dateBuild: 0`/`''` — l'URL est stable, donc cette durée n'est *pas* honorée ; la réponse devient `public, max-age=0, must-revalidate`. Un long `max-age` sur une URL qui ne change pas fige le premier payload que le navigateur a vu. - `0` — ne définit pas `Cache-Control` du tout (utile en débogage local) - Non appliqué en développement (`import.meta.dev`) afin que le HMR ne soit pas contrarié par le cache navigateur - Atteint uniquement les réponses servies par Nitro. Les payloads copiés dans `public/` et servis par la plateforme d'hébergement prennent les en-têtes de cette plateforme — voir le guide Performance. Analogue à l'option expérimentale `httpCacheDuration` de `@nuxtjs/i18n` (v10.2.0), mais sous forme d'en-tête de réponse explicite plutôt que via le `maxAge` de `defineCachedEventHandler` de Nitro. |
| `dateBuild` | `string \| number` | — | Valeur utilisée pour le cache-busting des requêtes de traduction (`?v=...`). Lorsqu'elle n'est pas fournie, le module retombe sur `Date.now()` (non déterministe). Pour des déploiements reproductibles/rolling, définissez ceci à une valeur stable (par ex. un SHA git ou un numéro de build). |
| `experimental` | `Record<string, unknown>` | — | Réceptacle pour les options expérimentales/instables. Leur contenu peut changer ou être supprimé sans préavis entre versions mineures. |
