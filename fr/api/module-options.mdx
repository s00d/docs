# Référence des options du module

Toutes les options que `nuxt-i18n-micro` accepte, lues au moment du build depuis l'interface `ModuleOptions` dans [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts). Rien ici n'est écrit à la main, donc cela ne peut pas se désynchroniser du code. Les types, valeurs par défaut et descriptions viennent directement de la déclaration.

Pour comprendre ce que ces options *signifient* ensemble — quelles combinaisons ont du sens, ce qui change lorsque vous changez de stratégie, des exemples travaillés — lisez [Configuration](/guides/configuration). Cette page est la liste exhaustive ; celle-là est l'explication.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'de', iso: 'de-DE', dir: 'ltr' },
    ],
    defaultLocale: 'en',
  },
})
```

Les options imbriquées apparaissent sous leur chemin pointé, donc `translationPayloads.mode` désigne la clé `mode` à l'intérieur de l'objet `translationPayloads`.

## Locales et routage

Quelles langues existent et comment elles apparaissent dans l'URL.

| Option | Type | Défaut | Description |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Liste des locales prises en charge. Chaque entrée définit un code de locale plus des métadonnées optionnelles (ISO, direction, nom d'affichage, etc.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Stratégie de routage URL pour les préfixes de locale. - `'no_prefix'` — pas de locale dans l'URL ; locale stockée dans un cookie. - `'prefix_except_default'` — préfixe toutes les locales sauf celle par défaut. - `'prefix'` — toujours préfixer, y compris la locale par défaut. - `'prefix_and_default'` — comme `prefix`, mais la locale par défaut est aussi accessible sans préfixe. |
| `defaultLocale` | `string` | `'en'` | Locale à utiliser lorsqu'aucune locale ne peut être déterminée depuis l'URL ou les préférences utilisateur. Sert également de locale de repli pour les traductions manquantes quand `fallbackLocale` n'est pas défini. |
| `localeCookie` | `string \| null` | `null` | Nom du cookie pour persister la préférence de locale de l'utilisateur entre les sessions. Mettez à `null` pour désactiver la persistance par cookie. Défini automatiquement à `'user-locale'` pour la stratégie `no_prefix` s'il n'est pas fourni. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `\{\}` | Configuration de locale au niveau route global. Permet de restreindre ou de personnaliser les routes de locale pour certaines pages sans modifier leurs composants. - `false` — exclure la route de la localisation. - `Record<LocaleCode, string>` — chemins personnalisés par locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Expression régulière personnalisée (ou son code source sous forme de chaîne) pour matcher les codes de locale dans les segments d'URL. Tous les codes de locale définis dans `locales` doivent correspondre à ce motif, sinon un avertissement est émis. |
| `noPrefixRedirect` | `boolean` | `false` | Pour la stratégie `no_prefix` : activer la redirection depuis une URL préfixée par locale (par exemple `/en/about`) vers la version sans préfixe (`/about`). |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Motifs d'URL (chaînes ou RegExp) à exclure totalement du traitement i18n. Les routes correspondantes n'auront pas de préfixe de locale, de redirection ni de chargement de traductions. Les chemins internes de Nuxt (`/__nuxt_error`, etc.) sont toujours exclus automatiquement. |
| `routeLocales` | `Record<string, string[]>` | — | Restrictions de locale par route, extraites des appels `defineI18nRoute()`. Associe un chemin de route (par exemple `'/about'`) à un tableau de codes de locale autorisés. Les routes non listées n'ont aucune restriction (toutes les locales autorisées). |

## Traductions

Où résident les fichiers de traduction et comment les clés sont résolues.

| Option | Type | Défaut | Description |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Chemin vers le répertoire contenant les fichiers JSON de traduction, relatif à la racine du projet. |
| `disableWatcher` | `boolean` | `false` | Désactive le watcher qui crée automatiquement les fichiers de traduction manquants en mode développement. |
| `routesLocaleLinks` | `\{ [key: string]: string \}` | `\{\}` | Associe des noms de route à d'autres noms de route pour partager les mêmes fichiers de traduction. Par exemple, `\{ 'about-us': 'about' \}` signifie que la page `about-us` utilisera les traductions de la page `about` au lieu des siennes. |
| `plural` | `PluralFunc` | `built-in pluralization (form index by count)` | Fonction de pluralisation personnalisée. Reçoit `(key, count, params, locale, getter)` et doit renvoyer la forme plurielle sélectionnée sous forme de chaîne, ou `null`/`undefined` pour retomber sur la logique `defaultPlural` intégrée (vous pouvez ainsi ne surcharger que certaines locales). Pour le module Nuxt, la fonction est sérialisée via `.toString()` dans `.nuxt/i18n.plural.mjs`. Elle doit être autonome (pas d'imports / de portée extérieure). Une chaîne de chemin de fichier n'est **pas** prise en charge. |
| `disablePageLocales` | `boolean` | `false` | Désactive les fichiers de traduction par page. Quand `true`, seules les traductions globales (`\{locale\}.json`) sont chargées ; les fichiers spécifiques à une page (`pages/\{page\}/\{locale\}.json`) ne sont ni générés ni chargés. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Code de locale de repli global. Quand une clé de traduction est manquante dans la locale active, le module la cherche dans cette locale avant de renvoyer la clé elle-même. |

## Payloads et cache

Comment les traductions parviennent au navigateur. [Performance](/guides/performance) explique ce que ces options changent à l'exécution.

| Option | Type | Défaut | Description |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Précharge les traductions de la page d'index dans le middleware global Nitro (serveur uniquement, config privée). |
| `apiBaseUrl` | `string` | `'_locales'` | Segment de chemin URL de base pour la route API des traductions (utilisée lors du fetch de données SSR/SSG). Peut également être défini via la variable d'environnement `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Surcharge l'hôte utilisé pour les requêtes de fetch de traductions côté client. Utile quand le client accède au serveur via un nom d'hôte différent de celui que Nuxt voit. Peut également être défini via la variable d'environnement `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Surcharge l'hôte utilisé pour les requêtes de fetch de traductions côté serveur. Utile dans les configurations conteneurs/microservices où le serveur s'atteint via un nom d'hôte interne. Peut également être défini via la variable d'environnement `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Contrôle la façon dont les payloads de traduction sont émis (Node : `public/<apiBaseUrl>` ; Edge : `serverAssets` de Nitro). - **Node** : `serverAssets` signifie SSR local via `readFile` sous `public/` (pas de `raw:` Rollup). - **Edge** : `serverAssets` enregistre les `serverAssets` de Nitro (`assets:i18n`) ; cela ne force pas une copie publique. Conservez les valeurs par défaut pour la configuration tout-en-un habituelle. Pour de gros catalogues Edge, préférez `mode: 'source'`. Pour les déploiements adossés à un CDN, désactivez les sorties locales et définissez `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Stratégie de payload de traduction. - `premerged` : matrice `\{page\}/\{locale\}/data.json` au moment du build (par défaut). - `source` : fichiers source compacts fusionnés à l'exécution (préféré sur Edge / gros catalogues). |
| `translationPayloads.serverAssets` | `boolean` | `true` | Payloads SSR locaux : Node lit `public/<apiBaseUrl>` (force la copie publique) ; Edge les intègre via `serverAssets` de Nitro. - **Node** : pas de `serverAssets` Nitro (évite `raw:` de Rollup). Le SSR lit   `public/<apiBaseUrl\|publicDir>` sous la forme `\{page\}/\{locale\}/data.json` ; quand cette option est `true`,   une copie publique est forcée même si `publicAssets` est à false. - **Edge** (`nitro.node === false`) : `serverAssets` de Nitro (`assets:i18n`) avec la même   disposition que `mode`. Ne force **pas** de copie publique — mettez `publicAssets: true` pour le CDN. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Enregistre la route serveur intégrée à `/\{apiBaseUrl\}/:page/:locale/data.json`. Désactivez ceci lorsque les payloads de traduction sont servis depuis un hôte externe / CDN. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Copie les payloads dans la sortie publique de Nitro. Premerged → `\{page\}/\{locale\}/data.json` sous `apiBaseUrl` ; source → arbre compact. Sur Node, cet arbre est également la source SSR lorsque `serverAssets` force une copie publique. |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Active le prerender Nitro de `/\{apiBaseUrl\}/.../data.json`. Généralement redondant lorsque `publicAssets` premerged a déjà écrit ces fichiers. |
| `translationPayloads.publicDir` | `string` | — | Dossier de sortie publique relatif à la racine publique de Nitro. Par défaut à `apiBaseUrl` (`_locales`). Ainsi les fichiers statiques correspondent aux URL de fetch client (`/\{apiBaseUrl\}/\{page\}/\{locale\}/data.json`). |
| `translationPayloads.warnFileCount` | `number` | `500` | Avertir pendant le build lorsque le nombre de fichiers de payload générés dépasse ce seuil. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Avertir pendant le build lorsque la taille totale des payloads générés dépasse ce seuil en octets. |

## SEO

Balises meta générées pour chaque page localisée.

| Option | Type | Défaut | Description |
| --- | --- | --- | --- |
| `meta` | `boolean` | `true` | Génère automatiquement les balises meta SEO (`hreflang`, `canonical`, `og:url`, `og:locale`). |
| `metaBaseUrl` | `string` | `undefined` | URL de base pour les balises meta SEO (canonical, og:url, hreflang). - Une chaîne d'URL concrète (par exemple `'https://example.com'`) — utilisée telle quelle (priorité maximale). - `undefined` — retombe sur `site.url` de `nuxt-site-config` quand ce module est   présent, sinon sur l'origine de la requête courante   (`useRequestURL().origin` côté serveur, `window.location.origin` côté client). |
| `metaTrustForwardedHost` | `boolean` | `true` | Faire confiance à l'en-tête `X-Forwarded-Host` lors de la résolution de l'URL de base pour les meta. Activez lorsque l'app tourne derrière un reverse proxy (nginx, Cloudflare, AWS ALB, etc.) qui définit cet en-tête avec le nom d'hôte réellement vu par le client. |
| `metaTrustForwardedProto` | `boolean` | `true` | Faire confiance à l'en-tête `X-Forwarded-Proto` lors de la résolution du protocole pour les meta. Activez lorsque l'app tourne derrière un proxy qui termine le TLS, afin que les URL canoniques utilisent `https://` même si l'app elle-même écoute en HTTP. |
| `canonicalQueryWhitelist` | `string[]` | `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']` | Liste des noms de paramètres de requête préservés dans les balises meta canonical et `og:url`. Les paramètres absents de cette liste sont retirés de l'URL canonique. |

## Détection et redirections

Choix d'une locale pour un visiteur qui n'en a pas encore choisi.

| Option | Type | Défaut | Description |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Active les redirections automatiques basées sur la locale. Quand `true`, les visiteurs sont redirigés vers leur locale préférée (détectée depuis le cookie, l'en-tête `Accept-Language` ou la valeur par défaut) lors de la première visite. |
| `autoDetectLanguage` | `boolean` | `true` | Détecte automatiquement la langue préférée de l'utilisateur depuis l'en-tête HTTP `Accept-Language`. Utilisé en combinaison avec `autoDetectPath` pour décider quand la détection intervient. |
| `autoDetectPath` | `string` | `'/'` | Où les redirections basées sur cookie / Accept-Language peuvent s'exécuter (quand `redirects` est activé). - `'/'` — uniquement `/` (les deep links dans la locale par défaut restent accessibles ; défaut). - `'no_prefix'` — uniquement les chemins sans préfixe de locale. - `'*'` — chaque chemin, y compris pour réécrire un préfixe de locale explicite   (par exemple `/fr/about` → `/de/about` quand le cookie préfère `de`). - toute autre chaîne — correspondance exacte de chemin (par exemple `'/welcome'`). Le nettoyage de la stratégie préfixée (par exemple `/en` → `/` sous `prefix_except_default`) n'est pas soumis à cette porte. |

## Enregistrement

Parties du module que vous pouvez désactiver.

| Option | Type | Défaut | Description |
| --- | --- | --- | --- |
| `define` | `boolean` | `true` | Enregistre le plugin macro `defineI18nRoute()`, activant les appels `defineI18nRoute()` par page. |
| `plugin` | `boolean` | `true` | Enregistre le plugin i18n principal qui fournit `$t()`, `$tc()`, `$getLocale()`, `$switchLocale()` et les autres aides runtime. |
| `hooks` | `boolean` | `true` | Enregistre le plugin i18n hooks qui fournit les hooks au niveau app `i18n:register` et `i18n:beforeLocaleSwitch` / `i18n:afterLocaleSwitch`. |
| `components` | `boolean` | `true` | Enregistre les composants i18n intégrés (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`). Passez à `false` pour désactiver l'enregistrement automatique des composants (par exemple si vous ne les utilisez pas et que vous voulez réduire l'empreinte du module). |
| `types` | `boolean` | `true` | Génère les déclarations de types TypeScript pour `useI18n`, `$t` et les aides associées, à partir des clés de traduction dans vos fichiers de locale par défaut. |
| `debug` | `boolean` | `false` | Active des logs de debug verbeux pour la détection de locale, la génération de routes et le chargement de traductions. |

## Autre

| Option | Type | Défaut | Description |
| --- | --- | --- | --- |
| `hreflangBaseLanguage` | `boolean` | `false` | Émet également un `hreflang` en langue nue dérivé du `iso` de chaque locale (par exemple `es-ES` → aussi `es`). La première locale régionale dans `locales` s'approprie la balise nue pour cette langue. Le `code` de routage n'est jamais utilisé — seulement `iso \|\| code`. |
| `vueDevtools` | `boolean` | `true` | Enregistre l'inspecteur Vue DevTools et la timeline en dev (extension navigateur). Distinct de l'onglet personnalisé Nuxt DevTools. |
| `localizedRouteNamePrefix` | `string` | `'localized-'` | Préfixe ajouté aux noms de routes localisées (par exemple `'localized-index'`). Utilisé en interne pour distinguer les routes d'origine des variantes générées par locale. |
| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Désactivation des balises meta par route, extraite des appels `defineI18nRoute()`. Associe un chemin de route à `true` (désactiver toutes les meta) ou à un tableau de codes de locale pour lesquels les meta doivent être désactivées. |
| `missingWarn` | `boolean` | `true` | Affiche des avertissements console lorsqu'une clé de traduction est manquante. |
| `hmr` | `boolean` | `true` | Active le Hot Module Replacement pour les fichiers de traduction en développement. Quand `true`, les modifications des fichiers JSON de traduction déclenchent un rechargement automatique sans recharger toute la page. |
| `cacheMaxSize` | `number` | `0` | Nombre maximum d'entrées dans le cache de traductions en mémoire. `0` signifie pas de limite. |
| `cacheTtl` | `number` | `0` | Durée de vie (en secondes) des entrées de cache de traductions. `0` signifie que les entrées n'expirent jamais. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Formats de nombres nommés par locale (compatibles Vue I18n). Permet des appels de style `$tn(1000, 'currency')`. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Formats date/heure nommés par locale (compatibles `datetimeFormats` de Vue I18n). Permet des appels de style `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | max-age HTTP `Cache-Control` (secondes) pour `/\{apiBaseUrl\}/:page/:locale/data.json`. S'applique pleinement uniquement tant que `dateBuild` casse l'URL (`?v=...`), ce qui est le défaut : la réponse est alors `public, max-age=…, immutable` et sûre pour les navigateurs et les CDN. - `dateBuild: 0`/`''` — l'URL est stable, donc cette durée n'est *pas* honorée ; la   réponse devient `public, max-age=0, must-revalidate`. Un long `max-age` sur une URL   immuable fige la première charge utile jamais vue par un navigateur. - `0` — ne pas définir `Cache-Control` du tout (utile en debug local). - Non appliqué en développement (`import.meta.dev`) pour que le HMR ne soit pas contré par le cache navigateur. - N'atteint que les réponses servies via Nitro. Les payloads copiés dans `public/` et servis   par la plateforme d'hébergement prennent les en-têtes de cette plateforme — voir le guide Performance. Analogue au `httpCacheDuration` expérimental de `@nuxtjs/i18n` (v10.2.0), mais sous forme d'en-tête de réponse explicite plutôt que via `maxAge` de `defineCachedEventHandler` de Nitro. |
| `dateBuild` | `string \| number` | — | Valeur utilisée pour le cache-busting des requêtes de traduction (`?v=...`). Quand non fournie, le module retombe sur `Date.now()` (non déterministe). Pour des déploiements reproductibles/progressifs, fixez cette valeur à une valeur stable (par exemple un SHA git ou un numéro de build). |
| `experimental` | `Record<string, unknown>` | — | Panier pour options expérimentales/instables. Le contenu peut changer ou être supprimé sans préavis entre versions mineures. |
