Cette page répertorie chaque clé de l'objet `i18n` dans `nuxt.config`. Utilisez les tableaux pour retrouver un type ou une valeur par défaut, et les détails ci-dessous pour les exemples et les mises en garde. Les types, valeurs par défaut et descriptions sont générés à partir de l'interface `ModuleOptions` dans [`packages/types/src/index.ts`](https://github.com/s00d/nuxt-i18n-micro/blob/main/packages/types/src/index.ts).

```ts nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', displayName: 'English' },
      { code: 'de', iso: 'de-DE', displayName: 'Deutsch' },
    ],
    defaultLocale: 'en',
  },
})
```

Une option imbriquée apparaît sous son chemin à points : `translationPayloads.mode` est la clé `mode` de `translationPayloads`.

## Locales et routage {#locales-and-routing}

Quelles langues existent et comment elles apparaissent dans l'URL.

| Option | Type | Défaut | Description |
| --- | --- | --- | --- |
| `locales` | `Locale[]` | `[]` | Liste des locales prises en charge. Chaque entrée définit un code de locale ainsi que des métadonnées facultatives (ISO, direction, nom affiché, etc.). |
| `strategy` | `Strategies` | `'prefix_except_default'` | Stratégie de routage des URL pour les préfixes de locale. - `'no_prefix'` — pas de locale dans l'URL ; la locale est stockée dans un cookie. - `'prefix_except_default'` — préfixe toutes les locales sauf celle par défaut. - `'prefix'` — préfixe toujours, y compris la locale par défaut. - `'prefix_and_default'` — comme `prefix`, mais la locale par défaut est aussi accessible sans préfixe. |
| `defaultLocale` | `string` | `'en'` | La locale utilisée lorsqu'aucune locale ne peut être déterminée à partir de l'URL ou des préférences de l'utilisateur. Ce n'est pas une locale de repli pour les traductions : définissez `fallbackLocale` pour cela. |
| `localeCookie` | `string \| null` | `null` | Nom du cookie qui conserve la préférence de locale de l'utilisateur d'une session à l'autre. Définissez `null` pour désactiver la persistance par cookie. Défini automatiquement à `'user-locale'` pour la stratégie `no_prefix` s'il n'est pas fourni ; un `null` explicite dans le bloc de configuration `i18n` le désactive également dans ce cas. |
| `globalLocaleRoutes` | `GlobalLocaleRoutes` | `{}` | Configuration globale des locales au niveau des routes. Permet de restreindre ou de personnaliser les routes localisées de certaines pages sans modifier leurs composants. - `false` — exclut la route de la localisation. - `Record<LocaleCode, string>` — chemins personnalisés par locale. |
| `customRegexMatcher` | `string \| RegExp` | `undefined (uses built-in pattern based on locale codes)` | Expression régulière personnalisée (ou sa source sous forme de chaîne) pour reconnaître les codes de locale dans les segments d'URL. Chaque code de locale de `locales` doit correspondre au motif entier, sans ses flags, sinon le build échoue. |
| `noPrefixRedirect` | `boolean` | `false` | Pour la stratégie `no_prefix` : lorsque la locale par défaut a un chemin personnalisé pour une page (`localeRoutes` / `globalLocaleRoutes`), redirige le chemin d'origine de la page vers le chemin personnalisé de la locale du visiteur, ou à défaut de la locale par défaut (par ex. `/about` → `/about-us`). Une locale sans chemin personnalisé propre reste sur le chemin d'origine. Les pages avec des segments dynamiques ne sont pas redirigées. |
| `excludePatterns` | `(string \| RegExp)[]` | `undefined` | Chemins à exclure du routage i18n : une chaîne est un préfixe de chemin (`/admin` couvre `/admin/x`) ou un glob `*` / `?` ; une RegExp est testée sur le chemin. Les pages correspondantes n'ont ni variantes de locale, ni redirection de locale ou 404, et sont retirées du prérendu ; elles sont toujours rendues avec les traductions. `/api`, `/_nuxt`, `/__*`, la route des traductions et les fichiers statiques courants (sitemap, robots.txt, favicon, assets selon leur extension) sont toujours exclus. |
| `routeLocales` | `Record<string, string[]>` | — | Restrictions de locales par route, extraites au build à partir des appels à `$defineI18nRoute()`. Associe un chemin de route (par ex. `'/about'`) à un tableau de codes de locale autorisés. Les routes non listées n'ont aucune restriction (toutes les locales sont autorisées). |

## Traductions {#translations}

Où se trouvent les fichiers de traduction et comment les clés sont résolues.

| Option | Type | Défaut | Description |
| --- | --- | --- | --- |
| `translationDir` | `string` | `'locales'` | Chemin du répertoire contenant les fichiers JSON de traduction, relatif à la racine du projet. |
| `disableWatcher` | `boolean` | `false` | Désactive le watcher de fichiers qui crée automatiquement les fichiers de traduction manquants en mode développement. |
| `routesLocaleLinks` | `{ [key: string]: string }` | `{}` | Associe des noms de route à d'autres noms de route pour partager les mêmes fichiers de traduction. Par exemple, `{ 'about-us': 'about' }` signifie que la page `about-us` utilisera les traductions de la page `about` au lieu des siennes. |
| `plural` | `PluralFunc` | ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)`` | Fonction de pluralisation personnalisée. Reçoit `(key, count, params, locale, getter)` et doit renvoyer la forme plurielle choisie sous forme de chaîne, ou `null`/`undefined` pour revenir à la logique intégrée `defaultPlural` (vous pouvez ainsi ne surcharger que certaines locales). Pour le module Nuxt, la fonction est sérialisée avec `.toString()` dans `.nuxt/i18n.plural.mjs` — elle doit être autonome (pas d'imports ni de portée externe). Une chaîne de chemin de fichier n'est **pas** prise en charge. |
| `disablePageLocales` | `boolean` | `false` | Désactive les fichiers de traduction par page. Lorsque `true`, seules les traductions globales (`{locale}.json`) sont chargées ; les fichiers propres aux pages (`pages/{page}/{locale}.json`) ne sont ni générés ni chargés. |
| `fallbackLocale` | `string` | `undefined (no fallback; returns the raw key)` | Code de la locale de repli globale. Les clés manquantes dans une locale sont prises dans cette locale (fusionnées dans chaque payload lors de sa génération ou de son chargement) ; sans elle, une clé manquante s'affiche telle quelle. |

## Payloads et mise en cache {#payloads-and-caching}

Comment les traductions parviennent au navigateur. [Performances](/fr/guide/performance) explique ce que ces options changent à l'exécution.

| Option | Type | Défaut | Description |
| --- | --- | --- | --- |
| `serverTranslationPreload` | `boolean` | `false` | Précharge les traductions de la page index dans le middleware global de Nitro (serveur uniquement, configuration privée). |
| `apiBaseUrl` | `string` | `'_locales'` | Segment de chemin de l'URL de base pour la route d'API des traductions (utilisé pour la récupération des données en SSR/SSG). Peut aussi être défini via la variable d'environnement `NUXT_I18N_APP_BASE_URL`. |
| `apiBaseClientHost` | `string` | `undefined` | Remplace l'hôte utilisé pour les requêtes de récupération des traductions côté client. Utile lorsque le client atteint le serveur via un nom d'hôte différent de celui que voit Nuxt. Peut aussi être défini via la variable d'environnement `NUXT_I18N_APP_BASE_CLIENT_HOST`. |
| `apiBaseServerHost` | `string` | `undefined` | Remplace l'hôte utilisé pour les requêtes de récupération des traductions côté serveur. Utile dans les configurations à base de conteneurs ou de microservices où le serveur s'atteint lui-même via un nom d'hôte interne. Peut aussi être défini via la variable d'environnement `NUXT_I18N_APP_BASE_SERVER_HOST`. |
| `translationPayloads` | `TranslationPayloadOptions` | — | Contrôle la façon dont les payloads de traduction sont émis (serveur Node : `public/<apiBaseUrl>` ; Edge / fonction / inline : `serverAssets` Nitro). - **Serveur Node** (`node-server`, `node-cluster`, `serveStatic` sur disque) : `serverAssets` signifie un SSR local via `readFile` sous `public/` (pas de `raw:` Rollup). - **Edge, presets de fonctions et `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …) : `serverAssets` enregistre des `serverAssets` Nitro (`assets:i18n`),   car `public/` n'est pas disponible sur disque pour le SSR. Ne force pas de copie publique — définissez `publicAssets: true` pour un CDN ou un hébergement statique. Conservez les valeurs par défaut pour la configuration tout-en-un habituelle. Pour les gros catalogues sur Edge, privilégiez `mode: 'source'`. Pour les déploiements adossés à un CDN, désactivez les sorties locales et définissez `apiBaseClientHost` / `apiBaseServerHost`. |
| `translationPayloads.mode` | `'premerged' \| 'source'` | `'premerged'` | Stratégie des payloads de traduction. - `premerged` : matrice `{page}/{locale}/data.json` générée au build (par défaut) - `source` : fichiers sources compacts fusionnés à l'exécution (à privilégier sur Edge / avec de gros catalogues) |
| `translationPayloads.serverAssets` | `boolean` | `true` | Payloads SSR locaux : un serveur Node qui sert `public/` depuis le disque lit cette arborescence (force la copie publique) ; Edge, les presets de fonctions et `serveStatic: "inline"` embarquent via les `serverAssets` Nitro. - **Serveur Node** (le preset sert lui-même `public/`, par ex. `node-server`) : pas de `serverAssets` Nitro (évite le `raw:` Rollup). Le SSR lit   `public/<apiBaseUrl\|publicDir>` sous la forme `{page}/{locale}/data.json` ; lorsque cette option vaut `true`,   une copie publique est forcée même si `publicAssets` vaut false. - **Edge, presets de fonctions et inline** (`nitro.node === false`, pas de `serveStatic` sur disque, comme `vercel` /   `netlify` / `aws-lambda`, ou `serveStatic: "inline"`, par ex. winterjs) : `serverAssets` Nitro (`assets:i18n`)   avec la même structure que `mode`. Ne force **pas** de copie publique — définissez `publicAssets: true` pour un CDN ou un hébergement statique. |
| `translationPayloads.serverHandler` | `boolean` | `true` | Enregistre la route serveur intégrée `/{apiBaseUrl}/:page/:locale/data.json`. Désactivez-la lorsque les payloads de traduction sont servis depuis un hôte externe ou un CDN. |
| `translationPayloads.publicAssets` | `boolean` | `true in premerged mode, false in source mode` | Copie les payloads dans la sortie publique de Nitro. Premerged → `{page}/{locale}/data.json` sous `apiBaseUrl` ; source → arborescence compacte. Lorsque le SSR lit `public/` (`node-server` et similaires), `serverAssets: true` force également cette copie. Sur les presets Edge / fonction / `serveStatic: "inline"`, la copie n'a lieu que si cette option vaut `true` (le SSR utilise l'embarquement Nitro). |
| `translationPayloads.prerenderRoutes` | `boolean` | `false` | Active le prérendu par Nitro de `/{apiBaseUrl}/.../data.json`. Généralement redondant lorsque `publicAssets` en mode premerged a déjà écrit ces fichiers. |
| `translationPayloads.publicDir` | `string` | — | Dossier de sortie publique relatif à la racine publique de Nitro. Vaut par défaut `apiBaseUrl` (`_locales`). Ainsi, les fichiers statiques correspondent aux URL récupérées par le client (`/{apiBaseUrl}/{page}/{locale}/data.json`). |
| `translationPayloads.rootDelta` | `boolean` | `true` | Écrit un fichier racine par locale et, dans chaque fichier de page, uniquement ce qui en diffère. Le client et le SSR les fusionnent ; un chunk complet fonctionne toujours partout où un fichier est lu. `false` conserve un dictionnaire complet dans chaque fichier de page. Uniquement en mode `premerged`, et désactivé avec `disablePageLocales`. |
| `translationPayloads.warnFileCount` | `number` | `500` | Émet un avertissement pendant le build lorsque le nombre de fichiers de payload générés dépasse ce seuil. |
| `translationPayloads.warnSizeBytes` | `number` | `10485760 (10 MB)` | Émet un avertissement pendant le build lorsque la taille totale des payloads générés dépasse ce seuil en octets. |

| `metaBaseUrl` | `string` | `undefined` | URL de base des balises meta SEO (canonical, og:url, hreflang). - Une URL concrète (par ex. `'https://example.com'`) — utilisée telle quelle (priorité la plus haute). - `undefined` — se rabat sur `site.url` de `nuxt-site-config` lorsque ce module est   présent, sinon sur l'origine de la requête courante   (`useRequestURL().origin` côté serveur, `window.location.origin` côté client). |

À activer lorsque l'application tourne derrière un proxy qui termine le TLS, afin que les URL canoniques utilisent `https://` même si l'application elle-même écoute en HTTP. |

## Détection et redirections {#detection-and-redirects}

Choisir une locale pour un visiteur qui n'en a pas sélectionné.

| Option | Type | Défaut | Description |
| --- | --- | --- | --- |
| `redirects` | `boolean` | `true` | Active les redirections automatiques de locale (plugin serveur et middleware de route client). Lorsque `true`, les stratégies avec préfixe redirigent une URL sans préfixe vers sa forme localisée. La locale provient de l'état de l'application, du cookie ou de `Accept-Language` là où `autoDetectPath` le permet, sinon de la locale par défaut. Avec `no_prefix`, la détection ne modifie jamais l'URL (voir `noPrefixRedirect` pour les chemins personnalisés). |
| `autoDetectLanguage` | `boolean` | `true` | Détecte automatiquement la langue préférée de l'utilisateur à partir de l'en-tête HTTP `Accept-Language`. Utilisé conjointement avec `autoDetectPath` pour décider quand la détection a lieu. |
| `autoDetectPath` | `string` | `'/'` | Où les redirections selon la préférence du cookie / de Accept-Language peuvent s'exécuter (lorsque `redirects` est activé). - `'/'` — uniquement `/` (les liens profonds dans la locale par défaut restent accessibles ; par défaut) - `'no_prefix'` — uniquement les chemins sans préfixe de locale - `'*'` — tous les chemins, y compris en réécrivant un préfixe de locale explicite   (par ex. `/fr/about` → `/de/about` lorsque le cookie préfère `de`) - toute autre chaîne — ce chemin, sans tenir compte des barres obliques finales (par ex. `'/welcome'`) Avec `prefix`, une URL sans préfixe en dehors des chemins autorisés redirige toujours vers la forme de la locale par défaut (`/about` → `/en/about`). La locale par défaut avec un préfixe sous `prefix_except_default` (`/en`) donne une 404, pas une redirection. |

| `routeDisableMeta` | `Record<string, boolean \| string[]>` | — | Désactivation des balises meta par route. Les entrées trouvées au build dans les appels à `$defineI18nRoute()` y sont ajoutées. |
| `missingWarn` | `boolean` | `true` | Affiche des avertissements dans la console lorsqu'une clé de traduction est manquante (build de développement, dans le navigateur). |
| `hmr` | `boolean` | `true` | Active le Hot Module Replacement pour les fichiers de traduction en développement. Lorsque `true`, les modifications des fichiers de traduction JSON déclenchent un rechargement automatique sans rafraîchissement complet de la page. |
| `cacheMaxSize` | `number` | `0` | Nombre maximal d'entrées dans les caches de traduction en mémoire. Les caches de récupération et serveur suppriment l'entrée la moins récemment utilisée ; la table des dictionnaires du navigateur supprime la plus ancienne (FIFO). `0` signifie aucune limite dans le navigateur ; les caches serveur conservent alors au plus 1000 entrées, afin que des URL de requête désignant des pages inventées ne puissent pas faire croître la mémoire du serveur. |
| `cacheTtl` | `number` | `0` | Durée de vie (en secondes) des caches de traduction de récupération et serveur, comptée à partir du stockage d'une entrée (les lectures ne la prolongent pas), afin que les données provenant de `apiBaseServerHost` soient rafraîchies au moins à cette fréquence. Les dictionnaires actifs du navigateur n'expirent pas avec elle. `0` signifie que les entrées n'expirent jamais. |
| `cacheStorage` | `string` | — | Nom d'un montage de stockage Nitro (`nitro.storage`, par ex. `'redis'`) que plusieurs instances serveur partagent comme cache de dictionnaires, lu après le cache du processus et avant la source. Rentable surtout avec `apiBaseServerHost` : une seule récupération depuis le backend au lieu d'une par instance. Les entrées sont indexées par build et expirent après `cacheTtl`, ou au bout d'un jour lorsqu'il vaut `0`. Désactivé en dev et lors du prérendu. Un stockage défaillant se rabat sur la source. Non défini : pas de cache partagé. |
| `numberFormats` | `Record<string, Record<string, Intl.NumberFormatOptions>>` | — | Formats de nombres nommés par locale (compatibles avec Vue I18n). Permet des appels du type `$tn(1000, 'currency')`. |
| `timeZone` | `string` | `the runtime's zone` | Fuseau horaire IANA pour `$td` et `<i18n-t date>` (`Europe/Berlin`). Définissez-le pour afficher la même date sur le serveur et dans tous les navigateurs ; le `timeZone` propre à un format nommé est prioritaire. |
| `datetimeFormats` | `Record<string, Record<string, Intl.DateTimeFormatOptions>>` | — | Formats de date et d'heure nommés par locale (`datetimeFormats` compatibles avec Vue I18n). Permet des appels du type `$td(date, 'short')`. |
| `httpCacheDuration` | `number` | `31536000` | max-age HTTP `Cache-Control` (en secondes) pour `/{apiBaseUrl}/:page/:locale/data.json`. S'applique pleinement uniquement tant que `dateBuild` rend l'URL unique (`?v=...`), ce qui est le cas par défaut : la réponse est alors `private, max-age=…, immutable` : un navigateur la fige, ce que ne peut pas faire un CDN qui ignore la query (`public` avec `httpCacheControl: false`). - `dateBuild: 0`/`''` — l'URL est stable, donc cette durée n'est *pas* respectée ; la   réponse devient `public, max-age=0, must-revalidate` à la place. Un long `max-age` sur une   URL qui ne change pas fige le premier payload qu'un navigateur ait jamais vu. - `0` — ne définit pas du tout `Cache-Control` (utile pour le débogage local) - Non appliqué en développement (`import.meta.dev`) afin que le cache du navigateur ne contrarie pas le HMR - Ne concerne que les réponses servies par Nitro. Les payloads copiés dans `public/` et servis   par la plateforme d'hébergement reçoivent les en-têtes de cette plateforme — voir le guide Performances. Analogue à `httpCacheDuration` expérimental de `@nuxtjs/i18n` (v10.2.0), mais sous la forme d'un en-tête de réponse explicite plutôt que du maxAge de `defineCachedEventHandler` de Nitro. |
| `httpCacheControl` | `string \| false` | `'public, max-age=60'` | `Cache-Control` d'un fichier de payload servi par un hôte ou par une règle s'appliquant à tout un chemin, qui ne peut pas voir `?v=`. Sur un serveur Node, une réponse au `?v=` courant est figée pendant `httpCacheDuration` et toute autre est revalidée ; avec `source`, `cacheTtl` ou `apiBaseServerHost`, où un dictionnaire change sans build, chaque réponse reçoit cet en-tête. `false` maintient chaque fichier en `max-age=0, must-revalidate`. |
| `dateBuild` | `string \| number` | — | Valeur utilisée pour le cache-busting des requêtes de traduction (`?v=...`). Si elle n'est pas fournie, le module utilise un hash des fichiers de traduction, de sorte que la valeur ne change que lorsque les traductions changent (`Date.now()` lorsqu'aucun hash ne peut être calculé). `0` ou `''` désactive le cache-busting. Définissez une valeur stable (un SHA git, un numéro de build) pour la figer vous-même. `NUXT_I18N_DATE_BUILD` ou `runtimeConfig.public.i18nRuntime.dateBuild` la remplace à l'exécution, après le remplacement d'un dictionnaire sur place : les URL figées sont laissées de côté, sans rebuild. |
| `experimental` | `Record<string, unknown>` | — | Espace réservé aux options expérimentales/instables. Son contenu peut changer ou être supprimé sans préavis entre deux versions mineures. |

## Détails des options {#option-details}

Les options pour lesquelles il n'y a rien à ajouter au tableau ne sont pas répétées ici.

### Locales et URL {#locales-and-urls}

#### `locales` {#locales}

**Type** `Locale[]` · **Défaut** `[]`

Liste des locales prises en charge.
Chaque entrée définit un code de locale ainsi que des métadonnées facultatives (ISO, direction, nom affiché, etc.).

Chaque entrée est un objet `Locale` :

| Propriété | Type | Description |
| --- | --- | --- |
| `code` | `string` | **Obligatoire.** Segment d'URL et nom de fichier (`en`, `de-at`). |
| `iso` | `string` | Balise BCP-47 pour `<html lang>`, `hreflang`, les pluriels et `$tn` / `$td` / `$tdr` (`en-US`). |
| `displayName` | `string` | Libellé dans `<i18n-switcher>` et `$getLocaleName()`. |
| `dir` | `'ltr' \| 'rtl' \| 'auto'` | `<html dir>`. Sans elle, les langues RTL connues reçoivent `rtl` et toutes les autres locales n'ont pas d'attribut. Voir [SEO](/fr/guide/seo#text-direction). |
| `disabled` | `boolean` | Exclue des routes, des payloads et du changement de locale. Son préfixe donne une 404, et les liens vers elle restent sur la page. |
| `fallbackLocale` | `string` | Locale de repli pour cette locale ; remplace le `fallbackLocale` global. |
| `seo` | `boolean` | `false` exclut la locale de `hreflang` et de `og:locale:alternate`. |
| `og` | `string` | Valeur de `og:locale` (`ar_AE`) ; par défaut : `iso` converti. |
| `baseUrl` | `string` | Le domaine propre de la locale : un seul build le sert, et les liens vers lui depuis d'autres domaines sont absolus. |
| `baseDefault` | `boolean` | Avec `baseUrl` : la locale par défaut de son hôte, sans préfixe `/<code>` dans les liens vers elle (`prefix` le conserve). |

Les autres propriétés sont conservées et renvoyées par `$getLocales()`. Typez-les en augmentant `Locale` :

```ts
// i18n.d.ts
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
  }
}
export {}
```

Le module hisse `@i18n-micro/types`, donc cela fonctionne avec pnpm sans installer le package.

#### `defaultLocale` {#defaultlocale}

**Type** `string` · **Défaut** `'en'`

La locale utilisée lorsqu'aucune locale ne peut être déterminée à partir de l'URL ou des préférences de l'utilisateur.
Ce n'est pas une locale de repli pour les traductions : définissez `fallbackLocale` pour cela.

#### `strategy` {#strategy}

**Type** `Strategies` · **Défaut** `'prefix_except_default'`

Stratégie de routage des URL pour les préfixes de locale.

- `'no_prefix'` — pas de locale dans l'URL ; la locale est stockée dans un cookie.
- `'prefix_except_default'` — préfixe toutes les locales sauf celle par défaut.
- `'prefix'` — préfixe toujours, y compris la locale par défaut.
- `'prefix_and_default'` — comme `prefix`, mais la locale par défaut est aussi accessible sans préfixe.

URL par stratégie et redirections : [Stratégies de routage](/fr/guide/strategy).

#### `globalLocaleRoutes` {#globallocaleroutes}

**Type** `GlobalLocaleRoutes` · **Défaut** `{}`

Configuration globale des locales au niveau des routes.
Permet de restreindre ou de personnaliser les routes localisées de certaines pages sans
modifier leurs composants.

- `false` — exclut la route de la localisation.
- `Record<LocaleCode, string>` — chemins personnalisés par locale.

Les clés sont des noms ou des chemins de route. Généralement défini page par page avec [`$defineI18nRoute`](/fr/guide/per-component-translations).

```ts
globalLocaleRoutes: {
  about: { en: '/about-us', de: '/ueber-uns' },
  'admin-dashboard': false, // not localized
}
```

Détails, segments dynamiques et routes `pages:extend` : [Chemins localisés](/fr/guide/custom-locale-routes).

#### `routeLocales` {#routelocales}

**Type** `Record<string, string[]>` · **Défaut** —

Restrictions de locales par route, extraites au build à partir des appels à `$defineI18nRoute()`.
Associe un chemin de route (par ex. `'/about'`) à un tableau de codes de locale autorisés.
Les routes non listées n'ont aucune restriction (toutes les locales sont autorisées).

#### `routeDisableMeta` {#routedisablemeta}

**Type** `Record<string, boolean \| string[]>` · **Défaut** —

Désactivation des balises meta par route. Associe un nom ou un chemin de route à `true` (désactive toutes les meta) ou à un tableau
de codes de locale pour lesquels les meta doivent être désactivées. Les entrées trouvées au build dans les appels à `$defineI18nRoute()`
y sont ajoutées.

#### `customRegexMatcher` {#customregexmatcher}

**Type** `string \| RegExp` · **Défaut** `undefined (uses built-in pattern based on locale codes)`

Expression régulière personnalisée (ou sa source sous forme de chaîne) pour reconnaître les codes de locale dans les segments d'URL.
Chaque code de locale de `locales` doit correspondre au motif entier, sans ses flags, sinon le build échoue.

```ts
customRegexMatcher: '[a-z]{2}-[a-z]{2}', // en-us, de-at
```

#### `excludePatterns` {#excludepatterns}

**Type** `(string \| RegExp)[]` · **Défaut** `undefined`

Chemins à exclure du routage i18n : une chaîne est un préfixe de chemin (`/admin` couvre `/admin/x`)
ou un glob `*` / `?` ; une RegExp est testée sur le chemin. Les pages correspondantes n'ont ni variantes
de locale, ni redirection de locale ou 404, et sont retirées du prérendu ; elles sont toujours rendues avec
les traductions. `/api`, `/_nuxt`, `/__*`, la route des traductions et les fichiers statiques courants
(sitemap, robots.txt, favicon, assets selon leur extension) sont toujours exclus.

```ts
excludePatterns: ['/admin', '/docs/*', /^\/preview\//],
```

En savoir plus : [Exclure des chemins](/fr/guide/excluding-static-files).

#### `localizedRouteNamePrefix` {#localizedroutenameprefix}

**Type** `string` · **Défaut** `'localized-'`

Préfixe ajouté aux noms de routes localisées (par ex. `'localized-index'`).
Utilisé en interne pour distinguer les routes d'origine des variantes de locale générées.

#### `trailingSlash` {#trailingslash}

**Type** `'append' \| 'remove'` · **Défaut** `undefined (inherit from Nuxt)`

Barre oblique finale pour `$localePath` / `$switchLocalePath` (parité avec NuxtLink).
Vaut par défaut `experimental.defaults.nuxtLink.trailingSlash` lorsqu'elle n'est pas définie.
Définissez-la explicitement pour remplacer le comportement par défaut des liens Nuxt dans les helpers de chemins i18n.

### Traductions {#translations}

#### `translationDir` {#translationdir}

**Type** `string` · **Défaut** `'locales'`

Chemin du répertoire contenant les fichiers JSON de traduction, relatif à la racine du projet.

Relatif à la racine de chaque layer, et non à `app/` (`'app/locales'` pour une structure Nuxt 4). Organisation des fichiers : [Fichiers de traduction](/fr/guide/translations).

#### `additionalTranslationDirs` {#additionaltranslationdirs}

**Type** `string[]` · **Défaut** `[]`

Répertoires supplémentaires (relatifs à la racine du projet / à la racine de chaque layer Nuxt) dont les fichiers
`{locale}.json` de premier niveau sont fusionnés en profondeur dans le dictionnaire global avant `translationDir`.

Ordre de fusion : chaque entrée dans l'ordre du tableau (à travers les layers), puis `translationDir` (prioritaire en cas de conflit).
Seuls les fichiers racine `{locale}.json` sont lus — `pages/` sous ces répertoires est ignoré.

Exemple : `translationDir: 'frontend'`, `additionalTranslationDirs: ['common']` → `common/en.json` puis `frontend/en.json`.

#### `disablePageLocales` {#disablepagelocales}

**Type** `boolean` · **Défaut** `false`

Désactive les fichiers de traduction par page.
Lorsque `true`, seules les traductions globales (`{locale}.json`) sont chargées ;
les fichiers propres aux pages (`pages/{page}/{locale}.json`) ne sont ni générés ni chargés.

#### `fallbackLocale` {#fallbacklocale}

**Type** `string` · **Défaut** `undefined (no fallback; returns the raw key)`

Code de la locale de repli globale.
Les clés manquantes dans une locale sont prises dans cette locale (fusionnées dans chaque payload lors de sa
génération ou de son chargement) ; sans elle, une clé manquante s'affiche telle quelle.

#### `routesLocaleLinks` {#routeslocalelinks}

**Type** `{ [key: string]: string }` · **Défaut** `{}`

Associe des noms de route à d'autres noms de route pour partager les mêmes fichiers de traduction.
Par exemple, `{ 'about-us': 'about' }` signifie que la page `about-us` utilisera
les traductions de la page `about` au lieu des siennes.

```ts
routesLocaleLinks: { 'products-id': 'products' },
```

#### `plural` {#plural}

**Type** `PluralFunc` · **Défaut** ``built-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories)``

Fonction de pluralisation personnalisée.
Reçoit `(key, count, params, locale, getter)` et doit renvoyer la forme plurielle
choisie sous forme de chaîne, ou `null`/`undefined` pour revenir à la logique intégrée
`defaultPlural` (vous pouvez ainsi ne surcharger que certaines locales).

Pour le module Nuxt, la fonction est sérialisée avec `.toString()` dans
`.nuxt/i18n.plural.mjs` — elle doit être autonome (pas d'imports ni de portée externe).
Une chaîne de chemin de fichier n'est **pas** prise en charge.

La règle intégrée et son marqueur `=0 ` sont décrits à [`$tc`](/fr/api/methods#$tc). Votre fonction la remplace pour ce à quoi elle répond, reçoit la valeur brute avec l'éventuel marqueur en place, et `null` lui rend la main. La fonction reçoit `(key, count, params, locale, getter)` ; `getter(key)` renvoie la chaîne brute avec toutes les formes. Écrivez-la sous la forme d'une expression `function` ou fléchée autonome (pas de syntaxe abrégée de méthode, pas d'imports, pas de variables externes) :

```ts
plural: function (key, count, params, locale, getter) {
  if (!locale.startsWith('en')) return null // built-in rule for other locales
  const forms = String(getter(key) ?? '').split('|').map((form) => form.trim())
  const index = count === 0 ? 0 : count === 1 ? 1 : 2
  return (forms[Math.min(index, forms.length - 1)] ?? '').replace('{count}', String(count))
},
```

```json
{ "apples": "no apples | one apple | {count} apples" }
```

#### `numberFormats` {#numberformats}

**Type** `Record<string, Record<string, Intl.NumberFormatOptions>>` · **Défaut** —

Formats de nombres nommés par locale (compatibles avec Vue I18n).
Permet des appels du type `$tn(1000, 'currency')`.

Utilisé par [`$tn`](/fr/api/methods#$tn).

#### `datetimeFormats` {#datetimeformats}

**Type** `Record<string, Record<string, Intl.DateTimeFormatOptions>>` · **Défaut** —

Formats de date et d'heure nommés par locale (`datetimeFormats` compatibles avec Vue I18n).
Permet des appels du type `$td(date, 'short')`.

Utilisé par [`$td`](/fr/api/methods#$td).

#### `timeZone` {#timezone}

**Type** `string` · **Défaut** `the runtime's zone`

Fuseau horaire IANA pour `$td` et `<i18n-t date>` (`Europe/Berlin`). Définissez-le pour afficher la même date sur
le serveur et dans tous les navigateurs ; le `timeZone` propre à un format nommé est prioritaire.

#### `disableWatcher` {#disablewatcher}

**Type** `boolean` · **Défaut** `false`

Désactive le watcher de fichiers qui crée automatiquement les fichiers de traduction manquants en mode développement.

#### `missingWarn` {#missingwarn}

**Type** `boolean` · **Défaut** `true`

Affiche des avertissements dans la console lorsqu'une clé de traduction est manquante (build de développement, dans le navigateur).

Pour signaler les clés manquantes à la place, utilisez [`$setMissingHandler`](/fr/api/methods#$setmissinghandler).

### Payloads et mise en cache {#payloads-and-caching}

#### `translationPayloads` {#translationpayloads}

**Type** `TranslationPayloadOptions` · **Défaut** —

Contrôle la façon dont les payloads de traduction sont émis (serveur Node : `public/<apiBaseUrl>` ; Edge / fonction / inline : `serverAssets` Nitro).

- **Serveur Node** (`node-server`, `node-cluster`, `serveStatic` sur disque) : `serverAssets` signifie un SSR local via `readFile` sous `public/` (pas de `raw:` Rollup).
- **Edge, presets de fonctions et `serveStatic: "inline"`** (`vercel`, `netlify`, `aws-lambda`, winterjs, …) : `serverAssets` enregistre des `serverAssets` Nitro (`assets:i18n`),
  car `public/` n'est pas disponible sur disque pour le SSR. Ne force pas de copie publique — définissez `publicAssets: true` pour un CDN ou un hébergement statique.

Conservez les valeurs par défaut pour la configuration tout-en-un habituelle. Pour les gros catalogues sur Edge, privilégiez `mode: 'source'`.
Pour les déploiements adossés à un CDN, désactivez les sorties locales et définissez `apiBaseClientHost` / `apiBaseServerHost`.

Les sous-options figurent dans le tableau [Payloads et mise en cache](#payloads-and-caching). Quelle combinaison convient à Node, au serverless, à Edge, à l'hébergement statique ou à un CDN : [Déploiement](/fr/guide/deployment).

#### `apiBaseUrl` {#apibaseurl}

**Type** `string` · **Défaut** `'_locales'`

Segment de chemin de l'URL de base pour la route d'API des traductions (utilisé pour la récupération des données en SSR/SSG).
Peut aussi être défini via la variable d'environnement `NUXT_I18N_APP_BASE_URL`.

Les URL des payloads sont de la forme `/{apiBaseUrl}/{page}/{locale}/data.json`.

#### `apiBaseClientHost` {#apibaseclienthost}

**Type** `string` · **Défaut** `undefined`

Remplace l'hôte utilisé pour les requêtes de récupération des traductions côté client.
Utile lorsque le client atteint le serveur via un nom d'hôte différent de celui que voit Nuxt.
Peut aussi être défini via la variable d'environnement `NUXT_I18N_APP_BASE_CLIENT_HOST`.

#### `apiBaseServerHost` {#apibaseserverhost}

**Type** `string` · **Défaut** `undefined`

Remplace l'hôte utilisé pour les requêtes de récupération des traductions côté serveur.
Utile dans les configurations à base de conteneurs ou de microservices où le serveur s'atteint lui-même via un nom d'hôte interne.
Peut aussi être défini via la variable d'environnement `NUXT_I18N_APP_BASE_SERVER_HOST`.

Un hôte doit servir les mêmes réponses `/{apiBaseUrl}/{page}/{locale}/data.json` que la route intégrée.

#### `dateBuild` {#datebuild}

**Type** `string \| number` · **Défaut** —

Valeur utilisée pour le cache-busting des requêtes de traduction (`?v=...`).

Si elle n'est pas fournie, le module utilise un hash des fichiers de traduction, de sorte que la valeur ne change
que lorsque les traductions changent (`Date.now()` lorsqu'aucun hash ne peut être calculé). `0` ou `''` désactive
le cache-busting. Définissez une valeur stable (un SHA git, un numéro de build) pour la figer vous-même.
`NUXT_I18N_DATE_BUILD` ou `runtimeConfig.public.i18nRuntime.dateBuild` la remplace à l'exécution, après le remplacement
d'un dictionnaire sur place : les URL figées sont laissées de côté, sans rebuild.

#### `httpCacheDuration` {#httpcacheduration}

**Type** `number` · **Défaut** `31536000`

max-age HTTP `Cache-Control` (en secondes) pour `/{apiBaseUrl}/:page/:locale/data.json`.

S'applique pleinement uniquement tant que `dateBuild` rend l'URL unique (`?v=...`), ce qui est le cas par défaut :
la réponse est alors `private, max-age=…, immutable` : un navigateur la fige, ce que ne peut pas faire un CDN qui ignore la query
(`public` avec `httpCacheControl: false`).

- `dateBuild: 0`/`''` — l'URL est stable, donc cette durée n'est *pas* respectée ; la
  réponse devient `public, max-age=0, must-revalidate` à la place. Un long `max-age` sur une
  URL qui ne change pas fige le premier payload qu'un navigateur ait jamais vu.

- `0` — ne définit pas du tout `Cache-Control` (utile pour le débogage local)
- Non appliqué en développement (`import.meta.dev`) afin que le cache du navigateur ne contrarie pas le HMR
- Ne concerne que les réponses servies par Nitro. Les payloads copiés dans `public/` et servis
  par la plateforme d'hébergement reçoivent les en-têtes de cette plateforme — voir le guide Performances.

Analogue à `httpCacheDuration` expérimental de `@nuxtjs/i18n` (v10.2.0), mais sous la forme d'un
en-tête de réponse explicite plutôt que du maxAge de `defineCachedEventHandler` de Nitro.

#### `cacheMaxSize` {#cachemaxsize}

**Type** `number` · **Défaut** `0`

Nombre maximal d'entrées dans les caches de traduction en mémoire. Les caches de récupération et serveur
suppriment l'entrée la moins récemment utilisée ; la table des dictionnaires du navigateur supprime la plus ancienne (FIFO).
`0` signifie aucune limite dans le navigateur ; les caches serveur conservent alors au plus 1000 entrées, afin que des URL
de requête désignant des pages inventées ne puissent pas faire croître la mémoire du serveur.

#### `cacheTtl` {#cachettl}

**Type** `number` · **Défaut** `0`

Durée de vie (en secondes) des caches de traduction de récupération et serveur, comptée à partir du stockage d'une
entrée (les lectures ne la prolongent pas), afin que les données provenant de `apiBaseServerHost` soient rafraîchies au
moins à cette fréquence. Les dictionnaires actifs du navigateur n'expirent pas avec elle. `0` signifie que les entrées
n'expirent jamais.

Ce que ces deux options changent à l'exécution : [Performances](/fr/guide/performance).

#### `serverTranslationPreload` {#servertranslationpreload}

**Type** `boolean` · **Défaut** `false`

Précharge les traductions de la page index dans le middleware global de Nitro (serveur uniquement, configuration privée).

### SEO {#seo}

#### `meta` {#meta}

**Type** `boolean` · **Défaut** `true`

Génère automatiquement les balises meta SEO (`hreflang`, `canonical`, `og:url`, `og:locale`).

Surcharges par page : [`useI18nHead`](/fr/composables/useI18nHead). Tout le reste : [SEO](/fr/guide/seo).

#### `metaBaseUrl` {#metabaseurl}

**Type** `string` · **Défaut** `undefined`

URL de base des balises meta SEO (canonical, og:url, hreflang).

- Une URL concrète (par ex. `'https://example.com'`) — utilisée telle quelle (priorité la plus haute).
- `undefined` — se rabat sur `site.url` de `nuxt-site-config` lorsque ce module est
  présent, sinon sur l'origine de la requête courante
  (`useRequestURL().origin` côté serveur, `window.location.origin` côté client).

#### `metaTrustForwardedHost` {#metatrustforwardedhost}

**Type** `boolean` · **Défaut** `true`

Fait confiance à l'en-tête `X-Forwarded-Host` pour déterminer l'URL de base des balises meta.
À activer lorsque l'application tourne derrière un reverse proxy (nginx, Cloudflare, AWS ALB, etc.)
qui définit cet en-tête avec le vrai nom d'hôte vu par le client.

Lu uniquement lorsque ni `metaBaseUrl` ni `site.url` ne sont définis. Définissez-le à `false` lorsque l'application est accessible sans proxy qui écrase l'en-tête : un client pourrait sinon choisir l'hôte de vos URL canoniques.

#### `metaTrustForwardedProto` {#metatrustforwardedproto}

**Type** `boolean` · **Défaut** `true`

Fait confiance à l'en-tête `X-Forwarded-Proto` pour déterminer le protocole des balises meta.
À activer lorsque l'application tourne derrière un proxy qui termine le TLS, afin que
les URL canoniques utilisent `https://` même si l'application elle-même écoute en HTTP.

Même portée que `metaTrustForwardedHost`.

#### `trustForwardedHost` {#trustforwardedhost}

**Type** `boolean` · **Défaut** `false`

Choisit le domaine d'une requête (`locales[].baseUrl`) à partir de `X-Forwarded-Host` au lieu de
`Host`. À activer uniquement derrière un proxy qui écrase cet en-tête.

Distinct de `metaTrustForwardedHost` et désactivé par défaut : ici, l'en-tête sélectionnerait les locales d'un autre domaine, et pas seulement l'origine d'une balise. Voir [Layers et domaines](/fr/guide/layers#multiple-domains).

#### `hreflangBaseLanguage` {#hreflangbaselanguage}

**Type** `boolean` · **Défaut** `false`

Émet aussi un `hreflang` de langue seule dérivé de l'`iso` de chaque locale
(par ex. `es-ES` → aussi `es`). La première locale régionale de `locales` s'attribue
la balise de langue seule pour cette langue. Le `code` de routage n'est jamais utilisé — uniquement `iso || code`.

#### `canonicalQueryWhitelist` {#canonicalquerywhitelist}

**Type** `string[]` · **Défaut** `['page', 'sort', 'filter', 'search', 'q', 'query', 'tag']`

Liste des noms de paramètres de requête conservés dans les balises meta canonical et `og:url`.
Les paramètres absents de cette liste sont retirés de l'URL canonique.

### Détection et redirections {#detection-and-redirects}

Les règles que ces options alimentent : [Détection de la locale](/fr/guide/locale-detection).

#### `redirects` {#redirects}

**Type** `boolean` · **Défaut** `true`

Active les redirections automatiques de locale (plugin serveur et middleware de route client).
Lorsque `true`, les stratégies avec préfixe redirigent une URL sans préfixe vers sa forme localisée. La locale
provient de l'état de l'application, du cookie ou de `Accept-Language` là où `autoDetectPath` le permet, sinon
de la locale par défaut. Avec `no_prefix`, la détection ne modifie jamais l'URL (voir `noPrefixRedirect` pour les chemins personnalisés).

Avec `false`, le middleware de redirection client n'est pas enregistré. Le plugin serveur renvoie toujours une 404 pour les URL de locale invalides et écrit le cookie pour une URL préfixée.

#### `autoDetectLanguage` {#autodetectlanguage}

**Type** `boolean` · **Défaut** `true`

Détecte automatiquement la langue préférée de l'utilisateur à partir de l'en-tête HTTP `Accept-Language`.
Utilisé conjointement avec `autoDetectPath` pour décider quand la détection a lieu.

#### `autoDetectPath` {#autodetectpath}

**Type** `string` · **Défaut** `'/'`

Où les redirections selon la préférence du cookie / de Accept-Language peuvent s'exécuter (lorsque `redirects` est activé).

- `'/'` — uniquement `/` (les liens profonds dans la locale par défaut restent accessibles ; par défaut)
- `'no_prefix'` — uniquement les chemins sans préfixe de locale
- `'*'` — tous les chemins, y compris en réécrivant un préfixe de locale explicite
  (par ex. `/fr/about` → `/de/about` lorsque le cookie préfère `de`)

- toute autre chaîne — ce chemin, sans tenir compte des barres obliques finales (par ex. `'/welcome'`)

Avec `prefix`, une URL sans préfixe en dehors des chemins autorisés redirige toujours vers la forme de la
locale par défaut (`/about` → `/en/about`). La locale par défaut avec un préfixe sous
`prefix_except_default` (`/en`) donne une 404, pas une redirection.

#### `localeCookie` {#localecookie}

**Type** `string \| null` · **Défaut** `null`

Nom du cookie qui conserve la préférence de locale de l'utilisateur d'une session à l'autre.
Définissez `null` pour désactiver la persistance par cookie.
Défini automatiquement à `'user-locale'` pour la stratégie `no_prefix` s'il n'est pas fourni ; un
`null` explicite dans le bloc de configuration `i18n` le désactive également dans ce cas.

Sans cookie, `Accept-Language` pilote toujours les redirections ; le cookie mémorise un choix d'une visite à l'autre.

#### `noPrefixRedirect` {#noprefixredirect}

**Type** `boolean` · **Défaut** `false`

Pour la stratégie `no_prefix` : lorsque la locale par défaut a un chemin personnalisé pour une page
(`localeRoutes` / `globalLocaleRoutes`), redirige le chemin d'origine de la page vers le chemin
personnalisé de la locale du visiteur, ou à défaut de la locale par défaut (par ex. `/about` → `/about-us`).
Une locale sans chemin personnalisé propre reste sur le chemin d'origine. Les pages avec des segments
dynamiques ne sont pas redirigées.

### Enregistrement et développement {#registration-and-development}

#### `plugin` {#plugin}

**Type** `boolean` · **Défaut** `true`

Enregistre le plugin i18n principal qui fournit `$t()`, `$tc()`, `$getLocale()`,
`$switchLocale()` et les autres helpers d'exécution.

#### `define` {#define}

**Type** `boolean` · **Défaut** `true`

Fournit `$defineI18nRoute()` à l'exécution. Le build lit les appels à `$defineI18nRoute()` dans les pages
dans tous les cas.

#### `hooks` {#hooks}

**Type** `boolean` · **Défaut** `true`

Appelle le hook d'application `i18n:register` au chargement et à la navigation pour que les plugins puissent ajouter des traductions.

Voir [Hooks](/fr/api/events).

#### `components` {#components}

**Type** `boolean` · **Défaut** `true`

Enregistre les composants i18n intégrés (`<i18n-link>`, `<i18n-switcher>`, `<i18n-t>`, `<i18n-group>`).
Définissez `false` pour désactiver l'enregistrement automatique des composants (par ex. si vous ne les utilisez pas
et souhaitez réduire l'empreinte du module).

#### `types` {#types}

**Type** `boolean` · **Défaut** `true`

Génère les déclarations de types TypeScript pour `useI18n`, `$t` et les helpers associés
à partir des clés de traduction des fichiers de votre locale par défaut.

Distinct du package [`@i18n-micro/types-generator`](/fr/integrations/types-generator).

#### `hmr` {#hmr}

**Type** `boolean` · **Défaut** `true`

Active le Hot Module Replacement pour les fichiers de traduction en développement.
Lorsque `true`, les modifications des fichiers de traduction JSON déclenchent un rechargement automatique
sans rafraîchissement complet de la page.

#### `debug` {#debug}

**Type** `boolean` · **Défaut** `false`

Active une journalisation de débogage détaillée pour la détection de locale, la génération des routes et le chargement des traductions.

#### `vueDevtools` {#vuedevtools}

**Type** `boolean` · **Défaut** `true`

Enregistre l'inspecteur et la timeline Vue DevTools en dev (extension de navigateur).
Distinct de l'onglet personnalisé de Nuxt DevTools.

#### `experimental` {#experimental}

**Type** `Record<string, unknown>` · **Défaut** —

Espace réservé aux options expérimentales/instables.
Son contenu peut changer ou être supprimé sans préavis entre deux versions mineures.
