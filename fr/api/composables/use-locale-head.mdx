# 🌍 Composable `useLocaleHead`

Le composable `useLocaleHead` est un utilitaire de `Nuxt I18n Micro` qui vous aide à gérer les attributs SEO et les balises meta HTML pour les routes localisées. Il génère dynamiquement les attributs `lang` et `dir` du document HTML et crée les balises `meta` et `link` afin d'améliorer le SEO de votre contenu localisé.

## ⚙️ Options

Les balises head SEO pour la route courante : les alternates `hreflang` pour chaque locale plus `x-default`, un lien canonical, `og:locale` et `lang`/`dir` sur `<html>`.

À utiliser uniquement lorsque `meta` est désactivé ou que les valeurs par défaut doivent être ajustées. Avec `meta: true`, le module enregistre lui-même les mêmes balises.

## 🛠️ Valeurs de retour

Le composable `useLocaleHead` renvoie un objet réactif et une fonction de mise à jour que vous devez appeler lorsque les données sources changent. Les deux formes sont dans la signature ci-dessus, générées à partir du code source.

### `metaObject`

Charge utile head réactive (attrs html, meta, link) adaptée à `useHead(metaObject)`.

- **Exemple** :
  ```js
  const { metaObject } = useLocaleHead()
  useHead(metaObject)
  ```

### `updateMeta`

Recalcule `metaObject` à partir de la route courante, de la locale et de la configuration. Appelez-la lorsque les entrées changent, par exemple lors d'un changement de route.

- **Exemple** :
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  useHead(metaObject)
  watch(
    () => route.fullPath,
    () => updateMeta(),
    { immediate: true },
  )
  ```

### Accès à `link` et `meta`

Les tableaux `link` et `meta` sont accessibles via `metaObject.value` :

- **Exemple** :
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  updateMeta()
  console.log(metaObject.value.link)
  // Output: [{ id: 'i18n-can', rel: 'canonical', href: 'https://example.com/about' }, ...]
  console.log(metaObject.value.meta)
  // Output: [{ id: 'i18n-og', property: 'og:locale', content: 'en_US' }, ...]
  ```

## 🛠️ Exemples d'utilisation

### Utilisation de base

Générez des attributs head spécifiques à la locale avec les options par défaut.

```js
const head = useLocaleHead()
```

### Personnaliser l'attribut identifiant

Utilisez un attribut identifiant personnalisé pour les balises générées.

```js
const head = useLocaleHead({ identifierAttribute: 'data-i18n' })
```

### Désactiver les attributs SEO

Générez des attributs head sans ajouter les balises meta et link liées au SEO.

```js
const head = useLocaleHead({ addSeoAttributes: false })
```

### Spécifier une URL de base

Définissez une URL de base personnalisée pour les URL canoniques et alternates.

```js
const head = useLocaleHead({ baseUrl: 'https://mywebsite.com' })
```

## 🚀 Fonctionnalités supplémentaires

### Balises meta et link SEO

Quand `addSeoAttributes` est activé, le composable génère automatiquement les balises suivantes :

- `og:locale` pour la locale courante (`language_TERRITORY`, avec un tiret bas). Dérivé de `locale.og` ou converti depuis `locale.iso` lorsque possible.
- `og:url` pour l'URL canonique de la page.
- `og:locale:alternate` pour les versions en langues alternatives.
- Liens `rel="canonical"` et `rel="alternate"` pour l'optimisation SEO.
- Lien `hreflang="x-default"` pointant vers l'URL de la locale par défaut. Cela indique aux moteurs de recherche quelle URL présenter aux utilisateurs dont la langue ne correspond à aucune des locales définies.

### Locale et direction dynamiques

Le composable détermine dynamiquement les attributs `lang` et `dir` en fonction de la locale de la route courante, garantissant que votre document HTML est correctement configuré pour les utilisateurs internationaux.

### Gestion des routes localisées

Si vos routes sont préfixées par des codes de locale (par exemple, `/en/about`), le composable ajuste intelligemment le chemin complet pour générer les URL, ce qui garantit que les attributs SEO sont exacts et pertinents.

Ce composable simplifie l'optimisation de votre application Nuxt pour un public international, en veillant à ce que votre site soit bien préparé pour les moteurs de recherche et les utilisateurs du monde entier.

## 🛠️ Exemple d'utilisation

L'exemple suivant montre comment utiliser le composable `useLocaleHead` dans un composant Vue avec les paramètres par défaut :

```vue
<script setup>
import { useRoute, watch } from '#imports'
const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({
  addDirAttribute: true,
  identifierAttribute: 'id',
  addSeoAttributes: true,
})
useHead(metaObject)
watch(
  () => route.fullPath,
  () => updateMeta(),
  { immediate: true },
)
</script>
```

### Explication du code

- **Composable `useLocaleHead`** : ce composable est appelé dans la section `<script setup>` et renvoie un objet contenant `htmlAttrs`, `meta` et `link`.

- **Balise `<html>`** : les attributs `lang` et `dir` du document HTML sont déterminés dynamiquement en fonction de la locale courante et appliqués à la balise `<html>`.

- **Section `<head>`** :
  - **Balises meta** : des balises meta liées au SEO sont générées, notamment `og:locale`, `og:url`, ainsi que les balises `rel="canonical"` et `rel="alternate"` pour spécifier les versions en langues alternatives de la page.
  - **Balises link** : les liens canoniques, les liens vers les versions en langues alternatives et le lien `hreflang="x-default"` (pointant vers l'URL de la locale par défaut) sont inclus.

- **Section `<body>`** : le contenu principal de la page est affiché ici. Dans cet exemple, un simple titre et un paragraphe sont utilisés.

### 📝 Notes

1. **Attributs** : les attributs utilisés (`lang`, `dir`, `rel`, `href`, `hreflang`, `property`, `content`) sont extraits de l'objet renvoyé par `useLocaleHead`.

2. **Génération des balises SEO** : si l'option `addSeoAttributes` vaut `true`, le composable génère automatiquement les balises SEO pour la locale courante.

3. **URL de base** : vous pouvez définir votre URL de base personnalisée via l'option `baseUrl` pour générer correctement les liens canoniques et alternates.

Cet exemple montre à quel point il est simple d'intégrer `useLocaleHead` dans les composants de votre application afin d'assurer des attributs SEO corrects et d'améliorer l'indexation par les moteurs de recherche des pages localisées.

## 🧩 Personnalisation et cycle de vie

- `useLocaleHead` ne s'abonne pas lui-même aux changements. Il renvoie `metaObject` et `updateMeta`.
- Vous devez appeler `updateMeta()` lorsque les entrées changent (typiquement lors d'un changement de route), par exemple depuis un plugin :

```ts
// plugins/02.meta.ts
export default defineNuxtPlugin(() => {
  const route = useRoute()
  const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
  useHead(metaObject)
  if (import.meta.server) updateMeta()
  else
    watch(
      () => route.fullPath,
      () => updateMeta(),
      { immediate: true },
    )
})
```

## Quand utiliser plutôt `useI18nHead`

Quand `meta: true` (par défaut), préférez [`useI18nHead`](/api/composables/use-i18n-head) pour les surcharges **page par page** (hreflang personnalisé, `og:title` supplémentaire, désactivation partielle). Utilisez `useLocaleHead` directement uniquement lorsque `meta: false` ou que vous gérez `useHead` vous-même.
