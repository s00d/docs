# 🌍 Composable `useLocaleHead`

Le composable `useLocaleHead` est un utilitaire de `Nuxt I18n Micro` qui vous aide à gérer les attributs SEO et les balises meta HTML pour les routes localisées. Il génère dynamiquement des attributs pour `lang` et `dir` du document HTML et crée les balises `meta` et `link` pour améliorer le SEO de votre contenu localisé.

## ⚙️ Options

Les balises head SEO pour la route actuelle : alternatives `hreflang` pour chaque locale plus `x-default`, un lien canonical, `og:locale` et `lang`/`dir` sur `<html>`.

Nécessaire uniquement lorsque `meta` est désactivé ou que les valeurs par défaut doivent être ajustées — avec `meta: true`, le module enregistre lui-même les mêmes balises.

## 🛠️ Valeurs de retour

Le composable `useLocaleHead` renvoie un objet réactif et une fonction de mise à jour que vous devriez appeler lorsque les données sources changent. Les deux formes figurent dans la signature ci-dessus, générée à partir des sources.

### `metaObject`

Payload head réactif (attrs html, meta, link) adapté à `useHead(metaObject)`.

- **Exemple** :
  ```js
  const { metaObject } = useLocaleHead()
  useHead(metaObject)
  ```

### `updateMeta`

Recalcule `metaObject` en fonction de la route, de la locale et de la configuration actuelles. Appelez-la lorsque les entrées changent — lors d'un changement de route, par exemple.

- **Exemple** :
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  useHead(metaObject)
  watch(
    () => route.fullPath,
    () => updateMeta(),
    { immediate: true },
  )
  ```

### Accéder à `link` et `meta`

Les tableaux `link` et `meta` sont accessibles via `metaObject.value` :

- **Exemple** :
  ```js
  const { metaObject, updateMeta } = useLocaleHead()
  updateMeta()
  console.log(metaObject.value.link)
  // Output: [{ id: 'i18n-can', rel: 'canonical', href: 'https://example.com/about' }, ...]
  console.log(metaObject.value.meta)
  // Output: [{ id: 'i18n-og', property: 'og:locale', content: 'en_US' }, ...]
  ```

## 🛠️ Exemples d'utilisation

### Utilisation de base

Générer des attributs head spécifiques à la locale avec les options par défaut.

```js
const head = useLocaleHead()
```

### Personnaliser l'attribut identifiant

Utiliser un attribut identifiant personnalisé pour les balises générées.

```js
const head = useLocaleHead({ identifierAttribute: 'data-i18n' })
```

### Désactiver les attributs SEO

Générer des attributs head sans ajouter les balises meta et link liées au SEO.

```js
const head = useLocaleHead({ addSeoAttributes: false })
```

### Spécifier une URL de base

Définir une URL de base personnalisée pour les URLs canoniques et alternatives.

```js
const head = useLocaleHead({ baseUrl: 'https://mywebsite.com' })
```

## 🚀 Fonctionnalités supplémentaires

### Balises meta et link SEO

Lorsque `addSeoAttributes` est activé, le composable génère automatiquement les balises suivantes :

- `og:locale` pour la locale actuelle (`language_TERRITORY`, souligné). Dérivée de `locale.og` ou convertie depuis `locale.iso` lorsque possible.
- `og:url` pour l'URL canonique de la page.
- `og:locale:alternate` pour les versions alternatives de langue.
- Liens `rel="canonical"` et `rel="alternate"` pour l'optimisation SEO.
- Lien `hreflang="x-default"` pointant vers l'URL de la locale par défaut. Ceci indique aux moteurs de recherche quelle URL afficher aux utilisateurs dont la langue ne correspond à aucune des locales définies.

### Locale et direction dynamiques

Le composable détermine dynamiquement les attributs `lang` et `dir` selon la locale de la route actuelle, garantissant que votre document HTML est correctement configuré pour les utilisateurs internationaux.

### Gestion des routes localisées

Si vos routes sont préfixées par des codes de locale (par ex. `/en/about`), le composable ajuste intelligemment le chemin complet pour générer les URLs, garantissant que les attributs SEO sont exacts et pertinents.

Ce composable simplifie le processus d'optimisation de votre application Nuxt pour un public international, garantissant que votre site est bien préparé pour les moteurs de recherche et les utilisateurs mondiaux.

## 🛠️ Exemple d'utilisation

L'exemple suivant montre comment utiliser le composable `useLocaleHead` dans un composant Vue avec les paramètres par défaut :

```vue
<script setup>
import { useRoute, watch } from '#imports'
const route = useRoute()
const { metaObject, updateMeta } = useLocaleHead({
  addDirAttribute: true,
  identifierAttribute: 'id',
  addSeoAttributes: true,
})
useHead(metaObject)
watch(
  () => route.fullPath,
  () => updateMeta(),
  { immediate: true },
)
</script>
```

### Explication du code

- **Composable `useLocaleHead`** : Ce composable est appelé dans la section `<script setup>` et renvoie un objet contenant `htmlAttrs`, `meta` et `link`.

- **Balise `<html>`** : Les attributs `lang` et `dir` du document HTML sont déterminés dynamiquement selon la locale actuelle et sont appliqués à la balise `<html>`.

- **Section `<head>`** :
  - **Balises meta** : Les balises meta liées au SEO sont générées, incluant `og:locale`, `og:url` et les balises `rel="canonical"` et `rel="alternate"` pour spécifier les versions alternatives de langue de la page.
  - **Balises link** : Les liens canoniques, les liens vers les versions alternatives de langue et le lien `hreflang="x-default"` (pointant vers l'URL de la locale par défaut) sont inclus.

- **Section `<body>`** : Le contenu principal de la page s'affiche ici. Dans cet exemple, un simple en-tête et un paragraphe sont utilisés.

### 📝 Notes

1. **Attributs** : Les attributs utilisés (`lang`, `dir`, `rel`, `href`, `hreflang`, `property`, `content`) sont extraits de l'objet renvoyé par `useLocaleHead`.

2. **Génération des balises SEO** : Si l'option `addSeoAttributes` est définie sur `true`, le composable génère automatiquement les balises SEO pour la locale actuelle.

3. **URL de base** : Vous pouvez définir votre URL de base personnalisée à l'aide de l'option `baseUrl` pour générer correctement les liens canoniques et alternatifs.

Cet exemple montre à quel point il est facile d'intégrer `useLocaleHead` dans les composants de votre application pour garantir des attributs SEO corrects et améliorer l'indexation par les moteurs de recherche des pages localisées.

## 🧩 Personnalisation et cycle de vie

- `useLocaleHead` ne s'abonne pas lui-même aux changements. Il renvoie `metaObject` et `updateMeta`.
- Vous devez appeler `updateMeta()` lorsque les entrées changent (typiquement lors d'un changement de route), par exemple depuis un plugin :

```ts
// plugins/02.meta.ts
export default defineNuxtPlugin(() => {
  const route = useRoute()
  const { metaObject, updateMeta } = useLocaleHead({ baseUrl: 'https://example.com' })
  useHead(metaObject)
  if (import.meta.server) updateMeta()
  else
    watch(
      () => route.fullPath,
      () => updateMeta(),
      { immediate: true },
    )
})
```

## Quand utiliser `useI18nHead` à la place

Lorsque `meta: true` (par défaut), préférez [`useI18nHead`](/api/composables/use-i18n-head) pour les surcharges **par page** (hreflang personnalisé, `og:title` supplémentaire, désactivation partielle). N'utilisez `useLocaleHead` directement que lorsque `meta: false` ou que vous gérez `useHead` vous-même.
