# useI18nLocale

## Signature

{/* generated:symbol:useI18nLocale — do not edit; run `pnpm run docs:generate` */}

useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getLocaleWithServerFallback: (serverLocale?: string | null) => string | null; getPreferredLocale: () => string | null; hashCookie: any; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: any; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }

Point d'entrée centralisé pour la gestion des locales i18n.
Combine `useState('i18n-locale')`, le cookie de locale et des utilitaires de synchronisation.

{/* /generated:symbol:useI18nLocale */}

## Utilisation

```vue
<script setup>
const {
  locale,
  localeCookie,
  hashCookie,
  validLocales,
  getPreferredLocale,
  getLocale,
  getLocaleWithServerFallback,
  getEffectiveLocale,
  resolveInitialLocale,
  setLocale,
  syncLocale,
  isValidLocale,
} = useI18nLocale()

// Set locale (updates state and cookies)
setLocale('de')

// Get current locale (state → cookie)
const current = getLocale()

// Get valid preferred locale
const preferred = getPreferredLocale()
</script>
```

## API

| Propriété/Méthode                               | Type                                | Description                                                                          |
| ----------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------ |
| `locale`                                        | `Ref<string \| null>`               | État réactif de la locale (`useState('i18n-locale')`)                                |
| `localeCookie`                                  | `Ref`                               | Cookie de locale (quand l'option `localeCookie` est activée)                         |
| `hashCookie`                                    | `Ref`                               | Cookie utilisé quand `hashMode` est actif                                            |
| `validLocales`                                  | `string[]`                          | Codes de locale activés depuis la config du module (exclut `disabled`)               |
| `getLocale()`                                   | `() => string \| null`              | Locale courante : état → cookie (ou hash cookie en mode hash)                        |
| `getPreferredLocale()`                          | `() => string \| null`              | Locale depuis l'état/le cookie **validée** contre `validLocales`, ou `null`          |
| `getLocaleWithServerFallback(serverLocale?)`    | `(serverLocale?) => string \| null` | État → cookie → contexte serveur optionnel (utilisé lors de l'init `no_prefix`)      |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string`             | Locale pour charger les traductions : en mode hash, l'état est préféré ; sinon, lecture depuis la route |
| `resolveInitialLocale(options)`                 | `(options) => string`               | Résout la locale : état → `serverLocale` → route ; synchronise l'état si nécessaire  |
| `setLocale(locale)`                             | `(locale: string \| null) => void`  | Définit la locale et la synchronise avec les cookies                                 |
| `syncLocale(locale)`                            | `(locale: string \| null) => void`  | Synchronise uniquement les cookies (pas de mise à jour d'état)                       |
| `isValidLocale(locale)`                         | `(locale) => boolean`               | Vérifie que la chaîne est dans `validLocales`                                        |

### Options de `resolveInitialLocale`

```typescript
interface ResolveInitialLocaleOptions {
  route: unknown
  serverLocale?: string | null
  getLocaleFromRoute: (route?: unknown) => string
}
```

Utilisé en interne par le plugin principal au démarrage. Les plugins personnalisés peuvent l'appeler lorsqu'ils implémentent des flux de détection alternatifs.

### `getEffectiveLocale`

```typescript
const { getEffectiveLocale } = useI18nLocale()
const { $getLocale } = useNuxtApp()

const locale = getEffectiveLocale(route, (r) => $getLocale(r))
```

Renvoie la locale utilisée pour charger les traductions et formater les messages pour un objet de route donné.

## Définition programmatique de la locale

Préférez `useI18nLocale()` à l'usage direct de `useState('i18n-locale')` :

```ts
// plugins/i18n-loader.server.ts
import { defineNuxtPlugin } from '#imports'

export default defineNuxtPlugin({
  name: 'i18n-custom-loader',
  enforce: 'pre',
  order: -10,

  setup() {
    const { setLocale } = useI18nLocale()
    const detectedLocale = 'ja' // Your detection logic here
    setLocale(detectedLocale)
  },
})
```

<Tip>
`setLocale()` ne met à jour que la préférence de locale (état + cookie). Pour recharger également le contexte de traduction actif côté client, utilisez `$switchLocale()` depuis `useNuxtApp()` ou `useI18n()`. Cela compte surtout pour `no_prefix`, où l'URL ne change pas. Voir [FAQ — changer de locale sans changer l'URL](/guides/faq#-switch-locale-without-changing-the-url).
</Tip>
