## Nuxt I18n Micro v3.22.0 — Formats, cache et Translation Memory {#nuxt-i18n-micro-v3-22-0-—-formats-cache-&-translation-memory}

**Date** : 2026-07-30

**Version** : `v3.22.0`

![Version v3.22.0](/images/3.22.0.png)

Nous annonçons la **v3.22.0** : des formats nommés de nombres et de dates à la Vue I18n avec un cache de formateurs, une mise en cache des payloads de traduction adaptée aux CDN (empreinte de contenu + `httpCacheDuration`) et une API Translation Memory pour lire et remplacer le dictionnaire actif à l'exécution.

## Quoi de neuf ? {#what’s-new}

### `numberFormats` / `datetimeFormats` nommés + cache de formateurs {#named-numberformats-/-datetimeformats-+-formatter-cache}

Des formats nommés compatibles avec Vue I18n et un formatage Intl plus rapide :

- Configuration : `numberFormats` / `datetimeFormats` par locale
- API : `$tn(1000, 'currency')`, `$td(date, 'short')` (+ surcharge de locale et fusion d'options)
- `FormatService` met en cache `Intl.NumberFormat` / `DateTimeFormat` / `RelativeTimeFormat` par locale+options

Voir [Méthodes — `$tn` / `$td`](/fr/api/methods#$tn) et [Options du module](/fr/api/module-options#numberformats).

### `dateBuild` utilise par défaut une empreinte de contenu {#datebuild-defaults-to-a-content-fingerprint}

Le paramètre `?v=` des requêtes `/_locales` valait auparavant `Date.now()` par défaut, alors que les réponses sont servies `immutable` pendant un an. Chaque rebuild invalidait donc le dictionnaire de tous les clients, même si aucune traduction n'avait changé.

La valeur par défaut est désormais une empreinte SHA-256 des sources de traduction, dans l'ordre des layers. Les rebuilds sans modification des traductions conservent la même URL. Définir `dateBuild` explicitement reste prioritaire. Voir [Options du module — `dateBuild`](/fr/api/module-options#datebuild).

### `httpCacheDuration` pour les payloads `/_locales` {#httpcacheduration-for-/_locales-payloads}

La route intégrée `/{apiBaseUrl}/:page/:locale/data.json` envoie désormais un en-tête HTTP `Cache-Control` pour les navigateurs et les CDN :

- Option : `httpCacheDuration` (en secondes, `31536000` / 1 an par défaut)
- En-tête : `Cache-Control: public, max-age=…, immutable`
- Compatible avec le cache-busting existant via `dateBuild` (`?v=...`) ; `0` désactive l'en-tête ; non appliqué en développement

Équivalent de `experimental.httpCacheDuration` de `@nuxtjs/i18n` v10.2.0, sous la forme d'un en-tête de réponse explicite.

### Payloads publics compressés {#compressed-public-payloads}

`nitro.compressPublicAssets` s'applique désormais aux payloads de traduction copiés dans le répertoire public (`.gz` + `.br`). Nitro compresse les assets publics avant que la copie n'ait lieu ; auparavant, les payloads étaient donc la seule partie non compressée d'un build statique — 6,65 Mo bruts contre 1,01 Mo en gzip sur l'index du playground. Le module n'active toujours jamais la compression de lui-même. Voir [Performances](/fr/guide/performance#payload-size).

### `resolveTranslations()` et `setTranslation(key, value)` {#resolvetranslations-and-settranslationkey-value}

Des helpers d'exécution pour lire et remplacer en mémoire le dictionnaire de traduction actif :

- **`resolveTranslations()`** renvoie l'arbre complet dans lequel `$t()` lit pour la locale et la route actives — utile pour les DevTools, les tests et les éditeurs à l'exécution. Lorsqu'un second layer est actif (locale de repli ou rechargement à chaud lors d'une transition de page Nuxt), le dump conserve la forme imbriquée via `mergeTranslationLayers` et n'utilise des clés plates à points que pour les collisions scalaire/objet qu'un arbre unique ne peut pas exprimer autrement.
- **`setTranslation(key, value)`** remplace la valeur d'une clé (de premier niveau, chemin à points, objet, chaîne ou scalaire). Il s'agit d'un **remplacement**, pas d'une fusion ; utilisez `$mergeTranslations` lorsque les clés sœurs doivent être conservées.
- Disponible sur `useI18n()`, `useNuxtApp()` et les instances i18n des frameworks héritées de `@i18n-micro/core`.
- `@i18n-micro/test-utils` ajoute les helpers correspondants `resolveTranslations` / `setTranslation` pour les tests unitaires.

### `getAllTranslations()` supprimé du package Vue {#getalltranslations-removed-from-vue-package}

Utilisez `resolveTranslations()` pour l'arbre de recherche actif. Pour un dump complet du stockage dans Vue, utilisez `getStorage()` ou `getRouteCache()`.

## Changements incompatibles {#breaking-changes}

Rien dans la configuration publique n'impose de modifier le code de l'application pour un usage classique. Ces points comptent si vous accédiez aux mécanismes internes de l'exécution :

- **Le payload SSR est passé de `useState('i18n-ssr-chunks')` à `nuxtApp.payload.data['i18n-ssr-chunks']`.** Il contient toujours les **chunks de traduction complets** pour chaque couple `(locale, route)` chargé pendant le SSR — les mêmes dictionnaires qu'avant, dans un emplacement que Nuxt peut externaliser dans `_payload.json` lors du prérendu. `useState('i18n-ssr-chunks')` ne renvoie plus rien. Lire les traductions de cette manière n'a jamais été pris en charge, mais c'était décrit dans la documentation de l'API de cache, d'où cette mention.
- **`NuxtTranslationLoaderOptions` expose `setSsrChunk`.** Le loader écrit chaque chunk fusionné dans `payload.data` côté serveur au fur et à mesure du chargement. `getSsrChunks` n'est pas utilisé.
- **`nitro.compressPublicAssets` émet désormais des fichiers `.gz` / `.br` à côté des payloads copiés.** Attendez-vous à davantage de fichiers dans la sortie publique si l'option était activée. Les outils de déploiement qui énumèrent le répertoire des traductions devront peut-être en tenir compte.
- **Les URL des payloads changent une fois lors de la mise à jour**, car `?v=` passe d'un horodatage de build à une empreinte de contenu. Les clients re-téléchargent le dictionnaire à la première requête après la mise à jour, puis le conservent lors des déploiements suivants — c'est justement le but.
- **`getAllTranslations()` supprimé de `@i18n-micro/vue`.** Utilisez `resolveTranslations()` / `getStorage()` / `getRouteCache()` à la place.

## Corrections de bugs {#bug-fixes}

- **`<i18n-switcher>`** — omet du menu déroulant les locales ayant `disabled: true`. `$getLocales()` renvoie toujours la liste complète pour votre propre code, tandis que la sortie SEO/meta intégrée exclut les locales désactivées.
- **Styles du switcher** — `cursor: not-allowed` s'applique à la locale **courante** via `activeLinkStyle` / `customActiveLinkStyle` ; `customDisabledLinkStyle` est rétabli pour la rétrocompatibilité et appliqué au bouton du switcher lorsque la locale courante a `disabled: true`.
- **HMR en dev** — une écriture qui laisse le contenu du fichier inchangé (sauvegarde à la perte de focus dans l'éditeur, réécriture par un formateur) ne déclenche plus de nouvelle fusion. Les modifications de la locale racine reconstruisent chaque page de cette locale ; c'était donc coûteux pour une opération sans effet.
- **HMR en dev** — les pages sont refusionnées en parallèle lors d'une modification de la locale racine, au lieu de l'être l'une après l'autre.
- **Transitions de page** — la navigation dans la même locale conserve le chunk sortant comme layer de repli jusqu'à `page:transition:finish`, au lieu d'une fusion profonde coûteuse à chaque navigation.

## Pourquoi c'est important {#why-it-matters}

- Un formatage à la Vue I18n sans embarquer une pile plus lourde.
- Des URL de traduction adaptées aux CDN qui restent stables d'un rebuild à l'autre lorsque le dictionnaire n'a pas changé.
- Une API d'exécution prise en charge pour inspecter et modifier le dictionnaire actif — les DevTools, les tests et les éditeurs n'ont plus besoin de helpers privés.

Le changelog complet sera publié avec la version sur [GitHub](https://github.com/s00d/nuxt-i18n-micro/blob/main/CHANGELOG.md).
