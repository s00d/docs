**Date** : 2026-06-25

**Version** : `v3.21.0`

![v3.21.0 release](/images/3.21.0.png)

Cette version ajoute **`useI18nHead`** — un composable au niveau de la page pour surcharger le SEO i18n par-dessus le plugin intégré `02.meta`. Personnalisez `hreflang`, l’URL canonique, `og:url` et les balises Open Graph par route sans plugin meta personnalisé ni `meta: false`.

## Quoi de neuf ? {#what’s-new}

### Composable `useI18nHead` {#usei18nhead-composable}

Appelez `useI18nHead` dans n’importe quelle page lorsque `meta: true` (par défaut). Le module fusionne vos données après `useLocaleHead` à chaque mise à jour de route :

```vue
<script setup lang="ts">
useI18nHead(() => ({
  meta: [{ property: 'og:title', content: article.value?.title }],
  replace: {
    canonical: article.value?.canonicalUrl,
    ogUrl: article.value?.canonicalUrl,
    hreflang: localeCodes.map((locale) => ({
      rel: 'alternate',
      hreflang: locale,
      href: article.value!.locales[locale]!,
    })),
    ogAlternates: localeCodes,
  },
}))
</script>
```

Prend en charge les objets statiques, les getters réactifs, l’ajout via `meta` / `link`, `replace` pour les groupes intégrés et `disable` pour supprimer les balises générées automatiquement. Voir [`useI18nHead`](/fr/composables/useI18nHead).

### Utilitaire `mergeI18nHead` (`@i18n-micro/utils`) {#mergei18nhead-utility-@i18n-micro/utils}

La logique de fusion indépendante du framework se trouve dans `@i18n-micro/utils/merge-i18n-head` — utilisée par le plugin `02.meta` et testable isolément. Les types (`I18nHeadInput`, `I18nHeadLink`, `I18nHeadMeta`) sont exportés depuis `@i18n-micro/types`.

### Intégration aux plugins {#plugin-integration}

- **`02.meta`** — fusionne la sortie de `useLocaleHead` avec l’état de la page issu de `useI18nHead` via `useHead`
- **`01.plugin`** — réinitialise les surcharges de la page lors d’un changement de nom de route via `resetPageHead()` (état partagé avec le composable)

## Cas d’usage typiques {#typical-use-cases}

| Scénario                                     | Approche                                                       |
| -------------------------------------------- | -------------------------------------------------------------- |
| Blog/CMS avec traductions partielles         | `replace.hreflang` + `replace.ogAlternates` depuis les locales de l’API |
| URL canonique personnalisée depuis le CMS    | `replace.canonical` + `replace.ogUrl`                          |
| OG uniquement sur une landing page           | `meta: [{ property: 'og:title', ... }]` — conserver le hreflang du module |
| Pas de hreflang sur une page                 | `disable: ['hreflang', 'x-default']`                           |
| Remplacer un plugin personnalisé (`i18nManualHreflang`) | `useI18nHead` par page de contenu + `meta: true`    |

Le **JSON-LD** reste dans `useHead({ script: [...] })` — `useI18nHead` ne génère pas de données structurées.

## Changements incompatibles {#breaking-changes}

Aucun pour un usage standard de `nuxt.config`. Le nouveau composable et le sous-chemin utils sont purement additifs.

## Pourquoi c’est important {#why-it-matters}

- **Aucun plugin meta personnalisé** pour les articles CMS, actualités ou guides avec des URL par locale
- **Pipeline unique** — valeurs par défaut du module + surcharges de la page dans un seul appel `useHead`
- **Typage sûr** — `I18nHeadInput` pour des helpers comme `buildArticleHead(content)`
