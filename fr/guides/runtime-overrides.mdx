# Surcharges i18n au runtime

Utilisez ce guide lorsque vous avez besoin qu'un seul artefact de build s'exécute avec des valeurs par défaut de locale différentes selon l'environnement (par exemple, différentes instances de locataires).

## Ce qui peut être surchargé à l'exécution

Le module prend en charge en toute sécurité les surcharges à l'exécution pour :

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Ces surcharges s'appliquent au-dessus de la config de build issue de `.nuxt/i18n.strategy.mjs` et `.nuxt/i18n.config.mjs`.

## Ce qui ne peut pas être surchargé à l'exécution

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) est une question de build car cela affecte le comportement des routes générées.

Si vous passez une surcharge de stratégie au runtime, elle est ignorée et un avertissement est émis.

## Surcharges via RuntimeConfig

Fournissez les valeurs runtime sous `runtimeConfig.public.i18nRuntime` :

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Surcharges via variables d'environnement

Vous pouvez également configurer les surcharges via des variables d'environnement :

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (séparées par des virgules, par exemple `fr,it`)

Des alias de repli sont également pris en charge :

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Règles de validation

À l'exécution, le module valide les surcharges afin d'éviter un état cassé :

- Vous ne pouvez pas désactiver toutes les locales.
- `defaultLocale` doit pointer vers une locale activée.
- `fallbackLocale` doit exister dans les locales déclarées.

Si une surcharge est invalide, le module conserve une valeur sûre et enregistre un avertissement.

## Notes pour les déploiements multi-instances

Cette fonctionnalité runtime est conçue pour l'activation de locales et les valeurs par défaut par instance, sans reconstruire.

Si les instances nécessitent des stratégies d'URL différentes (`no_prefix` vs `prefix`), utilisez des builds séparés pour chaque stratégie.

## Locales désactivées et payloads statiques

`runtimeConfig.public.i18nRuntime.disabledLocales` met à jour le routage, le sélecteur et le **handler** de payload Nitro. Mais Nitro sert les fichiers sous `public/` **avant** ce handler.

Si `translationPayloads.publicAssets` (ou la copie publique forcée du SSR Node) a déjà écrit `/_locales/\{page\}/\{locale\}/data.json`, une désactivation à l'exécution ne peut pas cacher ce fichier. Préférez `locale.disabled: true` au build pour que la préfusion n'émette pas les payloads statiques de cette locale.
