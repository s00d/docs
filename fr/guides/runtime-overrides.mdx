# Surcharges i18n à l'exécution

Utilisez ce guide lorsque vous avez besoin qu'un même artefact de build s'exécute avec des valeurs de locale par défaut différentes selon l'environnement (par exemple : différentes instances tenant).

## Ce qui peut être surchargé à l'exécution

Le module prend en charge en toute sécurité les surcharges à l'exécution pour :

- `defaultLocale`
- `fallbackLocale`
- `disabledLocales`

Ces surcharges sont appliquées par-dessus la configuration de build issue de `.nuxt/i18n.strategy.mjs` et `.nuxt/i18n.config.mjs`.

## Ce qui ne peut pas être surchargé à l'exécution

`strategy` (`no_prefix`, `prefix`, `prefix_except_default`, `prefix_and_default`) est une préoccupation de build car elle affecte le comportement des routes générées.

Si vous passez une surcharge de stratégie à l'exécution, elle est ignorée et un avertissement est émis.

## Surcharges basées sur RuntimeConfig

Fournissez des valeurs d'exécution sous `runtimeConfig.public.i18nRuntime` :

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      i18nRuntime: {
        defaultLocale: 'de',
        fallbackLocale: 'en',
        disabledLocales: ['fr'],
      },
    },
  },
})
```

## Surcharges par variables d'environnement

Vous pouvez également configurer les surcharges via des variables d'environnement :

- `NUXT_I18N_DEFAULT_LOCALE`
- `NUXT_I18N_FALLBACK_LOCALE`
- `NUXT_I18N_DISABLED_LOCALES` (séparées par des virgules, par ex. `fr,it`)

Des alias de repli sont également pris en charge :

- `NUXT_PUBLIC_I18N_RUNTIME_DEFAULT_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_FALLBACK_LOCALE`
- `NUXT_PUBLIC_I18N_RUNTIME_DISABLED_LOCALES`

## Règles de validation

À l'exécution, le module valide les surcharges pour éviter un état invalide :

- Vous ne pouvez pas désactiver toutes les locales.
- `defaultLocale` doit pointer vers une locale activée.
- `fallbackLocale` doit exister parmi les locales déclarées.

Si une surcharge est invalide, le module conserve une valeur sûre et journalise un avertissement.

## Notes pour les déploiements multi-instances

Cette fonctionnalité d'exécution est conçue pour l'activation de locale et les valeurs par défaut par instance sans reconstruire.

Si les instances nécessitent des stratégies d'URL différentes (`no_prefix` vs `prefix`), utilisez des builds séparés pour chaque stratégie.

## Locales désactivées et payloads statiques

`runtimeConfig.public.i18nRuntime.disabledLocales` met à jour le routage, le switcher et le **handler** de payload Nitro — mais Nitro sert les fichiers sous `public/` **avant** ce handler.

Si `translationPayloads.publicAssets` (ou la copie publique forcée du SSR Node) a déjà écrit `/_locales/\{page\}/\{locale\}/data.json`, une désactivation à l'exécution ne peut pas masquer ce fichier. Préférez `locale.disabled: true` au build afin que le premerge n'émette pas les payloads statiques de cette locale.
