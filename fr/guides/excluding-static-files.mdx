# Exclure les fichiers statiques du routage i18n

## Vue d'ensemble

Par défaut, nuxt-i18n-micro exclut automatiquement les fichiers statiques courants du traitement de routage i18n. Cependant, vous pouvez également configurer des motifs d'exclusion personnalisés pour empêcher que certains chemins soient traités par le système i18n.

## Exclusions intégrées

Le module exclut automatiquement les types de fichiers et motifs suivants :

- **Sitemaps** : `/sitemap*.xml`, `/sitemap-en.xml`, etc.
- **Fichiers SEO** : `/robots.txt`, `/favicon.ico`
- **Fichiers PWA** : `/manifest.json`, `/sw.js`, `/workbox-*.js`
- **Ressources statiques** : Fichiers avec des extensions comme `.xml`, `.txt`, `.ico`, `.json`, `.js`, `.css`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`
- **Chemins internes de Nuxt** : Tout chemin commençant par `__` (comme `/__nuxt/`)

## Motifs d'exclusion personnalisés

Vous pouvez définir des motifs d'exclusion personnalisés à l'aide de l'option `excludePatterns` :

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],

  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'it', iso: 'it-IT' },
    ],
    defaultLocale: 'en',

    // Custom exclusion patterns
    excludePatterns: [
      // String patterns (exact match or prefix)
      '/api/health',
      '/admin',

      // String patterns with wildcards
      '/api/*',
      '/admin/**',

      // Regular expressions
      /^\/api\/v\d+\//,
      /\.(pdf|doc|docx)$/,
    ],
  },
})
```

## Types de motifs

### Motifs sous forme de chaîne

- **Correspondance exacte** : `'/api/health'` - correspond exactement à `/api/health`
- **Correspondance de préfixe** : `'/admin'` - correspond à `/admin` et `/admin/dashboard`
- **Wildcards** : `'/api/*'` - correspond à `/api/users` mais pas à `/api/users/123`
- **Wildcards profonds** : `'/admin/**'` - correspond à `/admin/users` et `/admin/users/123`

### Expressions régulières

Utilisez des objets RegExp pour une correspondance de motifs complexe :

```typescript
excludePatterns: [
  /^\/api\/v\d+\//, // API versioned routes
  /\.(pdf|doc|docx)$/, // Document files
  /^\/static\//, // Static directory
  /^\/[a-z]{2}\/api\//, // Localized API routes
]
```

## Cas d'usage

### Fichiers SEO

```typescript
excludePatterns: ['/sitemap.xml', '/sitemap-*.xml', '/robots.txt', '/favicon.ico']
```

### Routes API

```typescript
excludePatterns: ['/api/**', '/graphql', '/webhook/**']
```

### Panneaux d'administration

```typescript
excludePatterns: ['/admin', '/admin/**', '/dashboard']
```

### Ressources statiques

```typescript
excludePatterns: ['/assets/**', '/static/**', '/uploads/**']
```

## Comment cela fonctionne

1. **Middleware serveur** : Un middleware Nitro s'exécute en premier pour vérifier les motifs d'exclusion
2. **Traitement des pages** : Lors de la résolution des pages, les chemins exclus sont ignorés
3. **Route fourre-tout** : La route de repli vérifie les exclusions avant le traitement
4. **Prérendu** : Les chemins exclus ne sont pas inclus dans les routes prérendues

## Impact sur les performances

- Les vérifications d'exclusion sont optimisées et s'exécutent tôt dans le cycle de vie de la requête
- Les motifs intégrés utilisent une correspondance regex efficace
- Les motifs personnalisés sont mis en cache et réutilisés
- Surcharge de performance minimale pour les chemins exclus

## Dépannage

### Les fichiers statiques sont toujours interceptés

1. **Vérifiez la syntaxe du motif** : Assurez-vous que vos motifs correspondent à la structure exacte du chemin
2. **Utilisez regex pour les motifs complexes** : Les wildcards de chaînes ont des limitations
3. **Testez les motifs** : Utilisez les outils de développement du navigateur pour vérifier le chemin réel de la requête
4. **Vérifiez l'ordre** : Assurez-vous que les motifs d'exclusion sont définis avant les autres configurations i18n

### Le motif ne fonctionne pas

```typescript
// ❌ Wrong - this won't work
excludePatterns: ['sitemap.xml']

// ✅ Correct - include leading slash
excludePatterns: ['/sitemap.xml']

// ✅ Better - use regex for flexibility
excludePatterns: [/^\/sitemap.*\.xml$/]
```

### Mode debug

Activez le mode debug pour voir le traitement des exclusions :

```typescript
i18n: {
  debug: true,
  excludePatterns: ['/api/**']
}
```

Cela affichera les décisions d'exclusion dans la console.

## Migration depuis les contournements

Si vous utilisiez des contournements comme les route rules ou les middleware, vous pouvez maintenant les remplacer par `excludePatterns` :

```typescript
// ❌ Old workaround
export default defineNuxtConfig({
  routeRules: {
    '/sitemap*.xml': { headers: { 'content-type': 'application/xml' } },
  },
})

// ✅ New approach
export default defineNuxtConfig({
  i18n: {
    excludePatterns: ['/sitemap*.xml'],
  },
})
```

La nouvelle approche est plus fiable et fonctionne à plusieurs niveaux du système de routage.
