# Résultats des tests de performance

## Informations sur le projet

- **[plain-nuxt](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/plain-nuxt)** : ./test/fixtures/plain-nuxt
- **[i18n-micro](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n-micro)** : ./test/fixtures/i18n-micro
- **[i18n](https://github.com/s00d/nuxt-i18n-micro/tree/main/test/fixtures/i18n)** : ./test/fixtures/i18n
- **[CLI](https://github.com/s00d/nuxt-i18n-micro/tree/main/scripts/src/commands/performance.ts)** : `pnpm -C scripts cli performance` / `pnpm test:performance`

### Description

Compare **plain Nuxt** (référence sans module i18n), **i18n-micro** et **`@nuxtjs/i18n` v10.6** sous un profil de dictionnaire partagé.

Focus : temps de build, RSS pic, **code vs traductions vs total** déployable et comportement serveur sous Artillery + Autocannon.

### Notes méthodologiques

- Les métriques sont des **moyennes de 3 exécutions consécutives par fixture** (fixture A ×3, puis B ×3, puis C ×3 — pas entrelacées).
- Les **traductions** incluent les JSON de locale sous `locales/` / `_locales/` / `translations/`, tout sous `chunks/raw/`, et les chunks de locale correspondants. Les rapports plus anciens qui affichaient « traductions : 0 B » pour `@nuxtjs/i18n` et une énorme colonne « code » comptaient les chunks de messages comme du code applicatif.
- **plain-nuxt** sert le même volume de feuilles que du JSON `public/translations` statique (et non des imports JS statiques). Sous Artillery, cette référence est intensive en I/O ; ce n'est pas un « surcoût i18n », c'est le coût de récupérer de gros JSON par requête.

### Exécutions

Toutes les métriques ci-dessous sont des **moyennes sur 3 exécutions**.

### Profil de fixture

| Paramètre | Valeur |
|------|-------|
| Locales | **4** (`en`, `de`, `ru`, `fr`) |
| Pages | **2** (`index`, `page`) |
| Arbre d'index | profondeur **5**, branche **7** → **16 807** clés feuilles / locale |
| Pages secondaires | profondeur **5**, branche **6** → **7 776** clés feuilles / page / locale |
| Objectif | Profil CLI par défaut (`--locales 4 --keys 10000`) ; augmentez les paramètres pour des charges radar-régression |

Les dictionnaires proviennent de `test/fixtures/perf-shared/runtime.json` (écrit par la CLI) afin que les trois fixtures restent alignées.

## Performance de build pour test/fixtures/plain-nuxt

- **Temps de build** : 5,32 secondes
- **Taille du bundle** : 8,33 Mo (code : 1,53 Mo, traductions : 6,8 Mo)
- **Bundle de code** : client : 201,88 Ko, serveur : 1,33 Mo
- **CPU max / moy.** : 207,10 % / 166,29 %
- **Mémoire max / moy.** : 810,26 Mo / 585,14 Mo

## Performance de build pour test/fixtures/i18n

- **Temps de build** : 8,34 secondes
- **Taille du bundle** : 9,37 Mo (code : 2,16 Mo, traductions : 7,21 Mo)
- **Bundle de code** : client : 315,17 Ko, serveur : 1,86 Mo
- **CPU max / moy.** : 203,97 % / 164,39 %
- **Mémoire max / moy.** : 1820,57 Mo / 1177,11 Mo

## Performance de build pour test/fixtures/i18n-micro

- **Temps de build** : 5,34 secondes
- **Taille du bundle** : 8,54 Mo (code : 1,74 Mo, traductions : 6,8 Mo)
- **Bundle de code** : client : 272,93 Ko, serveur : 1,48 Mo
- **CPU max / moy.** : 203,60 % / 177,27 %
- **Mémoire max / moy.** : 1065,16 Mo / 667,77 Mo

## Résumé des performances de build (moyenne de 3 exécutions)

| Projet | Temps de build | Bundle de code | Traductions | Total |
|---------|------------|-------------|--------------|-------|
| **plain-nuxt** (référence) | 5,32s | 1,53 Mo | 6,8 Mo | 8,33 Mo |
| **i18n-v10** | 8,34s | 2,16 Mo | 7,21 Mo | 9,37 Mo |
| **i18n-micro** | 5,34s | 1,74 Mo | 6,8 Mo | 8,54 Mo |

> « Total » = ce qui est déployé (code + traductions). Micro conserve les traductions en JSON paresseux ; `@nuxtjs/i18n` embarque toujours un graphe de code plus important même après classification correcte des chunks de messages.
