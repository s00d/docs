---
title: "useI18nLocale"
description: "useI18nLocale lit et écrit l'état de la locale et le cookie de locale — le point d'entrée de la détection de locale personnalisée."
---

`useI18nLocale()` donne accès à la locale choisie par l'application : l'état `i18n-locale` et le cookie de locale. Utilisez-le dans un plugin qui détecte lui-même la locale (domaine, profil utilisateur, en-tête) au lieu d'écrire `useState('i18n-locale')` ou le cookie à la main. Ses vérifications de validité utilisent les locales activées, surcharges d'exécution comprises.

## Signature {#signature}

```ts
useI18nLocale(): { getEffectiveLocale: (route: unknown, getLocaleFromRoute: GetLocaleFromRoute) => string; getLocale: () => string | null; getPreferredLocale: () => string | null; hashCookie: CookieRef; isValidLocale: (locale: string | null | undefined) => locale is string; locale: any; localeCookie: CookieRef; resolveInitialLocale: (options: ResolveInitialLocaleOptions) => string; setLocale: (locale: string | null) => void; syncLocale: (locale: string | null) => void; validLocales: string[] }
```

Point d'entrée centralisé pour la gestion de la locale i18n.
Combine useState('i18n-locale'), le cookie de locale et les utilitaires de synchronisation.

## Valeurs renvoyées {#returned-values}

| Membre | Type | Description |
| --- | --- | --- |
| `locale` | `Ref<string \| null>` | La ref `useState('i18n-locale')`. |
| `localeCookie` | `Ref<string \| null>` | Le cookie [`localeCookie`](/fr/api/module-options#localecookie) ; un simple `{ value: null }` lorsque l'option vaut `null`. |
| `hashCookie` | `Ref<string \| null>` | Le cookie `hash-locale` en routage par hash ; `{ value: null }` sinon. |
| `validLocales` | `string[]` | Codes des locales activées. |
| `setLocale(locale)` | `(locale: string \| null) => void` | Écrit l'état et les cookies. Ne valide pas et ne charge pas les traductions. |
| `syncLocale(locale)` | `(locale: string \| null) => void` | Écrit uniquement les cookies. |
| `getLocale()` | `() => string \| null` | L'état, puis le cookie de préférence (cookie de hash en routage par hash). Non validé. |
| `getPreferredLocale()` | `() => string \| null` | La première valeur **valide** entre l'état et le cookie de préférence, ou `null`. |
| `getEffectiveLocale(route, getLocaleFromRoute)` | `(route, fn) => string` | L'état en routage par hash s'il est défini ; sinon `getLocaleFromRoute(route)`. |
| `resolveInitialLocale(options)` | `(options: ResolveInitialLocaleOptions) => string` | `options.urlLocale`, puis un état valide, puis `options.serverLocale`, puis la locale de la route. Enregistre le résultat dans l'état lorsque celui-ci n'est pas valide ; côté client, écrit aussi le cookie. |
| `isValidLocale(locale)` | `(locale) => locale is string` | Indique si `locale` figure dans `validLocales`. |

Les cookies durent un an, avec `path: '/'` et `sameSite: 'lax'`.

## Exemple {#example}

```ts
// plugins/locale-from-domain.server.ts
export default defineNuxtPlugin({
  name: 'locale-from-domain',
  enforce: 'pre',
  setup() {
    const { setLocale, isValidLocale } = useI18nLocale()
    const host = useRequestURL().hostname // e.g. de.example.com
    const code = host.split('.')[0]
    if (isValidLocale(code)) setLocale(code)
  },
})
```

Le plugin loader du module lit l'état à son démarrage ; un plugin qui le définit doit donc s'exécuter avant (`enforce: 'pre'`). Comment l'état se combine avec l'URL, le cookie et `Accept-Language` : [Détection de la locale](/fr/guide/locale-detection). Guide complet : [Détection personnalisée](/fr/guide/custom-auto-detect).

`setLocale()` ne change pas les traductions affichées à l'écran. Pour changer la locale de la page courante, appelez [`$switchLocale()`](/fr/api/methods#$switchlocale).
