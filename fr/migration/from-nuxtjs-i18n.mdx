# 🔄 Migrer de `nuxt-i18n` vers `Nuxt I18n Micro`

## De quel guide avez-vous besoin ?

| Vous migrez depuis…                    | Guide                                            |
| -------------------------------------- | ------------------------------------------------ |
| `@nuxtjs/i18n` (module basé sur vue-i18n) | **Cette page**                                |
| `nuxt-i18n-micro` v2.x                 | [Passer de v2.x à v3.x](/migration/v2-to-v3)     |

## Pourquoi migrer ?

- **Performances améliorées** : builds environ 51 % plus rapides et mémoire de build réduite d'environ 54 % par rapport à `@nuxtjs/i18n` **v10.6** dans nos [fixtures de benchmark](/guides/performance-results)
- **Configuration simplifiée** : mise en place rationalisée avec des valeurs par défaut sensées
- **Meilleure gestion des ressources** : traitement optimisé des grands fichiers de traduction

## Différences clés

| Fonctionnalité          | `nuxt-i18n`                      | `Nuxt I18n Micro`                         |
| ----------------------- | -------------------------------- | ----------------------------------------- |
| Fichiers de traduction  | JS/TS/JSON, chargés via `vueI18n` | JSON uniquement, générés automatiquement en dev |
| Génération de routes    | À l'exécution                    | Au moment du build (`@i18n-micro/route-strategy`) |
| Chargement des traductions | Empaqueté dans le JS          | JSON chargé à la demande par page         |
| État de la locale       | `useI18n()` depuis `vue-i18n`    | Composable `useI18nLocale()`              |
| `detectBrowserLanguage` | Pris en charge                   | Utilisez `autoDetectLanguage` à la place  |

## Étape par étape

### 1. Installer

```bash
npm install nuxt-i18n-micro
```

### 2. Mettre à jour la configuration

**Avant (nuxt-i18n) :**

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US' },
      { code: 'fr', iso: 'fr-FR' },
    ],
    defaultLocale: 'en',
    vueI18n: './i18n.config.js',
    detectBrowserLanguage: { useCookie: true },
  },
})
```

**Après (Nuxt I18n Micro v3) :**

```typescript
export default defineNuxtConfig({
  modules: ['nuxt-i18n-micro'],
  i18n: {
    locales: [
      { code: 'en', iso: 'en-US', dir: 'ltr' },
      { code: 'fr', iso: 'fr-FR', dir: 'ltr' },
    ],
    defaultLocale: 'en',
    translationDir: 'locales',
    meta: true,
    localeCookie: 'user-locale',
    autoDetectLanguage: true,
  },
})
```

### 3. Réorganiser les fichiers de traduction

Déplacez les traductions vers le répertoire `locales` au format JSON. Voici une comparaison complète du projet :

**Before (`nuxt-i18n`):**

```text
my-app/
├── i18n/
│   └── locales/          # langDir
│       ├── en.json       # all translations in one file
│       ├── ru.json
│       └── de.json
├── pages/
│   ├── index.vue
│   └── page.vue
├── server/
│   └── tsconfig.json
├── nuxt.config.ts        # config will change
└── package.json
```

**After (Nuxt I18n Micro):**

```text
my-app/
├── locales/              # translationDir
│   ├── en.json           # root-level translations
│   ├── ru.json
│   ├── de.json
│   └── pages/            # page-specific
│       ├── index/
│       │   ├── en.json
│       │   ├── ru.json
│       │   └── de.json
│       └── page/
│           ├── en.json
│           ├── ru.json
│           └── de.json
├── pages/
│   ├── index.vue         # API changes
│   └── page.vue
├── server/
│   └── tsconfig.json
├── nuxt.config.ts        # new config
└── package.json
```

<Tip>
Missing page-specific translation files are **auto-generated** in development mode — just run `nuxt dev` and the module will create empty JSON files for each page and locale.
</Tip>

### 4. Mettre à jour la navigation

```diff
- <nuxt-link :to="{ name: 'index' }">Home</nuxt-link>
+ <NuxtLink :to="$localeRoute({ name: 'index' })">Home</NuxtLink>
+ <!-- or use the built-in component -->
+ <i18n-link :to="{ name: 'index' }">Home</i18n-link>
```

### 5. Mettre à jour le SEO

Supprimez toutes les configurations SEO manuelles de `nuxt-i18n`. Nuxt I18n Micro génère automatiquement les balises `hreflang`, les URLs canoniques et les balises Open Graph lorsque `meta: true` est défini.

### 6. Tester

Testez minutieusement les traductions, le changement de locale, les redirections et les balises meta SEO.

## 🛡️ Problèmes courants et dépannage

### ❌ Les fichiers de traduction ne se chargent pas

Assurez-vous que les fichiers de traduction sont dans le bon répertoire et respectent le format JSON. Vérifiez que `translationDir` correspond à l'emplacement de vos fichiers.

### ⚠️ Erreurs de route introuvable

Vérifiez que tous les codes de locale dans le tableau `locales` sont corrects et que les routes sont correctement configurées.

### 🏷️ Balises SEO manquantes

Vérifiez que `meta: true` est défini et que chaque locale possède un code `iso` valide.

### 🔄 Incompatibilités d'hydratation

Si vous utilisez la stratégie `no_prefix`, définissez la locale dans un plugin serveur avec `order: -10` en utilisant `useI18nLocale().setLocale()` pour vous assurer que le serveur et le client s'accordent sur la locale. Voir [Détection de langue personnalisée](/guides/custom-language-detection).

### 🍪 Les redirections ne fonctionnent pas

Pour les stratégies de préfixe, assurez-vous que `localeCookie: 'user-locale'` est défini. Sans cookie, le plugin de redirection serveur n'a aucun moyen de mémoriser la locale préférée de l'utilisateur entre les rechargements de page.
