# 📦 Passer de v2.x à v3.x

<Tip>
Consultez [Migration depuis nuxt-i18n](/migration/from-nuxtjs-i18n) — ce guide couvre le passage depuis l'écosystème vue-i18n, pas depuis nuxt-i18n-micro v2.
</Tip>

v3.0.0 introduit des changements architecturaux fondamentaux : paquets de stratégies, nouveau système de mise en cache, gestion centralisée des locales via `useI18nLocale()` et un pipeline de redirection redessiné. Cette section couvre tous les changements incompatibles et comment mettre à jour votre code.

## Étapes de migration

```mermaid
flowchart LR
    A["1. Update deps"] --> B["2. Fix config"] --> C["3. Update plugins"] --> D["4. Test"] --> E["✅ Done"]
```

## Résumé des changements incompatibles

- **État de la locale** — `useState` / `useCookie` manuellement → composable `useI18nLocale()`
- **Accès à la config** — `useRuntimeConfig().public.i18nConfig` → `getI18nConfig()` depuis `#build/i18n.strategy.mjs`
- **Composant de redirection** — option `fallbackRedirectComponentPath` → plugin de redirection serveur + middleware de route client (automatique)
- **`includeDefaultLocaleRoute`** — Pris en charge (déprécié) → Supprimé, utilisez l'option `strategy`
- **`experimental.hmr`** — Sous `experimental` → Option de niveau racine
- **`previousPageFallback`** — Entièrement supprimé (la stratégie de fusion cumulative gère cela automatiquement)
- **Mise en cache** — `useStorage('cache')` → singleton `TranslationStorage` (`Symbol.for` sur `globalThis`)
- **Transfert SSR** — Runtime config → payload Nuxt (v3 utilisait `useState` ; les chunks vivent maintenant dans `payload.data`, voir [Performance](/guides/performance#server-side-payload-transfer))
- **Classes de stratégie** — Interne → Paquets séparés (`@i18n-micro/route-strategy`, `@i18n-micro/path-strategy`)

## Supprimé : `fallbackRedirectComponentPath`

L'option `fallbackRedirectComponentPath` et le composant de fallback `locale-redirect.vue` ont été supprimés. La logique de redirection est maintenant gérée par :

1. **Middleware serveur** (`i18n.global.ts`) — définit `event.context.i18n.locale`
2. **Plugin de redirection serveur** (`06.redirect.ts`, serveur uniquement) — redirections 302 avant le rendu
3. **Middleware de route client** (`i18n-redirect.global.ts`) — redirections SPA après l'hydratation

```diff
 i18n: {
   strategy: 'prefix_except_default',
-  fallbackRedirectComponentPath: '~/components/MyRedirect.vue',
 }
```

Si vous aviez une logique de redirection personnalisée dans le composant de fallback, implémentez-la plutôt dans un plugin serveur :

```ts
// plugins/i18n-loader.server.ts
export default defineNuxtPlugin({
  name: 'i18n-custom-redirect',
  enforce: 'pre',
  order: -10,
  setup() {
    const { setLocale } = useI18nLocale()
    // Your custom detection logic
    setLocale(detectedLocale)
  },
})
```

## Supprimé : `includeDefaultLocaleRoute`

Utilisez plutôt l'option `strategy` :

- `includeDefaultLocaleRoute: true` → `strategy: 'prefix'`
- `includeDefaultLocaleRoute: false` → `strategy: 'prefix_except_default'` (la valeur par défaut)

```diff
 i18n: {
-  includeDefaultLocaleRoute: true,
+  strategy: 'prefix',
 }
```

## Accès à la config : `getI18nConfig()` remplace `useRuntimeConfig`

```diff
- const config = useRuntimeConfig()
- const cookieName = config.public.i18nConfig?.localeCookie || 'user-locale'
+ import { getI18nConfig } from '#build/i18n.strategy.mjs'
+ const { localeCookie: configCookie } = getI18nConfig()
+ const cookieName = configCookie ?? 'user-locale'
```

## Gestion de la locale : `useI18nLocale()` remplace l'état manuel

En v2, vous avez peut-être utilisé `useState('i18n-locale')` ou `useCookie('user-locale')` directement. En v3, utilisez le composable centralisé `useI18nLocale()` :

```diff
- const locale = useState('i18n-locale')
- const cookie = useCookie('user-locale')
- locale.value = 'fr'
- cookie.value = 'fr'
+ const { setLocale } = useI18nLocale()
+ setLocale('fr') // Updates both state and cookie atomically
```

Voir [Détection de langue personnalisée](/guides/custom-language-detection) pour des exemples détaillés.

## Options expérimentales déplacées / supprimées

`hmr` est passé de `experimental` au niveau racine. `previousPageFallback` a été entièrement supprimé — le module utilise désormais une stratégie de fusion profonde cumulative (profondeur de 2 niveaux) qui préserve automatiquement les traductions de la page précédente pendant les animations de transition, même lorsque les pages partagent des clés imbriquées qui se recoupent. Une fois l'animation de transition terminée, le hook `page:transition:finish` nettoie les clés de l'ancienne page en mémoire.

```diff
 i18n: {
-  experimental: {
-    hmr: true,
-    previousPageFallback: true
-  }
+  hmr: true,
+  // previousPageFallback removed — handled automatically
 }
```

## Architecture de redirection (v3)

Les redirections sont désormais gérées automatiquement par deux composants :

1. **Côté serveur** (`06.redirect.ts`, serveur uniquement) : S'exécute pendant le SSR, émet des redirections 302 avant tout rendu de page — pas de « clignotement d'erreur »
2. **Côté client** (`i18n-redirect.global.ts`) : Middleware de route global sur la navigation SPA ; préserve la chaîne de requête et le hash

Priorité de la locale pour les redirections :

1. `useState('i18n-locale')` — défini via `useI18nLocale().setLocale()`
2. Cookie — si `localeCookie` est configuré
3. En-tête `Accept-Language` — si `autoDetectLanguage: true`
4. `defaultLocale` — repli

Aucun changement de code requis pour les configurations standard.

<Warning>
Pour les stratégies `prefix` et `prefix_except_default` avec `redirects: true`, définissez `localeCookie: 'user-locale'` pour activer la persistance de la locale entre les rechargements de page. Sans cela, les redirections utilisent uniquement `Accept-Language` ou `defaultLocale`.
</Warning>

## TypeScript : types de modules internes (optionnel)

Si vous rencontrez des erreurs de types liées à des imports internes comme `#i18n-internal/plural`, `#i18n-internal/strategy` ou `#i18n-internal/config`, ajoutez la section `imports` au `package.json` de votre projet :

```json
{
  "imports": {
    "#i18n-internal/plural": "nuxt-i18n-micro/internals",
    "#i18n-internal/strategy": "nuxt-i18n-micro/internals",
    "#i18n-internal/config": "nuxt-i18n-micro/internals"
  }
}
```
